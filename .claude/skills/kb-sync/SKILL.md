## When a construct lands

Check its box in the tracker AND flip its `status` in `constructs.json`. Both, same commit.

## When a fix-queue item lands

Update the queue's LANDED header, and the tracker's §B. If it moved the worklist, update plan §0.

## The Obsidian vault

The vault root is the repo itself. `kb/Reference/` is a **generated build output** — gitignored, regenerated by
`pwsh scripts/gen-vault-reference.ps1` from the `///` summaries, and guarded by `VaultReferenceGeneratorDriftTests`.
Never hand-edit it; regenerate.

`kb/Context/Doctrine & Anti-Patterns.md` and `kb/Spec/Lookup/Constraints.md` are hand-maintained mirrors of
`CONSTRAINTS.md`, which is the SSOT for the labelled anti-pattern catalog. If you change a catalog row, change all
three.

## Doc drift — fix ON DISCOVERY

The moment you find a doc inconsistent with reality, fix it. Do not batch doc fixes to end of session and do not
park them behind in-flight work — a doc edit is safe while a battery runs, since the battery reads binaries and
corpora, not markdown. Then grep the whole doc set and fix EVERY occurrence.

**When the stale thing is live state duplicated across many sites, do not repoint each site** — that re-drifts on
the next change. Add one authoritative banner that supersedes the local copies and POINTS at plan §0.

Every doc except `DEVLOG.md` reads as CURRENT state — no "was X, now Y", no commit hashes, no phase provenance
tags. Leave genuinely historical artifacts alone: `DEVLOG.md`, `PHASE4_RECONCILIATION.md`, and the
`PHASE-*`/`SURVEY-*`/`CRITIQUE-*` records are point-in-time.

## At every phase close

Sweep all of it: the phase doc's status and each exit criterion reconciled to as-built, plan §0's worklist and
next-phase pointer, the affected design docs' open questions, `docs/DOC_INDEX.md` rows for anything added or
retired, the memory index, and a DEVLOG entry.
