(1) A printable item cannot be referenced: \"Data-name-1 may be referenced only if the entry defines a sum counter\" (§1985:XIII.3.9.3 SR10). A report group's own name is used only by GENERATE, by USE BEFORE REPORTING and to qualify a sum counter. (2) Nothing a group presents depends on what its positions held before. A SOURCE item is moved at presentation: \"It is at this time that the implicit MOVE statements specified by SOURCE clauses are executed by the report writer control system\" (§1985:XIII.3.18.4 GR1). A SUM item likewise: the control system \"moves the data contained in the sum counter, according to the rules of the MOVE statement, to the printable item for presentation\" (§1985:XIII.3.19.4 GR4). A VALUE item: \"the printable item will assume the specified value each time its report group is printed\" (§1985:XIII.3.22.4 GR2). Under GROUP INDICATE \"it causes the SOURCE or VALUE clause to be ignored and spaces supplied\" (§1985:XIII.3.13.4 GR1). And every other position of the line is spaces: the control system \"supplies space characters for all positions of a print line that are not occupied by printable items\" (§1985:XIII.3.11.4 GR3), which covers the positions before the first item and after the last, where a shared area would show what another group left. (3) The one item a program can read is a sum counter (SR10 d; \"It is permissible for Procedure Division statements to alter the contents of sum counters\", §1985:XIII.3.19.4 GR6). The text does not say whether a counter lies in its group's area: §1985:XIII.3.19.4 GR5 separates it only from the printable item (\"the data-name is not the name of the printable item that the entry may also define\"), and §1985:XIII.3.19.4 GR1 says only that it is \"a compiler-generated numeric data item with an operational sign\". The SUM clause's own rules for crossfooting and rolling forward (§1985:XIII.3.19.4 GR9 to GR12, on folios XIII-53 and XIII-54, the latter transcribed from the GovInfo scan, kb/Work PB5789) state the same times; the argument uses the TYPE clause's rule for them. An implementation that kept a counter where building another group overwrites it would show a counter that does not hold what those rules give, which breaks them and shows nothing this rule adds; each has a 1985 witness of its own. So the program the first refuter wrote (running totals displayed between GENERATE statements) prints the same for every implementation that keeps those rules, whether its groups share an area or not, and the third refuter's program (two detail groups of different lengths presented alternately, GROUP INDICATE, a SOURCE that names another group's counter, a counter rolled forward, an ADD to a counter between GENERATE statements, a USE BEFORE REPORTING procedure that reads counters; run r3ovl-001) found every value fixed by one of them. (4) In this implementation the set is empty by construction as well: a report group has no storage area. A print line is composed anew at each presentation (ReportWriterEmitter.cs#EmitCompose, CobolReport.NewLine), and a sum counter is an object of the report engine (CobolReport.SumEntry), reached only through the engine's own subtotalling, rolling forward and reset.
