- **D-MCS-RAISE — an exception sent to the requestor** (kb/Work PB4744; DESIGN-message-control.md §0 Q6). §2023:14.9.38.4 GR8 sends "exception-name-1 or the name of the last exception raised in the current run unit" to the requestor, and the
  implicit SEND of §2023:14.6.11 item 7 and §2023:14.6.12 sends EC-MCS-NORMAL-TERMINATION or EC-MCS-ABNORMAL-TERMINATION; no rule says what the requestor's RECEIVE does with it. The RECEIVE moves the reply into identifier-1 and its length into
  data-name-2, then is unsuccessful with that condition, set to exist when the requestor's checking for it is enabled at the RECEIVE (any name, tested by name at run time). §2023:14.9.38.3 has no level-3 rule, so a level-1 or level-2 name
  is a legal RAISING operand; the requestor's RECEIVE is then unsuccessful and sets no condition, because "Only the lowest level exception-names are associated with exception status indicators" (§2023:14.6.13.1.1). LAST with no exception raised
  sends none. A server that ends with a message it has not replied to answers it as §2023:14.6.11 item 7 prescribes, from a temporary item of spaces the size of the receiving item of the RECEIVE; a killed server is answered for with EC-MCS-ABNORMAL-TERMINATION.
