- **D-MCS-SERVER — how a message server is named, found and started; a missing requestor** (kb/Work PB4744; DESIGN-message-control.md §0 Q2, Q3).
  §2023:14.9.38.3 SR2 says "Message-server-name-1 is the name of a message server run unit" and §2023:14.9.38.4 GR4 sends to the run unit "identified by the
  content of literal-1 or message-server-name-1". A message-server-name-1 is a bare word naming the server and is never resolved as a data item; a server name is the
  word or the literal's value with trailing spaces removed, compared without regard to case. A run unit serves a name when it is started with
  `WISEOWL_COBOL_MCS_SERVER=<name>`. A name no live run unit serves is EC-MCS-NO-SERVER (GR5); several run units may serve one name and the first RECEIVE takes the
  request. A name `mcs.json`'s `servers` member defines with a `start` command (a command line, or an array of the program and its arguments) is started by the SEND that finds no live server of it (kb/Work PB4745; DESIGN-message-control.md §5.4.5): the requestor takes the name's activation lock, finds the name still unserved, and runs the command in the MCS directory with `WISEOWL_COBOL_MCS`, `WISEOWL_COBOL_MCS_SERVER`, `WISEOWL_COBOL_MCS_NOTIFY` and `WISEOWL_COBOL_MCS_LOG` set; the server's standard output and error are the log `servers/<name>.<run id>.log` of the MCS directory. A command that ends before its server has published its listener, or cannot be started, or an unusable `mcs.json` (a member of the wrong shape, a name defined twice) is EC-MCS-IMP (Q8); a name no run unit serves and no definition can start is EC-MCS-NO-SERVER. The printed standard has defects here, recorded and not coded around:
  GR1 ends "the execution of the RECEIVE statement is unsuccessful" in the SEND statement (the SEND is unsuccessful); GR4 says the message "contains the content of data-name-1",
  which is the RETURNING tag (the message is identifier-1's content); GR7 raises "the EC-MCS-NO-RECEIVER exception condition", a name Table 13 does not list
  (EC-MCS-NO-REQUESTER is raised, D-MCS-NR extended: a SEND Format 2 whose tag is NULL, a server tag or an answered message, and a RECEIVE FROM NULL in a run unit that
  serves no name, which no requestor can address). A tag of another message control system is EC-MCS-INVALID-TAG, the test §2023:14.9.31.4 GR1b makes of the same operand.
  A tag's contents are the MCS identity, the party's role, the server name or the requestor run unit, and the message's serial number (A.1 item 212); two tags are equal
  when they name the same party (§2023:8.8.4.2.14). Witnesses `conformance-test:MessagingProcessTests`, `unit:MessagingProtocolTests`, `unit:MessagingPeerTests`.
