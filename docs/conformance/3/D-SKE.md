- **D-SKE — a SORT/MERGE key whose length varies, at every edition (§2023:14.9.40.3 SR6 d), §2023:14.9.24.3 SR4 d); kb/Work PB2512, PB5321)**: **not a determination: each edition's own text forbids the key, and the compiler refuses it at every edition from that edition's rule.** The 2023 text refuses a key that is "a variable-length group, an occurs-depending-on data item, a dynamic-length elementary item or an item subordinate to a dynamic-capacity table" (MERGE's copy prints a comma before "or an item subordinate"; the refusal quotes each statement's own copy verbatim). The 1985 text refuses the one varying-length key an 85 program can write, the occurs-depending group (DYNAMIC LENGTH is 2014 and a dynamic-capacity table is 2023): `§1985:XI.4.4.3 SR4c` (SORT) and `§1985:XI.4.1.3 SR4c` (MERGE), "The data items identified by key data-names must not be group items that contain variable occurrence data items." The 2002 text refuses every variable-length key: `§2002:14.8.36.2 SR6d` (SORT), "The data items identified by key data-names shall not be variable-length data items.", and `§2002:14.8.23.2 SR4d` (MERGE), "The data items identified by key data-name shall not be variable-length data items." So the occurs-depending arm of `SortKeyAdmission` is correctly not edition-gated, on the text of every edition; at `--std 85` its refusal cites the 1985 rules. **The OCCURS arm is the same rule at every edition:** a key "described by an entry which either contains an OCCURS clause or is subordinate to an entry which contains an OCCURS clause" is refused by `§1985:XI.4.4.3 SR4e` (SORT; MERGE's `§1985:XI.4.1.3 SR4e` prints "that" for "which"), `§2002:14.8.36.2 SR6f` / `§2002:14.8.23.2 SR4f`, and `§2023:14.9.40.3 SR6f` / `§2023:14.9.24.3 SR4f` ("None of the data items identified by key data-names may be described by an entry that either contains an OCCURS clause or is subordinate to an entry that contains an OCCURS clause"); at `--std 85` a key that carries a fixed OCCURS clause or lies under one is refused citing SR4e, and a key that is a group containing a fixed OCCURS entry is accepted, as SR4c and SR4e allow (the Mythos ruling's probes `pb5321a`, `pb5321b`, 2026-11-20, kb/Work PB5321). Corroboration, below the text: GnuCOBOL 3.2 (`cobc -fsyntax-only -free` at `-std=cobol85`, its default, `ibm` and `mf`) compiles the occurs-depending group key with exit 0 at every dialect, so it has no such check; Micro Focus's SORT statement page prints the prohibition ("The data items identified by KEY data-names must not be variable length items"). (Goldens `14.9.24-MERGE/pb1173-sort-file-key-odo-group`, `pb1173-merge-key-odo-group`, refused at 85, 2002, 2014 and 2023.)
