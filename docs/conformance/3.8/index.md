---
heading: "### 3.8 The COBOL-85 Segmentation module (kb/Work PB5084)"
---
Segmentation is an obsolete optional module of X3.23-1985, deleted from COBOL-2002 (COBOL0902). WiseOwl COBOL keeps every segment
resident, which §1985:XVI.1.6 permits ("the implementor must provide control transfers to maintain the logical flow specified in
the source program"), and implements the two rules a program can observe. The design is D4 of `docs/CONTROL_FLOW_DESIGN.md`.

| Item | Determination |
|---|---|
| The procedures a PERFORM, SORT or MERGE names | The range is the executed one: "The range includes all statements that are executed as the result of a transfer of control by CALL, EXIT, GO TO, and PERFORM statements in the range of the PERFORM statement" (§1985:VI.6.21.4 GR11), and the program that breaks §1985:XVI.3.3.2, XVI.3.3.3 or XVI.3.3.4 has an undefined result ("The results of violating the formats or rules of Standard COBOL are undefined unless otherwise specified in this standard", §1985:I.1.6), so which violations are diagnosed is a choice. WiseOwl COBOL diagnoses (COBOL6877) the procedures the statement NAMES (procedure-name-1 through procedure-name-2, in either physical order) as far as execution reaches them by fall-through and GO TO (an alterable GO TO also to each procedure an ALTER names for it); a section of that span no path of the range reaches is not in the range and is not asked (kb/Work PB5442: `PERFORM A-SEC THRU C-SEC`, A going to C over a section of another segment, is legal). Each PERFORM, SORT and MERGE inside those procedures is asked about its own range, and the procedures it performs are not added to the outer statement's: the CCVS-85 segmentation programs SG102A and SG103A, written to be accepted, PERFORM the fixed-portion report paragraphs from inside an independent segment's performed range, which the letter of GR11 makes a violation with an undefined result; diagnosing it would refuse both |
| An independent segment's initial state | §1985:XVI.1.4.3 and §1985:VI.6.7.4 GR1: its ALTERed GO TOs return to their written targets whenever control enters it from a segment with a different segment-number (falling through, a SORT or MERGE procedure entry, an explicit transfer), and keep their state when control returns to it implicitly (the return of a PERFORM, and each execution of an iterative PERFORM's range after the first, which the control mechanism enters implicitly, §1985:IV.4.4.2 GR1; kb/Work PB5380) or by EXIT PROGRAM. A CALL that re-enters a program is not a transfer from another segment of it: the program is in its last-used state (§1985:X.5.2.4 GR5), its independent segments included. The modified GO TO is the state the 1985 text names as returned (VI.6.7.4 GR1); data is not segmented (§1985:XVI.1.3: "COBOL segmentation deals only with segmentation of procedures"), so nothing else is reset |
| SEGMENT-LIMIT and fixed overlayable segments | A null facility in function: a fixed overlayable segment "is always made available in its last used state" (§1985:XVI.1.4.2), which is what a resident segment is. Its range is checked (COBOL6819) |
| --permissive at a later edition | The segment-number is a removed construct, accepted with a warning (COBOL0902); it keeps its 1985 run-time meaning (as ALTER does), so the two rules that make that meaning well-defined are asked: a section's range (§1985:XVI.3.2.3 SR1 and SR3, COBOL6819) and the ALTER restriction (§1985:XVI.3.3.1, COBOL6877), because the initial-state reset would silently undo an ALTER from another segment (kb/Work PB5223, PB5224). The PERFORM, SORT and MERGE restrictions (§1985:XVI.3.3.2-4) and the SEGMENT-LIMIT range restrict only what a program may write, change nothing the kept meaning runs, and are not asked |
