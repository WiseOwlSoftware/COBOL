---
heading: "### 3.5 Two I-O syntax rules of COBOL-85 that later editions dropped (kb/Work PB5076, PB5077, PB5270)"
---
Both rules are explicit syntax rules of X3.23-1985, so a program that breaks them is not a conforming source program (§1985:I.1.6) and `--std 85` refuses it. The design is D31 of `docs/FILES_DESIGN.md`.

| Rule | Editions | Determination |
|---|---|---|
| AT END or INVALID KEY mandatory where no applicable USE AFTER STANDARD EXCEPTION procedure is specified (§1985:VII.4.4.3 SR2, §1985:VIII.4.5.3 SR5, §1985:IX.4.5.3 SR7 for READ; the WRITE, REWRITE, DELETE and START rules of §1985:VIII.4 and §1985:IX.4) | 85 only | a hard error, COBOL6826, never a --permissive warning: the omission is no tolerated dialect. "Applicable" is read statically as §1985:VII.4.6.4 GR5 words it: a declarative naming the file, or one for an open mode (INPUT, OUTPUT, I-O, EXTEND: the file may be in any mode it can be opened in when a statement runs, one the statement does not suit included, so an INPUT, OUTPUT or I-O declarative covers every statement and an EXTEND one only a file that can be opened EXTEND, a sequential-access file without LINAGE, §1985:VIII.4.4.3 SR1, §1985:VII.4.3.3 SR3; CCVS-85 SQ148A reads a file open OUTPUT under a USE ON OUTPUT), of this program or, written with the GLOBAL phrase, of a containing one (§1985:X.5.5.4 GR1 b). The access mode qualifies DELETE and REWRITE as the 1985 text does; a sequential file's WRITE, REWRITE and START need no phrase |
| The FROM or INTO operand is not the file's record area (§1985:IX.4.5.3 SR1 and nine siblings; §2002:14.8.29.2 SR2 and four) | 85, 2002 | COBOL6827. "The same storage area" is read exactly, because the rule refuses the statement: a record of the file or of a SAME RECORD AREA peer, or a subordinate item that begins the record and is as long as it. A part of the record, a reference-modified operand and another file's record are legal. ISO/IEC 1989:2014 dropped the rule for all five phrases (§2014:E.3 items 21, 24, 25, 26 and 38, each "no longer prohibited"; kb/Work PB5270), leaving the overlap to the overlapping-operand rules COBOL-2023 keeps (§2023:14.6.10), so 2014 and 2023 accept the program (the result is undefined) |
