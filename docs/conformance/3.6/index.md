---
heading: "### 3.6 The run unit's external file connector rules, and the PADDING CHARACTER clause (kb/Work PB5069, PB5070)"
---
Every edition states that the file control entries of the run unit that describe one external file connector agree, and that some
of the data items their clauses name are external data items (§1985:VII.2.3.4 GR1, §1985:VII.2.4.3 GR3, §1985:VII.2.7.4 GR6,
§1985:VIII.2.3.4 GR1, §1985:VIII.2.4.4 GR8, §1985:IX.2.3.4 GR1, §1985:IX.2.5.4 GR5; §2002:12.3.4.3 GR1; §2023:12.4.5.3 GR1). The design
is D32 of `docs/FILES_DESIGN.md`.

| Item | Determination |
|---|---|
| Which entries are compared at compile time | The entries of one compilation group (`ExternalFileConnectorRules`); a difference is COBOL6847 at the entry that differs from the first describer, at every edition, and it compares the same segments the run time's EC-EXTERNAL-FILE-MISMATCH check compares between separately compiled runtime elements (`FileEntryIdentity.Segments`). The consistency rules for the implementor-defined operands (ASSIGN, RECORD DELIMITER) are A.1 items 72 and 149 (§7); the 1985 text's "consistent specification" of implementor-name-1 or literal-1 (§1985:VII.2.3.4 GR1 b) takes the same rule |
| The file description entries' agreement (X3.23-1985 only; kb/Work PB5300) | §1985:VII.3.6.3 GR4 (LABEL RECORDS, imported by the relative file description, §1985:VIII.3.2.4), §1985:VII.3.3.3 GR5 (BLOCK CONTAINS: the values of integer-1 and integer-2, not the unit), §1985:VII.3.4.4 GR3 (CODE-SET: the character set each alphabet-name denotes), §1985:VII.3.7.4 GR11 (LINAGE: the integers written; a data-name operand agrees with anything at compile time), §1985:VII.3.8.4 GR2 (RECORD, all three formats: the operands written, the format part of the value, an omitted or refused operand agreeing with anything; kb/Work PB5387) and §1985:VII.3.9.4 GR2 (VALUE OF) are asked of the entries that WRITE the clause, each against the first that does (`FileDescriptionIdentity`, COBOL6847 at the clause). The implementor's VALUE OF consistency rule ("The implementor will specify the consistency rules"): two entries are consistent when every implementor-name both write is given the same literal-1 VALUE (its class and value, never its spelling: `'A'`, `"A"` and `X"41"` agree, as do `1`, `01` and `1.0`, and `SPACE` and `SPACES`; kb/Work PB5362), and a data-name-1, whose value is known at run time, is consistent with anything. A report file description's clauses take their Sequential I-O meaning, the REPORT clause excepted (§1985:XIII.3.2.4 GR3), so its clauses are compared like a sequential file's; its RECORD ... DEPENDING ON phrase is read by no report engine, because the report file's record structure is the implementor's (§1985:XIII.3.2.4 GR2) |
| The RELATIVE KEY item | An external data item, and the same one in every entry, at EVERY edition (COBOL1624, COBOL1575, an error at every strictness): §1985:VIII.2.4.4 GR8 "data-name-1 must reference an external data item and the RELATIVE KEY phrase in each associated file control entry must reference that same external data item in each case", §2002:12.3.4.3 GR1 i), §2023:12.4.5.3 GR1 h). Annex E.2 item 24 of the 2023 text calls the requirement new; what is new there is "corresponding" across separately compiled runtime elements, and the in-group rule is older. Rejected: gating it at 2023 (the compiler's earlier reading, which accepted the 1985 violation) |
| The FILE STATUS and LINAGE items | External, and the same FILE STATUS item in every entry, at 2023 only (COBOL1624, COBOL1573): the Annex E.2 items 9 and 12 requirement, which no earlier edition states for FILE STATUS; its severity follows the removal policy (a warning under --permissive) |
| The PADDING CHARACTER clause (85, 2002; deleted from 2014) | A null facility in function: WiseOwl COBOL has no blocking model, so no padding character is written or bypassed (§1985:VII.2.7.4 GR2: the creation or recognition of padding characters does not occur where the clause is not applicable to the device type). With the clause omitted, the padding character the implementor defines (§1985:VII.2.7.4 GR5; §1985:C.2 item 52) is likewise never used. The padding character is a fixed file attribute (§1985:VII.2.7.4 GR3) that OPEN does not validate: which attributes OPEN validates is the implementor's (§1985:VII.4.3.4 GR8; §1985:C.2 item 86), and the OPEN validation determination (A.1 item 129, section 7) validates only what a file's physical format records, which a padding character is not. Its syntax rules are enforced (COBOL6848: §1985:VII.2.7.3 SR1 a one-character nonnumeric literal, a figurative constant counting as one character, a symbolic-character with or without ALL included (read before the word is tried as data-name-1; kb/Work PB5420), and an ALL literal only when its literal is; SR3 a one-character alphanumeric item outside the communication, file and report sections; §2002:12.3.4.10.2 SR1, SR3), and for an external file connector the clause is part of the entry identity and data-name-1 must be an external data item (§1985:VII.2.7.4 GR6, §2002:12.3.4.3 GR1 h)) |
