cells: ["DOC-A.1-138", "**Parameterized classes and interfaces — manner and time of expansion**, §2023:7.1 (with §2023:12.3.8.4 GR5 / GR8), required + need not be documented (documented voluntarily)", "**Time:** a parameterized class or interface is expanded at compile time, once per compilation group, AFTER all text manipulation — COPY, REPLACE and the compiler directives have finished, the source has been parsed, and expansion runs at the start of binding (`OoExpansion.Expand`, called from `BinderDriver`). So a REPLACE that produces a formal parameter's name inside the definition takes part in the substitution. **Manner:** each distinct expansion (`CLASS new-name EXPANDS definition USING actual …` or the interface form in a REPOSITORY paragraph) becomes an ORDINARY class or interface: the definition's own tokens re-parsed with every occurrence of each formal parameter replaced by its actual parameter (§2023:12.3.8.4 GR5 / GR8) and the header renamed to the expansion's name. It is never a .NET generic type, and from binding onward an expansion cannot be told from a written class — its FACTORY and OBJECT data are its own (two expansions of one definition keep separate factory counters). The parameterized definition itself generates nothing. **Identity (§2023:9.3.12):** specifiers that repeat one (expansion name, definition, actual parameters) triple, in one or several source elements, create ONE class; reusing an expansion name with a different definition or different actuals is **COBOL2240**. **Across compilation groups (§2023:9.3.12 \"Within a run unit, two classes with the same externalized object-class-name that are created by expanding the same parameterized class with the same actual parameters are the same class instance\"):** a group built with `--repository-update on` publishes each parameterized definition as a SKELETON (its source text after text manipulation, its formals, the identity of each class and interface its own REPOSITORY paragraph names, and the compile state it was compiled under: the edition, `--permissive`, `--sign-encoding`, `--numeric-display`, `--flag-extensions`, the `>>COBOL-WORDS` map, the `>>TURN` / `>>PROPAGATE` / `>>REF-MOD-ZERO-LENGTH` / `>>LEAP-SECOND` directives in force at the definition and the `>>DEFINE`d variables), and a group whose REPOSITORY expands a skeleton it does not define reads it from the external repository. An expansion publishes its identity (the definition and the actuals) and an EXPANSION KEY, a SHA-256 over the skeleton, its compile state and the published surface of every class and interface it names, so two expansions with one key are the same class text over the same surfaces. An expansion of that name and key that the search space already holds is the class: the group emits no copy and names the existing types (also for the skeleton's own group, when the existing assembly references its previous build). Otherwise an expansion whose code names no class of the expanding group is compiled as a compilation of its own, from the expansion's text under the recorded compile state, into `<externalized name>.dll` beside the output (placement (a)); one that names a class of the group is emitted in the group's assembly (placement (b)). An expansion of the same name, definition and actuals under another key is STALE: it is never imported, REPO-9 (COBOL5969, a warning) names it, the first component of its key that changed and every assembly of the search space that references it (those were compiled against the earlier class), and it is replaced; an expansion of that name of another definition or other actuals is REPO-2 (COBOL5963), and a file its assembly would overwrite that is no expansion of that name is **COBOL2240**.
