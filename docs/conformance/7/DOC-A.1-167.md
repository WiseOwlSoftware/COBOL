cells: ["DOC-A.1-167", "**Run unit — the relationship and interaction between COBOL and non-COBOL components**, §2023:14.6.1, conditionally required (condition met: a .NET host can activate WiseOwl COBOL programs, items 65, 141) + documented", "**The only non-COBOL component a run unit can contain is .NET code that ACTIVATES WiseOwl COBOL programs** (a \"host\"); COBOL never activates non-COBOL code — a CALL cannot reach it (item 16) and CANCEL does not touch it (item 19). **Beginning:** an executable built by `cobol` begins its run unit in its generated `Main` and contains no host. A host begins a run unit with `RunUnit.Run(body)`, which gives it a FRESH run unit — program table, EXTERNAL items, files, switches, locale (read from the process once, at that moment — item 120), FUNCTION RANDOM sequence, report state and exception status — and activates programs through their generated host entries (`Call`, items 65 and 141), each of which first registers its module through the module's one registration member, `__CobolModule.EnsureRegistered()` (once per run unit, refusing a module of another runtime major or call ABI, or one whose outermost name another module already registered — EC-PROGRAM-NOT-FOUND). An activation outside `RunUnit.Run` joins the ambient run unit of the host's execution context (`RunUnit.Current`, one per async flow). **Storage:** the host and COBOL share only what an activation passes — the USING arguments and the RETURNING item (item 141); COBOL storage is otherwise invisible to the host, and each run unit's EXTERNAL items are its own. **Ending normally:** GOBACK or EXIT PROGRAM returns to the host at its call site (item 65); the run unit ends when `RunUnit.Run`'s body returns, or at process exit for the ambient run unit, and either way the §2023:14.6.11 actions run (every open file of the run unit closed). **STOP RUN, and a fatal exception condition that terminates the run unit (§2023:14.6.12), end the RUN UNIT ONLY — never the host process** (owner decision kb/Work R48, deliberately unlike GnuCOBOL's process exit): WiseOwl COBOL performs the §2023:14.6.11 actions (every file of the run unit closed), replaces the ended run unit with a new one as the host's ambient run unit (so its state — switches, SET LOCALE — item 168 —, report and exception state, WORKING-STORAGE — starts fresh), and returns control to the host as ONE documented, catchable .NET exception, `WiseOwl.Cobol.Runtime.RunUnitEndedException`, whose `ExitStatus` is the item-192 STOP RUN status (or 1, the abnormal-termination status) and whose `Abnormal` says whether termination was abnormal (§2023:14.6.12) or normal (a STOP RUN, with an ERROR phrase or not); no other exception type escapes to the host for a run-unit ending, and `Environment.Exit` is never called. The outermost activation boundary does this: a host entry's activation, whose activator is outside every program. Nor does a run unit write the host's exit code (kb/Work PB3163) or reconfigure the host's console (item 59; kb/Work PB3193): only the entry that IS the process writes either. The host process continues and may begin another run unit, which inherits nothing (witness `conformance-test:HostRunUnitEndingTests.StopRunAndFatalCondition_EndTheRunUnitOnly_AndReachTheHostAsOneDocumentedException`). A standalone `cobol` executable IS its own host: its `Main`'s boundary (`ProgramTable.RunModule`) ends the run unit and exits the process with the status. Every edition. The ambient run unit is ended by the process's exit (`AppDomain.ProcessExit`) as a normal termination, with the §2023:14.6.11 2) actions and the §2023:9.1.18.5 commit, when it has opened a file (kb/Work PB4946).
