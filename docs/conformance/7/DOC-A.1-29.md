cells: ["DOC-A.1-29", "**Compile-time arithmetic — mode of arithmetic used and rules for intermediate data handling**, §2023:7.3.6 (§2023:7.3.6.3 GR2 · §2023:7.3.6.2 SR2), required + documented", "**A mode unique to compile-time arithmetic: .NET `System.Decimal`**, the same for a constant entry (`CONSTANT AS`), a `>>DEFINE` value and a `>>IF`/`>>EVALUATE` operand (one evaluator, `CompileTimeExpressionEvaluator`). It is neither a §2023:8.8.1 standard mode nor the runtime's native arithmetic. **Precision and range:** each intermediate result is a decimal number of up to 28–29 significant digits (at most 28 of them after the decimal point) whose magnitude is below about 7.9×10²⁸; an intermediate result outside that range is a compile-time error — COBOL1547 in a constant entry, COBOL1619 in a directive — never a wrapped or truncated value (`9999999999999999999999999999 * 10` is refused). **Intermediate rounding:** addition, subtraction, multiplication and division are exact whenever the exact result fits those digits; otherwise the result is **rounded to the nearest representable value, a tie to the even digit** — division does NOT truncate: `2 / 3 * 3` is 2 and `100 / 7 * 7` is 100 (a truncating division would give 1 and 99), while `1 / 3 * 3` is 0; `0.0000000000000000000000000005 / 2 * 10000000000000000000000000000` is 2 and `0.0000000000000000000000000015 / 2 * 10000000000000000000000000000` is 8. **Final result:** truncated toward zero to its integer part, as §2023:7.3.6.3 GR3 requires (`-7 / 2` is -3, `2.5 + 0` is 2). The exponentiation operator (§2023:7.3.6.2 SR1a) and a division by zero (SR1c) are rejected. **COBOL-2023 only** — the edition at which Annex E.2 6) makes the mode implementor-defined. **Why System.Decimal and not GnuCOBOL's choice** (CLAUDE.md rule 1 precedence, surveyed 2026-09-26 from the GnuCOBOL 3.2 sources, read and never copied): cobc folds a binary operation over two numeric literals with 64-bit integers (`cob_s64_t`, scales aligned by ×10), folds `/` only for simple integer operands and otherwise leaves the expression to run time, and its `>>IF` conditions are comparisons with no arithmetic evaluator — a 64-bit integer shortcut narrower than System.Decimal's 28–29 digits, not a designed mode, so it suggests nothing different. **Before 2023 the mode is not an implementor choice, and it differs between 2002 and 2014.** At COBOL-2002 §2002:7.2.5.2 GR1 says \"Standard arithmetic shall be used for all arithmetic operations\", so every compile-time arithmetic expression (the same three consumers, the same one evaluator) runs on the 2002 standard intermediate data item: 32 significant digits (§2002:8.8.1.3.1.1), every operand and every `+ - * /` result TRUNCATED toward zero to 32 digits (§2002:8.8.1.3.2, §2002:8.8.1.3.4, §2002:8.8.1.3.5), magnitude 10^-999 through 10^1000 - 10^968, a value outside it refused. Consequences a 2002 program sees: `2 / 3 * 3` is 1 (0.66…6 of 32 digits times 3 is 1.99…9), `100 / 7 * 7` is 99 and `1000000000000000000000000000000 * 100 + 9 - 1000000000000000000000000000000 * 100` is 0 (the 33-digit 10^32 + 9 loses its 9). At COBOL-2014 §2014:7.3.5.2 GR1 says \"The results of all arithmetic operations shall be as if ARITHMETIC IS STANDARD-DECIMAL were in effect at compile time\" and Annex E.2 6) records that the 2023 edition replaced it: this compiler evaluates in its standard-decimal intermediate data item (§2023:8.8.1.5.2: 34 significant digits, magnitude up to 9.99×10⁶¹⁴⁴), an inexact intermediate rounded **NEAREST-AWAY-FROM-ZERO** (§2023:11.9.11.2 GR3 a — a compile-time expression has no OPTIONS paragraph to name another), the same engine `ARITHMETIC IS STANDARD-DECIMAL` runs on. Consequences a 2014 program sees: `9999999999999999999999999999 * 10` is 99999999999999999999999999990 (not refused), `0.0000000000000000000000000015 / 2 * 10000000000000000000000000000` is 7 (7.5E-28 is exact), `2 / 3 * 3` is 2, `100 / 7 * 7` is 100 and `1 / 3 * 3` is 0 as at 2023. **In every edition**: a single numeric literal is a literal, not an expression (§2023:7.3.11.4 GR5), so no mode bounds it — only the literal's own 31-digit capacity (§2023:8.3.3.3.2); a literal operand past that capacity is refused; and an expression's final result, being \"an integer numeric literal\" (§2023:7.3.6.3 GR3), is refused when it has more than 31 digits (reachable only under standard arithmetic: `9999999999999999999999999999999 * 9999999999999999999999999999999`). The edition edges are `DialectBehavior.CompileTimeArithmeticIsStandardDecimal` (2014) and `DialectBehavior.CompileTimeArithmeticImplementorDefined` (2023), read by `CompileTimeArithmetic.For` (kb/Work PB1592, PB5575).", "`conformance:cases/A.1-Implementor-defined-language-element-list/gl2m2_ct_arith_mode`; `conformance:cases/A.1-Implementor-defined-language-element-list/gl2m2-ct-arith-intermediate-overflow`; `conformance:cases/_unassigned/pb1592_ct_arith_standard`; `conformance:cases/_unassigned/pb1592-ct-result-over-literal-capacity`; `unit:CompileTimeArithmeticModeTests.ModeDependentValues_FollowTheEditionsMode`; `unit:CompileTimeArithmeticModeTests.Selection_IsTheEditionsMode`"]
