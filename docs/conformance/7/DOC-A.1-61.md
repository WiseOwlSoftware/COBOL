It is **reallocated only when a receiving reference or a SET needs a higher capacity than the array holds** (a sending reference beyond the current capacity never allocates or grows the table), by doubling (from at least 4) until it is large enough, never beyond 1,073,741,823 occurrences, and to exactly the size requested when the doubled size cannot be allocated; newly allocated occurrences, including every intermediate one, are initialized immediately — the occurrences the table opens with from the element's initial state, and every occurrence a statement creates later from the initial state too, EXCEPT under the INITIALIZED phrase, where it is initialized as §2023:8.5.1.9.5's INITIALIZE … WITH FILLER ALL TO VALUE THEN TO DEFAULT would (kb/Work PB1267; without INITIALIZED that content is undefined and the initial state is this implementation's choice). **Lowering the capacity** (SET … TO / DOWN BY) clears the deleted occurrences and keeps their slots for reuse, as the §2023:8.5.1.9.4 NOTE permits, and an occurrence re-created by a later increase is initialized afresh, never the value it held before. **A variable-length group MOVE or boundary transfer into the table** (§2023:14.6.9.2) allocates a NEW array holding the sender's occurrences (raised to the FROM minimum with space-filled elements) and releases the old one.
