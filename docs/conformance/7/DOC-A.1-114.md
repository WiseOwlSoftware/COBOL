A final line with no delimiter ends at end of file. **A lone CR (one not followed by LF) is not a delimiter.** It is record data, and because CR is outside the line sequential character set (item 115), the READ that delivers it answers '09'. A line longer than the record area is delivered truncated with '06' (§2023:9.1.13.2), and the rest of the line is the next record. This follows GnuCOBOL, which writes a line sequential file in the host's text mode and drops a CR only when an LF follows it; ISO leaves the delimiter to the implementor (CLAUDE.md rule 1; kb/Work PB1540). Implemented once, in `SequentialConnector` (`LineSequentialDelimiter` for every line end it writes, `ReadPhysicalLine` for every line it reads).
