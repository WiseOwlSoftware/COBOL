The sharing mode belongs to each FILE CONNECTOR: it comes from that connector's SHARING clause, or from the SHARING phrase of the OPEN that opens it (§2023:14.9.27.4 GR21–GR23). It is set when the OPEN succeeds and checked against the connectors that have the same physical file open at that moment (§2023:9.1.15 Table 19). When the connector is closed, its sharing mode is gone. So a file created through a `SHARING WITH NO OTHER` connector can later be opened through two `SHARING WITH ALL OTHER` connectors at once, and both OPENs succeed with 00. While the NO OTHER connector is open, any other OPEN of the file fails with 61, and the NO OTHER connector's own OPEN fails with 61 while other connectors have the file open. This is also why A.1 item 129's validated fixed attributes never include sharing. Implemented by `FileRegistry.RegisterSharing` (the per-connector mode) and `FileRegistry.SharedOpenAttempt` (the check at OPEN).", "`conformance:cases/A.1-Implementor-defined-language-element-list/l1c11_sharing_not_fixed_attribute`"]
