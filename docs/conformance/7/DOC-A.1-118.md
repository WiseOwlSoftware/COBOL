cells: ["DOC-A.1-118", "**Locale specification — how the user default and system default locales are defined**, §2023:8.2.1, required — A.1 says this need not be documented, and it is documented here anyway because the environment variables are the user's only control over the defaults", "Both defaults are decided **once per run unit, when the run unit starts** (`LocaleState`, created with the `RunUnit`), and they are always two separate settings. **User default locale:** the environment variable **`COBOL_USER_LOCALE`** if it is set; otherwise the process's current .NET culture (`CultureInfo.CurrentCulture`, which on Unix follows `LANG`/`LC_ALL`); otherwise the root locale. **System default locale:** the environment variable **`COBOL_SYSTEM_LOCALE`** if it is set; otherwise the host's installed UI culture (`CultureInfo.InstalledUICulture`); otherwise the root locale. The variables' values are locale names in the item-119 notation, trimmed; `C`, `POSIX`, `root` or `INVARIANT` names the root locale. **At least one user default and one system default always exist**: in an environment with no locale data at all (.NET invariant globalization), both fall back to the root locale and the run unit starts normally. The current locale starts as the user default for every category (§2023:14.6.6). A program can change the user default for the rest of the run unit with `SET LOCALE USER-DEFAULT TO …`, but it cannot change the system default (§2023:8.2.1: the capability is not provided), so `LocaleState.SystemDefault` has no setter. Example: with `COBOL_USER_LOCALE=de-DE` and `COBOL_SYSTEM_LOCALE=fr-FR`, `FUNCTION LOCALE-DATE(\"20260924\")` gives `24.09.2026` after `SET LOCALE LC_ALL TO USER-DEFAULT` and `24/09/2026` after `SET LOCALE LC_ALL TO SYSTEM-DEFAULT`.
