cells: ["DOC-A.1-124", "**Native arithmetic — when an operand represents an integer**, §2023:5.5 GR3a, required + documented", "**An operand represents an integer exactly when its value has no nonzero digit to the right of the decimal point.** The test uses the operand's own exact value, never a rounded or truncated copy. A fixed-point data item is tested at its full declared scale. An arithmetic expression is tested on the value the native intermediate data item (item 123) holds for it. A floating-point operand is an integer only when its binary value is exactly integral: COMP-2 `2.0` is an integer, `2 + 1.0E-10` is not. The same value gets the same answer at every rule that asks: a subscript, a reference-modification start or length, a SET index or amount, and an integer argument of an intrinsic function. A subscript or reference-modification bound that is an arithmetic expression or a floating-point item is evaluated once, before the statement, and tested on the carrier it evaluated on — the exact scaled value, the SDIDI under standard arithmetic, or binary64 — before its integer position is stored (`CobolTable.OccValue*` / `CobolString.RefModValue*`, kb/Work PB1890; it used to be stored into a 9-fraction-digit temporary first, which hid a fraction past the 9th digit). When checking for the rule's exception condition is enabled, a non-integer is refused by that condition (for example EC-BOUND-SUBSCRIPT; for an intrinsic function's integer argument, §2023:15.3 type 6, it is EC-ARGUMENT-FUNCTION — every carrier of the operand asks the test, the exact scaled value, the SDIDI and binary64, narrow and wide, kb/Work PB1526) and, with that checking off, the truncated integer is the result the implementor defines (§2023:15.3's last sentence; a reference-modification position is the exception — an unchecked EC-BOUND-REF-MOD violation terminates the run unit, owner decision R60). A floating-point operand (which reaches an intrinsic function's integer argument only under `--permissive`) whose integer lies beyond ±1.7×10³⁸, outside the implementation's 128-bit integer carrier, cannot be represented, so it is EC-ARGUMENT-FUNCTION — never a nearer integer substituted for it — except at TEST-DATE-YYYYMMDD and TEST-DAY-YYYYDDD argument-1 and FIND-STRING argument-3, which answer the same for every integer past their bound and so answer it (kb/Work PB651). The compile-time screen of §2023:5.5 SR2 is separate (COBOL1627) and, since kb/Work PB5889, refuses an intrinsic integer argument only when it can name a value of the operands at which the expression is not an integer (D-INTEGER-ARGUMENT-SCREEN): an argument it neither proves nor refutes (`FACTORIAL(FUNCTION ORD (A) / 2)`) is accepted and its value checked when it is evaluated (`CobolIntrinsics.CheckedIntegerArgument*`, naming the function, the argument and the value), by this rule from COBOL-2002 (EC-ARGUMENT-FUNCTION with checking on, the truncated integer with it off), while at COBOL-85, which has no exception conditions, a non-integer value of such an argument terminates the run unit (§1993:p.B-46). A subscript or reference-modification position is tested at run time as before.
