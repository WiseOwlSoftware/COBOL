cells: ["DOC-A.1-77", "**File sharing — the default sharing mode when none is specified**, §2023:9.1.15, §2023:14.9.27.4 GR23 (and §2023:9.1.3), required + documented", "**It depends on the open mode.** When neither the OPEN statement's SHARING phrase nor the file control entry's SHARING clause gives a mode, the OPEN establishes one of §2023:9.1.15's own modes for the connector: **`OPEN INPUT` opens `SHARING WITH READ ONLY`**, and **`OPEN OUTPUT`, `OPEN I-O` and `OPEN EXTEND` open `SHARING WITH NO OTHER`**. The mode lasts until the connector is closed, and every other connector is arbitrated against it by §2023:9.1.15 Table 19, whether that connector is in this run unit or in another one. So with two clause-less connectors on one file: `OPEN INPUT` and a second `OPEN INPUT` both succeed with 00; `OPEN INPUT` followed by a second connector's `OPEN I-O`, `OPEN EXTEND` or `OPEN OUTPUT` fails with 61; and any OPEN of a file that a clause-less connector holds open in OUTPUT, I-O or EXTEND mode fails with 61. The host lock for these modes is described in item 75. This follows GnuCOBOL, which locks a file shared for input and exclusive for every other mode; ISO leaves the choice to the implementor (CLAUDE.md rule 1). This paragraph covers COBOL 2002, 2014 and 2023. **COBOL-85 (`--std 85`) is the other determination, the owner's of 2026-10-23 (kb/Work PB670, option (i)): the file sharing facility is not in effect.** File sharing and record locking is an optional module (Annex A.4.7), §2023:A.4.1 makes \"any associated syntax rules, general rules, other rules, exception conditions, and I-O status values\" optional with it, and the SHARING and LOCK MODE clauses are COBOL-2002 introductions, so a COBOL-85 program is compiled for a processor that does not have it. §2023:9.1.15 lets the implementor define the default as \"a mode completely specified by the implementor\", and for such a program that mode **restricts no other connector**: Table 19 is not asked, no file lock is established against other run units, and I-O status 61 (a status the 1985 edition does not define) is never answered. Two connectors of one run unit open the same physical file in any pair of modes, every OPEN answers 00 (an `OPEN OUTPUT` beside a connector that holds the file creates it empty, §2023:14.9.27.4 GR18, and the holder's next READ is at end), and a second run unit is not refused either; a process outside the run unit that holds the file exclusively makes the OPEN answer 30, §2023:9.1.13.6 item 1. This is GnuCOBOL's measured `-std=cobol85` behaviour (cobc 3.2: every OPEN of a file another connector of the run unit holds answers 00).
