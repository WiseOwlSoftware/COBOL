cells: ["DOC-A.1-158", "**Reference format — rightmost character position of the program-text area (margin R)**, §2023:6.3, required + documented", "**Margin R is immediately to the right of character position 72**, i.e. the fixed-form program-text area is columns **8–72**. Characters beyond it are not part of the program text and are ignored — they are not an error (§2023:6.3.4; comment-text likewise runs only \"up to margin R\"). Note §2023:6.3.1 makes this position *implementor-defined*: the standard does **not** mandate 72, and ISO 2023 has no \"identification area\" (that was a COBOL-85 card-image convention). Columns 1–6, the sequence number area, are **optional** and may hold any character (§2023:6.3.2) — a blank sequence area is ordinary fixed-form source. Free-form reference format (§2023:6.2) is not column-bounded and is unaffected. **The initial reference format is FIXED form** — §2023:7.3.24.3 2) \"The default reference format of a compilation group is fixed form\" — at every entry point (the `cobol` CLI, `CompilerDriver.Options.SourceFormat`, `Frontend.InitialFormat`), and a `>>SOURCE FORMAT` directive switches it (§2023:7.3.24.3 1)); a SOURCE FORMAT directive on the FIRST line may be written in either format (4)). The compiler option **`--source-format`** (`fixed`, `free` or `auto`) is the implementor-defined mechanism §2023:4.2.10 3) requires for selecting a nonstandard behavior of this required element: `free` starts the text in free form, and `auto` is the nonstandard extension that DETECTS the initial format from the text's layout (`ReferenceFormatProcessor.IsFixedForm` — a heuristic that reads conforming fixed-form source with a non-numeric or blank sequence area and text past margin R as free form, which is why it is never the default; kb/Work PB1362). GnuCOBOL, the rule-1 precedent, likewise defaults to fixed form and selects free form by a flag. **Text past margin R is dropped silently, but a SYNTAX ERROR beside it says so** (kb/Work PB2555, warning COBOL5788): a statement that ran past position 72 ends early, so the parse fails at the next token (`cannot parse construct near STOP`) or at a word the margin cut in two (`unexpected 'END-SEN'` for `END-SEND`), and the warning names the line, the position where the program text was cut and the text that lay past it. It is reported only beside a syntax error and never for a numeric sequence area, the rest of an inline comment or comment line (§2023:6.3.7.2, §2023:6.3.7.3), or the identification tags (one word of at most eight characters in positions 73–80) of a file in which such a word recurs on two lines or more (one tag-shaped word alone is indistinguishable from the tail of a statement, so it still draws the note, which says \"may\"). A line that holds text ONLY past margin R reads as blank, and the warning names it as a line with no program text (kb/Work PB4372). A line the compiler never read is not asked about, whatever it holds past margin R (kb/Work PB4412): a line of a false `>>IF` or unmatched `>>WHEN` branch (§2023:7.3.16.4 GR 3, §2023:7.3.13.4 GR 4 and 5) and a debugging line of a unit without `WITH DEBUGGING MODE` (a comment line); with the mode the debugging line is source and is asked about. **A token the margin cut in two is named even where the program still parses** (kb/Work PB4999, warning COBOL6688): when a token's last character stands at position 72 and the cut text begins at position 73 with no space between, the format read the token short (`Y ** 0.7` with its `7` at position 73 is `Y ** 0.`), so the program means something else with no syntax error to say so; the warning names the line, the token and the text that lay past it. A sequence number or tag set off by a space stays silent, as do the other shapes listed above. A compiler directive is recognized in the program-text area OF THE FORMAT IN EFFECT — positions 8 through margin R of a source line in fixed form, whatever the sequence area holds, and the whole line in free form (§2023:7.3.3 SR2/SR3; kb/Work PB1361). Every conformance-suite test states its reference format in its metadata header (`source-format`, fixed or free) and the suite runner compiles it in that format, never `auto` (`ConformanceSuiteRunner`; kb/Work PB3177); the in-repo xUnit harnesses that compile inline source select `auto` explicitly; the NIST CCVS programs compile under the fixed default. **Library text** is logically converted by the same walker and starts in the reference format in effect for its COPY statement (§2023:7.3.24.3 3)); its own `>>SOURCE FORMAT` directives switch it, and the COPY statement's text is back in its own format after it (5)).
