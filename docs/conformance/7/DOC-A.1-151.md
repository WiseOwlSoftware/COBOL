cells: ["DOC-A.1-151", "**RECORD DELIMITER clause — the method for determining the length of a variable-length record when the clause is NOT specified**, §2023:12.4.5.11.4 GR5, required + documented", "**Two methods, chosen by the file’s ORGANIZATION — and this determination governs EVERY variable-length file WiseOwl COBOL writes, including one that DOES write a RECORD DELIMITER clause, because that clause is declined whole (§2 row 26, COBOL1778).** **(a) Record sequential, relative and indexed:** each record is framed on the medium by a **4-byte little-endian binary length prefix** giving the record’s byte length, immediately followed by that many payload bytes; a relative or indexed record is the same frame, held as the value of its key’s entry in the keyed store engine’s B+ tree (an empty relative record number is no entry, so no gap is written anywhere; kb/Work PB3333-PB3335). ONE implementation serves every organization — `RecordFraming`, whose ONE frame-head encoder (`EncodeFrameHead`) and ONE decoder (`ReadFrame`) serve the keyed store’s leaf value (`EncodeFrame`/`DecodeFrame`) and the stream-level shape `SequentialConnector` streams. A frame the data ends inside (a torn tail), and a head this writer cannot produce, END the file’s data at that frame for every reader: the forward READ, the record count and the backward-READ index, and the OPEN’s framing check (kb/Work PB2754). A frame whose length word has bit 31 set carries the record’s EXTENT TABLE between the word and the payload (§3 D-FRA (v); kb/Work PB1053) — framing like the prefix, never part of the record. **(b) LINE SEQUENTIAL:** no prefix is written; the length is the number of characters between line delimiters, which is §2023:9.1.7.2’s own rule (“In line sequential files the length of each record is determined by the number of characters between the preceding line delimiter and the following line delimiter or the end of file if no line delimiter is present”), so a line-sequential file stays plain text. **The licence to add a header at all is §2023:9.1.7.2**, not §2023:9.1.13.6 — “In record sequential files the length of each record is determined by any information the implementor may add to the record on the physical storage medium (such as record length headers)”; §2023:9.1.13.6’s “externally-defined boundaries” is the I-O status 34 rule about writing past a FILE’s end and answers a different question (the miscitation it replaced lived in `RecordFraming`’s own header until 2026-09-05, kb/Work PB292). **§2023:12.4.5.11.4 GR1 is honoured in both arms** — “Any method used shall not be reflected in the record area or the record size used within the function, method, or program”: the prefix is stripped before the record area is filled and never enters a record size a program reads, and the line delimiter likewise.
