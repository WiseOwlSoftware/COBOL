The standard answers every disagreement such a re-read can produce with a SUCCESSFUL completion rather than a refused OPEN: §2023:9.1.13.2 item 3's '04' (\"A READ statement is successfully executed but the physical record from the file is shorter than or longer than the minimum or maximum length of records allowed for the fixed file attributes for that file\"), item 5's '06' and item 7's '09'. A prefix that parses but falls outside the RECORD clause's bounds is NOT a conflict: that is item 3's '04' on the READ, which a '39' at the OPEN would make unreachable. A file shorter than one prefix states nothing and is not a conflict. **(3) RELATIVE and INDEXED — whatever the keyed store's COMMITTED META PAGE carries** (the paged store format 6 of `docs/rearchitecture/DESIGN-runtime-library.md` 2.2.1.4, read from pages 0 and 1 by `MetaPage.Describes`): the **organization**, the **record type** (fixed or variable), the **minimum and maximum logical record size in bytes**, and the **key table** — each key's byte windows (one per data-name-2 of a SOURCE phrase, kb/Work PB1099), DUPLICATES phrase, SUPPRESS WHEN value and collating-sequence fingerprint (the sequence identified by its weights, not by the alphabet-name that produced them). Those two organizations live in an implementor-defined store whose STRUCTURE is those attributes — an indexed file has one B+ tree per key, ordered under that key's sequence — and the meta page is where that structure is written down — IN THE FILE, as GnuCOBOL's ISAM key definitions are in the file. A file whose meta pages are absent or unreadable is not a store this build can interpret — a whole-store file of an earlier build (format 5 and below, its magic at offset 0) included: '39', loud, rather than a silent misread. **The format's own limits are part of the set** (2.2.1.4): a key is stored as one byte per character position in a B+ tree leaf that holds at most 1 016 key bytes, so a prime key longer than 1 016 character positions, or an alternate key longer than 1 008 (its tree's entry key carries the 8-byte release ordinal after it), and a key table whose descriptors do not fit the meta page (3 927 bytes, at least 50 keys of 64-byte descriptors) are declarations the physical format cannot hold, refused with '39' at the OPEN in every mode, OUTPUT included, before any file is touched (GR25).
