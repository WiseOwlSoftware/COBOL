A file connector whose file control entry has neither a LOCK MODE clause nor a SHARING clause, opened by an OPEN with no SHARING phrase, SETS NO RECORD LOCKS: a READ does not lock, and an explicit `WITH LOCK` phrase on its I-O statements obtains nothing (`FileRegistry.ImplementorDefaultShare`, lock mode `FileLockMode.None`). It still RESPECTS other connectors' locks, because §2023:9.1.16 makes a locked record inaccessible to every other file connector: its READ, REWRITE and DELETE of a record another connector has locked are refused with I-O status `51`, and READ … IGNORING LOCK reads it. Example (a connector with neither clause can be open beside another connector only in the input mode, because a clause-less OPEN I-O, EXTEND or OUTPUT establishes SHARING WITH NO OTHER, item 131): A is declared `SHARING WITH ALL OTHER` with `LOCK MODE IS MANUAL` and opens INPUT; B has neither clause and opens INPUT (`00`, `00`). A `READ … WITH LOCK` record 1 (`00`); B's READ of record 1 is `51`, B's `READ … IGNORING LOCK` of it is `00`, B's READ of the unlocked record 2 is `00`, and after A's UNLOCK B's READ of record 1 is `00`. A connector that must REWRITE or DELETE beside a locker declares `SHARING WITH ALL OTHER` and a LOCK MODE clause (§2023:14.9.27.3 SR8) and then is refused a locked record the same way (`pb669_lock_visibility_plain_connector`: REWRITE and DELETE of a locked record are `51`).
