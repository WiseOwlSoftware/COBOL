cells: ["DOC-A.1-72", "**FILE-CONTROL entry, ASSIGN clause — consistency rules for external file connectors**, §2023:12.4.5 GR1, required + documented", "§2023:12.4.5.3 GR1 b) requires the file control entries that reference one external file connector to have *\"A consistent specification for data-name-1, device-name-1, and literal-1 in the ASSIGN clause\"* and leaves the rules to the implementor. **WiseOwl COBOL's rule: the entries must name the same file target and the same data-name-1, and nothing more.** (1) **The TO phrase is compared by the operand that names the file** (item 71), not by every word written: a leading device class is dropped, a literal is compared by its value and a device-name by its spelling. So `ASSIGN TO DISK \"xa.dat\"`, `ASSIGN TO PRINTER \"xa.dat\"` and `ASSIGN TO \"xa.dat\"` are consistent, and a device-name and a literal with the same spelling are the same name, so `ASSIGN TO XADAT` and `ASSIGN TO \"xadat\"` are consistent. Item 71's host-path mapping is NOT applied before the comparison: `ASSIGN TO XADAT` and `ASSIGN TO \"xadat.txt\"` are NOT consistent, although both open the host file `xadat.txt`. The comparison ignores case, so `\"Data.txt\"` and `\"data.txt\"` are consistent, even though on a case-sensitive host they name different physical files; the file opened is the one named in the program that executes the OPEN. An entry with a TO phrase and one without are not consistent. (2) **The USING data-name-1 is compared by spelling, qualifiers included, ignoring case.** `IN` and `OF` are the same, so `FNAME IN G` and `FNAME OF G` are consistent; `FNAME` and `FNAME OF G` are not, and neither are an entry with a USING phrase and one without. Two programs of ONE compilation group are checked when the group is compiled: a difference is COBOL6847 at the second entry (`ExternalFileConnectorRules`, which compares the same segments, `FileEntryIdentity.Segments`; kb/Work PB5069). Between separately compiled programs the check runs only when checking for EC-EXTERNAL-FILE-MISMATCH is enabled. It happens when a second program that describes the external file is activated: the two ASSIGN fields are part of the `SelectFingerprint` each program registers with `ExternalStore.Describe` (built at bind time by `FileEntryIdentity.Of`, the one §2023:12.4.5.3 GR1 identity, into `FileModel.SelectFingerprint` — kb/Work PB1079, PB2403), and a difference raises **EC-EXTERNAL-FILE-MISMATCH** (§2023:14.8.4.4), which is fatal. **⛔ The two programs still hold SEPARATE STORAGE for an identically-spelled data-name-1, and that is deliberate.** §2023:12.4.5.3 GR3 b) associates the connector with the file named *\"in the runtime element that executes the OPEN, SORT, or MERGE statement\"*, which only makes sense if the entries MAY name different data items. GR1 i) shows how the standard words it when it wants the opposite (FILE STATUS: *\"where data-name-4 shall reference the same corresponding external data item\"*), and §2023:13.4.5.4 GR2 c) 2. does the same for LINAGE; GR1 b) says neither.
