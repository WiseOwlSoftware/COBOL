cells: ["DOC-A.1-113", "**Life cycle for objects — timing and algorithm for deciding that an object can no longer take part in continued execution**, §2023:9.3.14.3, required (A.1 does not require it to be documented; documented here because it decides when §2023:9.1.4's implicit CLOSE of an object's files happens)", "**Reachability, decided by the .NET garbage collector.** An instance object is a managed instance of a class derived from `CobolObject`. It can no longer take part in continued execution once no object reference in the run unit reaches it. The .NET tracing garbage collector decides that at a time of its own choosing, which is nondeterministic, as §2023:9.3.14.3 permits. When it has decided, the object is destroyed. Its finalizer implicitly CLOSEs every per-object file connector the object owns (§2023:9.1.4, 'when the object is deleted'), **in the run unit that created the object**, and the object's storage is reclaimed. A later OPEN of the same physical file is therefore arbitrated only against connectors that are still live. At run-unit termination every object not yet destroyed is destroyed, and its files are closed with the run unit's (`CobolFile.CloseAll`). Whichever of the two happens first is the destruction. An object that owns no file has no observable destruction beyond its storage being reclaimed.
