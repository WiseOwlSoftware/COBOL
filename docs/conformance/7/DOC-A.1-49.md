A compilation-variable-name is a COBOL word, so every spelling of one name (`MyVar`, `MYVAR`, `myvar`, and a spelling Annex C.2 makes the same word, such as an extended letter and its own lowercase) reads the SAME variable, `MYVAR`, on every host, including a host whose environment names are case-sensitive; two names Annex C keeps apart (a long s and `S`; the Kelvin sign and `K`, A.1 item 20) read two variables (kb/Work PB2990). **No value ⇒ the name is NOT defined** (GR4's second sentence), and a definition it had before the directive is removed. **The FORM of a value is the implementor's (GR4), and GnuCOBOL 3.2 decides it** (`cobc/ppparse.y`, the `PARAMETER` action and `ppp_check_needs_quote`; CLAUDE.md rule 1; kb/Work PB1626): the classification is SYNTACTIC, on the text exactly as the environment holds it, at EVERY edition, and does not depend on a numeric type's range. (1) An absent variable, an EMPTY variable and a variable whose text BEGINS WITH A SPACE make no value available. (2) A text that begins with a quotation symbol is ONE quoted literal when a closing delimiter of that symbol ends it (a doubled quotation symbol is content, §2023:8.3.3.2.3 3)): the name is defined with that literal (`\"ab\"\"c\"` is `ab\"c`, `'x y'` is `x y`, `\"7\"` is alphanumeric); one that is not so closed — `\"abc`, `\"a\"b\"`, `\"a\" & \"b\"` — makes no value (GnuCOBOL tests only the first and last characters; this compiler holds the text to one literal). (3) A text that is the SPELLING of a fixed-point numeric literal (§2023:8.3.3.3.2: at least one digit, at most one sign and it the leftmost character, at most one decimal point and never the rightmost — `7`, `007`, `-2.5`, `+.5`) is NUMERIC, of ANY length, and its value is made by the path a numeric literal written in the directive takes (`>>DEFINE X AS 12…`), so a 29-31-digit value is numeric whatever the edition's compile-time arithmetic mode, and a value of more than 31 digits is refused (COBOL1619, naming the directive) where that path refuses the same literal, at the definition (GnuCOBOL reports it at the use). `5.` is not a numeric literal's spelling (§2023:8.3.3.3.2 3)), so — unlike GnuCOBOL, which calls it numeric — it is alphanumeric. (4) Any other text — `1,000`, `1E5`, `7x`, `7 ` (a trailing space is content) — is ALPHANUMERIC with the text exactly as given. The one implementing site is `DefineParameterValue.Classify`. Every read is recorded on the compilation's inputs (`CompilationInputs.EnvironmentReads`).
