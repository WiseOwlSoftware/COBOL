# PHASE 03 — Version-Gating Framework: EditionValidator Waves + Harness-Driven VCR Audit

- **Phase:** P3
- **Track:** feature-iso
- **Risk:** HIGH (the strict/permissive posture affects 243/459 NIST programs; a wrong gate silently breaks
  continuity or false-greens the matrix)
- **Depends on:** **P2** (`Cobol.Net.Editions` leaf assembly exists; `EditionInfo` immutable value +
  `IDiagnosticSink` + `EditionSeverityPolicy` + a byte-stable `EditionContext` adapter over them; `ConstructRegistry`
  moved into `Cobol.Net.Editions` and generated from `constructs.json`; `EditionCodes`/`ConstructDialectStatus`/
  `ReservedWords*` re-homed). This phase consumes that framework — it does **not** re-create the assembly.
- **Blocks:** P14 (matrix closure + one-time equivalence proof) consumes the harness-driven VCR + the behavior
  matrix this phase stands up.

## Goal (one paragraph)

Deliver the "four compilers in one" **version-gating validator running natively on the P2 editions framework**
(`EditionInfo` + `IDiagnosticSink`, not the pre-rearchitecture `EditionContext` sink), and — the headline, least-
tracked leg — **make the version-gating audit mechanical**: the `VERSION_CHANGE_REFERENCE.md` (VCR) status column is
*derived from passing (construct × edition) fixtures*, never hand-ticked, so a stale ledger becomes structurally
impossible. Fold the five surviving inline gates into registry rows, backfill the missing 85→2002 / 2002→2014 row
sets, add a behavior-variant matrix (the currently-absent INV-3 leg), promote the INV-1 continuity sweep to a
standing in-process test that is green permissive at all four editions with every strict failure tracing to a
recognized edition-band code, and pin every gate with a negative witness. **Feature *implementation* (national data,
OO, M3/M4 surface) is OUT of scope — this phase gates, skeletons, and audits only.** **Phase 03 owns delivery of
the ENTIRE version-conformance pipeline, sequenced residue-first** (Steps 12–15): the Batch C residue migration,
the `ReservedWordEditionHints` deletion, and the `VersionConformancePass` skeleton land here.

## Exit criteria (the phase is DONE when all hold)

1. **Continuity sweep green permissive at all four editions** (`85|2002|2014|2023`), as a standing in-process test;
   every *strict* failure at ≥2002 traces to a recognized edition-band code (`COBOLNET0900–0903` or a pinned 08xx).
2. **Every gate has a negative witness** in `constructs.json` pinning its exact diagnostic code (positive at
   ≥intro / < removed; negative at intro−1 and at ≥removed).
3. **VCR status is generated by the harness** (`scripts/gen-vcr.ps1` + a `--emit-status` emitter), with a drift test
   asserting the committed `VERSION_CHANGE_REFERENCE.md` equals the generated output — **no hand ticks remain**.
4. **INV-1-strong-at-2023 golden re-match is seeded** (the full NIST golden battery re-runs byte-exact at `--std 2023
   --permissive`) and guarded by a test.
5. **Full legacy guard green** (NIST 353 MATCH) + the full greenfield battery (conformance + unit) green.
6. The validator, registry `Check`, and all gate call-sites consume **`EditionInfo` + `IDiagnosticSink`** (the P2
   framework); the `EditionContext` adapter is not on the edition-gating path.
7. **All 7 residue gates migrated** (grammar edition predicates dropped; bind-time `Check` at each recognition
   point) **+ `ReservedWordEditionHints` deleted.**
8. **The `VersionConformancePass` is the sole edition-gating funnel and the binder is edition-agnostic** (zero
   `ConstructRegistry.Check` calls in the binder).
9. **Emit is unreachable when any diagnostics exist** (no codegen on an errored tree).

## 2. Rationale — the problems this phase fixes

The edition subsystem is *conceptually* singular (`ConstructRegistry.Check` is the one funnel;
`EditionContext.Removed` the one severity seam) and, thanks to council Phases 1–2 (DEVLOG 583–599), most of the
gating is **already built** — but on the **pre-rearchitecture `EditionContext`** sink, and its **audit leg is
unmechanized and stale**. From `DESIGN-edition-framework.md` §1 and the AS-IS dossier:

- **P8 (HIGH) — the version-gating track is unaudited.** `VERSION_CHANGE_REFERENCE.md` carries **117 `TODO` rows**
  across 302 lines; VCR status is **hand-ticked**, not derived from fixtures, so the doc cannot be trusted as the
  gap list. Genuine holes exist un-catalogued (e.g. SYNCHRONIZED-on-group emits a generic `COBOL0001` under both
  2002 and 2023, no gate). — `docs/VERSION_CHANGE_REFERENCE.md`.
- **P4 (HIGH) — two parallel gating mechanisms.** A handful of gates stay inline with pinned codes and are **not
  registry rows**, so **none enter the version matrix**: `0816` END-ACCEPT (intro), `0803` ROUNDED MODE (intro),
  `0810`/`0811` ALTER / bare GO TO (removed), `0882` CALL ON OVERFLOW (removed). — `StatementBinder.Accept.cs:45`,
  `StatementBinder.cs:1229`, `StatementBinder.AlterSwitches.cs:119,137`, `StatementBinder.Call.cs:176`.
- **Missing behavior-variant leg (INV-3).** `VersionMatrixTests` computes accept/reject only; there is **no test
  that runs a construct under each `--std` and diffs stdout**. This is the weakest leg of "four compilers in one".
- **Missing 85→2002 / 2002→2014 rows.** The VCR admits (its own "Scope limit" note) there is **no 85→2002 row set at
  all** and the 2002→2014 rows are under-documented. The matrix therefore cannot assert those boundaries.
- **The continuity sweep is a bash script, not a gate.** `scripts/version-continuity-sweep.sh` proves the INV-1
  posture out-of-band; per `DESIGN-test-build-ci.md` the authoritative regression must move **in-process**
  (cross-platform `dotnet test`) so it gates every commit, not just a Linux CI loop.
- **The framework is still the old sink.** `EditionValidator(EditionContext)` and `ConstructRegistry.Check(
  EditionContext, id, where)` (see `src/Cobol.Net.Compiler/Validation/EditionValidator.cs:28,61` and
  `Validation/ConstructDialectStatus.cs:183`) consume `EditionContext`'s `List<string>` accumulators. P2 introduces
  `EditionInfo` + `IDiagnosticSink`; the validator/registry must run on those natively (P6/P9 of the design), with
  the adapter off the edition path.

**Already-built, preserve — do NOT redo** (verified in Step 0): the `EditionValidator` visitor with fail-fast
before Emit (`CompilerDriver.cs:106-116`); the `0900–0903` band (`Validation/EditionCodes.cs`); the reserved-word
generation (`scripts/gen-reserved-words.ps1` → `reserved-words.json` + `ReservedWords.Table`); the ~14 removal gates
+ the STOP-literal 85 fix (`BoundStopLiteral`); the global permissive flip + the **349/349 byte-exact** INV-1-strong
re-run (DEVLOG 588); W1.5 ~24 intro-gate → 0900 upgrades (`EditionGateHints`); the W3 XOR-2023 regate + preprocessor
`DialectLevel` threading; the loud-guard sweep + the national/boolean loud-not-implemented skeleton; the
position-aware reserved-word funnel; the 18+4 negative-corpus cases; the constructs.json metadata scrub already
carries `type-clause-2002` (provisional 2002), `logical-xor-operator-2023`, the float split
(`usage-float-short-2002` / `usage-float-binary32-2014`), and the `constant-entry-2002` / `concat-operator-2002`
seed rows. **P3 re-homes this onto P2's framework and mechanizes the audit; it does not rebuild the gates.**

## 6. Rollback / resumability

**Resume after interruption:** read STATUS; run **Step 0** (baseline + reconciliation) to re-establish ground truth;
`git log --oneline` to find the last landed `P3 step N` commit; continue at step N+1. Every step is an independent
commit boundary that leaves the battery green, so a mid-phase checkout is always in a known-green state.

**Rollback granularity:** each step is one commit; `git revert` a single step commit to back it out. Steps 3, 5, 6,
7, 9 are additive (new rows/tests/scripts) and cannot regress runtime behavior. Steps 2 and 4 touch the compile
path — their neutrality is proven by the guard + the diagnostic-text corpora; if either shows a text diff, the fix
is to restore byte-identical message strings (do NOT re-baseline goldens to a reworded diagnostic without a spec
citation — memory `feedback_diff_is_a_bug`). Steps 12–14 touch the grammar + the compile path; their neutrality
gate is the FULL legacy guard + the byte-exact NIST battery in the same change set.

**Risks & mitigations:**
- **R1 — Step 2 changes diagnostic text.** The 290-site `EditionContext` migration or the `sink.Report` rewrite
  could reword a message. *Mitigation:* copy message strings verbatim; the `EditionGateDiagnosticTests` /
  `ReservedWordPosition*` corpora are the tripwire; run them first in Step 2's verify.
- **R2 — Folding inline gates (Step 4) breaks the "still binds after permissive warn" contract.** *Mitigation:* the
  CLI reproduction (`--std 2002 --permissive --run`) proves ALTER runs 85 semantics; do not early-return on Check.
- **R3 — Backfilled rows (Step 5) over-gate a valid program** (unconfirmed 2002/2014 metadata). *Mitigation:* the
  VCR scope-limit rule — unconfirmed deltas land `status:"pending"`, never an active reject; the continuity sweep
  (Step 8) is the corpus-wide backstop (a false reject shows as a permissive break).
- **R4 — VCR generation (Step 6) churns the whole doc.** *Mitigation:* generate only the delimited block; the
  hand-written prose is outside it; `VcrDriftTests` guards the boundary.
- **R5 — The behavior-variant matrix (Step 7) reveals many un-gated semantic deltas at once.** *Mitigation:* land
  candidates as `pending` (catalogued, loud); it is a discovery tool, not a gate on the phase; burn down in P12/P13.
- **R6 — A step outside 12–14 tempts a grammar change.** Steps 0–10 gate + audit and should need none; the grammar
  work of this phase lives in Steps 12–14 (the residue migration). If one is unavoidable elsewhere, run the FULL
  legacy guard in the same commit (memory `feedback_autonomous_grammar_nist`) and flag it in the DEVLOG.
