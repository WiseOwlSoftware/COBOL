Owner: "As a test, pick one of the easier pending work items and submit it to ollama using the appropriate available
model and evaluate its response." Evaluated by the Mythos session (Claude Mythos 5.1) against the code, the spec and
the project's rules. Raw files beside this record in `2026-10-09-ollama-pb2695/`: `prompt.txt` (the 17,110-character prompt) and `qwen3.8-27b-response.txt` (the model's full output, thinking included). Nothing here changed the compiler, a golden or PB2695, which stays open for the fix lane. Earlier local-model trial: `2026-10-03-local-model-spike.md`.

## Setup
- Item: kb/Work/PB2695 (MINOR, runtime/tables, 33-line note): the EC-BOUND-SUBSCRIPT detail text prints the saturated
  long 9223372036854775807 instead of the program's subscript value. One code site, one spec rule (§8.4.2.3.4 GR2).
- Model: `qwen3.8:27b` (Ollama 0.35.1, local; the newest general/coding model of the thirteen installed; the explicit
  code model `north-mini-code-1.0:q4_K_M` was not tried). Default sampling, no tools, one shot.
- Prompt (17,110 chars, `2026-10-09-ollama-pb2695/prompt.txt`): the note body, the GR2 text, CobolTable.cs lines
  36-175 line-numbered, the saturating `CobolNum.Position(Int128)` helper, and five numbered asks (root cause, root-cause
  fix with design rationale, replacement C#, a fixed-form COBOL 2023 golden with expected output, a sibling sweep).
- Cost: 282 s wall on the local GPU; 37,677 chars out, of which 69 % is visible "thinking". Assembling the prompt by
  hand cost about five orchestrator turns, which is MORE than an Opus implementer spends orienting itself with tools.

## What it got right
1. Root cause: exact. The narrowing in `CobolNum.Position(Int128)` clamps before `CobolTable.At<T>` formats the
   `long`, so the detail can only show the clamp. Two sentences, correct, no hallucination.
2. The ODO overload's `depending` is the same mechanism (a real sibling).
3. It kept the condition's semantics (saturation must stay out of range) and quoted GR2 in the code comment.
4. It rejected a thread-local "last wide value" slot for the right reasons.

## What it got wrong
1. **The COBOL test program would not compile.** It uses `PERFORM … EXCEPTION WHEN EC-BOUND-SUBSCRIPT` (no such
   phrase in §14.9.28), `EXCEPTION-TEXT` (not in the standard: 0 hits; the functions are EXCEPTION-STATUS,
   -STATEMENT, -LOCATION, -FILE, -OBJECT), an `EXCEPTION-SETTINGS` paragraph (0 hits), `01 T(3) PIC X(10)` as a table
   (a table needs OCCURS), and `GOBACK` inside a performed paragraph. The repo's real goldens use
   `>>TURN EC-BOUND-SUBSCRIPT CHECKING ON`, `OCCURS 3 TIMES` and DECLARATIVES with USE AFTER. The model even wrote
   "I'm not sure EXCEPTION-TEXT is valid" in its thinking and used it anyway.
2. **The fix shape violates the project's rule 5 while claiming to satisfy it.** It adds `string? subscriptDisplay`
   to `At<T>` and asks the COMPILER to format and pass the wide value at every wide-subscript emission site (18
   references across six binder/model files). Nothing then forces the next carrier to pass the text (no drift test),
   the formatting runs eagerly on every access of a wide subscript (a hot path), and the knowledge "this value was
   wide" is split between the runtime's Occ overloads and the code generator. The shape that makes the next case
   automatic is an `At<T>(T[], Int128)` overload (range-check on Int128, index narrowed only inside the range, the
   message prints the true value, no saturation at all on that path), which the model considered and rejected with a
   wrong argument ("would duplicate the value's role").
3. **Hallucinated vocabulary in the sweep:** "reference-modifier bounds (REVERSED, DELETED, CONTIGUOUS subscripts)"
   are not COBOL concepts. The grep heuristic in sweep item 6 is sound.
4. It cannot probe, build, gate, run cite.py or sweep with tools; every claim above had to be checked by hand.

## Verdict
- As an implementer: NOT usable. A confident, well-formatted answer whose test is uncompilable and whose design is
  the wrong shape is the expensive kind of wrong: it reads as done and costs a reviewer a full orientation to refute.
- As a root-cause explainer on a pre-assembled bundle: good (1 of 1 correct).
- As a sibling-sweep brainstorm: partial (2 real siblings, 1 invented family).
- Economics: the human/orchestrator assembly of a self-contained prompt is the dominant cost and exceeds what an
  Opus implementer spends orienting with tools; the model's 282 s is free but its output needs an expert review.
  No lane in the current process (implementer, lander, adjudicator, refuter, clerk, locator) can take a tool-less
  one-shot model: the mechanical roles need tools, the judgment roles need accuracy on COBOL syntax this run lacked.
- Not tried, worth one more run before a conclusion about local models in general: the dedicated code model
  (`north-mini-code-1.0`) and a smaller ask (root cause + sweep only, no test program), where this run scored well.
