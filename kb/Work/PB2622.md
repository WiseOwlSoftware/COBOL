**Rule it breaks:** One rule in one place (design §5.2; dimensions.md 4: one rule written in two places). CLAUDE.md rule 1: a citation that is not checked mechanically is not a citation. The descriptor's own contract (DiagnosticDescriptor.cs:59-61) calls the descriptor the documented identity and the ISO citation of a diagnostic, but EditionContext.Error/Warning(DiagnosticDescriptor, string) forward only descriptor.Code (EditionContext.cs:206, 219). The citation and rule text the user sees are therefore the site's literal, not the descriptor's.

**Scenario:** Measured on the pin with a regex scan of src/**/*.cs for 'DiagnosticCatalog.<Name>,' followed by the call text up to ');': 862 call expressions pass one of the 517 catalog descriptors together with a message, and 720 of them (356 distinct descriptors) spell an ISO § inside the message literal. 179 of those cite a clause that the descriptor's IsoSection does not name. Most of the 179 are legitimate supporting clauses, but each is a second copy that no test checks against the first. The copies are often verbatim: ReportSumAddendUnresolved's Title is 'A SUM addend does not resolve to a data item outside the report section.' with IsoSection 'ISO §13.18.54.3 SR5' (DiagnosticCatalog.cs:1861-1863), and DataBinder.Reports.cs:4518-4519 repeats the sentence word for word with '(ISO §13.18.54.3 SR5)' appended. TableNestingTooDeep quotes §13.18.38.3 SR10's 'as long as the number of subscripts required does not exceed seven' in its Title (DiagnosticCatalog.cs:486-492), and DataBinder.Odo.cs:328-331 quotes it again. The cost of these copies has already been paid. PB388 (MAJOR, wrong_answer) shipped wrong §/rule numbers to users through hand-written message citations. PB177 arm C had to correct the same wrong '§13.18.16.3 SR3' in three places, the descriptor and its two message sites (the comment at DiagnosticCatalog.cs:1526-1530). PB1074 found a descriptor that said Warning while its only site raised an Error (the comment at DiagnosticCatalog.cs:1358-1362). PB772 found that COBOLNET1582's descriptor kept a mis-citation after the generated doc had been patched over it. docs/DIAGNOSTICS.md is rendered from the descriptor copy, and the user reads the site copy, so the document and the compiler output can disagree with no failing test.

**Target:** Amend §8.3 (2) so that the message is part of the row. A diagnostics.json row of the edition catalog carries the rule text and the citation once, as one or more arms {arm, citation, template}, where template is a positional message like the frontend record's MessageTemplate. The generator emits typed arm handles. The emit seam becomes EditionContext.Error/Warning(DiagnosticDescriptor.Arm, params object[] args), and it renders '<template> (<citation>)' from the row, so a site supplies only names and values. Title and IsoSection become the row's summary and the union of its arms' citations, both derived and never written beside them. DiagnosticRegistryDriftTests gains one more rule: no string argument of an Error/Warning/Declined call outside the generated files contains 'ISO §' or '§'. Every row's citations pass cite.py --check in the generator. Migration is mechanical per descriptor, and the golden byte image is unchanged when each template reproduces today's composed text.
