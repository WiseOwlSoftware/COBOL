# PB2650 — the FROM literal-1 edition gate covers RELEASE only

## Landed (w1040w, 2026-10-08)

ONE grammar rule for the phrase: `writeFrom`, `rewriteFrom` and `releaseFrom` (three copies of `FROM sendingOperand`
in `CobolIO.g4`) became `recordFromPhrase`, used by `writeStatement`, `rewriteStatement` and `releaseStatement`.
ONE gate on it: `VersionConformancePass.ParseArm.VisitRecordFromPhrase` replaces `VisitReleaseFrom`, names the
statement from the phrase's parent, and checks the renamed construct `from-literal-2002` (was
`release-from-literal-2002`; COBOLNET0871 kept, no code minted). The binders (`SequentialIoBinder`, `KeyedIoBinder`,
`SortBinder`) and `StatementValidation.ScreenSortMergeRecordReferences`' SR4 FROM exception read the one context.
After the fix, at `--std 85`: `gn1lit85.cob(14,17): error COBOLNET0871: FROM literal-1 requires COBOL-2002
(targeting COBOL-85) — WRITE … FROM literal-1`, and (18,19) the same for REWRITE; RELEASE unchanged; 2002 and later
run as before (`DONE`). `--permissive` refuses it too (an introduction).

Edition-gate sweep: positive `2002/pb2650_from_literal` (WRITE FROM "HELLO" / "AB" / ALL "XY", REWRITE FROM "WORLD" /
SPACE, RELEASE FROM "BRAVO" / "AL" / ALL "C"; output derived from §14.6.8.5 and §8.3.3.6.4 GR2, identical at 2002,
2014 and 2023); negatives `pb2650-{write,rewrite,release}-from-literal-85` (COBOLNET0871). Four COBOL-85 sources
that relied on the under-rejection now write an identifier, outputs unchanged: `85/l1c37_write_same_record_area`,
`85/pb1401_computed_numeric_numeric`, `85/pb367_use_procedure_is_the_section_85`,
`negative/pb854-eop-use-name-below-2002`. VERSION_CHANGE_REFERENCE row 7.34 records the derived edge;
COBOLNET_FILES_DESIGN.md states the one-rule, one-gate shape. Sibling sweep: no other statement prints a FROM or
USING literal-1 phrase with this edge (CALL's Format 1 BY CONTENT admits identifiers only at every edition,
COBOLNET0899; PERFORM VARYING FROM, INITIALIZE REPLACING BY, MOVE, INSPECT and STRING take literals at 85).

For the next implementer:
- `src/Cobol.Net.Frontend/Grammar/Core/CobolIO.g4#recordFromPhrase` — the ONE FROM phrase of WRITE / REWRITE /
  RELEASE; a new statement taking the phrase names this rule and is edition-gated by construction.
- `src/Cobol.Net.Compiler/Validation/VersionConformancePass.cs#VisitRecordFromPhrase` — the edge; per-verb phrase
  rules stay rows of `MoveBinder.cs#FromPhraseRules`, never a second gate.
- Trap: renaming a grammar rule or a Visit method orphans inventory `code-location`s
  (`SpecTraceabilityInventoryDriftTests.EveryCodeLocation_ResolvesInTheTree`, a leg-2 case in the trial) — retire
  them in the same batch (`retire-witnesses` + `retire-reason`).

## Rule

The 2023 general formats print the same phrase for all three statements: `FROM { identifier-1 | literal-1 }`
(§14.9.51.2 WRITE, §14.9.35.2 REWRITE, §14.9.32.2 RELEASE; each `cite.py --check … "literal-1"` OK), and each
statement's general rules make it the same implicit MOVE (§14.9.51.4 5) a), §14.9.35.4 7) a)). The 1985 edge is
DERIVED, not quoted (the repo holds no 1985 or 2002 text): X3.23-1985 prints `FROM identifier-1` for all three; the
`release-from-literal-2002` row records that derivation for RELEASE; none of the 459 NIST CCVS-85 programs writes
a literal after FROM in any of the three statements; and `conformance:85/l1m8_rewrite_format_85`'s header names FROM
literal-1 a later addition. GnuCOBOL 3.2 accepts all three at `-std=cobol85` (silence, as for RELEASE).

## Code site

`src/Cobol.Net.Compiler/Validation/VersionConformancePass.cs#VisitReleaseFrom` (ParseArm) gates `releaseFrom`
only; `writeFrom` and `rewriteFrom` (`src/Cobol.Net.Frontend/Grammar/Core/CobolIO.g4`, three copies of
`FROM sendingOperand`) have no gate. A two-arm divergence: the fix is one grammar rule for the phrase and one gate
on it, so the next statement that takes the phrase is gated by construction.
