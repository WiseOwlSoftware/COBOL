# PB110 — `CLASS … IN alphabet-name` / `SYMBOLIC CHARACTERS … IN alphabet-name` / FD `CODE-SET` — the coded-character-set references nothing binds

> ⚙ **flags:** wrong answer + silent (a CLASS whose integer literals are ordinals IN a non-native alphabet is built
> from the NATIVE ordinals — measured below), rejects legal source (the 2002 `CODE-SET FOR ALPHANUMERIC IS … FOR
> NATIONAL IS …` format has no production), under-rejects (§12.3.7.3 SR16g / SR17d and §13.18.13.3 SR1/SR2 never
> diagnosed) · found 2026-08-19 while landing [[PB64]] T5: the §8.8.4.4.3 SR2 refusal of a LOCALE alphabet in a class
> condition (COBOLNET1669) is ONE member of a four-site rule family, and `DataBinder.AlphabetBind` already carried a
> comment recording that the other three sites "are inert in this compiler today (no binder resolves them), so there
> is no name check to extend yet" — this note is that debt, registered.

**Spec.** §12.3.7.2: `CLASS class-name-1 [FOR {ALPHANUMERIC|NATIONAL}] IS {literal-5 [THROUGH literal-6]}… [IN
alphabet-name-4]` and `SYMBOLIC CHARACTERS [FOR …] {symbolic-character-1… {IS|ARE} integer-1…}… [IN alphabet-name-3]`.
§12.3.7.4 GR12 a) (`--check` OK): "When the literal is numeric, the ordinal number of a character within the relevant
native character set, or, when the IN phrase is specified, within the character set referenced by alphabet-name-4";
GR11 b) (`--check` OK): symbolic-character-1 is "the coded character at ordinal position integer-1 in the native
alphanumeric character set or, if the IN phrase is specified, in the character set referenced by alphabet-name-3".
§12.3.7.3 SR16g / SR17d (`--find` OK): "Alphabet-name-3 / -4 shall not reference an alphabet specified with the LOCALE
phrase". §13.18.13.2 CODE-SET: `{ IS alphabet-name-1 [alphabet-name-2] | { FOR ALPHANUMERIC IS alphabet-name-1 | FOR
NATIONAL IS alphabet-name-2 }… }` (choice indicators — either or both FOR phrases, any order); §13.18.13.3 SR1
(`--check` OK): "Alphabet-name-1 shall reference an alphabet that defines an alphanumeric coded character set"; SR2
national; §13.18.13.4 GR2 (`--check` OK): on OPEN "the coded character set used to represent alphanumeric data on the
storage medium is the one referenced by alphabet-name-1".

**Measured** (`--std 2023`, `scratchpad/probe109.cob`):
```
       SPECIAL-NAMES. ALPHABET REV IS "Z" THRU "A"
                      CLASS BYORD IS 66 THRU 68 IN REV.        *> ordinals 66-68 IN REV
       01 X PIC X(3) VALUE "ABC".   IF X IS BYORD -> BYORD-X=yes    (the NATIVE ordinals 66-68 = "ABC"; IN REV ignored)
```
`SwitchBindClass` reads `cd.cobolWord(0)` (the class-name) and never `cd.cobolWord(1)` (the IN alphabet);
`LiteralChars` maps an integer to `(char)(ordinal - 1)` — the native sequence — unconditionally. The
`symbolicCharactersClause` entry in `SwitchBindSpecialNames` is a `continue` ("accepted-inert (unbound)"). The FD
`codeSetClause : CODE_SET IS? cobolWord` (CobolData.g4) is the COBOL-85 single-name form — `CODE-SET FOR ALPHANUMERIC
IS A FOR NATIONAL IS B` is a parse error — and no binder reads it (`grep codeSetClause src/Cobol.Net.Compiler` →
nothing).

**Fix shape (one helper, four sites).** (1) `DataBinder.CodedCharacterSetAlphabet(name, site, rule)` — resolves an
alphabet-name to the coded character set it identifies per §12.3.7.4 GR7 / Table 6, refusing a LOCALE alphabet with
COBOLNET1669 (the `IsLocaleAlphabet` predicate PB64 T5 introduced — the class-condition arm already uses it) and an
undeclared name with the existing undeclared-alphabet diagnostic; resolution AFTER the SPECIAL-NAMES walk (the
clauses are order-free — the same deferred shape as `ResolveProgramCollating`). (2) `SwitchBindClass`: an integer
literal under `IN alphabet-name-4` is the ordinal in THAT set (a literal alphabet: its collating-sequence position;
STANDARD-1/2: ISO 646; NATIVE: as today); SR17b2's range check against that set. (3) SYMBOLIC CHARACTERS: bind the
clause at last — the figurative constants (§8.3.4 symbolic-character) with the GR11 value, `IN` per (1). (4)
CODE-SET: the 2002 grammar (`codeSetClause : CODE_SET (IS? cobolWord cobolWord? | (FOR (ALPHANUMERIC|NATIONAL) IS?
cobolWord)+)`), SR1/SR2/SR3 in the FD binder, and GR2 in the file I-O layer — the on-medium coded character set is the
record's byte encoding for a LINE SEQUENTIAL / SEQUENTIAL file (today every file is the native encoding). Goldens for
each; the PB109 class-condition set derivation shares (1)'s Table-6 mapping — land them together or (1) first.
