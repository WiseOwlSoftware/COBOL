# PB1125 — OPEN

## The rule
> "Both the ALL and LEADING phrases are transitive across the operands that follow them"
`cite.py --check 14.9.22.4 "Both the ALL and LEADING phrases are transitive across the operands that follow them"` → `OK  §14.9.22.4 10)  (General rules)`

## Measured (adjudicator / refuter evidence, verbatim)
### [inspect-statement-p1] The INSPECT grammar over-generates the printed formats and the binder accepts the extra shapes without a diagnostic: several FOR clauses per counter, an adjective-less first operand, and repeated BEFORE/AFTER on CONVERTING
- **Rows:** FMT-14.9.22.2 — harm `under-rejects`
- **Repro:** INSPECT X TALLYING N FOR ALL 'A' FOR ALL 'B' (N=04); INSPECT X TALLYING N FOR 'A' (N=02); INSPECT X REPLACING 'A' BY 'Z' (ZBCZB); INSPECT X CONVERTING 'ABCDEF' TO 'abcdef' BEFORE 'E' BEFORE 'C' (abCDEF - last one wins); ... AFTER 'A' AFTER 'C' - all at --std 2023
- **Expected (spec):** Each is a syntax error: the tallying-phrase prints one `identifier-2 FOR` per outer repetition and requires CHARACTERS/ALL/LEADING before the first operand; the replacing-phrase requires CHARACTERS/ALL/LEADING/FIRST; the after-before-phrase's choice indicators allow each of AFTER/BEFORE at most once (§5.2.6.4).
- **Observed:** inspectTallyingItem is `dataReference inspectForClause+`; inspectCountPhrase's {IsBareInspectOperand()}? arm and inspectReplacingItem's optional adjective admit a first bare operand (binder seeds All 'for that (ungrammatical) case'); inspectConvertingPhrase uses `inspectBeforeAfterPhrase*` while TALLYING/REPLACING use inspectDelimiters (at most one of each) - two arms for one after-before-phrase, only one right. If any shape is to be kept as a GnuCOBOL/IBM extension it must be dialect-gated (--permissive), not accepted at strict --std.
- **Code site:** src/Cobol.Net.Frontend/Grammar/Core/CobolIO.g4#inspectTallyingItem / #inspectCountPhrase / #inspectReplacingItem / #inspectConvertingPhrase; src/Cobol.Net.Compiler/Binding/Procedure/Verbs/InspectBinder.cs#BindPhraseOperands

### [inspect-statement-p2] The tallying-phrase's end-of-transitive-list predicate IsBareInspectOperand() is `LA(2) != FOR`, which recognizes the next identifier-2 only when it is one bare word; a subscripted, qualified or reference-modified identifier-2 is parsed as one more transitive ALL/LEADING operand of the previous counter and its FOR clause re-attaches to the previous counter
- **Rows:** GR-14.9.22.4-10 — harm `wrong-answer`
- **Repro:** 01 S1 PIC X(6). 01 N PIC 9 VALUE 0. 01 CT. 05 C PIC 9 OCCURS 3 VALUE 0. 01 G. 05 M PIC 9 VALUE 0. MOVE 'AAB' TO S1. INSPECT S1 TALLYING N FOR ALL 'A' C(1) FOR ALL 'B' -> N=3 C=000; INSPECT S1 TALLYING N FOR ALL 'A' M OF G FOR ALL 'B' (N reset) -> N=3 M=0. (E:/Temp/claude/E--CobolSharp/a700c052-f9e4-4942-84ff-a13c7505d6ec/scratchpad/adj-d1/out/probe/inspect-p2/p6.cob)
- **Expected (spec):** N=2 and C(1)=1 (resp. M=1): in §14.9.22.2's tallying-phrase an operand is never followed by FOR, so `C(1) FOR` / `M OF G FOR` can only be the next `identifier-2 FOR`; GR10 makes ALL transitive only 'across the operands that follow'.
- **Observed:** CobolParserCoreBase.IsBareInspectOperand() => TokenStream.LA(2) != CobolLexer.FOR; for `C ( 1 ) FOR` LA(2) is '(' so the bare alternative is taken, C(1) becomes pattern '0' of N's ALL list, and `FOR ALL 'B'` is parsed as a second inspectForClause of N. No diagnostic; silent wrong count at every edition. The predicate must look past the whole dataReference extent (subscripts, qualifiers, ref-mod) for FOR.
- **Code site:** src/Cobol.Net.Frontend/Parsing/CobolParserCoreBase.cs#IsBareInspectOperand; src/Cobol.Net.Frontend/Grammar/Core/CobolIO.g4#inspectCountPhrase

### [inspect-statement-p3] The bare-operand predicate IsBareInspectOperand() is `LA(2) != FOR`, so a SUBSCRIPTED (or qualified / ref-modified) next TALLYING counter such as `CNT(I) FOR …` is swallowed as a transitive pattern operand of the previous counter and its FOR clause attaches to that counter: legal source is silently mis-parsed
- **Rows:** FMT-14.9.22.2, GR-14.9.22.4-6 — harm `wrong-answer`
- **Repro:** 01 X PIC X(3) VALUE "AAB". 01 I PIC 9 VALUE 1. 01 T. 05 CNT PIC 9 OCCURS 5 VALUE 0. INSPECT X TALLYING I FOR ALL "A" CNT(I) FOR ALL "B". DISPLAY I " " T.
- **Expected (spec):** I=3 T=10000. §14.9.22.2 Format 1 needs identifier-2 before each FOR, so CNT(I) is a counter, and GR6 identifies CNT(I) with I=1.
- **Observed:** Pinned cobol.exe prints I=4 T=00000. I tallies 'A','A', CNT(I)'s content and 'B', and CNT is never a counter. CobolParserCoreBase.IsBareInspectOperand only checks the token after the first token of the operand. It has to check whether the whole dataReference is followed by FOR. FMT-14.9.22.2 belongs to sibling part 1 and is recorded here because this adjudication found it.
- **Code site:** src/Cobol.Net.Frontend/Parsing/CobolParserCoreBase.cs#IsBareInspectOperand (L593); src/Cobol.Net.Frontend/Grammar/Core/CobolIO.g4#inspectCountPhrase

## What the fixer owes
Decide the end of a transitive list by parsing the next identifier and testing for FOR after it (a syntactic lookahead over `identifier FOR`, not LA(2)), and spell the printed formats: one FOR per counter, first operand requires ALL/LEADING/CHARACTERS, at most one BEFORE and one AFTER per CONVERTING. Render §14.9.22.2 (scripts/render-spec-page.py) before touching the .g4.
