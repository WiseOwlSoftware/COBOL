## What is missing

On a store left without a file by a refused retake, `KeyedStore.AdoptAgainForTransaction` makes COMMIT or ROLLBACK pay
the OPEN row and a writable fence promotion before its own work. The 2.2.1.10 prose says so; the 2.2.1.13 table rows
for COMMIT and ROLLBACK ("per file with a transaction") do not. Add the cost to those rows once PB3630 lands, and keep
the prose and the table stating it once each way (the doc describes the current compiler only).
