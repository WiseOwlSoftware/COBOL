## Repro

`E:\COBOL-coord\scratch\w1039e\k3.cob`: `REPOSITORY. FUNCTION SUM INTRINSIC.` and `COMPUTE N = SUM(1 2)` compiles
and prints 03 at `--std 85`; LENGTH does the same since PB845. The REPOSITORY paragraph first appears in COBOL 2002,
so an 85 program cannot write it.

## Code sites (a two-arm disagreement)

`src/Cobol.Net.Compiler/Validation/VersionConformancePass.cs#VisitRepositoryEntry` (about line 1618) treats a
FUNCTION-intrinsic entry as version-invariant; `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs#BindIntrinsic`'s
reserved-name arm lacks the `< 2002` gate that `KeywordOmittedFunction` has (line 299). The fix needs the edition fact
for REPOSITORY FUNCTION as a constructs.json row, and one gate both arms read.

## Landed 2026-10-11 (w1059 H)

Re-probed: `k3.cob` printed 03 at `--std 85`. The two arms of the note were one missing edition fact: the REPOSITORY
FUNCTION entry (all three 12.3.8.2 FUNCTION alternatives) had no construct row, so `VisitRepositoryEntry` gated CLASS,
INTERFACE, PROGRAM and PROPERTY but not FUNCTION, while `KeywordOmittedFunction` hard-coded 2002. New row
`repository-function-2002` (constructs.json, regenerated `.g.cs`); `VisitRepositoryEntry` gates the entry (COBOL0900
below 2002); `KeywordOmittedFunction` and the reserved-name arm's diagnostic read it through the new
`ConstructRegistry.IsAvailable`, so no second literal 2002 remains. Goldens `2002/pb2589_repository_function_keyword_omitted`
and `negative/pb2589-repository-function-at-85`.
