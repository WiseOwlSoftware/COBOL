# PB5351 - ALL literal into 9(3)V99 at 2002 and later: which value does the rule give?

**Sites:** `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/MoveEmitter.cs` (`AllLiteralNumber`, `ConvertSource`: the 85 arm versus the 2002+ positional arm; kb/Work PB5176, PB426).

**Source:** lead of the PB5141 implementer's report (`E:/COBOL-coord/scratch/reports/w20262000b-PB5141-report.md`, "New defects / leads", first paragraph); the branch reviewer added nothing.

The figurative constant is "treated as if it were an unsigned integer" (§2023:14.9.25.4 GR6d.3; `cite.py --check` OK on those words. The report wrote the locator as "GR6 d 3 b" and `cite.py` names GR6d.3 as the right designator) with N digits, where N counts the fraction digits of the receiver. That reading gives 121.00 (the integer of the repeated string, as 1985 does) as well as 121.21 (positional) for `MOVE ALL "12" TO` a `PIC 9(3)V99` item. PB5176 made `--std 85` read it as an integer (121.00) and kept the positional reading (121.21) from 2002 on, following PB426.

**Fix direction:** adjudicate the 2002, 2014 and 2023 text for which value the rule gives (render the printed page with `scripts/render-spec-page.py` if the transcription is ambiguous). Either confirm the positional reading with a recorded determination in docs/CONFORMANCE.md 3.10, or move 2002+ to the integer reading with goldens at each edition.
