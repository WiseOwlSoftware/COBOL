# PB2504

Filed by the w1033 clerk from the PB867 refuter (`E:\COBOL-coord\scratch\w1033-adj\PB867-refute.md` section 4, "Sibling finding: file it as a note").
The refuter does not call it a compiler defect: both choices fall within `§14.6.13.1.3 8)` ("If checking for the exception condition is not enabled,
the implementor defines whether or not execution will continue"), but A.1 item 70 is "required + documented" (`OK §A.1 70)`).

**Observed (pinned build `pin-97006f3`, 2002 and 2023; probes `PB867-refute\src\r9fatal.cob`, `r14gbf.cob`).**
- `RAISE EXCEPTION EC-BOUND-SUBSCRIPT` with checking not enabled terminates the run unit: "raised by RAISE with checking not enabled ... this
  implementation terminates", exit 1 (`CodeGen/EcEmitter.cs#EmitRaise` throws `CobolFatalException` for a fatal name with checking off).
- `GOBACK RAISING EXCEPTION EC-BOUND-SUBSCRIPT` into an un-TURNed activator continues, status blank, exit 0. `docs/CONFORMANCE.md` documents the
  GOBACK case as "never raised (§14.6.13.1.1)".
- So the two sibling verbs make OPPOSITE choices for the same item, and `docs/CONFORMANCE.md` documents the RAISE choice only for the EC-*-IMP
  names (DOC-A.1-100), not for the predefined fatal names of Table 13. DOC-A.1-70 is CONFORMS in the inventory but says "other fatal conditions'
  dispositions are documented with their statements", and RAISE's disposition is documented nowhere.

**Owed.** Decide whether the asymmetry is intended (adjudication, `§14.6.13.1.3 8)` is implementor latitude, so the precedence order applies: ISO, then
GnuCOBOL (which implements neither RAISE nor USE AFTER EXCEPTION CONDITION, so no guidance), then IBM/Micro Focus); document the chosen disposition
for both verbs in `docs/CONFORMANCE.md`; when `GR-14.9.29.4-1` is recorded (see `PB867`) its notes should point at that documentation.
