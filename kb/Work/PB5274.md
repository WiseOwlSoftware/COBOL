# PB5274 - at --std 85 a file SORT written (not executed) inside an input or output procedure of a SORT or MERGE is refused COBOL2700: GateSortMergeProcedures applies the 2002-and-later lexical ban at every edition, where 1985 forbids only executing one

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs` (`GateSortMergeProcedures`)

**Mechanism.** §1985:XI.4.4.3 SR1 lets a SORT "appear anywhere in the Procedure Division except in the declarative portion", and the input and output procedure rules (§1985:XI.4.4.4 GR7, GR10; §1985:XI.4.1.4 GR8 for MERGE) forbid only that the procedure's range "cause the execution of" a SORT, a run-time prohibition with no stated result. `GateSortMergeProcedures` reports COBOL2700 for a file SORT written in such a procedure at every edition (its BoundSort arm sits outside the Year >= 2023 block; kb/Work PB1139 decided it from the 2002 rule), while its MERGE arm is already 2023-only. So a 1985 program with a SORT on a path that never runs is refused.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids below. None of them is recorded: the non-conforming verdicts wait in `E:/COBOL-coord/scratch/coderead-85/p2-for-register.json`.

**Rules (4 claimed; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-GR-XI.4.4.4-7` - `§1985:XI.4.4.4 GR7` (read: PARTIAL, harm: rejects-legal-source): "The range of the input procedure must not cause the execution of any MERGE, RETURN, or SORT statement"
- `1985-GR-XI.4.4.4-10` - `§1985:XI.4.4.4 GR10` (read: PARTIAL, harm: rejects-legal-source): "The output procedure may consist of any procedure needed to select, modify, or copy the records that are made available one at a time by the RETURN statement in sorted order"
- `1985-GR-XI.4.1.4-8` - `§1985:XI.4.1.4 GR8` (read: DIVERGES, harm: rejects-legal-source): "must not cause the execution of any MERGE, RELEASE, or SORT statement"
- `1985-SR-XI.4.4.3-1` - `§1985:XI.4.4.3 SR1` (read: DIVERGES, harm: rejects-legal-source; its other half, a SORT in a debugging section, is kb/Work PB5275): "A SORT statement may appear anywhere in the Procedure Division except in the declarative portion"

**Repro.** `E:/COBOL-coord/scratch/coderead-85/out-pipe/work-slice-46/c3/sortinout.cob` (output procedure holds `IF NEVER = "Y" SORT SG ON ASCENDING KEY GR USING FI GIVING FO`, NEVER is "N"), `sortinip.cob` (the same in an input procedure), `E:/COBOL-coord/scratch/coderead-85/out-pipe/work-slice-47/S4A.cob`, `E:/COBOL-coord/scratch/coderead-85/out-pipe/work-slice-45/g8a.cob` (a MERGE output procedure); `cobol.exe --std 85 --source-format fixed --run <file>`.

**Observed (a build of origin/main f2cf36fd15, rerun 2026-11-11; main has since changed only `IndexedConnector.cs` under `src/`, which none of these repros reaches).** Each exits 65 with `error COBOL2700: a file SORT of 'SG' shall not appear in an input or output procedure of a SORT or MERGE statement (ISO §2023:14.9.40.3 SR3)` (`SW2`, `SWK` for the others).

**Expected (from the 1985 text).** Each compiles and runs (sortinout prints AAA, BBB, DONE).

**Fix direction (root cause, CLAUDE.md rule 4).** Move the SORT arm under the same edition test as the MERGE arm (the lexical ban is a 2002 rule; check §2002 for its edition), with the four repros as the 85 test.
