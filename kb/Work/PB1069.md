# PB1069 — LANDED (w68w, then wave 73 D)

## Harm
Only a host that runs several run units in one process sees it (the conformance test host does; an embedding host
may). A switch turned ON by run unit 1 reads ON in run unit 2; two run units on two threads that both take an
out-of-range subscript with checking off write the same scratch slot.

## What the fixer owes
Make 'a new run unit' mean a NEW `RunUnit` object (the `RunUnit.Run` shape) on the emitted driver path too, so no
field can be forgotten, and move the scratch slot onto the run unit (or `[ThreadStatic]`). Extend
`RunUnitStateDriftTests` to assert that every mutable member is fresh in the second run unit (reflection over the
members, not a hand list).

## Landed — wave 73 group D (branch `worktree-wf_1a52c830-9ba-4`): static storage belongs to the run unit too

**Re-probed first** (`w73d/probe/mws.cob --std 2002`): the method's `01 MC PIC 9 VALUE 0` was still emitted as
`private static long MC = 0L;` with no reset — the w68w remainder reproduced.

**One adoption mechanism for every static storage (rule 5).** Static data is the one kind of run-unit state a new
`RunUnit` object cannot make fresh by construction, so the run unit now ADOPTS each unit's `__ResetStatics`
(`RunUnit.AdoptStaticStorage`, keyed by the delegate so a reset is adopted once): it runs at adoption (§14.6.2.3.2 1)
— "The first time the function, method, or program in which it is described is activated in a run unit") and again
at `RunUnit.Terminate`, the ONE termination epilogue that `ProgramTable.RunMain`'s finally and `RunUnit.Run`'s finally
now both call (it also owns item 2's CloseAll, formerly written at both boundaries). Two producers feed it:
- a RECURSIVE program's / FUNCTION-ID's static WS — `ProgramTable.Register` adopts the `staticReset` it used to invoke
  once (so termination now releases it too, instead of holding its references until the next run unit's registration);
- a class's METHOD WS — `DataBinder.EmitsStaticReset` lost its unit-kind conjunct (the static channel is populated only
  for static data), `DataBinder.MethodWorkingStorageRoots` joins `StaticStorageRoots`, the ONE walk
  `RecordStructEmitter.EmitStaticReset` emits from, so each class half with method WS emits `__ResetStatics`; the
  factory overrides the new `CobolObject.__AdoptRunUnitStorage` to adopt both halves' resets (then calls base, so every
  superclass adopts its own), and `RunUnit.FactoryObject` calls it when the run unit creates the factory — which
  always precedes a method's first activation in that run unit (a method runs on a factory object or on an instance
  its factory's New made).

**Witnesses.** `conformance-test:RunUnitScopeHostTests.ASecondRunUnitInOneProcess_FindsMethodWorkingStorageInItsInitialState`
(a host runs the program twice in one process: `COUNT 1 / COUNT 2` both times, and after each run unit the host reads
the static MC back at 0; measured RED on a mutant without the adoption as `AFTER MC=2 … COUNT 3`) and
`unit:RunUnitStateDriftTests.StaticStorage_IsResetAtAdoption_OnceEach_AndAgainAtTermination`. Rows closed (batch
`w73d/batch-w73d-PB1069.json`, GAP 866 → 862): GR-14.6.11-3, GR-14.6.11-4, GR-14.6.11-6, GR-14.9.42.4-1.
