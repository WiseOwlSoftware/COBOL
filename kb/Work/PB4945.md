# PB4945 - RERUN's 1985 syntax rules are not screened

**What happens.** Under `--std=1985`, the RERUN clause of the I-O-CONTROL paragraph is parsed, and since PB4919 its
file-name-2 is required after RECORDS. But none of its syntax rules was checked. `ScreenRerunClause` (now `ScreenRerunClauses`)
(`FileControlBinder.IoControl.cs`) screens only that one shape. The rules, from §1985:VII.2.12.3 as printed:
1. SR1: file-name-1 must be a sequentially organized file.
2. SR2: END OF REEL/UNIT may be used only when file-name-2 is a sequentially organized file.
3. SR3: when integer-1 RECORDS or integer-2 CLOCK-UNITS is specified, implementor-name-1 must be given.
4. SR4: more than one RERUN clause may name a given file-name-2, but no two integer-1 RECORDS phrases, and no two END OF
   REEL or END OF UNIT phrases, may name the same file-name-2.
5. SR5: only one RERUN clause may contain CLOCK-UNITS.
Each violation compiles clean today, which is an under-rejection of illegal 1985 source. RERUN is removed at 2002 (VCR row
7.15), so these rules apply only where the clause is accepted.

**The fix.** Screen each rule in the binder, where the files' organizations are resolved. Use one diagnostic per rule, or
one diagnostic whose message names the rule. Each refusal cites `§1985:VII.2.12.3` with its SR, checked with `cite.py
--check`. Run the edition-gate sweep of the new-construct skill. Each rule needs a witness under `--std=1985` that fails on
the old code. Sweep the clause's siblings that are parsed and ignored the same way: the other I-O-CONTROL clauses (SAME AREA,
MULTIPLE FILE TAPE), each against its 1985 syntax rules.

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/FileControlBinder.IoControl.cs` (`ScreenRerunClauses`, `ScreenMultipleFileClause`, `ResolveIoControlFile`).

## Landing (wave 20261917 group A, 2026-11-07)

**Re-probe.** On the base build every violation compiled clean at `--std 85`: SR1 (`RERUN ON <relative file> EVERY END OF
REEL OF FS`), SR2 (END OF UNIT of an indexed file), SR3 (RECORDS or CLOCK-UNITS with no ON phrase or with ON file-name-1),
SR4 a/b (two RECORDS, or two END OF REEL/UNIT, phrases naming one file), SR5 (two CLOCK-UNITS clauses). The sibling sweep
found three more under-rejections of the same root (the clauses' operands were never resolved): an undefined file-name-2,
an undefined MULTIPLE FILE TAPE file-name, and a condition-name-1 that is no switch status.

**Fix.** `FileControlBinder.ScreenRerunClauses` asks the format and all five rules after the whole I-O-CONTROL paragraph
(SR4 and SR5 compare clauses): COBOL6529 (SR1, SR2), COBOL6530 (SR3, and GR2 f/g: condition-name-1 needs an ON phrase),
COBOL6531 (SR4 a, SR4 b, SR5), COBOL6496 unchanged. The ON word is file-name-1 when it names a visible file, otherwise
implementor-name-1. `ResolveIoControlFile` resolves every RERUN and MULTIPLE FILE file-name (COBOL1639), and condition-name-1
resolves against the SPECIAL-NAMES switch statuses (COBOL1639). Every rule is asked at every edition, as COBOL6496 is.

**SAME.** The 1985 SAME rules (§1985:VII.2.13.3 SR1-SR3 c) were already enforced through their 2023 counterparts
(§2023:12.4.6.4.3 SR2, SR3, SR7, SR9; COBOL2738); re-probed at 85, each refuses.

**Tests made legal.** Three `Ansi85AcceptanceTests` programs, the `rerun-removed-2002` constructs.json source and
`cases/_unassigned/rerun.cob` wrote `RERUN ON <file> EVERY n RECORDS` or `CLOCK-UNITS`, which SR3 forbids; each now names
the implementor-name SYSRR.

**Witnesses.** `conformance:cases/12.4.6-I-O-CONTROL/pb4945_rerun_seven_forms_85` (accept 85) and eleven `pb4945-*`
refusals, refused at every edition.
