## What the code does today

- `src/Cobol.Net.Compiler/Oo/OoClassTable.cs#Build` builds every class's roster from METHOD-ID paragraphs and runs
  MarkRoster (OVERRIDE/FINAL, COBOLNET0837/0838/0839) — it screens a GET/SET PROPERTY METHOD-ID only on
  `HasUsing`/`HasReturning` booleans (COBOLNET0842), and stages an interface GET/SET PROPERTY prototype
  (`DiagnosticCatalog.OoInterfacePropertyPrototype`, 0899).
- `src/Cobol.Net.Compiler/Oo/OoDriver.cs#BindClassData` then, per class in SOURCE order, calls
  `src/Cobol.Net.Compiler/Binding/DataBinder.Oo.cs#OoBindPropertyClauses`, which appends the clause accessors
  (`AddAccessor` → `TryAddMethod`), enforces §11.7.3 SR5 only as a roster collision, and walks `cls.Base` rosters for
  §13.18.42.3 SR4 — which, for a subclass bound before its base, has no accessors yet.
- `src/Cobol.Net.Compiler/Binding/ReferenceResolver.cs#OoTryBindPropertyReference` recognizes `name OF x` only when
  `x` is ONE bare word naming a class or an unsubscripted typed reference, refuses a group-valued property (0899), and
  picks `get?.Returning ?? set!…` as the temp's model without comparing them.
- `src/Cobol.Net.Compiler/Binding/Bound/BoundStores.cs#StoreKindOf` returns null for 13 statement kinds (SET object
  reference, SET pointer, ALLOCATE, …), and `OoBinder.cs#OoWrapPropertyOps` turns every null into COBOLNET0843.

Measured (this tree): OVERRIDE of a clause accessor → 0838 (legal source refused); a FINAL clause accessor redefined
without OVERRIDE → compiles, `N=9` (under-reject); `PROPERTY WITH NO GET` + explicit GET PROPERTY → compiles;
`SET PROPERTY BAL` with two USING formals → compiles; GET PROPERTY returning ACTIVE-CLASS → compiles; GET `PIC 9(5)` /
SET `PIC X(3)` → compiles and runs `SET:00005`; `01 P TYPE T PROPERTY` over `T TYPEDEF BASED` → compiles (the written
`BASED PROPERTY` twin is COBOLNET2333); `SET R OF A TO A` → 0843; `MOVE GRP OF A TO W` (group-valued) → 0899;
`DISPLAY BAL OF I` (interface-typed) → 0899 at the prototype + COBOLNET1639.

## Proposed single structure

1. **`OoPropertySymbol`** on the class (instance and factory halves) and on the interface: name, GET accessor, SET
   accessor (each an `OoMethodSymbol` that is either explicit — a METHOD-ID GET/SET PROPERTY — or clause-generated),
   FINAL, and the ORIGIN (clause data-name or explicit). It is built INSIDE `OoClassTable.Build` from the PARSE TREE
   before MarkRoster (the clause's name, WITH NO GET/SET and IS FINAL are all syntactic), so OVERRIDE/FINAL/SR4 a)
   resolve over one roster in one pass, and §13.18.42.3 SR4 walks base symbols that exist regardless of source order.
2. **One screen per rule, once, on the symbol:** §11.7.3 SR5 (explicit accessor for a data-name that carries ANY
   PROPERTY clause, NO GET/NO SET included), SR6/SR7 (formal COUNT and ACTIVE-CLASS, asked where the bound header is
   first known — `DataBinder.OoBindMethodData`), §8.4.3.9.3 SR7 (GET returning vs SET using, through the ONE
   §14.8.2.3.2 identity comparator — PB1780's relation), §13.16.3 SR21 on the COMPOSED entry (a `DataItem` PROPERTY
   fact read by `DataBinder.ScreenComposedBased`).
3. **Reference side:** a property reference is identifier Format 7 resolved by the ordinary identifier resolver
   (qualification, subscripts, then `OF` property — §8.4.3.1.4 GR1), whose object is any object-reference identifier
   (PB1782's tier: SELF, `x OF SUPER`, a subscripted/qualified reference, a chained property, an inline invocation);
   the receiver's TYPE selects the property symbol (class or interface), and the temp's description is the symbol's
   one (SR7 guarantees GET and SET agree). Polarity comes from a store taxonomy with NO null arm: every bound
   statement kind classifies each operand (sending / receiving / read-write), so `SET R OF A TO A` is a receiving
   use by construction; a drift test asserts `StoreKindOf` is total over the bound-statement visitor.
4. **Group-valued and interface properties** fall out: the temp is built from the symbol's description whatever its
   category (a group included), and an interface-typed receiver dispatches through the interface's property symbol
   (the C# interface carries the accessor pair).
