# PB3384 — a folded file and its narration outlived the fold

A lead from the Mythos lane's PB3334 finisher ("tests/nist/chains.tsv is a stale copy of corpus.tsv's chain column and
should go"), checked and fixed by the operator on 2026-10-18.

**What was found.** At P0, `tests/nist/corpus.tsv` folded the chain table into its `chain-preds` column
(DESIGN-test-build-ci.md section 3.2; DEVLOG entry 667, verdict-equivalent 349/349). But `tests/nist/chains.tsv` was
never deleted. On 2026-10-18:
- nothing read it (`git grep` across `scripts`, `tests` and `src` found only comments);
- its own header still declared it "the ONE chain source of truth";
- the docs described the pre-fold state as current:
  - DESIGN-test-build-ci.md §1.2: "a hand-maintained ~318-row `[InlineData]` list", "three sources of truth";
  - the same doc's §6 risk 4, still open;
  - plan Phase 14: a rationale bullet, a precondition saying "fold … chains.tsv", a risk, and "`chains.tsv` KEPT
    (bash guard/sweep still read it)";
- the code comments narrated the fold ("the former chains.tsv").

**Fixed in this landing.**
- `tests/nist/chains.tsv` is deleted.
- The design doc, the plan and the comments in `CorpusManifest.cs`, `NistDifferentialTests.cs` and `corpus.tsv`'s
  header now state the current shape: `corpus.tsv` is the one source of the green set and of every chain. No line
  names the deleted file except the DEVLOG history and one dated status quote in the plan.

**The pattern (the owner, 2026-10-18: "You seem to have a habit of failing to remove obsolete information after a
change of process").** A change that folds or replaces a source deletes the old source and every sentence that
describes it as current, in the same change (CLAUDE.md rules 4 and 6).
