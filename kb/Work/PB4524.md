# PB4524 — formatted-time-offset-sign-under-one-hour: FORMATTED-TIME / FORMATTED-DATETIME: a negative offset under one hour is written with a plus sign

Filed 2026-11-03 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-batch-3000-20261103`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

FORMATTED-TIME and FORMATTED-DATETIME with an offset format write a negative offset of less than one hour (argument-3
from -1 to -59) with a plus sign: -45 becomes `+00:45` instead of `-00:45`. The returned value then describes a different
instant.

## Minimal test case

Free reference format (`-free`).
```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. OFFSIGN.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 WS-OFF PIC S9(4) VALUE -45.
PROCEDURE DIVISION.
    DISPLAY "A [" FUNCTION FORMATTED-TIME
        ("hh:mm:ss+hh:mm" 3600 WS-OFF) "]"
    DISPLAY "B [" FUNCTION FORMATTED-TIME
        ("hhmmss+hhmm" 3600 WS-OFF) "]"
    DISPLAY "C [" FUNCTION FORMATTED-DATETIME
        ("YYYYMMDDThhmmss+hhmm" 1 3600 WS-OFF) "]"
    STOP RUN.
```

## Environment

cobc (GnuCOBOL) 3.2.0 on WSL2 Ubuntu. `cobc -x -free -std=cobol2014 -o p prog.cob && ./p`.

## Observed result

```
A [01:00:00+00:45]
B [010000+0045]
C [16010101T010000+0045]
```
Exit code 0.

## Expected result (per ISO)

§2023:15.41.4 rule 3 (2014 and 2023): "the offset in argument-3 is reflected directly in the offset portion of the returned
value"; §2023:15.40.4 rule 3 says the same of FORMATTED-DATETIME: "the offset in argument-4 is reflected directly in the
offset portion of the returned value". §2023:15.3.3.6.1 gives the sign position its meaning: a plus sign means the time is adjusted downward to give UTC, and
"A minus sign to indicate that the common time portion of the data is adjusted upward by the offset values to represent
UTC". An offset of -45 minutes is therefore written with a minus sign. Expected:
```
A [01:00:00-00:45]
B [010000-0045]
C [16010101T010000-0045]
```
An offset of -60 or below is written correctly (`-01:00`, and `-01:45` for -105); -1 gives `+00:01`.
The same rules are in the committee draft that led to ISO/IEC 1989:2014 (CD 1.2, 2009).

## Our compiler

WiseOwl COBOL (fresh judge) prints the expected output above.

## Fix site

libcob/intrinsic.c (read in a 3.3-dev tree), `add_offset_time`: the sign comes from formatting `hours = offset / 60`
with `%+2.2d`; for -59..-1 the integer division gives 0, which prints as `+00`, and the minutes use `abs`, so the sign
is lost.

## Draft issue

**Title:** FORMATTED-TIME / FORMATTED-DATETIME: a negative offset under one hour is written with a plus sign

cobc (GnuCOBOL) 3.2.0, WSL2 Ubuntu, `cobc -x -free -std=cobol2014 -o p prog.cob && ./p`.

With an offset time format, argument-3 is the offset from UTC in minutes. For an offset from -1 to -59 the result
carries a plus sign: `FUNCTION FORMATTED-TIME ("hh:mm:ss+hh:mm" 3600 -45)` returns `01:00:00+00:45`; expected
`01:00:00-00:45`. ISO/IEC 1989:2014 §15.41.4 rule 3 says the offset in argument-3 "is reflected directly in the offset
portion of the returned value" (§2023:15.40.4 rule 3 the same for FORMATTED-DATETIME), and §2023:15.3.3.6.1 says a minus sign in that position means the time is adjusted upward to
represent UTC. An offset of -60 is written correctly as `-01:00`; -1 gives `+00:01`.

Program (free format):
```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. OFFSIGN.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 WS-OFF PIC S9(4) VALUE -45.
PROCEDURE DIVISION.
    DISPLAY "A [" FUNCTION FORMATTED-TIME
        ("hh:mm:ss+hh:mm" 3600 WS-OFF) "]"
    DISPLAY "B [" FUNCTION FORMATTED-TIME
        ("hhmmss+hhmm" 3600 WS-OFF) "]"
    DISPLAY "C [" FUNCTION FORMATTED-DATETIME
        ("YYYYMMDDThhmmss+hhmm" 1 3600 WS-OFF) "]"
    STOP RUN.
```
Observed: `A [01:00:00+00:45]`, `B [010000+0045]`, `C [16010101T010000+0045]`.
Expected: `A [01:00:00-00:45]`, `B [010000-0045]`, `C [16010101T010000-0045]`.

In libcob/intrinsic.c `add_offset_time` takes the sign from `offset / 60`, which is 0 for -59..-1.
