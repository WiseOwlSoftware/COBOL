# PB4028 — a reader sees a dead APPLY COMMIT owner's uncommitted record

**Sites:** `src/WiseOwl.Cobol.Runtime/IO/KeyedConnector.cs:1158` (`HoldingsGate`: `if (!file.Writable) break;`).

**The question for the adjudicator (not decided here).** After an APPLY COMMIT writer is killed, an `OPEN INPUT` reader reads
the dead owner's uncommitted change with status `00` until some run unit makes a writable entry (which performs the
rollback). The reader used neither IGNORING LOCK nor a sharing phrase. Is that (a) the documented determination of
DESIGN-runtime-library.md 2.2.1.10 "As built" (2) and the bullet before it, citing Annex D.2.5, or (b) a wrong answer
against 9.1.18.5, which rolls those changes back at abnormal termination?

**Evidence.** Probe `E:\COBOL-coord\scratch\w20261740c\probe\committer.cbl`, killed after its second COMMIT, then `reader.cbl`
printed `REL 0007 R-SEVEN`, a record written AFTER the last COMMIT. The D.2.5 sentence the design cites continues "... when
the sharing mode ... is 'with all other' or 'with read only' and the 'ignoring lock' phrase is used"; this reader used
neither. The design's own D.2.5 reading at DESIGN-runtime-library.md 1836-1837 says the read is possible "only with IGNORING
LOCK" (the reviewer ran `cite.py --check`: the sentence does continue so). Yet the PB3330 close-out bullet
(`kb/Work/PB3330.md:347`) calls the same read "the documented determination ... not a defect", while the same branch's
report and DEVLOG entry raise it as an open lead. Those two statements disagree; the verdict settles which stands, and the
close-out bullet is corrected to match it.

**Alternatives named by the report.** Answer `51` while the dead holding stands; or roll back through a short-lived writable
handle at the reader's OPEN. No other lead shares this root cause.

**Needs.** An adjudicator reading 9.1.18.5, D.2.5 and the sharing rules, with the precedence for latitude (ISO, then
GnuCOBOL, then IBM/Micro Focus); on a wrong-answer verdict, an implementer note for the fix at the site above.

## Verdict (2026-10-30): WRONG ANSWER, outcome (b). The fix is PB4097.

Adjudicated by a cobol-adjudicator against `specs/ISO_COBOL.md` at main 802352531
(`E:/COBOL-coord/scratch/adj/PB4028-verdict.md`), and attacked by a cobol-refuter, which UPHELD the wrong answer and
AMENDED the fallback (`E:/COBOL-coord/scratch/adj/PB4028-refute.md`). Every quote was checked with `cite.py --check`.

- §9.1.18.5 rolls a dead run unit's uncommitted changes back at the abnormal termination, and only "then" releases the
  file and record locks: no other run unit may observe the un-rolled-back state. §9.1.17 and §9.1.16 agree. The
  implementor-defined default sharing and locking choose the READER's locks; they cannot change what the file holds
  after the rollback, so no latitude applies and the precedence stops at ISO (no owner decision).
- Annex D.2.5 (informative) does not license the read: its sentence covers a live "current run unit", sharing "with all
  other" or "with read only", and a read "with the ignoring lock phrase". The design's own reading at
  DESIGN-runtime-library.md about line 1836 ("only with IGNORING LOCK") already said so; 2.2.1.10's "As built" (2)
  contradicted it.
- The refuter's amendments: the fallback status is `61` at OPEN (§9.1.13.9 1) a)) where the dead connector's sharing was
  NO OTHER, as in the probe; `51` applies only where its sharing admitted the reader's OPEN, and rests on §9.1.16, not on
  §14.9.30.4 GR9. A written record is not a locked record (only READ sets record locks); R-SEVEN is protected by §9.1.17,
  the file lock and §9.1.18.5. It found a SECOND path: the SEQUENTIAL organization (`SequentialConnector.CommitControl.cs`
  `ReadHoldingsGate`) shows a dead transaction's uncommitted REWRITE to an OPEN INPUT reader the same way, reproduced.
- The IGNORING LOCK read after the death also returns the dead change; the preferred fix (roll back before any reader
  observes the file) covers it.

The note's "No other lead shares this root cause" was wrong: the sequential organization does, and PB4097 carries both.
The close-out bullet in `kb/Work/PB3330.md` that called the read "the documented determination ... not a defect" now
points here. The design and CONFORMANCE.md statements of the overturned determination are PB4097's sites, corrected with
the fix that makes them false.
