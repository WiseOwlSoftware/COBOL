**Landed (wave 20262076 group A, 2026-11-16).** Re-probed on a build of main e14987286b: `iclose.cob` printed
`AFTER CANCEL GST=10` and `AFTER INITIAL GST=10` at `--std 85` and `--std 2023`, as filed.

**Root cause.** `src/WiseOwl.Cobol.Compiler/CodeGen/ProgramEmitter.cs#EmitProgramClass` emitted `CloseFiles()` as one
`RuntimeApi.FileCloseIfOpen` call per internal non-SD file (`CobolFile.CloseIfOpen` -> `FileRegistry.CloseIfOpen`): a second,
smaller close beside the explicit CLOSE (`SequentialIoEmitter.cs#EmitClose`), which never did the CLOSE's statement-level work,
the I-O status store into the FILE STATUS item (`§2023:14.9.6.4 GR4`; `§1985:VII.4.2.4 GR4`).

**The shape.** One CLOSE reached several ways: `SequentialIoEmitter.cs#EmitCloseStatement` renders every CLOSE the program
executes (the CLOSE scope, the written form's Table 14 entry, the status store, then the reach's own USE hook). The explicit
CLOSE, the SORT/MERGE USING and GIVING closes, and the new `SequentialIoEmitter.cs#EmitImplicitClose` all go through it. The
implicit reach differs only where its rule says so: it runs only for a connector "that is open" (`CobolFile.IsOpen`, so a
closed file keeps its status and gets no '42'), and it passes no USE hook (`§1985:X.5.3.4 GR10`, `§2023:14.9.5.4 GR9`).
`CobolFile.CloseIfOpen`, `RuntimeApi.FileCloseIfOpen` and the one-argument `RuntimeApi.FileClose` are deleted.
`CloseSequenceDriftTests` holds it: no code-generator source but `EmitCloseStatement` renders `RuntimeApi.FileClose` or
`RuntimeApi.FileBeginClose`, `EmitImplicitClose` alone renders the open guard and passes no hook, and `EmitProgramClass`
calls it.

**Found on the way, fixed here.** A CANCEL of a RECURSIVE container whose RECURSIVE containee has no live instance built the
containee's transient instance with a null parent (`ProgramTable.cs#CancelNode`), so the new store into an outer GLOBAL FILE
STATUS item threw a NullReferenceException. `ProgramTable.cs#InstanceForClose` completes the transient parent chain
(`CancelCascadeOrderTests.CancelOfARecursiveContainer_ClosesARecursiveContaineeOnAnUnbrokenParentChain`).

unchanged. A FILE STATUS item in the LINKAGE SECTION of the cancelled program (1985 probe): the store reaches the last
call's argument (00), no failure.

exception exists"); no USE procedure and no WHEN phrase runs either way, so it is visible only through FUNCTION
