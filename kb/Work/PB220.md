# PB220

Found by the cluster-B review fleet on the pre-commit [[PB169]]–[[PB172]] tree, 2026-08-31.
[[PB170]] put its §8.8.1.1 class screen (and the §13.18.38.3 r7 index-name screen) inside `RenderSegment`'s
per-token loop, where `ResolveSubscriptName` resolves each name. But the loop has FIVE exits to the D18
materializer and three of them fire LATE — a token with no `case` arm (`**`), an unresolvable name, and a
scaled operand inside a compound segment. When one of those fires, the whole segment is re-bound through the
expression binder, which applies the same rule again to the same operand.

**MEASURED before the fix** (`01 XE PIC X(4)`, `05 E PIC X OCCURS 3`, `MOVE E(XE ** 2) TO R`):

    --std 2023            -> COBOLNET0844 count = 2
    --std 2023 --permissive -> COBOLNET0844 count = 2

One source defect, two diagnostics. Under `--permissive` the pair is worse than either lane alone would be: the
fast path warns and the D18 route warns again over the same operand.

**⛔ A `_diagnosed` DEDUPE CANNOT FIX IT, which is why the fix is structural.** The sibling screens in
`ReferenceResolver` guard with `_diagnosed.Add(dref)`, and the review's first prescription was to copy that. It
would not work: the SECOND diagnostic is emitted by a different class (`ExpressionBinder`) over a different
bound operand, with no shared key. A set can only deduplicate what one component emits.

**FIXED BY:** deferring the fast path's screens to its COMMIT POINT. `ResolveSubscriptName` now QUEUES a
`PendingScreen` (the resolved item for the class screen, or the name alone for the r7 index-name screen) and
`RenderSegment` flushes the queue only on the path that actually returns a rendered segment. Every exit to D18
returns early and discards the queue, so the deduplication is a property of the CONTROL FLOW rather than of a
set — and the NEXT late exit added to the loop is covered automatically, with no edit. The `_probing` purity
guard moved to the flush, so it lives in ONE place beside the ordering fix.

**MEASURED after:** exactly one COBOLNET0844 in each lane, and the lane's own verdict (reject / accept) is
unchanged.

**PINNED BY:** `ArithmeticOperandClassTests.ReroutedCompoundSegment_DiagnosesExactlyOnce`, a COUNT assertion in
both lanes — the shape a "does it reject?" fixture cannot express.

⚠ Related and NOT closed by this: the same order-dependence is why [[PB215]]'s third residual bullet named the
wrong exemplar. `E(IDX + 1)` never reaches D18 (every token has an arm), so the index DATA item there is
screened on the fast path and is already rejected; the residual belongs to the segments that genuinely hand off
— `E(IDX / 1)`, `E(FUNCTION INTEGER(IDX))`. PB215's bullet is corrected in that note.
