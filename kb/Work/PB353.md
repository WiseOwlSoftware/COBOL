# PB353 — a per-edition compiler with a hole where a bind bailed out early

**Rows:** `GR-14.9.41.4-20`, `GR-14.9.41.4-21` (shared with **PB352**, which owns the missing behaviour; this
note owns the gating family).

## The measurement

`cobol.exe probe/seq-start/STPRB2.cob --std 85 -o z2.dll` → **exit 0, no diagnostic**. Contrast
`probe/gate85/STPRB9.cob` — an identical `START ... FIRST` but `ORGANIZATION IS RELATIVE`:
`cobol.exe STPRB9.cob --std 85 -o z9.dll` → `error COBOLNET0900: START FIRST/LAST requires COBOL-2002 (targeting
COBOL-85) - START FIRST (ISO 14.9.41)`.

## Why that is wrong

FIRST and LAST are ONE construct, gated once. §14.9.41.2 prints ONE general format, and §14.9.41.3 SR2 only makes
the phrase MANDATORY for sequential organization rather than different. **A per-edition compiler that accepts at
COBOL-85 a construct it rejects at COBOL-85 one SELECT clause away is not four compilers; it is one with a hole.**

## The mechanism, and why it generalises

The gate is registered in `ConstructRegistry.g.cs` as `('start-first-last-2002', 'START FIRST/LAST', 2002,
COBOLNET0900)` and `VersionConformancePass` fires it on `BoundKeyedStart.Mode in {First, Last}`
(`VersionConformancePass.cs:265`). `BindStart` returns `BoundUnsupported` for a sequential file **before
constructing that node**, so nothing self-identifying ever reaches the pass.

This is the more dangerous of the early return's two costs, because unlike **PB352** it produces **no run-time
signal at all** in a program that never executes the START — the assembly is simply built for the wrong edition.

**And it generalises: any construct whose edition gate keys on a bound node's SHAPE is silently un-gated on every
path that bails out to `BoundUnsupported` before building the node.** The same shape is visible in the READ
family, where `VersionConformancePass`'s `case BoundRead sr` cannot see a sequential PREVIOUS because the
direction never reaches the node (**PB334**).

## The fix shape

Repairing `BindStart` closes these two rows, and that is the small half. The durable half is a **drift test that
every `ConstructRegistry` row's gate fires from every organization / operand shape that can reach the verb** —
which is what makes the answer automatic instead of remembered. Pair it with the `BoundUnsupported` invariant
**PB236** proposes: a node the grammar accepted and the binder refused must carry a reported diagnostic, which
also makes an un-gated bail-out impossible to ship silently.

**Code sites:** `KeyedIoBinder.cs#BindStart` · `VersionConformancePass.cs:265` ·
`src/Cobol.Net.Editions/ConstructRegistry.g.cs:19`.

## Landed 2026-09-06

**The small half was already gone, and the general shape was not.** PB352 (9bb9535f) moved the FIRST/LAST arm
above the sequential bail-out, so this note's own repro no longer reproduces: on today's tree BOTH
`probe/STPRB2.cob` (sequential) and `probe/STPRB9.cob` (relative) report
`error COBOLNET0900: START FIRST/LAST requires COBOL-2002` at `--std 85`. The MECHANISM this note generalised
was still live, on the same statement, four more times — measured at `--std 85` before this change:

| written construct | what the compiler said | what it did not say |
|---|---|---|
| `START NOSUCHF FIRST` | COBOLNET1639 | the edition |
| `START SDF FIRST` (an SD) | COBOLNET1692 | the edition |
| `START IXF KEY = NOSUCHK WITH LENGTH 3` | COBOLNET1639 + COBOLNET1756 | the edition |
| `READ NOSUCHF PREVIOUS ADVANCING ON LOCK` | COBOLNET1639 | TWO editions |
| `INVOKE NOSUCHO "M1"` | COBOLNET0823 | the edition |

**The root cause is a MIS-CLASSIFICATION, not a missing null check.** `VersionConformancePass` is two arms and
documents the test for choosing one: a gate whose identity is a RESOLVED bound fact goes on the bound arm,
everything else fires on RECOGNITION. Five gates were classified bound-arm because their bound node is
*self-identifying* — and self-identification is not the test. `BoundKeyedStart.Mode`, `BoundKeyedStart.Length`,
`IBoundRead.Kind` and `IBoundRead.AdvancingOnLock` are each assigned from `st.FIRST()/st.LAST()`,
`kp.startWithLength()`, `readDirection PREVIOUS` and `readAdvancingOnLock` and from nothing else, so the
bound-tree home bought no precision and cost the diagnostic on every bail-out path. §14.9.41.2 prints ONE
general format for FIRST/LAST/KEY and §14.9.41.3 SR2 makes the phrase MANDATORY on a sequential file rather
than different there (`cite.py --check` OK on both), so the FIRST/LAST introduction cannot be conditional on
an organization the gate never sees.

All five moved to `VersionConformancePass.ParseArm` (Step 14h.5), where-strings byte-identical:
`VisitStartStatement`, `VisitStartWithLength`, `VisitReadDirection`, `VisitReadAdvancingOnLock`,
`VisitInvokeStatement`. Two came with their own findings. `RecordLockPhrase2002` was firing from BOTH arms -
IGNORING LOCK and the retention phrase on recognition, ADVANCING ON LOCK on the bound node — which is the
pass's own "a Check for any one construct fires from EXACTLY one arm" invariant, broken, and the
two-arm-dispatch shape again. And `case BoundInvoke` was over-inclusive as well as under: `BoundInvoke` is
equally the bound form of a PROPERTY get/set re-write and of NEW / SELF-NEW, all of which were being named
"the INVOKE statement"; `invokeStatement` is a dedicated rule reached from one place, so recognition fixes
both halves. `KeyedIoBinder` now holds no edition gate of any kind.

**The durable half is `EditionGateArmDriftTests`, and it is derived, not remembered.** Two halves over ONE
adjudicated table, so they cannot disagree. STATIC: brace-match the `ParseArm` class out of the pass source,
collect each arm's `Constructs.` ids, and require every BOUND-arm id to name the resolved fact that keeps it
there (both directions — an entry for a gate that has moved is deleted with it), plus no construct gated from
both arms without an adjudication. BEHAVIOURAL: for every gated construct, take its own `constructs.json`
program, rename every procedure-division reference to a declared name so the binder must bail (declarations,
keywords, literals and the parse SHAPE untouched), and require the edition diagnostic to survive — 87 rows,
the exempt ones being exactly the bound-arm adjudications. Its liveness is asserted separately: the population
must stay >= 90 breakable rows and >= 80 broken programs must actually draw an undefined-name error, so a
mutation that stopped biting is red rather than green. **Proved red on the pre-fix pass** (checked
`9fad13e5`'s `VersionConformancePass.cs` back in): 5 failures — three survival rows (start-first-last,
start-with-length, read-previous) plus both static facts.

The PB236 invariant this note asked to be paired with is already landed and enforced
(`StatementDeferralAnnounceDriftTests` / COBOLNET1756 announced from `StatementBinder.BindStatement`), and it
held on every probe above: each refused statement carried a reported diagnostic. It was never the missing
half — what was missing is that a reported OTHER error is not the EDITION diagnostic. COBOLNET1917 was
reserved for it and is UNUSED; no new descriptor was minted (the 0900 family already carries these).

**Goldens:** five negative cases, one per moved gate, each pinning that the edition is named when the
statement also fails to bind — `tests/conformance/negative/pb353-*.cob` (PB353N1-N5).
**Rows:** `GR-14.9.41.4-20` / `GR-14.9.41.4-21` stay CONFORMS on PB352's behavioural golden and gain the
edition-gate references; GAP 2780 → 2780 (they were already closed).
**PB334's shape**, which this note cited as the same defect in the READ family, is fixed twice over: the
`IBoundRead` one-arm gate landed in e6808945, and `VisitReadDirection` now makes the organization-independence
unconditional.
