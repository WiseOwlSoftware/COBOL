#### `SR-8.3.2.2-1` — PARTIAL (adjudicator + refuter record, verbatim)

Rule: `OK  §8.3.2.2 1)` "a compilation-variable-name may be the same as any other type of user-defined word" — the first exception to `OK §8.3.2.2` "Within a source element, a given user-defined word may be used as only one type of user-defined word with the following exceptions:". Compilation variables live only in the preprocessor's directive symbol table and are consumed before the parser sees the source element, so no source-element namespace ever meets them. PROBES (pinned cobol.exe, out/probe/onetype/cv.cob) at 2002 and 2023: >>DEFINE ZQ AS 1 / PQ AS 2 / FQ AS 3 beside 01 ZQ (data-name), paragraph PQ, ALPHABET FQ IS NATIVE, and >>IF ZQ = 1 AND PQ = 2 AND FQ = 3 selecting a DISPLAY of the data item ZQ -> prints `CV A` at both (the compilation variables evaluate and the same-spelled data-name reads its own value); out/probe/cdw/cdw3.cob likewise pairs >>DEFINE DEFINE with 01 DEFINE at 2014/2023. The sentence forbids nothing, so it has no rejecting edge to verify; the permission is the whole rule and holds. No spec-derived test names the exception, so test-ref is empty. || REFUTED: PARTIAL — [SUPERSEDES the earlier line for this rule: citation corrected to 7.3.11.4 GR1] The permission lets a compilation-variable-name be the same word as any other user-defined word. A compilation-variable-name can be referenced in three places (section 7.3.11.4 GR1): compiler directives, defined conditions, and the constant entry's FROM phrase. Only the first two are consumed by the preprocessor. The adjudicator verified only those two. The FROM phrase is where the permission actually has to be resolved inside the source element: '01 J CONSTANT FROM CQ' beside '>>DEFINE CQ' AND '01 CQ CONSTANT AS ...' must take the compilation variable. The pinned compiler never gets that far, because every CONSTANT ... FROM compilation-variable-name is staged loud as not implemented (COBOLNET0899 in DataBinder.Constants.cs). So this rule's sharing arm in that context is unverifiable, and the rule has two halves of which only one is verified, which makes it PARTIAL. The root cause is section 13.10.4 GR1 staged loud; the fix belongs there, and this row would then need a re-probe. The directive and defined-condition arms do hold: >>IF ZQ = 7 AND PQ = 4 is true beside 01 ZQ and a paragraph named like PQ.
