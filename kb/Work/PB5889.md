# PB5889 - decision: an integer argument that is an integer only by an algebraic identity is refused

**Decision.** The type 6 screen (kb/Work PB5886) decides an integer argument by the TYPES of its terms and the VALUES of its
literals: an integer term (an integer literal, an integer data item, an integer function by the type its definition's table
gives for the argument types written, and sums, differences, products and non-negative powers of integer terms), items under
literal factors whose net coefficient the items' scale makes whole, and a quotient by a literal whose reciprocal terminates. It
does NOT decide by algebra. A form that is an integer only because two terms that are not integer terms are equal or cancel is
refused (COBOL1627), at every edition:
- `FUNCTION SQRT (N) - FUNCTION SQRT (N) + 5` (SQRT is a numeric function);
- `S2 - FUNCTION MAX (S2)`, `S2 - FUNCTION ABS (S2)` and `G2 - FUNCTION MAX (G2)` over a scaled S2 or G2 (MAX and ABS of a scaled
  argument are numeric functions; a one-argument MAX returns its argument);
- `FUNCTION MEAN (N, N) + 1` (MEAN is a numeric function).

**Rule.** `§2023:15.3 AR6` "An arithmetic expression that will always result in an integer value or an integer data item shall be
specified"; `§1989:A.2.2 AR4` "An arithmetic expression which will always result in an integer value must be specified" (both
cite.py --check OK). Each form above does always result in an integer, so the refusal rejects legal source: this note is that debt
(CLAUDE.md rule 3).

**Why the screen does not decide them.** A decidable rule that admitted them must prove two terms equal for every valuation: that a
call evaluated twice returns the same value (a user function, RANDOM or a function over a changing item does not), that the items
it reads share no storage with what an earlier term changes, and that the order of evaluation leaves both terms reading the same
values. That reaches into side effects and evaluation order, which the screen does not model; an identity rule short of that proof
would admit a form that is not always an integer. A form that needs an identity can be written without it (`5`, `0`).

**Goldens.** The deleted `pb4795_identity_difference_legal` is replaced by the refusal `pb5889-identity-difference`
(`cases/15.3-Arguments/`, refused at 85, 2002, 2014 and 2023); `pb5886-numeric-function-terms` refuses `S2 - FUNCTION MAX (S2)`.

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/IntrinsicArgumentRules.cs#CollectAdditive` (the call arm: a function term that is not
of the integer type is refused) and `src/WiseOwl.Cobol.Compiler/Binding/IntrinsicArgumentRules.cs#NotAlwaysIntegral`.
