# PB4387 - the sidecar entry mutex is taken and retired on every sequential WRITE

**Sites:** `src/WiseOwl.Cobol.Runtime/IO/SequentialConnector.CommitControl.cs:499` (`SequentialConnector.UncoveredChangeGuard`, called at lines 314 and 394 for `EveryHolding` and `HoldsTheRecord`), `src/WiseOwl.Cobol.Runtime/IO/Sharing/SidecarLockFiles.cs:223` (`SidecarLockFiles.RetireDirectory`; its caller at line 259), and `docs/rearchitecture/DESIGN-runtime-library.md` 2.2.2.3.

**Read at:** origin/main d40c75536.

An uncovered sequential writer (no APPLY COMMIT) whose file lock admits another writer takes the sidecar entry mutex, a lock DIRECTORY, around each change and releases it by `SidecarRegionLocks.Dispose` -> `RetireDirectory` (rename away, then delete: PB3109). That is the guarantee PB3340 R1-1 added, and it is paid once per record. On Windows each record costs a directory create, publish, enumerate and rename, then a directory rename and delete: about ten metadata operations.

Evidence (PB4278 finisher, branch `worktree-wf_ca25d124-0aa-5`; a stack taken mid-run in run 000003 shows every sequential WRITE going `CobolFile.WriteShared` -> `SequentialConnector.Write` -> `SidecarRegionLocks.Dispose` -> `SidecarLockFiles.RetireDirectory` -> `Directory.Move`):
- SQ214A (the PRINT-FILE and SQ-FS1 WRITEs) takes 3 s wall alone. In 24 concurrent copies on the Dev Drive E: (ReFS) it takes 19-30 s wall at 3-4 s CPU each, so the cost is metadata I/O, not CPU.
- Run `000002-20261101T113354Z`: OBSQ4A, SQ203A, SQ214A and IX103A each TimedOut at 120000 ms during a Dev Drive defragmentation and retrim (11:45:59Z). Run `000003-20261101T130631Z`: SQ214A alone, 3.9 s CPU over 120 s, host 57 % busy, no stall.
- The branch and the merge change nothing here: `git diff 370c842b2 38809c5d7 -- src/WiseOwl.Cobol.Runtime` is empty, and the emitted `SQ214A.g.cs` is byte-identical between its GREEN branch-head gate and its RED merged-head gate. On the merged head the four programs pass in isolation in 0.8-3 s (16/16 cases).
- Repro: `E:\COBOL-coord\scratch\finisher-PB4278\sq214a-template` (the dll taken from the compiled-program cache), run 24 times at once.

Harm: no flag. A user's program is not wrong, only slow, and only under metadata contention; the harm is to the gate (two RED landing gates, one of them whole-population), and the harm is to the process only (`process_only: true`, since a program of the user is never wrong).

Fix direction: keep PB3340 R1-1's guarantee (another writer cannot interleave inside one change) without per-record directory churn, for example the mutex held across the connector's open, or the lock directory kept for the connector's life and retired once at close. It is a DESIGN-runtime-library 2.2.2.3 change (the design doc moves with it) and carries MANDATORY-PRACTICES I11 tests: two writers interleaving, a writer killed while holding, and the exception paths of the changed WRITE, REWRITE and DELETE. A structural test pins the number of directory operations per WRITE (a count, never wall time).

Branch status: PB4278's branch `worktree-wf_ca25d124-0aa-5` is re-armed only once main carries this fix (or PB4388's, which stops the same timeout from being refused on the retry).

Related: PB3340 (the guarantee), PB3109 and PB3313 (the retire-by-rename protocol), PB3108, PB3388, PB4388 (the harness side of the same reds). Grepped `kb/Work` for `UncoveredChangeGuard` and `RetireDirectory`: only the landed PB3109, PB3313 and PB3814 name them; none covers the per-record cost.
