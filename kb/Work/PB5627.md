# PB5627 - a 2023 clause rule is cited at --std 85 where a 1985 rule governs

**Sites:**
- `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs` (`DataBinder.UniqueOrReportAmbiguous`: the COBOL1639 text and its citation)
- `src/WiseOwl.Cobol.Compiler/Binding/FileControlKeyRules.cs` (`FileControlKeyRules.Rules1985`, `FileControlKeyRules.Rules85`: the SR1 OCCURS rows, RELATIVE KEY, FILE STATUS and dynamic-length SR3 rows that still carry only a 2023 citation)
- `src/WiseOwl.Cobol.Compiler/Binding/FileControlBinder.Resolve.cs` (`FileControlBinder.ScreenFileStatusItem`, `FileControlBinder.FileStatusShapeFault`)
- `src/WiseOwl.Cobol.Compiler/Binding/LinageClauseRules.cs` (whole: the LINAGE OCCURS arm has no 1985 row)
- `src/WiseOwl.Cobol.Compiler/Binding/ReportSectionBinder.cs` (`ReportSectionBinder.SumCounterOperand85`, `ReportSectionBinder.ReportItemOperandRefused`)

**Mechanism.** kb/Work PB5361 (landed) gave `Rule1985` and `Supersedes` to the LINAGE, RECORD DEPENDING, RECORD KEY and
ALTERNATE RECORD KEY sum-counter refusals, so at --std 85 each cites the 1985 rule. The rows and arms below were left on
the 2023 citation. At --std 85 a diagnostic's cited rule must be the 1985 text (CLAUDE.md rule 1; each edition stands on
its own text).

**Members.**
1. COBOL1639 (every ambiguous reference, `UniqueOrReportAmbiguous`) cites §2023:8.4.2.2.3 SR1 ("uniqueness shall be
   established through a sequence of qualifiers that precludes any ambiguity of reference", `cite.py --check` OK) at 85,
   where §1985:IV.4.3.8.1 SR3 governs ("uniqueness must then be established through qualification for each user-defined
   name explicitly referenced", `cite.py --check` OK). Repro: `RECORD KEY IS K` (K in the FD record and in WS) at
   `--std 85`, `E:/COBOL-coord/scratch/w20262040h/u_bad_reckey.cob`; kb/Work PB5566 made it refuse.
2. The other `FileControlKeyRules` rows (SR1 OCCURS rows, RELATIVE KEY unsigned-integer, FILE STATUS §2023:12.4.5.8.3,
   whose message also names the local-storage section COBOL-85 lacks, dynamic-length SR3), `FileControlBinder.ScreenFileStatusItem`,
   and the LINAGE OCCURS arm (§2023:13.18.34.3 SR1 has no 1985 text). Repro: `ix-record-key-occurs` in
   `FileControlKeyRuleSpecTests` at 85.
3. A sum counter named ambiguously at 85: `SumCounterOperand85` reports the ambiguity and returns null, then the operand
   also reaches `ReportEntryReferenceRefused` through `ReportItemOperandRefused`, a second 2023-citing verdict.
4. Comment drift: the `ReportItemOperandRefused` doc comment (ReportSectionBinder.cs:4644) names a nonexistent
   `ReportEntryReferenceRefusalDriftTests`; the real class is `ReportItemOperandDriftTests`.

**Fix direction.** Extend `Rule1985` and `Supersedes` to every row of members 1-2 (one table, each row asking the
edition's own citation), make `UniqueOrReportAmbiguous` choose its citation by edition, and let member 3 return one verdict.
The `Every1985Designation_*` drift test in `RecordClauseRuleDriftTests` already re-derives rows from the ANSI text; extend
it to the new rows so "automatic" stays true.
