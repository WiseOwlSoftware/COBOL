## Measured

### Finding property-clause — ISO/IEC 1989:2023 §13.18.42.4 GR1, GR2, GR3; §11.7.3 SR3, SR4 a); §8.4.3.9.1 (rejects-legal-source; rows GR-13.18.42.4-1, GR-13.18.42.4-2, GR-13.18.42.4-3)

**Mechanism.** Clause-synthesized property accessors are created AFTER OoClassTable.Build's MarkRoster resolves OVERRIDE/FINAL, so they are invisible to §11.7.3 SR3/SR4a: a legal OVERRIDE of one is refused, and a FINAL one can be redefined

**Repro.** Base class CG3C OBJECT WS `01 N PIC 9 VALUE 1 PROPERTY.`; subclass CG3D INHERITS CG3C with `METHOD-ID. GET PROPERTY N OVERRIDE. ... PROCEDURE DIVISION RETURNING LK. MAIN. MOVE 9 TO LK. END METHOD.`; client `DISPLAY "N=" N OF A` on a CG3D -> COBOLNET0838 'method '__GET_N' specifies OVERRIDE but no superclass defines a method with that name'. Twin: base `01 N PIC 9 VALUE 1 PROPERTY IS FINAL.`, subclass `METHOD-ID. GET PROPERTY N.` (no OVERRIDE) -> compiles clean, prints N=9. Probes gr3_nonfinal_override, gr3_final_nooverride, gr3_final_override.

**Expected, from the standard.** GR1/GR2 make the clause 'cause a method to be defined for the containing object' and §8.4.3.9.1 calls it 'a method implicitly generated for a data item described with the PROPERTY clause', so it is a superclass method for §11.7.3: the non-FINAL OVERRIDE compiles and prints N=9; per GR3 the FINAL accessor carries FINAL, so §11.7.3 SR3 ('The method in the superclass shall not be defined with the FINAL clause') refuses the OVERRIDE form and SR4a refuses the OVERRIDE-less redefinition.

**Observed.** BinderDriver line ~333 builds OoClassTable (MarkRoster -> 0837/0838/0839 against sym.Base.FindMethod) before OoDriver runs data.OoBindPropertyClauses, which TryAddMethod's the __GET_/__SET_ accessors. MarkRoster therefore never sees them: OVERRIDE finds no base method (0838), FINAL is never consulted (0839 unreachable), and a same-named subclass method without OVERRIDE draws no 0837. The emitter sets IsFinal => non-virtual, so the subclass's `virtual __GET_N` hides the base member in C#. Fix shape: synthesize the accessors when the roster is built (from the parse tree -- names, kind, FINAL are all syntactic) so one resolution pass sees every method.

**Code site.** src/Cobol.Net.Compiler/Oo/OoClassTable.cs#Build/MarkRoster (~lines 476-560); src/Cobol.Net.Compiler/Oo/OoDriver.cs (~lines 74, 93); src/Cobol.Net.Compiler/Binding/DataBinder.Oo.cs#OoBindPropertyClauses

PROPERTY`) -> 0842 SR4. Both definition routes and the whole chain are covered. No spec-derived test exists (OoSpineTests has none for SR4), so test-ref is empty. || REFUTED: DIVERGES — SR4 is enforced only when the superclass's CLAUSE-generated accessors already sit on its roster, which depends on SOURCE ORDER: BinderDriver binds classes in source order (foreach cls in classes -> OoDriver.BindClassData -> OoBindPropertyClauses), and the SR4 walk reads b.Methods of the base.
