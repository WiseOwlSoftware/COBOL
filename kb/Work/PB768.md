# PB768 — OPEN — the drift guard blesses the launcher shape it was built to catch

Found 2026-09-06 in the PB735 implementer's report (NEW DEFECT B), which met it from the inside: its own first
draft of `ConflictMarkerDriftTests.ListTrackedFiles` rolled a private `Process.Start` + `ReadToEnd` +
`WaitForExit()`, this guard passed it, and self-review — not the gate — rewrote it onto
`ProcessObserver.ObserveOrThrow`. Verified against main (`9fad13e5`) by reading the predicate and by measuring
its complement.

## The predicate, verbatim

`tests/Cobol.Net.Tests.Unit/ProcessObservationDriftTests.cs`:

```csharp
:33   private const string Launch = "Process.Start(";
:42   private static readonly Regex BoundedWait = new(@"WaitForExit\s*\(\s*[^)\s]", RegexOptions.Compiled);
:49   private static readonly string[] Exempt =
      [ "ProcessObservation.cs", "ProcessObservationDriftTests.cs",
        "GrammarDiagramGeneratorDriftTests.cs", "VaultReferenceGeneratorDriftTests.cs" ];
:68   if (!body.Contains(Launch, StringComparison.Ordinal)) continue;
:69   var wait = BoundedWait.Match(body);
:70   if (wait.Success) offenders.Add(...);
```

So a file is an offender only if it contains BOTH needles. `WaitForExit()` with no argument does not match
`[^)\s]` after the open paren, and a file that never waits at all matches nothing either. **The class doc at
`:10-11` states the rule it means to enforce — *"Keeps the child-process observer collapsed to ONE
implementation"* — and the predicate does not enforce it.**

## ⛔ MEASURED: the complement is not empty, on main, today

`feedback_measure_the_selectors_complement` — the guard is evidence about what it RETURNED, never about what it
dropped. Every test source containing `Process.Start(`:

| file | bounded `WaitForExit(<arg>)` | unbounded `WaitForExit()` | verdict |
|---|---|---|---|
| `tests/_shared/ProcessObservation.cs` | 2 | 0 | exempt (it IS the observer) |
| `tests/Cobol.Net.Tests.Unit/ProcessObservationDriftTests.cs` | 2 | 1 | exempt (it quotes the needles) |
| `tests/Cobol.Net.Tests.Unit/GrammarDiagramGeneratorDriftTests.cs` | 1 | 0 | exempt by name |
| `tests/Cobol.Net.Tests.Unit/VaultReferenceGeneratorDriftTests.cs` | 1 | 0 | exempt by name |
| **`tests/CobolSharp.Tests.Unit/CliExitCodeTests.cs`** | **0** | **1** | ⛔ **not exempt, and PASSES** |

`CliExitCodeTests.cs:38-41`:

```csharp
using var p = Process.Start(psi)!;
string stdout = p.StandardOutput.ReadToEnd();
p.StandardError.ReadToEnd();
p.WaitForExit();
```

That is a private launcher of exactly the family plan §11 A12 extracted six copies of, sitting in the tree with a
green guard over it — and it additionally reads both pipes SYNCHRONOUSLY before waiting, the deadlock shape A12's
note records for `BinderDecompositionTests`. It is the SEVENTH copy, and the guard's own remarks (`:22-25`)
predict it: *"writing a fifteen-line process launcher is cheaper in the moment than finding the one that already
exists, so the copies grow back one project at a time."*

## Why the AND-clause protects nothing

The doc comment at `:30-32` calls the second needle deliberate: *"Either half alone stays legal — a generator
drift test that shells out to `pwsh` and waits is answering a different question than 'what did the program under
test print'."* But the two generator drift tests that argument names are **already exempted BY NAME** at `:52`.
The AND-clause therefore buys nothing that the exemption list does not already buy, and it costs the entire
unbounded-wait population. `feedback_two_arm_dispatch`: the predicate has two arms — bounded and unbounded — and
only the bounded one was ever wired to the failure.

Two smaller properties of the same block, worth stating so the fix is not over-built:

- **The exemption is by `Path.GetFileName`** (`:59`), not by relative path, so a same-named file anywhere under
  `tests/` inherits it silently.
- **The population is a `Directory.EnumerateFiles` walk** with hand-written `obj`/`bin` filters (`:55-59`), where
  [[PB735]]'s sibling guard scopes itself to `git ls-files` and gets its exclusions structurally.

## Harm

`process_only`. Nothing a user's program computes is affected. What is affected is the harness's ability to tell
a **non-observation from a wrong answer** — the whole point of A12: a private launcher hands back an empty stdout
on a launch failure, and an `Assert` on that stdout reports a value mismatch. `ProcessObserver.ObserveOrThrow`
raises `HarnessNonObservationException` instead. The cost is paid in unattributable red, which is the most
expensive kind (`feedback_comprehensive_gate_mechanics`).

## The fix shape

1. **Fire on `Process.Start(` in any test source outside `Exempt`, bounded or not, and DELETE `BoundedWait`.**
   `ProcessObserver` is the one supported way to start a child from a test; that is the rule, and it is one
   predicate (`feedback_one_rule_one_place`). The exemption list already carries the only legitimate exceptions
   and names them individually on purpose.
2. **In the same change set, land `CliExitCodeTests` onto `ProcessObserver.ObserveOrThrow`** — the widened
   predicate makes it red the moment it ships, and adding it to `Exempt` instead would be the hand-maintained
   list where a fix belongs (CLAUDE.md rule 5). If the legacy `CobolSharp.Tests.Unit` assembly genuinely cannot
   reference `tests/_shared`, that is the finding to record, not to route around.
3. **Exempt by repo-relative path, not by bare file name.**
4. ⛔ **Prove it fails once** (`feedback_green_gates_arent_evidence`): plant a `Process.Start(psi); p.WaitForExit();`
   fixture, watch it go red, remove it. A guard that has never named an offender has never been tested — this
   note exists because that was true of its unbounded arm for its whole life.

## Sweep

Same shape one layer over: [[PB735]]'s `ConflictMarkerDriftTests` had to choose a population and chose
`git ls-files` so its exclusion could not rot; this guard chose a filesystem walk plus a name list. Both are
"the extraction is not the fix, the guard is" tests — `TestRepoDriftTests` is the third, named in this file's own
remarks. If the by-name exemption is widened to a path, sweep all three for the same weakness at the same time.
