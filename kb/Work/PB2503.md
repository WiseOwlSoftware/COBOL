# PB2503

Filed by the w1033 clerk from the PB865 refuter (`E:\COBOL-coord\scratch\w1033-adj\PB865-refute.md` section 4, "Bookkeeping notes for the
operator"). Neither item is a compiler defect and neither changes the PB865 verdict.

1. **Row `SR-13.4.5.3-7`** (`tests/version-matrix/traceability-inventory.json`) names only `MaterializeImpliedRecord` and the PB345 tests, which cover
   SR7's second sentence. Its first sentence (relative and indexed FDs are Format 2) is enforced by
   `src/Cobol.Net.Compiler/Binding/FileDescriptionFormats.cs#Of` and `DataBinder.cs#FileDescriptionClauseAdmitted` and pinned by
   `conformance-suite/cases/13.4.5-File-description/pb1238-fd-linage-relative.cob`, but the row does not cite them. Owed: add the code-location and test-ref (a
   registrar edit, not a verdict change).

   elements. `docs/CONFORMANCE.md` should state whether the project claims it (`§A.4.1`: syntax is accepted only when support is claimed). The file
   says "should be checked separately"; the clerk did not check it.

Owner 2026-10-17: addressed in the SORT and file I/O campaign (kb/Work PB3353).

## Landed (w1129h, 2026-10-19)

Both items re-probed on a fresh build; neither is a compiler defect, and no compiler code changed.

1. **Row `SR-13.4.5.3-7`.** `cite.py --check 13.4.5.3 "Format 2 is the file description entry for a relative file or an indexed file."` -> OK
   (13.4.5.3 7)). Re-probe: `pb1238-fd-linage-relative.cob` draws COBOLNET2604 at `--std 85` and `2023` (the Format 2 clause list
   refuses LINAGE), `pb345-indexed-no-record.cob` draws COBOLNET1837. A `record_verdicts` batch (witness merge, verdict unchanged,
   notes restated with the first-sentence enforcement) added `FileDescriptionFormats.cs#Of`, `DataBinder.cs#FileDescriptionClauseAdmitted`
   and the tests `pb1238-fd-linage-relative` and `pb1238_fd_formats_admitted`; both cases now list `SR-13.4.5.3-7` in their `rules`.
2. **Annex A.4.11 item 10.** `cite.py --check A.4.11 "LINAGE clause (13.18.34)"` -> OK (A.4.11 10)); `--check A.4.1 "An implementation shall
   accept the syntax and provide the functionality for an optional element only when support for that language element is claimed by the
   implementor."` -> OK. The compiler implements LINAGE whole (sequential file, every `--std`; probe: `LINAGE IS 5 LINES WITH FOOTING AT 4`
   runs and `LINAGE-COUNTER` reads 2 at 85/2002/2014/2023), so the claim is YES. `docs/CONFORMANCE.md` section 5's A.4.11 row now says so,
   with the Format 2/Format 3 refusal as the general format's rule rather than A.4.1's licence, and
   `FileDescriptionFormatDriftTests.TheLinageClaim_AgreesWithTheFileDescriptionFormatTable` holds the sentence to the table.
