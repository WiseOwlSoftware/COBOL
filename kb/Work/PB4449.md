# PB4449 — over-wide phrase suppression in the recovery bookkeeping, and its wrong citation

Both findings sit in the PB4436 review branch (`worktree-wf_a56965c4-16c-9`, head 797d1e17d), not yet on main; the
members named below arrive with it. One note: same member, and the citation is the rule the suppression implements.

**1. Lost diagnostic (R2-1).** `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs:188`
(`ContinuesAStatementTheRecoveryLeft`) takes a phrase word as the left statement's own with `consume: false`, so the
record stays and EVERY later occurrence of the same phrase is suppressed, including one that ISO 14.5.3.3 says is not
associated with that statement: "If all permitted occurrences of a phrase have already been specified for a given
statement, a subsequent occurrence of that phrase is not syntactically associated with that statement"
(`cite.py --check 14.5.3.3`: OK, §14.5.3.3 4)). A genuine second fault that main reported is now silent, contradicting
the design paragraph's "a genuine later fault in the sentence is still reported". Fix direction: consume the occurrence
once the phrase's permitted count is reached (the count is in the ATN the way `PhraseWords` already reads the words).

**2. Wrong citation (R2-2).** The doc comments at `CobolErrorStrategy.cs:178` and
`tests/WiseOwl.Cobol.Tests.Unit/ParseRecoveryCascadeTests.cs:147` cite ISO 14.5.3.2 2) for "the IF's statement-1 and
statement-2 are the phrases of one IF". 14.5.3.2 2) says only that an explicit scope terminator also ends the
unterminated statements between; the phrase-association rule is 14.5.3.3's closing paragraph: "Any phrase encountered
is the next phrase of the most-recently preceding unterminated statement with which that phrase may be syntactically
associated" (`cite.py --check 14.5.3.3`: OK, as 4)). Correct both comments (and the DESIGN-frontend-grammar paragraph if
it repeats the citation).

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs` (`CobolErrorStrategy.Report`), `tests/WiseOwl.Cobol.Tests.Unit/ParseRecoveryCascadeTests.cs`, `docs/rearchitecture/DESIGN-frontend-grammar.md` (whole: the PB4382 paragraph restates the suppression rule).
