# PB5762 - a table passed BY REFERENCE with a variable subscript loses its subscript range check

**Sites (landing, one root for PB5605 and PB5762):** `src/WiseOwl.Cobol.Compiler/Binding/Model/PlaceBuilder.cs` (`PlaceBuilder.WindowScopeOf`, `PlaceBuilder.FixedLevelTerm`, `PlaceBuilder.BoundOf`, `PlaceBuilder.OdoReferenceCheckFor`), `src/WiseOwl.Cobol.Compiler/Binding/Model/Position.cs` (`OffsetTerm.Bound`, `OccurrenceBound`), `src/WiseOwl.Cobol.Compiler/CodeGen/Roslyn/PositionRenderer.cs` (`PositionRenderer.RenderIndex`), `src/WiseOwl.Cobol.Compiler/CodeGen/Roslyn/RuntimeApi.cs` (`RuntimeApi.WindowSubscript`), `src/WiseOwl.Cobol.Runtime/Values/Tables/CobolTable.cs` (`CobolTable.Subscript`), `src/WiseOwl.Cobol.Compiler/Binding/ReferenceResolver.cs` (`ResolveForAddressOf`)

**Sites (as filed):** `src/WiseOwl.Cobol.Compiler/CodeGen/Roslyn/PlaceRenderer.cs` (`PlaceRenderer.ByteWindowRead`, `PlaceRenderer.RvOffset`), `src/WiseOwl.Cobol.Compiler/Binding/Model/PlaceBuilder.cs` (`PlaceBuilder.WindowScopeOf`). This is a lead: it comes from the writer's reading of the emitted C#, and the integrator did not trace it to the line. When a BY REFERENCE argument has a variable subscript, the record becomes cell storage (an ADDRESS-OF-taken record, `_scell_TBL`). Every subscripted reference into it is then lowered as a byte window, `CobolString.Window(_redef_TBL, offset, 4)`, whose offset is built from `CobolTable.Occ(...)` with no range test. Ordinary storage uses `CobolTable.At(TBL.T, Occ(...))`, which raises EC-BOUND-SUBSCRIPT. The fix belongs where a Tier-B view's position is built from a subscript, so that every arm (read, write, the CALL argument) checks it.

**Repro** (`E:\COBOL-coord\scratch\gl2002\integrate-9\repro\close\c4.cob`, from the writer's `lane1\run\g2002u-14-8-6-1-close\`; control `c3.cob` passes the argument BY CONTENT):

```cobol
       >>TURN EC-BOUND-SUBSCRIPT CHECKING ON
       IDENTIFICATION DIVISION.
       PROGRAM-ID. G2BND.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 TBL.
          05 T PIC X(4) OCCURS 3 TIMES.
       01 IX PIC 9 VALUE 4.
       01 A4 PIC X(4) VALUE "ARG4".
       PROCEDURE DIVISION.
       DECLARATIVES.
       D-BOUND SECTION.
           USE AFTER EXCEPTION CONDITION EC-BOUND-SUBSCRIPT.
       D-BOUND-P.
           DISPLAY "DECL-BOUND [" FUNCTION EXCEPTION-STATUS "]"
           RESUME AT NEXT STATEMENT.
       END DECLARATIVES.
       MAIN SECTION.
       M-P.
           MOVE T(IX) TO A4
           DISPLAY "M1 END"
           CALL "G2BNDS" USING T(IX)
           DISPLAY "M2 END"
           STOP RUN.
       END PROGRAM G2BND.
       IDENTIFICATION DIVISION.
       PROGRAM-ID. G2BNDS.
       DATA DIVISION.
       LINKAGE SECTION.
       01 L4 PIC X(4).
       PROCEDURE DIVISION USING L4.
           DISPLAY "S RAN [" L4 "]"
           GOBACK.
       END PROGRAM G2BNDS.
```

**Observed** (golden-2002-9 integrator, `cobol.exe c4.cob --std 2002 --run`): `M1 END`, `S RAN [    ]`, `M2 END`, rc 0. No declarative runs, the MOVE reads four bytes past the table, and the callee runs on them. `--std 2023` gives the same output. The control `c3.cob` differs only in passing the argument `BY CONTENT`. It prints `DECL-BOUND [EC-BOUND-SUBSCRIPT             ]`, `M1 END`, `DECL-BOUND [EC-BOUND-SUBSCRIPT             ]`, `M3 END` at both editions, which is correct.

**Expected:** the c3 output with `M2 END` in place of `M3 END`. That is `DECL-BOUND [EC-BOUND-SUBSCRIPT             ]` at the MOVE, again at the CALL, and G2BNDS is not called. These rules were each checked with `python scripts/spec/cite.py --check`, verdict OK:
- `§2002:8.4.1.2.3 GR2`: "The highest permissible occurrence number for any given dimension of the table is the maximum number of occurrences". A subscript greater than that sets EC-BOUND-SUBSCRIPT to exist, and that condition is Fatal in the 2002 exception-name table.
- `§2002:14.8.4.3 GR3a`: "If an exception condition exists, no program is called and execution proceeds as specified in general rule 3g". The condition is not an EC-PROGRAM one, so the declarative runs.

**Harm:** an out-of-range subscript is checked or not depending on whether the same table is passed BY REFERENCE anywhere in the program. When it is not checked, the program reads and writes past the table silently. The writer's draft `g2call13_execution_arms` (leg L7) is held out of the tree under `gl2002\lane1\out\g2002u-14-8-6-1-close\` until this is fixed. Its other nine legs pass.

**Rows:** `2002-GR-14.8.4.3-3` waits on this. The fix's golden is g2call13 at 2002 plus a 2023 twin, since 2023 behaves the same way.
