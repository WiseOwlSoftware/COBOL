# PB6014 - a pending unit's quotation is attributed to the unit row before it

**Site:** `scripts/spec/cite.py` (`resolve`, line 740: `book.rule_at(cited.locator, at)`; the extent `rule_book` gives a
row minted from a unit, `RuleBook.rule_at`).

**Repro** (base be6c60fd80 and branch train85b-cat alike):

    python scripts/spec/cite.py --check "§1985:IV.4.2.2.1.3" "There are three types of reserved words"
    OK  §1985:IV.4.2.2.1.3  (4.2.2.1.3 Reserved Words)  the text is in the clause; it lies in p1

The words are unit p3, whose disposition is `pending` (kb/Work PB6001); p1 is the SR row `1985-SR-IV.4.2.2.1.3-p1`.
The design ("Phase A, continued", point 5) says a quotation inside a unit with no row answers `OK §<clause> (unnumbered
prose, pending)` and never names the rule above it (kb/Work PB222's repair). The pending branch is taken only when
`rule_at` finds no row, and a unit row's extent runs on past its own paragraph to the next row, so it swallows every
later pending unit of the clause. Same on `§1985:XIII.3.10.7` "A blank entry in column 1 or column 2 indicates" (answers
`p4` on the base, `p3` on the branch, the unit's own row: right only by luck of the extent).

**Fix direction:** a row minted from a unit has the unit's own lines as its extent (`text_units.Unit.lines`, which
PB6001 added for the prose-holes measure), so `rule_at` finds no row for a pending unit's line and the answer is the
pending one. Sweep the stored citations whose `--check` answer names a unit row (`cite.py`'s citation audit).
