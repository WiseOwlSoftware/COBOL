# PB3920 — boolean-class-condition-not-supported--is-boolean: Class condition 'IS BOOLEAN' (ISO 2002/2014) is refused with 'syntax error, unexpected BOOLEAN'

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S8) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\boolean-class-condition-not-supported--is-boolean.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\boolean-class-condition-not-supported--is-boolean\`.

## Summary

GnuCOBOL 3.2 refuses the class condition `identifier-1 IS [NOT] BOOLEAN` on an alphanumeric item, under
`-std=cobol2014` and under the default dialect: `syntax error, unexpected BOOLEAN`. The BOOLEAN class test is part
of ISO/IEC 1989 since the 2002 edition and is in the 2014 edition that `-std=cobol2014` claims. Class: feature
missing. This is one of two mechanisms filed together as boolean-class-condition-not-supported; the other, a boolean
COMPUTE over PIC 1 items, is recorded as boolean-class-condition-not-supported--boolean-compute.

## Minimal test case

Free reference format (`-fformat=free`), 10 lines, written for this record. File:
`E:\COBOL-coord\scratch\op\pb3838\records\boolean-class-condition-not-supported--is-boolean.cob`. The witnesses
fz00990, fz00991, fz03456 (night 2) and fz01199 (night 3) all stop first on `unexpected BOOLEAN` at an `IS BOOLEAN`

## Expected result (per ISO)

The program is legal and prints `A BOOLEAN` then `B NOT BOOLEAN`.

- ISO/IEC 1989:2023 §8.8.4.4.2 (checked): the class condition's general format lists `BOOLEAN` among its
  alternatives, `identifier-1 IS [ NOT ] { ... | BOOLEAN | ... }`.
- §8.8.4.4.3 3) (checked): "If the alphabet-name-1, ALPHABETIC, ALPHABETIC-LOWER, ALPHABETIC-UPPER, BOOLEAN, or
  class-name-1 phrase is specified, identifier-1 shall reference a data-item whose usage is display or national." A and
  B are usage display. §8.8.4.4.3 5) (checked): "BOOLEAN shall not be specified if the category of the data item
  referenced by identifier-1 is numeric or numeric-edited." A and B are alphanumeric, so the test is allowed.
- §8.8.4.4.4 3) e) (checked): "If BOOLEAN is specified, the condition is true if the content of the data item
  referenced by identifier-1 consists entirely of the boolean values '0' and '1'." "101" does; "1A0" does not, and
  §8.8.4.4.4 2) (checked): "If the word NOT is specified, the truth value is reversed."

Edition: a 2002 feature, present in 2014. The ISO/IEC 1989:2002 text (§8.8.4.1.3) and the 2009 committee draft that
became ISO/IEC 1989:2014 (CD 1.2, §8.8.4.1.3) both list BOOLEAN in the class condition's general format and carry
general rule 3) e) in the 2023 wording; Annex E of the 2023 standard lists no change to it.

Edition as recorded by the adjudicator: 2014 (introduced 2002). `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Our compiler (WiseOwl)

WiseOwl COBOL (built from main 6ed90bd1c), `cobol iscb.cob --std 2014 --source-format free -o iscb.dll`, then

## Fix site (GnuCOBOL 3.2 source, read observationally)

- `cobc/parser.y`, rule `condition_or_class` (line 18532): the class-condition arms are `NUMERIC`, `ALPHABETIC`,
  `ALPHABETIC_LOWER`, `ALPHABETIC_UPPER` and `CLASS_NAME`; the line after them (18547) is a source comment marking
  BOOLEAN as missing ("CHECKME: seems missing | BOOLEAN"). The `BOOLEAN` token exists (line 2559) and is used in the
  USAGE and category rules.
- The run-time test would sit with the other class tests built from the operators pushed by `condition_or_class`
  (`cobc/tree.c` and `cobc/typeck.c`, the `'A'`/`'L'`/`'U'` arms); libcob has no boolean class test.
