# PB72 — LANDED — Table 16's alphabetic/edited/noninteger axes are partial, and a ref-mod view carries the inner item's finer flags

> ✅ **LANDED 2026-08-09 (with PB59 family 7's rider — one landing, same edit sites):** the four missing
> `MoveTable16.Refusal` arms (alphabetic column + row, the alphanumeric-edited row's numeric leg — its

> caught it — and the noninteger row's alphanumeric leg), `Table16Operand.Of(Place)` (the GR2/GR6
> ref-mod erasure), both MoveBinder positions and the OoBinder BY CONTENT crossing rebuilt through it
> (the Place now travels, not `.Item`). All eight probes flip/hold as derived; negatives `pb72-move-*`,
> golden `pb72_table16_admitted_cells`, SR-14.9.25.3-10 blank→CONFORMS. The two open derivations moved
> to [[PB73]] (kind: adjudication).

> ⚙ **flags:** wrong-answer (silent stores through refused cells), rejects-legal-source (the ref-mod
> erasure). Found 2026-08-09 by the PB59 family-7 scout's scan-all-similar sweep over the printed
> Table 16 (specs/ISO_COBOL.md:25263, read as printed); six cells CLI-probed.

**The mechanism.** `MoveTable16.Refusal` implements only the arms "around the NEW categories"
(boolean/national rows+columns); the classic path admits the whole alphanumeric-family × numeric
plane. And `MoveBinder`'s Table-16 position construction reads the finer flags (`IsAlphabetic`,
`IsEdited`, `IsNonInteger`) from `Place.Item.Pic` — which for a `RefModPlace` is the INNER item, while
§8.4.3.3.4 GR2/GR6 make every usage-DISPLAY ref-mod view CLASS AND CATEGORY ALPHANUMERIC (never
alphabetic, never edited, never numeric; GR1 + SR5 admit no alphabetic result anywhere in the ref-mod
scheme).

**Measured (2026-08-09, all six probed):**
1. `MOVE 5 TO PIC A(4)` ACCEPTED — Table 16 Numeric-Integer × Alphabetic = No (stores "5   ").
2. `MOVE PIC-A TO PIC 9(3)` ACCEPTED — Alphabetic × Numeric = No (stored 000 for "ABCD").
3. `MOVE PIC-XXBXX TO PIC 9(3)` ACCEPTED — Alphanumeric-edited × Numeric = No.
4. `MOVE 5.5 TO PIC X(6)` ACCEPTED — Numeric-Noninteger × Alphanumeric = No.
5. `MOVE A-ITEM(1:2) TO PIC 1(2)` REFUSED 0819 — the view is plain alphanumeric (GR2/GR6), and
   Alphanumeric × Boolean = Yes: legal source rejected.
6. `MOVE AE-ITEM(1:2) TO PIC 1(2)` REFUSED 0819 — same erasure, the GR6a leg.

**Fix shape (lands WITH PB59 family 7 — same edit sites, same axis):** complete `MoveTable16.Refusal`
to the full printed table over the modeled categories (the alphabetic column+row arms, the
alphanumeric-edited row's numeric leg, the noninteger row's alphanumeric leg); add
`Table16Operand.Of(Place)` routing a ref-mod view through the GR6 rewrites (category via
`RefModPlace.CategoryOf`, finer flags all false); rebuild `MoveBinder`'s sender/receiver positions
through it; pass the PLACE (not `.Item`) through `OoBinder.OoContentMismatch` so the INVOKE BY CONTENT
crossing gets the same answer (two-arm discipline).

**Residues (documented, not silently scoped):**
- A NONINTEGER-scaled intrinsic result as a MOVE sender (`MOVE FUNCTION SQRT(2) TO PIC X`) still rides
  the computed-sender arm with `IsNonInteger` false — whether §15.4's temporary item makes Table 16's
  noninteger row apply needs its own derivation (the item-92 function-as-text determination is
  adjacent); not changed in the family-7 landing.
- `RefModPlace.CategoryOf`'s doc (Place.cs:254) claims GR6's base case preserves alphabetic-ness;
  under GR2-feeds-GR6 (GR1+SR5's closed class lists) it does not — the comment is corrected by the
  family-7 landing. The same reading makes a ref-mod view over a DISPLAY-FORM boolean item
  alphanumeric (the usage-BIT view stays boolean, GR5a); the landed CategoryOf keeps boolean for both
  — a separate adjudication, registered here as an open question, NOT changed by family 7.
