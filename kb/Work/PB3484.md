# PB3484 — CloseDisplaced leaves the kept handle behind

From the implementer report of PB3337 (`E:\COBOL-coord\scratch\reports\w1137a-PB3337-report.md`, `## New defects` 3, carried from round 1). PB3337 has landed (PR #351, main 2353545b2), so this note is ready.

**Mechanism.** `FileRegistry.CloseDisplaced` closes what a re-registration displaces (PB168, PB603). PB3337 adds a kept handle and file lock held past CLOSE until COMMIT, and a connector displaced by re-registration keeps it forever.

**Fix shape.** Release the kept state on every path that drops a connector (CloseDisplaced, CloseAll, CloseAndDrop, Reset) through the one release, `KeyedConnector.ReleaseKeptFileLock`, and add a witness per path (the siblings sweep, rule 4).

**Sites:**
- `src/WiseOwl.Cobol.Runtime/IO/FileRegistry.cs`
- `src/WiseOwl.Cobol.Runtime/IO/KeyedConnector.cs`

## Landed (wave 1140, group B; kb/Work PB3480 shares the change)

**Re-probe.** Reproduced on the base (62cd0d954): a connector CLOSEd (or abandoned open) under commit control and then displaced by the re-registration of its
element left another run unit's OPEN WITH NO OTHER at '61' after the COMMIT, forever, and its transaction was beyond the COMMIT and ROLLBACK.
**The note's fix shape was corrected.** "Release the kept state on every path that drops a connector" would roll a canceled element's uncommitted changes back
at the next dead-owner step: §12.4.6.3.4 GR5 keeps an APPLY COMMIT clause active after its element is canceled until a COMMIT or ROLLBACK deactivates it, and
§14.9.7.4 GR3 gives the COMMIT the changes of the files of the active clauses. A connector that leaves `_files` (`CloseDisplaced`, `CloseAndDrop`) holding what a
CLOSE under commit control kept is therefore RETIRED (`FileRegistry._retired`): `TransactionConnectors` finds its transaction, and `ReleaseCommitLocks` and
`CloseAll` (so `Reset`) give back what it kept through the one release, `KeyedConnector.ReleaseKept`. `CloseAll`'s pending-object-close drain, which dropped
connectors before its release loop, is covered by the same list.
**Witnesses** (`CommitRollbackRuntimeTests`): `A_connector_displaced_by_a_registration_leaves_what_its_close_kept_to_the_commit` (closed or still open; changed or only
read; COMMIT and ROLLBACK; both organizations), `An_instance_file_dropped_with_its_object_leaves_what_its_close_kept_to_the_commit` (CloseAndDrop and the queued GC close),
`A_run_units_boundary_gives_back_what_a_close_under_commit_control_kept` (Reset and CloseAll: the sibling arms, already correct, now pinned).

## Landing

- `src/WiseOwl.Cobol.Runtime/IO/FileConnector.cs#CloseKeepsLocks` - the ONE decision that a CLOSE keeps the record locks and the handle (KeyedConnector: under commit control with a handle); the registry's `SharedClose` and `KeyedConnector.CloseCore` both ask it. Trap: decide it BEFORE `c.Close()`, the fields it reads are cleared by the close.
- `src/WiseOwl.Cobol.Runtime/IO/KeyedConnector.cs#Kept.Endpoint` / `ReleaseKept` / `CarryKeptOver` / `Attach` / `AbandonOpen` - the kept endpoint owns the locks published through it; a re-OPEN that takes its own handle moves them (`PhysicalFileTable.Rehome`, inside the attach's mutex hold) before the kept handle goes, and a failed one moves them back. Trap: disposing an endpoint releases every byte it holds, so any give-back of a kept handle that skips the move silently drops the locks from the host while this run unit's table still claims them.
- `src/WiseOwl.Cobol.Runtime/IO/Sharing/PhysicalFileTable.cs#ReleaseThrough` / `Rehome` / `Unpublish` / `Republish` - release, move, unpublish (bytes off the host, table entries kept) or publish again (through the kept handle a failed re-OPEN takes again, PB3483) by ENDPOINT (the connector does not know its registry key); unpublished locks are the registry's, by name.
- `src/WiseOwl.Cobol.Runtime/IO/FileRegistry.cs#_retired` / `Retire` / `ReleaseAllKept` - a connector leaving `_files` holding kept state stays the COMMIT's and ROLLBACK's (ISO 12.4.6.3.4 GR5); `ReleaseAllKept` is the one give-back for COMMIT, ROLLBACK, `CloseAll` and `Reset`. `ReclaimRetired` (called at the OPEN, before the physical file is associated) hands the kept state to the same-name replacement through `KeyedConnector.InheritKept` so its own run units kept handle never refuses it 61; a retired connectors unpublished record locks are released by name through its own `Physical`. Trap: releasing at displacement is WRONG, it turns a CANCEL, CALL, COMMIT sequence into a rollback.
- `tests/WiseOwl.Cobol.Tests.Unit/Store/CommitRollbackRuntimeTests.cs` - the witnesses (`A_close_under_commit_control_keeps_its_record_locks...`, `A_refused_reopen_leaves...`, `A_connector_displaced_by_a_registration...`, `An_instance_file_dropped...`). Trap: a Relative connector's `Opened` reads no page, so only an INDEXED EXTEND re-open can be refused AFTER the attach.
