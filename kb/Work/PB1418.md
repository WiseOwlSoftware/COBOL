## Finding — `function-identifier` (under-rejects; rows `SR-8.4.3.2.3-13`, `SR-8.4.3.2.3-14`)

**Mechanism.** Two-arm dispatch: the user-defined-function activation (UdfBinder.UdfActivate) never runs the §14.8.2 argument-conformance and bit-alignment screens that its CALL Format-2 twin runs (CallBinder: OoConformance.DescriptionMismatch / ContentConformanceReason / ScreenBitAlignment). The consequence is that a non-conforming BY REFERENCE argument to a FUNCTION compiles and runs.

**Repro.** out/probe/function-identifier/p3_sr13_conform.cob: FUNCTION FIP3F(WX) with WX PIC X(4) and formal L-X PIC 9(4) -> compiles, prints X=0013. out/probe/function-identifier/q6_sr13_ret.cob: PIC X(4) to a PIC X(2) formal -> R=AB. out/probe/function-identifier/p9_sr14_bit_bg.cob: 01 G GROUP-USAGE BIT. 05 B1 PIC 1. 05 B2 PIC 1(3). FUNCTION FIP9F(B2) -> compiles, R=101. Control: q5_sr14_call_bg.cob (CALL with the same B2) -> COBOLNET1683 + COBOLNET1688.

**Expected from the spec.** §8.4.3.2.3 SR13 makes §14.8.2 a syntax rule for function-prototype/function-pointer references, and §14.8.2.3.2 rule 2 (activated element 'a function') requires the same ALIGN, BLANK WHEN ZERO, DYNAMIC LENGTH, JUSTIFIED, PICTURE, SIGN and USAGE clauses BY REFERENCE. SR14 requires a BY REFERENCE bit argument to be byte-aligned, with literal-only subscripts and ref-mod start. Every probe above should be a compile-time diagnostic, as the CALL lane already gives.

**Observed / reasoning.** UdfActivate checks arity, SR9 (OMITTED needs OPTIONAL) and SR10 (BY VALUE class), then UdfArg builds the BoundCallArg. None of the CallBinder conformance helpers is called, and the BoundCallProgram it registers is never routed back through CallBinder.BindCall. The fix belongs in ONE shared per-argument conformance routine that both lanes (CALL Format 2 and function activation, including the function-pointer path, which shares UdfActivate) call, so that they cannot drift.

**Code site.** src/Cobol.Net.Compiler/Binding/Procedure/Verbs/UdfBinder.cs#UdfActivate (lines ~188-232) vs src/Cobol.Net.Compiler/Binding/Procedure/Verbs/CallBinder.cs lines ~600-670 and #ScreenBitAlignment

## Finding — `function-identifier` (wrong-answer; rows `GR-8.4.3.2.4-5`)

**Mechanism.** The GR5 manner mapping (UdfBinder.UdfArg) sends every identifier argument BY REFERENCE and never asks whether the identifier is 'permitted as a receiving operand'. As a result, a non-receiving identifier (a CONSTANT RECORD item) is aliased into the function, and the function's stores overwrite the structured constant.

**Repro.** out/probe/function-identifier/p4_gr5b_const.cob: 01 CR CONSTANT RECORD. 05 CX PIC 9(4) VALUE 5. COMPUTE WR = FUNCTION FIP4F(CX), where FIP4F does ADD 1 TO L-X and MOVE L-X TO L-R; DISPLAY 'R=' WR ' C=' CX -> prints R=0006 C=0006.

**Expected from the spec.** §8.4.3.2.4 GR5 b): BY CONTENT is assumed for 'any identifier that is not permitted as a receiving operand'. §13.18.15.3 SR2 bars a CONSTANT RECORD item (and its subordinates) as a receiving data item. So CX crosses BY CONTENT and the output is R=0006 C=0005.

**Observed / reasoning.** UdfArg: BoundFieldOperand f => new BoundCallArg(formal.ByValue ? Value : Reference, f.Place, null) - unconditional Reference. The screen the rule needs, 'is this identifier permitted as a receiving operand', exists for receiving positions (the CONSTANT RECORD SR2 screen, the §8.4.3.2.3 SR1 function screen), and UdfArg should ask that same predicate. Sweep siblings: CALL Format-2 prototype arguments are governed by the same kind of assumed-manner rule, and INVOKE by §14.9.23.

**Code site.** src/Cobol.Net.Compiler/Binding/Procedure/Verbs/UdfBinder.cs#UdfArg

## Finding — `function-identifier` (rejects-legal-source; rows `SR-8.4.3.2.3-8`, `GR-8.4.3.2.4-5`)

**Mechanism.** UdfArg has no arm for a boolean EXPRESSION argument (BoundBoolOperand), so a legal SR8 argument shape is refused on the user-function path with a 'not yet supported' COBOLNET1506, while the intrinsic path binds the same shape (PB65).

**Repro.** out/probe/function-identifier/p4b_bool_arg.cob: 01 WB PIC 1(4) VALUE B'1100'. MOVE FUNCTION FIP4BF(WB B-AND B'1010') TO WR, where FIP4BF USING L-X PIC 1(4) RETURNING L-R PIC X(4) does MOVE L-X TO L-R -> COBOLNET1506 'this argument form ... is not yet supported for user-defined function activation'.

**Expected from the spec.** §8.4.3.2.3 SR8 admits 'a boolean expression' as argument-1, and §8.4.3.2.4 GR5 b) passes it BY CONTENT. The program compiles and prints E=1000.

**Observed / reasoning.** UdfArg's switch covers BoundFieldOperand and BoundNumericLiteral/BoundStringLiteral/BoundComputedOperand, and returns null for BoundBoolOperand, which UdfActivate reports as COBOLNET1506 (a capability limit shipped as a diagnostic). A boolean literal already works (q3_boollit_arg.cob L=0110). The ADDRESS-identifier argument refusal is the open note PB1060 and should not be re-filed.

**Code site.** src/Cobol.Net.Compiler/Binding/Procedure/Verbs/UdfBinder.cs#UdfArg / #UdfActivate (COBOLNET1506 arm)

## Finding — `function-identifier` (under-rejects; rows `SR-8.4.3.2.3-10`)

**Mechanism.** The SR10 class screen UdfArgIsValueClass tests Pic.Category == Numeric without excluding Usage.Index, so an index data item (class index) is accepted as the argument for a BY VALUE formal.

**Repro.** out/probe/function-identifier/q4_sr10_index.cob: 01 WI USAGE INDEX. COMPUTE WR = FUNCTION FIQ4F(WI), where FIQ4F is USING BY VALUE L-X PIC S9(9) BINARY -> compiles and prints I=0000.

**Expected from the spec.** §8.4.3.2.3 SR10: an argument for a BY VALUE formal 'shall be of class numeric, object, or pointer'. §13.18.60.4 GR10: 'The class and category of an index data item are index'. This should be a compile-time COBOLNET1554.

**Observed / reasoning.** BoundFieldOperand f => f.Place.Item.Pic?.Category is PicCategory.Numeric or ... is true for a USAGE INDEX item. IntrinsicArgumentRules.NonIntegralItemReason already spells the exclusion '{ Category: Numeric, Usage: not Usage.Index }'. The class question should come from one predicate, not be re-derived per screen.

**Code site.** src/Cobol.Net.Compiler/Binding/Procedure/Verbs/UdfBinder.cs#UdfArgIsValueClass

## What the fixer owes

Bind a function activation's arguments through CALL Format 2's argument binder (OoConformance.DescriptionMismatch / ContentConformanceReason / ScreenBitAlignment) — ONE mechanism — with the GR5 manner mapping (BY CONTENT for a literal, expression or non-receiving identifier), the boolean-expression arm the intrinsic path already has (PB65), and SR10's class screen excluding USAGE INDEX. Drift test pairing CALL and function activation screens.
