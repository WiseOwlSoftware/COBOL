# PB3470 — temp_names.py does not see a glob over the shared temp directory

Source: coordinator lead, 2026-10-20. `scripts/temp_names.py` `scan_py` (line 214) flags a fixed name joined to the
temp directory (the PB2922 / PB3243 hazard: concurrent sessions share one machine-global path) but not a glob over
it, for example `Path(tempfile.gettempdir()).glob("x-*")`.

That gap let the `--self-test --keep` check in `conformance-suite/harness/run.py` enumerate and delete other runs'
`conformance-kept-*` directories in the shared temp dir. The race turned the Linux gate red on branch
`worktree-wf_6fa84a9d-fb8-4`; the run.py use was fixed there in commit 4ca925da3. Repro: the old run.py lines 777 and
780 (at e435d448a3ff) pass `python scripts/temp_names.py --check`.

Fix: make `scan_py` flag `glob`, `rglob`, `iterdir`, `os.listdir` and `os.scandir` applied to the temp directory
(directly or through a variable bound to it), with a fixture test containing the old run.py lines. Sweep the
PowerShell, shell and C# scanners for the same enumerate-the-shared-directory shape.
