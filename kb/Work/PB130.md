# PB130

Rows: FMT-14.9.4.2, SR-14.9.4.3-2/-3/-4/-24, GR-14.9.4.4-9/-11, findings [call-statement-p1/p2/p3].

REJECTS: (a) `callByValue : BY VALUE …` requires BY where the figure underlines only VALUE (§5.2.3; the sibling arms three lines away write `BY?`) — the INVOKE/CobolData twins repeat it, 4 sites; (b) no OMITTED alternative in callArgument/callByReference (PB46's note claims the CALL side has it — false, do not inherit); (c) Format 2's bare literal-2 / arithmetic-expression-1 (`USING 42`, `USING N + 1`) are parse errors (callArgument's bare arm is dataReference only); (d) `CALL N"P"` / `CALL X".."` fall to BoundUnsupported → run-time throw (SR2 admits both; CANCEL repeats it — and BindCancel's per-target loop aborts the WHOLE statement, losing already-legal targets); (e) `USING ADDRESS OF X` cannot parse (ADDRESS OF exists only in setAddressStatement). Fix travels with the callArgument production; the negative pb6-call-by-value-alphanumeric is itself written in the illegal Format-1 shape and must be respelled.
