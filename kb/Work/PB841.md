# PB841 — OPEN — checking enablement is per compilation group, and the engine holds it per run unit

Sources: the `PB367b` report item (b) and the `PB640` report item (c), which re-checked it and deliberately did
NOT fold it in (PB640's EC-SIZE family is a COMPILE-TIME kernel selection, not an ambient flag, so the
mechanisms do not overlap).

## Observed, at the site (main `b5ca78fb`)

`src/Cobol.Net.Runtime/Control/ProgramTable.cs`, `CallProgram`: the only state saved and restored across the
activation boundary is

```
279:  int savedPerformDepth = exc.PerformDepth;
306:  exc.TrimPerformTo(savedPerformDepth);
```

`grep -n "_checking" src/Cobol.Net.Runtime/Control/ProgramTable.cs` returns nothing. `ExceptionEngine._checking`
is run-unit state; the only save/restore anywhere is §14.9.28.4 GR14's exception-checking PERFORM
(`PushAllCheckingOff` / `PopAllChecking`, emitted by `EcEmitter` and `ControlFlowEmitter`).

## The rule, quoted

```
$ python scripts/spec/cite.py --check 14.6.13.1.1 "Checking is not enabled unless the TURN directive or WHEN phrase of the PERFORM statement is used to enable checking for the exception"
  OK  §14.6.13.1.1   (General)
```

and §7.3.25 makes `>>TURN` a compile-time directive over the source text that FOLLOWS it in the compilation
group. A callee compiled without one has checking disabled for its own statements, in every activation.

## Repro shape (⚠ owed — this note is a code-read)

Program A: `>>TURN EC-BOUND-SUBSCRIPT CHECKING ON` around `CALL "B"`. Program B, separately compiled with no
`>>TURN`, subscripts a table out of range. Expected: B's reference is unchecked (§14.6.13.1.1) and
`FUNCTION EXCEPTION-STATUS` in B is spaces. Expected-on-this-tree: B raises. The blast radius did not widen when
PB367b landed — the dispatcher is per-activation, so the callee runs its OWN declarative — but the RAISE itself
should not happen.

## Shape of the fix

One more save/restore in `CallProgram`'s existing `finally`, beside the PERFORM depth: the checking mask is
saved, replaced by the callee's compile-time mask, and restored. The callee's mask is already a compile-time
fact (`EcEmitter.FatalAmbientGates` / `NonfatalAmbientGates`); what is missing is a per-program record of it that
`CallProgram` can install.

## Sibling sweep the fixer owes

* `RunMain` (the run unit's entry) has the same shape for the initial program.
* INVOKE (`OoBinder` / the method activation path) is an activation boundary too.
* Every ambient gate in `EcEmitter.FatalAmbientGates` / `NonfatalAmbientGates` is in the blast radius, not only
  EC-BOUND-*; the fix is one mechanism for all of them.
