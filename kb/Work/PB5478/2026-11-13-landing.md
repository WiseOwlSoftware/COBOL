## The fix (worker w20262023a, 2026-11-13)

**Second occurrence.** GitHub merge-group run 43550577247, `Windows shard 6/7`, bounced pull request #1607 the same way:
"the holder under C:\Users\runneradmin\AppData\Local\Temp\...\grammar-diagram-held-b478fdd23ae4 failed ... (held 4

**Measured, not guessed.** A scratch harness watched a temp directory with a 64 KB buffer while the generator ran with
`TMP`/`TEMP`/`TMPDIR` pointed at it (`E:\COBOL-coord\scratch\op-20261113\w20262023a\harness`, `measure`): 184 Created
events in 23.5 s, 0 errors, 14,980 bytes of reports, about 100 of them fitting in the default 8,192-byte buffer. 162 of the
184 are java's `jar_cache*.tmp` (18 for each of the 9 rr.war runs), 9 `hsperfdata_<user>\<pid>`, 10 the notes, 3 pwsh's.
The 106 the note counted were what was left after the drop. The watcher's callback runs on a thread-pool thread, and a
Unit population running at once keeps that pool busy, so the stall that fills 8 KB is ordinary under load.

**Reproduced on demand.** The holder as on main at f1b100cba3, with only test seams added (a hook on the watcher's event
thread, `ProveAsync` callable twice), under the new test's first form: stall the event thread on the first burst report,
write 1,000 files (about 36 KB of reports), plant a second probe, release. Red 5 times in 5:
`System.InvalidOperationException : the holder's probe was not taken: the watcher reported an error ----
System.IO.InternalBufferOverflowException : Too many changes at once in directory:...grammar-diagram-overflow-...`. The
harness's copy of the same holder: 20 stalled bursts of 400 files, 20 overflowed, 20 missed files (held 2 of 401).
Unstalled, 20 bursts of 400 never overflowed on an idle host: load, not size alone, decides it.

**Root.** A `FileSystemWatcher` is lossy by contract: under load its buffer overflows and the reports are dropped. A
holder that takes only the files its reports name misses the files whose reports were dropped, and PB5463 correctly
made that a red. A bigger buffer or a retry only moves the load at which it happens. So nothing the holder holds now
depends on a report arriving.

**The mechanism.** `GrammarDiagramGeneratorDriftTests.FreshFileHolder` finds files by ENUMERATING the held tree
(`Directory.EnumerateFiles`, recursive, no attribute skipped) on a scan thread of its own. Every report (a created or
renamed file or directory) and every `InternalBufferOverflowException` only WAKES that scan, which takes each file it has
not met; the overflow is counted in the report (`watcher overflows N`) and is no error. Any other watcher error (it
stopped watching), a scan that throws or a take that throws still fails the test. A file whose writer refuses the share
is waited out on a thread-pool work item of its own, as before. `ProveAsync` now plants a fresh probe per call and
completes only when the probe is held AND a scan that listed it has ended, so every file written before the call has
been met. The guarantee PB5463 asked for holds without depending on delivery: no file that is still there when a wake
arrives escapes, and a dropped report always leaves a wake behind it (the overflow). The wake is a monitor, not a
disposable wait handle, so a report raised during disposal cannot throw on the watcher's thread.

**Proved.**
- `Holder_HoldsEveryFile_WhenItsWatcherOverflows` (new): stalls the event thread through the hook, writes 1,000 files,
  plants a second probe, and on Windows drops every report the hook sees after the first probe, so the overflow is the
  only wake left. Asserts 0 errors, 1,002 held, and on Windows at least one overflow. Before: red 5/5 (above). After:
  `Passed!  - Failed: 0, Passed: 1` 10 times in 10 (81 ms to 2 s), plus 10 of 10 under its first form.
- Mutation, the overflow's wake removed: the test never proves its second probe and hangs (`--blame-hang-timeout 60s`
  aborted the run). It never passes.
- Mutation, the pre-PB5447 generator (`git show 2352eff5df:scripts/gen-grammar-diagrams.ps1`, uncommitted) under the new
  holder: `Failed!  - Failed: 1`, "exited 1 while this test held every fresh file ... (held 15 file(s), skipped 1,
  watcher overflows 0, errors 0)", `CobolWords.md` "being used by another process". The hostile half still bites.
- `Generator_RunsClean` with the current generator: `Passed!` twice (46 s, 48 s).
