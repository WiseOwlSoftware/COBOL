# PB5237 - the Bash tool halves backslash runs

**Observed (2026-11-10, Claude Code 2.1.322, Windows 11, Git Bash).** A Bash tool call
`printf '%s|' 'A\\nZ' 'A\\Z' 'A\\\\Z' 'A\\"Z' 'A\nZ'` (single quotes: bash changes nothing inside them) writes
`A\nZ|A\Z|A\\Z|A\\"Z|A\nZ|`. Every run of two or more backslashes that does not end at a double quote arrives halved (six
become three); a run before `"` and every single backslash arrive intact. The transcript, which is also what a PreToolUse
hook receives, records the command as written; `/proc/$$/cmdline` inside the call shows bash received
`bash -c "source <snapshot> ... && eval '<command>'"` with the run already halved. So the change happens in the Bash
tool's wrapping, after the hooks and before bash.

**Not affected.** The Write and Edit tools, the PowerShell tool (`@'...'@` and `@"..."@` here-strings), and a heredoc run by
bash from a file: all byte-exact (`check.py`, whose expected bytes are built from `chr(92)`).

**Harm.** Silent: a patch script's anchor counts 0, a JSON or C# escape changes meaning, a single-quoted `sed` or `grep`
program changes. In bash double quotes or an unquoted heredoc a single PAIR is halved by bash anyway, so most uses hide
it; a quoted heredoc and single quotes do not. In the window, 176 heredoc bodies and 153 other Bash commands carried the
shape (of 40,101 Bash calls).

**In this repository.** The cause cannot be fixed here. `forbidden_commands.py` rule 3 refuses exactly that shape in a
Bash heredoc body (kb/Work PB5234), which is where it does the most harm; MANDATORY-PRACTICES P12 names the Write and
PowerShell tools as byte-exact. Reporting it to Anthropic is the owner's decision (CLAUDE.md, Ownership: anything sent
to people outside); this note is the record for that report. It closes when the harness passes the command through
unchanged, re-measured with `E:/COBOL-coord/scratch/stage5/check.py` and `t2.bin`'s probe, and rule 3 is then deleted.
