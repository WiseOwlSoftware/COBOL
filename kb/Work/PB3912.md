# PB3912 — justified-right-on-usage-bit: PIC 1 boolean item: JUSTIFIED RIGHT refused ("cannot have JUSTIFIED RIGHT clause") under -std=cobol2014

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S6) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\justified-right-on-usage-bit.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\justified-right-on-usage-bit\`.

## Summary

GnuCOBOL 3.2 refuses the JUSTIFIED clause on a boolean data item: `'B' cannot have JUSTIFIED RIGHT clause`. The
standard allows JUSTIFIED for the categories alphabetic, alphanumeric, boolean and national. The night witness used
`USAGE BIT PIC 1(5)`; the refusal is the same for a usage-display boolean item `PIC 1(5)`, so it does not depend on
USAGE BIT. cobc's own JUSTIFIED check accepts category boolean, but cobc assigns a `PIC 1` item the numeric category
(its picture builder carries a FIXME saying so), and the check refuses a numeric item. Class: rejects legal ISO
source. The same miscategorisation produces wrong output for boolean items and literals; that is the split record
`justified-right-on-usage-bit--boolean-data-numeric-wrong-output`.

## Observed result

`jrdisp.cob`, both commands, exit code 1:

```

```


Without `-std` (`cobc -fformat=free -fsyntax-only`), both programs draw the same error, exit code 1.

## Expected result (per ISO)

The program is legal and prints `[00011]`.

- §13.18.32.3 3) (checked): "The JUSTIFIED clause may be specified only for a data item whose category is alphabetic,
  alphanumeric, boolean, or national."
- §13.18.40.4 8) (checked): "To define an item as boolean, character-string-1 shall contain only one or more
  occurrences of the symbol '1'." B is boolean.
- §13.18.32.4 2) (checked): when the receiving item has the JUSTIFIED clause and is larger than the sending operand,
  "the data is aligned at the rightmost character position or boolean position in the data item with zero fill for the
  leftmost boolean positions". B"11" (§8.3.3.4.1, checked: "Boolean literals are of the class and category boolean")
  into five boolean positions gives 00011.
- §14.6.8.6 (checked): boolean receiving items take the data "into the corresponding boolean positions"; "If the
  JUSTIFIED clause is specified for the receiving item, alignment within the receiving item differs as specified in
  13.18.32".

Edition: 2014. The 2009 committee draft that became ISO/IEC 1989:2014 (CD 1.2, 13.18.31.2 syntax rule 3) has the same
sentence with boolean in the list, and the same general rule 2. Boolean items are a 2002 feature.

Edition as recorded by the adjudicator: 2014 (introduced 2002). `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Class

GNUCOBOL-DEFECT: rejects legal ISO source (edition 2014; introduced 2002).

## Our compiler (WiseOwl)

WiseOwl COBOL (built from main 6ed90bd1c), `cobol jrdisp.cob --std 2014 --source-format free -o jrdisp.dll`, then
`dotnet jrdisp.dll`: compile exit 0, run exit 0, output `[00011]`. `jrbit.cob`: `[00011]`.

WiseOwl-side lead carried by this family's night record, not decided here (it does not concern GnuCOBOL, which never
compiles the program): the witness's `MOVE WS-SEND-SHORT TO WS-BIT-JUST` moves alphanumeric "AB" into the bit item
and WiseOwl displays `000AB`. §14.6.8.6 says the data is transferred "after any necessary conversion" and §14.9.25.4
6) a) has no rule for an alphanumeric sender into a boolean receiver, so no rule pins the stored value; the open
question is whether characters other than '0' and '1' may be stored unconverted in a bit item.

## Fix site (GnuCOBOL 3.2 source, read observationally)

- `cobc/tree.c`, `cb_build_picture`: the symbol `1` adds `PIC_NUMERIC` to the category (marked "FIXME: this is
  WRONG" in the source), so a `PIC 1` item gets the numeric category instead of boolean.
- `cobc/field.c`, `validate_justified_right`: accepts `CB_CATEGORY_BOOLEAN` but, given the numeric category, reports
  `cannot have JUSTIFIED RIGHT clause`. Fixing the picture category fixes this refusal; the JUSTIFIED alignment for
  boolean items (zero fill on the left) then needs to exist in the move code.
