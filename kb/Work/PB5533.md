# PB5533 - every --std 85 no-phrase arithmetic statement carries two try regions; what does that cost in a PERFORM loop

UNVERIFIED LEAD: measure before changing anything.

**Site:** `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/ArithmeticEmitter.cs#EmitArith` (the private overload at about line 701; `catchesEveryCondition`).

**Mechanism.** PB5484 made an unphrased 1985 arithmetic statement catch every raise (`catchesEveryCondition`), so with no ON SIZE ERROR phrase and no EC-SIZE checking it no longer takes the unchecked fast path (`emitStores(false); return;`). It emits the statement's outer `try { emitStores(true) }` and, inside it, each receiver's own `GuardedStore` try (`using (w.Block("try")) emitOne(at)` plus `WriteSizeCatches`). Every ADD, SUBTRACT, MULTIPLY, DIVIDE and COMPUTE at `--std 85` therefore carries two try regions and a `bool __sizeErrN` flag, where before the change it carried none.

**What is unknown.** The cost of the two regions in a hot PERFORM loop. A try region that never throws costs little on the happy path in the CLR, but it can stop the JIT inlining the statement's helper calls and forces locals live across the region into memory. Nothing was measured; the report only noted it.

**To do.** (1) Measure an 85 program with a PERFORM VARYING of N million `ADD 1 TO X` / `COMPUTE` statements, compiled at `--std 85` and at `--std 2023` with the same source (the 2023 fast path has no try), and compare wall time and the emitted C# (`.g.cs`). (2) If the gap is real, the redesign is one try per statement that covers all receivers, or a throw-free checked kernel (TryStore) for the unphrased case that latches the condition without an exception; the choice is a design change to the EmitArith shape, so update the arithmetic design doc with it. (3) If the gap is noise, close this note with the numbers.
