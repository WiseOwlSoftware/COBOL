# PB4060 — `DataDivision._inherit` does not carry the whole description of a SAME AS / TYPE source

**Sites:** `scripts/fuzz_undefined.py#DataDivision`, `scripts/fuzz_undefined.py#_inherit`, `scripts/fuzz_undefined.py#_copy`

(The code lives on PR #773's branch `worktree-wf_484eb705-564-28` and reaches main when PB3862 lands. It is not on main at filing.)

## One mechanism, two symptoms

`DataDivision._inherit` is the one place that implements "as though the description of the source had been coded in place"
(ISO 13.18.49.4 1, 2 a for SAME AS; 13.18.57.4 1, 2 a for TYPE). It copies the picture, usages, VALUE and the subordinate
items (`_copy`) and stops there. Two parts of the rule are missing, both in that function, so they are one note.

1. **Level-88 condition-names are not copied (review lead R2-1, line 39 of the report; a false proof).**
   `DataDivision.conditions` maps a condition-name to ONE item, the source. A `SET cond TO TRUE` of the name, which writes
   the inheriting item, is credited to the source, so the inheriting item is reported `UNWRITTEN_STORAGE`: the tool proves
   an unwritten byte of an item a statement wrote. A wrong answer of the fuzz tool, not of the compiler.
2. **EXTERNAL and REDEFINES of the source are not told apart from other opaque shapes (the report's New defects bullet; a
   missed finding).** SAME AS excludes the CONSTANT RECORD, EXTERNAL, GLOBAL, REDEFINES and SELECT WHEN clauses of the
   source (13.18.49.4 1), so an item that is SAME AS an EXTERNAL or REDEFINES source is an ordinary item. The line
   `item.opaque = item.opaque or src.opaque` copies the flag, so the item reads as defined and an unwritten read of it is
   never reported. TYPE's own exclusions are GLOBAL, SELECT WHEN and TYPEDEF (13.18.57.4 1); whoever fixes this derives
   what a TYPEDEF source carrying EXTERNAL or REDEFINES does from that rule.

## Fix shape

Make `opaque` carry WHY (EXTERNAL, BASED, index or pointer, REDEFINES aliasing, unresolved source) instead of one bool, have
`_inherit` drop the reasons the clause excludes, and give `conditions` a list of items per name (or copy the level-88
entries in `_copy`) so a condition-name of an inherited group resolves to the inheriting item. Test arms, each seen RED
first: a SET of an inherited condition-name leaves the item written; a SAME AS of an EXTERNAL source and of a REDEFINES
source that is never written is reported.

## Citations (checked with `cite.py --check`)

- 13.18.49.4 1: "excluding the level-number, name, and the CONSTANT RECORD, EXTERNAL, GLOBAL, REDEFINES, and SELECT WHEN clauses".
- 13.18.49.4 2 a and 13.18.57.4 2 a: "the subject of the entry is a group whose subordinate elements have the same names,
  descriptions, and hierarchy as the subordinate elements of" the source.
