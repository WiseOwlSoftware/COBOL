# PB5292 - a statement of a USE procedure that a debugging section PERFORMs never triggers another debugging section: the run-time flag __dbgBusy suppresses every trigger while any debugging section runs, where 1985 exempts only statements written in a debugging section

**Sites:**

- `src/WiseOwl.Cobol.Compiler/CodeGen/DispatchEmitter.cs` (`EmitDebugRunner`)

**Mechanism.** §1985:XV.3.2.4 GR1: "Automatic execution of a debugging section is not caused by a statement appearing in a debugging section." The binder already plans no triggers for statements in a debugging section, which is the rule. `EmitDebugRunner` also sets one `__dbgBusy` flag for as long as any debugging section runs and refuses every trigger while it is set, so a statement in a USE procedure the section PERFORMs (legal, §1985:XV.3.2.3 SR4), which is in no debugging section, never runs the section that monitors what it changes (GR6).

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids below. None of them is recorded: the non-conforming verdicts wait in `E:/COBOL-coord/scratch/coderead-85/p2-for-register.json`.

**Rules (1 claimed; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-GR-XV.3.2.4-1` - `§1985:XV.3.2.4 GR1` (read: DIVERGES, harm: wrong-answer): "is not caused by a statement appearing in a debugging section"

**Repro.** `E:/COBOL-coord/scratch/coderead-85/out-pipe/work-slice-67/g1a.cob`: D1 (USE FOR DEBUGGING ON MAIN-PARA) does `MOVE "Q" TO V. PERFORM U-PARA.`; D2 monitors W and V; U-PARA (in a USE AFTER ERROR section) does `MOVE "Z" TO W`; `cobol.exe --std 85 --source-format fixed --run g1a.cob`.

**Observed (a build of origin/main f2cf36fd15, rerun 2026-11-11; main has since changed only `IndexedConnector.cs` under `src/`, which none of these repros reaches).** `D1 MAIN-PARA`, `U-PARA`, `MAIN ZQ`, `D2 W ... Y` (no D2 after `MOVE "Z" TO W`).

**Expected (from the 1985 text).** `D1 MAIN-PARA`, `D2 W ... Z`, `U-PARA`, `MAIN ZQ`, `D2 W ... Y`.

**Fix direction (root cause, CLAUDE.md rule 4).** Drop the run-time busy flag for the GR1 exemption (the binder already applies it statically); keep only whatever guard recursion needs, and test this program.
