that implements an interface specified in the RAISING phrase of the procedure division header of the source element
containing this EXIT or GOBACK statement" ⇒ "as if EXCEPTION EC-OO-EXCEPTION were specified in the RAISING phrase …

## Landed (wave 1001 group A, w1001a)

Re-probed first (the main checkout's pre-change binary, then this tree): `o1` (no `>>TURN`, method BOOM
`PROCEDURE DIVISION RAISING CXO1E`, `GOBACK RAISING W-E`, no declaratives) terminated abnormally on EC-OO-EXCEPTION
(exit 1) and `o3` printed `B-F4 / A-F4 / A-AFTER` — both reproduced. One mechanism, fixed once:
every place §14.6.13.1.5 says "as if EXCEPTION EC-OO-EXCEPTION were specified in the RAISING phrase" is now a NAMED
propagation, and the named propagation reaches the activator's ONE checking-gated arm.

- **One census** (`EcState.PdRaisingObjectCsTypes`, set per program unit and per METHOD): the C# types an object must be
  an instance of to be "an applicable class or interface" in the header's RAISING phrase (item 1 a)/b); a FACTORY OF
  entry lists only the factory type, a plain class entry the instance hierarchy). It used to exist only inside
  `AutomaticPropagation` (PROPAGATE ON, item 3); `AutomaticPropagation` now carries only `InMethod` and
  `EcEmitter.ObjectApplicableTest` renders the one `x is T1 or T2` / `false` test for items 1 and 3.
- **Item 1** — `GOBACK / EXIT … RAISING LAST EXCEPTION` of an object status: `CallEmitter.EmitRaisingStage` passes the
  test to `ExceptionState.SetPropagatingLast(bool objectApplicable, …)`, which stages the NAMED EC-OO-EXCEPTION on a
  miss. `StageAutomaticObjectPropagation` is DELETED (it was the same object-or-EC-OO choice; item 3 now emits
  `SetPropagatingLast(<test>)`). `RAISING identifier-1` keeps its static discharge (D-EO5, now says so).
- **Item 4** — `CallEmitter.EmitPropagationPickup`'s object block no longer sets and selects EC-OO-EXCEPTION
  unconditionally: on `NoHandler` (after item 3's return) it calls `ExceptionState.ConvertObjectPropagationToNamed()`
  (the named slot for THIS activation — `StagingFor` would name the activator's activator) and the named block below
  takes it through `TakeRaisedPropagation(site.ActivatorChecking…)` (PB408). `OoEmitter` INVOKE sites (two) delegate to
  the same method, so INVOKE follows. `reportRaised` now flags an object as propagated only when an F4 declarative
  took it or the named arm raised it (CONFORMANCE §3 records the reading; probed `nx`/`nx2`: checking off ⇒ NOT ON
  EXCEPTION runs, checking on ⇒ it does not).

After: `o1` prints `AFTER` (exit 0); with `>>TURN EC-OO-EXCEPTION CHECKING ON` it still terminates abnormally (unit
test); `o3` prints `B-F4 / A-ECOO EC-OO-EXCEPTION / A-AFTER`; the header-RAISING twin prints `B-F4 / A-F4 / A-AFTER`.
