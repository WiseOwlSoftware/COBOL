# PB5024 - the margin-R warning fires inside a comment entry

**Found.** Wave 20261936 group E (PB4999). A COBOL-85 comment-entry paragraph (`AUTHOR.`, `REMARKS.` and the other identification
comment paragraphs) holds free commentary. When one of its tokens ends at position 72 and text sits at position 73, the
margin-R screen draws COBOL6688 (text past margin R was cut) although the cut text is commentary and nothing about the program
changes. The warning misleads the programmer into looking for lost program text.

**Owed.** The screen skips tokens the tree marks as comment-entry, so only program text draws the note. Witness: a fixed-form
program whose `AUTHOR.` entry ends a word at column 72 with text at 73 compiles with no COBOL6688; the same cut in a data
description still draws it.

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/MarginRCutScreen.cs` (`MarginRCutScreen.Warnings`), `src/WiseOwl.Cobol.Frontend/Parsing/CommentEntryTokens.cs` (`CommentEntryTokens.Of`, `AddTo`; also used by `WordCharacterScreen.TreeFacts`), `src/WiseOwl.Cobol.Frontend/Pipeline/Frontend.cs` (`LexAndParseOnce` call). Origin: PB4999 (landed), which
does not mention comment entries.

**Landed.** The screen skips every token the parse tree gives to a CommentEntry (the one rule PB3845 made of the six comment paragraphs); unit tests ACutInACommentEntry_IsNotNamed and TheSameCutInADataDescription_IsStillNamed and the conformance case pb5024-comment-entry-cut-at-margin-r witness it.
