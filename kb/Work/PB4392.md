# PB4392 - the tooling lane's whole-tree self-tests are unbounded

**Read at:** origin/main f0e4650e5.

`scripts/gate.py` runs the SELF-TESTS audit (`("SELF-TESTS", ["scripts/self_tests.py"])`, line 330) and the post-build half (`BUILT_SELF_TESTS`, line 362) for any change that touches tooling (`TOOLING_ONLY`, `Lane.tooling`). `scripts/self_tests.py` discovers every script self-test (kb/Work PB2563), so each tooling-lane gate runs all of them whatever the change touched. At the PB4328 gate they took 769 s, led by `merge_drivers`, `test_adopt_main` and `test_plan_wave`.

PB4328 (landed) recorded this as estimate correction (4), "not bounded here". No open note owns it, and a landed note cannot own new work.

**Source:** branch `worktree-wf_1338af20-657-4`, report `E:/COBOL-coord/scratch/reports/w20261805a-PB4348-report.md`, lead 1 (an own root).

**Fix shape:** the lead gives none beyond "own root". Measure each self-test's time, then bound the lane by a structure, not a list: a self-test declares what it reads (as `SELF-TEST-NEEDS: build` already declares a need) and the gate runs those whose inputs changed, or the slowest are sharded across the gate's slots. A self-test whose inputs are unchanged since a recorded PASS is already reused (PB2914); find why these three are not.
