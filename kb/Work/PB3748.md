# PB3748 — covered_by_driver matches by suffix

**Sites:** `scripts/merge_drivers.py#covered_by_driver`, `scripts/merge_drivers.py#conflict_report`, `scripts/merge_drivers.py#self_test` (the `patterns:` arm).

`covered_by_driver` matches a path with `PurePosixPath.match`, which matches from the right, so `x/kb/Work/PB1.md` reads as covered by the `kb/Work/*.md` driver. The driver-file guard only asks whether a file the driver resolves may be taken, so the over-match is harmless there, but `conflict_report` counts conflicts by whether a driver covers the path and so counts a file the driver never sees. Fix: anchor the match to the repo root (`PurePosixPath(path).full_match` or compare the leading parts) and add a self-test with a nested path.

(2026-10-25.)

## Discharged (wave 20261704, group D): already fixed by PB3727, a pin added

**Re-probe (2026-10-25, this build).** `covered_by_driver("x/kb/Work/PB1.md")` is False, as are `x/src/Cobol.Net.Runtime/RuntimeAbi.pin`
and `kb/Work/sub/PB1.md`; `kb/Work/PB1.md` is True. The note described `PurePosixPath(path).match(p)`, which matched from the
right. PB3727 (commit `1cc737801`, the same day, 14:09 PDT) replaced it with `pattern_matches`, gitattributes' own rule: a
pattern with a `/` is anchored at the repository root. The note was filed against the tree before that commit. The other
site it names, `conflict_report`, never called `covered_by_driver`: it counts the files the landing logs name, and the
`--conflicts` command prints the coverage beside them, through the same function.

**What this change adds.** The note's fix asked for a self-test with a nested path, which PB3727's arm lacked (it tested
`pattern_matches("kb/Work/x/PB1.md", …)`, not the covering function). The `patterns:` arm of `merge_drivers.py --self-test`
now asserts `covered_by_driver` on a path that only ENDS in a driver's pattern (`x/kb/Work/PB1.md`,
`x/src/Cobol.Net.Runtime/RuntimeAbi.pin`, `kb/Work/sub/PB1.md`), so a return to a right-anchored match fails.
