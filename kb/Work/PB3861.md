# PB3861 — no hint names the literal kind a nonnumeric literal violates

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs#GuessCobolIntent` (hint 15, silenced by PB906's
fix)

## The defect

PB906's fix made hint 15 of `CobolErrorStrategy.GuessCobolIntent` silent, because it claimed a missing feature that now
exists. The effect on a statement that carries a nonnumeric literal where the general format admits only a numeric
literal or an identifier is that the winning diagnostic became the bare `COBOL0001: unexpected '"A"'` with no hint naming
the literal kind. The output is true (the previous false `COBOL0308` is gone), but it is a misleading/bare diagnostic as
PB906 classes it: it tells the user nothing about what the token should have been.

## Failure scenario (verbatim from the report)

`SET W-N TO "A".` and `WRITE R AFTER ADVANCING "A".` report a bare `COBOL0001: unexpected '"A"'`, with no hint naming
the literal kind. The review of group C (R1-2) found the residue left only in the report's prose.

## Acceptance

- Each statement above draws a diagnostic that names the kind the position admits (a numeric literal or an identifier) and
  the kind written (a nonnumeric literal), at the literal's own position.
- It needs ONE new diagnostic code, a catalog row, a `docs/CONFORMANCE.md` entry, a per-kind message and goldens. This
  note does not allocate it: the implementer does, through `alloc.py`.
- The fix covers every position whose general format admits a numeric literal or identifier but no nonnumeric literal
  (sweep the grammar for the siblings), not only the two statements named.
- Standing owner rules: fix the root causes, never simply making the diagnostic pass; always be consistent with
  ourselves barring an explicit requirement differently.

## Landing (wave 20261769 group C, with PB3428)

**Re-probe** (`cobol.exe` on 802352531): `SET W-N TO "A".` drew `COBOL0001: cannot parse construct near '"A"'`.
`WRITE R AFTER ADVANCING "A".` does NOT reproduce: the grammar takes any literal there and the binder refuses it by
name, `COBOL2365` (ISO §14.9.51.3 SR15), since a374ee660 (2026-09-23, PB1021/PB1023), before this note was filed.

**Fix.** One mechanism with PB3428 (hint 0i, COBOL5506, `AdmittedKinds`): the parse at the literal, its predicates
evaluated, takes an identifier and a numeric literal, so the refusal names both sides: "The alphanumeric literal "A" is
not expected here: of the literals, only a numeric literal is expected at this position". The figurative ZERO is named
only where a ZERO written at the token would parse (branch review R1-1): the parse takes ZERO_ARITH, the token
`ZeroTokenRewriter` makes of a ZERO beside an arithmetic operator, and `AdmittedKinds.Refusal` names it only when the
rewriter's own test, `ZeroTokenRewriter.AZeroWrittenAtIsArithmetic`, holds at the refused token (`COMPUTE W-N = 1 +
"A"` names it). Naming it after `SET IX TO` sent the user to `SET IX TO ZERO`, which the parse refuses (a separate
mechanism, registered in the wave report: a sole figurative ZERO at a position whose only operand is an arithmetic
expression is refused, though §14.9.39.2 Format 1's arithmetic-expression-1 with §8.8.1.1 admits it). The literal category comes from
`LiteralTokens.CategoryOf` (§8.3.3.1), held total over `LiteralTokens.Whole` by
`WrittenKindRefusalTests.EveryWholeLiteralToken_HasACategory`. Hints 15 (COBOL0308 "a data-name is expected here, not
a literal") and 16 (COBOL0309 its converse) named the kind in two shapes only, from the predicate-blind expected set;
both are deleted and 0i covers their shapes (`CALL "P" RETURNING 5`: "no literal is expected at this position").
Siblings swept: every position that takes a numeric literal or identifier and no alphanumeric literal is named the same
way, from the parse, not a list (`SET IX UP BY "A"`, `PERFORM "A" TIMES`, `OCCURS "A" TIMES`); `ADD "A" TO …` and
`WRITE … ADVANCING "A"` are bind-time refusals already (COBOL0844, COBOL2365).

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/AdmittedKinds.cs#Refusal`,
`src/WiseOwl.Cobol.Frontend/Parsing/ZeroTokenRewriter.cs#AZeroWrittenAtIsArithmetic` (the rewrite's context test,
shared with the refusal), `src/WiseOwl.Cobol.Frontend/Parsing/LiteralTokens.cs#CategoryOf`,
`src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs#GuessCobolIntent` (hints 15 and 16 deleted, 0i added),
`src/WiseOwl.Cobol.Frontend/Diagnostics/DiagnosticDescriptors.cs` (COBOL0308, COBOL0309 deleted).

**Goldens.** `14.9.39-SET/pb3861-set-index-to-alphanumeric-literal` (refused at every edition),
`pb3861_set_index_to_integer_literal` (accepted at every edition, prints C).
