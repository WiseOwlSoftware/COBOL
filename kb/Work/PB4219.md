# PB4219 — the non-data tier of the nearest-declaration screen has no depth

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.IoControl.cs#ScreenEnclosingFileOperand`,
`src/WiseOwl.Cobol.Compiler/Binding/DataBinder.NonDataNames.cs#NonDataDeclarationOf`.

Until PR #891 (PB3557) is on main these members exist only on branch `worktree-wf_34371f8b-c21-12`; this note is blocked on it.

**Mechanism.** The screen of an APPLY COMMIT / I-O-CONTROL operand decides by the nearest declaring source element for data
items, report entries and GLOBAL files. The tier for names that are not data items (`NonDataDeclarationOf`: constant-name,
index-name, condition-name) carries no containment depth, so it cannot be compared with `fileDepth`. `NonDataDeclarationOf`
also asks `IsVisibleFileName` before `TryResolveCondition`, so a file-name outranks a condition-name regardless of nesting.
ISO §2023:8.4.6.2.1 3) a) makes the item declared in the contained element B the referenced item, and 3) b) 2. makes the nearest
containing declaration win otherwise.

**Repros** (branch cobol.exe, head 37f8a61aa).
1. PA declares `01 T1 GLOBAL` / `05 E OCCURS 3 INDEXED BY RELF`; contained PB declares `FD RELF IS GLOBAL`; PC inside PB:
   `APPLY COMMIT ON RELF`. Draws COBOL1639 "RELF is declared as an index-name", but PB's GLOBAL file is the nearer
   declaration, so SR11 (COBOL4709) is the rule broken.
2. PA declares `FD RELF IS GLOBAL`; contained PB declares `01 W PIC X` / `88 RELF VALUE "A"`; `APPLY COMMIT ON RELF`. Draws
   COBOL4709 SR11 about PA's file, but PB's own condition-name RELF is the referenced item, so the not-a-data-item refusal
   applies.

Both programs are illegal either way: the wrong rule is named and no legal program is refused. The same FileName-before-
ConditionName order in `NonDataDeclarationOf` words the FILE STATUS and OCCURS DEPENDING refusals the same way (round-1 content).

**Fix direction.** Give the non-data tier its depth (own versus inherited constant, index-name, condition-name) and compare it
with `fileDepth` as the data and report tiers are compared; ask an own condition-name before an inherited file-name in
`NonDataDeclarationOf`. Goldens pin both repros.

## Landed (wave 20261816, group A)

**Re-probe** (this tree before the fix, `scratch/w20261816a/p4219/r1.cob`, `r2.cob`): repro 1 drew COBOL1639 "'RELF' is
declared as an index-name"; repro 2 drew COBOL4709 SR11 about the container's file. Both as the note says.
**Fix.** `NonDataDeclaration` carries the `Depth` of its declaring source element (`DeclaringDepth`'s measure): an
index-name the depth of its table, a constant-name its inherited distance, a condition-name its nearest conditional
variable's, a file-name `DataBinder.FileDepth` (which replaces `InheritedFileDepth`: 0 for an own file). In
`NonDataDeclarationOf` a file-name and a condition-name are ranked by that depth (own condition-name before a
container's GLOBAL file; equal depth keeps the file, a §2023:8.3.2.2 conflict). `ScreenEnclosingFileOperand` lets a non-file
declaration hide the GLOBAL file only when it is no farther (`declared.Depth <= fileDepth`). After the fix repro 1 is
COBOL4709 SR11 and repro 2 COBOL1639 "is declared as a condition-name". The FILE STATUS and OCCURS DEPENDING arms read the
same query, so they word a nearer condition-name the same way.
**Goldens:** `conformance:cases/12.4.6-I-O-CONTROL/pb4219_apply_commit_nearer_global_file_beats_farther_index_name`,
`conformance:cases/8.4.6.2-Local-and-global-names/pb4219_apply_commit_own_condition_name_beats_container_global_file`
(2023, where APPLY COMMIT is).
**Sites (added by the landing):** `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.NonDataNames.cs` (`NonDataDeclaration`,
`DataBinder.NonDataDeclarationOf`), `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs` (`DataBinder.FileDepth`),
`src/WiseOwl.Cobol.Compiler/Binding/DataBinder.IoControl.cs` (`DataBinder.ScreenEnclosingFileOperand`),

## The data-name / condition-name sibling (wave 20261819, group A)

Wave 20261816's lead 2: the data-name and condition-name lookups each ranked their OWN class by depth and ignored the
other, though §2023:8.4.6.2.1 1) builds the set from "all names" (`cite.py --check 8.4.6.2.1 "3)"` OK). Re-probe
(`scratch/w20261819a/lead2/`): `c2.cob` — a contained program's own `88 RELF` beside its container's `01 RELF … GLOBAL`
— compiled `DISPLAY RELF` and displayed the container's `7`; `c3.cob` — the contained program's own `01 RELF PIC 9`
beside the container's GLOBAL `88 RELF` — compiled `IF RELF` and ran the container's condition (`COND TRUE`). `c1.cob`
(`IF RELF` with the own 88) was right. **Fix:** `SymbolTable.NearestDeclaringNamed<T>` is split into
`NearestDeclaringData` (hides the tier when a report entry or, new, a condition-name of the spelling is declared nearer:
`SymbolTable.NearerConditionNameHides`) and `NearestDeclaringConditions` (hides the tier when a data-name or report entry
is declared nearer: the existing `NearerDataNameHides`); every caller (`TryResolveUnqualified`,
`DataBinder.QualifiedCandidates`, `DataBinder.QualifiedConditionCandidates`) changed, nothing kept. `NonDataDeclarationOf`
reads the ranked data answer for an unqualified reference, so the hidden data item no longer stops it from naming the
condition-name. After: `c2` COBOL1639 "'RELF' is a condition-name … identifies no data item", `c3` COBOL2318 "'RELF' is
used as a condition, but it is data item 'RELF'", `c1` unchanged. `GlobalNameClassDriftTests.ADataNameNarrowing_RanksTheReportEntriesToo`
asserts both narrowings ask the other class. Goldens
`conformance:cases/8.4.6.2-Local-and-global-names/pb4219_own_condition_name_hides_container_global_data_item` (COBOL1639)
and `…/pb4219_own_data_item_hides_container_global_condition_name` (COBOL2318), refused at 85, 2002, 2014 and 2023.
Inventory: GR-8.4.6.2.1-3 stays CONFORMS; batch `w20261819a-pb4219-cross-class` re-sites its witness and adds the two
goldens. **Sites (added by the sibling):** `src/WiseOwl.Cobol.Compiler/Binding/Model/SymbolTable.cs`
(`SymbolTable.NearestDeclaringData`, `SymbolTable.NearestDeclaringConditions`, `SymbolTable.NearerConditionNameHides`,
`SymbolTable.TryResolveUnqualified`), `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs` (`DataBinder.QualifiedCandidates`,

## Review R1-1 (wave 20261821): the condition-only positions

The positions that admit only a condition-name asked the RAW condition table after the narrowing left no survivor, so a
container's GLOBAL condition-name hidden by the contained program's own data item was worded as a condition-name that
"identifies no data item": SET Format 4 (`SET RELF TO TRUE`) and SEARCH ALL's bare `WHEN RELF (IX)` through
`ConditionBinder.ReportMisqualifiedCondition` (COBOL1639), and SEARCH ALL's `WHEN RELF (IX) = 1` through the "is a
condition-name" receiving-operand arm of `SearchAllFormat2Rules` (COBOL1757). **Fix:** both ask
`DataBinder.ConditionNameHiddenByNearerDataItem`, which reads `SymbolTable.NearerDataItemHidesConditions` (the data-item
half of `NearerDataNameHides`, split out as `SymbolTable.NearerDataItemHides`) and requires the data item to survive
`QualifiedCandidates`. The first two now say the reference names a data item (COBOL1639,
`ReferenceResolver.HiddenConditionText`); the third reaches SR8 (COBOL1965). Goldens
`conformance:cases/8.4.6.2-Local-and-global-names/pb4219_set_names_own_data_item_hiding_container_global_condition_name`,
`…/pb4219_search_all_when_names_own_data_item_hiding_container_global_condition_name` and
`…/pb4219_search_all_relation_names_own_data_item_hiding_container_global_condition_name`, refused at 85, 2002, 2014 and
2023; `tests/WiseOwl.Cobol.Tests.Conformance/HiddenConditionNameTests.cs` pins the wording. Batch
`w20261821a-pb4219-review-r1-1` adds them to GR-8.4.6.2.1-3. Still open on the same rule (review lead R1-3, for the

depth, and `SymbolTable.IndexCandidates` ranks an index-name only against a nearer data-name.
