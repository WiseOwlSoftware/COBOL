# PB5630 - Level85Forbidden refuses a subordinate group of a USAGE IS INDEX group

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Validation/StatementValidation.cs:638` (`StatementValidation.Level85Forbidden`)

**Mechanism.** `Level85Forbidden` (called from line 599 at dialect level below 2002) walks every ancestor of the operand
and refuses it as an index item (D1/D2) when any ancestor carries USAGE IS INDEX. A subordinate GROUP item of such a group
has no USAGE clause of its own; the cited 1985 rule says a group-level USAGE "applies to each elementary item in the
group" (§1985:VI.5.14.4 GR1, `cite.py --check` OK), so the clause reaches the elementary items only, not a subordinate
group. The code's comment cites §2023:13.18.60.4 GR1, which adds "and not to the group itself" (`cite.py --check` OK), so
the 2023 text agrees on the group level too. Legal 85 source that names such a subordinate group in a statement `Level85Forbidden`
guards is refused.

**Repro.** Reported by the PB5105 review (R1-1) against the tree at that branch's tip; no probe file was kept. Write a
group `01 G USAGE IS INDEX` containing a `05 SUB.` group with `10 X`, and name `SUB` as an operand of a statement the
function guards at `--std 85`; expect acceptance of a group item, observe the D1/D2 refusal.

**Fix direction.** Walk only to the first ancestor that carries a USAGE clause for an elementary operand, and ask a group
operand's own clause; golden both operands at 85.

**Related drift (info, not a defect).** The PB5105 DEVLOG entry (DEVLOG/pending-pb5105-corresponding-85-level66-index.md,
line 9) says both goldens carry a legal control line; `1985-GR-VI_6_4_3-3-usage-index.cob` has none, every PROCEDURE
statement in it is a refused one. Correct the entry's wording in the same change (a landed DEVLOG entry is history; say so in
a new DEVLOG paragraph, not by editing it).
