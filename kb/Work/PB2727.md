**Rule it breaks:** ISO §12.4.6.2 (I-O-CONTROL. [[apply-commit-clause].] [[{same-clause}…].] — rendered PDF p363: one period after the SAME-clause group), §12.3.7.2 (SPECIAL-NAMES. [clauses] … [ORDER TABLE …] . — one period; §12.3.7.3 SR31 lets one of the two go only when NO clause is written), §12.3.8.2 (REPOSITORY. [{specifier}… .] — the period printed inside the bracket, once). §5.2.1 makes the printed sequence normative. The I-O-CONTROL comment (CobolIO.g4:320-322) justifies the tolerance as 'compilers commonly tolerate a period after each', which CLAUDE.md rule 1 forbids (implementor precedence settles LATITUDE only, never a vendor's non-ISO extension); docs/CONFORMANCE.md §3.2 registers no such extension and --flag-extensions does not flag it.

**Scenario:** Measured with the built compiler (grammar of these three rules unchanged since the pin): `I-O-CONTROL. SAME AREA FOR F1 F2. SAME RECORD AREA FOR F3 F4.` compiles exit 0 at --std 85 and 2023 (two period-terminated SAME groups; the format prints one); the same paragraph with NO period at all before `DATA DIVISION.` also compiles and runs; `SPECIAL-NAMES. CLASS HEXD IS "0" THRU "9". DECIMAL-POINT IS COMMA.` compiles (the paragraph ended at the first period, so DECIMAL-POINT is not in it); `REPOSITORY. FUNCTION PI INTRINSIC. FUNCTION E INTRINSIC` with no closing period before `DATA DIVISION.` compiles and runs. Nothing is flagged even with --flag-extensions, so a program that will not compile on a conforming implementation is passed in silence. One shape in three rules, so a fix to one leaves two (feedback_two_arm_dispatch).
