# PB3334 — INDEXED on the engine

Implement FROM `docs/rearchitecture/DESIGN-runtime-library.md` §2.2.1, sections 2.2.1.3 (decision 3), 2.2.1.4 ("Keys are
BYTES", "An INDEXED record is n + 1 entries"), 2.2.1.5 (code set and collating sequence) and 2.2.1.9. Follows PB3333 (same
files: `KeyedConnector.cs`, `KeyedStoreTable.cs`, `PagedStore.cs`).

## Mechanism

- `IndexedConnector` holds root[0], the PRIME tree (prime key bytes → frame with the ordinal vector), and root[k+1] per alternate
  key, a COMPOSITE tree ((alternate key bytes, 8-byte big-endian ordinal) → prime key bytes), each under the key order its
  declared collating sequence selects (`OrdinalKeyOrder` for native, `WeightedKeyOrder` otherwise); the meta page's per-key
  descriptors carry format 4's fields plus the tree root.
- ⛔ **Each tree's `WeightedKeyOrder` is built from the sequence FROZEN AT THE OPEN, never from the declared carrier**
  (kb/Work PB3331, review w1123b R1-1): §12.4.5.7.4 GR1 (`--check` OK) "*Each collating sequence is a fixed file
  attribute and the collating sequence is set upon the successful execution of an OPEN statement that creates the physical
  file*". The declared carrier of `ALPHABET … IS LOCALE` without a locale-name is `LocaleCollation.Current`, which
  resolves LC_COLLATE at each use (§12.3.7.4 GR7 e)), so an order built over it would move with a `SET LOCALE` between two
  statements on the open file: its tree would then be searched by an order other than the one its keys were inserted under,
  and its high-water marks (`MarksOf`, 2.2.1.4) computed under the old collator, so a READ of a present key could answer '23'
  and a partial START land on the wrong record. The whole-store connector already freezes them (`FreezeOpenSequences`,
  called by `FileConnector.Open` before GR10's comparison; each key's `CobolCollation.Snapshot`, bound to the locale current
  at the OPEN and pinned to ONE collator, so a cache clear between two key builds cannot hand the tree keys of two
  collators): keep that freeze and pass its sequences to the trees. A test: the golden
  `cases/12.4.5.7-COLLATING-SEQUENCE/pb3331_locale_key_sequence_fixed_at_open` stays GREEN over the engine, plus a partial
  START after a mid-file `SET LOCALE` over a tree with nonzero marks.
- WRITE: the GR38 ascending check, the prime '22', the alternate '22'/'02' from a `Seek(prefix)` on each alternate tree, then
  `RefusedAtCommit`, then n + 1 inserts with one fresh mint value (§14.9.51.4 GR40); a key equal to its SUPPRESS WHEN value gets
  no alternate entry (§12.4.5.6.4 GR6; §14.9.30.4 GR21 c)). REWRITE: validate first (two passes as today), then `Replace` the prime
  value and, per `AltChanged(i)`, delete the old composite entry and insert the new one with a fresh ordinal (§14.9.35.4 GR24
  a)/b)). DELETE: n + 1 deletes. The release mint lives in the meta page.
- READ random under key k (§14.9.30.4 GR32): `Seek(prefix =)` on tree k gives the FIRST released duplicate (the smallest ordinal
  sorts first); the prime lookup fetches the frame. READ NEXT/PREVIOUS: the cursor on the key-of-reference tree, positioned from
  the file position indicator (a KEY VALUE, kb/Work PB342) and the prior READ's ordinal (GR21 e)/f)) exactly as
  `SelectSequentialRecord` decides today, including the 2023 after-OPEN READ PREVIOUS rule (kb/Work PB344); the '02' look-ahead
  (GR27) is the next entry's key prefix. START (GR17): `Seek` with the partial key under the order; FIRST/LAST under the prime
  tree (GR18/GR19, kb/Work PB356).
- `Ordered(keyIndex)`, `FindRandom`, `_recs.Any(...)` scans and `KeyedRec` as a list element are deleted; `IndexedStore` becomes
  the tree-handle view (`NextOrdinal` moves to the meta page).
- `docs/CONFORMANCE.md` DOC-A.1-107: the indexed sentences replaced by 2.2.1.9's text; DOC-A.1-129's key-length and key-count
  limits of the format stated (1 016-byte keys, descriptors within the meta page).

## Landed (wave 1118, group A4)

INDEXED runs on the keyed store engine. `IndexedConnector` drives `IndexedStore` (`IO/KeyedStoreTable.cs`): the PRIME tree
(the prime key's channel bytes → the record's frame, whose ordinal vector carries one release ordinal per key the meta page
records) at root[0] and one COMPOSITE tree per alternate key ((key bytes, 8-byte big-endian ordinal) → prime key) whose root
follows the key's descriptor, each under the order its collating sequence and CODE-SET select (`IndexedKeyOrders`:
`KeyOrders.Ordinal` native, `WeightedKeyOrder` otherwise, `CompositeKeyOrder` for the trees). WRITE is n + 1 inserts under
ONE ordinal minted from the meta page (`PagedFile.ReleaseMint`, claimed by `Begin`); a SUPPRESS WHEN value is no entry
(§12.4.5.6.4 GR6); REWRITE moves only the changed keys' entries to the end of their duplicates (§14.9.35.4 GR24 a)/b) by
construction); DELETE is n + 1 deletes; each is ONE page-layer statement (`KeyedStore.Change`, the multi-tree statement).
READ by key, READ NEXT/PREVIOUS (a fresh seek from the key value and the prior READ's ordinal, §14.9.30.4 GR21 d)-f), the
2023 after-OPEN rule kept) and START (a prefix seek under the key's order, §14.9.41.4 GR17; FIRST/LAST the prime tree's edges)
are seeks; '02' is the next entry's key part (GR27 a)). The record list, `Ordered`, `FindRandom`, the `_recs.Any` scans,
`KeyedRec` and `IndexedConnector.WholeStore.cs` are deleted. With both organizations on the engine the keyed lifecycle is
written once in `KeyedConnector` (kb/Work PB2753): `OpenCore`, `Attach`/`Detach`, `CloseCore`, `FpiValid`, `StartFail`,
`InvalidateFilePosition`, `Failed`, `Entered`, the coherent entry, and `FormatHolds` — a prime key past 1 016 bytes, an
alternate key past 1 008 (the measured correction: the composite entry key carries the ordinal) or descriptors past the meta
page are '39' at the OPEN in every mode, before the file is touched. `KeyedStore` is the one engine handle both stores derive
from (`KeyedStore.MediumObserver` the one fault seam). The `COBOLNET_KEYCHECK` opt-out drives the FILE's trees by key number
(DOC-A.1-129). Docs: DOC-A.1-107 (both organizations, 2.2.1.9's text) and DOC-A.1-129 (the meta page, the format's key
bounds, the opt-out's trees) rewritten; DESIGN-runtime-library 2.2.1.4 and 2.2.1.14 corrected; COBOLNET_FILES_DESIGN's
duplicate-order, coherent-entry and opt-out paragraphs describe the engine. Cases: `IndexedEngineTests` (2.2.1.16's death
after every write and refusal at every write of WRITE/REWRITE/DELETE/CLOSE under ALL OTHER, READ ONLY and NO OTHER, read
back by BOTH keys, with a second run unit's next statement; 2.2.1.17's two run units sharing one duplicate order and the '02'
look-ahead; the R2-6 READ ONLY writer beside a concurrent INPUT reader; a duplicate walk through a tree another run unit splits;
START with each operator, full and partial keys, found and not found; GR24 a)'s byte-identical untouched trees; the opt-out's
trees; format 4 and 5 files '39'; the key bounds '39'; a torn tree page '30'; 2.2.1.11's per-statement page bound), the
golden `14.9.41-START/pb3334_start_indexed_tree_operators` (with and without a FILE STATUS item and a USE declarative),
`FileBoundaryTests.IndexedRecord_IsNPlusOneEntries_*` and `IndexedWrite_TheHostsRefusalIsAtTheStatement_*`, and the indexed
rows of `KeyedStoreReloadFailureDriftTests` on the engine; the PB3334 rows of `PendingStoreCases` are now these running cases.
