# PB2532 — COBOL-85 comment-entry paragraphs are counted by no row

Filed 2026-10-07 by the train-1036 lander from the PB1508 implementer's report (wave 1032 group D,
`E:\COBOL-coord\scratch\reports\w1032d-PB1508-report.md`, "New defects").

## What happens

PB1508 made the `ClauseCardinalities` row for `IdentificationParagraphContext` (§11.2.1) rank the one element the
2023 figure prints, the `[ options-paragraph ]`, and left the COBOL-85 / COBOL-74 comment-entry paragraphs
(AUTHOR, INSTALLATION, DATE-WRITTEN, DATE-COMPILED, SECURITY, REMARKS) in the row's `Repeatable` set, because the
2023 figure does not print them (they are removed at 2002 and refused there by the removal gate). At `--std 85`,
where they are legal, nothing screens them: the COBOL-85 identification division prints each of them in its own
bracket, once, in a fixed sequence, so a repeated or reordered paragraph is non-conforming source that compiles
clean.

## Repro

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. P2532.
       AUTHOR. A.
       AUTHOR. B.
       PROCEDURE DIVISION.
           STOP RUN.
```

`cobol --std 85 p2532.cob` compiles with no diagnostic. The same holds for `SECURITY. X.` written before `AUTHOR. A.`.

## Code site

`src/WiseOwl.Cobol.Frontend/Cst/ClauseCardinality.cs#ByClauseContext`, the `IdentificationParagraphContext` row (its
`Repeatable` set and its one-element `Sequence`). The fix is an edition-aware sequence for that row (the COBOL-85
paragraphs ranked after PROGRAM-ID at 85 only), read by `ClosedFormatPass.ScreenClauseRepetition`.

## Why it was not fixed in the train

The authority is ANSI X3.23-1985, which `specs/ISO_COBOL.md` does not carry, so the rank order needs the 1985 text
rather than a `cite.py --check` against the 2023 standard. Harm is low: the paragraph bodies are comment-entries and
change no behavior.

## Landed

Fixed on branch `worktree-wf_4959cab1-c5a-12` (wave 1071 group H). Re-probed on the branch's own build first: both
repros compiled clean at `--std 85` (EXIT 0).

**The mechanism.** `ClauseCardinalities` had one figure per list, the 2023 one, so a list whose EARLIER edition
printed different elements could not be screened at that edition. `ClauseList` now carries an optional
`Earlier: EarlierFigure(Until, Figure)` chain and `At(year)` returns the figure in force at an edition;
`ClosedFormatPass.ScreenClauseRepetition` asks `row.At(edition.DialectLevel)`. The identification-division row's
earlier figure (below 2002, `"ANSI X3.23-1985"`) ranks AUTHOR, INSTALLATION, DATE-WRITTEN, DATE-COMPILED and SECURITY
and leaves OPTIONS (a 2002 introduction, COBOL0804 at 85) and REMARKS (the COBOL-74 carryover) uncounted; from
2002 the ISO §11.2.1 figure is unchanged. A row's `Clause` became `Format`, the authority the diagnostics name
("ISO §11.2.1" or "ANSI X3.23-1985"), and `UnrepeatedElements.AtMostOnce` takes the same text, so the COBOL-85 figure's
COBOL2423 / COBOL2987 never misattribute it to an ISO clause. ISO rows' messages are byte-identical.

**The figure is derived, not quoted** (the repository holds no 1985 text; `docs/VERSION_CHANGE_REFERENCE.md` row 7.10
records the derivation): each paragraph in its own bracket with the ellipsis on the comment-entry; the 38 NIST CCVS-85
programs that write them keep that sequence once each, and no source in the in-repository corpora repeats or
reorders them.

Now: two AUTHOR paragraphs at 85 → COBOL2423 at the second; SECURITY before AUTHOR → COBOL2987 at AUTHOR. At
2002+ the paragraphs stay the removal gate's (COBOL0902; under `--permissive` warnings only, not counted). Goldens
`85/pb2532_identification_comment_paragraphs_85`, `negative/pb2532-comment-paragraph-repeated`,
`negative/pb2532-comment-paragraph-out-of-order`; `ClauseCardinalityDriftTests` holds every figure of a chain to the
row obligations and pins the edition edge (`TheIdentificationDivisionRow_ScreensTheCobol85FigureBelow2002`).

## For the next implementer

- `src/WiseOwl.Cobol.Frontend/Cst/ClauseCardinality.cs#ClauseList.Earlier` / `#ClauseList.At` — an earlier edition's figure for a row (`EarlierFigure(Until, Figure)`); add one where an older figure counts or ranks an element the 2023 figure does not. `Format` is the authority string diagnostics print.
- `src/WiseOwl.Cobol.Compiler/Validation/ClosedFormatPass.cs#ScreenClauseRepetition` — asks `row.At(edition.DialectLevel)`; never read `ByClauseContext` rows directly for counting.
- `src/WiseOwl.Cobol.Compiler/Binding/UnrepeatedElements.cs#AtMostOnce` — its `format` argument is the full authority ("ISO §13.14.2"), not a bare clause number.
- `tests/WiseOwl.Cobol.Tests.Unit/ClauseCardinalityDriftTests.cs` — iterates `row.Figures()`, so an earlier figure meets the same Repeatable/Sequence obligations as the row.
- Trap: the identification-division comment-entries reach the parser blanked, so a 2423/2987 message names the paragraph as `'AUTHOR. .'`.
