# PB2532 — COBOL-85 comment-entry paragraphs are counted by no row

Filed 2026-10-07 by the train-1036 lander from the PB1508 implementer's report (wave 1032 group D,
`E:\COBOL-coord\scratch\reports\w1032d-PB1508-report.md`, "New defects").

## What happens

PB1508 made the `ClauseCardinalities` row for `IdentificationParagraphContext` (§11.2.1) rank the one element the
2023 figure prints, the `[ options-paragraph ]`, and left the COBOL-85 / COBOL-74 comment-entry paragraphs
(AUTHOR, INSTALLATION, DATE-WRITTEN, DATE-COMPILED, SECURITY, REMARKS) in the row's `Repeatable` set, because the
2023 figure does not print them (they are removed at 2002 and refused there by the removal gate). At `--std 85`,
where they are legal, nothing screens them: the COBOL-85 identification division prints each of them in its own
bracket, once, in a fixed sequence, so a repeated or reordered paragraph is non-conforming source that compiles
clean.

## Repro

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. P2532.
       AUTHOR. A.
       AUTHOR. B.
       PROCEDURE DIVISION.
           STOP RUN.
```

`cobol --std 85 p2532.cob` compiles with no diagnostic. The same holds for `SECURITY. X.` written before `AUTHOR. A.`.

## Code site

`src/Cobol.Net.Frontend/Cst/ClauseCardinality.cs#ByClauseContext`, the `IdentificationParagraphContext` row (its
`Repeatable` set and its one-element `Sequence`). The fix is an edition-aware sequence for that row (the COBOL-85
paragraphs ranked after PROGRAM-ID at 85 only), read by `ClosedFormatPass.ScreenClauseRepetition`.

## Why it was not fixed in the train

The authority is ANSI X3.23-1985, which `specs/ISO_COBOL.md` does not carry, so the rank order needs the 1985 text
rather than a `cite.py --check` against the 2023 standard. Harm is low: the paragraph bodies are comment-entries and
change no behavior.
