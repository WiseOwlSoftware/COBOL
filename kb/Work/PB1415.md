## Finding — `figurative-constant-values` (under-rejects; rows `SR-8.3.3.6.3-1`)

**Mechanism.** The VALUE clause's numeric-category screen (DataBinder.ValidateValueCategory) reads the figurative KIND through FigurativeConstants.Classify, which strips Formats 1-5's optional ALL, so 'isZeroWord' is true for ALL ZERO/ZEROS/ZEROES and the §8.3.3.6.3 SR1a 'without the ALL phrase' half is never asked — the PB218 defect (sign-condition operand) one clause over, reaching item VALUE (formats 1/2) and level-88 VALUE (format 3) under a numeric subject

**Repro.** IDENTIFICATION DIVISION. PROGRAM-ID. VZ1. DATA DIVISION. WORKING-STORAGE SECTION. 01 V6 PIC 9(3) VALUE ALL ZEROES. 01 V7 PIC S9(3)V9 COMP-3 VALUE ALL ZEROS. 01 V4 PIC 9. 88 C4 VALUE ALL ZERO. PROCEDURE DIVISION. DISPLAY V6. STOP RUN.  (probes t_u.cob, t_r.cob under out/probe/figurative-constant-values)

**Expected from the spec.** A compile-time diagnostic on each VALUE: §13.18.63.3 SR2 'If the category of the subject of the entry is numeric, all literals in the VALUE clause shall be numeric' restricts the literal to numeric, and §8.3.3.6.3 SR1a then permits only 'ZERO (ZEROS, ZEROES) without the ALL phrase'. (VALUE ZERO stays legal; the sibling spellings VALUE SPACE and VALUE ALL "0" already draw COBOLNET1657.)

**Observed / reasoning.** All three compile clean with no diagnostic and run (V6 displays 000). The procedure-division screens reject the same spelling (ADD ALL ZERO, PERFORM ... FROM ALL ZERO, IF ALL ZERO IS POSITIVE -> COBOLNET0844 citing SR1a), so the rule is enforced in one channel and not the other.

**Code site.** src/Cobol.Net.Compiler/Binding/DataBinder.cs:2273 ValidateValueCategory (isZeroWord = figOp.Kind is 'Z' after Classify's ALL strip)

## What the fixer owes

Carry 'begins with ALL' on the classified figurative (Classify returns it, never strips it) and read it in ValidateValueCategory; sweep every Classify consumer (PB1180 is the procedure-division twin).
