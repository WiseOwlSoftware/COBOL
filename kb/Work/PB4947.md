# PB4947 - a bare special register as a condition is under-rejected

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/ConditionBinder.cs` (`ConditionBinder.RefuseNonCondition`)

**Probe** (the built compiler of 2026-11-03; the arm is unchanged at main 596d9e2ad6; sources and outputs in
E:/COBOL-coord/scratch/analyses-audit/probes/PB4154/):
- `IF W` over a `PIC 9` item is refused with error COBOL2318, as it must be.
- `IF LINAGE-COUNTER` and `IF LINAGE-COUNTER OF F` draw only warning COBOL1756 ("not implemented; reaching this statement
  aborts the run unit"), and the compile succeeds.
- Run, both die with `NotImplementedCobolFeatureException`, exit 127.

LINAGE-COUNTER is an unsigned integer, not a condition: §2023:8.8.4.2.1 lists the simple conditions as "the relation,
boolean, class, condition-name, switch-status, sign, and omitted-argument conditions", and a bare identifier of a
numeric register is none of them.

**Cause.** In `RefuseNonCondition` the `BareClassWord` and mnemonic tests read `dref.cobolWord()`, which in the register
alternatives of `dataReference` is the QUALIFIER (`F`) or null (PB4154's hazard); `ctx.Refs.Probe` finds no data item for
a register, so the operand falls to the `else if (dref is { } undefined)` arm and becomes an Unbuilt (COBOL1756) instead
of `ReportNotACondition`. The fix routes LINAGE-COUNTER, LINE-COUNTER and PAGE-COUNTER (every register alternative) to the
not-a-condition refusal, with goldens for each register, bare and qualified, and sweeps PB4154's other sites that build a
message from `cobolWord()` (SEARCH ALL's "'F' is not a condition-name" for `WHEN LINAGE-COUNTER OF F` names the right
fault with the wrong word). Check the citation with `scripts/spec/cite.py --check`.
