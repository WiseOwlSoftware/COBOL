# PB3869 — a NOT-only SIZE ERROR phrase is treated as the SIZE ERROR phrase

## Owner decision

The owner APPROVED the fix on 2026-10-27 at about 10:10 PDT, in chat (Mythos session ef566665): "Approve fixing PB3869;
hand it to the operator." (A fuzz finding: the owner's standing instruction of 2026-10-24 is that no fuzz-identified
issue is fixed without explicit approval.) The fix is the root cause: every arithmetic statement's disposition asks
whether ON SIZE ERROR is written, never whether a phrase object exists, with the sibling sweep below.

**Sites:** `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/ArithmeticEmitter.cs#EmitArith`,
`src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/ArithmeticEmitter.cs#GuardedStore`,

## Landed (wave 20261728 C)

Re-probed on the branch build before the fix: all four repros reproduced (`DIVIDE 1 BY 0 GIVING Q NOT ON SIZE ERROR`
`Q=7.00 F=-` exit 0; `ADD 1 TO X` `X=9`; `MULTIPLY 50 BY M` `M=42`; `COMPUTE R = 5 / Z` `R=42`).

**The adjudicator's one-line reading was incomplete, and a plain `OnError is not null` test would have been wrong.**
§14.7.5's closing paragraph transfers control to the NOT SIZE ERROR imperative when no size error condition occurred, and
the no-phrase paragraph ignores it when one did; so a NOT-only statement must still LEARN whether the condition existed
while disposing of it as the phraseless statement does (DOC-A.1-70). Treating it as plain phraseless would have lost
the NOT imperative on every statement that fits (`ADD 1 TO X NOT ON SIZE ERROR ...` with room).

The fix: with EC-SIZE checking off and no ON SIZE ERROR phrase, `EmitArith` no longer emits the checked shape. The
operands render unchecked and each receiver goes through `DetectingStore` (set by `EcState.SizeErrDetectVar`): its
CHECKED form runs first (nothing changes when the condition exists), and if that raised the condition (checked landing
failed, or a `CobolSizeError`/`OverflowException`) its UNCHECKED form runs from the same state, landing the low-order
digits or raising what the phraseless statement raises (a zero divisor ends the run unit). A flag records that the
condition existed and `if (!flag)` guards the NOT imperative. With EC-SIZE checking ON the existing shape was already
right (fatal on a size error, NOT runs otherwise) and is unchanged. Witnesses: golden
`14.7.5-.../pb3869_not_size_error_alone` (2002+, the no-phrase rules start there; 85 leaves a size error without a
phrase undefined, so there is no refusal row: the syntax is legal at every edition), and
`SizeErrorDispositionTests` (zero-divisor rows for every divide shape and lane, the checking-off store rows over
fixed, edited and float receivers, and the checking-on pair).

Sibling sweep (probed on the branch build): CALL ... NOT ON EXCEPTION alone (program missing: terminates like the
phraseless CALL), STRING and UNSTRING ... NOT ON OVERFLOW alone (overflow: continues, phrase skipped; fit: phrase runs),
READ ... NOT AT END alone (end of file: continues like the phraseless READ), READ ... NOT INVALID KEY alone (missing key:
phrase skipped). None share the defect: only the arithmetic phrase turns a checked shape on.

## The rule

§14.7.5 distinguishes "the SIZE ERROR phrase is specified" from "a SIZE ERROR phrase is not specified", and the second
branch ends: "processing proceeds as specified in 14.6.13.1.3, Fatal exception conditions. If a NOT SIZE ERROR phrase is
specified, it is ignored." (`cite.py --check 14.7.5` OK; the sentence follows the not-specified list and governs all of it, and this defect is its items 2), a zero divisor, and 4), truncation.) So a statement written with
only `NOT ON SIZE ERROR` behaves exactly as the same statement with no phrase. With EC-SIZE checking off, WiseOwl's
documented no-phrase behavior is DOC-A.1-70: a zero divisor ends the run unit (EC-SIZE-ZERO-DIVIDE), and a result too
large for its receiver stores the low-order digits.

## The defect (reproduced on the judge, main deae52c90)

```cobol
       01 Q PIC 9V99 VALUE 7.
       01 F PIC X VALUE "-".
           DIVIDE 1 BY 0 GIVING Q
               NOT ON SIZE ERROR MOVE "N" TO F
           END-DIVIDE
           DISPLAY "Q=" Q " F=" F
```
Expected: the run unit ends with EC-SIZE-ZERO-DIVIDE, as the phraseless `DIVIDE 1 BY 0 GIVING Q` does. Actual: `Q=7.00
F=-`, exit 0.

```cobol
       01 X PIC 9 VALUE 9.
       01 Y PIC 9 VALUE 9.
           ADD 1 TO X NOT ON SIZE ERROR MOVE "N" TO F END-ADD
           ADD 1 TO Y
```
Expected `X=0 Y=0 F=-`; actual `X=9 Y=0 F=-`. COMPUTE (`R = 5 / Z`, Z zero: R keeps 42, run continues) and MULTIPLY
(`MULTIPLY 50 BY M`, M PIC 99 VALUE 42: keeps 42, expected 00) do the same. With `>>TURN EC-SIZE CHECKING ON` the same
statements terminate correctly. Repros: session ef566665 scratch `fuzz6\adj\B2\probes\nse1.cob` to `nse4.cob`.

## The cause (the adjudicator's reading; confirm before fixing)

`EmitArith` takes the checked path when `sizeErr is not null`, and a `SizeErrorPhrase` that holds only `NotOnError` is
not null. The checked path catches the size error and, having no ON SIZE ERROR statement, drops it, so the statement acts
as if ON SIZE ERROR were written with an empty imperative. A few lines further on the same method already asks the right
question (`sizeErr?.OnError is not null`).

## Siblings to sweep (rule 4; not probed)

Every paired conditional phrase where the positive phrase's absence has its own disposition: NOT ON EXCEPTION (CALL,
INVOKE, ACCEPT/DISPLAY), NOT AT END and NOT AT END-OF-PAGE, NOT INVALID KEY, NOT ON OVERFLOW (STRING, UNSTRING). The same
"phrase object is non-null" test may stand in for "the positive phrase is written" in each.
