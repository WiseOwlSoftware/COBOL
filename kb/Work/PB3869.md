# PB3869 — RETIRED — a NOT-only SIZE ERROR phrase keeping its receivers is DOC-A.1-70's documented latitude

## Retired (2026-10-27, after the merge queue bounced PR #716)

**Not a defect.** §14.7.5 sends a statement written with only NOT ON SIZE ERROR to the no-phrase rules, which end in
§14.6.13.1.3 item 8 (`cite.py --check 14.6.13.1.3 "the implementor defines whether or not execution will continue, how it
will continue, and how any receiving operands are affected"` OK): with checking off, the implementor defines whether
execution continues and how the receivers are affected. "If a NOT SIZE ERROR phrase is specified, it is ignored"
(`cite.py --check 14.7.5` OK) settles the NOT imperative, never the receivers. ISO does not control, so CLAUDE.md rule
1's precedence goes to GnuCOBOL: GnuCOBOL 3.2 keeps an overflowing resultant unchanged whenever the statement carries a
SIZE ERROR or a NOT SIZE ERROR phrase (`cobc/typeck.c`, "There is a [NOT] ERROR/OVERFLOW/EXCEPTION - Set in parser",
`COB_STORE_KEEP_ON_OVERFLOW`; `cobc/parser.y` sets `SIZE_ERROR_HANDLER` for `not_on_size_error` too), runs on, and skips
the NOT phrase. The one exception (the round-2 review of 4b840ee05): a COMP-5, COMP-X or COMP-N receiver of a NOT-only statement, which GnuCOBOL stores as if no phrase were written (its `build_store_option` sets the flag for those usages only with ON SIZE ERROR); the owner ruled that exemption
GnuCOBOL's error, so WiseOwl keeps those receivers too (kb/Work PB3989, a decision). That was main's behaviour all along, and it is what the CCVS85 programs expect. The adjudication is the
Mythos lane's reading (mailbox 20261027-185209), its citation re-checked by the operator, recorded in the branch report.

**How it was found.** The fix (branch `worktree-wf_f781f6f8-448-20`, reviewed CLEAN at `c7d7f6ed0`) made the NOT-only
statement store the phraseless low-order digits. GitHub's merge group (run 40612629630) failed twelve CCVS85 programs,

## The original finding (kept for the record)

### The rule (as filed)

§14.7.5 distinguishes "the SIZE ERROR phrase is specified" from "a SIZE ERROR phrase is not specified", and the second
branch ends: "processing proceeds as specified in 14.6.13.1.3, Fatal exception conditions. If a NOT SIZE ERROR phrase is
specified, it is ignored." (`cite.py --check 14.7.5` OK; the sentence follows the not-specified list and governs all of it, and this defect is its items 2), a zero divisor, and 4), truncation.) So a statement written with
only `NOT ON SIZE ERROR` behaves exactly as the same statement with no phrase. With EC-SIZE checking off, WiseOwl's
documented no-phrase behavior is DOC-A.1-70: a zero divisor ends the run unit (EC-SIZE-ZERO-DIVIDE), and a result too
large for its receiver stores the low-order digits.

### The finding (reproduced on the judge, main deae52c90)

```cobol
       01 Q PIC 9V99 VALUE 7.
       01 F PIC X VALUE "-".
           DIVIDE 1 BY 0 GIVING Q
               NOT ON SIZE ERROR MOVE "N" TO F
           END-DIVIDE
           DISPLAY "Q=" Q " F=" F
```
Expected: the run unit ends with EC-SIZE-ZERO-DIVIDE, as the phraseless `DIVIDE 1 BY 0 GIVING Q` does. Actual: `Q=7.00
F=-`, exit 0.

```cobol
       01 X PIC 9 VALUE 9.
       01 Y PIC 9 VALUE 9.
           ADD 1 TO X NOT ON SIZE ERROR MOVE "N" TO F END-ADD
           ADD 1 TO Y
```
Expected `X=0 Y=0 F=-`; actual `X=9 Y=0 F=-`. COMPUTE (`R = 5 / Z`, Z zero: R keeps 42, run continues) and MULTIPLY
(`MULTIPLY 50 BY M`, M PIC 99 VALUE 42: keeps 42, expected 00) do the same. With `>>TURN EC-SIZE CHECKING ON` the same
statements terminate correctly. Repros: session ef566665 scratch `fuzz6\adj\B2\probes\nse1.cob` to `nse4.cob`.

### The cause (the adjudicator's reading)

`EmitArith` takes the checked path when `sizeErr is not null`, and a `SizeErrorPhrase` that holds only `NotOnError` is
not null. The checked path catches the size error and, having no ON SIZE ERROR statement, drops it, so the statement acts
as if ON SIZE ERROR were written with an empty imperative. A few lines further on the same method already asks the right
question (`sizeErr?.OnError is not null`).

### Siblings named at filing

Every paired conditional phrase where the positive phrase's absence has its own disposition: NOT ON EXCEPTION (CALL,
INVOKE, ACCEPT/DISPLAY), NOT AT END and NOT AT END-OF-PAGE, NOT INVALID KEY, NOT ON OVERFLOW (STRING, UNSTRING). The same
"phrase object is non-null" test may stand in for "the positive phrase is written" in each.
