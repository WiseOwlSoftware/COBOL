# PB3068 — the registry of rendered views does not see an embedded generated region

**Found 2026-10-11** twice over: PB3026's implementer listed it as a note-ready lead (its report, "New defects" 1), and the
train 1063 lander's review pass (a silent-failure-hunter shard) found the check that misses it.

**Code sites:** `scripts/rendered_views.py#unregistered_problems` (reads the first `MARKER_LINES` = 12 lines of each tracked `docs/` and
`kb/` markdown for a "generated" declaration); `docs/VERSION_CHANGE_REFERENCE.md` (the `<!-- GEN:VCR-STATUS -->`
region); its generator `scripts/gen-vcr.ps1`; its check `tests/WiseOwl.Cobol.Tests.Conformance/VcrDriftTests.cs:228`
(`GeneratedStatusIndex_IsInSync`).

**Why it matters.** PB3026's rule is that the tree holds sources and derived indexes are rendered, because two queued
pull requests that each regenerate a committed index collide (DESIGN-test-build-ci.md section 3.17.4). The VCR status
region is exactly such an index — one row per gated construct, rewritten by any change that gates one — but it lives
inside a hand-written doc, so the registry's whole-file rule cannot see it.

**Fix shape.** Either (a) move the region into its own rendered view (a `VIEWS` row, gitignored, `VcrDriftTests`
asking the renderer instead of comparing a committed copy), or (b) keep it in the doc with one sorted row per construct
so it merges line by line, and teach `unregistered_problems` to scan the whole file for `<!-- GEN:` markers so the next
embedded region is caught either way. The owner's PB3026 direction (views leave the tree) argues for (a).
