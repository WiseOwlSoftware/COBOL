## Reproduced

- `reg11/p45.cob`: `REPOSITORY. FUNCTION W46HZ5.` (a zero-argument FUNCTION-ID in the same compilation group),
  then `COMPUTE R = W46HZ5()` → **`p45.cob(21,31): error COBOL0001: cannot parse construct near ')'`**.
- `reg11/p43.cob`: `01 FZ USAGE FUNCTION-POINTER TO W46HZ.` then `COMPUTE R = FUNCTION FZ()` PARSES (the keyword form
  takes another path) and the next line `COMPUTE R = FZ()` → **`p43.cob(25,27): error COBOL0001: cannot parse
  construct near ')'`**.

## Rule

- `python scripts/spec/cite.py --check 8.4.3.2.3 "the word FUNCTION may be omitted from the function-identifier"` → OK §8.4.3.2.3 2)
  (for function-prototype-name-1 and function-pointer-name-1 alike)
- `… --check 8.4.3.2.3 "If function-pointer-name-1 is specified, the parentheses shall be specified"` → OK §8.4.3.2.3 5)
  — so a zero-argument function-pointer reference MUST be written `FZ()` when the keyword is omitted; bare `FZ` is
  not an option. The §8.4.3.2.2 general format brackets argument-1 inside the parentheses (the fixer re-renders the
  printed page, `scripts/render-spec-page.py`, before relying on the transcription's diagram).

## Code site

`src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4:612` `subscriptPart : LPAREN subscriptOrRefMod SUB_RPAREN` with
`subscriptOrRefMod : subToken+`. The keyword-omitted function reference is recognised as an identifier followed by a
subscript part, and an empty subscript part cannot exist. There are 11 readers of `subscriptOrRefMod()` in the
binder; relaxing the rule to `subToken*` means each reader must answer the empty case (a subscript or
reference-modifier with nothing inside it is still illegal for a DATA reference, and must stay diagnosed with a
named code, not a null-dereference).

## Landed (wave 51 group D)

Re-probed on the implementer's own build: `p45.cob` and `p43.cob` both COBOL0001 near ')'; after the fix `p45` prints
`R=000000077` and `p43` prints `Z1=` and `Z2=000000077`. The printed §8.4.3.2.2 figure (PDF p157 / folio 127) brackets
`{argument-1 | OMITTED}` INSIDE the parentheses, so the empty list is the format's own.

- **Grammar:** `subscriptOrRefMod : subToken*` (and the nested `SUB_LPAREN subToken* SUB_RPAREN`, so SR6's NOTE
  spelling `MAX(RANDOM() A B)` parses keyword-omitted too). The ONE capture keeps carrying the keyword-omitted
  argument list; an empty group is the same thing the whitespace-only `F( )` group always was, so no reader of
  `subscriptOrRefMod()` meets a new shape (it is never null).
- **The data-reference arm, by name:** `ReferenceResolver.ScreenEmptyParentheses` / `IsEmptyGroup` refuse an empty or
  whitespace-only group after a name that resolved to a DATA item — COBOLNET2309 (§8.4.2.3.2 `( subscript … )`,
  §8.4.3.3.2 required leftmost-position) — at both resolver sites, and `DataBinder.BindConstantLength` (the
  `CONSTANT AS LENGTH OF x()` reader) asks the same predicate. ⛔ The sweep found the whitespace-only spelling was an
  existing COMPILE-CLEAN-THEN-ABORT: `DISPLAY WS-X( )` built and threw `NotImplementedCobolFeatureException` at run
  time, `MOVE … TO WS-X( )` drew COBOLNET0899's "not yet implemented". Both now draw COBOLNET2309.
- Siblings measured: `RANDOM()`, `CURRENT-DATE()(1:2)`, `MAX(RANDOM() 5 3)` and `PI()` under `FUNCTION ALL INTRINSIC`
  all run; `MAX()` draws COBOLNET1504 (at least one argument); a bare `FZ` over a function-pointer is refused as a
  non-numeric operand (SR5's parentheses). Inline method invocation already admitted `::"m"()`.
- Goldens `2002/pb969_empty_argument_list`, `2014/pb969_function_pointer_empty_arguments`; negative
  `pb969-empty-parentheses-on-data-item` (COBOLNET2309, all editions). SR-8.4.3.2.3-2 and FMT-8.4.3.2.2 GAP → CONFORMS.
