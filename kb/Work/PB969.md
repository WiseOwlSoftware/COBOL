## Reproduced

- `reg11/p45.cob`: `REPOSITORY. FUNCTION W46HZ5.` (a zero-argument FUNCTION-ID in the same compilation group),
  then `COMPUTE R = W46HZ5()` → **`p45.cob(21,31): error COBOL0001: cannot parse construct near ')'`**.
- `reg11/p43.cob`: `01 FZ USAGE FUNCTION-POINTER TO W46HZ.` then `COMPUTE R = FUNCTION FZ()` PARSES (the keyword form
  takes another path) and the next line `COMPUTE R = FZ()` → **`p43.cob(25,27): error COBOL0001: cannot parse
  construct near ')'`**.

## Rule

- `python scripts/spec/cite.py --check 8.4.3.2.3 "the word FUNCTION may be omitted from the function-identifier"` → OK §8.4.3.2.3 2)
  (for function-prototype-name-1 and function-pointer-name-1 alike)
- `… --check 8.4.3.2.3 "If function-pointer-name-1 is specified, the parentheses shall be specified"` → OK §8.4.3.2.3 5)
  — so a zero-argument function-pointer reference MUST be written `FZ()` when the keyword is omitted; bare `FZ` is
  not an option. The §8.4.3.2.2 general format brackets argument-1 inside the parentheses (the fixer re-renders the
  printed page, `scripts/render-spec-page.py`, before relying on the transcription's diagram).

## Code site

`src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4:612` `subscriptPart : LPAREN subscriptOrRefMod SUB_RPAREN` with
`subscriptOrRefMod : subToken+`. The keyword-omitted function reference is recognised as an identifier followed by a
subscript part, and an empty subscript part cannot exist. There are 11 readers of `subscriptOrRefMod()` in the
binder; relaxing the rule to `subToken*` means each reader must answer the empty case (a subscript or
reference-modifier with nothing inside it is still illegal for a DATA reference, and must stay diagnosed with a
named code, not a null-dereference).
