# PB3128 — a run-time slice of an ANY LENGTH / DYNAMIC LENGTH item into a typed group formal is refused

Source: wave 1071 (unit `w1071a`, PB2077 round 3), carried from `w1070d`'s PB2077 report (lead 2). PB2077 is held by its
branch and is NOT edited; this note names it.

**The rule.** `python scripts/spec/cite.py --check 8.4.3.3.4 "Reference modification creates a unique data item that is a subset of the data item referenced by identifier-1"` -> OK, §8.4.3.3.4 5) (GR5 b)/c) bound the slice by identifier-1's positions). `--check 14.8.2.2 "the maximum length is used"` -> OK, §14.8.2.2 2). An ANY LENGTH item and a dynamic-length item (§8.5.1.10) have no static length, so a slice of one is still a legal argument whose extent is known at run time; its formal group takes the argument's length (§14.8.2.3.2 2) d), checked OK: "its length is considered to match the length of the corresponding argument").

**Observed.** PB2077 round 1 added `RefModPlace.StaticInnerPositions` (`src/Cobol.Net.Compiler/Binding/Model/Place.cs:1181` on branch `worktree-wf_787860dd-104-18`), the ONE reader of identifier-1's positions when they are static, and null for ANY LENGTH / DYNAMIC LENGTH identifier-1. `ActivationDescriptions.OfReferenceModification` (`src/Cobol.Net.Compiler/Oo/ActivationDescriptions.cs:146`) then gets `inner == null` and describes the slice with length zero; a typed group formal of positive length then refuses with COBOLNET0828 ("formal ... is larger than the argument (0)"). The case is the report's "`StaticInnerPositions` returns null" case: `E:\COBOL-coord\scratch\w1070d\r1\g1.cob` proves the STATIC case (`G(1:N)`, `G(3:)` of a 10-character group); the ANY LENGTH / DYNAMIC LENGTH twin has no recorded repro (R2: none to run), so the implementer writes it from `g1.cob` by making `G` a `PIC X ANY LENGTH` formal of a contained program/method, or a DYNAMIC LENGTH item.

**Fix shape.** A slice of a no-static-length item needs a run-time extent: take the slice's own length expression (the `N` of `(start:N)`, or identifier-1's run-time length for `(start:)`), the way D-RM1 a) of PB2077 does for the write-back; do not guess zero. Sibling readers that took `OperandPic?.Length` before PB2077 were already switched (`CallEmitter.AreaOf` `src/Cobol.Net.Compiler/CodeGen/Verbs/CallEmitter.cs:680`, `ConditionBinder.StaticBoolRefLength` `Binding/Procedure/Verbs/ConditionBinder.cs:262`); `AcceptDisplayEmitter.cs:100` spells `OperandPic?.Length ?? ImageWidth` and was not read (SIGN SEPARATE / DYNAMIC LENGTH unjudged): sweep it.

## Landed (wave 1072 group E, 2026-10-13)

**Re-probe (this worktree's build, before the fix).** A method with `01 LA PIC X ANY LENGTH` doing `INVOKE SELF "TG"
USING LA(1:M)` / `LA(3:)` into a 4-byte group formal, and `D PIC X DYNAMIC LENGTH` doing `INVOKE T "TG" USING D(1:N)` /
`D(3:)`: all four refused COBOLNET0828 "larger than the argument (0)"; the universal twin compiled. The sibling sweep
found the same root in two more places, both WRONG ANSWERS and silent: `MOVE LA(2:5) TO X1 X2` (the §14.9.25.4 GR1
intermediate) gave `x1=B     ` (a one-position capacity), and `ACCEPT D(3:)` / `ACCEPT LA(2:)` / `ACCEPT S(2:)` (S
`PIC S9(4) SIGN LEADING SEPARATE`) transferred 0, 0 and 3 characters (`AB        `, `A     `, `-0009`). Probes:
`E:\COBOL-coord\scratch\w1072e\p\a1.cob` to `a5.cob`.

**Root.** identifier-1's positions were read as if every item's description fixed them: `RefModPlace.InnerPositions`
(`PositionCount`, which is the ONE PICTURE symbol of an ANY LENGTH item) sized the intermediate, the activation
description used `StaticInnerPositions` and fell to ZERO when it was null, and `AcceptDisplayEmitter` re-spelled the
count as `OperandPic?.Length ?? ImageWidth` (the PICTURE length: one for ANY LENGTH and DYNAMIC LENGTH, the digits
without the SIGN SEPARATE position).

**Fix.** Two readers, one question each. `RefModPlace.MaximumInnerPositions` (replacing `InnerPositions`) is the BOUND:
the static count, a DYNAMIC LENGTH item's §8.5.1.10.1 maximum size, and for an ANY LENGTH item, whose description fixes
none (§13.18.2.4 GR1 b)), the carrier's ceiling `CobolDynString.MaxLength`. `SendingValueTemp.OfPlace` and
`ActivationDescriptions.OfReferenceModification` read it; docs/CONFORMANCE.md D-RM1 a) now says how such a slice's
maximum extent is measured, so a `LIMIT 3` slice still never fits a 4-byte group formal. At run time
`PlaceRenderer.SliceLength` is the ONE evaluated-length renderer (the specified length, or identifier-1's static count
or CURRENT length from the leftmost position, §8.5.1.10.4 / §13.18.2.4 GR1 b)): the ACCEPT transfer width and
`CallEmitter.AreaOf`'s extent both take it (`CallEmitter.SliceExtent` deleted). `ConditionBinder.StaticBoolRefLength`
was already right (the exact static length; null fails open) and is unchanged; `PtrBinder`'s range-check size answers
another question and ADDRESS OF a dynamic-length item is refused anyway (§8.4.3.11.3 SR6, COBOLNET2785).

**Review round 1 (w1072e-review-r1).** R1-1: the SIGN SEPARATE sweep missed its USAGE NATIONAL twin.
`RefModPlace.PositionCount` read the PICTURE length for every national item, which is the digit count alone, so
`PIC S9(4) USAGE NATIONAL SIGN LEADING SEPARATE` measured 4 positions where §8.4.3.3.4 GR3/GR4 give 5 (`cite.py
--check 8.4.3.3.4 "the sign position is assigned an ordinal number within that data item"` -> OK, GR4). Measured:
`ACCEPT S(2:)` gave `-0009`, and `T(1:5)` / `T(5:1)` / `S2(2:4)` were refused COBOLNET2670. Fixed at the reader: only a
BIT item (and a national GROUP, through its as-if PICTURE) reads `OperandPic.Length`; an elementary national item takes
`ImageWidth`, which counts national positions and the separate sign. Pinned by
`conformance:2002/pb3128_refmod_national_sign_separate` and
`AcceptDifferentialTests.Device_OmittedLengthNationalSignSeparateSlice_CountsTheSignPosition`. R1-2: the §8.5.1.10.1
quotation "the smallest of" is not the standard's text ("is smallest of:"); corrected in `Place.cs` and in the twelve
sibling quotations of the same misquote across `src/`, `tests/` and `docs/CONFORMANCE.md`.

**For the next implementer.**
- `src/Cobol.Net.Compiler/Binding/Model/Place.cs#MaximumInnerPositions`: the bound of identifier-1; `#StaticInnerPositions` the exact static count. Never `PositionCount` of an ANY LENGTH item.
- `src/Cobol.Net.Compiler/CodeGen/Roslyn/PlaceRenderer.cs#SliceLength`: the C# `int` of a slice's evaluated length. Reuse it; never re-spell `Max(0, size - start + 1)`.
- `src/Cobol.Net.Compiler/Oo/ActivationDescriptions.cs#OfReferenceModification`: the compile-time `Positions` is the maximum extent; both run-time lanes overwrite it with the evaluated length (`CobolInvokeArg.ReferenceModified`, `CallEmitter.Described`).
