## Measured (adjudicator / refuter evidence, verbatim)
### GR-14.7.5-8 (PARTIAL)
|| REFUTED: PARTIAL — The adjudicator's premise that 'each explicit site has a live code site throwing the named EC' is false. §14.7.4.3 r7 is one of the rules case 8 delegates to, and it names EC-SIZE-TRUNCATION; the OUTERMOST-division PROHIBITED arm (CobolNum.DivideOrThrow) throws CobolSizeError('PROHIBITED rounding on an inexact quotient') with NO ec name, so it defaults to EC-SIZE-OVERFLOW. With the SIZE ERROR phrase the condition does exist and the phrase runs (the half that is verified); without it, under checking, the wrong level-3 EC is set, so a USE AFTER EC-SIZE-TRUNCATION declarative never sees it. Two halves, one verified -> PARTIAL.
- **Code location (record):** src/Cobol.Net.Runtime/Values/Numeric/CobolSizeError.cs#CobolSizeError; src/Cobol.Net.Runtime/Values/Numeric/CobolDec.cs#Pow; src/Cobol.Net.Runtime/Control/CobolPtr.cs; src/Cobol.Net.Compiler/CodeGen/Verbs/ArithmeticEmitter.cs#EmitArith; src/Cobol.Net.Compiler/CodeGen/Verbs/ArithmeticEmitter.cs#StoreArith

### GR-14.7.5-L2.1 (DIVERGES)
|| REFUTED: DIVERGES — Rule 1 of the phrase-specified branch: a size error during the arithmetic operations leaves ALL resultants unchanged and runs the SIZE ERROR phrase. A zero divisor is a size error (case 2) whatever the operand usage, but the native FLOATING arm renders a bare C# double '/' with no zero-divisor test (NumericRenderer's Divide/DivideOrThrow covers only the Int128 arm). COMPUTE FR = FL / FZ ON SIZE ERROR ... NOT ON SIZE ERROR (FLOAT-LONG operands and receiver) runs the NOT phrase and STORES +Infinity into FR; DIVIDE FZ INTO FR ON SIZE ERROR does the same. A wrong answer delivered silently on the exact situation the rule governs (2002+, where FLOAT-LONG exists). The fixed-point probe legs the adjudicator ran do hold.
- **Code location (record):** src/Cobol.Net.Compiler/CodeGen/Verbs/ArithmeticEmitter.cs#EmitArith; src/Cobol.Net.Compiler/CodeGen/Verbs/ArithmeticEmitter.cs#StoreArith; src/Cobol.Net.Runtime/Values/Numeric/CobolSizeError.cs#CobolSizeError

### GR-14.7.5-L3.2 (DIVERGES)
|| REFUTED: DIVERGES — No-phrase rule 2 requires EC-SIZE-ZERO-DIVIDE for ANY zero divisor in a divide operation or DIVIDE statement. The floating-point arm never tests the divisor: with EC-SIZE checking on and a USE AFTER EC-SIZE declarative, COMPUTE FR = FL / FZ (FLOAT-LONG) raises nothing, runs the NOT phrase and stores Infinity; DIVIDE FZ INTO FR the same; IF FL / FZ > 1 evaluates TRUE with no EC; COMPUTE A = FL / FZ into PIC 9(3) raises the WRONG level-3 EC, EC-SIZE-TRUNCATION (the Infinity saturates at the store). Only the Int128/SDIDI arms the adjudicator probed are right.
- **Code location (record):** src/Cobol.Net.Compiler/CodeGen/Emit/NumericRenderer.cs#Divide; src/Cobol.Net.Compiler/CodeGen/EcEmitter.cs; src/Cobol.Net.Runtime/Values/Numeric/CobolSizeError.cs#CobolSizeError

### GR-14.7.5-L3.5 (DIVERGES)
|| REFUTED: DIVERGES — Rule 5: a nonzero result nearer to zero than the receiver permits under ROUNDED MODE IS PROHIBITED sets EC-SIZE-TRUNCATION. The adjudicator probed only COMPUTE with a literal VALUE (0.35). When the value is a QUOTIENT - the outermost division computed at the receiver's scale by CobolNum.DivideOrThrow - the PROHIBITED throw carries no EC name and sets EC-SIZE-OVERFLOW instead. DIVIDE 1 BY 30 GIVING D ROUNDED MODE IS PROHIBITED (D PIC 9V9; 0.0333 is nonzero and nearer to zero than 0.1) and COMPUTE D ROUNDED MODE IS PROHIBITED = 1 / 30 both dispatch the declarative with EC-SIZE-OVERFLOW. Wrong level-3 EC: a USE AFTER EC-SIZE-TRUNCATION section never runs. Non-division PROHIBITED legs (literal, ADD, MULTIPLY, float/20) are right.
- **Code location (record):** src/Cobol.Net.Compiler/CodeGen/Verbs/ArithmeticEmitter.cs#EmitArith; src/Cobol.Net.Compiler/CodeGen/Verbs/ArithmeticEmitter.cs#StoreArith; src/Cobol.Net.Compiler/Binding/RoundingModes.cs
