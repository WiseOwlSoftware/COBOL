# PB3325 — review finishers are not in the dispatch ledger

## Source

`E:\COBOL-coord\scratch\reports\w1101a-PB3198-report.md` (wave 1101 A), as relayed by the Mythos session of 2026-10-16/17.

## Repro

While a wave's own review finisher (`fix-<letter>-r<n>`) runs on a DONE-with-FINDINGS branch, run any planner
(`plan_wave.py`, the Mythos session's or the loop's): it offers a duplicate finisher for that branch, and the survey reads the
branch DECISION. On 2026-10-16 the planner offered a finisher for PB3198 (wave 1101 A) in the plans of waves 1102, 1103 and
1104 while wave 1101's review finishers were running; the Mythos session recorded a hand hold (ledger entry 1101AR1) as a
stop-gap.

## Harm

A foreseeable duplicate dispatch (two finishers on one branch) unless a session holds it by hand (memory rule
prevent-known-failures). Process only.

## Code site

`.claude/skills/workstream/templates/wf_rolling_wave.js`, `fixFindings` (about lines 166-175): it calls `agent(...)` for the
`fix-<letter>-r<n>` finisher and never calls `record_dispatch`, so `<coord>/inflight-groups.json` holds no entry for it and
`held_by_dispatch` (`plan_wave.py`) does not hold the note.

## Fix shape

When the wave dispatches a review finisher, `record_dispatch` an entry (slug `w<wave><letter>-r<n>`, the group's notes and
file set); drop it at that agent's result. `held_by_dispatch` then holds the note.
