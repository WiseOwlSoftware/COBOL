# PB5322 - a RED audit did not withdraw the gate's slot ticket

**Sites:** `scripts/gate.py` (`Gate._gate`, `Host.take_slot`); `scripts/gate_slot.py` (`GateSlots.acquire`).

**Evidence.** Run `000004-20261111T162601Z` of worktree wf_c902d12a-c75-2: the audits finished RED at about 6 min
(`timings.audits_s` 350.0, "RENDERED VIEWS RED - fail-fast: an audit was RED while the gate queued for the slot: NO TEST RAN"),
but `verdict.json` and `gate.log` were written only when the gate took slot 2, 72 min later (`slot_wait_s` 4328.9). The worker
waited 66 minutes for a verdict known at 08:32, and the ticket stood ahead of five other gates the whole time.

**Root cause.** PB4326 moved the audits beside the slot wait. `Gate._gate` checked `_audits_known_red` once BEFORE
`take_slot` and once AFTER it (`_tested`); `GateSlots.acquire` blocks in its poll loop with no way for the caller to say "my
verdict is decided". An audit that ended RED during the wait was seen only at the slot. There is one wait loop, so the fix is
in that loop and no second path exists.

**Fix.** `GateSlots.acquire(abandon=)` polls the caller's predicate before every attempt; true withdraws the ticket
(`_drop_ticket`, the exit every exception already took), takes no slot and raises `QueueAbandoned`. `Host.take_slot` passes it
through; `Gate._gate` hands it `_audits_known_red` and ends the gate in `_audit_red` (verdict.json, log, exit 1). A GREEN audit
changes nothing (the gate waits for its slot), nor does a RED test after the slot.

**Witness.** gate_slot.py self-test arm "a queued waiter whose abandon turns true withdraws its ticket" (real queue: one holder,
one waiter; the ticket is gone and the queue behind is served); gate.py self-test arm "audit-slot" now plants a queue that never
admits the gate and a RED audit: the gate returns within seconds, no slot taken, ticket gone, verdict file written. Both fail on
the old code (`acquire` has no `abandon`; the old planted queue returned only when the slot was taken).
