## Extended 2026-09-24 by REGISTRAR 15c (lane-3 batch d2-15c, pinned tree `071ff04ea`)

### Finding — `report-counters` (crashes; rows `GR-8.4.3.15.4-1`)

**Mechanism.** A report counter (and LINAGE-COUNTER) in an identifier slot binds as BoundComputedOperand wrapping BoundReportCounterRef, not as a numeric integer item, so every consumer that expects an item either aborts at run time (the string-image visitor) or refuses it (the integer classifier).

**Repro.** One RD R1 (PAGE LIMIT 10 ... FOOTING 9), INITIATE R1, GENERATE D1, then any one of these: `DISPLAY PAGE-COUNTER.` / `DISPLAY LINE-COUNTER OF R1.` / `MOVE LINE-COUNTER TO WS-X` (PIC X(4)) / `IF PAGE-COUNTER IS NUMERIC ...` / `STRING "P" PAGE-COUNTER DELIMITED SIZE INTO WS-X`. Each compiles clean and aborts: NotImplementedCobolFeatureException 'computed expression in a string context'. `PERFORM PAGE-COUNTER TIMES ...` is refused COBOLNET1646. Sibling: `DISPLAY LINAGE-COUNTER` aborts the same way. Probes rcd1/rcd2/rcd3/rcd6/rcd9/rcda/lnc.cob under E:\Temp\claude\E--CobolSharp\a700c052-f9e4-4942-84ff-a13c7505d6ec\scratchpad\adj-d2\out\probe\report-counters

**Expected from the spec.** §8.4.3.15.4 GR1: the counters 'reference temporary unsigned integer data items of class and category numeric'; §8.4.3.15.3 SR1: 'In the procedure division, PAGE-COUNTER and LINE-COUNTER may be referenced in any context where an integer data item may appear'. After INITIATE + one GENERATE placing the detail at line 1 of page 1: DISPLAY PAGE-COUNTER shows 1 as an unsigned integer image, MOVE LINE-COUNTER TO a PIC X(4) moves its digits left-justified, IS NUMERIC is true, and PERFORM PAGE-COUNTER TIMES runs once.

**Observed / reasoning.** ExpressionBinder.FieldOperand returns `new BoundComputedOperand(rcx)` for `host.Rw.CounterExpr(dref)`. OperandText.AsStringVisitor.Visit(BoundComputedOperand) emits EmitText.LoudValue('string', 'computed expression in a string context'), which DISPLAY, MOVE to alphanumeric, STRING and the class condition reach. ControlFlowBinder.CountOperand runs IntrinsicResultType.IsIntegerOperand, which does not treat the computed counter as an integer item. The arithmetic, relation, subscript and function-argument paths go through RefExpr and work (COMPUTE -> 0031, relation, WS-E(PAGE-COUNTER), MAX). R16 fixed this same shape for index-names by adding a compile-time screen, which is correct for them because they are illegal there. For the counters the operand is LEGAL, so the fix is to render the counter as an integer item in these slots, not to screen it.
