Record text as adjudicated:

Split from `call-returning-invalid-returning-field` during reduction: the same pair of programs with numeric items
(which cobc's CALL check accepts) compiles with only the warning "program RETURNING is not implemented [-Wpending]",
and the run dies with SIGSEGV at the first statement of the called program that stores into the RETURNING item. cobc
3.2 implements RETURNING for user-defined functions only; for a program it gives the linkage-section returning item no
storage, yet still produces an executable. Same result under `-std=cobol2014` and the default dialect.

## Minimal test case

Free reference format (`-fformat=free`), `records/call-returning-invalid-returning-field--program-returning-crash.cob`:

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. RETX.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 WS-R PIC 9(3).
PROCEDURE DIVISION.
    CALL "SUBRX" RETURNING WS-R
    DISPLAY WS-R
    STOP RUN.
IDENTIFICATION DIVISION.
PROGRAM-ID. SUBRX.
DATA DIVISION.
LINKAGE SECTION.
01 LK-R PIC 9(3).
PROCEDURE DIVISION RETURNING LK-R.
    MOVE 123 TO LK-R
    GOBACK.
END PROGRAM SUBRX.
END PROGRAM RETX.
```

## Expected result (per ISO)

ISO/IEC 1989:2023, all checked with `scripts/spec/cite.py --check`:

- §14.2.2 SR 4): "The RETURNING phrase may be specified in a method definition, a program definition, or a program
  prototype." SR 5): "Data-name-2 shall be defined as a level 01 entry or level 77 entry in the linkage section."
- §14.2.3 GR 6): "Data-name-2 is the name used in the function, method, or program for the result that is returned to
  the activating element according to 14.6.5, Results of runtime element execution." NOTE 1 to that rule: "In COBOL,
  the storage for the returning item is allocated in the activating source unit. The activated element contains only
  a formal description in its linkage section."
- §14.9.4.4 GR 4): "If a RETURNING phrase is specified, the result of the activated program is placed into
  identifier-3."
- §14.8.3.3: the receiving operand "shall have the same ALIGN, BLANK WHEN ZERO, DYNAMIC LENGTH, JUSTIFIED, PICTURE,
  SIGN, and USAGE clauses" — `PIC 9(3)` against `PIC 9(3)` conforms.

Expected: `123`, exit 0.

Edition: the RETURNING phrase of a program's procedure division header and CALL ... RETURNING were introduced in
ISO/IEC 1989:2002 and are in 2014, the edition `-std=cobol2014` claims; unchanged in 2023 (Annex E lists no change).

Edition as recorded by the adjudicator: 2014. `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Fix site (GnuCOBOL 3.2 source, read observationally)

`cobc/parser.y`, the `RETURNING WORD` alternative of the procedure division header's returning rule (lines 11190-11222):
for a program (`prog_type` not `COB_MODULE_TYPE_FUNCTION`) the assignment `current_program->returning = $2` is
disabled under `#if 0` with the comment that it "doesn't work for programs, will be fixed with allocating in the
source-unit", and `CB_PENDING ("program RETURNING")` is issued instead (lines 11211-11219). The returning item is left a
linkage item with no storage and no caller-supplied address, so the MOVE dereferences an invalid pointer. A fix
passes the caller's identifier-3 storage to the called program (as for functions, per 14.2.3 GR 6 NOTE 1); until
then, an error rather than a `-Wpending` warning would stop the crashing executable from being produced.

**Title:** Feature request: PROCEDURE DIVISION RETURNING in a program (announced as "not implemented" at compile time; the run ends in an unchecked NULL linkage access)

**Body:**

Environment: GnuCOBOL 3.2.0 (Ubuntu `gnucobol3 3.2-4build1`), Linux x86_64.

Steps: save as `retn.cob`, run `cobc -std=cobol2014 -fformat=free -x -fsource-location -o retn retn.cob && ./retn`.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. RETX.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 WS-R PIC 9(3).
PROCEDURE DIVISION.
    CALL "SUBRX" RETURNING WS-R
    DISPLAY WS-R
    STOP RUN.
IDENTIFICATION DIVISION.
PROGRAM-ID. SUBRX.
DATA DIVISION.
LINKAGE SECTION.

```

Observed: compile succeeds with `warning: program RETURNING is not implemented [-Wpending]`; the run fails with
`retn.cob:16: attempt to reference invalid memory address (signal)`, last statement MOVE at line 16, exit 139.

Expected: `123`. ISO/IEC 1989:2023 (and 2002/2014) 14.2.2 syntax rule 4 allows RETURNING in a program definition;
14.2.3 general rule 6 (NOTE 1) places the returning item's storage in the activating source unit, and 14.9.4.4 general
rule 4 places the result in the CALL's identifier-3. Until program RETURNING is implemented (`parser.y`, the `#if 0`
around `current_program->returning` for programs), reporting it as an error rather than a warning would avoid
producing an executable that crashes.
