## The rule (every citation re-run by the registrar through `cite.py --check`)

## Finding — `string-statement` (under-rejects; rows `SR-14.9.43.3-2`)

**Mechanism.** M2 - ExpressionBinder.FigurativeOperand drops the word ALL from `ALL ZERO/SPACE/HIGH-VALUE/LOW-VALUE/QUOTE`, so the STRING sending-position SR2 screen (which keys on BoundAllLiteral.BeginsWithAll) never sees them

**Repro.** 01 OUT1 PIC X(10) VALUE ".........".  STRING ALL ZEROES DELIMITED BY SIZE INTO OUT1  (probe sr2c.cob; also sr2a.cob with ALL SPACES) - pinned cobol.exe --std 2023 --run

**Expected from the spec.** §14.9.43.3 SR2: "Literal-1 or literal-2 shall not be a figurative constant that begins with the word ALL." The expected result is a compile-time rejection, the same COBOLNET1757 that `STRING ALL "AB"` (conformance:negative/pb1029-string-all-literal) and `DELIMITED BY ALL SPACE` already get.

**Observed / reasoning.** The program compiles without errors and runs, printing [0........ ]: the figurative is transferred as one '0'. The grammar arms `ALL ZERO | ALL SPACE | ALL HIGH_VALUE | ALL LOW_VALUE | ...` of figurativeConstant reach FigurativeOperand's `fig.ZERO() is not null -> new BoundFigurative('Z')` arms, and nothing records that ALL was written. BindString's sender screen checks only `BoundAllLiteral { BeginsWithAll: true }`. The delimiter position is caught only because the grammar's own `DELIMITED BY ALL` token is tested separately, which is the two-arm shape: one position is fixed and the other is not. Every other statement whose rules bar "a figurative constant that begins with the word ALL" through the same BeginsWithAll test (see BoundTree.cs:509 and RefusalNodeDriftTests) should be swept for the same loss.

**Code site.** src/Cobol.Net.Compiler/Binding/Procedure/ExpressionBinder.cs#ExpressionBinder.FigurativeOperand; src/Cobol.Net.Compiler/Binding/Procedure/Verbs/StringUnstringBinder.cs#StringUnstringBinder.BindString (line ~42)
