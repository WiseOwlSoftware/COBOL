# PB1923 — LANDED (CONFIRMED, w1033)

Filed by the train-1004 lander from wave 1004 group C's report (`w1004c-PB1175-report.md`).

## Question

Wave 1004 group C (kb/Work PB1055) read §8.4.2.3.3 SR5 e) and SR6 as: the data-name-2 of a Format-2 SORT is written
with exactly OCCURS-count − 1 subscripts (one per enclosing table, a rightmost ALL being an omission), so `SORT TE(1)`
over a one-level table names an ELEMENT, not a table, and is refused with COBOLNET2097. Before the change it sorted the
whole table silently. The reading rejected was that a subscript for the table's own level is ignored.

**Site.** `src/Cobol.Net.Compiler/Binding/ReferenceResolver.cs#ScreenTableSubjectArity` (one line to change if
overturned). Negative golden `conformance:negative/pb1055-table-sort-subject-subscripts`.

**Verdict needed.** CONFIRM (close as landed) or OVERTURN (admit and ignore the own-level subscript), citing the clause.

## Adjudication 2026-10-07 (w1033)

Decision `E:\COBOL-coord\scratch\w1033-adj\PB1923-decision.md`; refuter `PB1923-refute.md` (core ruling UPHELD; "no defect, no lead" OVERTURNED). Pinned build `pin-97006f3` (main `97006f310`).

**Outcome: CONFIRMED (PB1055's determination is correct); closed as landed. No defect in the own-level subscript rule.** The refuter's version is the outcome: the decision's "no defect, filed no lead" is wrong for the same
data-name-2 reference, and the sibling is filed as `PB2511` (SORT Format-2 subject never screened for a reference modifier).

**Spec (cite.py --check OK; the refuter re-ran all six and added Annex D).**
- `§8.4.2.3.3 SR3` (one subscript per OCCURS of the referenced element); `SR5 e)` exempts "the subject of a SORT statement that references a table where the rightmost subscript is not the word ALL" and with ALL rightmost the count is
  "one less than the number of OCCURS clauses"; `SR6` permits ALL "as the rightmost or only subscript of a table in the table format of a SORT statement. This is equivalent to omitting the rightmost or only subscript in this context."
- `§14.9.40.3 SR13` imports `8.4.2.3`; `§14.9.40.4 GR18`: the SORT sorts the TABLE referenced by data-name-2. So `SORT TE(1)` over a one-level table (a single element) breaks SR5 e)/SR6 and must be refused (COBOLNET2097); the legal spellings
  are `SORT TE` and `SORT TE(ALL)`. Pre-PB1055 sorting the whole table was a silent wrong answer, not a lost extension.
- Refuter's rejected alternative (ALL counted): ruled out by informative Annex `D.3.6.4` (`sort tabl2 (t1-ind, ALL) descending elem-item1 of group2.`: enclosing subscript plus ALL in the own position; "tabl2 normally requires two levels of subscripting, but
  cannot be subscripted as data-name-2 in the SORT statement"); `§14.9.37.3 SR2` says the same for SEARCH. No clause admits a numeric own-level subscript and then ignores it. GnuCOBOL 3.2.0 also refuses `TE(1)`.

**Code and probes.** `src/Cobol.Net.Compiler/Binding/ReferenceResolver.cs#ScreenTableSubjectArity` (line 1159: `enclosing = table.SubscriptArity - 1`, refused unless `written == enclosing`); `InterpretSubscripts(..., admitRightmostAll: true)` (lines 2175/2184) drops a
rightmost ALL, implementing SR6. Probes `PB1923\p1own..p7nestbare` (seven shapes match the spec; GnuCOBOL lacks SR6's ALL) and refuter `PB1923-refute\` (refused: `NE(ALL)`, `R(1)`, `R(1, ALL)`, `R(ALL)`, `R(1, 2, 1)`, `TE(K)`, `TE(X1)`, `ROW(1)` with COBOLNET2097;
`NE(ALL, ALL)`, `NE(ALL, 2)` COBOLNET2363; `X(1)`, `X` with no OCCURS COBOLNET1757; sorted correctly: `NE(RX)`, `NE(RX + 1)`, `NE OF T2 (2)`, `NE(1 + 1)`, `NE(2 ALL)`, `R(1, 2, ALL)`, `TD(ALL)`, `ROW(ALL) DESCENDING`). Golden
`tests/conformance/negative/pb1055-table-sort-subject-subscripts` (reject-at 2002 2014 2023); optionally add the SR6 cite to its header. Wording polish (not a defect): with zero enclosing tables the 2097 text still says "writes 0 subscripts, outermost first".

**Open observation (not decided).** `TE(ALL)` is accepted at `--std 2002` and `2014`; no 2002/2014 text in the repository shows whether SR6's SORT ALL existed before 2023, so that edition gate stays open (a missing observation is not a negative).
