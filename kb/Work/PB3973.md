# PB3973 — a self-test read a child's command line before Linux had set it

**Sites:** `scripts/orchestrator/impact_lane.py` (`self_test`, its arm 8b), `scripts/orchestrator/land_lane.py`
(`self_test`, its test 10b)

## Observed

The operator's second gate of `notes-pb3838-tier5`, a change of three notes and a DEVLOG entry, ended `=== BUILD-LOCAL
GATE: RED — LINUX HALF RED`: `scripts/orchestrator/impact_lane.py --self-test` failed one check, `a live Python that
does not is a stranger on a reused pid, not the worker (got True, want False)`. The first gate of the same branch was
GREEN; the third, unchanged, was GREEN; six isolated WSL runs of the self-test passed.

## The mechanism (measured)

`worker_alive` (and `land_lane.runner_alive`) read a live Python's command line from `/proc/<pid>/cmdline` and treat an
EMPTY one as alive on purpose (a live worker must never be started beside). The arms spawn a stranger and check it at
once. `subprocess.Popen` returns when the child's close-on-exec error pipe closes, which happens inside `execve` before
Linux sets the new image's argument area, so for a moment the child's `/proc/<pid>/cmdline` reads empty. Measured under
WSL (the operator's scratchpad `cmdline_race.py`, 300 spawns, reading the file the moment Popen returns): 78 empty idle,
55 empty with eight CPU-bound processes; never the parent's command line. An empty read makes the stranger "alive", so
the check reads True.

## The fix

Each spawned sleeper prints `ready` once Python runs, and the arm reads that line before it checks (`cmdline_ready.py`,
the same 300 spawns read after `ready`: 0 empty). The arms' processes are killed, waited and their pipes closed in the
`finally`. Sibling sweep (`grep -rn 'subprocess.Popen(\[sys.executable, "-c"' scripts`): the same shape is
`land_lane.py` test 10b (fixed the same way); `run_gate_legs.py`'s holder and follower already wait for a handshake
(`readline`, the pid file); `enqueue.py` and `test_plan_wave.py` spawn `pass` and check only that it ended.

Verified: `impact_lane.py --self-test` 5 of 5 GREEN under WSL with eight CPU-bound processes and GREEN on Windows;
`land_lane.py --self-test` GREEN on Windows, and its test 10b passes under WSL (three other land_lane checks fail when the
self-test runs from the /mnt/e checkout, the same on unchanged main; the gate runs it in a WSL clone, where it passes).
