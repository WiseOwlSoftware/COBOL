# PB5895 - a sum counter that is its own addend is refused at --std 85 under a 2023 rule

Filed by the PB5789 branch from the Mythos lane's rulings on the printed folios, `kb/Work/PB5683/2026-11-17-rulings-pb5789-folios.md`. The ruling's bullet, unchanged:

- kb/Work PB5895 (rejects legal source at 1985): a sum counter that is its own addend (`S5 SUM WS-A S5`) is refused
  COBOL2730 under `§2023:13.18.54.3 SR4e`, a 2023 rule. Programs: `.../f/probes/sumxf.cob` and
  `.../f/refute-sum/probes/rfself.cob`.

**The rules.** `§1985:XIII.3.19.4 GR9a` (printed folio XIII-54, kb/Work PB5789): "When one of the addends is the sum counter defined by the data description entry in which that SUM clause appears, the initial value of that sum counter at the time of summation is used in the summing operation". `§1985:XIII.3.19.3 SR1` permits a sum-counter identifier "defined either in the same report group that contains this SUM clause" or a lower one. No 1985 syntax rule forbids a self addend. (`cite.py --check`: OK for both.)

**The refuter's program** `rfself.cob` (`E:/COBOL-coord/scratch/my-20261115/w20262099/f/refute-sum/probes/rfself.cob`), in full:

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. RFX.
       ENVIRONMENT DIVISION.
       INPUT-OUTPUT SECTION.
       FILE-CONTROL.
           SELECT PF1 ASSIGN TO "RFX.OUT".
       DATA DIVISION.
       FILE SECTION.
       FD PF1 REPORT IS R1.
       WORKING-STORAGE SECTION.
       01 WS-KEY PIC 9 VALUE 1.
       01 WS-A   PIC 99 VALUE 0.
       REPORT SECTION.
       RD R1 CONTROL IS WS-KEY.
       01 D1 TYPE DE LINE PLUS 1.
          02 COLUMN 1 PIC 99 SOURCE WS-A.
       01 CFK TYPE CF WS-KEY LINE PLUS 1.
          02 SA COLUMN 1  PIC 999 SUM WS-A SA.
          02 SB COLUMN 5  PIC 999 SUM WS-A.
          02 SC COLUMN 9  PIC 999 SUM WS-A.
       PROCEDURE DIVISION.
       DECLARATIVES.
       CF-USE SECTION.
           USE BEFORE REPORTING CFK.
       CF-USE-P.
           DISPLAY "CF " SA " " SB " " SC.
       END DECLARATIVES.
       MAIN SECTION.
       P0.
           OPEN OUTPUT PF1.
           INITIATE R1.
           MOVE 1 TO WS-A. GENERATE D1.
           MOVE 2 TO WS-A. GENERATE D1.
           MOVE 2 TO WS-KEY.
           MOVE 4 TO WS-A. GENERATE D1.
           TERMINATE R1.
           CLOSE PF1.
           STOP RUN.
```

Printed at `--std 85` (run `.../f/refute-sum/runs/rfself-001`, exit 65):

```
  rfself.cob(18,44): error COBOL2730: a chain of SUM data-name-1 references never terminates: 'SA' of report 'R1' → 'SA' of report 'R1' — any chain of reference shall terminate at an entry that does not contain a SUM clause referring to a data-name-1 defined in the report section (ISO §2023:13.18.54.3 SR4 e))
```

By GR9a the program is legal. SA subtotals WS-A (1 + 2 = 3), then crossfoots its own value at the time of summation (3), giving 6. SB and SC hold 3. The second footing has SA = 4 + 4 = 8.

Printed at `--std 85` (run `.../f/runs/sumxf-001`, exit 65):

```
  sumxf.cob(25,44): error COBOL2730: a chain of SUM data-name-1 references never terminates: 'S5' of report 'R1' → 'S5' of report 'R1' — any chain of reference shall terminate at an entry that does not contain a SUM clause referring to a data-name-1 defined in the report section (ISO §2023:13.18.54.3 SR4 e))
```

**Every edition's rule to be read.** `§2023:13.18.54.3 SR4e` refuses the self chain at 2023. Each held edition's own text (2002, 2014) decides whether it does there. The fix is an edition arm of the chain check. The value it adds at 85 is GR9a's: the counter's value at the time of summation. That value also depends on the crossfoot order (kb/Work PB5894).
