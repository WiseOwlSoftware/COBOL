# PB874 — OPEN — the wave-local gate's composition excludes its only independent oracle

Source: the `PB344-finisher2` report, "New defects" item (b) — recorded there as "Process, for the orchestrator,
not a compiler defect", which is why it needs a register note rather than a paragraph.

## Measured, on this tree

```
$ grep -n "Leg " scripts/build-local.ps1
64: Leg 'conformance'      @('tests/Cobol.Net.Tests.Conformance', '--no-build', '--filter', $Filter)
65: Leg 'unit'             @('tests/Cobol.Net.Tests.Unit', '--no-build')
66: Leg 'characterization' @('tests/Cobol.Net.Tests.Characterization', '--no-build')

$ grep -rln "class NistDifferentialTests" tests/
tests/Cobol.Net.Tests.Conformance/NistDifferentialTests.cs

$ python scripts/filter_population.py --filter "FullyQualifiedName~Nist" --filtered tests/Cobol.Net.Tests.Conformance
  FullyQualifiedName~Nist  ->  selects 356 in Cobol.Net.Tests.Conformance
```

Two of the three legs run UNFILTERED by design; the third — the one holding the NIST differential — runs under
whatever `-Filter` the implementer wrote. The 356 cases are therefore in the per-commit gate only by
coincidence of wording. The PB344 finisher reports that the twenty-five filter terms named across five
implementer reports matched NONE of them.

## Why this is a defect and not a preference

The NIST goldens are the only wave-local evidence whose expected output COBOL.NET did not write. Every
`tests/conformance/**` golden is authored from the same reading of the standard as the code it guards, so a
determination made from a WRONG reading is pinned, not contradicted, by its own golden — `feedback_green_gates_arent_evidence`
and `feedback_green_test_can_hold_a_gap_open` in their most expensive form. `kb/Work/PB837` (the SORT/MERGE
USING retrieval failure hooked to the implicit CLOSE's status) is exactly that class: a behaviour no
COBOL.NET-authored golden disagrees with.

The cost of closing it is measured and small: the leg is ~1.5 min, against a ~2 min wave-local budget that
already accepts a full unfiltered Unit assembly.

## Code site and the shape of the fix

`scripts/build-local.ps1` (the three `Leg` invocations, lines 64-66) and its `scripts/build-local.sh` twin — the
two must move together; `kb/Work/PB751` records that these twins drift. The fix is a FOURTH leg that runs
`tests/Cobol.Net.Tests.Conformance --filter "FullyQualifiedName~Nist"` unconditionally, beside the caller's own
filtered conformance leg, so the caller's `-Filter` governs what ELSE runs and never what the NIST leg runs.
Adding `~Nist` to the briefs (which the PB344 lander did for I/O changes) is the hand-maintained list rule 5
forbids: it works only for the implementer who remembers, on the change class someone predicted.

`scripts/filter_population.py`'s accounting must learn about the new leg at the same time, or the unconditional
leg becomes a second assembly "the gate runs UNFILTERED" that the INERT-term message does not know about —
`kb/Work/PB839` owns that message and should be read alongside.
