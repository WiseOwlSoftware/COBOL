# PB5687 - the verdict baseline of the GnuCOBOL differential sends a change to the full lane

**Sites:** `scripts/lane_classification.py` (`CLASSIFICATION.read`, the entry for `tests/external/gnucobol-verdict-baseline.tsv`),
`scripts/corpus_sweep.py` (`BASELINE`), `scripts/gnucobol_differential.py` (whole: the file that reads the baseline at its `--baseline` default), `scripts/battery.sh` (whole: the nightly's caller of the differential),
`scripts/build_targets.json`.

**What happened.** Branch `worktree-agent-a1eea5830c42debfa` (PR #1723, wave 20262046 group A) changed two lines of
`tests/external/gnucobol-verdict-baseline.tsv`, one script and that script's self-tests. Its gate chose the full lane and ran
the whole Windows population: `tests_s` 3114.5, `wall_s` 3753.6 (`verdict.json`, `timings`).

**Evidence.**
- `E:/COBOL/.claude/worktrees/agent-a1eea5830c42debfa/TestResults/build-local/000001-20261115T174836Z/gate.log` line 3:
  "build-local: full lane (scripts/lane_classification.py) — 1 of 8 changed path(s) may be read by a compiler test or the
  build, e.g. tests/external/gnucobol-verdict-baseline.tsv; 3 touch(es) a script, e.g. scripts/gnucobol_differential.py".
- `scripts/lane_classification.py` line 390: `"tests/external/gnucobol-verdict-baseline.tsv": "scripts/corpus_sweep.py (the
  differential's committed cases)",` (an entry of the `read` map).
- In this session `scripts/gnucobol_differential.py` (line 300, `--baseline` default), `scripts/corpus_sweep.py` (line 59,
  `BASELINE`) and `scripts/battery.sh` (the nightly) were the readers of the file that were seen; no test target of
  `scripts/build_targets.json` and no build step was seen to read it.

**The question this note asks.** Does any test target of `scripts/build_targets.json`, or the build, read
`tests/external/gnucobol-verdict-baseline.tsv`? If none does, the file belongs to the tooling lane; if one does, the entry's
named reader says which.
