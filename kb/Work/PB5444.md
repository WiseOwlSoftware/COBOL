# PB5444 - the survey's CLI reads no chain records

**Site.** `scripts/prune_worktrees.py#main` calls `live_survey(reports_dir=..., min_age=..., stale_hours=...)` with no
`coord_dir`. `live_survey` passes that `None` to `chain_records`, which returns `[]` for `None`
(`if not coord_dir: return []`), so `chain_links` holds no link of a one-file chain (kb/Work PB4396). The landing lane
(`land_lane.py`, `live_survey(repo, coord_dir=cdir, ...)`) and the planner (`plan_wave.py`) pass the directory and read the
chain. `in_flight_slugs` and `coord.reports_dir` already fall back to the default coordination directory on `None`;
`chain_records` alone treats `None` as "no ledger", a silent default where the input is unresolved
(memory feedback "an unresolvable input fails loudly").

**Witness (2026-11-12, main d457dec4d5).** `python scripts/prune_worktrees.py --brief` printed
`WAITING TO LAND worktree-wf_c902d12a-c75-3 ... the landing lane lands it (enqueue.py land)`; the session probe printed
the same line (it runs `--brief`). The landing lane's `E:\COBOL-coord\land-lane\survey.json` from the same minute reads the row
`IN FLIGHT`: "dispatch w20261998c left an overflow (PB5118, PB5174) that a later wave plans onto this branch: one step per
file, the chain lands once, with its last link". The lane correctly never landed it.

**Harm.** The two production readers disagree about one branch. An attended session or an enqueue unit that trusts
`--brief` sees a branch "the lane lands" that never lands, and O11 ("nothing simple waits") invites it to land the link by
hand, which lands a one-file chain before its last link: the step PB4396 exists to prevent. `--apply` deletes only LANDED
rows, so no work is lost.

**Fix direction.** One reader, one default: `live_survey` (or `chain_records`) resolves `coord_dir` through
`coord.coord_path()` the way `in_flight_slugs` and `coord.reports_dir` do, so every caller reads the same ledger; give the
CLI `--coord` for the self-test's scratch directory. Add a self-test case where the CLI path (no explicit directory) and the
lane's path survey one chain record and must agree. PB5439's split of `prune_worktrees.py` should carry the fix into
`branch_survey.py` if it lands first.
