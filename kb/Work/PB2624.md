**Scenario:** DiagnosticDescriptors.cs:422-498 declares COBOL0100, 0101, 0102, 0103, 0107, 0200, 0201, 0300, 0303, 0304, 0305, 0306, 0307, 0308, 0309, 0310 and 0312 as DiagnosticSeverity.Warning, each with a MessageTemplate. Their only product use is CobolErrorStrategy.GuessCobolIntent (CobolErrorStrategy.cs:164-352). It builds DiagnosticHint(descriptor, <message re-typed as a literal>, priority), and BuildMessage (:129-145) reads only descriptor.Code into a '[CODE] ...' prefix. CobolErrorListener.SyntaxError (CobolErrorListener.cs:61-90) parses the code back out of the string and calls diagnostics.ReportError, so the severity is Error whatever the descriptor says. The compile fails: GeneralFormatViolationTests pins PBGF03/05/15/18/21 as REFUSED with COBOL0307. So the registry states a severity no user ever sees, and it keeps a second copy of every message that nothing checks against the first (COBOL0303's template and the literal at CobolErrorStrategy.cs:270 are equal today only by hand). Of the 30 descriptors the census finds reachable at the pin (R0-0152 lists the other 187 as unreachable), only CBL3620-3622, through CopyProcessor.Report -> DiagnosticBag.Report(descriptor, ...), read DefaultSeverity and MessageTemplate. Cost: PB2363 generates DiagnosticDescriptors.g.cs from diagnostics.json, and design §8.3 (2) maps `severity` and `message` straight from these records. That wave would carry 17 false 'warning' rows into the generated catalog and into any documentation rendered from it, and it would freeze the duplicate text as data.
