# PB4957 - a truncated message still delivers a tag from beyond the capacity

**Sites:** `src/WiseOwl.Cobol.Runtime/Messaging/AsyncMessaging.cs` (`SlotsOf`, `Resolve`, `Resolved`, `TagOf`, `SendToServer`, `SendResponse`, `MessageOutcome`), `src/WiseOwl.Cobol.Runtime/Messaging/MessageSlot.cs` (`MessageSlot`), `src/WiseOwl.Cobol.Runtime/Messaging/PeerFrame.cs` (`MessageBody.Carrying`, `MessageBody.Truncated`, `PeerFrameCodec.Writer.Body`, `PeerFrameCodec.Reader.Body`), `src/WiseOwl.Cobol.Runtime/Messaging/ProtocolMessages.cs` (`StatementResult`), `src/WiseOwl.Cobol.Runtime/PublicAPI.Unshipped.txt`, `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/MessagingEmitter.cs` (`EmitReceive`, `SentMessage`), `src/WiseOwl.Cobol.Compiler/CodeGen/Roslyn/RuntimeApi.cs` (`AsyncSlotsOf`, `AsyncResolved`, `AsyncTagOf`), `src/WiseOwl.Cobol.Compiler/CodeGen/Roslyn/PlaceRenderer.cs` (`ImagedGroupLeaves`, `CellLeaves`; `WriteMessageGroupImage` deleted), `src/WiseOwl.Cobol.Compiler/CodeGen/DataDivision/GroupImageCodec.cs` (`EmitImageMethods`, `EmitMemberFromImage`, `TableElementFromImage`, `EmitVarImageMethods`; `FromMessageImage` deleted), `src/WiseOwl.Cobol.Compiler/CodeGen/DataDivision/PhysicalModel.cs` (`Physical.Group` deleted), `src/WiseOwl.Cobol.Compiler/Binding/Model/DataItem.cs` (`HoldsOnlyMessageTagSlots`, `CurrentExtentMessageImageCapable` docs)

**Report (round-1 review LEAD, low; left for the clerk because AsyncMessaging.cs is not a file the PB4744 finisher changed).** `TagOf` takes the message's first slot whatever position it came from, and `MessageBody.Truncated` cuts the image to the capacity but keeps every slot. So a too-long message received into an elementary message tag sets the tag to a tag that lay beyond the 8 positions D-MCS-LENGTH says identifier-1 receives (docs/CONFORMANCE.md D-MCS-LENGTH: an elementary message tag is an 8-position message whose tag travels as its one slot).

Expected (to be adjudicated, not decided here): `Truncated` drops the slots that start beyond the capacity (or `TagOf` checks the slot's position against the capacity), with a two-process test that sends a message longer than 8 positions to an elementary tag receiver. Sweep `MessageBody.Truncated`'s other readers.

## Resolution (landed)

Re-probed on the w20261930a build with a two-process test (`MessagingProcessTests.AReceivedTagIsTheContentOfItsOwnPositions_SoATagTheMessageCarriedElsewhereOrPastTheCapacityIsNotIt`): a sender's `[X(8) LOW-VALUES, tag]` received into an elementary tag gave `T1 SET` (the slot-0 tag), where §2023:14.9.31.4 GR1b ("The content of identifier-1 is the content of the message") and GR3's cut to identifier-1 give NULL. The defect was wider than the elementary arm: `WithTags` matched slots to the receiver's tags in storage ORDER, so any two layouts that differ (a `[tag, tag]` receiver of `[X(8), tag]`) put a tag where the message held data.

Fix (one mechanism, positions decide): each slot now carries the TOKEN that stands for its tag in the image (`MessageSlot`, encoded on the wire); the receiver stores the image as a record area is stored (the record struct's `FromImage`, so `FromMessageImage` and its skip plumbing are deleted), each tag decoding its own positions by the DOC-A.1-212 token decode, and `AsyncMessaging.Resolved` replaces an unresolved tag whose positions are a carried slot's token by that slot's tag. A storage-cell receiver (`PlaceRenderer.ImagedGroupLeaves`) decodes its tags from their positions because the window write does not reach the cell's managed slots. `MessageBody.Carrying` keeps only the slots whose token the image holds, so a cut to the capacity (`Truncated`, on the GRANT and REPLY paths) and an unused OCCURS DEPENDING occurrence carry no tag. Witnesses: the test above, `AReceivingGroupInAStorageCell_TakesEachTagFromItsOwnPositions_NotFromTheSlotItHeldBefore`, and `MessagingProtocolTests.AMessageCarriesOnlyTheSlotsItsImageHolds_SoACutToTheCapacityDropsATagPastIt`.

## Landing

- `src/WiseOwl.Cobol.Runtime/Messaging/AsyncMessaging.cs#Resolve` owns the rule (a received tag is its positions; a carried token maps to its slot); `SlotsOf` builds slots, `Resolved` walks a leaf vector, `TagOf(image, slots)` is the elementary arm. Reuse `Resolve`, never match slots by order.
- `src/WiseOwl.Cobol.Runtime/Messaging/PeerFrame.cs#MessageBody.Carrying` is the one construction of a body with slots (drops slots whose token the image lacks); `Truncated` goes through it.
- `src/WiseOwl.Cobol.Runtime/Messaging/MessageSlot.cs#MessageSlot` (token + tag) is the wire and outcome slot type; the codec refuses a token that is not 8 units.
- `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/MessagingEmitter.cs#Emit(BoundReceiveMessage)` stores a group through `EmitImageInto` (FromImage), then `WriteGroupLeaves(AsyncResolved(ImagedGroupLeaves(..)))`.
- `src/WiseOwl.Cobol.Compiler/CodeGen/Roslyn/PlaceRenderer.cs#ImagedGroupLeaves` - trap: a storage cell's byte-window image write does not update its managed slots, so a cell's tags are decoded from their positions (`CellLeaves(slotsFromPositions: true)`).
- `src/WiseOwl.Cobol.Compiler/CodeGen/DataDivision/GroupImageCodec.cs#EmitImageMethods` - there is no `FromMessageImage`; a message area receives through `FromImage`.
