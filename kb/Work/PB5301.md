# PB5301 - a constant-name and a data item of one spelling: the reference takes the constant instead of being refused as ambiguous

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs` (`UniqueOrReportAmbiguous`, the COBOL1639 ambiguity reporter whose candidate set must include the constants), `src/WiseOwl.Cobol.Compiler/Binding/ConstantEntryBinder.cs` (`ResolveConstantName`, which takes the constant before the data items are asked). The exact member that lets `DISPLAY KK` pick the constant is not located: the fix site belongs to the first implementer.

**Rule.** §2023:8.3.2.2 exception 3 lets a constant-name and a data-name have one spelling in a source element. §2023:8.4.2.2.1 1) (`cite.py --check` OK: "No other name has the identical spelling.") lets a name be written unqualified only when no other name has its spelling; a constant-name cannot be qualified, so a reference `KK` with both a constant KK and a data item KK is not unique and shall be refused (the COBOL1639 family, §2023:8.4.2.2.3 SR1).

**Repro** (`E:/COBOL-coord/scratch/w-mythos/w20261998a/p/c1.cob`, fixed format):

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. C1.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  KK CONSTANT GLOBAL AS 5.
       01  KK PIC 9 VALUE 1.
       PROCEDURE DIVISION.
           DISPLAY KK.
           STOP RUN.
```

**Observed.** `cobol c1.cob --source-format fixed`: exit 0, no diagnostic; the program displays `5` (the constant), though the data item KK is as much a match.

**Expected.** A refusal of `DISPLAY KK` as an ambiguous reference. A program that never references KK stays legal (exception 3).

**Owed.** Make the resolver ask uniqueness across constants and data items together (one candidate set, so the next name class is automatic), golden at the introducing edition (constants exist from 2023) and one refusal.
