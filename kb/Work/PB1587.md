# PB1587

Raised 2026-09-25 by the doc-rows-2 d5 refuter while refuting item 164 (RESERVE default), probes under
`<scratchpad 9db39f61…>\doc2\out\run-refute\d5` (RSV.cob, RSV2.cob). Derive from §9.1.15 (file sharing) and the WRITE / READ general rules whether a record written
by one connector must be visible to a sharing reader before CLOSE; survey GnuCOBOL (fileio.c flush behaviour under
sharing) per rule 1; then either close as a documented determination (with the DOC-A.1-164 row's I-O-area statement) or
convert to a defect (flush per WRITE when the file is shared).

## doc-rows-2 landing (2026-09-25)

## Landed (wave 1126, group C)

**Decision.** ISO decides, so the answer is the standard's: §14.9.51.4 GR12 (*"The successful execution of a WRITE
statement releases a logical record to the operating environment"*) puts a written record in the physical file at the
statement, and §9.1.15 2) (*"restricts concurrent access to a physical file through file connectors other than this one,
to input mode"*) admits the INPUT connector beside a `SHARING WITH READ ONLY` writer, whose READ selects from that file
(§14.9.30.4 GR21). The standard prints no buffering rule that could keep a record in a run-unit area. So this is a defect,
not a determination, and the doc-rows-2 / PB643 reading (records wait in the 4,096-byte area until it fills) is retired.
GnuCOBOL 3.2 (probes under the wave scratch dir, WSL cobc): SEQUENTIAL and RELATIVE visible at the WRITE, LINE
SEQUENTIAL and INDEXED not (their stdio and Berkeley DB buffers). It is no authority where ISO controls, and it agrees
with the ISO answer for the two organizations where its answer is not an artifact of its own buffering.

**Re-probe on the build** (`rsv.cob`, and one program per organization): SEQUENTIAL and LINE SEQUENTIAL, OUTPUT and
EXTEND, `SHARING WITH READ ONLY` writer: WRITE `00`, reader READ `10`. RELATIVE: `00` (the engine writes per statement).
INDEXED, reader in the SAME run unit: `00` (one in-memory store); reader in ANOTHER run unit: `10` (the whole store
persisted at CLOSE). One rule, three organizations answering one program three ways.

**Fix.** `SequentialConnector.ReleaseRecord` flushes (and announces the release to sibling readers) whenever
`FileLockPosture.AdmitsAnotherRunUnit(HostShare)` - every mode but `NO OTHER` - where it asked `AdmitsAnotherWriter`;
the ordinal-off-the-medium count and the repositioning append stream stay on `AdmitsAnotherWriter`.
`IndexedConnector.CoherentUnder` (the whole store) asks the same predicate, so a changed store is persisted at the
statement. The cost is one flush per record for a READ ONLY writer; `NO OTHER` keeps its buffered load.

**Witnesses.** `conformance:cases/14.9.51-WRITE/pb1587_write_released_to_input_reader`, `..._line_sequential` (2023) and
`..._keyed_organizations` (relative and indexed; the `21` and `22` refusals release nothing);
`ReadOnlyWriterReleaseDriftTests` (every framing x OUTPUT/EXTEND x READ ONLY/ALL OTHER, the read-ahead reader, the empty
file `10` then `46`, the refused reader `61` beside READ ONLY and NO OTHER, the keyed organizations across two run units, and
`/dev/full` answering `34` at the FIRST write). `pb643_reserve_areas_visibility` is re-derived: the count of areas changes
nothing a sibling reader sees (100 in every phase). DOC-A.1-164 and `DESIGN-runtime-library.md` carry the new text.

**Left for PB3334.** The INDEXED whole-store arm is fixed here only until PB3334 replaces it: the engine's
`AdmitsAnotherRunUnit` is the same rule, and `AKeyedReadOnlyWriter_IsReadByAnotherRunUnit_AtTheWrite[Indexed]` is the
witness the engine must keep green.

**Landing (for the next implementer).**
