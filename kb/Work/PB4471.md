# PB4471 - the PB4454 golden quotes the sequential-access branch of the WRITE rule

**Site (origin/main, confirmed):** `conformance-suite/cases/13.18.27-GLOBAL/pb4454_global_file_operand_under_unnamed_root.cob`, the comment block
at lines 18-30: the `cite.py --check 14.9.51.4 "the relative record number of the record being released is moved into the relative key
data item by the operating environment during execution of the WRITE statement"` line ends `-> OK  14.9.51.4 29) a)`. The review line
reads `:24`; the quoted citation is on lines 24-30.

**Why it is wrong.** INNERG writes `RFL`, a relative file with `ACCESS MODE RANDOM` opened I-O. `29) a)` is the SEQUENTIAL access-mode
branch (the operating environment moves the release's relative record number into the relative key). The rules that govern this WRITE:

- `29) b)`: "If the access mode of the write file connector is random or dynamic, prior to the execution of the WRITE statement the value
  of the relative key data item shall be initialized by the runtime element with the relative record number to be associated with the
  record that is to be written."
- `32)`: "When a relative file is opened in the I-O mode and the access mode is random or dynamic, records are to be inserted in the associated
  file. Prior to the execution of the WRITE statement, the value of the relative ke[y data item ...]".

Both validated: `python scripts/spec/cite.py --check 14.9.51.4 "<text>"` prints `OK  14.9.51.4 29)` (the sub-rule b) is the one printed) and
`OK  14.9.51.4 32)`. The expected output is unaffected: the key is the caller's input and stays `0002` (the golden prints `RK=0002`).

**Fix.** Replace the quoted text and the `-> OK` line with the 29) b) and 32) texts, say in the prose that the key is the caller's input
and is not overwritten, and re-run `cite.py --check` on each. Sweep: `grep -rn "29) a)" conformance-suite/cases` for the same inherited
mis-citation on other RANDOM or DYNAMIC relative-file goldens.
