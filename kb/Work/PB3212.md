**Scenario:** External: DataBinder.Odo.cs:511-512 (HasExternalAttribute) and DataBinder.cs:4312-4317 (IsInExternalRecord) are the same expression `HasExternalClause || ExternalFromType || Files.Any(f => f.IsExternal && f.Records.Contains(root))`, differing only in that one walks to the root itself; BinderDriver.cs:374 (ExternalItemIdentity, the section 14.8.4.2 corresponding-external-item key behind COBOLNET1575) tests only `HasExternalClause || ExternalFromType`, so an item of an EXTERNAL FD record answers not external there and external at the other two, and no site records whether that difference is intended; DataBinder.Linkage.cs:646-689 (CallBindExternalAndGlobal) re-derives the same three cases as three loops. Global: DataBinder.Odo.cs:504-505 (IsGlobalRecord, also read by DataBinder.Reports.cs:2691) computes HasGlobalClause or GLOBAL-FD record by a Files scan, while DataBinder.Linkage.cs:649 and 696-700 build the same population into _callGlobalRoots. A fourth source of the attribute (for example an EXTERNAL or GLOBAL attribute inherited another way) must be added at every copy, and the narrower copy shows they already diverge.
