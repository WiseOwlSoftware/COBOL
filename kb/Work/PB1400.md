## Measured (rows this note claims beyond the findings above)

### `GR-8.5.2.5-3` — PARTIAL (adjudicator + refuter record, verbatim)

Rule: '3) A group item explicitly or implicitly described with a GROUP-USAGE clause with the BIT phrase.' (cite.py OK). Both halves verified: explicit (GB) and IMPLICIT (subordinate group GBS inside a GROUP-USAGE BIT group) -- probe p2.cob: LENGTH(GBS)=6 boolean positions (§15.50.4 r1), MOVE B"110011" TO GBS -> GB1=1100 GB2=11. pb522 golden derives the boolean-position LENGTH of explicit and nested bit groups from §8.5.2.5 item 3 + §15.50.4. || REFUTED: PARTIAL — The LENGTH, MOVE and COMPUTE-boolean paths treat a GROUP-USAGE BIT group as boolean. GBS B-OR B"101010" works, and MOVE GB TO a PIC 1(4) item gives 1011. But a second site restates group class without the GROUP-USAGE branch: ExpressionBinder.NonNumericOperandKind has the arm '_ when p.Item.IsGroup => class alphanumeric, ISO 8.5'. So COMPUTE N = GB + 1 on a bit group is rejected with a diagnostic that tells the user the bit group is 'class alphanumeric'. §8.5.2.1 and §8.5.2.5 item 3 make it class and category boolean. This is one rule in two places, and one of them is wrong for this rule's subject. The rejection itself is correct. Fix: derive that text from ItemCategory.GroupKindsOf / ClassOfItem.

### `GR-8.5.2.10-3` — PARTIAL (adjudicator + refuter record, verbatim)

Rule: '3) A group item explicitly or implicitly described with a GROUP-USAGE clause with the NATIONAL phrase.' (cite.py OK). Both halves probed (p2.cob): subordinate group GS inside '01 GN GROUP-USAGE NATIONAL' -> LENGTH 3 national positions, BYTE-LENGTH 6, and MOVE "XYZ" TO GS converts to national as an elementary PIC N(3) (§13.18.29.4 GR2 b) -> GN1=XY GN2=Z. pb522 derives explicit + nested national group LENGTH; negative/pb59-display-of-group pins the complement (a plain group is not national). || REFUTED: PARTIAL — MOVE, LENGTH and the SR10 screen treat a GROUP-USAGE NATIONAL group as national. MOVE 'PQ' TO GN converts, and MOVE GS TO X2 is rejected as a national sender. The same second site as the bit group, ExpressionBinder.NonNumericOperandKind's IsGroup arm, gets it wrong: COMPUTE N = GB + 1 on a national group is diagnosed as 'group item GB (class alphanumeric, ISO 8.5)', but §8.5.2.10 item 3 / §8.5.2.1 make it class national. Two sites derive group class, and one lacks the GROUP-USAGE branch. There is also a group-MOVE lead, recorded under GR-8.5.2.3-3: a national group moved into an alphanumeric group is converted instead of being copied without conversion (§14.9.25.4 GR5).

## What the fixer owes

Derive the diagnostic's class text from ItemCategory.GroupKindsOf / ClassOfItem (the one derivation LENGTH/MOVE already use) and delete the private IsGroup arm. The refusal itself is correct; this is the one-rule-two-places shape.
