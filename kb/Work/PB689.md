# PB689 — OPEN — twenty-six rules the denominator never counted

Found 2026-09-05 by the `PB329` implementer (report §"New defects" N2) while looking for §14.9.51.4 GR23's inventory
row to close — there is none. Its scan (`<a9d94900 scratch>/PB329/scan_gr.py 14.9.30.4 14.9.35.4 14.9.51.4`):
`14.9.30.4 spec 1–32 | inventory max 32`; `14.9.35.4 spec 1–25 | inventory max 25`; **`14.9.51.4 spec ordinals 1–42,
count 42 | inventory max 16, count 16`**, with interior headings `['## SEQUENTIAL FILES', '## 15 Intrinsic
functions']`. Confirmed on main: `grep -c '"rule-id": "GR-14.9.51.4-'` over the inventory counts 16 rows.

## The mechanism

`scripts/spec/extract_rule_catalog.py` scans a clause's text up to the next `#`-heading; `specs/ISO_COBOL.md` line
≈29358 carries `## SEQUENTIAL FILES` as a sub-heading inside §14.9.51.4's general rules (the transcription of the
printed running head, or a group heading the standard itself prints mid-list). Everything after it — GR17 through
GR42, GR23's '71' among them — never reached `docs/rearchitecture/spec-rule-catalog.json`, so `build_inventory.py`
never made a row. The GAP metric v1.0 is defined against is therefore computed over a denominator that is short by
at least 26 rows in this clause alone, and the implementer measured only three clauses.

## Fix

Rule 5: fix the STRUCTURE, then re-derive the denominator. (1) Make the section scan stop only at a heading whose
number is a clause number (`#### 14.9.52`, `### 14.10`, …), never at an unnumbered interior `##`; better, key the
scan on the clause hierarchy the transcription already carries. (2) Sweep every clause: list the interior unnumbered
headings inside numbered clauses across the whole spec and the per-clause rule counts the catalog holds versus the
ordinals the text prints — a drift test that the catalog's count per clause equals the printed count. (3) Rebuild the
catalog and the inventory once, on a quiet main (no lander running — the inventory JSON is shared by every landing),
record the GAP change as the denominator correction it is (the ledger's trend line will step UP; the narrative must
say why), and re-attribute the new rows to the notes that already own their mechanisms (GR23 → PB329's landed
mechanism, via a batch). Also check whether the transcription's interior heading is itself a transcription artifact
to repair (rule 1: fix the transcription on discovery) — if the printed page has no such heading, remove it.
