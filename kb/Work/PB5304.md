# PB5304 - decision: kb/Work PB191's true-offset determination covers the 1989 CURRENT-DATE row 1989-RV-A.2.11.3-1; it is one implementor choice, recorded once

**Question (kb/Work PB5164 item 1; set 1's NEEDS-OWNER-DECISION row).** Does the owner decision of kb/Work PB191, which reports the TRUE UTC offset in positions 18-19 of CURRENT-DATE and WHEN-COMPILED even beyond the table's range, cover the 1989 intrinsic-function amendment's row `1989-RV-A.2.11.3-1`?

**Decision: yes.** §1989:A.2.11.3 prints the same table PB191 decided for 2023 ("two numeric digits are returned in the range 00 through 13"), and one formatter, `CobolDate.Format21`, serves every edition. So it is the same implementor choice, made once, and it is recorded once: docs/CONFORMANCE.md's CURRENT-DATE / WHEN-COMPILED offset entry now states that it holds for the 1989 amendment, and names the 1985 ground for documenting it (§1985:I.1.5.2.1: elements specified in part by the implementor).

**What it implies for the row.** The adjudicator's file gives the row NEEDS-OWNER-DECISION, recommending DOCUMENTED-NON-SUPPORT once this decision is made. That verdict follows from the decision, but no refuter has attacked it and the file does not carry it as a verdict, so the row is left open (not recorded). The verdict this decision implies is DOCUMENTED-NON-SUPPORT, the verdict PB191 gave the 2023 rows `RV-15.21.3-1` and `RV-15.99.3-1`. PB5164's second item (R43 and `1985-GR-VII.4.4.4-9`) is not decided here.

**Why it is mine to decide.** The CLAUDE.md Ownership section delegates design and implementor-latitude decisions; extending an existing determination to an older edition's identical table is one.
