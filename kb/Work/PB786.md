# PB786 — OPEN — the sweep PB712 proposed, still done by hand

Filed 2026-09-06 by the registrar from the PB712 finisher's report (`PB712-report.md` §"New defects" (c)).
**It is filed as its own note rather than appended to [[PB712]] deliberately**: PB712's fix lands with train 20
and its `status` flips to `landed` in that same change set, at which point the mechanical sweep it proposed in
one closing sentence would become an open obligation inside a closed note — the precise shape CLAUDE.md rule 8
exists to prevent (a live item sitting in prose where no work list can see it).

## The claim that is testable, and is not tested

A general format's figure note in `specs/ISO_COBOL.md` states, in prose, what the printed delimiters mean. The
WRITE one, `specs/ISO_COBOL.md:29192`:

> ⚠ **Two groups in this figure carry CHOICE INDICATORS** (the `|` bars). (1) `BEFORE`/`AFTER` sit inside choice
> indicators enclosed by **braces**: per 5.2.6.4 that means one or more of the enclosed alternatives, each
> specified at most once, in any order. (2) The `AT … END-OF-PAGE` and `NOT AT … END-OF-PAGE` phrases sit inside
> choice indicators enclosed by **brackets**: zero or more of them may be specified, each at most once, in any
> order …

Mechanically checked: `cite.py --check 5.2.6.4 "one or more of the alternatives contained within the choice
indicators shall be specified"` → **OK §5.2.6.4** (*Choice indicators*), and `cite.py --check 5.2.6.3 "braces"`
→ **OK §5.2.6.3** (*Braces*). So the note is a statement with a truth value about a `.g4` rule: **the enclosed
WORDS repeat, the surrounding PHRASE does not.** A grammar that repeats the phrase instead has transcribed the
choice indicators as repetition, which is what PB712 measured: `WRITE R BEFORE AFTER ADVANCING 4 LINES` — the one
spelling §14.9.51.2 prints — was rejected outright, while a two-operand form the standard never prints compiled
and silently discarded an end-of-page condition.

**Population, measured on main `07cbb2ad`:** `grep -c "braces enclosing choice indicators" specs/ISO_COBOL.md`
→ **15**; WRITE's note is a sixteenth, worded differently (`grep -n "enclosed by \*\*braces\*\*"` →
`:29192`). Sixteen live claims; zero of them checked by anything.

## ⛔ Premise correction — the crude grep does NOT return nothing

The dispatch (and PB712's report, written on its own worktree) says the check *"currently returns nothing"*. On
`origin/main` at `07cbb2ad` it returns one line:

```
$ grep -rnE "^\s*[:|]\s*([a-z][A-Za-z0-9]*)\s+\1\??\s*(;|$)" --include=*.g4 src/Cobol.Net.Frontend/Grammar/
src/Cobol.Net.Frontend/Grammar/Core/CobolIO.g4:548:    : writeAdvancePhrase writeAdvancePhrase?
```

Both statements are true of their own tree: PB712's fix deletes `writeAdvancePhrase`, and it is on the train-20
branch, unlanded. ⭐ **This makes the case for the check stronger, not weaker.** It is not a hypothetical guard
looking for a defect that has never existed — on main today it is RED, it names the live defect, and it turns
green at the exact commit that fixes it. That is `feedback_green_gates_arent_evidence` satisfied for free: the
assertion can be watched failing before it is trusted, without fabricating a case.

⛔ Consequently the ORDER matters: land the check with or after train 20, or land it red and say so. Landing it
before train 20 and "fixing" the grep to pass would delete the only evidence it works.

## What exists today, and why it does not cover this

`scripts/spec/audit_figure_structure.py` (299 lines) is the closest thing, and its own docstring rules itself
out:

- it compares **counts per page**, not geometry — *"a page whose counts AGREE can still nest wrongly — counts
  are blind to which delimiter encloses what"*;
- its output is explicitly *"a SHORTLIST and not a defect list"*, ~46 of 161 general-format pages disagreeing,
  *"an UPPER BOUND still contaminated by layout … NOT a count of broken figures and must not be quoted as one"*;
- and it compares **the PDF against the transcription**. This note's claim is a different join entirely: the
  **transcription's figure note against the `.g4` rule**. No audit in `scripts/spec/` crosses that boundary.

⛔ **And nothing runs it.** `grep -rln "audit_figure_structure\|audit_figure_text\|audit_underlining" tests/
scripts/ .github/` matches only the three scripts themselves — the figure audits are hand-run tools with no gate
behind them, unlike `audit_derivations.py`, `extract_annex_a2.py` and `audit_code_citations.py`, each of which
has a drift test that calls it.

## Fix shape — the repo already has the pattern, twice

⭐ **The model is `tests/Cobol.Net.Tests.Unit/RequiredFormatPhraseDriftTests.cs`**, which is this note's exact
mirror image (it hunts formats printed WITHOUT brackets that the grammar makes optional; this one hunts formats
printed with choice indicators that the grammar makes repeatable). Its design comment states the governing rule
verbatim: *"ONE such line is not a pattern worth a hand-maintained list (CLAUDE.md rule 8) — so this SCRAPES
them out of `specs/ISO_COBOL.md` instead, and asserts that every one is adjudicated WITH THE MECHANISM THAT
ENFORCES IT"*, and it reads the transcription for real (`:60`, `File.ReadAllText(TestRepo.Specs("ISO_COBOL.md"))`).

1. **Now, cheap:** the crude repetition grep as a drift assertion over `src/Cobol.Net.Frontend/Grammar/**/*.g4`
   — *no parser rule may consist of a sub-rule repeated* — with the one current hit either fixed by train 20 or
   recorded as the witness. It is not the real check; it is the half of it that costs nothing and that already
   catches the shape once.
2. **Durable, beside `audit_figure_structure.py`:** scrape the sixteen figure notes, resolve each to the clause
   whose general format it annotates, and join to the `.g4` rule that spells that format, asserting that the
   repeated element is the ENCLOSED WORD SET and not the surrounding phrase. ⛔ The hard half is the
   note→rule mapping, and the two precedents disagree about how to get it: `RequiredFormatPhraseDriftTests`
   derives it by scraping, `OptionalWordSubsetDriftTests` carries a hand-maintained `Formats` list plus the
   audit script as the finder. **Prefer the scrape** (rule 5: the shape that makes the next case automatic);
   if the mapping proves underivable, the fallback is the audit script emitting the pairs and the test asserting
   the POPULATION it received, never a hand list checked in silence.
3. ⛔ **Assert the population either way.** Sixteen notes today; a check that silently finds zero because the
   note wording changed is `feedback_measure_the_selectors_complement` all over again — the two wordings already
   differ, which is how WRITE's note nearly escaped PB712's own manual sweep.

## Why `process_only`, when the defect class it catches is not

Nothing a user compiles changes when this note is fixed — the flag is honest and `work.py check` requires it.
⚠ But the defect class it fails to catch is `rejects_legal_source` **and** over-acceptance at the same time:
PB712 is one measured instance where both happened to one statement for a year, and the edition gate fired
correctly the whole time, which is precisely what kept the spelling from ever being checked. Read the flag as
"this note is a gate, not a bug", never as "this is harmless".
