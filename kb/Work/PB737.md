# PB737 — LANDED — three rows that became true, and the three sentences inside them that had no test

## Why the row was unowned

kb/Work PB339 made the sending operand of a `READ … INTO` / `RETURN … INTO` implicit MOVE the CURRENT RECORD
rather than the space-padded record area, and shipped `tests/conformance/{85,2002,2014,2023}/`
`pb339_into_current_record` with seven derived legs. Three inventory rows became implemented AND pinned by that
work, and its implementer deliberately did not claim them: the dispatch scoped it to the rows its own note owned,
and no `kb/Work` note owned these three (`grep -rln` over `kb/Work/` found none). Claiming unowned rows is the
adjudication lane's job. This note is that claim, and it exists so the rows have an owner in the register rather
than only a sentence in a report.

## What the re-derivation found that the report did not

⛔ **Each of the three rules has an obligation that PB339's goldens do not reach**, and a row closed on the legs
alone would have been the half-right outcome `record_verdicts.py`'s own doctrine names as the worst available.
Each was measured on this tree first, then given a test.

1. **`GR-13.18.43.4-16` has THREE obligations, not the two lettered arms.** Its closing sentence — *"If the
   number of bytes determined as above is zero, the record is a zero-length item"* (`cite.py --check 13.18.43.4`
   → OK 16)) — is reachable source, not a corner: §13.18.43.3 SR7 is *"Integer-2 shall be greater than or equal
   to zero"* (`--check 13.18.43.3` → OK 7)), so `RECORD IS VARYING IN SIZE FROM 0` is legal. Measured at all four
   editions on this tree: a zero-length record read `INTO` a `PIC X(5)` pre-loaded with dots yields five SPACES
   with `LEN=0000` — neither the record area's leftover `ZZZZZ` nor an `EC-BOUND-REF-MOD` — and the following
   `READ` still returns the next 4-byte record, so the zero-length read did not disturb the file position
   indicator. `OperandText.CurrentRecordImage` passes `allowZeroLength: true` to the ref-mod slice for exactly
   this sentence and says so in its own comment; nothing exercised it.

2. **`GR-13.18.32.4-1` names BOOLEAN POSITIONS as well as character positions**, and the goldens' JUSTIFIED legs
   are all DISPLAY alphanumeric. Measured: five positions into three truncates the leftmost two for `PIC N(3)`,
   `PIC A(3)`, `PIC 1(3)` and `USAGE BIT PIC 1(3)` alike. §13.18.32.3 SR3 fixes the clause's legal categories at
   alphabetic, alphanumeric, boolean and national, so those four usages are the rule's WHOLE domain — which is
   why measuring them is a closed argument and not a sample.

3. **`GR-13.18.32.4-2` states its fill PER USAGE, in three sentences after the alignment sentence** — display,
   national, and *"For data items implicitly or explicitly described as usage bit, bit zeros shall be used for
   zero fill"*. `NationalBooleanDataTests.JustifiedRight_NationalAndBoolean_LeftFill` covered the national and
   boolean-category legs and `conformance:2002/boolean_data` the `PIC 1(4)` one, but a `PIC 1(4)` DISPLAY carrier
   does not stand in for a `USAGE BIT` one when the rule keys on usage. Measured `0011` for both carriers.

None of the three was a DEFECT: the implementation was already whole. They were three sentences with no evidence,
which is a different failure and closes the same way.

## Also carried by the same batch — `GR-14.9.20.4-3`'s stale prose (kb/Work PB419's row, verdict untouched)

PB695's family-2 implementer found that the row's `notes` name the walk over identifier-1 by its GENERATED PARSER
ACCESSOR, `ini.dataReferenceList().dataReference()`, and that a rename of that subrule to `initializeOperandList`
— the `DEFAULT`-reservation guard for the `THEN TO DEFAULT` phrase — was in flight. On THIS tree the accessor
still reads `dataReferenceList` (`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/InitializeBinder.cs:65`), so the
sentence is not yet false; the root problem is that it was never durable. A generated accessor is a BUILD OUTPUT
of the `.g4` (`Generated/` is never committed), so it cannot be a code-location. The prose now names the grammar
rule (`Core/CobolData.g4#initializeStatement`'s list subrule) and the binder symbol (`InitializeBinder.cs#Bind`),
which no rename can invalidate. **Verdict, evidence, editions and both code sites are unchanged** — re-verdicting
another note's row without redoing that row's evidence is the worse error — and the change went through the
batch, never a hand edit of the JSON, because a lander re-applies BATCHES on the merged tree and silently drops
hand edits.
