# PB5080 - at --std 85 a contained program's INITIATE, GENERATE and TERMINATE of a GLOBAL report is refused (COBOL2392 citing a 2023 rule) unless the report file's FD is also GLOBAL; 1985 has no such rule

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/ReportWriterBinder.cs#RejectContainedReportFile` (line 464; its callers bind INITIATE, GENERATE report-name, GENERATE data-name and TERMINATE; it now asks Edition.Has(2002), the rule's introducing edition: §2002:14.8.20.2 SR2, §2002:14.8.42.2 SR2, §2002:14.8.15.2 SR3/SR4).

**Mechanism.** RejectContainedReportFile enforces the 2023 restriction (a report of a containing program is usable from a contained program only if its file description entry is GLOBAL too, §2023:14.9.21.3 SR2) at every edition. 1985 has no such rule: the only syntax rule of INITIATE and TERMINATE is that the report-name is defined by a report description entry, and a global name may be referenced from every contained program without describing it again. A legal 1985 program is refused.

**Found by.** The 1985 `--std=85` draft triage (kb/Work PB4995 item 3): each rule below is a conformance-suite draft that did not MATCH at `--std 85`, and its adjudicator decided COMPILER-DEFECT. Harm and observed text are the records'; nothing here was re-derived.

**Inventory.** The traceability inventory carries no 1985 rows yet, so `inventory_rows` is empty; the rows this note covers are the 1985 rule ids listed below (catalog `docs/rearchitecture/spec-rule-catalog-1985.json`).

**Rules (1; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-GR-X.4.4.4-2` - `§1985:X.4.6.4 GR2` (record harm: rejects-legal-source, slice-17): §1985:X.4.4.4 GR2 sends the report description entry's GLOBAL clause to page X-24, where §1985:X.4.6.4 GR1 says "A data-name, file-name, or report-name described using a GLOBAL clause is a global name" and §1985:X.4.6.4 GR2 says "A statement in a program contained directly or indirectly within a program which describes a global name may reference that name without describing it again." §1985:X.1.3.8.2 repeats it: "A global name may be referenced in the program in which it is declared or in any programs which are directly or indirectly contained within that program." The only syntax rule of the 1985 INITIATE and TERMINATE statements is "Report-name-1 must be defined by a report description entry in the Report Section of the Data Division" (§1985:XIII.4.4.3 SR1, §1985:XIII.4.7.3 SR1). No 1985 rule requires the file description entry that names the report to carry GLOBAL as well (the Report Writer module, pages XIII-1 to XIII-79, does not contain the word GLOBAL; §1985:X.4.6.3 SR1-SR3 hold no such condition). The compiler refuses the contained program's reference under a 2023 rule.

**Repro (`1985-GR-X.4.4.4-2`, slice-17).**

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. RDGLOB.
       ENVIRONMENT DIVISION.
       INPUT-OUTPUT SECTION.
       FILE-CONTROL.
           SELECT RPT-FILE ASSIGN TO "RPTOUT".
       DATA DIVISION.
       FILE SECTION.
       FD  RPT-FILE
           REPORT IS RPT1.
       REPORT SECTION.
       RD  RPT1 IS GLOBAL.
       01  DET-LINE TYPE IS DETAIL LINE NUMBER IS PLUS 1.
           05  COLUMN NUMBER IS 1 PIC X(4) VALUE "BODY".
       PROCEDURE DIVISION.

       PROCEDURE DIVISION.

       END PROGRAM RDGLOB.
```

**Expected (from the 1985 text).** --std 85 accepts the program and runs the report from the contained program. The deciding words: "A statement in a program contained directly or indirectly within a program which describes a global name may reference that name without describing it again." (§1985:X.4.6.4 GR2).

**Observed (copied from `1985-GR-X.4.4.4-2`).** compile --std 85, exit 65: "p.cob(26,12): error COBOL2392: INITIATE RPT1: report 'RPT1' is defined in a containing program and its file description entry 'RPT-FILE' does not contain a GLOBAL clause; the file description entry associated with a containing program's report shall contain a GLOBAL clause (ISO §2023:14.9.21.3 SR2)" and the same COBOL2392 at (27,12) for TERMINATE "(ISO §2023:14.9.46.3 SR2)"; a GENERATE of the report in the contained program is refused the same way "(ISO §2023:14.9.16.3 SR4)". The control, the same program with FD RPT-FILE IS GLOBAL, compiles and displays "REPORT DONE". Code site: src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/ReportWriterBinder.cs, RejectContainedReportFile (line 464; its callers bind INITIATE, GENERATE report-name, GENERATE data-name and TERMINATE), which asks no edition. THE DRAFT AS WRITTEN was suspect on two counts and its refusal was right: it has no body group (§1985:XIII.3.20.3 SR7: "The description of a report must include at least one body group") and its report heading at LINE 1 has no region to occupy (§1985:XIII.3.8.3 SR8 a: a report heading not presented on a page by itself lies between "integer-2" and "integer-3 minus 1", and by §1985:XIII.3.8.4 GR2 b "If the FIRST DETAIL phrase is omitted, a value equal to integer-2 is given to integer-3", so the region is lines 1 to 0); the compiler reported both, COBOL2749 and COBOL2199, citing only §2023 clauses at --std 85. With a detail group and FIRST DETAIL 3 added, the draft's own program (RD RPT1 IS GLOBAL, no contained program) compiles and displays "REPORT DONE", exactly as it does without IS GLOBAL: it shows the clause is parsed, not what it does. The draft below uses the global name from a contained program.
