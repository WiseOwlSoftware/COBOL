## Measured (adjudicator / refuter evidence, verbatim)
### [procedure-division-structure] The procedure-division-header formal/RETURNING screen is written TWICE - DataBinder.CallBindLinkage (program + function) and DataBinder.OoBindMethodData (method) - and each arm implements a different subset of §14.2.2 SR1/SR5/SR6, with no uniqueness check in either arm and no BASED/REDEFINES check on the RETURNING item in either arm; the unscreened shapes crash Roslyn or compile clean
- **Rows:** SR-14.2.2-1, SR-14.2.2-5, SR-14.2.2-6 — harm `crashes`
- **Repro:** (a) program: `LINKAGE SECTION. 01 A PIC 9(3). PROCEDURE DIVISION USING A A.` -> backend CS0102 'already contains a definition for __lnk0'. (b) method: `01 A PIC 9(3). 01 B REDEFINES A PIC X(3). 01 C PIC X(3) BASED. PROCEDURE DIVISION USING B C.` -> CS0103 'The name B does not exist'. (c) method `RETURNING B` (B REDEFINES A) -> CS0103. (d) program `RETURNING B` with B REDEFINES A, or B BASED -> compiles and runs clean; method `RETURNING B` with B BASED -> clean. (e) program and function `PROCEDURE DIVISION USING A RETURNING A.` -> clean. (f) method `USING A A` -> clean. Probes under out/probe/pds (dupformal, sr5redef, sr5based, sr6prog, sr6func) and out/probe/pds/b2 (m_dup, m_sr1redef, m_sr5redef, m_sr5based).
- **Expected (spec):** §14.2.2 SR1: 'A particular user-defined word shall not appear more than once as data-name-1. The data description entry for data-name-1 shall not contain a BASED clause or a REDEFINES clause.' SR5: 'The data description entry for data-name-2 shall not contain a BASED clause or a REDEFINES clause.' SR6: 'Data-name-2 shall not be the same as data-name-1.' Every repro is a syntax-rule violation and shall be refused with a COBOL diagnostic, identically on the program, function and method arms.
- **Observed:** CallBindLinkage checks SR1 level-01/77 + REDEFINES/BASED on USING items, and level-01/77 only on RETURNING; OoBindMethodData checks level-01/77 on both and SR6 (message mis-cites 'SR4'), nothing else. Neither tracks names already seen. The fix shape is ONE header screen both binders call (the RaisingPhrase.Partition precedent for the RAISING phrase), with a drift test that the two arms share it.
- **Code site:** src/Cobol.Net.Compiler/Binding/DataBinder.Linkage.cs#CallBindLinkage (the USING loop and the RETURNING block); src/Cobol.Net.Compiler/Binding/DataBinder.Oo.cs#OoBindMethodData (the PD header formals block)

### [procedure-division-structure] The using-phrase is parsed flat and the plain `OPTIONAL? dataReference` arm inherits the threaded BY VALUE mode, so OPTIONAL is accepted on a BY VALUE formal although §14.2.1 prints OPTIONAL only in the BY REFERENCE alternative
- **Rows:** FMT-14.2.1 — harm `under-rejects`
- **Repro:** `LINKAGE SECTION. 01 LX PIC 9(3). 01 LY PIC 9(3). PROCEDURE DIVISION USING BY VALUE LX OPTIONAL LY. GOBACK.` compiles clean (out/probe/pds/b3/byvalue_optional.cob); LY is recorded as an OPTIONAL BY VALUE formal.
- **Expected (spec):** §14.2.1 using-phrase: `USING { [BY REFERENCE] { [OPTIONAL] data-name-1 }... | BY VALUE { data-name-1 }... }...` - OPTIONAL occurs only in the BY REFERENCE alternative; after BY VALUE, `OPTIONAL LY` continues the BY VALUE alternative and is not a legal element of it. Shall be refused.
- **Observed:** CallBindLinkage sets `optional = prm.OPTIONAL() is not null` on the plain arm while `byValue` stays true from the preceding BY VALUE; nothing checks the combination.
- **Code site:** src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4#usingParameter; src/Cobol.Net.Compiler/Binding/DataBinder.Linkage.cs#CallBindLinkage

## What the fixer owes
ONE header screen called by both binders (program/function and method) implementing SR1 (level, uniqueness, BASED/REDEFINES), SR5/SR6 on RETURNING, and OPTIONAL only on BY REFERENCE (§14.2.1's printed alternative — render the page). Negatives at 2002 for each; the Roslyn crash is the blocker leg.
