# PB5289 - at --std 85 the SEND operand screens misread their 1985 rules: a P-scaled one-character integer (PIC 9P) as identifier-2 and PIC 9PP as identifier-3 are refused, ADVANCING ALL ZERO is refused, while a USAGE INDEX item and a symbolic-character are accepted in the ADVANCING phrase

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CommunicationBinder.cs` (`BindSend`, `ScreenSendAdvancing`, `IsIntegerItem`)

**Mechanism.** One screen, five departures. (1) identifier-2 "must reference a one-character integer without an operational sign" (§1985:XIV.3.6.3 SR2) and identifier-3 "an integer data item" (SR3). An integer is a numeric item "that does not include any digit positions to the right of the decimal point" (§1985:III.2), and "The scaling position character P is not counted in the size of the data item" (§1985:VI.5.9.4), so PIC 9P and 9PP are integers and PIC 9P has size one; `BindSend` and `ScreenSendAdvancing` test `Scale == 0` and refuse them. (2) the same SR3 test accepts a USAGE INDEX item, because `PicInfo.IndexItem` is numeric with scale 0, but an index data item is no integer data item and may be referenced only in SEARCH, SET, a relation condition or USING (§1985:VI.5.14.3 SR5). (3) the mnemonic-name arm is taken only when SPECIAL-NAMES declares the word a mnemonic-name, and the identifier-3 check only for a field operand, so a symbolic-character (a user-defined figurative constant) falls through both and is accepted (SR4: "The mnemonic-name is defined in the SPECIAL-NAMES paragraph"). (4) integer-1 "may be zero" (SR5) and the figurative ZERO is accepted, but `ALL ZERO` (the same figurative, ALL being redundant, §1985:IV.4.2.2.2.3) is refused because the screen compares the token text "ALLZERO". The refuter of SR4 notes WRITE ADVANCING (SequentialIoBinder) as the sibling to sweep.
