# PB4710 — TRIM(I2 + 1) under --permissive dies at run time

**Sites:** `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/IntrinsicRenderer.cs` (`IntrinsicRenderer.StrArgVisitor`)

Copied from the two PB4635 reports (w20261868f and w20261869a), pre-existing on main: a genuinely compound numeric argument at a string position, `TRIM(I2 + 1)`, compiles under `--permissive` after the demoted COBOL1627 and dies at run time in `IntrinsicRenderer.StrArgVisitor.Visit(BoundComputedOperand)` (the loud arm); the demoted class refusal has no coercion to apply for a computed value.

Repro: `E:\COBOL-coord\scratch\w20261868f\q3.cob` with `--permissive --run`.

**Landed (wave 20261872, group A).** Re-probed on the build (`E:/COBOL-coord/scratch/w20261872a/pd/t10.cob`, `--permissive --run`): `DISPLAY FUNCTION TRIM(I2 + 1)` compiled after the demoted COBOL1627 warning and died at run time with `NotImplementedCobolFeatureException: intrinsic string argument 'BoundComputedOperand'`; it now prints 3.

Cause: the binder's `--permissive` coercion of a class-numeric argument at a character position (COBOL1627, `IntrinsicArgumentRules.IsCoercible`) has a rendering for a parenthesized item or literal (the enclosed operand's image, PB4635 R2-3) and for a numeric function's value (`OperandText.AsString`, DOC-A.1-92) but none for a COMPOUND arithmetic expression, which fell to `StrArgVisitor.Visit(BoundComputedOperand)`'s loud arm (the wrong-stage family: legal-shaped, warned source aborting at run time). Fix: the visitor renders a binary, negated or power expression through `OperandText.AsString`, whose arithmetic-expression arm (`NumericExprText`, which already served the folded LENGTH sum) is widened to `BoundNegate` and `BoundPower`; the text is the value's, the one form a numeric function's returned value has at a character position (`TRIM (I2 + 1)` is "3", `TRIM (- I2)` "-2", `TRIM (I2 ** 3)` "8"). The positions that read characters (CONCAT, BASECONVERT argument-1) keep their error in every mode (`IsCoercible`), so the arm never serves them. Sibling sweep: `StrNum` is the same visitor instance, `Str`/`StorageArg` reach it for the other string functions, and `OperandText`'s own visitor stays loud for the shapes no coercion reaches (an index-name).

**Test:** `ParenthesizedIntrinsicArgumentPermissiveTests.ACompoundArithmeticExpressionAtACharacterPosition_RendersItsValueText` (a unit test, as its siblings: the shape is refused in every strict edition, so no conformance golden can run it).

**Sites:** `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/IntrinsicRenderer.cs` (`IntrinsicRenderer.StrArgVisitor.Visit(BoundComputedOperand)`), `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/OperandText.cs` (`OperandText.AsString`, the arithmetic-expression arm).
