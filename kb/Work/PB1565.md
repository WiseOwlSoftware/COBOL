## Landed (wave 59, w59l)

Re-probed on the w59l build first: `b21var.cob` printed `VAR=00000` / `SD=00000` (reproduced). ROOT: the native
float family's variadic arm (`IntrinsicRenderer.FloatBody`'s default arm) rendered every argument through `Dbl` — the
PB1041 exact intake (`LeadArg` / `ExactArg`) reached argument-1 of the fixed-arity bodies only. FIX: the declared set
`IntrinsicRenderer.ExactListBodies` {Variance, StandardDeviation, PresentValue} — every float-family EAE that SUBTRACTS
its arguments across the list (§15.98.4 r1, §15.86.4 r1, §15.74.4 r1) — takes an all-exact list lifted exactly
(`DecArgList` / `DecOf`, table(ALL) included) to new runtime overloads `(CobolRounding mode, …CobolDec…)` in
`CobolIntrinsics.Float.cs`, which evaluate the EAE with the function's ONE Dec body (`VarianceDec` / `StdDevDec` /
`PresentValueDec`, native intermediate rounding) and narrow the RESULT once (`NarrowResult`, range-checked per PB1566).
Now VARIANCE = 0.25, STANDARD-DEVIATION = 0.5, PRESENT-VALUE(0 1E17+1 −1E17) = 1. PRESENT-VALUE's §15.74.3 r2 is decided
by `PresentValueDec`'s exact compare (the one `PresentValueDomain` raise site), as on every SDIDI evaluation of it. A list
with a FLOATING argument keeps the binary64 body: CONFORMANCE.md DOC-A.1-92's determination for the exact family's float
arm, which the sweep found also governs SUM / MEAN / MEDIAN / MIDRANGE / RANGE's `…Real` bodies (the dispatch's named
siblings) — their narrowing happens only with a float argument present, where the EAE is by determination evaluated in
binary64, so they are not this defect. An SDIDI argument was already on the Dec bodies (PB69).
`WholeRangeBodiesDriftTests.EveryVariadicFloatRow_IsAnExactListBody_WithTheListOverload` requires every variadic Float
catalog row to be a member. Golden `tests/conformance/85/pb1565_variadic_exact_argument_list` (Python-decimal oracle);
no negative — the three functions exist in every edition.
