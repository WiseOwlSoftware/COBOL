# PB5283 - after a first SEND on an I-O CD fails (status 50 or 60) the program may change SYMBOLIC TERMINAL and later statements succeed on the new terminal: the terminal lock is taken only when the send reaches SendToTerminal

**Sites:**

- `src/WiseOwl.Cobol.Runtime/Communication/MessageControlSession.cs` (`Send`, `SendToTerminal`, `LockedTerminalChanged`)

**Mechanism.** §1985:XIV.2.2.4 GR31: "After executing the first statement referencing cd-name-1, the content of the data item referenced by data-name-3 must not be changed by the program. If this content is changed, the execution of any statement referencing cd-name-1 is unsuccessful". `LockedTerminalChanged` records the first terminal and the path, purge, receive and terminal-send paths consult it, but `Send` returns status 50 or 60 before `SendToTerminal` records the lock, so a first SEND that fails those checks fixes no terminal. The program breaks a "must not", but the standard defines the result, and the runtime does not give it.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids below. None of them is recorded: the non-conforming verdicts wait in `E:/COBOL-coord/scratch/coderead-85/p2-for-register.json`.

**Rules (1 claimed; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-GR-XIV.2.2.4-31` - `§1985:XIV.2.2.4 GR31` (read: DIVERGES, harm: wrong-answer as read; filed under-rejects, since the program breaks a rule whose result the standard states): "must not be changed by the program"

**Repro.** `E:/COBOL-coord/scratch/coderead-85/reprobe-85d/gr31/gr31.cob` with mcs.json `{"terminals":[{"name":"T1"},{"name":"T2"}]}`: an I-O CD; `MOVE "T1" TO IO-TERM. MOVE 9 TO IO-LEN. SEND IOCD FROM MSG WITH EMI.` (MSG PIC X(5)), then `MOVE "T2" TO IO-TERM. MOVE 5 TO IO-LEN. SEND ...`, then `ENABLE I-O TERMINAL IOCD`; `cobol.exe --std 85 --source-format fixed --run gr31.cob`.

**Observed (a build of origin/main f2cf36fd15, rerun 2026-11-11; main has since changed only `IndexedConnector.cs` under `src/`, which none of these repros reaches).** `FIRST 50`, `SECOND 00` (and T2.out holds HELLO), `ENABLE 15`.

**Expected (from the 1985 text).** `FIRST 50`, then `SECOND 20` with nothing sent, `ENABLE 21` (Table 1, unknown terminal).

**Fix direction (root cause, CLAUDE.md rule 4).** Take the lock where the statement is entered, before any status check, so every statement referencing the CD fixes it; test a failing first SEND and a failing first RECEIVE.
