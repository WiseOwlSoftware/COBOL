# PB5411 — the `Gate` class split: its pass carry and re-derivation (`gate_reuse.PassCarry`), its generated targets (`gate_generated.Generations`) and its test populations (`gate_legs.Legs`) become collaborators that return what they found; `Gate` keeps the run and the one place a verdict is written

**Sites:** `scripts/gate.py` (whole: the class is cut into collaborators), `scripts/gate_reuse.py` (new), `scripts/gate_generated.py` (new), `scripts/gate_legs.py` (new), `scripts/selftests/gate/`, `scripts/script_layering.py` (`LINES`, `NODES`, `SPLITS`)

## The design this step implements

`docs/rearchitecture/DESIGN-orchestrator-loop.md` section 16.5 (step 2) (kb/Work PB3726). The design is the SSOT; this note does not restate it.

## The step

Cut `Gate` as section 16.5 step 2's table says. A collaborator never calls back into `Gate`, and the seven edges
today's moved methods have across the new boundaries are each decided in section 16.5's second table: `_generate` and
`_all_up_to_date` return their failure or early verdict as a value and `_gate` joins the work beside and finishes;
`_first` takes the previous run's directory as an argument; `Generations.generate` takes the facets as an argument;
`PassCarry.record_passes` takes the generations' outputs as an argument; `Legs` is constructed with the `Generations`
instance and calls its `handed`. Re-run the AST walk of every `self.<attr>` in each moved method before cutting: an
edge the table does not decide is a design correction made in the same change.

## Oracle

The gate's case files GREEN with the same labels; a gate run on one recorded tree before and after writes a record with
the same fields and verdict (`gate.py --await` of both); `--rederive` of one recorded run gives the same record; the gate
GREEN.

## Done when

`Gate` holds only the methods section 16.5 leaves it; `script_layering.py`'s cases GREEN with the line `gate_host ← gate_reuse, gate_generated ← gate_legs ← gate` declared.
