# PB378 — an audit whose population includes a derived, untracked view

Found at the battery #42 close (2026-09-03). `citations: ⛔ 23 finding(s)`, every one `[PHANTOM]` in
`kb/Reference/{Bound,Compiler,Frontend,Runtime}/…` — §8.8.4.1.4, §8.3.1.2, §8.4.2.4, §8.8.4.1.2, §14.2.4.
`kb/Reference/` is in `.gitignore` (line 113) and is produced by `scripts/gen-vault-reference.ps1` from the C#
XML doc comments; the local copy dated from 2026-07-26, and the citation-repair sweep (`9c08e6fe`, DEVLOG 1439)
had since removed those citations from the source it renders. Regenerating took the audit to 0 findings without
a single tracked file changing.

## Why it is a defect and not a chore

A gate's population must be the thing the commit can change. The tracked tree is; a gitignored derived view is
not — CI never sees it, so the same commit is green in CI and red locally, and the red names files nobody edits.
That is the `green_gates_arent_evidence` / `verdict_evidence_invariant` shape in reverse: a manufactured red
teaches the reader to discount the leg.

## What closes it

One of two shapes, chosen by reading the audit's enumeration: (a) the audit walks only `git ls-files` (the
tracked population) — the generated view is then covered transitively through the XML docs it is rendered
from; or (b) `battery.sh` regenerates `kb/Reference` immediately before the audit, so the leg measures a fresh
rendering. (a) is preferred: it makes the population a property of the repository rather than of the machine.
Prove the failure branch by planting a phantom in a tracked file (red) and in an ignored file (not counted).

## Landed 2026-09-03 — shape (a), and it retired an earlier hand-kept list

`citation_corpus.repository_files()` enumerates `git ls-files --cached --others --exclude-standard` once
(memoised) and `_keep` admits only members of it; the `FROZEN` policy exclusion stays. This also retired
`BUILD_OUTPUT = {obj, bin, Generated}` — the first answer to the same defect shape (the ANTLR `obj/antlr-lib`
grammar copies), a directory-name list that would have needed a third entry for `kb/Reference` and a fourth for
`kb/Conformance`; the ignore rules already named all of them (rule 5: the shape that makes the next case
automatic). Failure branch proved at landing: a `§99.99.99` planted in an untracked-not-ignored `docs/` file is
counted (1 finding), the same text planted in the ignored `kb/Reference/` is not, and both audits are at zero
with the probes removed. No git available is a loud refusal, never a fallback to the disk.
