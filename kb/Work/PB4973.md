# PB4973 - STRING re-evaluates a function-identifier sending (D-STR4)

**Sites:** `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/StringEmitter.cs` (`StringEmitter.ReadOperand`, `StringEmitter.ReadsStorageOf`; `Reach`/`ReachOf` deleted), `docs/CONFORMANCE.md` (D-STR4), `docs/STRING_OPS_DESIGN.md`, `docs/DESIGN.md`, `tests/WiseOwl.Cobol.Tests.Unit/StringLiveReadDriftTests.cs`, `tests/version-matrix/inventory/GR-14.9.43.4-10.json`, golden `conformance-suite/cases/14.9.43-STRING/pb1908_string_overlap_function`.

**Report.** `StringEmitter.ReadOperand` / `ReachOf` identify a later sending's function up front and evaluate it AGAIN at its transfer when its
argument may share identifier-3's storage (D-STR4; golden pb1908: `STRING "xy" FUNCTION UPPER-CASE(F) INTO F` gives `xyXYCDEF`). GR10's
overlap rule needs identifier-1 to OCCUPY identifier-3's storage, and a function's temporary item never does (`cite.py --check "§2023:8.4.3.2.4 GR1"`
OK: "A function-identifier references a temporary data item whose value is determined when the function is referenced at runtime"; `§2023:14.9.43.4 GR10`
OK: the overlap rule; `§2023:14.6.4 GR7` OK: item identification is the first step of evaluating an identifier). So the standard defines the result:
one evaluation at identification, giving `xyABCDEF`. GnuCOBOL gives `xyXYCDEF`. Same cause as PB4115 (treating a function as re-readable storage), which
fixed the INSPECT arm and measured GnuCOBOL evaluating identifier-1 once but a pattern's function at its phrase.

**Needed.** An owner adjudication, because the fix overturns the documented determination D-STR4 (and the pb1908 golden). Fixing it would delete
`Reach`/`ReachOf` entirely. Mirror PB4115's shape (`InspectEmitter.TallyOperandTexts`: evaluate each function operand once, in source order, into a local before the first transfer).
Sweep the siblings: UNSTRING `LiveReads.Of` already excludes function results; INSPECT REPLACING/CONVERTING already evaluate once.

## Resolution (wave 20261925 group C)

Re-probe before the fix: pb1908_string_overlap_function printed F1 [xyXYCDEF], F2 [z12.......]. Decision: CLAUDE.md rule 1 puts the standard first and the standard defines the result (cite.py --check OK on 2023:8.4.3.2.4 GR1, 14.9.43.4 GR10, 14.6.4 GR7); GnuCOBOL evaluating later is a divergence, as PB4115 recorded for INSPECT. Fix: StringEmitter.ReadOperand reads every operand once in statement order, ReadsStorageOf answers only for a data-item reference, Reach/ReachOf deleted. Golden restated to xyABCDEF and z12Z34...., D-STR4 rewritten as the reversal, drift tests inverted. After the fix the golden prints F1 [xyABCDEF], F2 [z12Z34....].
