# PB5979 - qualified references are printed with their words run together

A diagnostic that names a written operand takes `ParserRuleContext.GetText()`, which joins the operand's tokens with no
separators, so `X OF Q` prints as `XOFQ` and `KY OF IREC` as `KYOFIREC`. The reader sees a name that is not in the program.
Seen in three messages so far: COBOL1637 (an index-name used where an identifier is required: the MOVE operand screen), the
follow-on COBOL0864 after an ambiguous RECORD KEY, and the indexed START refusal under §1985:IX.4.7.3 SR4. Binding calls
`GetText()` 551 times; every one that feeds a message text is the same defect.

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/IndexNameRule.cs` (`IndexNameRule.NotAnIdentifier`, `IndexNameRule.NotArithmetic`), `src/WiseOwl.Cobol.Compiler/Binding/NameResolution.cs` (whole: the operand screens that build messages from GetText)

## Fix shape
One renderer of a written reference for messages (the source text of the context's span with its whitespace folded to single
spaces, so `X OF Q` and `X IN Q` print as written), used by every message; a RepoDrift test refuses `GetText()` inside a
diagnostic's message argument, so the next message cannot regress. Witnesses: the three messages above, each with a qualified
operand, expecting the words as written.
