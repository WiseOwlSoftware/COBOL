# PB4558 — type-clause-nested-table-condition-name-refused: -std=cobol2014: a condition-name inherited through a TYPE clause inside a TYPEDEF, under an OCCURS, cannot be subscripted ('T-ON' cannot be subscripted)

Filed 2026-11-03 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-batch-3000-20261103`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

A type declaration T-ORDER holds `05 O-LINE TYPE T-ITEM OCCURS 2 TIMES`, and T-ITEM has a level-88 condition-name T-ON. For `01 A TYPE T-ORDER`, cobc 3.2 refuses `SET T-ON OF O-LINE OF A (2) TO TRUE` with "'T-ON' cannot be subscripted"; in the fuzz program the qualified form is reported as "'WS-IT-ON IN WS-OR-LINE IN WS-ORD-A' is not defined". Without the OCCURS, or with the OCCURS outside a TYPEDEF, the same reference compiles. Class: rejects legal source. Fuzz programs: fz01295, fz02705 (slice D3).

## Minimal test case

Free reference format.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. TYP5.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 T-ITEM IS TYPEDEF.
   05 T-FLAG PIC X.
      88 T-ON VALUE "Y".
01 T-ORDER IS TYPEDEF.
   05 O-LINE TYPE T-ITEM OCCURS 2 TIMES.
01 A TYPE T-ORDER.
PROCEDURE DIVISION.
    MOVE "NN" TO A
    SET T-ON OF O-LINE OF A (2) TO TRUE
    DISPLAY "A " A
    STOP RUN.
```

## Environment

`cobc (GnuCOBOL) 3.2.0`, WSL2 Ubuntu x86_64. Compiled with `cobc -x -free -std=cobol2014 -o typ5.x typ5.cob` (the same diagnostics under `-fsyntax-only`); no executable is produced.

## Observed result

Compile, exit code 1:

```text
typ5.cob:13: error: 'T-ON' cannot be subscripted
```

Controls: with `05 O-LINE TYPE T-ITEM.` (no OCCURS) and `SET T-ON OF O-LINE OF A TO TRUE`, and with `01 A. 05 A-LINE TYPE T-ITEM OCCURS 2 TIMES.` and `SET T-ON OF A-LINE (2) TO TRUE`, both compile and run correctly. In the failing program the data item itself takes the subscript: `MOVE "Y" TO T-FLAG OF O-LINE OF A (2)` compiles and prints `A NY`. Only the condition-name is refused, and in every form tried: unqualified `SET T-ON (2) TO TRUE` and the condition `IF T-ON OF O-LINE OF A (1)` give the same "'T-ON' cannot be subscripted".

## Expected result (per ISO)

The program is legal and prints `A NY`.

- §13.18.57.4 (checked): "as though the data description identified by type-name-1 had been coded in place of the TYPE clause". General rule 1: A, and each O-LINE in it, is described as though T-ITEM's entries, its level 88 entry included, were written there.
- §13.18.57.4 (checked): "the subject of the entry is a group whose subordinate elements have the same names, descriptions, and hierarchy as the subordinate elements of type-name-1". General rule 2 a).
- §8.4.2.3.3 (checked): "the conditional variable associated with qualified-condition-name-1 shall contain an OCCURS clause or shall be subordinate to a data description entry that contains an OCCURS clause". Syntax rule 2: T-FLAG of O-LINE of A is subordinate to O-LINE, which has the OCCURS clause, so T-ON takes one subscript.
- §13.18.58.4 (checked): "Subordinate data description entries, condition-name entries, and RENAMES clauses are part of the type declaration of that type." General rule 1: the level 88 T-ON belongs to T-ITEM and is assumed, with T-FLAG, wherever T-ITEM is used, including inside the type declaration T-ORDER.

Edition: 2014. The TYPEDEF and TYPE clauses arrived with ISO/IEC 1989:2002, and the 2014 text carries the same general rules.

## Our compiler

WiseOwl COBOL (fresh judge, `--std 2014 --source-format free`): compiles with no diagnostic; the run prints `A NY`, exit code 0.

## Fix site

`cobc/field.c`, functions `copy_into_field`, `copy_into_field_recursive` and `copy_children` (the TYPE clause's copy of the type's subordinate entries, which carries `outer_indexes`); when the copy happens inside a second type under an OCCURS, the copied T-FLAG receives the subscript count of its new OCCURS (it subscripts correctly) but its condition-name T-ON does not, and `cobc/typeck.c` (the "cannot be subscripted" check in the reference resolver) then refuses the subscript. The field.c functions are the same in the 3.2 source; typeck.c was read in the 3.3-dev tree. The exact line that drops the count is not identified.
