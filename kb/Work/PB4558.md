# PB4558 — type-clause-nested-table-condition-name-refused: -std=cobol2014: a condition-name inherited through a TYPE clause inside a TYPEDEF, under an OCCURS, cannot be subscripted ('T-ON' cannot be subscripted)

Filed 2026-11-03 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-batch-3000-20261103`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

A type declaration T-ORDER holds `05 O-LINE TYPE T-ITEM OCCURS 2 TIMES`, and T-ITEM has a level-88 condition-name T-ON. For `01 A TYPE T-ORDER`, cobc 3.2 refuses `SET T-ON OF O-LINE OF A (2) TO TRUE` with "'T-ON' cannot be subscripted"; in the fuzz program the qualified form is reported as "'WS-IT-ON IN WS-OR-LINE IN WS-ORD-A' is not defined". Without the OCCURS, or with the OCCURS outside a TYPEDEF, the same reference compiles. Class: rejects legal source. Fuzz programs: fz01295, fz02705 (slice D3).

## Minimal test case

Free reference format.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. TYP5.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 T-ITEM IS TYPEDEF.
   05 T-FLAG PIC X.
      88 T-ON VALUE "Y".
01 T-ORDER IS TYPEDEF.
   05 O-LINE TYPE T-ITEM OCCURS 2 TIMES.
01 A TYPE T-ORDER.
PROCEDURE DIVISION.
    MOVE "NN" TO A
    SET T-ON OF O-LINE OF A (2) TO TRUE
    DISPLAY "A " A
    STOP RUN.
```

## Environment

`cobc (GnuCOBOL) 3.2.0`, WSL2 Ubuntu x86_64. Compiled with `cobc -x -free -std=cobol2014 -o typ5.x typ5.cob` (the same diagnostics under `-fsyntax-only`); no executable is produced.

## Observed result

Compile, exit code 1:

```text
typ5.cob:13: error: 'T-ON' cannot be subscripted
```

Controls: with `05 O-LINE TYPE T-ITEM.` (no OCCURS) and `SET T-ON OF O-LINE OF A TO TRUE`, and with `01 A. 05 A-LINE TYPE T-ITEM OCCURS 2 TIMES.` and `SET T-ON OF A-LINE (2) TO TRUE`, both compile and run correctly. In the failing program the data item itself takes the subscript: `MOVE "Y" TO T-FLAG OF O-LINE OF A (2)` compiles and prints `A NY`. Only the condition-name is refused, and in every form tried: unqualified `SET T-ON (2) TO TRUE` and the condition `IF T-ON OF O-LINE OF A (1)` give the same "'T-ON' cannot be subscripted".

## Expected result (per ISO)

The program is legal and prints `A NY`.

- §2023:13.18.57.4 (checked): "as though the data description identified by type-name-1 had been coded in place of the TYPE clause". General rule 1: A, and each O-LINE in it, is described as though T-ITEM's entries, its level 88 entry included, were written there.
- §2023:13.18.57.4 (checked): "the subject of the entry is a group whose subordinate elements have the same names, descriptions, and hierarchy as the subordinate elements of type-name-1". General rule 2 a).
- §2023:8.4.2.3.3 (checked): "the conditional variable associated with qualified-condition-name-1 shall contain an OCCURS clause or shall be subordinate to a data description entry that contains an OCCURS clause". Syntax rule 2: T-FLAG of O-LINE of A is subordinate to O-LINE, which has the OCCURS clause, so T-ON takes one subscript.
- §2023:13.18.58.4 (checked): "Subordinate data description entries, condition-name entries, and RENAMES clauses are part of the type declaration of that type." General rule 1: the level 88 T-ON belongs to T-ITEM and is assumed, with T-FLAG, wherever T-ITEM is used, including inside the type declaration T-ORDER.

Edition: 2014. The TYPEDEF and TYPE clauses arrived with ISO/IEC 1989:2002, and the 2014 text carries the same general rules.

## Our compiler

WiseOwl COBOL (fresh judge, `--std 2014 --source-format free`): compiles with no diagnostic; the run prints `A NY`, exit code 0.

## Fix site

`cobc/field.c`, functions `copy_into_field`, `copy_into_field_recursive` and `copy_children` (the TYPE clause's copy of the type's subordinate entries, which carries `outer_indexes`); when the copy happens inside a second type under an OCCURS, the copied T-FLAG receives the subscript count of its new OCCURS (it subscripts correctly) but its condition-name T-ON does not, and `cobc/typeck.c` (the "cannot be subscripted" check in the reference resolver) then refuses the subscript. The field.c functions are the same in the 3.2 source; typeck.c was read in the 3.3-dev tree. The exact line that drops the count is not identified.

## Draft issue

**Title:** Level-88 under an OCCURS gets the wrong subscript count when copied by TYPE or SAME AS

As posted (owner-reviewed, 2026-11-04):

When a TYPEDEF contains a table whose entry has a level-88 condition-name, the condition-name cannot be subscripted through an item declared with that type, although the data item takes the subscript. SAME AS does the same.

### To reproduce

`typ88.cob` (attached, free format):

~~~~
IDENTIFICATION DIVISION.
PROGRAM-ID. TYP88.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 T-TAB IS TYPEDEF.
   05 T-E PIC X OCCURS 2 TIMES.
      88 T-Y VALUE "Y".
01 A TYPE T-TAB.
PROCEDURE DIVISION.
    MOVE "NN" TO A
    SET T-Y OF A (2) TO TRUE
    IF T-Y OF A (2) DISPLAY "A " A END-IF
    STOP RUN.
~~~~

    cobc -x -free -std=cobol2014 -o typ88 typ88.cob

### What happens

3.2.0 and 3.3-dev r5751 both stop with (source excerpts omitted)

~~~~
typ88.cob:11: error: 'T-Y' cannot be subscripted
typ88.cob:12: error: 'T-Y' cannot be subscripted
~~~~

The same happens without `-std`. `MOVE "Y" TO T-E OF A (2)` compiles, and `SET T-Y OF A TO TRUE`, with no subscript, compiles and sets the first occurrence. `typ88n.cob` and `typ88o.cob`, attached, show the same for a TYPE inside the TYPEDEF (`'T-ON' cannot be subscripted`) and for an item with its own OCCURS and that TYPE, where `T-Y OF B-ROW (3, 2)` gets `'T-Y' requires one subscript`, and `same88.cob` the same for SAME AS (`'S-Y' cannot be subscripted`).

### What should happen

The program should print `A NY`. A TYPE clause acts "as though the data description identified by type-name-1 had been coded in place of the TYPE clause" (ISO/IEC 1989:2023 13.18.57.4 general rule 1), and the type declaration includes its condition-name entries (13.18.58.4 general rule 1). So T-Y's conditional variable T-E has an OCCURS clause, and T-Y takes one subscript (8.4.2.3.3 syntax rules 2 and 3). The same in 2002 and in the 2014 FCD.

### Why it happens

In `cobc/field.c`, `copy_into_field_recursive` copies an item of the type, then its level-88 entries (`copy_validation`) and its children, and only at the end sets the copy's `indexes` to `source->indexes + outer_indexes`. `cb_build_field_tree` gives a new condition-name the `indexes` of its parent, so it gets the count from before that assignment: 0 in typ88, one too few in typ88o.

### Proposed fix

The attached `n10-type-condition-name-subscript.patch` (against 3.3-dev r5751) moves that assignment to the top of `copy_into_field_recursive`, so the level-88 entries and children see the parent's final count. SAME AS goes through the same copy, so the patch fixes it too. With it the four programs print `A NY`, `A NY`, `B NNNNNY` and `S2 NY`. cobc now also refuses `SET T-Y OF A TO TRUE`, with no subscript (`'T-Y' requires one subscript`), as it does for a table declared without TYPE, and `SET T-Y OF B-ROW (2) TO TRUE` in typ88o's layout (`'T-Y' requires 2 subscripts`), which unpatched compiles and applies to occurrence (1, 2).

It adds the testsuite case "TYPEDEF with condition-name in a table" to `run_fundamental.at`, with ChangeLog entries. `make check`: 1373 expected, 9 skipped, 0 failed (1372 unpatched); the new test fails without the patch.
