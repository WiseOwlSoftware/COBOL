# PB1967

Found by wave 1014 group S (while fixing PB1416), filed by the train-1014 lander. Pre-existing: it reproduces with
the lexer as it was before PB1416's change.

## Rule

§8.4.3.12.2 prints `ADDRESS OF FUNCTION { function-prototype-name-1 | identifier-1 }`, and §8.4.3.1.3 SR1 lets any
identifier slot take any identifier format, so a function-identifier whose argument is a subscripted identifier is
legal there (row SR-8.4.3.1.3-1, owned by kb/Work PB1407/PB1425). Spacing between a name and its subscript list is
insignificant.

## Repro

`scratchpad\w1014s\probe\p1lB.cob` (orchestrator scratchpad of session e8598e10) against `p1lE.cob` / `p1lA.cob`
(the unspaced form and the DISPLAY form, both of which compile): `SET P TO ADDRESS OF FUNCTION FUNCTION
UPPER-CASE(WS-NAME (1)).` then any statement -> COBOL0001 on that next statement.

## Code site

`src/Cobol.Net.Frontend/Grammar/Core/CobolLexer.g4#OnDefaultLParen` (the SUBSCRIPT / FNARG mode interplay and the
`_fnParenStack`), with `src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4#functionAddressIdentifier`. PB1416 added
`_functionIsAddressOperand` (the FUNCTION after ADDRESS [OF] heads no function-identifier); the inner `FUNCTION
UPPER-CASE(` does, and the spaced `(1)` inside its argument appears to pop the wrong paren-stack entry.
