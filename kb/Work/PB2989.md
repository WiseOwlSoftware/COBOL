Filed and fixed 2026-10-11 by the train 1056b lander (owner 2026-10-10: "A timing sensitive watchdog failure is still
a failure to be fixed").

## Repro

`wsl -d Ubuntu --cd <worktree> -- bash -lc 'bash scripts/linux-gate.sh'` on the train 1056b head 66eff9b4e printed

    leg selftests-built: RED (rc=2) in 1s — === SELF-TESTS: NOT RUN — the inputs of the self-tests cannot be read:
    Command '['git', 'hash-object', '--stdin-paths']' returned non-zero exit status 128. ===

Re-running `git ls-files -o --exclude-standard | git hash-object --stdin-paths` in the clone afterwards was rc 0: the
failure depends on timing, not on content. Nothing in the train touched the mechanism; it is main's.

## Mechanism

Since PB2879 every Linux-gate leg runs in parallel against the one build. `guard_leg` (scripts/linux-gate.sh) gave
`guard-fast.sh` `TMPDIR="$snap/.guard-tmp"`, a directory INSIDE the clone, where NuGet and the guard create and delete
temp files (`.guard-tmp/NuGetScratch<user>/lock/*`, `gf_*.txt`). `selftests-built` runs at the same moment, and
`scripts/self_test_inputs.py` `Tree.load` keys the self-tests' inputs by every untracked, non-ignored file of the
clone: `git ls-files -o` listed a guard temp file, the guard deleted it, and `git hash-object --stdin-paths` failed
on the missing path (exit 128), so the whole leg was NOT RUN.

## Fix

`guard_leg` puts the scratch BESIDE the clone (`$snap.guard-tmp`, emptied first), so no leg writes untracked files
into the tree another leg reads. CI is not exposed (its guard is a separate job on its own runner).
