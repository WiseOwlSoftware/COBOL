# PB1712 — CLOSED by PB1717 (M11)

Found 2026-09-28 by the PB1708 architect (design workflow wf_2a880f25-d10), while measuring the registry coupling.

## The defect

The PB1683 impact recorder instruments METHOD entry. A static table read through a FIELD (`ldsfld` /
`ldsflda`), for example a `DiagnosticCatalog` descriptor, is invisible to it. The fields are populated once in a
static constructor, so the map attributes the whole constructor to whichever test first triggered it, and attributes
nothing to later readers.

Measured on the map at `dbea12428`:
- a change to one DiagnosticCatalog entry selects **80** tests, although 264 of 422 descriptors are reported by
  methods that more tests reach (median 279, max 9,225);
- a DiagnosticDescriptors entry selects **1** test.

`impacted_tests.py` prints the narrowed selection with no fallback, which is a SILENT under-selection: the very
failure the tool exists to prevent. It is latent today only because no map is recorded for current bases, so the
tool falls back to the whole assembly. Per-commit recording is retired (PB1709, owner 2026-09-28), but a map
recorded ON DEMAND into the shared store `<git common dir>/cobol-impact/` for a base arms it just the same.

- **Repro:** `docs/rearchitecture/evidence/impact-map-pb1708/a5.py` and `a9.py` (in the tree; its `README.md` names
  the recorded maps they need, which are not).
- **Sites:** `tools/impact/ImpactInstrumenter/Program.cs` (probe points) and `scripts/spec/impacted_tests.py#MapIndex.expand`.

## Under the "order, don't skip" pivot (owner, 2026-09-28; design `DESIGN-test-build-ci.md` section 3.14.7)

The owner's fourth PB1708 decision makes the map ORDER a whole-population gate and never select it. Under that
design this under-selection is HARMLESS to soundness: a test the map under-reaches lands in a later tier or leg of
the SAME gate and still runs, so the cost is a later red, never a missed one. It remains a real limit on ORDERING
quality and stays documented here. The replay of 68b X (`impact-map-pb1708/b4`) shows why no field probes are
planned: nearly every test is tier 1 for this compiler, and recorded COST, not the map, carries most of the order.

## Fix and closure (design `DESIGN-test-build-ci.md` section 3.14.9)

**This note closes when mechanism M11 lands.** M11 deletes the NARROWING: from M11 on, `impacted_tests.py`'s filter
line is always the whole-assembly filter, so nothing it prints can skip a test, whatever map exists. The filter line
itself, `--plus`, and every caller that reads them (MANDATORY-PRACTICES I1/I2/I7, the three implementer briefs, the
gate skill, `check_practices.py`) go in M13, in one change, so no caller is ever left reading an output that is gone.
**Until M11 lands, record no impact map into the shared store** (`record_impact_map.py` without `--store`): a map
for a base re-arms the silent under-selection above. The earlier fix (map schema 3, static-field probes, "M1
before M9") belonged to the rejected selection design and is shelved.

## Closed by PB1717 (M11, wave 71 group C, 2026-09-28)

**Re-probed first** on the pre-M11 script with the `dbea12428` map (`probe1712.py`: a hunk inside
`DiagnosticCatalog::.cctor`, lines 60–5554): the map selected **80 of 9,274** tests and the filter NARROWED — the
defect reproduced. After M11 the same change TIERS the assembly (1 test tier 1, 79 tier 2, 9,191 tier 3) and the filter
line is `FullyQualifiedName~.`: nothing can be skipped, whatever map exists. The field-read blindness remains an
ORDERING-quality limit (a later red, never a missed one), recorded above and in `DESIGN-test-build-ci.md` §3.14.7.
Recording a map into the shared store is safe from M11 on.
