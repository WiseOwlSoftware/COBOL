# PB1712 — OPEN

Found 2026-09-28 by the PB1708 architect (design workflow wf_2a880f25-d10), while measuring the registry coupling.

## The defect

The PB1683 impact recorder instruments METHOD entry. A static table read through a FIELD (`ldsfld` /
`ldsflda`), for example a `DiagnosticCatalog` descriptor, is invisible to it. The fields are populated once in a
static constructor, so the map attributes the whole constructor to whichever test first triggered it, and attributes
nothing to later readers.

Measured on the map at `dbea12428`:
- a change to one DiagnosticCatalog entry selects **80** tests, although 264 of 422 descriptors are reported by
  methods that more tests reach (median 279, max 9,225);
- a DiagnosticDescriptors entry selects **1** test.

`impacted_tests.py` prints the narrowed selection with no fallback, which is a SILENT under-selection: the very
failure the tool exists to prevent. It is latent today only because no map is recorded for current bases (PB1709),
so the tool falls back to the whole assembly. The moment per-commit maps exist, it would under-select.

- **Repro:** `docs/rearchitecture/evidence/impact-map-pb1708/a5.py` and `a9.py` (in the tree; its `README.md` names
  the recorded maps they need, which are not).
- **Sites:** `tools/impact/ImpactInstrumenter/Program.cs` (probe points) and `scripts/spec/impacted_tests.py#MapIndex.expand`.

## Under the "order, don't skip" pivot (owner, 2026-09-28; design `DESIGN-test-build-ci.md` section 3.14.7)

The owner's fourth PB1708 decision makes the map ORDER a whole-population gate and never select it. Under that
design this under-selection is HARMLESS to soundness: a test the map under-reaches lands in a later tier or leg of
the SAME gate and still runs, so the cost is a later red, never a missed one. It remains a real limit on ORDERING
quality and stays documented here. The replay of 68b X (`impact-map-pb1708/b4`) shows why no field probes are
planned: nearly every test is tier 1 for this compiler, and recorded COST, not the map, carries most of the order.

**Closure.** This note closes when mechanism M13 (the ordered gate, section 3.14.9) lands and deletes
`impacted_tests.py`'s filter output — from then on nothing can be skipped. Until M13, the filter output exists and
the latent under-selection described above stands (it bites only once per-commit maps exist, PB1709). The earlier
fix (map schema 3, static-field probes — "M1 before M9") belonged to the rejected selection design and is shelved.
