# PB1712 — OPEN

Found 2026-09-28 by the PB1708 architect (design workflow wf_2a880f25-d10), while measuring the registry coupling.

## The defect

The PB1683 impact recorder instruments METHOD entry. A static table read through a FIELD (`ldsfld` /
`ldsflda`), for example a `DiagnosticCatalog` descriptor, is invisible to it. The fields are populated once in a
static constructor, so the map attributes the whole constructor to whichever test first triggered it, and attributes
nothing to later readers.

Measured on the map at `dbea12428`:
- a change to one DiagnosticCatalog entry selects **80** tests, although 264 of 422 descriptors are reported by
  methods that more tests reach (median 279, max 9,225);
- a DiagnosticDescriptors entry selects **1** test.

`impacted_tests.py` prints the narrowed selection with no fallback, which is a SILENT under-selection: the very
failure the tool exists to prevent. It is latent today only because no map is recorded for current bases (PB1709),
so the tool falls back to the whole assembly. The moment per-commit maps exist, it would under-select.

- **Repro:** `docs/rearchitecture/evidence/impact-map-pb1708/a5.py` and `a9.py` on the architect's branch
  `worktree-wf_2a880f25-d10-1`.
- **Sites:** `tools/impact/ImpactInstrumenter/Program.cs` (probe points) and `scripts/spec/impacted_tests.py#MapIndex.expand`.

## Fix

Design mechanism M1 in `DESIGN-test-build-ci.md` §3.14.1, map schema 3: static-field entries, with the static
constructor's sequence points split by the `stsfld` target, plus `ldsfld`/`ldsflda` read probes. **M1 must land
before M9 (per-commit maps).** Until then, a registry-touching change must select the whole assembly; the current
fallback does that only because no map exists. Sweep for siblings: any other static-initialized table read through
fields (see the M10 static-table sweep).
