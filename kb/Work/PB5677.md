# PB5677 - an alphanumeric figurative constant into a noninteger numeric or numeric-edited receiver is not a number

**Site (lead, from the writer):** `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/MoveEmitter.cs#FigurativeToNumericImageStore`
and `#ConvertSource`: HIGH-VALUE, LOW-VALUE and QUOTE sent to a numeric or numeric-edited receiver store the fill
character in every character position of the image. PB5176 made a digit-only ALL literal one numeric value
(`MoveEmitter.AllLiteralNumber`) and left this arm as it was. The ALL-literal arm's own 2002 question is kb/Work PB5351.

**Rule (checked with `python scripts/spec/cite.py --check`, verdict OK on each quotation).**

- `§2002:14.8.24.3 GR4`: "the figurative constant is replicated in this item" and "If the receiving item is not an
  integer, the number of digits includes both those to the right and the left of the decimal point". The constant is
  an unsigned integer of the receiver's digit count, moved by the numeric rules: aligned by decimal point, and edited
  for an edited receiver.
- The informative `§2002:G.1` says the same of ALL "9": "if the item is PIC 99V99 you get 99.00 and not 99.99".

**Repro** (`E:/COBOL-coord/scratch/gl2002/integrate-2/repro/g2mvd1.cob`, a copy of the writer's
`lane1/run/g2002-14-8-24-move-p2/gr4defect/g2mvd1.cob`; `cobol.exe g2mvd1.cob --std 2002 --run`). The program
collating sequence `ALPHABET ALF5 IS "5"` makes LOW-VALUE the digit 5, so the move is a valid numeric move:

```cobol
       OBJECT-COMPUTER. G2HOST
           PROGRAM COLLATING SEQUENCE IS ALF5.
       SPECIAL-NAMES.
           ALPHABET ALF5 IS "5".
       ...
       01 NV   PIC 9(3)V99.
       01 X5 REDEFINES NV PIC X(5).
       01 NE   PIC ZZ9.99.
       ...
           MOVE LOW-VALUE TO NV NE.
           DISPLAY "LV NV=" X5 " NE=[" NE "]".
```

- **Expected** (from GR4): `LV NV=55500 NE=[555.00]`.
- **Observed** at --std 2002, on a build of main 63ab0c4ece: `LV NV=55555 NE=[555555]`, exit 0, no diagnostic. The
  same at --std 85 and 2014. At 2023 the move is COBOL0902, removed; under --permissive it takes the 2014 path.

**Blocks:** `2002-GR-14.8.24.3-4`, recorded DIVERGES naming this note and PB5351 (the row's ALL-literal leg, whose
2002 line `AL NV=55555 NE=[555.55]` is also wrong).

**Sites:** `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/MoveEmitter.cs:686` (`AllLiteralNumber`: the figurative arm now applies at every edition, an integer sender of scale 0 at the receiver's digit count from 2002); its callers `ElementaryStore`, `IsNumericOperand` and `ConvertSource` are unchanged.

**Landing, 2026-11-23 (2002 and 2014).** Re-probe before the fix at --std 2002: `NV=55555 NE=[555555]`. After: `NV=55500 NE=[555.00] NEB=[$55.00]`, `NS=55500+ NI=555 NP=555.00 NB=555.00` at 2002 and 2014. The 2002 digit count is the item's digits (`9(3)V99` 5, `ZZ9.99` 5 digit positions, `$$9.99` 4), the value an unsigned integer aligned by decimal point (§2002:14.8.24.3 GR4b; §2014:14.9.24.3 GR6d.3.b). Witness `conformance:cases/14.8.24@2002-MOVE-STATEMENT/pb5677_figurative_digit_to_noninteger_2002` (rule 2002-GR-14.8.24.3-4). No negative golden: the same program is accepted below 2002 and gives the same values (the 85 golden of the first landing).
