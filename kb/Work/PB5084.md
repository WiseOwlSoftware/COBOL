# PB5084 - the 1985 Segmentation module is accepted-inert at --std 85: segment-numbers are parsed and never range-checked or flow-checked, and an ALTERed GO TO in an independent segment is not returned to its initial state on re-entry

**Mechanism.** The root cause is one decision, recorded in docs/VERSION_CHANGE_REFERENCE.md row 7.18: the section-header segment-number is parsed and discarded at 85 as a conforming all-resident posture, and the independent-segment special rules are deliberately not implemented. That posture is conforming only for programs that obey the 1985 segmentation rules; it gives no refusal for a SEGMENT-LIMIT above 49, a section segment-number above 99, a declarative segment-number of 50 or more, or the MERGE output-procedure flow restrictions (compile-time under-rejects), and it runs an ALTERed GO TO in an independent segment as if it were resident when the 1985 text returns it to its initial state on the three listed re-entries (wrong answer: the second pass prints ALTERED where 1985 prints INITIAL). Row 7.18 documents the leniency as deliberate and Segmentation is an optional module, so the fix may need an owner decision (CLAUDE.md rule 3: a deferral is debt without one); the note is filed so the decision is visible.
