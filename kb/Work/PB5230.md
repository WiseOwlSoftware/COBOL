## The decision

PB5207 item 2, built. The Unit assembly held two kinds of test: the compiler's unit tests, and the repository's drift tests,
which read the documents' data files, the records, the scripts a test runs, the CI files, every test source and the names
of every tracked file. So `unit`'s declared inputs were `@population-inputs`, and a workflow, an architecture record or
another project's test source re-ran 40,746 compiler tests. They are now two assemblies and two targets:

- **`unit`** (`tests/WiseOwl.Cobol.Tests.Unit`, 40,574 cases) declares `@build`, its own project, exactly the data its
  sources read (the ISO text, `data/unicode/`, the rule catalog, six word lists, the construct catalogue and the conformance
  register under `tests/version-matrix/`, `tests/nist/`, `conformance-suite/`, `tests/doc-facts/`), and the inputs of the one
  process its tests run: SuiteManifest's `conformance-suite/harness/generate.py --out` (the inventory of both editions, its
  schema, the A.2 list, both rule catalogs, and the `scripts/` modules it imports), each entry naming that process as its
  reader. A traced run of the generator on this branch confirmed the list.
- **`repo-drift`** (`tests/WiseOwl.Cobol.Tests.RepoDrift`, 176 cases) declares `@population-inputs`.

**The split is derived, not listed.** With `unit` declared as above, the BUILD TARGETS audit (`python scripts/buildgraph.py
check`) read every Unit source: a source whose spelled reads lie outside those inputs, or whose read it cannot resolve,
moved; a class holding both kinds was split by method (ClassSpellingDriftTests, FileControlKeyRuleDriftTests,
GateLegDriftTests, ProcessObservationDriftTests, RecordClauseRuleDriftTests, RegistryShapeDriftTests). A method that is the
planted-input proof of a moved sweep moved with it, and a class whose methods share state across the two kinds moved whole.
Two moves the per-file audit could not see were found by the build: BackendContractDriftTests reads the architecture edges
file through `ArchitectureEdgesDriftTests.EdgesFile`, and SelfTestArmSource and TestsTreeWalks serve only moved tests.

**The audit holds it.** A planted Unit source reading `docs/rearchitecture/architecture-edges.json` is
`=== BUILD TARGETS: RED — 1 repository read(s) outside their target's declared inputs ... ===` naming its file and line;
before this change the same read was covered by `@population-inputs`.

**The 107 bare root references, resolved to zero in Unit.** The audit learned to read what the sources write: a root made
relative (`Path.GetRelativePath(TestRepo.Root, f)`, 35 sites) or interpolated into a message is no read; a collection
expression (`TestRepo.At(["src", ..])`, `Path.Combine([TestRepo.Root, "src", ..])`) is read through its literals;
`TestRepo.SuiteCase` reads its two trees; a whole-tree `TreeScope` (Under `""`) is a bare root. One new helper,
`TestRepo.Within("src/…/", rel)`, declares the directory a computed path lies in and throws at run time when it does not, so
the audit reads the declared directory and the declaration cannot drift; 12 Unit sites use it (the narrowest true
directory each). Three shared files are judged by hand in `unit`'s `judged` map, with reasons: TrackedTree's `git ls-files`
(filtered by each caller's declared scope, whose literal prefixes the audit reads), GateLegAudit.HostRoot (the root as text),
PythonInstrument's working directory (the generator). Every other root left with its test. Unit's verdict-line count is 0.

**Found by the first gate, fixed at its root.** WITNESS LOSS read DOC-A.1-141's repointed ref as a lost witness: git's
rename record re-spelled only file-backed refs (a suite program), never an xUnit test whose class's file moved between
test projects. `respelled_from_name_status` now maps `<form>:<Class>.` across such a rename and `respelled_ref` keeps the
method, with self-test arms (`=== WITNESS LOSS ...: 0 unexcused, ... 1 re-spelled ... GREEN ===`). The ANNEX A.1 REGISTER
audit also held the row's `Pinned by` in docs/CONFORMANCE.md to the old spelling; it is repointed.

**Consumers changed in this change (rule 4):** the solution, the RepoDrift project (it builds Unit first, never referencing
it), InternalsVisibleTo in the compiler, `GATED_ASSEMBLIES` (the gate, the shards and the population checks read it),
the gate's self-test, linux-gate.sh, battery.sh, the determinism script, CI (one step per shard job, the listings and
ci-gate's union), the weights (the 23 whole-moved classes' measured weights renamed; split halves at the default until
`shard_weights.py generate`), the inventory's test-ref forms (`repo-drift:`, one row repointed; normalize_batch now reads
the forms from the schema instead of its own copy), drift_rules.py (`Within`), the inert classification's reader names,
record_verdicts.py's printed gate, r2_inputs' project order, test_plan_wave's path, and the docs that name the populations.
TrackedTreeScopeDriftTests now reads the compiled TreeScope fields of every project that declares one (Unit's from its
build output through `ScratchDirectory.LoadAssembly`), since the index spans both assemblies.

**The population is conserved:** Unit 40,746 before = Unit 40,574 + RepoDrift 176 after, less four new cases: each gated
assembly carries its own per-assembly arms, so Unit gained `GateLegDriftTests.Arm4_ThisAssembly_NamesTheGateFramework` (its
tree-wide Arm4 moved) and RepoDrift gained `GateLegDriftTests.Arm5_NoDiscoveredCase_CarriesTheRepositoryRoot`,
`ThisTestHost_IsConfiguredForServerGc` and `ThisAssembly_EmbedsTheShardWeights`. Every other case is the same case; the
173 moved ones (Unit 40,746 - 40,573 kept = 173 = RepoDrift 176 - its 3 new) changed only their namespace (`WiseOwl.Cobol.Tests.Unit.` to `WiseOwl.Cobol.Tests.RepoDrift.`).

## Found, and left (each needs an id; none allocated here)

1. **A records change still re-runs Unit**, through SuiteManifest's generator, until kb/Work PB5231 makes the generator a
   target with an output: then `unit` declares the generator target's output instead of the generator's inputs, exactly as
   `conformance` will, and the six inventory paths and seven `scripts/` modules leave Unit's declaration. Moving the
   suite-manifest readers to RepoDrift now was measured and refused: three of them (RepositoryRoundTripCorpusTests,
   HostEntryShapeDriftTests' and SignatureIdentityDriftTests' corpus Facts) are compiler tests that need the compiler's
   internals through Unit's repository-codec helpers, which no shared source can carry (tests/_shared is linked into
   assemblies without that access).
2. **Conformance (5) and Characterization (4) still have bare roots**, all text uses or the three judged shared files. Judge
   them, then make the audit refuse a bare root in any target that does not declare `@population-inputs`, so Unit's zero is
   held mechanically and not by review.
3. **The weights of the six split classes' RepoDrift halves** are the default until the next `shard_weights.py generate`.
