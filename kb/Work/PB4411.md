# PB4411 - The RESUMED hold waits for an agent that does not exist

**Site:** `scripts/orchestrator/plan_wave.py`, the `RESUMED:` arm of the findings-case classifier (the `else` under
`s.stamped(r, cls) and not s.findings(r, cls)`, kb/Work PB3446).

**What happens.** Report `w20261788b-PB4240-report.md` is DONE at `b3e09f47c722` and its branch review stamped
FINDINGS there. The operator then committed two PB4274 split-out commits on the branch by hand (`2d3750c6e`,
`4df460e31`: the PB4274 half was landed separately as `tooling-pb4274-trx-spelling`). No agent was running on the
branch, so nobody rewrote the report. The arm's comment assumes "a resumed agent rewrites its report". Here none
will. The branch survey reads the branch as a DECISION (idle 14.6 h), and the planner holds PB4240, PB4229, PB4176
and PB4233 "until its agent rewrites its report". That hold has no exit. The resume unit's DECISION ruling (FINISH,
2026-11-01 17:12 and again at 18:32) cannot reach the planner either. The DECISION row also holds
`worktree-wf_2201113e-54d-29` (PB4207/PB4208/PB4214/PB4218) through the file-set collision on
`DESIGN-frontend-grammar.md`. So two FINDINGS branches waited a day.

**Harm.** No user program is affected (`process_only`). The planner's text names an action that never happens
(`misleads_diagnosis`), and nothing alerts that the hold is permanent (`silent`).

**Fix direction.** The RESUMED arm must tell a live owner from none. Use the same ownership test the IN FLIGHT arm uses
(`prune_worktrees.owned`: a live agent, a dispatch out, a touch inside --min-age). An unowned branch whose tip passed
its report goes to a finisher. Its brief names the commits after the report, and the finisher answers the stamped
findings on top of them. Add a self-test row in which an idle branch's tip has passed its report.

**Interim (this instance).** The resume unit handed `worktree-wf_2201113e-54d-26` to the enqueue unit's finisher
(next_unit `enqueue`), the path the unit prompt gives a DECISION row that needs an agent.
