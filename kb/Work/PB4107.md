# PB4107 — the identity rules for restricted pointers are answered with the signature relation

## The rule (the deciding adjudication; every quote checked with `cite.py --check`, OK)

- §14.8.2.3.2 (BY REFERENCE parameters): "If either is a restricted pointer, both shall be restricted and of the same
  type." "Of the same type" is §8.5.3.1's relation: "Two typed items are of the same type when: ... The items are
  described with TYPE clauses that reference equivalent type declarations", and equivalent declarations "have the same
  type-name". Every restricted program-, function- or data-pointer is a typed item: §13.18.60.3 SR18 / SR19 require the
  TYPEDEF clause on its entry.
- §9.3.6 match rule 3 e) (INVOKE, BY REFERENCE) and §14.8.3.3 (returning items) require "the same ... USAGE clauses": the
  TO phrase is compared by the prototype (or type) it names.
- Only SET and the rules that send to it say "same signature": §14.9.39.3 SR22 ("the program-prototypes associated with
  identifier-7 and identifier-8 shall have the same signature"), SR20 (function-pointers), SR19 (a data-pointer
  "restricted to the same type"), CALL §14.9.4.3 SR14, and §14.8.2.3.3 / §9.3.6 4 c), 5 c), 6 (BY CONTENT, BY VALUE and
  RETURNING rule 6 conform "as if a SET statement were performed").

The ISO text decides; no implementor latitude, no owner decision. The compiler's unknown-signature stance for prototypes
the external repository would resolve (PB3162, PB1086 / PB2103) is a stance on the SIGNATURE relation only.
