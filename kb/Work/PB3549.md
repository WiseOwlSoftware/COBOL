# PB3549 — the kept file's liveness lock survives its give-back on Linux

## Owner's rules that apply

"a timing failure is a failure" (a red that passes alone is a defect), and, 2026-10-17, "a crash/concurrency design needs an
executable simulator from round one".

## Measurement (a cobol-locator, read-only, 2026-10-22)

   Command: `dotnet test tests/Cobol.Net.Tests.Unit --no-build --no-restore --filter

## What the assertion reads

- Test lines 1894 to 1936. Row abnormal-always: the write predicate (1908) refuses every non-meta page write while
  refusals > 0; refusals = 1 (1930) before `a.CloseAll()`, so the implicit rollback AND the CLOSE-time commit-then-rollback
  are refused; the transaction is left standing "as a death leaves it" (FileRegistry.cs:540, KeptFile.cs:67).
- Then refusals = 0 and `Settled` (129 to 134) opens a NEW writable FileRegistry "S" on the same host file; its OPEN must
  run the dead-owner step (KeyedConnector.cs:414/460/973 → `KeyedStore.RollBackDeadOwners`, KeyedStore.cs:381-398).
  Immediately `AssertNoTransactionLeft` (TransactionTrees.cs:28-33) reads
  `reg.PagedStoreOf("S").Meta.HoldingsRoot.IsNone` then `TransactionsRoot.IsNone`: the in-memory meta (page 2) of S's own
  store, once, right after OPEN. HOLDINGS is asserted first, so a failure means the dead-owner rollback did NOT run (or did
  not finish) for a's transaction.
- `RollBackDeadOwners` only rolls back id != own where the pre-fix probe `OwnerIsDead(prober, id)` (KeyedStore.cs:341-342; the fix replaced it with `OwnerOf`, read through `MayRollBack`) =
  `prober.HeldByAnother(liveness byte) == Ok`. Any other answer (Held, Unavailable) means "alive": a host that cannot say
  answers alive (KeyedStore.cs:340 comment). Nothing else gates it.

## Mechanism candidates, Linux-only (candidates; NEITHER IS CONFIRMED)

- **Candidate A.** a's liveness byte is not released synchronously by the CLOSE. `KeptFile.GiveBack` (KeptFile.cs:48-59)
  only nulls the field (`KeyedStore.LivenessGoneWith`, KeyedStore.cs:297-300); `HandleRegionLocks.Dispose` is a no-op
  (HandleRegionLocks.cs:63); the lock goes only when `Stream.Dispose` closes the fd. Linux uses OFD locks
  (OfdRegionLocks.cs), released only when EVERY fd on the open-file description is gone. `OfdRegionLocks.Release` (doc
  around lines 149 to 153) states that a fork in another thread holds a copy until exec closes it. The gate ran about 35k
  tests in parallel in one process, including CALL "SYSTEM" and child-process tests; a fork in that window keeps a's byte
  locked for milliseconds, so S sees the owner "alive", no rollback runs, and HOLDINGS stays. Windows `LockFileEx` is per
  handle, closed with the handle: no such window. Passing in isolation (no concurrent forks) matches.
- **Candidate B.** `OfdRegionLocks.HeldByAnother` uses the 4-argument `Classify` (OfdRegionLocks.cs around lines 158 to
  160): EINTR is not retried (only `Hold` loops, around line 131), and ENOLCK, EINTR and EBADF map to Unavailable, which
  reads as "alive". Signal or lock-table pressure under load would do the same.

Not found: finalizers, Task.Run, timers or background flush in KeyedStore, KeptFile, KeyedConnector or Sharing (grep
empty). ext4 versus NTFS enters only through candidates A and B.

Unmeasured: A versus B (no instrumentation run), Windows runs, repeating under parallel load.

## Fix shape (for the implementer)

- The liveness byte is released explicitly by the one lock-hold mechanism (`HostRegionLocks`, which d06-2 made the single
  store-mutex hold) when the kept state is given back, never left to the fd close.
- "Unavailable" is never read as alive without a bounded retry.
- The sequential journal and kept-state model (`scripts/models/`) gains the fork-copy case, so the race is reproduced
  deterministically before the fix and shown gone after.

## Landing (wave 1156 group B)

For the next implementer:
- `src/Cobol.Net.Runtime/IO/Sharing/HandleRegionLocks.cs#Dispose` — owns "every byte given back explicitly"; the hold map `_held` is the one record of what the endpoint holds (Hold adds, Release removes). Trap: holds do not stack on any host; never unlock through a byte the map does not hold.
- `src/Cobol.Net.Runtime/IO/Sharing/OfdRegionLocks.cs#Classify` — the one `fcntl` reading (EINTR repeated, ENOLCK bounded by `LockRecordAttempts`); add a command by calling it, never by reading errno elsewhere.
- `src/Cobol.Net.Runtime/IO/KeyedStore.cs#OwnerOf` / `#MayRollBack` — the dead-owner probe's three answers (`OwnerLiveness`); reuse `MayRollBack` for any new roll-back decision.
- `src/Cobol.Net.Runtime/IO/SequentialConnector.cs#CloseCore` / `#AbandonOpen` — flush, give the endpoint back, THEN close the streams.
- `src/Cobol.Net.Runtime/IO/Sharing/HandleColumnLockHost.cs#Published.Dispose` — unlock the column byte, then close.
- `tests/_shared/DescriptionCopy.cs#Of` — a second handle on the same open file: the deterministic stand-in for a fork not yet at exec; reuse it for any "lock outlives the close" witness.
- `scripts/models/kept_liveness_model.py` — the give-back model; extend its ROWS and MUTATIONS for a new lock-release step.

**Candidate A confirmed, deterministically, on Windows as well as Linux.** A second handle on the same open file (Linux
`dup`, Windows `DuplicateHandle`: `tests/_shared/DescriptionCopy.cs`) stands in for a fork not yet at its exec. Before the
fix, `CommitRollbackRuntimeTests.An_abandoned_transaction_is_rolled_back_while_a_copy_of_its_owners_handle_lives` (both
keyed organizations) failed every run with the gate's own message, "the HOLDINGS tree is empty once no transaction is open",
and `RegionLocksDriftTests.DisposingAnEndpointGivesBackEverythingItHolds` / `OneReleaseGivesBackAByteHeldTwice` answered
`Held` for bytes the disposed endpoint had held. The drift test had exempted the handle-owned hosts ("the handle-owned hosts
give a lock back when the connector closes the handle"), which is how the contract gap stayed green.

**Fix.** `HandleRegionLocks` keeps a map of the bytes it holds (holds do not stack, as on the lock-file host) and its
`Dispose` unlocks each one while the handle is still open: the `RegionLocks.Dispose` contract ("give back everything this
endpoint holds") on every host. Every owner already disposed the endpoint first except `SequentialConnector`'s CLOSE and
abandoned OPEN, which closed the streams first; they now flush, give the endpoint back, then close. `HandleColumnLockHost`
(Windows) unlocks its column byte before closing its handle, including a refused publication's byte. Candidate B:
`OfdRegionLocks.Classify` is the one `fcntl` reading for every command and asks `EINTR` again for as long as it recurs and
`ENOLCK` up to four calls in all. The probe's three answers are one enum, `OwnerLiveness` (`KeyedStore.OwnerOf`), read by
`KeyedStore.MayRollBack` for `RollBackDeadOwners` and the lock test (`KeyedConnector.HoldingsGate`); Unknowable reads as alive.

**Model.** `scripts/models/kept_liveness_model.py --self-test` (discovered by `scripts/self_tests.py`): 522 interleavings
GREEN; under the mutation `dispose-leaves-bytes-to-close` (the old protocol) the row `give-back-under-fork` is RED with the
interleaving open, fork, draw, end-refused, detach, dispose, close, B probed Alive. Design: DESIGN-runtime-library.md, the
region-lock endpoint paragraph and the dead-owner step (2.2.1.10).
