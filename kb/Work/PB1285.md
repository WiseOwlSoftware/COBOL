## Measured

### Finding report-clause — 13.18.46.3 SR1, SR2 (under-rejects; rows SR-13.18.46.3-1, SR-13.18.46.3-2)

**Mechanism.** The FD side of the report-name <-> REPORT-clause correspondence is never checked: ResolveReports walks only the RDs (diagnosing an RD no FD names) and binds the owning file with FirstOrDefault, so a REPORT clause naming a report with no RD, and a report named in two REPORT clauses, both compile clean.

**Repro.** (a) FD RPT REPORT IS R-1.  FD RPT2 REPORT IS R-NONE.  with only RD R-1 in the REPORT SECTION; (b) FD RPT REPORT IS R-1.  FD RPT2 REPORTS ARE R-1.  Both: cobol x.cob --run -> compiles, prints OK (probe files sr1b.cob / sr2.cob under out13/probe/report-clause).

**Expected, from the standard.** Both are syntax-rule violations and must be rejected at compile time: (a) 13.18.46.3 SR1 'Each report-name-1 shall be the subject of a report description entry in the report section of the same source element.'; (b) 13.18.46.3 SR2 'Each report-name-1 may appear in only one REPORT clause.'

**Observed.** DataBinder.ResolveReports: `model.File = Files.FirstOrDefault(f => f.ReportNames.Any(rn => rn.Equals(model.Name, ...)))` - the loop is over Reports only; no loop over FileModel.ReportNames checks for an RD, and no count of FDs naming a report. The comment above it asserts the exactly-one requirement it does not enforce (and cites it as 13.18.46.4 GR1 / 13.14, whereas it is 13.18.46.3 SR2).

**Code site.** src/Cobol.Net.Compiler/Binding/DataBinder.Reports.cs#ResolveReports (~lines 2544-2557)

### Finding report-description-entry — 13.14.3 SR1 / 13.18.46.3 SR2 (under-rejects; rows SR-13.14.3-1)

**Mechanism.** ResolveReports binds a report to the FIRST FD whose REPORT clause names it and never counts the others, so a report-name named in two FDs' REPORT clauses is accepted silently

**Repro.** SELECT RPT ... SELECT RPT2 ... FD RPT REPORT IS R-1. FD RPT2 REPORT IS R-1. RD R-1 PAGE LIMIT 20. -> compiles, runs, output only to RPT

**Expected, from the standard.** §13.14.3 SR1 'There shall be one and only one REPORT clause specifying report-name-1 ...' and §13.18.46.3 SR2 'Each report-name-1 may appear in only one REPORT clause.' -> a compile-time error naming both FDs.

**Observed.** Files.FirstOrDefault(...) in ResolveReports; only the zero case is diagnosed (and that one under the not-implemented COBOLNET0899 band rather than a syntax-rule code).

**Code site.** src/Cobol.Net.Compiler/Binding/DataBinder.Reports.cs#ResolveReports
