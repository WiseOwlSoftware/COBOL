## The measurement

`<scratch>/reg6/probe/q06_sum_arith.cob`, `--std 2023`:

```
  q06_sum_arith.cob(19,44): error COBOL0307: unexpected '+'. A period may be missing at the end of the
  previous sentence.
```

The source line is `03 COLUMN 1 PIC 9999 SUM WS-K + 1.` — a complete entry, correctly terminated, whose
`arithmetic-expression-1` addend has no grammar surface (that is `PB883`). **No period is missing.** The
message sends the reader to look at the previous sentence, which is fine.

The PB396 report named two more instances on shipped goldens:
`conformance-suite/cases/_unassigned/pb712-write-two-advancing-operands.cob` and
`conformance-suite/cases/14.9.30-READ/pb331-read-key-before-lock.cob`, which "now report only that hint".

## The mechanism

`src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs#GuessCobolIntent`, hint 14. It is a heuristic with
priority 25. Before PB396's SLL fix, the duplicate SLL report contributed a neutral `COBOL0001` that
competed with it; with the duplicate gone the hint has no competitor and therefore always wins on this
shape.

## The honest diagnostic

A statement that parses up to a phrase the general format does not print should be reported as such — naming
the phrase and the statement's own § (or §5.2.6.4 for the sentence structure) — not as a guess about
punctuation. Concretely: when the error token is INSIDE a statement the parser has already recognised, the
period hint is the wrong family and should be de-prioritised below a "phrase not admitted by this format"
message.

## Why this is process-only and still worth a note

No program computes the wrong answer and no legal source is refused (the source in the measurement above IS
refused, but by `PB883`, not by this). What is wrong is that the user is pointed at the wrong line. It is
filed because it is a REGRESSION in diagnostic quality introduced by a specific change, recorded by the
implementer who introduced it, and because three shipped negatives now depend on the wrong message — so
whoever fixes it must re-baseline their `.err` expectations.

## The sibling sweep

`GuessCobolIntent`'s other hints are the same shape: each is a guess with a priority, and each was tuned
against a diagnostic population that has since changed. The fixer should re-measure which hint wins on every
`tests/conformance/negative/*.cob` and flag any whose winning hint names a cause the file's own
`*> reject-at:` line contradicts. **A hint that wins by default is not a hint.**

## Landed (wave 20261711 group C)

**Re-probe on a fresh build (main 1b6af36e5 plus the PB3831/PB3832 branch).** The registrar's measurement had moved: PB3832
(round 2) already made hint 14 ask whether a period lets the TOKEN follow, so `SUM WS-K + 1` no longer fails (PB883 gave
SUM an arithmetic expression) and the three goldens the note names draw the bare COBOL0001 or the true COBOL0306. What
still drew the wrong family was the same mechanism one token later: `WRITE SQ-REC IGNORING LOCK.` (golden
`pb331-write-ignoring-lock`, PB3844's repro) drew COBOL0307, because IGNORING is a context-sensitive word and so a legal
paragraph-name, `. IGNORING` parses, and the walk asked about one token only. The fifth fuzz night's witness (fz02341,
`WRITE R INVALID KEY SET X TO "INVALID"`) now lands on the literal, not on INVALID (PB3832's offending-position work);
its wording was the remaining defect.

**The root.** A complete statement followed by a word its general formats do not print there was told it lacked a period.
Three faults in how `CobolErrorStrategy` read that shape: (1) the missing-period reading checked one token, not the
sentence that would start there; (2) no hint named the real fault, so the family fell to a guess or to a bare COBOL0001;
(3) hint 15 ("a data-name is expected here, not a literal") said "not a literal" where the format also admits a literal of
another kind (`SET X TO "A"` admits an arithmetic-expression, ISO §14.9.39.2 Format 1).

**The fix.** (1) `OffendingPosition.APeriodLetsTheSentenceFollow` walks the period, the token and the rest of the sentence
through its separator period (sixteen tokens at most). (2) Hint 0h: `OffendingPosition.StatementThatEndedBefore` finds the
statement the parser completed just before the token, re-simulates it over every path
(`ResimulationWalk.Over`) to show it cannot take the token, and names the innermost statement whose format prints the
word after a statement it holds (`CobolErrorStrategy.TokensAfterANestedStatement`, read from the ATN: a second ELSE names the IF,
not the DISPLAY before it; the `>` of an IF's condition after a complete MOVE names the MOVE; a SET format is named SET); the hint is COBOL2269 citing ISO §5.2.1 and fires only where no structural hint stands and the
token is no scope terminator. (3) Hint 15 stands only where no literal is expected. `DiagnosticHint.IsStructural` and
`HasStructuralHint` are the one statement of the priority-0 convention the guards had each spelled.

**Population audit (the note's sibling sweep).** All 2,884 refused conformance cases re-run before and after on the
branch's own build (`measure.py` and `diff.py` in the wave's scratch directory): 14 changed, each a stray
phrase after a complete statement (13 COBOL0001 or COBOL0307 to COBOL2269, one cascade COBOL0307 to COBOL0001). The
COBOL0307 that still wins (`l1c10`, `l1c20`, `pb1966`, `pb3390`) is a true missing period each time; COBOL0312 and
COBOL0305 stay vague guesses and false in none of the cases. Registrar 14f's stale hints (OCCURS KEY, SEARCH,
EVALUATE ALSO) were already corrected or deleted by PB1266 and PB2770; hint 8 is a position hint and still true.
