# PB906 — OPEN — a guess that wins because nothing else is left to say

Source: the `PB396` report, "New defects" item 2 — the recorded residue of that change set's own SLL fix.

## The measurement

`<scratch>/reg6/probe/q06_sum_arith.cob`, `--std 2023`:

```
  q06_sum_arith.cob(19,44): error COBOL0307: unexpected '+'. A period may be missing at the end of the
  previous sentence.
```

The source line is `03 COLUMN 1 PIC 9999 SUM WS-K + 1.` — a complete entry, correctly terminated, whose
`arithmetic-expression-1` addend has no grammar surface (that is `PB883`). **No period is missing.** The
message sends the reader to look at the previous sentence, which is fine.

The PB396 report named two more instances on shipped goldens:
`tests/conformance/negative/pb712-write-two-advancing-operands.cob` and
`tests/conformance/negative/pb331-read-key-before-lock.cob`, which "now report only that hint".

## The mechanism

`src/Cobol.Net.Frontend/Parsing/CobolErrorStrategy.cs#GuessCobolIntent`, hint 14. It is a heuristic with
priority 25. Before PB396's SLL fix, the duplicate SLL report contributed a neutral `COBOL0001` that
competed with it; with the duplicate gone the hint has no competitor and therefore always wins on this
shape.

## The honest diagnostic

A statement that parses up to a phrase the general format does not print should be reported as such — naming
the phrase and the statement's own § (or §5.2.6.4 for the sentence structure) — not as a guess about
punctuation. Concretely: when the error token is INSIDE a statement the parser has already recognised, the
period hint is the wrong family and should be de-prioritised below a "phrase not admitted by this format"
message.

## Why this is process-only and still worth a note

No program computes the wrong answer and no legal source is refused (the source in the measurement above IS
refused, but by `PB883`, not by this). What is wrong is that the user is pointed at the wrong line. It is
filed because it is a REGRESSION in diagnostic quality introduced by a specific change, recorded by the
implementer who introduced it, and because three shipped negatives now depend on the wrong message — so
whoever fixes it must re-baseline their `.err` expectations.

## The sibling sweep

`GuessCobolIntent`'s other hints are the same shape: each is a guess with a priority, and each was tuned
against a diagnostic population that has since changed. The fixer should re-measure which hint wins on every
`tests/conformance/negative/*.cob` and flag any whose winning hint names a cause the file's own
`*> reject-at:` line contradicts. **A hint that wins by default is not a hint.**
