# PB504

## Mechanism — data-description-entry-p2
F4 — §13.16.3 SR9's implied PICTURE is synthesized NOWHERE. BindEntry's `pic` derivation is a chain of arms keyed on USAGE (INDEX, POINTER, PROGRAM-POINTER, OBJECT REFERENCE, the BINARY-* family, the float family) and has no arm keyed on the VALUE literal; ResolveIndexItems' post-forest adjudication likewise has arms for GROUP-USAGE, the NATIONAL/BIT pending mark, index and object-reference, and none for a picture-less elementary DISPLAY item. The item therefore ends bind with Pic == null and no diagnostic, and the FAILURE SURFACES IN THE BACKEND: the field is never emitted, so a reference to the user's own data-name leaks a raw Roslyn `CS0103` to the user.

### Expected, from the standard
ISO/IEC 1989:2023 §13.16.3 SR9 (cite-checked): "The PICTURE clause may be omitted for an elementary item when an alphanumeric, boolean, or national literal that is not a zero-length literal is specified in the data-item format of the VALUE clause. A PICTURE clause is implied as follows: a) if the literal is alphanumeric, 'PICTURE X(length)' b) if the literal is boolean, 'PICTURE 1(length)' c) if the literal is national, 'PICTURE N(length)' where length is the length of the literal as specified in 8.3.3, Literals." So `01 A VALUE "HELLO".` is legal, A is PIC X(5), and the scalar probe shall print `[HELLO]` then `5`; the group probe shall print `[HELLOXYZ]`.

```
$ python scripts/spec/cite.py --check 13.16.3 "The PICTURE clause may be omitted for an elementary item when an alphanumeric, boolean, or national literal that is not a zero-length litera..."
  FAIL: §13.16.3 exists but does NOT contain 'The PICTURE clause may be omitted for an elementary item when an alphanumeric, boolean, or national literal that is not a zero-length literal is specified in the data-item format of the VALUE clause. A PICTURE clause is implied as follows: a) if the literal is alphanumeric'
$ python scripts/spec/cite.py --check 13.16.3 "where length is the length of the literal as specified in 8.3.3, Literals"
  OK  §13.16.3 9) c)  (Syntax rules)
```

### Observed
Scalar: `error: backend compilation failed (generated C# at p_sr9_alnum.g.cs): (41,52): error CS0103: The name 'A' does not exist in the current context` — a raw compiler-internal error on conforming user source, at all four editions. Group: compiles, then `NotImplementedCobolFeatureException: ... whole-group image of 'R' with a dynamic-length / dynamic-capacity member (a variable-length group has no fixed record window)` — the picture-less member is silently reclassified as variable-length, so a legal fixed-length group becomes an unsupported one. `git grep '13.16.3 SR9' src/` returns nothing; the whole rule has no implementation site. The zero-length-literal exclusion (`01 A VALUE "".`) is untestable-as-conforming while the rule is absent — it currently compiles clean too, for the same reason. Edition scope 2002+: the rule's boolean and national literal categories are post-1985 additions; at 85 the missing behaviour is instead SR8's rejection, which is also absent (see F5).

## Mechanism — data-description-entry-p2
F5 — the same missing arm as F4, seen from the ILLEGAL side: §13.16.3 SR8's positive half ('For any other entry describing an elementary item, a PICTURE clause shall be specified') has no check either, so a picture-less elementary DISPLAY item with no VALUE literal is accepted and carried into code generation with Pic == null. The emitter is not defensive against it and CRASHES the compiler with an unhandled NullReferenceException. The project's own precedent for exactly this shape is DEVLOG 597 (the binary-usage crash), whose cure was the recovery-shape synthesis in ResolveIndexItems — that cure covers the NATIONAL/BIT pending marks and never reached the plain-DISPLAY case.

### Expected, from the standard
ISO/IEC 1989:2023 §13.16.3 SR8 (cite-checked): "... For any other entry describing an elementary item, a PICTURE clause shall be specified except as indicated in Syntax rule 9." USAGE DISPLAY is not one of SR8's picture-less usages and no VALUE literal is present, so the entry is nonconforming and shall be rejected at compile time with a diagnostic naming the missing PICTURE.

```
$ python scripts/spec/cite.py --check 13.16.3 "... For any other entry describing an elementary item, a PICTURE clause shall be specified except as indicated in Syntax rule 9"
  OK  §13.16.3 8)  (Syntax rules)
```

## What PB487 changed here, and what it did NOT (2026-09-09)

PB487 landed `CheckPictureRequired`, the §13.16.3 SR8 closing guard, so BOTH of this note's repro shapes now
draw a NAMED diagnostic instead of leaking: `01 A VALUE "HELLO".` answers `COBOLNET0881: data item 'A': a
PICTURE clause shall be specified for an elementary item (ISO 13.16.3 SR8)` where it used to reach the user as
a raw Roslyn `CS0103` (or, inside a group, a `NotImplementedException` at DISPLAY). The national (`N"..."`) and
boolean (`B"..."`) legs answer identically -- measured on the PB487 finisher tree.

**The defect itself is UNCHANGED and this note stays open.** SR9's implied PICTURE is still synthesized nowhere,
so what the compiler now does with legal SR9 source is REJECT it loudly rather than mis-emit it silently. That
is a strictly better failure and not a fix: the rule says the PICTURE `may be omitted`, and the implied
`X(length)` / `1(length)` / `N(length)` is the feature this note owns. `SR-13.16.3-9` stays NOT-IMPLEMENTED.

⛔ **The one thing an implementer must not do here** is silence 0881 for VALUE-bearing entries as a way to make
the source compile again. PB487 measured that exact shortcut: with the SR8 diagnostic skipped for any entry
carrying a VALUE, `01 B VALUE "AB".` binds as the ONE-CHARACTER recovery item and `DISPLAY B` prints `A` -- a
silent wrong answer traded for a loud rejection. The guard's carve-out is therefore the FIGURATIVE case only
(`01 A VALUE SPACE.`, which §7.3.15.4 GR4 k's `>>FLAG-14 VALUE-FIG-CON-LENGTH` option shows is accepted and
flagged, not rejected). Synthesizing the implied PICTURE is what makes the entry stop being picture-less, and
the guard then never sees it.

## Landed (2026-09-13)

**SR9 is now APPLIED, and that is what removed the carve-out rather than widening it.** The new bind pass
`SynthesizeImpliedPictures` (`src/Cobol.Net.Compiler/Binding/DataBinder.ImpliedPicture.cs`) walks the
COMPOSITION forest between `ExpandTypes` and `UsageInheritancePass` and gives every entry inside SR9's grant the
PICTURE character-string the rule spells out -- `X(length)` / `1(length)` / `N(length)` -- then hands that string
to **the same `PictureAnalyzer.Analyze` call a WRITTEN clause takes**, argument for argument (the entry's own
usage and SIGN clause; `explicitUsage` = "this entry wrote a USAGE clause"). From that point the item is
indistinguishable from one whose source wrote the clause, so §13.18.60.4 GR1 group inheritance, the §13.18.60.3
SR3/SR5/SR12/SR20 screens, SIGN inheritance, the VALUE initializer and the emitter all reach it through their
existing single sites. §13.18.60.3 SR13 a) and SR20 are written for exactly this -- they speak of the "explicit
or **implicit** picture character-string" -- so an implied `N(n)` acquires usage national by the standard's own
words rather than by a special case. The placement is the design: one pass later and `UsageInheritancePass`
would already have rejected `01 A USAGE NATIONAL VALUE N"AB".` for having no PICTURE, which SR9 says it may omit.

**F4 and F5 both close, and they close differently.** F5 (SR8's positive half) stays PB487's
`CheckPictureRequired` guard -- unchanged except that its FIGURATIVE carve-out and `IsFigurativeValueText` are
**deleted**. What the guard reports is now exactly SR8's own population: a numeric literal VALUE, the
class-pointer figurative NULL, a zero-length literal (SR9 excludes it by name), a Format-2 table VALUE (SR9
grants only the data-item format), and an entry with no VALUE clause at all. F4 (SR9) is the synthesis.

**Measured on this worktree's own build**, every repro in this note re-run: `01 A VALUE "HELLO".` prints
`[HELLO]` then `5`; the national and boolean legs print `[HELLO]/5` and `[1011]/4`; the group form prints
`[HELLOXYZ]`; the TYPEDEF-template and LINKAGE spellings compile and run; `01 A USAGE NATIONAL VALUE N"HELLO".`
is accepted; `--std 85` answers `COBOLNET0900 ... requires COBOL-2002` (the new `value-implied-picture-2002`
construct row -- COBOL-85 made no such grant).

**THE SIBLING SWEEP THIS NOTE ASKED FOR FOUND A SECOND ARM, AND IT IS FIXED.** `grep -n "PICTURE clause may be
omitted" specs/ISO_COBOL.md` returns exactly THREE hits, because the standard states this rule once per entry
