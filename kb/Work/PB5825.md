# PB5825 - OPEN INPUT of a file already open OUTPUT or EXTEND fails with status 41 and runs no declarative, though USE ... ON OUTPUT or ON EXTEND is declared (every edition)

**Ruling: UPHELD (b), harm wrong_answer.** Cause (b): wrong the same way at 2023. The checker's confidence: high; the checker's harm word is "wrong_answer (silent)". The ruling's session ran it: `m6mode.cob` printed `OPEN INPUT SF WHILE OPEN OUTPUT 41` with no declarative before it, then `USE-OUTPUT SF=41` for the same-mode OPEN, then `OPEN INPUT GF WHILE OPEN EXTEND 41` with no declarative. Severity MAJOR is the clerk's choice (a wrong-answer defect is at least MAJOR); the ruling names none.

**Mechanism 6, ruled** (the ruling's paragraph, unchanged). `§1985:XIII.4.8.4 GR5b` runs the OUTPUT procedure "for any file open in the output mode or in the process of being opened in the output mode" (cite.py OK). A file open in the output mode on which an OPEN
INPUT fails with 41 is a file open in the output mode, so the OUTPUT procedure runs. The compiler answers with the
ATTEMPTED mode only (`FileConnector.OpenModeView`, since kb/Work PB5200), so with only OUTPUT and EXTEND procedures
declared nothing runs. Which procedure runs when both the current and the attempted mode have one is not stated by
the text and is not part of this ruling. The checker found the same at 2023 (row `GR-14.9.49.4-6`).

**The checker's evidence.** `§1985:XIII.4.8.4 GR5b` and `GR5c` run the OUTPUT (EXTEND) procedure for a file open, or being opened, in that mode. A file open OUTPUT on which OPEN INPUT fails (41) is open in the output mode, and with only OUTPUT and EXTEND procedures declared nothing competes, so USE ON OUTPUT must run. `FileConnector.OpenModeView` answers the ATTEMPTED mode (the PB5200 fix), so the current mode's procedure is lost. The program: OPEN INPUT of SF open OUTPUT gives 41 and no procedure; a same-mode OPEN OUTPUT gives 41 and USE-OUTPUT runs; OPEN INPUT of GF open EXTEND gives 41 and no USE-EXTEND. `§2023:14.9.49.4 GR6c` has the same words and the same output. Which procedure runs when both the attempted and the current mode have one is left open by the text; the defect claimed is only the case where one applies.

**Defect (the checker's summary).** An OPEN in mode X of a file already open in mode Y fails 41 and runs no USE procedure when only the mode-Y procedure is declared: the open-mode view reports the attempted mode, so the procedure for the mode the file IS open in (`§1985:XIII.4.8.4 GR5b` and `GR5c`) is skipped, at every edition.

**Expected:** `USE-OUTPUT` after `OPEN INPUT SF WHILE OPEN OUTPUT 41`; `USE-EXTEND` after `OPEN INPUT GF WHILE OPEN EXTEND 41`. **Observed:** no procedure for either.

**Where** (the checker's reading): `FileConnector.OpenModeView` replaces the current open mode with the attempted mode; `FileConnector.BeginOpen` records it before the 41 refusal; the consumer is `EmitScopeTiers`.
