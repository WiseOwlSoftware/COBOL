# PB5107 - at --std 85 ENABLE INPUT/OUTPUT TERMINAL opens only the send half of the path: a RECEIVE before the ENABLE is given the terminal message, where 1985 activates the logical path both ways

**Sites:** `src/WiseOwl.Cobol.Runtime/Communication/MessageStoreState.cs#Deliver`, whose `terminal:` arm (lines 126-130) adds the terminal message with no test of the terminal Enabled flag, where the queue arm tests the queue and the source; `src/WiseOwl.Cobol.Runtime/Communication/MessageControlSession.cs` (whole: the record names line 250, `TakeFromTerminal`, which the file does not declare as a member under that name) takes it with no test either. Sibling: DISABLE I-O TERMINAL (§1985:XIV.3.2.4 GR5, "and the program is deactivated") leaves the same input path open.

**Mechanism.** 1985 makes the path between a terminal and the program two-way (§1985:XIV.3.3.1) and ENABLE activates it. The compiler gates only the SEND half (status 10 before the ENABLE, 00 after) and gives the terminal message to a RECEIVE issued before the ENABLE. The redraft defines a disconnected terminal to this implementation MCS itself (it writes mcs.json into the MCS directory first) and expects no data from it until the ENABLE.

**Found by.** The 1985 MATCH confirmation pass (kb/Work PB4995 item 3): each rule below is a corrected draft (a "redraft") that the compiler at `--std 85` still fails (redraft_run MISMATCH). Harm and observed text are the records; nothing here was re-derived.
