# PB388 — the citation is inherited, never re-derived, and two of them are in the text the user reads

<!-- audit-doc-citations: names-misfilings — this note IS the misfiling register; every row below PAIRS a
     clause with a quotation that is NOT in it, which is the point of the note. -->

⚠ **FLAG PROVENANCE — read this before the flags.** This note's OWN mechanism (citation drift) changes no
program's behaviour: it is `silent`. `wrong_answer` and `rejects_legal_source` are set by two of the five
INVENTORY ROWS this note owns, whose divergences rest on *other* mechanisms (the dispatcher-`break` idiom and the
SET Format-7 receiver arity) — both re-measured on HEAD in **Rows** below. **Those two deserve their own notes**;
they are recorded here because the b2 clustering gave this note their rows and a row must not go unowned.

## THE MECHANISM

Four distinct sites, one shape: a clause number written for one verb, one format numbering or one edition, then
carried forward by copy without ever being re-derived — CLAUDE.md rule 1's named failure mode, operating in
*shipped diagnostic text* rather than in a design doc.

1. **Shared-verb diagnostics.** `EcBinder`/`EcNameResolution` serve RAISE, GOBACK RAISING and EXIT … RAISING
   from one code path, and each message hard-codes ONE verb's clause. `EcNameResolution.cs:52` prints
   *"(ISO §14.9.29.3 SR1)"* — RAISE's rule — for an EXIT PROGRAM statement; `EcBinder.cs:205` prints
   *"(ISO §14.9.18.3 SR2 …)"* — GOBACK's — likewise; `EcBinder.cs:178/:185/:195` print
   *"§14.9.18.3 SR4 / SR4d / SR4a"* where an EXIT statement's rules are §14.9.14.3 SR5 / SR5d / SR5a. The verb
   STRING is already threaded through this path (`"EXIT PROGRAM RAISING"` appears in every message); the clause
   is not.
2. **The SET format ordinals.** §14.9.39.2 numbers the formats 4 = condition-setting, 5 =
   object-reference-assignment, 7 = data-pointer-assignment. Eighteen sites in `src/` and `tests/` say otherwise
   — the data-pointer slice is labelled "Format 4" and the condition-name slice "Format 5" — and **two of them
   are the message text of COBOLNET0869**, so a programmer is sent to the condition-setting page for a pointer
   rule. `PtrBinder.cs` and `BoundTree.cs:762` get Format 7 right twenty lines away, so the file disagrees with
   itself.
3. **The SEARCH GR numbering.** Every Format-1 citation in the SEARCH path names, under the 2023 clause label
   `§14.9.37.4`, a rule number belonging to FORMAT 2, and the shift is uniform: **GR1→GR5, GR3→GR8, GR4→GR6**.
   What hid it is that the numbering is internally consistent and its most-cited member coincides (GR9 is the
   SEARCH ALL rule in both schemes), so the wrong scheme's citations all "look" right. It has already propagated
   out of `src/` into three test files and **two shipped goldens**.
4. **A clause that answers a different question.** `ControlFlowEmitter.EmitGoToDepending` documents itself as
   *"(ISO §14.9.20 Format 2)"* and *"the selector 'shall be an integer' (§14.9.20.3 SR2)"*. §14.9.20 is
   INITIALIZE. Because the clause-keyed source dossier greps on the citation, **the only file that implements
   GO TO DEPENDING's GR2 was absent from the 14.9.17 file list** — a wrong citation corrupts every mechanical
   selector built on citations, which is the cost that makes this more than cosmetics.

## THE RULES, QUOTED, EACH `--check`ED — AND THE TRAP THEY DEMONSTRATE

⛔ **The same sentence lives in three different clauses.** Running `--check` on the quote proves nothing about
which rule you meant; the ANTECEDENT ("this EXIT statement" / "this GOBACK statement") is what disambiguates:

* `--check 14.9.14.3 "If exception-name-1 is a level-3 exception-name for EC-USER, exception-name-1 shall be
  specified in the RAISING phrase of the procedure division header"` → **`OK §14.9.14.3 3)`** … *"of the source
  element in which this **EXIT** statement is contained."*
* the identical fragment `--check 14.9.18.3 …` → **`OK §14.9.18.3 2)`** … *"in which this **GOBACK** statement is
  contained."*
* `--check 14.9.29.3 "Exception-name-1 shall be a level-3 exception-name"` → **`OK §14.9.29.3 1)`** (RAISE), and
  `--check 14.9.14.3` on the same words → **`OK §14.9.14.3 3)`** (EXIT). Three OKs, three different rules.
* `--check 14.9.14.3 "Identifier-1 shall be an object reference, subject to the following constraints"` →
  **`OK §14.9.14.3 5)`**; `--check 14.9.14.3 "Identifier-1 shall not be a universal object reference"` →
  **`OK §14.9.14.3 5) d)`**. So COBOLNET0849's three messages want SR5 / SR5a / SR5d, not GOBACK's SR4 family.
* `--check 14.9.17.3 "Identifier-1 shall reference a numeric elementary data item that is an integer"` →
  **`OK §14.9.17.3 1)`** (GO TO's real rule), while `--check 14.9.20.1 "INITIALIZE statement provides the ability
  to set selected data items"` → **`OK §14.9.20.1 (General)`** — the clause the emitter names is INITIALIZE.
* `--check 14.9.14.4 "CYCLE phrase causes control to be passed to an implicit CONTINUE statement immediately
  preceding the END-PERFORM"` → **`OK §14.9.14.4 5) b)`**; `--check 14.9.14.4 "EXIT PARAGRAPH statement causes
  control to be passed to an implicit CONTINUE statement"` → **`OK §14.9.14.4 6)`**. `StatementEmitter.cs:140`
  cites **GR6** for EXIT PERFORM CYCLE — GR6 is EXIT PARAGRAPH; CYCLE is GR5b.
* `--check 14.9.39.2 "Format 7 (data-pointer-assignment)"`, `"Format 4 (condition-setting)"`,
  `"Format 5 (object-reference-assignment)"` → all three **`OK §14.9.39.2 (General formats)`**. A format ORDINAL
  is not a quotation, so `--check` can never catch this class on its own — see the repair.
* SEARCH, both halves of the collision: `--check 14.9.37.4 "If index-name-1 is specified in the INDEXED BY phrase
  in the OCCURS clause associated with identifier-1, the index referenced by index-name-1 is the search index"` →
  **`OK §14.9.37.4 3)`** (Format 1 — what `SearchBinder` implements), while `--check 14.9.37.4 "Any other indexes
  associated with identifier-1 remain unchanged by the search operation"` → **`OK §14.9.37.4 8)`** (Format 2 —
  what `SearchBinder` CITES). `--check 14.9.37.4 "control is transferred according to the rules for that
  statement"` → **`OK §14.9.37.4 1) b) 2.`**

**The repair is not 40 edits (CLAUDE.md rule 5).** Three structural pieces:

1. **A citation belongs to the SITE, not to the message string.** The shared EXIT/GOBACK/RAISE path already
   threads the verb; thread `(verb, clause)` as one value so a message physically cannot name another verb's
   clause. Same for the OO SET tail (`OoBinder.cs:942` appends a CONSTANT "SR12" sentence to every rejection on
   that path, so an SR10 violation prints two rule numbers, one of them wrong — see the SR-14.9.39.3-10 row).
2. **A citation LINT that resolves the ordinal, not just the quote.** `scripts/spec/cite.py --check` validates
   TEXT; a wrong FORMAT number or a wrong GR number inside a right clause is invisible to it. Extend the existing
   `scripts/spec/audit_doc_citations.py` over `.cs`, `.g4` and `.cob` comments to resolve `§<clause> Format <n>`
   against the general-format list the spec's own `<clause>.2` carries, and `§<clause> GR<n>/SR<n>` against the
   rule list — failing on a mismatch. **Make it fail once against the sites above before fixing them.**
3. **The banner check that already paid off.** The `// VERB (§14.9.N)` ↔ spec-heading match, run above by hand,
   found the two survivors; it is four lines of Python and belongs in the same lint.

## THE SIBLING SWEEP THE FIXER MUST DO

* Every message string in the tree that contains `ISO §` or `ISO 14.` and is produced by a path serving MORE THAN
  ONE verb — the EXIT/GOBACK/RAISE family is the one measured, but the arithmetic, MOVE and SET binders share
  screens the same way (`ArithmeticBinder`'s `Receivers(…, clause)` parameter is the right pattern: it is already
  a parameter, it is simply passed a coarser value on the SUBTRACT arm).
* Every `Format <n>` in `src/` and `tests/`, not just §14.9.39's: the ordinal drift is a 2002→2023 renumbering
  artefact and any clause whose formats were renumbered carries the same risk.
* Both SEARCH goldens and the three test files, since a corrected src comment beside an uncorrected golden banner
  re-seeds the error on the next read.
* `docs/` — rule 6 makes every doc describe the current compiler; a design doc that inherited "Format 4" for the
  pointer slice will re-seed all eighteen sites.
