# PB2531 — the git common dir is computed in four places

## Measured (wave 1033 group W, 2026-10-07, branch `gate-perf`)

`grep -rn "git-common-dir" scripts --include=*.py` outside self-tests and comments, after kb/Work PB2527 added
`scripts/gate_slot.py#git_common_dir` (used by `slot_dir` and by `run_gate_legs.py` for the shared timings store):

- `scripts/spec/impacted_tests.py:114` — `Path(git("rev-parse", "--git-common-dir"))`, for the impact-map store
  `<git common dir>/cobol-impact`;
- `scripts/spec/record_impact_map.py:79` — the same expression, for the same store;
- `scripts/orchestrator/account.py:165` — `git -C <repo> rev-parse --path-format=absolute --git-common-dir`.

Each resolves a relative answer differently (two rely on their own `git()` helper's cwd, one asks git for an absolute
path), so a fix to the rule in one (a relative path under a linked worktree, `GIT_DIR` set in the environment) misses
the others.

## Shape

ONE helper: move `git_common_dir(repo)` to a small shared module the spec, gate and orchestrator scripts may all import
(not `gate_slot.py`, which the spec scripts should not depend on), make `gate_slot.py` and the three sites above call
it, and delete their copies (CLAUDE.md rule 4: no forwarders). A drift test: no `--git-common-dir` call under `scripts/`
outside that module and the self-tests that build repositories on purpose.
