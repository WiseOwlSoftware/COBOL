## Landed 2026-10-03 (wave-1005 implementer E)

Re-probed on a fresh Debug build: sr5_occ_grp and sr5_sub_occurs_ok reproduced (COBOLNET0899 on the receiver, COBOLNET1756 on the sender).

**Cause.** `ReferenceResolver.PlaceForItem`'s Tier-B arm asked `BuildBackingPath(sc)` for the backing, which built the canonical's parent path with NO subscripts and so returned null for any canonical below an OCCURS. The emitter was never the gap: `PhysicalModel.BuildPhysicals` already declares the class's string backing as a field of the canonical's containing struct, seeded by the canonical's VALUE, so every occurrence of an enclosing table already owned its backing.

**Fix.** The reference's subscripts split at the canonical: the LEADING `canonical.Parent.SubscriptArity` ones select the enclosing element and build the parent path (`BuildBackingPath(cls, outerIndexExprs)`, now an instance method so the element path carries the same §13.18.38.4 GR7 OCCURS DEPENDING check as every other element path), and the trailing ones are the in-class levels the window displacement already used. The arity check is `outer + in-class` (§8.4.2.3.3 SR3 through `SubscriptArity`, the one count). `RefResolution.cs`'s description of `DeferredShape.NestedClassBacking` now names what is still deferred.

**Spec (cite.py --check OK).** §13.18.44.3 SR5 sentence 2, §13.18.44.4 GR1 and GR2.

**Golden.** `conformance:85/pb1279_redefines_within_occurs` — two OCCURS levels with a VALUE seed, a group view, MOVE / INITIALIZE / reference modification / PERFORM VARYING over the views, a table inside the redefined group, and an OCCURS DEPENDING table. The rule is edition-invariant (the same sentence is X3.23-1985's), so no negative exists below it. A table SORT whose subject sits in such a class under an OCCURS (`SortBinder`'s `ResolveItemAt` guard) now resolves and sorts correctly (probe o4).

**Rows.** GR-13.18.44.4-1 and GR-13.18.44.4-2 close (CONFORMS). SR-13.18.44.3-5 stays OPEN under PB1281: its sentence 3 (a subscripted data-name-2 in the REDEFINES clause) is rejected under the wrong rule (COBOLNET1654 instead of SR5 S3).

**Remainder.** A string-canonical class under an OCCURS **DYNAMIC** table is still `DeferredShape.NestedClassBacking` (COBOLNET0899 on the receiver, COBOLNET1756 on the sender): a dynamic element is reached through sending / receiving accessors (`RenderPath(..., AccessDir.Receiving)` grows and seeds), and every `RedefViewPlace` write arm in `PlaceRenderer` renders its backing with `AccessDir.Sending`. Repro: `05 T OCCURS DYNAMIC CAPACITY IN C FROM 2 TO 5. 10 A PIC X(4). 10 B REDEFINES A. 15 B1 PIC X(2). 15 B2 PIC 99.` then `MOVE "ab12" TO A(2)`.
