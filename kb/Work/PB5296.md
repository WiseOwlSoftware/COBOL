# PB5296 - a debugging section for a data item runs when the statement does not explicitly reference it or does not change it: SET condition-name TO TRUE fires the conditional variable's section, and ADD ... ON SIZE ERROR that left the item unchanged fires its bare (change) section

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/Bound/DebugTriggerPlanner.cs` (`PlanLeaf`)

**Mechanism.** ALL REFERENCES OF identifier-1 runs the section "for every statement that explicitly references identifier-1" (GR5), and an explicit reference is one where "the name of the referenced item is written in a Procedure Division statement" (§1985:IV.4.4.1); the bare form runs it after a statement "that explicitly references and causes the content of the data item referenced by identifier-1 to be changed" (GR6). `PlanLeaf` takes every place of the lowered statement, and SET condition-name TO TRUE carries its conditional variable as a receiver, so an implicit reference counts (IF and EVALUATE on the same condition-name rightly fire nothing). And `PlanLeaf` asks only whether the statement names the item as a receiver, so an ADD whose ON SIZE ERROR left the item unchanged (§1985:VI.6.4.2) still fires; docs/CONFORMANCE.md D-DEBUG-DATA (1) chose that from GnuCOBOL, and the 1985 text decides it.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids below. None of them is recorded: the non-conforming verdicts wait in `E:/COBOL-coord/scratch/coderead-85/p2-for-register.json`.
