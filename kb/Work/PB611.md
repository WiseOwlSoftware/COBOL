# PB611 — OPEN — one phrase, five specifiers, one wired

Found 2026-09-05 by the `PB237` implementer after rendering PDF page 334 (§12.3.8.2); re-derived on this tree.

## The rule

§12.3.8.2's general format carries `[AS literal-n]` on every specifier (CLASS literal-1, INTERFACE literal-2,
PROGRAM literal-3, PROPERTY literal-4/5, FUNCTION literal-5 — render the page to confirm the numbering); §12.3.8.4
GR2 (`cite.py --check 12.3.8.4 "If the AS phrase is specified, literal-1, literal-2, literal-3, or literal-5 is
the externalized name by which the class, interface, function, or program, respectively, is known to the
operating environment."` → run it first) gives the phrase its meaning: the externalized name.

## The mechanism

`CobolParserCore.g4#repositoryEntry`: the `PROGRAM` alternative takes `repositoryAsPhrase?` (PB237); the CLASS,
INTERFACE, PROPERTY and FUNCTION alternatives do not, so the phrase is a parse error there. The reason PB237 did
not widen the grammar is the right one and bounds the fix: each specifier's externalized name is consumed by a
different subsystem (class/interface resolution in the OO binder, the user-function table in `BinderDriver`,
the property mapping), and a parsed-but-unbound `AS` would silently substitute the COBOL word for the
externalized name GR2 assigns — a wrong answer worse than today's rejection. The `repositoryParagraph` g4
comment records this.

## Fix shape

One mechanism per specifier, each binding its externalized name where that specifier is resolved (the
FUNCTION twin already keys its table by externalized name, so it is the cheapest); a positive golden per
specifier proving the externalized name is what reaches the operating environment (a function definition
whose PROGRAM-ID/FUNCTION-ID differs from the referencing word, resolved through `AS`), and the existing
`pb237_program_prototype` golden as the PROGRAM control. Row `FMT-12.3.8.2` (unadjudicated, owned by no note)
closes on the full set.
