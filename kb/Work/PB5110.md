# PB5110 - delete the custom merge drivers; one file per entry instead

**Owner (2026-11-10):** "I continue to fail to understand why we need our custom merge drivers. Multiple developers submit
changed files all the time. Sometimes those changes affect common files. Git merges them when there's no conflict and raises
a merge error to be resolved when there is a conflict. No custom merge drivers are required. This seems a far better design."
Asked whether to file it: "I want it ASAP."

**Sites:** `scripts/merge_drivers.py` (whole: the DRIVERS registry, `merge`, `config_args`, `attributes_tree`, the drivers),
`.gitattributes` (the `merge=cobol-*` block), `scripts/orchestrator/enqueue.py` (`driver_file_holders`, `merge_main`,
EXIT_DRIVER_FILE_QUEUED), `scripts/orchestrator/land_lane.py` (`driver_files_free`), `tests/version-matrix/constructs.json`
(whole), `kb/Work/` (layout), `scripts/spec/work.py` (the note reader), `src/WiseOwl.Cobol.Runtime/RuntimeAbi.pin`,
`src/**/PublicAPI.*.txt`, and every caller of `merge_drivers.py merge` (finisher brief, units, skills).

**Why the drivers exist, and why they lose.** PB3610 added them because two branches that each APPEND to one file (a work note)
or each ADD an entry beside the same neighbour (constructs.json, a PublicAPI baseline, the ABI pin's counters) make git stop
on a conflict whose answer is always "keep both", and each stop cost a finisher (~100 k tokens and a re-gate). But GitHub's
merge queue runs plain git with no drivers, so PB3642 had to hold any branch that shares a driver-covered file with an open
pull request (exit 16, DRIVER FILE QUEUED). That hold is a standing source of waits, and on 2026-11-09 it produced a false hold:
#1444's file list was cut off at 100 by GitHub, and `driver_file_holders` assumed it changed every driver file of the branch
(notes-pb5099 and worktree-wf_14a80b82-683-1 were held on PB5099.md and PB5060.md, which #1444 never touched). The repository
already found the better shape and says so in merge_drivers.py's own docstring: "A REGISTRY OF ENTRIES NEEDS NO DRIVER WHEN
EACH ENTRY IS A FILE (kb/Work PB4147)"; splitting the diagnostics registry and the inventory one file per entry removed 71 of
the landing lane's 79 holds.

**The decision.**
1. Work notes: a finding, lead or landing paragraph added to an existing note after it is filed is a NEW FILE beside it (for
   example `kb/Work/PB5083/2026-11-10-confirm-85.md`), which `work.py` reads as part of the note; the note file itself is edited
   only for its own frontmatter (status, closes_rows) and by its owner. Two branches then never edit one file for an append, and
   a real frontmatter clash is a real conflict git should raise.
2. `tests/version-matrix/constructs.json`: one file per construct (the inventory's shape, `inventory_store.py`), with its readers
   and the generated `ConstructRegistry.g.cs` moved in the same change.
3. `RuntimeAbi.pin` and `PublicAPI.*.txt`: plain git. They change only with the compiler surface; a conflict there is resolved by
   regenerating (the pin's drift test and RS0016/RS0017 catch a wrong resolution).
4. Delete `merge_drivers.py`'s drivers and `merge`/`config_args`/`attributes_tree`, the `.gitattributes` block, the DRIVER FILE
   QUEUED hold and `driver_files_free`; every merge is `git merge`, the same here and in the merge queue. Rule 4: no shim, no
   compatibility path; every caller changes in the same change.
5. Migrate the existing appended paragraphs only where a test or reader needs it; history stays in git.
6. **Batch compaction (owner addition, 2026-11-10, relayed by Mythos at 00:37).** One file per entry keeps the file count
   growing, so a compaction step folds the per-entry files back into fewer files, for example a note's addenda into the note
   itself. It runs only when nothing else is in flight on those files: no open pull request and no live worktree touches any
   file it would fold. So the file count stays small and the compaction can never create a merge conflict. It is a command
   (a `work.py compact` subcommand, or a script beside `inventory_store.py` for the other registries) that lands through
   `enqueue.py land` like any branch. It reads the open pull requests' changed files from git (fetch each head and diff it
   against its merge base, never GitHub's file list, which stops at 100), and the live worktrees from `git worktree list`.
   A self-test plants an in-flight touch and checks that nothing is folded, and plants a quiet registry and checks that it
   folds. The fold leaves `work.py`'s rendered note text unchanged.
A drift test refuses a new `merge=` attribute and a registry file that two entries share.
`enqueue.py`'s DRIVER FILE QUEUED hold, `driver_file_holders` and `land_lane.driver_files_free` (item 4) were already
deleted by PB5109 (branch fix-same-file-hold), so this note's implementer starts with that part done.
