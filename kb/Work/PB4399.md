# PB4399 - The stall watchdog does not outlive a long wave

**Sites:** `.claude/skills/workstream/templates/MANDATORY-PRACTICES.md` row O8 (start
`tools/claude-skills/skills/agent-fleet/references/stall_watch.py <transcript dir>` with `run_in_background` right
after the Workflow call), `scripts/orchestrator/units/wave.md` step 3 ("run stall_watch.py beside it as the skill
says"), and the Bash tool's background limit (`timeout` at most 7,200,000 ms).

**Witness.** Wave 20261808 (run `wf_01545e8c-f44`) started at 08:55 PST on 2026-11-01 and returned at about 15:00
(21,953 s, 48 agents). The unit started the watchdog with the maximum background timeout. The harness killed it at
2 h, about 10:55, with the Workflow still running. The watchdog's log was empty because it was killed, not because it
exited on a stall. The tool's own note says not to restart a command already at the maximum timeout, so the remaining
4 h ran with no O8 watchdog. During that time group A's fix agent sat in 9-minute `gate.py --await` loops for over two
hours, which is exactly when a watchdog is wanted.

**Mechanism.** O8 assumes the watchdog lives as long as its Workflow. A loop unit can only start it as a background
Bash task, and those end at 2 h, while PB3638's 60-minute STOP-UNIT lets the running Workflow finish, so a wave with
whole-population tooling gates (group A's Conformance alone took 5,718 s) outlives the watchdog by hours.

**Fix (pick the one mechanism, delete the other).** Either the watchdog's own process re-arms (a `--until-file
<workflow output>` mode that exits only on a stall or on the Workflow's result, started by a wrapper the unit re-runs
on each 2 h expiry, with the unit text saying to re-run it), or the supervisor's stall detection (orchestrate.ps1
already logs a PROGRESS line every 10 minutes and posts each stalled item to the operator, PB3638) is the loop's only
watchdog and O8 and wave.md step 3 stop asking a loop unit to start one. The second is one mechanism per job and
needs no restart rule; either way a drift test should hold the unit text and O8 to the chosen one.
