# PB814 — OPEN — the RAISING phrase can name an interface, and the compiler says it cannot

Filed 2026-09-09 by the registrar (second pass) from the **PB365 implementer's report** ("New defects" (b)) —
`scratchpad/reports/PB365-report.md`. **Re-probed on this worktree's own build at `d3ba5795`.**

## The measurement

```
$ cobol.exe p07_raising_iface.cob --std 2023
error COBOLNET0858: PROCEDURE DIVISION RAISING PBRI1: not an exception-name or a class of the compilation group
  (ISO §14.2.2 SR7–SR9; interface names are a later refinement of the EC-OO wave)
exit=70
```

(`registrar2/probe/p07_raising_iface.cob` — a program whose REPOSITORY declares `INTERFACE PBRI1` and whose
procedure-division header is `PROCEDURE DIVISION RAISING PBRI1.`, with the interface defined in the same
compilation group. The source conforms.)

**The diagnostic cites the very rule it violates.** COBOLNET0858 names §14.2.2 SR7–SR9 and then refuses SR9's
own alternative — a green-looking, deliberate-looking refusal of legal COBOL
(`feedback_green_test_can_hold_a_gap_open`).

## The rule, quoted, with the `--check` line actually run

```
$ python scripts/spec/cite.py --check 14.2.2 "Interface-name-1 shall be the name of an interface specified in the REPOSITORY paragraph."
OK  §14.2.2 9)  (Syntax rules)
    9) Interface-name-1 shall be the name of an interface specified in the REPOSITORY paragraph.
```

And the printed general format carries the alternative — measured from the PDF, not read off the transcription
(`feedback_spec_diagrams_render_pdf`):

```
$ python scripts/spec/clause_page.py 14.2.1     ->  PDF page 557   printed folio 527
$ python scripts/spec/figure_extract.py 558     ->  exception-name-1
                                                   . ... _RAISING_ [ _FACTORY_ OF ] object-class-name-1
                                                   interface-name-1
```

Three alternatives, one of which is `interface-name-1`.

## Expected vs observed

| | expected | observed |
|---|---|---|
| `PROCEDURE DIVISION RAISING <interface-name>` | accepted; SR9 checks the name is an interface in REPOSITORY | COBOLNET0858, compile fails |
| `METHOD-ID … RAISING <interface-name>` | same | same |

## Code site

- `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/EcBinder.cs#EcAddPdRaisingWord` (`:237`) — the program /
  function procedure-division-header arm.
- `src/Cobol.Net.Compiler/Binding/DataBinder.Oo.cs` — the METHOD-ID partition, **the second arm**: both sites
  carry the same "later refinement" comment, so a fix to one leaves the other refusing the same source
  (`feedback_two_arm_dispatch`).

## What is actually left to write

[[PB365]]'s landing introduced ONE class-name / interface-name resolution funnel
(`src/Cobol.Net.Compiler/Binding/Oo/OoNameResolution.cs`, `Want.Interface`), so the **lookup already exists**.
What remains is the §14.9.18.3 SR4 / §14.9.14.3 SR5 propagation check's interface leg — and that leg is
unreachable from the other end too, which is [[PB815]]. **The two are separable but must be sequenced**: landing
this one alone makes the header spellable while the operand end still cannot name an interface.

⚠ **PB365 is in flight (train 25).** The probe above runs on `main` at `d3ba5795`, where the refusal is
unconditional; the funnel this note relies on arrives with that landing.

## Inventory

`SR-14.2.2-9` carries **no verdict** and state **GAP**; this note claims it. No verdict is changed.

## Sibling sweep the fixer owes

`RAISING` is written in five places — the procedure-division header, METHOD-ID, EXIT, GOBACK and RAISE — and
§14.2.2 SR7–SR9 govern the header form only. Enumerate which of the five admit an interface-name under their own
rules before writing the screen, and write the admission once.
