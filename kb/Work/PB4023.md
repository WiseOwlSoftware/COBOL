# PB4023 — the step name is the first key, not `name:` first

**Sites:** `tests/WiseOwl.Cobol.Tests.Unit/LandingPipelineDriftTests.cs:220` (`StepsThatCanFailTheJob`; its doc comment at lines 212-213).

**What.** The doc comment says a step is named by its `name:`, else its `id:`, else its `uses:`. The code takes the first of
those keys in TEXT order. A step written `- uses: x` then `name: Y` is named `x`, not `Y`, so the failure message and any
name-keyed allowance (the `continue-on-error` check) name the step differently from the comment.

**Failure scenario.** A step whose `uses:` precedes its `name:` is reported (or allowed) under its `uses:` value, so an
allowance written by `name:` does not match it.

**Fix shape.** Resolve the name in the documented precedence (`name:`, else `id:`, else `uses:`) whatever the key order,
with an arm that puts `uses:` before `name:`; or change the comment if text order is intended, and say why.
