# PB4890 - the screen entry's name slot holds no gated word, so a reserved name is reported as a missing CONSTANT

**What the report says (the implementer's words).** A reserved word as a screen item's name draws "expected CONSTANT". Flags:
misleads_diagnosis. Repro: `E:/COBOL-coord/scratch/w20261887h/p2/c22.cob`, `SCREEN SECTION.` then `01 SCREEN LINE 1.` draws
`COBOL5506: The word LINE is not expected here: expected CONSTANT` where WORKING-STORAGE and the report slot draw COBOL0901.

**Mechanism.** `screenName` (`cobolWord | FILLER`) carries no `reservedGatedWord`, so `constantEntry` is the loop's sole
surviving alternative in `screenSection` and the diagnostic names the wrong fault. The same implementer's PB4818 note records
that the screen loop "is covered if that changes".

**Not probed here.** The clerk ran nothing; re-run the repro against a fresh build first.

**Sites:** `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolScreen.g4` (`screenDescriptionEntry`; rule `screenName` deleted), and the readers of the screen entry's name, now `dataName()`: `src/WiseOwl.Cobol.Compiler/Binding/ScreenFacility.cs` (`ScreenFacility.ReportSection`), `src/WiseOwl.Cobol.Compiler/Validation/LevelNumberPass.cs` (`EntryName`), `src/WiseOwl.Cobol.Frontend/Cst/ClosedFormats.cs` (`EntryAwaitingItsName`), `src/WiseOwl.Cobol.Compiler/Oo/OoExpansion.cs` (`SlotOf`: a `dataName` under `screenDescriptionEntry` is the screen-name slot); doc comments in `src/WiseOwl.Cobol.Frontend/Parsing/CobolParserCoreBase.cs` (`entryNameHere`, `ReadingParses`) and `src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs` (`IsProvableUserWordPosition`).

**Re-probe (fresh Debug build at fe01e3195e).** `c22.cob` (`01 SCREEN LINE 1.`) at 2002 and 2023: `COBOL5506: unexpected 'LINE'. The word LINE is not expected here: expected CONSTANT`; the WORKING-STORAGE twin `01 SCREEN PIC X.` draws `COBOL0901: 'SCREEN' is a reserved word`. Reproduced.

**Fix.** §2023:13.17.2 prints `level-number [ entry-name-clause ]` and the entry-name clause is §2023:13.18.20, the rule the data and report group entries read (§2023:13.18.20.4 GR1 names screen items). The screen arm now reads `dataName` behind the same `entryNameHere(RULE_screenDescriptionBody)` predicate as `reportGroupEntry` (kb/Work PB4889), and the private `screenName` rule is deleted, so the one entry-name rule makes the next admitted word automatic here. The predicate is needed: COLUMN, COL, COLS, COLUMNS and NATIONAL are reservation-gated words that begin a screen clause, and without it `05 COLUMN 5 VALUE "A".` would read COLUMN as the name and draw COBOL0901 on conforming source.

**After.** `01 SCREEN LINE 1.` and `01 CRT LINE 1.` at 2002/2023: COBOL1560 (section, LINE clause) and COBOL0901 naming the word; at 85 CRT names the item (COBOL1560 only). `05 COLUMN 5`, `05 COL 5` (85 too), `05 COLS 5`, `05 NATIONAL PIC N(3) ...`: the clause's COBOL1560, no COBOL0901.

**Sibling sweep.** Every rule beginning with `levelNumber` (`grep -rn "levelNumber" Grammar --include=*.g4`): `dataDescriptionEntry`, `reportGroupEntry` (both had the predicate), `constantEntry` (`dataName?`, CONSTANT follows), now `screenDescriptionEntry`. The other definition slots without `reservedGatedWord` (`conditionName`, `indexNameList`, `reportName`) were probed with CRT at 2002/2023: each draws COBOL0901 already (the error strategy's ReservedWordUse).

**Adjudication.** `tests/WiseOwl.Cobol.Tests.Unit/EditionReadDriftTests.cs` records the new edition read (`CobolScreen.g4 | screenDescriptionEntry | entryNameHere`, WordStatus), as PB4889 did for the report entry.

**Goldens.** `conformance-suite/cases/13.17-Screen-description-entry/pb4890-screen-entry-named-by-a-reserved-word` (refused 2002/2014/2023, COBOL0901) and `pb4890-screen-entry-named-by-a-free-word-at-85` (refused 85, COBOL1560 the SCREEN SECTION); unit `ScreenFacilityConstructDriftTests.AReservedWordAsAScreenEntrysName_IsRefusedByName_AsInWorkingStorage` (every §2023:8.9 screen-surface word at every edition) and `AClauseAReservedWordBegins_IsNotReadAsTheScreenEntrysName`; `ReadingParsesFollowDriftTests` now finds `screenDescriptionBody`.

## Landing

- `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolScreen.g4#screenDescriptionEntry`: the screen entry's name is `dataName` behind `entryNameHere(RULE_screenDescriptionBody)`; never reintroduce a screen-only name rule (it loses `reservedGatedWord` and the COBOL0901). Trap: a new `entryNameHere` site is a front-end edition read, so `EditionReadDriftTests` must record it (WordStatus).
- `src/WiseOwl.Cobol.Compiler/Binding/ScreenFacility.cs#ReportSection`, `Validation/LevelNumberPass.cs#EntryName`, `Frontend/Cst/ClosedFormats.cs#EntryAwaitingItsName`: read `dataName()` of the screen entry.
- `src/WiseOwl.Cobol.Compiler/Oo/OoExpansion.cs#SlotOf`: a `DataNameContext` whose parent is `ScreenDescriptionEntryContext` is the screen-name slot.
- `tests/WiseOwl.Cobol.Tests.Unit/ScreenFacilityConstructDriftTests.cs`: `ScreenEntryNameCases` derives the 8.9 screen words from the grammar scrape; reuse it for any screen name-slot theory.
