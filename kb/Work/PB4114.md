# PB4114 — the partition bound has no warning before the merge queue

## What happened

`ConformancePartitioningDriftTests.TheSuiteRunner_KeepsItsPartitionCount_AndBoundsEveryPartition` fails when a
conformance-suite partition would hold more than 500 rows (kb/Work PB2527). On 2026-10-30 the merge group of #811
(17b-15) went red on it on both operating systems (run 41107427092): "the suite has grown to 12005 rows, 501 per
partition at 24 partitions (bound 500)". The branch's own gate had passed, because its base had fewer rows, and a branch
is gated at its head while the merge with main is the merge queue's to test (owner 2026-10-23, kb/Work PB3612). So the
bound, a property of main plus a branch, can be crossed only in the merge queue, and every golden-adding landing bounced
until the count was raised to 32 (tooling-suite-partitions).

## What is still missing

1. **No warning before the cliff (review R1-1).** At 32 partitions the bound returns at 16,000 rows, about five weeks
   away at the measured ~110 rows a day. Nothing says the suite is approaching it. The fix should make the next crossing
   impossible to meet in the merge queue: either a shape that grows the partition count with the suite (rule 5: the next
   case automatic, with a drift test that it stays so), or a warning that fires on main well before the bound (for
   example the session probe printing rows against `Partitions × 500` and a check that goes red at 90 %, on a commit of
   main where the operator can raise the count before any landing bounces).
2. **The 32-partition leg was not re-measured (review R1-2).** The drift test's own message says "raise
   ConformanceSuiteTestsBase.Partitions, add the partition classes and slots, and re-measure". The re-measure is owed:
   record the Conformance leg's per-partition durations at 32 (a gate run's trx, or the shared timings store) in
   `docs/rearchitecture/DESIGN-test-build-ci.md` §3.11.1, whose other rows all carry measured durations.

**Sites:** `tests/WiseOwl.Cobol.Tests.Conformance/ConformancePartitioningDriftTests.cs#TheSuiteRunner_KeepsItsPartitionCount_AndBoundsEveryPartition`,
`tests/WiseOwl.Cobol.Tests.Conformance/ConformanceSuiteTests.cs#ConformanceSuiteTestsBase`, `tests/_shared/TestPartitioning.cs` (whole: the slot ladder grows with the partition count),
`scripts/session-probe.ps1` (whole: if the warning goes there, a new line of its report), `docs/rearchitecture/DESIGN-test-build-ci.md` §3.11.1.

## Retired 2026-10-30: folded into PB4146

The owner approved a partitioning redesign the same afternoon (kb/Work PB4146, the Mythos lane): derive
`ConformanceSuiteTestsBase.Partitions` from the row total (floor 24), generate the partition classes and slots, and make
the drift test guard coverage and measured balance instead of total size, for the optional-word sweep too. That removes
the cliff item 1 above describes and carries the re-measure of item 2, so this note is retired into it rather than
kept as a second register entry for the same work.
