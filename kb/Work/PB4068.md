# PB4068 — the PB3581 assertion cannot see a multi-line run block

PB3581 is landed; this note owns the hole in its guard. Code on the branch `worktree-wf_484eb705-564-18` (PR #777, tip 9c0c240a0, PB3819); `tests/_shared/CiWorkflow.cs` is NOT on origin/main yet.

## Lead (verbatim, E:/COBOL-coord/scratch/reports/w20261752f-PB3819-report.md)

> R1-2 LEAD (low, not blocking at round 1): tests/WiseOwl.Cobol.Tests.Unit/SelfTestDiscoveryDriftTests.cs:235 The PB3581 negative assertion
> (no self_tests.py in windows-build-test) reads RunCommands, which by its own doc comment leaves out every `run: |` block, so a self-test
> run added to windows-build-test as a multi-line run block passes it; the rewrite kept the old RunLines hole although the new reader,
> which now puts the PB3581 banner on the job below it, makes the whole-job check possible.

## Mechanism and fix shape

`Assert.DoesNotContain("self_tests.py", string.Join("\n", RunCommands(jobs["windows-build-test"])))` reads single-line `run:` values only.
The job's `Code` (as the next assertion already uses for `windows-self-tests`) covers the whole job. Check the whole job text, comments
excluded; a drift arm adds a `run: |` block naming the script to the job and expects the assertion to fail.
