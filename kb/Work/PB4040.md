# PB4040 — test-numval-f-trailing-sign-accepted: TEST-NUMVAL-F returns 0 for a sign after the significand ("123.45+"); ISO returns the sign's position

Filed 2026-10-29 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-20261028-210601`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

Under `-std=cobol2014`, `FUNCTION TEST-NUMVAL-F("123.45+")` and `FUNCTION TEST-NUMVAL-F("123.45-")` return 0 (valid).
The NUMVAL-F argument format allows a sign only before the significand (and the required sign of the exponent after
`E`), so a sign that follows the significand is the first character in error and ISO requires its position, 7.
libcob's validator accepts one sign anywhere after the first digit when no leading sign was written. Class: wrong
output. Found by the differential fuzz run fuzz-20261028-210601: fz02860 (`ERR10` for "123.45+", `ERR11` for
"123.45-": GnuCOBOL 0, 7 required).

## Expected result (per ISO)

§15.95.3 (checked): "Argument-1 shall be an alphanumeric or national literal or a data item of class alphanumeric or
national.", so each call is a valid TEST-NUMVAL-F reference whatever its content, and its result is defined.
§15.95.4 (checked): the returned value is 0 "If the content of argument-1 conforms to the argument rules for the NUMVAL-F
function", and "Otherwise, if one or more characters are in error, the position of the first character in error".
§15.69.3 (checked): "Argument-1 shall be an alphanumeric or national literal or data item whose content has the following
format"; the format (PDF page 928, rendered and read) is `[space-string] [+|-] [space-string] {digit [. [digit]] | .
digit} [space-string] [E [space-string] {+|-} [space-string] n [space-string]]`. The only sign positions are before the
significand and right after `E`; nothing may follow the significand except spaces and the exponent group, so in
"123.45+" the `+` at position 7 is the first character in error. Edition: NUMVAL-F and TEST-NUMVAL-F are already in
ISO/IEC 1989:2002 (its 15.56 and 15.77), and the 2009 committee draft for ISO/IEC 1989:2014 (CD 1.2, its 15.64.2 rule 1
and 15.88.3) gives the same sign-first format and the same returned-value rule, so the 2014 answer is the same. Expected
output:

```text
TRAILING-PLUS 0007
TRAILING-MINUS 0007
LEADING-MINUS 0000
```

## Our compiler

WiseOwl COBOL (fresh judge `E:\tmp\fuzz-judge-20261029\cobol.exe`, `--std 2014 --source-format free`): no diagnostic;
prints `TRAILING-PLUS 0007`, `TRAILING-MINUS 0007`, `LEADING-MINUS 0000`, exit code 0.

## Fix site

`libcob/intrinsic.c`, function `cob_check_numval_f`, called by `cob_intr_test_numval_f` (and by `cob_intr_numval_f`
only when libcob is built with `INVALID_NUMVAL_IS_ZERO`; by default 3.2's NUMVAL-F parses without this pre-validation).
In its second scanning loop (after the first digit or decimal point), the `'+'` / `'-'` case with no `E` seen accepts the
character as the significand's sign when no leading sign was seen (`plus_minus` is still 0). Per §15.69.3 a sign there
is in error: after the significand only spaces and the exponent group may follow. The function's own header comment
states the ISO format with the sign first.

## Draft issue

**Title:** TEST-NUMVAL-F returns 0 for a sign after the significand ("123.45+"); ISO returns the sign's position

Environment: GnuCOBOL 3.2.0, WSL2 Ubuntu x86_64; `cobc -x -free -std=cobol2014 -o p prog.cob && ./p`.

Program:

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. TNVFSGN.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 N PIC 9(4).
PROCEDURE DIVISION.
    MOVE FUNCTION TEST-NUMVAL-F("123.45+") TO N
    DISPLAY "TRAILING-PLUS " N
    MOVE FUNCTION TEST-NUMVAL-F("123.45-") TO N
    DISPLAY "TRAILING-MINUS " N
    MOVE FUNCTION TEST-NUMVAL-F("-123.45") TO N
    DISPLAY "LEADING-MINUS " N
    STOP RUN.
```

Observed: `TRAILING-PLUS 0000`, `TRAILING-MINUS 0000`, `LEADING-MINUS 0000`.

Expected: `TRAILING-PLUS 0007`, `TRAILING-MINUS 0007`, `LEADING-MINUS 0000`. ISO/IEC 1989:2023 §15.95.4 returns 0 only
when argument-1 conforms to the NUMVAL-F argument format and otherwise the position of the first character in error
(§15.95.3 admits any alphanumeric argument); §15.69.3 rule 1 allows a sign only before the significand and after `E`.
The 2002 standard and the 2009 committee draft of the 2014 standard have the same format and returned-value rules.

In `libcob/intrinsic.c`, `cob_check_numval_f` accepts a `+` or `-` after the first digit as the significand's sign when
no leading sign was written; that branch should return the position of the sign.
