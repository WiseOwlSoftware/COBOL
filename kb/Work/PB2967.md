# PB2967 — a binary64 result saturates silently into a 16-byte COMP-5 receiver

Filed 2026-10-10 by the train 1056 lander from the wave 1056 C implementer's report
(`E:\COBOL-coord\scratch\reports\w1056c-PB2918-report.md`, lead 3). Independent of PB2918 (A has 30 digits).

**Repro:** `E:\COBOL-coord\scratch\w1056c\var1.cob`: `COMPUTE R = FUNCTION VARIANCE(A, 1) ON SIZE ERROR ...` with
A PIC S9(30) VALUE 10^29 and R PIC S9(19) COMP-5 stores 2^127 - 1 (170141183460469231731687303715884105727) and takes
NOT ON SIZE ERROR. The variance is about 2.5E+57, which no 16-byte container holds. The same statement into a
PIC S9(18) receiver correctly takes ON SIZE ERROR.

**Site:** the float-to-fixed landing for a `BinaryCapacity` receiver (the `CobolFloat` to `CobolNum` store): the
observed value (exactly Int128.MaxValue) says the binary64 value is converted to the Int128 carrier with saturation
before the receiver's capacity test, so the saturated value passes as fitting (to be confirmed at the site).

**Why.** §14.7.5: a result whose value exceeds the largest value the resultant identifier can contain is the size
error condition; a silent clamp with NOT ON SIZE ERROR is a wrong answer. The fix is the same `WideningFits`-first
order PB639 gave the fixed-point landings: test that the binary64 value fits the carrier (and then the receiver)
before converting.
