# PB5696 - nothing bounds a probe's memory, and --run waits forever

**Harm: process-only.** One probe (PB5695) starved the host and killed another session's landing ("cannot start new thread",
exit 6). Gates running in that window may have shown infrastructure reds.

**Sites:** `src/WiseOwl.Cobol.Cli/Program.cs:424` (`Program.Run`); the conformance harness's runner is named by the fix once it finds it.

**Facts (observed).**
- `src/WiseOwl.Cobol.Cli/Program.cs`, the `--run` path (about line 426): `Process.Start(new ProcessStartInfo("dotnet",
  dllPath))` then `proc.WaitForExit()`, with no time limit and no memory limit.
- Nothing bounds the child's memory.
- The only bound that ended the incident was an agent shell's 300 s limit, not the tool's.

**What exists since 12:50 PST (interim, not the fix).** The operator session runs a watchdog (log
`E:/COBOL-coord/scratch/op-20261115/probe-memory-watchdog.log`) that kills a `dotnet.exe` or `cobol.exe` user-program process
whose commit passes 12 GB. Every fleet brief now carries a HOST SAFETY rule: no probe that exhausts storage; such a rule is
witnessed by a refusal, by the non-failing path, or reported not closable.

**Requirement (the design is the fix's, open).** A probe or test run on a shared host is bounded in memory and time by the
tool that starts it, not by each agent's care. For example, a job object or a runtime heap limit on the child that `--run`
starts, with a stated default and a switch, and the same bound in the conformance harness's runner. One mechanism for every
caller (CLAUDE.md rule 4). Open for the fix: the mechanism, the default limits, the switch's name and whether time and memory
share one switch.
