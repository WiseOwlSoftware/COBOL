# PB89 — LANDED 2026-08-18 — `SET ADDRESS OF BODO TO NULL` drew COBOL0001 "no viable alternative at input 'NULL'"

> ⚙ **flags:** rejects-legal-source (a parse error) · found 2026-08-18 writing PB80's golden (disassociating a
> based item to measure LENGTH r4a) · fixed in the same commit (DEVLOG 1308).

**Measured** (`--std 2023`): `SET ADDRESS OF BODO TO NULL` → `COBOL0001: no viable alternative at input 'NULL'`.
§14.9.39.2 Format 7 (data-pointer-assignment): `SET {ADDRESS OF data-name-1 | identifier-5}… TO identifier-6`;
SR19: identifier-6 "shall be the predefined address NULL or shall reference a data-pointer" — so TO NULL is legal
and disassociates the based item (its implicit data-address pointer returns to §13.18.5 GR2's initial NULL).

**Mechanism:** `setAddressStatement`'s receiver arm admitted only `TO dataReference`.

**Fix:** the arm is `TO (dataReference | NULL_)`; `PtrBinder.BindSetAddress` binds the NULL form as
`BoundSetAddressOfBased(based, Source: null)`; `PtrEmitter` assigns `ManagedPointer.Null`. Pinned by
`pb80_based_odo_group` (LENGTH answers the maximum again after the SET). Verdict SR-14.9.39.3-19 → CONFORMS.
