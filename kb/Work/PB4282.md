# PB4282 — the screen walk allocates a string per keyword token

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/WordCharacterScreen.cs:95` (`WordCharacterScreen.IsCandidate`; its two callers at :63 and :82 in the screen walk).

## What happens

PB4240's change made `IsCandidate` read `token.Text` of every keyword token on the once-per-compile walk. An ANTLR `CommonToken` with no explicitly set text builds a new `string` from the input stream on each `Text` read, so a program of N keyword tokens allocates N strings to find the rare keyword spelled with an extended letter (§8.3.2.1 extended letters; PB4156). Not measured: the cost is linear in program size and once per compile, so it is probably small; measure it first (allocation count for the largest corpus program before and after) and file the figure on this note.

## Fix

Decide the extended letter from the start/stop indexes against the already-held character array (no string), or test the token's type before its text so only candidates read `Text`. Pair a measured benchmark witness with the change (the dotnet-engineering rule), not a wall-clock test. Sweep the other whole-token-stream walks that read `.Text` for the same shape.
