# PB2855 — OPEN — a bare `plan_wave.py --dry-run` plans as though no report exists

**Found by:** the resume unit of 2026-10-08 21:46 PDT, while deciding branch `worktree-wf_8750e914-ee4-1` (wave 1047 A).

## What happened
`python scripts/orchestrator/plan_wave.py --budget-points 3 --dry-run` (the form the module docstring and the
workstream skill give) printed `PB1941: held by dispatch w1045A, which has no report yet ... (plan_wave.py --release
that dispatch if it was aborted)`, and the same for PB2051. Both dispatches were answered: `w1045a-PB1941-report.md`
(18:04) and `w1047a-PB1941-report.md` (19:04, SPLIT) are in `E:\COBOL-coord\scratch\reports`. The same command with
`--reports E:/COBOL-coord/scratch/reports` planned PB1941 + PB2051 as wave 1048's finisher group A, which is what the
wave unit (it passes `--scratch {SCRATCH}`) would do. Following the first output would have meant a needless
`--release` of a ledger entry, and the preview's group list, costs and codes differed from the real plan.

## Mechanism
`plan_wave.py` main: `reports_dir = pathlib.Path(a.reports) if a.reports else (pathlib.Path(a.scratch) / "reports"
if a.scratch else None)`, and `load_reports(None)` returns `[]` without a word. Every report-driven step then reads
"no report": awaiting-landing exclusion (step 1), the held-by-dispatch answer test, and finishers (step 2).
`prune_worktrees.default_reports_dir()` already knows the default location (`<coord>/scratch/reports`).

## Fix shape
Default the reports directory to `<coord>/scratch/reports` (one helper shared with `prune_worktrees`, not a second
copy of the path), and refuse (or say loudly) when the directory is missing, instead of planning from nothing. A
`test_plan_wave.py` case: a dry run with no `--scratch` sees a planted SPLIT report as a finisher.
