# PB5383 - at --std 85 the CALL USING level rule reads the wrong item twice: a 66 RENAMES ... THRU item, which is a group, is accepted, and a reference-modified subordinate group, which is an elementary item, is refused COBOL0900

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs#GateStatement` (the call-using-group-any-level-2002 row: tests `IsGroup` and the level of the item behind the place)
- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CallBinder.cs#ScreenCallOperand` (the section half, correct)
- `src/WiseOwl.Cobol.Compiler/Binding/Model/Place.cs#DenotesGroupItem` (the group-item question of a reference, added by the fix)

**Mechanism.** The gate asks whether the item behind the operand's place is a group at a level other than 01 or 77. A RENAMES ... THRU item is level 66 and not flagged as a group, so it passes; a reference-modified place reports its base item, a level 05 group, so a reference-modified operand that is an elementary item is refused. kb/Work PB4305 introduced the gate and covers neither shape; PB4901 and PB4938 cover the section half only.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids below. Its row is recorded PARTIAL naming this note.

**Rules (1 claimed; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-SR-X.5.2.3-3` - `§1985:X.5.2.3 SR3` (read: PARTIAL, harm: under-rejects and rejects legal source): each USING operand "must be a level 01 data item, a level 77 data item, or an elementary data item". `§1985:VI.5.11.4 GR1`: "When data-name-3 is specified, data-name-1 is a group item". `§1985:IV.4.3.8.4.4 GR5`: "The unique data item is considered an elementary data item without the JUSTIFIED clause".

**Repro.** `E:/COBOL-coord/scratch/coderead-85/out-reread2/work-rr-06/call/u06.cob` (`66 W66G RENAMES WA THRU WG`, `CALL "SUBP" USING W66G`), `u15.cob` (`CALL "SUBP" USING WG(1:2)`, WG a level 05 group), `v01.cob` (both); `cobol.exe --std 85 --source-format fixed --run <file>`.

**Observed (the pinned compiler of `E:/COBOL-wt/coderead85-tree-b` (origin/main 8147f008b3; `git diff --stat 8147f008b3 origin/main -- src` is empty at 5237495315), rerun 2026-11-12; `E:/COBOL-coord/scratch/coderead-85/reprobe-85f/log.txt`).** u06 runs and prints `IN SUBP [ABCD]`. u15 is refused `COBOL0900: a CALL USING argument that is a group item with a level-number other than 01 or 77 requires COBOL-2002 (targeting COBOL-85) - the CALL USING argument 'WG', a group item at level 05`.

**Expected (from the 1985 text).** u06 is refused (a level 66 group is none of the three admitted kinds); u15 compiles and runs (a reference-modified item is elementary).

**Fix direction (root cause, CLAUDE.md rule 4).** Decide the operand's kind from the bound operand, not the item behind the place: a reference-modified operand is elementary, and a RENAMES ... THRU item is a group. Sweep the other edition gates that read `IsGroup` through a place (the same mistake would reach every "group item" rule).
