# PB91 — OPEN — `IF A * B > 5` past 10^38 under EC-SIZE-OVERFLOW checking compares a WRAPPED product

> ⚙ **flags:** wrong-answer, silent, RARE (needs a native product / sum past the Int128 carrier in a condition,
> argument or subscript with EC-SIZE checking enabled) · found 2026-08-18 landing [[PB75]] (which made the SDIDI
> carrier's overflow in the same positions a fatal EC — the native carrier's twin was out of that landing's scope).

**Measured (by reading, not yet a repro):** `NumericRenderer` emits `CobolNum.MulChecked` / `AddChecked` /
`SubChecked` (the §14.7.5 case-5 raise) only when `_rcv.InSizeError` — the ReceiverContext an ARITHMETIC statement
under ON SIZE ERROR / EC-SIZE checking renders in. A condition, a function argument or a subscript renders under
`ReceiverContext.None` (InSizeError false), so a native product past 10^38 wraps in binary (item 179 (1) documents
the wrap for the no-phrase / checking-OFF case) — also when `>>TURN EC-SIZE-OVERFLOW CHECKING ON` is in effect,
where §14.7.5 no-phrase rule 3 makes it EC-SIZE-OVERFLOW ("if an arithmetic operation on an intermediate data item
… would cause the new nonzero value to be farther from zero … than is allowed for the intermediate data item")
and §14.6.13.1.3 #4/#5/#7 the dispositions PB75 now gives the SDIDI carrier in those positions.

**Fix shape:** the checked kernels are selected by the STATEMENT's checking state, not only by the arithmetic
statement's phrase — `InSizeError` (or a sibling flag) must be true for every render under an EC-SIZE-enabled
statement (the binder knows: `EcWrap` queries the family for every statement since PB75), so a condition's product
raises `CobolSizeError` and PB75's guard dispatches it. Sweep: `AddChecked`/`SubChecked`/`MulChecked`, `DivideOrThrow`
(a zero divisor in a condition — EC-SIZE-ZERO-DIVIDE — is the same shape), `RescaleEscape` (already loud), the
`Pow` exact arm.
