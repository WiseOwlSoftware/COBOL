# PB3761 — the targeted Linux half runs no script self-test

**Sites:** `scripts/linux-gate.sh#selftests_leg`, `scripts/linux-gate.sh#audit_built_legs`, `scripts/linux-gate.sh#targeted_leg`.

Filed 2026-10-25 by the enqueue clerk from the R1-1 LEAD (low, not blocking at round 1) of PB3308's review. With `--legs targeted`, `scripts/linux-gate.sh` empties the audit order
(`[ "$targeted" = 1 ] && order=()`, about line 832) and skips the audit clone (about lines 857-860: "THE TARGETED LEG (kb/Work PB3612) runs no audit: the gate that started it ran them on Windows, and CI's `audits`
job runs them on Linux on every event"). So the Linux `selftests` leg that runs `scripts/self_tests.py` (PB2563) does not run in the implementer's gate, and the new
`scripts/install-dotnet-sdk.sh --self-test` (PR #594) has never run on Linux before CI. A shell self-test is the case where Windows and Linux differ most (CI invariant, owner 2026-10-04:
a CI red is also a defect in the local gates).

PB1957 still records the script self-tests as **(a), made identical** and run by the Linux gate (section on the script self-tests, PB2563). PB3612's targeted mode no longer does; a dated paragraph in PB1957 says so.
Related but different: PB3646 (the inert lane exits before the selftests leg).

## Fix direction
Either run the `selftests` leg in the targeted Linux half (it needs no build; `scripts/self_tests.py` discovers every self-test, and PB2914 lets the Windows half reuse a recorded PASS while inputs are unchanged), or, when the change touches a script
with a self-test, name that script's self-test as a targeted leg input. Pin it with the PB1957 job-to-leg drift test, then update PB1957's row. The choice is a cost decision (one Python start versus the audit clone), so measure first.
