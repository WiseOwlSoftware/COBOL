# PB407 — the GOBACK general format is written as an ordered stack where the standard prints choice indicators

**Row:** `FMT-14.9.18.2`. Adjudicated in lane-3 batch b2; **every measurement below was re-run on this
worktree's HEAD `cobol.exe` (base 89044aa0)**, not inherited from the pinned 5fe593a0 compiler.

## THE MECHANISM

`src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4:1360-1364` writes the whole statement as

```
gobackStatement
    : GOBACK ((RETURNING | GIVING) dataReference)? (raisingPhrase | statusPhrase)?
```

with `raisingPhrase` at `:1390-1392` (`RAISING (EXCEPTION cobolWord | LAST EXCEPTION | dataReference)`) and the
shared `statusPhrase` at `Core/CobolControlFlow.g4:352-354`
(`WITH? (ERROR | NORMAL) (STATUS (dataReference | literal)?)?`). Three distinct facts of the printed general
format are inverted by that one line, and none of them is a missing rule — the shape is wrong:

1. `(raisingPhrase | statusPhrase)?` says **at most one phrase, in a fixed order**. The printed figure puts the
   two phrases inside CHOICE INDICATORS (the `| … |` bars) enclosed by a bracket, which means zero or more of
   them, each at most once, in any order.
2. `STATUS (dataReference | literal)?` makes `STATUS` **required before an operand**. It is not underlined on
   the printed page, so it is an optional word.
3. `LAST EXCEPTION` requires both words. Only `LAST` is underlined; the trailing `EXCEPTION` is not.

The root cause is inherited, not invented, and it is still readable in the tree: the comment at `:1361-1362`
says the two are "the mutually-exclusive §14.9.18.2 tail alternatives", and
`docs/rearchitecture/PHASE-13-wave-c-scout.md:724` records the reading the grammar was written from
("status vs raising are MUTUALLY EXCLUSIVE in the format braces — grammar must NOT allow both"). ⚠ **The spec
SSOT has since been corrected and the grammar was never re-derived from it**: `specs/ISO_COBOL.md` §14.9.18.2
now carries explicit figure notes recording the choice indicators, the un-underlined `STATUS`, and the
un-underlined second `EXCEPTION` (with the measured x-offsets), and the transcription ledger row at
`specs/ISO_COBOL.md:47217` records the page-661 underlining correction.

## THE RULE, QUOTED, WITH ITS `--check` LINE

- `python scripts/spec/cite.py --check 5.2.6.4 "When enclosed by brackets, zero or more of the alternatives"`
  → `OK §5.2.6.4 (Choice indicators)`. §5.2.6.4: "When enclosed by brackets, zero or more of the alternatives
  contained within the choice indicators shall be specified, but any single alternative may be specified only
  once." and "The alternatives may be specified in any order."
  (`--check 5.2.6.4 "The alternatives may be specified in any order"` → `OK §5.2.6.4`.)
- `--check 5.2.3 "not underlined in general formats"` → `OK §5.2.3 (Optional words)`. §5.2.3: "Optional words
  are reserved words or context-sensitive words. They are shown in uppercase and not underlined in general
  formats."
- `--check 7.3.21.4 "as though a GOBACK RAISING LAST statement were executed"` → `OK §7.3.21.4 2)`. The
  standard's own PROPAGATE rule writes the phrase back with `LAST` alone, third-party evidence that `LAST` is
  the operative word and `EXCEPTION` after it is optional.
- `--check E.3.3 "This only takes effect when the GOBACK statement appears in a COBOL main program"` →
  `OK §E.3.3 32)` — the annex item that introduced the status phrase, and the one that says it is the STOP
  statement's phrase, which is why the grammar shares one rule for both verbs (see the sweep).

§14.9.18.2 itself is a FIGURE; it is cited here for the format, and the underlining facts are quoted from the
transcription's own measured figure notes rather than re-asserted.

## THE CODE SITE AND THE SHAPE OF THE REPAIR

- `CobolParserCore.g4:1360-1364` — the statement rule and its stale comment.
- `CobolParserCore.g4:1390-1392` — `raisingPhrase`; `LAST EXCEPTION` must become `LAST EXCEPTION?`.
- `Core/CobolControlFlow.g4:352-354` — the shared `statusPhrase`; `STATUS` must become `STATUS?`.
- `src/Cobol.Net.Editions/ConstructRegistry.g.cs:24` and `tests/version-matrix/constructs.json:127-131` — the
  `goback-returning-2002` row, whose `citation` field names a clause of the GOBACK statement for a phrase that
  clause does not contain. `docs/rearchitecture/DESIGN-SPEC-RECONCILIATION.md:82` (row 24) already recorded the
  mis-citation; nothing acted on it, and no register note owned it until this one.

⛔ **Not the smallest diff (CLAUDE.md rule 5).** `(a | b)?` cannot express "zero or more, each at most once, any
order" — the correct ANTLR shape is a repeated alternation with a duplicate check, e.g.
`gobackStatement : GOBACK ((RETURNING|GIVING) dataReference)? (raisingPhrase | statusPhrase)* ;` with a
"specified only once" screen at the bind site citing §5.2.6.4 — and the CHOICE-INDICATOR pattern should be
written once and reused, because §14.9.18.2 is not the only figure that uses the bars. A hand-written
`if (both) error` at the GOBACK binder is the shape to avoid; the next format that acquires choice indicators
must not need a second one.

The RETURNING/GIVING phrase is an **owner decision, not a code question**: either it is dropped at 2002+ with a
diagnostic, or it stays as a documented extension gated on the strictness axis like every other latitude
(`dialect_two_axes`) — but the registry row must stop citing a GOBACK clause as its authority either way.

## SIBLING SWEEP the fixer must do

1. **`statusPhrase` is SHARED with `stopStatement` (`Core/CobolControlFlow.g4:341`)** — so the required-`STATUS`
   bug is a two-verb bug. §14.9.42.2's figure notes record the same un-underlined `WITH`/`STATUS` for STOP, and
   **measured on HEAD**: `STOP RUN WITH ERROR 5.` → `COBOL0001: no viable alternative at input '5'` +
   `COBOL0308`. One rule, one fix, two verbs — do not fix GOBACK alone.
2. **EXIT Format 2 carries the same `raisingPhrase`.** The `LAST EXCEPTION` underlining fact is measured on the
   EXIT figure too (transcription ledger row `specs/ISO_COBOL.md:47216`, page 653), and `raisingPhrase` is the
   same grammar rule, so `EXIT PROGRAM RAISING LAST.` inherits the fix automatically — add a golden for it so
   it stays inherited.
3. **RAISE** also takes a raising-shaped operand; check whether `RAISE LAST EXCEPTION` spellings are affected.
4. Every edition: the four rejected spellings must be checked at `--std 2002/2014/2023` after the fix
   (`feedback_edition_gate_sweep`), because the status phrase is 2023-gated and RAISING is 2002-gated.
5. Goldens ship with the fix: one per rejected spelling above plus the two controls, so a later "simplify the
   grammar" edit that re-collapses the alternation fails.
