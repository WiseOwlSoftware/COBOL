# PB2499

Filed by the w1033 clerk from the PB259 refuter (`E:\COBOL-coord\scratch\w1033-adj\PB259-refute.md`, section 1), which OVERTURNED
the decision's CONFORMS for `FMT-14.9.1.2`. This note now holds that row (moved from `PB259`).

**Mechanism.** The mnemonic arm of `acceptSource` is `dataReference` (`src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4#acceptSource`,
about lines 1856-1864), which admits subscripts, reference modification and qualification (`cobolWord dataReferenceSuffix*`, lines
681-709). `AcceptDisplayBinder.cs#BindAcceptFromMnemonic` reads only `mnemonic.cobolWord()` and drops every suffix without a word.
This is the two-arm shape: `displayUpon` spells its mnemonic as `cobolWord` and refuses the suffix (COBOL0307), `acceptSource`
ignores it.

**Expected from the spec (cite.py --check OK, per the refuter).**
- `§14.9.1.2` Format 1: `ACCEPT identifier-1 [ FROM mnemonic-name-1 ] [ END-ACCEPT ]`; the slot is a mnemonic-name.
- `§8.3.2.2.16`: a mnemonic-name identifies an implementor-defined device-name, feature-name or switch-name, established in
  SPECIAL-NAMES; it is a word, not a data item.
- `§8.4.2.2.2`: no qualification format qualifies a mnemonic-name. `§8.4.2.3.3 2)`: a subscript needs a data description with
  OCCURS; `§8.4.3.3.1`/`.2`: reference modification applies to an identifier.
- `§4.2.2`: a warning mechanism for violations of the general formats and explicit syntax rules.

**Observed (pinned build `pin-97006f3`, exit 0, NO diagnostic, program runs; every edition, also with `--flag-extensions`).**
Probes in `E:\COBOL-coord\scratch\w1033-adj\PB259-refute\src\`: `MA1.cob` `ACCEPT WS-X FROM MYIN (1).` (`GOT=[B   ]`), `MA2.cob`
`... FROM MYIN OF WS-G.`, `MA3.cob` `... FROM MYIN (1:1).`, `MA6.cob` `... FROM MYIN IN MYIN.`, `MA7.cob` `... FROM MYIN (1) END-ACCEPT.`
Controls: `MA5.cob` `FROM MYIN.` clean (correct); `MA4.cob` `FROM DATE (1).` COBOL0307; `MD1.cob` `DISPLAY 'X' UPON MYOUT (1).` COBOL0307.
Repro MA1 (SPECIAL-NAMES `SYSIN IS MYIN.`, `01 WS-G. 05 WS-X PIC X(4).`):

    ACCEPT WS-X FROM MYIN (1).
    DISPLAY 'GOT=[' WS-X ']'.

**Sibling (refuter, same mechanism).** `MS1.cob`: with `SWITCH-1 IS MYSW ON STATUS IS SW-ON.`, `SET MYSW (1) TO ON.` compiles clean and
prints `ON` at 2002 and 2023. Same mechanism in SET Format 3 (switch-setting); its row `FMT-14.9.39.2` is recorded CONFORMS and
is to be re-checked when this lands. (SET's binder site is not named in the refuter file; the implementer locates it.)

**Fix direction (refuter).** Spell the slot as the word, as `displayUpon` does, or refuse any suffix by name at bind. Witness: a
negative golden per suffix kind (subscript, ref-mod, qualification) for ACCEPT and for SET. Harm is low: the suffix is ignored, the
data comes from the named device, nothing is miscompiled; it is a silent acceptance of syntax that violates the general format.
The row closes CONFORMS when this lands, on the A.4.2 reasoning in PB259 (Format 3 declined and refused).

## Landing (wave 1037 group D)

Re-probed on the w1037d build (`E:\COBOL-coord\scratch\w1037d\probes\`, copies of the refuter's MA1-MA7, MD1, MS1 plus
MS2 and the WRITE sibling MW1-MW4): MA1/MA2/MA3/MA6/MA7 ran rc=0 printing `GOT=[BXYZ]`, MS1 printed `ON`, MS2 (`SET MYSW
OF WS-G TO ON` / `SET MYSW (1:1) TO OFF`) printed `OFF` - the note held. Now every one is COBOLNET2269 at 85, 2002, 2014
and 2023, naming the mnemonic-name and the rule; MA5 (`FROM MYIN`), MS3 (`SET MYSW TO ON`) and MW4 (`ADVANCING MYTOP`)
still compile and run.

**The four mnemonic-name-1 slots, every arm answered.** ACCEPT (14.9.1.2 Format 1), DISPLAY (14.9.11.2 Format 1),
SET Format 3 (14.9.39.2) and WRITE Format 1 (14.9.51.2) are the only procedure statements that print one (spec grep).
- `src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4#acceptSource` / `#setSwitchPhrase` - the slot is `cobolWord`, as
  `displayUpon` already was; a suffix is a syntax error.
- `src/Cobol.Net.Frontend/Parsing/CobolErrorStrategy.cs#MnemonicSuffixMessage` - re-codes that syntax error as
  COBOLNET2269 from the parser state: the just-completed `acceptSource` / `displayUpon` context ending right before the
  '(' / OF / IN, or the SET statement whose suffixed list ends at `TO ON|OFF`. Priority 0, so the misleading COBOL0307
  "a period may be missing" hint no longer rides along. (DISPLAY UPON's suffix was a bare COBOL0307 before.)
- `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/SequentialIoBinder.cs#MnemonicOperand` - WRITE's slot shares
  identifier-2's `dataReference`, so the registry is asked about the reference's WORD (it used to key on the whole text,
  so `ADVANCING MYTOP (1)` fell through to the data resolver and drew COBOLNET1639 "'MYTOP (1)' is not defined" for a
  declared name); `BindAdvancing` refuses the suffix. The SR13 LINAGE screen asks the same helper.
- `src/Cobol.Net.Frontend/Parsing/MnemonicNameSlot.cs#SuffixMessage` - the ONE message both layers use. REUSE it for
  any new mnemonic-name slot.
- `AcceptDisplayBinder.BindAcceptFromMnemonic` / `SetAlterBinder.SwitchBindSet` now take the word (`CobolWordContext`),
  so there is no suffix left to drop.
- Trap: ANTLR reports SET's failure as NoViableAlt "cannot parse construct near 'ON'" (the furthest token the
  prediction reached), so the SET arm keys on the statement's token run, not on the offending token.
