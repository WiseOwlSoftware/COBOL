**Rule it breaks:** DESIGN-listing.md section 6.6 (the data map states what the compiler decided for each item) and ListingDataItem own contract (OccursMin is the minimum number of occurrences, OccursMax 0 for a table of dynamic capacity); §2023:13.18.38.4 GR16/GR17 make integer-4 the minimum capacity and integer-5 the expected capacity of a Format 4 table. The renderer ignores the documented sentinel, so the text and HTML data maps misstate the table.

**Scenario:** 05 T PIC X OCCURS DYNAMIC CAPACITY IN C FROM 5 TO 100. binds to OccursSpec{Min=5, Max=0, IsDynamic=true, ExpectedMax=100} (DataBinder.Odo.cs:75-79); SymbolTableFinish.cs:232-233 copies Min/Max only, DataMapBuilder.cs:76 passes them on, and DataMapText.DetailParts (Text/DataMapText.cs:118-121) prints 'OCCURS 5 TO 0' because min != max. OCCURS DYNAMIC with no FROM gives min 0 = max 0 and prints 'OCCURS 0', a table of no occurrences. Neither row says DYNAMIC and TO 100 (integer-5) is lost; the HTML data map renders the same DetailParts, and a JSON reader must know the 0 sentinel to tell a dynamic table from a fixed one.
