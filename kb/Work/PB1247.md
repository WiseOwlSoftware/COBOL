# PB1247 — OPEN

## Measured

**line-clause** — The report heading and report footing presentation (CobolReport.PresentHeadingFooting) has no unpaged arm: in a report that is not divided into pages it places a relative first line with the paged formulas (HEADING + integer-2 - 1, FOOTING + integer-2) over the RD's zero page regions, instead of LINE-COUNTER + integer-2.

- **Repro:** RD R-FL. (no PAGE clause) / 01 RH-A TYPE RH LINE PLUS 3 (COLUMN 1 VALUE 'RHEAD') / 01 DET-A TYPE DE LINE PLUS 1 / 01 RF-A TYPE RF LINE PLUS 2; INITIATE, GENERATE DET-A x3, TERMINATE (probe E:/Temp/claude/E--CobolSharp/a700c052-f9e4-4942-84ff-a13c7505d6ec/scratchpad/adj-d1/out13/probe/line-clause/rh3.cob; also rf.cob, rf2.cob).
- **Expected (spec):** 13.18.35.4 5) c): the first line of each group = LINE-COUNTER + integer-2. RHEAD on line 3 (0+3), DET on 4/5/6, RFOOT on line 8 (6+2), lines 1-2 and 7 blank.
- **Observed:** RHEAD on line 2 (0+3-1), DET 3/4/5, RFOOT on 6 (0+2 = 2, at/above the cursor, pushed down one line by PresentLine's overlap seam). With RF LINE PLUS 5 after three details RFOOT lands on 5 instead of 9. Paged RH/PH/body/PF/RF placement was verified exact (pg.cob), so only the unpaged heading/footing path is wrong. PresentBody already has the `_paged` branch (GR5 c) for body groups, pb484) - this is the two-arm shape: the unpaged arm was added to one of the presentation methods and not to the other.
- **Code site:** src/Cobol.Net.Runtime/IO/ReportWriter.cs#CobolReport.PresentHeadingFooting (the first-line target expression, lines ~999-1004)
- **Clause (adjudicator):** ISO/IEC 1989:2023 13.18.35.4 5) c) (cite.py --check OK)

**line-clause** — CobolReport.PresentLine forces a one-line advance whenever a line's target is at or above the physical cursor (`if (advance < 1 && _physLine != 0) advance = 1;`) and then records the TARGET, not the physical line, as _physLine. A relative line with integer-2 of zero therefore never overprints the preceding line, and every later line of the report prints one physical line below its line number.

- **Repro:** Unpaged RD; 01 DET-A TYPE DE. 02 LINE PLUS 1. 03 COLUMN 1 PIC X(3) VALUE 'ABC'. 02 LINE PLUS 0. 03 COLUMN 5 PIC X(3) VALUE 'XYZ'. GENERATE DET-A twice (probe E:/Temp/claude/E--CobolSharp/a700c052-f9e4-4942-84ff-a13c7505d6ec/scratchpad/adj-d1/out13/probe/line-clause/ov.cob).
- **Expected (spec):** 13.18.35.4 3): 'the non-space characters of a relative line specified with an integer-2 of zero will overwrite the corresponding characters of the preceding line'; 7) b) + 7): the new line number is LINE-COUNTER + 0 and 'the line is now printed on the page at that vertical location'. Output: two lines, 'ABC XYZ' / 'ABC XYZ'.
- **Observed:** Four lines: 'ABC' / '    XYZ' / 'ABC' / '    XYZ'. LINE-COUNTER is right (1 after the first GENERATE) but the second group's line 2 prints on physical line 3, so the physical page and the line numbering disagree from the first zero-advance on. How the overprint is realized on the print stream (a zero-advance record, or merging into the pending line image) is the implementer's design choice; the forced advance is not a conforming one.
- **Code site:** src/Cobol.Net.Runtime/IO/ReportWriter.cs#CobolReport.PresentLine (line ~1050)
- **Clause (adjudicator):** ISO/IEC 1989:2023 13.18.35.4 3) and 7) (cite.py --check OK); 13.18.35.3 3) 'Integer-2 may be zero.'

### Refuter evidence — row `GR-8.4.3.15.4-4` (PARTIAL)

PARTIAL — GR4's first sentence requires LINE-COUNTER to equal the page line on which each line is printed. §13.18.35.3 SR3 permits LINE PLUS 0 ('Integer-2 may be zero'), and §13.18.35.4 GR3 gives it overprint semantics on the preceding line. PresentLine sets LineCounter = target but forces a physical advance of 1 when advance < 1 (the overlap seam), then records _physLine = target. A PLUS 0 line is therefore printed one line below the line LINE-COUNTER names, and every later line of the page is one line lower than LINE-COUNTER says. The second half (the final value after a group, and NEXT GROUP taking over) does hold on the adjudicator's probes. Because one half is broken, the verdict is PARTIAL.
