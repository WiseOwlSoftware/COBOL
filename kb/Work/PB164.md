# PB164

Re-homed from PB133's mechanism (7): `CallEmitter.ArgText` loud-stages a CALL argument group whose leaves
are not `IsImageCapable`, and `OperandText`/`PlaceRenderer`/`RecordStructEmitter` hold the same Tier-C
island posture for MOVE/REDEFINES/records — conforming source throws at RUN time.

**The COMP-5 half is pure predicate drift**: `PicInfo.ByteForm`'s own doc (written after V59) says COMP-5
and BINARY-CHAR..DOUBLE "are excluded from the IMAGE by their BinaryCapacity discipline … never by their
representation: stating the form here is what makes admitting them a WIDTH question, not a representation
question" — their `ByteForm = Binary` and `StorageWidth` are pinned, `CobolNum.FormatImage`'s Binary lane
renders full container values through the Int128/UInt128 bits contract, and `IsImageCapable`'s leaf arm
(`Usage.Display or Usage.Binary or Usage.Packed`) simply never widened. The landing must move in LOCKSTEP
across every consumer — `DataItem.IsImageCapable` + `ElementaryImageWidth`, `PhysicalModel`'s own usage
filter (a second copy of the predicate — the [[feedback_two_arm_dispatch]] shape), `GroupImageCodec`,
`OperandText`, `PlaceRenderer`, `SortBinder`, `OoBinder`'s group-conformance arm — with a
`BYTE-LENGTH`/image drift test pinning the widened set.

**The FLOAT half needs a new pin**: COMP-1/COMP-2 leaves have no `NumericByteForm` member — an IEEE 754
big-endian 4/8-byte image form (`Ieee32`/`Ieee64`) with FormatImage/ParseImage lanes over the float
carriers (which do not ride the Int128 lane), plus the same consumer sweep.

**The INDEX half is an owner decision**: `NumericByteForm.None`'s doc deliberately makes a codec handed a
USAGE INDEX item reject loudly (§13.18.60.4 GR10 — an occurrence-number carrier only SET may reference).
A group CONTAINING one that crosses CALL BY REFERENCE is conforming source; pinning index bytes (e.g.
8-byte binary occurrence number) versus keeping the documented loud is a §4.2.16 documentation choice —
ask as a bare question when this lands.

**Consolidated from PB148 (2026-08-29):** the DISPLAY-side legs of the same island — (a) `DISPLAY G`
over a group with a float/COMP-5/INDEX leaf throws the Tier-C loud on legal source (GR-14.9.11.4-4's
PARTIAL residue); (b) the VARIABLE-LENGTH-GROUP display format (§14.9.11.4 GR7 + Annex A.1 item 57 —
a REQUIRED documented determination; GR-14.9.11.4-7 NOT-IMPLEMENTED) — the natural format is the fixed
prefix plus each dynamic leaf at its CURRENT length / dynamic table at current capacity, the same sum
`IntrinsicBinder.VariableLengthGroupSum` computes for FUNCTION LENGTH under §15.50.4 r7; add the A.1
item-57 CONFORMANCE.md row WITH the format; (c) TierCIsland.Reason's default leafKind string blames
'float/COMP-5/INDEX' even for a variable-length group — fix the message with the mechanism; (d) the
GR-14.9.11.4-6 sum-of-sizes residue for such operands closes with (a)/(b).
