## Measured

### Finding occurs-clause-p1 — §13.18.38.3 SR29 (wrong-answer; rows SR-13.18.38.3-29)

**Mechanism.** Format 4's integer-4 / integer-5 have no specified maximum and are parsed with `int.TryParse`, whose failure silently DROPS the phrase; values above the runtime cap CobolDynTable.MaxOccurrences (0x3FFF_FFFF) are accepted and give capacity 0

**Repro.** `05 T PIC X OCCURS DYNAMIC CAPACITY IN C FROM 1073741824.` then `DISPLAY C` (out13/probe/occurs-p1/sr29_max_plus1.cob -> 0000000000); `FROM 99999999999 TO 99999999999999` (sr29_huge_from -> 0000000000); `FROM 1 TO 99999999999` (sr29_to_huge: TO silently ignored)

**Expected, from the standard.** §13.18.38.3 SR29: 'The implementor shall specify a maximum permissible value for integer-4 and integer-5. Their values shall not exceed this maximum value.' So the maximum is documented, and a value above it is a compile-time rejection.

**Observed.** No documentation (docs/CONFORMANCE.md has no row), no compile-time check, and the program runs with capacity 0 instead of the written minimum capacity.

**Code site.** src/Cobol.Net.Compiler/Binding/DataBinder.Odo.cs#OdoBindOccursSpec (`int.TryParse(ph.integerLiteral()?.GetText(), out ...)` for FROM/TO); src/Cobol.Net.Runtime/Values/Tables/CobolDynTable.cs#MaxOccurrences

### Finding occurs-clause-p1 — §13.18.38.3 SR30; §8.3.2.2 (under-rejects; rows SR-13.18.38.3-30)

**Mechanism.** The CAPACITY register's 'not defined elsewhere' test consults only the data-name index (ByName) and other registers, so a register spelled like a file-name (or paragraph-name) is accepted

**Repro.** `SELECT F ...` / `FD F.` plus `05 T PIC X OCCURS DYNAMIC CAPACITY IN F.` (out13/probe/occurs-p1/sr30_file.cob); a paragraph named C beside `CAPACITY IN C` (sr30_dup_para.cob)

**Expected, from the standard.** Rejection. §13.18.38.3 SR30: 'Data-name-3 shall not be defined elsewhere in the source element', and §8.3.2.2: 'a given user-defined word may be used as only one type of user-defined word'.

**Observed.** Both compile clean; a data-name duplicate is correctly COBOLNET1523. The paragraph-name case shares a cross-cutting §8.3.2.2 gap: an ordinary `01 C` plus paragraph `C` also compiles (sr30_general_para). The file-name case is SR30's own.

**Code site.** src/Cobol.Net.Compiler/Binding/DataBinder.Odo.cs#DynamicResolve (`ByName.ContainsKey(capName) || _capacityRegisters.ContainsKey(capName)`)
