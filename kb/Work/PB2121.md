# PB2121 — orphaned differential goldens are undetectable

Found by wave 1025 group A (PB2108, report `w1025a-PB2108-report.md`), filed by the train-1025 lander.

## Mechanism

`DifferentialGolden.Assert` (`tests/Cobol.Net.Tests.Conformance/DifferentialGolden.cs:45` `GoldenPath`, `:53` `Hash`)
names each golden by a content hash of `(edition, source)`. When a case's source is edited or a case is deleted, the
old `<hash>.out` stays on disk and nothing reads it. Until PB2108 the opt-in `COBOLNET_DIFF_MODE=bake` re-sweep was
the only path that rewrote the folder; it is gone with the legacy engine (R69), and
`DifferentialGoldenDriftTests` (`tests/Cobol.Net.Tests.Conformance/DifferentialGoldenDriftTests.cs:44`, `:56`)
checks only that each converted class has a non-empty folder and each folder maps to a class. A stale file is
therefore silent dead data (364 `.out` files in 42 folders on `4b8045980`).

## Repro

Edit any `[InlineData]` source of a `*DifferentialTests` funnel, commit the new golden the failing test names, and
leave the old one: every gate stays green and the old `.out` is never flagged.

## Fix shape (not done: needs a design choice)

The hash is computed at run time from the test's source, so a static scan cannot know the live set. Either record
every path `Assert` resolves during the Conformance run and compare it with the files on disk in a drift fact that
runs after the class's cases (xUnit collection fixture), or have the Delete census (PB2119) sweep it once. No user
program is affected; the cost is repository litter and a misleading golden count.
