# PB4567 - a hyphenated site file never resolves in fix_clusters

**Sites:** `tools/claude-skills/skills/agent-fleet/references/fix_clusters.py#sites`

`sites()` matches a path as `([\w./-]*?)([A-Za-z_]\w*(?:\.\w+)*?)(<ext>)`. The stem group admits no `-`, so for
`tests/version-matrix/reserved-words.json` the lazy prefix takes `tests/version-matrix/reserved-` and the stem is
`words`. `source_index` keys the file under its real stem, `reserved-words`, so the lookup misses. Measured
2026-11-03: with `--src tests/version-matrix --ext .cs,.g4,.json`, PB3600 (`constructs.json`) resolved and PB3957
(`reserved-words.json`) stayed unsited.

**Harm today.** None in the current population: no `.cs` or `.g4` file under `src/` has a hyphen in its name, and since
PB4566 an unsited note is planned as a group of its own anyway. It matters once the population takes a data root, and
for any other consumer of the public base.

**Fix.** Admit `-` in the stem (`[A-Za-z_][\w-]*(?:\.[\w-]+)*?`), add a hyphenated case to the base's eval, release the
base, and move the pin in every overlay that names it (`.claude/skills/{workstream,gate,review,spec-lookup,
architecture-review}/SKILL.md`), as kb/Work PB1699 requires: a practice improved here goes into the public base first.
