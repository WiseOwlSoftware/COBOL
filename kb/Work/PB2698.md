**Wave kind:** defect-for-fix-lane. Filed by the train 1042b lander. Train 1042's cluster F (PB2640/PB2641) wrote a
"more Int128.MinValue magnitude sites" paragraph into kb/Work/PB2639 while PB2639 was open on main; train 1042b then
landed PB2639 (cluster H), which fixed the `CobolNum` and edit sites (`PositionOf`, `TryStore`, `InBinaryRange`,
`WrapBinary`, `RescaleStoreCap`, `InPictureRange`, `CobolEdit`, `CobolLocaleEdit`) but not the intrinsic ones. So the
remaining sites would have been orphaned in a landed note; they live here.

**Sites (on the tree train 1042b leaves):**
- `src/Cobol.Net.Runtime/Intrinsics/CobolIntrinsics.Exact.cs:86` — `AbsScaled(Int128 v) => v < 0 ? -v : v`: for
  `Int128.MinValue` the negation wraps and FUNCTION ABS returns a NEGATIVE value. §15.7.4 (ABS returns the absolute
  value); the result does not fit the Int128 carrier at all, so the fix must decide the §14.7.5 / EC-SIZE disposition,
  not only swap in `CobolDec.UAbs`.
- `src/Cobol.Net.Runtime/Intrinsics/CobolIntrinsics.Exact.cs:473` — `Rescaled`: `Int128.Abs(unscaled) > limit`
  throws on MinValue. Probably unreachable today (the parsed significand is at most 38 digits), so the fix is
  `CobolDec.UAbs(unscaled) > (UInt128)limit` for robustness, with the reachability measured, not deduced.
- `src/Cobol.Net.Runtime/Intrinsics/CobolIntrinsics.Exact.cs:512` — `-p.Unscaled` feeding `CobolFloat.ScaledToSingle`
  (same bound as :473).
- `CobolNum.Divide` with exp < 0 and a divisor of `Int128.MinValue` takes the SDIDI through
  `CobolDec.From(Int128.MinValue, scale)` (a 39-digit significand), untested on the DivToOdd arm (F's lead).

**Repro shape:** a signed 16-byte `COMP-5` item holding LOWEST-ALGEBRAIC (the R2 batch 1 repro in PB2639), then
`COMPUTE R = FUNCTION ABS(X)` into an unsigned 16-byte COMP-5 receiver; expected 2^127 (or a size error by §14.7.5 if
the function's carrier is the limit), observed a negative intermediate.

**The one magnitude:** `CobolDec.UAbs(Int128) → UInt128` (train 1042b collapsed `CobolNum.Magnitude` and
`FloatResultant`'s private copy into it). Reuse it; do not add another.

## Landing

**Landed 2026-10-10 (wave 1052 E).** Every site re-probed on a fresh build before any edit (probes under
`E:\COBOL-coord\scratch\w1052e\`).

1. **ABS (`AbsScaled`, :86) — reproduced, fixed.** A signed 16-byte COMP-5 holding −2^127 reached `-v` = −2^127: `COMPUTE R
   = FUNCTION ABS(S)` into a `PIC S9(19) COMP-5` stored −1687303715884105728 (the low 19 digits of 2^127, negated) with
   `NOT ON SIZE ERROR` taken. The disposition the note asked to decide: |−2^127| = 2^127 is past the native intermediate
   data item (a scaled `Int128`, DOC-A.1-123), the §15.7.4 r1 b equivalent expression `(- (argument-1))` is exactly the
   negation that leaves it, and §14.7.5 r5 with the range CHECKED (DOC-A.1-179) makes that the size error condition, so ABS
   now goes through the file's one `SizeEscape` like MOD, SUM and RANGE. ⛔ A `UInt128` return (which would hold 2^127 for an
   unsigned 16-byte receiver) was designed and REJECTED: it changes a shipped public signature, an incompatible change of the
   runtime surface (`PublicAPI.Shipped.txt`, `RuntimeAbiPinDriftTests`), i.e. a runtime-major bump, which is an owner/ABI
   decision and not this note's. The accidental pre-fix result `U = FUNCTION ABS(S)` = 2^127 for an UNSIGNED receiver (via
   `UAbs` at the store) is therefore now the size error; the value-preserving `U = S` still stores 2^127 (golden
   pb2639). `ExactCarrierBoundaryDriftTests` no longer exempts `AbsScaled` (its premise, that `RescaleEscape` holds every
   argument at or below `Int128.MaxValue`, is true of a RESCALED argument only) and pins its boundary.
2. **Sibling arm found and fixed (I9): the unsigned-wide operand.** `Arg` passes a `NumX.U` operand through unlanded and the
   five unary exact arms (ABS, SIGN, INTEGER, INTEGER-PART, FRACTION-PART) handed its `UInt128` expression to `Int128`
   parameters: Roslyn CS1503 on conforming source (`FUNCTION ABS(U)` with `U PIC 9(19) COMP-5`). Each now has a U-named twin
   (`SignOfU`, `IntegerPartU`, `FractionPartU`; ABS of an unsigned operand is the operand, no call), additions to
   `PublicAPI.Unshipped.txt`, named and not overloaded (an int literal converts to both lanes, CS0121). Witness: golden
   `2023/pb2698_unary_functions_unsigned_wide_and_minimum` (U2 = 2^127+1 at scale 2).
3. **`Rescaled` (:473) and `-p.Unscaled` (:512) — measured UNREACHABLE.** The scan's `Unscaled` is a non-negative magnitude
   below 10^digitCap (the cap is tested before each digit; the emitter passes 31 or 34) and the sign is applied after, so
   `MinValue` cannot arrive. `Rescaled` nevertheless reads `CobolDec.UAbs` so the bound does not rest on that reachability;
   `CobolIntrinsicsMinValueTests` pins the largest admitted significand (34 nines) on both.
4. **`CobolNum.Divide`, exp < 0, divisor `Int128.MinValue` — probed, CORRECT.** The SDIDI arm (`CobolDec.DivToOdd` over
   `From(MinValue, scale)`) lands the tiny quotient on the right sign-dependent 0 or ±1 unit in every rounding mode;
   `CobolIntrinsicsMinValueTests.Divide_ByInt128MinValue_OnTheSdidiArm_…` pins 12 mode × sign rows.
5. **More sites of the same mechanism, found in files read (I9), fixed.** `CobolIntrinsics.PowNativeIntDec`
   (`CobolIntrinsics.RealArgs.cs`) took `Int128.Abs(b)`, which throws for a base of `Int128.MinValue` (the generated
   catch turned the `OverflowException` into a size error whatever the exponent): the magnitude is now `UAbs` in a `UInt128`
   loop; the powers of that base leave the carrier and take the documented double approximation. `Floor` / `Truncate` at a
   negative scale multiplied by 10^k unguarded; they now go through `ExactMul` (loud past the carrier).

**Sweep.** `x < 0 ? -x : x`, `Int128.Abs`, `-v` over a carrier in `src/Cobol.Net.Runtime`: the remaining `Int128.Abs`
sites read a `CobolDec.Sig` (an SDIDI significand, at most 34 digits by the decimal128 invariant PB2641's sweep recorded) or a
`rem` below a positive divisor.

**Leads left (not fixed, outside this slice):** (a) the SDIDI lift `CobolDec.From(container value)` of a 16-byte COMP-5 item
with more than 34 digits (or `Int128.MinValue`) violates the significand invariant its own `Int128.Abs` sites assume
(`COMPUTE R = S + 1` under `ARITHMETIC IS STANDARD-DECIMAL` with S = −2^127 is a size error where −2^127+1 fits `R`);
(b) the alphanumeric image of a binary item renders the byte 0xFF as U+FFFF while an `X"FF"` literal is U+00FF (`IF GX =
X"FFFFFFFE"` is false after `MOVE -2 TO S` for a `PIC S9(9) COMP-5` overlay).
