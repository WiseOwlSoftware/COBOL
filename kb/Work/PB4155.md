# PB4155 — LANDED (wave 20261780 G)

## Landing — a CALL argument's NULL at an edition that leaves the word free is the undeclared user word

**Re-probe** (`CALL "X" USING NULL`, then BY REFERENCE / BY CONTENT / BY VALUE / `USING W NULL`): at `--std 85` the bare form drew
COBOL0899 ("a keyword-less literal or expression argument belongs to the program-prototype CALL"), BY CONTENT / BY VALUE the same
code, and BY REFERENCE NULL COBOL1677 (the §14.9.4.3 SR3 address screen); at `--std 2002` the same five. The note named only the bare
form; the sweep found four positions answering about a predefined NULL the edition does not have.

**Verdict.** The one PB1673 verdict (§8.9 reserves NULL from COBOL-2002; at 85 it is an undeclared user word, §8.4.2.1, COBOL1639).
**Fix.** `CallBinder.NullSpellingOf` names the predefined NULL an argument writes in any of the four places the grammar lets it
(BY REFERENCE `predefinedNull`, and the operand `ConditionBinder.ReduceArgument` reduces BY CONTENT, BY VALUE and the bare argument
to), and `CallBinder.BindCall` asks `UnreservedKeywordReference.IsFreeAt("NULL", edition)` once per argument, before the Format-1
narrowing and the BY REFERENCE NULL screen, and reports `UnreservedKeywordReference.Report`. At 2002+ the diagnostics are unchanged
(§8.4.3.10.3 SR1 a) admits NULL as an argument only in a program-prototype format CALL).
**Golden.** `8.3.2-COBOL-words/pb4155-call-null-undeclared-at-85` (refused at 85, expect "'NULL' is not defined"); the 2002 half is the
accepted `pb1630_null_argument_crossing`.

# PB4155 — as filed

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CallBinder.cs` (`CallBinder.BindCall`, `CallBinder.NullSpellingOf`, `CallBinder.Format2OnlySpellingOf`).

A lead PB1673's landed note records only as "Not changed: `CALL "X" USING NULL` at 85 still draws CallBinder's Format-2-argument
diagnostic before any operand binds (reported as a lead)", and that PB1906's finisher report carries over ("CALL `USING NULL` at 85
(`CallBinder.cs:907`)"). No open note held it, so this is the item. PB1673 / PB1906 made every other NULL read at 85 (VALUE, CONSTANT,
DISPLAY, MOVE, STRING, relation, INITIALIZE BY NULL, SET) draw the §8.4.2.1 undefined reference through
`UnreservedKeywordReference.IsFreeAt("NULL", edition)` and `UnreservedKeywordReference.Report`, because §8.9 reserves NULL only from
2002; CALL's argument classifier asks first and draws a COBOL-2002 Format-2 wording that the target edition does not have.

Fix: ask `UnreservedKeywordReference.IsFreeAt("NULL", ctx.Edition)` in `CallBinder.Format2OnlySpellingOf` (or before it classifies the
bare argument) and report the one PB1673 verdict, then pin it with a refuse-at-85 negative beside
`8.3.2-COBOL-words/pb1673-set-null-undeclared-at-85`. Probe first: no repro file was recorded; `CALL "X" USING NULL` at `--std 85`
and `--std 2002` is the pair (at 2002 the current diagnostic must be unchanged).
