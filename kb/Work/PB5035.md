# PB5035 - an unconditional parse-tree walk in the margin-R screen

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/MarginRCutScreen.cs` (`MarginRCutScreen.Warnings`), `src/WiseOwl.Cobol.Frontend/Parsing/WordCharacterScreen.cs` (`WordCharacterScreen.HasCandidate`, the model guard)

**Found.** PB5024 review R1-2 (performance). `MarginRCutScreen.Warnings` (line ~35) runs `CommentEntryTokens.Of(tree)`, a walk
of the whole parse tree, on every parse, and uses the result only for a token the locator says ends at margin R. The
ordinary program has no such cut. The sibling `WordCharacterScreen.RunOnTokens` asks `HasCandidate(tokens)` first and
skips the walk.

**Owed.** Compute the comment-entry set lazily, on the first token whose `MarginRCutAt` reports `EndsAtMarginR`, or guard
with a cheap candidate test as the sibling does. Keep one shape for both screens (`CommentEntryTokens` is shared) so the
next screen takes the guard automatically. Pin it with a structural test (the walk does not run for a program with no
cut), not a timing limit.
