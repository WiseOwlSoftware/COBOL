# PB4519 — const-fold-power-overflows-long-long: Constant folding of literal ** literal overflows a 64-bit integer silently (2 ** 100 gives 0)

Filed 2026-11-03 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-batch-3000-20261103`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

cobc folds `literal ** literal` at compile time in a signed 64-bit integer (`long long`) with no overflow test, so a
power at or above 2**63 overflows silently: `2 ** 100` becomes 0, `2 ** 63` becomes -9223372036854775808 (a negative
value for a positive base), and `10 ** 30 / 10 ** 28` becomes 1.1337. The same power with a data item holding the same
base is evaluated exactly by cobc's run-time routine (`WS-B ** 100` gives 1267650600228229401496703205376). No
diagnostic, and an ON SIZE ERROR phrase on the COMPUTE is not taken. Signed overflow of a `long long` is also undefined
behaviour in C. Class: wrong output. A second mechanism in the constant-folding arm already recorded for `0 ** 0`
(`const-fold-zero-power-zero`); that note's fix (declining to fold a zero base) leaves this one. Fuzz night
2026-11-03: fz00213, fz00918, fz00920, fz00919, fz01623 (OUTPUT_DIFFERS:8.8.1.5.2) and fz00518, fz02632, fz02631
(OUTPUT_DIFFERS:8.8.1.4.2).

## Minimal test case

Free reference format (`-free`).

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. POWBIG.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 WS-B PIC 9 VALUE 2.
01 WS-I PIC S9(31) VALUE 0.
01 WS-R PIC S9(9)V9(4) VALUE 0.
PROCEDURE DIVISION.
MAIN-PARA.
    COMPUTE WS-I = 2 ** 100
    DISPLAY "LIT  " WS-I
    COMPUTE WS-I = WS-B ** 100
    DISPLAY "ITEM " WS-I
    COMPUTE WS-I = 2 ** 63
    DISPLAY "P63  " WS-I
    COMPUTE WS-R = 10 ** 30 / 10 ** 28
    DISPLAY "LITDIV " WS-R
    STOP RUN.
```

## Environment

`cobc (GnuCOBOL) 3.2.0` on WSL2 Ubuntu. Compiled with `cobc -x -free -std=cobol2014 -o p pow.cob` (no diagnostic other
than the distribution's `_FORTIFY_SOURCE` redefinition notice) and run as `./p`. Native arithmetic is in effect (no
OPTIONS paragraph); cobc 3.2 announces STANDARD-DECIMAL arithmetic as not implemented [-Wpending] and gives the same
three wrong values under it.

## Observed result

```
LIT  +0000000000000000000000000000000
ITEM +1267650600228229401496703205376
P63  -0000000000009223372036854775808
LITDIV +000000001.1337
```

Exit code 0.

## Expected result (per ISO)

- §8.3.3.3.2 4): "The value of a fixed-point numeric literal is the algebraic quantity represented by the characters in
  the fixed-point numeric literal." The literals 2, 100, 63, 10, 30 and 28 have those values.
- §8.8.1.3: "Native arithmetic is an implementor-defined method of evaluating an arithmetic expression", and "The
  implementor shall specify techniques used for native arithmetic." The standard leaves the native technique, and so
  the size of the native intermediate data item, to the implementor; §14.7.5 5) makes range checking of that
  intermediate the implementor's choice too ("if native arithmetic is in effect and the implementor defines that the
  range of values allowed for the intermediate data item is to be checked"). The standard alone therefore does not
  require these exact 31-digit results under native arithmetic. What makes the output wrong is cobc's own technique:
  its run-time evaluation of the same operation is exact (`WS-B ** 100` with WS-B = 2), and no documented technique of
  cobc wraps a positive power to zero or to a negative value. The constant-folding path departs from the technique the
  implementation otherwise applies, through a C signed overflow, and silently.

Expected (cobc's run-time technique, which the folding should match): `LIT  +1267650600228229401496703205376`,
`ITEM +1267650600228229401496703205376`, `P63  +0000000000009223372036854775808`, `LITDIV +000000100.0000`.
Edition: the rules cited are those of ISO/IEC 1989:2023 and are unchanged from the committee draft that became
ISO/IEC 1989:2014 (CD 1.2, 2009); the behaviour does not depend on the edition.

## Our compiler

WiseOwl COBOL (fresh judge, `--std 2014 --source-format free`) prints the exact values for the 2 ** 100, WS-B ** 100
and 10 ** 30 / 10 ** 28 lines, with no diagnostic (the 2 ** 63 line was added by the refuter and not run on WiseOwl).

## Fix site

`cobc/tree.c`, function `cb_build_binary_op`, the constant-folding branch for two numeric literals (guarded by
`cb_constant_folding`): in the `case '^'` arm the result is multiplied up in a `long long` (`rslt = rslt * xval` in a
loop) with no overflow test, then formatted with `CB_FMT_LLD`. Confirmed present in the 3.2 source. A fix declines to
fold when the product would leave the `long long` range, leaving the operation to the run-time routine
`cob_decimal_pow`. The `'*'` arm may share the pattern.

**Title:** Constant folding of literal ** literal overflows a 64-bit integer silently (2 ** 100 gives 0)

Environment: GnuCOBOL 3.2.0 (cobc), WSL2 Ubuntu; `cobc -x -free -std=cobol2014 -o p pow.cob`, then `./p`.

Steps: compile and run the program below.

Observed: `LIT  +0000000000000000000000000000000`, `ITEM +1267650600228229401496703205376`,
`P63  -0000000000009223372036854775808`, `LITDIV +000000001.1337`. No diagnostic; an ON SIZE ERROR phrase is not taken.

Expected: `LIT  +1267650600228229401496703205376`, `ITEM` the same, `P63  +0000000000009223372036854775808`,
`LITDIV +000000100.0000`. Native arithmetic is the implementor's technique (ISO/IEC 1989 §8.8.1.3, with range checking
of the intermediate optional per §14.7.5), and cobc's technique at run time is exact: `WS-B ** 100` (WS-B = 2) gives
the right value, while `2 ** 100` over the literal 2 (§8.3.3.3.2 rule 4: its value is 2) gives 0, and `2 ** 63` gives a
negative number.

In cobc/tree.c, cb_build_binary_op folds `literal ^ literal` by repeated multiplication in a long long without an
overflow check (signed overflow, undefined behaviour in C); 2**100 mod 2**64 is 0.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. POWBIG.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 WS-B PIC 9 VALUE 2.
01 WS-I PIC S9(31) VALUE 0.
01 WS-R PIC S9(9)V9(4) VALUE 0.
PROCEDURE DIVISION.
MAIN-PARA.
    COMPUTE WS-I = 2 ** 100
    DISPLAY "LIT  " WS-I
    COMPUTE WS-I = WS-B ** 100
    DISPLAY "ITEM " WS-I
    COMPUTE WS-I = 2 ** 63
```
