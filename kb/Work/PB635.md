# PB635 — OPEN — the wrong question at the float dispatch

Found 2026-09-05 by the `PB254` implementer (report §"New defects" (A)) while widening FIND-STRING's argument-3
intake; not fixed there because the dispatch it lives in is `RenderFloat`'s, which PB253 restructured on the same
day (train 6 row 1), and because adding a `FindStringReal` body would encode the wrong shape.

## Repro (`--std 2023`; `<a9d94900 scratch>/PB254/probe5.cob`)

```cobol
       01 FL USAGE FLOAT-LONG.
       ...
           COMPUTE FL = 1.0E19
           MOVE FUNCTION FIND-STRING(WS-HAY WS-NDL START AFTER FL) TO WS-P
```

```
error CS0117: 'CobolIntrinsics' does not contain a definition for 'FindStringReal'
```

The emitted line — `FindStringReal((double)(CobolNum.FromAlphanumeric(WS_HAY)), (double)(CobolNum.FromAlphanumeric(WS_NDL)),
CobolFloat.Sending((double)(FL)))` — is wrong three ways at once: a runtime body that does not exist, the two
string arguments converted to `double`, and the LAST/ANYCASE phrases dropped.

## The rule

§15.37.3 r1: "Argument-1 shall be a data item or literal of class alphabetic, alphanumeric, or national"
(`OK §15.37.3 1)`) — the function has no binary64 carrier at all; its only numeric argument is argument-3, an
integer (§15.37.3 r3, `OK §15.37.3 3)`), and a floating-point item at an integer position is either admitted by
§15.3 type 6 (PB248's screen decides) or rejected there — never a reason to move the whole call to the float lane.

## The mechanism

`src/Cobol.Net.Compiler/CodeGen/Emit/IntrinsicRenderer.cs`, `RenderNum` (`:159` on main after train 5):
`if (AnyRealArgument(ic) && sig.RuntimeMethod != "Factorial") return RenderFloat(...)`. The predicate asks "is ANY
argument floating" where the question is "is any argument IN A NUMERIC-CARRIER POSITION floating". Every function
whose catalog row mixes string-class positions with a trailing integer is exposed: FIND-STRING, SUBSTITUTE, CONVERT,
BASE-CONVERT, STANDARD-COMPARE — unswept, and `Factorial` is already a hand-written exception to the same predicate,
the shape [[one_rule_one_place]] warns about.

## Fix shape

Derive the predicate from the catalog: `AnyRealArgument` over the positions whose declared argument class is
numeric (the `IntrinsicCatalog` row already names each position's class — PB248's screen reads it), so a
string-position argument can never trip it and the `Factorial` exception disappears into the same derivation
(FACTORIAL's one position is an integer whose float form the screen rejects). Drift test: for every catalog row
with a string-class position, a program passing a FLOAT-LONG in its trailing integer position compiles to a call
of the row's own runtime method (or is rejected by PB248's screen with COBOLNET1627), never to a `...Real` name;
the emitted C# is the assertion, as in PB253's `StandardModeReturnedValueContainerDriftTests`. Goldens: FIND-STRING,
SUBSTITUTE and BASE-CONVERT with a float trailing argument at 2023 — positive where §15.3 type 6 admits the value
(an integral float, e.g. 2.0E0), negative where it does not.
