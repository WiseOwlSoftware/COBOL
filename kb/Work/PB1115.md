## The rule
> "If either the argument or the formal parameter is a universal object reference"
`cite.py --check 14.8.2.3.2 "If either the argument or the formal parameter is a universal object reference"` → `OK  §14.8.2.3.2 1)  (Elementary items passed by reference)`

## Measured (adjudicator / refuter evidence, verbatim)
### GR-14.8.2.3.2-1 (PARTIAL)
|| REFUTED: PARTIAL — The INVOKE and CALL AS NESTED/prototype arms enforce the rule at bind, but the third activation arm, a user-defined FUNCTION reached through a REPOSITORY function-prototype, has no bind-time check at all. A typed argument into a universal formal, or the reverse, compiles cleanly. It fails only at run time because the .NET carrier type happens to differ.
- **Code location (record):** src/Cobol.Net.Compiler/Oo/OoConformance.cs#DescriptionMismatch; src/Cobol.Net.Compiler/Binding/Model/ObjectRefDescriptor.cs#SameDescriptionAs; src/Cobol.Net.Compiler/Binding/Procedure/Verbs/OoBinder.cs#OoBindInvocationArg; src/Cobol.Net.Compiler/Binding/Procedure/Verbs/CallBinder.cs#BindCall

### GR-14.8.2.3.2-2 (PARTIAL)
|| REFUTED: PARTIAL — Same defect in the function arm. A class-typed argument into an interface-named formal of a user-defined function is not diagnosed at compile time, even though §8.4.3.2.3 SR13 applies. It fails at run time only through a carrier cast.
- **Code location (record):** src/Cobol.Net.Compiler/Oo/OoConformance.cs#DescriptionMismatch; src/Cobol.Net.Compiler/Binding/Model/ObjectRefDescriptor.cs#SameDescriptionAs

### GR-14.8.2.3.2-3 (PARTIAL)
|| REFUTED: PARTIAL — This is a silent acceptance of non-conforming source. A user-defined function argument described 'OBJECT REFERENCE C1 ONLY', passed BY REFERENCE into a formal described 'OBJECT REFERENCE C1', compiles and runs with no diagnostic and no exception. Rule 3 requires the ONLY phrase to be the same on both sides, and §8.4.3.2.3 SR13 makes that a syntax rule for function activation. The INVOKE arm (r3a-r3d) is correct, but the function arm never calls the comparator, and the runtime carrier check cannot see ONLY because both sides share a carrier.
- **Code location (record):** src/Cobol.Net.Compiler/Oo/OoConformance.cs#DescriptionMismatch; src/Cobol.Net.Compiler/Binding/Model/ObjectRefDescriptor.cs#SameDescriptionAs

## What the fixer owes
Route the function-prototype activation's arguments through the same DescriptionMismatch/ContentMismatch the INVOKE and CALL AS NESTED arms use (the third arm of a three-arm dispatch). Negatives for the three rows at 2002.
