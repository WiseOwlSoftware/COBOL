# PB6349 — report operands are not seen by GENERATE's EC-ARGUMENT-FUNCTION guard

**What.** `SOURCE FUNCTION LOG10(W-Z)` in a report group, with checking on, raises nothing at GENERATE when W-Z is out of the function's domain: the program prints no CAUGHT (the PB6223 implementer's `probe2.cob`). The same holds for a function reference in a SUM operand or a PRESENT WHEN condition. The governing rule is §2023:15.3 AR14 (the implementer's report records it checked OK).

**Mechanism.** PB6223 made the EC operand rule a node test over `BoundValueWalk.SelfAndDescendants`, fed by `BoundVisitorGenerator`. The report operands live in `ReportModel` / `ReportGroupModel` (`src/WiseOwl.Cobol.Compiler/Binding/ReportModel.cs`: `List<BoundCondition> PresentWhen` near line 470, `BoundExpr` Value/From/By near lines 628-1067), which the generator does not enter: it reads no `List<T>`, and the model cycles back to itself (`BoundReportCounterRef.Report`). `BoundValueWalkDriftTests.ModelsHeldByReference` names the gap.

**Fix shape.** A cycle-safe walk of the report model that yields the same value nodes, so `EcBinder.PartHasIntrinsic` and `OperandsIn` need no report-specific arm; the drift test then drops the allowance.

## Landing

**Fixed at the root (2026-11-27, wave 20262180).** `ReportValueWalk` (`src/WiseOwl.Cobol.Compiler/Binding/ReportValueWalk.cs`, `EvaluatedBy` and
`ValueNodes`) walks the report description by containment, each model node entered once, and yields the PRESENT WHEN conditions, SOURCE
operands, SUM addends, VARYING FROM/BY expressions and item-occurrence values, the operand-evaluation steps of a SOURCE or CODE
clause, and the SUM terms of other reports that name a detail of this report in UPON (`ReportModel.UponTriggeredTerms`, recorded by
`ReportSectionBinder.RecordUponTriggers`). `EcBinder.OperandRaisableNames` asks it beside the statement's own `OwnValueParts` for a
GENERATE or TERMINATE, so `PartHasIntrinsic` and `OperandsIn` carry no report arm. The drift test's `ModelsHeldByReference` allowance is
gone: `BoundValueWalkDriftTests.Mentions` leaves the report description to `ReportValueWalkDriftTests`, which populates every property of
every description type with a sentinel, closes the list of named back and cross references, and decides what each bound node holding the
description does with it. Conformance `15.3-Arguments/pb6349_ec_argument_function_report_operands` (2002, 2014, 2023; eight positions) and
its 1985 refusal.
