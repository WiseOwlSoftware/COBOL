# PB6349 — report operands are not seen by GENERATE's EC-ARGUMENT-FUNCTION guard

**What.** `SOURCE FUNCTION LOG10(W-Z)` in a report group, with checking on, raises nothing at GENERATE when W-Z is out of the function's domain: the program prints no CAUGHT (the PB6223 implementer's `probe2.cob`). The same holds for a function reference in a SUM operand or a PRESENT WHEN condition. The governing rule is §2023:15.3 AR14 (the implementer's report records it checked OK).

**Mechanism.** PB6223 made the EC operand rule a node test over `BoundValueWalk.SelfAndDescendants`, fed by `BoundVisitorGenerator`. The report operands live in `ReportModel` / `ReportGroupModel` (`src/WiseOwl.Cobol.Compiler/Binding/ReportModel.cs`: `List<BoundCondition> PresentWhen` near line 470, `BoundExpr` Value/From/By near lines 628-1067), which the generator does not enter: it reads no `List<T>`, and the model cycles back to itself (`BoundReportCounterRef.Report`). `BoundValueWalkDriftTests.ModelsHeldByReference` names the gap.

**Fix shape.** A cycle-safe walk of the report model that yields the same value nodes, so `EcBinder.PartHasIntrinsic` and `OperandsIn` need no report-specific arm; the drift test then drops the allowance.
