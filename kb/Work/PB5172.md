# PB5172 - at --std 85 the CLASS clause accepts the IN alphabet-name phrase, and the class then takes its ordinals in the alphabet, not the native character set: a different answer to the class condition

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/SpecialNamesBinder.Classes.cs` (`SwitchBindClass`)
- `src/WiseOwl.Cobol.Compiler/Binding/SpecialNamesBinder.Literals.cs` (`LiteralPhraseOperand`)
- `src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs` (`VisitClassDefinitionClause`)
- the fix (2026-11-11): `src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs` (`VisitClassDefinitionClause`); `tests/version-matrix/constructs/class-clause-in-alphabet-2002.json`

**Mechanism.** §1985:VI.4.5.4 GR10 makes class-name-1 the set of native characters its literals name (a numeric literal is the ordinal within the native character set). The 1985 CLASS clause has no IN phrase. `VersionConformancePass.VisitClassDefinitionClause` gates only the FOR phrase, and `SwitchBindClass` applies the alphabet of the IN phrase through `LiteralPhraseOperand` at every edition, so `CLASS C1 IS 1 THRU 2 IN AL` compiles at --std 85 and answers by AL's ordinals (TRUE where the native reading gives FALSE). The SPECIAL-NAMES format row 1985-FMT-VI.4.5.2 records the same acceptance; kb/Work PB5171 claims it.

Code sites read: src/WiseOwl.Cobol.Compiler/Binding/SpecialNamesBinder.Classes.cs#SwitchBindClass; src/WiseOwl.Cobol.Compiler/Binding/SpecialNamesBinder.Literals.cs#LiteralPhraseOperand; src/WiseOwl.Cobol.Compiler/Binding/SpecialNamesBinder.Literals.cs#OneCharacterOperands; src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/ConditionBinder.cs#BindUserWordClassCondition; src/WiseOwl.Cobol.Runtime/Values/Text/CobolClass.cs#IsInClass; src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs#VisitClassDefinitionClause; src/WiseOwl.Cobol.Frontend/Grammar/CobolParserCore.g4#classDefinitionClause. Code read: No kb/Work note owns the fix (none found for the CLASS clause's IN phrase at 85). §1985:VI.4.5.4 GR10 makes class-name-1 the exclusive set its literals list: a numeric literal is "The ordinal number of a character within the native character set", a nonnumeric one "The actual character within the native character set" (each character of a multi-character literal), and a THROUGH pair the contiguous native characters between its ends "in either ascending or descending sequence"; "Class-name-1 can be referenced only in a class condition." SpecialNamesBinder.SwitchBindClass builds the member string at every edition through LiteralPhraseOperand (ordinal n is code unit n - 1 of the 65,536-character native set; 0, an ordinal above it, a signed or noninteger numeric literal are refused, COBOL1671) and swaps a descending THROUGH pair; ConditionBinder.BindUserWordClassCondition is the only reader of the class and CobolClass.IsInClass tests each character. Probed right at 85: mixed numeric and nonnumeric THROUGH ends in both orders, repeated characters, a space member, a group operand, a class inherited by a contained program, and the reference bar (MOVE, DISPLAY, INSPECT, a relation operand, SET TO TRUE, a bare IF and the VALIDATE CLASS clause are all refused). PARTIAL for one arm: the 2002 phrase IN alphabet-name-4 has no edition gate (VisitClassDefinitionClause gates only the FOR phrase; classDefinitionClause parses IN and SwitchBindClass binds it), so at --std 85 CLASS C1 IS 1 THRU 2 IN AL compiles and its numeric literals are ordinals in AL's character set, the §2002:12.2.6.3 GR12 reading the row's change record names, where the 1985 format (§1985:VI.4.5.2) prints no IN phrase for CLASS and GR10 fixes the native set. The witness runs six 1985-format classes (multi-character, THRU both ways, ordinals).

**Repro (`1985-GR-VI.4.5.4-10`).** `cobol.exe b1.cob --std 85 --source-format fixed --run`

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. CLIN.
       ENVIRONMENT DIVISION.
       CONFIGURATION SECTION.
       SPECIAL-NAMES.
           ALPHABET AL IS "Z" "Y"
           CLASS C1 IS 1 THRU 2 IN AL.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  W PIC X(2) VALUE "ZY".
       PROCEDURE DIVISION.
       P1.
           IF W IS C1 DISPLAY "TRUE" ELSE DISPLAY "FALSE".
           STOP RUN.
```

**Expected (from the 1985 text, the record's).** --std 85 refuses line 7 at the IN phrase. §1985:VI.4.5.2 prints the clause as CLASS class-name-1 IS {literal-4 [THROUGH literal-5]} ... with no IN phrase (the format's only IN phrase is "[IN alphabet-name-2]" of SYMBOLIC CHARACTERS), and §1985:VI.4.5.4 GR10 gives a numeric literal one meaning: "The ordinal number of a character within the native character set, if the literal is numeric." The IN phrase is the 2002 form (§2002:12.2.6.3 GR12: "or, when the IN phrase is specified, within the character set referenced by alphabet-name-4").

**Observed (the record's).** exit 0, no diagnostic; the program runs and displays TRUE: ordinals 1 and 2 were taken in AL's character set (Z and Y), the 2002 reading. The same clause without IN AL displays FALSE at 85 (native ordinals 1 and 2). Control at --std 85: CLASS C1 FOR ALPHANUMERIC IS "A" THRU "C" draws COBOL0900 (the FOR phrase is gated; the IN phrase is not).

**Fix direction (root cause, CLAUDE.md rule 4).** Refuse the IN phrase of the CLASS clause below the edition that introduced it, in VisitClassDefinitionClause beside its FOR gate, as a registry construct.
