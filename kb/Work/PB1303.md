**Mechanism.** GLOBAL type declarations are not inherited by contained programs: TypeDecls is per-DataBinder and BinderDriver's contained-unit inheritance carries GLOBAL constants, FDs, RDs and data roots but has no arm for GLOBAL type-names

**Repro.** PROGRAM-ID. OUTER. WORKING-STORAGE: 01 T TYPEDEF GLOBAL. 05 A PIC X(2) VALUE "GL". PROCEDURE: CALL "INNER". STOP RUN. / nested PROGRAM-ID. INNER. WORKING-STORAGE: 01 R TYPE T. PROCEDURE: DISPLAY A OF R. GOBACK. END PROGRAM INNER. END PROGRAM OUTER.  (probe out13/probe/typedef-clause/td12global.cob)

**Expected, from the standard.** Compiles and prints GL. §13.18.58.4 GR3 'The GLOBAL clause applies to the scope of the type-name'; §8.4.6.2.2 'type-name described with a GLOBAL clause is a global name'; §8.4.6.2.1 a global name may be referenced in any directly or indirectly contained source element.

**Observed.** COBOLNET1530 'TYPE 'T' on 'R': the type-name is not defined by any TYPEDEF entry' plus cascading COBOLNET0881/1639. Control td17ctl (a GLOBAL data item in the identical shape) prints GL; without GLOBAL the rejection is correct (td12local). BinderDriver inherits InheritGlobalConstants BEFORE data.Bind and GLOBAL FDs/RDs/CallGlobalRoots after it; TypeDecls has no inheritance arm, and since ExpandTypes runs inside Bind the global type declarations must join before Bind (nearest container first, a local declaration shadowing). Sibling to sweep: §8.4.6.2.2's object-definition clause (a type-name declared in a factory/instance definition is global to its methods).
