# PB5480 - a relative or indexed file connector opened INPUT on a zero-byte file reads records written later outside its own record size with status 00, not 04: the zero-byte OPEN validates nothing and the keyed READs have no record length conflict arm

**Sites:**

- `src/WiseOwl.Cobol.Runtime/IO/KeyedConnector.cs` (`KeyedConnector.FixedAttributeConflict`)
- `src/WiseOwl.Cobol.Runtime/IO/RelativeConnector.cs` (`RelativeConnector.ReadSequential`, `RelativeConnector.ReadRandom`)
- `src/WiseOwl.Cobol.Runtime/IO/IndexedConnector.cs` (`IndexedConnector.ReadSequential`, `IndexedConnector.ReadRandom`)
- docs/CONFORMANCE.md (the '04' entry, DOC-A.1-129: "A RELATIVE or INDEXED record outside the attributes cannot reach a READ" changes with the fix)

**Mechanism.** Status 04 is "A READ statement is successfully executed but the length of the record being processed does not conform to the fixed file attributes for that file" (§1985:VIII.1.3.4, §1985:IX.1.3.4), and docs/CONFORMANCE.md holds that a keyed record outside the attributes cannot reach a READ because OPEN validates them. That premise fails for a zero-byte store: `KeyedConnector.FixedAttributeConflict` returns false for `StoreFormat.Empty`, so a connector opened INPUT on it is never checked against the attributes another connector gives the file when it writes. Its later READs of records outside its own RECORD VARYING bounds truncate to its maximum (GR16/GR18's truncation) but report 00, and the DEPENDING ON item holds the untruncated length, above the reader's maximum. The sequential connector already has the arm (`SequentialConnector.ReadRecord`, its short/long check against VaryMin/VaryMax); the relative and indexed READs have none. Both rows are one root.

**Latitude.** The 1985 READ rules (§1985:VIII.4.5.4 GR16, §1985:IX.4.5.4 GR18) measure "the record description entries for file-name-1", while the 04 definition names "the fixed file attributes", and §1985:II.2.1 makes "the minimum and maximum logical record size" a fixed attribute the RECORD clause provides. Both readings survive the words, so the adjudicator decided it as latitude: the 04 condition is measured against the reading connector's minimum and maximum record size (reading B, the reading on which kb/Work PB5238 was retired, here on 1985 grounds). Support: §1985:B.2.2 item (40) a (informative), §2023:14.9.30.4 GR14 NOTE 2, and GnuCOBOL 3.2 (as the adjudicator established it: libcob/fileio.c sequential_read compares with f->record_min/record_max, which cobc/tree.c sets from the RECORD clause widened by the descriptions). Under B the refuters' description-only probes conform (`ixsep`, `relsep`: 00/00/00); this note is the half that fails under EITHER reading: the zero-byte records lie outside the reader's own record size. The adjudicator records the counter-argument: the probe needs two connectors open at once on one physical file, which 1985 does not define, and a sequential OPEN OUTPUT created the zero-byte file (§1985:VIII.4.4.4 GR8 leaves the validated attributes to the implementor).
