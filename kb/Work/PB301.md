# PB301 — HALF — the screen-word sweep (5 of 27 fixed)

Found by the sweep step of the **A.4.2 screen-handling** landing (kb/Work PB260): *grep for any screen word the
lexer reserves that could break a legal 85/2002 program using it as a user word.*

## The measurement

§8.10's context-sensitive table was read at source and joined against the lexer's token list and the generated
`cobolWord` rule. Five screen words are **lexer tokens that `cobolWord` did not admit**, so a legal declaration
was a raw parse error:

| Word | Its §8.9 / §8.10 status (checked at source) | Broken at |
|---|---|---|
| `BACKGROUND-COLOR` | §8.10 context-sensitive, "screen description entry"; **not in §8.9 at all** | 85 · 2002 · 2014 · 2023 |
| `FOREGROUND-COLOR` | §8.10 context-sensitive, "screen description entry" | 85 · 2002 · 2014 · 2023 |
| `REVERSE-VIDEO` | §8.10 context-sensitive, "screen description entry and SET attribute statement" | 85 · 2002 · 2014 · 2023 |
| `CRT` | §8.9 reserved — **2002 onward only** (`reserved-words.json` r85 false) | 85 |
| `CURSOR` | §8.9 reserved — 2002 onward only | 85 |

The first three are the sharper case: they are reserved *nowhere*, at *no* edition, so `01 REVERSE-VIDEO PIC X.`
in WORKING-STORAGE has always been legal COBOL and the compiler has always refused it. The screen module we do
not implement was costing the user three words in programs that never mention a screen.

## The fix

All five become `nameSlot` rows in `tests/version-matrix/cobol-words.json` — the single generated source for
`cobolWord` and `_dataNameTokens` — with `CRT` and `CURSOR` **reservation-gated** (`{!reservedHere("CRT")}?`,
the COMMIT/ROLLBACK precedent of PB137) so the user-word space is admitted exactly where §8.9 leaves it.

A second arm was needed, and it is the arm a name-slot-only fix would have missed: `specialNameEntry`'s
`crtStatusClause` / `cursorClause` alternatives are now gated on `{reservedHere("CRT")}?` /
`{reservedHere("CURSOR")}?`. Without that, `SPECIAL-NAMES. CURSOR IS FOO.` at `--std 85` — a perfectly legal
COBOL-85 **implementor-switch entry** — parsed as the screen module's CURSOR clause and drew a screen-facility
verdict for a program with no screen in it. `ScreenFacilityConstructDriftTests` pins both directions: the
85 reading carries no COBOLNET1560, the 2023 reading carries exactly it.

## The complement, measured — 22 more words of the same shape, OUTSIDE this module

The same join over the **whole** §8.10 table finds **25** context-sensitive words that are lexer tokens and not
`cobolWord` alternatives. Three of them are the screen words fixed here; the other twenty-two are not this
module's and are NOT fixed by this note:

`AWAY-FROM-ZERO` · `BACKWARD` · `CAPACITY` · `CYCLE` · `INITIALIZED` · `INTRINSIC` · `MULTIPLE` ·
`NEAREST-AWAY-FROM-ZERO` · `NEAREST-EVEN` · `NEAREST-TOWARD-ZERO` · `PARAGRAPH` · `PREVIOUS` · `PROHIBITED` ·
`RECURSIVE` · `SIGNED` · `STRONG` · `TOWARD-GREATER` · `TOWARD-LESSER` · `TRUNCATION` · `UNSIGNED` ·
`YYYYDDD` · `YYYYMMDD`

Each is, on the same reading of §8.10, a legal user-defined word outside its one construct, and each is a parse
error in a declaration today. They are listed here rather than fixed because `cobolWord` feeds every name slot
in the grammar and admitting twenty-two keywords at once is an ALL(\*) prediction change that needs its own
measurement and its own gate — not because the reading is different. Whoever takes them should re-run the join
(it is nine lines against `specs/ISO_COBOL.md` §8.10, the lexer and the generated `cobolWord`) rather than trust
this list, since both inputs move.
