# PB5031 - SET general rule 2 names index-name-1 for index-name-2's table

**Sites:** none (an adjudication: no code file changes; the verdict below is the record the 1985 SET adjudication reads).

**Found.** §1985:VI.6.23.4 GR2 (page 360, VI-128) reads "If index-name-2 is specified, the value of the index before the
execution of the SET statement must correspond to an occurrence number of an element in the table associated with
index-name-1." The sentence is about index-name-2's own table, so the sense wants index-name-2; the 1985 text, read on the
rendered page by PB4984, prints index-name-1. Both quotations pass `cite.py --check`. PB4984 listed it among the reader leads it
left as printed, because the standard's wording stands until the page shows a misprint.

**Owed.** When the 1985 adjudication of the SET rule runs (PB4995's lineage slices), it reads this sentence as printed and
decides whether the behaviour under `--std 85` follows the printed or the evident sense; a verdict that depends on the word
cites this note. If the page shows a printed misprint, add an Errata entry in `specs/ANSI_COBOL_1985.md` the way C20 to C30 do.

**Read on the page (Mythos session, 2026-11-09).** PDF page 360 (folio VI-128), rendered at 150 dpi: the standard prints
`table associated with index-name-1.`, so the transcription reproduces the page. The Errata's policy (the paragraph above
C20-C30's table) kept this operand as printed; the OWNER OVERRULED that policy the same day: "our markdown transcription
should always be the most accurate version of the specification ... we never continue to list incorrect information just
because it was in the original specification that way". So this is an evident misprint to CORRECT with attribution
(`index-name-1` -> `index-name-2`; the sentence's subject is index-name-2, and §2023:14.9.39.4 GR2 b) speaks of
"the table element associated with index-name-2"), in the sweep kb/Work PB5045 owns. The lineage record
`1985-GR-VI.6.23.4-2` (CHANGED into GR-14.9.39.4-2, -4 and GR-13.18.38.4-2, source audit-1985/state-route) rests on the
rule's first sentence (the index value AFTER the SET), not on this one, so it does not depend on the word. What stays
owed is the rule's `--std=85` verdict (the 1985 verdicts after transcription): it reads the sentence as printed and
cites this note if its verdict turns on the operand.
## Verdict (wave 20261949, rendered page 360 read)

The rendered page (VI-128, 200 dpi) prints `index-name-1` in the second paragraph of general rule 2, exactly as the transcription
has it: a printed word, not a transcription slip. Read as printed, the rule would require index-name-2's value to be an occurrence
number of index-name-1's table. General rule 3a rules that reading out: it provides for index-name-2 being "related to" a
different table than index-name-1 and converts by occurrence number in that case (§1985:VI.6.23.4 GR3, quoted text passes
`cite.py --check`), so a requirement that index-name-2 always index index-name-1's table would make the conversion unreachable.
The evident sense, index-name-2's own table, is the one the rule has. The behaviour under `--std 85` follows the evident sense,
and it needs no code: the rule constrains the run-time VALUE of an index (an occurrence number inside its table), the standard
leaves the result of a violation undefined, and the compiler issues no diagnostic and no check for either reading, so neither
reading changes a compiled program.

The transcription keeps the printed word. The Errata preface of `specs/ANSI_COBOL_1985.md` fixes the policy PB4984 applied: an
operand the sense seems to want changed (`index-name-1` where `index-name-2` reads better) stays as printed, because a corrected
operand number changes the standard's own requirement as quoted, and the C20 to C30 entries are limited to words where the page
prints one real word for another. This sentence is exactly the case that policy names, so no Errata entry is added. A rule
verdict that depends on the word cites this note and the evident sense above.
