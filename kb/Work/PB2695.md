**Wave kind:** defect-for-fix-lane. Found by the wave-1042 group G implementer (PB2616) and filed by the train 1042b lander.

**Sites:**
- `src/Cobol.Net.Runtime/Values/Tables/CobolTable.cs:58` (the EC-BOUND-SUBSCRIPT detail text)
- `src/Cobol.Net.Runtime/Values/Tables/CobolTable.cs:130-142` (CobolTable.Occ / OccScaled: an out-of-long occurrence number saturates to `long.MaxValue` so §8.4.2.3.4 GR2's out-of-range condition survives)

**Rule:** §8.4.2.3.4 GR2 (a subscript outside 1..the maximum occurrences sets EC-BOUND-SUBSCRIPT). The condition IS raised correctly; only the diagnostic wording is wrong.

**Scenario (implementer's repro `E:\COBOL-coord\scratch\w1042g\p4.cob`, not re-measured by the lander):** `01 A PIC 9(21) VALUE 100000000000000000001.` and `MOVE EL2(A) TO …` raises EC-BOUND-SUBSCRIPT, and its detail names the subscript value 9223372036854775807 (the saturated long) where the item's value 100000000000000000001 is what the program holds. A user reading the message is sent looking for a value the program never computed.

**Fix direction:** carry the saturation as a flag (or format the original image/Int128) into the detail text rather than the clamped long.

# PB2695 — LANDED

## Landed (wave 1051, group A)

**Re-probed on the wave-1051 build** (`E:\COBOL-coord\scratch\w1051a\p1.cob`, free form: `EL2 PIC 9 OCCURS 3`, `A PIC 9(21) VALUE
100000000000000000001`, `>>TURN EC-BOUND-SUBSCRIPT CHECKING ON`, `MOVE EL2(A) TO I`): `abnormal run-unit termination:
EC-BOUND-SUBSCRIPT (fatal): subscript 9223372036854775807 is outside 1..3`. The expression arm (`p4.cob`, `EL2(A + 5)`) printed the
same number.

**Root cause.** `CobolNum.Position` SATURATES an occurrence number to `long` (§8.4.2.3.4 GR2 needs an out-of-range subscript to
stay out of range, never wrap), and every table accessor took that `long`, so the one place that raises had only the clamp to
print. Not one arm: the same clamp reached the fixed-table accessor `At`, its OCCURS DEPENDING overload (the `depending` count),
`OdoExtent`/`OdoExtentChars` (a group's extent), the dynamic-capacity table's references (`RefSending`, `RefReceiving` and its growth
diagnostics), a report sum counter's subscript (`CobolReport.SumImage`/`SetSumImage`), and the expression arm's 19-digit temporary,
which stored the `long`-saturated position.

**Fix (the shape that makes the next carrier automatic, not a display-text parameter at each emission site).** A new runtime struct
`Occurrence` (`Values/Tables/Occurrence.cs`): the saturated `long` every accessor positions by, plus the exact value text built
only at the two saturation extremes. `CobolTable.Occ(x, in NumProfile)` returns it for every carrier (`long`, `Int128`, `UInt128`,
`ulong`, character image), computed through ONE factory (`Occurrence.Of`); it converts to and from `long` implicitly. The
accessors that raise (`At`, the ODO `At`, `OdoExtent`, `OdoExtentChars`, `CobolDynTable.RefSending`/`RefReceiving`,
`CobolReport.SumImage`/`SetSumImage`) take an `Occurrence` and have ONE overload each (a `long` overload beside it makes every
`int` argument ambiguous, because the conversions run both ways). The emitted C# is unchanged but for the report sum address's
dropped `(long)` cast: C# overload resolution picks the carrier, so no code-generator site passes display text and no drift
test is needed to keep a list of sites current. The expression arm keeps the exact value across its temporary: `SegmentTempPic` is
38 digits and `CobolTable.OccValue*` return the exact `Int128` integer (`CobolNum.PositionOfWide`), saturating by sign at the
temporary's capacity so a store can never wrap it back inside 1..n. Found and fixed in the same read: `Occ(UInt128)` saturated
every value past `Int128` "whatever its fraction", so a 16-byte unsigned item whose scale divides it back inside `long` positioned
the clamp; it now reads the UInt128 itself (GR1b's integrality too).

**Public surface.** The change edits shipped members (return and parameter types), so the runtime MAJOR is 2
(`Directory.Build.props`, `RuntimeAbiPinDriftTests` re-pinned beside the new `PublicAPI.Shipped.txt` hash); `Occurrence` and
`CobolNum.PositionOfWide` are listed in `PublicAPI.Unshipped.txt`.

**Tests.** `WideSubscriptDiagnosticTests` (Conformance, 14 cases: the termination text per arm and per carrier shape, checking OFF
unchanged), `OccurrenceTests` (Unit: the unsigned-wide carrier, scale and trailing-P arithmetic, the expression intake's capacity),
golden `2002/pb2695_wide_item_subscript_and_odo_count` (the CONDITION on each wide item shape; the message text is unobservable
from COBOL, so no negative golden below 2002 exists: nothing here adds syntax or an edition gate).

**For the next implementer.**
- `src/Cobol.Net.Runtime/Values/Tables/Occurrence.cs#Occurrence.Of` — THE factory (Int128 and UInt128 arms); the exact text exists
  only at the two saturation extremes. REUSE it for any new position carrier; never format a clamped `long`. Trap: with
  conversions in BOTH directions a `long` overload beside an `Occurrence` one makes every `int` argument CS0121, and
  `Occurrence` needs its own `Int128` conversion (`long` -> `Int128` is user-defined, so C# will not chain it).
- `src/Cobol.Net.Runtime/Values/Tables/CobolTable.cs#At` / `#OutOfRange` — the one range test and the one outcome; the
  `OccValue*` expression intake returns the exact `Int128` and `CobolNum.PositionOfWide` saturates at the 38-digit temp.
- `src/Cobol.Net.Compiler/Binding/Bound/StatementBinder.SubscriptSegments.cs#SegmentTempPic` — 38 digits; the narrowing to
  `long` happens only at the subscript read. Trap: a saved-in-an-item position must saturate at the item's capacity, never
  truncate (a modulo wrap could land back inside 1..n).
- `src/Cobol.Net.Runtime/PublicAPI.Shipped.txt` + `tests/Cobol.Net.Tests.Unit/RuntimeAbiPinDriftTests.cs` — changing a shipped
  member's type raises the runtime major (now 2) and re-pins the hash; the characterization snapshots carry the version literal.

**Sibling sweep.** Readers of a saturating narrowing: (1) reference modification, `CobolString.RefModPosition` / `RefModValue*` ->
`HostInt32` -> `RefMod`/`SpliceInto` messages, print the `int`-saturated start/length for a value past `int`
(`reference modification (2147483647:...)`): the same shape on a different consumer chain (an `int` API with many callers), left
open and reported as a lead; (2) `CobolIndex.TryAmount`/`Land` take the amount as an `Int128` already and name it in `detail`
(no narrowing before the message); (3) the report sum-counter subscript was an arm of this bug and is fixed above.
