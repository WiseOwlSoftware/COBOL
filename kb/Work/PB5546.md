# PB5546 - two comments left by PB5497 misstate the 1985 area rule: the AreaPlacementPass class summary is stale and a golden's comment cites the wrong clause

Both comments describe the rule PB5497 implemented and both misstate it, so they share one mechanism: PB5497's round-2 commit (the DECLARATIVES / END DECLARATIVES line-alone exception, `LineAlone`) changed the behavior and not the prose around it.

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Validation/AreaPlacementPass.cs#AreaPlacementPass` (class summary, line 17: the format "placed every item by where it BEGINS ITS LINE"; its area-A bullet does not mention the DECLARATIVES / END DECLARATIVES line-alone exception, and the first bullet already says an area-A item "STARTS in area A ... whether or not it begins the line", so the two sentences disagree).
- `conformance-suite/cases/_unassigned/pb5497-end-declaratives-after-text-85.cob` (the comment: "a header after text is legal only for a paragraph-name, §1985:IV.7.3.3").

**R2-1.** The summary's lead sentence and the area-A bullet contradict the bullet's own parenthesis. Rewrite so area-A items START in area A (positions 8-11) wherever on the line they are, and DECLARATIVES / END DECLARATIVES alone must also be the only text on their line (§1985:IV.7.5, which PB5497's report cites as cite.py-checked).

**R2-2.** The reviewer reports the golden's claim is wrong: the compiler (correctly, per §1985:IV.7.3.2 "must start in area A") also accepts a section header, a division header or an end marker that starts in area A after other text; only DECLARATIVES / END DECLARATIVES are line-alone. Re-derive the clause with `cite.py --check` before writing it; the comment should name §1985:IV.7.5 for the refusal and say nothing about paragraph-names being the only legal header after text.

**Fix.** Edit the two comments in one change (a `.cob` comment edit does not change the golden's expected result); check the golden still passes.
