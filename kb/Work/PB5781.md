# PB5781 - a juxtaposed parenthesised argument becomes a subscript

**Site:** `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolExpressions.g4#functionArgList`
(`functionArgument (FNARG_SEPARATOR? functionArgument)*`). The separator is optional, so after the argument `A` the
next `(` is taken by `A`'s `dataReference` as its `subscriptPart`, and `(- B)` becomes a subscript on `A` instead of a
second argument. The grammar's own comment there says that only a comma or semicolon separator protects a following
`(`. (kb/Work PB4246 is the open naming analysis of the same tokens; it does not cover this parse.)

**The rule.** §1985:VI.6.2.3 SR4 names the very context the program uses: "If the first operator in an arithmetic
expression is a unary operator, it must be immediately preceded by a left parenthesis if that arithmetic expression
immediately follows an identifier or another arithmetic expression." Each argument "must be an identifier, a literal, or an
arithmetic expression" (§1985:IV.4.3.8.3.3 SR1, as amended), so `(- B)` after `A` is the second argument, and MIN
returns "the content of the argument-1 having the least value".


**Repro** (kept out of the tree, with its derived `.out`:
`E:/COBOL-coord/scratch/gl1985/lane1/out/g1985b-vi-6-22-search/defects/conformance-suite/cases/VI.6.2@1985-ARITHMETIC-EXPRESSIONS/g85_bf15_01.cob`).
Its legs E1-E7 pass; the failing lines are

```cobol
           COMPUTE R = FUNCTION MIN (A (- B)).
           ...
           COMPUTE R = FUNCTION MIN (A - B).
```

with A = 7 and B = 3.

**Expected (from the text):** the program compiles; `E8=-0003` (two arguments, 7 and -3) and `E9= 0004` (one
argument, 7 - 3).

**Observed** at `--std 85` (and at `--std 2023`), exit 65, nothing run:

```
g85_bf15_01.cob(62,38): error COBOL2096: 'A (- B)': a subscript is written on 'A', whose data description entry neither contains an OCCURS clause nor is subordinate to one, so no subscript may be written on it (ISO §2023:8.4.2.3.3 SR2). ...
g85_bf15_01.cob(62,41): error COBOL0900: a subscript that is not a COBOL-85 positive integer, ... requires COBOL-2002 (targeting COBOL-85) — the arithmetic-expression subscript - B ...
```

With a comma, `MIN (A, - B)`, the program prints `-0003`. Both diagnostics also mislead: each tells the programmer to
change a subscript the program never wrote.

**The fix's shape.** An argument whose `dataReference` names an item with no OCCURS (and no table above it) cannot take
a following parenthesised expression as a subscript; the choice belongs where the reference is bound or in a grammar
predicate, and a table item followed by `(expr)` keeps its subscript reading (that ambiguity is the standard's own:
the SR4 sentence is what makes a unary-led expression need its own parentheses). Once fixed, `g85_bf15_01` relands as
the golden of `1985-SR-VI.6.2.3-4`.
