# PB3295 — a drift test reads note status by substring

**Landed with PB2878 (wave 20261029 A2), by removing the read rather than parsing it.** `EcRaiseSiteRegistryDriftTests`
asked whether the note that built each activation-boundary name contained `status: landed`; the evidence that a name is
raised there is the raise site (`Raised`), which the same test checks, and a test must read no `kb/` note now that the
vault is inert (DESIGN-test-build-ci.md §3.18). `RaisedAtTheActivationBoundary` is a list of names and its comment
names the building notes (PB408, PB1121). Sweep: no other private status reader in tests, scripts or src (a grep for
`status: landed` and `"status:` finds only fixtures).

Source: `E:\COBOL-coord\scratch\reports\w1098a-PB3196-report.md` (not w1098a-PB2099: the wave number collided), "New defects" (branch worktree-wf_e3902303-54c-1, PB3196, PR #142 merged). Harm: process_only.

**Code site** (re-verified on origin/main 494246263): `tests/Cobol.Net.Tests.Unit/EcRaiseSiteRegistryDriftTests.cs:265`, `File.ReadAllText(file).Contains("status: landed", StringComparison.Ordinal)`. It should read the parsed status, `WorkRegister.Parse(...)?.Status == "landed"` (`tests/_shared/WorkRegister.cs:38`).

**Repro (as given):** a note with `status: open` whose body mentions `status: landed` passes the check.

**Root.** The same as PB3196 (landed): a private status reader beside the one parser. PB3196 did not fix this site because it lay outside that wave's declared file set. A grep for `Contains("status:` over tests and scripts finds only this site; a sweep for other private readers (regexes on `status`) belongs to the implementer.
