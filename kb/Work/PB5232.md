## What this is

Stage 3 of kb/Work PB5207 (the build redesign the owner approved 2026-11-10), second half. The first half (PB5225, PB5226,
PB5227) made the self-tests reuse their recorded PASS by narrowing what a PASS is keyed on. This half changes the shape.

## The decision (Claude, under the owner's delegation of 2026-11-10)

**A self-test's inputs are DECLARED, as a test assembly's are (PB5218), and the trace is demoted from the key to the
audit.** Three review rounds of PB5227 each found a new way for the traced key to be wrong: a path read as a revision, a
submodule read keyed on the parent, an import searched before its package loaded, a namespace package gaining
`__init__.py`, a case-differing directory, a search pattern read as a pathspec. Every one was a hole in an inference.
An inference of what a program reads, made by watching it run, has no bottom; a declaration checked by a watch does. So:

1. Each self-test is a target in the build graph (`scripts/buildgraph.py`, the targets PB5231 generalizes) with declared
   inputs: by default its own file and the modules it imports under `scripts/` (derived statically, as the BUILD TARGETS
   audit derives a test assembly's reads), plus what it names in a `SELF-TEST-READS` header. Its key and its recorded pass
   live in the one store.
2. The tracer stays as the AUDIT of the declaration: a traced run that reads a tracked path outside the target's
   declared inputs FAILS that self-test, naming the path (the same rule the owner set for an unresolved read, 2026-11-10:
   "If it cannot be resolved, there is a problem/bug"). The git grammar and the import key built for PB5227 are what that
   audit uses; they no longer decide reuse, so a hole in them can cost a missed finding but never a false green key.
3. Each target declares its seconds; its timeout is a small multiple of them and ends as a red of that target alone.
4. The runner prints one line when a self-test starts and one when it ends, with `n of N` (kb/Work PB5222).
5. The clock proof (PB5226) is declared the same way: a self-test that depends on the date says so in its header and
   takes an injected clock; the 400-day second run is kept only for the tests that declare it, and the date-literal
   detector is retired.
6. A self-test that reads the REAL repository's history or tree declares it and is keyed on it honestly
   (`test_plan_wave.py` today), or is given a scratch repository.
7. A self-test that needs the BUILT assemblies is a target that depends on the test assemblies' targets, so its pass is
   recorded at their keys. Today such a self-test records no pass: on 2026-11-11 run `000003-20261111T095635Z` of branch
   selftest-cost found Conformance, Unit and Characterization all up to date and still queued for a gate slot, two
   gates deep, only to rebuild for `scripts/filter_population.py`, after a commit that added one kb/Work note.

`scripts/orchestrator/enqueue.py`'s self-test took 1,689 s of a 1,698 s self-test stage on 2026-11-11 (run
`000001-20261111T055208Z` of branch selftest-cost). Stage 4b (kb/Work PB5233) deletes `enqueue.py` and moves its arms into
several test files, which run in parallel. This note does not split it first.

## The first commits: the findings PB5227 landed with (review round 3, `E:\COBOL-coord\scratch\review-w20261995-a.jsonl`)

The reviewer's judgment, which the controller accepted: no present self-test uses these forms and CI runs every self-test
fresh, so nothing here endangers main; they were landed with, recorded here, and are fixed first.

- **R3-1 (medium), `git_reads`:** a path given before `--` is read as a revision (`git log -1 --format=%H
  scripts/devlog.py` keys `rev:scripts/devlog.py`, which resolves to no object forever). A revision that resolves to no
  object is an UNKEYED READ.
- **R3-2 (low):** `rev-parse --abbrev-ref HEAD` and `--symbolic-full-name HEAD` print a branch name but are keyed on
  HEAD's commit. Both are UNKEYED.
- **R3-3 (low):** a git command run inside the `specs-private` submodule is keyed against the parent repository. A
  command whose directory is inside a submodule is UNKEYED.

**Sites:** `scripts/self_test_inputs.py` (`git_reads`, `read_trace`, `Deps.changed`) · `scripts/self_tests.py` (`Runner.run`, `Runner.run_one`, `Runner._report`, `PassStore.lookup`) · `scripts/self_test_clock.py` (`keys_proof`) · `scripts/buildgraph.py` (`load_targets`)
