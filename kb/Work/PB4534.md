# PB4534 — blank-when-zero-v-becomes-character-position: PIC 99V9 BLANK WHEN ZERO has length 4: the assumed decimal point becomes a character position

Filed 2026-11-03 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-batch-3000-20261103`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

An unsigned numeric item with an assumed decimal point and BLANK WHEN ZERO, such as `PIC 99V9 BLANK WHEN ZERO`, gets
one character position too many: cobc gives it a length of 4 instead of 3, so `12.3` displays as `1230` and zero as
four spaces. The 'V' is an assumed decimal point and is not counted in the size of the item; BLANK WHEN ZERO only
changes the item's category to numeric-edited.

## Minimal test case

Free reference format (`-free`).
```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. BWZV.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 D PIC 99V9 BLANK WHEN ZERO.
PROCEDURE DIVISION.
    MOVE 12.3 TO D
    DISPLAY "D [" D "] LENGTH " FUNCTION LENGTH (D)
    MOVE 0 TO D
    DISPLAY "Z [" D "]"
    STOP RUN.
```

## Environment

cobc (GnuCOBOL) 3.2.0 on WSL2 Ubuntu. `cobc -x -free -std=cobol2014 -o p prog.cob && ./p`.

## Observed result

Exit code 0:
```
D [1230] LENGTH 4
Z [    ]
```

## Expected result (per ISO)

§13.18.40.4 14): "The symbol 'V' indicates the position of the assumed decimal point for alignment purposes. The symbol
'V' is not counted in the size of the item." §13.18.8.4 2): for an item whose picture is category numeric, "the BLANK
WHEN ZERO clause defines the item as numeric-edited"; it does not add a character position. The item therefore has 3
character positions: 12.3 is stored as the digits 123, and zero gives three spaces. Both rules are in the 2014
edition. Expected output:
```
D [123] LENGTH 3
Z [   ]
```

## Our compiler

WiseOwl COBOL (fresh judge, `--std 2014 --source-format free`) compiles it with no diagnostic and prints
`D [123] LENGTH 3` and `Z [   ]`, exit 0.

## Fix site

cobc/field.c, `validate_elementary_item` (read in the GnuCOBOL 3.2 source): for `flag_blank_zero` on a category-numeric
picture with `scale > 0`, the "Reconstruct the picture string" block rebuilds the picture as '9', 'V', '9' symbols and
then executes `f->pic->size++`, so the assumed decimal point 'V' is counted as a character position and the item is one
position longer than its picture. The `scale == 0` branch does not increment the size, which is why `PIC 999 BLANK WHEN
ZERO` is unaffected.
