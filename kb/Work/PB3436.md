# PB3436 — the missing-period diagnosis admits integers that cannot be a level-number

Filed 2026-10-19 by the enqueue clerk from `E:\COBOL-coord\scratch\reports\w1129b-PB3390-report.md` (PB3390, PR #295 in the
merge queue; the sites are on its branch). Register check: see PB3435 (same grep; no existing note).

**Mechanism.** `src/Cobol.Net.Frontend/Parsing/CobolErrorStrategy.cs:549`: the data form dropped every unsigned integer from
the run tail, and the after-period exclusion treats ANY INTEGERLIT as a possible next level-number. ISO 8.3.2.2.13 says a
level-number is a one-digit or two-digit number. An integer that can never be one (three or more digits) now draws a false
missing-period diagnosis instead of the by-name refusal main gave.

**Fix shape.** Decide the exclusion from the level-number shape (one or two digits, 8.3.2.2.13; run
`python scripts/spec/cite.py --check 8.3.2.2.13 "level-number"` before writing the clause into code), in one place shared
with the grammar's level-number token, and add a case with a three-digit integer after the period.
