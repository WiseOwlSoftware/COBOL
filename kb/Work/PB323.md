# PB323 — the presence probe the PB140 sweep replaced everywhere but here

**Rows:** `GR-14.9.27.4-3`.

## The program

`<lane3 scratch>/out-b1/probe/gr3-authority/` — create `locked/secret.dat`, then
`icacls locked /inheritance:r /grant:r "<user>:(F)"` followed by `icacls locked /deny "<user>:(RX)"`
(restore with `/remove:d` + `/inheritance:e`). `p.cob` declares `SELECT FP ASSIGN TO "locked/secret.dat"` and
`SELECT OPTIONAL FQ` over the same path, and opens both INPUT.

## The rule

> §14.9.27.4 GR3: If the file associated with file-name-1 is present and insufficient authority exists to open
> the file, the execution of the OPEN statement is unsuccessful, and the I-O status value in the file connector
> referenced by file-name-1 is set to '37'.

`--check 14.9.27.4 "insufficient authority exists to open the file"` → **OK**. Both opens must be unsuccessful
with '37'. Table 18's *file is available* predicate (*physically present and recognized by the operating
environment*) is likewise not satisfied by an authority failure.

## What the compiler does

Non-optional `OPEN INPUT` = **'35'** (file not present); OPTIONAL `OPEN INPUT` = **'05'** — a SUCCESSFUL open —
and the first READ reports AT END '10'. So a program is told a file it merely lacks authority to read does not
exist, and the OPTIONAL arm then invents an empty file. The .NET behaviour was confirmed on the same path:
`File.Exists` returns `False` while `File.GetAttributes` throws.

`FileRegistry.DeleteFile` already documents the mechanism verbatim: *File.Exists swallows every access error and
answers false, classifying a PRESENT-but-unobservable file as gone — GR16 requires '37' there — so the probe is
File.GetAttributes, whose failures DISTINGUISH the two (PB140).* This is the OPEN arm that sweep never reached,
in three connectors.

**Code sites:** `SequentialConnector.cs#OpenCore` (line 210) · `RelativeConnector.cs#OpenCore` (line 96) ·
`IndexedConnector.cs#OpenCore` (line 126) · contrast `FileRegistry.cs#DeleteFile` (lines 462-465).

## The fix shape

ONE shared presence probe returning `present / absent / unauthorized`, used by DELETE FILE and by all three
`OpenCore` bodies, rather than three hand-written `File.Exists` calls plus one correct one — and a drift test
asserting no `File.Exists` survives in `src/Cobol.Net.Runtime/IO`.
