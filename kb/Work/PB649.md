# PB649 — LANDED — the leg that knows the rule was never reached

Found 2026-09-05 by the `PB297` implementer (report §"New defects" (A)), which moved figurative SIZING to the
operand actually compared and measured this collation defect as pre-existing: for this input the anchor slot
holds a non-figurative operand, so the expression PB297 edited is byte-identical in effect to the old one.
Deliberately not taken there — it is a §8.8.4.2.6 mechanism, not the §8.3.3.6.4 sizing one.

## Repro (`--std 2002`+)

```cobol
       OBJECT-COMPUTER. XX PROGRAM COLLATING SEQUENCE AL.
       SPECIAL-NAMES. ALPHABET AL IS "ZYXWVUTSRQPONMLKJIHGFEDCBA".
       01 XA PIC X(2) VALUE "AC".
       01 NB PIC N(2) VALUE N"AB".
           IF ALL N"AB" < XA ...        *> measured 0   ⛔
           IF NB        < XA ...        *> measured 1
```

## The rule

§8.8.4.2.6, comparison of alphanumeric and national operands: "The alphanumeric operand is treated as though it
were converted and moved in accordance with the rules of the MOVE statement from an alphanumeric elementary data
item to a temporary elementary data item of class national" (`OK §8.8.4.2.6`), after which the national
comparison rules (§8.8.4.2.9, where "AB" < "AC" under the native national sequence) govern. Both lines above are
one class-national and one class-alphanumeric operand — §8.3.3.6.3 SR2 gives `ALL N"AB"` its literal's class —
so both must answer the same. The alphanumeric PCS (`ALPHABET AL`) applies to alphanumeric-vs-alphanumeric
comparisons only.

## The mechanism

`src/Cobol.Net.Compiler/CodeGen/Emit/ConditionRenderer.cs`, `RenderFigurativeRelational` (`:221` on main; the
figurative branch is entered from `:163` BEFORE the general relational renderer): `anchorCat` (`:232`) is derived
from ONE operand — the non-figurative anchor — so with an alphanumeric anchor the collation lands on
`ctx.CollateArg` (the alphanumeric PCS). The NON-figurative national leg twenty lines below asks the right
question (`StringCategoryOf(r.Left) is National || StringCategoryOf(r.Right) is National`) and also threads
`deSign: true`; a national figurative never reaches it. Classic [[two_arm_dispatch]]: the figurative branch
runs first and repeats half of the rule.

## Fix shape

One category decision for a relation, made before either branch: "is EITHER operand of class national" —
including a figurative whose context or literal class is national (PB297's context rule for fig-vs-fig) — selects
the national comparison (§8.8.4.2.6 conversion of the alphanumeric side, then §8.8.4.2.9, `deSign` threaded the
same way), and only an alphanumeric-vs-alphanumeric pair reads the alphanumeric PCS. Write it once (a
`RelationClass` computed by one function from both operands) and have `RenderFigurativeRelational` and the general
renderer both consume it, so the figurative branch cannot repeat half the rule. Settle the `deSign` divergence
between the two legs in the same change (say which is right, from §8.8.4.2.6's MOVE-rules conversion). Goldens
at 2002/2014/2023 under a reversed alphanumeric PCS: the pair above (both 1), `ALL N"AB" < NB`'s fig-vs-national
control, an alphanumeric-vs-alphanumeric control that DOES take the PCS, and the equality/ordering pair; extend
`FigurativeSizingTests`' edition sweep with the collation axis. Drift: the category function is the only reader
of `ctx.CollateArg` in the relation renderers.

## Landed — wave 43 (B)

**Re-probed first.** Under `ALPHABET AL IS "ZYX…A"` as the PCS, `IF ALL N"AB" < XA` printed 0 while `IF NB < XA`
printed 1 on this worktree's own build — the note reproduced verbatim.

**Root, and the note named one arm of two.** `RenderFigurativeRelational` derived `anchorCat` from the
non-figurative anchor and then computed `figCat` FROM `anchorCat`, so `CollatingSelection.ForComparison` — the
one two-operand rule — was handed one operand's answer twice. The fix is `ConditionRenderer.RelationCategories`:
one pair of categories per relation, with §8.3.3.6.4 GR1's context inheritance for a category-LESS figurative
WORD only (an `ALL literal-1` keeps its literal's own class, §8.3.3.6.3 SR2). BOTH legs consume it — the
figurative branch and the general relational renderer — and each figurative is now seeded in ITS OWN category
rather than the anchor's, which is the second arm: `FigSeed(ALL N"AB", …)` was being handed Alphanumeric.

**The `deSign` divergence the note asked me to settle is already settled** and I am recording it rather than
re-fixing it: both legs thread `deSign: true` (the figurative leg gained it in the PB741 sweep), which is what
§8.8.4.2.5 → §14.9.25.4 GR6a requires, and it is a no-op for every non-signed-numeric operand.

**Sibling sweep.** The three other `CollateArgFor` call sites in `ConditionRenderer` were checked: the general
relation leg now takes the pair; `RangeCollateArg` takes both range ends; the level-88 membership site passes the
conditional variable's category twice and that is CORRECT and documented (§13.18.63.3 SR2/SR4/SR5/SR10 make a
level-88 VALUE literal the variable's own category). A drift test now asserts that set of call shapes, because a
behavioural probe only sees the defect for the operand pairing that happens to differ.
