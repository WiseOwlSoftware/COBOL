# PB3754 — a test comment inherits a wrong clause number for INHERITS

**Sites:** `tests/Cobol.Net.Tests.Conformance/OptionalWordSubsetDriftTests.cs#OptionalWordSubsetDriftTestsBase` (the INHERITS row comment at about line 621).

The row comment reads "§11.3.4 GR1 gives the subclass its superclass's methods, so the inherited MIX must answer in both spellings."
The failure mode CLAUDE.md rule 1 names: a real sentence under a clause number that was inherited, never re-derived. Checked
2026-10-25 with `python scripts/spec/cite.py --check`:

- `--check 11.3.4 "gives the subclass its superclass's methods"` FAILS: "§11.3.4 exists but does NOT contain" the text.
- `--check 11.3.4 "object-class-name-1"` is OK at `§11.3.4 1)`: General rule 1 is about object-class-name-1 naming the class declared.
- `--check 11.3.4 "The INHERITS clause specifies the names of classes that are inherited"` is OK at `§11.3.4 2)`: "The INHERITS clause specifies the names of
  classes that are inherited by object-class-name-1 according to 9.3.9, Class inheritance." (`--check "11.3.4 GR2"` is refused: the
  transcription numbers the general rules `1)`, `2)`, so cite the clause and the rule number as `11.3.4 2)`.)
- `--check 9.3.9 "Class inheritance"` is OK; §9.3.9 carries the semantics (what the subclass gets).

PB715's branch already rewrites the neighbouring comment; this one is the same line of the same row, so the PB715 landing did not reach it.

## Fix
Cite "§11.3.4 General rule 2 with §9.3.9" and run `cite.py --check` on the final text. Sweep the file's other row comments for a clause number
whose quoted text `--check` does not find (rule 4, every bug is a pattern).
