## Finding — `sort-statement-p1` (under-rejects; rows `SR-14.9.40.3-8`)

**Mechanism.** SortMapIoFiles never asks whether a USING/GIVING FD is a REPORT file, so SR8's report-file half is unenforced

**Repro.** SELECT RPF ASSIGN TO "ADJRP.DAT". FD RPF REPORT IS RPT. REPORT SECTION. RD RPT PAGE LIMIT 60. 01 TYPE DETAIL. 05 LINE 1 COLUMN 1 PIC X(3) SOURCE K1. `SORT SW ASCENDING K1 USING IN1 GIVING RPF` -> --std 2023 rc 0 (probe s8grp); `... USING RPF GIVING OU1` rc 0 (s8urp).

**Expected from the spec.** §14.9.40.3 SR8: file-name-2 and file-name-3 shall be described in a file description entry that is not for a report file — both probes are compile-time errors.

**Observed / reasoning.** SortMapIoFiles rejects an SD (SR8's other half, probes s8usd/s8gsd rc 70) and any non-sequential organization, but a report file is sequential and carries no sort-merge flag, so it passes. MERGE's USING/GIVING lists go through the same helper and inherit the gap.

**Code site.** src/Cobol.Net.Compiler/Binding/Procedure/Verbs/SortBinder.cs#SortMapIoFiles (lines 601-616)

## Finding — `write-statement-p1` (under-rejects; rows `SR-14.9.51.3-12`)

**Mechanism.** Report-file FD accepts a record description and WRITE of that record: no statement-level or FD-level screen reads FileModel.IsReportFile except OPEN's mode check, so a record is injected into the report output

**Repro.** FD P REPORT IS RP. 01 PR PIC X(10). REPORT SECTION. RD RP PAGE LIMIT 60. 01 DL TYPE DETAIL LINE PLUS 1. 05 COLUMN 1 PIC X(5) VALUE "HELLO". PROCEDURE: OPEN OUTPUT P, INITIATE RP, GENERATE DL, MOVE "INJECTED" TO PR, WRITE PR, GENERATE DL, TERMINATE RP, CLOSE P (probe out/probe/write-statement-p1/ws4rpt.cob, pinned cobol.exe --std 2023 --run)

**Expected from the spec.** Compile-time rejection: §14.9.51.3 SR12 'The file description entry associated with the write file shall not contain the REPORT clause and shall not be a sort-merge file description entry.' and, at the FD, §13.4.5.3 SR8 'No record description entries or constant entries shall be associated with the file description entry for a report file.'

**Observed / reasoning.** Compiles with rc=0 and no diagnostic at --std 2023; at run time the report file holds 'HELLO\r\nINJECTED\r\nHELLO\r\n' - the WRITE's record lands between the report lines. The FD with a record description alone (no WRITE) also compiles clean (ws3rpt0). The sort-merge half of SR12 IS enforced (COBOLNET1692 through UnsupportedOrg/ScreenSortMergeFile), so this is a two-arm rule with one arm built (feedback_two_arm_dispatch). REWRITE §14.9.35.3 and the READ family should be swept for the same missing report-file screen.

**Code site.** src/Cobol.Net.Compiler/Binding/Procedure/Verbs/SequentialIoBinder.cs#BindWrite (no IsReportFile test beside UnsupportedOrg); src/Cobol.Net.Compiler/Binding/DataBinder.cs (FD record entries not refused for a report FD, §13.4.5.3 SR8)

## What the fixer owes

Screen report files at the ONE place each rule lives: SortBinder.SortMapIoFiles (SORT and MERGE USING/GIVING share it), SequentialIoBinder.BindWrite beside UnsupportedOrg/ScreenSortMergeFile, and the FD record-entry binding in DataBinder (§13.4.5.3 SR8). Sweep REWRITE §14.9.35.3 and the READ family for the same missing report-file screen. Negatives: s8grp, s8urp, ws3rpt0, ws4rpt.
