# PB470 — LANDED — three intrinsics implement a substituted value nobody wrote down

Found 2026-09-04 by the `PB383` implementer, outside its own cluster and deliberately left unfixed (its report,
§"New defects found outside this item", finding 1). Every citation below was **re-run on this tree** for this
note, and the code sites were re-read rather than inherited.

## The mechanism

When an argument rule is violated and `EC-ARGUMENT-FUNCTION` checking is not enabled, these three intrinsics
return **`""` — a zero-length value**:

`src/Cobol.Net.Runtime/Intrinsics/CobolLocale.cs`

| line | site |
|---|---|
| 49 | `Date` — argument-1 not a valid `YYYYMMDD` date (§15.52.3 r1/r2) |
| 65 | `Time` — argument-1 not `HHMMSS` form (§15.53.3 r1/r2) |
| 71 | `Time` — argument-1 out of this clause's own ranges (§15.53.3 r3) |
| 83 | `TimeFromSeconds` — seconds outside the standard numeric time form (§15.54.3 r1) |

## Why that is not covered by any determination

`docs/CONFORMANCE.md` §7 row `DOC-A.1-90` states one rule for every intrinsic: the substituted value is *the ZERO
VALUE of the returned type* — numeric 0; alphanumeric/national **spaces**; one space for the fixed one-character
`CHAR`/`CHAR-NATIONAL`; a boolean item's zero positions; **and a zero-length value where the returned length is
itself derived from the rejected argument**.

The three LOCALE functions return an alphanumeric value whose length derives from **neither** the function nor the
rejected argument. It derives from the **locale**:

```
python scripts/spec/cite.py --check 15.52.4 "The length of the returned value depends on the format indicated in the locale."
OK  §15.52.4 3)  (Returned value rules)
```

So the zero-length exception, read as the determination writes it, **does not reach these sites**, and the general
clause does — an alphanumeric result, so *spaces*. Either the code is wrong or the determination is incomplete;
what is certain is that **the code is implementing a determination nobody has written**, and row `DOC-A.1-90` is
closed on a determination its own code sites do not satisfy.

⛔ **A correction to the framing this note was dispatched with.** It is *not* true that "A.1 item 90 requires the
result to be documented". The standard says the opposite, in item 90's own words:

```
python scripts/spec/cite.py --check A.1 "This item is required. The value returned doe"
OK  §A.1 90)  (Implementor-defined language element list)
    90) Function-identifier (result when argument rules are violated and checking for the EC-ARGUMENT-FUNCTION
        exception condition is not enabled). This item is required. The value returned does not have to be
        documented in the implementor's user documentation. (15.3, Arguments)
```

The §7 determination was written **voluntarily** — the inventory row's own `notes` say so, and give the reason:
*"three different substituted values were in play across the corpus and a golden may not pin an unwritten
determination."* That does not make this finding smaller; it makes it exactly the condition the voluntary
determination exists to prevent, and it means the fix is owned by the project's own rule rather than by a
conformance obligation.

## Harm — a wrong answer, and silent

`wrong_answer` is set on the *possible* wrong answer, and it is set deliberately rather than left to `silent`
alone: if the determination is the thing that stands, every one of these four sites returns the wrong value today,
and `work.py next` must be able to see that (`silent` alone is not an actionable harm flag — it qualifies a wrong
answer rather than naming one). If instead the code is what stands, the flag drops and this becomes documentation
work. **Nobody has decided which**, which is the defect.

It is `silent` because the difference is **invisible in a MOVE**: §14.6.8.5 — *"If the sending data item or
literal is zero-length, the entire receiving data item is space filled."* A zero-length sender and a
spaces-of-locale-length sender produce the identical receiver. The difference **is** observable under `DISPLAY` of
the function result and under reference modification, and under `FUNCTION LENGTH`.

## ⛔ The one green witness on this path cannot discriminate

`tests/conformance/2014/pb64t4_locale_functions.cob` already has the leg:

```cobol
MOVE FUNCTION LOCALE-DATE("20261399") TO S
DISPLAY "ARG=[" FUNCTION TRIM(S) "]"
```

and its `.out` expects `ARG=[]`. That line is green under **either** substituted value — the MOVE space-fills `S`
from a zero-length sender by §14.6.8.5, `TRIM` then removes the spaces, and the spaces answer trims to the same
empty string. The path has been exercised since PB64 T4 landed and the test has never been able to contradict the
code. (This is `green_gates_arent_evidence` in the corpus: a leg that runs, passes, and measures nothing.)

None of row `DOC-A.1-90`'s five `test-ref`s names a LOCALE function at all — measured: `pb65_domain_guards`,
`l1_argument_default_boolean_length`, `pb59_char_representative`, `l1_char_national_argument_bound`,
`l1_char_national_also_positions` contain no `LOCALE-DATE`/`LOCALE-TIME` reference.

## Fix shape

1. **Decide the value**, from the determination's own words rather than from the code: an alphanumeric result
   whose length is locale-derived is not the stated zero-length case, so the default reading is *spaces of the
   length the locale format would have produced*. If zero-length is kept, the determination must say so and say
   why a locale-derived length is treated like an argument-derived one.
2. **State it in `docs/CONFORMANCE.md` §7 row `DOC-A.1-90`** so the rule derives its own list rather than carrying
   an enumeration (see `kb/Work/PB471`, which is the same wording problem seen from the FORMATTED-* side).
3. **Cite the code to it.** The four sites go through the one mechanism the row already names — `ArgumentError`
   (the zero value of the returned type) or `ArgumentErrorZeroLength` — never a bare `return ""`, which is how
   the drift got in.
4. **Write a witness that discriminates**: `DISPLAY "[" FUNCTION LOCALE-DATE(W-BAD) "]"` and
   `FUNCTION LENGTH(FUNCTION LOCALE-DATE(W-BAD))` — never a MOVE — with a legal-argument control leg beside it,
   covering all three functions and all four sites.
5. **Re-verdict `DOC-A.1-90`** with the widened `code-location` and the new `test-ref`.

## Landed — 2026-09-04 — SPACES, one position, out of the same rule table as every other intrinsic

**The question is answered the way the determination's own words answer it: the result is SPACES.** Row
`DOC-A.1-90` settles the class by asking what determines the returned item's LENGTH, and for these three
§15.52.4 / §15.53.4 / §15.54.4 rule 3 all say the same thing — it depends on the format
indicated in the LOCALE. Rejecting argument-1 leaves the locale intact, so the row's zero-length class (a
length *derived from the rejected argument*) does not reach these sites and its general clause does; the
function type is alphanumeric (§15.52.1 / §15.53.1 / §15.54.1), so the answer is spaces.

**ONE space, and that number is derived rather than chosen.** DETERMINATION L10 renders `d_fmt` / `t_fmt` as
the culture's own patterns, whose rendered width varies with the VALUE as well as with the format (`en-US`'s
`M/d/yyyy` is 8 positions on 2 February and 10 on 31 December), so once the value is rejected the format
alone fixes no width to fill — "spaces of the length the locale would have produced" is not a length
that exists. The standard answers exactly that shape itself, and the citation was `--check`ed:

```
python scripts/spec/cite.py --check 15.30.3 "the returned value is one alphanumeric space character"
OK  §15.30.3 1)  (Returned value rules)
```

§15.30.3 r1/r2a is EXCEPTION-LOCATION — an alphanumeric function whose length is "based on its
contents" — answering *one alphanumeric space character* when the contents are absent. Row DOC-A.1-90
adopts it, which is also what makes the answer locale-independent and therefore testable.

**The fix is the rule table, not the four sites.** PB383 had left the text side with ONE mechanism
(`ArgumentErrorZeroLength`) and the other class — spaces — spelled as a literal at four CHAR /
CHAR-NATIONAL guards, which is why a fifth class member could be written wrong without anything noticing.
Now both classes are values in `CobolNet.Runtime.Exceptions.ArgumentSubstitute` (`ZeroLength`, `Spaces(n)`)
with `ArgumentErrorZeroLength` / `ArgumentErrorSpaces(detail, positions)` as the raise-and-substitute
expressions over them, and `positions` deliberately has NO default so the length stays the call site's cited
decision (`CobolLocale.LocaleSubstitutePositions`, `CobolIntrinsics.CharPositions`). Twelve sites moved onto
the table — the four LOCALE guards (the defect), CHAR ×2 / CHAR-NATIONAL ×2, CONVERT's
§15.19.3 r1 arm, SUBSTITUTE's three §15.87.2 shape arms, and the three post-predicate arms in
`FormattedTime` / `FormattedDatetime` whose raise lives in a `bool` screen — and only the LOCALE four
changed VALUE. `ArgumentSubstituteDriftTests` then bans the shape structurally over
`src/Cobol.Net.Runtime/Intrinsics`: a returned string literal of nothing but spaces is, in that folder,
always one of the two classes and never a computed result, so the ban needs no exemption list; its second
fact feeds the detector the verbatim pre-fix lines so the watchdog is shown to bite.

**Witnesses that can tell the two answers apart**, since the existing one could not:
`tests/conformance/2014/pb470_locale_argument_substitute` (all four guards, plus legal controls through the
same locale, plus the CHECKING-ON arm proving the condition is set and nothing is stored) and
`tests/conformance/2002/pb470_locale_argument_substitute_2002` (the two functions COBOL-2002 has). Every leg
is read twice — a bracketed DISPLAY (§14.9.11.4 GR1) and a `FUNCTION LENGTH` read-out
(§15.50.4 r3) — and nothing is MOVEd except the one leg whose point is that nothing arrived.
Measured before: `D-BAD=[]` / `LEN=00`. After: `D-BAD=[ ]` / `LEN=01`.
