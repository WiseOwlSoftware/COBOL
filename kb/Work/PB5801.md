# PB5801 - THE COMPILER CRASHES (an unhandled InvalidOperationException, 'no Place was built for data item') when a level 66 item is named as FILE STATUS, LINAGE, DEPENDING ON, RELATIVE KEY or a report CONTROL (every edition; legal source)

**The most serious note of the four batches of 1985 code-read rulings: the compiler ends with an unhandled .NET exception on legal source.** A level 66 item that renames one elementary item, named as FILE STATUS, a LINAGE operand, RECORD VARYING DEPENDING ON, RELATIVE KEY or a report CONTROL operand, ends the compiler with an unhandled `System.InvalidOperationException` ("no Place was built for data item") and a full .NET stack, with no COBOL diagnostic, at `--std 85` and at `--std 2023` alike (exit 1, with `--compile-only` too). Each use is legal: "all of the data attributes of data-name-2 become the data attributes for data-name-1" (`§1985:VI.5.11.4 GR2`). Ruling: UPHELD (b), harm crashes, on legal source (the checker's confidence: high). I ran the FILE STATUS case myself at `--std 85`, compile only: it ends with the exception below (exit 1).

**The exception (the checker's runs, `ren_fs.cob`; identical at `--std 2023`).** First line:

`Unhandled exception: System.InvalidOperationException: no Place was built for data item 'FS66' when binding finished ... (kb/Work PB2375)`

Top five stack frames: `PlaceTable.Of` <- `OccurrenceOf` <- `FileStatusOf` <- `SequentialIoEmitter.EmitStoreFileStatus` <- `EmitOpen`.

**The five uses (each program is in full below; each crashes at `--std 85` and at `--std 2023`, exit 1).**

| Use | Program | Item | Stack, top to bottom (the checker's) |
|---|---|---|---|
| FILE STATUS | `ren_fs.cob` | `FS66` | `PlaceTable.Of` <- `OccurrenceOf` <- `FileStatusOf` <- `SequentialIoEmitter.EmitStoreFileStatus` <- `EmitOpen` |
| LINAGE | `ren_lin.cob` | `RN66` | `PlaceTable.Of` <- `SequentialIoEmitter.LinageOpExpr` <- `LinageArg` <- `EmitOpen` |
| RECORD VARYING ... DEPENDING ON | `ren_dep.cob` | `RN-LEN` | `PlaceTable.Of` <- `SequentialIoEmitter.VaryingDepending` <- `VaryingLengthArg` <- `EmitWrite` |
| RELATIVE KEY | `ren_rel.cob` | `K-REN` | `PlaceTable.Of` <- `OccurrenceOf` <- `RelativeKeyOf` <- `KeyedIoEmitter.Rrn` <- `EmitWrite` |
| report CONTROL | `ren_ctl.cob` | `RX` | `PlaceTable.Of` <- `OccurrenceOf` (CONTROL IS RX) |

Control: `ren_ctl0.cob` names the renamed item itself (`CONTROL IS CX`) and compiles at both editions (exit 0).

**What is wrong.** The compiler passes every screen and then throws during C# emission. The place table's item set omits level 66 entries, and the file-clause and CONTROL paths ask `PlaceTable.Of` of the 66 item itself. It is not a C# backend error and not an under-rejection. For `1985-SR-XIII.3.7.3-2` the row's own check is right for every operand that compiles (`ScreenControlItemsDistinct`, a comparison of resolved items); whether `CX RX` names one data item or two is a separate reading the crash pre-empts. The PIC 99 FILE STATUS history of `1985-SR-VII.2.5.3-2` (COBOL2455) is a different input and untouched.
