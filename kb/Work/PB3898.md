# PB3898 — national-items-displayed-as-utf-16-bytes--initialize-national-no-op: INITIALIZE of an elementary PIC N item generates no code (item left unchanged)

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S4) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\national-items-displayed-as-utf-16-bytes--initialize-national-no-op.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\national-items-displayed-as-utf-16-bytes--initialize-national-no-op\`.

## Summary

`INITIALIZE NAT`, where NAT is an elementary `PIC N` item, compiles to nothing: the item keeps its old content. The
standard sets it to national spaces. The same statement on a `PIC X` item compiles to a space fill. A national item
subordinate to an initialized group is skipped the same way: `INITIALIZE GRP` over `05 GN PIC N(1)` and `05 GX PIC X(1)`
emits a fill for GX only, and GN keeps its value (probe `gprobe.cob`). Found while reducing
the "national items displayed as UTF-16 bytes" family (probe `sprobe.cob`); no fuzz program of the five nights carries
it. It happens under `-std=cobol2014`, `cobol2002`, `ibm`, `mf` and the default dialect. Class: wrong output.

## Minimal test case

Free reference format (`-fformat=free`), 9 lines, written for this record.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. NINIT.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 NAT PIC N(1) VALUE N"A".
PROCEDURE DIVISION.
INITIALIZE NAT
IF NAT = N"A" DISPLAY "UNCHANGED" ELSE DISPLAY "CHANGED" END-IF
STOP RUN.
```

File: `E:\COBOL-coord\scratch\op\pb3838\records\national-items-displayed-as-utf-16-bytes--initialize-national-no-op.cob`.

## Environment

- `cobc (GnuCOBOL) 3.2.0`, Ubuntu package `gnucobol3 3.2-4build1`, WSL2 (Linux 6.18.54.1-microsoft-standard-WSL2 x86_64).
- Commands:
  ```
  cobc -std=cobol2014 -fformat=free -x ninit.cob
  ./ninit
  cobc -std=cobol2014 -fformat=free -C ninit.cob    # to read the generated C
  ```

## Observed result

Compile exit code 0, with `-Wunfinished` warnings for USAGE NATIONAL and national literals. Run exit code 0, output
`UNCHANGED`. In the generated C the comment line `/* Line: 7 : INITIALIZE : ninit.cob */` is followed by no
statement. The probe `work\national-items-displayed-as-utf-16-bytes\iprobe.cob` initializes a `PIC N(2)` and a
`PIC X(2)` item after moving "AB" to both: the PIC X item gets `memset (b_2, (unsigned char)' ', 2)` and changes, the
PIC N item has no code and does not change; the same with `-std=default`, `cobol2002`, `ibm` and `mf`.

## Expected result (per ISO)

Output `CHANGED` (NAT becomes one national space).

- ISO/IEC 1989:2023 §14.9.20.4 4) (checked): "the effect of the execution of the INITIALIZE statement is as though a
  series of implicit MOVE or SET statements" were executed.
- §14.9.20.4 5) c) 4. (checked): an elementary item referenced by identifier-1 is a receiving operand when "Neither the
  REPLACING phrase nor the VALUE phrase is specified."
- §14.9.20.4 6) (checked), the table of rule 6 c): for a national receiving operand the sending operand is "Figurative
  constant national SPACES".

Edition: the 2009 committee draft for ISO/IEC 1989:2014 (CD 1.2) carries the same INITIALIZE table entry ("National:
Figurative constant national SPACES"); the national category is a 2002 feature.

Edition as recorded by the adjudicator: 2014 (INITIALIZE national entry since 2002; same table in the 2009 CD); also every cobc dialect. `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Class

GNUCOBOL-DEFECT: wrong output (the statement has no effect).

## Our compiler (WiseOwl)

WiseOwl COBOL (built from main 6ed90bd1c), `cobol ninit.cob --std 2014 --source-format free -o ninit.dll`, then
`dotnet ninit.dll`: compile exit 0, run exit 0, output `CHANGED`.

## Fix site (GnuCOBOL 3.2 source, read observationally)

`cobc/codegen.c`:

- `output_initialize` (line 5683): for `INITIALIZE_DEFAULT` it asks `initialize_uniform_char`; when that returns -1 it
  falls through to `INITIALIZE_COMPOUND` and calls `output_initialize_compound`, which walks only `children`. An
  elementary field has none, so nothing is emitted.
- `initialize_uniform_char` (line 4664): returns a fill byte for binary, numeric DISPLAY and alphanumeric types and -1
  for the rest, including `COB_TYPE_NATIONAL`, which sends an elementary national item down the compound path.

- `output_initialize_compound` (the loop over children, around line 5490): a national child is `INITIALIZE_DEFAULT`
  with no uniform character too, and the group probe shows no code for it either.

The elementary case needs `output_initialize_one` (as for `INITIALIZE_ONE`), and the national fill it then produces
must be the national space (see `national-items-displayed-as-utf-16-bytes--national-space-fill`: the default path,
`output_initialize_to_default`, line 5224, moves `cb_space`, which fills with 0x20 bytes).

## Draft issue

**Title:** INITIALIZE of an elementary PIC N item generates no code (item left unchanged)

**Body:**

Environment: GnuCOBOL 3.2.0 (Ubuntu gnucobol3 3.2-4build1), x86_64 Linux. Same result with `-std=default`, `cobol2002`,
`cobol2014`, `ibm`, `mf`.

Steps: `cobc -std=cobol2014 -fformat=free -x ninit.cob && ./ninit` with

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. NINIT.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 NAT PIC N(1) VALUE N"A".
PROCEDURE DIVISION.
INITIALIZE NAT
IF NAT = N"A" DISPLAY "UNCHANGED" ELSE DISPLAY "CHANGED" END-IF
STOP RUN.
```

Observed: `UNCHANGED`; `cobc -C` shows no statement after the INITIALIZE line comment. INITIALIZE of a PIC X item in
the same position emits a space fill. INITIALIZE of a group skips its PIC N children the same way.

Expected: `CHANGED`. ISO/IEC 1989:2014 (2023 §14.9.20.4 rules 5c4 and 6c): with neither REPLACING nor VALUE, an
elementary national item is a receiving operand and receives "Figurative constant national SPACES".

Cause: in cobc/codegen.c `output_initialize`, `initialize_uniform_char` returns -1 for a national field and the
`INITIALIZE_DEFAULT` case falls through to `output_initialize_compound`, which only visits children.
