# PB1523 — OPEN

## The rule

> 1) A constant-name, data-name, file-name, report-name, or screen-name described using a GLOBAL clause is a global name. All data-names subordinate to a global name are global names. All condition-names associated with a global name are global names.

`cite.py --check 13.18.27.4 "All data-names subordinate to a global name are global names"` → OK §13.18.27.4 1).

> 3) If the GLOBAL clause is used in a data description entry that contains the REDEFINES clause, it is only the subject of that REDEFINES clause that possesses the global attribute.

`cite.py --check 13.18.27.4 "REDEFINES"` → OK §13.18.27.4 3).

The records of a GLOBAL FD are subordinate to a global name, and GR3 expressly contemplates GLOBAL on a REDEFINES entry. All three programs below are legal and must compile and run.

## Mechanism and code sites

- `src/Cobol.Net.Compiler/Binding/BinderDriver.cs#BindUnitData` adds `DataBinder.GlobalBridgesOf(g)` for EVERY `CallGlobalRoot`
  (`unit.Bridges.AddRange` per root). Two global roots that share one StringCanonical redefines class (every GLOBAL FD with
  ≥ 2 record descriptions; a GLOBAL redefiner of a GLOBAL item) each contribute the shared `_redef_<anchor>` backing bridge,
  so the nested class declares `private ref string _redef_R1 => ref __outer._redef_R1;` twice.
- `src/Cobol.Net.Compiler/Binding/DataBinder.Linkage.cs#GlobalBridgesOf` emits a Field bridge for a GLOBAL redefiner of a
  NON-StringCanonical (alias) class — a member the container never declares — and does not bridge the anchor it aliases.
- Emission: `src/Cobol.Net.Compiler/CodeGen/ProgramEmitter.cs` (bridge members).

Fix shape (rule 5): the bridge set is a SET keyed on the emitted member, computed once per containee from the union of the
global roots, and a redefines tier contributes its storage anchor (never a member the container does not emit). Pair it with a
drift test that compiles a containee against every redefines-tier shape the class table can produce.
