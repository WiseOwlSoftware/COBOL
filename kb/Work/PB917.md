# PB917 — OPEN — repetition where the format prints a bracket, not an ellipsis

Sources: the `PB511` report and the `PB511-finisher` report, which independently reach the same conclusion
and disagree only about whether it belongs with PB544. The finisher is right that it is its own mechanism:
the subject is not USAGE, it is closed general formats.

## The measurement

`<scratch>/reg7/probe/h_double_usage.cob`, `--std 2023`, `--run`:

```cobol
       01 N USAGE DISPLAY USAGE BINARY PIC 9(3).
       PROCEDURE DIVISION.
           MOVE 12 TO N
           DISPLAY "N=" N
```

```
N=012
```

No diagnostic at any edition. The LAST clause wins, silently, and the user's first USAGE is discarded
without a word. A reader of that entry cannot tell which usage the item has without knowing this
compiler's override order.

## The rule — and it is NOT a per-clause rule

```
$ python scripts/spec/cite.py --check 5.2.6.2 "Brackets"
OK  §5.2.6.2   (Brackets)
    Brackets, [ ], enclosing a portion of a general format indicate that the syntax element contained
    within the brackets … may be explicitly specified or that portion of the general format may be omitted.
$ python scripts/spec/cite.py --check 5.2.7 "ellipsis"
OK  §5.2.7   (Ellipses)
    In the general formats, the ellipsis represents the position at which the user elects repetition of a
    portion of a format.
```

§13.16.2 Format 1 prints `[ usage-clause ]` ONCE and carries **no ellipsis** on that slot. §5.2.6.2 grants
exactly two readings — present once, or absent — and §5.2.7 is the only thing in the meta-language that
licenses repetition. So the second USAGE is non-conforming BY THE GENERAL FORMAT, which is the same §4.2.2
reading COBOLNET2117-2120 and COBOLNET2172 already stand on.

⚠ There is no general per-clause repetition rule to lean on instead:
`cite.py --find "shall not be specified more than once"` returns only §12.3.7.3, §14.9.28.3 and
§14.9.39.3. Reading this as "USAGE needs a repetition rule" would produce one screen per clause in the
language. It is a rule about FORMATS.

## The code site

`src/Cobol.Net.Compiler/Binding/DataBinder.cs#BindEntry` — the `firstUsage` / `extraUsages` capture that
the PB511 change set landed IS the structure this should be enforced from; it already knows there was more
than one. And `src/Cobol.Net.Compiler/Binding/Validation/ClosedFormatPass.cs` already owns the sibling
question "a word this format does not print", which is where the general answer belongs.

## Why the fix is one pass, not one screen

`ClosedFormatPass` is the right owner because the obligation is uniform: for every closed general format,
a bracketed slot with no ellipsis may be filled at most once. Written there, with the clause list derived
from the same source the grammar is derived from, the NEXT clause is covered for free — written in
`BindEntry` as an `extraUsages.Count > 0` test, it covers USAGE and nothing else. CLAUDE.md rule 5.
