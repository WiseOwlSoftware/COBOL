# PB1732 — a Linux gate before CI

## What happened (2026-09-28/29, train 71b)

Train 71b's first `push-main` (head `4fdc6897c`, CI run 36533008383) was RED in exactly one place:
- job `Greenfield unit + characterization (Linux)`;
- test `GateLegDriftTests.Arm5_TheRootAudit_FiresOnPlantedOffenders`, which expected 3 and got 0.

Group F's (PB1719) new test plants the Windows root `E:\COBOL-wt\battery87`. `GateLegAudit.RootCarrying` normalizes
it with `Path.GetFullPath`, and on Linux that string is RELATIVE, so no planted offender matched. It was green on
Windows. The lander dropped F and re-pushed.

**Cost:** one ~30-minute CI round trip, a second push, and M12 (with M13 behind it) carried to the next session.

## Root cause

- No gate before CI ran anything on Linux. Implementer gates (`build-local.ps1`) and lander gates both run on the
  Windows host, and CI's Linux jobs were the first Linux run a change ever got.
- The practice already existed: the orchestrator's memory `reference_wsl_linux_repro` says "run it BEFORE pushing,
  not after CI goes red", and the owner's standing instruction is to use WSL. But it lived only in memory, not in
  MANDATORY-PRACTICES or any brief, so no agent ever ran it.
- The orchestrator wrote a WSL step into group E's spec by hand (the gate-slot self-test) but not into F's, although
  F's change (test names, repository paths) was plainly platform-sensitive.

## The fix

- **`scripts/linux-gate.sh`** runs CI's Linux test legs under WSL, in a LINUX CLONE OF THE COMMITTED HEAD. It is a
  `--shared` clone into `~/linux-gate/<tree>`, which borrows the Windows object store read-only. Each leg's project is
  built there with the Linux SDK and tested there; the GnuCOBOL corpus is copied in, or fetched as CI does.
  - `pwsh` and Java are now in WSL (`setup-wsl.sh`), so the ANTLR pre-build that used to block Linux builds runs.
  - At `4fdc6897c` (train 71b with F) it reproduced CI exactly: `Arm5` the ONE red, the other legs green, 195 s.
- **Two earlier designs failed**, each on a measurement:
  1. **Windows-built binaries run `--no-build`.** The Conformance tests find their goldens through
     `[CallerFilePath]`, baked in as `E:\…` paths: 363 false reds.
  2. **Running in the Windows tree with `GIT_DIR`/`GIT_WORK_TREE` EXPORTED**, so Linux git could read a worktree
     whose `.git` names an `E:/` gitdir. ⛔ It damaged the shared repository (2026-09-29, wave 72).
     - The variables reached every test process. `gate_slot.py`'s self-test (git init, an empty commit and
       worktree add, in its own temp repositories) was redirected into the REAL repository.
     - `core.worktree = /mnt/e/COBOL/.claude/worktrees/wf_10d5c11f-c83-1` landed in the shared `E:\COBOL\.git\config`,
       and every git command in every checkout failed ("Invalid path '/mnt'").
     - Group G (PB1719) caught it and undid its stray commit and worktree. The owner removed the config line; the
       auto-mode classifier had denied the agent that change.
     - The clone design exports NOTHING. The script's only git calls on the Windows repository are two reads, with
       their settings passed inline.
     - G is also making `gate_slot.py`'s self-test scrub the repository-selection variables, a second, independent
       guard.
- **Measured cost of all three legs** on main at `9a0ab2dd4`: unit ~143 s, characterization ~3 s, conformance 149 s
  including the Linux build (9,319/9,319). About 5 minutes in all.
- **A platform-sensitivity detector was built and DELETED the same night.** At the owner's suggestion,
  `scripts/platform_sensitive.py` flagged diffs touching constructs whose behavior differs by platform, to add the
  conformance leg only when needed.
  - On F's branch it flagged the exact failing line and the planted `E:\` literal; on B's branch it printed `no`.
  - Once the whole Linux population measured at ~5 min, no selection was worth its possible misses (PB1708, "order,
    don't skip"), and a detector with no job is a second mechanism. So every gate runs every leg.
- **MANDATORY-PRACTICES:**
  - **I8** (implementers): all three legs under WSL after the Windows gate is green and committed.
  - **L10** (landers): all three legs before `push-main`; a red drops its cluster.
  - Wired into `fix-lane-implementer-brief.md` 7b, `dispatch-spec-implementer.md`, `lander-train-brief.md` 3b and
    `lander-brief.md` 3b. `check_practices.py` refuses a brief without them.
- **`LinuxGateDriftTests`** (Unit): every test project a Linux job of `build-and-test.yml` runs is a leg of
  `linux-gate.sh`. It was seen RED on a planted missing leg.
- **Line endings.** The script's reads of the Windows tree pass `core.autocrlf=true` inline. Git for Windows sets it in its SYSTEM config, which
  Linux git never reads, and without it a clean tree showed 9,543 "modified" files.

## Limits

- The gate cap (PB1720) does not span operating systems, so WSL legs are not counted against it.
- The conformance leg builds only COMMITTED HEAD. It prints a note when tracked changes are uncommitted.
- WSL is not CI: `ubuntu-latest` versus the local distro, and Debug here versus CI's mixed Debug and Release. It
  catches platform assumptions, not every CI difference, and push-main's CI run remains the proof.
