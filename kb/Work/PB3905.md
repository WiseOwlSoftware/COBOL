# PB3905 — subscript-out-of-range-refused-at-compile-time--checking-on: cobc 3.2: literal subscript beyond OCCURS refused at compile time with EC-BOUND-SUBSCRIPT checking enabled; with -frelax-syntax-checks the enabled run-time check is skipped

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S5) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\subscript-out-of-range-refused-at-compile-time--checking-on.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\subscript-out-of-range-refused-at-compile-time--checking-on\`.

## Summary

A literal subscript greater than the OCCURS maximum (`E(3)` on `OCCURS 2`) is legal syntax: the out-of-range value is
the run-time exception condition EC-BOUND-SUBSCRIPT (fatal). The standard lets an implementation refuse to produce
executable code for a fatal condition it detects at compile time only when checking for it is not enabled. cobc 3.2
refuses the reference ("subscript of 'E' out of bounds: 3") also when checking is enabled by
`>>TURN EC-BOUND-SUBSCRIPT CHECKING ON` or `-fec=EC-BOUND-SUBSCRIPT`. With `-frelax-syntax-checks` the error becomes a
warning and the program compiles, but the run-time check is skipped for a literal subscript even though checking is
enabled: the program reads past the table and ends normally.

With checking not enabled the compile-time refusal is implementor latitude: sibling record
`subscript-out-of-range-refused-at-compile-time--checking-off` (NOT-A-DEFECT).

## Minimal test case

Free reference format (`-fformat=free`), `records/subscript-out-of-range-refused-at-compile-time--checking-on.cob`:

```cobol
>>TURN EC-BOUND-SUBSCRIPT CHECKING ON
IDENTIFICATION DIVISION.
PROGRAM-ID. SUBOOR.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 T.
   05 E PIC X OCCURS 2 VALUE "A".
PROCEDURE DIVISION.
    DISPLAY "[" E(3) "]"
    STOP RUN.
```

## Environment

- `cobc (GnuCOBOL) 3.2.0`, Ubuntu package `gnucobol3 3.2-4build1`, WSL2 Ubuntu on Windows 11.
- `cobc -std=cobol2014 -fformat=free -x -o suboort suboort.cob`
- Without the directive (`suboor.cob`): `cobc -std=cobol2014 -fformat=free -fec=EC-BOUND-SUBSCRIPT -x -o suboor
  suboor.cob`: the same error.
- `cobc -std=cobol2014 -fformat=free -frelax-syntax-checks -x -o suboortr suboort.cob && ./suboortr`
- Witness: n5-fz05091 (`WS-TWO(3)` on `OCCURS 2`).

## Observed result

Strict:

```
suboort.cob:9: error: subscript of 'E' out of bounds: 3
    7 |    05 E PIC X OCCURS 2 VALUE "A".
    8 | PROCEDURE DIVISION.
    9 >     DISPLAY "[" E(3) "]"
   10 |     STOP RUN.
   11 | <EOF>
```

cobc exit code 1.

With `-frelax-syntax-checks`: `suboort.cob:9: warning: subscript of 'E' out of bounds: 3 [-Wothers]`, cobc exit 0; the
run prints `[`, a NUL byte, `]` (bytes `[ \0 ]`), exit 0: no EC-BOUND-SUBSCRIPT, no abnormal termination.

## Expected result (per ISO)

ISO/IEC 1989:2023, each citation checked with `scripts/spec/cite.py --check`:

- §8.4.2.3.3 (syntax rules for subscripts) has no range rule. §8.4.2.3.4 rule 2): "If the value of the subscript is not
  a positive integer or is less than one or is greater than the highest permissible occurrence number, the
  EC-BOUND-SUBSCRIPT exception condition is set to exist."
- §14.6.13.1.6, the exception table: EC-BOUND-SUBSCRIPT, Fatal, "Subscript out of bounds".
- §7.3.25.4 rule 6): with the ON phrase "checking for the exception condition associated with exception-name-1 is
  enabled for the procedure division statements and procedure division headers that follow in the compilation group".
- §14.6.13.1.3 rule 7): "If checking for the exception condition is enabled, execution of the run unit is terminated
  abnormally". The paragraph after rule 8): "If checking is not enabled for a fatal exception condition and the
  exception condition is detected by the compiler, the implementor is not required to produce executable code."

With checking enabled the program is legal and its run must terminate abnormally at the DISPLAY, before anything is
displayed. Expected: compiles; the run terminates abnormally with EC-BOUND-SUBSCRIPT. (The strict-mode part rests on
the condition in the §14.6.13.1.3 paragraph; the `-frelax-syntax-checks` part, a compiled program that runs past the
table with checking enabled, contradicts rule 7 directly.)

Edition: subscripting, the fatal EC-BOUND-SUBSCRIPT (ISO/IEC 1989:20xx CD 1.2, 2009-08-23: "EC-BOUND-SUBSCRIPT Fatal
Subscript out of bounds"), the TURN directive and the compile-time paragraph (same wording in that CD and in the 2002
text) are all in 2014.

Edition as recorded by the adjudicator: 2014. `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Class

Rejects legal ISO source (with exception checking enabled); with `-frelax-syntax-checks`, enabled checking not
performed (wrong output).

## Our compiler (WiseOwl)

`cobol.exe suboort.cob --std 2014 --source-format free -o suboort.dll`: exit 0; `dotnet suboort.dll`: exit 1, stderr
`abnormal run-unit termination: EC-BOUND-SUBSCRIPT (fatal): subscript 3 is outside 1..2 (ISO 8.4.2.3.4 GR2)`.
Without the directive WiseOwl compiles and the run prints `[]`, exit 0 (checking off: implementor-defined).

## Fix site (GnuCOBOL 3.2 source, read observationally)

`cobc/typeck.c`, function `cb_build_identifier` (line 2517), the subscript loop (lines 2677-2702; the `continue` at line 2696): for a literal
subscript outside 1..`occurs_max` it calls `cb_syntax_check_x` ("subscript of '%s' out of bounds: %d", line 2694),
an error unless relaxed syntax checks are on, with no test of `CB_EXCEPTION_ENABLE (COB_EC_BOUND_SUBSCRIPT)`; when
relaxed it `continue`s past the run-time check generation (the comment says it skips the run-time check "as MF does"),
so the following `CB_EXCEPTION_ENABLE (COB_EC_BOUND_SUBSCRIPT)` block (line 2702) is never reached for that
subscript. `cb_syntax_check_x` is in `cobc/error.c` (line 940). A fix, when EC-BOUND-SUBSCRIPT checking is enabled,
warns and falls through to the run-time check instead of refusing or skipping it.

## Draft issue

**Title:** cobc 3.2: literal subscript beyond OCCURS refused at compile time with EC-BOUND-SUBSCRIPT checking enabled; with -frelax-syntax-checks the enabled run-time check is skipped

**Body:**

Environment: GnuCOBOL 3.2.0 (Ubuntu `gnucobol3 3.2-4build1`), Linux x86_64.

Steps: save as `suboort.cob`, run `cobc -std=cobol2014 -fformat=free -x -o suboort suboort.cob`, then
`cobc -std=cobol2014 -fformat=free -frelax-syntax-checks -x -o suboortr suboort.cob && ./suboortr`.

```cobol
>>TURN EC-BOUND-SUBSCRIPT CHECKING ON
IDENTIFICATION DIVISION.
PROGRAM-ID. SUBOOR.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 T.
   05 E PIC X OCCURS 2 VALUE "A".
PROCEDURE DIVISION.
    DISPLAY "[" E(3) "]"
    STOP RUN.
```

Observed: strict, `suboort.cob:9: error: subscript of 'E' out of bounds: 3`, exit 1 (also with `-fec=EC-BOUND-SUBSCRIPT`
in place of the directive). Relaxed, a warning, then the run prints `[`, a NUL byte, `]` and exits 0.

Expected: the program compiles and its run terminates abnormally with EC-BOUND-SUBSCRIPT at the DISPLAY. An
out-of-range subscript is a run-time condition, not a syntax error (ISO/IEC 1989:2023 8.4.2.3.4 rule 2;
EC-BOUND-SUBSCRIPT is fatal, 14.6.13.1.6). 14.6.13.1.3 lets an implementation omit executable code for a fatal
condition detected at compile time only "if checking is not enabled"; with checking enabled (7.3.25.4 rule 6) rule 7
requires abnormal termination. The relaxed build shows the run-time check being skipped although checking is enabled.

Cause: in `cb_build_identifier` (cobc/typeck.c) the literal-subscript test calls `cb_syntax_check_x` regardless of
`CB_EXCEPTION_ENABLE (COB_EC_BOUND_SUBSCRIPT)`, and under relaxed checks `continue`s past the run-time check.
