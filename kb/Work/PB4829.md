# PB4829 - IntrinsicBinder.CheckConcatArgs cites ISO 9.3.6 SR3 as the general rule that a numeric literal has implied usage DISPLAY; 9.3.6 3) scopes it to method invocation

**What the report says (the reviewer's words).** R1-1 LEAD (low, not blocking at round 1): `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs:2118` The new comment (and the golden header, the note and the DEVLOG) cites ISO 9.3.6 SR3 as the general rule that a numeric literal has implied usage DISPLAY, but 9.3.6 3) scopes that statement to method invocation: For the purpose of determining an exact match (specs/ISO_COBOL.md:10710). The refusal itself is right on 15.18.3 r2 alone: a numeric literal is never usage national, so if any argument is usage national the rule is broken whatever usage the literal is assigned. Re-run: `cite.py --check 9.3.6 "For the purpose of determining an exact match"` is OK (§2023:9.3.6 3), Method invocation), consistent with the reviewer. The comment is still at IntrinsicBinder.cs:2119-2120.
