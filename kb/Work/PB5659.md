# PB5659 - SET of an ACTIVE-CLASS receiver at 2002 (COBOL0867)

**The lead.** "SET of an ACTIVE-CLASS receiver at 2002 (OoConformance.cs ~486-573, COBOL0867 citing §2023:14.9.39.3 SR14); repro
E:/COBOL-coord/scratch/w20262043g/prop.cob --std 2002. Not in a file changed here."

**Repro run once (2026-11-15, on the Debug `cobol.exe` in `E:/COBOL/src/WiseOwl.Cobol.Cli/bin/Debug/net10.0`, dated Nov 8, so older than main):** `cobol prop.cob --std 2002`
gives COBOL2790 twice (the GET and SET PROPERTY methods use ACTIVE-CLASS items, citing §2023:11.7.3 SR6 / SR7) and then
`prop.cob(15,12): error COBOL0867: SET '__PROP-TEMP-200002' TO 'A': an object reference described 'CPA' does not conform to a receiver described with the
ACTIVE-CLASS phrase (ISO §2023:14.9.39.3 SR14 - its closed list of senders is an ACTIVE-CLASS reference, SELF and NULL)` on `SET B TO SELFREF OF A`: the
receiver is the compiler's own property temporary. The fixer re-runs it on a current build first.

**What the 2002 text says.** The same SR exists at 2002: `§2002:14.8.35.2 SR14` "If the data item referenced by identifier-3 is described with an ACTIVE-CLASS
phrase, the data item referenced by identifier-4 shall be one of the following" (`cite.py --check` on the 2023 twin `§2023:14.9.39.3 SR14`, same words: OK; the 2002
text found with `--edition 2002 --find`). So the refusal may be right and the defect only the message's edition (it names 2023 at 2002), or the
synthesized `__PROP-TEMP` receiver wrongly carries the ACTIVE-CLASS description at 2002. The 2002 property rules differ from 2023's `11.7.3 SR6/SR7` bans
(PB5598's goldens pb5598-active-class-property-2002 / -refused show 2002 accepts an ACTIVE-CLASS property): the adjudication is which of the two it is.

**Sites:**, `src/WiseOwl.Cobol.Runtime/Control/ObjectReferenceSet.cs` (`ObjectReferenceSet.Refusal`, `ObjectReferenceSet.Rules2023`), `src/WiseOwl.Cobol.Compiler/Oo/OoConformance.cs` (`OoConformance.SetRules`, `OoConformance.ClassNameSenderRule`)
- `src/WiseOwl.Cobol.Compiler/Oo/OoConformance.cs` (`OoConformance.ActiveClassFormalMismatch`, `OoConformance.ObjectReferenceContentMismatch`)
- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/OoBinder.cs` (`OoBinder.OoBindSetObjectRef`)

**Sibling sweep.** Every diagnostic in `OoConformance` / `OoBinder` that cites `§2023:` while firing at `--std 2002` (the message's edition must be the
compiler's active one, `EditionInfo`); the synthesized property temporaries (`__PROP-TEMP-`) created in `CompilerTemps` and what description each is given.

**Landed (wave 20262165 group A, 2026-11-24): the SET object-reference refusal cites the edition's SET rule and names the receiver as written.** Adjudicated: the refusal is RIGHT at 2002. §2002:8.4.2.9.2 SR6 gives a receiving object property the description of the set property method's USING parameter (an ACTIVE-CLASS reference), and §2002:14.8.35.2 SR14 admits only an ACTIVE-CLASS reference, SELF or NULL into it. The defect was the message: it cited §2023:14.9.39.3 SR14 and named the compiler's `__PROP-TEMP-200002`. `ObjectReferenceSet.Refusal` now takes the SET rules clause (`OoConformance.SetRules`: §2002:14.8.35.2, §2014:14.9.35.2, §2023:14.9.39.3, whose SR8 to SR14 and their items are numbered alike); the run time passes `ObjectReferenceSet.Rules2023`. `OoBinder.OoBindSetObjectRef` names each receiver by `WrittenSource`. After: `SET 'SELFREF OF A' TO 'A': ... (ISO §2002:14.8.35.2 SR14 ...)`. Golden `wiseowl/cases/14.9.39-SET/pb5659-set-property-active-class-2002`.
