**The WRITE addendum (the row `1985-GR-VII.3.8.4-14`, "WRITE puts out 4 characters where GR15 makes it 10") is NOT adopted, and is a ruling for the Mythos lane to re-read.** A first attempt sized the connector's bound (`VaryMin`) and the WRITE image (`SequentialIoEmitter.SentRecordImage`, `AreaUse.Whole`) at the maximum too; the Conformance leg of the gate went RED on `ST137A` (NIST: `RECORD CONTAINS 148 TO 1435`, an ODO table, "VARIABLE LENGTH RECORDS (148 TO 1435 CHARACTERS) USING ODO"), whose files grew from 24327 to 73389 bytes: every record went out at 1435. The text does not require that: `§1985:VII.3.8.4 GR13` leaves it implementor defined whether a format 3 file holds fixed or variable length records, and `§1985:II.2.1.4.2` (specs/ANSI_COBOL_1985.md line 4168) says a variable length record's length "is affected by ... the DEPENDING phrase of an OCCURS clause". GR15 sizes the record DESCRIPTION ("the size of each data record is specified in terms of the number of character positions required to store the logical record"), and GR10c, which fixes what a WRITE sends, is under Format 2. This compiler treats format 3 as variable (GR13), so a WRITE sends the record at its current occurrences, a choice inside the latitude. `VaryMin` therefore stays the descriptions' own minimum (the connector's bound), and only the SORT/MERGE rule comparisons use GR15's size.
