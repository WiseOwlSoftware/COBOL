## The mechanism, read out of the code

`scripts/spec/cite.py` builds a printed path by walking backwards from the matched line and taking the first
line at each level (`rule_path`, `:61-72`). Its three level regexes are:

```
TOP    = re.compile(r"^(\d+)\\?\)\s")
SUB    = re.compile(r"^\s{2,}([a-z])\\?\)\s")
SUBSUB = re.compile(r"^\s{2,}(\d+)\\?\.\s")
```

`SUB` **requires two or more leading spaces**. A lettered item transcribed at column 0 therefore matches
nothing: the walk steps over it, `seen_sub` stays false, and the next indented `a)` it meets — the outdented
item's own preceding sibling — is recorded as that line's sub-item level. The reported path is the path of a
DIFFERENT rule, and it is reported as `OK`.

This is the same accident as [[PB698]] with the ordinal class changed. It is invisible to every existing check
for a reason that is mechanical, not accidental: the catalog's ordinal regexes are **digit-only** —
`extract_rule_catalog.py:102` `ORDINAL = ^(?P<n>\d+)\\?(?P<form>[.)])\s+` and `:110`
`INDENTED_ORDINAL = ^\s+(?P<n>\d+)\\?[.)]\s` — and `last_indented`, the state that decides sub-list
segmentation, is written only from `INDENTED_ORDINAL` (`:501`). A lettered line, indented or not, is body text
of the enclosing rule, and `flush()` joins body text with `" ".join(x.strip() …)`. **So no catalog row moves,
no rule text changes, and no `rule-digest` changes.** There is nothing for `extract_rule_catalog.py --check`,
the inventory drift suites or the digest guard to notice. The only artifact that is wrong is the one CLAUDE.md
rule 1 makes every citation pass through.

## Why it matters

No user program changes: nothing here reaches the compiler. What changes is the reliability of the ONE
mechanism CLAUDE.md rule 1 installs to stop a wrong clause number from propagating — *"⛔ VALIDATE EVERY
CITATION MECHANICALLY"*. `--check` answers `OK` for a wrong path, so a citation validated exactly as the rule
demands still ships the wrong printed path into a code comment, a golden, an adjudication and the DEVLOG. That
is `feedback_a_real_clause_can_answer_a_different_question` mechanized: the text is real, the clause path is
wrong, and the tool says OK. It is also `feedback_green_gates_arent_evidence` — the checker has never once been
shown to fire on this shape.

Severity is MINOR and `process_only` because it moves no verdict and no compiled behaviour. It is not
low-value: PB698's identical defect one level down produced two wrong CA10 citations.

## The fix shape

**PB698's method, per site — the printed page decides, never the ordinal arithmetic.** For each of the 50:

1. Locate the printed line on the canonical PDF (`python scripts/render-spec-page.py <page>`; the PDF is
   `specs-private/ISO+IEC+1989-2023_ for X_952804 COBOL.pdf`).
2. Read that page's **level ladder** — the x0 of the block's top-level ordinal, of its lettered items, of its
   numbered sub-items — and compare the candidate's **ordinal glyph x0** against it. ⛔ A modal-x0 "body
   margin" is unusable on a page that is mostly one nested list: PB698 measured it mislabelling 9 of 23 sites.
3. Repair only if the glyph is printed indented, taking the exact leading whitespace of its own preceding
   sibling. `specs/ISO_COBOL.md` is CRLF; byte-check after any scripted write (CRLF count, 0 lone LF, 0 NUL, no
   BOM) and keep the line COUNT unchanged — artifacts keyed to spec md-line numbers depend on it.

**Sequencing, and what the branch's tooling is for.** Because the lettered class touches no ordinal state, the
repair is expected to be catalog- and digest-NEUTRAL by construction. That expectation is a prediction, not a
measurement, so run it as PB698 ran its own: rebuild the catalog and the inventory before and after and diff
the id sets, under `build_inventory.py --check` with the `rule-digest` carry guard from branch
`worktree-agent-a978d10810e78251a`. If any id or digest does move at a site, that site is entangled with a
NUMBERED repair and inherits PB698's **text-keyed** migration obligation — a positional `L<sublist>.<n>` id
shifts when a sub-list changes, and six adjudicated rows kept their id while their text changed underneath
during PB698. **Land this behind that branch, not beside it.**

**Ship a check that fails first** (`feedback_prove_the_watchdog_fails`). The detection above belongs beside
`cite.py` as a `--check`-class gate over the transcription — assert the candidate count is zero after the
repair, and prove the gate fires by feeding it a fixture with one outdented lettered item. Without it, the
class silently regrows on the next transcription edit, exactly as the numbered class did.
