# PB3321 — core obligation or as worded

Filed by the clerk from lead 3 of the PB3173 report (`E:\COBOL-coord\scratch\reports\w1104c2-PB3173-report.md`, "New defects (leads)"). PB3173's branch is PR #173; this note's work starts once it is on main.

**Question.** 80 clause-15 function rows have a band that starts LATER than the function's `IntrinsicCatalog` window (`IntrinsicSig.IntroducedIn`), a reading of the 2023 wording of each rule. Does a rule's band start at its facility's introduction ("core obligation") or at the edition whose wording states the rule ("as worded")? PB3173 allows late starts and calls this the open reading question. PB3320 waits on the answer.

**Repro.** `python E:\COBOL-coord\scratch\w1104\w1104c2\fnsweep.py`. Run on origin/main (before PB3173's R1-3 correction of nine early rows) it printed `EARLY 9` and `LATE 75` (88 lines in all, 84 rule rows), not 80; the 80 is PB3173's own count on its branch. Re-run it on the landed inventory to get the current set.

**How to decide.** An adjudicator first derives the answer from the ISO text and `docs/VERSION_CHANGE_REFERENCE.md` (CLAUDE.md rule 1), with `cite.py --check` on every citation. Only if the standard leaves it open does it become an owner question, asked as a bare question.

**Fix shape (for the implementer to confirm).** Record the reading in `docs/VERSION_TEST_MATRIX_DESIGN.md`, re-decide the late-start rows in one `record_verdicts.py` batch if the answer is "core obligation", and extend the function-rule drift test to the other direction.

**Resolution (wave 20262140 group C, 2026-11-22).** The answer is neither: a rule's band starts at the first edition whose OWN text states the same obligation (docs/VERSION_TEST_MATRIX_DESIGN.md P2.9). The 57 late-start rows on the landed per-rule store (the sweep on the 2023 headings and `IntrinsicCatalog`, 0 early) split by each edition's own text (the 1985 file's Intrinsic Function module, `ISO_COBOL_2002.md`, `ISO_COBOL_2014.md`):
- 44 stay: the 2002, 2014 or 2023 text first states a new obligation (a strong-group bar, a zero-length-literal bar, a figure the earlier text gives differently, a standard-binary or standard-decimal arm, the LOCALE rules, `EXCEPTION-FILE`'s argument-1, `TRIM`'s argument-2).
- 13 started later than the first edition that states the same obligation, and are re-banded in one `record_verdicts` batch (`adjudication/pb3321-function-rule-bands/batch.json`, GAP 4 to 4): ten argument rules and `FMT-15.68.2` start at 85 (the 1989 module's text; the compiler already refuses each at `--std 85` with COBOL1627 citing it), `FMT-15.14.2` and `RV-15.14.4-2` at 2002 (BYTE-LENGTH, §2002:15.12.3 RV2 word for word). `RV-15.84.4-1` stays 2014 (review R1-1: §2023:15.84.4 RV1 names 2014's standard-binary and standard-decimal modes; 2002's ARITHMETIC IS STANDARD rule is a different one).
- One mechanical check now holds the other direction: `SpecTraceabilityInventoryDriftTests.EveryFunctionRule_StartsNoLaterThanItsFirstVerbatimStatement`.
- Left as read: `RV-15.68.4-2` (NUMVAL-C ignores the currency string and grouping separators) is worded first in 2023, its obligation is only implied by the 85 and 2002 formats; its band stays 2002. It is the one lower-confidence row.
