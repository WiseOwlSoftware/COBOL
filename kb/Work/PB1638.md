# PB1638 — OPEN

Split out of PB1633 on 2026-09-27.

**Observed.** `SET PP TO ENTRY "PCMP"` compiles clean at the default `--std 2023`, strict, not `--permissive`
(`scratchpad\pb1632\sweep.cob`, session eb162d4b). The grammar keeps it deliberately
(`CobolParserCore.g4#setEntryStatement`, whose comment says `TO ENTRY` "occur[s] nowhere in ISO/IEC 1989:2023" and is
kept because field programs use it). Its semantics are the §8.4.3.13 program-address-identifier's, including GR4's
EC-PROGRAM-NOT-FOUND, and PB935 is the open owner question about its restricted-pointer enforcement.

**Why it is a question.** Two standing rules pull against an unconditional acceptance:
- dialect two axes: every leniency is dialect-gated;
- R43, unsupported means unsupported.

`--permissive` is described as accepting "constructs the targeted edition removed", which is not a vendor extension
the standard never had. So there is no switch under which strict mode refuses the spelling.

**To decide (derive first, then ask only if the precedence does not settle it).**
1. Is a vendor-only spelling ever accepted in strict mode anywhere else in this compiler? Find the policy, and its
   `docs/CONFORMANCE.md` section, that governs vendor extensions (PB549's landing chose to keep it: read why).
2. §4.2 conformance: a conforming implementation may accept extensions if it can flag them. Check
   whether this compiler's claim requires a diagnostic (warning or error) in strict mode for nonstandard syntax.
3. Then: an edition-gated, dialect-flagged spelling (for example a warning in strict mode, clean under an
   IBM/MF dialect) versus a documented always-on extension. That choice is the owner's only if 1 and 2 leave it open.
