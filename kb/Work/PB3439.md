# PB3439 — the Linux landing red is not a "previous red" for the next plan

Filed 2026-10-19 by the enqueue clerk from `E:\COBOL-coord\scratch\reports\w1129g-PB2500-report.md`, "New defects found".
Register check: a grep of kb/Work by `read_previous_run` and `previous red` found PB3022 item 8 (a re-gate runs the previous
reds) and PB3247/PB3131 (what leg 1 plans from a diff); none says where the previous reds are read from. The other causes of
the same report went to PB3247 as a witness.

**Mechanism.** PB3022 item 8 makes a re-gate after a fix run the previous reds first. `scripts/gate_plan.py:221`,
`read_previous_run`, builds that set from the trx files in ONE run directory, the Windows gate's. A red found only by the
landing's Linux gate (here `EveryWordAdmittingLiteralSlot_IsWitnessedByAGolden_OrArgued`, found by the Linux unit leg) is not
in it, so the finisher's re-gate (run 20261019T192753Z-6de1c5) left the case in leg 2 although its diff edited that test file.

**Fix shape.** Read the Linux gate's reds too (its trx or its red list, from the evidence directory the gate already keeps),
through the same function, with a self-test whose only red is in the Linux directory.

## Retired (wave 20261029 group D, 2026-10-24): already fixed by PB3155 and PB3184

Re-probed on this tree (cut from main `e5cf90436`). The mechanism the note names no longer exists:
`scripts/gate_plan.py` `previous_gates` is now THE ONE READER of a worktree's previous gates (`TRX_WRITERS`): it reads
build-local's previous run through `read_previous_run` (timings and reds) AND `<worktree>/TestResults/linux-gate/`
through `read_reds` (reds only, since another host's durations would mis-time this host's plan). Both callers use it:
`run_gate_legs.py:570` (the gate driver) and the CLI (`gate_plan.py` `--previous-run`). A case red only at the
landing's Linux gate is tier 0a, so it runs in leg 1 of the next gate. Landed by commit `3a7660117` (PB3155 and
PB3184, the same defect found twice more), after this note was filed on 2026-10-19.

The fix shape's self-test exists and passes on this tree (`python scripts/gate_plan.py --self-test`, ALL GREEN): "a
case red only at the Linux gate is tier 0a of the next plan, in leg 1 by its name key" gives the Windows run its own
red and the Linux directory a different one; "no previous gate on either host" and "a Linux gate whose trx files hold
no Failed outcome adds no red" pin the empty arms. `GateLegDriftTests` holds `TRX_WRITERS` equal to the live tools
that write a trx file, so a new writer cannot be left unread. Sibling sweep: `read_previous_run` has one caller,
`previous_gates` (grep of `scripts/`); no other reader of previous reds exists.

**Sites:** none changed; the landed fix is in `scripts/gate_plan.py` (`previous_gates`, `read_reds`, `TRX_WRITERS`) and
`scripts/run_gate_legs.py` (`Host.plan`), neither touched here.
