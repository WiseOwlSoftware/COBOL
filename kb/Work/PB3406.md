# PB3406 — `last_verdict` can raise

Filed by the operator from PB3381's branch review (R7-1, low, not blocking at round 7; `w1125a-PB3381-report.md`).

**The mechanism (`scripts/orchestrator/review_findings.py`, on main at 49e1c6b79).** `last_verdict(path)` says "It never
raises: a file that cannot be read is a tear (examine), and so is any failure of the reader itself". Its first line,
`s, data = examine(path)`, is outside the `try`. `examine` catches only the `OSError` of `read_bytes`. It then calls
`scan(data, path)` unguarded, and `scan` parses each line with `json.loads`.

**The failure.** The reviewer's repro (`r7/probe7b.py`) was a findings file whose last line is 50,000 `[` characters.
`json.loads` raises `RecursionError`, which escapes `examine` and `last_verdict`. `unanswered` then raises out of the
branch survey (`prune_worktrees.py`), and the CLI's `last-verdict` exits 1. The wave reads that exit as unanswered, so it
fails closed and releases nothing. No writer, kill, BOM edit or foreign tool is known to write a line that deep, which is
why the severity is low. But the reader's contract is false, and a survey that raises stops the whole branch listing.

**The fix.** Move `examine` inside the `try` (or catch `Exception` in `examine` around `scan`), so every failure of the
reader reads TORN. Add the deep line to the self-test's tear cases, beside the `SCHEMA` cases.
