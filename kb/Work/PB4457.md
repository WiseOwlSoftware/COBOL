# PB4457 - errors of a placement-(a) expansion sub-compilation name a deleted temp file, the CLI prints no generated-C# path and the sub-compilation's warnings are dropped; the own-assembly relabelling has no test

**Sites:** `src/WiseOwl.Cobol.Compiler/ExpansionAssemblies.cs:38` (the `expansion-<guid>.cob` temp file, deleted in the `finally`; the review cited line 40) and `:53` (the `e.Replace(temp, where, ...)` relabelling), `src/WiseOwl.Cobol.Cli/Program.cs:378` (prints `generated C# at {result.GeneratedCsPath}`). Sites are at the head of branch `worktree-wf_d44be67f-63e-4` (PB2104, PR #1046); line numbers are that head's.

**Defect.** (1) An error whose text still names the temp file (any position the relabelling does not reach) points at a file that no longer exists. (2) On a backend failure the CLI prints "generated C# at " with no path for this arm, so the user cannot open the C# the message promises. (3) `Write` returns only `result.Errors`; the sub-compilation's `result.Warnings` are dropped, while an expansion made in the group (arm b) reports its diagnostics at the EXPANDS entry. The two arms therefore disagree about where, and whether, a diagnostic of an expansion shows. (4) The relabelling of an own-assembly expansion's error positions has no test: no case compiles an expansion whose text has an error and asserts the reported position.

**Fix shape.** One reporting path for both arms (warnings carried, positions at the EXPANDS entry or at the expansion text with a kept or named artifact), the CLI prints only a path that exists, and a test for the relabelled position and for a carried warning.

## Landed (wave 20261840, group A)

`ExpansionToWrite` carries the EXPANDS entry's `SourceLocation` (file, line, column through `EditionContext.LocationOf`, the position `edition.At(entry)` gives an expansion made in the group) in place of a bare line. `ExpansionAssemblies.Write` returns a `Written` record (files, errors, warnings, generated C#) and passes every error and warning of the sub-compilation through `AtTheEntry`: a position in the throw-away file becomes the entry's location, a position-less diagnostic takes it, the expansion is named after the message, and any other mention of the temp file becomes the expansion's name. `CompilerDriver.Compile` merges the warnings into `Result.Warnings` on every outcome. The CLI's `BackendFailureHeadline` names the generated C# only when the file exists (a sub-compilation that failed before writing C# had no path, and the headline read `generated C# at `).

Tests: `ADiagnosticOfAnExpansionText_IsRelabelledToTheExpandsEntry` (each shape of position), `AWarningOfAnExpansionInAnAssemblyOfItsOwn_IsCarriedAndReportedAtTheExpandsEntry` (a real library at 2023 whose skeleton uses NEXT SENTENCE, COBOL0903, reported at the client's EXPANDS entry, line 8 column 5), `TheBackendFailureHeadline_NamesTheGeneratedCSharp_OnlyWhenItExists`. The golden of PB4456 run with its fix disabled printed the relabelled COBOL2690 at the entry (`...pb4456_expansion_literals_at_every_column.cob(40,12): error COBOL2690 ... [in the expansion 'HOLD-BOX']`) and a headline with no path.

A warning the group's own bind also raises for the expansion text (a COBOL3146 in the probe) is now reported twice: once by the group's bind of the expansion, once by the sub-compilation of the same text under the skeleton's recorded state. Both stand at the EXPANDS entry's line; the sub-compilation is the only one that sees the recorded edition's gates (COBOL0903 appeared only from it).
