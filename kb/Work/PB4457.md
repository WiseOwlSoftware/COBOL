# PB4457 - errors of a placement-(a) expansion sub-compilation name a deleted temp file, the CLI prints no generated-C# path and the sub-compilation's warnings are dropped; the own-assembly relabelling has no test

**Sites:** `src/WiseOwl.Cobol.Compiler/ExpansionAssemblies.cs:38` (the `expansion-<guid>.cob` temp file, deleted in the `finally`; the review cited line 40) and `:53` (the `e.Replace(temp, where, ...)` relabelling), `src/WiseOwl.Cobol.Cli/Program.cs:378` (prints `generated C# at {result.GeneratedCsPath}`). Sites are at the head of branch `worktree-wf_d44be67f-63e-4` (PB2104, PR #1046); line numbers are that head's.

**Defect.** (1) An error whose text still names the temp file (any position the relabelling does not reach) points at a file that no longer exists. (2) On a backend failure the CLI prints "generated C# at " with no path for this arm, so the user cannot open the C# the message promises. (3) `Write` returns only `result.Errors`; the sub-compilation's `result.Warnings` are dropped, while an expansion made in the group (arm b) reports its diagnostics at the EXPANDS entry. The two arms therefore disagree about where, and whether, a diagnostic of an expansion shows. (4) The relabelling of an own-assembly expansion's error positions has no test: no case compiles an expansion whose text has an error and asserts the reported position.

**Fix shape.** One reporting path for both arms (warnings carried, positions at the EXPANDS entry or at the expansion text with a kept or named artifact), the CLI prints only a path that exists, and a test for the relabelled position and for a carried warning.
