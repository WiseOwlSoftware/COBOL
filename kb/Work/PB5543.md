# PB5543 - ConcatFolder takes a symbolic-character operand through SymbolicValue, dropping the national flag (unprobed)

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/ConcatFolder.cs#Classify` (`if (env.SymbolicValue(op, word) is { } ch) return Term.Symbolic(ch, word);`)
- `src/WiseOwl.Cobol.Compiler/Binding/LiteralEnvironment.cs#SymbolicValue` and `#SymbolicOf` (the latter returns `(Value, National)`)
- `ConcatFolder.Term.Symbolic(string value, string word)`

**Mechanism.** `LiteralEnvironment.SymbolicOf` returns the symbolic-character's value AND its category (`National` is true for `SYMBOLIC CHARACTERS FOR NATIONAL`); `SymbolicValue` keeps only the value. The concatenation folder uses `SymbolicValue`, so a national symbolic-character operand of a concatenation-expression becomes an ordinary alphanumeric `Term.Symbolic`, and the national category of the operand never reaches the folded literal or the class/usage checks on it. kb/Work PB5523 closed the same flag-dropping for `CodeFigurativeCharacters` (COBOL2713) and kb/Work PB5420 for PADDING CHARACTER (`FileControlBinder.Padding.cs#SymbolicCharacter` reads `SymbolicOf(...) is { National: false }`).

**Status of the claim.** Not probed by the reporting wave. First step for the implementer: compile a concatenation `SYM-N & "A"` with `SYMBOLIC CHARACTERS FOR NATIONAL` and see whether the folded literal is alphanumeric, national or refused, against the concatenation-expression rules of §2023:12.3.7 (cite-check before quoting).

**Fix direction.** Read `SymbolicOf`, carry `National` in `Term`, and sweep every `SymbolicValue(` caller (the grep lists the folder and the `DataBinder` raw-text readers) so none drops the flag by using the value-only accessor; consider removing `SymbolicValue` if no caller wants the value alone.
