# PB2496 — OPEN

Filed by the train-1034b lander from the wave-1034 group B report (PB244, `E:\COBOL-coord\scratch\reports\w1034b-PB244-report.md`,
new defect 1).

**Mechanism.** PB244 carried an OCCURS DEPENDING table of variable-length elements on the §8.5.1.12 component carrier
(`VarPartKind.OdoTable`, unrolled at its maximum). A DYNAMIC-CAPACITY table of such elements still joins only the one-way image
(`DataItem.CurrentImageCapable`): the carrier's component for a dynamic table is its occurrences' concatenated images
(`GroupImageCodec.VarParts`, the `DynTable` arm), which cannot be split back into elements that each hold components. So
`MOVE G2 TO G3`, a relation and a CALL operand over such a group reach the named Tier-C loud.

**Expected.** The standard defines the operation, which overturns the w1033c "no matching rule" claim:
§14.6.9.2 2) "Correspondingly numbered elements are moved according to the rules of the MOVE statement specified in 14.9.25, MOVE
statement." and §14.6.9.3 compares element by element, the remaining ones against spaces (`cite.py --check` OK on both).

**Fix shape.** Nested element carriers in `CobolVarGroup` (Slice / Concat / Reshape / Overlay / Compare / FromFixedImage and the
`StorageCell` cell helpers), so a dynamic table contributes one carrier per element. Shares the carrier component model with
PB2497. **Repro.** `E:\COBOL-coord\scratch\w1034b\p\t1.cob`. **Sites.** `src/Cobol.Net.Compiler/Binding/Model/DataItem.cs#CurrentExtentComposes`
(dynamic-table arm, `carrier: true`), `src/Cobol.Net.Compiler/CodeGen/DataDivision/GroupImageCodec.cs#VarParts`.
