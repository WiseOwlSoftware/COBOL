# PB2496 — LANDED

Filed by the train-1034b lander from the wave-1034 group B report (PB244, `E:\COBOL-coord\scratch\reports\w1034b-PB244-report.md`,
new defect 1).

**Mechanism.** PB244 carried an OCCURS DEPENDING table of variable-length elements on the §8.5.1.12 component carrier
(`VarPartKind.OdoTable`, unrolled at its maximum). A DYNAMIC-CAPACITY table of such elements still joins only the one-way image
(`DataItem.CurrentImageCapable`): the carrier's component for a dynamic table is its occurrences' concatenated images
(`GroupImageCodec.VarParts`, the `DynTable` arm), which cannot be split back into elements that each hold components. So
`MOVE G2 TO G3`, a relation and a CALL operand over such a group reach the named Tier-C loud.

**Expected.** The standard defines the operation, which overturns the w1033c "no matching rule" claim:
§14.6.9.2 2) "Correspondingly numbered elements are moved according to the rules of the MOVE statement specified in 14.9.25, MOVE
statement." and §14.6.9.3 compares element by element, the remaining ones against spaces (`cite.py --check` OK on both).

**Fix shape.** Nested element carriers in `CobolVarGroup` (Slice / Concat / Reshape / Overlay / Compare / FromFixedImage and the
`StorageCell` cell helpers), so a dynamic table contributes one carrier per element. Shares the carrier component model with
PB2497. **Repro.** `E:\COBOL-coord\scratch\w1034b\p\t1.cob`. **Sites.** `src/Cobol.Net.Compiler/Binding/Model/DataItem.cs#CurrentExtentComposes`
(dynamic-table arm, `carrier: true`), `src/Cobol.Net.Compiler/CodeGen/DataDivision/GroupImageCodec.cs#VarParts`.

## Landed 2026-10-08 (w1042c)

Re-probed on base `7fb5cab75`: `E:\COBOL-coord\scratch\w1039f\pb2496\t1.cob` still aborted at RUN time on `MOVE G2 TO G3`
with the named loud. After the change it prints `G2=[hq ]` and `G3=[hq ]` (its WRITE is PB2497's loud).

**Mechanism.** The §8.5.1.12 carrier (`CobolVarGroup`) holds a dynamic-capacity table whose elements are variable-length
groups as ONE nested component: `Dynamic[k]` is `""` and the occurrences' own carriers ride in `Elements[k]`. The run-time
count of such occurrences, each holding components of its own, can no longer move the ordinal of later components.
§14.6.9.2 ("Correspondingly numbered elements are moved according to the rules of the MOVE statement") and §14.6.9.3
(element by element, the larger table's remainder against spaces) take exactly those carriers. `cite.py --check` is OK
on both and on §8.5.1.12.3, §14.6.9.4, §8.8.4.2.17 and §8.5.1.12.2.
- Runtime: `CobolVarGroup.Elements` / `ElementsAt` / `ElementCarriersAt` / `ElementList`. `Slice`, `Concat`, `SplitTail` and
  `JoinTail` keep them. `Reshape`, `Overlay` and `Compare` recurse per element over `GroupAtom.Element` (`IsNested` is the
  one test). The span adapters `ToFixedImage` / `OverlayFixedImage` refuse a nested component by name.
  `CobolDynTable.Recreate<TPart>` is the one §14.6.9.2 recreation; `SpaceFillElements<TPart>` and
  `CurrentOccurrencesAs` are new. `StorageCell.VarGroupAt` / `StoreVarGroupAt` take the element shapes (`CellGroupShape`
  gained `DynMax`).
- Codegen: `GroupImageCodec` `VarPartKind.DynGroupTable` (AsVarImage: the component plus its elements; FromVarImage:
  `Recreate` from the element carriers, or `SpaceFillElements(CobolVarGroup.Empty, …)` when not carried).
- Model: the one-way `DataItem.CurrentImageCapable` became identical to `CurrentExtentImageCapable` and was deleted.
  `CurrentExtentUse` is now `{Operand, Record}`.

**Sibling found and fixed (WRONG ANSWER).** A MOVE between two COMPATIBLE variable-length groups of DIFFERENT shapes handed
the sender's carrier to the receiver ordinally, although the INVOKE boundary already reshaped it (the two-arm shape). For
example, `G1 (X, T OCCURS DYNAMIC, D DYNAMIC LENGTH)` → `G2 (X, T OCCURS 2, D …)` put T's occurrences into D: the output
was `x  a` where §14.6.9.2 gives `xa dd`. The comparison likewise walked both carriers at one side's offsets. Probe:
`E:\COBOL-coord\scratch\w1042c\p\s1.cob`. Now `PlaceRenderer.VarGroupOperand` gives each operand in its own shape (a
fixed group is its image with no components). A MOVE reshapes into the receiver's shape (`VarGroupInShape`), and
`CobolVarGroup.Compare` walks the pair over both shapes. Two USAGE-BIT groups with no atoms compare in their one layout
(`CompareInLayout`).

**Residue (named loud):** a FIXED-length group opposite such a table across an ACTIVATION BOUNDARY, where `CallAbi` /
`OoEmitter` still pair a fixed group by the flat `CorrespondingSpans` adapters, which carry no element layout. A MOVE or
comparison converts the pair.

Goldens `conformance:2014/pb2496_vlg_dynamic_element_tables`, `conformance:2014/pb2496_vlg_dynamic_element_tables_call`;
negative `conformance:negative/pb2496-dynamic-element-table-below-2014`; unit `CobolVarGroupNestedTests`.
