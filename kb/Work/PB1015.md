# PB1015 — LANDED

## Repro — measured
`scratchpad/reg12/q18_rangein.cob --std 85`: `ALPHABET AL IS NATIVE`, `88 MID VALUE "A" THRU "M" IN AL`, and
`EVALUATE WS-C WHEN "A" THRU "M" IN AL …` → compiles, prints `IN` / `MID`.

## What is open
`docs/VERSION_CHANGE_REFERENCE.md` has no row for the phrase (grep "IN alphabet" / "THROUGH … IN" → nothing). Determine
the introducing edition from the Annex E change lists (§E.3.x) or the 2002 text, add the VCR row, and gate it (the
`new-construct` skill's edition-gate sweep: every golden compiling the phrase below that edition moves). If it is
2002-new, this is an under-reject at 85; if it existed in 85 the probe is correct and the VCR row still belongs.

## Landed

2026-09-22, wave 54 group I. Re-probed first on the implementer's own build: `q18_rangein.cob --std 85` compiled and
printed `IN` / `MID`, as filed. After: three COBOLNET0900 "the THROUGH range's IN alphabet-name phrase requires
COBOL-2002 (targeting COBOL-85)" — the VALUE clause's explicit-IN and IN-omitted spellings and the EVALUATE
range-expression; unchanged output at 2002+.

**Determination (⚠ DERIVED edge, 2002).** The 2023 Annex E covers 2014→2023 only and lists no range/collation
delta, so the phrase exists by 2014. COBOL-85's EVALUATE and VALUE formats carry a bare THROUGH pair; §14.7.8
rule 2's own NOTE ("to allow an implementor to define the collating sequence in a manner compatible with previous
COBOL implementations") and its LC_COLLATE locale arm (LOCALE is reserved from 2002) tie the phrase to the 2002
collation rework. The repo holds no 2002 or 2014 text, so the edge is stated in VCR row 7.22 where one line
overturns it — the precedent is row 7.19 (ORDER TABLE) and `value-false-phrase-2002`.

**Gate shape.** constructs.json row `range-in-alphabet-2002` (COBOLNET0900), checked at the ONE resolver both formats
already share, `DataBinder.TryResolveRangeAlphabet` (new `GateRangeAlphabetPhrase`), plus the VALUE clause's
no-THROUGH SR31 refusal, which is the one path that recognises the phrase without resolving it. It is deliberately a
BIND-site gate: IN is an optional word (PB983) and an EVALUATE identifier-4 `IN word` parses as a qualification until
EvaluateBinder peels it (PB843), so no parse-arm recognition sees every spelling. It fires only once the word IS an
alphabet-name, so a stray word keeps its own COBOLNET1997.

**Sweep.** Every `tests/conformance/85/*.cob` (139) recompiled at `--std 85`: no hit. The 85-listed negatives that
write the phrase (`pb398-/pb502-…-numeric-operands`, `pb555-false-in-collated-range`) now also draw 0900 but keep
their own `.err` code (measured). **Goldens:** positive already pinned at 2002 (`pb398_range_in_alphabet`,
`pb502_value_range_in_alphabet`); new negative `negative/pb1015-range-in-alphabet-85` (reject-at 85). VCR row 7.22
added and the gating index regenerated.
