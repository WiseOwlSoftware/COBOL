# PB1164 — LANDED

## Landed (wave 1005, group C) - one RETURNING-conformance entry for CALL and INVOKE

**Root cause (two-arm dispatch).** INVOKE had been given §14.8.3.3 rule 1's SET rule for an object-reference RETURNING pair
(`ObjectRefAssignmentMismatch` + `ReturningSender`); the Format-2 CALL still handed the same pair to
`OoConformance.DescriptionMismatch`, whose object-reference arm is §9.3.8.2.3's identity comparison (COBOLNET1736 'same kind,
name, FACTORY presence and ONLY presence'), so a subclass-typed returning item into a class-typed or universal receiver was
refused on CALL. Re-probed on the wave tree (`scratchpad/w1005c/p1164.cob`): both CALLs drew COBOLNET1736.

**Fix.** `ParameterConformance.ReturningConformanceReason` is the ONE returning-item half of §14.8.3 (beside `CheckArgument`):
two object references take the SET rule (rule 1; rule 2's ACTIVE-CLASS sender from the invocation), everything else the strict
description comparison. `CallBinder.BindCall` and `OoBinder.OoBindResolvedInvoke` both ask it and their private copies are gone;
the run-time delivery `CobolArgAdapt.StoreReturn<T>` stores a subclass-typed result into a superclass-typed or universal carrier
through `ManagedPointer.TryAssign` (it raised EC-PROGRAM-ARG-MISMATCH for the legal pair). The FUNCTION-ID object-reference
RETURNING refusal (`UdfReturningResidue`, COBOLNET1510) went with PB1419; a function's result temp is a clone of the RETURNING
item, so §14.8.3 needs no screen there. `ActivationConformanceDriftTests` pins that CALL and INVOKE ask the one entry.

**Goldens.** `conformance:2002/pb1164_call_returning_set_rule` (CLASS, UNIV, FOBJ, FNUL legs) + negative
`pb1164-call-returning-superclass-into-subclass` (all four editions' reject cells use the 2002+ editions that have OO; message
names §14.8.3.3 rule 1).

**Siblings.** The §14.8.2.3.2 BY REFERENCE argument twin keeps the identity rule (correct per that clause); BY CONTENT object
arguments already took the SET rule (`ContentMismatch`). The universal-INVOKE RUN-TIME descriptor comparison is PB1780's design.

## Finding — `returning-items` (rejects-legal-source; rows `GR-14.8.3.3-1`)

**Mechanism.** Format-2 CALL RETURNING conformance for object references uses the §9.3.8.2.3 identity comparator instead of the SET rules (two-arm dispatch: INVOKE was fixed, CALL was not); FUNCTION-ID object-reference RETURNING staged loud

**Repro.** Nested program MKR5 'LINKAGE SECTION. 01 L-O USAGE OBJECT REFERENCE RID5. PROCEDURE DIVISION RETURNING L-O.' (RID5 INHERITS FROM RIB5); caller: '01 B USAGE OBJECT REFERENCE RIB5.' 'CALL "MKR5" AS NESTED RETURNING B' and '01 U USAGE OBJECT REFERENCE.' 'CALL "MKR5" AS NESTED RETURNING U' (probe/returning-items/p5.cob).

**Expected from the spec.** §14.8.3.3 rule 1: conformance is as if SET B TO <returning item> were performed; §14.9.39.3 SR12 a)2. admits a subclass-typed sender into a class-typed receiver and SR8 constrains nothing for a universal receiver. Compiles; INVOKE B "WHO" prints DERIVED, U is set.

**Observed / reasoning.** COBOLNET1736 on both CALLs: 'object-reference description mismatch (formal ... 'RID5', argument ... 'RIB5' - §9.3.8.2.3 rule 2 requires the same kind, name, FACTORY presence and ONLY presence)'. CallBinder.BindCall hands the pair to OoConformance.DescriptionMismatch, whose ObjectReference arm is SameDescriptionAs; OoBindResolvedInvoke special-cases object references to ObjectRefAssignmentMismatch. The fix is to make the object-reference leg part of the ONE RETURNING-conformance entry (not a per-caller branch) so CALL, INVOKE and function activation share it. Separately UdfBinder.UdfReturningResidue refuses an object-reference RETURNING item for a FUNCTION-ID (COBOLNET1510, 'a named residue'; no register note).

**Code site.** src/Cobol.Net.Compiler/Binding/Procedure/Verbs/CallBinder.cs#BindCall (RETURNING conformance block); src/Cobol.Net.Compiler/Oo/OoConformance.cs#DescriptionMismatch (ObjectReference arm); src/Cobol.Net.Compiler/Binding/Procedure/Verbs/UdfBinder.cs#UdfReturningResidue

## What the fixer owes

Make the object-reference leg part of the ONE RETURNING-conformance entry (not a per-caller branch) so CALL, INVOKE and function activation share it: CallBinder.BindCall's RETURNING block must route object references to the SET-rule check OoBindResolvedInvoke already uses (ObjectRefAssignmentMismatch). Separately lift UdfBinder.UdfReturningResidue's COBOLNET1510 for an object-reference FUNCTION-ID returning item (no register note owned it). Siblings: the §14.8.2.3.2 BY REFERENCE argument twins.
