# PB5156 - the merge-incomplete BRANCH arm has no producer

**Sites:** `scripts/gate.py` (`NOT_RUN_CAUSES`, `self_test`): the `merge-failed` row, the `merge-blocked` row's wording, which
still names the ABI-pin settle's measuring build, and the cause-list assertion;
`scripts/orchestrator/enqueue.py` (`EXIT_MERGE_INCOMPLETE`, `land`, `self_test`): the BRANCH half of `land`'s inner `incomplete()`, the module docstring's
`merge-failed` sentence, and the self-test arm that plants `git_merge.Merged(incomplete=failure)` with a BRANCH cause; `.claude/skills/workstream/templates/finisher-brief.md`'s
exit-5 paragraph; any landing.md or DESIGN-orchestrator-loop.md text that names exit 5.

**What is wrong.** PB5110 made `git_merge.merge` plain git: it no longer settles `RuntimeAbi.pin`, so the only `incomplete` it
returns is git refusing to start or commit the merge (`abi_pin.MERGE_BLOCKED`, an ENVIRONMENT cause). Nothing produces a
BRANCH-carried incomplete merge any more, yet the `merge-failed` cause, exit 5, the `blocked()` line telling a finisher to remove
"the cause the line names" and the finisher brief's paragraph remain, exercised only by a planted value. CLAUDE.md rule 4 forbids
keeping a mechanism nothing uses.

**Fix.** Delete the BRANCH arm: the `merge-failed` cause, `EXIT_MERGE_INCOMPLETE`, the BRANCH half of `incomplete()` (it keeps
the ENVIRONMENT exit 2), the planted self-test arm, and the finisher brief's and docs' exit-5 text; reword `merge-blocked` to what
`git_merge` can still report (git refused a write of the merge, a lock, a full disk). Sweep the land lane (`land_lane.py`) and
`next_unit.py` for any branch on exit 5 and delete it with the rest.
