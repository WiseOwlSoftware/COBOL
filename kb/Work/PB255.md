# PB255

**Rows:** `RV-15.92.4-1`

TEST-FORMATTED-DATETIME answers a character position that does not exist in argument-2, and the two OFFSET subfield bounds are the only ones in the analyzer with no clause.

ROW: RV-15.92.4-1 (§15.92.4 r1 — 'the value returned is the ordinal character position at which the first error in argument-2 was detected').

WHAT IS RIGHT, and it is most of the rule: the per-digit range NARROWING (not a per-field check, which would have reported the START of the offending field and failed the NOTE) reproduces both of the NOTE's worked examples for the NOTE's reasons — 'yyyymmdd'/'20051314' → 6 at the '3' where the interval [13,13] first exceeds 12; '15990316' → 2 at the '5' where [1500,1599] first falls below 1601. Every failure arm returns `pos + 1`, the 1-based index of the character under examination, and 0 is returned only after every format segment is consumed AND `pos == data.Length`. The Fraction subfield is deliberately exempt from narrowing (§15.3.3.2 puts no range on it), `dateRepresentable` is correctly ignored here (a value with no §15.5.2 integer date form has no character IN ERROR), and six spec-derived refs between them hit every error CLASS the narrowing implements.

⛔ FINDING 1 — AN ANSWER OUTSIDE THE RULE'S CODOMAIN. When argument-2 is SHORTER than the format, `if (pos >= data.Length) return pos + 1;` yields `data.Length + 1` — a position that does not exist in argument-2 — where §15.92.4 admits only 'the ordinal character position at which the first error IN ARGUMENT-2 was detected'. The input is REACHABLE: §15.92.3 places no size rule on argument-2 and the compiler applies none — the schema row carries no `ArgPredicate` width at either position, in deliberate contrast to TRIM's `ExactWidth(1, …)` five rows above. The adjudication defended the answer with §15.93.4 r1 c)'s `(FUNCTION LENGTH (argument-1) + 1)` — a real, --check-able clause that legislates TEST-NUMVAL's returned value, not this function's: the a_real_clause_can_answer_a_different_question shape, and it was the whole of the evidence offered. No test covers the shape and docs/CONFORMANCE.md carries no determination for it (its only §15.92 entry is item 112, the LEAP-SECOND one). Either a determination is recorded under §4.2.6 or the answer changes; it cannot stay unwritten.

⛔ FINDING 2 — TWO BOUNDS JUSTIFIED BY A CLAUSE THAT DOES NOT COVER THEM. The adjudication said it checked the subfield bounds against §15.3.3.3 — 'hours 00 to 23, minutes 00 to 59'. Those arms are SHARED with the OFFSET subfields, and §15.3.3.3 governs only the COMMON TIME format by its own words; the clause that governs the offset subfields is §15.3.3.6.2 ('The offset-hours subfield of the data associated with a basic or extended offset time format shall contain a value from 00 to 23 inclusive' / '… offset-minutes … from 00 to 59 inclusive', specs/ISO_COBOL.md :29747 and :29749), which the adjudication never located. The VALUES turn out right — but §15.92.4's answer is conditioned on exactly 'format problems or RANGE problems', so a bound whose justification is a different clause is an unverified bound, and `Fld.OffHour`/`Fld.OffMinute` are the only arms in the table with no citation while every neighbour has one. The repair is the citation at the arm plus a golden that exercises an out-of-range offset-hours.

⚠ FINDING 3, documentation-grade. §15.92.4's NOTE writes `FUNCTION TEST-FORMATTED-DATETIME ("yyyymmdd", A-DATE)` in LOWERCASE, and both recognisers are case-SENSITIVE (`CobolDate.Tokenize`'s switch matches 'Y'/'M'/'D' uppercase only and falls to `default → return null`; `DateTimeFormatGrammar.BasicDates` holds uppercase literals, so bind-time `Classify` returns null and the reference draws DateTimeFormatKindMismatch). The NOTE's own program does not compile. That is DEFENSIBLE — §15.3.1.2 normatively requires uppercase and a NOTE is not normative — but the adjudication claimed to have hand-traced 'BOTH OF THE NOTE'S OWN EXAMPLES' while every test silently substitutes uppercase (`grep "yyyymmdd"` across tests/ returns nothing), and the substitution was never recorded. Record the determination beside the bounds.

VERIFIED LIVE AT HEAD (read-only): `CobolDate.cs` :507/:512/:539 unchanged; :526 and :528 still uncited while :519, :527 and :531 carry their clauses.

## Mechanism

src/Cobol.Net.Runtime/Intrinsics/CobolDate.cs#Analyze — `if (pos >= data.Length) return pos + 1;` at :507, :512 and :539 yields `data.Length + 1`; the bound table at :518-530 cites §15.3.1.3 on Year, §15.3.3.3 on Second and §15.3.3.6.1 on the zero-sign narrowing, but `Fld.OffHour => (0, 23)` (:528) and the `Fld.Minute or Fld.OffMinute => (0, 59)` arm (:526) carry no citation; the reachability comes from IntrinsicArgumentRules' row `Schema("§15.92.3 r1/r2", ['s','s'], cross: MatchArgument1)`, which carries no width ArgPredicate at either position
