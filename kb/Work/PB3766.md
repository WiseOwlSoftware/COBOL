# PB3766 — GLOBAL report items are not visible while a contained data division binds

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/BinderDriver.cs#BindUnitData` (the GLOBAL RD inheritance loop that calls `InheritGlobalReport`, about line 755 on the PB1046 branch), `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.Reports.cs#ReportEntriesNamed`, `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.Reports.cs#VisibleReports`

PB1046 (PR #596, not yet on main; the members above are on branch worktree-wf_1341dc87-1c4-11) makes `ReportEntriesNamed` / `ReportEntryReferenceRefused` the one refusal that says a report item may not be named outside the report (ISO §13.8.6.2.3, checked with `cite.py --check 13.8.6.2.3`: "Report items shall not be accessed or referred to by any clauses in any other section of the data division or by any other procedure division statements, except in the following cases:"). A contained program's own data-division clause (FILE STATUS, RELATIVE KEY, OCCURS DEPENDING ON) that names a container's GLOBAL report item still draws the old "not defined" wording (COBOL1639 / COBOL0851), because `VisibleReports` is filled by `BinderDriver.BindUnitData` AFTER the contained data division binds, so `ReportEntriesNamed` finds no inherited report at that point.

Harm: wrong message only; the source is refused either way. Fix shape: inherit the container's GLOBAL reports before the unit's own data division binds (the container has already bound), or make `ReportEntriesNamed` walk the container chain directly; pin it with a golden beside the PB1046 `pb1046-global-report-item-referenced-in-contained-program` case.

(2026-10-25, PB1046 report, New defects 1.)

## Landed (wave 20261780 group D)

**Re-probe (on the PB3766 build, `cobol` with a contained program whose FILE STATUS names `PV` and whose ODO names `PN`, both items of the container's `RD R-1 GLOBAL`).** Still reproduced: `COBOL0851 OCCURS … DEPENDING ON 'PN' on 'E': data-name-1 is not defined` and `COBOL1639 FILE STATUS 'PV': the clause's data-name references no data item`.

**Fix (the order is the root).** `BinderDriver.BindUnitData` no longer inherits the containers' GLOBAL reports after `data.Bind`; it OFFERS them (`ContainerGlobalReportsOf`, nearest container first, each with its `__outer` depth) through `DataBinder.ContainerGlobalReports`, and `DataBinder.InheritContainerReports` inherits them at the end of `BindDeclarations`, after the unit's own names are declared (a local name still hides, §8.4.6.2) and before `BindResolve`, whose resolvers ask `ReportEntryReferenceRefused`. `InheritGlobalReport` is unchanged (the inventory rows cite it). The container-chain walk the note offered as the alternative would have been a second source of the same list.

**Witnesses.** Conformance negatives `pb3766-contained-file-status-names-global-report-item` and `pb3766-contained-odo-names-global-report-item` (COBOL5092 at 85, 2002, 2014, 2023); unit `ReportItemReferenceTests.ADataDivisionClauseOfAContainedProgram_NamingAGlobalReportItem_IsRefusedAsAReportItem` (GLOBAL: COBOL5092 twice and no COBOL1639/0851; without GLOBAL the old verdicts stand).

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/BinderDriver.cs#BindUnitData`, `src/WiseOwl.Cobol.Compiler/Binding/BinderDriver.cs#ContainerGlobalReportsOf`, `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.Reports.cs#InheritContainerReports`, `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.Reports.cs#ContainerGlobalReports`, `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs#BindDeclarations`, `src/WiseOwl.Cobol.Compiler/Binding/BinderDriver.cs#ContainerGlobalRootsOf`, `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.Linkage.cs#InheritContainerGlobalData`, `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.Linkage.cs#ContainerGlobalRoots`

**Review round 1, finding R1-1 (the data-item sibling).** The containers' GLOBAL DATA roots were inherited after `data.Bind` as well (`InheritGlobalSubtree` in the loop of `BindUnitData`), so a contained program's FILE STATUS / ODO naming a container's GLOBAL working-storage item was refused as not defined (COBOL1639 / COBOL0851), which rejected legal source (ISO 13.18.27.4 GR1/GR2; 12.4.5.8.3 SR2). Fixed at the same root: `BinderDriver.ContainerGlobalRootsOf` is the one list; `DataBinder.InheritContainerGlobalData` inherits the names beside `InheritContainerReports`, and the C# bridges are built from the same list. Golden `13.18.27-GLOBAL/pb3766-contained-clauses-name-global-data-item` (accept 2002; prints `T=AA`, `GS=35`).

## Landing

- `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.Reports.cs#InheritContainerReports` — the ONE point a container's GLOBAL reports become visible to a contained program: the end of `BindDeclarations`, before `BindResolve`; REUSE `ContainerGlobalReports` (set by `BinderDriver.BindUnitData` before `Bind`), never re-walk the container chain. Trap: `Edition.At(cursor)` is the `DiagnosticCursorExtensions` extension, so `DataBinder.Reports.cs` needs `using WiseOwl.Cobol.Editions;` (the instance `EditionContext.At` takes a parse context only).
- `src/WiseOwl.Cobol.Compiler/Binding/BinderDriver.cs#BindUnitData` — offers the list (`ContainerGlobalReportsOf`); the after-`Bind` inheritance loop is gone.
