# PB3161 — an ABANDONED record abandoned the successor it named

> ⚙ **flags:** process-only · silent

**Found 2026-10-14 16:47 PDT by the resume unit** while it recorded `worktree-wf_84f0c364-28e-2` and
`worktree-wf_84f0c364-28e-5` ABANDONED in PB3127 and PB2099. Its first draft of each record named the successor on
the same line, and `abandon_record` then reported both successors (`worktree-wf_15ec6338-3a0-2`, `-3a0-3`) as recorded
too.

**The defect.** `scripts/prune_worktrees.py#abandon_record` is the guard behind the owner's rule (PB2600, MANDATORY-PRACTICES
O10): `--apply --abandon <branch>` deletes a DECISION row only once a kb/Work note records the decision. It matched any
line that named the branch as a whole word and held the word ABANDONED. A superseded branch's record names its
successor, which is the usual shape (PB1688: "`worktree-wf_8d59ef7b-0cb-3` ABANDONED, superseded: its commits were
cherry-picked onto `worktree-wf_6f53c0b7-a74-2`"; PB1941 likewise). So the guard read that line as a decision to abandon
the successor. When the successor became a DECISION row (a SPLIT report idle past `--min-age`), an `--abandon` of it
with no recorded decision deleted the branch carrying the work.

**Witness.** The self-test's record now names a successor before and after the word ("split-branch carries the rest,
so the orphan branch: ABANDONED …, replaced by PB9 on split-branch"). With the old matcher swapped in, the self-test
is RED (3 checks): `split-branch` is removed. With the new matcher it is GREEN
(`E:\COBOL-coord\scratch\resume-20261014\witness_old_abandon.py`).

**Fix.** The word ABANDONED abandons the last branch the line names before it. `abandon_record` takes the survey's
branch names, and a line counts for `branch` only when another known branch name does not fall between it and the
word. The record rule now reads "a line naming the branch and then the word ABANDONED" in the module docstring, the
refusal message, MANDATORY-PRACTICES O10, the workstream skill's `references/landing.md` and the resume unit
(`scripts/orchestrator/units/resume.md`).

**Sibling sweep.** No other script reads ABANDONED records (`grep -ril abandoned scripts`: `prune_worktrees.py`, the
resume unit, and `gen-constructs.ps1`, where the word means something else). The two records this unit wrote resolve to the
branch they abandon and nothing else: `abandon_record` finds `worktree-wf_84f0c364-28e-2` in PB3127 and
`worktree-wf_84f0c364-28e-5` in PB2099, and finds no record for either successor.
