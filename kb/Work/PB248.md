# PB248

**Rows:** `AR-15.90.3-1`, `AR-15.91.3-1`, `AR-15.100.3-1`, `AR-15.100.3-2`, `AR-15.100.3-4`

The 'i' integer-argument screen has no floating-point arm, so a COMP-2 item and an E-form literal slide into every integer argument position and are silently truncated.

ROWS: AR-15.90.3-1 (TEST-DATE-YYYYMMDD r1), AR-15.91.3-1 (TEST-DAY-YYYYDDD r1), AR-15.100.3-1 (YEAR-TO-YYYY r1), AR-15.100.3-2 (r2), AR-15.100.3-4 (r4). All five are §15.3 type 6 ('an arithmetic expression that will always result in an integer value or an integer data item').

MECHANISM, from the rows' own READ notes and re-measured at HEAD. `IntrinsicArgumentRules.Violation` opens `if (kind == 'i' && IntegerViolation(op) is { } notInteger) return notInteger;`. `IntegerViolation` has exactly four arms and a `_ => null` fail-open: a nested NUMERIC function (§8.4.3.2.3 SR11), a `BoundFieldOperand` whose `Pic is { Category: PicCategory.Numeric, Scale: > 0, Usage: not Usage.Index }`, a `BoundNumericLiteral` with `HasNonZeroFraction`, and PB124's `NotAlwaysIntegral` expression screen. `PicInfo.FloatItem(usage)` constructs `(PicCategory.Numeric, Length: 0, Digits: 0, Scale: 0, Signed: true)` — so a COMP-1/COMP-2/FLOAT-SHORT/FLOAT-LONG/FLOAT-EXTENDED/FLOAT-BINARY-*/FLOAT-DECIMAL-* item is admitted by `Admissible('i') = [CobolClass.Numeric]` AND misses the `Scale: > 0` arm. `PicInfo.IsFloat` (:379) exists and is consulted elsewhere (INITIALIZE's §14.9.20 category matching keys on `IsAlphabetic` the same way); it is not consulted here. SECOND PROVABLE SHAPE, from AR-15.90.3-1's refuter: `HasNonZeroFraction` opens `if (text.Contains('E') || text.Contains('e')) return false;` with the in-code justification 'an E-form literal is left to the runtime', so the LITERAL arm is disarmed for every floating-point literal, and the grammar admits one directly in the argument region (`CobolExpressions.g4:536 numericLiteralCore : FLOATLIT`; `CobolLexer.g4:807 FN_SIGNED_FLOATLIT` covers the sign-adjacent form inside a FUNCTION-argument region).

WHAT IT DOES. `01 F USAGE COMP-2 VALUE 20240229.9.` then `FUNCTION TEST-DATE-YYYYMMDD(F)` compiles clean, renders through `IntrinsicRenderer.cs:127 if (AnyRealArgument(ic) …) return RenderFloat(ic, RealMethod(...))` into `CobolIntrinsics.RealArgs.cs#TestDateYyyymmddReal`, whose `TryIntegerArg` TRUNCATES with `(long)Math.Truncate(v)`, and answers 0 — 'the date is valid' — on an argument that is not an integer. `FUNCTION TEST-DATE-YYYYMMDD(2.02402295E7)` does the same from a literal needing no PicInfo at all. `FUNCTION YEAR-TO-YYYY(85, F)` with F holding 23.6 windows as though 23 were written. EC-ARGUMENT-FUNCTION is never set, not even under `>>TURN EC-ARGUMENT-FUNCTION CHECKING ON`, which §15.3 rule 14 requires ('If the evaluation of an argument results in an incorrect value for that argument … the EC-ARGUMENT-FUNCTION exception condition is set to exist'). §15.3's latitude is over the RESULT when checking is off, not over whether the condition is set.

FAN-OUT. The whole 'i' kind is affected, not the five rows: CHAR, FACTORIAL, DATE-OF-INTEGER, INTEGER-OF-DAY, TEST-DATE-YYYYMMDD, TEST-DAY-YYYYDDD, YEAR-TO-YYYY and every other `Uniform('i', …)` / `Schema(… ['i','i','i'])` row. The shape is STATICALLY decidable from a datum the method already holds.

AR-15.100.3-4's OTHER half is NOT this note's and is NOT open: its refuter found r4 firing SPURIOUSLY on the float carrier for a reference that omits argument-3, because `RealArgs.cs` had one method filling `baseYear = 0`. At HEAD `CobolIntrinsics.RealArgs.cs:120` and `:124` are TWO overloads (`YearToYyyyReal(double yy, double off = 50)` calling the two-argument `CobolDate.YearToYyyy(y, o)`, and the three-argument twin) — the PB65 'omitted-ness is the ARITY, never a value' discipline propagated. That half is carried in the stale-verdict note, not here.

VERIFIED LIVE AT HEAD (read-only): IntegerViolation's four arms carry no `IsFloat` test; `HasNonZeroFraction:1199` still returns false for any 'E'/'e' text.

CLOSING EVIDENCE OWED: an `IsFloat` arm plus an E-form-literal arm in `IntegerViolation`, negative fixtures for BOTH shapes on at least two 'i' functions, and a drift test asserting every `Uniform('i')`/'i'-positioned row rejects a float item.

## Mechanism

src/Cobol.Net.Compiler/Binding/IntrinsicArgumentRules.cs#IntegerViolation (:1072-1101) + #HasNonZeroFraction (:1197-1202) + Admissible('i') (:866); the admitted shape is built by src/Cobol.Net.Compiler/Binding/Model/PicInfo.cs#FloatItem (:525) and consumed by src/Cobol.Net.Runtime/Intrinsics/CobolIntrinsics.RealArgs.cs#TryIntegerArg

## Lineage

PB40 (landed) — its arms are the §8.4.3.2.3 SR11 nested-numeric-function case and the PICTURE-scale item; PB124 (landed) added the two §15.3 type-6 EXPRESSION arms. Neither sweep reached the float carrier, which is the arm PB40's own primitive ('items — PICTURE scale 0, usage not INDEX') cannot see.
