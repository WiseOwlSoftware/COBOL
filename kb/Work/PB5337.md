# PB5337 - GENERATE report-name of a one-detail report at --std 85 does not run the sole detail's USE BEFORE REPORTING procedure: the engine runs none (§1985:XIII.3.20.4 GR11 b)

**Sites:**

- `src/WiseOwl.Cobol.Runtime/IO/ReportWriter.cs` (`CobolReport.GenerateSummary`, `CobolReport.GenerateCore`, `CobolReport.BeginGroup`, `CobolReport.RunBeforeReporting`)

**Mechanism.** §1985:XIII.3.20.4 GR11 b) (`cite.py --check "§1985:XIII.3.20.4 GR11b" "If there is a USE BEFORE REPORTING procedure that refers to the data-name of the report group, the USE procedure is executed"` prints OK): when the description of a report includes exactly one detail report group, GENERATE report-name performs the detail-related processing as though GENERATE data-name were executed, and that includes the sole detail's USE BEFORE REPORTING procedure. The engine runs none for that form. It shares its root with PB5249 (`CobolReport.GenerateSummary` / `GenerateCore(detailName, printDetail)`: "which detail" is now separate from "print it").

**Edition.** 2023 produces no group there (the 1985 one-detail GENERATE report-name processing is gone), so the fix is an edition arm: a fourth `DialectBehavior` row (VCR Table 7 row, `tests/doc-facts/compiler-facts.json` entry) beside the three PB5243 added. The lead notes SUPPRESS has nothing to suppress in this form, which is why PB5243's landing did not fold it in.

**Fix direction (as the lead states it).** Run the sole detail's USE BEFORE REPORTING procedure from `GenerateSummary` at 1985, through `RunBeforeReporting`, with a golden at 85 whose declarative displays a marker.

**Source.** PB5243's implementer (landing report, New defects / leads item 1); not fixed in that landing (separate semantics).
