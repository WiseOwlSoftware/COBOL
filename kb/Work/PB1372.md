## Finding — cobol-words-directive (rejects-legal-source)

Lex-time keyword actions are unreachable by the post-lex >>COBOL-WORDS rewriter: the PIC/PICTURE rule's pushMode(PICMODE) and the FUNCTION argument-region predicate (PreviousIsFunctionName, keyed on the FUNCTION token type) fire during lexing, but CobolWordsRewriter retypes synonyms and de-reserved words only AFTER the token stream is filled. So an EQUATE/SUBSTITUTE synonym of PIC/PICTURE/FUNCTION never enters PICMODE / never opens an argument region, and an UNDEFINE'd/SUBSTITUTE'd PICTURE/PIC used as a data-name still enters PICMODE and swallows the next word. The map-aware lexer seam (SetCobolWordsDataNames) exists but covers only the de-reserved data-name trigger, not these actions.

**Rows:** GR-7.3.10.4-2, GR-7.3.10.4-3, GR-7.3.10.4-4

**Repro:**

```
>>COBOL-WORDS EQUATE "PIC" WITH "PX" / 01 X PX 9(3) VALUE 7. / DISPLAY X  -> COBOL0001 unexpected '9'.  >>COBOL-WORDS EQUATE "FUNCTION" WITH "FN" / 01 X PIC X(3) VALUE "abc". / DISPLAY FN UPPER-CASE(X) -> COBOL0307 unexpected '('.  >>COBOL-WORDS UNDEFINE "PICTURE" / 01 PICTURE PIC X(3) VALUE "PPP". / DISPLAY PICTURE -> COBOL0001 near 'PIC'.  >>COBOL-WORDS SUBSTITUTE "PICTURE" BY "LOOKS" / 01 X LOOKS 9(3) VALUE 7. -> COBOL0001. (all --std 2023, pinned cobol.exe)
```

**Expected from the spec:** §7.3.10.4 GR2: literal-2 'may be used in any syntax requiring the use of the reserved word ... that is the content of literal-1' -> the programs display 007 and ABC. GR3: literal-3 'may be used as a ... data-name' -> PPP. GR4: literal-5 'shall be used in any syntax where ... literal-4 is documented' -> 007.

**Observed:** Probes gr2_pic_only, gr2_picture, gr2_fn_only, gr2_function, gr3_undef_picture, gr4_pic all fail at parse. Ordinary keyword synonyms (DISPLAY, TO, ZERO, IS) work, so the fault is specific to keywords whose lexer rule carries an action or whose token type steers a lexer predicate.

**Code site:** src/Cobol.Net.Frontend/Grammar/Core/CobolLexer.g4:716 (PIC : ('PIC' | 'PICTURE') -> pushMode(PICMODE)); CobolLexer.g4:86 PreviousIsFunctionName; src/Cobol.Net.Frontend/Parsing/CobolWordsRewriter.cs#Rewrite (post-lex only)

## Finding — cobol-words-directive (rejects-legal-source)

The directive is applied TWICE to an intrinsic-function name that is also a lexer keyword token (LENGTH, SUM, SIGN, RANDOM): CobolWordsRewriter already retyped the synonym literal-5 to the literal-4 token and respelled it canonically, then IntrinsicBinder.BindIntrinsicCore calls ctx.CobolWords.Resolve on that canonical text, finds literal-4 in DeReserved and treats the function as removed. CobolWordsRewriter.CanonicalWordOf is the documented once-only resolution for already-lexed tokens, but BindIntrinsicCore's comment assumes 'Only PURE intrinsic-name synonyms reach here'.

**Rows:** GR-7.3.10.4-4

**Repro:**

```
>>COBOL-WORDS SUBSTITUTE "SUM" BY "TOTAL" / 01 X PIC 99 VALUE 0. / MOVE FUNCTION TOTAL(1 2 3) TO X / DISPLAY X -> COBOLNET1501 'FUNCTION SUM is not an intrinsic function'. Same with SUBSTITUTE "LENGTH" BY "LEN" + FUNCTION LEN(X), "SIGN" BY "SGN" + FUNCTION SGN(-4), "RANDOM" BY "RND" + FUNCTION RND(5).
```

**Expected from the spec:** §7.3.10.4 GR4: literal-5 'shall be used in any syntax where the COBOL word that is the content of literal-4 is documented as required or optional' -> X = 06 (SUM), 7 (FUNCTION LENGTH of a PIC X(7) item, §15.50), -1 (SIGN), a value in [0,1) (RANDOM).

**Observed:** Probes gr4_sum, gr4_sign, gr4_random, gr4_length_nodata all COBOLNET1501; the control SUBSTITUTE "TRIM" BY "STRIP" (TRIM is not a lexer token) works, and EQUATE "SUM" WITH "TOTAL" works (no de-reserve), isolating the double application to SUBSTITUTE of a tokenized intrinsic name.

**Code site:** src/Cobol.Net.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs#BindIntrinsicCore (~line 488, ctx.CobolWords.Resolve(name)); also DefinitionPermitsArguments (~line 117) shares the shape; src/Cobol.Net.Frontend/Parsing/CobolWordsRewriter.cs#CanonicalWordOf

## What the fixer owes (and the sibling sweep)

Apply the COBOL-WORDS map at ONE point that precedes every lexer action keyed on a keyword (extend the lexer seam to the PIC→PICMODE rule `CobolLexer.g4:716` and `PreviousIsFunctionName` `:86`), and make `CanonicalWordOf` the only resolution (delete the second `ctx.CobolWords.Resolve` in `BindIntrinsicCore` ~488 and `DefinitionPermitsArguments` ~117). Goldens: EQUATE 'PICTURE' WITH 'PICX'; UNDEFINE 'PICTURE' then PICTURE as a data-name; SUBSTITUTE 'LENGTH' BY 'LEN'.
