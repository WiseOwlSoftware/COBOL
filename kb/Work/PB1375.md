## Finding — flag-02-directive (silent)

FLAG-02 b EC-PROGRAM-EXCEPTIONS detects 'calls a function / invokes a method' only through three parse-node kinds inside a ProgramUnitContext — a keyword-less function reference (REPOSITORY FUNCTION ALL INTRINSIC / function specifier) and any call/invoke inside a METHOD definition (a source element that is not a programUnit) are invisible, so the TURN is never flagged

**Rows:** GR-7.3.14.4-L2.1, GR-7.3.14.4-L2.2

**Repro:**

```
b1: `>>FLAG-02 EC-PROGRAM-EXCEPTIONS ON` / PROGRAM-ID F02B1 / REPOSITORY. FUNCTION ALL INTRINSIC. / 01 X PIC X(3) VALUE "abc". 01 Y PIC X(3). / PROCEDURE DIVISION. / `>>TURN EC-PROGRAM CHECKING ON` / MOVE UPPER-CASE(X) TO Y. DISPLAY Y. -> compiles, prints ABC, no COBOLNET1620 (with `FUNCTION UPPER-CASE` it IS flagged). m1: the same TURN + FUNCTION UPPER-CASE inside a FACTORY method of a CLASS-ID -> compiles clean, no COBOLNET1620.
```

**Expected from the spec:** §7.3.14.4 GR4 b: the TURN for EC-ALL/EC-PROGRAM/EC-PROGRAM-ARG-OMITTED/EC-PROGRAM-NOT-FOUND 'shall be flagged if 1. the source element calls any function, or 2. the source element invokes any method'. §12.3.8.4 GR13: 'intrinsic-function-name-1 may be specified as a function-identifier without being preceded by the keyword FUNCTION' — still a function call. §3.164: a source element is a 'source unit excluding any contained source units' — a method definition is one. Both probes: COBOLNET1620 on the TURN line.

**Observed:** VisitFunctionCall / VisitInvokeStatement / VisitInlineMethodInvocation add _currentUnitCtx, which only VisitProgramUnit sets; FlagEcProgramDirectives picks the owner from group.Units (program units). The binder, not the parse tree, knows a dataReference is a keyword-less function activation, so the detector must read the BOUND fact (the one 'is a function activation' decision) rather than re-derive it from syntax; OO source elements need an owner model covering class/factory/object/method definitions. Unverified sibling: a property reference (§8.4.3.9, ReferenceResolver.OoTryBindPropertyReference) invokes a get/set method and is likewise unseen.

**Code site:** src/Cobol.Net.Compiler/Validation/FlagConformancePass.cs#FlagConformancePass.VisitFunctionCall; src/Cobol.Net.Compiler/Validation/FlagConformancePass.cs#FlagConformancePass.FlagEcProgramDirectives; src/Cobol.Net.Compiler/Validation/FlagConformancePass.cs#FlagConformancePass.VisitProgramUnit

## Finding — flag-02-directive (silent)

FLAG-02 f TERMINATE-WITH-VARYING builds its VARYING-report set from ReportFieldModel.Varyings, which DataBinder.Reports fills only for PRINTABLE entries — a VARYING clause on a group (non-printable) report group description entry never reaches the set

**Rows:** GR-7.3.14.4-L3.2

**Repro:**

```
RD RPT. 01 DL TYPE DETAIL LINE PLUS 1. 05 G1 OCCURS 3 VARYING K FROM 1 BY 1. 10 COLUMN + 2 PIC X(3) VALUE "AB". ... `>>FLAG-02 TERMINATE-WITH-VARYING ON` / TERMINATE RPT. (--std 2014) -> compiles, runs (' AB  AB  AB'), no COBOLNET1620. Moving the VARYING onto the printable entry (`05 COLUMN + 2 PIC 9 SOURCE K OCCURS 3 VARYING K FROM 1 BY 1.`) flags.
```

**Expected from the spec:** §7.3.14.4 GR4 f: 'A TERMINATE statement shall be flagged if the report being terminated contains a VARYING clause' — any VARYING in the report description; §13.18.64.3 SR1 admits VARYING on any report group description entry carrying OCCURS or a multiple LINE/COLUMN clause, group entries included. Expected COBOLNET1620 on the TERMINATE.

**Observed:** FlagConformancePass.Run: `report.Groups.Any(g => g.Lines.Any(l => l.Fields.Any(f => f.Varyings.Count > 0)))`; DataBinder.Reports.cs collects `varyings` per entry and only `field.Varyings.AddRange(varyings)` for a printable field. The fact 'this report description contains a VARYING clause' should be recorded once on the bound report model at the clause (every entry), and read here.

**Code site:** src/Cobol.Net.Compiler/Validation/FlagConformancePass.cs#FlagConformancePass.Run; src/Cobol.Net.Compiler/Binding/DataBinder.Reports.cs (reportVaryingClause collection ~line 1695, field.Varyings ~line 2013)

**Expected from the spec:** §7.3.14.4 GR4 d 1: flag when 'the operands are of category alphanumeric-edited'; §8.4.3.3.4 GR6 a: for a reference-modified unique data item 'the category alphanumeric-edited is considered class and category alphanumeric'. ## Finding — flag-14-directive (silent)

Four FLAG-14 GR4 detectors derive their construct population from a syntactic proxy that is narrower or wider than the rule's own words. (b) Only directive fragments are scanned, never the constant entry. (d) IsKeyed tests file organization and ignores access mode. (e/f) Only a two-operand relation or a level-88 is recognized. (g/j/l) Numeric-edited is decided from the PICTURE string alone. (m) Any writeAtEndOfPage node suppresses the flag.

**Rows:** GR-7.3.15.4-4

**Repro:**

```
E:/Temp/claude/E--CobolSharp/a700c052-f9e4-4942-84ff-a13c7505d6ec/scratchpad/adj-d2/out/probe/flag14/GB.cob: '>>FLAG-14 COMPILE-TIME-ARITHMETIC-EXPRESSIONS ON' then '01 K1 CONSTANT AS 5 * 2.' (no warning). IO2.cob: USE ... ON OUTPUT declarative, '>>FLAG-14 ALL ON'; REWRITE on a RELATIVE ACCESS SEQUENTIAL record and DELETE on RELATIVE/INDEXED ACCESS SEQUENTIAL files are flagged; 'IF FS = "00" OR "04"' and 'EVALUATE FS WHEN "07"' are not (IO.cob:52 'EVALUATE FS WHEN "04"' is not either). BZ.cob: '01 X PIC 999 BLANK WHEN ZERO VALUE ZERO.' and '01 Y PIC 999 BLANK WHEN ZERO VALUE 12.' are not flagged. MX.cob:25: 'WRITE PR-R NOT AT END-OF-PAGE ...' on a LINAGE file is not flagged.
```

**Expected from the spec:** (b) The constant entry's arithmetic-expression-1 is a compile-time arithmetic expression (7.3.6.1; 13.10.3 SR7), so it is flagged. (d) GR4 d flags only a statement that 'can be specified with an INVALID KEY phrase'. DELETE in sequential access mode (14.9.10.3 SR2) and REWRITE on a relative sequential-access file (14.9.35.3 SR2) cannot be, so they are NOT flagged. (e/f) Every reference to the FILE STATUS item that tests for '04' / '07' is flagged, including an EVALUATE subject/WHEN object pair and an abbreviated combined relation. (g/j/l) A PIC 999 BLANK WHEN ZERO item is numeric-edited (13.18.8.4 GR2), so VALUE ZERO draws g+l and VALUE 12 draws j. (m) A WRITE without the END-OF-PAGE phrase is flagged even when NOT END-OF-PAGE is written (14.9.51.3 SR19 names the two phrases separately).

**Observed:** In each case the pinned compiler's warnings are absent (b, e/f, g/j/l, m) or spurious (d) as described in the repro. The d over-flag is a false migration warning; the rest are required warnings that never appear. The detectors' own comments call several of these 'rare false-negatives', but GR4 says 'shall be flagged'.

**Code site:** src/Cobol.Net.Frontend/Preprocessor/ConditionalCompilationProcessor.cs#DirectiveDiag.FlagArithmetic (sole b caller: directive operands); src/Cobol.Net.Compiler/Validation/FlagConformancePass.cs#IsKeyed / #VisitComparisonExpression / #IoStatusRelation / #IsNumericEditedPicture / #VisitWriteStatement
