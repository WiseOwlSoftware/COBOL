# PB1902 — LANDED

**Landed with PB2466 (wave 1033 G, 2026-10-07).** Re-probed with `E:\COBOL-coord\scratch\w1032a\p\r1.cob`
(`R RENAMES N1 THRU X2`, a window ending on the first byte of N2): COBOLNET1655 on the wave's base. The root is
PB2466's: a span part was kept in character positions, so a range splitting a national character could not be
represented. Every part is now a range of its cell's STORAGE BYTES, a usage-national cell is composed through
`NationalBytesPlace`, and a partial part is a byte `RefModPlace` over it (see PB2466). After the fix `r1.cob` gives
R = 3 and S = 5 bytes, and the MOVEs through both reach the right bytes. Witness: the RB alias of golden
`2002/pb2466_renames_half_national_byte`. Note for the lander: the unlanded wave-1032 A branch
(`worktree-wf_19837670-9d4-1`, commit 7861c89ef) fixed this by FILTERING candidates in the tiler's `Consider`
through `FromBytes`; this landing deletes `FromBytes`, so on a merge conflict that hunk and its note edit are
superseded and its golden `2002/pb1902_renames_window_inside_national` still passes on this mechanism.

Filed 2026-10-01 by the train-1001 lander from the wave-1001 group D implementer report
(`w1001d-PB1233-report.md`, new defect 2).

**Shape.** Wave 1001 D (kb/Work PB1665) moved the RENAMES THROUGH tiling into STORAGE bytes, so a national leaf
counts two bytes per position. A window whose FROM or THRU boundary falls on the odd byte of a national character —
only a REDEFINES overlay of a different layout can put a boundary there — has no whole character of that leaf, and
`RenamesSpanPart.FromBytes` returns null, which the tiler reports as COBOLNET1655. §13.18.45.4 GR2 makes the alias an
alphanumeric group over the record's storage, so the window is addressable byte-wise; the refusal rejects legal source.

**Code site.** `src/Cobol.Net.Compiler/Binding/Model/RedefinesModel.cs#RenamesSpanPart.FromBytes` and its caller in
`src/Cobol.Net.Compiler/Binding/DataBinder.cs` (the RENAMES tiling loop, `stuck = true` arm).

**Repro.** None recorded in the report; the first step is to write one: a record whose national leaf is overlaid
by a REDEFINES of alphanumeric items with an odd-byte boundary inside that leaf, and a RENAMES … THROUGH whose
window ends at that boundary.

`pb1902_renames_window_inside_national.cob`:

```cobol
      *> kb/Work PB1902 - a RENAMES THROUGH window whose boundary falls on the odd byte of a national
      *> character, reachable only through a REDEFINES view of the national items (national items: ISO 2002).
      *> 13.18.45.4 GR2: "When the THROUGH phrase is specified, data-name-1 defines an alphanumeric group item that
      *> includes all elementary items starting with data-name-2 ... and concluding with data-name-3", and
      *> 13.18.45.3 SR11 orders only the two operands' storage areas, so R is the record's storage from the start
      *> of N1 to the end of X2. Layout (one national character = 2 bytes): N1 bytes 1-2, N2 bytes 3-4; the view
      *> GX: X1 byte 1, X2 bytes 2-3, X3 byte 4; T bytes 5-6. Expected values:
      *>   LENGTH OF R = 3 (bytes 1-3: R ends inside N2), LENGTH OF S = 5 (S = X2 THRU T, bytes 2-6)
      *>   MOVE "WXYZ" TO GX, MOVE "QRS" TO R:   R = QRS, GX = QRSZ, X1 = Q, X2 = RS, X3 = Z
      *>   MOVE "abcde" TO S:                    S = abcde, GX = Qabc, T = de, R = Qab
       IDENTIFICATION DIVISION.
       PROGRAM-ID. PB1902REN.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 REC.
          05 G.
             10 N1 PIC N VALUE N"A".
             10 N2 PIC N VALUE N"B".
          05 GX REDEFINES G.
             10 X1 PIC X.
             10 X2 PIC X(2).
             10 X3 PIC X.
          05 T PIC X(2) VALUE "TT".
       66 R RENAMES N1 THRU X2.
       66 S RENAMES X2 THRU T.
       PROCEDURE DIVISION.
           DISPLAY FUNCTION LENGTH(R) " " FUNCTION LENGTH(S)
           MOVE "WXYZ" TO GX
           MOVE "QRS" TO R
           DISPLAY R "|" GX "|" X1 "|" X2 "|" X3
           MOVE "abcde" TO S
           DISPLAY S "|" GX "|" T "|" R
           STOP RUN.
```
