**Rule it breaks:** ISO §8.4.2.1: a reference shall uniquely identify its resource, and alphabet-names, class-names and switch condition-names cannot be qualified. The sibling arms in the same file enforce it: LocaleBind (COBOLNET1665, §8.3.2.2), DynamicLengthStructureBind (§8.4.2.1) and SwitchBindSymbolic (§12.3.7.3 SR16 a). One rule should be checked in one place (CLAUDE.md rule 4, feedback_two_arm_dispatch).

**Scenario:** Measured with the current build (src/Cobol.Net.Cli/bin/Debug/net10.0/cobol.exe, whose binder lines are unchanged since the pin). SPECIAL-NAMES with `CLASS C1 IS 'A' THRU 'C'` and then `CLASS C1 IS 'X' THRU 'Z'`, followed by `IF V IS C1` where V = 'Y': the program compiles with no diagnostic and prints C1-NO, because the second definition was discarded. `ALPHABET A1 IS 'ZYX'` then `ALPHABET A1 IS NATIVE` also compiles clean, and the first table wins for every PROGRAM COLLATING SEQUENCE, SORT or IN reference. `SWITCH-1 ON STATUS IS S-ON` with `SWITCH-2 ON STATUS IS S-ON` compiles clean, and `IF S-ON` silently tests SWITCH-1. `ALPHABET A2 IS NATIVE` with `ALPHABET A2 FOR NATIONAL IS NATIVE` registers the name in both class maps, so TryResolveRangeAlphabet and CodedCharacterSetOf resolve one word to two alphabets. In each case the program's reference is ambiguous, and it compiles and runs on a definition the author may not have meant.
