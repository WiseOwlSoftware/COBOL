**Rule it breaks:** ISO §8.4.2.1: a reference shall uniquely identify its resource, and alphabet-names, class-names and switch condition-names cannot be qualified. The sibling arms in the same file enforce it: LocaleBind (COBOL1665, §8.3.2.2), DynamicLengthStructureBind (§8.4.2.1) and SwitchBindSymbolic (§12.3.7.3 SR16 a). One rule should be checked in one place (CLAUDE.md rule 4, feedback_two_arm_dispatch).

**Scenario:** Measured with the current build (src/WiseOwl.Cobol.Cli/bin/Debug/net10.0/cobol.exe, whose binder lines are unchanged since the pin). SPECIAL-NAMES with `CLASS C1 IS 'A' THRU 'C'` and then `CLASS C1 IS 'X' THRU 'Z'`, followed by `IF V IS C1` where V = 'Y': the program compiles with no diagnostic and prints C1-NO, because the second definition was discarded. `ALPHABET A1 IS 'ZYX'` then `ALPHABET A1 IS NATIVE` also compiles clean, and the first table wins for every PROGRAM COLLATING SEQUENCE, SORT or IN reference. `SWITCH-1 ON STATUS IS S-ON` with `SWITCH-2 ON STATUS IS S-ON` compiles clean, and `IF S-ON` silently tests SWITCH-1. `ALPHABET A2 IS NATIVE` with `ALPHABET A2 FOR NATIONAL IS NATIVE` registers the name in both class maps, so TryResolveRangeAlphabet and CodedCharacterSetOf resolve one word to two alphabets. In each case the program's reference is ambiguous, and it compiles and runs on a definition the author may not have meant.

## Landed

Re-probed on the Debug build (std 2023): `CLASS C1 IS "A" THRU "C"` then `CLASS C1 IS "X" THRU "Z"` compiled clean (`IF V IS C1`, V = "Y", printed C1-NO); `ALPHABET A1 IS "ZYX"` then `ALPHABET A1 IS NATIVE` compiled clean; `SWITCH-1 ON STATUS IS S-ON` with `SWITCH-2 ON STATUS IS S-ON` compiled clean (the note).

**Fix.** The rule is one check at the declaration funnel: `DataBinder.DeclareUserWord` asks `CheckUnqualifiableDeclaration` for every kind in the new data set `UserWordKinds.DeclaredUnqualifiable` (alphabet-name, class-name, dynamic-length-structure-name, locale-name, mnemonic-name, ordering-name), counting declarations per source element in `UserWordCensus.DeclareUnqualified`; a switch's condition-names (the `ConditionName` type is also the qualifiable level-88's) ask the same check explicitly in `BindImplementorNameEntry`. One descriptor, `COBOL4250 special-name-declared-twice` (ISO 8.4.2.1); the first declaration stands (every registry already keeps it). The two private refusals are deleted: `LocaleBind`'s COBOL1665 (retired in the catalog, never reallocated; its golden `pb64t1-locale-name-duplicate`, `DESIGN-locale-facility.md`, `CONFORMANCE.md` and the plan now name COBOL4250) and `DynamicLengthStructureBind`'s `ownNames` set (its repeat now stops at the census count, and a first declaration still replaces an INHERITED structure, 8.4.6.1). The mnemonic-name sweep: `MnemonicName` joins the set, so `SYSOUT IS DEV` beside `CONSOLE IS DEV` is refused. `SpecialNameRedeclarationDriftTests` fails when a SPECIAL-NAMES declaration kind goes through the funnel without joining the set.

SYMBOLIC CHARACTERS keeps its own §12.3.7.3 SR16 a rule and is left out of the set on purpose. A switch condition-name beside a level-88 of the same spelling is NOT a declaration conflict (a qualified reference tells them apart; only the unqualified one is ambiguous).

Goldens (cases/_unassigned, refused at 2002-2023): `pb3216-alphabet-name-declared-twice`, `pb3216-class-name-declared-twice`, `pb3216-switch-condition-declared-twice`, `pb3216-mnemonic-name-declared-twice`; the LOCALE twin `pb64t1-locale-name-duplicate` and the DYNAMIC LENGTH STRUCTURE case in `DynamicLengthTests.StructureClause_Refused` now expect COBOL4250.
