# PB3469 — the half-full-to-full leaf range is not an invariant of the keyed store

Source: PB3457 branch review R1-1 (`E:\COBOL-coord\scratch\reports\w1134c-PB3457-report.md`, "Review findings", low).
`tests/Cobol.Net.Tests.Unit/Store/KeyedStorePerformanceWitnessTests.cs` line 73 (the `LedgerPagesAtCheckpoint`
comment), `docs/rearchitecture/DESIGN-runtime-library.md` 2.2.1.11, `kb/Work/PB3457.md` and the PB3457 DEVLOG entry say
a scattered load leaves each ledger leaf anywhere from half full to full. The B-tree code does not keep that range: an
append split leaves an almost empty right leaf, and a delete shrinks a leaf to a quarter page before it merges.

Fix: read the split and merge policy in the store, state the true bound (or drop the range), and correct the comment,
the design doc and the PB3457 note in one change. The DEVLOG entry is history; a new entry corrects it. Sweep the other
fill-factor statements in the design doc.
