# PB2688 — wave trains cannot carry a branch that is already WAITING TO LAND

**Found by:** the wave-1041 unit (2026-10-08 05:53 PDT), planning the wave the train-1040 land unit handed it.

## Defect

Train 1040's land unit left `note-trend1040` (notes-only, PB2426 trend points; report
`scratch/reports/w1040t-PB2426-report.md`, Status DONE) unlanded with `next_unit: wave` and the reason "too small for
a train (never a lander for 1-2 clusters), so fold it into the next fix-lane wave's first train". The next wave cannot
do that:

- `plan_wave.py` sees the branch and prints it as `UNLANDED branches naming no open note (judgment): note-trend1040`,
  but writes nothing about it into `wf-args-w<wave>.json`.
- `.claude/skills/workstream/templates/wf_rolling_wave.js` builds each train's manifest (`land(batch)`) only from the
  results of its own implementer groups; it takes no argument naming a branch that finished before the wave started.
- The train lander brief (`templates/lander-train-brief.md`) tells a lander to carry every WAITING TO LAND branch only
  in the attended "cannot wait" case (MANDATORY-PRACTICES O11), not in a wave's trains.

So the hand-off asks for something no mechanism performs. The branch reaches main only when a later land unit batches
it with enough other DONE branches, and a land unit applying the same "never a lander for 1-2 clusters" rule hands it
on again. A trend-point branch that waits also goes stale against each later `gen_ledger.py` render (PB2426).

## Fix direction

One landing queue (PB2602) should also mean a waiting branch has a defined next train. Either `plan_wave.py` writes
every WAITING TO LAND branch (from `prune_worktrees.py`) into the args as carried manifest entries that the wave's FIRST
train lands with its own clusters, or `next_unit.py` chooses a land unit whenever a DONE branch has waited through one
wave. The first keeps "no solo trains" (memory batch-landings-no-solo-trains) and is the shape that makes the next case
automatic; it needs a drift test that a branch listed WAITING TO LAND at planning time appears in the first train's
manifest.
