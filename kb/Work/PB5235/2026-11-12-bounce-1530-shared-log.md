**Merge-group bounces 2 and 3 of #1530 (runs 43130044782 and 43132487649, 2026-11-12): one cause, a GENUINE red of
this branch's CI change, fixed on the branch.**

In both runs Linux shards 2-5/5 and Windows shards 2-7/7 failed at ONE step, "The hosts ran the generated outputs they
were handed (ci_plan.py handed)", with `GENERATED BY THE HOST: a Conformance host generated its own conformance-suite
instead of the one handed it`; every test step before it passed (Linux shard 5: Conformance 4,247/4,247, INV-1-strong
62/62). The Conformance steps WERE handed the suite (`WISEOWL_COBOL_GATE_SUITE` in their env). The shard 5 artifact's
`harness-observations.log` holds one `GENERATED-OWN  conformance-suite` line at 01:13:06Z, pid 3194: the UNIT step's
host (Characterization started 01:15:05Z, Conformance 01:15:07Z). The Unit assembly reads `SuiteManifest`
(BoundDeferralDriftTests and FormatWordDriftTests among others), depends on no generated target (its key covers every
population input, the suite's among them), is handed nothing, and so generates its own, legitimately. Every test step of
a shard pointed `WISEOWL_COBOL_HARNESS_LOG` at the one `harness-observations.log`, so `handed` read the Unit host's line
as the Conformance host's. Shard 1 was green because its Unit partition holds none of those classes. The local gate never
had the defect: it writes `<run>/<asm>.observations.log` per host and `_check_generated` reads the dependent's.

**Fix.** `buildgraph.observation_log(directory, assembly)` is the one name of a host's log, used by gate.py and CI. Each
CI test step writes `TestResults/<OS>-shard/<Assembly>.observations.log`; `ci_plan.py handed --results <dir>` reads
only each dependent assembly's own log. `ci_wiring` refuses a test step whose log is not its host's own, and a handed
step whose `--results` is not the steps' results directory; `test_linux_gate.py`'s harness-log rule now names the
host's own log, found from the build target whose project the step tests. New negatives: `ci_plan` plants the shared
log in the real workflow, and its `handed` arm plants the bounce itself (the Unit host's own mark in its own log is
GREEN, the Conformance host's is RED); `test_linux_gate` plants the shared name and a project no target names. The
three path patterns of a test step moved into `ci_workflow` (the one reader of a workflow's shape), so both readers
share them.
