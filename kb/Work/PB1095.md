# PB1095 — OPEN — `CodedCharacterSet.CharAt` answers every coded-set ordinal of a literal-phrase alphabet with ONE character (literal-1 of an ALSO group), applying GR7 k6's SYMBO

## Rule text (every citation re-run by the registrar)
- `python scripts/spec/cite.py --check 12.3.7.4 "If alphabet-name-1 is referenced in a SYMBOLIC CHARACTERS clause, only literal-1 is used to represent the character in the native character set"` → `OK  §12.3.7.4 7) 2.  (General rules)`

### Adjudicator finding (special-names-paragraph-p3, harm wrong-answer)
- **Mechanism:** CodedCharacterSet.CharAt answers every coded-character-set ordinal of a literal-phrase alphabet with ONE character, RepByPos (literal-1 of an ALSO group), so GR7 k6's SYMBOLIC-CHARACTERS-only exception ('only literal-1 is used') is applied to every coded-set reference: a CLASS clause numeric literal IN such an alphabet admits literal-1 and drops the literal-3 characters that share its ordinal.
- **Repro:** probe/snp3/k6.cob, --std 2023: SPECIAL-NAMES. ALPHABET AL IS "B" ALSO "A" ALSO "Z", "C" CLASS C1 IS 1 IN AL. 01 X PIC X VALUE "A". 01 Y PIC X VALUE "B". IF X IS C1 ... IF Y IS C1 ... -> prints A-NOT-C1, B-IN-C1.
- **Expected (spec):** GR7 k6: 'the characters of the native character set specified by the value of literal-1 and literal-3 are assigned to the same ordinal position in ... the character code set', and only 'If alphabet-name-1 is referenced in a SYMBOLIC CHARACTERS clause, only literal-1 is used'. Ordinal 1 of AL's coded set therefore holds B, A and Z; GR12 a makes CLASS literal 1 IN AL name that ordinal, so class C1 = {B, A, Z} and 'A' IS C1 is TRUE.
- **Observed:** Measured A-NOT-C1 / B-IN-C1. SYMBOLIC CHARACTERS SB IS 1 IN AL -> 'B' is correct (the exception's own case). Reading-dependent: GR12 a says 'the ordinal number of a character' (singular), so an adjudicator may hold the single-character reading; the k6 exception sentence would then be redundant, which is why the plural reading is preferred here. Classified PARTIAL on the row, not DIVERGES, pending that reading; the fix would give CodedCharacterSet a 'characters at ordinal' answer for set-valued references and keep CharAt (literal-1) for SYMBOLIC CHARACTERS.
- **Code site:** src/Cobol.Net.Compiler/Binding/CollatingModel.cs#CodedCharacterSet.CharAt (if (ordinal <= t.NextFree) return ((char)t.RepByPos[ordinal - 1]).ToString();); caller DataBinder.Switches.cs#LiteralPhraseOperand (r.InSet arm)
- **Clause (adjudicator):** ISO/IEC 1989:2023 §12.3.7.4 GR7 k)6 (cite.py --check 12.3.7.4 "If alphabet-name-1 is referenced in a SYMBOLIC CHARACTERS clause, only literal-1 is used to represent the character in the native character set" -> OK, located by cite.py under GR7); GR12 a
