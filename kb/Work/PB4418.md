# PB4418 — complete counts a bounce as a failed merge-group run only; a queue removal is a bounce the record already carries

**Measured 2026-11-02:** `python scripts/orchestrator/landing_measure.py complete` prints
`landing-measure: PR #963: 1 bounce cause(s) name more than the 0 bounce(s)` and does not complete the record. PR #963
(branch worktree-wf_d2f43316-4ca-4, merged 2026-11-01T13:41:08Z) never gets its merged time or its CI wall. The record's own
note field reads "merge_conflict removal 2026-11-01T09:46Z".

**Mechanism.** `landing_measure.py` `complete()` (~637-680) sets `bounces` to the count of merge-group runs of the pull
request whose conclusion is failure or timed_out (`mine`, filtered on the `/pr-<n>-` head branch). A pull request the merge
queue REMOVED for a merge conflict has no failed run, so the recount gives 0. The record already carries `bounces: 1` and
`bounce_causes: ["conflict"]`, written by the landing lane or by `record --bounce-causes conflict`. The patch writes the
recount over the record, and the validation (~200, `len(rec["bounce_causes"]) > rec["bounces"]`) refuses it:
"bounce cause(s) name more than the N bounce(s)". The refusal repeats on every `complete` run.

**Fix direction.** One definition of a bounce: a failed merge-group run OR a queue removal, with removals read from the
pull request timeline (the removed-from-merge-queue events), or a separate removals count that the cause list is checked
against. Add a self-test case for a conflict removal (a record with `bounce_causes: ["conflict"]` and no failed run
completes with its merged time and CI wall). Not the same as PB3124 (which over-counts a stacked group's failure as a
bounce) or PB3987 (the lane re-landing a bounced branch); extend neither.
