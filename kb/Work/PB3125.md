# PB3125 — the branch survey cannot see a stopped landing-lane attempt

> flags: process-only

Source: resume unit 2026-10-13 ~11:20 PDT.

**Mechanism:** `scripts/prune_worktrees.py` `lifecycle` (near line 381) takes a DONE report into its WAITING arms only
when the report is no older than the branch's last activity plus `REPORT_SLACK_MIN` (10 minutes, near line 378; the
DONE arm near line 407). `enqueue.py land` merges origin/main into the branch and commits the DEVLOG stamp BEFORE
the landing oracle runs. When the oracle refuses (exit 7), no pull request exists, so the BOUNCED arm does not apply,
and the two new commits make the branch's last activity newer than its report. The row falls through to the final
`return 'DECISION', evidence(row)` (near line 429), whose evidence names neither the stop nor who acts next. DECISION
is not in `CARRIER_STATES` (near line 587), so `contained` leaves every predecessor the branch carries at DECISION too.
The survey never reads the lane's attempt records (`<coord>/land-lane/`), although `land_lane.py tick` reads the
survey.

**Instance (2026-10-13):** `worktree-wf_d63f7207-db5-30` (wave 1069 G, PB2720 + PB374) has a DONE report written
2026-10-12 23:32 PDT and stamped Review CLEAN at `0a377e174dca`. Then enqueue.py merged main as `01bcbcd23` (23:36) and
stamped DEVLOG 1997 as `881a92aee` (23:49). Lane attempt `20261013T063646769097Z` passed both gates (Windows leg 1
GREEN, `=== LINUX GATE: GREEN ... HEAD 01bcbcd23 ===`) and then stopped at
`=== LANDING ORACLE: REFUSED (1 reason(s)) ===` / `=== ENQUEUE: NOT QUEUED (exit 7, above) ===`. From 06:36Z on:
- `land_lane.py status` lists it `STOPPED ... exit 7 — the enqueue unit's: step 4 finisher`;
- `plan_wave.py --dry-run` lists it under "awaiting landing (excluded; an `enqueue` unit first)";
- `prune_worktrees.py` lists it `DECISION`, along with its two ancestors `worktree-wf_d63f7207-db5-28` and
  `worktree-wf_d63f7207-db5-9` ("no fix-lane report names it").

So three readers give two answers. The resume unit must decide every DECISION row (MANDATORY-PRACTICES O10), so it
re-derived the owner by hand from the lane's status, the land log and `git merge-base --is-ancestor`. Every later
session will do the same until the oracle finisher moves the tip.

**Harm:** process cost only. Each resume unit and operator tick re-investigates three branches the lane already
assigned. The survey's DECISION count, which the session probe prints every session, is inflated by rows that have
an owner.

**Fix shape (for the implementer to confirm, and to record in MANDATORY-PRACTICES O10 and
DESIGN-orchestrator-loop):** the survey reads the lane's attempt records through land_lane's own reader (one reader,
imported lazily because land_lane imports the survey; its status text is never re-parsed). A branch whose newest
attempt is STOPPED and uncollected, at its current tip or at a tip followed only by mechanical commits (main merged
in, the DEVLOG stamp: the `unreviewed_since(...) == []` test `review_holds` already uses), reads a state that names
the stop and its owner. That state belongs in `CARRIER_STATES`, so the predecessors it carries read IN FLIGHT. A
self-test plants a DONE report with a CLEAN stamp, a later merge plus DEVLOG-stamp commit and a STOPPED attempt. That
row must not read DECISION, and its ancestor must read IN FLIGHT. Rejected shape: measuring the report's age against
the last non-mechanical commit alone. That would make the row WAITING TO LAND, and the lane would re-run a landing
that the oracle refuses until a finisher re-records the baseline (kb/Work PB3107).
