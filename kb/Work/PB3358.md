# PB3358 — DISPLAY of a strong variable-length group with a pointer/object-reference leaf aborts at run time

Source: `E:\COBOL-coord\scratch\reports\w1114a-PB3139-report.md`, "New defects". No existing note covers the mechanism
(grepped `kb/Work` for `GroupImage`, `CurrentExtentComposes`, `Tier-C byte island`, `pointer/object-class leaf`, `DOC-A.1-214`:
PB3139 only names DISPLAY among the consumers that "need their own determination", PB3129/PB3289 are the CALL and imageless-operand
refusals).

**Symptom.** DISPLAY of a strong variable-length group that holds a pointer or object-reference leaf compiles clean and aborts at
run time: `NotImplementedCobolFeatureException: whole-group image of 'WS-G' with a pointer/object-class leaf ... Tier-C byte
island`. Repro (outside the tree, in the coordinator scratch directory): `E:/COBOL-coord/scratch/w1114a/WHOLE.cob`, edition 2023.
Siblings in the same directory: `WHOLE2.cob` (relation and FUNCTION LENGTH run: `LEN 0015`, `EQ`); a MOVE to PIC X is correctly
refused COBOL1931.

**Rule.** ISO §14.9.11.4 GR7 (checked with `cite.py --check`): "If identifier-1 references a variable-length group, the format in
which its contents are displayed is defined by the implementor." The implementor's documented format is
`docs/CONFORMANCE.md` DOC-A.1-214: a reference's positions are the D-SLOT placeholder (eight spaces) in the group image that
every character consumer reads, DISPLAY included.

**Code sites.** `src/WiseOwl.Cobol.Compiler/CodeGen/Roslyn/PlaceRenderer.cs:703` (`GroupImage`), gated on
`src/WiseOwl.Cobol.Compiler/Binding/Model/DataItem.cs:1120` (`CurrentExtentComposes`, which excludes a reference leaf).

**Why not fixed in the discovering slice.** Admitting a reference to that law also routes the CALL carrier
(`BoundaryImageCapable`) away from the leaf vector, so the fix needs a one-way-image capability apart from the carrier (the split
PB2496 merged; link). Shares PB3139's shape, not its mechanism. PB3273 (landed 2026-10-18: it added `DataItem.CurrentExtentAreaCapable`, the member law with a reference a fixed placeholder, a candidate for the one-way capability this note needs; host entry of a strong group with a variable-length
component and a reference) is a different mechanism, related.

## Landed (2026-10-18, w1120 group C)

**Re-probe.** On a fresh Debug build of main b349e6d44, `WHOLE.cob` (edition 2023) printed `LEN 0015` and then aborted with `NotImplementedCobolFeatureException: whole-group image of 'WS-G' with a pointer/object-class leaf`. The cell-backed twins (an EXTERNAL strong group; an ADDRESS-OF-taken one) aborted with the same island, in `CellVarContiguous`'s loud ("variable-length group image of"), and by `IntrinsicBinder.ImageOrStage`'s guard (read, not run on the old build) FUNCTION LENGTH of a table of variable-length elements holding the leaf staged its named Tier-C.

**Root cause.** One capability was asked two questions. `DataItem.CurrentExtentImageCapable` gates the DISPLAY format (A.1 item 57), FUNCTION LENGTH, AND the section 8.5.1.12 component carrier; its member law (`CurrentExtentComposes`) tests `IsImageCapable`, which excludes a pointer/object leaf, so the format was refused for a reason that only the carrier has (a placeholder has no inverse). The fixed-group sibling had been split in PB244 (`TransferImageCapable` beside `IsImageCapable`); the variable-length arm never was.

**Fix.** `DataItem.CurrentExtentTransferImageCapable` is the one-way twin: the member law is ONE function with a `transfer` flag (`TransferImageCapable` / `ElementTransferImageCapable` for the fixed-image tests), so the two capabilities cannot classify a member differently. `GroupImageCodec.VarParts` and `DynElementImage` classify by the one-way predicates (equal to the two-way ones for every group without a slot leaf), `RecordStructEmitter` emits `CurrentImage()` for the wider capability and the `AsVarImage`/`FromVarImage` carrier pair only for the narrower, and `PlaceRenderer.VarGroupCurrentImage` takes `transfer:` (the twin of `GroupImage`'s) through its declared and cell-window arms. DISPLAY (`AcceptDisplayEmitter`), FUNCTION LENGTH / BYTE-LENGTH (`IntrinsicBinder.ImageOrStage`, `IntrinsicRenderer`) pass it; MOVE, comparison, CALL and a record keep the carrier capability, so PB3139's refusals stand.

**Sibling sweep.** Every consumer of the capability was walked (`grep CurrentExtentImageCapable`): the sending consumers are exactly DISPLAY and LENGTH/BYTE-LENGTH; the others read back or carry (MOVE/compare `VarGroupOperand`, CALL `CallEmitter`, `ActivationDescriptions`, `WriteVarGroupContiguous`, `RecordAreaImage`, SORT keys) and keep the narrow law. Shapes probed on the fix: a nested fixed strong group, a nested variable-length strong group, a fixed table of references, an OCCURS DEPENDING table of fixed and of variable-length elements, a dynamic-capacity table of fixed and of variable-length elements, a fixed table of variable-length elements, one element of each (`DISPLAY FT OF G (2)`), POINTER and PROGRAM-POINTER leaves, and the EXTERNAL and ADDRESS-OF cell forms; a BASED variable-length group is refused at the declaration (COBOL2560). FUNCTION UPPER-CASE of a variable-length group stays refused (COBOL1627), and `--permissive`'s coercion of one aborts at run time with the Tier-C island, with or without a reference leaf (a separate lead, not this mechanism).

**Goldens.** `pb3358_vlg_display_reference_leaf` (2014: every declared shape), `pb3358_vlg_display_reference_leaf_cell` (2023: EXTERNAL and ADDRESS OF), `pb3358_vlg_display_pointer_leaf` (2014: POINTER and PROGRAM-POINTER, NULL images), and the negative `pb3358-vlg-display-reference-leaf-at-2002` (COBOL0900 at 85 and 2002, for the DYNAMIC LENGTH clause); the drift test `VariableLengthBoundaryDriftTests.CurrentExtentTransferCapability_IsDefinedOnceOverTheSameMemberLaw` keeps the capability single and its consumers on the right side.

**Merged with PB3273 (2026-10-19, w1128 group B).** PB3273 had landed `CurrentExtentAreaCapable`, the identical member law for the host entry cell area; the two are now ONE property, `CurrentExtentTransferImageCapable`, and the host-entry and published-record callers use it. Learned: `DataItem.cs#CurrentExtentTransferImageCapable` is the single reference-tolerant current-extent law (one-way image consumers and the cell area); `CurrentExtentImageCapable` stays the carrier law; never add a third.

## Finisher (2026-10-19, w1128 group B, after the landing's Linux gate)

The landing stopped `GATE RED (Linux)` on 161bacdc3: `NulByteDriftTests.NoTrackedTextFileContainsANulByte` found the NULL pointer images in `pb3358_vlg_display_pointer_leaf.out`. A pointer image always holds zero positions, so the golden now DISPLAYs each group at an extent with no pointer occurrence (ODO count 0; dynamic capacity 0) and counts the leaves with FUNCTION LENGTH; the displayed pointer characters are pinned by `tests/WiseOwl.Cobol.Tests.Conformance/VariableLengthGroupPointerImageTests.cs`. That test found a shape the first pass missed: a dynamic-capacity table whose ELEMENT is a pointer/object leaf failed the backend compile (CS0029 in `CurrentImage`, `DynElementImage`'s pass-through lambda); `GroupImageCodec.DynElementImage` (`src/WiseOwl.Cobol.Compiler/CodeGen/DataDivision/GroupImageCodec.cs`) now renders such an element as `SlotImageOf` renders a fixed table's. The Windows leg 1 never ran the NUL sweep: PB3112's tier-0c cost cap.
