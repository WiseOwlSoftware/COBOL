# PB4280 — the "floating comment line" unit case duplicates the fixed-comment case

**Sites:** `tests/WiseOwl.Cobol.Tests.Unit/DivisionCursorTests.cs` (whole: the R1-1 blank/space/floating/fixed comment cases near :146 on the PB4241 branch), `src/WiseOwl.Cobol.Frontend/Preprocessor/ReferenceFormatProcessor.LogicalConversion.cs:191` (`LogicalLineBuilder.TryFirstText`, the arm the case is meant to pin; read-only here).

## What happens

PB4241's report claims unit cases for floating comment lines. The case so labelled is `"      *> ..."`: six spaces, so the asterisk stands in column 7, the indicator area. `KindOf` classifies it `LineKind.Comment`; it never reaches `CommentEntryOf` or `TryFirstText`, so it duplicates the fixed-comment case. No test or golden pins the floating-comment arm of `TryFirstText` for an Area-A `*>` line, which is round 1 R1-1's exact scenario (a `*>` that opens in Area A, columns 8-11, and not in the indicator column).

## Fix

Change the case to put the `*>` in Area A (column 8 or later, after the indicator space) and assert it neither begins a division header nor ends a comment entry; add a golden if the unit case cannot reach the converter path. Check the other cases in the theory for the same column slip.
