# PB4275 — COBOL0863's summary and its absence-guards lag the move of the required-clause report to COBOL5701

**Sites:** `src/WiseOwl.Cobol.Editions/Diagnostics/DiagnosticCatalog.cs:3962` (`DiagnosticCatalog.FileKeyClauseRule`: the summary still says it covers ISO 12.4.5.1, the file control entry's required clauses; the branch moved that requirement to COBOL5701 and trimmed only the message text),
`tests/WiseOwl.Cobol.Tests.Conformance/FileControlKeyRuleSpecTests.cs:287` (`FileControlKeyRuleSpecTests.LegalIndexedEntry_WithAGroupKeyAndAQualifiedReference_IsAccepted`),
`tests/WiseOwl.Cobol.Tests.Conformance/FileControlKeyRuleSpecTests.cs:400` (`FileControlKeyRuleSpecTests.ALegalSortMergeEntry_DrawsNoKeyClauseDiagnostic`),

## What happens

Review findings R1-1 and R1-2 of the PB4236 branch (wave 20261788, group A; both low, not blocking at round 1).

1. R1-1. COBOL0863 (`FileKeyClauseRule`) names a key clause that was written; PB4236 moved the "required clause is absent" report, RECORD KEY included, to COBOL5701 (`FileControlClauseRequired`) and trimmed only the message text. The descriptor's summary still says it covers ISO 12.4.5.1 (the required clauses). The catalog summary is the text a user reads for the code.
2. R1-2. The over-rejection guards (the four methods above, at the report's lines :405, :294, :514 and :818 on the branch) assert only that COBOL0863 is absent. A false "has no RECORD KEY" report on a legal entry now goes out under COBOL5701, so none of the four would go red; the sort-merge guard's own doc names that message as what it protects.

## Fix

Reword the summary to the key clause's own subject (cite 12.4.5.1 only for what COBOL0863 still enforces; validate with `python scripts/spec/cite.py --check`). Make each guard assert that neither COBOL0863 nor COBOL5701 is drawn on its legal entry. Sweep the other tests that assert the absence of one code where the report moved to another.
