# PB1940 — OPEN

Filed by the train-1007 lander from wave 1007 group B's report (`w1007b-PB480-report.md`, "New defects" item 1).
Same root as [[PB1116]], which landed the typed-INVOKE arm in train 1007.

## Defect

A strong group whose subordinates include `USAGE OBJECT REFERENCE` has no boundary character image, so the CALL and
user-function lanes have no carrier for it, and `CALL "PGNS" AS NESTED USING G` (G of a `TYPEDEF STRONG` holding an
object reference) draws COBOLNET1688 "this activation boundary does not yet carry such a group". §14.8.2.2 2) "If
either the formal parameter or the corresponding argument is a strongly-typed group item, both shall be of the same
type" (`cite.py --check 14.8.2.2` → `OK §14.8.2.2 2)`) is the only conformance rule, and the source satisfies it;
§14.9.4.3 SR25 sends CALL's argument conformance to §14.8.2.

## Re-probed and sited — wave 1015 Z2 (2026-10-04, not started: the group split at PB988)

Still COBOLNET1688 on the wave build. The program ABI decides a boundary item's carrier through ONE classification,
`CallEmitter.CrossingOf(Place)` (activating side) and `ProgramEmitter.FormalCrossing` (activated side), with arms Native /
Text / VarGroup / Managed. The fix is a fifth arm, `CallCrossing.Leaves` (`OoClassTable.LeafCarried`, tested before
VarGroup/Text), carried as `ManagedPointer<object?[]>`: `CallEmitter.RefCarrier` (OverField over `PlaceRenderer.GroupLeaves`
/ `WriteGroupLeaves`), the BY CONTENT snapshot in `ArgCarrierText` (and exempt it from that method's loud imageless-group
arm), `ProgramEmitter.FormalCarrierType` (`object?[]`), `FormalAdopt` (a new `CobolArgAdapt.Leaves` that admits only a
`ManagedPointer<object?[]>` — `Slot<T>` would also admit the predefined NULL), the unbound seed, copy-in
(`WriteGroupLeaves`) and copy-out (`GroupLeaves`), and `ReturningDelivery` with a `StoreReturn(CobolArg?, object?[])`
overload. Then delete the two carrier residues, `ParameterConformance.CheckArgument`'s LeafCarried refusal and
`ReturningCarrierResidue` (asked at `CallBinder.cs` ~656). Conformance itself is already decided by
`OoConformance.DescriptionMismatch` (both LeafCarried → same-type sentence).

## Superseded fix — PB2087 item 5 (2026-10-05, external-repository design round 7)

The leaf-vector arm above (`CallCrossing.Leaves`, `ManagedPointer<object?[]>`) is NOT to be built. kb/Work PB2087
moves every boundary-aliased group (and REDEFINED formal) into a `StorageCell`, which carries managed SLOTS, and
crosses it as a cell + offset + width area (PB2087 item 5), so a strongly-typed group with an object-reference or
pointer leaf crosses by the same mechanism and the `ParameterConformance` refusal goes in that change. One carrier, not
two (CLAUDE.md rule 4; `docs/rearchitecture/DESIGN-external-repository.md` preamble "Not in this design" and §21 slice 3).
This note closes when PB2087 lands; its repro (`pgn.cob`, expected `LX=ABC` then `REF:XYZ`) becomes one of PB2087's
goldens.
