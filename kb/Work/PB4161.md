# PB4161 — the COBOL1666 SET LOCALE message is pinned by no test

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/SetBinder.cs:374` (`SetBinder.BindSetLocale`), `tests/WiseOwl.Cobol.Tests.Unit/SetDiagnosticNamesReceiversDriftTests.cs:46` (`SetDiagnosticNamesReceiversDriftTests.ElidedEcho`).

Review lead R1-1 (low, not blocking at round 1) of the PB4121 branch. PB4121 reworded `BindSetLocale`'s duplicate-category message
(COBOL1666, reachable from source) from `SET LOCALE ... {w}` to name the earlier categories, e.g. `SET LOCALE LC_TIME LC_TIME: ...`.
Nothing pins it: `SetLocaleDispositionTests` asserts only the code, and `ElidedEcho`'s pattern needs the ellipsis immediately after
`SET`, so it cannot see a `SET LOCALE ...` head; reverting to the elided form passes every gate. The new echo is also a prefix of
the categories (`Skip(1).Take(i)`), not the statement as written, so for a third duplicate it does not show the later categories.

Fix: assert the message text in `SetLocaleDispositionTests` (the categories as written, from the cited SET LOCALE rule) and widen
`ElidedEcho` to see `SET <word> ...` heads, or fold this into PB4160's generalized drift test over every message opening. Make the
echo the statement's written text (`WrittenSource.Of`), not a prefix slice.
