**Rule it breaks:** dimensions.md 3 (allocation on a hot path; work not needed for the answer) and design section 5.4 (a measured premise); section 8.1 places the one text law in the runtime layer, so the change belongs in the runtime kernel, never in a per-site emitter fold

**Scenario:** ConditionRenderer.RenderFigurativeRelational emits CobolString.CompareFig for every relation with exactly one figurative or ALL-literal operand, whatever the other operand's width, with no compile-time fold for a fixed-width item (the sizing moved to run time for the ref-mod case, PB297). CompareFig calls FigToWidth, which allocates new string(seed, w) for a one-character seed and, for an ALL literal of k > 1 characters, a StringBuilder, its char[w+k] chunk, the built string and the [..w] substring, and only then compares character by character. So the most common condition in COBOL, IF WS-NAME = SPACES on PIC X(30), allocates an 88-byte string per evaluation that the comparison never needed: GR2's sized figurative at position i is just seed[i % seed.Length]. A batch loop over 1,000,000 records with three such tests allocates 3,000,000 strings (about 264 MB of Gen0 garbage); the same test against a non-figurative item allocates nothing. The EVALUATE / level-88 range twin ThruMemberFig sizes BOTH ends the same way (up to 2 strings per range test), and ThruMember re-runs the lo-versus-hi inversion test on every evaluation.

**Measured how:** R2 batch finding `runtime-values-3--performance--f1#1` (pair runtime-values-3--performance), read in the pinned tree at 8be23006851a; skeptics rule refuted, scenario upheld, site upheld. Measurement: Counted on the pinned code at a stated size, not timed (a build is refused while the fleet runs in the tree): one evaluation of IF X = SPACES on PIC X(30) runs CompareFig -> FigToWidth, which allocates 1 string of 22 + 2*30 = 82 -> 88 bytes; one evaluation of IF X = ALL "AB" allocates 4 objects (StringBuilder, char[32] chunk, 32-char string, 30-char substring). 1,000,000 iterations x 3 such tests = 3,000,000 allocations, about 264 MB. A non-figurative relation of the same operands (CobolString.Compare) allocates 0.
