# PB4564 — read-next-after-failed-read-not-46: READ NEXT after an unsuccessful random READ returns a record (status 00) instead of status 46

Filed 2026-11-03 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-batch-3000-20261103`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

A relative file is open in dynamic access. A random READ ends with the invalid key condition (status 23), and the
sequential READ after it (READ NEXT) then succeeds with status 00, returning the next existing record after the
requested key. ISO requires that READ to be unsuccessful with I-O status 46, because the previous READ on the file
connector was unsuccessful. Status 46 is not the at end condition, so a program that loops on READ NEXT until AT END
ends on GnuCOBOL but, by the standard, does not end at AT END when the implementor continues after the status.

## Minimal test case

Free reference format (`-free`).
```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. RDNXT46.
ENVIRONMENT DIVISION.
INPUT-OUTPUT SECTION.
FILE-CONTROL.
    SELECT F ASSIGN TO "rdnxt46.dat"
        ORGANIZATION IS RELATIVE
        ACCESS MODE IS DYNAMIC
        RELATIVE KEY IS RK
        FILE STATUS IS FS.
DATA DIVISION.
FILE SECTION.
FD F.
01 REC PIC X(4).
WORKING-STORAGE SECTION.
01 RK PIC 9(2) VALUE 0.
01 FS PIC XX VALUE SPACES.
PROCEDURE DIVISION.
    OPEN OUTPUT F
    MOVE 2 TO RK
    MOVE "R002" TO REC
    WRITE REC
    CLOSE F
    OPEN INPUT F
    MOVE 1 TO RK
    READ F
        INVALID KEY DISPLAY "RANDOM READ 1: " FS
    END-READ
    READ F NEXT RECORD
        AT END DISPLAY "AT END: " FS
        NOT AT END DISPLAY "NEXT: " REC " " FS
    END-READ
    DISPLAY "AFTER READ NEXT: " FS
    CLOSE F
    STOP RUN.
```

## Environment

cobc (GnuCOBOL) 3.2.0 on WSL2 Ubuntu (Windows 11 host). Compiled with `cobc -x -free -std=cobol2014 -o p prog.cob`
(prog.cob holds the program above) and run as `timeout 10 ./p` from the program's directory; the program creates its
own data file.

## Observed result

Exit code 0. Output:
```
RANDOM READ 1: 23
NEXT: R002 00
AFTER READ NEXT: 00
```

## Expected result (per ISO)

- §2023:14.9.30.4 rule 21: "For a sequential READ statement, if the previous READ or START statement for the file connector
  was unsuccessful, then the READ statement is unsuccessful and the I-O status is set to '46'".
- §2023:14.9.30.4 rule 19: "An implicit or explicit NEXT phrase or a PREVIOUS phrase results in a sequential read", so READ
  NEXT is a sequential READ.
- §2023:14.9.30.4 rule 29: the random READ of relative key 1 is unsuccessful: "If the physical file does not contain such a
  record, the invalid key condition exists and execution of the READ statement is unsuccessful".
- §2023:14.9.30.4 rule 18: after an unsuccessful READ, "the file position indicator is set to indicate that no valid record
  position has been established".
- §2023:9.1.13.7 rule 6 defines status 46 for exactly this case: "The preceding READ statement referencing that file
  connector was unsuccessful."
- §2023:9.1.13.1: a status beginning with 4 is a fatal exception condition, after which "The implementor may either continue
  or terminate the execution of the run unit"; if it continues, control goes to the end of the READ statement and
  "Any NOT AT END or NOT INVALID KEY phrase specified for that statement is ignored."

Edition: these rules hold in COBOL 2014. The 2009 committee draft (CD 1.2) that led to 2014 carries the same status-46
definition and the same READ rules, and Annex E of 2023 lists no change to them. The READ NEXT is unsuccessful,
makes no record available, and runs neither AT END (no at end condition exists) nor NOT AT END. If the implementation
continues the run unit after the fatal status (§2023:9.1.13.1), the expected output is:
```
RANDOM READ 1: 23
AFTER READ NEXT: 46
```
If it terminates the run unit instead, the output stops after `RANDOM READ 1: 23`. Under neither choice may the READ
NEXT return `R002` with status 00.

## Our compiler

WiseOwl COBOL (`--std 2014 --source-format free`) compiles the program with no diagnostic (no COBOL#### code). It
prints `RANDOM READ 1: 23` and then `AFTER READ NEXT: 46`, and exits with code 0.

## Fix site

libcob/fileio.c, `cob_read`. The sequential-read arm (`key == NULL`) returns COB_STATUS_46_READ_ERROR only when
`flag_end_of_file` or `flag_begin_of_file` is set. An unsuccessful random read (a 2x status from the organization's
`read`, here `relative_read` returning COB_STATUS_23_KEY_NOT_EXISTS) sets no flag. The `read_next` that follows
therefore continues from wherever `relative_read` left the file offset, which is the missing slot. The fix records
that the last READ or START was unsuccessful and refuses the next sequential read with status 46.
