# PB3463 — differential fuzzing with a local model

## The owner's decision — 2026-10-20 ~11:00 PDT

The owner asked (10:40) how the RTX 5090 could run a local model overnight on "some of our work", a focused task of 6 to 10
hours, and whether file edits were a fit. The evaluation (this session, recorded in the evidence file below) said: a local
model can do useful overnight work here only where a MACHINE judges its output, because the three recorded experiments (the
2026-10-03 spike, PB2886's one-shot, the aider run closed in DEVLOG 714) each produced confident output an expert had to
refute; unsupervised edits to the compiler are that class of task. Two shapes fit, both named untried by the 2026-10-03
record: differential fuzzing (this note) and a vision model as second reader of the spec's rendered diagrams (not built).
The owner, verbatim: **"Build the harness, but we'll try a small test run today"**, after an earlier note that additional
or alternative models can be downloaded.

## What was built — `scripts/differential_fuzz.py`

- **The model writes; it never judges.** Each program is seeded from one clause of `specs/ISO_COBOL.md` (statements §14.9,
  intrinsic functions §15, data description clauses §13.18, arithmetic §8.8 by default; `--clauses` selects) with a system
  prompt that forbids extensions, input, files (unless the clause is about files) and nondeterminism, and requires every
  result to be DISPLAYed. A program GnuCOBOL refuses goes back to the model once with the diagnostics (`--repairs`, default 1);
  one it still refuses is `GNU_REJECTS`: the model's failure, counted against it and dropped — the failure mode of PB2886 (a
  test program using four constructs the standard does not have) is filtered mechanically. A reply Ollama cut off at the output
  cap (`done_reason` "length") is sent back for a shorter program the same way.
- **The mechanics are the conformance suite's.** Both compilers run through `conformance-suite/adapters/<compiler>.json` by
  the harness's own `Run.operation` (DESIGN-conformance-suite.md §5): the command lines, the crash exit codes, the locale pin
  and the hang guard are the suite's, not a second copy (CLAUDE.md rule 4). On Windows the GnuCOBOL steps cross into WSL
  through the adapter's hook interface (`WslBridge`), as the adapter's own comment prescribes. Both compilers are pinned to
  the 2014 edition (the latest GnuCOBOL 3.2 has a dialect for) in free reference format.
- **Verdict classes** per program: `GNU_REJECTS`, `AGREE`, `WE_REJECT`, `OUTPUT_DIFFERS`, `WE_CRASH`, `WE_HANG`,
  `THEY_FAIL_RUN`, `THEY_HANG`, `RUNNER_ERROR` (an unobserved compiler is never a verdict, plan §11 A12e). Survivors are
  grouped by SIGNATURE (class + WiseOwl's diagnostic codes, or class + clause) so one defect hit forty times is one triage
  row. `results.jsonl` is appended per program (a kill loses nothing); `report.md` is rendered every 25 programs and at the
  end; the model is unloaded when the run ends (the GPU is shared).
- **Modes:** `--model --count|--hours [--jobs]` (the run), `--bake-off m1,m2 --count N` (the share of each model's programs
  GnuCOBOL accepts, and its seconds per program: the winner generates the overnight run), `--report DIR`, `--self-test`
  (24 checks: the seed reader and its folding, the program extraction including odd fence strings and truncated replies,
  every verdict class, the signature, the report, both adapters, the WSL bridge; discovered by `scripts/self_tests.py`). Output goes under `conformance-suite/results/` (git-ignored); the
  script touches no tracked file.

## ⛔ The triage rule — what a survivor is and is not

The ISO spec decides (CLAUDE.md rule 1). GnuCOBOL is a NET: an `OUTPUT_DIFFERS` row says the compilers disagree, not which
is right; a `WE_REJECT` row is ours only where the construct is ISO (GnuCOBOL's default dialect carries extensions, which is
why `-std=cobol2014` is pinned). A confirmed defect becomes its own `kb/Work/` note (search the register first,
[[search-register-before-filing]]); a confirmed program becomes a conformance-suite case whose expected output is derived
from the standard, never copied from either compiler. Nothing the model wrote enters the register, a golden or the suite
without that check (owner's rule 2026-10-03).

## The test runs — 2026-10-20 (the evidence record carries the numbers and the findings)

`docs/rearchitecture/evidence/fleet-optimization/2026-10-20-differential-fuzz.md`. Three smoke runs: the first two lost every
program to the harness (a fence info string the extractor refused; replies cut off at a 3000-token output cap behind
fixed-form indentation), both fixed in the tool with self-test checks; the third compiled 4 of 4 under GnuCOBOL (3 after one
repair round) and surfaced two OUTPUT_DIFFERS signatures (DISPLAY of an implied decimal point after ADD; MOVE of figurative
constants into boolean, alphanumeric and national items) for the morning triage.

**The 40-program test run (12:44–12:59 PDT, three in flight, `qwen3-coder:30b`):** 40 programs in 14 min 23 s (about 22 s
of wall clock each: an 8-hour run writes about 1,300); GnuCOBOL accepted 16 (40 %), 13 of them only after the one repair
round; classes GNU_REJECTS 24 · WE_REJECT 9 · AGREE 4 · OUTPUT_DIFFERS 3; **12 survivors in 5 signatures**, each a lead
for a spec check (the evidence record tables them: a unary `-` before a separator space, COBOLNET2993 × 6; DISPLAY of a
signed item and the `0 ** -1` size condition; a VALUE literal not representable, COBOLNET1625 × 2; DISPLAY of an implied
decimal point; PICTURE 9(34) refused where the standard's limit is 31 digits, a GnuCOBOL extension). Its first attempt died
on a harness bug (fixed: a harness exception inside one program is a RUNNER_ERROR row, never the end of the run), and it
showed the seed walk never left §8.8, so the seed list is now shuffled by default (`--seed`, `--in-order`).
