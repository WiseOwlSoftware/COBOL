# PB935 — OWNER — how disciplined should an accepted extension be?

Source: the `PB511-finisher` report, "New defects" item 5. Filed as a `kind: decision` because the answer
is a posture, not a derivation: the spec does not govern a form it does not print.

## The bare question

**Should the vendor `SET program-pointer TO ENTRY literal` form enforce §13.18.60.4 GR25's restricted
program-pointer content rule, at the cost of breaking the shipped golden
`tests/conformance/2002/pb817_restricted_program_pointer` — or should an accepted extension stay outside
the ISO content rules it was never printed under?**

## The facts the decision rests on

```
$ python scripts/spec/cite.py --check 13.18.60.4 "A restricted program-pointer shall contain only the predefined address NULL"
OK  §13.18.60.4 25)  (General rules)
    25) If program-prototype-name-1 is specified, this data item is a restricted program-pointer. A
        restricted program-pointer shall contain only the predefined address NULL or the address of a
        program with the same signature as that identified by the specified program-prototype-name.
```

* GR25 is a **content** obligation on the ITEM, not a rule about one statement — so an argument that "the
  ENTRY form is not in the standard, therefore GR25 does not reach it" is not obviously right: the item is
  an ISO item whatever loads it.
* The ISO path already enforces it. The `ADDRESS OF PROGRAM` lane got the SR22 determination in wave 41 and
  checks at bind.
* `tests/conformance/2002/pb817_restricted_program_pointer` **depends on the current permissiveness** — so
  the decision has a visible cost either way, and closing it is not free.
* Row `GR-13.18.60.4-25` is CONFORMS / OK ("THE RESTRICTED PROGRAM-POINTER IS DECLARABLE", PB497's
  finding). Whichever way this goes, that row's witnesses should say which lanes were measured.
