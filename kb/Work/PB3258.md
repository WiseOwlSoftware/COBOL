# PB3258 — the implementer dispatch spec never says push

**Symptom:** wave 1091 group F (PB1012, worktree-wf_00451f9d-3d9-2) returned DONE, reviewed CLEAN, gate GREEN, with no
upstream and nothing on origin (`git ls-remote origin refs/heads/worktree-wf_00451f9d-3d9-2` empty at 06:25 PDT
2026-10-16); the orchestrating session pushed it by hand. Sibling 3d9-1 was unpushed at DONE too.

**Measurement:** `grep -i push` finds nothing in `.claude/skills/workstream/templates/dispatch-spec-implementer.md`,
`.claude/skills/workstream/templates/MANDATORY-PRACTICES.md`, `.claude/agents/cobol-implementer.md`, nor in any rendered
spec (w1084, w1089, w1090, w1091); CLAUDE.md rule 7 ("Commit AND push every checkpoint") is the only source, and
`enqueue.py land` pushes at the landing, so the exposure is the DONE-to-landing window (a disk or worktree loss loses
the branch: memory rule never-lose-work).

**Root cause:** the spec template's checkpoint block says commit, not push; no check reads origin at DONE.

**Target:** the template's checkpoint block pushes after every checkpoint commit (`git push -u origin <branch>`),
`check_practices.py` requires that line in every rendered implementer and finisher spec, and the rolling wave's review
step refuses a DONE branch whose tip is not on origin (`git ls-remote`), a seconds-cost backstop (prevent-known-failures).
