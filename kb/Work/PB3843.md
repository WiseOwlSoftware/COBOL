# PB3843 — Parse recovery draws extra, false diagnostics after the true one

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs#Recover`, `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs#GuessCobolIntent`, `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs#Report`, `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs#EndsAConstructEarly`, `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs#ResynchronizationSet`, `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs#ConsumeUntil`, `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs#ScopeTerminatorWords`

Repro (group B): `IF W-N = 0 MOVE 1 TO W-N END-ADD MOVE 2 TO W-N END-IF.` draws the true COBOL0306 at END-ADD, then a false "END-IF appears without a matching IF": the recovery closed the IF. Also seen in `PBGF05`, `PBGF15` and golden `pb331-read-key-before-lock` (at END-READ). Group C: after a COBOL2269 unowned-phrase report the same recovery adds a stray COBOL0306 or COBOL0001. Pre-existing on main (group B's round-1 lead 2); neither branch fixed it.

Both look like the recovery resuming at a state that has already consumed or closed the construct the first report was about. A user fixing the true diagnostic is sent after a second one that disappears with it, and a golden pinning the cascade pins the noise (the implementer confirms the shared cause before fixing; if the two differ, split the note).

Register class: a message that names the wrong fault is filed `process_only: true` today because the register has no harm class for it (kb/Work PB3836); the flag becomes the new class when PB3836 lands.

## Witness, 2026-10-27 (fuzz night 6)

fz06606 (`conformance-suite/results/fuzz-20261026-225310/programs/fz06606.cob`, slice C3): after the true COBOL2269 the
compiler emits a second COBOL2269 at NOT and a false COBOL0901 ("'END-ACCEPT' is a reserved word ... cannot be used as a
user-defined word"). A new code in the same recovery cascade; the site is `CobolErrorStrategy.Recover`.

## Acceptance

- A stray terminator, and an unowned phrase, each draw exactly one diagnostic (the true one) on the repros above and on PBGF05, PBGF15, pb331-read-key-before-lock.
- A drift test sweeps every `END-*` terminator against an open and a closed enclosing statement.
- Fix the root cause, never simply making the diagnostic pass; be consistent with ourselves barring an explicit requirement differently.

## Landed (wave 20261764 group C)

**Re-probe on the build (all reproduced):** `IF W-N = 0 MOVE 1 TO W-N END-ADD MOVE 2 TO W-N END-IF.` drew COBOL0306 at END-ADD and a false COBOL0306 at END-IF; PBGF05 (a second ELSE), PBGF15 and `STRING … ON OVERFLOW … ON OVERFLOW … END-STRING` a true COBOL2269 and a false COBOL0306 at END-STRING; `pb331-read-key-before-lock` the same at END-READ; fz06606 a true COBOL2269, a second at NOT, and COBOL0901 at END-ACCEPT; PBGF09 COBOL2073 and a false COBOL0306 at END-EVALUATE. One mechanism, so no split.

**Root.** An explicit scope terminator is optional, so every statement ends where its next token is not its own, and the refusal is found at the sentence's period or its `statement+` loop, AFTER the enclosing IF / STRING / ACCEPT / EVALUATE has closed. ANTLR's recovery then resumed at the first token a statement could take and parsed the rest of the sentence as new statements of a sentence the construct no longer belonged to, so the construct's own END-x (and the NOT phrase of a paired phrase) met nothing. `CobolErrorStrategy.Report` now marks a fault whose winning hint is COBOL2269, COBOL2073 or COBOL0306 (`EndsAConstructEarly`), and `ConsumeUntil` (through `ResynchronizationSet`; both `Sync`'s loop recovery and `Recover` reach it) stops that fault's resynchronization only at the sentence's separator period.

**Gate.** Whole Conformance (19363, the four reds were the re-pinned pb331-read-two-from-one-lock-bracket, whose RETRY-bearing source drew COBOL0001 only as the cascade; the source now writes ADVANCING ON LOCK with IGNORING LOCK and is refused with COBOL2269), Unit and Characterization run green on the change; `ParseRecoveryTailTests` sweeps every terminator the grammar spells (read from the ATN map the hint uses) against an open and a closed enclosing statement.

**Not fixed here (leads).** (1) `reservedGatedWord` holds END-ACCEPT, END-DISPLAY, END-RECEIVE and END-SEND, so a stray one parses as a data-name and the §8.9 funnel answers COBOL0901 where hint 13 is never asked; likewise a misplaced RETRY after ADVANCING ON LOCK reads as a user word (COBOL0901) where the READ statement's refusal (COBOL2269) would name the fault. (2) PBGF04 / PBGF07 / PBGF10 (`IF DISPLAY "X" END-IF`) draw COBOL0001 and then COBOL2072 (the empty block ANTLR's single-token deletion left), and PBGF32 two COBOL0001: a different recovery (single-token deletion inside a statement's header), not the early closure.
