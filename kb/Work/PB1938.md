# PB1938 — LANDED (wave 1056 group H)

Filed by the train-1006 lander from wave 1006 group D's report (`w1006d-PB1144-report.md`, "New defects", item 2).

## Defect

PB1144 (landed in train 1006) binds §14.6.9.2's element moves ("Correspondingly numbered elements are moved according
to the rules of the MOVE statement") beside the group move, reaching each table from its group's resolved place with
`MoveBinder.TableCursor`. A level-66 THROUGH alias is a group item (§13.18.45.4 GR2), but its atoms are its span's
leaves and the tables are not subordinates of the alias item, so `TableCursor` returns null. The element move then
carries `Unsupported` and `MoveEmitter.EmitElementMoves` renders a loud run-time stop instead of moving the elements.
It only matters when the corresponding elementary elements differ in description (identical or group elements take
the image transfer and need no element move).

**Fix shape.** Walk the alias's span to the table (the renamed record's place plus the table's path), or give the
cursor a RENAMES arm. Golden: a variable-length group MOVE whose sender is a THROUGH alias over a table of `PIC 9(4)`
moved to a corresponding `PIC 9(2)V99` table.

**Site.** `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/MoveBinder.cs#TableCursor` (and `ElementMove`'s
`Unsupported` arm).

## Landed

Re-probed on the wave-1056 build: `MOVE SALIAS TO DST` (alias over `ST PIC 9(4) OCCURS 2`, receiver `D1 PIC 99V99 OCCURS DYNAMIC`) stopped at run time with the loud element-move message. Root cause: `MoveBinder.TableCursor` walked the table up its parent chain to the group item, and a level-66 THROUGH alias is a group item with no subordinates (13.18.45.4 GR2), so the walk found nothing. Fix, one reach for both group kinds: `VariableLengthCompatibility.CorrespondingTables` now returns `TableSite(Table, Part)` pairs, where `Part` is the `RenamesSpanPart` the alias atom was laid from (the same span `AliasAtoms` already read for compatibility), and `MoveBinder.ReachElement` reaches an alias table as the RECORD table at the outer occurrences the part names (`RenamesSpanPart.SubscriptsFor(Position)`, now taking a typed position) through `ReferenceResolver.ResolveItemAt`, and every other table down the cursor as before. Both directions and a table leaf under an OCCURS group inside the range are pinned by `tests/conformance/2014/pb1938_through_alias_vlg_element_moves`; the Table 16 refusal of the element pair by `tests/conformance/negative/pb1938-through-alias-element-move-illegal`. Sibling sweep: the no-THROUGH alias forwards to the renamed item (its `Place.Item` is that item), so its cursor walk already worked; INITIALIZE of a THROUGH alias is refused by 14.9.20.3 SR5; no other consumer of `CorrespondingTables` exists.
