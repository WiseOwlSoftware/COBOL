# PB4159 — the wildcard early-return comment's macOS claim is false

**Sites:** `src/WiseOwl.Cobol.Frontend/Pipeline/CompilationInputs.cs:103` (`CompilationInputs.LocateFile`).

Review lead R1-3 (info, not blocking at round 1) of the PB1680 branch (PB1680 is held by an in-flight group, so this is a new note
that names it). `LocateFile` returns the probe path unchanged when the name holds `*` or `?`, with the comment "A wildcard in the
name would be a pattern, not a name; no file system that matches case-insensitively allows one." The default macOS (APFS and HFS+)
volume is case-insensitive and does allow both characters in a name, and the PB1680 test file itself names macOS as a
case-insensitive host. The early return is still the right guard (an `EnumerateFiles` pattern would otherwise match other files);
only the justification is wrong.

Fix: reword the comment to say what the guard is for (the name would be read as an enumeration pattern, so the listing cannot answer
for it) without a claim about which file systems allow the characters. If a macOS case-insensitive volume holds a copybook whose
name has `*` or `?`, the early return also means its spelling is not corrected; say so, or escape the name for the listing.
