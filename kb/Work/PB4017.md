# PB4017 — the fuzz ledger's main-tree verdict has no end-to-end self-test

**Sites:** `scripts/test_fuzz_history.py`, `scripts/fuzz_history.py#main_verdict`, `scripts/fuzz_history.py#MAIN_EXTRACT`

**Gap.** PB4010 made `fuzz_history.py status` judge main by main's own committed tree: `main_verdict` extracts origin/main's
`scripts/`, `kb/Work/`, history and FUZZ-LEDGER.md with `git archive` and runs that copy's `fuzz_history.py verify`, reading its
last stdout line as JSON. The self-test covers `extract_main` (committed content only), `verify`'s pieces and every
`sync_status` state with a stubbed judge, but nothing runs the subprocess, the JSON parse or the error mapping. Its
"the extract holds everything the render reads" case compares `MAIN_EXTRACT` with a hand-written copy of its own entries, so a
future render input outside the four (a file `verify` imports or reads beside `scripts/` and `kb/Work/`) keeps the test GREEN
while `status` prints "could not be rendered" or a false REGENERATE OWED. The round-7 reviewer ran it by hand: Windows, 6 s,
`same=true`; WSL Python 3.15, `same=true`.

**Fix.** An end-to-end case: a `ScratchRepo` (PB3584) whose commit holds a copy of the real `scripts/` tree, a small `kb/Work/`,
a history and the FUZZ-LEDGER.md that tree renders; `refs/remotes/origin/main` at it; then `main_verdict(repo)` returns
`same: true`, and after a commit that changes a fuzz note's status without re-rendering it returns `same: false` with the new
version, and a broken `verify` returns the `error` arm. That test, not a list, is what keeps `MAIN_EXTRACT` complete.
