# PB3960 — a figurative ZERO in a reference-modification position escapes the compile-time range screen: T(ZERO:2) over PIC X(4) compiles and aborts at run time, T(0:2) is refused COBOL2670

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/ReferenceResolver.cs#BindPosition` (the direct walk's `Primary` reads a `ZERO_ARITH` primary as `PositionConstant(0)`, its `ALL` edition edge queued as a `PendingScreen`), `src/WiseOwl.Cobol.Compiler/Binding/ReferenceResolver.cs#LiteralRefModRangeViolation`, `src/WiseOwl.Cobol.Compiler/Binding/ReferenceResolver.cs#ScreenRefModLiterals`, `src/WiseOwl.Cobol.Compiler/Binding/FigurativeAssociation.cs#GateAllZeroAsArithmeticOperand`, `src/WiseOwl.Cobol.Compiler/Binding/Procedure/ExpressionBinder.cs#ZeroOperand`, `src/WiseOwl.Cobol.Compiler/Binding/Model/Position.cs` (doc), `docs/CONFORMANCE.md` (DOC-A.1-69)

`DISPLAY T(ZERO:2)` over `PIC X(4)` compiles and aborts at run time with EC-BOUND-REF-MOD, while `T(0:2)` is refused
COBOL2670 at compile time (rule: §8.4.3.3.4 5) b), the R60 screen). `ReferenceResolver.LiteralRefModRangeViolation`'s
caller passes start / length as null for anything but an integer literal, so the `ZERO_ARITH` primary is never judged. Repro
`E:/COBOL-coord/scratch/w20261720b/p/ZY.cob`. Harm: under-reject (a compile-time error left to run time). Separate root from
PB3961 (the message text).

## Acceptance
- The screen judges a figurative ZERO as the value 0 at the start and the length position (`ZERO` and `ALL ZERO` forms);
  golden refusal pair `T(ZERO:2)` and `T(2:ZERO)`; sweep the siblings (subscripts, the other literal-only screens).

## Landed

Root cause: the resolver's direct position walk (`BindPosition`) had no arm for the `ZERO_ARITH` primary, so a figurative ZERO beside the ref-mod colon routed to the D18 materializer and became a computed temporary read; `LiteralPosition` saw no literal and the R60 screen never judged it. The walk now reads the primary as the integer 0 (ISO 8.8.1.1, 8.3.3.6.4 GR4); `ALL ZERO` keeps its 8.3.3.6.3 SR1 a) edition edge through the one gate `FigurativeAssociation.GateAllZeroAsArithmeticOperand`, queued with the walk's other screens so an abandoned walk cannot report twice. Goldens: `8.4.3.3-Reference-modification/pb3960_figurative_zero_refmod_position` (positive) and `pb3960-refmod-zero-start`, `pb3960-refmod-zero-length`, `pb3960-refmod-all-zero-start` (refusals).
