# PB189

Observed and recorded during the PB164 variable-length-group DISPLAY wave (2026-08-30, DEVLOG 1398) as
"PB164-family residue", carried in that note's prose until this landing; **promoted to its own note here**
because a defect living inside a paragraph is invisible to `work.py next` — CLAUDE.md rule 8's own worked
example.

**THE SHAPE.** The VLG wave split `DataItem.IsImageCapable` into an `ElementImageCapable` half precisely so a
dynamic-capacity table's ELEMENT struct carries `AsImage()`/`CurrentImage()` per occurrence. It does. But the
DISPLAY sender arm still asks its question of the TABLE item — "does this item have a variable-length axis?" —
and a subscripted reference `DISPLAY T(3)` reaches it carrying the table's own item, so the operand is staged
loud even though the element it names has an image sitting right there.

**WHY IT IS LEGAL SOURCE.** §14.9.11.4 GR4 transfers "the data item being transferred", and the data item here
is the ELEMENT, not the table. §8.5.1.12.1 (`--check` OK) defines a variable-length group as "a group item whose
data description has at least one dynamic-length elementary item or dynamic-capacity table as a SUBORDINATE
item. All other group items are referred to as fixed-length groups" — the dynamic axis belongs to the TABLE, and
one occurrence of it has no such subordinate, so the element is a FIXED-length group and every ordinary group
rule applies to it. No syntax rule bars the operand, and the compiler already knows how to render it.

**FIX SHAPE.** The arm must ask about the REFERENCED operand, not about the declaring item — the same
discriminator lesson the VLG wave paid for once already (its CRITICAL was `Occurs is null` being true for a
Format-4 dynamic table). Route the subscripted place through the element struct's own image the way every other
element-granular path does, and pin it with a golden that DISPLAYs `T(n)` at two different current capacities
alongside the whole-table DISPLAY, so the element and the composed table image are observed to agree. Related:
[[PB176]] (the GroupImage guard for the ODO-plus-dynamic sender) and the GR-14.9.11.4-4 inventory row, whose
residue list now names this note.
