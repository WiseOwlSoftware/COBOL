# PB3576 - the lock table is keyed by path, not by physical file

## Lead (PB3533 report, new defect 1, and review lead R1-1, low)

PB3533 gave the kept state and the `StoreTable` a physical-file identity (`HostFile.IdentityOf` / `IdentityAt`, statx dev+ino on
Linux, FILE_ID_INFO on Windows). `PhysicalFileTable` still holds ONE `State` per path (`_byHost`, a dictionary keyed by
`HostFile.PhysicalFileComparer`, kb/Work PB2748), so its Table 19 file locks and its record locks follow the path, not the file.

### Repro (Linux; harm: a wrong refusal, '61' or '51', never wrong records)

Connector F holds file P open and locks record 7. P is replaced outside the run unit (removed and recreated, or renamed away
and recreated). Connector G of the same run unit opens P (the new file) and READs WITH LOCK record 7. `PhysicalFileTable`
hands G the path's `State`, so G meets F's lock on a record of the OLD file and gets the refusal.

### Same mechanism as review lead R1-1

R1-1 (low): a kept file that is RENAMED away outside the run unit has its kept state ENDED, not retired
(`KeyedConnector.cs` around line 737, `EndWhatWasKeptOfAnotherFile`), so the next COMMIT answers success while the program's
changes to the still-existing physical file are abandoned and rolled back by the next writable OPEN. PB3494 retires the same
state when an ASSIGN USING moves the connector to another path, so COMMIT reaches it. PB3533 chose to end it because
`PhysicalFileTable` keeps one file per path and would hold the old file's record and file locks against the new file at the
path (the PB3533 report's "Rejected" line). That determination was forced by this table staying path-keyed, not by the
standard (§14.9.27.4 25 is silent on a file replaced outside the run unit). One root, so one note: key the table by identity
and the retire route opens up.

## Fix shape (for the implementer)

Key `PhysicalFileTable` (and the Table 19 arbitration in `FileRegistry.OpenShared`) by physical-file identity, taken at
arbitration time, before the handle exists (`HostFile.IdentityAt`), the way `StoreTable` already is. Keep the path as the
lookup for a file that is absent. Then revisit PB3533's end-the-kept-state determination for a file renamed away: retire the
state to the registry as PB3494 does, so COMMIT reaches the file it changed. Update `docs/rearchitecture/DESIGN-runtime-library.md`
2.2.1.7 and 2.2.1.10 with it. Witnesses (rule I11): the repro above on Linux; the identity itself on both hosts.

**Sites:** `src/Cobol.Net.Runtime/IO/Sharing/PhysicalFileTable.cs` (line 102, `_byHost`), `src/Cobol.Net.Runtime/IO/FileRegistry.cs`
(`OpenShared`, `ReleaseKeptOf`), `src/Cobol.Net.Runtime/IO/KeyedConnector.cs` (line 737 area), `src/Cobol.Net.Runtime/IO/KeptFile.cs`.

## Landed (wave 20261024, group A3)

**Re-probe (Linux, the unfixed runtime).** See the DEVLOG entry: the new witnesses fail on the unit leg under WSL with the path-only behaviour restored
(a second connector of the run unit opening the replaced path met the old file's Table 19 entry and record lock; a DELETE FILE of the new file was refused '62'
by a connector open on the old one), and pass with the fix. On Windows the kept handle's share mode admits no delete, so the host refuses the replacement.

**Fix (DESIGN-runtime-library.md 2.2.1.7 and 2.2.1.10).**
- `PhysicalFileTable` is keyed by the physical file. `State.Identity` (the host's `PhysicalFileIdentity`, learned from a connector's open handle by
  `PhysicalFileTable.Learn`); `For(path, HostFile.IdentityAt(path))`, asked at the arbitration of every OPEN before the handle exists, finds the state BY the
  identity, whatever the file is named; the path finds a state only for an absent file or where the host cannot tell. A connector's record statements and
  `UNLOCK` use the state its last OPEN arbitrated (`FileConnector.Physical`, `FileRegistry.PhysicalOf`), never a path lookup; the run unit's record-lock
  ceiling counts every state.
- A kept file the path no longer names RETIRES instead of ending (review lead R1-1): `FileConnector.RetireWhatWasKeptOfAnotherFile(presence)` (Present and Absent)
  → `KeyedConnector.RetireKept` → its `KeptSink` (`FileRegistry._retired`), the one hand-over `FileRegistry.Retire` (the ASSIGN USING case) uses too. The
  renamed file's change is COMMITted, not rolled back by the next writable OPEN. The two `ReleaseKept()` calls of the absent OPTIONAL arms are gone: the hook
  has handed the state over before the arms run, so a refused handle leaves it whole.
- Sibling swept in the same file (I9): `FileRegistry.OpenByAnotherConnector` (DELETE FILE's '62') compared connectors' paths; it asks the file's state now.
- Known determination, recorded in 2.2.1.10: on a host whose column locks are published by path (the sidecar host, macOS) the retired state's column file stays
  published until the COMMIT and the OPEN of the file at the path is arbitrated against it as against any holder.

**Witnesses.** `PhysicalFileTableIdentityTests` (every host: the file decides, never its name; an absent path's state becomes the file's; a vanished file leaves its
path; the run-unit ceiling over every state); `CommitRollbackRuntimeTests`: `Two_connectors_on_a_path_whose_file_was_replaced_meet_none_of_each_others_locks`,
`A_delete_file_of_a_path_whose_file_was_replaced_is_refused_by_no_connector_open_on_the_old_file`, `A_retired_kept_states_unpublished_record_locks_...`, and the
PB3533 witnesses re-stated for the retire (`..._retires_what_the_close_kept`, `A_refused_reopen_of_an_optional_file_that_vanished_leaves_the_retired_kept_state_as_the_close_left_it`).

**For the next implementer.** `PhysicalFileTable#For(path, identity)` finds a file's state by identity (path only for an absent file); `#Learn` is its one writer of
`State.Identity`. A statement uses `FileRegistry#PhysicalOf(connector)` (its last OPEN's state), never a path lookup; a path question about a PHYSICAL FILE
(`OpenByAnotherConnector`) asks the state. `KeyedConnector#RetireKept` → `KeptSink` is the one hand-over of a kept state without ending it (`FileRegistry#Retire`,
`FileConnector#RetireWhatWasKeptOfAnotherFile`). Traps: the replaced-file witnesses run only where the host unlinks under an open handle (Linux), so run them
through `bash scripts/linux-gate.sh --legs unit --nice` (about 3 minutes; it fails on "No space left on device" when other fleets fill the WSL disk, re-run it); a
state's identity is learned from the handle AFTER a successful OPEN, so an OPEN OUTPUT of an absent path arbitrates on the identity-less state of the path.
