# PB1352 — OPEN

Only a main-text REPLACE vs `>>DEFINE/>>IF` is immune, and only because those lines were already consumed.

## Finding — compiler-directives (wrong-answer)

replacing-rewrites-directive-lines: the one COPY REPLACING / REPLACE text-word pass (CopyProcessor.ApplyReplacements over TokenizeTextWords) treats a '>>' compiler-directive line as ordinary text words. TokenizeTextWords skips '*>' comment lines but not directive lines, so COPY REPLACING (applied to the copybook text in ResolveOneCopy before the CC driver renders the copybook's own >>DEFINE/>>IF/>>EVALUATE) and REPLACE (Step 3, applied before the post-COPY TURN/PUSH/POP/PROPAGATE/REF-MOD-ZERO-LENGTH/FLAG stages read their lines) rewrite the directives. Only a main-text REPLACE vs >>DEFINE/>>IF is immune, and only because those lines were already consumed. Sibling in the same pass: §7.2.4.4 GR8 c) 5 ('Each occurrence of a compiler directive line is treated as a single space', cite.py --check 7.2.4.4 OK) for matching is equally unimplemented.

**Rows:** GR-7.3.4-1, GR-7.3.4-2

**Repro:**

```
Copybook cb2.cpy: '       >>DEFINE VV AS 1' / '       >>IF VV = 1' / '           DISPLAY "CB2 VV=1".' / '       >>ELSE' / '           DISPLAY "CB2 ELSE".' / '       >>END-IF'. Program: PROCEDURE DIVISION. 'COPY cb2 REPLACING ==AS 1== BY ==AS 3==.' STOP RUN. (E:\Temp\claude\E--CobolSharp\a700c052-f9e4-4942-84ff-a13c7505d6ec\scratchpad\adj-d2\out\probe\cd\p3.cob). Also p1.cob: 'REPLACE ==CHECKING== BY ==CHEKING==.' then '>>TURN EC-ALL CHECKING OFF'; p2.cob: 'COPY cb1 REPLACING ==CHECKING== BY ==CHEKING==.' over a copybook holding '>>TURN EC-ALL CHECKING OFF'.
```

**Expected from the spec:** §7.3.4 GR1 'A compiler directive line is not affected by the replacing action of a COPY statement or a REPLACE statement.' p3 must print 'CB2 VV=1' (the >>DEFINE and >>IF lines are untouched, VV = 1); p1 and p2 must compile clean with EC checking OFF.

**Observed:** p3 prints 'CB2 ELSE' with no diagnostic (the REPLACING rewrote '>>DEFINE VV AS 1' to 'AS 3'). p1 and p2 each fail with COBOLNET0719 x2 ('file-name CHEKING' / 'file-name OFF') and COBOLNET0718 (malformed >>TURN) on legal source. p4 (main-text REPLACE ==AS 1== BY ==AS 3== over >>DEFINE/>>IF) prints 'P4 VV=1' only because the CC driver ran first.

**Code site:** src/Cobol.Net.Frontend/Preprocessor/CopyProcessor.cs#TokenizeTextWords (the '*>' skip has no '>>' sibling); CopyProcessor.cs#ApplyReplacements; CopyProcessor.cs#ResolveOneCopy (REPLACING applied before the copybook's directives are rendered)

## Finding — if-directive (wrong-answer)

COPY REPLACING is applied to the whole copybook text — compiler directive lines included — before the conditional-compilation driver processes the copybook, so a REPLACING operand that matches a compilation-variable name rewrites the >>IF (or nested >>IF) condition and the wrong branch is compiled.

**Rows:** GR-7.3.16.4-1

**Repro:**

```
cpy/IFCB3.cpy: '>>IF V = 1' / 'DISPLAY "V-TRUE"' / '>>ELSE' / 'DISPLAY "V-FALSE"' / '>>END-IF'. Main (p15): PROCEDURE DIVISION. / >>DEFINE V AS 1 / >>DEFINE W AS 2 / COPY IFCB3 REPLACING ==V== BY ==W==. / STOP RUN. Run with --copy cpy --run. Nested variant p21 (IFCB4: '>>IF U = 1' wrapping '>>IF V = 1 … >>ELSE … >>END-IF') gives NEST-FALSE; with BY ==Q== (p14) a spurious COBOLNET1619 'Q is not a previously-defined compilation variable'.
```

**Expected from the spec:** §7.3.16.4 GR1: only 'text words in text-1 or text-2 that do not form a compiler directive line are subject to the matching and replacing rules of the COPY statement'; §7.3.4 GR1: 'A compiler directive line is not affected by the replacing action of a COPY statement or a REPLACE statement.' The >>IF V = 1 line keeps V, V = 1 is TRUE, §7.3.16.4 GR2 includes text-1: output V-TRUE (p21: NEST-TRUE; p14: no diagnostic, V-TRUE).

**Observed:** p15 prints V-FALSE; p21 prints NEST-FALSE; p14 fails with COBOLNET1619. CopyProcessor.ExpandCopiesOneLevel calls ResolveOneCopy (which returns the copybook text with REPLACING already applied) and only then expandCopybook(one.Mapped!, …) = ConditionalCompilationProcessor.Run.RenderCopybook. The REPLACE-statement path is not affected (ApplyReplaceStatements runs after CC has consumed the IF/ELSE/END-IF lines), but directive lines LEFT for downstream stages (TURN, PROPAGATE, FLAG-xx…) are still in the text when REPLACE runs — sweep §7.3.4 GR1 for them.

**Code site:** src/Cobol.Net.Frontend/Preprocessor/CopyProcessor.cs#ResolveOneCopy / #ExpandCopiesOneLevel (REPLACING before CC); src/Cobol.Net.Frontend/Preprocessor/ConditionalCompilationProcessor.cs#ProcessWithCopyMapped

**Repro:**

**Expected from the spec:** 8) c) 5: the directive line is a single space, so SHOW-IT NOW matches and the program displays 'W1 '.

**Observed:** out/probe/replace-p2/dir.cob and dir5.cob: COBOL0001 'cannot parse construct near NOW'; control dir2.cob without the line prints W1; >>DEFINE and >>SOURCE lines (consumed before Step 3) do not break the match.

**Code site:** src/Cobol.Net.Frontend/Preprocessor/CopyProcessor.cs#TokenizeTextWords (no '>>' directive-line arm)

## What the fixer owes (and the sibling sweep)

Make a compiler directive line a first-class element of the text-word stream (one space for matching, never a replacement target, never scanned for COPY) — the directive-line recognizer already exists (`CompilerDirectiveLine.TryParse`); `TokenizeTextWords`, `ApplyReplacements` and `FindCopyKeyword` must consult it. Sweep every stage that reads `>>` lines AFTER a replacing pass. Goldens: COPY REPLACING ==X== BY ==Y== over a copybook containing `>>IF X = 1` (condition unchanged); REPLACE spanning a `>>TURN` line; `>>PAGE COPY FOO.` inside a REPLACING copybook compiles clean.
