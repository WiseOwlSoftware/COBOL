# PB1477 — OPEN

## The rule (every citation re-run by the registrar through `cite.py --check`)

> The rules for comparing a conditional variable with a condition-name value are the same as those specified for relation conditions

`python scripts/spec/cite.py --check 8.8.4.5.3 "…"` → `OK  §8.8.4.5.3 2)  (General rules)`

## Refuter evidence — row `GR-8.8.4.5.3-2` (PARTIAL)

PARTIAL — The comparison is NOT the relation-condition comparison for a conditional variable that is a group containing an OCCURS DEPENDING ON table (legal: SR1 of 13.18.63.3 excludes only strongly-typed and variable-length groups, and 8.5.1.12 defines variable-length group as one with a dynamic-length item or dynamic-capacity table, not ODO). StringMembershipValue sizes a figurative (ALL literal, ZEROS, SPACES...) to parent.ImageWidth = the MAXIMUM extent, while the operand read is the CURRENT extent; the relation IF GV = ALL "X" sizes the figurative to the current operand and answers TRUE where the 88 answers FALSE. Every other probed shape (PIC A, AE, NE, P-scaling, DECIMAL-POINT COMMA, 31-digit, FLOAT-LONG, boolean pad, PCS ALSO range) agrees with the relation rules.

**Code site.** src/Cobol.Net.Compiler/CodeGen/Emit/ConditionRenderer.cs#RenderCondition88; src/Cobol.Net.Compiler/CodeGen/Emit/ConditionRenderer.cs#RenderMembershipTest; src/Cobol.Net.Compiler/CodeGen/Emit/ConditionRenderer.cs#StringMembershipValue; src/Cobol.Net.Compiler/Binding/ValueSubject.cs

## What the fixer owes

RenderCondition88 / RenderMembershipTest must size a figurative to the operand's CURRENT extent exactly as the relation renderer does — better, route the 88 value comparison through the relation comparison itself so the two can never diverge again. Golden: ODO group, IF GV = ALL "X" and the 88 agree at a partial count.
