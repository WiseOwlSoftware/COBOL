# PB3964 — report-section 2002 introductions are not gated at --std 85: FILLER in a report group, '+' / '-' as the PLUS / MINUS symbols in LINE / COLUMN, and SOURCE with an arithmetic expression, a function or ROUNDED all compile clean

**Sites:** `src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs` (`VisitReportGroupEntry`, `VisitReportRelativeSign`, `VisitReportSourceClause`), `tests/version-matrix/constructs.json` (rows `report-filler-2002`, `report-plus-symbol-2002`, `report-source-expression-2002`, `report-source-rounded-2002`), `docs/VERSION_CHANGE_REFERENCE.md` (row 7.45), `docs/REPORT_WRITER_DESIGN.md` (section 0), `conformance-suite/wiseowl/diagnostics.json`. The note named `DataBinder.Reports.cs` (`BindReportEntry`): not used, because the gate is a recognition arm (the report-clause precedent: PRESENT WHEN, VARYING, the multiple COLUMN / LINE / SOURCE forms), which sees every written form once and never a replay.

Annex F.2 item 115 (ISO/IEC 1989:2002) introductions with no construct row, each compiling clean at `--std 85`
(probes s1, s2, s3 in PB3683's scratch probe directory): FILLER in the report section; `+` / `-` as the PLUS / MINUS symbols
in LINE and COLUMN; SOURCE with an arithmetic expression, a function or ROUNDED. Shared root: the report-section 2002
introductions are not gated. Flags per the report: MINOR, under_rejects, silent.

## Acceptance
- A construct row per introduction (`new-construct` rules: grammar fragment, version predicate, constructs.json row,
  edition-gate sweep) quoting Annex F.2 item 115; a refusal golden at 85 and an acceptance golden at 2002 for each.

## Landed (wave 20261732, group A) - four construct rows, one recognition arm each

**Re-probe** (`E:/COBOL-coord/scratch/w20261732a/s1-filler.cob`, `s2-plus-symbol.cob`, `s3-source-expr.cob`, base `6974abd43`):
FILLER in a report group, `LINE + 1` and `SOURCE WN + 1` each exited 0 at `--std 85`. Now each is COBOL0900 at 85 and compiles at 2002.

**Spec.** The edge is QUOTED from ISO/IEC 1989:2002 Annex F.2 (post-ballot text v200112.txt, the archived P2 draft, in
`E:/COBOL-coord/research/pb296-dl/fcd/`): item 53 "FILLER. FILLER is allowed in the report section."; item 115's bullets
"PLUS or MINUS can be the symbol '+' or '-', respectively" and "SOURCE allows arithmetic expressions and functions and a
ROUNDED phrase". The 2023 rules: 13.18.20.3 SR3 + 13.18.20.4 GR1, 13.18.35.3 SR1 / 13.18.37.3 SR2 / 13.18.14.3 SR2 ("PLUS and +
are synonyms"), 13.18.53.2 + 13.18.53.3 SR3 + 13.18.53.4 GR2 (all `cite.py --check` OK).

**Fix.** Rows `report-filler-2002`, `report-plus-symbol-2002`, `report-source-expression-2002`, `report-source-rounded-2002`
(constructs.json + `gen-constructs.ps1`, VCR row 7.45), asked by three parse arms in `VersionConformancePass`:
`VisitReportGroupEntry` (the entry name is the word FILLER; a FILLER DATA description entry is COBOL-85 and is another rule),
`VisitReportRelativeSign` (the ONE production every relative operand shares, PB951, so LINE and NEXT GROUP are one gate; a
COLUMN operand is skipped, its relative form being gated whole by `report-multi-column-2002`) and `VisitReportSourceClause`
(an operand that `SoleOperand.DataRef` does not reduce to one bare data reference is arithmetic-expression-1, a parenthesized
identifier included; `roundedPhrase`). The '-' of item 115's "PLUS or MINUS" names nothing: no 2023 relative format has a MINUS
operand, and the grammar refuses `LINE - 1` at every edition.

**Goldens.** Three existing goldens that were filed `accept: [85]` used these 2002 forms and had been the silent proof of the
hole; they now carry `accept: [2002, 2014, 2023]` and serve as the 2002 positives
(`pb1226_report_filler_entry_name`, `pb957_next_group_forms`, `pb852_report_source_expression`); negatives
`pb3964-report-filler-85`, `pb3964-report-plus-symbol-85`, `pb3964-report-source-expression-85`,
`pb3964-report-source-rounded-85` (`diagnostics.json`, COBOL0900 at 85). Sweep: every conformance-suite program and every NIST
program with a REPORT SECTION was compiled at each accepted edition (`sweep.py`, `check-batch`): exactly those three tripped.

**Leads (same family, not this mechanism).** Item 115's other bullets still compile clean at `--std 85` (probe
`E:/COBOL-coord/scratch/w20261732a/probe115.py`): `CODE IS identifier` in an RD, `OR PAGE` on a CONTROL HEADING, an omitted control
data-name (`TYPE CF` with no operand), the optional `ON` / `FOR` words, `PAGE LIMIT ... n COLUMNS`, and the SUM clause's
arithmetic-expression operand and ROUNDED phrase (the SUM clause "has many changes", item 115, without a list).

## Landing (for the next implementer)

- `src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs#VisitReportGroupEntry`, `#VisitReportRelativeSign`,
  `#VisitReportSourceClause`: the report-section 2002 gates are recognition arms (once per written form), not binder screens. A new
  report-clause introduction is a constructs.json row + `pwsh scripts/gen-constructs.ps1` + `pwsh scripts/gen-vcr.ps1` + a VCR
  Table 7 row with `<!-- gate:ID -->` markers + one arm here.
- Reuse `SoleOperand.DataRef` for "is this operand one bare identifier"; reuse the one `reportRelativeSign` production for any
  relative operand. Trap: three goldens were filed `accept: [85]` while using 2002 forms; sweep REPORT SECTION programs at every
  accepted edition (`cobol check-batch`) before trusting a new gate.
- Residue (not gated; probes in `E:/COBOL-coord/scratch/w20261732a/probe115.py`): CODE IS identifier, OR PAGE, an omitted control
  name, optional ON / FOR, PAGE LIMIT ... COLUMNS, SUM with an expression or ROUNDED (Annex F.2 item 115).
