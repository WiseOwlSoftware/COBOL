# PB4228 — reflection sweeps over an assembly are invisible to leg-1 selection

**Sites:** `scripts/spec/drift_rules.py` (`scopes_of`, `index`, `in_scope`), `tests/_shared/TrackedTree.cs` (`TreeScope`), `tests/WiseOwl.Cobol.Tests.Unit/RunUnitStateDriftTests.cs` (`NoStaticMutableCollection_OutsideTheDocumentedProcessStores`, `NoWritableStatic_OutsideTheDocumentedProcessStores`). The planner's tier 0d already plans whatever the index lists, and the new guard is modelled on `TrackedTreeScopeDriftTests`, which itself does not change.

## What happens

Under batched gating (PB2515) the gate runs leg 1 only, and leg 1 holds a test only when something attributes it to the
change: the change's own tests (0a), the cheap `Sweep` classes (0c), the drift tests the drift-rule index lists for a
changed file (0d), or the impact map's tiers. A drift test that enumerates every type or field of an assembly by
reflection (`typeof(RunUnit).Assembly.GetTypes()` and the like) governs every source file of that assembly. Neither
attribution sees that:

- the drift-rule index knows only the paths a test names and the `TreeScope`s it declares, and a reflection sweep
  reads no file;
- the coverage impact map records the code a test EXECUTES, and reading metadata executes none of the scanned types.

So a change that adds a static field, a type or a member to an assembly does not put that assembly's reflection
sweeps in leg 1. The gate reads GREEN, and CI's whole-population run is the first to run them. That is the CI
invariant (owner 2026-10-04) broken by design, not by chance.

## The recorded case (2026-10-31)

PR #894 (`worktree-wf_94e81f77-f38-7`, PB107) added `CldrTailoringBuilder.s_baseRoots`, a `static readonly
ConditionalWeakTable`, to `WiseOwl.Cobol.Runtime`. Merge groups 41228707145 (18:17Z) and 41230044770 (18:34Z) failed
the Linux unit and Windows legs on `RunUnitStateDriftTests.NoStaticMutableCollection_OutsideTheDocumentedProcessStores`.
Run 41230045564, PR #896 queued behind it, failed with it. The branch's GREEN gate `000001-20261031T175321Z` lists both
static-store cases of that class in `not-run-Unit.txt`. The operator registered the field by hand at `d917370e0`, and
that gate ran the test only because the test file itself changed (tier 0a).

## The fix's shape (make the next case automatic)

1. A declared assembly scope, like `TreeScope`: a reflection drift test reads its types only through one shared
   helper that names the assembly and the source tree it governs (e.g. `src/WiseOwl.Cobol.Runtime/`).
   `drift_rules.py` reads the declaration as it reads `TreeScope`, so `drift_rules.py <file>` lists the sweep for
   every file under that tree, and tier 0d puts it in leg 1 for a change there.
2. A guard drift test, the sibling of `TrackedTreeScopeDriftTests`: every test call that enumerates an assembly's
   types or members (`GetTypes`, `GetExportedTypes`, `DefinedTypes`, `GetFields`/`GetMethods` over all types) goes
   through the declared scope, so a new reflection sweep cannot be invisible.
3. Sweep the existing reflection tests. On 2026-10-31, 20+ test files call `GetTypes()` without the `Sweep` trait,
   among them `RunUnitStateDriftTests`, `EcSizeGuardDriftTests`, `FileLockPostureDriftTests`,
   `GobackPhraseDecodeDriftTests`, `PlaceStorageCellDriftTests`, `SortWorkBoundDriftTests`,
   `RepositoryVocabularyDriftTests` and `BoundIoPhraseConsumptionDriftTests`. Classify each one: a whole-assembly
   sweep, which gets the scope, or a read of one named type, which the coverage map already attributes.
4. Keep `HostWitnessTraitDriftTests`' rule that the `Sweep` set equals `drift_rules.py`'s sweeps: an assembly-scoped
   class is a tree-wide sweep of its project, so it carries the trait. Update DESIGN-test-build-ci.md (the tier list)
   in the same change.

The other selection gap seen the same day, the impact map 111 commits stale, which reduced leg 1 to the cheapest 2 %
(PR #880), is PB2696's. This note is only the reflection-sweep class.
