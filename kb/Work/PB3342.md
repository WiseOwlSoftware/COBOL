# PB3342 — COBOLNET4213 refuses legal source: an override named like its class

Source: the PB1784 implementer's lead (carried from round 1 of review), report `E:/COBOL-coord/scratch/reports/w1108a-PB1784-report.md`, "New defects / leads"; branch `worktree-wf_9e52adb3-fa2-7`, PR #188. The lead was NOT re-verified by the filing clerk. The code sites below are on PR #188's branch; main gains them when that PR merges.

**What the compiler does.** A COBOL class that overrides an inherited method whose name equals the overriding class's own name is refused with COBOLNET4213 (`OverrideNamedLikeItsClass`). The diagnostic text itself calls it an "implementation restriction". The restriction comes from C#: the emitted member name would equal the generated class name, which C# rejects as CS0542 ("member names cannot be the same as their enclosing type").

**Why it is a defect.** The lead says the source is legal COBOL. Rejecting legal source is debt (CLAUDE.md rule 3), and the fix is an emitted-name mapping for the collision, never a refusal (rule 4, no workaround).

**Repro.** A base class with a method `M`; a subclass named `M` that OVERRIDEs it. Expected: it compiles and the override dispatches. Seen: COBOLNET4213.

**Code sites (on PR #188's branch).**
- `src/Cobol.Net.Compiler/Oo/OoClassTable.cs`, `MarkRoster` (about line 972): `m.CsName = baseM.CsName; if (m.CsName == sym.CsName) edition.Error(DiagnosticCatalog.OverrideNamedLikeItsClass, ...)`.
- Descriptor: `src/Cobol.Net.Editions/Diagnostics/DiagnosticCatalog.cs` (about line 7083).

**To verify (the implementer's first step).** The spec citation that makes the source legal is NOT yet checked: derive it from `specs/ISO_COBOL.md` and run `python scripts/spec/cite.py --check <clause> "<text>"` before it enters code, a golden or the DEVLOG. Until then it is "to verify", not a citation. Frontmatter values are the most conservative the lead supports (severity MINOR, rejects_legal_source true); the implementer may raise the severity once the repro is measured.

**Fix shape.** Map the emitted C# member name when it equals the class name (one mechanism, in the name allocator that sets `CsName`), delete COBOLNET4213 with its descriptor, docs row and tests in the same change, and sweep for sibling C# naming collisions (member versus enclosing type, member versus nested type).

## Landed (2026-10-17, w1111b)

**Re-probed first** on the worktree's own build (main 4016a67cb + this branch): `E:/COBOL-coord/scratch/w1111b/OVR1.cob`
(class `M3342` overriding `K3342B`'s `M3342`) drew `error COBOLNET4213` exactly as the lead said. The sibling sweep found
two more arms of the same mechanism: `OVR2.cob` (class `N3342` implementing an interface prototype `N3342`) compiled
through the binder and FAILED IN ROSLYN, `CS0535: 'N3342' does not implement interface member 'I3342.N3342()'`, because
the class's own method was renamed alone (PB975) while the prototype kept the plain name; and `OVR3.cob` (a class named
`FACTORYOBJECT` overriding BASE's FactoryObject, which section 16.2 does not declare FINAL) drew COBOLNET4213 against the
runtime's member `FACTORYOBJECT()`.

**Legal source** (each `cite.py --check` OK): section 8.3.2.2 bars one word as two types of user-defined word only "Within
a source element"; section 10.5 "A source element is a source unit excluding any contained source units", so the
METHOD-ID's method-name and the CLASS-ID's object-class-name sit in different source elements (section 8.4.6.1: "independent
of the use of these user-defined words by other source elements"); section 11.7.3 rule 3) requires only "a method with the
same method resolution signature ... defined in a superclass"; section 9.3.6 binds "the class of the actual object
referenced at runtime".

**Fix (one rule, one place).** `OoClassTable.NameMethodSlots`, run at the end of `ResolveOverrides`: every method that C#
requires to share one member name is one SLOT (an override chain, joined with every interface prototype a member of it
implements, found through the same `FindMethod` / `FindFactoryMethod` roster key `OoConformance.ValidateImplements` asks).
A slot is named once, from its first non-overriding method's word (a standard method's runtime name when it holds one),
and renamed to `NamingConvention.ClassNamedMethodName` (`__method_X`) when any type declaring a member of it (instance
class, factory class, interface) spells that name. `AddMethods`' own-name rename (the PB975 special case) is deleted: it is
the one-member case of the slot rule. The runtime's `BASE.FACTORYOBJECT()` is `BASE.__FactoryObject()`
(`OoStandardClasses.FactoryObjectCsName`), the reason `New` is `__New`. COBOLNET4213 `OverrideNamedLikeItsClass` is
deleted with a retirement comment (the id is never reallocated); `docs/COBOLNET_OO_DESIGN.md` item 5 describes slots.

**Goldens.** `conformance-suite/cases/9.3.6-Method-invocation/pb3342_slot_named_like_its_class` (2002/2014/2023: the
override typed, through the base reference and through a universal reference; an implementation of a prototype spelled
like the class; a prototype spelled like its interface, implemented and overridden; a factory method spelled like its
class; FactoryObject overridden in class FACTORYOBJECT) and the negative `pb3342-slot-named-like-its-class-at-85`
(COBOLNET0900 at 85, `wiseowl/diagnostics.json`).

**For the next implementer.**
- `src/Cobol.Net.Compiler/Oo/OoClassTable.cs#NameMethodSlots` — the one C# naming rule for every method slot (an override chain with the prototypes it implements); never rename a method alone.
- `src/Cobol.Net.Compiler/Oo/OoStandardClasses.cs#FactoryObjectCsName` — `__FactoryObject` (runtime `BASE.__FactoryObject()`), a name no class-name spells, like `__New`.
