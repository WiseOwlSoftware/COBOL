# PB4937 - an edition-less citation in a golden

**Sites:** `conformance-suite/cases/12.3.8-REPOSITORY/pb4822-function-literal5-refused-reference.cob` (whole: its header comment, line 7, is the only change)

**Report (R1-2 low).** The golden's header says "ISO 12.3.8.3 SR2: literal-5 shall not be a zero-length literal", which CLAUDE.md rule 1 (owner 2026-11-06, kb/Work PB4887) forbids:
every citation written carries its edition, `§2023:12.3.8.3 SR2`, validated with `python scripts/spec/cite.py --check "§2023:12.3.8.3 SR2" "zero-length"`.
The fix rewrites that line and sweeps the sibling goldens the same wave added for bare `ISO <n>` citations (`git grep -n "ISO [0-9]" conformance-suite/cases/12.3.8-REPOSITORY`), since the
register's rule is that a bare citation is never the standard. PB4887's rewrite of the older tree covers the old ones; this is the one the PB4822 landing introduced.

Source report and lead: `w20261905h-PB4822-report.md`, R1-2.
