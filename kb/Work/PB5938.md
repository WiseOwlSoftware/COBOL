# PB5938 - the citation audit cannot read a citation in a table cell next to its quotation

**Sites:** `scripts/spec/audit_doc_citations.py#POST` (line 97), `#PAT` (line 87), `#citations` (line 254), `docs/rearchitecture/DESIGN-listing.md`
(the section 2 tables, lines 54-61 and on).

**The lead.** The design review's author noted that `audit_doc_citations` counted 1962 verbatim-shaped citations before and after adding
`docs/rearchitecture/DESIGN-listing.md`, so it might not read the new doc.

**Evidence (run this session in the notes-25 worktree on origin/main 0d4042678a).**
- `python scripts/spec/audit_doc_citations.py | head -3`: `1981 verbatim-shaped citations checked · 1893 correct`, `0 MISFILED`, `0 ELIDED` (the
  count moved from 1962 as other docs changed; it is not evidence about DESIGN-listing.md).
- The probe that matters, scanning the one file with the audit's own `scan` (`citation_corpus.all_files()` includes the doc, 19251 files):
  `python -c` with `audit_doc_citations.scan([docs/rearchitecture/DESIGN-listing.md], [])` printed `DESIGN-listing: ok 0 misfiled 0 absent 0`. The
  file is read, and not one quotation of it is paired with a citation.
- Why: the doc's tables write a row as `| 85-1 | "each compiler accepts source programs ..." | §1985:IV.7.1 | ... |`. The postfix form `POST` (line 97)
  accepts a citation after the quote only when it ends in one of `)` `]` `,` `.` `;` `:` `/` `·` or end of line, and the prefix form `PAT` needs
  the citation BEFORE the quote with at most 80 characters of non-quote text between. A table cell separator `|` ends neither.
- The quotations themselves are real where sampled: `python scripts/spec/cite.py --check "§1985:IV.7.1" "each compiler accepts source programs
  written in reference format and produces an output listing of the source program in reference format"` -> `OK  §1985:IV.7.1 ... the text is in the
  clause`; `--check "§1985:IV.7.4" "The entries on the output listing need be indented only if the input is indented"` -> `OK  §1985:IV.7.4`.
  This is the rule-1 failure mode's opening, not an observed misfiling: the check that would catch an inherited clause number never runs here.
- Siblings: `git grep -c '" | §[0-9]' -- docs kb src tests` counts the shape in `docs/rearchitecture/DESIGN-external-repository.md` (25),
  `DESIGN-listing.md` (16), `DESIGN-message-control.md` (2), `PHASE-11-scout-notes.md` (27), `kb/Spec/Lookup/IR Mapping.md` (1) and `kb/Work/PB379.md`
  (6). Those counts are lines of the shape, not proven unpaired; the next owner runs the one-file probe above on each.

**Fix shape.** Teach `citations()` the table form (a quotation in one cell, its citation in the next cell, and the reverse order), in the one
parser the audit and `audit_code_citations.py` share where the order rule lives, and add a `--self-test` case that fails on a planted table row with
a wrong clause (the check must be able to fail). Then run it across the corpus, adjudicate what it finds (rule 1: validate each with `cite.py
--check`), and add a drift assertion that the audit pairs at least one citation in every doc that has a section of quoted table rows, so a doc shape
the audit cannot read is a red, not a silence.
