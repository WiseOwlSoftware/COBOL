**Mechanism.** The SD (and FD) binder synthesizes a FileModel for a file description entry whose file-name no SELECT names, and no pass diagnoses the missing file control entry

**Repro.** FILE-CONTROL. SELECT IN1 ASSIGN TO "in1.dat" ORGANIZATION LINE SEQUENTIAL. / FILE SECTION. FD IN1. 01 IN-REC PIC X(10). SD SRT. 01 SRT-REC. 05 SK PIC X(10). / PROCEDURE DIVISION. SORT SRT ON ASCENDING KEY SK USING IN1 GIVING IN1. DISPLAY "DONE". STOP RUN.  (cobol sr1.cob --std 2023 --run)

**Expected, from the standard.** Compile-time error: §13.4.6.3 SR1 "File-name-1 shall be specified in a file control entry." SRT has no SELECT. The FD twin §13.4.5.3 SR1 (identical text) likewise requires rejecting `FD SRT.` without a SELECT.

**Observed.** Compiles clean, runs, sorts in1.dat and prints DONE. The FD variant (FD SRT without SELECT, OPEN INPUT SRT CLOSE SRT) also compiles and runs clean. DataBinder's SD arm does `if (!FilesByName.TryGetValue(sdName, out var sdFile)) sdFile = new FileModel { CobolName = sdName, SelectName = sdName }` and nothing downstream checks that a SELECT created the file.

**Code site.** src/Cobol.Net.Compiler/Binding/DataBinder.cs#ResolveFiles (SD arm ~L1543-1548 and the FD arm's equivalent lookup)
