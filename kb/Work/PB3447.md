# PB3447 — landing_check.py arm 1 is disabled by any empty ledger group

> ⚙ **flags:** process-only

Source: wave 1131 group G (PB3263, PR #309), branch review `w1131g-review-r1` finding R1-2, severity low.

**Code site.** `scripts/orchestrator/landing_check.py:231` (`check`). Arm 1 turns EVERY outside-the-declared-set stop into a warning when ANY consulted ledger group has no files, even when another consulted group for the same notes declares a full set. The ledger keeps every non-terminal group across waves (`record_dispatch` upserts by wave+letter only), so a stale 0-file earlier dispatch of a note disables the arm-1 stop for every later landing of it.

**Fix direction.** Take the declared set from the group that owns THIS landing (or the union of the consulted groups' files, warning only when every consulted group is empty), and retire a superseded group when a later dispatch of the same notes is recorded. Pin with a test: one stale empty group plus one full group still stops an outside-the-set file.
