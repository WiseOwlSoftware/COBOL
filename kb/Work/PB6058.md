# PB6058 — LANDED — every stop file is printed at session start

## The defect

The loop's `<coord>\STOP` and `<coord>\STOP-UNIT` and the loop fleet's `scratch\STOP-loop`, all written 2026-11-16
17:47, were still present on 2026-11-22. The owner: "We should have no STOP files from 6 days ago." A stop halts
whatever reads it for as long as it exists, so a stop nobody lifts stops its reader silently. `stop.ps1 -Status` read
them, but no session ran it, and the session probe never printed any stop. Five wave stops (`STOP-w1108`,
`STOP-w20261809`, `STOP-w20261810`, `STOP-w20261909`, `STOP-a4-finisher`) and five hand-archived copies under
`scratch\op-20261115` had collected the same way. All of them were removed on 2026-11-22.

## The fix

`coord.stop_signals` lists every stop file present with its age: the loop's `STOP` and `STOP-UNIT`, the owner's
global `scratch\STOP`, and each `STOP-<scope>` in `scratch` or one directory below it. `coord.stop_report`
marks a stop older than `STALE_STOP_S` (24 h) with ⛔, because a stop lives for one wind-down. `coord.py stops`
prints the report and exits 1 when a stop is stale. The session probe prints it as its `stops` line, so every
session start, resume and compaction shows each stop and its age. `coord.py --self-test` covers which files are
found (the names, an exact-case match because a Windows glob ignores case, one level below scratch) and the
stale count.
