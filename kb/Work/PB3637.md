# PB3637 — scripts reconfigure stdout after argparse has already printed

**Sites:** every `scripts/**/*.py` that calls `sys.stdout.reconfigure` (71 files), the one place that sets UTF-8 mode for the repository's Python entry points, a new `--help` drift test.

Found 2026-10-24 ~11:15 PDT by the attended operator session (2f7da35b) while answering the owner's "What others notes
aren't being enacted".

## Repro

On the Windows host (Git Bash or PowerShell, console code page cp1252):

    python scripts/spec/work.py --help

dies with `UnicodeEncodeError: 'charmap' codec can't encode character '⛔' in position 226`. The module docstring
(the argparse description) carries `⛔`; `main()` calls `sys.stdout.reconfigure(encoding="utf-8")` at
`scripts/spec/work.py:1249`, after `ap.parse_args()` at line 1247, and `--help` exits inside `parse_args`.

## Sweep

A scan of `scripts/**/*.py` for a `.parse_args(` that precedes the file's first `stdout.reconfigure(` found 71 files,
every one also carrying non-cp1252 text (e.g. `scripts/devlog.py`, `scripts/gate_plan.py`, `scripts/differential_fuzz.py`,
`scripts/filter_population.py`, `scripts/arch/member_index.py`). Any of them dies the same way on `--help` or on a usage
error whose text holds such a character.

## Where it goes (kb/Work PB3726, `docs/rearchitecture/DESIGN-orchestrator-loop.md` §16.10)

Re-clustered from PB1957 into the PB3726 restructure campaign on 2026-10-25, tier 1: it edits one line in each of the 71
scripts, five of which every later split of that campaign rewrites, so it lands first, dispatched as a group claiming the 71
files WHOLE (the dispatch ledger holds every colliding group of either lane out while it runs). The ONE mechanism is the
environment: `PYTHONUTF8=1` set once in `scripts/python-resolve.sh`, `scripts/python-resolve.ps1`, `scripts/orchestrator/
orchestrate.ps1` and the CI workflow's top-level `env:`, and in the hooks' environment (`.claude/settings.json`), with every
per-script `sys.stdout.reconfigure` deleted in the same landing and the drift test below. The loop plans PB1957 and PB3608
and never this cluster.

## Fix direction

The cause is 71 copies of one line in the wrong place, so the fix is ONE mechanism, not 71 moved lines (CLAUDE.md rule
4, rule 5): the repository's Python runs in UTF-8 mode on every host (a single place sets it for every entry point,
e.g. `PYTHONUTF8=1` in the environment the hooks, the supervisor, the gate and the units inherit, or one shared
`console_utf8()` called at import by a common module), and every per-script `reconfigure` copy is deleted in the same
change. Drift test: every `scripts/**/*.py` with an argparse `main` runs `--help` to exit 0 under a cp1252 console
(`PYTHONIOENCODING=cp1252`), and no script carries its own `stdout.reconfigure`.

## Landed (wave 20261503 group A, branch `worktree-wf_94698d58-de0-1`)

**Re-probe (2026-10-25, base 6401498bd).** `python scripts/spec/work.py --help` through a pipe on the Windows host:
`UnicodeEncodeError: 'charmap' codec can't encode character '\u26d4' in position 251`. A measured sweep (every argparse
entry point under `live_tools.ROOTS` run with `--help` and an unknown option, stdout and stderr encoded cp1252) found 31
crashing, not the 71 a text scan counted; 126 tracked Python files carried their own `reconfigure` copy, 122 of them live tools.

**Determination: the mechanism is a call IN THE PROGRAM, not the environment.** The "Where it goes" plan above names
`PYTHONUTF8=1` set in the launchers. Two facts overrule it: the owner's direction of 2026-10-10 (recorded in PB1546:
"this would work if the compiler startup (plus likely test cases) set the console output encoding to UTF-8"; the
environment variable alone does not do it), and a measurement on this host: `PYTHONUTF8=1 PYTHONIOENCODING=cp1252
python -c "import sys; print(sys.flags.utf8_mode, sys.stdout.encoding)"` prints `1 cp1252`, and `work.py --help` still
crashes under that pair, so the plan's own oracle (`--help` exits 0 under `PYTHONIOENCODING=cp1252`) cannot pass with
the environment alone, and a hand run carries no variable at all. `docs/rearchitecture/DESIGN-orchestrator-loop.md`
§16.10 (on `design-PB3726`, not on main) still names the environment and needs the same correction. (2026-10-26: corrected - the design IS on main, section 16.10 "The order, the waves and PB3637", and the PB3637 landing already corrected its row and paragraph; the review's R1-3 found this sentence stale.)

**Fix.** `scripts/standard_streams.py#ensure_utf8` is the ONE place: stdin, stdout and stderr to UTF-8 with UTF-8 mode's
error handlers (PEP 540), safe with no console or a replaced stream, `line_buffering=True` for the two scripts whose
log another process tails (`run_gate_legs.py`, `record_impact_map.py`). Every live Python entry point calls it as the
first statement of its `__main__` block (a hook or stand-alone self-test with no such block: at module level, after its
imports); every live per-script `reconfigure` copy (122 files) is deleted and the call added to the 51 entry points that had none, `land_lane.py`'s fake enqueue child included.
The launchers keep setting UTF-8 for a child (PythonInstrument, self_tests.py, orchestrate.ps1), as the owner asked;
`ExternalCorpusPopulationDriftTests` lost its private copy of PythonInstrument's interpreter probe and launches through
it. `docs/**/evidence/**` and `adjudication/**` are frozen records (live_tools.py) and keep their copies.

**Drift test.** `standard_streams.py --check` (rules COPY, ENTRY, HELP), run by
`tests/WiseOwl.Cobol.Tests.Unit/ScriptStandardStreamsDriftTests.cs` (a tree-wide sweep, leg 1 of every gate, Windows and
the Linux half): 183 live Python files scanned, 127 entry points probed under cp1252, 0 findings. Its `--self-test`
(discovered by self_tests.py) plants a parser whose prog and help carry ⛔: without the call the probe reports two
findings (the --help traceback on stdout, the backslash-escaped `\u26d4` on stderr), with it none.

**For the next implementer.**
- `scripts/standard_streams.py#ensure_utf8` — the one UTF-8 switch; import it (`from standard_streams import
  ensure_utf8`, with `scripts/` on sys.path: subdirectory scripts append it) and call it first in `__main__`.
- `scripts/standard_streams.py#scan` / `#probe_cli` — the rule and the probe; a NEW script that skips the call is red
  in ScriptStandardStreamsDriftTests by name. Trap: stderr's errors handler is backslashreplace, so a usage error never
  crashes, it prints `\u26d4`; the probe reads that escape as the failure.
