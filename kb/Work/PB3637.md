# PB3637 — scripts reconfigure stdout after argparse has already printed

**Sites:** every `scripts/**/*.py` that calls `sys.stdout.reconfigure` (71 files), the one place that sets UTF-8 mode for the repository's Python entry points, a new `--help` drift test.

Found 2026-10-24 ~11:15 PDT by the attended operator session (2f7da35b) while answering the owner's "What others notes
aren't being enacted".

## Repro

On the Windows host (Git Bash or PowerShell, console code page cp1252):

    python scripts/spec/work.py --help

dies with `UnicodeEncodeError: 'charmap' codec can't encode character '⛔' in position 226`. The module docstring
(the argparse description) carries `⛔`; `main()` calls `sys.stdout.reconfigure(encoding="utf-8")` at
`scripts/spec/work.py:1249`, after `ap.parse_args()` at line 1247, and `--help` exits inside `parse_args`.

## Sweep

A scan of `scripts/**/*.py` for a `.parse_args(` that precedes the file's first `stdout.reconfigure(` found 71 files,
every one also carrying non-cp1252 text (e.g. `scripts/devlog.py`, `scripts/gate_plan.py`, `scripts/differential_fuzz.py`,
`scripts/filter_population.py`, `scripts/arch/member_index.py`). Any of them dies the same way on `--help` or on a usage
error whose text holds such a character.

## Where it goes (kb/Work PB3726, `docs/rearchitecture/DESIGN-orchestrator-loop.md` §16.10)

Re-clustered from PB1957 into the PB3726 restructure campaign on 2026-10-25, tier 1: it edits one line in each of the 71
scripts, five of which every later split of that campaign rewrites, so it lands first, dispatched as a group claiming the 71
files WHOLE (the dispatch ledger holds every colliding group of either lane out while it runs). The ONE mechanism is the
environment: `PYTHONUTF8=1` set once in `scripts/python-resolve.sh`, `scripts/python-resolve.ps1`, `scripts/orchestrator/
orchestrate.ps1` and the CI workflow's top-level `env:`, and in the hooks' environment (`.claude/settings.json`), with every
per-script `sys.stdout.reconfigure` deleted in the same landing and the drift test below. The loop plans PB1957 and PB3608
and never this cluster.

## Fix direction

The cause is 71 copies of one line in the wrong place, so the fix is ONE mechanism, not 71 moved lines (CLAUDE.md rule
4, rule 5): the repository's Python runs in UTF-8 mode on every host (a single place sets it for every entry point,
e.g. `PYTHONUTF8=1` in the environment the hooks, the supervisor, the gate and the units inherit, or one shared
`console_utf8()` called at import by a common module), and every per-script `reconfigure` copy is deleted in the same
change. Drift test: every `scripts/**/*.py` with an argparse `main` runs `--help` to exit 0 under a cp1252 console
(`PYTHONIOENCODING=cp1252`), and no script carries its own `stdout.reconfigure`.
