# PB3948 — the COBOL1720 rationale (IoPhraseForbiddenHere) explains the READ INVALID KEY arm for sequential organization only: it omits the second READ site and SR8 / SR9 / GR19

**Sites:** `src/WiseOwl.Cobol.Editions/Diagnostics/DiagnosticCatalog.cs:311` (`IoPhraseForbiddenHere`), `src/WiseOwl.Cobol.Compiler/Binding/Validation/StatementValidation.cs` (`StatementValidation.CheckReadKeyFormat`, comment that quoted the old rationale), `docs/CONFORMANCE.md` (the READ KEY paragraph, §14.9.30)

**Landed 2026-10-30 (wave 20261769).** The rationale now names both READ sites (`SequentialIoBinder.BindRead`,
`KeyedIoBinder.BindRead`) and quotes GR19, SR8 and SR9 (each `cite.py --check` OK: `14.9.30.3 "If neither the NEXT phrase
nor the PREVIOUS phrase is specified and ACCESS MODE SEQUENTIAL"` OK 8), `14.9.30.3 "the NEXT phrase is implied if any of
the following phrases"` OK 9), `14.9.30.4 "An implicit or explicit NEXT phrase or a PREVIOUS phrase results in a
sequential read"` OK 19)); the sequential-file ACCESS MODE rule it leans on was checked as well. Its citation list gained SR8, SR9 and GR19. The two prose
copies of the old quotation (`CheckReadKeyFormat`'s summary, `docs/CONFORMANCE.md`) were reworded to match. The
`diagnostics.json` entries carry only the code, so they already agreed.

PB3569 added a second COBOL1720 READ site (`KeyedIoBinder.BindRead`, lines 99 to 102) for an INDEXED or RELATIVE file whose
READ binds sequential (SEQUENTIAL access by SR8, DYNAMIC with ADVANCING / AT END by SR9). The catalog rationale of
COBOL1720 still explains the arm only as "every READ of a sequential-organization file a Format-1 read" and its citation list
omits SR8, SR9 and GR19. `StatementValidation.CheckReadKeyFormat` now quotes this rationale as the shared reading, so the
text a user reads is incomplete.

## Acceptance
- The rationale names both sites and cites the rules with `python scripts/spec/cite.py --check` run on each; the catalog,
  `diagnostics.json` and `docs/CONFORMANCE.md` agree.
