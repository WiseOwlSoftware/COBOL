**Rule it breaks:** One rule in one place (design §5.2; dimensions.md 4). Determination L12 calls NormalizeLocaleText THE ONE normalization of locale-sourced text (LocaleFacts.cs:155-172). No aliases or forwarders (CLAUDE.md rule 4).

**Scenario:** LocaleFacts.NormalizeLocaleText strips every Unicode Cf character and maps U+00A0/U+202F/U+2009 to a space. The NUMVAL-C / TEST-NUMVAL-C LOCALE scan restates that set by hand at CobolIntrinsics.NumvalLocale.cs:264 and maps only the three spaces; it never skips Cf. So the argument side and the snapshot side apply different equivalences. The snapshot currency symbol of an ar-* locale has its trailing U+200F stripped, but an argument that carries the culture own formatted string ("value.ToString("C", culture)", U+200F included) fails MatchAt at the currency position. When the next ICU release introduces another spacing character (as U+202F arrived in ICU 72), whoever extends NormalizeLocaleText also has to know about the literal in MatchAt, or PICTURE format-2 editing and NUMVAL-C recognition drift apart. That is exactly the drift MonetaryFacts says it exists to prevent. LocaleFacts.NormalizeSpacing is a one-line alias of NormalizeLocaleText; its only callers are DateFormat/TimeFormat and two test asserts.
