**Scenario:** LocaleFacts.NormalizeLocaleText strips every Unicode Cf character and maps U+00A0/U+202F/U+2009 to a space. The NUMVAL-C / TEST-NUMVAL-C LOCALE scan restates that set by hand at CobolIntrinsics.NumvalLocale.cs:264 and maps only the three spaces; it never skips Cf. So the argument side and the snapshot side apply different equivalences. The snapshot currency symbol of an ar-* locale has its trailing U+200F stripped, but an argument that carries the culture own formatted string ("value.ToString("C", culture)", U+200F included) fails MatchAt at the currency position. When the next ICU release introduces another spacing character (as U+202F arrived in ICU 72), whoever extends NormalizeLocaleText also has to know about the literal in MatchAt, or PICTURE format-2 editing and NUMVAL-C recognition drift apart. That is exactly the drift MonetaryFacts says it exists to prevent. LocaleFacts.NormalizeSpacing is a one-line alias of NormalizeLocaleText; its only callers are DateFormat/TimeFormat and two test asserts.

## Landed (wave 1096, group G)

**Re-probe (worktree build at 32f372674):** a free-format probe under `LOCALE AE IS "ar-AE"` gave TEST-NUMVAL-C 14
for ar-AE's own `1,234.56 د.إ.` + U+200F (the culture's `ToString("C")`; the snapshot symbol has the U+200F
stripped), 9 for `1,234.56` U+00A0 `د.إ.` (U+00A0 matched a normalized separator in `MatchAt` but `Sp()` never
skipped it as a space), 1 for a leading U+200F, and NUMVAL-C of the first returned 0 under EC-ARGUMENT-FUNCTION.
The finding held: the snapshot and the argument were compared under two different equivalences.

**Fix (the target):** `LocaleFacts.TryFoldLocaleChar` is THE per-character L12 fold (Cf removed; U+00A0, U+202F,
U+2009 to the plain space). `NormalizeLocaleText(string)` (every snapshot string) and the new
`NormalizeLocaleText(string, out int[]? origins)` both fold through it. `NvScanLocale` folds argument-1 once and
scans the folded text; every position it reports (the structural one and the digit-cap one) maps back through
`origins` to the original argument's ordinal, with LENGTH + 1 of the original for r1 c. `MatchAt` no longer
restates the spacing set (ordinal, plus the ANYCASE fold). `NormalizeSpacing` is deleted; `DateFormat`,
`TimeFormat` and `CobolLocaleTests` call `NormalizeLocaleText`. Decision on Cf in an argument: IGNORABLE, recorded
with L12 in docs/CONFORMANCE.md (§15.68.3 r5 b "a format consistent with the specifications of locale category
LC_MONETARY", `--check` OK), and in DESIGN-locale-facility §4.6.

**Behavior:** not neutral, by design. NUMVAL-C / TEST-NUMVAL-C LOCALE now accept an argument carrying a Cf
character or a no-break space where a space is admitted (both were rejected before, a wrong answer under L12's
"recognition matches through the same equivalence"). Witnesses: golden `2002/pb2766_numvalc_locale_l12_argument`,
`NumvalCLocaleScanTests.L12Equivalence_*` and `EveryHostCulture_RecognizesItsOwnFormattedCurrencyString` (every
host culture's own currency string is conforming and evaluates to its value; mn-Mong-MN, whose mon_thousands_sep
is its mon_decimal_point, is the §8.2.1 invalid-content case and is excluded).

**Sweep:** the L12 character set is now written once (`grep u00A0|u202F|u2009|UnicodeCategory.Format` over src:
LocaleFacts only). The format-2 de-edit (`CobolLocaleEdit.DeEditNum` / `TryUnwrap`) stays ordinal: §14.6.13.2 r4
admits only "a possible result" of the edit, which is already folded. `CobolIntrinsics.Text.cs`'s `MatchAt` is the
unrelated SUBSTITUTE matcher.

**For the next implementer:**
- `src/Cobol.Net.Runtime/Globalization/LocaleFacts.cs#TryFoldLocaleChar` owns the L12 character set; a new ICU spacing or mark character is added there and nowhere else. REUSE `NormalizeLocaleText(string)` for a snapshot string and `NormalizeLocaleText(string, out int[]? origins)` for text matched against locale data (origins is null for the identity).
- `src/Cobol.Net.Runtime/Intrinsics/CobolIntrinsics.NumvalLocale.cs#NvScanLocale` scans the FOLDED argument; its local `Ordinal(k)` is the only way a scan index becomes a reported §15.94.4 position. Trap: `TryLocTemplate` and `MatchAt` see the folded text, so never compare their indices with the original's length.
- `src/Cobol.Net.Runtime/Globalization/TimeFacts.cs` reads `LocaleFacts.DateFormat` / `TimeFormat`, which normalize through `NormalizeLocaleText`.
- `tests/Cobol.Net.Tests.Unit/NumvalCLocaleScanTests.cs#EveryHostCulture_RecognizesItsOwnFormattedCurrencyString` holds every host culture's own currency string to the scan; mn-Mong-MN (mon_thousands_sep = mon_decimal_point) is the §8.2.1 invalid case and is skipped.
