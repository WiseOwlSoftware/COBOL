# PB5209 - a reference modifier on a table element subscripted with ALL in an intrinsic function argument (FUNCTION MAX (TE (ALL) (2:1))) is refused COBOL2363: TryBindAllArgument gives up on any suffix after the subscript list, and the ordinary resolver then refuses the ALL

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs` (`TryBindAllArgument`)
- `src/WiseOwl.Cobol.Compiler/Binding/SubscriptBinder.cs` (`MaterializePosition`, `IllegalPositionMessage`)

**Mechanism.** The identifier format prints `data-name-1 ... [({subscript} ...)] [reference-modifier]` (§1985:IV.4.3.8.5.2), the subscript may be ALL in a function argument (§1985:IV.4.3.8.2.3 SR7), and the reference-modification rules name exactly this combination (§1985:IV.4.3.8.4.4 GR3). `IntrinsicBinder.TryBindAllArgument`, the one place a `table (... ALL ...)` argument becomes a `TableAllPlace`, returns false as soon as anything follows the subscript list ("anything after the subscript group - not the shape", and a qualification carrying a `refModPart`). The argument then goes to the ordinary operand bind, whose `SubscriptBinder.MaterializePosition` meets the word ALL outside the contexts it knows and refuses it as COBOL2363, with a message that says ALL is permitted in an intrinsic function argument, which this one is. The defect has no edition arm: the same refusal is printed at `--std 2023`.

**Found by.** The 1985 refuter pass (2026-11-10; records `E:/COBOL-coord/scratch/refute-85/out/r02.json`, probes `probes-r02/genr.py` with `rcases2.txt` r01 to r03): a refuter attacked the CONFORMS verdicts of the two rows below, OVERTURNED both on the same probes, and the repro was rerun on current main for this note.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids below.

**Rules (2; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-FMT-IV.4.3.8.4.2` - `§1985:IV.4.3.8.4.2` (refuter: OVERTURNED, harm: rejects-legal-source). The reference modifier follows data-name-1, which "may be qualified or subscripted" (§1985:IV.4.3.8.4.3 SR4: "Data-name-1 may be qualified or subscripted"); §1985:IV.4.3.8.2.3 SR7: "The subscript ALL may be used only when the subscripted identifier is used as a function argument"; §1985:IV.4.3.8.4.4 GR3: "If an ALL subscript is specified for an operand, the reference-modifier is applied to each of the implicitly specified elements of the table". The rest of the row held (CURRENT-DATE (1:2), A (N:), TE (N) (N:), a RENAMES item, a function result modified, and the refusals of a COMP item, a condition-name, `A ()` and two modifiers).
- `1985-FMT-IV.4.3.8.5.2` - `§1985:IV.4.3.8.5.2` (refuter: OVERTURNED, harm: rejects-legal-source). Format 2 prints `[({subscript} ...)] [reference-modifier]` after the qualifiers, so the sequence is legal with ALL as the subscript in a function argument; same probes, same refusal. Qualification by a file-name, a sort file-name and a report-name, and the refusal of a misplaced qualifier, held.

**Observed (current main, the build at 3d12682fd2, rerun 2026-11-10).** exit 65: `ar1.cob(13,31): error COBOL2363: the subscript ALL is written where it is not permitted: ISO §2023:8.4.2.3.3 SR6 - "The subscript ALL may be used only" when the subscripted identifier is an intrinsic function argument, ...`, followed by a cascade COBOL0819 on the MOVE. The same at `--std 2023`. Control: the program without line 13 (`ar0.cob`) runs and prints `CONTROL GHI`.

**Expected (from the 1985 text).** The program compiles and prints `CONTROL GHI` and `REFMOD H `: the modifier (2:1) applies to each of TE (1), TE (2), TE (3), giving B, E and H, and MAX returns H (§1985:IV.4.3.8.4.4 GR3).

**Fix direction (root cause, CLAUDE.md rule 4).** Let the ALL argument shape carry a reference modifier: `TryBindAllArgument` reads the subscript list and an optional trailing `refModPart` (on the direct suffix and on the last qualification), and the `TableAllPlace` it builds holds the modifier, applied per enumerated element by the backend's one enumeration. The ordinary resolver must never see an ALL from a function argument, so the COBOL2363 message stays true; add a drift test that every suffix the identifier grammar allows after a subscript list is either taken by the ALL shape or refused by a diagnostic of its own.
