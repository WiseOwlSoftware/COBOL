# PB243

**Rows:** `GR-14.9.11.4-2`, `GR-14.9.11.4-3`, `GR-14.9.11.4-5`

DISPLAY's landed DETERMINATIONS are pinned by nothing: the unbounded one-write transfer size, the GR5 chunking leg that is vacuous only because of it, and the `ALL literal-1` arm have no spec-derived golden between them.

ROWS: GR-14.9.11.4-2 (PARTIAL — GR2, 'The implementor shall define, for each device, the size of a data transfer', A.1 item 58), GR-14.9.11.4-5 (PARTIAL — GR5 legs (a) chunking / (b) left-alignment), GR-14.9.11.4-3 (PARTIAL — GR3, the single-occurrence figurative and its ALL arm). One emit path, one class of missing evidence.

WHAT CHANGED SINCE THE ROWS WERE WRITTEN. GR-14.9.11.4-2's residue as filed was 'docs/CONFORMANCE.md has NO row for item 58'. That row now EXISTS and states the determination outright (docs/CONFORMANCE.md §7 row 58): 'Unbounded. The standard display device (a byte stream) imposes no transfer size: every DISPLAY statement's operands are joined into ONE sending item and written in a single stream operation (GR3's device-accommodates arm is always taken; no operand splitting, no line folding). Implemented in AcceptDisplayEmitter.EmitDisplay.' Row 56 (conversion) landed with PB148 and row 57 (the VLG format) with PB164. So the DOCUMENTATION half of all three rows is closed and the rows are stale in that respect — what holds them open now is that NOTHING OBSERVES ANY OF IT.

MEASURED at HEAD, read-only: `grep -l "DISPLAY ALL " tests/conformance/*/*.cob` returns NOTHING — the `ALL literal-1` arm (and its boolean sub-leg `DISPLAY ALL B'101'`, itself a determination with no A.1 row) is exercised by zero goldens; only the BARE figurative arm is pinned, by conformance:2002/ca3_figurative_display_pcs (`DISPLAY 'BARE=' LOW-VALUE` under PROGRAM COLLATING SEQUENCE AL -> `BARE=Z`, pinning length-1 and the alphanumeric-PCS resolution). And no conformance program displays an operand long enough to prove no chunk boundary or wrap is inserted.

WHY THAT IS ONE RESIDUE, NOT THREE. GR5 leg (a) — 'repeat the transfer leftmost-first until the item is exhausted' — is UNREACHABLE BY CONSTRUCTION here: there is no device transfer size for the sending item to exceed. That vacuity is sound ONLY because GR2's determination says 'unbounded', so leg (a)'s verification IS GR2's determination plus one long-operand golden; the same golden closes GR2. Leg (b) (left alignment) holds trivially — a stream write deposits characters left-to-right and adds nothing. GR3's two sentences are implemented in two arms of the SAME OperandText.AsString entry (the bare-figurative arm renders `new string(FigurativeConstants.Fill(...), 1)`; the BoundAllLiteral arm renders the literal once with Category stamped by CobolLiteral.ClassOf, which is what keeps the national carve-out honest) — one arm pinned, the other not.

WHAT CLOSES IT (one fixture batch): a golden that displays a 300-character operand and asserts ONE unbroken output line (closes GR2's determination and makes GR5 leg (a) provably vacuous), and a golden covering `DISPLAY ALL 'AB'` / `ALL X'4142'` / `ALL N'..'` / `ALL B'101'` (closes GR3's second arm and the boolean determination). Both are AssertOutput-class evidence, not differential.

CAUTION FOR WHOEVER WRITES THEM: PB150 (open) records that CutRunner.Normalize trims every line's trailing spaces and the final newline, so a golden asserting 'one unbroken line' must not depend on trailing padding to prove it.

SPEC REFS (carried from the rows, each --check OK in the rows' own notes): §14.9.11.4 GR2 ('The implementor shall define, for each device, the size of a data transfer'), GR3 ('only a single occurrence of the figurative constant is displayed'), GR4/GR5 ('If the device is capable of receiving data of the same size as the data item being transferred, then the data item is transferred'); Annex A.1 item 58; §8.3.3.6.2 Formats 1-7 (the figurative list).

## Mechanism

Two symbols on one emit path. `src/Cobol.Net.Compiler/CodeGen/Verbs/AcceptDisplayEmitter.cs#EmitDisplay` is literally one `sink.Write(image)` / `sink.WriteLine(image)` over System.Console / System.Console.Error — no chunk width, no per-device table, no length test, no loop, no wrap, no padding; and `src/Cobol.Net.Compiler/CodeGen/Emit/OperandText.cs#AsString` renders `ALL literal-1` / a symbolic-character reference through the BoundAllLiteral arm as `EmitText.CsLiteral(n.Literal)` — the literal ONCE.
