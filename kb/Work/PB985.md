Filed 2026-09-22 by the ORCHESTRATOR on the owner's decision ("do #5 while we wait on scheduled work, as we recoup the
effort quickly").

## Why

The lander's whole-Conformance leg is the campaign's serial bottleneck: ~7,900 cases, measured **9.6 min quiet,
18.5 min at battery #84, 30.6 min in train 48** (DEVLOG, lander-throughput entry). Trains 46, 47 and 48 each hit 1–3
reds on their first gate, and the fixes were overwhelmingly TEST-SIDE (a probe template, a stale test-ref, a pinned
expectation) — yet the re-gate recompiled every program from scratch. Implementers re-gate the same way.

## What to build

A content-addressed cache of each case's COMPILED program, keyed by everything that determines the compiler's
output: the bits of the compiler and runtime assemblies under test (their hashes, not their versions), the case's
source (and every copybook it reads), the edition and every compiler option. A hit reuses the compiled artefact and
still RUNS it (runtime behaviour is what the case checks); a miss compiles and stores. Any compiler/runtime change
therefore misses everywhere — correctness never depends on the cache — while a re-gate after a test-only fix hits on
every case.

## Obligations

1. **Measure first**: where does a case's time actually go (COBOL front end, Roslyn emit, load, run)? If Roslyn
   emit is not the dominant cost, say so and size the cache to what is.
2. The key must be provably complete — a drift test that fails if a compiler input is added that the key omits
   (flip one input, prove a miss).
3. Safe under PARALLEL test hosts and PARALLEL worktrees (atomic writes; per-worktree or content-addressed shared
   dir; a size cap / eviction).
4. Opt-out switch, and the battery / CI run COLD by default unless the owner decides otherwise.
5. Report the measured before/after for a whole-assembly re-gate with no product change.

## Landed

Implemented by the PB985 implementer (2026-09-22) — design in `docs/rearchitecture/DESIGN-test-build-ci.md` §3.12.

1. **Measured first.** Serial, sampled: a corpus case spends ≈ 60 ms in the front end + bind, ≈ 40 ms in emit +
   Roslyn + packaging and ≈ 176 ms RUNNING; a NIST case ≈ 634 ms front end + bind, ≈ 98 ms emit, ≈ 203 ms run.
   Roslyn emit is NOT the dominant cost — the COBOL front end is — so the cache skips the WHOLE compile.
2. **The key is complete.** `CompiledProgramCache` keys the compiler's own bits (a hash of its reference closure +
   framework build + culture + cwd), EVERY `CompilerDriver.Options` property by reflection, the source path and
   content, and the compiler's OWN ambient-input record — the new `CompilationInputs` (every file read, every probe
   including the absent ones, every `>>DEFINE … PARAMETER` environment read, the WHEN-COMPILED clock), carried on
   `CompilerDriver.Result.Inputs` with `Result.OutputFiles`. A clock-reading compilation and a backend failure are
   never stored; a program that references an unkeyed assembly is never stored. `CompiledProgramCacheDriftTests`
   flips every axis and proves a miss, proves the output directory does not reach the output, and scans the compiler
   for any ambient read that bypasses `CompilationInputs`.
3. **Parallel-safe.** Temp-file-then-rename writes, content-addressed Brotli blobs, a per-worktree store under
   `.cache/compiled-programs/`, LRU eviction under an exclusive lock once per process (cap 4096 MB).
4. **Switch.** `COBOLNET_COMPILE_CACHE=off|on`; unset = ON locally, OFF under CI; `scripts/battery.sh` exports `off`
   — the battery and CI run COLD (the owner may decide otherwise).
5. **Measured before/after**, whole Conformance assembly (7,951 cases), `BelowNormal`, no product change: cold
   **22 m 53 s**; first gate with an empty store 21 m 31 s; warm re-gate **1 m 27 s** (13,133 hits / 27 misses);
   all green in all three. Store: 49 MB.
6. **Found on the way — every commit changed every compiler bit.** The SDK stamped the commit into each assembly
   (informational version + the Source Link map whose PDB checksum the dll embeds), so the lander's re-gate AFTER
   committing a test-only fix would have missed on every case. `Directory.Build.props` now makes Debug builds issue
   no source-control queries (Release keeps its stamp); `ADebugBuild_DoesNotStampTheCommit` pins it. Real flow
   re-measured: populate, commit a test-only change, rebuild (5 s), whole assembly **1 m 18 s**, 13,133 hits,
   7,952 green.
