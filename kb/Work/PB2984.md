# PB2984 — the OO name-resolution drift guard does not see OoClassTable's own lookups

Filed 2026-10-10 by the train 1055 lander from the wave 1055 C report
(`E:\COBOL-coord\scratch\reports\w1055c-PB2463-report.md`, new defect 2).

**Repro:** `tests/WiseOwl.Cobol.Tests.Unit/OoNameResolutionDriftTests.cs:67`, the `TableLookup` regex
`(?:OoClasses|\btable)\s*\??\.\s*(?:Find|FindInterface)\(` . `src/WiseOwl.Cobol.Compiler/Oo/OoClassTable.cs#SetOperand`
(about line 183) calls `FindInterface(d.Name!)` and `Find(n)` on itself, unqualified; the guard counts neither, so a
name-REFERENCE lookup added inside `OoClassTable` (rather than at a binder site through the funnel) passes the
drift test with no adjudication.

**Why it matters.** The guard's rule is that every class / interface name lookup goes through the resolution funnel
or is adjudicated by count. The two calls in `SetOperand` are lookups of an already-validated descriptor name, so
today's behavior is correct; the hole is the guard's.

**Fix shape:** count unqualified `Find(` / `FindInterface(` call sites inside `Oo/OoClassTable.cs` too (excluding
the declarations), adjudicate the current ones by count with their reason, and keep the drift test red on a new one.
