# PB934 — RETIRED (superseded by PB3102) — a name the compiler accepts and does nothing with

Source: the `PB404` report, "New defects" item 1. It shares its root cause with **PB409**'s sibling-sweep
item 2, and PB409 is `landed` — so the sweep it asked for has no owner. This is that owner.

## The measurement

Before wave 39, `EC-FLOW-GLOBAL-GOBACK` appeared at exactly ONE site in `src/` — its own row in
`src/WiseOwl.Cobol.Runtime/Exceptions/ExceptionCatalog.cs` — and neither
`EcEmitter.NonfatalAmbientGates` nor `FatalAmbientGates` carried a row for it. `>>TURN
EC-FLOW-GLOBAL-GOBACK CHECKING ON` therefore compiled clean and wired nothing. PB409 closed that name.

`EC-FLOW-GLOBAL-EXIT` **is still in that state** — legitimately, because no rule sets it — and that is
exactly why the check cannot be a grep: the grep's answer is identical for "nobody implemented it" and
"nothing in the standard raises it". A `grep -c` gives a number; what is needed is a REASON PER NAME.

## The rule

```
$ python scripts/spec/cite.py --check 14.6.13.1.1 "checking"
OK  §14.6.13.1.1   (General)
    An exception status indicator is a conceptual entity that exists for each function, method, or program
    for each exception condition and has two states, set or cleared. …
```

§14.6.13.1.1 governs enablement. The DEFECT is not in that clause — it is the absence of a mechanical
assertion that the catalogue and the emitter agree.

## What is owed

A drift test beside `ExceptionRaiseHelperDriftTests` asserting, for **every** row of `ExceptionCatalog`,
one of:

* a raise site in `src/` **and** a row in `EcEmitter.FatalAmbientGates` / `NonfatalAmbientGates`; or
* a recorded determination naming the reason no rule sets it — stored beside the catalogue row, not in a
  comment somewhere, so it is data the test reads.

That is `feedback_a_dead_lookup_is_also_unverified` made mechanical: a catalogued name nothing reads has
never been contradicted, and today nothing can tell a deliberate blank from a hole.

## Code sites

* `src/WiseOwl.Cobol.Runtime/Exceptions/ExceptionCatalog.cs`
* `src/WiseOwl.Cobol.Compiler/CodeGen/EcEmitter.cs` (`FatalAmbientGates`, `NonfatalAmbientGates`)
* a new drift test beside `ExceptionRaiseHelperDriftTests`

## Rows

None claimed — the per-name rows belong to the clauses that raise the conditions. What this note adds is
the mechanism that keeps those rows honest.

## Retired (wave 1078, 2026-10-14) — what is owed already exists

Re-probed on this tree's own `dotnet build WiseOwl.Cobol.sln -c Debug` (0 warnings, 0 errors) at main `c29af1704`. PB3102 (landed
wave 1070, group E) built the mechanism this note asked for, so nothing remains to implement:

| PB934 asked for | where it is now |
|---|---|
| a drift test beside `ExceptionRaiseHelperDriftTests`, over EVERY `ExceptionCatalog` row | `tests/WiseOwl.Cobol.Tests.Unit/EcRaiseSiteRegistryDriftTests.cs`, `EveryCataloguedLevel3Name_IsDeclaredAndRaised_OrDeclinedWithAReason`; 3/3 pass on this build |
| a raise site AND a gate row | the gate is now the binder declaration (`EcBinder.RaiseDeclarations.cs`: `NodeKindRaises`, `OperandRaises`, `AmbientRaises`; `EcBinder.AllDeclaredNames`), whose enabled names `EcEmitter.FatalAmbientGates` / `NonfatalAmbientGates` then wire to checking flags; the test fails each of the three shapes by name (raised-but-never-declared, declared-but-never-raised, neither) |
| a recorded determination for a name no rule sets, as data the test reads | `DeclinedRaiseSites`: every entry names a `docs/CONFORMANCE.md` Annex A.1 row, section 4 facility or section 3 determination, and `EveryDeclinedEntry_NamesACataloguedName_AndItsAnchorQuotesIt` fails when that text does not quote the name. `EC-FLOW-GLOBAL-EXIT`, this note's own example, is `§3:D-GLOBAL-EXIT` (CONFORMANCE.md line 170); a stale entry (declined but declared or raised) also fails |

The determination lives in CONFORMANCE.md with the test-project table pointing at it, not on the catalogue row itself (design D13
of `docs/CONDITIONS_EXCEPTIONS_DESIGN.md`): the catalogue is in the Runtime assembly, which carries no documentation
anchors, and the anchor text is the one a reader consults. The test reads both, so a blank cannot be mistaken for a hole. No
source change is owed. `cite.py --check 14.6.13.1.1` re-run: OK.
