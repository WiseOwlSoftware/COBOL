# PB5199 - at --std 85 OPEN ... REVERSED on a medium that cannot be positioned (a FIFO) is honoured instead of ignored, and every READ then fails with status 30: PositionReversed sets the backward direction whatever the medium

**Sites:**

- `src/WiseOwl.Cobol.Runtime/IO/FileRegistry.cs` (`ReversedPhraseEffect`)
- `src/WiseOwl.Cobol.Runtime/IO/SequentialConnector.cs` (`PositionReversed`, `ReadRecord`)

**Mechanism.** §1985:VII.4.3.4 GR10: "The NO REWIND and REVERSED phrases will be ignored if they do not apply to the storage medium on which the file resides." The NO REWIND half conforms. REVERSED is implemented for record sequential files (ReversedPhraseEffect, PositionReversed), which is right on a medium that can deliver records in reverse, but `PositionReversed` sets the backward direction on a medium that cannot be positioned too, so on a FIFO every READ fails with 30 and the USE procedure runs for a permanent error, where the rule ignores the phrase and reads forward. kb/Work PB668 (landed) chose the permanent error before the 1985 text was held.

Code sites read: src/WiseOwl.Cobol.Runtime/IO/FileRegistry.cs#NoRewindPhraseEffect; src/WiseOwl.Cobol.Runtime/IO/FileRegistry.cs#ReversedPhraseEffect; src/WiseOwl.Cobol.Runtime/IO/SequentialConnector.cs#PositionReversed; src/WiseOwl.Cobol.Runtime/IO/SequentialConnector.cs#ReadRecord; src/WiseOwl.Cobol.Runtime/IO/SequentialConnector.cs#SeekToOrdinal; src/WiseOwl.Cobol.Compiler/Binding/Validation/StatementValidation.cs#CheckOpenTapePhrase. Code read: §1985:VII.4.3.4 GR10: "The NO REWIND and REVERSED phrases will be ignored if they do not apply to the storage medium on which the file resides." The NO REWIND half conforms: every sequential file is on a non-reel/unit medium, FileRegistry.NoRewindPhraseEffect lets the OPEN run as a plain open and overlays I-O status 07 on a successful one (§1985:VII.1.3.5: "for an OPEN statement with the NO REWIND phrase, the referenced file is on a non-reel/unit medium"); probed at --std 85, OPEN INPUT and OPEN OUTPUT WITH NO REWIND position at the beginning, create or empty the file, and report 07 (a failed open keeps 35; an absent OPTIONAL input file reports 07 where the plain open reports 05). REVERSED is implemented, not ignored, for record sequential files (the 1985 arm: CheckOpenTapePhrase admits it, COBOL0902 from 2002; ReversedPhraseEffect and PositionReversed set the position past the last record and the backward direction), which is right where the medium can deliver records in reversed order (§1985:p.XVII-94 item 14; §1985:VII.4.3.4 GR12); probed on a regular file, fixed and RECORD VARYING, the records come last to first and then at end. The part that breaks the rule: on a medium that cannot be positioned the phrase is still honoured instead of ignored. PositionReversed sets the direction whatever the medium, and ReadRecord's backward arm answers a stream that SeekToOrdinal cannot position with the permanent error 30 (the member's own remarks say so). Observed with the pinned build on Linux against a FIFO: the plain OPEN INPUT and OPEN INPUT WITH NO REWIND read REC1 REC2 REC3 (status 00 and 07), and OPEN INPUT REVERSED returns 00 and then 30 on every READ with no record delivered. docs/CONFORMANCE.md states nothing about REVERSED or the media it applies to. The witness is the NO REWIND half on a disk file (OPEN OUTPUT and OPEN INPUT WITH NO REWIND, first record read back).

**Expected (from the 1985 text, the record's).** §1985:VII.4.3.4 GR10: "The NO REWIND and REVERSED phrases will be ignored if they do not apply to the storage medium on which the file resides." A FIFO cannot make records available in reversed order (§1985:p.XVII-94 item 14 makes the phrase "dependent upon a reel or mass storage type of device having the capability of making records available in the reversed order"), so the phrase is ignored and the program reads as the control without it does: OPEN 00, READ 00 REC1, READ 00 REC2, READ 00 REC3.

**Observed (the record's).** Pinned build, compiled at --std 85 --source-format fixed, run under WSL (Linux) against a FIFO holding REC1REC2REC3: "OPEN 00", then four times "USE 30" and "READ 30 ----" (no record delivered, the USE procedure runs for a permanent error). The control without REVERSED prints OPEN 00, READ 00 REC1, READ 00 REC2, READ 00 REC3; with WITH NO REWIND it prints OPEN 07 and the same three records. On a regular file REVERSED prints REC3, REC2, REC1, AT END 10. (On Windows a named pipe is refused at OPEN with 30 in every form, so the case is reachable on Linux only.) Log: E:/COBOL-coord/scratch/coderead-85/out/work-slice-31/p10/fifo.log.

**Fix direction (root cause, CLAUDE.md rule 4).** Ask the connector whether its medium can be positioned before applying REVERSED, and ignore the phrase when it cannot, in ReversedPhraseEffect, the one place the phrase's effect is decided.
