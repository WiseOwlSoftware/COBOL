# PB358 — a declared non-support with no witness

**Rows:** `SR-14.9.41.3-7`, `GR-14.9.41.4-15`, `GR-14.9.41.4-16`. (`GR-14.9.41.4-13` and `-17` are held at
PARTIAL by the same absence and are owned by **PB357** and **PB355**.)

⛔ **A correction to the batch input.** The start-statement-p2 finding directs these rows to be appended to
`kb/Work/PB144`, describing it as `status: open`. **PB144 is `status: landed`.** A landed note does not hold rows
for the `DefectiveRowCoverage` gate, so appending them there would have left them uncovered the moment the gate
ran. They get this note instead; PB144's body does record the same missing grammar, and a fixer should read it.

## Why there is no probe

That is the finding. `SELECT F ... RECORD KEY IS K-NAME SOURCE IS D-1 D-2` does not parse:
`CobolIO.g4` `recordKeyClause` (line 159) is `RECORD KEY? IS? dataReference` and `alternateKeyClause` (line 163)
is `ALTERNATE RECORD? KEY? IS? dataReference (WITH? DUPLICATES)? alternateKeySuppressWhen?` — neither carries the
SOURCE alternative. Consequently `START f KEY IS = record-key-name-1` can never be written, and
`KeyedIoBinder.BindStart`'s `ctx.Refs.Resolve(dref)` would in any case fail on a record-key-name, a distinct name
class (§8.4.6.2.4).

## The rules that name the operand

§12.4.5.12.2's general format is `RECORD KEY IS { data-name-1 | record-key-name-1 SOURCE IS { data-name-2 } ... }`
(`cite.py --check 12.4.5.12.2 "record-key-name-1 <u>SOURCE</u> IS"` → **OK**), with the identical alternative in
§12.4.5.6.2 for ALTERNATE RECORD KEY.

> §14.9.41.3 SR7: Record-key-name-1 shall be specified with the SOURCE phrase in the RECORD KEY clause or in the
> ALTERNATE RECORD KEY clause in the file control entry for file-name-1

`--check 14.9.41.3` → **OK**. Four of START's general rules name record-key-name-1 as a first-class operand
alternative: GR13 (its class decides whether the count is alphanumeric or national character positions), GR15
(the prime key may be spelled as one), GR16 (it becomes the key of reference) and GR17 b) (its length sizes the
temporary area).

## The disposition, and the half that is a defect

`docs/CONFORMANCE.md` §A.3 item 40 already declares *SOURCE phrase of RECORD KEY / ALTERNATE RECORD KEY ... Not
claimed — the `record-key-name SOURCE IS` key form is not provided*, and Annex A.3 item 40 makes the capability
processor-dependent, with §4.2.6 requiring the absence to be specified in user documentation. **So refusing the
source is CONFORMING and this is not a new owner decision.**

**What IS a defect is that the refusal is unwitnessed.** `out-b1/probe/sr7-source/prb.cob` draws
`COBOL0312: unexpected SOURCE. Unexpected token in FILE-CONTROL paragraph. Check SELECT/ASSIGN TO syntax. A
period may be missing at the end of the previous sentence.` — a generic parse failure whose remedial text points
the user at a missing period. There is no named diagnostic saying the SOURCE phrase is not provided, and a grep
over `tests/` finds **no fixture pinning the rejection**, so a future widening of `recordKeyClause` /
`alternateKeyClause` that swallowed SOURCE and IGNORED it would break nothing. This is an A.3
PROCESSOR-DEPENDENT element, not an A.4 optional module, so the declined-module witness notes (PB260, PB261,
PB281-PB283) do not cover it.

## For whoever lands the grammar

`IndexedConnector` models a key as ONE `(offset, length)` slice (`#KeyOf`, ~line 515), so a concatenated SOURCE
key needs a **multi-slice key model**, not just a parser change — and that model is also what §14.9.41.4 GR17 a)'s
plural *relevant parts* refers to (**PB355**).

**Code sites:** `CobolIO.g4#recordKeyClause` (line 159), `#alternateKeyClause` (line 163) ·
`IndexedConnector.cs#KeyOf` · `docs/CONFORMANCE.md` §A.3 item 40.
