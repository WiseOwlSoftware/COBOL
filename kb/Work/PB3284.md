# PB3284 — the runtime ABI pin conflicts by design when two branches each change the shipped runtime surface

`RuntimeAbiPinDriftTests` pins the runtime surface as a hand-copied digest of the whole `src/Cobol.Net.Runtime/PublicAPI.Shipped.txt` (plus the codec images) on one line, so ANY two branches that each change the shipped runtime surface conflict at landing, even when their Shipped-file edits merge cleanly, and neither side's value is right for the merged tree.

Source: landing finisher 5's "New defects (finisher 5)" paragraph, verbatim, in `E:\COBOL-coord\scratch\reports\w1091h-PB442-report.md` (the section after "## Finisher (5)").

- **The runtime ABI pin conflicts by design whenever two branches each change the shipped runtime surface.** `RuntimeAbiPinDriftTests.cs:48-49` holds `PinnedMajor` and `PinnedRuntimeHash` as two hand-edited constants on adjacent lines. The hash is a digest of the whole of `PublicAPI.Shipped.txt` plus the codec images, so any two branches that each edit the Shipped file (even independent lines that git merges cleanly) produce different hashes on the same line, and git can never merge them. Neither side's value is right for the merged tree: the only correct value is the hash of the merged surface, which exists only after the merge. Measured on this branch: 2 of its 5 landing stops (land-lane attempts 20261016T153501998428Z with PB651, and 20261016T175855567717Z with PB2758), each costing a finisher, a gate and a re-review. The other 3 were the PB3116 manifest hotspot. The rule that a hand finisher applies (the major is max(main, branch) when only one side crossed a boundary, and +1 over main when both did; then re-pin the printed hash) is mechanical, but the bump decision is not. A shape that removes the conflict keeps the decision and drops the hand-copied digest. Pin the major beside a COMMITTED record that a tool regenerates from the surface (for example, a `runtime-abi.lock` written by a `scripts/` regenerator that `enqueue.py` re-runs after merging main, like the PB3116 proposal for the manifests), or pin the surface by the Shipped file's content directly (the test diffs the Shipped file against a recorded per-major baseline, so a merge that unions two removals is a text merge). Code site: `tests/Cobol.Net.Tests.Unit/RuntimeAbiPinDriftTests.cs:45-51`, `#TheRuntimeMajor_IsPinnedBesideTheShippedSurfaceAndTheCodecImages`. Repro: any two branches off one base that each delete a different line of `src/Cobol.Net.Runtime/PublicAPI.Shipped.txt` and re-pin; merging the second into the first conflicts at line 49.

**Measurement.** 2 of worktree-wf_00451f9d-3d9-20's 5 landing stops on 2026-10-16: land-lane attempts 20261016T153501998428Z against PB651 and 20261016T175855567717Z against PB2758; each cost a finisher, a gate and a re-review.

**Candidate shapes.** (1) A tool-regenerated committed lock file that `enqueue.py` re-runs after merging main, like the PB3116 proposal. (2) A per-major recorded Shipped baseline the test diffs against. The bump DECISION (major) stays a human/agent judgment; only the digest is mechanical.
