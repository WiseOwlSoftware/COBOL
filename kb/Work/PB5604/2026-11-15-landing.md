Re-probe on the Debug build: `p2/cd_ptr_min.cob` and `p/cdptr.cob` both reproduced COBOL0899. Root cause: `CommunicationSectionBinder.BindEntry` linked every CD record, and the area, into one implicit redefinition class (`RedefinitionKind.ImplicitCommunicationRecord`) with no `FileModel.IsOutOfLineRecord` arm, the path an FD record takes (kb/Work PB981). A pointer-class record has no character image, so the class model rejected it.

Fix: `BindEntry` links only the records that have a character window (the first of them is the anchor, the area when none is). A pointer-class, dynamic-length or variable-length record stays out of the class. After the fix both probes compile and run (`CP SET`, `BX=WXYZ`); the golden `pb5604-output-cd-pointer-records` runs ALLOCATE, SET ADDRESS OF, SET TO ENTRY, CALL, INVOKE, SET object reference, RAISE and the two SET LOCALE formats through level-1 POINTER, PROGRAM-POINTER and OBJECT REFERENCE records under an output CD.
