# PB450 — SET's printed outer repetitions are missing from Formats 4 and 7

Lane-3 adjudication batch b2, group g7-set-a. **Every repro below was re-run on HEAD `89044aa0`**; all still
reproduce.

## 1. THE MECHANISM

Three of SET's printed formats put an **ellipsis outside a brace**. The grammar transcribed one of them and
not the other two, in the same file, eighteen lines apart.

    CobolParserCore.g4:1230   setSwitchStatement  : SET (dataReference+ TO (ON | OFF))+ ;     ← outer repeat PRESENT
    CobolParserCore.g4:1248   setBooleanStatement : SET dataReference+ TO (TRUE_ | FALSE_) ;  ← outer repeat ABSENT
    CobolParserCore.g4:1255   setAddressStatement : SET ADDRESS OF dataReference TO (dataReference | NULL_)
                                                  | SET dataReference TO ADDRESS OF dataReference ;

Formats 3 and 4 have the **same printed skeleton** — an outer brace around `{ name } … TO { keyword | keyword }`
with a trailing ellipsis on the outer brace. One transcription carries it, its twin does not.

Format 7 is worse than a missing repeat: it is **split into two fixed productions on the sender's spelling**
instead of on the format. The printed receiving operand is one brace, `{ ADDRESS OF data-name-1 | identifier-5 }`,
with the ellipsis **outside** it — so a Format-7 statement may carry any number of receivers, each independently
either spelling, mixed in any order, and identifier-6 may itself be a data-address-identifier. The two
productions cover two cells of that cross-product and hard-code arity one in both. The plural-`identifier-5`
case survives only **by accident**, through a different rule: `SET P1 P2 TO P0` is claimed by
`setToValueStatement` and re-routed semantically at `SetBinder.cs:345-346` into `BindSetPointer`, which does take
a target list. That accident is the tell — the arity is not a considered restriction.

Because these are **parse** failures, no syntax rule is ever asked about the operands: SR17 and SR18 are
unreachable on every shape the grammar cannot express.

### 3b. SR18's second half — the scope-blind name map (refuter, re-measured on HEAD)

↔ **This half is a DISTINCT mechanism and has its own note, [[PB467]]** (the resolver defect: a scoped question
answered from the flat unit-wide map, reaching `ALLOCATE`'s §14.9.3.3 SR1 through the same helper). PB450 keeps
the `SR-14.9.39.3-18` row because it owns the format-shape mechanism; PB467 claims no rows. **Fix them
together** — the summary below is what PB467 measures in full.

`PtrResolveBased` (`PtrBinder.cs:293-303`) reads `ctx.Data.ByName` **directly** instead of the scope-aware
`SymbolTable.TryResolve`, which consults `scope.Method.ByName` first. Measured on HEAD, probes from
`.../lane3/out-b2/probe/rf-set1/`:

    cobol s2_method_local_based.cob --std 2023 --run
      … error COBOLNET0869: 'MB': the operand shall be a BASED level-01/77 item (ISO §14.9.39 SR18 / …)
      — MB is declared `01 MB BASED` in the METHOD, i.e. exactly what SR18 requires. Wrong verdict.
    cobol s4_method_local_storage_based.cob --std 2023 --run
      … the same COBOLNET0869 on a method LOCAL-STORAGE `01 MB BASED`.
    cobol s3_method_shadow_nonbased.cob --std 2023 --run
      … NO SR18 diagnostic at all — a method-local NON-based `01 SHR` that legally shadows an object-level
        `01 SHR BASED` is accepted as based. The opposite wrong verdict, same map.

Both directions flip when the *same* declaration moves between the object's and the method's data division,
which is the proof that scope — not the declaration — is deciding. Every one of these programs also draws the
named residue `COBOLNET0899: BASED data or ADDRESS OF in a class definition's data divisions is recognized but
not yet implemented`, so SR18's whole domain inside class definitions is loud-unimplemented today.

| SR18's scope-blind lookup | `PtrBinder.cs:293-303` `PtrResolveBased` (`ctx.Data.ByName` … `list[0]`) |

⛔ **The repair is three productions and one lookup, not four more alternatives** (CLAUDE.md rule 5):

1. **One shape for Formats 3 and 4.** `SET (dataReference+ TO position)+` with a **single** group-splitting
   helper, replacing `SwitchBindSet`'s hand-written token-position re-assembly. A second hand-written
   re-assembler beside it is the thing to avoid; the FALSE arm ([[PB455]]) then gets its grouping for free.
2. **One production for Format 7.** `setAddressStatement : SET setAddressReceiver+ TO (dataReference | addressOf | NULL_)`
   with `setAddressReceiver : ADDRESS OF dataReference | dataReference`, bound to a **receiver list whose
   elements carry their own kind**. GR12 and GR13 then become one loop over one list, exactly as the standard
   writes them, and the next receiver spelling is automatic.
3. **SR18 resolves through the SymbolTable**, not `ctx.Data.ByName`. The class doc-comment at `PtrBinder.cs:22`
   already flags the bypass as a "documented SymbolTable bypass … a flagged behavior-sensitive follow-up"; the
   measurement in §3b is that follow-up coming due.

  whole domain, and (iii) SR18 never being asked about the second and later `ADDRESS OF data-name-1` operands.
