# PB4713 — USE FOR DEBUGGING ON a cd-name reported undeclared (DB205A)

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/ProcedureTableBuilder.cs:631` (`ProcedureTableBuilder.FinalizeDebug`)

**Sites (landed):** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/ProcedureTableBuilder.cs` (`ProcedureTableBuilder.FinalizeDebug`, the bare-name arm; `ProcedureTableBuilder.NamesCommunicationDescription`, new), `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.NonDataNames.cs` (`NonDataDeclarationKind.CdName`, `NonDataDeclaration.DeclaredAs`, `NonDataDeclaration.ClassPhrase`, `DataBinder.NonConditionDeclarationsOf`), `tests/WiseOwl.Cobol.Tests.Conformance/DebugFacilityTests.cs` (`CdOperandProgram`, `BareOperandNamingACdName_At85_IsTheStagedCdNameSubject`, `AllOperandNamingACdName_At85_IsDeclaredAsACdName`).

**Landed (wave 20261872 E):** the bare `USE FOR DEBUGGING ON cd-name` operand is the staged COBOL1571 (the program is right, the cd-name trigger is not modeled) and no longer COBOL1639 "not defined"; DB205A draws COBOL1571 for CM-INQUE and CM-OUTQUE. R1-6's sibling is fixed at its root: the one non-data-name query (`NonDataDeclarationOf`) did not know a cd-name, so `ALL CM-IN` and `MOVE CM-IN TO T` also said "not defined"; they now say "declared as a cd-name (a communication description entry), not as a data item" (COBOL1639). Witnesses: `conformance:cases/_unassigned/pb4713-debug-cd-name`, `pb4713-debug-all-cd-name`, `pb4713-move-cd-name`. What stays: the cd-name, file-name and data-name debug TRIGGERS are not modeled (the staged posture of `docs/CONFORMANCE.md` D-DEBUG-USE), so DB205A is still refused, now truthfully.

The site exists on main and, with the communication facility, on open PR #1161 (branch `worktree-wf_d99db659-fdf-22`); the line is read from that worktree. Copied from the PB4677 report (wave 20261869 b), lead 1, with R1-6 correcting the predecessor's lead:

`FinalizeDebug` takes `ReportUnresolvedDebugOperand` for a declared cd-name, because its test asks only `NamesDataItem` and `NamesFile`, and X3.23-1985's debug module triggers on ENABLE, DISABLE, PURGE, RECEIVE and SEND of a cd-name, which now exist. Same mechanism as the file and data triggers of the DB module; outside the PB4677 group.

Repro: `cobol --nist DB205A tests/nist/programs/DB205A.cob` gives `error COBOL1639: 'CM-INQUE' is not defined`.

R1-6 (low), copied: a declared cd-name is reported as undeclared: `USE FOR DEBUGGING ON cd-name` takes `ReportUnresolvedDebugOperand`, so the staged message that names a cd-name (`DebugSubFacilityStaged`) is unreachable for one. The PB4677 report says this site answers `DebugSubFacilityStaged`, which it does not. `MOVE CIN TO X` has the same not-defined text from the reference resolver.
