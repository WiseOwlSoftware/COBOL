# PB3144 — a changed snapshot does not raise its own case into leg 1

> flags: process-only

Source: `E:\COBOL-coord\scratch\reports\w1072c-PB2690-report.md`, "## Finisher", bullet "Lead (note-ready, process)".

**What was seen.** Branch `worktree-wf_dfc118ad-872-19` raised `Directory.Build.props` `<Version>` from 2.0.0 to 3.0.0. Every emitted module records the runtime version (`src/Cobol.Net.Compiler/CodeGen/Roslyn/RuntimeApi.cs:2203-2205`, the `CobolRepositoryAttribute` text and the registrar), so 14 committed snapshots under `tests/Cobol.Net.Tests.Characterization/Snapshots/*.txt` went stale. The Windows leg-1 gate ran 6 of 36 Characterization cases: with no impact map all 36 are tier 1, and the snapshot cases fell past the leg-1 budget into leg 2. Neither the stale snapshots nor their fix were verified locally; the landing's Linux gate caught it (exit 5).

**Mechanism.** A changed `Snapshots/*.txt` file does not raise its own `EmittedCSharpSnapshotTests.EmittedCSharp_MatchesSnapshot` case to tier 0a the way a changed corpus golden does (tier 0a's definition is near the top of `scripts/gate_plan.py`), and a runtime `<Version>` bump, which changes every snapshot, raises none of them either. Same shape as PB3131: a test's data input is not part of its impact edge.

**Repro.** `TestResults/build-local/20261014T044102Z-546226/plan.json` in `E:\COBOL\.claude\worktrees\wf_dfc118ad-872-19` (Characterization tiers `{"1": 36}`, leg 1 has no snapshot case).

**Fix direction.** Treat a snapshot file as the case's golden for tier 0a (derive the case from the file name, no hand list), and treat a `<Version>` change as touching every snapshot case. Add a drift test that every `Snapshots/*.txt` maps to a case. Related, distinct: PB2835 (tier 0a misses a corpus case name over 50 characters), PB3112 (the tier-0c cost cap), PB3131.

**Third recurrence (2026-10-16).** The runtime 4.0.0 -> 5.0.0 bump on `worktree-wf_f560587e-74d-18` (PB651) stopped the landing's Linux gate on 348b0926c the same way: 14 of 36 snapshot cases red, the leg-1 gate having run 6 of 36 (run `20261016T122458Z-b6a869`). The finisher re-recorded them. The diff is the two version lines per snapshot.
