# PB3770 — the build guard reads rolling-wave implementers as main-tree agents

**Sites:** `scripts/hooks/fleet_active_build.py:242` (`place_of`), `:259` (`launch_cwd`), `:286` (`agent_place`), `:297` (`collides`), `:309` (`project_refs`), `:376` (`build_places`), `:455` (`agents_sharing_any`), `:567` (`_build_fixture`), `:642` (`self_test`); the deleted `main_repo_root`, `agent_id_of`, `agent_working_tree` and `agents_sharing_tree`; `docs/rearchitecture/DESIGN-test-build-ci.md` (section 1.7).

## What happens

The Mythos lane reported (mailbox 20261025-135010) that its PB3631 adjudicator, read-only with its probe in `E:/COBOL-coord/scratch/mythos/adj-20261025/PB3631/probe`, was refused a probe build at about 19:20Z ("denies the build while sibling adjudicators are live") and waited about 90 minutes for a window that never came. `agent_working_tree` maps a foreign agent to `<main>/.claude/worktrees/agent-<agentId>` when that exists, else to the MAIN checkout. Rolling-wave implementers work in `.claude/worktrees/wf_<run>-<n>` (git worktree add, not `Agent(isolation="worktree")`), so every live implementer of either lane reads as a main-tree agent, and a scratch build (an UNKNOWN tree) is denied while any runs, which with two lanes is all day.

## Fix direction

Decide an agent's tree by construction for BOTH worktree shapes (`agent-<id>` and the rolling wave's `wf_<run>-<n>`, which the wave records in its journal and the dispatch ledger), and let a build in a tree no live agent works in (a scratch probe) proceed. Self-tests: a live wf_* implementer does not block a scratch build; an agent that really works in the main checkout still does.

## Landed (2026-10-25, fix-lane wave 20261703 group C)

**Re-probe (this build, the real adjudicator probe and this session's real transcripts).** `agents_sharing_any` over the
probe directory `E:/COBOL-coord/scratch/mythos/adj-20261025/PB3631/probe` and a live wave implementer's transcript
(`wf_3fef8479-1cf/agent-a0b2a6039fad90dd2.jsonl`, launched in `.claude/worktrees/wf_3fef8479-1cf-3`) returned 1 sharing agent:
the note's symptom. Two defects, not one. (1) The scratch directory is in no working tree (`E:/COBOL-coord` has no `.git`),
the deliberate UNKNOWN arm, so every foreign agent denied. (2) `agent_working_tree` read the implementer as a main-checkout
agent (no `agent-<id>` directory), so a build in its OWN worktree saw 0 sharing agents and a build in `E:/COBOL` saw it.

**Root.** The agent-to-tree map was inferred from a directory naming convention (`agent-<id>` exists or not), one of the
host's several ways to start an agent, and the scratch arm answered UNKNOWN for a project whose graph is readable.
**Fix.** (1) A foreign agent's tree is the tree of the directory it was launched in, read from the `cwd` of the first
record of its own transcript (`launch_cwd`, `agent_place`): one mechanism for `agent-<id>`, `wf_<run>-<n>`, a named
worktree and the main checkout; an unreadable transcript or a removed directory is UNKNOWN (denies). `main_repo_root`,
`agent_id_of`, `agent_working_tree` and `agents_sharing_tree` are deleted (the `.git` file parse existed only to find the
main checkout for the `agent-<id>` path). (2) A build outside every tree writes where its project graph says
(`build_places`): the project or solution named, or the only one in the directory, and the closure of its
`ProjectReference`s, solution members and `#:project` directives; a reference into a worktree makes that worktree a place
(PB2599's evidence: a scratch probe referencing `perf-gate`'s project). A graph the guard cannot read to the end stays
UNKNOWN: a missing project, `$(…)`, `<Import>`, an output-path property, a `Directory.Build.*` file above it.
**Sweep.** No other hook infers an agent's tree (`grep` of scripts/ for `worktrees/agent`, `subagents`: only this file);
`--self-test` grew from 62 to 94 cases over real temp trees, scratch projects and transcripts, and six mutations of the
new code (trees never collide, an unknown agent allowed, references ignored, `<Import>` allowed, `Directory.Build` ignored,
a tree's own graph walked) each fail it. End to end, the real hook now allows the probe build with this session's live
fleet. The `Place`-to-`Place` comparison is the one rule; the in-tree arm still does not read a graph (a tree project
referencing another tree is unchanged, and not a regression).
