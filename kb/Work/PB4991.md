# PB4991 - rule lineage across editions

**The owner, 2026-11-08**, asked which model 1985 conformance should use (separate 1985 rows, or the conformance suite's
banded single inventory): "I think we need separate lists for each versions rules. 1985 sets the original aka base set
of them. Then 2002 can do one of three things for each 1985 rule: it inherits or keeps a 1985 rule. Basically that rule
applies to 2002. In effect it is a 2002 rule. It can deprecate a 1985 rule, implying it will be removed in the future.
It can remove a 1985 rule. Eg that syntax is no longer valid. And it can define new to 2002 syntax. And similarly for
later versions. We need a mechanism to efficiently and maintainably support syntax and semantics changes over multiple
versions. How best to do that?" The design below was proposed and **approved** ("Approve") the same day, and the owner
added: "This also may provide a way for a compilation error to accurately describe the edition + rule violated" (PB4950).

**The design** is docs/rearchitecture/DESIGN-spec-conformance-review.md §10.2:
- one rule list (catalog and inventory store) per edition, from its own text;
- a `next` change record on each older row, to the next HELD edition only: KEPT, CHANGED or REMOVED, with the citation
  in each text; NEW derived; obsolete and archaic a per-edition `status`, so deprecation is KEPT-into-obsolete, then
  REMOVED;
- a verdict held once per KEPT chain, on its newest row; older rows reference it;
- derived: per-edition GAP and conformance statement, the conformance suite's bands, the edition-gate drift test, and
  each diagnostic's citation at each edition;
- until 2002 and 2014 are transcribed, 1985's `next` bridges to 2023, and composing the adjacent records later must
  reproduce the bridge.

**What it replaces.** The plan of 1985 rows in the one 2023 store carrying a 2023 verdict by reference (the earlier
§10.2), and the conformance suite design's decision 10 ("The 1985 text will not be obtained"): the 1985 text is held
(PB4850), so a 1985 edge's evidence is the 1985 text, and bands are a view of the chains
(DESIGN-conformance-suite.md, amended).

**The slices:** PB4992 (the store takes the edition; the 1985 rows), PB4993 (the `next` and `status` schema and its
recording path; the audit's upheld SAME answers recorded as KEPT), PB4994 (chain state and the per-edition GAP),
PB4995 (the fleet adjudication of the disputed and own-row rules), PB4996 (derived bands and the edition-gate drift
test), PB4997 (the 1985 conformance statement, with PB4885). PB4950 waits on PB4995.
