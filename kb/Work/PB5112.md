# PB5112 - the codebase is Claude's; the delegation rules are removed

**Owner (2026-11-10), in order:** "The entire wise owl cobol code base is yours. What it's for and how it's built are your
call; and you'll continue to build upon it." "This ownership of your extends to reorganization of the existing code base."
"Also clean up Claude.md of no longer useful constraints. Remove all prior sub agent delegation rules. You are smart enough
to figure out on your own when and how to use them. You decide when to delegate."

**Sites:** `CLAUDE.md` (whole), `scripts/hooks/dispatch_guard.py` (rules 1 and 2), `scripts/hooks/test_dispatch_guard.py`
(whole), `.claude/skills/workstream/templates/MANDATORY-PRACTICES.md` (the rows that mandate when and how to dispatch),
`.claude/skills/workstream/check_practices.py` (the checks that hold those rows), the SessionStart hook's SKILLS text, and
`PROMPT.md` where it restates either.

**Done in this change (CLAUDE.md).** A new Ownership section states the delegation and what stays the owner's (money and
quota beyond the plan in force, accounts, anything sent outside, publishing, deleting history others use). Rule 9 (no
dispatch without the `workstream` skill) is deleted; its second half, an agent fixes what it finds, is folded into rule 4,
where it belongs. Rules 1 to 8 keep their numbers, since some sixty places cite them. Removed as no longer true: the
transitional sentence about bare citations before PB4887 landed, "only an explicit owner decision" in rule 3 (a recorded
decision note now), the per-rule owner datelines, the instruction to load a lane's skills before any dispatch. Added, each
earned on 2026-11-09: subagents are used on judgment; do not redo work whose inputs did not change (PB5099, PB5100, PB5110).

**Claude's standing choices under the delegation.** The mission stays (ISO/IEC 1989:2023 conformance with correct
1985/2002/2014, typed-native C#, no byte substrate). The spec stays the oracle. Rules 1 to 8 stay.

**Owed (tooling, a second change).** The structural half of rule 9 still stands in code and must go with it, or the rule
is only renamed: `dispatch_guard.py` refuses a Workflow or an implementer/finisher Agent call unless the `workstream`
skill was loaded and the brief is a rendered, checked spec (its rules 1 and 2). Delete both rules and their tests; keep its
rule 0 (a loop unit launches no fleet after the supervisor's STOP-UNIT), which is the loop's own wind-down, not a rule
about delegating. Then reduce MANDATORY-PRACTICES and `check_practices.py` to what the orchestrator loop's own machinery
needs to run (the spec renderer, the ledger, the graceful stop), with every "must dispatch through" row gone, and the
SessionStart SKILLS text to the session-start skill alone. The loop keeps working throughout: it is a tool Claude may use.
