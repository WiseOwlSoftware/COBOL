# PB3922 — boolean-class-condition-not-supported--boolean-held-as-number: 'COMPUTE R = B-NOT A' over PIC 1 items compiles without a diagnostic and gives a wrong value (B"1100" is held as integer 12)

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S8) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\boolean-class-condition-not-supported--boolean-held-as-number.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\boolean-class-condition-not-supported--boolean-held-as-number\`.

## Summary

GnuCOBOL 3.2 compiles `COMPUTE R = B-NOT A` for boolean items `A` and `R` (PICTURE 1(4), usage display) without a
diagnostic, and at run time R does not hold the negation: with A = B"1100", R compares unequal to B"0011". cobc builds
the boolean literal B"1100" as the integer 12, holds the PICTURE 1 item as a number (DISPLAY of A prints `0012`), and
evaluates B-NOT as an integer bit-wise complement. Boolean items and the B-NOT operator are part of ISO/IEC 1989 since
2002 and in the 2014 edition that `-std=cobol2014` claims. Class: wrong output, silent. This is one of the mechanisms
filed together as boolean-class-condition-not-supported (witness fz04838, whose `NOT0`/`NOT1` lines are B-NOT over
PIC 1 items; that program stops first on the B-AND refusal recorded as
boolean-class-condition-not-supported--boolean-compute).

## Minimal test case

Free reference format (`-fformat=free`), 10 lines, written for this record. File:
`E:\COBOL-coord\scratch\op\pb3838\records\boolean-class-condition-not-supported--boolean-held-as-number.cob`. The
result is tested with a boolean relation rather than DISPLAY, because DISPLAY's conversion to the device is
implementor-defined (§14.9.11.4 1)).

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. BNOT3.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 A PIC 1(4) VALUE B"1100".
01 R PIC 1(4).
PROCEDURE DIVISION.
COMPUTE R = B-NOT A
IF R = B"0011" DISPLAY "OK" ELSE DISPLAY "WRONG" END-IF
STOP RUN.
```

## Environment

- `cobc (GnuCOBOL) 3.2.0`, Ubuntu package `gnucobol3 3.2-4build1`, WSL2 (Linux 6.18.54.1-microsoft-standard-WSL2
  x86_64), C compiler gcc 15.2.0 (Ubuntu 15.2.0-16ubuntu1).
- Commands:
  ```
  cobc -std=cobol2014 -fformat=free -x bnot3.cob
  ./bnot3
  ```

## Observed result

Compile exit code 0. The only messages are the C compiler's `<command-line>: warning: '_FORTIFY_SOURCE' redefined`
and its note, which come from the distribution's build flags and not from the COBOL source. Run exit code 0, output:

```
WRONG
```

The default dialect (`cobc -fformat=free -x bnot3.cob`) gives the same. A variant that displays the items
(`DISPLAY A` before the COMPUTE, `DISPLAY R` after it, and a second COMPUTE over an item with VALUE B"0000") prints
`0012`, `1603` and `1615`: A holds the integer 12, and B-NOT of 12 and of 0 give numbers, not four boolean positions.

## Expected result (per ISO)

The program is legal and prints `OK`.

- ISO/IEC 1989:2023 §14.9.8.2 (checked), format 2 `COMPUTE { identifier-2 } … = boolean-expression-1`; §14.9.8.3 2)
  (checked): "Identifier-2 shall reference an elementary boolean data item."
- §8.8.2 (checked): a boolean expression may be "a boolean expression preceded by a unary boolean operator"; §8.7.2
  (checked) lists B-NOT as the "Negation operation" (the transcription prints the operator as "-NOT").
- §8.8.2 10) (checked): "The result of the evaluation of each boolean operation shall be a boolean value whose length
  shall be the number of boolean positions of the larger item referenced in that operation." Four positions.
- §D.10 (informative, checked), Table "Examples of boolean operations": "| Negation | | B-NOT | 1100 | 0011 |".
- §8.8.4.2.8 (checked): "Comparison of operands of class boolean is a comparison of their boolean value, regardless of
  their usage." R holds 0011, so `R = B"0011"` is true.

Edition: a 2002 feature, present in 2014 (boolean data, boolean literals and B-NOT are in the ISO/IEC 1989:2002 text
and in the 2009 committee draft that became ISO/IEC 1989:2014; Annex E of the 2023 standard adds only the B-SHIFT
operators).

Edition as recorded by the adjudicator: 2014 (introduced 2002). `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Class

GNUCOBOL-DEFECT, wrong output (edition 2014; introduced 2002). The program compiles under the strict `-std` with no
diagnostic and computes a value that is not a boolean result. If boolean items are not implemented, cobc should
refuse them rather than compile them as integers.

## Our compiler (WiseOwl)

WiseOwl COBOL (built from main 6ed90bd1c), `cobol bnot3.cob --std 2014 --source-format free -o bnot3.dll`, then
`dotnet bnot3.dll`: compile exit 0, run exit 0, output `OK`. On the display variant WiseOwl prints `0011` for
`DISPLAY R`.

## Fix site (GnuCOBOL 3.2 source, read observationally)

- `cobc/scanner.l`, `scan_b` (line 1844): a boolean literal is built with `cb_build_numeric_literal` from the integer
  value of its bits; the source carries "FIXME: we should likely build a boolean literal" (line 1930) and notes that
  only 64 boolean characters are supported.
- `cobc/tree.c`, `cb_build_binary_op` (line 5798), `case 'n'` (line 5979): B-NOT is given category numeric, with no
  check of the operand's category; `cobc/typeck.c` (the `'n'` arms, lines 668 and 764, "BIT-WISE NOT") and
  `cobc/codegen.c` (line 2851) generate an integer complement.
- A PICTURE 1 item of usage display is held as a numeric field (DISPLAY of A gives `0012`), so the fix needs a boolean
  storage form (one character '0' or '1' per boolean position for usage display) and boolean evaluation of B-NOT,
  B-AND, B-OR and B-XOR.
