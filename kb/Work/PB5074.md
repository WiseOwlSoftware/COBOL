# PB5074 - at --std 85 operands the 1985 text requires to be integers accept non-integers and negatives (subscripts, DISPLAY literal, SET UP BY and TO, STOP literal), and STOP SPACE displays the word SPACE

**Sites:** `src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs#IsCobol85Subscript`, `src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs#VisitSubscriptPart`, `src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs#VisitDisplayStatement`; `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/SetBinder.cs#BindSetUpDown` and `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/SetBinder.cs#BindSetTo`; `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/ControlFlowBinder.cs#BindStop`; SubscriptBinder is named by one record without a member.

**Mechanism.** The 1985 rules ask for an integer (a numeric literal with no digit position right of the decimal point, or a numeric data item with none; Section III Integer): a subscript data-name and integer-1 (positive), DISPLAY's numeric literal (unsigned integer), SET's UP BY / DOWN BY item and TO operand (integer-1 positive), STOP's literal (not an ALL figurative constant, unsigned integer). Each binder either gates only the SHAPE of the operand (IsCobol85Subscript passes any numeric literal) or binds the later editions' arithmetic-expression, so the integer and sign tests are never applied. A second defect at the STOP site is a wrong answer for legal source: STOP SPACE and STOP ZERO display the words SPACE and ZERO where 1985 communicates the figurative constant's value (records 1985-SR-VI.6.24.3-1).

**Found by.** The 1985 `--std=85` draft triage (kb/Work PB4995 item 3): each rule below is a conformance-suite draft that did not MATCH at `--std 85`, and its adjudicator decided COMPILER-DEFECT. Harm and observed text are the records'; nothing here was re-derived.

**Inventory.** The traceability inventory carries no 1985 rows yet, so `inventory_rows` is empty; the rows this note covers are the 1985 rule ids listed below (catalog `docs/rearchitecture/spec-rule-catalog-1985.json`).

**Rules (7; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-SR-IV.4.3.8.2.3-5` - `§1985:IV.4.3.8.2.3 SR5` (record harm: under-rejects, slice-02): §1985:IV.4.3.8.2.3 SR5: "Data-name-2 may be qualified and must be a numeric elementary item representing an integer." §1985:III.2 defines the term: "Integer. (1) A numeric literal that does not include any digit positions to the right of the decimal point. (2) A numeric data item defined in the Data Division that does not include any digit positions to the right of the decimal point." The rule has two halves. The draft tests the first (an alphanumeric item, `01 IDX PIC X`, used as a subscript) and the compiler refuses it, at the references (lines 11 and 12) and not at the item's description (line 8) the draft marks; with one reference and the mark on it, that draft MATCHES (control: a PIC 9 subscript compiles, runs, displays 'A'). The second half is not enforced: a numeric elementary item with a digit position to the right of the decimal point (`PIC 9V9`) is not an integer by the definition, so `ELT (IDX)` violates SR5, and the compiler accepts it. The repro is that corrected draft: violating line 12 (`MOVE "A" TO ELT (IDX).`), control the same program with line 8 `01  IDX PIC 9 VALUE 1.`
- `1985-SR-IV.4.3.8.2.3-6` - `§1985:IV.4.3.8.2.3 SR6` (record harm: under-rejects, slice-02): §1985:IV.4.3.8.2.3 SR6: "Integer-1 may be signed and, if signed, it must be positive." In `MOVE "ABC" TO ELEM (-1).` the subscript is integer-1 of the format in §1985:IV.4.3.8.2.2, it is signed, and it is not positive, so the statement violates the syntax rule and the draft is right to expect a refusal at line 9. Its control, `ELEM (+1)`, is the signed positive form the rule allows.
- `1985-SR-VI.6.10.3-2` - `§1985:VI.6.10.3 SR2` (record harm: under-rejects, slice-04): §1985:VI.6.10.3 SR2: "If literal-1 is numeric, then it must be an unsigned integer." The literal 1.5 is numeric and is not an integer, so the DISPLAY statement of line 5 breaks the rule; the draft reads the rule correctly and its control (DISPLAY 15) compiles and displays 15.
- `1985-SR-VI.6.23.3-3` - `§1985:VI.6.23.3 SR3` (record harm: under-rejects, slice-05): §1985:VI.6.23.3 SR3: "Identifier-3 must reference an elementary numeric integer." An integer data item is (§1985:III.2, Integer, item 2) "A numeric data item defined in the Data Division that does not include any digit positions to the right of the decimal point." N is PIC 9V9, so `SET IX UP BY N` breaks SR3. A program that breaks the rule is not a conforming source program (§1985:I.1.6: "A conforming source program is one which does not violate the explicitly stated provisions and specifications of Standard COBOL."). The draft is right.
- `1985-SR-VI.6.23.3-4` - `§1985:VI.6.23.3 SR4` (record harm: under-rejects, slice-05): §1985:VI.6.23.3 SR4: "Integer-1 and integer-2 may be signed. Integer-1 must be positive." Integer-1 is the TO operand of Format 1 (§1985:VI.6.23.2), and §1985:III.2 (Integer) adds: "Where the term 'integer' appears in the general formats, integer must be a numeric literal which is an integer, and it must be neither signed nor zero unless explicitly allowed by the rules for that format." SR4 allows the sign and requires a positive value, so `SET IX TO -1` breaks it (and so does `SET IX TO 0`: zero is nowhere allowed and is not positive). A program that breaks the rule is not a conforming source program (§1985:I.1.6: "A conforming source program is one which does not violate the explicitly stated provisions and specifications of Standard COBOL."). The draft is right.
- `1985-SR-VI.6.24.3-1` - `§1985:VI.6.24.3 SR1` (record harm: under-rejects, slice-05): §1985:VI.6.24.3 SR1: "Literal-1 must not be a figurative constant that begins with the word ALL." `ALL "A"` is such a figurative constant (§1985:IV.4.2.2.2.3, item 6: "ALL literal Represents all or part of the string generated by successive concatenations of the characters comprising the literal."), so `STOP ALL "A"` breaks SR1. A program that breaks the rule is not a conforming source program (§1985:I.1.6: "A conforming source program is one which does not violate the explicitly stated provisions and specifications of Standard COBOL."). The draft is right.
- `1985-SR-VI.6.24.3-3` - `§1985:VI.6.24.3 SR3` (record harm: under-rejects, slice-05): §1985:VI.6.24.3 SR3: "If literal-1 is numeric, then it must be an unsigned integer." 1.5 is a numeric literal with a digit position to the right of the decimal point, so it is no integer (§1985:III.2, Integer, item 1: "A numeric literal that does not include any digit positions to the right of the decimal point."), and `STOP 1.5` breaks SR3. A program that breaks the rule is not a conforming source program (§1985:I.1.6: "A conforming source program is one which does not violate the explicitly stated provisions and specifications of Standard COBOL."). The draft is right.
