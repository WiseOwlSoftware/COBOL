## Landed

Re-probed on the Debug build: the note's container (R1 local `X`, R2 GLOBAL `X`) with `SET P TO ADDRESS OF X` in the contained program drew COBOLNET0869 "an OCCURS-resident anchor"; with the records swapped it compiled and displayed GLOB (the note). The BY REFERENCE twin compiled but resolved no head (two candidates), so the global record never got its cell by that claim.

**Fix.** `PtrResolveAddressOfTarget` and `ResolveByReferenceOperand` were two copies of one head resolution that differed only in how they pick among several candidates; they are now `DataBinder.ResolveStorageClaimHead(name, quals, method, contained, firstOfSeveral)`. A CONTAINED head is resolved among the unit's GLOBAL names alone (`CallGlobalRoots`), counted: a container-local record that shares a name with a GLOBAL one is not a candidate (13.18.27.4 GR2; 8.4.6.2.1). The ADDRESS OF arm keeps its historical first-of-several pick (`firstOfSeveral: true`, the permissive reading the SET bind takes), the BY REFERENCE arm still never guesses. `PtrBinder.PtrBindAddressOf`'s fallback reason no longer says "an OCCURS-resident anchor" (a root is never OCCURS-resident); it names the storage tier the record was left in. `StorageClaimHeadDriftTests` pins the one resolver and the global filter.

Goldens (13.18.27-GLOBAL, accepted 2002-2023; below 2002 GLOBAL itself is the version matrix's refusal): `pb3286-contained-address-of-global-beside-local` (LOCL, GLOB), `pb3286-contained-address-of-global-first` (GLOB, the other declaration order), `pb3286-contained-by-reference-global-beside-local` (SUB!, the callee sees the GLOBAL record change before it returns).
