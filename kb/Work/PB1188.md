## Finding — `terminate-statement` (silent; rows `GR-14.9.46.4-5`)

**Mechanism.** The report engine has no raise site for any NONFATAL report exception (EC-REPORT-PAGE-LIMIT, EC-REPORT-LINE-OVERLAP, EC-REPORT-PAGE-WIDTH, EC-REPORT-COLUMN-OVERLAP), so the TERMINATE continuation rule for a nonfatal exception has no path to act on

**Repro.** >>TURN EC-REPORT-PAGE-LIMIT CHECKING ON; RD R-1 PAGE LIMIT 5 LINES with a TYPE RF group of 8 lines; USE AFTER EXCEPTION CONDITION EC-REPORT-PAGE-LIMIT declarative that DISPLAYs; INITIATE; GENERATE; TERMINATE. (reasoned from source: grep of src/ for the four names finds only ExceptionCatalog.cs entries)

**Expected from the spec.** §13.18.35.4 GR2: a report group that cannot be printed on one page raises EC-REPORT-PAGE-LIMIT; §14.9.46.4 GR5: after a nonfatal exception during TERMINATE, execution resumes at the next report item, line or report group in logical order — the declarative runs, then the rest of the TERMINATE's groups are produced.

**Observed / reasoning.** ReportWriter.cs raises only FlowReportError, ReportActiveError, ReportInactiveError and ReportFileModeError (all Fatal). The nonfatal names are catalogued in ExceptionCatalog.cs (lines ~197-204) with no raise site; PB326 (landed) lists them as residual geometry seams with no open owning note. The declarative never runs and no resumption semantics exist.

**Code site.** src/Cobol.Net.Runtime/IO/ReportWriter.cs (PresentBody / PresentHeadingFooting / PresentPageFooting — no nonfatal raise); src/Cobol.Net.Runtime/Exceptions/ExceptionCatalog.cs (the unraised Nonfatal EC-REPORT-* names)

## What the fixer owes

Give ReportWriter (PresentBody / PresentHeadingFooting / PresentPageFooting) raise sites for the four nonfatal names with resumption per GR5, bound PRECISELY like the fatal EC-REPORT-* family in EcBinder; PB326 (landed) listed them as residual geometry seams with no owner — this note owns them. Sweep GENERATE's nonfatal twin rule.
