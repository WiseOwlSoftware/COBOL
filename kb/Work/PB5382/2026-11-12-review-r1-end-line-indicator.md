**Review finding R1-1 (wave 20262012, fixed).** `ApplyReplacements` decided the indicator of the text after a whole-replacement match from the line the match BEGINS on, so a multi-line match that crossed between a debugging line and a source line gave the rest of its end line the wrong indicator (a source-line `DISPLAY "S1".` swallowed into a debugging line; a debugging line's `DISPLAY "D1"` run as source). Section 1985:XII.3.4 GR11 decides only the INTRODUCED lines, so the text after the replaced text keeps the indicator of the line the match ENDS on. The fix reads that line (`endLineDebugging`, from `firstLineIsDebugging` for a slice's first line), compares it with the line the replacement ends on (`resultEndsDebugging`), and starts a line of its own for the rest whenever they differ, writing the carrier when the end line is a debugging line.
