## What happened

2026-11-11T04:27Z. The owner pasted the usage panel: weekly 56 % used, Fable row 67 %. At the same minute
`python scripts/orchestrator/budget.py` printed

    account1: weekly ≈ 70.73 % of an allowance of 42.9 % (day 3) … → hold-day until 2026-11-11T10:05:00+00:00
    (no account1 meter reading this week: estimate from telemetry alone)

and `--json` carried `"anchor": null`. Yet `~/.claude/rate-limits.json` held this session's reading, `seven_day
used_percentage 55`, `measured_at 2026-11-11T03:43:46Z`, in a file the status line had rewritten at 04:27Z.

## Cause

`budget.live_reading` returns None when `now - measured_at > LIVE_MAX_AGE` (30 minutes). `measured_at` is when the
figure last CHANGED (review R1-1 of PB4505: an idle session repeats old figures). The meter reads in whole percents, so
a figure that stands for 44 minutes is ordinary. The reading is then discarded outright, where a reading in
readings.json of the same age would still anchor the estimate with the telemetry spent since added on. With no anchor
the estimate is telemetry alone, which this week is 15 points high (the owner's mid-week reset refunded quota that
telemetry cannot see). The wrong figure tells a loop to hold the day.

## What is owed

**Sites:** `scripts/orchestrator/budget.py` (`live_reading`, `current`, `estimate`)

A status-line reading measured this week ANCHORS the estimate at its `measured_at` whatever its age, exactly as a
recorded reading does, and the telemetry spent after it is added. `LIVE_MAX_AGE` then has no job and is deleted. The
output names the anchor's age. A self-test arm: a reading 44 minutes old with no telemetry after it yields its own figure
and a non-null anchor. Check the Fable row the same way (the panel's 67 % has no counterpart in the output above).
