# PB3168 — continuation line area A is not screened at --std 85

Source: `E:\COBOL-coord\scratch\reports\w1078f-PB3147-report.md` (residual of PB3147, same root; PB3147 is held by an in-flight branch, so this is a separate note).

- Repro: `E:/COBOL-coord/scratch/w1078f/probe/pc.cob` (continuation quote at column 11) compiles. Under-rejects at `--std` 85 only. GnuCOBOL 3.2 accepts it too.
- Code site: `ReferenceFormatProcessor.LogicalLineBuilder.cs`, the continuation arm.
- Needs the X3.23-1985 text to adjudicate (see memory reference_historical_spec_revisions); the ISO 2023 text does not carry this rule.

## Landing (w1085f, 2026-10-15)

**Re-probed** on the worktree build at f5fec711b: `pc.cob` (a continued literal whose opening quotation symbol stands in
column 11) compiled at `--std 85`; the same with a period alone on the continuation line in column 10 (`pw.cob`) too.

**Rule.** The repo holds no 1985 text. IBM Enterprise COBOL for z/OS and OS/390 V3R2 Language Reference, "Continuation
lines" (publibfp.dhe.ibm.com/epubs/pdf/igy3lr10.pdf), states it outright: "Any sentence, entry, clause, or phrase that
requires more than one line can be continued in Area B of the next line that is neither a comment line nor a blank
line. ... Area A of a continuation line must be blank." GnuCOBOL 3.2's `areacheck` does not ask it, so CLAUDE.md rule 1's
precedence reaches the IBM text (no implementor latitude: the rule is the 1985 standard's, which IBM's reference format
implements). The ISO 2023 side is §6.3.1 (OK) and §6.5 6) a), b) (OK, `cite.py --check`): no areas. PB3147's area-B arm
(any line's first text) already covered a continued clause on a line with a blank indicator; the residual was the lines
with a HYPHEN in the indicator area, whose literal tail is no token's start.

**Fix.** The same row and code as PB3147's area-B arm (`fixed-form-text-in-area-a-2002`, COBOLNET3735): the rule is one,
"only an area-A item or a level-number begins in area A, and a continuation line has none". `LogicalLineBuilder.Add`
asks `FixedFormLine.IsAreaAOffset(first)` of every fixed continuation line and reports
`ReferenceFormatDiagnostics.OnContinuationTextInAreaA` (every line, at its first text). `FixedFormLine` gained
`ContinuationIndicator` (the one spelling, now read by the line classifier too), `IsAreaAOffset` (the one test of where
area A ends; `BeginsInAreaA` uses it) and `IsContinuation`; `ReferenceFormatMap` keeps whether a line is a continuation
line and `AreaPlacement.BeginsContinuationLineInAreaA` makes the area pass leave such a token to the walk (a period or
word at the start of a hyphen line is one diagnostic, not two). Goldens: `2002/pb3168_continuation_area_a` (a literal
continuation with its quotation symbol in position 8 and a period continuation in position 10), negative
`pb3168-continuation-area-a-85`; unit cases in `AreaPlacementPassTests` (positions 8, 9, 11; position 12 accepted;
period reported once; library text). DESIGN-frontend-grammar.md and VCR row 7.35 carry the determination.

**Not asked (named, not a defect).** A continuation line inside an obsolete comment-entry paragraph (AUTHOR ... SECURITY)
is commentary and is discarded before the builder; and a front-end error (this family's one) hides later bind-time
gates of the same program until fixed (DESIGN-frontend-grammar.md says why the pass cannot ask it).
