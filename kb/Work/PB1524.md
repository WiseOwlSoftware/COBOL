# PB1524 — LANDED (wave 59, with PB1548)

## The rule

> 2) If resources needed to create a new object are not available, the returned object reference is set to NULL, and the EC-OO-RESOURCE exception condition is set to exist and is propagated back to the runtime element that invoked the New method.

`cite.py --check 16.2.1.2 "the returned object reference is set to NULL, and the EC-OO-RESOURCE exception condition is set to exist"` → OK §16.2.1.2 2).

## Observed (adjudicator `adj-w2-misc-s3`, decided by code reading; re-checked by the registrar)

`grep -rn OO-RESOURCE src --include=*.cs` → ONE hit, the catalog entry `src/Cobol.Net.Runtime/Exceptions/ExceptionCatalog.cs:171`
(`L3("EC-OO-RESOURCE", EcFatality.Fatal)`). No raise site exists:

- `INVOKE C "NEW" RETURNING R` → `BoundOo` `InvokeForm.New` renders `R = new C()`;
- factory `SELF "NEW"` / `SUPER "NEW"` → `InvokeForm.NewSelf` renders `__New() => new C()` (`src/Cobol.Net.Compiler/CodeGen/Verbs/OoEmitter.cs` ~l.314);
- inline `class::"NEW"` goes through `OoBinder.InlineInvocation` to the same constructor.

None is wrapped, so an `OutOfMemoryException` (or any allocation failure) during construction terminates the run unit with an
unhandled .NET exception. Resource exhaustion is not reproducible in a golden; the planned slice
(`docs/COBOLNET_OO_SLICE_BRIEFS.md` l.248, "EC-OO (EC-OO-RESOURCE on New per §16.2.1 GR2 …)") never landed.

## Fix shape

One runtime helper every NEW form calls (so `InvokeForm.New`, `NewSelf` and the inline form inherit it), catching the
allocation failure → NULL reference + `EC-OO-RESOURCE` raised through the ordinary EC path. Precedent in-tree:
`src/Cobol.Net.Runtime/.../CobolPtr.cs` ~l.211 already maps `OutOfMemoryException` to NULL + a condition for ALLOCATE.
Witness: a unit test that injects the allocation failure through the helper's seam (a golden cannot exhaust memory).

## Sibling sweep

The dynamic-capacity table growth OOM (PB1410) and the ALLOCATE path — same "host resource failure must become an EC"
pattern. The BASE-class half of §16.2.1.2 GR1 is PB1506's.

## Landed (wave 59, implementer J — with PB1548)

`BASE__FACTORY.__New` (`src/Cobol.Net.Runtime/Control/BASE.cs`) is the ONE body every New form reaches; it catches the
allocation failure of `__Create` and raises EC-OO-RESOURCE through `ExceptionState.OoResourceError` (new
`OoResourceChecking` flag, set by the `EcEmitter` gate table), returning NULL when checking is off; every emitted New
site (`OoEmitter.EmitNew`) stores NULL into the receiving item first. Witness: `StandardClassBaseNewResourceTests`
(the creation seam; a golden cannot exhaust memory).
