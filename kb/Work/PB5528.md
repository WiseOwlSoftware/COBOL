# PB5528 - the FileConnector.LastReadLength doc comment still calls it the frame length that can never disagree with CurrentRecord, stale since PB5480 capped it at VaryMax

**Sites:** `src/WiseOwl.Cobol.Runtime/IO/FileConnector.cs` (`FileConnector.LastReadLength`, the property at line 858 and its doc comment just above)

**Mechanism.** The doc comment says `LastReadLength` is the frame length on a varying file and, written only through `NoteRecordRead`, can never disagree with `CurrentRecord`. Since PB5480 (`NoteRecordRead`, line 877: `LastReadLength = IsVarying && record.Length > VaryMax ? VaryMax : record.Length`) it is the length DELIVERED to the record area, capped at `VaryMax`, and differs from `CurrentRecord.Length` after a long-record READ. That is the distinction PB5480 fixed in `RewriteRecordSequential` (the REWRITE now compares `CurrentRecord.Length`, `§2023:14.9.35.4 GR16` checked in the PB5480 landing); the next reader who trusts the comment reintroduces the defect.

**Fix direction.** Reword the comment to the delivered-length meaning and name `CurrentRecord.Length` as the physical record; the doc comment at line 1631 ("its true length is LastReadLength") needs the same reading.
