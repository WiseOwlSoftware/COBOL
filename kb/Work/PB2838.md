# PB2838 — OPEN — GetText drops the spaces in operand text quoted by diagnostics

Found by the w1047e implementer (report lead 4) and Filed by the train 1047 lander, 2026-10-08 20:53 PDT.

## Repro
- `E:\COBOL-coord\scratch\w1047e\p1935\r9udfx.cob`: COBOLNET0844 quotes the operand as `'FUNCTIONUFX(1)'`
  (`src/Cobol.Net.Compiler/Binding/Procedure/ExpressionBinder.cs` ~1316-1325, the `what` text of
  `BindIdentifierOperand` / `ScreenIdentifierOperand`, `id.GetText()`).
- `E:\COBOL-coord\scratch\t1047\p2836\a.cob` (`CALL "S2836" USING BY CONTENT (C) (N)`): COBOLNET0899 says
  `CALL … USING BY CONTENT BYCONTENT(C)` — the operand text is `byContent.GetText()`
  (`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/CallBinder.cs` ~326), which also glues the BY CONTENT keywords in.

## Fix shape

object-view arm): every diagnostic that quotes source should use it. Sweep `GetText()` inside diagnostic messages
(`grep -n "GetText()" src/Cobol.Net.Compiler/Binding` within `Error(`/`Warning(` calls and `BoundUnsupported` text).
