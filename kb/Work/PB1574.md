# PB1574

Found 2026-09-25 by the w59h finisher, who fixed the 14 findings at their roots. Fix: run
`audit_code_citations.py --check` and `audit_doc_citations.py --check` in the CI workflow's fast lane (docs-only pushes
included — kb/Work notes carry citations), so `ci-gate` refuses a citation regression. Sweep build-local.ps1 for every
other check CI does not run and decide each one the same way.

## Landed (wave 60 A)

A new `audits` job in `.github/workflows/build-and-test.yml` is a `needs:` of `ci-gate`. It is NOT behind
`run_matrix`, so it runs on every push, docs-only pushes included. It has one step per audit, each `if: !cancelled()`,
so one red never hides the others: `audit_code_citations --check`, `audit_doc_citations --check`,
`audit_evidence_supersession --check`, `audit_witness_loss --check --base <the push's own base>`, and
`work.py check`. The `changes` job now exports that base (`base..sha` is what the push adds). The sweep of
build-local found exactly four checks CI never ran, the four audits, and all four are now in CI. `work.py check`
is added because a `kb/` edit is a docs-only push and nothing else validated it there. The rest of build-local
already has a CI seat: the build, the unit, characterization and conformance legs, `filter_population.py` on CI's
own filtered legs, and the GnuCOBOL corpus fetch.

The premise that kept the audits out of CI was stale: `specs/ISO_COBOL.md` is tracked in this repository, and
only the PDF is in the private submodule. `audit_code_citations --check` used to SKIP PHANTOM and the ordinal family
when the spec was absent. Now that it gates CI, a skip there would read as a whole green, so it REFUSES (exit 2)
instead. Probes on this build: a planted PHANTOM (the audit's own self-test case, a figurative-constant comment
citing a clause the standard does not have, in an untracked `src/` file) made `audit_code_citations --check` exit 1 (`[PHANTOM] …PB1574Plant.cs:6`). A planted
misfiling in an untracked `kb/Work` file made `audit_doc_citations --check` exit 1 (`1 MISFILED …
kb/Work/PB1574-plant.md:3`). A malformed note made `work.py check` exit 1. With the plants removed, all five exit 0.
The workflow change can be proven only by the lander's push-main CI run. Locally, the YAML parses, every `needs`
resolves, `ci-gate` needs all ten other jobs (the workflow's own drift step passes when run against the file), and
every module the job imports parses at the Python 3.12 grammar.
