# PB4757 - NonIntegralItemsBeneath: the type-6 screen fails open

**What the report says (R2-2, low; left for the clerk because `IntrinsicArgumentRules.cs` was not changed in that round).** The
R1-4 answer of PB4709 (the walk enters call arguments) walks the arguments of every call in `NonIntegralItemsBeneath`, so an item
inside any numeric function argument becomes opaque and the type-6 screen fails open on illegal source main refused:
`S2 PIC 9V9 VALUE 0.2`, `FACTORIAL (S2 + FUNCTION ABS (S2))`. The report names no probe path.

**R1.** No open note covers it. PB4709 (landed) is the change that introduced it.

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/IntrinsicArgumentRules.cs#NonIntegralItemsBeneath`.

**Fix (landed, as round 2 left it, commit 50718d8bd).** `CollectAdditive` reads `FUNCTION ABS` of a bare numeric item, signed or unsigned, or of its negation, as the item (`UnsignedArgumentOfAbs`, §15.7.4 1) a): a witness needs one non-negative valuation), so `S2 + FUNCTION ABS (S2)` counts S2 twice and the witness refuses it (COBOL1627). `G2 - FUNCTION ABS (G2)` over a signed G2 still nets to 0 and stays legal; any other function keeps its items opaque (no identity is read; the screen fails open there, sound but incomplete: PB4795). Round 1 had read an unsigned argument only. Probe on the pre-fix build: `FACTORIAL (S2 + FUNCTION ABS (S2))` over `S2 PIC 9V9 VALUE 0.2` compiled clean and printed `000000001`. Witnesses (COBOL1627, 2002/2014/2023): `conformance-suite/cases/15.3-Arguments/pb4757-abs-unsigned-sum-non-integral.cob`, `pb4757-abs-signed-sum-non-integral.cob` and `pb4757-abs-negated-sum-non-integral.cob`, each with its `conformance-suite/wiseowl/diagnostics/*.json`. Leads the round-2 review left: PB4796.
**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/IntrinsicArgumentRules.cs#CollectAdditive`, `#UnsignedArgumentOfAbs`, `#NonIntegralItemsBeneath`.
