# PB4452 - the slice reservation reserves whole files

**Seen.** `python scripts/orchestrator/plan_wave.py --cluster PB2293 --from-budget --dry-run` at 174ac1048 (2026-11-02
09:45 PST) planned no campaign step. Every one, PB2299, PB2371-PB2375, PB2296, PB2352-PB2361, PB2398, PB2401, PB2402,
PB2403, PB4319 and PB2293 itself, waited on "file-set collision with in-flight work the open external-repository slices
[RUNNING (worktree wf_a45e0bcf-285-1; worktree wf_a56965c4-16c-1)] (src/WiseOwl.Cobol.Compiler/Binding/BinderDriver.cs)".
Those two branches carry frontend fixes under PB2103's lead and change no line of BinderDriver.cs.

**Mechanism.** `scripts/orchestrator/inflight.py#slice_reservation` reserves `work.slice_file_set()` (DESIGN-external-repository
§12's in-flight set) "whole" against every restructuring wave (its docstring: "every file of the set is reserved whole").
A restructuring note's computed file set (`scripts/arch/member_index.py --note`) names every CALLER of what it moves,
so nearly every binder extract shares a file such as BinderDriver.cs with the set. The meeting rule `inflight.collision`
already reads member claims (PB3670), but the reservation never offers one. PB2296, PB2398 and PB2401 also carry the same
hold as prose ("dispatched only when its file set collides with ... no open external-repository slice", owner, PB2118
question 5, 2026-10-07), and PB2296's `blocked_by` lists PB2103 and PB2104 for it.

**Owner rule it breaks.** Two changes to different parts of one file merge without conflict (PB3670, 2026-10-24:
"Developers do this all the time"; restated 2026-11-02, quoted above). The 2026-11-02 Mythos session dispatched the
ReferenceResolver chain (w20261827a) beside PB2103 part 2 by hand.

**Fix.** Reserve the slices' MEMBERS (the units their open notes change), or nothing beyond the slices' own in-flight
diff, so `collision` decides on members as it does for any other owner. Re-derive the prose holds and the `blocked_by` of
PB2296, PB2398, PB2401 and their steps: keep a blocker only where a step needs a slice's RESULT (PB2401 needs slice 8's
Origin source case). Then check whether the PB2118 question-5 hold should be withdrawn or restated per member, and put
that question to the owner. `test_plan_wave.py` pins the member reading.

## Landed (2026-11-02)

`inflight.hold` is the rule of a hold: running work holds a group only where a member of one matches a member of the
other; a shared file or a whole claim holds nothing. The reservation (`slice_reservation`, `SLICE_OWNER`,
`InFlight.reserves`), `work.slice_file_set`, `open_slices` and `restructuring` and the register's slice-wait check are
deleted. The owner's question-5 hold (PB2118) is withdrawn as the planner's file-level hold: PB2296, PB2398 and PB2403
no longer wait on PB2103/PB2104; PB2401 and PB4319 keep PB2104 for its RESULT. `landing_check.py` check 1 is removed and
check 2 stops only on a shared member. DEVLOG entry: the landing's own.
