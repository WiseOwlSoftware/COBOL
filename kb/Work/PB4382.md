# PB4382 - a branch with no statement: the recovery cascades

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs:729` (`CobolErrorStrategy.GuessCobolIntent`, the COBOL2072 hint from `at.EmptyBlockOwner()` and the COBOL2073 hint at :761; `CobolErrorStrategy.Recover`, the recovery for a missing required `statementBlock`).

**Read at:** origin/main 4aff86e01 (lines above); the same hints sit at :836 and :868 on the PR #971 branch a4f54e0a4, so the site does not depend on the PR.

Repros (outside the repo): `E:/COBOL-coord/scratch/w20261804b/fin/e1.cob` (`IF W-N = 1 ELSE DISPLAY W-A END-IF.` then `MOVE 1 W-N.`) draws COBOL2072 plus a FALSE COBOL0306 at END-IF (the recovery has left the IF open, so the END-IF reads as orphaned); `fin/e2.cob` (`EVALUATE W-N WHEN 1 WHEN OTHER DISPLAY W-A END-EVALUATE.`) draws COBOL2073, which names a misplaced WHEN OTHER where the fault is WHEN 1 having no statement.

Mechanism: the branch rules are spelled `statementBlock`, which cannot match empty, so the violation arrives as an empty block at the offending token. COBOL2072 names it correctly, but the recovery does not supply the missing block: the construct is left unclosed (cascade at END-IF) or the next WHEN is judged against the wrong state (COBOL2073). Related landed work: PB3832 (which fault COBOL2072 names), PB3843 (false END-IF-without-IF after a stray terminator), PB4133 (single-token deletion in a header). Independent of PB4381 and PB4383.

Fix direction: recovery treats the empty required `statementBlock` as present-but-empty (derived from the ATN like the hint, not per verb) so the enclosing construct closes normally; one diagnostic per empty branch, naming that branch.

Grepped `kb/Work`: no open note covers the empty-branch recovery cascade; PB3843 and PB4133 are landed and cover other shapes.
