# PB6059 - the planner cannot tell another account's live branch from an abandoned one

**Observed.** `plan_wave.py --cluster PB3160 --budget-points 10 --scratch E:/COBOL-coord/scratch/pb3160` at 554c7c9305
planned wave 20262137 with six groups. Group A (PB2628, PB3229) and group B (PB2619, PB3321) were FINISH groups: their
specs told a new implementer to cherry-pick the unlanded commits of `worktree-wf_ef90b3a1-3e3-4` (PB3229 flipped to
`landed` on the branch) and `worktree-wf_ef90b3a1-3e3-3` (PB2619). Both branches belong to account 1's wave 20262135,
which had wound down for a CLI restart 20 minutes earlier and whose loop (`orchestrate.ps1 -Cluster PB1754`, started
11:51) was about to review and land them. Running A and B would have done the same work twice and landed it twice.
The wave reports of 20262135 sat in its scratch as `*-report.split-backup.md`, so the planner saw branches with
unlanded work and no report, the shape FINISH-FIRST exists for (an implementer that died mid-work).

**Handled by hand.** `plan_wave.py --release 20262137a` and `--release 20262137b`, the two groups removed from
`groups.json` and the wave args, and the wave run with C-F only (wf_7b34b83a-2b6). PB3321 went with B and waits for
the next PB3160 wave.

**The root.** A branch's owner is not recorded anywhere the planner reads: the dispatch ledger
(`inflight-groups.json`) records groups, not which account's session runs or will resume them, and a wave stop file
(`STOP-w<wave>`) means "wound down", not "abandoned". FINISH-FIRST should take over a branch only when no live account
claims it.

**Fix.** Record the dispatching account (the config dir's account name) on every ledger entry and on the wave's stop
file. Have the planner hold, not finish, a branch whose wave belongs to another account unless that account's mailbox
session has released it. Add a drift test that plans over a fixture ledger holding another account's wound-down wave
and expects a hold.
