# PB5729 - a REDEFINES under the second record of a multi-record FD overflows the compiler's stack

**Sites (lead, not traced to the line that builds the bad class):**
- `src/WiseOwl.Cobol.Compiler/Binding/Passes/StorageFormPass.cs#Classify` (line 318-319, arm (2): `if (cls.Tier == RedefinesTier.Alias) return Classify(cls.Canonical, promoted);`), the frame that repeats.
- `src/WiseOwl.Cobol.Compiler/Binding/Passes/ClassifyRedefinesClassesPass.cs#Run` (line 108-115: an explicit REDEFINES' anchor becomes a class's `Canonical`, every other member `IsCanonical = false`).
- `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs#AssignClassBitOffsets` (line 5722: every descendant of a record-area class member is set `IsCanonical = false` and given that class). The suspected combination: data-name-2 `A`, a descendant of the second record, is left non-canonical while it is also the `Canonical` of its own explicit REDEFINES class, so arm (2) forwards `A` to itself without end. Under WORKING-STORAGE, `01 R2 REDEFINES R1` with the same subordinate REDEFINES compiles (the writer's control `w1.cob`), so the trigger is specific to the file section's implicit redefinition of the record area.

**Repro** (`E:\COBOL-coord\scratch\gl2002\integrate-5\repro\redef\m3.cob`, from the writer's `lane1\run\g2002-13-16-42-redefines\crash\`):

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. CR1.
       ENVIRONMENT DIVISION.
       INPUT-OUTPUT SECTION.
       FILE-CONTROL.
           SELECT F ASSIGN TO "cr1.dat"
               ORGANIZATION IS SEQUENTIAL.
       DATA DIVISION.
       FILE SECTION.
       FD  F.
       01  R1 PIC X(10).
       01  R2.
           05 A PIC X(5).
           05 H REDEFINES A PIC X(5).

       PROCEDURE DIVISION.
           MOVE "AB" TO A
           DISPLAY H
           STOP RUN.
```

**Observed** (golden-2002-5 integrator, `cobol.exe m3.cob --std 2002 --run` on a Debug build of main 20cad156a4): `Stack overflow.`, the frame `WiseOwl.Cobol.Binding.Passes.StorageFormPass.Classify(DataItem, HashSet<DataItem>)` repeated, exit 127. The same at the default `--std` (2023), exit 127. Control `e.cob` (the redefining record FIRST in the FD, `R1` after it) compiles and prints `AB   ` on the same build.

**Expected:** the program compiles and prints `AB   `.
- `§2002:13.16.42.3 GR1` (cite.py OK): "Storage association for the subject of the entry starts at the first bit of the data item referenced by data-name-2 and continues over an area sufficient to contain the number of bits required by the data item referenced", so H holds A's five characters, `AB` and three spaces.
- The entry breaks no syntax rule: `§2002:13.16.42.2 SR3` (cite.py OK), "This clause shall not be specified in level 1 entries in the file section or in any entry subordinate to a file description entry that contains a FORMAT clause", bars only level 1 here; A and H are level 05 of equal size.
- 2023 gives the same: `§2023:13.18.44.4 GR1` (cite.py OK).

**Rows:** no open row waits on this. `2002-GR-13.16.42.3-1` is already CONFORMS on a communication-description record (`g2-redefines-cd-record-storage`), and the 2023 `GR-13.18.44.4-1` is CONFORMS; this case shows both rules fail for a file-section record, so the fix's golden widens their witnesses. A compiler crash on legal source is a defect whatever the inventory says.
