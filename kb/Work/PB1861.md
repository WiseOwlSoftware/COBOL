# PB1861 — OPEN

`scripts/build-local.ps1` (both modes) and `scripts/linux-gate.sh` run the Conformance, Unit and Characterization populations of the `Cobol.Net.Tests.*` projects. CI's Windows build and Guard jobs also run `tests/CobolSharp.Tests.Unit` (1,199 legacy-oracle unit tests, about 1 s) and `tests/CobolSharp.Tests.Integration`. On 2026-09-30 the INSPECT branch deleted the legacy `StringStatementBinder.BindInspectBeforeAfter` on purpose; its reflection test row in `BoundTreeBuilderDecompositionTests` stayed, both local gates were green, and CI run 36774514999 failed on exactly that one case.

**Fix shape (root cause, not a reminder):** make the gate population include every test project CI runs, so a green local gate implies a green CI for test failures. CLAUDE.md "Testing" says every gate runs the whole discovered population; the legacy projects are outside the discovery. Add them to the discovery in `build-local.ps1` and `linux-gate.sh` and pair it with a drift test that compares the gate's project list with the projects the CI workflow runs. Until then an implementer whose change removes or renames legacy code runs `dotnet test tests/CobolSharp.Tests.Unit --no-build` by hand.

**2026-10-06 (R69):** this defect exists only because the legacy test project exists. It closes as MOOT when PB2110
deletes `tests/CobolSharp.Tests.Unit`; PB2110 flips this note to `retired` in its landing commit with
`closes_rows_reason: "moot: the project is deleted (PB2110)"`. No gate change is made for it before then.
