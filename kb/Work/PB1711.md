# PB1711 — OPEN

**Owner, 2026-09-28 ~13:45 PDT:** "We need to validate all learnings first. It's reasonable that the devlog summarizes
to a learning that subsequently we show to be incorrect. The LEARNINGS file should always only contain the final
vetted learnings, battle tested and proven useful. Only those learnings should be encoded into a skill." Asked how to
handle what was already public, he chose "Withdraw now".

## Done so far

The withdrawal is in public claude-skills v1.11.0, which the owner pushes:
- LEARNINGS.md is removed.
- agent-fleet's `status_guard.py` is removed; it stays a project experiment (PB1701).
- The devlog skill carries the three-stage pipeline (devlog → CANDIDATES → VALIDATION → vetted LEARNINGS) and a
  validation brief.

## To do

1. **Validate each of the 145 candidates** (the withdrawn file is at claude-skills c686033, `LEARNINGS.md`) with
   adversarial validators batched by theme, following the devlog skill's `templates/validate-brief.md`.
   - **VETTED requires all four:**
     - the root cause is confirmed;
     - the evidence is re-checked against primary sources (DEVLOG, evidence records, kb/Work);
     - no later entry contradicts it;
     - the fix has been used and shown useful.
   - Otherwise UNPROVEN, naming the missing evidence, or REFUTED, naming the contradicting source.
2. **Publish** LEARNINGS.md with only the VETTED learnings, each recording its validation. Refuted and unproven
   candidates stay in the research record (`docs/rearchitecture/evidence/fleet-optimization/`), marked, never
   silently dropped.
3. **Audit every rule in the public skills** against a vetted learning. A rule with none is withdrawn, or held as a
   project experiment with a measurement plan (as PB1701 is).
4. **Validate first** the items kept pending validation: the stamped handoff (88-agent A/B), `stall_watch.py`, the
   rolling-wave ceiling and the dead-agent handling.
