# PB4526 — renames-elementary-loses-usage-and-sign: 66 RENAMES of a single elementary item ignores its USAGE and SIGN clause

Filed 2026-11-03 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-batch-3000-20261103`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

A level-66 RENAMES of one elementary item (no THROUGH) does not take the renamed item's USAGE or SIGN clause. A RENAMES
of a PACKED-DECIMAL item reads the packed bytes as DISPLAY digits, and a RENAMES of a `SIGN TRAILING SEPARATE` item
reads the sign in the wrong place. Arithmetic through the alias then corrupts the renamed item.

## Minimal test case

Free reference format (`-free`).
```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. REN66.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 WS-REC.
   05 WS-P PIC S9(3)V99 PACKED-DECIMAL VALUE 12.34.
   05 WS-S PIC S9(3) SIGN IS TRAILING SEPARATE VALUE -45.
66 WS-RP RENAMES WS-P.
66 WS-RS RENAMES WS-S.
01 WS-ED PIC -ZZ9.99.
PROCEDURE DIVISION.
    MOVE WS-RP TO WS-ED
    DISPLAY "RP " WS-ED
    ADD 1 TO WS-RP
    MOVE WS-P TO WS-ED
    DISPLAY "P  " WS-ED
    DISPLAY "RS [" WS-RS "]"
    ADD 10 TO WS-RS
    DISPLAY "S  [" WS-S "]"
    STOP RUN.
```

## Environment

cobc (GnuCOBOL) 3.2.0 on WSL2 Ubuntu. `cobc -x -free -std=cobol2014 -o p prog.cob && ./p`.

## Observed result

```
RP    .00
P   323.33
RS [+450]
S  [046+]
```
Exit code 0.

## Expected result (per ISO)

§13.18.45.4 rule 1 (2014, 2023): "When the THROUGH phrase is not specified, all of the data attributes of
data-name-2 become the data attributes of data-name-1 and the storage area occupied by data-name-2 becomes the storage
area occupied by data-name-1." WS-RP is therefore `PIC S9(3)V99 PACKED-DECIMAL` and WS-RS is `PIC S9(3) SIGN TRAILING
SEPARATE`, both over the same storage. Expected:
```
RP   12.34
P    13.34
RS [045-]
S  [035-]
```

## Our compiler

WiseOwl COBOL (fresh judge) prints the expected output above.

## Fix site

cobc/parser.y (read in a 3.3-dev tree), the `renames_clause` action: with no THROUGH phrase it sets `redefines` and
copies only `pic` from the renamed item ("RENAMES acts like REDEFINES"); it does not copy the usage or the sign flags
(`flag_sign_separate`, `flag_sign_leading`), and neither does `cb_validate_renames_item` nor `compute_size` in
cobc/field.c, which takes only `f->redefines->size`. The alias is therefore compiled with the right PICTURE but as a
DISPLAY item with an embedded sign.

cobc (GnuCOBOL) 3.2.0, WSL2 Ubuntu, `cobc -x -free -std=cobol2014 -o p prog.cob && ./p`.

ISO/IEC 1989:2014 §13.18.45.4 rule 1: "When the THROUGH phrase is not specified, all of the data attributes of
data-name-2 become the data attributes of data-name-1". With

```
05 WS-P PIC S9(3)V99 PACKED-DECIMAL VALUE 12.34.
05 WS-S PIC S9(3) SIGN IS TRAILING SEPARATE VALUE -45.

66 WS-RS RENAMES WS-S.
```

`MOVE WS-RP TO` an edited item gives `.00` (expected `12.34`); `ADD 1 TO WS-RP` leaves WS-P as `323.33` (expected
`13.34`); `DISPLAY WS-RS` gives `+450` (expected `045-`); `ADD 10 TO WS-RS` leaves WS-S as `046+` (expected `035-`).

Program (free format):
```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. REN66.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 WS-REC.
   05 WS-P PIC S9(3)V99 PACKED-DECIMAL VALUE 12.34.
   05 WS-S PIC S9(3) SIGN IS TRAILING SEPARATE VALUE -45.
66 WS-RP RENAMES WS-P.

01 WS-ED PIC -ZZ9.99.

    MOVE WS-RP TO WS-ED

    MOVE WS-P TO WS-ED

    DISPLAY "RS [" WS-RS "]"
    ADD 10 TO WS-RS
    DISPLAY "S  [" WS-S "]"

```
Observed: `RP    .00`, `P   323.33`, `RS [+450]`, `S  [046+]`.
Expected: `RP   12.34`, `P    13.34`, `RS [045-]`, `S  [035-]`.

In cobc/parser.y the RENAMES clause without THROUGH copies only the PICTURE of the renamed item, not its USAGE or
SIGN attributes; `compute_size` in cobc/field.c takes only its size.
