# PB6150 - the 1985 ENABLE/DISABLE KEY alphanumeric-edited refusal has no witness

**Mechanism.** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CommunicationBinder.cs:184`: PB5722 added `EditMask: null` to
`IsCommunicationAlphanumericArea(DataItem)`. The same predicate serves the 1985 ENABLE/DISABLE KEY operand screen (`IsAlphanumericKey`; the 1985 syntax
rules 4 of the two statements, 1985 clause XIV.3.2.3 and XIV.3.3.3). An alphanumeric-edited key item, accepted on main, is now refused COBOL6171 at
`--std 85`. The PB5722 report names this sibling effect, but the only new refusal case is the 2002 RECEIVE one.

The reviewer's reading looks right (the 1985 INSPECT general rules treat an alphanumeric edited item as alphanumeric only when redefined as one), so this
is a missing witness, not a wrong verdict.

**Work.** A 1985 ENABLE and a 1985 DISABLE case with an alphanumeric-edited KEY item, a refuse-at-1985 golden each with COBOL6171, the expectation derived
from the 1985 text before the case is written (`cite.py --check` on each rule), and a plain alphanumeric key beside them as the accept case.
