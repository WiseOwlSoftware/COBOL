# PB314 — an argument from the ABSENCE of a sentence, which is why it is an adjudication

## The distinguishing program

```cobol
       01 H PIC X(5) VALUE "AAAAA".
       01 N PIC X(2) VALUE "AA".
       MOVE FUNCTION FIND-STRING(H N LAST) TO P.
```

**4** under an overlapping reading of "occurrence"; **3** under a non-overlapping one.

## The reading, and its evidence

§15.37.4 r1 speaks of *"the first occurrence where the string represented by argument-2 matches a substring within
argument-1"* — every character position at which argument-2 equals a substring of argument-1 is such an
occurrence, and nothing in §15.37 consumes or excludes overlapping ones.

The contrast is decisive in the standard's own drafting: **§15.87.4 r3 (SUBSTITUTE) says outright** that
*"execution of the function proceeds from the character position that is equal to the current character position of
argument-1 plus the length of argument-2"* — it defines non-overlapping resumption **explicitly where it means
it** — and §15.37.4 says no such thing. Both `--check` OK.

⚠ **That is an argument from the absence of a sentence, not from a sentence.** It is strong but it is not what
CLAUDE.md rule 1 calls deriving the answer from the spec, which is why this is filed for an owner/adjudicator
rather than pinned by an agent.

## What the compiler does

`CobolIntrinsics.Text.cs#FindString` enumerates with
`for (int i = 0; (i = h.IndexOf(n, i, StringComparison.Ordinal)) >= 0; i++)` — **overlapping-inclusive**, agreeing
with the literal reading, and the method's own doc-comment asserts it: *"a plain substring match, OVERLAPPING
occurrences included; §15.37 defines no consumption/advance"*.

## Why this is filed and not pinned

An **under-determined axis that is observable**: r1 under `LAST` and r2 with a non-zero argument-3 give different
answers under the two readings, and **no golden anywhere pins it**. Every needle in every existing case and in all
four FIND-STRING goldens the lane landed has matches exactly `len(argument-2)` apart, so the corpus is silent in
both directions and a future change either way would go unnoticed.

⛔ Reporting rather than pinning is deliberate, and one draft had to be walked back to keep it so: a draft of
`tests/conformance/2023/find_string_format_lattice.cob` DID pin it — lines 75-79 wrote
`FIND-STRING("AAAAA" "AA" LAST)` and `FIND-STRING("AAAAA" "AA" 1)` with `.out` rows `OVL=0004` and `OVLSKIP=0002`.
Those statements, their comment block and both `.out` rows were deleted before landing, because 4 and 2 follow only
from the overlapping reading and are exactly what `CobolIntrinsics.Text.cs:507` produces — i.e. the expectation was
being taken from the implementation on a contested reading. **Writing the golden because the implementation does it
that way would be bending the golden toward the implementation.**

## To close

If the overlapping reading is accepted, **one line** — `FIND-STRING("AAAAA" "AA" LAST)` → 4 — added to
`find_string_format_lattice` pins it permanently, and that file's header already names the place. If the
non-overlapping reading is accepted, `FindString`'s enumeration advances by `n.Length` and the same line pins 3.
