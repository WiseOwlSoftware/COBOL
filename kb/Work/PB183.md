# PB183

Found by the PB179 skeptic round (2026-08-30): grep shows §13.18.60.3 SR3/SR5/SR10/SR12/SR13/SR20
enforced and SR14 nowhere. The transcription's SR14 (specs/ISO_COBOL.md:19936) confines the five
pointer/object usages to level-1 elementary items or elementary items under a STRONG type — which would
make `01 G. 05 P USAGE POINTER.` (an ordinary group member) NONCONFORMING. That reading is restrictive
enough that ⛔ **the PRINTED PDF page must be rendered and checked before implementing** (the
falsely-restrictive-OCR hazard; also derive the per-edition history — the rule may be 2002+ shaped
differently). Then: sweep the corpus for pointer/object members of plain groups (OO goldens are likely
holders), decide the dialect posture (strict reject + `--permissive` leniency per the two-axes model if
other compilers accept it — run the survey), and land the screen with negative fixtures.

CONSEQUENCES TODAY: the under-reject is mostly benign EXCEPT where the missing screen lets nonconforming
shapes reach machinery that must then defend piecemeal — the PB179 REDEFINES backstop arm is exactly
such a defense (a nested pointer leaf under REDEFINES is this rule's violation, caught there only
because the class machinery happened to look). COMPANION DERIVATION owed with this: whether §13.18.57.3
SR4's letter overturns the recorded internal-typedef-REDEFINES carve-out (`CheckStrongTypeDeclarations`
— "An INTERNAL redefine … is legitimate and NOT flagged"), which the PB179 screen's cross-root
narrowing deliberately preserved pending this adjudication.
