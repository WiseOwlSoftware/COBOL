# PB2528 — a ReadyToRun runtime for the gates and the package (owner, 2026-10-07)

## The question and the owner's words

Asked, 2026-10-07 18:00 PDT: **"Build the COBOL runtime ReadyToRun for both the gates and the shipped WiseOwl.COBOL
package (rebuilt automatically whenever runtime code changes)?"** The owner answered **"Yes, gates and package
(Recommended)"**, after noting that "it will need to be rebuilt anything code in the COBOL runtime changes".

## The measurement the decision rests on

From the wave-1033 gate-speed diagnosis (`E:\COBOL-coord\scratch\reports\w1033-perf-gate-report.md`, lever 5;
artifacts under `E:\COBOL-coord\scratch\w1033-perf\`):

- Every Conformance case runs its compiled program as a child process (`dotnet <prog>.dll`), with
  `Cobol.Net.Runtime.dll` copied beside it by `AssemblyPackager`. Per case, the child is about 60-75 % of the
  single-thread cost (median 89 ms of about 120 ms).
- Child start, one program, 30 runs each: the Debug runtime the gate deploys 88-150 ms; a Release runtime 89 ms;
  a **ReadyToRun runtime 59-64 ms**, about 35 % off each program's start (median 98 ms to 64 ms).
- End to end, 600 cases at 32 threads: 13.1 s to 10.8 s (about 17 %), every output byte-identical (600/600).
- The diagnosis named the cost of the choice: the gate then certifies an optimized, precompiled runtime instead
  of the Debug one. `src/Cobol.Net.Runtime` has no `Debug.Assert` (0 found), and CI's Windows Conformance
  shards already run Release, so no checking is lost. That trade is what the owner decided.

## What "done" means

1. The runtime the gates' COBOL programs load and the runtime the WiseOwl.COBOL package ships are the SAME
   ReadyToRun build, produced by the ordinary `dotnet build` with no manual step: crossgen reruns exactly when
   the runtime's IL changes, and an unchanged runtime costs nothing on an incremental build.
2. It covers every RID the package and CI target (Windows and Linux at least).
3. A drift test or build assertion fails when the runtime the tests deploy is not ReadyToRun, or differs from
   the one the package carries.
4. The before/after program start time and the build-time cost of a runtime change are measured and recorded.
5. `docs/rearchitecture/DESIGN-test-build-ci.md` and the packaging design
   (`docs/rearchitecture/DESIGN-USER-DOCUMENTATION.md` §6, kb/Work PB1613) describe it.

## Landing

Branch `runtime-r2r` (wave 1033 X). The mechanism is DESIGN-test-build-ci §3.16; the package side is
DESIGN-USER-DOCUMENTATION §6 (kb/Work PB1613 still owns the pack itself and its platform list).

- **Platforms:** `win-x64` and `linux-x64` (root `Directory.Build.props` `CobolRuntimeReadyToRunIdentifiers`), the
  operating systems every CI runner uses. Both images are built on every host (crossgen2 cross-compiles).
- **Measured start** (24 corpus programs, 21 interleaved runs each, 21/24 outputs equal to the golden in both arms):
  Debug portable runtime 104.7 / 102.8 ms → ReadyToRun image 74.5 / 76.5 ms (−29 % / −26 %); an earlier quieter pair
  83.2 → 60.4 ms (−27 %). The diagnosis's ~35 % compared single programs; the sample's median gain is about 27 %.
- **Measured build cost** of a runtime source change, gate-slot settings (no node reuse, no compiler server):
  8.5–11.5 s with the images against 4.3–7.1 s without, about +4 s; no-op builds unchanged.

For the next implementer:
- `src/Cobol.Net.Runtime/Cobol.Net.Runtime.csproj#CobolRuntimeReadyToRunImages` — the ONE producer (SDK ReadyToRun
  publish per platform, Release, no source stamp). Hooked `AfterTargets="CoreCompile"`: a `BeforeTargets` on
  `CopyFilesToOutputDirectory` runs AFTER that target's DependsOn content copy, which then finds no image (MSB3030).
- `src/Cobol.Net.Compiler/CodeGen/AssemblyPackager.cs#RuntimePath` / `#ReadyToRunPlatform` — the ONE selector;
  reuse it (it is public for the Conformance cache). `ReadyToRunPlatform` must be declared before `RuntimePath`:
  static initializers run in declaration order.
- `tests/Cobol.Net.Tests.Conformance/CompiledProgramCache.cs#ToolFiles` — the cache key's file set; the deployed
  runtime is not the in-process one.
- `tools/impact/ImpactRecording.targets` — sets `CobolRuntimeReadyToRun=false`; the recorder needs the probed
  portable runtime deployed.
- `tests/Cobol.Net.Tests.Unit/ReadyToRunRuntimeDriftTests.cs` — reads PE headers (machine = arch XOR OS code);
  a new CI runner kind must be mapped in `CiPlatforms` and declared.
