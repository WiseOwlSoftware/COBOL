# PB5618 - EXIT METHOD and EXIT FUNCTION in a GLOBAL declarative are accepted, though EXIT PROGRAM and GOBACK there are refused (2002 SR2 bans every EXIT format)

**Sites:**
- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/OoBinder.cs#OoBindExitMethod`
- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/UdfBinder.cs#UdfBindExitFunction` (the check is EnclosingContext.cs PlacementRules#RefusedInGlobalDeclarative)

**Mechanism.** ControlFlowBinder routes EXIT METHOD to OoBinder.OoBindExitMethod and EXIT FUNCTION to UdfBinder.UdfBindExitFunction; neither calls PlacementRules.RefusedInGlobalDeclarative, which only the EXIT PROGRAM arm and GOBACK call.

**Inventory.** Rows claimed: `2002-SR-14.8.13.2-2`.

**Rules (each citation checked with `python scripts/spec/cite.py --check`, verdict OK).**

- `§2002:14.8.13.2 SR2`: "The EXIT statement shall not be specified in a declarative procedure for which the GLOBAL"
- `§2002:14.8.13.2 SR9`: "An EXIT FUNCTION statement may be specified only in a function procedure division"

**Repro.** Scratch originals under `E:/COBOL-coord/scratch/op-20261114/read-2002/defects-work/` (p2/exitfn-global.cob); the text is inline. Command: `cobol.exe p2/exitfn-global.cob --std 2002 --run`

`p2/exitfn-global.cob`:

```cobol
       IDENTIFICATION DIVISION.
       FUNCTION-ID. F1.
       ENVIRONMENT DIVISION.
       INPUT-OUTPUT SECTION.
       FILE-CONTROL.
           SELECT F ASSIGN TO "q26-f1.dat".
       DATA DIVISION.
       FILE SECTION.
       FD F.
       01 FR PIC X(10).
```

**Observed.** compiles and runs, prints 7, rc=0.

**Expected (from the 2002 text).** refused at compile time.

**Sibling sweep.** the run-time EC-FLOW-GLOBAL-EXIT of §2002:14.8.13.3 GR2 for the function and method formats (not probed); every statement routed past the EXIT dispatcher to another binder.

**Other editions.** 2014: yes presumably (EXIT METHOD/FUNCTION are kept to 2014 per the binder comment). 2023: EXIT METHOD/FUNCTION are removed forms. 85: n/a.
