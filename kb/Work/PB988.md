# PB988 — OPEN

## Repro — measured
`scratchpad/w48u/probe/pd_endname.cob`: `PROGRAM-ID. PDX.` … `END PROGRAM PDY.` → compiles, prints `RAN`. No diagnostic.

## The rule
`OK  §10.7.3` — "2. Program-name-1 shall be identical to the program-name declared in a preceding PROGRAM-ID paragraph."
`OK  §10.7.3` — "8. Program-prototype-name-1 shall be identical to the program-prototype-name declared in the corresponding
PROGRAM-ID paragraph." Rules 4–7 and 9 state the same for END CLASS, END METHOD, END INTERFACE, END FUNCTION (user
function and function prototype).

## Code site
The end-marker contexts (`endProgramHeader` and its siblings in the grammar) are parsed and read by nothing in the binder.

## What the fixer owes
ONE check over all seven end-marker kinds (not seven): the nesting walk that pairs an ID paragraph with its end marker
compares the names (case-insensitively — they are COBOL words) and reports the rule of the marker's kind. Rule 5's
second sentence (a PROPERTY method's END METHOD omits the name) is part of the same check. Negative goldens per kind at
the edition that introduced it; rules 1 and 3 (presence and order) are not claimed here.

### Finding — `end-markers` (under-rejects; rows `SR-10.7.3-2`, `SR-10.7.3-3`, `SR-10.7.3-7`, `SR-10.7.3-8`, `SR-10.7.3-9`)

**Mechanism.** The END PROGRAM / END FUNCTION marker name (endProgramHeader.programName) is never compared with the unit it closes, for program, user-function, program-prototype or function-prototype units. The name is not checked, the kind (PROGRAM or FUNCTION) is not checked, and the order of nested markers is not checked.

**Repro.** E:\Temp\claude\E--CobolSharp\a700c052-f9e4-4942-84ff-a13c7505d6ec\scratchpad\adj-d2b\out\probe\end-markers\p1.cob: PROGRAM-ID. EMP1X. ... END PROGRAM EMP1Y. compiles and prints RAN. p2.cob: a PROGRAM-ID closed by END FUNCTION EMP2X compiles and runs. p3.cob: EMP3A contains EMP3B, closed by END PROGRAM EMP3A. END PROGRAM EMP3B. (reversed); it compiles and prints NESTED. p6.cob: FUNCTION-ID. EMP6F ... END FUNCTION EMP6G compiles, and the caller prints 7. q1.cob, q2.cob and q3.cob: prototype markers with the wrong name or the wrong alternative compile clean.

**Expected from the spec.** A compile-time diagnostic for each case. §10.7.3 SR2/SR7/SR8/SR9 require the marker name to be identical to the name its PROGRAM-ID / FUNCTION-ID declared, which also means using the alternative that matches the unit kind. SR3 requires a contained program's END PROGRAM to precede its container's.

**Observed / reasoning.** Nothing in src/Cobol.Net.Compiler reads endProgramHeader().programName(). PrototypeUnitRules and PushPopAllPlacementPass test only whether the marker is present. The grammar pairs each marker with the innermost open unit, so a wrong name, a wrong kind or a reversed order is silently re-paired.

**Code site.** src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4#endProgramHeader (END (PROGRAM|FUNCTION) programName DOT); no binder consumer

### Finding — `end-markers` (under-rejects; rows `SR-10.7.3-1`)

**Code site.** src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4#programUnit (endProgramHeader?); src/Cobol.Net.Compiler/Binding/PrototypeUnitRules.cs (prototype-only presence check)

### Finding — `end-markers` (under-rejects; rows `SR-10.7.3-5`)

**Mechanism.** END METHOD is name-checked only on the class instance and factory arms, and only for non-PROPERTY methods. The interface method-prototype loop never reads the END METHOD name, and a GET/SET PROPERTY method's END METHOD is allowed to carry a name, which the second sentence forbids. This is a two-arm dispatch where only one arm was fixed.

**Repro.** E:\Temp\claude\E--CobolSharp\a700c052-f9e4-4942-84ff-a13c7505d6ec\scratchpad\adj-d2b\out\probe\end-markers\o2.cob: METHOD-ID. GET PROPERTY V. ... END METHOD ZZZ. compiles clean. o3.cob: in an interface, METHOD-ID. M1. ... END METHOD M2. compiles clean. By contrast, o1.cob and o6.cob (class and factory END METHOD mismatches) correctly give COBOLNET0820.

**Expected from the spec.** §10.7.3 SR5: method-name-1 shall be identical to the METHOD-ID's method-name, which applies to interface prototypes too. If PROPERTY is specified, method-name-1 shall be omitted. Both probes require a diagnostic.

**Observed / reasoning.** OoClassTable.Build guards the END METHOD comparison with `sel is null && m.methodName().Length > 1`, so property methods are skipped. The interface prototype loop has no comparison at all. PB988 owns row SR-10.7.3-5. Its note says 'nothing reads the end-marker name', which is inaccurate for OO. PB988 also owns SR4 and SR6, which already conform (OoClassTable plus OoExpansion, with tests EndClassNameMismatch_0820 and Interface_EndNameMismatch_0840). The note should drop those two rows.

**Code site.** src/Cobol.Net.Compiler/Oo/OoClassTable.cs#Build (interface methodDefinition loop; instance/factory END METHOD guard `sel is null`)
