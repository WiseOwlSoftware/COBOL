# PB1323 — OPEN — illegal source reaches the backend and crashes it

## Measured (`battery-86/probe/dupusing/prog.cob`, `--std 2023`)
The header is `PROCEDURE DIVISION USING p p o.` over two LINKAGE items, with no ENTRY statement.
```
error: backend compilation failed (generated C# at dupusing.g.cs):
  (14,36): error CS0102: The type '_PRG_DUPUSING' already contains a definition for '__lnk0'
  (19,9): error CS0229: Ambiguity between '_PRG_DUPUSING.__lnk0' and '_PRG_DUPUSING.__lnk0'
  (20,9): error CS0229: Ambiguity between '_PRG_DUPUSING.__lnk0' and '_PRG_DUPUSING.__lnk0'
```
exit 70 (internal/backend failure).

## The rule
```
$ cite.py --check 14.2.2 'A particular user-defined word shall not appear more than once as data-name-1'
  OK  §14.2.2 1)  (Syntax rules)
      1) Data-name-1 shall be defined as a level 01 entry or a level 77 entry in the linkage section. A
         particular user-defined word shall not appear more than once as data-name-1. …
```
Expected: a COBOL diagnostic at the second `p`, citing §14.2.2 SR1, exit 65/70 by the compiler's own convention,
and NO backend run. A Roslyn error on user source is a compiler defect whatever the source's legality: the
backend must only ever see bound, legal programs.

## Mechanism
- The USING operands are bound into the formal list (`src/Cobol.Net.Compiler/Binding/DataBinder.Linkage.cs`,
  the `ProcedureFormal` record at :15-18) with no uniqueness check.
- The emitter then declares a `__lnk{item.Uid}` carrier per FORMAL (`DataBinder.Linkage.cs:325`), and two
  formals with the same item share a Uid.

## What the fixer owes
- ONE uniqueness screen over a USING list, keyed on the resolved item and not on the spelling (qualification can
  make two spellings name one item), and asked by every USING list that has the rule:
  - `PROCEDURE DIVISION USING` (§14.2.2 SR1);
  - the ENTRY statement's USING;
  - the method and function prototype/definition USING lists;
  - the class/interface `USING` parameter-name lists, where the rule is the same one:
```
$ cite.py --check 11.3.3 'A given parameter-name shall not appear more than once in a USING clause'
  OK  §11.3.3 9)
$ cite.py --check 11.6.3 'A given parameter-name shall not appear more than once in a USING clause'
  OK  §11.6.3 7)
```
    Those two rows are CONFORMS via `OoExpansion.AddSkeleton`. The fixer checks whether that is a second copy of
    the same screen and, if it is, folds it into the one screen ([[feedback_one_rule_one_place]]).
- **Defensive invariant:** the emitter asserts that carrier names are unique before handing C# to Roslyn, so the
  next unscreened duplicate is an internal-error diagnostic that names the item, not CS0102.
- Negative golden per USING-list kind; the program header case at every edition.
