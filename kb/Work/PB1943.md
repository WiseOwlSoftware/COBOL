# PB1943 — OPEN

Filed by the train-1007 lander from wave 1007 group A's report (`w1007a-PB1271-report.md`, "New defects" item 1).
[[PB1271]] (train 1007) made a repeating SUM entry's counter a table with subscripted references.

## Question

Does reference modification apply to a sum counter? A sum counter is numeric, its usage unspecified (§13.18.54.4);
§8.4.3.3.3 states which data items may be reference-modified. If it is admitted, `CF-T(1:2)` reads the counter's
character image; if not, the diagnostic should name §8.4.3.3.3, not "not defined" — GR5 does declare the name
("the data-name is the name of the sum counter"). Either way the current COBOLNET1639 is a misdiagnosis.
The fixer runs `cite.py --check` on the governing §8.4.3.3.3 sentence before deciding.

## Repro

Any RD with `03 CF-T COLUMN 1 PIC 9999 SUM WS-X` plus `MOVE CF-T(1:2) TO WS-Y` in the procedure division.

## Code site

`src/Cobol.Net.Compiler/Binding/ReferenceResolver.cs#SumCounterFor` — `if (written.RefModCount > 0) return null;`
sends the reference to ordinary resolution, which cannot see a sum counter.
