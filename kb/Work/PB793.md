# PB793 — OWNER — the empty code-name set

Filed 2026-09-06 14:19 PDT by the registrar from the PB770 implementer's report, which recorded the question
under "⛔ The one owner-visible question this leaves" and explicitly did NOT decide it. PB770 itself LANDED in
train 19 and is on main; `kb/Work/PB770.md:318-327` says the same in its own words — *"Raised in the report; not
decided here."* This note is that question's home in the register, so it stops living inside a landed defect's
prose (CLAUDE.md rule 8's whole subject).

## ⛔ The bare question

**Should COBOL.NET accept `ASCII` and `EBCDIC` as ALPHABET `code-name-1`?**

## The default, if the owner does not say otherwise

**Yes — accept both**, per the standing protocol. `feedback_owner_decision_protocol` (2026-08-30): follow the
surveyed model implementations; ask only on significant considerations. `follow_gnucobol_on_split_latitude`
(owner decision): where the standard leaves a point implementor-defined and the vendors split, follow GnuCOBOL —
its LATITUDE, never its non-ISO extensions. The PB770 implementer's survey: **GnuCOBOL, Micro Focus and IBM all
accept `ASCII` and/or `EBCDIC` as code-name-1**; GnuCOBOL treats `ASCII` as the native set and `EBCDIC` as its
translation table. This note is filed rather than defaulted because the cost is not a clause — it is a coded
character set, its collating sequence, its correspondence with the native set, and two conditionally-required
Annex A.1 documentation items. That is the "significant consideration" the protocol reserves for the owner.

## Why it is latitude and not conformance — mechanically checked

```
python scripts/spec/cite.py --check 12.3.7.3 "The implementor shall specify the names supported for code-name-1 and code-name-2 in the ALPHABET clause, if any"
  OK  §12.3.7.3 15)  (Syntax rules)
      15) The implementor shall specify the names supported for code-name-1 and code-name-2 in the ALPHABET
          clause, if any.
python scripts/spec/cite.py --check 12.3.7.4 "The ALPHABET clause provides a means of relating a name to a specified coded character set"
  OK  §12.3.7.4 7)   (General rules)
```

"**if any**" is the licence for an empty set, and Annex A.1's own preamble makes the item OPTIONAL ("The element
may be provided at the implementor's option"). So **today's refusal is conforming** — that is why every harm flag
on this note is false and `process_only` is true. Nothing a user writes is answered wrongly; a spelling other
compilers accept is refused, by documented design.

## What main does today (PB770, landed)

`src/Cobol.Net.Compiler/Binding/DataBinder.Switches.cs:941-951`, `AlphabetCodeNameRefused` — *"⛔ THE ONE
§12.3.7.3 SR15 check, for code-name-1 (alphanumeric) and code-name-2 (national) alike … This implementation
supports NONE"*:

```
ALPHABET A-ASC IS ASCII
→ COBOLNET1907: ALPHABET A-ASC IS ASCII: not a supported code-name — this implementation defines no
  code-name-1 names (ISO §12.3.7.3 SR15; the alphanumeric coded character sets are NATIVE, STANDARD-1,
  and STANDARD-2)
```

The check is deliberately narrow: it fires only on a definition that is ONE bare word, which is the only shape
code-name-1/-2 has in the general format (`specs/ISO_COBOL.md` §12.3.7.2, "where alphabet-name-clause is" —
`code-name-1` / `code-name-2` stacked with NATIVE / STANDARD-1 / STANDARD-2 / UCS-4 / UTF-8 / UTF-16 / LOCALE /
`{ literal-phrase } …`). Before PB770 an unrecognized code-name was silently reinterpreted as the CHARACTERS OF
ITS OWN SPELLING — `ALPHABET A-ASC IS ASCII` built an alphabet whose first four positions were A, S, C, I — so
the empty set replaced a wrong answer with a diagnostic. **Whatever is decided here, that reinterpretation does
not come back.**

## The documentation state, and what "yes" would add

`docs/CONFORMANCE.md:1121`, **DOC-A.1-184** (*"the names supported for code-name-1 and code-name-2"*, §12.3.7.3
SR15, **optional** + documented-if-provided) currently reads **"Not provided. The set of supported code-names is
EMPTY, in both classes."** Its own text records the two items that wake up the moment a code-name exists:

- **DOC-A.1-183** — *"SPECIAL-NAMES paragraph, ALPHABET clause, code-name-1 (alphanumeric coded character set and
  collating sequence; ordinal number of characters; correspondence with native alphanumeric character set)"*,
  **conditionally required** *"because it is conditioned upon the existence of a code-name"*.
- **DOC-A.1-185** — the code-name-2 / national twin, same requirement class.

Both are VACUOUS today and are recorded as such. (Row texts read from
`docs/rearchitecture/spec-rule-catalog.json:40110` and `:40132`.)

## What implementing "yes" actually costs

1. A **code-name table** — the structure SR15's answer belongs in, not a pair of hand-written `if` arms
   (CLAUDE.md rule 5). `AlphabetCodeNameRefused` becomes a LOOKUP with a refusal on miss, so the next supported
   code-name is a row, and the empty-set case stays exactly today's diagnostic.
2. For `ASCII`: the coded character set, its ordinals and its correspondence with the native set — which on this
   compiler's UTF-16 substrate (`charset_utf16`; implementor item 188 / D-N1) is the identity over the first 128
   positions, so DOC-A.1-183 is short but must be written.
3. For `EBCDIC`: a real coded character set AND its collating sequence AND its native correspondence. ⚠ Which
   EBCDIC — there are many code pages — is itself an implementor choice this note does not pre-empt; GnuCOBOL
   ships one translation table, and `survey_compilers_on_latitude` says to survey before choosing.
   ⛔ **GPL: GnuCOBOL's table may not be copied** (`feedback_gnucobol_differential`); the latitude may be
   followed, the source may not.
4. DOC-A.1-183 and DOC-A.1-185 flip from vacuous to REQUIRED and need `docs/CONFORMANCE.md` rows with witnesses,
   and DOC-A.1-184 is rewritten from "Not provided" to the supported set.
5. `CONFORMANCE.md` §7 / Annex A.1 sweep, plus a positive golden per code-name per class.

## The measured consequence of leaving it empty

`kb/Work/PB770.md:318-327` records the differential row this moved, measured by the implementer against the
battery-#59 baseline: **`run_misc:5406` went `AGREE_ACCEPT` → `WE_REJECT_THEY_ACCEPT`.** The witness declares
both `ALPHABET A-EBC IS EBCDIC` and `ALPHABET A-ASC IS ASCII` and both now draw COBOLNET1907. ⚠ That flip
REPLACED A WRONG ANSWER (we printed `[,]` where the test expects no output) with a diagnostic, so it is an
improvement either way; deciding "yes" here would return the row to `AGREE_ACCEPT` for the right reason.
