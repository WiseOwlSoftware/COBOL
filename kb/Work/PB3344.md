# PB3344 — message-only negative goldens are outside the header-code guard

Source: the PB1784 review finisher's work on branch `worktree-wf_9e52adb3-fa2-7` (PR #188): commit `5a4ef7960` added `NegativeGoldenHeaderCodeDriftTests` to keep negative goldens' header codes current when a diagnostic code's meaning moves, and `f84c138f0` made it a specific rule rather than a tree sweep. Report `E:/COBOL-coord/scratch/reports/w1108a-PB1784-report.md`, "New defects / leads".

**What is wrong.** A golden that asserts only the diagnostic MESSAGE text (no code in its header) is not seen by that guard. A code reassignment or a descriptor split can therefore leave such a golden asserting a stale meaning, and the guard stays green.

**Code site.** The guard's file is `NegativeGoldenHeaderCodeDriftTests` under `tests/WiseOwl.Cobol.Tests.Unit/` on PR #188's branch (main gains it when the PR merges); its selection predicate, the one that picks goldens by a header code, is the site. The filing clerk did not read the branch's file; the implementer names the exact member on opening it.

**Harm.** None to a user's program; a guard hole in a test.

**Fix.** Make the guard see every negative golden: resolve a message-only golden's message to the descriptor that owns it (from the catalog) and fail when no descriptor owns that text any more, or require the golden to carry its code. One structure, not a hand list. Prove the guard fails by moving one code's meaning and confirming a message-only golden goes red.
