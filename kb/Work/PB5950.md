# PB5950 - every source line's number printed twice

**Sites:** `src/WiseOwl.Cobol.Listing/Text/TextListingRenderer.cs` (`TextListingRenderer.FileLineColumn`, `TextListingRenderer.SourceRow`), `src/WiseOwl.Cobol.Listing/Html/HtmlListingRenderer.cs` (`HtmlListingRenderer.Sections.Line`)

**Found** by the owner (2026-11-19 19:05) on NC105A's listing: "Every source code line appears to have its line # printed twice."
The row was `     1         1 000100 IDENTIFICATION DIVISION.`: the listing line number (columns 1-6) and the line's number in its
own file (11-16). In a program with no COPY statement, and in any program up to its first library text, they are the same number.

**Decided (the codebase owner's call):** the file-line column prints only where it differs from the listing number, in both the
text and HTML listings, through one function (`TextListingRenderer.FileLineColumn`). It still says what it was for: after an
inclusion, and on every line of a library text, it names the line in the file the programmer edits. The model and the JSON listing
keep `FileLine` on every line (a program reads it; nothing is printed twice there). The user guide's row table and HTML paragraph
say it.

**Witness:** `HtmlListingRendererTests.EveryLine_IsARow_WithItsText` expects an empty column where the numbers agree and the number
where they differ, and asserts the document holds both kinds. NC105A after: `     1           000100 IDENTIFICATION DIVISION.`.
