# PB5788 - a report file with a CODE clause and RECORD CONTAINS 2 or 1 is written longer than the file's records: three characters (ABW) where the record is 2 or 1 (every edition)

**What is wrong.** With a CODE clause and RECORD CONTAINS 2 or 1 the compiler writes `ABW`; the 2-character record is `AB`. (The note's harm is minor: degenerate sizes.) GR2: the CODE positions "are included in the logical record size"; RECORD CONTAINS 2 makes every record 2 positions, so the line width is 0 and each record is `AB` (the compiler's own determination DOC-A.1-159 says the record is the FD's size and a column past the size less the CODE is not recorded). The compiler writes `ABW` (3 characters) at sizes 2 and 1; size 3 is right (`ABW`). A size of 1 cannot hold the two-character code at all (GR1 places it in the first two positions of each record); refusing it is the plain answer, and writing 3 characters is wrong under any reading. Same at 2023, cause (b).
