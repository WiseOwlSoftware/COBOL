# PB5860 - a variable-length record sequential file written with ADVANCING, or under LINAGE, cannot be read back through the file description that wrote it (every edition)

**Ruling: UPHELD (b), harm wrong_answer.** A variable-length record sequential file that a program WRITES with ADVANCING, or under LINAGE, cannot be read back through the file description that wrote it: OPEN INPUT answers 39 and the READ 47. The same file written with no print control reads back. The rows `1985-GR-VII.2.8.4-4`, `1985-GR-VII.4.3.4-8` and `1985-GR-VII.1.3.5-L2.3` do not close on their inherited verdict. The checker's confidence for the first row (`1985-GR-VII.2.8.4-4`): medium. Cause (b): the same at `--std 2023`. Severity MAJOR: a wrong-answer defect is at least MAJOR.

**Mechanism 1: why 39 is wrong, and what the fix must hold to.** Status 39 is for a conflict "between the fixed file attributes and the attributes specified for that file in the program" (`§1985:VII.1.3.5`, cite.py OK), and here the program's own description created the file. Nothing in 1985 makes a file written with ADVANCING unreadable: the phrase is there to "allow control of the vertical positioning of each line on a representation of a printed page" (`§1985:VII.4.7.4 GR16`, cite.py OK), and "The execution of the WRITE statement releases a logical record to the operating system" (`§1985:VII.4.7.4 GR7`, cite.py OK). The code decides the 39 by asking whether the file's length prefixes parse, and the print controls its own WRITE put between the records make them not parse; the read side has no case for those controls either, so removing the 39 alone would not make the READ right. The register does not cover it: A.1 item 146 states the write form only, and for a LINAGE file it contradicts A.1 item 151.
DECIDED, as a bound on the fix and not as its design: every file a program can write through a file description it can read back through the same description, record for record, at every combination the description admits (ADVANCING, LINAGE, each record format); the method that does it is the implementor's (`§1985:VII.2.8.4 GR4`), is chosen by the precedence of CLAUDE.md rule 1 (what GnuCOBOL does for a record sequential file written with ADVANCING or LINAGE is read from its source first), and is stated ONCE in the register, so that items 146 and 151 agree. The checker did not probe the fixed-length sibling (a fixed-length file written with ADVANCING, whose control characters may be read into the record area): the fix sweeps it and says what item 146 documents of it.

**The checker's evidence (rulings.json, copied).** The checker ran `adv39.cob` (run/adv39-001) at `--std 85` (exit 0) and printed `W1 00 00 00`, `W2 00 00 00`, `OPEN-IN 39 39 00`, and `R1 47 00 [          ] 47 00 [          ] 00 04 [AB        ]` (FA = ADVANCING, FB = LINAGE, FC = control). The files on disk: `ADV39A.DAT` = `0a 04 00 00 00 41 42 20 20 0a 03 00 00 00 43 44 45 0a`; `ADV39B.DAT` = `0d 0a 41 42 20 20 0d 0a 43 44 45 0d 0a`; `ADV39C.DAT` = `04 00 00 00 41 42 20 20 03 00 00 00 43 44 45`. At `--std 2023` (run/adv39-002, exit 0) the output is identical to `--std 85`. The checker's reasoning: 1985 sets no limit on reading back a file written with ADVANCING or LINAGE: `§1985:VII.4.7.4 GR16` makes ADVANCING control vertical positioning on a representation of a printed page (it does not change the logical records released, GR7, GR12); LINAGE GR1 to GR9 describe the logical page only. The file was created by OPEN OUTPUT through the same FD, so its fixed file attributes (record type variable, sizes 1 to 10) are the ones the program specifies, and no conflict can exist: 39 is defined only for a conflict between the fixed file attributes and the program's (`§1985:VII.1.3.5` item f; `§1985:VII.4.3.4 GR8`). The 39 comes from `SequentialConnector.FixedAttributeConflict` inferring the record type from `RecordFraming.StreamFramingParses`, which the implementation's own print stream fails (the ADVANCING file begins `0a 04 00 00 00`, a prefix of 1034; the LINAGE file is CR LF text). The conformance register (DOC-A.1-146 (c'), DOC-A.1-151) documents the WRITE form of a print stream and says nothing that excuses or documents an unreadable file; DOC-A.1-151 (a) even says the prefix method governs EVERY variable-length record sequential file, which (c') contradicts for a LINAGE file. It is not a conforming answer the register documents: a defect of the open check AND of the read side (with the 39 removed, the frame reader would still misread the interleaved controls).

**Expected:** OPEN INPUT 00 for FA and FB; READ 00 with LA/LB = 04 and `[AB  ]`, then L=03 `[CDE]` (`§1985:VII.4.3.4 GR8`, `§1985:VII.1.3.5` item f, `§1985:VII.2.8.4 GR4`, `§1985:VII.4.7.4 GR7` and GR12). **Observed:** `OPEN-IN 39 39 00`; READ 47 47 00 (the control file FC reads L=04 `[AB]`).
