# PB705 — OPEN — the second arm of a two-arm reader

Found 2026-09-05 by the `PB678` implementer (report §"New defects" N2) while folding the class→sequence rule onto one
classifier: the sibling site sixty lines above already reads `OperandPic` (via `StringCategoryOf`); this one reads
`Pic` unguarded. It was NOT measured — reachability is a probe to run, not a conclusion — so the first step is the
repro.

## The rule

§13.18.29.4 GR2 b) (`cite.py --check 13.18.29.4 "a national group is treated as though it were an elementary data
item of usage national"` → OK): a national group is an elementary national operand, and GR1 b) says the same for a
bit group; §8.8.4.2.9 compares national operands under the national program collating sequence, §8.8.4.2.8 compares
boolean operands "by their boolean value, regardless of their usage" with a boolean-zero pad.

## The mechanism (to confirm)

`src/Cobol.Net.Compiler/CodeGen/Emit/ConditionRenderer.cs` ≈464: `var cat = parent.Pic?.Category;` in
`RenderMembershipTest` — null for a group, so the membership test classifies as alphanumeric. PB678 folded the
class→sequence choice for the other sites onto `CollatingSelection.Of`/`EmitContext.CollateArgFor`; this site should
read `OperandPic` and route through the same classifier, which is a one-line change once the defect is measured.

## Fix

Probe first: a `GROUP-USAGE NATIONAL` conditional variable with a level-88 VALUE, under a `PROGRAM COLLATING SEQUENCE
FOR NATIONAL` that reorders the alphabet so the alphanumeric and national readings disagree; and a `GROUP-USAGE BIT`
one whose VALUE is shorter than the item so the pad matters. If either disagrees with §8.8.4.2.9/.8, fix by reading
`OperandPic` through the one classifier, golden both, and sweep `grep -n "\.Pic?\.\|\.Pic\." src/Cobol.Net.Compiler/
CodeGen/` for other readers of `Pic` where `OperandPic` is the rule (D20's family).
