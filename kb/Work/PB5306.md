# PB5306 - decision: a destination named more than once in the DESTINATION TABLE of one SEND receives the whole message once per occurrence

**Question.** When a symbolic destination appears in more than one occurrence of the DESTINATION TABLE a SEND uses, does the MCS take the message once, or once per occurrence? The 1985 text does not decide it: a SEND releases "only a single portion of a message segment or a single portion of a message to the MCS" (§1985:XIV.3.6.4 GR6), and either answer keeps that, provided each copy is the whole message. ISO 2023 has no Communication facility, and GnuCOBOL, IBM and Micro Focus provide no MCS to follow (CLAUDE.md rule 1 precedence runs out).

**Decision: once per occurrence.** Each occurrence up to DESTINATION COUNT is a destination of the statement, so the message is delivered once per occurrence, each copy the whole message under its own segment and message control, and each occurrence's error key is set on its own. This is the reading that needs no rule the text does not state: the count and the error keys are already per occurrence (§1985:XIV.2.2.4 GR22 updates "each occurrence of data-name-4, up to and including the occurrence specified by the content of data-name-1"), and nothing de-duplicates names. It is recorded in docs/CONFORMANCE.md beside the communication devices row. The runtime does not do this today; kb/Work PB5288 holds the fix, and its rows `1985-GR-XIV.3.6.4-10` and `1985-GR-XIV.3.6.4-6` close with it.
