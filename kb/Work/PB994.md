# PB994 — OPEN

## Repro — measured
`scratchpad/reg12/q07_sortrel.cob`: a RELATIVE file (ACCESS SEQUENTIAL) as SORT USING, a line-sequential GIVING →
`q07_sortrel.cob(23,12): error COBOLNET1757: SORT/MERGE USING/GIVING on Relative file 'RPF' (sequential slice;
relative/indexed USING-GIVING — incl. the GR15b relative key 1..n — are the G5 keyed slice)`.

## The rule
`OK  §14.9.40.4 15)` — "For a relative file, the relative key data item for the first record returned has the value 1;
for the second record returned, the value 2; etc." SR12 ("If file-name-2 references a relative or an indexed file, its
access mode shall be sequential or dynamic") presupposes such files are legal operands.

## Code site
`SortBinder` (the "G5 keyed slice" refusal); the emitter's USING/GIVING loops assume a sequential connector.

## What the fixer owes
USING: read a relative/indexed file in its sequential order through the existing keyed connectors. GIVING: write
relative records with the relative key 1..n (GR15 b), indexed records by prime key (an out-of-order key is the INVALID
KEY path the declarative sees). MERGE shares both arms. Goldens for relative and indexed, USING and GIVING.
