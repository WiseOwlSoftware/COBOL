# PB6180 — two forbidden-command cases fail on the Linux clone

**Observation (from the report, not re-run here).** The Linux gate of branch `wf_b65a448b-ca0-6` (HEAD 3868bd493) was RED on one leg,
`selftests`: `scripts/hooks/test_forbidden_commands.py` passed 398 of 400. The two failures are the cases
`("git push https://github.com/WiseOwlSoftware/COBOL x", False)` (line 460) and `("git push --repo=https://github.com/WiseOwlSoftware/COBOL", False)`
(line 493), both expected to PASS (the guard shall let them through because the spelled URL is the repository itself, the "same
repository spelled as a URL" cases). Unit (43049/43049) and conformance (29317/29317) legs were GREEN, and the branch touches nothing
under `scripts/hooks` (`git diff --name-only ddf3400a61..HEAD | grep -c scripts/hooks` = 0), so the red is main's.

**Likely cause (the reporter's guess).** The PB6136 push guard (13df97d260, hook rule 2c) reads a remote/URL fact that differs in the
Linux clone (the clone's `origin` URL, or a remote name the Windows checkout has and Linux lacks), so a push to the repository's own URL
is judged a push to another repository. Log: `E:\COBOL\.claude\worktrees\wf_b65a448b-ca0-6\TestResults\linux-gate\selftests.log`.

**Fix shape.** Find which fact the rule reads (probe: run the self-test on a Linux clone and print the rule's decision for the two
commands), make the test fixture supply the fact it needs instead of reading the host's, so the self-test does not depend on the clone's
remotes.
