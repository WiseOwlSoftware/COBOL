Filed 2026-10-03 by the **train-1009 lander** from wave 1009 group A's implementer report (lead 2; the same
finding is in PB1316's landing paragraph, which named it a lead and left it unfixed because the mechanism is the
GRAMMAR, not the report binder).

## Measured (wave 1009 A's build of `e08b604ca` + group A)

```cobol
       WORKING-STORAGE SECTION.
       01  KC CONSTANT AS 5.
       01  KL CONSTANT AS 2.
       01  KT CONSTANT AS 3.
       01  WS-X PIC 9 VALUE 5.
       REPORT SECTION.
       RD  R1 PAGE LIMIT 20 LINES.
       01  DET-A TYPE DE.
           02  LINE PLUS KL.
               03  COLUMN KC PIC 9 VALUE KC.
               03  COLUMN 8 PIC 9 SOURCE WS-X PRESENT WHEN WS-X = KC.
               03  COLUMN 10 PIC 9 OCCURS KT TIMES STEP 2 VALUE 1.
```

(the full program, with FD/SELECT and an INITIATE / GENERATE / TERMINATE procedure, was
`scratchpad/w1009a/p/cs1.cob` of session 5ab816c6.) `LINE PLUS KL` and `COLUMN KC` are each
`COBOL0309: unexpected 'KL'. A literal value is expected here, not a data-name`. On the same program `VALUE KC`,
`PRESENT WHEN WS-X = KC` and `OCCURS KT TIMES` already accept the constant-name and print correctly (PB1316's
sweep, probe cs2).

## Rule

§13.10.3 SR2 (checked with `cite.py --check 13.10.3 "constant-name"`): "Except in a compiler directive,
constant-name-1 may be used anywhere that a format specifies a literal of the class and category of
constant-name-1. If constant-name-1 is an integer, it may also be used to specify re…" — so if `integer-1` of the
LINE clause (§13.18.35) and of the COLUMN clause (§13.18.14) is a literal position, an integer constant-name is
legal there. The implementer should confirm against the rendered general formats that integer-n there is a
literal position (`scripts/render-spec-page.py`), and read the `SignedIntegerSlotDriftTests` rule (kb/Work PB553)
before changing the slot's rule, since that test inventories the grammar's two integer-literal rules.

## Code site

`src/Cobol.Net.Frontend/Grammar/Core/CobolReportWriter.g4` — `reportLineOperand` (line 175) and
`reportColumnOperand` (line 211) take `integerLiteral`; the data binder that reads the line/column numbers
(`DataBinder.Reports.cs`) then needs the constant's integer value through `DataBinder.FindConstant`, as the OCCURS
count already does.

## Landed 2026-10-03 (wave-1010 implementer A)

**Re-probe (main binary, the golden's program).** `LINE PLUS KL`, `COLUMN KC`, `COLUMN PLUS KR`, `LINE KA`, the
PAGE clause's `LIMIT KP LINES KW COLUMNS HEADING KH …` and `NEXT GROUP PLUS KG` each drew COBOL0309; with the
grammar fixed, `OCCURS KN TIMES STEP KS` drew COBOL0307 (the `occursStepAhead` predicate wanted an integer TOKEN
after STEP). Citations checked: `13.10.3` SR2 (`constant-name-1 may be used anywhere that a format specifies a
literal`), `5.5` 1) (integer-n "refers to a fixed-point integer literal"), `13.10.4` GR1 ("as if literal-1 … were
written"). The rendered formats print `integer-n` at every one of these positions (§5.5 1) says what that means).

**Mechanism.** The OCCURS bounds already wrote the answer privately (`occursBound : integerLiteral | cobolWord`,
`OccursBoundValue`); the report-writer clauses simply never wrote it. The ROOT is that "an integer-n position" was
spelled per clause, so each new clause forgot. One rule now: `integerOperand : integerLiteral | cobolWord`
(`CobolExpressions.g4`), written by the OCCURS bounds (`occursBound` DELETED), OCCURS DYNAMIC `FROM`/`TO`, OCCURS
`STEP`, and every integer of the PAGE, LINE, COLUMN and NEXT GROUP clauses; `DataBinder.IntegerOperandValue` is the
ONE reader (was `OccursBoundValue`), memoised per node, and it asks of a constant what the written literal is asked —
§5.5 1) unsigned and nonzero (the clause's own zero permission, `IntegerOperandRules.Classify`, keyed by the
OWNING clause through `OwnerOf`) and the host limit (COBOLNET2427). `occursStepAhead` also accepts an IDENTIFIER after
STEP. The legacy oracle's four `integerLiteral()` readers became `integerOperand()` (shape only).

**Witnesses.** `conformance:2002/pb1947_report_constant_operands` (13 constants across every position; expected
lines derived from §13.18.35.4 GR5 b) 3., §13.18.37.4 GR4 b), §13.18.14.4 GR8/GR9, §13.18.38.4 GR12 a) and printed
`LINE 03 [    5  AB   ]`, `LINE 04 [ZZ          ]`, `LINE 07 [7     7     ]`), negatives `pb1947-report-constant-operand-at-85`
(COBOLNET0900), `pb1947-report-column-constant-zero` (COBOLNET2386, a NEW verdict: a zero constant in a nonzero
slot — OCCURS had none) and `pb1947-report-line-constant-noninteger` (COBOLNET1547); the drift test
`IntegerOperandSlotDriftTests.ReportWriterGrammar_SpellsNoBareIntegerLiteral` and the re-keyed classification
inventory.

**Sibling sweep.** The same hole exists at every OTHER bare `integerLiteral` of the grammar that is a printed
`integer-n`: probed on this build, `RESERVE KR AREAS`, `BLOCK CONTAINS KB RECORDS`, `RECORD CONTAINS KB CHARACTERS` and
`DYNAMIC LENGTH LIMIT IS KB` each draw COBOL0309; the rest are `CobolIO.g4` (POSITION, RERUN, `RESERVE`), `CobolData.g4`
(BLOCK, RECORD, DYNAMIC LENGTH LIMIT, PICTURE LOCALE SIZE), `CobolSpecialNames.g4` (SYMBOLIC CHARACTERS) and the '85
Segmentation positions. They are the NEXT adopters of `integerOperand` — reported as a lead, not fixed here: each is a
different subsystem's binder reader (file, FD, special-names) outside this slice.

**Code sites for the next implementer.**
- `CobolExpressions.g4#integerOperand` — the rule a clause writes for an `integer-n`; `DataBinder.Constants.cs#IntegerOperandValue` —
  the ONE reader (memoised per node: the report binder replays a repeating entry's subtree), which asks of a constant what
  `IntegerOperandPass` asks of a literal. Adopt a new clause by writing `integerOperand` in its grammar rule, adding the
  clause to `IntegerOperandRules.Slots` (keyed by the OWNING clause: `OwnerOf` looks through the carrier) and calling the reader;
  `IntegerOperandSlotDriftTests.ReportWriterGrammar_SpellsNoBareIntegerLiteral` keeps the report writer on it.
- Trap: `occursStepAhead` (CobolParserCoreBase.cs) gates the context-sensitive word STEP on what follows it — an integer token
  was the whole predicate until a constant-name could follow.
