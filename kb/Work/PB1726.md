# PB1726 — OPEN

Filed by the train-71 lander from wave 71 group D's report (`w71d-PB1718-report.md`, new lead 3).

## Finding

On a Windows console whose encoding is cp1252, with no `PYTHONIOENCODING`, these crash with `UnicodeEncodeError`:
- `python scripts/spec/drift_rules.py .github/workflows/build-and-test.yml` (the ⛔ in a rule's text);
- `python scripts/spec/record_impact_map.py --help` and `python scripts/filter_population.py --help` (non-ASCII in
  the argparse help text).

MANDATORY-PRACTICES P11 tells every agent to run `drift_rules.py <files>` before editing, so the crash is on the
documented path.

**Code sites.** The `main` of each script.

**Fix shape.** One root cause: stdout/stderr are not reconfigured to UTF-8. Every script under `scripts/` that prints
non-ASCII should call `sys.stdout.reconfigure(encoding="utf-8")` (and stderr) at entry — sweep every script for the
same pattern, and pin it with a drift test (a script under `scripts/` whose source holds a non-ASCII character in a
printed string must reconfigure its streams) so the next script is covered automatically.
