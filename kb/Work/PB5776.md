# PB5776 - STRING into a group receiver that holds an OCCURS DEPENDING ON table with its count item inside the group stores short and reports overflow (every edition)

**What is wrong.** STRING into a group holding an OCCURS DEPENDING ON table whose object (data-name-1) is inside the group uses the current extent instead of the maximum length, so it raises a false overflow, transfers too few characters and blanks the rest of the group. Identifier-3 is the receiving item (STRING GR1); with data-name-1 inside the group the maximum length is used (`§1985:VI.5.8.4 GR3b`); only the positions referenced change (GR8), with no space filling (GR4a). Expected no overflow, `H=[5ab***] PTR=04`. Observed `OVF`, `H=[5a    ] PTR=03` at 85 and at 2023. `StringEmitter.EmitString` reads `s.Into` with the sending (current-extent) image and stores it back at the receiving maximum. The checker split this from the UNSTRING row (PB5777): a different site and the opposite direction of error. The Mythos lane did not run this program itself.
