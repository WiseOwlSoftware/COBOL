## Finding — `cobol-character-repertoire` (rejects-legal-source; rows `GR-8.1.3.2-4`, `GR-8.1.3.2-3`)

**Mechanism.** The lexer's word-character class NAME_BODY/NAME_TAIL is ASCII-only ([a-z0-9_-]), so no Annex B extended letter can appear in any COBOL word although docs/CONFORMANCE.md A.4.6 claims the Extended letters module; the case-folding (b) and combining-character length (c) legs are therefore unreachable

**Expected from the spec.** Compiles and DISPLAYs 'abc': U+00C9/U+00E9 are Annex B characters present in the UTF-16 compile-time coded character set, hence extended letters (8.1.3.2 GR4 a), legal COBOL-word characters (8.3.2.1), and the uppercase form folds to the lowercase one per Annex C (GR4 b), so CAFÉ and café are the same data-name. A combining character in a word counts as its own character toward the 63-character limit (GR4 c).

**Observed / reasoning.** error COBOL0001: cannot parse construct near 'É' and COBOL0307: unexpected 'é'; likewise 01 ÄRGER -> COBOL0307 unexpected 'Ä'. When fixed: the binder's 63 StringComparer.OrdinalIgnoreCase sites are invariant upper-casing, not Annex C lower-folding -- they diverge on extended letters (U+0130, U+212A ...), so the fix needs ONE Annex C folding function the name tables share (rule 5: shape that makes the next case automatic), plus the 2014->2023 Annex B deltas (E.2 item 4: U+037A deleted, U+30FB not first/last) gated per edition, and the 8.3.2.1 63-character count by code point with combining marks counted separately.

## Finding — `cobol-words` (rejects-legal-source; rows `GR-8.3.2.2-L2.2`, `SR-8.3.2.2-3`)

**Mechanism.** The lexer's COBOL-word rule admits only basic letters: NAME_BODY is built from [a-z] (case-insensitive), digits, hyphen and underscore, so ANY extended letter in a user-defined word is a lexical error — while docs/CONFORMANCE.md claims Annex A.4.6 'Extended letters' as Claimed (on the strength of the national-literal repertoire, which is a different facility)

**Expected from the spec.** With A.4.6 claimed, é and Ü are extended letters (Annex B) and the programs compile; Xé displays ABC, and case folding per §8.1.3.2 4) b) makes XÉ the same word. If the owner instead declines A.4.6, CONFORMANCE.md must say Not claimed and the §8.3.2.2 externalized-extended-letter determination (PB661 item a) follows from that.

**Observed / reasoning.** Lexer error at the first extended letter at 2002 and 2023. Either the lexer (NAME_BODY / NAME_TAIL and the word-length measure of §8.1.3.2 4) c)) must admit the Annex B set, or the claim is false; this is an owner-visible conformance claim contradiction.

## Wave 1005 group B — NOT STARTED (SPLIT at the note boundary; what the next implementer should know)

The wave-1005 implementer finished PB1372, PB1915, PB1669 and PB1459 (its turn budget did not cover this note) and read only the
spec side of this one. Verified facts: ISO §8.1.3.2 rule 4 a) "A character in Annex B is included in the set of extended letters if it
exists in the implementor-defined compile-time coded character set", b) Annex C case folding of an uppercase extended letter, c) "the
base character and each combining character are treated as separate characters in determining the length of a user-defined word";
§8.3.2.1 (63 characters); Annex B.1/B.3 is the UAX #31 (Unicode 13.0.0) XID_Start repertoire plus the basic digits (the supplementary
planes are in it: Adlam 1E900-1E943, Ahom 11700-1171A, …); A.1 items 20 (case mapping) and 219 (externalized words) and A.4.6 are the
claims. The frontend lexes a `string` through `AntlrInputStream`, i.e. UTF-16 code UNITS, and many readers index that text by token
offsets (`som.Start.InputStream.GetText`, `PictureSeparatorPeriodRule`, `SeparatorRule`, the debugging-line carrier blanking), so
switching the whole lexer to a code-point stream is itself a redesign; the lexer class for supplementary-plane letters needs either that
or a surrogate-pair arm.
**Hypotheses NOT yet checked (verify before relying):** that ANTLR 4.13.1's lexer-set syntax `\p{XID_Start}` / `\p{XID_Continue}` is
accepted by the generator for the C# target and which Unicode version its tables carry (Annex B pins 13.0.0, so a newer table needs a
frozen 13.0.0 subtraction or a generated Annex B set, with a drift test against the spec text, like `ContextSensitiveWordsDriftTests`);
that the 63 `OrdinalIgnoreCase` name comparisons the note counts are all the places that fold names (the C# emitter derives .NET
identifiers from COBOL names too, so an extended letter must also survive that sanitizer). The shape the rule-5 design wants: ONE
Annex C folding function (`CobolNames.Fold`) that every name table shares, with a drift test that no `StringComparer.OrdinalIgnoreCase`
remains over a COBOL name, plus a per-edition Annex B delta (E.2 item 4: U+037A deleted, U+30FB not first or last).
