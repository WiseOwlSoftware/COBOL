# PB3947 — CldrLocaleLoaderTests reads the CLDR site directory that LocaleCollationFailureTests sets through a process-global environment variable, and is not in [Collection("process-globals")]

**Sites:** `tests/WiseOwl.Cobol.Tests.Unit/CldrLocaleLoaderTests.cs`, `tests/WiseOwl.Cobol.Tests.Unit/LocaleCollationFailureTests.cs` (`SiteDirectory`)

`LocaleCollationFailureTests.SiteDirectory` sets a process-global environment variable; `CldrLocaleLoaderTests` reads
the CLDR site directory it names, and is not in `[Collection("process-globals")]`. xUnit runs the two classes in parallel, so
one test can read the other's directory. It did not recur in the PB3635 review (unchanged from round 1), but it is a race
by construction, so a red would be a CI flake that no local run reproduces (the CI invariant).

## Acceptance
- Both classes (and every other reader or writer of that variable) join `[Collection("process-globals")]`; a drift test
  that every test class touching a process-global environment variable names the collection (seen RED first on this pair).
