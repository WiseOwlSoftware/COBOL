**Rule it breaks:** one rule in one place (DESIGN-architecture-review §5.2; CLAUDE.md rule 4): ISO §14.9.43.3 SR1 and §14.9.22.3 SR1/SR2 state the same predicate ('described implicitly or explicitly as usage display or national'), which ItemCategory.UsageOf is documented as THE ONE READER of and StatementValidation.IsInspectElementaryCharacterItem implements for INSPECT; StringUnstringBinder.Sr1Offence re-derives it from Pic.Usage guarded by !IsGroup, plus a storage-form StoreAsImage exemption (a post-bind StorageFormPass fact, always false at procedure bind)

**Scenario:** Measured with the 2026-10-15 Debug cobol.exe (Sr1Offence is unchanged between the pin and HEAD): `01 BG GROUP-USAGE BIT. 05 B1 PIC 1(8) VALUE B'01000001'. 05 B2 PIC 1(8) VALUE B'01000010'.` then `STRING BG DELIMITED BY SIZE INTO R` compiles clean and runs, storing 0100000101000010 into R; the same BG as `INSPECT BG TALLYING N FOR ALL 'A'` is refused COBOLNET1626 citing the word-identical SR1 of §14.9.22.3. §13.18.29.4 GR1b treats the bit group as an elementary item of usage bit, so STRING SR1 is violated and a syntax error is owed (under-rejects; the bit string is then sent as characters). Root: Sr1Offence's elementary arm requires !Item.IsGroup and its group arm handles only the strongly-typed group, so the as-if elementary bit group (OperandPic usage Bit) falls to `_ => null`; the shared reader answers Usage.Bit for it. The same function is SR1's identifier-3 (INTO) screen, so STRING ... INTO BG is admitted the same way.

**Measured how:** R2 batch finding `procedure-binding-5--duplication--f2#1` (pair procedure-binding-5--duplication), read in the pinned tree at 8be23006851a; skeptics rule upheld, scenario upheld, site upheld.

**Spec:** §14.9.43.3 "all identifiers, except identifier-4, shall be described implicitly or explicitly as usage display or national" (`cite.py --check` passed at collection); §13.18.29.4 "a bit group is treated as though it were an elementary data item of usage bit and class and category boolean" (`cite.py --check` passed at collection)

**Target:** ONE predicate for 'an operand described implicitly or explicitly as usage display or national' in Binding.Model.ItemCategory (beside UsageOf, which it reads), with the strongly-typed group's leaf-usage reading (FirstLeafOutsideDisplayOrNational) as its strongly-typed arm; STRING SR1 (Sr1Offence) and INSPECT SR1/SR2 (StatementValidation.IsInspectElementaryCharacterItem, which §8.3 moves into InspectRules) both ask it, and the StoreAsImage exemption is deleted (a storage-form fact is not a usage). A drift test pins that every rule worded with that phrase asks the one predicate. Lands through the fix lane with a bit-group golden for STRING identifier-1/-2/-3.

**Design reference:** §8.3.

**Landed (wave 1111 F).** Re-probed: `STRING BG DELIMITED BY SIZE INTO R` over a `GROUP-USAGE BIT` group compiled clean while `INSPECT BG TALLYING` was refused COBOLNET1626. Fix at the root: ONE predicate for "described implicitly or explicitly as usage display or national" in `ItemCategory`, beside `UsageOf`: `IsDisplayOrNationalUsage` (positive; INSPECT's elementary arm, `StatementValidation.IsInspectElementaryCharacterItem`, asks it) and `UsageOutsideDisplayOrNational` (the offending item, for STRING SR1's diagnostic; null when described display/national or when the standard states no usage, a variable-length group). The strongly-typed group's leaf walk is its strongly-typed arm, moved out of `StringUnstringBinder`; the `StoreAsImage` exemption is deleted (a storage form is not a usage: a Tier-B BINARY or PACKED leaf is stored as a character image too with its `Pic.Usage` unchanged, and the post-bind flag is not yet computed when procedure binding runs, so the exemption was dead code). Goldens: three refusals `14.9.43-STRING/pb3228-string-bit-group-{sender,delimiter,receiver}` (COBOLNET1626, identifier-1/-2/-3, 2002+) and the positive control `pb3228_string_group_usage_controls` (alphanumeric group, national group). Drift test `DisplayOrNationalUsagePredicateDriftTests` pins that STRING and INSPECT ask the one predicate and that the leaf walk exists once. Citations `--check`ed: §14.9.43.3 SR1, §14.9.22.3 SR1/SR2, §13.18.29.4 GR1 b)/GR2 b), §8.5.2.1, §8.5.1.12.1. No diagnostic code used.
