# PB3180 — a merge commit is charged with what its parents carry

## The defect

`scripts/orchestrator/landing_check.py` `check()` attributes R3 work PER COMMIT (PB2703): for every `sha` of
`rev-list base..rev` it read `work_notes(git, f'{sha}^', sha)` and `changed_files(git, f'{sha}^', sha)`. For a MERGE
commit `sha^` is its FIRST parent, so:

- a merge that brings a predecessor branch in (a review finisher's `Merge worktree-… for the review finisher`, first
  parent main) is charged with the predecessor's WHOLE diff — every note its commits flip, every subject id in
  `sha^..sha`, every file they change — although the same `rev-list` already enumerates each of those commits one by
  one, so the merge double-counts them and SMEARS one commit's R3 note across other commits' files;
- a `Merge origin/main into <branch>` commit (first parent the branch) is charged with main's own landings since the
  branch point, R3 ones included.

## Repro (measured 2026-10-15)

Branch `worktree-wf_15ec6338-3a0-4` (PB3154, HEAD 9c45f7c61): `python scripts/orchestrator/landing_check.py --rev
worktree-wf_15ec6338-3a0-4 --base origin/main` STOPS with `R3 work (PB2160) changed N file(s) outside its declared
file set (computed now): src/WiseOwl.Cobol.Compiler/Binding/DataBinder.Constants.cs, …IoControl.cs,
tests/WiseOwl.Cobol.Tests.Unit/GlobalNameClassDriftTests.cs …`. The only commit that works on PB2160 is 18246d045
(`WIP checkpoint: PB3154 landed in the register (and PB2160, absorbed)`), which changes kb/Work and DEVLOG only. The
files come from merge dacb04b6c (parents c29af1704 = main, 04778967c = the predecessor worktree-wf_84f0c364-28e-17),
whose first-parent diff includes 18246d045's PB2160 flip and the predecessor's .cs files. The false stop holds PB3154
out of the merge queue, and with it PB3153 (3a0-19) and PB3164 (423-5), which wait for 3a0-4 by the same check.

## The rule

A merge commit is attributed only what the MERGE ITSELF introduced, never what its parents carry: the files that
differ from EVERY parent (combined-diff semantics, as `git diff-tree -c` lists them: conflict resolutions and
evil-merge edits), the notes whose `status` it changes relative to every parent, and the ids leading its OWN subject.
A non-merge commit is attributed its diff against its one parent, as before.

## Landing

Fixed at the root in `scripts/orchestrator/landing_check.py`: ONE attribution function, `commit_work(git, base,
rev)`, walks `rev-list --reverse --parents base..rev` and returns, per commit, (the notes it works on, the files it
changed), each charged only with what the commit introduced. A non-merge commit is its diff against its parent (a root
commit's against git's empty tree); a merge commit is the INTERSECTION over its parents of the per-parent file lists
and per-parent status flips (the combined-diff set), plus the ids leading its own subject. `status_flips(git, *revs)`
is the register-patch reader `work_notes` and `commit_work` now share; `check()`'s per-commit loop reads only
`commit_work`. Self-test cases PB3180a (a merged predecessor's R3 flip and fix-lane code edit stay apart), b/b'/b''
(an R3 merge's conflict resolution and evil-merge edit still stop; a resolution that takes the other parent's version
introduces nothing), c (a `Merge origin/main` carrying main's R3 landing is not the branch's) and d (a root commit):
a, b'' and c failed on the first-parent code, 31/31 pass now. The repro (`--rev worktree-wf_15ec6338-3a0-4`) went from
`STOP (1 stop(s), 9 warning(s))` to `PASS (0 stop(s), 0 warning(s))`: the nine warnings were the same smear (the
smeared .cs files made every shared file R3).

Sibling sweep (every per-commit parent diff in scripts/): `prune_worktrees.mechanical` already compares a merge with
`git merge-tree` of BOTH parents and a single-parent commit with `diff-tree` (right); `prune_worktrees.train_clusters`
and `spec/audit_witness_loss.history` walk `--first-parent` on purpose (a train's own commits; what each landing added
to main); `devlog.stamp_floor` reads the first parent of a non-merge stamp commit (right). Every other diff is
range-level (`plan_wave.changed_files`, `identity()`'s `work_notes(base, rev)`).

For the next implementer: `landing_check.py#commit_work` owns per-commit attribution; never diff `sha^..sha` for a
commit's work. `landing_check.py#status_flips` is the one register-patch reader. Trap: a self-test merge with a
conflict needs `merge --no-commit` without `check=True`, then the resolution written and committed.
