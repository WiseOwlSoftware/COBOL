# PB818 — LANDED — the BY CONTENT arm of PB204's rim

Filed 2026-09-09 by the registrar (second pass) from the **PB393 implementer's report**, "New defects" (2) —
`scratchpad/reports/PB393-report.md`, which left it untouched with the note *"kb/Work PB393 names PB204 as the

⛔ **It is filed as its own note, and the reason is register hygiene, not disagreement.** [[PB204]] is
`status: landed`. Its closing section names this exact residue — *"BY CONTENT/BY VALUE at the CALL boundary, the
dynamic Format-1 runtime EC, and the prototype lane remain"* — and an open obligation living inside a closed note
is invisible to `work.py next` and to every reader who filters on `status: open`. That is the [[PB786]]

work register can rank.

## The defect

`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/OoBinder.cs:719`:

```csharp
return arg.IsImageCapable ? null : "the argument group has no character image (Tier-C)";
```

`IsImageCapable` is false for a variable-length group, so a legal BY CONTENT group argument is refused. Its BY
REFERENCE sibling, `OoConformance.DescriptionMismatch`, was corrected by [[PB204]] to
`BoundaryImageCapable` + `VariableLengthCompatibility.Mismatch`; this line was not. One dispatch, two arms, one
fixed (`feedback_two_arm_dispatch` — the most reproducible defect shape in this project).

## The rule, quoted, with the `--check` line actually run

```
$ python scripts/spec/cite.py --check 14.8.2.2 "If either the formal parameter or the argument is a variable length group, the formal parameter and the argument shall be compatible, as described in 8.5.1.12"
OK  §14.8.2.2 2)  (Group items)
    If either the formal parameter or the argument is a variable length group, the formal parameter and the
    argument shall be compatible, as described in 8.5.1.12, Variable-length groups.
```

§14.8.2.3.3 makes the BY CONTENT crossing a MOVE, and §8.5.1.12.1 admits a variable-length group whose other
operand is a compatible group — which is exactly what §14.8.2.2 says for BY REFERENCE. The compatibility
predicate the rule names **already exists** on this tree: `VariableLengthCompatibility`, written by PB204.
