shared-primary-file rule), `scripts/orchestrator/land_lane.py` (exit 4 and a DIRTY pull request),

## What happens (measured 2026-10-24)

- **A whole subsystem for a note with no site block.** The loop's fix-lane wave w20261032 dispatched group A (PB493,
  PB3280, PB539, PB494, PB538, PB1319, PB3162: the SYNCHRONIZED and SIGN clauses in `DataBinder.cs`) and group B
  (PB547: the character size of alphanumeric items). None of their notes has a site block, so `collision` treats their
  sets as UNKNOWN and the dispatch ledger records group A with 234 files (all of `src/Cobol.Net.Compiler/Binding/`) and
  group B with 222. The owner-approved fuzz fixes PB3664 (`CobolEdit.cs`) and PB3665 (`StringUnstringBinder.cs`) then
  planned as "waiting (a later wave): file-set collision with in-flight work", although neither group's mechanism
  touches those files.
- **One file, one group.** A known set meets another on any shared FILE, and `check_practices.py` refuses two groups
  of one wave whose roots name the same primary `src/` file unless one is the other's successor. Two groups editing
  different methods of one file, which git's three-way merge combines cleanly, never run side by side.
- **What the rule was answering.** The conflicts of the day were real line overlaps: PB3628 and PB3275 rewrote the same
  NOT QUEUED rule in `prune_worktrees.lifecycle` (PR #505 DIRTY), and PB3612 met PB3310 in the same code of
  `enqueue.py`. PB3640 already concluded that no partition removes conflicts, because a declared set is a prediction,
  and that the cost reducer is resolving a conflict at once on small, short-lived branches.

## The bar

1. **Members, not files.** Two groups meet only when the members they change overlap. A member is a method, property,
   constructor or type-level declaration with its line range in the member index (`member_index.py`, which
   `declared_sets` already loads). For a file the member index does not cover (Python, PowerShell, a design doc), use
   the same rule at that file's natural unit (a Python function via `ast`, a Markdown section), or let the groups share
   it and rely on rule 4. Two groups on different members of one file are planned in the same wave. `check_practices.py`'s
   shared-primary-file refusal becomes a shared-MEMBER refusal.
2. **Never a whole subsystem.** A note with no site block reserves no subsystem. The planner locates its sites at plan
   time (from the code sites its text names, `orient.py` or a `cobol-locator` lookup recorded back into the note) or
   dispatches it UNPARTITIONED, without holding it or anything else. The implementer adds the `**Sites:**` paragraph in
   its first checkpoint (the spec tail already says so), and the ledger's entry is narrowed to those sites when it lands.
3. **Callers only for a moved or re-signed member.** A body-only change reserves no callers. Only a note that moves,
   renames or changes the signature of a member reserves its callers (the build-breaking case), and CI's merge-group
   run catches the rest.
4. **A real conflict is repaired at once.** When `enqueue.py land` exits 4 or a queued pull request reads DIRTY, the
   landing lane dispatches the conflict finisher at that moment, with both branches' notes and reports in its brief
   (PB3640's direction, beside PB3608's review lane), instead of waiting for the next serial enqueue unit.
5. **Measured.** Over the first day of waves after the change, record per wave the groups held by a collision and their
   reasons, and per landing the conflicts and their causes (`landing_measure.py` bounce causes). Compare with the day
   before. Self-tests: two groups on different members of one file are planned together; two on one member are not; a
   note with no site block holds nothing; a re-signed member holds its callers.
6. **The docs follow the code** in the same change: DESIGN-architecture-review §8.7 (the declared set),
   DESIGN-orchestrator-loop (the partition), the workstream skill's rolling-wave text and MANDATORY-PRACTICES O2 (both
   say `check_practices.py` refuses two groups on one primary file), and the operator memory that says never to dispatch
   an UNPARTITIONED plan.

**What changed (items 1, 2, 3, 5 and 6).**
1. Members, not files. `scripts/arch/source_units.py` (new) reads the natural unit of a file: a C# member (a tokenizer
   covering every string form, and a brace walk; all 7,523 tracked `.cs`, `.py` and `.md` files read), a Python function
   or method (`ast`), a Markdown section, and a type's own lines as `Type.<own>`. `touched` maps a diff's hunks to units
   on both sides. `work.note_sites` reads the members a site block names (`path#Member`, or `` `path` (`member`, ...) ``
   when the parenthesis opens with a code span). `plan_wave.Claim` carries files and members, and `collision` meets
   only on a file either side claims whole or on a matching member. A merge-driver file never meets.
   `inflight_units` reads the units each worktree's and branch's actual diff touches in shared files, using batched
   git (one diff-tree, two cat-file calls). The ledger, the groups file (`member_set`) and `make_dispatch_specs.py`
   carry member claims. In a wave, two groups on one primary file chain only when their claims there meet.
   `check_practices.py`'s O2 refusal is now a shared-MEMBER refusal.
2. Never a whole subsystem. An empty set meets nothing (PB3263's subsystem rule and `plan_wave.subsystems` are deleted).
   A fix-lane note's folder site reserves nothing. The plan and spec name an empty group UNPARTITIONED and ask for
   Sites with members in the first checkpoint.
3. Callers only for what moves, renames or re-signs. The `**Moves or changes:**` / `r2_members:` / doc-id names keep
   their callers, and each caller file is claimed whole. A body-only edit is a site member and reserves no caller.
   The fix lane never reserves callers.
5. Measured. Every dispatched wave appends `partition_record` to `<coord>/partition-measure.jsonl` (same-file pairs run
   side by side, notes held and why). `plan_wave.py --partition-summary` prints it per day. The landings' conflicts
   are `landing_measure.py`'s bounce causes. Self-tests (`test_plan_wave.py` section 12 and the 9-series,
   `member_index.py`, `source_units.py`): two groups on different members of one file are planned together, two on
   one member are not, a note with no site block holds nothing, and a re-signed member holds its callers.
6. The docs follow: DESIGN-architecture-review §8.7, DESIGN-orchestrator-loop section 9 items 1b and 4 and the campaign
   paragraph, the workstream SKILL.md, MANDATORY-PRACTICES O2, and `work.py`'s SITES rule text.
