# PB2689 — the element pair skips §8.5.1.12.3 sentence 3

## What was found (w1042 C, PB2496, landed in train 1042)
PB2496 made a dynamic-capacity table whose elements are variable-length groups move and compare element by element.
Its implementer found that the compatibility walk applies the §8.5.1.12.3 matching rule only at the top level of a
pair. Inside an element pair it compares the elements' STATIC byte lengths first, so an element that holds a
dynamic-capacity table facing an element that holds a fixed `OCCURS 2` table differs by element bytes (1 against 2)
and the pair is refused with COBOLNET1931.

§8.5.1.12.3 (`cite.py --check` OK): "If one of the corresponding tables is not a dynamic-capacity table, that table is
treated as though it were a dynamic-capacity table whose capacity is either its fixed number of occurrences or the
value of the DEPENDING operand, as applicable. For purposes of determining compatibility, the dynamic-capacity table
is considered to be the same length as the corresponding table." The groups are compatible, so the MOVE is legal
source (§8.5.1.12.1).

## Repro
`E:\COBOL-coord\scratch\w1042c\p\n2.cob`, edited so the receiving element's inner table is `IB OCCURS 2` (the probe as
saved uses a dynamic table on both sides). Expected: compiles at 2014+ and moves element by element; observed:
COBOLNET1931.

## Site
`src/Cobol.Net.Runtime/Values/GroupCompatibility.cs#Walk`, the `ElementBytesDiffer` arm (around line 168): the
`x.ElementBytes != y.ElementBytes` test runs before the walk recurses into `GroupAtom.Element`. When either element
carries a dynamic-capacity table (directly or nested), its static byte length is not its length for compatibility;
the test belongs AFTER the element recursion, or must be skipped for an element that contains a dynamic component.
The same comparison sits in the atom equality at line ~329 (`x.ElementBytes != y.ElementBytes`); sweep both.

A 2014 positive golden: element `05 E OCCURS DYNAMIC` of `10 IA OCCURS DYNAMIC` against `05 F OCCURS DYNAMIC` of
`10 IB OCCURS 2`, MOVE and compare, values derived from §14.6.9.2/.3.
