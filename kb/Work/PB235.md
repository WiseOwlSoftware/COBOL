# PB235

**Rows:** `GR-14.9.6.4-2`, `GR-14.9.6.4-L2.1`, `GR-14.9.6.4-7`, `GR-14.9.6.4-9`

CLOSE changes only a status: there is no unit-media category, no volume pointer, no file position indicator, no record-area availability bit — and `CLOSE … UNIT` releases neither the file lock nor any record lock.

Rows: GR-14.9.6.4-2 (the four physical-file categories Table 14 is indexed by), GR-14.9.6.4-L2.1 (Table 14 symbol e, 'Close unit', the input / input-output unit-media branch, item 1), GR-14.9.6.4-7 (record-area availability after CLOSE), GR-14.9.6.4-9 (the file lock and record locks released by CLOSE). ONE post-close state model that consists of a status assignment.

MECHANISM, re-verified live at HEAD. FileRegistry.CloseReelUnit is four lines: narrow to a SequentialConnector, set a status, return. It never calls SharedClose or PhysicalFileTable.ReleaseAllForConnector (FileRegistry.Close, five lines away, does both), it never touches a file position indicator, and there is no volume pointer, unit counter or unit-swap concept anywhere in src/Cobol.Net.Runtime/IO/ — a grep for volume / unit swap / reel returns only the CLOSE doc comments plus unrelated CobolDate text. On the compiler side SequentialIoEmitter.EmitClose touches only the runtime call, the status store and the USE hook, and nothing anywhere consults the SAME RECORD AREA grouping at CLOSE time.

GR2 — NO CATEGORY MODEL (process_only, plus a required documentation obligation). GR2 partitions physical files into (a) Non-unit, (b) Sequential single-unit, (c) Sequential multi-unit, (d) Non-sequential single/multi-unit (definitions re-read at specs/ISO_COBOL.md:22980-22988), and those four names are Table 14's column headings, so a conforming implementation must place each supported physical file in exactly one. The (a)/(d) half IS realized structurally by the SequentialConnector vs Relative/IndexedConnector split — a real type the runtime dispatches on — but (b)/(c) have no representation at all, so two of Table 14's columns are unreachable, and the placement of every SequentialConnector file into (a) exists ONLY as an undocumented sentence in one comment on CloseReelUnit ('CLOSE … REEL/UNIT on a disk medium: a no-op that leaves the file open with status 07 (the file is not reel-structured)'). That is defensible only as an implementor statement that no supported medium is reel/unit structured — and Annex D item 24 makes GR3c a REQUIRED documented implementor item ('CLOSE statement (closing operations). This item is required. This item shall be documented in the implementor's user documentation. (14.9.6, CLOSE statement, General rule 3c)', verbatim at specs/ISO_COBOL.md:34264), while `grep -n '14\.9\.6\b' docs/CONFORMANCE.md` returns NOTHING.

L2.1 — THE UNIT-MEDIA BRANCH HAS NO CODE. Symbol e's branch for input and input-output files on unit media, item 1: when the current unit is the last or only unit, CLOSE UNIT performs no unit swap, leaves the current volume pointer unchanged, and sets the file position indicator so that no next or previous logical record exists (a following READ NEXT is at-end, a READ PREVIOUS is at-end). CloseReelUnit sets a status. The implementation instead always takes symbol e's THIRD branch (non-unit media), which is correct for its own category — but that makes this branch unreachable, not implemented, and the categorisation that makes it unreachable is the undocumented comment above.

GR7 — HALF (b) HAS NO IMPLEMENTATION (silent). Half (a) — the record area stays AVAILABLE after a CLOSE while another connector named in the same SAME RECORD AREA clause is open — holds by construction: BindIoControl binds Format 2 (selected by RECORD being PRESENT — note the row's own note inverts that sense; the code is `if (clause.sameClause() is not { } same || same.RECORD() is null) continue;`) by pointing every member file's first record at a shared anchor, `f.Records[0].RedefinesTarget ??= anchor`, cited to §12.4.6.4.4 GR2 (cite.py --check 'implicit redefinition' → OK); the area is a live typed field in the emitted class and nothing on the CLOSE path invalidates it. Half (b) — a successful non-UNIT CLOSE makes the record area UNAVAILABLE — has no availability bit on FileModel or FileConnector, no clearing step in EmitClose or CloseCore, and a grep for RecordAreaAvailable finds only two unrelated doc comments (FileModel.cs:211, KeyedIoEmitter.cs:128). The pre-CLOSE content simply persists and remains readable. The implementation cannot tell case (a) from case (b): it is right in (a) by accident and absent in (b).

GR9 — THE UNIT PATH RELEASES NOTHING (under_rejects). Half (a) IS implemented and pinned: FileRegistry.Close calls SharedClose (st.Open.Remove drops the connector's file-level open registration that Table-19 arbitration consults; ReleaseAllForConnector drops every record lock it holds), and conformance:2002/file_sharing_seq.cob:108-115 is a spec-derived golden whose source comments cite §9.1.16, §14.9.51 GR11 and §14.7.9 — an EXTEND connector appends WITH LOCK, the reader gets '51' then RETRY FOREVER bails to '52', then `CLOSE F-C.` and the READ yields `D4=00 DDDDD`; corroborated for the file-level lock by unit:CobolFileLockTests.DeleteFile_OpenByAnotherConnector_62_ThenCloseFrees. But GR9 has no 'without the UNIT phrase' qualifier and CloseReelUnit calls neither SharedClose nor ReleaseAllForConnector, so `CLOSE F UNIT` leaves the file lock and every record lock held while the program believes it closed. One caveat recorded on the row and worth keeping: SharedClose runs BEFORE the connector's own Close, so locks are released even on an unsuccessful CLOSE ('42'); the rule says 'released by the execution of the CLOSE statement' rather than 'of a successful CLOSE', so that reads as conforming — but it is the same unconditional-side-effect shape that IS a defect on the WITH LOCK path (GR-14.9.6.4-1), and a golden should pin the intended reading.

NOT PART OF THIS NOTE'S DEBT: GR9's other half — 'Except when the file is specified in an APPLY COMMIT clause' — cannot be honoured because APPLY COMMIT exists nowhere in src/ (no ioControlClause APPLY arm in any .g4, no ApplyCommit anywhere in C#), and that is licensed by the documented A.4.3 commit/rollback non-support (docs/CONFORMANCE.md §4 item 2, §5 row A.4.3 'Not claimed'). Carved out here so nobody re-files it.

WHAT WOULD CLOSE IT: a named category model — or an explicit documented determination in docs/CONFORMANCE.md that every supported medium is category (a)/(d), which discharges Annex D item 24 and makes L2.1 legitimately vacuous; a record-area availability transition on FileModel/FileConnector consulted by EmitClose and aware of the SAME RECORD AREA grouping; and a lock-release step on the REEL/UNIT path (or a derivation showing it should not have one). Goldens: two files in one SAME RECORD AREA clause with one closed and one open; a `CLOSE F UNIT` followed by a second connector's OPEN.

SPEC REFS as carried by the rows: §14.9.6.4 GR2, GR3c and Table 14 symbol e, GR7, GR9; Annex D item 24 (verbatim at :34264); the undefined-behaviour annex entry for an unsuccessful CLOSE without UNIT; §12.4.6.4.4 GR2 (cite.py OK); §9.1.16; §14.9.51 GR11; §14.7.9.

## Landed — 2026-09-05

**ONE post-close state model, and it is Table 14 itself.** `PhysicalFileCategory` (new,
`src/Cobol.Net.Runtime/IO/CloseTable14.cs`) carries §14.9.6.4 GR2's four categories with each definition
quoted and `cite.py --check`ed; `FileConnector.Category` is ABSTRACT, so the placement is total by
construction — `SequentialConnector` (a) Non-unit, `RelativeConnector`/`IndexedConnector` (d). `Table14.Cell`
returns the printed symbol set for all 16 (format × category) pairs and `FileRegistry.CloseByFormat` is the
ONE dispatch that executes it, replacing three hand-copied per-form transcriptions of the Non-unit column.
`CLOSE … REEL/UNIT FOR REMOVAL` became its own Table 14 row end to end (`BoundCloseKind.ReelUnitForRemoval`,
`CobolFile.CloseReelUnitForRemoval`), which finally gave `opt.REMOVAL()` a consumer. §14.9.6.4 GR1 is hoisted
to the top of that dispatch, so an unsuccessful CLOSE performs none of the closing actions — the
unconditional `SharedClose`-before-`Close()` shape this note flagged as a caveat is gone. The two bare `"07"`
literals became `FileStatusCode.PhraseOnNonReelMedium`, whose doc carries §9.1.13.2 item 6 — the clause that
FORCES the category (a) placement rather than leaving it a preference.

**Annex A.1 item 24 is discharged** (the note called it Annex D; it is A.1). `docs/CONFORMANCE.md` §7 now
carries the item 24 row — the (a)/(d) placement and why it is forced, the closing operations symbol c names,
and the post-CLOSE record-area realization — and §2 rows 28–30 / 33–34, which read as a contradiction of the
code comments, now cite it. `audit_annex_a1.py` moves 42 → 43 required items discharged. §8 gains
`DRV-GR-14.9.6.4-L2.1` (arm `unpopulatable-antecedent`), the same medium determination the owner already
signed for `DRV-GR-14.9.30.4-20`/`-23`. Design: `docs/COBOLNET_FILES_DESIGN.md` **D11**.

**Two of this note's charges did NOT survive re-probing, and the report says so.** (1) GR9 — `CLOSE F UNIT`
already retained the file lock (a second connector's OPEN still `61`) and the record locks (another
connector's READ still `51`) at HEAD, and that is CORRECT: Table 14 gives `CLOSE UNIT` symbol e alone, whose
non-unit branch is *"the file remains in the open mode … and no other action takes place"*, and GR9's release
rides symbol c "Close file". Releasing an open connector's own lock would leave it arbitrating against
nothing. The note's `under_rejects` harm claim was inverted; `conformance:2002/pb235_close_unit_locks` pins
the derived reading through both lock kinds and both arms. (2) GR7 half (b) — "no availability bit" is not a
gap: the standard defines nothing about referencing an unavailable record area (Annex A.2 item 5 makes the
unsuccessful case outright undefined), so it is a DETERMINATION, now stated in §7. Half (a), the half a
program CAN observe, holds structurally and is pinned by `conformance:85/pb235_same_record_area_close`.

**Rows re-verdicted** — `GR-14.9.6.4-2` PARTIAL→CONFORMS, `GR-14.9.6.4-L2.1` NOT-IMPLEMENTED→CONFORMS (on the
derivation), `GR-14.9.6.4-7` PARTIAL→CONFORMS, `GR-14.9.6.4-9` PARTIAL→CONFORMS. GAP 2969 → 2965.

**Drift test, falsified once.** `CloseTable14Tests` pins the 16 cells against the printed table, asserts both
enums still have exactly four members (the `_` arm C# requires for out-of-range casts would otherwise swallow
a new one), and PLACES each connector kind through the behaviour Table 14 assigns rather than through a
getter. Corrupting the (Unit, NonUnit) cell to `e,f` reddened three tests including the dispatch's own loud
arm; restored and green.
