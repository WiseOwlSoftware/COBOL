# PB5656 - goldens whose `rules:` trace to the wrong inventory rows

One mechanism: a golden's `rules:` list is what the inventory reads as the witness of a row, so a golden that lists the neighbouring rule credits the
wrong row and leaves the right one with no witness.

**1. `pb5602-control-footing-other-occurrence` (PB5602 R2-1 LEAD, low).** `conformance-suite/cases/13.16.15@2002-CONTROL-CLAUSE/pb5602-control-footing-other-occurrence.cob:3`
declares `rules: [2002-SR-13.16.15.2-3]` (CONTROL clause SR3), but the rule it witnesses, and the one its own comment cites ("the same as one of the
operands of the CONTROL clause", §2002:13.16.55.2 SR10), is catalog id `2002-SR-13.16.55.2-10`. Verified in this filing: `cite.py --check "§2002:13.16.55.2
SR10" "shall be the same as one of the operands of the CONTROL clause"` OK; `2002-SR-13.16.55.2-10` is in `docs/rearchitecture/spec-rule-catalog-2002.json`
(and `tests/version-matrix/inventory-2002/` holds -9, -11, -13..-16 for that clause but no -10 file: the fixer checks why before crediting the row).

**2. `pb5598-base-inline-new-2002` and `pb5598-base-inline-new-refused` (PB5598 R2-1 LEAD, low).**
`conformance-suite/cases/13.16.40@2002-PROPERTY-CLAUSE/pb5598-base-inline-new-2002.cob:3` and
`conformance-suite/cases/13.16.40@2002-PROPERTY-CLAUSE/pb5598-base-inline-new-refused.cob:3` both declare `rules: [2002-SR-8.4.2.9.2-5, 2002-GR-13.16.40.3-1]`
(object property / PROPERTY clause rows) and sit in the PROPERTY-CLAUSE directory, but they witness the inline invocation of BASE New: 2002 8.4.2.4.2 SR4 /
8.4.2.4.3 GR1, and, for the 2014/2023 refusal twin, the 2023 `SR-8.4.3.4.3-4`. Catalog ids present: `2002-SR-8.4.2.4.2-4`, `2002-GR-8.4.2.4.3-1`
(spec-rule-catalog-2002.json) and `SR-8.4.3.4.3-4` (tests/version-matrix/inventory/). Verified: `cite.py --check "§2002:8.4.2.4.2 SR4" "shall not be
described with the ANY LENGTH clause"` OK; `cite.py --check "§2002:8.4.2.4.3 GR1" "An inline method invocation references a temporary data item with the
same class, category, and content as the temp-identifier"` OK. The refused twin's diagnostic file is
`conformance-suite/wiseowl/diagnostics/pb5598-base-inline-new-refused.json` (`refuse-at` 2014, 2023; expect COBOL2140).

**The fix.** Re-point each header's `rules:` (the 2002 case to `2002-SR-8.4.2.4.2-4`, `2002-GR-8.4.2.4.3-1`; the twin to `SR-8.4.3.4.3-4`) and move the pair out
of the PROPERTY-CLAUSE directory if the suite's directory-per-clause convention requires it (conformance-suite's generator decides; `generate.py --check`).
This is a header edit: a `.out` and the diagnostic JSON do not change.

**Sites:** none (conformance-suite golden headers only, no code file: `conformance-suite/cases/13.16.15@2002-CONTROL-CLAUSE/pb5602-control-footing-other-occurrence.cob`,
`conformance-suite/cases/13.16.40@2002-PROPERTY-CLAUSE/pb5598-base-inline-new-2002.cob`, `conformance-suite/cases/13.16.40@2002-PROPERTY-CLAUSE/pb5598-base-inline-new-refused.cob`)

**Sibling sweep.** Every golden added by PB5598 and PB5602 (`pb5598-*`, `pb5602-*`): each `rules:` entry resolved to the clause the golden's own comment
cites. A drift test that a golden's header rules include the rule its comment cites by `§<edition>:<clause> <rule>` would make the check automatic.
