# PB1058 — OPEN

## Measured
`05 COLUMN 77777777777 PIC X(3) VALUE "ABC".` → `Unhandled exception: System.OverflowException: Value was either too
large or too small for an Int32. at System.Int32.Parse … at CobolNet.Binding.DataBinder.BindReportEntry
(DataBinder.Reports.cs:line 1624)`. `RD RR PAGE LIMIT 77777777777 LINES.` → the same exception at
`BindReportDescriptionClauses` (DataBinder.Reports.cs:line 781). Exit 1, no diagnostic.

## What the fixer owes
Route every report-writer integer through the one checked integer decoder PB1002 introduced for LINE / NEXT GROUP
(`LineInteger`), reporting the clause's own range rule (LINE: §13.18.35.3 3); COLUMN: §13.18.14.3 SR6 via PB1059;
PAGE: §13.18.39.3) instead of throwing. Grep `int.Parse(` over `Binding/` for the rest (the lead says the PAGE
subclauses share it). Negative golden per clause. Legal source cannot reach it, but a compiler crash on ANY source is
a MAJOR by the register's rule.

## Landed — w59b (fix-lane implementer, branch `worktree-agent-a488d53c4b7e35173`)

**Mechanism:** the binder read integer-n literals with `int.Parse` (throws) or `int.TryParse` (silently drops the
clause — `OCCURS 77777777777 TIMES` compiled clean), a dozen copies across `DataBinder*.cs`. **Fix:** ONE screen and
ONE reader. `Validation/IntegerOperandPass` (already THE ONE §5.5 1) screen over every `integerLiteral`) now also
reports **COBOLNET2427** for an integer-n above 2,147,483,647 — ISO §4.5 (translation may fail on "the limits of an
implementation") — except `IntegerOperandRules.FullValueSlots` (PERFORM TIMES, WRITE ADVANCING, DYNAMIC LENGTH
LIMIT), whose values are carried wide. Every binder site reads through `IntegerOperandRules.HostValue`, which
saturates (the screen has already reported) and never throws; `LineInteger` (PB1002's private copy) is gone.
Measured after: `PAGE LIMIT 77777777777`, `COLUMN 77777777777`, `LINAGE 77777777777`, `OCCURS 77777777777`,
`RECORD CONTAINS` / `BLOCK CONTAINS 77777777777` each → COBOLNET2427, no crash. Negative golden
`conformance:negative/pb1058-integer-operand-beyond-limit` (reject-at 85 2002 2014 2023); unit
`IntegerOperandSlotDriftTests.HostValue_SaturatesAtTheLimit` / `EveryFullValueSlot_IsAClassifiedRule`; semgrep
`cobolnet-integer-n-parsed-outside-host-value`. The clause range rules stay with their notes: PAGE §13.18.39.3 SR5/SR6
(PB1270), COLUMN §13.18.14.3 SR6 page width (PB1059). Documented: docs/CONFORMANCE.md §3 "Integer operands and host
carriers".
