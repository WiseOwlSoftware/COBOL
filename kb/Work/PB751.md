# PB751 — OPEN — a regenerator that regenerates nothing, and says it did

Found 2026-09-06 by the `PB708` implementer (report, "New defects" (1)), which filed it rather than folding it
into PB708's change set. **Verified against main (`0a24276f`) by reading; nothing was renamed and nothing was
run** — the mechanism is decidable from the four lines below plus `feedback_vstest_filter_terms`, and the repro
the report gives (append `Zz` to a method name) would edit a script this registrar is fenced from touching.

## The two sites, verbatim at main's line numbers

`scripts/gen-vcr.ps1:14-18`:

```powershell
    $env:COBOLNET_WRITE_VCR = '1'
    dotnet test tests/Cobol.Net.Tests.Conformance/Cobol.Net.Tests.Conformance.csproj -c Debug `
        --filter 'FullyQualifiedName~VcrDriftTests.GeneratedStatusIndex_IsInSync'
    if ($LASTEXITCODE -ne 0) { throw "regeneration test failed (exit $LASTEXITCODE)" }
    Write-Host 'Regenerated the VERSION_CHANGE_REFERENCE.md gating status index.'
```

`scripts/gen-diagnostics-doc.ps1:12-16`:

```powershell
    $env:COBOLNET_WRITE_DIAGNOSTICS_DOC = '1'
    dotnet test tests/Cobol.Net.Tests.Unit/Cobol.Net.Tests.Unit.csproj -c Debug `
        --filter 'FullyQualifiedName~DiagnosticRegistryDriftTests.DiagnosticsDoc_IsInSync_WithTheCatalogue'
    if ($LASTEXITCODE -ne 0) { throw "regeneration test failed (exit $LASTEXITCODE)" }
    Write-Host 'Regenerated docs/DIAGNOSTICS.md from DiagnosticCatalog.'
```

Both scripts follow the same design, stated in their own headers (`gen-vcr.ps1:6-9`,
`gen-diagnostics-doc.ps1:5-7`): the renderer lives in the drift test, so the script runs that ONE test with an
env var that flips it from *asserting* the committed artifact to *writing* it. The env var is the whole
regeneration; the filter is the whole selection; and **`$LASTEXITCODE` is the whole verification.**

## The mechanism

vstest answers a filter that matches nothing with a **passing run of zero tests** — exit 0, no warning, no red
(`feedback_vstest_filter_terms`; PB287 measured the same answer against CI). So if either test is renamed, or its
class is renamed or partitioned:

1. the filter selects nothing;
2. `dotnet test` exits **0**;
3. `if ($LASTEXITCODE -ne 0) { throw }` does not fire;
4. `Write-Host 'Regenerated …'` prints;
5. the artifact on disk is untouched, and the operator has a success line saying otherwise.

⛔ **Both filters are keyed `Class.Method`, which is the shape PB287 established as a latent silent-green.**
[[PB287]] landed 2026-09-02 after the A13 collection split made `NistDifferentialTests` into
`NistDifferentialTests_P0 … _P5`, so `~NistDifferentialTests.NistProgram_MatchesGolden` could never match
`…_P0.NistProgram_MatchesGolden`; its fix was to key all four CI filters on the **method name alone**, because
"the class half is the half that moves". That sweep stopped at `.github/workflows/`. These two scripts carry the
same construction and were not touched. Both classes are unpartitioned TODAY —
`tests/Cobol.Net.Tests.Conformance/VcrDriftTests.cs:22` / `:221` and
`tests/Cobol.Net.Tests.Unit/DiagnosticRegistryDriftTests.cs:20` / `:110` — so the filters are exact right now;
that is the definition of latent, not of safe.

## Why it is MINOR and process-only, stated so the severity is not re-argued

The harm is **bounded downstream by the same test run normally**: with the env var unset, `VcrDriftTests` and
`DiagnosticRegistryDriftTests` assert the committed artifact against its source, and CI runs them. So a doc that
silently failed to regenerate then fails its own drift test at the next gate. The cost is a confusing false
success and a wasted debugging cycle — *"I ran the regenerator and it still says drift"* — not a wrong doc
shipped. Nothing a user's COBOL program does is affected, hence `process_only: true`; the report's own
classification, and it is re-derived here rather than inherited.

⚠ The one way the harm is NOT bounded is a rename that hits the drift test's *own* CI filter at the same time —
i.e. if the drift test is renamed AND the leg that runs it selects by a filter naming the old name. Neither drift
test is selected by name in `.github/workflows/build-and-test.yml` today (they run inside the unfiltered/sharded
legs), so that compound is not live. It is named here because it is what would turn this into a shipped wrong doc,
and it is [[PB752]]'s territory.

## The fix shape

**Assert the population before trusting the exit code** — `feedback_verdict_evidence_invariant`, the rule PB708
lands: *a run must assert its population*, and *a MISSING observation is not a NEGATIVE one*.

1. ⭐ **Preferred — call `scripts/filter_population.py` before the run.** That helper is PB708's change set and is
   **not on main today**; it exists on branch `worktree-agent-a6d2907b763ee0741` (landing train 17) and will be
   the ONE place the "did this filter select anything" rule lives, asking vstest for its own filter language via
   `dotnet test --list-tests --filter <term>` per term. Calling it here is the whole fix and adds no logic to
   either script (`feedback_one_rule_one_place`). **⛔ Sequence: this note lands AFTER PB708, or it has nothing to
   call.**
   ⚠ **The report's caveat about the helper does not bite at these two sites, and that is worth knowing before
   an `--allow-build` mode is built for them:** the report says the helper "needs a built tree, so either build
   first or give the helper an `--allow-build` mode that drops `--no-build`". Neither regenerator passes
   `--no-build` (`gen-vcr.ps1:15`, `gen-diagnostics-doc.ps1:13`) — both already build the test project as part of
   the run, and `--list-tests` builds by default too. The caveat was written for the `--no-build` gate legs in
   `build-local.{ps1,sh}`. Verify it when implementing rather than inheriting either claim.
2. **Fallback if PB708 slips — assert `Total: N` with `N >= 1` from the run's own output.** vstest prints
   `Total: <n>` on every run; the CI shard legs already extract exactly that
   (`.github/workflows/build-and-test.yml:139` and `:266`,
   `grep -Eo 'Total:[[:space:]]+[0-9]+' shard.log | tail -1`), so the idiom is already in the repo. In PowerShell
   this means capturing the output instead of letting it stream, which is a real change to both scripts and is
   why it is the fallback.

⛔ **Prove it fails once before trusting it** (`feedback_green_gates_arent_evidence`): run the changed script with
a deliberately dead term (append `Zz` to the method name in a scratch copy) and watch it refuse, then restore.
A guard that has never been red is not evidence.
