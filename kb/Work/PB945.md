Source: the **PB394 (MOVE operands) implementer report**, "New defects" item 3, filed deliberately and honestly:
the same change set converted **twenty** sites to `DenotedItem` and left these, *"because they ask a DIFFERENT
question, and that is stated rather than assumed."* `PB602` landed that conversion in train 43.

## The question they ask, and why `DenotedItem` is not it

`DenotedItem` answers *"which DATA ITEM does this operand denote?"* — and a level-66 THROUGH alias denotes its
own item, so `DenotedItem` is non-null for a `RenamesPlace`. These six sites ask something else:

> Is this operand's storage **one contiguous declared item**, such that a receiver-shaped rule about the item's
> description (its record, its FD, its INTO-admissibility) applies to it?

A reference-modified slice is not, and a RENAMES window is not. Both answers are right today. **The defect is the
FORM**: it is a list of the two `Place` kinds that happen to fail, written out six times, instead of a property
on `Place` that every kind answers for itself.

## Why this is worth a note rather than a tidy-up

`feedback_model_the_rule_shape_not_one_case` and CLAUDE.md rule 5. A type list is closed by enumeration: the next
`Place` kind added — and `kb/Work/PB886`'s boolean reference-modified slice and `PB602`'s own `PlaceDecorator`
both show the model still gains kinds — defaults to *"yes, contiguous"* at all six sites **silently**, because
nothing tests a kind that does not exist yet. A property defaults to nothing: a new kind does not compile until
it answers. The six sites are two files and one sitting; the structure is what makes the seventh site and the
fourth kind automatic.

## The shape the fix should take

One property on `Place` — the name the source report reaches for is a contiguity/denotation predicate; the
implementer picks it against `DESIGN-data-model.md` §2.2, which `PB602` already amended with the `DenotesAs`
decision and which must be amended again in the same change set (CLAUDE.md rule 2). Every kind implements it;
the six sites ask it; a drift test asserts that no `Place` kind is missing an answer and that the predicate's
value for each existing kind is unchanged — which is the only form of this change that can prove it is
behaviour-preserving, since all six sites are on paths with no diagnostic of their own.

## The sibling sweep the fixer owes

`RefModPlace` alone and `RenamesPlace` alone are also written out as type tests elsewhere
(`grep -rn "is RefModPlace\|is RenamesPlace" --include=*.cs src/`). Each is either the same question — fold it —
or a genuinely different one, which the site must then SAY, with the rule it serves. A type test with no stated
question is how six of them accumulated.
