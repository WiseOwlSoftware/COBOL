**Found by** the PB2182/PB2361 landing (PR #1101, branch worktree-wf_3436403d-198-1), reports w20261855a and w20261856a. It became visible only once the walk reached the slices.

**The defect.** The storage tier hands the backend C# member NAMES (text), not the root, class or index symbol the name derives from:
- `src/WiseOwl.Cobol.Compiler/Binding/Model/StorageTierSlice.cs#StaticRootFields`, `#StaticBasedBridgeAddrs`, `#StaticAddressableCells`, `#StaticIndexCells`, `#AddressableBackings`, `#BasedBridges`, `#AddressableCellOf`
- `src/WiseOwl.Cobol.Compiler/Binding/Model/DataBindResult.cs#CellLifetimes`, `#CellFieldsOf`
- `LinkageFacts.SuppressedRootFields`

A rename in the emitter's naming convention and the binder's string must agree by convention only; one model value means a symbol on one side of the phase boundary and emitted text on the other (the same root as PB3251, which records it for `FileModel.InstanceKeyField`).

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Model/StorageTierSlice.cs` (`StorageTierSlice.StaticRootFields`, `StorageTierSlice.StaticBasedBridgeAddrs`, `StorageTierSlice.StaticAddressableCells`, `StorageTierSlice.StaticIndexCells`, `StorageTierSlice.AddressableBackings`, `StorageTierSlice.BasedBridges`, `StorageTierSlice.AddressableCellOf`), `src/WiseOwl.Cobol.Compiler/Binding/Model/DataBindResult.cs` (`DataBindResult.CellLifetimes`, `DataBindResult.CellFieldsOf`)

**Fix shape.** Carry the root, class or index symbol on each channel and let the backend read its CLR name from the symbol (one naming mechanism, in the backend). Pair it with a drift test that no `StorageTierSlice` / `DataBindResult` member is typed `string` for a storage member name. Update `docs/rearchitecture/` data-bind design in the same change.

**Links.** PB3251 (same root: model fields holding emitted C# names), PB2361 (landed the slices).
