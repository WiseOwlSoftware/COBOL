**Scenario:** Grammar: STRINGLIT | NATLIT | BOOLLIT | HEXLIT is written in nonNumericLiteral (CobolExpressions.g4:777-785), concatOperand (:816-824) and allLiteral (:897-903). kb/Work PB1627 is the recorded cost of this shape: allLiteral carried its own quoted-only operand list and refused ALL "A" & SPACE and ALL "A" & K, which PB1406 had already fixed for concatOperand. Binding: ConcatFolder.Classify (ConcatFolder.cs:278-282), ExpressionBinder.NonNumericLiteralOperand (ExpressionBinder.cs:216-230), CompileTimeExpressionEvaluator.NonNumericOperand (CompileTimeExpressionEvaluator.cs:351-354), DataBinder.BindConstantStringLiteral (DataBinder.Constants.cs:548-551) and ExternalizedName.Screen (ExternalizedName.cs:98-101) each map the token kind to a class and a decoder by hand, and they already disagree on the decoder (four call CobolLiteral.DecodeHex for HEXLIT, the compile-time evaluator calls CobolLiteral.Decode, which re-dispatches on the prefix), so the result is right only because both paths happen to end in DecodeHexGroups. VersionConformancePass (:2403-2429) reads NATLIT/BOOLLIT per context for the same class question. A change to the class rule (a new prefix, which CobolLiteral.PrefixLetters says is one edit to that string) reaches ClassOf readers and misses the five token ladders and the three grammar lists.
