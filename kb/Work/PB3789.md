# PB3789 — `kb/Work.base` `formula.blocked` was never run

**Sites:** `kb/Work.base#formula.blocked` (line 7), `scripts/spec/work.py` (the Python rule it mirrors, if the formula must change)

## Measured

PB3389 removed the stored `blocked:` line from every note and made `blocked` a derived fact. `work.py` computes it in
Python; `kb/Work.base` spells the same rule in the Bases language as
`link(value).asFile().properties.status`. The report states the formula was written from the Bases documentation and
NOT run in Obsidian, so whether it resolves a `blocked_by` link to the target note's `status` is unverified. A wrong
formula makes the **Fix next** view (`not landed AND (wrong-answer OR crashes) AND not blocked`) list a blocked defect or
hide an open one, silently, while `work.py next` stays right.

The report left the file untouched ("no change to that file here") and asked for a one-time check in the app.

## Acceptance

- The formula is run in Obsidian against the register; Fix next and Blocked views list the same set as `python
  scripts/spec/work.py next` and the blocked listing of `work.py`. The result (the set compared, any difference) is in
  the note.
- If the views differ, the formula is corrected, or the view removed, so `kb/Work.base` and `work.py` state ONE rule
  (CLAUDE.md rule 8: the Base is only a view).
