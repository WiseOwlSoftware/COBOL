# PB4133 — single-token-deletion recovery inside a statement's header

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs:405` (`CobolErrorStrategy.SingleTokenDeletion`), `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs:418` (`CobolErrorStrategy.TheMissingElementLetsItFollow`), `tests/WiseOwl.Cobol.Tests.Unit/ParseRecoveryDeletionTests.cs`, `tests/WiseOwl.Cobol.Tests.Conformance/GeneralFormatViolationTests.cs`.

New defect 2 of PB3843's implementer (also in PB3843's landed note under "Not fixed here (leads)"). PBGF04 / PBGF07 / PBGF10
(`IF DISPLAY "X" END-IF`) draw COBOL0001 and then COBOL2072 (the empty block ANTLR's single-token deletion left); PBGF32 draws two
COBOL0001. A different recovery from the early-closure one PB3843 fixed: single-token deletion inside a statement's header
(`DefaultErrorStrategy.RecoverInline`'s path), NOT `ConsumeUntil`.

**Fix:** when `RecoverInline` deletes a token and the repair leaves an empty block (`ResimulationWalk.EmptyBlockOwner` knows the
shape), suppress the derived COBOL2072 and keep the single true diagnostic; the second COBOL0001 of PBGF32 is the same cascade.
Pin PBGF04/07/10/32 as goldens (each draws exactly one diagnostic).

Source: report `w20261764c-PB3843-report.md`, "New defects" item 2; PB3843 (landed). Sibling of PB4134 (the tail discard).

## Landed, 2026-10-30 (wave 20261780, group F)

Re-probe on the wave build: PBGF04, 07, 10 drew COBOL0001 then a false COBOL2072; PBGF32 drew COBOL0001 then COBOL5506 at GIVING
(the second COBOL0001 of the note became COBOL5506 when PB3428 landed). One cause in two arms of the dispatch: ANTLR's
`SingleTokenDeletion` is reached from `Sync` (a block start: PBGF04, 07, 10, and the key list of PBGF32) and from `RecoverInline`
(a match), and both took a token for stray when the token after it was a legal element, though the token itself was what the
MISSING element would have let follow. The root is not the empty block (the note's proposed fix suppressed the derived COBOL2072,
a symptom): the deletion repaired the wrong element. `SingleTokenDeletion` now declines when `TheMissingElementLetsItFollow`
(the follow of the state after the element: ANTLR's own insertion test; of a block's end; of the whole rule when it has consumed
nothing), so the missing element is the one fault and the statement parses as written. The PB911 empty-block test stays: it
covers a block one element further downstream than the state the parser stands at. Every row of `GeneralFormatViolationTests`
now asserts exactly one diagnostic (all 40 draw one). Sibling sweep: `IF MOVE ... END-IF`, `IF a AND DISPLAY ...`, `EVALUATE DISPLAY ...
WHEN`, `IF DISPLAY ... ELSE` (which drew a false COBOL2072 at ELSE) and `EVALUATE ... WHEN DISPLAY ... WHEN OTHER` (a false COBOL2073)
draw one each now. Design: `DESIGN-frontend-grammar.md` section 3.9. Gate: see the DEVLOG entry.
