# PB2845 — OPEN — the fold drift test has a blind spot, and one host upper-case key survives

Found by the train 1047 lander's review (step 5b; `E:\COBOL-coord\scratch\reports\train1047-report.md`, finding (b)) on cluster 47A (PB1965's Annex C word keys), stated by the reviewer; the site is confirmed by reading the code. The lander had no ids left; the land unit reserved this id and the resume unit of 2026-10-08 21:46 PDT filed it.

## What is wrong
1. `tests/**/CobolNameFoldDriftTests.cs` scans `WordProjects = ["Cobol.Net.Compiler", "Cobol.Net.Frontend",
   "Cobol.Net.Editions"]`. PB1965 moved the word key into `Cobol.Net.Runtime` (`CobolNames.UpperFold`) and the run-time
   EXTERNAL identities use it, so a host `ToUpperInvariant` key added to the runtime is not caught.
2. `src/Cobol.Net.Frontend/Preprocessor/FlagDirective.cs:128`:
   `ByWord.TryGetValue((directive, word.ToUpperInvariant()), out var info)`. That is a COBOL word keyed by the host's
   upper-casing, the shape PB1965 removed everywhere else (OK §8.1.3.2 3) folds by Annex C; .NET keeps U+212A KELVIN
   SIGN as itself, so a Kelvin-spelled option word does not find its entry). The drift test should have flagged it
   and did not, so its pattern also needs checking.

## Probe owed
By trace, `FlagOptions.TryOption` returns null for such a word and the directive parser refuses it ("is not a valid
option of >>…", FlagDirective.cs:220), hence `rejects_legal_source`. Confirm with a `>>FLAG-…` option word spelled with
U+212A at `--std 2023` before the fix.

## Done when
The drift test scope covers every project that keys a COBOL word (derived from the project list, not a second
hand list), its pattern catches the FlagDirective shape, and FlagDirective keys by `CobolNames.UpperFold`.
