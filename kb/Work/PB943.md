# PB943 — LANDED — the receiver filter's proof is not true of NATIONAL

Source: the **PB394 (MOVE operands) implementer report**, "New defects" item 1, which asks that it be filed as an
extension of `PB896`. **`PB896` landed in train 43**, so it gets its own note and a `cluster:` back-link instead.

## Observed, byte-exact (`f2_zl_national.cob`, `--std 2023`)

```
       01 N PIC 9 VALUE 0.
       01 NG.
          05 NE PIC N USAGE NATIONAL OCCURS 0 TO 4 DEPENDING ON N.
       01 R-NAT PIC N(4) VALUE N"ZZZZ".
       01 R-ALN PIC X(4) VALUE "ZZZZ".
       …
           MOVE NG TO R-NAT
           MOVE NG TO R-ALN
```

`od -c` of the program's own output:

```
N A T = [ \0     \0     ]   L E N = 4
A L N = [ \0     \0     ]   L E N = 4
N A T - S P A C E S = N O
A L N - S P A C E S = N O
```

The `PIC N(4)` receiver ends up holding **U+0000, U+0020, U+0000, U+0020**. `FUNCTION LENGTH` still says 4, and
`IF R-NAT = ALL N" "` takes the ELSE branch. That interleaved image is the **byte** representation of two
national spaces written into **four character** positions: the fill is being counted in bytes and stored as
characters. (PB394's report saw only the ELSE branch; the byte dump is what says which wrong answer it is.)

## Expected, from the standard

```
$ python scripts/spec/cite.py --check 14.9.25.4 "it is as if literal-1 were specified as a zero-length literal"
  OK  §14.9.25.4 1)  (General rules)
```

§14.9.25.4 GR1 makes a zero-length sending ITEM the same statement as a zero-length LITERAL sender, and GR2 then
substitutes the figurative SPACE for it against any receiver other than a dynamic-length elementary item. Either
route — GR2's substitution or §14.6.8's alignment-and-fill — gives a `PIC N(4)` receiver **four national
spaces**. Neither gives U+0000 in an odd position.

## The code site, and the sentence that has to change

`src/Cobol.Net.Compiler/Binding/Bound/MoveClassifier.cs` — `ZeroLengthItemRoute`:

```csharp
target.Item.OperandPic is { Category: PicCategory.Numeric or PicCategory.NumericEdited }
```

Its doc comment states the filter as a **proof**, and this is the sentence the measurement contradicts:

> **The receiver filter is a PROOF, not a shortcut.** A test is emitted only for a NUMERIC or NUMERIC-EDITED
> receiving operand, because for every other category the two readings are the same store: an empty sending value
> aligns per §14.6.8 and pads the whole receiver with its category's fill — space for alphabetic / alphanumeric /
> national and their edited forms (§14.6.8.3–14.6.8.5) …

For NATIONAL the two readings are **not** the same store, because the "empty sending value aligns and pads"
branch does not produce national spaces here. `feedback_a_dead_lookup_is_also_unverified` and
`feedback_probe_the_shape_the_subject_hides`: the argument was never measured on the axis the subject held fixed,
and an argument in a doc comment is a claim.

## ⚠ A hypothesis for the implementer to CONFIRM in this code, not to inherit

The interleaved NUL/space image has the shape of a **byte-width vs character-width** split, which is exactly
`kb/Work/PB546`'s open mechanism (*"ONE national leaf has TWO widths and the consumers split:

should land together and this note's fix is PB546's. **That is a lead, not a diagnosis**

## LANDED — 2026-09-22, wave 49 (group senders into non-alphanumeric receivers)

Re-probed on the wave-49 worktree's own build (0/0) before any change: byte-exact as filed —
`NAT=[00 20 00 20]`, `ALN=[00 20 00 20]`, both `…-SPACES=NO`.

**The hypothesis held, and it was two mechanisms, not one.** (1) The interleaved image is a UNIT split, but
not PB546's leaf-offset one: `OdoModel.WrapGroup` computed the §13.18.38.4 GR8 a) extent as
`fixed + occ × elem` with `elem = table.ImageWidth` (CHARACTER positions — 1 per national leaf) and
`fixed = RecordLayout.PhysicalWidth(group) − elem × max` (BYTES — 2 per national leaf, since PB327 made the group
image the record's bytes). For `NE PIC N OCCURS 0 TO 4` that is `8 − 4 = 4`, so a zero count sent four bytes
of the maximum image (`00 20 00 20`) and every count below the maximum sent too much (`N = 2`: six bytes). The
stride now comes from `RecordLayout.PhysicalOccurrenceWidth` — the per-occurrence contribution the physical
walk already used twice, extracted rather than spelled a third time. (2) The receiver filter WAS false, but not
where the note first looked: with the extent right, `MOVE ZG TO PIC N(4)` stores four national spaces by
either reading. It fails for a zero-length GROUP sender into an EDITED receiver (group move: `"     "`; GR1's
SPACE, edited: `"  /  "`), into a BOOLEAN receiver (alphanumeric spaces vs D-B2's boolean zero), and for a
zero-length BIT GROUP (GR3's ZERO) into any character receiver (`"   "` vs `"000"`). The filter is now GR2's
own set (`MoveClassifier.SubstitutesForZeroLength`, asked by `Sender`, `ZeroLengthItemRoute` and
`NeedsLengthFreeze`), and the zero arm is the statement's own dispatch over the substituted figurative
(`MoveEmitter.EmitStore`). ⚠ DETERMINATION: a GR9 move (both groups, one variable-length) keeps GR9.
