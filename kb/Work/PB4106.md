# PB4106 — GnuCOBOL: table-format VALUE ... FROM (s...) TO (s...) is refused unless every FROM subscript is <= its TO subscript: FROM (1 3) TO (2 1), legal in element order, gives 'entry in FROM (3) must be <= entry in TO (1)'

Found by patcher E while patching the drafted ticket `table-value-from-to-silent` (kb/Work PB3933): the draft's patch
section (`E:\COBOL-coord\scratch\mythos\gc-file\drafts\table-value-from-to-silent.md`, line 118) records that the parser
"still checks FROM <= TO subscript by subscript". Recorded nowhere else before this note. Reproduced for this filing on
2026-10-30.

## Summary

For a table-format VALUE clause on a multi-dimensional table, cobc requires each FROM subscript to be less than or
equal to the TO subscript in the same position, and refuses the entry otherwise. The standard's condition is on the
table ELEMENTS: the element named by TO shall be the same as, or follow, the element named by FROM in the order the
table is initialized (the last subscript varies fastest). `VALUES 1 2 FROM (1 3) TO (2 1)` on `R OCCURS 2` /
`E OCCURS 3` runs from the third element to the fourth and is legal, but cobc stops with `entry in FROM (3) must be <=
entry in TO (1)`. Present in 3.2.0 and 3.3-dev r5751, under `-std=cobol2014` and the default dialect. Class: rejects
legal source. (Once accepted, the values would still not be stored: that is PB3933, which the control below shows.)

## Minimal test case

Free reference format (`-fformat=free`), file `~/gc-notes/PB4106/tvord.cob` (WSL):

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. TVORD.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 T.
   05 R OCCURS 2.
      10 E PIC 9 OCCURS 3 VALUES 1 2 FROM (1 3) TO (2 1).
PROCEDURE DIVISION.
DISPLAY E (1 3) E (2 1)
STOP RUN.
```

Control `~/gc-notes/PB4106/tvctl.cob`: the same with line 7 `... VALUES 1 2 FROM (1 2) TO (2 2).` and line 9
`DISPLAY E (1 2) E (1 3) E (2 1) E (2 2)` (every FROM subscript <= its TO subscript).

## Observed result

`tvord.cob`, all three compiles (3.2.0 strict and default dialect, 3.3-dev strict), exit 1:

```
tvord.cob:7: error: entry in FROM (3) must be <= entry in TO (1)
    5 | 01 T.
    6 |    05 R OCCURS 2.
    7 >       10 E PIC 9 OCCURS 3 VALUES 1 2 FROM (1 3) TO (2 1).
    8 | PROCEDURE DIVISION.
    9 | DISPLAY E (1 3) E (2 1)
```

`tvctl.cob`: compile exit 0 on both, run exit 0, output `0000` on both (PB3933: the values are not stored; ISO `1212`).

## Expected result (per ISO)

`tvord.cob` compiles; E (1 3) is 1 and E (2 1) is 2, so it prints `12`.

- §13.18.63.3 21) (checked): "The specification of subscript-2 in one TO phrase shall be such that the table element
  associated with subscript-2 is the same occurrence or a successive occurrence of the table element associated with
  the corresponding subscript-1." The rule compares elements, not subscripts.
- §13.18.63.4 12) (checked): "Consecutive table elements are referenced by incrementing by 1 the subscript that
  represents the least inclusive dimension of the table", with a subscript at its maximum reset to 1 and the next more
  inclusive one incremented: the order is (1 1) (1 2) (1 3) (2 1) (2 2) (2 3), and (2 1) follows (1 3).
- §13.18.63.4 13) (checked): with TO, the literals are reused "until the table element identified by subscript-2 is
  initialized": 1 goes to (1 3), 2 to (2 1).
- §13.18.63.3 20) (checked): "Each instance of subscript-1 shall not exceed the maximum number of occurrences specified
  in the OCCURS clause associated with that instance" (rule 21 says the same of subscript-2). With every subscript in
  range, element order is the lexicographic order of the subscript lists, most inclusive first; that is the comparison
  rule 21 needs, and it can be made in the parser without the OCCURS maximums.

## Class

rejects-legal-source: a legal table-format VALUE clause (COBOL 2002 and later) is refused with an error. Every FROM/TO
pair whose TO starts a later row at a lower column, the common way to initialize a run that wraps a row, is affected.

## Fix site

- 3.3-dev r5751: `cobc/parser.y`, rule `value_table_item` (`value_item_list from_subscripts _to_subscripts`, about line
  8935): the `while (f)` loop errors as soon as one `f_idx > t_idx`. Inferred fix: compare lexicographically, stopping
  at the first position where the two subscripts differ and erroring only if FROM's is the greater there. The range
  checks of rules 20 and 21 against the OCCURS maximums belong where the clause is matched to its OCCURS levels, which
  the code notes is postponed. 3.2.0 has the same loop (`cobc/parser.y`, about line 8718).
- Not built or tested. Patcher E's patch for PB3933 (`drafts/table-value-from-to-silent/table-value-from-to-silent.patch`)
  deliberately leaves this check unchanged, so this fix stacks on it.

## Draft issue

**Title:** table-format VALUE: FROM/TO checked subscript by subscript, so FROM (1 3) TO (2 1) is refused

**Body:**

Environment: GnuCOBOL 3.2.0 (Ubuntu gnucobol3 3.2-4build1) and 3.3-dev r5751, x86_64 Linux.

Steps: `cobc -std=cobol2014 -fformat=free -x tvord.cob` with the attached `tvord.cob` (the program above).

Observed: `tvord.cob:7: error: entry in FROM (3) must be <= entry in TO (1)`, exit 1 (also without `-std`).

Expected: the clause is legal and covers elements (1 3) and (2 1). ISO/IEC 1989:2023 §13.18.63.3 syntax rule 21
(2014: same rule): "the table element associated with subscript-2 is the same occurrence or a successive occurrence of
the table element associated with the corresponding subscript-1"; general rule 12 defines successive elements by
incrementing the least inclusive subscript first. The program should print `12`.

Where: `cobc/parser.y`, `value_table_item`: the loop over the subscripts errors on the first `f_idx > t_idx`. A
lexicographic comparison (stop at the first differing subscript; error only if FROM's is greater) gives the
standard's order whenever the subscripts are within their OCCURS bounds.

Note: with the check passed (e.g. FROM (1 2) TO (2 2)) the program compiles but the values are not stored (prints
`0000`, expected `1212`); that is reported separately (PB3933's repro).
