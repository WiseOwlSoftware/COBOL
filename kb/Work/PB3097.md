# PB3097 — the finisher role never loaded, and the readiness check printed OK

> ⚙ **flags:** silent, process-only

**The defect.** `.claude/agents/cobol-finisher.md` (on main since `4f439ad5c`, kb/Work PB3023) carried an unquoted
`description:` holding `… and returns DONE: its commits are reviewed …`. Inside a YAML plain scalar, `: ` starts a
mapping, so the frontmatter does not parse (`yaml.safe_load`: "mapping values are not allowed here"; the other six
roles parse). Claude Code therefore never loaded the role: `Agent(subagent_type: "cobol-finisher")` answered "Agent type
'cobol-finisher' not found", so every enqueue unit's step-4 finisher dispatch failed, and so did the workflows'
`agentType: 'cobol-finisher'`. The finisher of PB3029 (w1064f) ran under `cobol-implementer` for that reason.

**Why nothing saw it.** `scripts/hooks/tooling_check.py`, the session-start readiness check, printed `OK role agents`
because it tested only that each role FILE existed. A role that exists and never loads read as ready.

**Fix (landed with PB3029's finisher change).**
1. `cobol-finisher.md`: `DONE: its commits` became `DONE; its commits`, and its frontmatter now parses into the same keys
   as the implementer's.
2. `tooling_check.py#definition_problems` / `#frontmatter_problems`: every `.claude/agents/*.md`, `.claude/skills/*/SKILL.md`
   and `.claude/commands/*.md` frontmatter is parsed with PyYAML (`safe_load`). It must give a mapping with a non-empty
   `description`. An agent's `name` must equal its file stem and a skill's must equal its directory, and every required
   role must exist. Any failure makes the TOOLING line `ASK-OWNER` and names the file, the YAML line and the remedy;
   it is never `OK`. A host without PyYAML is reported, not passed.
3. Its self-test plants the finisher's exact defect, a mismatched name, an empty description and a missing role; each
   must be reported, and a loadable file never is. It also runs the check over the repository's own `.claude/`, so a
   broken role or skill fails every gate's self-tests and CI's. Mutant: the old `cobol-finisher.md` gives
   `frontmatter is not valid YAML (frontmatter line 2): mapping values are not allowed here`.
4. PyYAML is pinned where the self-test runs without it: CI's `audits` job (`pip install --user
   --break-system-packages pyyaml==6.0.3`) and `windows-build-test` (beside tzdata). It is also in the WSL and cloud
   setup package lists (`scripts/wsl/setup-wsl.sh`, `scripts/cloud/setup-env.sh`). The local hosts carry 6.0.3: Windows
   pip, and under WSL the uv-managed python3.14 that `linux-gate.sh` runs (not `/usr/bin/python3` with python3-yaml),
   installed by `setup-wsl.sh`. Branch review R3-1 found that interpreter without it (`tooling_check.py --self-test` RED
   (6) under `linux-gate.sh`): `linux-gate.sh` now refuses with `NOT RUN (<py> has no PyYAML — run
   scripts/wsl/setup-wsl.sh once)` instead of a red self-test leg, and the owner installed it on this host by hand
   (2026-10-12).

**Sweep.** All nine `.claude/skills/*/SKILL.md` parse with `name` equal to their directory, and the six other roles
parse. There is no `.claude/commands/` directory today; the check covers it the day one is added.

**For the next implementer.**
- `scripts/hooks/tooling_check.py#FRONTMATTER_KINDS` holds the one list of definition kinds Claude Code reads from
  frontmatter, each with the name it must carry. A new kind is one row, and the self-test's live-tree check covers it.
- Trap: a description that reads like prose (`returns DONE: its …`) is YAML syntax. Quote the value, or use a
  `>-` block scalar, whenever it holds `: ` or starts with an indicator character.
