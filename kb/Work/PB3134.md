# PB3134 — the README's status section was incomplete and its test list was stale

## Found (2026-10-13 11:40 PDT, the owner)
The owner: "Update the Wiseowl.COBOL README in the repo. it is outdated" (the root `README.md`, landed the night before
by PB3100 at `241c6de2d`). Every claim in it was re-verified against the tree at `2da05a28a`: the pinned tools
(`global.json`, CONTRIBUTING.md), the CLI options and verbs (`Program.cs`), the files a compile writes
(`AssemblyPackager`), the gate and CI (`build-and-test.yml` runs the three test projects on Linux and Windows for the
merge group), the project tree (`Cobol.Net.sln`), the referenced documents and community files, the license, and the
NuGet and documentation-site plans (nothing on nuget.org; `/cobol/docs/` is PB1614, still planned). Three things were
stale or incomplete:

1. **The status section said "Four facilities are declined"** and named the Message Control System, commit and
   rollback, VALIDATE and screen handling. `docs/CONFORMANCE.md` §1, §2 and §5 also decline, each by name: FORMAT and
   SELECT WHEN file handling (A.4.8, COBOLNET1705) and WRITE FILE and REWRITE FILE (A.4.13, COBOLNET1706), both
   refusals; ARITHMETIC IS STANDARD-BINARY (A.3 item 2, COBOLNET0806); FLOAT-BINARY-128 and the standard decimal
   floating-point usages (A.3 items 17 and 19, COBOLNET1564) with the FLOAT-DECIMAL clause warned (item 13,
   COBOLNET2424); the RECORD DELIMITER clause warned (item 26, COBOLNET1778); the SOURCE phrase of a record key refused
   (item 40, COBOLNET1954); class multiple inheritance (COBOLNET0849) and method overloading (COBOLNET0822) refused
   (A.4.10); the report writer (A.4.11) and dynamic-length items (A.4.5) partial. A reader of the README was told the
   list was complete when it was not.
2. **The test list omitted two projects of the solution:** `tests/Cobol.Net.ArchOracle` (the behavior-neutrality
   oracle's runner, kb/Work PB2116) and `tests/Cobol.Net.Benchmarks` (the performance baseline's harness, kb/Work
   PB2117).
3. **The test list did not say what the oracle does.** The first commit named the recorded baseline under
   `docs/rearchitecture/evidence/arch-oracle/` and the landing check that refused a stale one (kb/Work PB2885); PB3107
   (PR 38, merged 2026-10-13 17:17 PDT, between this branch's first commit and its review) retired both: the oracle
   commits nothing, `compare_oracle.py` captures the base commit on demand, and `enqueue.py` has no exit 7. The operator
   flagged it (mailbox 20261013-171929) and the branch merged main and restated the paragraph before review.

## Review R1-1 (2026-10-14): the hand-completed list was itself incomplete
The branch review found the rewritten list, presented as complete, still omitting rows §2 declines by name: CODE-SET
with an alphabet no device encodes (A.3 item 27, COBOLNET1672, witness `negative/pb110-code-set-nonidentity`), a
national collating sequence by literals or LOCALE on a national record key (items 41–42, COBOLNET1584, witness
`negative/pb1074-file-collating-national-declined`) and CONTINUE AFTER beyond whole seconds (item 8, witness
`2023/pb138_continue_after`). Re-reading every §2 and §5 row found three more of the same shape: the refused halves
of declined facilities whose accepted halves the list named, the MESSAGE-TAG usage (A.3 item 4, COBOLNET1943), the
APPLY COMMIT clause (A.4.3, COBOLNET1709), and VALIDATE's data-division clauses and EC-VALIDATE names (A.4.14,
COBOLNET1708, COBOLNET1710). The cause was the shape: a hand-kept summary of a register drifts. The finisher made it
mechanical: every README bullet names its Annex item, and `ReadmeDeclinedSummaryDriftTests` (reading §2 through
`AnnexA3RegisterDriftTests.Register`, the register's one parser) fails when a §2 or §5 row that is not Claimed is
not named, or when the README names a row the tables claim.
