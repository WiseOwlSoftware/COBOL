# PB103 — LANDED — the fleet build guard blocked builds inside `.claude/worktrees/`

> ⚙ **flags:** process · found 2026-08-18 by the normalization-subsystem agent ([[PB101]] section C): its
> `dotnet build` was denied ("3 subagent transcript(s) were written in the last 120s") with its own transcript among
> the three; it proceeded via `dotnet.exe` (which the matcher does not catch) rather than return an unverified
> deliverable, and reported it · **landed 2026-08-18** in the PB101 batch (DEVLOG 1327).

**Fix (two modes).** (1) The hook bails (allows) when the tool's `cwd` — or a `cd` in the command — is under
`/.claude/worktrees/`: an isolated worktree has private `bin/obj` and its own checkout, so nothing it builds is the
binary another agent probes. (2) The CALLER's own transcript (the hook payload's `transcript_path`) is excluded from
the live set — it is always fresh at PreToolUse, so a MAIN-TREE agent counting itself could never build either (the
T7 agent of the same session hit this second mode and could not run its gate; the main session gated its work). The
main-tree rule is otherwise unchanged (verified: a main-tree `dotnet build` with two OTHER live transcripts is denied). The `dotnet.exe` spelling remains uncaught — deliberately not tightened here: the
guard is a reminder for the model, fail-open by construction, not a security boundary.
