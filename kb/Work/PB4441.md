## Defect

Found by wave unit 20261826 (2026-11-02, main @ e22ffd875). The operator's handoff ordered: plan PB4421 as its own
group FIRST and hold PB2103 and PB2104 out of the wave. The planner offers no way to do that:

1. `plan_wave.py --from-budget --borrow-days 2` (the fix lane) planned **0 groups**: PB4421 is `process_only: true`, and
   the fix lane's clusters skip process-only notes, so it never appears, not even under "waiting". Every other
   candidate (PB2103, PB4279 ... PB4435, PB4310, PB4434) waited on a file-set collision with the in-flight worktrees
   `worktree-wf_a56965c4-16c-2`, `-3` and `-6`.
2. `plan_wave.py --cluster PB4421` refuses ("no kb/Work note names the cluster 'PB4421'"): a note cannot be planned by
   its own id unless another note names it as a cluster.
3. `plan_wave.py --cluster PB3114 --dry-run` planned group A, a `finisher` for PB2103 with PB4279, PB4281, PB4283,
   PB4284, PB4285, PB4297, PB4305, PB4307, PB4312 and PB4435 (CobolIO.g4), and group B, PB4421 alone. **Group A is
   placed although the fix-lane plan of the same minute held every one of those notes for colliding with
   `wf_a56965c4-16c-2/-3/-6`** (DESIGN-frontend-grammar.md, INTERPROGRAM_DESIGN.md). Either the campaign path's
   in-flight check misses a collision the fix-lane path sees (the module docstring says one rule gates both lanes,
   kb/Work PB2807, PB3670), or a finisher group is exempted from it in a way that does not hold here (its branches were
   recorded ABANDONED by DEVLOG 2997, so there is no carrier branch to continue).

The unit could neither launch PB4421 alone (editing groups.json is forbidden) nor launch the campaign without
breaking the operator's hold and colliding with running work, so it launched nothing.

**Sites:** `scripts/orchestrator/plan_wave.py` (`plan_partition`, `plan_fill`, `plan_main`)

## Fix direction

- Let the planner plan a named note set (`--notes PB4421`), through the same partition, collision and ledger path, so
  an operator's "plan X first" is a planner input, not a hand-edit.
- Reconcile the campaign path's in-flight check with the fix lane's: one function decides "held by in-flight work"
  for both, and a planner test pins that a note held in the fix lane is held in a `--cluster` plan of the same tree.
