# PB5943 - gate_slot.py's self-test is red intermittently inside the audit run

**Observed** by listing step 6b slice 1 (w20262104k, branch `listing-step-6b`, 2026-11-18), on a tree whose changes since main
are under `src/`, `tests/`, `docs/`, `kb/` and `DEVLOG/` only (no file under `scripts/`):

| Run | Command | gate_slot.py |
|---|---|---|
| 1 | `python -I E:/COBOL-coord/scratch/my-20261115/session-scripts/run_audits.py` (head 82820eddff's parent) | RED ("SELF-TESTS: RED - 1 of 211 failed: scripts/gate_slot.py") |
| 2 | `python scripts/gate_slot.py --self-test` alone | GREEN, "ALL GREEN - 16 arms" |
| 3 | run_audits.py (head 82820eddff) | GREEN ("AUDITS: GREEN of 33") |
| 4 | run_audits.py (head 2245bf77d1, main merged) | RED, the same line |
| 5 | `python scripts/self_tests.py` (no `--reuse`) | GREEN in 27.6 s |
| 6 | run_audits.py (head 2245bf77d1) | GREEN |

The failing arm's text was not captured (the audit summary prints only the file). Other gates of other sessions may have held
slots on the host during runs 1 and 4; the self-test's arms exercise FIFO order, a shared cap across worktrees, heartbeats and
the hold-median flag, so an arm that reads machine-wide slot state or a wall-clock interval under load is the first suspect.

**Next:** capture the failing arm (run the audit with the self-test's full output kept), then fix the arm at its root: isolate
it from the host's real slot state, or replace a timing assumption with an event. Never a retry (CLAUDE.md, "a flake is a
kb/Work defect fixed at its root").
