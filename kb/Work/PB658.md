# PB658 — LANDED (wave 1009, group C) — one rule, two owners

## Landed

Re-probed: `FUNCTION NUMVAL-C(ED "$")` over `PIC ZZ9` drew one COBOLNET1627 from the bespoke arm; `NUMVAL(ED)` and `NUMVAL-F(ED)`
compiled clean. **One mechanism now owns every category-worded string position**: a new per-position predicate,
`ArgPredicateKind.CharacterCategory` (`IntrinsicArgumentRules.EditedCategoryOf` / `PredicateViolation`), bars the three EDITED
categories (numeric-edited, alphanumeric-edited, national-edited), declared in the schema row beside the clause that says
category: NUMVAL §15.67.3 r1, NUMVAL-F §15.69.3 r1, NUMVAL-C §15.68.3 r1, TEST-NUMVAL-C (§15.94.3 r1 -> §15.68.3 r1) and — found by
the sibling sweep of every §15 argument rule that says "category" — ORD §15.70.3 r1 ("of category alphabetic, alphanumeric, or
national": a one-position `PIC Z` item is class alphanumeric and category numeric-edited). The bespoke `IntrinsicBinder` arm is deleted.

**The 't' kind was wrong, not just duplicated.** It was a hand-listed CATEGORY set that listed the de-editing class, shared by rows
whose clauses differ: TEST-NUMVAL §15.93.3 r1 and TEST-NUMVAL-F §15.95.3 r1 say "a data item of CLASS alphanumeric or national" and
LOCALE-DATE §15.52.3 r1 / LOCALE-TIME §15.53.3 r1 say "of class alphanumeric or national", which Table 2 gives numeric-edited (display),
so they ADMIT it and always did, by accident of the same set. The kind is now `'a'` = `ByClass(Alphanumeric, National)` (derived, no
hand list), the predicate rides only the category rows, and the category-worded exemption in
`EveryClassWordedArgumentKind_IsClosedUnderItsTable2Class` is gone. A new drift test
(`CategoryWordedStringArguments_CarryTheCategoryPredicate_AndClassWordedOnesDoNot`) reads each clause's wording from the specification and
demands the predicate exactly when it says category. HIGHEST/LOWEST-ALGEBRAIC (§15.43.3 / §15.58.3, "category numeric or numeric-edited") and
SMALLEST-ALGEBRAIC (§15.83.3, "category numeric") were probed and are right (`BindAlgebraicFold`); NATIONAL-OF's argument-2 ("category
national") is `CheckRepertoireArgs`'s and unchanged.

Goldens: `conformance:2002/pb658_numval_category_positions` (a ref-mod view of a numeric-edited item is category alphanumeric, §8.4.3.3.4
GR6, and TEST-NUMVAL admits the item itself), negatives `pb658-numval-numeric-edited-argument` and `pb658-ord-numeric-edited-argument`
(the NUMVAL-C numeric-edited negative this replaces stays covered by `pb60-numvalc-edited-argument`). Under `--permissive` the category
screen is the usual DA6 warning (the bespoke arm errored in every mode).

## The note as filed

Found 2026-09-05 by the `PB305` implementer (report §"New defects" A), which made the cross-argument CLASS rule
project each operand through §8.5.2.1's Table 2 before merging, and observed that `FUNCTION NUMVAL-C(ED "$")` over
`01 ED PIC ZZ9.` drew TWO COBOLNET1627 diagnostics before its fix — one for the class disagreement (now gone) and
one from a bespoke category arm — while `Admissible`'s own `'t'` set claims to admit the item.

## The rule

§15.68.3 r1: "Argument-1 shall be of category alphanumeric or national" (`OK §15.68.3 1)`) — CATEGORY-worded; and
§8.5.2.1: "Use of the name of a data class or data category in the rules of COBOL refers to the category unless
class is specifically indicated" (`OK §8.5.2.1`). A numeric-edited item is category numeric-edited, so r1 excludes
it; the same reading applies to every `'t'`-kind position whose rule is category-worded (§15.3's argument
definitions name the string-argument positions by category).

## The mechanism

`src/Cobol.Net.Compiler/Binding/IntrinsicArgumentRules.cs` — the `CategoryStringRules` field and `Admissible`'s
`'t'` arm (`:963` on main) list `CobolClass.NumericEditedDeEditing`, so the generic screen ADMITS a numeric-edited
item at a category-worded string position; `IntrinsicBinder` carries a bespoke EDITED-category arm for NUMVAL-C
and TEST-NUMVAL-C only, which REJECTS it. Two mechanisms, one rule ([[one_rule_one_place]]); the `'t'` set already
excludes `PIC A` (category alphabetic), which shows it was meant to be a category enumeration and the de-editing
class crept in.

## Fix shape

Decide which mechanism owns §15.68.3 r1 and every category-worded `'t'` position, and delete the other: the
generic screen's `'t'` set becomes the CATEGORY set (alphanumeric, national — no de-editing class), derived from
the kind table the way PB305 derives the class sets, and the bespoke `IntrinsicBinder` arm is removed. Then sweep
the ten-plus `'t'` functions with a `PIC ZZ9` argument at each string position: each is either correctly rejected
under its category-worded rule (COBOLNET1627 naming the rule) or, where the function's own rule is CLASS-worded
(say which, with `cite.py --check`), admitted through PB305's Table-2 projection. Goldens: the NUMVAL-C negative
(one diagnostic, the right rule), a positive for a class-worded sibling if one exists, and a drift test asserting
no function has both a generic-set admission and a bespoke rejection for the same category.
