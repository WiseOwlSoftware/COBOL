**Rule it breaks:** ISO 13.18.40.4 GR14 es: for extended editing sign control symbols with FIXED insertion each occurrence counts the literal width; only the FLOATING form counts one literal plus one per repetition. EditingPositions multiplies by occ only for the IS form (r.SimpleInsertion ? occ : 1), so every FOR-form rule is sized as floating even when EditRule.Floating is false. PB855 made two fixed occurrences of one letter legal (golden E07 L999L) and HasFloatingString already decides fixed vs floating, but the size count never asks it.

**Scenario:** Measured with the Oct-15 build (PictureAnalyzer unchanged since the pin): 01 G. 05 W PIC L999L EDITING L FOR NEGATIVE IS "DB ". 05 T PIC X VALUE "|". MOVE -123 TO W displays [DB 123DB ] (9 characters) but FUNCTION LENGTH(W) = 7 and FUNCTION LENGTH(G) = 8, while MOVE G TO R (PIC X(12)) stores DB 123DB | (10 characters). GR14 gives W 9 and G 10: the declared size disagrees with the item image, so LENGTH, group size, record size and any REDEFINES or file record over G are silently wrong.

**Measured how:** R2 batch finding `data-binding-9--code--f1#2` (pair data-binding-9--code), read in the pinned tree at 8be23006851a; skeptics rule upheld, scenario upheld, site upheld.

**Spec:** §13.18.40.4 "For extended editing sign control symbols with fixed insertion, each occurrence of the character(s) specified in the associated literal are counted in the size of the item." (`cite.py --check` passed at collection); §13.18.40.3 "For extended editing sign control symbols, either one or two extended editing sign control symbols may be used in character-string-1." (`cite.py --check` passed at collection)

**Target:** EditingPositions sizes a FOR-form rule by its own Floating flag (computed just above in ValidateEditing): fixed = occ x (Width-1), floating = (Width-1) once; the size count and the renderer then read the one fixed/floating decision. Add the multi-character fixed L999L row to PictureCategoryDriftTests so GR4 size equals rendered width over the accepted set.

**Design reference:** §8.3.

## Landed — wave 1093 (group E)

Re-probed on the wave's own build: `PIC L999L EDITING L FOR NEGATIVE IS "DB "` displayed `[DB 123DB ]` with
`FUNCTION LENGTH(W)` = 7 and the group 8 (GR14 gives 9 and 10). Fixed at the root: `PictureAnalyzer.EditingPositions`
sized a FOR rule as floating (`r.SimpleInsertion ? occ : 1`); it now reads the one fixed-or-floating decision the
renderer reads, `EditRule.Floating` (`PictureComposition.HasFloatingString`, rule 6's adjacency test): floating = one
literal-wide occurrence plus one character per repetition, every other rule counts the literal at each occurrence.
Golden `2023/pb3220_editing_for_fixed_occurrences_size_2023` (L999L = 9, LLLL9.99 = 13, the IS form, L$999L); no
negative (legal source, no new refusal). Drift: `PictureCategoryDriftTests.EveryAcceptedEditingPicture_HasTheSizeOfItsRenderedImage`
walks 5 symbols x form x literal width x DECIMAL-POINT mode and compares the bound size with the rendered width.

Review round 1 (finding R1-1, same mechanism, mixed arm): one character-1 can hold BOTH a floating string and a FIXED
occurrence (`PIC LL9L EDITING L FOR NEGATIVE IS "DB "`: SR24 counts the string as one extended symbol and the trailing
L as the second; Table 10 leaves the floating string out and SR25/SR26 own the order). The per-rule `Floating` flag
could not describe it: size 6 instead of 8, the trailing L a third digit position, its literal never rendered.
`PictureAnalyzer.SeparateFixedFromFloating` now gives such a letter's fixed occurrences a KEY of their own in the mask
(a private-use character) with a twin rule differing only in `Floating: false`, after `PictureComposition.Validate`
has accepted the string as written, so size, digit anchors, renderer and de-editor each read one kind per key.
Golden `2023/pb3220_editing_for_mixed_floating_fixed_2023` (LL9L = 8, LLL9L = 7, the images, the group MOVE); Unit
`AFloatingStringAndAFixedOccurrenceOfOneCharacter1_AreSizedEachByItsOwnKind` (GR14 arithmetic written per occurrence,
independent of the renderer) and a `mixed > 0` population guard in the size walk.
