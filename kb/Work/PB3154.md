# PB3154 — repository class names are declared again in the factory and instance censuses

Source: wave 1076 (unit `w1076a`, PB2921), new-defects lead 2. The repro was run by the w1076a implementer on its build (bf8-1 at 3429aad94) with the result below; the report adds that the w1074a2 build refuses it too, so it predates PB2921. Not re-probed by the clerk (R2). R1: no open note covers it (PB2160 unifies the two OoReparent* copies, a different mechanism).

**Rule.** The report cites §10.5 and §8.4.6.1. §8.4.6.1 checks OK; the quoted text of §10.5 could not be checked mechanically (`cite.py --check 10.5 "REPOSITORY"` FAILs), so only the clause numbers are recorded and an implementer must re-derive them (rule 1).

**Observed.** `01 F1G PIC X.` in the FACTORY of class F1H, whose REPOSITORY names CLASS F1G, is refused COBOLNET2692, although the factory never uses F1G. Expected: accepted (legal source).

**Code site.** `OoDriver.BindClassData` (`src/Cobol.Net.Compiler/Oo/OoDriver.cs:117`) binds the class's environment division through each definition's binder, via `OoReparentClassData` (defined :219, called :143) and `OoReparentFactoryData` (defined :231, called :162); the repository entries are thereby declared in the factory census too (`fdata.BindDeclarations(fsynthetic)`, :163) and in the instance census (:144). Related: PB2160 (the two reparent copies).

**Repro (`f1.cob`, scratch path transient, source inline):**

```cobol
       IDENTIFICATION DIVISION.
       CLASS-ID. F1G INHERITS FROM BASE.
       ENVIRONMENT DIVISION.
       CONFIGURATION SECTION.
       REPOSITORY.
           CLASS BASE.
       END CLASS F1G.

       IDENTIFICATION DIVISION.
       CLASS-ID. F1H INHERITS FROM BASE.
       ENVIRONMENT DIVISION.
       CONFIGURATION SECTION.
       REPOSITORY.
           CLASS BASE
           CLASS F1G.
       IDENTIFICATION DIVISION.
       FACTORY.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 F1G PIC X.
       END FACTORY.
       END CLASS F1H.
```

**Fix shape.** Declare the class environment's repository names once, in the binder that owns them, and give the factory and instance binders an inherited (not declared) view, the PB990 inherited-name model; sweep the instance (OBJECT) side, which shares the mechanism.

## Landed 2026-10-14 (w1077 C)

Re-probed on the wave's build (a6744fa4d): the repro above (`01 F1G` in the FACTORY) and its OBJECT twin (`01 F2G` in
the OBJECT) were both COBOLNET2692 "names two types of user-defined word in this source element (object-class-name and
data-name)"; after the fix both compile. Rule, re-derived: §10.5 "A source element is a source unit excluding any
contained source units" (OK §10.5), §3.165 "Any source units contained within a source unit are part of the containing
source unit" (OK §3.165; Annex D.6.1.1 lists factory and object definitions as source units), §8.3.2.2 "Within a source
element, a given user-defined word may be used as only one type of user-defined word" (OK §8.3.2.2), §8.4.6.1 "each
source element may use identical user-defined words to name items independent of the use of these user-defined words by
other source elements" (OK §8.4.6.1), §12.3.4 GR1 (OK §12.3.4 1)).

Root: each half binder took the class definition's ENVIRONMENT DIVISION into its own synthetic unit, so every word the
class's REPOSITORY and SPECIAL-NAMES declare was declared again in the factory's census and in the instance census, which
was moreover the class's own (so the CLASS-ID too). Three arms, one mechanism: a REPOSITORY class (the note), a
SPECIAL-NAMES word (an alphabet-name, a class-name, a symbolic-character ...), the CLASS-ID in OBJECT data.

Fix: `OoDriver.BindClassData` binds the class's environment division and CLASS-ID ONCE, in a binder of the class's own
element (`ElementBinder(classCtx, ...)`), and each half binder takes `DataBinder.InheritConfiguration(classData)` before
it binds its own divisions (`OoDriver.OoReparent(env, data)`, which replaced `OoReparentClassData` and
`OoReparentFactoryData`: kb/Work PB2160). `OoClassTable.CensusOf` gives the instance definition its own census. With one
environment division per unit, `DataBinder.EnvDivisions` (the multi-division reverse walk) is deleted and its six callers
read `environmentDivision()`. Sweep findings fixed here: `InheritConfiguration` never carried SYMBOLIC CHARACTERS, so a
contained program's `MOVE SYM-B TO Y` naming its container's symbolic-character was COBOLNET1639 (the halves need it
too now); and an OBJECT data-name spelling the CLASS-ID, legal after the fix, emitted a field named like its enclosing
C# type (CS0542), so `DataBinder.ReserveClassMemberNames` (was `ReserveMethodMemberNames`) reserves the type name.

Goldens: `2002/pb3154_half_data_named_like_class_words` (factory and object data spelling a REPOSITORY class, an
alphabet-name and the CLASS-ID; the object method reads the class's SYMBOLIC CHARACTERS and CLASS clauses);
`85/pb3154_contained_symbolic_character`; negative `pb3154-object-data-spells-a-class-it-references` (the object element
USES the class-name too: COBOLNET2692 at 2002 2014 2023).

For the next implementer:
- `src/Cobol.Net.Compiler/Oo/OoDriver.cs#BindClassData` — the class element's binder (`classData`) declares the class's
  words; each half `InheritConfiguration`s from it, THEN `CallInheritOptions` (InheritConfiguration writes the options
  baseline too). `ElementBinder` is the one DataBinder constructor for every OO element; `OoReparent` the one synthetic.
- `src/Cobol.Net.Compiler/Oo/OoClassTable.cs#CensusOf` — one census per element, the OBJECT paragraph's included.
- `src/Cobol.Net.Compiler/Binding/DataBinder.Switches.cs#InheritConfiguration` — the one carrier of a container's
  configuration state; a new SPECIAL-NAMES table must be added HERE or contained programs and OO halves lose it.
- `src/Cobol.Net.Compiler/Binding/DataBinder.Oo.cs#ReserveClassMemberNames` — every name the emitted C# class holds
  before the data binds (type name + methods).

**Review round 1 (R1-1, fixed by the review finisher).** The inherited SYMBOLIC CHARACTERS table had no shadowing: a
nearer data-name of the spelling (a contained program's own, a middle program's GLOBAL one, an OBJECT or FACTORY data
item, a method's own item) lost to the container's figurative. Each inherited symbolic now carries its containment
distance and `DataBinder.DropShadowedConstants` hides it through `DeclaredNearerThan` (data-, condition- and
index-names); a method's own names hide symbolics and constant-names at reference time (`ActiveMethodDeclares`). Goldens
`85/pb3154_contained_symbolic_shadowed`, `2002/pb3154_half_data_hides_class_symbolic`.

**Review round 2 (R2-1, fixed by the review finisher).** `DeclaredNearerThan` asked `ByName`, `Conditions` and
`IndexNames` only, but two data-name classes live off `ByName`: the named OCCURS DYNAMIC CAPACITY register (§13.18.38.3
SR30, `_capacityRegisters`) and the REPORT SECTION sum counter (§13.18.54.4 GR5, `_sumCounters`). So a contained
program's register or sum counter spelled like its container's symbolic-character still read the figurative (a
regression against main, which did not inherit symbolics), and its register spelled like a container's GLOBAL constant
read the constant (pre-existing on main). The predicate now asks both indexes (a method's table excluded at
the object tier); `ActiveMethodDeclares` asks the method's own tables' registers; `GlobalNameClassDriftTests` holds the
predicate to the inherited name-index list. Goldens `2014/pb3154_capacity_register_hides_alias`,
`2014/pb3154_half_capacity_register_hides_symbolic`, `2002/pb3154_sum_counter_hides_symbolic`.

**Review round 3 (R3-1, fixed by the review finisher).** The round-2 sum-counter ask had no tier: `_sumCounters` also
holds every inherited GLOBAL report's counters (`InheritGlobalReport`, §13.18.27.4 GR1), so a FARTHER container's
counter removed a NEARER container's GLOBAL constant (`INNER 005` for `INNER KKK`, a regression against main). The ask
now places each counter by its report (`ReportDepth(c.Report) < depth`). The sibling arm, pre-existing on main:
`ReferenceResolver.SumCounterFamilyFor` resolved a farther container's counter before ordinary lookup, so it also beat a
nearer container's GLOBAL data item or index-name (§8.4.6.2.1 3) b) 2.); it now yields to a name declared nearer than
the counter's report (`DeclaredNearerThan` unqualified, the qualified item's `DeclaringDepth` otherwise). Golden
`2002/pb3154_global_sum_counter_tier`; the drift Fact also pins the tiered ask.
