# PB475 — OPEN — a rule about a WIDTH, closed on witnesses that cannot see one

Found 2026-09-04 by the `PB470` implementer, outside its mechanism: its 2014 golden's `RAISED=` leg displayed
`FUNCTION EXCEPTION-STATUS` and the raw stdout carried `EC-ARGUMENT-FUNCTION` followed by eleven trailing spaces
— 31 positions — while the `.out` it matched carries none. Re-derived on this tree for this note.

## The rule

`python scripts/spec/cite.py --check 15.33.3 "A 31-character, left-justified, alphanumeric character string that is the exception-name"`
→ **OK §15.33.3 1) (Returned value rule)**: "A 31-character, left-justified, alphanumeric character string that is
the exception-name or the value 'EXCEPTION-OBJECT', as applicable, associated with the last exception status.
All letters in the exception-name are returned as uppercase letters and all unused characters are alphanumeric
spaces. If the last exception status indicates no exception, alphanumeric spaces are returned."

The number 31 is the STANDARD's, not an implementor determination — nothing to add to `docs/CONFORMANCE.md`.
`src/Cobol.Net.Runtime/Exceptions/EcFunctions.cs#Status` cites the rule and returns 31 positions; PB470's probe
measured exactly that.

## Why the row's evidence does not measure the rule

`tests/version-matrix/traceability-inventory.json` row **`RV-15.33.3-1`** is `OK / CONFORMS` on
`conformance:2023/ec_range_invalid`, `conformance:2002/oo_ec_raise_object` and siblings, each of which DISPLAYs
the function's value. `tests/Cobol.Net.Tests.Conformance/CompilerUnderTest.cs:51-52` normalizes every captured
line with `line.TrimEnd(' ')` before the golden comparison — so a 20-position result, the correct 31, or a
40-position one all print `EC-ARGUMENT-FUNCTION` and all match. The row is closed on witnesses that are
evidence for the NAME and the CASE, and for nothing the rule says about WIDTH or the trailing spaces. This is the
positive-only-evidence shape `kb/Work/PB468` lists among its owner questions, on an RV row.

## What closes it

One witness that survives the trim, added to an existing golden that already raises a condition (no new
program): `DISPLAY "LEN=" FUNCTION LENGTH(FUNCTION EXCEPTION-STATUS)` → `LEN=31` (§15.50.4 r3), and a
bracketed reference-modification `DISPLAY "[" FUNCTION EXCEPTION-STATUS (21:11) "]"` → eleven spaces inside the
brackets, which the trim cannot reach. Then `RV-15.33.3-1`'s `test-ref` names that golden. Sibling sweep for the
implementer: every RV row whose rule fixes a WIDTH (EXCEPTION-LOCATION §15.30.3, EXCEPTION-STATEMENT §15.32,
CURRENT-DATE §15.22.4, WHEN-COMPILED) closed on a bare DISPLAY has the same hole — check each row's witness for
a trim-surviving read before calling it closed.
