# PB5741 - OWNER: does D-UTC-OFFSET extend to --std 2002?

**Sites:** none (an owner determination; `docs/conformance/3/D-UTC-OFFSET.md` is the determination's text, and `CobolDate.Format21` the code it describes, which does not change by this note).

**For the owner, not decided here.** The determination `docs/conformance/3/D-UTC-OFFSET.md` (owner, for 2023: §2023:15.21.3 r1 and
§2023:15.99.3 r1) reports the true UTC offset in positions 17 to 21 even when it leaves the rule's stated range, because UTC+14:00
is a real zone (`Pacific/Kiritimati`) and every in-range answer misreports it. No kb/Work note owns that determination, so this is the
decision-pending note the 2002 row needs; the clerk that filed the 2002 read's notes could not attach the row anywhere.

The 2002 text states the same bound. `§2002:15.16.2 RV1` (`cite.py --check`: OK): "If character position 17 is '+', two numeric
digits are returned in the range 00 through 13 indicating the number of hours that the local time is ahead of Coordinated Universal
Time", and `§2002:15.16` (`cite.py --check`: OK) defines the value as the "local time differential factor provided by the system on
which the function is evaluated".

**Observed** (re-run 2026-11-15 on the registrar landing's build of main 95e8e476ad;
`E:/COBOL-coord/scratch/op-20261114/read-2002/defects-work/d/p/dt1.cob`, `WISEOWL_COBOL_CLOCK=2026-11-15T10:20:30.45+14:00`,
log `E:/COBOL-coord/scratch/op-20261115/registrar-sample/runs4.log`): `CD=2026111510203045+1400 LEN=000000021` at `--std 2002` and
at `--std 2023` alike.

**The question.** Should D-UTC-OFFSET cover `--std 2002` as it covers 2023 (then `2002-RV-15.16.2-1` is recorded under the
determination at 2002, and the determination's text names §2002:15.16.2 RV1 too), or should 2002 behave otherwise (then the row is a
defect with its own note)?
