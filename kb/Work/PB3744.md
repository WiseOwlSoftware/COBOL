# PB3744 — queue_facts.py's docstring undercounts its callers

**Sites:** `scripts/orchestrator/queue_facts.py#read`, `scripts/orchestrator/queue_facts.py` (the module docstring).

The module docstring (line 8) says two readers use `queue_facts.read` and "nothing else asks GitHub about a pull request's place in the queue" (the branch survey `prune_worktrees.live_survey` and the landing lane's queue watch `land_lane.py`, with a third caller for bounce reds). Commit 1888d3219 on the PR #580 branch adds a fourth, `enqueue.driver_file_holders`, and through it `land_lane.driver_files_free` on every exit-16 wait tick. After PR #580 merges, rewrite the paragraph to name every caller or, better, to say the module is the one reader without counting them (a count rots); grep the other docs that say "two readers" (DESIGN-orchestrator-loop.md section 4.9).

(2026-10-25, review R2-1, severity low.)

## Landed

Re-probe (branch worktree-wf_a588e886-609-2): the docstring still said "Two readers use it and nothing else asks GitHub" and then counted a third and a fourth caller; `enqueue.driver_file_holders` and `land_lane.driver_files_free` were named nowhere. Rewritten to name the operations and what each answers, with no count of callers (the grep that finds them is in the docstring). The "two readers" sweep over docs/ and scripts/ found no other copy of the count (DESIGN-orchestrator-loop.md section 4.9 names no number). Closes no inventory row: process tooling, no ISO rule.

For the next implementer: `scripts/orchestrator/queue_facts.py` (module docstring) names each operation (`read`, `fetch_bounce_results`, `live_heads`) and what it answers, never a count of callers; the callers of an operation are `grep -rn "queue_facts.<operation>" scripts`. The trap: a PB3637-era merge of main brings entry points the `standard_streams` audit has not seen (`cancel_superseded.py`, `verdict_line.py`, `test_held_analyzer_output.py`).
