# PB5094 - work.py check refuses 1985 rule ids in inventory_rows

**Sites:** `scripts/spec/work.py` (whole: the `inventory_rows` resolution check, which reads only the 2023 inventory).

**Found (2026-11-09).** Filing the 1985 `--std=85` triage's defects, the clerk found that `work.py check` rejects a 1985 rule id
(`1985-SR-...`) in `inventory_rows`: the check resolves claims against the 2023 traceability inventory alone, though the 1985
inventory exists as a view (PB4991; 1985 GAP 1,044 after PB5062). So all 23 notes PB5069-PB5091 carry `inventory_rows: []`
and list their rows in the body, where no gate sees them, and their landings cannot fill `closes_rows`. Fix: resolve each
claimed id against the inventory of the edition its prefix names (the one home of the edition prefixes), then move the
rule ids of PB5069-PB5091 from their bodies into `inventory_rows` in the same change.
