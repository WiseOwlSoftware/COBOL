# PB3717 — the record-age message spells the schema change's note id by hand

**Sites:** `scripts/run_gate_legs.py:793` (`predates_landing`; the function is on branch `worktree-wf_5669d89a-9c0-19`, A3, PB3660, and lands after A2), `scripts/run_gate_legs.py` (`RECORD_SCHEMA`, `SCHEMA_NOTES`).

## What happens

PB3660 made the reader tell an older gate's record from a dirty tree through `RECORD_SCHEMA`. `predates_landing(rec)` builds its answer
with the literal `"scripts/run_gate_legs.py predates kb/Work PB3612"`. The schema number is the structured fact; the note id is prose copied
beside it. The next change to the record's fields bumps `RECORD_SCHEMA` and leaves the sentence naming PB3612: the refusal then tells the
operator an old record "predates PB3612" when it predates the later change.

## Fix

Derive the sentence from the data: a table in `run_gate_legs.py` maps each `RECORD_SCHEMA` value to the note that introduced it
(one place, next to the constant), and `predates_landing` words the message from the record's schema and that table. A drift test fails
when `RECORD_SCHEMA` has no table row.

## Landed (2026-10-25, fix-lane wave 20261703 group A, with PB3707 and PB3724)

`predates_landing` is on main (A3 landed), so the note's premise held: the message spelled `kb/Work PB3612` by hand beside the
structured `RECORD_SCHEMA`. `SCHEMA_NOTES` (next to the constant: schema 3 is PB3536, schema 4 is PB3612) is now the one
place that pairs a schema with its introducing note, and `predates_landing` words the sentence from
`SCHEMA_NOTES[RECORD_SCHEMA]`. The drift test is a `run_gate_legs` self-test arm: every schema from `LANDABLE_SCHEMA` to
`RECORD_SCHEMA` has a row, the sentence names the current schema's note, and a simulated bump (schema 5, note PB9999) names
PB9999, so a bump that forgets its row fails the arm (the table lookup raises). Sibling sweep: no other message in
`scripts/` carries a note id beside a schema number.
