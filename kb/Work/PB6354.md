# PB6354 — a backend type name in the data map

**What.** The data map row for a dynamic table (OCCURS DYNAMIC) prints `.NET T1 : CobolDynTable<string>`, the emitted-C# runtime type, in the listing's detail row.

**Rule.** Owner rule: no user-facing text or link names emitted C# in the listing, and the listing stays backend-neutral. DESIGN-listing intends the COBOL view of each item. The report's note that "the field/type is intentional, spelled by one function on StorageForm" describes the mechanism, not a justification for a CLR type name in this column.

**Fix shape.** Spell a dynamic table's storage form from its COBOL attributes (item category, size, OCCURS DYNAMIC with its capacity phrases) in the one function that produces the field, and drop the CLR generic name. Update DESIGN-listing and the data-map golden in the same change. `src/WiseOwl.Cobol.Listing/ListingDataMap.cs` is the starting site; PB6226's `ListingDynamicCapacity` sits beside it.

**Related gap (PB6226 review lead R1-1).** `ListingDynamicCapacity` omits the CAPACITY IN data-name-3 phrase, and neither the table nor its capacity register links to the other in the map, whereas a DEPENDING ON object is linked by entry id. Fold into this note's fix.
