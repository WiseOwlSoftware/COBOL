# PB5986 - at `--std 85` no mechanism flags the 1985 obsolete elements, and no user document names them (§1985:I.1.5.2.3)

§1985:I.1.5.2.3 (sentences 3 and 4 of the campaign's slice 85p-01) requires the implementation to identify the obsolete
elements of 1985 in its documentation and to provide a way to flag their use. At `--std 85` ALTER, MEMORY SIZE and LABEL
RECORDS (among the 16 obsolete items) compile with no warning, by default or with `--flag-extensions`; COBOL0903 is driven by
`ObsoleteIn`, which is null on every 1985 row (`ConstructDialectStatus.cs#StatusAt`). The refuter notes `--std 2002
--permissive` does warn on them, so a mechanism exists to extend. No user document (editions.md cites only 2023 Annex F.2)
lists the 1985 obsolete elements. Harm: none of the program-harm flags fits (a conformance obligation on the implementation);
it blocks the 1985 conformance claim (PB4885, PB4997). Golden drafted: work/85p-01/goldens/pb5924-obsolete-warning-85.

**Sites:** `src/WiseOwl.Cobol.Compiler/ConstructDialectStatus.cs` (whole: the obsolete-in status of the 1985 rows; the fix names the member)
