# PB2966 — unsigned-wide values have no STANDARD-DECIMAL landing

Filed 2026-10-10 by the train 1056 lander from the wave 1056 C implementer's report
(`E:\COBOL-coord\scratch\reports\w1056c-PB2918-report.md`, lead 2).

**Repro:** `E:\COBOL-coord\scratch\w1056c\sd2.cob`: under `ARITHMETIC IS STANDARD-DECIMAL`, `COMPUTE Q = W + 0` with W
and Q unsigned 16-byte COMP-5 and W = 2^128 - 1 takes the size error.

**Sites:** `NumericRenderer.CombineCore` (`a = DeU(a)`, about line 618: loud above 2^127 - 1 on the arithmetic
funnel) and `CobolDec.ToUnscaledCore`, which returns `Int128`, so the store `CobolNum.TryStore(CobolDec)` cannot carry
a value at or above 2^127 into an unsigned receiver even when the receiver holds it.

**Why.** §8.8.1.5.2 r1 rounds the operand into the SDIDI (PB2918 added `CobolDec.FromUnsigned` for relations and
function arguments); the arithmetic operand and the store still go through the signed carrier, so a value the
receiver's container holds is a size error (§14.7.5 applies only to a result the receiver cannot hold). The fix needs
an unsigned arm on the arithmetic funnel's SDIDI lift and an unsigned landing of the SDIDI result. Same family as
PB2965 (the unsigned lane has no SDIDI arm).

## Landing

**Landed 2026-10-11 (wave 1059 C).** Re-probed on a fresh build before any edit (`sd2.cob` under the coordination
scratch directory): `COMPUTE Q = W + 0` with W = 2^128 - 1 took the size error exactly as filed, and so did
`COMPUTE R = W / 4` (a signed receiver, a result near 2^126). The rule (cite.py --check OK): §8.8.1.5.2 r1 rounds an
operand that "cannot be expressed exactly in an SDIDI" under §11.9.11, so a 39-digit container value is an operand to
round, not to refuse; §14.7.5 3) makes the size error the RESULT's, "further from zero than permitted for the associated
resultant data item", and §13.18.60.4 GR12 gives a 16-byte unsigned item its whole container [0, 2^128). Two roots, as
the note named, one change set:

1. **The operand (`NumericRenderer.CombineCore`, `Power`, `Visit(BoundNegate)`).** `CombineCore` narrowed both operands
   through `DeU` (`CobolNum.Widen`, loud above 2^127 - 1) BEFORE choosing the lane, so the SDIDI lane, whose
   `DecOperand` already rounds an unsigned-wide operand (`CobolDec.FromUnsigned`, PB2918), never saw one. The lane
   decision now comes first and the funnel runs only on the native Int128 paths that remain. `Power` took the same
   funnel ahead of its standard-mode `DecPow` return (`W ** 1` was the size error); the standard branch now returns
   first. A unary minus over an unsigned-wide operand under a standard mode lifts it to the SDIDI before negating
   (`Negate` applied the native funnel).
2. **The landing (`CobolDec.ToUnscaledMagnitude`, `CobolNum.Store` / `TryStore(CobolDec, ...)`).** `ToUnscaled` and
   `ToUnscaledChecked` return `Int128`, so an SDIDI result in [2^127, 2^128) could not reach a receiver that holds it:
   the checked store was the size error and the no-phrase store kept the low-order DIGITS of it. An unsigned 16-byte
   BinaryCapacity receiver (`NumProfile.ImageExceedsInt128`) now takes a `UInt128` magnitude landing, returned as the
   container's bits (the form `WrapBinary` and the emitted `unchecked((UInt128))` cast already use). A magnitude past
   2^128 keeps the signed twin's disposition (checked: EC-SIZE-TRUNCATION; unchecked: the low-order digits a 38-digit
   store can use). `StoreOrRaise(CobolDec)` and the CALL/INVOKE formal landing ride `TryStore`, so they follow.

Sibling sweep (every `DeU` / `NumWiden` / `ToUnscaled*` site in `src`): the value-semantics consumers (subscript,
SET amount, PTR amount, KEYED START length, SecondsArg, `Align`/`AlignRoundedUp`, `FixedLane`, `IntakeCarrier`, CALL BY
VALUE) are Int128-lane consumers by design (CONFORMANCE.md DOC-A.1-179 (2)) and keep the funnel; `EditedLanding` hands the
edit an `Int128` and a numeric-edited receiver cannot hold 2^127 anyway. Witnesses: golden
`2023/pb2966_sdidi_unsigned_wide_operand_and_landing` (COMPUTE, ADD, SUBTRACT GIVING, MULTIPLY GIVING, DIVIDE GIVING,
`**`, unary minus; unsigned and signed receivers; checked and unchecked; the past-2^128 size error), `CobolDecWideLiftTests`
(the landing), `SdidiOperandLiftDriftTests.TheNativeWidenFunnel_RunsOnlyAfterTheSdidiLaneHasTakenItsOperands`. Docs:
`NUMERIC_DESIGN.md` D27; `CONFORMANCE.md` DOC-A.1-179 (3).

**Found and left (other mechanisms, reported as leads):** (a) `DIVIDE ... REMAINDER` of an unsigned-wide dividend under
STANDARD-DECIMAL goes through `FixedLane` (`DeU`), whose subsidiary-quotient kernel is Int128, so a dividend at or above
2^127 is still the loud size error; (b) `DecOperand`'s unsigned arm rounds at 34 digits even in a native Dec-lane
statement, where a signed operand of up to 38 digits lifts exactly (`ExactLiftDigits`): the two arms disagree for an
unsigned value of 35-38 digits.
