# PB2966 — unsigned-wide values have no STANDARD-DECIMAL landing

Filed 2026-10-10 by the train 1056 lander from the wave 1056 C implementer's report
(`E:\COBOL-coord\scratch\reports\w1056c-PB2918-report.md`, lead 2).

**Repro:** `E:\COBOL-coord\scratch\w1056c\sd2.cob`: under `ARITHMETIC IS STANDARD-DECIMAL`, `COMPUTE Q = W + 0` with W
and Q unsigned 16-byte COMP-5 and W = 2^128 - 1 takes the size error.

**Sites:** `NumericRenderer.CombineCore` (`a = DeU(a)`, about line 618: loud above 2^127 - 1 on the arithmetic
funnel) and `CobolDec.ToUnscaledCore`, which returns `Int128`, so the store `CobolNum.TryStore(CobolDec)` cannot carry
a value at or above 2^127 into an unsigned receiver even when the receiver holds it.

**Why.** §8.8.1.5.2 r1 rounds the operand into the SDIDI (PB2918 added `CobolDec.FromUnsigned` for relations and
function arguments); the arithmetic operand and the store still go through the signed carrier, so a value the
receiver's container holds is a size error (§14.7.5 applies only to a result the receiver cannot hold). The fix needs
an unsigned arm on the arithmetic funnel's SDIDI lift and an unsigned landing of the SDIDI result. Same family as
PB2965 (the unsigned lane has no SDIDI arm).
