# PB4031 — the report compose ignores `>>TURN EC-SIZE CHECKING`

**Sites:** `tests/WiseOwl.Cobol.Tests.Unit/ExactWideSettlementDriftTests.cs` (`TheOptInSites_SettleWhatTheyKeep`, whose pinned MoveEmitter text names the new checkedTransfer argument); `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/ReportWriterEmitter.cs` (`TransferImage`, `FieldImage`, `RaisingImage`, `KeptOnProhibitedInexact`, `EmitGenerate`, `EmitTerminate`, `EmitPresenting`), which reaches `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/MoveEmitter.cs` (`ConvertSource`'s `raiseOnSizeError`, `RaisingImage`, `ComputeSender`); `src/WiseOwl.Cobol.Compiler/CodeGen/Roslyn/RuntimeApi.cs` (`EditTryFormatFor`, `SizeRaisingImage`, `SizeTruncationChecking`); `src/WiseOwl.Cobol.Compiler/CodeGen/UnitEmitters.cs` (the `ReportWriterEmitter` construction); `src/WiseOwl.Cobol.Compiler/CodeGen/EcEmitter.cs` (the EC-SIZE-TRUNCATION gate row's comment); `src/WiseOwl.Cobol.Runtime/Exceptions/CheckingFlags.cs` (`SizeTruncation`) and `src/WiseOwl.Cobol.Runtime/Exceptions/ExceptionState.cs` (`ExceptionEngine.SizeTruncationChecking` and its `ExceptionState` shim). The compile-time state was `EcState.SizeChecking` / `EcState.SizeTruncationChecking`, which the compose never sees.

**What.** A printable item's `SOURCE IS <expression>` is an implicit COMPUTE. The compose is emitted outside any statement,
so no statement-level checking state is set when it runs and the store takes the unchecked landing.

**Repro.** `E:/COBOL-coord/scratch/w20261744b/r1/ck.cob`: under `>>TURN EC-SIZE CHECKING ON`, `SOURCE IS WS-A * WS-B` with
100 x 100 into a `PIC 9(3)` item prints `000` and the run goes on; the same `COMPUTE` statement in the procedure division
terminates with EC-SIZE-TRUNCATION.

**Why it was left.** It needs a design for which `>>TURN` state governs a report compose (the state at the REPORT SECTION
item, or at the GENERATE that runs the compose). That is a spec question to cite (the report-writer rules and the EC-SIZE
rules), not a clerk's. Shares no root with the PB3990 R1-1 fix beyond the call site.

## Resolution (landed, wave 20261762 group D)

**The design question, settled from the spec.** §7.3.25.4 GR6 enables checking "for the procedure division statements and
procedure division headers that follow in the compilation group", so a TURN at the REPORT SECTION entry enables nothing
there, and §14.7.5 names GENERATE among the statements whose execution the size error condition "may occur as a result
of". The implicit COMPUTE (§13.18.53.4 GR2; §13.18.54.4 GR4's ROUNDED face) runs as part of the GENERATE or TERMINATE that
prints the item, and THAT statement's state governs. This is the same answer the report's own runtime conditions already
took (EC-REPORT-SUM-SIZE, EC-REPORT-VARYING ride flags the presenting statement's guard sets).

**The fix.** One compose serves every presenting statement, so the state travels at run time: a GENERATE or TERMINATE whose
line enables EC-SIZE-TRUNCATION sets `ExceptionState.SizeTruncationChecking` around its engine call through the one
`EcEmitter.OpenGateFlags` scope (`ReportWriterEmitter.EmitPresenting`), and each implicit COMPUTE in the compose picks
the RAISING final transfer under it (`MoveEmitter.ConvertSource(raiseOnSizeError: true)`: the checked landings, the Try
stores thrown as EC-SIZE-TRUNCATION, and the size-error kernels for the operations that develop the result, so an
intermediate past binary64 raises EC-SIZE-OVERFLOW exactly as the COMPUTE statement does) and the checking-off transfer
otherwise (DOC-A.1-70's low-order digits, or §14.7.4.3 rule 7's keep). A compilation group with no exception checking
emits only the checking-off transfer (`EcState.Active`).

**Re-probe.** The repro now ends `abnormal run-unit termination: EC-SIZE-TRUNCATION (fatal)` at the GENERATE, as the
COMPUTE statement does. Goldens `conformance-suite/cases/13.18.53-SOURCE/pb4031_report_source_size_checking` (2002+),
`pb4031_report_source_prohibited_checked` (2014+) and the refusal `pb4031-report-turn-size-85`.
