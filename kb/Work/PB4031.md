# PB4031 — the report compose ignores `>>TURN EC-SIZE CHECKING`

**Sites:** `tests/WiseOwl.Cobol.Tests.Unit/ExactWideSettlementDriftTests.cs` (`TheOptInSites_SettleWhatTheyKeep`, whose pinned MoveEmitter text names the new checkedTransfer argument); `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/ReportWriterEmitter.cs` (`TransferImage`, `FieldImage`, `UnderPresentingChecking`, `RenderChecked`, `KeptOnProhibitedInexact`, `PresentExpr`, `PlanOf`, `VaryValue`, `VaryInteger`, `EmitGenerate`, `EmitTerminate`, `EmitPresenting`), which reaches `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/MoveEmitter.cs` (`ConvertSource`'s `raiseOnSizeError`, `RaisingImage`); `src/WiseOwl.Cobol.Compiler/CodeGen/EmitterState.cs` (`EcState.ComposeSizeChecking`, read by `EcState.SizeChecking`); `src/WiseOwl.Cobol.Compiler/CodeGen/Roslyn/RuntimeApi.cs` (`EditTryFormatFor`, `SizeRaisingImage`, `SizeChecking`, `SizeTruncationChecking`); `src/WiseOwl.Cobol.Compiler/CodeGen/UnitEmitters.cs` (the `ReportWriterEmitter` construction); `src/WiseOwl.Cobol.Compiler/CodeGen/EcEmitter.cs` (the EC-SIZE-TRUNCATION gate row's comment); `src/WiseOwl.Cobol.Runtime/Exceptions/CheckingFlags.cs` (`Size`, `SizeTruncation`) and `src/WiseOwl.Cobol.Runtime/Exceptions/ExceptionState.cs` (`ExceptionEngine.SizeChecking`, `ExceptionEngine.SizeTruncationChecking` and their `ExceptionState` facades). The compile-time state was `EcState.SizeChecking` / `EcState.SizeTruncationChecking`, which the compose never sees.

**What.** A printable item's `SOURCE IS <expression>` is an implicit COMPUTE. The compose is emitted outside any statement,
so no statement-level checking state is set when it runs and the store takes the unchecked landing.

**Repro.** `E:/COBOL-coord/scratch/w20261744b/r1/ck.cob`: under `>>TURN EC-SIZE CHECKING ON`, `SOURCE IS WS-A * WS-B` with
100 x 100 into a `PIC 9(3)` item prints `000` and the run goes on; the same `COMPUTE` statement in the procedure division
terminates with EC-SIZE-TRUNCATION.

**Why it was left.** It needs a design for which `>>TURN` state governs a report compose (the state at the REPORT SECTION
item, or at the GENERATE that runs the compose). That is a spec question to cite (the report-writer rules and the EC-SIZE
rules), not a clerk's. Shares no root with the PB3990 R1-1 fix beyond the call site.

## Landing (wave 20261762 group D)

**The design question, settled from the spec.** §7.3.25.4 GR6 enables checking "for the procedure division statements and
procedure division headers that follow in the compilation group", so a TURN at the REPORT SECTION entry enables nothing
there, and §14.7.5 names GENERATE among the statements whose execution the size error condition "may occur as a result
of". The implicit COMPUTE (§13.18.53.4 GR2; §13.18.54.4 GR4's ROUNDED face) runs as part of the GENERATE or TERMINATE that
prints the item, and THAT statement's state governs. This is the same answer the report's own runtime conditions already
took (EC-REPORT-SUM-SIZE, EC-REPORT-VARYING ride flags the presenting statement's guard sets).

**The fix.** One compose serves every presenting statement, so the state travels at run time as two flags, the run-time
twins of `EcState.SizeChecking` and `EcState.SizeTruncationChecking`: a GENERATE or TERMINATE whose line enables any
EC-SIZE-* name sets `ExceptionState.SizeChecking`, and one enabling EC-SIZE-TRUNCATION sets
`ExceptionState.SizeTruncationChecking` too, around its engine call through the one `EcEmitter.OpenGateFlags` scope
(`ReportWriterEmitter.EmitPresenting`). Each numeric render of the compose and the presence probe (a SOURCE expression, a
SUM counter's ROUNDED face, a PRESENT WHEN chain, a VARYING FROM/BY value) is rendered twice, plain and under
`EcState.ComposeSizeChecking` (the checked kernels, `NumericRenderer.CheckedFor`), and `UnderPresentingChecking` selects
on `SizeChecking`, so an intermediate past its range raises EC-SIZE-OVERFLOW (§14.7.5 no-phrase rule 3). Each implicit
COMPUTE also has its RAISING final transfer (`MoveEmitter.ConvertSource(raiseOnSizeError: true)`: the checked landings and
the Try stores thrown as EC-SIZE-TRUNCATION), selected by `SizeTruncationChecking`, and the checking-off transfer otherwise
(DOC-A.1-70's low-order digits, or §14.7.4.3 rule 7's keep). A compilation group with no exception checking emits only the
plain render (`EcState.Active`).

**Branch review round 1, finding R1-1.** The first version carried EC-SIZE-TRUNCATION alone, so under
`>>TURN EC-SIZE-OVERFLOW CHECKING ON` a GENERATE printed `000` for `SOURCE IS WS-D * WS-D` (1.0E200 squared) where the
COMPUTE statement raised EC-SIZE-OVERFLOW, and a PRESENT WHEN or VARYING BY expression never raised. The family flag and
the checked twin fixed it; `MoveEmitter.ComputeSender` was deleted (the twin is the one mechanism).

**Re-probe.** The repro now ends `abnormal run-unit termination: EC-SIZE-TRUNCATION (fatal)` at the GENERATE, as the
COMPUTE statement does. Goldens `conformance-suite/cases/13.18.53-SOURCE/pb4031_report_source_size_checking` (2002+),
`pb4031_report_overflow_checking` (2002+, EC-SIZE-OVERFLOW alone), `pb4031_report_source_prohibited_checked` (2014+) and
the refusal `pb4031-report-turn-size-85`.

**For the next implementer.**
- `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/ReportWriterEmitter.cs#UnderPresentingChecking` / `#FieldImage` / `#EmitPresenting` own the rule: the presenting statement's EC-SIZE state, carried by the two run-time flags; route EVERY new numeric render the compose or the presence probe makes through `UnderPresentingChecking`, and REUSE `EmitPresenting` for any new presenting verb. Trap: the compose is compiled ONCE, so `EcState.Info` is empty there; never read compile-time checking state in compose code except through `RenderChecked`.
- `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/MoveEmitter.cs#ConvertSource` (`raiseOnSizeError`, `RaisingImage`): the raising implicit-COMPUTE FINAL transfer; its operations take their kernels from the render's checking state. A MOVE never passes it. `ExactWideSettlementDriftTests` pins the two `TransferWide` lines' text.
- `src/WiseOwl.Cobol.Compiler/CodeGen/Roslyn/RuntimeApi.cs#SizeRaisingImage` / `#EditTryFormatFor`: an edited Try store as a raising expression; REUSE before writing a new raising kernel.
- `src/WiseOwl.Cobol.Runtime/Exceptions/CheckingFlags.cs#Size` / `#SizeTruncation`: the flags are NOT in `EcEmitter.FatalAmbientGates` (the EC-SIZE rows stay null-flagged; a flagged row needs a FatalIfEnabled helper, `ExceptionRaiseHelperDriftTests`), and a new public runtime member needs `PublicAPI.Unshipped.txt`.
