# PB3816 — a doc comment contradicts the branch that made the cap edition-dependent

**Sites:** `src/Cobol.Net.Compiler/Validation/VersionConformancePass.cs#VisitConcatenationExpression` (doc comment, line 2530-2532:
"The §8.8.3.2 SR checks (same class / no ALL figurative / 8,191 cap) are the binder's ConcatFolder — edition-invariant
semantics, not gates.").

## Measured

Re-read on origin/main 33e3dcf21: the comment still says so. PB1601 made the cap depend on the edition
(`CobolLiteral.MaxPositions`: 160 below COBOL-2014, through `ConcatFolder.ResultLengthViolation(folded, dialectLevel)`; VCR row
7.43). The implementer's sibling sweep of `8191|8,191` over src missed this line.

## Acceptance

- The comment says the same-class and no-ALL checks are edition-invariant and that the length cap is the edition-dependent
  one (cite the PB1601 row and `ConcatFolder.ResultLengthViolation`).
- Re-sweep `git grep -nE "8191|8,191" -- src` and `git grep -n "edition-invariant" -- src` for any other comment that says the cap does not move.
