## Rule

ISO 13.10.3 SR2: "Except in a compiler directive, constant-name-1 may be used anywhere that a format specifies a
literal of the class and category of constant-name-1" (`cite.py --check 13.10.3` OK). The REPOSITORY paragraph's
class-, function-, interface-, program- and property-specifiers each specify `AS literal-n`.

## Re-probe and scope correction (w1051d, 2026-10-10; not landed, returned SPLIT)

Re-probed on the w1051d build (main 471d0e954): `rep1.cob` still gives `COBOL0001: unexpected '.'` at (6,25), rc 65.

**The estimate is wrong (CLAUDE.md rule 5): this is not PB1942's one-binder shape.** `externalizedNamePhrase` is ONE
rule shared by eleven positions, and admitting a word there hands it to every reader, most of which run BEFORE any
constant entry is bound:
- `DataBinder.Switches.cs#BindSpecifierExternalizedName` (REPOSITORY PROGRAM / FUNCTION / PROPERTY / CLASS /
  INTERFACE) and `DataBinder.cs` EXTERNAL `AS` (lines ~2002 and ~5884) run inside DataBinder, where `FindConstant`
  binds a constant on demand: these can resolve the word.
- `Oo/OoNameResolution.cs#Collect` reads the REPOSITORY CLASS / INTERFACE `AS` literal with the pure
  `ExternalizedName.Peek` BEFORE binding, to build the OO repository scope; a word there resolves nothing, so
  `CLASS C AS K` would silently resolve C by its declared word.
- `BinderDriver.cs#MakeUnit` (~line 501: PROGRAM-ID / FUNCTION-ID `AS`) and `Oo/OoClassTable.cs#Externalized` (CLASS-ID,
  INTERFACE-ID, METHOD-ID, prototypes) form the externalized name before the unit's DATA DIVISION is bound.
So the complete fix needs a PRE-BIND reading of an alphanumeric / national constant-name (only `CONSTANT AS literal-1`
and `CONSTANT FROM compilation-variable-name` can be of that class, §13.10.4 GR2) that the OO scope, the unit
builder and the class table can ask, and which `DataBinder.SpecialNamesConstant` then shares (one rule, one place),
plus the grammar arm and one `ExternalizedName.Screen` overload over the phrase. Scoping the change to the REPOSITORY
binder alone would leave the OO scope misresolving `CLASS C AS K`. The identification-paragraph positions are the same
rule (§13.10.3 SR2 has no positional exception besides compiler directives) and belong in the same change.

## Landed (w1053b, 2026-10-10)

The re-scope above was right and is what landed. `externalizedNamePhrase : AS (literal | cobolWord)`, and the ONE
screen `ExternalizedName.Screen` now takes the PHRASE and a constant reading (`Binding/ConstantReading.cs`: not a
constant / refused at its own entry / a constant with its literal's class, category and value). Inside the data bind
the REPOSITORY specifiers and both EXTERNAL clauses pass `DataBinder.ReadConstant` (FindConstant, so a container's
GLOBAL constant is seen); before it, `BinderDriver.MakeUnit` (PROGRAM-ID / FUNCTION-ID), `OoClassTable.Build`
(CLASS-ID, INTERFACE-ID, METHOD-ID, prototype methods) and `OoRepositoryScope` (REPOSITORY CLASS / INTERFACE through
`ExternalizedName.Peek`) pass `Binding/PreBindConstants.cs#Read`, which reads the constant entry off the parse tree:
the source element's own DATA DIVISION, and for a method its object or factory definition's too (§11.7.4 GR5). No
containing program is read, because no pre-bind position stands in a contained program (§11.10.3 SR2, §12.3.3 SR1).
Both readers decode through `DataBinder.LiteralTokenValue` / `DataBinder.VariableStringValue`, and a constant's literal
is then held to the same class, zero-length and formation rules as a written one. A word naming no constant draws the
clause's own code with the one `ConstantReading.NotAConstantMessage` (shared with `SpecialNamesConstant`); a numeric
constant draws "stands for a numeric literal".

Goldens: `tests/conformance/2002/pb2588_as_constant_name` (PROGRAM-ID, FUNCTION-ID, METHOD-ID from its object's and
from its own LOCAL-STORAGE, REPOSITORY CLASS / FUNCTION / PROGRAM, EXTERNAL); negatives
`pb2588-as-word-names-no-constant` (another outermost program's constant is not in scope) and
`pb2588-as-numeric-constant`. Doc: `docs/COBOLNET_OO_DESIGN.md` (the REPOSITORY-scope paragraph).
