# PB1067 — OPEN

## Measured
`p8.cob` (fixed form) `COPY CPYSRC.`, with `CPYSRC.cpy`:
```
000100     DISPLAY "CPY-FIXED"                                          CPYSEQ01
000200 >>SOURCE FREE
DISPLAY "CPY-FREE"
```
prints only **`CPY-FIXED`**, exit 0, no diagnostic.

## The rule
`cite.py --check 7.3.24.3 "shall be treated as fixed form if FIXED is specified, or as free form if FREE is specified"`
→ `OK §7.3.24.3 1)`: the format switch applies to 'source text or library text following the directive'.

## Code site
`CopyProcessor.NormalizeCopybookMapped` converts a copybook it classifies as fixed-form in one piece and never looks
for `>>SOURCE` switches inside it.

## What the fixer owes
Normalize library text through the SAME line-by-line reference-format walker the main source uses (one mechanism —
feedback `one_mechanism_per_job`), starting in the format of the COPY statement (§7.3.24.3 3)); golden for FIXED→FREE
and FREE→FIXED inside a copybook, and for the format restored after the copybook ends.

## 2026-09-24 — REGISTRAR 15a extends this note

Batch 15a (source-format-directive finding #60, compiler-directives GR-7.3.4-5) WIDENS this note: library text gets its reference format from its OWN heuristic (`CopyProcessor.NormalizeCopybookMapped`), not from the format in effect for the COPY statement (§7.3.24.3 GR3 — `cite.py --check 7.3.24.3 "The default reference format of library text is the reference format that was in effect for the COPY statement"` → OK §7.3.24.3 3)), and a copybook judged fixed skips the >>SOURCE walker, so a SOURCE FORMAT directive in library text neither takes effect nor reverts at its end (GR5), and GR-7.3.4-5 ('applies to all of the source text and library text that follows') is PARTIAL for exactly this directive.
