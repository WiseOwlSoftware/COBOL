# PB1067 — LANDED

## Landed 2026-09-27 (wave 67 M)

Library text goes through the ONE §6.5 walker the source text uses,
`ReferenceFormatProcessor.NormalizeToFreeFormMapped` (its new overload takes the initial format and reports a
`ReferenceFormatMap` — `src/Cobol.Net.Frontend/Preprocessor/ReferenceFormatMap.cs`), instead of
`CopyProcessor.NormalizeCopybookMapped`'s own ≥50 %-sequence-numbered heuristic, which sent a numbered member to
`ConvertFixedToFreeMapped` with no `>>SOURCE` handling (the silent drop). The initial format is the one "in effect for
the COPY statement" (§7.3.24.3 3), cite.py OK): `Frontend.Preprocess` registers the compilation group's map
(`CopyProcessor.RegisterReferenceFormat`), each library text's map is registered as it is normalized, and
`ResolveOneCopy` asks the map of the text the COPY is written in, at the COPY's origin line
(`ReferenceFormatMap.LibraryTextDefaultAt`). GR5's revert needs no code: the COPY's text was converted on its own.
**Determination** (docs/CONFORMANCE.md DOC-A.1-158, beside the auto-detection it extends): a format a directive stated,
or a library text inherited, is handed on; a DETECTED fixed format is handed on; a text detected FREE hands nothing on
and its library text is detected by its own structure (seven-space indentation is legal in both formats, so free
detection is no evidence about the library text). The legacy oracle registers its map too
(`CobolSharp.Compiler/Compilation.cs`). Probes p8 / p9 / p10 (w67m `probe/`) print `CPY-FIXED CPY-FREE MAIN-AFTER`,
`LIB-FREE LIB-FIXED MAIN-FREE-AFTER`, `LIB-FX MAIN`. Witnesses: `conformance:2002/pb1067_library_text_source_format`
(six legs), `unit:LibraryTextReferenceFormatTests`. `GR-6.5-9` leaves this note unclosed: its iteration half is done
(witness added), its documentation half (A.1 item 117) is PB1496's, which still claims the row. Copybooks are still
normalized with `diagnostics: null` — that is PB1640, now a one-argument change at `NormalizeCopybookMapped`.

## The defect as filed

## Measured
`p8.cob` (fixed form) `COPY CPYSRC.`, with `CPYSRC.cpy`:
```
000100     DISPLAY "CPY-FIXED"                                          CPYSEQ01
000200 >>SOURCE FREE
DISPLAY "CPY-FREE"
```
prints only **`CPY-FIXED`**, exit 0, no diagnostic.

## The rule
`cite.py --check 7.3.24.3 "shall be treated as fixed form if FIXED is specified, or as free form if FREE is specified"`
→ `OK §7.3.24.3 1)`: the format switch applies to 'source text or library text following the directive'.

## Code site
`CopyProcessor.NormalizeCopybookMapped` converts a copybook it classifies as fixed-form in one piece and never looks
for `>>SOURCE` switches inside it.

## What the fixer owes
Normalize library text through the SAME line-by-line reference-format walker the main source uses (one mechanism —
feedback `one_mechanism_per_job`), starting in the format of the COPY statement (§7.3.24.3 3)); golden for FIXED→FREE
and FREE→FIXED inside a copybook, and for the format restored after the copybook ends.

### Row `GR-6.5-7` — DIVERGES (editions 2002/2014/2023 (free-form reference format; the SOURCE FORMAT directive that selects it is a 2002 introduction))

'If the line is a free-form line and is not a continuation line, that line is copied to the resultant compilation group.' (--check OK §6.5 7)). The free segment arm copies each line as-is (TrimEnd('\r') only; line 172), and a whole-file free source returns MappedText.Identity. Probes rf1/rf9/rf16 (free) compile their non-continuation lines unchanged. The continuation half of free-form lines is GR-6.5-8 (NOT-IMPLEMENTED). No isolating spec-derived golden. || REFUTED: DIVERGES — §6.5 applies to source text AND library text, in the order lines are obtained. The main-source free arm of NormalizeToFreeFormMapped does copy free lines as-is (probes p10/p11/p13 correct), but library text is not routed uniformly: CopyProcessor.NormalizeCopybookMapped sends any member whose lines are >=50% sequence-numbered straight to ConvertFixedToFreeMapped, which has NO >>SOURCE handling. A free-form line following a legal '>>SOURCE FORMAT FREE' in such a member is therefore read as fixed form (cols 1-6 as sequence area, col 7 as indicator - here 'P', which the converter treats as a CCVS comment line) and is silently DROPPED instead of copied; the directive line itself is also not discarded by this stage. Same defect falsifies GR-6.5-1's 'mode is determined' for library text.
