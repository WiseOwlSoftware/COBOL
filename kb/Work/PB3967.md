# PB3967 — work.py's GPL size guard counts only closed backtick fences, and upstream_findings' docstring names a check (check_base_agrees) it never calls

**Sites:** `scripts/spec/work.py:536` (`fence_lengths`), `scripts/spec/work.py:512` (`_FENCE`), `scripts/spec/work.py:1647` (`upstream_findings`)

Two leads of PB3838 (held by the in-flight branch `notes-pb3838-upstream-file`, so filed here), one file.

1. `work.py:536` `fence_lengths` drops a block whose closing fence is missing, and `_FENCE` (line 512) does not recognise
   tilde fences, so an `upstream` record can carry a fenced program of any length and pass `work.py check`: the GPL size
   guard (standing requirement 3) is bypassable.
2. `work.py:1647` `upstream_findings` says it checks that the shipped `kb/Work.base` and the planner-facing exclusions agree
   (`check_base_agrees`), but never calls it; the three new `Work.base` arms run only in `work.py check` against the shipped
   file and have no falsifying case in `--self-test`.

## Acceptance
- An unclosed fence counts to the end of the body and a tilde fence is a fence; `upstream_findings` calls the check it
  names or its docstring is corrected; a `--self-test` arm per case, each seen RED first.
