# PB177

Found 2026-08-30 by the PB176 skeptic round (two read-only adversarial agents over the GroupImage guard;
their full analyses are in the DEVLOG-1399 session's task outputs — the load-bearing claims are restated
here). All PRE-EXISTING; PB176 changed none of these paths. One family: the boundary copy-in/copy-out
image paths were built before the image predicate and never gained it.

**A — OO method group formals / RETURNING, NO gate at all (CS1061):** `OoEmitter` emits
`{root}.FromImage({param})` and `{formal}.AsImage()` for method LINKAGE formals and RETURNING items with
no image-capability consult; `DataBinder.Oo` adds formals unscreened. The `OoConformance`/`OoBinder`
IsImageCapable checks run at INVOKE/override time — the METHOD BODY emits unconditionally, so a method
declaring `01 G. 05 A PIC X. 05 N USAGE INDEX.` as a formal fails BACKEND compilation (the struct gets
no image methods: ElementImageCapable false and no variable-length subordinate either).

**B — CallStringWrite's fall-through (CS0029), the write twin of PB176:** it guards on IsImageCapable
but falls through to `PlaceRenderer.Write(p, value)`, which for a group MemberPlace renders
`_G = <string>;`. A CALLED program with a non-image-capable group LINKAGE formal (INDEX leaf) gets
`_G = __lnkp0.Value;` — uncompilable — while its read twin correctly stages the loud. Same exposure via
ReportWriterEmitter's `CONTROL IS <group>` write.

**C — the bind-side half, missing screens:** §14.9.4.3 SR12's variable-length-group argument screen is
gated `!isReturning && !formatTwo`, so Format-2 (AS NESTED / prototype) CALL arguments and RETURNING
items are unscreened; INVOKE arguments have no SR12 equivalent anywhere. DERIVE FIRST what the spec
actually requires per form (§14.9.4.3 / §14.8.2 / the INVOKE rules) — the screens may be spec-required
rejections, not just defensive. Also: the binder screens dynamic-CAPACITY under REDEFINES
(COBOLNET1525, §13.18.44 SR5) but has NO screen for DYNAMIC LENGTH under REDEFINES — derive §13.18.44's
rules for it (an IntrinsicBinder comment asserts SR17 bars dynamic items under REDEFINES; validate with
cite.py, then either screen it or admit it deliberately).

**WHAT WOULD CLOSE IT:** the boundary paths consult the SAME predicate every operand path consults —
A: gate the method-body formal image round-trip (loud or bind-reject per the derived spec rule);
B: CallStringWrite's fall-through stages the loud like its read twin (the eighth two-arm instance);
C: the derived screens, each with negative fixtures. Sweep every `.AsImage()`/`.FromImage(` spelled
outside PlaceRenderer (the ONE-reader law in GroupImage's doc) — PB178 carries the AsStorageImage
instance.
