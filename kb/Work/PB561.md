# PB561

## Mechanism — value-clause-p3
`SET condition-name TO FALSE` is unimplemented, and the failure is staged at RUN TIME rather than at compile time. The `WHEN SET TO FALSE IS literal-4` phrase parses (CobolData.g4:538) and is then dropped: `DataBinder.BindCondition` iterates only `value.valueItem()`, and `Condition88` has no member to hold literal-4. `SetBinder.BindSetCondition` therefore answers `if (b.TRUE_() is null) return new BoundUnsupported(...)`, which the emitter turns into a `NotImplemented.Run` call — so the program compiles clean, starts, executes its preceding statements and only then throws.

### Expected, from the standard
§13.18.63.4 GR20 — "When a condition-name is referenced in a 'SET condition-name TO FALSE' statement, the value of literal-4 from the FALSE phrase is placed in the associated conditional-variable" — with §14.9.39.4 GR7, which adds the placement rule ("according to the rules for the VALUE clause") and the exception ("If the length of the conditional variable is zero, the SET statement leaves it unchanged"). The repro must print AFTER-FALSE=[N] and then NOW-FALSE. §14.9.39.4 SR7 ("If the FALSE phrase is specified, the FALSE phrase shall be specified in the VALUE clause of the data description entry for condition-name-1") makes the rider program illegal source, so it must draw a compile-time diagnostic, not run.

```
$ python scripts/spec/cite.py --check 13.18.63.4 "If the FALSE phrase is specified, the FALSE phrase shall be specified in the VALUE clause of the data description entry for condition-name-1"
  FAIL: §13.18.63.4 exists but does NOT contain 'If the FALSE phrase is specified, the FALSE phrase shall be specified in the VALUE clause of the data description entry for condition-name-1'
$ python scripts/spec/cite.py --check 13.18.63.4 "statement, the value of literal-4 from the FALSE phrase is placed in the associated conditional-variable"

```

### Observed
Measured. Note the harm is TWO-fold and the second half is the more expensive one: the decision is fully determined at compile time (both the 88 entry and the SET statement are in the source), so staging it to a runtime throw lets a program that cannot possibly complete start and perform work — the wrong-stage shape kb/Work PB88 named. LANDING SHAPE: (1) a literal-4 carrier on Condition88, filled in BindCondition, screened by §13.18.63.3 SR27 ("The value of literal-4 shall not be equal to the value of any occurrence of literal-2 ... nor to any value in the range of any occurrence of literal-2 through literal-3"); (2) a SetBinder arm that binds TO FALSE to a store of literal-4 through the SAME VALUE-clause compose the TO TRUE arm should be using (see the SetEmitter finding above — do not add a second private recipe); (3) the §14.9.39.4 GR7 zero-length exception; (4) an introduction gate for the phrase, which today does not exist at all — there is no ConstructRegistry row for it and it is accepted at `--std 85`.
