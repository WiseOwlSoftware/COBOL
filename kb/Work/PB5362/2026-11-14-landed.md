# PB5362 landed (wave 20262029 group C)

**Sites (landed):** `src/WiseOwl.Cobol.Compiler/Binding/FileControlBinder.ObsoleteFdClauses.cs` (`CaptureValueOf`, new `ValueOfLiteralValue`, `CaptureLabelRecords`), `src/WiseOwl.Cobol.Compiler/Binding/FileDescriptionIdentity.cs` (`ValueOfValue`, `Of`), `src/WiseOwl.Cobol.Compiler/Binding/Model/FileModel.cs` (`FdClauseValue` gains `Written`), `src/WiseOwl.Cobol.Compiler/Binding/ExternalFileConnectorRules.cs` (`CheckFileDescriptions` shows `Written`), `src/WiseOwl.Cobol.Compiler/Binding/FileControlBinder.FileSection.cs` (the BLOCK CONTAINS and CODE-SET producers).

**Mechanism and fix.** `CaptureValueOf` keyed each literal-1 by `GetText()`, so `'A'` and `"A"` disagreed (COBOL6847 on a consistent pair). The key is now the literal's class and value (`ValueOfLiteralValue`): a nonnumeric literal by class and decoded content (hexadecimal, so no character collides with the `|`/`=` separators of `ValueOfValue`, which a decoded `"A|B"` would have broken), a numeric literal by its normalized value (`7`, `007.0` agree; DECIMAL-POINT IS COMMA honored), a figurative constant by its kind (SPACE, SPACES agree, `§1985:IV.4.2.2.2.3`). The comparison key is no longer readable, so `FdClauseValue` carries the clause as written beside it and COBOL6847 shows that (`"VALUE OF FILE-ID "B"" against "VALUE OF FILE-ID "A""`).
