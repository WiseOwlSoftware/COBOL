## Review round 2, R2-1 (blocking): the external key table was in a different order from a plain describer's

Round 1 registered an EXTERNAL file's alternate keys in the sorted identity order and every other file's in clause order. The physical key table is the registration order and `FixedFileAttributes.Conflicts` compares it positionally, so the EXTERNAL clause alone changed the file's key table: a file created through an external describer got status 39 on OPEN through an otherwise identical plain one, and the reverse (reviewer's probe EXTW/NOXR). Fix at the root: the key table order no longer depends on the entry. `KeyedIoEmitter.ConnectorKeyIndex` orders every indexed file's alternate keys by their physical descriptors (the byte windows compared numerically, so an entry written in record order keeps its clause order and the NIST IX212A/IX213A key tables are unchanged; then DUPLICATES, collation, suppression value), so two descriptions of one physical file register the same table whatever their clause order, data-names or EXTERNAL clause; registration, `FileReadKeyedShared` and `FileStartIndexed` all use it. `FileEntryIdentity.AlternateKeyConnectorOrder` and `FileModel.AlternateKeyConnectorIndex` are deleted (the order cannot come from the identity string, which carries data-names). Golden `pb5567-external-and-plain-describers-share-a-key-table` crosses an external and a plain describer of one physical file in both directions. R2-2 (stale `AlternateKeys` doc comment) is corrected in the same change.
