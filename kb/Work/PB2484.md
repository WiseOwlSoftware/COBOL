# PB2484 — LANDED

Filed 2026-10-07 by the train-1035 lander from the wave-1033 group A implementer report (`w1033a-PB833-report.md`,
new lead 1). PB833 landed in that train with the cross-run-unit file lock on Windows (mandatory share modes plus the
OUTPUT host probe) and on Linux (open-file-description region locks); macOS was left without one and documented as
such in `docs/CONFORMANCE.md` DOC-A.1-75.

**Shape.** `src/Cobol.Net.Runtime/IO/Sharing/OfdRegionLocks.cs#AbiMatches` admits only Linux on x86-64/arm64, so
`OfdRegionLocks.Open` returns null on Darwin and `RunUnitFileLock.Take` answers `Unavailable`; the connector then has
only the file lock its `FileShare` gives, which .NET maps onto one advisory `flock` `LOCK_SH` for every posture but
NO OTHER. §9.1.15 2) — "The sharing with read only mode restricts concurrent access to a physical file through file
connectors other than this one, to input mode" — therefore binds another connector of the same run unit (the
`FileRegistry` Table 19 arbiter) but not another run unit.

**Repro.** `RunUnitFileLockDriftTests.ASecondRunUnitsOpenIsArbitratedByTable19` on a macOS host: the rows where a
READ ONLY or ALL OTHER holder must refuse a writer go red. No CI leg runs macOS, so this is untested here.

**Fix direction.** Darwin's classic `fcntl` locks are owned by the process and dropped when any descriptor of the file
closes (the reason Linux uses OFD locks), and its OFD commands are not public. Candidates: a per-file lock-helper
descriptor kept open for the run unit's life with process-owned `F_SETLK` locks plus in-process reference counting, or
`flock` on a per-column sidecar lock file. Either must keep the Table 19 lookup the one answer (`Table19.Cell`), as
`RunUnitFileLock` does.

## Landing

- `src/Cobol.Net.Runtime/IO/Sharing/RunUnitFileLock.cs#Take` — the POLICY of §9.1.15's file lock (the column an
  OPEN publishes, the columns its row refuses, `WireNumber`), host-neutral; `#HostOfThisProcess` is the ONE choice of
  host (Linux OFD, none on Windows, lock files elsewhere). REUSE `Take(host, …)` in a witness to hold any host to
  Table 19. Trap: a second `Take` overload exists only so a test can name the host; production calls the short one.
- `src/Cobol.Net.Runtime/IO/Sharing/SidecarColumnLockHost.cs#Establish` — the lock-file host (macOS, every non-Linux
  Unix): publish `pending-<guid>`, verify the lock is in force, rename to `<column>-<guid>`, then test the others.
  Trap: a per-COLUMN file cannot answer "anybody but me" (a request row can refuse its own column), and no `fcntl`
  P/Invoke is right on Apple arm64 (variadic); keep it managed code over `HostFile.OpenLockHolder` and
  `HostFile.IsHeldByAnother`, because `HostFileProbeDriftTests`, `SharedExtendOpenDriftTests` and
  `FileLockPostureDriftTests` forbid a stream open or a `FileShare` anywhere else under `IO/`.
- `src/Cobol.Net.Runtime/IO/FileSupport.cs#HostFile.PhysicalFileKey` — the case rule as a STRING another process
  derives identically (`PhysicalFileComparer` reads the same `FileSystemFoldsCase`); REUSE it for any name that must
  agree across run units. `HostFile.OpenLockHolder` is the one lock-file open.
- Witness: `SidecarColumnLockHostDriftTests` runs on every host; to see the host through FileConnector on a Linux box,
  force `HostOfThisProcess` to the sidecar in a throwaway clone and run `RunUnitFileLockDriftTests` (768 pairs) — it
  was green that way on 2026-10-10.

**Re-probe.** There is no macOS host here and no CI leg for one, so the shape was re-derived from the code and the
premise measured on the hosts that exist: `OfdRegionLocks.AbiMatches` is Linux x86-64/arm64 only, so on Darwin
`OfdRegionLocks.Open` answered null and `RunUnitFileLock.Take` `Unavailable`, and the connector had only .NET's
`flock` (`LOCK_EX` for `FileShare.None`, `LOCK_SH` otherwise), which says rule 1 and nothing of rules 2 and 3.

**Root cause and fix.** Neither candidate in the fix direction survived. A process-owned `F_SETLK` helper
descriptor loses its locks whenever any descriptor of the file closes (the runtime opens and closes bookkeeping
handles on a connector's file all the time), and no `fcntl` P/Invoke is right on Apple arm64 at all: `fcntl` is
variadic and Apple's calling convention passes variadic arguments on the stack where a fixed signature puts them in
registers. A per-COLUMN sidecar fails differently: a request row can refuse its OWN column, and a `flock` cannot say
"anybody but me" about a file the asker holds. The landed mechanism is a lock file PER HOLDER beside the physical
file (`SidecarColumnLockHost`): `.wolk-<16 hex>/<column>-<guid>`, held open so .NET takes a shared `flock`, tested by
requesting exclusive access (`HostFile.IsHeldByAnother`), published atomically by rename from a `pending-<guid>` file,
swept when its holder died, deleted before its descriptor closes. It is managed code over `FileShare`, with no native
call. To keep ONE policy, `RunUnitFileLock` was split into the policy (`Take`: the column, the refused columns, the
wire numbers) and a host seam, `IColumnLockHost`, with `OfdColumnLockHost` (the Linux code, moved unchanged) and the
new host, chosen once by `RunUnitFileLock.HostOfThisProcess`. `HostFile` gained `PhysicalFileKey` (the case rule as a
string another process can derive; `PhysicalFileComparer` reads the same fact) and `OpenLockHolder`.

**Witness.** `SidecarColumnLockHostDriftTests` holds the new host to `Table19.Conflicts` over all 144 (sharing, mode)
pairs, plus the simultaneous-open race, a dead holder's leftovers, the wire names and the case rule. Because it is
plain managed code it runs on Windows and Linux (and so on macOS) and witnesses the macOS path without a Mac; a
mutation that refuses only column 0 turned 76 of its 152 cases red. `RunUnitFileLockDriftTests` still passes unchanged
through the Linux and Windows hosts.

**Not done here.** The PB2660 half of the same host gap, the cross-run-unit store mutex and record locks, are
byte-range locks keyed on a record and have no lock-file expression; macOS keeps them unavailable (docs/CONFORMANCE.md
DOC-A.1-75 says so). The sidecar host trusts a lock file it cannot read as free (a foreign user's unreadable file):
`HostFile.IsHeldByAnother` treats insufficient authority as not-held, as DELETE FILE's probe needs.
