# PB5963 - a method's CALL of a program of the run unit is listed as an external program

**Found** by review round 1 of listing step 9b (lead R1-1, head `51b5e2983d`, reviewer review-LS9b; round 1 verdict CLEAN, 4 leads).

**Mechanism.** `BinderDriver.BindUnitProcedure` sets `ProgramsInScope` on its `StatementBinder` (`BinderDriver.cs:797`). `OoDriver.BindClassBody`
builds two `StatementBinder`s, the class-body one at `src/WiseOwl.Cobol.Compiler/Oo/OoDriver.cs:184` (`new StatementBinder(data, refs) { OoClasses = ... }`)
and the factory one at `OoDriver.cs:200` (`fbinder`), neither with `ProgramsInScope`. `CallBinder.RecordProgramName` then sees
`host.ProgramsInScope == null` and records every literal target as the group `ExternalProgram` entry. §2023:8.4.6.3 SR3 lets an outermost program be
referenced from any source element of the run unit, and the run-time resolver (`ProgramTable.ResolveVisible`) activates the group program.

**Observed** (reviewer's probe `E:/COBOL-coord/scratch/my-20261115/listing-build/review-LS9b/probe1/oocall.cob`, `--std 2023 --listing-sections xref`):
outermost programs MAINP and MAINQ, class OOC, method M1 with `CALL "MAINQ"` at line 26. The cross-reference prints row 4 `PROGRAM MAINQ` (refs 5 13)
and a second row 5 `EXTERNAL MAINQ` (ref 26); the CALL graph row for line 26 targets the EXTERNAL row.

**Fix shape** (reviewer): give the OO binders the same scope, set wherever a `StatementBinder` is made: for a method, the group's outermost programs
(a method contains no program and has no COMMON container), computed by the one `ProgramsVisibleFrom` with a null caller; a test with a method CALL of a
group program. The same defect is a sibling of PB5965 (the program-name scope written more than once).

**Verified** in the worktree 2026-11-20: both construction sites at `OoDriver.cs:184` and `:200` carry only `OoClasses` in the initializer.

**Sites:** `src/WiseOwl.Cobol.Compiler/Oo/OoDriver.cs:184` (`OoDriver.BindClassBody`), `src/WiseOwl.Cobol.Compiler/Binding/BinderDriver.cs:797` (`BinderDriver.BindUnitProcedure`, `BinderDriver.ProgramVisibleFrom`)
