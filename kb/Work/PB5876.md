# PB5876 - at `--std 85` a statement that references a USING operand whose table is DEPENDING ON a Linkage item of a record that is no operand compiles and reads no storage

**Ruling: UPHELD against the code (the text decides). Harm: wrong_answer (silent) and under_rejects. Severity MAJOR.** Read pass 16 of the 1985 code reads (slice 1985-233) read row `1985-GR-X.5.1-4` again after kb/Work PB5846's fix had landed; the reader found it conforming and the refuter overturned it. The rulings are in `kb/Work/PB5683/2026-11-16-rulings-code-reads-batch-16.md`. PB5846's fix holds for the mechanism it fixed (a non-operand Linkage item as a subscript or a reference-modification operand); what is ruled here is a second mechanism on the same row.

## Mechanism 1, ruled from the text: a Linkage item that is not addressable is referenced implicitly, through OCCURS DEPENDING ON, and the program compiles and reads no storage

`§1985:X.5.1 GR4` lets a Linkage Section item be "referenced within the Procedure Division of that program if, and
only if," it is an operand of the header's USING phrase, subordinate to one, or one of the three related cases the
rule lists. `§1985:IV.4.4.1` says what a reference is: it may be explicit or implicit, and "Such an implicit
reference occurs if and only if the data item contributes to the execution of the statement." The object of an
OCCURS DEPENDING ON phrase contributes to every statement that references the table's record: it fixes its
length. So when the operand `L1` holds a table DEPENDING ON `LN`, and `LN` lies in a Linkage record that is NOT an
operand, `DISPLAY L1` references `LN` within the Procedure Division, and GR4 forbids it.

The compiler refuses every WRITTEN reference to a non-operand Linkage item (`COBOL2746`; the refuter's
`lk_callarg.cob`). It does not ask the question of the implicit one. My run of
`E:/COBOL-coord/scratch/coderead-1985/out/refute-1985-233/src/lk_odo.cob` at `--std 85`: exit 0, `S L1E1=A`, then
`S L1=` and nothing after it, though the caller passed five characters: `LN` has no storage and is read as zero.
The refuter reports the same output at `--std 2023`; what 2023 requires is judged from 2023's own text by the fix
(kb/Work PB1249, landed, read the 2023 rule as reaching written references only; the fix reads 2023's definition
of an implicit reference before it keeps or changes that).

UPHELD. Harm: wrong_answer (silent: the length is taken from storage that does not exist) and under_rejects.
Severity MAJOR. Site (the refuter's reading): `src/WiseOwl.Cobol.Compiler/Binding/LinkageBinder.cs#UnreferenceableLinkageRecord`
is asked for written references only. The fix refuses a statement whose operand's size depends on a Linkage item
GR4 does not admit; a table that no statement references is not refused.

**The refuter's evidence** (the refuter's own words, from `E:/COBOL-coord/scratch/coderead-1985/out/1985-233-refute.json`, case `1985-GR-X.5.1-4`; it is the refuter's report, not the Mythos lane's): "Probe lk_odo.cob at --std 85 ... DISPLAY "S L1=" L1 -- compiles clean and prints 'S L1=' (empty: LN, in the non-operand record L2, is read as 0 with no storage), though the caller passed 5 A's. 1985 defines a Procedure Division reference as explicit OR implicit ... LN contributes to DISPLAY L1 (it fixes L1's length), so LN is referenced within the Procedure Division, and GR4 admits that 'if, and only if' it satisfies a-e; LN satisfies none. 1985 OCCURS (§1985:VI SR1-12) puts no section restriction on data-name-1, so the source is otherwise legal and the reference is the only defect. Same output at --std 2023 (lk_odo-002). lk_callarg.cob: explicit references in a DECLARATIVES paragraph and as a CALL USING argument are refused COBOL2746 (the explicit path holds). kb/Work PB1249's sweep chose the opposite reading ('the data-division resolvers (OCCURS DEPENDING ...) are not within the procedure division and are not asked'), argued from the 2023 text; the 1985 text's IV.4.4.1 is the counter. The reader's probes covered only explicit references." Its corrected verdict: "PARTIAL: legs a-e are enforced for every explicit reference, but an implicit Procedure Division reference to a non-operand Linkage item through an operand's OCCURS DEPENDING ON is admitted and reads storage that does not exist (LN = 0). Harm: under-rejects / wrong-answer. Cause (b): the same at --std 2023."
