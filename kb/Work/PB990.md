# PB990 — LANDED

## Repro — measured
`scratchpad/reg12/q02_onetype.cob`: `SPECIAL-NAMES. ALPHABET ZQ IS NATIVE.` and `01 ZQ PIC X VALUE "A".` → compiles,
prints `RAN A`. (The lead's original shape: an alphabet-name that is also a dynamic-length-structure-name.)

## The rule
`OK  §8.3.2.2` — "Within a source element, a given user-defined word may be used as only one type of user-defined word
with the following exceptions:" 1) a compilation-variable-name may match anything, 2) a level-number may match a
paragraph-name or section-name, 3) constant-name, data-name, property-name, record-key-name and record-name may share
a name.

## Code site
Each declaration kind keeps its own registry (alphabets and classes in the SPECIAL-NAMES registry, data items in the
data model, DLS names in PB829's registry, procedure names in the procedure table); no pass crosses them.

## What the fixer owes
One cross-kind name census per source element after declarations are collected, applying the three exceptions as DATA
(a table of which kinds may share), with a drift test that every §8.3.2.2 type in the bullet list has a registry feeding
the census. Negative goldens for at least alphabet/data, class/paragraph, file/data; positive for the exception-3 set.

**Code site (located 2026-09-27).** `src/Cobol.Net.Compiler/Binding/BinderDriver.cs#CheckDefinitionNameUniqueness`; also `src/Cobol.Net.Compiler/Binding/DataBinder.Switches.cs`, `src/Cobol.Net.Compiler/Binding/DataBinder.cs#BindEntries` (code). no within-source-element cross-kind census exists; CheckDefinitionNameUniqueness is THE ONE definition-name uniqueness check (group/externalized scope only, §8.3.2.2 COBOLNET2213) and is the natural home; per-kind registries are separate (SPECIAL-NAMES alphabets/classes in DataBinder.Switches, data items in DataBinder)
