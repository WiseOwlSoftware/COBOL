# PB4546 — resume-statement-not-supported: -std=cobol2014: the RESUME statement is refused ("'RESUME' is a reserved word, but isn't supported")

Filed 2026-11-03 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-batch-3000-20261103`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

Under `-std=cobol2014`, cobc 3.2 refuses every RESUME statement: "'RESUME' is a reserved word, but isn't supported".
RESUME (ISO/IEC 1989:2002 and later) is the statement that ends a declarative and transfers control to a procedure-name
or to the statement after the one that raised the exception. Class: feature missing. Fuzz programs: fz00618 and 9 more
(night fuzz-batch-3000-20261103, slice D1).

## Minimal test case

Free reference format.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. RS1.
ENVIRONMENT DIVISION.
INPUT-OUTPUT SECTION.
FILE-CONTROL.
    SELECT F1 ASSIGN TO "rs1-missing.dat" ORGANIZATION IS SEQUENTIAL
        FILE STATUS IS FS.
DATA DIVISION.
FILE SECTION.
FD F1.
01 R1 PIC X(4).
WORKING-STORAGE SECTION.
01 FS PIC XX.
PROCEDURE DIVISION.
DECLARATIVES.
D1 SECTION.
    USE AFTER STANDARD EXCEPTION PROCEDURE ON F1.
D1-P.
    DISPLAY "DECL " FS.
    RESUME AT M2.
END DECLARATIVES.
MAIN-S SECTION.
M1.
    OPEN INPUT F1
    DISPLAY "NOT REACHED"
    STOP RUN.
M2.
    DISPLAY "RESUMED " FS
    STOP RUN.
```

## Environment

`cobc (GnuCOBOL) 3.2.0`, WSL2 Ubuntu x86_64. Compiled with `cobc -fsyntax-only -free -std=cobol2014 rs1.cob` (and
`cobc -x -free -std=cobol2014 -o p rs1.cob`, same diagnostics); no executable is produced. The file rs1-missing.dat does
not exist.

## Observed result

Compile, exit code 1:

```text
rs1.cob: in section 'D1':
rs1.cob: in paragraph 'D1-P':
rs1.cob:20: error: 'RESUME' is a reserved word, but isn't supported
rs1.cob:20: error: syntax error, unexpected AT, expecting SECTION or .
rs1.cob:20: note: 'RESUME' is not a statement
```

## Expected result (per ISO)

The program is legal and prints `DECL 35` then `RESUMED 35`.

- §14.9.33.1 (checked): "The RESUME statement transfers control to a procedure-name or to the statement following the
  statement that caused a declarative ... to be executed."
- §14.9.33.3 1) (checked): "The RESUME statement may be specified only in a declarative or in an imperative statement in
  a WHEN phrase of an exception-checking PERFORM statement." It is in a declarative.
- §14.9.33.3 2) (checked): "The RESUME statement shall not be specified in a declarative procedure for which the GLOBAL
  phrase is specified in the associated USE statement." The USE statement of D1 has no GLOBAL phrase.
- §14.9.33.3 3) (checked): "Procedure-name-1 shall be a procedure-name in the nondeclarative portion of the function,
  method, or program." M2 is.
- §9.1.13.6 5) (checked): "I-O status = 35. A permanent error exists because an OPEN statement with the INPUT, I-O, or
  EXTEND phrase is attempted on a file that is not described as optional and the physical file is not present."
- §14.9.27.4 25) d) (checked): "Any applicable USE FOR EXCEPTION or USE AFTER EXCEPTION procedure is executed as
  specified for the rules for the USE statement." D1 runs and prints `DECL 35`.
- §14.9.33.4 3) (checked): "If procedure-name-1 is specified, control is transferred to procedure-name-1 as if a GO TO
  procedure-name-1 were executed." M2 prints `RESUMED 35`.

Edition: 2014. RESUME arrived with common exception processing in ISO/IEC 1989:2002 (the 2009 committee draft that led to 2014
has `RESUME AT { NEXT STATEMENT / procedure-name-1 }` with the same syntax rules for a RESUME in a declarative); Annex E of the 2023 standard lists
no change to it.

## Our compiler

WiseOwl COBOL (fresh judge, `--std 2014 --source-format free`): compiles with no diagnostic; the run prints `DECL 35`
and `RESUMED 35`, exit code 0.

## Fix site

`cobc/reserved.c` (read in the GnuCOBOL 3.2 release source (gnucobol-3.2.tar.xz)): the reserved-word table entry for RESUME carries token -1 (no grammar
token), so `lookup_reserved_word` reports "'%s' is a reserved word, but isn't supported"; `cobc/parser.y` has no RESUME
statement production.

## Upstream state

Unreported; tracker not yet searched. NEWS and TODO do not mention RESUME.

## Vetting (2026-11-04)

Verdict OPTIONAL_UNCLAIMED and DUPLICATE, ended; the refuter agrees. RESUME is an optional element in Annex A.4 (A.4.12 1) in 2023, and A.4.5 of the 2009 CD for 2014), and cobc does not claim it: it says "'RESUME' is a reserved word, but isn't supported", --list-reserved shows No and cbrese.tex line 747 says Implemented: No, on 3.2.0 and 3.3-dev alike. That meets A.4.1 and 4.2.7 (cite.py --check OK), so the -std=cobol2014 report is not a defect. The same mechanism is feature-requests #171 "Implement RESUME" (accepted, 2016); a cobol2002 reject is a real gap (only Communications is optional there) but #171 covers it. Retired with `upstream_status: duplicate` and that ticket.
