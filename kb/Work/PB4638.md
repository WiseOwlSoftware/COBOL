## Landing (wave 20261868 D)

The reviewer's reading held. Line 2095 expanded `ExpandSameAs` for each MEMBER's `SameAsName`, but `DescendantsOf(template)` never visits the
template itself, so the declaration's OWN `SameAsName` (a refused co-clause the PB4602 recovery keeps, with the TYPEDEF role) was the one reference
nothing expanded. Re-probed on the wave's build: `01 Z. 05 ZA PIC X. 05 ZB PIC 9.` / `01 T TYPEDEF SAME AS Z.` / `01 X TYPE T.` /
`MOVE "A" TO ZA OF X.` drew COBOL1555, then COBOL1639 on each `ZA OF X` (the STRONG form identically). A SAME AS on a MEMBER of the declaration,
an elementary target, and a `BASED SAME AS` storage item were already right.

Fix at the root: `ExpandTemplate` walks `SelfAndDescendantsOf(template)` and expands each item's TYPE, then SAME AS, the order
`ExpandTypesPass.Run` gives every storage item (ISO 13.18.49.4 GR1, cite.py --check OK). The one walk replaces the special-cased TYPE-on-self line,
so the next reference kind a declaration may carry is automatic. After: COBOL1555 alone. Witnesses: `SameAsGroupWithTypedef_SubordinatesOfTheTypeResolve`
(plain, STRONG, and a target that is itself a SAME AS subject; exactly one diagnostic) and the golden
`conformance:cases/13.16-Data-description/pb4638-typedef-same-as-group-one-refusal` (refused at 2002, 2014, 2023).
