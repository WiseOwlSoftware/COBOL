# PB2819 — two quiet arms of `mailbox.py status`

Found by the train 1045 lander's review of PB2814's fix (2026-10-08 18:20 PDT). The fix itself landed; these two arms
of it give a misleading answer where they should say they cannot tell.

## 1. A missing operator-session.json makes every session the Mythos lane

`scripts/orchestrator/mailbox.py#lane`: `op = session(cdir, None, None, None).get("config_dir")`, then
`"operator" if op and account.same_dir(...) else "mythos"`. With `operator-session.json` absent (a fresh coordination
directory) or unreadable (`session` returns `{}`), `op` is None and the operator session is told
`mailbox (mythos): 0 open in to-mythos` and asked to arm `watch --inbox mythos`. Expected: a line that says the lane is
unknown and names `mailbox.py session` as the command that records it.

## 2. An unreadable process table is reported as "not in a Claude Code session"

`scripts/orchestrator/mailbox.py#status`: when `coord.process_table()` returns `[]` (its documented answer when the
CIM query fails or times out), `session_root` finds nothing and `status` returns
`watcher state unknown (not running under a Claude Code session)` with `armed = True`, so the stop line never prints.
Expected: "process table unreadable" as its own wording, and the caller (session-probe) treating it as unarmed or as a
warning, not as all-clear.

## Fix shape

`lane` returns a distinct unknown value when no operator config dir is recorded, and `status` prints it; `status`
tells an empty table apart from a table with no Claude ancestor. Self-test arms for both, beside PB2814's.
