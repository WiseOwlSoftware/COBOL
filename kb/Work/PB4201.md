# PB4201 — an illegal literal at an open identifier position draws only a bare COBOL0001

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/AdmittedKinds.cs` (`AdmittedKinds.Refusal`: the `named.Open` path, lines 73-75),
`src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs` (`CobolErrorStrategy.GuessCobolIntent`, hint 0i).

**The defect.** `USAGE 5` (and any similar position where the grammar expects an IDENTIFIER and nothing else) draws a bare
`COBOL0001 unexpected '5'` at every edition. Hint 0i, which names what a literal there should have been, says nothing:
the position is open (`Named.Open`) and no literal is expected, so `Refusal` takes the early return and nothing is written
for the reader. The reader is told what is wrong but not what was wanted.

**Not the same as PB4174** (that note is the edition filter on the names the sentence prints; this is the sentence being
absent for an open position). **Not PB765** either: PB765 is a grammar predicate moving ANTLR's recovery point, which gives
one source a different token and code per edition; this reproduces identically at every edition. PB3751 (landed) was grepped
for the same path and does not cover it.

Repro: `USAGE 5` in a data description entry (the report's scratch probe `u.cob`; not kept). Re-probe once at `--std 2023`
before fixing, then sweep the other open-identifier positions for the same silence.

**Landed (the root was not the note's premise).** The position expects no IDENTIFIER and no literal: after `USAGE` the
parse expects only the usage keywords. `AdmittedKinds.Name` called it open because `admitted.And(statementStart).Count > 0`
held for ONE token, DISPLAY, which is a statement's opening word and a USAGE keyword. `AdmittedKinds.BeginsAStatement` now
asks for the whole of FIRST(`statementBlock`) (each start admitted, or a word a refusing text predicate tested: COMMIT,
SEND, the gated verbs, `ResimulationWalk.AdmittedAt`'s `Words`), the containment `OffendingPosition.EmptyBlockOwner`
already used. `USAGE 5` now draws COBOL5506 naming the usage keywords of the compile edition; a literal at a true
statement start stays the bare COBOL0001 (the imperative-statement arms own it). Witnesses:
`unit:WrittenKindRefusalTests` (`usage-literal-85|2023`, control `literal-at-a-statement-start`) and
`conformance:wiseowl/diagnostics/pb4201-usage-literal-names-the-usages-85|2023`. Re-probe (wave 20261785): at 85, 2002,
2014 and 2023 the source drew `error COBOL0001: unexpected '5'` before the fix.
**Sites (as landed):** `src/WiseOwl.Cobol.Frontend/Parsing/AdmittedKinds.cs` (`AdmittedKinds.Name`, `AdmittedKinds.BeginsAStatement`).
