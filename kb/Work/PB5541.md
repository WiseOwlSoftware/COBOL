# PB5541 - a duplicate FD of one file-name (FD FA. twice, one SELECT) compiles clean at --std 2023: the FD does not declare through DeclareUserWord, so COBOL4250 never fires

**Site:** `src/WiseOwl.Cobol.Compiler/Binding/FileControlBinder.FileSection.cs` (`FileControlBinder.BindFileSection`).

**Mechanism.** The FD entry does not declare its file-name through `DeclareUserWord`, so the second FD of the same name draws no COBOL4250 (user-defined word not unique). Same root idea as kb/Work PB5307 (a second unqualifiable declaration is accepted), a different arm. The SELECT-twice arm is already refused (COBOL2634).

**Repro.** `E:/COBOL-coord/scratch/review-w20262034-b/dupfd.cob`: two `FD FA.` entries, one SELECT; compiles clean at --std 2023.

**Expected.** The second FD of a file-name is refused as a non-unique user-defined word (COBOL4250). Sweep the other declaring arms for the same gap.

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/FileControlBinder.FileSection.cs` (`FileControlBinder.BindFileSection`, `FileControlBinder.DescriptionRepeated`)
- `src/WiseOwl.Cobol.Editions/Diagnostics/DiagnosticCatalog.cs` (`SpecialNameDeclaredTwice`, COBOL4250 text)

**Landed.** The file-name is declared by the SELECT (one declaration), so the FD is no second `DeclareUserWord`; `DescriptionRepeated` refuses a second FD or SD of a file-name under COBOL4250 (ISO §2023:8.4.2.1), at both arms of `BindFileSection`; the first description stands. Witness: `conformance-suite/wiseowl/diagnostics/pb5541-fd-declared-twice.json`.
