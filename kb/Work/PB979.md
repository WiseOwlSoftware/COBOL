Filed 2026-09-22 by **REGISTRAR #11** from wave 46 group M's lead C (PB871 implementer report, lander lead M-C:
"not measured") and wave 45 group B's PB887 finisher lead 1 (UNSTRING's receiver arms are a private copy of the
MOVE rules). **Measured here for the first time, on this registrar's own build of main `6871b6e10`** (0/0).

## Reproduced

- `reg11/mc2.cob` (contained program, `01 L PIC X ANY LENGTH.` `PROCEDURE DIVISION USING L.`, called with a
  `PIC X(6) VALUE "ABCDEF"` argument; `01 S2 PIC X(4) VALUE "WXYZ".` `UNSTRING S2 INTO L`) →
  **`L=[W     ]`** and back in the caller **`S=[W     ]`**. Silent wrong answer; expected `L=[WXYZ  ]`.
- `reg11/mc.cob`: `01 S PIC X(6) VALUE "ABCDEF".` `01 R PIC X(8) VALUE ALL "*".` `UNSTRING S INTO R(2:3)` →
  **`warning COBOLNET1756: UNSTRING without DELIMITED BY into a reference-modified receiver (no static reception
  size, ISO §14.9.48.4 GR11b) — not implemented; reaching this statement aborts the run unit`**. Expected
  `R=[*ABC****]`.

## Rule

- `python scripts/spec/cite.py --check 14.9.48.4 "If the DELIMITED BY phrase is not specified, the number of characters examined is equal to the size of the current receiving area"` → OK §14.9.48.4 11) (b))
- GR11 c) then moves the examined characters to the receiver "according to the rules for the MOVE statement"
  (`… --find "according to the rules for the MOVE statement"` lists §14.9.48.4 11) twice — c) and d)).

The size is a property of the receiving area at the moment the statement executes: an ANY LENGTH formal's length is
its argument's (§13.18.2), a reference-modified receiver's is its evaluated length, and a dynamic-length receiver's is
the one PB871 settled (`ReceivingStore.DynamicReceivingSize`).

## Cause (read in the code)

The binder computes GR11b's examination count as a compile-time integer on the bound UNSTRING
(`BoundStringUnstring.cs:38`: "−1 marks a reference-modified receiver whose size is not static"), from the receiver's
PICTURE length — 1 for `PIC X ANY LENGTH`; the −1 case is staged loud. The store half already knows the run-time
size (`StringEmitter.MoveString`'s ANY LENGTH arm writes at `{Read(target)}.Length`), so the examination and the store
disagree about the same receiver.

## What the fixer owes

1. The examination count becomes a run-time expression from the SAME receiver-size authority the store uses (one
   answer per receiver, not a binder integer plus an emitter expression), with SEPARATE-sign's "one less" rule on it.
2. The structural half (PB887's finisher lead): `StringEmitter.MoveString` re-renders the MOVE rules per receiver
   category by hand where GR11 c)/d) say "according to the rules for the MOVE statement". Bind a MOVE of the examined
   characters (as the conceptual elementary alphanumeric / national sender GR11 c) defines) instead, as PB887 did
   for ACCEPT — then ANY LENGTH, reference-modified, dynamic-length and national receivers are automatic. The INVOKE
   BY CONTENT boolean argument store (`OoEmitter.cs` ≈830–845, §14.8.2.3.3 2) d)'s MOVE store written with
   `StrStoreBoolean`/`StrStoreAligned`) is the same shape and goes in the same change set.
3. Sweep: DELIMITER IN (GR11 d)) into the same receiver kinds; COUNT IN; POINTER with a reference-modified receiver;
   STRING INTO a reference-modified / ANY LENGTH receiver (the sibling verb).
