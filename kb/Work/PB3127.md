# PB3127 — the CALL lane's run-time ANY LENGTH arms compare category and usage only

Source: wave 1071 (unit `w1071a`, PB2077 round 3), carried from `w1070d`'s PB2077 report (lead 1). The PB2077 note is held
by its branch and is NOT edited here; this is a NEW note that names it.

The successor is `worktree-wf_15ec6338-3a0-2` (wave 1078 group B, report `w1078b-PB3101-report.md`); it replays all four of its commits patch-identically (`git range-diff a6744fa4d..9e5054890 c29af1704..37d15c9d5`: every pair `=`) and builds on them, so nothing unique remains; PB3127 and PB3101 land through the successor. `prune_worktrees.py --apply --abandon worktree-wf_84f0c364-28e-2` deletes it after this record lands.

**The rule.** Checked: `python scripts/spec/cite.py --check 14.8.2.3.2 "its length is considered to match the length of the corresponding argument"` -> OK, §14.8.2.3.2 2) d). Rule 2) e) (also checked OK): "If the argument is described with the ANY LENGTH clause, the corresponding formal parameter shall be described with the ANY LENGTH clause." Under 2) the formal's other clauses still have to be the argument's: only its LENGTH is exempt.

**The code.** `src/Cobol.Net.Runtime/Control/ActivationRelations.cs:229-234` (the `if (formal.AnyLength)` arm of the rule-2 comparator, around `:222` for "Additionally" e)) answers an ANY LENGTH formal with
`Category` equality and `Usage` equality and returns null otherwise, so every other clause of the pair (SIGN, JUSTIFIED, BLANK WHEN ZERO, SYNCHRONIZED, ...) goes unchecked. The code's own comment calls it "completeness, not a common path" (§13.18.2.3 SR2 confines ANY LENGTH to a function, a contained program or a method). The sibling at `:56` and `:93` reads `formal.AnyLength` too. By contrast the typed lane diffs the argument's `AnyLengthClauses` (`ActivationRelations.FirstClauseDifference`, PB2077 round 1, branch `worktree-wf_787860dd-104-4`/`-18`), so the two lanes of one relation give different verdicts for the same pair.

**Repro.** None was recorded by the predecessor (R2: no repro given to run). The nearest is `E:\COBOL-coord\scratch\w1070d\r1\j1.cob` (`J PIC X(4) JUSTIFIED RIGHT` into `PIC X ANY LENGTH`, which the typed INVOKE lane now refuses naming "'JUSTIFIED' where the formal parameter has '-'"). The implementer writes the CALL-lane twin: an ANY LENGTH formal in a contained program and a clause-differing argument, then runs it on both lanes (the drift test `TypedAndUniversalInvokeVerdictsAgreeDriftTests` is the home for the pair).

**Fix shape.** One comparator for both lanes: the ANY LENGTH arm compares the argument's `AnyLengthClauses` opposite the formal's (what `SameClausesAtFormalLength` compares) rather than re-spelling category + usage. Sweep: every `AnyLength` reader in `ActivationRelations.cs` (`:56`, `:93`, `:222`, `:229`, `:273`, `:311`, `:316`, `:434`).

Judgment left open: whether a contained-program CALL can reach this arm at all (the comment says not); if it cannot, the lane is dead code and the fix is to delete the arm, which is a design decision for the implementer.

## Landed (wave 1077 group B, 2026-10-14)

Re-probed on `a6744fa4d`: the run-time arm was unreachable on its own (a CALL that reaches rule 2 at run time needs a
program-specifier, and §13.18.2.3 SR2 confines ANY LENGTH to a function, a contained program or a method), and the
bind-time lane refused `J PIC X(4) JUSTIFIED RIGHT` into `PIC X ANY LENGTH` through `OoConformance.DescriptionMismatch`
(probe `E:/COBOL-coord/scratch/w1077b/p2_anylen.cob`). The judgment the note left open is settled by PB3101 in the same
change: `ParameterConformance.CheckArgument` now asks `ActivationRelations.CallArgumentViolation` for a Format-2 CALL
(prototype or NESTED) and a function, so the arm IS the bind-time verdict and is live, not dead. Fixed at the root:
the ANY LENGTH arm of `ByReferenceViolation` compares `SameClausesAtFormalLength` (the argument's `AnyLengthClauses`
opposite the formal's `Clauses`, every rule-2 clause but the length), as match rule 3 e) does; `CallReturningViolation`'s
§14.8.3.3 "Additionally" 5) arm is the sibling, fixed the same way (and both "Additionally" arms now apply to an
elementary pair only: opposite an alphanumeric group §14.8.3.2 governs, where an ANY LENGTH sender is its receiver's
length by §13.18.2.4 GR1 b)). `ClauseDifference` names the clause that differs (JUSTIFIED) and, for an argument with no
ANY LENGTH form (a slice), the PICTURE clause itself. Sweep: every `AnyLength` reader in `ActivationRelations.cs`
(`ClauseDifference`, `SameClausesAtFormalLength`, `ByReferenceViolation` e) / d), `ByContentViolation` 2 a) / c) —
length only, unchanged —, `CallReturningViolation` 4) / 5), `ReturningViolation`'s GR7 c) ban — unchanged).
