# PB5775 - a report group name that is also a Working-Storage name is resolved without the ambiguity being reported (GENERATE, USE BEFORE REPORTING; every edition)

**What is wrong.** A report-group data-name and a same-spelled non-report data-name are resolved in separate namespaces, so an unqualified GENERATE or USE BEFORE REPORTING reference to the shared name compiles instead of being refused as nonunique (and so does an ordinary MOVE). With a Working-Storage `01 DA` and a report group `01 DA TYPE DE`, `DA` is a nonunique user-defined name; an unqualified explicit reference must be refused (`§1985:IV.4.3.8.1 SRL2.1`); GENERATE SR1 supplies the report-name qualifier (write `DA OF R-1`). `GENERATE DA` and `USE BEFORE REPORTING DA` compile and run at 85 and at 2023 because `ReportGroupResolution#Resolve` collects only report groups. The control `m4ctl` (two Working-Storage items named DA) is refused COBOL1639, so the ambiguity verdict exists but never sees the report namespace. Sibling, same root in the other direction: `MOVE "Z" TO DA` compiles and binds to the Working-Storage item (`m4mov`). The checker rates the GENERATE and USE findings high and the MOVE sibling medium. The Mythos lane did not run these programs itself.

**Sites:**
- `src/WiseOwl.Cobol.Compiler/Binding/ReportGroupResolution.cs#Resolve` (candidates from report groups only; shared by GENERATE, USE BEFORE REPORTING and SUM UPON, per the refuter)
