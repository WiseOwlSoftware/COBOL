**Rule it breaks:** ISO §14.9.39.2 Format 14 prints one data-name-2 with no ellipsis, and §14.9.39.3 SR29 requires data-name-2 to reference a CAPACITY register. SetFormatSelection (its own doc, kb/Work PB449) requires that receiver order never change the verdict, and BoundUnsupported is only for an unbuilt feature, never for illegal source (BoundTree.cs:886-895, kb/Work PB909).

**Scenario:** SetFormatSelection.Select chooses Format 14 as the nearest row for any receiving list that contains a CAPACITY register (F14 is the first row and its Dir is Any). BindSetCapacity then looks only at targets[0] (SetBinder.cs:1407): when that receiver is not a register, it returns new BoundUnsupported("SET capacity-register — the register could not be addressed") before the cardinality check at 1418 runs. No error is drawn, so StatementBinder reports COBOL1756 as a warning and the emitter plants a NotImplemented.Run abort. Measured on the pin build with WS-CAP (OCCURS DYNAMIC CAPACITY IN WS-CAP FROM 2 TO 10), WS-N PIC 9(4) and index-name IX, --std 2014 --run: `SET WS-N WS-CAP TO 5` and `SET IX WS-CAP UP BY 1` compile with two COBOL1756 warnings, and the run dies with NotImplementedCobolFeatureException after displaying START. `SET WS-CAP WS-N TO 5` and `SET WS-CAP IX UP BY 1` draw error COBOL1524. Illegal source reaches production and crashes. BindSetSize, the Format 16 twin, checks the count first (1473) and has no such hole.

**Measured how:** R2 batch finding `procedure-binding-5--code--f1#2` (pair procedure-binding-5--code), read in the pinned tree at 8be23006851a; skeptics rule upheld, scenario upheld, site upheld.

**Spec:** §14.9.39.3 "Data-name-2 shall reference a data item defined in the CAPACITY phrase of a dynamic-capacity-table format OCCURS clause." (`cite.py --check` passed at collection)

**Target:** BindSetCapacity checks the receiver count first, as BindSetSize does, through SetFormatSelection.ReportNotAdmittedCardinality or COBOL1524. A receiver that is not a register then reports through ReportNotAdmitted (COBOL2112 with SR29) and returns BoundRejected. The BoundUnsupported arm at 1407-1408 stays only for a register that genuinely cannot be addressed, if that case can occur at all. Add negative goldens for both receiver orders and both directions (TO and UP BY), and a sibling sweep of every SetFormatSelection-selected binder for other reads of targets[0] that come before the cardinality check.

**Design reference:** §8.3.

## Landed

Re-probed before the fix: `SET WS-N WS-CAP TO 5`, `SET IX WS-CAP UP BY 1` and `... DOWN BY 1` compiled with COBOL1756 (not implemented) and aborted the run unit; the register-first orders drew the bare, uncatalogued COBOL1524. Fixed in `SetBinder.BindSetCapacity`: the whole receiving list is screened before any receiver is read, through the new `SetFormatSelection.ReportNotSoleReceiver` (an operand the Format 14 brace does not admit is named first, SR29; otherwise the count, since data-name-2 has no ellipsis), both reporting COBOL2112 in either order. The uncatalogued COBOL1524 literal is deleted; the unreachable "register could not be addressed" `BoundUnsupported` arm is now an invariant `InvalidOperationException`. Sibling: `BindSetSize` (Format 16) takes the same helper, and its sole-receiver bind is split out so the explicit `SIZE OF` arm no longer fakes a one-element list. `ReportNotAdmitted` now returns whether it reported. Witnesses: `conformance:cases/14.9.39-SET/pb3225-set-capacity-register-{second-integer,second-index-up-by,first-integer,first-index-down-by}` and `pb3225-set-capacity-two-registers`. The other SetFormatSelection-selected binders read no `targets[0]` before their own checks (swept).
