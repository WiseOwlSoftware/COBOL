# PB2985 — rule 2's ACTIVE-CLASS sender is not described from the invocation at run time

**Sites:** `src/WiseOwl.Cobol.Runtime/Control/CobolObject.cs` (`CobolObject.NarrowUniversal`, `CobolObject.CheckActiveClassReturning`, `CobolObject.CheckActiveClassFormal`), `src/WiseOwl.Cobol.Runtime/Control/ActivationRelations.cs` (`ActivationRelations.ReturningConformance`, `ActivationRelations.ActiveClassReturningViolation`, `ActivationRelations.ActiveClassFormalViolation`), `src/WiseOwl.Cobol.Runtime/Control/BASE.cs` (`BASE.__CobolInvoke`, `__FACTORY_BASE.__CobolInvoke`, `StandardMethodCrossing`), `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/OoEmitter.cs` (`OoEmitter.EmitCobolInvokeCase`, `OoEmitter.OoUnivCallerWrite`), `src/WiseOwl.Cobol.Compiler/CodeGen/Roslyn/RuntimeApi.cs` (`RuntimeApi.ObjNarrowUniversal`, `RuntimeApi.ObjCheckActiveClassReturning`, `RuntimeApi.ObjCheckActiveClassFormal`)

## Landed (wave 20261505 group A)

**Re-probe (own build).** `pa.cob` T4 (`SET U TO OS`, `INVOKE U "RA" RETURNING OP`, OP described P, RA's returning item
ACTIVE-CLASS) printed no exception and delivered the object; `pd.cob` ran clean. Rule (`cite.py --check`: OK 14.8.3.3 2)
b) 4.): "If the activated method is invoked with any other object reference, the sending operand has the same description
as that object reference" — a universal INVOKE is invoked with a universal reference, so the sender is universal;
§14.9.39.3 SR10 / SR12 / SR14 (OK 14.9.39.3 12)) close their lists of senders without a universal one and SR8 (OK
14.9.39.3 8)) lets only a universal receiving item take it; §14.9.23.4 GR7 c) (OK 14.9.23.4 7)) sets EC-OO-UNIVERSAL "if
checking for it is enabled in both the activated method and the activating runtime element" and makes the invocation
unsuccessful. The compile-time lane agreed already (COBOL0828 for an INVOKE through an interface-typed reference into
a class-typed receiver, `OoConformance.ReturningSender`); the run-time lane admitted every ACTIVE-CLASS item
(`ReturningConformance`'s `if (sending.ObjectKind is ActiveClass) return null`).

**Fix (the ONE table, the universal arm).** `ActivationRelations.ActiveClassReturningViolation` asks
`ObjectReferenceSet.Refusal` with a universal sender; `CobolObject.CheckActiveClassReturning(enabledInMethod, what,
receiving, sending)` raises EC-OO-UNIVERSAL before the method runs when checking is enabled in both halves, and returns
silently otherwise (the delivery's `NarrowUniversal` class narrowing stays the floor, so an unchecked program that worked
still works). Asked by every emitted `__CobolInvoke` case whose returning item is ACTIVE-CLASS (`EmitCobolInvokeCase`,
`RuntimeApi.ObjCheckActiveClassReturning`) and by BASE's New and FactoryObject (the standard class has no source, so its
half is on). It is a relation of its own, not a term of `ReturningViolation`, because that one's stop is unconditional
(`OoUnivStop`: an implementor-fatal when unchecked), which would turn a working unchecked program into a crash.

**Sibling sweep.** Arms of the dispatch: universal emitted case (fixed), BASE New / FactoryObject (fixed), typed INVOKE
(`ReturningSender`, already right, golden t03 pins it), CALL RETURNING (`CallReturningViolation` -> `ReturningConformance`:
ACTIVE-CLASS is legal only in a factory / instance / method definition, §13.18.60.3 SR16 — a program's returning item
cannot be one, so that arm is unreachable and unchanged). `pb2463_universal_returning_set_match` c14 (a universal INVOKE
of an ACTIVE-CLASS item into a typed receiver whose class is the containing class) changes from "match" to
EC-OO-UNIVERSAL: its own note recorded that rule 2 b) 4. would refuse it; its golden and comment are updated.

**Goldens.** `conformance-suite/cases/14.8.3.3-Elementary-items/pb2985_active_class_returning_universal_invocation`
(ten cases: universal and typed receivers, factory and instance methods, BASE New / FactoryObject, the method's half off,
the activator's half off); negative `pb2985-active-class-returning-universal-invocation-below-2002` (COBOL0900);
`tests/WiseOwl.Cobol.Tests.Unit/ActiveClassReturningUniversalSenderTests.cs`.

## Landing

- `src/WiseOwl.Cobol.Runtime/Control/ActivationRelations.cs#ActiveClassReturningViolation` — THE run-time rule 2 b) 4. for a universal INVOKE: the one SET table (`ObjectReferenceSet.Refusal`) with a universal sender; reuse it, do not add an ACTIVE-CLASS arm to `ReturningConformance` (CALL shares that, and ACTIVE-CLASS cannot occur there).
- `src/WiseOwl.Cobol.Runtime/Control/CobolObject.cs#CheckActiveClassReturning` — the raise, asked by every method that returns an ACTIVE-CLASS item to a universal caller; unchecked it returns silently and `NarrowUniversal` stays the floor. Trap: do NOT fold it into `ReturningViolation`/`OoUnivStop` — that stop is an implementor-fatal when unchecked and would crash a program that worked.
- `src/WiseOwl.Cobol.Runtime/Control/BASE.cs#BASE.__CobolInvoke` / `__FACTORY_BASE.__CobolInvoke` — the standard methods ask it after `StandardMethodCrossing.Matches` (their method half counts as enabled); a third standard method that stores `returning!.Value` must too (`ActiveClassReturningUniversalSenderTests` guards it).
- `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/OoEmitter.cs#EmitCobolInvokeCase` — emits `RuntimeApi.ObjCheckActiveClassReturning` for a returning item whose description is ACTIVE-CLASS (after the `__viol` stop, before the ANY LENGTH stop).

## Review round 1 (wave 20261505 review finisher)

- **R1-2 (the formal arm), fixed.** An ACTIVE-CLASS FORMAL reached through a universal INVOKE is the same invocation read at §14.8.2.3.2 rule 4 (`cite.py --check`: OK 14.8.2.3.2 4)): a) and b) name SELF, SUPER, an ACTIVE-CLASS reference, an object-class-name or an ONLY reference, and a universal invoking reference is none of them, so a supplied argument cannot conform (§14.8.2.3.3's BY CONTENT paragraph names the same two invocations and is not reached: every universal argument is BY REFERENCE, §14.9.23.3 SR6). `ActivationRelations.ActiveClassFormalViolation` / `CobolObject.CheckActiveClassFormal` / `RuntimeApi.ObjCheckActiveClassFormal`, asked by `OoEmitter.EmitCobolInvokeCase` per ACTIVE-CLASS formal after the §9.3.6 match (a mismatching argument is still EC-OO-METHOD) and before the method runs; unchecked it proceeds, the match having already required the argument to be an object of the class the method runs on. The compile-time lane agreed already (`OoConformance.ActiveClassFormalMismatch` with a universal `invokedWith`). Golden `14.8.2.3.2-Elementary-items-passed-by-reference/pb2985_active_class_formal_universal_invocation` (eight cases), `ActiveClassFormalUniversalInvocationTests`; `pb1112_active_class_universal` keeps witnessing the match alone with `>>TURN EC-OO-UNIVERSAL CHECKING OFF`.
- **R1-1 (BASE), no_change_needed.** GR7 c) governs "a COBOL method", and §16.2's NOTE permits BASE to be implemented outside COBOL, but §16.2 also requires the class to be "described with an IMPLEMENTS clause that references the interface defined here" (cite.py OK 16.2), COBOL text whose New and FactoryObject carry an ACTIVE-CLASS returning item. docs/CONFORMANCE.md DOC-A.1-101 already declares that WiseOwl COBOL has no non-COBOL method an INVOKE can reach (GR7 e)'s implementor-defined execution never occurs), so BASE's two methods are COBOL methods of that interface, and exempting them would make a universal INVOKE of `New` observably differ from one of a user method with the same interface. The reviewer's second point was right and is fixed: the choice (BASE a COBOL method; "enabled in the activated method" read as always enabled, the standard class having no source for a directive) is now written in DOC-A.1-101 and the design doc.
