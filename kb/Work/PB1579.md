# PB1579 — LANDED

Found 2026-09-25 by the w59k implementer (latent, not probed at these sites). Route each through
`IntegerOperandRules.HostValue` (train 60, w59b) or the COBOLNET2427 limit screen, as its rule requires, and extend
w59b's semgrep rule `cobolnet-integer-n-parsed-outside-host-value` so TryParse is caught too — find out why it missed
these (rule 5: make the next one automatic). Probe each site with an 11-digit literal before and after.

## Landing (wave 70, group U finisher)

Re-probed on the w70u build. The note's seven file:line sites were from the w59k tree: train 60 (PB1058,
`IntegerOperandRules.HostValue`) had already moved five of them before the note was filed. What remained, and what
the sweep found (`grep -E '(int|long)\.(Try)?Parse\(' src/Cobol.Net.Compiler`), were COBOL-literal TEXT parses that
never touched an `integerLiteral` node:

- **One text reader**: `IntegerOperandRules.TryHostValue(text, out value, out saturated)` (`Validation/IntegerOperandPass.cs`)
  answers "is this an integer literal" and "its host value, saturated" separately; `BeyondHostLimit` rides it, and
  `BeyondLimitMessage` is the one COBOLNET2427 sentence (pass, constant-name, CONTROL ref-mod).
- **OCCURS integer constant-name** (`DataBinder.Constants.cs` `OccursBoundValue`): `01 K CONSTANT AS 77777777777` /
  `OCCURS K` was refused as "not an INTEGER constant-name"; now COBOLNET2427 as the substituted literal is (§13.10.4 GR1).
- **CONTROL / TYPE CF / SUM RESET ON ref-mod literal** (`ReferenceResolver.ReadOperandSuffixes`): `CX(1:77777777777)` was
  refused under §13.18.16.3 SR4 as "not an integer literal"; `RefModSuffixes.BeyondHostLimit` now carries the fact and
  `DataBinder.Reports.cs` raises COBOLNET2427 (the wave-68 half-fix handed the saturated length on and the program
  died "Out of memory." at its first GENERATE — measured on this branch before the screen).
- **Format 2 VALUE subscripts** (`DataBinder.BuildTableValueSpecs`): the SR20/SR21 diagnostics quoted the SATURATED number
  (2147483647 for `-99999999999999999999` on main; -2147483648 after the wave-68 reader); `TableValueSpec.FromWritten` /
  `ToWritten` now carry the written text and every Format 2 VALUE diagnostic quotes it.
- **CURRENCY SIGN** (`DataBinder.Switches.cs` `CurrencyTextLiteral`): numeric-or-not was `int.TryParse || decimal.TryParse`;
  a 31-digit literal read as non-numeric and was refused under SR22; now `lit.numericLiteral()` (§8.3.3.3.1) → SR18.
- **BASECONVERT argument-2/-3** (`IntrinsicBinder.StaticIntLiteral`): a 20-digit base skipped the static range screen;
  it now reports, quoting the literal. **STANDARD-COMPARE argument-4**: a 20-digit POSITIVE level was refused as "not a
  positive nonzero integer". **BOOLEAN-OF-INTEGER width** (`ConditionBinder.StaticBoolCallWidth`): 11 digits failed open.
- **Semgrep** `cobolnet-integer-n-parsed-outside-host-value` widened from the `integerLiteral().GetText()` accessor to any
  parse of `.GetText()` / `.Text` in Binding/ and Validation/ (level-numbers exempt). Why it missed these: it matched one
  spelling and the comment left `lit.GetText()` "to review". Run over main's files it flags 5 of the 8 sites; a value
  first copied into a local (`text`, `t`, `it`) stays invisible to a regex.
- Swept and left: `Place.StaticLength`, `InitializeBinder` occurrence keys, `OoBinder` window, `ParameterConformance`
  parse RENDERED C# text (not COBOL literals); level-number parses; float-exponent parses (two digits by the lexer).

Negatives (each at 2002/2014/2023, the CONTROL one also 85): `pb1579-control-refmod-beyond-limit`,
`pb1579-constant-occurs-bound-beyond-limit`, `pb1579-currency-sign-long-numeric`, `pb1579-table-value-subscript-as-written`.
