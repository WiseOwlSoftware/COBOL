## Landed

Determination (wave 20261711, group D): **no compiler defect**. The signature's description was a guess from the
clause the seed named: no row is a MOVE of a figurative constant into a boolean item, and the few that move a
figurative constant (HIGH-VALUE into a national item or a numeric item, LOW-VALUE, ZERO into a group) differ in a
documented, spec-undefined or GnuCOBOL-lacking way, never in a rule of §14.9.25.

**The sources were kept after all.** Four later runs under `conformance-suite/results/fuzz-*/` (git-ignored) carry the
signature on 17 rows with their programs (`fuzz-20261021-211424` fz01110 fz01111 fz01932 fz01933 fz04400;
`fuzz-20261022-163846` fz01282 fz01980 fz01981; `fuzz-20261023-204437` fz00704 fz02112 fz02113 fz02818 fz04932
fz04934; `fuzz-20261025-220901` fz04079 fz05487 fz06194). All 17 were re-run on this branch's build (WiseOwl COBOL
`--std 2014`, GnuCOBOL 3.2 `-std=cobol2014` under WSL, free form, the suite's adapters). Each differing line falls in one
class:

1. **HIGH-VALUE's character** (fz01110, fz01981, fz02113, fz04079, fz04400, fz05487, fz06194). WiseOwl's HIGH-VALUE
   is U+FFFF (owner decision kb/Work R52, `docs/CONFORMANCE.md` DOC-A.1-183 and DOC-A.1-31); GnuCOBOL's byte 0xFF
   reads back as U+FFFD. §8.3.3.6.4 GR6 makes the character the highest of the collating sequence, so which character
   it is, is the implementor's. fz02113 also moves HIGH-VALUE and LOW-VALUE to a NUMERIC-EDITED item: permitted through
   ISO 2014 (Annex E.2 item 1), pinned by `MoveEditionDifferentialTests.HighLowValue_PreRemoval_ImageFill_At85`;
   GnuCOBOL's `   0` is its own reading.
2. **Storage read before it is written** (fz01110, fz01111, fz01282, fz01933, fz01980, fz02818, fz04400, fz00704): a
   `MOVE CORRESPONDING` or group move whose names do not correspond, then a DISPLAY of items with no VALUE clause.
   WiseOwl shows zeros and spaces, GnuCOBOL NULs. The standard leaves the initial value of such an item undefined
   (`cite.py --check A.2 "the initial value of the data item is undefined unless the INITIALIZED clause is specified
   in the OPTIONS paragraph"` -> OK §A.2 19)). The model's program is not a conforming one.
3. **GnuCOBOL's USAGE NATIONAL is unfinished** (fz00704, fz02112): `cobc` itself warns `handling of USAGE NATIONAL is
   unfinished`; a PIC N(5) item holds 20 bytes and prints NUL-interleaved. No authority.
4. **Incompatible data** (fz02113 `MOVE "ABCDE" TO PIC 9(5)`, fz04932 `MOVE "ABC" TO PIC 9(5)`, fz00704 a PIC -ZZ9
   item whose VALUE " 12" leaves a space in a digit position): the result of the MOVE is undefined (`cite.py --check
   14.6.13.2 "Incompatible data"` -> OK §14.6.13.2; `cite.py --check 14.9.25.4 "the results of the execution of the
   MOVE statement are undefined"` -> OK §14.9.25.4 6)). WiseOwl decodes the non-digits as zero
   (`MoveEditionDifferentialTests.NonDigitFilledNumeric_DecodesZeroInArithmetic_1461312`), GnuCOBOL copies them.
5. **Out-of-range subscript and reference modification** (fz04934 `EV (4)` of an OCCURS 3 table; fz04932 `WS-SRC (1:WS-LEN)`, WS-LEN being 5 at run time
   of a 2-position item). With checking off an out-of-range subscript continues (`docs/CONFORMANCE.md` DOC-A.1-69);
   an unchecked out-of-range reference modification ends the run unit with EC-BOUND-REF-MOD (the DETERMINATION in
   `docs/CONFORMANCE.md` "an unchecked out-of-range reference modification ends the run unit"), which is why
   fz04932's WiseOwl run exits 1 and stops printing.
6. **Numeric display forms recorded before `--numeric-display decimal`** (PB3505): fz01932 and the F3 line of fz01111
   no longer differ on this build.

The 17 programs and a per-row diff are in `E:\COBOL-coord\scratch\op\w-pb3852\w20261711d\` (`src\`, `cmp.txt`).

**The figurative-constant receivers themselves** were then probed directly, one MOVE per (figurative constant,
receiver) pair across alphanumeric, alphabetic, alphanumeric-edited, national, national-edited and boolean (bit and
display) receivers at `--std 2014` and `--std 2023` (84 pairs, identical at both): every acceptance and refusal follows
Table 16, SR6 (ZERO to alphabetic), SR7 (a non-boolean figurative constant to a boolean item) and Table 17, and the
stored values follow §8.3.3.6.4 GR2 and GR4. One GnuCOBOL divergence appeared and is WiseOwl's to keep: GnuCOBOL does
not edit a `MOVE ALL "lit"` into an alphanumeric-edited item (`ABABA` for `PIC X(2)BX(2)`, `ABABABA` for
`PIC X(3)/X(3)`), though it edits ZERO, SPACE and an ordinary literal; §14.9.25.4 GR6 and §13.18.40.5 rule 3 put the
insertion character in its own position and the characters in the data positions (`AB AB`, `ABA/BAB`).
