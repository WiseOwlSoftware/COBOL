# R14 — the (statement, location) pair is dropped at most last-exception-status writes; EcWrap has no SEARCH or GO TO arm

> R00 ledger-audit orphan (2026-08-08): F3 (with F4-probe corroboration) of `PHASE-B-15.32-15.44-findings.md`, probe-verified OPEN
> against the R10-landed tree (`5312996a`). The probe programs are reproducible from the finding text.

PROBE (2026-08-08): `>>TURN EC-RANGE-SEARCH-NO-MATCH CHECKING ON WITH LOCATION` + a no-match SEARCH, then
`DISPLAY FUNCTION EXCEPTION-STATEMENT` prints 63 SPACES where §15.32.3 r2 requires `SEARCH` + 57 spaces. A
second probe (`GO TO … DEPENDING ON T(I)` with the subscript out of range inside a Format-3 PERFORM) raised
NOTHING at all — the EcWrap QueryFor switch has no BoundSearch and no GO TO arm, so those statements never
receive a wrapper. The control (`MOVE T(I) TO X` in the same PERFORM shape) prints `CAUGHT=[MOVE …]`, so the
kind-mapped name machinery (R01–R10 wave's R04) works where a wrapper exists.

Ledger F3 enumerates the full site list: every `ExceptionState.Set(name, fatal)` 2-argument call drops the
(statement, location) pair — SEARCH's two range conditions, the nonfatal ambient gates (EC-DATA-CONVERSION,
EC-BOUND-OVERFLOW), CobolTiming, CobolDynString, CobolString.ThruMember, EmitPropagationPickup — and
`GOBACK/EXIT PROGRAM … RAISING` cannot even thread it (`BoundRaising` has no location fields, unlike its
sibling `BoundRaise`). FIX SHAPE (ledger, one-rule-one-place): make the pair AMBIENT per statement — the same
channel the `…Checking` flags already ride — set/cleared by the emitted statement wrapper, so
`ExceptionState.Set` picks it up unconditionally and no raise site can forget it; give SEARCH and GO TO their
QueryFor arms; bring the RAISING leg onto the channel; delete the positional stmt/loc parameters from the
7 sites that thread them today. Pair with a drift test that no Set call can fire under WITH LOCATION while
the ambient slot is unset. Also corrects COBOLNET_CONDITIONS_EXCEPTIONS_DESIGN.md's claim that the name is
recorded at the raise site.

## LANDED 2026-08-08

**The fix is the AMBIENT statement context** (`ExceptionEngine.EnterStatement`/`ExitStatement` + the 2-argument
`Set` fallback), exactly the ledger's shape — with three corrections to this note's own pre-implementation
claims, each measured before building on it:

- **R04/R06/R07 had already landed their halves** — the Table-12 kind resolver (probe: `CAUGHT=[GO TO]`), the
  per-condition WITH LOCATION rule (probe: the mixed statement still answers spaces), and the
  `SetPropagating` stmt/loc threading. What remained was the CHANNEL for the sites an emitter cannot thread.
- **The "GO TO gets no EC wrapper" observation was really a SAME-LINE enable bug**: the GR14 implicit TURN is
  spliced AT the PERFORM's line and `TurnState.Fold` breaks at `Line >= statementLine`, so
  `PERFORM WITH LOCATION GO TO ... WHEN ...` written on ONE line silently escaped checking (measured: raised
  nothing; the two-line form raised and caught). Fixed with an `Inclusive` marker on the two SYNTHETIC events
  (the GR14 enable AND the handler floor, which had the mirror-image same-line hole in the disabling
  direction); real directives occupy their own lines and keep the strict compare.
- **`__IoCheckEc` keeps its positional channel**, deliberately: WITH LOCATION on `EC-I-O-... FILE F1` is
  per-(name, FILE), which the ambient name set cannot express — a same-name raise on another file would
  wrongly stamp. File-scoped entries are excluded from the ambient set and the bridge's explicit operands
  always win (pinned by `PositionalOperands_AlwaysWin_OverTheAmbientPair`).

Landed: `EnterStatement`/`ExitStatement` + `Set` per-name fallback (runtime) · `EmitChecked` enters the
context once per checked statement with the WITH-LOCATION name set · QueryFor arms for `BoundSearch` and
`BoundContinueAfter` + ambient-tail gates for EC-STORAGE-NOT-AVAIL / EC-RANGE-INVALID · the per-site
`EcStmtLoc`/`EcStmtLocExpr` baking DELETED (EmitArgOrPlain, EmitSizeHandling, EmitOverflow, CallEmitter's
program-EC catch, PtrEmitter x2 all collapse to 2-argument Set; the size-error fatal message reads the name
back from the status just set). Probes after: SEARCH -> `[SEARCH]`, CONTINUE AFTER -> `[CONTINUE]`, one-line
GO TO -> `[GO TO]` caught, the mixed statement still spaces. Golden `exception_statement_ambient` (2023) +
`AmbientExceptionContextTests` (6). Doc-sync: COBOLNET_CONDITIONS_EXCEPTIONS_DESIGN.md's "recorded at the
raise site" claim corrected (the ledger F3 predicted it would be falsified).
