# PB3116 — the conformance manifests are a duplicate of the folder, and a landing conflict hotspot

> ⚙ **flags:** process-only

Source: the operator, from `land_lane.py status` after the landing lane's first evening (PB3103, landed PR 18).

## What happens

Each of `tests/conformance/{85,2002,2014,2023,negative}/manifest.json` holds two flat name lists, `enabled` and
`pending`. Measured at origin/main `015c04173`:

| folder | enabled | pending | `.cob` files | on disk but unlisted |
|---|---|---|---|---|
| 85 | 419 | 0 | 419 | 0 |
| 2002 | 836 | 0 | 836 | 0 |
| 2014 | 240 | 0 | 240 | 0 |
| 2023 | 846 | 1 (`pb485_value_only_format1`) | 847 | 0 |
| negative | 2623 | 0 | 2623 | 0 |

So apart from one pending case the lists restate the folder exactly. None is sorted: a new golden's name is
written at the TOP of `enabled`. Every branch that adds a golden therefore edits the same lines of the same file,
and two such branches conflict whenever the second one merges origin/main.

The runner says as much: `CorpusRunnerTests.cs` calls the manifest "a DISCOVERY register — two flat name lists whose
only job is that nothing on disk goes unlisted". Two more mechanisms exist only to keep the duplicate in step: the
integrity fact "Every on-disk .cob is manifest-listed (enabled ⊕ pending)" in `CorpusRunnerTests.cs`, and the
PostToolUse hook `scripts/hooks/golden_registered.py`, added because a forgotten registration "has bitten twice in
one session".

## The cost, observed

The landing lane's first evening (2026-10-12, 18:25 to 21:44) started 8 landing attempts. One merged (PR 23) and six
stopped. Two of the six stopped on these manifests:

- `worktree-wf_76dbe266-f46-3` (w1070h, PB1616): `CONFLICT in tests/conformance/negative/manifest.json`, found when
  `enqueue.py land` brought origin/main in again AFTER its gate, so that gate's time was spent for nothing.
- `worktree-wf_d63f7207-db5-30` (PB2720): `CONFLICT in tests/conformance/2002/manifest.json,
  tests/conformance/negative/manifest.json`.

The file is touched often: 127 of the 376 commits on main's first-parent line from 2026-10-05 00:00 PDT to
`015c04173` edit one of the five manifests (`git rev-list --first-parent --since='2026-10-05 00:00' 015c04173 --
tests/conformance/{85,2002,2014,2023,negative}/manifest.json`; an explicit time of day, since a bare
`--since=2026-10-05` starts at the current clock time and drifts with the hour it runs). Each stop costs a finisher, a review of the new tip and a second gate on both hosts. The fix lane adds goldens with
nearly every defect (MANDATORY-PRACTICES I4: "parser + emitter + golden + manifest in one commit"), so the conflict
rate grows with the number of branches landing in parallel. Raising that number is the landing lane's whole purpose.

## Fix shape (for the implementer to confirm against the design)

Per CLAUDE.md rule 5, prefer the shape that makes the next case automatic: the population is the folder. A golden
needs no registration, and the one per-case fact a manifest holds (pending) moves into the program's own leading
comment block. That is where the corpus already keeps its other per-case facts: `*> reject-at:` (negative corpus)
and `*> options:` (kb/Work PB803). Delete the manifests, the integrity fact and `golden_registered.py`. Change every
reader in the same change, with no fallback (rule 4). The files that name `manifest.json` or `"enabled"`, from a grep
over `tests/`, `scripts/`, `.claude/` and `.github/` (2026-10-12, on `015c04173`); some of them mean the arch-oracle's
own `*.manifest.json` files, a different family that stays, and the collation and grapheme `*.manifest.json` data
files (`scripts/collation/`, `scripts/unicode/`, `CollationTableTests.cs`, `GraphemeBreakerTests.cs`) stay too:
- runner and corpus facts: `CorpusRunnerTests.cs`, `ArchOracleDriftTests.cs`;
- unit drift tests that read a conformance manifest directly: `FormatWordDriftTests.cs:100` (each edition's
  `enabled`), `IntrinsicArgumentClassDriftTests.cs:145` (a negative is in `negative/manifest.json`),
  `IntrinsicModeFlagCoverageDriftTests.cs:158` (each folder's `enabled`) and `IntrinsicResultTypeDriftTests.cs:264`,
  `:279` (the negative and 2023 manifests). Their "is listed" assertions become "is on disk and not pending" (the
  header marker); a missing file would otherwise throw at the Linux gate if PB3112's cap keeps them out of leg 1;
- scripts: `scripts/arch/capture_oracle.py`, `scripts/arch/compare_oracle.py`, `scripts/orchestrator/landing_check.py`,
  `scripts/orchestrator/landing_oracle.py`, `scripts/prune_worktrees.py`, `scripts/spec/impacted_tests.py` (tier 0a
  keys on "a corpus row whose manifest entry or golden files the diff changes"), `scripts/hooks/golden_registered.py`
  (deleted), `.claude/skills/workstream/templates/build_lane1_inputs.py` and the golden-lane workflow template
  `.claude/skills/workstream/templates/wf_lane1_draft.js` (its output schema REQUIRES `manifest_entries` and
  `negative_manifest_entries`, lines 35-36 and 44, its prompt asks each writer for the entries to register, line 125,
  and lines 167-168 pass them on);
- instructions: `.claude/skills/land-a-fix/SKILL.md:53-55` and the briefs `implementer-brief.md`,
  `fix-lane-implementer-brief.md` and `golden-lane-brief.md` under `.claude/skills/workstream/templates/`, which tell an
  implementer to register a golden; `docs/VERSION_TEST_MATRIX_DESIGN.md`, MANDATORY-PRACTICES I4 and I7,
  `tests/conformance/README.md` and `.github/PULL_REQUEST_TEMPLATE.md`. A grep over `docs/` names 11 more design and
  history files; sweep the ones that describe the current registration.

If the design needs a list kept for some other reason, sorting it would only lower the conflict rate, not remove it,
and a `merge=union` attribute on a JSON array is a shim that can write invalid JSON. Neither is the fix.

Related: PB3107 (the arch-oracle's one-baseline rule, the other serializing file family in tonight's stops: db5-4
conflicted on three `arch-oracle/*.manifest.json` files).
