# PB1558

Found 2026-09-24 by the golden-lane-2 misc-p30 writer, who rendered the PDF page (p290) for the SPECIAL-NAMES
format order; **re-probe first**. Repro: `<scratchpad 9db39f61…>\gl\held\misc-p30\tests\conformance\2002\l1c30_alphabet_named_locale_format_order.cob`.

Fix: resolve LOCALE names after the whole SPECIAL-NAMES paragraph is bound (a two-pass / deferred lookup), not in
source order. Then CORRECT `pb64t1_locale_declare` to the format's order (its current order is itself non-conforming
source — check whether the format lets LOCALE precede ALPHABET at all; if not, that golden must reject or be rewritten),
and sweep every SPECIAL-NAMES clause that refers forward to another clause of the same paragraph.

## Landed — wave 59 group K (with PB1557)

Re-probed on the w59k build first: `l1c30_alphabet_named_locale_format_order` drew COBOLNET1664 "no LOCALE clause
is in scope", as filed.

**Root.** `SwitchBindSpecialNames` bound each SPECIAL-NAMES clause in SOURCE order, and `AlphabetBind` resolved
`IS LOCALE locale-name-2` (§12.3.7.3 SR24) on the spot. The §12.3.7.2 format prints alphabet-name-clause BEFORE
the LOCALE clause and §5.2.1 requires "the sequence given in the general format", so locale-name-2 is a FORWARD
reference in every conforming program. The walk is now DEPENDENCY-ordered: the clauses that reference no
paragraph name (LOCALE among them) bind first, then every ALPHABET clause, then — as before — CLASS / SYMBOLIC
CHARACTERS and the OBJECT-COMPUTER clauses. Design docs updated (`DESIGN-locale-facility.md` §4.4.2,
`COBOLNET_DESIGN.md`).

**Sweep of the clause-to-clause references inside SPECIAL-NAMES:** ALPHABET → LOCALE (fixed here); CLASS … IN and
SYMBOLIC CHARACTERS … IN → ALPHABET (already deferred, PB110); ALPHABET's SR11 symbolic-name check (already read
syntactically before the walk, PB226); OBJECT-COMPUTER PCS / CHARACTER CLASSIFICATION (already after the walk).
`SpecialNamesClauseOrderTests` compiles each of the four reference pairs in BOTH orders.

**Goldens that pinned non-conforming order, corrected to the format's order (ALPHABET before LOCALE):**
`2002/pb64t1_locale_declare` (header says so), `2002/pb64t1_ec_locale_missing`, `2002/pb64t1_locale_scope_and_return`,
`2002/pb64t1_save_restore_locale`, `2002/pb64t1_set_locale_categories`, `2002/pb64t1_sort_locale_snapshot`,
`2014/pb764_format_keywords_not_names`, and `negative/pb64t1-alphabet-locale-name-undeclared` (its `.err` now
pins "declared: ES", proving the post-paragraph lookup saw the later clause and still refused SV). New golden:
`2002/l1c30_alphabet_named_locale_format_order` (the misc-p30 repro). Rows witnessed by batch
`w59k-PB1557-PB1558`: SR-12.3.7.3-24, GR-12.3.7.4-L2.2.
