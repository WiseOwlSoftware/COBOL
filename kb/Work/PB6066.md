# PB6066 - a row's code-location is trusted when it is written and unread when it is wrong

**A. The drift test reads one inventory.** `SpecTraceabilityInventoryDriftTests.EveryCodeLocation_ResolvesInTheTree`
(tests/WiseOwl.Cobol.Tests.RepoDrift) reads `TraceabilityInventory.Rows` (`tests/version-matrix/inventory`); nothing reads the
`inventory-1985`, `inventory-2002` or `inventory-2014` code-locations. PB5781 deleted `IntrinsicBinder.ArgsOf`; its finisher re-sited
the two code-reads-1985 rows the test caught, but `tests/version-matrix/inventory-2002/2002-FMT-15.38.1.json` still names
`IntrinsicBinder.cs#ArgsOf` (re-probe: grep the file; the row may have been re-sited since, in which case the gap is the test, not
the row). CLAUDE.md rule 4 (change every caller) cannot hold for a reference no gate reads. Extend the test to every edition's
inventory and to the `code-location` entries of the code reads.

**B. Re-verdicts replace the site list with the new helper.** Three branches that flipped a row to CONFORMS re-sited its
`code-location` to the one method they added and dropped the rest: SR-14.9.30.3-11 and SR-14.9.41.3-6 to
`RecordLayout.cs#SameClassCategoryUsage` alone (dropping `KeyedIoBinder.BindRead/BindStart`, `KeyIndexOfKeyItem`, `GenericKeyIndex`,
`IsInRecordOfFile`, `RecordKeyNameOf`, `CategoryOfItem`, `UsageOfItem`); SR-13.18.38.3-21 and -18 to a helper predicate, dropping
`OdoResolvePass.cs#DependingAttributeFault` (where SR18/SR21 are decided) and `DataBinder.cs#IsInExternalRecord`; GR-13.18.33.4-3
to `ClassifyRedefinesClassesPass.cs#Run`, dropping six sites its report says were kept. A row whose notes still say "OdoResolve
asks DependingAttributeFault" while its code-location omits it misdirects the next reader. Compare each row's code-location on main
with the one at its landing's parent, restore what the notes still name, and have the verdict recorder refuse a re-site that drops a
site its own notes mention (or require the union).

**C. Registrar records owed.** `1985-SR-VI.6.16.3-3` is recorded KEPT to FMT-14.9.19.2 though no later edition prints the rule
(`record_verdicts` refuses a verdict on a KEPT row; PB5768 report). The 1985 catalog row for §1985:VI.6.3.1.1.1 is owed (PB5835
report). Each needs a registrar change record, not an edit of a stored row.

**Sites:** tests/WiseOwl.Cobol.Tests.RepoDrift/SpecTraceabilityInventoryDriftTests.cs (`EveryCodeLocation_ResolvesInTheTree`); scripts/spec/record_verdicts.py (`merged`, `validate`); tests/version-matrix/inventory/SR-14.9.30.3-11.json (whole: inventory row record); tests/version-matrix/inventory/SR-14.9.41.3-6.json (whole: inventory row record); tests/version-matrix/inventory/SR-13.18.38.3-21.json (whole: inventory row record); tests/version-matrix/inventory/GR-13.18.33.4-3.json (whole: inventory row record); tests/version-matrix/inventory-2002/2002-FMT-15.38.1.json (whole: inventory row record); tests/version-matrix/inventory-1985/1985-SR-VI.6.16.3-3.json (whole: inventory row record); tests/version-matrix/code-reads-1985/1985-SR-VI.6.16.3-3.json (whole: code-read record). Re-probe for item A: 2002-FMT-15.38.1 no longer names `IntrinsicBinder.cs#ArgsOf` as a live code-location (only a `retired-witness:` mark, re-pointed to `ArgumentsOf` by PB5932), so item A's gap is the test alone.

## Landed (2026-11-24, wave 20262166 group C)

**A.** Re-probe on the branch build: `EveryCodeLocation_ResolvesInTheTree` already reads every held edition's store
(`TraceabilityInventory.Editions`, PB5932 review round 2 R2-2) and `2002-FMT-15.38.1` no longer cites `ArgsOf` as a live
site, so the code-location half was discharged before this change. The sibling that read the 2023 store alone was
`EveryNotesLocation_ResolvesInTheTree`; it now reads every edition (22 SpecTraceabilityInventory tests pass, 0 unresolved). A code read's
`code-location` is evidence at its pin and is validated by `code_reads.py` at import (PB5863), so the drift test does not read it, by design.

**B.** `inventory_schema.dropped_sites_named_in_prose` (asked by `record_verdicts.validate`) refuses a record that drops a
code-location whose symbol the row's restated prose still names; the self-test `audit_witness_loss.py --self-test` plants four
shapes. The four rows' dropped sites were restored through a `record_verdicts` batch; `DataBinder.cs#IsInExternalRecord` is gone
since PB5797 (replaced by `DataBinder.Odo.cs#IsDescribedInContainer`, already cited), so it was retired, not restored.

**C.** `1985-SR-VI.6.16.3-3` is recorded CONFORMS with a REMOVED change record (no 2023 clause prints the END-IF/NEXT SENTENCE
restriction). The catalog row for §1985:VI.6.3.1.1.1 exists (`1985-GR-VI.6.3.1.1.1-p1`/`-p2`, CONFORMS with a suite case), so
that item was a misreading of the report and is discharged.
