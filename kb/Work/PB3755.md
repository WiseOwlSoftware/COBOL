# PB3755 — GateSr5 has two askers; the activation arm is a third

**Sites:** `src/Cobol.Net.Compiler/Binding/FigurativeAssociation.cs` (`FigurativeAssociation.GateSr5`, `FigurativeAssociation.Sr5FigurativeText`, `FigurativeAssociation.Sr5ReceiverOf`), `src/Cobol.Net.Compiler/Validation/VersionConformancePass.cs` (`VersionConformancePass.GateMove`, `VersionConformancePass.GateInitialize`), `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/ParameterConformance.cs` (`ParameterConformance.CheckArgument`, `ParameterConformance.GateFigurativeEdition`), `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/OoBinder.cs` (`OoBinder.OoBindInvocationArg`), `tests/Cobol.Net.Tests.Conformance/EditionGateArmDriftTests.cs`

Filed 2026-10-25 by the enqueue clerk from PB3605's R1-1 LEAD (low, pre-existing, not a PB3605 regression).
`GateSr5` (VersionConformancePass.cs about line 401) holds the SR5 edition rows (HIGH-VALUE, LOW-VALUE, QUOTE and a non-digit ALL
literal as the sender of a MOVE to a numeric item) and has exactly two askers: `GateMove` (line 375) and `GateInitialize` (INITIALIZE REPLACING's hypothetical MOVE).

Rule (read in `specs/ISO_COBOL.md` on 2026-10-25):
§14.8.2.3.3 rule 2 d) "Otherwise, the conformance rules are the same as for a MOVE statement with the argument as the sending operand and the corresponding
formal parameter as the receiving operand" (rule 2 applies to a program with a REPOSITORY program-specifier, a NESTED CALL, a method, a function). So a figurative argument BY CONTENT
into a non-numeric elementary formal is under the same MOVE rules as the explicit statement. PB3605 fixed the SPACE arm in both phases (the MOVE chain and
`ActivationRelations`), but the edition rows are not asked of the activation arm.

## What the user's program sees
A nested CALL (or a method or function call) that passes a 2023-removed figurative BY CONTENT into the formal the removal row names compiles clean at
`--std 2023`, where the equivalent MOVE is refused by the SR5 edition row. No diagnostic; the source is accepted where the edition forbids it
(under-rejection, silent).

## Fix direction
Make the activation arm a third asker of `GateSr5` (the edition rows live in one place, PB879), or better, make the rows part of the conformance relation the
activation arm already asks (the MOVE rules), so a fourth asker is automatic. Golden per edition (85, 2002, 2014, 2023). Cross-link PB3605.

## Landed

Re-probed on the worktree build (main 204718793; `CALL "SUB" AS NESTED USING BY CONTENT <figurative>` into a `PIC ZZ9` formal of a
contained program): HIGH-VALUE, LOW-VALUE, QUOTE and ALL "X" compiled clean at 2002, 2014 and 2023 (the 2014 QUOTE obsolescence warning
and the 2023 removal error were both missing), and ALL "57" compiled clean at every edition although the written MOVE is
COBOLNET0902 from 2002 (8.3.3.6.3 SR3). Both are 14.8.2.3.3 rule 2 d): "the conformance rules are the same as for a MOVE statement".
A NUMERIC formal is rule 2 a)'s COMPUTE and was already refused by the relation (COBOLNET1688), so only a numeric-edited formal is
the SR5 case.

Fix shape (not the note's "third asker of a private method"): the three rows left `VersionConformancePass` for ONE public body,
`FigurativeAssociation.GateSr5` (beside `GateSr3`, which it asks first), with the receiver exemptions in `Sr5ReceiverOf`, so the
written MOVE (`GateMove`), INITIALIZE REPLACING (`GateInitialize`) and the activation arm call the same code. The activation arm is
`ParameterConformance.GateFigurativeEdition`, asked after the edition-blind relation passed from `CheckArgument` (CALL and a
user-defined function: the one entry both lanes share) and from the INVOKE figurative arm: all three lanes probed, HIGH-VALUE /
LOW-VALUE / ALL "X" are COBOLNET0902 at 2023 and valid at 2002 and 2014, QUOTE is the 0903 warning at 2014 and the error at 2023,
ALL "57" is 0902 from 2002. A call whose program is located by name at run time has no compile-time formal (and no run-time lane
carries an edition), so it has nothing to gate. The rows no longer appear in `VersionConformancePass`, so the three
`EditionGateArmDriftTests` bound-arm entries left with them; `Sr5EditionRowAskerDriftTests` pins that the rows are read only by the
body and that every file that asks `ContentConformanceReason` also asks `GateFigurativeEdition`.

Goldens: `pb3755_content_figurative_numeric_edited_formal` (2002, 2014; CALL, INVOKE and function lanes in one program),
`pb3755-call-content-high-value-numeric-edited-2023`, `pb3755-invoke-content-low-value-numeric-edited-2023`,
`pb3755-function-content-all-literal-numeric-edited-2023` (2023 each), `pb3755-content-all-multichar-numeric-edited-2002` (2002 on).

**For the next implementer.** A new activation lane that asks `ParameterConformance.ContentConformanceReason` must also call
`GateFigurativeEdition` (the drift test names the file otherwise).
