# PB3365 — OPEN — a legal SEARCH of a nested dynamic table aborts at run time

Found 2026-10-18 by the wave-1115 PB2849 branch (`E:\COBOL-coord\scratch\reports\w1115e-PB2849-report.md`, New defects item 1). Register check: the COBOLNET1756 notes PB1029, PB1030, PB1054, PB1055, PB1136, PB1173, PB1175, PB1260, PB1279 and PB1283 are all landed and none covers SEARCH of a nested dynamic table; no open note names SearchBinder with OCCURS DYNAMIC.

**Repro.** `E:\COBOL-coord\scratch\w1115e\p2.cob`: `10 EP PIC X OCCURS DYNAMIC CAPACITY IN ECAP INDEXED BY EX` nested under another table, then `SEARCH EP(I) VARYING J AT END ... WHEN EP(I, EX) = "~" CONTINUE`. The compile warns COBOLNET1756 and the run aborts with `NotImplementedCobolFeatureException`.

**Code site.** `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/SearchBinder.cs` lines 46-55: `table.IsDynamicTable && ReferenceResolver.BuildTablePath(table) is null` returns `BoundUnsupported` ("a later increment"). The scan bound (current capacity, §8.5.1.9.1) and the EnterSearch/ExitSearch bracket need a subscripted capacity path over the enclosing indices.

**Rule.** §8.5.1.9.1 (dynamic-capacity tables: the logical capacity is the physical capacity, the current capacity bounds the table). Not a SORT or file I/O item. Rules 3 and 4: implement the capacity path for the nested case; a deferral is debt. Sweep the sibling statements for the same `BuildTablePath ... is null` deferral (SORT table PB1055 landed the nested fixed case).
