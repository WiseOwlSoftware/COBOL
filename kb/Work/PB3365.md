Rules 3 and 4: implement the capacity path for the nested case; a deferral is debt. ## Landed (wave 1120 B)

**Re-probe.** Programs of the note's shape (`SEARCH EP(I)` and the bare `SEARCH EP` over `EP OCCURS DYNAMIC` inside `E OCCURS 3`, in a plain record, an EXTERNAL record, a TYPEDEF'd record and LOCAL-STORAGE) all drew the COBOL1756 warning and aborted at run time, exactly as the note says.

**Root.** A dynamic-capacity table's scan bound is its CURRENT CAPACITY (§8.5.1.9.1), and each occurrence of an enclosing table holds a capacity of its own (§8.5.1.9.2), so the bound exists only for ONE enclosing occurrence. The binder refused to build it because it asked the whole-table path (`BuildTablePath(table)`, null under another table) instead of the instance path the SORT table subject already builds (`BuildTablePath(table, enclosing)`).

**Fix.** `SearchBinder.Identifier1` reads identifier-1's enclosing subscripts when it wrote them all (SR2 bans only the searched level's); otherwise `Phrases` binds the WHEN conditions under `ReferenceResolver.CaptureEnclosingSubscripts`, which takes the enclosing positions from the first committing subscript reading of a reference to the table (§14.9.37.4 GR1 puts the occurrence "in the WHEN phrases"; the bare spelling is the standard's own suite's, NC233A). `SearchBinder.DynamicTablePath` builds the path once for both formats; `ControlFlowEmitter.EmitSearch` reads the `CobolDynTable` into one local that carries the scan bound and the EnterSearch/ExitSearch bracket. A nested dynamic table no phrase subscripts is refused COBOL2075 (`StatementValidation.SearchNestedDynamicWithoutOccurrence`) instead of guessed. `ReadSubscripts`' `bool tableSubject` became `TableSubject {None, Sort, Search}`. Determination D-SRCH-DYN in `docs/CONFORMANCE.md` §3.

**Goldens.** `cases/14.9.37-SEARCH/pb3365_search_nested_dynamic_table` (accept 2014; S1-S10: capacities 3/1/4, both spellings, both formats, VARYING, a WHEN body that moves the enclosing subscript) `pb3365_search_nested_dynamic_property` (an object-property subscript in the WHEN phrase, bare SEARCH in a loop and SEARCH ALL, plus a property as a function argument) and the negative `pb3365-search-nested-dynamic-no-occurrence` (refuse-at 2014, 2023; COBOL2075). Drift: `SearchOperandResolutionDriftTests` (the answer, and the one-place guard).

**Sibling sweep.** The other `BuildTablePath ... is null` deferrals: `SortBinder` (UnbuiltAccessPath after the instance path, unchanged), `InitializeBinder:203` (a whole-table INITIALIZE with no suffix, a different rule), `CapacityRegisterPlaceOf` (a documented SR30/SR31 determination). No other SEARCH-shaped deferral remains; the two tests that used this shape as THE genuine COBOL1756 exemplar (`StatementDeferralAnnounceDriftTests`, `BoundDeferralDriftTests`) now use INSPECT over LINAGE-COUNTER and say how to replace it next.
