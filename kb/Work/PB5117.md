# PB5117 - at --std 85 a random READ KEY IS of an indexed file whose alternate key has duplicates returns I-O status 00 where 1985 returns 02 (the key equals the next record's key in the key of reference)

**Sites:** `src/WiseOwl.Cobol.Runtime/IO/IndexedConnector.cs#ReadRandom` (ends `return ReadSucceeded(FileStatusCode.Success)` at every edition; `ReadSequential` alone returns `DuplicateAlternateKey`)

**Sites (landed):** `src/WiseOwl.Cobol.Runtime/IO/IndexedConnector.cs:546` (`ReadRandom`, `NextRecordDuplicatesKey`); `src/WiseOwl.Cobol.Runtime/Control/DialectBehavior.cs` (`DialectBehavior.IndexedDuplicateKeyStatusSequentialOnly`, VCR row 7.55); goldens `conformance-suite/cases/14.9.30-READ/pb5117_random_read_dup_status_1985` (85) and `pb5117_random_read_dup_status` (2002 2014 2023).

**Mechanism.** The 1985 list of successful-completion statuses gives 02 for any READ whose current key of reference equals the same key in the next record; its READ item names no access mode, so it covers the format 2 (random) READ with a KEY phrase. The compiler applies the 2023 rule (§2023:9.1.13.2 GR2 and §2023:14.9.30.4 GR27: 02 only for a sequential READ) at every edition. The rest of the status sequence in the draft (OPEN of an absent OPTIONAL file 05, WRITE 02, REWRITE 02, sequential READ NEXT 02 and 00) matches. No commit on main since the pin (e8a1b94f50) touches IndexedConnector.cs. 04 is not in the draft: it needs a record whose length conflicts with the file's fixed attributes, which one portable program cannot create.

**Found by.** The 1985 witness-drafting pass (kb/Work PB4995 item 3): each rule below is a witness program drafted from the 1985 text alone, run at `--std 85`, and its result differs from what the text requires (outcome MISMATCH). Harm and observed text are the record's; nothing here was re-derived.

**Inventory.** The traceability inventory carries no 1985 rows yet (PB5094: work.py refuses 1985 ids), so `inventory_rows` is empty; the row this note covers is the 1985 rule id listed below (catalog `docs/rearchitecture/spec-rule-catalog-1985.json`).

**Rules (1; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-GR-IX.1.3.4-L2.1` - `§1985:IX.1.3.4` (record harm: wrong-answer, slice-02): Item (1) Successful Completion, "b. I-O Status = 02" for READ: "For a READ statement, the key value for the current key of reference is equal to the value of the same key in the next record within the current key of reference". The key of reference of a format 2 READ is established by its KEY phrase (§1985:IX.4.5.4 GR15) and the first record found is the first of a sequence of duplicates released in order (§1985:IX.4.5.4 GR17).
