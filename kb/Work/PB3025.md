# PB3025 — one file per DEVLOG entry, so two queued landings never touch the same file

**Owner decision 2026-10-11 ~11:36 PDT (kb/Work PB3015 Q2): "Yes, one file per entry (Recommended)"** — `DEVLOG/NNNN-slug.md`
per landing; a script renders the descending narrative; a CI check refuses a landing with no entry file; no two landings
touch the same file. Rule 6 (CLAUDE.md) is unchanged in substance: one entry per landing on main, newest first, the only
history. Why: with a merge queue, two queued pull requests that both insert at the top of one `DEVLOG.md` collide and the
second is bounced; the work register solved the same problem with one file per note.

**Design:** `DESIGN-test-build-ci.md` §3.17.4.
**NEEDS-OPUS:** a one-time migration of the project's only history (7.1 MB, about 2,000 entries) and the check that replaces
the push-time rule need judgment and a byte-level proof, not a mechanical edit.

## What changes
1. `DEVLOG/` directory; one file per entry, `NNNN-<slug>.md` (`NNNN` zero-padded to the current width, the slug from the
   title); the file's first line is the header exactly as today: `## Entry NNNN — YYYY-MM-DD HH:MM TZ — Title`; the body
   follows unchanged. Line endings: LF, like every tracked text file (PB3029, owner 2026-10-11: one line-ending format);
   the migration keeps each entry's content and normalizes its line endings to LF; `DEVLOG.md -text` leaves
   `.gitattributes` with the file.
2. `scripts/devlog.py`: `render [--since NNNN] [--out <file>]` (the descending view; `DEVLOG.rendered.md` gitignored);
   `stamp <branch>` (allocates `NNNN` through `alloc.py devlog`, renames the branch's `DEVLOG/pending-<slug>.md`,
   completes the header's number and stamp, one commit — called by `enqueue.py` so number order is enqueue order and
   therefore landing order; operator review item 2); `check [--base origin/main]` (exactly one NEW stamped entry file
   in the change, header well-formed, number not already on `main`, stamp parseable, no `pending-` file; the content
   of `landing_devlog.py` moves here and that script is deleted); `next` (the highest number in `DEVLOG/`, the
   allocator's floor); `--self-test` with planted trees for every arm.
3. The implementer writes `DEVLOG/pending-<slug>.md` with its entry's title and body and NO number (the
   `implementer-brief` and `dispatch-spec-implementer.md` say so; the lander's L1 "one entry per train" is gone with
   PB3023); `plan_wave.py` allocates no DEVLOG number any more (the stamp at enqueue does). The attended session's own
   branch follows the same shape.
4. **One-time migration** (`scripts/devlog_migrate.py`, run once in this landing, then deleted or kept as a self-tested
   tool with no further use — rule 4 says deleted): split `DEVLOG.md` (every `## Entry` header, 7.1 MB, mixed CRLF,
   unnormalized) into the files byte-faithfully; prove it by rendering and comparing bytes to the original before
   deleting `DEVLOG.md` and `scripts/prepend-devlog.py`.
5. Every reader of `DEVLOG.md` moves to `devlog.py`: `session-probe.ps1`, `gen_ledger.py` / `ledger_state.py` (the entry
   number on the ledger), the `devlog` memory and `brent-tools:devlog` skill text, `land-a-fix`, `kb-sync`, the DEVLOG
   drift tests (`DevlogDriftTests` or their current name), `docs/DOC_INDEX.md` (the `DEVLOG.md` row becomes `DEVLOG/`),
   CLAUDE.md rule 6 (the shape, not the rule), MANDATORY-PRACTICES L1/I-rules that say "the TOP of DEVLOG.md".
6. CI's `audits` job runs `devlog.py check` on `pull_request` and `merge_group`.

**Not blocked.** Lands before PB3023 (which calls `devlog.py check`).
**Code sites:** `DEVLOG.md`, `scripts/prepend-devlog.py`, `scripts/orchestrator/landing_devlog.py`, `scripts/orchestrator/{alloc.py,plan_wave.py}`,
`scripts/session-probe.ps1`, `scripts/spec/gen_ledger.py`, `CLAUDE.md`, `docs/DOC_INDEX.md`, `.github/workflows/build-and-test.yml` (audits).

## Landed (wave 1062, group A)

**Tooling.** `scripts/devlog.py` is the one reader and writer of `DEVLOG/`: `render [--since N] [--out F]` (README, then
entries by number then letter, descending, the files concatenated byte for byte), `stamp <branch>` (the branch's
worktree's one `pending-<slug>.md`, first line `## <Title>`, becomes `NNNN-<slug>.md` with the header
`## Entry NNNN — YYYY-MM-DD HH:MM TZ — Title`, the number from `alloc.py devlog`; one commit), `check [--base] [--rev]`
(the landing rule on committed trees: exactly one new entry — a header the base's history lacks, the base's monolith
included — stamped, plain-numbered above the base's highest; no pending, stray, mismatched or duplicate-numbered file,
no monolith, no deleted entry — a deleted entry counts the base's monolith too, header by header with its repeats,
so the migrating landing cannot drop an entry main has (review R1-1); exit 2 NOT RUN on an unreadable rev), `next`, and
`--self-test` (35 arms: planted trees for
every check arm, the migrating-landing shape, stamp in a real linked worktree with the allocator, the PB2605 hook repro
kept from `landing_devlog.py`, and `lint` over this repository's own `DEVLOG/`). `alloc.py devlog`'s truth is
`devlog.highest`; `plan_wave.py` reads the newest entries through `devlog.newest` and plans no DEVLOG number (the
`devlog_n` arg and the briefs' `{DEVLOG_N}` are gone); `inventory_ratchet.py`'s excuse lines come from `DEVLOG/` and
`kb/Work` (untracked files of both); `census.py`'s history class is the `DEVLOG/` prefix; `check_practices.py`'s
frozen prefix is `DEVLOG/`; `push-main.sh` exit 6 runs `devlog.py check`; CI's `audits` job runs it on every pull
request, merge group and `ci/**` landing branch (base: the PR merge's first parent, the merge group's base, or the
merge-base with main); the doc-only path list says `DEVLOG/`. `landing_devlog.py` and `prepend-devlog.py` are deleted.

**Migration** (`scripts/devlog_migrate.py`; first run at commit f5cbb6db6, re-run by the review finisher on main
01f392184's `DEVLOG.md`, and run once more by the landing on main's): it splits the committed `DEVLOG.md` (`-text`,
mixed CRLF and LF) at every `## Entry` line into README.md + one entry file per header, LF (PB3029). PROOF: the render is
byte-identical to the LF-normalized monolith (on main 01f392184: 7,183,749 bytes, 1,982 entries through Entry 1962,
sha256 72a608024e766f55c6996b74370722c89dca134b9ae84ca3982f253626eb5574), checked again by an independent `render
--since 0` against `git show HEAD:DEVLOG.md`. Each run rewrites the README's history sentence, `(entries 001–NNNN,
split from …`, to the range it split (review R1-2), so no doc carries a count the landing's re-run would make stale. Every header is kept as written; 44 file names carry a letter (1191a-d from their headers;
the twenty numbers the monolith used twice, 008-014 and 171-185, lettered b above a in the monolith's order). The
README's ordering note was then rewritten for the new shape. `.gitattributes` loses `DEVLOG.md -text`;
`DEVLOG.rendered.md` is gitignored.

**⛔ LANDING THIS BRANCH (the lander, once).** Main's `DEVLOG.md` gains entries after this branch's base, so the
rebase stops on a modify/delete conflict on `DEVLOG.md`: take MAIN's `DEVLOG.md` (`git checkout <main side> --
DEVLOG.md`), run `python scripts/devlog_migrate.py` (it re-splits the whole file, keeps `DEVLOG/README.md` and the
pending entry, brings the README's range up to date, re-proves the render, and `git rm`s `DEVLOG.md`), then `git rm
scripts/devlog_migrate.py` in the same landing (CLAUDE.md rule 4). Skipping the re-run is no longer silent: keeping
the branch's own split drops main's newer entries, and `devlog.py check` refuses that landing (exit 6) by naming each
header of main's monolith that no entry file carries. The landing's own entry is this branch's `DEVLOG/pending-*.md`, folded with the train's
and numbered by `python scripts/devlog.py stamp <branch>` after the final rebase; `devlog.py check` (push-main exit
6, and CI) then passes with exactly one new entry. Until PB3023's `enqueue.py` lands, the lander stamps (lander briefs
step 4, MANDATORY-PRACTICES L1).
