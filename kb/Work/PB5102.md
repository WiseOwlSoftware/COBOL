# PB5102 - at --std 85 a sequential READ of a file in dynamic access mode is accepted without NEXT (indexed and relative): READ file RECORD AT END compiles and is bound as READ NEXT, the later editions rule

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/KeyedIoBinder.cs#BindRead` (the keyed READ binder, relative and indexed alike; the call site), `src/WiseOwl.Cobol.Compiler/Binding/Validation/StatementValidation.cs#CheckReadDynamicNextWritten` (the one rule, COBOL7144), `src/WiseOwl.Cobol.Editions/Diagnostics/DiagnosticCatalog.cs#ReadDynamicNextRequired`

**Mechanism.** 1985 requires the NEXT phrase when a dynamic-access file is read sequentially, for indexed and for relative files alike. The compiler accepts `READ file RECORD AT END ...` on an ACCESS MODE IS DYNAMIC file at --std 85 and binds it as a sequential read with NEXT implied, the later editions rule (§2023:14.9.30.3 SR9, as the record cites it). In 1985 the AT END phrase exists only in format 1, and format 2 is the random retrieval, so the READ without NEXT is the sequential READ the syntax rule forbids.

**Found by.** The 1985 MATCH confirmation pass (kb/Work PB4995 item 3): each rule below is a corrected draft (a "redraft") that the compiler at `--std 85` still fails (redraft_run MISMATCH). Harm and observed text are the records; nothing here was re-derived.

**Inventory.** The traceability inventory carries no 1985 rows yet (PB5094: work.py refuses 1985 ids), so `inventory_rows` is empty; the rows this note covers are the 1985 rule ids listed below (catalog `docs/rearchitecture/spec-rule-catalog-1985.json`).

**Rules (2; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-SR-IX.4.5.3-5` - `§1985:IX.4.5.3 SR5` (record harm: under-rejects, slice-20): "The NEXT phrase must be specified for files in dynamic access mode" (followed by ", when records are to be retrieved sequentially"). The draft only writes NEXT; the corrected draft drops NEXT from the sequential READ of the dynamic indexed file (AT END exists only in format 1 of §1985:IX.4.5.2; SR6 gives format 2 to random retrieval).
- `1985-SR-VIII.4.5.3-3` - `§1985:VIII.4.5.3 SR3` (record harm: under-rejects, slice-22): "The NEXT phrase must be specified for files in dynamic access mode" (followed by " when records are to be retrieved sequentially"). The Relative I-O sibling, the same words: `READ REL-FILE RECORD AT END` on a dynamic relative file (E:/COBOL-coord/scratch/confirm-85/out/work-slice-22/r11bad/r11bad.cob, line 31); its control keeps NEXT.

**Repro (`1985-SR-IX.4.5.3-5`, slice-20).** cobol.exe r06.cob --std 85 --source-format fixed --flag-extensions -o r06.dll, then dotnet r06.dll (line 34 is the READ without NEXT)

**Expected (from the 1985 text).** A diagnostic at line 34. The deciding words: "The NEXT phrase must be specified for files in dynamic access mode" (§1985:IX.4.5.3 SR5).

**Observed (copied from `1985-SR-IX.4.5.3-5`).** Compile exit 0 with no diagnostic; the run prints BRAVO then CHARL. The READ is bound as a sequential read with NEXT implied, the later editions' rule (§2023:14.9.30.3 SR9), applied at --std 85. The Relative I-O sibling §1985:VIII.4.5.3 SR3 (the same words) is accepted the same way: work-slice-20/p06r/p06r.cob, READ RFILE RECORD AT END on an ACCESS MODE IS DYNAMIC relative file, compiles clean and prints ALPHA.
