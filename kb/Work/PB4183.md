# PB4183 — docs/CONFORMANCE.md DOC-A.1-159 names the wrong cause for the host newline of a report file

**Sites:** `docs/CONFORMANCE.md` (row DOC-A.1-159, line 4015, the sentence "`FileRegistry.RegisterReport` registers every report connector as not line sequential, which is what makes the line end the host newline whatever the ORGANIZATION"); `src/WiseOwl.Cobol.Runtime/IO/FileRegistry.cs` (`FileRegistry.RegisterReport`, the comment at lines 209-212) carries the same ordering in a milder form.

**The defect (verified against the files).** `SequentialConnector.SelectLineEnd` (`src/WiseOwl.Cobol.Runtime/IO/SequentialConnector.cs:1026`) is `_lineSequential || !_recordDescribed || HasLinageClause ? LineSequentialDelimiter : RecordPrintLineEnd`. `RegisterReport` constructs the connector with `lineSequential: false, recordDescribed: false`. The host newline therefore comes from `recordDescribed: false` (the `!_recordDescribed` arm), not from `lineSequential: false`. What `lineSequential: false` does is keep the connector off the line sequential arm of the WRITE rules, which is why a print line holding a character above U+00FF is refused with `'91'` (§9.1.13.11) and never the `'71'` of §14.9.51.4 GR23 (a line sequential file's WRITE rule).

**The comment in `RegisterReport` (FileRegistry.cs:209-212)** says "the report writer's line end is the host newline either way, so the connector never takes the line sequential arm and a print line ... is refused with '91'". Its facts are right, but the "so" chains the two effects as if one caused the other: the host newline is `recordDescribed: false`'s doing and the `'91'` is `lineSequential: false`'s. It carries the same misattribution in a milder form, so it is a site.

**Fix direction.** Reword the DOC-A.1-159 sentence to name `recordDescribed: false` (`SelectLineEnd`'s `!_recordDescribed` arm) as the cause of the host newline and `lineSequential: false` as the cause of `'91'`; give the `RegisterReport` comment the same two-part reading. Sweep the other statements of the claim: grep `docs/` and the Runtime/IO comments for "not line sequential" and "host newline".
