# PB5198 - at --std 85 the RERUN clause has no function: BindIoControl drops every form after its screen and no rerun information is ever written

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/FileControlBinder.IoControl.cs` (`BindIoControl`, `ScreenRerunClauses`, `RecordRerunRecords`)
- `src/WiseOwl.Cobol.Compiler/Binding/Model/FileModel.cs` (`FileModel.RerunRecords`, `RerunRecordsClause`)
- `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/SequentialIoEmitter.cs` (`EmitAreaRegistrations`, `EmitRerunRegistration`); `src/WiseOwl.Cobol.Compiler/CodeGen/Roslyn/RuntimeApi.cs` (`FileRegisterRerunRecords`)
- `src/WiseOwl.Cobol.Runtime/IO/FileConnector.cs` (`RerunRecords`, `RecordProcessed`, `ReadSucceeded`, `Open`); `src/WiseOwl.Cobol.Runtime/IO/RerunRecordsPoint.cs`; `src/WiseOwl.Cobol.Runtime/IO/FileRegistry.cs` and `CobolFile.cs` (`RegisterRerunRecords`)
- `src/WiseOwl.Cobol.Runtime/IO/SequentialConnector.cs` (`Write`, `WriteAdvancing`, `Rewrite`), `RelativeConnector.cs` (`Write`, `Rewrite`, `Delete`), `IndexedConnector.cs` (`Write`, `Rewrite`, `Delete`)

**Mechanism.** §1985:VII.2.12.4 GR1 says where the rerun information is written (on each reel or unit of an output file, or as a separate file on an implementor-named device), and GR2 requires the implementor to provide at least one of the seven forms. RERUN is not in the hardware dependent language element list, so the implementation must accept the syntax and provide the function. `BindIoControl` keeps nothing of the clause after `ScreenRerunClauses` (its summary: a null rerun facility is conforming), and no member of CodeGen or the runtime reads it: with both ways written, no rerun file is created. kb/Work PB5086 (landed) named this null facility as a sibling still owed a note.

**Found by.** The 1985 code read (2026-11-10; its records are `E:/COBOL-coord/scratch/coderead-85/for-register.json`): each rule below was read against the code sites it names and probed at `--std 85`, and found non-conforming. Verdict, harm, evidence, repro and observed text are the records'; the rows' verdicts are recorded on another branch.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids of the list below.

If file-name-1 is specified, the rerun information is written on each reel or unit of an output file" at a place the implementor specifies, and "b. BindIoControl keeps nothing of a RERUN clause after the screen (its summary: "a null rerun facility is conforming"), no member of CodeGen or the runtime reads the clause, and a probe with both ways (ON a file with END OF REEL, ON an implementor-name with 1 RECORDS) writes no rerun information: the file named in ON is never created and no separate file appears. Same absence as the row 1985-GR-VII.2.12.4-2 (the seven forms). The witness writes RERUN ON a file EVERY END OF REEL OF an output file and checks only that the program runs.

**Expected (from the 1985 text, the record's).** Rerun information on the device SYSRR after each record written to OUTF, or a diagnostic that says the form is not provided. §1985:VII.2.12.4 GR2: "The implementor must provide at least one of the specified forms of the RERUN clause." and its form d: "When the integer-1 RECORDS phrase is used. In this case, the rerun information is written on the device specified by implementor-name-1, which must be specified in the ON phrase, whenever integer-1 records of file-name-2 have been processed." §1985:I.1.5.2.2: "An implementation must accept the syntax and provide the function for all Standard COBOL language elements as specified in a given level of a module which is claimed as being included in the implementation, except those language elements dependent on specific hardware components"; the RERUN clause is not in that list (§1985:p.XVII-94).

**Observed (the record's).** exit 0, no diagnostic (none with --flag-extensions); the program displays RERUN DONE. The directory then holds r3data.txt, 20 bytes (the two records), and the compiler's own outputs; nothing else is written, and the generated r3.g.cs does not mention SYSRR or the clause. The other six forms behave the same (conformance:cases/12.4.6-I-O-CONTROL/pb4945_rerun_seven_forms_85 compiles and runs; the witness's form a leaves outdata.txt at its 10 record bytes). At --std 2002 and later the clause is refused (COBOL0902).

**Fix direction (root cause, CLAUDE.md rule 4).** Either implement one form (writing a checkpoint record to the implementor-named file is the smallest that meets GR2) or record a determination in docs/CONFORMANCE.md that the 1985 null facility is a documented non-support; which one is a design decision for this note, recorded as a decision note.
