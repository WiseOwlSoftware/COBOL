# PB3938 — the upstream size guard sees only closed backtick fences

**Sites:** `scripts/spec/work.py#fence_lengths`, `scripts/spec/work.py#_FENCE`, `scripts/spec/work.py#upstream_problems`,
`scripts/spec/work.py#body_sections`, `scripts/spec/work.py#upstream_findings`

## The defect

PB3838 standing requirement 3 forbids committing GnuCOBOL source, testsuite programs or expected output (GPL). The
`upstream` kind enforces it as a cap of `UPSTREAM_MAX_FENCE_LINES` (60) lines on any fenced block of a note body
(`upstream_problems` over `fence_lengths`). The guard has two holes, both found by the tier 1 review (R1-1), both visible
by reading `scripts/spec/work.py` (line 536 and line 512 when the review was made):

1. `fence_lengths` appends a block's line count only when it meets the CLOSING fence. A block whose closing fence is
   missing never reaches `out.append(n)` and is dropped, so a record can end in an unclosed fence of any length and pass
   `work.py check`.
2. `_FENCE` is ``^[ \t]*```` : it does not recognise a tilde fence (`~~~`), which Markdown also allows. A program inside a
   tilde fence is invisible to `fence_lengths`, and `body_sections` does not treat its `#` and `##` lines as fenced, so
   they are read as headings.

So a record can carry a fenced program of any length and pass. The tier 4 notes keep every fenced program closed with
backticks and within the cap until this is fixed (tier 4 instruction), so the hole is open but unused.

## The fix (root cause, not a patch)

One fence tracker, used by `body_sections` and `fence_lengths` alike (today each keeps its own toggle): it recognises
backtick and tilde fences of three or more characters, closes a fence only with the same character and at least the same
length (CommonMark), and reports a block still open at the end of the body as a block of its lines so far (or as its own
problem, `has an unclosed fence`). Add to `upstream_findings` a falsifying case for each hole (an unclosed 61-line block,
a 61-line tilde block, a tilde block holding a `## ` line) so the next variant of the fence syntax is caught by the self-test.
