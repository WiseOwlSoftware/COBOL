# PB1706 — LANDED

Filed by the train-70b lander from wave 70 group U's report (`w70u-PB1213-report.md`, new defect 2).

## Finding

**Repro.** `E:\Temp\claude\E--COBOL\73cac64c-391d-42c0-bcdf-c880e3e10305\scratchpad\w70u\p\rm99.cob`:
`RD R-1 CONTROLS ARE CX(1:99) CX(4:)` over `05 CX PIC X(6)` compiles with no diagnostic; at run time the major
control footing prints after the first detail line (`MAJ=010`). Wrong answer, silent.

**Rule.** `cite.py --check 8.4.3.3.4 "The sum of leftmost-position and length minus the value one shall be less than or
equal to the number of positions in the data item referenced by identifier-1"` → OK §8.4.3.3.4 5) c); the leftmost
position bound is §8.4.3.3.4 5) b). With literal operands the violation is known at compile time. The prior control
(§13.18.16.4 3): "an internal data item, known as a prior control, is implicitly defined, having the same data
description as the corresponding data item") has no well-formed description for an out-of-range subset.

**Code site.** `src/Cobol.Net.Compiler/Binding/DataBinder.Reports.cs` `ControlOperandRef` (about lines 3073–3100):
`sfx.Start` / `sfx.Length` are taken as written and never compared with the item's length. Same consumer as PB1579's
COBOLNET2427 arm (`RefModSuffixes.BeyondHostLimit`), which handles only literals beyond the host integer limit.
Sweep: every other bind-time consumer of a literal ref-mod (MOVE, DISPLAY operands) — whether each checks the literal
bounds against the item at bind time, as one rule.

## Landed (wave 1005 group A, 2026-10-03) - discharged: fixed earlier by PB1707 part 1, witness added

Re-probed on a fresh Debug build of e0e7878e1: `RD R-1 CONTROLS ARE CX(1:99) CX(4:)` over `CX PIC X(6)` is refused
`COBOLNET2670: RD 'R-1': CONTROL operand 'CX(1:99)': the reference modification (1:99) extends past the 6-position item
(ISO §8.4.3.3.4 5) c))`. The screen is the CONTROL-operand arm of `DataBinder.Reports.cs` `ResolveReports`
(`ReferenceResolver.LiteralRefModRangeViolation`), added by PB1707 part 1 (commit dee9483e1), which made the bind-time
literal range check ONE function shared with the procedure division. A TYPE CH/CF operand and a SUM ... RESET ON operand
must equal a CONTROL operand by written reference (`SameOperandAs`, §13.18.57.3 SR10 / §13.18.54.3 SR8), so an
out-of-range spelling there is refused as a non-operand (probed: `TYPE CF CX(1:99)` -> the SR10/SR11 refusal).

Sweep: the other consumers of `ReadOperandSuffixes` (SUM addend, UPON, clause operands) reject any ref-mod outright, and a
SOURCE ref-mod is the separate staged-loud `COBOLNET0899` stage (not this mechanism). The only gap was a witness:
PB1707's golden covers the procedure division only, so `conformance:negative/pb1706-control-refmod-out-of-range` now pins
the CONTROL arm. `cite.py --check 8.4.3.3.4 "The sum of leftmost-position and length minus the value one shall be less
than or equal to the number of positions in the data item referenced by identifier-1"` -> OK 5) c).
