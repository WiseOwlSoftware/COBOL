# PB6351 — no literal range screen on an intrinsic function result

**What.** `FUNCTION UPPER-CASE (A) (20:5)` where the result width is known (the catalog knows it for some functions, CURRENT-DATE being 21) applies no literal range screen. The only callers of `ScreenRefModLiterals` / `LiteralRefModRangeViolation` are `RefModBinder` (data references, `RefModOf`), the user-function arm and `ReportSectionBinder`.

**Site.** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs`, `ResultRefMod` (the `BoundIntrinsicCall` arm, near line 228). Its comment says the result size "is screened where it is known", which is false today; correct the comment with the fix.

**Same root as PB6304** (a reference-modified inline method invocation skips the count and range screens); the size source differs here: the function catalog, not a data item.
