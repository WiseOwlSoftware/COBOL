### Finding — `null-object-reference` (rejects-legal-source; rows `SR-8.4.3.7.3-2`, `FMT-8.4.3.7.2`)

**Mechanism.** NULL has no object-reference operand model: the binder represents it only as BoundFigurative('N'), classed Pointer, so it cannot serve as an INVOKE argument (identifier-5) or an INVOKE receiver

**Repro.** --std 2023 (also 2002). Class CN1 has an instance method TAKE with `LINKAGE SECTION. 01 P USAGE OBJECT REFERENCE CN1. PROCEDURE DIVISION USING P.` The caller has `01 G USAGE OBJECT REFERENCE CN1.` and runs `INVOKE CN1 "NEW" RETURNING G`, then one of: (a) `INVOKE G "TAKE" USING BY CONTENT NULL.` -> COBOLNET0828 "argument form for formal 'P' is not yet carried across a method activation"; (b) `INVOKE G "TAKE" USING BY VALUE NULL.` -> COBOL0001 unexpected '.'; (c) `INVOKE NULL "TAKE" USING G.` -> COBOLNET0823 "the predefined NULL object reference cannot be a receiver (ISO §14.9.23.3)". Probes in scratchpad/adj-d2/out/probe/null-object-reference/{p1,p3,n5}.cob.

**Expected from the spec.** §8.4.3.1.3 SR7 makes NULL an identifier (Format 6, predefined-object reference). §8.4.3.7.3 SR2 describes it as class object, category object reference. So (a) is legal: §14.9.23.2 BY CONTENT identifier-5, SR5a satisfied by the BY REFERENCE formal. It should compile, and TAKE should see P = NULL (it prints P-NULL). (b) is the same under BY VALUE and should parse. Binding it also needs a BY VALUE method formal, which PB1051 owns. (c) meets §14.9.23.3 SR1 ("Identifier-1 shall be an object reference"), and nothing in §14.9.23.3 excludes NULL, while §8.4.3.4.3 SR2 and §8.4.3.9.3 SR2 exclude it by name for inline invocation and object property. It should compile, and at run time §14.9.23.4 GR5 raises EC-OO-NULL (Fatal) and terminates the INVOKE.

**Observed / reasoning.** ExpressionBinder binds every NULL operand to BoundFigurative('N'). IntrinsicArgumentRules.CandidateClasses classifies it as [CobolClass.Pointer] (the §8.4.3.10 predefined address), never class object. OoBindInvocationArg has arms for identifiers, arithmetic/boolean expressions and alphanumeric/boolean/numeric literals, but none for a NULL object-reference value, so it falls to the trailing 'not yet carried' diagnostic. invokeArgument's BY VALUE arm (addressIdentifier | arithmeticExpression) has no NULL alternative. OoBindByReceiver rejects target.NULL_() outright, citing a §14.9.23.3 prohibition that does not exist (the cited clause answers a different question). What works: SET ... TO NULL and relation conditions, which have their own NULL paths. The sibling defect for the pointer reading (§8.4.3.10.3 SR1a: NULL as a method-invocation argument when the formal is a pointer) likely goes through the same arm and should be swept.

**Code site.** src/Cobol.Net.Compiler/Binding/Procedure/Verbs/OoBinder.cs#OoBindInvocationArg (trailing Err at ~l.933); OoBinder.cs#OoBindByReceiver ~l.286-291 (COBOLNET0823 on target.NULL_()); src/Cobol.Net.Frontend/Grammar/Core/CobolOO.g4#invokeArgument (BY VALUE arm); src/Cobol.Net.Compiler/Binding/IntrinsicArgumentRules.cs ~l.391 (BoundFigurative 'N' => Pointer)
