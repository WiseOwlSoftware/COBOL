# PB916 — OPEN — one usage, three statements about it that are false

Sources: the `PB511` report and the `PB511-finisher` report (items 2 and 3), plus the `PB399` report's
Table-2 lattice lead. All three are the MESSAGE-TAG surface and all three are in the same two files, so
they are ONE note and ONE fill unit.

## Arm 1 — the edition text contradicts the edition behaviour

`<scratch>/reg7/probe/i_msgtag.cob` (`01 M USAGE MESSAGE-TAG.`) at **`--std 2014`**:

```
i_msgtag.cob(5,8): error COBOLNET1943: data item 'M': USAGE MESSAGE-TAG: … MESSAGE-TAG is a COBOL-2023
addition (Annex E.2 item 25); below --std 2023 the word is a user-defined word and the entry draws the
ordinary introduction gate.
```

Byte-for-byte the same diagnostic as `--std 2023`. The message ends by telling the reader what happens
below 2023, and what happens below 2023 is the message. The Annex A.3 decline pre-empts the introduction
gate, so the edition axis never runs.

⛔ This is what holds the golden `pb544-message-tag-usage-exclusive` pinned at 2023 only, and it is why
PB544's landed COBOLNET2158 screen is deliberately edition-blind. Fixing it is what lets that golden take
the four-edition sweep `feedback_edition_gate_sweep` requires.

## Arm 2 — an inherited message-tag usage is reported as a floating-point usage

`<scratch>/reg7/probe/j_msgtag_group.cob`, `--std 2023`:

```
j_msgtag_group.cob(6,11): error COBOLNET1521: data item 'M': PICTURE may not be specified with a
floating-point usage (COMP-1/COMP-2/FLOAT-SHORT/-LONG/-EXTENDED/FLOAT-BINARY-*/FLOAT-DECIMAL-*) — a
floating-point item is picture-less (ISO §13.16.3 SR8; §13.18.60.2) — the usage is the one written for the
group item 'G' and applies to each elementary item in it (ISO §13.18.60.4 GR1)
```

`M`'s inherited usage is MESSAGE-TAG. The screen is RIGHT — §13.16.3 SR8 excludes message-tag by name, in
the same sentence as the floating-point usages —

> 8) The PICTURE clause shall not be specified for the subject of a RENAMES clause or for an item whose
> usage is binary-char, binary-short, binary-long, binary-double, float-short, float-long, float-extended,
> index, **message-tag**, object reference, pointer, function-pointer, or program-pointer. For any other
> entry describing an elementary item, a PICTURE clause shall be specified except as indicated in Syntax
> rule 9.

— and only its MESSAGE-TAG arm is unnamed in the text. The message hands the reader a list that does not
contain their usage and tells them their usage is in it. (Note the run also produces the correct
COBOLNET1724 for §13.18.60.3 SR14, so the entry is not under-rejected — this is purely which words the
user reads.)

```
$ python scripts/spec/cite.py --check 13.18.60.3 "message-tag"
OK  §13.18.60.3 4)  (Syntax rules)
    4) The INDEX, MESSAGE-TAG, OBJECT REFERENCE, POINTER, FUNCTION-POINTER, and PROGRAM-POINTER phrases
       shall not be specified in a data item described with the CONSTANT RECORD clause …
```

## Arm 3 — a stale justification that will read as a decision

`src/Cobol.Net.Compiler/Binding/IntrinsicArgumentRules.cs`, the `CobolClass.Index` member's remark, still
records message-tag as *"Table 2's other unexpressed class … has NO Usage member … so it gets no dead enum
member here"*. **`Usage.MessageTag` exists** (added by `kb/Work/PB487`). Nothing can reach the gap today
because `ParseUsage` refuses the word by name at every edition (arm 1 above), so the comment is inert — and
that is precisely the shape `feedback_a_dead_lookup_is_also_unverified` names: a justification nothing
contradicts, which will read as a considered decision the moment the usage lands.
