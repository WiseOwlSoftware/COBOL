# PB5768 - the declarative exemption of the 85 RELEASE/RETURN range gate is too wide

**Sites:**
- `src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs:196` (`VersionConformancePass.GateReleaseReturnRange`:
  `if (pc < prog.EntryPc && range.Count > 0) continue;`)
- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/ProcedureReach.cs` (`ProcedureReach.Closure`: the range closure the new
  question reads)
- `docs/conformance/3/D-SORT-RELEASE-RETURN-RANGE-85.md` (whole: the determination states the run-time-fact reason the
  exemption rests on)
- `src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs#DeclarativeExecutableFromRange` and `#UseTriggeringFiles` (the fix)

**Rule.** §1985:XI.4.3.3 SR3: "A RETURN statement may only be used within the range of an output procedure associated
with a SORT or MERGE statement for file-name-1"; §1985:XI.4.2.3 SR2: "A RELEASE statement may be used only within the
range of an input procedure associated with a SORT statement" (both `cite.py --check` OK). The range includes
"all statements in declarative procedures that are executed as a result of the execution of statements in the range of
the output procedure" (§1985:XI.4.4.4 GR10; the same words for the input procedure in GR7; both OK). So a declarative
statement is in the range only if some statement of the range can cause that declarative to execute.

**What PB5572 fixed, and why this arm escaped.** PB5572 (landed, wave 20262040) made the gate ask a RELEASE or RETURN
written in the declaratives at all: "Ask a declarative RELEASE or RETURN in `GateReleaseReturnRange` too, against the one
fact that is decidable at compile time: whether any input (output) procedure for its file exists from which a
declarative could be executed. Keep the run-time latitude where one exists." So where no range exists the statement is
refused (COBOL7081), and where one exists it is exempted wholesale. A second fact is decidable too: whether the range's
closure contains ANY statement able to cause the declarative to run (an input-output statement on a file the USE
covers, a CALL, or a debugging or report-writer trigger). Where it contains none, the declarative can run only from
outside the range, and the statement is outside every range at compile time.

**Repro** (re-run 2026-11-15 on this branch's build, `registrar-1985-reread/log-misc.txt`):

- `E:/COBOL-coord/scratch/op-20261115/open-rows-1985/refute-b/t13.cob`: a SORT with INPUT PROCEDURE IN-P (MOVE, RELEASE)
  and OUTPUT PROCEDURE OUT-P (RETURN, DISPLAY, GO TO within OUT-P, EXIT): no input-output statement, no CALL. The
  declarative `USE AFTER STANDARD ERROR PROCEDURE ON F` holds `RETURN SA AT END DISPLAY "T13 DECL END"`; after the SORT
  the main line runs `OPEN INPUT F` on a missing file. At `--std 85`: exit 0, no diagnostic; it prints
  `T13 ZZZ | T13 DECL END | T13 FS 35`: the declarative RETURN executes after the SORT ended and silently takes AT END.
- `refute-b/t14.cob`: the same with `MOVE "DDD" TO RA. RELEASE RA.` in the declarative: exit 0, no diagnostic,
  `T14 ZZZ | T14 DECL | T14 FS 35`.

**Expected:** COBOL7081 for each (the statement is outside every range), as for a declarative RELEASE/RETURN in a program
with no range (`pb5572-release-in-declarative-no-input-procedure-85`, `pb5572-return-in-declarative-no-output-procedure-85`).
**Actual:** accepted, and the statement runs with no sort in progress. Harm: under-rejects; at run time a RETURN takes AT
END silently.

**Counter-reading, for the fix to weigh.** §1985:I.1.6: "The results of violating the formats or rules of Standard COBOL
are undefined" (`cite.py --check` OK), so accepting a violation is not by itself a non-conformance; but the project
refuses every statically known SR2/SR3 violation (COBOL7081 for the main line and PB5572's no-range case), and t13 and t14
are statically known.

**Fix direction (root).** Replace the wholesale exemption with the question GR7/GR10 ask: exempt a declarative statement
only when the range's closure holds a statement that can raise a condition the declarative's USE covers (an input-output
statement on a covered file, including the SORT's own USING/GIVING files where the range reaches them, a CALL, or a
debugging or report-writer trigger), and refuse it otherwise. Update the determination file above in the same change.
Tests (I11): the refused t13/t14 shapes at 85, the accepted shape where the range holds an I-O statement on the covered
file (`pb5572_release_in_declarative_of_input_procedure_85` is one), and a CALL-bearing range.
