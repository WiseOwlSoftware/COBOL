# PB5347 - the four hand-written integer-date conversions of CobolDate (400-year-cycle arithmetic replacing System.DateTime) have no unit test pinning them against a reference over 1..3,067,671

**Sites:**

- `src/WiseOwl.Cobol.Runtime/Intrinsics/CobolDate.cs` (`CobolDate.YearAndDayOf`, `CobolDate.DaysBeforeYear`, `CobolDate.DaysBefore`)

**Finding.** CobolDate.cs:343 and its helpers replaced `System.DateTime` with hand-written 400-year-cycle arithmetic (`YearAndDayOf`, `DaysBeforeYear`, `DaysBefore`), and no unit test pins it against `DateTime` over 1..3,067,671; only spot values (the year-10000 golden, NIST dates) cover it. The reviewer ran the algorithm against Python `datetime` over every day 1..3,067,671 with 0 mismatches (E:/COBOL-coord/scratch/review-w20262001-a/date_probe.py), so the code is right today; the gap is the missing guard.

**Fix direction.** A unit test that compares `DateOfInteger`/`IntegerOfDate`/`DayOfInteger`/`IntegerOfDay` with `System.DateTime` for every integer date 1..3,067,671 (the range where `DateTime` exists), plus the 400-year cycle edges beyond 9999. The reference is `DateTime` / §2023:15.5.2's Gregorian rules, not the code's output.

**Source.** Review lead R1-2, low, not blocking at round 1.
