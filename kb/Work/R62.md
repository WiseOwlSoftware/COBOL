# R62 — WORKING-STORAGE in a method (researched 2026-09-30)

**Question.** §13.5.3 SR1 (2023): the working-storage section "may be specified only in a factory definition or an instance definition, but not in a method definition". The compiler gates that only at 2023; --std 2002/2014 accept a method's WORKING-STORAGE silently (class-static semantics).

**Evidence.** Micro Focus Visual COBOL documentation (Working-Storage Section; whose OO model follows ISO 2002 and predates the 2023 text): "In class definitions, the Working-Storage Section must be specified only in a factory definition or an instance definition, but not in a method definition" — the same words as 2023 SR1, in documentation written for earlier editions. IBM Enterprise COBOL documents LOCAL-STORAGE (allocated per invocation) as the method-level storage. Annex E.2 (2014->2023) does NOT list a removal of method WORKING-STORAGE, while it does list EXIT METHOD's, which is the evidence the ban predates 2023 (PB1308 option (a)). GnuCOBOL has no OO to consult.

**Determination (owner accepts the research).** The method exclusion is original text: a method's WORKING-STORAGE is rejected at **every** edition. VCR row 130e becomes a normal rejection (no 2023-only window), `OoSpineTests.MethodWorkingStorage_StaticSemantics_EditionWindow` (which pins the 2002 acceptance) is re-derived. **Confidence:** medium-high (two vendor documents plus the Annex E.2 silence; the ISO 2002/2014 texts were not obtained).
