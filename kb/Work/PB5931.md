# PB5931 - a listing test asserted host path length

**Found by.** Merge-group run 44341572782 (PR #1864), Windows shard 7/7:
`ListingDiagnosticsTests.ABindError_IsPlacedOnItsLine_InlineAndInTheSummary_WithTheRuleItCites` (line 85) failed with
`Not found: "     5  error COBOL0801 C:\\Users\\runnerad"...`. PB4950 only made the merge group run it on Windows.

**Mechanism.** `TextListingRenderer.SummaryRows` wraps each entry with `Indented(..., 0, 8, width)` at the page width, 132.
The entry is `line  error CODE <source path>(line,col): message`. `Indented` breaks at the last space in the window, else cuts. On
the runner the scratch path (`C:\Users\runneradmin\AppData\Local\Temp\wiseowl-cobol-tests\<pid>-<id>\listingdiagxxxx\diag1.cob`)
is long enough that the path no longer fits after `error COBOL0801 `, so the renderer breaks at that space and the path
starts the next row (indented 8). The test asserted `"     5  error COBOL0801 <path>(5,8): "` as one substring, true
only where the path is short. The wrap is the designed behavior (section 6.3: "wrapped"); the defect is the assertion.

**Reproduced.** The old assertion, run in a directory whose path is 160 characters, failed with `Not found: "     5  error
COBOL0801 E:\\Temp\\wiseowl-c"...`, and passed in the short one (this host, 2026-11-18).

**Sites:**
- `tests/WiseOwl.Cobol.Tests.Conformance/Listing/ListingDiagnosticsTests.cs` `ABindError_IsPlacedOnItsLine_InlineAndInTheSummary_WithTheRuleItCites`

**Fix.** The test is a Theory run at a short directory and at `LongDirectory()` (a path padded to the page width plus 28, so the
entry always wraps and the path is itself cut). It reads the entry as the row that opens it plus the rows indented 8 under it
and asserts: no row is wider than the page; the rows hold exactly the entry's words in order (spaces removed, so a break at a
space and a cut of a word no space lets fit read alike); they equal `TextListingRenderer.Indented(entry, 0, 8, 132)`; and, in
the long case, the entry spans several rows. The expected entry text is built from the record's own fields, not read off the listing.
The renderer needed no change: a word longer than the window is cut by design ("broken at a space where one is, else cut").

**Guard.** The long-path Theory case is the guard: it makes every host behave like the runner. A change to
`ScratchDirectory` to lengthen every scratch path was not made: it would put every test of the suite near Windows path limits to
protect assertions that need it only in the listing, and the sweep below found the one site.

**Sweep (every test that asserts rendered listing text, `.lst` content, a summary or banner, or a host path).**
Unsafe: only the site above. Already safe, checked:
- `ListingDiagnosticsTests` lines on the arrow row (start of row only), the caret row, the `Errors:` counts line, `DIAGNOSTICS` heading.
- `Listing1985Tests`: source lines contained in the text (source text, wrapped by column, not by path), page-heading line 1
  (`(--std 85)  OUTER85  ` and the instant: line 1 never exceeds the page width and its fields yield in a fixed order, the path is on line 2), `DIAGNOSTICS` page.
- `Listing2023Tests`, `Listing2002Tests`, `Listing2014Tests`, `ListingHookCases`: rows found by `EndsWith` the source line's text, the `>>LISTING` rows, `COPY SUPPBOOK SUPPRESS.`, the instant in row 0.
- `ListingJsonTests`, `ListingOutcomeTests`: paths asserted in `result.OutputFiles` and in the compiler's error strings (`cannot write the listing '<path>'`), not in rendered listing rows.
- `ListingCliTests`: `Contains("PROGRAM-ID. ...")` in the `.lst`.
- `TextListingRendererTests` (`ALongPath_NeverWidensARow`, `ALongMessage_WrapsUnderItself_...`): synthetic documents with fixed paths and widths.
- `ListingOffDoesNoWorkDriftTests`, `BoundDeferralDriftTests`, `StatementDeferralAnnounceDriftTests`, `CompiledProgramCache*`: no assertion on listing text.
