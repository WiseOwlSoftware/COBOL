# PB3818 — a golden comment cites a negative golden that was never written

**Sites:** `conformance-suite/cases/13.18.60-USAGE/pb817_restricted_program_pointer.cob` (line 26,
"negative pb935-set-entry-restricted-program-pointer").

## Measured

On origin/main 33e3dcf21, `ls conformance-suite/cases/*/pb935*` lists only
`14.9.39-SET/pb935-set-entry-restricted-identifier-list.cob` and `14.9.39-SET/pb935-set-entry-restricted-literal.cob`. The
pb817 header (rewritten by PB935) names a third, `pb935-set-entry-restricted-program-pointer`, for the SET … TO ENTRY of an
unrestricted program-pointer into a restricted receiver (GR25).

## Acceptance

- Either the missing negative golden exists (SET restricted-PP TO ENTRY <unrestricted program-pointer>, refused per
  §13.18.60.4 GR25, expected output from the spec, citation run through `cite.py --check`) or the header names the two
  goldens that do exist. Prefer writing the golden if PB935's refusal covers that source form; confirm by compiling it.
- Sweep: every golden header that names another golden by id resolves to a file (a drift test if none exists).
- Land with PB3817's INITIALIZE golden if the same implementer takes both.
