# PB57 — CLOSED STALE — the defect was real when the adjudication note read the path, and R21 (`43da1c9d`) fixed it before this note was filed

### ✅ CLOSED ON A PROBE 2026-08-09 (the R09 shape — a note's word is not evidence, in EITHER direction)

> `CobolDate.cs:44` is `CurrentDate() => Format21(RunUnit.Current.Clock.Now())` — R21's commit message
> even says "the last two direct reads die", and this was one of the two. **Probed, not deduced:** under
> `COBOLNET_CLOCK=1999-12-31T23:59:59+00:00`, `CURRENT-DATE` returns `1999123123595900+0000` (the pin, with
> correct offset digits) and the §15.100.3 r5 identity holds — `YEAR-TO-YYYY(50)` defaulted and
> `YEAR-TO-YYYY(50, 10, NUMVAL(CURRENT-DATE(1:4)))` spelled out both return 1950. The only remaining
> `DateTimeOffset.Now` in the runtime is `SystemClock`'s own default (`Clock.cs:38`), which IS the seam.
> **The filing inherited the RV-15.21.3-1 adjudication note's PATH READ, which predates R21's landing —
> the premise-failure pattern's 15th instance, this time mine: I filed from a note without re-probing the
> current tree.** The RV-15.21.3-1 note's stale seam claim gets corrected at its next re-verdict (its
> +14:00 half remains the open NEEDS-OWNER-DECISION).
> Residue worth keeping: the r5-identity conformance golden this note proposed is still worth shipping
> with the CURRENT-DATE row's eventual closure — the probe program is the golden, minus the pin plumbing.

> ⚙ **flags:** wrong-answer (pinned-clock runs only), silent

> **Recorded in the RV-15.21.3-1 adjudication note and in `CobolDate.cs`'s own doc comment ("NOT the
> CurrentDate direct-DateTimeOffset.Now path, which predates the seam") — i.e. prose-ledgered where no work
> list could see it, which is why this note exists (CLAUDE.md rule 8).**
>
> **THE DEFECT.** R21 landed the ONE injectable `DateTimeOffset` clock seam (`RunUnit.Current.Clock`);
> SECONDS-PAST-MIDNIGHT, YEAR-TO-YYYY and the windowing family read it. `CobolDate.CurrentDate()` still
> reads `DateTimeOffset.Now` directly (`Format21(DateTimeOffset.Now)`). Under a pinned clock
> (`COBOLNET_CLOCK`), a program observes CURRENT-DATE disagreeing with SECONDS-PAST-MIDNIGHT — and
> **§15.100.3 r5 DEFINES YEAR-TO-YYYY's argument-3 default as
> `FUNCTION NUMVAL(FUNCTION CURRENT-DATE(1:4))`** — an identity the seam split breaks: the defaulted form
> and the spelled-out form return different years across a New-Year boundary pin.
>
> **THE FIX** is the R21 shape: route `CurrentDate()` through `RunUnit.Current.Clock` (one call-site
> change), and the `NowFunctions_OnePinnedClock_OneInstant` unit test extends to assert CURRENT-DATE is on
> the same instant as the rest of the now-family. WHEN-COMPILED is unaffected (compile-time constant).
> **Sweep:** grep `DateTimeOffset.Now` / `DateTime.Now` across `src/Cobol.Net.Runtime` — any OTHER direct
> read outside the seam is the same defect (the two-mechanisms anti-pattern).
> Fix lands with: the extended unit test + a conformance golden pinning the §15.100.3 r5 identity under
> COBOLNET_CLOCK, and the RV-15.21.3-1 row's note updated (its +14:00 half stays NEEDS-OWNER-DECISION).
