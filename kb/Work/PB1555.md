# PB1555

Raised 2026-09-24 by the golden-lane-2 misc-p25 writer (it could not derive an indexed expectation for REWRITE GR13 —
file position unaffected — so the golden covers sequential and relative files only). The misc-p25 refuter rendered
PDF page 728 (printed folio 698): e)1. reads "whose key value is greater than or equal to the key value in the file
position indicator", and `specs/ISO_COBOL.md` matches word for word — NOT a transcription defect; the tension with
e)3.'s "greater than" is in the printed standard.

To decide: (1) which record a READ NEXT returns on an indexed file in each GR21 d)/e) arm, from the rule structure
(which arm is reached after START / random READ / a prior sequential READ); (2) whether "the previous operation on the
file" includes REWRITE (GR21 d)); (3) what `src/Cobol.Net.Runtime` does today and whether an existing golden pins it.
Then an indexed leg of REWRITE GR13 (§14.9.35.4) can be written. Survey GnuCOBOL / IBM on the latitude if the text
does not settle it (CLAUDE.md rule 1 precedence).

**Now blocks a witness (golden lane #2 misc-p37 refuter):** GR-14.9.51.4-34's golden `85/l1c37_indexed_every_key_path`
walks READ NEXT after a successful READ on each key path — GR21 e) governs, and under e)1. read literally ('>= the FPI')
the same record is returned again. The golden is held until this analysis decides e)1. vs e)3. (a rewrite using random
READ KEY IS or one START + one READ NEXT would avoid the arm; the lane may take that route instead).

## LANDED 2026-09-30 (R66) - answer

e)1 prints `greater than or equal to` and e)2 `less than or equal to` for a READ after a successful READ; meant: `greater than` / `less than` (Addendum C12, printed page 698, marked edit). Evidence: GR21 g) sets the FPI to the key of the record just returned, so `>=` would return it again forever; the `or equal to` arm belongs to d) (after OPEN/START); f) is strict both ways; GnuCOBOL 3.2 `libcob/fileio.c` `indexed_read_next` (BDB) does DB_SET_RANGE on the last key read and steps one further when it finds the same key. e)3's closing `Otherwise` sentence is left as printed (D4). REWRITE does not count as "the previous operation": §14.9.35.4 GR13 says the FPI is not affected by REWRITE and d)/e) read the FPI; GnuCOBOL's indexed_rewrite leaves last-read-key state alone; `IndexedConnector._positioner` is set only by OPEN/START/READ. The indexed leg of REWRITE GR13 and golden `85/l1c37_indexed_every_key_path` are unblocked.
