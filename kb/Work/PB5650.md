# PB5650 - a locale-edited picture with no currency symbol still gets the locale's sep_by_space space

**Site (lead, from the writer, not re-read by the integrator):** `src/WiseOwl.Cobol.Runtime/Globalization/MonetaryPlacement.cs#Render`:
`sp1 = c.SepBySpace == 1 ? " " : ""` is added whether or not the currency string `cs` is empty, so a cs-follows locale
(de-DE) gets `value + " " + ""` and a sign-before locale (pt-BR, nl-NL) gets `sign + "" + " " + value`.

**Rules (each checked with `python scripts/spec/cite.py --check`, verdict OK).**

- `§2002:13.16.38.3 GR17`: "The currency symbol indicates that the item is to include a currency string in accordance with the specifications in the locale" - with no currency symbol in the picture there is no currency string, so no currency-to-value separation either.
- `§2002:13.16.38.4 GR14`: "the data is right justified, with space fill for the leftmost character positions"
- `§2002:13.16.38.4 GR13` (the '+' sign placed as the locale specifies): the writer's discriminating legs are nl-NL positive and hr-HR U+2212.

**Repro 1** (`E:/COBOL-coord/scratch/gl2002/lane1/out/g2002-13-16-38-picture/defects/defect-g2locsp.cob`; `cobol.exe defect-g2locsp.cob --std 2002 --run`, `COBOL_USER_LOCALE=INVARIANT`):

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. G2LOCSP.
       ENVIRONMENT DIVISION.
       CONFIGURATION SECTION.
       SPECIAL-NAMES.
           LOCALE GER IS "de-DE"
           LOCALE BRA IS "pt-BR".
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 L5 PIC ZZZZZZ9.99 LOCALE IS GER SIZE IS 14.
       01 L7 PIC +ZZZ9.99 LOCALE IS BRA SIZE IS 14.
       PROCEDURE DIVISION.
           MOVE 1234567.89 TO L5
           MOVE -1234.5 TO L7
           DISPLAY "L5=[" L5 "] L7=[" L7 "]"
           STOP RUN.
```

Expected: `L5=[  1.234.567,89] L7=[     -1.234,50]`. Observed (main b15bb9088f, this note's re-probe): `L5=[ 1.234.567,89 ] L7=[    - 1.234,50]`.

**Repro 2** (`.../defects/defect-g2sign13.cob`): `PIC +ZZZ9.99 LOCALE ... SIZE IS 14` in nl-NL (+1234.5, -1234.5), hr-HR, de-CH and
en-US (+1234.5). Expected `P1=[     +1.234,50]` and P3 a leading U+2212 with no trailing space. Observed:
`P1=[    + 1.234,50] P2=[     -1.234,50] P3=[    −1.234,50 ]` / `P4=[     -1’234.50] P5=[     +1,234.50]`.

**Rows.** 2002-GR-13.16.38.4-13 (held, no golden) and 2002-GR-13.16.38.4-14: its en-US golden
`g2-pic38-cd-categories-locale` landed in golden-2002-1, but its CONFORMS record was held back because repro 1 violates
GR14 a) in de-DE and pt-BR. After the fix, close both with a nl-NL positive leg, a U+2212 leg and the repro-1 legs.

**Sibling sweep (to do in the fix).** Every arm of `MonetaryPlacement.Render` that adds a separator next to an empty
currency string (sep_by_space 1 and 2, cs_precedes 0 and 1, sign positions 0 to 4); the 2023 twin rules (§2023 PICTURE
editing rules) share the runtime, so 2023 is affected the same way.
