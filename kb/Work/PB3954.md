# PB3954 — CobolDec.Div pads an EXACT quotient to 34 digits: DISPLAY FUNCTION MEAN(1 2 3) prints 2.000000000000000000000000000000000

**Sites:** `src/WiseOwl.Cobol.Runtime/Values/Numeric/CobolDec.cs` (`CobolDec.Div`, `Round34Wide`)

`CobolDec.Div` pads an exact quotient to 34 digits instead of reducing it toward the IEEE 754 preferred exponent (ISO
§8.8.1.5.3 defers to 60559:2020 5.4.1), so `DISPLAY FUNCTION MEAN(1 2 3)` prints `2.000000000000000000000000000000000` under
native and standard arithmetic alike. Harm per the report: cosmetic output on every DISPLAY of an SDIDI quotient; MAJOR for
goldens that print one. Repro `E:/COBOL-coord/scratch/op/w-pb3852-g/w20261717a/p/i.cob`. Not fixed in PB3860 because many
goldens read the representation. The citation §8.8.1.5.3 is the report's; the "preferred exponent" wording was not found in
that clause by `cite.py --check`, so the adjudication must re-derive it before it is written into a golden.

## Acceptance
- Derive the exact-quotient exponent rule from the spec, make `Div` (and its `Round34Wide` caller) hold an exact quotient
  at the preferred exponent, update every golden that printed the padded form in the same change, sweep the other SDIDI
  operations (sum, product) for the same padding.
