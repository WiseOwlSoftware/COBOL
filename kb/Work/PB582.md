# PB582 — OPEN — the verdict is right, the reason printed is not the governing rule

Found 2026-09-04 by the `PB206` implementer, which routed the group subject through the same screen and left this
arm alone deliberately: correcting it selects the rule by the RECEIVER's category, a small dispatch of its own.
Re-derived on this tree for this note.

## The mechanism

`src/Cobol.Net.Compiler/Binding/DataBinder.cs`, `ValidateValueCategory`, the arm
`case not (PicCategory.National or PicCategory.Boolean) when isNatLit || isBoolLit` reports *"a national (N"…") /
boolean (B"…") literal may seed only a data item of its own category (ISO §13.18.63 SR5/SR10)"*.

```
python scripts/spec/cite.py --check 13.18.63.3 "If the item is of category alphabetic, alphanumeric, or alphanumeric-edited literals in the VALUE clause shall be alphanumeric literals."
OK  §13.18.63.3 4)
python scripts/spec/cite.py --check 13.18.63.3 "If the category of the subject of the entry is numeric, all literals in the VALUE clause shall be numeric"
OK  §13.18.63.3 2)
```

SR5 and SR10 constrain what a NATIONAL / BOOLEAN subject may carry. The rule that forbids `01 GA PIC X(4) VALUE
N"AB".` is SR4 sentence 1 (an alphanumeric subject takes alphanumeric literals); for `01 N PIC 99 VALUE B"1".` it
is SR2. The rejection is correct; the citation printed to the user — and inherited into any golden `.err` that
quotes it — names the wrong rule. This is `feedback_a_real_clause_can_answer_a_different_question` in a
diagnostic's text.

## Fix shape

Select the cited rule by the receiver's category in that arm (alphabetic/alphanumeric/alphanumeric-edited → SR4
s.1; numeric/numeric-edited → SR2; boolean → SR10 s.1; national → SR5 s.1), through the same per-category table
the size arms now use (the `ValueSubject` descriptor's `SizePositions` — PB206's shape as PB598
restructured it), so the category-to-rule mapping exists once. Update the
`DiagnosticCatalog` descriptor text and regenerate `docs/DIAGNOSTICS.md`; re-derive every negative golden whose
`.err` quotes the old rule text (grep `SR5/SR10` under `tests/conformance/negative/`).
