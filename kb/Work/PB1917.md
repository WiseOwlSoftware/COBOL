# PB1917 — a fix arm without its witness

Filed by the train-1003 lander from wave 1003 group B's report (`w1003b-PB1140-report.md`, self-review gap 2).

## Finding

PB1140 routes the short-record fill of both SORT and MERGE USING transfers through one emitter method
(`src/Cobol.Net.Compiler/CodeGen/Verbs/SortEmitter.cs#EmitInputFile`, the fixed-SD arm calling `CobolSort.FillTo` with
`FileModel.ShortRecordFillNational`). The SORT legs of `conformance-suite/cases/14.9.24-MERGE/pb1140_sort_merge_short_record_fill.cob`
execute it; the MERGE leg (M1) uses a variable-length SD, so the MERGE USING arm with a fixed SD and a national-record
USING file never runs.

## What the fixer owes

A MERGE leg in that golden (or a sibling) with a fixed-length merge file whose USING file's one record description is a
national data item shorter than the merge record, reading the merged record's bytes back (ORD) to show the national
space fill.

Owner 2026-10-17: addressed in the SORT and file I/O campaign (kb/Work PB3353).

## Landed (wave 1126 H)

Re-probed on the w1126h build (base 6e2244f3d), program `E:\COBOL-coord\scratch\w1126h\p\pb1917.cob`: the MERGE USING arm with
a FIXED SD already fills correctly, so the defect was the missing witness only. A national record N(2) and an elementary
usage-national numeric item fill 00 20 (GR2 a); an X(4) record and a two-description national/alphanumeric USING file fill
20 20 (GR2 c); an OUTPUT PROCEDURE RETURNs the already-filled record; a missing second USING file ends the MERGE at its
implicit OPEN (status 35 with a FILE STATUS clause, GR7 a) and leaves the GIVING file unopened.

Golden `conformance-suite/cases/14.9.24-MERGE/pb1917_merge_fixed_sd_short_record_fill` (accept 2002; the expected bytes are
derived from GR2 a) and c), not from a run). No negative: it adds no syntax and no edition gate (national usage below 2002
is refused by the existing edition tests).
