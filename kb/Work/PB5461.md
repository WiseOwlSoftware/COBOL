# PB5461 - no form on main pins a warning on an accepted program

**What the design says.** `docs/rearchitecture/DESIGN-conformance-suite.md` §3.2 (lines 271-280, 17f) puts a flagged
test in `<file>.flagged.jsonl` (`kind: syntax`), derived from its control, and judges it PASS when the compiler reports
a diagnostic at the site, warning or error alike (lines 219-222). Its WiseOwl layer (lines 296-301, 17j) is
`wiseowl/diagnostics/<file>.jsonl`, whose `at` entries carry `"severity": "error" | "warning"`, and "where the test is
also accepted, compares output". S6 (line 922, PB4686) is the step that builds them.

**What main reads.**
- A flagged test is its own `.cob` with `flag: {kind, at}`, `control:` and a `<<` mark
  (`conformance-suite/harness/generate.py#Reader._flag`, `#_check_flag`; the one on main is
  `cases/14.9.8-COMPUTE/compute-alphanumeric-receiver.cob`). `generate.py#check_cases` (lines 914-917) refuses any
  flagged test without `wiseowl/diagnostics/<id>.json`: "a flagged test needs a file wiseowl/diagnostics/<id>.json: the
  editions at which WiseOwl COBOL refuses it and what it reports".
- `wiseowl/diagnostics/<id>.json` is `{"refuse-at": [...], "expect": "..."}` (`generate.py#check_cases`, lines 865-885,
  which also refuses an entry at an edition where the test is accepted), read into `SuiteRefusal`
  (`tests/_shared/SuiteManifest.cs#WiseOwlManifest.Parse`), and
  `ConformanceSuiteTestsBase.WiseOwlRefusal_RefusesTheSourceWithItsDiagnostic` requires `FrontendError` or `BindError`.
- So a program WiseOwl compiles with a warning can be neither a flagged test (its refusal pin would fail) nor a
  WiseOwl-layer pin. The flagged runner itself (`ConformanceSuiteRunner.Flagged`, `DiagnosticLines`) would pass on a
  warning: only the generator's coupling of "flagged" to "refused" stands in the way.

**Repro.** A flagged twin of `cases/XV.3.2@1985-USE-FOR-DEBUGGING-STATEMENT/1985-GR-XV_3_2_4-1` (`flag: {kind: syntax,
at: [85]}`, `control: 1985-GR-XV_3_2_4-1`, the line `PERFORM ERR-PARA.` marked `<<` and changed to `PERFORM
MAIN-PARA.`): `python conformance-suite/harness/generate.py --check` printed "REFUSED ...probe-sr2-flag.cob:1: a flagged
test needs a file wiseowl/diagnostics/<id>.json ..." and "RED — 1 refusal(s)" (2026-11-13). The compiler, at
`--std 85`, exits 0 on it with `warning COBOL2375` at the PERFORM's line.

**The fix** is S6's: the design's `.flagged.jsonl` and the `wiseowl/diagnostics/<file>.jsonl` layer with a severity, so
a flagged test stands on its site alone and a warning is pinned beside an accepted output. It is not bent here: no
refusal is pinned for a program WiseOwl accepts (kb/Work PB4995 decision 2026-11-12). When it lands, these five pins are
placed from the table above.
