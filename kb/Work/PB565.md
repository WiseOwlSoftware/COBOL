# PB565

## Mechanism — value-clause-p4
An OCCURS clause in a report group description is refused by name (COBOLNET0899, 'OCCURS in a report group description (ISO 13.18.38 repeating entries) is not yet implemented'), which is legal COBOL rejected. Two rules in this part depend on that vehicle and are therefore unreachable rather than merely untested: 13.18.63.4 GR21 imports GR9 ('A VALUE clause specified in a data description entry that contains an OCCURS clause ... causes every occurrence ... to be assigned the specified value') into Format 4, and GR22's exception list names 'an OCCURS clause with the DEPENDING phrase' as one of the three clauses that may suppress a printable item. No open kb/Work note visible in this subject's dossier owns the report-group OCCURS refusal; the multiple LINE clause beside it is staged loud the same way (DataBinder.Reports.cs:354-358, COBOLNET ReportMultipleLine), so the repeating-entry family in the report section rests on the multiple COLUMN clause alone. Registering it matters because the loud stage currently reads as a decision: a green corpus over multiple-COLUMN-only report groups cannot see that two general rules have empty populations.

### Expected, from the standard
13.18.38 admits an OCCURS clause in a report group description (a repeating entry), 13.18.63.4 GR21 makes GR9 apply to it, and GR22 names OCCURS ... DEPENDING as a suppressor of a printable item's appearance. The entry is conforming source and must compile.
