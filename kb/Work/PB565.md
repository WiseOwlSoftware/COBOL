# PB565

## Mechanism — value-clause-p4
An OCCURS clause in a report group description is refused by name (COBOLNET0899, 'OCCURS in a report group description (ISO 13.18.38 repeating entries) is not yet implemented'), which is legal COBOL rejected. Two rules in this part depend on that vehicle and are therefore unreachable rather than merely untested: 13.18.63.4 GR21 imports GR9 ('A VALUE clause specified in a data description entry that contains an OCCURS clause ... causes every occurrence ... to be assigned the specified value') into Format 4, and GR22 — 'except that a GROUP INDICATE, PRESENT WHEN, or OCCURS clause with the DEPENDING phrase may suppress the appearance of the item' (the adjudicator's near-quote here was repaired to the verbatim sentence on landing; `cite.py --check` now passes on it). No open kb/Work note visible in this subject's dossier owns the report-group OCCURS refusal; the multiple LINE clause beside it is staged loud the same way (DataBinder.Reports.cs:354-358, COBOLNET ReportMultipleLine), so the repeating-entry family in the report section rests on the multiple COLUMN clause alone. Registering it matters because the loud stage currently reads as a decision: a green corpus over multiple-COLUMN-only report groups cannot see that two general rules have empty populations.

### Expected, from the standard
13.18.38 admits an OCCURS clause in a report group description (a repeating entry), 13.18.63.4 GR21 makes GR9 apply to it, and GR22 names OCCURS ... DEPENDING as a suppressor of a printable item's appearance. The entry is conforming source and must compile.

## Landed — 2026-09-21, the VERTICAL repetition axis (wave 43 A)

RE-PROBED FIRST on this worktree's own build (merged predecessor branch at 3942ea157, `dotnet build
CobolSharp.sln -c Debug` 0/0): the refusal still reproduced — `03 LINE PLUS 1 OCCURS 3 TIMES.` over a
`05 COLUMN 1 PIC X(3) SOURCE WS-A` drew `error COBOLNET0899` naming the vertical axis.

⛔ AND THE FIRST RE-PROBE FOUND A SECOND DEFECT IN THE HORIZONTAL LANDING. With the 0899 lifted, the same
program was REFUSED AGAIN, by COBOLNET2021: §13.18.38.3 SR25c/SR25d had been read as ONE subtree scan for an
absolute COLUMN clause. The rule does not say that. c) is "contains an absolute COLUMN clause" — the entry's
OWN clause — and d) adds the qualifier §13.18.38.4 GR10b/GR12b carry, "being itself subordinate to an entry
with a LINE clause". A
vertically repeating entry whose repetitions are spread by its LINE clause and whose column is the same in each
is GR10c, and it was being rejected. Fixed leg by leg (`AbsoluteLineClauseIn` / `AbsoluteColumnClauseIn` /
`SubordinateToLineClause`); a/b (the absolute LINE legs) went live at the same time.

WHAT LANDED.

- **THE AXIS IS A FIELD, NOT A TEST AT EACH SITE** — `ReportOccursSpec.Axis`. §13.18.38.4 GR10a/GR10b and
  GR12a/GR12b are the COLUMN arms, GR10c/GR10d and GR12c/GR12d the LINE arms, so the same integer-3 is a
  horizontal interval on one entry and a vertical one on another. An entry that contains, or has subordinate to
  it, a LINE clause repeats VERTICALLY; everything else horizontally. `ReportGroupBuild.Shift(axis)` and
  `Undisplaced(axis)` are the only readers of a frame's STEP, pinned by
  `ReportRepeatingEntryDriftTests.TheStepDisplacement_IsReadThroughTheAxis`.
- **THE MULTIPLE LINE CLAUSE IS THE SAME REPLAY**, because §13.18.35.4 GR9 says it is: "functionally
  equivalent to a LINE clause with a single operand, together with a simple OCCURS clause whose integer is equal
  to the number of operands of the LINE clause". `ReportRepetitionOf` builds exactly that — a simple,
  STEP-less, vertical `ReportOccursSpec` — and the repetition ORDINAL selects the LINE operand. Modelling it
  as a second repetition mechanism would have been the duplication rule 8 and `one_mechanism_per_job` forbid;
  the standard's own reduction was available and is what shipped.
- **Placement** — `RepeatedLine`, the twin of `RepeatedPlacements`. An absolute line displaces to
  integer-1 + Σ ordinal × integer-3 and stays a compile-time constant (SR25a/SR25b guarantee integer-3 exists
  there). A relative line has no compile-time page line, so its first occurrence SEEDS an engine-held anchor
  (`ReportGroupLine.Anchor`, cleared per presentation) with the line it lands on and later occurrences are
  `ReportLineKind.Step` at anchor + displacement. The anchor and not LINE-COUNTER is the datum because GR12d
  measures from "the line they occupy in the preceding occurrence" while §13.18.35.4 GR1's LINE-COUNTER holds
  the last line PRINTED, and the lines between them belong to the intervening occurrences.
- **ONE subsequent-line rule** — `ReportWriter.SubsequentTarget`. §13.18.35.4 GR7 was FOUR copies of
  `LineCounter + l.Value`, one per group presentation (body, page heading, page footing, report
  heading/footing). A new placement kind in one of four arms is this repo's most reproducible defect shape, so
  the rule was extracted before the Step arm was added; the drift test counts the four call sites.
- **The page-fit trial sum** — `ReportGroupLine.TrialInterval`, each line's expected offset minus the running
  one, so Σ over the group is exactly GR4c's "expected position of the last line of the report group" however
  the repetitions interleave, and GR4c's own sentence about an OCCURS "at the level of the LINE clause or
  above" needs no second encoding.
- **DEPENDING reaches the LINE** — GR13 makes the surplus repetitions not EXIST, which vertically means the
  whole report line is absent, not blank. `ReportLineModel.RepetitionGuards` + `ReportWriterEmitter.LinePresent`
  compose it into the SAME delegate as the PRESENT WHEN chain, which is what makes GR4c's "these clauses are
  taken into account in computing the trial sum" true of both suppressors at once.
- **Syntax rules** — §13.18.35.3 SR4 (`ScreenReportLineNesting`, screened over the flat entry array once per
  RD so a replay cannot report it per repetition) and SR10 a/b/c/d (`MultipleLineOperands`) on the new
  **COBOLNET2199** `report-line-clause-rule`, the COBOLNET2021 bundling precedent. SR25 leg by leg and SR26 on
  the entry's own axis (`ReportEntryLineSpan`).
- **Both 0899 stages RETIRED** — `report-occurs-in-group` and `report-multiple-line` are gone from
  `DiagnosticCatalog`, never to be reallocated;
  `ReportRepeatingEntryDriftTests.NeitherRepetitionAxis_StagesLoud` fails if either is re-declared.

MEASURED (`conformance:2002/pb565_report_vertical_repetition`, every line number derived from the spec before
the program was run): page lines 02 `X` · 04 `Y` · 07 `Z` (multiple LINE + a three-operand VALUE, GR23) ·
09 `2` · 11 `5` · 14 `8` (multiple LINE carrying a VARYING counter) · 16/18/20 `AAA` (GR12c over an absolute
line) · 21 `P` 22 `Q` 25 `P` 26 `Q` (GR12d over a group of relative lines) · 27/28/29 `BBB` (GR10c, no STEP) ·
30/31 `A B C` (the two axes nested — the shape that makes §13.18.63.4 GR23's wrap-around reachable at all).
Negatives: `pb565-report-multiple-line-at-85` (0900), `pb565-report-line-step-required` (2021 SR25a),
`pb565-multiple-line-with-occurs` (2199 SR10d), `pb565-report-line-in-line` (2199 SR4, all four editions).

## Landed — 2026-09-13, the HORIZONTAL repetition axis

RE-PROBED FIRST on main c68205ee: the refusal still reproduced verbatim (`error COBOLNET0899: RD 'R-V': OCCURS
in a report group description (ISO 13.18.38 repeating entries) is not yet implemented`).

⛔ AND THE NOTE'S OWN REPRO WAS NOT CONFORMING SOURCE. `03 COLUMN 1 PIC X(3) OCCURS 3 VALUE "AAA".` is
rejected by §13.18.38.3 SR25c — "The STEP phrase shall be specified if the entry … c) contains an absolute
COLUMN clause" — because without it §13.18.38.4 GR12 gives the repetitions no interval and all three would
print in column 1. That shape is now `conformance:negative/pb565-report-occurs-step-required`; the legal
shapes are the positive golden's five lines.

WHAT LANDED. §13.18.38 FORMAT 3 as a whole, on the horizontal (COLUMN) axis:

- **Grammar** — `occursStepPhrase` (`STEP integer-3`) with the `occursStepAhead()` text predicate. STEP is a
  §8.10 CONTEXT-SENSITIVE word ("OCCURS clause"), never reserved, so it gets NO lexer token: a token would
  have to join the generated `_dataNameTokens` set to keep `STEP (1)` subscripting a user item named STEP, and
  that set is derived from the §8.9 RESERVED table. The LOCALE / ATTRIBUTE precedent. Without the phrase the
  clause did not even PARSE, so the 0899 refusal was hiding a second, earlier rejection of legal source.
- **Binder** — `ReportOccursOf` reads the clause and enforces SR1a, SR10, SR16, SR17, SR24, SR25c/d, SR26 and
  SR27 plus the formats-1/2/4-only phrases (DYNAMIC, KEY, INDEXED BY), all on ONE new code, **COBOLNET2021**
  (the COBOLNET1559 bundling precedent). `BindReportEntries` binds the entry's SUBTREE once per repetition —
  the one shape that gives GR11 ("the same effect on each repetition") for free rather than teaching each
  clause about repetition, and the shape GR9's *subordinate to an OCCURS clause* leg needs.
- **Placement** — `ReportColumnKindModel` {Absolute, Relative, AnchorSeed, AnchorStep}. GR12's displacement
  Σ ordinal × integer-3 is additive over nested repeating entries, so an absolute operand moves by it; a
  relative one seeds a compose-local anchor `__raN` with the column it lands on and later repetitions place at
  anchor + displacement, because GR12 measures from the preceding occurrence's LEFTMOST while §13.18.14.4 GR9's
  horizontal counter holds its RIGHTMOST.
- **DEPENDING** — GR13's arithmetic emitted literally, composed into the SAME guard as the PRESENT WHEN chain
  so §13.18.63.4 GR22's three suppressors cannot drift apart. Every repetition is BOUND either way, which is
  GR23's "VALUE operands are nevertheless assigned to them, even though they are not printed".
- **VARYING** — `ReportFieldModel.RepetitionOrdinal` counts placements per ENTRY, and the §13.18.64.4 GR3
  counter became the closed form FROM + n × BY: a replayed entry is one field per repetition, so the old
  field-local accumulator could not have spanned it. The forms are exactly equal (GR3 adds
  arithmetic-expression-2 itself; both operands truncate to scale 0 once).
- **Edition** — `report-occurs-2002` + the `VisitOccursClause` report-group arm: the COBOL-85 report group
  description entry has no OCCURS clause, which is why its whole repeating-entry family (multiple LINE/COLUMN,
  VARYING, PRESENT WHEN) already gated at 2002. Negative golden `pb565-report-occurs-at-85`.

MEASURED (`conformance:2002/pb565_report_repeating_entry`, content derived from the spec and verified byte for
byte): `AAA AAA AAA` · `BBBBBBBBB` · `DDD EEE   DDD EEE` · `2  5  8` · `CCC CCC`.
