## The edition, derived (the note's first work item)

The 2002 edge the gates carry was "derived from Annex E's silence", which only proves ≤2014. Two independent sources
now put it after 1985: IBM's list of the 2002/2014 standard's substantive changes (Enterprise COBOL Language
Reference, "2002/2014 COBOL Standard features implemented in Enterprise COBOL 3 or later versions") carries the item
"VALUE clause, WHEN SET TO FALSE phrase in data division — The WHEN SET TO FALSE phrase allows specification of a
FALSE condition value. This value is moved to the associated conditional variable when the SET TO FALSE statement is
executed" — a change against COBOL-85, so the phrase (and the SET … TO FALSE arm it feeds) is not a COBOL-85
construct. The list mixes 2002 and 2014 items, so it cannot split those two; the 2002 edge stays the provisional one
(rows 7.21/7.26's discipline): it is the edge that never refuses a legal 2002 program, and a wrong guess costs only an
under-reject at `--std 2002`. GnuCOBOL 3.2 has no dialect option for the phrase (`cobc -std=cobol85` accepts it),
which is silence, not evidence. Recorded as VCR Table 7 row 7.32. No code changed.

## The grammar, and the tell

`src/Cobol.Net.Frontend/Grammar/Core/CobolData.g4:621-638` — the condition-name arm of `valueClause`:

```
| (VALUE | VALUES) (IS | ARE)? valueItem ({!(is2002() && TokenStream.LA(1)==PROPERTY)}? COMMA? valueItem)*
  (WHEN SET TO FALSE_ IS? literal)?        // :629  — ungated
  (IN IDENTIFIER)?                          // :630  — ungated
  ({is2002()}? validateValidPhrase)?        // :637  — GATED
```

Three optional tails on one alternative; the third carries `{is2002()}?` at its left edge and the first two carry
nothing. `VersionConformancePass.ParseArm.VisitValueClause`
(`src/Cobol.Net.Compiler/Validation/VersionConformancePass.cs:885-889`) is the whole of the clause's edition
logic and reads exactly one thing:

```csharp
public override object? VisitValueClause(CobolParserCore.ValueClauseContext ctx)
{
    if (ctx.valueClauseTablePhrase().Length > 0) _p.Check(Constructs.ValueTableFormat2002, "the Format 2 (table) VALUE clause");
    return base.VisitChildren(ctx);
}
```

So the Format-2 table phrase is gated at the pass and the Format-5 tail at the grammar, and the two Format-3 tails
are gated nowhere. **Whichever of the two mechanisms is right, "gated in neither" is not a third position anybody
chose** — it is the shape a construct has when nobody asked.

## ⛔ What the derivation actually produced — read this before writing a gate

Three sources were checked mechanically. None of them dates either phrase:

1. **Annex E** (`specs/ISO_COBOL.md` lines 42853–44026, the whole of E.1/E.2/E.3.1/E.3.2/E.3.3) contains the
   strings "FALSE" and "alphabet" **zero times**. Annex E is the 2014→2023 window, so this is a real result and
   not a null one: **neither phrase is a COBOL-2023 introduction; both existed by 2014.**
2. **`docs/VERSION_CHANGE_REFERENCE.md` Table 7** is the declared home of every pre-2023 delta ("⛔ Any pre-2023
   delta belongs HERE"). It has 22 rows and **no row for either phrase**. The 85 edge is simply not researched.
3. **`tests/version-matrix/reserved-words.json`** — the evidence that dated the ORDER TABLE clause's 2002 edge
   (`constructs.json`: *"Annex E covers 2014-2023 only, so the 2002 edge is derived from the ORDER reserved-word
   row … not from an E-list entry"*) — carries `FALSE` as **`r85: true`**, "continuous since 1985". FALSE is
   EVALUATE's word at COBOL-85, so the reserved-word test cannot discriminate here. `IN` and `ALPHABET` are
   likewise '85 words.

What the compiler asserts today is therefore unsupported in the repo: `DiagnosticCatalog` COBOLNET1756's message
text says the phrase is *"the VALUE . WHEN SET TO FALSE phrase, COBOL-2002+, ISO 14.9.39 SR7"*, and nothing
derives the "2002+". `under_rejects: true` is set against **the compiler's own stated edition model** — under D13
the four per-edition compilers are the product, and today two phrases sit outside the model entirely. If the
derivation instead lands on 1985, the defect does not disappear, it changes shape: the message text is wrong and
the two tails are correctly ungated.

**The first work item is the derivation, not the gate.** Sources that could settle it, in order of authority:
ANSI X3.23-1985's own §13 VALUE clause and §14 SET statement formats if a copy can be obtained (ratified decision
#1 says the repo holds no pre-2023 text, so this is an owner-facing acquisition, not a search); failing that,
the surveyed model implementations per `feedback_owner_decision_protocol` — GnuCOBOL's `-std=cobol85` acceptance
of both spellings is the cheapest discriminating probe available and its verdict, recorded as a survey, is the
project's standing answer where the standard is silent to us. Record the result as a **VCR Table 7 row** (never a
new table — CLAUDE.md rule 8) with its derivation stated in the row, exactly as rows 7.19/7.20 do.

## The fix, once the edition is known

If post-85: one `Constructs.*` row per phrase and one `_p.Check` per phrase inside `VisitValueClause` — the pass,
not the grammar, because the pass is where this clause's other introduction gate already lives and
`feedback_one_mechanism_per_job` forbids a second. The `{is2002()}?` at `:637` should move there with them; a
predicate at the grammar's left edge and a recognition Check in the pass are two mechanisms for one job, and this
rule currently runs both. The SET statement's `TO FALSE` form (probe a) gates in the same change set or the
edition claim is still false — `feedback_edition_gate_sweep`, and note that gating either phrase below its
edition will newly reject any corpus program that writes it at `--std 85`; sweep `tests/` before landing.

If 1985: the note closes as an analysis, COBOLNET1756's message text is corrected in the same commit, and the
`{is2002()}?` at `:637` is re-derived too — a gate nobody has checked is not evidence
(`feedback_a_dead_lookup_is_also_unverified`).
