# PB3603 — the register drift tests are not tree-wide sweeps

## Symptom

The landing of `notes-analyses-sweep-20261023` (a kb/Work-only change, 50 notes edited) ran `enqueue.py land`. The
Windows gate was `LEG 1 ONLY ... GREEN` (run `E:\COBOL-wt\notes-analyses-sweep-20261023\TestResults\build-local\000001-20261023T204143Z`).
The Linux gate (all legs) was RED on `ClosesRowsBackLinkDriftTests.EveryLandedDefectNote_StatesWhatItClosed` and
`DefectiveRowCoverageDriftTests.EveryDefectiveRow_IsClaimedByALiveWorkNote` (its `TestResults/linux-gate/unit.log`).
Both tests read `kb/Work/*.md` and the inventory, and the branch changed exactly those inputs.

In the Windows run both classes are in `not-run-Unit.txt` (leg 2) and absent from `leg-1-Unit.log`. Leg 1's plan did
not select them: neither file carries `[Trait("Sweep","tree")]` (`grep -c 'Trait("Sweep"'` gives 0 and 0), while
`SpecTraceabilityInventoryDriftTests.cs` carries it, and the reach map has no row from `kb/Work/*.md` to a test.
A notes-only branch is therefore landable on the Windows gate alone while CI's whole-population run and the Linux gate
fail it, and the merge queue would bounce it. The Linux gate caught this one only because `enqueue.py land` runs all
four Linux legs.

## Root cause

A test whose input is the register or the inventory, not a source file, is reached by no file-level impact map. The
tier-0c sweep trait is the mechanism that puts such tests in every leg 1. Measured 2026-10-23: of the 8 unit-test
classes that mention `WorkRegister` or `traceability-inventory`, only `SpecTraceabilityInventoryDriftTests` carries it;
the other 7 (AnnexA1RegisterDrift, ClosesRowsBackLinkDrift, DefectiveRowCoverageDrift, DerivedVerdictDrift,
FileControlKeyRuleDrift, RecordClauseRuleDrift, SortWorkTraceabilityDrift) do not.

## Fix (structural, rule 5)

Not two attributes by hand but the rule: every test class that reads `tests/_shared/WorkRegister.cs` or
`tests/version-matrix/traceability-inventory.json` carries `[Trait("Sweep","tree")]`. A drift test over the unit-test
tree enforces it, listing the consumers mechanically (`grep -rl "WorkRegister|traceability-inventory"
tests/Cobol.Net.Tests.Unit/*.cs` is the population) and failing for any member without the trait. Add a measured
witness: re-run the leg-1 plan for a kb/Work-only diff and show the register-reading classes selected. Sibling sweep:
tests that read `constructs.json`, `docs/CONFORMANCE.md` or the rule catalog the same way.
