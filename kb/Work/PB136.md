# PB136

Rows: GR-8.8.1.2-5 (DIVERGES), the [arithmetic-expressions] subscript findings.

(1) ReferenceResolver.SplitSubscriptTokens's new-segment starter set lacks SUB_LPAREN, so a parenthesized subscript after another subscript never splits and the count check rejects ISO NOTE 2 / §D.3.5.3's required form. ⚠ ARCHITECTURAL (rule 5): a depth-0 '(' after a literal or ')' can join the starter set outright, but after an IDENTIFIER it is ambiguous with a subscripted-identifier subscript (`DOG (BAKER (I) 3)`) — the splitter must become declaration-informed (does the preceding name carry OCCURS?). (2) RenderSegment's `/` case splices C# integer division over long operand reads; the D18 exact-evaluation escape fires only when an operand is SCALED, so the all-scale-0 quotient truncates silently where §8.4.2.3.4 GR1b requires the non-integer evaluation to raise EC-BOUND-SUBSCRIPT. Not covered by PB17/PB41/PB42/PB48/PB50 (PB41 fixed only the scaled-operand compound routing). Fix: route `/`-bearing subscripts to D18 unconditionally.
