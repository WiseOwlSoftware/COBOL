# PB373 — the witness debt the PB280 Q1 landing leaves behind

**Rows:** `DOC-A.1-127`, `DOC-A.1-206`. Both carry `DOCUMENTED-NON-SUPPORT` (owner decision PB280 Q1,
2026-09-02) and their computed §7 anchor; both are **GAP**, and that is correct rather than unfinished.

⚠ **Neither is a defect in the compiler.** A derived verdict is not a shortcut past the witness: the schema
closes a declined row only on a SPEC-DERIVED test proving the documented posture is *what actually happens*
(`inventory-schema.json` → `$verdict-vs-state`). The determination is written, filed under its own item and
correct; nothing on disk asserts it. That is the identical Phase-C category as CONFORMS-but-untested.

They are also, today, the only two rows in the register that the PB280 Q3 answer bites on: each states a VALUE,
so each *can* be pinned, which is exactly why by-reference-only determinations were refused.

## `DOC-A.1-127` — OBJECT-COMPUTER computer-name and implied equipment configuration (§12.3.6 GR2, optional)

**The determination:** *Not provided.* `computer-name-1` is accepted with any spelling and identifies no
equipment configuration — there is ONE object computer, the .NET runtime the program is compiled for — whether
the name is present, absent (§12.3.6.4 GR3) or the paragraph is omitted entirely (GR4).

**What its witness must assert.** ⛔ Not "a program with an OBJECT-COMPUTER paragraph compiles". The claim is an
INVARIANCE over three source shapes, so the golden has to measure the same observable three ways and get one
answer: the **same program** — one that reports something the standard lets an equipment configuration change,
i.e. the clauses that follow the computer-name (PROGRAM COLLATING SEQUENCE and CHARACTER CLASSIFICATION behave
identically with or without a name) plus a storage observable such as `FUNCTION BYTE-LENGTH` of a group — built
(a) with `OBJECT-COMPUTER. SOME-MACHINE-NAME.`, (b) with the paragraph present and the name absent, and (c) with
no OBJECT-COMPUTER paragraph at all, producing **byte-identical output**. A fourth leg is worth its line: a
second, differently-spelled computer-name must give the same answer as (a), which is what "identifies no
equipment configuration" actually means and what a future name-keyed lookup would break.

## `DOC-A.1-206` — USAGE BINARY-CHAR / -SHORT / -LONG / -DOUBLE, wider range than the minimum (§13.18.60.4 GR12, optional)

**The determination:** *Not provided.* Each usage holds exactly the GR12 minimum range for its width —
CHAR ±128 / 0–255 · SHORT ±32768 / 0–65535 · LONG ±2^31 / 0–2^32 · DOUBLE ±2^63 / 0–2^64.

**What its witness must assert.** ⛔ Not that the endpoints store and display, which any wider implementation
would also pass. The claim is that the range is **exactly** the minimum, so the golden must measure BOTH edges of
each of the eight bands: the extreme value round-trips, **and** one step beyond it does not silently become a
wider container — the SIZE ERROR / EC-SIZE-TRUNCATION disposition for `BINARY-CHAR` at 128, `BINARY-CHAR
UNSIGNED` at 256, `BINARY-SHORT` at 32768, and the corresponding LONG and DOUBLE edges. An implementation that
*did* provide the optional wider range answers the second leg differently and the first identically, which is the
whole reason the second leg is the measurement and the first is only its control.

⚙ Both goldens belong to the golden lane. Landing either one also obliges its §7 row's `Pinned by` cell — the
determination and its evidence are one artifact, and `audit_annex_a1.py --check` holds them in agreement.

## Status 2026-09-05 — ONE OF THE TWO ROWS IS WITNESSED; the other is blocked on its own determination

**`DOC-A.1-127` is CLOSED.** Golden-lane round 3 landed `tests/conformance/2023/pb373_object_computer_name_inert`
and §7 line 1003's `Pinned by` cell now names it. The witness is the INVARIANCE this note asked for and one leg
more: eight separate outermost source units of one compilation group (GR1's containment inheritance cannot leak a
configuration between them, and a CONFIGURATION SECTION in a contained program is COBOLNET1643 anyway). Part 1
runs a computer-name, a DIFFERENT computer-name, the paragraph with no name (§12.3.6.4 GR3) and no paragraph at
all (GR4), each computing one equipment-configuration signature, all SAME, with a CONTROL leg that reports
DIFFER. Part 2 is the leg this note under-specified: all four Part-1 legs run under the DEFAULT arms GR10 and
GR6 — the branches that apply precisely BECAUSE no clause is written — so Part 1 alone cannot carry the second
claim, that the clauses FOLLOWING the name behave identically with or without one. Four more units write
`PROGRAM COLLATING SEQUENCE IS REV` and `CHARACTER CLASSIFICATION IS TR` with and without a computer-name and are
compared to EACH OTHER, never to a pinned code point, so §8.2.1's runtime locale availability cannot make the
golden environment-dependent.

⚠ The row also needed a correction the writer's record did not carry: its `code-location` named only its own
`docs/CONFORMANCE.md#DOC-A.1-127` anchor, and the DOC kind's `is_observable` predicate reads the
`implementation-pattern` `^src/Cobol\.Net\.` over the row's OWN location list — so the row would have stayed a
GAP with a green witness on disk. It now names the two sites the determination is observed through: the grammar
rule that ACCEPTS `computerName computerAttributes?`
(`src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4#objectComputerParagraph`) and the binder that walks
`objectComputerParagraph` reading only its CLAUSES and never the computer-name
(`src/Cobol.Net.Compiler/Binding/DataBinder.Switches.cs#SwitchBindSpecialNames`).

**`DOC-A.1-206` is BLOCKED on `kb/Work/PB592`, and this note's own statement of it was wrong.** The
determination this note repeats — "each usage holds exactly the GR12 minimum range for its width — CHAR ±128 …"
— is contradicted by the standard and by the compiler. §13.18.60.4 GR12's table is ASYMMETRIC: every SIGNED row
prints a strict `<` on BOTH sides (`-128 [-2**7] < n < 128 [2**7]`) while every UNSIGNED row prints `<=` on the
left, so the signed minimum band EXCLUDES `-2**(w-1)` — and the compiler stores -128 and -32768 (probed
2026-09-05). The optional element is therefore PROVIDED, minimally, by exactly one value per signed usage. This
note's "what its witness must assert" paragraph is wrong for the same reason: it asks for SIZE ERROR at
BINARY-CHAR 128 and BINARY-CHAR SIGNED -128 alike, but only the first is a minimum-band edge. The witness draft
exists and passes; it is parked, not landed, until the owner repairs the cell — PB592 carries the exact repair
text and the evidence.

**So one row of the two remains open**, and this note stays open with it.
