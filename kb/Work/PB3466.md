# PB3466 — BYTE-LENGTH as the last DISPLAY operand is a parse error

Source: PB3441 implementer report (`E:\COBOL-coord\scratch\reports\w1133b-PB3441-report.md`, "New defects").
Repro: `E:/COBOL-coord/scratch/w1133b/p/T13.cob`:
`DISPLAY FUNCTION BYTE-LENGTH (G1) " " FUNCTION BYTE-LENGTH (K1)` fails to parse when BYTE-LENGTH is the LAST
operand; substituting FUNCTION LENGTH parses. Legal source is rejected (§15.14.4 defines BYTE-LENGTH as a function;
§14.9.11.3 allows a function-identifier operand of DISPLAY).

Suspected sites (not narrowed further): the function-call rule in
`src/Cobol.Net.Frontend/Grammar/Core/CobolExpressions.g4` near line 636 and `constantByteLengthWord`
(`src/Cobol.Net.Frontend/Grammar/Core/CobolData.g4` line 333), which may let the BYTE-LENGTH word take the
`CONSTANT ... AS BYTE-LENGTH OF` reading at the end of the operand list. The fix is the root grammar cause plus a
golden; sweep the other statements that end in a function operand. The PB3441D golden avoids the defect by MOVEing
the function result to a field.
