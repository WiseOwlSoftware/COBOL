## Landed (wave 1001 C, 2026-10-01)

`ReferenceFormatDiagnostics` is a public top-level class in its own file (it was nested and private) and ONE instance is
created per front-end pass by `Frontend.Parse` — the same object `Normalize` hands the main-source walk and `Preprocess`
hands `CopyProcessor` (`referenceFormatGates`), which passes it to the shared walker for every copybook
(`NormalizeCopybookMapped`). The FILE is an argument of every report (`OnFloatingComment(file, line, column)` …), never
state of the instance, so the once-per-compilation gates (COBOLNET0900 / 0902 / 0903) fire once however many files use the
construct, and each rule is sited at the file and physical line that broke it. `ReferenceFormatProcessor
.NormalizeToFreeForm[Mapped]` take the instance instead of `(dialectLevel, permissive, DiagnosticBag)`; every caller was
changed (the legacy oracle passes none — it reports nothing). Witnesses:
`conformance:LibraryTextReferenceFormatDiagnosticsTests` (a copybook's `N*> c` is COBOLNET2495 at the copybook, both
formats; the obsolete column-7 hyphen is ONE warning for main source plus copybook, and sited at the copybook when it is
the first user), `unit:LogicalLineBuilderTests.OneGatesInstance_ServesEveryFile_SitedAtTheFileThatBrokeTheRule`. The brief's
corpus negatives are xUnit facts instead: the negative corpus compiles with no library text beside the program, and a `.err`
substring sees neither the SITE nor the COUNT.


# PB1640 — LANDED

Filed 2026-09-27 by the train-65 lander from the wave-65 B implementer report (PB1491 + PB1493). The implementer
found it while landing the one §6.5 logical conversion; it predates that change.

**Observed.** `src/Cobol.Net.Frontend/Preprocessor/CopyProcessor.cs:633-634` converts library text through
`ReferenceFormatProcessor.ConvertFixedToFreeMapped(text, copybookPath)` (the public overload passes `gates: null`)
or `NormalizeToFreeFormMapped(..., diagnostics: null, ...)`. `ReferenceFormatDiagnostics` (formerly `EditionGates`)
has only ever served the main source. So in library text:

- §6.2.3.2 SR2 (a floating comment indicator not preceded by a separator space, COBOLNET2495) is not diagnosed;
- §6.2.3.2 SR3 (a multiple-character floating indicator split across a continuation, COBOLNET2496) is not diagnosed;
- the fixed-form 2002 introduction gate on `*>` (COBOLNET0900 below 2002, VCR row 7.23) is not asked;
- COBOLNET0902/0903 (the continuation-line gates) are not asked.

**Repro.** A copybook containing `MOVE A TO X*> c` (fixed or free form), copied into any program: compiles clean.
The same line in the main source is COBOLNET2495.

**Rule.** §6.2.3.2 2): "The floating comment indicator of an inline comment shall be preceded by a separator space"
(`cite.py --check 6.2.3.2` OK). The syntax rules of clause 6 govern library text as they govern the source text:
library text is processed by the same §6.5 logical conversion.

**Fix shape.** Give the copybook conversion the same `ReferenceFormatDiagnostics` the main source gets, sited at
the copybook's file and line (the line map already carries both), at the compilation's edition. Sweep every other
caller of the null-diagnostics overloads (`NistPreprocessor`, `ConvertFixedToFree`).

## 2026-09-27 — train 67: now a one-argument change

PB1067 (train 67) made copybook normalization the same §6.5 walker as the main source
(`ReferenceFormatProcessor.NormalizeToFreeFormMapped`, reference format per file in `ReferenceFormatMap`), so the
fixed-form arm with no gates is gone: `CopyProcessor.NormalizeCopybookMapped` passes `diagnostics: null` to the
shared walker, and passing the compilation's `ReferenceFormatDiagnostics` (sited by the copybook's map) is the fix.

## Task brief (research 2026-09-30)

Re-probed on 4a1dda60e: a copybook line `    MOVE 1 TO X*> c` copied into a fixed-form program compiles clean at `--std
2023` (the same line in the main source is COBOLNET2495) — confirmed. **More than one argument:**
`ReferenceFormatProcessor.cs#ReferenceFormatDiagnostics` is constructed PER CALL of `NormalizeToFreeFormMapped` with
the file baked in (`sourcePath`) and holds the once-per-compilation flags (`_col7Flagged`, `_wordFlagged`,
`_floatingCommentFlagged`), so passing a fresh one per copybook would repeat COBOLNET0903 / 0902 / 0900 per file.
Fix: ONE `ReferenceFormatDiagnostics` per compilation, created by `Frontend` (edition, permissive, bag) and passed to
both the main-source normalization and `CopyProcessor` (`NormalizeCopybookMapped`); the FILE becomes a per-call
argument (every `On…` method already builds a `SourceOrigin(file, line)`). Delete the `diagnostics: null` path for
library text (the legacy oracle's callers keep their own). Goldens: `negative/pb1640-copybook-unseparated-comment`
(COBOLNET2495 sited at the COPYBOOK's file and line), `2023/pb1640_col7_obsolete_once` (main source and a copybook
both use the column-7 hyphen → exactly ONE COBOLNET0903). Estimate: half a Sonnet slot; independent (lands before or
after PB1800 — if after, it takes `PhysicalLineSet`).
