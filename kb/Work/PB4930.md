# PB4930 - a failed canary cannot be retried

**Sites:** `scripts/spec/audit_batch.py` (`main`, `canary_proven`), `scripts/spec/test_audit_batch.py` (`main`)

**Report (R1-2 low, carried unfixed as R2-1).** In `audit_batch.main` (`scripts/spec/audit_batch.py:496` at the reviewed head), the branch for `submit`/`retry` calls a retry
the canary when its todo is a SUBSET of the canary items ("a retry of nothing but canary items is still the canary (its replies failed)"). But a retry's
todo holds every item with no answer and no uncollected batch, which after a canary includes EVERY item never submitted. So after a canary whose replies
all failed (no valid answer, `canary_proven` false) and before any full submit, the todo is a superset of the canary items, the comment's case never fires,
and `retry` is refused ("a submit without --canary is refused until that pass has a collected canary with at least one valid answer"): the failed canary items
cannot be resubmitted, and `submit --canary N` resubmits only the first N unanswered items (the same ones, at best, by luck of ordering). The branch
condition fires only once every item sits in some batch. Expected: `retry` before a proven canary resubmits the failed canary items, as a canary (the canary's
own item list is the todo), never the whole population. Repro: plant a state with a collected canary whose answers all failed (the fake client in
`scripts/spec/fake_batches.py` can answer `errored`), run `retry` and observe the refusal. Fix with a test case in `test_audit_batch.py`.

Source report and lead: `w20261910a-PB4886-report.md`, R1-2 and R2-1 (the same lead twice).
