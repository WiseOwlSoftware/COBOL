## The refuter's measurement (row GR-12.4.5.3-4, batch 14a)
DOC-A.1-73: 'The association is made at every OPEN, SORT and MERGE'; content empty after space removal, or carrying a character below U+0020, 'names no physical file: the association cannot be made, so the statement is unsuccessful'. The OPEN arm honours it (`FileConnector.Associate`: `spec.Trim(' ')`, `ch < ' '` → '31'), and a SORT GIVING file does through its implicit OPEN. The sort-merge file ITSELF does not: SD SELECT … ASSIGN USING WS-N with WS-N = SPACES or X"01" → SORT completes, records returned, no exception status.

## What the fixer owes
Associate the sort-merge file's ASSIGN USING content at SORT/MERGE time through the same `Associate` rule (one rule, one place), making the statement unsuccessful per DOC-A.1-73; or amend DOC-A.1-73 to say what the sort-merge file does. Golden: SORT with an all-spaces USING name.

rendering of the executing element's assignment is `SequentialIoEmitter.ExecutingAssignment`. Golden
