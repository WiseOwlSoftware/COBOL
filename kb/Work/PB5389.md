# PB5389 - no golden pins the widened SR10 arm of ScreenSameClauses

**Sites:** none (adds goldens under conformance-suite/cases/12.4.6.4-SAME and changes no code file; the arm under test is the SR10 loop of ScreenSameClauses, line 757 of the binder's IoControl partial)

**Mechanism.** PB5250 widened the SR10 loop's filter from `SameKindOf(m) == SameFileKind.Other` to `SameKindOf(m) != SameFileKind.SortMerge` (line 757 on main, 5237495315), so a report file named in a file-area SAME clause that a SAME SORT / SORT-MERGE AREA clause also names, with members missing from the sort clause, is refused with the SR10 text. The PB5250 goldens (`pb5250-same-sort-area-report-file`, `pb5250_same_sort_area_report_file_85`, `pb5250_same_record_area_partly_in_sort_area`) pin the report-file-in-sort-area acceptance and the record-area shape; none has a SAME AREA clause holding a report file that a sort-merge clause also names and omits members of. Reverting the predicate therefore passes the whole gate. PB5250 withdrew SR5c for SAME RECORD AREA (kb/Work/PB5250/2026-11-11-landing-sr5c-record-area-not-applied.md); the arm under test is the file-area clause only, as the comment at line 750 says. The lead holds on main.

**Fix direction.** Add a negative golden at each edition whose rule applies (the diagnostic COBOL2738 / `SameClauseRule`, expected text from §2023:12.4.6.4.3 SR10) with a report file in `SAME AREA FOR RF OTHER-FILE` and a `SAME SORT AREA FOR RF SORTFILE` omitting OTHER-FILE, plus the accepted twin where the sort clause lists every member. Decide the 1985 reading from the rule PB5250 names as SR10's 1985 counterpart (its note holds the checked citation) and check any citation written with `cite.py --check`. Expected values come from the rule, not the compiler.
