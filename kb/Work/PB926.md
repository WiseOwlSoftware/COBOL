# PB926 — OPEN — availability, not bandwidth

Source: the `PB897` report, "New defects" item 2.

## The measurement

`tests/external/gnucobol-3.2.tar.xz` is git-ignored and therefore PER-WORKTREE. `scripts/build-local.ps1`
and `scripts/build-local.sh` fetch on absence. **Repro: `ls tests/external/` in any fresh worktree** — this
one included.

The cost is not the 2.9 MB. Since **PB277** and **PB897** landed, a corpus that cannot be fetched makes the
population gate RED (`POPULATION UNMEASURED`) instead of silently green — which is correct, and which means
every fleet member now depends on ftp.gnu.org being reachable at the moment its worktree is created. One
blip reds a gate for an agent that changed nothing.

## The fix

`scripts/fetch-gnucobol-tests.ps1`'s `Test-Archive` / download block should, before touching the network,
look for a VERIFIED copy in a shared cache — the main checkout's `tests/external/`, or
`$env:COBOLNET_CORPUS_CACHE` — and hard-link or copy it, **through the same sha256 gate** that guards the
download. A cache hit that skips the hash check would be a worse defect than the one it fixes.

tooling items in one sitting.
