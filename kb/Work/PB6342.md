**Scenario:** AddressConformanceReason takes no passing mode and, for a program-address-identifier, returns a violation whenever exactly one of formal and argument is restricted (formalProto is null || pa.Prototype is null, :331). Repro (2014/2023): a program-prototype PP in the REPOSITORY, a nested program C with LINKAGE 01 F USAGE PROGRAM-POINTER (unrestricted) and PROCEDURE DIVISION USING BY VALUE F (or by content), then CALL "C" AS NESTED USING BY CONTENT ADDRESS OF PROGRAM PP: refused with the argument-conformance diagnostic "one is a RESTRICTED program-pointer and the other is not restricted". By §2023:14.8.2.3.3 the conformance is that of SET F TO ADDRESS OF PROGRAM PP, which SetBinder.cs:1124-1129 accepts (an unrestricted receiver meets no SR22 condition), so the same pair is legal as a SET and refused as the argument the standard defines by that SET. The same pair through INVOKE USING BY CONTENT is refused the same way.
