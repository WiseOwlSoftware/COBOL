## What happened

A self-test's PASS is reused while nothing its run read has changed (kb/Work PB2914; `scripts/self_test_inputs.py`). The
run is traced, so a self-test that runs git in the REAL checkout, or lists one of its directories, is keyed on what that
read: a `git merge-base` or a `git fetch` with no pathspec is the whole tree's content, and every gate re-runs it. The
tooling gate of build-stage1 (`TestResults/build-local/000001-20261111T023340Z/gate.log`) re-ran these for that reason:

| self-test | gate seconds | what keyed it |
|---|---|---|
| `scripts/orchestrator/test_adopt_main.py` | 848 | `git merge-base --is-ancestor` from `plan_wave.py`, run as a child over the real checkout |
| `scripts/spec/gen_ledger.py` | 370 | the trend arm's `git_batch.resolve` and `git log -1 --format=%s <sha>` of planted shas, before `REPO` moved to the scratch |
| `scripts/orchestrator/test_orchestrate_stop.ps1` | 367 | `stop.ps1 -Status` ran `ledger_state.py owed` with no `--repo`: `git remote`, `git fetch origin main` in the real checkout |
| `scripts/orchestrator/test_orchestrate_steer.ps1` | 349 | the same `stop.ps1 -Status` call |
| `scripts/devlog.py` | 989 | the lint of the real `DEVLOG/` (every entry file and the listing); every landing changes it |
| `scripts/orchestrator/test_orchestrate_adopt.ps1`, `_ledger.ps1` | 515, 470 | the landing lane's tick read the register of the script's own checkout, not `--repo`'s |
| `scripts/orchestrator/test_inventory_ratchet.py` | 29 | `inventory_ratchet.py --base HEAD --head HEAD` over the real repository |
| `scripts/differential_fuzz.py` | 28 | `main()` read the real `kb/Work` for the cadence gate |

Two causes were the tracer's, not the self-tests'. Every Python self-test that imports from `scripts/` was keyed on the
NAMES in `scripts/` (`entries:scripts`, in 30 of the gate's 42 re-runs): the import system fills a directory cache with
`os.listdir` (`FileFinder._fill_cache`), and the tracer read that as a listing. And a wildcard pathspec
(`:(glob)scripts/spec/work*.py`) was read as the whole tree's names.

## The fix

**Sites:** `scripts/self_test_inputs.py` (`TRACER`, `git_reads`, `self_test`) · `scripts/orchestrator/test_adopt_main.py`
(section 9, the planner's guard) · `scripts/spec/gen_ledger.py` (`self_test`) · `scripts/orchestrator/stop.ps1` (`-RepoDir`,
`-Status`) · `scripts/orchestrator/test_orchestrate_stop.ps1`, `test_orchestrate_steer.ps1` (the `-Status` calls) ·
`scripts/devlog.py` (`self_test`, `lint` docstring) · `scripts/hooks/tooling_check.py`
(`registered_hooks_leave_wip_commits_alone`, `self_test`) · `scripts/prune_worktrees.py` (`live_survey`) ·
`scripts/orchestrator/land_lane.py` (`survey_rows`) · `scripts/orchestrator/testdata/orchestrate_test_lib.ps1` (`Note`) ·
`scripts/orchestrator/test_orchestrate_adopt.ps1`, `test_orchestrate_ledger.ps1` (their register files) ·
`scripts/orchestrator/inventory_ratchet.py` (`--repo`, `added_lines`, `_git`) · `scripts/spec/audit_witness_loss.py`
(`default_base`, `_git`) · `scripts/orchestrator/test_inventory_ratchet.py` (section 7) · `scripts/differential_fuzz.py`
(`self_test`, the writer cases) · `scripts/inert_lane.py` (the `DEVLOG/` and `.gitmodules` reader names) ·
`docs/rearchitecture/DESIGN-orchestrator-loop.md` (sections 7 and 12)

1. `test_adopt_main.py`: the planner-guard arm runs `plan_wave.main` in-process with `plan_wave.REPO` pointed at the
   scratch repository for that one call. The guard is the same code; only its checkout moves.
2. `gen_ledger.py`: `REPO` moves to the scratch repository before the trend arm. A repository with no commit answers the
   planted shas as the real one does.
3. `stop.ps1` takes `-RepoDir` (default: its own checkout, as `orchestrate.ps1 -RepoDir`) and passes it to
   `ledger_state.py --repo`. The two self-tests pass their fixture repository.
4. `devlog.py`: the lint of the real `DEVLOG/` is gone from the self-test. `devlog.py check` lints the whole tree at every
   landing (enqueue.py's checks and CI's merge group), and the self-test proves every lint rule on planted trees. The
   PB2605 repro (no registered PreToolUse hook asks for a DEVLOG entry on a worktree WIP commit) MOVED, unchanged in what
   it proves, to `tooling_check.py`'s self-test: it is a property of the registered hooks, which that check holds, and no
   hook's own self-test covered it. It now builds its own scratch repository and worktree. Its failure branch was shown by
   a fake hook answer naming DEVLOG. devlog's `entries:scripts` key was the tracer's import-cache listing (below).
5. `test_orchestrate_adopt.ps1`: NOT folded. The analysis said its dry-run and red-main cases re-prove `adopt_main`'s
   rules. The dry-run case does not: in a dry run the supervisor never calls `adopt_main.py` (`orchestrate.ps1`'s own
   `-DryRun` branch), so it proves the supervisor's rule. The red-main case proves that a KEPT answer still runs the unit
   and leaves the checkout alone, which is the supervisor's too. Folding the two would need a stateful fake `gh` and a
   two-unit run whose second unit `next_unit.py` chooses. That costs more than the 12 s (idle) the fold saves. Its real
   cost was the re-run on every gate, and that is fixed: the test was keyed on the real `kb/Work` because
   `prune_worktrees.live_survey` and `land_lane.survey_rows` read the register of the SCRIPT's checkout instead of the
   surveyed one (`land_lane.py tick --repo`). Both now read `<repo>/kb/Work`, a latent production defect of the same
   kind. The fixture's register files became real notes (`Note` in the shared harness), or the tick stops on them.
6. `test_inventory_ratchet.py`: a defect, not its purpose. HEAD against itself can only be GREEN, so it proved only that
   the real inventory reads, which `inventory_view.py`'s gate audit already proves. Its excuse diff (`DEVLOG`, `kb/Work`)
   and `cat-file --batch` keyed it on the whole tree. `inventory_ratchet.py` takes `--repo`, and the arm now runs the
   command line over planted commits of a scratch repository: GREEN, RED naming the reopened row, GREEN once an excuse
   line is added, and exit 2 for a base with no inventory. It proves more than before.
7. The tracer drops a listing made by the import system's directory cache (the module files an import opens are still
   recorded). A wildcard pathspec is narrowed to the directory of its literal prefix. `self_test_inputs.py --self-test`
   holds both.

## Left, and why

These self-tests still read the real tree; each is listed with the reason it stays for now.

- `scripts/spec/ledger_plan.py`: `live_problems()` on the real register and inventory is an AUDIT ("the plan reads cleanly
  off the register"). No gate or CI step runs it elsewhere; moving it needs an audit entry in `scripts/gate.py`, which
  another change is editing. It keys the PASS on every note.
- `scripts/spec/gen_ledger.py`: its arm "the inventory's numbers carry every held edition" runs `measure_inventory()` on
  the real stores (`tests/version-matrix/inventory`, `inventory-1985`), so the PASS is keyed on those listings; an
  inventory landing re-runs it (about 21 s idle), a DEVLOG or register landing no longer does.
- `scripts/prune_worktrees.py`: lists the real `scripts/orchestrator` for its structural rule ("production readers call
  live_survey, never survey"): a real-tree audit, keyed on that listing only.
- `scripts/arch/file_census_notes.py`, `scripts/orchestrator/landing_rules.py`, `scripts/spec/spec_pdf.py`: `git ls-files`
  over the real tree (names). `landing_rules.py` declares `SELF-TEST-POPULATION: tree`; the other two are judged by the
  runner. Each is keyed on file NAMES, so an added or removed file re-runs it, never an edit.
- `scripts/orchestrator/test_plan_wave.py`: declares `SELF-TEST-POPULATION: tree` (it plans over the real register and
  branches by design). The wildcard narrowing removes its `:(glob)` whole-tree reads; its plain `git ls-files -z` stays.
- `scripts/scratch_repo.py`, `scripts/self_tests.py`: their self-tests run their audits over the real tree by design (the
  audit is the subject).
