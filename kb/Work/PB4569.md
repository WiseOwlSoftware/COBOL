# PB4569 - native `2 ** 130` keeps 16 significant digits

**Determination (adjudicator, wave 20261861).** §8.8.1.3 leaves native evaluation to the implementor and requires the technique to
be specified, so CLAUDE.md rule 1 sends it to GnuCOBOL. GnuCOBOL's run-time power is exact (`mpz_pow_ui`): `X ** N` with X = 2,
N = 130 shows 1361129467683753853853498429727072845824. Its 0 for `2 ** 130` is cobc folding `literal ** literal` in a signed
64-bit integer that wraps (`7 ** 45` shows 7^45 mod 2^64). It is not a technique. The 16 digits come from
`CobolIntrinsics.PowNativeIntDec`, whose `Math.Pow` fallback past `Int128` is D19 part (a): an owner decision of 2026-08-03 that
took IBM's and Micro Focus's floating-point fallback before rule 1's precedence existed. CONFORMANCE.md DOC-A.1-179 calls it "the
documented double approximation", while DOC-A.1-123, the required native-technique item, says an exponentiation with an exact base
and an integer exponent is formed on the wide form. PB2617 (a scaled base) and PB4575 (an exact base) already follow GnuCOBOL. The
integer base is the one arm left, so `X ** 130` over `PIC 9` gives 16 digits, over `PIC 9V9` 34, and `B65 * B65` all 40, for the
same value. Every consumer inherits it silently: MOD, REM, INTEGER, SUM, the relations, and an arithmetic statement that cancels
the power. The pb69 golden pins the approximation (`MOD (A ** 3, B)` 1012193 for 980012199, `A ** 3 / A ** 2` 999999999999998 for
A).

**Owed:** the native integer power is exact while its value fits the 77-digit wide form,
and past it the SDIDI's `PowNativeDec`, as for every other native power. Fix: `NumericRenderer.Power` routes a scale-0 base through
the PB2617 / PB4575 arm (`CobolWide.Pow` for a bounded literal exponent, else `CobolExact.Pow`), and `PowNativeIntDec` is deleted.
NUMERIC_DESIGN D19 (heading, (a), the PB69 paragraph and its "Cost, documented" sentence, (c)'s last sentence) and CONFORMANCE.md
DOC-A.1-123 / DOC-A.1-179 change in the same commit. Determination, legs and siblings:
`E:/COBOL-coord/scratch/op-w20261861/a/determination.md`.

**Owner decision (2026-11-04):** asked "does CLAUDE.md rule 1's precedence supersede NUMERIC_DESIGN D19 (a) (the PB18 decision of
2026-08-03), so a native integer power too large for the Int128 carrier is computed exactly as GnuCOBOL does (the wide form, then
the SDIDI) instead of the binary64 approximation?", the owner answered "Yes, exact". The fix therefore changes D19 (a),
DOC-A.1-123, DOC-A.1-179 and the pb69 golden in the same change set, as the determination's fix shape says (the clerk changes none
of those files: the implementer does). The note waits on no one, so `blocked_by` stays empty.

**Separate.** A power past 77 digits is the round-to-odd chain, not one rounding of the exact power (`2.5 ** 100` ends …0127 where
the 34-digit rounding ends …0124): the analysis note PB4587. GnuCOBOL's wrapping constant fold: the upstream note PB4588.
