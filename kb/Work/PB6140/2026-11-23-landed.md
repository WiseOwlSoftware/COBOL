**The decision.** The dispatch methods (`__Dispatch`, a method's `__MDispatch`) take `bool __direct = false`. The activation entry passes `__direct: true` to the top frame (it ignores the frame's result); `DispatchState.DispatchCall`, the one construction site of an out-of-line PERFORM's or a SORT/MERGE procedure's bounded call, passes the calling frame's `__direct` on and renders `if (__Dispatch(s, e, __direct) == ElementReturn.Returned) return ElementReturn.Returned;`. `DispatchState.ReturnToActivator` is the one spelling of the return for GOBACK (`CallEmitter.EmitGoback`), a called program's EXIT PROGRAM (`CallEmitter.EmitExitProgram`), a method's GOBACK (`StatementEmitter.Visit(BoundMethodReturn)`) and the dispatcher's §2023:14.6.3 implicit GOBACK: `if (__direct) return ElementReturn.Returned; throw new ProgramReturn();` (`MethodReturn` in a method). The frames entered any other way, `__RunUse` (USE procedures and Format-3 handlers) and `__RunDebug`, pass no `__direct`, so a return below them still throws, through the `catch (ProgramReturn) when (CobolSort.UseProcedureExited(...))` filter §2023:14.9.40.4 GR17 needs in `__RunUse`.

Why neutral: between a GOBACK and the activation entry, a direct chain crosses only dispatch frames and the C# blocks of the statements they run. A `return` runs the same `finally` blocks a throw does; the only catch clause in emitted code that takes the return signal is the GR17 filter, which sits in `__RunUse`, below which `__direct` is false. An operand-evaluation step (which may run in a lambda) always throws (`ReturnToActivator` asks `InOperandEvaluation`, the rule `TransferJump` keeps for its `goto`). `EcEmitter.PropagationReturn` / `ObjectPropagationReturn` (the automatic propagation of an unhandled fatal condition, §2023:14.6.13.1.3 GR6) still throw: their text is also emitted into the generated `__IoCheckEc` helper, which has no dispatch frame; that path is the fatal-condition path and costs nothing on a normal return.
