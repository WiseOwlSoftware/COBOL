# PB4922 - a long Windows temp path makes every messaging statement EC-MCS-IMP

**Sites:** `src/WiseOwl.Cobol.Runtime/Mcs/McsSocketDirectory.cs` (`McsSocketDirectory.Resolve`, `McsSocketDirectory.EndPointOf`), `src/WiseOwl.Cobol.Runtime/Messaging/MessagingPeer.cs` (`MessagingPeer.Start`), `docs/rearchitecture/DESIGN-message-control.md` (5.1, the socket directory table that states the limit without a remedy)

**What the finisher found.** A Unix-domain socket path is limited to 107 UTF-8 bytes (`McsSocketDirectory.MaxPathBytes`). On Windows
the socket directory is under the user's temp directory and there is no fallback (Unix falls back to `/tmp`). A temp path over 45 bytes, which in the
default layout (`C:\Users\<name>\AppData\Local\Temp`) means a user name over 16 characters, leaves no room for the longest entry, so
`McsSocketDirectory.Resolve` yields no usable directory and every messaging statement of that user is EC-MCS-IMP with a clear reason
(after the PB4742 finisher's fix: a start failure, never an exception). The 2023 messaging facility is therefore unusable for such a user though the
source is legal. Repro (finisher): set TMP and TEMP to a 48-byte directory and run `MessagingPeerTests`; 18 cases went red across the socket classes
and `PlatformAssumptionTests.TheWorstCaseEntry...` names the cause. Two scratch directories from that probe were left behind on the host the
finisher used: `C:\t2345678901234567890123456789012345678901234` and `C:\t1234567890123456789012345678901234567890` (the permission layer refused
their removal; someone deletes them by hand).

**Expected.** The facility works for every Windows user name. A shorter per-user base (for example a fixed short directory the runtime creates
and permission-restricts, or a hashed short name under the temp directory) is a design decision the finisher judged too large for its stop: design
5.1's table states the limit without a remedy. The fix writes the decision into DESIGN-message-control and DESIGN-runtime-library.

Source report and lead: `w20261887g-PB4742-report.md`, finisher Leads.

## Landed (wave 20261915 A) - the Windows fallback

**Decision (implementor latitude; the standard names no path).** The Windows socket directory is the twin of the Unix one: under the temp directory when the longest
entry fits there, else `%ProgramData%\wiseowl-mcs-<u>\<h>\`, `<u>` the first 16 hex digits of the SHA-256 of the user's SID. `%ProgramData%` lets any user create a
directory, so the user level is created owned by the user with a protected access list that grants the user alone, and an existing one is refused unless the user owns
it, it inherits nothing and it allows no one else (the Unix mode-0700 posture). The worst case is 94 bytes under `C:\ProgramData`. Written into
DESIGN-message-control.md 5.1 and 6 (DESIGN-runtime-library.md has no socket-directory section; message-control 6 is the one home).
**Re-probe.** `MessagingPeerTests`, `SocketTransportTests` and `PlatformAssumptionTests` with TMP and TEMP set to a 55-byte directory: 62/62 green (the note measured
18 red), and the fallback directory `C:\ProgramData\wiseowl-mcs-<u>` was created.
Tests: `unit:McsResolutionTests.TheWindowsDirectoryStaysUnderATempPathWithRoom_AndFallsBackToTheUsersProgramDataLevelOnOneTooLong`,
`unit:McsResolutionTests.TheWindowsUserLevelIsTheUsersAlone_AndOneThatInheritsOrGrantsAnotherIsRefused`, `unit:PlatformAssumptionTests.TheWorstCaseEntryOfTheSocketDirectoryFitsMaxPathBytes` (the fallback case).

**Sites:** `src/WiseOwl.Cobol.Runtime/Mcs/McsSocketDirectory.cs` (`Resolve`, `WindowsDirectory`, `WindowsUserKey`, `SecureWindowsUserLevel`), `docs/rearchitecture/DESIGN-message-control.md` (5.1, 6).
