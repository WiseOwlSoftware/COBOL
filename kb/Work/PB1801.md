# PB1801 — a column-carrying source map (research 2026-09-30, tree 4a1dda60e)

No ISO clause governs a compiler's diagnostic positions (process-only, product quality), so this is a design note,
not a conformance finding.

## Measured

- `col.cob` (fixed form, `           DISPLAY NOSUCHNAME.` — `DISPLAY` at column 12): `col.cob(4,5): error COBOLNET1639`
  at `--std 85` and `2023`. The column is program-text-relative (12 − 7 = 5): PB1688's premise holds exactly.
- PB1671 (by its lander, re-read here): `CopyProcessor.cs#Report` / `#ScreenOperandPair` locate through
  `mapped.OriginAt(p)`, which returns a `SourceOrigin(File, Line)` — every COPY/REPLACE diagnostic prints column 1.

## Today's code

- `src/Cobol.Net.Frontend/Common/SourceLineMap.cs#SourceOrigin` — `(File, Line)`; `ToLocation(column)` takes the
  caller's column verbatim.
- `#MappedText` — `SourceOrigin[] Lines`, one per resultant line piece; `#OriginWriter` appends slices keeping each
  piece's origin (a piece takes the origin of its FIRST content).
- Consumers of a resultant position: `src/Cobol.Net.Frontend/Parsing/CobolErrorListener.cs:84` (`lineMap.Origin(line)`,
  then the resultant column), `src/Cobol.Net.Compiler/Binding/EditionContext.cs:107` (`OriginOf`), and the preprocessor
  stages (`CopyProcessor` ×27 `OriginAt`/`ToLocation`, `ConditionalCompilationProcessor` ×5, one each in the TURN,
  FLAG, LEAP-SECOND, COBOL-WORDS and directive-site stages).
- Producers: `ReferenceFormatProcessor.cs#Mapped` (fixed form: origin = physical line; columns 1–7 dropped, so
  resultant column c is physical column c + 7), `#ConvertFreeFormMapped` (identity), the continuation join
  (`FixedFormConverter.Continue` appends a second physical line's text to the first line's piece — the fragment keeps
  the FIRST line's origin, so a diagnostic in the continued text names the wrong line AND column).

## The design (rule 5)

1. **`SourceOrigin` stays (File, Line); a resultant line piece gets `OriginSpan[]`** — ordered
   `(int ResultColumn, SourceOrigin Origin, int SourceColumn)`: resultant columns from `ResultColumn` on come from
   `Origin` starting at physical (expanded) column `SourceColumn`. A plain fixed-form line is ONE span
   `(0, line, 8)`; a free-form line `(0, line, 1)`; a fixed continuation join appends a span at the join point
   `(len(head), continuationLine, 8 + first)` (for a literal: the character after the continuation's quotation
   symbol); a floating continuation (PB1359) the same.
2. **Physical columns are reported, TAB-corrected.** The spans hold EXPANDED columns (what the reference format
   measures); `Locate` converts through the file's `PhysicalLines` tab map (PB1800) to the physical CHARACTER index, so
   an editor's `file(line,col)` jump lands on the character (a TAB counts one, as every editor's column does).
   Recommendation, not an owner decision: no rule governs it and the alternative (report the tab-stop column) makes
   the column disagree with every editor that shows the file.
3. **`OriginWriter` carries spans.** `AppendSlice` offsets the input spans; text a stage WRITES (a COPY statement's
   replacement library text keeps its own spans; REPLACE / REPLACING replacement text takes ONE span at the start of
   the text it replaced — the only honest answer for synthesized text) gets a span at the write point.
   `MappedText.Slice` keeps the spans of its pieces.
4. **One lookup:** `SourceLineMap.Locate(int line, int column, string fallbackFile)` and
   `MappedText.LocateAt(int pos)` return `SourceLocation` with the physical line AND column; `CobolErrorListener`,
   `EditionContext.OriginOf` (which today returns an origin and lets each caller add a column) and every preprocessor
   `OriginAt(p).ToLocation(...)` call change to it. `OriginAt` returning a bare `SourceOrigin` is deleted so no caller
   can reach a column-less origin again.
5. **Drift test.** A characterization test compiles one fixed-form source with a deliberate error at a known column in
   each producer arm — plain line, fixed continuation fragment, after a TAB, inside a copybook, inside REPLACE
   replacement text, after a `>>SOURCE FREE` switch — and asserts `file(line,col)` = the physical position; plus a
   reflection test that `MappedText` exposes no column-less origin accessor.

**Sizing: needs Opus** (it reshapes the one map every mapped stage writes; the 27 CopyProcessor call sites and the
REPLACE line-map (`CopyProcessor.ReplaceLineMap`) must keep the PB82 line invariant). It depends on PB1800 (the tab
map). PB1688 and PB1671 land together through it.

## Update 2026-09-30 (PB1800 landed, DEVLOG 1814) — the prerequisite is in

`PhysicalLines.Read` now yields a `PhysicalLine(Number, Text, Tabs)` per line, and a line that held a tab carries a `TabMap`
(`ToExpanded` / `ToPhysical`, round-trip property-tested in `PhysicalLinesTests`). NOTHING consumes the map yet, so a
diagnostic on a line that held a TAB reports the EXPANDED position (PB1586 made a tab one to eight columns), which is not the
column the programmer's editor shows — the fix is this note's: the origin span list should translate the expanded column
through `PhysicalLine.Tabs.ToPhysical` when it is born. Every `FixedFormConverter` / `ConvertFreeLines` step now has the
`PhysicalLine` in hand, and its `Number` is file-relative (the `lineOffset` parameter is gone), so the span list can be built
where the lines are converted.
