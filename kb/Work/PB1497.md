## Landed (wave 1011, group C) — with the override leg of kb/Work PB1112

- **Owner-less description.** `ObjectRefDescriptor.ActiveClass(string? containing)`: the containing class is NULL for an
  ACTIVE-CLASS item written in an interface method PROTOTYPE (a prototype IS a method definition, §10.6.1 NOTE;
  §13.18.60.3 SR16). `SameDescriptionAs` ignores the containing class of two ACTIVE-CLASS descriptions (§9.3.8.2.3 rule 2 d)
  / 5 d): the phrase and the FACTORY presence only), which also closes PB1112's override pair (probe O2A).
  `DataBinder.OoBindObjectRefDescriptor` refuses the phrase only outside a class body (a program, function or
  program/function prototype), or in a method's WORKING-STORAGE.
- **One wire type.** An ACTIVE-CLASS formal names the ACTIVATION's class (GR22 e)), so it crosses the method ABI as
  `CobolObject?` (`OoEmitter.OoFormalCrossingType`) — the same C# signature for the method, every override of it and the
  interface prototype it implements (a `ref` parameter admits no subclass, the CS0115 trap PB1112 recorded). The body views
  it as its containing class through the checked cast of the copy-in; the INVOKE temporary is the universal type, narrowed
  back into the argument on copy-out. `ValidateImplements`' covariant-return adapter is now chosen by the two C# TYPES the
  returns project to, not by description equality.
- **Sibling found and fixed (I9).** An ACTIVE-CLASS method INHERITED by a subclass and invoked on a subclass instance
  (`INVOKE Y "M" USING Y`, Y `DAC1 ONLY`) generated a `ref DAC1` argument for a `ref CAC1?` parameter (CS1503, a crash on
  legal source); the universal crossing removes the direct-ref path for such formals. Golden `pb1497_active_class_inherited_method`.

## Finding — `conformance-for-object-orientation` (rejects-legal-source; rows `GR-9.3.8.2.3-2`, `GR-9.3.8.2.3-L2.3`)

**Mechanism.** The §13.18.60.3 SR16 placement check refuses USAGE OBJECT REFERENCE [FACTORY OF] ACTIVE-CLASS in an INTERFACE method prototype's LINKAGE SECTION ('written outside a class definition', COBOLNET1924) — SR16 admits 'the linkage or local-storage section of a method definition', and a prototype IS a method-definition (§10.6.1 NOTE) — so rule 2 d) and 5 d) can never be exercised on the IMPLEMENTS leg

**Repro.** --std 2023: INTERFACE-ID. IR2F, METHOD-ID. M, LINKAGE `01 A USAGE OBJECT REFERENCE ACTIVE-CLASS.`, PROCEDURE DIVISION USING A; class CR2F implementing it with the same formal -> COBOLNET1924 at the prototype, then a cascading 0841 (the refused description fell back to universal) (probes R2F, R2G).

**Expected from the spec.** The prototype is accepted (§13.18.60.3 SR16: 'The ACTIVE-CLASS phrase may be specified only in a factory definition, an instance definition, or the linkage or local-storage section of a method definition'; §10.6.1 NOTE: 'A method-definition in an interface-definition defines a method prototype'), and the class conforms under rule 2 d) (ACTIVE-CLASS on both sides, same FACTORY presence).

**Observed / reasoning.** DataBinder.Oo.OoBindObjectRefDescriptor refuses whenever !OoIsClassUnit || OoOwnerClassName is null — an interface unit has no owner class, so the linkage-of-a-method-definition leg of SR16 is never reached for a prototype. ObjectRefDescriptor.ActiveClass needs a containing-class name, so the model itself has no shape for an interface-side ACTIVE-CLASS; fixing this needs an owner-less ACTIVE-CLASS descriptor (which also removes the Name dependence in the previous finding). This is the SR-13.18.60.3-16 row's defect; it is reported here because it makes rule 2 d)/5 d) unreachable.

**Code site.** src/Cobol.Net.Compiler/Binding/DataBinder.Oo.cs#OoBindObjectRefDescriptor

## What the fixer owes

DataBinder.Oo.cs#OoBindObjectRefDescriptor's SR16 placement test must accept a method PROTOTYPE's linkage section (interface method definitions, and program/function prototypes where SR16 allows). Then exercise rules 2 d)/5 d) on the IMPLEMENTS leg with PB1112's corrected ACTIVE-CLASS comparator. Golden: IR2F/CR2F from the repro; negative: ACTIVE-CLASS in a program's WORKING-STORAGE (still refused).
