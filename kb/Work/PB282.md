# PB282 — the unclaimed module the compiler implements

`docs/CONFORMANCE.md` §5 recorded **"A.4.13 | REWRITE FILE and WRITE FILE | Not claimed | No surface — a parse
error today"**. Both halves of that note are **false**, measured 2026-09-02, and they are false in two
*different* directions — which is `feedback_two_arm_dispatch` verbatim: one construct, two arms, two postures,
neither of them the documented one.

## What is actually there

`src/Cobol.Net.Frontend/Grammar/Core/CobolIO.g4` carries `writeStatement : WRITE (recordName | FILE fileName) …`
and `rewriteStatement : REWRITE (recordName | FILE fileName) …`. **FILE is reserved at every edition**
(`tests/version-matrix/reserved-words.json`: r85 / r2002 / r2014 / r2023 all true), so it can never be a
user-defined word and the `FILE fileName` alternative is the ONLY parse of that source. It is reached.

**Arm 1 — `WRITE FILE F FROM X` compiles and RUNS, with no diagnostic at any edition.**
`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/SequentialIoBinder.cs` has a live
`else if (w.fileName() is { } fn && ctx.Data.FilesByName.TryGetValue(fn.GetText(), out var f) && f.AreaRecord is
{ } far)` arm that writes the whole record area through `FileModel.AreaRecord`. That is **undeclared support for
an unclaimed optional module** — and it is not even the standard's model: §14.9.51.4 GR8's implicit-record-1 takes
the description of *identifier-1*, not the largest record's view. So the module is simultaneously unclaimed,
undiagnosed and **wrong**.

**Arm 2 — `REWRITE FILE F FROM X` compiles clean and fails at RUN TIME.** `BindRewrite` reads only
`rw.recordName()`, so the FILE arm falls through to
`new BoundUnsupported($"REWRITE record '{rw.recordName()?.GetText()}' not resolvable to a file")` — and
`StatementEmitter` turns `BoundUnsupported` into `NotImplemented.Run(...)`, a run-time throw. The interpolated
name is **empty on this path**, because `recordName()` is null exactly when the FILE arm was taken: the message
reads ``REWRITE record '' not resolvable to a file``.

Neither `FlagConformancePass` nor `VersionConformancePass` gates the alternative; there is no edition predicate on
it, no `constructs.json` row, no named diagnostic anywhere in `src/` or `docs/DIAGNOSTICS.md`, and no test in
`tests/conformance` or `tests/characterization` touches the construct.

## Why it matters, in the standard's own terms

A.4.1: *"An implementation shall accept the syntax and provide the functionality for an optional element **only
when** support for that language element is claimed by the implementor."* (`--check` → OK). We claim A.4.13 in no
documentation, and we accept its syntax and provide (part of) its functionality. The harm is not theoretical: a
program using `WRITE FILE` compiles here and writes bytes by a rule the standard does not specify, and the same
program's `REWRITE FILE` sibling compiles and then dies in production with a message naming nothing.

## The fix, and it is one place rather than two

⛔ **Do not gate the WRITE arm — DELETE it** (CLAUDE.md rule 4: fix the root cause, not add a guard in front of
it). It is undeclared support for an unclaimed module and it implements the wrong record model.

Raise ONE named diagnostic in the COBOLNET1560 non-support band from **the single shared point where both
statements name their target** — `CheckFilePhraseUnclaimed(ctx.fileName())` on the shared IO path, not two call
sites, because the shape that makes the next arm automatic is the one to prefer
(`feedback_one_mechanism_per_job`). Take the next free code from `scripts/session-probe.ps1`.

**The witness set, in one commit with the goldens and the manifest rows:**

1. `tests/conformance/negative/a413_write_file_unclaimed.cob` and `…/a413_rewrite_file_unclaimed.cob` — the
   minimal Format-1 shapes `WRITE FILE F FROM WS-REC` and `REWRITE FILE F FROM WS-REC`, each asserting the code
   BY NAME. **These two must land as a PAIR**: the current asymmetry is precisely how a fix lands on one arm and
   the queue reads green.
2. **The positive control**, without which this is a green gate that never looked
   (`feedback_green_gates_arent_evidence`): `WRITE REC FROM WS-REC`, `REWRITE REC FROM WS-REC` and
   `WRITE REC AFTER ADVANCING 1 LINE` still compile and RUN to correct output — proving the gate keys on the FILE
   arm and has not taken the two mandatory statements down with it. Run it once against the pre-fix compiler and
   see the negatives fail and the control pass before trusting the suite.
3. ⚠ **ANSWER THE EDITION QUESTION FROM THE STANDARD BEFORE WRITING A FOUR-EDITION SWEEP.** Optional-module
   non-support and edition INTRODUCTION are different questions (`feedback_four_editions_one_compiler`). Annex E's
   substantive-change list carries no WRITE/REWRITE FILE-phrase item, `VERSION_CHANGE_REFERENCE.md` has no entry,
   and `constructs.json` has zero rows for the construct — so **nothing in this tree establishes the introduction
   edition**. If the phrase is post-85, the COBOL-85 leg's correct diagnostic is the introduction gate, not the
   A.4.13 code, and a sweep demanding one code at all four editions would pin the wrong answer as a golden.

## Two stale citations ride the same grammar rules, repair them here

`CobolIO.g4`'s header comments say **"WRITE (§14.9.46 …)"** — §14.9.46 is TERMINATE — and **"REWRITE
(§14.9.36)"** — §14.9.36 is ROLLBACK. The correct clauses are §14.9.51 and §14.9.35, which the same file cites
correctly in its body comments. And the premise this whole row inherited,
`PHASE-13-plan-vs-spec-review.md` R5's *"A.4.13: zero REWRITE FILE/WRITE FILE code surface"*, is false; §5's note
was that claim propagated. `CONFORMANCE.md` §5 is corrected in the landing change set.

## The 12 rows

flipped 83 rules of two mandatory statements. They stay a GAP until the witness above lands.
