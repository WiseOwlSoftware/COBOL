# R55 — TAB in a literal

The tab width (stops every 8 positions) was settled by DOC-A.1-157. Open was the tab INSIDE an alphanumeric literal: expand, keep the character, or reject. GnuCOBOL's reader expands tabs before the scanner (`pplex.l`), so a literal's tab becomes spaces. **Owner: expand to spaces** — one rule for every TAB, applied once at the line-entry stage (`PhysicalLines`, PB1800); a program that needs a TAB character in data writes it as a hexadecimal-alphanumeric literal `X"09"`.

## Re-verified against the ISO text (2026-09-30)

The ISO text does not mention a horizontal tab character anywhere in the reference-format or character-repertoire clauses (searched), so tab handling is implementor-defined and already documented as such (Annex A.1 item 157, DOC-A.1-157: stops every 8 positions). Rule 1 then selects GnuCOBOL, whose reader expands tabs before the scanner. A tab inside a literal is therefore expanded like every other tab. Not an owner-discretion question; `X"09"` remains the way to put a TAB in data.
