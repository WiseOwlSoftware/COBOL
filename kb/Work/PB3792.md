# PB3792 — the meter test does not test the dedupe

**Sites:** `scripts/orchestrator/test_orchestrate_meter.ps1` (line 23), `scripts/orchestrator/orchestrate.ps1#Report-MeterUnreadable`

## Measured

`test_orchestrate_meter.ps1:23` asserts `[regex]::Matches($q, 'meter unreadable').Count` is 2 ("the heading and the marker
line"). In case 1 (`-MaxUnits 4`) and case 3 (the breaker trips after unit 4) the gate is reported at exactly one choice,
so Report-MeterUnreadable runs once and the count of 2 holds even if the `Select-String` marker short-circuit in
orchestrate.ps1 never fires. Deleting the dedupe leaves the test green, so a second report to the owner per choice, the
defect the check exists to forbid, would not be caught.

## Acceptance

- A case where the gate is reported at two choices in one run asserts the owner's question holds ONE marker line.
- The test fails when the short-circuit is removed (shown by deleting it once, locally, and recording the red).
