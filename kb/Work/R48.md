# R48

Asked 2026-09-25 (doc-rows-2, A.1 item 167 — run unit and non-COBOL components): "When a COBOL program is called
from a .NET host application and executes STOP RUN (or hits a fatal exception), what should happen to the host?"
Options: end the run unit, host continues · exit the whole process (GnuCOBOL).

**Answer: end the run unit; the host continues (recommended).** The CLAUDE.md rule-1 precedence would have followed
GnuCOBOL's process exit; the owner overrides it here because COBOL.NET is meant to be embedded in services and
applications. Implementation (owning notes PB1149, PB1253, PB1069): STOP RUN / a fatal EC closes every file of the run
unit, resets run-unit state (including SET LOCALE, item 168), and surfaces to the host as ONE documented, catchable
result carrying the exit status — never an arbitrary exception type, never Environment.Exit. A standalone `cobol`
executable still exits its own process with the status (it IS the host).

# Also recorded here — orchestrator application of standing decisions (not an owner question)

doc-rows-2 writer d1 asked whether the alphanumeric coded character set (A.1 items 31, 36, 38) is the whole UTF-16 BMP
or one byte per position. That is already decided: memory `project_charset_utf16` (the repertoire is full UTF-16 by
design — "do not re-frame Unicode as an open fork") plus R47 (files: Latin-1, refuse above U+00FF). Determination: the
alphanumeric coded character set is the UTF-16 BMP; its BYTE image (DOC-A.1-209, §8.1.2) is one byte per position in
ISO 8859-1; a character above U+00FF has no byte image — EC-DATA-CONVERSION at in-memory byte channels (DOC-A.1-33),
an I-O status refusal at a file (R47).

**Confirmed 2026-09-25:** after reviewing the pros and cons (GnuCOBOL's process exit vs. run-unit isolation; IBM LE's
enclave end and Micro Focus .NET RunUnit as the nearer precedents; the cost — run-unit isolation must be real, e.g.
PB1570's process-wide sort store), the owner answered "keep R48". No process-exit switch.
