**What leaks.** DESIGN-backend-abstraction §1.2 forbids "the name of a C# METHOD LOCAL" on a node: a CIL method
addresses its locals by slot. PB4321 gave every binder statement local a `MethodLocal` identity and a CORRESPONDING
anchor a `LocalRootSegment`, but three roots still carry a local's NAME in `RootFieldSegment.CsField`, whose other
values are program-class members:
- the METHOD arm's carrier-resident formal: `DataBinder.OoBindMethodData` sets `DataItem.ResidentCarrier =
  OoFormal.CarrierLocal` (`__lnk{Uid}`, a local of the method), and `ReferenceResolver.AddRoot` roots every access
  at `RootFieldSegment(item.ResidentCarrier)` (the PROGRAM arm's carrier, `LinkageFormal.CarrierField`, is a class
  member, a CLR name);
- the Roslyn backend's own hoisted cell: `PlaceIdentification.FreezeView` re-roots a cell-backed view at
  `RootFieldSegment(local)` for the local it hoisted;
- a recreated dynamic table's element cell: `PlaceRenderer.CellLeavesStore` hands `ViewCursor.AtElementCell` the
  lambda parameter `__le{depth}`, which roots the cursor at `RootFieldSegment(cellLocal)`.

**Fix direction.** Each root becomes a `LocalRootSegment`: the carrier local a `MethodLocal` the binder makes (a new
role, spelled `__lnk{Uid}` by `LocalNames.Of`, so the OO emitter's declaration and every reference agree), the two
backend locals `CSharpLocal`s. `DataItem.ResidentCarrier` then holds a carrier FACT (the program's member or the
method's local identity), not a name, and `RootFieldSegment.CsField` holds only a member's CLR name and can be renamed
for it (`MemberClrName`). The two backend locals change `PlaceRenderer.Received`'s BASED-area match and `FreezeView`'s
re-hoist, so the emitted C# may change (fewer hoists): prove each difference with `scripts/arch/compare_oracle.py`
and explain it by class, or keep the emitted C# identical. The landing deletes the L8 leak row of
`BackendContract.Table` (`Model.RootFieldSegment.CsField`, `Model.DataItem.ResidentCarrier`) and marks §1.3 L8 DONE
with no residue.

## Landed (wave 20261814 C)

**Re-probe (base ab63c898e).** All three roots stood as the note says. The method arm: `DataBinder.OoBindMethodData`
set `DataItem.ResidentCarrier = formal.CarrierLocal` (the string `__lnk{Uid}`), `ReferenceResolver.AddRoot` rooted the
formal at `new RootFieldSegment(carrier, ...)`, and the base's emitted C# for `suite/2002/oo_method_args` declared that
name as a method local, `ManagedPointer<string> __lnk1 = __omitted0 ? ... : __formal_LK_AMT;`.
`PlaceIdentification.FreezeView` re-rooted a hoisted cell at `new RootFieldSegment(local, ...)`, and
`ViewCursor.AtElementCell(DataItem, string)` rooted the element cell at `new RootFieldSegment(cellLocal)`, the
`__le{depth}` lambda parameter `PlaceRenderer.CellLeavesStore` passed. `BackendContract.Table` tolerated
`Model.RootFieldSegment.CsField` and `Model.DataItem.ResidentCarrier` as its L8 row.

**Fix.** Every root is a `RootSegment` (`Binding/Model/AccessPath.cs`), the one type that carries a formal's
*-ARG-OMITTED guard: `RootFieldSegment(MemberClrName, Guard, Anchor)` holds only a CLR name, and
`LocalRootSegment(MethodLocal, Guard)` is a local by identity, now guarded too. The guard's rendering
(`PlaceRenderer.RenderPath`), the "evaluates at run time" test (`PlaceIdentification.PathEvaluates`) and the BASED
area's received-reference record (`PlaceRenderer.Received`) ask `RootSegment`, so they answer for both kinds.
`DataItem.ResidentCarrier` is a `FormalCarrier` fact (`Binding/Model/FormalCarrier.cs`): `Member(MemberClrName)` for
the program arm's class member, `Local(MethodLocal)` for the method arm's local, each making its own root
(`FormalCarrier.Root`), so `AddRoot` asks the carrier, not the arm. The method's carrier is the new
`StatementLocalRole.MethodFormalCarrier` (ordinal = the formal's Uid, `OoFormal.Carrier`), declared by `OoEmitter` as
`LocalNames.Of(bf.Carrier)`. The AREA formal's per-activation pointer, a member, is `OoFormal.AreaPointerClrName`
(`__lnk{Uid}`, unchanged). The two backend locals are `CSharpLocal`s on a `LocalRootSegment`
(`FreezeView`, `CellLeavesStore` -> `AtElementCell(DataItem, MethodLocal)`).

**The emitted C# changed in one class.** The method carrier's stem is `__mlnk`, not `__lnk`: `__lnk{Uid}` is also the
program arm's carrier MEMBER, which the binder names in `DataBinder.CallBindLinkage`, and
`MethodLocalIdentityDriftTests.NoBinderSource_SpellsALocalStem` refuses a binder literal holding a local's stem. The two
were never one name; they only shared a spelling. `scripts/arch/compare_oracle.py --base ab63c898e`: 104 of 15829 cases
differ, every one an OO method with a resident formal, and each is byte-identical once `__mlnk` is read as `__lnk`
(classified by script, no other class). The `FreezeView` and `AtElementCell` changes emit identical C#.

**Witness.** `ModelAccessStructureTests.AMethodsResidentFormal_IsRootedAtItsCarrierLocalsIdentity` binds a class whose
method has a resident formal and asserts its path is `[LocalRootSegment(StatementLocal(MethodFormalCarrier, uid)),
CarrierValueSegment]` with the formal's guard; planted back to a `RootFieldSegment`, it failed on the segment types.
`TheFormerAccessTextCarriers_HoldNoStringButAName` now covers `RootFieldSegment`, `LocalRootSegment` and both
`FormalCarrier` arms. The L8 row is deleted from `BackendContract.Table`; §1.3 L8 is DONE.

**Also fixed (I9).** The §14.7.6 citation on `LocalRootSegment` and `StatementLocalRole.CorrespondingSendingAnchor`
quoted text the standard does not have ("the identification is done at the start of the statement"); both now quote
§14.7.6's "Any item identification associated with a corresponding pair of operands is done at the start of the execution
of the statement containing the CORRESPONDING phrase" (`cite.py --check` OK).

- `src/WiseOwl.Cobol.Compiler/Binding/Model/FormalCarrier.cs#Root` — a carrier-resident formal's root; a third carrier
