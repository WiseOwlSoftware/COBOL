# PB1698 — HALF (mechanism landed; evaluation open)

**Owner, 2026-09-28 ~10:10 PDT:** "Add it to the wave and evaluate its effectiveness. I will wait to post the
response until we have data". The response is a reply to an outside reviewer who asked whether "read the commits,
not the summary" gives back the orientation savings the summaries were meant to buy.

## The defect

Wave 68's group Y and group U agents died after committing but before rewriting STATUS.md. Each follow-on agent found a
summary that silently omitted the last commit(s). The fallback rule became "read the commits, not the summary", which
costs a re-read of the whole branch on EVERY resume, stale or not. Orientation is the dominant cost: it was 46 % of
implementer tokens in waves 45–57.

## The mechanism (landed with this note)

- STATUS.md's first line is `STATUS-AT: <full sha>`, written AFTER the checkpoint commit. STATUS.md is gitignored, so
  writing it never moves HEAD.
- `scripts/spec/status_delta.py <worktree>` (or `--status <file> --ref <branch>`) prints one of:
  - CURRENT (exit 0): the summary covers every commit;
  - STALE by N (exit 1): the only commits to read, with their file stats;
  - UNSTAMPED or DIVERGED (exit 2): every commit since the base, as before.
  It always prints the uncommitted changes as well.
- Wired into the fix-lane implementer brief, the dispatch-spec template, MANDATORY-PRACTICES P4, the rolling wave's
  same-file successor text and `check_practices.py`, which refuses a brief or spec without it.

## Evaluation (OPEN — this note closes when both are recorded)

1. **Controlled A/B (2026-09-28).**
   - Scenario: wave-68 group U's real stale branch (`worktree-wf_e9a82a33-6b6-4`). Its STATUS.md describes
     59f19d6e8, and the preservation commit aaf1823fc (PB1579 WIP in four files) came after it.
   - Arms: OLD (the unstamped STATUS.md plus the pre-stamp instruction "read it and `git log`") versus NEW (the same
     STATUS.md stamped at 59f19d6e8, plus `status_delta.py`). Three fresh read-only Opus agents per arm.
   - Each agent must reconstruct the branch state and the exact next step, then stop before any edit.
   - Measured: turns, tokens and wall time to a finished state report, and CORRECTNESS against the known truth: did
     it find aaf1823fc's uncovered, ungated PB1579 work?
   **RESULT (workflow wf_2190fcf0-fec, 2026-09-28 10:15 PDT; 8/8 agents returned, 623 k subagent tokens):**

   | arm | turns | tool calls | tokens processed (incl. cache reads) | wall time | commits inspected | correct |
   |---|---|---|---|---|---|---|
   | OLD (unstamped, "read it and git log") | 14.8 (11–19) | 15.8 | 1.00 M | 147 s | 6.5 | 4/4 |
   | NEW (stamped + status_delta.py) | 10.2 (9–12) | 11.8 | 0.67 M | 116 s | 4.5 | 4/4 |

   - Correct means all three of: named aaf1823fc as uncovered and characterized it as partial PB1579 work; said the
     branch was never gated; chose to resume on top of it rather than restart. All 8 agents were correct. (The
     scorer's regex first missed NEW-1's "GATE: never run on this branch"; the answer was re-read by hand.)
   - The stamp cut turns by 31 %, tokens processed by 33 % and wall time by 21 %, at equal accuracy.
   - Most stamped agents still spot-checked earlier commits (1, 5, 6 and 6 inspected), which is the intended
     "navigation, not evidence" behavior; the saving came from not having to reconstruct coverage.
   - Limits: n = 4 per arm, one branch of 6 commits, orientation only (no build). The CURRENT case (stamp = HEAD)
     was not measured. Score: `scratchpad\stamp-eval\score.py`.

2. **Production (waves 70+).** Every resumer and same-file successor from wave 70 on: turns and tokens up to its first
   source edit, against the pre-stamp baseline of the wave 68/69 finishers and successors. Wave 70's U (resuming an
   unstamped branch under the old rule) and U2 (the first stamped successor) are the first pair.
