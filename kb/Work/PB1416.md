## Finding — `function-address-identifier` (rejects-legal-source; rows `FMT-8.4.3.12.2`)

**Mechanism.** The lexer retypes the '(' immediately after 'FUNCTION <word>' to FNARG_LPAREN (the intrinsic argument-list paren), and subscriptPart accepts only LPAREN (refModPart accepts both), so a directly subscripted identifier-1 in ADDRESS OF FUNCTION identifier-1 cannot parse.

**Repro.** REPOSITORY. FUNCTION FAIDBL.  01 FP1 USAGE FUNCTION-POINTER TO FAIDBL.  01 WS-NAMES. 05 WS-NAME PIC X(6) OCCURS 2.  ...  MOVE "FAIDBL" TO WS-NAME(2)  SET FP1 TO ADDRESS OF FUNCTION WS-NAME(2)  IF FP1 = NULL DISPLAY "REF-NULL" ELSE DISPLAY "REF-SET". (probe/fai/p1h.cob, --std 2023; same at 2014)

**Expected from the spec.** Compiles and prints REF-SET: 8.4.3.12.2 admits identifier-1, 8.4.3.1.3 SR1 makes identifier-1 any identifier format including a subscripted one, and 8.4.3.12.4 GR1 a) takes the function from the content of the referenced item ('FAIDBL', a REPOSITORY function).

**Observed / reasoning.** p1h.cob(26,53): error COBOL0001: missing token before ')' (also with a space before the paren). The qualified spelling 'WS-NAME OF WS-NAMES (2)' parses and prints REF-SET, and a ref-mod 'WS-NAMES(7:6)' parses, isolating the defect to the FNARG_LPAREN retype vs subscriptPart.

**Code site.** src/Cobol.Net.Frontend/Grammar/Core/CobolLexer.g4#OnDefaultLParen; src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4#subscriptPart (line 699) vs refModPart (line 758); src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4#setFunctionAddressStatement (line 1715)

## What the fixer owes

Let subscriptPart accept FNARG_LPAREN where the preceding FUNCTION word is an identifier (or stop retyping after ADDRESS OF FUNCTION); positive golden.
