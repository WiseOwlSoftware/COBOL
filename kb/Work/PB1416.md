## Finding — `function-address-identifier` (rejects-legal-source; rows `FMT-8.4.3.12.2`)

**Mechanism.** The lexer retypes the '(' immediately after 'FUNCTION <word>' to FNARG_LPAREN (the intrinsic argument-list paren), and subscriptPart accepts only LPAREN (refModPart accepts both), so a directly subscripted identifier-1 in ADDRESS OF FUNCTION identifier-1 cannot parse.

**Repro.** REPOSITORY. FUNCTION FAIDBL.  01 FP1 USAGE FUNCTION-POINTER TO FAIDBL.  01 WS-NAMES. 05 WS-NAME PIC X(6) OCCURS 2.  ...  MOVE "FAIDBL" TO WS-NAME(2)  SET FP1 TO ADDRESS OF FUNCTION WS-NAME(2)  IF FP1 = NULL DISPLAY "REF-NULL" ELSE DISPLAY "REF-SET". (probe/fai/p1h.cob, --std 2023; same at 2014)

**Expected from the spec.** Compiles and prints REF-SET: 8.4.3.12.2 admits identifier-1, 8.4.3.1.3 SR1 makes identifier-1 any identifier format including a subscripted one, and 8.4.3.12.4 GR1 a) takes the function from the content of the referenced item ('FAIDBL', a REPOSITORY function).

**Observed / reasoning.** p1h.cob(26,53): error COBOL0001: missing token before ')' (also with a space before the paren). The qualified spelling 'WS-NAME OF WS-NAMES (2)' parses and prints REF-SET, and a ref-mod 'WS-NAMES(7:6)' parses, isolating the defect to the FNARG_LPAREN retype vs subscriptPart.

**Code site.** src/Cobol.Net.Frontend/Grammar/Core/CobolLexer.g4#OnDefaultLParen; src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4#subscriptPart (line 699) vs refModPart (line 758); src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4#setFunctionAddressStatement (line 1715)

## What the fixer owes

Let subscriptPart accept FNARG_LPAREN where the preceding FUNCTION word is an identifier (or stop retyping after ADDRESS OF FUNCTION); positive golden.

**Code site (located 2026-09-27).** `src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4#subscriptPart`; also `src/Cobol.Net.Frontend/Grammar/Core/CobolLexer.g4#OnDefaultLParen`, `src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4#setFunctionAddressStatement` (code). subscriptPart (CobolParserCore.g4:701) accepts only LPAREN while refModPart (760) accepts FNARG_LPAREN too; the lexer member OnDefaultLParen (CobolLexer.g4:126, LPAREN action line 1003) retypes '(' after FUNCTION word

## Landed 2026-10-04 (wave 1014 group S)

Re-probed on this tree (59ef8b01b): `p1h.cob` (`SET FP1 TO ADDRESS OF FUNCTION WS-NAME(2)`) → COBOL0001 "cannot parse
construct near ')'". After the fix it prints `REF-SET`.

- **Root cause, in the lexer, not the parser.** `PreviousIsFunctionName` answered "yes" for the word after EVERY
  FUNCTION token, so the `(` after `ADDRESS [OF] FUNCTION word` became §8.4.3.2.3 SR6's argument paren
  (FNARG_LPAREN, DEFAULT mode) and `subscriptPart` (LPAREN, SUBSCRIPT mode) could not take it. §8.4.3.12.2's operand
  is a prototype name (no argument list) or identifier-1 (any identifier format, §8.4.3.1.3 SR1), so that FUNCTION never
  heads a function-identifier. `CobolLexer.g4` now records, as each FUNCTION token is emitted, whether it follows
  ADDRESS or ADDRESS OF (`_functionIsAddressOperand`; OF optional, not underlined), and `PreviousIsFunctionName` is false
  for it. A nested `ADDRESS OF FUNCTION FUNCTION F(…)` is unaffected: the second FUNCTION follows FUNCTION.
  The note's alternative (let `subscriptPart` take FNARG_LPAREN) was rejected: it would leave the subscript's content in
  DEFAULT mode, a second way to lex one subscript.
- Golden `2014/pb1416_function_address_subscripted_identifier` (subscripted `WS-NAME(2)`, OF omitted with a variable
  subscript, reference-modified `WS-LONG (3:7)`, each compared to the prototype arm's address). No negative: the
  construct's edition gate (USAGE FUNCTION-POINTER, 2014) is unchanged and already witnessed.
- Row FMT-8.4.3.12.2 DIVERGES → CONFORMS (batch `w1014s/batch-pb1455-pb1416.json`).
- Found, not fixed (lead in the w1014s report): `SET FP TO ADDRESS OF FUNCTION FUNCTION UPPER-CASE(WS-NAME (1))`
  followed by any statement is COBOL0001 at that statement on the PRE-change lexer too (the unspaced `WS-NAME(1)`
  parses); cause not located.
