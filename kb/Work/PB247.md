# PB247

**Rows:** `AR-15.87.3-3`

SUBSTITUTE's §15.87.3 r3 zero-length argument-2 walk sits BELOW the table-ALL early return, so a statically zero-length argument-2 written before an enumeration is accepted.

ROW: AR-15.87.3-3 (§15.87.3 r3 — 'Neither argument-1 nor argument-2 shall be of zero length').

WHAT IS VERIFIED. Argument-1's half is closed by code reading: `ArgPredicate.MinWidth(1, "§15.87.3 r3")` rides position 0 and is evaluated through `PredicateViolation` with `KnownWidth` on BOTH exits of `BindSubstitute`; `KnownWidth` is total over the static shapes (literal length, literal-length ref-mod, group `ImageWidth` when nothing beneath varies, ALL literal, figurative = 1) and null only for a genuinely runtime width — the documented fail-open. Argument-2's half on the ORDINARY path is closed by two enabled negative fixtures (`negative/pb58-subst-zero` = `SUBSTITUTE(X3 "" "Z")`, pair 1; `negative/pb58-subst-zero2` = `SUBSTITUTE(X3 "A" "Z" "" "Q")`, pair 2), both `.err` = COBOLNET1627, both citing §15.87.3 r3. And `2023/pb58_argument_predicates_legal` supplies r3's NEGATIVE SPACE — `SUBSTITUTE(X3 "A" "" "C" "ZZ")` with `SUBST=[BZZ…]` — proving the odd-position walk SKIPS the even positions and does not over-reject a legal zero-length argument-3, which the two rejection fixtures cannot show.

THE HOLE, by control flow and not by sampling. Once any operand is a table enumeration the binder sets `flat = true` and returns inside the `if (flat)` block, which sits ABOVE the odd-position walk. `FUNCTION SUBSTITUTE(X3 "" "Q" T(ALL))` therefore binds clean although `operands[1]` is a statically known zero-length argument-2 — `flat` is only set when `T(ALL)` is REACHED, by which point the walk has been skipped. The shape is real and shipped: `tests/conformance/2023/pb81_substitute_table_all.cob` mixes written operands with enumerations (`SUBSTITUTE("aXbXc" "X" T3(ALL) "-")`). Argument-1's half is unaffected there because its predicate rides the schema and `CheckArgumentClasses` IS called on the flat path (:1203).

NO WRONG ANSWER RESULTS, and that is why it is under_rejects and not wrong_answer: the RVR twin is present — `CobolIntrinsics.Text.cs:401` tests `source.Length == 0 || froms.Any(f => f.Length == 0)`, raises EC-ARGUMENT-FUNCTION and returns a zero-length value per §15.87.4 r1, and `SubstituteFlat` funnels into that same kernel. But §15.87.4 r1 is the RETURNED-VALUE rule and cannot close an ARGUMENT rule.

TWO FURTHER GAPS THE ROW RECORDS. (i) No fixture exercises the ARGUMENT-1 half of r3 — both existing negatives target argument-2. (ii) `CorpusRunnerTests.EnabledNegativeCase_RejectsWithItsDiagnostic` asserts only the diagnostic CODE, and COBOLNET1627 has FOUR producers (the class screen, the per-position predicate screen, CrossViolation, and this r3 walk); on these two inputs only the r3 walk can fire, so they do exercise r3, but they would not distinguish a future regression producing 1627 from a different arm.

FIX SHAPE: decide r3 for every statically-known operand BEFORE the flat early return (the widths are known there — `CheckArgumentClasses` already runs on that path), or move the walk above the `if (flat)` block and let the run-time pairing remain a run-time fact. Goldens: a zero-length argument-1, and a mixed written-operand + enumeration negative.

VERIFIED LIVE AT HEAD (read-only): the `if (flat)` return at :1198-1204 still precedes the r3 walk at :1219-1226.

## Mechanism

src/Cobol.Net.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs — the `if (flat) { … CheckArgumentClasses(sig, operands); return new BoundIntrinsicCall(…); }` block at :1198-1204 returns ABOVE the odd-position r3 walk at :1219-1226 (`if (KnownWidth(operands[i]) is 0) … COBOLNET1627 … "§15.87.3 r3"`); the schema row at IntrinsicArgumentRules.cs:791-793 carries `MinWidth(1, "§15.87.3 r3")` on position 0 only, with no tail predicate

## Lineage

PB58 (landed) built the schema and the r3 walk; PB62 (landed) introduced the flat/table-ALL bind whose early return the walk now sits below. Neither note records the interaction.
