## Finding — `inline-method-invocation` (under-rejects; rows `SR-8.4.3.4.3-4`)

**Mechanism.** Predefined NEW bypasses §8.4.3.4.3 SR4: OoBindImplicitNew synthesizes an ONLY-typed temp instead of checking NEW's ACTIVE-CLASS RETURNING description

**Repro.** REPOSITORY. CLASS PB428ACC. ... MOVE PB428ACC :: "NEW" :: "GETNAME" TO W. (exactly case 7 of tests/conformance/2002/pb428_inline_method_invocation.cob); compile --std 2023 --run

**Expected from the spec.** §16.2 BaseFactoryInterface: New's RETURNING item is '01 outObject usage object reference active-class'; §8.4.3.4.3 SR4: the RETURNING data item of the invoked method 'shall not be described with ... the ACTIVE-CLASS phrase'. So object-class-name-1 :: "NEW" (and SELF/SUPER :: "NEW") is a syntax-rule violation: compile-time diagnostic COBOLNET2140.

**Observed / reasoning.** Accepted and runs (7=ACCOUNT). OoBindClassInvoke routes ReturningImplicit NEW to OoBindImplicitNew, which never reaches the SR4 checks in OoBindResolvedInvoke. The SELF::"NEW" arm is rejected, but by COBOLNET0826 'without RETURNING' (wrong rule). The pb428 golden case 7 must move to a negative fixture.

**Code site.** src/Cobol.Net.Compiler/Binding/Procedure/Verbs/OoBinder.cs#OoBinder.OoBindClassInvoke (site.ReturningImplicit -> OoBindImplicitNew); src/Cobol.Net.Compiler/Binding/Procedure/Verbs/OoBinder.InlineInvocation.cs#OoBinder.OoBindImplicitNew; OoBindByReceiver SELF/SUPER NEW arm

## What the fixer owes

Route the implicit NEW through the same SR4 returning-description screen as a declared method; negative golden.

## Landed (wave 59, implementer J — with PB1548)

OoBindImplicitNew is deleted. New is the standard class BASE's factory method with its section 16.2 signature (RETURNING
`object reference active-class`), and every invocation of a BASE method binds through `OoBinder.OoBindStandardInvoke`,
which refuses the inline form with COBOLNET2140 (section 8.4.3.4.3 SR4). Witness: negative `pb1548-inline-new-active-class`.
Golden `2002/pb428_inline_method_invocation` step 7 now invokes the factory method OPENACC (same output) instead of
the refused `PB428ACC :: "NEW"`.
