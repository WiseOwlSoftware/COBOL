## Scope

Every open kb/Work note whose subject is SORT/MERGE or file I/O, in any area: the runtime, the binder, code generation,
validation, diagnostics, tests and goldens, documentation, citations and traceability. File I/O covers every
organization (sequential, line sequential, relative, indexed), sort-merge files (§9.1.19, §9.1.20) and report files
(§9.1.22), the I-O statements and their I-O status values (§9.1.13), sharing (§9.1.15) and record locking (§9.1.16),
commit and rollback (§9.1.18), and the runtime's file and stream layers. The SORT statement on a table (PB1951's table
SORT) counts as SORT. Console ACCEPT/DISPLAY does not, unless the note is about a file. Report Writer notes count when they
are about the report FILE (its record structure, its page advance, the status of its writes), not when they are about
report-group layout.

The two redesigns of 2026-10-17 define the shape:
- **PB3339** (landed, PR #201): SORT and MERGE keep their records in bounded memory, with sorted runs on temporary files
  and a k-way merge (`src/Cobol.Net.Runtime/IO/SortWork.cs`; docs/CONFORMANCE.md §3 D-SWK).
- **PB3330** (designed on branch `design-pb3330-keyed-storage-20261017`, not on main when this note was filed): a paged
  on-disk engine for RELATIVE and INDEXED files, DESIGN-runtime-library.md §2.2.1, implemented as groups PB3331-PB3338
  and PB3340. Section 2.2.1.13 of that design document lists what it deletes and what it keeps.
