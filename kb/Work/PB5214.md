# PB5214 - a COPY statement written on a debugging line, in a program without WITH DEBUGGING MODE, still brings its library text in as ordinary source and the copied statements run: the copied lines do not carry the debugging-line marker, so DebuggingLineRewriter never hides them

**Sites:**

- `src/WiseOwl.Cobol.Frontend/Preprocessor/CopyProcessor.cs` (`ExpandCopiesOneLevel`, `ResolveOneCopy`)
- `src/WiseOwl.Cobol.Frontend/Preprocessor/TextWord.cs` (`TextWordScanner.TryNext`)
- `src/WiseOwl.Cobol.Frontend/Parsing/DebuggingLineRewriter.cs` (`DebugLines`)

**Mechanism.** 1985 makes the text a COPY statement brings in inherit the statement's debugging line: "each text word introduced appears on a debugging line if the COPY statement begins on a debugging line" (§1985:XII.2.4 GR9), and without WITH DEBUGGING MODE "any debugging lines are compiled as if they were comment lines" (§1985:VI.4.3.4 GR5). A fixed-form D line reaches text manipulation as the debugging-line carrier plus its text; `TextWordScanner.TryNext` skips the carrier so the line's words take part in COPY and REPLACE matching (the intended 1985 rule), and `CopyProcessor` then replaces the COPY statement by the library text as plain lines. The carrier stays on the line the COPY statement began on, but the included lines have none, so `DebuggingLineRewriter.DebugLines` (which owns the tokens after a marker on the marker's own line) sees ordinary source and keeps it. A D line INSIDE the library text is handled right (hidden without the mode, kept with it), and so is REPLACE pseudo-text matched on a D line.

**Found by.** The 1985 refuter pass (2026-11-10; records `E:/COBOL-coord/scratch/refute-85/out/r09.json`, probes `probes-r09/p1a.cob`, `p1b.cob`, `p1c.cob`, `LIBN.cpy`, `LIBD.cpy`): a refuter attacked the CONFORMS verdict of the row below, OVERTURNED it, and the repro was rerun on current main for this note.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the row this note claims is the rule id below.

**Rules (1; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-GR-VI.4.3.4-5` - `§1985:VI.4.3.4 GR5` (refuter: OVERTURNED, harm: wrong-answer). §1985:VI.4.3.4 GR5: "any debugging lines are compiled as if they were comment lines"; §1985:XII.2.4 GR9: "each text word introduced appears on a debugging line if the COPY statement begins on a debugging line". The text a D-line COPY brings in is debugging lines, so without the mode it is comment.

**Repro (`p1a.cob`, with `LIBN.cpy` and `LIBD.cpy` beside it).** `cobol.exe --std 85 --source-format fixed --copy <dir> --run p1a.cob`

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. P1A.
       ENVIRONMENT DIVISION.
       CONFIGURATION SECTION.
       SOURCE-COMPUTER. X.
       PROCEDURE DIVISION.
       MAIN.
           DISPLAY "START".
      D    COPY LIBN.
           COPY LIBD.
      D    THIS IS NOT VALID COBOL @@ ((.
           DISPLAY "END".
           STOP RUN.
```

`LIBN.cpy` is the one line `           DISPLAY "COPIED-ON-DLINE".`; `LIBD.cpy` is `           DISPLAY "LIB-NORMAL".` and `      D    DISPLAY "LIB-DEBUG".`

**Observed (current main, the build at 3d12682fd2, rerun 2026-11-10).** exit 0; prints `START`, `COPIED-ON-DLINE`, `LIB-NORMAL`, `END`. The generated C# holds `Console.WriteLine("COPIED-ON-DLINE")`.

**Expected (from the 1985 text).** `START`, `LIB-NORMAL`, `END`: the DISPLAY copied by the D-line COPY is on a debugging line (§1985:XII.2.4 GR9) and is a comment in a program without WITH DEBUGGING MODE (§1985:VI.4.3.4 GR5), as the D line inside LIBD.cpy is.

**Fix direction (root cause, CLAUDE.md rule 4).** Carry the debugging-line property through inclusion: when `CopyProcessor` replaces a COPY statement that begins on a carrier line, emit every line of the resulting text with the carrier, so the one decision in `DebuggingLineRewriter` sees each introduced text word on a debugging line, with and without the mode. Keep the rule in the copy expansion, the one place text is introduced, and test a D-line COPY with and without WITH DEBUGGING MODE, a nested COPY inside it, and COPY ... REPLACING on a D line.
