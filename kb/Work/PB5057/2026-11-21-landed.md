## 2026-11-21 — landed (wave 20262132 group i): every program child a test starts is bound to its host's lifetime

**Fix.** `tests/_shared/HostBoundChildren.cs` is the ONE starter-side binding: `HostBoundChildren.Bind(Process)`, called
by `ProcessObserver.Observe` and `LiveProcess.Start` the moment each starts its child, puts the child in the host's one
Windows job object, created with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` and never closed by the host. The operating system
closes a process's handles however it ends, so a host that dies (a stopped gate, a killed run, a crashed testhost) closes
the job's last handle and the operating system kills every process in it, the child's own descendants included (a
process a job member starts joins its job). A job the operating system refuses fails loudly (`Win32Exception`), never a
silent unbound child.

**Linux, decided: no binding.** `PR_SET_PDEATHSIG` is the only per-child equivalent and must be set between `fork` and
`exec`, which `Process.Start` does not expose; it also fires when the forking THREAD ends, and a test's thread-pool thread
can retire while its child still runs, which would kill a healthy child mid-test. The Linux runs are CI's merge group and
`linux-gate.sh`'s WSL legs, whose runner or distribution ends every process it started. The decision is written in the
class's summary.

**Proof.** `ProcessObservationDriftTests.AChildInTheHostsJob_DiesWhenTheJobsLastHandleCloses` (Unit) starts a sleeper
that never ends, puts it in a fresh `KillOnCloseJob`, closes the job (the host's death in miniature) and asserts the
sleeper exits; on a host that is not Windows it asserts the job does not exist. Passed with the flag; with `LimitFlags = 0`
(the mutation, reverted) it FAILED ("the job's last handle closed and its process is still running"), so it can fail.
The process tests around it (`ProcessObservationDriftTests`, `RunUnitProcessBoundaryTests`, `PlatformAssumptionTests`):
65 passed, 0 failed.
