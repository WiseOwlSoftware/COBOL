# PB1533 — LANDED (wave 1004 B)

## The rule

> 4) … the value … is obtained from the operating environment by an implementor-defined method …

`cite.py --check 7.3.11.4 "is obtained from the operating environment by an implementor-defined method"` → OK §7.3.11.4 4).
Annex A.1 item 49 requires the method to be documented.

## Repro (adjudicator `adj-a1-w1-s2`, Linux; not re-probed by the registrar)

```cobol
      >>DEFINE MyVar AS PARAMETER
      >>IF MyVar IS DEFINED
```

With `MYVAR=x` in the environment → NOT DEFINED; with `MyVar=x` → DEFINED. A compilation-variable-name is a COBOL word and so
case-insensitive; the method the implementation chose makes its value depend on the spelling.

## Code sites

`src/Cobol.Net.Frontend/Preprocessor/ConditionalCompilationProcessor.cs` (the `DefineKind.Parameter` arm of `ApplyDefine`) and
`src/Cobol.Net.Frontend/Pipeline/CompilationInputs.cs#GetEnvironmentVariable` read `Environment.GetEnvironmentVariable(name)` with the
name as spelled; the numeric-vs-alphanumeric typing is an invariant decimal parse. Neither is documented (no `DOC-A.1-49` row).

## Fix

Normalize the looked-up name (the canonical upper-case COBOL word), document the method (name mapping, typing, absent-variable
behaviour) as the §7 `DOC-A.1-49` row, and pin both with goldens run under a set environment variable. PB1367 owns a different
DEFINE PARAMETER defect (the SR2 bypass). Row `DOC-A.1-49` (adjudicated **DIVERGES** on `claude/adj-a1-w1-s2`; not recorded —
DOC rows wait on PB1535).

Harm flag: `wrong_answer: true` — `>>IF … IS DEFINED` and the defined value depend on the spelling of one case-insensitive name.
