# PB5819 - 1985-GR-XIII.4.5.4-18: the rule says record sizes are fixed at file creation and must not later change, a constraint on the program whose violation a conforming program cannot observe; the row has no witness and stays open until the inventory can close a row nothing can witness

**Decision (registered 2026-11-15 from the refuter's overturn of the draft case `g85_z03`).** `1985-GR-XIII.4.5.4-18` gets NO case and NO record. The draft `g85_z03` does not land. The row stays open (GAP) until the inventory has a way to close a row nothing can witness; PB5792 is the same kind of row.

**The text (each citation checked again with `python scripts/spec/cite.py --check`, verdict OK).**
- `§1985:XIII.4.5.4 GR18`: "The minimum and maximum record sizes for a file are established at the time the file is created and must not subsequently be changed."
  `OK  §1985:XIII.4.5.4 GR18  (4.5.4 General Rules)  the text is in GR18`
- `§1985:XIII.4.5.4 GR6`: "The implementor defines which of the fixed file attributes are validated during the execution of the OPEN statement."
  `OK  §1985:XIII.4.5.4 GR6  (4.5.4 General Rules)  the text is in GR6`

**Why no program witnesses it.** GR18 states a constraint on the program and the file and gives no outcome for a violation. The only detection mechanism the 1985 text gives is GR6's file attribute conflict, and GR6 leaves which fixed attributes are validated to the implementor, so a conforming program cannot observe what GR18 requires. Within one program the FD fixes the record sizes, so the program cannot change them. The draft's positive arm (same RECORD CONTAINS 4 TO 20, EXTEND 00, two records appended) printed the same lines on a compiler that ignored GR18: it showed GR10 and GR16 behaviour, which `g85_z02` already witnesses for GR10.

**What closes the row.** Either an argued derivation ("no program can observe the property") with a refuter pass under DESIGN-spec-conformance-review.md section 1.1, or an owner-visible decision that the conformance register states the rule as not observable. Until then the row stays GAP.
