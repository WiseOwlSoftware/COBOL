# PB2130 — interface members used only through their implementations

Found by wave 1026 group C (PB2115, the R0 census; report `w1026c-PB2115-report.md`), filed by the train-1026 lander.

## Observation

The census's semantic walk found no use of three interface members in `src/Cobol.Net.Compiler/Binding/Bound`:
`IArithmeticStatement.SizeError`, `IBoundRead.AdvancingOnLock` and `IBoundRead.Kind`. Only `SymbolFinder`'s cascade
(an interface member counts as used when an implementation is) keeps them out of the unreferenced list. The census
record lists them as `walkMisses`:
`docs/rearchitecture/evidence/arch-census/a02b165dae86b674e16399468144e1386171236b.json`.

## What the Delete wave owes

Confirm by a caller query (LSP `findReferences` on each member) that no code reads the member through the interface
type. If none does, either remove it from the interface (the implementations keep their own property) or record why
the interface must carry it (a generic consumer still to come). Prove neutrality with the R0 oracle
(`python scripts/arch/compare_oracle.py`) and the whole-population gate. Input to the Delete program, PB2119.
