**Rule it breaks:** DESIGN-architecture-review.md section 5.1 (one mechanism per job; clean phase boundaries) and section 8.3 (4), whose NameResolution takes candidates in; ReferenceResolver.cs:1330-1334 itself declares ReadWritten THE ONE DECOMPOSITION of a written reference (kb/Work PB443), yet the sub-references the symbols decide are re-expressed as new parse trees instead of slices of that decomposition

**Scenario:** Whenever the resolved symbols split a written reference (section 8.4.3.1.2 Format 7 property chains, a view of a qualified item, a THROUGH range IN alphabet-name, a function result reference modifier), the code builds a new generated context, copies children into it and patches Start/Stop by hand: WithoutTrailingSuffix (ReferenceResolver.cs:108-126, called from DataBinder.cs:4668 and EvaluateBinder.cs:699), ViewSubjectChain (ObjectProperty.cs:119-145, new DataReferenceContext and QualificationContext), PropertyObjectReference with WithoutRefMods (ObjectProperty.cs:342-380, which casts q.GetChild(0) to ITerminalNode on the assumption that OF/IN is the first child), WithoutResultRefMods (ObjectProperty.cs:390-408, called from OoBinder.PropertyObject.cs:57) and Suffix (:412-419). Each forger encodes the generated parser internals (invokingState, child order, which accessor finds which child) that no compiler check ties to CobolParserCore.g4:693-735, so the section 8.4 grammar regroup or any edit to dataReference, qualification or propertyObject turns them into run-time InvalidCastException or a silently mis-read chain at bind time rather than a build error. The forged nodes also carry fresh object identity, so the resolver per-reference report set (_diagnosed, a HashSet of ParserRuleContext) and WasDiagnosed answer for the forged node, never for the reference the user wrote; and DataBinder keeps a dictionary of forged contexts (_alphabetPeeledOperands, DataBinder.cs:4668, 6372) as cached state. PB2731 already counts two read mechanisms over the parse tree (the Cst facade and raw contexts); forging is a third, and it is the only one that writes trees.

**Target:** Make WrittenReference the resolver input: ReadWritten produces, once per written reference, an immutable model (head word, ordered qualifier segments each with its own subscript group and reference modifiers, the property object, the source span) and the ReferenceResolver funnel and the section 8.3 (4) NameResolution, SubscriptBinder and RefModBinder take it. Every split becomes a slice of the model (WithoutLast, Identifier3, ViewSubject, WithoutResultRefMods) carrying the original span, so the per-reference report key is the source span and WasDiagnosed answers for what the user wrote. Delete the four forgers, Suffix and the _alphabetPeeledOperands cache; EvaluateBinder, DataBinder and OoBinder.PropertyObject pass the slice.
