**Addendum (2026-11-10): status 41, from the 1985 refuter pass.** The note's mechanism (the open-mode USE tier reads `FileConnector.OpenModeView`, whose being-opened mode is wrong) has a third arm. An OPEN refused with 41 because the file is already open in another mode never records the mode being opened: `OpenModeView` keeps the CURRENT open mode, so `UseTierEmitter.EmitScopeTiers` runs the current mode's procedure, or none, where 1985 runs the procedure of the mode being opened.
