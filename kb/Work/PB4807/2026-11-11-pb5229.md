## PB5229 fixed the first cause and deleted LIVE_MAX_AGE

kb/Work PB5229 (landing with this branch) removed the 30-minute age test: `budget.live_reading(acct)` no longer takes `now`,
`LIVE_MAX_AGE` is deleted, and a status-line reading measured in the current quota week anchors at any age (the telemetry
since is added on). The first cause below ("the fallback anchors days back because a fresh reading is never stored") no
longer arises through the status line: the reading in `rate-limits.json` anchors however long its figure has stood. The Sites
line naming `LIVE_MAX_AGE` and the Fix bullet that sizes the drift by it are therefore history.

**What remains of PB4807.** (1) The calibration refit: `calibration.tokens_per_point` was fitted on 2026-10-07 from one
bracket of one session and undercounts the spend since an anchor by about a fifth; the stored-bracket refit and its test are
still to do. (2) The ledger readers: `ledger_plan.py#measure_pacing` and `#estimate_inputs` read only `<coord>/readings.json`,
so the ledger shows the last STORED reading, never the live one. Persisting a live reading into readings.json (the Fix's
first bullet) is needed only for those readers, not for the estimate. Related: PB5229.
