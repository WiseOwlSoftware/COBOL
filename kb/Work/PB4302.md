# PB4302 - `DataBinder.PtrDescendants` is a recursive yield iterator - 22.7% of binder allocation on the corpus - and the pointer scans built on it re-walk every contained program's subtree from every container, so bind is superlinear in nesting depth (558 ms at 100, 3,640 ms at 200)

Found by the Mythos front-end review, gap pass, 2026-10-31 (GAP-REVIEW.md, G6-1; artifact https://claude.ai/artifact/KaxkLe85tfZBZ3nZ1tDGTs). Pin d7daee1cf.

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.Ptr.cs` (`PtrDescendants` :402-410, `ScanByReferenceOperands` :295-347 with its local `OperandIdentifier`, `PtrScanAddressOfSenders` :389-399, `PtrScanAddressOfTargets` :369-385, `PtrBindBasedAndAddressables` :135-137/:175-181 where the container's IsUserFunction predicate lives); `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.Linkage.cs:445-447`; siblings `DataBinder.Constants.cs:220-228` (`Descendants`), `DataBinder.PreOrder`, `SetAlterBinder.AlterStatementsIn`.

**Finding.** `DataBinder.PtrDescendants` (DataBinder.Ptr.cs:402-410) is a recursive `yield` iterator (O(nodes x depth) MoveNext chain, one iterator object per interior node); the three pointer scans built on it (ScanByReferenceOperands :295-347, PtrScanAddressOfSenders :389-399, PtrScanAddressOfTargets :369-385; PtrBindBasedAndAddressables :135-137/:175-181 over `program.nestedProgram().SelectMany(...)`; DataBinder.Linkage.cs:445-447 for USING) re-walk every CONTAINED program's whole subtree from every containing unit. Corpus allocation (refuter re-run): bind 4,144 -> 3,205 MiB with an explicit-stack prototype (-940 MiB, -22.7%), outcomes identical {bind-error 2672, bound 3167, no-tree 172, frontend-error 205}; that is ~1.4% of whole-corpus allocation including DB201A/OBNC1M (the first report's "10.4% of every byte" excluded them). Depth: NESTED_100 bind 558 ms/143 MiB -> 156 ms/12.3 MiB; NESTED_200 3,640 ms/551 MiB -> 223 ms/25 MiB (x6.5 per doubling at the pin, not x8); 400 SIBLING programs ~70 ms; EVALS BindUnitData 174 ms/62.5 MiB -> 34 ms/0.1 MiB (the scans walk the PROCEDURE division from the data bind). With the iterator linear, the per-container re-walk is still quadratic (prototype BindUnitData 114/154/665 ms at depth 100/200/400). Production depth (10-25) binds in 18-29 ms, hence MEDIUM. The corpus wall-time gain did NOT reproduce on the loaded box (base 8.0 s, prototype 10.5 s, with the identical front end moving 5.5 -> 7.5 s): allocation deltas are the attributable evidence, wall time is not. Siblings Descendants, PreOrder, AlterStatementsIn allocate 271/165/327 MiB in the same profile. PB3227 lists PtrDescendants as a unify-wave member only, without the measurement (cross-reference; PB3227 gains an addendum).

**Fix direction.** Replace the iterator with an explicit-stack walk, then remove the per-container re-walk. The first report's bottom-up merge ("the container needs only the names the contained unit's own scan already yields") is NOT established: the container scans the contained subtree with the CONTAINER's IsUserFunction predicate (:175-177), so a merge must keep that predicate and region or prove them equal, else it changes which items are forced into cells.
