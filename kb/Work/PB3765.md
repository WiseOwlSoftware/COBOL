# PB3765 — no fast lane for a fix to CI itself

**Sites:** `.github/workflows/build-and-test.yml` (the `changes` job's decide step and `ci-gate`), `scripts/orchestrator/enqueue.py`, `scripts/orchestrator/ruleset.py`, `docs/rearchitecture/DESIGN-test-build-ci.md`

## What happened (2026-10-25)

From about 18:50Z the .NET download origin behind the aka.ms link answered HTTP 409 for the 10.0.14 runtime and the
10.0.403 SDK, so every merge group that runs the matrix failed at `Setup .NET 10` (PB3308). The fix (wave 20261700,
PR #594: a fallback feed, retries and a cache) was DONE and reviewed CLEAN, then:

1. it waited in the merge queue behind entries the outage was failing; the head entry (#591, a design-doc landing the
   `changes` job sends to the matrix) failed, was ejected, and every group behind it restarted;
2. its own merge group ran the whole matrix (a workflow edit counts as code, correctly), about 20 jobs, half of them
   queued under GitHub's concurrent-job limit beside superseded runs that still held runners (cancelled by hand);
3. the owner approved an immediate merge; the ruleset binds administrators and has no bypass actor, so the session set
   ruleset 24904083 to `disabled`, merged #594 (6401498bd, 20:25:27Z) and restored it (`ruleset.py check`: ACTIVE).
   Disabling it also dropped #593 and #595 from the queue.

Main took no code landing from ~19:00Z to 20:25Z.

## The defect

The landing has one path and one speed. A change whose purpose is to restore CI is gated by the CI it repairs, queued
behind the failures it would cure, with no way to jump the queue and no bounded bypass short of disabling the ruleset
(which also ejects every other entry).

## What a fix must give

- A fast lane for a CI repair: a change confined to `.github/workflows/` and CI scripts, landed while main's own CI is
  failing for an infrastructure cause, jumps to the head of the queue (GitHub's `enqueuePullRequest(jump: true)`)
  through `enqueue.py`, never by hand, with the reason recorded in its landing record.
- Superseded merge-group runs cancelled when GitHub rebuilds the groups, so they release runners
  (`concurrency` keyed on the merge-group ref, or a cancel step), measured against today's restart.
- A bounded owner bypass, if one is still needed, that does not eject the other entries (a bypass actor for the
  owner's merge only, applied and removed by `ruleset.py` with a record), replacing the disable-and-restore done by hand
  today.
- Drift test: the fast lane is reachable only for the CI-repair path set and only under a recorded infrastructure red.
