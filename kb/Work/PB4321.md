# PB4321 — C# method locals on model nodes (leak L8)

**Found:** by the PB4265 implementer (wave 20261790 group B, report
`E:\COBOL-coord\scratch\reports\w20261790b-PB4265-report.md`), recorded as the OPEN row L8 of
`docs/rearchitecture/DESIGN-backend-abstraction.md` §1.3; PB4265 itself named `PositionLocal` and `LocalVector` as the
C#-only names to move out of the model. Campaign PB2293 (owner 2026-10-31: eliminate the backend seam leaks asap).

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Model/Position.cs:157` (`PositionLocal`, `LocalVector`);
`src/WiseOwl.Cobol.Compiler/Binding/Bound/BoundTree.cs:264` (`BoundReportVaryingRef`);
`src/WiseOwl.Cobol.Compiler/Binding/DataBinder.Reports.cs:527` (`ReportVaryingModel.CsName`).

**What leaks.** These strings name C# method locals (`__kv{Uid}` and the position temporaries), not CLR members: no
other module binds to them, so they are no ABI, and a CIL backend has no use for a local's name (it allocates a slot).
A target-naming decision for a local is frozen into the neutral tree.

**Fix direction.** A neutral local identity on the node (the owning model object, or a small `LocalId` value), named
by each backend when it renders; the Roslyn backend keeps today's spellings so the generated C# does not change (the
§4 oracle proves it). PB4266's §6 assertion 2 flags exactly these fields, so this note shrinks its allow-list.
