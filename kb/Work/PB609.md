# PB609 — OPEN — the second arm of the restricted-pointer pair

Found 2026-09-05 by the `PB237` implementer as the one half of `SR-14.9.4.3-14` its registry could not close;
the row moves here so PB237 lands whole. Re-derived on this tree for this note.

## The rules

```
python scripts/spec/cite.py --check 13.18.60.3 "If program-prototype-name-1 is specified, the TYPEDEF clause shall be specified for the subject of the entry."
python scripts/spec/cite.py --check 13.18.60.4 "If program-prototype-name-1 is specified, this data item is a restricted program-pointer. A restricted program-pointer shall contain only the predefined address NULL or the address of a program with the same signature as that identified by the specified program-prototype-name."
```

(both copied from the transcription at those headings — run the checks as the fix's first step). §14.9.4.3
SR14 is the CALL-side consumer: a CALL through a restricted program-pointer takes its signature from the
prototype the pointer names.

## The mechanism

`DataBinder.cs` (~`:2620`) refuses the `USAGE PROGRAM-POINTER TO program-prototype-name-1` shape with a staged
loud — `tests/conformance/negative/program-pointer-restricted` is a GREEN test pinning that non-support, the
`feedback_green_test_can_hold_a_gap_open` shape. `StrongTypeModel.PointerRestriction` answers only for
`PicCategory.Pointer` (the restricted DATA-pointer PB153 landed under §13.18.60.3 SR18); `PicCategory.
ProgramPointer` has no carrier at all. PB237 landed the registry a restricted program-pointer needs
(`StatementBinder.ProgramPrototypes`, `CallBinder.ResolvePrototype`, `CalleeSignature`), so the remaining work is
the data-division half: SR19's TYPEDEF shape, GR25's restriction carried on the type, and SR14's consumption at
CALL (a CALL through the pointer conforms its arguments to the prototype's signature exactly as a Format-2 CALL
does).

## Fix shape

Add the `ProgramPointer` arm to `PointerRestriction` mirroring the data-pointer arm; enforce SR19 at the entry
(a named diagnostic, not the 0899 loud); make `CallBinder`'s pointer-CALL path look up the restriction's
prototype through `ResolvePrototype` and reuse `CalleeSignature`; retire the `program-pointer-restricted` loud
and rewrite its negative fixture into SR19's real rejection (a restricted program-pointer declared without
TYPEDEF). Positive golden at 2002+: a TYPEDEF restricted program-pointer, `SET` to a same-signature program,
called through it, with the §14.8.2 argument checks observed; negative for a signature mismatch.
