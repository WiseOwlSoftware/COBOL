# PB2560 — R2's workflow, collection and filing

**Why.** B3: the first workflow wrote each reviewer's file only at the END; batch 1 ran 20:45–20:58 with eight Opus
agents and everything was discarded. B5: its findings had a free-text `site` the planner could not place, and a clerk
would have filed them from prose. B6: one refuter per reviewer, only when findings existed — a null was accepted
unexamined, and one transcript deciding fifteen findings caps out.

**What landed.**
- `.claude/skills/workstream/templates/wf_r2_review.js` (registered in `check_practices.py`): finders per
  (shard × dimension), two from opposite ends over 4,000 lines; a finisher for exactly the unread remainder; a null
  examiner; three skeptics (site · rule · scenario) per chunk of four findings; eight agents at once; the scoped stops.
  Every agent appends one JSON line per decision and skips what its file holds, so a relaunch resumes.
  `scripts/arch/test_wf_r2_review.mjs` dry-runs every arm with stubbed agents.
- `scripts/arch/r2_collect.py`: reads the lines FROM DISK and decides each finding (two of three skeptics), each
  pair's completeness and each null; validates the schema (files in the pin's tree, `design_ref`, wave kind,
  severity, a defect's harm) and writes `collected.json` and one file per pair.
- `scripts/arch/file_census_notes.py --r2`: one note per UPHELD finding in cluster PB1754 (`kind: analysis`, or
  `kind: defect` for the fix lane), sites as backticked paths, members as the `**Moves or changes:**` line, census
  findings as `census_refs:`, the finding id on `r2_ids:` (idempotent), ids from `alloc.py`, stale paths refused.

**Refuted and fixed (the w1034 claim refuter, three blocking findings; fixed in w1037s).**
- **C2, resume.** The skip was per AGENT while the workflow planned from agent RETURNS: a relaunch re-read a
  finisher's files, never ran the finisher again and left its findings unverified; chunks moved, so findings were
  decided twice; a finder that wrote findings and returned nothing orphaned them in one launch. Now
  `r2_collect.py --launch` writes `launch-args.json` (each PAIR's on-disk state) and the workflow refuses to start
  without it; agents ask `--status` for the pair's decisions and record through `--append` (validated; no reused id,
  no heredoc). Test: `test_wf_r2_review.mjs` (the refuter's S1, S2, sim3; the pre-fix workflow fails 10 arms).
- **C3, de-duplication.** Upheld findings of one wave kind on overlapping members or sites are ONE mechanism
  (`collected.json` `mechanisms`); `file_census_notes.py --r2` files one note per mechanism with every id, refuses a
  batch that is not COMPLETE and adds a later batch's duplicate to the existing note. Test: both self-tests; the
  refuter's planted cli duplicate files as one note.
- **C4, modern-C# evidence.** The IDE/SYSLIB rules of design §5.5 were never reported (CA only); `MODERN_RULES` is now
  the analyzer tree's `.globalconfig`, and batch 1's shards carry IDE0305, IDE0032, IDE0078 and IDE0290. Modern-C#
  stays in batch 1. Also: mech steps cached under a key, corrections applied per lens, defects' `spec_refs` checked
  through `cite.py`, the root scripts and role files in the reviewed domain, no build command in the performance
  input. Design §3 R2 rewritten to match; DEVLOG 1933.
