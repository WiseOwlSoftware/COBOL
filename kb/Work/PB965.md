## Reproduced

`scratchpad/reg10/p907calg.cob` (nested) and `vlgsib.cob` (the same program with the callee as a separately
compiled sibling, `CALL "RG10SUG" USING SG` without AS NESTED):

```cobol
       01 SRC.
          05 S0 PIC X(2) VALUE "AB".
          05 SG.
             10 S1 PIC X(2) VALUE "CD".
             10 ST PIC X OCCURS 3 VALUE "T".
             10 S3 PIC X(2) VALUE "EF".
           CALL "…" USING SG            *> BY REFERENCE (the default)
           DISPLAY "SRC=" SRC
      * callee
       LINKAGE SECTION.
       01 LG.
          05 L0 PIC X(2).
          05 L1 PIC X OCCURS DYNAMIC CAPACITY IN LCAP.
          05 L3 PIC X(2).
       PROCEDURE DIVISION USING LG.
           DISPLAY "LCAP=" LCAP " L0=" L0 " L1=" L1(1) L1(2) L1(3) " L3=" L3
           MOVE "qq" TO L0
```

Observed on both variants: `LCAP=0000000000 L0=   L1=    L3=  ` and then `SRC=ABCDTTTEF`.
**Expected:** `LCAP=0000000003 L0=CD L1=TTT L3=EF`, then after the callee's store `SRC=ABqqTTTEF`.

## Rules (each `cite.py --check`ed)

- `--check 14.8.2.2 "If either the formal parameter or the argument is a variable length group, the formal parameter and the argument shall be compatible"` → `OK §14.8.2.2 2)`. The pair is compatible:
- `--check 8.5.1.12.2 "Two tables correspond if at least one of them is a dynamic-capacity table and they occupy the same relative byte positions within their groups."` → `OK §8.5.1.12.2`. ST and L1 both start at relative byte 2.
- `--check 8.5.1.12.3 "If one of the corresponding tables is not a dynamic-capacity table, that table is treated as though it were a dynamic-capacity table whose capacity is either its fixed number of occurrences"` → `OK §8.5.1.12.3`. ST is treated as capacity 3, and the element lengths (1 and 1) are equal, so they match.
- `--check 14.2.3 "If the argument is passed by reference, the activated runtime element operates as if the formal parameter occupies the same storage area as the argument."` → `OK §14.2.3 8)`. That is why the callee's `MOVE "qq" TO L0` must be visible in SRC.

The binder ACCEPTS the call (no diagnostic), so this is not a refusal. It is a crossing that delivers nothing.

## Mechanism (where to look)

PB204 LANDED the variable-length-group crossing (`CobolVarGroup(Fixed, Dynamic[])`, `AsVarImage`/`FromVarImage`)
and measured it with a variable-length group on BOTH sides (`2023/pb204_vlg_boundary`). The fixed-length ARGUMENT →
variable-length FORMAL direction was never measured. The fixed-length argument has no `AsVarImage()` to project
itself into the §8.5.1.12 model, so the callee receives an empty carrier and the write-back has nothing to write
into. Sites: `CallEmitter.cs` (argument marshalling), `VariableLengthCompatibility.cs` (it already computes the
correspondence the projection needs), `GroupImageCodec.cs`.

## What the fixer must do

1. Project a fixed-length group (and a THROUGH alias, once PB907 admits it) INTO the variable-length carrier using the
   correspondence `VariableLengthCompatibility` computes: a fixed table at the position of a dynamic-capacity table
   crosses at its fixed occurrence count (§8.5.1.12.3). Write back through the inverse. The callee cannot grow a
   fixed-length argument's table past its fixed extent. Decide and document what happens if it tries (§8.5.1.12 is
   silent on it, so this is an A.1 determination question: file a `kind: decision` note if the survey splits).
2. Sweep every crossing direction with a fixed side: CALL BY REFERENCE / BY CONTENT, RETURNING with a fixed returning
   item into a variable-length activating item and the reverse (§14.8.3.2's compatibility sentence), INVOKE USING /
   RETURNING, and the nested vs separate CALL arms. **Measure each one. PB204's goldens only prove the VLG↔VLG pair.**
3. Golden at 2023 (dynamic-capacity tables are 2023) for each direction, spec-derived expected output first.

## Half-landed — 2026-09-22 13:27 PDT (wave 48 group R, with PB962)

**Re-probed on the implementer's build** (main + wave-46 group K): `p907calg.cob` and `vlgsib.cob` no longer
answered with the empty carrier the note measured - PB615 had turned the silent empty read into a loud
EC-PROGRAM-ARG-MISMATCH ("its carrier (ManagedPointer`1) cannot be read through a variable-length group formal").
The pair is still one §8.5.1.12 admits, so the loud was as wrong as the silence. After the fix both print
`LCAP=0000000003 L0=CD L1=TTT L3=EF` / `SRC=ABqqTTTEF` - the note's expected output exactly.

**The root was structural, and the estimate was wrong (CLAUDE.md rule 5).** The correspondence between a fixed
group and a variable-length one is a fact about the PAIR (§8.5.1.12.2), and the two sides of a CALL are compiled
apart - so neither side can decide it alone. The fix makes each group's §8.5.1.12 LAYOUT a description that
TRAVELS (`CobolArg.Layout`, beside PB873's `NumProfile`), and decides the pair in ONE walk,
`CobolVarGroup.CorrespondingSpans`, called at run time by the formal's adapter and at compile time by the GR9 MOVE
and the typed INVOKE. It replaced `VariableLengthCompatibility.FlatTableSpans`, which answered "every table of the
fixed group" and was a SIBLING DEFECT on the MOVE path (measured: `MOVE SRC TO VLG` where SRC's first table stands
opposite VLG's plain bytes moved that table into the dynamic one - `VCAP=2 VA=cc VB=aa`, now `VCAP=3 VA=aa VB=bbb`).
The RETURNING directions needed the RECEIVER's layout inside the activated element, so the RETURNING item now
crosses as a `CobolArg` too (`ICobolProgram.Call(CobolArg[], CobolArg?)`) - the change PB962 needed for the
receiver's description as well.

**Every direction measured:** nested and separately compiled CALL BY REFERENCE and BY CONTENT, a level-66 THROUGH
alias argument, INVOKE USING, RETURNING fixed-into-variable and variable-into-fixed (Format 1), and the GR9 MOVE both
ways. ⚠ DETERMINATION (§8.5.1.12 is silent): a callee cannot grow a fixed-length argument's table past its fixed
extent, so the write-back fits each component as §14.6.9.2 fits a dynamic sending table into a non-dynamic receiving
one (superfluous occurrences are not moved; missing ones are space filled) - `docs/COBOLNET_INTERPROGRAM_DESIGN.md`.
NOT fixed here and reported as leads: a variable-length ARGUMENT into a fixed-length FORMAL, and RETURNING between
the two for a nested CALL or an INVOKE, are refused at BIND (COBOLNET1688 / 1736 / 0828) because the size compare
reads the variable-length group's collapsed width.

## Finished - 2026-09-22 15:30 PDT (wave 50 group C, the bind-time residue)

**Re-probed on the finisher's build** (main `6871b6e10` + wave 48 R): `w48r/vlgdirs.cob` still refused with
COBOLNET1688 "the formal (7 character positions) exceeds the argument (5)" and COBOLNET1736 twice; `vlginv.cob` with
COBOLNET0828 "character length mismatch (formal 7, argument 5)". All three askers go through
`OoConformance.DescriptionMismatch`, which compared the variable-length group's COLLAPSED `ImageWidth` (a
dynamic-capacity table counted as one element).

**The rule** (`cite.py --check` on each): `OK §14.8.3.2` - the RETURNING length sentence applies only when "neither of
them is strongly typed or a variable length group"; `OK §14.8.2.2 1)` binds an ALPHANUMERIC group item, and `OK §3.11`
defines that as a "group item except for ... a variable-length group item"; `OK §8.5.1.12.3` - "For purposes of
determining compatibility, the dynamic-capacity table is considered to be the same length as the corresponding
table". So: two variable-length groups - compatibility is the whole rule; a fixed group opposite one BY REFERENCE -
rule 1 in the lengths the PAIR has (`VariableLengthCompatibility.PairCharWidths`, the same walk that decides the
correspondence); a RETURNING pair - compatibility only. Override-signature equality (§9.3.8.2.3) is unchanged.

**The admitted pairs run.** `CobolArgAdapt.Text` / `TextValue` gained the variable-length-carrier arm (every group
formal now states its §8.5.1.12 layout, `ProgramEmitter.GroupFormalLayout`); the typed INVOKE gained the argument arm,
its write-back and both mixed RETURNING arms (`OoEmitter.VarPlaceSpans`). ⚠ DETERMINATION (§8.5.1.12 and §14.2.3 are
silent): a formal with a FIXED occurrence count cannot change the argument table's current capacity, so a store
OVERLAYS the argument's storage (`CobolVarGroup.OverlayFixedImage`) - the mirror of wave 48's determination.

**Sibling found on the same row:** an OCCURS DEPENDING group BY CONTENT sent its MAXIMUM image where §14.8.2.2 says
"the length of the argument is determined by the rules of the OCCURS clause for a sending data item" (measured
`C=[abcdefg]` at a count of 2 of 5; now `C=[abcd   ]`, CALL and INVOKE, `CallEmitter.CallContentRead`).

Goldens `2014/pb965_vlg_into_fixed_boundary`, `2014/pb965_vlg_into_fixed_invoke`, `2002/pb965_odo_group_argument_length`;
