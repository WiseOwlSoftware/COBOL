# PB5765 - the harness observes nothing after the run unit ends

**Sites:** `conformance-suite/harness/run.py#execute` (the test's process; the run gains a comparison of a declared
output file in the run's directory after the process ends), `conformance-suite/harness/generate.py` (whole: the header
reader and the manifest gain the declared output file), `tests/WiseOwl.Cobol.Tests.Conformance/ConformanceSuiteRunner.cs`
(whole: the in-process runner compares the same file), `tests/_shared/SuiteManifest.cs` (whole: the manifest's new
field), `docs/rearchitecture/DESIGN-conformance-suite.md` (whole: the header field of its section 3.1 and the runner's
contract of its section 5).

## The defect

A suite case is judged on its standard output against its `.out` (DESIGN-conformance-suite.md section 3.1; `files`
declares inputs staged beside the case, never an output the harness reads back). A program prints nothing after STOP
RUN, and `build` (the only multi-step facility) is refused in `cases/`. So a rule whose effect is visible only once the
run unit has ended has no observable a case can pin.

The 1985 row this blocks:

- `1985-GR-VI.6.24.4-2`. §1985:VI.6.24.4 GR2: "During the execution of a STOP RUN statement, an implicit CLOSE
  statement without any optional phrases is executed for each file that is in the open mode in the run unit. Any USE
  procedures associated with any of these files are not executed." (`python scripts/spec/cite.py --check
  "§1985:VI.6.24.4 GR2" "an implicit CLOSE statement without any optional phrases is executed for each file that is in
  the open mode"` printed `OK  §1985:VI.6.24.4 GR2  (6.24.4 General Rules)  the text is in GR2` on 2026-11-15.) The
  implicit CLOSE shows only in the file left on disk (its last records written and the file complete), after the
  program's last output line. The USE leg alone cannot fail: a conforming program provokes no error on the implicit
  CLOSE, so a case printing nothing from its USE procedure would pass on a compiler that ignored the rule.

The writer's draft and reasons: `E:\COBOL-coord\scratch\gl1985\lane1\reports\g1985-vi-6-27-unstring.json` (row
`1985-GR-VI.6.24.4-2`, disposition `not-closable`).

## The fix

Give a case header a declared output file (name and expected content, the content file beside the case like a `.out`)
that both runners compare after the process ends, on the same normalization as the standard output. Then a 1985 case
writes records to a sequential file, does not CLOSE it, and ends with STOP RUN; the declared file must hold every record.
This is the output-side sibling of kb/Work PB5755 (no standard input): both are facilities the harness lacks, filed
separately because they change different halves of the runner.
