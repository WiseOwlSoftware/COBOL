## Later finding (2026-11-28): the retirement reason names COBOL2198, a USAGE rule

Source: `E:/COBOL-coord/scratch/reports/w20262177j-PB6276-report.md`, Review R1-1 (low, not blocking). The retirement stands: the probe `SUM X Y` under DECIMAL-POINT IS COMMA sums correctly on the unchanged tree, and the golden `13.18.54-SUM/pb6341_report_rolled_value_decimal_point_comma` pins it.

One reason given is false. The "Retired" section (line 50, and `DEVLOG/4087-a-method-s-own-select-when-level-88-resolves-a-condition.md` line 30) says a floating-point VALUE "is not admitted on a report entry (COBOL2198)". COBOL2198 is the USAGE-clause rule (only DISPLAY or NATIONAL in a report group item; `DEVLOG/3537-pb5373-eight-of-the-21-no-witness-1985-rows-recorded-classes.md` line 7 calls it "the USAGE rule"), not a VALUE rule, and the compiler does admit a floating-point VALUE on a report entry. The statement that no form is lost to the `RawNumber` character filter therefore has no support there. The retirement needs only the first part of its argument (the VALUE literal arrives normalized through `DataBinder.RawValueOperandText`). Whether a floating-point VALUE on a report entry reaches `SUM` correctly is unprobed; whoever needs it probes it and files a defect. The retirement is not reopened.
