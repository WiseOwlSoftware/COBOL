# PB4466 - concurrent agents share one scratchpad directory and collide by file name

**Sites:** the session scratchpad convention (one folder for every agent of a session), the implementer and finisher briefs under
`.claude/skills/workstream/templates/` (they tell agents to write helper scripts there), and
`scripts/orchestrator/make_dispatch_specs.py` (where a per-agent directory would be rendered into each spec).

**What happened.** During the PB2296 wave the PB2359 implementer wrote `callers.py` into the shared scratchpad; the group D agent
wrote its own `callers.py` over it. The PB2359 agent then ran THEIR copy once, against THEIR worktree (`wf_fecdc036-63b-4`): it
re-applied that agent's intended renames to `ReferenceResolver.cs`, `ReportGroupResolution.cs` and `ReportWriterBinder.cs`. Nothing
of the first agent's changed, but another agent's script edited a tree it did not own. The mechanism that gave PB3702 a false green
(a shared gate log named by the caller) lets any shared file name carry one agent's work into another's.

**Fix shape.** Render a per-agent scratch subdirectory (keyed by workflow and slice id, as PB3702's run directory is) into each
dispatch spec and brief and tell agents to write only there; a `check_practices.py` rule refuses a brief or spec that names the
bare session scratchpad as a write target.
