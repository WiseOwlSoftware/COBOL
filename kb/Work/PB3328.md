# PB3328 — the landing lane has no per-branch hold

## Found (2026-10-17 ~11:00, the enqueue unit)
Evidence: `E:\COBOL-coord\scratch\enqueue-20261017-1100-lane-order.md`. At 10:46:59 the lane started `enqueue.py land` for c06-13
(PB370, 10 files under `tests/conformance/`), fa2-7 (PB1784, 21 files) and fa2-16 (PB3268, 21 files). All three carried
CLEAN stamps, so they read WAITING TO LAND. The operator steer `E:\COBOL-coord\scratch\operator-steer-restart-20261017.md`
section 1-2 ordered S2 (PB3177, the move to `conformance-suite/`) to land first and the lane not to attempt these before their
re-home. The unit could not carry that out and left the three running in all three gate slots.

## Mechanism (`scripts/orchestrator/land_lane.py`)
- `candidates` (line 446) returns every WAITING TO LAND row in survey order, then the retryable and re-armed ones; nothing
  lets a branch wait for another.
- `decide` (line 225) classifies a killed runner DIED, class ONCE, and retries it once at the next tick (line 250), so killing
  a runner only wastes a gate.
- `stop_reason` (line 403) knows only the global stops (STOP-UNIT, the loop's STOP, the owner's global STOP, HALT); each stops
  EVERY landing, and an enqueue unit may create none of them.
The only per-branch control is `rearm` (line 374), which can only start a landing, never withhold one.

## Harm
Either order is a cost: if the three queue before S2, S2's generator audit refuses their new `tests/conformance/` files and S2
needs one finisher that re-homes them; if S2 queues first, they bounce in the merge group and each needs its own re-home
finisher. The workaround used (leaving a branch unreviewed so it never reads WAITING TO LAND) does not help a branch that is
already CLEAN.

## Fix shape (the implementer decides)
- A per-branch `hold` record beside `rearm`: `land_lane.py hold <branch> --until-landed <branch> --why <text>`. `candidates`
  honours it (the held branch is not a candidate while the named branch is not on main) and the survey shows it
  (`HELD behind <branch>`), with a drift test beside the `rearm` self-test (line 910). It lifts itself when the named
  branch lands; a hold on a branch that never lands is listed, never silent.
- Or an `after:` landing dependency carried from the branch's report header, read by `candidates` through the same reader.
The first keeps the operator's ordering steer a mechanical record rather than a convention.
