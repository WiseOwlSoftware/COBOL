# PB5317 - scripts/spec/cite.py --check does not validate a 1985 citation's rule number: "§1985:XI.4.4.4 GR10" and even "GR99" pass with a quotation that sits in rule 7, while the same mistake in a 2023 citation fails

**Sites:**

- `scripts/spec/cite.py` (`check`)

**Mechanism.** CLAUDE.md rule 1 makes `cite.py --check` the mechanical validation of every citation, and its stated guarantee is that "a wrong clause number cannot pass quietly". For a 2023 citation it compares the rule ordinal with the numbered rule the quotation sits in (`FAIL: §2023:14.9.40.4 contains 'input procedure', but under rule 3) b), not GR99`). For a 1985 citation it checks only the clause: the quotation is found in the clause region and the rule number is never compared, so a citation with a real clause, a real quotation and a wrong rule number passes. Every 1985 citation checked since the 1985 locators were added is exposed (the code-read notes, the inventory rows' notes, docs/CONFORMANCE.md). The set-2 refuter found one such pass (a wrong GR3); the repro below is a fresh one. Until the fix, a note can compare the ordinal by hand: `cite.py` prints the numbered paragraph it found the quotation in.

**Repro.** From the repository root: `python scripts/spec/cite.py --check "§1985:XI.4.4.4 GR10" "The input procedure may consist of any procedure needed to select, modify, or copy the records that are made available one at a time by the RELEASE statement"`, then the same with `GR99`, then the control `python scripts/spec/cite.py --check "§2023:14.9.40.4 GR99" "input procedure"`.

**Observed (a build of origin/main d9dde0e7ba (the source exported to `E:/COBOL-coord/scratch/main-d9dde0e7ba`), rerun 2026-11-11).** The two 1985 checks exit 0 and print `OK  §1985:XI.4.4.4   (4.4.4 General Rules)` followed by the paragraph `(7) The input procedure may consist of ...`, so the tool itself shows the quotation is in rule 7. The 2023 control exits 1: `FAIL: §2023:14.9.40.4 contains 'input procedure', but under rule 3) b), not GR99`.

**Expected (from the 1985 text).** Both 1985 checks fail, naming rule 7.

**Fix direction (root cause, CLAUDE.md rule 4).** Give the 1985 transcription the same rule-path parse the 2023 one has (numbered paragraphs `(n)` with their lettered items) and compare the ordinal in the one check path both editions use; then re-run every 1985 citation in kb/Work, the inventory store and docs/CONFORMANCE.md through the fixed check, and file what it finds. Do not fix it on a records branch: scripts/ is being restructured.
