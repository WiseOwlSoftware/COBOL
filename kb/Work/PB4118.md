# PB4118 — DeclinedFacilityBinder.ClassifySend treats every TO operand that is no message-tag item as message-server-name

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/DeclinedFacilityBinder.cs#ClassifySend`, `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/DeclinedFacilityBinder.cs#ScreenName`, `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/DeclinedFacilityBinder.cs#BindSend`, `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/DeclinedFacilityBinder.cs#BindReceive`, `docs/CONFORMANCE.md` §4 item 1, `tests/WiseOwl.Cobol.Tests.Conformance/SendFormatClassificationTests.cs`, `tests/WiseOwl.Cobol.Tests.Unit/DeclinedFacilityOperandDriftTests.cs#ScreenedNames`, `conformance-suite/wiseowl/cases/14.9.38-SEND/pb4118-*`, `conformance-suite/wiseowl/cases/14.9.31-RECEIVE/pb4118-*`, `conformance-suite/wiseowl/diagnostics.json`

Review lead R1-1 (low, round 1) of PB4090. In `ClassifySend` (DeclinedFacilityBinder.cs:101 on the reviewed branch) every operand after TO
that is not a message-tag item is classified as message-server-name-1 with no test of its written shape. A message-server-name-1
(§14.9.38.3 SR2) is a bare name, and data-name-2 is a data-name, so no format prints a subscripted, reference-modified or qualified
reference, or a special register, after TO; each is accepted today as a server name. An under-reject on illegal source.

**Fix:** ask the written shape (the operand's text/segment form, as the other binders do through `WrittenSource.Of`) before treating it
as a server name; refuse the shapes no format prints. Pin with negatives for each shape (`SEND TO A(1) FROM x`, `SEND TO A(1:2) ...`,
`SEND TO A OF B ...`, a special register).

Source: report `w20261765b-PB4090-report.md`, review lead R1-1; PB4090 (landed). Related PB4085 (the SEND format screen).

## Landed (wave 20261773 D, 2026-10-30)

Re-probed on the tree first (Debug build, 0/0): `SEND TO TBL(1) FROM M RETURNING R`, `SEND TO R(1:2) FROM M RETURNING R`,
`SEND TO C OF B FROM M RETURNING R` and `SEND TO NOP OF B FROM M RETURNING R` (NOP declared nowhere) all compiled, and so did
the same operands as RETURNING's data-name-1 and RECEIVE's data-name-1 / data-name-2: the siblings of the one missing question.
(`SEND TO LINAGE-COUNTER ...` already died in the parser when RETURNING or RAISING followed; with `LINE-COUNTER` or a bare
statement it compiled.)

**Fix.** The question "how was this operand WRITTEN?" is asked before "what is it?". `DeclinedFacilityBinder.ScreenName` is
the ONE call of the existing data-name-n shape screen (`DataBinder.ScreenDataNameShape`, COBOL2024) for every operand the
general formats print as a NAME: SEND's TO operand (message-server-name-1 or data-name-2), RETURNING's data-name-1 and RECEIVE's
data-name-1 and data-name-2. A refused operand is read no further: it is not resolved, and it gives `ClassifySend` no format
evidence (a statement with no other evidence is `SendFormat.Unclassified`, so it is not also asked for a RETURNING it may not
need). **Qualified operands are NOT refused, which departs from this note's text:** §8.4.2.2.2 Format 1 makes a data-name a
qualified-data-name, so `A OF B` is a legal data-name-2. What the shape does decide is the FORMAT: a message-server-name-1 is a
bare name (SR2), so a qualified TO operand is Format 2's evidence exactly as a message-tag item is, it resolves like any data
reference (an undefined one is COBOL1639) and RETURNING beside it is COBOL5488. No new diagnostic code was needed
(COBOL5554-5556 returned).
