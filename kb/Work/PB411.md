# PB411 — one screen that rejects a shape SR6 admits, and one dispatch arm that never reaches the screen at all

**Rows:** `SR-14.9.18.3-6`, `SR-14.9.18.3-7`, `SR-14.9.18.3-8`. The three rules share ONE enforcement site, so
they share one note. All measurements re-run on this worktree's HEAD `cobol.exe` (base 89044aa0).

## MECHANISM 1 — the screen rejects an alphanumeric group, which SR6 admits (rejects legal source)

`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/ControlFlowBinder.cs#AdmittedStatusItem` (`:182-195`) is the
completeness structure for SR6's two alternatives. Its first line is

```csharp
if (p.Item.OperandPic is not { } pic) return false;
```

An alphanumeric group item has no elementary picture, so `OperandPic` is null and the operand is rejected
before either alternative is asked. The comment at `:192-194` states the intent correctly — "a data item WITH
USAGE DISPLAY OR NATIONAL, whatever its category" — but a group never reaches it.

That is the alternative the group satisfies. §8.5.2.1: "An alphanumeric group item is treated as though it had a
usage of display." An alphanumeric group therefore IS a data item with usage display, and SR6's second
alternative admits it. The inconsistency is visible inside the screen itself: a GROUP-USAGE NATIONAL group *is*
admitted (`:189`/`:194` via its usage), on exactly the reasoning that admits the alphanumeric one.

⚠ This is the "a real clause can answer a DIFFERENT question" shape. §8.5.2.1 does give an alphanumeric group
the class alphanumeric with no elementary description — a true statement about CLASS — and SR6's second
alternative is about USAGE, not class.

## MECHANISM 2 — the method arm never reaches the screen (under-rejects SR6, SR7, SR8 and the edition gate)

`Binding/Procedure/Verbs/CallBinder.cs#BindGoback:494` forks to `OoBinder.cs#OoBindMethodGoback` when
`host.InMethod`. That method (`:1045-1051`) reads `g.dataReference()` and `g.raisingPhrase()` and **never reads
`g.statusPhrase()`** — the phrase is silently discarded. `ControlFlowBinder.cs#BindTerminationStatus` (`:78`),
the single place SR6/SR7/SR8 are enforced (via `ScreenStatusOperand` `:130` and `IsIntegerLiteralText` `:200`),
is unreachable in a method context. The same drop swallows the COBOL-2023 introduction gate.

`OoBindMethodGoback`'s own doc comment (`:1043-1044`) asserts that "the RETURNING/GIVING and 2023 status
phrases" stage loud in a method. That is true of RETURNING/GIVING (`:1047-1049` returns a `BoundUnsupported`)
and false of the status phrase — `docs_current_state_only`.

## EXPECTED vs OBSERVED — re-measured on HEAD

`cobol.exe <src> --std <ed>`.

**Mechanism 1** — `scratchpad/probe-g3-goback-goto/grp/gbgrp.cob`: `01 WS-GRP.` with two `PIC X` subordinates,
then `GOBACK WITH ERROR STATUS WS-GRP.` **Expected:** compiles (SR6, second alternative, via §8.5.2.1).
**Observed at --std 2023:**

```
gbgrp.cob(11,12): error COBOLNET1704: the status operand 'WS-GRP' shall reference an integer data item or a
data item with usage display or usage national (ISO 14.9.42.3 SR2 for STOP RUN; 14.9.18.3 SR6 for GOBACK)
```

The identical program with `STOP RUN WITH ERROR STATUS WS-GRP.` (`grp/stgrp.cob`) draws the identical
diagnostic — one screen, both verbs.

**Mechanism 2** — `scratchpad/probe-g3-goback-goto/methstatus/`, an OBJECT method invoked from a driver:

| probe | method body | expected | OBSERVED |
|---|---|---|---|
| `zerolen.cob` | `GOBACK WITH ERROR STATUS "".` | COBOLNET1704 citing SR8 | compiles clean at **2023, 2014 and 2002**; runs `IN-METHOD` / `AFTER-INVOKE` |
| `nonint.cob` | `GOBACK WITH ERROR STATUS 1.5.` | COBOLNET1704 citing SR7 | compiles clean, runs |
| `plain.cob` (control) | a legal status phrase | compiles; inert in a non-main element | compiles, runs |

The program arm, for contrast, is measured correct on HEAD: `GOBACK WITH ERROR STATUS 5.` at `--std 2014` and
`--std 2002` draws `COBOLNET0900: GOBACK WITH NORMAL/ERROR STATUS requires COBOL-2023` and compiles clean at
2023 (`scratchpad/probe-g3-goback-goto/gate/gbgate.cob`). So the edition gate exists on one arm only — the
two-arm dispatch shape, not a one-rule miss.

## THE SHAPE OF THE REPAIR

⛔ Do not add a `p.Item.OperandPic is null → is it an alphanumeric group?` special case at `:184`, and do not
copy `BindTerminationStatus` into `OoBindMethodGoback` (CLAUDE.md rule 5).

- **Mechanism 1** is a classifier gap, not a status-phrase gap: `AdmittedStatusItem` needs a USAGE answer for a
  group item, which the one §8.5.2.1 classifier should give it (`IntrinsicArgumentRules.ClassOfPlace` is
  already consulted at `:186` for pointer/object). Give the classifier the group-usage answer once and every
  position that asks "is this a data item with usage display" gets it — this is the same defect shape
  [[PB169]] and [[PB217]] exist to close, one group kind over.
- **Mechanism 2** is a dispatch gap: the method fork at `CallBinder.cs:494` hands the whole
  `GobackStatementContext` to a second binder that re-decides which phrases exist.
  `change_the_dispatch_not_the_callers` — the phrase decoding (RETURNING, RAISING, STATUS) belongs on ONE path
  that both arms share, with the arms differing only in what they do with the decoded parts. Then a phrase
  added to the grammar cannot be silently dropped by one arm again. Pair it with a drift test that every
  sub-context of `gobackStatement` is read on both arms.

## THE SIBLING SWEEP

1. **STOP RUN** carries mechanism 1 verbatim (§14.9.42.3 rule 2 is SR6's twin, and the diagnostic text already
   cites both). Fix once, prove both.
2. **A GREEN TEST HOLDS MECHANISM 1 OPEN and must be re-baselined, not preserved.**
   `tests/Cobol.Net.Tests.Conformance/StopGobackExitCodeTests.cs:234`
   (`TheStatusPositionsOwnRules_AreEnforcedAndCited`) carries an `InlineData` row asserting that a group status
   operand draws COBOLNET1704, and `:187`
   (`RefModAndNationalGroupStatusOperands_AreAdmittedBySR2`)'s doc comment states that the alphanumeric group
   stays rejected. `tests/conformance/negative/pb169-status-group-identifier.{cob,err}` is the corresponding
   negative fixture. All three pin the wrong answer (`feedback_green_test_can_hold_a_gap_open`) and all three
   must flip with the fix.
3. **The other method-arm phrases**: `OoBindMethodGoback:1047` also rejects `GOBACK RETURNING` inside a method
   as unsupported. That is a separate question ([[PB407]] covers whether the phrase belongs in the grammar at
   all) but it lives at the same site and should be re-examined in the same change.
4. **Every other `InMethod` fork.** The mechanism is "a second binder re-reads the parse context and misses a
   sub-context"; grep `host.InMethod` and check each fork against the phrases its grammar rule can carry.
5. Edition sweep: after the fix the method arm must draw COBOLNET0900 at 2002/2014, exactly as the program arm
   does — that is the cheapest single assertion proving both arms now share the path.
