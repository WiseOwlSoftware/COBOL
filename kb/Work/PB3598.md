# PB3598 - the implicit bit filler has no storage in the ODO, dynamic-capacity and leaf-vector shapes

PB3564 gave the implicit filler after a USAGE BIT item a stored hidden field in the common shapes (`MOVE "AB" TO G1` then `DISPLAY G1`
now keeps `AB`). Its note registers three shapes as "not stored, reads zero as before" in prose only; this note makes them trackable
(PB3564 holds the prose, not a work item). Same defect: 8.5.1.6.3 makes the filler bits data, and a group MOVE (14.9.25.4) must carry
them.

1. A run holding an OCCURS DEPENDING bit table stores no tail, because the tail moves with the count (`BitLayout.HasFixedTail`;
   `GroupImageCodec.OdoPrefixImage` and the `FromVarImage` reader).
2. The elements of a dynamic-capacity bit table keep no padding (`GroupImageCodec.DynElementImage`).
3. A strongly-typed group carried as a leaf vector drops the filler (`RecordStructEmitter.EmitLeafMethods`).

## Fix shape (for the implementer)

State the filler per shape once: for ODO the tail is a function of the current count and travels with the prefix image; a dynamic
element image includes its pad; a leaf vector carries the filler positions `BitLayout.FillersOf` names. Reuse `FillerPositions` as the
single enumeration. Goldens per shape (MOVE of an alphanumeric to the group, then DISPLAY and a byte read), 2002/2014/2023. Run each
citation through `cite.py --check` first.

**Sites:** src/Cobol.Net.Compiler/Binding/Model/BitLayout.cs, src/Cobol.Net.Compiler/CodeGen/DataDivision/GroupImageCodec.cs, src/Cobol.Net.Compiler/CodeGen/DataDivision/RecordStructEmitter.cs

Lines: `GroupImageCodec.cs:400` (`OdoPrefixImage`), `:466` (`DynElementImage`), `RecordStructEmitter.cs:207` (`EmitLeafMethods`) on
main; `BitLayout.cs:342` (`HasFixedTail`) on PB3564's branch `worktree-wf_37d4041f-6f7-47` (87a2182c2; it replaced `StoresTail` there).
