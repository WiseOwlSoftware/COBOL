# PB2071 — OPEN — is a REDEFINES inside an UNUSED strong type declaration a syntax-rule violation?

## Repro

```cobol
       01 U IS TYPEDEF STRONG.
          05 UX PIC X(4).
          05 UY REDEFINES UX PIC X(4).
```

with no `TYPE U` anywhere compiles clean (any edition with TYPEDEF STRONG). Add `01 V TYPE U.` and it is rejected
COBOLNET1697 (PB1282's landing, negative `pb1282-redefines-in-strong-typedef`).

## Code site

`src/Cobol.Net.Compiler/Binding/DataBinder.cs#Sr12Sr14Violation` (callers at DataBinder.cs:7361 and :7499) is asked
of a TYPE subject's expanded members, so a type declaration with no subject is never visited.

## The question

§13.18.44.3 SR14 (cite.py OK): "Data-name-2 shall not be of class object, message-tag, or pointer, a strongly-typed
group item, or an item subordinate to a strongly-typed group item." §13.18.58.4 GR2 (cite.py OK): "A type declaration
has no storage associated with it." and GR3: "All other data description clauses and subordinate data descriptions
are assumed by data defined using the type-name." One reading: UX is not yet a data item (no storage), so SR14 bites
only when GR3 hands the clause to an instance — today's behavior. The other: UX is written subordinate to a strong
group's description, so the source is already non-conforming and an unused template should be rejected the same way.
GnuCOBOL has no STRONG; decide under CLAUDE.md rule 1's precedence and record the choice in docs/CONFORMANCE.md.
