# PB1502 — OPEN

## The rule (every citation re-run through `cite.py --check`)

> 5) If a given method-name is inherited from more than one interface, the method prototype in each inherited interface shall be such that this interface conforms to all inherited interfaces.

`OK  §11.6.3 5)  (Syntax rules)`

> 6) A given interface-name shall not appear more than once in an INHERITS clause.

`OK  §11.6.3 6)  (Syntax rules)`

> b) if this method definition is contained in an interface definition, no inherited method prototype shall have the same method resolution signature as the method prototype declared by this method definition.

`OK  §11.7.3 4) b)  (Syntax rules)`


## Finding — `interface-id-paragraph` (under-rejects; rows `SR-11.6.3-5`)

**Mechanism.** INTERFACE-ID multiple inheritance never checks that the inheriting interface conforms to every inherited interface: OoClassTable.Build enforces §11.6.3 SR2/SR3/SR6 but has no SR5 arm, and OoInterfaceSymbol.AllPrototypes merges the inherited prototype rosters first-declaration-wins by name (its comment claims SR5 is validated at Build; it is not).

**Repro.** --std 2002: INTERFACE-ID. N5A. PROCEDURE DIVISION. METHOD-ID. SPEAK. DATA DIVISION. LINKAGE SECTION. 01 X PIC 9. PROCEDURE DIVISION USING X. END METHOD SPEAK. END INTERFACE N5A. / INTERFACE-ID. N5B. PROCEDURE DIVISION. METHOD-ID. SPEAK. PROCEDURE DIVISION. END METHOD SPEAK. END INTERFACE N5B. / INTERFACE-ID. N5C INHERITS FROM N5A N5B. ENVIRONMENT DIVISION. CONFIGURATION SECTION. REPOSITORY. INTERFACE N5A INTERFACE N5B. END INTERFACE N5C. (probe: out/probe/interface-id-paragraph/sr5_conflict.cob)

**Expected from the spec.** A compile-time error on N5C: SPEAK is inherited from two interfaces with 1 and 0 formals, so by §9.3.8.2.3 rule 1 N5C (one SPEAK) cannot conform to both, which §11.6.3 SR5 and §9.3.10 ('The inheriting interface shall always conform to each of the inherited interfaces') require. Identical prototypes in both bases (sr5_same.cob) must stay legal.

**Observed / reasoning.** Compiles rc=0 with no diagnostic. The violation only appears later if some class IMPLEMENTS N5C (sr5_impl.cob: COBOLNET0841 citing the N5A prototype), i.e. it is attributed to the class, not the illegal interface; an unimplemented interface is accepted. The same mechanism also admits an interface whose OWN prototype contradicts an inherited one (sr5_own_vs_inherited.cob: N5OC declares SPEAK() and inherits SPEAK USING X -- accepted), which §9.3.10's conformance sentence forbids. Fix shape: a Build-time pass comparing, per method name, every inherited prototype (own + closure) through the SAME §9.3.8.2.3 comparator the class-conformance pass (COBOLNET0841) already uses.

**Code site.** src/Cobol.Net.Compiler/Oo/OoClassTable.cs#Build (interface INHERITS block after the SR6 check); src/Cobol.Net.Compiler/Oo/OoInterfaceSymbol.cs#AllPrototypes

## Finding — `method-id-paragraph` (under-rejects; rows `SR-11.7.3-4`)

**Mechanism.** §11.7.3 SR4 b) has no implementation: the interface arm of OoClassTable.Build rejects a duplicate prototype only WITHIN one interface (TryAddPrototype), and OoInterfaceSymbol.AllPrototypes absorbs a prototype redeclared from an INHERITED interface ('first declaration wins'). Since SR2 forbids OVERRIDE in a prototype, every such redeclaration is illegal and is silently accepted.

PING.; INTERFACE-ID MQ5J INHERITS FROM MQ5I (REPOSITORY INTERFACE MQ5I) with prototype METHOD-ID. PING. Compile --std 2002 / 2023.

**Expected from the spec.** Compile-time error: §11.7.3 SR4 b) 'if this method definition is contained in an interface definition, no inherited method prototype shall have the same method resolution signature as the method prototype declared by this method definition' (OVERRIDE not specified — and §11.7.3 SR2 forbids it in a prototype).

**Observed / reasoning.** Compiles clean (rc 0, no diagnostic) at 2002 and 2023. The class arm (SR4 a) is enforced (COBOLNET0837, incl. an indirect ancestor — probe p8); only the interface arm is missing — the two-arm-dispatch shape.

**Code site.** src/Cobol.Net.Compiler/Oo/OoClassTable.cs#Build (interface prototype loop / interface INHERITS resolution); src/Cobol.Net.Compiler/Oo/OoInterfaceSymbol.cs#AllPrototypes

## Row `SR-11.6.3-6` — PARTIAL (editions 2002, 2014, 2023 (the OO facility, introduced by ISO/IEC 1989:2002; interface definitions are rejected COBOLNET0900 at 85))

Rule (cite.py --check 11.6.3 OK, SR 6): 'A given interface-name shall not appear more than once in an INHERITS clause.' Code: when a resolved base is already in isym.Inherits, COBOLNET0840 'duplicate INHERITS FROM ... (ISO §11.6.3 SR6)'. Probe probe/interface-id-paragraph/sr6_dup.cob (N6B INHERITS FROM N6A N6A) -> COBOLNET0840 at the second N6A. The comparison is on the resolved symbol, so a case-variant spelling of the same word is caught too (names resolve case-insensitively). Edge noted, not a defect: two DIFFERENT repository words aliasing one externalized interface would also be caught (symbol identity), which is the stricter reading. No existing spec-derived test -> test-needed. || REFUTED: PARTIAL — The literal-name half is correct. Repeating the same interface-name is rejected, including a case variant (R7A r7a is one COBOL word), at 2002 and 2023. But the duplicate test keys on the RESOLVED SYMBOL, not the written interface-name. Two DIFFERENT interface-names that are REPOSITORY aliases of one externalized interface (INTERFACE R6X AS "EXT-R6A" and INTERFACE R6Y AS "EXT-R6A") are rejected with a message citing SR6. SR6's text forbids only the same interface-name appearing twice, and §12.3.8.3 SR1 constrains only the same name specified twice, so nothing in the cited rule forbids that source. The code enforces a broader rule under SR6's name. Whether that source should be legal is arguable: C# forbids a repeated base, so the emitter would have to dedupe. That uncertainty is enough to deny CONFORMS. At fix time, either dedupe silently with a design-doc note or cite the rule that actually forbids it.
