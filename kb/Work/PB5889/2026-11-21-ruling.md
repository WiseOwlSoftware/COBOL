# PB5889 ruling (controller, account 2 operator session, 2026-11-21): accept every form not shown to be non-integer; check at run time

**The text decides the first half.** A form that always yields an integer is conforming source and must be accepted at
every edition: §1985:I.1.5.2 ("must fully support all the language elements of that subset") and §2023:4.2.2 ("shall
accept the syntax and provide the functionality"). The type bar applies only where a numeric FUNCTION is itself the integer
argument (§1989:A.2.3 GR2, §2023:8.4.3.2.3 SR11), not to an expression containing one. So refusing `S2 - FUNCTION MAX (S2)`
or `FUNCTION MEAN (N, N) + 1` (COBOL1627 today, at 85 and 2023) rejects legal source: option (a), keeping the refusal, is
out. (Adjudication `E:/COBOL-coord/scratch/w20262131/pb5889/finding.md`, every citation cite.py OK.)

**The text leaves the second half to the implementor.** Detecting a breach of the integer rule is not required at 1985
(§1985:I.1.6: programs "violating the formats or rules ... are undefined"; at run time §1989:A.2.2 p3 "the result of such a
reference is undefined", and Amendment 2, §1993:p.B-46, "allows an implementation ... to terminate processing"). At 2023
compile-time detection is the implementor's (§2023:4.2.2 "left to the implementor's discretion to determine what is
syntactically distinguishable"; §2023:14.6.13.1.3 GR8), and at run time a non-integer argument raises EC-ARGUMENT-FUNCTION
(§2023:15.3 AR14).

**Decided (option b, every edition):** the integer-argument screen has THREE outcomes, not two:
- PROVEN INTEGER (today's type and literal reasoning): accept;
- SHOWN NON-INTEGER (the screen exhibits a value of the operands at which the expression is not an integer, as today's
  `MOD (N / 3, 2)` message does, "at N = 1 it is 1/3"): refuse COBOL1627, the message naming that value;
- UNDECIDED (neither): accept, and emit a run-time check of the argument's value: at 2023 (and 2002/2014, whose texts
  carry the same exception; the implementer cites each) a non-integer raises EC-ARGUMENT-FUNCTION under the edition's
  checking rules; at 1985 the run unit terminates with a message naming the function, the argument and the value
  (the Amendment 2 permission).
A refusal now requires a counterexample; the absence of a proof is never a refusal. That is the shape that makes the next
form automatic (rule 5): no list of accepted identities, no algebra. The register documents the determination (what the
screen proves, what it refutes, what it leaves to run time) as an Annex A.1 / section 3 entry, so the latitude is stated.
The COBOL1627 message's malformed citations (`§2023:15.36.3 r1`, `§2023:15.64.3 r1`, `§2023:15.3 type 6`) are fixed in the
same change. Implemented by wave 20262131 group l (branch train85b-intarg).

**Addendum (controller, same day): the implementer's objection is upheld.** A counterexample is a value of the expression's
OPERANDS (data items, literals) at which the expression is not an integer. A value assigned to a function's result
(`FUNCTION ORD (A) = 1`) is not one unless the function's range is shown to include it, and the screen does not model
function ranges; so the four PB5886 forms that rested on such a value are checked at run time, not refused. Modelling each
function's range is not owed: the run-time check is conforming at every edition.
