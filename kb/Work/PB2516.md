# PB2516

Filed from the PB1954 refuter (`E:\COBOL-coord\scratch\w1033-adj\PB1954-refute.md`, Amendment C), whose flags are under-rejects and silent with no diagnostic; `wrong_answer: true` is added because the same file shows B's storage merged into D (`LENGTH` 2, `MOVE "ZZ" TO D` changes B). Searched by the refuter: no existing note (PB1309 covers only a section's first entry).

**Observed (pinned build `pin-97006f3`).** `wsconst.cob`: `01 D. 05 A PIC X VALUE "A". 01 K CONSTANT AS 3. 05 B PIC X VALUE "B".` with `DISPLAY D` compiles clean at 2002, 2014 and 2023 and prints `AB`. `wsconst2.cob`: `FUNCTION LENGTH(D)` prints `2`, and after `MOVE "ZZ" TO D`, `B` prints `Z`. At 85 it is refused only because constant entries do not exist there. GnuCOBOL 3.2.0: `wsconst.cob:8: error: level number must begin with 01 or 77`. Probes in `E:\COBOL-coord\scratch\w1033-adj\PB1954-refute\`.

**Expected from the spec (cite.py --check OK).** `§13.5.2` lists `constant-entry` and `record-description-entry` as separate alternatives; `§13.16.2` has no constant format, so a constant entry is not a data description entry; `§13.11.1`: "A record description entry consists of a set of data description entries, the first of which shall have level-number 1". So the constant ends D, and `05 B` begins a record description that does not start at level 1: the shape PB1246's empty-stack arm already refuses (COBOLNET2771).

**Site.** `src/Cobol.Net.Compiler/Binding/DataBinder.cs#BindEntries`, the constant-entry handling at about lines 891-898, which `continue`s without closing the level stack. The report arm is unaffected (`rptconst` is refused COBOLNET2772). Fix: close the stack at a constant entry; negative golden `wsconst` at 2002+. Related: `PB1954`.
