# PB2516

Filed from the PB1954 refuter (`E:\COBOL-coord\scratch\w1033-adj\PB1954-refute.md`, Amendment C), whose flags are under-rejects and silent with no diagnostic; `wrong_answer: true` is added because the same file shows B's storage merged into D (`LENGTH` 2, `MOVE "ZZ" TO D` changes B). Searched by the refuter: no existing note (PB1309 covers only a section's first entry).

**Observed (pinned build `pin-97006f3`).** `wsconst.cob`: `01 D. 05 A PIC X VALUE "A". 01 K CONSTANT AS 3. 05 B PIC X VALUE "B".` with `DISPLAY D` compiles clean at 2002, 2014 and 2023 and prints `AB`. `wsconst2.cob`: `FUNCTION LENGTH(D)` prints `2`, and after `MOVE "ZZ" TO D`, `B` prints `Z`. At 85 it is refused only because constant entries do not exist there. GnuCOBOL 3.2.0: `wsconst.cob:8: error: level number must begin with 01 or 77`. Probes in `E:\COBOL-coord\scratch\w1033-adj\PB1954-refute\`.

**Expected from the spec (cite.py --check OK).** `§13.5.2` lists `constant-entry` and `record-description-entry` as separate alternatives; `§13.16.2` has no constant format, so a constant entry is not a data description entry; `§13.11.1`: "A record description entry consists of a set of data description entries, the first of which shall have level-number 1". So the constant ends D, and `05 B` begins a record description that does not start at level 1: the shape PB1246's empty-stack arm already refuses (COBOLNET2771).

**Site.** `src/Cobol.Net.Compiler/Binding/DataBinder.cs#BindEntries`, the constant-entry handling at about lines 891-898, which `continue`s without closing the level stack. The report arm is unaffected (`rptconst` is refused COBOLNET2772). Fix: close the stack at a constant entry; negative golden `wsconst` at 2002+. Related: `PB1954`.

## Landing (wave 1037 group B)

Re-probed on the wave's own build first: `wsconst` compiled clean and printed `AB`, `wsconst2` printed `2` and `Z` (as filed). After the fix both are refused COBOLNET2771 at `05 B` at 2002, 2014 and 2023.

- `src/Cobol.Net.Compiler/Binding/DataBinder.cs#BindEntries`: the local `CloseRecord(stillOpen)` is the ONE place the walk ends a record short of the next level-1 data entry (level stack, `lastDescribed`, `renamesBegun`, the template state and the new `openRecord`). The constant-entry arm calls `CloseRecord(null)`; the prebound-record arm calls it with the prebound root. `openRecord` replaces `newRoots[^1]` as the level-66 owner, so a 66 after a constant entry is refused COBOLNET2740 (`ScreenRenamesPlacement`, §13.18.45.3 SR2) instead of silently renaming the record before the constant: a sibling under-reject of the same open-record state, fixed here. A TYPEDEF template is closed the same way (`01 T IS TYPEDEF. 05 A. 01 K CONSTANT AS 3. 05 B.` no longer adds B to T).
- `src/Cobol.Net.Compiler/Binding/DataBinder.EntryOrder.cs#EndsRecord` already drew this boundary for the out-of-order binder; `DataBinder.Reports.cs#BindReportSectionEntries` already does for the report arm (`rptconst` COBOLNET2772). Every `constantEntryBody()` reader in `src/` was swept: no other walker keeps a level stack across a constant.
- Spec (cite.py --check OK): §13.5.2 (constant-entry is its own alternative), §13.11.1 ("the first of which shall have level-number 1"), §13.10.1, §13.18.45.3 SR2.
- Goldens: `negative/pb2516-constant-ends-record` (COBOLNET2771) and `negative/pb2516-renames-after-constant` (COBOLNET2740), reject-at 2002 2014 2023; positive `2002/pb2516_constant_between_records` (constants between records stay legal, the 66 before a constant still renames its record).
- Rows: re-verdicted `GR-13.18.33.4-1` and `SR-13.18.45.3-2` (both recorded CONFORMS, false for the constant case until now) with the new witnesses; batch `E:\COBOL-coord\scratch\w1037b\batch-pb2516.json`.
