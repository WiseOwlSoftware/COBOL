# PB4431 - CallBinder operand texts still taken by GetText()

**Defect.** `kb/Work/PB4267.md` (landed) says every CallBinder message that quoted a node now uses `DataBinder.WrittenText`.
The report finds five calls that still pass `GetText()` as the operand text to `ValueClassScreen` (COBOL1628) and
`AddBareExpressionArg`, so a qualified BY VALUE operand (`A OF G`) prints glued (`AOFG`).

**Witness.** `E:/COBOL-coord/scratch/reports/w20261821a-PB2103-report.md`, Review findings R1-2 (low, not blocking at round 1). At origin/main
`CallBinder.cs` lines 430 (`vdref.GetText()`), 459 (`vax.GetText()`), 550 (`bare.GetText()`), 614 (`bArith.GetText()`)
and 621 (`a.GetText()`). Not probed by the reporter; probe each with a qualified operand and a ZERO operand.

**Fix direction.** Name each node as written through `DataBinder.WrittenText`, as PB4267 did for the rest of the file; then
sweep the six binders for any remaining `GetText()` inside a message (PB4252 is the drift-test analysis).
