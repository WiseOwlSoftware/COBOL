# PB6184 — a queued chain predecessor is held back by its own chain

**Timeline (2026-11-24).** `worktree-wf_c37a519f-ba4-15` was stamped (DEVLOG 4036) and queued as pull request #2063, which bounced
(`merge_conflict`, 14:54Z). A conflict finisher fixed it and it was reviewed CLEAN at `c06642d2f9`. The survey
(`prune_worktrees.py`) then classed it IN FLIGHT: "continued by dispatch w20262164a on worktree-wf_38508f28-551-1: the chain lands once,
with its last link" (kb/Work PB4396), so `land_lane.py` `candidates()` never offered it for landing again. Its two successors,
`worktree-wf_38508f28-551-1` and `worktree-wf_dc6f75bb-a8b-25`, each ended exit 15 PREDECESSOR QUEUED, waiting on #2063 (land-lane
attempts 001218 and 001228). The chain was deadlocked: the predecessor waited for its successors to land it, and the successors
waited for the predecessor's pull request to land.

**Why it contradicts the rule.** `enqueue.py` (PB3693, PB3145) lands a stamped, queued predecessor on its own pull request: the
successors wait on that pull request. `prune_worktrees.py` `chain_links()` (PB4396: "one step per file, the chain lands once, with its
last link") reclassifies a link `WAITING TO LAND` that a later link continues as IN FLIGHT, and its docstring says "a pull request
already queued lands as queued". A link whose pull request bounced and was then repaired is `WAITING TO LAND` again but owns an open
pull request (#2063) that a successor's exit 15 names. The two rules read different facts.

**Break (done by hand).** The enqueue unit ran `python scripts/orchestrator/land_lane.py rearm worktree-wf_c37a519f-ba4-15`.

**Fix shape.** `chain_links` (or `candidates`) must not class IN FLIGHT a chain link that owns an open pull request: a link a successor
waits on by pull request (its successors' last land-lane attempt is exit 15 PREDECESSOR QUEUED, or `gh pr list --head <branch>` is
open) lands on that pull request, the one rule of PB3693/PB3145. A drift test builds a chain (predecessor with an open pull request at its
tip, a continuing dispatch) and asserts the survey leaves it for the landing lane.

**Sites:** `scripts/prune_worktrees.py:1331` (`chain_links`), `scripts/orchestrator/land_lane.py:1395` (`candidates`)
