# PB4256 — a carrier waits forever on a predecessor pull request that left the merge queue

**Sites:** `scripts/orchestrator/enqueue.py` (`open_pull_requests`, `open_predecessors`, `awaited_predecessors`, `driver_file_holders`), `scripts/orchestrator/land_lane.py` (`predecessor_free`, `driver_files_free`).

## The case (measured 2026-10-31)

PR #894 (`worktree-wf_94e81f77-f38-7`, PB107, stamped DEVLOG 2861) was queued at 18:17Z and left the merge queue at 18:49Z
(`RemovedFromMergeQueueEvent`, reason `failed_checks`). The bounce finisher pushed d917370e0 to that branch at 18:55Z, which
turned auto-merge off (`autoMergeRequest: null`). The review lane reviewed d917370e0 FINDINGS at 19:10Z (two blocking
mediums). Wave 20261787 group B, its review finisher, worked on a successor branch (`worktree-wf_74ca01bc-99c-2`, after:
f38-7). That branch was reviewed CLEAN at 6d1fcc280 and carried #894's stamped entry 2861 beside its own 2874.
`enqueue.py land` then ended exit 15 PREDECESSOR QUEUED, naming #894 (attempt 000480-20261031T201828Z). The lane retries
exit 15 only once no open pull request owns the entry. #894 stayed open and nothing would ever queue it again: its head
had FINDINGS, and the survey reads f38-7 as contained in worktree-wf_74ca01bc-99c-2, so its work lands through that
branch. The wait could never end. The status showed only RETRY-WHEN-FREE and nothing alerted anyone.

## The mechanism

`open_pull_requests`, the one listing behind `open_predecessors`, `awaited_predecessors`, `driver_file_holders` and the
lane's `predecessor_free`, counts every open pull request into main as one that will merge. That includes a pull request
outside the merge queue, with auto-merge off, whose head a carrier contains: it can never merge. The same stranded pull
request would hold the carrier at exit 16 DRIVER FILE QUEUED forever when both change a merge-driver file.

## Hand action

Every hand action is a loop defect (O11). The enqueue unit closed #894 as superseded at about 20:28Z. The lane's retry then
ended exit 6 NO ENTRY (two stamped entries), and a finisher folds the two entries into one.

## Root-cause candidates (the implementer decides)

(a) `land` treats an open predecessor pull request that is neither queued nor auto-merging, and whose head the branch
contains, as superseded: it closes it with a comment naming the carrier and folds its stamped entry. (b) The planner gives
the review finisher of a branch that already owns an open pull request THAT branch, so `queue` reuses its pull request and
never makes a successor.
