## Measured

### Finding occurs-clause-p1 — §13.18.38.3 SR18, SR21 (under-rejects; rows SR-13.18.38.3-18, SR-13.18.38.3-21)

**Mechanism.** OdoResolve never checks data-name-1's GLOBAL / EXTERNAL attribute against the table's record

**Repro.** `01 N PIC 9 VALUE 2. 01 G GLOBAL. 05 T PIC X OCCURS 1 TO 5 DEPENDING ON N.` (out13/probe/occurs-p1/sr18_global_bad.cob); `01 N PIC 9 VALUE 2. 01 E EXTERNAL. 05 T PIC X OCCURS 1 TO 5 DEPENDING ON N.` (sr21_external_bad.cob)

**Expected, from the standard.** Both rejected. SR18: data-name-1 'shall be a global name and shall reference a data item that is described in the same data division'. SR21: data-name-1 'shall reference a data item possessing the external attribute that is described in the same data division'.

**Observed.** Both compile clean and run. An external record's current extent then depends on a non-external, per-program counter, so two run-unit programs sharing E can disagree about its length.

**Code site.** src/Cobol.Net.Compiler/Binding/DataBinder.Odo.cs#OdoResolve (after `spec.Depending = dep;`)

### Finding occurs-clause-p1 — §13.18.38.3 SR20; §13.18.33.4 GR3 (under-rejects; rows SR-13.18.38.3-20)

**Mechanism.** SR20's byte-range test compares record ROOTS (`ReferenceEquals(RootOf(dep), RootOf(item))`) rather than STORAGE AREAS, so a counter in a sibling FD record (the same area by implicit redefinition) escapes

**Repro.** `FD F. 01 R1. 05 T PIC X OCCURS 1 TO 5 DEPENDING ON N. 01 R2. 05 N PIC 9.` (out13/probe/occurs-p1/sr20_fd_shared.cob)

**Expected, from the standard.** Rejection. §13.18.38.3 SR20 forbids data-name-1 any byte position from the table's first byte to the end of its record, and §13.18.33.4 GR3 says 'Multiple level 1 entries subordinate to a FD or SD entry represent implicit redefinitions of the same area', so N sits on T's first byte.

**Observed.** Compiles clean. The same-record case is rejected correctly (COBOLNET0857).

**Code site.** src/Cobol.Net.Compiler/Binding/DataBinder.Odo.cs#OdoResolve (the SR20 block)
