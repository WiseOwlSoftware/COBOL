# PB5355 - HIGH-VALUES into PACKED-DECIMAL stores +0, undocumented

**Site:** `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/MoveEmitter.cs` (`FigurativeToNumericImageStore`; the report's line 296 is the nearest doc comment).

**Source:** review lead R1-3 (info, not blocking at round 1), from `E:/COBOL-coord/scratch/reports/w20262000b-PB5141-report.md` "Review findings".

For a PACKED-DECIMAL receiver the byte-fill of HIGH-VALUES (or any fill that is not a valid packed form) decodes through the tolerant `ParsePackedImage` (reached through `NumericRenderer.CarrierOfImage`) to +0. The determination in docs/CONFORMANCE.md 3.10 ("the value the receiver storage bytes hold ... read in the item byte form") does not state that result, and the golden `pb5176_move_figurative_binary_receiver` tests only LOW-VALUES into COMP-3.

**Fix direction:** decide, against the ISO text for a figurative constant moved to a numeric receiver (check any quotation with `cite.py` before writing it down), whether +0 is the right value or the move should refuse or retain the invalid image; then state the result in docs/CONFORMANCE.md 3.10 and add a HIGH-VALUES golden for COMP-3 and the other packed usages.
