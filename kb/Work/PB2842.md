# PB2842 — LANDED — the in-statement store reload maps a host failure to the permanent error 30

Found by the train 1047 lander's review (step 5b) and filed by it, 2026-10-08 20:54 PDT. Reviewer finding on cluster 47B (PB2692+PB2748+PB2751), CONFIRMED pre-existing; the train corrected the
comment that claimed otherwise (`KeyedConnector.ReadImage`).

## Mechanism
`KeyedConnector.ReadImage` throws an `IOException` for a file longer than `RecordFraming.MaxStoreBytes`
(kb/Work PB2748). At OPEN, `FileConnector.Open`'s catch maps it to '30' (§9.1.13.6 1), "no further information is
available"). A reload inside a later statement — `KeyedConnector.Enter` (~line 297), reached from
`FileRegistry.BeginStatement` (`FileRegistry.cs:624`) and the other statement entry points when another run unit
moved the generation stamp — has no `IOException` catch, so the exception escapes the run unit.

## Repro to build
Two run units sharing an INDEXED file `SHARING WITH ALL OTHER`; the second grows the file past `MaxStoreBytes` (or a
test overwrites it with an oversize image between statements); the first's next READ. Expected '30'; observed (by
trace) an unhandled IOException.

## Code sites
`src/Cobol.Net.Runtime/IO/KeyedConnector.cs#Enter`, `#ReadImage`; `src/Cobol.Net.Runtime/IO/FileRegistry.cs#BeginStatement`.

## Landed
Re-probed on the branch build: the repro was a unit test (two `FileRegistry` instances = two run units; the second
writes, then the file is extended past `RecordFraming.MaxStoreBytes` through a third handle), and every keyed verb
(READ NEXT, random READ, WRITE, REWRITE, DELETE, START FIRST, START key, plus the unshared READ NEXT / WRITE
entries) on both organizations threw the `IOException` out of `KeyedConnector.Enter`; the RETRY wait re-entry
(`WaitOutsideStatement` finally block) threw it out of the wait.

Fix: `KeyedConnector.Enter` catches a host failure (`IsHostStoreFailure`: `IOException`, `UnauthorizedAccessException`,
`OutOfMemoryException`; the one predicate `CompleteStatement` now shares) and sets I-O status 30
(§9.1.13.6 1), which starts the §9.1.13.1 permanent error). The statement stays entered, so depth and mutex unwind
through the ordinary Dispose, and every verb first line (`FileConnector.PermanentErrorReplay`) ends the statement
before the stale store is read; READ and START invalidate the file position indicator as for any permanent error.
Witness: `KeyedStoreReloadFailureDriftTests` (22 cases: 2 organizations x 9 verbs on the process host, 2 on the
lock-file host, and the RETRY re-entry on both organizations). Design: `docs/COBOLNET_FILES_DESIGN.md` (coherent
statement entry bullet).
