# PB2842 — OPEN — the in-statement store reload has no '30' mapping

Found by the train 1047 lander's review (step 5b) and filed by it, 2026-10-08 20:54 PDT. Reviewer finding on cluster 47B (PB2692+PB2748+PB2751), CONFIRMED pre-existing; the train corrected the
comment that claimed otherwise (`KeyedConnector.ReadImage`).

## Mechanism
`KeyedConnector.ReadImage` throws an `IOException` for a file longer than `RecordFraming.MaxStoreBytes`
(kb/Work PB2748). At OPEN, `FileConnector.Open`'s catch maps it to '30' (§9.1.13.6 1), "no further information is
available"). A reload inside a later statement — `KeyedConnector.Enter` (~line 297), reached from
`FileRegistry.BeginStatement` (`FileRegistry.cs:624`) and the other statement entry points when another run unit
moved the generation stamp — has no `IOException` catch, so the exception escapes the run unit.

## Repro to build
Two run units sharing an INDEXED file `SHARING WITH ALL OTHER`; the second grows the file past `MaxStoreBytes` (or a
test overwrites it with an oversize image between statements); the first's next READ. Expected '30'; observed (by
trace) an unhandled IOException.

## Code sites
`src/Cobol.Net.Runtime/IO/KeyedConnector.cs#Enter`, `#ReadImage`; `src/Cobol.Net.Runtime/IO/FileRegistry.cs#BeginStatement`.
