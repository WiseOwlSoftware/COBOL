**2026-11-18: review round 9 of pb4950-sweep (at c846d990c0): 2 blocking findings and 4 leads, all fixed in the branch (round 10).**

- **Blocking 1: the analyzer was built under two configurations in one Release build.**
  - **The facts.** MSBuild hands a referenced project every global property of its caller. It can drop only a named list of
    them (`GlobalPropertiesToRemove`, `UndefineProperties`, the MSBuild task's `RemoveProperties`), never all of them; the SDK
    targets were read to confirm this.
  - The runtime's per-platform ReadyToRun publish adds Configuration, RuntimeIdentifier, PublishDir,
    EnableSourceControlManagerQueries and IncludeSourceRevisionInInformationalVersion. The round-9 removal list covered three
    of those five, so the analyzer was still built twice into one `obj/Release`.
  - The two builds wrote different assembly attributes: the outer build stamps the commit and the nested one does not. So
    every Release build recompiled the analyzer.
  - **The decision: one configuration, by two rules, not a longer list.**
    - Every reference pins the analyzer to Release (`SetConfiguration`): the src props reference, and the Unit tests' library
      reference.
    - A nested MSBuild call in src passes `BuildProjectReferences=false`. The runtime's ReadyToRun publish now does, because its
      outer build has already built the references and the publish re-compiles only the runtime. Its references are resolved by
      GetTargetPath, which builds nothing.
    - A future nested call that omits the switch is refused: `AnalyzerWiringDriftTests.EveryNestedBuildInSrc_BuildsNoReferences`
      parses every src build file, checks each `<MSBuild>` call's Properties and its items' AdditionalProperties, and has a
      planted judge.
  - **The check that can fail:** `scripts/selftests/_tree/analyzer_builds_once/test_builds_once.py`, a self-test in the
    self-test runner.
    - It stages the runtime, the analyzer and their build files in a scratch git repository; the repository is what makes the
      outer and nested builds' attributes differ.
    - It builds the runtime in Release twice at detailed verbosity.
    - It requires the analyzer's CoreCompile in exactly one request, and no recompile (and an untouched obj assembly) on the
      second build.
    - Before the fix, both arms were RED: CoreCompile ran in requests 2:9 and 2:12, and the second build compiled the analyzer in
      both. After the fix, both are GREEN.
    - Cost: about 12 s on this host. A unit test was not needed, since the self-test is that cheap.
- **Blocking 2: the rules could be silenced.**
  - Both descriptors now carry `WellKnownDiagnosticTags.NotConfigurable`.
  - `EditionCiteAnalyzerTests.NoFormOfSilencing_SilencesARule` plants five forms: NoWarn, a severity lowered to warning (the only
    way WarningsNotAsErrors could reach the rule), an `.editorconfig` severity, a `.globalconfig` severity, and `#pragma warning
    disable`. With the tag the error survives each. Without it, all five, and SuppressMessage, silenced the rule.
  - In a real `dotnet build` of the Compiler with NoWarn, WarningsNotAsErrors, a src `.editorconfig` and a `#pragma` all
    planted, the build still failed with WOCA0001.
  - `[SuppressMessage]` is applied by the analyzer driver after the tag is read, so the tag does not stop it. A unit test pins
    that premise, and the tree refuses the attribute: `AnalyzerWiringDriftTests.NoSourceOrConfiguration_NamesARuleToSilenceIt`
    scans every product source and every `.editorconfig`/`.globalconfig` for a pragma, a SuppressMessage or a
    `dotnet_diagnostic` entry naming a WOCA id. The MSBuild evaluation also refuses a NoWarn or WarningsNotAsErrors entry naming
    one.
  - Planted together (a pragma and an assembly SuppressMessage in a Listing source, NoWarn and WarningsNotAsErrors in the
    Listing csproj, a tracked src `.editorconfig`, and the nested publish without the switch), they turned 4 of the 7 wiring
    tests red, each naming its offender. All plants were restored.
- **Lead 3: the tool mark is checked, not trusted.** ProcessObservationDriftTests now reads the observed ProcessStartInfo's first
  argument as the source spells it: the constructor's second argument, the first `ArgumentList.Add`, or the first element of
  the array a `foreach` adds from. It must be an SDK verb.
  - A mark on `new ProcessStartInfo("dotnet", $"\"{dll}\"")` is an offence ("not an SDK verb"), and so is a first argument the
    source does not spell as a literal. Both are planted in the test.
- **Lead 4: internals.** `VisibleToAnotherAssembly` now reads the compilation's own `InternalsVisibleTo` attributes. An internal
  member counts as visible to another assembly when a grantee is not a test assembly (no dotted name segment ending in `Tests`);
  that direction errs toward one mark too many, never toward a missed derivation.
  - The planted theory covers a product grantee with and without a public key (WOCA0002 on the internal derived member, none on
    the private one) and two test grantees (none).
  - With the grant ignored, the two product cases were red.
  - The products today grant only to tests, so nothing in src changed.
- **Lead 5:** DEVLOG 3835 now records the analysis of generated trees, the wiring test, the build-once rules, the
  `InternalsVisibleTo` reading, and the silencing rules. P2.3a is updated to match.
