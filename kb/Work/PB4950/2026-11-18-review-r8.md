**2026-11-18: review round 8 of pb4950-sweep (the build analyzer): one blocking finding and four leads, all fixed in the branch.**

- **R8-1 (blocking): generated trees were never collected.**
  - `GeneratedCodeAnalysisFlags.None` skipped every tree with an auto-generated header: the ANTLR lexer and parser, and the
    `*.Table.cs` files. So no derivation ran through them, and a choice written in a `*.Table.cs` was not reported. The deleted
    test had scanned those files.
  - The flags are now `Analyze | ReportDiagnostics`. Which trees hold no message is the analyzer's own path rule
    (`IsOutsideTheMessages`: a `Generated` directory, `.g.cs`, `obj/`, `CodeGen`), which matches the old test's scope.
  - A sweep for other skips found only the decider's file, which is skipped on purpose: it is neither derived from nor
    scanned, as before.
  - New test `AGeneratedHeader_HidesNoDerivation_AndNoChoice` plants a derived member in a file with a `// <auto-generated/>`
    header, read by a hand-written ternary, and a choice in a `Words.Table.cs` with an `<auto-generated>` header.
    - With the flag set back to `None` it failed: expected 2 diagnostics, got `[]`.
    - With the fix it passes.
  - The product build stays clean (0 warnings, 0 errors): nothing in the generated trees derives into a refused choice.
- **R7-1:** the analyzer's summary now names `WiseOwl.Cobol.Runtime.EditionDerivedAttribute`.
- **R7-2:** the `EditionInfo.Cite` summary names the analyzer, not the deleted test. A grep of the tree finds the deleted test's
  name only in dated kb/Work history files.
- **R7-3:** 8 members carry the mark, not 7: HasEditionSpelling, MaxLength, is85, is2002, is2014, is2023, setLocaleAhead and
  EditionContext.MaxDigits. A grep finds 8. The count is corrected in the analyzer note and in the report.
- **R7-4: the wiring is checked.** `AnalyzerWiringDriftTests` (RepoDrift) has MSBuild evaluate every committed
  `src/**/*.csproj` (TrackedTree, never a list) with `-getProperty`/`-getItem`, in Debug and in Release. Evaluation only: nothing
  is built or restored.
  - Each project that is not a Roslyn component must hold a ProjectReference to the analyzer project with
    `OutputItemType="Analyzer" ReferenceOutputAssembly="false"`, and must not set `RunAnalyzers` or `RunAnalyzersDuringBuild`
    to false.
  - Planted in the Listing csproj, each then restored:
    - `RunAnalyzers=false` under a Release condition turned the Release case red and left Debug green.
    - `<ProjectReference Remove=...>` of the analyzer turned both red.
  - A planted judge test covers each offence and the Roslyn-component exemption.
- **Found while proving R8-1: a parallel-build race the analyzer reference brought into the runtime.**
  - The first build after an analyzer edit failed with CS2012 ("cannot open ...obj/Release/netstandard2.0/
    WiseOwl.Cobol.Analyzers.dll for writing ... used by another process"), twice in two tries.
  - The cause: the runtime publishes one ReadyToRun image per platform in parallel, with Configuration=Release and a
    per-platform RuntimeIdentifier and PublishDir. Each publish resolved the analyzer reference as a distinct build, and the
    builds wrote one obj file at once.
  - The fix: the reference in `src/Directory.Build.props` sets `GlobalPropertiesToRemove="RuntimeIdentifier;PublishDir;SelfContained"`,
    so every publish asks for the same platform-neutral build and MSBuild builds it once.
  - After the fix, three edit-and-build cycles gave 0 CS2012.
