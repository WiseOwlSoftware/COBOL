# PB6138 — a NATIONAL dynamic-capacity table has two layout codes

**Mechanism.** For a dynamic-capacity table (`OCCURS DYNAMIC`) of NATIONAL elements, the declared lane and the cell lane compute the
layout code differently. `GroupImageCodec.ContiguousLayout` (DynTable arm) passes code 0. `FileModel.LayoutCodeOf` (the cell's
`VarGroupWindow.DynStructure`) gives `PlainCode(2)`. `CobolContiguousLayout._spaceUnit` then pads with the one-unit space 0x20 in one
lane and the two-byte pair 00 20 in the other, and `ToFixedForm` / `Decompose` trim by it. PB2746 made the two lanes share one
`CobolContiguousLayout.Of`, so the difference is now only in what each lane passes to it.

**Reachability (unprobed).** The implementer suspected a silent wrong answer in a fixed-length file record (`PIC N(2) OCCURS DYNAMIC`,
WRITE short, then READ). Its reviewer's read (R1-1) is that this is likely unreachable: `_spaceUnit` acts only for a FILE record, and a
dynamic-capacity table may not be defined in the file section (§2023:8.5.1.9.1 SR3, COBOL1526). The flags record the suspicion (`wrong_answer`, `silent`); until a probe settles it the note is a consistency lead: make the DynTable arm pass `FileModel.LayoutCodeOf` so both lanes hand
`Of` identical inputs. The first step is the probe the report described, to turn the lead into a defect or close it as unreachable.

PB2080 (cell `VarGroupWindow` WRITE arms not gated on `CurrentExtentImageCapable`) stays open and is not part of this note.

**Sites:**
- `src/WiseOwl.Cobol.Compiler/CodeGen/DataDivision/GroupImageCodec.cs` (`GroupImageCodec.ContiguousLayout`)
- `src/WiseOwl.Cobol.Compiler/Binding/Model/FileModel.cs` (`FileModel.LayoutCodeOf`)

**Landed (wave 20262165, group G).** Reachability: unreachable as a wrong answer today. `_spaceUnit` acts only in `ToFixedForm` / `Decompose` for a
FILE record, and a dynamic-capacity table may not be defined in the file section (§2023:8.5.1.9.1 SR3). So the lead is closed as a consistency fix:
`GroupImageCodec.ContiguousLayout`'s `DynTable` / `DynGroupTable` arm now passes `FileModel.LayoutCodeOf(p.Item)`, the cell lane's code, so both lanes hand
`CobolContiguousLayout.Of` identical inputs (emitted `Of(0, [0], [1073741823], [32], [2], default)` for `PIC N OCCURS DYNAMIC`, was `[0]`). Pinned by
`DynamicTableLayoutCodeTests`. Sibling sweep: `Place.cs` `ShapeOf` and `VarGroupWindow` already call `LayoutCodeOf`; no other `ContiguousLayout` arm passes a literal code.
