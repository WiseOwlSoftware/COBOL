# PB3710 — a re-enqueue's landing record is refused by its own validator

**Sites:** `scripts/orchestrator/landing_measure.py` (`record_enqueued`, `patch_record`, `stage_times`, `done_times`, `validate`) and its `_self_test` (stage arm); `tests/WiseOwl.Cobol.Tests.Unit/LandingMeasureDriftTests.cs` (`TheLandingMeasurement_DeclaresEveryArm`, the stage arm's pinned text); `docs/rearchitecture/DESIGN-test-build-ci.md` (section 3.17.5, the `stage_times` sentence).

## What happens

`record_enqueued` bounds the stage times by this call's enqueue time, but `patch_record` keeps the record's first `enqueued` and overlays
`review_clean`. Scenario: PR #90 enqueued 09:00 (record: `review_clean` 08:40, `enqueued` 09:00); it bounces, a review finisher fixes it,
round 2 stamps CLEAN at 10:00 and `enqueue.py land` re-runs at 10:10 reusing the PR. `stage_times(..., enqueued=10:10)` accepts clean 10:00;
`patch_record` keeps `enqueued` 09:00 and sets `review_clean` 10:00; `validate` raises "enqueued 09:00 is before review_clean 10:00". `queue()`
prints the warning "landing record was NOT written" and the update is lost (the reviewer probed `patch_record` directly: REFUSED). It
contradicts `stage_times`' docstring, which promises it never yields a record `validate` refuses.

## Fix

Bound `stage_times` by the record's existing first `enqueued` (read the record before computing the stages), or have `patch_record` treat
`review_clean` as it treats `enqueued` (first wins). Add a self-test arm with the bounce, re-review and re-enqueue sequence above.

## Landed

Re-probed on this build: `record` with the bounce, re-review and re-enqueue sequence was REFUSED (enqueued 09:00 is before review_clean 10:00). `stage_times` now takes the pull request's existing record (`record_enqueued` reads it) and judges the order against what `patch_record` will hold: the first `enqueued`, the earliest `done`, the carried `review_clean`. The second CLEAN verdict, which follows the first enqueue, is left out of the record. Sibling arm in the same overlay: `patch_record` let a later `dispatched` replace the first; it now moves only earlier, as `done` does. Review round 1 (R1-1, blocking): the same bound was missing from the DONE arm: `record_enqueued` called `done_times` with this call's time, so a branch first enqueued with no DONE report and finished after a bounce wrote `done` after the kept first `enqueued`, and `validate` refused it. `record_enqueued` now bounds `done_times` by the record's first `enqueued` as well (a finish after it is no DONE of this landing and stays unrecorded, like the late CLEAN). The self-test stage arm carries the end-to-end sequence through `record_enqueued`, the `stage_times` bound and the dispatch arm; it fails with the `existing` argument withheld.
