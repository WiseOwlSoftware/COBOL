# PB5124 - at --std 85 a RELEASE of a record shorter than integer-2 or longer than integer-3 of the SD's RECORD IS VARYING clause succeeds and the record is sorted; 1985 makes the statement unsuccessful

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Bound/BoundSort.cs` (`BoundRelease`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/SortBinder.cs` (`BindRelease`), `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/SortEmitter.cs` (`EmitRelease`), `src/WiseOwl.Cobol.Compiler/CodeGen/Roslyn/RuntimeApi.cs` (`SortReleaseStatement`), `src/WiseOwl.Cobol.Runtime/IO/CobolSort.cs` (`ReleaseStatement`), `src/WiseOwl.Cobol.Runtime/PublicAPI.Shipped.txt` (`CobolSort.ReleaseStatement`)

**Mechanism.** The Amendment 2 paragraph of §1985:VII.3.8.4 GR10 makes an output statement unsuccessful when the logical record is outside the RECORD IS VARYING range, with the I-O status set (to 44 for WRITE and REWRITE, §1985:VII.1.3.5) except during RELEASE. The WRITE and REWRITE half is right (USE F1 44, record not stored, DEPENDING ON item unchanged, every WRITE/REWRITE line of the draft matches). RELEASE is not checked: both the 2-character and the 9-character record of a sort file described as 3 to 8 characters are released and returned. kb/Work PB1036 (landed) raises EC-SORT-MERGE-RELEASE only when 2023 checking is enabled and records "checking off keeps every pre-PB1036 behaviour", so with no checking (all a 1985 program can have) the record is still released. --std 2023 prints the same (there the condition is a fatal EC-SORT-MERGE-RELEASE with checking on, implementor-defined with it off, §2023:14.6.13.1.3 GR8).

**Found by.** The 1985 witness-drafting pass (kb/Work PB4995 item 3): each rule below is a witness program drafted from the 1985 text alone, run at `--std 85`, and its result differs from what the text requires (outcome MISMATCH). Harm and observed text are the record's; nothing here was re-derived.

**Inventory.** The traceability inventory carries no 1985 rows yet (PB5094: work.py refuses 1985 ids), so `inventory_rows` is empty; the row this note covers is the 1985 rule id listed below (catalog `docs/rearchitecture/spec-rule-catalog-1985.json`).

**Rules (1; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-GR-VII.3.8.4-10` - `§1985:VII.3.8.4 GR10` (record harm: wrong-answer, slice-04): Checked quotations: "If data-name-1 is specified, by the content of the data item referenced by data-name-1" and (Amendment 2) "If the number of character positions in the logical record to be written is less than integer-2 or greater than integer-3, the output statement is unsuccessful"; for WRITE and REWRITE the status is 44, `§1985:VII.1.3.5` "An attempt is made to write or rewrite a record that is larger than the largest or smaller than the smallest record allowed by the RECORD IS VARYING clause of the associated file-name". The SD's RECORD clause is the same clause (§1985:XI.3.2.4 GR2); a successful RELEASE is §1985:XI.4.2.4 GR1.
