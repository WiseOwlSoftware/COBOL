# R66 — keep the markdown spec updated

**Owner, 2026-09-30:** "I believe we have a markdown version of the ISO spec. We must keep it updated." Together with the PB738 answer ("We want correctness to rule over faithfulness to typos, errors") this is a STANDING RULE:

1. `specs/ISO_COBOL.md` (the tracked transcription every `scripts/spec/cite.py --check`, every audit and every citation in code, goldens, notes and DEVLOG runs against) is the project's working copy of the standard and must be CORRECT, not merely faithful.
2. **A defect found is fixed in the change set that finds it** — a transcription slip (OCR loss, a lost indentation, typographic look-alike characters, a mis-fenced diagram, a dropped sequence) AND an erratum in the printed standard itself (a cross-reference to a sub-item that does not exist, two general rules that disagree). No "note it and move on".
3. **Every correction is MARKED, using the convention the transcription already has** (`specs/README.md` "Corrections"): the corrected text stays in the body and is FLAGGED in place, and every departure is listed in the ADDENDUM at the end of `ISO_COBOL.md` with the printed form, the printed folio and the reason, so any correction can be reversed; `scripts/spec/verify_publishable.py` fails if a correction is flagged but missing from the Addendum or listed but referenced nowhere. That convention was written for "three points"; R66 widens its scope (every defect found, not only clear misleading ones) and the README is updated to say so. `cite.py --check` accepts the corrected text, and a quotation of the printed form keeps passing through the Addendum entry (existing citations must not break); doubtful cases are still transcribed as printed and listed.
4. **Nothing drifts silently:** the audits that already guard the transcription (the rendering lint, the figure/underlining audits, the rule-catalog check) stay green, and a drift test ensures every marked edit names its printed form and page. The derived artifacts (the rule catalog, the traceability-inventory rule digests, `kb/Conformance`) are regenerated in the same change when a correction changes a rule.
5. The other editions' texts (1985, 2002, 2014) are not in the repository (R61, R62 record the consequence); if they are ever added they follow the same rule.

**Backlog (one note each; dispatched as one batch):** PB738 (five dropped `<letter><space><opening-quote>` sequences), PB1635 (263 rule lines numbered `N.` instead of `N)`), PB291 (typographic look-alikes for hyphen and minus), PB309 (§14.9.8.4 indentation), PB1589 (§7.3.23.2 diagram fenced in a blockquote), PB308 (`cite.py` answers OK when the check cannot be valid), PB1588 (`extract_rule_catalog.py --check` drift: §9.3.6), and the two printed errata PB1555 (§14.9.30.4 GR21 e)1. and e)3. disagree) and PB1568 (§14.9.48.4 GR11 g) cites "General rules 12b through 12f" where 11b through 11f is meant).
