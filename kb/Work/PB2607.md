# PB2607 — the planner's report reader misses attended branches

Found by w1038v (PB2600-PB2602) while making attended DONE reports the land unit's input (MANDATORY-PRACTICES O11).
Not fixed there: `plan_wave.py` is edited by the unlanded branch `plan-wave-split-finishers` (PB2575/PB2562), and the
dispatch spec kept it out of the group for that reason.

## Repro (2026-10-08, on ea20c28e3 + w1038v)

`E:\COBOL-coord\scratch\w1038v\probe_pw.py` writes two reports in the shapes in use today and parses each with
`plan_wave.parse_report`:

```
w1038v-PB2600-report.md status DONE branch None worktree E:\COBOL\.claude\worktrees\w1038v-branch-lifecycle head abc1234
w1039d-PB2489-report.md status DONE branch worktree-wf_2d68bf0d-aa5-4 worktree None head None
```

## Defect

Code sites: `scripts/orchestrator/plan_wave.py:83` `BRANCH = re.compile(r"\b(worktree-…)")` (only the harness's
`worktree-` names), `:84` `WORKTREE` (only `X:\…\worktrees\<name>`, never `E:/…/worktrees/<name>`, which the loop's
own handoffs and the w1039d report write), `:85` `HEAD` (case-sensitive `HEAD`, so `Head 5880c6cf6` is missed), and
`plan()` at `:550`: `cls = classify(r.branch) if r.branch else "ABSENT"`, and ABSENT is in `LANDED_CLASSES`. So a
DONE report whose branch is not a `worktree-…` name (every attended branch: `w1038v-branch-lifecycle`,
`selftests-gate`, `landing-lease`, `plan-wave-split-finishers`) reads as LANDED: its notes are not held as `awaiting`,
and the next wave plans them again over the finished, unlanded branch — duplicate work, and a second branch racing the
first for the same files.

## Fix shape

**The branch half is landed (kb/Work PB3077):** `plan_wave.parse_report` reads the header's `branch:` FIELD whatever
the name (`plan_wave.BRANCH_FIELD`, matched at a field position only), before the `worktree-…` fallback. That rule
governs, not the survey's: `prune_worktrees.BRANCH_FIELD` matches `branch` followed by any word anywhere in the header
and takes a mention for the branch a report is about (kb/Work PB3084). The one-reader item (planner and survey cannot
disagree on which branch a report is about) is PB3084's: the survey reuses `plan_wave.BRANCH_FIELD`, not the reverse.

Still open here: fall back to the worktree path with either slash (`WORKTREE` matches only `X:\…\worktrees\<name>`)
and resolve the worktree's branch through `git worktree list`, and match `HEAD`/`Head` case-insensitively (`HEAD`
misses `Head <sha>`); add both shapes to `test_plan_wave.py`.
