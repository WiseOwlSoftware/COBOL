# PB4717 — LevelNumberArm.FileRecord's message and citation do not cover a CD record

**Sites:** `src/WiseOwl.Cobol.Compiler/Validation/LevelNumberPass.cs:15` (`LevelNumberArm`, `LevelNumberRules.Arm`, `LevelNumberRules.Classify`, `LevelNumberPass.VisitLevelNumber`), `tests/WiseOwl.Cobol.Tests.Unit/LevelNumberArmDriftTests.cs` (`TheLevelNumberRuleIsWrittenOnce`)

The line is read from open PR #1161 (branch `worktree-wf_d99db659-fdf-22`). Reported by the branch review, not probed. R1-9, copied: `LevelNumberArm.FileRecord` now answers a CD record too, and its message still says "subordinate to a FD or SD entry" and cites 2023 13.18.33.3 SR2, which does not name a CD; the rule that applies, per the review, is ISO/IEC 1989:2002 13.16.31 SR2, "a CD, FD, or SD entry". That citation is the review's and has not been run through `cite.py --check` here.

## Fix (landed)

Re-probe on the branch build showed the defect as filed (`--std 2002`, level 77 under a CD: "subordinate to a FD or SD entry ... (ISO 13.18.33.3 SR2)"). Root: the arm table keyed message and citation to the FD/SD sentence, and `Arm` carried only a bare rule number that the pass prefixed with the 2023 clause. Fix: a fifth arm `LevelNumberArm.CommunicationRecord` (same permitted set, its own sentence naming a CD entry) and `Arm.SyntaxRule` became `Arm.Citation`, the edition-qualified printed citation, so a 2002-only rule never wears a 2023 clause. The CD citation (ISO/IEC 1989:2002 13.16.31 SR2) comes from the review; the 2002 text is not in `specs/ISO_COBOL_2023.md`, so `cite.py --check` cannot reach it, and the CD sentence is the FD sentence with CD in place of FD or SD. Witness: `conformance-suite/wiseowl/diagnostics/pb4717-cd-level-77-message.json` (expects the message text "subordinate to a CD entry").
