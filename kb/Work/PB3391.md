# PB3391 — LANDED — NoViableAlt from a predicated sole survivor in the residue run

Filed 2026-10-18 from the w1126b review finisher's report (`E:\COBOL-coord\scratch\reports\w1126b-PB3373-report.md`, "New defects (note-ready)" lead 2, third shape) and `kb/Work/PB3373.md` (landed, PR #262). Register check: a grep of kb/Work by `NoViableAlt`, `residueOpening`, `residueItem`, `genericClause` and `ClosedFormatPass` found no existing note for this shape (PB3373 only). The report says this lead shares its root with the leading-comma and format-dependent integer leads (PB3390: the residue set cannot be format-dependent). It is filed as its own note because its symptom, an ANTLR NoViableAlt from a text-predicated alternative that is the only survivor, is a prediction failure rather than a misattributed token. Whether it is the same mechanism as PB3390 is NOT judged here (it needs a read of the ATN decision, a compiler judgment). If an implementer finds one root, close this note into PB3390 with the reason.

## What happens

`OBJECT-COMPUTER. XYZ FOO IS 12.` raises a NoViableAlt from a predicated sole survivor. PB3373's note records the neighbouring measurement: an INTEGERLIT-free tail turns `SEGMENT-LIMIT IS? integer`'s text predicate into a NoViableAlt at the decision's first token (`OBJECT-COMPUTER. XYZ FOO 12.`), which is why the tail keeps the integer. `FOO IS 12` is listed by the report as the remaining shape. Harm: a bare parse error in place of a by-name refusal (process_only per the lead). No scratch repro file was named for this shape; the source line above is the repro.

## Landed (w1129c, 2026-10-19) — the 0g arm names a word the prediction refused at the production's own opening

**Spec.** ISO §12.3.6.2, §12.3.7.2 and §13.16.2 (Format 1) print closed clause lists; FOO opens no clause of any of
them at any edition (at 85, where SEGMENT-LIMIT and MEMORY SIZE were OBJECT-COMPUTER clauses, FOO is still neither).
The source is refused everywhere; the defect is the message: a bare COBOL0001 plus a second refusal of the next token.

**Re-probe (worktree build, before).** `OBJECT-COMPUTER. XYZ FOO IS 12.` drew COBOL0001 "cannot parse construct near
'FOO'" and COBOL1971 "'IS' is not a paragraph of the CONFIGURATION SECTION", at 85 and 2023; the same for `XYZ FOO
IS.`, `OBJECT-COMPUTER. FOO IS 12.` and `XYZ FOO SIZE 12 WORDS` (MEMORY SIZE's shape). Siblings with the same
mechanism: `XYZ FOO BAR IS 12.` (NoViableAlt at BAR, inside the run), `01 X PIC X FOO SIZE 3.` (PICTURE's LOCALE
phrase; plus a second refusal at SIZE), `SPECIAL-NAMES. FOO BAR IS "x".` (the LOCALE clause; plus a false "a
data-name is expected here" at the literal), and the reserved-word case the 0g arm already named,
`XYZ CHARACTER FOO IS X.`, which still drew the second refusal at IS. Scratch `w1129c\probe.py`.

**Root.** Not PB3390's mechanism (whose integer and leading-comma tokens are the production's own set): the
production's left edge is shared with clauses recognized by the TEXT of their word, and where the run cannot continue
at the reserved word such a clause takes next, the clause is the prediction's sole SLL survivor; ANTLR evaluates the
accept state's predicates and throws NoViableAlt at the decision's start token when none holds. `ClosedFormatResidue`
declined every IDENTIFIER on the premise that "an IDENTIFIER there would have been taken by the error production",
which this shape refutes, and the base recovery stopped AT the word (an IDENTIFIER is in nearly every recovery set),
so an enclosing list took the rest of the run as its own residue.

**Fix (CobolErrorStrategy only; no grammar change).** (1) `IsPredictionFailedAt`: a NoViableAlt whose start token is
its offending token. (2) `ClosedFormatResidue(…, predictionFailedAt)` admits an IDENTIFIER there and skips the
after-period exclusion for it (the decision's lookahead already tried every path out of the list); the 0g hint names
the word in the innermost open list's format, the pass's own code and sentence. (3) `Recover` consumes a token the
0g arm named at a failed prediction and the rest of the run, up to a recovery-set token no run holds
(`ResidueRunTokens`, read from `residueOpening` and `residueItem`), so the residue is one refusal, for a reserved word
too. The grammar comment at `genericClause` and DESIGN-frontend-grammar.md say why. No new code (COBOL4580-4582
returned).

**Goldens.** Negatives at 85 2002 2014 2023: `12.3.6-OBJECT-COMPUTER/pb3391-object-computer-predicated-clause-word`,
`12.3.7-SPECIAL-NAMES/pb3391-special-names-locale-shape-word`, `13.16-Data-description/pb3391-data-entry-picture-locale-word`.
Unit: `ClosedFormatReservedWordTests.PredicateRefusedWord` (nine shapes, each the one diagnostic), the next-entry and
next-paragraph controls (recovery never swallows them) and the malformed-clause control (`SEGMENT-LIMIT IS.` is never
called foreign).

**Not closed here (reported as a lead).** A text predicate INSIDE a clause the format prints still draws a bare parse
error at the word it refuses: `OBJECT-COMPUTER. XYZ MEMORY SIZE 12 FOO.` (the unit word) is COBOL0001 "cannot parse
construct near 'FOO'", and `SEGMENT-LIMIT IS.` "near '.'": the expected set cannot show a word a predicate tests.

**For the next implementer (w1129c):**
- `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs#ClosedFormatResidue` — the ONE place a token at a closed
  format's residue position is judged; pass `predictionFailedAt` (from `IsPredictionFailedAt`) only from a NoViableAlt
  report. Trap: the after-period exclusion holds IDENTIFIER in the configuration section (its own error production),
  so an IDENTIFIER must skip it or the arm never fires.
- `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs#Recover` / `#ResidueRunTokens` — the recovery that consumes a
  refused run; reuse `ResidueRunTokens` (read from `residueOpening` and `residueItem`) rather than listing tokens. Trap:
  the base recovery stops AT an IDENTIFIER, and an enclosing list then refuses the next token a second time.
- `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolExpressions.g4#genericClause` — comment only; the tail's integer no longer
  exists for SEGMENT-LIMIT's predicate (a NoViableAlt there is now named), which PB3390 may use.
