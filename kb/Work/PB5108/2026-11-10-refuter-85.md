**The doubt, and the reading the text settles.** The refuter of 1985-SR-VI.6.26.3-1 doubted only which ROW owns the defect, not the defect. The text settles the defect: "Integer and numeric functions may be used only in arithmetic expressions." (§1985:IV.4.3.4, the 1989 Amendment 1 text), and an ADD or SUBTRACT operand is an identifier, not an arithmetic expression, so `ADD FUNCTION LENGTH (W) TO Y` is not 1985 source. The operand rules read with it: §1985:VI.6.26.3 SR1: "Each identifier must refer to a numeric elementary item except that:" and §1985:VI.6.6.3 SR1: "In formats 1 and 2, each identifier must refer to an elementary numeric item" (all three checked with `scripts/spec/cite.py --check`). A function-identifier references a temporary item that, at 85, may appear only inside an arithmetic expression, so it is not an admissible identifier of either statement. The one fix this note already names (the placement screen for numeric and integer functions) refuses all of them, so this note claims both operand rows; kb/Work PB5094 still refuses a 1985 rule id in `inventory_rows`, so they are listed here.
