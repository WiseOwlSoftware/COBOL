# PB4000 — national-items-displayed-as-utf-16-bytes--compare-no-conversion: Comparing an alphanumeric or integer operand with a national operand compares raw bytes ("AB" is not equal to N"AB")

Filed 2026-10-28 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-20261027-215606`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

Under `-std=cobol2014`, a relation condition between an alphanumeric operand (item or literal) and a national
operand, or between an integer display item and a national literal, compares the stored bytes as they are: the
alphanumeric "AB" (`41 42`) against the national N"AB" (`00 41 00 42`), so equal values compare unequal and the order
follows the byte values. The standard compares as though the alphanumeric or integer operand were first moved to a
national item. Equal national operands compare right (line 1 of the repro). Class: wrong output. A mechanism of the
harvest family "national items displayed as UTF-16 bytes", distinct from `move-alphanumeric-to-national-copies-bytes`
(PB3894, the MOVE statement: here no MOVE is executed, and fixing the MOVE leaves the comparison path untouched) and
from `--compare-pad` (padding of unequal-length national operands). Fuzz night 2026-10-27/28: fz04010 (signature
OUTPUT_DIFFERS:8.8.4.2.6) and fz03836 (OUTPUT_DIFFERS:8.8.4.2.5, `WS-INT-LARGE = N"1234"` with PIC 9(4) VALUE 1234).

## Minimal test case

Free reference format (`-fformat=free`), 13 lines, written for this record.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. NCMPCNV.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 ALPHA-1 PIC X(2) VALUE "AB".
01 NAT-1   PIC N(2) VALUE N"AB".
01 INT-1   PIC 9(4) VALUE 1234.
PROCEDURE DIVISION.
IF NAT-1 = N"AB" DISPLAY "1 EQUAL" ELSE DISPLAY "1 NOT EQUAL" END-IF
IF ALPHA-1 = NAT-1 DISPLAY "2 EQUAL" ELSE DISPLAY "2 NOT EQUAL" END-IF
IF "AB" = NAT-1 DISPLAY "3 EQUAL" ELSE DISPLAY "3 NOT EQUAL" END-IF
IF INT-1 = N"1234" DISPLAY "4 EQUAL" ELSE DISPLAY "4 NOT EQUAL" END-IF
STOP RUN.
```

File: `E:/COBOL-coord/scratch/fuzz-triage/fuzz-20261027-215606/records/national-items-displayed-as-utf-16-bytes--compare-no-conversion.cob`.
Line 1 is the control. Only equality is tested, so the result does not depend on any collating sequence.

## Observed result

Compile exit code 0, with `-Wunfinished` warnings ("handling of USAGE NATIONAL is unfinished", "handling of national
literal is unfinished") and the C compiler's "'_FORTIFY_SOURCE' redefined" warning (the Ubuntu package's build flags,
not the program). Run exit code 0, output:

```
1 EQUAL
2 NOT EQUAL
3 NOT EQUAL
4 NOT EQUAL
```

## Expected result (per ISO)

Output `1 EQUAL`, `2 EQUAL`, `3 EQUAL`, `4 EQUAL`.

- §8.8.4.2.6 (checked): "Two operands, one class alphanumeric and one class national, may be compared. The
  alphanumeric operand is treated as though it were converted and moved in accordance with the rules of the MOVE
  statement from an alphanumeric elementary data item to a temporary elementary data item of class national with the
  same length in terms of character positions as the alphanumeric operand." "AB" so converted is N"AB" (lines 2, 3).
- §8.8.4.2.5 (checked): "The numeric integer operand shall be an integer literal or an integer numeric data item of
  usage display or national. The other operand may be a literal or data item of class alphanumeric or national." and
  "The integer operand is treated as though it were moved, according to the rules of the MOVE statement, to an
  elementary data item of the same length in terms of character positions as the number of digits in the integer, and
  of the same class and usage as the alphanumeric or national operand": 1234 moved to a 4-position national item is
  N"1234" (line 4).
- §8.8.4.2.10 1) (checked): "The operands are determined to be equal if all pairs of corresponding national characters
  are equal."

Edition: both rules are COBOL 2002 features; the 2009 committee draft for ISO/IEC 1989:2014 (CD 1.2, std.txt lines
8822-8834) has them in the same words in substance ("The alphanumeric operand is treated as though it were converted
and moved in accordance with the rules of the MOVE statement to an elementary data item of class national"; "The
integer is treated as though it were moved to an elementary data item ... of the same class and usage as the
comparand").

## Fix site

GnuCOBOL 3.2 source, read observationally: `libcob/common.c`, `cob_cmp` (line 3834). Its national branch is compiled
out (`#if 0` at line 3863, "FIXME later: must cater for national fields, too, at least if that is numeric NATIONAL"),
and the code that follows ("all else -> alphanumeric comparision") sends every remaining pair, a national operand
included, to `cob_cmp_alnum` (line 1951), a `memcmp` of the stored bytes. A numeric operand is compared in its
numeric-display form (copied into a numeric-display field first only when its usage is not display), the same way. A comparison with one national operand needs the other
operand converted to national (the MOVE conversion) before the byte comparison.

## Draft issue

**Title:** Comparing an alphanumeric or integer operand with a national operand compares raw bytes ("AB" is not equal to N"AB")

**Body:**

Environment: GnuCOBOL 3.2.0 (Ubuntu gnucobol3 3.2-4build1), x86_64 Linux.

Steps: `cobc -x -free -std=cobol2014 -o p ncmpcnv.cob && ./p` with

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. NCMPCNV.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 ALPHA-1 PIC X(2) VALUE "AB".
01 NAT-1   PIC N(2) VALUE N"AB".
01 INT-1   PIC 9(4) VALUE 1234.
PROCEDURE DIVISION.
IF NAT-1 = N"AB" DISPLAY "1 EQUAL" ELSE DISPLAY "1 NOT EQUAL" END-IF
IF ALPHA-1 = NAT-1 DISPLAY "2 EQUAL" ELSE DISPLAY "2 NOT EQUAL" END-IF
IF "AB" = NAT-1 DISPLAY "3 EQUAL" ELSE DISPLAY "3 NOT EQUAL" END-IF
IF INT-1 = N"1234" DISPLAY "4 EQUAL" ELSE DISPLAY "4 NOT EQUAL" END-IF
STOP RUN.
```

Observed: `1 EQUAL`, `2 NOT EQUAL`, `3 NOT EQUAL`, `4 NOT EQUAL` (exit code 0).

Expected: all four `EQUAL`. ISO/IEC 1989:2023 8.8.4.2.6 (the same rule in the 2014 edition's committee draft): "The
alphanumeric operand is treated as though it were converted and moved in accordance with the rules of the MOVE
statement ... to a temporary elementary data item of class national"; 8.8.4.2.5: an integer display operand compared
with a national operand is treated as though it were moved to a national item of as many positions as it has digits.

Cause, as read in the source: libcob/common.c cob_cmp has its national branch under `#if 0` (FIXME "must cater for
national fields, too"), so a mixed comparison falls through to cob_cmp_alnum, a byte comparison with no conversion.
