# PB1933 — LANDED

## Landed — wave 1006 group B, 2026-10-03

Re-probed on a fresh Debug build: the repro drew COBOLNET0899 on both receivers and COBOLNET1756 on both senders.
**Fix, two halves of one path.** (1) `ReferenceResolver.BuildBackingPath` no longer refuses a canonical with an
OCCURS DYNAMIC ancestor: `BuildAccessPath` already builds the element path with a `DynTableSegment`, whose accessor
`PlaceRenderer.RenderPath` picks from the direction. (2) `PlaceRenderer`'s three backing STORE arms — the byte window
(`ByteWindowWrite`), the bit window and the national window — rendered the backing `AccessDir.Sending` on both sides of
the assignment; they now render `AccessDir.Receiving`, so a store creates an occurrence past the current capacity
(§8.5.1.9.3) instead of splicing into a read's scratch. The read arms stay Sending. For every non-dynamic path the two
directions render identically, so nothing else changes. `DeferredShape.NestedClassBacking` keeps its (now narrower)
meaning — no buildable parent path — and its texts say so.

Citations (`cite.py --check`): 13.18.44.3 "data-name-2 may be subordinate to an item whose data description entry
contains an OCCURS clause" → OK §13.18.44.3 5); 13.18.44.4 "Storage association for the subject of the entry starts at
the first bit of the data item referenced by data-name-2" → OK §13.18.44.4 1); 8.5.1.9.3 "the capacity of the table is
increased" → OK §8.5.1.9.3.

MEASURED: `conformance:2023/pb1933_redefines_in_dynamic_table` — a store through A read through B1/B2 and back
(`B=ab/12`, `A=zz17` after `ADD 5 TO B2(2)`), and stores through the REDEFINES view into occurrence 4 of a capacity-2
table grow it (`CAPACITY=0000000004`, `A4=cd34`).

Sibling sweep: the other `RenderPath(…, AccessDir.Sending)` writers in `PlaceRenderer.Write` render a CELL path (pointer
slot, dynamic-length slot, variable-length group window), which is always a bare root field (`BuildCellPath`), so
direction cannot matter there; `MemberPlace` renders Sending on a path that has no dynamic segment by construction
(`PlaceForItem` returns a `DynTablePlace` for any path crossing a dynamic level).

Filed by the train-1005 lander from wave 1005 group E's report (`w1005e-PB1271-report.md`, lead 2; the remainder
PB1279 records). Not re-probed by the lander.

## The defect

§13.18.44.3 SR5 sentence 2 lets data-name-2 be subordinate to an item with an OCCURS clause, and §13.18.44.4 GR1
gives each occurrence its own redefinition. PB1279 (landed in train 1005) reaches the class's backing through the
subscripted parent path; `ReferenceResolver.BuildBackingPath` refuses a canonical with an OCCURS DYNAMIC ancestor,
because a dynamic table's element is reached through receiving / sending accessors that a `RedefViewPlace` does not
carry, so the reference stays the `NestedClassBacking` deferral.

**Repro.** `05 T OCCURS DYNAMIC CAPACITY IN C FROM 2 TO 5. 10 A PIC X(4). 10 B REDEFINES A. 15 B1 PIC X(2).
15 B2 PIC 99.` then `MOVE 'ab12' TO A(2)` and `DISPLAY B1(2) B2(2)` — COBOLNET0899 on the receiver, COBOLNET1756 on the
sender.

**Sites.** `src/Cobol.Net.Compiler/Binding/ReferenceResolver.cs#BuildBackingPath` (the dynamic-ancestor refusal) and
`src/Cobol.Net.Compiler/CodeGen/PlaceRenderer.cs` ~220-243 (the write arms render the backing with
`AccessDir.Sending`).
