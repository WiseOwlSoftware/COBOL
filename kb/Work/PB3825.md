# PB3825 — make "a new driver lands alone" mechanical

**Sites:** `scripts/merge_drivers.py#check` (`--check`), `scripts/merge_drivers.py#new_driver_files`, `scripts/merge_drivers.py#MAIN_REF`, `docs/rearchitecture/DESIGN-orchestrator-loop.md` (section 16.9,
"A NEW DRIVER LANDS ALONE"), `docs/rearchitecture/DESIGN-test-build-ci.md` (section 3.17.2 step 2),
`tests/WiseOwl.Cobol.Tests.Unit/MergeDriverDriftTests.cs`.

## Measured (PB3727, PR #608, 22:43Z)

`enqueue.py land` merges main in through MAIN's registry. PB3727 added the `cobol-keyed-publicapi` driver and had also sorted
both PublicAPI baselines, so main's registry (no such driver) fell back to git's line merge and every later main change to a
baseline conflicted. The finisher's fix was to put the baselines back to main's bytes, and the design now says a new driver
lands alone and does not reformat the files it governs. That rule exists only as text: `git grep -n "lands alone"
scripts/merge_drivers.py` finds nothing, so the next driver can repeat the bounce.

## Acceptance

- `merge_drivers.py --check` refuses a branch that changes a file matched by a DRIVERS pattern which origin/main's
  `.gitattributes` does not yet assign to that driver, unless the file is byte-for-byte main's. Where the checkout has no
  origin/main (CI's) it says so and does not pass silently.
- A `--self-test` arm covers the refusal and the byte-for-byte pass.
- Optional follow-up the report names: one small landing after PB3727 that sorts both baselines and runs `abi_pin.py repin`.

## Landed

Branch `worktree-wf_a5b6fa01-f4e-6` (wave 20261737 group F). **Re-probe:** the rule had no code (`--check` was GREEN on a tree
that gave a baseline's pattern `union` on main and changed the baseline on the branch, the PB3727 shape). **Fix:**
`merge_drivers.new_driver_files(repo, main)` (`MAIN_REF` = `origin/main`) is the one definition: a DRIVERS pattern whose driver
`main`'s `.gitattributes` does not give it is NEW; a file `merge-base(HEAD, main)..HEAD` changed that such a pattern governs
(`pattern_matches`) and whose blob is not main's is a finding; no `main` ref or no merge base is a returned reason that `--check`
prints as `NOTE ... NOT CHECKED` (CI's merge-group checkout), never a pass. `--check` reads it, so
`MergeDriverDriftTests.TheDriverRegistry_AgreesWithGitattributes` runs it in every gate. Five `--self-test` arms (`new driver: ...`)
are declared in `TheSelfTests_DeclareEveryArm`. Replaying the check with the commit before PB3727's landing as main flags both
baselines of both runtime projects (the PB3727 bounce) and the ABI pin. **Sites added:** `scripts/merge_drivers.py#new_driver_files`,
`#MAIN_REF`, `#self_test`, `#main`; DESIGN-orchestrator-loop.md section 16.9; DESIGN-test-build-ci.md section 3.17.2 step 2. The
optional follow-up (sort both baselines, repin) is no defect and stays unfiled: the drivers converge the order at the first
two-sided merge.

**Branch review round 1 (R1-1, R1-2).** R1-1: the Linux half of the gate read a different main. A `--shared` clone's
`refs/remotes/origin/main` is the SOURCE repository's local `main`, which nothing advances, so `--check` run by the test leg in
the clone could refuse (or pass) a branch the Windows half judged the other way. `scripts/linux-gate.sh#pin_origin_main` now sets
both clones' origin/main to the tree's sha (and deletes it where the tree has none, so the tool says NOT CHECKED); three
`--self-test` checks measure the stale ref, the pin and the absent ref. R1-2: a pair is NEW only when the merge base's
attributes did not give the pattern that driver either, so a branch cut before main re-pointed a driver is told to merge main,
not refused (a sixth `new driver:` arm). **Sites added:** `scripts/linux-gate.sh#pin_origin_main` (and its two callers in the
clone steps, and the `--self-test` block).
