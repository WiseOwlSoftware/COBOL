# PB3825 — make "a new driver lands alone" mechanical

**Sites:** `scripts/merge_drivers.py#check` (`--check`), `docs/rearchitecture/DESIGN-orchestrator-loop.md` (section 16.9,
"A NEW DRIVER LANDS ALONE"), `docs/rearchitecture/DESIGN-test-build-ci.md` (section 3.17.2 step 2),
`tests/Cobol.Net.Tests.Unit/MergeDriverDriftTests.cs`.

## Measured (PB3727, PR #608, 22:43Z)

`enqueue.py land` merges main in through MAIN's registry. PB3727 added the `cobol-keyed-publicapi` driver and had also sorted
both PublicAPI baselines, so main's registry (no such driver) fell back to git's line merge and every later main change to a
baseline conflicted. The finisher's fix was to put the baselines back to main's bytes, and the design now says a new driver
lands alone and does not reformat the files it governs. That rule exists only as text: `git grep -n "lands alone"
scripts/merge_drivers.py` finds nothing, so the next driver can repeat the bounce.

## Acceptance

- `merge_drivers.py --check` refuses a branch that changes a file matched by a DRIVERS pattern which origin/main's
  `.gitattributes` does not yet assign to that driver, unless the file is byte-for-byte main's. Where the checkout has no
  origin/main (CI's) it says so and does not pass silently.
- A `--self-test` arm covers the refusal and the byte-for-byte pass.
- Optional follow-up the report names: one small landing after PB3727 that sorts both baselines and runs `abi_pin.py repin`.
