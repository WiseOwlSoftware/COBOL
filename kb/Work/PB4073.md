# PB4073 — Frontend.Parse's doc comment misses its second null return

**Sites:** `src/WiseOwl.Cobol.Frontend/Pipeline/Frontend.cs#Parse`

The summary reads: "Returns the parse tree, or null if a fatal syntax error was reported". PB1092's `SourceTextDecoder`
adds a second null return. A main source whose byte-order mark names an encoding its content is not well-formed in
draws COBOL5434, and `Parse` returns null before any parse runs. A caller that reads the summary would treat a null
result as a syntax error. The diagnostic bag holds the real reason, so no user sees a wrong message, but the contract is
misstated.

**Fix.** State both null returns in the summary, and check each caller of `Parse` reads the bag, not the null, for the
reason.
