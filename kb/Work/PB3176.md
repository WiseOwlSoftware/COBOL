# PB3176 — conformance suite slice S1c

Owner approved `docs/rearchitecture/DESIGN-conformance-suite.md` on 2026-10-14 ("approved", revision 2; kb/Work PB3160 holds the decisions verbatim).

**Prerequisites:** PB3174, PB3175.

**Scope:** Design §13 S1c, built from §5 ("In WiseOwl's own pipeline") and §9. An xUnit runner in `tests/Cobol.Net.Tests.Conformance` executes the generator's manifests in-process: an accepted test compiles, runs and compares through `CutRunner.Normalize`; a flag test's diagnostic is at the marked line; `wiseowl/diagnostics.json` holds WiseOwl's refusals and their code or message. It never parses a test header (the generator is the one parser). Drift tests: its verdicts equal `run.py`'s on the WiseOwl adapter for every test; the C# and Python normalizations agree on one shared fixture.

**Rules for the implementer:** implement this slice FROM the design (the sections named above), not from this note, which is its register entry; the complete slice with its tests and drift tests (CLAUDE.md rules 3, 5); a design correction lands in the design in the same change (rules 2, 6); every ISO citation through `python scripts/spec/cite.py --check`; no wrapper, alias or compatibility layer (rule 4); the gate is `pwsh scripts/build-local.ps1 -Priority BelowNormal`; flip this note to `landed` and write `closes_rows` (or `closes_rows_reason`) in the commit that lands it.

## Landed

Wave 1104 C5 (2026-10-16), on PB3175's branch (PB3172-PB3175 land through it).

**The runner.** `tests/Cobol.Net.Tests.Conformance/ConformanceSuiteTests.cs` runs every test of the generator's
`wiseowl` manifest (both trees, portable or not) at every edition it names through `ConformanceSuiteRunner`, which
judges exactly as `run.py` judges through the WiseOwl adapter (PASS, FAIL, NOT APPLICABLE, NO VERDICT, design §5)
but compiles in-process through `CompiledProgramCache`; a row is red on FAIL or NO VERDICT, as `run.py` is with no
baseline. A second theory compiles every refusal of `wiseowl/diagnostics.json` at each edition it names: the front
end or the binder must refuse the source and report the entry's code or text. `ConformanceSuite` generates the
manifests once per test process into a directory of its own (`generate.py --out`, new), so the runner never reads a
test header and never rewrites the repository's `suites/`; it reads the WiseOwl adapter's diagnostic pattern and the
profile rather than restating them.

**The drift tests.** `ConformanceSuiteRunnerDriftTests.BothRunners_GiveEverySuiteTestTheSameVerdict` generates the
suites, runs `run.py --compiler wiseowl --set cobol=<this build's cobol>` on them, and requires the in-process runner
to run the same tests with the same verdict, naming every difference with both reasons;
`BothNormalizations_MapTheSharedFixtureToItsStatedResults` holds `CutRunner.Normalize` and `run.py`'s `normalize()`
(imported and run by Python) to `conformance-suite/harness/normalization-fixture.json` (16 cases: every line end
.NET reads, the vertical tab it does not, spaces against tabs and no-break spaces, leading and trailing empty lines).
`BothRunners_RunAProgramUnderTheSameDefaultLocales` holds the WiseOwl adapter's new `environment` (both default
locales pinned to the root locale, DOC-A.1-118) to `CutRunner.LocalePin`, the in-process runner's pin.
The Conformance project builds `Cobol.Net.Cli` (a project reference with `ReferenceOutputAssembly="false"`), since
CI's Conformance legs build that project alone. A mutation probe (a wrong line appended to one `.out`) turned that
test's four rows red with the line named, and both runners still agreed (FAIL).

**Design corrections** (DESIGN-conformance-suite.md §4, §5, §13): the verdict drift test runs `run.py` itself, so
every gate and both CI operating systems run it, rather than a CI job of its own; a refusal's manifest entry carries
the refused test's declared files. The theories are one class each until the move (S2, PB3177) brings the corpus
and partitions them; S2 also decides the verdict drift test's shape at the corpus's size (`run.py` starts one `cobol`
process per compile).
