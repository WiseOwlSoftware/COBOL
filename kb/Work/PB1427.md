# PB1427 — LANDED

## Landing (wave 69 finisher) — NULL outside the operand model; the lander's findings

The train-68b lander dropped the wave-68 branch on a CRASH its review found: `01 K CONSTANT AS NULL.` threw a
NullReferenceException in `DataBinder.BindConstantStringLiteral`, because once NULL became its own `nonNumericLiteral`
arm the constant decoder took it for the last arm it read (the boolean literal). The same shape — a literal decoder
that read the figurative arm and nothing after it — was measured at every position that decodes a literal WITHOUT
the procedure operand model: `PIC X VALUE NULL` / `PIC 9(4) VALUE NULL` / `88 … VALUE NULL` / report `VALUE NULL`
compiled and stored LOW-VALUE (`IsLiteralValueOperand` counted NULL "a literal by shape" — PB939's population), and
`PROGRAM-ID. P AS NULL` was refused as "a boolean literal". Probes: scratch `w69y/probe/{KNULL,VALX,VALN,VAL88,VAL88T,
RPTV,PIDN}.cob`.

- `src/Cobol.Net.Compiler/Binding/PredefinedNullRule.cs#Report` — THE ONE COBOLNET2576 text (the operand binder and
  the concatenation folder each had their own). REUSE it for any new position that decodes a `nonNumericLiteral`.
- `DataBinder.Constants.cs#BindConstantStringLiteral` — NULL arm (§13.10.2; §13.10.3 SR7), and the chain now NAMES
  every arm and throws on an unknown one instead of decoding it as the last.
- `DataBinder.cs#IsLiteralValueOperand` — NULL is not a literal; `#ReportNonLiteralValueOperand` reports it (2576),
  for every VALUE position that predicate serves (data item, condition-name, report group, EDITING, SUPPRESS WHEN).
- `DataBinder.cs` §13.16.3 SR10 (COBOLNET2168) keys on the VALUE clause being WRITTEN (`valueClauseWritten`, and
  `_valueClauseWritten` for the acquired-usage arm), not on a stored value — so `USAGE POINTER VALUE NULL` draws
  both 2168 and 2576 (the negative `pb557-value-null-on-pointer` pins 2168). Trap: a refused operand stores no value.
- `ExternalizedName.cs#Screen` — NULL arm; the arms are named and an unknown one throws.
- `PredefinedNullContextDriftTests` — two new facts: 2576 is reported only through `PredefinedNullRule`, and every
  literal decoder outside `Binding/Procedure/` that reads the figurative arm decides the `predefinedNull` arm too
  (exempt: DataBinder.Switches, OptionsBinder, SearchAllFormat2Rules, each with the rule that already refuses NULL).
- `STOP RUN WITH ERROR STATUS NULL` → COBOLNET2576 (was the test's 1704). ⚠ DETERMINATION: NULL is an identifier
