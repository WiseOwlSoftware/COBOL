## Finding — evaluate-directive-p1 (wrong-answer)

The >>EVALUATE frame carries no phrase-structure state: WHEN / WHEN OTHER / END-EVALUATE arms act on whatever frame is on top, and the stack is never checked at end of source nor tagged with the library text it opened in

**Rows:** FMT-7.3.13.2, SR-7.3.13.3-9

**Repro:**

```
PROCEDURE DIVISION. >>EVALUATE 1 / >>WHEN 2 / DISPLAY "W2" / >>WHEN OTHER / DISPLAY "O1" / >>WHEN OTHER / DISPLAY "O2" / >>END-EVALUATE -> compiles clean, prints O1 then O2 (also --std 2002). Variant: >>WHEN OTHER (O1) followed by >>WHEN 1 (W1) prints O1 then W1. Also clean: >>EVALUATE with no >>WHEN; >>EVALUATE never closed at EOF; stray >>END-EVALUATE / >>WHEN with no open EVALUATE; copybook holding `>>EVALUATE 1 / >>WHEN 1` closed by >>END-EVALUATE in source; >>EVALUATE in source whose >>WHEN/>>END-EVALUATE sit in a copybook (the COPY is never expanded and the REST OF THE PROGRAM is silently omitted, rc 0).
```

**Expected from the spec:** §7.3.13.2: the `>>WHEN operand` group is required and repeatable, `[>>WHEN OTHER [text-2]]` is one optional phrase after it, `>>END-EVALUATE` is required -- a second or non-final WHEN OTHER, a missing WHEN, a missing END-EVALUATE and an orphan WHEN/END-EVALUATE each violate the general format and require a diagnostic. §7.3.13.3 SR9: excluding text-1/text-2, all phrases of one EVALUATE directive shall be in the same library text or all in source text -- a diagnostic when they straddle a COPY boundary.

**Observed:** ConditionalCompilationProcessor.Run.Render: the WHEN arm computes `f.Emitting = f.ParentActive && !f.BranchTaken` for every OTHER (so each repeated OTHER re-includes its text) and never sets BranchTaken for OTHER (so a later WHEN still matches and its text-1 is included alongside text-2); the arms are guarded by `_stack.Peek().Kind == FrameKind.Evaluate` and silently no-op otherwise; nothing inspects _stack after the last line; Frame has no SeenOther/SeenWhen-before-END gate and no origin library-text identity (Frame.Start is recorded for FLAG-14 only). The same shape applies to the >>IF frame (§7.3.16 siblings: orphan >>ELSE/>>END-IF, unclosed >>IF) -- sweep it with the fix.

**Code site:** src/Cobol.Net.Frontend/Preprocessor/ConditionalCompilationProcessor.cs#Run.Render (EVALUATE/WHEN/END-EVALUATE arms, lines ~251-295; end of Render) and #Frame

## Finding — if-directive (under-rejects)

The conditional-compilation driver's IF/ELSE/END-IF frame stack never validates structure: an >>ELSE or >>END-IF with no open >>IF frame (or with an >>EVALUATE frame on top) is silently ignored, a second >>ELSE in one IF re-opens emission, an >>IF left open at end of the compilation group is never reported, and because the stack is shared through copybook recursion with no depth check at the copybook boundary an IF directive may open in library text and close in source text.

**Rows:** FMT-7.3.16.2, SR-7.3.16.3-7

**Repro:**

```
Fixed form, --std 2023, pinned cobol.exe, programs in probe/if-directive/: (p02) PROCEDURE DIVISION. / DISPLAY "A" / >>ELSE / DISPLAY "B" / STOP RUN. -> compiles, prints A B. (p04) >>DEFINE V AS 1 / >>IF V = 1 / DISPLAY "A" / STOP RUN. (no >>END-IF) -> compiles, prints A. (p05) >>DEFINE V AS 1 / >>IF V = 2 / DISPLAY "A" / >>ELSE / DISPLAY "B" / >>ELSE / DISPLAY "C" / >>END-IF -> prints B C. (p12) >>EVALUATE TRUE / >>WHEN V = 1 / DISPLAY "W1" / >>ELSE / DISPLAY "EL" / >>END-EVALUATE -> prints W1 EL. (p10) copybook IFCB1.cpy = '>>IF V = 1' + 'DISPLAY "IN-CB"'; main: >>DEFINE V AS 1 / COPY IFCB1. / DISPLAY "MID" / >>END-IF -> prints IN-CB MID.
```

**Expected from the spec:** §7.3.16.2 general format '>> IF constant-conditional-expression-1 [ text-1 ] [ >> ELSE [ text-2 ] ] >> END-IF': >>ELSE only after >>IF, at most once, >>END-IF required. §7.3.16.3 SR7: 'The phrases of a given IF directive shall be specified all in the same library text or all in source-text.' Every repro is non-conforming source and must draw a compile-time diagnostic (the same holds for >>WHEN/>>END-EVALUATE under §7.3.13.2 — sweep the sibling).

**Observed:** All five compile clean with no diagnostic. ConditionalCompilationProcessor.Run.Render: case "ELSE"/"END-IF" act only 'if (_stack.Count > 0 && _stack.Peek().Kind == FrameKind.If)' with no else-branch diagnostic; case "ELSE" sets f.Emitting = f.ParentActive && !f.BranchTaken without recording that an ELSE was seen; after the line loop Render calls Flush() and returns without inspecting _stack; RenderCopybook only saves/restores _depth, not the frame-stack depth.

**Code site:** src/Cobol.Net.Frontend/Preprocessor/ConditionalCompilationProcessor.cs#Run.Render (switch arms ELSE / END-IF / END-EVALUATE, end of loop); #Run.RenderCopybook; #Frame (no SawElse)

## What the fixer owes (and the sibling sweep)

Give `Frame` its kind (IF/EVALUATE), phase (THEN/ELSE; before-WHEN/WHEN/OTHER) and origin (library text id); every arm checks the top frame's kind and phase; end of source and end of each copybook check the depth. Named diagnostics per violation. Negative goldens: orphan ELSE, double ELSE, unclosed IF, IF opened in a copybook and closed in source.
