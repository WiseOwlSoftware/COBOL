# PB5325 - the audit-slot self-test arm compares a stopwatch reading against 30 s

`scripts/gate.py:2641` on branch `fix-gate-red-audit-withdraws` (PR #1516, queued to land): the arm that proves an audit
turning RED while the gate queues ends the gate at once ends its condition with
`and o.timings.get("slot_wait_s", 99) < 30`. That is a fixed time limit in a test, the shape kb/Work PB1590 removed
from the Unit population: a loaded host (a CI runner, or a local host running three gates) can take more than 30 s
with no code change, and the self-test then reports the PB5322 mechanism broken when it is not.

The same condition already checks the structural facts that prove the gate never waited for the slot:
`h.slots_taken == 0`, `not h.ticket_live`, `o.slot is None`, `not h.built`, and `h.events == ["fetch", "slot"]`.
The planted queue never admits the gate, so a gate that DID wait would never return at all. The fix deletes the
timing clause, or swaps it for an event-order or fake-clock witness, and leaves every structural clause in place.
