Filed 2026-09-22 by **REGISTRAR #11** from the wave-45 PB843 finisher's lead 1 (report `PB843-report.md`, repro
`w45e2/p12.cob`). **Re-run on this registrar's own build of main `6871b6e10`** (0/0), at the default `--std 2023`.

## Reproduced

`reg11/h843a.cob`:

```cobol
       SPECIAL-NAMES.
           CLASS MY-DIG IS "0" THRU "9".
       ...
       01 WS-X PIC X VALUE "5".
       PROCEDURE DIVISION.
           IF WS-X DISPLAY "IF-WSX" END-IF
```

→ compiles with **no diagnostic**, then `Unhandled exception. CobolNet.Runtime.NotImplementedCobolFeatureException:
COBOL.NET: a COBOL feature that is not yet implemented was reached at run time: condition 'WS-X'` (rc 127). The source
report measured `IF MY-CLASS` the same way.

## Rule

- `python scripts/spec/cite.py --check 8.8.4.2.1 "The simple conditions are the relation, boolean, class, condition-name, switch-status, sign, and omitted-argument conditions"` → OK §8.8.4.2.1

A PIC X data-name is none of these, and a bare class-name is a class condition only WITH its identifier (the
identifier-less form is §14.9.13.3 SR5's EVALUATE selection object, which PB843 handles, and not an IF condition).
`IF WS-X` is non-conforming and must be a compile-time error. ⚠ A BOOLEAN data item alone IS a boolean condition
(§8.8.4.2.1's "boolean") — the fixer keeps that arm legal and measures it.

## Cause and what the fixer owes

`ConditionBinder.BindSoleOperandCondition` (`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/ConditionBinder.cs`, callers
at :281 and :768) ends in a branch that returns `BoundConditionError` WITHOUT reporting a diagnostic, and the emitter
lowers an error node to a run-time NotImplemented throw. Two fixes, both owed: (1) the branch reports a named
diagnostic naming what the word IS (data-name / class-name / alphabet-name / mnemonic) and what a condition may be;
(2) a drift test that every `Bound*Error` node the binder returns is accompanied by a reported diagnostic — the
emitter's NotImplemented lowering of an error node is a silent-crash channel for every other verb too (sweep the other
`Bound…Error` constructions for the same diagnostic-less return). Condition positions to sweep: IF, EVALUATE `WHEN`
condition objects, PERFORM UNTIL, SEARCH WHEN, the NOT / AND / OR operands, and an abbreviated combined relation.

## Landed (wave 51 group G)

Re-probed on this worktree's build (base train-48 head `0abe2c80f`): `IF WS-X` over PIC X, `IF MY-DIG` (bare
class-name), `IF AL` (bare alphabet-name), `IF SW1` (a switch's mnemonic-name), `IF 5`, `IF "A"`, `IF ZERO`,
`IF NUM + 1`, `IF FUNCTION LENGTH(WS-X)`, `IF TE(1)`, `IF WS-X(1:1)`, `IF NOT WS-X`, `IF WS-X IS NUMERIC AND WS-X`,
`PERFORM UNTIL WS-X`, `SEARCH … WHEN WS-X` all compiled clean and threw NotImplementedCobolFeatureException at run
time. After: each is **COBOLNET2318** (operand-is-not-a-condition), naming what the operand IS. The legal bare
operands are unchanged — a level-88, a one-position boolean item, a boolean literal, and an abbreviated-relation
object (`IF N = 1 OR 5`, `IF WS-X = "4" OR WS-X`).

- Rule: `cite.py --check 8.8.4.2.1 "simple conditions are the relation, boolean, class, condition-name,
  switch-status, sign, and omitted-argument conditions"` → OK §8.8.4.2.1; `--check 8.8.4.1 "There are two
  categories of conditions associated with conditional expressions"` → OK §8.8.4.1.
- Fix: `ConditionBinder.RefuseNonCondition` at the sole-operand arm's end. The structural half: `ConditionBinder.Refused`
  is now the ONE construction site of `BoundConditionError` (the 17 other `new BoundConditionError(` sites in
  ConditionBinder and EvaluateBinder route through it), and it fails the compile with the internal **COBOLNET2319**
  when no failing diagnostic has been recorded — so no condition error node can reach a successful compile.
  `ConditionErrorConstructionDriftTests` (Unit) forbids any other construction.
- Goldens: `conformance:2002/pb982_bare_operand_conditions` (the legal bare operands);
  `conformance:negative/pb982-data-item-as-condition`, `conformance:negative/pb982-class-name-as-condition`
  (reject-at 85 2002 2014 2023, COBOLNET2318).
- Not done here (a lead for the registrar): the other four error families (`BoundOperandError`, `BoundExprError`,
  `BoundBoolError`, `BoundUnsupported`, ~190 construction sites) keep the silent-compile / loud-run channel.
