# PB6355 — COBOL1639 says "identifies no resource" for a name that identifies one

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/SetConditionBinder.cs` (`BindSetCondition`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/SetBinder.cs` (the SET format dispatch)

At `--std 85`, a SET Format 4 statement (`SET mnemonic-name TO ON/OFF`, and the condition-name form the
85 text admits) whose operand is a DECLARED data-name, mnemonic-name of another kind, procedure-name,
alphabet-name, class-name or index-name draws COBOL1639 with the text "the reference identifies no
resource (§1985:IV.4.3.8)". The name does identify a resource: the true ground is that it is not a
name of the category the SET format requires (§1985 SET's own syntax rules for Format 4). The message
names the wrong mistake.

**Expected:** the refusal names the category the operand has and the category the SET format requires,
citing the 1985 SET rule (checked with `cite.py --check` against the 1985 text), and keeps COBOL1639
only for a name that resolves to nothing. Re-probe each declared kind at `--std 85`, and judge 2002,
2014 and 2023 each on its own SET text (the same screen may misname there too).
