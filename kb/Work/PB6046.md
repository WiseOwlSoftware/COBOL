# PB6046 - the COBOL-85 suite, replanned (design revision 4)

**The owner, 2026-11-22:** "If 1985 is now complete, we should focus on creating the WiseOwl comprehensive 1985 test case
suite, a better superset of the NIST test cases", then "replan the test suite. Lots has changed".

Revision 3 of `docs/rearchitecture/DESIGN-conformance-suite.md` (approved 2026-11-04) put the 85 suite at the end of
about 20 tool slices. This note replaces its order of work (§8) and its slice list (§13) for COBOL-85. The owner's
decisions 1-17 of §1.1 stand, except where "What changes" below says otherwise. Every figure below was measured on main
608ccf507c on 2026-11-22; the scripts and outputs are in `E:\COBOL-coord\scratch\suite-replan\` and the session scratchpad
(`m85b.py`).

## What changed since revision 3

1. **The 1985 text is held and its catalog is complete.** 3,109 rows (GR 1,861, SR 874, FMT 213, RV 91, AR 70), 0 GAP,
   each closed on its own verdict (`edition_status.py --edition 1985`: COMPLETE). Revision 3 inferred "85" from the 2002
   working document and counted 2,017 rows of the 2023 inventory banded at 85. **The 85 suite's unit is now the 1985
   catalog's row.** The suite's own completeness report still counts the banded 2023 rows (33 of 1,870 observable) and
   does not see the 1985 catalog at all.
2. **The tests largely exist.** 2,624 tests in 293 `cases/<clause>@1985-<Name>/` folders name a 1985 row; 43 are cleared
   as portable. By row: 46 rows have a suite test, 1,973 only an uncleared accepted test, 325 only a refusal test, 647
   are named in no test's header, 113 are closed by derivation, 5 are documented non-support. The work is mostly
   CLEARING tests, not writing them.
3. **A 1985 row's test runs at 85 alone** (design §3.5: an older edition's rule exists at its own edition). So the 85
   suite needs none of revision 3's cross-edition machinery: band ends and `{from:}` (S5), facility links (S10), edge
   evidence (S11), content variants (S12), removed facilities' rows (S13).
4. **NIST's own references now resolve.** Revision 3 called NIST's 1,928 ANSI-REFERENCE settings pointers "into the
   unheld 1985 text" and planned a hand adjudication of 459 programs. `cite.py --edition 1985` resolves a 1985
   locator, so the crosswalk's first pass is mechanical. The `unit` disposition (a facility "no held text describes":
   Segmentation, Debug, ALTER) is gone: the 1985 catalog holds those rules, so every unit maps to rows.
5. **What 85 requires a compiler to report is now read, not inferred.** The 1985 text requires two warning mechanisms
   and no other diagnosis: for obsolete elements (§1985:I.1.5.2.3: "must provide a warning mechanism, which optionally
   may be invoked by the user at compile time to indicate, if appropriate, that a program contains obsolete language
   elements") and for nonstandard extensions (§1985:I.1.5.2.5.2: "required to flag only extensions that are
   syntactically distinguishable"). It requires no diagnosis of a syntax-rule violation, and §1985:I.1.7 says a
   conforming program's translation "does not imply that the program will be translated or executed successfully".
6. **The tree doubled** (11,098 tests against 6,323; 5,329 WiseOwl diagnosis files against 3,370), so revision 3's
   whole-tree migrations (S5b's case files, S7's respelling) cost twice what was planned and sit in front of the pilot.
7. **Harness features landed outside the slices:** `stdin`, `output-file`, `servers`, `warn-at`, `reformat.py`.
8. **The owner's lessons from 1985** (2026-11-22, memory `2002-plan-measure-first`): measure the denominator first; make
   the path work end to end on one slice before any fleet; process work off content trains; one gate and one landing
   per train; status is a tool's line; cost per row per stage, and stop to redesign when it is worse than planned.

## The plan

**Done means one computed line.** `python conformance-suite/harness/suite_status.py --edition 85` prints
`=== SUITE 85: COMPLETE ===` only when all four hold, and otherwise names each count:
- **rows:** every 1985 row a program can observe has a cleared accepted test that WiseOwl passes at 85;
- **points:** every alternative of every 1985 general format appears in a cleared accepted test (decisions 1, 7);
- **NIST:** every NIST-85 unit has a disposition, every mapped unit is subsumed, every divergence carries its 1985
  citation (design §6.3; the 17 FIPS programs excluded, decision 11);
- **second compiler:** every cleared test has a recorded GnuCOBOL verdict, each FAIL classified with a citation.

### Stage 0 - measure: the four denominators and the status line (tooling, one train)
Nothing is cleared or written until the line exists and every denominator is fixed.
- `suite_status.py` and the completeness report count the 1985 catalog's rows by witness kind (the report's 85 line
  is wrong today).
- Row obligations for the 1985 catalog (`obligations.py`, revision 3's S9 cut to 85): an accepted test per observable
  row. The 647 rows no header names are classified mechanically: a `test-ref` whose test does not list the row
  (repair the header), or no 85 test (an authoring obligation).
- The NIST unit list and its mechanical map (`crosswalk.py`, S17's first half): 6,969 units enumerated; each
  ANSI-REFERENCE and each format-keyed paragraph name (`MPY-TEST-F1-n`) resolved to 1985 rows through `cite.py`.
  Output: units mapped, units ambiguous, units unmapped.
- The 1985 coverage-point catalog (S14 cut to 85): the points of the 213 FMT rows, read from the decided figures
  (`figures-1985`), and the credit of each point from WiseOwl's parse of the existing tests (S15, decision 8).
- The second-compiler run: every accepted 85 test on GnuCOBOL at `-std=cobol85`, with the failures bucketed by cause
  (in flight today as a read-only measurement; its figures go in an addendum beside this note).
**Exit:** the status line prints four counts, and this note's addendum records them. They are the campaign's size.

### Stage 1 - the pilot: one slice end to end (one train)
One slice chosen from Stage 0's numbers: about 100 rows holding arithmetic statements, one file statement, at least one
SR row with only a refusal test, and the NIST programs the map sends there. On it, run every later stage's step with
the real tools: clear, triage the residue, write the missing tests, credit the points, adjudicate the NIST units, land.
**Exit:** the slice reads COMPLETE on the status line with no hand repair of a tool, and the cost per row, per test
cleared, per test written and per NIST unit is recorded. A tool that needed a hand repair is fixed and the pilot step
re-run before Stage 2 starts. These costs set the stop rule of every later stage: a stage that runs above twice the
pilot's cost per unit stops for a redesign.

### Stage 2 - clear the existing tests (mechanical first; one landing for the mechanical part)
A test is CLEARED when (a) the portability lint passes, (b) WiseOwl passes it at 85, (c) its expected output is the
one a 1985 read recorded for its row (the reads of PB5453 and PB6003 already derived each from the text, with a
refuter), and (d) its GnuCOBOL verdict is recorded. A test that passes on both compilers with the same output clears
with no agent. The rest is the RESIDUE, bucketed by cause (a GnuCOBOL non-conformance, recorded in its baseline with
the 1985 citation; a non-portable test, rewritten or kept WiseOwl-only; a WiseOwl defect, a kb/Work note), and each
bucket is one fix train. GnuCOBOL is a second signal, never the authority (design §6.1).

### Stage 3 - write what is missing (fleets by 1985 section, imported in few landings)
New tests only for a measured obligation: a row with no accepted test (the 325 refusal-only rows need a legal-form
test), a format point no test credits, a NIST unit whose checked behaviour no test of its rows exercises. The
authoring lane of design §6.1 (dossier, expected result derived from the text before anything runs, a refuter).
Intake programs (fuzz, vetting and report repros, PB4613) are read here as source material.

### Stage 4 - NIST-85 subsumed, then retired from the gate
The residue of the map (ambiguous and unmapped units) is adjudicated per program with a refuter. When the status
line's NIST term is zero, `tests/nist/` leaves the gate and the nightly guard (design §6 step 5), which also shortens
the gate (GATE GROWTH has fired: test phase median 724 s against a 360 s limit). The report lists what NIST missed:
the 1985 rows and format points no NIST unit exercises.

### Stage 5 - the shipped shape
Case files (decision 17: tests of closely related features in one source file, one grouped run), applied to the 85
suite's folders by `group.py` and held neutral by BOTH compilers' verdicts; results as JUnit XML and JSON; the
per-edition archive (S4, held until the owner chooses the license, PB3159).

## Rules of the campaign

- Tooling lands on its own branch, never on a content train. One gate and one landing per train.
- Each stage reports its cost per unit against the pilot's; above twice, it stops for a redesign.
- Status is the status line, never an estimate.
- A WiseOwl defect a test exposes is a kb/Work note and re-opens 1985 (`edition_status.py`); it is fixed before its
  test clears.
