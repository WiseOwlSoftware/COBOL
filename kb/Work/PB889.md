# PB889 — LANDED — a set of three, screened as a set of two

Source: the `PB522` report, "New defects" item 2. **Two things in that lead did not survive re-measurement,
and both are corrected here.**

## ⛔ Correction 1 — the report's probe is MASKED, and filing it as written would have sent the fixer at the wrong screen

The report's program is `01 OUTER GROUP-USAGE NATIONAL. 02 INNER SAME AS SRC2.` with `SRC2 PIC X(4)`, and it
says it "compiles clean and runs". On this tree it does not:

```
## p43_sameas_gu.cob  (SRC2 PIC X(4))       --std 2023 --run
  error COBOLNET0881: data item 'INNER': USAGE NATIONAL may not be specified with an alphabetic or
  alphanumeric PICTURE (X(4)) ... (ISO §13.18.60.3 SR12; §13.18.40.3 SR30)
rc=70
```

The refusal is real but it is a PICTURE/USAGE rule, not SR9 — a different question with the same answer
(memory `a_real_clause_can_answer_a_different_question`). Remove the collision and the defect appears:

```
## q43_sameas_gu_nat.cob  (SRC2 PIC N(4))   --std 2023 --run
COMPILED-AND-RAN
rc=0
```

and the control, which proves the screen exists and is simply missing an arm:

```
## p43b_sameas_usage.cob  (01 OUTER USAGE DISPLAY. 02 INNER SAME AS SRC2.)
  error COBOLNET1555: 'INNER': a group item to which a SAME AS entry is subordinate shall not contain a
  GROUP-USAGE, SIGN, or USAGE clause (ISO §13.18.49.3 SR9)
rc=70
```

**The diagnostic's own text says GROUP-USAGE. The code does not test it.**

## ⛔ Correction 2 — the TWIN's rule TEXT was inherited and is wrong

The report quotes §13.18.57.3 SR5 with §13.18.49.3 SR9's wording. It is not the same sentence:

```
$ python scripts/spec/cite.py --check 13.18.49.3 "A group item to which the subject of the entry is subordinate shall not contain a GROUP-USAGE, SIGN, or USAGE clause"
  OK  §13.18.49.3 9)  (Syntax rules)
      9) A group item to which the subject of the entry is subordinate shall not contain a GROUP-USAGE,
      SIGN, or USAGE clause.
$ python scripts/spec/cite.py --check 13.18.57.3 "shall not contain a GROUP-USAGE, SIGN, or USAGE clause"
  FAIL: §13.18.57.3 exists but does NOT contain 'shall not contain a GROUP-USAGE, SIGN, or USAGE clause'
$ python scripts/spec/cite.py --check 13.18.57.3 "No group item to which the subject of the entry is subordinate shall contain a GROUP-USAGE, SIGN, or USAGE clause"
  OK  §13.18.57.3 5)  (Syntax rules)
      5) No group item to which the subject of the entry is subordinate shall contain a GROUP-USAGE, SIGN, or
      USAGE clause.
```

*"A group item ... shall not contain"* vs *"No group item ... shall contain"*. Same obligation, different
sentence, and the ordinal (SR5) was right all along. **A quotation carried across clauses is precisely the
CA10 failure mode CLAUDE.md rule 1 names**; the fixer must use the text above, not the report's.
