# PB2814 — the mailbox is invisible to a restarted session

Owner, 2026-10-08 ~16:45 PDT: "You are not reading your inbox from Mythos? Why?"

## Measured

- The two-lane protocol (`E:\COBOL-coord\mailbox\README.md`; memory note two-sessions-2026-10-07) has each session keep
  ONE background watcher on its inbox (`mailbox.py watch --inbox <lane> --timeout 0`) and re-arm it after each wake; it is
  the only wake-up between the lanes (the ListAgents doorbell does not cross config dirs).
- The operator session restarted at 00:20 and again at 14:50 (Claude Code update) and armed no watcher either time:
  nothing in its start path (session-start skill, session-probe, the START HERE resume note) names the mailbox.
- `to-operator\` held, unread: four `publish` notices from the loop (04:59, 05:50, 12:09, 13:12; each publish was done
  anyway from the tick), a Mythos `info` (14:53, its resume), and a Mythos `question` (15:07: the owner's 15:05 direction
  that the Mythos lane take operator work on Opus — wave 1045, waiting for GO). Answered GO at 16:47, 1 h 40 min late.
- The session probe printed branches, CI and GAP at 14:50 and nothing about the 5 open messages.

## Fix (rule 5: the next restart is automatic)

1. `scripts/session-probe.ps1` prints a `mailbox:` line per lane: open messages in `to-operator\` / `to-mythos\` (count,
   oldest age, any `question`/`approval`/`needs_owner`), and whether a watcher process for this lane's inbox is running
   (a python process whose command line is `mailbox.py watch --inbox <lane>`); a lane with open messages and no watcher
   prints ⛔.
2. The session-start skill's first actions for either lane: list the inbox, act on it, arm the watcher. The resume note
   template carries the line.
3. A self-test for the probe line (an inbox with one `question` and no watcher prints ⛔).

## Landed 2026-10-08 (operator, on the owner's "Fix it so a restart re-arms the inbox watcher")

A hook cannot arm the watcher (it must be the session's own background Bash task, whose exit wakes that session), so the
fix makes an unarmed watcher impossible to miss wherever a session looks:
- `mailbox.py status`: this session's lane (None for a loop unit carrying `COBOL_LOOP_UNIT`; `operator` under the config
  dir `operator-session.json` names; else `mythos`), its open messages (count, oldest, any question, approval, task or
  needs_owner) and whether a `mailbox.py watch --inbox <lane>` process descends from THIS session's Claude Code process;
  with none, a ⛔ line naming the arm command. `lane`, `session_root`, `watchers` and `status` carry 13 new self-test
  checks (another session's watcher does not count; a parent cycle ends the walk; a loop unit arms nothing).
- `coord.process_table()` (PowerShell CIM on Windows, /proc elsewhere) beside `process_name`, with a self-test against
  the real table; `account._same` became the public `same_dir` (both callers changed) so the lane check reuses it.
- `scripts/session-probe.ps1` prints the line right under `push`, and the SessionStart hook runs the probe at every
  start, resume, clear and compaction; `list` prints it; `done` prints it when no watcher is armed; a firing `watch`
  prints the re-arm command as it exits.
- Docs: DESIGN-orchestrator-loop.md section 15, and the protocol README in the coordination directory's mailbox folder
  (outside the repo).
- Item 2 (the session-start skill names the step) is met by the probe line itself: the skill already runs the probe
  first, and the line carries the command.
