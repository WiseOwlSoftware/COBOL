# PB1562

Found 2026-09-24 by the w59e (PB1053) implementer, a different root cause from PB1053; **first derive from §13.18.43.3
(RECORD clause Format 1) whether a record with dynamic-length members is legal under a fixed-length RECORD clause at
all** — if not, the defect is an UNDER-REJECT and the fix is the diagnostic; if it is, the record must round-trip.
Repro: FD F in `<scratchpad 9db39f61…>\w59e\p1\fixedfmt.cob`. Suspected site: `FileModel.ImpliesVariableFormat` / `IsOutOfLineRecord`.

## Landed (bundle w0930-io)

**Derivation.** §13.18.43.3 SR3 bounds a record description by its MAXIMUM (§13.18.43.4 GR8 b), and PB1276 already gave a
dynamic-length item its maximum size (§8.5.1.10.1) as GR8 b)'s number; `RecordClauseRules` nevertheless skipped every
record holding one ("GR8 has nothing to sum"). So the note's first arm holds for the repro — two unbounded dynamic members
describe up to 2,147,483,585 bytes, far above `RECORD CONTAINS 20` — and the screen was an UNDER-REJECT (COBOLNET2010 now,
SR3 and both SR4 arms; minimum = dynamic items at zero length, §8.5.4 item 4). The second arm also holds for the LEGAL
variant (LIMIT-bounded members totalling 19 bytes): its records must round-trip, and read back mis-split because
`ImpliesVariableFormat` required an ABSENT RECORD clause, so an explicit Format 1 clause gave the file plain 20-byte blocks
that cannot carry the extent table of D-FRA (v). `ImpliesVariableFormat` no longer reads the clause: a file with a
variable-length record frames its records (integer-1 stays the area width and the maximum, SR3 keeping every description
within it). Goldens `conformance:2014/pb1562_variable_group_under_fixed_record_clause` and negatives
`pb1562-record-contains-unbounded-dynamic`, `pb1562-record-varying-range-unbounded-dynamic`,
`pb1562-record-varying-range-below-dynamic-minimum` (COBOLNET2010 at 2014 and 2023). D-FRA (iv)/(v) amended.
