# PB1735 — OPEN

Filed by the train-72 lander, 2026-09-29, from wave 72 group H's report.

## Finding

**Code site.** `.claude/skills/workstream/templates/registrar-brief.md:13` (step 5, GATE):
`dotnet test tests/Cobol.Net.Tests.Unit --no-build --filter "FullyQualifiedName~SpecTraceabilityInventory|FullyQualifiedName~DefectiveRowCoverage|FullyQualifiedName~DerivedVerdict"`.

M13 (PB1721) made "order, don't skip" the only gate: `build-local -Mode implementer|lander` runs the whole
population, and a deliberately filtered run goes through `scripts/filter_population.py`, which refuses any filter
term that names no real test (kb/Work PB708). The registrar brief was not in the M13 caller list, and it is still a raw filtered `dotnet test`.

**Harm.** A registrar's validation run is evidence only about the three classes it names. With no population check,
a filter that matched nothing would exit 0 (see `reference_vstest_filter_terms`). The registrar writes only
`kb/Work` notes and inventory verdicts, so the exposure is those drift classes, not compiler code.

**Fix shape.** Route the step through `python scripts/filter_population.py` (the checked form of a filtered run), or through
`pwsh scripts/build-local.ps1 -Mode lander` when the registrar changes anything a wider test reads. Then add the
registrar brief to whatever drift test pins that no brief carries a raw filtered `dotnet test`
(`FilterPopulationGuardDriftTests` or `check_practices.py`), so the next caller sweep is mechanical.
