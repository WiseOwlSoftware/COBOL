# PB3821 — one listing and one scrubbed environment, each written more than once

**Sites:** `scripts/self_tests.py#tracked_scripts` (about line 247), `scripts/scratch_repo.py#audit` (about 416),
`scripts/temp_names.py#live_scripts` (about 250), `scripts/standard_streams.py#live_python`, and the `scrubbed_env`
definitions at `scripts/scratch_repo.py` (about 125) and `scripts/test_population.py` (about 115); the roots are
`scripts/live_tools.py#ROOTS`. `tests/WiseOwl.Cobol.Tests.Unit/SelfTestDiscoveryDriftTests.cs` reads the `live_tools.ROOTS`
text in each reader and needs the same move.

## Measured

PB3637's implementer found four readers that each run `git ls-files -z -- <live_tools.ROOTS>` with their own environment and
suffix filter, and two `scrubbed_env` definitions, and did not fix them: it changes four readers' git environment and that
drift test. PB3584 owns one git-environment scrub for the tooling (`_scrubbed_env`/`scrubbed_env` in its text) and PB1718
the callers that pass `env=scrubbed_env()`; neither names the listing. Re-grep the sites before editing: they were located by
line number in the report.

## Acceptance

- `live_tools.tracked(repo, suffixes, env)` is the one listing; the four readers call it.
- ONE `scrubbed_env` (the PB3584 one if it has landed, else the one place its note names); the two copies are deleted.
- `SelfTestDiscoveryDriftTests` reads `live_tools.ROOTS` once, through the new function, and fails on a new reader that
  spells the `git ls-files` listing itself.

## Landing (wave 20261737, group C)

**Re-probe (`git grep` for the listing on this base).** Seven spellings of `git ls-files -z -- <live_tools.ROOTS>`, not
four: `self_tests.tracked_scripts`, `scratch_repo.audit`, `temp_names.live_scripts`, `standard_streams.live_python`,
`gate_plan.audit_trx_writers` and `gate_plan.audit_trx_readers` (imported as `LIVE_ROOTS`), and `line_endings.live_python`
(`*.py` then a prefix filter), each with its own suffix filter, missing-file rule and environment.

**The fix.** `scripts/live_tools.py#tracked(repo, suffixes=None, env=None)` is the one listing (sorted, existing files
only, suffix filter, the child's environment). All seven readers call it; `tracked_scripts` is deleted. A reader that may
run under a git hook keeps passing the git scrub (`self_tests`, `scratch_repo`). `live_tools.py --self-test` (a scratch
repository: roots, suffixes, a deleted file, a leaked `GIT_DIR`) is discovered by the runner.
`SelfTestDiscoveryDriftTests` now holds each reader to `live_tools.tracked(` (`gate_plan.py` joins the list) and has
`NoLiveScript_SpellsTheLiveTreeListingItself`, a net over every tracked Python file under the roots that fails on a
`git ls-files` argument list holding `ROOTS`.

**The two `scrubbed_env` are NOT copies, so the second acceptance bullet was a wrong premise.** `scratch_repo.scrubbed_env`
drops git's repository-selection variables (PB1719/PB3584); `test_population.scrubbed_env` drops the gate's leg handshake,
the VSTest filters and `RunSettingsFilePath` from a `dotnet test` child (PB1718). Different jobs, one name, each defined once.
The hazard was the shared name, so the git one is renamed `scratch_repo.git_env` (every caller changed: `scratch_repo`,
`self_tests`), and `SelfTestFixtureDriftTests.TheFixturesRules_AreWrittenOnce` now refuses a second definition of either
name outside its home. Nothing was deleted because nothing was a duplicate; the `dotnet test` scrub (many callers, workflow
text, DESIGN-test-build-ci.md 3.14.4) keeps its name.

**Behaviour change, stated.** `self_tests.discover` used to read every listed path and raise on one deleted from the working
tree; `tracked` does not list it (the other six readers all skipped it). An unreadable file still raises.
