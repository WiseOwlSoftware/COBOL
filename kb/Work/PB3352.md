# PB3352 — a user-manual chapter on the COBOL file types

## Owner request, 2026-10-17 ~18:00 PDT (verbatim)

While the keyed store engine (kb/Work PB3330) and the bounded-memory SORT (kb/Work PB3339) were in progress, the owner
wrote: "As part of our future COBOL documentation, we should describe the implementation and support of the COBOL file
types".

## What exists

`docs/rearchitecture/DESIGN-USER-DOCUMENTATION.md` §4 (owner decision R50: docs-as-code, Astro Starlight on
wiseowlsoftware.com) gave files one clause of the *User guide*: "files and I-O (organizations, the Latin-1 no-CODE-SET
rule of R47, status codes)". The implementation is described only for maintainers:
- `docs/rearchitecture/DESIGN-runtime-library.md` §2.2 (IO) and 2.2.1 (the keyed store engine);
- `docs/COBOLNET_DESIGN.md` SORT/MERGE;
- `docs/CONFORMANCE.md` (the DOC-A.1 determinations, among them DOC-A.1-107, the file size boundary; DOC-A.1-75; and §3
  D-SWK, the sort work files).

A user cannot learn from the manual how a file is stored, how large it can grow, what sharing and locking do, or where
SORT puts its temporary files. kb/Work PB1610 (the manual's hand-written chapters) is the parent.

## The bar

A hand-written chapter, *File types*, in `docs/manual/` (the PB1610 scaffold), per organization and file kind. It
describes the CURRENT compiler (CLAUDE.md rule 6), so it is written once PB3330's last group has landed:
- **Sequential** (record sequential, with fixed and variable records), **line sequential**, **relative**, **indexed**,
  **sort-merge** and **report** files, each covering:
  - the access modes and statements supported, per edition (`--std`);
  - how the file is stored on disk: the paged store format 5 for relative and indexed files (B+ trees, 4 KiB pages,
    no sidecar), the record framing of sequential files, and the line sequential text and its code set (R47);
  - the limits, from DOC-A.1-107 and the other DOC-A.1 rows;
  - what a file written by another compiler gets (status '39');
  - what is documented as not supported, with its warning codes.
- **Sharing and record locking:** the SHARING phrase, Table 19, LOCK MODE, status 51 and RETRY, and the lock-file host
  where the platform needs one (macOS).
- **APPLY COMMIT, COMMIT and ROLLBACK:** what is under commit control, what a run unit's ROLLBACK restores, and what
  happens at normal and abnormal termination (§9.1.18), with the guarantee the engine gives after a crash: the state
  after the last completed statement, never a torn one.
- **Performance characteristics a user can plan by:** pages read per keyed statement, OPEN reading only the header, bulk
  load linear in N, and the bounded memory of SORT and MERGE with their configurable limit and temporary-file location
  (PB3339, D-SWK).
- **Status codes** per organization, with the condition each reports.

Every fact cites the determination or design section it comes from, so a later change to the format, a limit or a
status code is a change to one place that the chapter follows. A drift test pins each DOC-A.1 id and each configuration
name the chapter cites to an existing row and setting (the R50 rule: generated where possible, drift-tested where
hand-written).
