# PB5133 - the range-membership arm of the PB5106 sign predicate

**Sites:** `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/ConditionRenderer.cs` (`Visit(BoundRangeMembership)`, near line 108; `DropsOperationalSign`),
`ConditionBinder.CheckedRangeMembership`, `conformance-suite/cases/8.8.4.2-Simple-relation-conditions/pb5106-numeric-with-group-1985.cob`.

**Found.** The reviewer's finding: a `BoundRangeMembership` is built only for an IN alphabet-name phrase or EC-RANGE-INVALID
checking, and both are refused at --std 85 with COBOL0900, while `DropsOperationalSign` is always true from 2002. So the PB5106
edit to that arm changes nothing today. If the arm ever became reachable at 85, its shared subject read would give a wrong answer
for a mixed range: the subject is read once for both range ends, and takes the sign-keeping image only when both ends agree (the
implementer's report names this exotic mix). Separately, the golden comment and the report present U7 as covering the range arm,
but U7 lowers to the relational pair, so the arm has no witness.

**Owed.** Either remove the unreachable edit (and the claim) or make the arm correct per range end and give it a witness; pick by
whether an 85 route to a range membership exists.
