# PB4560 — inspect-tallying-all-after-characters-refused: INSPECT TALLYING ... FOR CHARACTERS ... ALL "A" is refused: 'missing value between ALL/LEADING/TRAILING words'

Filed 2026-11-03 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-batch-3000-20261103`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

cobc 3.2 refuses an INSPECT TALLYING phrase in which an ALL or LEADING phrase follows a CHARACTERS phrase for the same tally counter (`FOR CHARACTERS BEFORE INITIAL "C" ALL "A"`) with "missing value between ALL/LEADING/TRAILING words". The same phrases in the other order (`FOR ALL "A" CHARACTERS BEFORE INITIAL "C"`) compile and run. The general format repeats the CHARACTERS / ALL / LEADING alternative after one FOR in any order. Class: rejects legal source. Fuzz programs: fz01726 (night fuzz-batch-3000-20261103, slice D4).

## Minimal test case

Free reference format.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. IN1.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 T PIC X(8) VALUE "ABACADAE".
01 C PIC 99 VALUE 0.
PROCEDURE DIVISION.
    INSPECT T TALLYING C FOR CHARACTERS BEFORE INITIAL "C" ALL "A"
    DISPLAY C
    STOP RUN.
```

## Environment

`cobc (GnuCOBOL) 3.2.0`, WSL2 Ubuntu x86_64. Compiled with `cobc -x -free -std=cobol2014 -o p in1.cob`; when an executable is produced it is run as `./p` under `timeout 10`. Control: `FOR ALL "A" CHARACTERS BEFORE INITIAL "C"` compiles and prints `05`. `FOR CHARACTERS ALL "A"` (no BEFORE phrase) gives the same error.

## Observed result

```text
in1.cob:8: error: missing value between ALL/LEADING/TRAILING words
```

## Expected result (per ISO)

The program is legal and prints `05`. Positions 1-3 (before the first C) are tallied by CHARACTERS; position 4 (the C) matches neither operand; the A's at positions 5 and 7 are tallied by ALL "A": 3 + 2 = 5.

- §14.9.22.2 (checked): the tallying-phrase is `{ identifier-2 FOR { CHARACTERS [after-before-phrase] | ALL {...}... | LEADING {...}... } ... } ...`: the middle ellipsis repeats the selected CHARACTERS / ALL / LEADING phrase for one identifier-2 (rendered from the printed page: PDF page 673, printed page 643).
- §14.9.22.4, general rule 8 e) (checked): "If the CHARACTERS phrase is specified, an implied one character operand participates in the cycle ... as if it had been specified by literal-1".

Edition: 2014 (and every earlier edition): the format with the repeated phrase is unchanged; Annex E of 2023 adds only BACKWARD.

## Our compiler

WiseOwl COBOL (fresh judge, `--std 2014 --source-format free`): compiles with no diagnostic; the run prints `05`, exit code 0.

## Fix site

`cobc/parser.y`, function `check_preceding_tallying_phrases`: for `ALL_LEADING_TRAILING_PHRASES` it reports "missing value between ALL/LEADING/TRAILING words" when `previous_tallying_phrase == CHARACTERS_PHRASE`; a CHARACTERS phrase is complete in itself and may be followed by ALL or LEADING.

## Draft issue

**Title:** INSPECT TALLYING ... FOR CHARACTERS followed by ALL or LEADING is still refused (please reopen)

As posted (owner-reviewed, 2026-11-04), a comment on bugs #47:

The last two posts here reopened this ticket for bugs #138's example, `INSPECT s1 TALLYING n1 FOR CHARACTERS, LEADING 'ABC'`. The ticket is closed again, but 3.2.0 and 3.3-dev r5751 still refuse that statement, and CHARACTERS followed by ALL as well. Could it be reopened? A patch is attached.

### To reproduce

`inspchar.cob` (attached):

~~~~
       IDENTIFICATION DIVISION.
       PROGRAM-ID. INSPCHAR.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  T  PIC X(8) VALUE "ABACADAE".
       01  C  PIC 99 VALUE 0.
       PROCEDURE DIVISION.
       MAIN-PARA.
           INSPECT T TALLYING C
               FOR CHARACTERS BEFORE INITIAL "C" ALL "A"
           DISPLAY C
           MOVE 0 TO C
           INSPECT T TALLYING C FOR CHARACTERS, LEADING "ABA"
           DISPLAY C
           STOP RUN.
~~~~

    cobc -x inspchar.cob && ./inspchar

### What happens

Both versions stop with (source excerpts omitted)

~~~~
inspchar.cob: in paragraph 'MAIN-PARA':
inspchar.cob:10: error: missing value between ALL/LEADING/TRAILING words
inspchar.cob:13: error: missing value between ALL/LEADING/TRAILING words
~~~~

and the same with `-std=cobol2014`, `cobol2002`, `cobol85`, `ibm` and `mf`. The reverse gets through: `allchar.cob` (attached) has `FOR ALL CHARACTERS`, with no value after ALL, and prints `08`.

### What should happen

`05` and `08`. In the tallying-phrase (ISO/IEC 1989:2023 14.9.22.2) the CHARACTERS / ALL / LEADING choice after FOR has its own ellipsis, so the phrases may follow one another in any order. The operands are tried left to right at each position (14.9.22.4 general rule 8 a) to c)), and CHARACTERS is "an implied one character operand" (8 e)): it counts positions 1-3, before the C, and ALL "A" the A's at 5 and 7; in the second INSPECT it matches every position before LEADING is tried. The same in 2002 and in the 2014 FCD.

### Why it happens

`check_preceding_tallying_phrases` in `cobc/parser.y` reports the missing value for ALL/LEADING/TRAILING after CHARACTERS, which is complete in itself, but not for CHARACTERS after ALL/LEADING/TRAILING. The 2020-03-27 change for this ticket ("allow consecutives CHARACTERS keywords") covered `CHARACTERS CHARACTERS`; the testsuite case "INSPECT repeated keywords" accepts that and has no case of CHARACTERS followed by ALL or LEADING.

### Proposed fix

The attached `n10-inspect-characters-all.patch` (against 3.3-dev r5751) turns the check around, so `inspchar` prints `05` and `08` and `allchar.cob` gets the missing-value error, the patch's one new refusal.

libcob tallies one operand at a time, not in the GR 8 cycle, so with the patch `FOR CHARACTERS AFTER INITIAL "D" ALL "DAE"` on `ABACADAE` prints `02` (ISO `01`). `FOR ALL "BA" ALL "AB"` on `ABAB` already prints `01` (ISO `02`). That is a separate runtime issue.

The patch adds the test "INSPECT TALLYING CHARACTERS then ALL/LEADING" to `run_misc.at`, a `FOR ALL CHARACTERS` line to "INSPECT repeated keywords" in `syn_misc.at`, and ChangeLog entries. `make check`: 1373 expected, 9 skipped, 0 failed (1372 unpatched); the new and changed tests fail without the patch.

### Details

GnuCOBOL 3.2.0 (Ubuntu `gnucobol3 3.2-4build1`) and 3.3-dev r5751 (CI snapshot 3.3-dev.138 of 2026-10-29), x86_64 Linux, both run 2026-11-04.
