# PB4560 — inspect-tallying-all-after-characters-refused: INSPECT TALLYING ... FOR CHARACTERS ... ALL "A" is refused: 'missing value between ALL/LEADING/TRAILING words'

Filed 2026-11-03 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-batch-3000-20261103`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

cobc 3.2 refuses an INSPECT TALLYING phrase in which an ALL or LEADING phrase follows a CHARACTERS phrase for the same tally counter (`FOR CHARACTERS BEFORE INITIAL "C" ALL "A"`) with "missing value between ALL/LEADING/TRAILING words". The same phrases in the other order (`FOR ALL "A" CHARACTERS BEFORE INITIAL "C"`) compile and run. The general format repeats the CHARACTERS / ALL / LEADING alternative after one FOR in any order. Class: rejects legal source. Fuzz programs: fz01726 (night fuzz-batch-3000-20261103, slice D4).

## Minimal test case

Free reference format.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. IN1.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 T PIC X(8) VALUE "ABACADAE".
01 C PIC 99 VALUE 0.
PROCEDURE DIVISION.
    INSPECT T TALLYING C FOR CHARACTERS BEFORE INITIAL "C" ALL "A"
    DISPLAY C
    STOP RUN.
```

## Environment

`cobc (GnuCOBOL) 3.2.0`, WSL2 Ubuntu x86_64. Compiled with `cobc -x -free -std=cobol2014 -o p in1.cob`; when an executable is produced it is run as `./p` under `timeout 10`. Control: `FOR ALL "A" CHARACTERS BEFORE INITIAL "C"` compiles and prints `05`. `FOR CHARACTERS ALL "A"` (no BEFORE phrase) gives the same error.

## Observed result

```text
in1.cob:8: error: missing value between ALL/LEADING/TRAILING words
```

## Expected result (per ISO)

The program is legal and prints `05`. Positions 1-3 (before the first C) are tallied by CHARACTERS; position 4 (the C) matches neither operand; the A's at positions 5 and 7 are tallied by ALL "A": 3 + 2 = 5.

- §14.9.22.2 (checked): the tallying-phrase is `{ identifier-2 FOR { CHARACTERS [after-before-phrase] | ALL {...}... | LEADING {...}... } ... } ...`: the middle ellipsis repeats the selected CHARACTERS / ALL / LEADING phrase for one identifier-2 (rendered from the printed page: PDF page 673, printed page 643).
- §14.9.22.4, general rule 8 e) (checked): "If the CHARACTERS phrase is specified, an implied one character operand participates in the cycle ... as if it had been specified by literal-1".

Edition: 2014 (and every earlier edition): the format with the repeated phrase is unchanged; Annex E of 2023 adds only BACKWARD.

## Our compiler

WiseOwl COBOL (fresh judge, `--std 2014 --source-format free`): compiles with no diagnostic; the run prints `05`, exit code 0.

## Fix site

`cobc/parser.y`, function `check_preceding_tallying_phrases`: for `ALL_LEADING_TRAILING_PHRASES` it reports "missing value between ALL/LEADING/TRAILING words" when `previous_tallying_phrase == CHARACTERS_PHRASE`; a CHARACTERS phrase is complete in itself and may be followed by ALL or LEADING.
