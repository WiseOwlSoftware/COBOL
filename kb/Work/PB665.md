# PB665 — OPEN — the data-name-1 half of SR19

Found 2026-09-05 by the `PB231` pointer-third implementer (report §"New defects" (3)) — it is the reason that
landing's golden does not window a strongly-typed record: doing so needs exactly the statement the standard
forbids, and the compiler accepts it.

## Repro (`--std 2002`+)

```cobol
       01 T-PTR IS TYPEDEF STRONG.  05 T-P USAGE POINTER.  05 T-N PIC X(4).
       01 R TYPE T-PTR BASED.
       01 W PIC X(12) BASED.
       01 T-RP IS TYPEDEF USAGE POINTER TO T-PTR.
       01 WS-P TYPE T-RP.
       ...
           ALLOCATE R
           SET WS-P TO ADDRESS OF R
           SET ADDRESS OF W TO WS-P          *> accepted; W(9:4) then reads T-N
```

## The rule

§14.9.39.3 SR19: "If identifier-6 references a restricted data-pointer, either identifier-5 shall reference a
data-pointer restricted to the same type or data-name-1 shall be a typed item of the type to which identifier-6 is
restricted." (`OK §14.9.39.3 19)`). §8.4.3.11.4 GR2 makes `ADDRESS OF R` (R strongly typed) a restricted
data-pointer, so `WS-P` is restricted to `T-PTR`; in `SET ADDRESS OF W TO WS-P` identifier-5 is absent and
data-name-1 (`W`) is untyped, so neither leg holds and the statement is nonconforming. Annex D.9.2.2's point — a
restricted pointer cannot be used to view its target through another description — is what the accepted statement
defeats.

## The mechanism

`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/PtrBinder.cs`: the SET screen enforces the identifier-5 half
(COBOLNET0869 when a plain pointer receives the address of a strongly-typed group) and has no arm for the
`SET ADDRESS OF data-name-1 TO identifier-6` form with a restricted identifier-6. [[two_arm_dispatch]].

## Fix shape

One SR19 check with both legs, written once and called from both SET forms: given a restricted identifier-6, admit
the statement iff (identifier-5 is a data-pointer restricted to the same type) or (data-name-1 is a typed item of
that type); otherwise the existing COBOLNET0869 descriptor (its text widened to name both legs — re-run
`gen-diagnostics-doc.ps1`). Negatives at 2002/2014/2023: the repro above; `SET ADDRESS OF <typed-other-type> TO
WS-P`; positive controls: `SET ADDRESS OF R2 TO WS-P` with `R2 TYPE T-PTR BASED`, and `SET WS-Q TO WS-P` with WS-Q
restricted to the same type. Then PB231's golden gains the strongly-typed byte-quantity leg the implementer had to
leave out, through the conforming spelling.
