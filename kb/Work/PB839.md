# PB839 — OPEN — the population check's two false alarms, and why they cost the real one

Sources: the `PB500` report ("New defects found" item 2) and the `PB355` report ("New defects" item 2). Both
are defects of the same reporter, so they are one note.

## (a) A corpus-CASE term is reported DEAD when vstest matches it

`pwsh scripts/build-local.ps1 -Filter "~pb500_format1_value_dynamic_table|~OccursDynamic"` prints

```
⛔ DEAD FILTER TERM: FullyQualifiedName~pb500_format1_value_dynamic_table selects no test ... so whatever it was
meant to cover was never tested
```

and refuses to run — while the same case executes under vstest as
`CorpusRunnerTests_P0.EnabledProgram_CompilesStrict_AndMatchesOutIfPresent(edition: "2014", name:
"pb500_format1_value_dynamic_table")`. The theory's `[MemberData]` arguments ARE part of the FullyQualifiedName
at execution time; `filter_population.py` enumerates without them. Consequence: an implementer who wants to run
exactly their own golden is told it "was never tested" and widens to `~CorpusRunner` (1959 cases, ~3 min).
It fails CLOSED, so this is a usability defect, not a false green.

## (b) INERT-because-unfiltered wears the DEAD banner

```
⛔ INERT FILTER TERM: FullyQualifiedName~SpecTraceabilityInventory selects no test in Cobol.Net.Tests.Conformance
   ... the name matches 15 test(s) in Cobol.Net.Tests.Unit, which this invocation runs UNFILTERED - those tests
   ran, but not because of this term
⛔ FILTER POPULATION: 1 of 9 term(s) INERT
```

The message already contains the whole diagnosis; the SUMMARY line is what conflates it with the PB708 hazard.
Only a term that matches nothing anywhere is a reason to distrust the run.

## Shape of the fix

One classification with three values — MATCHED / INERT-BECAUSE-UNFILTERED / DEAD — computed once and printed
once, with the ⛔ reserved for DEAD; and the enumeration taught to expand theory data (or, where it cannot, to
report UNKNOWN rather than DEAD). A term that names a corpus case is answerable from the corpus manifest without
enumerating vstest at all.

## Harm

`process_only`. The cost is measured in implementer turns and in trained-in skepticism toward the one line that
protects against a filtered gate proving nothing (`feedback_vstest_filter_terms`, `kb/Work/PB708`).

## Sibling sweep the fixer owes

* The three terms observed inert or dead by implementers this week — `~ItemCategory` (PB337), `~GroupValue`
  (PB646), `~VersionMatrix` in `Cobol.Net.Tests.Unit` (PB535) — are the regression corpus for the fix: after it,
  each should report its true class. Two of them additionally say something true about COVERAGE (no test is
  NAMED for the `ItemCategory` predicate or for the group-VALUE distributor); that is a different finding and
  belongs to whoever owns those predicates, not here.
* `scripts/build-local.ps1` and `build-local.sh` both print the summary line — fix both.
