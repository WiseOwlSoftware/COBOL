# PB6210 - OPEN - `--find` and `--check` disagree on how a list item is cited

**Repro (2026-11-24, main @ 070078bb16).**

    python scripts/spec/cite.py --find "each inherited class upward in the hierarchy" --edition 2002
    -> §2002:9.3.5 2)  (Method invocation)
    python scripts/spec/cite.py --check "§2002:9.3.5 2)" "each inherited class upward in the hierarchy"
    -> FAIL: '2)' is not a rule designator: write SR n, GR n, ... or a list item: item <n>, item L<m>.<n> ...

The form `--check` accepts for the same text is `§2002:9.3.5 item L2.2` (PB5580's citation correction ran it OK).

**Harm.** CLAUDE.md rule 1 sends every citation through `--check`; `--find` is how an author gets the clause. A search that
prints an uncheckable designator invites the hand-made `rule 2` form PB5580's finding carried, i.e. a citation nobody can
check. No compiled program is affected.

**Site.** `scripts/spec/cite.py` `_found`: it prints `rule_path(lines, i, s, labels_of(edition))`, the printed list path,
instead of the designator of the catalog unit holding line `i` (`Rule.designator`, which yields `item L2.2` for a list item,
PB5998). Siblings to sweep: every other place that prints a rule path for a person to cite (`--check`'s "run --find" hint at
`cite.py:1238`), and the 1985 and 2023 forms of the same list-item case.

**Done when** every `--find` hit prints a designator that `--check` accepts for that hit's own text, pinned by a self-test that
round-trips each hit of a planted clause with a numbered list through `--check`.
