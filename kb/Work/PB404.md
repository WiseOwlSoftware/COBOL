# PB404 — one rule, three subjects, one of them enforced

## 1. The mechanism

The "where am I bound?" family of syntax rules — *is this statement inside a declarative? which one? does its
USE carry GLOBAL? am I inside a WHEN phrase of an exception-checking PERFORM?* — is implemented once, for
RESUME, and never wired to EXIT or GOBACK, **although all three verbs are bound in the same two files and the
machinery sits within sixty lines of the unchecked sites.**

`EcBinder.BindResume` already does the whole job:
`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/EcBinder.cs:104` tests `ctx.EcState.InF3When`, `:113` does the
declarative-range lookup (`ctx.Table.Declaratives.FirstOrDefault(d => ctx.BindCursor >= d.StartPc && ctx.BindCursor <= d.EndPc)`),
`:118` raises COBOLNET0712 for the declarative-or-WHEN placement rule, and `:124-126` tests `decl.Global` and
raises COBOLNET0713 for the GLOBAL-phrase rule.

Ten lines further down the same file, `EcBinder.EcBindRaising` (`EcBinder.cs:163`) returns
`new BoundRaising(null, IsLast: true, Fatal: false, Enabled: true)` for the LAST form **with no context test at
all**. And `ControlFlowBinder.BindExit`'s PROGRAM arm
(`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/ControlFlowBinder.cs:243-257`) tests only `host.InMethod`
(`:245`) — never `decl.Global`.

Because `EcBindRaising` is shared, the SR6 gap reaches GOBACK too: 14.9.18.3 SR5 states the same rule for
GOBACK and is equally unenforced. 14.9.18.3 SR1 is the GOBACK twin of SR2.

## 2. The rules, quoted, each `--check`ed on this tree

    python scripts/spec/cite.py --check 14.9.14.3 "The EXIT statement shall not be specified in a declarative procedure for which the GLOBAL phrase is specified in the associated USE statement"
      -> OK  §14.9.14.3 2)  (Syntax rules)
    python scripts/spec/cite.py --check 14.9.14.3 "The LAST phrase may be specified only in a declarative procedure or a WHEN phrase in a PERFORM statement"
      -> OK  §14.9.14.3 6)  (Syntax rules)
    python scripts/spec/cite.py --check 14.9.18.3 "The GOBACK statement shall not be specified in a declarative procedure for which the GLOBAL phrase is specified"
      -> OK  §14.9.18.3 1)  (Syntax rules)
    python scripts/spec/cite.py --check 14.9.18.3 "The LAST phrase may be specified only in a declarative procedure or WHEN phrase of a PERFORM statement"
      -> OK  §14.9.18.3 5)  (Syntax rules)

Note the GOBACK pair is worded *almost* identically to the EXIT pair but not byte-identically ("or WHEN phrase
of a PERFORM statement" against "or a WHEN phrase in a PERFORM statement"), so each of the four fragments above
was checked against its own clause. A fixer must not assume one quotation covers both verbs.

## 3. Expected vs observed — RE-MEASURED ON HEAD (89044aa0), both rules and both controls

**SR2 — EXIT PROGRAM in a GLOBAL declarative.** The probe's DECLARATIVES hold
`USE GLOBAL AFTER STANDARD ERROR PROCEDURE ON F` and its declarative paragraph D1-P executes EXIT PROGRAM.

    $ cobol.exe sr2-exit-global-decl.cob --std 2023
      sr2-exit-global-decl.cob(27,12): warning COBOLNET0903: the EXIT PROGRAM statement is obsolete as of
      COBOL-2023 ... (warning only, the element remains conforming)                               [exit 0]

    $ cobol.exe sr2b-resume-global-decl.cob --std 2023      # byte-identical, RESUME AT NEXT STATEMENT substituted
      sr2b-resume-global-decl.cob(24,12): error COBOLNET0713: RESUME shall not be specified in a declarative
      procedure whose USE statement carries the GLOBAL phrase (ISO §14.9.33.3 SR2)                [exit 70]

Expected: REJECTED. Observed: accepted, with only the archaic warning. **The control is the proof**: the same
program with one verb swapped IS rejected, so the declarative-range lookup and the `Global` flag are present in
the same file and are simply not consulted by the EXIT path.

**SR6 — RAISING LAST EXCEPTION outside a declarative and outside a WHEN phrase.**

    $ cobol.exe sr6-raising-last-outside.cob --std 2023     # EXIT PROGRAM RAISING LAST EXCEPTION in an ordinary paragraph
      sr6-raising-last-outside.cob(10,12): warning COBOLNET0903: ... (warning only)               [exit 0]

    $ cobol.exe sr6b-goback-raising-last-outside.cob --std 2023   # the GOBACK twin (§14.9.18.3 SR5)
      (no output — exit 0)

Expected: both REJECTED. Observed: both accepted, and the accepted EXIT form emits a live
`ExceptionState.SetPropagatingLast()` under the `__asCalled` guard
(`src/Cobol.Net.Compiler/CodeGen/Verbs/CallEmitter.cs:627`) — so the illegal statement is not merely
tolerated, it is compiled into working code that stages a propagating exception the standard says may not be
staged from there. RESUME's identical "declarative or WHEN only" rule IS enforced as COBOLNET0712, which is the
same one-rule-two-subjects split as SR2.

## 4. The code site and the shape of the repair

- `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/ControlFlowBinder.cs:243-257` — the PROGRAM arm, no
  `decl.Global` test.
- `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/EcBinder.cs:163` — `EcBindRaising`'s LAST return, no context
  test.
- The working twin: `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/EcBinder.cs:98-143` (`BindResume`), whose
  `:104` / `:113` / `:118` / `:124` are the four pieces every placement rule needs.

**⛔ FIXING THIS AS TWO MORE `if`s IS THE WRONG ANSWER.** There are now at least five placement rules over three
verbs (14.9.14.3 SR2, SR6, SR7, SR8; 14.9.18.3 SR1, SR5; 14.9.33.3 SR1, SR2) and each one is re-deriving "where
am I bound?" from `ctx.BindCursor` by hand — or, more often, not deriving it at all. Per CLAUDE.md rule 5 the
shape that makes the next case automatic is **one context probe** that every placement rule consults:

    ctx.BindingContext  ->  { InDeclarative: decl?, DeclarativeIsGlobal: bool, InF3When: bool,
                              InInlinePerform: bool, SourceElementKind: program|function|method|prototype }

computed once at the bind cursor, with the four verbs asking it instead of each reaching into
`ctx.Table.Declaratives` themselves. That probe also answers PB403's SR8 (`InInlinePerform`) and its SR7
(`SourceElementKind`), which is why the two notes should be landed together — and it should carry a drift test
that enumerates the placement rules and asserts each one has an asker, so a sixth rule cannot be added with no
enforcement and no one noticing.

## 5. The sibling sweep the fixer must do

- **GOBACK is not optional here.** 14.9.18.3 SR1 and SR5 state the same two rules; the SR6 half is literally
  the same code path (`EcBindRaising` serves both verbs), so a fix that names only EXIT leaves half the defect
  in place while the note reads closed. The b2 sweep control `sr6b-goback-raising-last-outside` exists for
  exactly this.
- **Every other statement with a declarative-placement rule** — grep the SRs for "declarative procedure" and
  check each has an asker. `STOP RUN`, `ALTER` and the USE family all have placement constraints.
- **The GLOBAL declarative's dynamic-vs-static split.** `BindResume`'s comment records that a RESUME executed
  within a global declarative's DYNAMIC scope is CONTINUE (GR1) while the STATIC case rejects. Whatever the
  EXIT/GOBACK rules require, the fix must not accidentally import RESUME's GR1 semantics — 14.9.14.3 SR2 is a
  flat prohibition with no dynamic arm.
- **COBOLNET0712 / 0713 are RESUME-worded.** The diagnostics name RESUME and cite 14.9.33.3; EXIT and GOBACK
  need their own messages citing their own clauses, or the user is told about the wrong statement.

## 6. Rows

- **`SR-14.9.14.3-2`** (NOT-IMPLEMENTED) — measured above, with the RESUME control proving the machinery exists
  and is unwired. Editions: EXIT PROGRAM and USE ... GLOBAL are in every edition.
- **`SR-14.9.14.3-6`** (NOT-IMPLEMENTED) — measured above, with the GOBACK twin showing the shared binder
  carries the gap to a second verb. Editions: the RAISING phrase arrives with the 2002 exception model, so this
  rule spans 2002/2014/2023 and not 1985.

Severity is MINOR because neither rule changes what a CONFORMING program does — both are missed diagnostics on
non-conforming source. It is filed anyway because the enforcement machinery already exists ten lines away, and
because the SR6 gap compiles illegal source into a live exception-staging call rather than into nothing.
