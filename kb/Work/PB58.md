# PB58 — OPEN — the intrinsic argument screen cannot express width/integrality/value-domain/cross-arg/strong-type predicates

> ⚙ **flags:** under-rejects · **41 inventory rows** (triage 2026-08-09, probe+refute confirmed; the
> per-row mechanisms live in the triage record and each row's inventory notes)

> **THE SHAPE, not forty instances:** `IntrinsicArgumentRules.Verified` is a per-position CLASS table,
> and the triage measured five predicate kinds the standard's argument rules need that a class column
> structurally cannot carry — MINIMUM WIDTH (SS15.57.3 r1, SS15.78.3 r1), INTEGRALITY of a computed
> operand (the PB40 arm reads a data item's declared scale and never sees `BoundComputedOperand`),
> VALUE DOMAIN (SS15.13.3 r2), STRONG-TYPE exclusion (ORD-MAX/MIN group items), and CROSS-ARGUMENT
> agreement (PB31's `CrossArgRule.AllSameClass` was wired onto MAX/MIN only — the two-arm-dispatch scar
> again, on ORD-MAX/ORD-MIN). Plus WHOLE FUNCTIONS with no row at all (the date family, NUMVAL/NUMVAL-F,
> CONVERT, CONCAT), so `CheckArgumentClasses` returns at the `Verified.TryGetValue` guard and screens
> nothing for them.
> **The fix is the table's SHAPE** (feedback_model_the_rule_shape_not_one_case): the schema row becomes a
> predicate LIST per position plus cross-arg rules, populated from the SS15.3 argument-type taxonomy, with
> a drift guard asserting every catalogued function HAS a row — the absent-row class dies structurally.
> Mostly under-rejection (illegal source accepted; EC latitude unexercised); no wrong answers on legal
> programs, which is why this ranks below the wrong-answer clusters.
