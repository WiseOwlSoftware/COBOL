# PB4384 - a semicolon inside an embedded block is still judged as COBOL

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/EmbeddedBlockReading.cs` (`EmbeddedBlockReading.Read`, `EmbeddedBlockReading.Scan`, new, replacing `Block`; `EmbeddedBlockReading.Message`, `EmbeddedBlockReading.Report`), `src/WiseOwl.Cobol.Frontend/Parsing/ProgramText.cs` (`ProgramText.Holds`, now the one test `Read` asks of a block's tokens), `src/WiseOwl.Cobol.Frontend/Diagnostics/DiagnosticDescriptors.cs` (`DiagnosticDescriptors.COBOL5842`, new), `src/WiseOwl.Cobol.Editions/Diagnostics/DiagnosticCatalog.cs` (`DiagnosticCatalog.UnterminatedEmbeddedBlock`, new), `tests/WiseOwl.Cobol.Tests.Unit/EmbeddedPrecompilerBlockTests.cs`, `conformance-suite/wiseowl/cases/4.2.10-Nonstandard-extensions/pb4381-exec-sql-block-unterminated.cob`, `conformance-suite/wiseowl/diagnostics/pb4381-exec-sql-block-unterminated.json`, `conformance-suite/wiseowl/cases/4.2.10-Nonstandard-extensions/pb4384-exec-sql-semicolon-in-block.cob`, `conformance-suite/wiseowl/diagnostics/pb4384-exec-sql-semicolon-in-block.json`, `docs/CONFORMANCE.md` (section 3.2, item 4), `docs/rearchitecture/DESIGN-frontend-grammar.md` (section 3.9), `docs/manual/migrating.md`.

**Read at:** commit a4f54e0a4 (tip of `worktree-wf_ca25d124-0aa-10`, PR #971); not on main 4aff86e01 yet.

The lexer rule `SEMICOLON : ';' -> channel(HIDDEN)` puts a semicolon with no space after it on the HIDDEN channel precisely so `SeparatorRule.Violations` can judge it (section 8.3.5 separator rules). `Read` skips every non-default token of a block, so that semicolon keeps channel HIDDEN, `ProgramText.Holds` is true for it, and `Violations` judges SQL text as COBOL. That contradicts `docs/CONFORMANCE.md` 3.2 item 4 and DESIGN-frontend-grammar 3.9 (a block's text draws no COBOL diagnostic of its own). What the user sees: a separator diagnostic on a `;` inside `EXEC SQL ... END-EXEC`. The code path was verified by reading; the exact code and text were not probed, so the implementer writes the repro first (for example `EXEC SQL SELECT A;B INTO :W-H FROM T END-EXEC.`).

Fix direction: move every token of a block, whatever its channel, onto `EMBEDDED_BLOCK_TEXT`, with a unit row for the semicolon.

Grepped `kb/Work`: no note covers it.

## Landed

`EmbeddedBlockReading.Read` now moves every token of a block that `ProgramText.Holds` (the program's COBOL text), whatever
its channel, to `EMBEDDED_BLOCK_TEXT`; a token already off the COBOL text (an absent debugging line) stays. The probe
`EXEC SQL SELECT A;B INTO :W-H FROM T END-EXEC.` drew COBOL2631 beside COBOL5818 and now draws COBOL5818 only
(`EmbeddedPrecompilerBlockTests.ASemicolonInsideABlock_DrawsNoSeparatorDiagnostic`).
