# PB3156 — an untracked named stage: LENGTH of a bit group with an ALIGNED ODO table

Filed by the clerk from the enqueue unit's review r1 of 07e9d546f (2026-10-14), new defect 3 in
`E:\COBOL-coord\scratch\reports\w1076a-PB2921-report.md` (items 1 and 2 of that section are PB3153 and PB3154).

**Mechanism.** FUNCTION LENGTH of a GROUP-USAGE BIT group that holds an ALIGNED OCCURS DEPENDING table is refused with the
stage "the ALIGNED OCCURS DEPENDING table '<name>' of a bit group — its occurrences are padded to whole bytes, which a
boolean-position count cannot state". Legal source is rejected, loudly.
**Site.** `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs` ~:2504, the
`bitPositions && strideBits != BitLayout.WidthBits(c)` arm.

**Rule.** §15.50.4 rule 1), checked with `cite.py --check 15.50.4 "boolean positions"` (OK): "If argument-1 is a bit group
item, an elementary boolean data item, a boolean literal, or a type declaration for a boolean item, the returned value is an
integer equal to the length of argument-1 in boolean positions". The answer for an ALIGNED table whose occurrences are padded
to whole bytes still has to be derived from that rule and the §8.5.1.6.3 layout before the stage is closed.

**Relations.** PB2498 (landed) closed the unaligned ODO tables of bit elements at LENGTH and left this ALIGNED shape a named
stage on purpose (its body, ~line 53). PB573 (open: ALIGNED has no grammar rule) is related but a different mechanism.
No open note owned this stage (grepped kb/Work).

**Test pin.** `IntrinsicFunctionDifferentialTests.StagedLoudResidue_FailsLoud_NeverWrong` pins this stage as its loud residue
(once branch worktree-wf_d289834a-bf8-1, PR #60, lands). Closing the stage moves that test: it must be re-pointed at the
remaining residue, or retired if none is left.

**Inventory rows.** Not named: the row this stage holds open could not be identified with certainty, so `inventory_rows` is
empty. Do not guess one; the implementer names it when the stage closes.

## Landed 2026-10-14 (w1077 D)

Re-probed on a fresh build: `FUNCTION LENGTH(BG)` of `01 BG GROUP-USAGE BIT. 05 BA PIC 1 USAGE BIT. 05 TA PIC 1(3) USAGE BIT
ALIGNED OCCURS 1 TO 4 DEPENDING ON N.` staged COBOL1756 (BYTE-LENGTH answered 3). The stage was one symptom of ONE rule
missing from the layout model: the extent of n occurrences of an ALIGNED table is `stride × (n − 1) + width` (§13.18.1.4 GR2:
every occurrence starts a byte; §8.5.1.6.3: filler only "as needed to advance alignment ... for the next item", and the last
occurrence has no next one), and it was spelled three times (`BitLayout.RunBits`, `FileModel.MinExtent`,
`SequentialIoEmitter.OdoRecordExceedsMaximum`) while the OCCURS DEPENDING readers counted `count × stride`. It is
`BitLayout.TableBits` now, read by all three; `BitLayout.TrailingFillerBits` is the padding `OdoGeometry.TrailingUnits` /
`BoundOdoExtent.TrailingWidth` give back once an occurrence exists (`CobolTable.OdoExtentTrimmed`, new in the runtime
surface), and the stage is deleted: LENGTH is 8 / 11 / 19 / 35 positions at 0 / 1 / 2 / 4 occurrences, equal to the fixed
twin at the same count.
Found in the same files and fixed with it (I9), the same rule in the sibling arms: the record struct's `AsBits()`,
`FromBits`, `AsImage()`, `FromImage` and the Tier-B image seed laid an ALIGNED table's occurrences one WIDTH apart instead
of one STRIDE (`GroupImageCodec.BitCarrierOf` / `EmitRunMemberFromBits` / `InitialBitCarrierOf`; the Tier-B window lane and
the VALUE slicer already used the stride), so `DISPLAY` of a bit group holding `OCCURS 2 ... ALIGNED` printed 14 positions
where its LENGTH is 19, `MOVE` of two ALIGNED-ODO bit groups threw `ArgumentOutOfRangeException`, and a table VALUE seeded
the wrong bytes behind a REDEFINES. `CobolBits.Strided` (new) pads every occurrence but the last. Golden
`2002/pb3156_aligned_odo_bit_table_extent` (LENGTH, BYTE-LENGTH, the fixed twin, DISPLAY, a group MOVE, the alphanumeric
group's image, the seeded VALUE); unit `AlignedBitTableExtentDriftTests`. No negative golden: the change removes a refusal and
adds none. `IntrinsicFunctionDifferentialTests.StagedLoudResidue_FailsLoud_NeverWrong` pinned this stage and no residue
remains, so it is retired into `ByteLengthOfARefModArgument_IsTheWindowLength` (its first half, now a positive test); the
§1.4 doctrine's pin is `BoundDeferralDriftTests.GenuineDeferral_StillCompiles_AndAnnounces`.
Left open and reported as a lead (not this mechanism): an ALIGNED item inside a bit group that itself starts MID-byte is
aligned relative to the group's start, not to a byte of the record (`BitLayout.Walk`), so §13.18.1.4 GR1 is not met there.
