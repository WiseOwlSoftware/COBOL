# PB5764 - no recursive delete of a variable path; one tracked tool runs a probe in a fresh directory

**What is wrong.** A read-only agent that probes the compiler (a code reader, a witness writer, a refuter, an
adjudicator) and an integrator that validates drafts each need to run a COBOL program in a directory that holds
nothing from an earlier run: a file the program wrote last time changes what an OPEN or a READ does this time. The
briefs say only "in a run directory of your own". So each agent writes its own reset, and they converge on
`rd=$R/$id; rm -rf "$rd"; mkdir -p "$rd"; cp ...; cd "$rd"`. Examples from one lane on 2026-11-15
(`E:/COBOL-coord/scratch/gl1985/lane1/run/`): `g1985b-viii-1-3-language-concepts/run.sh:6` (`rm -rf "$R/$id"`),
`g1985-viii-4-7-start/run.sh:5` (`rm -rf $B/$id`, unquoted), `g1985-ix-1-3-language-concepts/runone.sh:5`,
`g1985b-ix-4-4-open/run.sh:4`, `g1985b-vii-4-3-open/gen/run.sh:5`, and `my-20261115/open20/runcase.sh:5`.

**The harm.** When a variable in the path is empty the command is `rm -rf /<id>` or `rm -rf /`. The harness sees it
and raises "Dangerous rm operation on possibly-empty variable path" to the owner each time; with fleets of forty
agents that is a stream of warnings, and behind the warning is a real way to lose a tree or a disk.

**Also seen the same day, the same root (no tool, so each agent improvises):** the compiler writes its output beside
the source, so an agent that runs a suite case where it lies leaves `.dll`, `.g.cs`, `runtimeconfig.json` and the
program's data files in a git tree (47 untracked files in `E:/COBOL/conformance-suite/cases` on 2026-11-15 morning;
38 in `E:/COBOL-wt/gl1985-tree-a/conformance-suite` the same evening, removed by the agent that made them).

**Stopgap in force (scratch, not tracked):** `E:/COBOL-coord/scratch/gl1985/run_case.py` and the never-delete
paragraph in `E:/COBOL-coord/scratch/gl1985/wf_lane1_draft_1985.js` and `integrator-brief-1985.md`.

**Fix direction.** One tracked tool that runs a program on a named compiler in a NEW directory outside every git
tree and deletes nothing; one practice for all roles (no recursive delete of a path that holds a variable; a probe
runs through the tool); the guard hook refuses the command with the reason and the alternative, so the agent is
taught before the owner is warned; every template and brief that tells an agent to run a program names the tool.
