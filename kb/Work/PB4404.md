# PB4404 — a C# test keeps four orchestrator files in the code lane

**Sites:** `tests/WiseOwl.Cobol.Tests.Unit/ArchReviewFleetDriftTests.cs` (`ArchReviewFleetDriftTests.EachFleetInstrument_PassesItsSelfTest`), `scripts/self_test_arms.py` (`DECLARED`).

`tests/WiseOwl.Cobol.Tests.Unit/ArchReviewFleetDriftTests.cs:39-48`, `EachFleetInstrument_PassesItsSelfTest`, runs
`r2_inputs.py`, `r2_collect.py`, `r2_cost.py` and `file_census_notes.py` with `--self-test` from the compiler's Unit
assembly. `inert_lane.code_readers` therefore counts those scripts, and what they import, as read by compiler tests:
through `r2_inputs.py` and `r2_cost.py` that is `scripts/orchestrator/coord.py`, `budget.py`, `model_rules.json` and the
telemetry modules. A change to any of them runs the full code lane (build plus Unit) instead of the tooling lane, which
is the cost PB4395 item 1 removed for the other pipeline classes.

**Fix.** Move this theory into the script self-test runner the way PB4395 moved the others: each R2 instrument's
self-test is declared to the runner (and its arms to `self_test_arms.py`), and the C# method is deleted. The rest of
`ArchReviewFleetDriftTests` (the `.claude/agents/*.md` checks PB3776 and PB3781 rely on) stays only if it reads no
`scripts/` file; otherwise it moves too. Acceptance: `inert_lane.py classify` on a planted change to
`scripts/orchestrator/budget.py` answers `lane=tooling`.
