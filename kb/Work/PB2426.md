**Found by:** the R1 (PB2118) landing brief. `gen_ledger.py` (`TREND`, the append at its `write_text`) adds one point
per GAP-moving landing and one `program` point to `docs/rearchitecture/evidence/ledger-trend.json`. The operator renders
the ledger from the main checkout after every landing (owner 2026-10-04), so main's working tree carries an uncommitted
change to a tracked file between landings. On 2026-10-07 it held four points (e68c3365, 24a007fe, 42a68e20 and the
program point 37f2b131) that no commit carried; the R1 landing merged them into its branch by hand.

**Harm:** a dirty tracked file in main's checkout blocks `git pull`/rebase there, a frozen-evidence series loses points
if the checkout is reset, and a branch that commits the file picks up points it did not measure.

**Fix direction (rule 5):** one of two shapes, chosen by the implementer and recorded in DESIGN-orchestrator-loop:
(a) the series lives in the coordination directory (it is the publish's state, not the product's), with the tracked
file retired; or (b) the publish commits the new points through a branch and `push-main.sh`. A test asserts a render in
a clean checkout leaves `git status` clean.
