# PB2618 — STRING INTO a property loses the untouched positions

## Landed (wave 1052, group C)

**Re-probed** on base `471d0e954`: `E:\COBOL-coord\scratch\w1039a2\p\p13.cob` printed `A1=0001/Q      A2=0001/ABCDEF`.
**Adjudication (the note's first question):** GR7's "data that was present before" is the property's value, so a
position that stores only PART of the item gets the GET first. Whether such a position is a sending use (SR3 would then
refuse a WITH NO GET property) is not stated; STRING's identifier-3 is "the receiving operand" (§14.9.43.3 SR10) and a
STRING into a WITH NO GET property was accepted by kb/Work PB1275, so it stays accepted and the receiving temporary
starts as spaces there. Recorded as `docs/CONFORMANCE.md` D-PROP1.
**Mechanism (two arms of one rule):** `BoundStores.StoreKind` gained `WriteInPart` (get when the class has one, set
after). Arm 1: `Visit(BoundStringStmt)` answers it for INTO (the POINTER stays ReadWrite). Arm 2, found by the sibling
sweep: a store through a reference-modified receiver (`MOVE "Q" TO NM OF D(1:1)`) replaced the whole property the same
way (§8.4.3.3.4 GR5 "a unique data item that is a subset"); `StoreKindVisitor.Hit` notes a store through a window
(`Place.DenotedItem` null) once, for every whole-receiver arm, present and future, and `StoreKindOf` promotes `Write` to
`WriteInPart`. `OoBinder.OoWrapPropertyOps` takes the GET for `WriteInPart` when `op.Get` exists and no longer refuses a
missing one. **Witnesses:** `conformance:2002/pb2618_string_into_property_keeps_unreferenced` (four lines, derived),
`conformance:negative/pb2618-string-into-property-no-set` (SR4: a partial store is still a receiving use).

## Landing

- `src/Cobol.Net.Compiler/Binding/Bound/BoundStores.cs#StoreKindOf` and `StoreKindVisitor.Hit` - the polarity a statement
  gives a property temp; a new bound statement's store arm is automatically `WriteInPart` through a reference-modified
  window because every arm asks `Hit`. REUSE `Hit`/`TargetHit`/`ReceiversHit`; never test `p.Item` directly in an arm.
  Trap: STRING's identifier-3 cannot be reference-modified (SR4, COBOLNET1651), so the STRING arm needs its own answer.
- `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/OoBinder.cs#OoWrapPropertyOps` - `needGet` is true for `WriteInPart`
  only when `op.Get` exists (a missing GET is not refused there: the position is receiving, SR10); `needSet` is every
  kind but `None`. The GET rides in `open`, so a claimed receiver's bracket places it with the identification.
- `docs/CONFORMANCE.md` D-PROP1 records the determination (GET for the kept positions; WITH NO GET stays accepted).
