# PB2618 — STRING INTO a property loses the untouched positions

Filed by the train 1039b lander from the wave-1039 group A2 implementer report (`w1039a2-PB2078-report.md`, "Lead
(adjudication)"), re-run on train 1039b's build. It shares no root with PB2078.

**Rule.** §14.9.43.4 7): "At the end of execution of the STRING statement, only the portion of the data item
referenced by identifier-3 that was referenced during the execution of the STRING statement is changed"
(`cite.py --check` OK). PB1275 read §14.9.43.3 SR10 and §8.4.3.9.4 GR2 as making a STRING receiver a RECEIVING-only
property reference, so no GET is made: the temporary that the SET method receives starts as spaces, not as the
property's value, and GR7's "data that was present before" is lost.

**Adjudication needed first.** Whether a receiving-only property reference in STRING has a "present" value for GR7
(a GET before the statement), or whether §8.4.3.9.4 makes the whole temporary the receiving item (the current
output). The answer decides the fix; record it in docs/CONFORMANCE.md either way.

**Repro.** `E:\COBOL-coord\scratch\w1039a2\p\p13.cob` (copy in `E:\COBOL-coord\scratch\train1039b\leads\`): class PQC
with `01 NM PIC X(6) VALUE "ABCDEF" PROPERTY`; `STRING "Q" DELIMITED BY SIZE INTO NM OF D`. Train 1039b's build:
`I=1 A1=0001/Q      A2=0001/ABCDEF`; GR7 read literally gives `A1=0001/QBCDEF`.

**Code site.** `src/Cobol.Net.Compiler/Binding/Bound/BoundStores.cs#Visit(BoundStringStmt)` (the receiver's
store polarity), with `OoBinder.OoWrapPropertyOps` (whether a GET precedes the SET).
