## Measured (adjudicator / refuter evidence, verbatim)
### GR-14.9.22.4-2 (PARTIAL)
|| REFUTED: PARTIAL — GR2 a) requires identifier-2 to be UNCHANGED when identifier-1 is zero-length, and c) requires control to go straight to the end of the statement. The implementation has no zero-length short-circuit. It still runs the counter store counter := counter + 0 (ArithmeticEmitter.StoreArith through CobolNum.Store/FormatImage), and that store rewrites identifier-2 whenever its content is not already in canonical form. The adjudicator probed only a canonical counter (PIC 99 VALUE 7), where adding 0 happens to leave the value alone. Identifier-1 unchanged (half a) and no EC set (half b) were confirmed. Identifier-2 unchanged fails for a non-canonical counter, so the rule is PARTIAL, and in fact a defect for that shape.
- **Code location (record):** src/Cobol.Net.Compiler/CodeGen/Verbs/InspectEmitter.cs#Emit; src/Cobol.Net.Runtime/Verbs/CobolInspect.cs#Tally; src/Cobol.Net.Runtime/Verbs/CobolInspect.cs#Replace; src/Cobol.Net.Runtime/Verbs/CobolInspect.cs#Convert

### GR-14.9.22.4-4 (DIVERGES)
|| REFUTED: DIVERGES — Two arms of GR4 are wrong. (1) GR4c + Table 2 (8.5.2.1): a numeric-edited item with USAGE NATIONAL is class national and is inspected as category national. The binder classes it as alphanumeric instead. The legal INSPECT NE TALLYING C FOR ALL N" " is REJECTED with COBOLNET2306 (SR4 class mixing), and the SR4-violating alphanumeric literal " " is accepted. (2) GR4d, second sentence: the original sign is not kept when the replaced digit image becomes zero. EmitStore re-signs with (Read(p)<0 ? -mag : mag), and -0 collapses to +0 in both the native arm and the string-stored arm. A negative item loses its sign. The other arms work: GR4a, GR4b, the de-signed read of identifier-1 and identifier-3, and a nonzero result's sign.
- **Code location (record):** src/Cobol.Net.Compiler/CodeGen/Verbs/InspectEmitter.cs#Emit; src/Cobol.Net.Compiler/CodeGen/Verbs/InspectEmitter.cs#EmitStore; src/Cobol.Net.Compiler/CodeGen/Verbs/InspectEmitter.cs#OperandTextOf; src/Cobol.Net.Compiler/CodeGen/Emit/OperandText.cs#AsString

### GR-14.9.22.4-20 (PARTIAL)
|| REFUTED: PARTIAL — GR20 makes a format 4 behave as a format 2 with one ALL c BY d pair per character. The per-character map in CobolInspect.Convert is right for alphanumeric and national ELEMENTARY items and for alphanumeric groups. W1 PIC N(5) and W2 alphanumeric group GA both give 'ZZYZZ'. The BEFORE delimiter case W4 gives 'XYCABC'. The duplicate-from case W5 gives 'XYCXYC'. A plain figurative TO QUOTE, W3, expands correctly. Two shapes fail. (1) A NATIONAL GROUP identifier-1 (GROUP-USAGE NATIONAL, which SR1 allows) is CORRUPTED. On a fixed 5-occurrence national group, CONVERTING N"A" TO N"Z" gives '婚婚娠††' where 'ZZZZZ' is expected. On a national ODO group the live positions become mojibake. The emitter stores the converted UTF-16 character string through the group byte-image path (GF.FromImage(__ins) / SpliceInto(GN.AsImage(), ...)). REPLACING corrupts the same way (X3), so the defect is in the shared store; the format 2 equivalence holds, but its result is wrong. (2) A figurative constant beginning with ALL is legal as literal-5: SR3 bars ALL only for literals 1-4, and GR22 sizes a figurative literal-5 to literal-4. The binder still rejects 'CONVERTING "ABC" TO ALL "Q"' with COBOLNET1757, so that legal format 4 source never executes. The claim that a figurative literal-5 is expanded at bind time holds only for the non-ALL figuratives.
- **Code location (record):** src/Cobol.Net.Runtime/Verbs/CobolInspect.cs#Convert; src/Cobol.Net.Compiler/Binding/Procedure/Verbs/InspectBinder.cs#BindPhraseOperands

## Landed — the sign arm (wave 1018 B, 2026-10-04)

**The data-model decision the earlier waves left open was the second option they named: INSPECT's signed numeric
identifier-1 goes through the character image.** `UsageCollectionPass.Visit(BoundInspect)` marks the target of a
REPLACING or CONVERTING as a character channel, so a numeric DISPLAY / NATIONAL elementary identifier-1 INSPECT writes
into is character-image stored (the same promotion STRING's receiver and a MOVE-through-image already take); a native
`long` is never asked to hold a negative zero. `InspectEmitter.EmitStore` then re-signs the replaced digit run with
`CobolNum.RetainSign(digits, current, profile)`, which reads the ORIGINAL image's sign apart from the magnitude
(`ImageIsNegative`) and formats the signed image in the item's own sign convention (separate leading / trailing,
overpunch, binary minus) through the new `FormatDisplaySigned(unscaled, neg, receiver)` overload — the one way to write
a negative zero. The native `Read(p) < 0 ? -mag : mag` arm survives for ONE shape only, an OCCURS DYNAMIC element
(`DynTablePlace`), which no character channel promotes because it is a typed member of its `CobolDynTable<T>`; any
other numeric elementary item that reaches the store unpromoted throws, so a new shape cannot silently fall back to the
value carrier. The dynamic element's negative-zero residual is `kb/Work/PB2004`.

**Train 1018 lander review:** the first version of this arm threw for the dynamic element too, so `INSPECT DT(I)
REPLACING ALL "5" BY "7"` over `05 DT PIC 9(3) OCCURS DYNAMIC` CRASHED the compiler ("numeric item stored natively"),
where main printed `107`. The lander restored the native arm for `DynTablePlace` alone and added the regression golden
`conformance:2014/pb1128_inspect_dynamic_table_element` (a signed member, an unsigned member and an elementary
dynamic element; `X=-107 Y=107 D=138`).

Witness `conformance:85/pb1128_inspect_signed_sign_retained` (S1 trailing separate -5 → `000-`; S2 leading separate →
`-000`; S3 a positive item keeps `+`; S4 -57 with 5 → 1 → `017-`; S5 the default overpunch `-5` → `00}`). The citation
`cite.py --check 14.9.22.4 "the original value of the sign is retained upon completion of the INSPECT statement"` → OK
§14.9.22.4 4) d); the overpunch code is implementor-defined (§13.18.52.4 4), `cite.py --check 13.18.52.4 "Neither the
representation nor the position of that operational sign"` → OK), so S5 documents this compiler's EBCDIC-style zone.
Row GR-14.9.22.4-4 → CONFORMS (batch `w1018b-pb1128-pb1123`). The predecessor's ungated checkpoint
(`worktree-wf_a4d90677-e09-2` @`32c796d21`) was cherry-picked, not merged.
