# PB3848 — inventory notes name grammar rules PB3830 deleted

**Sites:** `tests/version-matrix/traceability-inventory.json#GR-14.5.3.2-2`, `#GR-14.5.3.3-2`, `#GR-14.5.3.3-4`,
`#SR-14.9.2.3-5`, `#SR-14.9.30.3-9`, `#GR-14.9.30.4-19`, `#SR-14.9.51.3-2`, `#FMT-14.9.10.2`, `#FMT-14.9.26.2`,
`#FMT-14.9.44.2` (changed through the `record_verdicts.py` tool, never by hand), and the 31 further rows the sweep found
(below); `tests/WiseOwl.Cobol.Tests.Unit/SpecTraceabilityInventoryDriftTests.cs#RetiredGrammarRulesNamedInProse`,
`tests/WiseOwl.Cobol.Tests.Unit/SpecTraceabilityInventoryDriftTests.cs#NoRowsProse_NamesAGrammarRule_ARetirementRecordsAsDeleted`

## The defect

PB3830 (wave 20261707 C) replaced every per-statement conditional-phrase rule with the one `conditionalPhrases` rule and
its association predicate, and restated the code-locations of the rows that named the old rules (its
`closes_rows_reason`). The rows' `notes` prose was not restated. On main 38463d537, `arithmeticOnSizeError`,
`readAtEnd` and `writeInvalidKey` appear in no grammar file under `src/WiseOwl.Cobol.Frontend/Grammar/`, yet ten rows' notes
still name them:

| Row | Names |
|---|---|
| GR-14.5.3.2-2, GR-14.5.3.3-2, SR-14.9.2.3-5, FMT-14.9.10.2, FMT-14.9.26.2, FMT-14.9.44.2 | arithmeticOnSizeError |
| GR-14.5.3.3-4 | arithmeticOnSizeError, readAtEnd |
| SR-14.9.30.3-9, GR-14.9.30.4-19 | readAtEnd |
| SR-14.9.51.3-2 | writeInvalidKey |

Measured by matching the three names as whole words in every string field of every row (the report said eight rows).

## Acceptance

- Each row's notes describe the mechanism that exists now (the `conditionalPhrases` rule and
  `ConditionalPhraseAssociation`, as PB3830's own restated rows do), applied as one `record_verdicts.py` batch; verdicts
  and editions unchanged.
- A sweep for every other grammar rule name in inventory prose that no longer exists in the grammar (not only these
  three): either it is restated in the same batch, or this note records the count and why it was left.
- Consider whether a drift test should refuse inventory prose naming a grammar rule that does not exist, so the next
  grammar restructure cannot leave prose behind; if it is added, it lands here.

## Landed (wave 20261764 F)

**Re-probe (main 20fecec14).** The three names appear in no grammar file; matching them as whole words in every string
field of every row finds the same ten rows. Four of them (GR-14.5.3.2-2, GR-14.5.3.3-2, GR-14.5.3.3-4, FMT-14.9.26.2)
name `arithmeticOnSizeError` / `readAtEnd` only INSIDE a `retired-witness:` mark, the recorded history of PB3830's witness
retirement, which stays; their prose already describes `conditionalPhrases`. The other six (SR-14.9.2.3-5, FMT-14.9.10.2,
FMT-14.9.44.2, SR-14.9.30.3-9, GR-14.9.30.4-19, SR-14.9.51.3-2) named the dead rules in PROSE and are restated against the
grammar and binders as they are now (`conditionalPhrases`, `ConditionalPhrases.HasFamily`, `receiversOrSendingOperand`).

**Sweep (acceptance 2).** Every rule name any grammar revision ever declared that the grammar no longer has (177 names
with a capital letter, read from `git log -p -- '*.g4'`) was matched as a whole word against every string field of all
4,214 rows, outside the retirement marks. 24 further rows named such a rule (`addOperandList`, `divideIntoOperand`,
`subtractFromOperand`, `moveSendingOperand`, `startInvalidKeyPhrase`, `occursBound`, `repositoryAsPhrase`,
`subscriptQualification`, `computerAttributes`, `genericClause`, `linkageProcedureParameter` and the rest); the drift test
below found 7 more through lexer tokens (`SUB_HEXLIT`, `SUB_COLON`, `COMMA_SEP`) the camel-case sweep cannot see. All 31
are restated in two `record_verdicts.py` batches (37 rows with the six above; verdicts, editions and witnesses unchanged;
GAP 20 before and after; `audit_witness_loss.py --check` GREEN), so the sweep now finds none. Left, by design: a
single-word rule name (`identifier`, `literal`) cannot be told from the English word and no mechanical sweep covers it;
and line-number citations in older notes (`ArithmeticBinder.cs:94-139`, `lines 29-41`) are another kind of staleness, not
a rule name, so they stay except where they stood beside a dead rule name.

**Drift test (acceptance 3).** `SpecTraceabilityInventoryDriftTests.NoRowsProse_NamesAGrammarRule_ARetirementRecordsAsDeleted`:
a grammar rule or lexer token that any row's `retired-witness: ...g4#Name` mark records, and that no committed `.g4`
mentions in code, may be named in no row's prose. It needs no list of its own: the marks are the record, so the next
restructure that retires a witness cannot leave another row's prose behind. Its first run found the 7 rows above, which
is the evidence it looks; `TheseChecks_ActuallyFail_OnAFabricatedInventory` drives it against planted rows and grammar
(negative, the retiring row's own prose, and four positive controls). Reach: a deleted rule that no row ever cited as a
`.g4#Rule` witness has no mark and is reached only by the one-off history sweep above.

## Landing

- `tests/WiseOwl.Cobol.Tests.Unit/SpecTraceabilityInventoryDriftTests.cs#RetiredGrammarRulesNamedInProse` owns the rule "no row's prose names a grammar symbol a retirement mark records as gone"; reuse `ProseOf`, `CodeText` and `WholeWord` rather than a second prose splitter or word regex.
- `tests/version-matrix/traceability-inventory.json`: restate a row's prose only through `record_verdicts.py`, giving the WHOLE `notes` (marks included): build the record by replacing inside the row's own text and assert each old string occurs exactly once before the first mark.
- Trap: a shell heredoc whose body has a backslash is refused by the hook here; write the script with the Write tool and run it.
