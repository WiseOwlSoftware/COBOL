# PB3848 — inventory notes name grammar rules PB3830 deleted

**Sites:** `tests/version-matrix/traceability-inventory.json#GR-14.5.3.2-2`, `#GR-14.5.3.3-2`, `#GR-14.5.3.3-4`,
`#SR-14.9.2.3-5`, `#SR-14.9.30.3-9`, `#GR-14.9.30.4-19`, `#SR-14.9.51.3-2`, `#FMT-14.9.10.2`, `#FMT-14.9.26.2`,
`#FMT-14.9.44.2` (changed through the `record_verdicts.py` tool, never by hand)

## The defect

PB3830 (wave 20261707 C) replaced every per-statement conditional-phrase rule with the one `conditionalPhrases` rule and
its association predicate, and restated the code-locations of the rows that named the old rules (its
`closes_rows_reason`). The rows' `notes` prose was not restated. On main 38463d537, `arithmeticOnSizeError`,
`readAtEnd` and `writeInvalidKey` appear in no grammar file under `src/WiseOwl.Cobol.Frontend/Grammar/`, yet ten rows' notes
still name them:

| Row | Names |
|---|---|
| GR-14.5.3.2-2, GR-14.5.3.3-2, SR-14.9.2.3-5, FMT-14.9.10.2, FMT-14.9.26.2, FMT-14.9.44.2 | arithmeticOnSizeError |
| GR-14.5.3.3-4 | arithmeticOnSizeError, readAtEnd |
| SR-14.9.30.3-9, GR-14.9.30.4-19 | readAtEnd |
| SR-14.9.51.3-2 | writeInvalidKey |

Measured by matching the three names as whole words in every string field of every row (the report said eight rows).

## Acceptance

- Each row's notes describe the mechanism that exists now (the `conditionalPhrases` rule and
  `ConditionalPhraseAssociation`, as PB3830's own restated rows do), applied as one `record_verdicts.py` batch; verdicts
  and editions unchanged.
- A sweep for every other grammar rule name in inventory prose that no longer exists in the grammar (not only these
  three): either it is restated in the same batch, or this note records the count and why it was left.
- Consider whether a drift test should refuse inventory prose naming a grammar rule that does not exist, so the next
  grammar restructure cannot leave prose behind; if it is added, it lands here.
