# PB308 — the validator that CLAUDE.md rule 1 rests on, failing open twice

CLAUDE.md rule 1: *"A citation you did not run `--check` on is not a citation."* Both defects below make a `--check`
that PASSES worthless in a way the caller cannot see, which is worse than a `--check` that fails.

## Mechanism 1 — an all-punctuation quotation matches everything

```
python scripts/spec/cite.py --check 7.1      "| + | + | - |"   ->  OK   exit 0
python scripts/spec/cite.py --check 3.1      "| + | + | - |"   ->  OK   exit 0
python scripts/spec/cite.py --check 15.43.4  "| + | + | - |"   ->  OK   exit 0
python scripts/spec/cite.py --find           "| + | - |"       ->  matches §1 Scope (and everything after it)
```

`norm()` is `re.sub(r"\s+", " ", re.sub(r"[^\w\s]", " ", s)).strip().lower()` (`scripts/spec/cite.py:49-51`).
`\w` keeps letters, digits and underscore, so a quotation made **entirely** of punctuation and spaces normalizes
to the empty string — and the empty string is a substring of every clause.

**Control, showing the hazard does NOT extend to needles carrying digits** (and correcting the record: the
original report of this defect claimed it fired on the §15.43.4 NOTE-table rows; that claim is FALSE and these
two lines disprove it — no §15.43.4 verdict was ever obtained vacuously):

```
python scripts/spec/cite.py --check 15.43.4 "| S999 | +999 |"  ->  OK   exit 0
python scripts/spec/cite.py --check 7.1     "| S999 | +999 |"  ->  FAIL exit 1
```

`norm('| + | + | - |') == ''` but `norm('| S999 | +999 |') == 's999 999'`. The live shape at risk is a
**Table-8-style all-punctuation row** — Table 8's sign-control column is literally `+`, `-`, `CR`, `DB`, ` ` —
which a golden's header is a plausible place to quote.

**Fix:** fail closed when the normalized needle is empty, on BOTH paths. `--check` exits non-zero with
*"quotation carries no word characters; nothing to match"*; `--find` refuses rather than returning §1.

## Mechanism 2 — an unlettered trailing paragraph inherits the last sub-item letter

```
python scripts/spec/cite.py --check 14.7.7 "The composite of operands is a hypothetical data item resulting from
the superimposition of specified operands in a statement aligned on their decimal points."
   observed:  OK  §14.7.7 2) b)
   correct :  OK  §14.7.7 2)
```

The sentence is General rule 2's own trailing paragraph, not part of sub-item b). It sits at
`specs/ISO_COBOL.md:21869` indented three spaces — the SAME level as `   a)` (`:21853`) and `   b)` (`:21861`)
whose body text is indented six — and it defines a term both sub-items use; b)'s own text ends at *"the composite
of all other operands shall not contain more than 31 digits."* (`:21867`). **The Markdown indentation here is
correct**, so unlike PB309 this is a tracker defect and not a transcription defect: once a lettered sub-item has
been seen, an unlettered trailing paragraph of the parent rule inherits the last letter instead of falling back to
the rule ordinal.

**Fix:** reset the pending sub-item letter when a paragraph at the sub-item's own indentation level carries no
`<letter>)` marker, so such a paragraph reports the bare rule ordinal.

## Why both matter more than their size

The consequence is identical and it is CLAUDE.md rule 1's named failure mode exactly: **`--check` passes on
genuine rule text while returning a sub-ordinal that is wrong**, and the wrong sub-ordinal is what propagates into
goldens, design docs and the DEVLOG. It was caught here only because a refuter re-derived a citation the writer
had already `--check`ed: the golden-lane writer drafted two fixtures citing *"§14.7.7 2) b)"* on the tool's own
say-so.

**Drift tests, and make each fail once before trusting its silence** (`feedback_green_gates_arent_evidence`):
assert that `--check` on a punctuation-only quotation exits non-zero, and pin both `§14.7.7 2)` and
`§14.9.8.4 1) b)` (see PB309) as expected sub-ordinals.
