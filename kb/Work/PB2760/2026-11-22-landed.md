## Landed (wave 20262135, group E)

`CollationRuntime` and `CollationRuntimeStatus` moved from `Collation/CollationRuntime.cs` (namespace
`WiseOwl.Cobol.Runtime.Collation`) to `Control/CollationRuntime.cs` (namespace `WiseOwl.Cobol.Runtime`), the names
kept: the class is the run unit's start-up hook, and every reader (the `COBOL_COLLATION_WARMUP` row, the READMEs,
DESIGN-locale-facility) knows it by that name. Every caller changed in the same commit (RunUnit's constructor,
RuntimeConfig's row path, the three test files, the RunUnitStateDriftTests keys), no forwarder. The namespace change
removes shipped public surface, so the runtime major was bumped (`python scripts/abi_pin.py bump --runtime-major`).

Measured after the move (grep over src/WiseOwl.Cobol.Runtime/Collation/*.cs, the top namespace only): no `using` of
`.Unicode`, `.Unicode.Segmentation` or `.Collation.Locale`, and no type of the root namespace named outside doc
comments, so the `Collation ↔ Runtime`, `Collation ↔ Unicode`, `Collation ↔ Unicode.Segmentation` and
`Collation ↔ Collation.Locale` edges the finding counted are gone. What the finding did not count: `Collation.Locale`
itself reads the run unit (`LocaleManager` → `RunUnit.Current.Locale`, `LocaleConfig` → `LocaleState`), so with the
warm-up now in the root namespace `Runtime ↔ Runtime.Collation.Locale` is a cycle; DESIGN-architecture-review §8.1
records it as one layer (control) by placement, to be placed when the Move waves give `Control/` its namespace.
