# PB1174 — OPEN

## The rule (every citation re-run by the registrar through `cite.py --check`)

> 20) The number of occurrences of table elements referenced by data-name-2 is determined by the rules in the OCCURS clause.

`python scripts/spec/cite.py --check 14.9.40.4 "…"` → `OK  §14.9.40.4 20)  (General rules)`

> 7) The value of the data item referenced by data-name-1 represents the current number of occurrences of the subject of the entry.

`python scripts/spec/cite.py --check 13.18.38.4 "…"` → `OK  §13.18.38.4 7)  (General rules)`

## Finding — `sort-statement-p2` (wrong-answer; rows `GR-14.9.40.4-20`, `GR-14.9.40.4-24`, `GR-14.9.40.4-18`)

**Mechanism.** The Format-2 table SORT sorts the whole PHYSICAL array: EmitTableSort binds `var __ta = <ArrayPath>` (the typed field sized to integer-2) and CobolTable.Sorted/Array.Copy reorder every element, never consulting the OCCURS DEPENDING ON value, so occurrences beyond the table's current count are sorted into it.

**Repro.** 01 N PIC 9 VALUE 5. 01 TBL. 05 ITM PIC 9(2) OCCURS 1 TO 5 TIMES DEPENDING ON N. -- MOVE 30,10,50,05,01 TO ITM(1..5); MOVE 3 TO N; SORT ITM ASCENDING; MOVE 5 TO N; DISPLAY ITM(1..5). (out/probe/sort-statement-p2/podo.cob, pinned cobol.exe, --std 2023)

**Expected from the spec.** 14.9.40.4 GR20 'The number of occurrences of table elements referenced by data-name-2 is determined by the rules in the OCCURS clause' + 13.18.38.4 GR7 'The value of the data item referenced by data-name-1 represents the current number of occurrences of the subject of the entry': only the 3 current occurrences {30,10,50} are sorted -> ITM(1..3) = 10, 30, 50 (occurrences 4..5 are undefined, but can never enter occurrences 1..3).

**Observed / reasoning.** ITM(1..5) = 01, 05, 10, 30, 50: the two values beyond the DEPENDING count were sorted into occurrences 1 and 2 and the real element 50 was pushed out to occurrence 5. Silent; no diagnostic at any stage.

**Code site.** src/Cobol.Net.Compiler/CodeGen/Verbs/SortEmitter.cs#EmitTableSort (the __ta/__ts/Array.Copy lines); src/Cobol.Net.Runtime/Values/Tables/CobolTable.cs#Sorted; src/Cobol.Net.Compiler/Binding/Procedure/Verbs/SortBinder.cs#SortBindTable (BoundTableSort carries no occurrence-count place)

## What the fixer owes

BoundTableSort must carry the table's occurrence-count place (the ODO object, or a dynamic-capacity table's current capacity) and SortEmitter.EmitTableSort must sort only [0, count) — CobolTable.Sorted / Array.Copy over `__ta` today reorder every physical element. Sweep the dynamic-capacity table (OCCURS DYNAMIC) subject and a SEARCH/table-SORT sibling that also reads the physical length. Golden podo.cob at 2002.
