# PB3130 — 58 doc comments carry two `<summary>` elements

Source: wave 1071 (unit `w1071b`, PB546 rounds 1 and 3, lead 1). PB546 is held by its branch and is NOT edited.

**Measured (R2).** A scan of every `///` block under `src/**/*.cs` in the notes worktree (at main `3b1261dfe`) that contains the text `<summary>` more than once finds **58** blocks (script `E:\tmp\pb3126\dsum.py`). First four: `src/Cobol.Net.Compiler/Binding/BinderDriver.cs:287`, `:594`, `src/Cobol.Net.Compiler/Binding/DataBinder.cs:2710`, `:5086`. A second `<summary>` in one doc comment is not what tooling expects (IntelliSense shows one summary); the implementer confirms what Roslyn does with the second one before choosing the drift test's form.

**Fix.** Merge each second `<summary>` into the first as `<para>` (or turn it into `<remarks>`), keeping the text. **Mechanical change: it touches many files, so it must LAND FIRST and ALONE** (the standing "a tree-wide mechanical change lands first" practice), and be paired with a drift test, not a hand-kept list: a Roslyn-based test (documentation mode) failing on a second `SummaryElement` in one doc trivia, or the CS1587/CS1570 family promoted to an error if it covers the case.

**Sweep.** `tests/`, `scripts/` and `docs/`-embedded C# are out of scope here; run the same scan over `tests/**/*.cs`.
