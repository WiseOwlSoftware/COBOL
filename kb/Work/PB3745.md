# PB3745 — wave labels have a date's shape and are written as landing dates

**Sites:** `scripts/orchestrator/plan_wave.py#next_wave`, `scripts/orchestrator/alloc.py` (the `wave` kind, PB3700; PR #576).

The wave label is an allocated serial in the shape YYYYMMDD (20261107, 20261104, from the `wave` kind of `alloc.py`, which replaces `plan_wave.next_wave` in PR #576), but it is not a date: today is 2026-10-25. Agents read it as one and write it into a landing date, as `kb/Work/PB3145.md` and `kb/Work/PB3662.md` did (`Landed (2026-11-04, wave 20261104)`); the clerk corrected those two to the merge's real date (2026-10-24) in the change that filed this note. The wave-E review fixed its own branch's instances.

Fix: give the label a shape that cannot be mistaken for a date (a plain serial, or a prefix such as `w1107`), or have `alloc.py wave` print the rule "a label, not a date" beside the value and have `check_practices.py` refuse a landing paragraph that dates itself from a wave label; sweep the DEVLOG and kb/Work for the same misreading (`Landed (2026-1[12]-`).

(2026-10-25.)
