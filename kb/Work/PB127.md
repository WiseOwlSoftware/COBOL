# PB127

Battery #29's guard-fast leg reported `int_rc=1` — one failure among CobolSharp.Tests.Integration's 504 —
and the log carried ONLY the `Failed!` summary line: both .NET test legs ran `--verbosity quiet` (which
prints no per-test lines) and the report step grepped `Passed!|Failed!|error`. The failing test was
therefore UNNAMEABLE, which the gate discipline forbids ("never call a failure a 'flake' without naming the
test"). A serial re-run of the full suite returned 503/504 green (the one skip is the documented D10 block),
so the red was schedule-dependent — but its name is lost.

**Fix (landed with the battery-29 bookkeeping):** both legs add `--logger "console;verbosity=minimal"` (the
console logger at minimal verbosity prints each failed test's name and message even while the build verbosity
stays quiet), and the report greps widen to carry `[FAIL]`/failed-test lines (tail -6). The next
schedule-dependent red arrives with its name.

**Disposition of the unnamed red itself:** logged as one schedule-dependent failure in the LEGACY integration
suite (the opt-in differential net, deleted at P15), serial re-run green; it cannot be registered as its own
defect without a name — if it recurs, the fixed harness names it and it becomes a note (likely the
process-globals family PB126 documented for the greenfield suite).
