# PB578

## Mechanism
LINAGE-COUNTER's implicit-increment sentence is modelled nowhere and the argument that it is unobservable has a hole: a USE AFTER STANDARD ERROR declarative can read LINAGE-COUNTER mid-statement

### Inventory row `GR-13.18.34.4-L2.1` (PARTIAL)
THE RESET IS IMPLEMENTED AND TESTED; THE IMPLICIT-INCREMENT SENTENCE HAS NO IMPLEMENTATION AND ITS UNOBSERVABILITY IS A DERIVATION WITH A HOLE. Sentence 1 ('automatically reset to one') is the `lines < 0` arm and the named test pins it. Sentence 2 ('during the resetting ... the value of LINAGE-COUNTER is implicitly incremented to exceed the value specified by integer-1') is modelled nowhere: the arm sets EndOfPage = false and returns. The argument that this costs nothing runs: (a) the only consumer of 'exceeds the page size' is 14.9.51 GR26a's page-overflow condition; (b) its observable effects are the reposition-and-reset (already done) and GR6b3's re-evaluation, which GR6b2 already performs on this same arm (:163); (c) its END-OF-PAGE flag cannot be seen, because 14.9.51.3 SR18 forbids ADVANCING PAGE and END-OF-PAGE in one statement and the compiler enforces it (conformance-test:WiseOwl.Cobol.Tests.Conformance.LinageConformanceTests.Sr18_AdvancingPageWithEop_IsRejected). THE HOLE: step (c) assumes no user code observes LINAGE-COUNTER mid-statement, and a USE AFTER STANDARD ERROR declarative entered from inside this WRITE could. That path is currently unreachable only because of a separate defect (p18_use.cob: the declarative never fires), so the derivation rests on a bug rather than on the language. PARTIAL under 'an unverified edge => PARTIAL'; it is a candidate for the PB386 no-observable-obligation close once the EC path exists.

## Landing (2026-10-16, wave 1095 group E)

**The derivation that the implicit increment is unobservable was wrong, and not only at the hole the note named.**
§13.18.34.4 GR7 c) 1 (`cite.py --check 13.18.34.4 "During the resetting of LINAGE-COUNTER to the value one, the value
of LINAGE-COUNTER is implicitly incremented to exceed the value specified by integer-1 or the data item referenced by
data-name-1."` -> OK 7) c) 1.) puts the counter past the page size, which is §14.9.51.4 GR26 a)'s trigger (`"This
occurs when the associated LINAGE-COUNTER is equal to or exceeds the page size."` -> OK 26)); GR27 a) then sets
EC-I-O-EOP-OVERFLOW to exist, and GR28 keeps a NOT END-OF-PAGE imperative from running. Step (c) of the old argument
missed two observers: GR27 a)'s exception condition needs no END-OF-PAGE phrase (a USE AFTER EXCEPTION CONDITION
declarative, an exception-checking PERFORM's WHEN, FUNCTION EXCEPTION-STATUS), and SR18 bars only the AT phrase (SR19
and GR28 name the NOT END-OF-PAGE phrase separately), so `WRITE ... ADVANCING PAGE NOT AT END-OF-PAGE ...` is legal
source - which the compiler REJECTED with COBOL0861.

**Re-probe on this build (before the fix):** the note's own hole no longer reproduced as written - the USE AFTER
STANDARD ERROR declarative fires (p18_use's defect is fixed; `2023/pb526_linage_ec_condition` pins it) and, on a
GR6 b) 2 violation during ADVANCING PAGE, reads LC=000 (GR6 b) 2's value, after the WRITE's own I-O operation). The
EC-I-O-EOP-OVERFLOW observer DID reproduce: no declarative entry after ADVANCING PAGE, and the NOT-only phrase was
refused at bind.

**Fix.** `SequentialConnector.PositionOnLogicalPage`: ADVANCING PAGE (`lines < 0`) joins the page-overflow arm
(`lines < 0 || counter + lines > page body`) - one transition (`BeginNextLogicalPage`), one reset, one
EC-I-O-EOP-OVERFLOW; the separate ADVANCING PAGE arm is gone. `SequentialIoBinder.BindWrite` asks SR18 only when the
AT phrase is present (`PhraseBlocks.HasOnBranch`, the same predicate `FlagConformancePass` uses for "END-OF-PAGE
phrase specified"). Determination: docs/CONFORMANCE.md §4 "WRITE ADVANCING PAGE on a logical page is a page
overflow"; docs/FILES_DESIGN.md's GR26 mapping updated.

**Witnesses.** `85/pb578_advancing_page_overflow_85`, `2002/pb578_advancing_page_eop_overflow`, negative
`pb578-write-advancing-page-at-and-not-eop` (COBOL0861 at every edition), and
`LinageConformanceTests.Sr18_AdvancingPageWithNotEopOnly_IsLegalAndTheEndOfPageConditionOccurs` /
`Sr18_AdvancingPageWithNotFirstEopPair_IsRejected`. Rows: GR-13.18.34.4-7 and GR-8.4.3.14.4-2 PARTIAL -> CONFORMS;
SR-14.9.51.3-18 re-verdicted (still CONFORMS, NOT-only now legal); GR-14.9.51.4-27/-28 gained witnesses (batch
`w1095e-pb578`).
