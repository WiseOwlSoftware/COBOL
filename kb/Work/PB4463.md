# PB4463 - raw diagnostic codes with no catalog descriptor, and COBOL1512 shared by three rules

**Sites (PB2296 integration head, branch worktree-wf_7d06ed65-e14-4):** `Binding/Passes/OdoResolvePass.cs` (COBOL0850 and
neighbours, 8 literals), `Binding/Passes/ResolveTableValuesPass.cs` (COBOL1586-1588, 4), `Binding/Passes/CheckStrongTypeDeclarationsPass.cs`
(3), `Binding/Passes/DynamicResolvePass.cs` (3), `Binding/Passes/ResolveRedefinesPass.cs` (2),
`Binding/Passes/CheckValueLiteralClassesPass.cs` (COBOL0898), `Binding/Passes/ClassifyRedefinesClassesPass.cs` (1); COBOL1512 at
`Binding/FileControlBinder.cs:266` (LOCK MODE with sequential access), `Binding/Procedure/Verbs/FileLockBinder.cs:98` (the
AUTOMATIC-locking phrase ban), `Binding/Validation/StatementValidation.cs:1594` (OPEN lock phrase). The descriptor table is
`DiagnosticCatalog`. Find the sites with `rg 'Edition\.Error\("COBOL' src`.

**What is wrong.** These `Edition.Error` calls pass a string literal instead of a `DiagnosticCatalog` descriptor, so the codes
0850-0857, 0898, 1522, 1523, 1525, 1526, 1532, 1539, 1542 and 1586-1588 (19 codes) have no catalog row: no title, no severity or
edition metadata, no documentation entry, no uniqueness check, and `wiseowl-cobol-raw-diagnostic-code-literal` counts each site.
COBOL1512 is one code reused by three different rules (LOCK MODE on a sequential file, the explicit lock phrase under AUTOMATIC
locking, the OPEN lock phrase), so a user who searches the code finds three unrelated meanings and a test that asserts the code
cannot tell the rules apart. The sites were invisible to semgrep until the passes moved to parseable files (PB4462), which is why
they surfaced in the PB2352/PB2355 baseline moves (225 -> 229, 225 -> 226).

**Fix shape.** One catalog descriptor per rule (give the three COBOL1512 rules their own codes, from `session-probe`'s next-free
code, and update every test and golden that asserts COBOL1512), route each call through the descriptor, and drive the raw-literal
rule's baseline down by the same count. A drift test that every `Edition.Error` code argument is a catalog member makes the next
case automatic (CLAUDE.md rule 5).

## Landed (kb/Work PB4463, branch worktree-wf_ec0327b7-bfd-2)

Every emit call in `src/` now names a `DiagnosticCatalog` descriptor: no `Error`, `Warning`, `Report`, `ReportError`,
`ReportWarning` or `Emit` call takes a `"COBOLnnnn"` literal, and `wiseowl-cobol-raw-diagnostic-code-literal` is at ZERO findings
(230 -> 0; the rule left `scripts/semgrep/baseline.json`). The note named 19 codes; the sweep found 93 raw codes at 255 sites and
all of them are done, because a drift test that every emit site names a descriptor is true only of the whole population.

* One descriptor per rule where a code was reused across unrelated rules, which took 23 new codes (COBOL5977-COBOL5999):
  COBOL1512 (LOCK MODE MULTIPLE / the lock phrase under AUTOMATIC / OPEN SHARING needs LOCK MODE), COBOL0898 (VALUE national,
  VALUE boolean, THROUGH on a boolean condition-name, numeric-edited VALUE class, undeclared alphabet-name, ALPHABET branch,
  SPECIAL-NAMES literal class, SPECIAL-NAMES literal empty, collating-sequence alphabet kind, ORDER TABLE repeated), COBOL1542 (ANY
  LENGTH placement / PICTURE / other clauses / header reference / REDEFINES / CALL), COBOL1532 (STRONG level / redefined / renamed),
  COBOL0844 (arithmetic operand / boolean relation / FUNCTION CHAR), COBOL0864 (READ KEY / LINAGE-COUNTER), COBOL0897 (USE rules /
  PERFORM WHEN file) and COBOL1530 (TYPE undefined / self reference).
* One descriptor per code where the sites are one family of the same kind of rule (the intrinsic-function argument bands 1504,
  1514, 1516, 1546, the PICTURE string band 0808, the declarative USE band 0897, the currency band 0890-0892, the boolean-expression
  band 1511): the title names every clause, and a later split of a band is its own note when a rule needs it.
* The semgrep rule is blind over part of `DataBinder.cs` (PB4462), so the net that holds is the unit fact
  `DiagnosticRegistryDriftTests.NoSourceLine_WritesACodeLiteral`, a text scan of every source line outside the catalogue (review round 1, R1-2).
  It failed once on two unqualified sites (`EditionContext.CheckDigitCapacity`) before it went green.

### Review round 1 (R1-1, R1-2): the report-then-refuse sites and the three codes that named one rule of several

The branch review found the population was not whole. `BoundRejected.Report(EditionContext, string code, string message)` was a literal-code
overload that fell back to the catalogue by code (the shim of kb/Work PB1029), and 50 sites called it with a `"COBOLnnnn"` literal; code tuples
(`DataBinder.Sr8PicturelessVerdict`, `ClassConditionModel.Wording`), a `ReceivingBar` constructor, `OoNameResolution.Resolve`'s `code` argument and
five `EditionDiagnostic` constructors did the same. Both the unit fact and the semgrep rule required the literal to be the FIRST argument of an
emit call, so the shape was invisible and the net stayed green. The overload is deleted, every site names its descriptor, and the fact now reads
every source line outside the catalogue, the generated registry, `EditionCodes.cs` and the front end's own parse-hint registry
(`NoSourceLine_WritesACodeLiteral`); the semgrep rule gained the `$X.Report($EDITION, $CODE, ...)` shape. 17 new descriptors cover 0712-0714,
0812, 0813, 0818, 0823-0826, 0848, 0865, 0866, 0870, 1521 and 1568 (one per code, the title naming every clause of the verb's band); 0827 became the EXIT
placement family. COBOL0827, COBOL0844 and COBOL1523 had named one rule while other rules emitted them, so each minority rule took a code
(COBOL6000 class condition SR4, COBOL6003 class condition SR8, COBOL6001 CAPACITY register as a receiving operand, COBOL6002 SELF/SUPER placement)
and the refusal goldens and tests that asserted the old code moved with them.
