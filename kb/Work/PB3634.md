# PB3634 — stale docs: the keyed transaction is not rolled back before the connector leaves the removed file

Filed 2026-10-28 by the clerk from the PB3492 branch review (R2-1, low, not blocking). Related: PB3492. Not a wrong answer: same result either way.

**Sites:** `src/Cobol.Net.Runtime/IO/FileRegistry.cs` (`RollbackKeyed` doc, line ~1378), `src/Cobol.Net.Runtime/IO/KeyedConnector.cs`
(`LeaveTheRemovedFile` doc, line ~334), `docs/rearchitecture/DESIGN-runtime-library.md` (2.2.2.14).
The code exists on main once PR #491 (branch `worktree-wf_42255de2-426-13`, PB3492, tip fc3a5ff52) merges; read it with
`git -C 'E:\COBOL' show fc3a5ff52:<path>` until then.

**Defect.** All three say a creation ROLLBACK rolls back the open connector's keyed transaction first, then the connector leaves
the file. It does not: `SequentialJournal` sets `Replaced = (start == Absent)` in its constructor, so for every START A journal
`RollbackKeyed` skips `holder.Rollback`, and `LeaveTheRemovedFile` detaches the store with its transaction still standing. Nothing
reads that store again, so the result is the same, but the docs describe a step that never runs.

**Fix direction.** Correct the three texts to the real sequence (or, if the rollback step is wanted for the store's sake, make the
code do it; the implementer decides). Same change set; no historical narrative in the design doc.
