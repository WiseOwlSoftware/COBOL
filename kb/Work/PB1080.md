### Adjudicator finding (file-status-clause, harm under-rejects)
- **Mechanism:** The FILE STATUS operand is resolved but never screened: DataBinder.ResolveFiles calls ResolveClauseOperand for data-name-1 and runs none of §12.4.5.8.3's four syntax rules on the resolved item (no OCCURS, category/length/section, dynamic-length/variable-length, or BASED check). Its LINAGE twin ResolveLinage in the same file does screen its OCCURS SR. The only FILE STATUS item validator in the tree is the legacy CobolSharp.Compiler FileStatusValidator (CBL3201-3204), which was never ported. So every non-conforming FILE STATUS item compiles, and the result depends on what the emitter does with it: a silent pad or truncation, a Roslyn backend crash, or a run-time process kill.
- **Repro:** Pinned E:/CobolSharp-pins/adj-d1 cobol.exe --run, --std 2023. SELECT F ASSIGN TO "x.dat" ORGANIZATION SEQUENTIAL FILE STATUS IS FS; PROCEDURE: OPEN INPUT F (missing file).
