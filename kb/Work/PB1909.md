# PB1909 — UNSTRING ALL-run consumption order versus GnuCOBOL

Found by wave 1002 group B (PB1907's UNSTRING part), documented by it as D-UNS2's exception and filed at the
train-1002 landing.

## The difference

An UNSTRING with `DELIMITED BY ALL <identifier>` where an INTO (or DELIMITER IN / COUNT IN) store of the SAME
statement overwrites that delimiter: libcob consumes the repeat run of the delimiter AFTER the INTO store, so the
run is matched against the overwritten value; WiseOwl COBOL consumes it BEFORE the store. Repro
`E:/Temp/claude/E--COBOL/eccdd4e4-0de7-4375-91cb-d99841bdb009/scratchpad/w1002b/x3.cob`: ours `Y2=[b;;;;c;  ]`,
libcob 3.2 `Y2=[;b;;;;c; ]`. The case is undefined (§14.9.48.4 GR18, Annex A.2 item 61; §4.4 2)), so ours is a
conforming result, but the owner's 2026-10-01 choice for PB1907 is "Follow GnuCOBOL, except WRITE length", and this
is a measured difference that was kept for cost, not chosen. It is pinned as ours in
`conformance:cases/14.9.48-UNSTRING/pb1907_unstring_overlap_delimiter` leg B2 and documented in `docs/CONFORMANCE.md` D-UNS2.

## Code sites

- `src/Cobol.Net.Compiler/CodeGen/Verbs/StringEmitter.cs` `EmitUnstring` — the per-receiver re-read sequence.
- `src/Cobol.Net.Runtime/Verbs/CobolStringOps.cs` `UnstringExtract` (~line 113, the ALL skip loop) — the run is
  skipped inside the one examination call, before the emitter stores.

## Why it was not fixed in wave 1002

Following libcob needs the kernel's examination split around the store (match the field's delimiter, return, let
the emitter store, then skip the ALL run against the live delimiter): two kernel calls per receiving area on the
overlap path. Fixing it means changing D-UNS2, the B2 golden line and the kernel together.
