# PB1909 — UNSTRING ALL-run consumption order versus GnuCOBOL

Found by wave 1002 group B (PB1907's UNSTRING part), documented by it as D-UNS2's exception and filed at the
train-1002 landing.

## The difference

An UNSTRING with `DELIMITED BY ALL <identifier>` where an INTO (or DELIMITER IN / COUNT IN) store of the SAME
statement overwrites that delimiter: libcob consumes the repeat run of the delimiter AFTER the INTO store, so the
run is matched against the overwritten value; WiseOwl COBOL consumes it BEFORE the store. Repro
`E:/Temp/claude/E--COBOL/eccdd4e4-0de7-4375-91cb-d99841bdb009/scratchpad/w1002b/x3.cob`: ours `Y2=[b;;;;c;  ]`,
libcob 3.2 `Y2=[;b;;;;c; ]`. The case is undefined (§14.9.48.4 GR18, Annex A.2 item 61; §4.4 2)), so ours is a
conforming result, but the owner's 2026-10-01 choice for PB1907 is "Follow GnuCOBOL, except WRITE length", and this
is a measured difference that was kept for cost, not chosen. It is pinned as ours in
`conformance:cases/14.9.48-UNSTRING/pb1907_unstring_overlap_delimiter` leg B2 and documented in `docs/CONFORMANCE.md` D-UNS2.

## Code sites

- `src/Cobol.Net.Compiler/CodeGen/Verbs/StringEmitter.cs` `EmitUnstring` — the per-receiver re-read sequence.
- `src/Cobol.Net.Runtime/Verbs/CobolStringOps.cs` `UnstringExtract` (~line 113, the ALL skip loop) — the run is
  skipped inside the one examination call, before the emitter stores.

## Why it was not fixed in wave 1002

Following libcob needs the kernel's examination split around the store (match the field's delimiter, return, let
the emitter store, then skip the ALL run against the live delimiter): two kernel calls per receiving area on the
overlap path. Fixing it means changing D-UNS2, the B2 golden line and the kernel together.

## Landed — 2026-10-23 (wave 20261027 group G)

Re-probed on a fresh build before the change: the golden's leg B2 gave Y2=[b;;;;c;  ] against libcob 3.2.0's Y2=[;b;;;;c; ], and four
more probes (a run that only matches after the INTO store overwrote the delimiter, an INTO store into the sender inside the run, a
two-character ALL delimiter, two ALL delimiters) differed the same way where the run's length depended on the overwrite.

**Fix (the kernel split the note asked for, one mechanism).** `CobolStringOps.UnstringExtract` now consumes ONE occurrence of the
matched delimiter and returns the matched delimiter's list position in a new `matched` out-argument (this replaces
`MatchedDelimiterIndex`, which guessed the position back from the text; the `allFlags` argument left it). The new
`CobolStringOps.UnstringSkipRun` consumes the contiguous repeats (§14.9.48.4 GR7) over the sender and the delimiter as handed in.
`StringEmitter.EmitAllRun` renders it after the receiving area's INTO store and before DELIMITER IN and COUNT IN, which is libcob's
`cob_unstring_into` order, re-reading the sender and the matched ALL delimiter first wherever `StorageSharing.MayShare` says a store can
reach them; a statement without an ALL phrase renders no skip and no flag array. The note proposed to do this "only on the overlap
path"; the kernel call is rendered for every ALL phrase instead, because one place for the run is the structure that keeps the next
case automatic, and the re-read stays on the overlap path only.

**Runtime major 16 to 17.** Removing `MatchedDelimiterIndex` and changing `UnstringExtract`'s signature edits `PublicAPI.Shipped.txt`, so
`Directory.Build.props` is 17.0.0 and `RuntimeAbiPinDriftTests` is re-pinned (runtime hash 997188CC94F3A8D8).

**Evidence.** Golden `cases/14.9.48-UNSTRING/pb1907_unstring_overlap_delimiter` gains legs B3 (the run follows the store), B4 (the INTO
store reaches the sender) and B5 (a two-character ALL delimiter) and B2 changes to libcob's line; all five lines were also run through
cobc 3.2.0 and agree. Unit: `UnstringKernelTests`, and `UnstringLiveReadDriftTests` gains the ALL-run emission rules. The
Characterization snapshot `char_string_ops.85.g.cs.txt` moved by the new call shape only. `docs/CONFORMANCE.md` D-UNS2 lost its
"one documented difference" sentence.
