# PB3324 — the ledger audit RENDERED VIEWS took 2,713 s inside one gate run

## Source

The implementer's lead ("Gate cost") in `E:\COBOL-coord\scratch\reports\w1102g-PB3261-report.md` (wave 1102 G): "gate cost in
`scripts/spec/gen_ledger.py:469-483` (`audit RENDERED VIEWS` 2,713 s)", measured inside gate run `20261017T022622Z-00cb65`.

## Repro

Run the gate (`pwsh scripts/build-local.ps1 -Priority BelowNormal`) on a branch whose base is many commits past the ledger
trend's last recorded point; the audit "RENDERED VIEWS" (the ledger's rendered-view check) runs `scripts/spec/gen_ledger.py`,
which runs `git show` of the inventory for every commit since the trend's last point. Run `20261017T022622Z-00cb65` spent
2,713 s there.

## Harm

Gate wall time (process only): one audit, which reads only the tree, dominated a gate run. No wrong answer.

## Code site

`scripts/spec/gen_ledger.py:469-483` (the back-fill loop over `git log --reverse ... -- INVENTORY_REL kb/Work`, calling
`inventory_counts_at(sha)` and `register_counts_at(sha)` per commit).

## Fix shape

Bound the back-fill: cache the counts per commit, or compute only the missed points once, outside the gate's audit list.

## Related

PB2912 (the ledger), PB2524 (gate audits run before the gate queues).

## Landing (wave 20261031, group E; the same mechanism as PB3315)

Fixed by PB3315's change set: `scripts/spec/gen_ledger.py#measure_commits` reads every commit since the trend's last point
through two git processes (`git_batch.tree_entries`, `git_batch.blobs`), and `inventory_counts_at` / `register_counts_at`
are deleted. `gen_ledger.py --self-test` holds the process count constant in the number of commits. Code site for the next
implementer: `measure_commits`, the one per-commit reader.
