# PB96 — OPEN — `66 AC RENAMES A THRU C.` yields "ababcd" (LENGTH 6) where the record area is "abcd" (4)

> ⚙ **flags:** wrong-answer, silent · found 2026-08-18 writing [[PB93]]'s legal-shape test.

**Measured** (`scratchpad/pb93/rn.cob`, `--std 2023`):
```
       01 REC.
          05 A PIC X(2) VALUE "ab".
          05 B REDEFINES A PIC X(2).
          05 C PIC X(2) VALUE "cd".
       66 AC RENAMES A THRU C.
           DISPLAY "[" AC "] LEN=" FUNCTION LENGTH(AC).      ->  [ababcd] LEN=6
```
The record's storage is A(2) + C(2) = 4 characters; B overlays A (§13.18.44 — a redefinition adds no storage).

**Spec:** §13.18.45.4 GR1/GR2 — data-name-1 (the alias) is the storage area beginning at data-name-2 and ending at
data-name-3 within the record; §13.18.44.4 — the redefining entry describes the SAME area. The alias's content
is the record's characters from A's first to C's last: "abcd".

**Mechanism:** `DataBinder.ResolveRedefines`'s RENAMES loop composes `info.SpanLeaves` by walking the record's leaves
in declaration order between FROM and THRU and summing `ImageWidth × Occurs` — a redefining leaf (`B`, whose
`RedefinesTargetName` is set) is a VIEW over A's storage, yet it is added to the span as if it occupied its own
characters, and the alias's `Pic.Length` and image both count it. The same walk feeds `SpanLeaves` to the
RENAMES place's read/write, so the alias reads A twice.

**Fix shape:** the span is a STORAGE window, not a leaf list — compose it from the record's NON-redefining leaves
only (`RedefinesTargetName is null`, the same filter `DataItem.ImageWidth` / `RecordLayout` / `BitLayout` already
apply), or better from the record's character offsets: FROM's start offset to THRU's end offset over
`RecordLayout`, so a THRU that ends inside a redefinition (`RENAMES A THRU B`) is the storage window B overlays.
Sweep: `FUNCTION LENGTH` of the alias, the alias as a MOVE/compare operand, a RENAMES range with an OCCURS'd leaf
(SR3 forbids subject items with OCCURS, but a subordinate table inside a group operand?), and the RENAMES place's
write (`WriteRenames`) which distributes back over `SpanLeaves`. Golden: the four-shape probe above (THRU C,
THRU B, FROM B, a THRU inside a nested group).
