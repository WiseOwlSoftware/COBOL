# PB3989 — the owner: GnuCOBOL's COMP-5 / COMP-X / COMP-N exemption is GnuCOBOL's error

**The owner (2026-10-27 ~21:50 PDT), on GnuCOBOL's exemption:** "That sounds like a GnuCobol error".

**The facts.** A statement with only a NOT ON SIZE ERROR phrase, checking off, falls under §14.6.13.1.3 item 8
(`cite.py --check 14.6.13.1.3 "the implementor defines whether or not execution will continue, how it will continue,
and how any receiving operands are affected"` OK), where CLAUDE.md rule 1 follows GnuCOBOL (PB3869, retired). GnuCOBOL
3.2 keeps an overflowing resultant for any [NOT] SIZE ERROR phrase (`cobc/typeck.c`, "There is a [NOT]
ERROR/OVERFLOW/EXCEPTION" sets `COB_STORE_KEEP_ON_OVERFLOW`) EXCEPT a COMP-5, COMP-X or COMP-N receiver of a NOT-only
statement: its `build_store_option` sets the flag for those usages only with an ON SIZE ERROR handler ("Do not check NOT
ERROR case, so that we optimize"), so they take the phraseless store (the container residue, `libcob/numeric.c`
`cob_decimal_get_binary`). That exemption is an optimization that contradicts GnuCOBOL's own rule for every other
usage, so it is GnuCOBOL's inconsistency, not an implementor model to copy.

**The decision.** WiseOwl COBOL keeps every receiver of a [NOT] SIZE ERROR statement that meets a size error, every usage
alike (main's behaviour; DOC-A.1-70 states it and names this exemption). No code changes. The attempt to follow the
exemption (`worktree-wf_5cf68b99-205-1`, `fcdd97e47`, wave 20261735 group A) is not to land; it also carried a regression
(PB3990's rule-7 case).

**Owed:** an `upstream` note (PB3838's kind) recording the exemption for GnuCOBOL's maintainers, to PB3838's eight-item
bar: a minimal repro (`ADD 200 TO X5 NOT ON SIZE ERROR ...` with X5 `PIC 99 COMP-5`, beside the same statement on a
DISPLAY item), the cobc command and output, the clause, the site above, a draft issue.

Filed as its own note so the register sees it: PB3993 (no witness yet pins the keep for a COMP-5 / COMP-X / COMP-N
receiver; round-3 review lead R3-3 of `worktree-wf_f781f6f8-448-20`).
