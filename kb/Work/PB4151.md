# PB4151 — the Format-3 PERFORM acceptance test asserts too little

**Sites:** `tests/WiseOwl.Cobol.Tests.Unit/RequiredImperativeStatementDriftTests.cs:399` (`RequiredImperativeStatementDriftTests.TheFormat3Statement_WithEveryBodyWritten_IsAccepted`).

Review lead R1-1 (low, not blocking at round 1) of the PB3948 branch. The test compiles and runs the Format-3 (exception-checking)
PERFORM `PERFORM DISPLAY "A" WHEN EC-ALL DISPLAY "B" WHEN OTHER EXCEPTION DISPLAY "C" WHEN COMMON DISPLAY "D" FINALLY DISPLAY "E"
END-PERFORM` at 2023 and asserts `Assert.DoesNotContain("COBOL2072", detail)` then `Assert.True(ok || !Codes(detail).Contains("COBOL0001"), detail)`.
That second assertion passes when the statement is refused with any code other than COBOL0001 and when the run fails, so the
test cannot catch a regression to a different refusal. Its summary says "Compiled, not run with the runtime staged work", while
`CompileAndRun` does run it, and the report records that the program already runs correctly (A then E on that build).

Fix: assert `ok` (and the run's output A then E, or the output the cited rule gives), and correct the summary sentence to say the
statement is compiled and run. Derive the expected output from the spec's Format-3 PERFORM rule before pinning it (validate the clause with
`python scripts/spec/cite.py --check`); do not copy the build's output.
