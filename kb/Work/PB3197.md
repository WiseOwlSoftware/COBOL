In the cloud image setup-env.sh:69-85 describes, when uv fails and no python3.12+ exists the image's /usr/local/bin/python3 -> python3.11 stays first on PATH; linux-gate.sh:53 accepts it and the legs fail on the scripts' PEP 701 f-strings with a SyntaxError, instead of the 'no runnable Python >= 3.12' refusal PB1637 built. Each new gate script picks a resolver by copy-paste, so the PB1637 failure class (a name on PATH that is not a usable interpreter) stays open in every script that did not copy the right one.
