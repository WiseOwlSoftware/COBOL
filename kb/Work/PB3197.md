## Landed (wave 1098 group B, branch `worktree-wf_e3902303-54c-4`)

**Re-probe (2026-10-16, base 16b82f639).** `bash scripts/build-local.sh` on a PATH whose only interpreter is a
`python3` (stock Ubuntu shape): `scripts/build-local.sh: line 19: python: command not found`, exit 127, no verdict
line. `linux-gate.sh:129`'s `command -v python3 || command -v python` on a PATH whose `python3` answers the floor probe
as 3.11 does: it took it and ran it; `python-resolve.sh` on the same PATH refused. The note's fourth site
(`linux-gate.sh:107`, a bare `python3` in a hook loop) is gone from the tree, as its skeptics' correction said.

**Fix.** One rule per shell: `build-local.sh` and `linux-gate.sh` source `scripts/python-resolve.sh` and run `"$PY"`;
`build-local.ps1` dot-sources the new PowerShell twin `scripts/python-resolve.ps1` (same candidates in the same order,
same floor probe; a terminating error on none, since a dot-sourced `exit` would end only the twin) and runs `& $PY`.
The three entry points resolve so that a host with no runnable Python still ends on their own verdict line, NOT RUN with
exit 2 (`build-local.sh`/`linux-gate.sh` source the resolver in a subshell; `build-local.ps1` catches the twin's error).
`linux-gate.sh --self-test` gained three arms with stand-in interpreters (a python3 below the floor passed over;
`$PYTHON` probed first; none is NOT RUN, exit 2). Drift test `PythonInterpreterDriftTests` (Unit, tree sweep): no bash
script under `scripts/` and no PowerShell twin of one names an interpreter as a command, every `$PY` user sources its
shell's resolver, and the two resolvers are equal; seen red on the base tree at exactly the three note sites. Design:
DESIGN-test-build-ci.md §3.14.11 (new), DESIGN-architecture-review.md §5.6, DOC_INDEX row.

**For the next implementer.**
- `scripts/python-resolve.sh` / `scripts/python-resolve.ps1`: THE interpreter rule, one per shell. A new gate script
  sources its shell's resolver and runs `"$PY"` / `& $PY`. Never name `python`/`python3` as a command, because
  `PythonInterpreterDriftTests` is red on it. Change the candidates or the floor in BOTH files, because the drift test
  holds them equal.
- `scripts/build-local.{sh,ps1}`, `scripts/linux-gate.sh#resolve_py`: a script with a verdict line runs the bash
  resolver in a `$(…)` subshell (its `exit 1` ends only the subshell). PowerShell catches the twin's throw. Trap: an
  `exit` in a dot-sourced PowerShell script ends only that script, not its caller (measured), hence the throw.
- `scripts/linux-gate.sh --self-test`: stand-in interpreters are shell functions (`python3() { return 1; }`), which the
  resolver's probe calls before PATH. They must `return`, never `exit`, inside the `$(…)`.
