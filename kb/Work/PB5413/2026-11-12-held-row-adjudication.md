**Amendments.**

1. **This note also claims `1985-SR-IX.4.3.3-2`** (the indexed DELETE). Its EXTEND arm needs no reading: `held-85/set6/p/u-ext-io.cob` and the refuter's `d-useEXT.cob` compile and print `AFTER DELETE 23`. The set 6 adjudicator also settled the reading the note left open: a USE ON INPUT or ON OUTPUT procedure IS applicable to a DELETE, REWRITE or START, because "applicable" binds the procedure to the file ("for which", `§1985:IX.4.3.3 SR2`), the USE rules make a procedure apply by an open mode the file can be in, and a DELETE of a file open INPUT does run the USE ON INPUT procedure (`u-in-in.cob`: `USE RAN 49`). So the INPUT and OUTPUT arms conform, and only EXTEND under-rejects.

2. **A sequential file with LINAGE is the same defect.** Such a file can never be opened EXTEND: "The EXTEND phrase must only be used for files for which the LINAGE clause has not been specified" (`§1985:VII.4.3.3 SR3`, checked with `cite.py --check`). The adjudicator's `held-85/set7/p/linx.cob` (FD with LINAGE IS 10 LINES, only USE ... ON EXTEND, a READ with no AT END) compiles with no diagnostic; I reran it on the pinned compiler (`E:/COBOL-wt/coderead85-tree-c`, fafa91a83c) and it compiled and printed `AFTER 00`. Expected: COBOL6826. So the fix's rule is "EXTEND only for a sequential-access file without LINAGE", and this note claims `1985-SR-VII.4.4.3-2`, which records-85j re-recorded CONFORMS to PARTIAL naming this note.
