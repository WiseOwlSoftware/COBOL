# PB4811 - the file-name debugging trigger

**What fails.** `USE FOR DEBUGGING ON <file-name>` is refused COBOL1571 (staged in `ProcedureTableBuilder.FinalizeDebug`), so a
legal debug declarative on a file does not compile (the DB201A family's file triggers).

**The rules to implement** (sources and line numbers in kb/Work/PB4808.md, Findings):
- OPEN and CLOSE fire after the I/O; DEBUG-CONTENTS is spaces.
- READ fires only when it took neither AT END nor INVALID KEY; DEBUG-CONTENTS is the whole record read.
- DELETE and START fire right after the I/O, whatever its outcome; DEBUG-CONTENTS is spaces.
- WRITE and REWRITE do not fire the file-name trigger (their record's data trigger is PB4810's).
- SORT and MERGE USING and GIVING, RELEASE and RETURN fire no file-name trigger.
- DEBUG-CONTENTS is as long as the largest of 30, each data-name target and each file's maximum record.

**Sites:**
- `docs/CONTROL_FLOW_DESIGN.md` (the debug-facility section PB4810 writes; this note adds the file arm)
- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/ProcedureTableBuilder.cs#FinalizeDebug`
- `src/WiseOwl.Cobol.Compiler/Binding/Bound/BoundTree.cs#BoundDebugSubject`
- `src/WiseOwl.Cobol.Runtime/Control/DebugItem.cs#DebugItem`
- the file-statement emitters for OPEN, CLOSE, READ, DELETE and START (members named by the design)

**Order.** After PB4810: it shares the design section, the subject model and DEBUG-CONTENTS sizing.

**2026-11-06 (from w20261885a-PB4810-report.md, round-1 lead).** PB4811 should reuse `DebugTriggerEmitter`/`DebugWhen` (the wave-20261885 branch of PB4810; not yet on main). Related lead: PB4858.

**Landed (wave 20261887 A).** The text is the 1985 standard itself (the owner's copy, PDF page 694 rule 2, page 698 rule 23), which
decides what PB4808 read from the vendors: OPEN and CLOSE run the section after the statement (rule 2 a), a READ only when it delivered a
record (2 b), DELETE and START after the I-O whatever its outcome (2 c); rule 7 makes the INVALID KEY statement a statement of its own, so the
section runs before it. DELETE FILE follows GnuCOBOL. The design is `docs/CONTROL_FLOW_DESIGN.md` D20 (file-name-1) and the determination
`docs/CONFORMANCE.md` D-DEBUG-FILE; witnesses `pb4811-debug-file-name-triggers`, `pb4811-debug-file-name-repeated` (COBOL6335) and
`pb4811-debug-file-name-removed-2002` (COBOL0902).
- Model: `DebugTargetKind.FileName`, `BoundDebugTarget.File`, `DebugFire.Contents` (`DebugContents`) with a null `DebugFire.Referenced` for a fire that
  references no place.
- Plan: `src/WiseOwl.Cobol.Compiler/Binding/Bound/DebugTriggerPlanner.cs` (`DebugTriggerPlanner.PlanFile`).
- Collect: `src/WiseOwl.Cobol.Compiler/Binding/Procedure/ProcedureTableBuilder.cs` (`ProcedureTableBuilder.AddDebugFileTarget`, `FinalizeDebug`).
- Land: `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/DebugTriggerEmitter.cs` (`DebugTriggerEmitter.EmitFire`, `HasAfterAction`),
  `SequentialIoEmitter.EmitRead`, `KeyedIoEmitter.EmitRead`, `EmitDelete`, `EmitDeleteFile`, `EmitStart` (`Debug.LandAfterAction`).
- Found on the way and fixed with it (PB4858's first half): `ReferenceResolver` (`Identify`, the DEBUG-ITEM arm) now lets `DEBUG-CONTENTS (1:n)`
  take the reference-modification tail, so a debugging section can read part of the register.
