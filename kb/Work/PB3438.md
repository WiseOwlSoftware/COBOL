# PB3438 — the third EC-I-O arm of the constant-named ASSIGN golden is missing

Filed 2026-10-19 by the enqueue clerk from `E:\COBOL-coord\scratch\reports\w1129g-PB2500-report.md` (PB2500's branch was
being landed by the lane; the golden is on it). Register check: a grep of kb/Work by `pb2500_assign` and `EC-I-O` found PB2500
and PB3114 and PB3260/PB3263 (the feature and its siblings); no note tracks this arm.

**Gap.** `conformance-suite/cases/12.4.5-File-control/pb2500_assign_constant_name.cob:66` covers the EC-I-O arms FILE STATUS
without USE and USE without FILE STATUS for a constant-named file. It does not cover the third arm the standing requirement
names (MANDATORY-PRACTICES I11; memory feedback_io_tests_cover_exception_paths): neither a FILE STATUS item nor a USE
declarative, where the fatal EC-I-O condition terminates the run unit. The reviewer named 14.6.13.1.3 3); mechanically
checked here: `python scripts/spec/cite.py --check 14.6.13.1.3 "fatal exception condition"` returns OK for the clause title
"Fatal exception conditions" (the exact paragraph number 3) still needs the quote check by the implementer).

**Fix.** Add the arm to the golden (the run unit ends with the standard's fatal-condition termination), derived from the
clause, not from the compiler's output.

**Sites:**
- `tests/WiseOwl.Cobol.Tests.Conformance/AssignConstantNameTests.cs` (the new Theory)
- `conformance-suite/cases/12.4.5-File-control/pb2500_assign_constant_name.cob` (comment pointer only; `.out` unchanged)
- `docs/CONFORMANCE.md` (the DOC-A.1-103 witness list)

**Landed.** The note's own fix text, "add the arm to the golden", cannot be done as written: the conformance harness requires
a golden to exit 0 (`pb1453_program_address_operand_not_found.cob` says so; `DESIGN-conformance-suite.md` calls abnormal
termination "not a portable expectation"), and the arm with neither a FILE STATUS item nor a USE declarative ends the run
unit abnormally (14.6.13.1.3 3) and 8): EC-I-O checking is not enabled, so the implementor defines the outcome; Annex A.1 item 103). The witness for that arm is a unit-level conformance test,
the home `DocA1Item103WitnessTests` already uses for the same arm of a literal-named file. Re-probe on the wave-1132 build:
`OPEN INPUT NF` of a constant-named absent file with neither prints `BEFORE`, then `abnormal run-unit termination:
EC-I-O-PERMANENT-ERROR (fatal): I-O status 35 on NF (OPEN); the file has no FILE STATUS clause and no USE procedure
applies`, exit 1. `AssignConstantNameTests.ConstantNamedFile_FatalStatus_NeitherFileStatusNorUse_TerminatesTheRunUnit`
covers OPEN ('35', EC-I-O-PERMANENT-ERROR, 9.1.13.6 5)) and WRITE to an unopened file ('48', EC-I-O-LOGIC-ERROR,
9.1.13.7 8)), each asserting that nothing after the failing statement ran. The golden's comment now points at it.
