PB3666 (owner-approved: the MOVE converts each character, '1' to 1 and any other to 0) states that only a group receiver (GR4) and a REDEFINES view leave non-boolean characters in a boolean item. Its R1-1 fix (the `AreaHoldsCharacters` arm) adds a third: an alphanumeric group sent into a USAGE NATIONAL boolean item. The content is undefined under §14.6.13.2 1), so no wrong answer follows, but the three texts must list every bypass, or the code must close it. Decide which, and make the three texts one.

## Adjudication 2026-10-25 (mythos lane, pinned main 51103b9a1)

**Final verdict:** DEFECT  
**Checkpoint (full record):** `E:/COBOL-coord/scratch/mythos/adj-20261025/PB3697.json`

**Expected from the spec:** ISO leaves non-boolean content in a boolean item undefined (§3.21: a boolean character is zero or one; §14.6.8.6: 'after any necessary conversion'; §14.6.13.2 1): undefined result plus EC-DATA-INCOMPATIBLE). So the rule that binds is the owner's D-B5 determination (PB3666, 2026-10-24): every store of characters into a boolean item converts them, '1' to 1 and anything else to 0. That covers every path from an alphanumeric or national sender, INCLUDING 'a group-to-elementary path', so that DISPLAY and the operators agree. §14.9.25.4 GR4 (no conversion of internal representation; bit and national groups treated as elementary) fixes only that the receiving AREA takes the sender's BYTES. The receiver's characters are then decoded from those bytes. Converting the DECODED characters is D-B5's normalization of undefined content, not a representation conversion. Converting the raw bytes before decoding, which review R1-1 rightly rejected, is one. Expected: MOVE GA ('A1Z1') TO BN (PIC 1(4) USAGE NATIONAL) leaves BN = 0000, because the pairs x4131, x5A31, x2020 and x2020 decode to characters other than '1'. That is what MOVE GA TO BN(1:2) already does. A READ or RETURN of an elementary boolean record area goes through the same single storage-area store (§14.9.30.4 GR13 c) and §14.9.34.4 GR3: the record 'is made available in the record area'), so it should get the same conversion. What a store cannot close is content that reaches the item through ANOTHER DESCRIPTION OF THE SAME STORAGE: a group receiver's area (GR4), a REDEFINES view, or storage shared by a BY REFERENCE argument (and, not probed, EXTERNAL, BASED or ADDRESS OF aliases).

**Citations checked:**
- OK §14.9.25.4 4) except that there is no conversion of data from one form of internal representation to another
- OK §14.9.25.4 4) Bit group items and national group items are treated as elementary items in the MOVE statement
- OK §14.6.13.2 1) the result of the reference is undefined and an EC-DATA-INCOMPATIBLE exception condition is set to exist
- OK §14.6.8.6 after any necessary conversion, into the corresponding boolean positions of the receiving data item
- OK §3.21 unit of information that consists of the value zero or one
- OK §14.9.30.4 13) If no exception condition exists, the record is made available in the record area
- OK §14.9.34.4 3) to be made available in the record area associated with file-name-1

**Repro and observed:** Pinned build E:/COBOL-wt/pin-adj-20261025 (51103b9a1), run with cobol.exe --run. (1) E:/COBOL-coord/scratch/mythos/adj-20261025/PB3697/natbool.cob: MOVE GA ('A1Z1') TO BN PIC 1(4) USAGE NATIONAL. DISPLAY shows four national characters that are not boolean (U+4131 U+5A31 U+2020 U+2020), B-NOT gives 1111 (the operators read 0000), and 'BN = ZERO' is FALSE, so DISPLAY, the comparison and the operators disagree (the PB3666 symptom). In the same program, MOVE GA TO BN(1:2) converts the decoded pairs (BN becomes 0001) and MOVE GA TO BD (USAGE DISPLAY) gives 0101. Of the GR4 group-move arms, only the whole-item national arm does not convert. MOVE GN (N'101') TO BN2 gives 101, R1-1's case, which stays right under decode-then-convert. (2) E:/COBOL-coord/scratch/mythos/adj-20261025/PB3697/readbool.cob: WRITE 'A1Z1B101', then READ it into FD record RB PIC 1(8). DISPLAY shows A1Z1B101 and B-NOT gives 10101010. READ into RN PIC 1(4) USAGE NATIONAL shows four CJK characters and B-NOT gives 1111. This is a fourth bypass the texts do not list, through the same StorageArea store. (3) E:/COBOL-coord/scratch/mythos/adj-20261025/PB3697/callbool.cob: CALL BY REFERENCE passes PIC X(4) 'A1Z1' to LINKAGE PIC 1(4). DISPLAY shows A1Z1 and B-NOT gives 1010. This is a storage alias, the same class as REDEFINES, and no store can close it.

**Code site:** src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/ReceivingStore.cs#StorageCharacters; src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/ReceivingStore.cs#Characters; src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/ReceivingStore.cs#AreaHoldsCharacters; tests/WiseOwl.Cobol.Tests.Unit/ReceivingStoreDriftTests.cs#EveryStoreIntoABooleanItem_ConvertsItsCharacters; src/WiseOwl.Cobol.Compiler/CodeGen/Roslyn/RuntimeApi.cs#StrStoreBoolean; docs/DATA_MODEL_DESIGN.md (D19 boolean-store paragraph); docs/CONFORMANCE.md (D-B5)

**Action:** Close the store bypasses in code, then make the three texts say the same thing. Fix: add a category-boolean arm to ReceivingStore.StorageCharacters that converts the DECODED characters through RuntimeApi.BoolFromCharacters: BoolFromCharacters(NatReadWindow(area, 0, positions)) for a national item and BoolFromCharacters(area) for a display boolean. USAGE BIT stays as it is, because every bit pattern is valid. StorageArea, SliceStorageArea and MoveEmitter.GroupRecord all decode through StorageCharacters, so this one arm covers three cases: the whole national boolean receiver of a GR4 group move, the record-value receiver, and READ or RETURN into an elementary boolean record area (display and national). It matches the slice arm, which PlaceRenderer.Write already converts. ReceivingStore.Characters' boolean arm then keeps only the boolean zero fill for a display area. The drift test currently pins the national exemption ('is not { Usage: Usage.National or Usage.Bit }'); change it to require the StorageCharacters boolean arm. Extend golden pb3666_boolean_receiver_converts_characters with three cases: MOVE GA ('A1Z1') TO BN PIC 1(4) USAGE NATIONAL gives DISPLAY 0000 and B-NOT 1111; the N'101' group gives 101; and a READ of 'A1Z1B101' into an elementary PIC 1(8) record gives 01010101. Determination text, word for word in DATA_MODEL D19, CONFORMANCE D-B5 and the StrStoreBoolean summary: 'Every STORE into a boolean item converts its characters. That includes a GR4 group move (the decoded characters of a national or display receiver; a USAGE BIT receiver's bits are all valid) and a READ or RETURN into an elementary record area. A boolean item can still hold a character other than 0 or 1 only through another description of the same storage, which no store into the item reaches: a group receiver (GR4 moves the group's bytes), a REDEFINES view, or storage shared through a BY REFERENCE argument, EXTERNAL, BASED or ADDRESS OF. That content is undefined (§14.6.13.2 1)), and the boolean operators read such a position as zero.' Remove the 'Two things bypass it' and 'Two exemptions' wording from DATA_MODEL and the national-exemption sentence from D-B5. If the owner wants no code change, the alternative is to keep the code and list four bypasses in all three texts: the national group move, READ or RETURN into an elementary record, and the alias class. I do not recommend it, because the whole-item national arm would still disagree with its own reference-modified arm.

## Landed (wave 20261716, group B; DEVLOG entry `pb3697-...`)

Re-probed on a fresh build: all three repros of the adjudication reproduced (a group `A1Z1` into `PIC 1(4) USAGE NATIONAL` displayed four CJK characters and `B-NOT` gave 1111; a READ of `A1Z1B101` into an elementary `PIC 1(8)` record showed `A1Z1B101`; the BY REFERENCE alias shows `A1Z1`). Fixed in code, as the adjudication recommended, at the one place that decodes a storage area: `ReceivingStore.StorageCharacters` now converts the DECODED characters of a boolean item (display or national; a USAGE BIT item is exempt) through `BoolFromCharacters`, on top of the new private `DecodedStorage` (the representation decode it used to be). `StorageArea`, `GroupRecord` (the record-value receiver) and the READ / RETURN elementary record area all go through it, so one arm closes the whole-item national group move, the READ / RETURN into an elementary boolean record (display and national) and the record-value receiver. `ReceivingStore.Characters` lost its boolean arm (it would convert a second time: the fit pads with spaces and the conversion makes every space a boolean zero, the same §14.6.8.6 zero fill), and `SliceStorageArea` decodes through `DecodedStorage` because the splice (`PlaceRenderer.Write`) converts a boolean slice itself. The three texts are one sentence, word for word, in `RuntimeApi.StrStoreBoolean`, `DATA_MODEL_DESIGN.md` D19 and `CONFORMANCE.md` D-B5, pinned by `BooleanStoreDeterminationDriftTests`; the national exemption and the "two bypasses" wording are gone. Content that reaches a boolean item through another description of the same storage (a group receiver, a REDEFINES view, a BY REFERENCE argument, EXTERNAL, BASED, ADDRESS OF) is undefined under §14.6.13.2 1) and no store can close it; the text now says so. Golden: lines L13 to L15 of `pb3666_boolean_receiver_converts_characters` (a group into a national boolean gives 0000 / 1111; a READ into an elementary display and national boolean record, and the AT END path of the second READ).

### Branch review round 1 (review finisher, same wave)

R1-1 and R1-2 (both blocking, both correct): the READ / RETURN record-area store and the APPLY COMMIT restore both reach `ReceivingStore.StorageArea`, which now converts, but neither is a STORE of characters into the item. A READ fills the record AREA's bytes (the widest record's view, shared with the other records of the FD by §13.18.33.4 GR3 and with a SAME RECORD AREA peer's by §12.4.6.4.4 GR2), and ROLLBACK returns an item to its saved image (§14.9.36.4 GR3), which a REDEFINES view may hold as any characters. Fixed at the root: `ReceivingStore.VerbatimStorageArea` (the decode with no boolean conversion) beside `StorageArea`, both over the private `WriteDecoded`, and `SequentialIoEmitter.EmitImageInto` takes `storesIntoOwnItem` from every caller: true only for a READ / RETURN into an area `FileModel.AreaHasOneDescription` (one record, no SAME RECORD AREA peer); false for a shared area, the peer view, the "also available" store of a released record and the ROLLBACK restore. The determination sentence (three places, word for word) now says so; goldens L16 and L17 of `pb3666_boolean_receiver_converts_characters` and the new `pb3697_rollback_restores_boolean_item_verbatim`; the drift test pins every `EmitImageInto` call to name the argument.

### Branch review round 2 (review finisher, same wave)

R2-1 (blocking, correct): `FileModel.AreaHasOneDescription` ignored an EXTERNAL FD, whose record area this compiler binds to ONE run-unit cell keyed by the file name; every other runtime element that describes the file and records as external reads it (§13.18.22.4 GR4 b), and GR6 lets that element add its own complete redefinition). A READ in the element with one boolean record converted the shared bytes, so the other element read the converted characters (probe: `RVEXTA` reads `A1Z1B101` into `RB PIC 1(8)`, `RVEXTB` shows `RA2 PIC X(8)` as `01010101`; the record read is `A1Z1B101`). The same mechanism as R1-1, one arm further. Fixed at the predicate: `AreaHasOneDescription => Records.Count == 1 && !IsExternal && !SameRecordAreaPeers.Any()`, so an EXTERNAL file's READ takes `VerbatimStorageArea`. Golden: L18 of `pb3666_boolean_receiver_converts_characters` (a CALLed contained program describes the same external file with `RA2 PIC X(8)`; expected `A1Z1B101`, the record, from GR4 b)); the drift test pins the predicate's three terms. The determination sentence already listed EXTERNAL among the storage no store reaches, so its three texts are unchanged; `DATA_MODEL_DESIGN.md` D19 and the `ReceivingStore.StorageCharacters` summary now name the EXTERNAL area among the shared areas. Sibling sweep: the other sharers of one record area are a second record (`Records.Count`), a SAME RECORD AREA peer (`SameRecordAreaPeers`) and an EXTERNAL file; BASED and ADDRESS OF cannot describe an FD record area; a keyed READ and a SORT RETURN reach `EmitImageInto` only through `EmitRecordAreaStore` (verbatim).
