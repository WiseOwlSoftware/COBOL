# PB3697 — the boolean-store invariant is overstated in three places

**Sites:**
- `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/ReceivingStore.cs` (`StorageCharacters`)
- `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/ReceivingStore.cs` (`Characters`)
- `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/ReceivingStore.cs` (`AreaHoldsCharacters`)
- `tests/WiseOwl.Cobol.Tests.Unit/ReceivingStoreDriftTests.cs` (`EveryStoreIntoABooleanItem_ConvertsItsCharacters`)
- `src/WiseOwl.Cobol.Compiler/CodeGen/Roslyn/RuntimeApi.cs` (`StrStoreBoolean`)
- `docs/DATA_MODEL_DESIGN.md (D19 boolean-store paragraph)`
- `docs/CONFORMANCE.md (D-B5)`

PB3666 (owner-approved: the MOVE converts each character, '1' to 1 and any other to 0) states that only a group receiver (GR4) and a REDEFINES view leave non-boolean characters in a boolean item. Its R1-1 fix (the `AreaHoldsCharacters` arm) adds a third: an alphanumeric group sent into a USAGE NATIONAL boolean item. The content is undefined under §14.6.13.2 1), so no wrong answer follows, but the three texts must list every bypass, or the code must close it. Decide which, and make the three texts one.

## Adjudication 2026-10-25 (mythos lane, pinned main 51103b9a1)

**Final verdict:** DEFECT  
**Checkpoint (full record):** `E:/COBOL-coord/scratch/mythos/adj-20261025/PB3697.json`

**Expected from the spec:** ISO leaves non-boolean content in a boolean item undefined (§3.21: a boolean character is zero or one; §14.6.8.6: 'after any necessary conversion'; §14.6.13.2 1): undefined result plus EC-DATA-INCOMPATIBLE). So the rule that binds is the owner's D-B5 determination (PB3666, 2026-10-24): every store of characters into a boolean item converts them, '1' to 1 and anything else to 0. That covers every path from an alphanumeric or national sender, INCLUDING 'a group-to-elementary path', so that DISPLAY and the operators agree. §14.9.25.4 GR4 (no conversion of internal representation; bit and national groups treated as elementary) fixes only that the receiving AREA takes the sender's BYTES. The receiver's characters are then decoded from those bytes. Converting the DECODED characters is D-B5's normalization of undefined content, not a representation conversion. Converting the raw bytes before decoding, which review R1-1 rightly rejected, is one. Expected: MOVE GA ('A1Z1') TO BN (PIC 1(4) USAGE NATIONAL) leaves BN = 0000, because the pairs x4131, x5A31, x2020 and x2020 decode to characters other than '1'. That is what MOVE GA TO BN(1:2) already does. A READ or RETURN of an elementary boolean record area goes through the same single storage-area store (§14.9.30.4 GR13 c) and §14.9.34.4 GR3: the record 'is made available in the record area'), so it should get the same conversion. What a store cannot close is content that reaches the item through ANOTHER DESCRIPTION OF THE SAME STORAGE: a group receiver's area (GR4), a REDEFINES view, or storage shared by a BY REFERENCE argument (and, not probed, EXTERNAL, BASED or ADDRESS OF aliases).

**Action:** Close the store bypasses in code, then make the three texts say the same thing. Fix: add a category-boolean arm to ReceivingStore.StorageCharacters that converts the DECODED characters through RuntimeApi.BoolFromCharacters: BoolFromCharacters(NatReadWindow(area, 0, positions)) for a national item and BoolFromCharacters(area) for a display boolean. USAGE BIT stays as it is, because every bit pattern is valid. StorageArea, SliceStorageArea and MoveEmitter.GroupRecord all decode through StorageCharacters, so this one arm covers three cases: the whole national boolean receiver of a GR4 group move, the record-value receiver, and READ or RETURN into an elementary boolean record area (display and national). It matches the slice arm, which PlaceRenderer.Write already converts. ReceivingStore.Characters' boolean arm then keeps only the boolean zero fill for a display area. The drift test currently pins the national exemption ('is not { Usage: Usage.National or Usage.Bit }'); change it to require the StorageCharacters boolean arm. Extend golden pb3666_boolean_receiver_converts_characters with three cases: MOVE GA ('A1Z1') TO BN PIC 1(4) USAGE NATIONAL gives DISPLAY 0000 and B-NOT 1111; the N'101' group gives 101; and a READ of 'A1Z1B101' into an elementary PIC 1(8) record gives 01010101. Determination text, word for word in DATA_MODEL D19, CONFORMANCE D-B5 and the StrStoreBoolean summary: 'Every STORE into a boolean item converts its characters. That includes a GR4 group move (the decoded characters of a national or display receiver; a USAGE BIT receiver's bits are all valid) and a READ or RETURN into an elementary record area. A boolean item can still hold a character other than 0 or 1 only through another description of the same storage, which no store into the item reaches: a group receiver (GR4 moves the group's bytes), a REDEFINES view, or storage shared through a BY REFERENCE argument, EXTERNAL, BASED or ADDRESS OF. That content is undefined (§14.6.13.2 1)), and the boolean operators read such a position as zero.' Remove the 'Two things bypass it' and 'Two exemptions' wording from DATA_MODEL and the national-exemption sentence from D-B5. If the owner wants no code change, the alternative is to keep the code and list four bypasses in all three texts: the national group move, READ or RETURN into an elementary record, and the alias class. I do not recommend it, because the whole-item national arm would still disagree with its own reference-modified arm.
