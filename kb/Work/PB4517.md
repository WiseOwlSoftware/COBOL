## Landing (wave 20261852 A)

**Re-probe** (`cobol pwfunc.cob --source-format free --run` on the branch base): `error COBOL0899: RD 'R': a FUNCTION
reference inside a PRESENT WHEN condition (ISO §13.18.41) is not yet implemented`. **The root was wider than the refusal.**
The report clauses bind before the first statement and outside every statement (`StatementBinder.Bind` →
`ReportWriterBinder.BindReportGroupClauses`), yet a function-identifier, a function-bearing subscript or an inline invocation in
them registers an operand-evaluation step on the statement-scoped pending list. Undrained, the FIRST procedure statement
hoisted those steps, so they never ran at a presentation. The refusal hid it for PRESENT WHEN only. Measured siblings on the
same base, both SILENT WRONG ANSWERS: `SOURCE WS-T (FUNCTION MOD (WS-N, 2) + 1)` printed spaces on every line (expected
ODD / EVN / ODD), and `SOURCE FUNCTION user-fn (WS-N)` printed 0 on every line (expected 1 0 1). SOURCE with an intrinsic
alone was right only because an intrinsic registers no step.

**Fix.** Every report clause operand is its own per-evaluation window (the ONE drain, `UdfBinder.DrainPerEvaluation`): a
PRESENT WHEN condition becomes a `BoundUdfEvaluated` (its IIFE runs in the presence probe), a SUM addend and a VARYING FROM / BY
a `BoundUdfEvaluatedExpr`, and a SOURCE operand (both forms) and the CODE identifier keep their steps beside the value. The
emitter runs them at each evaluation (`ReportWriterEmitter.EmitSteps`): before the placement in the compose, inside the sum
and rolled-total closures, before each VARYING setting (a BY with steps is stepped, never the closed form), inside the CODE
read. A GENERATE or TERMINATE that can reach a report with steps counts as having evaluated them, so it takes its
`BoundActivationSite` (§14.9.33.4 GR2 a) 2.). `BindReportGroupClauses` throws if anything is left on the lists, so a future
clause operand that skips the window fails loud. The COBOL0899 arm, its catalog entry and `HasToken` are deleted.

**Witnesses.** `conformance-suite/cases/13.18.41-PRESENT-WHEN/pb4517-report-clause-functions` (2002: every arm above,
values derived in its header) and `pb4517-present-when-function-at-85` (refused COBOL0900 by the clause's own 2002 gate).

**Left open (a lead in the wave report):** a report-clause activation's §14.9.18.4 GR1 b) activator profile is the empty
profile (`TurnState.ProfileAt(0)`), not the presenting GENERATE's, so a condition a user function propagates with RAISING
from a report clause is not raised in the activator even where the GENERATE enables its checking.
