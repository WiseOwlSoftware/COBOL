# PB4150 — does per-row parallelism beat the partition classes now that M6 removed the lexer lock?

**Sites:**
- `tests/_shared/TestPartitioning.cs` (`SliceRows`, the slot types, `TestPartitionAudit`)
- `tests/WiseOwl.Cobol.Tests.Conformance/ConformanceSuiteTests.cs#ConformanceSuiteTestsBase` and the other partitioned
  families (`VersionMatrixTests`, `NistDifferentialTests`, `OptionalWordSubsetDriftTests`)
- `tests/Directory.Build.props` (test-host settings; server GC, PB2526)
- `docs/rearchitecture/DESIGN-test-build-ci.md` sections 3.11, 3.11.1 and the M6 measurements

**The question.** xUnit 2.9.2 parallelizes by test collection, and each class is one collection, so every row of a
`[Theory]` in one class runs serially. The repository answers that with partition classes (PB2527; PB4146 made their
balance a share check). Section 3.11.1 declared the class-split lever exhausted, but it measured that under the ANTLR
lexer's ATN-simulation lock; M6 removed the lock (one benchmark went from 110.1 s to 3.4 s at one thread, with zero
contended acquisitions) and server GC was adopted after it (PB2526). The doc itself says the partition counts are
re-measured after M6. A framework that runs theory rows inside one class in parallel would make every partition
class, slot type and share audit unnecessary (CLAUDE.md rule 5: the shape that makes the next case automatic).

**The experiment (on an experiment branch that does not land the package).**
1. Arm A, today: the Conformance assembly as on main (32 partition classes), compiled-program cache OFF, server GC.
2. Arm B: the same assembly with `Meziantou.Xunit.ParallelTestFramework` (the latest release that supports xUnit v2),
   theory rows parallel inside a class, the same thread cap; if it needs the partition classes collapsed to show its
   effect, measure that variant too.
3. Same host, arms alternated, at least three runs each, the host otherwise idle (no other gate in its slot); record
   wall time, CPU utilisation, GC pause share and the pass set. The pass sets must be IDENTICAL; any row that fails only
   under arm B is shared mutable state and is listed by name (for example `OptionalWordBaselines`, console
   redirection, the current directory).
4. If arm B clears the bar, repeat the comparison on the Unit assembly.

**The bar.** Arm B is adopted only if it is faster by more than run-to-run noise (state the noise measured) with an
identical pass set. A wall-clock reading is evidence here, never a test assertion (PB1590).

**Done when.** The measurements are in this note and in DESIGN-test-build-ci section 3.11.1 (replacing the pre-M6
"exhausted" verdict with the post-M6 numbers, whatever the outcome), and the determination is written: either adopt
(a new defect note naming every site the replacement deletes: the partition classes, slot types, `TestPartitionAudit`,
its drift tests, and `gate_plan.py`'s collection-is-a-class model) or keep the partitions with the measured reason.
