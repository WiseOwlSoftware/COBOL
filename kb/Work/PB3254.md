## Landed (wave 1105, group G)

**Re-probed on this worktree's build (base `c042f44e0`).** The note reproduced exactly: with `INPUT PROCEDURE IS S-B THRU S-A` over sections (S-A = A1, A2 physically before S-B = B1, B2, B3) a file SORT in B2 and one in A1 compiled with no diagnostic, while `S-A THRU S-B` drew COBOLNET2700 at both.

**Fix.** `PcRange` stores `SpanLow`/`SpanHigh` (private, set by `At`, `Of`, `EmptyAt`); `Through` composes the hull of both operands' spans and leaves `(Start, End)` and `IsEmpty` as they were; `Spans`/`SpannedPcs` read the stored span. An empty range is the gap `(s, s-1)`, so a hull with an empty operand covers exactly the paragraphs between, and an empty span agrees with `IsEmpty`. AFTER: both SORTs draw COBOLNET2700 at their own positions. The SR3 ban, the MERGE/COMMIT/ROLLBACK arms of `GateSortMergeProcedures` and `ProcedureReach.Closure` (14.9.28.3 SR8) all read `Spans`/`SpannedPcs`, so one change covers all four arms; every other `Range.Start`/`End` reader in the compiler is a single procedure-name, an emit pair or a declarative's own contiguous section.

**Goldens.** `conformance:85/pb3254_sort_inverted_section_thru` (legal inverted section THRU, runs), negatives `pb3254-sort-in-inverted-section-sort-procedure-first` / `-last` (all editions, COBOLNET2700) and `pb3254-merge-in-inverted-section-sort-procedure` (2023, COBOLNET1572); unit test `ProcedureRangeEmptinessDriftTests.ThroughSpansEveryParagraphOfBothOperandsInWhicheverOrder`. Design: `docs/COBOLNET_CONTROL_FLOW_DESIGN.md` D5a.
