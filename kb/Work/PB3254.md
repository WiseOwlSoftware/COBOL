**Scenario:** PcRange carries only (Start = first pc of procedure-name-1, End = last pc of procedure-name-2); Through() drops procedure-name-1 End and procedure-name-2 Start, so for INPUT PROCEDURE IS S-B THRU S-A with S-A (A1,A2) physically before S-B (B1,B2,B3), Spans covers only A2..B1. MEASURED with the built CLI (main, PcRange/VersionConformancePass unchanged since the pin): a file SORT written in B2 (inside procedure-name-1 itself) and one in A1 (inside procedure-name-2) both compile with no diagnostic, while the same program with S-A THRU S-B reports COBOLNET2700 at both. The same lossy span seeds ProcedureReach.Closure (SpannedPcs) for 14.9.28.3 SR8, and the MERGE/COMMIT/ROLLBACK arms of GateSortMergeProcedures read the same Spans.
