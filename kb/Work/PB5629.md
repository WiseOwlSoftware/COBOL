# PB5629 - the GLOBAL name-uniqueness screen's two second-order effects

**Sites:**
- `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.NameUniqueness.cs` (`DataBinder.ScreenGlobalNameUniqueness`)
- `conformance-suite/cases/13.18.27-GLOBAL/pb5150-global-subordinate-name-reused-by-local-record.cob` (whole: the golden does not name the same-record arm)

**Status of the candidate: NEEDS ADJUDICATION.** The first half is a candidate `rejects_legal_source`, not a verified one.

**1. Two same-named subordinates inside one GLOBAL record (R1-3).** kb/Work PB5150 widened the screen so that "All
data-names subordinate to a global name are global names" (§2023:13.18.27.4 GR1, `cite.py --check` OK) and §2023:8.4.2.1
forbids the same name for a global item and any other data item of the source element ("The same name shall not be used
both as the name of an item possessing the global attribute", `cite.py --check` OK). The screen therefore also refuses
two same-named subordinates inside ONE GLOBAL record, or inside two records of one GLOBAL FD (the loop in
`ScreenGlobalNameUniqueness` counts each pair once the first is global). That is a common shape in real programs
(the PB5150 reviewer's words) and it compiled on main before PB5150. The adjudication
discusses only two GLOBAL records and local-versus-global; no golden pins or names this arm. Open question: does
§2023:8.4.2.1's "any other data item" reach a second subordinate of the same GLOBAL record, where qualification already
distinguishes them? The adjudicator decides; if it is legal, the screen must leave it and the golden must pin it.

**2. Where a TYPE-copy clash is reported (R1-2).** Now that copied subordinates count as global, a clash created by TYPE
copies is reported at the TYPEDEF subordinate's line (the copy's `DeclaredAt`), not at "the LATER entry of the two, where
the user can edit it" the doc comment promises. The user must edit the entry that uses the TYPE, not the TYPEDEF. Same
function, so same note.

**Fix direction.** Adjudicate half 1 first (a `kind: adjudication` note or a record in this directory). Half 2: report
a copied item's clash at the entry that brought it in (the TYPE or SAME AS user), and pin it with a diagnostics JSON.
