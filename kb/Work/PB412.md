# PB412 — the grammar is the union of two formats plus a deleted one, and nothing subtracts the complement

**Row:** `FMT-14.9.17.2`. All measurements re-run on this worktree's HEAD `cobol.exe` (base 89044aa0).

## THE MECHANISM

`src/Cobol.Net.Frontend/Grammar/Core/CobolControlFlow.g4:207-209`:

```
goToStatement
    : GO TO? procedureName? (procedureName)* (DEPENDING ON? dataReference)?
```

That is the union of ISO §14.9.17.2 Format 1, Format 2 and the ANSI-85 target-less form, with every element
optional and the procedure-name list unbounded in **both** arms. Neither of the two places that could re-narrow
it does:

- `src/Cobol.Net.Compiler/Validation/VersionConformancePass.cs#VisitGoToStatement` (`:1604-1609`) inspects the
  shape only to fire the bare-form edition gate:
  `if (ctx.procedureName().Length == 0 && ctx.dataReference() is null) _p.Check(Constructs.BareGotoRemoved2002, …)`.
- `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/ControlFlowBinder.cs#BindGoTo` (`:219-237`) dispatches on the
  POSITIVE cases only — `dataReference is not null && names.Length >= 1` is Format 2 (`:222`), `names.Length == 0`
  is the bare form (`:233`), and **everything else falls into the Format-1 arm**, which reads `names[0]` (`:234`)
  and drops the rest on the floor.

The complement of the two formats is therefore accepted rather than diagnosed. This is the two-arm-dispatch
shape with the arms mislabelled: the arm that WAS written is the edition gate; the arm that decides *which
format this is* was never written at all.

## THE FORMAT, AND THE `--check` LINES FOR WHAT SURROUNDS IT

§14.9.17.2 is a pair of FIGURES, so it is cited for the format and described rather than quoted. As transcribed
in `specs/ISO_COBOL.md` (§14.9.17.2, rendered from the printed page): Format 1 is GO, the optional word TO, and
a single required procedure-name-1, with no DEPENDING; Format 2 is GO, the optional word TO, one or more
procedure-names under an ellipsis, then a required DEPENDING, the optional word ON, and identifier-1. Only GO
and DEPENDING are underlined. **Neither format admits two procedure-names without DEPENDING, and neither admits
DEPENDING with zero procedure-names.**

- `--check 14.9.17.3 "Identifier-1 shall reference a numeric elementary data item that is an integer"` →
  `OK §14.9.17.3 1)` — Format 2's own operand rule (its enforcement is [[PB210]]'s row, not this one).
- `--check 14.9.17.3 "A GO TO statement shall not be specified in a WHEN phrase of an exception-checking PERFORM statement"`
  → `OK §14.9.17.3 3)` — the one §14.9.17 placement rule the compiler DOES enforce (COBOLNET1608, measured
  firing on `probe/refute-go-to/s5-goto-nested-inline-perform.cob`), which is why the format-shape gap is the
  outlier rather than the norm.
- `--check 4.2.2 "syntax"` → `OK §4.2.2` — the standard owes a compile-time indication for source no format
  admits.

`cobol.exe <src> --std <ed> --run`, probes in `scratchpad/probe-g3-goback-goto/go-to/`.

| `p13-dep-no-names.cob` | `GO TO DEPENDING ON W-N.` | rejected | compiles clean at **2023 and 2002**, then aborts at run time: `CobolNet.Runtime.NotImplementedCobolFeatureException: … GO TO DEPENDING without procedure-names (ISO §14.9.17 Format 2)` |

Controls, all measured correct on HEAD and all of which the fix must keep: `p2-no-to.cob` (`GO PARA-A.` → `A-REACHED`,
TO genuinely optional); `p10-fmt1-section.cob` (a SECTION target enters its first paragraph and falls through
— `S-TWO-FIRST` then `S-TWO-SECOND`); `p17-qualified.cob` (`GO TO DUP-P IN S-TWO` reaches S-TWO's copy);
`p11-bare.cob` (the 85-only target-less form correctly rejected at 2023 by
`COBOLNET0811 … removed in COBOL-2002`).

Probe 1 is the worse of the two: a program that means nothing under the standard is given a *specific*
behaviour instead of a diagnostic, so the operand the programmer wrote vanishes without a word. Probe 2 tells
the user a feature is unimplemented when the truth is that the source is illegal, and defers to run time a
defect the compiler had in hand at parse time — a program whose only fault is this typo can ship and abort in
production. The loud stage is `SetAlterBinder.cs#AlterBindBareGoTo:98-99`.

## THE SHAPE OF THE REPAIR

⛔ Not a pair of `if`s in `BindGoTo` (CLAUDE.md rule 5). **The grammar should present the formats as separate
alternatives** so that the shapes no format permits fail in the parser:

```
goToStatement
    : GO TO? procedureName+ DEPENDING ON? dataReference   // Format 2
    | GO TO? procedureName                                // Format 1
    | GO TO?                                              // the 85 target-less form, edition-gated
    ;
```

(Order matters — ANTLR takes the first matching alternative, `feedback_grammar_precedence` — and the bare arm
keeps its existing `BareGotoRemoved2002` gate rather than a parse error, because the four-compilers rule wants
the edition named.) `BindGoTo` then dispatches on which alternative matched instead of reconstructing the
format from optional children, and every future edit to either format stays automatic instead of needing a new
hand-written validation clause. Add a drift test that `goToStatement` has exactly as many alternatives as
§14.9.17.2 has formats plus the gated legacy arm.

If the owner prefers a bind-time diagnostic over a parse error for these two shapes (better messages), the
diagnostic still belongs to a *structure* — one table of (names-count, has-depending) → format-or-error — not
to two inline conditions.

## THE SIBLING SWEEP

1. **`ALTER`** shares the target-less form's machinery (`SetAlterBinder.cs#AlterGoTo`, `AlterBindBareGoTo`);
   re-check `probe/p11-bare.cob` and the ALTER goldens at 85 after any grammar re-shaping.
2. **Every other statement rule written as an optional-everything union.** The mechanism here is "one ANTLR
   alternative covering N general formats, with the format choice reconstructed later" — grep the `.g4` files
   for rules whose every element is `?`-suffixed and check each against its clause's format count. That sweep is
   the value of this note beyond the one row.
3. `constructs.json`'s `bare-goto-removed-2002` row already carries the version-matrix coverage for the legacy
   arm; the two new rejections need negative fixtures and the four controls above need goldens, in the same
   commit (`feedback_goldens_ship_with_the_feature`).
4. Edition sweep: both illegal shapes were measured accepted at every edition probed (85/2002/2014/2023), so the
   new diagnostics must be asserted at all four.
