# PB5305 - decision: a duplicated cd-name is one defect, charged to 1985-SR-IV.4.3.8.1-1 (every referenced user-defined name must be unique); the seven Communication rows that name a cd-name conform

**Question (held-4's seven slice-66 rows).** Two CD entries with one cd-name (`CD XCD FOR INPUT`, then `CD XCD FOR OUTPUT`) compile at --std 85, and every statement binds to the LAST one. Does that break each statement's "cd-name-1 must reference an ... CD" rule (`1985-SR-XIV.3.2.3-3`, `1985-SR-XIV.3.3.3-1`, `-2`, `-3`, `1985-SR-XIV.3.4.3-1`, `1985-SR-XIV.3.5.3-1`, `1985-SR-XIV.3.6.3-1`)?

**Decision.** 1985 forbids the program, by its uniqueness rule, not by the statement rules. "Every user-defined name explicitly referenced in a COBOL source program must be uniquely referenced" (§1985:IV.4.3.8.1), and a cd-name cannot be qualified, so two CDs with one name make every reference to it ambiguous. That is ONE defect, charged to row `1985-SR-IV.4.3.8.1-1` and filed as kb/Work PB5307. The seven statement rules constrain the KIND of CD a reference designates ("Cd-name-1 must reference an output CD when the OUTPUT phrase is specified"), and the refuter of each upheld the adjudicator's reading from the text: 1985 states uniqueness once, over every reference, and where it ties uniqueness to an operand it writes a separate clause. So the seven rows are CONFORMS, and they are recorded in the PB4996 held-rows batch.
