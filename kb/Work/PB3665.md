# PB3665 — STRING accepts one integer function and refuses another as a literal

✅ **APPROVED BY THE OWNER (2026-10-24).** The owner (2026-10-24 ~18:00 PDT, attended operator session 0a5c7c77), after the operator's explanation of the spec text and GnuCOBOL's behavior for PB3664-PB3666: "Approve all three for fix, and make DISPLAY and the boolean operators agree, and record the choice in docs/CONFORMANCE.md".

**Sites:** `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/StringUnstringBinder.cs` (`Sr1Offence`, its
`BoundNumericLiteral` arm at about line 457; callers at about :54 for the sender and :68 for the delimiter).

## What happens (re-run by the operator at 300fd78bd)

```cobol
01 G.
   05 G-A PIC X(3).
   05 G-B PIC X(4).
01 N PIC 9(4) VALUE 7.
01 R PIC X(4).
...
    STRING FUNCTION INTEGER(N) DELIMITED BY SIZE INTO R    *> compiles; R gets 7
    STRING FUNCTION LENGTH(G) DELIMITED BY SIZE INTO R     *> refused
```

The refusal reads: `error COBOL1626: STRING sending operand 'FUNCTION LENGTH(G)' is a numeric literal; SR1 admits
only alphanumeric, boolean and national literals (ISO §14.9.43.3 SR1)`. `FUNCTION LENGTH` of a fixed-size item folds to a
`BoundNumericLiteral` with `FunctionValue = true`, and `Sr1Offence`'s literal arm ignores `FunctionValue`. The
`DELIMITED BY FUNCTION LENGTH(G)` position is refused the same way.

## The rules (checked)

- §14.9.43.3 1): "All literals shall be described as alphanumeric, boolean, or national literals, and all identifiers,
  except identifier-4, shall be described implicitly or explicitly as usage display or national." §14.9.43.3 8):
  "Where identifier-1 or identifier-2 is an elementary numeric data item, it shall be described as an integer…"
- §8.4.3.2.1: "A function-identifier references the unique data item that results from the evaluation of a function."
  It is an identifier, never a literal, so the message's reason is false whatever the verdict.
- §15.2 4) and 5) give numeric and integer functions class and category numeric with an operational sign. Unlike
  alphanumeric (usage display), national and boolean functions, they state NO implicit usage. §8.4.3.2.4 1): "the
  temporary data item is an elementary data item whose description and category are specified by the definition of that
  intrinsic function".

## The question to adjudicate

Does an integer function's temporary item meet SR1's "described implicitly or explicitly as usage display or national"?

- **If yes** (its usage is the implementor's to define, and WiseOwl's integer temporaries take display semantics), both
  statements are legal. The LENGTH refusal rejects legal source, and the fix makes `Sr1Offence` honor `FunctionValue`.
  GnuCOBOL accepts both, which is the owner's precedence for latitude (CLAUDE.md rule 1).
- **If no**, both are illegal. The INTEGER arm under-rejects, and the LENGTH arm must say "an integer function is not
  usage display or national" instead of calling it a literal.

Either way the two arms must agree, and the diagnostic must not call a function-identifier a literal. Decide from the
spec first, record the latitude choice in `docs/CONFORMANCE.md` if it is one, and sweep the other statements whose
rules require usage display (UNSTRING, INSPECT, DISPLAY's operand screens) for the same folded-literal arm.

## Decided (2026-10-24)

The owner approved the operator's recommendation: REFUSE both forms. SR1 requires every identifier except identifier-4 to be "described implicitly or explicitly as usage display or national"; §15.2 gives alphanumeric functions implicit usage display, national functions usage national and boolean functions usage bit, and states no usage for numeric or integer functions. So an integer or numeric function-identifier is not a legal STRING sending operand or delimiter. The fix: (1) `FUNCTION INTEGER(N)` and every unfolded numeric or integer function in those positions is refused (today it compiles: under-rejection); (2) a FOLDED function (`BoundNumericLiteral` with `FunctionValue = true`) is refused for the SAME reason with the same message, which names the identifier rule, never "a numeric literal"; (3) a real numeric literal keeps COBOL1626's literal message; (4) sweep the statements with the same usage rule (UNSTRING, INSPECT and their identifier positions) for the folded-literal arm and the unchecked function arm; (5) goldens for each refused form and a positive one for an alphanumeric function (`FUNCTION UPPER-CASE`) as a sender. Allocate any new diagnostic code from the orchestrator.

## GnuCOBOL 3.2 (read in the pinned 3.2 source, 2026-10-24)

It accepts both and is no precedent: `cobc/typeck.c` `cb_emit_string` checks usage display or national only for a data item (`CB_TAG_REFERENCE`); a literal carries `/* TODO: check for type here */` (so it also accepts `STRING 7 ...`) and a function call falls into `default: break;`. At run time `FUNCTION INTEGER(N)` stores the raw bytes `\a\0\0\0`, because `cob_intr_integer` returns a 4-byte binary field (`cob_alloc_field`), and `FUNCTION LENGTH(G)` stores `7` because `cobc/tree.c` folds LENGTH of a fixed item into a numeric literal.

## Landed (2026-10-24, wave 20261102 group A)

Re-probed on a fresh build: `STRING FUNCTION INTEGER(N)` compiled and stored 7, `STRING FUNCTION LENGTH(G)` and `DELIMITED BY FUNCTION LENGTH(G)` were refused as "a numeric literal". The sweep found the rule wider than the note: every numeric function (`ORD`, `NUMVAL`, `PI`), the boolean function (`BOOLEAN-OF-INTEGER`, usage bit, sent "0111") and the same functions at INSPECT's identifier-3 .. identifier-n positions (TALLYING FOR, REPLACING BY, CONVERTING, BEFORE/AFTER) compiled clean. UNSTRING already refused them by SR2's category, and only worded the folded LENGTH delimiter as a literal.

Fix: `IntrinsicSig.ImplicitUsageOf` states §15.2 1)-3) once (alphanumeric display, national national, boolean bit, numeric/integer/index none); `IntrinsicArgumentRules.FunctionIsNotDisplayOrNational` reads a function-identifier in all three shapes it reaches a verb binder (call, lowered tree, folded literal) and is asked by `StringUnstringBinder.Sr1Offence` (before its numeric-literal arm) and `StatementValidation.CheckInspectFunctionUsage` (COBOL1626, COBOL0847; no new code). The UNSTRING delimiter wording names the folded function as category numeric (SR2). `ConditionBinder`'s and `StaticUsageOf`'s private copies of the usage table now read `ImplicitUsageOf`. Determination D-FNUSE in docs/CONFORMANCE.md. Goldens: `pb3665-*` (nine refusals) and the controls `pb3665_string_function_usage_controls`, `pb3665_inspect_function_usage_controls`; `da4_function_sending_operand` and `pb26_ec_argument_function_every_statement` sent a numeric function to STRING and now send an alphanumeric one. Drift pin: `DisplayOrNationalUsagePredicateDriftTests`.
