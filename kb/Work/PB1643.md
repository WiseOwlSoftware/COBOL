# PB1643 — OPEN

Filed 2026-09-27 by the train-65 lander from the wave-65 F implementer report (PB1230). Not related to PB1230's root.

**Observed.** With `DECIMAL-POINT IS COMMA`, `DISPLAY 1,5` prints `1.5`. `DISPLAY K`, where `K CONSTANT AS 1,5`,
prints the same (since PB1230 the constant substitutes the literal as written, so the two are identical).

**Repro.** `E:\Temp\claude\E--COBOL\eb162d4b-e0bb-4027-b8a0-86fd190d20be\scratchpad\w65f\probe\p2.cob`.

**Rule.** §14.9.11.4 GR1: the conversion of data for DISPLAY "is defined by the implementor". §12.3.7.4 GR14 a) makes
the comma the decimal separator in the program's literals and PICTURE strings. The open question is whether the
implementor-defined conversion of a numeric literal should honor that. This is a determination, not necessarily a
defect. If the determination is that it should, it becomes a wrong-output defect.

**Code site.** The display rendering of `BoundNumericLiteral`: the canonical dot-decimal text produced by
`ExpressionBinder.CheckLiteral` (`src/Cobol.Net.Compiler/Binding/Procedure/ExpressionBinder.cs:1022`), which DISPLAY
renders as written. Precedence for the determination (CLAUDE.md rule 1): the ISO spec does not control, so GnuCOBOL,
then IBM Enterprise COBOL or Micro Focus. Record the choice in `docs/CONFORMANCE.md`.

**Spec and precedence (cite.py --check OK; the refuter re-ran all and added §12.3.7.4 GR1 and §8.3.5 2)).** `§14.9.11.4 GR1`: "Any conversion of data required between literal-1 or
the data item referenced by identifier-1 and the device is defined by the implementor", so ISO does not fix the character image: IMPLEMENTOR LATITUDE. `§12.3.7.4 GR14` and `GR14 a)`:
with DECIMAL-POINT IS COMMA the decimal separator exchanged with the grouping separator, "the character written in numeric literals to represent the decimal separator shall be the comma";
`§3.54`; `§15.3.3.2` (time formats follow the clause); the NUMVAL arguments follow it too. The refuter's survey: the only carve-out is the locale-format PICTURE. Precedence (CLAUDE.md
rule 1): GnuCOBOL 3.2.0 prints the literal as written with the program's separator in `default`, `cobol85`, `cobol2002`, `cobol2014`, `xopen`, `mf` (`1,5`, `-1,5`, `+0,25`, `,5`, `1,50`, `001,5`);
only the vendor configurations `ibm`, `mvs`, `bs2000`, `acu` (`pretty-display: no`) print digits only. WiseOwl's own convention is already "the literal as written" (DOC-A.1-92; golden
`2002/pb1230_constant_literal_as_written`); only the separator is canonicalised to `.` before DISPLAY. The decision is therefore a determination, no owner question. Attack lines that failed
(digits only; dialect configuration; an existing determination; a standard-defined run-time separator that ignores DPC): see the refuter section 2.
