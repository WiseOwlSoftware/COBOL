# PB4356 - PB4329's documentation residue

**Sites** (measured on the branch head `origin/worktree-wf_25c06ee4-5ac-1`, PR #964, in the merge queue; PB4329 has not landed, so the old text is what `origin/main` 2ce2e70a2 carries today, and the branch head did not change these three sites):
- `docs/DOC_INDEX.md` row at line 193 (`scripts/test_population.py`): says CI's `conformance-population` job checks each platform's shard trx against the listing each shard took from its own build, and lists the scrub as `WISEOWL_COBOL_GATE_*`, `VSTest*`, `RunSettingsFilePath` without `WISEOWL_COBOL_SHARD`.
- `docs/DOC_INDEX.md` row at line 192 (`scripts/filter_population.py`): says the `inv1-strong-2023` CI leg calls it.
- `docs/rearchitecture/DESIGN-test-build-ci.md` lines 232-233 (209 on main): calls the matrices "the conformance jobs" and quotes the check name "Greenfield conformance (Linux, sharded) (corpus-nist, ...".

True after PB4329 (`.github/workflows/build-and-test.yml` on that head): the tests run as weighted shards, jobs `linux-shard` (5 shards, `WISEOWL_COBOL_SHARD: k/5`) and `windows-shard` (7 shards), each running every test assembly, with the test framework dealing it the classes of its shard (`tests/_shared/GateLegs.cs`, GateShard). Shard 1 of each OS uploads the one `--list-tests` listing (step "List the discovered populations (shard 1; scripts/test_population.py, scrubbed)"), and `ci-gate` runs `test_population.py check` per OS and assembly against that one listing. INV-1-strong is a step of every Linux shard ("INV-1-strong, this shard"), not a leg. `WISEOWL_COBOL_SHARD` is the one variable the scrub leaves alone (workflow comment near line 78). The check names are `Linux shard k/5` and `Windows shard k/7`.

Fix: rewrite the three sites to this shape in the change that lands PB4329 (or right after it), naming `ci-gate` as the owner of the check and `WISEOWL_COBOL_SHARD` in the scrub list. Sibling sweep: `git grep -n -E "conformance-population|inv1-strong-2023|conformance jobs|Greenfield conformance" -- docs README.md .claude scripts` after PB4329 lands.
