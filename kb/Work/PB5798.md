# PB5798 - at --std 85 IF with NEXT SENTENCE and END-IF is accepted, which the 1985 rule forbids

**What is wrong.** `IF A = 1 NEXT SENTENCE END-IF` (`if1.cob`) and `IF A = 1 DISPLAY "ONE" ELSE NEXT SENTENCE END-IF` (`if2.cob`) compile and run at `--std 85` with no diagnostic; control goes to the next sentence. `§1985:VI.6.16.3 SR3` says "If the END-IF phrase is specified, the NEXT SENTENCE phrase must not be specified". I ran `if1.cob` at `--std 85` myself: it compiled and printed `NEXT`. At 2023 both compile with only the archaic NEXT SENTENCE warning, which is kb/Work PB396's recorded determination for 2023 (owner-overturnable latitude); that acceptance is not touched. 1985 has no latitude, because its own syntax rule forbids the combination: cause (a), an 85 arm is missing.

**Sites:**
- `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolControlFlow.g4#ifStatement` (admits END-IF after NEXT SENTENCE at every edition)
- `src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs#VisitNextSentenceStatement` (gates only the 2023 archaic warning and never looks at END-IF; no 1985 check)
- `src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs#VisitIfStatement` and `src/WiseOwl.Cobol.Editions/Diagnostics/DiagnosticCatalog.cs#NextSentenceWithEndIf` (the fix, COBOL7486)

**1985 rows this note blocks.** `1985-SR-VI.6.16.3-3`. `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094), so the row is named here.

**2023 rows whose stored verdict is wrong.** None: cause (a).

**Existing note.** None for the 1985 rule. kb/Work PB396 (landed) holds the 2023 acceptance determination and does not address `§1985:VI.6.16.3 SR3`.
