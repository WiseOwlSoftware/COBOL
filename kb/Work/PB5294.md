# PB5294 - DEBUG-SUB-n and DEBUG-CONTENTS of a subscripted data-item trigger describe the occurrence the subscript names AFTER the statement: the subscript expressions are evaluated again when the debugging section runs, where 1985 evaluates them once at the start of the statement

**Sites:**

- `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/DebugTriggerEmitter.cs` (`OccurrenceNumbers`, `DataItemImage`, `FireText`)

**Mechanism.** GR14 enters "the occurrence number of each level" of the reference, and GR24 makes DEBUG-CONTENTS the content of "the data item referenced by identifier-1"; subscripts are "evaluated only once as the first operation of the execution of that statement" (§1985:IV.4.3.8). `OccurrenceNumbers` and `DataItemImage` render the subscript expressions into the call that runs the section after the statement, so a statement that changes its own subscript (`MOVE TE (SUB) TO SUB`) reports the new occurrence and its content. The same mechanism as kb/Work PB5279 in RECEIVE.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids below. None of them is recorded: the non-conforming verdicts wait in `E:/COBOL-coord/scratch/coderead-85/p2-for-register.json`.

**Rules (2 claimed; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-GR-XV.3.2.4-14` - `§1985:XV.3.2.4 GR14` (read: PARTIAL, harm: wrong-answer): "the occurrence number of each level"
- `1985-GR-XV.3.2.4-24` - `§1985:XV.3.2.4 GR24` (read: PARTIAL, harm: wrong-answer): "at the time that control passes to the debugging section"

**Repro.** `E:/COBOL-coord/scratch/coderead-85/out-pipe/work-slice-68/p13/a.cob`: `01 T. 02 TE PIC 9 OCCURS 5.`, `01 SUB PIC 9 VALUE 2.`, USE FOR DEBUGGING ON ALL REFERENCES OF TE; `MOVE 4 TO TE (2). MOVE TE (SUB) TO SUB.`; `cobol.exe --std 85 --source-format fixed --run a.cob`.

**Observed (a build of origin/main f2cf36fd15, rerun 2026-11-11; main has since changed only `IndexedConnector.cs` under `src/`, which none of these repros reaches).** For the second MOVE: `D2 [TE ...] [+0004] [0    ]` and `SUB=4`.

**Expected (from the 1985 text).** `[+0002] [4    ]`: the reference is TE (2), whose content is 4.

**Fix direction (root cause, CLAUDE.md rule 4).** Capture each triggering reference's occurrence numbers (and so its place) at the start of the statement and pass the captured values to the section; test a statement that changes its own subscript.
