# PB5982 - the LINAGE data-names of an EXTERNAL file are not held to be external at `--std 85`

§1985:VII.3.7.4 GR11c: every file description entry for one external file connector must have "The same corresponding external
data items referenced by data-name-1, data-name-2, data-name-3, and data-name-4". `FD PFILE IS EXTERNAL LINAGE IS LN LINES`
with LN a WORKING-STORAGE item that is not EXTERNAL compiles at `--std 85` (lin1b, exit 0); two programs naming different
non-external items compile too (lin2b). The same source is refused COBOL1624 at `--std 2023`, and at 85 the PADDING CHARACTER
twin is refused COBOL1624 under §1985:VII.2.7.4 GR6. `ExternalFileConnectorRules.Check` gates the LINAGE screen on 2023
(`if (is2023 && f.Linage is { } lin)`, citing it as new in 2023), which the 1985 text contradicts.

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/ExternalFileConnectorRules.cs` (`ExternalFileConnectorRules.Check`)

## Fix shape
Run the LINAGE externality screen at 85 with the 1985 citation (GR11c), as the PADDING screen already does; check whether
2002 and 2014 have the rule in their own text and record it (2002 is frozen: note it, do not change it). Goldens at `--std 85`:
lin1b's shape and lin2b's, each refused COBOL1624, beside the PB5638 witnesses.
