# PB2143 — DISPLAY keeps an inline copy of the sending operand set

Found by the PB2114 implementer (wave 1028 group D), filed by the train-1028 lander.

PB2114 unified the `{identifier | literal}` sending operand into `CobolParserCore.g4#sendingOperand` for ten
positions. DISPLAY's operand list was left inline: naming the rule there kept every legal parse identical but changed
error recovery. Over the three test assemblies' lexer inputs, 83 error-recovery trees differed (0 on clean parses), 17
with a higher syntax-error count:

- `DISPLAY COLUMN.` at `--std=1985`: 1 syntax error before, 2 after.
- `DISPLAY COL COLS COLUMNS CRT CURSOR SCREEN.` at `--std=2014`: 2 before, 5 after.

So the grammar still writes the set twice, and `SendingOperandDriftTests` carries DISPLAY as its one recorded
exemption.

**Repro:** the `ReservedWordPositionConformanceTests` DISPLAY rows. Apply the unification to `displayStatement` and
compare the error count and the diagnostics.

**Code sites:** `src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4#displayStatement`;
`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/AcceptDisplayBinder.cs:233` (the binder reads the inline arms).

**Fix shape:** name `sendingOperand` in DISPLAY and restore the recovery: either an explicit error alternative for a
reserved word in operand position, or ANTLR error-strategy tuning, so that the reserved-word rows keep their single
named diagnostic. Then delete the exemption from `SendingOperandDriftTests`. Measure with the same token-stream and
error-tree differential PB2114 used.
