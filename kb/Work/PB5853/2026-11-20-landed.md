# PB5853 landed, 2026-11-20 (wave 20262115, group A)

**Fix.** `ReportWriter.PresentLine` no longer clamps a computed line below 1 to 1. The empty-page state that the clamp
protected is now its own value: `_physLine` is `long?`, null for "nothing printed on this page" (INITIATE, the page
feed), so line 0 can be a real line. LINE-COUNTER takes the line the rules compute: §1985:XIII.3.10.8 GR4d and GR6d,
§1985:XIII.3.10.6 GR3d, and at 2002/2014/2023 §2023:13.18.35.4 GR5c, whose arithmetic each later edition prints in the
same words. On an empty page, lines 0 and 1 both rest on the first physical line (one line lower when the device stands
on an open line). Every later line travels by its difference from the line before it, so the report file is
byte-identical and only LINE-COUNTER changes. In a paged report a computed line 0 lies above HEADING, which the binder
already refuses (COBOL2199, probe `pagedrh0.cob`, at 85 and 2023).

**Re-probe before the fix** (tree a2bd139087, `--std 85`): `lc0.cob` LC 0/3/5, `rh0.cob` LC 0/3/5, `lc1.cob` LC 0/3/6.
**After:** `lc0` LC 0/2/4 with the file `A`, blank, `A`, blank, `B` unchanged; `rh0` LC 0/2/4; `lc1` 0/3/6 unchanged.
`reinit0.cob` (the file left open by TERMINATE, then INITIATE and a first LINE PLUS 0): A and B land on new lines below
the earlier run's last line, with LC 1, at 85 and 2023.
