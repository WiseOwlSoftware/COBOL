# PB541

## Mechanism — usage-clause-p1
usage-p1-F4-report-printable-item-gate-tests-usage-is-display-where-sr7-admits-display-or-national

### Expected, from the standard
SR7 names TWO admitted phrases. `RD R-1. 01 DET-1 TYPE DE LINE PLUS 1. 03 COLUMN 1 PIC N(4) USAGE NATIONAL SOURCE W.` is conforming COBOL-2002-and-later source and shall compile and print. Conversely, a report GROUP entry carrying `USAGE COMP` is nonconforming (a report group item is exactly SR7's subject) and shall be diagnosed.

```
(the finding quotes no rule sentence verbatim, so there is nothing to --check; the implementer MUST quote §13.18.60.3 and re-run `cite.py --check` before writing a code comment)
```

### Observed
The gate is `Usage is not Display`, one alternative narrower than the rule, so the NATIONAL half rejects legal source with COBOLNET0899 at --std 2002, 2014 and 2023 (u_sr7_national, e85_sr7n_2002/_2014/_2023) while the DISPLAY spelling of the identical entry runs (u_sr7_display). The diagnostic's cited authority does not support it: §13.15 nowhere says printable items are DISPLAY -- the nearest text, §13.18.14.4 GR3, says only that 'There is a one-to-one correspondence between a column and a character in an alphanumeric character set' -- and the rule that actually governs the pairing, SR7, names NATIONAL explicitly. This is the a_real_clause_can_answer_a_different_question shape: a real § justifying an omission that a different, on-point rule contradicts. Two further consequences. (a) The PROHIBITIVE half is only accidentally right: COMP / BINARY / PACKED-DECIMAL are refused by the same staging gate rather than by an SR7 screen (u_sr7_comp, u_sr7_binary, u_sr7_packed), and INDEX / POINTER by a third message again ('has no PICTURE clause', u_sr7_index, u_sr7_ptr) -- so no diagnostic in the compiler states SR7. (b) A USAGE clause on a report GROUP entry is silently DISCARDED: `03 USAGE COMP. 05 COLUMN 1 PIC 9(4) SOURCE W.` compiles and runs (u_sr7_group), because the report binder hands usageText only to the printable leaf and never inherits or validates it -- the report-section face of the same GR1 gap as finding 2.

## Landed — 2026-09-21

RE-PROBED FIRST on this worktree's own build (base main 8e321d13b): `03 COLUMN 1 PIC N(4) USAGE NATIONAL
SOURCE W.` in a `TYPE DE` group still drew `error COBOLNET0899: RD 'R-1': a non-DISPLAY printable item at
COLUMN 1 (ISO §13.15 — printable items are DISPLAY) is not supported`, and `03 USAGE COMP.` over a printable
item still compiled and RAN. The note's SR7 quotation was re-run through `cite.py --check` (OK §13.18.60.3 7).
Annex A was checked as the note asked: `docs/CONFORMANCE.md` rates A.4.11 *Partial* and its staged-LOUD band
named this refusal, so it was a defect and not a recorded non-support; the band entry is corrected in this
change set.

ONE SCREEN, ASKED WHERE A USAGE BECOMES KNOWN. `DataBinder.Reports.ScreenReportUsage` is the rule's only text.
It is asked (a) of the USAGE CLAUSE as it is captured — the rule's own subject ("any USAGE clause associated
with a report group item"), and the ONLY place a GROUP entry's clause is visible — and (b) of the usage a
printable item SETTLES on when no clause stated one, which is §13.18.60.4 GR7/GR8's implied usage (`PIC N(2)`
with no USAGE clause is a national item). Asking it at (b) unconditionally reported one violation twice, so it
is gated on "no clause was written or inherited".

THE THREE FINDINGS IN THE NOTE, ALL THREE ANSWERED:
- the NATIONAL half of SR7 is live at 2002/2014/2023, and the edition gate still refuses it at 85;
- the prohibitive half is no longer accidental — COMP/BINARY/PACKED-DECIMAL/INDEX/POINTER are refused BY SR7,
  with SR7's own words and its own code **COBOLNET2198** (`ReportNonDisplayItem`, which cited §13.15 for a
  sentence §13.15 does not contain, is deleted and its id retired);
- a USAGE clause on a report GROUP entry is no longer discarded: it is screened, and §13.18.60.4 GR1 —
  "If the USAGE clause is specified or implied at a group level, it applies only to each elementary item in the
  group" — now carries it down the entry scope stack to the printable leaves, with §13.18.60.3 SR2's
  group/subordinate agreement ("the same usage shall be specified in both entries") on the same code.

MEASURED after, at 2023 and at 2002: an own-clause NATIONAL item prints beside a DISPLAY item on one line
(`[WXYZ ABC]` — one COLUMN per character, §13.18.14.4 GR9), a group-inherited NATIONAL item prints (`[PQR]`),
a picture-implied one prints (`[MN]`); `USAGE COMP` on an elementary entry, on a GROUP entry, and `USAGE INDEX`
are each refused COBOLNET2198; the SR2 conflict is refused; at `--std 85` the national report item draws
COBOLNET0900 on the REPORT ITEM in its own right.

⚠ ONE NEW DEFECT FOUND ON THE WAY, reported as a lead and NOT fixed here (it is the print stream's, not the
binder's): a national report item whose characters are above the 7-bit range prints `?` per character —
`SequentialConnector.PrintSafe` maps every char > 0x7F to `?` on a print-control write. Measured: `N"ÄÖÜ"`
reaches the report file as `???`. The goldens here use 7-bit national characters deliberately.
