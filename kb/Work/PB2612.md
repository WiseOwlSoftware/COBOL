# PB2612 — "the sequence" of SR2 is the consecutive IMPERATIVE statements, not the sentence

Found by the w1039g adjudication of battery #89's differential flips while probing `listings:1860` (PB397's rule;
`E:\COBOL-coord\scratch\reports\w1039g-PB397-report.md`, "Sibling DEFECT"). None of the 7 flips is affected.

## Rule (each checked with `cite.py --check`)

- `OK §14.9.17.3 2)` (Syntax rules): "If a GO TO statement represented by format 1 appears in a consecutive sequence of
  imperative statements within a sentence, it shall appear as the last statement in that sequence."
- `OK §14.5.1` (General): "Any statement with a conditional phrase that is not terminated by its explicit scope
  terminator is a conditional statement".

A conditional statement ends the consecutive run of imperative statements, so a GO TO written directly before one is
the last statement of its imperative sequence and SR2 is satisfied. All four editions; the rule text carries no
edition qualifier.

## Repro (re-probed on w1039x's build of `ea20c28e3`, `--std 2023`)

`E:\COBOL-coord\scratch\w1039x\probes\g1.cob` and `g2.cob`:

```
       P1.
           GO TO P2
           ADD 1 TO A ON SIZE ERROR DISPLAY "Z".
       P2.
           DISPLAY "P2" STOP RUN.
```

`g1.cob(8,5): error COBOLNET2967: A Format 1 GO TO ... this one is followed by ADD in the same sequence` (exit 70);
`g2.cob` (`GO TO P2` then `IF A = 1 DISPLAY "Y".`) draws the same error naming IF. The adjudicator also saw it inside a
phrase (`IF A = 1 GO TO P2 ADD 1 TO A ON SIZE ERROR DISPLAY 'Z' END-IF.`, G4). Control: `GO TO P2 IF A = 1 DISPLAY 'Y'
END-IF.` (G5) is correctly refused, because a delimited-scope IF is imperative.

## Code site and shape

`src/Cobol.Net.Compiler/Binding/Procedure/StatementPosition.cs`: `PlacementRules.GoToLast` uses `FollowedBy` /
`StatementPosition.IsLast`, which treat every statement of the sentence or `statementBlock` as "the sequence". The SR2
predicate must ask whether the FOLLOWING statement is imperative: a statement with a Table 12 conditional phrase and no
explicit scope terminator is conditional. The tree has no conditional-statement classifier (no `IsConditionalStatement`
/ `IsImperative`), so the fix adds one, derived from §14.5.1 and Table 12, in one place.

`docs/CONFORMANCE.md` D-SEQ (a) defines "the sequence" as all the statements of one sentence or phrase, which is wrong
for SR2 and is corrected in the same change. D-SEQ (b) ties the STOP RUN placement rule (COBOLNET2968) to "the SAME
sequence §14.9.17.3 SR2 names"; probe S1 (`DISPLAY 'S' STOP RUN IF A = 1 DISPLAY 'Y'.`) is refused with COBOLNET2968
today, so the fix re-decides that reading as well.
