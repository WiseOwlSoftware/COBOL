# PB5390 - test_forbidden_commands.py fails two PASS cases under WSL

**Sites:**

- `scripts/hooks/test_forbidden_commands.py:310` (`<module>`: the case `git push https://github.com/WiseOwlSoftware/COBOL x`, expected PASS)
- `scripts/hooks/test_forbidden_commands.py:341` (`<module>`: the case `git push --repo=https://github.com/WiseOwlSoftware/COBOL`, expected PASS)
- `scripts/hooks/forbidden_commands.py:235` (`_pushes_elsewhere`, `_repo_key`)

**Mechanism.** `_pushes_elsewhere` returns whether any push URL's `_repo_key` differs from `_repo_key` of `git remote get-url origin` of the repository (line 242-245). The two cases spell THIS repository as the GitHub URL and expect "not elsewhere". That holds only where origin is that GitHub URL (the Windows host). The Linux selftest runs in a WSL clone whose origin is a local path (`_repo_key` resolves a local path to its resolved path, line 168-171), so the URL's key `github.com/wiseowlsoftware/cobol` never equals it, the push reads as another repository, and the guard blocks: 265 of 267 cases pass (the report's LINUX GATE verdict `RED (failed or not run: selftests; HEAD 24dd74567)`). Read from the code only; not re-run here (R2: the lead carries its repro, `bash scripts/linux-gate.sh --legs selftests`, and its cause is a probable reading, unprobed).

**Harm.** A Linux-gate red the merge group's Linux self-test leg will meet too, and an unattended agent on a Linux checkout whose origin is a path could never push this repository's URL spelling. The hooks' fail-closed rule (line 243) makes the second harm a refusal, not a leak.

**Fix direction.** The test's fixture should not depend on this clone's origin spelling: build the "same repository" cases from the scratch repository's own configured origin (the test already has `THIS_ORIGIN` and `same_origin`, line 28 and 32), or have the fixture's origin URL set to the GitHub URL for these two cases, so the result is the same on every host. If the hook itself should also treat a clone's remote spelled as a path as the same repository as its own upstream URL, that is a design decision for the PB5269 owner; record it before changing the rule. The fix is the test's input; do not loosen `_repo_key`.
