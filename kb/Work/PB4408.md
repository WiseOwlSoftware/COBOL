# PB4408 - a family landing through an integrate PR is still planned as finisher work

**Sites:** `scripts/orchestrator/plan_wave.py` (`plan_held` and its `carrier`/`drained` rule, `PlanState.awaiting`).

**Lead (wave 20261811 handoff):** the planner excludes only the integrate branch's own note (PB4395), not the notes its
contained branches carry. It therefore planned a finisher group (PB4204, PB4271, PB4331, PB4334, PB4396) for a family that
was landing through integrate PR #991; the operator released the group unrun from the dispatch ledger, and the diagnostic
codes COBOL5881-5883 allocated to it were wasted.

**Read at origin/main 9d465df8d.** The exclusion in `plan_held` is per report: `PlanState.awaiting` collects the notes of a
DONE report whose branch is not on main (module docstring item 1), and `Sweep.drained` / `carrier` (a DONE branch that
CONTAINS another, via `inflight.branch_carrier`) hold back finishers only for a contained branch's own report-bearing
notes. A note carried by a contained branch that has no report of its own, and that the integrate branch's register closes,
is not in `awaiting`, so the finisher stage plans it. The trace of exactly which stage admitted these five ids was not
done; the implementer reproduces it from the wave 20261811 ledger first. Fix at the structure: the integrate branch's
`add_closed_notes` reaches the notes its contained branches carry (one rule for "work that lands through branch X"), with a
test in `test_plan_wave.py` that plans a family under an integrate branch and expects no group.

Grepped `kb/Work` for `integrate`, `plan_wave` and `carrier`: PB4352 and PB3170 cover carriers of DONE branches; none covers the integrate branch's contained notes.
