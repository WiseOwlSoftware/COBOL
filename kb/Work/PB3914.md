# PB3914 — subscript-all-in-function-argument-not-supported: Subscript ALL in an intrinsic-function argument not supported: FUNCTION SUM (E (ALL)) gives "syntax error, unexpected ALL"

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S6) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\subscript-all-in-function-argument-not-supported.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\subscript-all-in-function-argument-not-supported\`.

## Summary

GnuCOBOL 3.2 refuses the subscript ALL in a table reference used as an intrinsic-function argument:
`FUNCTION SUM (E (ALL))` draws `syntax error, unexpected ALL`, and so do `E (ALL 2)` and `E (2 ALL)` in a
two-dimensional table. The standard permits the subscript ALL exactly there, for functions whose argument may be
repeated a variable number of times, and defines it as the list of every element along that subscript. Writing the
elements out (`FUNCTION SUM (E (1) E (2) E (3))`) compiles and runs. The capability is absent as a whole (no grammar
alternative and no argument expansion), so it is recorded as a missing feature of the 2014 edition. Seven night
witnesses over nights 3, 4 and 5 (fz01372, fz03468, fz02367, fz03072, fz04482, fz03297, fz06119) all stop on this one
error.

night 4: `COMPUTE WS-SUM = FUNCTION SUM(WS-TABLE(ALL))`).

## Expected result (per ISO)

The program is legal and prints `06`.

- §8.4.2.3.2 (general format of subscript, rendered as the figure note records): a subscript is one of `ALL`,
  arithmetic-expression-1, or index-name-1 [{+|-} integer-1].
- §8.4.2.3.3 6) (checked): "The subscript ALL may be used only: — When the subscripted identifier is used as an
  intrinsic function argument, or — as the rightmost or only subscript of a table in the table format of a SORT
  statement."
- §8.4.2.3.4 1) a) (checked): "If ALL is specified, the subscript is all of the possible values of a subscript for the
  associated table as specified in the rules for the functions for which the subscript ALL is allowed."
- §15.3 (Arguments, checked): "When the definition of a function permits an argument to be repeated a variable number
  of times, a table may be referenced by specifying the data-name and any qualifiers that identify the table, followed
  immediately by subscripting where one or more of the subscripts is the word ALL." and "When ALL is specified as a
  subscript, the effect is as if each table element associated with that subscript position were specified."
- §15.88.1 (checked): "The SUM function returns a value that is the sum of the arguments." The general format
  (§15.88.2) is `FUNCTION SUM ( { argument-1 } ... )`, a repeated argument; §15.88.3 1) (checked): "Argument-1 shall be
  of class numeric." E (ALL) is therefore E (1) E (2) E (3), and the sum is 6.

Edition: 2014. The 2009 committee draft that became ISO/IEC 1989:2014 (CD 1.2, 8.4.1.2.2 syntax rule 7) has "The
subscript ALL may be used only: -- When the subscripted identifier is used as an intrinsic function argument, or ...",
and its clause 15 has the same "When the definition of a function permits an argument to be repeated a variable number
of times ..." and "When ALL is specified as a subscript ..." paragraphs. The 2002 text (ISO/IEC 1989:2002(E) post-ballot
draft, 8.4.1.2.2 syntax rule 6) has "The subscript ALL may be used only when the subscripted identifier is used as an
intrinsic function argument or to identify the table in the table format of the SORT statement." The feature is at
least as old as the 2002 edition.

Edition as recorded by the adjudicator: 2014 (present in 2002). `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Class

FEATURE-MISSING: an ISO feature of the claimed edition (2014; present in 2002) that cobc does not implement. The
refusal is a plain syntax error rather than a "not implemented" diagnostic; legal source of the claimed edition is
refused.

## Our compiler (WiseOwl)

WiseOwl COBOL (built from main 6ed90bd1c), `cobol sumall.cob --std 2014 --source-format free -o sumall.dll`, then
`dotnet sumall.dll`: compile exit 0, run exit 0, output `06`. `maxall.cob`: `7` (the larger of E (1 2) = 7 and
E (2 2) = 4) and `2` (ORD-MAX of E (2 1) = 3, E (2 2) = 4). `sumlst.cob`: `06`.

## Fix site (GnuCOBOL 3.2 source, read observationally)

- `cobc/parser.y`, rule `subref`: a subscript list is `TOK_OPEN_PAREN exp_list TOK_CLOSE_PAREN`, and `exp_list`/`exp`
  have no `ALL` alternative, so the word ALL is a syntax error in any subscript position.
- `cobc/tree.c`, `cb_build_intrinsic`: the argument list of a variable-argument function (`CB_INTR_SUM`, `CB_INTR_MAX`,
  `CB_INTR_MEAN`, ... in its switch) is taken as written; supporting ALL needs an expansion of each ALL subscript into
  the element references of §15.3 (in the left-to-right, rightmost-subscript-fastest order, bounded by OCCURS DEPENDING
  ON where present), at compile time for fixed tables and at run time for variable-occurrence ones, and a syntax check
  that limits ALL to function arguments (and to the SORT table format).
