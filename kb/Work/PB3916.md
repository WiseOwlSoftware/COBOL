# PB3916 — group-usage-clause-not-supported: GROUP-USAGE BIT / GROUP-USAGE NATIONAL (ISO 2002/2014) refused: 'GROUP-USAGE' is a reserved word, but isn't supported

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S7) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\group-usage-clause-not-supported.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\group-usage-clause-not-supported\`.

## Summary

GnuCOBOL 3.2 refuses the GROUP-USAGE clause in both its forms, `GROUP-USAGE BIT` and `GROUP-USAGE NATIONAL`, with
`'GROUP-USAGE' is a reserved word, but isn't supported`, followed by cascading errors on the group's subordinate
entries. The clause (bit groups and national groups) is in ISO/IEC 1989:2002 and 2014; `-std=cobol2014` claims 2014,
so this is a missing feature of that edition. Class: feature missing.

## Minimal test case

Free reference format (`-fformat=free`), 17 lines, written for this record. The 11 fuzz witnesses of nights 2 to 5
(for example fz00334, fz00936, fz01105; 23 programs across the nights) all stop on the same
`'GROUP-USAGE' is a reserved word, but isn't supported` at their first GROUP-USAGE entry and reduce to it.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. GRPUSE.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 BG GROUP-USAGE BIT.
   05 B1 PIC 1(4).
   05 B2 PIC 1(4).
01 NG GROUP-USAGE NATIONAL.
   05 N1 PIC N(3).
   05 N2 PIC N(2).
01 LEN PIC 99.
PROCEDURE DIVISION.
MOVE FUNCTION LENGTH(BG) TO LEN
DISPLAY LEN
MOVE FUNCTION LENGTH(NG) TO LEN
DISPLAY LEN
STOP RUN.
```

File: `E:\COBOL-coord\scratch\op\pb3838\records\group-usage-clause-not-supported.cob`. Either group alone shows the
refusal; both are kept so one program covers both phrases.

The program is legal. BG and NG are group items, not strongly typed and not variable-length (§13.18.29.3 1)). Under
GROUP-USAGE BIT, USAGE BIT is implied for the group (§13.18.29.3 2)) and a usage implied at a group level applies to
each elementary item (§13.18.60.4 1)), so B1 and B2 (PIC 1, category boolean) are usage bit as SR2 requires. Under
GROUP-USAGE NATIONAL, N1 and N2 are PIC N, usage national (§13.18.29.3 3)).

## Expected result (per ISO)

The program compiles and prints `08` then `05`.

- ISO/IEC 1989:2023 §13.18.29.1 (checked): "A GROUP-USAGE clause with a BIT phrase specifies that the group item
  defined by the subject of the entry is to be treated as an elementary item of usage bit and category boolean", and
  "A GROUP-USAGE clause with a NATIONAL phrase specifies that the group item defined by the subject of the entry is to
  be treated as an elementary item of usage national and category national". General format (§13.18.29.2):
  `GROUP-USAGE IS { BIT | NATIONAL }`.
- §13.18.29.3 1) (checked): "The GROUP-USAGE clause may be specified only if the subject of the entry is a group item
  that is not strongly typed and not a variable-length group."
- §13.18.29.3 2) (checked): "All elementary items subordinate to the subject of the entry shall be explicitly or
  implicitly described as usage bit, class and category boolean." §13.18.29.3 3) (checked): "All elementary items
  subordinate to the subject of the entry shall be explicitly or implicitly described as usage national."
- §13.18.60.4 1) (checked): "If the USAGE clause is specified or implied at a group level, it applies only to each
  elementary item in the group."
- §13.18.29.4 1) b) (checked): "a bit group is treated as though it were an elementary data item of usage bit and
  class and category boolean described with PICTURE 1(m), where m is the bit length of the group." §8.5.1.6.3
  (checked) places B2 at the next bit position after B1 ("an elementary bit data item immediately following an
  elementary bit data item or bit group item of the same level") and "No filler is generated at the end of a record
  that is entirely a bit group", so m = 8.
- §13.18.29.4 2) b) (checked): "a national group is treated as though it were an elementary data item of usage
  national and class and category national described with PICTURE N(m), where m is the length of the group"; m = 5.
- §15.50.4 1) (checked): "If argument-1 is a bit group item, an elementary boolean data item, a boolean literal, or a
  type declaration for a boolean item, the returned value is an integer equal to the length of argument-1 in boolean
  positions." §15.50.4 2) (checked): "If argument-1 is a national group item, an elementary data item of usage
  national other than a boolean data item" the length is in national character positions. So LENGTH(BG) = 8 and
  LENGTH(NG) = 5.

Edition: GROUP-USAGE is a 2002 feature, present in 2014. The 2002 text (ISO/IEC 1989:2002, §13.16.27) and the 2009
committee draft that led to 2014 (CD 1.2, §13.18.28) both define it with the BIT and NATIONAL phrases and the same
general rules; Annex E of the 2023 standard does not list it as new. GnuCOBOL's own `cobc/reserved.c` tags
GROUP-USAGE as a 2002 word.

Edition as recorded by the adjudicator: 2014 (introduced 2002). `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

under-rejection.

## Fix site (GnuCOBOL 3.2 source, read observationally)

- `cobc/reserved.c`, table entry "GROUP-USAGE" (line 1481): token -1, which `cobc/reserved.c` `lookup_reserved_word`
  (the check near line 4900) reports as "is a reserved word, but isn't supported".
- `cobc/parser.y`, rule `data_description_clause` (line 7472): no GROUP-USAGE alternative.
- `cobc/field.c` (`validate_field_1`, `compute_size`): a fix would set the group's category and usage (boolean/bit or
  national), check the subordinate usages per SR2/SR3, and size a bit group in bits.
