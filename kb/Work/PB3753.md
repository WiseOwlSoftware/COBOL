# PB3753 — the optional-word audit cannot reach the nine directive formats or §10.6.1

**Sites:** `scripts/spec/audit_grammar_optional_words.py#parser_rules` (reads the parser grammar only), `scripts/spec/audit_grammar_optional_words.py#declared_formats`.

Filed 2026-10-25 by the enqueue clerk. PB715 found a second blindness in the registrar extension: 20 anchored formats whose
optional words anchored NO rule ran clean. Ten have a parser token (USE, USAGE, ORGANIZATION, SIGN, PICTURE, FORMAT, COLLATING,
FILE STATUS, INTERFACE-ID, METHOD-ID) and PB715 covers them. Ten have none: the nine directive formats (§7.3, for example
`>>TURN … CHECKING ON WITH LOCATION`) and §10.6.1 (`IS PROTOTYPE`, `IS INITIAL`). The audit reads only the parser grammar
(`parser_rules`), so an optional word a directive or a §10.6.1 phrase makes required would be reported by nothing.

## Code site that the audit does not read
The preprocessor's directive parsing (the directive syntax is not in the parser grammar), and the interface-definition phrases of §10.6.1.

## Fix direction
Give the audit a second source for those formats (the directive operand syntax table and the grammar rule that carries the §10.6.1
phrases), reading one `GrammarModel` as PB2024's inverse audit also should (PB715's "for the next implementer"), not a second parser.
Then the 10 unanchored formats anchor a rule, and the population assertion holds for all 20.
