# PB660 — OPEN — the outermost half of a uniqueness rule

Found 2026-09-05 by the `PB303` implementer (report §"New defects" D-1), measured at `--std 2023` on its tree
while giving every unit two names; pre-existing (the declared-name twin reproduces on main without any AS phrase).

## Repro (`--std 2023`; one compilation group)

```cobol
       IDENTIFICATION DIVISION.  PROGRAM-ID. P3DUPA AS "P3DUPX".
       PROCEDURE DIVISION.  DISPLAY "FIRST".  GOBACK.  END PROGRAM P3DUPA.
       IDENTIFICATION DIVISION.  PROGRAM-ID. P3DUPB AS "P3DUPX".
       PROCEDURE DIVISION.  DISPLAY "SECOND".  GOBACK.  END PROGRAM P3DUPB.
       IDENTIFICATION DIVISION.  PROGRAM-ID. P3MAIN.
       PROCEDURE DIVISION.  CALL "P3DUPX".  GOBACK.  END PROGRAM P3MAIN.
```

Compiles, exit 0, prints `FIRST`. Two outermost `PROGRAM-ID. P3DND.` definitions (no AS phrase) behave the same.

## The rule

§8.3.2.2: "Within a run unit, all instances of a given name that is externalized to the operating environment shall
identify the same kind of entity or item" (`OK §8.3.2.2 2)`) — two program definitions with one externalized name
are two entities under one name; the compilation group is the compiler's whole view of the run unit it produces,
and a duplicate it can see is a duplicate it must report. §8.4.6.3's uniqueness sentence is the CONTAINED-program
half and appears enforced (a second contained program with the same name is refused); the OUTERMOST half has no
check on either axis.

## The mechanism

`src/Cobol.Net.Compiler/Binding/BinderDriver.cs#BuildProgramDefinitionTable` — `map.TryAdd(...)` returns false for
the second definition and nothing reads the result; `src/Cobol.Net.Runtime/Control/ProgramTable.cs#Register` /
`ResolveVisible` rule 4 — the first `_order` match wins with no uniqueness assertion on `CallName`. One fix at the
bind-time table covers both the declared and the externalized axis, since PB303 keys the table on both names.

## Fix shape

At `BuildProgramDefinitionTable`, a duplicate outermost definition — same declared name, or same externalized name,
case per the name kind (declared: case-insensitive; externalized: ordinal, per PB303's determination) — is a
compile-time error naming both definitions and the rule (one descriptor; the next free code); the runtime
`Register` keeps a debug assertion so a duplicate arriving from separately compiled assemblies (outside the
compiler's view) is at least loud. Negatives at 2002/2014/2023: the declared-name pair, the externalized-name pair,
and a declared/externalized cross (`PROGRAM-ID. P3DUPX.` beside `PROGRAM-ID. P3DUPB AS "P3DUPX".`); positive control:
a contained program reusing an outermost name where §8.4.6.3 permits it (measure first). Sweep: FUNCTION-ID,
CLASS-ID and INTERFACE-ID definitions through the same table for the same two axes.
