# PB3832 — the missing-imperative hint fires on the wrong fault

## Owner decision

The owner APPROVED this on 2026-10-26 at about 11:10 PDT, in chat: "Approve the CLASS IS BOOLEAN and COBOL2072 wording fixes too".

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs#GuessCobolIntent`, `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs#IsEmptyRequiredStatementBlock`

## Repro and result

Verdict line (slice C3, signature `WE_REJECT:COBOL0001,COBOL2072`, WISEOWL-DEFECT, harm "diagnostic wording only";
first program fz02783). Repro:
`E:\Temp\claude\E--COBOL\f2318ea1-8657-407b-8f1b-8fd54f53ad3f\scratchpad\fuzz5\adj\C3\probes\fz02783\r14.cob`

```cobol
           IF F = 1
               DISPLAY "A"
           ELSE IF F = 2
               DISPLAY "B"
           END-IF
           IF LENGTH OF WS-OUT = 30
               DISPLAY "C"
           END-IF
```

- Expected: a parse error at `OF` that names the construct, with no claim about a missing statement.
- Actual (the orchestrator re-ran it): COBOL0001 plus COBOL2072, which says the IF's general format shows an
  imperative-statement that is not bracketed. That is false: the IF has its DISPLAY.
- It fires only when this IF follows an `IF .. ELSE IF .. END-IF`, which leaves the OUTER IF open. A lone IF (probes
  r1, r3, r7 to r12) gets a bare COBOL0001.
- A second witness for the same hint (slice C4, `probes\notne\notne.cob`): `IF A NOT <> B` draws "unexpected 'NOT'" and
  then the same false missing-statement claim. The fault there is the NOT before `IS <>`, which §8.8.4.2.2 Format 1
  does not print.

## The rules (checked)

- §8.9: `python scripts/spec/cite.py --check 8.9 "LENGTH"` is OK. LENGTH is a reserved word, so the program cannot use
  it as a data-name and the refusal stands.
- §5.2.6.2: the hint's own cited rule; `--check 5.2.6.2 "omit"` is OK. Brackets mark a portion that may be explicitly
  specified or omitted. It says nothing that makes this IF empty.

## Mechanism

`GuessCobolIntent` attaches COBOL2072 when `IsEmptyRequiredStatementBlock` finds a parse position that expects the
start of a statement block and met a token that starts none (PB396's arm, computed from the ATN). After the open outer
IF the parser's expected set at `OF` is such a position, so the test cannot tell "the block is empty" from "the block
began and this token is an error inside it". Related: [[PB911]] (the same detector NOT firing on PERFORM Format 3).

## Acceptance (when the owner approves)

- COBOL2072 fires only when the statement block is in fact empty. The repro draws the same diagnostic as the lone
  IF, and the `IF A NOT <> B` witness stops claiming a missing statement.
- A diagnostic case pins both programs, and the sibling sweep names every other arm of `GuessCobolIntent` that reads
  the expected set rather than the consumed tokens.
