# PB3832 — the missing-imperative hint fires on the wrong fault

## Owner decision

The owner APPROVED this on 2026-10-26 at about 11:10 PDT, in chat: "Approve the CLASS IS BOOLEAN and COBOL2072 wording fixes too".

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs#GuessCobolIntent`, `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs#IsEmptyRequiredStatementBlock`

## Repro and result

Verdict line (slice C3, signature `WE_REJECT:COBOL0001,COBOL2072`, WISEOWL-DEFECT, harm "diagnostic wording only";
first program fz02783). Repro:
`E:\Temp\claude\E--COBOL\f2318ea1-8657-407b-8f1b-8fd54f53ad3f\scratchpad\fuzz5\adj\C3\probes\fz02783\r14.cob`

```cobol
           IF F = 1
               DISPLAY "A"
           ELSE IF F = 2
               DISPLAY "B"
           END-IF
           IF LENGTH OF WS-OUT = 30
               DISPLAY "C"
           END-IF
```

- Expected: a parse error at `OF` that names the construct, with no claim about a missing statement.
- Actual (the orchestrator re-ran it): COBOL0001 plus COBOL2072, which says the IF's general format shows an
  imperative-statement that is not bracketed. That is false: the IF has its DISPLAY.
- It fires only when this IF follows an `IF .. ELSE IF .. END-IF`, which leaves the OUTER IF open. A lone IF (probes
  r1, r3, r7 to r12) gets a bare COBOL0001.
- A second witness for the same hint (slice C4, `probes\notne\notne.cob`): `IF A NOT <> B` draws "unexpected 'NOT'" and
  then the same false missing-statement claim. The fault there is the NOT before `IS <>`, which §8.8.4.2.2 Format 1
  does not print.

## The rules (checked)

- §8.9: `python scripts/spec/cite.py --check 8.9 "LENGTH"` is OK. LENGTH is a reserved word, so the program cannot use
  it as a data-name and the refusal stands.
- §5.2.6.2: the hint's own cited rule; `--check 5.2.6.2 "omit"` is OK. Brackets mark a portion that may be explicitly
  specified or omitted. It says nothing that makes this IF empty.

## Mechanism

`GuessCobolIntent` attaches COBOL2072 when `IsEmptyRequiredStatementBlock` finds a parse position that expects the
start of a statement block and met a token that starts none (PB396's arm, computed from the ATN). After the open outer
IF the parser's expected set at `OF` is such a position, so the test cannot tell "the block is empty" from "the block
began and this token is an error inside it". Related: [[PB911]] (the same detector NOT firing on PERFORM Format 3).

## Acceptance (when the owner approves)

- COBOL2072 fires only when the statement block is in fact empty. The repro draws the same diagnostic as the lone
  IF, and the `IF A NOT <> B` witness stops claiming a missing statement.
- A diagnostic case pins both programs, and the sibling sweep names every other arm of `GuessCobolIntent` that reads
  the expected set rather than the consumed tokens.

## Landed (wave 20261707 group B)

Re-probed on the branch build: `r14.cob` drew COBOL2072 plus COBOL0001 at OF, `r1.cob` (the lone IF) a bare
COBOL0001, and `notne.cob` COBOL2072 at NOT. After the fix `r14.cob` and `r1.cob` draw the same single COBOL0001
at OF, and `notne.cob` draws COBOL0001 "unexpected 'NOT'".

- **The root.** Two faults in how `CobolErrorStrategy` read a cause. (1) A failed adaptive prediction reports the
  token where every alternative died while the parser stays at the decision's first token. After the open
  `IF .. ELSE IF .. END-IF`, the inner IF's optional END-IF is a dangling decision whose full-context prediction looks
  through the following statements, so the failure at OF was read at the END-IF, inside the inner IF, where every
  statement start is expected. Every nested empty block was also named IF (the parser's rule stack), and the
  scope-terminator hint said "END-ADD appears without a matching ADD statement" of an ADD written after the decision.
  (2) The emptiness test itself (expected set holds every statement start, the token none) was also true after a
  complete statement and after a condition the token wrongly continued (`IF A NOT <> B`, `IF A NOT <= B`).
- **The fix.** One view of the parse AT the offending token (`OffendingPosition`), built on the existing
  full-context `ResidueWalk`, renamed `ResimulationWalk` now that it serves every such hint. The empty-block hint asks
  the parse: a block is empty exactly when one CONTINUE stepped from a configuration that begins a statement directly
  in a `statementBlock` lets the offending token follow, and the owner is named from that configuration's stack. The
  figurative-spelling hint reads the expected set there, and the rule-stack hints read the rules open there. A report
  at the token the previous report named is suppressed (the recovery resumed at the decision and met the same fault).
- **Witnesses.** `RequiredImperativeStatementDriftTests`: `ATrulyEmptyBlock_IsNamedByItsOwnStatement_AtEveryDepth`
  (IF, ELSE, EVALUATE WHEN, inline PERFORM, PERFORM UNTIL and SEARCH WHEN at depth 0 and inside the open nest, nested
  ON SIZE ERROR), `ABlockWhoseStatementFails_IsNotCalledEmpty_AtAnyDepth` (the same constructs plus the two condition
  shapes), `TheNestedFailure_DrawsTheLoneIfsOneDiagnostic`, and `AWhollyEmptyInlinePerform_IsRejected_WithTheNamedDiagnostic`
  (the "known message gap" of DESIGN-frontend-grammar §3.11 is closed). The golden `pb1034-not-lteq` now expects
  COBOL0001: its COBOL2072 was this note's false claim.
- **Sibling sweep.** Every arm of `GuessCobolIntent` that reads parser state: 0a (empty block) and 0d (figurative
  spelling, the expected set) and the rule-stack arms 3, 7, 13, 17, 19 now read at the offending token. 0b (WHEN OTHER),
  0c (GO TO), 0e (SEARCH), 0e' (mnemonic suffix) and 0f read the token stream or anchor on token adjacency; 0g already
  walked. The expected-set guesses (5, 6, 8, 12, 14, 15, 16, 17) read the position's expected set since review round 2
  (below); they used to read the text of the exception's set, which a failed prediction does not carry.
- **Review round 1 (two blocking findings, both fixed).** R1-1: the walk gave up sixteen tokens past the parser, so an
  empty block written after a long statement inside the open nest drew a bare COBOL0001 (the one-report rule then
  suppressed the recovery's named report). The dangling decision looks to the end of the sentence; the walk now does
  too, and the sixteen-token bound limits only where the closed-format residue may stand. R1-2: at depth 0 an empty or
  failing paired conditional phrase (ON SIZE ERROR, AT END, INVALID KEY, ON OVERFLOW, ON EXCEPTION and their NOT forms)
  drew COBOL0307 "A period may be missing" at the phrase word: the phrase is an optional decision whose exit ends the
  statement, and SLL prediction took the exit when the phrase's own alternative died later. The report now stands
  where the closed construct's own full-context re-simulation dies (`OffendingPosition.CarryForward`), so every family draws the
  same one diagnostic at both depths; a structural hint at the parser's token outranks the move, and the WHEN OTHER
  arm (0b) no longer reads a present body as a misplaced phrase when the closed EVALUATE takes it. Witness: `EveryConditionalPhrase_EmptyOrFailing_DrawsItsOneDiagnostic_AtEveryDepth`
  (12 phrase forms), the AH..AJ and M0/AD0 rows of `ATrulyEmptyBlock_IsNamedByItsOwnStatement_AtEveryDepth`, and
  `ABlockWhoseStatementFails_IsNotCalledEmpty_AtAnyDepth`, which now asserts the one COBOL0001 at the fault token.
- **Review round 2 (two blocking findings, both fixed).** R2-1: the one-report rule kept a failed prediction's first
  report and dropped the recovery's repeat at the same token, but only the repeat carried an expected set (the text of
  the exception's), so a missing separator period before a section or paragraph header (ISO §14.5.1) drew a bare
  COBOL0001 where main drew COBOL0307. Every report kind now reads `OffendingPosition.Expected()`, and the
  expected-set guesses read it only where it does not hold the token. R2-2: `ResimulationWalk.OpenRuleNames` read the
  CLOSED configurations at the token, so every statement rule a statement may begin with there was "open", and a
  stray END-IF after a complete statement found its IF: hint 13's COBOL0306 (ISO §14.5.3.2) fell silent. It now reads
  the configurations that took the previous token, counting an invocation only while it can still take a token (the
  IF a just-written END-IF completed is not open). Witnesses: `ParseRecoveryHintTruthTests`
  `AMissingSeparatorPeriod_IsNamedOnTheFaultsOneReport` (PBHT31..37, depth 0 and inside an open IF and the open nest)
  and `AScopeTerminatorOutsideItsStatement_NamesTheStatement` (PBHT13..18, now asserting the one COBOL0306).
