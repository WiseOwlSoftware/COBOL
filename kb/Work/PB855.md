## Why it is unimplemented, and what makes it hard

PB528's determination made character-1 TRANSPARENT to the precedence walk, because applying §13.18.40.6's
sentence literally also rejects `PIC L9999.99F` (Annex D.24) and `PIC LL EDITING "L" IS ":"` (SR12 a) — both of
which the standard admits. So the open question is whether a WEAKER form holds (the 'es' confined to the
row/column of the LEADING or TRAILING currency symbol, but not measured against another 'es'), and SR26's
singular "optionally preceded by character-1" is likewise a reference to the syntactic term rather than a
demonstrated count — no rule of the clause states a bound. Row 26's notes record that reading; this note exists
so the next adjudicator does not re-derive it from scratch and so the question has an owner.

## Landed — wave 1020 (group A)

**Re-probed on a fresh build of `7546af101`:** `PIC 99L99 EDITING L FOR NEGATIVE IS "("` bound clean and rendered `-12.3` as `00(12`; `PIC LF$999` bound
with two extended symbols ahead of the currency symbol and rendered `-12` as `()$012` (the note's quoted-literal spelling `EDITING "L"` is itself
COBOLNET2149 since PB568; the bare form is the repro). Both are fixed. Citations re-run through `cite.py --check`: §13.18.40.6 (the closing
"same precedence as the 'cs' symbol" sentence), §13.18.40.3 SR24 / SR25 / SR26, all OK.

**The answer to "does a WEAKER form hold" is: yes, and it is not weak.** PB530's premise — that §13.18.40.6's sentence "cannot be applied literally"
because Table 10's leading-currency-before-trailing-currency cell is BLANK and would reject Annex D.24's `PIC IS L9999.99F` — is true of the cell and
false of the reading. A non-floating FOR-form character-1 now takes the `cs` roles (`PicRole.CurrencyLeading` / `CurrencyTrailing`, position-ambiguous
exactly like a fixed currency symbol) and is asked of EVERY other symbol by the matrix; the ONE pair the matrix does not judge is a currency-like
symbol against another (`es`/`es`, `es`/`cs`), which `PictureComposition.CurrencyLikeRoles` exempts because SR25 and SR26 own that order (a fixed
`cs` is bounded to one by SR24, so the exemption removes nothing for a picture with no `es`). So `PIC 99L99` is COBOLNET1935; `PIC L999`, `9999L`,
`L$999`, `999$L`, `L$999F` bind. ONE predicate shared by `cs` and `es`, as the note's sibling sweep required; Annex D.24's examples bind
(`PictureEditingTests`, 15 green). The IS form (simple insertion, rule 3) and a FLOATING extended string stay transparent, for the reasons in the code.

**SR25 is now read AS WRITTEN** (DETERMINATION, owner may overturn; replaces PB530's): with two extended symbols the first phrase's character-1 IS the
string's first symbol and the second's its last, COBOLNET1984. That closes SR26's "singular" question the note named: `PIC LF$999` is refused by SR25
(F is not the rightmost symbol), so no rule needs a multiplicity bound on "optionally preceded by character-1". `PIC $L99` / `PIC 999L$` (an `es`
after / before the currency symbol, the one order Table 10's blank cell would refuse and no sentence does) are ACCEPTED — the reading that rejects less.

**FOUND ON THE WAY AND FIXED (I9, same file, same sibling class — a count where an adjacency belongs):**
* SR24's "one or two extended symbols" was asked over EDITING PHRASES, so `PIC L9L9L` under ONE phrase (three fixed occurrences) escaped it; it is now
  asked over the PICTURE in `PictureComposition.Validate` (each fixed occurrence and each floating string is one symbol), which also bounds the
  role search at 2^4. COBOLNET1985.
* `EditRule.Floating` was `occ >= 2` — a bare occurrence count (the PB528 error, fixed for the currency symbol and left here): `PIC L999L` (two FIXED
  occurrences) rendered `-12` as `(0012`. It is now `PictureComposition.HasFloatingString`, rule 6's adjacency test; it renders `(012(`.
