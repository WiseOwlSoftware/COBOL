# PB2833 — OPEN — DynMaxOf is 0 for every dynamic-capacity table

Found by the w1045h implementer (PB1951, report "New defects") and Filed by the train 1047 lander, 2026-10-08 20:53 PDT.

## Mechanism
`src/Cobol.Net.Compiler/Binding/Model/Place.cs#DynMaxOf` (line ~636) reads a component's maximum from
`OccursSpec.Max`, and the binder sets `Max = 0` for every `OCCURS DYNAMIC` table
(`src/Cobol.Net.Compiler/Binding/DataBinder.Odo.cs:79`: `Min = fromCap ?? 0, Max = 0, IsDynamic = true`). The
`VarGroupWindow` built from those maxima (Place.cs:602 and :630) therefore admits zero occurrences for the table.

## Harm (latent, measured once)
Any `StoreContiguousAt` of an image into a cell-backed (EXTERNAL / BASED) group that holds such a table drops its
occurrences. The one measured reacher, the Format 2 table SORT of an EXTERNAL element, now moves that element as its
component carrier (PB1951's sibling fix, train 1047), so it no longer reaches this. The other reachers (READ INTO,
record-image stores into EXTERNAL groups, a group MOVE into one) are UNPROBED. A dynamic-capacity table has no fixed
maximum unless `TO` gives one, so the window must take the current capacity, or the `TO` bound when it exists.

## Repro to build
`05 G EXTERNAL` group holding `10 T PIC X OCCURS DYNAMIC CAPACITY IN C1`; give T three occurrences; `READ F INTO G`
(or `MOVE <image> TO G`) and `DISPLAY C1`, then each occurrence. Expected: the occurrences the image carries. Start from
w1045h's probes under `E:\COBOL-coord\scratch\w1045h\`.
