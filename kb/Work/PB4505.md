# PB4505 — the live quota from the status line, per account

**Sites:** `scripts/statusline_tap.py` (whole: new), `scripts/orchestrator/budget.py` (`live_reading`, `current`,
`LIVE_MAX_AGE`, `LIVE_FILE`), `scripts/orchestrator/test_budget.py` (whole: test)

**What was wrong.** Before a dispatch the orchestrator read the quota meter from a month-old owner reading, or opened the
claude.ai usage page in Chrome. On 2026-11-03 the telemetry estimate said 19 % of the week and the page said 29 %. Yet
Claude Code hands its status line command a JSON record at every refresh carrying `rate_limits` (`five_hour`,
`seven_day`, each `{used_percentage, resets_at}` in epoch seconds), the same meter, and the installed `ccstatusline`
renders it. Its own cache (`~/.cache/ccstatusline/usage.json`) is written only when it falls back to the usage API, so
that file had stopped at 2026-10-29.

**As landed.** `scripts/statusline_tap.py` is the status line command: it writes the record's `rate_limits` with the time
it saw them to `<config dir>/rate-limits.json` (the session's own `CLAUDE_CONFIG_DIR`, else `~/.claude`: one file per
account), atomically, then runs the status line command after `--` with the same stdin and passes its output through.
Anything that fails in the tap is skipped, never raised. `budget.live_reading(acct, now)` reads that account's file and,
when it is at most `LIVE_MAX_AGE` (30 minutes) old and has a `seven_day` row, `current()` appends it to the readings as
the newest, so the estimate anchors on the meter itself. Both accounts are on the Ultra plan, which has no five-hour
window (owner, 2026-11-03), so a missing `five_hour` row reads as session 0.

**Configuration.** Both accounts' `settings.json` (`~/.claude/` and `~/.claude-acct2/`) run
`python E:/COBOL/scripts/statusline_tap.py -- npx -y ccstatusline@latest` as the status line command, set once this
landed on the main checkout.

**Witnesses.** `python scripts/statusline_tap.py --self-test` (written, skipped on bad input, an unwritable directory,
the config dir rule, end to end through a stub status line); `python scripts/orchestrator/test_budget.py` (each account
reads its own file; stale, unreadable and weekly-less files anchor nothing; Ultra's missing five-hour row).

**Branch review round 1 (w20261846d-review-r1).** R1-1 (high): the tap stamped the time it RAN, but Claude Code updates
`rate_limits` only on an API response while the status line re-runs every `refreshInterval` (10 s) even when idle, so an
idle session republished hours-old figures as current and the estimate dropped everything spent since (a headless
`claude -p` fleet has no status line at all). The tap now keeps per session the figures and the time they last CHANGED
(`measured_at`), publishes the most recently measured session, and drops a session unseen for eight days; `budget.py`
anchors on `measured_at` and counts the telemetry after it. Leads taken: R1-2, stdin and the status line's output pass
through as bytes (no CRLF, no UTF-8 failure); R1-3, the temporary file is removed when the rename fails; R1-4, the config
dir comes from `account.config_dir`, the one resolver (an import failure skips the tap, never the status line); R1-5,
`test_budget.py` covers `current()`'s merge (the newest anchor, another account's file, a stale measurement).
