# PB894 — OPEN — the twin that was never written

Source: the `PB403` report, "New defects".

## The measurement — the construct and its twin, same tree, same edition

```
## p13_proto.cob     PROGRAM-ID. R6P13P IS PROTOTYPE.        --std 2023
  p13_proto.cob(2,30): error COBOLNET0901: 'PROTOTYPE' is a reserved word in COBOL-2023 and cannot be used as
  a user-defined word (ISO §8.9)
rc=65

## p13b_fnproto.cob  FUNCTION-ID. R6P13F IS PROTOTYPE.       --std 2023
rc=0
```

The diagnostic is not even about the construct — it reads the word as a misplaced user-defined word.

## The code sites

* `src/Cobol.Net.Frontend/Grammar/CobolIdentification.g4` — `programIdAttribute` offers only
  `commonProgramAttribute` (COMMON / INITIAL / RECURSIVE / GLOBAL), where `functionIdParagraph` carries
  `(IS? PROTOTYPE)?`.
* `src/Cobol.Net.Compiler/Binding/BinderDriver.cs:345` — `bool isPrototype = fid?.PROTOTYPE() is not null`,
  derived from the FUNCTION-ID paragraph alone, so `BoundUnit.IsPrototype` can never be true for a program.

## The sibling sweep

Every IDENTIFICATION DIVISION attribute the standard gives to BOTH a program and a function: PROTOTYPE is
the one found. `AS literal-1`, the OPTIONS paragraph's per-element clauses and the END markers are the
others to check. The structural remedy is for `programIdAttribute` and `functionIdParagraph` to share one
attribute production rather than each carrying its own list — the shape that makes the next attribute
automatic.
