# PB2846 — LANDED — a refused module registration crashes past RunMain

Found by the train 1047 lander's review (step 5b; `E:\COBOL-coord\scratch\reports\train1047-report.md`, finding (c)) on cluster 45B (PB2097's module registration), PLAUSIBLE (traced in code, not run). The lander had no ids left; the land unit reserved this id and the resume unit of 2026-10-08 21:46 PDT filed it.

## Mechanism
`src/Cobol.Net.Compiler/CodeGen/ProgramEmitter.cs:871` emits `<registrar>.EnsureRegistered();` and line 881 emits
`try { ProgramRegistry.RunMain(...); }`. `EnsureRegistered` is `ProgramRegistry.RegisterModule(registrar,
runtimeVersion, callAbi, Register)` (line 795), which refuses a module built against a different runtime version or
call ABI. That refusal is thrown before the try, so it never reaches the RunMain boundary that owns the run unit's
termination (the STOP-status flush and the fatal-error report, ProgramTable.RunMain).

## Repro to build
Compile a main program, then run it against a runtime assembly whose version or call ABI differs (or force
`RegisterModule` to refuse in a unit test of the emitted shape). Observed (by trace): an unhandled .NET exception and
the host's stack dump. Expected: the runtime's fatal-error report and exit status.

## Done when
Registration runs inside the RunMain boundary (or RunMain performs it), with a unit test that a refused registration
ends the run unit through the same surface as any other fatal error.

## Landed (wave 1051 F, 2026-10-10)

Re-probed on a fresh build before the fix: a main program compiled, its recorded runtime version rewritten to another
major (a UTF-16 literal in the assembly's user-string heap), then run, exited `-532462766` (0xE0434352, an unhandled
.NET exception) with the host's stack dump. Root cause as the note said: the emitted `Main` ran
`__CobolModule.EnsureRegistered()` BEFORE `try { ProgramRegistry.RunMain(...) }`, and RunMain owns the termination
surface (the STOP-status flush, the ISO 14.6.12 abnormal-termination diagnostic and exit status, and the 14.6.11
epilogue).

Fix at the root: the registration moved INSIDE the boundary rather than a second catch written beside it.
`ProgramTable.RunModule(Action ensureRegistered, string? mainPath)` (facade `ProgramRegistry.RunModule`;
`RuntimeApi.RunModule` renders the call) runs the registration and then the main program through the one private
`RunOnThisThread` body, whose three fatal catches and `finally { Terminate }` now cover both; the main activation became
`ActivateMain`. The emitted Main is `try { ProgramRegistry.RunModule(__CobolModule.EnsureRegistered, "<path>"); } catch
(StopRun) { }`, and a module with no main program (a function or prototype library) emits
`ProgramRegistry.RunModule(__CobolModule.EnsureRegistered, null)`. `ProgramRegistry.RunMain(path)` stays the HOST entry
(a host that registers its modules itself, `NonCobolActivatorLinkageTests`). Both new members are in
`PublicAPI.Unshipped.txt` (new members, no Shipped edit, so the runtime major is unchanged).

Witness: `RunUnitTerminationTests.MainModuleRefusedAtRegistration_RaisesAbnormalTerminationSurface` (before: exit
-532462766; after: exit 1, stderr names `abnormal run-unit termination` and EC-PROGRAM-NOT-FOUND). Fourteen
characterization snapshots re-recorded (the Main text only). Sibling sweep: the other statements of the emitted `Main`
ahead of the boundary are `ProgramRegistry.Reset()` (begins the run unit) and `CobolFile.Init()` (the file-subsystem
init); neither depends on a module's registration, so nothing else of the entry runs outside the boundary. The
pre-boundary lookups in the old RunMainOnThisThread (the `_byPath` lookup and the factory call) are now inside it too.

## Landing

- `src/Cobol.Net.Runtime/Control/ProgramTable.cs#RunModule` — the standalone entry: runs the module's registration INSIDE the
  RunMain boundary (`RunOnThisThread`: three fatal catches and `finally { Terminate }`). `RunMain(path)` stays the HOST entry.
  Reuse `ActivateMain` for the main activation; the trap was that the old body looked the node up and called its factory
  BEFORE the try.
- `src/Cobol.Net.Runtime/Control/ProgramRegistry.cs#RunModule` — the facade; both members are in `PublicAPI.Unshipped.txt`.
- `src/Cobol.Net.Compiler/CodeGen/ProgramEmitter.cs#EmitMain` — emits `try { ProgramRegistry.RunModule(__CobolModule.EnsureRegistered, "<path>"); } catch (StopRun) { }`
  through `RuntimeApi.RunModule`; a module with no main emits `RunModule(..., null)`.
- `tests/Cobol.Net.Tests.Conformance/RunUnitTerminationTests.cs#MainModuleRefusedAtRegistration_RaisesAbnormalTerminationSurface`
  makes the skew real by rewriting the recorded runtime version's UTF-16 literal in the compiled assembly (same length, so the
  metadata stays valid). Fourteen characterization snapshots carry the Main text.
