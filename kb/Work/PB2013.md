# PB2013 — LANDED: a finisher for a half note on an unlanded branch now carries that branch's resume instruction

Wave 1017 was killed before any implementer wrote a report, leaving six worktrees
(`worktree-wf_a4d90677-e09-1..6`) with WIP commits for notes that are `status: half`. The first wave-1018 plan
scheduled all six groups as finishers, but every rendered spec said only "finish the open half" and cut the worktree
from main. Nothing named the branches, so the finishers would have redone the work and the WIP would have been
stranded.

Two mechanisms in `scripts/orchestrator/plan_wave.py#plan` and `#unlanded_branch_notes`:

1. The `half_clusters` loop claimed the notes (`taken`) before the unlanded-branch loop ran. That loop then skipped
   every id already taken, so a branch's resume instruction was discarded whenever its notes were also half.
2. `unlanded_branch_notes` kept only `UNLANDED` branches. Branch 2 had only edited existing files and classified as
   `CHECK`, so it was invisible even with the order fixed. `finisher_pred` already treats `CHECK` like `UNLANDED` for
   reported branches.

Fix: the half loop appends `branch_resume(<branch>, <its ids>)` for every unlanded branch naming a note in the
chunk, and `unlanded_branch_notes` includes `CHECK`. Regression check in `test_plan_wave.py` (`half pred names its
unlanded branch`, `half note planned once`). Re-planned wave 1018: all six specs now name their branch.
