## Measured (adjudicator / refuter evidence, verbatim)
### [exception-condition-handling] Item-identification reads (subscript, reference-modifier position, OCCURS DEPENDING object) decode a character-image numeric data-name through CobolTable.Occ(string) = CobolNum.DigitMagnitude, the tolerant scan, so §14.6.13.2's EC-DATA-INCOMPATIBLE check never runs for them - inside a class condition (rule 1's second sentence / NOTE 1) or anywhere else (rule 2).
- **Rows:** GR-14.6.13.2-1, GR-14.6.13.2-2 — harm `silent`
- **Repro:** >>TURN EC-DATA-INCOMPATIBLE CHECKING ON; 01 G. 05 N PIC 9. 05 K PIC 9. 01 T. 05 BT PIC 1(2) OCCURS 3 VALUE B"10". 01 OG. 05 OE PIC X OCCURS 1 TO 5 DEPENDING ON K. 01 TX. 05 TE PIC X OCCURS 5. 01 X PIC X(5). USE AFTER EXCEPTION CONDITION EC-DATA-INCOMPATIBLE (DISPLAY "RAISED", RESUME NEXT STATEMENT). MOVE "A3" TO G. IF BT(N) IS BOOLEAN ... ; MOVE TE(N) TO X; MOVE X(N:1) TO X; MOVE "3A" TO G. MOVE OG TO X. (scratch: adj-d1/out/probe/ecinc/r1s.cob, r2.cob)
- **Expected (spec):** Each statement sets EC-DATA-INCOMPATIBLE (fatal) and the declarative runs: N / K are numeric sending items whose content 'would evaluate to false in a numeric class condition' and are referenced (§14.6.13.2 2)); for the class test, §14.6.13.2 1) 'The EC-DATA-INCOMPATIBLE exception condition is set to exist for a class condition ... when invalid data is detected during item identification' and NOTE 1 'a subscript reference during a class test could cause the EC-DATA-INCOMPATIBLE exception condition to exist'.
- **Observed:** Pinned cobol.exe: IF BT(N) IS BOOLEAN prints 'nb' (occurrence 0 read leniently) with no raise; MOVE TE(N), MOVE X(N:1) and MOVE OG TO X (ODO object 'A') complete silently. Generated code: CobolTable.At(T.TE, CobolTable.Occ(G.N)) / CobolString.RefMod(X, (int)CobolTable.Occ(G.N), 1) / CobolTable.OdoExtentChars(CobolTable.Occ(G.K), ...). The same N as a direct operand (ADD 1 TO N, DISPLAY N, IF N = 1) raises, so only the item-identification lane is unwired - a two-arm dispatch where the value/string chokepoints got ParseImageSending/SendingImage and Occ(string) did not.
- **Code site:** src/Cobol.Net.Runtime/Values/Tables/CobolTable.cs#Occ(string) and #Occ(string,int) (no SendingRef, no IsNumericImage test); the subscript/refmod/ODO renderers that emit them

### [exception-condition-handling] A BINARY or PACKED-DECIMAL leaf of a group that is written as a whole (no REDEFINES in play) keeps a native value carrier - StorageFormPass.IsImagePromotable promotes usage DISPLAY only - so a group MOVE decodes the leaf's bytes through CobolNum.ParseImage at STORE time and the incompatible content is normalized away: the numeric class condition answers true and rule 2's raise can never fire.
- **Rows:** GR-14.6.13.2-2 — harm `wrong-answer`
- **Repro:** 01 GP. 05 P PIC 9(3) COMP-3. MOVE X"0A1F" TO GP. IF P IS NUMERIC DISPLAY "num" ELSE DISPLAY "notnum". and, under >>TURN EC-DATA-INCOMPATIBLE CHECKING ON with a USE declarative, ADD 1 TO P. (scratch: adj-d1/out/probe/ecinc/r1.cob; contrast pk.cob where 01 GX REDEFINES GP PIC XX exists)
- **Expected (spec):** The group move stores the two bytes unconverted (§14.9.25.4 4) '... except that there is no conversion of data from one form of internal representation to another'); nibble A is not a valid packed digit, so IS NUMERIC is false (§8.8.4.4.4 3) d) 2. c 'consists entirely of a valid representation for the usage') and, under checking, ADD 1 TO P sets EC-DATA-INCOMPATIBLE (§14.6.13.2 2)).
- **Observed:** Pinned cobol.exe prints 'num' (checking on and off) and ADD 1 TO P raises nothing; generated store is P = (long)CobolNum.ParseImage(__s.Substring(0, 2), _P_3). Adding a REDEFINES of GP makes P a window and the same program answers 'notnum' and raises - the answer depends on storage form. kb/Work PB992 (landed) demoted DISPLAY leaves for the character channels and handed BINARY/PACKED to PB970, which landed only the CALL-boundary half; the whole-group-move residue is unowned.
- **Code site:** src/Cobol.Net.Compiler/Binding/Passes/StorageFormPass.cs#IsImagePromotable / ComputePromotedSet.AddNumericDisplayLeaves (DISPLAY-only promotion); the group-store FromImage decode that calls CobolNum.ParseImage

## What the fixer owes
(1) Occ(string) takes the SendingRef path with the IsNumericImage test (raise under checking, class-condition exemption per rule 1/2's bullets); (2) StorageFormPass promotes BINARY/PACKED leaves of a whole-written group to image form as it does DISPLAY (or the group store keeps the raw bytes), so the numeric class condition answers false and rule 2's raise can fire. Goldens under `>>TURN EC-DATA-INCOMPATIBLE CHECKING ON` for a subscript and for a group MOVE of spaces over a COMP-3 leaf.


## Landed — w70c (fix-lane group C, wave 70)

**Mechanism (A), item identification — FIXED at the one numeric position read.** A NUMERIC position operand now
reads through its OWN profile at every scale and in every position: the bind-time subscript text is
`CobolTable.Occ(<field>, _P_n)`, a reference-modification bound `CobolString.RefModPosition(<field>, _P_n)`
(`ReferenceResolver.PositionRead`), and every codegen-time count — the OCCURS DEPENDING object, a RECORD VARYING
DEPENDING length, a report DEPENDING count, SEARCH's bound — goes through the new `PlaceRenderer.CountRead`, the one
renderer of `RuntimeApi.TableOcc(expr, profile)`. The character-image arm of both runtime methods is
`CobolNum.ParseImageSending`, THE checked §14.6.13.2 rule 2 read, so the class-condition exemption covers the item a
class test examines and never the subscript that locates it (rule 1's second sentence, NOTE 1). The profile-less
scale arities `Occ(x, int)` / `RefModPosition(x, int)` are deleted; the one-argument `Occ(long|string)` survives only
for the two NON-numeric `--permissive` carriers COBOLNET0844 admits. `PositionCarrierOverloadDriftTests` holds the
compiler's two carrier lists to the runtime overloads and forbids a profile-less numeric arity from returning.

**Siblings the sweep found and fixed in the same read.** (1) the tolerant digit scan also DROPPED THE SIGN: a signed
image holding −1 positioned occurrence 1 silently (now EC-BOUND-SUBSCRIPT, §8.4.2.3.4 2)); (2) a trailing-P item's
value was read as its storage: `PIC 9P` = 20 positioned occurrence 2 (`CobolNum.PositionOf` now multiplies for a
negative scale, saturating). Both arms of the dispatch — subscript and ref-mod — and both emitters — bind-time
`PositionRead` and codegen-time `CountRead` — take the same profile read.

**Mechanism (B), BINARY / PACKED whole-group leaves — ALREADY LANDED by kb/Work PB1466** (`56098c443`,
`StorageFormPass.IsImagePromotable` promotes every pinned byte form). Re-probed on the w70c build:
`MOVE X"0A1F" TO GP; IF P IS NUMERIC` → `notnum`, `ADD 1 TO P` → RAISED, the COMP leaf `X"FFFF"` → `bnotnum`.
