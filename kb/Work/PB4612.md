# PB4612 — USAGE POINTER TO type-name is a 2002 construct

**What is wrong.** Construct row `usage-pointer-to-type-2014` (status `pending`, `introducedIn: 2014`) says the true edition
is "2002 or 2014". The 2002 text answers it. The refuter's reason: `t2002.txt` is WG4 N 0147 of 2001-12-04, headed
"ISO/IEC 1989:2002(E)"; line 19354 has the USAGE format `POINTER [ TO type-name-1 ]`; line 19422 has SR17 "If type-name-1 is
specified, theTYPEDEF clause shall be specified for the subject of the entry."; line 19574 has GR15 "If type-name-1 is
specified, this data item is a restricted data-pointer." Every statement of the row's witness is legal in 2002 (TYPEDEF
STRONG 19252-19262, BASED 14656, ALLOCATE 22493-22520, SET ADDRESS OF 27931, FREE 24118). The construct appears unchanged in
tfcd2001.txt (19155, 19371), t2009.txt (20776), the FCD (t2014.txt:23051, 23435) and 2023 (§13.18.60.2 `TO type-name-1`,
§13.18.60.3 SR18, §13.18.60.4 GR23, `cite.py --check` OK).

**Our compiler.** `conformance-suite/cases/13.18.60-USAGE/pb153_restricted_pointer.cob` compiles clean at `--std 2002` and
`--std 2014`; no gate fires, and `Constructs.UsagePointerToType2014` has no caller outside the generated files.

**Fix shape.** The row's `introducedIn` becomes 2002, or the row is deleted if nothing should gate it; the fix decides and
records which. Every doc that names the row (`docs/DATA_MODEL_DESIGN.md` about line 1828, `docs/ISO2023_CONFORMANCE_PLAN.md`
about line 654) follows in the same change set.

**Sites:** `tests/version-matrix/constructs.json` (row `usage-pointer-to-type-2014`), `docs/DATA_MODEL_DESIGN.md`,
`docs/ISO2023_CONFORMANCE_PLAN.md`.

**Assignment.** The owner assigned this fix to the Mythos lane (2026-11-04).

**Landed (wave 20261866 A, branch worktree-wf_4dd35aaa-2ac-1).** Decision: the row is DELETED, not renamed to `-2002`.
Re-probe: `pb153_restricted_pointer` compiles and runs at `--std 2002` and `2014` (output identical to its `.out`), and at
`--std 85` draws COBOL0900 through the TYPEDEF, TYPE and BASED gates (`cobol pb153_restricted_pointer.cob --std 85`: TYPEDEF
clause requires COBOL-2002 at lines 34 and 36, TYPE clause at 37, BASED at 37). The restricted pointer's dependencies already
carry the 2002 edge, so a `-2002` row would gate nothing the others do not, and an unwired `pending` row is a dead record
(CLAUDE.md rule 4). The 2002 text (`t2002.txt:19354` `POINTER [ TO type-name-1 ]`, 19422 SR17, 19574 GR15; `cite.py --check
13.18.60.4` OK for the 2023 GR23) is recorded in the golden: `13.18.60-USAGE/pb153_restricted_pointer` now declares
`accept: [2002, 2014, 2023]`. `docs/DATA_MODEL_DESIGN.md`, `docs/ISO2023_CONFORMANCE_PLAN.md` (both said "deferred" for a
feature that is live since PB153) and the construct catalogue lookup follow.

**Sites (as landed):** `tests/version-matrix/constructs.json` (row deleted) with `ConstructRegistry.g.cs` and `Constructs.g.cs`,
`docs/DATA_MODEL_DESIGN.md`, `docs/ISO2023_CONFORMANCE_PLAN.md`, `kb/Spec/Lookup/Construct Catalogue.md`,
`conformance-suite/cases/13.18.60-USAGE/pb153_restricted_pointer.cob`.
