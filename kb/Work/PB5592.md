# PB5592 - a USE FOR DEBUGGING data-name target that is a RENAMES name is matched by the renamed item

**Sites:**
- `src/WiseOwl.Cobol.Compiler/Binding/Bound/DebugTriggerPlanner.cs` (`DebugTriggerPlanner.Find`)
- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/ProcedureTableBuilder.cs` (`ProcedureTableBuilder.AddDebugDataTarget`)
- `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/DebugTriggerEmitter.cs` (`DebugTriggerEmitter.FireText`)

**Rules.** A data-name target's section runs "Immediately after the execution of any other COBOL statement that explicitly
references and causes the content of the data item referenced by identifier-1 to be changed" (§1985:XV.3.2.4 GR6c), and
"DEBUG-NAME contains the first 30 characters of the name that caused the debugging section to be executed"
(§1985:XV.3.2.4 GR13). Both checked with `python scripts/spec/cite.py --check` (OK). A 66-level RENAMES name is an
identifier, and USE FOR DEBUGGING admits any identifier-1 not in the Report Section (§1985:XV.3.2.3 SR9).

**Repro** (`E:/COBOL-coord/scratch/op-20261114/out-read6/refute-rd-01/b7a.cob`, `b7b.cob`; rerun by records-85-held on
its build of origin/main 689413b7de, `E:/COBOL-coord/scratch/op-20261114/records-held/probe/probe.log`), run as
`cobol.exe --std 85 --source-format fixed --run <file>`:

```cobol
       01  W-G.
           05 W-Y PIC 9 VALUE 0.
       66  W-R RENAMES W-Y.
       ...
       D1 SECTION.
           USE FOR DEBUGGING ON W-R.        *> b7b: ON W-R W-Y.
       D1-P.
           DISPLAY "D1 " DEBUG-NAME.
       ...
           MOVE 5 TO W-Y.
           MOVE 6 TO W-R.
```

**Expected (from the text).** b7a (ON W-R): `D1 W-R`, once, for `MOVE 6 TO W-R` (it explicitly references W-R and
changes it; `MOVE 5 TO W-Y` does not reference W-R). b7b (ON W-R W-Y): `D1 W-Y` then `D1 W-R`.

**Observed.** b7a prints nothing: the section never runs. b7b prints `D1 W-Y` twice: the store through W-R runs the
section with DEBUG-NAME `W-Y`, a name the statement never wrote.

**Mechanism (the registrar's reading, to confirm).** `DebugTriggerPlanner.Find` matches a target by
`ReferenceEquals(p.Item, item)`: a store through W-R reaches a place whose item is the renamed W-Y, while
`AddDebugDataTarget` records the target as the item `ProbeDeclaration` resolves for W-R, so the W-R target never
matches and the W-Y target matches both statements; DEBUG-NAME is then the matched target's name. The fix matches a
RENAMES target by the name the statement wrote (and keeps the W-Y target for W-Y's own references), with a witness for
GR6c and GR13 on a RENAMES name, and sweeps the ALL REFERENCES OF arm (GR5) and a RENAMES THRU range for the same
mechanism.
