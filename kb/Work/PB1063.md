## Landing (wave 1007 B, 2026-10-03)

**Re-probed first** (w1007b build): `INVOKE O "M" USING BY CONTENT DP` (DP restricted to `REC-T`, formal `USAGE POINTER`)
compiled and printed `IN-M`. After: COBOLNET0828 "the sender is a RESTRICTED data-pointer of type 'REC-T' … (ISO §14.9.39.3
SR19, third sentence)"; the CALL AS NESTED twin is COBOLNET1688.

**Fix.** The class-pointer arm of `OoConformance.ContentMismatch` compared only the category. It now asks the WHOLE SET
question through `SetBinder.PointerAssignmentReason(receiver, sender)` — ONE §14.9.39.3 pair verdict: data-pointer SR19 (both
directions, over `StrongTypeModel.PointerRestriction` / `SameRestriction`), program-pointer SR22 (only a RESTRICTED receiver is
conditioned; an unrestricted sender into it is refused), function-pointer SR20 (same signature). SET Format 8 and Format 9 use
the same predicate (their two hand loops were deleted), and `ContentMismatch` takes it as a required delegate, so the INVOKE lane
(`OoBinder.OoBindInvocationArg`) and the CALL/function lane (`ParameterConformance.ContentConformanceReason`) ask it alike.
Sibling arm fixed in the same change: the SR22 program-pointer leg (an unrestricted program-pointer BY CONTENT into a restricted
formal was admitted).
