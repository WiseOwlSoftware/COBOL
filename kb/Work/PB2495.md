# PB2495 — LANDED

Filed by the train-1034b lander from the wave-1034 group G report (PB2464, `E:\COBOL-coord\scratch\reports\w1034g-PB2103-report.md`,
lead 2). Not re-probed by the lander.

**Mechanism.** PB2464 typed a restricted program- or function-pointer by its prototype's SIGNATURE class
(`src/Cobol.Net.Compiler/Binding/PrototypeSignatureClasses.cs`, built by `PrototypeSignatures.Same`). A signature whose formal is
itself a restricted pointer compares that formal's restriction through the pointer arm
(`src/Cobol.Net.Compiler/Oo/OoConformance.cs#CategoryArmMismatch`, the program/function-pointer arm, via
`PrototypeSignatures.RestrictionIdentity`), and inside `Same` that nested restriction resolves to the prototype's own NAME when it
names a prototype still being classified. Two prototypes P1 and P2 whose only formal is a pointer restricted to P1 (resp. P2) are
the same signature by §13.18.60.4 GR25 (bisimilar), but the comparison sees `TO P1` against `TO P2` and founds two classes.

**Expected.** §13.18.60.4 GR25: a restricted program-pointer holds "the address of a program with the same signature as that
identified by the specified program-prototype-name"; §14.9.39.3 SR20 / SR22 admit a SET between pointers of the same signature;
§14.8.2.3.2 4) "both shall be restricted and of the same type". The class relation must be the greatest fixed point
(bisimulation): assume the pair equal while comparing their nested restrictions.

**Repro.** `E:\COBOL-coord\scratch\w1034g\probe\selfref.cob`. **Site.** `PrototypeSignatureClasses.Namespace.Identity` and the
pointer arm of `OoConformance.CategoryArmMismatch`.

## Landed (wave 1070, group F)

**Re-probe.** The note's `selfref.cob` is not legal source as written (a prototype's DATA DIVISION may hold only a LINKAGE
SECTION, §10.6.2 SR4 e), COBOLNET2272). The legal shape — `PS1 IS PROTOTYPE` with `REPOSITORY. PROGRAM PS2.` and `USING`
a `TYPEDEF ... PROGRAM-POINTER TO PS2` item, `PS2` the mirror, `PS3` naming itself — reproduced on base `92cfea452`:
`SET B TO A` (TO PS2 from TO PS1) drew COBOLNET1959 (`E:\COBOL-coord\scratch\w1070f\probe\mutualrepo.cob`).

**Mechanism, measured.** Two causes, one rule. (1) Inside `PrototypeSignatures.Same` a formal that is itself a restricted
pointer was compared through the typed comparator's pointer arm by its stamped class identity, which during classification
is the prototype's own NAME — so the comparison was the least, not the greatest, fixed point. (2) The group-level signature
checks — `CheckPrototypeSignaturePairs` (§10.6.2 SR2 / SR3, COBOLNET1513) and the four OO checks (override COBOLNET0829,
implements COBOLNET0841, interface inheritance, property accessors) — ran BEFORE `BinderDriver.ResolvePointerRestrictions`,
so they compared every restricted prototype-pointer pair by name: a prototype / definition pair or an override restricted
to two differently named prototypes of ONE signature was refused (`probe\pairs.cob`, `probe\override.cob`; PB2464's sibling).

**Fix.** `DataItem.RestrictedPrototype` (record `RestrictedPrototype`: namespace, externalized name, signature) is attached
to every pointer by `DataBinder.ResolveRestrictedPrototypes` over EVERY forest first; `DataBinder.ClassifyRestrictedPrototypes`
then stamps the class. `PrototypeSignatures.SameType` is the ONE "of the same type" relation: outside a signature comparison
it compares classes; inside `Same` (which now threads a `PrototypeBisimulation` through `OoConformance.DescriptionMismatch`'s
`prototypes:` parameter) it compares the two named signatures with the pair assumed equal — the greatest fixed point. The
signature checks moved after `ResolvePointerRestrictions`, pinned by
`PrototypePointerTypeDriftTests.EverySignatureCheckRunsAfterThePointerTypesAreResolved`. `PrototypeSignatureClasses.Identity`
replaces `ProgramIdentity` / `FunctionIdentity`. The function-pointer carrier shares the code (probed: `probe\fmutual.cob`).

**Goldens.** `2002/pb2495_recursive_prototype_signature` (SET SR22 between PS1 / PS2 / PS3, a CALL against a prototype /
definition pair restricted to PS2 / PS1, a universal INVOKE that matches, and one into DX1 — a different signature two steps
down — that sets EC-OO-METHOD); `2002/pb2495_pointer_type_in_signature_checks` (SR2 pair, override, implements); negative
`pb2495-recursive-prototype-signature-mismatch` (COBOLNET1959, at 2002 2014 2023). No inventory row (closes_rows: []).
