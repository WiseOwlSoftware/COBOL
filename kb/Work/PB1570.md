# PB1570

Found 2026-09-24 by the w59c (PB1036) implementer — latent, not measured to misfire. Site
`src/Cobol.Net.Runtime/IO/CobolSort.cs` `private static readonly Dictionary<string, Store> Files`. Fix: scope the store to
the run unit (the same carrier the other per-run-unit runtime state uses — find it, do not invent a second one), and
probe two run units sorting concurrently (a parallel test) before and after. Sweep the runtime for other process-wide
statics holding run-unit state (variant-analysis).

**Now measured to misfire (2026-10-05, wave 1021 group E, `E:\COBOL-coord\scratch\reports\w1021e-PB1408-report.md`).**
The Unit leg threw "Collection was modified" when `SortMergeStatementEcTests` ran beside another sort test class: two
in-process run units enumerating and mutating `Files` (CobolSort.cs:113) at once. The implementer serialised the sort
test classes, which hides the race in the gate; the root fix above is still owed (a per-run-unit store ends the class).

## Landing (wave 1034, group H)

Code sites for the next implementer: `src/Cobol.Net.Runtime/IO/SortFileTable.cs#SortFileTable` — the run unit's sort-merge
stores (`Get` creates, `Find` is the no-create lookup the checked RELEASE/RETURN entries use, `AnyInPhase` is the PB1036
-ACTIVE scan; reuse them, never a second dictionary); `src/Cobol.Net.Runtime/IO/CobolSort.cs#Stores` — the one read of
`RunUnit.Current.SortFiles`; `tests/Cobol.Net.Tests.Unit/RunUnitStateDriftTests.cs#ProcessLifetimeCollections` — add a
reason there for any new `static readonly` mutable collection. Trap: a test that sets `ExceptionState.*Checking` and
uses `CobolSort` shares the ambient run unit's state, which is now the isolation boundary, not a process lock.

Re-probed against the old store: both new witnesses in `tests/Cobol.Net.Tests.Unit/SortFileRunUnitScopeTests.cs`
FAILED on the old code (`ConcurrentRunUnits_DoNotShareSortFilesOrProcedurePhases`: run unit B's `Init` raised
EC-SORT-MERGE-ACTIVE because run unit A sat in an input procedure; `AbandonedStatement_DoesNotOutliveItsRunUnit`: a
statement abandoned in run unit 1 raised -ACTIVE in run unit 2) and pass on the fix.

Root fix: the stores are `RunUnit.SortFiles` (`SortFileTable`, `src/Cobol.Net.Runtime/IO/SortFileTable.cs`, holding
`SortStore` and `ProcedurePhase` moved out of `CobolSort`), reached through `RunUnit.Current`; `CobolSort` keeps the
statement logic and the emitted surface and only its storage moved. A new run unit is a new object, so it starts with no
store and `AnyInPhase` (the PB1036 scan) sees only its own run unit's procedures (ISO 14.6.1: a run unit
communicates only via messages, process files and switches). No lock: a run unit executes on one logical thread.

Structure that keeps it true: `RunUnitStateDriftTests.NoStaticMutableCollection_OutsideTheDocumentedProcessStores`
reflects over every `static readonly` mutable collection in the runtime assembly (the blind spot the existing
writable-static test documented) and requires a written reason for each of the 14 that are legitimately process state.
The two `[Collection("process-globals")]` serialisations wave 1021 added to `SortMergeStatementEcTests` and
`SortNumericKeyLaneTests` hid this race and are removed. Sibling sweep: the other static mutable collections are
memos keyed by immutable inputs, the exception-condition table, a locked once-per-process stderr latch, and the
pointer-image base tables (process-wide by PB970); none holds a run unit's state.
