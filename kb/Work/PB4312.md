# PB4312 (re-scoped 2026-11-02; original title below) - COBOL0901 and COBOL0001 print the FOLDED spelling of a word written with U+0130 or U+212A (U+0130 in DISPLAY prints "DISPLAY is a reserved word"; WOR+U+212A+ING-STORAGE prints "unexpected 'WORKING-STORAGE'"), naming a spelling the user did not write; the refusals themselves are correct under section 8.1.3.2 4) and E.2 14)

Found by the Mythos front-end review, gap pass, 2026-10-31 (GAP-REVIEW.md, G5-7; artifact https://claude.ai/artifact/KaxkLe85tfZBZ3nZ1tDGTs). Pin d7daee1cf.

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/CobolParserCoreBase.cs:709` (the user-word gate: `CobolNames.UpperFold` -> `ReservedWordSet.RejectsAt`); `CobolNames.Table.cs` (mappings 0130->0069, 212A->006B); the COBOL0901/COBOL0001 message sites; `docs/rearchitecture/DESIGN-frontend-grammar.md` section 3.13 (record the determination).

**Finding.** `DISPLAY "X".` spelled with U+0130 draws COBOL0001 and `01` + U+0130 + `ISPLAY PIC X` draws COBOL0901 "DISPLAY is a reserved word" (`G5/u130-*.cob`; `u-identity.cob` shows identity already folds U+0130 -> i, PB1402). The first report's "one refusal is wrong whichever way GR4 b) is read" is REFUTED by the rule's own scope: section 8.1.3.2 4) opens "Extended letters in user-defined words are subject to the following rules", so the b) fold governs user-defined words only; keywords match only through 3) a) (basic letters, case-insensitive). The U+0130 spelling is not the keyword (COBOL0001 right) and as a user word folds to `display`, which section 8.3.2.1 1) forbids (COBOL0901 right). The reading "never fold a basic-letter-target mapping" is refuted by 2023 E.2 14), which lists the deletion of (0131,0069) as a change affecting existing programs - only true if such mappings fold user words. What survives: COBOL0901 and COBOL0001 print the FOLDED spelling ("DISPLAY"; the Kelvin probe `u-kw-kelvin.cob` WOR+U+212A+ING-STORAGE draws "unexpected 'WORKING-STORAGE'", a spelling the user did not write that looks legal). Only (0130,0069) and (212A,006B) in Annex C.2 have a basic-letter target. Probes u130-keyword, u130-userword, u-identity, u-kw-kelvin.

**Fix direction.** Print the user's spelling in both messages. Record the determination (fold scoped to user-defined words; basic-letter-target mappings DO fold user words) in DESIGN-frontend-grammar.md section 3.13. PB4240's direction reverses: its accepted U+0130 `>>IF`/`>>END-IF` are the outliers (see the PB4240 addendum).

**Waits on owner question 2** (GAP-REVIEW.md section 5.3): "Confirm the reading that section 8.1.3.2 GR4's fold (Annex C, including the two basic-letter-target mappings 0130->i and 212A->k) governs user-defined words only, so DISPLAY written with U+0130 is neither the DISPLAY verb nor a legal data-name, and directive keywords are matched on basic letters alone?" Recommended yes (GR4's opening sentence; E.2 14); the pinned compiler already does exactly this except for `>>IF`/`>>END-IF`). No (fold keywords too): nothing in the text supports it. The residual either way is the diagnostics printing the folded spelling.

**Citations checked** (`python scripts/spec/cite.py --check`): section 8.1.3.2 "Extended letters in user-defined words are subject to the following rules"; section 8.3.2.1 "Reserved words shall not be used as user-defined words or system-names"; section E.2 "The following case mappings have been deleted".

**Evidence.** E:/COBOL-coord/scratch/w-gr2/GAP-REVIEW.md (sections 2 and 5.1); G5/u130-*.cob, u-identity.cob, u-kw-kelvin.cob; review-G5.md. ## Re-verdict (wave 20261817 A review, 2026-11-02) and re-scope

**The U+0130 / U+212A cases no longer reproduce.** PB4420 (landed; owner 2026-11-01, "Follow gnucobol") stopped the fold from mapping an extended letter to a basic one: `(0130,0069)` and `(212A,006B)` (and, below 2023, `(0131,0069)`) are in `CobolNames.NotApplied`. So a word written with U+0130 is no longer the keyword DISPLAY and no longer the user word `display` (no COBOL0901 "DISPLAY is a reserved word" at all), and the PB4420 reviewer's probe of `WOR<U+212A>ING-STORAGE` prints the Kelvin sign as written, not "unexpected 'WORKING-STORAGE'". This note is NOT closed: that verdict comes from the PB4420 review report, not from a re-run against a built compiler in this change, and the cases below remain.

**What stays (the re-scope).** The same root, a diagnostic printing a folded spelling instead of the user's, survives where the fold still changes a letter:
- `CobolWordsDirectiveProcessor#Spelled` (about line 291, `keyword ? CobolKeywords.Spelling(text) : CobolNames.UpperFold(text)`): the keyword / user-word split now differs only in how an extended letter is spelled in a diagnostic (`UpperFold` lowercases an uppercase extended letter such as E-acute, `Spelling` keeps it), so a user word in a `>>COBOL-WORDS` diagnostic is printed folded. Found by the PB4420 review (lead 2).
- The dotless i (U+0131) below 2023: unverified. PB4420 leaves it as written at 2002 and 2014, so the diagnostic should print it as written; probe a data name starting with U+0131 at `--std 2014` before closing.
- The other COBOL0901 / COBOL0001 message sites that print a folded user word (the Sites list above): sweep them for the written spelling.

**Fix direction (unchanged).** Print the user's spelling in every message that names a user-written word, from the token text and never from the fold; probe the three cases above on a built compiler and close the note when none prints a spelling the user did not write.

## Landed (wave 20261826 group A)

**Re-probe** (built tree 753b58483, `--std 2023`): `>>COBOL-WORDS RESERVE "CAFÉ-"` drew COBOL1623 "'CAFé-' is not a valid
user-defined word"; a second `RESERVE "ÉCOLE"` drew SR5's "the COBOL word 'éCOLE'"; and the §8.9 funnel named a word that
`RESERVE "café"` reserved, written `CAFÉ`, as "'CAFé' is a reserved word". The U+0130 / U+212A cases stay discharged by
PB4420 (re-probed: no fold to a basic letter). The dotless i at `--std 2014` (`01 ıTEM PIC X.` and a MOVE to it) compiles
clean, so no message prints it.

**Fix.** One rule: the fold decides identity, never spelling. `CobolWordsDirectiveProcessor.Spelled` keeps BOTH words in
`CobolKeywords.Spelling` (the letters written, the basic ones raised); the fresh word is compared through the fold
comparers it already met (`CobolWordsMap`'s `CobolNames.Comparer` sets, SR5's `seenWords`, the §8.9 and §8.10 tables), so
nothing that looks it up changed, and `Literal`'s `keyword` parameter, which only chose the spelling, is gone.
`VersionConformancePass.FlagReservedUserWord` takes the fold (lookup and once-per-word key) and the spelling (the message)
from both its callers. Determination recorded in DESIGN-frontend-grammar.md §3.13.

**Goldens.** `7.3.10-COBOL-WORDS/pb4312-reserved-fresh-word-named-as-written` (COBOL0901 'CAFÉ') and
`pb4312-fresh-word-diagnostic-spelled-as-written` (COBOL1623 'CAFÉ-'), both at 2023 (the directive's edition).
