# PB4312 - COBOL0901 and COBOL0001 print the FOLDED spelling of a word written with U+0130 or U+212A (U+0130 in DISPLAY prints "DISPLAY is a reserved word"; WOR+U+212A+ING-STORAGE prints "unexpected 'WORKING-STORAGE'"), naming a spelling the user did not write; the refusals themselves are correct under section 8.1.3.2 4) and E.2 14)

Found by the Mythos front-end review, gap pass, 2026-10-31 (GAP-REVIEW.md, G5-7; artifact https://claude.ai/artifact/KaxkLe85tfZBZ3nZ1tDGTs). Pin d7daee1cf.

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/CobolParserCoreBase.cs:709` (the user-word gate: `CobolNames.UpperFold` -> `ReservedWordSet.RejectsAt`); `CobolNames.Table.cs` (mappings 0130->0069, 212A->006B); the COBOL0901/COBOL0001 message sites; `docs/rearchitecture/DESIGN-frontend-grammar.md` section 3.13 (record the determination).

**Finding.** `DISPLAY "X".` spelled with U+0130 draws COBOL0001 and `01` + U+0130 + `ISPLAY PIC X` draws COBOL0901 "DISPLAY is a reserved word" (`G5/u130-*.cob`; `u-identity.cob` shows identity already folds U+0130 -> i, PB1402). The first report's "one refusal is wrong whichever way GR4 b) is read" is REFUTED by the rule's own scope: section 8.1.3.2 4) opens "Extended letters in user-defined words are subject to the following rules", so the b) fold governs user-defined words only; keywords match only through 3) a) (basic letters, case-insensitive). The U+0130 spelling is not the keyword (COBOL0001 right) and as a user word folds to `display`, which section 8.3.2.1 1) forbids (COBOL0901 right). The reading "never fold a basic-letter-target mapping" is refuted by 2023 E.2 14), which lists the deletion of (0131,0069) as a change affecting existing programs - only true if such mappings fold user words. What survives: COBOL0901 and COBOL0001 print the FOLDED spelling ("DISPLAY"; the Kelvin probe `u-kw-kelvin.cob` WOR+U+212A+ING-STORAGE draws "unexpected 'WORKING-STORAGE'", a spelling the user did not write that looks legal). Only (0130,0069) and (212A,006B) in Annex C.2 have a basic-letter target. Probes u130-keyword, u130-userword, u-identity, u-kw-kelvin.

**Fix direction.** Print the user's spelling in both messages. Record the determination (fold scoped to user-defined words; basic-letter-target mappings DO fold user words) in DESIGN-frontend-grammar.md section 3.13. PB4240's direction reverses: its accepted U+0130 `>>IF`/`>>END-IF` are the outliers (see the PB4240 addendum).

**Waits on owner question 2** (GAP-REVIEW.md section 5.3): "Confirm the reading that section 8.1.3.2 GR4's fold (Annex C, including the two basic-letter-target mappings 0130->i and 212A->k) governs user-defined words only, so DISPLAY written with U+0130 is neither the DISPLAY verb nor a legal data-name, and directive keywords are matched on basic letters alone?" Recommended yes (GR4's opening sentence; E.2 14); the pinned compiler already does exactly this except for `>>IF`/`>>END-IF`). No (fold keywords too): nothing in the text supports it. The residual either way is the diagnostics printing the folded spelling.

**Citations checked** (`python scripts/spec/cite.py --check`): section 8.1.3.2 "Extended letters in user-defined words are subject to the following rules"; section 8.3.2.1 "Reserved words shall not be used as user-defined words or system-names"; section E.2 "The following case mappings have been deleted".
