# PB24 — FUNCTION LENGTH is wrong or absent on four shapes

⚙ **ALL FOUR CLAIMS RE-MEASURED 2026-08-04 BEFORE ANY CODE CHANGED. Three held, one did not.**

## ✅ LANDED — a reference-modified argument (was: compiles clean, throws at run time)

`FUNCTION LENGTH(WS-NAME(1:5))` is conforming source — §15.50.3 r1 admits "a data item of any class or category"
and §8.4.3.3.3 makes a reference-modified item one (both `cite.py --check`ed). It bound to a `BoundExprError`,
which renders as a NotImplemented guard: **compiled clean, threw at run time, exit 127.** The PB7/DA7 wrong-stage
family — except there was no verdict to deliver at all, because the source is legal and the answer computable.

**The fix added no machinery, and that is the interesting part.** `IntrinsicRenderer`'s `Length` arm renders its
argument through the ONE string channel, and a reference-modified place renders as the **substring** — so the
runtime length over that image already IS §15.50.4's character-position count. Changing the arm from
`BoundExprError` to the runtime `BoundIntrinsicCall` was the whole change, and all three ref-mod forms fell out
together: literal `(1:5)` → 5, runtime `(I:L)` → 6, omitted-length `(15:)` → 6, and `(20:1)` → 1.
Golden: `2023/pb24_length_refmod_argument`.

## ⛔ OPEN — a variable-length group returns a SILENTLY WRONG constant

**Measured:** a group of `PIC X(4)` plus a `PIC X DYNAMIC LENGTH` child holding `"XYZ"` returns **4**. §15.50.4 r7
requires **7** — the fixed subordinates *plus the current lengths of dynamic-length subordinates*. No diagnostic.

**Root cause, located:** `BindLengthFold` is a `switch` with arms for ref-mod, ODO groups, ANY LENGTH, national
dynamic-length and dynamic-length *elementary* items — and **no arm for a GROUP containing a dynamic descendant**.
Such a group falls through to the fixed fold `BoundNumLiteral(f.Place.Item.ImageWidth)`, and `DataItem.ImageWidth`
returns **0** for a dynamic-length child (`DataItem.cs`, `if (IsDynamicLength) return 0;`). A missing arm in a
dispatch — this compiler's most reproducible defect shape.

⚠ **The obvious cheap fix does not work, and this was measured too:** routing the group to the runtime string
channel fails, because the whole-group image of a group with a dynamic child is itself staged loud
("Tier-C byte island … no whole-group character image"). The fix needs a purpose-built sum — constant fixed part
plus each dynamic child's current length plus dynamic-capacity tables at current capacity (r7 a/b/c) — built from
the compile-time known structure.

## ⛔ OPEN — the PHYSICAL argument does not exist

`FUNCTION LENGTH(WS-G PHYSICAL)` → `COBOLNET1504: FUNCTION LENGTH takes 1 argument(s); 2 given`. §15.50.2's
general format is `FUNCTION LENGTH ( argument-1 [ PHYSICAL ] )`, so `PHYSICAL` is an optional KEYWORD, not a
second argument — it is being parsed as one. Needs a grammar production (pre-authorised), a catalog arity slot,
and §15.50.4 r8's semantics. **This rejects legal source.**

## ⚠ NOT MEASURED — the §15.50.4 r9 rounding step

"When the returned value is expressed as a number of alphanumeric character positions and argument-1 does not
occupy an integral number of positions, the returned value is rounded up." Reachable only through boolean/bit
items, which this probe set did not construct. **Unverified either way** — do not record it as absent without a
repro.

## ⛔ AND ONE CLAIM DID NOT SURVIVE

The original entry said the variable-length group case covered **OCCURS DEPENDING** and was "silent". It is not:
an ODO group raises `NotImplementedCobolFeatureException` naming §15.50.4 r7 — **loud, at run time**. The silent
wrong answer is specific to a **dynamic-length** child (§8.5.1.12), which is what the entry's own citation said
and its prose contradicted. Corrected here rather than carried forward.
