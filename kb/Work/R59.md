# R59 — `USING N + 1`

The question was whether `INVOKE O "M" USING N + 1` is one argument or two (`N` and `+ 1`), for CALL and INVOKE together. **Owner: one argument — the expression is evaluated before the call**, its value passed as any other expression argument (by content). GnuCOBOL's CALL grammar takes no expressions, so it could not break the tie; the decision is the only reading under which the source means anything. CALL and INVOKE answer identically; the grammar half landed with PB1135 (9264d6dd4), this fixes the residual determination and its golden.

## Re-verified against the ISO text (2026-09-30)

Both general formats answer it. CALL (§14.9.4.2 Format 2 diagram) and INVOKE (§14.9.23.2) list `arithmetic-expression-1` (and `boolean-expression-1`) as a USING operand under `[ BY CONTENT ]` — the BY CONTENT bracket is OPTIONAL — and CALL SR20 (cite-checked) says "BY CONTENT shall not be omitted when identifier-4 is an identifier that is permitted as a receiving operand" (so it MAY be omitted for an expression or literal). SR17: any identifier in arithmetic-expression-1 is a sending operand. Therefore a keyword-less `N + 1` is ONE argument — an arithmetic-expression-1 passed by content — by the grammar, not by preference. The earlier claim that GnuCOBOL's silence left the question open was wrong: ISO is explicit. This was presented to the owner as a question in error.
