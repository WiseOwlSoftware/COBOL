# PB3628 — a re-armed NOT QUEUED branch is stranded

Filed 2026-10-24 by the clerk from the coordinator's report. Related: PB3103 (the landing lane), PB3527 (the queue watch).
Not re-probed by the clerk; no existing note covers it.

**Site.** `scripts/orchestrator/land_lane.py` line 742, `candidates()`: the re-arm loop skips a row whose state is in
("ENQUEUED", "NOT QUEUED", "LANDED"). The docstring (line ~725) says a re-armed BOUNCED branch is included because
`enqueue.py land` reuses its open pull request and queues it again. A NOT QUEUED branch is the same case, but it is excluded.

**Witness, 2026-10-24.** Worktree `worktree-wf_0e51b14b-ced-6` (PB3155). PR #467 bounced (ci-gate failed). Finisher 2 fixed it at
local tip 9e871991b, reviewed CLEAN r3, and `land_lane.py rearm` re-armed it at that head at 08:12:12Z. At 09:45Z, after many
supervisor ticks and one manual `land_lane.py tick`, no attempt had started. `land_lane.py status` still read "REARMED ... the next
tick lands it again". `prune_worktrees.py` read it NOT QUEUED (merge state DIRTY, ci-gate failure, remote PR head ff80fe76 differs
from local tip 9e871991). The lane's queue watch says "LEFT (pull request #467 is BOUNCED (ci-gate failed): the enqueue unit's
finisher)". So the branch is stranded: no reader acts on it, and the status line misleads.

**Two readers disagree.** The queue watch classifies the pull request BOUNCED; the survey classifies it NOT QUEUED.

**Fix direction (for the implementer).** Include a re-armed NOT QUEUED row when the open pull request's head differs from the
re-armed tip, or when its required check failed. Make the survey and the queue watch read one classification. Add a `land_lane`
self-test case beside the existing case 12 (rearm records the BOUNCED branch) for a re-armed NOT QUEUED branch.

## Landed (2026-10-24, fix-lane wave 20261030 group A)

**Re-probe.** The witness branch has moved on (it landed through a later attempt), so the repro is the survey's own
self-test: PR #467's shape (a pull request at an OLDER head than the branch's reviewed tip, auto-merge still on there,
a red required check, merge state DIRTY) read `NOT QUEUED` on the unfixed tree (`prune_worktrees.py --self-test`, three
new checks red). The note's diagnosis held, with a sharper root than the one it proposed.

**Root.** Not `land_lane.candidates` but `prune_worktrees.lifecycle`: its NOT QUEUED arm tested `pr.auto_merge_at`
without asking whether the pull request was at the branch's tip ("GitHub's promise to queue the pull request at ITS head,
whatever the local tip"). `enqueue.py land` force-pushes the tip onto the same pull request and queues it again, so a
pull request at an older head is the OLD landing's: the queue watch had already ended it (`watch_step`: a moved head is a
new landing, a red or conflicting one is LEFT as BOUNCED), and the survey's BOUNCED arm skips it too (`at_head`). Only the
NOT QUEUED arm still claimed it, a state neither `candidates` nor the enqueue unit acts on. The two readers did not
disagree about the pull request; the survey disagreed with its own BOUNCED rule ("a tip that moved past the bounced head
is the fix, and reads by its report again").

**Fix.** `lifecycle` reads NOT QUEUED only for a pull request AT the tip (`at_head and (auto-merge or the lane's ENQUEUED
attempt at the tip)`); an older-head pull request falls through to the report arms, so a reviewed-CLEAN branch reads
WAITING TO LAND and the lane lands it (re-armed or not). `candidates` needed no change (a NOT QUEUED row at the tip is the
queue watch's: the pull request is open, and re-landing it at the same head changes nothing), but its two hand-written
state tuples became one `QUEUE_OWNED`. Two siblings fixed in the same change: `landing_state`'s exit-0 arm said "no pull
request is open" of a branch whose pull request is open at another head (it now names the head), and `status`'s REARMED
line promised "the next tick lands it again" of a branch the lane would never start (`rearm_effect` reads the last survey).

**Tests.** `prune_worktrees.py --self-test`: the `unreviewed` fixture (head `x`, auto-merge on, removed) now reads WAITING
FOR REVIEW; the NOT QUEUED evidence check runs on a pull request at the tip; new checks for the stranded shape (WAITING TO
LAND), the re-armed variant through `land_lane.candidates`, and the exit-0-at-another-head evidence. `land_lane.py
--self-test` case 12c: the finisher's tip launches, a re-armed NOT QUEUED row does not, and its status line says so.

**Open sibling, not fixed:** `lifecycle` reads ENQUEUED for any pull request IN the merge queue whatever the local tip; a
commit made after the queue took the pull request is the queue's to merge first (a force-push would eject it), and the
branch then reads CHECK by its content. No stranded state results, so no note.
