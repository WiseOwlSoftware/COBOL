# PB5871 - at --std 2002 ASSIGN USING refuses an alphabetic data-name-1

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/FileControlBinder.Resolve.cs#ResolveAssignUsing` (asks
`ItemCategory.IsAlphanumeric(item)`, the DataItem overload with no edition, at every edition).

**Mechanism.** PB5615 put COBOL-2002's alphabetic-as-alphanumeric rule in one edition predicate,
`EditionInfo.AlphabeticIsAlphanumeric`, read through `ItemCategory.IsAlphanumericOrNational(Place, EditionInfo)` and
`IntrinsicArgumentRules.Violation`, and moved every statement-operand screen to it. It left the file-control clause
operands on the DataItem overloads, holding that a clause operand is not "an operand" of the 2002 sentence in the way a
statement's is. The golden-2002-7 integrator read §2002:12.3.4.2 SR7 with §2002:8.5.2.1 the other way, and that reading is
the plain one for ASSIGN USING: SR7 is worded "alphanumeric data item" and 8.5.2.1 lets an alphabetic item stand wherever an
elementary alphanumeric one "is permitted as an operand".

**Rules (each checked with `python scripts/spec/cite.py --check`, verdict OK).**

- `§2002:12.3.4.2 SR7`: "Data-name-1 shall reference an alphanumeric data item"
- `§2002:8.5.2.1`: "An alphabetic data item may be specified wherever an elementary alphanumeric data item is permitted as an operand"

**Repro.** In the finding file beside this note (`g2asg06.cob`, `--std 2002 --run`): COBOL1810, rc 65. Expected: compiles,
writes and reads back the record.

**Sibling sweep owed.** The other file-control clause operands on the same DataItem overloads (RECORD KEY, ALTERNATE RECORD
KEY, FILE STATUS, SORT and MERGE keys, REPORT CODE: `FileControlBinder.cs`, `FileControlKeyRules.cs`,
`ReportSectionBinder.cs`), each read against its own 2002 rule.

**Scheduling.** 2002 work is frozen behind 1985 (owner 2026-11-16); this note waits for that order to lift.

## Landed 2026-11-23 (wave 20262150 group C)

**Ruling (the question PB6073 item 1 carried).** The file control clause operands are operands of §2002:8.5.2.1's second sentence:
"Where an alphabetic data item is not expressly permitted, the alphabetic data item is treated as though it were an alphanumeric data
item" (checked with `cite.py --check`) is not limited to statement operands, and none of the 2002 file control rules (§2002:12.3.4.2 SR7,
§2002:12.3.4.12.2 SR2, §2002:12.3.4.5.2 SR2, §2002:12.3.4.7.2 SR2, §2002:12.3.4.10.2 SR3) expressly permits an alphabetic item. So at
`--std 2002` (`EditionInfo.AlphabeticIsAlphanumeric`) a PIC A item is admitted as ASSIGN USING data-name-1, RECORD KEY, ALTERNATE RECORD
KEY and their SOURCE data-name-2, FILE STATUS, PADDING CHARACTER and REPORT CODE operands; COBOL-2014 withdrew the sentence (§2014:E.2)
so those editions refuse it as before.

**Fix.** `ItemCategory.IsAlphanumeric` and `IsAlphanumericOrNational` (the DataItem overloads) take the `EditionInfo`, and the edition-less
overloads are deleted: one reader of the edition axis for the Place and the DataItem forms. Every caller passes its edition:
`FileControlBinder.Resolve.cs` (`ResolveAssignUsing`, `FileStatusShapeFault`, `KeySuppressionOf`), `FileControlBinder.cs`
(`IsNationalKey`, the collating-sequence key screens), `FileControlBinder.Padding.cs` (`ScreenPaddingDataName`),
`ReportSectionBinder.cs` (the CODE operand), `StatementValidation.cs` (`AdmitsIntoRecord`, the READ/RETURN INTO record arm b) and
the `FileControlKeyRules` rows through a new `FileKeyOperand.Edition` (the category rows and `CategoryDiffersFromFirstSource`).
ASSIGN USING's two messages cite the rule of the edition compiled (`AssignUsingRule`).

**Goldens.** `12.3.4@2002-FILE-CONTROL-ENTRY/pb5871-assign-using-alphabetic-2002`, `12.3.4.12@2002-RECORD-KEY-CLAUSE/pb5871-keys-status-alphabetic-2002`,
`12.3.4.10@2002-PADDING-CHARACTER-CLAUSE/pb5871-padding-alphabetic-2002`; refused below: `pb5871-assign-using-alphabetic-refused` and
`pb5871-keys-status-alphabetic-refused` (2014, 2023).
