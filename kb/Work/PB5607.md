# PB5607 - STRING ... WITH POINTER accepts a pointer item too small to hold 1 plus the size of the receiving item (2002 and 2023)

**Sites:**
- `src/WiseOwl.Cobol` .Compiler/Binding/Procedure/Verbs/StringUnstringBinder.cs#BindString (POINTER screen, ~line 144)

**Mechanism.** BindString screens identifier-4 through StrUnstrIsInteger (elementary numeric integer, no P) and never asks the size requirement of the same syntax rule; the pointer then truncates on store.

**Inventory.** Rows claimed: `2002-SR-14.8.39.2-6`.

**Rules (each citation checked with `python scripts/spec/cite.py --check`, verdict OK).**

- `§2002:14.8.39.2 SR6`: "of sufficient size to contain a value equal to 1 plus the size of the data item referenced"
- `§2002:3.1.1`: "to indicate violations of the general formats and the explicit syntax rules of standard COBOL"

**Repro.** Scratch originals under `E:/COBOL-coord/scratch/op-20261114/read-2002/defects-work/` (p/str6-small.cob); the text is inline. Command: `cobol.exe p/str6-small.cob --std 2002 --run`

`p/str6-small.cob`:

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. PSTR6SMALL.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 S1 PIC X(12) VALUE "ABCDEFGHIJKL".
       01 R PIC X(10).
       01 P1 PIC 9 VALUE 1.
       PROCEDURE DIVISION.
           STRING S1 DELIMITED BY SIZE INTO R WITH POINTER P1
             ON OVERFLOW DISPLAY "OVF"
             NOT ON OVERFLOW DISPLAY "NO-OVF" END-STRING.
           DISPLAY "[" R "] P1=" P1.
           STOP RUN.
```

**Observed.** 01 R PIC X(10), 01 P1 PIC 9, STRING ... INTO R WITH POINTER P1: no diagnostic, prints OVF then [ABCDEFGHIJ] P1=1, rc=0.

**Expected (from the 2002 text).** a compile-time diagnostic: P1 (at most 9) cannot hold 11.

**Sibling sweep.** UNSTRING POINTER (StringUnstringBinder ~line 328) and UNSTRING TALLYING / COUNT IN size rules; the kb/Work PB88 witness only covers the integer test.

**Other editions.** 2023: yes (same rule, same code). 85: unknown (check the 1985 STRING pointer rule).
