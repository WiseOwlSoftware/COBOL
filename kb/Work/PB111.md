# PB111 — LANDED 2026-08-19 — `CLASS-ID … OBJECT-COMPUTER. PROGRAM COLLATING SEQUENCE IS REV` / `CHARACTER CLASSIFICATION IS TR` → CS0103 on the emitted class

> ⚙ **flags:** crashes (the backend fails on legal source — `error: backend compilation failed (generated C# at
> …g.cs): error CS0103: The name '__COLLATE' does not exist in the current context`), rejects legal source ·
> found 2026-08-19 while landing [[PB64]] T5 by probing the shape the goldens held fixed — every T5 golden put the
> clause on a PROGRAM; a CLASS-ID with the same clause was the untested arm ([[probe_the_shape_the_subject_hides]])
> — and the PROGRAM COLLATING SEQUENCE sibling was found by the same probe, pre-existing since PB101 · **landed
> 2026-08-19** (the commit after T5's; DEVLOG 1335).

**Spec:** §11.3 (a class definition's ENVIRONMENT DIVISION — its CONFIGURATION SECTION applies to the class's
factory, object and methods); §12.3.6.4 GR8 (`--check` OK: "The character classifications explicitly or implicitly
established by the OBJECT-COMPUTER paragraph are effective with the initial state of the runtime modules to which
they apply"), GR11 (the program collating sequences govern the comparisons); §14.6.6 r2 (`--check` OK: "On
activation of a runtime element, if the CHARACTER CLASSIFICATION clause is specified …") — a METHOD is a runtime
element (§15.65.4 r5 names INVOKE among the activations; kb/Work PB36 put methods on the module-name stack).

**Measured** (`--std 2023`, `scratchpad/probe-oo-cls.cob` / `probe-oo-pcs.cob`): a FACTORY method `MOVE FUNCTION
UPPER-CASE("i") TO R` under `CHARACTER CLASSIFICATION IS TR` → `CS0103 '__CLASSIFY'`; an OBJECT method `IF "A" < "B"`
under `PROGRAM COLLATING SEQUENCE IS REV` → `CS0103 '__COLLATE'`.

**Mechanism:** `ProgramEmitter.EmitProgramClass` declared `__COLLATE` / `__CLASSIFY` / `__COLLATE_NAT` inline for a
PROGRAM class; `OoEmitter.EmitTypeHalf` (the instance and factory classes) declared none of them, while the
renderers (`EmitCore.CollateArg`, `IntrinsicRenderer`, `ConditionRenderer`) reference the names whenever the
unit's `DataBinder.Collating` / `.Classification` is set — and a class's DataBinder DOES carry its configuration.
Two emitters, one contract, written down once — the two-arm-dispatch shape.

## As built

`CodeGen/Roslyn/ObjectComputerEmit.cs` — THE renderer of a runtime-module type's OBJECT-COMPUTER members:
`EmitMembers(data, w, classificationField)` (the collating carriers as per-type constants; the `__CLASSIFY` FIELD for
a program type only) called by the program emitter AND by `EmitTypeHalf` for both class halves;
`ClassificationPrologue` (the program's `__Activate` assignment — a RECURSIVE program and every function get a fresh
instance per activation, so the field is per activation) and `ClassificationLocal` (a METHOD is re-entered on the
SAME object, so each method body resolves its own activation LOCAL — `var __CLASSIFY = CharacterClassification.
Resolve(…)` at the top of the body, captured by the method's dispatch local function — an inner invocation's
resolution never leaks into the outer's); the generated-source `using CobolNet.Runtime.Globalization` header also
counts class units. Golden `2023/pb111_class_object_computer` (CLS-UP = 305 under the class's Turkish
classification; CLS-REL = GT under the class's reversed PCS while the invoking program's PRG-REL = LT natively).
