# PB618 — OPEN — re-run every generator and diff

Found 2026-09-05 by the `PB250` implementer (report §"New defects" (a)), which re-ran `scripts/gen-reserved-words.ps1`
to add the generated §8.10 context-sensitive-word table and found the §8.9 output no longer reproduced what is
committed. That script is fixed in PB250's change set; this note is the SWEEP it deserves and did not get.

## The instance (fixed in PB250)

Two independent rots in one generator, neither detected by any gate:

1. It emitted `namespace CobolNet.Validation` where the committed `ReservedWords.Table.cs` says `CobolNet.Editions`
   — a re-run broke the build.
2. Its OCR continuation-join read the continuation line RAW while the stem line was normalised. After the transcription
   repair that bulleted and code-fenced continuations, the join produced ``FLOAT-NOT-A-NUMBER-- `QUIET` ``, the word
   regex dropped it, and a re-run silently removed **FLOAT-NOT-A-NUMBER-QUIET** and **FLOAT-NOT-A-NUMBER-SIGNALING**
   from the 2023 reserved-word table — an under-rejection (a program may then use them as user-defined words), latent
   until someone re-runs the generator. §8.9 is the authoritative list; its NOTE — "Words can be added or deleted from
   this list for a specific compilation group by use of the COBOL-WORDS directive." (`OK §8.9`) — makes the directive,
   not a generator drift, the only sanctioned way a word leaves it.

Repro of the pre-fix state: `git checkout a00e3529 -- scripts/gen-reserved-words.ps1 && pwsh scripts/gen-reserved-words.ps1
&& git diff tests/version-matrix/reserved-words.json`.

## The pattern ([[a_dead_lookup_is_also_unverified]])

A generated table is trusted BECAUSE it is generated; when the generator no longer reproduces it, the table is a
hand-maintained list wearing a generator's name, and the next person to "just re-run it" ships the drift. Nothing
in CI re-runs the generators and diffs.

## The work

1. Enumerate every generator and the committed artifact each owns. Measured on this tree: `scripts/gen-cobol-words.ps1`,
   `gen-constructs.ps1`, `gen-diagnostics-doc.ps1`, `gen-grammar-diagrams.ps1`, `gen-reserved-words.ps1`,
   `gen-vault-reference.ps1`, `gen-vcr.ps1`, plus the python generators under `scripts/spec/`
   (`gen_conformance_notes.py`, `build_inventory.py`, `gen_ledger.py`) and the `kb/Grammar` regeneration.
2. Re-run each on a clean tree and `git diff --stat` its output. Every non-empty diff is either a rot in the generator
   (fix the generator, keep the artifact) or an unreproduced hand edit to the artifact (fold it into the generator's
   input, never leave it in the output). Attribute each, one commit per generator.
3. Make it structural: a drift test per generator that runs it into a temp dir and asserts byte-equality with the
   committed artifact (the shape `ReservedWordsDriftTests`/`ContextSensitiveWordsDriftTests` already use for the
   spec-section side), so a generator that stops reproducing is red in the wave-local gate, not latent.
