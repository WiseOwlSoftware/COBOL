# PB3444 — a GUARD_TESTS subset naming only the consumer never compiles the predecessor

> flags: process-only

Source: wave 1131 E (PB3385, PR #303), branch review finding R1-1, severity low.

`scripts/guard-run-group.sh:62`. The fix and its comments (guard-run-group.sh 62-64, guard-verdict.sh 363-364, guard-verify.sh
256-258, PB3385 Landed, the DEVLOG) say a `GUARD_TESTS` subset naming only the consumer is where a crashing predecessor goes
unseen. But `guard-fast.sh` compiles only `$TESTS`, so in that subset the predecessor never compiles or runs: the consumer is
always `COMPILE NO-VERDICT`, blaming a compile that was never attempted, and the subset can never grade a chain consumer as
`NistRunner` does (NistRunner compiles the predecessors itself).

**Fix shape.** Either `guard-fast.sh` adds the chain predecessors of the named tests to the set it compiles, or the guard
refuses the subset with a message naming the missing predecessor; then correct the three comments and the PB3385 Landed
paragraph that describe the scenario. Sibling: PB3383 (the same scripts' `GUARD_TESTS` use).
