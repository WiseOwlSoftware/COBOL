# PB6062 - a COBOL program that ends with RETURN-CODE 124 is reported as a timeout

`run_probe.py` sets `status = EXIT_TIMEOUT` (124) in the `except subprocess.TimeoutExpired` arm, then tests `if status == EXIT_TIMEOUT`
after the `with` block. A program whose own exit status is 124 (`MOVE 124 TO RETURN-CODE`, the same value `timeout(1)` uses) takes the
same arm: the probe appends `run_probe: timed out after N s; the process tree was killed` to `stderr.txt`, and the printout says so,
although it ran to its end. An adjudicator reading a probe of a RETURN-CODE test is told the program was killed.

Fix at the root: carry a `timed_out` boolean set where the `TimeoutExpired` is caught, and test that, not the status. The status
stays the program's own. Pair it with a probe of a program that returns 124.

**Sites:** `scripts/orchestrator/run_probe.py` (`EXIT_TIMEOUT`, the wait and the report).
