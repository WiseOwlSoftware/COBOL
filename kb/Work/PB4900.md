# PB4900 - the finished test cannot tell a report that was not written from one it cannot parse

**Witness (wave 20261887, group E, 2026-11-06).** impl-E-PB4856 returned DONE naming `w20261887e-PB4856-report.md`. The file did
not exist. `plan_wave.py --finished` read it UNREADABLE (exit 2), the wave started no review, and the operator wrote the report
by hand at 17:50 (it now opens "Written by the operator on 2026-11-06 at 17:50 ... The facts below come from the branch and its
gate log, not from the implementer"). Its "New leads" section says "Not known: the implementer's own list was not recovered".

**Not PB3361.** PB3361's four witnesses are a `report` field that is a sentence (the path is wrong, the file exists at the
canonical path). Here the path is the canonical one and the file is absent: computing the path from the wave's args, as PB3361
asks, still reads UNREADABLE. The two notes share the finished test's step in the workflow and the exit-2 answer.

**Sites:** `.claude/skills/workstream/templates/wf_rolling_wave.js` (`finishedReport`), `scripts/orchestrator/plan_wave.py` (`finished_main`, whose UNREADABLE print is at line 977).

**Second witness (wave 20261915, group B, 2026-11-07).** impl-B-PB4920 returned DONE at 57193d9c34 with a GREEN gate (run 000001-20261108T000711Z) and wrote no `w20261915b-PB4920-report.md`; `plan_wave.py --finished` read UNREADABLE, no review started, and the loop mailed a STALL 48 minutes later. The operator wrote the report by hand at 17:30 from the branch, its DEVLOG entry and its gate log; the landing lane then reviewed it CLEAN. Two witnesses in two days.

**Third witness (wave 20261921, group H, 2026-11-07).** impl-H-PB4957 returned SPLIT naming `w20261921h-PB4957-report.md`
and wrote no file; the loop counted the group "137 min on running" and mailed STALLs. The operator recovered the report
verbatim from the transcript.

**Cause (found 2026-11-07 from all three transcripts).** Each implementer wrote its report with one shell command,
`mkdir -p <reports> && cat > <reports>/<report> <<'EOF' ... EOF` (group H's began `cd <worktree> &&`). The report directory lies
outside the agent's worktree, and Claude Code's worktree isolation refused the command: "This agent is isolated in the
worktree ..., but this command is too complex to verify that it stays inside the worktree. Refusing to run it". The very
next turn of all three agents was the structured return, naming the report path as if the write had run. The spec said
"write the report" and never how, so each agent chose the shell.

**The fix.** `dispatch-spec-implementer.md` now says, beside the report path, to write the report with the Write tool and
never a shell redirect or heredoc, to `test -f` it, and to return only once it exists; `check_practices.py` requires that
line in every rendered spec, so a later edit cannot drop it silently. MANDATORY-PRACTICES P12 names the isolation refusal
beside the hooks: a refused command did not run, and an agent never returns as if it had. The finished test still reads a
missing report as UNREADABLE and the loop's STALL mail still surfaces one, so a recurrence is caught where these were.
