# PB1507 — OPEN

## The rule (every citation re-run through `cite.py --check`)

> 5) The INITIAL clause shall not be specified if any program that directly or indirectly contains this program is a recursive program.

`OK  §11.10.3 5)  (Syntax rules)`

> 6) The RECURSIVE clause shall not be specified if any program that directly or indirectly contains this program is an initial program.

`OK  §11.10.3 6)  (Syntax rules)`

> When enclosed by brackets, zero or more of the alternatives contained within the choice indicators shall be specified, but any single alternative may be specified only once.

`OK  §5.2.6.4   (Choice indicators)`


## Finding — `cobol-compilation-group` (under-rejects; rows `FMT-10.6.1`)

**Mechanism.** The §10.6.1 source-unit SHAPE is screened only on the prototype arm (PrototypeUnitRules.ScreenUnitShape, COBOLNET2274); the program-definition and function-definition arms ride the shared superset rules programUnit / nestedProgram / endProgramHeader / commonProgramAttribute with no equivalent screen, so illegal nesting, missing or wrong-kind end markers, a non-ISO GLOBAL attribute and repeated attributes all compile silently.

**Repro.** Probes under E:\Temp\claude\E--CobolSharp\a700c052-f9e4-4942-84ff-a13c7505d6ec\scratchpad\adj-d2b\out\probe\cg, pinned cobol.exe, --std 2023 (and 2002), each compiles with NO diagnostic: (a) func_in_prog.cob: PROGRAM-ID. CGFIP. PROCEDURE DIVISION. ... FUNCTION-ID. CGFIPF. ... END FUNCTION CGFIPF. END PROGRAM CGFIP. (function nested in a program); (b) func_nested_run.cob: FUNCTION-ID. CGFNR. ... PROGRAM-ID. CGFNRIN. ... END PROGRAM CGFNRIN. END FUNCTION CGFNR. - runs, CALL 'CGFNRIN' prints INNER; (c) func_no_end.cob: FUNCTION-ID. CGFNE. ... GOBACK. <EOF> (no END FUNCTION); (d) func_end_program.cob: FUNCTION-ID. CGFEP. ... END PROGRAM CGFEP.; end_mismatch.cob: PROGRAM-ID. CGEM. ... END FUNCTION CGEM.; (e) nested_no_pd.cob: IDENTIFICATION DIVISION. PROGRAM-ID. CGNP1. (no PROCEDURE DIVISION) IDENTIFICATION DIVISION. PROGRAM-ID. CGNP1B. ... END PROGRAM CGNP1B. END PROGRAM CGNP1.; (f) global_attr.cob: PROGRAM-ID. CGGA IS GLOBAL PROGRAM.; (g) dup_attr.cob: PROGRAM-ID. CGDA IS INITIAL INITIAL PROGRAM.

**Expected from the spec.** Each is a compile-time error. ISO §10.6.1 (printed page 257, rendered): program-definition is '... [ procedure-division [ program-definition ] … ] [ END PROGRAM program-name-1. ]' - it contains only program-definitions and only after a procedure division - and function-definition is '... [ procedure-division ] END FUNCTION user-function-name-1.' with the end marker unbracketed and no contained unit; the PROGRAM-ID attribute group admits only COMMON and one of INITIAL/RECURSIVE, and §5.2.6.4: 'When enclosed by braces, one or more of the alternatives contained within the choice indicators shall be specified, but any single alternative shall be specified only once.' So (a),(b) violate the containment slots, (c) the required END FUNCTION, (d) the END FUNCTION / END PROGRAM keyword of each format, (e) the procedure-division bracket that carries the nested slot, (f) the attribute alternatives (GLOBAL is none of them), (g) the 'only once' of the choice indicator.

**Observed / reasoning.** All seven compile with exit 0 and no diagnostic; (b) additionally executes the nested program. The prototype arm of the SAME format IS screened - proto_nested.cob draws COBOLNET2274 'a prototype contains no other source unit' - so this is the recurring two-arm shape: PB894 wrote ScreenUnitShape for prototypes and left the definition arms unscreened. Grammar: programUnit/nestedProgram are 'procedureDivision? nestedProgram*' for either paragraph kind, endProgramHeader is 'END (PROGRAM | FUNCTION) programName DOT' for either kind, commonProgramAttribute includes GLOBAL, programIdAttributes is 'programIdAttribute+'. BinderDriver.MakeUnit folds attributes into three booleans (repeats vanish, GLOBAL is dropped) and calls ScreenUnitShape only when isPrototype. A shape fix belongs in ONE place that every unit kind asks (generalise PrototypeUnitRules.ScreenUnitShape into a per-kind source-unit-shape screen driven by the §10.6.1 table: kind -> may-be-contained, may-contain, end-marker keyword, end-marker required), per rule 5.

**Code site.** src/Cobol.Net.Compiler/Binding/BinderDriver.cs#MakeUnit (ScreenUnitShape called only for isPrototype; attribute loop at ~line 382); src/Cobol.Net.Compiler/Binding/PrototypeUnitRules.cs#ScreenUnitShape; src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4#programUnit, #nestedProgram, #endProgramHeader, #commonProgramAttribute

## Finding — `program-id-paragraph` (under-rejects; rows `SR-11.10.3-5`, `SR-11.10.3-6`)

**Mechanism.** SR5/SR6 containment exclusivity is never checked: MakeUnit tests INITIAL&&RECURSIVE only on the SAME PROGRAM-ID paragraph (COBOLNET0886) and never walks the container chain, and its own comment declares an INITIAL containee of a RECURSIVE container legal -- the opposite of §11.10.3 SR5

**Repro.** (a) `PROGRAM-ID. SR5OUT IS RECURSIVE.` directly (or via an intermediate program, sr5b.cob) containing `PROGRAM-ID. SR5IN IS INITIAL.`; (b) `PROGRAM-ID. SR6OUT IS INITIAL.` containing `PROGRAM-ID. SR6IN IS RECURSIVE.` -- the pinned cobol.exe --std 2023 (and 2002) compiles both clean and runs 'OUT / IN'. Sources: scratchpad adj-d2b/out/probe/program-id-paragraph/sr5.cob, sr5b.cob, sr6.cob.

**Expected from the spec.** §11.10.3 SR5: 'The INITIAL clause shall not be specified if any program that directly or indirectly contains this program is a recursive program.' SR6: 'The RECURSIVE clause shall not be specified if any program that directly or indirectly contains this program is an initial program.' Each probe is non-conforming source: a compile-time error at the offending clause, at every edition >= 2002. The check must walk ALL ancestors (directly or indirectly); for SR5 the ancestor test should read the effective recursive attribute (a program recursive by GR4 inheritance is still 'a recursive program'), which MakeUnit already computes parents-first.

**Observed / reasoning.** BinderDriver.MakeUnit: `if (initial && recursive) edition.Error("COBOLNET0886", ... (ISO §11.10.3 SR5-6))` is the only check; `parent` is consulted only for COMMON (SR4) and for GR4 inheritance. The comment above the inheritance line says 'The §11.10.3 SR5-6 exclusivity gate above sees only the WRITTEN clauses, so an INITIAL containee of a recursive container is legal and carries both attributes' -- a real clause answering a different question. The COBOLNET0886 case (INITIAL RECURSIVE in one paragraph) is excluded by the §11.10.2 Format 1 diagram (the inner braces carry no choice indicators), not by SR5/SR6, so its message citation is also wrong. Knock-on: ProgramTable.CallProgram's `n.Initial && n.Active == 0` guard and its PB133 comment exist to support the illegal INITIAL-under-RECURSIVE shape; golden conformance:2023/pb154_cancel_cascade (OUTER154 INITIAL containing INNERA154 RECURSIVE) pins an SR6-violating program as valid and must be reshaped in the same change set.

**Code site.** src/Cobol.Net.Compiler/Binding/BinderDriver.cs#MakeUnit (the COBOLNET0886 gate and the GR4 inheritance comment); src/Cobol.Net.Runtime/Control/ProgramTable.cs#CallProgram (Active==0 INITIAL guard comment); tests/conformance/2023/pb154_cancel_cascade.cob

## Finding — `program-id-paragraph` (under-rejects; rows `FMT-11.10.2`)

**Mechanism.** programIdAttribute+ accepts a non-ISO GLOBAL attribute and repeated attributes: commonProgramAttribute carries a GLOBAL alternative that MakeUnit silently ignores, and `programIdAttribute+` lets COMMON (or INITIAL/RECURSIVE) repeat, although §5.2.6.4 choice indicators allow each alternative at most once

**Repro.** `PROGRAM-ID. GLBX IS GLOBAL.` compiles and runs 'G'; a contained `PROGRAM-ID. DUPD IS COMMON COMMON.` compiles clean (rc 0) at --std 2023. Sources: probe/program-id-paragraph/glb.cob, dupc.cob.

**Expected from the spec.** §11.10.2 Format 1 admits only COMMON and {INITIAL|RECURSIVE} inside choice-indicator braces -- one or more, each at most once, any order (§5.2.6.4). GLOBAL is not a PROGRAM-ID attribute in any edition; both programs are syntax errors.

**Observed / reasoning.** CobolParserCore.g4 commonProgramAttribute: INITIAL_ | COMMON | RECURSIVE | GLOBAL; programIdAttributes: programIdAttribute+. MakeUnit's attribute loop has no GLOBAL arm and no duplicate check. Outside this worker's row set (FMT-11.10.2), reported so the register can file it.

**Code site.** src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4#commonProgramAttribute / #programIdAttributes; src/Cobol.Net.Compiler/Binding/BinderDriver.cs#MakeUnit
