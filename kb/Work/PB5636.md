# PB5636 - over-capacity VALUE literals draw two verdicts

**Sites:**
- `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs:1760` (`DataBinder.ValidateNumericValue`: its four COBOL1625 reporters, lines 1760, 1784, 1806 and 1819)
- `src/WiseOwl.Cobol.Frontend/Parsing/LiteralScreen.cs:145` (`LiteralScreen.ScreenDigitCapacity`)

**Mechanism.** kb/Work PB5529 (landed) asks the literal's digit capacity at the node, in the literal screen, so a VALUE,
level-88, CONSTANT or FD VALUE OF literal over capacity draws COBOL0801 (over 31) or COBOL0802 (over 18 at 85). The
binder then reads the same literal for the VALUE clause and, because it does not fit the item, also reports COBOL1625
(`ValueNumericOutOfRange`). One fault, two verdicts: the second is a cascade, unlike what kb/Work PB481 did for
refused clause operands ("one fault, one verdict").

**Repro.** From the PB5529 report: a 32-digit numeric literal in a VALUE clause at any edition, and a 19-digit literal in a
VALUE at `--std 85`; the report kept no probe path, so re-run both against the build of main first.

**Fix direction.** Record the literal the screen refused (the way `RefusedClauseOperands` records a refused operand) and
have the VALUE binder skip it, one verdict per literal; pin it with diagnostics JSONs counting exactly one error.
