# PB2131 — the census host is built by nothing but the census

Found by wave 1026 group C (PB2115; report `w1026c-PB2115-report.md`), filed by the train-1026 lander.

## Mechanism

`tools/ArchCensus/ArchCensus.csproj` is deliberately not in `Cobol.Net.sln` (it loads the solution through
MSBuildWorkspace and pins Roslyn 5.0.0). `scripts/build-local.ps1`, `scripts/linux-gate.sh` and CI all build the
solution, so none of them compiles the host. `ArchCensusDriftTests` (`tests/Cobol.Net.Tests.Unit/ArchCensusDriftTests.cs`)
runs `census.py --self-test` (the Python policy arms) and checks the newest record; it never builds the C# host. A
change to a Roslyn package version in `Directory.Packages.props`, or to a `src/` API the host names, can break the
host's compile with every gate green, and the next architecture-review wave finds it when `census.py` fails.
`tools/impact` has the same posture.

## Repro

Introduce a compile error in `tools/ArchCensus/Program.cs`; run `pwsh scripts/build-local.ps1 -Mode implementer`:
GREEN. Run `python scripts/arch/census.py`: fails building the host.

## What the fixer owes

One leg that builds every project under `tools/` that a script runs (`dotnet build tools/ArchCensus` and
`tools/impact`), in the guard leg (`scripts/guard-fast.sh`) or the build step, plus a drift test that every
`*.csproj` in the repository is either in the solution or named by that leg, so the next out-of-solution tool is
covered without an edit.
