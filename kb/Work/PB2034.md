# PB2034 — LANDED

Filed by the train-1020 lander from wave 1020 group E's report (`E:\COBOL-coord\scratch\reports\w1020e-PB2003-report.md`,
lead 1; first seen by wave 1019 G).

## Finding

**Mechanism.** `src/WiseOwl.Cobol.Editions/EditionDiagnostic.cs:23` — `EditionDiagnostic` has no source-location field
BY DESIGN (its remark: `WiseOwl.Cobol.Editions` sits below `WiseOwl.Cobol.Frontend` and cannot reference `SourceLocation`; "a
shared location type unifies in P4/P7"). A producer prints `file(line,col)` only when the sink it
reports to already carries a cursor. `VersionConformancePass` (every `_sink.Report` site of the pass: the COBOL-WORDS
SR3/SR4 checks, the reserved-word 0901, word-length 1567 and word-character 2773 diagnostics, the bound-arm statement
and data gates, the SORT / MERGE placement gates) was positioned by PB1925, so this note NO LONGER covers it
(re-probed on the PB1925 branch: a 41-character data name prints `(5,12): error COBOL1567`, `COMMIT` as a data name
prints `(6,12): error COBOL0901`; `undef_author.cob` prints `(line,col)`, pinned by
`BoundArmDiagnosticPositionTests.CobolWordsDirectiveCategoryViolation_NamesTheDirective`).

**Sites still bare** (each re-probed on the PB1925 branch with `--source-format free`):
- Report-section RD rules COBOL2713, 2714, 0899 (TYPE CH/CF), 2712, 2144, 2730 (DataBinder.Reports post-build
  resolvers); repro `conformance-suite/cases/13.18.12-CODE/pb1129-code-identifier-numeric.cob` (2713).
- External-file consistency COBOL1573, 1575, 1624 (`src/WiseOwl.Cobol.Compiler/Binding/BinderDriver.cs` near lines 366
  and 380, through `edition.Report`); repro `conformance-suite/cases/_unassigned/external-file-status-consistency-at-2023.cob`.
- OO / header rules COBOL2648, 1542, 1643; repro
  `conformance-suite/cases/14.2-Procedure-division-structure/pb1145-function-returning-is-a-formal.cob` (2648).
- COBOL0806 (`src/WiseOwl.Cobol.Compiler/Binding/OptionsBinder.cs:166`); repro
  `conformance-suite/cases/14.9.12-DIVIDE/l1-divide-arithmetic-standard-binary.cob`.

**Fix shape.** One shared location value carried on the Editions diagnostic (a location type both assemblies can see,
or a line/column pair the compiler-side adapter maps), filled at every producer, so the next producer is positioned
automatically; `DiagnosticPositionTests` then covers the codes. PB1925 (the bound-node arm, landed) is the sibling of the
same "conformance-pass diagnostic with no position" class. Too
large for wave 1020 E's slice: it touches every `EditionDiagnostic` producer.

## Landed (wave 20261780 group D)

**Re-probe.** A sweep of every refusal of `conformance-suite/wiseowl/diagnostics.json` (3089 entries, each compiled at its first refused edition with the group's own `cobol`, an error or warning line with no `(line,col)` prefix counted) found 54 bare lines on the PB2034 build: the note's four families (RD rules COBOL2713 / 2714 / 2712 / 2144 / 2730; external-file COBOL1573 / 1575 / 1624; COBOL2648 on a RETURNING item and COBOL1542 in a property method; COBOL0806) and, beside them, the same fault elsewhere: the CONTROL / TYPE CH-CF / RESET / SUM-addend / UPON rules of the same post-build report resolver (COBOL1699, 1700, 2670, 0899, 2045, 2046, 1639), COBOL1643, COBOL1507, COBOL1525 and the file-level COLLATING rules (COBOL1582). After the fix the same sweep finds none.

**The mechanism is not the type.** The note's fix shape (a `Location` on `EditionDiagnostic`, filled at every producer) would build a second position channel beside the one kb/Work PB82 built and every other diagnostic uses: the sink's CURSOR, set by a walker (`edition.At(context)`), which `Error` / `Warning` / `Report` stamp as `file(line,col): ` automatically. `EditionDiagnostic` stays location-free by design (the Editions assembly sits below the frontend's `SourceLocation`). A diagnostic printed bare because its PRODUCER ran outside every walker: a group-level pass (`CheckExternalFileConsistency`, `CheckFunctionUnits`) or a post-build resolver (`ResolveReports`, the CODE clause, the RETURNING item, the method ANY LENGTH sweep) that never set the cursor. The fix positions each producer where it knows the clause or entry: `FileModel.ClauseOrEntryAt` (the clause's own cursor, else the file control entry's; the three inline copies of that expression now call it), `ReportModel.At` and `ReportClauseName.At` (new), the printable item's and the SUM addend's own contexts, `BinderDriver.NameCtx` (now class level, for CheckFunctionUnits).

**The net that keeps it true.** `ConformanceSuiteTestsBase.WiseOwlRefusal_RefusesTheSourceWithItsDiagnostic` now also calls `EditionHarness.AssertEveryDiagnosticPositioned` on every error and warning of every refusal at every edition it names (8981 rows, all green): the next producer that forgets its position fails at the first negative that exercises it, which a hand-kept list of sites could not do.
