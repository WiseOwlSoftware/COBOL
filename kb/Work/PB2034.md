# PB2034 — OPEN

Filed by the train-1020 lander from wave 1020 group E's report (`E:\COBOL-coord\scratch\reports\w1020e-PB2003-report.md`,
lead 1; first seen by wave 1019 G).

## Finding

**Mechanism.** `src/Cobol.Net.Editions/EditionDiagnostic.cs:23` — `EditionDiagnostic` has no source-location field
BY DESIGN (its remark: `Cobol.Net.Editions` sits below `Cobol.Net.Frontend` and cannot reference `SourceLocation`; "a
shared location type unifies in P4/P7"). Every diagnostic `VersionConformancePass` raises through it therefore prints as
`error COBOLNET1623: …` with no file, line or column.

**Sites.** `src/Cobol.Net.Compiler/Validation/VersionConformancePass.cs#ReportCobolWordsInvalid` (the COBOL-WORDS SR3/SR4
checks, ~line 154) and the reserved-word and word-length diagnostics of the same pass. `CobolWordsOp.Line` already
carries the directive's line for the COBOL-WORDS arm, so the position exists and is dropped.

**Repro.** `E:\COBOL-coord\scratch\w1019g\p\undef_author.cob` (`>>COBOL-WORDS UNDEFINE "AUTHOR"`, then a minimal
program): the diagnostic prints with no position (the reporter measured rc 70).

**Fix shape.** One shared location value carried on the Editions diagnostic (a location type both assemblies can see,
or a line/column pair the compiler-side adapter maps), filled at every producer, so the next producer is positioned
automatically; `DiagnosticPositionTests` then covers the codes. PB1925 (SORT/MERGE placement diagnostics from bound
nodes) is a sibling of the same "conformance-pass diagnostic with no position" class and should land with it. Too
large for wave 1020 E's slice: it touches every `EditionDiagnostic` producer.
