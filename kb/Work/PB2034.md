## Finding

**Mechanism.** `src/Cobol.Net.Editions/EditionDiagnostic.cs:23` — `EditionDiagnostic` has no source-location field
BY DESIGN (its remark: `Cobol.Net.Editions` sits below `Cobol.Net.Frontend` and cannot reference `SourceLocation`; "a
shared location type unifies in P4/P7"). A producer prints `file(line,col)` only when the sink it
reports to already carries a cursor. `VersionConformancePass` (every `_sink.Report` site of the pass: the COBOL-WORDS
SR3/SR4 checks, the reserved-word 0901, word-length 1567 and word-character 2773 diagnostics, the bound-arm statement
and data gates, the SORT / MERGE placement gates) was positioned by PB1925, so this note NO LONGER covers it
(re-probed on the PB1925 branch: a 41-character data name prints `(5,12): error COBOL1567`, `COMMIT` as a data name
prints `(6,12): error COBOL0901`; `undef_author.cob` prints `(line,col)`, pinned by
`BoundArmDiagnosticPositionTests.CobolWordsDirectiveCategoryViolation_NamesTheDirective`).

**Sites still bare** (each re-probed on the PB1925 branch with `--source-format free`):
- Report-section RD rules COBOL2713, 2714, 0899 (TYPE CH/CF), 2712, 2144, 2730 (DataBinder.Reports post-build
  resolvers); repro `conformance-suite/cases/13.18.12-CODE/pb1129-code-identifier-numeric.cob` (2713).
- External-file consistency COBOL1573, 1575, 1624 (`src/Cobol.Net.Compiler/Binding/BinderDriver.cs` near lines 366
  and 380, through `edition.Report`); repro `conformance-suite/cases/_unassigned/external-file-status-consistency-at-2023.cob`.
- OO / header rules COBOL2648, 1542, 1643; repro
  `conformance-suite/cases/14.2-Procedure-division-structure/pb1145-function-returning-is-a-formal.cob` (2648).
- COBOL0806 (`src/Cobol.Net.Compiler/Binding/OptionsBinder.cs:166`); repro
  `conformance-suite/cases/14.9.12-DIVIDE/l1-divide-arithmetic-standard-binary.cob`.

**Fix shape.** One shared location value carried on the Editions diagnostic (a location type both assemblies can see,
or a line/column pair the compiler-side adapter maps), filled at every producer, so the next producer is positioned
automatically; `DiagnosticPositionTests` then covers the codes. PB1925 (the bound-node arm, landed) is the sibling of the
same "conformance-pass diagnostic with no position" class. Too
large for wave 1020 E's slice: it touches every `EditionDiagnostic` producer.
