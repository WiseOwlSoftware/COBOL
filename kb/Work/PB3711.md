# PB3711 — the turns measurement silently excludes successor reports

**Sites:** `scripts/orchestrator/turns_by_group_size.py` (`REPORT_NAME`, the report scan and its "left out" tally; now plan_wave.py's `REPORT_NAME`, imported; `TURNS`, `self_test`), `scripts/orchestrator/model_rules.json` (`max_notes_per_group_source`, which quotes the tally as complete).

## What happens

`REPORT_NAME` requires the letter to be followed by `-`, so a same-file successor's report (`w<wave><letter><n>-...`, for example
`w1021b2-PB1042-report.md`) fails the match and a bare `continue` drops it, counted in no "left out" bucket. The docstring says every
report left out is counted, and `max_notes_per_group_source` quotes the tally. On the live reports directory 702 reports match and
288 + 380 + 29 + 5 = 702 are accounted for, while 38 successor reports (`ls | grep -E '^w[0-9]+[a-z]+[0-9]+-'`) are excluded without trace.
The measurement that PB3641 exists to make honest therefore under-reports its population.

## Fix

Match `^w(\d+)([a-z]+\d*)-` and join to `msg-w<wave>-<letter><n>.txt`, or count the non-matching reports as their own left-out bucket.
Re-measure the per-note fit once the successors are in (PB3704 uses the number). Sweep other parsers of the report name
(`plan_wave.py`, `prune_worktrees.py`) for the same pattern.

## Landed (2026-10-25, wave 20261107 group A)

Re-probed on the live reports directory: 771 `w*-report.md` files, 702 matched the old pattern and 69 were excluded or
miscounted. Root cause: `turns_by_group_size.py` kept its own `REPORT_NAME`, a second copy of the fix-lane report name that
`plan_wave.REPORT_NAME` already owns with the successor digit (`[a-z0-9]*`). It now imports `plan_wave.REPORT_NAME` (one
rule, one place) and joins `w<wave><letter><n>-...` to `msg-w<wave>-<letter><n>.txt`, the name `make_dispatch_specs.py` writes
for a successor. A `w*-report.md` that is no group report (a train, refute or filing report; 32 today) is now counted as
"not a group report" instead of dropped, so the tally is complete: 322 joined + 32 + 375 + 37 + 5 = 771. Sweep:
`plan_wave.py` and `prune_worktrees.py` already read the successor form (`plan_wave.REPORT_NAME` is theirs); no other parser
of the report name exists. A sibling silent undercount in the same function was fixed too: `TURNS` read only `~N` and
`Turns used: about N`, so the `**turns:** about N` (15 reports) and the unbolded `turns ~N` headers fell into "no turns
figure"; both forms are read now. The self-test covers the successor, the non-group report and each header form.
