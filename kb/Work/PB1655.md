# PB1655 — LANDED 2026-09-29

Filed 2026-09-27 by the train-66 lander from the wave-66 L implementer report (PB1380). Independent of PB1380's root.

**Observed.** `MOVE ALL "*" TO T(7:3)` over `T PIC X(9) VALUE "---------"` leaves `------*  ` where `------***` is
required. A group slice and a RENAMES-alias slice do the same.

**Repro.** `E:\Temp\claude\E--COBOL\eb162d4b-e0bb-4027-b8a0-86fd190d20be\scratchpad\w66l\lead-all-literal-refmod.cob`
(copy it into the tests tree when fixing; the scratchpad is not durable).

**Rule.** §8.3.3.6.4 2): "the string of characters is repeated character by character until the size of the
resultant string is greater than or equal to the number of character positions in the associated data item"
(`cite.py --check 8.3.3.6.4` OK 2)). A reference-modified identifier is a data item: §8.4.3.3.4 GR5.

**Code site.** `src/Cobol.Net.Compiler/CodeGen/Verbs/MoveEmitter.cs:92`: a `BoundAllLiteral` source falls through to
`OperandText.AsString`; only `BoundFigurative` reaches `PlaceRenderer.WriteFill`. When the slice length is known only
at run time, the repetition must happen at run time.

**Sweep.** Check every other statement that can store an ALL literal into a `RefModPlace` (INITIALIZE, SET,
STRING INTO, VALUE-free INITIALIZE REPLACING) for the same fault.

## Landing 2026-09-29 (wave 73, group C)

**For the next implementer.**
- `src/Cobol.Net.Compiler/CodeGen/Roslyn/PlaceRenderer.cs#WriteFill` — takes a figurative SEED (C# string expr), emits `CobolString.SpliceInto(..., repeat: true)`; the ONE ref-mod fill.
- `src/Cobol.Net.Compiler/CodeGen/Verbs/MoveEmitter.cs#EmitStore` (RefModSlice arm) — BoundFigurative → FillText seed, BoundAllLiteral → CsLiteral(literal) seed.
- `src/Cobol.Net.Runtime/Values/Text/CobolString.cs#SpliceInto` — `repeat:` applies FigToWidth's GR2 in place; the unit test asserts the two agree.


**Root.** `MoveEmitter.EmitStore`'s `RefModSlice` arm sent a figurative WORD to the fill store and everything else,
`ALL literal-1` included, to the plain splice — which left-justifies the sender once and space-fills the rest.
§8.3.3.6.4 GR2 (`cite.py --check` OK 2): the figurative's characters are "repeated character by character until the
size of the resultant string is greater than or equal to the number of character positions in the associated data
item", and §8.4.3.3.4 GR5 makes the reference-modified identifier that data item — a length known only at run time.

**Fix.** ONE fill store for both figurative forms: `PlaceRenderer.WriteFill(RefModPlace, seed)` takes a SEED (one
fill character for a figurative word — `FigurativeConstants.FillText`, category-aware as before — or the ALL
literal's literal-1) and emits `CobolString.SpliceInto(…, repeat: true)`, which repeats the seed over every
position of the slice at run time. The pad-only fill it replaced is gone (no second fill path). `FigToWidth` and the
in-place repetition give the same answer, and the unit test asserts it.

**Sweep.** Every other store of an ALL literal into a `RefModPlace`: INITIALIZE `REPLACING … BY ALL "Q"` into
`T(3:4)` already repeats (probe `I1=[--QQQQ---]`, its own replacement path); STRING INTO a reference-modified
identifier-3 is illegal (§14.9.43.3 SR4); UNSTRING receivers store through the bound MOVE from the conceptual item
(no ALL literal); a relation sizes the ALL literal at run time (`CompareFig`, PB297); SET condition-name TO TRUE and
VALUE have no reference-modified target. Only the MOVE arm was wrong.

**Witnesses.** `conformance:85/pb1655_all_literal_refmod_receiver` (fixed slice, variable leftmost, the omitted-length
form, a group slice, a RENAMES-alias slice and a numeric-DISPLAY slice);
`unit:CobolStringPadTests.SpliceInto_Repeat_FillsTheSliceWithTheFigurativeSeed`. No negative: reference
modification and ALL literal-1 are both COBOL-85, so there is no edition below the rule.
