# PB4063 — branch-carried landing_check stops share exit 3 with the in-flight-overlap wait

**Sites:** `scripts/orchestrator/landing_check.py#check`, `scripts/orchestrator/enqueue.py#Check`, `scripts/orchestrator/land_lane.py#wait_free`, `scripts/orchestrator/land_lane.py#landing_check_free`

(Arm 0b is on PR #775's branch `worktree-wf_484eb705-564-19` and reaches main when PB3791 lands; arm 0 is on main.)

## One mechanism

`landing_check.check` returns STOP reasons and `enqueue.py` maps them to exit 3 (`land_lane.EXIT_CHECK_STOP`, whose comment
says "the branch shares a file with in-flight work"). The lane lists exit 3 in `land_lane.WAITS` as a retry-when-free exit:
`wait_free` calls `landing_check_free`, which re-runs the check and retries the landing once the in-flight overlap is gone.
That reading is right for the overlap stops, which clear when the other work lands. Two arms of the same check stop on a
fact the BRANCH carries, which never clears at that head:

- **arm 0**: the range carries a path no landing carries (`coord.NEVER_WORK`: the harness's per-machine settings, the
  checkpoint file, the gate's results);
- **arm 0b** (PB3694, PR #775): the public-API baseline lists a symbol twice (RS0025 fails the Release build).

Each stop's text tells a person what to do (restore the path, drop the duplicate), but the lane waits on it as if it were
overlap, and no BLOCKED report line sends the branch to a finisher, so the branch sits until a person reads the stop.
Failure scenario: a clerk or implementer commits `.claude/settings.local.json`; the landing exits 3 with arm 0's text; the
lane retries at the same head, finds the same stop, and reports "still waits on the in-flight work it shares a file with",
which names the wrong cause. The PB3791 report names arm 0 and arm 0b as one root.

## Fix shape

A stop that the branch carries gets its own exit code, threaded through `enqueue.py`'s `Check` table, `land_lane.EXIT_*` and
`WAITS` (it is not a wait; the lane writes the BLOCKED report line that routes the branch to a finisher), with the check
returning stops tagged by kind (overlap vs branch-carried) instead of one flat list, so the next arm declares its kind where
it is written. Test arms, each seen RED first: an arm-0 leak and an arm-0b duplicate each end with the branch-carried exit and
a BLOCKED line, an in-flight overlap still exits 3 and waits.
