# PB5191 - at --std 85 BLANK WHEN ZERO on PIC S9(4) is refused (COBOL1934): PictureComposition.Validate applies the 2023 bar on the symbol S, which 1985 does not have

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/PictureComposition.cs` (`Validate`)
- `src/WiseOwl.Cobol.Compiler/Binding/PictureAnalyzer.cs` (`AnalyzeCharacterString`, the numeric-edited promotion: landed)
- `src/WiseOwl.Cobol.Compiler/Binding/Passes/CheckClauseSubjectsPass.cs` (`Run`) and `src/WiseOwl.Cobol.Compiler/Binding/ReportSectionBinder.cs` (`BindReportEntry`): a recovery PICTURE profile no longer draws COBOL2405 (landed)

**Mechanism.** §1985:VI.5.4.3 SR1 allows BLANK WHEN ZERO on an elementary item whose PICTURE is numeric or numeric edited; 1985 bars only the asterisk with it, and a PICTURE of S and 9 is numeric. `PictureComposition.Validate` applies the 2023 rule (neither S nor * beside BLANK WHEN ZERO) with no edition test, so `PIC S9(4) BLANK WHEN ZERO` is refused at --std 85 (COBOL1934, then COBOL2405), a legal program rejected.

**Rules (1; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-SR-VI.5.4.3-1` - `§1985:VI.5.4.3 SR1` (record verdict: PARTIAL, harm: rejects-legal-source). Checked: §1985:VI.5.4.3 SR1: "The BLANK WHEN ZERO clause can be specified only for an elementary item whose PICTURE is specified as numeric or numeric edited". Code sites read: src/WiseOwl.Cobol.Compiler/Binding/Passes/CheckClauseSubjectsPass.cs#Run; src/WiseOwl.Cobol.Compiler/Binding/DataBinder.ClausePlacement.cs#BlankWhenZeroViolation; src/WiseOwl.Cobol.Compiler/Binding/Passes/CheckPictureRequiredPass.cs#CheckElementaryOnlyClauses; src/WiseOwl.Cobol.Compiler/Binding/PictureComposition.cs#Validate. Code read: No kb/Work note owns the fix. §1985:VI.5.4.3 SR1: "The BLANK WHEN ZERO clause can be specified only for an elementary item whose PICTURE is specified as numeric or numeric edited". The restriction is implemented at 85: CheckElementaryOnlyClauses refuses the clause on a group entry (COBOL2403) and CheckClauseSubjectsPass.Run refuses it, through BlankWhenZeroViolation, on an elementary item whose category is not numeric or numeric edited (COBOL2405); the level 66 and 88 formats take no such clause. Not implemented for 85: the numeric PICTURE that carries the symbol S. PictureComposition.Validate applies the 2023 rule (§2023:13.18.40.3 SR22, "Neither the symbol 'S' nor the symbol '*' shall be specified") with no edition test, so PIC S9(4) BLANK WHEN ZERO draws COBOL1934 at 85. The 1985 text bars the asterisk only (§1985:VI.5.9.3 SR7) and has no rule on S; a PICTURE of S and 9 is numeric, and §1985:VI.5.4.4 GR2 says what the clause does to it. The refusal is the 2002 change §2002:F.1 item 33: "The previous COBOL standard did not specify whether BLANK WHEN ZERO for a numeric item with a picture character-string including an 'S' was syntactically valid" and "The implementor will now provide a syntax error for such an occurrence". Probed at --std 85: accepted and blanked at zero are PIC 9(4), ZZZ9, 9(3)V99, -9(3).99, $$$9.99CR and 99PP; refused are PIC X(3), A(3), XBX, X(2)/X, 9X, A9, a group entry and a USAGE INDEX item; refused and legal are PIC S9(4) and PIC S9(3) SIGN IS LEADING SEPARATE. The witness is PIC X(3) BLANK WHEN ZERO, refused with COBOL2405.

**Expected (from the 1985 text, the record's).** The program compiles at --std 85 and displays [    ]: §1985:VI.5.4.3 SR1 admits the clause for "an elementary item whose PICTURE is specified as numeric or numeric edited", S9(4) is a numeric PICTURE, no 1985 rule bars the symbol S beside the clause (§1985:VI.5.9.3 SR7 bars the asterisk alone), and §1985:VI.5.4.4 GR1: "When the BLANK WHEN ZERO clause is used, the item will contain nothing but spaces if the value of the item is zero." §1985:I.1.6: "A conforming source program is one which does not violate the explicitly stated provisions and specifications of Standard COBOL." The syntax error is new in 2002 (§2002:F.1 item 33, a change "potentially affecting existing programs").

**Observed (the record's).** exit 65, no object program: BWZS.cob(5,8): error COBOL1934: invalid PICTURE S9(4) (expanded: S9999) — data item 'N2': the symbol 'S' is specified beside a BLANK WHEN ZERO clause — neither 'S' nor '*' may be (ISO §2023:13.18.40.3 SR22), followed by COBOL2405 on the same entry ("this item is of category alphanumeric", the recovery's category). --permissive gives the same two errors.

**Fix direction (root cause, CLAUDE.md rule 4).** Read the edition in Validate's BLANK WHEN ZERO arm: at 85 the symbol S is allowed and the asterisk is not.
