# PB3913 — justified-right-on-usage-bit--boolean-data-numeric-wrong-output: -std=cobol2014: boolean literal B"10100" and PIC 1 items hold binary-number values (MOVE to PIC X gives "00020"); same root as S8 boolean-held-as-number

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S6) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\justified-right-on-usage-bit--boolean-data-numeric-wrong-output.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\justified-right-on-usage-bit--boolean-data-numeric-wrong-output\`.

## Summary

Under `-std=cobol2014` GnuCOBOL 3.2 builds a boolean literal `B"..."` as a numeric literal whose value is the binary
number the digits spell, and gives a `PIC 1` item the numeric category. A boolean item with `VALUE B"10100"` therefore
holds the decimal digits `00020`, and moving it (or the literal `B"011"`) to an alphanumeric item stores `00020` and
`3`, where the standard moves the boolean characters `10100` and `011`. Class: wrong output. Found while reducing the
family `justified-right-on-usage-bit` (the same picture miscategorisation causes that refusal), and split from it.

## Minimal test case

Free reference format (`-fformat=free`), 12 lines, written for this record.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. BOOLMV.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 B5 PIC 1(5) VALUE B"10100".
01 X5 PIC X(5).
PROCEDURE DIVISION.
MOVE B5 TO X5
DISPLAY "[" X5 "]"
MOVE B"011" TO X5
DISPLAY "[" X5 "]"
STOP RUN.
```

## Observed result

`boolmv`: compile exit 0 (no diagnostic), run exit 0:

```
[00020]
[3    ]
```

`blit` (compile exit 0, run exit 0): `DISPLAY B"101"` prints `5`; `MOVE B"101"` to `PIC 1(3)` then DISPLAY prints `005`;
a `PIC 1(5) VALUE B"10100"` item displays `00020`; moving it to `PIC 1(3)` displays `020`.

## Expected result (per ISO)

The program prints `[10100]` and `[011  ]`.

- §8.3.3.4.1 (checked): "Boolean literals are of the class and category boolean." §8.3.3.4.3 2) (checked):
  "Boolean-character-1 shall be a boolean character, '0' or '1', from the computer's coded character set."
- §13.18.40.4 8) (checked): "To define an item as boolean, character-string-1 shall contain only one or more
  occurrences of the symbol '1'." §13.18.40.4 14) (checked): "Each symbol '1' represents a boolean position that shall
  contain a boolean character." §8.5.2.5 1) (checked): such an item is of category boolean. B5 therefore holds the five
  boolean characters 1 0 1 0 0.
- §14.9.25.4 6) a) (checked): when an alphanumeric item is the receiving operand, alignment is per 14.6.8, and "If the
  sending item is of class boolean, its boolean value shall be moved." The boolean value of B5 is 10100, of the
  literal 011; X5 is aligned left with space fill (14.6.8.5).

A boolean item or literal has no numeric value in a MOVE: §14.9.25.3 10) (checked) and Table 16, "Validity of types of
MOVE statements", mark Boolean to Numeric as "No" and Boolean to Alphanumeric as "Yes"; the standard converts between
boolean and integer values through the functions INTEGER-OF-BOOLEAN and BOOLEAN-OF-INTEGER.

Edition: 2014. The 2009 committee draft that became ISO/IEC 1989:2014 (CD 1.2) has "Boolean literals are of the class
and category boolean", the PICTURE rule 8 for '1', and the MOVE rule "If the sending item is of class boolean, its
boolean value shall be moved." Boolean literals and items are 2002 features.

Edition as recorded by the adjudicator: 2014 (introduced 2002). `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Fix site (GnuCOBOL 3.2 source, read observationally)

- `cobc/scanner.l`, `scan_b`: converts the digits of `B"..."` to an unsigned binary value and returns
  `cb_build_numeric_literal` of its decimal text (the source carries "FIXME: we should likely build a boolean literal");
  `config/cobol2014.conf` sets `numeric-boolean: ok`, so this treatment applies under `-std=cobol2014`.
- `cobc/tree.c`, `cb_build_picture`: the symbol '1' adds `PIC_NUMERIC` ("FIXME: this is WRONG"), so a `PIC 1` item is
  a numeric item of that many digits.
- A fix needs a boolean literal tree node and a boolean category for `PIC 1`, then MOVE, VALUE and DISPLAY handling
  for them; the family records `justified-right-on-usage-bit` and `evaluate-boolean-subject-when-true` show other
  effects of the same gap.
