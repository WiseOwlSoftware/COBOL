# PB6022 - a relabelled row leaves its read record naming an id no rule has

**Sites:** `scripts/spec/audit_batch.py#import_reads` (the refusal "read rule(s) of <record> are no rule of the 1985
catalog"), `scripts/spec/lineage_reads.py#load` / `#normal_slice` (the reads are keyed by row id, verbatim, digested),
and the relabel move of group j (`d85ad0e0fc`: record_verdicts MOVE batch for the store, nothing for the read records).

**Repro (branch train85b-reads at 0341db4e62):** `python scripts/spec/audit_batch.py import-reads --edition 1985 --reads
<any reads> --asked <in> --record tests/version-matrix/lineage-reads-1985 --state <empty dir>`:

    audit_batch: 3 read rule(s) of tests\version-matrix\lineage-reads-1985 are no rule of the 1985 catalog:
    ['1985-GR-XIII.3.10.7-p5', '1985-GR-XIII.3.10.9-p5', '1985-GR-XIV.2.2.6-T1']

(`import_records` has already written the new slices when the refusal fires.) `lineage_reads.py --check 1985` is GREEN
on the same tree, so the gate does not see that two of the reads now hang on ids no row has and that the reads of the
renamed rows `-p3`/`-p4`/`-T2` are read under the OLD ids (the old p4's read decides what is now p3, the old p5's what is
now p4).

**Why.** A row id is the read's key; group e's segmentation relabelled five rows (PB6001), group j moved their STORE
records with a MOVE batch, and the read records (verbatim, digested) cannot be moved the same way.

**Worked around in group o, not fixed:** the 85w import ran with `--record` a scratch copy holding only its own 8 slices
(byte-identical to the tracked ones it wrote), so the state's decisions are the new rows' only.

**Fix (owed):** the relabel is ONE mechanism for every keyed record of a row: a relabel map the catalog extraction
writes (old id -> new id, by unit key and digest), read by `lineage_reads.load` (and every other reader keyed by row id),
so a relabelled read is read under its new id; `lineage_reads --check` refuses a read record naming an id no rule has
and no relabel maps. Self-test: a read of a relabelled id, mapped and unmapped.
