# PB1212 — OPEN

## Measured

**based-clause** — The §13.18.5.3 SR1 class-object screen runs over the WRITTEN-entry ConformanceForest, which prunes TYPE-clone subtrees, so a BASED entry that acquires class object through TYPE is never screened

- **Repro:** WORKING-STORAGE: `01 T USAGE OBJECT REFERENCE TYPEDEF.` `01 O TYPE T BASED.` PROCEDURE: `ALLOCATE O. IF O = NULL DISPLAY "O NULL" END-IF.` -> compiles clean and runs (probe sr1f.cob).
- **Expected (spec):** Rejected: §13.16.3 SR14 permits BASED with TYPE, §13.18.57.4 GR1 makes O's description that of T (class object), so §13.18.5.3 SR1 'The subject of the entry shall not be of class object.' is violated - COBOLNET1797 at O, as the direct spelling `01 O USAGE OBJECT REFERENCE BASED.` already gets.
- **Observed:** DataBinder.UsageDeclaration.cs CheckUsageDeclarations iterates ConformanceForest() = DeclaredForest().Where(TypeAnchor(item) is null); O is a TYPE clone root, so the `item.IsBased && item.Pic is {Category: ObjectReference}` test never sees it. SR1 is a composed-entry rule (BASED from the site, class from the template) - the documented CompositionForest case. Sweep: every other composed-entry screen in CheckUsageDeclarations (e.g. §13.18.22.3 SR4 EXTERNAL + TYPE of a pointer/object typedef) has the same exposure.
- **Code site:** src/Cobol.Net.Compiler/Binding/DataBinder.UsageDeclaration.cs#CheckUsageDeclarations (SR1 arm ~L147-160); DataBinder.cs#ConformanceForest
- **Clause (adjudicator):** §13.18.5.3 SR1; §13.18.57.4 GR1; §13.16.3 SR14

**external-clause** — §13.18.22.3 SR4 is screened only on the entry's OWN USAGE: the check (item.HasExternalClause && SlotWindow.CarriedBySlot(item)) runs in the USAGE-declaration pass before a TYPE clause's description is known, so an elementary item that is class pointer/object BY ITS TYPE CLAUSE and carries the EXTERNAL clause escapes

- **Repro:** WS: `01 PT USAGE POINTER TYPEDEF.` `01 A TYPE PT EXTERNAL.` (probe SR4TY, 2023; same at 2002) - compiles and runs clean. Control: `01 A USAGE POINTER EXTERNAL.` -> COBOLNET1796.
- **Expected (spec):** §13.18.22.3 SR4: "The EXTERNAL clause shall not be specified for a data item of class object or pointer." A is an elementary data item of class pointer (its description is PT's, §13.18.57) with the EXTERNAL clause specified -> COBOLNET1796.
- **Observed:** No diagnostic; the program runs. The same TYPE-derived shape for OBJECT REFERENCE is the sibling to sweep. kb/Work PB1043 claims this row for the separate FD-record question; this mechanism is distinct.
- **Code site:** src/Cobol.Net.Compiler/Binding/DataBinder.UsageDeclaration.cs (§13.18.22.3 SR4 block); src/Cobol.Net.Compiler/Binding/DataBinder.cs#ExpandType (where the TYPE's class becomes known)
- **Clause (adjudicator):** §13.18.22.3 SR4

**external-clause** — §13.18.22.3 SR5's check keys on item.HasExternalClause (the record's own clause), so a record that is an external item WITHOUT carrying the clause - the record of an EXTERNAL FD, exactly the case the rule's NOTE names - is never checked

- **Repro:** `FD F IS EXTERNAL.` `01 R TYPE ST.` with WS `01 ST TYPEDEF STRONG. 05 A PIC X(3).` (probe SR5FD, 2023) - compiles and runs clean. Control: `01 W TYPE ST EXTERNAL.` in WS -> COBOLNET1558.
- **Expected (spec):** §13.18.22.3 SR5: "When a record description is an external item, any associated type declaration that is strongly typed shall also be external." NOTE: "This covers the situation where a file is declared as external and the associated record descriptions have TYPE clauses." R is external by §13.18.22.4 GR4 b) -> COBOLNET1558.
- **Observed:** No diagnostic. The predicate should be 'the record is an external item' (own clause, FD EXTERNAL, or external type), one predicate shared with the other external-item consumers.
- **Code site:** src/Cobol.Net.Compiler/Binding/DataBinder.cs#ExpandType (`if (item.HasExternalClause && template.TypedefStrong && !template.IsExternalTypedef)`)
- **Clause (adjudicator):** §13.18.22.3 SR5 + NOTE; §13.18.22.4 GR4 b)
