## Finding — source-format-directive (wrong-answer)

Compiler-directive line recognition admits only DIGITS in the fixed-form sequence area

**Rows:** GR-7.3.24.3-1, GR-7.3.24.3-4

**Repro:**

```
out/probe/source-format-directive/p12.cob: seven fixed lines numbered 000001-000007 (IDENTIFICATION ... `DISPLAY "FIXED-PART".`), then `SEQ008 >>SOURCE FORMAT FREE`, then free `DISPLAY "FREE-PART".` and `STOP RUN.`; and p6d.cob: first line `SEQ001 >>SOURCE FORMAT FREE` followed by a free program. `cobol pN.cob --run`.
```

**Expected from the spec:** §6.3.2: the sequence area 'may consist of any character in the computer's coded character set', so `SEQ008 >>SOURCE FORMAT FREE` is a fixed-form SOURCE FORMAT directive; §7.3.24.3 GR1 makes the following text free form, and GR4 lets the first line be in fixed form. p12 prints FIXED-PART then FREE-PART; p6d prints P6D-OK.

**Observed:** p12 prints only FIXED-PART, exit 0, no diagnostic: the directive goes unrecognized, and the free lines are read as fixed, silently losing the DISPLAY. p6d fails 'unexpected SEQ001'. CompilerDirectiveLine.TryParse (line 55) skips a leading run of `' ' | '\t' | (allowSequenceArea && char.IsAsciiDigit)` only. Sibling sweep owed: every allowSequenceArea caller (DirectiveStackOp.TryParse for >>PUSH/>>POP, ReferenceFormatProcessor.TryMatchStackOp) shares the same restriction.

**Code site:** src/Cobol.Net.Editions/CompilerDirectiveLine.cs#TryParse (line 55); src/Cobol.Net.Frontend/Preprocessor/ReferenceFormatProcessor.cs#TryMatchDirective

## Row SR-7.3.3-2 — PARTIAL (adjudicator + refuter record)

§7.3.3 SR2 'A compiler directive shall be preceded only by zero, one, or more space characters.' (cite.py --check 7.3.3 OK). TryParse accepts only spaces (and tab, the implementor's tab treatment) before '>>' (digits too only in the allowSequenceArea mode used by the fixed-form pre-normalization scan, where columns 1-6 are the sequence area, not program text). Probes: S2A 'DISPLAY "S2A". >>TURN EC-ALL CHECKING OFF' and S2B '... >>DEFINE VV AS 1' are rejected (COBOL0001 at the '>'). The rejection is a generic parse error, not a named diagnostic. No spec-derived test targets this rule specifically. || REFUTED: PARTIAL — The pre-normalization >>SOURCE / >>PUSH / >>POP scan (ReferenceFormatProcessor.TryMatchDirective / TryMatchStackOp -> CompilerDirectiveLine.TryParse(allowSequenceArea:true)) models the fixed-form sequence area as 'any run of digits or spaces anywhere before >>'. That is wrong both ways: (a) it ACCEPTS a directive preceded by non-space program text - '       12 >>SOURCE FORMAT FREE' (digits in the program-text area, fixed form) and '000100 >>SOURCE FORMAT FIXED' written in a FREE-form segment both switch the format, violating SR2; (b) it MISSES a legal fixed-form directive whose sequence area is non-numeric (§6.3.2: the sequence number area 'may consist of any character in the computer's coded character set'): 'ABCDEF >>SOURCE FORMAT FREE' after an explicit >>SOURCE FORMAT FIXED is not recognized, the following lines are read in the wrong reference format, and the program compiles and silently prints nothing. The post-normalization stages (DEFINE/IF) get SR2 right (X7, Y5). Half verified, half defective => PARTIAL.

**Code location:** src/Cobol.Net.Editions/CompilerDirectiveLine.cs#CompilerDirectiveLine.TryParse

## What the fixer owes (and the sibling sweep)

Recognize a directive by REFERENCE FORMAT, not by a character class: in fixed form the sequence area is columns 1-6 whatever they hold and the directive must start in the program-text area preceded only by spaces; in free form nothing but spaces may precede `>>`. One recognizer for the pre-normalization scan and the post-normalization stages (today they disagree). Goldens: alphabetic sequence area; digits in the program-text area rejected.

**Rows claimed:** SR-7.3.3-2, GR-7.3.24.3-1, GR-7.3.24.3-4

### Finding — `reference-format` (rejects-legal-source; rows `GR-6.1-1`, `GR-6.1-2`)

**Mechanism.** With no SOURCE FORMAT directive the reference format is chosen by a structural heuristic (IsFixedForm) rather than the standard's fixed-form default, and the heuristic calls conforming fixed-form source FREE when the sequence area holds non-digits (§6.3.2 allows any character) or when it is blank, no indicator glyph appears and columns 73+ hold text

**Repro.** E:\Temp\claude\E--CobolSharp\a700c052-f9e4-4942-84ff-a13c7505d6ec\scratchpad\adj-d2b\out\probe\reference-format\rf7.cob: every line `ABC00n` + space + text -> COBOL0001 unexpected 'ABC000'. rf8.cob: blank sequence area, text from col 8, tag 'RF8nnnnn' in cols 73-80 -> COBOL0001 near 'RF800000'.

**Expected from the spec.** §7.3.24.3 2) and §6.1 intro: 'The default reference format of a compilation group is fixed form'; §6.3.2 sequence area content is any character; §6.3.1 text past margin R is not program text. Both programs compile and display [OK7] / [OK8].

**Observed / reasoning.** IsFixedForm requires cols 1-6 digits-or-space (seqOk) and, absent a numeric sequence, a non-space indicator glyph with nothing past col 72. DOC-A.1-158 documents auto-detection as an 'implementor extension', but an extension cannot make a program the standard's default governs fail to compile. The fix is structural (the default must be fixed-form, with auto-detection at most a fallback that cannot override it for conforming fixed-form source) — an owner-visible choice because the NIST/free-form corpus relies on the heuristic.

**Code site.** src/Cobol.Net.Frontend/Preprocessor/ReferenceFormatProcessor.cs#IsFixedForm; src/Cobol.Net.Frontend/Preprocessor/ReferenceFormatProcessor.cs#NormalizeToFreeFormMapped (switches.Count == 0 arm and initialFixed)

### Row `GR-6.5-1` — DIVERGES (editions 2002/2014/2023 (the >>SOURCE FORMAT directive is part of the §7.3 compiler-directive facility; a COBOL-85 source has no directive line — gated COBOLNET0900))

'If the line is a SOURCE FORMAT directive, the reference format mode is determined and the SOURCE FORMAT directive line is logically discarded.' (--check OK §6.5 1)). NormalizeToFreeFormMapped collects the switches (TryMatchDirective, word-keyed via CompilerDirectiveLine, margin-R cut, sequence area allowed), partitions into segments whose format is the declared one, and emits a BLANK line in the directive's slot (line 178) — discarded content, line numbering preserved. Malformed operand is consumed and diagnosed (PB794, landed). Adversarial: a '*' comment line whose text is '>>SOURCE FORMAT FREE' is NOT taken as a directive (rf15.cob -> [OK15]); a free-form '*> >>SOURCE FORMAT FIXED' comment likewise (rf16.cob -> [OK16]). Unit tests SourceFormatTests (tests/CobolSharp.Tests.Unit/Preprocessor) drive CobolNet.Frontend's ReferenceFormatProcessor directly with spec-derived expectations (directive line blank; following segment in the declared format). || REFUTED: DIVERGES — The directive line must be recognized (and the mode determined) in whichever format is in effect. TryMatchDirective / TryMatchStackOp cut EVERY raw line at MarginR (col 72) before matching, but in free form the ENTIRE line is the program-text area (§6.4.1) and a directive may be preceded by any number of spaces (§7.3.3 SR2). A legal free-form '>>SOURCE FORMAT FIXED' whose operand lies past column 72 is truncated to '>>SOURCE FORMA', diagnosed COBOLNET1911 as malformed, the mode is NOT switched, and the following fixed-form lines are then misread (COBOL0001). Main paths hold (fixed/free directive lines, indented free directive with inline comment, library-text directives + revert per §7.3.24.3 GR3/GR5: probes p3/p4/p5/p7/p8 all correct), so the defect is the margin-R cut applied format-blind.

### What the fixer owes

Make the mode a STATE of the logical-conversion pass: fixed-form by default (§6.1), switched only by a SOURCE FORMAT directive (or an explicit compiler option documented in CONFORMANCE.md as the implementor's selection), and recognise a directive line against the program-text area OF THE MODE IN EFFECT — the whole line in free form, columns 8–72 in fixed form. If the heuristic survives as a convenience it must be an option-gated extension documented as such, never the default. Goldens: rf7/rf8 (non-digit and blank sequence areas compile as fixed form); a free-form directive with its operand past column 72. Sweep TryMatchStackOp and CopyProcessor's copybook classifier (PB1067's ≥50 % sequence-number rule is the same heuristic in library text).
