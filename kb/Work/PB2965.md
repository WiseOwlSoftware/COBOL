# PB2965 — STANDARD-DECIMAL exact-family functions keep the Int128 arm

Filed 2026-10-10 by the train 1056 lander from the wave 1056 C implementer's report
(`E:\COBOL-coord\scratch\reports\w1056c-PB2918-report.md`, lead 1).

**Repro:** `E:\COBOL-coord\scratch\w1056c\sd3.cob`: under `ARITHMETIC IS STANDARD-DECIMAL`, `COMPUTE R = FUNCTION
ABS(S)` with S PIC S9(19) COMP-5 holding -2^127 takes PB2698's size error.

**Site:** `IntrinsicRenderer.RenderNum` (the `AbsScaled` arm, about line 220) versus `RenderDec` (about line 1161):
D3's "exact residue" determination keeps the exact-family functions on the Int128 arm whenever every argument is
fixed-point, even under STANDARD-DECIMAL.

**Why.** §15.4.1 r1 makes these functions' arguments arithmetic expressions evaluated in the statement's mode, and
§8.8.1.5.2 r1 ("If the operand value cannot be expressed exactly in an SDIDI, the value is rounded according to the
rules in 11.9.11") rounds the 39-digit argument into the SDIDI; ABS of that SDIDI is a value R holds. PB2918 (train
1056) fixed the operand lift for arithmetic expressions; this arm bypasses the lift.

**Decide first (owner).** The fix reopens D3's exact-residue determination for the exact family under
STANDARD-DECIMAL; the implementer flagged it as needing an owner call before the arm moves.

## Landing

**Landed 2026-10-11 (wave 1059 B).** Re-probed on a fresh build before any edit (`w1059b/sd3.cob`, a copy of the filed
`w1056c/sd3.cob`): `COMPUTE R = FUNCTION ABS(S)` with S = -2^127 in `PIC S9(19) COMP-5` took ON SIZE ERROR exactly as filed.

**The owner call the note asked for is not one.** The spec decides, and it splits the "exact family" in two (cite.py --check
OK for each). ABS (§15.7.4 r1 b, `(- (argument-1))`), SIGN (§15.81.4 r1), INTEGER-PART (§15.49.4 r1,
`SIGN(argument-1) * INTEGER(ABS(argument-1))`) and FRACTION-PART (§15.42.4 r1, `argument-1 - INTEGER-PART(argument-1)`) each
have an EQUIVALENT ARITHMETIC EXPRESSION, so under STANDARD-DECIMAL the returned value "shall equal the value of the
equivalent arithmetic expression" (§15.4.1 r1), whose operand `argument-1` is converted into the SDIDI and "if the operand
value cannot be expressed exactly in an SDIDI, the value is rounded" (§8.8.1.5.2 r1). **INTEGER has none** (§15.44.4 r1: "the
greatest integer less than or equal to the value of argument-1"), and MAX / MIN return "the content of the argument-1"
(§15.59.4 r1 / §15.63.4 r1), so the note's list was wrong about INTEGER: its argument is a value and not an operand, and
INTEGER stays exact (D3's recorded determination for a result past 34 digits). D3's "documented equivalence" is not
reopened, it is bounded: the exact Int128 body equals the SDIDI evaluation exactly while the argument's lift is exact.

**Root and fix (one predicate, one set).** `NumericRenderer.LiftRounds(NumX)` is the one answer to "does this lift round?"
that `DecOperand` already embodied inline (PB2918); `IntrinsicRenderer.ArgumentRoundsAtLift` asks it of the call's arguments
for the members of the new `EquivalentExpressionUnaryArms` set (`AbsScaled`, `SignOf`, `Truncate`, `FractionPart`), and
`RenderDec`'s early-out lets such a call through to its existing `…Dec` body. A 16-byte container (bound 39) and an unknown
bound (Digits 0) take the SDIDI; a bound within 34 keeps the Int128 body unchanged. Probes after (own build): `ABS(S)` ->
170141183460469231731687303715884100000, stored; `ABS(T)` (T = 3*2^124) -> ...540000, not the exact ...539648;
`INTEGER-PART(S)` -> -...100000; `FRACTION-PART` of `PIC S9(22)V9(9) COMP-5` holding -2^127 -> -0.8841, not -0.884105728;
DISPLAY, MOVE, relation and nested-ABS channels agree.

Witnesses: golden `2023/pb2965_sdidi_equivalent_expression_functions_round_wide_argument` (it fails on the pre-fix compiler:
ABS size error, ABS(T) low digits ...539648, FRACTION-PART -0.884105728; the INTEGER / MIN / MAX legs pin the exact side);
`ExactCarrierBoundaryDriftTests` invariant 4 (every unary exact arm is routed or named as having no expression; the
selection arms stay out; the renderer asks `LiftRounds` and never restates 34). Docs: `NUMERIC_DESIGN.md` D3 + D27;
`CONFORMANCE.md` DOC-A.1-179 (3).
