# PB3490 — a hang on both sides is reported as ours

## What the report said and what the data says

`report.md` of the first overnight run: `WE_HANG | 8`. In `results.jsonl` three of the eight rows carry
`"they": {"hung": true}` — GnuCOBOL's program also ran into the 90 s guard:

| Program | Why both loop forever (per the standard) |
|---|---|
| fz01771 | `PERFORM VARYING WS-COUNTER FROM 5 BY -2 UNTIL WS-COUNTER > 8` on an UNSIGNED `PIC 9(3)`: 5, 3, 1, then 1 − 2 = −1 stores its absolute value 1 (§14.9.25.4 GR, "When an unsigned numeric item is the receiving item, the absolute value of the sending value is used", the store rule the arithmetic statements take through §14.7.7), and 1 never exceeds 8 |
| fz04123 | `PERFORM VARYING WS-INDEX FROM 10 BY -3 UNTIL WS-INDEX < 1` on `PIC 99`: 10, 7, 4, 1, then −2 stores 2, −1 stores 1, 2, 1, … |
| fz00122 | `PERFORM UNTIL WS-LOW > WS-HIGH` whose body changes neither bound |

The other five rows are real one-sided results and keep their class (GnuCOBOL finished with exit 11, a segfault,
on four programs whose PERFORM nesting is undefined — §14.9.28.4 GR2 — or whose subscripts are negative; WiseOwl
overflowed its stack on three of those and looped on one; fz02262 is a WiseOwl COMPILE hang, kb/Work PB3489).

## The code

`scripts/differential_fuzz.py` `classify()`: after the compile-side checks it tests `if we.hung: return "WE_HANG"`
and only then `if they.hung: return "THEY_HANG"`. There is no class for both, and the docstring's class list
(`WE_HANG` "WiseOwl's compile or program exceeded the hang guard while GnuCOBOL's finished") promises a
one-sidedness the code does not check. The report's TRIAGE RULE block then sends a reader to the spec for a
WiseOwl hang that is a property of the program.

## Fix shape

- Add `BOTH_HANG` (a model-failure class like `BOTH_REJECT`: a program both compilers run forever is the
  generator's, and belongs in the "model's failures" count, not among the survivors), returned when both
  observations have `hung`; `WE_HANG`/`THEY_HANG` only when exactly one does. Same for the compile-side pair.
- `--self-test`: a check that `classify(hung, hung) == "BOTH_HANG"` and that neither one-sided class matches it
  (the existing hang checks only cover one side at a time, which is why this passed).
- Re-render `report.md` of fuzz-20261020-224517 from its `results.jsonl` once the class exists (the harness's
  report step reads the jsonl; no model time needed) so the stored triage report matches.
