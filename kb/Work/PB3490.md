# PB3490 — a hang on both sides is reported as ours

## What the report said and what the data says

`report.md` of the first overnight run: `WE_HANG | 8`. In `results.jsonl` three of the eight rows carry
`"they": {"hung": true}` — GnuCOBOL's program also ran into the 90 s guard:

| Program | Why both loop forever (per the standard) |
|---|---|
| fz01771 | `PERFORM VARYING WS-COUNTER FROM 5 BY -2 UNTIL WS-COUNTER > 8` on an UNSIGNED `PIC 9(3)`: 5, 3, 1, then 1 − 2 = −1 stores its absolute value 1 (§14.9.25.4 GR, "When an unsigned numeric item is the receiving item, the absolute value of the sending value is used", the store rule the arithmetic statements take through §14.7.7), and 1 never exceeds 8 |
| fz04123 | `PERFORM VARYING WS-INDEX FROM 10 BY -3 UNTIL WS-INDEX < 1` on `PIC 99`: 10, 7, 4, 1, then −2 stores 2, −1 stores 1, 2, 1, … |
| fz00122 | `PERFORM UNTIL WS-LOW > WS-HIGH` whose body changes neither bound |

The other five rows are real one-sided results and keep their class (GnuCOBOL finished with exit 11, a segfault,
on four programs whose PERFORM nesting is undefined — §14.9.28.4 GR2 — or whose subscripts are negative; WiseOwl
overflowed its stack on three of those and looped on one; fz02262 is a WiseOwl COMPILE hang, kb/Work PB3489).

## The code

`scripts/differential_fuzz.py` `classify()`: after the compile-side checks it tests `if we.hung: return "WE_HANG"`
and only then `if they.hung: return "THEY_HANG"`. There is no class for both, and the docstring's class list
(`WE_HANG` "WiseOwl's compile or program exceeded the hang guard while GnuCOBOL's finished") promises a
one-sidedness the code does not check. The report's TRIAGE RULE block then sends a reader to the spec for a
WiseOwl hang that is a property of the program.

## Fix shape

- Add `BOTH_HANG` (a model-failure class like `BOTH_REJECT`: a program both compilers run forever is the
  generator's, and belongs in the "model's failures" count, not among the survivors), returned when both
  observations have `hung`; `WE_HANG`/`THEY_HANG` only when exactly one does. Same for the compile-side pair.
- `--self-test`: a check that `classify(hung, hung) == "BOTH_HANG"` and that neither one-sided class matches it
  (the existing hang checks only cover one side at a time, which is why this passed).
- Re-render `report.md` of fuzz-20261020-224517 from its `results.jsonl` once the class exists (the harness's
  report step reads the jsonl; no model time needed) so the stored triage report matches.

## Landed (2026-10-21 evening, before the second overnight run)

`classify()` tests a hang on both sides before either alone and returns `BOTH_HANG`, a model-failure class beside
`BOTH_REJECT` and `NO_PROGRAM`; the one-sided classes keep their names and now mean what the docstring says. The same
change set adds the report fold the first night's triage record asked for
(`docs/rearchitecture/evidence/fleet-optimization/2026-10-21-differential-fuzz-overnight.md`): two outputs equal under
`display_image()` — GnuCOBOL's leading separate sign and inserted decimal point and WiseOwl's over-punched digit image folded
to one sign-and-digits image — are `OUTPUT_LATITUDE`, listed under their own heading and never a survivor (PB803 settled the
sign, PB3467 asks about the point; the fold classifies a row and judges nothing). A row that differs elsewhere stays
`OUTPUT_DIFFERS` and the report lists its REAL differing lines first, counting the latitude-only lines beside them.

The fold is TEXT, and text cannot tell `PIC 9(5)V99`'s digit image (`0001250` against `00012.50`, the latitude) from an
edited `PIC ZZ9.99` whose point WiseOwl dropped (a wrong answer), nor an over-punched sign from a SIGN SEPARATE item
printed without its sign (branch review R1-1, mythos-review-pb3490-r1, which built four such pairs). So
`display_fold_allowed(source)` gates it: the fold applies only to a program whose pictures carry no point and no editing
sign (`.`, `+`, `-`, `CR`, `DB`) and that declares no SIGN SEPARATE item; in such a program a point or a separate sign in
GnuCOBOL's output can only be its display form. A program with such a picture keeps every difference as `OUTPUT_DIFFERS`.
Round 2 of the review closed two holes in the guard's reading of the source: the picture keyword is not matched as the
tail of a data name (`WS-EDIT-PIC PIC ZZ9.99` hid its picture; 149 first-night programs carry a `-PIC` name), and
`LEADING SEPARATE` is caught without the optional words `SIGN IS` (ISO 13.18.52.2).
The flag is recorded per row (`display_fold`); `--report` re-reads older rows from their source. `--self-test` pins all of it.

Replayed over the first night's `results.jsonl` (fuzz-20261020-224517): 3 `WE_HANG` rows become `BOTH_HANG` (the three
named above; the other five stay ours) and 501 of the 1,141 `OUTPUT_DIFFERS` rows become `OUTPUT_LATITUDE`, leaving 640
output rows to read (the triage's hand canonicalization counted 615 fold-equal rows; the text fold alone finds 676, and the
source guard keeps 175 of those as `OUTPUT_DIFFERS` because their program declares an edited picture or SIGN SEPARATE: the
sampled ones were genuine latitude, and the triage reads them rather than the fold deciding). The stored `report.md` was
re-rendered from the jsonl; the report the triage read is kept beside it as `report.as-triaged-2026-10-21.md`.
