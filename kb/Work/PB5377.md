# PB5377 - RECEIVE INTO a group that contains its own OCCURS DEPENDING ON object transfers into the group's current length instead of its maximum length, so a message or segment shorter than the area is split as if it were longer (wrong TEXT LENGTH, END KEY and contents)

**Sites:**

- `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/CommunicationEmitter.cs#EmitReceive` (passes the receiving area's image)
- `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/OperandText.cs#RecordAreaImage` (the image at the current ODO length)
- `src/WiseOwl.Cobol.Runtime/Communication/MessageControlSession.cs#PendingReceive` (`Next` fills the room it is given)

**Mechanism.** `EmitReceive` hands the runtime `OperandText.RecordAreaImage(into)`, the CURRENT image of identifier-1. When identifier-1 is a group holding its own ODO object, a receiving group is used at its maximum length, but the image is the length at the object's current value, so `PendingReceive.Next` sees a smaller area and splits the message. MOVE into the same group already uses the maximum length. kb/Work PB5309 (open) is the READ/RETURN INTO sending side of variable records, a different site.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids below. Its rows are not recorded: the refuter's OVERTURNED verdicts are held for adjudication in `E:/COBOL-coord/scratch/coderead-85/held-7.json`.

**Rules (3 claimed; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-GR-XIV.3.5.4-3` - `§1985:XIV.3.5.4 GR3` (refuter: OVERTURNED, harm: wrong answer): the message is transferred "to the receiving character positions of the area referenced by identifier-1"; for a group with its own ODO object, "If the group is a receiving item, the maximum length of the group will be used" (`§1985:VI.5.8.4 GR3b`).
- `1985-GR-XIV.3.5.4-8` - `§1985:XIV.3.5.4 GR8b` (refuter: OVERTURNED, harm: wrong answer): "If a message size is less than the area referenced by identifier-1", the message is left-aligned and the rest is unchanged.
- `1985-GR-XIV.3.5.4-9` - `§1985:XIV.3.5.4 GR9b` (refuter: OVERTURNED, harm: wrong answer): "If the segment size is less than the area referenced by identifier-1", the same for a segment.

**Repro.** `E:/COBOL-coord/scratch/coderead-85/out-reread2/refute-rr-06/g2/g2.cob` with `g2/mcs.json` (Q1 holds the message `5ABCDEFGH`; Q2 holds a message whose first segment is `7ABCDEFGH`): `01 GOD. 05 GN PIC 9. 05 GT PIC X OCCURS 1 TO 9 DEPENDING ON GN` (maximum 10 positions), GN = 3, then `RECEIVE CIN MESSAGE INTO GOD` and `RECEIVE CIN SEGMENT INTO GOD`; `cobol.exe --std 85 --source-format fixed --run g2.cob` in a directory holding the mcs.json.

**Observed (the pinned compiler of `E:/COBOL-wt/coderead85-tree-b` (origin/main 8147f008b3; `git diff --stat 8147f008b3 origin/main -- src` is empty at 5237495315), rerun 2026-11-12; `E:/COBOL-coord/scratch/coderead-85/reprobe-85f/log.txt`).** `MV [9ABCDEFGH ]` (the MOVE uses 10 positions), then `RM 0004 0 GN=5` and `RS 0004 0 GN=7`: four characters, END KEY 0, the rest held back for the next RECEIVE.

**Expected (from the 1985 text).** TEXT LENGTH 0009 with END KEY 2 for MESSAGE and 1 for SEGMENT, the whole text in GOD(1:9), position 10 unchanged.

**Fix direction (root cause, CLAUDE.md rule 4).** Size the receiving area of RECEIVE INTO as every other receiving use of a group does (its maximum length when it contains its own ODO object), through the one helper MOVE already uses rather than a second rule in the communication emitter.
