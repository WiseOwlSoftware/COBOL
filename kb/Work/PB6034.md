# PB6034 - run.py's cobol processes die with exit -1 in one window of a gate

**Sites:** `tests/WiseOwl.Cobol.Tests.Conformance/ConformanceSuiteRunnerDriftTests.cs` (`BothRunnersVerdictDriftTestsBase`, `Run`: run.py under an ObservationBudget), `conformance-suite/harness/run.py:260` (`it did not translate`).

**Observed.** Gate run `000002-20261121T204321Z` of branch `train-1985-b` (head 3d1601a4ee): five of the eight
partitions (P3, P4, P5, P6, P7) of `BothRunnersVerdictDriftTests` failed, 17 suite tests in all, every one at 2023 and
every one `in-process PASS (); run.py FAIL (it did not translate (exit 4294967295): no output)`. The partitions ran from
12:45:20 to about 12:52:40 PST (7 m 15 s to 7 m 21 s each), and the failures cluster in their last seconds. The Unit host
of the same gate ended at 12:51:50 (`Unit.trx` finish), about the moment those last run.py rounds ran. A rerun of P3 and P7
alone on the same build passed (`dotnet test ... --filter BothRunnersVerdictDriftTests_P3|_P7`: Passed 2), so the tree
does not earn the red.

**What the exit code says.** 4294967295 is -1 as an unsigned Windows exit code: the cobol CLI returns 0, 64, 65, 66, 70 or
73 (`Program.ExitCode`) and never -1, and the gate's own job kill (`process_job.ProcessJob.kill`) terminates with 1. A
`TerminateProcess(h, -1)` is what .NET's `Process.Kill` issues, so some .NET caller killed the `cobol` processes (or the
`dotnet` host under them) while run.py waited on them. Candidates to measure first: (1) the ObservationBudget's handling
of a child tree (`ProcessObservation`), (2) a test host's end-of-run reaping of scratch (`SCRATCH-LEFT ... the next test
host reaps it once this one has ended`) reaching a directory run.py's processes still use, (3) a Unit test that kills a
process tree it does not own.

**Fix wanted.** The mechanism, then a structural guard, never a retry; the root cause is not this train's.
