# PB4904 - stale comments about the DEBUG-* register

**What the report says (the reviewer's words).** R3-3 LEAD (low, not blocking at round 3): `Place.cs:1017` R2-3 made the register
writable and left the text that says otherwise: DebugRegisterPlace's summary (A COBOL program never assigns to a DEBUG-*
register, so PlaceRenderer.Write of this place is an internal-error backstop), ExceptionObjectPlace's summary in the same file
(internal-error backstop, exactly as it is for DebugRegisterPlace), the DebugItem class summary (`DebugItem.cs:34`, a read-only
view) and `ImplicitRegisters.cs:23` (its read-only runtime read expression). CONTROL_FLOW_DESIGN D20 (c) still lists READ under
LandAfterAction, which READ no longer calls.

**Still wrong on main (read, 2026-11-06).** `Place.cs:1017-1018` (DebugRegisterPlace summary), `Place.cs:1051` (ExceptionObjectPlace
summary, "exactly as it is for DebugRegisterPlace"), `DebugItem.cs:34` ("a read-only view"), `ImplicitRegisters.cs:23` ("read-only
runtime read expression"), and `docs/CONTROL_FLOW_DESIGN.md` D20 (c), which says `LandAfterAction` is landed "in RECEIVE and in the
READ, DELETE, DELETE FILE and START emitters" while `KeyedIoEmitter.cs:252` calls `LandAfterActionKeeping` for READ. No code is
changed by the fix; the ExceptionObjectPlace comment stays true for EXCEPTION-OBJECT itself (§8.4.3.6.3 SR1) and loses only its
comparison with the debug register.
