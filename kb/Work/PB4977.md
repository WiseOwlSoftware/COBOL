# PB4977 - the dynamic SEARCH prelude is held outside its WHEN phrase

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/SearchBinder.cs` (`SearchBinder.DynamicTablePath`, `prelude = host.Udf.OperandSteps(...)`, about line 95; the `whenEnclosing` / `Borrowed` consumers), `DebugTriggerPlanner.Leaves` over the `BoundSequence`, `BoundSearch.WhenSubscripts`.

**Report.** For a nested dynamic-capacity table whose WHEN subscripts contain a function or an object property, `SearchBinder.DynamicTablePath` hoists their
evaluation ahead of the scan as a separate statement step (`OperandSteps` of the WHEN subscripts' function/property pre-ops). The debug planner may then count an
operand of those steps as a reference of the statement even when no WHEN phrase is evaluated (e.g. AT END with no WHEN reached). NOT probed (too large for the round).
Same root as PB4855's R1-1, which fixed the other two consumers (`Table`, `DynTable`) with `BoundSearch.WhenSubscripts` + the implicit-operand skip: an operand borrowed from a WHEN
phrase and held outside it. Probe shape: `wdyn.cob` in `E:/COBOL-coord/scratch/w20261921e/f/` (`--std 2023 --permissive`, `C OCCURS DYNAMIC CAPACITY IN CC INDEXED BY CX` under `ROW OCCURS 2`) with a function in the WHEN subscript, plus a USE FOR DEBUGGING on the subscript's operand; expect no debug section on the AT END leg.
Witness to extend: `DebugFacilityTests.SearchWhenNamedOccurrence_IsReferencedOnlyWhenTheWhenIsEvaluated`.

## Landing

Re-probed on the branch build (a function in the WHEN subscript of a nested dynamic table, USE FOR DEBUGGING ON ALL REFERENCES OF I): AT END then `DB1 [2 ]` RAN before the fix (the hoisted prelude's operand I counted as the statement's), and the WHEN leg ran it once.
Two causes. (1) `SearchBinder.Preceded` put the prelude copies in the statement's own `BoundSequence`, so `DebugTriggerPlanner.Leaves` yielded them as leaves. (2) Behind it, `BoundReferences` never entered an operand-evaluation step held in a CONDITION's window (`BoundUdfEvaluated.Activations`), because a nested statement is skipped, so the phrase itself never reported a function's operand: an EVALUATE WHEN with a function in a subscript lost the section.
Fix: `BoundSequence.RepeatsPhraseOperands` marks the prelude (a nested sequence built by `Preceded`), the planner skips it, `EcBinder.StampActivators` keeps the flag (`with`), and `BoundReferences.Visit` enters a nested statement that is an `OperandEvaluation` step. Witness: `DebugFacilityTests.FunctionInWhenSubscript_IsReferencedOnlyWhenThePhraseIsEvaluated`.

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/SearchBinder.cs` (`Preceded`), `src/WiseOwl.Cobol.Compiler/Binding/Bound/BoundTree.cs` (`BoundSequence`), `src/WiseOwl.Cobol.Compiler/Binding/Bound/BoundReferences.cs` (`Visit`), `src/WiseOwl.Cobol.Compiler/Binding/Bound/DebugTriggerPlanner.cs` (`Leaves`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/EcBinder.cs` (`StampActivators`).
