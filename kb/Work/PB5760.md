# PB5760 - RESUME AT NEXT STATEMENT after a RELEASE's EC-SORT-MERGE-RELEASE ends the SORT

**Sites (lead, from the writer; not traced to the line that unwinds the SORT):**
- `src/WiseOwl.Cobol.Runtime/IO/CobolSort.cs#ReleaseStatement` (line 258-262: `ExceptionState.SortMergeReleaseError` raises the condition for a record outside the SD's range, before `rangeFailsStatement` returns).
- `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/SortEmitter.cs#EmitRelease` (line 716): the RELEASE's emitted call; the declarative's RESUME target is evidently not the implicit CONTINUE after the RELEASE but the end of the SORT statement that runs the input procedure.

**Rules (each checked with `python scripts/spec/cite.py --check`, verdict OK).**

- `§2002:13.16.41.3 GR14`: "If a RELEASE statement is being executed, the EC-SORT-MERGE-RELEASE exception condition is set to exist and the execution of the RELEASE statement is unsuccessful" (GR19 b says the same for the format 3 integer-4 / integer-5 range).
- `§2002:14.8.31.3 GR2`: "control is transferred to an implicit CONTINUE statement that immediately follows the end of the statement" ... "the applicable statement is the one in which the exception condition was raised" (GR2 a). Neither the RELEASE rules (§2002:14.8.30.3) nor the SORT rules specify otherwise for a RELEASE in an input procedure.

**Expected (2002 text):** the declarative runs, RESUME AT NEXT STATEMENT continues after the unsuccessful RELEASE, the input procedure goes on (`AFTER BAD RELEASE`, the in-range RELEASE, `AFTER GOOD RELEASE`), then the output procedure returns the one released record (the 3-byte `AAA`, `L=03`), then `END`.

**Observed at `--std 2002` (and `--std 2023`)**, on the golden-2002-8 build (main 5e49d46678), `cobol.exe ecr2.cob --std 2002 --run`:

```
DECL EC-SORT-MERGE-RELEASE
END
```

rc 0: nothing after the bad RELEASE runs, and the output procedure never runs.
