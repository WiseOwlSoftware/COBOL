# PB4528 — report-sum-counter-name-refers-to-printable-item: Report Writer: the data-name of a SUM entry refers to the printed field, not to the sum counter

Filed 2026-11-03 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-batch-3000-20261103`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

In the Report Writer, the data-name of an entry with a SUM clause names the sum counter. cobc binds the name to the
printable report field instead. A procedure-division reference to the name (DISPLAY, ADD, MOVE) therefore sees the
last printed image (spaces before the footing is printed) rather than the running total, and an ADD to it does not
change the counter.

## Minimal test case

Free reference format (`-free`). The program writes the report to the file `sumctr.out`.
```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. SUMCTR.
ENVIRONMENT DIVISION.
INPUT-OUTPUT SECTION.
FILE-CONTROL.
    SELECT F-REPORT ASSIGN TO "sumctr.out".
DATA DIVISION.
FILE SECTION.
FD F-REPORT REPORT IS R-SALES.
WORKING-STORAGE SECTION.
01 WS-AMT PIC 9(4) VALUE 0.
REPORT SECTION.
RD R-SALES CONTROL IS FINAL PAGE LIMIT IS 20 LINES.
01 RP-DET TYPE DETAIL LINE PLUS 1.
   02 COLUMN 1 PIC 9(4) SOURCE WS-AMT.
01 TYPE CONTROL FOOTING FINAL LINE PLUS 2.
   02 RP-TOT COLUMN 1 PIC 9(6) SUM OF WS-AMT.
PROCEDURE DIVISION.
    OPEN OUTPUT F-REPORT
    INITIATE R-SALES
    MOVE 100 TO WS-AMT
    GENERATE RP-DET
    DISPLAY "A " RP-TOT
    MOVE 50 TO WS-AMT
    GENERATE RP-DET
    DISPLAY "B " RP-TOT
    ADD 1 TO RP-TOT
    DISPLAY "C " RP-TOT
    TERMINATE R-SALES
    CLOSE F-REPORT
    STOP RUN.
```

## Environment

cobc (GnuCOBOL) 3.2.0 on WSL2 Ubuntu. `cobc -x -free -std=cobol2014 -o p prog.cob && ./p`.

## Observed result

```
A       
B       
C 999999
```
Exit code 0. The final footing line in `sumctr.out` is `000150`.

## Expected result (per ISO)

§13.18.54.4 rule 5 (2014, 2023): "If a data-name immediately follows the level number in the entry containing
the SUM clause, the data-name is the name of the sum counter, not the name of the associated printable item, if any."
Rule 1: "The sum counter is a conceptual data item that behaves as a data item of the category numeric" and "The sum
counter is signed, whether or not the corresponding PICTURE clause has an operational sign." Rule 7 c) 1.: the addend
is added "whenever any GENERATE statement is executed for the current report". Rule 12: "It is permissible for
procedure division statements to alter the content of sum counters." So RP-TOT is 100 after the first
GENERATE, 150 after the second, 151 after the ADD, and the footing prints 000151. Expected (the sign's representation
in DISPLAY is the implementor's):
```
A +000100
B +000150
C +000151
```

## Our compiler

WiseOwl COBOL (fresh judge) prints the expected output above, and its `sumctr.out` footing line is `000151`.

## Fix site

cobc keeps the counter as a separate field (`report_sum_counter` of the SUM entry's `cb_field`, emitted in
cobc/codegen.c `output_report_sum_counters` and the report-field output near it); name resolution of the entry's
data-name in a procedure-division reference yields the printable field rather than `report_sum_counter`. Read
observationally in a 3.3-dev tree.

Decisive: USE BEFORE REPORTING runs before the printable items are filled (14.9.49.4 GR9 d)), so #775 can only be fixed by 13.18.54.4 GR5, which also fixes this note. A comment on #775 carrying this note's repro (it adds GR12, ADD to the counter, and a reference outside the declaratives), not a new ticket, is the most to do.
