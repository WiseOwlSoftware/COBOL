# PB3518 — the exhaustion witness may pin a non-conforming answer

Low, non-blocking lead from the branch review of PB3498 (`E:/COBOL-coord/scratch/reports/w1142a-PB3498-report.md`, `## Review findings` R1-1). The branch is not yet on main (PR #382); the sites below are as they stand on that branch, so re-read them after it lands.

**The lead.** `tests/Cobol.Net.Tests.Unit/HandleColumnLockHostDriftTests.cs` about line 336: the new exhaustion witness asserts `Outcome.Unavailable` for a fresh SHARING WITH ALL OTHER I-O request while its own setup holds a READ ONLY INPUT column (kept), which Table 19 refuses that request against. The test therefore may pin a non-conforming answer as correct, and its comment ("never Refused, since 61 is another connector's") is false for that setup: `HandleColumnLockHost.Establish` returns `Unavailable` when `Publish` exhausts (about line 82) before it ever tests the refused columns.

**Open question (stated, not adjudicated).** When publication is exhausted and the request also conflicts with a held column, does a user program see status 61 (refused) or the status `Unavailable` maps to? The ISO rule is Table 19 (section 14.9.27.4); an adjudicator decides which outcome the spec requires.

**Fix shape, once decided.** Either order `Establish` so the refused-column test runs before `Publish` (and correct the witness), or change the witness setup so no held column conflicts with the request, and correct the comment.

**Sites:**
- `tests/Cobol.Net.Tests.Unit/HandleColumnLockHostDriftTests.cs`
- `src/Cobol.Net.Runtime/` `HandleColumnLockHost.Establish` and `Publish`
