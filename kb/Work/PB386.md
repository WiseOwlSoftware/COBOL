# PB386 — the GAP count is supposed to measure unfinished WORK, and three of these rows are unfinishable

Raised by the round-2 golden writer `singles`, which drew six rows and found **three of them in this class, each
for a different and legitimate reason**; the round-2 landing then measured the whole population and found
**eight** — every CONFORMS-but-untested row left on the tree except `DOC-A.1-93`, which is a real defect
(`PB383`). It is the same shape as **PB280 Q2** (does a DOC row with nothing in the compiler to observe close on
the register alone) — a question about what widens the definition of DONE, which
`DESIGN-spec-conformance-review.md` §1 owns and an agent may not widen.

⭐ **The population is the whole of it.** After golden-lane round 2 the inventory carries **9**
CONFORMS-but-untested rows; eight are below and the ninth is `PB383`. So this decision is not a corner: it is
the difference between a CONFORMS-but-untested band that empties and one that never can.

## The mechanism, measured

`Schema.state_for` (`scripts/spec/inventory_schema.py`) makes **every** resolving verdict owe at least one
SPEC-DERIVED `test-ref`, with no exemption anywhere in the verdict vocabulary or in any kind's evidence rules.
So a row with `verdict: CONFORMS` and an empty `test-ref` computes `GAP`, permanently, however completely the
rule has been verified. That clause is deliberate and correct in general — it is what makes
CONFORMS-but-untested expressible and what stopped the first Phase-B batch closing seven rows on NIST goldens
and a `*_MatchesLegacy` differential. The question is whether it admits a principled exception.

## The three rows, and why none of them can earn a golden

| Row | Why no expected value exists |
|---|---|
| `GR-14.9.5.4-11` | On **§A.2's explicit undefined-language-element list**. Every behaviour conforms, so there is nothing to derive an expected output from. |
| `GR-14.9.11.4-11` | Its antecedent is **false for every device the compiler can DISPLAY upon** — a closed, two-valued device set. The rule has no reachable instance. |
| `RV-15.50.4-9` | Its consequent returns **the same integer as §15.50.4 r5** for every argument r3 admits, so no conforming program can distinguish the two rules. |
| `DOC-A.1-19` | §14.9.5.4 GR10 governs a program the runtime **located** per GR2; `ProgramTable.Cancel` resolves with `probe: false` and returns on a null node, so no locate step runs and `CANCEL "Cobol.Net.Runtime"` and `CANCEL "L1NOSUCH"` take the byte-identical path. Reached this class from the other direction: golden-lane round 2 **wrote** the witness, the refuter showed its output was INVARIANT under the determination it claimed to measure, and it was deleted. |
| `GR-14.9.30.4-3` | *"the content of any data item, where any part of that data item lies beyond the range of the current record, is undefined"* — an **Annex A.2 grant of undefinedness**. Every observation conforms, and A.2 (unlike A.1) carries no documentation obligation, so there is not even a documented choice to assert. |
| `GR-14.9.30.4-20` | A requirement **on the source program** (*"shall be a single reel/unit mass storage file"*), not on the implementation. Every physical file a program can name already satisfies it — one ASSIGN target, one host path, no reel/unit model — so neither a positive nor a negative witness is constructible. |
| `GR-14.9.30.4-23` | Its antecedent needs an end of reel/unit recognized **while the logical end of file has not been reached**. On a single-volume medium those are the same event, so the antecedent can never hold. |
| `GR-14.9.34.4-2` | The RETURN twin of GR-14.9.30.4-3, and doubly unreachable: it is a grant of undefinedness, AND the region it governs can only exist if the SD carries records of different lengths with variable-length records, which §13.18.43.4 GR5 makes the implementor's choice. |

⚠ And the reason this is not simply "write the golden anyway": a manufactured witness for any of the three would
pin an IMPLEMENTATION CHOICE as though it were the standard's answer — precisely what the schema's
`spec-derived` clause exists to prevent. The cheap move here is the wrong one, twice over.

## The sketch the owner is asked to accept or reject

A resolving verdict whose evidence is a **derivation** rather than a test: an owner-signed determination,
recorded in `docs/CONFORMANCE.md` like any other, stating that the rule carries no observable obligation and
why — §A.2 membership, an unpopulatable antecedent, or an indistinguishable consequent. The row then computes
`OK` on that determination in place of a `test-ref`.

Three consequences if it is taken, and they are the cost:

1. **`Schema.state_for` and its C# twin `DerivedState` must learn it in the SAME change set** — PB315 is the
   note recording what happens when those two read one rule differently, and the disagreement was unobservable
   until a row first exercised the divergent branch.
2. The determination must be **checkable**, not a free-text escape hatch, or the GAP metric becomes cheaper to
   move than the work it stands for — which is the exact failure `state_for`'s docstring says the spec-derived
   clause is there to prevent. The A.2 arm is mechanically checkable against the standard's own list; the other
   two arms are arguments, and an argument needs a reader.
3. Every existing CONFORMS-but-untested row becomes a candidate for the escape, so the population must be
   MEASURED before the door opens, not after.

## ⚖ Owner decision 2026-09-03 — YES, checkable only

Asked as the bare question (AskUserQuestion, third pause). **Answer: a checkable, owner-signed derivation recorded
in `docs/CONFORMANCE.md` may stand in place of a spec-derived test for exactly this class.** Bounds the owner
accepted with it: the Annex A.2 arm is verified MECHANICALLY against the standard's own undefined-element list;
the unpopulatable-antecedent and indistinguishable-consequent arms are reviewed ARGUMENTS, each naming the closed
set that makes the antecedent unreachable or the rule whose consequent it cannot be told from; `Schema.state_for`
and its C# twin `DerivedState` learn the evidence kind in the SAME change set (PB315's lesson); the population is
measured before the door opens (it is the eight rows above; a ninth, `DOC-A.1-93`, is PB383 and a real defect).
Distinguished from PB280 Q2 ("No" for DOC rows): a DOC row asks the implementor to STATE a choice, so "nothing to
observe" is unfalsifiable; these rows carry no obligation at all, and the derivation is what proves it. Status →
`open` (implementable); the implementer's job is the evidence kind, its two checkers, the eight determinations, a
drift test that a derivation on a row with an observable obligation is REFUSED, and the re-verdict.

⛔ **Do NOT re-verdict these three rows on a manufactured witness in the meantime.** They stay GAP and visible,
which is the honest state: the inventory is telling the truth about them and it is the DEFINITION of done, not
the measurement, that has the hole.

## ✅ Landed 2026-09-04 — the evidence kind, its three checkers, the eight determinations, the re-verdict

`derivation` is now an adjudicated inventory field carrying the anchor `docs/CONFORMANCE.md#DRV-<rule-id>`,
COMPUTED from the row's own rule-id exactly as a `kind: DOC` row's §7 anchor is. `docs/CONFORMANCE.md` **§8**
is the register it points at, and both engines learned the rule in this one change set — `Schema.state_for` →
`Schema.derivation_stands` → `Derivation.refusals` on the Python side, `DerivedState` → `DerivationStands` →
`DerivationRefusals` on the C# side, over one parser per language now BOUNDED at the next `## ` heading (until
§8 existed, "read to end of file" and "read the section" were the same thing, and appending a second register
would have served every §8 row to `register_determinations` as an A.1 determination).

**The three arms, and what checks them.** `undefined-A.2` is mechanical: `scripts/spec/extract_annex_a2.py`
extracts Annex A.2's 66 items, parses each item's OWN trailing citation and resolves it against the rule catalog
into `tests/version-matrix/annex-a2-undefined.json`; the checker requires the named item to cover THIS row, so
naming a real item about a different rule is refused. `unpopulatable-antecedent` and
`indistinguishable-consequent` are reviewed arguments, shape-checked — the closed set must be STATED (≥20
characters; an em dash is refused) and the named rule must EXIST in the catalog and not be this one.
⭐ The A.2 list is a GENERATED artifact rather than a parse at check time for two reasons that both matter: the
C# gate would otherwise need a second markdown parser of the spec, and `EveryRowState_IsDerived_NotAsserted`
recomputes 4,311 rows every build. `--check` re-derives and diffs; `AnnexA2UndefinedListDriftTests` runs it.

**Six refusals, one predicate, two callers per side** — `record_verdicts.validate` prints them, `state_for` asks
only whether the list is empty: a spec-derived `test-ref` on the same row (the owner's explicit bound — the row
demonstrably HAS an observable obligation), a non-resolving verdict, a kind whose register determination is not
yet stated, an A.2 item that does not cover the row, a wrong or missing owner signature, and an anchor that is
not the computed one or that §8 has no row for. Every refusal carries a STABLE CODE, because two engines
refusing one row for two different reasons look identical under a boolean — the shape PB315 hid behind.

**⚖ PB280 Q2 is not reversed, and the coexistence is encoded by ORDER rather than by a special case.**
`state_for` charges a `kind: DOC` row's anchor and observability costs BEFORE it consults a derivation, so a row
whose only location is its §7 anchor still computes `GAP` with a perfectly valid derivation attached. Refusal 3
adds the other half: a DOC row §7 does not document may not carry a derivation at all. `DOC-A.1-19` is admissible
because its determination IS stated and it names implementing code — only its witness is impossible.

**Drift tests.** `TheDerivationRule_AgreesWithTheFixtureAndWithPython` drives
`tests/version-matrix/derivation-parity-cases.json` — 19 cases over a FABRICATED world — through the C# engine,
through the Python engine (shelled for real) and against the recorded expectation, comparing state AND refusal
codes; every code the evaluator can emit is driven by a case, and `audit_derivations.py --self-test` proves the
comparison itself can fail. `TheRowsClosedOnADerivation_AreTheEnumeratedPopulation` holds the population at the
eight rows measured before the door opened — the one deliberate hand list in the mechanism, so a ninth row is an
edit someone makes rather than a door that widened. `TheseChecks_ActuallyFail_OnAFabricatedInventory` gained the
refusal cases plus their positive controls.

**Two second arms found by sweeping** (`feedback_two_arm_dispatch`): `DifferentialOnlyCoverage` would have
reported every derivation-closed row as "closed on differential evidence alone", and `audit_annex_a1.check_pins`
keyed its §7-agreement demand on a spec-derived `test-ref`, so a derivation-closed A.1 row would have dropped out
of the check at the exact moment it started moving the burn-down. Both now ask the same closure predicate.
`audit_annex_a1`'s `DOC-A.1-<n>` token invariant also had to learn the second register — `DRV-DOC-A.1-19` is a
legitimate second occurrence — and its `--self-test` gained the pair that proves the widening did not blunt it: a
§8 row key is accepted, a prose mention beside it is still caught. `normalize_batch.ALLOWED` (a second copy of
`ADJUDICATED`) and `derive_verdict_batch`'s carried-field list would each have dropped the new field silently.

**The measurement.** `record_verdicts` accepted 8 of 8 submitted; **GAP 3054 → 3046**; CONFORMS-but-untested
**9 → 1**, the survivor being `DOC-A.1-93` = `PB383`, untouched here. The wave-local gate is 55/55 green.
