# PB747 — OPEN — one datum in two places, and only one of them is unambiguous

Found 2026-09-06 in the PB714 implementer's report (NEW DEFECT b), and hit independently the same day by PB713's
implementer. Verified against main (`89555b09`).

## The mechanism, verbatim

`scripts/spec/work.py:224`:

```python
HEADING_STATUS = re.compile(r"^#\s+\S+\s+—\s+(?P<status>[A-Z][A-Z\- ]*?)\s+—", re.M)
HEADING_ALIASES = {"closed": "landed", "fixed": "landed", "done": "landed"}
```

`check()` at `:269-275`:

```python
if (h := HEADING_STATUS.search(it.get("_body", ""))) is not None:
    spelled = h.group("status").strip().lower()
    meant = HEADING_ALIASES.get(spelled, spelled)
    if meant in STATUSES and meant != it.get("status"):
        bad.append(f'{it["_file"]}: heading says … but status is …')
```

with `STATUSES = {"open", "half", "landed", "owner", "blocked", "retired"}` (`:54`).

## ⛔ Premise correction — the report names the wrong slot, and the defect is still real

The report calls the matched field *"the CONSTRUCT field of a note's `#` heading"*
(`feedback_validate_the_premise_not_only_the_rule`: check what the construct can syntactically BE before
diagnosing). **Measured across the whole register**, 722 `kb/Work/PB*.md` notes:

- 281 headings carry a second dash-separated field at all; 441 have none.
- **217 of those 281 are a status word** — 137 `OPEN`, 73 `LANDED`, plus 11 dated `LANDED 2026-…` spellings and
  two `OPEN, BLOCKED ON THE OWNER…`.

So the slot is the **STATUS** slot by overwhelming convention, and `work.py` documents it as such in its own
comment three lines above the regex (`:219-223`): *"The `# PB45 — LANDED — …` heading writes the status a SECOND
time, beside the frontmatter."* The regex is not reading the wrong field. **The field's vocabulary collides with
COBOL's.**

## The collision set is exactly `{OPEN}` — measured, not assumed

`STATUSES ∪ HEADING_ALIASES` = `{open, half, landed, owner, blocked, retired, closed, fixed, done}`. Against
`tests/version-matrix/reserved-words.json` (462 words):

| word | COBOL reserved word? |
|---|---|
| **OPEN** | **yes** |
| CLOSED, DONE, FIXED, HALF, OWNER, BLOCKED, RETIRED, LANDED | no (`CLOSE` is reserved; `CLOSED` is not) |

So the report's hypothetical *"the check would also mis-read a heading whose construct were `CLOSED` or `DONE`"*
**does not fire** — neither is a COBOL word. `OPEN` is the whole of the collision, and it is simultaneously the
register's single most common heading status (137 notes). Two further properties of the regex, worth stating so
the fix is not over-built:

- The status group is `[A-Z][A-Z\- ]*?` — no `/`, so a heading field of `SORT/MERGE` never matches at all, and a
  multi-word construct like `DELETE FILE` matches the group but fails `meant in STATUSES`. Neither is affected.
- The failure fires **only on disagreement**. `# PB714 — OPEN — …` with `status: open` passes. It breaks the
  moment the note LANDS.

## Reproduced — through `check()`'s own code path, no scratch note left behind

Subject: main's own `kb/Work/PB714.md:21`, `# PB714 — OPEN — the "as if" OPEN that drops half of what it is as-if
of`, `status: open` today. The module was imported and `load()` monkeypatched so that the ONLY difference from
main is the frontmatter flip a lander performs:

```python
spec = importlib.util.spec_from_file_location("workmod", "scripts/spec/work.py")
m = importlib.util.module_from_spec(spec); spec.loader.exec_module(m)
real_load = m.load
def fake_load():
    its = real_load()
    for i in its:
        if i.get("id") == "PB714": i["status"] = "landed"   # what landing PB714 does
    return its
m.load = fake_load
rc = m.check()
```

```
HEADING_STATUS grp : 'OPEN'
⛔ 1 problem(s) in the work register:
      PB714.md: heading says 'OPEN' but status is 'landed' — a landed note that still reads OPEN is how the
      register lies to a reader (the frontmatter is what work.py next reads)
rc = 1
```

The checker's message is the tell: it asserts the heading is the stale copy. It cannot know that. On this note the
heading word was the SUBJECT.

## Why it matters

The check is right that the two copies disagree and structurally unable to be right about **which** copy is wrong,
because the heading word is ambiguous between a status and a construct name. The observed consequence is not a
false green or a wrong compile — it is that **the register's prose is being shaped by a regex**: PB714's heading
was reworded to `SORT/MERGE` to get past the check, PB713's implementer hit the same rule. Two independent agents
in one day is a rate, not an anecdote, and the cost lands on the note that is hardest to write well — the landed
one, which is the one a future reader opens.

⛔ It is `process_only` by the register's own definition, so **`work.py next` will not surface it**
(`feedback_measure_the_selectors_complement`; measured: `actionable()` returns 286 items on main and this is
not one of them). It reaches a lander through a register-hygiene pass, or through the next implementer who
tries to land a note about OPEN — which is how the last two found it.

## The fix shape

⛔ **The obvious first suggestion is a NO-OP and should not be implemented.** "Anchor the status word to the
heading's second dash-separated field" is precisely what `HEADING_STATUS` already does (`^#\s+\S+\s+—\s+…\s+—`
anchors to the H1, the id, and the first two em-dashes). It cannot help.

Two shapes that do:

1. ⛔ **Preferred — delete the second copy** (`feedback_one_rule_one_place`; the extraction IS the fix). `status:`
   lives in frontmatter; `work.py next` reads frontmatter; `kb/Work.base` reads frontmatter. The heading duplicate
   exists only so a reader opening the note sees the status first — which a `work.py` render, the Bases view, or
   a one-line frontmatter echo can supply. Drop `HEADING_STATUS` and the check with it, and no heading word can
   contradict anything ever again. It also frees the slot the notes are visibly trying to use: `# PB714 — SORT/MERGE — …`
   becomes legal, and so does `# PB714 — OPEN — …` meaning the statement.
2. **If the duplicate stays**, require the matched word to be in `STATUSES ∪ HEADING_ALIASES` **and absent from
   `tests/version-matrix/reserved-words.json`** — a mechanical register already in the repo, so the rule keeps
   holding as COBOL's word list moves and nothing is hand-maintained (CLAUDE.md rule 8). One set-membership test,
   and PB714 keeps its natural heading.
   ⚠ **It trades one blind spot for another**: it would stop checking every note whose real status word is `OPEN`
   — 137 of them today, the majority of all checked headings. That is why shape 1 is the answer and shape 2 is the
   fallback.

Either way, ⛔ **prove it fails once before trusting it** (`feedback_green_gates_arent_evidence`): flip a note's
frontmatter and watch the check go red, then flip it back.

## Sweep

Three other OPEN notes name holes in this same validator — [[PB265]] (it never asserts the frontmatter block IS
YAML), [[PB478]] (a note can land truncated and stay "well-formed"), [[PB720]] (it never reads `inventory_rows`,
and `load()` returns the ids still quoted). All three are cases of the checker **not looking**. This is the first
where the checker **looks and cannot tell what it is seeing** — a different failure, and the only one of the four
whose fix removes a rule rather than adding one.
