# PB5226 - the clock proof is keyed on the inputs that can change it

**Sites:** `scripts/self_test_clock.py` (`keys_proof`, `_handles_time`, `TIME_MODULES`, `DATED_RE`, `MECHANISM`, the module
docstring's THE CLOCK KEY, the `keys_proof` arms) · `scripts/self_tests.py` (`PASS_SCHEMA` 4, `PassStore.clock_proof`,
`PassStore.record`, `_key_changes`, `Runner.run_one`, `Runner._proof_key`, `Runner._clock`, `Runner._record`, the module
docstring's THE CLOCK PROOF, `fleet_arms`' clock-key arms) · `docs/rearchitecture/DESIGN-test-build-ci.md` §3.14.10
item 5 ("The clock key") · `docs/REARCHITECTURE_PLAN.md` (the self-test reuse paragraph).

## The measurement

The build-stage1 gate (`TestResults/build-local/000001-20261111T023340Z/gate.log`) ran 42 self-tests, 10,022 s summed
over each test's wall time. 28 of them were clock-proved: `Runner.run_one` ran each a second time with the clock moved
forward 400 days (PB4358), every time its PASS had to re-run. Those 28 took 6,419 s, about half of it the shifted runs.

The shifted run proves one thing: a fixture dated near the day it was written, compared with the wall clock, goes red now
and not on the day the clock passes it. Only code that reads the clock, does time arithmetic, or a fixture that carries a
date can change that answer. Yet `orchestrator/enqueue.py` (1,360 s), `orchestrator/land_lane.py` (652 s) and `gate.py`
(909 s) re-ran their shifted runs only because `inert_lane.py` and `buildgraph.py` changed, and neither imports a time
module (`keys_proof` answers False for both, True for the three). An analysis put the saving on that gate at about
1,460 s.

## The decision

The clock proof is its own record, keyed on a narrow input: the CLOCK KEY (`Runner._proof_key`), stored in the PASS
record as `clock.key` (a `Deps` shape) beside `clock.proved`, the moment the shifted run ran. `PASS_SCHEMA` goes from 3 to
4, so no record of the old shape is read as having a key.

The key holds, of the run's inputs:
- the self-test's own file, always;
- the proof's mechanism, `self_test_clock.py` (the shim) and `self_test_inputs.py` (the `sitecustomize` that installs it);
- every Python file that imports `datetime`, `time`, `calendar` or `zoneinfo` in any form, reaches the wall clock
  (`reads_wall_clock`), or names the shift variable;
- every PowerShell or bash script that reads a clock (`SCRIPT_CLOCK_RE`);
- every file that carries a date (`DATED_RE`: an ISO date, or a basic `20261111T023340` stamp);
- every input whose content cannot be read (absent, binary, a directory, a submodule);
- every directory a git command read whole (`content:` trees).
The runner's other files are left out, as `Clock.of` already leaves them out.

When a `--reuse` run (every gate's) must re-run a self-test because its PASS inputs changed, it runs the first run at
today's clock, derives the key from that run's own trace, and asks `PassStore.clock_proof` for a recorded proof under
exactly that key, inside its horizon. If there is one, the shifted run does not run; the console says `clock proof
reused: the shift of 400 days proved <when> holds until <day>, and none of its N clock input(s) changed`, and the new PASS
carries the reused proof's `proved` and `until` unchanged, so the 400-day limit still counts from the day the clock was
actually moved. If there is none, both runs run, as before, and the console names the clock inputs that changed since the
newest proof. Deriving the key after the first run means a file that starts doing time arithmetic in the change under
test is in the new key, and the shifted run runs.

A run without `--reuse` (CI, the Linux gate, a hand run) never reuses a proof and runs both, as before.

**Why a detector by import, not by call.** A window is defined where `timedelta` is imported, not where `now()` is called.
A detector that keyed only clock READS would miss a helper that holds the window and receives `now` as an argument. Keying
every importer of a time module over-approximates (`import time` for `time.monotonic` puts a file in the key) and costs
one shifted run; missing one would reuse a proof the edit changed.

## Residue, named

- A window length or a date defined in a module that imports no time module and carries no date literal
  (`RETAIN_DAYS = 90` in a constants module, compared with the clock by an unchanged module that does read it). An edit
  to it reuses a proof it may have changed.
- A date in a data file written in a form `DATED_RE` does not match (`11/10/2026`, an epoch number).
- The names in a directory listing (`entries:` and `paths:` trees are not in the key).

CI's merge group runs every self-test fresh, both runs, and is the backstop for all three.

## Proof

- `python scripts/self_test_clock.py --self-test` → `ALL GREEN`, with 12 `keys_proof` arms (a time import for a duration,
  date arithmetic with no clock read, a handed-in `now`, the shift variable, `inert_lane.py`'s shape, a dated fixture, a
  timestamped name, an undated file, a script with and without a clock, an unparsable dated `.py`, an unreadable input).
- `python scripts/self_tests.py --self-test` → `ALL GREEN`, with seven clock-key arms over a planted self-test that logs
  the shift of each of its runs: the recorded key holds its own file and its time helper, not its plain helper; an edit
  to the plain helper runs once (shifts `0`) and keeps the proof's `proved` and `until`; an edit to the time helper runs
  both (`0 400`) and names it; an edit to the self-test runs both; a plain helper that starts importing `time` runs both;
  a run without `--reuse` runs both; an expired proof under an unchanged key runs both and says it ended.
- Measured on the real tree with a private PASS store: `scripts/spec/work.py --self-test` fresh, both runs, 2.6 s, 36
  input files, 25 in its clock key; after an edit to `scripts/arch/source_units.py` (outside the key), the `--reuse` run
  was GREEN in 0.7 s with `clock proof reused`.
