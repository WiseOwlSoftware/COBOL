# R69 — the completion plan's three decisions (owner, 2026-10-06)

The owner asked how Mythos 5.1 should be used to plan the compiler's completion, then decided on the evidence below.

## 1. The legacy engine is deleted now, decoupled from v1.0

**Owner:** "I'm not convinced the legacy engine provides any real value anymore." Then: "Yes, delete the legacy now
decoupled from v1.0."

**Evidence measured 2026-10-06 (main `e36c9c9da`):**
- The one purpose it was kept for (DEVLOG 997, owner 2026-07-22: "stop gating, keep engine" for the P14 guard-equivalence
  proof) dissolved on 2026-09-06 when PB750 pointed the guard at the greenfield compiler. The guard runs 364 NIST
  programs through `cobol` in every CI run and every local Linux gate. `scripts/equivalence-proof.sh` and
  `docs/rearchitecture/EQUIVALENCE-PROOF.md` were never created and nothing needs them.
- Its only build-graph edge into the greenfield tree is `tests/Cobol.Net.Tests.Conformance.csproj` lines 34–35 (two
  `ProjectReference`s for the `LegacyCompiler` oracle, used only under `COBOLNET_DIFF_MODE=verify`), plus an
  `InternalsVisibleTo` in `Cobol.Net.Frontend.csproj`. No `src/Cobol.Net.*` source names a legacy type.
- The nightly bake-verify job re-proves 364 baked goldens against a live legacy run: green on every recent night, and
  it can only report that a spec-derived golden differs from the frozen engine, which is not actionable.
- The legacy unit and integration suites (1,199 + 504 tests, 32 s) run in CI's Guard job and every Linux gate and have
  caught zero product defects since July. They cost one dropped train (PB655: a legacy-only red) and one CI red
  (the legacy-divergent exemption misreading PB322's rows, DEVLOG 1838 era). PB1861 exists only because the legacy
  exists.
- It blocks D10 (the SUBSCRIPT lexer mode and about 250 lines of hand-rolled re-parsers), forces the shared grammar
  to stay additive-only, keeps two diagnostic descriptors alive, and is named by 14 greenfield test and script
  files, 6 guard scripts and 27 docs.
- The §11 gates the P15 text names as preconditions do not need it: A3 landed; A4 is the GnuCOBOL corpus, already in
  use with 1,323 groups; A5 never mentioned it; A6's benchmark is better served by GnuCOBOL and the self-relative R0
  baseline (PB2117).

**Consequences:** P15's Cuts 1 and 2 and Cut 2.5 (D10) run now as the `PB2108` cluster (PB2108–PB2114). v1.0 keeps
Cut 3 (the runtime namespace flip) and the §4.2.16 conformance documentation. D14's "v1.0 = the P15 exit" is
amended accordingly in plan §6; DEVLOG 997's "keep engine" is superseded.

## 2. R64 is split: the architecture review starts its measurement and design now

R64 (2026-09-30) started the review only after zero GAP. The remaining 173 GAP rows land in the god classes
(48 rows in §14.9 procedure statements, 22 in §13.18 data description, 14 in §12.3 environment division), so every
fix landed before the split enlarges the extraction, and the forgotten-arm dispatch — the most reproducible defect
shape here — is structural. The owner accepted the split:
- **Now:** R0 (census PB2115, oracle capture PB2116, performance baseline PB2117) and R1 (the target architecture,
  PB2118), so the external-repository slices PB2097–PB2104 and the remaining fixes are written INTO the target layout.
- **Between fix-lane trains, in partitioned subsystems:** R3 leaf waves (runtime values, editions, front-end layout)
  and the Delete waves (PB2119).
- **After GAP is near zero (R64's substance kept):** R2 and R3 over binding and code generation, where the fix lane
  lives.
- R1 takes the approved §8.13 external-repository design as given, never reopened.

## 3. Dead and obsolete code removal is mandated

**Owner:** "Included in the plan must be removal and deletion of dead/obsolete code." The review gains a fifth wave
kind, **Delete**: a census-measured (never deduced) dead member, file, script, doc or scaffold is removed with every
caller, under the §4 neutrality contract. PB2119 is the program; the legacy engine is its first and largest item.

## 4. Models

- **Mythos 5.1** is Fable-tier ($10 / $50 per MTok against Opus's $4 / $20) and follows the Fable rule: explicit
  owner approval per dispatch, never a default, never standing. Its one planned use is R1's authorship (and a second
  adversarial round only if Opus cannot break the design). MANDATORY-PRACTICES P1 says so.
- **Opus:** the retirement cuts (CI and gate scripts carry the CI invariant), R0 tooling, R1's refuter, R2
  reviewers, extract and unify waves, landers, refuters.
- **Sonnet:** census runs, the prose and register sweep, the solution rename, move-and-rename and analyzer waves
  driven by a Roslyn rewriter, Delete waves whose reachability the census has already measured. The oracle proves a
  mechanical wave; the model does not.
- `scripts/orchestrator/model_rules.json` routes `^build/(ci|legacy)` and `^architecture` to Opus; the defect fix
  lane is unchanged.
