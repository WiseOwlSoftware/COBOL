# PB5202 - at --std 85 a report file with a CODE-SET clause takes report items that are not SIGN SEPARATE or not DISPLAY: CheckCodeSetRecordItemsPass walks only FileModel.WrittenRecords, which a report file has none of

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/Passes/CheckCodeSetRecordItemsPass.cs` (`Run`, `CheckCodeSetRecordItem`)
- `src/WiseOwl.Cobol.Compiler/Binding/Model/FileModel.cs` (`WrittenRecords`)

**Mechanism.** §1985:VII.3.4.3 SR1: with CODE-SET, "all data in that file must be described as USAGE IS DISPLAY and any signed numeric data must be described with the SIGN IS SEPARATE clause", and the Report Writer file description takes its clauses' rules from the sequential ones. `CheckCodeSetRecordItemsPass.Run` walks `FileModel.WrittenRecords` only, the 2023 wording's record description entries, and a report file has none, so the report group items that describe the file's data are never screened: a signed PIC S9(4) report item without SIGN SEPARATE compiles at --std 85 and writes an over-punched sign.

**Found by.** The 1985 code read (2026-11-10; its records are `E:/COBOL-coord/scratch/coderead-85/for-register.json`): each rule below was read against the code sites it names and probed at `--std 85`, and found non-conforming. Verdict, harm, evidence, repro and observed text are the records'; the rows' verdicts are recorded on another branch.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids of the list below.

Checked: §1985:VII.3.4.3 SR1: "If the CODE-SET clause is specified for a file, all data in that file must be described as USAGE IS DISPLAY and any signed numeric data must be described with the SIGN IS SEPARATE clause.". Code sites read: src/WiseOwl.Cobol.Compiler/Binding/Passes/CheckCodeSetRecordItemsPass.cs#Run; src/WiseOwl.Cobol.Compiler/Binding/Passes/CheckCodeSetRecordItemsPass.cs#CheckCodeSetRecordItem; src/WiseOwl.Cobol.Compiler/Binding/FileControlBinder.FileSection.cs#BindCodeSetClause; src/WiseOwl.Cobol.Compiler/Binding/Model/FileModel.cs#CodeSetRecordClass; src/WiseOwl.Cobol.Compiler/Binding/Model/FileModel.cs#WrittenRecords. Code read: No kb/Work note owns the fix. §1985:VII.3.4.3 SR1: "If the CODE-SET clause is specified for a file, all data in that file must be described as USAGE IS DISPLAY and any signed numeric data must be described with the SIGN IS SEPARATE clause." Implemented at 85 for a file with record description entries: BindCodeSetClause records on FileModel.CodeSetRecordClass that the FD carries the clause, and the pass CheckCodeSetRecordItemsPass.Run, placed after sign and usage inheritance and with no edition arm, walks every written record through CheckCodeSetRecordItem and refuses with COBOL1672 each elementary item that is not usage DISPLAY and each signed numeric item whose effective SIGN clause is not SEPARATE. Probed at --std 85 beyond the witness (PIC S9(4) with no SIGN clause): SIGN LEADING and SIGN TRAILING without SEPARATE, a signed 01 elementary record, COMP, BINARY, PACKED-DECIMAL, a group USAGE COMPUTATIONAL, USAGE INDEX (elementary, level 01 and from a group), a second record, a REDEFINES item, an item under OCCURS and unnamed FILLER items are refused under STANDARD-1, STANDARD-2 and NATIVE alphabets; SIGN SEPARATE written on the item or on a containing group, unsigned numeric, alphabetic and edited items are accepted. Not implemented: a report file. Run walks FileModel.WrittenRecords only, and a report file has none (§1985:XIII.3.2.3 SR4), so the Report Section entries that describe the file's data are never screened; the pass follows the 2023 wording, which limits the rule to record description entries, where the 1985 rule covers all data in the file (the change record says so). The Report Writer file description entry prints the CODE-SET clause and takes its rules from this clause (§1985:XIII.3.2.4 GR3: "With the exception of the REPORT clause, all clauses within the file description entry for a report file shown on page XIII-7 are presented within the Sequential I-O module beginning on page VII-22."). So at --std 85 a report file with CODE-SET whose printable item is PIC S9(4) with no SIGN clause compiles, and the report line carries the over-punched sign character on a medium the clause says is converted.

**Expected (from the 1985 text, the record's).** A diagnostic at the printable item of line 22 (COLUMN 6 PIC S9(4) SOURCE IS WS-AMT) and no run: §1985:VII.3.4.3 SR1 "If the CODE-SET clause is specified for a file, all data in that file must be described as USAGE IS DISPLAY and any signed numeric data must be described with the SIGN IS SEPARATE clause.", which §1985:VI.5.12.3 SR3 restates ("If the CODE-SET clause is specified in a file description entry, any signed numeric data description entries associated with that file description entry must be described with the SIGN IS SEPARATE clause."). The item is signed numeric data of the report file RPT-FILE and no SIGN clause applies to it (§1985:XIII.3.17.4 GR2: such an entry "has an operational sign, but neither the representation nor, necessarily, the position of the operational sign is specified by the character 'S'").

**Observed (the record's).** exit 0, no diagnostic; the program displays OK and the report file holds the line 'AMT  001K' (the sign over-punched on the last digit). With SIGN IS LEADING SEPARATE written on the item the line is 'AMT  -0012'. The same record item in a record description entry (01 R. 05 S PIC S9(4).) under the same FD clause is refused with COBOL1672.

**Fix direction (root cause, CLAUDE.md rule 4).** Have the pass walk every description of the file's data, the report groups of a report file included, at the editions whose rule covers all data in the file.
