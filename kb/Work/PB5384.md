# PB5384 - SEND's identifier-2 (one-character unsigned integer) and identifier-3 (integer) checks accept a reference-modified numeric item, which is alphanumeric, and identifier-2 accepts a two-digit LINAGE-COUNTER: CommunicationBinder.IsIntegerItem reads the base item's PICTURE through the reference modification and answers true for every computed operand

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CommunicationBinder.cs#IsIntegerItem`
- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CommunicationBinder.cs#BindSend` (identifier-2, COBOL6171) and `#ScreenSendAdvancing` (identifier-3)

**Mechanism.** `IsIntegerItem` takes the PicInfo of the item behind a `RefModPlace`, so `I9 (1:1)` looks like an unsigned integer. It also answers true for any `BoundComputedOperand` without applying the one-character test, so LINAGE-COUNTER of a `LINAGE IS 60` file passes as identifier-2. kb/Work PB5289 (landed) closed the 9P, index and symbolic-character arms; PB5343 is the 2002 wording of the diagnostic.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids below. Its rows are recorded PARTIAL naming this note.

**Rules (2 claimed; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-SR-XIV.3.6.3-2` - `§1985:XIV.3.6.3 SR2` (read: PARTIAL, harm: under-rejects): "Identifier-2 must reference a one-character integer without an operational sign." LINAGE-COUNTER's description "is that of an unsigned integer whose size is equal to the size of integer-1" (`§1985:VII.1.3.7`).
- `1985-SR-XIV.3.6.3-3` - `§1985:XIV.3.6.3 SR3` (read: PARTIAL, harm: under-rejects): "Identifier-3 must reference an integer data item." Reference modification makes "the categories numeric, numeric edited, and alphanumeric edited are considered class and category alphanumeric" (`§1985:IV.4.3.8.4.4 GR5`).
