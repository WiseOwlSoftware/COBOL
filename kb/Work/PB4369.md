# PB4369 - The procedure-name drift scan misses two forms of read

**Sites:** `tests/WiseOwl.Cobol.Tests.Unit/ProcedureNameReaderDriftTests.cs` (the name-binding scan, line 40 at the filing; the self-test `TheScanSeesEveryFormOfRead`). The file lands with PR #965 (PB4277, queued, not on main at filing).

The scan binds a name to the `procedureName()` accessor only from typed parameters, typed locals, `foreach` variables, patterns and accessor-initialized declarators. Two reads escape it: an untyped lambda parameter over the accessor (`x.procedureName().Select(n => n.GetText())`) and a LINQ element call (`x.procedureName().First().GetText()`). A glued `GetText()` through either is the PB4252 defect and the scan would pass it, while the self-test's name claims every form is seen.

PB4252's general glued-`GetText()` test may generalize this scan (it is per node type here); if PB4252 lands that test first, this note closes into it. Otherwise: bind lambda parameters and LINQ element calls, and add both forms to the planted self-test.
