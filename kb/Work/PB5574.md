# PB5574 - the 2002 inventory to zero: decisions, stages, measures

**The owner's rule (2026-11-14):** "2002 spec covers 2002 rules. It should not matter to the 2002 rules whether or not 2023
removes/adds/changes a clause. That only affects 2023 rules."

**The decisions.**

1. **A 2002 rule is judged on the 2002 text, run at `--std 2002`.** The 2023 row is a pointer to the code that
   implements the rule and to candidate tests. It is never the authority. A row closes on evidence produced at its own
   edition. What a 2002 rule governs is what the 2002 clause says it governs, whatever 2023 later did to the clause.

2. **No edition is linked between 1985 and 2023, ever.** Every older held edition's change record names the newest held
   edition (2023), as a pointer. Holding an edition never re-targets another edition's records. Adjacent deltas are
   derived by composing two direct records into the same 2023 rule, and a drift script lists contradictions (a 1985
   record and a 2002 record into one rule that disagree).

   Why: linking 2002 would refuse all 2,260 1985 records. 648 of the 1,180 2023 rules that 1985 KEPT records reach
   could be composed by script; about 1,400 records would need judgment, and up to 1,373 closed 1985 rows would reopen
   meanwhile. Linking 2014 later would refuse every 2002 record. Neither closes a row. With direct chains, each of the
   four per-edition compilers is validated against its own edition, and no edition's GAP waits on, or inherits errors
   from, a neighbour.

   Follow-up (the tooling note filed beside this one, PB5583):
   - DESIGN-spec-conformance-review.md §10.2 and §10.4 state this design;
   - `Edition.linked`, the schema's `linked` key, `link_errors`' linking clause and the C# reading of it are deleted;
   - `next_held` of every older edition is the newest edition;
   - a chain proves its band at its own edition only (`lineage.spanned` / `chain_bands`).

3. **Every word-identical pair is read; a script only flags.** Deciding word-identical pairs by script failed two blind
   samples: 16 of 100 were wrong in the first, 13 of 100 wrong plus 3 doubtful in the second. A rule's words can be the
   same while the clause it sits in governs more in 2002 than the 2023 clause does (the communication section is the
   commonest case), so identical words do not show identical scope. Therefore:
   - a reader reads the 2002 clause, the 2023 row and any changed pending clause it names, and decides whether the
     existing evidence covers the 2002 rule;
   - an independent refuter attacks every "covered" verdict;
   - the screen (PB5589, `scripts/spec/lineage_screen.py`) only flags pairs for the reads; a change record comes only
     from an audit state, written by the one writer for every older edition.

   The 89 pending clauses are NOT adjudicated first. Their disposition decides the denominator (PB5456), not the meaning
   of a paired rule.

4. **Evidence for a row** is evidence produced at its own edition. Where the reader finds the existing evidence covers
   the 2002 rule, the record says so and names the evidence. Where it does not, the row needs its own 2002 evidence: a
   probe or witness run at `--std 2002`. A 2023-derived witness run at 2002 shows only that the compiler agrees with
   itself (review F2), and is evidence only where an edition gate sits on the rule's path. The widened cases that pass
   at 2002 (404) land as regression coverage. The 91 refused for an unrelated newer construct are reverted and need no
   2002 twin.

5. **Documented non-support** is recorded CHANGED, with the reason that the conformance requirement differs
   (§2002:3.1 against §2023:A.4.x), and its own 2002 verdict. A record that rests on a 2023 licence cannot carry a 2002
   one.
   - **Screen handling** (127 rows) is licensed by §2002:3.1.5 and B.3 item 1, and is recorded DOCUMENTED-NON-SUPPORT
     (PB5581).
   - **A.3 processor-dependent** (5 rows) holds only where B.3 lists the element.
   - **No licence** for VALIDATE (54 paired rows, PB5577), FORMAT and SELECT WHEN file handling (22, PB5578), REWRITE
     FILE and WRITE FILE (5, PB5579), and the OO optional items (1, PB5580). §2002:3.1.1 requires every element
     outside Annex A and the processor-dependent list. These rows are NOT-IMPLEMENTED until the features are built at
     `--std 2002`. I decide to build them.

**What the reads have measured so far.** Of the first 474 pairs read:
- 263 are covered by the existing evidence;
- 206 need their own 2002 evidence. On 138 of the readers' 156 findings a probe showed the compiler correct at
  `--std 2002`, so the work for those is the witness, not a fix;
- 5 are undecided and go to an adjudicator.
