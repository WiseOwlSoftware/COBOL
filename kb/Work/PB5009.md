# PB5009 - a drafts pass recorded under account1 cannot run with the one-key file

**Found.** Wave 20261931 group a. PB4916 made a run keep the account its record names (`api_key.read_run_key`): a
batch belongs to the account that created it, and a key that resolves to another account is a RuntimeError naming the
record. The drafts pass's state in `state-route/drafts` records `account1`; the key file the host now has holds ONE key
whose label names no account, so `read_run_key` cannot resolve `account1` and refuses. The 35 grown drafts cannot be
submitted.

**Owner action.** Label the key with the account it belongs to (or say which account it is); then no code change is
owed. If the owner decides the single unlabeled key is always the run's account, `read_api_key` takes a lone key as
every named account, which PB4916 deliberately refused (a wrong-account bill); that is a decision, not a fix.

**Sites:** none (an owner action on the key file; `scripts/api_key.py#read_run_key` already refuses correctly and changes only if the owner decides otherwise)
