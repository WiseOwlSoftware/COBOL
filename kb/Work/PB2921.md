# PB2921 — the factory suffix is not injective

Filed 2026-10-10 by the train 1052 lander (phase 1b) from the wave 1051 B implementer's report
(`E:\COBOL-coord\scratch\reports\w1051b-PB2843-report.md`, "New defects" item 2).

**Rule.** §8.3.2.1: a COBOL word may contain hyphens anywhere but first or last ("The hyphen or underscore shall not
appear as the first or last character in such words"), so `X--FACTORY` is a legal class-name.

**Where.** PB2839 (landing in train 1052) made the word-to-identifier mapping injective
(`DataItem.IdentifierCharacters`, `src/Cobol.Net.Compiler/Binding/Model/DataItem.cs`): `-` becomes `_`, so
`X--FACTORY` becomes `X__FACTORY`. The factory class of a class `X` is named `X` + `NamingConvention.FactorySuffix`
(`src/Cobol.Net.Compiler/Oo/NamingConvention.cs`, line 21: `"__FACTORY"`), also `X__FACTORY`.
`OoClassTable.Build` adds the factory name to `usedCsNames` and ignores the result
(`src/Cobol.Net.Compiler/Oo/OoClassTable.cs`, about line 355, commented "belt-and-braces (a `__` name cannot collide
with COBOL-derived names)"), and `docs/COBOLNET_OO_SLICE_BRIEFS.md` (Naming safety, about line 39) states the same false
premise.

**Repro (to write).** A compilation group with `CLASS-ID. X.` (with a FACTORY paragraph) and `CLASS-ID. X--FACTORY.`:
expected to compile and run; observed CS0101 (the namespace already contains a definition for `X__FACTORY`).

**Fix shape.** The tagged families (`__FACTORY`, `__Instance`, `__New`, ...) must be outside the image of the word
mapping: either the mapping escapes a doubled `-` (so no word yields `__`), or the suffix carries a character the
mapping never emits; then `usedCsNames.Add` failing is an internal error, not ignored. Correct the slice brief's
"Naming safety" paragraph in the same change, and add the pair to `IdentifierInjectivityTests`.

## Landed 2026-10-12 (w1069 B)

Re-probed on the wave's build (ddee217e3): the compilation group with `CLASS-ID. X.` and `CLASS-ID. X--FACTORY.` was
refused COBOLNET0820 "duplicate class definition 'X--FACTORY'" (X's factory name `X__FACTORY` was already in
`usedCsNames`), plus COBOLNET0825 on the INVOKE of the second class. Root: a SUFFIX appended to a word-derived
identifier is inside the image of the word mapping (`-` is written `_`), so `__FACTORY` was never safe; only a name
that BEGINS with `__` is (§8.3.2.1 bars a hyphen or underscore first, so no identifier begins `__`).

Fix: the factory class is the prefix family `NamingConvention.FactoryClassName` (`__FACTORY_X`; the runtime's
`CobolNet.Runtime.__FACTORY_BASE`, PublicAPI renamed), routed through every site (`OoClassSymbol.FactoryCsName`,
`ObjectRefDescriptor.ClrTypeName`, `OoEmitter`'s three INVOKE renderings through one `FactoryClassOf`, and the emitted
`__FactoryOfClass` override through `OoStandardClasses.BaseFactoryCsName`). `OoClassTable.Build` adds the factory name
after the class's own name and treats a failure as an internal error. Both families join
`NamingConvention.CobolWordDerivedPrefixes`, so `SynthesizedNameFamilyDriftTests` now holds every emitter literal out
of them. Sibling (same mechanism): the CS0542 rename of a METHOD-ID spelled like its CLASS-ID was the suffix `_M`
(`X_M`, the identifier of the method-name `X-M`); it is now the prefix family `NamingConvention.ClassNamedMethodName`
(`__method_X`), and the factory roster's "unreachable" `__FACTORY` + `_M` guard is deleted (its enclosing type is a
family no method-name spells). Docs: COBOLNET_OO_SLICE_BRIEFS "Naming safety" corrected; OO / design docs respelled.

Witnesses: `tests/conformance/2002/pb2921_factory_named_class` (X and X--FACTORY, each factory its own data);
`IdentifierInjectivityTests.NoIdentifier_BeginsAWordDerivedFamily_SoNoClassNameSpellsAFactoryClass` and
`TheRuntimeBaseFactory_IsTheConventionsNameForBase`. Every OO positive golden (244) re-run on the build: all pass.
