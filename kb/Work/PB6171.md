**Found 2026-11-24** while preparing R2's next batches on the new pin 9e65164eb (kb/Work
PB2911/2026-11-24-owner-releases-the-defect-hold.md). `python scripts/arch/r2_inputs.py --pin <pin> --out <dir>` stopped
at its first project:

```
the analyzer build of WiseOwl.Cobol.Editions failed (exit 1):
CSC : error CS0006: Metadata file '...\src\WiseOwl.Cobol.Analyzers\bin\Release\netstandard2.0\WiseOwl.Cobol.Analyzers.dll' could not be found
```

**The cause.** The analyzer step builds each project alone with `--no-incremental`, in the order `PROJECT_ORDER`, a
hand-written list of 12 projects. The solution has 14 projects. `WiseOwl.Cobol.Analyzers`, which every project
references as an analyzer, and `WiseOwl.Cobol.Listing` were both added after the list was written. So:
- `Editions` was built before the analyzer it references;
- `Listing` would never have been measured, and its shards' inputs would have stayed PENDING for ever.

**The fix (root).** `project_order(tree)` computes the order from `WiseOwl.Cobol.sln` and each project's
`<ProjectReference>`s, as a topological sort. It refuses a cycle, and it refuses a reference to a project outside the
solution. A project added later is then built in its place without anyone editing a list. The self-test plants a
four-project solution whose analyzer project no list names: the analyzer is ordered first, and a cycle is refused.

**The second cause, found by the fixed order.** With the analyzer project first, the next project failed the same way.
The tool's warm-up build compiled the SOLUTION. In a solution build, MSBuild gives every in-solution reference the
solution's configuration, so the analyzer that every `src` project references with `SetConfiguration=Release` was built
as Debug only. The analyzer step builds each project ALONE, where `SetConfiguration` applies, so it read `bin/Release`,
which did not exist.

This was reproduced in a fresh detached worktree at 9e65164eb: the solution build printed only
`WiseOwl.Cobol.Analyzers -> ...\bin\Debug\...`. The warm-up now builds each project alone, in `project_order`, so every
reference is built where the analyzer step reads it.

The old pin (cd85e49017) predates the analyzer project, which is why batches 1 to 5b never met either cause.

**Sites:** `scripts/arch/r2_inputs.py` (`project_order`, `analyzer_worktree`, `build`, `self_test`)
