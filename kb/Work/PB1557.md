# PB1557

Found 2026-09-24 by the golden-lane-2 misc-p30 writer (pin f0d582ccd); **re-probe first**.

Repros: `<scratchpad 9db39f61…>\gl\held\misc-p30\tests\conformance\2002\l1c30_full_alphabet_in_ordinals.cob` (rejects legal source) and
`<scratchpad 9db39f61…>\gl\held\misc-p30\tests\conformance\2002\l1c30_full_alphabet_char_ord_probe.cob` (wrong answer). `65535 THRU 1` works; `65536 THRU 1` wraps.

Code site: `src/Cobol.Net.Compiler/Binding/…/DataBinder.Switches.cs:1298` (`ushort next`) → `CollatingTable.Build`.
Fix: count ordinals in a type that holds the alphabet's full size (the native bound is 65,536 characters, ordinals
1…65,536); sweep every ordinal/count variable on the collating path (CHAR/ORD runtime, SYMBOLIC CHARACTERS, CLASS IN)
for the same 16-bit assumption. The two rows' refs to record once fixed are in the misc-p30 report's row notes.

**Sibling site (w59b implementer, not probed):** `DataBinder.Switches.cs:1533` runs `int.TryParse(text)` on an ALPHABET
literal ordinal, so an 11-digit ordinal falls into a different branch — the same 'ordinal counted in a too-narrow host
type' family on the collating path; fix both together.

## Landed — wave 59 group K (with PB1558)

Re-probed on the w59k build first: both repros reproduced exactly as filed (COBOLNET1671 + COBOLNET1670 on
`l1c30_full_alphabet_in_ordinals`; `CHAR-65471=" "` / `RT66=65504` on the CHAR/ORD probe).

**Root.** An alphabet that names every native character has 65,536 positions — legal, since §12.3.7.3 SR14 b4/c4
bound the count with "shall not exceed" — and the position COUNT is one more than a 16-bit counter holds.
`AlphabetLiteralPhrase` counted in a `ushort next`, and `CollatingTable.Build` took a `ushort nextFree`, so the
count wrapped to 0 and the table claimed an empty specified block. The positions themselves (0 … 65,535) do fit
16 bits, so the stored arrays stay `ushort[]`; the COUNT and the builder's position map are `int` now
(`DataBinder.Switches.cs#AlphabetLiteralPhrase`, `ImplementorCodeNames.cs#SingleByteCodePage`,
`CollatingModel.cs#Build`), and `Build` ASSERTS its invariants (count 0 … 65,536, one representative per position,
every position inside the block) so a builder that miscounts fails in the compiler, never in a user's program.
The runtime carrier (`LiteralPhraseCollation`) already held `int nextFree` — it was never the wrong arm.

**Sibling (same family — an ordinal read through a too-narrow host type).** Both readers of a SPECIAL-NAMES
ordinal used `int.TryParse`: the literal-phrase decoder (`LiteralPhraseOperand`, ALPHABET SR14 b1/c1 and CLASS
SR17 b2/c2) sent an 11-digit integer ordinal to the NONINTEGER literal's class rule (SR14 b2 / SR17 b3), and
`SwitchBindSymbolic` `continue`d SILENTLY — `SYMBOLIC CHARACTERS S1 IS 12345678901` compiled with no diagnostic
(measured on the pre-fix main build). The decision is now taken from the PARSE (`IntegerLiteralDigits`: an
integer literal, signed or not) and the value from ONE saturating reader (`OrdinalValue`), shared by both
clauses; a noninteger numeric literal (1.5) still takes the class rule, as kb/Work PB770 adjudicated.
