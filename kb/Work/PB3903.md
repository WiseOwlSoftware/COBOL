# PB3903 — picture-implied-from-value-required--national-format-literal: cobc 3.2: FORMATTED-DATE with a national format literal (N"YYYYMMDD") rejected as "invalid date/time format"

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S5) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\picture-implied-from-value-required--national-format-literal.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\picture-implied-from-value-required--national-format-literal\`.

## Summary

cobc 3.2 refuses `FUNCTION FORMATTED-DATE(N"YYYYMMDD", 1)` with "FUNCTION 'FORMATTED-DATE' has invalid date/time
format". The standard allows argument-1 to be a national or an alphanumeric literal (the function is then of type
national); the alphanumeric spelling of the same format compiles and prints `16010101`. cobc stores a national literal
as UTF-16 bytes and validates those bytes as if they were an alphanumeric format string.

## Minimal test case

Free reference format (`-fformat=free`), `records/picture-implied-from-value-required--national-format-literal.cob`:

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. FDNAT.
PROCEDURE DIVISION.
    DISPLAY FUNCTION FORMATTED-DATE(N"YYYYMMDD", 1)
    STOP RUN.
```

## Expected result (per ISO)

ISO/IEC 1989:2023 §15.39, each citation checked with `scripts/spec/cite.py --check`:

- §15.39.3 rule 1): "Argument-1 shall be a national or alphanumeric literal." Rule 2): "The content of argument-1 shall
  be a date format."
- §15.39.1: "The type of this function depends on the type of argument-1" (national argument, national function).

`N"YYYYMMDD"` is a national literal whose content is the date format YYYYMMDD; integer date 1 is 1601-01-01. Expected:
compiles; the function returns the national string `16010101`.

Edition: FORMATTED-DATE with the same argument rule 1 ("Argument-1 shall be a national or alphanumeric literal.") is in
the ISO/IEC 1989:20xx CD 1.2 (2009-08-23) that led to 2014 (its 15.35), and national literals are a 2002 feature, so
the program is legal under the edition `-std=cobol2014` claims.

Edition as recorded by the adjudicator: 2014. `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Fix site (GnuCOBOL 3.2 source, read observationally)

- `cobc/scanner.l`, function `read_literal` (lines 1522-1544): a national literal's characters are widened to UTF-16
  ("poor-man's conversion iso-8859 -> utf-16"), so the first byte of `N"YYYYMMDD"` is NUL.
- `cobc/tree.c`, function `try_get_constant_data` (line 976) returns that literal's data as a `char *`, and
  `valid_const_date_time_args` (line 990) passes it to `valid_format` / `cob_valid_date_format`, which read a C string
  that is empty at its first byte and reject it (error at line 1001).

A fix narrows a national literal to its character form before validation (and the run-time FORMATTED-DATE then needs
a national result).
