# PB3695 — plan_wave.partition_summary counts every parenthesised token of a hold reason as a colliding file, so PB3670's measurement lists branch names and note ids among the most-named files

**Sites:** `scripts/orchestrator/plan_wave.py` (`plan`, `collision_hits`, `file_set_collisions`, `partition_record`, `partition_summary`, `main`), `scripts/orchestrator/test_plan_wave.py`, `docs/rearchitecture/DESIGN-orchestrator-loop.md`.

PB3670's item 5 measurement (`partition_summary`) extracts every `(token)` from a hold reason. Real owner labels carry parentheses too (`worktree <name> (<branch>)`, `dispatched <slug> (PB547)`), so the most-named list is polluted: a reason for owners `worktree wf_x (worktree-wf_x) [RUNNING]` and `dispatched w9a (PB547) [...]` on `src/A.cs` gives `src/A.cs x2, PB547 x1, worktree-wf_x x1` (expected `src/A.cs x2`). The self-test's owner `worktree w [IN FLIGHT]` has no parenthesis, which hides it. Record the colliding files structurally in `held_by_collision` instead of parsing prose.

## Landed (2026-10-25, fix-lane wave 20261107 group C)

**Re-probe.** `partition_summary` took every `(token)` of a hold reason as a file; with real owner labels
(`worktree wf_x (worktree-wf_x)`, `dispatched w9a (PB547)`) the most-named list held branch names and note ids.

**Fix.** The colliding hits are data: `collision_hits(mine, busy)` returns (owner, hit) and `file_set_collisions` renders
the prose from it; `plan` returns `collided` ({note: [hit per owner]}); `partition_record` records it as `collided_on`
beside the prose `held_by_collision`; `partition_summary` counts `collided_on` and sorts ties by name. Nothing parses
prose any more. Records written before this change have no `collided_on` and contribute their hold count only.
**Test.** The self-test's owners now carry parentheses; the summary names the file and member and neither the branch nor
the note.
