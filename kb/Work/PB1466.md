## The rule (every citation re-run by the registrar through `cite.py --check`)

> consists entirely of a valid representation for the usage

`python scripts/spec/cite.py --check 8.8.4.4.4 "…"` → `OK  §8.8.4.4.4 3) d) 2.  (General rules)`

## Finding — `simple-class-condition` (wrong-answer; rows `GR-8.8.4.4.4-L2.1`)

**Mechanism.** RenderClass folds IS NUMERIC to the constant `true` for every numeric leaf that isn't windowed. But PACKED, BINARY and USAGE NATIONAL numeric leaves are never promoted to StoreAsImage. Content reaching them through an image boundary (a group MOVE, READ, or BY REFERENCE linkage) is normalised or truncated by ParseImage, so invalid or out-of-PICTURE-range content reports NUMERIC.

**Repro.** 01 G2. 05 G2B PIC 99 COMP.  01 G5. 05 G5P PIC 9(3) COMP-3.  01 G1 GROUP-USAGE NATIONAL. 05 G1N PIC 9(3) USAGE NATIONAL.  MOVE X"96" TO G2. IF G2B IS NUMERIC ...  MOVE X"ABCD" TO G5. IF G5P IS NUMERIC ...  MOVE N"AB1" TO G1. IF G1N IS NUMERIC ...  Also: READ an ORGANIZATION SEQUENTIAL record whose 05 FP PIC 9(3) COMP-3 holds X"ABCD", and CALL USING a PIC X(2) VALUE X"ABCD" into LINKAGE 01 LP PIC 9(3) COMP-3. Probes are under scratchpad adj-d2/out/probe/simple-class-condition/p2,p3,p5,p6.cob.

**Expected from the spec.** All five are FALSE. The binary value 150 is outside the 0..99 range implied by PICTURE 99, and the packed nibbles A/B/C are not a valid representation for the usage (§8.8.4.4.4 GR3 n)1.c: 'consists entirely of a valid representation for the usage and, if a PICTURE clause is specified, the numeric value is within the range of values implied by the PICTURE clause'). The national content 'AB1' is not the digits 0-9 (n)1.a).

**Observed / reasoning.** All five print TRUE, and the emitted C# is literally `if ((true))`. DISPLAY G2B prints 50, so the decode truncated the stored value that the class test was meant to categorize. DISPLAY-usage leaves in the same shapes answer correctly because StorageFormPass promotes them to StoreAsImage. PicInfo.IsCharacterFormNumeric restricts promotion to Display/National, and the doc comment says national leaves are deliberately not promoted. This is the case the n)1.c 'valid representation' test exists for, the classic validate-a-packed-field-after-READ idiom, and it silently answers yes.

**Code site.** src/Cobol.Net.Compiler/CodeGen/Emit/ConditionRenderer.cs#RenderClass (the `: "true"` arm after windowedNumeric); src/Cobol.Net.Compiler/Binding/Model/PicInfo.cs#IsCharacterFormNumeric

## Finding — `simple-class-condition` (wrong-answer; rows `GR-8.8.4.4.4-L2.1`)

**Mechanism.** A NUMERIC-category function-identifier operand has no BoundFieldOperand, so RenderClass computes numericCategory=false and applies GR3 n)2's all-digits test to the function's display text. A signed or fractional numeric result therefore answers NOT NUMERIC.

**Repro.** IF FUNCTION INTEGER(-5.5) IS NUMERIC DISPLAY "T" ELSE DISPLAY "F" END-IF.  IF FUNCTION NUMVAL("1.5") IS NUMERIC DISPLAY "T" ELSE DISPLAY "F" END-IF.  (probe/simple-class-condition/p1.cob, p6.cob)

**Expected from the spec.** Both are TRUE. §15.2 4) says numeric functions 'are of the class and category numeric', and §8.8.4.4.3 SR8 admits an identifier 'whose category is numeric'. So GR3 n)1 governs, and a function's numeric result is a valid representation (n)1.c).

**Observed / reasoning.** Both print F. The emitted code is `CobolClass.IsNumeric((CobolIntrinsics.NumvalDec("1.5")).ToFunctionText())`, and it rejects the '.' and '-'. FUNCTION ABS(-5) prints T only because its text happens to be all digits.

**Code site.** src/Cobol.Net.Compiler/CodeGen/Emit/ConditionRenderer.cs#RenderClass (`numericCategory = fld is not null && StringCategoryOf(fld) is PicCategory.Numeric`)

## What the fixer owes

The class test must inspect the STORED representation: either promote PACKED/BINARY/NATIONAL numeric leaves reachable through an image boundary to StoreAsImage (PicInfo.IsCharacterFormNumeric's Display/National restriction and its 'national deliberately not promoted' comment) or give the codec a validity query the renderer calls — never the constant `true`. A numeric FUNCTION result is category numeric (§15.2 4)) → GR3 n)1, valid by construction. Goldens: the five p2/p3/p5/p6 shapes (FALSE) and INTEGER(-5.5) / NUMVAL("1.5") (TRUE); the validate-a-packed-field-after-READ idiom is the headline case.

## Wave 70 group A — re-probed, NATIONAL arm still blocked by PB1665 (not landed here)

**Re-probed on the wave-70 build** (base `dbea12428`): `MOVE N"AB1" TO G1` over `01 G1 GROUP-USAGE NATIONAL. 05 G1N
PIC 9(3) USAGE NATIONAL.` → `G1N IS NUMERIC` prints T (scratchpad `w70a/probe/p1466.cob`); w65e probe p9 after
`MOVE SPACES TO G4` → `G4N IS NUMERIC` prints T (`SPN-T`). Spec: both FALSE (§8.8.4.4.4 GR3 n) 1. — "consists
entirely of a valid representation for the usage", cite.py OK §8.8.4.4.4 3) d) 2.). The arm reproduces.

**Why it did not land here.** Its prerequisite is kb/Work PB1665, which is a separate mechanism outside this group
and measured still open on this build (`w70a/nat/p11.cob`): an alphanumeric group holding a `PIC N(2)` leaf has
`LENGTH = BYTE-LENGTH = 8` and `AsImage()` = `G5A + CobolBits.NatBytes(G5N) + G5B` (8 characters), but a group
RECEIVER is sized by `DataItem.ImageWidth` = 6 (national positions counted once) — the emitted
`G6.FromImage(CobolString.Store(W8, 6))` drops `G6B`, and `IF G5 = G6` answers NE after `MOVE G5 TO W8; MOVE W8 TO G6`.
Admitting `Usage.National` to `StorageFormPass.IsImagePromotable` would route every alphanumeric group holding a
national-numeric leaf through that same truncating receiver (the w65e p9 corruption). A promotion restricted to
national-group parents would be a carve-out around the width bug, not a fix (CLAUDE.md rule 4). So the order is:
PB1665 (one width authority for a group's image — `ImageWidth` vs the byte-doubled national serializer, ~86
`.ImageWidth` readers to classify as "image characters" vs "national positions"; the national-group `PicInfo.Length`
at `DataItem.cs:95` must stay in positions), THEN drop NATIONAL from `IsImagePromotable`'s exclusion here.
