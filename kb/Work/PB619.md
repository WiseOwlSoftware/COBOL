# PB619 — OPEN — the exemption is a class, the rule is a word

Found 2026-09-05 by the `PB250` implementer (report §"New defects" (b)); the `FMT-15.94.2` adjudication had recorded
the same observation and PB250 confirmed it still holds on its tree. It is unrelated to PB250's reach mechanism (which
words a `>>COBOL-WORDS` directive can resolve) and was deliberately left alone there.

## Repro (`--std 2023`)

```cobol
       DISPLAY FUNCTION TEST-NUMVAL-C(ANYCASE)
```

Observed: `COBOLNET1639: 'ANYCASE' is not defined` and nothing else. ANYCASE is a §8.9 reserved word
(`cite.py --find ANYCASE` → §8.9), written here in argument-1's position — a user-defined-word position — which
§8.3.2.4.1 forbids outright: "Reserved words shall not be used as system-names or user-defined words"
(`OK §8.3.2.4.1`). The program is rejected either way; the diagnostic names a consequence (the name is undefined)
instead of the rule (a reserved word cannot BE a user-defined word). The same shape as [[PB582]] — a correct verdict
under the wrong rule — printed to the user.

## The mechanism

`src/Cobol.Net.Compiler/Validation/VersionConformancePass.cs`, `IsBareFunctionArgumentWord` (≈`:1947`), consulted by
the COBOLNET0901 reserved-word funnel (≈`:1996`): it exempts *every* bare word in a function-argument position from
the funnel, because §15's phrase words (ANYCASE, LOCALE, LEADING, TRAILING, …) legitimately appear there as keywords
and must not be reported as misused reserved words. The exemption is written for the CLASS "bare function-argument
word"; the rule that licenses it is per WORD and per POSITION — a phrase word is legal only in the argument position
its function's format gives it (§15.94.2 puts ANYCASE after argument-1, never AS argument-1).

## Fix shape

Replace the class exemption with the position-aware answer the intrinsic binder already computes: PB250's
`IntrinsicBinder.KeywordWordOf` is the one funnel that decides, per function and per argument position, whether a
bare word IS that format's phrase keyword. The conformance pass should exempt a word only when that funnel claims
it; any other reserved word in an argument position falls through to COBOLNET0901 with §8.3.2.4.1 cited. Under a
`>>COBOL-WORDS UNDEFINE "ANYCASE"` the word is no longer reserved (PB250's `CobolWordsMap.Resolve` returns null) and
the exemption question does not arise — the existing PB250 golden `pb250_cobol_words_phrase_word_undefine` is the
control. Negative golden: `TEST-NUMVAL-C(ANYCASE)` rejected with COBOLNET0901 at every edition where ANYCASE is
reserved; drift test that the exemption set equals the set of phrase words the intrinsic catalog declares.
