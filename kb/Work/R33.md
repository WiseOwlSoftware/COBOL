# R33 — adjudicate: an AMBIGUOUS unqualified name resolves FIRST-MATCH (ResolveUnqualified list[0]) instead of demanding qualification

> Found 2026-08-08 while fixing R31: `ResolveUnqualified` is documented "(first match; COBOL requires
> qualification to disambiguate)" and returns `list[0]` when several declarations share the name.

§8.4.2.2.1: "Qualification of a user-defined name is required unless one of the following is true: 1) No
other name has the identical spelling. …" (items 2–6 are narrow outs: REDEFINES/VARYING context, unreferenced
type subordinates, same-group implicit qualification, in-section paragraph names). An unqualified reference
to a multiply-declared name outside those outs is ILLEGAL — today it silently binds to whichever declaration
was registered first, which is a WRONG-ANSWER shape (the program compiles and reads/writes a different item
than another compiler would pick, or than the author intended).

⚠ CONSEQUENCE OF THE CURRENT SHAPE: R30's COBOLNET1639 ambiguity arm ("N declarations share the name …")
is DEAD CODE — Resolve's unqualified leg never returns null for ambiguity, so the arm cannot fire
([[a_dead_lookup_is_also_unverified]]: it has never been contradicted because nothing reaches it).

ADJUDICATE BEFORE FIXING: enforcing §8.4.2.2.1 items 1–6 precisely (especially item 5's same-group implicit
qualification) is a real algorithm, and the leniency may be load-bearing across NIST/corpus programs that
share names benignly. Measure the corpus blast radius first; the strict behavior likely wants the dialect
gate ([[dialect_two_axes]] — a strictness-axis diagnostic, suppressed under --permissive).

**MEASURED 2026-08-08** (scratch-instrumented `ResolveUnqualified`, env-gated, never committed): **ZERO
programs with an ambiguous unqualified resolution** — 303 corpus programs (all four editions, copybooks
included) and 459 NIST programs, every `list.Count > 1` occurrence counted: none. The leniency is
load-bearing NOWHERE in the measured population; strict enforcement is essentially free there. ⚠ DESIGN
CONSTRAINT found while measuring: `SymbolTable.TryResolve`'s list carries the §11.7 GR5 method-overlay
PRECEDENCE ordering — entries may be legitimately SCOPE-SHADOWED (§8.4.6), so `Count > 1` is NOT the same
predicate as "ambiguous per §8.4.2.2.1". The enforcement must ask the symbol table, where the scope rules
live (one-rule-one-place), for "unique AFTER scope resolution" — not count the raw list at the caller.
Implementation next; the differential (1,323 GPL cases) is the remaining unmeasured population and the
next battery arbitrates it.

## LANDED 2026-08-08 (adjudicated + implemented)

The design constraint resolved the easy way: `TryResolve` returns ONE namespace tier (the §8.4.6.2.1
rule-3a method overlay OR the unit map, never a mix), so a plural list IS genuine same-tier ambiguity
and no scope-rule ranking question arises — the enforcement lands at `ResolveUnqualified` after all,
with the tier fact documented at the check. Strict: null → `ReportUnidentified`'s N-declarations arm
(built by R30, DEAD until now — [[a_dead_lookup_is_also_unverified]] closed by making it reachable);
`--permissive`: the traditional first-declared match with a warning (the DA6/R29 disposition shape).
THE SWEEP (rule 4) found the condition-name siblings in `ConditionOf`: the unqualified plural-88 form
AND the qualified form's `FirstOrDefault` both resolved silently to the first match — both now report
(strict error + bind-first-anyway so no caller fallback runs a different reading; permissive warns).

Probes: duplicate data-names draw 1639's ambiguity message strict / warn+first permissive (prints 1);
duplicate 88s likewise (ON under permissive). Fixtures `unqualified-ambiguous-name` +
`condition-name-ambiguous` (reject-at all four editions). Gate: Corpus|Intrinsic|Udf 713/713 · the
three ambiguity fixtures by name · full Unit 4099/4099 · characterization 33/33. The next battery's
differential leg arbitrates the GPL population (zero expected — GnuCOBOL itself rejects ambiguous
references).
