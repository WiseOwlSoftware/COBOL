# PB3977 — markdown_units has its own, non-CommonMark fence toggle

**Sites:** `scripts/arch/source_units.py:486` (`source_units._FENCE`, `source_units.markdown_units`),
`scripts/spec/work.py` (`work.fenced_blocks`, the tracker PB3938 unified inside work.py only).

Filed 2026-10-28 by the enqueue unit's clerk from the PB3838 branch review's R1-1 lead (owed since the 2026-10-27 14:06
enqueue unit), carried unchanged. Not re-probed by the clerk.

## Mechanism

PB3938 made `work.fenced_blocks` the ONE fence tracker of a note body (CommonMark 0.31 section 4.5: a fence closes only
on a run of the same character at least as long as the opener, with nothing after it). `markdown_units` in
`scripts/arch/source_units.py` still toggles on `_FENCE = ^[ \t]{0,3}(```|~~~)`, which matches only the first three
characters, so any run of three or more of the same character closes the fence, info string or not.

## Failure

`markdown_units` of a text holding a four-backtick fence around a ```` ```cobol ```` block with a `# x` line inside
returns the units `<preamble>` (lines 1-2) and `x` (lines 3-6): the inner ```` ```cobol ```` line closes the outer
fence, so `# x` inside the code block becomes a unit boundary. `inflight.py`'s collision check then assigns lines of a
document that nests fences to the wrong unit, and the wave planner partitions on those units (PB3859).

## Fix

Move `fenced_blocks` to one shared module and have both `work.py` and `source_units.markdown_units` use it (no second
tracker, no forwarder: change both callers and delete `_FENCE` in source_units.py in the same change), with a test
that feeds `markdown_units` the nested-fence text above.
