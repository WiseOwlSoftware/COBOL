# PB4413 - The sidecar host's holds still publish and retire a file each

**Sites:** `src/WiseOwl.Cobol.Runtime/IO/Sharing/SidecarRegionLocks.cs` (`SidecarRegionLocks.SidecarHost.Open`, which builds the endpoint with `parkReleased: false`), `src/WiseOwl.Cobol.Runtime/IO/Sharing/HostRegionLocks.cs` (`HostRegionLocks.InStoreMutex`, `HostRegionLocks.KeptEntryMutex`).

PB4387 parks a released byte instead of retiring it (`SidecarRegionLocks.ParkingForPath`, used for the keyed `HostRegionLocks.InStoreMutex` per statement), so the next hold is one rename and one listing. The sidecar HOST's own store mutex and record locks still go through `Open(..., parkReleased: false)` and publish then retire a lock file per hold. This is the macOS / non-Linux lock-file host path, unmeasurable on this Windows host. `ParkingForPath` could serve them.

No harm flag: performance only. Measure on a lock-file host before and after; the park-then-rename protocol must keep PB3340 R1-1's publish-then-test guarantee.
