**Rule it breaks:** One mechanism per job / one rule in one place (design §5.2; dimensions.md 4). EditionSeverityPolicy.cs:5-10 states the rule in the code itself: 'Every removed / reserved / obsolete / not-yet-introduced emit site asks HERE - never a local if (permissive)'; ConstructRegistry.cs:5-10 calls Check 'the ONE gating entry point: every edition gate ... routes through Check'; design §8.3 (6) names ConstructRegistry.Check 'the one funnel'.

**Scenario:** The availability verdict (ConstructDialectStatus.StatusAt) and its severity (EditionSeverityPolicy.For: Removed => error strict, WARNING permissive) are re-derived by hand in two other places. IntrinsicSig.IsDefinedAt re-implements the [IntroducedIn, RemovedIn) window; IntrinsicBinder.BindFunctionResult emits COBOLNET1503 for a removed function through ctx.Edition.Error unconditionally, so the first intrinsic row given a RemovedIn (the D8 window is a column today and PB2300 moves it into intrinsics.json, where adding one is a data edit) is a hard error under --permissive, while every constructs.json row removed at the same edition is a warning there - the permissive migration mode silently diverges by which catalog a construct happens to live in. The three arms also word the same fact three ways ('requires COBOL-2002 (targeting COBOL-85)' vs 'was introduced by ISO/IEC 1989:2002 ... requires --std 2002 or later') and carry three code families, and a fourth window-carrying catalog would get a fourth copy because nothing names the verdict as the shared step.
