# PB178

Found 2026-08-30 by the PB176 skeptic round; PRE-EXISTING. `OperandText.AsStorageImage` handles
RefModPlace and OdoGroupPlace, then does `p.Item.IsGroup ? Read(p).AsImage() : ...` — no RedefViewPlace
arm, though its sibling `FieldAsString` returns the view's window early with the explicit comment "no
.AsImage() ... for a group or an elementary view alike". A Tier-B class with a GROUP member yields a
RedefViewPlace whose Read is the string window, so `FUNCTION CONVERT(B ANY TO ...)` over
`01 A PIC X(8). 01 B REDEFINES A. 05 B1 PIC X(4). 05 B2 PIC X(4).` emits
`CobolStr.RefMod(_redef_A, 1, 8).AsImage()` — CS1061 on `string` (CONVERT's bind screen rejects only
index/pointer/object usages, so the shape reaches the emitter).

FIX SHAPE: route AsStorageImage's group arm through `PlaceRenderer.GroupImage` (THE ONE reader — its
doc names exactly this violation) instead of spelling the call; that also inherits the PB176 capability
guard for free. Golden: a CONVERT over a Tier-B group view. Sweep the remaining self-spelled sites the
skeptic enumerated (OperandText:133 is guarded but still self-spelled; OoEmitter's are PB177's A).

## Implementation record - 2026-08-31 (burn-down cluster A)

**PROBED FIRST, on the clean tree at 876d8ab0.** The note's repro reproduced verbatim:
`FUNCTION CONVERT(B ANY ANUM HEX)` over `01 A PIC X(8) VALUE "ABCDEFGH". 01 B REDEFINES A. 05 B1 PIC X(4).
05 B2 PIC X(4).` emitted
`R = CobolString.Store(CobolIntrinsics.Convert(CobolString.RefMod(_redef_A, (int)(0 + 1), 8).AsImage(), ...))`
-> `CS1061: 'string' does not contain a definition for 'AsImage'`. A Tier-B group view carrying a
`PIC S9(4) COMP` leaf reproduced identically, proving the defect is keyed on PLACE SHAPE, not leaf category.

**FIX - the extraction, not a guard.** `PlaceRenderer` gained `SendingGroupImage(Place, context)`: THE ONE
reader of a group operand's image in a SENDING context - `GroupImage` except that an `OdoGroupPlace` is sliced
to 13.18.38.4 GR8's current extent. `GroupImage`/`SendingImage` gained an optional `context` so a consumer can
route through the ONE reader and keep its own Tier-C message (that need was the excuse for the copy).
Three consumers now route: `OperandText.AsStorageImage` (the defect - its explicit ODO arm and its self-spelled
group arm collapse into one call), `OperandText.FieldAsString` (byte-identical; the third copy removed), and
`NumericRenderer.FieldNumCore`.

**THE SIBLING'S REACHABILITY WAS MEASURED, NOT DEDUCED** (the note's open question). `FieldNumCore`'s group arm
is rejected under STRICT conformance (COBOLNET0844, 8.8.1.1) but LIVE under `--permissive`, a supported mode:
`COMPUTE X = <a BASED record with an ODO table> + 1 --permissive` was `CS1061` before and answers `001002004`
after. That probe also proves the arm's SECOND, independent half - it returned the MAXIMUM image where GR8 gives
a sending operand the CURRENT extent (8 characters, "01"+"002"+"003"), which its sibling `FieldAsString` already
got right. A wrong ANSWER, fixed by the same routing. Of `FieldNum`'s 9 callers, the SUBSCRIPT path turned out
not to reach `FieldNumCore` at all - see [[PB201]] (a GROUP used as a subscript).

**PINS.** Golden `pb178_convert_any_redefines_group` (4 legs, every expected value derived from 15.19.3 r7 +
13.18.44.4 GR1 and written before the confirming run: `4142434445464748`, `41424344`, `5758595A0102`,
`4142636363646464`). Leg 4 is the `OdoGroupPlace`-over-`RedefViewPlace` shape. The Tier-C group is NOT a
negative fixture - measured, it stages a RUNTIME loud whose context string still names CONVERT, which is the
correct posture and which the `context` parameter is what preserves.
Unit: `BoundaryImageChannelTests` - the source-level drift test. IT WAS RED FIRST, reporting exactly
`CodeGen/Verbs/OoEmitter.cs=3` (PB177 arm A's sites) once PB178's were gone.
