# PB728 — OPEN — the level-88 group arm takes the wrong collating sequence, and it also slips the screen that would have declined it

Found by the [[PB678]] implementer (report §N2) by inspection, filed with the explicit caveat *"Repro: not yet
cut … measuring it is the note's first step (`feedback_reachability_is_measured_not_deduced` applies: this is a
hypothesis, not a diagnosis)"*. **That step is done. It is not a hypothesis — it is a runtime wrong answer, and
the measurement found a second harm the report did not have.**

## The facts

**What the standard says.** A national group is not a group for comparison purposes — it *is* an elementary
national item, and the category is national, not null:

- `cite.py --check 13.18.29.4 "a national group is treated as though it were an elementary data item of usage
  national and class and category national"` → **OK §13.18.29.4 2) b)** (and GR2a: *"The subject of the entry is a
  national group; its class and category are national"*).
- `--check 13.18.29.4 "a bit group is treated as though it were an elementary data item of usage bit and class and
  category boolean"` → **OK §13.18.29.4 1) b)**.
- `--check 8.8.4.2.9 "national"` → **OK §8.8.4.2.9 (Comparison of national operands)** — national operands compare
  under the national sequence; §8.8.4.2.8 is the boolean twin (compare by value, right-extended with boolean
  zeros).
- `--check 14.7.8 "collating sequence"` → **OK §14.7.8 2)** — *"When the range of values is defined by alphanumeric
  or national literals, the range of values depends on the collating sequence used for evaluation of the range."*
  So for a THROUGH range the sequence is not decoration; it decides membership.

**What the code does.** `src/Cobol.Net.Compiler/CodeGen/Emit/ConditionRenderer.cs:464`, inside
`RenderMembershipTest`:

```csharp
var cat = parent.Pic?.Category;
string collate = ctx.CollateArgFor(cat);
```

`Pic` is **null for every group**, so `cat` is null and `CollateArgFor(null)` returns `""`
(`EmitCore.cs:58-63` — `CollatingClass.National → NatCollateArg`, `Alphanumeric → CollateArg`, `_ → ""`)… except
that the operand text three lines earlier has already been rendered through the string path, which for a national
group emits `.AsNat()`. The two halves disagree about what the operand IS.

The correct reader is 169 lines up in the same file, `StringCategoryOf` at `:295`, whose own comment states the
contract: *"**THE ONE category reader (D20/PB79)**: an elementary item's picture, **a bit / national group's
as-if picture**; an alphanumeric group has none and takes the alphanumeric (image) branch."* It reads
`f.Place.Item.OperandPic?.Category`, and `DataItem.OperandPic` is `Pic ?? AsIfPic` (`Model/DataItem.cs:83`) —
exactly the §13.18.29.4 GR1b/GR2b as-if picture. **One rule, written in two places, and only one of them was
updated** (`feedback_one_rule_one_place`, `feedback_two_arm_dispatch`).

**MEASURED — a runtime wrong answer, not an inspection.** Compiler on main (`0db46983`), sources in
`…/scratchpad/reg14/`. The discriminator declares two DIFFERENT sequences so neither leg can pass for the wrong
reason: `ALPHABET REV-AN IS "CBA"` (⇒ C < B < A) and `ALPHABET REV-NAT FOR NATIONAL IS N"BAC"` (⇒ B < A < C),
both installed by `OBJECT-COMPUTER. XCOMP PROGRAM COLLATING SEQUENCE IS REV-AN REV-NAT.`

`nat88b.cob` — equality form, one 88 over a `GROUP-USAGE NATIONAL` group and one over a national elementary.
Emitted C# (`nat88b.g.cs:58` and `:63`):

```csharp
if ((CobolString.Compare(GN.AsNat(), "ABC", __COLLATE)     == 0))   // 88 over the national GROUP  ← alphanumeric weights
if ((CobolString.Compare(EN,          "ABC", __COLLATE_NAT) == 0))  // 88 over the national ELEMENTARY ← correct
```

The image is national (`.AsNat()`), the weights are alphanumeric. Positive identification, not inference.

`nat88d.cob` — the same 88 as a THROUGH range, `88 GN-IN-RANGE VALUE N"AAA" THRU N"CCC"`, with `GN-A` holding
`N"CCC"`, run:

```
GROUP=FALSE
```

emitted as `CobolString.Compare(GN.AsNat(), "AAA", __COLLATE) >= 0 && CobolString.Compare(GN.AsNat(), "CCC",
__COLLATE) <= 0`. Under the declared **national** sequence REV-NAT (B < A < C) the range N"AAA" THRU N"CCC" is a
valid ascending range and `N"CCC"` is its upper bound, so the conforming answer is **TRUE**. Under the
alphanumeric REV-AN (C < B < A) the same range is INVERTED and therefore empty, so the answer is FALSE. **The
compiler answers FALSE. Silently.**

## The second harm the report did not have: the group also slips the screens

The identical THROUGH over a national **elementary** does not compile at all —
`src/Cobol.Net.Compiler/Binding/DataBinder.cs:2556`:

```
nat88c.cob(16,11): error COBOLNET0899: condition-name 'EN-IN-RANGE': a THROUGH range over a national
conditional variable (ordered by the national collating sequence) is recognized but not yet implemented
(Phase 4a residue) - (ISO 13.18.63 SR31)
```

The group form draws **nothing** and proceeds to emit the wrong answer. Same for the boolean ban: `bit88.cob`
puts the identical `88 … VALUE B"000" THRU B"111"` on a `GROUP-USAGE BIT` group and on a `PIC 1(3) USAGE BIT`
elementary — only the elementary is reported (`COBOLNET0898`, §13.18.63.3 SR29: `cite.py --check 13.18.63.3 "If
the category of the subject of the entry is boolean, the THROUGH phrase shall not be specified"` → **OK
§13.18.63.3 29)**). Both screens read `parent.Pic` (`DataBinder.cs:2553` and `:2556`) and a group has none.

⛔ **That half is [[PB575]]'s, not this note's** — PB575 already owns "every Format-3 VALUE guard in
`BindCondition` reads `parent.Pic`, and a BIT or NATIONAL GROUP conditional variable has none". It is recorded
here because the two COMPOUND and must be fixed together: PB575 is why the source reaches codegen at all, PB728
is what codegen then answers. Fixing PB575 alone converts today's silent wrong answer into a loud decline (an
improvement, and it would MASK PB728 for the national THROUGH shape while leaving the equality shape — which
PB575's screens do not touch — silently wrong).

**Note the boundary carefully:** the emitted equality form above (`nat88b`) is reached with NO diagnostic from
either note's screens, at every edition. That is the shape with no other owner.

## Why it matters

A condition-name test is the most-written conditional in COBOL, and a `GROUP-USAGE NATIONAL` group with an 88 on
it is the natural way to write one over a multi-field national key. The answer is wrong, the wrongness is
invisible (no diagnostic, correct-looking generated code), and it only manifests when a non-native collating
sequence is declared — i.e. in exactly the internationalized programs GROUP-USAGE NATIONAL exists to serve. Under
the default native sequence the two collations coincide, so **every existing green test passes**
(`feedback_green_gates_arent_evidence`): the corpus has no case that declares different alphanumeric and national
alphabets and then writes an 88 over a national group.

## The fix shape

`RenderMembershipTest` must take its category from the ONE reader, not from `Pic`:

```csharp
var cat = parent.OperandPic?.Category;
```

⛔ **Do not stop at the one line** (CLAUDE.md rule 4/5). `RenderCondition88` at `:435` has the same shape —
`c.Parent.Item.IsGroup || c.Parent.Item.Pic?.Category is …` — where the `IsGroup` disjunct accidentally covers the
national/bit group for the *isString* decision but for the wrong reason (it treats them as alphanumeric groups),
and `:402` (`fld?.Place.Item.Pic?.Category is PicCategory.Numeric`) is a third. The right change is to make
`Pic?.Category` unavailable as a category source in this file: route every category read through
`StringCategoryOf`/`OperandPic`, and pair it with a drift test that fails if a new `Pic?.Category` appears in
`ConditionRenderer.cs` — a semgrep rule beside the existing `bound-node-carries-rendered-text` is the cheap form,
since `scripts/semgrep/baseline.json` is already the mechanism for "this pattern shall not grow".

Ships with: a positive golden at 2023 that declares REV-AN and REV-NAT with DIFFERENT orders and asserts the
group 88 answers under REV-NAT (the `nat88b`/`nat88d` shape — the deliberately-different-orders discipline
[[PB678]]'s `pb678_sort_national_key_collating` already uses), the boolean twin (a `GROUP-USAGE BIT` 88, boolean
right-zero extension per §8.8.4.2.8), and the ALPHANUMERIC-group control that must stay on `__COLLATE`
(`feedback_edition_gate_sweep`'s over-rejection twin: the fix must not move the alphanumeric group). Prove the
golden load-bearing by swapping the two alphabets and watching it fail.
