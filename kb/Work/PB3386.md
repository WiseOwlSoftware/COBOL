# PB3386 — a merged SPLIT predecessor reads DECISION

**Sites:** `scripts/prune_worktrees.py` (`contained`).

A lead from the Mythos lane's PB3381 implementer (report `E:\COBOL-coord\scratch\reports\w1125a-PB3381-report.md`,
"New defects"), assigned to the operator's clerk. It predates PB3381.

**The site.** `scripts/prune_worktrees.py` `contained()` (about lines 678-695 at main 38926bffb) marks a branch IN
FLIGHT, carried, when its tip is an ancestor of a carrier's tip. Its skip condition passes over every DECISION row that
has a report unless that report is FINDINGS-stamped:

    or (r.state == 'DECISION' and r.report is not None and not findings)

**What goes wrong.** A SPLIT report puts its branch in DECISION (lifecycle: "a SPLIT report (DECISION)"). When a
successor or a finisher MERGES that branch, the predecessor's work lands through the carrier. Yet `contained()` skips the row because its
report is SPLIT, not FINDINGS, so the survey still prints a DECISION row. The operator is asked to land or abandon
work that is already on its way to main, and `--abandon` on it would record a false decision. PB3170 is the planner's
side of the same blind spot, for a cherry-picked SPLIT predecessor, where ancestry cannot see the carry at all.

**The fix.** `contained()` carries any DECISION row whose tip a carrier contains, whatever its report says. The
FINDINGS arm stays as it is, and a SPLIT report is carried the same way. A self-test pins a SPLIT-stamped predecessor
merged into a WAITING TO LAND successor, which must read IN FLIGHT with the successor named as its carrier.

## Landed (2026-11-07, wave 20261107 group E)

**Re-probe.** The note's headline case, a SPLIT predecessor merged by a WAITING TO LAND successor, no longer reproduced:
PB3652 (`unfinished`, `plan_wave.FINISH_STATUSES`) had already admitted a SPLIT / NOT STARTED row to `contained()`'s
candidates. The note's wider claim ("or anything but FINDINGS-stamped") still did: the skip clause
`r.state == 'DECISION' and r.report is not None and not findings and not unfinished` left three more DECISION rows
beside a carrier that lands the same commits, each reproduced on the self-test's scratch repository as an ancestor of
a DONE branch reviewed CLEAN at its tip (WAITING TO LAND): a DONE report 30 h old (`cw-stale`), a DONE report followed
by a commit it does not describe (`cw-moved`), and a DONE report whose lead note already landed (`cw-lost`). A fourth,
`rpred-fix` (a review finisher's BLOCKED branch at the head of a FINDINGS predecessor its successor carries), read the
same.

**Fix (`scripts/prune_worktrees.py` `contained`).** The report decides nothing in the ancestry arm: every DECISION row
whose tip a carrier contains is carried (the commits land with the carrier and its review covers them). The replay arm
keeps its own, narrower input (`replayable`: a DECISION with no report or an unfinished one, never a FINDINGS stamp),
because the planner plans a finisher only from those. `CARRIED_STATES` and the docstring say so, and
`DESIGN-orchestrator-loop.md` (the survey reads the planner's carrier rule) carries the sentence. Self-test arms
`cw-pred` (SPLIT), `cw-stale`, `cw-moved` and `cw-lost` are chained under `cw-succ`; `rpred-fix` now reads IN FLIGHT,
carried by `rsucc`, and the verdict-line counts moved with the five rows. The planner is unaffected (it reads `owned`,
which excludes carried rows).
