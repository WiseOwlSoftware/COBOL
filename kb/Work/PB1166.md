## Finding — `returning-items` (under-rejects; rows `GR-14.8.3.3-L2.1`, `GR-14.8.3.3-L2.2`, `GR-14.8.3.3-L2.3`)

**Mechanism.** The returning-item PICTURE identity compare is a raw character-string compare that ignores each element's SPECIAL-NAMES: no currency-STRING axis and no DECIMAL-POINT IS COMMA axis

**Repro.** Main 'SPECIAL-NAMES. CURRENCY SIGN IS "USD" WITH PICTURE SYMBOL "$".' '01 R PIC $$$9.99.' 'INVOKE O "GETC" RETURNING R'; class RIC10 'SPECIAL-NAMES. CURRENCY SIGN IS "EUR" WITH PICTURE SYMBOL "$".' method GETC 'RETURNING LR' LR PIC $$$9.99 (p10.cob). And class RIC9 'DECIMAL-POINT IS COMMA' returning LR PIC Z9,99 into a main (no DPC) R PIC Z9,99 (p9.cob); likewise PIC Z9.99 both sides (p9p.cob).

**Expected from the spec.** Rule 1: currency symbols match only if the currency strings are the same (USD vs EUR -> no match). Rules 2/3: period and comma symbols match only if DECIMAL-POINT IS COMMA is in effect in both elements or neither (class only -> no match). All three pairs are non-conforming -> COBOLNET0828 at the INVOKE.

**Observed / reasoning.** All three compile and run: p10 prints [ EUR12.34] into a USD-described receiver, p9 prints [12,34] (the receiver reads 1234 where the sender meant 12.34), p9p prints [12.34]. The conforming halves hold (p10m: 'USD' string under symbols '$' and 'U' accepted). DescriptionMismatch's NumericEdited arm compares EditMask only; the currency string and DPC state of the activating and activated elements are never consulted. Reachable only across separately-defined units, since contained units inherit SPECIAL-NAMES (§12.3.7.4 GR1). The §14.8.2.3.2 a)/b) BY REFERENCE twins share the comparator.

**Code site.** src/Cobol.Net.Compiler/Oo/OoConformance.cs#DescriptionMismatch (NumericEdited/National/Boolean arm EditMask compare)

## Finding — `returning-items` (rejects-legal-source; rows `GR-14.8.3.3-L3.2`, `GR-14.8.3.3-L3.3`)

**Mechanism.** DescriptionMismatch has no bit-group / national-group arm: §14.8.3.1's NOTE (such groups are elementary) and §14.8.3.3's matching rules are absent, so a group side falls into the alphanumeric-group arms and is refused

**Repro.** Nested SB11 'LINKAGE SECTION. 01 LB PIC 1(8) USAGE BIT. PROCEDURE DIVISION RETURNING LB.'; caller '01 GB USAGE BIT. 05 GB1 PIC 1(4). 05 GB2 PIC 1(4).' 'CALL "SB11" AS NESTED RETURNING GB'; nested SN11 returning 'PIC N(5)' into '01 GN GROUP-USAGE NATIONAL. 05 GN1 PIC N(2). 05 GN2 PIC N(3).' (p11.cob); reverse direction p12.cob.

**Expected from the spec.** 8 boolean positions / 5 national positions on each side -> conforming; runs printing [1111][0000], [AB][CDE] (p11) and [ABCDE] (p12).

**Observed / reasoning.** COBOLNET1736 'a group argument requires a group or alphanumeric formal' (p11, both CALLs) and 'a group formal requires a group or alphanumeric argument' (p12). The same comparator serves §14.8.2.3.2 b)/c) (BY REFERENCE arguments) and the INVOKE lane, so the sibling rows are affected identically. The inverse under-reject (a national group paired with an alphanumeric group of equal width, which §14.8.3.2 forbids because a national group is not an alphanumeric group) is likely but not probed.

**Code site.** src/Cobol.Net.Compiler/Oo/OoConformance.cs#DescriptionMismatch (formal.IsGroup and arg.IsGroup arms)

## Finding — `returning-items` (under-rejects; rows `GR-14.8.3.3-2`)

**Mechanism.** The returning-item PICTURE identity treats alphabetic and alphanumeric PICTUREs of equal length as the same clause (one Alphanumeric category, null EditMask)

**Repro.** Nested SA13 'LINKAGE SECTION. 01 LA PIC A(5). PROCEDURE DIVISION RETURNING LA.'; caller '01 EX PIC X(5).' 'CALL "SA13" AS NESTED RETURNING EX' (p13.cob).

**Expected from the spec.** The sending operand is not an object reference, so 'the receiving operand shall have the same ... PICTURE ... clauses'; PIC A(5) and PIC X(5) are different PICTURE clauses and none of the listed exceptions applies -> COBOLNET1736.

**Observed / reasoning.** Compiles and prints [ABCDE]. DescriptionMismatch's Alphanumeric arm compares JUSTIFIED, EditMask (null for both) and Length only. ALIGN and DYNAMIC LENGTH, also on the list, are compared nowhere in DescriptionMismatch (not probed). The §14.8.2.3.2 BY REFERENCE twin shares the arm.

**Code site.** src/Cobol.Net.Compiler/Oo/OoConformance.cs#DescriptionMismatch (case PicCategory.Alphanumeric)

## Refuter evidence — row `GR-14.8.3.3-L3.1` (PARTIAL)

An under-rejection at the identity edge; the mainstream pairs conform. Also the diagnostic cites §14.8.2.3.2 rule 2 (the argument rule) rather than §14.8.3.3 for a returning pair - cosmetic. No spec-derived test pins the returning pair (test-ref empty).
