# PB2021 — OPEN: is `SET ADDRESS OF x DOWN BY 32` legal in any edition?

The flip `run_misc:14097` has two source files. Its caller.cob was adjudicated as a correct rejection (§13.7.3 4): a LINKAGE
item referenced without USING). Its callee.cob also fails, with COBOL0001 "unexpected 'DOWN'", on a statement of the shape
`SET ADDRESS OF x DOWN BY 32`. The adjudicator did not decide it: in ISO 2023 §14.9.39, UP BY and DOWN BY appear only in Format 2
(index-names) and Format 14 (a dynamic-capacity table), so the form is most likely a GnuCOBOL or vendor extension (pointer
arithmetic), but the older editions were not checked (the repository holds only the 2023 text), and the 2002 and 2014 SET
statements had pointer formats whose UP BY / DOWN BY wording must be read in `docs/VERSION_CHANGE_REFERENCE.md` and the
historical-revisions sources before the answer is written.

Deliverable: the verdict per edition (CONFORMS / DIVERGES / DOCUMENTED-NON-SUPPORT) with `cite.py`-checked clauses, a
`docs/CONFORMANCE.md` entry if it is a documented non-support, and, if any edition makes it legal, the grammar fragment under
the version predicate (CLAUDE.md rule 3: no legal source rejected). The parse error's wording should name the actual rule either
way.
