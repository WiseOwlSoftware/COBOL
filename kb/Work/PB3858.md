# PB3858 — two devlog evals are red with the skill

**Sites:** none (the evals live in the public brent-tools repository, the `tools/claude-skills` submodule:
`evals/devlog-commit-hook/` and `evals/devlog-insert-entry/`; they are fixed there first and consumed by moving the pin)

## The defect

PB3788's split of the public plugin measured the extras suite. `devlog-commit-hook` scores 0.50 and `devlog-insert-entry`
0.00 on the split plugin, and on the UNSPLIT v1.22.0 clone both score 0.00 WITH the skill (3 runs per arm). The public
evals README says their expected outcomes were revised on 2026-10-11 and their scores not re-run, so the suite has
reported both as red ever since without a note to own them. An eval that its own skill fails is either a stale grader
or a skill that no longer does what the eval asks; either way the suite stops guarding the devlog skill.

## Acceptance

- Each of the two evals scores at or above its recorded score WITH the skill, by fixing whichever is wrong (the grader
  against the skill's current text, or the skill), recorded in the public evals README with the run.
- The README's "revised, not re-run" state is gone: every eval whose expectation changes is re-run in the same change.
- Standing owner rules: fix the root cause, never simply making the diagnostic pass; consistent with ourselves.
