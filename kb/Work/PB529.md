# PB529

## Mechanism — picture-clause-p1
SR14's LOWER bound is the capacity check's own skip guard. DataBinder.cs:2667 reads `if (pic is { Category: PicCategory.Numeric or PicCategory.NumericEdited, IsFloat: false, IsFloatEdited: false } && pic.DigitPositions > 0) Edition.CheckDigitCapacity(...)` - so the exact condition SR14 forbids, zero digit positions, is the condition that SKIPS the check. The `> 0` was presumably meant to spare picture-less and recovery shapes, but those are already excluded by the category test, and the format-2 arm shows the intended shape: PictureAnalyzer.cs:766-767 tests `if (digits == 0)` and rejects with COBOLNET1673 naming SR33. Consequence: a category-numeric item of ZERO length is constructible and every store into it is silently discarded.

### Expected, from the standard
ISO/IEC 1989:2023 13.18.40.3 SR14: "For data items of category numeric, and for fixed-point data items of category numeric-edited, the number of digit positions described by character-string-1 shall range from 1 through 31." A character-string describing ZERO digit positions is illegal source at every edition and shall draw a named diagnostic; it is independently illegal under SR12's no-FOR sub-rule a) (at least one of A N X Z 1 9 * or two occurrences of character-1 / '+' / '-' / the currency symbol). 13.18.40.4 GR14 row P supplies the counting rule the upper bound already honours: "The symbol 'P' is not counted in the size of the item, but each symbol 'P' is counted in the maximum number of digit positions."

```
$ python scripts/spec/cite.py --check 13.18.40.3 "For data items of category numeric, and for fixed-point data items of category numeric-edited, the number of digit positions described by ch..."
  OK  §13.18.40.3 14)  (Syntax rules)
```

### Observed
Measured at all four editions. The item binds as PicCategory.Numeric with Length 0 and Digits 0 (PictureAnalyzer.cs:352, `Length: digits`), so the emitted native field holds nothing, MOVE 5 into it is a no-op and DISPLAY prints an empty string - a wrong answer with no diagnostic anywhere in the chain. Because the guard sits on the DataBinder side and the count on the analyzer side, the fix belongs with the composition validator (the SR12 a) sub-rule catches the same shapes) rather than as an isolated `>= 1` test; the drift risk is that removing `> 0` starts firing on recovery PicInfos, so the recovery shapes must be excluded positively.
