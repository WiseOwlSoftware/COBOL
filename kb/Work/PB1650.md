# PB1650 — OPEN

Filed 2026-09-27 by the train-66 lander from the wave-66 G implementer report (PB1475 + PB1300). Found while
landing PB1300's composed-BASED screen (COBOLNET2510); it predates that change.

**Observed.** A TYPE clause now composes a BASED clause into its subject (§13.18.57.4 GR1, §13.18.58.4 GR3;
`DataItem.IsBased` is `EntryOnly` since PB1300). The PROPERTY placement rule is asked only of the WRITTEN clause:
`OoBindPropertyClauses` (`src/Cobol.Net.Compiler/Binding/DataBinder.Oo.cs:639-658`) runs before `ExpandTypes`
(`src/Cobol.Net.Compiler/Oo/OoDriver.cs:74`), and `DataItem` carries no PROPERTY fact that
`DataBinder.ScreenComposedBased` (the composed-clause screen) could read. So `01 P TYPE T PROPERTY.` over
`01 T TYPEDEF BASED ...` in a class's working-storage is not refused.

**Repro.** A class whose OBJECT working-storage declares `01 T TYPEDEF BASED PIC X(4).` and
`01 P TYPE T PROPERTY.` compiles clean; the same entry with a written `BASED` is refused.

**Rule.** §13.16.3 21) a): "The PROPERTY clause shall not be specified in the same data description entry as: a) a
BASED clause" (`cite.py --check 13.16.3 "The PROPERTY clause shall not be specified in the same data description
entry as"` OK 21)). By §13.18.57.4 GR1 the TYPE clause's effect is "as though the data description identified by
type-name-1 had been coded in place", so a composed BASED is in the same entry.

**Fix shape.** Record PROPERTY on the entry (a `DataItem` fact) so the one composed-clause screen,
`ScreenComposedBased`, asks SR21 a) beside SR5/SR13/SR16, or move the PROPERTY screen after `ExpandTypes`. Either way,
one screen for both the written and the composed BASED.

## Task brief (research 2026-09-30)

**Re-measured on `4a1dda60e`: reproduces** (`01 T TYPEDEF BASED PIC X(4). 01 P TYPE T PROPERTY.` in OBJECT WS →
compiles; the written `01 P PIC X(4) BASED PROPERTY.` → COBOLNET2333). Part of kb/Work PB1783 step 1.

- **Spec:** §13.16.3 SR21 "The PROPERTY clause shall not be specified in the same data description entry as" a) a BASED
  clause (cite-checked OK 21)); §13.18.57.4 GR1 (the TYPE clause composes the described entry in place).
- **Change:** record PROPERTY as a `DataItem` fact at declaration so `DataBinder.ScreenComposedBased` asks SR21 a) beside
  SR5/SR13/SR16 for the composed entry — ONE screen for written and composed BASED (delete the written-only arm in
  `OoBindPropertyClauses`). Sweep: SR21 b) TYPEDEF (a composed TYPEDEF cannot arise, but check `TYPE T` where T is
  itself TYPE-of-TYPEDEF).
- **Golden:** negative `pb1650-property-composed-based` (2002) → COBOLNET2333 on the TYPE entry.
- **Size:** quarter slot (part of PB1274's group or standalone).

## Landed (wave 1019 D2, 2026-10-05)

`DataBinder.cs#ScreenComposedBased` (the one screen for a BASED clause a TYPE or SAME AS clause composes) now asks
§13.16.3 SR21 a) ("The PROPERTY clause shall not be specified in the same data description entry as: a) a BASED
clause", cite.py OK 21)) beside SR5/SR13/SR16, reading `DataItem.Property`, which `BindEntry` records before
`ExpandTypes` runs. The written arm is the clause-placement table's NotWith row (COBOLNET2333); OoBindPropertyClauses
holds no SR21 arm any more. b) TYPEDEF cannot be composed. Goldens: `negative/pb1650-property-composed-based`
(COBOLNET2510), `2002/pb1650_property_typed` (the legal TYPE + PROPERTY spelling: ABCD / WXYZ).
