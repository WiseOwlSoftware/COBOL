# PB4996 - lineage slice 5: derived bands and the edition-gate drift test

docs/rearchitecture/DESIGN-spec-conformance-review.md §10.2, slice 5. A band is a chain's span, so the conformance suite's band schema (DESIGN-conformance-suite.md §3.5,
slice S5, PB4683) reads the chains instead of hand-written edges, and a 1985 edge's evidence class is the 1985 text.
A drift test holds each `constructs.json` window start and end, and each version predicate of the grammar, to a NEW or
REMOVED edge with its citation.

## Landed (wave 20261935 C): the edition-gate audit and the band drift

**The edition-gate drift test is an audit, not a Unit test.** The lineage's semantics live in Python (`lineage.py`, read
by the view), and the C# view only joins (PB4992), so a C# copy of the chain rules would be a second reader of them. It is
`scripts/spec/edition_gates.py --check`, the gate's and CI's EDITION GATES audit, in every lane. It reads every
`constructs.json` window and every `{isNNNN()}?` predicate of the grammar (citing what its rule's comment cites) and holds
each edge the held editions span to the rules the gate's citation names. **Design correction** (DESIGN-spec-conformance-
review.md §10.2): an edge is not only NEW or REMOVED. A start rests on a NEW rule or on one a CHANGED record names (an
alternative added to a format 1985 has: 229 of the windows), an end on a REMOVED or CHANGED 1985 rule; KEPT-only is a
contradiction. The first run found 48: 46 gates citing nothing the lineage could read (bare clause numbers, or no 1985
rule at all on an end) and two contradictions. Fixed: 40 `constructs.json` citations now name their rules (the ends cite
the 1985 rule whose record removes or changes them), and two 1985 records re-adjudicated: `1985-GR-VII.2.6.3-2` KEPT
into line sequential organization (it is record sequential's; line sequential is NEW at 2023) and the 1985 FILLER rules
`1985-FMT-VI.5.5.2`, `1985-GR-VI.5.5.4-2` (KEPT, now CHANGED: 2023's entry-name clause also names report and screen
items, ISO/IEC 1989:2002 Annex F.2 item 53). One finding is held open (`HELD_OPEN`): `remarks-removed-2002` accepts the
REMARKS paragraph at `--std 85`, which ANSI X3.23-1985 deleted (§1985:A, item 8), answering kb/Work PB1802's item 2; its
fix is a separate behaviour change, filed from this wave's report.

**The band drift.** `lineage.band_drift` derives the band at an older edition from its chains (a rule is at 85 exactly
when a KEPT record carries into it, a bridged one through 2002 and 2014 as well) and measures the stored bands against it;
`inventory_view.py --check` prints it and `--band-drift` lists it. At landing: 96 rules a KEPT chain reaches lack 85 in
their stored band (wrong bands, as the 1989 intrinsic function rules stored `2002,2014,2023`, or wrong KEPT records, as
CONTINUE AFTER's rules KEPT from "CONTINUE has no effect"), 1026 name 85 with no KEPT chain, 149 1985 rules unclassified.

**Branch review round 1 (wave 20261935 C finisher).** R1-1: the audit accepted a whole-clause citation as proof when any
rule under the clause changed, so a window wrongly moving CALL ... USING to 2002 citing `§2023:14.9.4` passed on BY
VALUE's rules. A citation now proves an edge only when EVERY rule it names changes, a `Format n` names the clause's FMT
rule, and either edition's rule carries either edge (a start can rest on a 1985 restriction REMOVED, as UNSTRING's
"Identifier-1 must not be reference modified"); the 27 windows proven only by breadth now cite the rule their edge rests
on (the general format's subclause, or the SR or GR). The construct windows are read in years through the schema, as the
grammar's predicates are (lead R1-3). R1-2: the band rule has one definition, `lineage.chain_bands` (each rule a KEPT
chain reaches and the positions it proves), which `band_drift` is built on and S5's band reader takes the 85 position
from; DESIGN-conformance-suite.md §3.5 says so.

**Branch review round 2 (wave 20261935 C finisher).** R2-1: the round-1 fix moved the breadth one level down. The catalog
holds ONE FMT rule per clause, every format and alternative of the statement, and a CHANGED one proved any construct of it:
`§2023:14.9.4 Format 1` proved CALL ... USING at 2002, and 111 of the 297 proven gates rested on one FMT rule alone. A
general format now proves only a whole diagram's edge (`diagram_bound`: a NEW newer FMT rule a start, an older one REMOVED
an end); 44 windows gained the SR or GR their construct rests on (each `cite.py --check`ed), the PERFORM LOCATION predicate's
comment names §2023:14.9.28.4 GR14 (Format 3 is new in 2023), and the 12 windows the standard states only in a diagram are
held open in `FORMAT_ONLY` (a catalog numbering each format's alternatives would prove them; a lead for the registrar).
Lead R2-2: a general format's proof now has a direction; an SR or GR's has none in the lineage, stated in the docstring.

## Remaining

The `85` token leaves the stored `editions`, and every reader takes the 85 position from `lineage.chain_bands`, when the
band drift is empty. Until then the token is the only 85 position the 1026 unproven rules have, so deleting it now would
place them nowhere. The drift closes by adjudicating its sets, each a band or a record decided through
`record_verdicts.py` against the two texts, never by a script: the 149 unclassified and the disputed rules are slice 4's
fleet adjudication (PB4995), and the 96 unstored rules' KEPT records the refutation PB5008 carries.

**Re-probe (wave 20261977 group B, 2026-11-10, main b91ec90f41).** `inventory_view.py --check`: band 85 drift 113
unstored, 931 unproven, 14 unclassified (the adjudications since landing moved all three), so the `85` token stays. The
suite side of the band rule moved: the generator reads every held edition's rules (`generate.Inputs.older`), a 1985 rule's
band is 85 alone and its test sits in its own clause (`cases/<clause>@1985-<Name>/`, DESIGN-conformance-suite.md §3.5),
where PB4995 item 3 placed 709 witnesses. S5's band reader still takes a 2023 rule's 85 position from the stored token,
until the drift is empty.
