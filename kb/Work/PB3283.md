# PB3283 — a running wave reviewer reads as WAITING FOR REVIEW

`scripts/prune_worktrees.py` lists a DONE branch as WAITING FOR REVIEW while its own wave's reviewer is still running. The reviewer has a `{"kind": "start"}` record at the branch tip in its findings file and no verdict yet. The enqueue unit's step 2 then dispatches a second, duplicate reviewer.

**Measured 2026-10-16**, branch worktree-wf_ff4f514b-355-20 (w1095i, PB1099), tip 35b3a36e7:
- 17:40:36Z: the wave reviewer `w1095i-review-r1` wrote its start record to E:\COBOL-coord\scratch\w1095\review-w1095-i.jsonl.
- About 17:45Z: the enqueue unit's survey listed "WAITING FOR REVIEW ... no review stamp" (E:\COBOL-coord\scratch\enqueue-leads-20261016e\prune2.log).
- 17:46:29Z: the wave reviewer reached its verdict, FINDINGS 3, and stamped the report.
- 17:46:33Z: the enqueue unit dispatched `enqueue-review-worktree-wf_ff4f514b-355-20-r1`. That reviewer re-found the same three findings plus one new one, at about 184k subagent tokens.

**Harm:** a duplicate reviewer costs about 184k subagent tokens per occurrence and produces a second set of findings to reconcile.

**Fix shape (for the implementer to confirm).** The survey reads the findings files (the wave's `review-w<wave>-<letter>.jsonl` and `review-<branch>.jsonl`). A `start` record at the tip with no `verdict` after it reads IN REVIEW (the wave's), not WAITING FOR REVIEW. Optionally age it out after `reviewer_ceiling_min`. Add a self-test row in prune_worktrees.py's fixture set.

**Related:** PB3027 (introduced the WAITING FOR REVIEW lifecycle), PB3084, PB3267 (other WAITING FOR REVIEW classification defects).
