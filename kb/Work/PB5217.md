# PB5217 - in a file whose record descriptions include one with an OCCURS DEPENDING ON table, a WRITE or REWRITE of a different, shorter record sends only the ODO record's current extent and the rest of the record is lost (WRITE R3 PIC X(7) with N = 1 stores ABCDE): SentRecordImage sends the record area through the ODO record's view

**Sites:**

- `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/SequentialIoEmitter.cs` (`SentRecordImage`)
- `src/WiseOwl.Cobol.Compiler/Binding/Model/FileModel.cs` (`TransfersPastRecord`, `AreaRecord`)
- `src/WiseOwl.Cobol.Compiler/Binding/Model/PlaceTable.cs` (`RecordArea`)

**Mechanism.** Without a RECORD clause "the size of each data record is completely defined in the record description entry" (§1985:VII.3.8.4 GR1), and the record a WRITE releases is record-name-1: "The execution of the WRITE statement releases a logical record to the operating system." (§1985:VII.4.7.4 GR7); with RECORD IS VARYING and no DEPENDING ON item, a record with no variable occurrence item is "the number of character positions in the record" (§1985:VII.3.8.4 GR10 b). `SequentialIoEmitter.SentRecordImage` (THE one record-area channel for WRITE and REWRITE, also used by the indexed and relative emitters) sends the image of the whole record area instead of record-name-1 whenever `FileModel.TransfersPastRecord` holds, and that predicate holds for a record narrower than the widest record of a file whose record size does not vary. The area is `PlaceTable.RecordArea`, the widest record's view, and when that widest record holds an OCCURS DEPENDING ON table its image is cut to the table's CURRENT extent (`OdoExtentChars` over the DEPENDING item). The record written is then neither record-name-1 (7 characters) nor the area (10): it is the ODO record's extent (5 when N = 1), and the remaining characters of record-name-1 are lost; a READ returns them as spaces. Same in every organization and at `--std 2023`; WRITE ... FROM and REWRITE take the same channel.

**Rules (every citation checked with `scripts/spec/cite.py --check`).**

- `1985-GR-VII.3.8.4-1` - `§1985:VII.3.8.4 GR1`: "If the RECORD clause is not specified, the size of each data record is completely defined in the record description entry." With §1985:VII.4.7.4 GR7: "The execution of the WRITE statement releases a logical record to the operating system." The record released by WRITE R3 is R3, 7 characters.
- `1985-GR-VII.3.8.4-10` - `§1985:VII.3.8.4 GR10` b: "If data-name-1 is not specified and the record does not contain a variable occurrence data item, by the number of character positions in the record." (the RECORD IS VARYING case of the same defect).
- The relative and indexed RECORD clauses point back to these rules; the indexed probe `wf4.cob` and the relative repro below show the same loss.

**Observed (current main, the build at 3d12682fd2, rerun 2026-11-10).** exit 0: `W 00`, `R 00 [ABCDE  ]`, in all three organizations, and the same at `--std 2023`. The generated WRITE is `CobolFile.WriteShared("OS1::F", CobolString.Window(_redef_R, (int)(0 + 1), 10).Substring(0, CobolTable.OdoExtentChars(CobolTable.Occ(N, _P_5), 1, 6, 4, 1, 0, 1)), ...)`. With R3 PIC X(10), as wide as R's maximum, the record round-trips (`TransfersPastRecord` is false). The refuters' indexed probe `wf4.cob` (R3 = RK PIC X(4) + R3N PIC S9(3), N = 1): WRITE R3 FROM S5 and MOVE S6 TO R3 / WRITE R3 read back `[K0050  ] +0` and `[K0060  ] +0` where the records written were K005 and K006 with -12. `rd6b.cob`: the 19-position record R3 reads back `+00202 +`.

**Expected (from the 1985 text).** `R 00 [ABCDEFG]`: the record written is R3, whose size is its own description's (§1985:VII.3.8.4 GR1), whatever the DEPENDING item of another record of the file holds.

**Fix direction (root cause, CLAUDE.md rule 4).** The record-area image `SentRecordImage` borrows for a record narrower than the area must be the area's CHARACTER WINDOW at its full width, never a record's view of it: an ODO record's current extent describes that record, not the area or another record. Render the area through the shared backing (the window `PlaceTable.RecordArea` already resolves over) without the widest record's ODO cut, and let the runtime cut it to the transferred length, which for a record with no variable occurrence item is record-name-1's own size at 85. Recheck `TransfersPastRecord` against §1985:VII.3.8.4 GR1 and GR10 for each edition in the same change (whether a fixed-length file with records of different sizes transfers record-name-1 or the area is an edition question the design doc should answer), and test WRITE, WRITE FROM and REWRITE of a short fixed record beside an ODO record in each organization.
