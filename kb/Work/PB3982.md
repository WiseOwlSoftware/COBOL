# PB3982 — ZeroTokenRewriter.IsSignOfNextLiteral re-implements the §8.3.3.3.2 2) sign-abuts-digits contiguity test twice instead of calling ArithmeticFormationRules.SignAbuts, and the copy drops the same-line check

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/ZeroTokenRewriter.cs:162` (`ZeroTokenRewriter.IsSignOfNextLiteral`), `src/WiseOwl.Cobol.Frontend/Expressions/ArithmeticFormationRules.cs:195` (`ArithmeticFormationRules.SignAbuts`)

Found by the round-1 review of the PB3962 fix: branch `worktree-wf_53929e80-790-1` (tip `cfa68e93a`; merged head `7ea5182fc`). The
function is on that branch only; on origin/main `ZeroTokenRewriter.cs` has no `IsSignOfNextLiteral`. Source finding:
`E:/COBOL-coord/scratch/review-w20261732-a.jsonl`.

> R1-2 LEAD (low, not blocking at round 1): src/WiseOwl.Cobol.Frontend/Parsing/ZeroTokenRewriter.cs:162 IsSignOfNextLiteral writes its own
> copy of the 8.3.3.3.2 2) sign-abuts-digits contiguity test (twice: sign to digits, comma to fraction) instead of calling
> ArithmeticFormationRules.SignAbuts, which is public in the same assembly and whose doc calls itself THE ONE CONTIGUITY TEST and lists its
> callers; the copy also drops the same-line check.

The rule is §8.3.3.3.2 2): "If a sign is used, it shall appear as the leftmost character of the literal" (cite-checked). The branch
compares `tokens[literal].StartIndex != tokens[index].StopIndex + 1` for the sign-to-digits step and again for the comma-to-fraction
step; `SignAbuts` is the one test and also checks the same-line fact the copy drops.

## Acceptance
- `IsSignOfNextLiteral` calls `ArithmeticFormationRules.SignAbuts` for both steps; add `IsSignOfNextLiteral` to the callers its doc
  lists; a test pins the line-break case (sign last on a line, digits first on the next).
