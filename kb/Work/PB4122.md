# PB4122 — kb/Work/PB1063.md's 'For the next implementer' still says SetBinder.PointerAssignmentReason is the one SET poi

**Sites:** `kb/Work/PB1063.md` (whole: one paragraph of a landed note, 'For the next implementer', lines 113-122 on main, is restated).

Review lead R1-2 (low, round 1) of PB3966. Deleting the `PicCategory.Pointer` arm of `SetBinder.PointerAssignmentReason` leaves a
data-pointer receiver falling to `default: return null` (the SET is valid), while PB1063.md:122 ("For the next implementer", which
`orient.py` prints to every implementer touching SetBinder.cs) still says `PointerAssignmentReason` is the one SET pointer pair rule to
reuse for any pointer stored by SET semantics, data-pointer SR19 included (PB1063.md:113). The reader is then told to extend a rule
that no longer decides SR19. The current owners of SR19 are `PtrBinder.ScreenPointerReceiverRestriction` (SET Format 7) and, for the
ADDRESS OF argument, `PtrBinder.AddressConformanceReason` (§14.8.2.3.2).

**Fix:** restate the paragraph for the current code (landed notes keep their history; the "next implementer" paragraph is the one part
meant to be current). See also the PB2625 paragraph appended 2026-10-30 (its premise is stale for the same reason).

Source: report `w20261769g-PB3966-report.md`, review lead R1-2; PB3966 (landed).
