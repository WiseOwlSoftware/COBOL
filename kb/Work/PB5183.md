# PB5183 - at --std 85 EVALUATE evaluates its selection objects pair by pair and stops at the first false pair, so an object with a side effect (a FUNCTION RANDOM reference) is not evaluated where 1985 evaluates every subject and object first

**Sites:**

- `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/EvaluateEmitter.cs` (`Emit`)
- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/EvaluateBinder.cs` (`BindSelectionObject`, `BindWhenItem`, `Bind`, `ReferencesAFunction`)
- `src/WiseOwl.Cobol.Runtime/Control/DialectBehavior.cs` (`EvaluateObjectsInWhenPhraseOrder`)

**Mechanism.** §1985:VI.6.13.4 GR1 says the statement operates as if each selection subject and each selection object were evaluated and assigned a value, then compared. `EvaluateEmitter.Emit` evaluates the objects inside the if / else-if chain, pair by pair, the 2023 order (no more pairs of a WHEN phrase are evaluated once one is false), with no edition arm. A program whose object has a side effect sees a different sequence at --std 85: the unreached RANDOM reference is never evaluated, so the seed-7 sequence shifts.

Verdict, harm, evidence, repro and observed text are the records'; the rows' verdicts are recorded on another branch.

**Expected (from the 1985 text, the record's).** ONE then OBJECT EVALUATED. §1985:VI.6.13.4 GR1: 'The execution of the EVALUATE statement operates as if each selection subject and selection object were evaluated and assigned a numeric or nonnumeric value', item c giving an arithmetic-expression object 'a numeric value according to the rules for evaluating an arithmetic expression'. So the second WHEN's object FUNCTION RANDOM (5) + 5 is evaluated although the first WHEN is selected; §1985:p.A-64 (RANDOM, 2.35.3): 'If a subsequent reference specifies argument-1, a new sequence of pseudo-random numbers is started' and 'subsequent references without specifying argument-1 return the next number in the current sequence'. The RANDOM after the EVALUATE is then the second number of the seed-5 sequence, the value R1 holds.

**Observed (the record's).** Exit 0, no diagnostic; displays 'ONE' then 'OBJECT SKIPPED' at --std 85 (and at --std 2023, where §2023:14.9.13.4 GR4 requires it): the unreached object is never evaluated, so R2 is the second number of the seed-7 sequence.

**Fix direction (root cause, CLAUDE.md rule 4).** At the editions whose rule evaluates every object first, have the emitter hoist each object's value into a local before the chain (the subjects already are, one SubjectSlot each), chosen in one place in the emitter by the edition.
