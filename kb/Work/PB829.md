# PB829 — OPEN — one catch-all rule, seven closed general formats, no diagnostic anywhere

outside my mechanism" item (c) (`scratchpad/reports/PB487-report.md`). **Every row of the table below was

## ⛔ Why ONE note and not six — the question the brief asked to be answered explicitly

Six notes or one? **One**, because they share more than a shape: they share **one grammar rule**
(`CobolExpressions.g4:15`, whose own comment says *"Shared across all grammars — one rule, one source of
truth"*), **one fix operation** (model the format's real clause list, then replace the catch-all with a NAMED
diagnostic for the residue), and **one trap** (closing a list without first auditing what the grammar does not
yet model rejects legal source — the trap ALIGNED sprang in PB487). Under the owner's
`feedback_fill_by_rows_per_mechanism` an implementer slot is filled per MECHANISM, so six notes would compete
for one slot while hiding that closing the second catch-all is the same operation as the first.

What is NOT shared is the **model gap** — each format lacks different clauses — so each catch-all gets its own
section below with its own inventory row, and a fixer may land them one section per commit.

⚠ **`computerAttributes` is deliberately NOT here.** `SOURCE-COMPUTER. IBM-370 WIBBLE WOBBLE.` is swallowed by a
different mechanism — a `~DOT` token SINK, not `genericClause` — and it contradicts two rows already verdicted
CONFORMS. That is **`kb/Work/PB830`**, filed the same day. PB487's report attributed it to
`CobolSpecialNames.g4:226`, which is not where it happens.

## The rule that makes this a defect

```
$ python scripts/spec/cite.py --check 4.2.2 "An implementation shall provide a warning mechanism that optionally may be invoked by the user at compile time to indicate violations of the general formats and the explicit syntax rules of standard COBOL."
  OK  §4.2.2   (Acceptance of standard language elements)
```

Each of the seven formats below is CLOSED — it enumerates its clauses and admits nothing else — so a word run
the format does not define is a violation of a general format, and §4.2.2 obliges the compiler to be able to
indicate it. Today none of them can: the residue is not merely unflagged, it is **not represented at all**.

## ⛔ The seventh consumer is now the TEMPLATE — copy it, do not re-invent it

PB487's own catch-all **landed closed with train 26** and is on `main` at `35f86874`. It did NOT delete the
`genericClause` reference; it turned it into an **error production**:

```antlr
// CobolData.g4:327 — inside dataDescriptionClause
    | unrecognizedDataClause   // ⛔ LAST — the error production above; refused BY NAME at bind (COBOLNET1941)
// CobolData.g4:344
unrecognizedDataClause
    : genericClause
    ;
```

That is the shape each of the six sections above wants: **recognize the word run so the parser does not die on
it, then refuse it BY NAME at bind with a diagnostic that quotes the words and the §.** It keeps recovery (the
rest of the entry still parses, so the user gets one good error instead of a cascade) and it removes the
silence. Read `CobolData.g4:288-345` before starting — the comment block there records why the alternative must
be LAST and what the ALIGNED trap was.

⛔ **PB487's sweep undercounted.** Its report lists *"four other call sites"* and names FD, FILE-CONTROL,
SPECIAL-NAMES, SOURCE-COMPUTER and the ID paragraph. Measured here: `ioControlClause`'s **inline** alternative
(#4) was missed — it is not a named `xxxClause : genericClause` wrapper, so a grep read by rule NAME skips it —
and SOURCE-COMPUTER is not a `genericClause` site at all (PB830). `feedback_scan_all_similar`: the sweep found
the shape and then enumerated it by the wrong key.

## The rule, and the shape of each fix

```antlr
// CobolExpressions.g4:15 — "Generic clause pattern for vendor/extension hooks.
//                           Shared across all grammars — one rule, one source of truth."
genericClause
    : IDENTIFIER (IDENTIFIER | literal)*
    ;
```

`IDENTIFIER (IDENTIFIER|literal)*` matches any word run, so wherever it sits in an alternative list it is a
total sink for everything the named alternatives missed. Per section, the fixer owes, IN THIS ORDER:

1. **Audit the format first** — render the printed general-format page (`scripts/render-spec-page.py`;
   `feedback_spec_diagrams_render_pdf` — the OCR'd diagrams were systematically lossy toward falsely-restrictive
   syntax) and list every clause the standard defines, including the ones only some editions have.
2. **Model what is missing**, gated per edition where the standard gates it
   (`feedback_edition_gate_sweep`: gating a construct breaks everything compiling it below that edition).
3. **Only then** replace the catch-all with a named diagnostic carrying the clause text and the §, so the
   residue is REPORTED rather than absorbed.

Doing (3) before (1) and (2) rejects legal source silently accepted today, which is a strictly worse defect than
the one this note describes. That ordering is the whole reason PB487 declined to sweep these.

## Sibling sweep — where else a total sink hides

`genericClause` is the named one; the shape is "an alternative that matches an unbounded token run". The two
others found on `main` are `computerAttributes` (`CobolParserCore.g4:497`, `({!objectComputerClauseAhead()}?
~DOT)+` → **PB830**) and the COMMENT-ENTRY family — `dateCompiledContent` / `securityContent` (`~DOT+`,
`CobolParserCore.g4:330,340`) and `remarksContent` (`(IDENTIFIER | STRINGLIT)+`, `:349`). Those last are
**correct and must not be closed**: a comment-entry's content is arbitrary text by definition, so an unbounded
token run is what the standard describes there. That is the distinction a fixer needs — a sink over a
COMMENT-ENTRY is right; a sink over a CLAUSE LIST is this note. Whoever takes it re-runs
`grep -nE "~DOT|IDENTIFIER \(IDENTIFIER" src/Cobol.Net.Frontend/Grammar/**/*.g4` and classifies every hit into
those two piles before touching anything.

## Why `silent` + `under_rejects` and not `rejects_legal_source`

The compiler accepts MORE than the standard defines, never less, so no legal program is refused. The harm is
that a typo inside a closed format — a misspelled clause word, a clause written in the wrong paragraph — is
absorbed without a word and its intended effect never happens. That is the under-rejection half of §4.2.2, and
it is silent by construction.
