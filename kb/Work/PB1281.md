## Measured

### Finding redefines-clause — §13.18.44.3 SR6; SR5 sentence 3 (under-rejects; rows SR-13.18.44.3-6, SR-13.18.44.3-5)

**Mechanism.** redefines-operand-text-capture: DataDescriptionCst.RedefinesTargetName returns dataReference().GetText(), so a qualified or subscripted data-name-2 reaches the binder as concatenated text. It is rejected only when the text happens to name nothing (COBOLNET1654, citing SR4/SR7/SR10, not SR5/SR6), and it BINDS SILENTLY to an unrelated item when the concatenation is itself a declared name.

**Repro.** `01 G. 05 AOFG PIC X(4) VALUE "WXYZ". 05 B REDEFINES A OF G PIC X(4).` DISPLAY B (sr6_aofg.cob).

**Expected, from the standard.** Rejected: SR6 'Data-name-2 shall not be qualified.' (and SR5 'the reference to data-name-2 in the REDEFINES clause shall not be subscripted' for `REDEFINES A(1)`), with a diagnostic naming that rule.

**Observed.** Compiles clean and prints WXYZ - B redefines AOFG. `REDEFINES A OF G` without an AOFG item -> COBOLNET1654 "'B' REDEFINES 'AOFG': data-name-2 does not name a preceding entry ... (SR4/SR7/SR10)"; `REDEFINES A(1)` -> 1654 on 'A(1)'.

**Code site.** src/Cobol.Net.Frontend/Cst/DataDescriptionCst.cs#RedefinesTargetName; src/Cobol.Net.Frontend/Grammar/Core/CobolData.g4#redefinesClause
