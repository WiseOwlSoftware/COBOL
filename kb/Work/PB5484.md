# PB5484 - at --std 85 a size error with no ON SIZE ERROR phrase ends the run unit (EC-SIZE-EXPONENTIATION, EC-SIZE-ZERO-DIVIDE); the 1985 rule says the program continues

UNVERIFIED LEAD: re-probe before fixing.

**Lead, verbatim (wave 20262020 group B, implementer lead; report `w20262020b-PB5186-report.md` "New defects (note-ready)").** "At --std 85 a size error with no ON SIZE ERROR phrase ends the run unit for EC-SIZE-EXPONENTIATION (COMPUTE R = Z ** 0) and EC-SIZE-ZERO-DIVIDE (COMPUTE R = 5 / Z): repro E:\COBOL-coord\scratch\op-20261113\w20262020b\p\probe5.cob and probe6.cob. §1985:VI.6.4.2 GR3 makes the resultant undefined and the program continues. Site: the fatal CobolSizeError raise with checking off (CobolIntrinsics.CheckPowRule6, CobolSizeError.ZeroDivide callers) has no 1985 arm."

**The report's fuller text.** "wrong_answer, crashes (abnormal termination). Repro: `probe5.cob` (`COMPUTE R = Z ** 0`, Z = 0) and `probe6.cob` (`COMPUTE R = 5 / Z`) at `--std 85`: `abnormal run-unit termination: EC-SIZE-... (fatal)`, exit 1, while `ADD 1 TO A` overflow continues. Rule: OK §1985:VI.6.4.2 GR3 "If the ON SIZE ERROR phrase is not specified and a size error condition exists after the execution of the arithmetic operations specified by an arithmetic statement, the values of the affected resultant identifiers are undefined" (the 1985 change record item 45: "the program will continue"). Site: the fatal EC-SIZE raise of `CobolSizeError` with checking off (`CobolIntrinsics.CheckPowRule6`, `CobolSizeError.ZeroDivide` callers) has no 1985 arm; the 2002+ Table 14 fatality is applied at 85. Shares no root with PB5186 (it is the no-phrase disposition, not the exponent screen)."
