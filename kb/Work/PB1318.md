## The rules
```
$ cite.py --check 8.4.3.14.3 'LINAGE-COUNTER may be referenced only in procedure division statements'
  OK  §8.4.3.14.3 1)  (Syntax rules)
$ cite.py --check 14.9.12.2 'identifier-1'
  OK  §14.9.12.2   (General formats)
```
LINAGE-COUNTER is an identifier that may be referenced in any procedure division statement. DISPLAY
identifier-1 has to display it the way it displays any unsigned integer item.

## Site
`src/Cobol.Net.Compiler/CodeGen/Emit/OperandText.cs:536` is
`EmitText.LoudValue("string", "computed expression in a string context")`. That is the fallback for an operand
with no character image. The special-register operand reaches it because its bound form is a computed
expression, a read of the file's linage state, and not a `Place` with a picture. The MOVE path converts through
the receiver's picture, which is why `MOVE … TO W` works.

## What the fixer owes
- LINAGE-COUNTER gets the character image its implicit description implies. Model it as a Place with an
  implicit PICTURE, so every string context (DISPLAY, STRING, INSPECT, a comparison with an alphanumeric) works,
  rather than adding a DISPLAY-only arm. Derive the implicit description from §8.4.3.14 and write down where its
  size comes from; this registrar did not check that clause, so no rule number is given for it here.
- **Sibling sweep:** LINE-COUNTER and PAGE-COUNTER of a report, RETURN-CODE, SORT-RETURN and the other
  special registers of §8.4.3, each in DISPLAY and STRING. One golden per register family.
- Positive golden: `DISPLAY LINAGE-COUNTER` after a WRITE (2023; and 85 if LINAGE is in the 85 subset).

## Landing 2026-09-29 (wave 73, group C — PB1153, PB1199 and PB1318 are ONE mechanism, landed together)

**For the next implementer.**
- `src/Cobol.Net.Compiler/Binding/AlgebraicRange.cs#CounterRegisterDigits/IsCounterRegister` — THE register description (PIC 9(d) DISPLAY) from the ONE capacity; ask it, never match BoundLinageCounterRef/BoundReportCounterRef yourself.
- `src/Cobol.Net.Compiler/CodeGen/Emit/OperandText.cs#AsString` — the counter arm renders the d-digit image; the visitor's loud computed arm is for arithmetic expressions / index-names only.
- `src/Cobol.Net.Compiler/Binding/IntrinsicResultType.cs#IsIntegerOperand`, `RelationComparability.cs#IsNumericIntegerOperand`, `IntrinsicBinder.cs#BindLengthFold/BindByteLengthFold` — the other consumers. Trap: a counter is a BoundComputedOperand, so every "is it an item" switch misses it unless it asks AlgebraicRanges.


**Root.** The binder carries LINAGE-COUNTER, LINE-COUNTER and PAGE-COUNTER as computed operands
(`BoundComputedOperand(BoundLinageCounterRef | BoundReportCounterRef)`) because they are runtime state, but the
standard makes each a DATA ITEM — "a temporary unsigned integer data item of class and category numeric"
(§8.4.3.14.4 GR1, §8.4.3.15.4 GR1; `cite.py --check` OK 1 each) — admitted "in any context where an integer data
item may appear" (§8.4.3.15.3 SR1, OK 1). Every consumer that asked "is this an item" answered no: the string
channel fell to `OperandText`'s loud computed arm (a clean compile, then NotImplementedCobolFeatureException),
`IntrinsicResultType.IsIntegerOperand` refused `PERFORM PAGE-COUNTER TIMES` (COBOLNET1646), the §8.8.4.2.5 relation
screen refused a comparison with an alphanumeric operand as an arithmetic expression (COBOLNET2532), and
`FUNCTION LENGTH(PAGE-COUNTER)` was refused as "a numeric literal" (COBOLNET1627).

**Fix — one statement of the register's description, asked by every consumer.** `AlgebraicRanges` already held THE
capacity (R26/PB1401); it now also answers `IsCounterRegister` and `CounterRegisterDigits` from the same
`CounterCapacity`, so the implicit description is `PIC 9(d) USAGE DISPLAY` with d the capacity's digits — the
determination is written into docs/CONFORMANCE.md beside the capacity (usage DISPLAY because SR1 admits the report
counters wherever an integer item may appear, and only a display/national integer may be a STRING sender,
§14.9.43.3 SR1, or §8.8.4.2.5's numeric operand). Consumers: `OperandText.AsString` (the d-digit zero-filled image —
DISPLAY, MOVE to alphanumeric, STRING, a relation with an alphanumeric operand), `IntrinsicResultType.IsIntegerOperand`
(both entries), `RelationComparability.IsNumericIntegerOperand`, and the LENGTH / BYTE-LENGTH folds (d). The loud
visitor arm now receives only arithmetic expressions and index-names (R16's screen), and its comment says so.

**Witness.** `conformance:85/pb1153_counter_register_character_image` — LINAGE 20 after OPEN OUTPUT + one WRITE:
`02` through DISPLAY (bare and qualified), MOVE to X(4), STRING, a relation with "02", LENGTH 2; the report counters
after INITIATE + GENERATE: `000000000000000001` / `000000000000000002`, MOVE LINE-COUNTER TO X(4) = `0000` (leftmost
four of 18 digits, §14.9.25.4 GR6 a)), STRING, a relation, `PERFORM PAGE-COUNTER TIMES` runs once, LENGTH 18. The
PB1318 repro (`LINAGE IS U-L LINES`, `U-L PIC 9(3)`) now prints `007`. BYTE-LENGTH, a COBOL-2002 function, is witnessed by `conformance:2002/pb1153_counter_register_byte_length` (2 / 18). No negative: LINAGE and the Report Writer
are both COBOL-85.
