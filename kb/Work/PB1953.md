## Found (train 1012, from the w1012k implementer report)

`UniversalCrossingShapeDriftTests` (tests/Cobol.Net.Tests.Conformance, rows UCS01–UCS09) carry a newline in their
data-row display names. `scripts/run_gate_legs.py` partitions the population by display name and selects leg 2 with a
name filter; a name containing a newline matches no filter term, so when leg 1 holds no Conformance case those rows
never run and the population check reports them NEVER RAN (the gate is correctly not green, but the implementer
loses a gate to a tooling hole). They ran in the next gate only because previous reds go to leg 1. The lander's
one-leg mode is unaffected (no partition).

**Repro:** an implementer gate over any diff that touches no conformance corpus file — run
`TestResults/build-local/20261004T135049Z-c38648` in worktree `wf_61172edf-587-5` showed 8 NEVER RAN.

**Code site:** `scripts/run_gate_legs.py` population/partition handling (the leg-2 filter construction). Fix the
selector (select by fully-qualified method name, which carries no newline, or escape the name), not the test names;
pair it with a drift case that holds a newline-named row.
