# PB5239 - at --std 85 a program that contains programs and has no Procedure Division is refused (COBOL2274): SourceUnitShape.Screen applies the 2023 shape [ procedure-division [ program-definition ] ... ] at every edition, where 1985 prints [ procedure-division ] and [ source-program ] ... as separate brackets

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/SourceUnitShape.cs` (`Screen`: the `format.MayContain && procedureDivision() is null` test)
- `src/WiseOwl.Cobol.Frontend/Grammar/CobolParserCore.g4` (`programUnit`, `nestedProgram`: these accept the 1985 shape)

**Mechanism.** §1985:X.2.3.1 prints a source program as identification-division [ environment-division ] [ data-division ] [ procedure-division ] [ source-program ] ... [ end-program-header ]: the Procedure Division and the contained programs are independent optional parts, and §1985:X.2.3.3 GR1 lets a division end at "An Identification Division header which indicates the start of another source program". The grammar accepts that shape, and the edition arms that matter at 85 are right (the IDENTIFICATION DIVISION header is required, division order and duplicates are refused, the end marker is enforced). But `SourceUnitShape.Screen` applies the 2023 format `[ procedure-division [ program-definition ] ... ]` (§2023:10.6.1) with no edition arm, so at --std 85 a program whose Environment or Data Division is followed directly by a contained program is refused. The same lead was recorded in the notes of the row `1985-FMT-IV.5.3.1` (code read slice 01) with no note.

**Found by.** The 1985 code read, slices 39 and 40 (`E:/COBOL-coord/scratch/coderead-85/out-pipe/work-slice-39/w8_noproc_nested.cob`, `E:/COBOL-coord/scratch/coderead-85/out-pipe/work-slice-40/q2.cob`).

None of them is recorded: the code read's non-conforming verdicts of slices 36-56 wait in `E:/COBOL-coord/scratch/coderead-85/pipe-for-register.json`.

**Rules (2 claimed; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-FMT-X.2.3.1` - `§1985:X.2.3.1` (read: DIVERGES, harm: rejects-legal-source): the format prints `[ procedure-division ]` and `[ source-program ] ...` as separate brackets.
- `1985-GR-X.2.3.3-1` - `§1985:X.2.3.3 GR1` (read: PARTIAL, harm: rejects-legal-source): "An Identification Division header which indicates the start of another source program" ends the division before it.


**Observed (the records-85c build of origin/main f2cf36fd15, rerun 2026-11-10).** exit 65: `w8_noproc_nested.cob(6,8): error COBOL2274: PROGRAM-ID 'OUTER': a program definition's contained programs follow its procedure division in the format (...), so a program that contains programs shall have a procedure division (ISO §2023:10.6.1)`. `q2.cob` (an Environment Division followed by a contained program) draws the same COBOL2274.

**Expected (from the 1985 text).** Both translate without a diagnostic (the program has nothing to run; it is the contained program a CALL would reach).

**Fix direction (root cause, CLAUDE.md rule 4).** The shape screen reads the edition's program format: the 2023 nesting `[ procedure-division [ program-definition ] ... ]` is an edition fact, so it belongs in the edition table the screen already consults, with the 1985 format as its other row; a test compiles both repros at 85 and keeps COBOL2274 at 2002 and later (check §2002 and §2014 for where the bracket moved before choosing the row's edition).
