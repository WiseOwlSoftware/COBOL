# PB6032 - the 1985 input-output statement set has no home

**Sites:** the row's record `tests/version-matrix/inventory-1985/1985-GR-III.2-p139.json` (to be written), and `src/WiseOwl.Cobol.Compiler/Binding/Bound/StatementBinder.cs#InputOutputStatement` (line 608 at 196e147f3f): the
one member that classifies a statement as an input-output statement lists the eight statements of §2023:9.1.13.1 (CLOSE,
DELETE in both formats, OPEN, READ, REWRITE, START, UNLOCK, WRITE) and is asked at every edition (line 439, the
§2023:13.4.6.3 SR4 screen).

**The 1985 text:** "The input-output statements are: ACCEPT (with the identifier phrase), CLOSE, DELETE, DISABLE, DISPLAY,
ENABLE, OPEN, PURGE, READ, RECEIVE, REWRITE, SEND, SET (with the TO ON or TO OFF phrase), START, and WRITE"
(§1985:III.2 p139; `cite.py --check` OK). So at `--std 85` the compiler has no member whose set is the edition's own, and
row 1985-GR-III.2-p139 (an UPHELD definitional derivation, `tests/version-matrix/derivation-refutations/lineage-reads-1985-g-03.jsonl`)
cannot name a code location: it stays GAP.

**Where the set is observable at 85:** the refuter's attempt names the USAGE INDEX rule §1985:VI.5.14.4 GR8 ("When a MOVE statement
or an input-output statement that references a group item that contains an index data item is executed, no conversion of
the index data item takes place"): a DISPLAY or ACCEPT of such a group is in the 1985 set and in no 2023-set member. No
wrong answer is known (the run-time does not convert an index item inside a group on any statement), which is why this is
MINOR and process-only today: what it blocks is the row's record, not a program's outcome.

**Fix:** the classification becomes an edition fact: one member answering "is this statement an input-output statement at
this edition" from each edition's own list (2023's eight; 1985's fifteen; 2002/2014 from their own text), asked by the SR4
screen and by any rule that names the term, with a drift test that holds each list to its edition's text. Then record
p139's derivation with that member as its code location (`audit_batch.py derivation-batch --locations`).
