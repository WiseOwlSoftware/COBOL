# PB1541 — OPEN

## The rule

`cite.py --check 9.1.13.1 "remains in effect for all subsequent input-output operations on the file"` → OK §9.1.13.1 — a permanent
error condition, once it occurs, "remains in effect for all subsequent input-output operations on the file" unless the implementor
provides a technique for correcting it (A.1 item 105, optional, documented if provided).

## Repro (`/tmp/adj/doc/doc-w1-s4/probe/p105.cob`; re-probed, `--std 2023`)

```cobol
           SELECT F ASSIGN TO "p105.dat"
               ORGANIZATION RELATIVE ACCESS RANDOM
               RELATIVE KEY RK FILE STATUS FS.
       ...
           OPEN OUTPUT F.
           MOVE 0 TO RK. MOVE "A" TO R.
           WRITE R INVALID KEY DISPLAY "IK".      *> FS = 34
           MOVE 1 TO RK.
           WRITE R INVALID KEY DISPLAY "IK".      *> FS = 00
```

Observed: `OPEN 00` / `WRITE0 34` / `WRITE1 00` / `CLOSE 00`. Expected: after the '34' the permanent error remains in effect, so the
second WRITE is unsuccessful too (unless a documented correction technique — e.g. "CLOSE and re-OPEN" — is the determination, in
which case a 'Not provided.' row cannot be written and the row must state the technique).

## Code site

`src/Cobol.Net.Runtime/IO/FileConnector.cs` (~l.391): no connector records a permanent-error state; the only persisted per-connector
error state is the '46' poison (§14.9.30.4 GR21). Decide the technique (the natural one is CLOSE — a successful CLOSE ends the
connector's state), implement the persistence, then write DOC-A.1-105.
