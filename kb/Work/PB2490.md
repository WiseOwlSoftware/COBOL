# PB2490 — OPEN

Filed 2026-10-07 by the train-1034 lander from the wave-1034 group E implementer report (`w1034e-PB1966-report.md`,
"New defects"; the implementer did not file it).

**Shape.** PB1914 (landed in train 1034) made `LogicalLineBuilder.EmitDebugging` pass a debugging line over, like a comment
line (§6.3.5 2) "Comment lines and blank lines may be interspersed among lines containing the parts of a literal"), while
the line before it leaves a literal awaiting continuation, because the walk runs BEFORE the source unit's WITH DEBUGGING
MODE clause is read. Without the clause that is right (the line is a comment; GnuCOBOL agrees). WITH the clause the line
is source, so the next `-` line no longer continues the literal: GnuCOBOL 3.2.0 with `-fdebugging-line` rejects the
program, this compiler joins the literal and accepts it. docs/CONFORMANCE.md D-DEBUG records the shape as non-conforming
and not diagnosed.

**Repro.** `E:\COBOL-coord\scratch\w1034e\p\dc_on.cob --std 85` compiles clean; expected a diagnostic.

**Code site.** `src/Cobol.Net.Frontend/Preprocessor/ReferenceFormatProcessor.LogicalLineBuilder.cs#EmitDebugging` (the
pass-over arm) and `DebuggingLineRewriter` (which keeps or hides each carrier once the mode is known). Fix shape: the
builder marks a passed-over carrier, and the rewriter reports it when it KEEPS that carrier (the mode is on).
Obsolete facility (debugging lines are absent from ISO 2023), hence MINOR.
