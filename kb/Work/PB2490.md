# PB2490 - LANDED (wave 1059 group A)

## Landing (wave 1059 group A, 2026-10-11)

**Re-probe (before):** `E:\COBOL-coord\scratch\w1034e\p\dc_on.cob --std 85` compiled clean. **After:**
`dc_on.cob(8,7): error COBOL3473` at every edition (at 2014+ beside the existing COBOL0902 on the same line).

**Rule.** ISO 6.3.5 2): "Comment lines and blank lines may be interspersed among lines containing the parts of a literal" (`cite.py
--check 6.3.5 "Comment lines and blank lines may be interspersed among lines containing the parts of a literal"` -> OK 6.3.5 2)). A
debugging line under WITH DEBUGGING MODE is source (D-DEBUG), so it is outside that allowance; ISO 2023 has no D indicator, so
the choice follows rule 1's precedence to GnuCOBOL 3.2.0 (`-fdebugging-line`: "continuation character expected"). Without the clause
the line is a comment and the literal is joined (the existing PB1914 goldens, unchanged).

**Fix (the shape the note proposed, with the registry in the per-compilation diagnostics object).**
- `LogicalLineBuilder.EmitDebugging`'s pass-over arm NOTES the physical (file, line) to `ReferenceFormatDiagnostics.NoteDebuggingLineBetweenLiteralParts`.
- `DebuggingLineRewriter.Rewrite(tokens, sourceLines)` also names the markers of the lines it keeps as SOURCE (the region lines
  it asks the frontend to blank are returned the old way and collected by the caller, since their marker is gone after the re-lex).
- `Frontend.LexAndParse` returns those lines (the final attempt's, plus the blanked region lines); `Frontend.Parse` maps their
  tokens through the pass's `SourceLineMap` to origins and calls `ReferenceFormatDiagnostics.OnSourceDebuggingLines`, which reports
  COBOL3473 (new `DiagnosticCatalog.DebuggingLineBetweenLiteralParts`) for each noted one, at the line's indicator. It reports from
  `Parse`, not from the lex attempt, because each attempt's diagnostics bag is discarded but the last.

Both continuation arms are covered (an open literal; a floating continuation awaiting its line - one pass-over arm). Goldens:
`negative/pb2490-debugging-line-between-literal-parts-source` (85 2002 2014 2023, `(18,7): error COBOL3473`); units
`LogicalLineBuilderTests.DebuggingLine_PassedOverInALiteral_IsDiagnosedOnlyWhenItIsSource`, `..._OutsideALiteral_IsNeverDiagnosed`,
`DebuggingLineRewriterTests.Rewrite_NamesTheDebuggingLinesThatAreSource_PerUnit`; `DiagnosticPositionTests.SourceDebuggingLine_BetweenLiteralParts_InACopybook_IsDiagnosedAtItsOwnLine`
(the copybook is named by its own file and line; the same program without the clause is accepted).

LEARNED: the D line's verdict (comment or source) is only known after the whole text is lexed, so anything that must depend on it travels
as an ORIGIN (physical file and line) from the §6.5 walk (`ReferenceFormatDiagnostics.NoteDebuggingLineBetweenLiteralParts`) to the
front end, never as a resultant line number (COPY and REPLACE move those). `Frontend.cs#LexAndParse` returns the source debugging lines;
the report is made in `Parse` because `LexAndParse` attempts discard their bags. `docs/CONFORMANCE.md` D-DEBUG records the choice.

# PB2490 — OPEN

Filed 2026-10-07 by the train-1034 lander from the wave-1034 group E implementer report (`w1034e-PB1966-report.md`,
"New defects"; the implementer did not file it).

**Shape.** PB1914 (landed in train 1034) made `LogicalLineBuilder.EmitDebugging` pass a debugging line over, like a comment
line (§6.3.5 2) "Comment lines and blank lines may be interspersed among lines containing the parts of a literal"), while
the line before it leaves a literal awaiting continuation, because the walk runs BEFORE the source unit's WITH DEBUGGING
MODE clause is read. Without the clause that is right (the line is a comment; GnuCOBOL agrees). WITH the clause the line
is source, so the next `-` line no longer continues the literal: GnuCOBOL 3.2.0 with `-fdebugging-line` rejects the
program, this compiler joins the literal and accepts it. docs/CONFORMANCE.md D-DEBUG records the shape as non-conforming
and not diagnosed.

**Repro.** `E:\COBOL-coord\scratch\w1034e\p\dc_on.cob --std 85` compiles clean; expected a diagnostic.

**Code site.** `src/WiseOwl.Cobol.Frontend/Preprocessor/ReferenceFormatProcessor.LogicalLineBuilder.cs#EmitDebugging` (the
pass-over arm) and `DebuggingLineRewriter` (which keeps or hides each carrier once the mode is known). Fix shape: the
builder marks a passed-over carrier, and the rewriter reports it when it KEEPS that carrier (the mode is on).
Obsolete facility (debugging lines are absent from ISO 2023), hence MINOR.
