# PB4508 — the up-front CALL judgement runs before the NULL screen

**Found:** 2026-11-03, PB4503's round-2 branch review (lead R2-1, not blocking). PB4503 added an up-front judgement of
the Format-2-only spellings below 2002 (`CallBinder.cs`, `judgedUpFront`). It runs `Format2OnlySpellingOf` /
`Format1Narrowing` on every argument BEFORE the argument loop's NULL screen, reversing the order PB4155 set and that
the loop's own comment ("asked BEFORE the Format-1 narrowing") still states.

At 85 NULL is not a reserved word, so an undeclared NULL is an undefined user word (an identifier-2, a Format 1
spelling): the right diagnostic is the undefined-name one alone. The up-front pass first judges it as a literal-2 the
edition lacks, so the user gets a second, misleading refusal.

**Fix.** One order for both passes: the NULL screen (and any other "what IS this word" question) before the edition
narrowing, with the comment true again; a test at 85 that an undeclared NULL draws exactly the undefined-name
diagnostic.

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CallBinder.cs` (`IsUndeclaredNullWord`, the one reader of the
free-NULL verdict; `Format2OnlySpellingOf`, which names no Format-2 spelling for it; the argument loop's NULL screen),
`tests/WiseOwl.Cobol.Tests.Conformance/FormatOneVendorCallPermissiveTests.cs` (`UndeclaredNull_At85_DrawsTheUndefinedNameAlone`,
`UndeclaredNull_ByValue_At85_KeepsThePhraseRefusalBesideTheUndefinedName`).

## Landing (wave 20261850 C)

The fix is in `IsUndeclaredNullWord` and `Format2OnlySpellingOf` rather than a reordering of the two passes, so the verdict
holds in either order. See this branch's DEVLOG entry.
