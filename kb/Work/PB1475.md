## Finding — `types` (under-rejects; rows `GR-8.5.3.1-2`)

**Mechanism.** Type-declaration equivalence (StrongTypeModel.SameAnalyzedProfile) relies on PicInfo record equality to carry §8.5.3.1 exception 2's DECIMAL-POINT IS COMMA condition, but PictureAnalyzer's numeric-edited profile is NOT DPC-resolved (Scale comes from 'V' only, the mask is stored verbatim), so the same edited picture text containing '.' or ',' compares equal across a DPC boundary

**Repro.** Two outermost programs in one file. TPOC: SPECIAL-NAMES (no DECIMAL-POINT IS COMMA); REPOSITORY. PROGRAM TPOS.; 01 T1 TYPEDEF STRONG. 05 F PIC 9.99.; 01 A TYPE T1.; MOVE 1.5 TO F OF A; CALL TPOS USING A. TPOS: SPECIAL-NAMES. DECIMAL-POINT IS COMMA.; 01 T1 TYPEDEF STRONG. 05 F PIC 9.99.; 01 N PIC 9(5)V99.; LINKAGE 01 L TYPE T1.; PROCEDURE DIVISION USING L. MOVE F OF L TO N; DISPLAY N. Pinned compiler: compiles clean, prints N=0015000.

**Expected from the spec.** §8.5.3.1 2): period picture symbols match only if DECIMAL-POINT IS COMMA is in effect for both or for neither declaration, so the two T1 declarations are not equivalent, A and L are not of the same type, and §14.8.2.2 ('If either the formal parameter or the corresponding argument is a strongly-typed group item, both shall be of the same type') makes the CALL a compile-time error (COBOLNET1688). A picture with no period/comma symbol must still match.

**Observed / reasoning.** TPO and TPS (both orientations) accepted; TPU runs and turns the caller's 1.50 into 150.00 in the callee. TPB (9.99 vs 9,99) is rejected only because the mask text differs, and TPC/TPK/TPL/TPM/TPN (no '.'/',' symbol, or DPC on both) behave correctly. Fix shape: make the DPC setting part of the analyzed profile for a picture that contains a period or comma symbol (or compare it explicitly in SameAnalyzedProfile), and correct the doc comment's false premise.

**Code site.** src/Cobol.Net.Compiler/Binding/Model/StrongTypeModel.cs#SameAnalyzedProfile (doc bullet 'Exception 2'); src/Cobol.Net.Compiler/Binding/PictureAnalyzer.cs (afterV / NumericEdited PicInfo, ~L324 and ~L433)

## Finding — `types` (rejects-legal-source; rows `GR-8.5.3.1-2`)

**Mechanism.** §8.5.3.1 exception 2's LOCALE identity is compared by synthesized record equality of LocaleEditSpec/LocaleRef/LocaleSymbol, which includes the locale-NAME and literal-vs-word form, instead of the external identification (LocaleSymbol.SameLocaleAs) that OoConformance's BY REFERENCE arm already uses - one rule, two mechanisms

**Repro.** Two outermost programs. Caller: SPECIAL-NAMES. LOCALE LA IS "fr_FR".; REPOSITORY. PROGRAM TPFS.; 01 T1 TYPEDEF STRONG. 05 F PIC +$9(5).99 LOCALE LA SIZE 16.; 01 A TYPE T1.; CALL TPFS USING A. Callee TPFS: SPECIAL-NAMES. LOCALE LB IS "fr_FR".; 01 T1 TYPEDEF STRONG. 05 F PIC +$9(5).99 LOCALE LB SIZE 16.; LINKAGE 01 L TYPE T1.; PROCEDURE DIVISION USING L. Pinned compiler: COBOLNET1688 'both shall be of the SAME type'.

**Expected from the spec.** §8.5.3.1 2): locale specifications match iff same SIZE phrase and 'both specify the LOCALE phrase with the same external identification, where the external identification is the external-locale-name or literal value associated with a locale-name' - the locale-NAME is not part of the test; the declarations are equivalent and the CALL conforms (compiles and runs).

**Observed / reasoning.** TPF rejected; TPJ (same name LA, same literal) accepted, so only the name differs. SameAnalyzedProfile compares PicInfo.LocaleEdit via record equality; LocaleSymbol is a positional record over (Name, External, FromLiteral). Fix: compare LocaleEdit through the one identity (Size, Picture, IsCurrent, SameLocaleAs) - ideally by giving LocaleEditSpec/LocaleRef value equality defined on that identity so both consumers read one predicate.

**Code site.** src/Cobol.Net.Compiler/Binding/Model/StrongTypeModel.cs#SameAnalyzedProfile; src/Cobol.Net.Compiler/Binding/Model/LocaleSymbol.cs#LocaleEditSpec/LocaleRef/LocaleSymbol

## What the fixer owes

Make exception 2 ONE explicit comparison in SameAnalyzedProfile: DPC state is part of the profile for a picture containing a period or comma symbol; the locale half compares (Size, Picture, IsCurrent, LocaleSymbol.SameLocaleAs) — the identity OoConformance's BY REFERENCE arm already uses — ideally by giving LocaleEditSpec/LocaleRef value equality defined on that identity so both consumers read one predicate. Correct the doc comment's false premise. Goldens TPO/TPS/TPU (COBOLNET1688) and TPF (compiles and runs).
