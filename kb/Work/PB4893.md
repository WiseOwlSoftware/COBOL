# PB4893 - the diagnostic-free returning-item question cannot answer for SELF, an object view or INVOKE RETURNING

**What the report says (the reviewer's words).** R1-2 LEAD (low):
`src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/OoBinder.InlineInvocation.cs:299` `InlineInvocationReturningItem` answers
null for a SELF or object-view receiver and an INVOKE RETURNING is not asked, so those statements still draw a class diagnostic
beside COBOL0900 (the two SET cases regress against the deleted `BindSetTo` hook). Not fixed: needs diagnostic-free
current-class/view resolution (OoBinder `host.OoCurrentClass`, factory vs instance, SUPER, AS views), a redesign beyond that
slice. The PB4866 implementer's "New leads" repeats it.

**Still true on main (read, 2026-11-06).** The summary of `InlineInvocationReturningItem` says a receiver it cannot resolve
without binding (a universal, interface or ACTIVE-CLASS reference, SELF, an object view, a computed receiver) answers null.
PB4868 (landed) built the funnel `StatementBinder.NamesGatedMessageTag` and this method, and records the null answer as the
design; no open note holds the SELF, object-view and INVOKE RETURNING arms.

**Also (R2-4 LEAD, info).** The doc comment of `InlineInvocationReturningItem` (`OoBinder.InlineInvocation.cs:291`) still
carries a stray closing parenthesis after "RETURNING item" (the sentence opens "(§2023:8.4.3.4.4 GR1 b): the temporary takes the
description of the invoked method's RETURNING item)"); R1-3 fixed the rule letter only. The rule letter was re-checked by the
reviewer (`cite.py --check` passes on GR1 b)). The fix to this paragraph is the same edit as the site's.

**Not probed here.** The clerk reproduced nothing.

**Landed (wave 20261911 C).** Re-probe on the Debug build at 2014 before the change, one statement each beside COBOL0900:
`SET N TO SELF :: "MGET" (N)` drew COBOL0869; `MOVE SELF :: "MGET" (N) TO N`, `MOVE SELF AS MTP :: ...`, `MOVE MTP :: "FGET"`
(a class-name receiver) and `MOVE I :: "MGET" (N)` (an interface-typed receiver) COBOL0809; `SET N TO U AS MTP :: ...` COBOL0869;
every INVOKE ... RETURNING N of a tag-returning method (typed, SELF, a view, a class-name, a FACTORY OF reference, an interface)
COBOL0828; and the sibling the note did not name, an argument whose same-file FORMAL is a tag, `INVOKE O "MSET" USING N` and
`O :: "MSET" (N)` COBOL0828 and `FUNCTION MTF2(N)` COBOL2470. Only a FACTORY OF receiver of an inline invocation was already gated.

Fix: the funnel's question is now "does the statement name a gated tag, or ACTIVATE a function or method whose signature (RETURNING
item or a formal) has one". `OoBinder.InvokedMethodsOf` (inline, segment by segment) and `InvokedMethodOf` (INVOKE) select the method
without binding or reporting, through every receiver `OoBindByReceiver` takes: an object view's last AS phrase (`ViewRoster`, now also
the property-object probe's), SELF and SUPER through `OoPredefinedSearchRoot(report: false)` over the containing method's factory or
instance interface, a function-identifier's RETURNING item, a data item's descriptor (ACTIVE-CLASS and interface included), a
class-name's factory interface, and a previous segment's returned reference. A concatenated method name folds through
`ConcatFolder.Peek`, so the probe reports nothing. `IntrinsicBinder.ReturningItemOf` became `SignatureOf` (every caller moved).
The roster lookup itself moved to ONE type, `MethodRoster.Find`, keyed by the externalized name on every arm: the interface arm of
`OoBindInstanceInvoke` compared method-name-1, so `INVOKE I "Y"` of a prototype `METHOD-ID. X AS "Y"` was refused COBOL0825 (legal
source, §2023:14.9.23.4 GR2a; §2023:11.7.4 GR1b), fixed here; the seven `factory ? FindFactoryMethod : FindMethod` sites ask it, and
`MethodRosterLookupDriftTests` refuses a new one. The R2-4 stray parenthesis went with the deleted method's doc comment.

Not fixed (registered in the report): CALL Format 2 (`CALL "SUBN" AS NESTED USING N`, a nested program whose formal is a tag) still
draws COBOL1688 beside COBOL0900; its callee signature has no diagnostic-free reader (literal-1 is read through
`ExpressionBinder.NonNumericLiteralOperand`, which reports).

Witnesses: `MessageTagIntroductionGateTests.AStatementActivatingASignatureWithATag_IsTheGateAloneBelowTheIntroduction` (19 statements
at 2014 and 2023), `conformance-suite/cases/14.9.23-INVOKE/pb4893-interface-externalized-method-name` (accepted from 2002) and its
`-at-85` refusal, `MethodRosterLookupDriftTests`.
