# PB4893 - the diagnostic-free returning-item question cannot answer for SELF, an object view or INVOKE RETURNING

**What the report says (the reviewer's words).** R1-2 LEAD (low):
`src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/OoBinder.InlineInvocation.cs:299` `InlineInvocationReturningItem` answers
null for a SELF or object-view receiver and an INVOKE RETURNING is not asked, so those statements still draw a class diagnostic
beside COBOL0900 (the two SET cases regress against the deleted `BindSetTo` hook). Not fixed: needs diagnostic-free
current-class/view resolution (OoBinder `host.OoCurrentClass`, factory vs instance, SUPER, AS views), a redesign beyond that
slice. The PB4866 implementer's "New leads" repeats it.

**Still true on main (read, 2026-11-06).** The summary of `InlineInvocationReturningItem` says a receiver it cannot resolve
without binding (a universal, interface or ACTIVE-CLASS reference, SELF, an object view, a computed receiver) answers null.
PB4868 (landed) built the funnel `StatementBinder.NamesGatedMessageTag` and this method, and records the null answer as the
design; no open note holds the SELF, object-view and INVOKE RETURNING arms.

**Also (R2-4 LEAD, info).** The doc comment of `InlineInvocationReturningItem` (`OoBinder.InlineInvocation.cs:291`) still
carries a stray closing parenthesis after "RETURNING item" (the sentence opens "(§2023:8.4.3.4.4 GR1 b): the temporary takes the
description of the invoked method's RETURNING item)"); R1-3 fixed the rule letter only. The rule letter was re-checked by the
reviewer (`cite.py --check` passes on GR1 b)). The fix to this paragraph is the same edit as the site's.

**Not probed here.** The clerk reproduced nothing.
