## Mechanism — blank-when-zero-clause
bwz-gr2-national-not-promoted - the GR2 promotion predicate hard-codes usage display. PictureAnalyzer.cs:345 reads `if (anyEdit || (blankWhenZero && digits > 0 && !signed && usage is Usage.Display))`, but SR2 admits the subject as usage display OR usage national, and GR2's own condition is only that the picture character-string be category numeric. A national-usage numeric subject therefore falls through to the plain-numeric return at PictureAnalyzer.cs:356 and is never defined numeric-edited - which would silently cost it GR1's blanking, the numeric-edited VALUE rules, the arithmetic-operand refusals of 8.8.1.1 / 14.9.2.3 SR2 and the de-editing MOVE. This is a scalar-condition-where-the-rule-names-a-SET shape: the predicate encodes one of the two usages SR2 lists.

### Expected, from the standard
ISO/IEC 1989:2023 13.18.8.4 GR2 - "If the subject of the entry is described by its picture character-string as category numeric, the BLANK WHEN ZERO clause defines the item as numeric-edited." - read with 13.18.8.3 SR2, which admits usage display OR usage national (both validated with scripts/spec/cite.py --check). WS-NAT is category numeric by its picture character-string and legal by SR2, so the clause defines it numeric-edited and GR1 blanks it on a zero store.

```
$ python scripts/spec/cite.py --check 13.18.8.4 "If the subject of the entry is described by its picture character-string as category numeric, the BLANK WHEN ZERO clause defines the item as..."

```
