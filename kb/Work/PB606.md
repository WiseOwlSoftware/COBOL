# PB606 — LANDED (wave 54 group F)

Raised 2026-09-05 by the `PB233` implementer, which fixed the activation-boundary half of §14.9.4.4 GR3i (a
callee's own failure no longer runs the activator's ON EXCEPTION phrase) and read the SECOND sentence of the
same rule against the emitter's ordering without running the probe, because the answer for a nonfatal
condition turns on an adjudication. Filed as `process_only` until the probe says otherwise
(`feedback_reachability_is_measured_not_deduced`).

## The rule

`python scripts/spec/cite.py --check 14.9.4.4 "If an exception condition is propagated from the called
program, execution continues as specified in 14.6.13.1, Exception conditions; otherwise, control is transferred
to the end of the CALL statement or, if the NOT ON EXCEPTION phrase is specified, to imperative-statement-2"`
→ run it first (the implementer's paraphrase, which dropped the clause title after "14.6.13.1", does NOT
`--check`; the sentence above is copied from the transcription at GR3 i) and is the one to validate).

The two outcomes are joined by "otherwise": a propagated condition takes the §14.6.13.1 path, and only the
absence of one reaches imperative-statement-2.

## The question

`src/Cobol.Net.Compiler/CodeGen/Verbs/CallEmitter.cs#EmitCall` emits the ON/NOT ON phrase dispatch and THEN
`EmitPropagationPickup()`. For a FATAL propagated condition the pickup terminates or transfers to a declarative
regardless, so any NOT ON body already executed would be a visible wrong answer. For a NONFATAL propagated
condition, §14.6.13.1.4 #4's continuation may itself resolve to "control is transferred to the end of the CALL
statement or to imperative-statement-2" — in which case running the NOT ON body is right and only the ORDER
relative to the declarative (if any) is in question. `kb/Work/PB408` (GOBACK RAISING asks the callee whether
checking is enabled where GR1b asks the activator) sits on the same propagation path and may change which
conditions reach the pickup at all; land after it or with it.

## The probe

A callee ending `GOBACK RAISING EC-USER-X` (declared in the activator's PROCEDURE DIVISION RAISING) under
`>>TURN EC-USER-X CHECKING ON` in the activator, called with `NOT ON EXCEPTION DISPLAY "NOT-RAN"` and a USE
declarative that displays the status: record (1) whether `NOT-RAN` appears, (2) whether it appears before or
after the declarative's output, (3) the same with a FATAL propagated condition. Then adjudicate against GR3i's
second sentence and §14.6.13.1.4 #4: if the fatal case prints `NOT-RAN`, that is a `wrong_answer` defect and
this note converts to `kind: defect` with the fix (emit the pickup BEFORE the phrase dispatch, or fold the
"propagated" test into the phrase selection); if only the nonfatal ordering differs, record the determination
in `docs/CONFORMANCE.md` and close.

## MEASURED — REGISTRAR #12 (2026-09-22, main `37f19e028`)

the CALL's own staged propagation (the staging names the same activator). Sweep INVOKE (`OoEmitter`'s pickup) and the
inline method / function activations for the same order. Golden: p5 at 2014 plus the INVOKE twin.
