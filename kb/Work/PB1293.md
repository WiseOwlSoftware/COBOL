## Measured

### Finding source-clause — ISO §13.18.53.3 SR2, SR8; §14.9.25.3 SR9, SR10 (crashes; rows SR-13.18.53.3-2, SR-13.18.53.3-8)

**Mechanism.** The SOURCE clause's implicit MOVE is never run through the MOVE statement's validity chain (MoveTable16.Validity / the §14.9.25.3 SR9 variable-length-group compatibility check), so SR2 and SR8 violations compile

**Repro.** probe out13/probe/source-clause/n4.cob: `01 WS-NUM PIC 9(3) VALUE 5.` and RD entry `05 COLUMN 12 PIC A(2) SOURCE WS-NUM.` (n4b: `PIC 9(2) SOURCE WS-AL` over `01 WS-AL PIC A(3)`). n5b.cob: `01 WS-VG2. 05 WS-VD PIC X DYNAMIC LENGTH.` and `05 COLUMN 12 PIC X(2) SOURCE WS-VG2.`

**Expected, from the standard.** §13.18.53.3 SR2 requires a MOVE from identifier-1 to the printable item to be valid; §14.9.25.3 SR10 Table 16 makes numeric-integer -> alphabetic and alphabetic -> numeric 'No', so n4/n4b are compile-time errors. §13.18.53.3 SR8 forbids a variable-length group (§8.5.1.12.1) as identifier-1, so n5b is a compile-time error.

**Observed.** n4 and n4b compile clean and print `00`. n5b compiles clean and aborts at GENERATE with NotImplementedCobolFeatureException ('whole-group image of 'WS-VG2' with a dynamic-length / dynamic-capacity member'). Controls: the same MOVEs in the procedure division are refused COBOLNET0819 (n4c) and COBOLNET1931 (n5c). MoveTable16 has callers in MoveBinder, InitializeBinder, CorrespondingBinder and AcceptDisplayBinder but none in DataBinder.Reports.cs; the fix is to ask the one validity chain with identifier-1 as sender and the printable item as receiver once FieldDataSource.Item resolves (the SUM clause's printable face, §13.18.54.3 SR2, is the sibling to sweep).

**Code site.** src/Cobol.Net.Compiler/Binding/DataBinder.Reports.cs#ResolveReports (FieldDataSource case); src/Cobol.Net.Compiler/Binding/MoveTable16.cs#Validity
