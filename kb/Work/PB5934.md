# PB5934 - OursIn never climbs into a base declared in an assembly that cannot name the mark

**Sites:** `src/WiseOwl.Cobol.Analyzers/EditionCiteAnalyzer.cs#OursIn` (line 126), `#Bases` / `#AllBases` (line 100),
`tests/WiseOwl.Cobol.Tests.Unit/EditionCiteAnalyzerTests.cs#ADerivedOverrideOfAFrameworkMember_LeavesTheFrameworkMemberAlone` (and a new planted test beside it).

**The lead (PB4950 review round 12, R12-1, low, latent).** `OursIn(compilation)` returns this compilation's assembly plus every referenced assembly
that (a) declares a type named `EditionDerivedAttribute` (`assembly.TypeNames.Contains(AttributeName)`) or (b) references one that does. Round 12
introduced it so that derivation does not climb into the framework (R11-1: one edition-derived `object.GetHashCode` override made every unrelated
read of that member an unsuppressible WOCA0001). The line it draws is wrong for BASES: a base climb needs no derived value in the base's assembly, the
derived member is the implementation in the compilation being analysed. So a product library whose emitted metadata does not reference
`WiseOwl.Cobol.Runtime` loses the round-11 detection of a read made through a base. That covers `WiseOwl.Cobol.Listing` (it references no project) and
any project whose Runtime `ProjectReference` is unused in IL (the C# compiler drops an unused reference from metadata). The doc comment's premise "an
assembly that cannot name it holds nothing to derive" is true of declarations, not of bases.

**Still true on origin/main (0d4042678a), read this session.** `EditionCiteAnalyzer.cs:125-131`: `OursIn` is unchanged since round 12 (commit
`3d9fbfa87a`), `git log -3 origin/main -- src/WiseOwl.Cobol.Analyzers/EditionCiteAnalyzer.cs` shows no later change. `src/WiseOwl.Cobol.Listing/`
holds no project reference (`WiseOwl.Cobol.Compiler.csproj:35` references it, not the other way). The lead's latency claim is the reviewer's:
Listing declares no interface, abstract or virtual member today, so nothing is missed yet; not re-derived here.

**Fix shape (the structure, not the smallest diff).** Decide "ours" by what makes an assembly ours (it is built from this repository: the
`WiseOwl.Cobol.*` assembly-name root, or a mark the build writes into every product assembly such as an `AssemblyMetadata`), never by "can it name
the attribute". The set must come from the compilation's references as today (no list of names), and a planted test must put an edition-derived
override over a base in a product library that references nothing, red under today's `OursIn` and green with the fix, beside
`ADerivedOverrideOfAFrameworkMember_LeavesTheFrameworkMemberAlone` (the framework must stay alone).
