# R29 — adjudicate: an index-name as an ARITHMETIC operand computes silently

Split from R16's landing (2026-08-08). R16 closed the crash band (DISPLAY/MOVE/STRING/UNSTRING/INSPECT →
COBOLNET1637) — but `COMPUTE N = IX + 1` still compiles and computes 3 (probe-verified), though §13.18.38.3
r7's closed context list has no arithmetic-expression entry and §8.8.1.1 does not name index-names among
arithmetic operands. This is the classic vendor extension (GnuCOBOL accepts index-name arithmetic), so the
disposition wants the PB1/DA6 shape: strict = reject with the r7 citation, `--permissive` = accept as the
documented coercion (the occurrence number).

**Why not folded into R16:** the screen must live in `ExpressionBinder.RefExpr`'s index arm, which ALSO
serves the r7-LEGAL numeric consumers (relation conditions at least; possibly SET amounts and
PERFORM/SEARCH VARYING operands, depending on which OperandContext those bind under) — the arm needs a
context audit before any rejection, or legal source breaks. Survey first
(feedback_survey_compilers_on_latitude), then thread the context.

## LANDED 2026-08-08 (adjudicated + implemented)

THE AUDIT the note demanded, complete: every `BindExpr`/`BindOperandExpr` caller enumerated and
classified. The r7-window callers — the D18 subscript fragment, PERFORM VARYING FROM/BY, every SET
amount/value (index, pointer, CAPACITY, SIZE), RW VARYING, EVALUATE computed operands, and the relation
comparison-operand arm — now bind under the new **`OperandContext.ArithmeticIndexWindow`**
(`BindIndexWindowExpr`), identical §8.8.1.1 screening, index-names admitted. The TRUE arithmetic
positions (COMPUTE and the arithmetic verbs, RETRY, CONTINUE AFTER, STOP/GOBACK STATUS, boolean SHIFT
amounts, sign conditions, compound function-argument expressions) keep `Arithmetic`/`FunctionArgument`,
where the new `IndexNameExpr` interception applies the adjudicated PB1/DA6 disposition: **strict =
COBOLNET1637 with the r7 citation; `--permissive` = warning + the documented occurrence-number
coercion.** CallByValue keeps its own SR22 screen (not intercepted).

Probes: `COMPUTE N = IX + 1` strict errors / permissive warns and prints 0003; the windows all stay
green end-to-end — `T(IX + 1)`, `SET IX UP BY 1`, bare and compound relation operands, `PERFORM VARYING
V FROM IX`. Goldens: negative `index-name-arithmetic` (reject-at 85 2002 2014 2023) + positive
`index_name_r7_windows` (85 — the over-rejection guard for the context threading). Gate: Conformance
Corpus|Intrinsic 662/662 · both cases green by name · FULL Unit 4099/4099 · characterization 33/33.
