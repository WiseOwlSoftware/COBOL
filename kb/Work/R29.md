# R29 — adjudicate: an index-name as an ARITHMETIC operand computes silently

Split from R16's landing (2026-08-08). R16 closed the crash band (DISPLAY/MOVE/STRING/UNSTRING/INSPECT →
COBOLNET1637) — but `COMPUTE N = IX + 1` still compiles and computes 3 (probe-verified), though §13.18.38.3
r7's closed context list has no arithmetic-expression entry and §8.8.1.1 does not name index-names among
arithmetic operands. This is the classic vendor extension (GnuCOBOL accepts index-name arithmetic), so the
disposition wants the PB1/DA6 shape: strict = reject with the r7 citation, `--permissive` = accept as the
documented coercion (the occurrence number).

**Why not folded into R16:** the screen must live in `ExpressionBinder.RefExpr`'s index arm, which ALSO
serves the r7-LEGAL numeric consumers (relation conditions at least; possibly SET amounts and
PERFORM/SEARCH VARYING operands, depending on which OperandContext those bind under) — the arm needs a
context audit before any rejection, or legal source breaks. Survey first
(feedback_survey_compilers_on_latitude), then thread the context.
