# PB4207 — the missing receiver is blamed on the next statement's verb

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorListener.cs:54` (`CobolErrorListener.SyntaxError`, the PB693 re-code through
`CobolParserCoreBase.ReservedUserWordViolation`), `src/WiseOwl.Cobol.Frontend/Parsing/CobolParserCoreBase.cs:455`
(`CobolParserCoreBase.LookaheadBeginsAStatementThatParses`, `CobolParserCoreBase.ReservedUserWordViolation`).

**The defect.** After an incomplete statement (`MOVE W-X TO`, receiver missing), a verb that correctly begins the next
statement is the token the parser stops at, and the listener re-codes the report to COBOL0901 (a reserved word used as a user
word, §8.3.2.1 1), `cite.py --check` OK). The word is a verb written correctly; the error is the missing receiver. PB3248's
review finisher fixed the RECOVERY half (`CobolErrorStrategy.ConsumeUntil` no longer consumes that verb, so no second
`COBOL0001` follows) but the REPORT is still named for the wrong cause. Repro at --std 2023 (originally `fin/t2.cob` under
E:/COBOL-coord/scratch/mythos/w-g7/w20261780c/, not durable):

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. RVW1.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 W-X PIC X(4).
       01 W-Y PIC X(4).
       01 W-N PIC 9(4).
       01 TB.
          05 TE PIC X OCCURS 4 INDEXED BY IX.
       PROCEDURE DIVISION.
       MAIN-P.
           MOVE W-X TO
           RECEIVE FROM W-X GIVING W-Y W-N
           DISPLAY "A".
           STOP RUN.
```

**Fix direction (the report's).** The listener could ask `LookaheadBeginsAStatementThatParses` before the re-code, so a verb
that begins a statement that parses keeps the ordinary "expected receiver" report. Care: the listener's offending token is not
always LT(1), so the ask has to run from the offending token, not from the lookahead.
