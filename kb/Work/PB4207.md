# PB4207 — the missing receiver is blamed on the next statement's verb

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorListener.cs:54` (`CobolErrorListener.SyntaxError`, the PB693 re-code through
`CobolParserCoreBase.ReservedUserWordViolation`), `src/WiseOwl.Cobol.Frontend/Parsing/CobolParserCoreBase.cs:455`
(`CobolParserCoreBase.LookaheadBeginsAStatementThatParses`, `CobolParserCoreBase.ReservedUserWordViolation`).

**The defect.** After an incomplete statement (`MOVE W-X TO`, receiver missing), a verb that correctly begins the next
statement is the token the parser stops at, and the listener re-codes the report to COBOL0901 (a reserved word used as a user
word, §8.3.2.1 1), `cite.py --check` OK). The word is a verb written correctly; the error is the missing receiver. PB3248's
review finisher fixed the RECOVERY half (`CobolErrorStrategy.ConsumeUntil` no longer consumes that verb, so no second
`COBOL0001` follows) but the REPORT is still named for the wrong cause. Repro at --std 2023 (originally `fin/t2.cob` under
E:/COBOL-coord/scratch/mythos/w-g7/w20261780c/, not durable):

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. RVW1.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 W-X PIC X(4).
       01 W-Y PIC X(4).
       01 W-N PIC 9(4).
       01 TB.
          05 TE PIC X OCCURS 4 INDEXED BY IX.
       PROCEDURE DIVISION.
       MAIN-P.
           MOVE W-X TO
           RECEIVE FROM W-X GIVING W-Y W-N
           DISPLAY "A".
           STOP RUN.
```

**Fix direction (the report's).** The listener could ask `LookaheadBeginsAStatementThatParses` before the re-code, so a verb
that begins a statement that parses keeps the ordinary "expected receiver" report. Care: the listener's offending token is not
always LT(1), so the ask has to run from the offending token, not from the lookahead.

## Landed (wave 20261788 D, 2026-10-31)

Re-probed on the tree first: `MOVE W-X TO` then `RECEIVE FROM W-X GIVING W-Y W-N` gave one `COBOL0901: 'RECEIVE' is a reserved word`. The listener
no longer re-codes (PB4132 moved the §8.9 decision into `CobolErrorStrategy.ReservedWordUse`), so the note's site (`CobolErrorListener.SyntaxError`)
is gone; the decision is the strategy's, and it did not ask whether the word begins a statement that parses: only the RECOVERY did
(`IsReportedReservedOperand`, PB3248), so the REPORT named the wrong cause while the recovery was right.

**Fix: one decision for the report and every recovery.** `ReservedWordUse` also asks `CobolParserCoreBase.ReadStatementAt(offendingToken)`
(a speculative parse of `statement` from the OFFENDING token, the note's care: a failed prediction reports a token the parser has not reached),
and the recovery's second copy of the question (`BeginsNoStatementThatParses`, `LookaheadBeginsAStatementThatParses`) is deleted. A verb that begins a
complete statement draws the ordinary report ("COBOL0001: unexpected 'RECEIVE'", what ADD or DISPLAY there draws) and the recovery resumes at it.
Review round 1 (R1-1) widened "begins a statement that parses" to `CobolParserCoreBase.ReadStatementAt` (None, Complete, CutShort: a statement the sentence's end
cuts short is also the next statement unless the word read as a name carries the whole sentence, `OffendingPosition.NameCarriesTheSentence`), so a next statement
with an operand missing of its own (`ADD 1 TO.`) keeps its own fault. A deliberate consequence of the single decision, measured by the sweep: a verb that is a complete statement alone (`DISPLAY GOBACK.`,
`MOVE W-X TO COMMIT.`) is also the next statement now, where its report used to say COBOL0901 while its recovery already resumed at it.

**Sites changed.** `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs` (`CobolErrorStrategy.ReservedWordUse`, `NextStatementBegins`, `OffendingPosition.NameCarriesTheSentence`, `IsReportedReservedOperand`,
`IsReservedOperand`), `src/WiseOwl.Cobol.Frontend/Parsing/CobolParserCoreBase.cs` (`ReadStatementAt`, `StatementReading`, `ReadingParses`),
`tests/WiseOwl.Cobol.Tests.Unit/ReadingParsesFollowDriftTests.cs`.

**Witnesses.** `ReservedWordPositionConformanceTests.AReservedVerbBeginningTheNextStatement_DrawsOneDiagnostic` (now asserts the report is not
COBOL0901 for every next-statement row, and is for the `SEND TO W-X.` control; ADD, CONTINUE and GOBACK rows added), and the refusal
`conformance-suite/cases/8.3.2-COBOL-words/pb4207-next-statement-verb-after-missing-receiver.cob` (2023, `COBOL0001: unexpected 'RECEIVE'`).
