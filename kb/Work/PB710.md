# PB710 — RETIRED — the gate the note said could not see the word was already looking at it

Retired 2026-09-06 by the registrar. The note was opened 2026-09-05 by the PB693 finisher as *a design boundary
of PB693's mechanism, stated there, not a regression* — an honest report of what he believed the mechanism could
not reach. **It could reach it.** The claim was never measured, and both halves of the refutation below are new
evidence: one mechanical read of main, one measurement by the PB301 implementer.

## What the note claimed

> The lexer tokenizes only the reserved words some grammar rule consumes as a keyword. Words §8.9 reserves that
> no rule consumes — the finisher's sweep names LOCALE, ORDER, CLASSIFICATION among the `cobolWord`-routed set …
> — reach the parser as IDENTIFIER, so the gate has nothing to test and `01 LOCALE PIC X.` at
> `--std 2002/2014/2023` compiles without COBOLNET0901.

## Refutation 1 — the funnel checks IDENTIFIER first, on main

`src/Cobol.Net.Compiler/Validation/VersionConformancePass.cs`. The §8.9 check in `VisitCobolWord` is guarded at
`:2072` by

```csharp
if (!CheckedTokenTypes.Contains(ctx.Start.Type) && !IsProvableUserWordPosition(ctx))
```

and `CheckedTokenTypes` (`:1986-1988`) opens with

```csharp
private static readonly HashSet<int> CheckedTokenTypes =
[
    CobolLexer.IDENTIFIER,
    …
```

So a `cobolWord` whose start token is `IDENTIFIER` — precisely the shape this note says the gate "has nothing to
test" for — is checked unconditionally, everywhere, by TEXT: the ladder runs and `FlagReservedUserWord(word)`
(`:2204`) tests the word's spelling against `ReservedWordSet.RejectsAt`. The gate PB693 built at the TOKEN level
has a second, name-keyed arm that predates and survives it, and the note's premise reads the token arm as the
whole mechanism. `feedback_a_dead_lookup_is_also_unverified` in the mirror: a mechanism nobody exercised was
assumed absent instead of assumed present, and neither is a measurement.

## Refutation 2 — measured, and it took no production change to demonstrate

The PB301 implementer (report §"Rows re-verdicted"), while verdicting `SR-8.3.2.1-1`:

> a §8.9 word the lexer never tokenizes is still caught, by NAME, by the same funnel — measured:
> `01 LOCALE PIC X.` at `--std 2023` → `COBOLNET0901: 'LOCALE' is a reserved word in COBOL-2023 …`
> (26 of the 410 words §8.9 reserves at 2023 have no lexer literal, so this was not safe to assume)

and the system-name half of §8.3.2.1 rule 1 too: `SPECIAL-NAMES. LOCALE IS SCR-MNEM.` at `--std 2023` draws the
same COBOLNET0901.

⭐ **The decisive detail is that his diff contains no `src/` file at all** — `docs/` ×3, `kb/Work/` ×2, `tests/`
×6, `tests/version-matrix/traceability-inventory.json`. Nothing in the compiler changed between the note being
written and the probe answering COBOLNET0901, so the behaviour the note predicted was already impossible on the
tree it was written against. That is what makes this a refutation rather than a fix.

`python scripts/spec/cite.py --check 8.3.2.1 "Reserved words shall not be used as user-defined words or
system-names"` → **OK, §8.3.2.1 1)** — the rule the note asked for is enforced, in both of its slots.

## ⚠ One thing this retirement does NOT assert

It does not say every §8.9 word is gated. `FlagReservedUserWord` reports **high-confidence rows only**
(`VersionConformancePass.cs:2026`, `ReservedWordSet.RejectsAt` — the conservative policy), and
`tests/version-matrix/reserved-words.json` has exactly one non-high row: `REPORTS`. That single exception is
recorded on [[PB655]] (dated append, 2026-09-06), not here. Retiring this note therefore closes a false premise
and leaves no measured gap unowned.
