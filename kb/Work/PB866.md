# PB866 — LANDED — the ban is on the FOR form, and the screen cannot tell the forms apart

Source: the `PB490` implementer report ("NEW DEFECT", the whole of it). Carried as an unfiled lead since
train 27.

## Repro — re-run on this tree

`scratchpad/reg4/probe/p29_float_edit_is_form.cob` (PROGRAM-ID `R4P29`), `--std 2023`:

```cobol
       01 FT PIC +9T9.9(3)E+99 EDITING "T" IS ":".
       01 FE PIC +9B9.9(3)E+99.
```
```
(5,8): error COBOLNET1658: invalid floating-point numeric-edited PICTURE +9T9.9(3)E+99 - data item 'FT': an
       EDITING character-1 may not be specified for a floating-point edited item (ISO §13.18.40.3 SR12 a)
```

The `B` sibling (`FE`) compiles and renders, which isolates the refusal to the EDITING phrase rather than to the
simple insertion it performs.

## The rule, quoted

```
$ python scripts/spec/cite.py --check 13.18.40.3 "Extended editing sign control symbols shall not be specified for a floating-point edited item"
  OK  §13.18.40.3 12) a)  (Syntax rules)
      a) No editing sign control symbols may be specified in character-string-1. Extended editing sign control symbols shall not be specified for a floating-point edited item.
```

The ban names the EXTENDED symbols — the FOR form. §13.18.40.4 GR13 b) admits for the significand "a valid
character-string for either a numeric item or a numeric-edited item for a fixed-point result", excluding only
floating insertion and zero suppression, and Table 7 gives the floating-point edited category "Simple insertion,
special insertion, and fixed insertion for the significand part". An IS-form character-1 is simple insertion.

## ⚠ Transcription hazard for whoever takes it

`specs/ISO_COBOL.md` §13.18.40.3 has TWO items labelled `a)` under rule 12 — "Literal-2 and literal-3 shall
occupy the same number of character positions" and the sentence above — the second orphaned after 12 c).
`cite.py` files both as `12) a)`, which is exactly why COBOLNET1658's citation passes the mechanical check while
pointing at the wrong sentence. **Render the printed page before that clause number is reused**
(`python scripts/render-spec-page.py <page>`; CLAUDE.md rule 1), and repair the transcription on discovery
(`feedback_fix_transcription_errors_immediately`).

## Code site

`src/Cobol.Net.Compiler/Binding/PictureAnalyzer.cs#AnalyzeFloatEdited` line ~740 —
`if (hasEditingPhrase) { Bad("an EDITING character-1 may not be specified ..."); ... }`, where
`hasEditingPhrase` is `char1Set.Count > 0` (line ~152) and so cannot tell the forms apart. The fix: pass the
FORM, refuse only the FOR phrase, and let `RenderFloat` — which already reads the one simple-insertion
predicate — carry an IS-form character-1.

## Sibling sweep the fixer owes

* Every other consumer of `char1Set.Count > 0` as a proxy for "an EDITING phrase is present" — the same
  conflation is the whole defect.
* The fixed-point twin: an IS-form character-1 on a NUMERIC-edited item already works, so it is the control.
* kb/Work PB855 owns the placement questions for the FOR form; this note is about the IS form only.

## Landed 2026-09-22 (wave 46 group M)

**Re-probed first**, on this worktree's own build at `8fe62bd1f`: `01 FT PIC +9T9.9(3)E+99 EDITING T IS ":".` ->
COBOLNET1658 "an EDITING character-1 may not be specified for a floating-point edited item (ISO 13.18.40.3 SR12 a)".
(The note's probe spelled character-1 as the quoted `"T"`, which PB568 has since made COBOLNET2149; the bare form
the general format writes reproduces the defect on its own.)

**The printed page settles the lettering.** p.442 of the PDF carries the SAME duplicate `a)` as the transcription:
SR12's FOR-phrase list runs a) b) c) a), and the fourth item is the one holding "Extended editing sign control
symbols shall not be specified for a floating-point edited item". The transcription is faithful; the standard's own
lettering is the hazard. The ban is inside the FOR-phrase list, so it bars the FOR form only.

```
$ python scripts/spec/cite.py --check 13.18.40.3 "Extended editing sign control symbols shall not be specified for a floating-point edited item"
  OK  13.18.40.3 12) a)  (Syntax rules)
$ python scripts/spec/cite.py --check 13.18.40.3 "If the FOR phrase is specified, character-1 is an extended editing sign control symbol"
  OK  13.18.40.3 12)  (Syntax rules)
```

13.18.40.5 rule 3 makes an IS-form character-1 a SIMPLE INSERTION symbol and Table 7 gives the floating-point edited
category "Simple insertion, special insertion, and fixed insertion for the significand part" and "None for the
exponent part".

**Fix.** `PictureAnalyzer.AnalyzeFloatEdited` now takes the resolved rules and the FOR-form set: a FOR phrase is
refused (the rule as written), an IS-form character-1 is admitted in the significand and refused in the exponent
(Table 7), the item's size counts literal-1 at each occurrence (GR14 'es', the same `EditingPositions` the fixed-point
arms use), and the PicInfo carries `EditingRules`. The runtime float lane (`CobolEdit.FloatMask`) carries the rules:
`RenderFloat` writes literal-1 whole, `DeEditFloat` matches it, `Length` counts its width, and under DECIMAL-POINT IS
COMMA the literal is held pre-swapped so SR13's symbol exchange never rewrites a literal's characters.

**The structural half (rule 5).** The EDITING rules were a SEPARATE `RuntimeApi.EditsArg` suffix each edited-store
call site appended after `EmitContext.EditCfg`; seven sites remembered and the two floating-point arms
(`MoveEmitter`'s float branch, `ArithmeticEmitter`'s `EditTryFormatFloat`) and `DeEditFloat` did not. `EditCfg` now
emits it, so every fixed- and floating-point edited store takes it from the one producer.

**Goldens.** `conformance:2023/pb866_float_edited_is_form` (PB866FLOATEDITEDISFORM: `+1:2.345E+00` LEN 12, a
two-character literal ` 1<>23.45E-01` LEN 13, the arithmetic store and both de-edits),
`conformance:2023/pb866_float_edited_is_form_comma` (DECIMAL-POINT IS COMMA, literal "." kept),
`conformance:negative/pb866-float-edited-for-form` (the FOR form, still refused) and
`conformance:negative/pb866-float-edited-char1-in-exponent` (Table 7's exponent half).
