### Row FMT-13.5.2 — PARTIAL (no separate finding; the adjudicator's / refuter's record)

Code location: `src/Cobol.Net.Frontend/Grammar/Core/CobolData.g4#workingStorageSection; src/Cobol.Net.Frontend/Grammar/Core/CobolData.g4#dataDescriptionEntry; src/Cobol.Net.Frontend/Grammar/Core/CobolData.g4#constantEntryBody`

§13.5.2 prints WORKING-STORAGE SECTION. (both words underlined, so required) followed by an optional bracket of {77-level-description-entry | constant-entry | record-description-entry | type-declaration-entry} with an ellipsis: any number, any order, possibly none. Grammar: `workingStorageSection : WORKING_STORAGE SECTION DOT dataDescriptionEntry*`. The four kinds all ride dataDescriptionEntry, and the binder separates them by level number and body (CONSTANT / TYPEDEF). Probe probe/ws/p1fmt.cob mixes 77, a CONSTANT AS numeric, a TYPEDEF, a level-01 record using TYPE, another 77, and a CONSTANT AS alphanumeric, and a second program has an EMPTY WS. At --std 2002/2014/2023 it prints `007 42 ABWXYZ Q HI` / `EMPTY-WS-OK`, which is what the spec requires. The non-standard level 78 is refused (negative/pb485-level-78-working-storage). cite.py --check 13.5.2 "record-description-entry" OK. No golden exists that was written for the §13.5.2 interleaving of all four kinds, so test-ref is left empty. || REFUTED: PARTIAL — The format admits exactly four entry kinds (77-level, constant, record-description, type-declaration). A record-description-entry's first entry shall have level-number 1 (13.11.1, cite.py OK). The grammar's `dataDescriptionEntry*` admits any level number as the first WS entry, and nothing downstream screens it: a WS whose first entry is `05 X PIC X` or `02 X PIC X` is none of the four kinds, yet it compiles clean and runs at --std 85, 2002 and 2023. That is under-rejection of the section format. The admission half (the four kinds interleaved, and an empty WS) is verified as the adjudicator said. Secondary: the BYTE-LENGTH OF constant-entry form is refused with COBOLNET0899. That form belongs to the 13.10 row, but it means one constant-entry shape the format admits is not accepted in WS.
