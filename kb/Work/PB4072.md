# PB4072 — the review lane cannot kill a hung reviewer on Linux; its self-test waits 20 minutes instead of failing

**Sites:** `scripts/orchestrator/review_lane.py#run_agent`, `scripts/orchestrator/review_lane.py#self_test` (section 9, the RUNNER: the `hang` stub and its CEILING and loop-stop arms), `scripts/detached.py#kill_tree`

**Measured.** Merge-group CI runs took about 15 minutes for code pull requests and 5 for notes-only ones until 12:28 PDT
on 2026-10-29. From then on every run took about 23 minutes, notes-only included whenever a code pull request was ahead
of it (pr-764: 22.7 min). The whole difference is the `audits` job's "Script self-tests" step. In run 40930944772 it
ran 112 self-tests in 139 s. In run 40965493994 it ran 113 in 1,217 s with the host "4% busy", and one of them,
`scripts/orchestrator/review_lane.py --self-test`, took 1,200.4 s and reported GREEN. That self-test arrived with
PB3608 (#760, review_lane.py's runner).

**Mechanism.** The self-test's section 9 writes a stub agent that, in mode `hang`, sleeps 600 s and then exits 3. Two arms
run it through `run_agent`: one with `ceiling_min` 0.0001, expecting STALLED, and one with the loop's STOP file, expecting
STOPPED. `run_agent` starts the agent with `subprocess.Popen(rec["argv"], ...)` and no new session. When the ceiling or
the stop fires, it calls `detached.kill_tree(proc.pid)`, whose POSIX arm is `os.killpg(pid, SIGKILL)`. The agent is
not a process-group leader, so no group has that id: `killpg` raises ProcessLookupError, `kill_tree` swallows it as
"already gone", and `proc.wait()` then waits out the full sleep. The outcome is still recorded as STALLED or STOPPED, so
both arms PASS, 600 s apart. On Windows `taskkill /T /F` works, which is why the local gate never saw it; it also reuses
a recorded PASS.

**Harm.** In production a hung reviewer under the review lane is never killed on Linux: the lane records STALLED or STOPPED
and then blocks until the agent ends by itself. In CI every merge-queue run of either lane pays about 17 extra minutes,
roughly double the queue's latency, and a run that should fail stays green. It is also a CI-invariant gap (CLAUDE.md, THE
CI INVARIANT): the slowdown exists only on Linux.

**Fix.**
1. Start the agent in its own session on POSIX (`start_new_session=os.name != "nt"`, as `detached.spawn_detached` and
   its line 132 already do), so `kill_tree` reaches it.
2. Make the self-test prove the kill rather than the bookkeeping. The `hang` stub's natural exit is 3, so assert the
   killed run's rc is not 3 (negative on POSIX, 1 from taskkill on Windows). The arm then fails on the old code at once,
   deterministically and with no time limit (the no-wall-clock-tests rule).
3. `kill_tree` should not hide the case this bug hit. A ProcessLookupError from `killpg` while `pid` itself is alive means
   the caller spawned it without a session, so fail loudly, or kill `pid` alone and report it, rather than return.

Sibling sweep (2026-10-29): `kill_tree` has two other callers, both in `detached.py` (lines 135 and 168), and both
spawn with `start_new_session`. This is the only caller that does not.

## Second harm: the landing lane's false bounces (kb/Work PB4052)

The 22-minute `audits` job outlived the landing lane's queue-watch grace on every pull request, so from 15:14 PDT the watch
requeued each one and the reopen cancelled its run: #773 to #777 read BOUNCED with no defect. PB4052 fixes the watch; this
note removes the 20 minutes that made every landing hit it.

## Fix (landed, operator 2026-10-29)

- `review_lane.py#run_agent` starts the agent with `start_new_session=os.name != "nt"`, so on POSIX it leads the process
  group `kill_tree` kills.
- `detached.py#kill_tree`: a ProcessLookupError from `killpg` is "already gone" only when `pid` is dead; a LIVE `pid` that
  leads no group is killed alone and raises ChildProcessError naming the caller's defect. New self-test arm 4 (POSIX):
  a group leader is killed (rc -9); a plain child is killed and raises; a process already gone is no error.
- `review_lane.py#self_test` section 9: the CEILING and loop-stop arms assert the killed run's rc is neither the stub's own
  3 nor missing: main's code fails them once the stub's sleeps run out (1,200 s), and a regression to a plain Popen fails at
  once (kill_tree raises ChildProcessError; the reviewer's mutation run stopped in 0.56 s). Measured under WSL: rc -9 for
  both, the whole self-test 0.64 s (CI: 1,200 s).
- Sibling: `run_gate_legs.py#_stop_tree` was a second copy of `kill_tree` with the same swallow (kb/Work PB3061's audit
  stop). It is deleted; `_Live.add`, `_Live.stop_all` and the self-test's follower kill call `detached.kill_tree`, and each
  of those processes is started with `start_new_session` on POSIX (`Host.audits`, the follower), so the contract holds.
  `DESIGN-orchestrator-loop.md`'s member table for `gate_host.py` drops `_stop_tree`. `gate_slot.py`'s self-test harness
  (`_Proc.kill`) had the same swallow on POSIX (review R1-2): its POSIX arm now calls `detached.kill_tree` (its holder is
  started with `start_new_session` there); its Windows arm keeps `p.kill()`, since the job object ends the tree there.
