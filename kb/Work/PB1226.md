# PB1226 — OPEN

## Measured

**constant-entry** — F-REPORT-SECTION — reportDescriptionEntry admits only report group entries, so a constant entry following an RD is a parse error

- **Repro:** FD F REPORT IS RPT. REPORT SECTION. RD RPT. 01 K CONSTANT AS 5. 01 TYPE DETAIL. 05 LINE 1 COL 1 PIC X(3) VALUE 'ABC'. PROCEDURE DIVISION. DISPLAY K.
- **Expected (spec):** Compiles; DISPLAY K prints 5. §13.8.2's format places {constant-entry | report-group-description-entry}... after each report-description-entry (figure note cite OK). Report Writer is claimed (CONFORMANCE A.4.11 Partial).
- **Observed:** COBOLNET0901 'CONSTANT is a reserved word in COBOL-2023 and cannot be used as a user-defined word' — `reportDescriptionEntry : RD reportName reportDescriptionClause* DOT reportGroupEntry*`. SR11's elementary-report-item screen is also absent from BindConstantLength, so it must land with this.
- **Code site:** src/Cobol.Net.Frontend/Grammar/Core/CobolReportWriter.g4#reportDescriptionEntry; src/Cobol.Net.Compiler/Binding/DataBinder.Constants.cs#BindConstantLength
- **Clause (adjudicator):** §13.8.2 general format; §13.10.3 SR11

**data-division-structure** — The report description entry's trailing list is modelled as report-group entries only (`reportGroupEntry*`), but §13.2.1/§13.8.2 print it as the brace group {constant-entry | report-group-description-entry}... , so a constant-entry inside the REPORT SECTION is refused as a reserved-word misuse

- **Repro:** SELECT RPF ASSIGN TO "RPT.TXT". ... FILE SECTION. FD RPF REPORT IS RP. REPORT SECTION. RD RP. 01 RK CONSTANT AS 4. 01 DL TYPE DETAIL LINE 1. 05 COLUMN 1 PIC X(2) VALUE "AB". PROCEDURE DIVISION. DISPLAY RK. STOP RUN. (probe DDS08.cob, --std 2023 or 2002)
- **Expected (spec):** Compiles; DISPLAY RK prints 4. §13.2.1 / §13.8.2: REPORT SECTION. [ report-description-entry { constant-entry | report-group-description-entry } ... ] ... ; constant-entry is a COBOL-2002 introduction, so legal at 2002/2014/2023.
- **Observed:** DDS08.cob(12,14): error COBOLNET0901: 'CONSTANT' is a reserved word in COBOL-2023 and cannot be used as a user-defined word (ISO §8.9); same at --std 2002. The reportGroupEntry rule (levelNumber reportGroupName? reportGroupClause* DOT) has no constantEntryBody arm, unlike dataDescriptionBody in CobolData.g4.
- **Code site:** src/Cobol.Net.Frontend/Grammar/Core/CobolReportWriter.g4#reportDescriptionEntry; src/Cobol.Net.Frontend/Grammar/Core/CobolReportWriter.g4#reportGroupEntry
- **Clause (adjudicator):** §13.2.1 general format; §13.8.2 general format

**data-division-structure** — Nothing enforces that an RD entry is followed by at least one entry: the grammar's `reportGroupEntry*` admits zero and no bind-time check replaces the brace group's one-or-more (the SD twin has COBOLNET1837; the RD has no counterpart)

- **Repro:** SELECT RPF ASSIGN TO "RPT.TXT". ... FILE SECTION. FD RPF REPORT IS RP. REPORT SECTION. RD RP. PROCEDURE DIVISION. DISPLAY "OK". STOP RUN. (probe DDS09.cob, --std 2023 and --std 85)
- **Expected (spec):** A compile-time error: §13.2.1/§13.8.2 print the list after report-description-entry as a brace group with ellipsis (one or more), and §13.8.4: 'An RD entry shall be followed by one or more report group description entries.'
- **Observed:** Compiles with zero diagnostics and runs, printing OK, at 2023 and at 85.
- **Code site:** src/Cobol.Net.Frontend/Grammar/Core/CobolReportWriter.g4#reportDescriptionEntry
- **Clause (adjudicator):** §13.8.4; §13.2.1 general format

**entry-name-clause** — The report group description entry's name slot (CobolReportWriter.g4 reportGroupName) is `cobolWord` only, so the filler format of the entry-name clause (§13.18.20.2 format 3) is unparseable in the REPORT SECTION, unlike its data-description twin CobolData.g4 dataName which lists FILLER.

- **Repro:** RD RPT PAGE LIMIT 10. / 01 DL TYPE DETAIL LINE 1. / 05 COLUMN 1 PIC X(5) VALUE "HELLO". / 05 FILLER COLUMN 7 PIC X(5) VALUE "WORLD". ; OPEN OUTPUT, INITIATE, GENERATE DL, TERMINATE, CLOSE (probe/entry-name-clause/p9.cob; also 01 FILLER TYPE DETAIL in p8.cob).
- **Expected (spec):** Compiles and writes 'HELLO WORLD' — the same as the omitted-name form (p10.cob): §13.15.2 `level-number [ entry-name-clause ]`, §13.15.3 SR2 'the data-name format or filler format shall be specified', §13.18.20.3 SR3 'either data-name-1 or FILLER shall be specified', §13.18.20.4 GR1 'The word FILLER may be used to name a data, report, or screen item.'
- **Observed:** COBOL0307 "unexpected 'FILLER'. A period may be missing at the end of the previous sentence." at --std 85, 2002, 2014 and 2023 (pinned adj-d1 cobol.exe). The FILLER lexer token is admitted by no cobolWord alternative. Sibling sweep: CobolData.g4 dataName and CobolScreen.g4 screenName both list FILLER; only the report arm omits it (two-arm-dispatch shape). Fix shape: one entry-name rule shared by all three description entries rather than three hand-written name rules.
- **Code site:** src/Cobol.Net.Frontend/Grammar/Core/CobolReportWriter.g4#reportGroupName (line ~90); src/Cobol.Net.Compiler/Validation/LevelNumberPass.cs#EntryName (already maps a missing report name to FILLER)
- **Clause (adjudicator):** 13.18.20.3 SR3; 13.18.20.4 GR1; 13.15.2; 13.15.3 SR2
