# PB4303 - COPY resolution re-probes the file system (name + 6 suffixes per place, then a directory listing) and re-reads/re-decodes the library text for every COPY statement, with no per-compilation memo: ~29% of a compile that copies the same two books 800 times

Found by the Mythos front-end review, gap pass, 2026-10-31 (GAP-REVIEW.md, G6-2; artifact https://claude.ai/artifact/KaxkLe85tfZBZ3nZ1tDGTs). Pin d7daee1cf.

**Sites:** `src/WiseOwl.Cobol.Frontend/Preprocessor/CopyProcessor.cs` (`LibraryPlaces` :1127-1131, `LocateInLibrary` :1144-1151, the `ReadSourceText` call :493, `ReportOnce` for COBOL5434/5435); `src/WiseOwl.Cobol.Frontend/Pipeline/CompilationInputs.cs` (`LocateFile` :99-123, `ReadSourceText` :49-51).

**Finding.** Every COPY goes CopyProcessor.LibraryPlaces (:1127-1131) -> LocateInLibrary (:1144-1151; the name as written plus 6 CopybookSuffixes per place) -> CompilationInputs.LocateFile (:99-123; File.Exists, then Directory.EnumerateFiles on the hit) -> ReadSourceText (:49-51; ReadAllBytes + Decode), nothing memoized. COPYSHARED (800 COPYs of two books): LocateFile 22.0% inclusive, ReadSourceText 6.8% of the compile; the refuter's cwd differential (7 fewer failing probes per COPY) cut pp.ccCopyReplace 212 -> 141 ms; micro-timings File.Exists 8.2-8.7 us, case listing 25.6 us, ReadAllBytes 21.5 us - ~125 us per COPY, ~100 ms of a 300-460 ms compile (Windows/NTFS only). Corrections to the first report: a (place, text-name) memo helps only when the SAME name is copied repeatedly - COPYHEAVY copies 1,601 DISTINCT books once each, so its 22% is first-resolution misses in the places ahead of the holding library (a separate lever touching PB4158's probe record); that run made 9 File.Exists + 1 listing per COPY, not 16 (the harness adds the corpus copylib only for Nist items); on Linux .cpy is the 4th suffix; the COPYHEAVY_n scaling (160/161/454/1,215 ms at 100/200/400/800) is noisy and superlinear, not evidence for a constant per-COPY cost. PB4157/PB4158/PB4159/PB1680 are about LocateFile's output, PB4242 about text re-scans.

**Fix direction.** A (place, text-name) -> path memo and a path -> decoded-text memo in CompilationInputs; the first resolution performs and records every probe as today (the probe/files-read consumers use Distinct, so the recorded dependency set is unchanged); ReportOnce must still report COBOL5434/5435 into the current bag.
