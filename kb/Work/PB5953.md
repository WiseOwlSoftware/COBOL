# PB5953 - the `All` listing row is over its budget with the cross-reference

**Measured** by listing step 7b (w20262104r, branch `listing-step-7b-2`), Release, one Windows host, the built benchmarks
(`dotnet run -c Release --project tests/WiseOwl.Cobol.Benchmarks -- --filter ...`), each tree from its own root; the parent
`0c54b1d651` in a detached worktree; order branch, parent, branch (full compile), parent, branch. Logs:
`E:/COBOL-coord/scratch/w20262104r-7b2/bench-*.txt`.

Full compile, allocated bytes, branch (one run):

| Program | None | All | All over None |
|---|---|---|---|
| IX113A | 199.34 MB | 248.59 MB | +24.7 % |
| NC105A | 113.79 MB | 149.27 MB | +31.2 % |
| NC218A | 111.23 MB | 145.46 MB | +30.8 % |
| SM201A | 42.25 MB | 54.26 MB | +28.4 % |

Front end and bind, `All`, branch (2 runs) against the parent (2 runs): IX113A 99.24, 99.13 MB against 87.17, 87.13; NC105A 52.09,
51.45 against 42.40, 42.27; NC218A 45.84, 45.98 against 37.99, 37.97; SM201A 23.75, 22.43 against 19.42, 19.39. The parent's `All` was
+16.8 to +23.5 % over `None` at main `0c29eebc42` (the benchmark README's "The `All` row at the merged tree"), so step 7b's
cross-reference is what puts the row over.

**Where the bytes go (to measure before changing anything):** per occurrence a mutable record in the store, a `SymbolPosition` key in
the position index, a place copy and a dictionary slot when it is linked, the `StorePositionsOf` enumeration per statement (a
`HashSet` and a `BoundReferences.Of` walk, and one visitor per asked place), the snapshot's `SymbolOccurrence` copies, the
cross-reference's `ListingReference`s and the lines' `ListingNameUse`s. A probe of each part (as PB5941's was) decides which to
change; the classification's visitor per place is the likely first, since it walks the statement once per operand.

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/SymbolTable/SymbolTable.Occurrences.cs` (`SymbolTable.EntryStore.Record`, `SymbolTable.EntryStore.Link`, `SymbolTable.EntryStore.Classify`), `src/WiseOwl.Cobol.Compiler/Binding/Bound/BoundStores.cs` (`BoundStores.StorePositionsOf`), `src/WiseOwl.Cobol.Compiler/Listing/CrossReferenceBuilder.cs` (`CrossReferenceBuilder.Build`, `CrossReferenceBuilder.MarkLines`)

**Budget**: section 9's `All` row, at most 25 % over `None` on a full compile.

**Landed (step 9b, branch `listing-step-9b`; the benchmark README's step-9b table).** The cross-reference's own cost is cut at its roots: the
classification (`BoundStores.StorePositionsAmong`, one survey pass, the old walk kept only as the pairing test's), the builder's copies and
boxed enumerators, the strings per number and link of the text and the page, the IL operands named once, three small records as structs. On a
thread-level probe the cross-reference's marginal share of the `All` row fell from 15.8 MB to 5.8 MB on IX113A before the 7b-2 review round
was merged, and stands at 0.25 MB (SM201A), 3.6 and 4.7 MB (NC105A, NC218A) at the merged head. The `All` row still lies over 25 % in some
runs of NC218A and SM201A at the merged head, by a share that is not the cross-reference's: kb/Work PB5962.
