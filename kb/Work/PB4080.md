# PB4080 — the R2 writer emits the one site form `work.py` reads as prose

**Sites:** `scripts/arch/file_census_notes.py` (`render_r2`)

**Where the code is.** `render_r2` (line 677 on main, unchanged on branch `worktree-wf_484eb705-564-32` at `92ff6f23b`) writes each site as a bullet of the form path-in-a-code-span followed by the symbol in a parenthesis outside any code span (the loop over `rec["sites"]`, about lines 698-702).

**What happens.** The register reader takes a member only from a code span (PB3797, landing on that branch: the reader stays strict about the one form), so a parenthesised bare `Type.Member` is prose; the planner then claims the file whole and `work.py check` can refuse the note. PB3797 rewrote the 52 site lines of eight existing R2 notes by hand and left the writer alone, so the next R2 batch writes the old form again.

**Fix.** Emit the symbol inside a code span in `render_r2`, and add a case to the writer's self-test that round-trips an R2 record through `work.py`'s site reader and finds the member.

## Landed (branch worktree-agent-a2787d9fe53a79a18, 2026-11-27)

`file_census_notes.site_line` renders each R2 site as the path (and `:lines`) in a code span followed by a parenthesis that opens with the member names, each in a code span (`work.member_name`, the one definition of a name that `_mention_members` now also calls); the finder's remaining words follow as prose. A symbol that names no member, a member the file does not declare at the tree the note is filed on (`work.undeclared_names`, formerly private), and a code file named with no symbol each claim the file whole with the reason `work.py check` requires (`(whole: why)`). Round trips (self-test): the rendered R2 note read back through `work.note_sites` gives its members; the old form `` `src/T.cs:10-90` (N.T.F) `` read back as `members={}` with the file unnamed (seen failing). Over the 28 notes batches 1a and 1b render, `note_sites(repo=...)` reports 0 unnamed or undeclared sites.

**Sibling sweep** (same writer): the census renderers of `file_census_notes.py` wrote three more bare code-file sites (a dead-artifact code file with a prose parenthesis, a god-class's files, an extract step's files and its "The files this step edits" line); they now use `whole_site` / `whole_span`, and the census self-test reads every rendered note back through `work.note_sites` and finds no unnamed code file.
