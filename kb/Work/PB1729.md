# PB1729 — OPEN

Filed by the train-71b lander, 2026-09-29.

## Finding

**Observed.** The lander ran the whole-assembly gate (`build-local.ps1 -Filter "FullyQualifiedName~."`) in
`E:\COBOL\.claude\worktrees\wf_db98f9ed-c65-8`, minutes after `git reset --hard eeebfa120` had rewritten the
working tree. Conformance passed 9319/9319 and Characterization 33/33. Unit had exactly one red:

`ConflictMarkerDriftTests.TheSweepActuallyReadsTheTrackedTree` — "the conflict-marker sweep could not open 1 tracked
file(s) … tests/conformance/85/l1c35_unstring_tallying_accessed.cob: UnauthorizedAccessException: Access to the path
… is denied. (attributes: Archive)".

The file was readable immediately afterwards. A `--no-build` re-run of the whole Unit assembly was
`Passed! 29745/29745`.

**Code site.** `tests/Cobol.Net.Tests.Unit/ConflictMarkerDriftTests.cs`, the open at about line 325. PB1583 already
opens with `FileShare.ReadWrite | FileShare.Delete` and records `IOException` / `UnauthorizedAccessException` as an
unread file. A sharing violation is therefore not the cause.

**Hypothesis (unverified).** On Windows, "access denied" on a readable file with plain attributes usually means a
delete is pending on it, or an on-access scanner holds it exclusively just after a bulk rewrite. `git reset --hard`
rewrites many files at once.

**Next step.** Reproduce with `git reset --hard <sha>` immediately followed by the Unit assembly. If it is transient,
retry the open a bounded number of times before counting the file unread. This is not a timing assertion; the sweep
still fails when the file stays unreadable.
