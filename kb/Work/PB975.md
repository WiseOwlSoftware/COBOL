## 1 — no source position (measured)

`reg11/i34.cob` (`CLASS-ID. R11I34 INHERITS NOSUCHBASE.` with `REPOSITORY. CLASS NOSUCHBASE.` and no such class) →

```
  error COBOLNET0821: class 'R11I34': INHERITS FROM 'NOSUCHBASE': no such a class is defined in this compilation group (ISO §11.3.3 SR2)
```

Every other diagnostic prints `i34.cob(line,col):`. A user with several classes in one compilation group cannot find
the clause. Cause (source report; the fixer confirms): `OoClassTable.Build` emits through `edition.Error` without
first scoping `using var _ = edition.At(ctx)` as every binder pass does. Sweep every `edition.Error` in Build's pass 1
(COBOLNET0820 END CLASS mismatch, 0821 INHERITS, the IMPLEMENTS captures PB946 also touches) and add a drift test
that no diagnostic leaves the compiler without a position.

## 2 — an inherited citation (checked)

`src/Cobol.Net.Compiler/Oo/OoClassTable.cs:323`: "a METHOD-ID named like its CLASS-ID is legal COBOL (§8.4.5 distinct
name categories), so the SYMBOL renames." `specs/ISO_COBOL.md` §8.4.5 is "Explicit and implicit data item references",
which says nothing about name categories. The governing clause is §8.3.2.2:

- `python scripts/spec/cite.py --check 8.3.2.2 "Within a source element, a given user-defined word may be used as only one type of user-defined word"` → OK §8.3.2.2

Whether a method-name may equal the class-name therefore turns on whether the METHOD-ID and the CLASS-ID are in the
same source element (a method definition is its own source element). The fixer DERIVES that, writes the clause that
actually decides it into the comment, and runs `python scripts/spec/audit_code_citations.py --check` — this site
passed that audit because §8.4.5 exists; the audit checks that a clause exists, not that it answers the question
(memory: a real clause can answer a different question).

**2 — the citation.** The CS0542 guard's "§8.4.5 distinct name categories" is replaced by the derivation:
§8.3.2.2 bars one word as two types only "Within a source element" (`OK §8.3.2.2`); §10.4 makes a method "directly
contained within" its factory/instance definition (`OK §10.4`); §10.5 "A source element is a source unit excluding
any contained source units" (`OK §10.5`); so the method-name and the class-name are in different source elements,
which §8.4.6.1 lets "use identical user-defined words … independent of … other source elements" (`OK §8.4.6.1`).
