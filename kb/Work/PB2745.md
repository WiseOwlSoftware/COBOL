**Rule it breaks:** ISO 15.32.3 r1/r2 and 15.30.3 r1: the statement and location answered are those of the statement that caused the raise, and spaces when the TURN that enabled the RAISED condition did not specify LOCATION; 7.3.25.4 GR6 makes enablement a property of the source text at the executing statement. The engine already writes this boundary discipline for the checking flags (PushAllCheckingOff, ExceptionState.cs:408-426, kb/Work PB891/PB841), but the sibling ambient register _stmtName/_stmtLoc/_stmtLocNames is entered only by EcEmitter.EmitChecked when locNames is non-empty and is never cleared at an activation or other-source-statements boundary: two paired ambient registers with different scope rules (review dimension 2, sibling agreement).

**Scenario:** Caller: >>TURN EC-BOUND-SUBSCRIPT CHECKING ON WITH LOCATION, then CALL SUB. EcBinder adds EC-BOUND-SUBSCRIPT to every statement of a checking-on region (EcBinder.cs:856-862), so the CALL emits ExceptionState.EnterStatement(CALL, <caller loc>, [EC-BOUND-SUBSCRIPT]). SUB is compiled with >>TURN EC-BOUND-SUBSCRIPT CHECKING ON (no LOCATION) and a USE AFTER EC-BOUND-SUBSCRIPT declarative that DISPLAYs FUNCTION EXCEPTION-STATEMENT and EXCEPTION-LOCATION. SUB executes MOVE T(I) TO Y with I out of range: its wrapper has empty locNames so it enters no context; ProgramTable.CallProgram pushes the checking flags off (ProgramTable.cs:298) but leaves the statement context; SubscriptError -> FatalIfEnabled -> Set(ec, true) finds statement null and EC-BOUND-SUBSCRIPT in the CALLER names (ExceptionState.cs:107-111), so LastStatement=CALL and LastLocation=the caller element and paragraph. The declarative prints CALL and the caller location where r1 requires 63 spaces and one space. The same leak happens in one program when a PERFORM in a WITH LOCATION region runs a paragraph after a later >>TURN ... ON without LOCATION (EcEmitter.cs:337 boundary), in an INVOKEd method (OoEmitter.cs:1260) and in a USE procedure (DispatchEmitter.cs:357). Silent wrong answer in a user program; no golden covers it (exception_statement_ambient pins the in-statement case only).

**Measured how:** R2 batch finding `runtime-control-2--code--f2#1` (pair runtime-control-2--code), read in the pinned tree at 8be23006851a; skeptics rule upheld, scenario upheld, site upheld.

**Spec:** §15.32.3 "is not specified and the implementor does not save the location information, the returned value is 63 spaces" (`cite.py --check` passed at collection); §15.32.3 "the name of the statement that caused the exception condition to be raised" (`cite.py --check` passed at collection); §15.30.3 "the returned value is one alphanumeric space character" (`cite.py --check` passed at collection); §7.3.25.4 "checking for the exception condition associated with exception-name-1 is enabled for the procedure division statements and procedure division headers that follow in the compilation group" (`cite.py --check` passed at collection)

**Target:** One scope mechanism for both ambient registers: the statement context joins the value PushAllCheckingOff/SaveChecking returns and RestoreChecking restores (or CheckingFlags carries it), so every boundary that opens a checking baseline also opens an empty statement context; with the 8.3 (7) split this is LastExceptionRecord + ExceptionEngine scope state. Drift test: a raise of a name without LOCATION in a callee, a PERFORMed range, a method and a declarative answers spaces when the activating statement had LOCATION; golden at 2023.
