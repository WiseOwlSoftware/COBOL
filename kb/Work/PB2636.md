**Rule it breaks:** performance: no per-evaluation allocation on an emitted hot path (DESIGN-architecture-review §4 item 5, §5.4; review dimensions.md 3) and the modern-C# standard (§5.5): CA1861 (avoid constant arrays as arguments) names the emitted `new int[] { 0, 0 }` scales array exactly, and C# 13 params collections (`params ReadOnlySpan<T>`, available at the pin's LangVersion 14 / net10.0) let a call site of fixed arity pass its arguments with no heap array

**Scenario:** IntrinsicRenderer.RawArgPairs (src/Cobol.Net.Compiler/CodeGen/Emit/IntrinsicRenderer.cs:1345-1356) renders FUNCTION MAX(WS-A WS-B) as `CobolIntrinsics.MaxAt(0, true, new Int128[] { WS_A, WS_B }, new int[] { 0, 0 })` (pinned snapshot tests/Cobol.Net.Tests.Characterization/Snapshots/char_intrinsics.85.g.cs.txt:50), so each evaluation allocates an Int128[n] of the argument values and an int[n] of scales that never change. Every other variadic body (SumScaled, RangeScaled, MedianScaled, MidrangeScaled, OrdMax/OrdMin, the twelve ...Dec bodies, the nine ...Real bodies, Variance/StandardDeviation/PresentValue, the eight ...String selection bodies, Concat, Trim) is `params T[]`, so the compiler allocates one array per call; MedianScaled/MedianDec/MedianReal then copy it again to sort. A PERFORM loop of 1,000,000 iterations computing FUNCTION MAX(A B) makes 2,000,000 short-lived arrays; FUNCTION SUM(A B C) makes 1,000,000. The MaxString/MinString/OrdMaxString/OrdMinString(CobolCollation, ...) overloads also create a new Func delegate per call from the instance method group `collation.Compare` (Exact.cs:332-344). The R0 baseline already shows allocation as the runtime's measured weak point (MOVEHOT 1,765.9 MiB allocated per run), and none of these arrays outlives the call.
