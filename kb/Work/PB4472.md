# PB4472 - EntryOptionsReaderDriftTests checks one file of twenty

**Where the code is.** The test is PB4464's, on branch `worktree-wf_ec0327b7-bfd-1` (worktree `E:\COBOL\.claude\worktrees\wf_ec0327b7-bfd-1`,
head `fc3b14bde`); origin/main does not have it yet (PB4464 is open). Read there:
`tests/WiseOwl.Cobol.Tests.Unit/EntryOptionsReaderDriftTests.cs:21` (`Binder(string file)`), `:26` (the scan of `Binder("DataBinder.cs")`), `:35`
(the second fact, which reads `OoDataBinder.cs`). `src/WiseOwl.Cobol.Compiler/Binding/DataBinder*.cs` is 20 files on that branch.

**Defect.** The test claims it refuses any direct read of the unit's options slice (`State.Configuration.Options.*`) by the entry binder.
The entry binder is `DataBinder` as a partial class, 20 files (`DataBinder.UsagePhrases.cs`, `DataBinder.UsageDeclaration.cs`,
`DataBinder.DescriptionCompletion.cs`, ...), and the first fact reads only `DataBinder.cs`. A direct read of `OptionsModel.FloatBinaryEndianness`
(or any field PB4464 swept) added in a partial passes the test and reintroduces the PB4464 wrong answer (a method's own `OPTIONS
FLOAT-BINARY` ignored by its local-storage entries). Today no partial has the shape; the claim is wider than the check.

**Fix shape.** Scan `Directory.EnumerateFiles(Binding, "DataBinder*.cs")` (and, after the extract in #1054 moves the entry binder, whatever
the drift-test pattern of `OptionsModelConsumerDriftTests` uses for its file set, so the two tests share ONE file-set definition), assert the
set is non-empty, and keep the `OoDataBinder.cs` fact. Per DESIGN-architecture-review section 8.3 (1) the reader list is a structure, not a
hand list: derive the file set, do not name it.
