# PB5936 - the compiled-program cache drift tests name three projects, the compiler's closure has more

**Sites:** `tests/WiseOwl.Cobol.Tests.Conformance/CompiledProgramCacheDriftTests.cs#EveryAmbientReadInTheCompiler_IsRecorded` (line 455, the
project list at line 465) and `#TheCompiler_HasNoPublicMutableStatic` (line 490, the name filter at line 494),
`tests/WiseOwl.Cobol.Tests.Conformance/CompiledProgramCache.cs#CompilerClosure` (line 232).

**Evidence (read and grepped on origin/main 0d4042678a).**
- `git grep -n "EveryAmbientReadInTheCompiler_IsRecorded\|TheCompiler_HasNoPublicMutableStatic\|CompilerClosure" -- '*.cs'` finds the two tests in
  `CompiledProgramCacheDriftTests.cs` and `CompilerClosure()` in `CompiledProgramCache.cs`.
- Test 1 scans `(string[])["WiseOwl.Cobol.Compiler", "WiseOwl.Cobol.Frontend", "WiseOwl.Cobol.Editions"]` by directory (`TestRepo.Src(project)`).
  Test 2 filters `CompilerClosure()` with `a.GetName().Name is "WiseOwl.Cobol.Compiler" or "WiseOwl.Cobol.Frontend" or "WiseOwl.Cobol.Editions"`.
- `src/WiseOwl.Cobol.Compiler/WiseOwl.Cobol.Compiler.csproj:35` has a `ProjectReference` to `..\WiseOwl.Cobol.Listing\WiseOwl.Cobol.Listing.csproj`, so
  `CompilerClosure()` (the compiler plus every non-framework assembly it transitively references, which `ToolFingerprint` already hashes, line 206)
  contains `WiseOwl.Cobol.Listing`, and the key's code half covers it while neither drift test does. A `File.ReadAllText` of a probe, an
  `Environment.GetEnvironmentVariable` or a public mutable static added to the Listing assembly would be an input no key sees and no test refuses.
- The same fixed list is a hand-maintained one (CLAUDE.md rule 5: "never a hand-maintained list where a structure belongs"): the next project the
  compiler references (the backend assemblies, a CIL backend) is outside again.

**Fix shape.** Derive both lists from `CompiledProgramCache.CompilerClosure()` restricted to the repository's own assemblies (the `WiseOwl.Cobol.`
name root, as the sibling test at line 377 does), and for test 1 map each assembly name to its `src/<name>` directory; a closure assembly with no
source directory fails loudly (rule: an input a tool cannot resolve is a bug that fails). Pair it with a planted check that the derived set equals
the compiler csproj's project references, so a project added to the closure is covered with no edit. Sweep the siblings that name the same three
projects: `git grep -n '"WiseOwl.Cobol.Frontend"' -- tests` and the doc comment at line 447. The sibling test at line 335 lists six `required` closure members by hand, but only asserts presence, so it is not itself blind to Listing; the stray-assembly check at lines 342-346 asserts a loaded product assembly is in the keyed closure, not that its source is scanned for ambient reads.
