## Summary

`INSPECT S REPLACING ALL F BY R(1:L)` and `INSPECT S CONVERTING F(1:L) TO R`, where the reference modifier's length is
a data item, are legal: the syntax rules put a size rule on two literals only, and the sizes of identifiers are
compared when the statement runs (EC-RANGE-INSPECT-SIZE). GnuCOBOL 3.2.0 compiles and runs both programs correctly.
GnuCOBOL 3.3-dev r5751 refuses both at compile time ("REPLACING operands incompatible" / "CONVERTING operands
incompatible", "note: operands differ in size", exit 1), in the strict `-std=cobol2014` dialect and in the default one.
In both programs the operands have equal sizes when the statement runs, so no exception condition exists at all.
Class: rejects legal source; a regression of the 3.3 development line.

## Expected result (per ISO)

Both programs compile and print `[AZAZ]` and `[XYXY]`. ISO/IEC 1989:2023, each citation checked with
`python scripts/spec/cite.py --check` on 2026-10-30:

- §8.4.3.3.3 5) (OK): "Unless otherwise specified, reference modification is allowed anywhere an identifier
  referencing a data item of class alphanumeric, boolean, or national is permitted."
- §14.9.22.3 2) (OK): "Identifier-3, … , identifier-n shall reference an elementary item described implicitly or
  explicitly as usage display or national." The only size rules among the syntax rules are for two literals: 6) (OK)
  "When both literal-1 and literal-3 are specified, they shall be the same size ..." and 9) (OK) the same for literal-4
  and literal-5.
- §14.9.22.4 6) (OK): "Item identification for any identifier is done only once as the first operation in the
  execution of the INSPECT statement."
- §14.9.22.4 14) (OK): "The size of literal-3 or the data item referenced by identifier-5 shall be equal to the size of
  literal-1 or the data item referenced by identifier-3. If these sizes are not equal, the EC-RANGE-INSPECT-SIZE
  exception condition is set to exist and the results of the execution of the INSPECT statement are undefined." 22)
  (OK) says the same for CONVERTING (identifier-6 and identifier-7).

The size of `R(1:L)` is a run-time value (1 in inspvar1, equal to F; 2 in inspcnv1, equal to R), so the sizes are equal
and no exception condition exists. The compile-time latitude of §14.6.13.1.3 (an implementor need not produce
executable code for a fatal exception condition the compiler detects while checking is not enabled) does not apply:
there is no exception condition to detect.

Edition: 2014. The 2009 committee draft that became ISO/IEC 1989:2014 (CD 1.2, `std.txt`) carries the same ref-mod
rule 5), the same item-identification rule (general rule 5 there) and the same REPLACING size rule (general rule 13
there, with the EC-RANGE-INSPECT-SIZE consequence) in the same words.

## Fix site (GnuCOBOL 3.3-dev r5751 source, read observationally)

- `cobc/typeck.c`, `validate_inspect`: it takes both sizes from `calc_reference_size`, which returns 0 when the size is
  not known at compile time (a ref-mod whose length is not a literal). It then reports "operands incompatible" /
  "operands differ in size" whenever `tag_y != CB_TAG_CONST && size1 != size2`, so 0 against a known size is refused.
- 3.2 (`cobc/typeck.c`, `validate_inspect`, read in the 3.2 source) compared only when both were known: `if (size1)`
  ... `if (size2 && size1 != size2)`. The 3.3-dev rework that added the identical-operand checks (cobc/ChangeLog
  2023-09-06: "typeck.c (validate_inspect): check for identical operands, check for invalid combination of operands",
  read in the r5751 tree) dropped that guard. Inferred from the source, consistent with both runs.
- The drafted patch adds `size1 != 0 && size2 != 0` to the comparison; libcob still compares the sizes at run time
  (`inspect_common`, `cob_inspect_converting_intern` in `libcob/strings.c`). It also restores the 3.2 expectation of
  `tests/testsuite.src/syn_refmod.at` "constant-folding out of bounds" (with `-fno-constant-folding`) and adds a run test;
  the drafter reports `make check` 1373 expected, 9 skipped, 0 failed with the patch.

## Draft issue

**Title:** INSPECT REPLACING/CONVERTING refused when a ref-mod operand has a variable length (3.3-dev regression)

**Versions:** GnuCOBOL 3.2.0 (Ubuntu `gnucobol3 3.2-4build1`) and 3.3-dev r5751 (CI snapshot 3.3-dev.138 of
2026-10-29), x86_64 Linux.

**Attached:** `inspvar1.cob`, `inspcnv1.cob` and `inspect-refmod-replacing-refused.patch` (against 3.3-dev r5751).

`inspvar1.cob` (free format):

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. INSPVAR1.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 S PIC X(4) VALUE "ABAB".
01 F PIC X(1) VALUE "B".
01 R PIC X(2) VALUE "ZZ".
01 L PIC 9 VALUE 1.
PROCEDURE DIVISION.
    INSPECT S REPLACING ALL F BY R(1:L)
    DISPLAY "[" S "]"
    STOP RUN.
```

`cobc -std=cobol2014 -fformat=free -x -o inspvar1 inspvar1.cob && ./inspvar1`: 3.2.0 compiles and prints `[AZAZ]`.
3.3-dev r5751 stops with `inspvar1.cob:10: error: REPLACING operands incompatible` / `note: operands differ in size`,
exit 1. `inspcnv1.cob` (`01 F PIC X(2) VALUE "AB".`, `01 R PIC X(2) VALUE "XY".`, `01 L PIC 9 VALUE 2.`, `INSPECT S
CONVERTING F(1:L) TO R`): 3.2.0 prints `[XYXY]`; 3.3-dev gives `CONVERTING operands incompatible`, exit 1. The default
dialect (no `-std`) gives the same errors.

The operands have the same size when the statement runs, and cobc cannot know the size of `R(1:L)` at compile time.

**Expected:** both compile and print `[AZAZ]` and `[XYXY]`, as with 3.2.0. ISO/IEC 1989:2023 (the 2014 committee draft
has the same rules): reference modification is allowed wherever an alphanumeric identifier is (8.4.3.3.3 rule 5); the
syntax rules of INSPECT require equal sizes only for two literals (14.9.22.3 rules 6 and 9); for identifiers the sizes
are compared when the statement runs, and a difference sets EC-RANGE-INSPECT-SIZE (14.9.22.4 rules 6, 14 and 22).

**Cause and patch:** `validate_inspect` in `cobc/typeck.c` gets the sizes from `calc_reference_size`, which returns 0
when the size is not known at compile time. 3.2 skipped the comparison when either size was 0; the 3.3-dev rework
(cobc/ChangeLog 2023-09-06) compares without that guard. The attached patch adds `size1 != 0 && size2 != 0` to the
comparison, restores the 3.2 expectation of `syn_refmod.at` "constant-folding out of bounds" (`-fno-constant-folding`,
length not known at compile time), and adds the run test "INSPECT REPLACING / CONVERTING with variable ref-mod" to
`run_misc.at`. `make check` on r5751 with the patch: 1373 behaved as expected, 9 skipped, 0 failed.

**Related:** bugs #1184 (INSPECT does not permit FUNCTION), a different refused INSPECT operand.
