# PB3371 — the survey calls a branch with unlanded work superseded

**Sites:** `scripts/prune_worktrees.py` (`lifecycle`), `scripts/orchestrator/review_lane.py` (`conflict_cause`, `tick`)

Filed 2026-10-18 from the operator's handoff (`E:\COBOL-coord\handoff.last.json`, item 2).

## What happens

`scripts/prune_worktrees.py` `lifecycle()`, the `if rep.lead_terminal:` arm (line ~463), marks a FINISHED report's
branch `DECISION ... superseded (its work reached main through another branch); confirm nothing unique remains, then
delete it` whenever the report's lead note is landed or retired, even when `evidence(row)` on the same line reports
`UNLANDED (1 added file(s) absent from main ...)`. A branch that AMENDS a landed note (adds unlanded work under a landed
lead) is therefore advised for deletion.

## Repro

Branch `notes-pb3149-owner-20261018` @1e4a4e8c6 (report `E:\COBOL-coord\scratch\reports\w1117z-PB3149-report.md`) adds
the owner's confirmation to the landed PB3149 note, to `docs/CONFORMANCE.md` D-MCS-NR and a
`DEVLOG/pending-pb3149-owner-confirms-the-requester-spelling.md`, none on main. At 2026-10-18 03:51 PDT the survey
printed it as `DECISION ... DONE, but PB3149 is already landed: superseded ...; UNLANDED (1 added file(s) absent from
main ...)`. The operator decided to land it (`enqueue.py land --lane clerk`, 2026-10-18).

## Harm

The survey's own instruction ("then delete it") would lose an owner's recorded decision (the never-lose-work rule).

## Fix shape

The lead_terminal arm decides "superseded" only when the content evidence shows nothing unlanded; a branch with
unlanded work under a landed lead reads as an ordinary finished branch (WAITING FOR REVIEW / WAITING TO LAND by its
review stamp, or a lane's).
