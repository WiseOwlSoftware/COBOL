# PB5826 - at --std 85 a relation or sign condition with no reference to a variable compiles clean, where the 1985 text requires one; the two sentences have no row in the 1985 catalog

**The row `1985-SR-VI.6.22.3-3` itself is CONFIRMED; a defect outside it is UPHELD (a), harm under_rejects.** The ruling's row for mechanism 7 (copied): `WHEN 1 + 1 = 2` and `WHEN 3 IS POSITIVE` compile clean at 85. SEARCH's SR3 admits any conditional expression and the compiler admits it, so this row stands. What is broken is the 1985 text of the relation and sign conditions, which has no catalog row. Cause (a): 2023 is right at 2023 (it dropped the sign sentence and asks only for an operand that is not a literal), so a 1985 arm is missing. The checker's confidence: medium. Severity MINOR follows the under_rejects notes of the same batches; the ruling names none.

**Mechanism 7, ruled** (the ruling's paragraph, unchanged). `§1985:VI.6.3.1.1` says: "The relation condition must contain at least one reference to a variable" (cite.py OK), and the sign condition's text says the same of its arithmetic expression. The compiler at 85
applies the 2023 rule instead (an operand that is not a literal, `docs/conformance` D-RELLITERAL), which `1 + 1 = 2`
passes. That is a defect at 85 and is filed. It is not a contradiction of `1985-SR-VI.6.22.3-3`: that rule grants
"any conditional expression" and is met. The two sentences are clause text with no row in the 1985 catalog, so no
1985 row could have caught them: the note carries that as a catalog gap.

**The catalog gap.** The checker's reading: the catalog has no `1985-*-VI.6.3.1.1-*` and no `VI.6.3.1.5` rows, so the SEARCH row is where the defect surfaced; the defect is in the shared condition binder, not SEARCH. The checker adds that the integrator may prefer a catalog row for the clause sentences. PB5481's GnuCOBOL latitude (EVALUATE literal x literal) does not reach this: EVALUATE builds no relation condition, while here the "must" governs the relation condition itself.

**The checker's evidence.** The 1985 text states for the relation condition that it must contain at least one reference to a variable, and for the sign condition that arithmetic-expression-1 must contain one. SEARCH SR3 admits any conditional expression, that is, a conforming one. `WHEN 1 + 1 = 2`, `WHEN 3 IS POSITIVE`, `IF 2 * 2 = 4` and `IF 2 * 2 IS NOT ZERO` compile and run at 85 with no diagnostic.

**Expected:** a refusal (or at minimum a flag) of each of the four conditions at `--std 85`. **Observed:** it compiles with no diagnostic; all four print HIT.

**Where** (the checker's reading): the 2023 not-a-literal test runs at every edition, and the 1985 sign condition has no variable check at all.
