# PB6116 - a second floating string of a different extended character-1 is accepted and renders wrongly

```cobol
01 D PIC LL99FF EDITING L FOR NEGATIVE IS "-"
                EDITING F FOR NEGATIVE IS "-".
...
MOVE -5 TO D
DISPLAY "[" D "]"
```

binds, and shows `[ -0005]` (repro `p4.cob`, item D, in the scratch directory of wave 20262145 group C; the file also holds item E with a P
between). §2023:13.18.40.3 SR27 permits no more than one floating string in character-string-1; the second `FF` run is a second floating string
(of a different extended character-1 from the leading `LL`). A trailing floating string also has no general rule that gives it an image: the
string of floating symbols represents leading numeric positions, so nothing renders the trailing `FF` as `-` and the `[ -0005]` is a result no rule
describes. Two defects in one: the program should be refused (under-rejection), and what is bound is a wrong answer.

Verified for the citation: `cite.py --check "§2023:13.18.40.3 SR27" "No more than one of the following may be specified in character-string-1"` answers
OK this session.

**Root.** `PictureComposition.Validate` walks Table 10 role by role. The `Precedence` role map gives a floating extended symbol no matrix role, so
the walk never asks Table 10 whether a second floating string may follow, and the first-run-names-the-string reading in `PictureShape`'s
constructor (after PB3221) counts only the occurrences of the first floating symbol.

**Site.** `src/WiseOwl.Cobol.Compiler/Binding/PictureComposition.cs` (`Validate`, the `Precedence` role map, the character-1 arm; and
`PictureShape`'s constructor, which comment-claims "the Table-10 walk refuses a second of '+', '-' or the currency symbol").

**Sibling sweep to do.** The same shapes for `+`, `-`, currency, `*` and `Z` (which the walk does refuse), then each extended pair (`LL99FF`, `LL99PPFF`
from the same probe's item E, one floating then a fixed extended symbol, two floating of the same character split by a digit), at every edition
that has the extended symbols (2023). Pair each with a refusal golden and a drift test that reads the Table 10 role map so a floating extended symbol
cannot again fall outside it.

**Next.** Give the floating extended symbol its Table 10 role (or refuse a second floating run in `Validate` before the shape is made), cite
§2023:13.18.40.3 SR27 and the extended-character rule from the clause's own text, and add the golden pair (the refused form, and `LL99` alone
accepted).
