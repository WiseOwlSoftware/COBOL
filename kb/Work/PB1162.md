# PB1162 — OPEN

## The rule (every citation re-run by the registrar through `cite.py --check`)

> RETRY ┤ FOR arithmetic-expression-2 SECONDS ├ (general format; arithmetic-expression-1 TIMES / FOREVER)

`python scripts/spec/cite.py --check 14.7.9.2 "…"` → `OK  §14.7.9.2   (General format)`

> An arithmetic expression may be … an arithmetic expression enclosed in parentheses

`python scripts/spec/cite.py --check 8.8.1.1 "…"` → `OK  §8.8.1.1   (General)`

## Finding — `retry-phrase` (rejects-legal-source; rows `FMT-14.7.9.2`)

**Mechanism.** Lexer subscript trigger is edition-blind: a '(' after a word that is reserved at the target edition (RETRY, B-AND, B-SHIFT-L, ...) is lexed as a subscript opener because the word is a legal user word at SOME edition

**Repro.** SELECT F ASSIGN "x.dat" ORGANIZATION RELATIVE ACCESS DYNAMIC RELATIVE KEY K LOCK MODE MANUAL. 01 N PIC S9V9 VALUE 1.5. PROCEDURE DIVISION. READ F RETRY (N) TIMES.  (also WRITE R RETRY (N + 1) TIMES / OPEN INPUT RETRY (N) TIMES F / DELETE FILE F RETRY (N) TIMES; sibling: COMPUTE C = A B-AND (B B-OR A). and COMPUTE C = A B-SHIFT-L (N). with USAGE BIT items) — cobol --std 2023

**Expected from the spec.** Compiles: §14.7.9.2 takes arithmetic-expression-1/-2, and §8.8.1.1 'An arithmetic expression may be ... an arithmetic expression enclosed in parentheses' (cite.py --check 8.8.1.1 OK); §8.8.2 Table (cite.py --check 8.8.2 "B-AND, B-OR, B-XOR" OK) permits '(' after a boolean operator.

**Observed / reasoning.** COBOL0001 'cannot parse construct near N' at 2002/2014/2023 for every RETRY site; `RETRY FOR (N) SECONDS` and `RETRY 1 + (N) TIMES` compile, isolating the '(' immediately after RETRY. `A B-AND B` compiles, `A B-AND (B B-OR A)` does not. Cause: CobolLexer.g4 OnDefaultLParen pushes SUBSCRIPT when PreviousTokenCouldBeDataName(), and the generated `_dataNameTokens` (CobolLexerWordSet.g.cs, from cobol-words.json subscriptTrigger rows) contains RETRY, B_AND, B_OR, B_XOR, B_SHIFT_L..., EXCLUSIVE_OR etc. with no edition test — at an edition where §8.9 reserves the word it can never be a data-name. Root fix: make the trigger consult the edition's reservation (the same derived set ReservationGateRewriter/IsReservationGated uses) rather than token type alone, and sweep every word in _dataNameTokens that a general format follows with an expression.

**Code site.** src/Cobol.Net.Frontend/Grammar/Core/CobolLexer.g4#OnDefaultLParen / PreviousTokenCouldBeDataName; src/Cobol.Net.Frontend/Parsing/CobolLexerWordSet.g.cs#_dataNameTokens

## What the fixer owes

Make CobolLexer.g4 OnDefaultLParen / PreviousTokenCouldBeDataName consult the edition's reservation (the same derived set ReservationGateRewriter / IsReservationGated uses) rather than token type alone; then sweep EVERY word in the generated `_dataNameTokens` (CobolLexerWordSet.g.cs, from cobol-words.json subscriptTrigger rows) that a general format follows with an expression or a parenthesised operand. Drift test: no word reserved at edition E is a subscript trigger at E.
