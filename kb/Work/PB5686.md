# PB5686 - at 2002 a universal INVOKE resolves by 2023's signature match, not by method-name

**Site (lead, from the writer; the integrator confirmed the member exists):**
`src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/OoEmitter.cs#EmitCobolInvokeCase`. A method that does not MATCH the argument
list (PB1500's 2023 rule, landed) breaks out into the base search, which ends in EC-OO-METHOD. Nothing gates this on
`--std`.

**Rules (each checked with `python scripts/spec/cite.py --check`, verdict OK).**

- `§2002:9.3.5`: "if a method with the method-name specified in the invocation is defined in the class of the object, that method is bound". The binding is by name alone. Only a name found nowhere sets EC-OO-METHOD (`§2002:14.8.22.3 GR7b`: "the EC-OO-METHOD exception condition is set to exist, the method is not activated").
- `§2002:14.8.22.3 GR7c`: "the EC-OO-UNIVERSAL exception condition is set to exist if checking for it is enabled in both the invoked method and the activating runtime element". It applies 14.7 conformance to the bound method.
- `§2002:14.7.1.1` rule 1 (writer's citation, OK): a BY REFERENCE alphanumeric group and an alphanumeric elementary item conform when the formal is no longer than the argument. A strong-typed formal needs an argument of the same type.

**Expected (derived from the 2002 text):** TW binds and violates rule 1 (a 4-byte argument for an 8-byte formal). TG
and TX bind and conform. TS binds and violates the same-type rule. NOSUCH is found nowhere.

```
H=[EC-OO-UNIVERSAL                ]
TG:ABCD
TX:ABCD
H=[EC-OO-UNIVERSAL                ]
H=[EC-OO-METHOD                   ]
END
```

**Observed at `--std 2002` (build of 63ab0c4ece):** `H=[EC-OO-UNIVERSAL ...]` once, then `H=[EC-OO-METHOD ...]` four
times, then `END`. TG, TX and TS are never activated.

**A golden encodes the 2023 answer at 2002.** `conformance-suite/cases/9.3.6-Method-invocation/pb480_universal_match_relations`
is accepted at `[2002]` only, cites the 2023 match rules (§2023:9.3.6), and, on the writer's reading, encodes the 2023 answer for its TG, TX, plain-group TS and TQ
legs. The fix must re-derive that case's 2002 expectations from `§2002:9.3.5` and `§2002:14.7`, or move
it to the edition whose rules it states.
