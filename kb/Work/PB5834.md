# PB5834 - OPEN: may ALL stand for any argument of a function whose definition allows repetition, or only for the repeated argument (PRESENT-VALUE (T (ALL)))? The 1989 text admits both readings

**Ruling: NOT DECIDED.** `PRESENT-VALUE (T (ALL))` supplies argument-1 and the whole argument-2 series from one table. The text admits two readings of where ALL may stand. GnuCOBOL was not measured (it is not on this host). The row `1989-FMT-A.2.34.2` stays `undecided`. Harm: under_rejects under reading B only (not set while the row is open). The checker's confidence: medium.

**What the compiler does.** `PRESENT-VALUE (WS-E (ALL))` over 0 10 20 30 equals `PRESENT-VALUE (0 10 20 30)` = 60 at 85 and at 2023 (`pvall.cob`).

**The two readings (the checker's).**
- Reading A (the compiler's): `§1989:A.2.2` gates ALL on the function's definition ("When the definition of a function permits an argument to be repeated a variable number of times") and defines the effect as textual expansion ("the effect is as if each table element associated with that subscript position were specified"), and the expansion `PV (E(1) E(2) E(3) E(4))` satisfies the general format `§1989:A.2.34.2`: legal.
- Reading B: the table reference stands only for the argument the definition lets repeat (argument-2), so a lone ALL reference leaves argument-1 unwritten and is outside the format: it must be refused.
- The 1985 text says neither "in place of that argument" nor "any argument"; 2023 keeps the sentence unchanged (`§2023` line 29610 of the transcription), so it does not settle it either. PRESENT-VALUE is the only 1989 function with a non-repeating leading argument and a repeated tail, so the question is this one row.
- What settles it: an X3J4/J4 interpretation, or the rule-1 precedence applied as latitude (GnuCOBOL's behaviour, measured; cobc is not on this host).
