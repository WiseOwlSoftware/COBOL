# PB4086 — the optional-words audit cannot see a word one merged format demands and the other omits

**Site:** `scripts/spec/audit_grammar_optional_words.py` (`Layout.demanded_with`, called from the per-arm required-word loop; line
759 at `4e8251f4f`, branch `worktree-wf_66e93b32-365-8`, PR #795 / PB2024).

**What it does.** For a grammar arm that omits a word, the audit reports `required-word` only if
`layout.demanded_with(xs, demanded_word)` holds, which needs EVERY printed SEND format to demand the word together with the arm's
demanded words. When the grammar merges two printed formats (SEND, §14.9.38.2) and one format prints the word unbracketed while
the other omits it (RETURNING: Format 1 prints it, Format 2 has none), only one format demands it and the audit stays silent.

**The consequence on record.** `tests/version-matrix/inventory/` row `SR-8.3.2.4.2-1` was re-verdicted CONFORMS
by PR #795 (PB2024; line 1077 on that branch) on the strength of the audit reporting 0 undecided candidates. The same report lists
a live violation of the rule it audits: `SEND TO message-server-name-1 FROM x` with no RETURNING compiles. PB4085 is that compiler
defect; this note is why the audit did not see it. The row's CONFORMS verdict rests on the audit while PB4085 is open. This note
does not edit the inventory.

**Direction (not a fix).** Judge each printed format of a construct separately: an omitted word is reportable when ANY printed
format demands it with the arm's other demanded words. Add a fixture-grammar arm to the audit's `--self-test` for two merged
formats where only one prints the word unbracketed.
