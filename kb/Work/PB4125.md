# PB4125 — for FUNCTION CONVERT (rule FollowsDestinationFormat) IntrinsicResultType.Resolve answers the declared sig.Type

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Bound/BoundTree.cs:366` (`BoundIntrinsicCall.ResultType`, `BoundIntrinsicCall.ResultIsAlphabetic`), `src/WiseOwl.Cobol.Compiler/Binding/IntrinsicResultType.cs:154` (`IntrinsicResultType.Resolve`).

Review lead R1-1 (low, round 1) of PB4036. `BoundIntrinsicCall.ResultType` (BoundTree.cs:374 on the reviewed branch) is documented as THE
call's §15.2 type that every reader asks. For `FUNCTION CONVERT` (rule `IntrinsicResultRule.FollowsDestinationFormat`, IntrinsicResultType.cs:193,
`=> sig.Type`) `Resolve` answers the catalog's declared type, `Alphanumeric`, while the destination format decides the actual category:
the node carries `ResultType` Alphanumeric beside `ResultCategory` National. The two type facts for one decision can disagree, and a
reader that asks the "THE type" property gets the declared one.

**Fix:** let `Resolve` take the destination format into account for this rule (the rule's name says it follows it), or remove the
declared type and make the one fact a function of the bound destination; pin with a test that `ResultType` and `ResultCategory` agree
for each CONVERT destination format (a drift test over the catalog's rules: every rule's `Resolve` result is consistent with the node's
category).
