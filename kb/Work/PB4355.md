# PB4355 - landing.md section 3 omits the exit-14 refusal and the one case where a landing gates

**Sites:** `.claude/skills/workstream/references/landing.md` (section 3, the first bullet, lines 5-12).

The bullet says `enqueue.py land` "reads the record of the branch's own local gate instead of gating", unconditionally. It omits two facts. First, when no record covers the branch tip, `land` refuses with exit 14. Second, when bringing main in changed a file the branch also changes (a true textual merge in a shared file), the landing does gate: `scripts/orchestrator/enqueue.py` lines 1195-1202 set `gate_why` from `merge_overlap(wt, tested_head, base)`. CLAUDE.md (Testing) and MANDATORY-PRACTICES L1 and L2 state both; the skill reference is the one place that reads as if the landing never gates.

Fix: add the exit-14 refusal and the shared-file merge exception to the bullet, in the wording of MANDATORY-PRACTICES L2. Sibling sweep: grep `.claude/skills`, `scripts/orchestrator/units` and `docs/rearchitecture/DESIGN-orchestrator-loop.md` for "instead of gating" and "gates nothing" and check each against the same two exceptions.
