# PB3280 — DISPLAY-only numeric image marks versus USAGE NATIONAL

Source: PB442's report (`E:/COBOL-coord/scratch/reports/w1091h-PB442-report.md`, "## New defects / leads", branch worktree-wf_00451f9d-3d9-20, PR #125). PB442's finisher probes showed that forcing the image mark on a SINGLE national leaf is safe; the open question is whether the sites below should also admit national.

**Sites re-checked on origin/main 4344c7fba** (`src/Cobol.Net.Compiler/Binding/`). The lead listed five; two of them are NOT DISPLAY-only, so the question is three sites, not five.

DISPLAY-only (`Category: Numeric, IsFloat: false, Usage: Usage.Display`), these are the subject:
- `DataBinder.cs:748` (whole-group union, comment cites 14.9.25.4 MOVE GR4).
- `DataBinder.cs:7857` (Tier-B leaves of a StringCanonical class; the comment notes a Ptr-FORCED class deliberately never records).
- `DataBinder.Reports.cs:3212` (report item, "compose wants the printable CHARACTER image").

Not DISPLAY-only (correction of the lead):
- `DataBinder.cs:7872` marks the fixed-point BINARY/PACKED branch of the same Tier-B loop, guarded at `:7862` by `HasImageByteForm: true, Usage: not Usage.Display` (the one image predicate, PB164).
- `DataBinder.Linkage.cs:888` uses `HasImageByteForm: true` with no usage test, so it already follows the one predicate; its comment at `:880-886` records that this predicate must equal CellCapable's.

**Work.** Probe each of the three DISPLAY-only sites with a USAGE NATIONAL numeric item (the lead supplied no repro for these three, so the probes are new), compare with the `HasImageByteForm` sites, and decide against the ISO spec (derive the clause and run `python scripts/spec/cite.py --check`) whether national belongs in each. If it does, fold the three sites onto the one image predicate rather than adding another hand-written condition (CLAUDE.md rules 4 and 5).

## Re-filed as a defect (analyses sweep, 2026-10-23)

Adjudicated read-only by an Opus cobol-adjudicator on main e7cf38ce4; accepted by the Mythos session.

A report printable item of category numeric with USAGE NATIONAL (legal: §13.18.60.3 SR7 admits NATIONAL in a report group item, and SR12 admits a numeric picture with usage national) crashes the compiler's backend with CS1503 at every edition. Repro: RD R PAGE LIMIT 10. 01 D TYPE DETAIL LINE 1. 05 COLUMN 1 PIC 9(3) USAGE NATIONAL SOURCE N. Expected: the program compiles and the line holds '042' in national characters. Cause: DataBinder.Reports.cs:3228 marks only { Numeric, !IsFloat, Usage.Display } as image-forced, so the national leaf reaches CobolReport.Place as a long. The national numeric-edited and PIC N arms work. The question this note asked is the image-form question, so the fix reads PicInfo.IsCharacterFormNumeric (the one predicate) at :3228 or composes the national image as the edited arm does, and the report entry moves from the 'KEEPER' bucket of DisplayUsageUnionDriftTests with a golden. The other two sites need no change: PB646 settled them.

Evidence: Of the three sites, PB646 (609e1e715) already answered two with measured reasons pinned in DisplayUsageUnionDriftTests.HandRolledDisplayUnion_IsTheKnownInventory: MarkImageLeaves (DataBinder.cs:781) is a carriage question and stays DISPLAY-only on purpose, and the Tier-B StringCanonical loop (DataBinder.cs:7918/7923) sends a national-form leaf to its HasImageByteForm arm. The third, the report site, is a live defect. Probe probes/pb3280/r3280.cob on a build of main 1595fabc8's src: a printable item PIC 9(3) USAGE NATIONAL SOURCE N fails backend compilation (CS1503 'cannot convert from long to string', g.cs line 42: __RPT_0.Place(__ln, 1, (long)CobolNum.Store(...))) at --std 2002/2014/2023. The DISPLAY twin (r3280b) prints '042  042', and PIC N(3) and Z9(2) USAGE NATIONAL items (r3280c) work.

Rule: §13.18.60.3 SR7 (checked); §13.18.60.3 SR12 (checked)

## Landed (wave 20261032, group A)

Re-probed on the branch's own build: r3280.cob failed backend compilation, `(42,32): error CS1503: Argument 3: cannot
convert from 'long' to 'string'`. **Fix.** The report printable item's image mark asks the IMAGE-FORM question, so it
now reads the one predicate that asks it, `PicInfo.IsCharacterFormNumeric` (display or national), instead of the
DISPLAY-only shape; a printable item is composed into its line and stored nowhere else, so the carriage concern that
keeps `MarkImageLeaves` DISPLAY-only (PB646) does not reach it. The other two sites stay as PB646 settled them.
`DisplayUsageUnionDriftTests.HandRolledDisplayUnion_IsTheKnownInventory` drops the Reports.cs entry and records why.
r3280 now prints `042  042`. **Golden** `2002/pb3280_report_national_numeric_item`: an own `USAGE NATIONAL` numeric
item, a level 1 `USAGE NATIONAL` inherited by a numeric item (§13.18.60.4 GR1), and a national signed item with
`SIGN LEADING SEPARATE` (`-005`, which also exercises PB493's §13.18.52.3 SR2 usage pair).
