# PB3280 — DISPLAY-only numeric image marks versus USAGE NATIONAL

Source: PB442's report (`E:/COBOL-coord/scratch/reports/w1091h-PB442-report.md`, "## New defects / leads", branch worktree-wf_00451f9d-3d9-20, PR #125). PB442's finisher probes showed that forcing the image mark on a SINGLE national leaf is safe; the open question is whether the sites below should also admit national.

**Sites re-checked on origin/main 4344c7fba** (`src/Cobol.Net.Compiler/Binding/`). The lead listed five; two of them are NOT DISPLAY-only, so the question is three sites, not five.

DISPLAY-only (`Category: Numeric, IsFloat: false, Usage: Usage.Display`), these are the subject:
- `DataBinder.cs:748` (whole-group union, comment cites 14.9.25.4 MOVE GR4).
- `DataBinder.cs:7857` (Tier-B leaves of a StringCanonical class; the comment notes a Ptr-FORCED class deliberately never records).
- `DataBinder.Reports.cs:3212` (report item, "compose wants the printable CHARACTER image").

Not DISPLAY-only (correction of the lead):
- `DataBinder.cs:7872` marks the fixed-point BINARY/PACKED branch of the same Tier-B loop, guarded at `:7862` by `HasImageByteForm: true, Usage: not Usage.Display` (the one image predicate, PB164).
- `DataBinder.Linkage.cs:888` uses `HasImageByteForm: true` with no usage test, so it already follows the one predicate; its comment at `:880-886` records that this predicate must equal CellCapable's.

**Work.** Probe each of the three DISPLAY-only sites with a USAGE NATIONAL numeric item (the lead supplied no repro for these three, so the probes are new), compare with the `HasImageByteForm` sites, and decide against the ISO spec (derive the clause and run `python scripts/spec/cite.py --check`) whether national belongs in each. If it does, fold the three sites onto the one image predicate rather than adding another hand-written condition (CLAUDE.md rules 4 and 5).
