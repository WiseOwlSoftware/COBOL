# R67 — implementer turn cap 400, smaller batches

**Observed 2026-09-30:** nearly every batch implementer stopped at the 220-turn cap with no report (PB468 had adopted 160 read-only / 220 implementer for ONE rendered kb/Work group per agent; the owner's workflow is a batch of 10-20 bugs per commit, each tested individually, two gates, and the register paperwork — it does not fit). **Owner: raise `maxTurns` to 400 and use smaller scopes.**

**Applied:** `.claude/agents/cobol-implementer.md` `maxTurns: 400`; MANDATORY-PRACTICES P5 and the workstream SKILL table updated (the old "never extend" wording is superseded for the implementer cap by this decision); the read-only cap stays 160 and the lander 220. **Dispatch rules from now on:** 6-8 bugs per implementer; checkpoint-commit after every 3-4 verified bugs so a cut-off loses nothing; verify each bug with a targeted test or filtered run and run the full gate ONCE at the end; run each gate once in the background and read the verdict once (no polling); batch tool calls and do not re-read files; stop and report at about 350 turns even if unfinished.
