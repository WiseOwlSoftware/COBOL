# PB5051 - the PB5031 verdict argues unreachability of GR3a, but the printed GR2 constrains only the index-name-2 value, so the argument is unsound

**Sites:** `kb/Work/PB5031.md` (the verdict, about line 47 of the PB5031 branch under review; the note on main has 40 lines, so the verdict is not yet on main).

**Found.** The verdict argues that the printed reading of `§1985:VI.6.23.4 GR2` ("If index-name-2 is specified, the value of the index before the execution of the SET statement must correspond to an occurrence number of an element in the table associated with index-name-1.", `cite.py --check` OK) would make GR3a conversion unreachable. The printed sentence constrains only the VALUE of index-name-2 (an occurrence number valid in the table of index-name-1), not which table index-name-2 is associated with, so GR3a conversion stays reachable under it. The evident-sense conclusion (the sentence means index-name-2's own table) is right, but rests on an unsound argument.

**Owed.** Replace the argument with a sound one (for example the sentence's subject, and the other GR2 uses of index-name-2) before the verdict lands or any 1985 behaviour cites it.

**Landed (2026-11-09, with PB5062).** Errata C32 and its flag in `specs/ANSI_COBOL_1985.md` now give the sound grounds: each of
the rule's three sentences pairs an index with its own table; an occurrence number means something only in the index's
associated table (GR1); GR3a's conversion reads index-name-2's value as an occurrence number of its own table; and
§2023:14.9.39.4 GR2a3b names the table element associated with index-name-2. The correction itself stands. PB5031's verdict
carries a pointer to this note beside the unsound sentence.
