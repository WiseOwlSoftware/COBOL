# PB6136 — LANDED — a push that would publish a licence stamp is refused before it leaves

## The defect

The bought PDFs stamp every page with the purchaser's name, an order number and the download date, and the repository
is public. `scripts/spec/verify_publishable.py` `check_tree` holds the tracked tree to `tree_shapes()`, but only inside
the gate, and a branch is pushed at every checkpoint (CLAUDE.md rule 7), gated or not. So stamp text reached origin
twice: the first time took a history rewrite and a GitHub Support purge (PB4814); on 2026-11-23 a branch pushed OCR text
carrying the stamp in commit `0953e584ed`, the gate went RED on it afterwards and the branch was force-pushed clean, but
GitHub still serves the commit by its SHA. Nothing ran the shape check before a push. Git ran no hook at all on this
host: the global `core.hooksPath` names the hooks directory of a former checkout, which does not exist.

## The fix

One scan, two callers.

- `scripts/spec/verify_publishable.py` `text_stamp_hits` / `stamp_hits` is THE tree matcher: the whole text of a file,
  searched for each `tree_shapes()` shape, so a shape that crosses a line break is found. `check_tree` and the push
  scan both read files through it.
- `scripts/hooks/git_pre_push.py` `scan(repo, sources, remote)` reads every file changed by a commit reachable from
  the push's sources `--not --remotes=<remote>` (`git log --raw`, merges against their first parent), whole, as its
  blob at that commit; those commits' messages; and the messages of the annotated tags the push sends (a tag named as
  a source or on git's stdin, every tag for `--tags`/`--mirror`, the tags pointing into the pushed commits for
  `--follow-tags` or `push.followTags`). A finding names the shape, the file and line (or the message) and the commit
  or tag object, never the matched text. A git it cannot read is a refusal (`None`): the scan fails closed. Commits
  already on the remote are not rescanned.
- `scripts/hooks/forbidden_commands.py` rule 2c calls it for every `git push` an agent runs through Claude Code whose
  destination is this repository's origin (`_push_destinations`), attended or in a unit, and refuses the tool call
  before the command line runs. `_push_sources` turns the refspecs into revisions (a deletion publishes nothing,
  `--all` the branches, `--mirror` every ref, no refspec HEAD); `--stdin` refspecs, refspecs fed by `xargs`, or a push
  in this repository whose destination cannot be determined, are refused. Because the scan runs before the line does,
  a push that follows any git call outside `_READS_ONLY` on the same line (commit, merge, cherry-pick, rebase, am,
  revert, tag, checkout, reset, an alias...) is refused with the instruction to push in its own command.
- `pre_push` in the same file is git's own pre-push hook, run by the tracked `.githooks/pre-push` wrapper (exit 1 when
  no Python is on PATH), so a push from any shell is covered.
- `scripts/hooks/tooling_check.py` `hooks_path_line` REPAIRs `git config --local core.hooksPath .githooks` at every
  session start when it is unset or anything else; the local value overrides the broken global one. The path is
  relative, so each worktree runs its own checkout's hook.

  expectations: a stamp in a changed file or a message refused, attended, in a unit and in the PowerShell tool; the
  clean neighbour, a deletion, another repository and a stamp already on origin passed; `--stdin`, xargs and an
  unreadable directory refused; the refusal names `ocr.json:1` and never the planted name; and the branch review's
  probes: `git add f && git commit -m x && git push -u origin HEAD` refused, a push after `git add`/`status`/`fetch`
  passed, after `checkout`, `merge` or an alias refused; an order number split across lines refused; an annotated
  tag's stamped message refused by name and through `--follow-tags`).

  21 expectations)`, including the tracked wrapper stopping a real `git push` to a scratch bare remote, which did not
  receive the ref, and letting a clean push through; a shape across a line break, in one commit and completed by a
  later one against the unchanged line; an annotated tag's message on git's stdin, by name, `--tags` and
  `--follow-tags`.

  `core.hooksPath` REPAIRED to `.githooks`, then OK).
