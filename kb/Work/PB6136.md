# PB6136 — LANDED — a push that would publish a licence stamp is refused before it leaves

## The defect

The bought PDFs stamp every page with the purchaser's name, an order number and the download date, and the repository
is public. `scripts/spec/verify_publishable.py` `check_tree` holds the tracked tree to `tree_shapes()`, but only inside
the gate, and a branch is pushed at every checkpoint (CLAUDE.md rule 7), gated or not. So stamp text reached origin
twice: the first time took a history rewrite and a GitHub Support purge (PB4814); on 2026-11-23 a branch pushed OCR text
carrying the stamp in commit `0953e584ed`, the gate went RED on it afterwards and the branch was force-pushed clean, but
GitHub still serves the commit by its SHA. Nothing ran the shape check before a push. Git ran no hook at all on this
host: the global `core.hooksPath` names the hooks directory of a former checkout, which does not exist.

## The fix

One scan, two callers.

- `scripts/hooks/git_pre_push.py` `scan(repo, sources, remote)` reads the ADDED lines (`git log -p -U0`, merges against
  their first parent) and the messages of every commit reachable from the push's sources `--not --remotes=<remote>`,
  and matches them against `verify_publishable.tree_shapes()`, imported, never copied. A finding names the shape, the
  file and line (or "the commit message") and the commit, never the matched text. A git it cannot read is a refusal
  (`None`): the scan fails closed. Commits already on the remote are not rescanned.
- `scripts/hooks/forbidden_commands.py` rule 2c calls it for every `git push` an agent runs through Claude Code whose
  destination is this repository's origin (`_push_destinations`), attended or in a unit, and refuses the tool call
  before git runs. `_push_sources` turns the refspecs into revisions (a deletion publishes nothing, `--all` the
  branches, `--mirror` every ref, no refspec HEAD); `--stdin` refspecs, or a push in this repository whose destination
  cannot be determined, are refused.
- `pre_push` in the same file is git's own pre-push hook, run by the tracked `.githooks/pre-push` wrapper (exit 1 when
  no Python is on PATH), so a push from any shell is covered.
- `scripts/hooks/tooling_check.py` `hooks_path_line` REPAIRs `git config --local core.hooksPath .githooks` at every
  session start when it is unset or anything else; the local value overrides the broken global one. The path is
  relative, so each worktree runs its own checkout's hook.

## Evidence

- `python scripts/hooks/test_forbidden_commands.py`: `forbidden_commands self-test: 387/387 GREEN` (19 rule-2c expectations:
  a stamp in an added line or a message refused, attended, in a unit and in the PowerShell tool; the clean neighbour,
  a deletion, another repository and a stamp already on origin passed; `--stdin` and an unreadable directory refused;
  the refusal names `ocr.json:1` and never the planted name).
- `python scripts/self_tests.py --only scripts/selftests/hooks/git_pre_push/test_pre_push.py`: GREEN, `PASS (6 cases,
  14 expectations)`, including the tracked wrapper stopping a real `git push` to a scratch bare remote, which did not
  receive the ref, and letting a clean push through.
- `python scripts/hooks/tooling_check.py --self-test`: `=== TOOLING_CHECK SELF-TEST: GREEN ===` (an other
  `core.hooksPath` REPAIRED to `.githooks`, then OK).
