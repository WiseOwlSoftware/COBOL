# PB3095 — a `cd` in a backgrounded list moves only the background subshell

## The finding (the operator's train-1067 land unit, 2026-10-11, lead 2)
The land unit launched its audit commands as `cd X && a & b &`. A single `&` ends an and-or list and runs the WHOLE list
in a background subshell (bash; a job in PowerShell 7), so the `cd` moved only that subshell: `a` ran under X and `b`
ran in the caller's directory, read the wrong tree, and reported OK. The false OK reached the queue's audit record.
MANDATORY-PRACTICES P14(b) already said "never `cd` inside a chain — use absolute paths or `git -C`", but
`scripts/hooks/forbidden_commands.py` enforced none of it, so the rule was prose only.

## Landed (wave 1068 A, branch of PB3024's closing change; MANDATORY-PRACTICES I9)
- `scripts/hooks/forbidden_commands.py` rule 7: `_and_or_lists` splits a command line into its and-or lists with their
  terminators (`;`, a newline, `&`, the end), quoted text never split; a `&` ends a list only as the background operator
  (never inside `&&`, never a redirection `2>&1` / `>&2` / `&>` / `|&`, never PowerShell's call operator at the start of
  a command). A list terminated by `&` that holds a location change (`cd`, `pushd`, `chdir`, `Set-Location`, `sl`,
  `Push-Location`) and is followed by another command is BLOCKED with the reason (use absolute paths or `git -C`; the
  backgrounded list ends at the `&`). The precise shape, not every `cd` in a chain: `cd X; a & b` (the `cd` is its own
  list and moves the caller), `cd X && a` and `cd X && a &` with nothing after it stay allowed.
- `scripts/hooks/test_forbidden_commands.py`: four block cases (the 2026-10-11 shape, `pushd`, a `||` in the list, the
  PowerShell form) and eight pass cases (a plain chain, a trailing `&` alone, a `cd` in its own list, `git -C` in the
  background, `2>&1`, `&>`, `|&`, quoted text, PowerShell's `& pwsh …` call operator): 105/105 GREEN.
- MANDATORY-PRACTICES P14(b) and `docs/DOC_INDEX.md`'s hook row name the enforced form.
- Code sites: `scripts/hooks/forbidden_commands.py` (`_CD_SEGMENT`, `_and_or_lists`, rule 7 at the end),
  `scripts/hooks/test_forbidden_commands.py` (`# 7.` cases, `PS_CASES`).

## Landing (for the next implementer; orient.py reads it)
- `scripts/hooks/forbidden_commands.py#_and_or_lists` is the one and-or-list splitter (terminators `;`, newline, the
  background `&`); `_segments` splits on `&&`/`||`/`;` for the verdict-chaining rule and is a different question. A `&`
  is background only when the segment before it is non-empty and it is not part of `&&`, `2>&1`, `>&2`, `&>` or `|&`.
- Trap: the hook guards the session that edits it — a heredoc with a backslash in the edit script is refused; write the
  script with the Write tool.
