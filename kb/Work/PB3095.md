# PB3095 — a `cd` in a backgrounded list moves only the background subshell

## The finding (the operator's train-1067 land unit, 2026-10-11, lead 2)
The land unit launched its audit commands as `cd X && a & b &`. A single `&` ends an and-or list and runs the WHOLE list
in a background subshell (bash; a job in PowerShell 7), so the `cd` moved only that subshell: `a` ran under X and `b`
ran in the caller's directory, read the wrong tree, and reported OK. The false OK reached the queue's audit record.
MANDATORY-PRACTICES P14(b) already said "never `cd` inside a chain — use absolute paths or `git -C`", but
`scripts/hooks/forbidden_commands.py` enforced none of it, so the rule was prose only.

## Landed (wave 1068 A, branch of PB3024's closing change; MANDATORY-PRACTICES I9)
- The shared parser `scripts/hooks/shell_location.py` (kb/Work PB2599) models the single `&` as the end of an and-or
  list that runs THE WHOLE LIST in a background subshell (Bash) or job (PowerShell 7, where a `&` after a command is the
  background operator and one that starts a command is the call operator): `_walk` snapshots the shell's state when a
  list begins and restores it when the list ends in `&`, so no location change (or variable) of a backgrounded list
  reaches the commands after it, and the first step after such a list carries that list's persisting location changes in
  `Step.stranded` (a `{ … }` group's too; a `( … )` subshell's, a pipeline side's or a `-c` payload's never persist
  anyway). Before, only the single command before a `&` was transient, so `cd X && a & b` gave `b` the cwd X: the build
  guard (`fleet_active_build.py`) and `status_guard.py` judged such a `b` to run under X.
- `scripts/hooks/forbidden_commands.py` rule 7 blocks any step whose `stranded` is non-empty, with the reason (use
  absolute paths or `git -C`; the backgrounded list ends at the `&`). The precise shape, not every `cd` in a chain:
  `cd X; a & b` (the `cd` is its own list and moves the caller), `cd X && a`, `cd X && a &` with nothing after it and
  `(cd X && a) & b` stay allowed. The first version (the reviewed head 746b383f5) used a private splitter that knew
  neither comments nor escapes and failed open (branch review R1-1); it is gone, and rules 5 (verdict chaining) and 6
  (WSL lifecycle) read the same parser too, so a comment's apostrophe, an escaped quote or a heredoc before a chain no
  longer hides it, and a `bash -c` payload's or a pipeline's later `wsl --shutdown` is seen.
- Self-tests: `test_shell_location.py` (backgrounded list, `{ }` group, comment apostrophe, PowerShell job, `stranded`)
  73/73; `test_forbidden_commands.py` 117/117 (rule 7's shapes plus the review's two repros, a `bash -c` payload, a
  `{ }` group, a heredoc body; rules 5/6's siblings). Each new case is RED against the reviewed head's hook and parser.
- MANDATORY-PRACTICES P14(b) and `docs/DOC_INDEX.md`'s hook row name the enforced form.
- Code sites: `scripts/hooks/shell_location.py` (`_walk`, `_command`, `_State.moved`, `Step.stranded`, `_split`'s `&`),
  `scripts/hooks/forbidden_commands.py` (`_steps`, `_segments`, rules 5-7), the two self-tests.

## Landing (for the next implementer; orient.py reads it)
- `scripts/hooks/shell_location.py#_walk` owns the and-or list: a hook asks it (`steps`), never splits a command line
  itself. `forbidden_commands.py#_segments` only groups the parser's steps into `&&`/`||`/`;`/newline segments, a group
  or `-c` payload as one opaque part. A `&` is background unless it is part of `&&`, a redirection (`2>&1`, `*>&1`,
  `&>`) or, in PowerShell, starts a command.
- Trap: the hook guards the session that edits it — a heredoc with a backslash in the edit script is refused; write the
  script with the Write tool.
