# PB5597 - The read decisions of the 2002 rules become inventory records only through an audit run

**Sites:** `scripts/spec/lineage_reads.py` (whole: a new module), `scripts/spec/audit_batch.py#import_reads`,
`scripts/spec/audit_batch.py#change_batch`, `scripts/spec/audit_batch.py#dispositions`,
`scripts/spec/lineage_screen.py#answer_problems`, `scripts/spec/lineage_screen.py#owed_records`,
`scripts/spec/lineage_screen.py#control_characters`, `scripts/spec/lineage.py#answer_shaped`,
`scripts/spec/record_verdicts.py#main`, `scripts/spec/inventory_schema.py#Edition`,
`scripts/spec/data/lineage-screen-triggers-2002.json` (the communication-reach `confined` pattern),
`tests/version-matrix/inventory-schema.json` (`own-edition-evidence`, the `answers` shape), `scripts/gate_audits.py#AUDITS`.

**The defect.** The 2002 inventory (3,298 rules) is being decided by reading: a reader states what each 2002 rule governs
in the 2002 text, the evidence at `--std 2002` and a verdict, and a refuter attacks every SAME (owner 2026-11-14: "2002 spec
covers 2002 rules"). About 1,400 rules had been read and none was recorded, because no path turned a read decision into a
change record: the one writer, `audit_batch.py change-batch --state`, writes an audit run's decisions, and no step of an
audit run took decisions made by reading. Four review leads of PB5589's branch (R2-1 to R2-4) sat on the same path:
- R2-4: no pass produced `next.answers`, so a run holding one flagged pair was refused WHOLE by the writer;
- R2-3: the trigger table's communication-reach `confined` pattern was written with a JSON `\b`, a backspace, so it never
  matched (no pair was mis-flagged yet; the next confining rule would have been over-flagged silently);
- R2-2: an answer was matched to its flag by trigger name only, so a later, different question under the same trigger
  counted as answered;
- R2-1: once a 2002 record was stored, any new flag on it (a compiler behaviour placed in no clause) would turn every
  stored record red.

**The fix (design: DESIGN-spec-conformance-review.md section 10.6, and 10.5's flag paragraphs).**
- `audit_batch.py import-reads --edition YEAR --reads DIR [--asked DIR] --state NEW`: the reads become the TRACKED read
  records (`tests/version-matrix/lineage-reads-<year>/<slice>.json`, each slice verbatim with its questions and its sources'
  digests) and an audit run whose map pass is each reader's answer and whose verify pass is each refuter's; the run's passes
  are read only and no Message Batches call is on the path. One normalization (`lineage_reads.load`) fails loudly by slice
  and rule.
- A KEPT record only from a SAME its refuter UPHELD, every screen flag answered for its detail, and (an edition whose schema
  entry names `own-edition-evidence`: 2002) a conformance-suite witness that runs at the row's own edition for every rule it
  carries into. Every other verdict is a work item (`needs-own-witness`, `defect`, `undecided`, `uninterpretable`) in the
  run's generated `reads-decisions.json`, never a record.
- R2-4: `dispositions` carries a map answer's `answers` and `source` into the CARRIES change; `change-batch` refuses each
  failing record ALONE and lists it in `<out>.refused.json`. R2-3: the pattern is `\\b`, and a control character in any
  trigger parameter is refused when the table loads (planted case `case_07`, which fails on the unfixed table). R2-2:
  `next.answers` is `{trigger: {"flag": detail, "answer": why}}`; an answer for another detail is no answer. R2-1:
  `record_verdicts.py` asks the screen of every change record it writes, so a stored record's later flag is the screen's
  change, listed as owed a re-read by `lineage_screen.py --check`, never red.
- `lineage_reads.py widen` plans (and with `--apply` makes, keeping only what passes at the edition) the band widening of
  the witnesses of the rows refused only for their evidence; `lineage_reads.py --check` is the gate's LINEAGE READS audit;
  `lineage_reads.py own-edition` measures an edition's stored KEPT records against the own-edition rule.

**Measured 2026-11-15 (dry runs, nothing written to the inventory).** 56 slices, 1,399 rules read: kept before the evidence
check 272; refused 597 (flag unanswered 313, no refuter record 284); work 530 (needs-own-witness 288, defect 187,
undecided 54, uninterpretable 1). `change-batch`: 197 KEPT records, 388 refused alone (a flag unanswered 313, no witness at
2002 159). `record_verdicts.py --edition 2002 --dry-run`: 197 accepted, GAP 3,297 to 3,101. `widen`: of the 75 rows refused
only for their evidence, 58 widenable (63 cases, 6 refusal entries) and 17 need a witness of their own. 1985: of 1,373
stored KEPT records, 887 have a witness at 85 for at least one target (671 for every target) and 486 have none.

**Still owed (the records worker's, not this branch's).** Importing the reads for real (the tracked read records), the
band widening and its gate, the KEPT records, the re-read of the 313 rows whose screen flags the slices never asked, the
refuter records of 284 SAME reads, and the work items. For 1985: whether its stored KEPT records are held to the
own-edition rule (the measurement above decides it; the schema names no `own-edition-evidence` for 1985).
