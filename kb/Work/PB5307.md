# PB5307 - at --std 85 two CD entries with one cd-name compile, and every statement binds to the last one: CommunicationSlice.Declare overwrites the first CD instead of refusing a name that is not unique

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/Model/CommunicationModel.cs` (`CommunicationSlice`, `Declare`)

**Mechanism.** Every referenced user-defined name must be uniquely referenced (§1985:IV.4.3.8.1), and a cd-name has no qualifier, so two CD entries with one name make every reference ambiguous. The Communication Section declares each CD into a slice keyed by its name, and the second declaration replaces the first (`CommunicationSlice.Declare`, as the set-3 refuter traced it), so the program compiles and every statement uses the last CD. The data-name uniqueness pass that landed on main after the adjudication (`CheckGlobalNameUniquenessPass`) does not reach cd-names: the repro still compiles at d9dde0e7ba. kb/Work PB5305 records why this is one defect on the uniqueness row and not seven on the statement rules.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids below. None of them is recorded: the adjudicated non-conforming verdicts wait in `E:/COBOL-coord/scratch/coderead-85/held-for-register.json`.

**Rules (1; every citation checked with `scripts/spec/cite.py --check`, and each 1985 rule number compared with the numbered paragraph the quotation sits in, which cite.py does not do: kb/Work PB5317).**

- `1985-SR-IV.4.3.8.1-1` - `§1985:IV.4.3.8.1` (decision PB5305, harm: under-rejects): "Every user-defined name explicitly referenced in a COBOL source program must be uniquely referenced"

**Repro.** `E:/COBOL-coord/scratch/held-85/set3/cd/r12.cob`: `CD XCD FOR INPUT TEXT LENGTH IS ILEN STATUS KEY IS IST.` then `CD XCD FOR OUTPUT TEXT LENGTH IS OLEN STATUS KEY IS OST.`; ENABLE OUTPUT, DISABLE OUTPUT, PURGE and SEND on XCD; `cobol.exe --std 85 --source-format fixed --run r12.cob`.

**Observed (a build of origin/main d9dde0e7ba (the source exported to `E:/COBOL-coord/scratch/main-d9dde0e7ba`), rerun 2026-11-11).** exit 0, `DUP RAN 30`.

**Expected (from the 1985 text).** Refused at the second CD entry (a name declared twice in one scope).

**Fix direction (root cause, CLAUDE.md rule 4).** Refuse a second CD entry with a name already declared in the program, where the Communication Section declares it (or let the data-name uniqueness pass see cd-names), and test it at 85.
