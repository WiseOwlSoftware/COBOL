# PB4099 — inspect-size-checking-not-honored: with EC-RANGE-INSPECT-SIZE checking enabled, an INSPECT size mismatch found at run time does not end the run

Found by drafter A of the PB3838 tier 6 drafting on 2026-10-30 (`E:\COBOL-coord\scratch\mythos\gc-file\drafter-A\inspvar2.cob`)
and recorded nowhere until this note. Upstream status `unreported`. Evidence, outside git on one machine: the reruns of
this filing in WSL `~/gc-notes/PB4099/` (sources also in this filing's scratchpad,
`E:\Temp\claude\E--COBOL\f044f739-1f07-4182-ae14-c9f6d8bd784b\scratchpad\pb4099\`).

## Summary

When the sizes of the REPLACING operands of an INSPECT differ only at run time (a reference modifier with a variable
length), EC-RANGE-INSPECT-SIZE is the fatal exception condition, and with checking for it enabled ISO ends the run unit
abnormally. GnuCOBOL 3.2.0 and 3.3-dev r5751, with `>>TURN EC-RANGE-INSPECT-SIZE CHECKING ON`, with
`-fec=EC-RANGE-INSPECT-SIZE` and with `-debug`, detect the mismatch (libcob skips the replacement and
FUNCTION EXCEPTION-STATUS returns `EC-RANGE-INSPECT-SIZE`) and continue the run to a normal end, exit 0, with no message.
The same class as PB3890 (EC-ARGUMENT-FUNCTION): the fatal flag libcob carries for the condition is never acted on.

## Minimal test case

Free reference format (`-fformat=free`; the directive starts in column 8), `inspvar3.cob`, which both versions compile:

```cobol
       >>TURN EC-RANGE-INSPECT-SIZE CHECKING ON
IDENTIFICATION DIVISION.
PROGRAM-ID. INSPVAR3.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 S PIC X(4) VALUE "ABAB".
01 F PIC X(2) VALUE "B".
01 R PIC X(2) VALUE "ZZ".
01 K PIC 9 VALUE 1.
01 L PIC 9 VALUE 2.
PROCEDURE DIVISION.
    INSPECT S REPLACING ALL F(1:K) BY R(1:L)
    DISPLAY "[" S "] [" FUNCTION EXCEPTION-STATUS "]"
    STOP RUN.
```

The drafter's program `inspvar2.cob` is the same with `01 F PIC X(1) VALUE "B".`, no `K`, and `INSPECT S REPLACING ALL
F BY R(1:L)`; 3.3-dev refuses that one at compile time (PB4098), so it shows this defect on 3.2.0 only. `inspvar2n.cob`
is `inspvar2.cob` without the directive line.

## Expected result (per ISO)

ISO/IEC 1989:2023, each citation checked with `python scripts/spec/cite.py --check` on 2026-10-30:

- §14.9.22.4 14) (OK): "The size of literal-3 or the data item referenced by identifier-5 shall be equal to the size of
  literal-1 or the data item referenced by identifier-3. If these sizes are not equal, the EC-RANGE-INSPECT-SIZE
  exception condition is set to exist and the results of the execution of the INSPECT statement are undefined." Here
  `F(1:K)` is 1 character and `R(1:L)` is 2.
- §14.6.13.1.6, Table 13 (OK): `EC-RANGE-INSPECT-SIZE | Fatal | Size of replace items in INSPECT differs`.
- §7.3.25.4 6) (OK): with the ON phrase "checking for the exception condition associated with exception-name-1 is
  enabled for the procedure division statements and procedure division headers that follow in the compilation group".
- §14.6.13.1.3 7) (OK): "If checking for the exception condition is enabled, execution of the run unit is terminated
  abnormally as specified in 14.6.12, Abnormal run unit termination." (No declarative, no PERFORM ... WHEN, no PROPAGATE
  in the program, so rules 4 to 6 do not apply.)
- §14.6.12 (OK): "The operating system shall indicate an abnormal termination of the run unit if such a capability
  exists within the operating system."

Expected: the run unit ends abnormally during the INSPECT; the DISPLAY is never executed; the exit status reports
abnormal termination. Undefined INSPECT results (rule 14) cover what happens to `S`, not whether the run continues.

Edition: 2014. The 2009 committee draft that became ISO/IEC 1989:2014 (CD 1.2) carries the REPLACING size rule (general
rule 13 there) in the same words and the fatal rule as rule 4) of its fatal-exception list (`std.txt` line 22619: "If checking for the exception condition is
enabled, execution of the run unit is terminated abnormally"); its exception table, read by word position on the CD PDF
(`STD.BK.pdf` page 447; the OCR text is row-shifted), lists `EC-RANGE-INSPECT-SIZE Fatal Size of replace items in INSPECT
differs`. The TURN directive is a 2002 feature.

## Fix site (GnuCOBOL 3.3-dev r5751 source, read observationally)

- `libcob/strings.c`, `inspect_common` (REPLACING) and `cob_inspect_converting_intern` (CONVERTING): when
  `f1->size != f2->size` (and the operand is not a figurative constant) they call
  `cob_set_exception (COB_EC_RANGE_INSPECT_SIZE)` and return without replacing.
- `libcob/common.c`, `cob_set_exception`: records the code and location only; it never ends the run. `libcob/exception.def`
  marks the condition fatal (`COB_EXCEPTION (0D03, COB_EC_RANGE_INSPECT_SIZE, "EC-RANGE-INSPECT-SIZE", 1)`), and nothing
  reads that flag here.
- `cobc`: no `CB_EXCEPTION_ENABLE (COB_EC_RANGE_INSPECT_SIZE)` site exists (grep of `cobc/*.c`), so libcob is never told
  whether checking is enabled. The reference-modification check shows the existing pattern: cobc passes an `abend`
  argument to `cob_check_ref_mod_detailed`, which calls `cob_runtime_error` and `cob_hard_failure`. The fix inferred:
  cobc passes the enabled state of EC-RANGE-INSPECT-SIZE to the INSPECT runtime (or emits a check), and libcob ends the
  run when it is enabled and the sizes differ. Not built or tested.

## Draft issue

**Title:** (comment on feature-requests #284) EC-RANGE-INSPECT-SIZE: an INSPECT size mismatch found at run time does not end the run with checking enabled

A current repro for this request with EC-RANGE-INSPECT-SIZE, the condition bugs #1271 (case 1) leaves to it. libcob
detects the mismatch and sets the exception, and the run continues.

**Versions:** GnuCOBOL 3.2.0 (Ubuntu `gnucobol3 3.2-4build1`) and 3.3-dev r5751 (CI snapshot 3.3-dev.138 of
2026-10-29), x86_64 Linux.

`inspvar3.cob` (free format):

```cobol
       >>TURN EC-RANGE-INSPECT-SIZE CHECKING ON
IDENTIFICATION DIVISION.
PROGRAM-ID. INSPVAR3.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 S PIC X(4) VALUE "ABAB".
01 F PIC X(2) VALUE "B".
01 R PIC X(2) VALUE "ZZ".
01 K PIC 9 VALUE 1.
01 L PIC 9 VALUE 2.
PROCEDURE DIVISION.
    INSPECT S REPLACING ALL F(1:K) BY R(1:L)

    STOP RUN.
```

`cobc -std=cobol2014 -fformat=free -x -o inspvar3 inspvar3.cob && ./inspvar3` (also with `-debug`, and with
`-fec=EC-RANGE-INSPECT-SIZE` on the program without the directive): compile exit 0, the run prints
`[ABAB] [EC-RANGE-INSPECT-SIZE          ]` and exits 0, on both versions.

**Expected:** the run ends abnormally in the INSPECT, and the DISPLAY is not reached. ISO/IEC 1989:2023 (the 2014
committee draft has the same rules): the sizes differ, so EC-RANGE-INSPECT-SIZE exists (14.9.22.4 rule 14); it is fatal
(14.6.13.1.6, Table 13); checking is enabled by the TURN directive (7.3.25.4 rule 6); and with checking enabled "execution
of the run unit is terminated abnormally" (14.6.13.1.3 rule 7).

**Where:** `inspect_common` and `cob_inspect_converting_intern` in `libcob/strings.c` call `cob_set_exception
(COB_EC_RANGE_INSPECT_SIZE)` and return; `exception.def` marks the condition fatal, but nothing acts on it, and cobc
has no `CB_EXCEPTION_ENABLE (COB_EC_RANGE_INSPECT_SIZE)` site that could tell libcob checking is on (compare the
`abend` argument of `cob_check_ref_mod_detailed`).

**Related:** bugs #1271 (case 1: the compile-time refusal of the same INSPECT with sizes known at compile time),
bugs #728 (the same gap for EC-SIZE-ZERO-DIVIDE).
