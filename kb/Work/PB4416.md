# PB4416 — method automatic data roots an access path on a CLR name, not on a local identity

**Found:** by the PB4380 implementer (its "Lead (architecture, process_only)") and, independently, by the round-1 review of
that branch (R1-1 LEAD). Both are one mechanism and are filed here as one note. PB4380 and PB4321 are landed and are not
reopened: PB4380 converted the carrier local, the hoisted cell and the element cell; this note is the root kind it did not reach.

**Sites (re-read on origin/main d0b7ed0e2, all still hold):**
- `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/OoEmitter.cs` (`EmitMethod`, `MethodRootPlace`): the local-root loop at ~1280 emits the Tier-B REDEFINES backing as `string {bkl.Name} = ...;` and ~1284 emits `{type} {root.ClrName} = {init};`, both inside the method body, so both are C# locals.
- `MethodRootPlace` (~49) roots the place at `new RootFieldSegment(root.ClrName)`.
- `src/WiseOwl.Cobol.Compiler/Binding/ReferenceResolver.cs` (`AddRoot`, `BuildBackingPath`) (~1836, `new RootFieldSegment(cls.BackingClrName, ...)`) root every access to the same data at a `RootFieldSegment`.
- `src/WiseOwl.Cobol.Compiler/Binding/Model/AccessPath.cs` (`RootFieldSegment`, `LocalRootSegment`): `RootFieldSegment`'s own doc says a CLR-named member or item storage.
- `docs/rearchitecture/DESIGN-backend-abstraction.md` line ~104: "An access path rooted at a local starts at a `LocalRootSegment`; a `RootFieldSegment` holds only a CLR name (kb/Work PB4380)", and section 1.3 L8's DONE mark with its contract-test row deleted.
- The landing's other changed sites: `src/WiseOwl.Cobol.Compiler/Binding/Model/MethodLocal.cs` (`MethodDataLocal`,
  `MethodRedefinesBackingLocal`, new); `src/WiseOwl.Cobol.Compiler/Binding/Model/DataItem.cs` (`DataItem.ActivationLocal`,
  new); `src/WiseOwl.Cobol.Compiler/Binding/Model/RedefinesModel.cs` (`RedefinesClass.BackingLocal`, new);
  `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.Oo.cs` (`OoBindMethodData`);
  `src/WiseOwl.Cobol.Compiler/Binding/ReferenceResolver.cs` (`StorageRoot`, new);
  `src/WiseOwl.Cobol.Compiler/CodeGen/Roslyn/LocalNames.cs` (`LocalNames.Of`);
  `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/OoEmitter.cs` (`ActivationLocalOf`, `MethodBackingDecl`, new;
  `MethodBoundaryValue`, and `EmitMethod`'s LINKAGE and LOCAL-STORAGE declaration loops);
  `tests/WiseOwl.Cobol.Tests.Unit/ModelAccessStructureTests.cs`
  (`AMethodsDataRoots_AreRootedAtTheirLocalsIdentity`, `TheFormerAccessTextCarriers_HoldNoStringButAName`).

**What leaks.** The name is the item's allocated CLR name (neutral by section 1.1), but the segment does not say "local of
method M". A CIL backend addresses locals by slot, so it must infer slot versus field from the item's section and owner.
The design sentence and L8's DONE mark therefore claim more than the code does, and the removed contract-test row no longer
guards the residue.

**Fix direction.** Give method automatic data (LOCAL-STORAGE roots, non-formal LINKAGE roots, the Tier-B backing string) a
`MethodLocal` identity, for example a `DataItemLocal(DataItem)` beside `StatementLocal`, and root their access paths at a
`LocalRootSegment` over it; the Roslyn backend spells it in `LocalNames.Of`. Restore a contract-test row for the root kind,
and correct the design sentence and L8's status in the same change set (CLAUDE.md rule 2). Sweep every caller of
`RootFieldSegment` for a sibling whose root is a method local. Related: PB4380, PB4321 (landed), campaign PB2293.

## Landed (wave 20261818 A)

**Re-probe (base cb668eca7).** A unit probe bound the class below (`ModelAccessStructureTests.MethodDataSource`) and
printed each method root's place: `LS-G` and `L-R` rooted at `RootFieldSegment { MemberClrName = LS_G }` /
`{ MemberClrName = L_R }`, the member `LS-A` at that root then `MemberSegment(LS_A)`, and the Tier-B class `LS-R`/`LS-V`
a `RedefViewPlace` whose backing was `RootFieldSegment { MemberClrName = _redef_LS_R }`, while `OoEmitter.EmitMethod`
declared each as a method local (`string _redef_LS_R = ...;`, `{type} {root.ClrName} = ...;`). The note held.

**Fix.** A method's data carries its local's identity. `DataBinder.OoBindMethodData` sets
`DataItem.ActivationLocal = new MethodDataLocal(root)` on every LOCAL-STORAGE and LINKAGE root (ISO §8.6.4: "Their
storage is allocated and set to initial state each time the runtime element containing them is activated"), and
`RedefinesClass.BackingLocal` derives a `MethodRedefinesBackingLocal(class)` for a stored (not cell-backed) Tier-B
class whose canonical is such a root, so it answers for the class's final tier and cell verdict. One function,
`ReferenceResolver.StorageRoot`, chooses the root kind for both path builders that root at storage (`AddRoot`,
`BuildBackingPath`): a `LocalRootSegment` over the identity when there is one, else the member's `RootFieldSegment`.
`OoEmitter.MethodRootPlace` roots at the same identity, and every declaration and read of the method's data in
`OoEmitter` spells it through `LocalNames.Of`, whose two new arms spell the storage's allocated CLR name
(`DataItem.ClrName`, `RedefinesClass.BackingClrName`), so the emitted C# is unchanged:
`scripts/arch/compare_oracle.py` reports IDENTICAL over 15853 cases against the base capture. A carrier-resident formal
(its carrier first), an AREA formal and any cell-backed class (members) and object data keep their roots.

**Witness.** `ModelAccessStructureTests.AMethodsDataRoots_AreRootedAtTheirLocalsIdentity` asserts every root of its
fixture carries its `MethodDataLocal`, that `LS-G`, `L-U` and `L-R` (and the member `LS-A`) are rooted at it, that the
Tier-B class is a window over its `MethodRedefinesBackingLocal`, and that the area formal `L-F` and the object datum
`OBJ-N` stay `RootFieldSegment`s; planted back to a member root (`StorageRoot` returning `RootFieldSegment`), it failed
on the segment type. `TheFormerAccessTextCarriers_HoldNoStringButAName` holds the two new identities to no string.
DESIGN-backend-abstraction §1.2 and §1.3 L8 now name the method's data.

**For the next implementer.**
- `src/WiseOwl.Cobol.Compiler/Binding/ReferenceResolver.cs#StorageRoot` — the one member-or-local choice; a new storage
  root kind asks it, never a second ternary.
- `src/WiseOwl.Cobol.Compiler/Binding/Model/RedefinesModel.cs#BackingLocal` — derived from the canonical's
  `ActivationLocal`, the tier and `IsCellBacked`; it must agree with `RecordStructEmitter.MethodRedefinesBackingDecl`, and
  `OoEmitter.MethodBackingDecl` throws if they part.
- Trap: the method arm's copy-in formal locals (a USING formal neither carrier-resident nor an area) and the group
  image-crossing arm are reached by no case of the oracle's 15853; only a formal no cell can carry (a leaf with no bound
  representation) reaches them.
