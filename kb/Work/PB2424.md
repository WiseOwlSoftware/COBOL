**Found by:** the PB2118 Draft 8 reviser (the seventh refuter's J2 made a wave's file set the computed callers of what
it moves, `scripts/arch/member_index.py`; DESIGN-architecture-review §8.7). `plan()` defers a campaign group whose
`files` meet `busy` (`file_set_collisions`, the partition's one rule), and `busy` is built once, before planning, from
the worktrees, the unlanded branches, the dispatch ledger and the open slices. A group it then PLANS is not added to
`busy`, so a later group of the same wave whose file set meets it is planned too. The same-file successor rule
(`after:`) keys on a group's primary `file` only.

**Harm:** two Extract groups of one wave that both edit a shared caller (for example two DataBinder steps' readers in
`ReferenceResolver.cs`) run in parallel and the lander meets a merge conflict, or worse a clean textual merge of two
restructurings that each assumed the other's file unchanged. Draft 7's sets (fix_clusters' sites of score 2 and up)
overlapped rarely; Draft 8's computed callers make overlaps common (PB2296 step 1 alone has 66 files).

**Fix direction (rule 5):** treat every group `plan()` admits as in flight for the groups after it in the same wave:
after admitting `g`, add `{f"planned {g.letter}": set(g.files)}` to `busy`, unless the later group is `g`'s successor
(`after:` chains already serialize); a `test_plan_wave.py` case plants two groups with disjoint primary files and one
shared caller and asserts the second waits or becomes the first's successor. Then re-derive §8.7's numbers.
