### Adjudicator finding (collating-sequence-clause, harm rejects-legal-source)
- **Mechanism:** M3 — the file-control COLLATING SEQUENCE grammar shape: Format 2 takes `OF cobolWord+`, refusing a qualified data-name-1, and Format 1's FOR choice group is `collatingForPhrase+` with last-wins capture, admitting a repeated alternative
- **Repro:** Two FDs with a key field of the same name, or simply `COLLATING SEQUENCE OF IX-KEY IN IX-REC IS REV.` (probe p14) -> COBOL0312 unexpected 'IN'. And `COLLATING SEQUENCE FOR ALPHANUMERIC IS REV FOR ALPHANUMERIC IS DREV` is accepted, the second silently winning (p15 shape).
- **Expected (spec):** data-name-1 is a user-defined word including qualification where needed (§5.2 metalanguage table; §8.4.2.2 'uniqueness shall be established through qualification for each user-defined name explicitly referenced') — the qualified form must compile; SR6 forbids only subscripting. §5.2.6.4: within braces with choice indicators 'any single alternative shall be specified only once' — a repeated FOR ALPHANUMERIC shall be diagnosed.
- **Observed:** Qualified name is a parse error; the repeated FOR phrase is accepted and CaptureFileCollating overwrites alnum/nat per phrase.
- **Code site:** src/Cobol.Net.Frontend/Grammar/Core/CobolIO.g4#fileCollatingSequenceClause (OF cobolWord+ IS? cobolWord); src/Cobol.Net.Compiler/Binding/DataBinder.cs#CaptureFileCollating
- **Clause (adjudicator):** ISO §12.4.5.7.2 (Format 1/2); §5.2.6.4; §8.4.2.2

## What the fixer owes
`fileCollatingSequenceClause`'s Format-2 operand becomes the qualified data-reference the other key clauses use (SR6 still forbids subscripting — refuse it by name at bind, as PB481 did for the key clauses); the Format-1 FOR group stays a superset parse and `CaptureFileCollating` refuses a repeated alternative (§5.2.6.4) — the PB917 'printed once, written twice' shape, so route it through that note's mechanism if it has landed.

## Landing (wave 70, group U2 finisher — no new code; reuses COBOLNET2024 and COBOLNET2104)

Format 2's operand is now a `dataReference` (`OF dataReference+ IS? alphabet-name-3`, `CobolIO.g4#fileCollatingSequenceClause`),
captured through the one data-name-n capture `DataBinder.ClauseDataName` (SR6's "shall not be subscripted" is refused
by name, COBOLNET2024) into `CollatingKeyOperand` / `KeyLevelCollatingClause` (FileModel.cs). `DataBinder.CollatingKeyNamed`
resolves each operand by §8.4.2.2 (`QualifiedCandidates` + `UniqueOrReportAmbiguous`) narrowed to this file's RECORD KEY /
ALTERNATE RECORD KEY items (the key clauses' own SR2 narrowing, `ResolveFiles#InRecords`), and SR4/SR5/SR7/SR8 and GR6
compare key ITEMS, never spellings (`ResolveKeyCollating`, `OoEmitter.SelectFingerprint`'s GR1 g) key positions). So
`COLLATING SEQUENCE OF IX-KEY IN IX-REC IS REV` compiles and orders the key by REV where it was COBOL0312.
Format 1's FOR group stays a `collatingForPhrase+` superset; `ChoiceIndicators.ForPhrasePair` refuses a repeated
alternative (§5.2.6.4, COBOLNET2104) instead of letting the last win. SIBLING SWEEP: the same pair is printed by five
formats and each walked its own array (four with private messages, two under the bare COBOLNET0898) — the PROGRAM
COLLATING SEQUENCE and CHARACTER CLASSIFICATION clauses (§12.3.6.2), SORT/MERGE COLLATING SEQUENCE (§14.9.40.2 /
§14.9.24.2) and CODE-SET (§13.18.13.2) now read it through the same reader (`ChoiceIndicators.AlphabetPair` adds the IS
form for the four alphabet-name formats). `ForPhrasePairDriftTests` derives the repeated FOR-phrase rules from the
grammar and fails on a binder that walks one itself. Golden `2002/pb1075_collating_qualified_key` (ZZZ, MMM, AAA);
negatives `pb1075-file-collating-for-repeated` and the existing `l1-file-collating-key-subscripted` (re-pinned from the
parse error COBOL0312 to COBOLNET2024). Rows FMT-12.4.5.7.2 → CONFORMS, SR-12.4.5.7.3-6 re-verdicted (code-location).
