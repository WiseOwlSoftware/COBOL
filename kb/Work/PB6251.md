**Rule it breaks:** Hot-path allocation is the performance dimension (tools/claude-skills/skills/review/references/dimensions.md 3; DESIGN-architecture-review 5.4): a write that changes a few positions of an n-character image must cost one n-character allocation, not two; one mechanism per job (engineering-standards) - the same copy-then-rebuild loop is written in seven kernels

**Scenario:** Counted on the pin: CobolString.SpliceInto, CobolString.WindowInto, NationalImage.WriteWindow, CobolBits.WriteWindow, CobolInspect.Replace, CobolInspect.Convert, CobolBool.Shift and CobolStringOps.StringTransfer each allocate a char[n] copy of the whole image (ToCharArray) and then a second n-character string (new string(char[])), so 2n characters of garbage per call where string.Create over the source would allocate n once. The benchmark MOVEHOT runs MOVE NUM-EDIT TO ALPHA-B (31:10), which PlaceRenderer.cs:208 lowers to CobolString.SpliceInto over the 40-character ALPHA-B, 2,000,000 times per run: 2,000,000 avoidable char[40] arrays of 104 bytes = about 198 MiB per run, against the 1,765.9 MiB allocated per run the baseline records (perf-baseline b1a42fc36e8b, row bdn/run/MOVEHOT). STRING is worse in shape: StringTransfer is called once per sending operand and rebuilds the whole receiver each time, so STRING A B C D E DELIMITED BY SIZE INTO R with R PIC X(1000) allocates 5 x 2 x 1000 = 10,000 characters (about 20 KB) for one statement whose result is one 1000-character string; the cost is O(operands x receiver size) where one working buffer per statement is O(receiver size).

**Measured how:** R2 batch finding `runtime-values-4--performance--f2#1` (pair runtime-values-4--performance), read in the pinned tree at 9e65164eb3a9; skeptics rule upheld, scenario upheld, site upheld. Measurement: Count read from the pinned code: 2 allocations of the full image (char[n] by ToCharArray, then string n) per call in each of the 8 kernels; MOVEHOT executes SpliceInto at n = 40 2,000,000 times per run (MOVEHOT.cob, PlaceRenderer.cs:208), so 2,000,000 x 104 B = 198 MiB avoidable of the 1,765.9 MiB per run in perf-baseline b1a42fc36e8b row bdn/run/MOVEHOT; STRING with k sending operands into an n-character receiver allocates 2kn characters (k calls of StringTransfer)
