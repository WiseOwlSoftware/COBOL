# PB5194 - at --std 85 UNSTRING accepts a reference-modified function-identifier as identifier-1: VisitUnstringStatement gates only the dataReference alternative of strUnstrSender

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs` (`VisitUnstringStatement`)
- `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolIO.g4` (`strUnstrSender`)

**Mechanism.** §1985:VI.6.27.3 SR7: "Identifier-1 must not be reference modified." `VersionConformancePass.VisitUnstringStatement` gates the construct unstring-sender-reference-modified-2002 on the dataReference alternative of `strUnstrSender` only, so SRC (1:5) is refused at 85 but FUNCTION UPPER-CASE (SRC) (1:5), a reference-modified alphanumeric function-identifier, compiles and runs.

**Found by.** The 1985 code read (2026-11-10; its records are `E:/COBOL-coord/scratch/coderead-85/for-register.json`): each rule below was read against the code sites it names and probed at `--std 85`, and found non-conforming. Verdict, harm, evidence, repro and observed text are the records'; the rows' verdicts are recorded on another branch.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids of the list below.

- `1985-SR-VI.6.27.3-7` - `§1985:VI.6.27.3 SR7` (record verdict: PARTIAL, harm: under-rejects). Checked: §1985:VI.6.27.3 SR7: "Identifier-1 must not be reference modified.". Code sites read: src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs#VisitUnstringStatement; src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolIO.g4#strUnstrSender. Code read: §1985:VI.6.27.3 SR7: 'Identifier-1 must not be reference modified.' VersionConformancePass.VisitUnstringStatement gates the construct unstring-sender-reference-modified-2002 (COBOL0900 below 2002), but only on the dataReference alternative of strUnstrSender: a data-name sender written SRC (1:5), SRC (1:), SRC OF G (1:5) or SRT (I) (I:5) is refused at 85 (probed), and a subscripted or qualified sender without a reference modifier is accepted. The functionCall alternative is never asked, so a reference-modified function-identifier (§1985:IV.4.3.8.3.3 SR2 'A reference-modifier may be specified only for functions of the category alphanumeric'; SR3 admits an alphanumeric function-identifier where an identifier is permitted) is accepted as identifier-1 at 85. Implemented for the data-name operand shape, not for the function-identifier shape. The witness refuses UNSTRING SRC (1:5) with COBOL0900.

**Expected (from the 1985 text, the record's).** A refusal at --std 85 on line 10: §1985:VI.6.27.3 SR7 'Identifier-1 must not be reference modified.' (the same COBOL0900 the data-name form UNSTRING SRC (4:4) gets).

**Fix direction (root cause, CLAUDE.md rule 4).** Ask the gate of the sender node, whichever alternative it is: the reference modifier is a property of the operand, so one test on the operand's reference-modifier child covers both.
