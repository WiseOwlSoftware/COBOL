# PB811 — OPEN — the underlining audit has been dark since the pages came out

Filed 2026-09-09 by the registrar (second pass). [[PB808]] flagged it in one closing sentence — *"Re-keying that
audit onto the clause hierarchy is the structural fix and is flagged inside PB808 as worth its own item if not
folded in"* — and it is filed here rather than appended to PB808 for the [[PB786]] reason: PB808's fix is a
`specs/` submodule edit that will flip PB808 to `landed`, and an open obligation inside a closed note is exactly
what CLAUDE.md rule 8 forbids.

## The measurement, on this worktree, with the PDF present

`specs-private` was initialized here (`git submodule update --init specs-private`; the gitlink is **unchanged**)
so that the run reaches the audit's own logic rather than its missing-PDF guard:

```
$ python scripts/spec/audit_underlining.py
HALTED: no page anchors in specs/ISO_COBOL.md — pages were removed from the transcription, so this page-keyed
audit can no longer bucket it. For figures use `python scripts/spec/sweep_figures.py --check`, which regenerates
and diffs exactly. This audit needs re-keying onto the clause hierarchy.
$ echo $?
1
```

**Without** the submodule it fails one step earlier and for a different reason (`FATAL: the ISO PDF was not
found under specs-private/`), which is why the halt has to be measured with the PDF in place — a reader who runs
it in a fresh worktree sees the PDF message and concludes the tool is fine.

**It exits 1, so it cannot produce a false green** — that half is right (`feedback_green_gates_arent_evidence`).
The defect is that nothing runs it: `grep -rn audit_underlining scripts/ tests/ .github/ docs/` returns only
prose — `audit_figure_structure.py:7`, `audit_figure_text.py:4`, plan §0's tooling paragraphs and
`REPAIR-PLAN.md:76`. No test, no CI leg, no gate.

## The stale claim it leaves behind

`scripts/spec/audit_figure_structure.py:7`, in its own header table:

> `audit_underlining.py`    which words are REQUIRED (5.2.2)  0 defects in 2,215 tokens

That is a result the tool can no longer produce, printed as current state (CLAUDE.md rule 6). A reader deciding
whether the underlining class is covered reads that line and stops.

## Why it matters — the defect class it was built to catch is live

Underlining decides required-vs-optional (`feedback_underlining_not_bracketing`). [[PB808]] is one figure note
whose two bolded conclusions invert §5.2.3 for `>>LISTING ON`, and it was found **by hand**, by one registrar
reading one page. The reconciliation LEDGER's own group sweep reached four of the seven ON/OFF notes and missed
LISTING. A mechanical pass over all 2,215 tokens is what would have found it, and that pass has not run since
the page anchors were removed.

## The fix shape

Re-key the audit onto the **clause hierarchy**, which is what every other spec tool now uses
(`cite.py`'s `clauses()`, `clause_page.py`, `gen_conformance_notes.py`): bucket the tokens by the enclosing
clause instead of the printed page, resolve the PDF page for a clause with `clause_page.py` when a geometry
measurement is needed, and keep the PDF requirement only for the measuring half. Then give it a test or a CI
leg, and delete the stale header line in `audit_figure_structure.py`.

⛔ **Do not "fix" it by re-adding page anchors to `specs/ISO_COBOL.md`** — pages are not a thing in Markdown
(memory `no_page_numbers_in_markdown`), and the transcription's de-paging was deliberate
(`scripts/spec/deindex_pages.py`, `strip_page_rules.py`).

## Sibling sweep the fixer owes

`audit_figure_text.py` and `audit_figure_structure.py` are named in plan §0 as HALTing the same way. Measure all
three on a tree with the PDF present and say, per tool, whether it halts, what it would measure, and what runs
it — a tool that halts and a tool that nothing runs are two different defects and both are present here.
