# PB3780 — the loop units load the overlay only, slimmed to what they run; the base is read on demand

**Sites:** `.claude/skills/workstream/SKILL.md`, `.claude/skills/workstream/references/rolling-wave.md` (new: §2's narrative moves here), `.claude/skills/workstream/references/landing.md`, `.claude/skills/workstream/check_practices.py#fleet_tooling`, `.claude/skills/workstream/check_practices.py#CAP_COPIES`, `scripts/orchestrator/units/wave.md`, `scripts/orchestrator/units/enqueue.md`, `scripts/orchestrator/units/common.md`, `scripts/hooks/dispatch_guard.py#skill_loaded`, `.claude/skills/workstream/templates/MANDATORY-PRACTICES.md` (the P10 Orchestrator row, O9), `.claude/skills/workstream/references/cost-law-and-budget.md`, `.claude/skills/workstream/templates/wf_rolling_wave.js`, `.claude/skills/workstream/make_dispatch_specs.py`, `scripts/orchestrator/test_plan_wave.py`, `scripts/orchestrator/test_rolling_wave.py`, `docs/DOC_INDEX.md`, `docs/rearchitecture/DESIGN-orchestrator-loop.md`

## Measured

Loop units (16 enqueue, 6 campaign, 2 wave, the resume units) each load `session-start` (1.2K tokens), `workstream`
(6.7K) and, as the overlay's first line orders, `brent-tools:agent-fleet` (4.5K): 12.4K tokens re-read on each of a
unit's about 45 turns. Across the 46 units of the day that is about 25M token-turns and 46 cache writes; the
agent-fleet load alone is $2.57 a day, workstream $4.05. No dispatched agent loads either (0 of 105 called the Skill
tool but two reviewers, for brent-tools:review), so only the orchestrator threads pay, and they pay for the base's
general text (checkpointing, the cost law, the rolling wave, landing, restart) that the overlay states again in
project terms. The overlay's §2 carries, beside the commands, about 9K chars on torn findings files, predecessor
verdicts and the review rounds, rules that `review_findings.py`, `prune_worktrees.py` and `wf_rolling_wave.js` enforce
and that no unit decides by hand. The Stats tab's 277.7m tokens for agent-fleet are these loads' label inherited by
every agent of the workflows the loaded thread launched (evidence record §"The 21 %"), not the skill's cost.

Saving: the base load gone from the units (about $25 a week) and the overlay at about 2.5K tokens (about $22 a week):
**about $50 a week**, and the Stats tab stops attributing the fleet's cost to one skill.

## Fix

The overlay's first block no longer orders the base load; it names the base's reference files to read when the unit
needs them (`references/orchestrator-loop.md` for a resume, `restart-and-standards.md` for §5, `landing.md` for the
enqueue unit), and `check_practices.fleet_tooling` asserts the pin and the reference paths instead of "invokes its
brent-tools base skill first" (the practice is removed from the checker in the same change, O1; the pin and the
"improved here, written into the public base first" rule stand, PB1699). `dispatch_guard.skill_loaded` keeps requiring
the overlay. SKILL.md is cut to the operational core: the commands, the args, the stop and steer rules, the landing
path, the allocation rules, the templates list; §2's narrative paragraphs move verbatim into
`references/rolling-wave.md`, which the wave unit reads once when it plans a chain, and `CAP_COPIES` follows the moved
sentences. `units/common.md` names which reference each unit reads, so the next unit kind is automatic.

Guard: `check_practices.py` asserts SKILL.md under a stated size and that every reference file the overlay names
exists; `CAP_COPIES` keeps every cap statement checked wherever it moved; the dispatch guard's self-test keeps the
overlay requirement.

## Acceptance

A loop unit's stream log shows one skill load (`workstream`) beside session-start and no `agent-fleet` load;
`check_practices.py` GREEN; the next day's `usage_report.py` shows the units' own-thread cost down by the skill's
share; the Stats tab's agent-fleet row stops growing with the fleet's cost.

## Landing

Wave 20261709, group A. Re-probe on this tree: the only thing that ordered the base load was the first block of
`workstream/SKILL.md` ("Invoke `brent-tools:agent-fleet` (Skill tool) before reading on"); the units' own text
(`units/common.md`, `wave.md`, `enqueue.md`) asked for `session-start` and `workstream` alone, and `dispatch_guard.skill_loaded`
requires only the overlay. SKILL.md was 28,995 bytes, section 2's rolling-wave narrative 11,350 of them.

Fix: the overlay's first block orders no base load and names, with full paths, the reference file each job reads once
(three of the base's, four of the overlay's); `references/rolling-wave.md` holds the former section 2 narrative moved
unchanged; the attended session's duties moved unchanged to the end of `references/landing.md`; SKILL.md sections 1 to 6 are
cut to the commands, the args, the stop and steer rules, the landing path, the allocation rules and the templates list
(13,953 bytes, 52 % smaller; about 3.2K tokens, not the note's estimated 2.5K, because the loop block and the landing path stay
whole). The turn-cap sentences stay in SKILL.md where `CAP_COPIES` checks them. `units/common.md` names which reference each unit
kind reads, so the next unit kind is a line there. `dispatch_guard.skill_loaded` is unchanged and still requires the overlay.

Guard: `check_practices.overlay_problems` (called by `fleet_tooling`, so by the gate's FLEET PRACTICES audit and CI) refuses an overlay in
`BASE_ON_DEMAND` (workstream) that orders its base's load by the Skill tool or by a Read of its SKILL.md, that exceeds
`SKILL_MAX_BYTES` (15,000), or that names a reference file that does not exist (the base's by its full submodule path, its own by
`references/<file>`); the gate, review and spec-lookup overlays still have to name their base. Each arm is seen refused on a plant in
`test_plan_wave.py` (7c4). The practice "invokes its brent-tools base skill first" is removed from the checker for workstream in this same change (O1).

Not yet observed (needs a loop unit after this landing): a unit's stream log with one skill load beside session-start and no `agent-fleet`
load, and the next `usage_report.py` day showing the units' own-thread cost down by the skill's share.

For the next implementer:
- `.claude/skills/workstream/SKILL.md`: operational core only; narrative goes to `references/`, and a new reference file is named
  there so `overlay_problems` checks that it exists. The size cap is `check_practices.SKILL_MAX_BYTES`.
- `.claude/skills/workstream/check_practices.py#overlay_problems`: the one definition of what an overlay may order; a new overlay
  that is loaded by every unit goes into `BASE_ON_DEMAND`.
- Trap: a base reference written as bare `references/x.md` is looked up in the overlay's own directory; write the base's with its
  full `tools/claude-skills/skills/<skill>/references/` path or the check reports it missing.
