# PB910 — OPEN — the integer-n contract nobody reads

Source: the `PB432` report, "New defects" item 1. Re-measured here.

## The measurement

`<scratch>/reg7/probe/e_perform_zero.cob`, `--std 2023`, `--run`:

```cobol
       01 N PIC 9(4) VALUE 0.
       PROCEDURE DIVISION.
           PERFORM 0 TIMES
              ADD 1 TO N
           END-PERFORM
           DISPLAY "N=" N
```

```
N=0000
```

No diagnostic. The body is correctly executed zero times — the RUN-TIME behaviour is what GR9 would give
for an identifier whose value is zero — but the SOURCE is not conforming, and accepting it silently is what
this note is about.

## The rule

```
$ python scripts/spec/cite.py --check 5.5 "it refers to a fixed-point integer literal that shall be unsigned and nonzero unless otherwise specified in the associated rules"
OK  §5.5 1)  (Integer operands)
    1) When the term 'integer-n' (n = 1, 2, …) is used in a general format and associated rules, it refers
       to a fixed-point integer literal that shall be unsigned and nonzero unless otherwise specified in
       the associated rules.
```

§5.5 is a rule about the META-LANGUAGE: it attaches to EVERY `integer-n` slot in EVERY general format at
once. §14.9.28.2 Format 2 prints `{ identifier-1 | integer-1 } TIMES`, so integer-1 inherits it, and the
"unless otherwise specified" escape is not taken here: §14.9.28.4 GR9's zero-or-negative sentence is
written about **identifier-1**, the run-time operand, and says nothing about the literal.

## The code site

`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/ControlFlowBinder.cs#CountOperand`. It screens §14.9.28.3
SR2's integrality — `PERFORM 1.5 TIMES` is caught — and stops there. The slot's OTHER contract, the one
§5.5 supplies to every integer-n in the language, is asked nowhere.

## ⛔ Why the fix is not a literal test in CountOperand

CLAUDE.md rule 5 and `feedback_one_rule_one_place`. §5.5 rule 1 holds for `integer-1` in
`OCCURS integer-1 TIMES`, in `INSPECT … CHARACTERS integer-1`, in `SORT … integer-1`, in every general
format that prints the token — this project has dozens of integer-n slots and writing the rule in each
binder is how the next one gets missed. The shape that makes the NEXT case automatic is one
`IntegerOperand` screen the binders route through, carrying the two facts §5.5 states (unsigned, nonzero)
plus a per-slot "otherwise specified" opt-out that names the clause granting it — and a drift test
enumerating the integer-n slots so an unrouted one is visible. `VaryingOperand`'s shape in the same file is
the local precedent for the call site.
