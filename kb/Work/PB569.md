# PB569

## Mechanism
a DOUBLED separator-shaped character survives PICMODE's single trailing-comma trim, so `PIC 999,, USAGE DISPLAY.` binds a character-string-1 whose last symbol is ',' with further clauses following - exactly what SR7 forbids - silently at all four editions

### The refutation this note is written from
Row `SR-13.18.40.3-7` was adjudicated CONFORMS and OVERTURNED to `PARTIAL` by the refuter. Its reasoning, verbatim:

> REFUTED. The record closes SR7 on a STRUCTURAL argument -- a trailing ',' or '.' can only BE part of character-string-1 when the separator period abuts it -- so no check is needed. That argument is TRUE for '.' and FALSE for ','. CobolLexer.g4 PICMODE trims exactly ONE trailing ','/';' and only when LA(1) is whitespace/EOF; nothing re-examines SR7 afterwards (PictureAnalyzer.cs:52-58 strips only a trailing ';'). So a DOUBLED separator-shaped character survives the trim and yields a character-string-1 whose LAST SYMBOL IS ',' while further clauses follow -- precisely what SR7 forbids -- and the compiler accepts it silently. `01 W1 PIC 999,, USAGE DISPLAY.` binds a 4-position numeric-edited item (MOVE 12 -> [012,]) with USAGE DISPLAY following the PICTURE clause; `01 W1 PIC 999,, VALUE ZERO.` and `01 W1 PIC 999,; VALUE ZERO.` do the same with VALUE following. The legal SR7 spelling `PIC 999,.` produces the IDENTICAL item (rf7d), which proves the accepted forms differ from the legal one ONLY in the SR7 violation. The '.' arm genuinely is structural (a trailing '.' always backs up into the separator period, so `PIC 999.. USAGE DISPLAY.` cannot bind), so the rule is half-enforced: every ',' violation goes undiagnosed at ALL FOUR editions and under DECIMAL-POINT IS COMMA. Not DIVERGES because the legal shapes all bind correctly and the '.' half is enforced; PARTIAL because a whole class of the rule's violations is accepted.

### Inventory row `SR-13.18.40.3-7` (PARTIAL)
SR7 is enforced STRUCTURALLY rather than by a check, which is the correct architecture: 8.3.5 rule 2 makes ',' + space a separator and rule 3 makes '.' + space the separator period, so a trailing ','/'.' can only BE part of character-string-1 when the separator period abuts it -- and a separator period necessarily ends the entry, which is precisely 'the PICTURE clause shall be the last clause ... followed immediately (without an intervening separator space) by the separator period'. MEASURED, all four legs: (a) `01 W1 PIC 999,.` MOVE 12 -> [012,], four character positions, the comma kept (probe sr7a); (b) `01 W1 PIC 999..` -> [012.] (sr7b); (c) `01 W1 PIC 999, VALUE ZERO.` -> the ',' is a separator, character-string-1 is '999', numeric, [000] (sr7c) -- the misbind VCR row 7.14 recorded is gone; (d) PICTURE last after another clause, `01 W1 VALUE ZERO PIC 999,.` -> [000,] (sr7d). The illegal shapes are unreachable or rejected: `PIC 999.. VALUE ZERO.` is a parse error (sr7g), `PIC 999,.USAGE DISPLAY.` is COBOLNET0808 (sr7h). Re-measured under DECIMAL-POINT IS COMMA (SR13's role swap): both forms still bind, [012.] and [012,] (sr7e/sr7f).
