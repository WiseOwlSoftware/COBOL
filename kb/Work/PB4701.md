# PB4701 — the stored quotient of a size error is the 34-digit image's low-order digits

**Sites:** `src/WiseOwl.Cobol.Runtime/Values/Numeric/CobolExact.cs:180` (`CobolExact.DivToOdd`), `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/NumericRenderer.cs` (`NumericRenderer.ExactFinalQuotient`)

From the PB4640 report (wave 20261868 b), lead 1, copied: the STORED quotient of a size error (no phrase, checking off) is the 34-digit
image's low-order digits: `REMD R = 000003000100000000`, exact decimal (GnuCOBOL) `000003000000000000`. Same in
`COMPUTE R = FUNCTION ABS (A*A*A+7)/1000` and `DIVIDE ... GIVING` without `REMAINDER`. Site: `CobolExact.cs` (`DivToOdd`) via
`NumericRenderer.ExactFinalQuotient`; the report's fix shape: land the final transfer from the exact wide quotient with a sticky
remainder. The report calls it item-8 latitude, a value the receiver cannot hold, and says it shares no root with another lead.

Repro: the report's scratch probe `rem2.cob` (`REMD`) on the PB4640 build, run by the implementer.

**Landed (wave 20261872, group A).** Re-probed on the build (`E:/COBOL-coord/scratch/w20261872a/pd/g01.cob`): the main build stored `R = 000003000100000000` for `DIVIDE FUNCTION ABS (A*A*A + 7) BY 1000 GIVING R REMAINDER R2`, for `COMPUTE R = FUNCTION ABS (A*A*A + 7) / 1000` and for `DIVIDE ... GIVING R`; this build stores 000003000000000000 in all three (and R2 = 6).

Fix: the final-transfer quotient into a fixed-point resultant no longer goes through the 34-digit round-to-odd image. `NumericRenderer.ExactFinalQuotient` lands it from `CobolExact.QuotientAtScale`: the exact quotient rounded ONCE at the resultant's scale in the receiver's mode from the true remainder (`CobolNum.RoundDiv` over the exact integers), and landed as every exact value lands (`CobolBig.ToUnscaled`'s disposition: checked, EC-SIZE-TRUNCATION; unchecked, the quotient's own low-order 38 digits, GnuCOBOL's `cob_decimal_div` then `cob_decimal_get_field`). A statement under INTERMEDIATE ROUNDING IS PROHIBITED keeps the 34-digit screened quotient (`CobolExact.DivToOdd`), the lane determination of DOC-A.1-82.

**Golden:** `conformance-suite/wiseowl/cases/14.9.12-DIVIDE/pb4701_size_error_stores_the_exact_quotient_digits` (2002, 2014, 2023; a WiseOwl case: the stored value of a size error with no phrase is implementor-defined, item 8); unit `CobolBigExactFormTests.QuotientAtScale_LandsTheExactQuotient`.
