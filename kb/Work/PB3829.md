# PB3829 — the codomain clamp cuts a ROUNDED result

## Owner decision

The owner APPROVED the fix on 2026-10-26 at about 11:05 PDT, in chat: "Approve fixing the ACOS ROUNDED defect. Ensure
that the fix actually corrects the ROUNDED root cause, not just fixes that one example". So the fix is the root cause
(the clamp cutting any ROUNDED landing of every codomain-bounded intrinsic), never the ACOS(-1) example alone.

⚠ **This finding would OVERTURN PART OF A LANDED FIX.** The clamp is the `FromDoubleBounded` member of landed

values in its ROUNDED legs (RASIN1, RASINM, RACOSM, RFRACP; landed [[PB647]] added those legs on purpose). The owner

## The rules, quoted (each run through `python scripts/spec/cite.py --check`, all OK)

- §14.7.4.3 4): "If the NEAREST-AWAY-FROM-ZERO phrase is specified or implied and the arithmetic value cannot be
  exactly represented in the resultant identifier, the arithmetic value is rounded to the nearest value that can be
  represented in the resultant identifier".
- §11.9.6.3 2): "If the DEFAULT ROUNDED clause is not specified, DEFAULT ROUNDED MODE IS NEAREST-AWAY-FROM-ZERO is
  implied."
- §14.9.8.4 2): the value is stored in conformance with 14.6.8, 14.7.4 (the ROUNDED phrase) and 14.7.5 (the SIZE ERROR
  phrase).
- §15.8.4 1) (ACOS): "The returned value is the approximation of the arccosine of argument-1 and is greater than or
  equal to zero and less than or equal to π." That bounds the RETURNED value, which is already at most π. It does not
  bound the receiving item's value after rounding, so the clamp reads the rule wider than it is written.

## Mechanism

`FromDoubleBounded` lands the double with `FromDouble` and then cuts the result to floor(bound x 10^scale).
`IntrinsicRenderer.RenderFloatNative` emits it for every catalog row that has a codomain (`IntrinsicCatalog.Build`, the
ACOS row). Under truncation the clamp is a no-op (PB647's own comment says so); under ROUNDED it cuts a correctly rounded
value back down by one unit in the last place.

## Acceptance

- `COMPUTE R ROUNDED = FUNCTION ACOS(-1)` into PIC 9V9999 stores 3.1416, and the same for ASIN(1) (1.5708), ATAN,
  RANDOM and FRACTION-PART under every ROUNDED mode §14.7.4.3 defines.
- The ROUNDED legs of `pb65_codomain_clamp.out` are re-derived from §14.7.4.3 (never copied from either compiler), and
  the note records which legs moved.
- PB65's clamp member is retired or reduced to what the §15.x returned-value rules actually bound; the inventory rows
  named above are re-checked and the doc that describes the clamp is updated in the same change.

## Determination (wave 20261707 group A implementer, 2026-10-26; every citation `cite.py --check` OK)

No rule of ISO/IEC 1989:2023 bounds the STORED value by a function's codomain. The §15.x.4 returned-value rules bound
the RETURNED value, which §15.4 places in "a temporary elementary data item" (§15.4: "The evaluation of a function
produces a returned value in a temporary elementary data item."; §15.75.4 1): "The returned value is greater than or
equal to zero and less than one."; §15.8.4 1), §15.10.4 1), §15.11.4 1) likewise). The value a resultant identifier
receives is §14.9.8.4 2)'s: "The value obtained according to rule 1 is then stored, in conformance with the
specifications in 14.6.8, Alignment and transfer of data into data items, 14.7.4, ROUNDED phrase, and 14.7.5, SIZE
ERROR phrase and size error condition". §14.7.4.3 2)-10) round the arithmetic value at the resultant identifier, and
§14.7.5 3) makes "the result of an arithmetic statement ... further from zero than permitted for the associated
resultant data item" a size error. So:

- ACOS(-1) ROUNDED into `9V9999` stores 3.1416 (§14.7.4.3 4)), past π; ASIN(1) stores 1.5708, ATAN(10^18) 1.5708.
- PB65's RANDOM case: a returned value 0.9999999996 stored ROUNDED into `9V9(9)` is 1.000000000; into `V9(9)`, which
  has no integer position, the rounded 1.000000000 is a SIZE ERROR condition (ON SIZE ERROR runs and the receiver is
  unchanged, §14.7.5 rule 2 of the phrase; without the phrase the store keeps the low-order digits, the documented
  §14.6.13.1.3 disposition), never a clamp to 0.999999999.

The adjudicator's reading holds. The clamp is therefore deleted at its root (not reduced): there is no bound left for
it to enforce.
