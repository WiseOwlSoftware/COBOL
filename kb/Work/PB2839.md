# PB2839 — LANDED — A-B and A_B are one C# identifier

Found by the w1047a implementer (PB1965, report lead 1) and Filed by the train 1047 lander, 2026-10-08 20:53 PDT.

## Repro
`E:\COBOL-coord\scratch\w1047a\p\u.cob` at `--std 2023`: a class with METHOD-IDs `A-B` and `A_B` (two distinct
COBOL words; underscore is a COBOL character at 2014+) fails to compile with Roslyn CS0111 (a duplicate member).

## Mechanism
`src/Cobol.Net.Compiler/Binding/Model/DataItem.cs#IdentifierCharacters` (line ~1305) maps '-' to '_' when it derives
a C# identifier from a COBOL name, so two names that differ only there collide. Every derived identifier (methods,
properties, programs, data items, formals) shares it. The fix needs an injective naming scheme (a NamingConvention
decision, e.g. escaping '_' when a name holds both, or a reserved encoding for '-'), which is why the implementer did
not fix it inside PB1965. It shares PB1965's "the derived identifier must be injective" root, not its fold.

## Code sites
`src/Cobol.Net.Compiler/Binding/Model/DataItem.cs#IdentifierCharacters` and its callers (`DataItem` line ~1282
"collision-safe C# identifier").

**2026-10-08 20:54 PDT, train 1047 lander review (cluster 45B, PB2097), evidence:** the same non-injective mapping now reaches
across modules. `CsNames.ModuleNamespaceOf` (`src/Cobol.Net.Compiler/CodeGen/CsNames.cs:47-51`) derives the module
namespace through `DataItem.Sanitize`, so modules `PAY-ROLL` and `PAY_ROLL` both get `Cobol.PAY_ROLL` and the same
registrar string; `ProgramTable.RegisterModule` (`ProgramTable.cs:163`) returns early for a registrar it has seen, so
the second module is skipped and a `CALL "PAY_ROLL"` answers EC-PROGRAM-NOT-FOUND ("does not carry the program"),
and a host referencing both assemblies gets CS0433. The injective scheme this note asks for fixes both; tie each
registrar to its assembly too, so a different assembly with the same registrar is refused with a reason, not skipped.

## Landed (wave 1051 B, 2026-10-10)
Re-probed on the wave's own build: `E:/COBOL-coord/scratch/w1051b/p2839/u.cob` (a copy of the w1047a repro) at
`--std 2023` failed CS0111 / CS0121; the new golden's shape (PROPERTY items `P-Q` and `P_Q`) crashed the compiler outright
(`InvalidOperationException: PROPERTY accessor '__GET_P_Q' is already on the roster`). Citation corrected: the word
formation rule is §8.3.2.1 (`cite.py --check 8.3.2.1` OK), not "8.3.1.1.1", which does not exist.
**Root:** `DataItem.IdentifierCharacters` is now INJECTIVE: a hyphen is `_` (the readable common case), an underscore
and every character a C# identifier cannot hold is `_uXXXX_`, and a hyphen that is first or is followed by a lowercase
`u` is escaped too, so an underscore in the output is a hyphen exactly when no `u` follows it and the input can be read
back. Every derived identifier goes through it (`Sanitize`, `WordIdentifier`, so methods, properties, formals, classes,
programs and `CsNames.ModuleNamespaceOf`), so the module half of the note is the same fix: `PAY-ROLL` is `Cobol.PAY_ROLL`
and `PAY_ROLL` is `Cobol.PAY_u005F_ROLL`, two registrars. The note's "tie each registrar to its assembly" needs no
second mechanism: a registrar is now a function of the assembly simple name, and two assemblies of one simple name
cannot both load into the default load context. `ProcedureTableBuilder` lost its private `.` → `_` pre-mapping (the one
mapping escapes `.`). Docs: CONFORMANCE DOC-A.1-121 (the accessor name `__GET_MY_u005F_BAL`), DESIGN-external-repository
§4.5, COBOLNET_PIPELINE_DESIGN D4. Tests: `conformance:2002/pb2839_hyphen_underscore_distinct_names` (methods, formals,
properties), `ModuleRegistrationHostTests.ModulesWhoseNamesDifferOnlyInHyphenAndUnderscore_AreTwoModules`,
`unit:IdentifierInjectivityTests` (a decoder reads back every word of up to four of the hard characters).
