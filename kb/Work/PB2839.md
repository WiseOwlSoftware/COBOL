# PB2839 — OPEN — A-B and A_B are one C# identifier

Found by the w1047a implementer (PB1965, report lead 1) and Filed by the train 1047 lander, 2026-10-08 20:53 PDT.

## Repro
`E:\COBOL-coord\scratch\w1047a\p\u.cob` at `--std 2023`: a class with METHOD-IDs `A-B` and `A_B` (two distinct
COBOL words; underscore is a COBOL character at 2014+) fails to compile with Roslyn CS0111 (a duplicate member).

## Mechanism
`src/Cobol.Net.Compiler/Binding/Model/DataItem.cs#IdentifierCharacters` (line ~1305) maps '-' to '_' when it derives
a C# identifier from a COBOL name, so two names that differ only there collide. Every derived identifier (methods,
properties, programs, data items, formals) shares it. The fix needs an injective naming scheme (a NamingConvention
decision, e.g. escaping '_' when a name holds both, or a reserved encoding for '-'), which is why the implementer did
not fix it inside PB1965. It shares PB1965's "the derived identifier must be injective" root, not its fold.

## Code sites
`src/Cobol.Net.Compiler/Binding/Model/DataItem.cs#IdentifierCharacters` and its callers (`DataItem` line ~1282
"collision-safe C# identifier").

**2026-10-08 20:54 PDT, train 1047 lander review (cluster 45B, PB2097), evidence:** the same non-injective mapping now reaches
across modules. `CsNames.ModuleNamespaceOf` (`src/Cobol.Net.Compiler/CodeGen/CsNames.cs:47-51`) derives the module
namespace through `DataItem.Sanitize`, so modules `PAY-ROLL` and `PAY_ROLL` both get `Cobol.PAY_ROLL` and the same
registrar string; `ProgramTable.RegisterModule` (`ProgramTable.cs:163`) returns early for a registrar it has seen, so
the second module is skipped and a `CALL "PAY_ROLL"` answers EC-PROGRAM-NOT-FOUND ("does not carry the program"),
and a host referencing both assemblies gets CS0433. The injective scheme this note asks for fixes both; tie each
registrar to its assembly too, so a different assembly with the same registrar is refused with a reason, not skipped.
