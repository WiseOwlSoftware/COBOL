# PB4044 — negated-condition-containing-not-refused: NOT before a condition that has its own NOT is refused: IF NOT X IS NOT ZERO gives "boolean expected with logical operator"

Filed 2026-10-29 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-20261028-210601`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

cobc 3.2 refuses a negated simple condition whose simple condition itself contains the word NOT:
`IF NOT X IS NOT ZERO`, `IF NOT X IS NOT = 0` and `IF NOT X IS NOT NUMERIC` each give "invalid expression: boolean
expected with logical operator". The same conditions compile when the inner condition is parenthesized
(`NOT (X IS NOT ZERO)`) or when the inner NOT is absent (`NOT X IS ZERO`). The standard allows the logical operator
NOT before any simple condition, and a sign, relation or class condition written with its own NOT is a simple
condition. Class: rejects legal source. Fuzz program fz03677 (night fuzz-20261028-210601), line 107
`IF NOT WS-O IS NOT ZERO`.

## Minimal test case

Free reference format.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. NEGNOT.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 X PIC S9(4) VALUE 1.
PROCEDURE DIVISION.
    IF NOT X IS NOT ZERO
       DISPLAY "1 T"
    ELSE
       DISPLAY "1 F"
    END-IF
    IF NOT X IS NOT = 0
       DISPLAY "2 T"
    ELSE
       DISPLAY "2 F"
    END-IF
    IF NOT X IS NOT NUMERIC
       DISPLAY "3 T"
    ELSE
       DISPLAY "3 F"
    END-IF
    STOP RUN.
```

## Environment

`cobc (GnuCOBOL) 3.2.0`, Ubuntu package `gnucobol3 3.2-4build1`, WSL2 Ubuntu (Linux 6.18.54.1-microsoft-standard-WSL2
x86_64). Compiled with `cobc -x -free -std=cobol2014 -o negnot negnot.cob`; no executable is produced, so nothing is
run. Controls, each a one-condition program with X = 1: `IF NOT (X IS NOT ZERO)` compiles and prints F;
`IF NOT X IS ZERO` compiles and prints T; `IF NOT X IS NOT POSITIVE` and `IF NOT X NOT ZERO` are refused like line 7.

## Observed result

Compile, exit code 1:

```text
negnot.cob:7: error: invalid expression: boolean expected with logical operator
negnot.cob:12: error: invalid expression: boolean expected with logical operator
negnot.cob:17: error: invalid expression: boolean expected with logical operator
```

## Expected result (per ISO)

The program is legal; it compiles and prints `1 F`, `2 F`, `3 T` (X is 1: X IS NOT ZERO is true, X IS NOT = 0 is true,
X IS NOT NUMERIC is false; NOT reverses each).

- §8.8.4.2.1 (checked): "The simple conditions are the relation, boolean, class, condition-name, switch-status, sign, and
  omitted-argument conditions." `X IS NOT ZERO` is a sign condition (§8.8.4.7.1, checked: "The sign condition
  determines whether or not the algebraic value of an arithmetic expression is less than, greater than, or equal to
  zero."; its general format is `arithmetic-expression-1 IS [ NOT ] { POSITIVE | NEGATIVE | ZERO }`), `X IS NOT = 0` a
  relation condition and `X IS NOT NUMERIC` a class condition, each with its own optional NOT.
- §8.8.4.10.1 (checked): "A condition is negated by use of the logical operator 'NOT', which reverses the truth value of
  the condition to which it is applied." The general format is `NOT condition-1`.
- §8.8.4.11.3 (checked): Table 5, "Combinations of conditions, logical operators, and parentheses": NOT may be first in a
  conditional expression and may be immediately followed by a simple-condition or a left parenthesis; a
  simple-condition may be immediately preceded by NOT. The only NOT pairing the clause forbids is NOT NOT (§8.8.4.11.3,
  checked: "the pair 'NOT (' is permissible while the pair 'NOT NOT' is not permissible"); here NOT is followed by an
  operand, not by NOT.
- The more specific rule considered: the abbreviated combined relation conditions (§8.8.4.12.1, checked: "When simple or
  negated simple relation conditions are combined with logical connectives in a consecutive sequence") give NOT a
  special reading only inside such a sequence; none of these conditions is combined or abbreviated.

Edition: 2014. The 2009 committee draft for ISO/IEC 1989:2014 (CD 1.2) has the same negated-condition rule and general
format `NOT condition-1` (its 8.8.4.2.1) and the same combinations table (its Table 6: NOT may be followed by a
simple-condition) with the same "'NOT NOT' is not permissible" note.

## Our compiler

WiseOwl COBOL (fresh judge, `--std 2014 --source-format free`): compiles with no diagnostic; the run prints `1 F`,
`2 F`, `3 T`, exit code 0. On the fuzz program fz03677 it prints `PASS-15` for line 107.

## Fix site

`cobc/typeck.c`: the expression builder (`cb_build_expr` with `build_expr_shift`, `build_expr_shift_sign` and the `'!'`
(NOT) case of `build_expr_reduce`) does not take the leading NOT as applying to the whole sign, relation or class
condition when that condition carries its own NOT; the negation reaches `cb_build_binary_op` in `cobc/tree.c` with a
non-condition operand, which reports "invalid expression: boolean expected with logical operator".
