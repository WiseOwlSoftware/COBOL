**Rule it breaks:** one rule, one place (design §5.2; dimensions.md 4). The rule is UTS #10 S2.1-S2.1.3; the tailoring builder's canonical closure exists precisely so a text orders the same precomposed or decomposed, which holds only while its walk matches what the run-time iterator does

**Scenario:** CollationElementIterator.TryMatchContraction/FindContraction/MatchesAt match every contraction of the table, and try the discontiguous extension whatever the first code point is. CldrTailoringBuilder.CloseOverComposites re-implements the same walk over the NFD of each composite, but matches only the TAILORED keys (byFirst), walks every other code point singly through Lookup, so a ROOT contraction inside the decomposition is never matched, and only extends when the first code point is a starter or already matched. A composite whose NFD holds a root contraction next to a tailored piece is therefore given elements the run-time iterator would not produce for its decomposed spelling, breaking the closure's own invariant; and a later correction to the blocking rule (S2.1.2) in one copy will not reach the other. Whether a CLDR 48 locale reaches the existing divergence is not measured.
