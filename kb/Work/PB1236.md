# PB1236 — OPEN

## Measured

**external-clause** — Externalized-name comparison is two rules: the §13.18.22.3 SR2 uniqueness screen (DataBinder.Linkage CheckExternalizedNameUniqueness) compares with StringComparer.Ordinal, while the run-unit store it protects (ExternalTable._cells) keys with StringComparer.OrdinalIgnoreCase - so two EXTERNAL entries in ONE source element whose externalized names differ only in case pass the screen and silently alias one cell of the first-created width

- **Repro:** WORKING-STORAGE: `01 A PIC X(3) EXTERNAL.` `01 B PIC X(5) EXTERNAL AS "a".` PROCEDURE: MOVE "ABC" TO A. MOVE "12345" TO B. DISPLAY "A=[" A "] B=[" B "]". (probe SR2ALIAS, default 2023; any edition >= 2002)
- **Expected (spec):** One formation/mapping of externalized names (§8.3.2.2 2) is implementor-defined but must be ONE): either the names are distinct -> `A=[ABC] B=[12345]`, or they are the same externalized name -> COBOLNET2159 at compile time per §13.18.22.3 SR2. Given the store's case-insensitive mapping (which also governs cross-element sharing, GR5), the conforming fix is the SR2 screen using the SAME comparer as the store (one comparer, shared, with a drift test).
- **Observed:** Observed `A=[123] B=[123  ]` - no diagnostic; B's 5-byte description windows A's 3-byte cell, truncating and aliasing both items.
- **Code site:** src/Cobol.Net.Compiler/Binding/DataBinder.Linkage.cs#CheckExternalizedNameUniqueness (new Dictionary<string,string>(StringComparer.Ordinal)); src/Cobol.Net.Runtime/Control/ExternalTable.cs (_cells / _describers OrdinalIgnoreCase)
- **Clause (adjudicator):** §13.18.22.3 SR2; §13.18.22.4 GR5; §8.3.2.2 2)

**external-clause** — The §13.18.22.4 GR6 VALUE-identity fact is emitted as RawValue.ToUpperInvariant(), which case-folds the literal CONTENT, so two record-name VALUE clauses that differ only in letter case compare identical and EC-EXTERNAL-FORMAT-CONFLICT is not raised

- **Repro:** Two elements, both with `>>TURN EC-EXTERNAL-FORMAT-CONFLICT CHECKING ON` before ENVIRONMENT DIVISION: caller `01 XV PIC X(4) IS EXTERNAL VALUE "ABCD".`, callee `01 XV PIC X(4) IS EXTERNAL VALUE "abcd".`; CALL with ON EXCEPTION DISPLAY FUNCTION EXCEPTION-STATUS (probe G6CASE).
- **Expected (spec):** §13.18.22.4 GR6 via §14.8.4.3: the VALUE clause specifications for the record name are not identical -> the CALL is not successful and ON EXCEPTION reports EC-EXTERNAL-FORMAT-CONFLICT (as it does for "ABCD" vs "WXYZ", probe G6VAL1).
- **Observed:** Observed SUB-RAN / NOEXC. Only keyword spellings (figurative constants) may be case-normalized; the literal's characters are significant. Also: the ExternalDescriptor doc comment in ExternalTable.cs describes a 'VALUE-composed initial image when ANY VALUE clause appears', which is not what the emitter builds (doc drift).
- **Code site:** src/Cobol.Net.Compiler/CodeGen/Verbs/OoEmitter.cs#EmitExternalDescribes (`ext.Record.RawValue is { } rv ? CsLiteral(rv.ToUpperInvariant())`)
- **Clause (adjudicator):** §13.18.22.4 GR6; §14.8.4.3
