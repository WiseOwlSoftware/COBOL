# PB1076 — OPEN — the OO environment-division PLACEMENT rules have one arm, and it is wrong: `OoBindMethodData` refuses a method's bare ENVIRONMENT DIVISION header (COBOLNET1519)

## Rule text (every citation re-run by the registrar)
- `python scripts/spec/cite.py --check 12.3.3 "The SOURCE-COMPUTER, OBJECT-COMPUTER, and REPOSITORY paragraphs shall not be specified in a factory definition or an instance definition"` → `OK  §12.3.3 3)  (Syntax rules)`
- `python scripts/spec/cite.py --check 12.4.3 "The input-output section shall not be specified within an interface definition"` → `OK  §12.4.3 1)  (Syntax rule)`
- `python scripts/spec/cite.py --check 12.3.7.3 "In a factory definition or instance definition, the only clauses that may be specified are the CURSOR and CRT STATUS clauses"` → `OK  §12.3.7.3 2)  (Syntax rules)`
- `python scripts/spec/cite.py --check 12.3.7.3 "In an interface definition, the ALPHABET clause, the CURRENCY clause, the DECIMAL-POINT clause, and the LOCALE clause are the only permitted clauses"` → `OK  §12.3.7.3 3)  (Syntax rules)`

### Adjudicator finding (configuration-section, harm rejects-legal-source)
- **Mechanism:** The §12.3.3 SR2 screen in OoBindMethodData tests for the ENVIRONMENT DIVISION instead of the configuration section, so a legal bare ENVIRONMENT DIVISION header in a method is refused (COBOLNET1519).
- **Repro:** CLASS-ID with FACTORY containing: METHOD-ID. BUMP. / ENVIRONMENT DIVISION. / PROCEDURE DIVISION. / MAIN. DISPLAY "BUMPED". / END METHOD BUMP. -- cobol.exe <src> --std 2023 --run (probe E:/Temp/claude/E--CobolSharp/a700c052-f9e4-4942-84ff-a13c7505d6ec/scratchpad/adj-d1/out/probe/configuration-section/meth_empty_env)
- **Expected (spec):** Compiles and prints BUMPED: §10.6.1 method-definition prints [ environment-division ]; §12.2.1 makes configuration-section and input-output-section both optional; §12.3.3 SR2 forbids only the configuration SECTION and §12.4.3 SR1 only the input-output SECTION. A CONFIGURATION SECTION header (even empty) in a method must still be rejected.
- **Observed:** error COBOLNET1519: method 'BUMP': a method definition shall not contain an ENVIRONMENT DIVISION ... (ISO §12.3.3 SR2 / §12.4.3 SR1), rc 70. The check is `if (m.Ctx.environmentDivision() is not null)`; it should key on environmentDivision().configurationSection() (SR2) and .inputOutputSection() (§12.4.3 SR1) separately, each with its own citation. OoSpineTests.MethodMayNotOwnEnvOrFileSection_1519 pins only the I-O arm and does not exercise the bare header.
- **Code site:** src/Cobol.Net.Compiler/Binding/DataBinder.Oo.cs#OoBindMethodData (~line 268)
- **Clause (adjudicator):** §12.3.3 SR2; §10.6.1; §12.2.1; §12.4.3 SR1

### Adjudicator finding (input-output-section, harm under-rejects)
- **Mechanism:** The §12.4.3 SR1 placement screen exists only on the METHOD arm: an input-output section in a CLASS-LEVEL environment division or an INTERFACE-level environment division is bound, not refused
- **Repro:** p4.cob: CLASS-ID. IOSC4. / ENVIRONMENT DIVISION. / INPUT-OUTPUT SECTION. / FILE-CONTROL. / SELECT F1 ASSIGN TO "iosc4.dat". / OBJECT. / DATA DIVISION. / FILE SECTION. / FD F1. / 01 R1 PIC X(5). / PROCEDURE DIVISION. / METHOD-ID. M1. PROCEDURE DIVISION. OPEN OUTPUT F1 CLOSE F1. END METHOD M1. / END OBJECT. / END CLASS IOSC4.  and  p6.cob: INTERFACE-ID. IOSI6. / ENVIRONMENT DIVISION. / INPUT-OUTPUT SECTION. / FILE-CONTROL. / SELECT F1 ASSIGN TO "iosi6.dat". / PROCEDURE DIVISION. / METHOD-ID. M1. PROCEDURE DIVISION. END METHOD M1. / END INTERFACE IOSI6.  -- `cobol p4.cob --std 2023` (and 2002) and `cobol p6.cob --std 2023` (and 2002) each exit 0 with no diagnostic (probe dir E:/Temp/claude/E--CobolSharp/a700c052-f9e4-4942-84ff-a13c7505d6ec/scratchpad/adj-d1/out/probe/iosec).
- **Expected (spec):** Both are nonconforming: §12.4.3 SR1 'Within a class definition, the input-output section may be specified only in a factory definition or instance definition, but not in a method definition. The input-output section shall not be specified within an interface definition.' The class-level environment division is neither a factory nor an instance definition, so a compile-time error is required for p4; p6 requires one by the interface sentence. (A class-level ENVIRONMENT DIVISION holding only a CONFIGURATION SECTION stays legal -- §10.6 prints [environment-division] in both skeletons.)
- **Observed:** The only placement check is DataBinder.Oo.cs OoBindMethodData (COBOLNET1519, method arm; interface method prototypes also reach it). OoDriver.OoReparentClassData / OoReparentFactoryData append the class-level environmentDivision to BOTH halves' synthetic program units and DataBinder.EnvDivisions iterates it, so the class-level FILE-CONTROL is silently bound into the OBJECT and the FACTORY binder (the file becomes visible to both halves). OoDriver.BindInterfaceData likewise binds the interface's environmentDivision through BindDeclarations with no screen. PrototypeUnitRules.Screen's §10.6.2 SR4 d) check covers only program/function prototypes. The fix belongs at the OO unit shape (one screen over classDefinition.environmentDivision().inputOutputSection() and interfaceDefinition.environmentDivision().inputOutputSection(), alongside the method arm so the three placement arms of SR1 are judged in one place), plus goldens/negatives for both arms.
- **Code site:** src/Cobol.Net.Compiler/Oo/OoDriver.cs#OoReparentClassData / #OoReparentFactoryData / #BindInterfaceData; src/Cobol.Net.Compiler/Binding/DataBinder.Oo.cs#OoBindMethodData (the only existing arm)
- **Clause (adjudicator):** §12.4.3 SR1

### Adjudicator finding (special-names-paragraph-p1, harm under-rejects)
- **Mechanism:** SPECIAL-NAMES clause restrictions for OO source units have no screen: the grammar admits an environment division in FACTORY, OBJECT and INTERFACE-ID definitions and OoDriver splices it into the bound unit, but nothing applies SR2's CURSOR/CRT-STATUS-only list or SR3's ALPHABET/CURRENCY/DECIMAL-POINT/LOCALE list (the prototype twin, PrototypeUnitRules.AdmittedInPrototype for §10.6.2 SR4 c), exists and is the shape to reuse)
- **Repro:** CLASS-ID. C. FACTORY. ENVIRONMENT DIVISION. CONFIGURATION SECTION. SPECIAL-NAMES. DECIMAL-POINT IS COMMA. PROCEDURE DIVISION. END FACTORY. OBJECT. ... END CLASS C.   and   INTERFACE-ID. I. ENVIRONMENT DIVISION. CONFIGURATION SECTION. SPECIAL-NAMES. CLASS DIG IS "0" THRU "9". PROCEDURE DIVISION. METHOD-ID. M1. PROCEDURE DIVISION. END METHOD M1. END INTERFACE I.  (--std 2023)
- **Expected (spec):** §12.3.7.3 SR2: 'In a factory definition or instance definition, the only clauses that may be specified are the CURSOR and CRT STATUS clauses.' SR3: 'In an interface definition, the ALPHABET clause, the CURRENCY clause, the DECIMAL-POINT clause, and the LOCALE clause are the only permitted clauses.' Each out-of-list clause is a compile-time error.
- **Observed:** Measured: FACTORY with DECIMAL-POINT IS COMMA or a CLASS clause, OBJECT with CURRENCY SIGN, and INTERFACE with CLASS / SYMBOLIC CHARACTERS / a device entry all compile rc=0 with no diagnostic; INTERFACE with ALPHABET, CURRENCY, DECIMAL-POINT (the permitted clauses) compile, as they should. grep over src finds no SR2/SR3 enforcement.
- **Code site:** src/Cobol.Net.Frontend/Grammar/Core/CobolOO.g4#factoryParagraph/#objectParagraph/#interfaceDefinition; src/Cobol.Net.Compiler/Oo/OoDriver.cs; sibling src/Cobol.Net.Compiler/Binding/PrototypeUnitRules.cs#AdmittedInPrototype
- **Clause (adjudicator):** §12.3.7.3 SR2, SR3
