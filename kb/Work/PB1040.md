# PB1040 — LANDED

## Measured
```cobol
       >>TURN EC-ALL CHECKING ON
       IDENTIFICATION DIVISION.
       PROGRAM-ID. C41OUT.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 R PIC X(5) VALUE "#####".
       PROCEDURE DIVISION.
           CALL "C41IN" RETURNING R
           DISPLAY "[" R "] L=" FUNCTION LENGTH(R)
           DISPLAY "EX=" FUNCTION EXCEPTION-STATUS
           STOP RUN.
       END PROGRAM C41OUT.
       IDENTIFICATION DIVISION.
       PROGRAM-ID. C41IN.
       DATA DIVISION.
       LINKAGE SECTION.
       01 L PIC X(3).
       PROCEDURE DIVISION RETURNING L.
           MOVE "ABC" TO L
           GOBACK.
       END PROGRAM C41IN.
```

prints **`[ABC] L=5`** and `EX=` blank: the receiver's image is three characters wide although FUNCTION LENGTH says 5.

## The rules
- `cite.py --check 14.8.3.3 "the receiving operand shall have the same ALIGN, BLANK WHEN ZERO, DYNAMIC LENGTH, JUSTIFIED, PICTURE, SIGN, and USAGE clauses"` → OK (§14.8.3.3; `PIC X(5)` vs `PIC X(3)` does not conform).
- `cite.py --check 14.9.4.4 "the rules for conformance specified in 14.8.2, Parameters and 14.8.3, Returning items apply"` → `OK §14.9.4.4 3)`: GR3 d)'s violation arm is EC-PROGRAM-ARG-MISMATCH.

## Code site
`src/Cobol.Net.Runtime/Control/CallAbi.cs` `StoreReturn(CobolArg?, string)` — `if (c is ManagedPointer<string> sp &&
r.Num is null) { sp.Value = value; return; }`. No width is consulted.

## What the fixer owes
Carry the receiver's character length on `CobolArg` (PB165's design finding: CobolArg has no byte length today — the
same registry closes both) and, on a mismatch, raise EC-PROGRAM-ARG-MISMATCH per GR3 d); with checking off, store
into the receiver's own width (never change its image width). Sweep the INVOKE RETURNING and function-result arms.

## Landed (wave 1003 group C, w1003c) — RETURNING conformance on the dynamic lane, plus the two sibling arms

Re-probed on the w1003c build before the fix: `[ABC] L=5`, `EX=` blank (the p1040 program above, with an ON EXCEPTION
phrase that never ran). After: `EXC`, `[#####] L=5`, `EX=EC-PROGRAM-ARG-MISMATCH` — the call is not successful, the
callee never runs and the receiver is untouched (§14.9.4.4 GR3 d) and GR3 h) 1., both cite-checked).

- **The mechanism is one description the two sides can compare.** `CobolArg` gains `Length` (the text-carried item's
  fixed character length, `Unstated` = -1 otherwise) beside `Num`/`Layout`; `BoundaryItem(Num, Length)` is the pair
  both sides state, `BoundaryItem.Conforms` the ONE rule (numeric-vs-character never conforms; two profiles must state
  one PICTURE, SIGN and USAGE, `NumProfile.ConformsTo`; two lengths must be equal; an item that states nothing — a
  pointer, DYNAMIC LENGTH, ANY LENGTH, a variable-length group — is not compared). The activated unit REGISTERS its
  RETURNING item's `BoundaryItem` with its formal counts (`ProgramRegistry.Register(…, returning:)`,
  `CallEmitter.RegisteredReturning`), the activating element sends the receiver's on the returning `CobolArg`
  (`CallEmitter.ReturningArgText`, `CallEmitter.BoundaryLength` — the one measure, in `CallStringRead`'s unit), and
  `ProgramTable.CallProgram` compares them before the activation under the same enabled-in-both gate as the count check.
- **Unchecked** (either half off) the call proceeds and every `StoreReturn` text leg stores into the RECEIVER'S OWN
  width (`CobolArgAdapt.FitToReceiver` — §14.6.8.5's left-justified, space-filled, right-truncated alignment; a numeric
  receiver reads the sender's value under its own profile, `ImageForReceiver`), so an item's image never changes width.
  The decision is recorded in `docs/CONFORMANCE.md` §3 ("a RETURNING result whose description does not conform").
- **Sibling sweep (CLAUDE.md rule 4) — two more arms of the same GR3 d) rule were silent, both fixed here.**
  (1) A unit with NO formals registered no count facts, so `CALL "NOFORMALS" USING A` ran under enabled checking where
  §14.8.2.1 ("The number of arguments … shall be equal to the number of formal parameters") makes it a mismatch; every
  unit now registers its counts. (2) `CallEmitter.InvocationText` passed the activating half of the gate to
  `CallProgram` only: the program-pointer and function-pointer arms dropped it, so the same CALL raised by name and not
  through a pointer. The INVOKE arm is not a sibling: a static INVOKE is conformance-checked at bind
  (`OoConformance`) and a universal one compares descriptors (`OoEmitter.EmitCobolInvokeCase`); the function-result arm
  reaches `CallProgram` through the same `BoundCallProgram` and the same `ReturningArgText`.
- **Goldens:** `conformance:2002/pb1040_returning_length_conformance` (checked X(3)→X(5), 9(3)→9(5) and group pairs
  raise and leave the receiver untouched; the conforming pair delivers; callee-unchecked and site-unchecked arms fit
  to width, truncating and padding, and a numeric receiver gets 00123) and
  `conformance:2002/pb1040_activation_mismatch_every_lane` (the formal-less count by name and through a
  program-pointer, the conforming pairs, and the RETURNING pair through a pointer). `>>TURN` is the 2002 introduction
  (`negative:pb1381-turn-before-header-85` already refuses it at 85), so no new negative: the rule's behaviour does not
  differ by edition from 2002 on.
- **Residue, not this note's:** the ARGUMENT side of the dynamic lane (a BY REFERENCE / BY CONTENT length or PICTURE
  mismatch, kb/Work PB165) still has nothing to compare against — `BoundaryItem` is the shape its per-formal registry
  extends. The function-pointer arm's `site` argument shares its one rendering with the program-pointer arm that the
  golden does pin; it has no golden of its own.

### For the next implementer (what each file now owns)

- `src/Cobol.Net.Runtime/Control/CallAbi.cs#BoundaryItem` — the pair (`Num`, `Length`) both sides of a dynamic CALL state and
  the ONE `Conforms` rule; REUSE it for the per-formal registry of kb/Work PB165, never a second shape. `CobolArg.Length` is
  stated for the RETURNING receiver only; the argument arms state none yet. Trap: `Length` is the TEXT carrier's width — a
  native numeric cell states `Num` and no `Length`, so a numeric pair is compared by profile alone.
- `src/Cobol.Net.Runtime/Control/CallAbi.cs#FitToReceiver` / `#ImageForReceiver` — the unchecked store; every `StoreReturn`
  string leg ends in one of them (§14.6.8.5). A new string leg must too, or an image of the wrong width reaches an item.
- `src/Cobol.Net.Runtime/Control/ProgramTable.cs#CallProgram` — the GR3 d) checks (count, RETURNING) share `mismatchChecked`
  (`siteArgMismatchChecking && node.ArgMismatchChecking`); `Register(…, returning:)` stores the callee's `BoundaryItem`. The
  pointer arms (`CallPointer`, `CallFunctionPointer`) now pass the site half too. Trap: they used to drop it, silently.
- `src/Cobol.Net.Compiler/CodeGen/Verbs/CallEmitter.cs#BoundaryLength` / `#RegisteredReturning` / `#BoundaryProfile` — the
  emit-side twins: one measure of a text item's length (via `Place.DenotedItem`, never a hand-written RefMod test —
  `PlaceDenotedItemDriftTests`) and one choice of which items state a numeric profile. Compare against
  `RuntimeApi.UnstatedBoundaryLength`, never a bare `CobolArg.Unstated` (`RuntimeApiGuardTests`).
- `src/Cobol.Net.Compiler/CodeGen/ProgramEmitter.cs#EmitEntryWrapper` — EVERY unit registers `formalCount` / `requiredCount` /
  `argMismatchChecking`; a formal-less unit used to register nothing. Trap: this changes the `Register` line of every
  emitted-C# snapshot (regenerate with `COBOLNET_UPDATE_SNAPSHOTS=1`; the diff must be that one line).
- Tests: `BoundaryItemConformanceTests` pins each clause of the rule; a golden that raises for the first difference cannot say
  which clause did. `>>TURN` in fixed form starts at column 8, and `FUNCTION TRIM` is a 2014 intrinsic (COBOLNET1502 at 2002).
