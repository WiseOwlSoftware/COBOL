# PB1040 — OPEN

## Measured
```cobol
       >>TURN EC-ALL CHECKING ON
       IDENTIFICATION DIVISION.
       PROGRAM-ID. C41OUT.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 R PIC X(5) VALUE "#####".
       PROCEDURE DIVISION.
           CALL "C41IN" RETURNING R
           DISPLAY "[" R "] L=" FUNCTION LENGTH(R)
           DISPLAY "EX=" FUNCTION EXCEPTION-STATUS
           STOP RUN.
       END PROGRAM C41OUT.
       IDENTIFICATION DIVISION.
       PROGRAM-ID. C41IN.
       DATA DIVISION.
       LINKAGE SECTION.
       01 L PIC X(3).
       PROCEDURE DIVISION RETURNING L.
           MOVE "ABC" TO L
           GOBACK.
       END PROGRAM C41IN.
```

prints **`[ABC] L=5`** and `EX=` blank: the receiver's image is three characters wide although FUNCTION LENGTH says 5.

## The rules
- `cite.py --check 14.8.3.3 "the receiving operand shall have the same ALIGN, BLANK WHEN ZERO, DYNAMIC LENGTH, JUSTIFIED, PICTURE, SIGN, and USAGE clauses"` → OK (§14.8.3.3; `PIC X(5)` vs `PIC X(3)` does not conform).
- `cite.py --check 14.9.4.4 "the rules for conformance specified in 14.8.2, Parameters and 14.8.3, Returning items apply"` → `OK §14.9.4.4 3)`: GR3 d)'s violation arm is EC-PROGRAM-ARG-MISMATCH.

## Code site
`src/Cobol.Net.Runtime/Control/CallAbi.cs` `StoreReturn(CobolArg?, string)` — `if (c is ManagedPointer<string> sp &&
r.Num is null) { sp.Value = value; return; }`. No width is consulted.

## What the fixer owes
Carry the receiver's character length on `CobolArg` (PB165's design finding: CobolArg has no byte length today — the
same registry closes both) and, on a mismatch, raise EC-PROGRAM-ARG-MISMATCH per GR3 d); with checking off, store
into the receiver's own width (never change its image width). Sweep the INVOKE RETURNING and function-result arms.
