# PB4215 — a read-only role's Bash command can write inside a git tree

**Sites:** `scripts/hooks/readonly_repo.py` (whole: the hook's matcher and target extraction change to cover Bash and PowerShell commands), the hooks blocks of `.claude/agents/cobol-reviewer.md`, `.claude/agents/cobol-refuter.md` and `.claude/agents/cobol-adjudicator.md`, `scripts/hooks/test_readonly_repo.py` (whole).

## What happens

`readonly_repo.py` is the PreToolUse hook of the READ-ONLY roles (cobol-reviewer, cobol-refuter, cobol-adjudicator). It blocks only Write, Edit and NotebookEdit calls whose target lies inside a git tree. A Bash command that writes inside a tree passes.

## The recorded case (2026-10-31)

The round-3 cobol-reviewer of `worktree-wf_34371f8b-c21-5` ran two `git archive -o` commands that wrote `brfix.tar` and `main6e.tar` into that worktree's root. It moved them out at once, but the guard did not stop it.

## Other shapes that pass the same way

`>` and `>>` redirection, `cp`, `mv`, `sed -i`, git commands that write (`commit`, `checkout`, `stash`, `archive -o`, `worktree add` inside a tree), and `dotnet build` output under the tree.

## Fix shape

Match Bash and PowerShell as well as the file tools, and refuse a command whose write targets resolve inside a git tree: redirects, `-o` / `--output`, the known writing git subcommands, and the destinations of `cp` / `mv` / `rm` / `sed -i`. Builds belong in the scratchpad: a read-only role builds a probe compiler from `git archive` into the scratchpad, never in place. Keep the hook fail-closed on a slow git, as PB3536 requires. Extend `test_readonly_repo.py` with one arm per shape above.
