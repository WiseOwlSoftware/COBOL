# PB4555 — set-index-to-arithmetic-expression-refused: -std=cobol2014: SET index-name TO arithmetic-expression (and SET index-name UP BY arithmetic-expression) is refused ("syntax error, unexpected +")

Filed 2026-11-03 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-batch-3000-20261103`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

cobc 3.2 refuses an arithmetic expression as the sending operand of SET Format 1 (index-assignment): `SET IX TO N + 3` gives "syntax error, unexpected +"; `SET IX UP BY N + 3` (Format 2) gives the same. ISO/IEC 1989:2002, 2014 and 2023 allow arithmetic-expression-1 / arithmetic-expression-2 there. Class: rejects legal source. Fuzz programs: fz00520, fz01226, fz01929 (slice D3).

## Minimal test case

Free reference format.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. SET1.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 N PIC 9 VALUE 2.
01 T.
   05 E PIC 9 OCCURS 9 TIMES INDEXED BY IX.
PROCEDURE DIVISION.
    MOVE "123456789" TO T
    SET IX TO N + 3
    DISPLAY E (IX)
    STOP RUN.
```

## Environment

`cobc (GnuCOBOL) 3.2.0`, WSL2 Ubuntu x86_64. Compiled with `cobc -x -free -std=cobol2014 -o set1.x set1.cob` (the same diagnostics under `-fsyntax-only`); no executable is produced.

## Observed result

Compile, exit code 1:

```text
set1.cob:10: error: syntax error, unexpected +
```

Variant set2 (`SET IX TO 1` then `SET IX UP BY N + 3`): `set2.cob:11: error: syntax error, unexpected +`, exit code 1.

## Expected result (per ISO)

The program is legal and prints `5` (IX refers to occurrence N + 3 = 5, which holds the digit 5).

- §14.9.39.2 (checked): "arithmetic-expression-1". Format 1 (index-assignment): `SET {index-name-1 | identifier-1} ... TO {arithmetic-expression-1 | index-name-2 | identifier-2}`.
- §14.9.39.3 (checked): "If identifier-1 references a data item of class index, arithmetic-expression-1 shall not be specified.". The only restriction on arithmetic-expression-1 concerns an index data item receiver; IX is an index-name.
- §14.9.39.4 (checked): "index-name-1 is set to a value causing it to refer to the table element that would correspond in occurrence number to that expression". General rule 2 a) 1. c.

Edition: 2014. The Format 1 arithmetic-expression-1 operand and the Format 2 arithmetic-expression-2 operand are in the 2002 text (cobolv200112, 14.8.35.1) and in the 2009 draft of 2014 (CD 1.2, 14.9.35.1).

## Our compiler

WiseOwl COBOL (fresh judge, `--std 2014 --source-format free`): compiles with no diagnostic; the run prints `5`, exit code 0 (set2 prints `6`).

## Fix site

`cobc/parser.y`, rules `set_to` (`target_x_list TO x`) and `set_up_down` (`target_x_list up_or_down BY x`): the sending operand is an `x` (identifier or literal), not an arithmetic expression; `cb_emit_set_to` and `cb_emit_set_up_down` in `cobc/typeck.c` would need an expression operand. The two parser.y rules read the same in the 3.2 source; typeck.c was read in the 3.3-dev tree.
