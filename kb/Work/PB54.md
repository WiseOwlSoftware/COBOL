# PB54 — the same reference, two spellings, two answers

> ⚙ **FOUND SWEEPING [[PB50]]'s SIBLINGS, and it is strictly worse than PB50** — PB50 aborts loudly, this one
> returned a wrong answer and kept going.

## ⛔ MEASURED

```
FUNCTION MIN(ZERO + 5, 2)  →  2      ✅ MIN(5, 2)
         MIN(ZERO + 5, 2)  →  0      ⛔ MIN(0, 5, 2) — WRONG ANSWER, no diagnostic
FUNCTION REM(ZERO + 7, 4)  →  3      ✅ REM(7, 4)
         REM(ZERO + 7, 4)  →  ⛔ COBOLNET1504: FUNCTION REM takes 2 argument(s); 3 given
```

**§8.4.3.2 SR2 makes the keyword-omitted form THE SAME REFERENCE** as the keyword form, so these pairs are one
program written two ways. §8.8.1.1 admits "the figurative constant ZERO" as an arithmetic operand and §15.3
admits an arithmetic expression as an argument, so every line is legal source.

⚠ **MIN IS THE DISCRIMINATOR, AND MAX WOULD HAVE HIDDEN IT.** `MAX(ZERO + 5, 2)` is **5** under BOTH readings —
the correct `MAX(5,2)` and the split `MAX(0,5,2)`. My first probe used MAX and passed while the defect was live
([[feedback_probe_the_shape_the_subject_hides]]); the second used values whose two readings differ.

## ▶ ROOT CAUSE — THREE FRAGMENT RE-PARSERS, ONE OF THEM RIGHT

`FunctionArgFragment`, `SubscriptExpressionFragment` and `DirectiveExpressionFragment` each hand-assembled the
same five steps (lex → prime → token stream → parse at an edition → null on syntax error), each with its own
copy of `SyntaxErrorFlag`. **Exactly one applied `ZeroTokenRewriter`**, the pass that turns a figurative `ZERO`
adjacent to an arithmetic operator into the `ZERO_ARITH` token `arithmeticExpression` can match. Without it the
bare `ZERO` ENDED the first argument and `+ 5` began a second.

They now share **`FragmentParse`**, where `rewriteZero` is an **explicit argument with no default** — a new
fragment must answer the question instead of inheriting an answer by omission, which is precisely how both this
and PB50 arose ([[feedback_one_rule_one_place]], [[feedback_two_arm_dispatch]] at three arms).

⚠ **THE PB48 RULE IS PRESERVED, and it was the thing to check before applying the rewriter to an ARGUMENT list.**
A bare `ZERO` argument must keep its figurative identity so the BINDER resolves it by the function's §15.3
argument type (§8.3.3.6.4 GR4 — "depending on context"). It does: the rewriter keys on adjacency to an
arithmetic operator or a PLAIN paren, and a fragment's text is the content BETWEEN its delimiters, so a bare
argument has nothing adjacent. `MAX(ZERO, 3)` is asserted in the golden for exactly this reason.

## ▶ PINNED

`pb54_keyword_omitted_figurative_zero_argument` — six assertions, each keyword/keyword-omitted pair asserted
TOGETHER so the two spellings can never drift apart again, plus the bare-figurative control.
