# PB5370 - land_lane.classify_red calls any merge-group red with no failed test case INFRA, whatever step failed: a branch's own red check step was re-queued once as infrastructure and spent a second merge group

**Sites:**

- `scripts/orchestrator/land_lane.py:827` (`classify_red`)
- `scripts/orchestrator/land_lane.py:843` (`red_facts`)
- `scripts/orchestrator/land_lane.py` (`RedFacts`)
- `scripts/orchestrator/land_lane.py` (`self_test`, which gains the check-step-only arm)

**Mechanism.** PB4271 and PB4331 classify a merge-group red against the branch's gate record from the failed test cases in the run's TRX results (`RedFacts.failed`). `classify_red` returns INFRA when `failed` is empty: "no test failed in merge-group run ...: a job died before or outside its tests". It never reads which step failed. A red verification step with every test passed (`ci_plan.py handed`, a self-test, an audit, the population check) is the branch's own red, not infrastructure, and the INFRA label re-queues it once.

**Evidence (the finisher's report).** PR #1530: merge-group run 43130044782 failed, with 10 shard jobs that end in `##[error]GENERATED BY THE HOST` after passing test steps (`gh run view 43130044782 --log-failed`); `RedFacts.failed` is empty and `classify_red` returns INFRA. The lane re-queued it, and run 43132487649 spent a whole second merge group failing the same way. Only then did the bounce reach a finisher, and still labelled INFRA. Not re-run here; figures are the report's.

**Fix direction (the report's shape).** Read the failed jobs' failed step names (`gh run view --json jobs`). A red step that is not a test-run or setup step is GENUINE (or MERGE when the branch's record shows it green at the same tree); only a runner or setup failure with no named step is INFRA. The set of test-run and setup step names is derived from the workflow file, not hand-kept, with a drift test. Add a self-test arm that plants a run whose only red is a check step.
