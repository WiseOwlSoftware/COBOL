# PB4200 — AddBeforeEffects reverses causes at a tied position and its cross-file arm is untested

**Sites:** `src/WiseOwl.Cobol.Frontend/Diagnostics/DiagnosticBag.cs:61` (`DiagnosticBag.AddBeforeEffects`),
`tests/WiseOwl.Cobol.Tests.Conformance/WordCharacterScreenTests.cs` (`WordCharacterScreenTests`: a new fact for each arm),
`tests/WiseOwl.Cobol.Tests.Unit/DiagnosticBagOrderTests.cs` (`DiagnosticBagOrderTests`: the placement contract on a bag).
The caller is `src/WiseOwl.Cobol.Frontend/Pipeline/Frontend.cs:529` (`Frontend.LexAndParseOnce`, the screen-diagnostics merge).

**R1-1 (the mechanism).** `AddBeforeEffects` documents "a tie in position puts the cause first" and adds causes in the order
given, but its loop compares each new cause against `_diagnostics[i]` with `>= 0` from `from`, so the second of two causes at
the same position meets the FIRST cause it inserted a moment earlier, ties with it, and is inserted before it. Two screen
diagnoses at one position therefore come out reversed: the frontend arm prints a word's diagnoses in the opposite order to
the binder arm (`RunOnTree`). Fix so a cause inserted by this call is never an "effect" (track the insertion point and
advance it past each cause added), then pin the order with a fact that has two causes at one position.

**R1-2 (the missing test).** The cross-file arm (an effect in another file is never compared; the cause goes before the next
same-file effect, or is appended) has no test, because both PB4131 facts compile a single source with no COPY. Add a fact
with a COPY member that holds an effect in another file between the causes' file's effects.

Found by the PB4131 branch review; both were LEADs, low, not blocking at round 1.
