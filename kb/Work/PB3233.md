**Rule it breaks:** ISO 14.9.22.3 SR6 and SR9 (same size unless the REPLACEMENT is figurative) read with SR3 (a figurative literal-1, -2 or -4 "refers to an implicit one character data item"). Sibling arms must agree (dimensions.md section 2).

**Scenario:** Measured on the pin build (src/Cobol.Net.Cli/bin/Debug/net10.0/cobol.dll --run), with 01 X / Y PIC X(6) VALUE "A B C ". `INSPECT X REPLACING ALL " " BY "QR"` is rejected: error COBOLNET0846, SR6. `INSPECT X REPLACING ALL SPACE BY "QR"` breaks the same rule, since SPACE as literal-1 is a one-character item by SR3, yet it compiles clean and runs, and X stays "A B C ": the statement silently does nothing. `INSPECT Y CONVERTING SPACE TO "QR"` (SR9, literal-4 figurative) also compiles clean, and at run time each space becomes Q ("AQBQCQ"). Cause: CheckInspectReplacingSize and CheckInspectConvertingSize (StatementValidation.cs:893-911) return true unless BOTH operands are BoundStringLiteral. InspectBinder passes the figurative flag of the replacement only (InspectBinder.cs:230-237, 263-267) and discards the pattern operand figurative flag, so a figurative or symbolic-character literal-1/literal-4 is never measured as the one character SR3 makes it.

**Measured how:** R2 batch finding `validation-1--code--f1#4` (pair validation-1--code), read in the pinned tree at 8be23006851a; skeptics rule upheld, scenario upheld, site upheld.

**Spec:** §14.9.22.3 "When both literal-1 and literal-3 are specified, they shall be the same size except when literal-3 is a figurative constant, in which case it is expanded or contracted to be the size of literal-1" (`cite.py --check` passed at collection); §14.9.22.3 "If literal-1, literal-2, or literal-4 is a figurative constant, it refers to an implicit one character data item" (`cite.py --check` passed at collection); §14.9.22.3 "When both literal-4 and literal-5 are specified they shall be the same size except when literal-5 is a figurative constant" (`cite.py --check` passed at collection)
