**Rule it breaks:** ISO 14.9.22.3 SR6 and SR9 (same size unless the REPLACEMENT is figurative) read with SR3 (a figurative literal-1, -2 or -4 "refers to an implicit one character data item"). Sibling arms must agree (dimensions.md section 2).

**Scenario:** Measured on the pin build (src/Cobol.Net.Cli/bin/Debug/net10.0/cobol.dll --run), with 01 X / Y PIC X(6) VALUE "A B C ". `INSPECT X REPLACING ALL " " BY "QR"` is rejected: error COBOLNET0846, SR6. `INSPECT X REPLACING ALL SPACE BY "QR"` breaks the same rule, since SPACE as literal-1 is a one-character item by SR3, yet it compiles clean and runs, and X stays "A B C ": the statement silently does nothing. `INSPECT Y CONVERTING SPACE TO "QR"` (SR9, literal-4 figurative) also compiles clean, and at run time each space becomes Q ("AQBQCQ"). Cause: CheckInspectReplacingSize and CheckInspectConvertingSize (StatementValidation.cs:893-911) return true unless BOTH operands are BoundStringLiteral. InspectBinder passes the figurative flag of the replacement only (InspectBinder.cs:230-237, 263-267) and discards the pattern operand figurative flag, so a figurative or symbolic-character literal-1/literal-4 is never measured as the one character SR3 makes it.

**Measured how:** R2 batch finding `validation-1--code--f1#4` (pair validation-1--code), read in the pinned tree at 8be23006851a; skeptics rule upheld, scenario upheld, site upheld.

## Landing (w1096d)

**Re-probe (worktree build, base 1fc8daf67).** `REPLACING ALL SPACE BY "QR"` compiled and printed `A B C `;
`CONVERTING SPACE TO "QR"` printed `AQBQCQ`; a symbolic-character literal-1 (`SYMBOLIC CHARACTERS BLANK-CH IS 33`,
`ALL BLANK-CH BY "QR"`) compiled and printed `A B C `; `ALL " " BY "QR"` drew COBOLNET0846. The note held.
After the fix all three draw COBOLNET0846 at 85, 2002, 2014 and 2023.

**Rule.** §14.9.22.3 SR3 `OK 3)` ("If literal-1, literal-2, or literal-4 is a figurative constant, it refers to an
implicit one character data item"), SR6 `OK 6)`, SR9 `OK 9)`; §12.3.7.4 GR11 `OK 11)` a) "Symbolic-character-1
defines a figurative constant".

**Fix.** SR6 and SR9 are one rule over two pairs: `StatementValidation.CheckInspectLiteralSizes` replaces
`CheckInspectReplacingSize` and `CheckInspectConvertingSize`, and takes each operand as the binder's
`(Op, Figurative)` tuple. `InspectLiteralSize` measures a figurative pattern as one character (SR3), a nonnumeric
literal by its length, and an identifier, function-identifier or refused operand as not a literal (null: GR14 /
GR22's run-time EC-RANGE-INSPECT-SIZE, which already measured a figurative pattern as one character). Only a
figurative replacement is exempt. `InspectBinder.BindPhraseOperands` no longer discards the pattern's flag.

- `src/Cobol.Net.Compiler/Binding/Validation/StatementValidation.cs#CheckInspectLiteralSizes` — the ONE SR6/SR9 size
  rule; `#InspectLiteralSize` is the static-size helper to reuse for any other INSPECT literal-size question.
- `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/InspectBinder.cs#BindPhraseOperands` — pass `InspectCharOperand`'s
  whole tuple for BOTH operands; deconstructing it with `_` was the defect.

**Goldens.** `conformance:85/pb3233_inspect_figurative_pattern_size` (PB3233FP); negatives
`pb3233-inspect-figurative-literal1-size`, `pb3233-inspect-figurative-literal4-size`,
`pb3233-inspect-symbolic-literal1-size` (reject-at 85 2002 2014 2023, COBOLNET0846).
