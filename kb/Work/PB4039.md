# PB4039 — two of the vanished-path fault's five stubs have no arm

## What is missing

`scripts/spec/impact_store.py#vanished_after_the_glob` (added by #734 for PB3807's bounce) makes each named path read
as gone through five calls: `Path.stat` and `Path.lstat` raise `FileNotFoundError`, and `Path.exists`, `Path.is_file`
and `Path.is_dir` answer False. Its docstring gives the reason all five are stubbed: CPython 3.12 routes `exists`,
`is_file` and `is_dir` through `Path.stat`, while 3.14 and later route them through `os.path`. A `Path.stat` stub alone
made a path read gone on 3.12 and present on 3.15, and the merge queue bounced #734 on exactly that.

The arm that pins the fault itself (`impact_store.py` self-test, "a vanished path reads gone through every call on this
Python, its directory present, and is back after", around line 355) reads `mtime(probe)` (which calls `stat`),
`probe.exists()`, `probe.is_file()` and `probe.parent.is_dir()`. No arm reads `probe.lstat()` or `probe.is_dir()`.

## Failure scenario

Someone deletes the `lstat` entry, or the `is_dir` entry, from the tuple of stubbed names. The self-test stays GREEN on
both 3.12 and 3.15. A later arm, or a reader that walks a directory with `lstat` (or asks `is_dir` on a pruned work
directory), then reads the "vanished" path as present on one Python and gone on the other. That is the same
version-dependent split that bounced #734, and the arm meant to catch it would not.

## Fix

- **`lstat`:** inside the block, check that `probe.lstat()` raises `FileNotFoundError`. After the block, check that it
  returns the file's stat again.
- **`is_dir`:** use a DIRECTORY, not `probe`. `probe` is a map file, so `probe.is_dir()` answers False whether or not
  the stub exists. Make a scratch subdirectory of the store vanish too, and check `is_dir()` is False inside the block
  and True after it.
- **Verify the arms.** Each new check must fail with its stub removed, on 3.15 (the manifest's Python, kb/Work PB4007).
