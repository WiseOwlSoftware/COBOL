## R2 batch 1f (pin 9e65164eb3a9): 1 finding on this note

### `codegen-6--architecture--f1#3` (finding, extract, votes upheld/upheld/upheld)

**Finding:** SequentialIoEmitter is also the file-I/O common services (status store, USE hook, RETRY, record-area send and receive channel) of the keyed, communication, messaging, transaction and SORT emitters, which forces the KeyedIo-SequentialIo constructor cycle; DESIGN-architecture-review §8.3 row R0-0031 (PB2326) splits it only per sequential verb

**Rule:** single responsibility per type and acyclic collaborators (DESIGN-architecture-review §5.1; DESIGN-architecture-review §8.3: a decomposition names every concern the type holds); UnitEmitters.cs:12-13 names KeyedIo to SequentialIo as one of the two cycles no construction order satisfies

**Scenario:** KeyedIoEmitter makes about 40 calls into SequentialIoEmitter: EmitStoreFileStatus 6, EmitUseHook 6, RenderRetry 6, EmitInvalid 4, RecordAreaSendImage 3, SentRecordImage 2, Begin/EndReleasedRecord 2 each, EmitNotPhrase 2, and EmitRecordAreaStore, OdoRecordExceedsMaximum, EmitReadLengthStore, LinageArg, plus static RuntimeRecordLock 4 and EmitAreaRegistrations 2. SequentialIoEmitter's constructor takes KeyedIoEmitter for the shared READ/REWRITE bodies, so KeyedIoEmitter.cs:26-29 has to take it back as a null! property. CommunicationEmitter (EmitImageInto 4), MessagingEmitter (EmitImageInto, EmitOutOfLineInto), TransactionEmitter (EmitStoreFileStatus 2, EmitUseHook, EmitImageInto, EmitForeignFileIoCheck) and SortEmitter (about 20 members) take the whole 1554-line sequential verb emitter as a constructor argument for the same services. PB2326's targets (ReadEmitter, WriteEmitter, OpenCloseEmitter, ReleaseReturnEmitter, one per verb leaf) give these shared members no home. The split would therefore either copy them into each new verb emitter, or leave every keyed, communication, messaging and SORT site depending on a ReadEmitter or WriteEmitter peer, with the cycle intact. A change to the record-area channel (kb/Work PB327, PB5217) or to the USE hook (PB3237) edits a type named for one organization's verbs.

**Target:** Amend DESIGN-architecture-review §8.3 row R0-0031 and PB2326 to extract FileIoServices first: EmitStoreFileStatus, EmitUseHook and UseHookResult, RenderRetry, RuntimeRecordLock, EmitInvalid, EmitNotPhrase, EmitPhrasePair, EmitForeignFileIoCheck, VaryingLengthArg, LinageArg, Begin/EndReleasedRecord, EmitAreaRegistrations. Extract RecordAreaChannel beside it: RecordAreaSendImage, SentRecordImage, EmitImageInto, EmitOutOfLineInto, EmitRecordAreaStore, OdoRecordExceedsMaximum, EmitReadLengthStore. Both take only already-built collaborators. The sequential and keyed verb emitters, Communication, Messaging, Transactions and Sort depend on them, not on each other. The KeyedIo.SeqIo back-edge goes, and the shared Format-1 READ that KeyedIoEmitter reaches through SequentialIoEmitter moves into the services or into a ReadEmitter that both organizations call. Every caller changes in the same wave.
