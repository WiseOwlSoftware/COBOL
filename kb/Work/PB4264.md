# PB4264 — a hand-written .tailor weight can take the numeric lead's primary

**Sites:** `src/WiseOwl.Cobol.Runtime/Collation/TailoringRules.cs` (`TailoringRules.ParseWeight`), `src/WiseOwl.Cobol.Runtime/Collation/CLDR/CldrTailoringBuilder.cs` (`CldrTailoringBuilder.Line`), `src/WiseOwl.Cobol.Runtime/Collation/CollationTable.cs` (`CollationTable`; its NumericLead member arrives with PB107's branch, PR #909). The fix: `src/WiseOwl.Cobol.Runtime/Collation/CollationTable.cs` (`CollationTable.WithTailoring`, `CollationTable.RefuseNumericLeadPrimary`), documented in the `TailoringRules.cs` class summary; test `tests/WiseOwl.Cobol.Tests.Unit/Collation/CollationTailoringTests.cs` (`Apply_RefusesAWeightAtTheNumericLeadPrimary`, `Apply_RefusesAWeightAtTheLeadOfTheTailoredZero`).

> LANDED (wave 20261791, group A). Re-probe on the build: a `.tailor` giving U+E000 the primary `Lookup('0').Primary - 1`
> applied with no error and U+E000 carried the numeric lead's primary. Fix at the root: `WithTailoring` reads the PRODUCED
> table's `NumericLead` after the rebuild and refuses an entry whose primary equals it, as a `LocaleCollationException`
> naming the file and the entry's line (kb/Work PB2773's contract), so a `.tailor` that moves the digit zero itself moves
> the reserved value. The CLDR builder arm already keeps the value free (`Line.reservedTop`), so the hand-written arm was
> the only one open. Not a conformance case: no ISO rule governs a `.tailor` file.

A numeric `.tailor` weight written at the value `root - 1` below the digit zero collides with the numeric lead. Nothing
guards it, because the `.tailor` format picks its values by hand (`TailoringRules.cs`). It has the same root as PB107
(numericOrdering): `CollationTable.NumericLead` is the zero's element with primary - 1, and `CldrTailoringBuilder.Line`
reserves the top of each primary gap only for the tailorings it builds, not for hand-written `.tailor` values.

Severity is low and the owner may decline it. Open question left as it stood: `[hiraganaQ on]`
(`CldrLocaleData.cs:228`, `CldrSettings.UnsupportedSettings`). The second lead of that report section, ICU's split of
digit runs past 254 into 254-digit numbers, is covered by PB4223 and is not filed again.
