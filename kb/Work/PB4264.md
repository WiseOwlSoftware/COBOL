# PB4264 — a hand-written .tailor weight can take the numeric lead's primary

**Sites:** `src/WiseOwl.Cobol.Runtime/Collation/TailoringRules.cs` (`TailoringRules.ParseWeight`), `src/WiseOwl.Cobol.Runtime/Collation/CLDR/CldrTailoringBuilder.cs` (`CldrTailoringBuilder.Line`), `src/WiseOwl.Cobol.Runtime/Collation/CollationTable.cs` (`CollationTable`; its NumericLead member arrives with PB107's branch, PR #909).

A numeric `.tailor` weight written at the value `root - 1` below the digit zero collides with the numeric lead. Nothing
guards it, because the `.tailor` format picks its values by hand (`TailoringRules.cs`). It has the same root as PB107
(numericOrdering): `CollationTable.NumericLead` is the zero's element with primary - 1, and `CldrTailoringBuilder.Line`
reserves the top of each primary gap only for the tailorings it builds, not for hand-written `.tailor` values.

Severity is low and the owner may decline it. Open question left as it stood: `[hiraganaQ on]`
(`CldrLocaleData.cs:228`, `CldrSettings.UnsupportedSettings`). The second lead of that report section, ICU's split of
digit runs past 254 into 254-digit numbers, is covered by PB4223 and is not filed again.
