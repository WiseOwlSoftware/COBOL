# PB4148 — one shared inventory file serializes the landings that close rows

The traceability inventory, `tests/version-matrix/traceability-inventory.json`, is one JSON list of 4,214 rows. A fix
that closes a row (its verdict, code location and test reference) edits that file. Two branches closing different rows
merge only through `merge=cobol-keyed-inventory`, which the merge queue cannot run (kb/Work PB3642). So `enqueue.py`
admits one such pull request at a time: 10 holds in the landing lane's logs, the second-largest cause after
`diagnostics.json` (kb/Work PB4147).

The fix is the same principle as PB4147: a row's adjudicated facts live where two different rows never share a file.
Candidates are one file per clause section or per row, with the inventory as a generated view, if the derived
JSON is still needed whole. Choose from `docs/VERSION_TEST_MATRIX_DESIGN.md` and `scripts/spec/build_inventory.py`'s
data flow (the rule catalog -> the inventory -> its burn-down). Acceptance: `.gitattributes` and `merge_drivers.DRIVERS`
no longer name the inventory; two branches closing different rows merge with git's plain merge; a drift test keeps it so.

## Landing

The inventory is one JSON file per row, `tests/version-matrix/inventory/<rule-id>.json` (4,214 files; the rows are byte for
byte the old file's, one object each). `scripts/spec/inventory_store.py` is the ONE reader and writer in Python
(`load_inventory`, `write_inventory`, `inventory_at(rev)`) and `tests/_shared/TraceabilityInventory.cs` the one in C#. Order of
`load_inventory()` is the spec's (section, ordinal, id), where the old file's was the catalog's page order; every consumer keys a
row by `rule-id`. `write_inventory` writes only the files whose text changed and deletes the file of a rule the spec dropped.
`inventory_at(rev)` reads a revision's directory, or the single legacy file `traceability-inventory.json` of a commit before this
landing, because `audit_witness_loss`, `backfill_closes_rows`, `inventory_ratchet` and `gen_ledger`'s trend cross that commit.
The `cobol-keyed-inventory` driver and its `.gitattributes` line are gone, so `covered_by_driver` is False for every inventory
file and `enqueue.driver_file_holders` holds no pull request for it. Two drift tests keep it so:
`SpecTraceabilityInventoryDriftTests.EveryRow_IsItsOwnFile_AndTheDirectoryHoldsNothingElse` and
`MergeDriverDriftTests.TheInventory_HasNoMergeDriver`; `inventory_store.py --self-test` proves the acceptance against git itself
(two branches closing different rows merge with git's plain merge, the SAME row closed two ways conflicts).

For the next implementer: a script that reads or writes the inventory goes through `inventory_store` (never `json.loads` of a
path); a rebuild with `build_inventory.py` is idempotent (0 files changed on an unchanged catalog); `drift_rules.data_files` now
reads every JSON file under a directory a drift test names (the registers that cite tree symbols), so a register kept one row per
file is still governed by `citing`; `constructs.json` is the remaining keyed catalogue and has no note of its own (same root).
