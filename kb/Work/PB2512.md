# PB2512

Filed by the w1033 clerk from the PB1924 decision (`E:\COBOL-coord\scratch\w1033-adj\PB1924-decision.md`, "Leads") and refuter (`PB1924-refute.md`, "New leads"), combined because none is a conformance defect and the
files do not decide the third. Separate defects may be split out when an implementer takes them.

1. **MERGE quote fidelity (cosmetic, harm none).** `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/SortKeyAdmission.cs#Violation` builds the SR4 d) quote from the SORT text ("... elementary item or an item subordinate ..."); `§14.9.24.3 4) d)` prints
   "... elementary item, or an item subordinate ...". The MERGE diagnostic (`PB1924\b_merge_odo_group_2023.log`) misquotes the clause it cites by one comma. Fix: choose the d) text per `SortKeyRules`, as the c) text already does for TableSort. `cite.py` ignores
   punctuation, so the citation check passes and cannot catch it (refuter).
2. **Goldens illegal for a second reason (refuter).** `conformance-suite/cases/14.9.24-MERGE/pb1173-sort-file-key-odo-group.cob` declares `IR PIC X(5)` while SW's largest record is 4 bytes, which breaks `§14.9.40.3 SR5` under either implied RECORD format (`§13.18.43.4 GR5`).
   Probe `golden_pb1173_cntkey` (key changed to the admissible CNT) is still refused with COBOLNET1757, now for SR5: not a false green because the `.err` text ("occurs-depending group item") pins the arm, but the fixture depends on the build checking the key before SR5 and stopping at the first error.
   The same holds for `pb1173-sort-file-key-occurs`, `pb1173-merge-key-occurs`, `pb1173-sort-file-key-boolean` (probes `sib_*_k1`: SD of 2-3 bytes against FD `X(5)`); the pointer variants probably break SR11 instead (not compiled). Fix: size each FD record to its SD record.
3. **Edition 85 unasserted (a MISSING observation, not a negative).** The golden carries `reject-at: 2002 2014 2023`; `CorpusRunnerTests.NegativeCase` asserts only the listed editions, but the build also refuses at `--std 85` (`a_sort_odo_group_85.log`,
   `b_merge_odo_group_85.log`). The repository holds no 1985 text, so whether ISO 1989:1985 carries an equivalent rule is unsettled; if it has none, `SortKeyAdmission`'s ungated d) arm rejects legal 85 source. The refuter recalls (unverified) that the 1985 SORT/MERGE rules bar "variable length items";
   the 85 NIST SORT programs with ODO records (ST137A, ST146A) key only on fixed items ahead of the table, so NIST has no witness. Owed: someone with the 1985 standard settles it; the 85 fixture then gains `85` in `reject-at` or the arm gains an edition gate. Related: `PB1924`.

Owner 2026-10-17: addressed in the SORT and file I/O campaign (kb/Work PB3353).

## Landed (wave 1131 group A)

1. **MERGE quote fidelity: fixed.** `SortKeyAdmission.Violation` picks the d) text per statement: MERGE prints the serial
   comma of 14.9.24.3 4) d), SORT Format 1 does not (14.9.40.3 6) d)); both checked with `cite.py --check`. The golden
   `14.9.24-MERGE/pb1173-merge-key-odo-group` pins the comma in its `expect` and `14.9.40-SORT/pb1173-sort-file-key-variable-group`
   pins the comma-less SORT form (cite.py ignores punctuation, so the goldens keep the quote verbatim).
2. **Second illegality of the PB1173 goldens: fixed.** Eight negatives (`pb1173-merge-key-occurs`, `-merge-key-pointer`,
   `-sort-file-key-boolean`, `-sort-file-key-dynamic-length`, `-sort-file-key-not-in-record`, `-sort-file-key-odo-group`,
   `-sort-file-key-occurs`, `-sort-file-key-pointer`) size their USING and GIVING records to the SD record, so the key rule is
   their only fault: each was re-compiled with its key swapped for an admissible one and compiles clean, and a control with a
   wrong FD size is refused by SR5. The pointer pair uses X(8), `DataItem.PointerByteWidth` (13.18.60.4 GR23: the size is the
   implementor's). A sweep of every other SORT/MERGE negative in `diagnostics.json` found no other SD/FD size mismatch. Added
   the MERGE twins of the SR4 d) shapes that had none (`pb1173-merge-key-odo-group`, `-merge-key-dynamic-length`,
   `-merge-key-variable-group`) and the SORT file `pb1173-sort-file-key-variable-group`.
3. **Edition 85: settled by determination, open to the standard itself.** The repository holds no 1985 text. The arm stays
   ungated (it refused at 85 already) and `85` joins `refuse-at` of both occurs-depending-group goldens; the basis (Micro Focus
   and Veryant references) and the rejected reading are `docs/CONFORMANCE.md` D-SKE.
