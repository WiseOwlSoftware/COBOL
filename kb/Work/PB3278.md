# PB3278 — the code-location resolver matches the member name anywhere in the file

**Mechanism.** `SpecTraceabilityInventoryDriftTests.EveryCodeLocation_ResolvesInTheTree` resolves a `file#Member` code-location with a whole-file word match (`Regex.IsMatch(body, \b<name>\b)` at `tests/WiseOwl.Cobol.Tests.Unit/SpecTraceabilityInventoryDriftTests.cs:665` on origin/main 21ef7293c). A deleted member still "resolves" while its name survives in a comment or a `<see cref>`, so inventory rows point at code that does not exist.

**Witnesses (both verified on origin/main 21ef7293c).**
- Row GR-14.9.51.4-23 names `src/WiseOwl.Cobol.Runtime/IO/SequentialConnector.cs#WriteBeforeAndAfter`, a method kb/Work PB712 deleted. It passes only because the comments at SequentialConnector.cs:1390 and :1399 mention the name. The enqueue-review of worktree-wf_9c1febe0-ebf-19 found it on 2026-10-16.
- Rows GR-12.4.5.11.4-1, GR-12.4.5.11.4-5 and DOC-A.1-151 name `RecordFraming.cs#WritePrefix`. On main it resolved only through a stale `<see cref="WritePrefix"/>` at RecordFraming.cs:62, after `WriteFrameHead` had replaced the member. Branch worktree-wf_9c1febe0-ebf-19 (PB2754) removed the cref, and the rows went red on the Linux landing gate (report `E:\COBOL-coord\scratch\reports\w1092f-PB2754-report.md`, section `## Finisher`).

**Fix shape (fix lane).** Resolve the symbol against declarations (Roslyn syntax, or a declaration-shaped match that ignores comments and doc comments). Re-site every row the stricter check turns red, GR-14.9.51.4-23 at least. Add a drift test proving that a comment-only mention does not resolve. Cross-link PB3131: the same test class runs in leg 2, so the stricter check will also surface late there.

## Resolution (wave 20261770, group A)

**Re-probe on the current tree.** The note's mechanism was written against 21ef7293c, before PB762's resolver landed
(`CodeText`: a C# file's tokens, so a line comment, a doc comment, a `<see cref>` and a disabled region are not code).
On this tree `SequentialConnector.cs` still mentions `WriteBeforeAndAfter` only in comments (lines 1580 and 1589), and
the fixture in `TheseChecks_ActuallyFail_OnAFabricatedInventory` already refuses a comment-only, doc-comment-only and
block-comment-only name. The four claimed rows cite live symbols (`SequentialConnector.cs#Write`, `#WriteAdvancing`,
`RecordFraming.cs#EncodeFrameHead`, `#ReadFrame`, `#EncodeFrame`) and resolve. So the comment/cref half is DISCHARGED
by PB762.

**What was still weak, and is fixed.** A dotted symbol was split into segments and each segment searched anywhere in
the file's tokens, so `Type.Member` resolved when `Member` belonged to ANOTHER type of the same file. The resolver now
walks the file's declarations (Roslyn) and a dotted name must be a declared qualified-path suffix (`Live.Run`,
`N.Live.Run`). All 33 dotted spellings in the inventory resolve under it. **Measured and rejected:** requiring a SIMPLE
name to be declared in the file (not merely used) turns 39 locations (81 rows) red, every one a row that cites the file
that USES a symbol declared elsewhere; a use cannot go stale without the build breaking, so those rows are correct and
the simple-name rule stays PB762's.
