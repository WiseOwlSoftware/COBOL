# PB3958 — under --permissive, a program that declares a word the target edition has removed (AUTHOR, ALTER) and also writes the removed construct gets a parse error instead of the COBOL0902 warning

**Sites:** `src/WiseOwl.Cobol.Frontend/Grammar/CobolParserCore.g4` (`authorParagraph`), `src/WiseOwl.Cobol.Frontend/Grammar/CobolControlFlow.g4` (`alterStatement`), `tests/version-matrix/cobol-words.json`

At 2002 and later under `--permissive`, a program that declares a word the edition removed (for example AUTHOR or
ALTER) and also writes the removed construct gets a parse error, not the COBOL0902 warning, because those keyword positions
spell the bare token. It is a diagnostic-quality defect (not legal source at any edition). Same root as PB3794: the fix is
`keywordWhereFree` rows in `cobol-words.json` for those words, generated by `gen-cobol-words.ps1` step 5c, never a hand rule.

## Acceptance
- A `keywordWhereFree` row per removed word the grammar spells bare (AUTHOR and the other obsolete-paragraph words, ALTER),
  the drift test `CobolWordsDriftTests` seen RED without them, a `--permissive` golden per word.
