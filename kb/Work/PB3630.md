# PB3630 — a refused retake leaves a kept handle with no file; ROLLBACK/COMMIT answer 30

Filed 2026-10-24 by the clerk from `E:/COBOL-coord/scratch/reports/w20261028b-PB3497-report.md`, "New defects" (wave 20261028,
landed as PR #489). Related: PB3497 (the not-retaken arm witness), PB3501. Not re-probed by the clerk; the repro is the report's
measurement. No existing note covers it (grepped kb/Work).

**Witness (measured by the PB3497 implementer).** In the PB3497 test, after the refused retake, calling `a.Rollback()` before the
re-OPEN returns "F" and status `30` with EC-I-O-PERMANENT-ERROR, on a healthy medium. The kept state still has its handle, but its
store has no file, so the commit/rollback path refuses.

**Rule.** ROLLBACK §14.9.36.4 GR3 (restore the files in active APPLY COMMIT clauses to their state at the last COMMIT) and COMMIT
§14.9.7.4 GR3 (permanently apply the changes, release the record locks). Both rule numbers pass `cite.py --check` at the clause
level (14.9.36.4 and 14.9.7.4, General rules); the text of each GR3 was read in `specs/ISO_COBOL.md`. Neither rule makes the
statement fail because an earlier retake was refused. Status 30 on a healthy file is a wrong answer.

**Fix shape (the report's, not adjudicated).** Re-adopt the store (it needs `HoldingsOrder`) when `File` is null and a writable
handle is attached, so Commit/Rollback do not refuse.

**Sites:**
- `src/WiseOwl.Cobol.Runtime/IO/KeptFile.cs` (CommitTransaction, RollbackTransaction)
- `src/WiseOwl.Cobol.Runtime/IO/KeyedStore.cs` (Commit, Rollback)
- `tests/WiseOwl.Cobol.Tests.Unit/Store/CommitRollbackRuntimeTests.cs` (the PB3497 witness to extend)

## Landed

Re-probed on this build: `CommitRollbackRuntimeTests.A_commit_or_rollback_after_a_refused_retake_reaches_the_file_the_close_kept`
(six of its eight rows) failed with ROLLBACK and COMMIT answering `F`/`30`. Fix: `KeyedStore.AdoptAgainForTransaction` adopts the
file again through the store's writable handle (under the store mutex) before `Commit`'s promotion and `Rollback`'s restore, so the
PB3497 state (handle kept, store without a file) is reached by both statements; a medium that still refuses answers `30`. Both
callers (`KeptFile.CommitTransaction`/`RollbackTransaction` and `KeyedConnector`'s own) pass the holdings order; `Open` and the new
step share `KeyedStore.Adopt`. For the next implementer: `KeyedStore.AdoptAgainForTransaction` is the one place a store with a
standing transaction and no file re-adopts; reuse it for any new statement that must reach such a store. Design doc:
DESIGN-runtime-library.md 2.2.1.10.
