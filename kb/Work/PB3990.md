`cite.py --check 14.7.4.3 "the content of the resultant identifier is unchanged"` -> OK §14.7.4.3 7): "If the
PROHIBITED phrase is specified, and the arithmetic value cannot be represented exactly in the resultant identifier, the
EC-SIZE-TRUNCATION exception condition is set to exist, the size error condition exists, and the content of the
resultant identifier is unchanged."

Observed (the reviewer's probe on main's behaviour, the statement written with no SIZE ERROR phrase): `D5 PIC 99`
binary with `VALUE 7`, `COMPUTE D5 ROUNDED MODE IS PROHIBITED = V` with V = 1.5 leaves D5 = 01; GnuCOBOL 3.2 prints 07,
as rule 7 requires. The same arm, reached from a NOT-only statement on worktree-wf_5cf68b99-205-1 (an attempt, not to land, to follow
GnuCOBOL's COMP-5 exemption, which the owner ruled GnuCOBOL's error, PB3989), gave 001, 008 and 044 for the
COMPUTE, ADD and wider COMPUTE variants (its review R1-1). The fix: an inexact PROHIBITED
value never reaches a store; sweep every store arm (fixed-point, binary, edited, float) and every statement (ADD,
SUBTRACT, MULTIPLY, DIVIDE, COMPUTE) for it, with goldens derived from rule 7.

## Every usage, and the determination it overturns (round-3 review lead R3-1, 2026-10-28)

The truncation is not confined to a binary receiver. With no SIZE ERROR phrase and checking off, `COMPUTE x ROUNDED MODE
IS PROHIBITED = V` (V `PIC 9V9 VALUE 1.5`, each x `PIC 99` with `VALUE 7`) gives D5 (COMP-5) = 001, DD (DISPLAY) = 01 and
DB (COMP) = 01 on main; GnuCOBOL 3.2.0 gives 007, 07 and 07. Main truncates ON PURPOSE: `docs/CONFORMANCE.md` DOC-A.1-70's
PB1196 paragraph ("ROUNDED MODE IS PROHIBITED with checking NOT enabled and no SIZE ERROR phrase ... the resultant
receives the TRUNCATED value") records it as the §14.6.13.1.3 item-8 determination, and the last leg of golden
`14.7.4-ROUNDED/pb1196_float_resultant_rounded_mode` (F1 UNCHECKED) expects it. Rule 7 says the receiver is unchanged, and
even read as item-8 latitude CLAUDE.md rule 1 picks GnuCOBOL, which keeps it. So the fix reverses that determination,
changes the pb1196 golden's unchecked leg with it, and fixes every usage, never the binary arm alone.

## Landed (wave 20261740 group A, branch `worktree-wf_0c0f6eee-9f8-1`)

Re-probed on main 1da5e0d6b (`E:/COBOL-coord/scratch/w20261740a/p3990a.cob`, `p3990s.cob`; GnuCOBOL 3.2 beside them): no
phrase, checking off, every receiver (DISPLAY, COMP, COMP-5, COMP-3, Z9, Z9.9, COMP-1, +9.9E+99) and statement (COMPUTE,
DIVIDE GIVING, MULTIPLY GIVING, ADD TO, a COMP-2 sender, an outermost quotient) stored the value cut (D5=01, C5=001, N5=03,
X5=02, A5=08, FS=0.099999994); under STANDARD-DECIMAL the same statement TERMINATED the run unit (EC-SIZE-TRUNCATION),
because the SDIDI's rounding table always raised and nothing caught it. GnuCOBOL keeps every fixed-point receiver (07).

**Fix (one mechanism).** PROHIBITED is never a rounding direction: the two one-rounding-decision tables
(`CobolNum.BumpsMagnitude`, `CobolDec.RoundFromRemainder`), `FloatResultant`'s unchecked entries and
`CobolEdit.FormatFloatStore` raise the one `CobolSizeError.ProhibitedInexact()` (EC-SIZE-TRUNCATION, `IsProhibitedInexact`)
whether or not the landing is checked; a Try form answers false. Under a phrase or EC-SIZE checking the statement's own
catch takes it; with neither, `ArithmeticEmitter.KeepsOnProhibitedInexact` wraps a PROHIBITED receiver's compute-and-store
(and its object-property accessors) in a try that catches that condition alone, so the receiver is unchanged and the
statement continues. Deleted as redundant: `CobolNum.DivideOrThrow` (+ `DivisionLosesPrecision`, its past-the-carrier test
moved into `Divide`), PB654's StoreArith gate (`CobolFloat.InexactAtScale`, `RuntimeApi.FloatInexactAtScale`), the
`checkedLanding` gate in `FromDouble`, the `checkedTransfer` mask in `TransferWide`. DOC-A.1-70's PB1196 determination is
reversed. After: 07 everywhere in both lanes; an exact value lands (2.0 -> 02); exact but too big keeps the low-order digits
(150 -> 50, GnuCOBOL's); inexact and too big is unchanged (150.5 -> 07).

**Witnesses.** Golden `14.7.4-ROUNDED/pb3990_prohibited_unchecked_keeps_the_resultant` (2014, 2023); `pb1196`'s unchecked
leg now 5.00000000000; `SizeErrorDispositionTests.Prohibited_CheckingOff_NoPhrase_KeepsTheResultantOnAnInexactValue` (24
rows, both lanes); kernel tests restated (`FloatResultantTests`, `CobolWideTests`, `WideTransferKernelTests`,
`CobolEditFloatRoundingTests`, `CarrierLandingFormTests`, `ArithmeticOneInitialEvaluationDriftTests` invariants 2-3).
GnuCOBOL 3.2 differs on two rows ISO decides: it keeps 07 for the EXACT 2.0 and stores 0.1 into a COMP-1.
