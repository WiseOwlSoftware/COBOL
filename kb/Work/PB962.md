## Reproduced

`scratchpad/reg10/goback_dyn2.cob`: the caller `CALL "W45BGS2" RETURNING RES` with `01 RES PIC 9(3)`. The callee
has `01 D PIC X DYNAMIC LENGTH LIMIT IS 3` (currently empty), `LINKAGE 01 R PIC 9(3)`,
`PROCEDURE DIVISION RETURNING R`, and does `MOVE D TO R` then `GOBACK`.

```
abnormal run-unit termination: RETURNING delivery: the character result "   " has no conforming store into the
activating element's RETURNING item (carrier ManagedPointer`1) — ISO §14.8.3.3 requires the same PICTURE and USAGE
clauses; §14.9.4.4 GR3d — EC-PROGRAM-ARG-MISMATCH
rc=1
```

Controls on the same build: `MOVE 123 TO R` delivers `RES=[123]`, and `MOVE "12A"`-valued PIC X(3) sender delivers
`RES=[012]` (no abort, and that value was not adjudicated here). Only a content that does not parse as a number aborts.

## Rules

- `cite.py --check 14.9.4.4 "If a RETURNING phrase is specified, the result of the activated program is placed into identifier-3."` → `OK §14.9.4.4 4)`
- `cite.py --check 14.8.3.1 "The returning item in the activated element is the sending operand, the corresponding returning item in the activating element is the receiving operand."` → `OK §14.8.3.1`
- `cite.py --check 14.8.3.3 "If the sending operand is not an object reference, the receiving operand shall have the same ALIGN, BLANK WHEN ZERO, DYNAMIC LENGTH, JUSTIFIED, PICTURE, SIGN, and USAGE clauses"` → `OK §14.8.3.3` (the non-object-reference conformance sentence)

R and RES are both `PIC 9(3)` USAGE DISPLAY, so the pair CONFORMS, and GR4 requires the result to be placed into
identifier-3. The abort cites §14.8.3.3 against a pair that §14.8.3.3 admits. **Expected:** `RES=[   ]`, meaning the
callee's returning item content is transferred as it stands (compare §14.2.3 GR8's same-storage model for
arguments). **Observed:** a fatal EC-PROGRAM-ARG-MISMATCH.

## Mechanism

`src/Cobol.Net.Runtime/Control/CallAbi.cs` `StoreReturn(ManagedPointer?, string)` (≈ line 553). The string leg
does `Int128.TryParse(value.Trim())`, then `double.TryParse`, then `Undeliverable(...)`. The design comment says a
cross-carrier pair "can only arise from source §14.8.3.3 already declares non-conforming". That premise is false:
here the carriers differ (a string result into a numeric-cell ManagedPointer) while the COBOL descriptions are
identical, so the carrier shape is not the conformance test. A value conversion cannot be the delivery for a
same-description pair. It must be a content transfer.

## What the fixer must do

1. Decide conformance from the DESCRIPTIONS (bind time already knows both), not from whether the runtime text parses.
   Deliver a conforming elementary pair by content: image in, image out, for every numeric USAGE (DISPLAY, COMP-3,
   binary), mirroring `FormatImage`/`StoreImage`. Reserve EC-PROGRAM-ARG-MISMATCH for a pair that really does not
   conform (§14.9.4.4 GR3d).
2. Sweep the sibling deliveries: `StoreReturn(…, long/Int128/UInt128/double)`, INVOKE … RETURNING, function-prototype
   RETURNING, and EXIT PROGRAM / GOBACK / fall-off-the-end (group B measured that the GOBACK form is not needed to fail).
   PB615 is the neighbouring degrade-to-ZERO mechanism on the ARGUMENT side of the same ABI. Take both together.
3. Golden at 2002 with the zero-length sender replaced by a 2002-legal source of a non-digit image in a numeric
   item (for example a REDEFINES write), plus the 2023 dynamic-length form above.
4. The upstream question of whether `MOVE <empty dynamic-length item> TO <PIC 9(3)>` should leave spaces belongs to
   the PB887 / MOVE-validity family. This note owns the delivery, whatever the content.
