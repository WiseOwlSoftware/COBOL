# PB92 — LANDED 2026-08-18 — `SET LOCALE LC_ALL TO USER-DEFAULT.` drew "'LOCALE' is not defined" + two false 0901s; `SET X TO LOCALE LC_ALL.` was `unexpected '.'`

**Landed (2026-08-18, DEVLOG 1314):** `setLocaleStatement : SET {setLocaleAhead()}? cobolWord cobolWord TO dataReference |
SET dataReference TO {saveLocaleAhead()}? cobolWord cobolWord`, listed FIRST in `setStatement` (predicated on the
LOCALE word + a locale category / LC_ALL / USER-DEFAULT, edition-gated 2002+ like `localeClauseAhead` — at '85 the
words are user words and `SET LOCALE TO 5` over an integer item named LOCALE stays Format 1, pinned); `SetBinder.BindSet`
emits ONE COBOLNET1518 naming the format and returns a Nop; the two keyword words are exempt from the §8.9 funnel
(PB27's shape). Measured: negatives `pb92-set-locale-format-11` / `-12`, `SetLocaleDispositionTests` (five shapes → exactly
one 1518; the '85 user-word control). Nine verdicts (SR-14.9.39.3-25/-26, GR-14.9.39.4-21…-27) → DOCUMENTED-NON-SUPPORT
(GAP 3989 → 3980). CONFORMANCE.md §4 item 5: every locale entry point is now recognized and rejected by name.

> ⚙ **flags:** rejects-legal-source — legal COBOL (with the optional locale module) that this processor may reject

> statement about the source, which is not that (the same flagging as [[PB78]]'s CHARACTER CLASSIFICATION half);
> found 2026-08-18 sweeping [[PB78]]'s siblings (CONFORMANCE.md §4 item 5 named these two as parse errors).

**Measured** (`--std 2023`): Format 11 `SET LOCALE LC_ALL TO USER-DEFAULT.` → `COBOLNET1639: 'LOCALE' is not defined`
+ `COBOLNET0901: 'LOCALE' is a reserved word … cannot be used as a user-defined word` + the same for USER-DEFAULT —
three false statements about source that uses the words as the standard's own keywords. Format 12 `SET X TO LOCALE
LC_ALL.` → `COBOL0001: unexpected '.'`. Formats 11 (set-locale: `SET LOCALE {LC_ALL|LC_COLLATE|LC_CTYPE|LC_MESSAGES|
LC_MONETARY|LC_NUMERIC|LC_TIME | USER-DEFAULT} TO {identifier-10 | locale-name-1 | USER-DEFAULT | SYSTEM-DEFAULT}`)
and 12 (save-locale: `SET identifier-11 TO LOCALE {LC_ALL | USER-DEFAULT}`) are Annex A.4.9 item 9 of the optional
locale module COBOL.NET does not provide; the conformant disposition is the LOCALE clause's / CHARACTER
CLASSIFICATION's: recognize the shape, reject with COBOLNET1518.

**Mechanism:** the SET grammar has no locale arm; LOCALE is not a lexer token (a plain word, reserved 2002+ by §8.9),
so `SET LOCALE LC_ALL …` binds as a generic SET of a data reference named LOCALE. **Fix shape:** two predicated arms
in the SET statement (`SET {localeSetAhead()}? cobolWord (LC_word | cobolWord) TO (…)`, `SET dataReference TO
{localeAhead()}? cobolWord (LC_ALL | USER-DEFAULT word)`), the binder emitting 1518 for both, the words exempt from
the 0901 funnel as the LOCALE clause's are (PB27), two negatives, CONFORMANCE.md §4 item 5 updated to "all locale
entry points named". Below 2002 LOCALE / LC_* are ordinary user words, so the predicates are edition-gated exactly
like `localeClauseAhead()`.
