# PB1944 — OPEN

Filed by the train-1007 lander. Train 1007's first CI run (37144040186, head faeec1f0e) went red on every Windows job
at "Build (Release, warnings-as-errors)" / "Build the conformance project (Release)"; the Linux jobs and both local
gates (Windows lander gate run 20261003T181309Z-e5c55f, Linux gate on 78aedf7a0) were green on the same tree.
Cluster D ([[PB1402]]) was dropped from the train for it.

## Defect

`src/Cobol.Net.Frontend/Grammar/Core/CobolLexer.g4:1070` (PB1402's branch) reads
`fragment EXT_CHAR : ~[\u0000-\u007F<U+FDD0>-<U+FDEF><U+FFFE><U+FFFF>] ;` with the four noncharacters written as RAW
UTF-8 bytes (the `﷐`-style escapes were decoded by the agent's tool input — the known harness behavior in
memory `tool_input_unicode_escapes_decoded`). ANTLR read the file as Cp1252 on the Windows runner, each three-byte
sequence became three Latin characters, and the set repeated characters: `warning(180): CobolLexer.g4:1070:22: chars …
used multiple times in set`. `Invoke-Antlr4CSharp.ps1` treats any ANTLR warning as a failure (correctly), so the
Frontend build failed. Locally `java -XshowSettings:properties` reports `file.encoding = UTF-8` (Java 23, JEP 400),
so the same file generates cleanly — the local gates cannot see this class of failure.

## Fix shape

1. `src/Cobol.Net.Frontend/Invoke-Antlr4CSharp.ps1#Invoke-AntlrStep`: pass `-encoding UTF-8` to the ANTLR tool, so the
   grammar's encoding never depends on the JVM default (the root cause; every runner then reads what the repo holds).
2. A drift test over `src/Cobol.Net.Frontend/Grammar/**/*.g4`: no non-ASCII character outside a comment — a code
   point in a lexer set is written as a `\uXXXX` escape (a reviewer cannot see a raw noncharacter, and the escape is
   what the ANTLR documentation uses).
3. PB1402's relanding writes EXT_CHAR as `~[\u0000-\u007F﷐-﷯￾￿]` (escapes typed so the tool does
   not decode them, e.g. built by a script from code points).

## Repro

Check out PB1402's branch (`worktree-wf_a08557c7-e3e-4`, head 0753cca0e) and run the ANTLR step with
`java -Dfile.encoding=Cp1252 -jar ... CobolLexer.g4`: warning(180) at 1070:22.
