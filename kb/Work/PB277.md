# PB277 — LANDED 2026-08-31

## The defect

Every `Build and Test` run since `66615f70` (the PB209 landing) failed on BOTH platforms' "Greenfield unit
tests" step — 2 failed / 5141 passed, always the same two:
`ExternalCorpusPopulationDriftTests.TheCensus_NamesEveryPopulationAndItsProgramCount` and
`SweepExternalPopulation_EqualsTheDifferentialsCommittedCaseCount`, with
`POPULATION BAD  EXTERNAL POPULATION ABSENT - no corpus at tests/external/gnucobol/tests/testsuite.src`.

Root cause is a DOCTRINE COLLISION, not a code bug. The corpus is GPL-3.0 and deliberately never committed
(`.gitignore:68-72`'s licensing block; `scripts/fetch-gnucobol-tests.ps1` fetches on demand). PB209's gate was
built on the never-skip rule — a population it cannot see must be a FAILURE, because a silent zero is exactly
the defect PB209 registered. Both rules are right; together they made CI structurally red: every CI checkout
lacks the corpus by policy, so the gate could never pass there. Local batteries stayed green (the corpus is
present locally), which is why five pushed landings sailed past it — battery.sh is not a superset of CI
(plan §0's own caution), and nobody read the CI verdicts until the owner did.

The fetch script's doc still carried the PRE-PB209 contract ("the adapter SKIPS with a loud notice"), which
the drift gate had silently superseded — the sentence is corrected in this change set.

## The fix (root cause, both jobs)

CI now runs the fetch script's on-demand contract itself: a `Cache GnuCOBOL testsuite tarball` step
(actions/cache keyed `gnucobol-tests-3.2-3bb48af4`) plus a `Fetch GnuCOBOL testsuite` step
(`pwsh ./scripts/fetch-gnucobol-tests.ps1` — pinned 3.2, sha256-verified, extract-only-tests) inserted before
the unit-test step in BOTH failing jobs (`greenfield-unit` Linux and `windows-build-test`). The gate then
measures the real 1,323-case population everywhere; on a cold cache with the GNU mirror down, the FETCH step
fails — an honest infrastructure red, never a silent skip and never a green that looked at nothing. Nothing
GPL is committed: the tarball lives only in the runner's cache, exactly as it lives only on dev disks locally.

## Residue

- The isolated earlier failure at `a3053400` (recovered by `d4e93d6b`) was not investigated (quota-paused

- Process lesson recorded: a landing whose new gate has an environment precondition must state where the
  precondition holds — the PB209 landing declared "missing python or absent corpus is loud, never a skip"
  without asking where absence is POLICY. The green-earned rule now has a platform axis.
