# PB325 — EXTEND diverts a random-access connector into the sequential branch

**Rows:** `GR-14.9.27.4-8`.

## The program

`<lane3 scratch>/out-b1/probe/table20-random-extend/p.cob` — `ORGANIZATION IS RELATIVE`, `ACCESS MODE IS
RANDOM`, `RELATIVE KEY IS R-KEY`; seed via OPEN OUTPUT, CLOSE, then OPEN EXTEND and WRITE.

## The rule

§14.9.27.4 GR8's Table 20 gives WRITE an X for the Random and Dynamic access rows only under the Output and I-O
open modes; **the Extend column is blank**. §9.1.13.7 item 8 b) names the status for the blank cell:

> If the access mode is dynamic or random, the file connector is not open in the I-O or output mode.

`--check 9.1.13.7 "If the access mode is dynamic or random, the file connector is not open in the I-O or output
mode"` → **OK**. I-O status '48'.

## What the compiler does

`OPEN EXTEND` = '00' and the following WRITE = '00'. `RelativeConnector.Write` (line 267) and
`IndexedConnector.Write` (line 342) choose the sequential-access branch with
`_access == FileAccessMode.Sequential || Mode == FileOpenMode.Extend`; the `|| Mode == Extend` disjunct diverts a
random-access connector into a branch that then only screens *Output or Extend*.

**The state is reachable because §14.9.27.3 SR2 is enforced nowhere** — no source file in `src` cites it — which
is **PB318**.

## The fix shape, in two parts

1. Enforce SR2 at bind (**PB318**), which also closes its LINAGE conjunct.
2. Make the WRITE branch selection depend on the ACCESS MODE alone, so a mis-opened connector still gets item
   8 b)'s '48'. A branch predicate that consults the open mode is what let one unenforced syntax rule turn into
   a wrong answer; removing the disjunct makes the runtime correct independently of the binder.

**Code sites:** `RelativeConnector.cs#Write` (line 267) · `IndexedConnector.cs#Write` (line 342).

## 2026-09-05 — Landed

**The branch predicate now reads the ACCESS MODE alone**, in both keyed connectors, and the fact it reads
lives in ONE place: a new abstract `KeyedConnector : FileConnector`
(`src/Cobol.Net.Runtime/IO/KeyedConnector.cs`) carries `Access` (and the `KeyedAccess` enum moved there from
`RelativeConnector.cs`), with the invariant on the type: **the OPEN MODE never SELECTS a keyed verb's
branch; it is only ever SCREENED.** Every branch the standard draws inside a keyed verb is drawn on the
access mode — §14.9.51.4 GR29 a)/b), GR38/GR39, §14.9.35.4 GR5 vs. GR21/GR22/GR23, §14.9.10.4 GR2 vs.
GR3/GR4 — and the open mode enters only as Table 20's permission test, whose own item-8 arm is itself
chosen BY the access mode. `RelativeConnector.Write` and `IndexedConnector.Write` open with
`bool sequentialRelease = Access == KeyedAccess.Sequential;`; the six sibling `_access ==` tests in the two
connectors were rewritten onto `Access` with their own citations.

**Probe, on this tree's own `cobol.exe`** — relative×random, relative×dynamic, indexed×random and
indexed×dynamic each seeded, closed, reopened EXTEND and written: `00` before, **`48` after**, on all four.

**Table 20 was read from the PDF (page 709)**, not only from the transcription: the load-bearing signal is a
BLANK CELL and an OCR'd blank is not self-evident. The rendered table confirms the Markdown — Random×WRITE
and Dynamic×WRITE carry X under Output and I-O only.

**Part 1 of the fix shape was NOT needed for correctness and was not done here.** The note proposed
enforcing §14.9.27.3 SR2 at bind first (**PB318**, still open). Doing part 2 alone is what the note asked
for and is the stronger half: the runtime now answers item 8 b) whether or not any bind-time screen holds.

**Evidence.** `conformance:2023/l1_table20_seq_relative` and `conformance:2023/l1_table20_indexed` walk
EVERY cell of Table 20 reachable from conforming source (139 observations over sequential, relative and
indexed organizations × three access modes × four open modes × READ/WRITE/REWRITE/START/DELETE RECORD);
every expected value is derived from Table 20 plus §9.1.13.7 items 7/8/9, and every one was observed — no
other cell of the table diverges. `conformance:negative/pb325-start-random-access` pins the blank
Random×START row on both keyed organizations at all four editions (COBOLNET0862, §14.9.41.3 SR1).
`unit:Table20WriteOpenModeTests` (12 facts) reaches the cell no golden can, because §14.9.27.3 SR2 makes
EXTEND-on-random illegal source: its four defect facts go RED with the disjunct restored (measured) and its
eight control facts stay green.

`GR-14.9.27.4-8` recorded **CONFORMS** (batch `pb325-table20-write-open-mode`; GAP 2830 → 2829).
`docs/COBOLNET_FILES_DESIGN.md` carries the invariant as a design bullet.

**Residue, filed against PB318, not here:** `OPEN EXTEND` on a random- or dynamic-access connector still
COMPILES. It is now inert at run time — the WRITE that follows is '48' — but SR2 says the source is
illegal and nothing says so.
