# PB350 — a RETURN loop that never terminates from the statement

**Rows:** `FMT-14.9.34.2` (shared with **PB351**, a second, independent defect in the same format row).

## The programs

`<lane3 scratch>/out-b1/probe/p1/p1.cob` — the OUTPUT PROCEDURE body is
`RETURN SF RECORD END-RETURN. DISPLAY "R=" S-TXT. ADD 1 TO WS-N. IF WS-N < 4 GO TO DUMP-1.`
`<lane3 scratch>/out-b1/probe/p2/p2.cob` — `RETURN SF NOT AT END DISPLAY "R=" S-TXT END-RETURN.`

Both compile clean at `--std 85, 2002, 2014 and 2023` (exit 0, no diagnostic). `p1 --run` prints
`R=ONE / R=TWO / R=TWO / R=TWO` — at end-of-data the record area keeps the previous record and control falls
through, so a program that loops on RETURN never terminates its loop from the statement.

## The rule

§14.9.34.2, rendered from the printed page 738 (folio 708):

```
RETURN file-name-1 RECORD [ INTO identifier-1 ]
    AT END imperative-statement-1
    [ NOT AT END imperative-statement-2 ]
    [ END-RETURN ]
```

**The AT END line is printed with NO brackets and NO choice indicators** — unlike READ (§14.9.30.2), whose
transcription figure note records the printed bar pair. Per §5.2.6.2 brackets are the only thing that makes a
portion omissible, and per §5.2.2 an underlined keyword is required subject to those conventions, so **the AT END
phrase is MANDATORY on every RETURN**. §14.9.34.3 SR4 permits reversal only *when specified*, which does not make
AT END omissible. Both programs shall be rejected at compile time, with a named diagnostic, at all four editions.

## What the compiler does

`CobolIO.g4:679` writes `returnAtEndPhrase?` and `:690`'s second alternative writes
`NOT AT? END statementBlock (AT? END statementBlock)?`, so both the whole phrase and the AT END half of the
reversed pair are optional. `SortBinder.BindReturn:268-273` binds `atEnd = null` without complaint
(`PhraseBlocks.Split` maps a NOT-led single block to `(null, first)`) and `SortEmitter.EmitReturn:177-180` emits
an empty `else` arm. A grep for `returnAtEndPhrase` over `src` finds `SortBinder.cs:269` as the SOLE consumer, so
no later pass recovers the rule.

## The fix, and the sibling that must NOT change with it

The fix belongs in the grammar — make the phrase required, with the reversed alternative requiring both halves —
plus a negative conformance case per edition. ⛔ **`readAtEnd` must not be changed:** READ's AT END really is
optional, and that asymmetry is the whole point of measuring the two pages separately.

**Code sites:** `CobolIO.g4#returnStatement`, `#returnAtEndPhrase`.

## Landed 2026-09-05 — COBOLNET1850, a bind-time screen, not a grammar change

**Re-probed first.** The note was written against an older tree, so both programs were rebuilt on this
worktree's own `cobol.exe` before anything was changed. `RETURN SF RECORD END-RETURN.` and
`RETURN SF NOT AT END DISPLAY … END-RETURN.` still compiled clean at `--std 85, 2002, 2014 and 2023` (exit 0,
no diagnostic), and the first still printed `R=ONE / R=TWO / R=TWO` — past end of data the record area kept the
previous record and control fell through the statement. The note held on today's tree in every particular.

**The page was rendered, not read from the transcription.** `python scripts/spec/clause_page.py 14.9.34.2`
→ PDF page 738, printed folio 708; `python scripts/render-spec-page.py 738`. The printed format is

```
RETURN file-name-1 RECORD [ INTO identifier-1 ]
    AT END imperative-statement-1
    [ NOT AT END imperative-statement-2 ]
    [ END-RETURN ]
```

with `RETURN`, `INTO`, `END`, `NOT`, `END-RETURN` underlined and `RECORD`/`AT` not. The AT END line carries no
bracket and no choice indicators while the two lines under it are bracketed — so the transcription is faithful
and the phrase is MANDATORY (`cite.py --check 5.2.6.2` and `--check 5.2.2` both OK; `--check 14.9.34.3` confirms
SR4 permits REVERSAL, never omission).

**The fix is in the binder, and that is a decision, not a shortcut.** `StatementValidation.ScreenOmittedRequiredPhrase`
— the mirror of `ScreenForbiddenPhrase`/COBOLNET1720, one descriptor carrying the SHAPE with each call site
quoting its own § — raises **COBOLNET1850** from `SortBinder.BindReturn`. Two reasons the grammar keeps
`returnAtEndPhrase?` (with a comment saying so):

- a bind-time diagnostic NAMES the omitted phrase, the statement and the clause; an ANTLR parse error can only
  report an unexpected token, and on the SR4 reversed spelling it would fail mid-alternative;
- the screen tests `atEnd is null` **after** `PhraseBlocks.Split` has normalized position away, so ONE test
  covers BOTH grammar arms. Screening `returnAtEndPhrase() is null` instead would have left the reversed
  NOT-only arm compiling — the two-arm dispatch with one arm fixed, this repo's most reproducible defect shape.

It is a hard ERROR at every edition, deliberately NOT routed through `EditionContext.Removed` the way its
forbidden-phrase mirror is: nothing in either corpus depends on the omission, and a permissive arm would keep
alive exactly the wrong answer this note reports.

**Sweeps.** Corpus: `grep -rn "RETURN" tests/conformance tests/nist --include=*.cob` minus
RETURNING/RETURN-CODE/RETURNED — every RETURN statement in both corpora writes its AT END (several on the
following line, several with the optional word `AT` omitted, e.g. `RETURN SORTFILE-1E END`), so no legal program
was newly rejected. Spec: over every `General format` `<pre>` block in `specs/ISO_COBOL.md`, §14.9.34.2's is the
ONLY unbracketed conditional-phrase line in any §14.9 statement format; SEARCH's two WHEN groups are the only
other mandatory phrase and the grammar already writes `searchWhenClause+` / `searchAllWhenClause+`.

**Paired with a drift test** (CLAUDE.md rule 5). `RequiredFormatPhraseDriftTests` re-derives that set from the
transcription, asserts every member is adjudicated WITH its enforcement mechanism, re-checks each mechanism is
still in place, and carries the negative control that §14.9.30.2's BRACKETED READ line is NOT reported. Its
failure branch was proven by temporarily mis-keying the RETURN row.

**Goldens.** `tests/conformance/2023/pb350_return_at_end_required.cob` (the minimal AT END-only form AND the SR4
reversed pair — the legal complement the screen must not reject) and its 85 twin, expected output derived from
§14.9.40.4 GR8 a), §14.9.34.4 GR3 and GR4; `tests/conformance/negative/pb350-return-without-at-end.cob` and
`pb350-return-reversed-not-only.cob`, both `reject-at: 85 2002 2014 2023`.

**The row stays DIVERGES.** `FMT-14.9.34.2` carried TWO independent defects and **PB351** still owns the other
(`statementBlock : statement+` admits an undelimited conditional statement where a format writes
imperative-statement-1, §14.5.1 — one mechanism under roughly fifteen formats). The row was re-verdicted with
the new code-locations, the four test-refs and a notes field that says exactly what is left; GAP delta 0, which
is the honest number.
