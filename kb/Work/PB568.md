# PB568

## Mechanism
the PICTURE EDITING phrase's grammar demands a QUOTED literal where the printed general format writes `EDITING character-1` bare, so every conforming EDITING phrase is a parse error and the SR10/SR11 checks are reachable only through a spelling the standard does not define

### The refutation this note is written from
Row `SR-13.18.40.3-10` was adjudicated CONFORMS and OVERTURNED to `PARTIAL` by the refuter. Its reasoning, verbatim:

> The predicate at PictureAnalyzer.cs:444-450 is right and the diagnostic is right, but NO CONFORMING PROGRAM CAN REACH IT. The standard writes character-1 BARE: the printed general format (rendered p441 at 300 dpi) is `EDITING character-1 { IS literal-1 | FOR { NEGATIVE IS literal-2 | POSITIVE IS literal-3 } }` - character-1 carries no quotation marks and no IS, exactly like character-string-1, while literal-1/-2/-3 are named as literals; SR8 calls character-1 'any basic letter in the COBOL character set ... or their lowercase equivalents'; SR9, the rule that TYPES the phrase's literals, enumerates only literal-1, literal-2 and literal-3; and 13.18.40.4 GR14 ('Character-1 in character-string-1 represents a character position') plus 13.18.40.5 editing rule 3 ('Character-1 and the symbols B, 0, /, , ... are used as the simple insertion editing symbols') make character-1 a PICTURE SYMBOL occurring in character-string-1, not a literal operand. CobolData.g4:429 spells it `EDITING literal ( IS? literal | FOR editingForPhrase )`, so the conforming spelling is a bare parse error and only the invented quoted spelling reaches ValidateEditing. Both halves of SR10 therefore fail for conforming source: the SR10-satisfying program is rejected (COBOL0001, not accepted) and the SR10-violating program is rejected by a generic syntax error that never names SR10. The check itself is located, sound and exercised in both binder arms, so this is PARTIAL rather than DIVERGES - and the root defect sits in 13.18.40.2, which has NO rule row in this subject (the clause map covers only .3/.4/.5), so it must not be parked inside a CONFORMS.

The citation was also loose: the GR lives in 8.1.3.2, and 8.1.3 itself contains no 'lowercase'.
