# PB115

Inventory: AR-15.10.3-2 (DIVERGES). `01 X PIC V9(31) VALUE .99…9` (31 nines) renders as
`Asin((double)(X) / 9.999999999999999E+30d)` = Math.Asin(1.0000000000000002) = NaN. The enforcement chain
(RealResult → ArgumentError) is intact — it is fed a value the argument never had. Fix direction: a
correctly-rounded scaled→double conversion (a Pow10D table through the double range, or decimal-string
round-trip for the wide scales) in BOTH `NumericRenderer.Real`'s divide and `CobolDec.ToDouble`; sweep every
float-lane function taking scaled arguments (the whole Float:true catalog) — the sibling sweep rule.

*(Found by the Phase-B §15 close-out batch, 2026-08-28 — one adjudicator + one independent refuter per subject;
the full forensic evidence lives in the named inventory rows' `notes` fields,
`tests/version-matrix/traceability-inventory.json`.)*

**LANDED:** `CobolFloat.ScaledToDouble` (fast path: exact operands, one rounding; slow path: the
correctly-rounded decimal parse), emitted via `RuntimeApi.ScaledToDouble` from the ONE `NumericRenderer.Real`
funnel; `CobolDec.ToDouble` rides it; `Pow10D` deleted. `ScaledToDoubleTests` (19) + golden
`2002/pb115_asin_scaled_argument`. The sweep found one other `Math.Pow(10` — EXP10's own r4-licensed body.
