# PB369 — a bound field nothing reads, behind a staged clause

**Rows:** `GR-14.9.49.4-4`.

## The program

`<lane3 scratch>/out-b1/probe/gr4-global-f2/p1.cob` — outer program UGR4A with `FD RPT GLOBAL REPORT IS R-1.`,
`RD R-1 GLOBAL PAGE LIMIT IS 10 LINES.`, a detail DET-1, and
`DECLARATIVES BR-SEC SECTION. USE GLOBAL BEFORE REPORTING DET-1. / BR-P. MOVE 7 TO WS-N.`; a CONTAINED program
UGR4B does `GENERATE DET-1.`; the outer reads the report file back.

Observed a hard rejection:
`p1.cob(18,1): error COBOLNET0899: RD 'R-1': the GLOBAL clause on a report description (ISO 13.18.27) is not yet
implemented - cross-program report visibility is staged`.

## The rule

§13.18.27.3 SR1 e) permits GLOBAL on a report description entry, so R-1 and its groups are visible to the
contained program (§13.18.27.4 GR1). §14.9.49.4 GR4 is headed **FORMATS 1 AND 2**, so with no qualifying
declarative in UGR4B the qualifying GLOBAL declarative in the next inclusive directly containing source element
is selected, running in the DECLARING program's instance: the produced line is `DE 7`.

## What the compiler does, behind the staging

The staging is loud and is not itself the whole finding. **Behind it the dispatch half is also absent by
reading:** `ProgramEmitter.EmitRunGlobalUse` emits only `decls[i].Global && Files.Count > 0` and
`decls[i].Global && ModeIndex is not null` arms — a **Format-2** `BoundDeclarative` has empty `Files` and null
`ModeIndex`, so it can NEVER be reached — and `ReportWriterEmitter.EmitReportConstruction` installs
`BeforeReporting` only from the EMITTING unit's own `bound.Declaratives`.

The `Global` flag IS captured for a Format-2 declarative (`DeclBindUse` returns `new DeclScope([], null, global,
group)`), so today it is **a bound field nothing reads**.

## Why this is filed now rather than when the staging lifts

⛔ **When the RD GLOBAL staging lifts, the walk must gain a report-group arm at the same time or the gap turns
from LOUD into SILENT** — a contained program's GENERATE would simply run no declarative, with nothing to say so.
That is the whole reason this row is registered while its surface is still refused: the two changes are one
change set, and separating them converts a documented deferral into an undetectable wrong answer.

**Code sites:** `ProgramEmitter.cs#EmitRunGlobalUse` · `ReportWriterEmitter.cs#EmitReportConstruction` ·
`ProcedureTableBuilder.cs#DeclBindUse` (the Format-2 arm's unread `Global`).

## Landed (wave 57, finisher of the w56b split)

**The staging and the dispatch half landed as ONE change set, exactly as this note required** — lifting the RD
GLOBAL staging without the Format-2 walk would have turned the loud gap silent.

- **RD GLOBAL is implemented** (cite.py --check 13.18.27.3 "A report description entry" → OK, SR 1 e);
  13.18.27.4 GR1/GR2 → OK). `ReportModel.IsGlobal`; `BinderDriver.BindUnitData` makes each container's GLOBAL
  report visible to a contained program (`DataBinder.InheritGlobalReport`, nearest container first, a local name
  hides) together with its groups and its sum counters. Two lists now: `DataBinder.Reports` is what a unit
  DECLARES, `DataBinder.VisibleReports` is what its procedure division can NAME — every report-name / group /
  counter / USE BEFORE REPORTING resolution reads it (drift-pinned by
  `GlobalReportScopeTests.ProcedureBinding_ResolvesReportsOnlyThroughVisibleReports`). The engine stays ONE
  object in the declaring program, reached through the `__outer` chain (`DataBinder.ReportDepth`,
  `RuntimeApi.ReportEngine(index, depth)`; the sum-counter and PAGE-COUNTER places carry the depth).
  `ReportGlobalClause` (COBOLNET0899 `report-global-clause`) is deleted.
- **GR4 Format 2 is a per-STATEMENT selection** (cite.py --check 14.9.49.4 GR 4 a) and 4 b) → OK). The
  per-group engine hook `ReportGroup.BeforeReporting` is GONE — it was the wrong shape: it could only run the
  DECLARING program's declaratives, NON-global ones included, for anybody's GENERATE. Each unit whose GR4 chain has
  a qualifying declarative for a visible report emits `__BeforeReporting_{uid}(gi, globalOnly)` (a non-GLOBAL case
  runs only when `!globalOnly`; the tail walks `__outer` while a container up to the declaring program has a
  GLOBAL one), and GENERATE / TERMINATE hand it to the engine (`Generate(name, sel)` / `Terminate(sel)`), which asks
  it by `ReportGroup.Index`. `ChainHasGlobalUse` now counts only Format-1 GLOBAL declaratives.
- **Siblings found on the way and fixed:** §14.9.16.3 SR3/SR4, §14.9.21.3 SR2 and §14.9.46.3 SR2 require the
  report's FD to be GLOBAL too for a contained GENERATE / INITIATE / TERMINATE — one check,
  `ReportWriterBinder.RejectContainedReportFile`, COBOLNET2392. §13.18.27.3 SR4's REPORT arm in a class
  (COBOLNET1520, `OoDriver.OoGateClassGlobal`) — it was covered only by the staging. The §14.9.6.4 GR5 CLOSE
  check and the §14.9.49.3 SR11 control-item check read `VisibleReports`.
- **Witnesses:** `conformance:85/pb369_global_report_use_selection` (GR4 a), b), the negative of b), a CF FINAL
  produced by a grandchild's TERMINATE, an inherited sum counter and PAGE-COUNTER);
  `conformance:85/pb369_global_file_use_selection` (the Format-1 GR4 a) half, which had only a legacy-baked
  witness); `negative/pb369-contained-generate-non-global-report` (1757);
  `negative/pb369-contained-report-file-not-global` (2392); `unit:GlobalReportScopeTests`;
  `conformance-test:OoSpineTests.ObjectReport_Global_1520`.
