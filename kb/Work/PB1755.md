# PB1755 — LANDED — a shared staging directory makes copybook staging a write race

## What happened

Implementer gate run `TestResults/build-local/20260929T202932Z-ebb36f` (worktree `wf_1a52c830-9ba-1`) went red on
one case, `VersionMatrixTests_P4.Construct_MatchesEditionExpectation(copy-replacing-non-pseudo-text-removed-2023, 85)`,
with `IOException: The process cannot access the file '…\.cache\compiled-programs\src\<hash>\VMCR1BK.cpy' because it
is being used by another process`. The next gate on the same tree was green.

## Mechanism

`tests/Cobol.Net.Tests.Conformance/EditionHarness.cs#CompileFull` (≈ line 36):

```
src = CompiledProgramCache.StageSource(src, source);
foreach (var (name, text) in copybooks ?? …)
    File.WriteAllText(Path.Combine(Path.GetDirectoryName(src)!, name), text);
```

`StageSource` moves the program into a directory named by the HASH OF THE PROGRAM TEXT (the PB985 compiled-program
cache), so every case that compiles the same program text — the version matrix compiles one construct at each of four
editions, in parallel — gets the SAME directory, and each writes the copybooks into it. Two writers of one file at once
is the race; the copybook's content is identical, so the race costs only the loser's exception.

## Fix shape (for the implementer)

The copybook set is part of the compile's input, so it belongs in the content hash: stage the program AND its
copybooks together into a directory keyed on both (an idempotent write-if-absent through a temp file + atomic move,
the pattern `StageSource` already uses for the program), rather than writing into a directory another case owns. Sweep
every `File.WriteAllText` into a `StageSource` directory (the other harnesses that pass `CopyPaths`).


## Landing (wave 1021 group B, fixed where it fired)

It fired on this wave's first gate (`TestResults/build-local/20261005T184851Z-9cba4a`, leg 2):
`VersionMatrixTests_P7.Construct_MatchesEditionExpectation(copy-replacing-non-pseudo-text-removed-2023, 2023)` —
`IOException … VMCR1BK.CPY … being used by another process`, exactly the note's mechanism (the group's new construct
row reshuffled the matrix partitions). Fixed by the note's own shape:
`CompiledProgramCache.StageSource(plannedPath, sourceText, companions)` stages the program AND its companion
copybooks into ONE directory whose name hashes all of them, each file written-if-absent through a temporary file and
an atomic move; `EditionHarness.CompileFull` passes its copybooks there and its `File.WriteAllText` loop is deleted.
The sweep: `grep "WriteAllText(Path.Combine(Path.GetDirectoryName("` over `tests/` named only that one site.

**For the next implementer.** `CompiledProgramCache.cs#StageSource` — a harness that needs files beside its program
passes them as `companions`; never write into a staged directory afterwards.
