# PB6056 - moved code may not silently re-open a COMPLETE edition

PB6053 (landed) re-read the five 1985 rows PB2635 left pointing at a deleted member. The mechanism stays: `code_reads.py
--check` prints "N read(s) owed a re-read (information, never red)" while `edition_status.py` counts them as a GAP term, so
a landing that moves a member a code read names turns an edition that read COMPLETE on main NOT COMPLETE with every
landing check green, and nobody is told.

**Fix:** the landing checks (`enqueue.py checks`) refuse a branch whose diff moves or deletes a member a code read of an
edition COMPLETE on main names, naming the rows, unless the branch carries their re-read; or the branch's own gate audits
that. Sweep `edition_status.py`'s other terms for the same information-versus-red split.

**Sites:** scripts/spec/code_reads.py; scripts/orchestrator/enqueue.py; scripts/spec/edition_status.py

## Landed (wave 20262138, group B)

**Fix.** `code_read_landing.py` (new, `scripts/spec/`) is a landing check (`enqueue.py checks`, the merged head's own copy, exit
6). It asks `code_reads.moved_by(ctx, records, head, base)`: a stored read of an older edition with a `code-location` entry that
resolves in origin/main and not in the merged head. Only when some read is moved does it ask main's status, by main's own
`edition_status.py --edition Y --json` in a detached worktree of main (the common landing pays nothing). It refuses an edition that
reads COMPLETE there, naming the rows and the remedy (re-read on the branch, `import --replace`); a branch that carries the re-read
passes, an edition not COMPLETE on main is not refused (it says so), an entry unresolved in main already is `moved_since`'s.
**Verified read-only** on `worktree-wf_ef90b3a1-3e3-1` (3 rows of 1985: IsInExternalRecord x2, IsGlobalRecord) and `-3e3-5` (1 row:
ListItemBoundary), each tip with its status of main stubbed COMPLETE: refused, naming the rows. With main's real status (1985 reads NOT
COMPLETE at d87e47fa1d: open notes and 2 code reads) the same run says "not refused": the rule holds only for an edition COMPLETE on main.

**Decision: the gate's CODE READS audit stays information.** It audits one tree (`--check`, the gate, CI's audits job) and cannot know
what main reads; a red there would fail every tree that carries an owed re-read, including main's own, so the one rule lives where both
trees are known. Both would call `moved_by` if it ever read red; none does.

**Sweep of `edition_status.py`'s other terms.** (1) inventory GAP and bound: changes by a verdict (`record_verdicts`) or a catalog
edit, in the landing's own diff. (3) open work notes: a note filed with `editions:` naming the edition re-opens it by filing, in
the diff and deliberate (PB6046: "a WiseOwl defect a test exposes is a kb/Work note and re-opens 1985"). (4) prose holes: change only
with the transcription or its dispositions. (2) code reads, the other arms: `stale` (a rule's text changed) and a `withdraw`n or
`owed` row change by a catalog or store edit, again in the diff; `fixed_since` re-reads only rows already counted contradicted. Moved
code is the one term an unrelated landing turns, so it is the one refused; no sibling arm has the information-versus-red split with
no visible cause.
