# PB4438 - a stray END-IF right after a recovered one is swallowed

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs` (`CobolErrorStrategy.Recover`, then
`CobolErrorStrategy.Resynchronize`, which consumes up to the period).

## Defect

After a recovery consumes the END-IF that ends a faulted IF, a second, stray END-IF that comes DIRECTLY after it (no
statement between them) falls inside the recovery window. `Resynchronize` consumes it on the way to the period, so the
stray END-IF draws no COBOL0306. The source is still refused, by the first fault, but the diagnostic list leaves out the
second error, which the user meets only on the next compile.

## Witness

From the report (`E:/COBOL-coord/scratch/reports/w20261823a-PB4299-report.md`, New defects 1; its Self-review keeps this
as a stated limit of the round-2 fix): `IF W-N = 1 END-IF END-IF.` and `IF W-N = 1 DISPLAY 'A'. IF W-N = 2 END-IF
END-IF.`. Each draws no COBOL0306 at the second END-IF. The report says origin/main behaves the same way, so the PB4299
branch did not cause it. The PB4382 fixes on that branch report a stray END-IF only when a statement stands between it
and the recovered END-IF.

## Fix direction

The recovery window should end at the statement terminator the recovery consumed. A following END-IF should then be
parsed again, so that it is reported as stray (COBOL0306), as it is when a statement stands between them. Pin it with
goldens for both witnesses, and with unit rows that assert the whole diagnostic list, as the PB4382 rows do.
