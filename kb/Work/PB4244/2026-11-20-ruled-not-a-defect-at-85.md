# PB4244 ruling
Verdict: NOT-A-DEFECT (at `--std 85`: no legal 1985 program was found that the missing condition boundaries misparse; the hand-maintained list itself stays a rule-5 structural item, not a harm)
Rule:
- `OK  §1985:VI.6.7.4 GR1  (6.7.4 General Rules)  the text is in GR1` — "Execution of the ALTER statement modifies the GO TO statement in the paragraph named procedure-name-1 so that subsequent executions of the modified GO TO statement cause transfer of control to procedure-name-2." (General format `ALTER {procedure-name-1 TO [PROCEED TO] procedure-name-2} ...`: a series with no separator, so `ALTER QA TO QB B-AND TO QC` names two pairs.)
- `OK  §1985:XIII.4.4.4 GR1  (4.4.4 General Rules)  the text is in GR1` — "The INITIATE statement performs the following initialization functions for each named report" (format `INITIATE {report-name-1} ...`; TERMINATE the same shape).
- B-AND, B-OR, B-XOR and B-NOT are not 1985 reserved words, so they are user-defined words at `--std 85` (the compiler agrees: every probe below declares them as paragraph, report or data names without a diagnostic).

How the predicate can go wrong (read at `src/WiseOwl.Cobol.Frontend/Parsing/CobolParserCoreBase.cs#boolExprAhead`, main 8244f1aa4b): the scan returns true when it meets a binary B-operator token with an operand term (`IsBoolOperandTerm`: IDENTIFIER, literal, `)`) just before it, or a B-NOT followed by an operand start, before any listed boundary. A statement verb missing from the list lets the scan run into the IF/WHEN/UNTIL body. At 1985 the only way a body supplies the trigger is a user word named B-AND/B-OR/B-XOR/B-NOT placed directly after (or, for B-NOT, before) another operand word inside the unlisted statement's own syntax.

The 1985 statement verbs missing from the boundary list: ALTER, DISABLE, ENABLE, ENTER, GENERATE, INITIATE, PURGE, RECEIVE, SEND, SUPPRESS, TERMINATE, USE (12). DISABLE, ENABLE and PURGE are lexer tokens absent from the list but also absent from the note's list of 14; the note's title undercounts. (ENTRY, UNLOCK, VALIDATE, COMMIT, ROLLBACK are not 1985 verbs.)

Evidence (each `--std 85`, tree `E:/COBOL/.claude/worktrees/rule85b`, run directories under `E:/COBOL-coord/scratch/rulings-1985-open3/s1/runs/`):
- ALTER, B-AND after an operand, in an IF with ELSE and in a plain IF; B-NOT before an operand (`ALTER B-NOT TO PROCEED TO PD PE TO PC`): `s1/pb4244a.cob`, run `pb4244a-001`, exit 0, `PB REACHED / PC REACHED / PD REACHED` (the altered path, correct by VI.6.7.4 GR1).
- ALTER with B-AND / B-OR / B-XOR after an operand, behind a condition-name, a class condition and a sign condition (the conditions whose operand alone is also a viable boolean operand, the most exposed case): `s1/pb4244c.cob`, run `pb4244c-001`, exit 0, `QB QC QF QG QI QJ REACHED` in order, correct.
- The same trigger in every other condition-tail position: IF with B-NOT before an operand, EVALUATE TRUE WHEN, SEARCH WHEN, inline PERFORM UNTIL: `s1/pb4244e.cob`, run `pb4244e-001`, exit 0, `B-NOT REACHED / QB / QE / QF / QH / QI / QK / QL REACHED`, correct.
- INITIATE and TERMINATE of report lists with reports named B-AND and B-NOT (`INITIATE R1 B-AND`, `INITIATE B-NOT R2`, TERMINATE the same, after a condition-name and a relation, with ELSE): `s1/pb4244g.cob`, run `pb4244g-001`, exit 0, `DONE`, report file holds `R1-LINE / BAND / BNOT / R2-LINE`, correct.
- ENTER: `s1/pb4244h.cob`, run `pb4244h-001`, exit 65, COBOL7240 "this implementation does not provide the ENTER statement" identically inside an IF (with and without `B-AND` after the routine name) and as a bare statement: the recorded implementor choice, the same in every position, so no parse the boundary changes.
- ENABLE ... WITH KEY B-AND, RECEIVE ... INTO B-NOT NO DATA, SEND ... FROM B-NOT WITH EGI AFTER ADVANCING N LINES, PURGE, DISABLE ... WITH KEY B-AND, each in an IF with ELSE: `s1/pb4244l.cob`, run `pb4244l-001` (compile only), exit 0, no diagnostic. In these formats no operand word is directly followed by a B-word (KEY, WITH, INTO and NO precede or follow it), so the trigger cannot form.
- GENERATE (one operand after the verb), SUPPRESS (`SUPPRESS PRINTING`, no operand) and USE (a declarative header, never in a condition tail) have no position where the trigger can form; not probed.

Reasoning: The missing boundaries let `boolExprAhead` return true for ALTER, INITIATE and TERMINATE bodies (the only 1985 shapes that can form the trigger), and the probes put the trigger behind every condition kind and every condition-tail position the 1985 language has. Every program parsed, bound and ran to the answer the 1985 rules give; the communication verbs cannot form the trigger at all. So no legal `--std 85` program is shown to misparse, which agrees with the 2026-11-07 audit and extends it from one case to all twelve 1985 verbs. The note's process_only stance holds for 1985. What remains is not a 1985 harm: the list is hand-maintained while `CobolErrorStrategy` reads FIRST(statementBlock) off the ATN, the shape CLAUDE.md rule 5 asks to replace (derive the boundary set once from the ATN, with a drift test), and it should add DISABLE, ENABLE and PURGE to the note's title if the note stays open. Later editions' verbs (ENTRY, UNLOCK, VALIDATE, COMMIT, ROLLBACK, and 2002+ forms where B-words are reserved) are outside this ruling.
