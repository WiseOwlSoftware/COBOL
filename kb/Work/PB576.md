# PB576

## Mechanism
a FLOAT VALUE can never be re-applied: InitializeEmitter stages every non-ZERO sender into a floating-point item LOUD, so the file-section, linkage, external and BASED occasions on which GR1/GR2 say the VALUE takes effect all abort at run time

### The refutation this note is written from
Row `GR-13.18.63.4-1` was adjudicated CONFORMS and OVERTURNED to `PARTIAL` by the refuter. Its reasoning, verbatim:

> GR1 (validated verbatim by cite.py, and it sits under the FORMAT 1 heading of 13.18.63.4) says 'the actual value given to the item is an approximation of the arithmetic value of the literal' for float-short / float-long / float-extended. The value is given only on GR4c's FIRST bullet (placed in initial state). On EVERY OTHER path a VALUE clause takes effect -- GR2 (file section), GR3 (linkage), GR4a (external), GR4b (based, under ALLOCATE), GR4c's second bullet (any INITIALIZE) -- the compiler ABORTS AT RUN TIME. src/Cobol.Net.Compiler/CodeGen/Verbs/InitializeEmitter.cs:29-45 matches 'case InitializeStore { Target.Item.Pic: { IsFloat: true } fp } s:' and, for any sender that is not the figurative ZERO, emits LoudStmt("INITIALIZE REPLACING/VALUE into floating-point item ... (float MOVE path deferred)"). The VALUE-phrase sender is exactly the non-ZERO sender, so a float VALUE can never be re-applied. The adjudicator never probed this arm: its 'ADVERSARIAL EDGE probed' covers only the SR2 compile-time range screen (COBOLNET1661), and its GR11 note asserts 'Format-1 controls in the same three sections all answer correctly' -- which is FALSE for the float format-1 control, i.e. for GR1's own subject. Two halves, one verified => PARTIAL. Harm: a legal program that INITIALIZEs a float, ALLOCATEs a BASED float INITIALIZED, or INITIALIZEs a LINKAGE float dies with an unhandled NotImplementedCobolFeatureException. No kb/Work note mentions this deferral (grep of kb/Work for 'float MOVE path deferred' returns nothing), so it appears to be a NEW defect, distinct from the COBOLNET0899 gap.

### Inventory row `GR-13.18.63.4-2` (PARTIAL)
MEASURED (probe gr2_file2, 2023): an FD record `01 R. 05 R1 PIC X(3) VALUE "ABC". 05 R2 PIC 9(3) VALUE 123.` is dirtied to XYZ999, then `INITIALIZE R ALL TO VALUE` restores ABC123 — the rule's operative half ("VALUE clauses take effect ... during the execution of an INITIALIZE statement") holds. A PLAIN `INITIALIZE R` gives [   000], the §14.9.20.4 GR6c category defaults, so the VALUE clause is NOT applied outside the TO VALUE phrase. IMPLEMENTOR LATITUDE, recorded not charged: the record area is ALSO seeded with the VALUEs at initial state (probe gr2_file: BEFORE=[ABC123] before any INITIALIZE). The rule's own second sentence — "The initial value of the data items in the file section is undefined" — makes any initial content permitted, so a program cannot conformingly depend on the difference; a future implementor decision to leave the area at its record-area content would be equally conforming. ⛔ SCOPE: this row is FORMAT 1 only. The same rule reaches FORMAT 2 through GR11 and there it does NOT hold — probe gr11_file2 shows `INITIALIZE R ALL TO VALUE` leaving a format-2 table VALUE unapplied; that defect is recorded on GR-13.18.63.4-11. CONFORMS-but-untested: no spec-derived test pins the file-section INITIALIZE arm. || REFUTED: PARTIAL — GR2 (cite.py OK): 'In the file section, VALUE clauses take effect only during the execution of an INITIALIZE statement.' The adjudicator verified only PIC X(3) / PIC 9(3) record items. For a file-section item whose usage is float-short / float-long / float-extended the ONE path the rule names cannot execute: InitializeEmitter.cs:44 stages the float VALUE sender LOUD, so 'INITIALIZE R ALL TO VALUE' aborts and the VALUE clause can NEVER take effect. GR2's operative half is therefore undelivered for the entire float population -- and this is NOT covered by the latitude the adjudicator invoked: GR2's second sentence ('The initial value of the data items in the file section is undefined') excuses only the INITIAL content, never the failure of the INITIALIZE path itself. The adjudicator's latitude reading of the initial-state seeding is UPHELD -- specs/ISO_COBOL.md line 34712 lists it among the undefined items: 'File section. The initial value of the data items in the file section is undefined. (13.4, File section, General rule 1 and 13.18.63, VALUE clause, General rule 2)' -- so the refutation rests solely on the float arm. Two halves, one verified => PARTIAL. Root cause is shared with GR1, but each row must say whether ITS rule is delivered.
