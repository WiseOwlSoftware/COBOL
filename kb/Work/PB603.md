# PB603 — OPEN — the implicit CLOSE that does not go through CLOSE

Found 2026-09-05 by the `PB235` implementer while making `FileRegistry.CloseByFormat` the one Table 14
dispatch; re-derived on this tree for this note. `process_only` because a single conforming run unit cannot
observe it — the harm is cross-run-unit contamination in a hosted process (the conformance harness, a host that
runs several run units in one process), which is a hygiene defect of the runtime, not a wrong answer to a
program.

## The rule

```
python scripts/spec/cite.py --check 9.1.16 "all record locks established for a file are released by the execution of an explicit or implicit CLOSE statement for the file"
OK  §9.1.16
```

Run-unit termination performs an implicit CLOSE for every open file (§14.6's termination rules); the standard
gives that implicit CLOSE the same effects as an explicit one, including GR9's lock release.

## The mechanism

`src/Cobol.Net.Runtime/IO/FileRegistry.cs#CloseAll` (~`:308`) iterates `_files.Values` and calls `c.Close()` on
each connector directly — never `Close(name)` and, since PB235, never `CloseByFormat(name, CloseFormat.Normal)`
— so `SharedClose` (`st.Open.Remove(name)` + `PhysicalFileTable.ReleaseAllForConnector`) does not run. The
static registry keeps the terminated run unit's connectors registered as open, and a later run unit in the same
process arbitrating for the same physical file sees them and reports a file-sharing conflict ('61') against a
program that has ended. Contrast `CloseIfOpen` (§14.9.5 CANCEL's implicit close), which routes through
`Close(name)` and is correct.

## Fix shape

Route `CloseAll` through `CloseByFormat(name, CloseFormat.Normal)` for every open connector, so the implicit
CLOSE is the same dispatch as the explicit one (§14.9.6.4 GR1 hoisted, Table 14 symbol c, GR9's release), and
decide deliberately — in the doc comment — whether the recorded "sequential connectors close unconditionally"
quirk survives or retires. Witness: an in-process harness test that runs two run units against one shared file
and asserts the second opens with '00'; the existing `2002/file_sharing*` goldens as the single-run-unit
controls.
