## Measured

### Finding working-storage-section — §13.5.3 SR1; §E.2 1) (under-rejects; rows SR-13.5.3-1)

**Mechanism.** The method-definition half of §13.5.3 SR1 is gated only at 2023 (ConstructRegistry method-working-storage-window, removedIn 2023; COBOLNET0902). --std 2002/2014 accept a method's WORKING-STORAGE silently and give it class-static semantics. This rests on VCR row 130e, which calls itself 'provisional' because 'Annex E.2 does NOT itemize the removal'. That silence is the only in-repo edition evidence, and it points the other way: a 2023 removal that affects existing programs would be listed in E.2 (it lists e.g. the EXIT METHOD statement), so the ban probably predates 2023.

**Repro.** probe/ws/p4meth.cob: a FACTORY method CNT with `DATA DIVISION. WORKING-STORAGE SECTION. 01 MW PIC 9(2) VALUE 0.`, invoked twice. `cobol p4meth.cob --std 2014 --run` compiles clean and prints MW=01 MW=02. `--std 2023` rejects it with COBOLNET0902.

**Expected, from the standard.** The 2023 §13.5.3 SR1 says WS may appear "only in a factory definition or an instance definition, but not in a method definition". Annex E.2 does not list the removal of method WS among the 2014->2023 changes, so the 2014 standard most likely carried the same syntax rule, and --std 2014 should reject method WS as 2023 does. The 2002 boundary cannot be derived in-repo. The owner decides by reading the 2014 (and 2002) texts, per VCR 130e's own 'shift removedIn' instruction.

**Observed.** Measured: 2014 accepts and runs; 2023 rejects (0902); an interface method prototype with WS is rejected at 2014 and 2023 by COBOLNET2272 (§10.6.2 SR4 e)), so the interface half conforms. conformance-test OoSpineTests.MethodWorkingStorage_StaticSemantics_EditionWindow asserts the 2002 acceptance (CTR=01/02/03), so it pins the questionable edge as correct.
