# PB867 — OPEN — an explicit RAISE that does nothing

Source: the `PB367` implementer report, item (a), which measured the behaviour and declined to call it a defect.

## Observed (the source report's probe, `p3-f3.cob`)

A program whose `MAIN` does `RAISE EXCEPTION EC-USER-DEMO.` with a matching `USE AFTER EC EC-USER-DEMO`
declarative and **no** `>>TURN` prints only `AFTER`: the declarative never runs and nothing is reported.

## The two texts

```
$ python scripts/spec/cite.py --check 14.6.13.1.1 "Checking is not enabled unless the TURN directive or WHEN phrase of the PERFORM statement is used to enable checking for the exception"
  OK  §14.6.13.1.1   (General)
$ python scripts/spec/cite.py --check 14.9.29.4 "RAISE"
  OK  §14.9.29.4 1)  (General rules)
      1) If exception-name-1 is specified, the associated exception condition is raised, and EXCEPTION-OBJECT is set to null. Execution continues as specified in 14.6.13, Exception condition handling.
```

Reading A (today's tree): §14.6.13.1.1 says checking for a user-defined condition is not enabled without a TURN
or a WHEN phrase, and an unchecked condition is not raised — so the RAISE is inert.

Reading B: §14.9.29.4 GR1 says the condition IS raised by the statement and that execution continues "as
specified in 14.6.13" — i.e. the RAISE is the enabling event for its own condition, and §14.6.13.1.1's sentence
governs conditions detected by the IMPLEMENTATION, not conditions a program raises explicitly.

## Why it needs deciding rather than fixing

An explicit RAISE of a condition nobody is checking silently doing nothing is a surprising outcome for a user,
and the surprise is exactly the kind that reaches a bug report as a wrong answer. But reading A is defensible
from the text and is what the tree does; changing it without the adjudication would be a behaviour change
pinned by nothing.

## Owner question

Does `RAISE EXCEPTION EC-USER-x` raise the condition when checking for it has not been enabled?

## Code site

`src/Cobol.Net.Compiler/CodeGen/EcEmitter.cs#EmitRaise` and the `>>TURN` mask.

## Sibling sweep whoever decides owes

* `RAISE identifier` (the EXCEPTION-OBJECT form) and `EXIT ... RAISING` / `GOBACK ... RAISING` ask the same
  question for the same conditions.
* The level-3 EC-USER family is where it bites; the level-1/2 conditions have implementation detection and are
  a different population.
