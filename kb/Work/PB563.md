# PB563

## Mechanism — value-clause-p4
The A.4.14 VALIDATE decline has a hole shaped exactly like the printed general format. CobolWords.g4 lists `VALID` as an UNGUARDED cobolWord alternative -- unlike its COMMIT / CRT / CURSOR neighbours, which carry a `{!reservedHere("...")}?` predicate -- even though 8.9's reserved-word list contains VALID. So at 2002+ the greedy VALUE operand loop (`valueItem : valueClauseOperand (valueClauseOperand)*`, guarded only against PROPERTY) consumes VALID as a constant-name operand, the Format-5 tail `({is2002()}? validateValidPhrase)?` never matches, and DeclinedFacilityPass.VisitValidateValidPhrase -- the ONE place COBOLNET1708 is raised -- is never reached. INVALID escapes because it is reserved at every edition and is not a cobolWord alternative; `IS VALID` escapes because the IS token terminates the operand loop before VALID is offered. The printed Format 5 (rendered from the PDF, page 546 = printed 516) brackets the connective as `[ IS / ARE ]`, so the connective-less spelling is the standard's own, and BOTH existing negative witnesses use the connective -- the corpus is green over precisely the half that works. The guard the grammar already writes for PROPERTY is the wrong shape for this: the fix is the reservedHere predicate (or removing VALID from cobolWord at 2002+), so the next context-dependent reserved word is handled by the structure rather than by a second hand-written token test.

### Expected, from the standard
13.18.63.2 Format 5 admits `{ VALUE | VALUES } { literal-5 [ THROUGH literal-6 ] } ... [ IN alphabet-name-1 ] [ IS | ARE ] { INVALID | VALID } [ WHEN condition-1 ]` -- the IS/ARE bracket is optional. The VALIDATE facility is an optional element (Annex A.4.14) whose support this implementation declines and which Annex F.2 item 5 additionally marks obsolete at 2023, so the entry must be refused BY NAME with COBOLNET1708 exactly as its IS-bearing twin is. Under no reading may VALID -- a reserved word per 8.9 -- be admitted as a user-defined constant-name operand, and under no reading may a raw C# compiler error reach the user.
