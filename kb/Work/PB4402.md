# PB4402 — the code lane pays for a corpus only a script self-test reads

**Sites:** `scripts/gate.py` (`Host.fetch_corpus`, `FakeHost.fetch_corpus`, `Gate._gate`), `scripts/linux-gate.sh` (whole: its corpus copy block and the leg that triggers it), `.github/workflows/build-and-test.yml`, `.github/workflows/nightly.yml`.

**What changed.** PB4395 (landed in #991) moved the pipeline's C# test classes into script self-tests. The GPL GnuCOBOL
corpus is now read by `scripts/corpus_sweep.py --self-test` (the population invariant, PB209) and by no compiler test.

**What still fetches it.** Every code-lane gate and CI shard still copies or downloads it:
- `scripts/gate.py` `Host.fetch_corpus` (line 652; `FakeHost.fetch_corpus` at 1597), called from `Gate._gate` (line 1248) on every gate;
- `.github/workflows/build-and-test.yml`, the shards' corpus fetch steps;
- `scripts/linux-gate.sh` (around line 589: "Copy the tree's (no network)").

Nightly's self-tests job, which now carries `corpus_sweep.py --self-test`, has no cache for the corpus tarball, so it
downloads it each night.

**Fix.** Fetch the corpus only where a reader needs it: the lane or job that runs `corpus_sweep.py --self-test` (and the
battery, which reads it). Drop the fetch from the code lane's gate, CI's code shards and `linux-gate.sh --legs targeted`,
and give nightly's self-tests job the tarball cache the shards use. Hold it with the CI-to-local drift test (PB1957): a
corpus fetch with no corpus reader in the same job is a finding.

**Not measured yet (from the PB4395 finisher).** The wall time of a tooling-lane gate, and a Linux watch run over the
narrowed CODE_READS. Record both in this note when the first tooling-lane gates run; they are the evidence for PB4323's
claim that the tooling lane is cheap.
