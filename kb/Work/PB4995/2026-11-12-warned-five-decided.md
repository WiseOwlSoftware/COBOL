**Decision (2026-11-12, Mythos session): the five warning-only rows of the 85n pass are witnessed by the flagged form in their clause pass. None closes without a witness, and none is an under-rejection.**

The rows are `1985-GR-VII.4.6.4-2`, `1985-GR-VIII.4.8.4-2`, `1985-GR-IX.4.8.4-2`, `1985-GR-XIII.4.8.4-2` and `1985-SR-XV.3.2.3-2`. The addendum `2026-11-12-drafts-85n.md` held them with a question; this file answers it.

**The text: a 1985 compiler need not refuse or flag a violation of either kind of rule.** §1985:I.1.6 says "The results of violating the formats or rules of Standard COBOL are undefined unless otherwise specified in this standard". "Formats or rules" makes no exception for a syntax rule, so the sentence reaches §1985:XV.3.2.3 SR2 ("there must be no reference to any non-declarative procedure within the debugging section") as it reaches the four general rules (§1985:VII.4.6.4 GR2, §1985:VIII.4.8.4 GR2, §1985:IX.4.8.4 GR2, §1985:XIII.4.8.4 GR2: "Within a declarative procedure, there must be no reference to any nondeclarative procedures"). What the edition requires of an implementation is that it "accept the syntax and provide the function for all Standard COBOL language elements" (§1985:I.1.5.2.2), and the only warning mechanisms it requires are for obsolete elements (§1985:I.1.5.2.3) and nonstandard extensions (§1985:I.1.5.2.5.2). None of the five rules specifies a result for its own violation. So the drafts' expectation "the compiler must refuse it" is wrong for all five, the syntax rule included. The resume note asked that the 85n worker's reading be tested against the text for the syntax rule before it was accepted; tested, it stands. All ten citations were run through `python scripts/spec/cite.py --check` on 2026-11-12 and each printed `OK`; a control quotation that is not in the rule printed `FAIL [text-not-found]`.

**What witnesses each row is already decided by `DESIGN-conformance-suite.md` section 3.2 and its obligations list,** so the held question's second arm (closing a row as one no compiler outcome witnesses) is not available.
- `1985-SR-XV.3.2.3-2` sits under a Syntax Rules heading and restricts. It takes an accepted test of the legal form and a `syntax` flagged line at 85 (the 85 mechanism is `inferred`, the design's decision 10). A flagged test passes when the compiler reports a diagnostic at its site, and the suite does not tell a warning from an error, so COBOL2375 at the violating line is that diagnostic.
- The four GR2 rows are general rules. Each takes an accepted test whose output shows a USE procedure of its module (Sequential I-O, Relative I-O, Indexed I-O, Report Writer) running with references only to declarative procedures. WiseOwl's COBOL2375 on the violating form is pinned in the WiseOwl layer only (`wiseowl/diagnostics`: code COBOL2375, severity warning), because flagging a general rule is the implementor's choice: "An implementation may, but is not required to, flag violations of such rules" (§2023:4.2.2), and the 1985 text asks for less.
- The warning itself is determination D-DECLREF of `docs/CONFORMANCE.md`, written for §2023:14.9.49.3 SR3. The 1985 rules are that rule's ancestors; the change that lands the witnesses adds the 1985 rules to that determination's record.
