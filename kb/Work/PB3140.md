# PB3140 — diagnostic output is part of CI's verdict

> flags: process-only

**What happened.** Merge-group run 38502926616 (PR #39, branch `worktree-wf_dfc118ad-872-14`, 2026-10-14): job
"Windows conformance (sharded) (corpus-nist ...)" printed `Passed! - Failed: 0, Passed: 5338`, then its step "Upload
test results (TRX + population listing + shard log)" failed with `##[error]Failed to CreateArtifact: Unable to make
request: ETIMEDOUT`. `ci-gate FAILS - windows-conformance=failure`, and the queue removed the PR (`failed_checks`,
2026-10-14T03:01:44Z). Every test had passed. The enqueue unit re-armed the branch with no commit. Log copy:
`E:\COBOL-coord\scratch\run-38502926616-failed.log` (lines 303, 320, 447).

**Mechanism.** Every `uses: actions/upload-artifact@v7` step in `.github/workflows/build-and-test.yml` (five: lines
465, 524, 602, 692, 761) has `if: ${{ always() }}` and no `continue-on-error`; the file contains no `continue-on-error`
at all and no retry. `always()` makes the step run after a failure; it does not make the step's own failure harmless.
So a transient failure of GitHub's artifact service turns a green test job red, fails the required `ci-gate`, and
costs a bounced landing, a re-queue and a second merge-group run. The artifacts are diagnostics (TRX, population
listing, shard log); the verdict is the test step's.

**Fix shape (to be confirmed).** Decide in one place how an artifact failure counts. Either `continue-on-error: true`
on the upload steps (the test step's outcome then decides, and `ci-gate` reads the test jobs), or a retry wrapper over
the upload; not a mix. Whichever is chosen must keep a RED test job's artifacts uploaded (that is why the steps run
`always()`), and a drift test should hold every `upload-artifact` step to the chosen form so the next one added cannot
reintroduce it. Sibling check: any other step whose failure is not a test result but is counted by `ci-gate` (cache
restore/save, logging). Relate: PB1957 (the CI-versus-local differences and its drift test that maps CI jobs to local
legs); this one is a CI-only robustness defect, not a local/CI difference.

## Landed (wave 20261026, group E)

**Re-probe (on the branch's base, 24e337272).** The mechanism stood as recorded: `.github/workflows/build-and-test.yml`
had five `actions/upload-artifact@v7` steps (the Linux and Windows conformance shards, greenfield-unit, inv1-strong-2023,
windows-build-test), each `if: ${{ always() }}` with no `continue-on-error`, and the file held no `continue-on-error`
and no retry anywhere. Its one download (`conformance-population`'s `actions/download-artifact@v8`) had the same shape
in the other direction: a transient download failure failed the population guard, and so `ci-gate`. CI-only, so the
probe is the file itself; the failed run's log is the note's.

**Fix: one rule, in two actions.** Every upload goes through the composite action `.github/actions/upload-results`:
three attempts (30 s, then 90 s apart; each retry `overwrite: true`, so a half-made artifact never blocks it), every
attempt `continue-on-error: true` under `always()`, and a `::warning::` when all three fail. The job's verdict is its
tests'. The callers keep `if: ${{ always() }}`, so a red job's results still upload. The one artifact a verdict needs,
a conformance shard's trx and listing, is checked where it is read: `conformance-population` downloads through
`.github/actions/download-results` (three attempts into an emptied destination; only the third failure fails the step),
and a shard whose upload was lost is absent from the union, so the guard fails there; its error line now says so. The
retention and `if-no-files-found` settings, written five times before, live once in the upload action.

**Held by `CiArtifactDriftTests`** (Unit, a tree sweep): no workflow under `.github/workflows/` names the raw upload or
download action; every upload step uses the upload action under `if: ${{ always() }}`; the upload action has two or more
attempts, each tolerated and under `always()`, each retry `overwrite: true`, and ends on a warning; the download action
has two or more attempts and only the last can fail. A self-test feeds each audit every forbidden shape. Measured: on the
base's workflow the audit is red. `CiHarnessLogDriftTests` and `FilterPopulationGuardDriftTests` read the action paths
from its constants.

**Sibling sweep.** Every other step `ci-gate` counts that is not a test result: `actions/cache` restore and save only
warn on failure (no change); `actions/checkout` and `actions/setup-dotnet` retry inside themselves; the one network
fetch a job makes itself, `scripts/fetch-gnucobol-tests.ps1` (the GnuCOBOL testsuite on a cache miss, Linux and Windows
jobs), had one `Invoke-WebRequest` and no retry: it now makes three attempts (15 s, then 45 s apart), since
`-MaximumRetryCount` retries only an HTTP error status, never a connection timeout. `scripts/gen-reserved-words.ps1`
also fetches, but only when a developer regenerates, never in CI.

**Sites:** .github/actions/upload-results/action.yml, .github/actions/download-results/action.yml,
.github/workflows/build-and-test.yml, scripts/fetch-gnucobol-tests.ps1, tests/WiseOwl.Cobol.Tests.Unit/CiArtifactDriftTests.cs,
tests/WiseOwl.Cobol.Tests.Unit/CiHarnessLogDriftTests.cs, tests/WiseOwl.Cobol.Tests.Unit/FilterPopulationGuardDriftTests.cs,

**For the next implementer.**
- A new CI artifact step uses `./.github/actions/upload-results` (with `name` and `path` only) under
  `if: ${{ always() }}`, or `./.github/actions/download-results` (`pattern`, `path`); `CiArtifactDriftTests` refuses
  the raw actions. Trap: a composite action's step may re-read the JOB's status, so each upload attempt says `always()`.
