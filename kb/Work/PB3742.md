# PB3742 — CAP_COPIES covers the read-only cap against the wrong roles

**Sites:** `.claude/skills/workstream/check_practices.py#CAP_COPIES`, `.claude/skills/workstream/check_practices.py#turn_cap_copies`, `.claude/skills/workstream/templates/MANDATORY-PRACTICES.md` (P5, "read-only 160"), `.claude/agents/cobol-reviewer.md` (about line 66).

`CAP_COPIES` checks the cost-law read-only row, P5's "read-only 160" and SKILL.md's "Turn caps: 160 for any read-only agent" only against `cobol-adjudicator` and `cobol-refuter` (both 160). The statements say "read-only", which also covers `cobol-reviewer` and `cobol-locator` (`maxTurns: 120`) and `cobol-clerk` (80), so `turn_cap_copies` prints that every statement matches its role while one it covers does not (`cobol-reviewer.md` itself says "its 160-turn cap does not bind a prose 'turn cap 120'").

Fix: give read-only a role list that is derived (every agent file whose tools forbid writing in a tree), or state per-role caps in P5 and check each; then drop the sentence in `cobol-reviewer.md` that explains the difference away. Drift test: add a read-only role and the check names it.

(2026-10-25, review R1-2, severity low.)
