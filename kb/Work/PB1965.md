# PB1965 — LANDED (wave 1047 A, 2026-10-08)

## Landed

Re-probed on the wave's build of 29362158a plus w1045a (`E:\COBOL-coord\scratch\w1047a\p\`; `run.py both <name>`
compares the main checkout's `cobol.exe` with this tree's): `b.cob` (`>>COBOL-WORDS EQUATE "UPPER-CASE" WITH "KUP"`,
`FUNCTION <Kelvin>UP (X)`) was COBOLNET1501 and prints `ABC`; `c.cob` (EXTERNAL `X<final sigma>` in the main program,
`X<sigma>` in the called one, `--std 2023`) printed `MAIN S` (one item) and prints `MAIN D`; `d.cob` (METHOD-IDs
`X<final sigma>` and `X<sigma>`) failed in Roslyn with CS0111 (two members `X<capital sigma>`) and runs both methods;
`e.cob` (`01 <Kelvin>EY`) compiled and is COBOLNET0901. The note's own Kelvin class repro (`a.cob`) did not reproduce,
and neither did any dotless-i shape: .NET's `ToUpperInvariant` keeps U+0131 as itself. Final sigma (which it raises
to capital sigma, as it does sigma) and the Kelvin sign (which it leaves alone) are the reachable letters.

- **The layering decision.** `Cobol.Net.Editions` references `Cobol.Net.Runtime`, the dependency-free foundation
  layer below it (`DESIGN-architecture-review.md` §8.1 layer 0; the allowed-edge list gains `["editions", "runtime"]`;
  `DESIGN-edition-framework.md` Q3 and the csproj say so). No new assembly: the fold already lives where the run-time
  externalized-name match needs it.
- **One upper-case key.** `CobolNames.UpperFold` (`src/Cobol.Net.Runtime/CobolNames.cs`): the Annex C fold with only
  the basic letters raised (§8.1.3.1 Table 1). It replaces `ToUpperInvariant` wherever a word is a key: the `Resolve`
  arguments (`FunctionWord`, `CobolParserCoreBase.Canonical`, `CobolWordsRewriter.CanonicalWordOf`,
  `DataBinder.Switches`, `VersionConformancePass`'s ALPHABET and reserved-user-word screens, `SetBinder`), the
  `>>COBOL-WORDS` operand contents, the directive word (`CompilerDirectiveLine`), the closed-set operand word, the
  parser's declared and freed-word sets, `ReservationGateRewriter`, the `>>TURN` file-names, `RaisingPhrase`, the
  default externalized names (`DataBinder.cs` FD, `DataBinder.Linkage.cs`) and the run-time EXTERNAL identities
  (`BinderDriver.ExternalItemIdentity`; `OoEmitter`'s strong-type key and `SelectFingerprint`'s key, alphabet, USING
  and RECORD DELIMITER word segments).
- **C# identifiers.** `DataItem.WordIdentifier` = `Sanitize(UpperFold(word))` at all twelve former
  `Sanitize(x).ToUpperInvariant()` sites (`BinderDriver`, `DataBinder.Oo`, `ObjectRefDescriptor.ClrTypeName`,
  `NamingConvention` x3, `OoClassTable` x5, `OoStandardClasses`).
- **Editions tables** on `CobolNames.Comparer`: `CobolWordsMap` (and `Is` by `CobolNames.Same`),
  `CompilerDirectiveCatalog`, `ContextSensitiveWords`, `ImplementorNames`, `NonstandardExtension.ForUsageSpelling`,
  `ReservedWords.Find`.
- **Drift.** `CobolNameFoldDriftTests` covers Cobol.Net.Editions, refuses the three host-upper key shapes
  (`NoHostUpperCase_AsTheKeyOfACobolWord`) and pins `UpperFold` by value.
- Goldens: `2023/pb1965_annex_c_word_keys` (SYNONYM ABC / SIGMA S / FINAL F / METHOD FINAL-SIGMA / METHOD SIGMA),
  `negative/pb1965-method-names-one-word-before-2023` (reject-at 2002 2014, COBOLNET0822),
  `negative/pb1965-kelvin-spelled-reserved-word` (reject-at 2023, COBOLNET0901).
- Not changed: upper-casing used only in diagnostic text, and the closed ASCII keyword comparisons (`FlagDirective`,
  `DivisionCursor`, `FigurativeConstants.KindOf`, …), where a keyword spelled with the Kelvin sign is a lexer
  keyword-recognition question, not a key.

## As filed

Found by wave 1014 group R (PB1402's relanding), filed by the train-1014 lander. PB1402 made ONE Annex C fold,
`src/Cobol.Net.Runtime/CobolNames.cs`, the key of every COBOL-word table in the compiler and the front end
(`CobolNameFoldDriftTests` refuses `OrdinalIgnoreCase` over a COBOL word there). Three families of sites sit outside
that drift test's scope and still use the host's case mapping, which disagrees with Annex C exactly on the extended
letters (§8.1.3.2 GR3 b) and GR4 b): `cite.py --check 8.1.3.2 "An uppercase extended letter is treated as though it
were folded to its corresponding lowercase extended letter"` -> OK §8.1.3.2 4) b)).

   `Resolve(x.ToUpperInvariant())`: `src/Cobol.Net.Editions/CobolWordsMap.cs:53-55,147-149`;
   `CompilerDirectiveCatalog.cs:28,89,144,158,159,174`; `ContextSensitiveWords.cs:36`; `ImplementorNames.cs:140`;
   `CompilerDirectiveLine.cs:63,78`; callers `src/Cobol.Net.Compiler/Binding/DataBinder.Switches.cs:1459`,
   `FunctionWord.cs:41`, `Validation/VersionConformancePass.cs:1408`, `src/Cobol.Net.Frontend/Parsing/CobolParserCoreBase.cs:57`,
   `Parsing/CobolWordsRewriter.cs:57-58`. **Layering question:** `Cobol.Net.Editions` references nothing and
   `CobolNames` lives in `Cobol.Net.Runtime`, so the fix needs a home below both (a new lowest leaf assembly, or the
   Annex B/C tables moved down) — an architecture decision for the implementer to make and record in the design doc.
2. **C# identifier keys** `DataItem.Sanitize(x).ToUpperInvariant()` at 12 sites: `Binding/BinderDriver.cs:530`,

   `Oo/OoClassTable.cs:204,255,312,364,431`, `Oo/OoStandardClasses.cs:81`: two class or method names equal under
   Annex C get two C# identifiers. Fix shape: one fold-then-ASCII-upper helper.
3. **Default externalized name** `item.CobolName.ToUpperInvariant()` (`Binding/DataBinder.Linkage.cs:794`,
   `Binding/DataBinder.cs:1847`): upper-cased by the host mapping before the run-time Annex C fold
   (`ExternalizedNames.Same`) compares it; U+0131 vs i collide differently by edition.
