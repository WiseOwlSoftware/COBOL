# PB4124 — a frozen function argument's FunctionValueField description differs from the unfrozen one for the selecting fu

**Sites:** `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/FunctionDeviceText.cs:132` (`FunctionDeviceText.Field`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/SendingValueTemp.cs:675` (`SendingValueTemp.OfComputed`).

New defect/lead 2 of PB4036's finisher ("file separately"). A frozen argument's `FunctionValueField` description differs from the
unfrozen one, for the selecting functions MAX / MIN / MEDIAN / ABS and for LENGTH / DISPLAY of the result:

- `LENGTH (MAX (A * B, 3))` -> 4 vs `LENGTH (MAX (A * B, UDF (A)))` -> 8;
- nested `LENGTH (MAX (MAX (C, 5), UDF (A)))` -> 38 vs unfrozen 8 (C PIC 9(8)).

The two forms of one call disagree, so at least one answer is wrong on legal source. Repro:
`E:/COBOL-coord/scratch/mythos/w-n1/w20261762e/p6.cob`.

**Root (the report's):** the freeze keeps the value, not the description. `FunctionDeviceText.Field`'s `BoundFieldOperand` arm describes a
frozen temp by its item; `SendingValueTemp.OfComputed` builds the temp. A nested function needs a `FunctionValueField`-holding temp, "a
design beyond this slice". Loosely shares the freeze-loses-identity root with PB4123 (the classifier lead); file and fix separately.
Determine the correct LENGTH from §15 (the result's description is the function's result type/size) before choosing which side is
the wrong one.
