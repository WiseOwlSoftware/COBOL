# PB4700 — implement the asynchronous messaging facility

**Decision (owner, 2026-11-04, on PB4117).** WiseOwl implements the asynchronous messaging facility (SEND, RECEIVE and USAGE
MESSAGE-TAG). The owner was offered four answers to PB4117: keep SR4 unscreened, screen it, accept MESSAGE-TAG only in the
declined facility's items, or implement the facility. The owner chose to implement it. PB4677 made the same choice for the
Communication facility at COBOL-85 and 2002.

**What is wrong.** `docs/CONFORMANCE.md` row 4 lists the facility (Annex E.3.2) as **Not claimed**, a documented non-support:
SEND and RECEIVE are accepted inert with the §4.2.6 warning (`DeclinedFacilityBinder.BindSend`, `BindReceive`), and USAGE
MESSAGE-TAG is refused by name (COBOL1943). So no program can declare the message-tag data item that §14.9.38.3 SR4 ("Data-name-1
and data-name-2 shall be the name of a message-tag data item", cite.py OK) and §14.9.31.3 SR1 ("Data-name-1 shall be the name of a
message-tag data item", cite.py OK) require, and every program that uses the facility is rejected or runs without effect.

**The work.** The facility exchanges messages between run units, so the runtime needs a message transport that the standard
leaves to the implementor. Following CLAUDE.md rules 2 and 5, the implementing change writes or extends the design doc first:
the deep-dive that owns statements and the runtime, or a new `docs/rearchitecture/DESIGN-*.md` listed in `docs/DESIGN.md` §0.5.
Settle the implementor latitude as rule 1 orders it: the ISO text, then GnuCOBOL, then IBM or Micro Focus, recorded in
`docs/CONFORMANCE.md`. The change then implements USAGE MESSAGE-TAG, SEND, RECEIVE and the facility's exception conditions, and
screens SR4 and SR1. It retires `DeclinedFacilityBinder`'s SEND/RECEIVE arms and COBOL1943, flips CONFORMANCE.md row 4, and
re-adjudicates the facility's inventory rows. Sweep the declined-facility notes PB3594, PB3593 and PB4202, whose subject this
removes.
