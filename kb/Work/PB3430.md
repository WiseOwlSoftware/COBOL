# PB3430 — Recover swallows IDENTIFIER-led SPECIAL-NAMES entries

Filed 2026-10-19 by the enqueue clerk; related PB3391 (landed; added the Recover arm).

**Mechanism.** In SPECIAL-NAMES the new `Recover` (`src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs:55`) consumes the
refused run through `ResidueRunTokens`. Mnemonic-name entries are made of residue-run tokens, so every IDENTIFIER-led entry
after a refused run is consumed up to the next keyword-led clause and a genuine error in those entries is silently dropped.
Main reported it; the reserved-word Sync arm in the same paragraph (which stops at `GetExpectedTokens`) still does. The
PB3391 DEVLOG claim that the controls prove recovery never swallows the next entry's error holds only for the data division.

**Fix shape.** Stop the recovery at the start of the next entry in SPECIAL-NAMES, with a test whose second entry is
erroneous and which asserts both diagnostics.
