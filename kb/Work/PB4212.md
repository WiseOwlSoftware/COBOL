**Sites:** `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/SetEmitter.cs:47` (`SetEmitter.EmitSetTo`: `"SET … TO"`),
`src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/SetEmitter.cs:186` (`SetEmitter.EmitSetUpDown`: `"SET … DOWN BY" : "SET … UP BY"`),

`src/WiseOwl.Cobol.Runtime/IO/FileRegistry.cs:373` (`FileRegistry.NoRewindPhraseEffect`: `$"OPEN … WITH NO REWIND reached ..."`),

Landing also changed `tests/_shared/ElidedMessageOpening.cs` (`ElidedMessageOpening.Source`),
`tests/WiseOwl.Cobol.Tests.Unit/DiagnosticOpeningElisionDriftTests.cs` and the new `tests/WiseOwl.Cobol.Tests.Conformance/IndexAmountMessageHeadTests.cs`.
The report named lines 47, 186, 443, 373 and 407; on main line 373 is the NO REWIND message and line 407 the REVERSED throw.

**The defect (a lead from PB4155's branch review).** PB4160 (landed) made no compile-time diagnostic open `VERB ... PHRASE`,
because the renderer prints the ellipsis as '.'. Its landing section lists these as "Not changed": the ELLIPSIS-labelled
messages of `SetEmitter` / `ControlFlowEmitter` (`LandAmount(..., "SET ... TO", ...)`, which a snapshot pins) and
`FileRegistry.MisroutedVerb` (`OPEN ... REVERSED`) are exceptions of the RUNNING program, "reported as a lead". It is the same
root at a different layer: the message a user sees when the generated program faults opens with an elided head (`detail` is
the head of the text that `CobolIndex.TryAmount` raises).

**Fix direction.** Name the phrase as written, as PB4160 did, or make the head a real phrase; extend the drift scan
(`DiagnosticOpeningElisionDriftTests`) to the emitter `LandAmount` call sites and the runtime exception heads so the next one
cannot arrive. A mid-sentence ellipsis stays (PB4160's rule). Regenerate the characterization snapshot and sweep the other
snapshots that pin an ellipsis head. PB4161 (SET LOCALE echo is a prefix slice) is open and separate; this note does not
cover it.

# PB4212 — LANDED (wave 20261786 C)

**Re-probe** (`>>TURN EC-BOUND-SUBSCRIPT CHECKING ON`, `SET IX TO N` over `N PIC S9V9 VALUE 1.5`, `cobol q1.cob --run`):
`abnormal run-unit termination: EC-BOUND-SUBSCRIPT (fatal): SET … TO — a non-integer value (ISO 14.9.39.4 GR2 a) 1. a)`;
`SET IX UP BY N` printed `SET … UP BY — a non-integer amount`. Reproduced on main.
**Fix.** The emitter's `detail` names the receiving operand's role in the general format, as the capacity register's
`SET capacity-register TO` already did: `SET index-name TO`, `SET index-name UP BY` / `DOWN BY` (built by interpolation from
`BoundSetUpDown.Down`, no conditional literal), `PERFORM VARYING index-name FROM`; `FileRegistry` says `OPEN WITH NO REWIND`
and `OPEN REVERSED` (the phrase as written, PB4160's repair). Both FileRegistry messages are raised only for a compiler defect
(a connector of the wrong organization), so no source reaches them.
**The next case is automatic.** `ElidedMessageOpening.Source` now also reads `LandAmount(`, `AugmentSetTarget(`, `MisroutedVerb(`
and any `new …Exception(` call, so `DiagnosticOpeningElisionDriftTests` sees the running program's message heads as well as the
compiler's. **Witness.** `IndexAmountMessageHeadTests` (Conformance) runs the four reachable messages and asserts the head.
**Swept, not messages.** `DialectBehavior.Table` titles, `VersionConformancePass` `where` labels and `BindProgramAddressTargets`
form labels open with `VERB …` but are registry titles or mid-sentence labels spliced after a dash, never a rendered message head.
