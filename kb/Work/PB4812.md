# PB4812 - the 1985 standard as public Markdown

**Source.** `specs-private/ANSI_COBOL_1985.pdf` (`spec_pdf.path(1985)`) (976 pages; owner bought it 2026-11-05; committed to the private
repo as specs-private 9cee9e8).

**Permission (verified).** PDF page 3 prints the CODASYL grant that the 2023 transcription relies on: "Any organization
interested in reproducing the COBOL standard and specifications in whole or in part ... is free to do so", on condition that the
acknowledgment paragraphs are reproduced in the preface. The per-copy stamp on every page ("Licensed to ... order # ...") must
NOT reach the public file.

**This PDF is a scan.** About 33 images per page, plus an OCR text layer in Arial and Helvetica. The text layer has OCR errors:
the permission sentence reads "OI" for "or". The 2023 PDF had a true text layer, so this transcription leans on the
render-and-compare half of the reconciliation, not on extraction alone. Every page is compared against its rendered image
before it is trusted.

**Output.** `specs/ANSI_COBOL_1985.md`, keeping the 1985 document's own structure: its modules (Nucleus, Sequential I-O,
Debug, Communication, ...) and level numbering, not the 2002/2023 clause numbers.

**The process is the 2023 one, unchanged** (owner 2026-11-05: "using the same processes and guidelines" as `specs/ISO_COBOL_2023.md`):
- Convert with `specs-private/scripts/convert_pdf.py`, `fix_pages.py`, `build_links.py` and `validate_doc.py`.
- Reconcile page by page against the PDF with the `spec-reconcile` skill and `.claude/workflows/spec-reconcile.js`. Its durable
  per-agent ledger lives under `docs/rearchitecture/spec-reconciliation/` (README.md, REPORT.md, LEDGER.json). Every claim gets
  an adversarial verify before a repair.
- Follow the rules in `docs/rearchitecture/spec-reconciliation/TRANSCRIPTION-STATE.md`: Markdown re-parses plain text, the
  rules for drawing a general format, and the standard's own defects transcribed AS PRINTED. `FIGURE-STYLE.md` and
  `PDF-TEXT-LAYER.md` apply too.
- Run the same gates: `lint_rendering.py`, `sweep_figures.py --check`, `verify_publishable.py` (no licence stamp, no order
  number, no licensee name anywhere in the public file) and `verify_acknowledgment.py`. Each tool gains a parameter naming the
  edition; none is copied (CLAUDE.md rule 4: no forks of a tool).
- Write a Preface like `specs/ISO_COBOL_2023.md`'s, naming the edition and the permission it is reproduced under, with the
  acknowledgment paragraphs reproduced in their entirety.
- Make `scripts/spec/cite.py` able to check a citation against this edition, so a design doc can cite the old edition
  mechanically (rule 1).
- Record the transcription in `docs/DOC_INDEX.md` and in `docs/VERSION_CHANGE_REFERENCE.md`, whose edition claims can then be
  checked against the edition's own text.

**First consumer.** PB4759 (the cd-name debugging trigger), whose rules are in the Debug module around PDF page 698. PB4759 may
read the PDF directly before this transcription lands; a design doc then cites by module and page.

## ⛔ The general formats (syntax diagrams) are the hard part (owner 2026-11-05)

The owner: "we need to properly handle all the difficult issues we encountered during the original spec convertion. THe syntax
diagrams were especially problematic with underlines, vertical bars, brackets and other graphical items indicating syntax and
grammar requirements that OCR and other techniques missed."

A general format carries four things, and losing any of them changes what the language permits (FIGURE-STYLE.md):
- grouping: brackets (at most one) and braces (exactly one);
- repetition and order: the choice-indicator bars;
- required against optional words: the UNDERLINE;
- operand structure: vertical alignment.
OCR and text extraction keep the words and drop all four. The 2023 transcription's general formats were wrong until they were
REGENERATED from the measured page, and four of FIGURE-STYLE.md's six rules were found by the owner looking at a rendered figure.
So for this edition:

1. **Every general format is regenerated from the measured page, never transcribed from extracted text.** Use the 2023 pipeline
   made edition-aware: `figure_geometry.py` measures the strokes, `figure_extract.py` reads the words with their coordinates,
   `render_figure.py` draws the figure and `sweep_figures.py --check` regenerates and diffs every figure. Then audit with
   `audit_underlining.py`, `audit_figure_structure.py`, `audit_figure_text.py` and `audit_grammar_optional_words.py`.
2. **Draw by FIGURE-STYLE.md and TRANSCRIPTION-STATE.md's "Rules for drawing one":**
   - `<pre>` with `<u>` for underlining, never a fenced block;
   - box-drawing glyphs only;
   - a collision-guarded canvas, and geometry computed, never counted;
   - `<` and `>` escaped at write time.
3. **Markdown re-parses the standard's notation** (TRANSCRIPTION-STATE.md, the class that did the most damage):
   - escape rule labels;
   - set character-sequence words in code;
   - never indent a sub-rule four spaces;
   - gate with `lint_rendering.py`, and render a slice with pandoc before any sweep.
4. **The printed page is the authority, rendered and looked at.** `render-spec-page.py` takes the edition through
   `spec_pdf.path(edition)`. A figure is accepted only after its rendered output is compared with the rendered page.
5. **Every figure gets an adversarial check,** as the 2023 `spec-grammar-conformance` and `spec-reconcile` workflows did. A
   refuter compares the drawn figure against the printed page for each of the four carried things.

**1985 is a SCAN: the geometry must come from the IMAGE.** Measured 2026-11-05: a 1985 general-format page has 0 vector drawings
and 33 images (PDF page 919), while the 2023 page measured had 34 vector strokes and the 2002 COPY format page 21. `figure_geometry.py`
measures vector rectangles, so it finds nothing in this PDF. The underlines, choice bars, brackets and braces exist only as PIXELS.
This edition needs a RASTER measurer:
- render each general-format region at high resolution;
- detect horizontal runs under words (the underline);
- detect vertical runs and their end serifs (brackets, braces, bars);
- map each stroke to the words of the OCR layer by coordinates, and the words themselves are verified against the image, because
  the OCR text layer has errors (the permission sentence reads "OI" for "or").
The measurer gets a self-test on planted images and a calibration against a dozen pages checked by eye. The rest of the pipeline is
unchanged. Do not trust the OCR text layer for anything inside a general format.
