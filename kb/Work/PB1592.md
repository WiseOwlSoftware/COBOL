# PB1592 — OPEN

Filed 2026-09-26 11:36 PDT by the golden-lane-2 lander from the gl2-misc-p2 writer's finding (brief step 2b (c)).

## The question
`docs/CONFORMANCE.md` row DOC-A.1-29 documents the compile-time arithmetic mode (.NET `System.Decimal`, ties to
even, one evaluator `CompileTimeExpressionEvaluator` for CONSTANT AS, `>>DEFINE` and `>>IF`/`>>EVALUATE`) and ends
"2002 onward". The inventory row's editions are 2002,2014,2023, and the compiler uses the same Decimal evaluator at
every edition. `tests/version-matrix/constructs.json` `arithmetic-intermediate-precision-2023` is still
pending/UNCONFIRMED, and `docs/VERSION_CHANGE_REFERENCE.md` row 12 records E.2 item 6 as gate-behavior-by-dialect
(todo).

## Expected, from the standard
```
$ python scripts/spec/cite.py --check E.2 "The mode of arithmetic used in evaluating compile-time arithmetic expressions and the handling of intermediate results is now explicitly implementor defined"
OK  §E.2 6)  (Substantive changes potentially affecting existing programs)
$ python scripts/spec/cite.py --check E.2 "The previous COBOL Standard required the use of an arithmetic mode that is no longer supported"
OK  §E.2 6)
```
So at 2002 and 2014 the mode was PRESCRIBED, and the implementor determination applies from 2023 only; below 2023,
compile-time expressions should follow the prescribed mode. Whether 2002/2014 output actually differs (for example
`15E-28 / 2 * 1E28` gives 7 under a wider exact mode, and `9999999999999999999999999999 * 10` fits in 32 digits)
needs the 2002/2014 text, which is not in the repo.

## What landed meanwhile
Golden lane 2 landed the 2023 witnesses `conformance:2023/gl2m2_ct_arith_mode` and
`conformance:negative/gl2m2-ct-arith-intermediate-overflow` and recorded the row CONFORMS with its editions
UNCHANGED (2002,2014,2023) — the lander was not to change them. This analysis decides the scope: reconcile
CONFORMANCE.md's "2002 onward" with VERSION_CHANGE_REFERENCE row 12, and either (a) gate the evaluator by dialect
(the 2002/2014 prescribed mode, with its own witnesses) or (b) narrow the row and the determination to 2023 and
record why the prescribed mode is equivalent or unsupported below it. The choice between (a) and (b) turns on the
2002/2014 text; if it cannot be read, it is an owner question under the precedence rule (ISO → GnuCOBOL → IBM/MF).
