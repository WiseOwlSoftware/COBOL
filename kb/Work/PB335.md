# PB335 — a scalar test where the rule names a set

**Rows:** `SR-14.9.30.3-9`, `GR-14.9.30.4-19`. Reported by read p1 and read p2 on two organizations; one line.

## The programs

**Indexed** (`out-b1/probe/sr9/dynadv.cob`): `ACCESS MODE IS DYNAMIC`, `RECORD KEY IS IX-KEY`, records
K001/`FIRST ` and K002/`SECOND`. `OPEN INPUT`; `MOVE "K002" TO IX-KEY`; `READ IXF RECORD ADVANCING ON LOCK`.
Observed `FS=00 KEY=K002 DATA=SECOND`; expected `FS=00 KEY=K001 DATA=FIRST `. The control (`dynate.cob`),
identical but with `AT END DISPLAY "AE"` instead of ADVANCING ON LOCK, prints the expected line.

**Relative** (`out-b1/probe/advdyn/ADVDYN.cob`): `ORGANIZATION RELATIVE`, `ACCESS DYNAMIC`, RRN 1/2/3 =
AAAA/BBBB/CCCC. `OPEN INPUT`; `MOVE 3 TO RK`; `READ R ADVANCING ON LOCK`. Observed `ADV-DYN 00 CCCC RK=0003`;
expected `ADV-DYN 00 AAAA RK=0001`.

## The rule

> §14.9.30.3 SR9: If neither the NEXT phrase nor the PREVIOUS phrase is specified and ACCESS MODE DYNAMIC is
> specified in the file control entry for file-name-1, the NEXT phrase is implied if any of the following
> phrases is specified: ADVANCING, AT END, or NOT AT END.

`--check 14.9.30.3 "the NEXT phrase is implied if any of the following phrases is specified"` → **OK**. The only
ADVANCING phrase in READ Format 1 is ADVANCING ON LOCK. With NEXT implied, §14.9.30.4 GR19 makes this a
SEQUENTIAL read; GR21's indexed rule d.1 then delivers K001 and its relative rule b) delivers RRN 1, and GR25
moves that RRN into the RELATIVE KEY item.

## What the compiler does

```csharp
FileAccessMode.Dynamic => previous ? KeyedReadKind.Previous
    : next || r.readAtEnd() is not null ? KeyedReadKind.Next
    : KeyedReadKind.Random,
```

`readAtEnd` covers BOTH `AT END` and `NOT AT END` (one grammar rule, either order), so two of SR9's three members
are present and the third is absent — although the SAME method reads `AdvancingOnLock =
r.readAdvancingOnLock() is not null` four lines later, to populate the node.

**The consequence is worse than a mis-selected record.** ADVANCING ON LOCK is a Format-1-only phrase (GR22
describes a skip-scan over a sequential walk), so the emitted Format-2 read carries a phrase whose semantics have
no meaning in that format: `KeyedIoEmitter` routes it through `FileReadLockGovern`, which cannot skip-scan. The
keyed emitter's inability to honour it at all is **PB340**.

## The fix shape

Model the trigger as the SET SR9 names — one derived predicate over `{ADVANCING, AT END, NOT AT END}` — rather
than the two members that happened to be needed first. **The same predicate then serves §14.9.30.3 SR6**, whose
forbidden set under ACCESS RANDOM is `{ADVANCING, AT END, NEXT, NOT AT END, PREVIOUS}` and which is already
written out longhand ten lines above in the same method: one rule, one place, two rules served.

**Code site:** `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/KeyedIoBinder.cs#BindRead` (the
`FileAccessMode.Dynamic` switch arm).
