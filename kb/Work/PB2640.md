**Rule it breaks:** ISO §14.7.4.3 GR4/GR5/GR6: under NEAREST-AWAY-FROM-ZERO (the bare ROUNDED), NEAREST-EVEN and NEAREST-TOWARD-ZERO the value is rounded to the NEAREST representable value; RoundDiv's own contract (CobolNum.cs:1101-1109) is the ONE rounding kernel for every carrier, so it must be exact over every divisor its callers pass

**Scenario:** RoundDiv computes twiceRem = T.Abs(rem) * 2 (CobolNum.cs:1117) with the unchecked generic operator. On Int128 any remainder above 2^126 overflows (verified on the pin's runtime: Int128 9.025e37 * 2 = -1.5978e38). CobolNum.Divide (1095-1098) passes den = b (or b*10^-exp) straight through, and NumericRenderer.Divide sends the OUTERMOST quotient to it at the receiver scale with the receiver's mode (NumericRenderer.cs:759-797); NumericRenderer.Multiply emits a bare Int128 product whenever the digit bounds sum to <= 38 (735-751). Repro: A, B PIC 9(19) VALUE 9500000000000000000; C, D PIC 9(19) VALUE 9700000000000000000; Q PIC 9; COMPUTE Q ROUNDED = (A * B) / (C * D). The quotient is 9.025e37 / 9.409e37 = 0.959, so GR4 stores 1; RoundDiv gets q = 0, rem = 9.025e37, twiceRem wraps negative, 'twiceRem >= divisor' is false, and Q is 0, silently, with no size error. The same happens for any binary-capacity 16-byte COMP-5 dividend and divisor above 8.5e37, and for NEAREST-EVEN / NEAREST-TOWARD-ZERO. The UInt128 lane is safe only because its divisors are powers of ten <= 10^38, and the CobolFloat caller only because its divisor is <= 2^126.

**Target:** RoundDiv compares the remainder against the divisor's complement instead of doubling it (|rem| against divisor - |rem|: '>=' for away, '>' for toward, '==' with q odd for even), which cannot overflow for any carrier; a unit test pins the 2^126 < divisor boundary on Int128 for all three NEAREST modes, and the sibling sweep covers every other 'remainder * 2' rounding test in the value lanes (CobolDec's quotient rounding).
