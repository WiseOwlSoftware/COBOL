**Rule it breaks:** ISO 14.9.13.2 selection-object: [NOT] brackets only identifier-2, literal-2, arithmetic-expression-2, boolean-expression-2 and range-expression; condition-2, partial-expression-1, TRUE, FALSE and ANY carry no NOT. 4.2.2 obliges an indication for source no format admits.

**Scenario:** MEASURED on the pin build (--std 2023): `EVALUATE X WHEN NOT ANY DISPLAY "NOT-ANY" WHEN OTHER DISPLAY "OTHER" END-EVALUATE` compiles with no diagnostic and prints OTHER; `EVALUATE TRUE WHEN NOT TRUE ... WHEN OTHER DISPLAY "OTHER3"` likewise compiles clean and prints OTHER3. evaluateWhenGroup (CobolControlFlow.g4:311-313) writes `NOT? evaluateWhenItem` over all seven arms, and EvaluateBinder.BindWhenGroup (EvaluateBinder.cs:105-106) wraps whatever arm parsed in BoundNot, so NOT ANY binds to the negation of 14.9.13.4 GR4 a) 1. (constant false): a WHEN arm that can never run, with no compile-time indication. A program ported from a compiler that rejects it, or a typo for WHEN ANY, loses that arm in silence.

**Landed (2026-10-14, wave 1077 F):** the re-probe confirmed the note (`WHEN NOT ANY` printed OTHER, `WHEN NOT TRUE`
printed OTHER3, both clean compiles) and found the same hoisted NOT was a SILENT WRONG ANSWER for legal source:
`evaluateWhenGroup : NOT? evaluateWhenItem` took the leading NOT of every condition-2 and partial-expression-1, so
`EVALUATE TRUE WHEN NOT A > B AND A > B` bound as NOT (A > B AND A > B) and `EVALUATE X WHEN NOT > 5 AND < 2` as
NOT (X > 5 AND X < 2) — both selected the wrong arm (§8.8.4.11.3 "The order of precedence of logical operators is
'NOT', 'AND'"). The note's target ("screen NOT on Condition / PartialExpression in the binder") would have refused that
legal source, so the fix is in the GRAMMAR: `evaluateWhenGroup` is deleted and `evaluateWhenItem` writes `NOT?` on the
five alternatives §14.9.13.2 prints it on ("The bracketed `NOT` applies only to the first five alternatives, exactly as
stacked"), plus `NOT? booleanLiteral` / `NOT? ANY` parsed only so `EvaluateBinder.ScreenObjectNegation` refuses them by
name — COBOL3710, at the NOT, every edition. TRUE/FALSE became their own alternative (the binder's
`SoleBooleanLiteral` parse-tree walk is deleted). Goldens `85/pb2722_evaluate_object_not_ownership`,
`2002/pb2722_evaluate_partial_not_ownership`, negatives `pb2722-evaluate-not-{any,true,false}`;
`EvaluateSelectionObjectArityDriftTests` pins which alternatives carry the NOT and whose NOT a leading NOT is.
DESIGN-frontend-grammar.md gains invariant 9 (a prefix stands on the alternatives that print it). Sibling arms: the
selection SUBJECT has no bracketed NOT and `EVALUATE NOT TRUE` is already COBOL2318; the `>>WHEN` directive refuses
`NOT 2` (COBOL1619); no other grammar `NOT?` precedes a sub-rule that can begin with NOT.
