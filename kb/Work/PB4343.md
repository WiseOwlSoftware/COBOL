# PB4343 — upper-case `D` only on the page, `D` or `d` in the preprocessor

**Found 2026-10-31** by the round-2 reviewer of the PB1610 finisher (wave 20261791 group C, report
`E:\COBOL-coord\scratch\reports\w20261791c-PB1610-report.md`, finding R2-2, LEAD, low, not blocking). **The page lands
with PR #933** (`docs/manual/user-guide/source-format.md` is not on main yet); the implementer starts after it lands.

**Sites:** `docs/manual/user-guide/source-format.md:15` (the debugging-indicator sentence, rewritten for R1-5),
`src/WiseOwl.Cobol.Frontend/Preprocessor/ReferenceFormatProcessor.LogicalConversion.cs` (`KindOf`: `'D' or 'd'` gives
`LineKind.Debugging`), `src/WiseOwl.Cobol.Frontend/Preprocessor/ReferenceFormatProcessor.cs:381`.

**The disagreement.** The page names only an upper-case D as the debugging indicator and says any other non-space
character in column 7 is COBOL2616. The preprocessor takes a lower-case d as a debugging line too. Related landed
notes: PB1494, PB1802, PB1914 (the fixed-form converter's indicator handling), PB4298 (the `>>D` form, open).

**This note does not decide which side is right.** The spec decides it: the implementer reads the fixed-form indicator
area rules in `specs/ISO_COBOL.md` (the reference-format clause, §6.2.2 is the cite the report gives for the D rows),
validates the clause with `cite.py --check`, then changes the page or the preprocessor, with a golden for a lower-case
d in column 7 either way.
