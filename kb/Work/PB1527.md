**Re-probed** on the wave-1011 Debug build (`28fc8a7f9` plus this change): the note's own repro and every neighbour — `STRING G …`, `STRING "Q" DELIMITED BY G …`, `UNSTRING G …`, `UNSTRING XX DELIMITED BY G …` over a strongly-typed group holding an OBJECT REFERENCE (and a POINTER) leaf — are COMPILE errors (COBOLNET1626 / COBOLNET1651), never a run-time abort. The question the train-1001 lander left ("does a non-strong group with a pointer/object leaf still reach the Tier-C abort through STRING/UNSTRING?") has a measured answer: it cannot exist. `USAGE POINTER` / `OBJECT REFERENCE` is legal only for an elementary item at level 1 or inside a STRONG type declaration (§13.18.60.3 SR14, `cite.py --check` OK; COBOLNET1724 refuses `05 P USAGE POINTER` under an ordinary group), and a STRONG typedef member cannot sit under a non-strong group (COBOLNET1532, §13.18.57.3 SR6). So the only group that can hold such a leaf is a strongly-typed one, which PB244's legs (`Sr1Offence`, `Sr2OffendingCategory`) refuse at bind on §8.5.2.1's text. The first attempt's one-way reader (`86e8ebf24`, `AsTransferString`) would be unreachable code behind that refusal and was NOT cherry-picked (one mechanism per job); its documentation commit `4deac4cfd` and gate-red fixes `0d6bc02ba` held nothing PB1527 still needs.

What landed: the stale warning in `docs/CONFORMANCE.md` §7 DOC-A.1-214 (it said STRING "compiles and then stops at run time") now states the compile-time refusal; the witnesses this note owed — golden `2002/pb1527_object_reference_group_image` (BYTE-LENGTH 11, DISPLAY and MOVE read the eight-space placeholder image) and negative `pb1527-string-object-reference-group` (COBOLNET1626); `DOC-A.1-214` is CONFORMS.
