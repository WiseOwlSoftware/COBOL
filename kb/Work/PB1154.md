## Landed (wave 1119, group F, campaign PB3353)

**Re-probe (own build).** The note named five codes; the whole Format-3 family was raw: COBOLNET1597, 1599, 1600, 1601, 1604, 1605-1617 (21 sites in `EcBinder.ExceptionPerform.cs`, `EcBinder.cs`, `ControlFlowBinder.cs`), none in `DiagnosticCatalog`. "Untested" was already stale (PerformFormat3Tests and `diagnostics.json` cover most), but "positioned at the PERFORM" reproduced exactly: a multi-file CLOSE, DELETE FILE, VALIDATE and a WHEN-phrase GO TO written on lines 20-24 all printed `(18,12)`, the PERFORM's own line and column.

**Fix.** (1) Seventeen `DiagnosticCatalog` descriptors, one per emitted code (1598/1602/1603/1609 are reserved numbers no rule emits), each quoting its syntax rule, every citation run through `cite.py --check`. (2) One reporter, `EcBinder.Ban<TStmt>(region, offends, rule, message)`, replaces eleven hand-written `foreach` loops and positions each report at the offending statement; SR14/SR15 report at the repeat, SR16 at the WHEN item. Two offending statements in one PERFORM are now two reports (before, both carried the PERFORM's position and text, so the second was dropped by the de-duplicator), and an offender inside a nested Format-3 PERFORM is still reported once. (3) Sibling found in the same function: the GR16 FINALLY transfer-out report (COBOLNET2927) positioned at `Column + 1`, one column right of every other statement diagnostic; the same off-by-one sat in `DataBinder` (MESSAGE-TAG exclusivity, COBOLNET2158). Both now use `Edition.At(context)`. (4) Semgrep `cobolnet-raw-diagnostic-code-literal` 244 -> 228, baseline updated. (5) `DiagnosticRegistryDriftTests.ExceptionCheckingPerformCodes_AreCatalogDescriptors` pins the family; `docs/COBOLNET_CONDITIONS_EXCEPTIONS_DESIGN.md` records the reporter.

**Witnesses.** Ten new refusal goldens under `conformance-suite/cases/` (one per code that had none: 1597, 1600, 1604, 1607, 1608, 1610, 1612, 1613, 1614, 1617) with their `diagnostics.json` entries; `ExceptionPerformBanPositionTests` (positions of all 17 codes, two-offender, nested, legal twins); `PerformFormat3IoStatementTests` (the abnormal I-O paths of the legal single-operand OPEN, CLOSE and DELETE FILE inside the PERFORM: statuses 35, 42, 41 and 05, with and without FILE STATUS, with and without a USE declarative, checking off, the GR14 implicit enable, an unmatched WHEN falling to the USE declarative, the fatal action).
