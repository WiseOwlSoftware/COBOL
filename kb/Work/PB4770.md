# PB4770 - the closed-format residue returns early on a header-writing slot before the residue-run check, so a foreign run ended by SECTION or DIVISION is no longer named

**What the report says (the reviewer's words).** R1-1 LEAD (low, not blocking at round 1): src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs:2032 The new at.WritesAHeader early return in ClosedFormatResidue runs before the at.ResidueRun check, so a foreign run ended by SECTION or DIVISION is no longer named, against the PB4301 rule stated a few lines below (A FOREIGN RUN IS REFUSED WHATEVER ENDED IT).

**R1.** No open note covers it (grep of kb/Work for the member name and key phrase).

**Sites.** `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs#CobolErrorStrategy.ClosedFormatResidue` (the `at.WritesAHeader` return, line 2032, and the `at.ResidueRun` check after it).

**Sites (as landed).** `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs` (`ClosedFormatResidue`: the `at.WritesAHeader` return now follows the `at.ResidueRun` check, which skips a run that IS the header's own name via `OffendingPosition.RunIsTheHeadersName`; `OffendingPosition.HeaderOpening`, `WritesAHeader`). The reviewer's lead was too broad: `PIC X MAIN SECTION.` is a header out of place (PB4706's pinned structure fault), and only a run that begins before the header's opening word is foreign. Unit theory `AForeignRunEndedByAHeader_IsNamed`. Goldens `pb4770-foreign-run-ended-by-section-in-an-entry` (COBOL1941 at VALEU) and `pb4770-foreign-run-ended-by-section-in-file-control` (COBOL1970 at ASIGN). Re-probed: `01 B PIC 9 VALEU SECTION.` gave COBOL0001, `SELECT F1 ASIGN SECTION.` COBOL0312, `01 B PIC 9 VALEU 5 DIVISION.` COBOL0001; all now name the run.
