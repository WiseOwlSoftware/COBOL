# PB5911 - three code comments cite "§2023:15.2 5)", which cite.py refuses; the audit does not catch it

The wave 20262097 group A reviewer's R1-4, unchanged: "The new doc comment cites "§2023:15.2 5", which cite.py --check refuses ("5 is not a rule designator"), so the citation the diff adds was never mechanically checked (CLAUDE.md rule 1)." (It was recorded in the batch 22 sweep as fixed; it is not, and the form is in three places.)

**Sites** (on main at a05cc533dc, `grep -n "15\.2 5)"`):
- `src/WiseOwl.Cobol.Compiler/Binding/IntrinsicArgumentRules.cs:1835` (a doc comment: "An integer function "has an operational sign and no digits to the right of the decimal point" (§2023:15.2 5))")
- `src/WiseOwl.Cobol.Compiler/Binding/IntrinsicResultType.cs:383` (a doc comment, the same sentence)
- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs:897` (a line comment: "(§2023:15.2 5) - "no digits to the right of the decimal point"")

**cite.py on both forms** (run here):
- `python scripts/spec/cite.py --check "§2023:15.2 5)" "has an operational sign and no digits to the right of the decimal point"` answers `FAIL: '5)' is not a rule designator: write SR n, GR n, AR n or RV n (its sub-item path glued: GR6d.2), Format n or Table n`
- `python scripts/spec/cite.py --check "§2023:15.2 GR5" "has an operational sign and no digits to the right of the decimal point"` answers `OK  §2023:15.2 GR5  (Types of functions)  the text is in GR5`

**These texts are comments, not diagnostics:** no message reaches a user, so this is a process note (process_only), not misleads_diagnosis.

**Two items for the fix.**
1. Change the three citations to `§2023:15.2 GR5`, and sweep every other `§<edition>:<clause> <n>)` form in code comments (the form of a numbered rule written with a closing parenthesis).
2. **The audit has a hole.** `python scripts/spec/audit_code_citations.py --check` answers `⛔ 0 finding(s)` with all three sites present (run here, after the grep above found them), so it does not catch this malformed form. The fix teaches the audit to refuse it, with a self-test case, so the next one cannot land.

**Sites (for the planner):** `src/WiseOwl.Cobol.Compiler/Binding/IntrinsicArgumentRules.cs` (whole: a doc comment on a member, to be named by the fix), `src/WiseOwl.Cobol.Compiler/Binding/IntrinsicResultType.cs` (whole: a doc comment on a member, to be named by the fix), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs` (whole: a line comment inside a long method), `scripts/spec/audit_code_citations.py` (whole: the audit learns a form).

**Scope.** No edition; comments and tooling.
