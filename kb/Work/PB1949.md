# PB1949 — VALUE before OCCURS … TIMES … STEP fails to parse

## Landing — DISCHARGED (wave 1020 H, 2026-10-05): not a defect, the period was past margin R

Re-probed on the wave-1020 build (base 7546af101). The note's repro line, indented ten spaces as written, is 73
characters long, so its separator period stands in **column 73** — outside the fixed-form program-text area
(§6.3.1, `cite.py --check 6.3.1 "The rightmost character position of the program-text area is a fixed position
defined by the implementor"` OK; this compiler's margin R is after column 72, `docs/CONFORMANCE.md` DOC-A.1-158).
The token dump of that line ends `IDENTIFIER 'STEP'`, `INTEGERLIT '1'` with no DOT, so COBOL0307 "missing token
before 'PROCEDURE'" is the correct report of an entry with no separator period. The same entry without `TIMES`
(`st6`) is six columns shorter, which is why it "worked". The same clauses wrapped onto two lines
(`VALUE "A"` / `OCCURS 1 TO 5 TIMES DEPENDING ON N STEP 1.`) parse in either clause order and reach the binder,
which refuses STEP in a data description entry as intended (COBOLNET2789, §13.18.38.2 Format 3). The clause-order
parse is correct; no code changed. Probes: `E:\COBOL-coord\scratch\w1020h\p\st4.cob`, `st4b.cob`, `v1`–`v7`,
`w1`–`w5`.

Filed by the train-1011 lander from wave 1011 group B2's report (`w1011b2-PB1087-report.md`, "New defects" item 1),
re-probed by the lander on the train-1011 build.

## Repro

```cobol
       01 N PIC 9 VALUE 2.
       01 G.
          05 T PIC X VALUE "A" OCCURS 1 TO 5 TIMES DEPENDING ON N STEP 1.
```

`cobol st4.cob` → `error COBOL0307: missing token before 'PROCEDURE'`. The same entry without `TIMES` (`st6.cob`)
and with the OCCURS clause written FIRST (`st1.cob`) both parse and compile. Repros are in the wave scratchpad
`w1011b2/p/st1.cob`, `st4.cob`, `st6.cob`.

## Code site

`src/Cobol.Net.Frontend/Grammar/Core/CobolData.g4#occursStepPhrase` and its prediction-time predicate
`src/Cobol.Net.Frontend/Parser/CobolParserCoreBase.cs#occursStepAhead`. A semantic predicate steers ANTLR's
prediction only at the left edge of a decision (memory `left_edge_predicates`), so the suspect is the predicate's
position relative to the `TIMES` token when another clause precedes the OCCURS clause. Dump the parse tree of `st4`
and `st1` before changing the rule (memory `use_antlr_tree_dump`).

## Rule

The report-writer OCCURS format with STEP (§13.18.38.2, the format 3 the data division admits) is a clause of the
data description entry, whose clauses are not ordered. Legal source rejected: `rejects_legal_source`.
