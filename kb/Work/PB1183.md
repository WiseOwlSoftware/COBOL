# PB1183 — OPEN

## Finding — `unstring-statement-p1` (under-rejects; rows `FMT-14.9.48.2`)

**Mechanism.** The grammar repeats the INTO keyword (`unstringIntoPhrase+` over `INTO unstringIntoTarget+`) where the general format has ONE INTO followed by a repeated receiver group, so `INTO A INTO B` is accepted

**Repro.** 01 S PIC X(12) VALUE "AB,CD5EF". 01 A PIC X(4). 01 B PIC X(4).  UNSTRING S DELIMITED BY "," INTO A INTO B.  -> compiles clean and runs A=[AB  ] B=[CD5E] at --std 85/2002/2014/2023.

**Expected from the spec.** A syntax error: §14.9.48.2 writes `INTO { identifier-4 [ DELIMITER IN identifier-5 ] [ COUNT IN identifier-6 ] } …` — the ellipsis repeats the braced receiver group, not the INTO keyword.

**Observed / reasoning.** CobolIO.g4 `unstringStatement : UNSTRING strUnstrSender unstringDelimiterPhrase? unstringIntoPhrase+ ...` and `unstringIntoPhrase : INTO unstringIntoTarget+`; BindUnstring iterates every unstringIntoPhrase without comment. Fix is `unstringIntoPhrase` (no +). The legacy Overlenient M417 tests are empty bodies (kb/Work PB387).

**Code site.** src/Cobol.Net.Frontend/Grammar/Core/CobolIO.g4#unstringStatement
