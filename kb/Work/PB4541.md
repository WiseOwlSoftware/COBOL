# PB4541 — next-group-line-counter-deferred: Report Writer: LINE-COUNTER after GENERATE does not include the group's NEXT GROUP adjustment

Filed 2026-11-03 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-batch-3000-20261103`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

In the Report Writer, a body group's NEXT GROUP clause does not change LINE-COUNTER when the group is printed. libcob
saves the NEXT GROUP value and applies it only when the next group is about to print, so the LINE-COUNTER a program reads
after GENERATE is the line of the group's last printed line. ISO requires the NEXT GROUP adjustment to LINE-COUNTER
immediately after the group's last line is printed. The physical position of the next group is correct.

## Minimal test case

Free reference format (`-free`). The program writes the report to `nxtgrp.out`.
```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. NXTGRP.
ENVIRONMENT DIVISION.
INPUT-OUTPUT SECTION.
FILE-CONTROL.
    SELECT RPT-FILE ASSIGN TO "nxtgrp.out".
DATA DIVISION.
FILE SECTION.
FD RPT-FILE REPORT IS RPT.
WORKING-STORAGE SECTION.
01 V PIC 9 VALUE 1.
REPORT SECTION.
RD RPT
    PAGE LIMIT 20 LINES
    HEADING 1
    FIRST DETAIL 3
    LAST DETAIL 16
    FOOTING 18.
01 D1 TYPE DETAIL LINE 5 NEXT GROUP PLUS 2.
   05 COLUMN 1 PIC 9 SOURCE V.
01 D2 TYPE DETAIL LINE PLUS 1 NEXT GROUP 12.
   05 COLUMN 1 PIC 9 SOURCE V.
PROCEDURE DIVISION.
    OPEN OUTPUT RPT-FILE
    INITIATE RPT
    GENERATE D1
    DISPLAY "AFTER D1 LC " LINE-COUNTER
    GENERATE D2
    DISPLAY "AFTER D2 LC " LINE-COUNTER
    TERMINATE RPT
    CLOSE RPT-FILE
    STOP RUN.
```

## Environment

cobc (GnuCOBOL) 3.2.0 on WSL2 Ubuntu. Command: `cobc -x -free -std=cobol2014 -o p next-group-line-counter-deferred.cob && ./p`
(cobc issued no diagnostic, compile exit code 0; the host C compiler's `_FORTIFY_SOURCE redefined` warning is an environment artifact of this WSL install; run directly).

## Observed result

```
AFTER D1 LC 0000000005
AFTER D2 LC 0000000008
```
Exit code 0. In `nxtgrp.out` D1 is on line 5 and D2 on line 8, so the NEXT GROUP PLUS 2 was applied before D2 printed.

## Expected result (per ISO)

§13.18.37.4 2): "The NEXT GROUP clause modifies the value of the current report's LINE-COUNTER after the printing of the
last line, if any, of the report group in whose description the clause appears." §13.18.37.4 4) b): for a body group, "If
the NEXT GROUP clause is relative and if the sum of integer-2 and LINE-COUNTER is less than the FOOTING integer,
integer-2 is added to LINE-COUNTER". §13.18.37.4 4) a): if the clause is absolute and "LINE-COUNTER is less than
integer-1", "LINE-COUNTER is set equal to integer-1". The report-counter rule says the same from the register's side,
§8.4.3.15.4 4): "The value of LINE-COUNTER after the printing of a report group is the same as the line number of the
last line printed, unless a NEXT GROUP clause is defined for the report group, in which case the final value of
LINE-COUNTER is defined by the general rules for the NEXT GROUP clause." D1 prints on line 5, then LINE-COUNTER becomes 5 + 2 = 7; D2
prints on line 8, then LINE-COUNTER becomes 12. The NEXT GROUP clause and these rules are in the 2002 and 2014 editions
(the Report Writer returned to the standard in 2002). Expected:
```
AFTER D1 LC 0000000007
AFTER D2 LC 0000000012
```

## Our compiler

WiseOwl COBOL (fresh judge, `--std 2014 --source-format free`) prints the expected output above, with no diagnostic.

## Fix site

libcob/reportio.c: `set_next_info` only stores the clause in the report header (`next_value`, `next_line`,
`next_line_plus`, `next_page`, `next_just_set`); the adjustment of `curr_line` ("Execute NEXT GROUP PLUS / LINE") happens
when the next group is output, and LINE-COUNTER is published from `curr_line` in between. Confirmed in the GnuCOBOL 3.2
release source (libcob/reportio.c).

(RD with PAGE LIMIT 20, HEADING 1, FIRST DETAIL 3, LAST DETAIL 16, FOOTING 18.) ISO/IEC 1989:2014 NEXT GROUP clause
general rule 2: the clause modifies LINE-COUNTER after the last line of its group is printed (the report counters' general
rule 4 says the same: after a group with NEXT GROUP, LINE-COUNTER's final value is the one NEXT GROUP defines); rule 4 a)
and b) give the values (integer-1 for the absolute form, LINE-COUNTER + integer-2 for the relative form). The printed positions are
right (D2 is on line 8); only LINE-COUNTER is late, because reportio.c saves the clause in `set_next_info` and adds it
to `curr_line` when the next group is output.
