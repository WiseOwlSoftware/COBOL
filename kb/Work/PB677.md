# PB677 — OPEN — a precondition the notice never states

Found 2026-09-05 by the `PB326` implementer (report §"New defects" 2) on its own golden
`tests/conformance/2002/pb326_ec_report_file_mode.cob`: after the first report is written (11 bytes), `OPEN EXTEND RPT`
prints the fixed-length layout notice on stderr. The corpus runner compares stdout only, so the golden is
unaffected; the user is not.

## The shape

`src/Cobol.Net.Runtime/IO/RecordLayoutNotice.cs#CheckFixedLengthFile`, called from `SequentialConnector.cs` at OPEN
(the `if (info.Exists) RecordLayoutNotice.CheckFixedLengthFile(HostPath, info.Length, …)` site), reports a file
length that is not a whole multiple of the fixed record length before a single record is misread. Its own doc
comment states the premise — a fixed-length RECORD-sequential file whose records carry no self-description — and
cites §9.1.7.2 (`cite.py --check 9.1.7.2` → OK; the record lengths are a property of the data and of the reading
program) and §14.9.30.4 GR14 for the standard's own detection — the status itself is §9.1.13.2 item 3
(`cite.py --check 9.1.13.2 "04"` → OK: *"the physical record from the file is shorter than or longer than the
minimum or maximum length of records allowed for the fixed file attributes"*); re-run `--check` on the GR14 number
before citing it in code, the comment paraphrases it. A report file connector satisfies none of that premise: its FD has no record
description the program reads, its "3-byte record" is the RD's derived line width, and its bytes are lines with
terminators and blank spacing lines, so the whole-multiple test is meaningless and the "misaligned" warning is
false. The notice needs a precondition — this connector has an ACTUAL record description that a READ will consume —
that a report FD does not satisfy. Sibling to check: LINE SEQUENTIAL files, whose records are also line-terminated
and variable, if the notice is reachable for them.

## Fix

Add the precondition at the ONE call site (or inside `CheckFixedLengthFile`, keyed on what the connector knows
about its record description — not on "is this a report file", which would be the first arm of a growing list), and
a unit test that opens a report connector EXTEND over an existing report and asserts an empty stderr. Not
dispatchable before train 10 lands: PB323 restructured the connectors' OPEN paths.
