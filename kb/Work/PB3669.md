# PB3669 — scripts/linux-gate.sh writes the never-work rule a second time (grep -v ' STATUS.md$'), so the harness's settings file counts as an untested tracked change in its NOTE

**Sites:** `scripts/linux-gate.sh` (the `dirty=` line, ~536), `scripts/orchestrator/coord.py#NEVER_WORK` and `NEVER_WORK_PATHSPECS`.

## What happens

The `dirty=` line counts tracked changes with `git status --porcelain --untracked-files=no | grep -v ' STATUS.md$'`. That is a shell copy of the never-work rule, and it lists one of the three paths. `coord.NEVER_WORK` is `.claude/settings.local.json`, `STATUS.md` and `TestResults/`. The harness's settings file therefore counts as an untested tracked change and appears in the gate's NOTE. The effect is cosmetic and process-only.

## Fix direction

One rule, one place: the shell script cannot import `coord`, so it asks `coord.py` for the pathspecs (`NEVER_WORK_PATHSPECS`) and passes them to `git status`, and the `grep -v` copy goes. This shares its root with PB3474 (`prune_worktrees.classify()` hand-codes the same rule); sweep every other hand-written copy of the list in `scripts/` when fixing.
