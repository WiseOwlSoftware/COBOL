# PB5360 - ConditionBinder.SoleOoIdentifier duplicates SoleOperand.TemporaryIdentifier: one rule written in two places

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/ConditionBinder.cs:1757` (`ConditionBinder.SoleOoIdentifier`)
- `src/WiseOwl.Cobol.Compiler/Binding/SoleOperand.cs` (`SoleOperand.TemporaryIdentifier`)

**Mechanism.** Two members decide the same thing, which identifier is the sole operand of an object-oriented expression, and each carries its own copy of the edition and shape tests. A rule change (PB4153 swept both for edition blindness) must be made twice, and a drift test cannot pin one rule that lives in two places. This is the duplication dimension of PROMPT.md section 4.

**Fix direction.** One member owns the rule; the other caller changes to it and the duplicate is deleted in the same change (CLAUDE.md rule 4, no forwarder left behind). Verify with the existing refuse-at-85 tests PB4153 added.

**Source.** PB5240's report: "duplicates `SoleOperand.TemporaryIdentifier`; own root". Not re-probed (a read-only duplication lead with a code site).
