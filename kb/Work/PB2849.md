# PB2849 — LANDED — a golden that does not observe what it tests, and a possible abort

Found by the train 1047 lander's review (step 5b; `E:\COBOL-coord\scratch\reports\train1047-report.md`, finding (f)) on cluster 45H (PB1951, PB1956), the golden gap stated by the reviewer; the abort PLAUSIBLE (traced, not run). The lander had no ids left; the land unit reserved this id and the resume unit of 2026-10-08 21:46 PDT filed it.

## What is wrong
1. **Test gap.** The PB1951 goldens (`conformance-suite/cases/_unassigned/pb1951_table_sort_external_variable_element.cob`,
   `conformance-suite/cases/_unassigned/pb1951_table_sort_external_pointer_dynamic_table.cob`) declare ECAP but never DISPLAY it,
   so a table SORT that leaves the capacity unshrunk produces the same output and the golden stays green.
2. **PLAUSIBLE abort.** A carrier element that holds an OCCURS DEPENDING ON table is handled by an immediate run-time
   abort rather than being deferred the way the other carrier shapes are.

The goldens display the capacity before and after (expected values derived from the TABLE SORT and dynamic-capacity
rules, not copied from output), and the ODO-carrier case is probed: fixed if it aborts, recorded here if it does not.

## Landed (wave 1115 group E, SORT and file I/O campaign PB3353)

**Re-probed first, on this build.** (1) The two PB1951 goldens printed the same output whatever the capacity of a
moved element (neither observes it): confirmed by reading them. (2) The abort did not reproduce, and its stated shape
is unwritable: an element cannot hold an OCCURS DEPENDING table, because 13.18.38.3 SR1 b says "The OCCURS clause
shall not be specified in a data description entry that ... Has an occurs-depending table subordinate to it"
(`cite.py --check` OK; the binder refuses such source with COBOL0854). Every shape that CAN meet a depending table
sorts correctly and none reached the run-time loud of `PlaceRenderer.VarGroupImageAt`: an OCCURS DEPENDING subject
whose elements are carriers (two dynamic-length items; a dynamic-capacity table; a fixed inner table of dynamic-length
items; a dynamic-capacity pointer table), with the count below the maximum; and a fixed carrier table in a record
whose trailing storage is a depending table.

**The observer.** The note says "DISPLAY ECAP". That reference is not writable: the register of a table nested
under a table is inside the outer table (13.18.38.3 SR30) and SR31 forbids subscripting it (COBOL2126). The
capacity is observed through the element's contiguous extent instead (8.5.1.11.2; 15.50.4 rule 3): FUNCTION LENGTH of
the element for the carrier golden, and (LENGTH of the element - LENGTH of EK) / LENGTH of a pointer for the pointer
golden (the pointer width cancels).

**Goldens.** `pb1951_table_sort_external_variable_element` and `pb1951_table_sort_external_pointer_dynamic_table` now
print the capacities before and after (values derived in their headers: element lengths 9 6 5 then 6 5 9; pointer
capacities 2 1 0 then 1 0 2). New in `cases/14.9.40-SORT/`: `pb2849_table_sort_carrier_odo_subject` (success with N
below the maximum, and the abnormal path: N above integer-2 under EC-BOUND-ODO checking, 13.18.38.4 GR7, a declarative
and RESUME NEXT STATEMENT 14.9.33.4 GR2, the statement places nothing) and `pb2849_table_sort_carrier_beside_odo_table`.

**Found, other subsystem, not fixed.** SEARCH and SEARCH ALL of a dynamic-capacity table nested under another table is
a COBOL1756 deferral that aborts at run time (`SearchBinder.cs`, "a later increment"); reported as a lead in the
wave-1115 E report.
