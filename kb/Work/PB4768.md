# PB4768 — a formal passed on BY REFERENCE nests one more view per activation

**Found** by the Mythos lane while writing the DOC-A.1-17 goldens (kb/Work A11), on origin/main at 8e30d4bbf.

**What happens.** `CobolArgAdapt.Text` (src/WiseOwl.Cobol.Runtime/Control/CallAbi.cs, the `case ManagedPointer<string> sp`
arm) adapts a character argument to a CHARACTER formal by returning a NEW `ManagedPointer<string>.OverField` whose read
and write closures call `sp`. When the activated program passes that formal on BY REFERENCE, the next activation's
argument carrier IS that view, and it gets wrapped again. After d activations the formal is a chain of d closures: each
read or write of it costs d nested delegate calls, and a chain deep enough exhausts the stack outside the activation-stack
check (docs/CONFORMANCE.md DOC-A.1-14: the one resource checked is the stack an activation needs).

**Repro** (one source, `--std 2002` or later; separate programs, so the CALL is dynamic):

    >>TURN EC-PROGRAM CHECKING ON
    PROGRAM-ID. DRV.  WORKING-STORAGE: 01 X PIC X(4) VALUE "ABCD".
        CALL "DP" USING X  STOP RUN.
    PROGRAM-ID. DP RECURSIVE.  LINKAGE: 01 L-A PIC X(4).  PROCEDURE DIVISION USING L-A.
        DECLARATIVES: USE AFTER EXCEPTION CONDITION EC-PROGRAM-RESOURCES; DISPLAY ...; RESUME AT NEXT STATEMENT.
        CALL "DP" USING L-A   then, at the level whose CALL failed, DISPLAY L-A.

The declarative runs (`DECL EC-PROGRAM-RESOURCES`) at about 21,400 levels; the DISPLAY of `L-A` then dies with
"Stack overflow. Repeated 21464 times: at WiseOwl.Cobol.Runtime.CobolArgAdapt+<>c__DisplayClass31_0.<Text>b__4()",
and the process ends (exit code of a .NET stack overflow), where §2023:14.9.4.4 GR3 c) and h) 2. require the run to continue
after the end of the CALL. The same crash with `L-A PIC 9(4)` and `PIC 9(4) COMP` (both reach the same arm). Passing
a LOCAL-STORAGE item of each level instead of the formal (the DOC-A.1-17 golden
`doc_a1_17_call_other_effects` does) runs clean, which isolates the chain.

**Harm.** `crashes`: a conforming program that recurses through a by-reference formal and handles EC-PROGRAM-RESOURCES
crashes. Below the crash depth it is a performance defect: a formal passed down d levels costs O(d) per access, so a
recursive walk that touches its formal at each level is O(d²).

**Root cause, and the shape of the fix.** A view over a view never collapses. A width window composes: reading
`Store(Store(base, a), w)` is the base truncated to `min(a, w)` and padded to `w`, so a window of a window is one window
over the BASE storage, and a store splices into the base the same way. The fix makes the adapter build its view over the
underlying storage and window (a view type that exposes them), never over another view, so depth d costs one indirection.
Sweep every `OverField`/`OverStorage` arm in `CobolArgAdapt` (the numeric-image arm, ANY LENGTH, the variable-length group
arm, `TextValue`, `DynText`, `Num`) and the BY CONTENT and pointer arms for the same nesting, with a drift test that
passes a formal on through N activations and asserts the view depth stays 1. docs/INTERPROGRAM_DESIGN.md states the
argument ABI and is updated in the same change.

**Landed** (wave 20261878, group G). `TextViews` (`Window`, `AnyLength`, `Dynamic`) builds every character view over the
underlying carrier and composes windows; the formal is one view deep at any recursion depth (docs/INTERPROGRAM_DESIGN.md).
Not collapsed, and not reachable by a same-description recursion: the variable-length-group `OverStorage` arms (a shape
conversion per hop) and the numeric converting arms.

**Sites:** `src/WiseOwl.Cobol.Runtime/Control/TextViews.cs` (`TextViews.Window`, `AnyLength`, `Dynamic`),
`src/WiseOwl.Cobol.Runtime/Control/ManagedPointer.cs` (`ManagedPointer<T>.ViewTag`, `OverView`),
`src/WiseOwl.Cobol.Runtime/Control/CallAbi.cs` (`CobolArgAdapt.Text`, `CobolArgAdapt.DynText`).
