# PB2489 — OPEN

Filed 2026-10-07 by the train-1034 lander from the wave-1034 group A implementer report (`w1034a-PB165-report.md`,
"New defects"), re-probed on the merged train build (HEAD of the train, before landing).

**Rule.** ISO §16.1: "A standard class BASE shall be provided by the implementation" (`cite.py --check 16.1` OK), and
§16.2.1.2 New is BASE's factory method, so `INVOKE BASE "NEW" RETURNING O` with `REPOSITORY. CLASS BASE.` is legal
source that returns a new BASE object.

**Repro.** `E:\COBOL-coord\scratch\train1034\p\pgo_base.cob` (`--std 2023`): compiles to C#, then
`error CS0117: 'BASE__FACTORY' does not contain a definition for '__Instance'` at the generated line
`O = (CobolObject?)BASE__FACTORY.__Instance.__New();   // INVOKE … "New" (ISO §16.2.1.2)`. Expected: `O:SET`.

**Code site.** `src/Cobol.Net.Compiler/CodeGen/Verbs/OoEmitter.cs` line ~854 (`s.SourceFactoryCs is { } fac ?
$"{fac}.__Instance"`): a user class's factory has a generated `__Instance` singleton; the runtime `BASE__FACTORY`
(PB1506's provided root) has none. Fix shape: give the runtime BASE factory the same singleton surface a generated
factory has (one shape for every factory, so the emitter needs no BASE arm), or route the BASE reference through the
runtime's own accessor. Sweep the other `__Instance` readers (factory-object references `BASE` as an identifier,
`INVOKE BASE "FactoryMethod"`).

## Landed (wave 1039 D) -- the standard class BASE is concrete and its factory has the generated factories' `__Instance`

Re-probed on the wave-1039 build before any edit: `INVOKE BASE "NEW" RETURNING O` (`train1034/p/pgo_base.cob`) failed the backend compile with CS0117, exactly as filed.
Root cause: the emitter reaches every factory as `{Class}__FACTORY.__Instance`, and the runtime pair standing for the standard class BASE (`CobolNet.Runtime.BASE` / `BASE__FACTORY`) was abstract and declared no such singleton, so BASE was the one class whose factory could not be named although ISO 16.2.1.2 GR1 makes New on it create an object (`cite.py --check 16.2.1.2` OK).
Fix at the root, one shape for every factory (no BASE arm at an emit site): `BASE__FACTORY` is concrete, declares `public static BASE__FACTORY __Instance => RunUnit.Current.FactoryObject<BASE__FACTORY>()` and creates a plain `BASE` through the now-virtual `__Create`; `BASE` is concrete with a virtual `__FactoryOfClass` defaulting to that singleton; both declare their class-identity types (`__FactoryClassType` / `__InstanceClassType`). A generated factory with ANY superclass now hides the accessor with `new` (`OoEmitter.EmitClassUnit`; it was only a COBOL superclass).
Sibling sweep (the other `__Instance` readers): `SET f TO BASE` (`EmitSetObjectRef`), and the `INVOKE class-name "M"` and `FACTORY OF` forms (`OoEmitter` factory-reference arms) all render `{Class}__FACTORY.__Instance`, so they work on BASE by the same shape; the golden drives `INVOKE BASE "NEW"` into universal and typed receivers, `SET FB TO BASE`, `INVOKE FB "NEW"` and `FACTORYOBJECT` through both a typed and a universal receiver.
Goldens: `2002/pb2489_invoke_base_new` (+ `.out`) and `negative/pb2489_invoke_base_new_below_2002` (COBOLNET0900 at 85). Doc: `COBOLNET_OO_DESIGN.md` BASE paragraph.
