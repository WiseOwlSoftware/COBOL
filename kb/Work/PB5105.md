# PB5105 - at --std 85 MOVE CORRESPONDING accepts a level-66 operand and a USAGE IS INDEX group; 1985 forbids level-number 66, 77 and 88 and USAGE IS INDEX in the description of either operand of all three CORRESPONDING statements

**Sites:** none (not located: the records name no site and the implementer locates the MOVE CORRESPONDING member)

**Mechanism.** MOVE CORRESPONDING accepts a level-66 sending operand, a level-66 receiving operand, and a group described USAGE IS INDEX as either operand at --std 85, and moves. ADD and SUBTRACT CORRESPONDING refuse the same level-66 operand (COBOL1757). kb/Work PB966 made MOVE CORRESPONDING accept a level-66 alias for the 2023 text; the 1985 edition forbids it (the record cites GR3 of §1985:VI.6.4.3, which governs MOVE, ADD and SUBTRACT CORRESPONDING alike). A level-66 RENAMES item is a group item (§1985:VI.5.11.4 GR1), so the "must be group items" rule (COBOL1757) does not catch it.

**Found by.** The 1985 MATCH confirmation pass (kb/Work PB4995 item 3): each rule below is a corrected draft (a "redraft") that the compiler at `--std 85` still fails (redraft_run MISMATCH). Harm and observed text are the records; nothing here was re-derived.

**Inventory.** The traceability inventory carries no 1985 rows yet (PB5094: work.py refuses 1985 ids), so `inventory_rows` is empty; the rows this note covers are the 1985 rule ids listed below (catalog `docs/rearchitecture/spec-rule-catalog-1985.json`).

**Rules (1; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-GR-VI.6.4.3-3` - `§1985:VI.6.4.3` (record harm: under-rejects, slice-09): "The description of D1 and D2 must not contain level-number 66, 77, or 88 or the USAGE IS INDEX clause" . The corrected draft MOVEs CORRESPONDING a level-66 RENAMES A THRU B to a group (line 13); the first draft used a level-77 item, which breaks the "group items" rule instead and is refused for that reason.
