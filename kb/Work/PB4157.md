# PB4157 — LocateFile returns two spellings of one path

**Sites:** `src/WiseOwl.Cobol.Frontend/Pipeline/CompilationInputs.cs:122` (`CompilationInputs.LocateFile`).

Review lead R1-1 (low, not blocking at round 1) of the PB1680 branch (PB1680 is held by an in-flight group, so this is a new note
that names it). `LocateFile` rebuilds the located path as `Path.Combine(directory ?? "", spelledAs)` only when the directory entry's
spelling differs from the probe's; an exact-spelling hit returns `path` verbatim. `Path.GetDirectoryName` on Windows normalizes every
separator to a backslash, so one file gets two path strings depending on how it was reached. The `alreadyIncluded` set
(`FoldComparer`: it folds case, not separators) then fails to recognize the second spelling as the first, and a circular COPY is
missed by one level before it is detected. The note and DEVLOG claim that "a directory component keeps the user spelling" is false
for that rebuilt path.

Fix: return one canonical string for a file, whichever branch finds it (keep the directory part as the caller wrote it, and change
only the final name, by replacing the name in the original string rather than recombining), or compare included paths by
normalized form; test with a circular COPY reached through mixed `/` and `\` separators and through both a case-changed and an
exact entry spelling. Correct the note's and DEVLOG's wording in the same change.
