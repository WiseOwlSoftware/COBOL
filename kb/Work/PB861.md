# PB861 — OPEN — a green assertion that is a tautology

Source: the `PB771` implementer report, item (b). Pre-existing, in
`tests/Cobol.Net.Tests.Unit/FileLockPostureDriftTests.cs`. PB771 moved it onto the ACCESS axis so it at least
ranges over the right domain, and deliberately did not rewrite a test outside its mechanism.

## The mechanism

```
exShare = FileLockPosture.For(exS, [incAccess])        // For(...) = base | Admitting(...)
assert exShare.HasFlag(Admitting(incAccess))           // (x | y).HasFlag(y) is true for all x, y
```

The assertion is entailed by the construction of its own subject, in both directions. It is green today and it
would be green against any implementation of `For` that keeps the `|`.

## Why it matters

`feedback_green_gates_arent_evidence`: the suite carries this as one of the symbolic theorems that protect the
OPEN-sharing matrix, and a reader counting theorems counts it. Its neighbour
`DeterminedModesNeedNoWidening` IS non-vacuous (PB771 strengthened it — it now quantifies over the accesses a
handle may take, and would have caught the widening bug symbolically), so the fix is to make this one quantify
over something its subject does not already guarantee: build the posture from the DECLARED sharing mode and
assert admissibility against the OTHER connector's access, with the mutual direction asserted independently.

## The bar for the fix

Mutate `FileLockPosture.For` to drop the `Admitting(...)` term and the test must FAIL. If it still passes, the
rewrite did not fix it.

## Sibling sweep the fixer owes

* The other `FileLockPostureDriftTests` assertions built from `For(...)` — the same construction, the same
  question.
* Any drift test in the suite whose assertion re-applies the function it is testing; that is the general shape,
  and one grep for `Assert.*\b(For|Of|Build)\(` in the drift tests finds the population.
