# PB3812 — the register reader leaves YAML escapes in a value

**Sites:** `scripts/spec/work.py#parse_frontmatter`, `scripts/spec/work.py#_scalar`, `scripts/spec/work.py#_YAML_ESCAPES`, `scripts/spec/work.py#frontmatter_errors`, `scripts/spec/work.py#scalar_findings`, `scripts/spec/work.py#self_test`, `tests/version-matrix/work-frontmatter-cases.json`

## Measured

`scripts/spec/work.py#parse_frontmatter` reads a one-line scalar with `v.strip('"')`, so a double-quoted title keeps its
escapes (`\"`, `\\`) as visible characters. The abandoned w20261703b implementer measured 236 titles carrying a visible
backslash. A fix was drafted there and never committed. Its diff is saved at
`E:\COBOL-coord\scratch\mythos\w20261703b-abandoned-wip.patch`; **the starting point is the `_scalar` / `_YAML_ESCAPES`
hunk of `scripts/spec/work.py` and its cases in `tests/version-matrix/work-frontmatter-cases.json`**. The rest of that
patch is the Obsidian-view work the owner retired (PB3799, PB3789) and is NOT part of this note.

## Acceptance

- A double-quoted one-line scalar is decoded by YAML's double-quote escape rules (at least `\"`, `\\`, and the others the
  YAML 1.2 spec defines) in the one reader; an unknown escape is an error code in `_errors`, never a silent pass (the
  reader's fail-open doctrine).
- `work-frontmatter-cases.json` carries a case per escape and a malformed one; `work.py --self-test` passes; a measured
  before/after count of titles with a visible backslash across kb/Work is in the report (236 to 0).
- Sweep: any other reader of register frontmatter (census.py, file_census_notes.py) goes through `parse_frontmatter`
  (PB3196 shape).

## Landed (wave 20261752 group A)

Re-probe on the tree: 279 titles read with a backslash in them (the 236 above had grown). `parse_frontmatter` now reads a
one-line scalar through `_scalar`: a double-quoted value is decoded by YAML 1.2 section 5.7's escapes (`\"`, `\\`, `\0 \a
\b \t \n \v \f \r \e`, space, `\/`, `\N \_ \L \P`, `\xNN \uNNNN \UNNNNNNNN`), a single-quoted value with `''` as a
quote. A backslash YAML does not define is the error code `unknown-escape:<key>`, and an opening quote that never closes
is `unterminated-quote:<key>`; both land in `_errors` (the value kept as written) and `work.py check` reports them by
code (`frontmatter_errors`, one place for every code: the unterminated-list message moved there from
`closes_rows_shape`). The check found four real notes whose titles held an undefined escape (a Windows path: PB1564,
PB2482, PB2483, PB897), and their titles now double the backslashes.

Measured on `kb/Work`, counting the titles whose read value shows an escape artifact (`\"` or a doubled backslash, which
the old reader left in): 279 before, 0 after; 17 titles still show a single backslash because they genuinely name a
Windows path. `work-frontmatter-cases.json` gained a `scalars` section (32 cases: every escape the reader defines, the
single-quoted forms, the three malformed forms) and one note-level case for `unknown-escape:title`; `--self-test`
demands a case for each key of `_YAML_ESCAPES` and falsifies the scalar comparison. Sweep: the other readers of register
frontmatter (`census.py`, `file_census_notes.py`, `clusters.py`, `backfill_closes_rows.py`, `gen_ledger.py`) all call
`parse_frontmatter`; no other module strips quotes from a frontmatter value.
