# PB4816 - the converter, rebuilt

**The defect.** The 2023 converter lives in the private repository as `specs-private/scripts/convert_pdf.py`, `fix_pages.py` and
`retry_failed.py` (plus `build_links.py` and `validate_doc.py`): hard-coded paths into a retired checkout (its OCR'd PDF
and an unversioned `ISO_COBOL.md`), a retired model (`claude-sonnet-4-6`), one synchronous call per page, the deprecated `fitz` import, a
prompt asking for prose descriptions of figures, and resume logic that re-reads the output file. None of it can convert
1985 or 2002.

**The measured replacement (2026-11-06).** The Mythos session converted 10 pages of the 1985 PDF with Opus 5.5 and Sonnet 5.5,
then submitted all 976 pages as two Message Batches with a restartable script (owner-approved). The script and its prompt
are the starting point: `E:\COBOL-coord\scratch\transcribe-1985\batch1985.py` and `pilot1985_prompt.py`. Measured: about
5,240 input tokens per page image (2,576 px long edge, grayscale PNG), $0.042 per page at Opus 5.5 standard rates
(half through batches); Sonnet 5.5 got the words and underlines right but drew general formats wrongly, so the model is
Opus 5.5. Batches are capped at 256 MB, so the converter splits under a 180 MB budget.

**The fix.** One tool, `scripts/spec/transcribe_pdf.py`, with subcommands `submit`, `status`, `collect`, `retry` and
`pages <list>` (re-convert named pages: what `fix_pages.py` did), taking `--edition` (the PDF and the output come from
`spec_pdf`, PB4815) and a state directory:
- **Restartable with minimal loss:** state written atomically (temp file plus rename) before and after every batch create;
  a crash between create and the write is reconciled from the server's batch list; `collect` takes each ENDED batch as soon
  as it ends, writes each page once and never overwrites; `retry` resubmits errored, expired, cut-off (`stop_reason` other
  than `end_turn`) and missing pages; SDK retries raised for network errors. Every subcommand can be re-run at any time.
- **The key** is read from a file named by `--api-key-file` (first non-empty line) and handed to the SDK client only, never
  printed, logged or written to state. Reuse `fuzz_claude.read_api_key` by moving it to one shared place, not a copy.
- **The prompt** is the pilot's: transcribe exactly, standard's defects as printed, omit only the per-copy stamp, general
  formats inside `<pre>` with `<u>` underlines and the box-drawing brackets and braces of FIGURE-STYLE.md. It names the
  edition. It carries no "licensed owner" wording.
- **Assembly** (`build_links.py`, `validate_doc.py`'s jobs) becomes edition-aware in the same tool or a sibling in
  `scripts/spec/`, writing `## Page N` sections into the edition's Markdown.
- **Cost guard:** `--max-usd` refuses a submit whose estimate (pages x measured tokens) exceeds it.
- The five `specs-private/scripts/*.py` files are deleted (a specs-private commit, the submodule pointer bumped in the
  same change), and `specs-private/WHERE-IS-THE-MARKDOWN.md` points at the new tool.
- Self-test on a planted 2-page PDF with the SDK client replaced by a fake: submit, a simulated crash after create, resume
  adopts the batch, collect, retry of an errored page. **It makes no API call.**

**Sites:** `scripts/spec/transcribe_pdf.py` (whole: new); `scripts/spec/test_transcribe_pdf.py` (whole: new); `scripts/api_key.py` (whole: new, the shared key reader moved here from fuzz_claude); `scripts/fuzz_claude.py` (`use_api_key_file`); `scripts/fuzz_batch.py` (`client_for`); `specs/ANSI_COBOL_1985.md` (whole: assembled); `specs/README.md`; `docs/DOC_INDEX.md`; `specs-private/scripts/convert_pdf.py`, `fix_pages.py`, `retry_failed.py`, `build_links.py`, `validate_doc.py` (whole: to be deleted, replaced by transcribe_pdf.py); `specs-private/WHERE-IS-THE-MARKDOWN.md` (whole: to point at the new tool). `scripts/differential_fuzz.py` (`main`) needed no change: it reaches the key through the shared reader.

**Re-scoped 2026-11-06, after the conversion finished (owner: "yes, go ahead with all the steps").** The raw 1985 pages already
exist (976 of 976, all LF, in `E:\COBOL-coord\scratch\transcribe-1985\pages\`). 971 came from the batch (`state.json`) and five
from a local model (`local.json`; PB4812 "The five pages, converted locally"). The tool therefore also:
- **Adopts an existing state directory.** It reads `state.json`, `local.json` and `pages/` as they stand, never resubmits a page
  that is already written, and never calls the API for 1985. The raw pages move into a tracked location only if they carry no
  stamp (`verify_publishable`); otherwise they stay private.
- **Has a local backend.** `pages <list> --local <ollama model>` does what `local1985.py` did: the same render and prompt sent to
  a local vision model, provenance (model, digest, time, tokens) recorded per page, and the outer code fence removed. The page
  footer check `check_local.py` performs (word agreement with the OCR layer, printing numbers only) becomes its `check`
  subcommand. A page is written only when it passes the stamp check.
- **Writes LF** (`newline="\n"`) for every page and state file.
- **Assembles** `specs/ANSI_COBOL_1985.md` from the pages, in the 1985 document's own structure: modules and level numbering,
  `## Page N` anchors, and the two amendments marked. The Preface and reconciliation are PB4850's. The general formats are
  PB4849's: assembly keeps the batch's drawn figures as they are, for PB4849 to cross-check.
- Runs on the real 1985 pages for assembly. The self-test still uses a planted 2-page PDF and a fake client, and makes no API call.

The scratch scripts (`batch1985.py`, `local1985.py`, `check_local.py`, `pilot1985_prompt.py`) are the starting point. They are
deleted from the scratch directory once the tool replaces them.
