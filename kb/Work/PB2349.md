# PB2349 — P15 Cut 3: the runtime namespace flip and the static runtime facades' deletion

**Wave kind:** Move and rename + Delete (one wave: the flip and the facade retirement are one emitted-surface change). **Model:** Sonnet rewriter for the move and the deletions; Opus for the one reviewed re-baseline (kb/Work R69 §4; DESIGN-architecture-review §8.3 (7)).

**What the plan says** (`docs/COBOLNET_REARCHITECTURE_PLAN.md`, PHASE-15 Cut 3): `RootNamespace` in `src/Cobol.Net.Runtime/Cobol.Net.Runtime.csproj` becomes `Cobol.Net.Runtime` (and the csproj banner is updated); every `src/Cobol.Net.Runtime/**/*.cs` changes `namespace CobolNet.Runtime[.X]` to `namespace Cobol.Net.Runtime[.X]`; the `RuntimeApi` façade is the ONE place the emitted `using` namespace is produced, and it flips with it; `Generated/` regenerates clean; a representative program compiles, shows the new `using`, and runs byte-identically. **Item 4a** (owner-ratified 2026-07-16, `DESIGN-runtime-library.md` §6 Q3): the P8 delegating facades (`ProgramRegistry`, `ExceptionState`, `ExternalStore`, `CobolModule`, `ExternalSwitches`, `CobolFile`, `AcceptSource` statics) are DELETED at Cut 3; emitted code reaches the instances through the run-unit driver's ONE captured `RunUnit` local (capture-once, never a per-statement `AsyncLocal` read on hot paths), routed via the `RuntimeApi` façade, so the retirement and the flip are one emitted-surface change and ONE reviewed characterization re-baseline. Cuts 1, 2 and 2.5 are decoupled from v1.0 and done or running as cluster PB2108; v1.0 keeps Cut 3 and the §4.2.16 documentation (R69).

**What DESIGN-architecture-review adds** (§8.2, "Cut 3 is more than a `using` line"): the emitted bodies name runtime types fully qualified inline. The oracle blobs carry `CobolNet.Runtime.Exceptions.ExceptionCatalog.IsFatalIoStatus` 6,249 times (from `CodeGen/Verbs/IoStatusClass.cs`) and `CobolNet.Runtime.IO` 1,185 times, so Cut 3's oracle difference is every case that emits an I-O status check or a qualified runtime name, not one line per case. The plan's Cut 3 already routes every runtime reference through the `RuntimeApi` façade and takes ONE reviewed re-baseline; §8.3 (9) keeps that true by making the façade the `RuntimeAbi` catalogue first. The external-repository design's `CobolNet.Runtime.Repository` attribute family is spelled under the runtime root and follows Cut 3 mechanically; nothing in that design is reopened. §8.3 (7): the `ExceptionEngine` split (PB2309) is the same wave as this one: both notes carry the same `blocked_by` and name `src/Cobol.Net.Runtime/Exceptions/ExceptionState.cs`, so `plan_wave.py --cluster PB2119` groups them (R1 Draft 3, verified by its dry run), and the facade deletion (this note) and the engine split (PB2309) change the emitted exception calls ONCE, under the one re-baseline; neither lands alone. The static `ExceptionState` facade's deletion is this note's, never PB2309's.

**The wave's contract:** every caller changes in the same change (CLAUDE.md rule 4: no alias, shim or forwarder); the drift tests that pinned the old names go with them or get new ones; the §4 oracle (`python scripts/arch/compare_oracle.py`) lists the explained differences above and the one re-baseline is reviewed by Opus before it is recorded; a change that changes behavior is a `kind: defect` lead for the fix lane, never part of the wave (PB2119).
