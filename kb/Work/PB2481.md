# PB2481 — the ledger artifact URL is a literal

Owner, 2026-10-07 13:17 PDT: a second Claude Code session, logged into a second Max 20x account (`CLAUDE_CONFIG_DIR=C:\Users\brent\.claude-acct2`), runs every Opus/Sonnet dispatch, the orchestrator loop and the landings (the OPERATOR); the first account's session keeps Mythos work. The owner seeded the second config dir by hand. Owner 13:36 PDT: account 2's week resets Saturday 2026-10-10 10:00 PDT and must be spent to 100 % before then, so every hour the tooling stops dispatch wrongly is quota lost.

**Model:** Opus (tooling with self-tests). All six notes are one mechanism (the account is a parameter of the coordination tooling, never an assumption) and are dispatched as one group.

## Defect

`scripts/spec/gen_ledger.py:1195` prints `publish: Artifact tool, action publish, url
https://claude.ai/code/artifact/7677f3c0-d6cf-41a2-a7c3-7d83c5fdbaee`. An artifact belongs to the account that
published it; account 2 cannot update account 1's. The operator published the ledger to
https://claude.ai/artifact/2Gy9JUzVP1A7KRUE91y9Gy on 2026-10-07 13:33 PDT.

## Shape

The URL lives in `E:\COBOL-coord\ledger_state` (or `ledger-published.json`), keyed by account (PB2478's account
resolver); `ledger_state.py mark-published --url <url>` records it; `gen_ledger.py` prints the current account's URL
or "no artifact yet for this account: publish a new one and record it". Also from the r1 landing leads: the default
`--out` is still `conformance-ledger.html` — make it `{COORD}\ledger.html`.


## Landed (branch acct2-tooling, wave 1033 group T)

Re-probed on this tree before the change: `gen_ledger.py` ended with the literal account-1 URL
(`7677f3c0-…`) whatever account ran it, and `--out` defaulted to `docs/rearchitecture/evidence/conformance-ledger.html`.

- `ledger-published.json` is keyed by account (`{"accounts": {<name>: {url, stamp, published_at}}}`, the account from
  `account.py`). `ledger_state.py owed` compares the running account's stamp and names its URL or says it has none;
  `mark-published --url <url>` records the account's artifact the first time (refused without one), later marks keep
  it; `ledger_state.py url` prints where to publish. A record from before 2026-10-07 (unkeyed, no URL) anchors no
  account and is dropped by the next mark.
- `gen_ledger.py` prints `ledger_state.publish_hint` for the running account instead of the literal URL, and writes
  `<coord>\ledger.html` by default (`coord.coord_path()`, which names the directory without creating it; `coord_dir`,
  `global_stop` and `ledger_plan.measure_pacing` use it, removing two copies of the env-or-default rule).
- The supervisor's LEDGER PUBLISH OWED line and the workstream SKILL say to publish to the account's artifact.
- `test_ledger_state.py`: the legacy record ignored, the first mark refused without `--url`, per-account URLs and
  stamps independent, a later mark keeps the URL, the file rewritten in the keyed shape.
- Operator action owed after this lands (the live state file is not this branch's to write): `python
  scripts/orchestrator/ledger_state.py mark-published --url https://claude.ai/artifact/2Gy9JUzVP1A7KRUE91y9Gy` from the
  account-2 session (the artifact it published 2026-10-07 13:33), so the next owed check names it.
