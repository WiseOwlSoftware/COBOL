# PB5200 - the open-mode USE procedures see a stale or missing being-opened mode: after a failed OPEN the attempted mode stays recorded until a successful CLOSE, and an OPEN refused for CLOSE WITH LOCK (38) never records it

**Sites:**

- `src/WiseOwl.Cobol.Runtime/IO/FileConnector.cs` (`OpenModeView`, `OpenOnceEntered`)
- `src/WiseOwl.Cobol.Runtime/IO/FileRegistry.cs` (`SharedOpenAttempt`)
- `src/WiseOwl.Cobol.Compiler/CodeGen/UseTierEmitter.cs` (`EmitScopeTiers`)

**Mechanism.** §1985:VII.4.6.4 GR5 makes a USE ... ON INPUT, OUTPUT, I-O or EXTEND procedure applicable to a file open in that mode "or in the process of being opened" in it. The open-mode tier (`UseTierEmitter.EmitScopeTiers`) asks `FileConnector.OpenModeView`, and the being-opened state is wrong both ways. (1) `OpenOnceEntered` records the mode of an OPEN that fails and nothing clears it until a successful CLOSE, so a later READ (47) or WRITE (48) of the file that is not open runs the INPUT or EXTEND procedure, which the same statement before any OPEN does not (1985-GR-VII.4.4.4-11, 1985-GR-VII.4.7.4-10). (2) The closed-with-lock arm of `FileRegistry.SharedOpenAttempt` sets 38 and returns before `FileConnector.Open`, so the attempted mode is never recorded and no mode procedure runs for the OPEN itself (1985-GR-VII.4.3.4-26). Both are probed the same at --std 2023.

**Expected (from the 1985 text, the record's).** READ BEFORE ANY OPEN 47 / USE INPUT 35 / OPEN INPUT 35 / READ AFTER FAILED OPEN 47: the second READ runs no USE procedure, as the first does not. §1985:VII.4.4.4 GR11 b: "control is transferred according to rules of the USE statement following the execution of any USE AFTER EXCEPTION procedure associated with the file connector referenced by file-name-1"; §1985:VII.4.6.4 GR5 b: "If INPUT is specified, the associated procedure is executed when the condition described in the USE statement occurs for any file open in the input mode or in the process of being opened in the input mode". After the OPEN has failed (35) the file is neither open in the input mode nor being opened.

**Observed (the record's).** exit 0; READ BEFORE ANY OPEN 47 / USE INPUT 35 / OPEN INPUT 35 / USE INPUT 47 / READ AFTER FAILED OPEN 47: the READ after the failed OPEN runs the USE ... ON INPUT procedure (the same at --std 2023).

**Fix direction (root cause, CLAUDE.md rule 4).** Make the being-opened mode a property of the OPEN statement's execution, set when the OPEN begins (before any refusal) and cleared when it ends, held apart from the file's open mode; OpenModeView answers the open mode, or the being-opened mode only while an OPEN is executing. One state, one owner, both defects gone.
