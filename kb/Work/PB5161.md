# PB5161 - at --std 85 FUNCTION NUMVAL-C applies the 2023 content bans to argument-2 (digits, * + - , . and CR or DB): a literal such as CRC or Fr. is refused (COBOL1627) and a data item holding one makes the function return 0

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs` (`BindNumvalCFamily`)
- `src/WiseOwl.Cobol.Runtime/Intrinsics/CobolIntrinsics.Exact.cs` (`InvalidCurrency`, `NumvalCDec`)
- LANDED: `src/WiseOwl.Cobol.Runtime/Control/DialectBehavior.cs` (`DialectBehavior.NumvalCCurrencyContentRules`, 2002, VCR 7.58); `src/WiseOwl.Cobol.Runtime/Intrinsics/CobolIntrinsics.Exact.cs` (`CurrencyStringViolatesContentRules`, the one copy of the rule that `InvalidCurrency` became, `NumvalCDec`'s `contentUnrestricted`, `TestNumvalC`); `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs` (`BindNumvalCFamily`); `src/WiseOwl.Cobol.Compiler/Binding/Bound/BoundTree.cs` (`BoundIntrinsicCall.CurrencyContentUnrestricted`); `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/IntrinsicRenderer.cs` (the `NumvalC` arm of `RenderDec`)

**Mechanism.** The 1989 intrinsic function module asks of NUMVAL-C argument-2 only its class (§1989:A.2.30.3 AR4) and defines cs as the string of one or more characters it specifies (§1989:A.2.30.3 AR1); it puts no rule on the characters. The compiler applies the later content bans at every edition, twice: `IntrinsicBinder.BindNumvalCFamily` refuses a literal argument-2 holding a digit, one of * + - , . or the pair CR or DB (COBOL1627), and the runtime `InvalidCurrency` makes `NumvalCDec` return 0 for a data item holding one. A legal 1989 program with currency string "CRC", "Rs." or "Fr." is refused, or silently computes 0.

**Found by.** The 1985 code read (2026-11-10; its records are `E:/COBOL-coord/scratch/coderead-85/for-register.json`): each rule below was read against the code sites it names and probed at `--std 85`, and found non-conforming. Verdict, harm, evidence, repro and observed text are the records'; the rows' verdicts are recorded on another branch.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids of the list below.

**Rules (2; every citation checked with `scripts/spec/cite.py --check`).**

- `1989-AR-A.2.30.3-1` - `§1989:A.2.30.3 AR1` (record verdict: DIVERGES, harm: rejects-legal-source). Checked: §1989:A.2.30.3 AR1: "the string of one or more characters specified by argument-2". Code sites read: src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs#BindNumvalCFamily; src/WiseOwl.Cobol.Runtime/Intrinsics/CobolIntrinsics.Exact.cs#InvalidCurrency; src/WiseOwl.Cobol.Runtime/Intrinsics/CobolIntrinsics.Exact.cs#NumvalCDec; src/WiseOwl.Cobol.Runtime/Intrinsics/CobolIntrinsics.Exact.cs#NvScan; src/WiseOwl.Cobol.Compiler/Binding/IntrinsicArgumentRules.cs#Verified. Code read: No kb/Work note owns the fix. §1989:A.2.30.3 AR1 defines cs as "the string of one or more characters specified by argument-2", and §1989:A.2.30.3 AR4 asks only that argument-2 be "a nonnumeric literal or alphanumeric data item". The compiler applies §2023:15.68.3 AR2's content bans at every edition ("Argument-2 shall not contain any of the digits 0 through 9", the characters * + - , . and the letter pairs CR and DB): BindNumvalCFamily refuses such a literal argument-2 with COBOL1627, and the runtime InvalidCurrency makes NumvalCDec return 0 for such a data item. So at --std 85 a currency string such as "CRC" or "Rs." is refused or yields 0 where argument-1 has the 1989 format. The rest of the rule conforms: the Verified row's class and category screen refuses numeric, alphabetic and edited argument-1, and NvScan accepts both 1989 formats (leading sign before cs, trailing + - CR DB, comma groups, ".75"). The row's change record does not list this 2023 restriction. The witness uses the currency string "$".
- `1989-AR-A.2.30.3-4` - `§1989:A.2.30.3 AR4` (record verdict: DIVERGES, harm: rejects-legal-source). Checked: §1989:A.2.30.3 AR4: "Argument-2, if specified, must be a nonnumeric literal or alphanumeric data item.". Code sites read: src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs#BindNumvalCFamily; src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs#CheckArgumentClasses; src/WiseOwl.Cobol.Compiler/Binding/IntrinsicArgumentRules.cs#Verified; src/WiseOwl.Cobol.Compiler/Binding/IntrinsicArgumentRules.cs#Violation; src/WiseOwl.Cobol.Runtime/Intrinsics/CobolIntrinsics.Exact.cs#InvalidCurrency. Code read: No kb/Work note owns the fix. §1989:A.2.30.3 AR4: "Argument-2, if specified, must be a nonnumeric literal or alphanumeric data item." The 1989 text puts no rule on the content of argument-2 (§1989:A.2.30.3 AR1: "cs is the string of one or more characters specified by argument-2"). The class half conforms at 85: CheckArgumentClasses screens the Verified NUMVAL-C row and Violation refuses a numeric literal (the witness), a numeric item and an arithmetic expression with COBOL1627, and accepts an alphanumeric item and a group. The content half does not: BindNumvalCFamily applies §2023:15.68.3 AR2's bans ("Argument-2 shall not contain any of the digits 0 through 9", the characters * + - , . and CR or DB) to a literal argument-2 with no edition arm, and the runtime InvalidCurrency applies them to a data item, so at --std 85 a nonnumeric literal such as "Fr." or "C1" is refused and a data item holding one makes the function return 0. The same mechanism is recorded on 1989-AR-A.2.30.3-1. Probed also at 85: an alphabetic (PIC A) argument-2 is refused with COBOL1627, which fits the rule's words "alphanumeric data item".

**Expected (from the 1985 text, the record's).** The program compiles and displays 00012.50: §1989:A.2.30.3 AR4 "Argument-2, if specified, must be a nonnumeric literal or alphanumeric data item." ("Fr." is a nonnumeric literal), §1989:A.2.30.3 AR1 "cs is the string of one or more characters specified by argument-2", and §1989:A.2.30.4 "The returned value is the numeric value represented by argument-1."

**Observed (the record's).** exit 65: NVC2.cob(11,27): error COBOL1627: FUNCTION NUMVAL-C argument-2 shall contain at least one non-space character and none of the digits 0-9, the characters '*' '+' '-' ',' '.', or the letter pair CR/DB in any case (ISO §2023:15.68.3 rule 2). The literal "C1" is refused the same way. With argument-2 a data item (01 WS-F PIC X(3) VALUE "Fr."; 01 WS-B PIC X(8) VALUE "Fr.12.50"; FUNCTION NUMVAL-C(WS-B WS-F)) the program compiles and displays 00000.00 (wrong-answer).

**Fix direction (root cause, CLAUDE.md rule 4).** One rule in one place: the content screen is a property of the edition, so the catalog row (IntrinsicArgumentRules) carries the content bans as an edition-gated predicate that both the binder and the runtime body read through the compiled program's edition, instead of two hard-coded copies. At 85 the function scans for cs as written (the 1989 GR) and returns the value for any currency string.
