# PB4226 — the PB4196 mechanism has two arms not yet worded by the nearer-entry rule

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Validation/SearchAllFormat2Rules.cs#CheckConditionNameSide`, `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs#ResolveClauseOperand`.

**The rule.** §8.4.6.2.1 3): the nearer declaration is the one referenced (`python scripts/spec/cite.py --check 8.4.6.2.1 "3)"` OK; the sub-item `3) a)` does not check as a text anchor, so it is not cited).

**(1)** `SearchAllFormat2Rules.cs` (line 286, in `CheckConditionNameSide`) words a condition-name hidden by a nearer report entry as "misqualified" via `ReferenceResolver.MisqualifiedConditionText`. Still refused; the wording is wrong.

**(2)** `DataBinder.ResolveClauseOperand`, the `inReportSection: true` arm (RD OCCURS DEPENDING ON, call in `DataBinder.Reports.cs`): a name hidden by a nearer report entry may reach the "is declared, but not under the given qualifier" wording. Unprobed; refused either way.

**Fix direction.** Route both through `DataBinder.NearerReportEntryHides`, as PB4196 did for its arms, probe (2) first, and pin each wording with a golden at the four editions. Sweep the other callers of `MisqualifiedConditionText`.

## Arm (1) landed; arm (2) re-probed (wave 20261816, group A)

**Arm (1), re-probe** (`scratch/w20261816a/p4226/sa.cob`): `SEARCH ALL E … WHEN CN`, CN a container's GLOBAL
condition-name and the contained program's own report entry, drew COBOL1965 "'CN' is a condition-name" AND COBOL5092 (the
condition binder's correct verdict); a genuinely misqualified `WHEN EKC OF K` (`sa2.cob`) drew COBOL1965 AND COBOL1639 with
the same text. **Fix:** `SearchAllFormat2Rules.CheckConditionNameSide` no longer words the reference a second time; it
asks `ConditionBinder.ReportMisqualifiedCondition` (the one wording, which already asks `ReportEntryReferenceRefused`
first and reports a reference once). After the fix each probe draws exactly one diagnostic (COBOL5092; COBOL1639).
Sweep: the other callers of `MisqualifiedConditionText` (`ReferenceResolver.ReportUnidentified`,
`ConditionBinder.ReportMisqualifiedCondition`) already ask the report-entry refusal first; `SetBinder`'s Format 4 arm calls
`ReportMisqualifiedCondition`. Pinned by `ReportItemReferenceTests.ASearchAllConditionNameTheReferenceDoesNotReach_IsReportedOnce`
and `conformance:cases/13.8.6.2.3-Report-Items/pb4226-search-all-when-nearer-report-entry`.

**Arm (2), re-probe** (`scratch/w20261816a/p4226/odo.cob`: a container's GLOBAL `05 N PIC 99`; the contained program's
own RD entry `10 N COLUMN 1 PIC 99 SOURCE 5`, then `10 … OCCURS 1 TO 3 DEPENDING ON N STEP 2`): COBOL1639 "'N' is
declared, but not under the given qualifiers" with no qualifier written. Reproduces, but the note's premise "refused
either way" does not hold up against the text: §13.8.6.2.3 bars report items from clauses of OTHER sections only, and no
§13.18.38.3 rule bars a report-section OCCURS DEPENDING ON from naming a report entry (SR17 "shall describe an integer"
holds for `PIC 99`). So the nearer report entry N may be a legal DEPENDING ON object, and the compiler would then refuse
legal source, whatever the wording. That is a resolution question (report-section clause operands never consult report
entries: `ResolveClauseOperand(…, inReportSection: true)`), not a wording one, and is reported as a lead of wave 20261816 A.
This note stays open for arm (2) until that question is settled.
**Sites (added by the landing):** `src/WiseOwl.Cobol.Compiler/Binding/Validation/SearchAllFormat2Rules.cs`
(`SearchAllFormat2Rules.CheckConditionNameSide`), `tests/WiseOwl.Cobol.Tests.Unit/ReportItemReferenceTests.cs`.

## Arm (2) landed (wave 20261819, group A)

**The question settled.** §13.15.3 SR7 (`cite.py --check 13.15.3 "The data-name shall not be referenced in any other
way"` OK): an entry's data-name may be referenced only in a GENERATE statement, a USE BEFORE REPORTING statement, as a
qualifier for a SUM counter, in the UPON phrase of the SUM clause, or as an operand in a SUM clause. An RD's OCCURS …
DEPENDING ON is none of them, so a report entry is never its object and the refusal stands; what was wrong is the rule
named. Re-probe (`scratch/w20261819a/p4226/`): `odo.cob` (the nearer report entry hiding a container's GLOBAL N) drew
COBOL1639 "declared, but not under the given qualifiers"; `lone.cob` (the program's only N a report entry) and `sum.cob`
(a sum counter S) drew COBOL1639 "no declaration in this source element gives the name". After: COBOL5092 for all three,
worded by SR7 alone (a sum counter is told that a SOURCE clause, §13.18.53.3 SR4, or a SUM clause admits it).
**Fix:** `DataBinder.ResolveClauseOperand` asks `ReportEntryReferenceRefused` in the report section as well, passing
`inReportSection`, and the refusal words that position by §13.15.3 SR7 instead of §13.8.6.2.3 (the other sections' rule).
**Sibling sweep** (the report section's other clause operands: `LookupQualified`'s CODE / CONTROL / SUM callers, the
SOURCE screen, the PRESENT WHEN scan; probes `code.cob`, `code2.cob`, `src.cob`): CONTROL has SR2's own wording, SOURCE
SR4's (COBOL2144, one verdict), and a SUM operand may name an entry. The RD CODE clause drew TWO verdicts — COBOL2713
"does not resolve to a data item" and a procedure-phase COBOL5092 under §13.8.6.2.3 — and an undeclared CODE operand
COBOL2713 plus COBOL1639; `ResolveReportCode` now asks the refusal first and `ReportWriterBinder.BindReportClauses` binds
the operand only when its base item resolved. A PRESENT WHEN condition naming a report entry drew SR16's COBOL1559 plus a
procedure-phase COBOL5092; `CheckConditionOperands` records each condition it refuses and the procedure phase's bind
delegate (`ReportWriterBinder.BindReportGroupClauses`) does not bind it. Pinned by
`conformance:cases/13.15-Report-group-description/pb4226-rd-occurs-depending-names-nearer-report-entry` (2002, 2014, 2023)
and `ReportItemReferenceTests.AnRdOccursDependingOnObject_NamingAReportEntry_IsRefusedUnderSr7` /
`AReportSectionClauseNamingAReportEntry_DrawsOneVerdict`.
