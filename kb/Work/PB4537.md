# PB4537 — justified-ignored-for-numeric-sender: MOVE of a longer unsigned numeric DISPLAY item to a JUSTIFIED RIGHT alphanumeric item keeps the leftmost digits

Filed 2026-11-03 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-batch-3000-20261103`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

MOVE of an unsigned numeric DISPLAY item to a shorter alphanumeric item described with JUSTIFIED RIGHT keeps the
LEFTMOST characters, as if JUSTIFIED were absent. ISO requires the leftmost characters to be truncated. The same MOVE from
an alphanumeric sender of the same content is correct, so only the numeric-sender path ignores JUSTIFIED.

## Minimal test case

Free reference format (`-free`).
```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. JUSTNUM.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 N  PIC 9(5) VALUE 12345.
01 X  PIC X(5) VALUE "12345".
01 J  PIC X(4) JUSTIFIED RIGHT.
PROCEDURE DIVISION.
    MOVE N TO J
    DISPLAY "NUMERIC [" J "]"
    MOVE X TO J
    DISPLAY "ALNUM   [" J "]"
    STOP RUN.
```

## Environment

cobc (GnuCOBOL) 3.2.0 on WSL2 Ubuntu. Command: `cobc -x -free -std=cobol2014 -o p justified-ignored-for-numeric-sender.cob && ./p`
(cobc issued no diagnostic, compile exit code 0; the host C compiler's `_FORTIFY_SOURCE redefined` warning is an environment artifact of this WSL install; run directly).

## Observed result

```
NUMERIC [1234]
ALNUM   [2345]
```
Exit code 0. `cobc -C` shows the first MOVE generated as `memcpy (b_3, b_1, 4);`.

## Expected result (per ISO)

§14.9.25.4 6) a): "When an alphanumeric, alphanumeric-edited, national, or national-edited data item is a receiving
operand, alignment and any necessary space filling shall take place" as defined in 14.6.8; the unsigned numeric integer
sender is a valid elementary move to an alphanumeric receiver. §14.6.8.5: "If the JUSTIFIED clause is specified for the
receiving item, alignment differs as specified in 13.18.32, JUSTIFIED clause." §13.18.32.4 1): "When the receiving data item is described
with the JUSTIFIED clause and the sending operand is larger than the receiving data item, the leftmost character positions
or boolean positions of the sending operand shall be truncated." Both rules are in the 2014 edition (JUSTIFIED is an
original COBOL clause; `docs/VERSION_CHANGE_REFERENCE.md` records no change). Expected:
```
NUMERIC [2345]
ALNUM   [2345]
```

## Our compiler

WiseOwl COBOL (fresh judge, `--std 2014 --source-format free`) prints the expected output above, with no diagnostic.

## Fix site

cobc/typeck.c `cb_build_move_field`: when the source is at least as long as the destination, the `CB_CATEGORY_NUMERIC`
case returns `cb_build_move_copy (src, dst)` for an unsigned DISPLAY source and an alphanumeric destination without
testing `dst_f->flag_justified`; the alphabetic and alphanumeric cases of the same switch do test it. libcob's
`cob_move_display_to_alphanum` (move.c) handles JUSTIFIED correctly, so the runtime path is right and only the inline copy
is wrong. Confirmed in the GnuCOBOL 3.2 release source (cobc/typeck.c).

## Draft issue

**Title:** MOVE of a longer unsigned numeric DISPLAY item to a JUSTIFIED RIGHT alphanumeric item keeps the leftmost digits

cobc (GnuCOBOL) 3.2.0, WSL2 Ubuntu, `cobc -x -free -std=cobol2014 -o p prog.cob && ./p`.

```
01 N  PIC 9(5) VALUE 12345.
01 X  PIC X(5) VALUE "12345".
01 J  PIC X(4) JUSTIFIED RIGHT.
...
    MOVE N TO J    *> J = "1234", expected "2345"
    MOVE X TO J    *> J = "2345", correct
```
ISO/IEC 1989:2014 JUSTIFIED clause general rule 1: when the sending operand is larger than the JUSTIFIED receiver, the
leftmost characters of the sender are truncated. The MOVE from N is generated as `memcpy (b_3, b_1, 4)`: in
`cb_build_move_field` the numeric-to-alphanumeric shortcut calls `cb_build_move_copy` without the `flag_justified` test
that the alphabetic and alphanumeric cases have. `cob_move_display_to_alphanum` already handles JUSTIFIED.
