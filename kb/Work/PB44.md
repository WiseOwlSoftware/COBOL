# PB44 — LANDED — a gate that can false-red

> ⚙ **FOUND BY ATTRIBUTING A RED, WHICH IS THE ONLY REASON IT IS HERE.** The [[PB43]] battery came back
> `=== BATTERY: NOT GREEN (rc=1) ===` on **1 failed of 3647** unit tests. Everything else was green —
> Conformance 4201/4201, characterization 33/33, `guard-fast` ALL GREEN, and the differential **0 per-case
> flips**. The temptation with a single red in a 3,647-test leg is to re-run and move on.

**MEASURED — the named mechanism, not "a flake":**

```
GrammarDiagramGeneratorDriftTests.Generator_RunsClean  [FAIL]
  gen-grammar-diagrams.ps1 -Check exited 1
  Exception calling "ReadAllText" with "1" argument(s): "The process cannot access the file
  'E:\Temp\ccf-…\CobolScreen.md' because it is being used by another process."
```

`scripts/gen-grammar-diagrams.ps1` shells out to the vendored `rr.war` to render one fragment's diagrams, then
immediately reads the file java just wrote. **java has exited, but its handle is not always released by the time
PowerShell resumes** — and on Windows an AV scanner can hold the file briefly as well. Serially the window is
invisible; under the battery's `Conformance ∥ Unit ∥ Characterization` load, with the conformance leg spawning
compiles of its own, it widened enough to fire. **Re-run serially: PASS** (1/1).

## ⚖ WHY IT WAS FIXED RATHER THAN RECORDED

§0 already says a high-JOBS parallel leg can FALSE-RED and that the named test should be re-run serially before a
regression is believed. That rule is correct and it is not sufficient: **a gate that can go red without a defect
teaches everyone to discount reds**, and the next real regression arrives looking exactly like this one. The read
now retries with backoff on `IOException` (10 attempts, 50 ms × attempt), which is the smallest change that
removes the failure mode rather than describing it.

⚠ **NOT related to [[PB43]], and that was checked rather than assumed:** the generator renders ANTLR grammar
fragments and touches nothing in the data model, the width surfaces, the image codec or the intrinsics — the only
things PB43 changed. The serial re-run on the SAME tree passing is the second piece of evidence.

⚠ **A residual honesty note:** the retry makes the read robust, it does not prove the generator has no other
handle race. If this test reds again with a different file or a different call, the answer is the same kind of
fix, not a longer backoff on this one.
