# PB3561 — pausing the fuzz run for a game loses the in-flight programs

## Facts (verbatim from the coordinator's diagnosis)

The wrapper (`E:\COBOL-coord\scratch\fuzz-night.ps1`; session scratch, to be moved into `scripts/` by the fix) detects a game
by per-process 3D-engine load, suspends the harness's process tree (NtSuspendProcess), asks `ollama stop <model>` and, since
22:05's fix, ends Ollama's runner process when the model is still resident after 10 s (Ollama's stop waits for in-flight
generations, which kept the GPU pegged for minutes on the first pause). On resume (120 s quiet) the harness's four in-flight
HTTP requests fail with `ollama HTTP 500: an error was encountered while running the model` and `health resp: Get
http://127.0.0.1...` while the runner restarts, and `ollama_chat`'s error path records each as `verdict RUNNER_ERROR`
(`scripts/differential_fuzz.py` about line 1113: `except (RuntimeError, urllib.error.URLError, OSError, TimeoutError) as e:
rec.update(verdict="RUNNER_ERROR", ...)`): rows fz02696, fz02698, fz02699 of run fuzz-20261022-163846.

Owner, 22:1x PDT: "Clearly the script did not pause and resume losslessly as it should have". Owner's bar (11:05): no hack.

## Fix shape (lossless pause is the harness's job; the wrapper only signals)

1. The harness honors a PAUSE file (for example `<run dir>/PAUSE`, path printed at start): between programs a worker waits
   while it exists. A worker whose in-flight request fails while PAUSE exists, or whose failure is a runner restart (HTTP
   500 model error, health-check error, connection refused), RE-QUEUES the program for one retry after the pause instead of
   recording a verdict. Only a failure outside a pause, or a second failure, records RUNNER_ERROR with the reason.
2. The wrapper creates PAUSE first, then (after a short grace for workers to notice) suspends nothing: it ends the runner to
   free the GPU at once (the harness's workers see the failure, see PAUSE, and re-queue), and removes PAUSE on resume. The
   model reloads on the next request.
3. The run's report counts paused time and re-queued programs, so the morning reads them as pauses, not as the model's
   failures.
4. Self-test with a stubbed Ollama: a request failing under PAUSE is retried once after PAUSE clears and recorded by its
   retry's verdict; the same failure without PAUSE records RUNNER_ERROR.
5. The wrapper moves into `scripts/fuzz_night.ps1` (a tracked tool, not scratch) with its own self-test of the
   game-detection and pause/resume logic against a stubbed counter feed.

**Sites:** `scripts/differential_fuzz.py` (`ollama_chat`, `Fuzz._one`, `Fuzz.run`, `render_report`, `self_test`), `scripts/fuzz_night.ps1`. The second is a new file: the night wrapper moves into the tree out of the coordination scratch.
