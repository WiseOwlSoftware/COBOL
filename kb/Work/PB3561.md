# PB3561 — pausing the fuzz run for a game loses the in-flight programs

## Facts (verbatim from the coordinator's diagnosis)

The wrapper (`E:\COBOL-coord\scratch\fuzz-night.ps1`; session scratch, to be moved into `scripts/` by the fix) detects a game
by per-process 3D-engine load, suspends the harness's process tree (NtSuspendProcess), asks `ollama stop <model>` and, since
22:05's fix, ends Ollama's runner process when the model is still resident after 10 s (Ollama's stop waits for in-flight
generations, which kept the GPU pegged for minutes on the first pause). On resume (120 s quiet) the harness's four in-flight
HTTP requests fail with `ollama HTTP 500: an error was encountered while running the model` and `health resp: Get
http://127.0.0.1...` while the runner restarts, and `ollama_chat`'s error path records each as `verdict RUNNER_ERROR`
(`scripts/differential_fuzz.py` about line 1113: `except (RuntimeError, urllib.error.URLError, OSError, TimeoutError) as e:
rec.update(verdict="RUNNER_ERROR", ...)`): rows fz02696, fz02698, fz02699 of run fuzz-20261022-163846.

Owner, 22:1x PDT: "Clearly the script did not pause and resume losslessly as it should have". Owner's bar (11:05): no hack.

## Fix shape (lossless pause is the harness's job; the wrapper only signals)

1. The harness honors a PAUSE file (for example `<run dir>/PAUSE`, path printed at start): between programs a worker waits
   while it exists. A worker whose in-flight request fails while PAUSE exists, or whose failure is a runner restart (HTTP
   500 model error, health-check error, connection refused), RE-QUEUES the program for one retry after the pause instead of
   recording a verdict. Only a failure outside a pause, or a second failure, records RUNNER_ERROR with the reason.
2. The wrapper creates PAUSE first, then (after a short grace for workers to notice) suspends nothing: it ends the runner to
   free the GPU at once (the harness's workers see the failure, see PAUSE, and re-queue), and removes PAUSE on resume. The
   model reloads on the next request.
3. The run's report counts paused time and re-queued programs, so the morning reads them as pauses, not as the model's
   failures.
4. Self-test with a stubbed Ollama: a request failing under PAUSE is retried once after PAUSE clears and recorded by its
   retry's verdict; the same failure without PAUSE records RUNNER_ERROR.
5. The wrapper moves into `scripts/fuzz_night.ps1` (a tracked tool, not scratch) with its own self-test of the
   game-detection and pause/resume logic against a stubbed counter feed.

**Sites:** `scripts/fuzz_ollama.py` (`PauseGate`, `lossless`, `read_pauses`, `runner_failed`, `OllamaError`, `repeat_abort`),
`scripts/differential_fuzz.py` (`Fuzz.__init__`, `Fuzz._one`, `Fuzz.run`, `render_report`, `self_test`),
`scripts/fuzz_night.ps1` (moved from the session scratch `E:\COBOL-coord\scratch\fuzz-night.ps1`), `scripts/fuzz_night_lib.ps1`,
`scripts/test_fuzz_night.ps1`

## Landed (2026-10-26, wave 20261711 group A)

Re-probed on the dispatch base: the error path of `Fuzz._one` still recorded every failed generation as a terminal
`RUNNER_ERROR`, and the wrapper existed only as session scratch. One mechanism, the five items of the note, as built:

1. **The harness honors `<run dir>/PAUSE`** (`PauseGate`; the path is printed at the start and recorded in `run.json`). A
   worker waits for it before every generation, which covers "between programs". `lossless` asks a generation AGAIN once when
   it fails while PAUSE exists or with a runner failure (`runner_failed`: a 5xx, an error line or a stream cut after the
   reply began, a refused or reset connection; a runner failure with no pause first waits 15 s for the runner to restart).
   A failure outside a pause that is no runner failure, or the second failure, is the row's `RUNNER_ERROR`, naming both
   failures. Beyond the note: PAUSE is a LEASE (the wrapper rewrites it every poll; one not rewritten for 300 s belongs to a
   dead wrapper and is ignored with a message), so a wrapper killed mid-pause cannot hang the night.
2. **The wrapper creates PAUSE first, then ends the runner** (after a 5 s grace for a worker between its check and its
   request), suspends nothing, rewrites PAUSE as the lease, and removes it after 120 quiet seconds.
3. **The report counts them**: `pauses.jsonl` (one pause and one resume event each), a `Pauses:` line in `report.md` (count,
   minutes, generations asked again, programs) and `requeued` / `requeue_reasons` on the row.
4. **Self-tests with a stubbed Ollama** (`fuzz_ollama.py --self-test`: a real socket server, plus `lossless` and `PauseGate`
   on an injected clock) and through `Fuzz._one` (`differential_fuzz.py --self-test`): a generation failing under PAUSE is
   asked again after it and judged; the same failure with no pause and no runner failure records `RUNNER_ERROR` at once; a
   second failure records it naming the first.
5. **`scripts/fuzz_night.ps1` is a tracked tool**, its logic in `scripts/fuzz_night_lib.ps1` and its self-test
   `scripts/test_fuzz_night.ps1` (a stubbed counter feed through the game detection, the state machine and the pause actions;
   the order PAUSE before the runner; the lease; the spelling of `PAUSE` agreeing with `fuzz_ollama.PAUSE_FILE`; and a guard
   that the lib reads nothing it was not passed). Running the real wrapper found what the self-test could not: a lib
   parameter named `$Log` shadowed the wrapper's `$Log` (PowerShell scopes dynamically) and the first real poll died; the
   parameter is `$Say` now and the guard holds the class. The wrapper also survives a run with no console.

End to end on this machine (real Ollama, qwen3-coder:30b, the judge build, 4 programs, 2 jobs): PAUSE written and the runner
process ended while a generation was in flight; the harness logged the pause, the failed generation was asked again after
PAUSE was removed, and all four programs got verdicts (no `RUNNER_ERROR`). The real wrapper, run with a low game threshold,
detected a process on the 3D engine, wrote PAUSE, ended the runner and rewrote PAUSE every poll.
