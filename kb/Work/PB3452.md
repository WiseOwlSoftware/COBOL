# PB3452 — the site-block rule grandfathers every open note filed before PB3443

> ⚙ **flags:** process-only

Source: report `w1131g-PB3263-report.md`, "New defects" item 2 "(carried)" (wave 1131 group G, PR #309, merged 2026-10-20T02:06:24Z). The report counted "171 open notes outside PB3353/PB3160 [with] no site block"; PB3263 item 2 counted 198 in all.

**Sites:** `scripts/spec/work.py` (`SITES_REQUIRED_FROM`, `sites_problems`), and the kb/Work notes it backfills.

**Mechanism.** PB3263 made `work.py check` refuse a cluster note with no `**Sites:**` block, but only from `SITES_REQUIRED_FROM = 3443` on ("A rule over every open note would have refused 198 at once, most in idle clusters; those stay readable as UNKNOWN"). The planner plans an UNKNOWN group alone on its subsystems, and the landing check reads an empty recorded set as UNKNOWN (a warning, never a stop). So every older open note without a block (a) loses fleet concurrency (planned serially) and (b) is landed with the landing check's arm 1 protection off. The rule is two rules: one for new notes and an exemption for the rest.

**Measured on origin/main 4e51b3db0 (2026-10-19), `python E:/tmp/sitecount_pb3452.py` run in the worktree** (`work.load()` over kb/Work, status not in `TERMINAL_STATUSES`, `work.note_sites(body).declared` empty): 829 open notes; 415 declare no site; 393 of those are not `kind: decision`; 378 of the 393 have an id below 3443; 165 of the 393 name a cluster. The report's 171 and PB3263's 198 are lower counts of the same population (they likely counted only notes the planner would otherwise place); the 393 is the whole non-decision set the reader leaves empty. The implementer should fix the definition before backfilling.

**Fix direction (for the implementer to confirm).** Backfill a `**Sites:**` block per note, campaign by campaign as PB3263 item 3 did for PB3353/PB3160, or derive declared sites mechanically where a note names a `file#member`; then delete `SITES_REQUIRED_FROM` so the check covers every open note (one rule, no grandfathered population). Pin with `sites_problems` over a fixture holding an old-id note with no block.
