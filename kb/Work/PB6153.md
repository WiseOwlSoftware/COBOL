# PB6153 - comments and a golden header that contradict the PB5677 fix

**Comments** (`src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/MoveEmitter.cs`). After PB5677 removed the edition gate, three comments still say the figurative arm
of `AllLiteralNumber` applies at 1985 only: `ElementaryStore` (line 245, "AllLiteralNumber: at 1985 a figurative whose character is a digit"), the
`FigurativeToNumericImageStore` doc comment (line 311, the same words), and the AllLiteralNumber doc bullet for COBOL-2002 on (around line 676), which
says the digits span the receiver's digit positions at its scale, now true only of the ALL literal.

**Golden header.** `conformance-suite/cases/14.8.24@2002-MOVE-STATEMENT/pb5677_figurative_digit_to_noninteger_2002.cob:11` puts in quotation marks text
the 2002 standard does not contain: "the same number of digits as the number of digits in the receiving operand and the figurative constant is replicated
in this item". The rule reads "the number of digits is the same as the number of digits in the receiving operand and the figurative constant is
replicated in this item"; `cite.py --check "§2002:14.8.24.3 GR4b"` on the quoted fragment answers FAIL [text-not-found]. The rule label is also coarse:
`--find` places the text at 14.8.24.3 4) b) 3. b. (GR4b.3.b), while the 2014 twin is cited to the sub-item (GR6d.3.b). Re-quote from `--find` output and
cite the sub-item, then check the header with `cite.py --check`.
