**Sites:**

**Rule it breaks:** ISO §13.18.8.4 GR3: an all-spaces BLANK WHEN ZERO sender "is considered to be zero"; §14.6.13.2 rule 4: only content that is "not a possible result for any editing operation" is incompatible; §14.6.8.4 rule 1: a stored nonzero value is normalized so its significand's most significant digit is not zero

**Scenario:** Measured on the pin build (src/Cobol.Net.Cli/bin/Debug/net10.0/cobol.dll at 8be230068, --source-format free --run). Repro 1: >>TURN EC-DATA-INCOMPATIBLE CHECKING ON; 01 FE PIC +9.99E+99 BLANK WHEN ZERO; 01 N PIC S9(5)V99 SIGN LEADING SEPARATE; MOVE 0 TO FE displays FE=[         ] as owed. MOVE FE TO N then ends with "abnormal run-unit termination: EC-DATA-INCOMPATIBLE (fatal): the content '         ' is not a possible result of editing into +9.99E+99" where N = 0 is owed. Repro 2: same TURN; 01 FX PIC +9.99E+99 with 01 G REDEFINES FX PIC X(9); MOVE "+0.12E+03" TO G; MOVE FX TO N displays N2=+0012000 with no exception, although no edit into FX can write a leading-zero significand for a nonzero value. Cause: DeEditFloat (CobolEdit.Float.cs:214-264) validates by its own position checks, and it has no BLANK WHEN ZERO parameter and no normalization check. The fixed-point DeEdit re-edits through Format with blankWhenZero and gets both cases right.

**Measured how:** R2 batch finding `runtime-values-2--duplication--f1#4` (pair runtime-values-2--duplication), read in the pinned tree at 8be23006851a; skeptics rule upheld, scenario upheld, site upheld.

**Spec:** §13.18.8.4 "the content of the sending data item is all spaces, the value of the sending data item is considered to be zero" (`cite.py --check` passed at collection); §14.6.13.2 "not a possible result for any editing operation" (`cite.py --check` passed at collection); §14.6.8.4 "most significant digit" (`cite.py --check` passed at collection)

**Target:** DeEditFloat treats an all-spaces image as zero when the item has BLANK WHEN ZERO (§13.18.8.4 GR3) and validates by re-rendering the de-edited value through FormatFloatCore with that BLANK WHEN ZERO, then comparing images, as DeEdit does. NumericRenderer.FieldNum passes the item's blankWhenZero. Goldens: both repros, the second raising EC-DATA-INCOMPATIBLE. The mechanism half is finding f1#3.

**Design reference:** §8.3.
