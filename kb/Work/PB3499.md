# PB3499 — the second-attempt gate is a proxy

Lead R1-2 (low) of the branch review of PB3482 (`E:/COBOL-coord/scratch/reports/w1140c-PB3482-report.md`).

`src/Cobol.Net.Runtime/IO/Sharing/RunUnitFileLock.cs` about line 126: the second-attempt gate asks whether ANY other INPUT opener holds a column, a proxy for the one case that needs it (an INPUT opener holding a WRITABLE handle because its transaction owes writes). So on Windows a SHARING WITH READ ONLY OPEN (the default of a clause-less OPEN INPUT, DOC-A.1-77) beside an outside writer changes from 61 to 00 whenever an unrelated WiseOwl ALL OTHER INPUT reader is open, and its handle then admits outside writers for the rest of the OPEN. The design doc (`docs/rearchitecture/DESIGN-runtime-library.md`) names the consequence. No test pins the 61 to 00 arm; only the no-INPUT-opener arm is pinned (`AReadOnlyOpenBesideAnOutsideWriterIsRefusedWhereTheShareModeRefusesIt`).

**Open judgment (the clerk did not make it).** Whether the 00 is a wrong answer. §9.1.15 2) (sharing with read only restricts concurrent access through other file connectors to input mode) and §9.1.13.9 1) arbitrate file connectors; an outside writer is not a file connector, so the spec may not decide it, and the choice is then latitude (GnuCOBOL first, CLAUDE.md rule 1). The implementer decides against those clauses (`cite.py --check` each) and sets `wrong_answer` accordingly (filed true so the note surfaces in `work.py next`; it is provisional). If it is wrong: make the gate test the exact condition (the INPUT opener's handle is writable) instead of the proxy, and pin both arms.
