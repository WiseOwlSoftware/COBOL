# PB4740 — Messaging slice S1: the message-tag type (USAGE MESSAGE-TAG, NULL, SET Format 17, comparison, INITIALIZE, BY VALUE); COBOL1943 and COBOL2205 retire

**Prerequisites:** none.

## Landed (2026-11-05)

Slice S1 is built as §4.2 and §2.3 of the design say. The re-probe on the build before the change: `USAGE MESSAGE-TAG` was refused
(COBOL1943), `SET` over one was refused (COBOL2205) and `IF T = NULL` drew COBOL0869; after it every form below binds and runs.

- **The type.** `PicCategory.MessageTag`, `PicInfo.MessageTagItem`, `StorageForm.MessageTagRef`, `CobolClass.MessageTag`,
  the runtime `MessageTag` readonly struct (`MessageTag.Null`, `SameParty`; the party enum `MessageParty`), the slot rule
  (`SlotWindow.CarriedBySlot`; image width 0, `FUNCTION BYTE-LENGTH` 8), `RepositoryCategory.MessageTag = 10`, `HostTypeKind.MessageTag`.
  `PicInfo.MessageTagRecovery`, COBOL1943 and COBOL2205 are deleted, and the written-usage arm of `ItemCategory.IsMessageTag` with them.
- **The statements.** SET Format 17 (`SetBinder.BindMessageTagSet` to `BoundSetMessageTag` to `SetEmitter.EmitSetMessageTag`, data-name-4 the
  receiver in both rules, D-SET17), the relation (`ConditionRenderer.RenderRelational` through `MessageTag.SameParty`), INITIALIZE
  (`InitializeBinder.InitializeItemCategory`), a strongly-typed group's message-tag leaf (`StrongGroupComparison` lowers it to the Format 3 relation),
  BY REFERENCE and BY CONTENT arguments (D-MCS-ARG), the BY VALUE formal.
- **The class rules** now decide a message tag instead of failing open: class condition, DISPLAY, ACCEPT, MOVE (both positions), EVALUATE range,
  the MAX/MIN family, INVOKE and header BY VALUE, VALIDATE, the relation checkpoint, `ContainsNonOrderableLeaf`, REDEFINES.
  The re-probe found three that were silent or crashing before the type existed in the lattice: DISPLAY (an emitter exception), ACCEPT and MOVE
  (a Roslyn CS error, and `MOVE N TO T` compiled and stored nothing); each has its refusal golden.
- **Goldens.** Positive: `message-tag-usage`, `set-message-tag`, `message-tag-relation`, `initialize-message-tag`, `message-tag-call-by-reference`.
  Refusals: the twenty-one `message-tag-refused-*` cases, one per class rule. `pb453` and `pb487` (the refusals of the retired codes) are deleted.
- **Registry.** The eight rows of the design's §9 S1 entry are CONFORMS; 24 more rows gained a message-tag witness; the `mcs-only` derived verdict no
  longer selects the message-tag class (S4 deletes it).
- **Left for the next slices.** The unequal-tags case of §8.8.4.2.14 needs a live party (S2-S4); the §8.8.4.2.14 prose gap note, which the design assigns to
  this slice, is the note-ready paragraph in the implementer's report (no note id was allocated to the slice).
