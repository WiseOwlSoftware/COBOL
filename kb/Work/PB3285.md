# PB3285 — the place-identity drift scan sees only the negative spellings

`PlaceDenotedItemDriftTests.NoProductSourceReDerivesTheIdentityQuestion` matches only the NEGATIVE spellings of the §8.4.3.3.4 GR5 whole-item question (`is not RefModPlace`, `Place: not RefModPlace`, `!(x is RefModPlace)`), so POSITIVE re-derivations such as `place is RefModPlace || place.Item.IsGroup` stay unseen, although kb/Work PB602 collapsed every caller's copy into `Place.DenotedItem`.

**Sites the landing finisher listed**, confirmed in the worktree (cut from origin/main 59208d8fb) with `git grep -n "is RefModPlace"` (all under `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/`; full path src/Cobol.Net.Compiler/Binding/Procedure/Verbs/):
- `SetBinder.cs:180` (`if (place is RefModPlace || place.Item.IsGroup`) and `SetBinder.cs:237` (`if (place is RefModPlace || pic is not { } fpic`).
- `IntrinsicBinder.cs:2704` (listed as `:2705`; `if (args[0] is not BoundFieldOperand f || f.Place is RefModPlace || f.Place.Item.IsGroup`).
- `InitializeBinder.cs:248` (`if (place is RefModPlace)`).
- `ControlFlowBinder.cs:194` (`if (p is RefModPlace) return usage is Usage.Display or Usage.National;`; a doc comment at `:183` mentions the former blanket form).
- `OoBinder.cs:1217` (`+ (place is RefModPlace && !formal.IsGroup`).

The same grep also lists other `is RefModPlace` uses in the tree (for example `StatementValidation.cs:1750`, `MoveBinder.cs`, `ConditionBinder.cs`); they were not judged here.

**To do.** Each listed site needs an adjudication: a category dispatch (legitimate, e.g. naming the operand "reference-modified") or an identity test that must ask `DenotedItem`. Then widen the scan to the positive spellings. If the adjudication finds a site that answers the GR5 identity question wrongly for a user's program, that site becomes its own defect note with its harm flag.

## Closed (analyses sweep, 2026-10-23)

Adjudicated read-only by an Opus cobol-adjudicator on main e7cf38ce4; accepted by the Mythos session.

Closed 2026-10-23 (open-analyses sweep S4). Each site was adjudicated on main 1595fabc8. SetBinder.cs:209 (SR31 'shall reference a numeric data item'), SetBinder.cs:266 (SR32 standard floating-point usage), IntrinsicBinder.cs:2708 (algebraic-argument category), InitializeBinder.cs:248 (single alphanumeric receiver), ControlFlowBinder.cs:194 (usage display/national) and OoBinder.cs:1400 (diagnostic wording for a PICTURE-less argument) each ask what the operand IS, and §8.4.3.3.4 GR6 answers that: the unique item has identifier-1's class, category and usage with no PICTURE or JUSTIFIED. None asks WHICH declared item is denoted, the §8.4.3.3.4 GR5 question that Place.DenotedItem owns. They are legitimate category dispatches. The non-THROUGH level-66 alias, the only other case where DenotedItem and Item differ, shares every attribute (§13.18.45.4 GR1), so these attribute tests give the same answer either way. The negative-only scan is the right boundary. A negative spelling beside a p.Item test approximates the identity question. A positive spelling is the category arm, which GR6 makes legitimate and which occurs 53 times in src. Widening the textual scan to positive spellings would flag them all and cannot tell identity from category. No change to the drift test.

Evidence: On main 1595fabc8 all six listed positive-form sites (SetBinder.cs:209 SR31 and :266 SR32, IntrinsicBinder.cs:2708, InitializeBinder.cs:248, ControlFlowBinder.cs:194, OoBinder.cs:1400) branch on the reference-modified operand's CATEGORY, USAGE or PICTURE, which §8.4.3.3.4 GR6 defines. None asks the GR5 identity question. The tree holds 53 positive `is RefModPlace` uses, nearly all of them category or render dispatch, so a textual widening would only add noise.
