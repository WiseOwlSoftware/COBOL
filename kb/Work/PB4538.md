# PB4538 — add-rounded-packed-truncates: ADD ... ROUNDED into a PACKED-DECIMAL item truncates when the addend has more decimal places

Filed 2026-11-03 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-batch-3000-20261103`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

`ADD literal TO packed-item ROUNDED`, where the literal has more decimal places than the PACKED-DECIMAL receiver, stores
the TRUNCATED sum instead of the rounded one. The same addition written as COMPUTE ROUNDED into the same packed item, or
as ADD ROUNDED into a DISPLAY item of the same PICTURE, rounds correctly.

## Minimal test case

Free reference format (`-free`).
```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. ADDRND2.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 P1 PIC S9(5)V99 PACKED-DECIMAL VALUE 0.
01 P2 PIC S9(5)V99 PACKED-DECIMAL VALUE -123.45.
01 P3 PIC S9(5)V99 PACKED-DECIMAL VALUE 0.
01 D1 PIC S9(5)V99 VALUE 0.
PROCEDURE DIVISION.
    ADD 77.105 TO P1 ROUNDED
    DISPLAY "P1 " P1
    ADD 200.556 TO P2 ROUNDED
    DISPLAY "P2 " P2
    COMPUTE P3 ROUNDED = 0 + 77.105
    DISPLAY "P3 " P3
    ADD 77.105 TO D1 ROUNDED
    DISPLAY "D1 " D1
    STOP RUN.
```

## Environment

cobc (GnuCOBOL) 3.2.0 on WSL2 Ubuntu. Command: `cobc -x -free -std=cobol2014 -o p add-rounded-packed-truncates.cob && ./p`
(cobc issued no diagnostic, compile exit code 0; the host C compiler's `_FORTIFY_SOURCE redefined` warning is an environment artifact of this WSL install; run directly).

## Observed result

```
P1 +00077.10
P2 +00077.10
P3 +00077.11
D1 +00077.11
```
Exit code 0. `cobc -C` generates the ADDs as `cob_add (&f_1, (cob_field *)&c_1, 1)`, so the ROUNDED option reaches libcob.

## Expected result (per ISO)

§14.7.4.3 1): "If the MODE phrase is not specified, the form of rounding is as described in 11.9.6, DEFAULT ROUNDED
clause." §11.9.6.3 2): "If the DEFAULT ROUNDED clause is not specified, DEFAULT ROUNDED MODE IS NEAREST-AWAY-FROM-ZERO is
implied." §14.7.4.3 4): with NEAREST-AWAY-FROM-ZERO "the arithmetic value is rounded to the nearest value that can be
represented in the resultant identifier". 0 + 77.105 is 77.105 (a tie, farther from zero is 77.11), and -123.45 + 200.556
is 77.106 (nearest is 77.11). The 2014 edition the `-std` flag claims carries the same rules (plain ROUNDED rounds half away
from zero in every edition). Expected:
```
P1 +00077.11
P2 +00077.11
P3 +00077.11
D1 +00077.11
```

## Our compiler

WiseOwl COBOL (fresh judge, `--std 2014 --source-format free`) prints the expected output above, with no diagnostic.

## Fix site

libcob/numeric.c: `cob_add` first tries `cob_addsub_optimized`, which for a PACKED-DECIMAL receiver converts a DISPLAY
or binary addend to a packed temporary that keeps the addend's scale and calls `cob_add_bcd (f1, &field, f1, opt, stmt)`.
`cob_add_bcd` is meant to round during the addition when `opt` requests it, but in this case the result it writes into f1
is the truncated sum: the decimal places beyond the receiver's scale are dropped and the requested rounding does not take
effect. The general path (`cob_decimal_add` then `cob_decimal_get_field (..., opt)`) rounds correctly. Both functions are
present in the GnuCOBOL 3.2 release source (libcob/numeric.c).

## Draft issue

**Title:** ADD ... ROUNDED into a PACKED-DECIMAL item truncates when the addend has more decimal places

cobc (GnuCOBOL) 3.2.0, WSL2 Ubuntu, `cobc -x -free -std=cobol2014 -o p prog.cob && ./p`.

```
01 P1 PIC S9(5)V99 PACKED-DECIMAL VALUE 0.
01 D1 PIC S9(5)V99 VALUE 0.
...
    ADD 77.105 TO P1 ROUNDED    *> P1 = +00077.10, expected +00077.11
    ADD 77.105 TO D1 ROUNDED    *> D1 = +00077.11, correct
```
`COMPUTE P1 ROUNDED = 0 + 77.105` gives the correct +00077.11, and `ADD 200.556 TO` a packed item holding -123.45
`ROUNDED` gives 77.10 instead of 77.11. ISO/IEC 1989:2014 14.7.4 (ROUNDED phrase) with the implied NEAREST-AWAY-FROM-ZERO
mode requires rounding to the nearest representable value. The ADD is generated as `cob_add (&f, &lit, 1)`;
`cob_addsub_optimized` takes the packed receiver through `cob_add_bcd`, whose stored result here is truncated although
the ROUNDED flag reaches it; the general path through `cob_decimal_get_field` rounds.
