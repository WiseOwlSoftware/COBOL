# PB599 — OPEN — one null, two meanings

Found 2026-09-05 by the `PB236` implementer while splitting `BoundUnsupported`'s three jobs; re-derived on this
tree for this note.

## The rule

§14.9.40.3 SR14 e) (quoted from `specs/ISO_COBOL.md`; `cite.py --check 14.9.40.3 "If the data item identified by
a key data-name is subordinate to data-name-2, it shall not be described with an OCCURS clause, and it shall not
be subordinate to an entry that is also subordinate to data-name-2 and contains an OCCURS clause."` is the fix's
first step): a table-SORT key inside an inner OCCURS is source the standard forbids, and §4.2.2 requires the
implementation to be able to indicate it at compile time.

## The mechanism

`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/SortBinder.cs#SortMemberPath` returns `null` both when the key
data item is inside an inner `OCCURS` (SR14 e — a rejection) and when it is a REDEFINES-view member (a real
deferral of the view-window key path). The call site sees one `null` and, since PB236, announces the statement
as not-implemented (COBOLNET1756, a warning) and defers to run time — so SR14 e's violation is under-rejected
with a message that says the compiler has a gap, while its SR14 a) sibling (a key not subordinate to
data-name-2) rejects at bind with COBOLNET1757.

## Fix shape

`SortMemberPath` returns WHICH: a small result type (path · syntax-rule violation naming SR14 e · deferral with
its reason), so the call site routes the violation to `StatementValidation` under COBOLNET1757 with the rule
quoted, and only the REDEFINES-view case stays announced. One negative golden for the inner-OCCURS key
(`*> reject-at: 85 2002 2014 2023`), one positive for a key at data-name-2's own level, and the existing SR14 a)
negative as the sibling control.
