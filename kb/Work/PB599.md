## Landed (w1012h, 2026-10-04)

The note's "one null, two meanings" split had already landed by another shape (kb/Work PB909): `SortBinder.KeyUnderInnerOccurs`
is a predicate over the data description alone, asked before the member path, so a written key inside an inner OCCURS draws
COBOLNET1757 naming §14.9.40.3 SR14 e) (re-probed, `SORT E ASCENDING KEY K` over `E OCCURS 3 / INNER OCCURS 2 / K` refused). What
remained was the OTHER meaning of the null, the genuine deferral: a key behind a REDEFINES view of the element
(`10 K PIC 9. 10 KR REDEFINES K PIC X.` — `SORT E ASCENDING KEY KR`) has no stored field on the element struct, and the statement
compiled to a COBOLNET1756 deferral that aborted the run unit — legal source (§14.9.40.3 SR14 a) asks only that the key be
subordinate to data-name-2), so rule 3 makes it debt. **Built:** `TableSortStorage.TypedArray` gained `KeyWindowOuter`; when any key
has no member path (`BoundTableSortKey.MemberPath` null) the binder records the enclosing occurrences, and
`SortEmitter.EmitArrayTableSort` reads EVERY key of the statement through its window at an element number (the
`SharedArea` law, `ReferenceResolver.ResolveItemAt`), sorts the numbers with the one `EmitKeyComparer`, and places the elements
back by that permutation (§14.9.40.4 GR24) — the member-path form stays for the common case. The numeric-over-alphanumeric view
sorts by VALUE (GR19 → the relation-condition rules). Golden `conformance:2002/pb599_table_sort_redefines_view_key` (five legs:
ascending, descending, a table inside another table, two keys with a view first, and the table's own KEY phrase naming the view).
The deferral fixtures of `BoundDeferralDriftTests.GenuineDeferral_StillCompiles_AndAnnounces` and
`StatementDeferralAnnounceDriftTests` were this very shape and moved to a SEARCH ALL of an OCCURS DYNAMIC table nested under
another table (a deferral that is still genuine). **Not part of this note and still open:** an OCCURS KEY phrase naming a key under
an inner OCCURS (`OCCURS 3 ASCENDING KEY IS K` with `INNER OCCURS 2` between) is §13.18.38.3 SR4/SR6 illegal at the DECLARATION —
`OccursKeyResolve` applies neither (kb/Work PB1263 owns it); until it lands that shape still reaches the sort's COBOLNET1756
deferral, which now names PB1263. `SEARCH ALL` over a view key already worked (probed).

# PB599 — LANDED — one null, two meanings

Found 2026-09-05 by the `PB236` implementer while splitting `BoundUnsupported`'s three jobs; re-derived on this
tree for this note.

## The rule

§14.9.40.3 SR14 e) (quoted from `specs/ISO_COBOL.md`; `cite.py --check 14.9.40.3 "If the data item identified by
a key data-name is subordinate to data-name-2, it shall not be described with an OCCURS clause, and it shall not
be subordinate to an entry that is also subordinate to data-name-2 and contains an OCCURS clause."` is the fix's
first step): a table-SORT key inside an inner OCCURS is source the standard forbids, and §4.2.2 requires the
implementation to be able to indicate it at compile time.

## The mechanism

`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/SortBinder.cs#SortMemberPath` returns `null` both when the key
data item is inside an inner `OCCURS` (SR14 e — a rejection) and when it is a REDEFINES-view member (a real
deferral of the view-window key path). The call site sees one `null` and, since PB236, announces the statement
as not-implemented (COBOLNET1756, a warning) and defers to run time — so SR14 e's violation is under-rejected
with a message that says the compiler has a gap, while its SR14 a) sibling (a key not subordinate to
data-name-2) rejects at bind with COBOLNET1757.

## Fix shape

`SortMemberPath` returns WHICH: a small result type (path · syntax-rule violation naming SR14 e · deferral with
its reason), so the call site routes the violation to `StatementValidation` under COBOLNET1757 with the rule
quoted, and only the REDEFINES-view case stays announced. One negative golden for the inner-OCCURS key
(`*> reject-at: 85 2002 2014 2023`), one positive for a key at data-name-2's own level, and the existing SR14 a)
negative as the sibling control.
