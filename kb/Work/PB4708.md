# PB4708 — CallBinder's sentence about a PROGRAM specifier is false on two routes

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CallBinder.cs:1146` (`CallBinder.ResolvePrototype`), `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.Configuration.cs:51` (`DataBinder.BindProgramSpecifier`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CallBinder.cs` (`CallBinder.BindCall`), `src/WiseOwl.Cobol.Compiler/Binding/ConfigurationSlice.cs` (`ConfigurationSlice.WhyNoPrototype`, `ConfigurationSlice.DeclaresProgramSpecifier`, `ConfigurationSlice.RefusedProgramSpecifiers`), `src/WiseOwl.Cobol.Compiler/Binding/ConfigurationStep.cs` (the REPOSITORY inheritance), `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs` (the USAGE PROGRAM-POINTER TO screen), `src/WiseOwl.Cobol.Compiler/Binding/LinkageBinder.cs` (`ProgramSpecifierRefusal`), `src/WiseOwl.Cobol.Compiler/Binding/BinderDriver.cs` (`BinderDriver.ProgramPrototypesOf`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/SetBinder.cs` (`SetBinder` ADDRESS OF PROGRAM operand, COBOL2157)

## Resolution

Both leads reproduced. `PROGRAM R4708P AS ""` (refused by SR2) drew "neither declared by a PROGRAM specifier" from CALL and CANCEL, and the USAGE PROGRAM-POINTER TO screen added its own "not a program-prototype-name" refusal for the same declared word. Where the external repository's own finding refused the specifier (REPO-3 and the like), the sentence cited an SR14 refusal that was never reported.

Fix: `ConfigurationSlice.RefusedProgramSpecifiers` remembers a declared word whose literal-3 was refused, and `ConfigurationSlice.DeclaresProgramSpecifier` is the one declared-word question that the CALL spelling-(b) arm, `CallBinder.ResolvePrototype` and the USAGE screen all ask. `ConfigurationSlice.WhyNoPrototype` (moved from CallBinder so SET ... ADDRESS OF PROGRAM, COBOL2157, reads it too: review R1-1) names the three routes apart: SR14 with COBOL5962, the external repository's own finding (recorded by `BinderDriver.ProgramPrototypesOf` from `RepositoryResolver.External`; a first attempt that handed the resolver to `StatementBinder` drew a new Bound to Binding edge in `ArchitectureEdgesDriftTests`), and SR2's literal-3 refusal. SR14's alternatives are quoted as the standard writes them. Tests: `ExternalRepositoryResolutionTests.ASpecifierWhoseLiteral3IsRefused_IsDeclaredAndNamesSr2` and the added assertions in `AFileNamedAfterTheUnitThatIsNoAssembly_IsRepo3`.

Reported by the branch review, not probed. Copied from the PB4633 report (wave 20261868 h):

R1-1: the false "neither declared by a PROGRAM specifier" sentence (`CallBinder.cs:1146`) survives on the second route to a declared word with no prototype: `DataBinder.BindProgramSpecifier` (`DataBinder.Configuration.cs:51`) adds no `ProgramSpecifiers` row when literal-3 is rejected, so `DeclaresProgramSpecifier` answers false for a word the REPOSITORY paragraph does declare; the report's sibling sweep says no sibling carries the sentence.

R1-2: the new sentence and its doc comment (line 1142) say the specifier is "itself refused (ISO section 12.3.8.3 SR14)", but `RepositoryResolver.ReportUnanswered` reports no REPO-1 when `MetadataRepositoryProvider.Refused` holds, so on that route no SR14 refusal exists and an entry was found; "no program of this compilation group" also paraphrases SR14's "specified previously".
