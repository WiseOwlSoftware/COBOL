# PB6359 — stale comments after PB6232

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/EvaluateSubjectBinder.cs` (`EvaluateSubjectBinder.Bind`, `EvaluateSubjectBinder.SubjectSlot.NeedsIntermediate`, `EvaluateSubjectBinder.SubjectUsage.NeedsIntermediate`)

PB6232 changed `SubjectUsageOf` so `ReadByFirstPhrase` is set only when every earlier pair of the first WHEN phrase is ANY; the deciding line is now `NeedsIntermediate => !(Uses == 1 && ReadByFirstPhrase)` (line 323). Three comments still state the old rule, that a single use anywhere in the first arm needs no intermediate:

- line 39, in `Bind`: `"one use, in the first arm"`;
- line 150, the summary of `SubjectSlot.NeedsIntermediate`: "at ONE use IN THE FIRST ARM the single render already IS the one evaluation";
- line 321, the summary of `SubjectUsage.NeedsIntermediate`: "the only shape in which the un-hoisted render is itself GR3 evaluation".

A reader who trusts them re-derives the PB6232 bug: `EVALUATE X ALSO R (J)` with one use of R in the first phrase, behind a non-ANY pair, short-circuits before R is evaluated. The PB6232 diff updated only the `SubjectUsageOf` remark.

**Expected:** each of the three comments states the PB6232 rule (one use, in the first phrase, with every earlier pair of that phrase ANY), citing the same clauses the PB6232 landing cites. No code change.
