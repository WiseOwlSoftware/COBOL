Filed 2026-09-26 by the **train-62 lander** from the w61h implementer report (PB1418/PB1115), lead 2.

## Observation (reported by the implementer, not re-probed by the lander)
PB1418 made a figurative constant or `ALL literal` argument passed BY CONTENT fill an ELEMENTARY formal to its size,
as §8.3.3.6.4 GR2 requires. The helper `CallEmitter.FigurativeFillWidth`
(`src/Cobol.Net.Compiler/CodeGen/Verbs/CallEmitter.cs`) returns a width only for an elementary formal that is not
any-length and not dynamic-length. A GROUP formal gets width null, so its argument crosses as one occurrence
(`"*"` rather than `"****"`). The implementer limited the fill to elementary formals on purpose: a group's extent
can be variable (OCCURS DEPENDING ON) and is then known only at run time.

Repro: `CALL "SUB" USING BY CONTENT ALL "*"`, with SUB's linkage formal `01 G. 05 A PIC X(2). 05 B PIC X(2).`
and SUB displaying G. Expected: `****`. Actual: `*` followed by the space-filled rest.

## Fix direction
For a fixed-extent group, the fill width is the group's image width at bind time. For a variable-extent group,
the width has to come from the run-time crossing. `CobolArgAdapt` or the content carrier sizes the value to the
formal's current extent, which is the one place that knows it. The fix should give one answer for both, not a
second compile-time table.
