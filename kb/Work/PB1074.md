### Adjudicator finding (record-key-clause, harm wrong-answer)
- **Mechanism:** DataBinder.ResolveKeyCollating resolves a key's file-level collating sequence as `alphabet ??= file.FileLevelCollating?.Alnum` for EVERY key, whatever its class, and never reads FileLevelCollating.Nat. So (a) a file-level ALPHANUMERIC alphabet (alphabet-name-1) is applied to a NATIONAL record key, which §12.4.5.7.4 GR2/GR5 confine to alphanumeric keys (a national key without alphabet-name-2 takes the native national sequence), and prime-key uniqueness (§12.4.5.12.4 GR1) is then judged under the wrong sequence; (b) a file-level `FOR NATIONAL IS alphabet-name-2` is dropped with NO diagnostic, although national-key collating is a processor-dependent decline (A.3 item 41) that docs/CONFORMANCE.md row 41-42 says is diagnosed by COBOLNET1584, and §4.2.6 requires a compile-time warning for an unsupported syntactically-detectable processor-dependent element - only the Format-2 key-level arm reaches COBOLNET1584.
- **Repro:** --std 2023 (probes out/probe/record-key-clause/gr1na.cob, gr1n.cob). gr1na: SPECIAL-NAMES. ALPHABET EQV IS "A" ALSO "B". SELECT G ... ORGANIZATION INDEXED ACCESS DYNAMIC RECORD KEY IS G-KEY FILE STATUS WS-FS COLLATING SEQUENCE IS EQV. FD G. 01 GR. 05 G-KEY PIC N(1). 05 G-DAT PIC X(2). OPEN OUTPUT G; WRITE with G-KEY N"A"; WRITE with G-KEY N"B"; DISPLAY WS-FS after each. gr1n: same file with ALPHABET NEQV FOR NATIONAL IS N"A" ALSO N"B" and COLLATING SEQUENCE FOR NATIONAL IS NEQV.
- **Expected (spec):** gr1na: §12.4.5.7.4 GR2 applies EQV only to keys of class alphanumeric; GR5 gives the national key the native national sequence, under which N"A" and N"B" are unequal, so both WRITEs complete '00'. gr1n: the file-level national alphabet either applies (GR3: keys equal, second WRITE '22' per §12.4.5.12.4 GR1 / §9.1.13.5 2) b)) or, since national-key collating is not claimed here (A.3 item 41, CONFORMANCE.md row 41-42), the clause draws the COBOLNET1584 compile-time indication §4.2.6 requires.
- **Observed:** gr1na: GW1 00, GW2 22 - a spurious duplicate-key INVALID KEY; the alphanumeric equivalence was applied to a national key. gr1n: compiles exit 0 with no diagnostic at all, and GW2 00 - the national alphabet is silently ignored. Code: DataBinder.cs ResolveKeyCollating, `alphabet ??= file.FileLevelCollating?.Alnum;   // GR2 file-level alphanumeric default` - neither the key's class nor the Nat slot is consulted. The same resolver serves alternate keys (AlternateKeyCollations), so the alternate-key GR4/uniqueness and ordering rules share the defect.
- **Code site:** src/Cobol.Net.Compiler/Binding/DataBinder.cs#ResolveKeyCollating (the `alphabet ??= file.FileLevelCollating?.Alnum` line); callers in #ResolveFileCollating for PrimeKeyCollation and AlternateKeyCollations
- **Clause (adjudicator):** ISO/IEC 1989:2023 §12.4.5.12.4 GR1; §12.4.5.7.4 GR2, GR3, GR5; §9.1.13.5 2) b); §4.2.6; Annex A.3 item 41
