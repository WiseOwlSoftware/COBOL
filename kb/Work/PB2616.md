# PB2616 — a subscript expression wraps in `long`

Filed by the train 1039b lander from the wave-1039 group G implementer report (`w1039g-PB1900-report.md`, new
defect 1), re-run on train 1039b's build.

**Rule.** §8.4.2.3.4 1) b): "the subscript is the result of the evaluation of arithmetic-expression-1"
(`cite.py --check` OK). The evaluation is the expression's, not a 64-bit machine product's; a value that is not a
positive integer within the table raises EC-BOUND-SUBSCRIPT (§8.4.2.3.4 2)), it never selects another element.

**Repro.** `E:\COBOL-coord\scratch\w1039g\p3.cob` (copy in `E:\COBOL-coord\scratch\train1039b\leads\`), free form:
`01 EL PIC 9 OCCURS 3 TIMES VALUE 5`, A = B = 100000000000000000001, C = 100000000000000000000,
D = 100000000000000000002 (PIC 9(21)); `MOVE EL(A * B - C * D) TO I`. The exact subscript is 1, so I = 5. Train
1039b's build: `PLAIN=5`, `SUBSCRIPT=0` (wrong element, no exception), `SUBSCRIPT2=5` for `EL(A * B - C * D + 1)`
(the right answer only by coincidence of equal elements).

**Code site.** `src/Cobol.Net.Compiler/CodeGen/Roslyn/PositionRenderer.cs:34` (`PositionBinary` renders `+ - *` in C#
`long`). PB1900 made the arithmetic statements' nested products exact (`CobolWide`, `NumericRenderer.Settle`); the
subscript lane has its own typed `Position` tree (kb/Work PB2151) and did not share it.

**Fix shape.** A subscript expression whose operands can exceed 18 digits evaluates on the exact lane (or the
intermediate rule the arithmetic statements use) and lands its integer result with the bound check; narrow operands
keep the `long` fast path, decided at compile time from the operands' digit bounds.

# PB2616 — LANDED

## Landed (wave 1042, group G)

**Reproduced on the base build** (`E:\COBOL-coord\scratch\w1042g\p3.cob`): `MOVE EL(A * B - C * D) TO I` selected EL(0)
silently (`SUBSCRIPT=0`); the exact subscript is 1.

**Root cause.** `ReferenceResolver.BindPosition`'s direct walk built a `PositionBinary` tree for any `+ - *` over item
reads, and `PositionRenderer` rendered it as C# `long` arithmetic, so a product past 18 digits wrapped (and a literal
product past `long` was a C# constant overflow). The subscript is "the result of the evaluation of
arithmetic-expression-1" (§8.4.2.3.4 1) b)).

**Fix.** `Position.ExceedsLongArithmetic` computes a worst-case magnitude from the operands' digit bounds at compile time
(`Int128`, saturating); a walk result that exceeds `long` routes the whole position to `MaterializePosition` (the D18
expression-binder lane, exact), before the walk's queued screens flush. Narrow operands keep the fast path. The same
walk serves reference-modification bounds. Golden `2023/pb2616_subscript_expression_wide_operands` (distinct element
values, so the coincidence that hid the defect cannot recur; wrap-to-valid `P * Q + 2` now raises EC-BOUND-SUBSCRIPT);
`DESIGN-binder-bound-tree.md` §3.9.2.

**Sibling sweep.** The other `PositionBinary` producers (`PlaceCursor`, `CorrespondingBinder`, `ReferenceResolver`
offsets, `Place.cs` bit offsets) combine compile-time constants and statement locals, never user operands. A lone wide
item as a subscript (`EL(A)`, A `PIC 9(21)`) reads through `CobolTable.Occ`, which saturates and raises
EC-BOUND-SUBSCRIPT (its message prints the saturated `long`, not the true value).

## Landing

- `src/Cobol.Net.Compiler/Binding/Model/Position.cs#ExceedsLongArithmetic` — the compile-time digit bound of a directly rendered position (`Int128`, saturating; operators check themselves and everything beneath them; a bare leaf never exceeds). Reuse it for any new producer of user `PositionBinary` trees; address terms (offsets, pointer displacements) are bounded at `long.MaxValue`.
- `src/Cobol.Net.Compiler/Binding/ReferenceResolver.cs#BindPosition` — one line after the direct walk: `if (bound.ExceedsLongArithmetic) return MaterializePosition(seg, position);`, before the queued §8.8.1.1 screens flush. Trap: a repro whose table elements are all equal hides the wrong occurrence (the wave-1039 repro printed the right answer for `A*B-C*D+1` by coincidence); the golden uses distinct elements and a wrap-to-valid product (`P * Q + 2`, 2^64+2 wraps to 2).
