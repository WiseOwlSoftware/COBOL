# PB697 — LANDED — a row whose last complaint is a decline, and the decline covers it

Found 2026-09-05 by the `PB332` implementer (report §"New defects" D). With PB332's two word-level defects on the
START format landed (`WITH?`, the operator no longer optional) and PB333's residue being an operator-SET question
filed on `SR-14.9.41.3-3`, the FMT row's remaining format-shape complaint — item (3) of its own notes: "the
record-key-name-1 arm of the brace group has no surface at all — see `SR-14.9.41.3-7` (an A.3 item 40 sanctioned
decline)" — is a decline the standard permits declining. PB332 left the row DIVERGES and had PB333 claim it,
because manufacturing a resolving verdict to move the GAP would be the wrong reason to make one.

## What settles it

Read the A.3 item 40 decline's scope against §14.9.41.2's brace group (`cite.py --check 14.9.41.2
"record-key-name"` → OK): if the decline covers the arm, the format row's shape is complete for everything the
implementation claims and the row resolves as the decline's own verdict kind (documented non-support on that arm,
CONFORMS on the rest — whichever convention the inventory uses for a partly-declined format; check a precedent
row before choosing). Record the reading as an adjudication paragraph on the row and re-verdict it through a batch;
otherwise it stays DIVERGES with the reason written down. A registrar-lane item, not an implementer's.

## LANDED 2026-09-06 — the decline covers the arm, and the arm was never missing

**The premise did not survive the probe, in the implementation's favour.** The residue reads "the
record-key-name-1 arm of the brace group has no surface at all". The printed general format was RENDERED and
READ (PDF page 784 / printed folio 754):

    START file-name-1
      [ FIRST                                                                              ]
      [ KEY relational-operator { data-name-1 | record-key-name-1 } [ WITH LENGTH ae-1 ]   ]
      [ LAST                                                                               ]

Both arms of the brace group are **un-underlined metalanguage placeholders** — user-defined words with ONE
lexical surface. No grammar can distinguish them, and `startKeyPhrase : KEY comparisonOperator dataReference`
(`src/Cobol.Net.Frontend/Grammar/Core/CobolIO.g4`) realizes **both**. There is no missing surface here.

**What is absent is the operand domain, and its absence is sanctioned.** §14.9.41.3 SR7
(`cite.py --check 14.9.41.3 "Record-key-name-1 shall be specified with the SOURCE phrase in the RECORD KEY
clause"` → OK, `7)`) makes record-key-name-1 definitionally a key name declared *with the SOURCE phrase*, and
that phrase is Annex **A.3 item 40** (`--check A.3 "The capability of specifying the SOURCE phrase of the RECORD
KEY clause and ALTERNATE RECORD KEY clause is dependent on the capabilities of the processor"` → OK, `40)`) — a
PROCESSOR-DEPENDENT element this implementation does not claim (`docs/CONFORMANCE.md` §2 row 40). §4.2.6
(`--check` OK) licenses precisely the absence: *"Language elements that pertain to specific processor-dependent
elements for which support is not claimed need not be implemented."*

**⛔ The decline is not free, and what it owes is owed elsewhere.** §4.2.6 (`--check` OK) also requires *"a
warning mechanism at compile time to indicate use of syntactically-detectable processor-dependent language
elements not supported by that implementation"*. The syntactically-detectable element is the SOURCE phrase in
the RECORD KEY / ALTERNATE RECORD KEY clause — not a user-defined word in a START statement — so the obligation
lands on `SR-14.9.41.3-7`, where [[PB358]] already records that the refusal is a generic parse error. That
citation was appended to the row by this adjudication; the row's verdict and state are unchanged.

**Precedent checked before choosing a verdict kind** (the note asked for this): `FMT-12.4.5.11.2` records that a
processor-dependent decline does not by itself make a format row DOCUMENTED-NON-SUPPORT — §4.2.6 licenses the
absence and only compels the warning, unlike Annex A.4.1, which governs unclaimed OPTIONAL modules and forbids
accepting their syntax. So no partly-declined-format convention had to be invented.

**The verdict does not move, and that is the finding.** `FMT-14.9.41.2` stays **DIVERGES** — not for two
reasons but for ONE: residue (a), `comparisonOperator` being the condition language's whole operator list where
§14.9.41.3 SR3 (`--check` OK, `3)`) admits only the 8.8.4.2 general-relation format minus 'IS NOT EQUAL TO' /
'IS NOT='. [[PB333]] owns that and the row with it. The row is **not** verdicted worse than it is; it is
verdicted for the one thing still true of it, and the reason is now written down where the next reader will
find it.
