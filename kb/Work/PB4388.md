# PB4388 - the harness does not wait for the process it killed

**Sites:** `tests/_shared/ProcessObservation.cs` (`ProcessObserver.ReportKilled`, `ProcessObserver.AwaitSurvivor`, `SurvivingProcess`, `ProcessOutcome.SurvivedKill`), `tests/WiseOwl.Cobol.Tests.Unit/ProcessObservationDriftTests.cs` (the PB4388 tests); before the fix `tests/_shared/ProcessObservation.cs:143` (`ProcessObserver.Observe`, the `proc.WaitForExit(5_000)` after `proc.Kill(entireProcessTree: true)`), and `tests/_shared/ProcessObservation.cs:252` (`ProcessObserver.RestoreForRetry`, called from `ProcessObserver.ObserveWithRetry` at line 225).

**Read at:** origin/main d40c75536.

After the budget expires, `Observe` kills the process tree and calls `proc.WaitForExit(5_000)`, discarding the bool. A process killed inside a blocking system call (here `MoveFileEx` on a loaded ReFS volume, PB4387) can outlive the 5 s wait. The observation still reads `process did not exit within N ms and was killed`, which is untrue, and `ObserveWithRetry` then calls `RestoreForRetry`, which refuses ("the run directory cannot be restored", "being used by another process") because the survivor still holds the program's files such as `sq214a.txt`. The retry never runs, so a transient stall becomes `HARNESS NON-OBSERVATION`.

Evidence: run `000002-20261101T113354Z` of `worktree-wf_ca25d124-0aa-5`: OBSQ4A, SQ203A, SQ214A and IX103A each ran 125-126 s, i.e. the 120 s budget plus the 5 s wait, with attempt 2 not run.

Fix direction: when `WaitForExit(5_000)` returns false, say so in the observation's detail (a process that survived its kill), and make the retry wait for that exit (bounded, then a named failure that identifies the surviving pid) before `RestoreForRetry`, so a transient hold ends in a retried observation, not a refused one. Tests with a fake process whose exit is delayed past the first wait pin each arm (exits within the wait; exits after it; never exits).

Harm: `misleads_diagnosis` (the detail text claims a kill that did not finish) and `process_only`; no user program is affected. Branch status: PB4278's branch `worktree-wf_ca25d124-0aa-5` is re-armed only once main carries PB4387's fix (or this one).

Related: PB4387 (what made the process slow to die), PB4150. Grepped `kb/Work` for `WaitForExit`: PB4150 and older notes mention it for other sites; none covers the ignored result after the kill.

## Landing

Fixed at its root in tests/_shared/ProcessObservation.cs. Observe now reads the wait after its kill (ProcessObserver.ReportKilled): a process that exited is TimedOut as before; one still alive is the new ProcessOutcome.SurvivedKill, whose detail names the process id and no longer claims a completed kill, and the observation carries a SurvivingProcess held by id. ObserveWithRetry waits for the survivor (SurvivorWaitMs, 60 s, before taking the retry gate), then restores the run directory and retries; a survivor still alive raises the non-observation naming its id with attempt2: not run, instead of the run directory cannot be restored refusal. Pinned by five tests in ProcessObservationDriftTests. Sibling sweep: the only other Kill in tests/_shared is LiveProcess.Kill, which waits unbounded and so cannot report a survivor as dead.
