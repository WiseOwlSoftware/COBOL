## Landed (wave 57, 2026-09-23) — one declaration per index-name, one resolution, one verdict

**The root was the MODEL, not a missing check.** The unit held index-names as `name → cell`, de-duplicated on
insert, so the two `INDEXED BY IX` of `TA`/`TB` were ONE C# cell (the re-probe printed `EA=11 EB=22` with no
diagnostic — both reads through the one shared cell), and nothing could have counted candidates because only one
existed. A fourth hand-written ambiguity arm could not have fixed that. So, per this note's own rule-5 demand:

* **`IndexDeclaration(Name, Table, Cell)`** (`Binding/Model/IndexDeclaration.cs`) — minted per table by
  `DataBinder.RegisterIndexes`, called from `RegisterName`, the one funnel every referenceable item (a TYPE clone
  included, a FILLER table included) passes through; cell `_IX_<table uid>[_k]`, collision-free across units.
  `DataItem.Indexes` carries a table's own declarations (SEARCH reads its first index there — a declaration, not a
  reference).
* **`IndexNameRegistry`** per scope — the unit, a method's §11.7.4 GR5 overlay, and (by §8.4.6.2.3, registered
  beside the table's data-names in `BinderDriver.RegisterSubtree`) a containing program's GLOBAL tables tagged with
  their nesting depth; `Candidates` applies §8.4.6.2.1 3) (the nearest declaring element wins). The pre-bind
  `SeedInheritedGlobalIndex` and its emission suppression are gone — a unit emits only `Own`.
* **ONE resolution** `ReferenceResolver.ResolveIndexName` over `SymbolTable.IndexCandidates`, for the subscript
  renderer AND `ExpressionBinder.IndexFieldOf` (SET, PERFORM/SEARCH VARYING, relation conditions), bare or
  §8.4.2.2.2 Format 3 qualified; qualifiers match from the table upward (`DataBinder.IndexQualifierChainMatches`,
  §8.4.2.2.3 SR6) through the same walk data-names use.
* **ONE verdict**: `DataNameCandidates` became `NameCandidates<T>` and `UniqueOrReportAmbiguous<T>` judges data-
  and index-name sets alike (COBOLNET1639, `--permissive` first-declared + warning). No new diagnostic code.
* **§8.4.2.3.3 SR4 by identity**: `ScreenIndexNameAssociation` now tests the resolved declaration's table, so
  `EB(IX OF EA)` is COBOLNET1961 where the old spelling test would have passed it.
* **The other name classes are routed, and a drift test holds it**: `Binding/QualifiedNameClasses` names the
  resolution of each of the eight §8.4.2.2.2 formats (condition-name `ConditionOf`, procedure-name
  `ResolveProcedureWord`, LINAGE-COUNTER `LinageFileOf`, LINE-/PAGE-COUNTER `CounterReportOf` — each MEASURED
  enforcing on this build; screen-name and record-key-name are declared only by declined facilities), and
  `QualifiedNameClassDriftTests` reads the format list from the standard's own text in both directions.
* **Sibling retired**: the COBOLNET1531 "INDEXED-BY type referenced twice" stage existed only because the clones
  shared one spelling-keyed cell; each clone now declares its own IX (`IX OF A` / `IX OF B`).

Goldens `85/pb919_index_name_qualified` (SET / subscript / PERFORM VARYING / SEARCH VARYING / relation / UP BY,
qualified through table, record, and IN) and `negative/pb919-index-name-ambiguous` (reject-at 85 2002 2014 2023);

# PB919 — (as filed) — one uniqueness rule, enforced per name class, and one class was never done

Source: the `PB413` report, "New defects" item 1, which filed it honestly as a MEASUREMENT lead
("Repro: not established"). It is established here.

## The measurements

**Index-names — DEFECTIVE.** `<scratch>/reg7/probe/y3_dup_index_set.cob`, `--std 2023`, `--run`:

```cobol
       01 TA.
          05 EA PIC 9(2) OCCURS 3 INDEXED BY IX.
       01 TB.
          05 EB PIC 9(2) OCCURS 4 INDEXED BY IX.
       PROCEDURE DIVISION.
           MOVE 11 TO EA(1)
           MOVE 22 TO EB(1)
           SET IX TO 1
           DISPLAY "EA=" EA(IX) " EB=" EB(IX)
```

```
EA=11 EB=22
```

No diagnostic. `IX` is declared twice and referenced three times without a qualifier. Worse than the
under-reject: `EA(IX)` and `EB(IX)` each resolved to a DIFFERENT index — so one written name denotes two
runtime objects in one statement, and `SET IX TO 1` set one of them (or both; the program cannot tell).
A user who writes this believes they have one index.

**LINAGE-COUNTER — ENFORCED, correctly.** `<scratch>/reg7/probe/y2_linage_ambig.cob`, two FDs with LINAGE:

```
y2_linage_ambig.cob(17,12): error COBOLNET0864: unqualified LINAGE-COUNTER with more than one LINAGE file:
qualify by file-name (ISO §8.4.3.14 SR3 / §8.4.2.2 Qualification)
```

So SR8's arm is done and is NOT part of this note.

**Screen-names — UNREACHABLE.** `<scratch>/reg7/probe/y4_dup_screen.cob` is refused whole by COBOLNET1560:
the SCREEN SECTION is an optional module (§4.2.7; Annex A.4.2) for which this compiler claims no support.
There is no screen-name arm to enforce, and saying so is the measurement
(`feedback_reachability_is_measured_not_deduced`).

**LINE-COUNTER / PAGE-COUNTER — NOT MEASURED.** My probe for an ambiguous LINE-COUNTER over two reports did
not compile for unrelated reasons (`FD … REPORT ARE` spelling, and SOURCE with a literal), so I have no
evidence either way and I am not claiming any. Building that probe is the fixer's first step.

## The rule

```
$ python scripts/spec/cite.py --check 8.4.2.2.3 "uniqueness shall be established through a sequence of qualifiers that precludes any ambiguity of reference"
OK  §8.4.2.2.3 1)  (Syntax rules)
    1) For each non unique user-defined name that is explicitly referenced, uniqueness shall be established
       through a sequence of qualifiers that precludes any ambiguity of reference.
```

SR1 is written about **user-defined names**, not about data-names — index-names are user-defined names and
are covered without exception. The standard even supplies the qualifier form for them:

```
$ python scripts/spec/cite.py --check 8.4.2.2.3 "index-name"
OK  §8.4.2.2.3 6)  (Syntax rules)
    6) The qualification of an index-name may include the name of the table with which the index-name is
       associated, as well as any name by which that table may be qualified.
```

SR6 exists precisely because index-names can be non-unique. The compiler implements neither half: it
neither refuses the unqualified reference nor accepts a qualified one.

## The code sites

* `src/Cobol.Net.Compiler/Binding/DataBinder.cs` (~2790) — the data-name "exactly one candidate" check.
  That is the shape the index-name arm needs.
* whatever registers `INDEXED BY` names — the index table has no ambiguity check at all.

## ⛔ Why this must not be a fourth copy of the rule

**PB466** (landed) wrote the procedure-name arm. `DataBinder` has the data-name arm. `ReferenceResolver`
has the LINAGE-COUNTER arm. Adding an index-name arm makes FOUR copies of one sentence, and
`feedback_one_rule_one_place` says the extraction IS the fix: one `UniqueNameResolution` service that every
name class routes through, with the qualifier forms SR2 / SR6 / SR8-SR10 describe as DATA, plus a drift
test enumerating the user-defined name classes so a new one cannot be added unrouted. This is a CLAUDE.md
rule 5 restructuring and the note says so on purpose: a fourth hand-written arm would be the smallest diff
that fits, and it is the wrong answer.
