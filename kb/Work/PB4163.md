# PB4163 — a test summary cites the wrong clause for EC-ARGUMENT-FUNCTION

**Sites:** `tests/WiseOwl.Cobol.Tests.Unit/HeldFunctionArgumentDescriptionTests.cs:121` (`HeldFunctionArgumentDescriptionTests`: the summary of the DATE-OF-INTEGER (0) test; the file is PB4124's, queued as pull request #845 and not on main when this was filed).

Review lead R2-1 (low, not blocking at round 2) of the PB4124 branch (PB4124 is held by an in-flight group, so this is a new note
that names it). The new test's summary says DATE-OF-INTEGER (0) raises EC-ARGUMENT-FUNCTION "(§14.6.13.1.3)". The reviewer found that
clause is "Fatal exception conditions" (what happens once a fatal condition exists); it does not contain EC-ARGUMENT-FUNCTION and says
nothing about arguments. The clause that raises EC-ARGUMENT-FUNCTION for an out-of-range DATE-OF-INTEGER argument is not named
here: the implementer finds it (the DATE-OF-INTEGER function's own exception paragraph and the EC-ARGUMENT-FUNCTION definition) and
validates it with `python scripts/spec/cite.py --check <clause> "<text>"` before writing it, per CLAUDE.md rule 1 (an inherited
citation is not a citation). Sweep the same test file and PB4124's other tests for the same inherited clause number.
