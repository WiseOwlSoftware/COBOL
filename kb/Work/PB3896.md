# PB3896 — national-items-displayed-as-utf-16-bytes--trim-bytes: FUNCTION TRIM of a national item trims 0x20 bytes, not national spaces (TRIM(N" AB ") is not N"AB")

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S4) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\national-items-displayed-as-utf-16-bytes--trim-bytes.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\national-items-displayed-as-utf-16-bytes--trim-bytes\`.

## Summary

Under `-std=cobol2014`, `FUNCTION TRIM` of a national argument removes bytes equal to the alphanumeric space (0x20)
from the ends of the storage, not national space characters. For N" AB " (bytes `00 20 00 41 00 42 00 20`) no leading
character is removed (the first byte is 0x00) and only the last byte is removed at the end, leaving seven bytes; the
result is reported as 3 characters long and compares unequal to N"AB". Class: wrong output. One of the mechanisms the
harvest grouped under "national items displayed as UTF-16 bytes" (fuzz programs fz00541, fz04065, fz04772, fz00210,
fz03031 and fz01620, nights 4 and 5).

## Minimal test case

Free reference format (`-fformat=free`), 9 lines, written for this record.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. NTRIM.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 NAT PIC N(4) VALUE N" AB ".
PROCEDURE DIVISION.
DISPLAY FUNCTION LENGTH(FUNCTION TRIM(NAT))
IF FUNCTION TRIM(NAT) = N"AB" DISPLAY "EQUAL" ELSE DISPLAY "NOT EQUAL" END-IF
STOP RUN.
```

File: `E:\COBOL-coord\scratch\op\pb3838\records\national-items-displayed-as-utf-16-bytes--trim-bytes.cob`.

## Observed result

Compile exit code 0, with `-Wunfinished` warnings for USAGE NATIONAL and national literals. Run exit code 0, output:

```
000000003
NOT EQUAL
```

The probe `work\national-items-displayed-as-utf-16-bytes\fprobe.cob` gives, for N" AB  " in `PIC N(5)`: TRIM length 4
(expected 2), TRIM LEADING length 5 (expected 4), TRIM TRAILING length 4 (expected 3).

## Expected result (per ISO)

Output `2` (displayed in GnuCOBOL's numeric format) and `EQUAL`.

- ISO/IEC 1989:2023 §15.96.3 3) b) (checked): when no argument-2 is specified, "if argument-1 is class national,
  argument-2 is as though a national space had been specified".
- §15.96.4 3) (checked): "If neither LEADING nor TRAILING is specified, the returned value is a character string that
  consists of the characters in argument-1 beginning from the leftmost character position that does not contain
  argument-2 through the rightmost character position after which all characters contain argument-2." For N" AB "
  that is N"AB", two national character positions.

Edition: TRIM of a national argument with LEADING / TRAILING is a 2002 feature; the 2009 committee draft for ISO/IEC
1989:2014 (CD 1.2, §15.89) defines the same result in terms of "a space character" with a national function type for a
national argument. The argument-2 list of the 2023 text is a 2023 addition, not used here.

Edition as recorded by the adjudicator: 2014 (2002 feature; same rule in the 2009 CD §15.89). `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Our compiler (WiseOwl)

WiseOwl COBOL (built from main 6ed90bd1c), `cobol ntrim.cob --std 2014 --source-format free -o ntrim.dll`, then
`dotnet ntrim.dll`: compile exit 0, run exit 0, output `2`, `EQUAL`.

## Fix site (GnuCOBOL 3.2 source, read observationally)

`libcob/intrinsic.c`, function `cob_intr_trim` (line 4120 in the 3.2 tree): the scans compare single bytes of
`srcfield->data` with `' '` from each end and size the result in bytes. For a national field the scans have to step by
two-byte character units and compare with the national space (`00 20` in GnuCOBOL's big-endian UTF-16 national
representation, the encoding its own N" " literal uses).

## Draft issue

**Title:** FUNCTION TRIM of a national item trims 0x20 bytes, not national spaces (TRIM(N" AB ") is not N"AB")

**Body:**

Environment: GnuCOBOL 3.2.0 (Ubuntu gnucobol3 3.2-4build1), x86_64 Linux.

Steps: `cobc -std=cobol2014 -fformat=free -x ntrim.cob && ./ntrim` with

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. NTRIM.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 NAT PIC N(4) VALUE N" AB ".
PROCEDURE DIVISION.
DISPLAY FUNCTION LENGTH(FUNCTION TRIM(NAT))
IF FUNCTION TRIM(NAT) = N"AB" DISPLAY "EQUAL" ELSE DISPLAY "NOT EQUAL" END-IF
STOP RUN.
```

Observed: `000000003`, `NOT EQUAL`.

Expected: a length of 2 and `EQUAL`. ISO/IEC 1989:2014 (2023 §15.96.3 rule 3b and §15.96.4 rule 3): for a national
argument the characters removed are national spaces, and the result runs from the first through the last position
that is not a national space.

Cause: `cob_intr_trim` in libcob/intrinsic.c scans bytes for `' '`; a national space is the two bytes `00 20`, so no
leading national space is ever removed and the trailing scan stops after one byte, leaving an odd byte count.
