# PB5654 - comments that misstate their rule (one mechanism: the comment was true when written, or true for one edition only)

**1. `CommunicationSectionBinder` class summary is stale (PB5604 R1-1 LEAD, low).** "`CommunicationSectionBinder.cs:119` The class summary of
CommunicationSectionBinder still says every record written after the CD joins the redefinition class and that the anchor is the FIRST written record; after
PB5604 an out-of-line record (pointer-class, dynamic- or variable-length) joins no class and the anchor is the first record with a character window."
The fix rewrites the summary to say that.

**2. `CompilerTemps.ForInvocationObject` doc comment (PB5598 R2-2 LEAD, low).** `CompilerTemps.cs:34` calls the temporary "the §2002:8.4.2.4.2 temporary",
but §2002:8.4.2.4.2 is the syntax rules (SR4 is the ANY LENGTH ban); the temporary is defined by §2002:8.4.2.4.3 GR1. Verified in this filing:
`cite.py --check "§2002:8.4.2.4.3 GR1" "An inline method invocation references a temporary data item with the same class, category, and content as the
temp-identifier"` OK; `cite.py --check "§2002:8.4.2.4.2 SR4" "shall not be described with the ANY LENGTH clause"` OK.

**3. D-WRT1, `FileModel.TransfersPastRecord`, `SequentialIoEmitter.SentRecordImage` (PB5579 LEAD).** The report says: "citation of '§2023:14.9.51.4 GR13' in
SentRecordImage / TransfersPastRecord comments and D-WRT1 is wrong (§2002:14.8.47.3 GR12; §2023:14.9.32.4 GR6): untouched". Checked in this filing:
- `§2023:14.9.51.4 GR13` is RIGHT for 2023: `cite.py --check "§2023:14.9.51.4 GR13" "the content of the bytes that extend outside the end of record-name-1
  are undefined"` OK, and `§2023:14.9.35.4 GR15` (REWRITE) says the same, OK.
- `§2023:14.9.32.4 GR6` named in the lead is WRONG: the same quotation FAILs there (14.9.32 is the RELEASE statement; the right clause is §2023:14.9.35.4
  GR15). A fixer takes nothing from that half of the lead.
- The real defect is the missing 2002 side. The mechanism (determination D-WRT1: WRITE/REWRITE of record-name-1 past its end sends the record AREA's
  content) runs at every edition, but the comments, D-WRT1 and the goldens cite only 2023. The 2002 rules are `§2002:14.8.47.3 GR12` (WRITE) and
  `§2002:14.8.33.3 GR15` (REWRITE), both `cite.py --check` OK with the quotation "if the number of bytes to be written to the file is greater than the number
  of bytes in record-name-1"; the 2002 undefined-element entries are `§2002:B.2` items 68 (WRITE) and 48 (REWRITE), whose text "The content of the bytes
  that extend beyond the end of the record are undefined" is OK in `§2002:B.2` (the 2023 items 64 and 49 are `§2023:A.2`). Note 2002 says "extend beyond",
  2023 "extend outside": quote each edition's own words.
- Files carrying the 2023-only citation: `FileModel.TransfersPastRecord` and `SequentialIoEmitter.SentRecordImage` (summaries),
  `docs/conformance/3.1/D-WRT1.md`, and the golden comments of `conformance-suite/cases/14.9.51-WRITE/pb1907_write_past_record.cob`,
  `conformance-suite/cases/14.9.51-WRITE/pb5217_write_beside_odo_record.cob`, `conformance-suite/cases/14.9.51-WRITE/pb5579_write_file_from_own_record.cob`,
  `conformance-suite/cases/14.9.35-REWRITE/pb1907_keyed_rewrite_past_record.cob`, `conformance-suite/cases/14.9.35-REWRITE/pb1907_past_record_whole_record.cob`,
  `conformance-suite/wiseowl/cases/14.9.51-WRITE/pb1880_national_pad_record_sequential_and_relative.cob`.
