# PB2847 — OPEN — the not-located reason is dropped on two pointer paths and keyed too coarsely

Found by the train 1047 lander's review (step 5b; `E:\COBOL-coord\scratch\reports\train1047-report.md`, finding (d)) on cluster 45B (PB2097's module registration), stated by the reviewer; the sites are confirmed by reading the code. The lander had no ids left; the land unit reserved this id and the resume unit of 2026-10-08 21:46 PDT filed it.

## What is wrong
1. CALL (`ProgramTable.cs:312-313`) and ADDRESS OF PROGRAM (`ProgramRegistry.cs:167/186`) append
   `NotLocatedReason(name)` to their EC-PROGRAM-NOT-FOUND / EC-FUNCTION-NOT-FOUND text. `SET … TO ENTRY`
   (`src/Cobol.Net.Compiler/CodeGen/Verbs/PtrEmitter.cs:250`, `ProgramRegistry.EntryOf`) and ADDRESS OF FUNCTION
   (`PtrEmitter.cs:294`, `ProgramRegistry.FunctionAddressOf`, raised at `:330`) report no reason, so the user is not
   told why the module was not found (a version skew, a load failure).
2. `ProgramTable._probeFailure` (`ProgramTable.cs:74`, written at `:837`) is a `Dictionary<string, string>` keyed by
   the externalized name alone. A failed probe for a program and a later lookup of a function (or another module's
   entry) with the same name share one slot, so a stale or unrelated reason can be printed.

The wrong answer is the run-time message text (finding 2 can print a reason that belongs to a different lookup);
program data is unaffected.

## Done when
Every not-found path carries the reason through one helper, and the probe-failure key includes what was probed for
(program, function, entry), with a unit test per path.
