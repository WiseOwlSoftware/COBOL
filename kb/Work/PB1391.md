## Finding — `abbreviated-combined-relation-conditions` (under-rejects; rows `SR-8.8.4.12.3-1`)

**Mechanism.** The §8.8.4.12.3 SR1 prohibition is implemented only as a side effect of the boolExprAhead() path: BindPrimaryBoolean resets the abbreviation carry, but a boolean relation with B-operator-free operands (item = item, item = boolean literal) is bound by BindComparison's relation arm, which seeds carry.Subject/Op, so a following abbreviated relation is silently expanded; and where the prohibition does bite, the refusal surfaces as the COBOLNET2319 internal-error diagnostic instead of naming the rule.

**Repro.** --std 2023: 01 B1 PIC 1 VALUE B"0". 01 B2 PIC 1 VALUE B"1". 01 B3 PIC 1 VALUE B"1".  IF B1 = B2 OR <> B3 DISPLAY "T" ELSE DISPLAY "F" END-IF   (also IF B1 = B2 OR = B3; and IF B1 B-AND B2 = B"0" OR = B3)

**Expected from the spec.** Compile-time error naming §8.8.4.12.3 SR1 for all three: relation-condition-1 is a boolean relation (Format 2 — §8.8.4.2.3 SR2/SR3 exclude boolean operands from Format 1), so no abbreviated relation may follow it.

**Observed / reasoning.** First two compile with no diagnostic and print T and F respectively (expanded as B1 <> B3 / B1 = B3). Third is rejected only by COBOLNET2319 "the condition form abbreviated relation with no preceding relation subject was refused without a diagnostic naming the rule it breaks; this is a COBOL.NET internal error". The same internal-error wording appears for the plain illegal shape `IF A IS NUMERIC OR < C` (no relation-condition-1 at all, §8.8.4.12.1) — the Refused("abbreviated relation with no preceding relation subject") arm in BindAbbreviatedRelation has no catalog diagnostic of its own. Fix: record in the carry whether the stated relation was a boolean relation (by operand category, not by parse path) and refuse with a named diagnostic in BindAbbreviatedRelation / BindSoleOperandCondition's abbreviation arm.

**Code site.** src/Cobol.Net.Compiler/Binding/Procedure/Verbs/ConditionBinder.cs#BindComparison (relation arm sets carry for boolean operands); src/Cobol.Net.Compiler/Binding/Procedure/Verbs/ConditionBinder.cs#BindAbbreviatedRelation (Refused without catalog code)

## What the fixer owes

Make the SR1 prohibition a property of the relation's CATEGORY (boolean operands), decided once where the carry is seeded, not a by-product of which parse path bound it; name the rule in the diagnostic. Sweep every seeding site of AbbrevCarry (BindComparison, BindPrimaryBoolean, EVALUATE partial spines).
