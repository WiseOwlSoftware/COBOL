# PB3686 — the PB3162 external-prototype relaxation was not applied to the RETURNING lane

**Sites:** `src/WiseOwl.Cobol.Runtime/Control/ActivationRelations.cs` (`ReturningConformance` and `SameElementaryClauses`, about
line 715; `SamePointerRestriction` is the relaxed comparison); `tests/WiseOwl.Cobol.Tests.Unit/PointerRestrictionLanesAgreeTests.cs`
(the three-lane agreement test); `conformance-suite/cases/14.8.2-Formal-parameters-and-arguments/pb3686_returning_external_prototype_pointer.cob`.

Filed 2026-10-24 by the enqueue unit's clerk from the R1-1 LEAD (low, not blocking at round 1) of the PB538 review,
branch `worktree-wf_6ffe8083-b46-1` (PR #533, merged), report
`E:\COBOL-coord\scratch\reports\w20261032a-PB538-report.md`. Not re-probed; a code reading.

## What happens

PB3162 (landed) applied the external-prototype relaxation (`SamePointerRestriction`) to `MaySet` and to the BY REFERENCE
pointer arm, but not to the RETURNING lane: `ReturningConformance` still compares a restricted pointer's `Clauses` with
`SameElementaryClauses` (strict string equality). The CALL RETURNING lane therefore still answers the PB3162 pair the
old way, so a RETURNING pointer pair that MaySet and BY REFERENCE accept can still be refused (or answered the other way).

## The spec judgment the clerk did not make (answered by the landing below)

Whether the relaxation belongs on the RETURNING lane is decided by the same rules PB3162 cites; the landing derives it
from §14.8.3.3, §13.18.60.4 GR25 and §12.3.8.4 GR10 c) and makes the three lanes one comparison.

## Landed (wave 20261500, group H)

Re-probed on the branch's own build (`--std 2014`, checking on): a program-pointer RETURNING pair whose prototypes have no
compile-time signature (callee `RETURNING R TYPE TB` restricted to X3686B, caller `RETURNING PA TYPE TA` restricted to
X3686A) raised EC-PROGRAM-ARG-MISMATCH for `CALL U3686 RETURNING PA` and for `CALL "U3686" RETURNING PA`, though `SET PB TO PA`
and BY REFERENCE / BY CONTENT admit the same pair (PB3162).

**Root.** `ReturningConformance`'s elementary tail compared every pair with `SameElementaryClauses` (strict string
equality of `Clauses`), so a class pointer's restriction, the one fact the other two lanes read through
`SamePointerRestriction`, was compared the old way. **Fix.** Two class pointers of one category take the same relation
there (`Category` equal and `SamePointerRestriction(receiving.Clauses, sending.Clauses)`); every other pair keeps
`SameElementaryClauses`. §14.8.3.3's "same ... USAGE clauses" reads the USAGE clause's TO phrase as the pointer's type,
which §13.18.60.4 GR25 / GR26 define as the prototype's signature, and §12.3.8.4 GR10 c) leaves an unresolved signature to
the run unit. An unrestricted pointer opposite a restricted one is still refused (a different USAGE clause).
`SignatureDifference` (the other `SameElementaryClauses` caller, §9.3.8.2.3's symmetric "same description") keeps exact
identity on purpose: an equivalence must stay transitive.

**Tests.** Unit `PointerRestrictionLanesAgreeTests` (SET, BY REFERENCE and RETURNING give one verdict for each restricted
pair, program- and function-pointers; unrestricted opposite restricted; data-pointer type identity; category mismatch).
Golden `14.8.2-Formal-parameters-and-arguments/pb3686_returning_external_prototype_pointer` (prototype CALL and dynamic
CALL RETURNING conform; the unrestricted receiver is refused).
