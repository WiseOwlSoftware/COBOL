# PB5089 - at --std 85 INSPECT CONVERTING accepts a repeated character in the from-literal, and the first occurrence decides (the later editions' behavior)

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/InspectBinder.cs` (whole: the records name the CONVERTING arm, which calls `CheckInspectLiteralSizes` for the size rule and asks nothing about a repeated character at --std 85, and no member).

**Mechanism.** 1985 says the same character must not appear more than once in literal-4 or the data item of identifier-6 of CONVERTING. The CONVERTING arm checks sizes only.

**Found by.** The 1985 `--std=85` draft triage (kb/Work PB4995 item 3): each rule below is a conformance-suite draft that did not MATCH at `--std 85`, and its adjudicator decided COMPILER-DEFECT. Harm and observed text are the records'; nothing here was re-derived.

**Inventory.** The traceability inventory carries no 1985 rows yet, so `inventory_rows` is empty; the rows this note covers are the 1985 rule ids listed below (catalog `docs/rearchitecture/spec-rule-catalog-1985.json`).

**Rules (1; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-SR-VI.6.18.3-10` - `§1985:VI.6.18.3 SR10` (record harm: under-rejects, slice-04): §1985:VI.6.18.3 SR10: "The same character must not appear more than once either in literal-4 or in the data item referenced by identifier-6." Literal-4 of `INSPECT WS-X CONVERTING "ABA" TO "XYZ"` holds the character A twice, so the statement of line 8 breaks the rule. The draft reads the rule correctly; its control (CONVERTING "ABC" TO "XYZ") compiles and displays XYZX.

**Repro (`1985-SR-VI.6.18.3-10`, slice-04).**

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. INSPDUP.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 WS-X PIC X(4) VALUE "ABCA".
       PROCEDURE DIVISION.
       MAIN-PARA.
           INSPECT WS-X CONVERTING "ABA" TO "XYZ".
           DISPLAY WS-X.
           STOP RUN.
```

**Expected (from the 1985 text).** --std 85 refuses `INSPECT WS-X CONVERTING "ABA" TO "XYZ"`, at the statement. The deciding words: "The same character must not appear more than once either in literal-4 or in the data item referenced by identifier-6." (§1985:VI.6.18.3 SR10).

**Observed (copied from `1985-SR-VI.6.18.3-10`).** Compile exit 0 with no diagnostic; the program runs and displays `XYCX` (the first A of literal-4 decides, the later editions' behaviour). `CONVERTING "AA" TO "XY"` likewise compiles and displays `XBCX`. Code site: src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/InspectBinder.cs, the CONVERTING arm (it calls CheckInspectLiteralSizes for the size rule, SR9, and asks nothing about a repeated character at --std 85). cobol.exe 25.0.0 of E:/COBOL/.claude/worktrees/pin-triage (e8a1b94f50), invoked as the conformance-suite adapter's flag command: cobol t.cob --std 85 --source-format fixed --flag-extensions -o t.dll
