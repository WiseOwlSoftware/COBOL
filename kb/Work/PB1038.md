# PB1038 — OPEN

## Measured
```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. B09CS.
       ENVIRONMENT DIVISION.
       CONFIGURATION SECTION.
       SPECIAL-NAMES.
           SYMBOLIC CHARACTERS BEL IS 8
           CLASS CC IS "A" BEL.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 X PIC X VALUE "A".
       PROCEDURE DIVISION.
           IF X IS CC DISPLAY "CC" END-IF
           STOP RUN.
```

→ `error COBOLNET1970: 'BEL' is not a clause of the SPECIAL-NAMES paragraph — the ISO §12.3.7.2 general format lists
the clauses …`. The source IS illegal, so the verdict is right; the message blames the wrong rule and points the user
at a clause list.

## The rule
`cite.py --check 12.3.7.3 "shall specify neither a symbolic-character figurative constant nor a zero-length literal"`
→ `OK §12.3.7.3 11)`. SR-12.3.7.3-11 is CONFORMS (PB226 screens all seven literals) — for LITERALS the grammar
accepts; a symbolic-character NAME never reaches that screen because the CLASS operand rule does not admit a word.

## What the fixer owes
Admit a user-defined word in the CLASS (and ALPHABET literal-phrase) operand positions of the grammar so PB226's
single operand decoder sees it, and report SR11 by name when the word is a symbolic-character. Sweep the other SR11
positions (ALPHABET literal-1/-2/-3, LOCALE literal-4, ORDER TABLE literal-9, CLASS literal-5/-6). Negative golden.
