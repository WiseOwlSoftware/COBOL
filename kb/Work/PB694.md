# PB694 — LANDED (wave 1097 F) — the two sub-rules PB345 could not honestly claim

Found 2026-09-05 by the `PB345` implementer (report §"New defects" 2), which implemented §13.4.5.3 SR3 a) (the
RECORD clause must establish a maximum) and deliberately left `SR-13.4.5.3-3` GAP because b) and c) are not
screened and CONFORMS would have been false.

## The rule

§13.4.5.3 SR3: "When no record description entries are specified: … b) a FILE phrase specifying file-name-1 and the
FROM phrase shall be specified on all WRITE and REWRITE statements associated with the file, and c) an INTO phrase
shall be specified on all READ statements associated with the file" (`cite.py --check 13.4.5.3 "an INTO phrase
shall be specified on all READ statements associated with the file"` → OK 3) c)). §14.9.30.4 GR6 defines the
as-though record only for the INTO form, so the phrase-less READ has no meaning the standard gives it.

**Repro:** `READ FIN AT END … END-READ` (no INTO) on `tests/conformance/2023/pb345_record_less_fd_area.cob`'s `FIN`
compiles clean and reads into an area the program cannot name.

## What has to be settled

- c) is a plain statement-level screen: beside the other phrase rules in `StatementValidation`, keyed on the file's
  records holding only the implied one (a flag on `FileModel`, or `Records[0].CobolName is null`) — dispatchable on
  its own.
- b) requires the `WRITE FILE … FROM` / `REWRITE FILE … FROM` form (§14.9.51.2 Format 2 / §14.9.35.2), which
  `tests/conformance/negative/a413-write-file-format-1.cob` pins as DECLINED (Annex A.4.13's optional element, PB282's
  family). Declining the form while accepting the record-less FD leaves a legal file that can be read and never
  written. Either the decline is documented as the reason a record-less WRITE is rejected (a `documented
  non-support` row with the A.4.13 posture, and a diagnostic that says so rather than silence), or A.4.13's element
  is implemented — an owner posture question the process review's Report-Writer question already resembles. Settle
  which before dispatching b).

## Landed 2026-10-16 (wave 1097 F)

**Re-probe** (main at `32f372674`, own Debug build): `FD F RECORD CONTAINS 10 CHARACTERS.` (sequential) and
`FD R RECORD CONTAINS 5 CHARACTERS.` (relative, ACCESS DYNAMIC), no 01 under either, `READ F AT END …` and
`READ R INVALID KEY …` / `READ R NEXT AT END …` without INTO: compiled clean and ran (c) reproduced). `WRITE FILE F
FROM W` / `REWRITE FILE F FROM W` on the record-less F: COBOL1706 each (b) as the note said).

**The A.4.13 question was already settled, so b) needed no owner decision.** A.4.13 is Not claimed and refused
(kb/Work PB282, CONFORMANCE.md §5 row A.4.13), and PB1255 (landed) already closed the CODE-SET row that leans on the
same declined phrase as a joint decline. b) is a requirement on SOURCE, and it is enforced structurally: the
record-name-1 alternative names "a logical record in the file section of the data division" (`cite.py --check
14.9.51.3` OK rule 5; `14.9.35.3` OK rule 1), which a record-less entry lacks (its implied record has no name), so no
WRITE or REWRITE without the FILE phrase can be associated with the file, and the FILE form is refused COBOL1706.
The consequence (a record-less file is INPUT-ONLY here) is now stated in the A.4.13 row, which is the §4.2.7 user
documentation, and in `FILES_DESIGN.md` D18.

**c) — the fix.** `StatementValidation.CheckReadIntoOnRecordLessFile` → **COBOL3983** (Error, every edition),
asked by `SequentialIoBinder.BindRead` BEFORE the `!file.IsSequential` reroute, so the relative arm
(`KeyedIoBinder.BindRead`) is under the same call. Its antecedent is the new `FileModel.HasNoRecordDescriptionEntries`
(`HasFd && !IsSortMerge && !IsReportFile && !WrittenRecords.Any()`), so it holds even where
`MaterializeImpliedRecord` could not build the implied record (COBOL1836/1837). Witnesses
`negative/pb694-read-no-into-sequential` (its READ INTO line draws nothing) and `negative/pb694-read-no-into-relative`,
both `reject-at: 85 2002 2014 2023`; the positive `2023/` and `85/pb345_record_less_fd_area` (READ INTO on both
organizations) are unchanged.

**Row.** `SR-13.4.5.3-3` DIVERGES → CONFORMS (batch `w1097f-PB694`), GAP 74 → 73.
