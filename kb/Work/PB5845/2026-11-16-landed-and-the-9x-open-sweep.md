# PB5845 landing: the edition choice and the sweep of every 9x an OPEN answers

**Choice (one `DialectBehavior`, number 28, VCR row 7.84).** `DialectBehavior.LinageViolatingOpenLeavesFileOpen`, from 2002. The 2002 text (`§2002:13.16.32.3 GR6`, cite.py OK) carries the same continuation as 2023 ("the LINAGE-COUNTER special register is set to 0 and remains at that value until the file is closed; and all subsequent WRITE statements referencing the file cause the EC-I-O-LINAGE exception condition to continue to exist until the file is closed"), so 2002 keeps what it does and only 85 changes. `FileRegistry.SharedOpenAttempt` asks it and, at 85, asks `SequentialConnector.RefuseOpenForLinage` BEFORE `c.Open(mode)`: nothing is opened, created or truncated, the status is '90' with EC-I-O-LINAGE named, and the already-open '41' (answered earlier by `RefusedAsAlreadyOpen`) still wins for a file that is open.

**Sweep of every 9x an OPEN answers** (`grep '"9[0-9]"'` over `src/WiseOwl.Cobol.Runtime`): '90' (`FileStatusCode.LinageValueViolation`) is given only by `SequentialConnector.BeginLinagePage` after a successful OPEN OUTPUT, for a sequential or line sequential file with a LINAGE clause (the LINAGE operands reach the OPEN only for such a file). '91' (`FileStatusCode.CharacterWithoutByteImage`) is a WRITE or REWRITE's status (`SequentialConnector.WriteRecord`/`RewriteRecord`, `KeyedConnector` write screen), never an OPEN's. `MessageStore`'s '91', '92', '93' belong to the message-control store of the communication module, not to a file OPEN. A relative or indexed connector never answers a 9x to an OPEN. The 9x that other statements give (a WRITE at a page transition whose LINAGE operand no longer conforms, with its latch, and the '91' WRITE/REWRITE) are not this rule and are unchanged; the page-transition WRITE leaves the file open at every edition, since the file is open there.

**What 85 still does not derive.** The 2002 continuation of a violation found at a WRITE (the counter at 0, every later WRITE raising until the CLOSE) has no 1985 text; the implementation applies it at 85 as its own determination (status '90', DOC-A.1-110). It is not pinned by an 85 case.
