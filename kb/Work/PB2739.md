DIVPROBE.` / `           PROCEDURE DIVISION.` (column 12) / `       REMARKS.` / `           DISPLAY "REACHED".` / `           STOP RUN.` gives `divprobe.cob(4,10): error COBOL0001: unexpected .` - FixedFormConverter.CommentEntryOf asks FirstAreaAWord, which returns null for a header in Area B, so the text is still "in the IDENTIFICATION DIVISION", REMARKS is taken for the obsolete comment-entry paragraph, its header becomes `REMARKS. .` and the DISPLAY and STOP RUN lines are discarded as comment-entry body. The same program with PROCEDURE DIVISION at column 8 prints REACHED, and the same paragraph moved into a copybook COPYed after the column-12 header also prints REACHED, because DivisionCursor.InIdentificationDivisionAt reads the logical text-words and leaves the division at any `... DIVISION`. Two readers of one rule, one per kind of text, give different answers for the same text.

**Landed (wave 1049 group E).** `DivisionCursor` is now the ONE rule for which division a text is in: `Feed` reads a `DIVISION` word (entered after IDENTIFICATION/ID, left after any other word), or one of PROGRAM-ID/CLASS-ID/FUNCTION-ID/INTERFACE-ID/METHOD-ID (`CompilationUnitStart.UnitParagraphNames` plus METHOD-ID, §11.2.1), over text-words wherever they begin (§6.3.1). Three defects had one root. (1) The fixed-form walk (`FixedFormConverter.CommentEntryOf`) decided a header only in Area A; it now calls `DivisionCursor.Read` on every non-comment-entry line, and Area A survives only as the start/end of the COBOL-85 comment-entry paragraph; `DivisionHeader` is deleted. (2) Both copies treated ANY word ending in -ID as a paragraph header (`MOVE 2 TO CUSTOMER-ID` re-entered the identification division); it is a closed list now. (3) The merged driver flushed one block per directive boundary and `CopyProcessor` made a fresh cursor per block starting at the file state, so a COPY after any directive line was judged to stand in the IDENTIFICATION DIVISION; the cursor now belongs to the TEXT (`Run.Render(input, division)`), `ExpandCopiesOneLevel` reads it through each block (`Finish`), skips the COPY statement (`Skip`, so REPLACING pseudo-text is not read) and adopts a spliced library text end division (`Adopt`); `CopyProcessor._libraryStartsInIdentification` and `CopyStandsInIdentificationDivision` are deleted. Goldens: 85/pb2739_indented_division_header_remarks, 85/pb2739_data_name_ending_id_then_copy, 2002/pb2739_copy_after_directive_line; unit tests: DivisionCursorTests. No edition gating differs, so there is no per-edition negative. FACTORY and OBJECT paragraphs are not entries to the identification division by design (no comment-entry exists in them).
