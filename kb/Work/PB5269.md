# PB5269 - three review leads of PB5234

**R1-1 (the harm; PB2044's).** `scripts/hooks/forbidden_commands.py` decided whether a unit's `git push` leaves this
repository by the push's first positional word, after dropping every word that starts with `-`. So
`git push --repo=https://github.com/WiseOwlSoftware/claude-skills.git` read as `origin` and passed. It also asked git for the
remote's fetch URL, ignoring `remote.<name>.pushurl`, and ignored the configured default push remote
(`remote.pushDefault`, `branch.<b>.pushRemote`, `branch.<b>.remote`). Fixed at the root: the destination is resolved as git
resolves it (`_push_urls`): `--repo=X` / `--repo X`, else the first positional word, else the branch's `pushRemote`,
`remote.pushDefault`, the branch's remote, `origin`; a remote name is read to its push URLs with
`git remote get-url --push --all` (pushurl over url, `insteadOf` applied); the call's own `-c k=v` options are passed to
git; EVERY resulting URL must be this repository's origin or the push is refused. Options that take a value as the next word
(`--repo`, `--receive-pack`, `--exec`, `-o`, `--push-option`) are skipped so a value is never read as the repository.
Self-test cases (ScratchRepo scratch repositories whose origin is this repository's): `--repo=URL` (with and without a
refspec; the old rule blocked the with-refspec form only because it read `HEAD` as a remote name), `--repo URL`, a pushurl
elsewhere, `remote.pushDefault` elsewhere, `branch.<b>.pushRemote`, `branch.<b>.remote`, a `-c remote.origin.pushurl=`,
each with a same-repository twin that must pass.

**R1-2.** Three unit-push cases (`QS + git push`, `xargs -n1 git push`, `` echo `git push` ``) had been flipped to expect
"not blocked", so they passed whether or not the push was seen, and their comments were stale. Each is now a pair: pointed at
another repository (must block) and at this one (must pass); `git` after `xargs` is still found.

**R1-3.** `Step.substitution` had no reader left but its own self-test; deleted with that test's use of it (the depth
level carries the nesting), `shell_location.py`'s "rule 7" became rule 6, the self-test's reference to the deleted rule 4
reader went, and `docs/rearchitecture/DESIGN-test-build-ci.md` §1.7 now describes the depth, not the substitution marking.

**Round 1 of the review (same branch).** (a) The first fix preferred `--repo` to the positional repository word; git does the
reverse (measured with two bare repositories: `git push --repo=origin ../b.git` pushes to b.git), so
`--repo=origin <url> HEAD` passed where main's hook blocked it. The positional word now wins. (b) A gap that predates the
branch: the destination ignored git's own inputs. A push carrying `--git-dir`, a `GIT_DIR` / `GIT_COMMON_DIR` / `GIT_CONFIG*`
assignment anywhere in the line (`GIT_DIR=x git push`, `export`, `env`, PowerShell `$env:` / `Set-Item env:`) or a
`-c url.*.insteadOf` / `pushInsteadOf` is refused (`_redirected`); a literal push URL is refused when the repository
configures a URL rewrite; the docstring lists what is resolved and what is refused. Git processes remain one to three
per push call inside a unit, none otherwise.
