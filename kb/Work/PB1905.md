# PB1905 — OPEN

Filed 2026-10-01 by the gl4 (witness-reuse) golden-lane lander, from the gl4-misc-p2 validator's side note on the
draft `l1g4_leap_second_off_explicit_2002` (its `01 CD PIC X(21)` was rejected at `--std 2002` with COBOLNET0901, which
is correct: §8.3.2.1 1) "Reserved words shall not be used as user-defined words or system-names", cite.py --check OK).

**Shape.** `scripts/gen-reserved-words.ps1` line 208 assigns one provenance string to every word with `r85` set and
`r2023` clear: `'1985-reserved, removed post-85 (GnuCOBOL per-standard lists; absent from ISO 2023 §8.9)'`. It never
looks at `r2002` / `r2014`, so a word still reserved in 2002 (CD: `true, true, false, false`) or in 2014
(CLOCK-UNITS, COBOL, COMMUNICATION, EVERY, MODULES, POSITION, PROCEDURES, PROCEED, REFERENCES, WORDS:
`true, true, true, false`) is described as removed after 1985. The flags drive the compiler and are right; only the
human-readable provenance is false, and it is what a reader checks when a reserved-word rejection surprises them.

**Code sites.** `scripts/gen-reserved-words.ps1:208` (the `elseif ($f85 -and -not $f23)` arm); the generated
outputs `src/Cobol.Net.Editions/ReservedWords.Table.cs` (for example line 66, CD) and
`tests/version-matrix/reserved-words.json` (provenance fields).

**Fix.** Name the last edition that reserves the word (`removed after 2002`, `removed after 2014`) from the flags the
same arm already has, then regenerate both outputs with the generator (never hand-edit the generated table).
`ReservedWordsDriftTests` holds the table to the JSON.
