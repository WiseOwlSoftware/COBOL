# PB3859 — markdown units are too coarse for the file-set partition

**Sites:** `scripts/arch/source_units.py` (`markdown_units`, `touched`, `units`), `scripts/orchestrator/inflight.py` (`inflight_units`, `unit_meet`, `collision`), `.claude/skills/workstream/check_practices.py`, `docs/rearchitecture/DESIGN-orchestrator-loop.md` (section 9 item 1b).

## What happens

The partition (kb/Work PB3670) lets two groups run side by side when their claims on a shared file touch different
UNITS. For markdown, `source_units.markdown_units` makes one unit per heading: every line belongs to the nearest
heading above it. `docs/CONFORMANCE.md` (3,859 lines) has eight `##` sections; section 3 (Behavior determinations) is
~2,000 lines under one heading and section 7 (the Annex A.1 register) ~390 table lines under one heading. So a group
editing row `DOC-A.1-1` (line ~3488) and one editing `DOC-A.1-92` (line ~3548) MEET on the unit
`7. Annex A.1 — implementor-defined language element register …`, and the later one waits, although git's three-way
merge combines the two edits without conflict.

Measured 2026-10-26 (owner's pre-fuzz deadline, PB3852): PB2923, PB3514, PB3294 and PB3697 were all held behind
PB3839's branch on `docs/CONFORMANCE.md`; only PB3514 shares a row with PB3839 (DOC-A.1-92). The owner overrode the
planner by a hand-planned wave whose `member_set` names rows.

The history says the conservative reading buys nothing: PB3643's replay (`merge_drivers.py --hunks docs/CONFORMANCE.md`)
found 17 conflicted merges of 199 where both parents changed the file, and its conflict hunks were revisions of the
SAME paragraph or row (31 revision hunks, 1 insertion).

## Fix direction

Give the markdown reader units at the grain branches actually collide on, with one rule, not a list of files:
- a TABLE ROW whose first cell is an id (`| DOC-A.1-92 |`, any `| <ID> |` row) is its own unit, named by that id; rows
  that share an id (DOC-A.1-92 has several) are one unit;
- every heading level stays a unit for the prose between headings, so section 3's `###` subsections are units.
Then a note's Sites that name `docs/CONFORMANCE.md` (`DOC-A.1-92`) resolve to that row, and `touched` maps an in-flight
branch's hunks to the rows it changed. A drift test pins it: two claims on different rows of one table never meet,
two on the same row always do, and a row the file does not hold claims the whole file (the present rule for an
undeclared name). Update DESIGN-orchestrator-loop.md section 9 item 1b in the same change.

## Not this

PB3738 (one file per determination) splits section 3's prose but keeps the A.1 table as a table, so it does not fix
the A.1 case; a merge driver (PB3643, retired) is not the question, because these merges do not conflict.
