# PB4301 - For a misspelled clause keyword the closed-format residue arm names the first reserved word after it as "not a clause"; the misspelled word is named only by ClosedFormatPass, which a unit with any parse error never reaches

Found by the Mythos front-end review, gap pass, 2026-10-31 (GAP-REVIEW.md, G4-3; artifact https://claude.ai/artifact/KaxkLe85tfZBZ3nZ1tDGTs). Pin d7daee1cf.

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs` (`Sync` :551-563, `IsClosedFormatResidueAhead` :591-608, `ClosedFormatResidue` :1022-1043, the 0g arm ~:815-860); `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolExpressions.g4:58-70` (`unrecognizedClause`, `unrecognizedDataClause`); `src/WiseOwl.Cobol.Compiler/Validation/ClosedFormatPass.cs:225` (`Refuse`); `src/WiseOwl.Cobol.Compiler/CompilerDriver.cs:154`.

**Finding.** For a misspelled clause keyword the closed-format residue arm names the first RESERVED word after it as "not a clause": `i3` `ASIGN TO` -> COBOL1970 at TO; `I27` `SINC LEFT` -> COBOL1941 at LEFT; `I26` `OCURS 3 TIMES` -> COBOL0001 at 3 plus a phantom level-03 COBOL1941 at TIMES; `i9/m7` `OCCURS 0 TO TIMES` names TO, a word OF the clause, where the fault is the missing integer-2 (section 13.18.38.2). The misspelled word is refused by name only by ClosedFormatPass at bind, which never runs when any parse error exists (`i29`: `SELECT F1 FOO.` beside `MOVE A B.` draws nothing for FOO; `I23` alone draws the by-name COBOL1970). cobc says "unexpected Identifier" at the word (class, not spelling).

**Fix direction.** Where the run the error production opened (unrecognizedClause/unrecognizedDataClause) is ended by a reserved word, report the run's OPENING word by name at parse time. Where the stray word is one the PRECEDING clause could have taken at the point it ended (the walk from the clause's end takes it: `OCCURS 0 TO` then TIMES), report that clause as incomplete with Expected() at the next token. Membership in TokensWithin is NOT that test (the first report's second branch was wrong): `SYNC LEFT RIGHT` (D1) and `PIC X ON` (D2) keep today's accurate "is not a clause" message. The integer-ended runs (`I25` `VALEU 5` -> COBOL0307; I26) need their own decision or a drift-test exclusion. Reconcile with the analysis note on shape-only refusals delegated to the bind (G4-4) so one word is never named twice.

**Citations checked** (`python scripts/spec/cite.py --check`): section 13.18.38.2 "integer-2 TIMES".

## Landed (wave 20261823 A)

Re-probed on a build of main 100d2f347 plus the PB4299 group: every probe reproduced (i3 COBOL1970 at TO, I27 at LEFT, I26
a bare COBOL0001 at the 3 plus a phantom level-3 entry's COBOL1941 at TIMES, i9/m7 TO, I25 COBOL0307 only; D1 and D2
named RIGHT and ON, accurately). i29 (`SELECT F1 FOO.` beside another parse error) is the bind-delegation trade-off,
PB4313's, and stays there.

**Fix.** Three parts in `CobolErrorStrategy`, one root: the by-name refusal of a foreign run named the wrong token.
(1) `OffendingPosition.ResidueRun` finds the error production's node the parser stands inside (the loop's Sync) or has just
completed (the data form's run returns at an integer); the 0g hint words the row's refusal from the run's OPENING item
(`ResidueRefusal`, the item `ClosedFormatPass` quotes at bind), and the hint's `Subject` makes the report stand at that
token. The run's tail is the refusal's own (`OrphansItsTail`), so `OCURS 3 TIMES` no longer leaves a level-3 entry
`3 TIMES` to be refused again; where a period would let the sentence at the token follow (`FOO` then `05 C PIC X.`) the
run is refused in a report of its own, once (`NoteRunRefused`), and the missing period is the next report's.
(2) `ClosedFormatResidue` defers where the closed construct before the token could take it
(`OffendingPosition.ClosedConstructTakes`: the TO of `OCCURS 0 TO TIMES`, ISO 13.18.38.2).
(3) `AdmittedKinds` fifth shape, a reserved word where an operand is due: `OCCURS 0 TO TIMES` now draws COBOL5506 at the
TIMES "expected a user-defined word or an integer literal" (was the bare COBOL0001), and so do the predecessor's lead
(`DISPLAY WHEN OTHER`, `ADD TO "X"`, `MOVE 1 TO WHEN`): said only of a set without punctuation, so `NUMVAL(A FROM` keeps
its COBOL0001; the user-defined word is one element (`UserWordSpellings`); the report leaves no tail
(`DiagnosticHint.LeavesNoTail`).
Witnesses: `ClosedFormatReservedWordTests` (4 new rows, the run-before-integer theory, 3 reworded rows), `WrittenKindRefusalTests`
(4 rows), `ParseRecoveryCascadeTests` (7 rows now COBOL5506); refusals `pb4301-misspelled-clause-keyword-is-named`,
`pb4301-occurs-to-without-integer-2`, `pb4301-misspelled-occurs-before-an-integer`; `pb4300` reworded. The arm also took over
eleven refusals that drew the bare COBOL0001 or the COBOL0312 guess (`pb333`, `pb2728`, `pb2292`, `pb3751`, `l1c24`,
`l1c27`, `pb2727`, `pb4207` x3, `pb4286`: their `expect` changed) and the conformance C# tests that pinned them
(`WordCharacterScreenTests`, `GeneralFormatViolationTests`, `ReservedWordPositionConformanceTests`,
`DiagnosticPositionTests`). Not an operand due, left bare: `NUMVAL(A FROM 1)` and `SET ADDRESS OF X UP BY` (the construct
before the token could take more than the set holds, PB4426's guard).
