`0a24276f`. The report's own framing is the important half: **a LANDED note's title already claims this works.**

## What the standard prints — rendered and MEASURED

`python scripts/spec/clause_page.py 14.9.23.2` → **PDF page 681, printed folio 651**;
`python scripts/render-spec-page.py 681`. The USING phrase's first brace arm is

```
             ╭ identifier-3 ╮
[ BY REFERENCE ] ┤              ├
             ╰ OMITTED      ╯
```

Two delimiters decide the shape and they say different things:

- `--check 5.2.6.2 "may be explicitly specified or that portion of the general format may be omitted"` → **OK
  §5.2.6.2 (Brackets)** — `[ BY REFERENCE ]` is a BRACKET, so the whole two-word phrase may be omitted.
- `--check 5.2.6.3 "shall be explicitly specified or is implicitly selected"` → **OK §5.2.6.3 (Braces)** — the
  brace holding `identifier-3` / `OMITTED` sits OUTSIDE that bracket, so exactly one of the two shall be
  written whether or not `BY REFERENCE` is. **`USING OMITTED` with no BY REFERENCE is a printed spelling too**,
  and the compiler must accept both.

**An independent, non-geometric confirmation that INVOKE really has this operand** — because a figure reading is

## What the grammar spells

`src/Cobol.Net.Frontend/Grammar/Core/CobolOO.g4:172-178` on main, verbatim:

```
invokeArgument
    : BY? VALUE arithmeticExpression   // BY optional (kb/Work PB130 — only VALUE is underlined)
    | BY REFERENCE dataReference
    | BY CONTENT ({boolExprAhead()}? booleanExpression | literal | arithmeticExpression)
    | dataReference
    | literal
    ;
```

`OMITTED` appears in NO arm — neither after `REFERENCE` nor in the bare list. `grep -n "OMITTED"` over the whole
grammar directory finds it at `CobolParserCore.g4:1162` (CALL's bare arm), `:1170` (`BY? REFERENCE
(dataReference | OMITTED)` — CALL's Format-2 arm), `CobolExpressions.g4:155` and `:385` (the §8.8.4.8
omitted-argument condition and the intrinsic-argument arm), `CobolData.g4:135` (LABEL RECORDS OMITTED) and
`CobolLexer.g4:604` (the token). **Every consumer of an omittable argument has the arm except INVOKE.**

⚠ **Where the family-3 branch differs.** `worktree-agent-a334880f747b22665` (train 17) relaxes the two `BY`s to
`BY? REFERENCE` / `BY? CONTENT` — the correct fix for the PLAIN word, and the sweep that found this note. It
does NOT add `OMITTED`; the operand set is untouched there. Landing family 3 leaves this defect exactly as
measured below.

## Why it matters

A conforming COBOL-2002/2014/2023 program that invokes a method with an OPTIONAL formal and elects not to supply
it has exactly two printed spellings and the compiler rejects both. There is no workaround inside the language:
`identifier-3` is the only other brace arm, and supplying an identifier is a DIFFERENT program — §14.9.23.3 SR18
exists precisely because the omitted case has to be distinguishable.

**And the omitted-argument condition on the callee side is left unreachable — checked, not assumed.** The
callee's `… IS OMITTED` test is implemented (`CobolExpressions.g4:155`, the §8.8.4.8 simple omitted-argument
condition, kb/Work PB133). A method's formal can only be made omitted by a caller, and this compiler has exactly
two method-call surfaces: `invokeArgument` (above, no OMITTED arm) and `inlineMethodInvocationStatement`
(`CobolOO.g4:197`), whose operand rule is `argumentList` → `argument : arithmeticExpression | literal |
dataReference` (`CobolExpressions.g4:480-488`) — **also no OMITTED arm**, though §8.4.3.4.2 prints OMITTED as a
brace alternative there too and the transcription's figure note calls it *"the only underlined word in the
printed figure"* (`--check 8.4.3.4.2 "inline method invocation syntax diagram"` → **OK §8.4.3.4.2 (General
format)**). So no route exists, and a landed conditional is dead for methods —
`feedback_reachability_is_measured_not_deduced` pointing back at a landed feature. The §8.4.3.4.2 half is a
SIBLING SITE of this same gap, recorded here for the fix to sweep rather than filed separately (it also lacks the
printed `::` and `literal-1` method-name entirely, which is a larger question than one operand).

## The fix shape

The shape CALL already has, one file away — this is `feedback_one_rule_one_place`, not a new mechanism:

```
invokeArgument
    : BY? VALUE arithmeticExpression
    | BY? REFERENCE (dataReference | OMITTED)
    | BY? CONTENT (…)
    | dataReference
    | literal
    | OMITTED
    ;
```

(the `BY?`s are family 3's, shown so whichever lands second produces the union rather than half of each — the
[[PB734]] lesson). The binder half is `OoBinder.OoBindInvokeArg`
(`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/OoBinder.cs:448`), which today selects the passing mode from
`arg.VALUE()` / `arg.REFERENCE()` / `arg.CONTENT()` and has no `arg.OMITTED()` branch;
`CallBinder.cs:194` and `:401` are the two existing `OMITTED()` branches to port the §14.8.2 treatment from, and
§14.9.23.3 SR18 is the check to add (an OMITTED argument requires an OPTIONAL formal — CALL's twin is
§14.9.4.3's, already enforced). Goldens: both printed spellings, the SR18 rejection when the formal is not
OPTIONAL, and an `IS OMITTED` condition inside the method observing TRUE — the last one is what proves the
feature reaches the semantics rather than merely parsing.

## Sweep

`grep -rn "OMITTED" --include=*.g4` was run above; after it, TWO sites lack the arm the page prints —
`invokeArgument` (§14.9.23.2) and `argument` under `inlineMethodInvocationStatement` (§8.4.3.4.2, measured in
"Why it matters"). Fix both in one change set and re-run the grep so the arms stay uniform. The wider pattern is
the one this repo keeps finding — `feedback_two_arm_dispatch`, and here a THREE-arm one: PB130 fixed CALL's `BY?`
and OMITTED, family 3 fixed INVOKE's `BY?`, and INVOKE's OMITTED was in neither pass. The mechanical guard that
would have caught it is an operand-set drift test over the printed brace arms, next to
`OptionalWordSubsetDriftTests`: a rule whose format prints `{ identifier | OMITTED }` and whose grammar admits
only the identifier is a testable claim.
