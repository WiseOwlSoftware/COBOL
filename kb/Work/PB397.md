# PB397 — the missing axis is POSITION, not context

⚠ **MINOR by the harm ladder (both rules are pure under-rejections — the accepted constructs are a no-op and
dead code respectively), but do not read it as "one check".** The reason both are unenforced is the same missing
structure, and every future rule of this shape lands in the same hole.

## THE MECHANISM

The binder carries **scope** context and uses it: `ctx.CurrentSection` powers §14.9.14.3 SR9 (EXIT SECTION only
in a section, `ControlFlowBinder.cs:260-263`), `host.InMethod` powers SR7 (EXIT PROGRAM only in a program
procedure division, `:245-249`), and the PERFORM subtree walk powers SR8's EXIT PERFORM CYCLE ban
(`EcBinder.ExceptionPerform.cs:249-254`). What it does NOT carry is **position**: which sentence a statement is
in, whether that sentence is the only one in its paragraph, and where the statement stands in a consecutive
sequence of imperative statements. So the two rules stated over a SEQUENCE have nowhere to live:

* **`§14.9.14.3` SR1 (bare EXIT)** — `ControlFlowBinder.cs:270` is the whole implementation:
  `return new BoundNop();   // bare EXIT`. Neither half of the rule (a sentence by itself; the only sentence in
  the paragraph) is tested at any site in `src/`.
* **`§14.9.17.3` SR2 (a Format-1 GO TO must be last in its consecutive sequence)** — implemented nowhere. The
  only `14.9.17.3` citation in `src/` is `EcBinder.ExceptionPerform.cs:298`, the SIBLING rule SR3, and the only
  shape check on `goToStatement` (`VersionConformancePass.VisitGoToStatement`) tests just the bare-form edition
  gate. **That is how the omission stayed invisible: the clause LOOKS covered because one of its three rules
  is.**

Both rules also want the same information a §14.9.19 or §14.9.28 empty-body check wants, which is why the answer
is a structure and not two `if`s.

## THE RULES, QUOTED, EACH `--check`ED ON THIS TREE

* `--check 14.9.14.3 "The EXIT statement shall appear in a sentence by itself that shall be the only sentence in
  the paragraph or in a section without paragraphs"` → **`OK §14.9.14.3 1)`** (SR1, Format 1, present in every
  edition).
* `--check 14.9.17.3 "it shall appear as the last statement in that sequence"` → **`OK §14.9.17.3 2)`** — the
  full rule reads *"If a GO TO statement represented by format 1 appears in a consecutive sequence of imperative
  statements within a sentence, it shall appear as the last statement in that sequence."*
* `--check 4.2.2 "a warning mechanism that optionally may be invoked by the user at compile time to indicate
  violations of the general formats and the explicit syntax rules"` → **`OK §4.2.2`** — both are explicit syntax
  rules, so a conforming implementation must be able to indicate them.

## OBSERVED ON HEAD (`89044aa0`) — both re-run, both still accepted silently

```
$ cobol.exe sr1_exit_not_alone.cob --std 2023 --run
  # MAIN-PARA.  DISPLAY "A".  /  EXIT.  /  DISPLAY "B".  /  STOP RUN.      (four sentences in one paragraph)
A
B                              rc=0, no diagnostic of any severity
  # the EXIT is a sentence by itself but NOT the only sentence in its paragraph → SR1 violated

$ cobol.exe p6-not-last.cob --std 2023 --run
  # MAIN-P.  DISPLAY "START"  GO TO PARA-A  DISPLAY "AFTER-GO-TO".         (ONE sentence, three statements)
START
A-TAKEN                        rc=0, no diagnostic; also identical at --std 85
  # the Format-1 GO TO is not the last statement of its consecutive sequence → SR2 violated
```

Neither acceptance produces a wrong value — GR1 makes the bare EXIT a no-op and the statements after the GO TO
are unreachable — **which is precisely the point: the errors these rules exist to catch (a stray EXIT, a missing
period) are exactly the ones that produce no visible symptom.** That is debt of the kind CLAUDE.md rule 3 names,
not a benign leniency.

## THE CODE SITES, AND THE SHAPE OF THE REPAIR

* `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/ControlFlowBinder.cs:270` — the bare-EXIT arm.
* SR2: **absent**. The natural homes are the statement-block walk that already hosts SR3
  (`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/EcBinder.ExceptionPerform.cs#CheckCrossStatementBans`) or
  beside `src/Cobol.Net.Compiler/Validation/VersionConformancePass.cs#VisitGoToStatement`.
* The context that exists: `src/Cobol.Net.Compiler/Binding/Procedure/BinderContext.cs:68` (`BindCursor`, a pc)
  and `:73` (`CurrentSection`).

**Repair (CLAUDE.md rule 5 — add the missing AXIS, then the rules are one line each):** give the binder (or a
validation pass over the parse tree, which is cheaper and is where SR3 already lives) an explicit
**statement-position context**: the enclosing sentence, this statement's index within its sentence's consecutive
imperative sequence, and the enclosing paragraph's sentence count. With that in hand:

* SR1 = "bare EXIT ⇒ my sentence has exactly one statement AND my paragraph has exactly one sentence (or I am in
  a section without paragraphs)";
* SR2 = "Format-1 GO TO ⇒ I am the last statement of my sequence";

and the NEXT sequence rule — §14.9.19's required consequent (PB396), the ALTER/NEXT SENTENCE placement rules,
the "shall be the last statement" family generally — becomes a one-line predicate instead of a new mechanism.
Write it so both diagnostics name their rule and the offending sentence, and add a `conformance:negative` case
for each: there is none today.

## THE SIBLING SWEEP THE FIXER MUST DO

* **Every rule in `14.9.*.3` whose text contains "shall be the last", "in a sentence by itself", "only
  statement", "only sentence", "shall appear ... in"** — `grep` the spec for those phrasings, then grep `src/`
  for each clause number; the SR2-vs-SR3 pattern (one rule of a clause implemented, its sibling not) is the
  thing to look for, and a clause with ONE implemented rule reads as covered.
* The three placement rules that ARE implemented (SR7, SR8, SR9) all key on SCOPE and should be re-expressed
  through the same context object when it lands, so the compiler has one placement mechanism rather than two.
* NEXT SENTENCE's own placement (`§14.9.19`) and ALTER's target constraints ask the same question and are the
  first candidates to reuse it.
