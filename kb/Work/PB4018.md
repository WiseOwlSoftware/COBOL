# PB4018 — `conflict_brief` has no pathspec bound

**Sites:** `scripts/orchestrator/land_lane.py:376` (`conflict_brief`); the rule to reuse is `scripts/orchestrator/inflight.py` (`bounded_pathspec`, `PATHSPEC_CHARS`).

**What.** `conflict_brief` runs `git log ... -- *files` with the conflicted-file list on the command line, with no bound on its
length. PB3786 fixed the same root for the planner's diff arms (`inflight.bounded_pathspec`, a pathspec-free diff when the
list is too long) and its sweep judged this site "bounded by what the finisher resolves", so it left it alone. The report
disagrees: a merge that conflicts in thousands of files exceeds the Windows command line (`FileNotFoundError: [WinError 206]`)
and the conflict finisher's brief is never written.

**Repro.** `conflict_brief(..., files=[300 long names])` on Windows (the report's wording; the same shape as PB3786's repro).

**Not fixed by PB3786.** The site is outside that group's slice; `land_lane` would need the rule from `inflight` (a layering
question: put the rule where both can import it, not a copy).

**Fix shape.** One pathspec-bounding rule for every computed path list on a git command line; `land_lane.conflict_brief` calls
it. A self-test arm plants 300 long names.
