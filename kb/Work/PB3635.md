# PB3635 — the sequential re-create after a ROLLBACK removal does not probe for another run unit's file (analysis: probe first)

Filed 2026-10-28 by the clerk from the PB3492 branch review (R2-2, low, not blocking). Related: PB3492, PB3340. The clerk did not
re-probe it, so `wrong_answer` stays false: the report shows the missing probe, not an observed wrong result.

**Sites:** `src/Cobol.Net.Runtime/IO/SequentialConnector.CommitControl.cs` (`BeginAppending`, line ~318), `src/Cobol.Net.Runtime/IO/KeyedConnector.cs`
(`CreateTheFileAgain`, the keyed twin).
Pre-existing on main and outside PR #491's diff, though the diff edits the method; the keyed twin and `ResumeRunUnitFileLock`'s
new call arrive with PR #491 (branch `worktree-wf_42255de2-426-13`, PB3492, tip fc3a5ff52); read them with
`git -C 'E:\COBOL' show fc3a5ff52:<path>`.

**Defect.** The `_fileRemoved` arm of `BeginAppending` begins a START A journal and calls `OpenWriter(FileMode.Append)` with no check
that the path is still absent, and `ResumeRunUnitFileLock` then publishes the file-lock column with no test. The keyed
`CreateTheFileAgain` answers I-O status 30 when another run unit has created a file at the path meanwhile (cited as ISO 9.1.13.6
item 1, "I-O status = 30", verified with `scripts/spec/cite.py --check`). If another run unit does create the file in that window,
the WRITE would append to its file; the clerk did not run that scenario.

**Fix direction.** Probe the path as the keyed twin does and answer 30; add a two-run-unit test for the window. The implementer
should probe the scenario first and set `wrong_answer` from the result.
