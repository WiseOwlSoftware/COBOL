# PB3802 — two rules for which branch a report belongs to

**Sites:** `scripts/orchestrator/reports.py#newest_report`, `scripts/orchestrator/reports.py#BRANCH_MENTION`, `scripts/orchestrator/reports.py#BRANCH_FIELD`, `scripts/orchestrator/reports.py#parse_report`

## Measured

`reports.newest_report` reads `BRANCH_MENTION` (any `branch x`, prose or field) while the planner reads `BRANCH_FIELD`
(field position only, PB3077's fix). Over 802 live reports 206 headers disagree, chiefly a successor's report that also
credits its predecessor's branch. Repro: `python E:\COBOL-coord\scratch\mythos\w20261702a\branch_rules.py <repo>
E:\COBOL-coord\scratch\reports`. Sibling of PB3077.

Review lead R1-1: the `BRANCH_FIELD` comment (reports.py:44-48), moved verbatim into the module that now also holds the
survey matcher, still says `prune_worktrees.newest_report` applies the same field-first rule, while `newest_report`
(reports.py:342) reads `BRANCH_MENTION`. A maintainer who trusts the comment makes a change that misattributes reports in
the survey or the landing review gate.

## Acceptance

- One rule decides which branch a report belongs to, or the two rules are kept on a measured reason that is written on
  both constants; a self-test holds the 206-header disagreement set to the chosen answer (a successor report naming its
  predecessor branch is credited to ONE branch).
- The `BRANCH_FIELD` comment states the rule the code applies.
