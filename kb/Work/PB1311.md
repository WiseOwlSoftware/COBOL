# PB1311 — OPEN — one domain rule, two screens

## The site
- `src/Cobol.Net.Runtime/Intrinsics/CobolIntrinsics.Dec.cs:245` `AnnuityDec` does
  `if (rate.Sig < 0 || periods <= 0) return … AnnuityDomain(rate.ToDouble(), periods)`.
- `CobolIntrinsics.Dec.cs:257` `PresentValueDec` does
  `if (Compare(rate, −1) <= 0) return … PresentValueDomain(rate.ToDouble())`.
- `src/Cobol.Net.Compiler/CodeGen/Emit/IntrinsicRenderer.cs:1087-1088` has the `RenderDec` "Annuity" and
  "PresentValue" arms, and neither routes its lead through the DomainArg screen that PB952 made the ONE site.
- The float twins raise through `CobolIntrinsics.Float.cs:235/241` (`AnnuityDomain`/`PresentValueDomain`). Every
  other domain-checked function raises through `DomainViolation` (`CobolIntrinsics.Float.cs:113`), and those
  messages differ.

## Why it matters
Each lane decides "is this argument in the domain" for itself. The Dec lane decides on the EXACT value, the float
lane on a binary64 image. PB1000 was exactly this divergence, a legal rate that rounds to −1.0. The next edit to
one copy will not reach the other. [[feedback_one_rule_one_place]]

## What the fixer owes
- Each domain rule (§15.9.3 r2/r3, §15.74.3 r2) is decided once, by the screen on the exact argument, and both
  lanes' bodies assume it.
- There is one raise site and one message shape.
- A drift test asserts that no `*Dec` body re-tests a domain that DomainArg owns.
- **Sweep** every `*Dec` twin in `CobolIntrinsics.Dec.cs` for the same in-body re-test. Candidates: RANDOM, the
  statistical family, SQRT and LOG.
