# PB5797 - a contained program's EXTERNAL or GLOBAL table may depend on a counter declared in the containing program (every edition)

**What is wrong.** `§1985:VI.5.8.3 SR8` and `SR9` each require data-name-1 of an OCCURS DEPENDING ON clause to be described in the same Data Division as the table. In `o8.cob` the contained program's EXTERNAL record holds a table DEPENDING ON `NE`, an EXTERNAL GLOBAL item of the CONTAINING program; in `o9.cob` the contained program's GLOBAL record holds a table DEPENDING ON `NG`, a GLOBAL item of the container. Both compile and run on the container's counter (`E=XY|`, `G=AB|`) at `--std 85` and at `--std 2023`. The attribute half is enforced: `o9b.cob`, a non-global counter for a GLOBAL table, is refused `COBOL2788`. `OdoResolvePass`'s comment says "described in the same data division holds by construction", because the pass runs before a contained program inherits names; the runs show data-name-1 resolving to the container's item, so the premise is false. 2023 keeps the same words (`§2023:13.18.38.3 SR18`: "shall reference a data item that is described in the same data division"), so the 2023 rows `SR-13.18.38.3-18` and `SR-13.18.38.3-21` are wrong too (cause b; a registrar re-records them non-conforming).
