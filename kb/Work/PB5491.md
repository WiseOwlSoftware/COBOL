# PB5491 - the TestsTreeWalks guard binds constructor arguments only from an explicit new Holder(...): a target-typed new(...) or a this(...) initializer is invisible, so a real walk of tests/ can be judged SAFE

UNVERIFIED LEAD: re-probe before fixing.

**Lead, verbatim (review of PB5478, lead R1-2, `tests/WiseOwl.Cobol.Tests.Unit/TestsTreeWalks.cs:179`).** "The new constructor-parameter binding indexes only ObjectCreationExpressionSyntax, so a target-typed new(...) or a this(...) chained initializer passing a hazard root is invisible; when the same file also has one explicit new passing a safe root (ScratchDirectory.Create), Judge calls the listing SAFE instead of UNRESOLVED"

**Failure scenario, verbatim.** "class Walker { readonly string _d; public Walker(string d) { _d = d; } void Scan() { Directory.EnumerateFiles(_d, "*.cs", SearchOption.AllDirectories); } } plus, in the same file, new Walker(ScratchDirectory.Create("x-")) and Walker w2 = new(TestRepo.Tests()). Before this branch the root was Unresolved and counted against the bound of 2 (loud); now the values are [Outside] only, Judge returns Safe, and the walk of tests/ passes NoTest_WalksTheTestsTreeFromTheFileSystem."

**Fix direction, verbatim.** "Index BaseObjectCreationExpressionSyntax; for an ImplicitObjectCreationExpressionSyntax or a ConstructorInitializerSyntax whose target cannot be bound syntactically, contribute a marker that makes Judge return Unresolved, and plant both shapes as hazards/unresolved."

**Note.** The guard code the lead names is in the PB5478 branch (the lead is from its round-1 review); the fixer checks that it is on main before work.
