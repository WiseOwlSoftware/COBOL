# PB190

Found 2026-08-31 while grepping the traceability inventory for the Tier-C residue at the PB164 landing.
`RV-15.78.4-1` is PARTIAL/GAP, and its note names exactly three argument shapes that "produce no returned value
at all — each compiles clean and then throws `NotImplementedCobolFeatureException` at run time":

1. an alphanumeric GROUP argument containing a float/COMP-5/INDEX leaf — blamed on "the Tier-C byte island";
2. a FIGURATIVE CONSTANT argument (`FUNCTION REVERSE(SPACE)`) — `StrArgVisitor.Visit(BoundFigurative)`;
3. `FUNCTION REVERSE(ALL "AB")` — the sibling `Visit(BoundAllLiteral)` arm.

**All three look already closed, by two different landings, and neither refreshed this row.** [[PB25]] (landed
2026-08-05) routed `StrArgVisitor`'s non-field leaves through `OperandText.AsString` for **every** §15 function
taking a string argument through `Str()`/`StrArgList`, and its golden
`pb25_figurative_intrinsic_argument` pins `REVERSE(ALL "AB")` = `BA` by name — shapes (2) and (3). [[PB164]]
wave 1 gave every numeric leaf kind a group image and its DISPLAY leg closed itself as a side effect — shape (1)
is the same image predicate, one consumer over.

⛔ **"Looks closed" is not a verdict.** This note exists because the row must not be flipped from a code reading:
[[feedback_reachability_is_measured_not_deduced]], and the row's own history is a warning — it already carries a
STRUCK test-ref that was cited for a rule it could not exercise. The work is three CLI probes (one per shape,
each with the value derived from §15.78.4 r1 BEFORE the run), then either a CONFORMS flip with real goldens for
the shapes that pass, or a re-stated residue for any that still throw.

**Blocked in practice, not by another note:** the finisher that found this could not run the probes because
`scripts/hooks/fleet_active_build.py` denies every `dotnet` verb to a subagent ([[PB185]]). Do this from a
session that can build, or after PB185 is fixed.

## Landed — 2026-09-19 (wave 40, §15 intrinsic residues)

`RV-15.78.4-1` CONFORMS — and the note's whole point was honoured: the row was NOT flipped from a code reading.
All three recorded shapes were re-run on a build of this tree with `src/Cobol.Net.Cli/bin/Debug/net10.0/cobol.exe`
at `--std 85`, each expected value derived from §15.78.4 r1 before the run. `FUNCTION REVERSE(SPACE)` returns
the one space §8.3.3.6.4 GR3 b) sizes it at; `FUNCTION REVERSE(ALL "AB")` returns `BA`; a group of
`PIC X(3)` + `PIC S9(4) COMP-5` reverses its whole five-position image, and INDEX-leaf and COMP-1-leaf groups
(FUNCTION LENGTH 11 and 7) reverse without faulting too. None throws. PB25 and PB164 wave 1 closed them, as the
note hypothesised, and neither refreshed the row — which is the mechanism [[PB245]] measures across a whole
clause family.

Golden `85/pb190_reverse_argument_shapes` writes the group leg as the RULE, not as a byte pin: two of the five
image positions are unprintable, so it asserts `reversed(j) = image(n − j + 1)` for all five j against the same
group's own image (`GRP=R1-HOLDS`), which measures the REVERSAL and stays independent of the group-image rule —
a different rule, on a different row. No further probes are blocked: `fleet_active_build.py` did not deny the
`dotnet` verbs in this worktree.
