**Landed (2026-11-14, wave 20262029 group G).** Re-probed on the branch's build before the fix: `ap1.cob` (the
addendum's repro) ran at `--std 85`, exit 0, printing `ABC'D`.

**The edge is QUOTED, not derived.** §2002:F.2 item 3: "Apostrophe as quotation symbol. The apostrophe character as
well as the quotation mark may be used in the opening and closing delimiters of alphanumeric, boolean, and national
literals"; §1985:IV.4.2.2.2.1 delimits a nonnumeric literal by "the separator quotation mark". So the construct is
`apostrophe-quotation-symbol-2002` (COBOL0900, VCR Table 7 row 7.72).

**Fix (root).** The fact is the literal's opening delimiter, which the ONE literal codec already locates
(`CobolLiteral.OpeningDelimiterAt`, the prefix scan that `IsHexadecimalFormat` and `ClassOf` read), so the question is
one predicate beside them, `CobolLiteral.IsApostropheDelimited`, and the gate is one arm of `LiteralScreen.GateFormat`,
the token gate every literal token of the unit and of each directive fragment passes. No new token kinds: the fix
direction's "the token kind carries the fact" would double the four delimited-literal token types for a fact the codec
reads in O(1) from the token text it is already handed, and every consumer already asks the codec. `STR_BODY` still
lexes either symbol at every edition (the lexer delimits; the screen gates), as for X"…".

**After.** At `--std 85` every apostrophe-delimited literal is COBOL0900 "the apostrophe-delimited literal" (DISPLAY,
MOVE, VALUE, level-88 VALUE, ALL, `'ABC''D'`, `X'4142'`), `"IT'S"` runs; at 2002 all run. Goldens:
`cases/8.3.5-Separators/pb5160_apostrophe_quotation_symbol` (accept 2002; legs moved from three 85 goldens whose subject
was the apostrophe: `l1c01`'s `LENGTH('A''B')`, `pb1350`'s `'QQ'` REPLACE match, `pb1492`'s continued apostrophe
literal), negative `cases/IV.4.2.2.2.1@1985-Nonnumeric-Literals/pb5160-apostrophe-literal-85`; unit
`CobolLiteralTests.IsApostropheDelimited_AsksTheOpeningDelimiter`. Three 85 goldens that wrote an apostrophe literal
incidentally (`pb4233_picture_string_then_separator_period`, `pb5425_static_sizes_accepted_85`,
`pb1525_flag_extensions_changes_nothing`) now write the quotation mark. NIST CCVS-85: none of the 459 programs writes
one (scanned). Rows: 1985-FMT-IV.4.2.2.2.1.1 and 1985-SR-IV.4.2.1-5 DIVERGES to CONFORMS (1985 GAP 206 to 204).

**Residual, a separate mechanism (reported as a lead, not fixed here).** Every literal-format gate is a TOKEN gate, run
after text manipulation, so a literal the source writes and a REPLACE operand replaces before lexing is never screened:
at 85 `REPLACE =='QQ'== BY =="RR"==.` with `DISPLAY 'QQ'` prints RR, and `REPLACE ==X"5151"== BY =="RR"==.` with
`DISPLAY X"5151"` prints RR (both probed). The fix is a text-word-level format screen in the text-manipulation stage,
shared by the three GateFormat arms.
