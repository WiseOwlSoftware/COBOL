# PB4610 — the oversize VALUE literal on a numeric-edited item is refused only at 2023; its rule is older

**What is wrong.** `01 X PIC ZZ9 VALUE "ABCDEF".` draws no diagnostic at `--std 2002` and `--std 2014` and COBOL1570 at
`--std 2023` (probe `E:/COBOL-coord/scratch/pb4608/ours/vne.cob`, compiled with main's `cobol.exe` on 2026-11-04). The
rule is not a 2023 addition. 2023 §13.18.63.3 SR4: "Alphanumeric literals in the VALUE clause of an elementary item shall
not exceed the size indicated by an explicit PICTURE clause." (`cite.py --check` OK). The same sentence stands at
`t2014.txt:23752-23754` (FCD SR4, no change bar on rendered p423; SR5 national at 23757-23758; SR8 at 23771-23774: editing
characters count toward the size) and at `t2002.txt:19799-19806` (SR4/SR5, SR8 at 19822-19825). Table 3 makes a
numeric-edited item class alphanumeric (usage DISPLAY) or national, so the sentence reaches it at every edition.

**Why the row is wrong.** Construct row `value-numeric-edited-oversize-removed-2023` is a removal gate (`removedIn: 2023`)
that treats the check as a 2023 change on the strength of Annex E.2 item 27. The refuter tried every rescue and none holds:
item 27 and item 29 describe the content of a literal that fits, not its length; the category-based restructuring of
SR3-SR7 is the 2023 feature of E.3.3 item 43 (numeric literals for numeric-edited items), not a change to the size rule;
FCD 3.2.1 (t2014.txt:1130-1131) and 2023 carry the same optional warning mechanism. 1985: no text is held; the 2002 Annex F.1
list of 1985-to-2002 changes (t2002.txt:43040ff) names no VALUE-literal size change (weak evidence that 1985 forbade it too).

**Expected.** COBOL1570 at every edition whose text is held (2002, 2014, 2023). 1985 is decided explicitly in the fix and
the decision recorded.

**Fix shape.** The check applies at 2002, 2014 and 2023; the row stops being a removal gate; no hard-coded edition test
remains beside the construct row (CLAUDE.md rule 4: one mechanism). DEVLOG 0902 records the current 2014 behavior and is
history; the docs that describe the check follow in the same change set.

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs` (the COBOL1570 check, `Edition.DialectLevel >= 2023`, about
line 1331, with `EditionSeverityPolicy.For(ConstructAvailability.Removed, ...)` beside it), `tests/version-matrix/constructs.json`
(row `value-numeric-edited-oversize-removed-2023`), `docs/VERSION_CHANGE_REFERENCE.md` (row 34).
