# the cross-reference classifies a store through an index-name's cell or a whole table as a read: those cells are held by the bound tree with no `Place`, so the statement's store positions name no occurrence of them

**Found by** listing step 7b (branch `listing-step-7b-2`, kb/Work PB5925's dated file `2026-11-20-step-7b-2-built`, lead 1 and 4 of its list), filed by step 9b so no lead of the listing's design stays in a dated paragraph alone.


`SET IX UP BY 1`, `SET IX TO 3` and a PERFORM or SEARCH VARYING index store into an index-name's cell, which the bound tree holds as its
field name (`ExpressionBinder.IndexFieldOf`, `BoundIndexRef`), not a `Place`; a table SORT (`BoundTableSort.Storage`) and INITIALIZE's
whole dynamic table store into the table with no place of the reference (design section 6.7.1, "Store kind": the table item is
`ReadWrite`, matched to the statement's occurrence of that table, and `WholeTable`'s `TableAllPlace` is not linked). The occurrence is
recorded and placed; only its use (`Read` for `Written`/`Modified`) is wrong.

**Fix shape:** the index cell as a place of its own (or the store taxonomy asking the index targets), `TableAllPlace` linked to the
table reference's occurrence; a planted case per statement form in `ListingCrossReferenceTests`.

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/ExpressionBinder.cs` (`ExpressionBinder.IndexFieldOf`), `src/WiseOwl.Cobol.Compiler/Binding/Bound/BoundStores.cs` (`BoundStores.StorePositionsAmong`), `tests/WiseOwl.Cobol.Tests.Conformance/Listing/ListingCrossReferenceTests.cs` (`ListingCrossReferenceTests.EachReference_StandsWhereItIsWritten_WithTheUseItsPositionGives`: the witness asserts only `SET IX`'s position).
