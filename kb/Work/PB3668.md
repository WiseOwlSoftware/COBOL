# PB3668 — prune_worktrees.contained()'s docstring says a carried unfinished branch waits under --drain or gets a finisher naming the carrier, by either arm; the REPLAY arm never gets a finisher of its own

**Sites:** `scripts/prune_worktrees.py#contained` (docstring, ~line 974; present on branch `worktree-wf_f39d3ad7-d92-13`, PR #525, until it merges), `scripts/orchestrator/plan_wave.py#branch_replays`.

## What happens

The PB3476 round-1 rewrite (R1-2) of the docstring says an unfinished branch carried by either arm "waits for the carrier" under `--drain`, and otherwise "its finisher's pred names the carrier". That holds for the ancestry arm (`plan_wave.branch_carrier`). It does not hold for the REPLAY arm: `plan()` routes a replayed branch to `replayed_to` before the drain check, so it never gets a finisher of its own in either mode. Its notes ride on the replaying branch's finisher, or they wait.

## Fix direction

Split the sentence by arm so each states what the planner does, and pin the replay half with the planner case that already shows the routing (or a `test_plan_wave.py` case if none does). Keep ownership of the routing in the planner; the docstring only describes it. Read the planner's routing first; if it shows the docstring and the planner disagree for a reason other than wording, file that apart from this note.
