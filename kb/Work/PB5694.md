# PB5694 - two case directories that differ only in letter case

**Sites:** `scripts/case_collisions.py` (new), `scripts/selftests/case_collisions/test_rules.py` (new),
`scripts/gate_audits.py` (`<module>`), `.github/workflows/build-and-test.yml` (whole: one step of the `audits` job),
`scripts/battery.sh` (`<header>`), `docs/rearchitecture/DESIGN-test-build-ci.md` (whole: one paragraph),
`conformance-suite/cases/8.4.2.2@2002-FUNCTION-IDENTIFIER/pb5640-function-arg-bit-refmod-data-length.cob` (moved),
`kb/Work/PB5669.md` (whole: the case path, twice).

**What was wrong.** On main d615406082, `git ls-files` listed `conformance-suite/cases/8.4.2.2@2002-FUNCTION-IDENTIFIER/`
(six files) and `conformance-suite/cases/8.4.2.2@2002-Function-identifier/` (one file,
`pb5640-function-arg-bit-refmod-data-length.cob`). Git stores both names. A Windows checkout folds them into one
directory, and a Linux checkout, including CI's, keeps two. A test-ref, a generator path, a `Pinned by` cell or a note's
**Sites:** path spelled one way therefore names a different set of files on each operating system. Nothing failed on
either: the generator walks whatever directories the checkout has, and no audit compared tracked names ignoring case.

**How it got in.** Two landings of the same day each created the directory with its own casing. The PB5640 review
round (commit f613aa021a, DEVLOG 3686) wrote `@2002-Function-identifier`, the spec heading's casing. The golden-2002-2
lane (commit dec77a16fe, DEVLOG 3692) wrote `@2002-FUNCTION-IDENTIFIER`, the upper-case form the golden lane uses for
84 of the 88 `@2002-` case directories. Each branch was clean on its own. The pair first existed in the merged tree,
and on the Windows host that gated both, the two names were one directory.

**The fix.**
- One directory, `8.4.2.2@2002-FUNCTION-IDENTIFIER`. The pb5640 case moved into it through a temporary name, so git
  records the rename on a case-insensitive file system. `git grep "@2002-Function-identifier"` finds nothing afterwards.
  The only references were the two in kb/Work PB5669; the three 2002 inventory records and DEVLOG 3692 already used
  the upper-case spelling.
- The audit `scripts/case_collisions.py --check`, `CASE COLLISIONS` in `gate_audits.AUDITS`, runs in every lane. It is
  also a step of CI's `audits` job, which reads the merged tree, where such a pair first appears, and a line of
  `battery.sh`. It refuses any two tracked names (paths, and the directories above them) that the simple one-to-one
  case mapping makes equal, and reports each collision once, at the shortest prefix where it starts. It has no
  allow-list. Its self-test plants both spellings in a scratch index with `git update-index`, the shape that got in,
  and it must be RED there. On main d615406082's tree, the rule finds exactly this one pair among 41,590 paths.

**Left as it is.** Four `@2002-` directories use the spec heading's mixed case (`8.4.1.1@2002-Qualification`,
`8.4.1.2@2002-Subscripts`, `8.4.2.11@2002-Data-address-identifier`, `8.4.2.1@2002-Identifier`). None of them collides
with another name, so the audit has nothing to refuse there. Making every directory follow one casing convention is
a naming choice. This defect is about collisions, so that choice is not made here.
