# PB3888 — exception-status-zero-divide-set-inside-size-error: FUNCTION EXCEPTION-STATUS reports EC-SIZE-ZERO-DIVIDE after a handled divide by zero when no checking is enabled

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S3) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\exception-status-zero-divide-set-inside-size-error.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\exception-status-zero-divide-set-inside-size-error\`.

## Summary

A DIVIDE by zero with an ON SIZE ERROR phrase, in a program with no TURN directive, leaves FUNCTION EXCEPTION-STATUS
returning `EC-SIZE-ZERO-DIVIDE`, both inside the SIZE ERROR phrase and after the statement. ISO sets the last exception
status only when an exception condition is raised, and a condition is raised only when checking for it is enabled by a
TURN directive or a PERFORM ... WHEN phrase; by default checking is not enabled for any exception condition. So
EXCEPTION-STATUS must return spaces. The same happens for 0 ** 0 (`EC-SIZE-EXPONENTIATION`). The cause is general:
libcob's `cob_set_exception` records the last exception every time a run-time routine detects a condition, whether or
not checking for it is enabled. The division case carries a FIXME in the source naming the SIZE ERROR phrase case.

## Minimal test case

Fixed reference format (cobc's default), 14 lines, `records/exception-status-zero-divide-set-inside-size-error.cob`:

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. DIVSTAT.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 A PIC 9 VALUE 1.
       01 Z PIC 9 VALUE 0.
       01 R PIC 9 VALUE 5.
       PROCEDURE DIVISION.
           DIVIDE A BY Z GIVING R
             ON SIZE ERROR
               DISPLAY "[" FUNCTION EXCEPTION-STATUS "]"
           END-DIVIDE
           DISPLAY "[" FUNCTION EXCEPTION-STATUS "]"
           STOP RUN.
```

## Expected result (per ISO)

ISO/IEC 1989:2023 14.6.13.1.1 (all checked):

- "An exception status indicator is set when checking for the associated exception condition is enabled either by a
  TURN compiler directive or a WHEN phrase in a PERFORM statement and the associated exception occurs."
- "By default, checking is not enabled for any exception condition." "During the execution of any statement, if
  checking for an exception condition is not enabled, the exception condition will not be raised".
- The last exception status "is a conceptual entity that is set to indicate the last level-3 exception condition that
  was raised in the run unit".

15.33.3 rule 1 (checked): "If the last exception status indicates no exception, alphanumeric spaces are returned."

The first sentence is the 2023 wording only: the 2009 committee draft toward 2014 says the indicator is "set when the
associated exception exists" (refuter), so the 2014 case rests on the other two, which the draft carries in the same
words (the edition paragraph below): a condition whose checking is not enabled is not raised, and the last exception
status names only a raised condition.

§14.7.5 (checked) could be read the other way: "Checking of a size error condition may be enabled by: — specifying
the SIZE ERROR phrase of an arithmetic statement, or by — using a TURN directive or a WHEN phrase of a PERFORM
statement to turn on checking for the EC-SIZE exception condition." That enables the size error CONDITION, which the
SIZE ERROR phrase handles; it does not raise the EC-SIZE EXCEPTION condition. Annex D.16.4 (informative, checked) says
so: "Checking for an exception condition is locally disabled by the presence of an explicit phrase. For example, if the
SIZE ERROR phrase is specified on an arithmetic statement, the raising of the EC-SIZE exception condition is disabled
for that statement", and "if an explicit SIZE ERROR phrase is specified, that phrase takes precedence and the EC-SIZE
exception condition is not raised". The program has no TURN directive and no exception-checking PERFORM, so no exception
condition is raised and both DISPLAYs must show 31 spaces between the brackets:

```
[                               ]
[                               ]
```

For the no-phrase DIVIDE in `nophrase.cob`, 14.6.13.1.3 rule 8 (checked) leaves continuation and the receiving operand to
the implementor when checking is not enabled, but the condition is still not raised, so EXCEPTION-STATUS must still be
spaces; this record rests on the SIZE ERROR case, which has no implementor latitude.

Edition: FUNCTION EXCEPTION-STATUS and the last exception status are ISO/IEC 1989:2002 features. Annex E of the 2023
text lists no change to them; the 2009 committee draft that led to 2014 (CD 1.2) carries the same last-exception-status
paragraph and the same "will not be raised" rule. The requirement holds for `-std=cobol2014`.

Edition as recorded by the adjudicator: 2014. `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Class

Wrong output (FUNCTION EXCEPTION-STATUS returns an exception-name where ISO requires spaces).

## Our compiler (WiseOwl)

`cobol divstat.cob --std 2014 --run` (WiseOwl, built from main 6ed90bd1c): two lines of `[` + 31 spaces + `]`, exit 0.
It matches the ISO expectation. (`nophrase.cob`: WiseOwl prints `POW [` + 31 spaces + `]` and then ends the run unit
at the unchecked zero divide, its documented 14.6.13.1.3 rule 8 choice; that second statement is latitude and not part
of this comparison.)

## Fix site (GnuCOBOL 3.2 source, read observationally)

- `libcob/common.c`, function `cob_set_exception`: records the code in the run unit's last exception
  (`last_exception_code`) unconditionally; nothing consults whether checking for that exception condition is enabled.
  `cob_intr_exception_status` (libcob/intrinsic.c) reads that last exception code. A fix records the last exception
  only for a condition whose checking is enabled (cobc knows this per statement via `CB_EXCEPTION_ENABLE`), keeping the
  internal code that drives the SIZE ERROR phrase separate from the ISO last exception status.
- `libcob/numeric.c`, function `cob_decimal_div`: the division-by-zero branch calls `cob_set_exception
  (COB_EC_SIZE_ZERO_DIVIDE)` under a FIXME comment saying the exception should be set only when the division is not
  within an arithmetic statement with a SIZE ERROR phrase.
- `libcob/intrinsic.c`, function `cob_decimal_pow`: the same unconditional `cob_set_exception
  (COB_EC_SIZE_EXPONENTIATION)` for 0 ^ 0.

## Draft issue

**Title:** FUNCTION EXCEPTION-STATUS reports EC-SIZE-ZERO-DIVIDE after a handled divide by zero when no checking is enabled

**Body:**

Environment: GnuCOBOL 3.2.0 (Ubuntu gnucobol3 3.2-4build1), `cobc -std=cobol2014 -x`.

Program (fixed format, no >>TURN directive):

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. DIVSTAT.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 A PIC 9 VALUE 1.
       01 Z PIC 9 VALUE 0.
       01 R PIC 9 VALUE 5.
       PROCEDURE DIVISION.
           DIVIDE A BY Z GIVING R
             ON SIZE ERROR
               DISPLAY "[" FUNCTION EXCEPTION-STATUS "]"
           END-DIVIDE
           DISPLAY "[" FUNCTION EXCEPTION-STATUS "]"
           STOP RUN.
```

Steps: `cobc -std=cobol2014 -x divstat.cob && ./divstat`

Observed: both lines print `[EC-SIZE-ZERO-DIVIDE            ]`. The same happens for `COMPUTE R = Z ** Z ON SIZE ERROR`
with Z = 0 (`EC-SIZE-EXPONENTIATION`).

Expected: both lines print `[` + 31 spaces + `]`. ISO/IEC 1989:2023 14.6.13.1.1, whose rules the 2014 text carries
in the same words: "By default, checking is not enabled for any exception condition"; "During the execution of any
statement, if checking for an exception condition is not enabled, the exception condition will not be raised"; and the
last exception status indicates "the last level-3 exception condition that was raised in the run unit". 15.33.3: "If
the last exception status indicates no exception, alphanumeric spaces are returned." The SIZE ERROR phrase does not
enable the EC-SIZE exception: 14.7.5's "Checking of a size error condition may be enabled by specifying the SIZE ERROR
phrase" is about the size error condition the phrase handles, and Annex D.16.4 (informative) says "Checking for an
exception condition is locally disabled by the presence of an explicit phrase. For example, if the SIZE ERROR phrase is
specified on an arithmetic statement, the raising of the EC-SIZE exception condition is disabled for that statement".

Cause: `cob_set_exception` (libcob/common.c) always records the last exception code read by EXCEPTION-STATUS. The
FIXME above the call in `cob_decimal_div` (libcob/numeric.c) already notes that the exception should not be set inside
an arithmetic statement with a SIZE ERROR phrase.
