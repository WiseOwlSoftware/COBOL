# PB4182 — the runner drift test recomputes the whole suite the partitions already judged

**Sites:**
- `tests/WiseOwl.Cobol.Tests.Conformance/ConformanceSuiteRunnerDriftTests.cs#BothRunners_GiveEverySuiteTestTheSameVerdict`
- `tests/WiseOwl.Cobol.Tests.Conformance/ConformanceSuiteRunner.cs#Judge`
- `tests/WiseOwl.Cobol.Tests.Conformance/ConformanceSuiteTests.cs#ConformanceSuiteTestsBase` (already calls `Judge` for every row)
- `conformance-suite/harness/run.py`, `conformance-suite/harness/normalization-fixture.json`

**What it does today.** The test exists for a good reason (PB3176): `run.py` is the runner any compiler vendor uses, the
in-process `ConformanceSuiteRunner` is WiseOwl's fast one, and a difference in their verdict logic would make our gate green
where a user's `run.py` run is red. But it proves that by brute force, in ONE `[Fact]`:
1. `run.py` over every per-edition suite (a `cobol` process per compile and per run, at most 8 jobs);
2. `ConformanceSuiteRunner.Judge` over every in-suite test again, in a serial LINQ `ToDictionary`;
3. a comparison of the two verdict sets.
Step 2 repeats exactly what the 32 partition classes do in the same run. Step 1 repeats it a third time through another
process boundary. Its own remarks say "Its cost grows with the suite". PB4150 measured it at 50-205 s, the last case
running in 1 of 9 arm-A runs and 4 of 6 arm-B runs.

**The defect (CLAUDE.md rule 4, rule 5; the four reviews' duplication dimension).** Agreement of two runners is a property
of their verdict LOGIC (how each reads the adapter's diagnostic pattern, the profile, normalization, the expected outcome),
not of 19,000 programs. The shape that tests the logic is a fixture, as the normalization half of this same test already
does (`normalization-fixture.json`, every case once).

**Direction.**
- A verdict fixture: one small case per verdict path both runners implement (PASS, FAIL on output, FAIL on a missing or
  extra diagnostic, the flagged control compile, NOT APPLICABLE by profile, a compile refusal, a run-time abort, a timeout),
  run through `run.py` and `Judge`, compared. Adding a verdict path adds a fixture row, and a drift test proves every
  verdict path of each runner has one (so "automatic" stays true).
- Delete the whole-suite step 2; the partitions' own judgments are the in-process verdicts.
- The whole-suite `run.py` run, if still wanted as a population check, runs once per CI merge group (its own leg), never in
  every local gate, and compares against the verdicts the partitions recorded in the same run, not a recomputation.
- Sweep for siblings: any other drift or equivalence test that re-runs a population another test already ran (grep the
  test projects for `SuiteManifest.Manifest`, `NistDifferential`, whole-corpus loops inside one `[Fact]`).

**Done when.** No local gate runs the suite more than once; the fixture covers every verdict path of both runners and a
drift test enforces that; CI still catches a runner disagreement; the Conformance leg's slowest case is no longer this test.
