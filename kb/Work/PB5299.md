# PB5299 - at --std 85 VALUE OF FILE-ID may name a table element without a subscript (05 E PIC X(10) OCCURS 2): ResolveValueOfDataNames checks USAGE INDEX and the section but not OCCURS, which MOVE refuses as COBOL2270

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/FileControlBinder.ObsoleteFdClauses.cs` (`ResolveValueOfDataNames`)

**Mechanism.** The VALUE OF clause's data-name-1 "cannot be subscripted, nor can data-name-1 be an item described with the USAGE IS INDEX clause" (§1985:VII.3.9.3 SR1). "Each table element reference must be subscripted except" in USE FOR DEBUGGING, a SEARCH subject, REDEFINES and OCCURS KEY IS (§1985:IV.4.3.8.2.3 SR4), and VALUE OF is none of these. So a table element can never be data-name-1. `ResolveValueOfDataNames` refuses USAGE INDEX and an item outside Working-Storage (COBOL6849), and the capture refuses a written subscript (COBOL2024). Nothing refuses a table element written without one; the same compiler refuses `MOVE E TO ...` with COBOL2270. The clause is shared by every FD format, so the relative FD (§1985:VIII.3.2.4 GR6) and the report FD (§1985:XIII.3.2.4 GR3) take the same path, and the sequential FD does too (the refuter's b1.cob). kb/Work PB5070 (landed) built this resolver.

**Found by.** The operator's re-read of rows fixed since their first read (`out-reread/reread-2.json`) read both rows CONFORMS. Their Opus refuters OVERTURNED both (`reread-2-refute.json`, probes `refute-reread-2/c1/a1.cob` and `c2/r9.cob`).

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty, and the rows this note claims are the rule ids below.

**Rules (2 claimed; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-GR-VIII.3.2.4-6` - `§1985:VIII.3.2.4 GR6` (re-read CONFORMS; refuter OVERTURNED to NONCONFORMING, harm: under-rejects), with `§1985:VII.3.9.3 SR1`: "cannot be subscripted", and `§1985:IV.4.3.8.2.3 SR4`: "Each table element reference must be subscripted except".
- `1985-GR-XIII.3.2.4-3` - `§1985:XIII.3.2.4 GR3` (re-read CONFORMS; refuter OVERTURNED, harm: under-rejects): "With the exception of the REPORT clause", all clauses of the report FD take their Sequential I-O meaning. The refuter's second point is a reading, not a defect: the RWCS ignores RECORD ... DEPENDING ON in a report FD. It rests on §1985:XIII.3.2.4 GR2 (record structure defined by the implementor), and the fix records it in docs/CONFORMANCE.md.

Run: `cobol.exe --std 85 --source-format fixed --run a1.cob`. `c2/r9.cob` is the same clause in a report FD.

**Expected (from the 1985 text).** Both are refused at compile time.

**Fix direction (root cause, CLAUDE.md rule 4).** In `ResolveValueOfDataNames`, refuse a data-name-1 whose description contains, or is subordinate to, an OCCURS clause. Ask the same table-element predicate MOVE asks (COBOL2270) instead of a second copy. Test it on a sequential, a relative and a report FD.
