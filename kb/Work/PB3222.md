**Scenario:** ByValueClass (ProcedureHeaderScreen.cs:79-86) tests item.Pic?.Category is Numeric or the pointer/object categories. An index data item carries category Numeric for its storage model, so it passes. ## Landed

Re-probed on the Debug build: `LINKAGE 01 IX USAGE INDEX` under `PROCEDURE DIVISION USING BY VALUE IX` compiled clean (the note).

**Fix.** `ProcedureHeaderScreen.ByValueClass` asks `IntrinsicArgumentRules.ClassOfItem` and admits class numeric, object and pointer, failing open on an undecidable class: the same answer `CallBinder.ValueClassScreen` (14.9.4.3 SR22) and `UdfBinder` function-argument screen take. The PicCategory list is deleted and the message names the class. `ByValueFormalScreenDriftTests` pins that the method asks the classifier and spells no PicCategory.

**Found and fixed in the same files (I9).** The screen ran at header time, before a TYPE clause had composed its subject, so a `01 NX TYPE NT` formal (NT numeric) had no PICTURE and was refused falsely (COBOLNET1553), while an alphanumeric-typed one was refused only by that accident. Both header arms (`CallBindLinkage`, `OoBindMethodData`) now call `CompleteDescriptionAhead(item)` before the class screen. Goldens: `14.2-Procedure-division-structure/pb3222-by-value-formal-index` (refused 2002-2023), `pb3222-by-value-formal-type-alphanumeric` (refused), `pb3222-by-value-formal-type-numeric` (accepted).
