# PB5254 - at --std 85 a PERFORM in a USE BEFORE REPORTING procedure whose range holds a GENERATE, INITIATE or TERMINATE compiles, and the performed GENERATE does nothing: the 1985 syntax rule has no site (2023 replaced it with the run-time EC-FLOW-REPORT)

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/ReportWriterBinder.cs` (`RejectInBeforeReporting`, read by `BindGenerate`, `BindInitiate`, `BindTerminate`)
- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/EnclosingContext.cs` (`InBeforeReportingProcedure`)

**Mechanism.** §1985:XIII.4.9.3 SR3 has two sentences: GENERATE, INITIATE and TERMINATE "must not appear in a paragraph within a USE BEFORE REPORTING procedure", and "A PERFORM statement in a USE BEFORE REPORTING procedure must not have GENERATE, INITIATE, or TERMINATE statements in its range." The first is `RejectInBeforeReporting` (COBOL2378) at every edition. The second has no site: 2023 replaced it with the run-time EC-FLOW-REPORT of §2023:14.9.49.4 GR10 (kb/Work PB326 landed that), and no 1985 arm restores the compile-time refusal. Only the range the PERFORM names is decidable at compile time.

**Found by.** The 1985 code read, slice 56.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids below. None of them is recorded: the code read's non-conforming verdicts of slices 36-56 wait in `E:/COBOL-coord/scratch/coderead-85/pipe-for-register.json`.
