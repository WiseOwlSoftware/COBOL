# PB1315 — OPEN — two diagnostics with nowhere to point

## Measured
`opt1727.cob` (`--std 2023`):
```cobol
       OPTIONS.
           INITIALIZE ALL TO SPACE.
```
```
  error COBOLNET1727: the INITIALIZE clause's fill literal SPACE is not a one-byte hexadecimal-alphanumeric literal …
```
`glob.cob` (`RD RG GLOBAL. 01 TYPE DE LINE 1. 05 COLUMN 1 PIC 9 SOURCE KC.` with `01 KC CONSTANT GLOBAL AS 5.`)
also produces a line with no position:
```
  error COBOLNET0899: RD 'RG': SOURCE 'KC' does not resolve to a data item (ISO §13.18.53.3 SR4)
```
Every other diagnostic in the same runs carries `file(line,col)`. PB1316 records that the SOURCE refusal is
itself wrong.

## Mechanism
The sink stamps the cursor set by `sink.At(line, column)` (`src/Cobol.Net.Editions/DiagnosticCursor.cs`, PB82),
and no report site passes a location. So a diagnostic without a position means the walker that reached the site
never opened an `At(…)` scope:
- `src/Cobol.Net.Compiler/Binding/OptionsBinder.cs:194`: the OPTIONS paragraph binder runs before the
  procedure/data walkers and positions nothing.
- The RD SOURCE resolver in `src/Cobol.Net.Compiler/Binding/DataBinder.Reports.cs` resolves SOURCE operands in a
  deferred pass after the entry walk has closed its scope.

## What the fixer owes
- Position the cursor at both sites, on the fill literal's token and on the SOURCE operand's token.
- A **drift test** in the mechanism's own shape: bind a corpus of negative goldens and fail on any Error-severity
  diagnostic whose cursor `IsSet` is false. A small allowlist covers the genuinely unit-level diagnostics, such as
  "no PROCEDURE DIVISION". The gap then shows up at the next site that forgets.
- **Sweep:** every deferred or post-walk pass (the report-writer resolution passes, `ClosedFormatPass`, the
  OPTIONS and SPECIAL-NAMES binders) for a report issued outside an `At` scope.
