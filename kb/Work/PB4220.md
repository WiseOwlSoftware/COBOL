# PB4220 — one rule, one place: how a capacity register is built

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.Oo.cs:865` (`DataBinder.CreateCompilerTempTable`, the register
literal at :879), `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.Odo.cs:634` (`DataBinder.DynamicResolve`, the register
literal at :742).

**Mechanism.** `CreateCompilerTempTable` mints the unnamed dynamic-capacity CAPACITY register by hand with the same five
fields `DynamicResolve` writes: `Level = 49`, `CsName = NamingConvention.CapacityRegisterName(...)`,
`Pic = PicInfo.BinaryItem(Usage.BinaryLong, signed: false)`, `Parent` = the table's parent, and a fresh `Uid`. That is a
second copy of how a capacity register is built (CLAUDE.md rule 4, one rule in one place). The `CreateCompilerTempTable`
summary even says the register is "minted here the same way".

**Fix direction.** One factory method on `DataBinder` (taking the table item and the optional COBOL name) that both sites
call, deleting both literals in the same change. A change to the register's shape (a new field, a different PIC) then
cannot reach one site only.
