# PB552

## Landed (wave 1031 C, 2026-10-07)

Re-probed on the wave's own build: `88 C VALUE 5 THRU 1.` with `MOVE 3` printed `NO`, rc 0; the equal pair, the
second pair of a list, the non-integer pair and `"Z" THRU "A"` all compiled clean. Rule: ISO §13.18.63.3 SR26,
"the value of literal-2 shall be less than the value of literal-3" (cite.py OK) — a) unconditionally, b) "when …
the runtime collating sequence is known". The note's blocker (the `IN alphabet-name-1` phrase being dropped) was
discharged by PB502; the second blocker the earlier waves named — whether a non-LOCALE sequence is "known" — was
settled by the owner's precedence (CLAUDE.md rule 1, protocol 2026-08-30): GnuCOBOL 3.2 checks neither arm
(measured), IBM Enterprise COBOL 6.4 requires literal-1 < literal-2 for every class, and SR27 b)'s screen already
answered "known" for every non-LOCALE sequence. Recorded as `docs/CONFORMANCE.md` §3 D-RANGE-KNOWN.

Fix: `DataBinder.CheckRangesAscending`, called in `BindCondition` once the alphabet phrase is resolved and before
literal-4 — a) algebraic for a numeric subject (or two numeric literals on a numeric-edited one), b) through the
SAME `ConditionValueOrder` SR27 reads (the IN alphabet, else the PROGRAM COLLATING SEQUENCE, else native; a LOCALE
sequence skipped). New COBOLNET2961 (`DiagnosticCatalog.ValueThroughNotAscending`). Negative golden
`tests/conformance/negative/pb552-value-through-not-ascending` (six arms). The national leg the correction above
names is covered (`N"ZZ" THRU N"AA"` draws 2961). Seven goldens relied on an inverted range in a known sequence and
were reworked: `2023/ec_range_invalid` and the three `2023/pb367b_*` (the inverted 88 now ordered `IN` a LOCALE
alphabet, which keeps the EC-RANGE-INVALID run-time arm and the outputs byte-identical; ec_range_invalid's numeric
descending leg moved to an EVALUATE WHEN range), `2002/pb502_value_range_in_alphabet` and
`2002/pb398_range_in_alphabet` (the inverted legs moved to the negative), `2002/pb728_level88_group_usage_collating`
and `2023/pb761_national_through_range` (the over-fix guards now use pairs that ascend in the alphanumeric reversed
sequence and would be inverted in the national one). Row SR-13.18.63.3-26 CONFORMS (batch `w1031c-pb552`).

### Expected, from the standard
Each of these is nonconforming and shall draw a compile-time diagnostic: `88 C VALUE 5 THRU 1.` (SR26 a); `88 C VALUE 9.5 THRU 1.5.` (SR26 a, non-integer); `88 C VALUE "Z" THRU "A".` (SR26 b -- the native runtime collating sequence is known); `88 C VALUE 5 THRU 5.` (the rule says LESS THAN, so an equal pair violates it); and a reversed range anywhere in a LIST, e.g. `88 C VALUE 1 THRU 3, 9 THRU 7.`. `88 C VALUE 1 THRU 5.` stays legal.

HARM is under-rejection with a silent consequence: the condition is simply never true, so a transposed range leaves a dead branch and the program runs to completion. ⛔ DO NOT LAND THIS ALONE -- SR26 b turns on the runtime collating sequence being KNOWN, and the `IN alphabet-name-1` phrase that names it is discarded (finding F2); a comparison added today would evaluate under the native sequence and would REJECT the conforming `88 C VALUE "C" THRU "A" IN ALPH1.` under an alphabet ordering C < B < A. COBOLNET0899, probe b_sr26_national)". **That is no longer true.** [[PB761]] discharged that stage: the
