# PB4705 — one SR14 violation through SAME AS draws two COBOL1724

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Passes/CheckUsageDeclarationsPass.cs:244` (`CheckUsageDeclarationsPass.ScreenSr14ElementaryPlacement`)

Reported by the branch review, not probed. R1-2, copied: not introduced by the PB4626 branch, `ScreenSr14ElementaryPlacement` reports a
member copied by SAME AS a second time at the source position of the written member, where the TYPE twin reports it once, so one
written violation of ISO 13.18.60.3 SR14 draws two COBOL1724.

**Landed (wave 20261872 H).** Re-probed on a fresh build before the change. `01 PG. 05 PX PIC X. 05 PP USAGE POINTER. 01 PHH SAME AS PG.
01 G. 05 Q SAME AS PG.` drew THREE COBOL1724, all at PP's position (line 7): the source member (level 05 under PG), PHH's copy (level 05
under PHH) and Q's copy (level 09 under Q). The TYPE spelling (`05 PZ TYPE PT` in PG, with the same two copies) drew three too, and the
elementary SAME AS (`05 Q SAME AS P`, P a level-1 pointer) drew one, at Q. The cause is wider than the member the note names:
`ConformanceForest` prunes only TYPE clones (`TypeAnchor`), so a member `CloneItem` copied for a SAME AS subject (ISO 13.18.49.4 GR1;
a level-1 group by 13.18.49.3 SR7) is a "written" entry to the first loop, and the second loop's `written` test
(`IsWrittenEntry(item.Parent)`) passes a TYPE entry beneath a SAME AS subject as well. Both SR14 arms (A, the group that wrote a phrase,
and B, the elementary item) now skip a copied member (`DataItem.ClonedFrom` set, `Sr14CopiedMember`): its verdict is the source member's,
which sits in the same forest and is screened at its own position. The SAME AS subject itself (no `ClonedFrom`) is still screened at its
own placement. A source legal under a strong type (`01 SV TYPE ST`, then `01 Q SAME AS SV`) carries the TYPE identity and stays clean
(pinned). The other first-loop screens (SR4 CONSTANT RECORD, SR15, the EXTERNAL and BASED class rules) are facts of the copy's PLACEMENT
that the source does not share, so they keep asking the copies. Re-probed after: one COBOL1724 per written violation in all the shapes
above, for each of the five phrases. Tests: `UsageDeclarationPlacementMatrixTests.ASameAsCopyOfAViolatingGroup_AddsNoSecondReport` (every
SR14 phrase, member and TYPE spellings, exact count; it fails with the guard off) and `ASameAsCopyOfAStronglyTypedGroup_StaysLegal`;
golden `pb4705-usage-pointer-same-as-group` (13.18.60-USAGE, refused at 2002-2023; the harness has no count field, so the count is the
unit test's).
