# PB882 — OPEN — two entries, one counter, because the key is the name

Source: the `PB482` report, "New defects" item 1.

## The measurement

`<scratch>/reg6/probe/q05_dupsum.cob` (PROGRAM-ID `R6Q05`), `--std 2023 --run`, one CONTROL FOOTING with two
SUM entries carrying the same data-name:

```cobol
01 TYPE IS CONTROL FOOTING FINAL.
   02 LINE 2.
      03 CF-T COLUMN 1 PIC 9999 SUM WS-A.        *> WS-A = 11
      03 CF-T COLUMN 7 PIC 9999 SUM WS-B.        *> WS-B = 22
```

`r6q05.txt`:

```
DET
0022  0022
```

Owed: `0011  0022`. The second registration replaced the first, so BOTH printable items render the second
counter.

## The rule

```
$ python scripts/spec/cite.py --check 13.18.54.4 "Each entry containing a SUM clause establishes an independent sum counter"
  OK  §13.18.54.4 1)  (General rules)
      1) Each entry containing a SUM clause establishes an independent sum counter and size error indicator.
      The sum counter is a conceptual data item that behaves as a data item of the category numeric. ...
```

"Each ENTRY" — the counter is established by the ENTRY, not by the name. And the source is legal: neither
`CF-T` is referenced anywhere, so §8.4.2.2.1's uniqueness requirement is not engaged (it bites on a
REFERENCE, not on a declaration nobody names).

## The code site

`src/Cobol.Net.Runtime/IO/ReportWriter.cs#AddSum` keys `CobolReport._sums` by `ReportSumModel.Id`, which the
binder fills with the entry's data-name. Two entries, one key, last write wins.

## ⛔ Why this is filed as its own note and NOT folded into PB840

The PB482 report asked the registrar to fold it into `kb/Work/PB840` ("a named SUM COUNTER is not published
into the procedure division's name space"), on the reading that one fix gives the counter an identity that is
not its spelling. **They are one FILL UNIT and two mechanisms**, and folding would have hidden a
`wrong_answer` inside a `rejects_legal_source` note: PB840's harm is that a legal reference is refused;
PB882's is that a correct program prints the wrong number, which is what `work.py next` ranks first. Both
notes carry `cluster:` naming the other so the fill hands one implementer the pair — and the implementer
should do PB840's symbol first, because a counter with a symbol has an identity PB882 can key on.

## The sibling sweep

Anything else in the report-writer runtime keyed by a user-chosen spelling rather than by the entry: the
`_sums` dictionary is the measured one; `CobolReport`'s control-break state, the PRESENT WHEN / GROUP
INDICATE per-entry flags and the `LINE-COUNTER`/`PAGE-COUNTER` maps are the places to look. A report with two
identically-named entries of ANY kind is the general probe.
