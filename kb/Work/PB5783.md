# PB5783 - 1985-GR-X.4.5.4-3 can be witnessed only by a refusal

**Sites:** `scripts/spec/data/lineage-evidence-kinds.json` (the evidence table, which classes every GR as needing an
accepted case) and `scripts/spec/lineage_reads.py#Witnesses.own_problems` (which applies it). No compiler site.

**The rule.** §1985:X.4.5.4 GR3: "Use of the EXTERNAL clause does not imply that the associated file-name or data-name
is a global name."

```
python scripts/spec/cite.py --check "§1985:X.4.5.4 GR3" "Use of the EXTERNAL clause does not imply that the associated file-name or data-name is a global name"
OK  §1985:X.4.5.4 GR3  (║4.5.4 General Rules║)  the text is in GR3
python scripts/spec/cite.py --check "§1985:X.1.3.8.2 GR3" "If the name is declared in program B, the object in program B is the referenced object"
OK  §1985:X.1.3.8.2 GR3  (1.3.8.2 Conventions for Condition-Names, Data-Names, File-Names, Record-Names, and Report-Names)  the text is in GR3
```

**Why no accepted case can fail on it.** The writer's case `g85_bf31_06` declares `BF31-XREC EXTERNAL` (not GLOBAL)
in the outer program; a contained program L declares its own non-external `BF31-XREC` and a contained program E
declares the record EXTERNAL itself. Every line it prints would print the same if EXTERNAL DID imply GLOBAL: under
§1985:X.1.3.8.2 GR3 a, a name declared in the contained program refers to that program's own object, so the local
declaration wins either way, and E reaches the record through its own EXTERNAL description. A contained program can
reach the outer item only by declaring the name, so no conforming accepted program tells "not global" from "global".
The refuter showed this and the fixer agreed; integrator c read both drafts and agrees.

**The one observable consequence** is a refusal: a contained program that does NOT describe the record and references
it must be refused. The draft `g85_bf31_07` does exactly that, and the compiler refuses it at `--std 85`
(`g85_bf31_07.cob(28,20): error COBOL1639: BF31-XREC is not defined`, exit 65, in the lane's run). The row's input says
`diagnosable: false` (a GR; the evidence table fails closed), so that refusal cannot close it today.

**Decision.** The row gets no golden in this landing and stays a GAP. Both drafts are kept, correct, out of the tree:
`E:/COBOL-coord/scratch/gl1985/lane1/out/g1985b-x-4-5-external/conformance-suite/cases/X.4.5@1985-EXTERNAL-CLAUSE/g85_bf31_06.cob`
(`.out`) and `g85_bf31_07.cob` with `conformance-suite/wiseowl/diagnostics/g85_bf31_07.json` beside it. The row closes
by one of two acts, whichever comes first:

1. the evidence table gains a class for a general rule whose only consequence is that a form is NOT available (a name
   not visible, a clause not implied), whose witness is a refusal at 85; `g85_bf31_07` then lands as this row's
   witness; or
2. the registrar records the row as an own 1985 verdict on a DRV record that names `g85_bf31_07` as its evidence.

The same shape (a "does not imply" general rule) is likely in other clauses of every edition; option 1 is the general
answer and should be weighed against them before it is chosen.
