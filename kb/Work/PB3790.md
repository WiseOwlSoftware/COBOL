# PB3790 — the documented landing-check order is not the executed order

**Sites:** `docs/DOC_INDEX.md` (the `enqueue.py` row, line 175), `docs/rearchitecture/DESIGN-test-build-ci.md` (section 3.17.2 step 3)

## Measured

`scripts/orchestrator/enqueue.py` line 258: `CHECKS = (devlog.py check, landing_check.py, work.py check)`, and
`run_checks` returns the first refusal. DOC_INDEX.md line 175 reads "`devlog.py check` exit 6, `work.py check` on the merged
head exit 6, landing_check exit 3", and DESIGN-test-build-ci.md section 3.17.2 step 3 gives the same order. Which exit a
landing reports when two checks would refuse depends on that order, so a reader diagnosing a refusal is told the wrong
precedence.

## Acceptance

- Both documents state the order `enqueue.CHECKS` runs (or name the tuple as the source instead of restating it), and a
  reader can derive the first-refusal exit from them.
- A drift test, or the existing doc audit, holds the documented order to `enqueue.CHECKS` so the next added check keeps
  the docs true (one place for the rule, CLAUDE.md rule 5).
