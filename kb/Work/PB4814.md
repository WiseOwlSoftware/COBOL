# PB4814 - the history rewrite that removed the per-copy licence stamp

**Why.** The bought 2023 PDF stamps every page with the purchaser's name, the reseller order number and the download date. That
stamp had reached the public repository: a spec-reconciliation agent quoted it into its ledger, the PDF's file name carried the
order number into docs and one script, and versions of the old single-file DEVLOG.md held it. The owner asked that it be removed
from the tree (landed with the spec rename, PB3208) and from the published history.

**What was done (2026-11-05, ~22:00-22:30 PST).**
- Both lanes were stopped (the operator's loop by stop.ps1, the global STOP) and the merge queue was empty.
- `git filter-repo` ran on a fresh mirror with a blob callback and a commit callback. It replaced the old PDF file name with
  `ISO_COBOL_2023.pdf`, "Licensed to <purchaser>..." with `[per-copy licence stamp]`, any download date with `[download date]`,
  and the order number with `[order number]`. That covered every blob, including four DEVLOG.md versions that a stray NUL made
  `--replace-text` skip as binary, and every commit message. Verified afterwards: zero diffs and zero messages match.
- The owner disabled the merge-queue ruleset (id 24904083) for one push and ran the force-push of `main` (08798ec72 ->
  16f4391f5) and the three tags, deleting four leftover `gh-readonly-queue` refs. Then the owner re-enabled the ruleset.
- This landing remapped the current tree's citations: about 8,400 old SHAs in 3,181 files, history included, each replaced by the new
  commit's SHA at the same length so column-sensitive COBOL sources keep their layout; the 16 evidence files NAMED after the commit they measured (arch-census, perf-baseline) are
  renamed to the new SHA, so the tools that build the name from `git rev-parse` find them; a DEVLOG entry's
  header line keeps its words (devlog.py keys entries on it). It also adds the commit map,
  `docs/history/commit-map-2026-11-05.txt`, and `scripts/history_sha.py` to translate any old SHA, full or a unique prefix.

**What remains (status half).** GitHub keeps the old commits reachable through the pull-request refs (`refs/pull/*`, read-only)
and its caches until GitHub Support purges them. The owner requests that through GitHub's sensitive-data removal process
("Removing sensitive data from a repository"). The 36 old commits that carried the stamp are listed in the request. Flip this
note to landed when GitHub confirms the purge.

**For every lane after the rewrite.** A checkout or worktree made before it is on the old history: hard-reset it to the new
`origin/main`, or re-create it. A SHA in a gate record, report or mailbox message from before the rewrite names an old commit;
translate it with `python scripts/history_sha.py <sha>`.
