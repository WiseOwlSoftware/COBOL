# PB3164 — a method's CONSTANT entries are not method-scoped

Source: `E:\COBOL-coord\scratch\reports\w1078d-PB3154-report.md` (carried from `w1077c-PB3154-report.md`).

- Repros: `E:\COBOL-coord\scratch\w1077c\p10.cob` and `p11.cob`. In p10, method SHOWA declares `01 K CONSTANT AS "A"` in LOCAL-STORAGE while the OBJECT declares `01 K PIC X VALUE "O"`; method SHOWB declares nothing and displays K.
- Code site: `DataBinder.Oo.cs#OoBindMethodData` -> `BindRemainingConstants`.
- Expected (clerk's reading of the repro, not adjudicated): SHOWB's K is the object's data item ("B O"). Observed per the reporter: the method's CONSTANT is not scoped to its method, so it leaks to the sibling.

## Landed (wave 1080 E)

Re-probed on the w1080e build (base 2b60d9fa9): p10 printed `A A` / `B A` (SHOWB substituted SHOWA's constant for the
object's data item K) and p11 drew a false COBOLNET1547 (SR9 across two methods). The sibling arms measured with them: a
method's data item lost to its object's constant of the same name (`A O`, expected `A M`); a method's `PIC X(N)` took a
sibling method's constant N; a method could not `ADD 1 TO N` against its object's data item N (COBOLNET1548); and two
interface prototypes' constants of one name drew SR9. Probes in `E:\COBOL-coord\scratch\w1080e\p10.cob`-`p15.cob`.

**Rule.** A method definition is a source unit, so a source element of its own (§3.164). The constant-names it declares
are local names (§8.4.6.2.2; §13.18.27.3 SR4 bars GLOBAL in a method definition), and "A local name may be referenced only
in the source element in which it is declared" (§8.4.6.2.1). The object's or factory's constant-names are global names
(§8.4.6.2.2), seen by its methods, and §11.7.4 GR5 makes any word a method's data division defines hide the containing
definition's declaration of that word inside the method. §13.10.3 SR9 compares a duplicated constant-name within one
source element (the PB1009 determination, now applied to methods).

**Fix (root).** The binder's one constant table became a per-source-element `DataBinder.ConstantScope` (bound constants,
declared entries, and for a method the other words its data division defines): the binder's own, plus one per method
(`OoMethodDataScope.Constants`). `DataBinder.ConstantScopeOf` is the one answer to which element's constant a word names
(the method's own entry; nothing when the method defines the word otherwise; else the containing definition's), and every
reader asks it: `FindConstant`, `IsFailedConstant`, `ClosesConstantCycle`, `NamesConstant` and the PICTURE-expansion guard.
A declared entry carries its element (`DeclaredConstant.Scope`), so its value and its SR9 comparison stay in that element;
the two declaration walks share `DeclareConstant`. Golden `2002/pb3164_method_constant_scope` (instance and factory arms,
index-name and condition-name hiding, PICTURE repetition, the object's data item and constants read from a method);
negative `pb3164-method-duplicate-constant-unequal` (SR9 inside one method still refuses). `COBOLNET_OO_DESIGN.md` D6
names the rule beside the data-name precedence.
