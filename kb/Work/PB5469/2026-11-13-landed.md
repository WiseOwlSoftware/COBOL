**Sites (as changed, wave 20262025):** `src/WiseOwl.Cobol.Frontend/Preprocessor/CopyProcessor.cs` (`ReadOperand`).

**Landed (2026-11-13, wave 20262025).** `ReadOperand` reads identifier-1 and identifier-2 in the identifier's general format: a data-name with its OF/IN qualifiers, or a function-identifier's `FUNCTION function-name-1` (§1985:IV.4.3.8.3.2, Amendment 1), followed by EVERY balanced parenthesized group (subscripts, arguments, a reference modifier: "a syntactically correct combination of qualifiers, subscripts, or reference modifiers", §1985:IV.4.3.8.5.1). No REPLACING operand begins with a left parenthesis, so the groups cannot swallow the next operand; `FUNCTION` followed by `BY` stays word-1 (PB5418's reading by position). The one reader serves COPY and REPLACE (a REPLACE operand that is not pseudo-text is still COBOL1641).

Re-probe on this build (before / after): `p3c.cob` COBOL2449 / prints D, D; `p3h.cob` COBOL2449 / prints `cd2026` (LOWER-CASE of CD, then CURRENT-DATE (1:4)); `b02.cob` and `b03.cob` COBOL2449 / run (u, 2, tt; t, 7, tt). Golden `pb5469-replacing-identifier-operands` (85: D, BB, cd, 7; TBL (2) alone is not a match of TBL (2) (1:1)); at 2023 the operands draw the existing removal gate COBOL0902.

Not done here (a lead in the wave report): the 2002 and 2014 identifier adds object forms (an inline method invocation `obj :: "name" (args)`, an object view `obj AS class-name`), which `ReadOperand` still reads as a word; `AS` after identifier-2 is also a legal word-1 of the next pair, so the reading needs a design, not a loop.
