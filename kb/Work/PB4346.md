## Adjudication (2026-11-03): all six flips are correct, the baseline is re-recorded

The nightly of 2026-11-03 (run 41679939118, also red on 11-01 and 11-02) showed SIX flips: this note's three and three
newer. Each was reproduced with the CLI built at main 12620aaa7 and adjudicated against the ISO text; none is a
compiler defect, so no fix lands and the baseline moves (`gnucobol_differential.py --write-baseline --record`).

- `run_extensions:2172`, `run_misc:5307` (AGREE_ACCEPT -> WE_REJECT_THEY_ACCEPT, COBOL0899 on `CALL "callee" USING ...
  OMITTED`). §2023:14.9.4.2 Format 1 (Program), rendered from PDF p618, prints USING `{ [BY REFERENCE] {identifier-2} ... |
  BY CONTENT {identifier-2} ... }` with no OMITTED; OMITTED exists only in Format 2 (program-prototype), selected by AS
  or a program-prototype-name (`cite.py --check 14.9.4.2 "Format 2 (program-prototype)"`: OK). ISO/IEC 1989:2002
  §2023:14.8.4.1 is the same (OMITTED only in Format 3, program-prototype), and COBOL-85 has no OMITTED, so the refusal is
  right at every edition; `--permissive` warns (PB4012). GnuCOBOL's acceptance is a non-ISO extension (CLAUDE.md rule
  1). The question above about the "staged COBOL0899 refusal" comments: they name other, earlier COBOL0899 uses; this
  refusal is `CallBinder.Format2OnlySpellingOf`.
- `syn_file:431` (WE_ACCEPT_THEY_REJECT -> AGREE_REJECT, COBOL5701): PB4236's §2023:12.4.5.1 refusal of a SELECT with no
  ASSIGN. The compilers now agree.
- `syn_misc:3951` (AGREE_ACCEPT -> WE_REJECT_THEY_ACCEPT, COBOL5962): `REPOSITORY. PROGRAM test-prog` with no prototype,
  no earlier definition and nothing in the external repository. §2023:12.3.8.3 SR14 requires one of the three (`cite.py
  --check 12.3.8.3 "the name of a program for which information exists in the external repository"`: OK); PB2103's
  resolver enforces it. GnuCOBOL's own expected output is a warning, "no definition/prototype seen".
- `syn_misc:7168` (AGREE_ACCEPT -> WE_REJECT_THEY_ACCEPT at `-std=cobol85`, COBOL0900): a sentence before the first
  paragraph-name. ISO/IEC 1989:2002 Annex F.2 item 90 lists "A paragraph-name is not required at the beginning of the
  procedure division or a section" as new in 2002 (PB4305's F.2 edges), so COBOL-85 requires it.
- `run_fundamental:2072` (WE_REJECT_THEY_ACCEPT -> AGREE_ACCEPT): a GLOBAL FD read in a contained program, legal at
  every edition (we now agree with GnuCOBOL; the landing that fixed it was not traced).
