# PB4794 - QuotientsTerminate is wrong for quotients longer than the arithmetic keeps

**What the report says (the reviewer's words).** R1-2 LEAD (low, not blocking at round 1): `src/WiseOwl.Cobol.Compiler/Binding/IntrinsicArgumentRules.cs:1927` `QuotientsTerminate` takes a terminating quotient as exactly what the arithmetic stores, which is false once the quotient has more fraction digits than the arithmetic keeps, so the PB4758 wrong answer survives for long terminating quotients (left for the clerk: needs the arithmetic's digit limit read from its one home).

**Link.** PB4758 (landed) introduced `QuotientsTerminate`; its wrong answer survives for long terminating quotients.

**R1.** A grep of kb/Work for `QuotientsTerminate` finds only PB4758 (landed). No open note covers it.

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/IntrinsicArgumentRules.cs#QuotientsTerminate`.

**Fix (landed, wave 20261881 group B).** Re-probe on the pre-fix build: `COMPUTE X = 1 / 1048576 * 1048576` into `PIC 9` stored 0 and `COMPUTE Y = FUNCTION ABS (1 / 1048576 * 1048576)` stored 1 (the quotient has 20 fraction digits, and the arithmetic of a one-digit receiver truncates a nested quotient at 14). `IntrinsicArgumentRules.QuotientsTerminate` is now `QuotientsAreExact`: a quotient (or power) is stored exactly only when its expansion terminates within `CobolNum.NestedQuotientScale(0, 0)` fraction digits, the least working scale the arithmetic gives any nested quotient (read from its one home through `ExactFractionDigits`); `ExactRational.IsTerminating` became `FractionDigits`. Witness: `conformance-suite/cases/15.3-Arguments/pb4794_abs_literal_quotient_long.cob`.
**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/IntrinsicArgumentRules.cs#QuotientsAreExact`, `#IsKeptExactly`, `#ExactFractionDigits`, `#ExactRational.FractionDigits`, `#ProvablyIntegral`.
