# PB5853 - OPEN: does a report with no PAGE clause have a line 0?

**Ruling: NOT DECIDED (an open reading).** In a report with no PAGE clause a first group that begins LINE PLUS 0 ends with LINE-COUNTER 3 where one reading gives 2. Does an unpaged report have a line 0? The rows `1985-GR-XIII.3.10.8-4` and `1985-GR-XIII.3.10.8-6` (a lead raised by the refuter of slice 1985-211) stay `undecided`. Harm: wrong_answer under reading A only (not set while the rows are open). **Checker's confidence: low-medium.** (The row `-4` is already contradicted by kb/Work PB5823 on another mechanism.)

**The checker's evidence (rulings.json, copied).** Table 3 sends an unpaged body group (relative LINEs, no NEXT GROUP) to rules 4d and 6d (`§1985:XIII.3.10.8`, folios XIII-34 to XIII-36, printed, not reconstructed). Rule 4d: "The sum of the content of LINE-COUNTER and the integer of the first LINE NUMBER clause defines the line number on which the first print line is presented". Rule 6d: "The final LINE-COUNTER setting is the line number on which the final print line of the body group was presented". LINE PLUS 0 is legal (`§1985:XIII.3.15.3 SR1` says "Integer-2 may be zero") and an unpaged report admits only relative LINEs (SR5). After INITIATE LINE-COUNTER is 0, so the text puts the first line on line 0 and, with LINE PLUS 2 after it, ends at 2. Observed (`lc0.cob`): LINE-COUNTER 3 after the first GENERATE and 5 after the second; the file's lines are placed as the text's relative spacing gives, so only LINE-COUNTER differs. Control `lc1.cob` (first LINE PLUS 1) gives 3, as the text does. Cause: `ReportWriter.PresentLine` clamps `if (target < 1) target = 1;` at every edition.
- READING A (literal): line 0 is a line number like any other in an unpaged report (the device's position before its first line), so LINE-COUNTER must be 2, then 4: UPHELD-b, harm wrong_answer (a SOURCE LINE-COUNTER or a program test sees 3); cost: let the unpaged first line be 0 and keep the physical placement.
- READING B: no line 0 exists on any device, and SR1 forbids an integer that presents a line "outside the vertical subdivision of the page"; then the program asks for an impossible line, the result is the implementor's, and the clamp conforms (cost: none, perhaps a register line).
- What would settle it: whether a line number of 0 is presentable in a report with no PAGE clause. The refuter called it degenerate and left it to this rule's own record; the checker agrees it is not settled by the text.
