# PB1699 — HALF (landed 2026-09-28: the submodule, the overlays and the scripts; the rolling-wave migration remains)

**Owner, 2026-09-28 ~10:20–10:25 PDT:** "Keep the skills in the skills repo up to date with our latest processing.
LinkedIn readers have a link to that repo and may examine it at anytime." Then: "Plus we should be self-hosting the
skills, where applicable."

## The defect

Each generic practice is written twice today: once in this repo's `.claude/skills/*`, and once, generalized, in the
public `brent-tools` plugin. The public copy is reached only through a prose "Generic base:" pointer, and the plugin is
not installed here. The earlier reason not to install it, a collision between its `review` and ours, does not hold:
plugin skills are namespaced (`brent-tools:review`).

So every improvement made here has to be hand-ported, and public v1.6.0 was already missing DEVLOG 1746's authorization
arg and DEVLOG 1749's stamped handoff. That is CLAUDE.md rule 5's "hand-maintained list where a structure belongs",
across two repos.

## The fix (design)

1. **Enable the plugin at project scope.** `.claude/settings.json` gets `extraKnownMarketplaces` (GitHub
   BrentRector/claude-skills) and `enabledPlugins: brent-tools@brentrector-claude-skills`, so a fresh clone and cloud
   sessions get it too.
2. **Overlays, not copies.** Each project skill with a public base (workstream → agent-fleet, gate → test-gate,
   review → review, spec-lookup → spec-oracle) opens by invoking its base. It then keeps ONLY what is
   project-specific: commands, paths, kb/Work, push-main, the owner's dated decisions and measurements. Generic text
   that duplicates the base is deleted here, after confirming the base carries it.
3. **One source per generic script.** Where the project script is the public script plus project configuration
   (orient.py, fix_clusters.py, status_delta.py, the rolling-wave workflow), the public repo becomes the source. It is
   brought in as a pinned git submodule, and the project passes only its configuration. The submodule is public, so CI
   needs no credentials. Where a project script has diverged for a project reason, the divergence is documented and a
   drift check compares the shared part.
4. **Drift test.** A check (in `check_practices.py` or CI) fails when a project overlay restates a rule its base
   carries verbatim, or when the pinned submodule is behind the plugin version the settings name.
5. **The loop.** A practice improved here is written into the PUBLIC base first, then consumed. That makes "keep the
   public repo current" automatic rather than a chore.

## Landing (2026-09-28)

Owner, mid-task, 2026-09-28: "We should ideally not have wrapper scripts. Update all dependencies to directly use the
public repo scripts." That superseded the design's "thin shim" step: there are NO project copies and NO wrappers.

- **Public repo first: tags v1.8.0, then v1.8.1.** The public copies were made the single superset of both
  sides' changes. Project → public: C# outline rules, numeric newest-first LEARNED order, sorted OPEN, tests limited
  to `.cs`, a name-length threshold, `area` and `files` in the cluster JSON, and singleton-absorbs-singleton
  clustering. Public → kept: multi-language outlines, per-rule cites, `--exclude`. New in the public copies:
  `.agent-fleet.json` (`fleet_config.py`), a single optional config file that all three scripts discover at the repo
  root; explicit flags override it. 1.8.1 corrects agent-fleet §5's liveness "why": it is a tool call that writes
  nothing until it returns, plus transcripts that move on a session restart, not lazy writing.
- **The pin.** `tools/claude-skills` is a submodule of `BrentRector/claude-skills` at tag **brent-tools 1.17.1**. It
  landed at 1.8.1 and moved the same day to 1.9.0 for `status_guard.py` (kb/Work/PB1701), which the project's
  hooks call directly from the submodule, and then to 1.10.0 for `stall_watch.py` and the rolling-wave
  implementer ceiling (kb/Work/PB1704). 1.17.1 fixes `stall_watch.py` reporting every just-started agent as
  stalled (kb/Work/PB2033).
  `.claude/settings.json` declares it as a directory marketplace and enables `brent-tools@brentrector-claude-skills`.
  The marketplace's plugin source is `./`, a relative path, so the plugin installs without a prompt.

  deleted. Every caller (briefs, templates, MANDATORY-PRACTICES, workstream SKILL, `cobol-locator`, DOC_INDEX, PB1546,
  PB1698, and the rolling wave's successor STRING) now names

  `.agent-fleet.json`.

  sides. Every membership difference traces to one of two causes. (1) A project bug: a cluster emptied by absorption
  went on absorbing, so PB1160 sat in a cluster labelled `ProgramEmitter.cs` although that is not its primary file.

  - workstream §5, the restart steps (the base's §12);

- **Drift check.** `check_practices.py` (now also in CI `audits`) is RED when:
  - the overlays or this note name a different brent-tools version than the submodule's;
  - `.agent-fleet.json` carries a key no fleet script accepts;
  - a tracked file names a `tools/claude-skills/…` script the pin lacks;
  - anything outside DEVLOG and frozen evidence still calls a retired copy.
