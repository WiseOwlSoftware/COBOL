# PB5758 - three 1985 rows no program can fail

**Sites:** none (a record of rows' evidence; `docs/conformance/8/` gains the DRV records when the registrar acts).

Each row below was drafted with a golden, the refuter showed the golden could not fail on the row, the fixer took the
row out of the case's `rules` and dropped its record, and integrator a agreed. Every citation was checked on
2026-11-15 with `python scripts/spec/cite.py --check` and printed `OK`.

**1985-GR-XIII.3.21.4-1.** The rule is §1985:XIII.3.21.4 GR1: "If the USAGE clause is written at a group level, it
applies to each elementary item in the group." A report group item can only specify DISPLAY (§1985:XIII.3.21.3 SR3: "The
USAGE clause for a report group item can specify only USAGE IS DISPLAY"). An item with no USAGE of its own, and none on
any group above it, is DISPLAY anyway (§1985:XIII.3.21.4 GR4: "the usage is implicitly DISPLAY"). So a compiler that
ignored GR1 would give every report elementary item the same usage and print the same report. The draft g85_f10_02
still lands, for SR1 and SR2.

**1985-GR-VI.5.13.4-3 and -4.** These are §1985:VI.5.13.4 GR3, where SYNCHRONIZED LEFT means the item will "begin at
the left character position of the natural boundary", and GR4, where SYNCHRONIZED RIGHT means it will "terminate on the
right character position of the natural boundary". WiseOwl treats every byte position as a natural boundary
(docs/conformance/7/DOC-A.1-197.md). So every placement meets both rules: there is no byte between a boundary and the
item's edge for a wrong placement to show. The draft g85_f09_02 still lands, for the format, GR1, GR2 and GR8.

**Decision.** These rows get no golden. Each stays a GAP until the registrar records it as an own 1985 verdict on a
DRV record. The rule's effect equals what every program shows, given SR3 with GR4 for the first row and DOC-A.1-197 for
the other two. A KEPT row cannot hold a derivation (PB5675). Re-adjudicate GR3 and GR4 if DOC-A.1-197 ever gives any
item a natural boundary wider than one byte.
