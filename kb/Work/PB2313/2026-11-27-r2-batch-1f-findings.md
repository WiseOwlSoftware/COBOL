### `procedure-binding-3--performance--f1#1` (lead, unify, votes refuted/upheld/upheld)

**Rule:** DESIGN-architecture-review §5.4 / DESIGN-architecture-review §4 item 5 and dimensions.md 3: repeated work whose inputs did not change, on a per-operand bind path

**Scenario:** Read from the pin: for a bare value operand that is a data item (EVALUATE X WHEN Y, or the C in IF A = B OR C), ConditionBinder.AnalyzeBareOperand asks ctx.Refs.Probe(mqr) at ConditionBinder.cs:1546 (the misqualified-condition arm), then IsBooleanValueOperand -> IsSoleBooleanOperand asks ctx.Refs.Probe(dref) again at :242 for the same DataReferenceContext, and the caller then binds it through ComparisonOperandOf -> host.Expr.FieldOperand (:1872), a third resolution. EvaluateBinder.AnalyzeObjectBare (EvaluateBinder.cs:488-491) runs it for every WHEN object, the most frequent caller. No row of perf-baseline/b1a42fc36e8b.md isolates resolution, so the share of FrontEndAndBind time is unmeasured: a lead.
