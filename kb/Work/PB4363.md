# PB4363 - USE FOR DEBUGGING ON ALL identifier: the operand is never resolved

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/ProcedureTableBuilder.cs` (`ProcedureTableBuilder.FinalizeDebug`, the ALL arm, line 585 at the filing); the test PB4237 added that pins the message for `ALL P1` (search `tests/WiseOwl.Cobol.Tests.Unit` and `conformance-suite/cases` for `P1`).

PB4237 (on main) made `USE FOR DEBUGGING ON ALL identifier` at `--std 85` report the legal-but-unmodeled subject. The ALL arm of `FinalizeDebug` does not resolve identifier-1, so the same message is given when the operand names a paragraph, or names nothing declared. The user sees "legal, not modeled" about a program that is in fact wrong (undeclared name) or a different subject (a procedure-name), and the new test pins that wrong message for `ALL P1` where P1 is a paragraph.

Fix: resolve identifier-1 in the ALL arm first; an undeclared name draws the undeclared-name diagnostic, a procedure-name the procedure-name subject message, and only a data item reaches the unmodeled message. Re-pin the test.

**Sites (landed):** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/ProcedureTableBuilder.cs` (`ProcedureTableBuilder.FinalizeDebug`:
both operand arms resolve first; `ResolveDebugProcedure`, `NamesDataItem`, `NamesFile`, `ReportUnresolvedDebugOperand` and
`DebugOperandAsWritten`, new), `src/WiseOwl.Cobol.Editions/Diagnostics/DiagnosticCatalog.cs` (`DiagnosticCatalog.DebugAllOperandIsProcedure`,
COBOL5848), `tests/WiseOwl.Cobol.Tests.Conformance/DebugFacilityTests.cs` (the `ALL P1` row of
`AllIdentifier_EverySpelling_At85_IsTheStagedDataItemOperand` moved to `AllOperandNamingAProcedure_At85_IsNoDataItem`; new
`OperandNamingNothing_At85_IsTheUndefinedReference`, `BareOperandNamingADataItemOrFile_At85_StaysStaged`,
`QualifiedProcedureNameSubject_At85_DebugsOnlyTheQualifiedParagraph`), `docs/CONFORMANCE.md` (D-DEBUG-USE).

**Landed.** Re-probe on f0e4650e5 (Debug build): `ALL P1`, `ALL MAIN` (a section) and `ALL NOSUCH` all drew COBOL1571 "the
data-item subject ... recognized but not modeled", as filed; the bare arm did the same for `ON NOSUCH` (the sibling) and
refused the legal qualified `ON P1 OF MAIN` with that text and the qualifier dropped. Now `ALL <paragraph|section>` is
COBOL5848 (a procedure-name identifies no data item, ISO 14.4.1 with 8.4.2.1), a name nothing declares is the one COBOL1639
in either arm, a qualifier a declared item is not under is COBOL1639's qualifier text (8.4.2.2.3 SR1), a data item or file
stays COBOL1571, and `ON word OF section` is a procedure-name subject. The two operand arms read procedure-names through the
one `ResolveDebugProcedure`. Goldens `conformance-suite/cases/_unassigned/pb4363_debug_qualified_procedure` (85),
`pb4363-debug-all-procedure-name` and `pb4363-debug-all-undeclared` (refusals at 85).
