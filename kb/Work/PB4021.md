# PB4021 — `_copy_lines` names the wrong line for a COPY in a string constant

**Sites:** `scripts/standard_streams.py:142` (`_copy_lines`).

**What.** For a COPY found inside a string constant, `_copy_lines` reports `node.lineno` plus the number of newline
characters in the DECODED value before the match. A string written with `\n` escapes, or an implicit concatenation of
adjacent literals on several lines, has decoded newlines that are not physical newlines (or physical ones that decode to
none), so the reported line is not the line the COPY is on; the docstring promises the line it is on.

**Repro.** A source holding `x = ("a\n" "b COPY ...")` or a triple-quoted string with `\n` escapes: the reported line differs
from `grep -n`.

**Fix shape.** Take the line from the token or the source segment (`ast` end positions or `tokenize`), not from the decoded
value; add an arm for an escape-sequence string and for an implicit concatenation.
