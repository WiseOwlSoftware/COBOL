# PB461 — one rule, three private copies, and a statement that falsifies its own condition

**Rows:** none — this note owns no traceability row. The row that measured the symptom is `GR-14.9.39.4-6`,
owned by PB462; this note owns the *shared* mechanism the fix has to land in, because it reaches three emitters
and two other verbs. Found by the b2 adjudicator `set-statement-p5` and the b2 refuter of `GR-14.9.39.4-6`;
**re-measured on the HEAD `cobol.exe` (base 89044aa0)**.

## THE MECHANISM

The parse tree's `GetText()` glues tokens, so a level-88 `VALUE ALL "*"` arrives at the emitters as the text
`ALL"*"` — no space. Three sites each decide, privately and differently, how to strip the `ALL`:

| site | how it strips `ALL` | `ALL "*"` | `ALL SPACES` |
| --- | --- | --- | --- |
| `CodeGen/DataDivision/ValueInitializer.cs:188` (+ `:302-305` `FigurativeKind`) | strips on the GLUED spelling **and** routes an ALL-literal through `EmitText.AllLiteralText` + `RepeatToWidth` | ✅ `[****]` | ✅ |
| `CodeGen/Emit/ConditionRenderer.cs:474` / `:485` `FigurativeFillChar` | calls `AllLiteralText`, but the figurative strip fires only when `char.IsWhiteSpace(t[3])` | ✅ | ❌ the glued `ALLSPACES` never strips |
| `CodeGen/Verbs/SetEmitter.cs:210` `FigurativeWordFill` | strips when `char.IsWhiteSpace(w[3]) || char.IsLetter(w[3])` — but there is **no `AllLiteralText` path in this emitter at all** | ❌ falls to the ordinary alphanumeric arm, raw text stored | ✅ |

`EmitText.AllLiteralText` (`EmitCore.cs:138` → `Frontend/Common/CobolLiteral.cs:221-227`) and
`EmitText.RepeatToWidth` are THE repetition service, and two of the three sites already call it. `SetEmitter`
does not, so `SetEmitter.cs:192-193` stores `CobolLiteral.Decode("ALL\"*\"")` — the parse text — truncated to
the item's width.

**The harm is not a formatting nit: the statement whose entire purpose is to make a condition true makes it
false.** And the mirror-image failure is in `ConditionRenderer`: after a *correct* store of four spaces,
`IF B-ALLSP` is false, because that site's strip never fires on the glued `ALLSPACES`. So a program can be wrong
on the SET side, on the TEST side, or on both, depending on which spelling of the figurative it used —
`feedback_one_rule_one_place` exactly: a single construct failing usually means ONE RULE written down in more
than one place, and the extraction IS the fix.

## THE RULES, QUOTED, EACH `--check`ed ON THIS TREE

* `--check 14.9.39.4 "If the TRUE phrase is specified, the literal in the VALUE clause associated with
  condition-name-1 is placed in the conditional variable according to the rules for the VALUE clause"` →
  **OK §14.9.39.4 6) (General rules)**. "According to the rules for the VALUE clause" is the whole finding: the
  SET emitter is required to decode the operand with the SAME decoder the VALUE clause uses.
* `--check 8.3.3.6.4 "the string of characters is repeated character by character until the size of the
  resultant string is greater than or equal to the number of character positions in the associated data item"` →
  **OK §8.3.3.6.4 2) (General rules)** — this is the repeat-and-truncate rule that makes `ALL "*"` into `****`
  in a four-character item, and `ALL "AB"` into `ABAB`.
* `--check 8.3.3.6.3 "Literal-1 shall be an alphanumeric, boolean, or national literal, any of which may be a
  concatenation expression. The literal shall be neither a figurative constant nor a zero-length literal."` →
  **OK §8.3.3.6.3 2) (Syntax rules)** — the Format-6 (`ALL literal-1`) syntax rule, which is what tells the
  three sites apart: `ALL SPACES` is the bare-figurative path, `ALL "*"` is the literal-repetition path, and a
  correct implementation needs BOTH.

⚠ **Citation correction.** The adjudicator's finding attributes the ALL-literal form to a clause numbered
`8.3.1.2`. **No such clause exists in the standard** — there is no heading below `8.3.1 General`, and a
`--check` against that number fails outright. The rules are the two validated above. Re-derived here, not
inherited (CLAUDE.md rule 1).

## EXPECTED vs OBSERVED — re-run on HEAD

Probes are the adjudicator's own, copied to `scratchpad/probe-g8-set-b/p5/`.

```
$ cobol.exe gr6-roundtrip.cob --std 2023 --run
   01 WS-A PIC X(4) VALUE "0000".   88 A-ALLSTAR VALUE ALL "*".
   01 WS-B PIC X(4) VALUE "0000".   88 B-ALLSP   VALUE ALL SPACES.
TEST-ARM-TRUE          MOVE ALL "*" TO WS-A  then IF A-ALLSTAR  -> the MOVE path is right
AFTER-SET=[ALL"]       MOVE "0000" TO WS-A;  SET A-ALLSTAR TO TRUE  -> expected [****]
ROUNDTRIP-FALSE        IF A-ALLSTAR after that SET               -> expected ROUNDTRIP-TRUE
CONTROL-FALSE          SET B-ALLSP TO TRUE; IF B-ALLSP           -> expected CONTROL-TRUE

$ cobol.exe gr6-allforms.cob --std 2023 --run
A=[ALL"]               88 … VALUE ALL "*"    on PIC X(4)  -> expected [****]
B=[    ]               88 … VALUE SPACES                  -> correct
C=[AB  ]               88 … VALUE "AB"                    -> correct (left-justified, space-filled)
D=[ALL"]               88 … VALUE ALL "AB"                -> expected [ABAB]

$ cobol.exe gr6-valuectl.cob --std 2023 --run     # the SAME source text through the VALUE initializer
INIT-A=[****]          01 WS-A PIC X(4) VALUE ALL "*".
INIT-B=[ABAB]          01 WS-B PIC X(4) VALUE ALL "AB".
```

The control is the proof: the identical operand text is decoded CORRECTLY one file away. Exit 0 throughout — no
diagnostic, no crash, just a wrong value and a false condition.

## THE CODE SITES AND THE SHAPE OF THE REPAIR

| site | today |
| --- | --- |
| `CodeGen/Verbs/SetEmitter.cs:184-199` | `figFill` (bare-figurative) or the ordinary store — no ALL-literal arm |
| `CodeGen/Verbs/SetEmitter.cs:207-215` `FigurativeWordFill` | private copy #3 of the ALL strip |
| `CodeGen/Emit/ConditionRenderer.cs:468-478` `StringMembershipValue` / `:482-492` `FigurativeFillChar` | copy #2 — has `AllLiteralText`, strips figuratives only before whitespace |
| `CodeGen/DataDivision/ValueInitializer.cs:188`, `:296-305` | copy #1 — the only complete one |
| `Frontend/Common/CobolLiteral.cs:221-227` `AllLiteralText` + `EmitText.RepeatToWidth` | the service two of the three already call |

⛔ **Do not add an `AllLiteralText` call to `SetEmitter` and stop** (CLAUDE.md rule 5). That fixes one of the
three copies and leaves the `ConditionRenderer` half broken — which is precisely the state that produced the
`CONTROL-FALSE` line above, and precisely the shape `feedback_two_arm_dispatch` names.

The structural repair is **ONE level-88 VALUE-operand decoder**: given (raw operand text, the conditional
variable's PicInfo/width, the collating state), it returns the stored image, handling bare figuratives, the
`ALL` prefix in BOTH spellings (glued and spaced), `ALL literal-1` repetition, national/boolean/numeric-edited
categories and the group case. `ValueInitializer` already contains ~all of it; extract it and have
`SetEmitter.EmitSet` and `ConditionRenderer.StringMembershipValue` call it, then DELETE both private copies.
§14.9.39.4 GR6 asks for exactly this in so many words — "according to the rules for the VALUE clause". Pair it
with a drift test that a level-88 VALUE, its SET store and its condition TEST all produce the same image for a
matrix of operand spellings, so a round trip can never disagree again.

## THE SIBLING SWEEP

* Every consumer of a level-88 VALUE operand: the SET store (here), the condition TEST
  (`ConditionRenderer.StringMembershipValue`), the ordinary VALUE initializer, `INITIALIZE … TO VALUE`, and
  `EVALUATE`'s condition-name subject. Each must go through the one decoder.
* Every OTHER private `StartsWith("ALL", …)` strip in the tree — three are named above; grep for more.
* Every category the decoder must cover: alphanumeric, national (`gr6-national` measures `N"AB"` on `PIC N(4)`
  as `[AB  ]`, correct today), boolean, numeric-edited, numeric. A one-category fix re-forks the rule.
* The `ALL SPACES` condition-TEST failure belongs to the §8.8.4 condition-name rows, not to §14.9.39 — sweep it
  with this fix rather than filing it as a separate defect.
