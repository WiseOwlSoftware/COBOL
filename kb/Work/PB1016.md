# PB1016 — LANDED

## Repro — measured
`scratchpad/reg12/q11_constlen.cob` → compiles, prints `KL=7`. SR-8.4.2.3.3-2 is CONFORMS (PB877) for procedure-division
references; this DATA DIVISION path was not in its witness set.

## The rule
`OK  §8.4.2.3.3 2)` — "If a subscript is specified, the data description entry describing qualified-data-name-1 … shall
contain an OCCURS clause or shall be subordinate to a data description entry that contains an OCCURS clause." SR3
(subscript count = OCCURS depth) is the sibling.

## Code site
`DataBinder.Constants.cs` `BindConstantLength` checks only that the subscript tokens are literals.

## What the fixer owes
Route the constant's operand through the one subscript-arity screen the procedure division uses (the same rule the
screen section's `ScreenSubscriptArity` re-implements — fold that one in too: memory `one_rule_one_place`).

## Landed

2026-09-22, wave 54 group I. Re-probed first on the implementer's own build: `q11_constlen.cob` compiled and
printed `KL=7`, as filed. After: `error COBOLNET2096: 'PLAIN(1)': a subscript is written on 'PLAIN', whose data
description entry neither contains an OCCURS clause nor is subordinate to one … (ISO §8.4.2.3.3 SR2)`.

**Mechanism.** `DataBinder.BindConstantLength` validated only the FORM of the subscripts (§13.10.3 SR3, "All
subscripts of data-name-1 and data-name-2 shall be literals") and never asked §8.4.2.3.3 whether a subscript may be
written at all (SR2), how many (SR3) or whether one may be omitted (SR5). **Fix:** the constant binder now calls the
ONE screen, `ReferenceResolver.ScreenSubscriptArity` (made `internal`), with the written count from the one
splitter (`SubscriptSegments`) — the same codes COBOLNET2096 / 2097 / 2270 the procedure division emits. A constant
entry is not among SR5's seven exemptions, so `CONSTANT AS LENGTH OF <table element>` unsubscripted is now 2270.

**Sibling found on the way (same file, same root).** The binder's private suffix walk looked only at a suffix's own
subscript part, so a subscript hung off a qualification (`CELL OF ROWX (3 2)`) was neither SR3-checked nor counted,
and a separately parsed `refModPart` was dropped unread. It now reads the reference through the ONE decomposition,
`ReferenceResolver.ReadWritten` (PB443), and a reference-modified operand is refused (data-name-2 is a data-name).
The note's "screen section's ScreenSubscriptArity re-implements" claim did not hold: there is one
`ScreenSubscriptArity` (ReferenceResolver), and the two other `SubscriptArity` comparisons (lines ~1617/1673) are
silent-null probe paths, not diagnosing screens.

**Goldens:** `tests/conformance/2002/pb1016_constant_length_subscripts` (K1=4 K2=8 K3=4 K4=24, from §13.10.4 GR6 →
the LENGTH function); negatives `pb1016-constant-length-subscript-on-non-table` (COBOLNET2096) and
`pb1016-constant-length-subscript-count` (COBOLNET2097), reject-at 2002 2014 2023. **Rows:** SR-8.4.2.3.3-2
re-witnessed CONFORMS; witness-only on SR-8.4.2.3.3-3 and -5 (batch `w54i/PB1016/batch.json`, GAP unchanged).
SR-13.10.3-3 stays GAP: its data-name-1 half is the BYTE-LENGTH OF form, still staged loud (COBOLNET0899).
