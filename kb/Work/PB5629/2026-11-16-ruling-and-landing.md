**Ruling: reading B.** The sentence of §2023:8.4.2.1 ("The same name shall not be used both as the name of an item possessing the global attribute and as the name of any other data item described in the source element that describes that global data item", `cite.py --check` OK; §1985:IV.4.3.8.1 SR4 says it of the same data-name, OK) concerns the ITEM THAT POSSESSES the global attribute: the entry that carries the GLOBAL clause, or whose file description does, which is the record. The data-names subordinate to it are global NAMES ("All data-names subordinate to a global name are global names", §2023:13.18.27.4 GR1; §1985:X.4.6.4 GR1, both OK), a matter of scope. The standard keeps the two apart: §2023:13.18.27.4 GR3 ("it is only the subject of that REDEFINES clause that possesses the global attribute", OK; §1985:X.4.6.4 GR3, OK) and §2023:8.4.6.2.3 ("If a data item possessing the global attribute includes a table described with an index-name", OK; §1985:X.1.3.8.3, OK) put the attribute on the entry, and §1985:X.1.3.8.2 GR1 applies "the normal rules for qualification and any other rules for uniqueness of reference" to a global name, which presupposes same-named global subordinates told apart by qualifiers (§2023:8.4.2.2.1: "Identical user-defined names may be specified in a source unit"). The text does not settle the question outright; under CLAUDE.md rule 1 the tiebreak is the implementations (GnuCOBOL and IBM Enterprise COBOL accept the shape; it compiled on main before PB5150) and the common real-program shape the PB5150 reviewer named.
