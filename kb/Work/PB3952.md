# PB3952 — FUNCTION NUMVAL-F rejects the text "1.5E2" (no sign in the exponent) that GnuCOBOL accepts

**Sites:** `src/WiseOwl.Cobol.Runtime/Intrinsics/CobolIntrinsics.Exact.cs` (`NumvalFDec`, `NvfScan` - unchanged), `tests/WiseOwl.Cobol.Tests.Unit/TestNumvalFPositionTests.cs` (`Native_PositionLegs`), `docs/CONFORMANCE.md` (the PB3952 NUMVAL-F exponent-sign determination beside PB256)

`FUNCTION NUMVAL-F` of a text GnuCOBOL accepts but TEST-NUMVAL-F rejects, `"1.5E2"` (an exponent with no sign), answers
0 here. The standard's NUMVAL-F text format requires the sign of the exponent (adjudicate: the TEST-NUMVAL-F rule and the
NUMVAL-F argument rule must agree; GnuCOBOL's acceptance is a latitude question, not authority). First recorded as a "lead
for the registrar" in PB3514's body.

## Acceptance
- Re-derive the argument format from the spec (`spec-lookup`, cite.py), decide whether the text is invalid (then both
  functions agree on the refusal) or valid (then TEST-NUMVAL-F accepts it); golden for the decided answer.

## Resolution 2026-10-27 (wave 20261728, group E)

**Verdict: not a defect; the standard decides.** Re-probed on a fresh build (`p1.cob`, `p2.cob` under the wave scratch):
`NUMVAL-F("1.5E2")` answers 0 in a fixed-point receiver, a COMP-2 receiver and DISPLAY, and `TEST-NUMVAL-F("1.5E2")` is 5;
the signed control `"1.5E+2"` is 150. Both functions ride the one `NvfScan`, so they already agree on the refusal (the note's
"answers 0 here" is the DOC-A.1-90 substituted result of a refused argument, not a mis-parse). Expected: ISO 15.69.3 r1's
figure makes the exponent sign a required choice (cite.py: OK 15.69.3 1), so the text violates the argument rules; 15.3 r14
sets EC-ARGUMENT-FUNCTION and leaves the unchecked result to the implementor, which DOC-A.1-90 fixes as the zero value for
every intrinsic. GnuCOBOL's leniency is not adopted: rule 1's GnuCOBOL tier settles latitude only where ISO leaves a choice,
and making NUMVAL-F read a text TEST-NUMVAL-F (15.95.1) must refuse would split the two functions. Pinned by
`conformance-suite/cases/15.69.3-Argument-rules/pb3952_numval_f_exponent_sign_required` and two new `TestNumvalFPositionTests`
rows; determination written in docs/CONFORMANCE.md beside PB256. No compiler code changed.
