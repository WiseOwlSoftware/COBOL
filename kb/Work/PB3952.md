# PB3952 — FUNCTION NUMVAL-F rejects the text "1.5E2" (no sign in the exponent) that GnuCOBOL accepts

**Sites:** `src/WiseOwl.Cobol.Runtime/Intrinsics/CobolIntrinsics.Exact.cs` (`NumvalFDec`)

`FUNCTION NUMVAL-F` of a text GnuCOBOL accepts but TEST-NUMVAL-F rejects, `"1.5E2"` (an exponent with no sign), answers
0 here. The standard's NUMVAL-F text format requires the sign of the exponent (adjudicate: the TEST-NUMVAL-F rule and the
NUMVAL-F argument rule must agree; GnuCOBOL's acceptance is a latitude question, not authority). First recorded as a "lead
for the registrar" in PB3514's body.

## Acceptance
- Re-derive the argument format from the spec (`spec-lookup`, cite.py), decide whether the text is invalid (then both
  functions agree on the refusal) or valid (then TEST-NUMVAL-F accepts it); golden for the decided answer.
