# PB4724 — exit 16 holds a branch on a guess, and its stop line states the guess as a fact

**Sites:** `scripts/orchestrator/enqueue.py` (`open_pull_requests`, `driver_file_holders`, `land`)

`python scripts/orchestrator/enqueue.py land notes-w1868-leads --lane clerk` stopped with:

`=== ENQUEUE: DRIVER FILE QUEUED — #1161 changes kb/Work/PB4617.md, kb/Work/PB4701.md, kb/Work/PB4702.md, …, which the branch changes too and the merge queue merges without the merge drivers: nothing stamped or queued; landed again once the open pull request(s) merge (notes-w1868-leads) ===`

PR #1161 does not change any of those notes. Of the 177 files `gh pr diff 1161 --name-only` lists, the only one under
`kb/Work/` is `kb/Work/PB4677.md`, and PB4701 did not exist when that pull request was opened.

The cause is `driver_file_holders`. `gh pr list --json files` lists at most 100 files (`FILES_LISTED`), so a pull request
at that length may have been cut off, and the function holds the branch for ALL of its driver-covered files. That wait
is safe. Two things are wrong with it:

1. The stop line reports the guess as a fact, so the reader goes looking for an overlap that does not exist. The clerk
   that hit this reported it as unexplained.
2. The wait is avoidable. `gh pr diff <n> --name-only` lists the whole pull request, so a list that was cut off can be
   read in full and the branch held only for a file the pull request really shares. Any large pull request now stops
   every notes branch until it merges.

The fix reads the full list for a pull request at `FILES_LISTED` files, and the stop line names only files it knows are
shared. Its self-test plants a pull request of 100 listed files that does not share the branch's note.
