# PB5070 - at --std 85 the file-description clauses VALUE OF, LABEL RECORDS, DATA RECORD and PADDING CHARACTER are word-eating grammar rules no binder reads: a missing implementor-name, an IGNORED label, an undefined or subscripted data-name, a two-character padding literal all compile clean

**Sites:** `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolData.g4#valueOfClause`, `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolData.g4#labelRecordsClause`, `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolData.g4#dataRecordsClause`, `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolIO.g4#paddingCharacterClause`; the only readers are `src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs#VisitValueOfClause`, `src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs#VisitPaddingCharacterClause` and `src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs#VisitDataRecordsClause`, which gate the clauses at 2002 and bind nothing.

**Mechanism.** The grammar admits each of these clauses as a loose word list (for example `VALUE OF (cobolWord | literal | IS)+` and `LABEL ... (STANDARD | OMITTED | cobolWord+)`), comments them "semantically inert", and no binder resolves their operands or applies the 1985 operand rules. So the 1985 general formats (an implementor-name-1 before every operand, no IGNORED label) and syntax rules (one-character nonnumeric PADDING literal, an alphanumeric one-character Working-Storage PADDING data-name, a DATA RECORD name with an 01 record description, a VALUE OF data-name that is unsubscripted, not an index item and in Working-Storage) are never asked at --std 85.

**Found by.** The 1985 `--std=85` draft triage (kb/Work PB4995 item 3): each rule below is a conformance-suite draft that did not MATCH at `--std 85`, and its adjudicator decided COMPILER-DEFECT. Harm and observed text are the records'; nothing here was re-derived.

**Inventory.** The traceability inventory carries no 1985 rows yet, so `inventory_rows` is empty; the rows this note covers are the 1985 rule ids listed below (catalog `docs/rearchitecture/spec-rule-catalog-1985.json`).

**Rules (7; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-FMT-VII.3.9.2` - `§1985:IV.2.1.4` (record harm: under-rejects, slice-01): §1985:VII.3.9.2 prints the clause as `<u>VALUE</u> <u>OF</u> { implementor-name-1 IS { data-name-1 | literal-1 } } ...` (the transcription's line: "VALUE OF ┤ implementor-name-1 IS ┤ ... ├ ├ …"): implementor-name-1 stands inside the braces before every data-name-1 or literal-1, and §1985:IV.2.1.4 says "When braces, { } , enclose a portion of a general format, one of the options contained within the braces must be either explicitly specified or implicitly selected." `VALUE OF "F1DATA"` has no implementor-name-1, so it does not match the general format; a program holding it is not a conforming source program (§1985:I.1.6: "A conforming source program is one which does not violate the explicitly stated provisions and specifications of Standard COBOL."). The draft is right.
- `1985-FMT-XIII.3.2.2` - `§1985:IV.2.1.4` (record harm: under-rejects, slice-01): §1985:XIII.3.2.2 prints the clause of a report file's FD as `[ <u>LABEL</u> { <u>RECORD</u> IS | <u>RECORDS</u> ARE } { <u>STANDARD</u> | <u>OMITTED</u> } ]` (the same format as §1985:VII.3.6.2), and §1985:IV.2.1.4 says "When braces, { } , enclose a portion of a general format, one of the options contained within the braces must be either explicitly specified or implicitly selected." IGNORED is neither option, so `LABEL RECORDS ARE IGNORED` does not match the general format and the program is not a conforming source program (§1985:I.1.6: "A conforming source program is one which does not violate the explicitly stated provisions and specifications of Standard COBOL."). The draft is right.
- `1985-SR-VII.2.7.3-1` - `§1985:VII.2.7.3 SR1` (record harm: under-rejects, slice-06): §1985:VII.2.7.3 SR1: "Literal-1 must be a one-character nonnumeric literal." The draft reads the rule correctly: `PADDING CHARACTER IS "AB"` gives literal-1 two characters, so the program violates a syntax rule and is not a conforming source program (§1985:I.1.6: "A conforming source program is one which does not violate the explicitly stated provisions and specifications of Standard COBOL."). The control (`PADDING CHARACTER IS "*"`) conforms and compiles.
- `1985-SR-VII.2.7.3-3` - `§1985:VII.2.7.3 SR3` (record harm: under-rejects, slice-06): §1985:VII.2.7.3 SR3: "Data-name-1 must be defined in the Data Division as a one-character data item of the category alphanumeric and must not be defined in the Communication Section, the File Section, or the Report Section." The draft reads the rule correctly: `PADDING CHARACTER IS PAD-CHAR` names `01 PAD-CHAR PIC X(2)`, a two-character item, so the program violates the syntax rule (§1985:I.1.6: "A conforming source program is one which does not violate the explicitly stated provisions and specifications of Standard COBOL."). The rule relates two places, the clause (line 8) and the item's description (line 14, the draft's mark); the standard gives a diagnostic no line, and the compiler reports at neither. The control (`PIC X`) conforms and compiles.
- `1985-SR-VII.3.5.3-1` - `§1985:VII.3.5.3 SR1` (record harm: under-rejects, slice-06): §1985:VII.3.5.3 SR1: "Data-name-1 is the name of a data record and must have an 01 level-number record description, with the same name, associated with it." The draft reads the rule correctly: `DATA RECORD IS OUT-FLD` names an 02-level item of the record OUT-REC, and no 01-level record description is named OUT-FLD, so the program violates the syntax rule (§1985:I.1.6: "A conforming source program is one which does not violate the explicitly stated provisions and specifications of Standard COBOL."). The clause is obsolete in 1985, not deleted, so its rules hold. The control (`DATA RECORD IS OUT-REC`) conforms and compiles.
- `1985-SR-VII.3.9.3-1` - `§1985:VII.3.9.3 SR1` (record harm: under-rejects, slice-06): §1985:VII.3.9.3 SR1: "Data-name-1 should be qualified when necessary, but cannot be subscripted, nor can data-name-1 be an item described with the USAGE IS INDEX clause." The draft reads the rule correctly: `VALUE OF ID IS WS-IX` names `01  WS-IX USAGE IS INDEX.`, so the program violates the syntax rule (§1985:I.1.6: "A conforming source program is one which does not violate the explicitly stated provisions and specifications of Standard COBOL."). The clause is obsolete in 1985, not deleted, so its rules hold. Implementor-name-1 (`ID`) is the implementor's to define, and the compiler accepts it: the control (`VALUE OF ID IS WS-NAME`, a PIC X(8) Working-Storage item) compiles.
- `1985-SR-VII.3.9.3-2` - `§1985:VII.3.9.3 SR2` (record harm: under-rejects, slice-06): §1985:VII.3.9.3 SR2: "Data-name-1 must be in the Working-Storage Section." The draft reads the rule correctly: `VALUE OF FILE-ID IS F1-REC` names the file's own record, an item of the File Section, so the program violates the syntax rule (§1985:I.1.6: "A conforming source program is one which does not violate the explicitly stated provisions and specifications of Standard COBOL."). Implementor-name-1 (`FILE-ID`) is the implementor's to define, and the compiler accepts it: the control (`VALUE OF FILE-ID IS WS-NAME`, a Working-Storage item) compiles and runs.
