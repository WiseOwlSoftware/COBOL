# Cell-lane VarGroupWindow WRITE arms are not gated on CurrentExtentImageCapable (read arm is)

Found by the train 1021 review of cluster B2 (PB1042, a9c029f6d); verified 2026-10-05 against the train1021 build.

## Code site
`src/Cobol.Net.Compiler/CodeGen/Roslyn/PlaceRenderer.cs`:
- `CellVarContiguous` (the READ arm) is gated: `v.Item.CurrentExtentImageCapable ? CellVarContiguous(...) : LoudValue(...)`.
- The three WRITE arms are not: `Write` (`RedefViewPlace { Coding: VarGroupWindow g }` -> `CellVarStoreContiguous`),
  `WriteVarGroupImage` (-> `CellVarStoreCarrier`), `WriteVarGroupContiguous` (-> `CellVarStoreContiguous`, gated only on
  `!HasOdoOnOrBeneath`). The record-struct lane's twins fall to `_ when !group.Item.CurrentExtentImageCapable => LoudStmt`.
  The sending-side `ReadVarGroupImage` arm (`CellVarCarrier`, `when maximum || odo is ""`) is also ungated.

## The shape the asymmetry admits
A cell-backed (EXTERNAL or ADDRESS-OF) group whose dynamic-capacity table's ELEMENT holds a component of its own (a
nested dynamic table or a dynamic-length item). Its fixed run does not carry the per-element components, so a write
that decomposes a contiguous image over `DynFixedAt`/`DynTable` cannot place the nested components.

## Reachability, measured (repros under E:/COBOL-coord/scratch/train1021/verify/B/b2/)
- `v23a.cob` MOVE alphanumeric literal TO G: refused at compile time, COBOLNET1931 (§14.9.25.3 SR9, §8.5.1.12.1).
- `v23e.cob` READ ... INTO G: refused, COBOLNET1931 (the implicit MOVE of §14.9.30.4 GR4 b)).
- `v23g.cob` / `v23h.cob` / `v23i.cob` MOVE G1 TO G2 between compatible groups (cell->cell, struct->struct,
  struct->cell): the SENDING side is loud first ("the sending operand of a variable-length group MOVE ... cannot
  compose"), so the receiving write arm is never reached with a value.
- `v23c.cob` / `v23d.cob` DISPLAY G: both lanes loud (consistent).
No observed wrong answer. The gap is latent: the write arms would compose a wrong image only if some statement
delivers a value to them, and every probed statement is refused or loud upstream.

## Why it is a note and not a fix
§8.5.1.11.2 / §14.9.25.4 do define the result for a compatible variable-length group move, so the expected answer
exists; what is missing is an observable path. The decision is whether to (a) gate the three write arms on the same
capability as the read arm (one-mechanism symmetry; makes the "named loud" explicit on both sides), or (b) teach the
cell composers the per-element components so both sides compose (closes DOC-A.1-57's residue for cells). (a) is
~3 changed lines; (b) is the redesign PB1042's report calls "Residue, not a defect". Pick with the owner of DOC-A.1-57.
