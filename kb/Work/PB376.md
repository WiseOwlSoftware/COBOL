# PB376 — a drift test that races itself across agents

Found by witness cluster B2 while attributing a FULL-Unit red: `GrammarDiagramGeneratorDriftTests` failed in the
fleet run and **passed in isolation**, twice.

## The mechanism

`scripts/gen-grammar-diagrams.ps1 -Check` builds its comparison tree at the FIXED path
`%TEMP%\cobolnet-grammar-check` and, at the end, `Remove-Item -Recurse -Force`s it. The path carries no process
id, no run id and no random suffix, so two concurrent runs share one directory: the second run's generator reads
files the first run's cleanup is deleting under it, and whichever loses reports a spurious mismatch.

⛔ **This is the shape a gate must not have.** The failure is indistinguishable, at the verdict line, from a real
grammar-diagram drift — so the honest reading of a red is "investigate", and the investigation costs a full
isolated re-run every time. It also fails in the direction that WASTES trust rather than granting it, which is
the better of the two directions but still a defect: a test that cannot say what it measured is not evidence
(feedback_gate_on_the_verdict_line).

## The fix shape (not done here)

Give the check a per-run directory and delete only what it created:
`Join-Path ([IO.Path]::GetTempPath()) ("cobolnet-grammar-check-" + [guid]::NewGuid())`, or
`New-TemporaryFile`-style creation, with the cleanup scoped to that path. ⚠ Then prove it: run two `-Check`
invocations concurrently and assert both pass — the race must be seen NOT to fire, since a fix to a
concurrency defect that is only ever tested serially has not been tested at all
(feedback_prove_the_watchdog_fails).

⚠ **Sweep for siblings.** Any other script under `scripts/` that composes a fixed `%TEMP%` path and recursively
deletes it has the same defect; grep for `cobolnet-` under a temp-path expression before calling this closed.

## Registrar verification 2026-09-06 — re-found by the PB714 implementer, and PB748 was NOT opened for it

The PB714 fix-lane implementer reported this as a new defect (its "new defect (c)") and an id (PB748) was
allocated for it. **The id is left unused: this note already owns the symptom, the mechanism and the fix shape.**
Recorded here so the third finder does not open a fourth.

**What the second finding adds.** A concrete failure string and a second observation context — two agents running
`GrammarDiagramGeneratorDriftTests.Generator_RunsClean` in different worktrees at the same time, one of which
died with:

```
Exception calling "WriteAllText" … Could not find a part of the path
'E:\Temp\cobolnet-grammar-check\CobolData.md'
```

That is the OTHER side of the race this note already describes: not "reads files the cleanup is deleting" but
"writes into a directory the other run's `Remove-Item -Recurse -Force` has just removed". Same shared path, same
two lines of script, opposite loser.

**Re-verified against main (`89555b09`) — the mechanism is unchanged.** `scripts/gen-grammar-diagrams.ps1:37-43`:

```powershell
$outDir = if ($Check) { Join-Path ([System.IO.Path]::GetTempPath()) 'cobolnet-grammar-check' }
          else        { Join-Path $repo 'kb/Grammar' }
...
if (Test-Path $outDir) { Remove-Item -Recurse -Force $outDir }
New-Item -ItemType Directory -Path $outDir | Out-Null
$tmp = Join-Path ([System.IO.Path]::GetTempPath()) ("ccf-" + [guid]::NewGuid().ToString('N'))
```

⛔ **The fix this note prescribes is already written on the NEXT LINE of the same script.** `$tmp` (`:43`) — the
per-fragment EBNF/markdown scratch directory — is already `GetTempPath() + "ccf-" + [guid]::NewGuid()`. `$outDir`
(`:37`) is the same author, two statements earlier, without the GUID. So this is not a design question and never
was; it is one expression that did not get the treatment its neighbour got.

**Consumer, and why the red lands somewhere else.** `tests/Cobol.Net.Tests.Unit/GrammarDiagramGeneratorDriftTests.cs:26`
shells the script out under `pwsh -File "…" -Check` and asserts on its exit code at `:39`. The colliding agent
does not own the script, the grammar, or the change under test — it just gets a red wave-local gate, which is
exactly the "manufactures a RED in an unrelated agent's transcript" cost this note's ⛔ paragraph names.

**Relation to the two other notes on this one test — three notes, three distinct causes, and they should not be
merged:**

- **This note (PB376)** — the shared `$outDir` path. A *cross-process* collision; deterministic given two
  concurrent runs.
- **[[PB588]]** — the 180-second wall-clock assertion at `:37` in a 5,300-test parallel suite. A *load* failure;
  no second process required.
- **[[PB736]]** — filed 2026-09-06 from the PB338 report on the SAME wall clock as PB588, with the fix shape
  (split the deadline from the drift assertions, kill the child tree on the way out) and the stderr/stdout
  `ReadToEnd` deadlock hazard worked out. ⚠ **PB736 and PB588 appear to be the same defect found twice** — that
  is a register-hygiene question for whoever lands either, not a claim resolved here.

A fix to any one of the three leaves the other two able to red the same test, so the lander that takes this
should read all three before deciding what "fixed" means for `Generator_RunsClean`.

**The proof obligation stands unchanged** (`feedback_prove_the_watchdog_fails`): run two `-Check` invocations
concurrently and assert both pass. Neither of the two independent sightings was reproduced deliberately — both
were collisions noticed after the fact — so the race has still never been made to fire on demand, and a
concurrency fix tested only serially has not been tested.
