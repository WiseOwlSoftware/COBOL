# PB376 — a drift test that races itself across agents

Found by witness cluster B2 while attributing a FULL-Unit red: `GrammarDiagramGeneratorDriftTests` failed in the
fleet run and **passed in isolation**, twice.

## The mechanism

`scripts/gen-grammar-diagrams.ps1 -Check` builds its comparison tree at the FIXED path
`%TEMP%\cobolnet-grammar-check` and, at the end, `Remove-Item -Recurse -Force`s it. The path carries no process
id, no run id and no random suffix, so two concurrent runs share one directory: the second run's generator reads
files the first run's cleanup is deleting under it, and whichever loses reports a spurious mismatch.

⛔ **This is the shape a gate must not have.** The failure is indistinguishable, at the verdict line, from a real
grammar-diagram drift — so the honest reading of a red is "investigate", and the investigation costs a full
isolated re-run every time. It also fails in the direction that WASTES trust rather than granting it, which is
the better of the two directions but still a defect: a test that cannot say what it measured is not evidence
(feedback_gate_on_the_verdict_line).

## The fix shape (not done here)

Give the check a per-run directory and delete only what it created:
`Join-Path ([IO.Path]::GetTempPath()) ("cobolnet-grammar-check-" + [guid]::NewGuid())`, or
`New-TemporaryFile`-style creation, with the cleanup scoped to that path. ⚠ Then prove it: run two `-Check`
invocations concurrently and assert both pass — the race must be seen NOT to fire, since a fix to a
concurrency defect that is only ever tested serially has not been tested at all
(feedback_prove_the_watchdog_fails).

⚠ **Sweep for siblings.** Any other script under `scripts/` that composes a fixed `%TEMP%` path and recursively
deletes it has the same defect; grep for `cobolnet-` under a temp-path expression before calling this closed.
