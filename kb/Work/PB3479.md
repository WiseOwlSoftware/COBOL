# PB3479 — the converted three-organization theories declare an illegal OPEN EXTEND

Low, non-blocking lead from the branch review of PB3471 (`E:\COBOL-coord\scratch\reports\w1136c-PB3471-report.md`, `## Review findings` R1-1).

**Mechanism.** `FileHarness.Register` gives keyed connectors the default `KeyedAccess.Dynamic`. The deleted private `RegisterOrg` and `Register` copies passed access mode 0 (sequential). After the conversion every OPEN EXTEND cell in `FileLockPostureDriftTests`, `SharingRefusalStatusTests`, `PermanentErrorOutranksRecordLockTests` and `RunUnitFileLockDriftTests` opens a RELATIVE or INDEXED file declared with dynamic access. ISO 1989:2023 section 14.9.27.3 SR2 ("The EXTEND phrase shall be specified only if the access mode of the file connector referenced by file-name-1 is sequential", checked OK by the reviewer) forbids that declaration, and the compiler rejects it (StatementValidation.cs:1541). The cells therefore exercise a state no program can reach, and the Table 19 and '61' answers they pin are measured on the wrong declaration.

**Fix shape.** Give `FileHarness.Register` an access-mode argument (or pass sequential for the EXTEND cells) so the theories use sequential access wherever the deleted copies did. Sweep the other FileHarness callers for the same default.

**Sites:**
- `tests/_shared/FileHarness.cs`
- `tests/WiseOwl.Cobol.Tests.Unit/FileLockPostureDriftTests.cs`
- `tests/WiseOwl.Cobol.Tests.Unit/SharingRefusalStatusTests.cs`
- `tests/WiseOwl.Cobol.Tests.Unit/PermanentErrorOutranksRecordLockTests.cs`
- `tests/WiseOwl.Cobol.Tests.Unit/RunUnitFileLockDriftTests.cs`

## Landing

Re-probed on this build. `cobol.exe` on a RELATIVE file declared `ACCESS MODE IS DYNAMIC` with `OPEN EXTEND F` answers
`COBOL2372 ... EXTEND requires sequential access (ISO §14.9.27.3 SR2)`, so the premise held: the harness's default
(`KeyedAccess.Dynamic`) put every converted EXTEND cell on a declaration no program makes. Which cells: not four classes but
five. `PermanentErrorOutranksRecordLockTests` opens only INPUT and I-O (legal under DYNAMIC), so the note's fourth site had no
EXTEND cell and needs no change. The one the note missed is `RelativeEngineTests` (`Opens`: I-O, EXTEND and OUTPUT crossed
with two sharing modes, three theories over `FileHarness.Register`).

Fix (CLAUDE.md rules 4 and 5, one rule in one place): `FileHarness.AccessFor(FileOpenMode)` states the rule once (EXTEND is
sequential access's, every other mode keeps DYNAMIC) and `FileHarness.Open(reg, name, mode)` fails a test that opens EXTEND over
a connector it registered with RANDOM or DYNAMIC access. `Register` records each connector's host and declared access for that
check. Every theory that crosses open modes (`FileLockPostureDriftTests` x4, `RunUnitFileLockDriftTests`,
`SharingRefusalStatusTests`, `RelativeEngineTests` x3) declares `access: FileHarness.AccessFor(mode)` per connector and opens
through `FileHarness.Open`; `IndexedEngineTests`' private copy of the same conditional now calls `AccessFor`. `RegisterAndShare`
takes the open mode as a required argument, so a new caller must state it. `FileHarnessExtendDeclarationTests` pins `AccessFor`
against the SR2 text, opens every organization x mode on the declaration it gives, and shows the guard failing RELATIVE and INDEXED
connectors declared RANDOM or DYNAMIC. Not changed on purpose: `Table20WriteOpenModeTests` opens a DYNAMIC and a RANDOM connector
EXTEND to test the runtime's own refusal ('48') of a state the compiler never produces.
