# PB5201 - a WRITE without ADVANCING before a file's first ADVANCING write is not advanced one line: SequentialConnector.WriteRecord applies the automatic advance only when SupportsVerticalPositioning already holds

**Sites:**

- `src/WiseOwl.Cobol.Runtime/IO/SequentialConnector.cs` (`WriteRecord`, `SupportsVerticalPositioning`, `WriteAdvancingRecord`, `AdvancingDeclared`)
- `src/WiseOwl.Cobol.Runtime/IO/FileRegistry.cs` (`Register`), `src/WiseOwl.Cobol.Runtime/IO/CobolFile.cs` (`Register`)
- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/SequentialIoBinder.cs` (`BindWrite`), `src/WiseOwl.Cobol.Compiler/Binding/Model/FileModel.cs` (`WrittenWithAdvancing`)
- `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/SequentialIoEmitter.cs` (`EmitFileRegistration`), `src/WiseOwl.Cobol.Compiler/CodeGen/Roslyn/RuntimeApi.cs` (`FileRegister`)

**Mechanism.** §1985:VII.4.7.4 GR16: "If the ADVANCING phrase is not used, automatic advancing will be provided by the implementor to act as if the user had specified AFTER ADVANCING 1 LINE." `SequentialConnector.WriteRecord` reroutes a WRITE without the phrase to `WriteAdvancingRecord` only when `SupportsVerticalPositioning` holds (a LINAGE clause, or an ADVANCING phrase already written since the OPEN), so in a file that mixes the two the plain WRITEs before the first ADVANCING one are bare records: AAABBB share one line and no line precedes them. kb/Work PB1027 (landed) left this case as an owner question it did not decide; docs/CONFORMANCE.md section 4 states it as a consequence of that determination.

Verdict, harm, evidence, repro and observed text are the records'; the rows' verdicts are recorded on another branch.
