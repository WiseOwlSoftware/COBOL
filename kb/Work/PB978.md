Filed 2026-09-22 by **REGISTRAR #11** from wave 46 group L's two leads (PB853 + PB885 implementer report; lander
leads L1 and L2 — one mechanism: a private first-match lookup where the one counting resolver belongs; the same root
kb/Work PB489 fixed for LINAGE). **Both re-run on this registrar's own build of main `6871b6e10`** (0/0).

## Reproduced

- `reg11/l1.cob`:

  ```cobol
         01 A.
            05 G.
               10 K PIC X VALUE "A".
         01 B.
            05 G.
               10 K PIC X VALUE "B".
         REPORT SECTION.
         RD RPT CONTROL IS K OF G.
  ```

  → compiles clean, `INITIATE` / `GENERATE` / `TERMINATE` run, prints `DONE`. `K OF G` names two items.
- `reg11/l2.cob`: `01 GA. 05 CNT PIC 9 VALUE 2.` `01 GB. 05 CNT PIC 9 VALUE 5.`
  `01 T. 05 E PIC X OCCURS 1 TO 9 DEPENDING ON CNT.` then `DISPLAY "LEN=" FUNCTION LENGTH(T)` → **`LEN=2`**: bound
  silently to GA's CNT.

## Rule

- `python scripts/spec/cite.py --check 8.4.2.2.3 "uniqueness shall be established through a sequence of qualifiers that precludes any ambiguity of reference"` → OK §8.4.2.2.3 1)

Both sources are non-conforming and must be refused with the ambiguous-reference diagnostic the PROCEDURE DIVISION
already gives (COBOLNET1639 "does not uniquely identify"). The harm is silent: the program runs on a data item the
author may not have meant, and nothing says which.

## Code sites and what the fixer owes

- `src/Cobol.Net.Compiler/Binding/DataBinder.Reports.cs:2711` `private DataItem? LookupQualified(string name,
  IReadOnlyList<string> qualifiers)` — callers at :2234 (CONTROL), :2288 (SOURCE/SUM data), :2434 (SUM addend).
- `src/Cobol.Net.Compiler/Binding/DataBinder.Odo.cs:202` `dep = cands[0];` (unqualified fallback).
- The counting resolver is `DataBinder.QualifiedCandidates` (callers at `DataBinder.cs:1738/1787/1857`). Delete the
  private twin and route every DATA DIVISION name resolution through ONE resolver that returns
  none / one / ambiguous, and add a drift test that no binder file indexes a candidate list with `[0]` after a
  qualified lookup. Sweep the other data-division name operands (RENAMES, REDEFINES object, KEY IS, ASSIGN USING,
  LINAGE — PB489's arm — VALIDATE operands, the SAME AS / TYPE targets). PB919 (index-names) is the same obligation on
  a different name class.

## Landed (wave 51 group G)

Re-probed on this worktree's build (base train-48 head `0abe2c80f`): `reg11/l1.cob` (`RD RPT CONTROL IS K OF G`
over `A.G.K` and `B.G.K`) printed `DONE`; `reg11/l2.cob` (`DEPENDING ON CNT` over `GA.CNT` and `GB.CNT`) printed
`LEN=2`. After: both are **COBOLNET1639** "does not uniquely identify a data item — 2 declarations match"
(§8.4.2.2.3 SR1).

- Rule: `cite.py --check 8.4.2.2.3 "uniqueness shall be established through a sequence of qualifiers that precludes
  any ambiguity of reference"` → OK §8.4.2.2.3 1); `--check 8.4.2.2.1 "the names of any group items superordinate to
  both the data-name and the subject of the data description entry clause are used as implicit qualifiers"` → OK
  §8.4.2.2.1 5) (the implicit qualification that makes a same-group counter the one meant).
- Fix — a TYPE, not a comment: `QualifiedCandidates` returns `DataNameCandidates`, which has no indexer and no
  enumeration (count, `Where`, `Single`); `SubtreeCandidates` is its record-confined twin; `EntryClauseCandidates`
  applies §8.4.2.2.1 rule 5 for a data description entry clause (OCCURS DEPENDING ON, SAME AS); and
  `UniqueOrReportAmbiguous` is the ONE ambiguity verdict (COBOLNET1639; `--permissive` warns and takes the first,
  the procedure division's R33 disposition). Deleted: the report binder's private `LookupQualified` twin, the
  ODO `FindInSubtree` + `cands[0]` fallback, `FindDescendantOrSelf`, and SAME AS's private `SameAsQualifiersMatch`
  (which cited §8.4.3.2 for the ambiguity). Siblings fixed the same way: RECORD KEY / ALTERNATE RECORD KEY
  (`FirstOrDefault … ?? cands[0]`), ASSIGN … USING (`.FirstOrDefault()`), RENAMES (qualifiers were DISCARDED as
  "redundant inside the owning record" — `RENAMES A OF G2` bound G1's A), SAME AS; LINAGE / FILE STATUS / RELATIVE
  KEY / RECORD DEPENDING already counted and now share the verdict. `DataNameResolutionDriftTests` (Unit) pins
  the type's shape, the single permissive reader, and no `[0]` off a raw candidate list in the data binder.
- Goldens: `conformance:85/pb978_data_division_qualified_operands` (qualified ODO and RENAMES bind the SECOND
  declaration); `conformance:negative/pb978-odo-depending-ambiguous`,
  `conformance:negative/pb978-report-control-ambiguous` (reject-at 85 2002 2014 2023, COBOLNET1639).
