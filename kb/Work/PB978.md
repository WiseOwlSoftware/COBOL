Filed 2026-09-22 by **REGISTRAR #11** from wave 46 group L's two leads (PB853 + PB885 implementer report; lander
leads L1 and L2 — one mechanism: a private first-match lookup where the one counting resolver belongs; the same root
kb/Work PB489 fixed for LINAGE). **Both re-run on this registrar's own build of main `6871b6e10`** (0/0).

## Reproduced

- `reg11/l1.cob`:

  ```cobol
         01 A.
            05 G.
               10 K PIC X VALUE "A".
         01 B.
            05 G.
               10 K PIC X VALUE "B".
         REPORT SECTION.
         RD RPT CONTROL IS K OF G.
  ```

  → compiles clean, `INITIATE` / `GENERATE` / `TERMINATE` run, prints `DONE`. `K OF G` names two items.
- `reg11/l2.cob`: `01 GA. 05 CNT PIC 9 VALUE 2.` `01 GB. 05 CNT PIC 9 VALUE 5.`
  `01 T. 05 E PIC X OCCURS 1 TO 9 DEPENDING ON CNT.` then `DISPLAY "LEN=" FUNCTION LENGTH(T)` → **`LEN=2`**: bound
  silently to GA's CNT.

## Rule

- `python scripts/spec/cite.py --check 8.4.2.2.3 "uniqueness shall be established through a sequence of qualifiers that precludes any ambiguity of reference"` → OK §8.4.2.2.3 1)

Both sources are non-conforming and must be refused with the ambiguous-reference diagnostic the PROCEDURE DIVISION
already gives (COBOLNET1639 "does not uniquely identify"). The harm is silent: the program runs on a data item the
author may not have meant, and nothing says which.

## Code sites and what the fixer owes

- `src/Cobol.Net.Compiler/Binding/DataBinder.Reports.cs:2711` `private DataItem? LookupQualified(string name,
  IReadOnlyList<string> qualifiers)` — callers at :2234 (CONTROL), :2288 (SOURCE/SUM data), :2434 (SUM addend).
- `src/Cobol.Net.Compiler/Binding/DataBinder.Odo.cs:202` `dep = cands[0];` (unqualified fallback).
- The counting resolver is `DataBinder.QualifiedCandidates` (callers at `DataBinder.cs:1738/1787/1857`). Delete the
  private twin and route every DATA DIVISION name resolution through ONE resolver that returns
  none / one / ambiguous, and add a drift test that no binder file indexes a candidate list with `[0]` after a
  qualified lookup. Sweep the other data-division name operands (RENAMES, REDEFINES object, KEY IS, ASSIGN USING,
  LINAGE — PB489's arm — VALIDATE operands, the SAME AS / TYPE targets). PB919 (index-names) is the same obligation on
  a different name class.
