# PB903 — OPEN — the transcription defects two implementers found while doing something else

Sources: the `PB388` report, "New defects" item 4; the `PB427` report, "New defects" item 2.

## Defect 1 — §14.9.18.3 SR4's sub-items lost their indentation

`cite.py` parses the rule list by INDENTATION, so a sub-item written flush with its parent is read as the
parent. The observable symptom the PB388 implementer recorded:

```
$ python scripts/spec/cite.py --check 14.9.18.3 "Identifier-1 shall not be a universal object reference"
  → answers 4) a)   where the text is 4) d)
```

**The control is in the standard itself**: the EXIT twin at §14.9.14.3 SR5 carries the same sub-item
structure WITH indentation, so this is a transcription slip and not a property of the clause.

Consequence: any selector keyed on sub-item paths inherits the wrong path, and a citation validated with
`--check` still prints the wrong sub-ordinal — which is precisely the propagation route CLAUDE.md rule 1
names. Nothing in this repository is wrong; the repair belongs in the `specs` submodule.

## Defect 2 — §8.5.3.1 reads "the same relative byte pr bit position"

```
$ grep -n "relative byte pr bit" specs/ISO_COBOL.md
```

An OCR slip for "or". The meaning is unambiguous and every quotation of it in this repository is verbatim
(so `--check` stays honest), which is why this is MINOR — but a verbatim quotation of a corrupt sentence is
a corrupt sentence in a diagnostic, and the repair is one character.

## Why one note for two

Both are repairs to the SAME artefact (the `specs` private submodule), both are found-while-passing-through,
and both need the same procedure: render the canonical PDF page, fix the markdown, bump the gitlink, re-run
`audit_doc_citations.py --check` and `audit_code_citations.py --check`, and check whether any existing
citation's ORDINAL changes as a result of defect 1 (it will, for anything citing §14.9.18.3 SR4's
sub-items). The spec-reconcile lane owns the OCR-slip class; this note is the two instances that are owed
now.

## ⛔ A caution for the fixer

`specs/ISO_COBOL.md` is a submodule and `DEVLOG.md`-style byte hazards apply: read bytes, write bytes, check
the diffstat rather than the exit code, and re-run `cite.py --check` on a citation in each repaired clause
BEFORE and AFTER, so the change is demonstrated rather than assumed.
