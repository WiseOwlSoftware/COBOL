# PB5225 - the line-ending audit checks only what a branch changes and CI keeps one full sweep

**Sites:** `scripts/line_endings.py` (`check`, new `changed_paths`, `scan_paths`, `changed_python`, `text_holds_cr`,
`attribute_findings`; `scan_writers` takes its file list; `main`'s `--base`/`--tree`; the self-test's PB5225 block) ·
`scripts/gate.py` (new `CHANGE_SCOPED`, `Host.gate_form`; `Host.audits` and `Gate._audits` carry the change; two new
self-test arms) · `.github/workflows/build-and-test.yml` (the `audits` job's step comment; the `windows-self-tests` step
deleted) · `.github/workflows/nightly.yml` (the `self-tests` step deleted) · `.gitattributes` (header) ·
`scripts/battery.sh` (comment) · `docs/DOC_INDEX.md`, `docs/rearchitecture/DESIGN-test-build-ci.md`, `CONTRIBUTING.md`

## The question

The owner asked on 2026-11-10: "Why do we need line_endings.py --check? We long ago standardized on LF and the GitHub
configuration should enforce that."

`.gitattributes` opens with `* text=auto eol=lf` (PB3029). It misses three cases:

1. A lone CR makes git's heuristic call the file binary, so git stores it as it is.
2. A Windows tool can write CRLF into the checkout. The file stays CRLF on disk until the next checkout, and the Windows
   gate compiles those bytes.
3. A commit made through the API never passes through `.gitattributes`.

So the rule stays. Its cost was the problem. `--check` read all 35,241 tracked files and parsed every live Python file in
every gate: 13.2 s measured, and 9 to 30 s on this host on 2026-11-10 under the other worktrees' load. CI ran the same
sweep three more times: the Linux `audits` job, a `windows-self-tests` step and the nightly `self-tests` job on both
OSes. A file already on main was read when it landed, so each later sweep re-read bytes that had not changed.

## The decision

**The gate reads the change.** `gate.py` hands every audit in `CHANGE_SCOPED` (today LINE ENDINGS alone) the change's
cut point and measured tree, `--base <base> --tree <tree>`. These are the same pair `Host.lane` classifies the lane from.
`line_endings.py` lists the paths with `inert_lane.changed`, the lane's own listing, so no second diff mechanism exists.
It adds `git ls-files -m -o --exclude-standard`, because one case is invisible to any tree diff: under `eol=lf` a CRLF
rewrite of an unchanged file cleans to the blob it had, so the measured tree equals the base at that path. The rewrite
changes the file's size, and `ls-files -m` trusts a size mismatch without comparing content, so that listing names it.
The INDEX and WORKING TREE arms read those paths' bytes (`scan_paths`, one `cat-file --batch`). WRITERS parses only the
live Python files among them (`changed_python`), an untracked new tool included. A gate with no base or no measured tree
runs the full sweep.

**CI keeps one full sweep**, in the Linux `audits` job of `build-and-test.yml`, once per merge group. It is the backstop
for case 3, which no branch's gate saw.

**The Windows `windows-self-tests` step and the nightly step are deleted, not turned into the change form.** The change
form needs a base and a checkout with local edits, and CI has neither: its checkout is the commit. A CI checkout is a
fresh checkout of the blobs the Linux sweep has just read, and under `* text=auto eol=lf` an LF blob checks out LF on
every OS whatever `core.autocrlf` says. Main changes only through a merge group, so the nightly re-read a tree that a
merge group had already swept.

That argument rests on the catch-all, so the script now checks it: a new ATTRIBUTES arm (`attribute_findings`) asks
`git check-attr` what `*` says for a path no narrower rule names, and refuses anything but `text=auto` and `eol=lf`. The
Windows step was the only thing that would have noticed a lost `eol=lf`. Now both forms of the check refuse it.

**The residue.** If a CRLF rewrite of an unchanged file is then staged, `git add` records the CRLF size against the LF
blob, so `ls-files -m` stops listing it. The change form misses that file. Its committed bytes are LF, so only this
host's Windows gate reads the CRLF copy. The full sweep (`--check` alone) and `--fix` find it.

- the full sweep (`--check`): 10.25 s, 29.64 s, 28.35 s (the host was loaded by other worktrees; the earlier measurement was 13.2 s)
