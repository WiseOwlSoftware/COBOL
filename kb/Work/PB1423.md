### `GR-8.4.3.2.4-2` — PARTIAL (adjudicator + refuter record, verbatim)

GR2 (cite.py --check 8.4.3.2.4 'its arguments are evaluated individually in the order specified in the list of arguments, from left to right' -> OK §8.4.3.2.4 2)). Arguments bind in list order and each nested activation registers on the shared PendingPreOps list while its consumer's arguments bind, so it is hoisted before the consumer. Probe out/probe/function-identifier/p6_gr2_order.cob: FIP6F(FIP6G(1), FIP6G(2), FIP6G(3)) prints G0001 G0002 G0003 then R=0123; the intrinsic MAX(FIP6G(4) FIP6G(5)) prints G0004 G0005, M=0005; the same function as its own argument FIP6G(FIP6G(6)) prints G0006 G0006, S=0006. All match the spec. conformance:2002/udf_nested_args covers nesting, but its output (sums) cannot observe evaluation ORDER, so no test is named and a test is still needed. || REFUTED: PARTIAL — Left-to-right holds only among function-identifier arguments. Hoisting every nested activation to a pre-op, ahead of the consumer, evaluates a later function argument BEFORE an earlier non-function argument (identifier expression / nested intrinsic). A side-effecting user function in position 2 is observed by the expression in position 1. Wrong answer.

## What the fixer owes

Evaluate arguments in list order: either hoist EVERY argument into ordered temps or none; golden with a side-effecting function in position 2 observed by an expression in position 1.
