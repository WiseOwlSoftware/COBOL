## PB5949's spans grow the `All` row further (measured 2026-11-19)

PB5949 (the HTML listing's syntax colouring) gives every line of the source section its spans, each a JSON object in the JSON listing
and an element in the HTML page. Measured against its parent 7f7ae8c3da on one Windows host, Release, full compile, allocated bytes
(the benchmark README's PB5949 table): `All` IX113A 333.18 (302.50) MB, NC105A 196.40 (181.59), NC218A 204.26 (185.54), SM201A 73.92
(68.30): +5.6 to +30.7 MB, +8.2 to +10.1 % over the parent's `All`, which was already over its 25 % budget. `TextAndJson` grows +4.9 to
+14.5 MB. The standard text listing stays inside its 10 % (IX113A +7.1 % over its `None`).

What it points to, beside this note's step-9 file: the HTML page and the JSON are each built as one string (`ListingOutput.Render`);
writing each renderer to the file's stream would drop two of the three copies of every span's markup. The spans themselves are built
once per listing that holds the source section, which the text-only listing does not print; building them only for a request that
renders them would make the document depend on the formats asked for (DESIGN-listing.md section 13 item 2: one request, one
document), so the cost is taken where it is, and this note's fix is the renderers' streaming.
