# PB666 — OPEN — a vacuity that the permissive lane un-vacates

Found 2026-09-05 by the `PB319` implementer (report §"New defects" A), measured on its worktree: `cobol.exe
tests/conformance/negative/apply-commit-open-sharing.cob --std 2023 --permissive` → zero errors, one
`warning COBOLNET1709`, and the program's `OPEN INPUT SHARING WITH ALL OTHER F` on an APPLY COMMIT file compiles
clean. Not taken there: a different rule, a different row, and the row's verdict is an owner decision recorded in
[[PB371]] (2026-09-02: fourteen rules whose antecedent only a not-claimed module can create are CONFORMS
"witnessed by the refusal of the antecedent").

## The rule

§14.9.27.3 SR7: "The sharing phrase shall not be specified for a file subject to an APPLY COMMIT clause"
(`OK §14.9.27.3 7)`). Its witness, `negative/apply-commit-open-sharing.cob`, asserts only that COBOLNET1709
refuses the APPLY COMMIT clause — edition-strict — and `ApplyCommitClauseUnsupported` is `PermissiveInert: true`
in `DiagnosticCatalog`, so under `--permissive` the clause is a warning, the program binds, and SR7 has nothing
enforcing it. [[PB651]] is the lane-level sibling (the `--permissive` lane under-probed since PB248); this is its
adjudication face.

## The work (two halves, one change set)

1. **The code.** SR7's screen beside SR8's in `SequentialIoBinder.BindOpen`: `if (sharing is not null &&
   file.SubjectToApplyCommit)` → a diagnostic naming SR7 (one descriptor; the next free code). PB319 put the fact
   in hand; the check is three lines. Negative golden asserting the SR7 diagnostic under `--permissive` (the
   corpus runner has no permissive axis — an `OpenSharingLockModeTests`-style fact, as PB319 did for SR8's
   exemption).
2. **The adjudication.** Re-read `SR-14.9.27.3-7`'s CONFORMS against the permissive axis and re-record it with the
   new witness; then sweep PB371's other six vacuously-satisfied rows with the same question — for each, is the
   refusing diagnostic `PermissiveInert`? If yes, the rule is live under `--permissive` and needs its own code or
   an owner re-decision; if no (a hard refusal in both lanes), the vacuity stands and the note says so with the
   measurement. Record the family answer in PB371 rather than seven times.
