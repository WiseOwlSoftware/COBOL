# PB6167 - a SPLIT carrier deadlocks with the DONE branch it contains

**What happened.** `worktree-wf_3da4b722-0ee-22` (PB5674, DONE, reviewed CLEAN and gated GREEN at its tip
09ed28c13d) is an ancestor of `worktree-wf_bd30c11f-c3a-1` (PB2737, SPLIT). Likewise `worktree-wf_bd30c11f-c3a-20`
(PB3227, DONE, CLEAN, GREEN at 4a00eaabf2) is an ancestor of `worktree-wf_b65a448b-ca0-1` (PB2622, SPLIT).

- The survey (`prune_worktrees.live_survey`, which the land lane reads) reports each DONE branch `IN FLIGHT`:
  "continued by dispatch ... one step per file, the chain lands once, with its last link (kb/Work PB4396)". The
  land lane therefore never lands it.
- `plan_wave.py` reads in-flight work through `inflight.branch_carrier`. That function counts only reports with
  `r.finished` as carriers, so a SPLIT successor carries nothing. `lands_through(0ee-22)` is `0ee-22` itself, not
  `c3a-1`. The finisher group that continues `c3a-1` (PB2737) then meets `0ee-22`'s claim (docs/DATA_MODEL_DESIGN.md
  D3, docs/VERSION_CHANGE_REFERENCE.md Table 7) as a foreign in-flight hold, and waits: "same-member collision with
  in-flight work worktree wf_3da4b722-0ee-22 [IN FLIGHT] ... it waits until that work finishes".
- The DONE branch never lands, because its successor has not finished. The successor's finisher is never planned,
  because the DONE branch has not landed. Through Table 7 the same hold also blocked PB5575, PB5580, PB5658 and PB5704
  (branches 26c-2, 26c-3, 0ee-2, 26c-8). The resume and wave handoffs of 2026-11-22 23:14, 11-23 04:29, 11-23 14:06 and
  11-24 02:05 each decided FINISH for these branches, and no wave planned one.

**Root cause.** Two readers of "whose work lands through which branch" disagree. The survey's continuation rule
(PB4396) counts a SPLIT successor as the carrier. The planner's carrier rule (PB4352, `branch_carrier`) does not. Per
the docstring, a SPLIT branch never lands alone, so `branch_carrier` reads only finished carriers. Rule 4 asks for
one rule: the planner must treat a branch the survey holds as "continued by X" as X's work (`lands_through` = X) for
any report status of X. Otherwise the survey must not hold a DONE predecessor behind an unfinished successor.

**Unblocked by hand (2026-11-24).** The resume unit re-armed `26c-14`, `0ee-22` and `c3a-20` with `land_lane.py
rearm`. Each was DONE, CLEAN and GREEN at its tip. Landing a predecessor alone is safe: its successor merges main.

**Fix wanted.** One predicate for "the branch this branch's work lands through", shared by `prune_worktrees` and
`inflight.branch_carrier`, plus a drift test. The drift test plants a DONE branch contained in a SPLIT branch and
asserts that the SPLIT branch's finisher is planned (or that the DONE branch is landed), never neither.
