# PB1727 — OPEN

Filed by the train-71b lander from wave 71 group A's report (`w71a-PB1715-report.md`, new defect 1). Not re-probed
by the lander: the lead carries its repro and its measured output.

## Finding

PB1715 (PB1708 pivot M6) removed the lexer's left-edge predicates, so the lexer no longer serializes the in-process
compile: `b2` at 1 thread went 110.1 s → 3.4 s and 12 threads reach 2.0 s with zero lock contention. The M6
acceptance row's CPU target (≥ 70 %) was NOT met — 21 % — and the limit is now the garbage collector.

**Repro.** `dotnet run --project docs/rearchitecture/evidence/impact-map-pb1708/b2-scaling -- 400 1,12`, once as is
and once with `DOTNET_gcServer=1`. Without it, 3.5 s of a 5.3 s round is GC pause and the 12-thread speed-up is 1.7x;
with it, 6.1x at 87 % CPU. Frozen output: `docs/rearchitecture/evidence/impact-map-pb1708/b2-scaling/b2-after-m6.txt`.

**Code site.** No GC mode is set anywhere a test host reads it: `tests/*/*.csproj` and `tests/Directory.Build.props`
carry no `ServerGarbageCollection` / `ConcurrentGarbageCollection` property. DESIGN-test-build-ci.md §3.14.5 names
the "Server GC" bullet; its `b6` re-run (the whole-assembly wall under the new lexer) is now due.

**Root.** Distinct from PB1715 (the lexer) and from PB1720 (the cross-worktree cap): a host-level runtime setting.
Choosing it needs the b6 measurement, since server GC on N concurrent gate hosts multiplies heaps per core.
