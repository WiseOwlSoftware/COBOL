# PB2147 — removing a spelling from the grammar is not checked against the corpus

Found by the PB2111 implementer (wave 1028 group A), filed by the train-1028 lander.

PB717 was the instance: PB332 correctly made START's relational operator required, and a legacy integration test
still wrote `START IX-FILE KEY IS IX-KEY`. Nothing in the landing looked for that spelling in the corpus, so the
stale test surfaced as the only red of a later battery (#57). PB717 retired as moot when PB2110 deleted the legacy
integration project, and with it the only note that recorded the process gap. Every grammar change that narrows
what parses can repeat it against a conformance golden, a characterization input or a unit-test source string.

**Code site:** beside `scripts/spec/audit_grammar_optional_words.py`. PB2024 is the inverse audit (a `?` on an
underlined word).

**Fix shape:** a mechanical check, run by the implementer gate when a `.g4` changes: diff the grammar's
required-word and alternative set against the base revision, and grep the corpus (conformance, characterization,
unit-test COBOL strings) for each spelling that is no longer accepted. Each hit is either a test to correct (with
the spec citation that makes it illegal) or a sign the change is wrong.
