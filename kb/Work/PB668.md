# PB668 — LANDED — a COBOL-85 phrase parsed, gated, and ignored

Found 2026-09-05 by the `PB317` implementer (report §"New defects" (a)) while sweeping `openFileSpec`'s
alternatives: NO REWIND (its mechanism) and REVERSED share one grammar alternative and one omission — neither was
read by any binder — and REVERSED is the one PB317 did not take, because it needs a runtime reverse read on
`SequentialConnector`, a different mechanism from the `'07'` overlay.

## Repro (`--std 85`)

A sequential file holding two records; `OPEN INPUT F REVERSED. READ F.` returns the FIRST record. No diagnostic
at compile or run time.

## The rule

The 2023 text has no REVERSED phrase — §14.9.27.2's general format is `{ file-name-1 [ WITH NO REWIND ] } …`
(`OK §14.9.27.4 1)` for the OPEN rules; the phrase's absence is measured by grep, not cited) — and Annex A.3 item
33 covers only its surviving sibling. `docs/VERSION_CHANGE_REFERENCE.md` row 7.12 records the deletion at 2002.
COBOL-85's OPEN general format carries `REVERSED` on a sequential INPUT file (the file is positioned at its end
and READ proceeds from the last record backward). The repository holds no 1985 text, so the semantics come from
the VCR row and the surveyed implementations ([[survey_compilers_on_latitude]]); GnuCOBOL implements REVERSED for
sequential files.

## The mechanism

`src/Cobol.Net.Frontend/Grammar/Core/CobolIO.g4#openFileSpec` — the `REVERSED` alternative;
`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/SequentialIoBinder.cs#BindOpen` — never reads it;
`src/Cobol.Net.Compiler/Validation/VersionConformancePass.cs:668–673` — the only consumer, and it only gates the
edition. [[four_editions_one_compiler]]: the 85 compiler must implement the phrase it admits, or refuse it by
name.

## Landed 2026-09-22 (wave 44 C)

Re-probed first and it REPRODUCED exactly as written: at `--std 85`, `OPEN INPUT F REVERSED` over a three-record
file answered `AAAAAAAA`, `BBBBBBBB`, `CCCCCCCC` — the FORWARD order — with no diagnostic at compile or run time,
while `--std 2002` correctly refused it with COBOLNET0902.

**The estimate was wrong in the direction CLAUDE.md rule 5 names.** The note's fix shape said "`BoundOpenFile`
gains `bool Reversed` beside `NoRewind`". That is a SECOND bool for the second alternative of ONE grammar
bracket — the same shape that produced the defect, since kb/Work PB317 gave NO REWIND a bool and REVERSED, sitting
in the same `openFileSpec` alternation, was read by nobody. The per-file-name TAPE PHRASE is now ONE enum end to
end: `BoundOpenTapePhrase` on `BoundOpenFile.Tape` → `RuntimeApi.OpenTapePhraseExpr` (the one seam between the
backend-neutral bound tree and the runtime enum) → `OpenTapePhrase` on `CobolFile.OpenTape`/`OpenShared` → ONE
effect switch in `FileRegistry.OpenCore`. The syntax rules are a TABLE (`StatementValidation.OpenTapePhraseRules`,
one row per phrase carrying its organization predicate and admitted modes with a clause and a diagnostic for
each), NAMED rather than indexed by ordinal and reached through `OpenTapePhraseRule.For`, a switch whose
default throws — so an inserted member cannot silently mis-key and one with no row is LOUD at the first OPEN
that writes it. `CheckOpenTapePhrase` is a lookup into that and nothing else, replacing
`CheckOpenNoRewindOrganization` and `CheckOpenNoRewindOpenMode`. A third tape phrase is a member on each enum,
an arm in the effect switch and a named row with an arm in `For`.

**REVERSED added no retrieval code.** §14.9.30.4 GR21 c) already defines the decreasing direction and
`SequentialConnector` has implemented it since kb/Work PB334 for `READ … PREVIOUS`. `PositionReversed` sets the
file position indicator to one past the last record (`ExistingRecordCount`, the same ONE measurement the
§14.9.51.4 GR19 EXTEND base uses) and raises a standing flag; `MovesBackward(previous) => previous ^ Reversed`
is the ONE conversion from a statement's direction phrase to the connector's travel, asked by both `Read` and the
§14.9.30.4 GR9 pre-read peek. The flag is cleared by every `OpenCore`, so the phrase cannot outlive its OPEN.

**Syntax rules, narrower than NO REWIND's on both axes:** record sequential organization only (COBOLNET2210) and
the INPUT group only (COBOLNET2211), against §14.9.27.3 SR5/SR6's both-sequential-kinds and INPUT-or-OUTPUT.
⚠ The LINE SEQUENTIAL cell of the organization rule is unreachable from conforming source at EVERY edition —
LINE SEQUENTIAL arrived in 2023, REVERSED left in 2002 — so it is defence in depth under `--permissive`, and the
negative golden witnesses the reachable half with a RELATIVE file.

**Also repaired on the way** (same construct, inherited citation): `tests/version-matrix/constructs.json`'s
`open-reversed-removed-2002` row cited §14.9.26 — the MULTIPLY statement — in BOTH its `description` and its
`citation`, which `ConstructRegistry.g.cs` and every COBOLNET0902 message carried. The VCR row itself had been
repaired on 2026-09-05 and the JSON had not. Corrected to §14.9.27 and the registry regenerated.

**Goldens.** `85/pb668_open_reversed_85` (last-to-first, the '10' at end at the first record, and a plain re-open
proving the phrase does not outlive its OPEN); `negative/pb668-open-reversed-organization` (COBOLNET2210) and
`negative/pb668-open-reversed-output` (COBOLNET2211), both `reject-at: 85` because 2002+ refuses the phrase
first. Docs: `COBOLNET_FILES_DESIGN.md` **D26**, `VERSION_CHANGE_REFERENCE.md` row 7.12, `DIAGNOSTICS.md`
(generated).

## Fix shape (as written 2026-09-05 — superseded by the Landed section above)

`BoundOpenFile` gains `bool Reversed` beside `NoRewind` (PB316's design D12 puts every file-name phrase on the
entry), bound from `spec.REVERSED()` at 85 only (the edition gate stays); the runtime's sequential connector gets a
reverse-read mode — position at end on OPEN, READ moves backward, AT END at the first record — implemented once
in `SequentialConnector` and selected by the OPEN, with the file-position-indicator rules of §14.9.27.4 GR14
adapted for the 85 semantics and stated in the FILES design. Goldens at 85 only: a three-record file read
REVERSED (last-to-first), the AT END after the first record, and REVERSED on a non-INPUT open rejected (the 85
format allows it on INPUT only — measure the 85 text through the VCR before asserting); a negative at 2002+ is
already the edition gate's.
