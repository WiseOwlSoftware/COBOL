# PB668 — OPEN — a COBOL-85 phrase parsed, gated, and ignored

Found 2026-09-05 by the `PB317` implementer (report §"New defects" (a)) while sweeping `openFileSpec`'s
alternatives: NO REWIND (its mechanism) and REVERSED share one grammar alternative and one omission — neither was
read by any binder — and REVERSED is the one PB317 did not take, because it needs a runtime reverse read on
`SequentialConnector`, a different mechanism from the `'07'` overlay.

## Repro (`--std 85`)

A sequential file holding two records; `OPEN INPUT F REVERSED. READ F.` returns the FIRST record. No diagnostic
at compile or run time.

## The rule

The 2023 text has no REVERSED phrase — §14.9.27.2's general format is `{ file-name-1 [ WITH NO REWIND ] } …`
(`OK §14.9.27.4 1)` for the OPEN rules; the phrase's absence is measured by grep, not cited) — and Annex A.3 item
33 covers only its surviving sibling. `docs/VERSION_CHANGE_REFERENCE.md` row 7.12 records the deletion at 2002.
COBOL-85's OPEN general format carries `REVERSED` on a sequential INPUT file (the file is positioned at its end
and READ proceeds from the last record backward). The repository holds no 1985 text, so the semantics come from
the VCR row and the surveyed implementations ([[survey_compilers_on_latitude]]); GnuCOBOL implements REVERSED for
sequential files.

## The mechanism

`src/Cobol.Net.Frontend/Grammar/Core/CobolIO.g4#openFileSpec` — the `REVERSED` alternative;
`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/SequentialIoBinder.cs#BindOpen` — never reads it;
`src/Cobol.Net.Compiler/Validation/VersionConformancePass.cs:668–673` — the only consumer, and it only gates the
edition. [[four_editions_one_compiler]]: the 85 compiler must implement the phrase it admits, or refuse it by
name.

## Fix shape

`BoundOpenFile` gains `bool Reversed` beside `NoRewind` (PB316's design D12 puts every file-name phrase on the
entry), bound from `spec.REVERSED()` at 85 only (the edition gate stays); the runtime's sequential connector gets a
reverse-read mode — position at end on OPEN, READ moves backward, AT END at the first record — implemented once
in `SequentialConnector` and selected by the OPEN, with the file-position-indicator rules of §14.9.27.4 GR14
adapted for the 85 semantics and stated in the FILES design. Goldens at 85 only: a three-record file read
REVERSED (last-to-first), the AT END after the first record, and REVERSED on a non-INPUT open rejected (the 85
format allows it on INPUT only — measure the 85 text through the VCR before asserting); a negative at 2002+ is
already the edition gate's.
