# PB2601 — the lander's push-main hand-off on a permission refusal

**Model:** Opus. One group with PB2600 and PB2602 (wave 1038 group V).

## Defect

2026-10-08 ~00:00 PDT: the attended R2 lander's `bash scripts/push-main.sh` was refused by the Claude Code auto-mode
permission classifier ("Git Destructive"). `lander-train-brief.md` had no instruction for that case, so the lander
returned BLOCKED and the train, committed and gated, waited until the owner said (00:10) "push-main.sh has been
accepted all day today".

Cause: that session had been started WITHOUT `--dangerously-skip-permissions`. `scripts/start-session.ps1` passes it
(owner decision 2026-09-20: a boot start never waits on a permission prompt), but account 2's user settings carry
`permissions.defaultMode: "auto"`, so a session started any other way runs under the classifier. Nothing at session
start reported the mode, so nobody saw the difference until a push was refused.

## Fix shape

- `lander-train-brief.md` + MANDATORY-PRACTICES: on a permission refusal of `push-main.sh` the lander never retries and
  never routes around it (P12); it leaves the train committed and gated and ends with the first line
  `READY-TO-PUSH <worktree> <sha>` for the session that dispatched it, which runs `push-main.sh` itself.
  `check_practices.py` requires that line in the template.
- The session-start TOOLING block states when the session is NOT in the permission mode the owner decided for this
  repository. Measured: the transcript records the mode (a `permission-mode` record and a `permissionMode` field on
  each user record; this session's transcript reads `auto` until 07:20:30Z and `bypassPermissions` after the 00:20
  PDT resume), and the hook payload carries `transcript_path` (and, where Claude Code sends it, `permission_mode`).

## Landed (w1038v, branch `w1038v-branch-lifecycle`)

- MANDATORY-PRACTICES L13 and all three lander templates (`lander-train-brief.md`, `lander-brief.md`,
  `golden-lander-brief.md`): a permission refusal of `push-main.sh` is never retried, rephrased or routed around; the
  lander leaves the train committed and gated and its report's FIRST line is `READY-TO-PUSH <this worktree> <HEAD
  sha>` for the dispatching session. `check_practices.py` requires that line in every lander template.
- MEASURED: Claude Code records the mode in the transcript (a `permission-mode` record and `permissionMode` on each user
  record; this session's transcript reads `auto` until 07:20:30Z and `bypassPermissions` after the 00:20 PDT resume).
  Whether the SessionStart payload itself carries `permission_mode` could not be observed from inside an agent; the
  check reads it when present and falls back to the transcript. At a fresh `startup` the transcript may not yet hold a
  record: then the line is `N/A permission mode — UNMEASURED: …` with the account's configured default and the fix, never
  a silent OK.
- `tooling_check.py`: `OWNER_PERMISSION_MODE = "bypassPermissions"` (owner decision 2026-09-20) and a `permission mode`
  TOOLING line — OK, or ASK-OWNER naming the mode, its source and the fix (`pwsh scripts/start-session.ps1`).
  `session_start.py` reads the hook payload FIRST (before the probe's children can inherit stdin) and passes it in.
  `tooling_check.py --self-test` covers payload, transcript (last record wins, bad lines skipped), missing and empty
  transcripts, and holds `start-session.ps1`'s launch line to `--dangerously-skip-permissions`.
