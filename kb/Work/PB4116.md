# PB4116 — the rewritten notes of inventory row GR-14.9.43.4-10 say GnuCOBOL 3.2.0 'was run on every golden leg', right a

**Sites:** `tests/version-matrix/traceability-inventory.json` (row GR-14.9.43.4-10, its `notes` text).

Review lead R3-1 (low, round 3) of PB1908. The row's `notes` (traceability-inventory.json, `"rule-id": "GR-14.9.43.4-10"`) say:
"Golden pb1908_string_function_order pins the order (EC-BOUND-REF-MOD before EC-BOUND-SUBSCRIPT). GnuCOBOL 3.2.0 was run on every
golden leg and on 1,350 random STRING statements over one record ...: identical."

The golden `pb1908_string_function_order` cannot be compiled by cobc 3.2.0 (USE AFTER EXCEPTION CONDITION is not implemented, RESUME
is unsupported), its header says `portable: unverified`, and the DEVLOG scopes the measurement to the five `pb1908_string_overlap_*`
goldens. As written, the sentence reads as GnuCOBOL agreement on the exception ORDER, which was never measured.

**Fix:** restate the sentence so the GnuCOBOL measurement names only the five `pb1908_string_overlap_*` goldens and the 1,350 random
statements, and says the order golden is `portable: unverified`. Applied through `record_verdicts.py` (never a hand edit of the JSON
hunk, L6), verdicts unchanged.
