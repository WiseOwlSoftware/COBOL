# PB3945 — ForeignFileCheckedApart compares whole EC-I-O masks, so a general >>TURN EC-I-O CHECKING ON emits a keyed arm no directive names

**Sites:** `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/SequentialIoEmitter.cs:310` (`SequentialIoEmitter.ForeignFileCheckedApart`)

`SequentialIoEmitter.ForeignFileCheckedApart` compares the WHOLE EC-I-O masks of the named GLOBAL file and of "no
file". `IoRaise` declares the full `IoMaskNames` family for each `BoundCommitRollback.ForeignFiles` entry, while the no-file
pairs hold only `EC-I-O-PERMANENT-ERROR`. Under a general `>>TURN EC-I-O CHECKING ON` (no file named) the masks therefore
always differ, so a keyed arm is emitted though no directive names the file. The PB3554 remark ("otherwise byte-identical"),
its DEVLOG entry and its note ("every other program emits the same text as before; an arm for each one whose checking a
naming directive changes") are false for that shape. Harm: dead code and a changed emitted text; no wrong answer shown.

## Acceptance
- Compare the masks over the same family on both sides (or compare only what a naming directive can change), a witness for
  a program with only a general directive that emits no keyed foreign arm (seen RED first), and the PB3554 prose corrected.
