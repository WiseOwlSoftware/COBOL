# PB6358 — render_designed emits authored sites without the site rule

**Sites:** `scripts/arch/file_census_notes.py` (`render_designed`), `scripts/spec/work.py` (`sites_problems`)

`render_designed` (`scripts/arch/file_census_notes.py:494`) writes each entry of a designed finding's `sites` list into the note as `- <entry>` with no check. An authored site that names a code file bare (a .cs, .py or .ps1 file with neither members nor a whole-file reason) therefore becomes a note that `python scripts/spec/work.py check` refuses under the site rule (kb/Work PB3797, MANDATORY-PRACTICES R3). The self-test fixture of the PB3259/PB4080 change names a code file bare, so the writer already produces such a note from its own test input. The PB3259 implementer left it unfixed: the sites are authored input, outside the writer PB4080 changed.

**Expected:** the designed-note writer refuses an authored site the site rule would refuse, before it writes the note, using the one site-rule reader in `scripts/spec/work.py` and not a second copy; the self-test fixture carries a valid site. No harm beyond a filing run that writes a note the register then refuses.

**Repro:** run `python scripts/arch/file_census_notes.py --self-test`, pass the rendered designed note to `python scripts/spec/work.py check`, and read the fixture's `sites` entry.
