## The rule (every citation re-run by the registrar through `cite.py --check`)

> A relation condition shall contain at least one reference to an operand that is not a literal

`python scripts/spec/cite.py --check 8.8.4.2.1 "…"` → `OK  §8.8.4.2.1 13)  (General)`

## Finding — `simple-relation-conditions-p1` (under-rejects; rows `GR-8.8.4.2.1-13`)

**Mechanism.** F5 — the §8.8.4.2.1 rule 'A relation condition shall contain at least one reference to an operand that is not a literal' is enforced nowhere: the code knows it (ExpressionBinder.NonNumericLiteralOperand's comment says the clause 'constrains only that not BOTH operands be literals') but no screen asks it

**Repro.** PROCEDURE DIVISION.  IF 1 = 1 DISPLAY "Y" END-IF  (also IF "A" = "A", IF "A" = SPACE, IF ZERO = ZERO)  -> compiles clean at 85, 2002, 2014 and 2023 and prints Y (probe srel1/gen.py lit_lit_num, lit_lit_an, lit_fig, fig_fig; srel2/und.cob).

**Expected from the spec.** §8.8.4.2.1: 'A relation condition shall contain at least one reference to an operand that is not a literal' (figurative constants are literals, §8.3.3.6 under §8.3.3 Literals). The rule is not an SR but is syntactically distinguishable, and §4.2.2 says 'This warning mechanism shall indicate violations of such rules' — the program must at least draw a diagnostic.

**Observed / reasoning.** No diagnostic at any edition. The natural site is CheckRelationalOperands (every relation, incl. EVALUATE pairings, PERFORM UNTIL, SEARCH WHEN). Care: an EVALUATE literal subject with a literal WHEN object is a relation too (§14.9.13.4 GR2), and an abbreviated relation reuses the subject; the DEFINE/cce relation (§7.3.8) is a different clause and must not be caught.

**Code site.** src/Cobol.Net.Compiler/Binding/Validation/StatementValidation.cs#CheckRelationalOperands (no both-literal arm); src/Cobol.Net.Compiler/Binding/Procedure/ExpressionBinder.cs#NonNumericLiteralOperand (comment ~line 213)

## What the fixer owes

A both-literal arm in CheckRelationalOperands (figurative constants are literals). Care: an EVALUATE literal subject with a literal WHEN object IS a relation (§14.9.13.4 GR2); an abbreviated relation reuses the subject; the >>DEFINE / compile-time relation (§7.3.8) is a different clause and must not be caught. The rule is unnumbered prose — cite.py stamps it '13)' (PB222). Negative goldens for the four probes.
