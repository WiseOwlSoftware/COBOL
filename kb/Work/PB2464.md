# PB2464 — LANDED (wave 1034 group G)

**Landed.** A restricted PROGRAM- or FUNCTION-pointer is typed by the SIGNATURE of its prototype (§13.18.60.4 GR25 /
GR26; `cite.py --check`: OK 13.18.60.4 25) and 26)), so two pointers restricted to two differently named prototypes of
one signature are of the same type (§14.8.2.3.2 4), OK) and §14.9.39.3 SR20 / SR22 admit a SET between them. The
repro was the universal lane (`INVOKE U "RP1" RETURNING R2` ended in EC-OO-METHOD); the sibling sweep found the TYPED
lane refused the same pair at compile time (COBOLNET0828 from `OoConformance.CategoryArmMismatch`'s name compare), so
the note's `rejects_legal_source` is true as well.

*The design differs from the note's "canonical signature key".* No canonical text can equal `PrototypeSignatures.Same`
(its group / bit-group / national-group arms are not an equivalence relation), so the type is a CLASS: the group's
prototypes are partitioned by `Same` itself (`PrototypeSignatureClasses`, one per `BindSession`; a class's identity is its
founder's externalized name, `TO name`, so a prototype that is its own founder, or took GR10 c), keeps the identity every
relation read before). `DataBinder.ResolveRestrictedPrototypes` stamps each pointer item
(`DataItem.PointerRestrictionIdentity`) from its forest's prototype tables — one group step,
`BinderDriver.ResolvePointerRestrictions`, over every unit, class (object and factory) and interface forest, after the
repository exists and before any body binds, so no pair of items is one stamped and one not — and `PrototypeSignatures.RestrictionIdentity`
is the ONE reader: `ActivationDescriptions.ElementaryClauses` / `OfAddress` (so `ActivationDescription.Clauses` carries it
and `MaySet`, `Matches` rule 3 e) and `ReturningViolation` all agree without a new field) and the typed pointer arm.
`PrototypePointerTypeDriftTests` keeps a name compare from returning. Goldens `2002/pb2464_prototype_pointer_signature_type`,
`2014/pb2464_function_pointer_signature_type`; negatives `pb2464-prototype-pointer-signature-type-below-2002`,
`pb2464-function-pointer-signature-type-below-2014`, `pb2464-typed-pointer-signature-mismatch`.

*Residue.* The class identity is group-local (a universal dispatch between two separately compiled groups compares two
founders); the external repository (`DESIGN-external-repository.md` §12 row for PB2464) replaces it with a record
identity. PB2463 (the class condition of rule 6's object arm) is untouched and still open.

## Filed text (kept for the forensic trail)

Filed 2026-10-07 by the train-1033 lander from the wave-1032 group B implementer report (`w1032b-PB2076-report.md`,
new defect 2).

**Shape.** PB2076's `ActivationRelations.MaySet` applies SET's pointer restrictions to §9.3.6 rule 6. For a
restricted program-pointer or function-pointer returning item it compares the two descriptions' `Clauses`
(`TO <prototype-name>`) for equality. Two prototypes with different names and the SAME signature are therefore a
mismatch, so the universal resolution ends in EC-OO-METHOD where the spec gives a match (followed by the §14.8.3.3
returning-item rules). A corner case: it needs two distinct prototypes with identical signatures.

**Rule.** §14.9.39.3 20) (`cite.py --check`: OK) — function-pointer operands "shall have the same signature";
§14.9.39.3 22) (OK) — for a restricted program-pointer, "the program-prototypes associated with identifier-7 and
identifier-8 shall have the same signature" (the rule continues past the cite excerpt).

**Repro.** Not yet written: a method `RETURNING PROGRAM-POINTER TO P1` invoked universally with a returning item
`PROGRAM-POINTER TO P2`, where P1 and P2 are two program prototypes with identical parameter and returning lists;
expected a match (no EC-OO-METHOD).

**Code sites.** `src/Cobol.Net.Runtime/Control/ActivationRelations.cs#MaySet` (the pointer arms over
`ActivationDescription.Clauses`); the compiler's signature identity is `src/Cobol.Net.Compiler/Binding/PrototypeSignatures.cs#Same`.

**Fix shape.** The description carries a canonical signature key (computed by the compiler from the same facts
`PrototypeSignatures.Same` compares) and `MaySet` compares keys. Same root as PB2463: the activation description lacks
the type facts SET needs.

## Landing

- `src/Cobol.Net.Compiler/Binding/PrototypeSignatures.cs#RestrictionIdentity` - the ONE reader of a restricted program- or function-pointer's TYPE (its prototype's signature class, `TO name`); reuse it, never compare `PicInfo.RestrictedPrototypeName` (`PrototypePointerTypeDriftTests`). Trap: `PrototypeSignatures.Same` is not an equivalence relation (bit/national group arms, the null wildcard), so no canonical key can equal it - the type is a class built by `Same` itself.
- `src/Cobol.Net.Compiler/Binding/PrototypeSignatureClasses.cs` - one per `BindSession`; founder = first prototype presented, identity = its externalized name; an unresolved (GR10 c) prototype is its own class. Group-local by design until the external repository supplies record identities.
- `src/Cobol.Net.Compiler/Binding/BinderDriver.cs#ResolvePointerRestrictions` - the one stamping step (units, class object/factory forests, interface forests) after `BuildGroupRepository`; stamping only SOME forests would let an item and its twin disagree. `DataBinder.ResolveRestrictedPrototypes` is the per-forest pass; the stamp lives on `DataItem.PointerRestrictionIdentity` (not `PicInfo`, whose record text is the strong-type key).
- `src/Cobol.Net.Compiler/Oo/ActivationDescriptions.cs#ElementaryClauses` / `#OfAddress` - the pointer's `Clauses` carry the identity, so `ActivationRelations.MaySet`, `Matches` rule 3 e) and `ReturningViolation` needed no change; `ActivationDescription.Unrestricted` is the `*` sentinel.
- `src/Cobol.Net.Compiler/Oo/OoConformance.cs#CategoryArmMismatch` (pointer arm) - the typed lane compared names and refused legal source (COBOLNET0828).
