**Expected from the spec:** At --std 85 a report group description entry may carry the SIGN clause only as an ELEMENTARY entry (numeric, PICTURE with S) and only WITH the SEPARATE CHARACTER phrase; a SIGN clause without SEPARATE, or on a report group entry that is a group (level 1 or any non-elementary level), is refused. At 2002, 2014 and 2023 both are legal: 2023 13.15.2 prints [ sign-clause ] referring to 13.18.52's format where SEPARATE CHARACTER is optional, and 13.18.52.3 SR1 admits 'a numeric report group description entry whose picture character-string contains the symbol S' and 'an alphanumeric group item, national group item, or strongly-typed group item'. The 1985 restriction is now QUOTED, not recalled: ISO/IEC 1989:2002(E) Annex F.2 (Substantive changes not affecting existing programs), item 123: 'SIGN clause in a report description entry. The SEPARATE phrase is no longer required in a report description entry and the SIGN clause may be specified at the group level.'; item 115's bullet: 'SIGN clause does not require SEPARATE phrase in report section'. Source: the archived post-ballot text v200112.txt lines 44271 and 44299-44300 (F.2 starts at line 43821), and the FCD fcd.txt lines 43735 and 43763 (item 122 there), under E:/Temp/claude/E--COBOL/8bd1c3d3-6c48-4db9-ada1-5e4edea40828/scratchpad/research/pb296-dl/fcd/. cite.py checks only the 2023 text; the 2002 Annex F lines are cited by file and line. The edge is 2002 (an F.2 item, so absent from 1985), and 2014 = 2023 (13.18.52.3 has the report and group bullets).
