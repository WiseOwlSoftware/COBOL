# PB5906 - COBOL0863 says the file lacks LINAGE when the real reason is that it is not visible

Filed from the lead of the Mythos lane's rulings on read pass 17 (`kb/Work/PB5683/2026-11-16-rulings-code-reads-batch-17.md`, "Leads that are not yet anything"). The ruling's bullet, unchanged: "COBOL0863 says a file that is not visible "lacks LINAGE" (the slice-239 reader)."

**The reader's words** (`1985-239.json`): "The refusal of a non-global file's counter in a containee is correct, though COBOL0863's wording ('the qualifier shall name a file whose FD contains a LINAGE clause', citing §2023) says the file lacks LINAGE when the real reason is that it is not visible; a wording point, not a conformance failure." The same note records: "The counter lives on the file connector, so an EXTERNAL file's single connector gives one counter per run unit and a GLOBAL file's counter follows the file's visibility (VisibleFiles)."

**Not run by the clerk.** The reader's reading is the source; no program was run. **Not ruled:** the wording the message should have.

**Sites:** none named by the source.

**Scope.** Edition 85 as the reader saw it; the message cites only a 2023 clause (kb/Work PB4950 holds the diagnostics that cite 2023 at `--std 85`).
