# PB2093 — record-struct member names collide with generated members

**Defect.** A COBOL data-name is legal when it is `AsImage` or `Equals` (§8.4.2: names need to be unique only when referenced). The compiler emits a record struct (`_T_0`) for each group, with generated members of those names (`AsImage`, `FromImage`, `Equals`, `GetHashCode`, and any other helper the emitter adds). A subordinate whose CsName is the same as a generated member fails the Roslyn build with CS0102 ("the type already contains a definition for ...").

**Found by.** The round-7 author's experiment `names` (scratchpad `r7/names`): a description `01 CUST. 05 CUST PIC X(4). 05 F PIC 9. 05 F PIC 9. 05 AsImage ...` fails on today's compiler; the design for the .NET host surface (DESIGN-external-repository.md §4.3, §4.5) needs the same names to be safe in a PUBLIC record struct.

**Fix.** Route every member of the record struct through ONE name allocator that is pre-loaded with the names the emitter already uses in that scope (the design's `CsNames.Allocate`, replacing `DataBinder.Unique`), with a documented suffix rule; a drift test asserts that no emitted member name can be reached by two paths. Sweep sibling scopes: program class members, nested record structs, REDEFINES areas, method parameters, enumerations. Golden: a COBOL program whose subordinates are named `AsImage`, `Equals`, `GetHashCode`, `ToString`, `FromImage`, `Value`, and a duplicate-name pair (`F`, `F`) compiles and runs with correct output (derive the expected output from ISO 8.4.2 and cite.py --check the clause).

## Landed (wave 1031 C, 2026-10-07)

Re-probed on the wave's own build before the change: `01 CUST. 05 CUST … 05 F … 05 F … 05 AsImage … 05 Equals …
05 GetHashCode … 05 ToString … 05 FromImage …` failed the Roslyn build with five CS0102 in `_T_0`, and a sibling
probe found the same shape ONE SCOPE UP — a WORKING-STORAGE record `01 CloseFiles` drew CS0102 in the program class
(`ICobolProgram.CloseFiles`). Rule: ISO §8.4.2.1, "In order to use a resource, a statement shall contain a reference
that uniquely identifies that resource" (cite.py OK) — uniqueness bites on a reference, and these are ordinary
user-defined words (§8.3.2.1).

Fix (the design's §4.5 allocator, slice 2 — kb/Work PB2098 lands with it): `Binding/Model/CsNames.cs` —
`CsNames.Allocate(baseName, scope)` over a `CsNameScope` SEEDED with the scope's reserved names
(`CsNames.RecordStructMembers`: the image / leaf-vector members the emitter writes and the members C# synthesizes for
a record struct; `CsNames.ProgramClassMembers`: the `ICobolProgram` surface). `DataBinder.Unique` is deleted with
every caller: the class-level roots allocate in `CsNameScope.ProgramClass()` (`_rootNames`), and a group's members
join it only through `DataItem.AddMember` (`Children` is now read-only), which allocates in the group's own
record-struct scope — so the TYPE / SAME AS clones (`CloneItem`), compiler-temp clones (`CloneTempNode`) and the
implied record's area take the same path; a cloned level-66 alias keeps its word's name (it is no C# member).
`CsNameReservationDriftTests` reads every member declaration the code generator writes, the members Roslyn
synthesizes for `record struct S`, and `ICobolProgram`'s members, and is red when one is in neither seed (made to
fail once with `CurrentExtents` and `PrintMembers` removed). Golden: `tests/conformance/2002/
pb2093_member_names_like_generated_members` (members `AsImage`, `Equals`, `GetHashCode`, `ToString`, `FromImage`,
`PrintMembers`, `CurrentExtents`, `F`, `F`, `F-2`, a record `CloseFiles`, and a TYPE clone of a type with such
members) compiles and runs with the spec-derived output. Sibling sweep: REDEFINES backings (`_redef_`), formals and
temporaries (`__`) and struct type names (`_T_n`) are outside the space a sanitized word reaches (§8.3.2.1: "The
hyphen or underscore shall not appear as the first or last character in such words"); an OO class's object
WORKING-STORAGE roots share the program-class scope (probed: `Equals`, `CloseFiles` in an OBJECT compile and run).
