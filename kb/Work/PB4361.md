# PB4361 - GOBACK RETURNING is refused with the STATUS phrase's message

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/ControlFlowBinder.cs` (`ControlFlowBinder.ReturningAsStatus`, line 102 at the filing). Landed by PB4335.

`ReturningAsStatus` folds a `GOBACK RETURNING operand` into the status path and runs the STATUS phrase's SR6 screen over the operand. Two consequences:

1. When the user wrote no status phrase the refusal still says the status operand shall reference an integer item and cites 14.9.18.3 SR6, a phrase the program does not contain.
2. An operand such as a COMP-3 item with decimals is refused here, although the same statement accepts that operand when a header RETURNING item exists. GnuCOBOL accepts it. No GnuCOBOL differential was run for that case.

**Whether the refusal itself is legal is an adjudicator's question**, not decided here: `rejects_legal_source` stays false until an adjudicator reads 14.9.18.3 (run `python scripts/spec/cite.py --check 14.9.18.3 "<text>"` first) and says whether a RETURNING operand is held to the status rule. If it is, only the message is wrong (this note). If it is not, the refusal is a second defect and this note's flags change.

## Landed (wave 20261808, group C)

**Sites (added by the landing):** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CallBinder.cs` (`CallBinder.BindGoback`: the
`ReturningAsStatus` call no longer passes the operand's text); `src/WiseOwl.Cobol.Compiler/Binding/MoveTable16.cs`
(`MoveTable16.SenderClassRefusal`, reused, unchanged); `docs/CONFORMANCE.md` (the `goback-returning` extension row).

Re-probed on the build: `GOBACK RETURNING X` (X `PIC S9(3)V99 COMP-3`, no header RETURNING item) drew COBOL1704 citing
"§14.9.42.3 SR2 for STOP RUN; §14.9.18.3 SR6 for GOBACK", while the same statement under `PROCEDURE DIVISION RETURNING R`
compiled clean; an index data item drew the same STATUS-phrase message.

**Adjudication (ISO, then GnuCOBOL; CLAUDE.md rule 1).** `cite.py --check 14.9.18.3`: SR6 reads "Identifier-2 shall reference
an integer data item or a data item with usage display or usage national", and identifier-2 is the operand of the
`WITH ... STATUS` phrase; §14.9.18.2 has no RETURNING phrase at all, so SR6 is no rule of the extension. The refusal was
therefore a second defect (an operand the extension accepts elsewhere was refused), not only a wrong message; the
`rejects_legal_source` flag is set accordingly. The standard is silent, GnuCOBOL moves the operand to RETURN-CODE (a MOVE) and
accepts a scaled item, so the operand is screened as the sender of that MOVE: §14.9.25.3 SR1 (`MoveTable16.SenderClassRefusal`,
the reader the header-RETURNING arm's `BindMoveOf` also asks) refuses an index, message-tag, object or pointer operand as
COBOL0809 naming the implicit MOVE of GOBACK RETURNING; every other operand renders through GR5's truncation to an integer
(CONFORMANCE.md item 192). No GnuCOBOL differential was run (no cobc reachable from the implementer's shell).

**Fix.** `ControlFlowBinder.ReturningAsStatus(Place)` no longer calls `ScreenStatusOperand`; its `text` parameter is gone and
its only caller updated. The STATUS phrase's screen (`StatusOperand` / `ScreenStatusOperand`) is untouched and keeps SR6.
Goldens: `14.9.18-GOBACK/pb4361_goback_returning_scaled_operand` (accept 2002) and `pb4361-goback-returning-index-item`
(refused COBOL0809 at 2002, 2014, 2023); exit values in
`StopGobackExitCodeTests.GobackReturningAScaledOperandWithoutAHeaderItem_ExitsWithItsTruncatedValue` (COMP-3 7.5 and COMP-2
7.5 exit 7). Sweep: `ReturningAsStatus` was the only caller of the status screen outside the two phrase arms.
