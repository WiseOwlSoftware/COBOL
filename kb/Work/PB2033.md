# PB2033 — LANDED: a just-started agent no longer reads as a stalled one

`tools/claude-skills/skills/agent-fleet/references/stall_watch.py` (MANDATORY-PRACTICES O8) exited `3` with
`transcript unreadable or empty` twice in wave 1019 while every agent was working:

1. At the fleet's start (watch started seconds after the Workflow call): implementers B, C and D.
2. When a freed rolling-wave slot started group G about 40 minutes later.

**Cause.** `last_record` skipped every record whose `message.content` is not a list. An agent's first record is
its prompt, whose content is a plain STRING, so a transcript holding only the prompt returned `None`, and
`check()` reports `None` as a stall at once. Every newly started agent therefore woke the orchestrator with a false
STALLED, and the watch then exited, leaving the rest of the fleet unwatched until someone restarted it.

**Sibling.** A transcript that is still empty (or not yet created) just after its agent's `started` journal record
hit the same immediate alarm.

**Fix (brent-tools 1.17.1, public repo commit `6e94e58`, base first per PB1699).** A string-content record reads
as "waiting on the model" with its own timestamp, so the normal `--model-stall` limit applies. A live watch times an
unreadable transcript from the poll that first saw it and alarms only past `--model-stall`; `--once`, which has no
earlier observation, still alarms at once, so an unreadable transcript is never treated as healthy.

**Verified.** A prompt-only transcript returns `(ts, False, "", "text")` where it returned `None`. `--once` over the
live wave-1019 fleet listed all six agents with `EXIT=0` where the 1.17.0 copy exited `3`. The fixed copy then
watched the rest of wave 1019 without a false alarm. `lint_skills.py`: OK.

**The pin.** `tools/claude-skills` moves from 1.17.0 to 1.17.1. The four overlays (gate, workstream, spec-lookup,
review) and PB1699 name the new version.
