# PB2462 — the ledger tracks the re-architecture program

The owner, 2026-10-07 08:45 PDT: "Also update ledger to track the new plans tasks." The plan is kb/Work R69's
completion plan: the legacy retirement cluster (`cluster: ["PB2108"]`), the architecture review's phases R0-R5
(`docs/rearchitecture/DESIGN-architecture-review.md` §3) and the Delete program with its R3 wave kinds
(`cluster: ["PB2119"]`). The owner's live status page, `scripts/spec/gen_ledger.py`, showed none of it, so the
program's standing could only be read by grepping the register.

**Model:** Opus (a tooling change with a self-test).

## Shape

1. A computed section "The re-architecture program" between "The three veins of remaining work" and "In flight
   right now": one row per phase R0-R5 with its notes and their statuses read from the register (a phase's notes
   are the ones whose title names it, plus a small explicit structure for the ones that do not), R0's evidence
   shas (the newest record in `arch-census/`, `arch-oracle/`, `perf-baseline/`), the retirement cluster by status,
   and the review program as wave kind × status. The wave kinds are the filing generator's own title prefixes
   (`scripts/arch/file_census_notes.py` PREFIX), imported, so a kind it gains appears with no edit here.
2. The program's counts become a second series in `ledger-trend.json`, appended when they move.
3. `gen_ledger.py --self-test` (also run by `--check`, the gate's audits and CI's `audits` job) fails when a phase
   note id is not in the register, a program note's title cannot be read, every program note reads as "other", or
   the section's totals disagree with `work.py`'s `cluster_order` count of the cluster.
4. The in-flight narrative rewritten for 2026-10-07.
