# PB820 — OPEN — the binder is still choosing emitted spellings in three places

Filed 2026-09-09 by the registrar (second pass) from the **PB365 finisher's report** §9 —
`scratchpad/reports/PB365-finisher-report.md`. **Re-measured on this worktree at `d3ba5795`.**

## The measurement

```
$ grep -rn "CsName" src/Cobol.Net.Compiler/Binding/Bound/
BoundOo.cs:50    BoundInvoke(InvokeForm Form, string? ClassCsName, Place? Receiver, string? MethodCsName,
BoundOo.cs:52                …, string? OwnerCsName = null)
BoundTree.cs:57  public sealed record BoundMethod(string CobolName, string CsName, int EntryPc, int EndPc);
BoundTree.cs:171 public sealed record BoundReportVaryingRef(string CsName) : BoundExpr;
```

Five members, three records. (`StatementBinder.cs:233` and `:273` populate `BoundMethod` from
`m.CsName`; `StatementBinder.SubscriptSegments.cs:108` builds a `DataItem` model with a `CsName` — that one is a
symbol, not a bound node, and is out of scope here.)

## Why it is a defect and not a style preference

`docs/COBOLNET_DESIGN.md` §1.3 / §2: the bound tree is the binder's **resolved** output and the backend chooses
spellings; a second backend behind `ICodeGenBackend` must be able to lower the same structure (memory
`dual_backend_goal`). A rendered C# name in a bound node is that seam crossed.

It is not hypothetical here. **[[PB366]] is exactly this bug, shipped**: `BoundDeclarative.EoClassCsName`
carried ONE rendered C# type name, and a COBOL class is emitted as TWO disjoint C# hierarchies, so the Format-4
USE selector tested one of them and a factory exception object silently matched no declarative. The cure was to
carry the symbol (`EoClass`, an `OoClassSymbol`) and let the emitter render the census. **Every remaining
`CsName` member is a place where a future "one COBOL name selects several C# types" rule gets silently narrowed
at bind time** — a scalar column where the rule may name a set
(`feedback_model_the_rule_shape_not_one_case`).

## ⛔ The invariant that should have caught it is blind to the spelling

`scripts/semgrep/invariants.yml:115` — `cobolnet-bound-node-carries-rendered-text` — says exactly the right
thing in its message ("no C# text, Roslyn syntax, mangled identifier or format literal enters a bound node or
Place … Carry the STRUCTURE and let the backend's renderer produce the text"). Its detector:

```
pattern-regex: '(?m)^[^\n]*\brecord\s+(?:struct\s+)?Bound[A-Za-z0-9_]*\s*\([^)]*\bstring\s+[A-Za-z0-9_]*(?:Text|Csharp|CSharp|Rendered|Fragment)\b'
```

`CsName` matches none of those suffixes. `scripts/semgrep/baseline.json` records
`cobolnet-bound-node-carries-rendered-text: 3`, and the three are `BoundNumLiteral(string Text)`,
`BoundNumericLiteral(string Text)` and `BoundStopLiteral(string Text)` — literal source text, a different and
arguably legitimate case. **The rule has never once looked at the members this note is about**
(`feedback_green_gates_arent_evidence`: a passing check proves nothing if it never looked at what changed).

## The fix shape

Per site, the same cure PB366 used: carry the SYMBOL — `OoClassSymbol` / `OoMethodSymbol` / the report symbol —
and let the emitter spell it. Then extend the semgrep regex with `Name` on a `Cs` prefix (or, better, invert it:
match any `string` member on a `Bound*` record and require an explicit allow-comment for the literal-text
three), and drop the baseline to the number that remains. A drift test phrased as *"no `CsName`-typed member on
a bound record"* is the finisher's own proposal and is the enforceable form of the invariant once the five are
converted.

⚠ **Order matters:** the regex must be widened **after** the five are converted, or the baseline simply grows.
Widen it once, watch it go red, then convert — `feedback_green_gates_arent_evidence` again, from the other side.

## Why `process_only: true` and not `wrong_answer: true`

Because it is honest about **today**. Five rendered names on three bound records do nothing to a running
program by themselves; what they do is make a *future* narrowing invisible. [[PB366]] is the instance where this
family DID produce a wrong answer, and it is landed — so setting `wrong_answer` here would rank a latent
architectural defect as if it were an observed one, and the register ranks on what a defect DOES to a user's
program. The flag should be revisited the moment a rule that names a SET is implemented over any of the five.
