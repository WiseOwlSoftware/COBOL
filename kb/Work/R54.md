# R54 — ADVANCING 0

§14.9.51.4 25) c) says only that "no repositioning of the representation of the printed page is performed"; the device representation is implementor-defined. GnuCOBOL 3.2 (`libcob/fileio.c`, `cob_seq_write_opt`) writes a bare carriage return (`"\r"`) for `AFTER/BEFORE ADVANCING 0` on a sequential file, so the next line overprints. **Owner: follow GnuCOBOL** — ADVANCING 0 writes CR (no line feed), documented in docs/CONFORMANCE.md beside the other print-control determinations; the report-writer's re-INITIATE line state (PB1667 arm 2) is re-derived from the same representation.

## Re-verified against the ISO text (2026-09-30)

The spec decides the SEMANTICS and they are explicit: §14.9.51.4 25) c) (cite-checked OK) "no repositioning of the representation of the printed page is performed" — the next line overprints. The spec leaves the device REPRESENTATION to the implementor, and CLAUDE.md rule 1 already settles implementor latitude (ISO -> GnuCOBOL -> IBM/MF): GnuCOBOL's `cob_seq_write_opt` writes a bare carriage return. So this was never an owner-discretion question; it is recorded here so the representation is documented (docs/CONFORMANCE.md).
