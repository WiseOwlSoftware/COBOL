# PB2004 — a signed numeric OCCURS DYNAMIC element cannot hold INSPECT's retained negative zero

Found by the train-1018 lander while reviewing PB1128's sign arm (DEVLOG 1878).

## The rule

§14.9.22.4 GR4 d): "If identifier-1 is a signed numeric item, the original value of the sign is retained upon
completion of the INSPECT statement" (`cite.py --check 14.9.22.4 "the original value of the sign is retained upon
completion of the INSPECT statement"` → OK §14.9.22.4 4) d)). A negative item whose digits all become zeros therefore
holds a NEGATIVE zero.

## What happens

PB1128 made INSPECT's REPLACING / CONVERTING target a character channel, so an ordinary numeric DISPLAY / NATIONAL
identifier-1 is character-image stored and `CobolNum.RetainSign` writes the negative zero. An element of an OCCURS
DYNAMIC table is a typed member of its `CobolDynTable<T>` (data-model D9), and `UsageCollectionPass.Channel` skips a
`DynTablePlace` exactly as every other character channel does, so the element keeps its native carrier.
`InspectEmitter.EmitStore` re-encodes the replaced digits as a VALUE for that shape (`Read(p) < 0 ? -mag : mag`), and a
value has no negative zero.

Repro (free form, `cobol x.cob --source-format free --run`):

```cobol
01 G.
   05 DT OCCURS DYNAMIC.
      10 X PIC S9(3).
...
    MOVE -5 TO X(1)
    INSPECT X(1) REPLACING ALL "5" BY "0"
```

The element reads back as positive zero (`00{` in this compiler's overpunch), where GR4 d) requires the negative zero
(`00}`), the answer the same statement gives on an ordinary `01 N PIC S9(3)` (golden
`85/pb1128_inspect_signed_sign_retained`, case S5). A replacement that leaves a non-digit is decoded by digit
positions, the same deterministic answer as before PB1128.

## Code sites

- `src/Cobol.Net.Compiler/CodeGen/Verbs/InspectEmitter.cs#EmitStore`: the `DynTablePlace` arm.
- `src/Cobol.Net.Compiler/Binding/Passes/UsageCollectionPass.cs#Channel`: skips `DynTablePlace`.
- The dynamic table's element codec (`CobolDynTable<T>`), which decides whether a member can be character-image stored.

## Why it was not fixed in the train

Holding a negative zero needs the dynamic table's member to carry its character image, a change to the dynamic-table
storage model (data-model D9), not to the INSPECT arm. That is a redesign beyond the lander's review fix, which only
stopped the compiler crashing (`2014/pb1128_inspect_dynamic_table_element`).

## Landed (wave 1033 H, 2026-10-07, with PB1939: one root)

Re-probed on the wave's build: `-5` in `X(1)` (group member) and in `DN(1)` (elementary element), `REPLACING ALL "5"
BY "0"`, both read back `00{` where the ordinary `N` reads `00}`.

**The design question settled small, against DESIGN-data-model §2.1.** `StorageForm.DynamicTable(Element)` already
named the element's OWN form, and `CharImage` is one; no table-storage redesign was needed. `StorageFormPass.Classify`
now wraps the PROMOTED element form, `DataItem.StoreAsImage` asks the element form, and
`UsageCollectionPass.Channel` no longer skips a `DynTablePlace`, so INSPECT's channel promotes the element exactly as
it promotes an ordinary item (`CobolDynTable<string>`; a group element's member becomes a string field of the
element struct). `InspectEmitter.EmitStore`'s native-value `DynTablePlace` arm is deleted: every numeric
identifier-1 reaching it is now image-stored, and the invariant throw covers the rest.

**Sibling sweep — every character channel into a dynamic element was broken the same way** (re-probed on the
pre-fix build): a group MOVE into an elementary element (`MOVE G TO DN (1)`) stopped the run unit as a Tier-C island
because `MoveEmitter.EmitGroupToElementaryMove` asked the ENTRY's `IsImageCapable` (false on the table's dynamic
axis) instead of the operand's `Place.ImageCapable` (kb/Work PB189's rule) — fixed; a BY REFERENCE argument the
callee filled from a group read back `000`; a reference-modified store read back `013` for `1X3`; and a figurative
fill (`MOVE SPACES TO DN (1)`, pre-2023) stopped the run unit as "without image-backed storage". All now hold their
characters.

Witnesses: `conformance:2014/pb2004_dyn_element_character_channels` (N1-N4, M, C, R) and the floor
`negative/pb2004-dyn-element-inspect-sign-2002`.

## Landing — for the next implementer

- `src/Cobol.Net.Compiler/Binding/Passes/UsageCollectionPass.cs#Channel` — every channel place but a Tier-B window
  names its item, a `DynTablePlace` included; `StorageFormPass.Classify` turns that into a `CobolDynTable<string>`.
- `src/Cobol.Net.Compiler/CodeGen/Verbs/InspectEmitter.cs#EmitStore` — no dynamic arm: a native numeric identifier-1
  is the invariant throw.
- `src/Cobol.Net.Compiler/CodeGen/Verbs/MoveEmitter.cs#EmitGroupToElementaryMove` — asks `Place.ImageCapable` (the
  operand), never `DataItem.IsImageCapable` (the entry, false on a dynamic table's axis; kb/Work PB189).
