# PB446 — five over-acceptances in the SEARCH formats, and a phrase the binder throws away

Adjudicated in lane-3 batch b2 (`search-statement` part 1, findings search-p1-F5 and search-p1-F6).
**All five re-measured on HEAD 89044aa0.** The printed diagram was **rendered** before the finding was
written — PDF page 750 (printed folio 720) at 300dpi — because the project's own history is that OCR'd
diagrams skewed toward falsely-**restrictive** syntax, so a finding that the grammar is too **loose** has to
rule out the opposite error first. The render **confirms** the transcription in `specs/ISO_COBOL.md` rather
than correcting it.

## 1. The mechanism

Five divergences, each caused by a grammar rule written to a looser shape than the printed diagram:

* **(a) A `KEY IS` phrase that exists nowhere in the standard, and that nothing reads.**
  `searchAllKeyPhrase : KEY IS dataReference` (`CobolControlFlow.g4:249`) is wired into `searchAllStatement`
  at `:244`, so `SEARCH ALL table KEY IS k …` parses — and `BindSearchAll`
  (`SearchBinder.cs:81-117`) **never calls `s.searchAllKeyPhrase()`**. The phrase is dropped on the floor
  between the parser and the bound tree. That is the worst of the three possible behaviours: not rejected,
  not honoured, silently accepted and ignored. A user who writes `KEY IS K2` to search on the second key gets
  a search that ignores the phrase entirely, with nothing in the compile output to say so. It is also a drift
  hazard on its own account — a grammar rule no binder reads has never been contradicted by anything, so it
  will keep passing every gate.
* **(b)** `searchAllWhenClause+` (`:245`) admits N WHEN phrases where Format 2 has exactly **one**: the
  ellipsis in the printed diagram sits on the AND **bracket**, not on the WHEN brace.
* **(c)** `searchAllWhenClause : WHEN condition statementBlock*` (`:253`) substitutes the compiler's general
  `condition` rule for Format 2's closed operand shape, so any relational operator, OR, class and sign
  conditions and arbitrary operands are accepted. (Format 1's own syntax rule 6 *does* grant that latitude,
  which is presumably how the Format-2 rule inherited it — tighten one arm, not both.)
* **(d)** Both WHEN rules end `statementBlock*` (`:223`, `:254`), making the printed
  `{ imperative-statement-2 | NEXT SENTENCE }` **brace** optional.
* **(e)** `searchAtEndClause` (`:232-235`) carries `(NOT AT? END statementBlock)?`. NOT AT END belongs to
  READ/RETURN and appears in neither SEARCH format — and because the rule is **shared** between
  `searchStatement` and `searchAllStatement`, the extension is admitted on both formats at once. The binder
  rejects it only at run time.

None of the five is gated by dialect or edition: it is the shape of the grammar, so no `--std` setting reaches
it. All five were measured at 85, 2002, 2014 and 2023.

## 2. The rules, quoted, with their `--check` lines

The load-bearing facts here are **bracketing facts in a figure**, which is why the page was rendered rather
than cited from prose. Three of them decide the finding and all three are visible in the render:

1. NOT AT END appears **nowhere** in either format;
2. the Format-2 ellipsis is attached to the **AND bracket**, not to the WHEN brace, so Format 2 carries
   exactly one WHEN whose AND phrase repeats — while in Format 1 the ellipsis sits **outside** the WHEN brace,
   so the whole WHEN group repeats;
3. the trailing `{ imperative-statement-2 | NEXT SENTENCE }` is a **brace** — a required choice — in both
   formats.

```
$ python scripts/spec/cite.py --check 14.9.37.2 "NEXT SENTENCE is an archaic feature"
OK  §14.9.37.2   (General formats)

$ python scripts/spec/cite.py --check 14.9.37.3 "The OCCURS clause associated with identifier-1 shall contain the KEY phrase"
OK  §14.9.37.3 7)  (Syntax rules)

$ python scripts/spec/cite.py --check 5.2.3 "Optional words"
OK  §5.2.3   (Optional words)

$ python scripts/spec/cite.py --check 4.2.2 "An implementation shall provide a warning mechanism that optionally may be invoked by the user at compile time to indicate violations of the general formats and the explicit syntax rules of standard COBOL"
OK  §4.2.2   (Acceptance of standard language elements)
```

The syntax rule quoted second is the one that shows where a KEY phrase legitimately lives: **the OCCURS
clause**, not the SEARCH statement. And the obligation in `§4.2.2` covers general-format violations in the
same sentence as syntax-rule violations, which is why an over-lenient grammar is a conformance defect and not
a convenience.

**What CONFORMS, checked in the same pass so the finding is not a blanket claim:** phrase order in both
formats; `VARYING { identifier-2 | index-name-1 }` (`dataReference` covers both, and `BindSearch:41-50` splits
same-table index / other-table index / data item correctly); `AT?` — AT is printed **without** an underline, so
it is an optional word and the AT-less spelling is conforming, which the grammar comment at `:226-228` gets
right and states with its own measurement; `searchWhenClause+` for Format 1; the optional END-SEARCH.

## 3. Expected vs observed, re-measured on HEAD

Compiler at 89044aa0, `--std 2023 --run`. **Every one of these must draw a compile-time general-format
diagnostic.**

```
(a) $ cobol sa_keyphrase.cob --run      ← SEARCH ALL E KEY IS K … WHEN K(IX) = 05 …
    exit=0   HIT 03
    $ cobol sa_ok.cob --run             ← the same program WITHOUT the KEY phrase
    exit=0   HIT 03                     ← byte-identical: nothing distinguishes "honoured" from "discarded"

(b) $ cobol sa_multiwhen.cob --run      ← two WHEN phrases on a SEARCH ALL
    exit=0   HIT5                       ← accepted; only the first is honoured

(c) $ cobol sa_greater.cob --run        ← WHEN K(IX) > 04   (Format 2 admits only equality)
    exit=0   HITGT 03
    (sr9_cn_range.cob shows a THRU condition-name accepted in the same position)

(d) $ cobol fmt_emptywhen.cob --run     ← SEARCH E AT END … WHEN K(IX) = 03 END-SEARCH, EMPTY WHEN arm
    exit=0   DONE                       ← the required brace is optional in practice

(e) $ cobol sa_notatend.cob --run       ← SEARCH ALL E AT END … NOT AT END … WHEN …
    exit=3762504530
    Unhandled exception. CobolNet.Runtime.NotImplementedCobolFeatureException: … SEARCH NOT AT END
    (non-ISO extension)                 ← it PARSES; the rejection arrives only at RUN time, compile is silent
```

Read confirmation for (a): `searchAllKeyPhrase` is defined at `CobolControlFlow.g4:249`, referenced at `:244`,
and appears in no `.cs` file outside the generated parser. It was found by reading `BindSearchAll` for the
calls it does **not** make — the shape a citation-and-name dossier cannot show, because deadness is a dataflow
property.

⛔ **The test file named for this row is a vacuous green gate.**
`tests/CobolSharp.Tests.Unit/Overlenient/M421_OverlenientSearchTests.cs` exists and its three `[Fact]` methods
are named for exactly these divergences — `Rejects_SearchMissingWhen`, `Rejects_SearchWithMultipleAtEnd`,
`Rejects_SearchInvalidVaryingPhrase` — and **all three bodies are empty**. Verified on HEAD: the file is 20
lines and contains no assertions at all. It passes without ever looking at anything, and it is the reason this
row could sit at DIVERGES behind a green suite.

## 4. The code site and the shape of the repair

* `src/Cobol.Net.Frontend/Grammar/Core/CobolControlFlow.g4:232-235` `searchAtEndClause` — the `NOT AT? END`
  arm, **shared by both formats**.
* `:245` `searchAllWhenClause+` — should be exactly one.
* `:253-255` `searchAllWhenClause` — the general `condition` where Format 2 has a closed operand shape, and the
  `statementBlock*` where the format has a required brace.
* `:222-224` `searchWhenClause` — the same `statementBlock*`.
* `:244`, `:249` `searchAllKeyPhrase` — defined, referenced, and read by nobody.
* `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/SearchBinder.cs:55` and `:96` — the two run-time NOT AT END
  rejections.
* `tests/CobolSharp.Tests.Unit/Overlenient/M421_OverlenientSearchTests.cs` — three empty facts.

**Repair shape.** (i) Split `searchAtEndClause` so the NOT arm is not shared — or better, delete the NOT arm
outright and let each statement that genuinely has one declare it, which is what stops a READ/RETURN phrase
leaking into SEARCH again. (ii) Give Format 2 its own WHEN rule matching the printed operand shape
(`data-name-1 {IS EQUAL TO | IS =} {identifier-3 | literal-1 | arithmetic-expression-1}` or a bare
`condition-name-1`, with a repeated AND phrase) — this is also the **precondition for PB445's key model**, so
the two land together. (iii) Make the trailing imperative/NEXT SENTENCE choice required in both WHEN rules.
(iv) Delete `searchAllKeyPhrase`; if the owner instead wants it kept as a documented vendor extension (IBM
Enterprise COBOL has no such phrase either — this appears to be home-grown), it must at minimum be
dialect-gated **and bound**. Silently discarding a phrase the user wrote is not an option under any reading.
(v) Fill in the three empty facts with the measured programs above, so the row cannot go green again without
being looked at.

## 5. The sibling sweep the fixer must do

* **Every rule shared between two statements' formats.** `searchAtEndClause` leaked a READ/RETURN phrase into
  both SEARCH formats through one shared reference; grep the grammar for other clause rules referenced from
  more than one statement and check each against both printed diagrams.
* **Every `statementBlock*` where the printed format has a brace.** The optional-where-required inversion
  appears twice here; it is a transcription habit, not a SEARCH accident.
* **⛔ Every empty `[Fact]` in `tests/CobolSharp.Tests.Unit/Overlenient/`.** M421 is unlikely to be the only
  one, and each is a green gate that has never looked at anything. Sweep the directory before trusting any
  "this row is covered" claim.
* **Every grammar rule with no `.cs` reader.** `searchAllKeyPhrase` was found by hand; a mechanical check
  (every parser rule accessor is called somewhere, or the rule is deleted) is the drift test this class of
  defect wants, per CLAUDE.md rule 5's "prefer the shape that makes the NEXT case automatic".
* **Editions.** All five reproduce at 85, 2002, 2014 and 2023 — the grammar is not edition-gated here, so the
  tightening needs the full edition-gate sweep.
