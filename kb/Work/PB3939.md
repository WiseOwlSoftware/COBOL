# PB3939 — upstream_findings never calls check_base_agrees

**Sites:** `scripts/spec/work.py#upstream_findings`, `scripts/spec/work.py#check_base_agrees`,
`scripts/spec/work.py#self_test`, `kb/Work.base`

## The defect

The docstring of `upstream_findings` (line 1647 when the review was made) says the function is the drift test of the
`upstream` kind and that it checks that the shipped `kb/Work.base` and the planner-facing exclusions agree
(`check_base_agrees`). The body does not call `check_base_agrees`. What it does check is the note-level rules
(`upstream_problems` through `register_problems`), that an upstream record is outside `actionable`, and that it is in no
cluster.

The three `Work.base` arms added for the kind (the `Upstream records` view selecting `kind == "upstream"`, the
`kind != "upstream"` exclusion in `Open but no harm flag set`, and a displayed `note.<key>` property for every
`UPSTREAM_KEYS` entry) therefore run only in `work.py check`, against the shipped file. `work.py --self-test` has no
falsifying case for any of them: deleting an arm from a copy of `kb/Work.base` is never shown to be caught, so a later edit
of `check_base_agrees` that silently stops testing one of them passes the self-test.

## The fix

Make `upstream_findings` do what its docstring says: run `check_base_agrees` over the shipped `kb/Work.base` and report
its findings, and add falsifying cases that feed `check_base_agrees` a copy of the file with each of the three arms removed
in turn (the view, the exclusion, one `note.<key>` property) and require a problem naming that arm. Otherwise correct the
docstring; the first is the one the other drift tests of the register follow.

## Landed (2026-10-27, the PB3838 tier 4 branch `worktree-wf_215c061b-df5-1`, its CONFLICT finisher)

`check_base_agrees` takes the file it reads (`base`, the shipped `kb/Work.base` by default), and `upstream_findings` now does what its docstring says: it reports `check_base_agrees` over the shipped file and feeds it a copy with each of the kind's three arms removed in turn (the `Upstream records` view's `kind == "upstream"`, the `kind != "upstream"` exclusion in `Open but no harm flag set`, the `note.upstream_ref` property), requiring a problem that names the arm; an arm the shipped file no longer spells is itself a finding, so the case never measures nothing. Each arm's case is killed by a mutant that drops its check.
