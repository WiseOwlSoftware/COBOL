# PB893 — OPEN — an inline per-operand dispatch with no "end of this implicit statement" landing

Source: the `PB419` report, "New defects".

## The rule

```
$ python scripts/spec/cite.py --check 14.9.6.4 "processing resumes at the next implicit CLOSE statement, if any"
  OK  §14.9.6.4 10)  (General rules)
      10) If more than one file-name-1 is specified in a CLOSE statement, the result of executing this CLOSE
      statement is the same as if a separate CLOSE statement had been written for each file-name-1 in the
      same order as sp...
```

GR10 decomposes `CLOSE A B` into two CLOSE statements. When a declarative resumes NEXT STATEMENT out of the
condition raised by the first, "the next statement" is the SECOND implicit CLOSE — **the remainder of the
first must not run.**

## The code site

`src/Cobol.Net.Compiler/CodeGen/Verbs/SequentialIoEmitter.cs#EmitClose`:

```csharp
if (c.ReportNotTerminatedCheck && ...reports is { Count: > 0 } reports)
{
    using (w.Block($"if ({...IsActive...})"))
    {
        w.Line("ExceptionState.Set(\"EC-REPORT-NOT-TERMINATED\", fatal: false);   // §14.9.6.4 GR5");
        int id = ctx.Names.NextEc();
        w.Line($"int __r{id} = {ec.EcDispatchExpr(...)};");
        w.Line(dispatch.ResumeTransfer($"__r{id}", ""));
    }
}
w.Line($"{RuntimeApi.FileClose(FileKeyExpr(file), kind)};");     // <-- reached on EVERY path
EmitStoreFileStatus(file);
EmitUseHook(file);
```

`ResumeTransfer`'s `-2` arm (RESUME NEXT STATEMENT) falls out of the `if` block and straight into
`FileClose` for the same file.

## Repro shape (NOT measured end to end)

A report file with an INITIATEd, un-TERMINATEd report; `>>TURN EC-REPORT-NOT-TERMINATED CHECKING ON`;
`CLOSE RPTF OTHERF`; a declarative resuming NEXT STATEMENT. Owed: `RPTF` stays open and `OTHERF` closes.
Observed (per the PB419 implementer, and structurally certain from the emitted text above): `RPTF` closes.
The fixer writes the golden first.

## The remedy — a landing, not a flag

An **inline** per-operand dispatch needs an "end of THIS implicit statement" label to jump to, which a bound
node series cannot supply. `EmitUseHook` already has exactly that idiom for SORT/MERGE
(`notNormalLabel`/`goto`). The repair is to give each implicit operand statement its own landing and have the
`-2` arm branch to it.

## The sibling sweep — this is the note's real scope

**Every inline `-2`-falls-through arm in the I-O emitters is the same defect.** The fixer enumerates every
`ResumeTransfer` call site inside a per-operand loop in `SequentialIoEmitter`, `RelativeIoEmitter`,
`IndexedIoEmitter` and the report-writer emitters, and gives them all the same landing — CLOSE is the one
that was found, not the only one. A drift test asserting that no `ResumeTransfer` inside a per-operand loop
is followed by unconditional operand code is what makes the next one automatic.
