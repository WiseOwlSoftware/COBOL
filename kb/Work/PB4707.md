# PB4707 — BindBareOperandStandalone does not judge as BindCondition does

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/ConditionBinder.cs:697` (`ConditionBinder.BindBareOperandStandalone`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/ConditionBinder.cs:718` (`ConditionBinder.BindBareOperandStandalone`, `ConditionBinder.BindSoleOperandCondition`)

Reported by the branch review, not probed. Copied from the PB4627 report (wave 20261868 g):

R1-1: `BindBareOperandStandalone` asks `ins.Active` before `ins.BooleanRelation`, in the opposite order to `BindSoleOperandCondition`, so a bare operand after a stated boolean relation is not judged as `BindCondition` judges it (the doc comment and the report claim it is): the address arm (line 697) never asks `BooleanRelation`, and the value/class-name arms (lines 710, 714) miss the boolean-expression relation, which `BindPrimaryBoolean` records with `BooleanRelation` true and no Subject.

R1-2: the walk's default arm ends the insertion for a boolean operand but never asks the section 8.8.4.3.3 SR1 length-1 screen (`AsCondition` / `BindSimpleBooleanCondition`), although the new doc comment says the walk judges the written condition as `BindCondition` does and that the analysis has already bound the operand; `AnalyzeBareOperand` binds it unwrapped and the screen lives only in the wrapper.
