# PB4566 - an unsited ready defect was planned by no wave

**Sites:** `scripts/orchestrator/clusters.py#fold_unsited`, `scripts/orchestrator/clusters.py#run_fix_clusters`,
`scripts/orchestrator/plan_wave.py#main`, `scripts/spec/ledger_plan.py#group_sizes`

**What happened.** On 2026-11-03 the owner asked to fix the ten open compiler defects. PB3600 and PB3957 were open,
unblocked and listed by `work.py next`, and the operator steered two waves to them (20261850, 20261851). Neither wave
planned them, and `plan_wave.py --dry-run` did not mention them at all: not as a group, not as waiting.

**Why.** `fix_clusters.py` (the public base, `tools/claude-skills`) resolves a note's sites only against
`.agent-fleet.json`'s `src` (`src/WiseOwl.Cobol.*`) and `ext` (`.cs,.g4`). Both notes are sited in compiler data files
under `tests/version-matrix/`, so it listed them under `unsited`. `clusters.run_fix_clusters` returned that list beside
`clusters`, and `plan_wave.py`'s `fix_clusters()` kept `["clusters"]` only, so an unsited note left the plan silently.
The ledger read the same call and counted each unsited note as a group of one (`ledger_plan.group_sizes`), so the page
promised work no planner would do. The campaign lane already had the right rule (`campaign_clusters`: "a note declaring
no site file is a group of its own").

**Fix (landed).** `clusters.fold_unsited` turns every unsited note into a one-note group carrying its own harm, area and
title, and returns `clusters` only, so no reader sees an `unsited` list it could drop. `run_fix_clusters` returns the
folded result, and `plan_wave.py`'s `--clusters-json` path folds a given file the same way. `ledger_plan.group_sizes`
loses its separate unsited count, because those notes now arrive as clusters. The group's collision set is still its
note's DECLARED set (`declare_fix_lane`), so the partition works as for any cluster. Witness:
`test_plan_wave.py` ("fold_unsited: ..." and "... and the folded note is PLANNED as a group of its own"), and the real
dry run at 1b7b9f19a planned PB3600 and PB3957 as groups A and B.

**Sibling (filed as PB4567).** `fix_clusters.sites` cannot match a hyphenated file stem, so `reserved-words.json` would
not resolve even with `tests/version-matrix` and `.json` in the population. That bug is in the public base.
