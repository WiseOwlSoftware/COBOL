# PB3166 — REDEFINES of a GROUP-USAGE BIT group does not compile

Source: `E:\COBOL-coord\scratch\reports\w1078e-PB3158-report.md`, item 1.

- Repro: `E:\COBOL-coord\scratch\w1078e\p5.cob` (`05 RSUB GROUP-USAGE BIT ...` then `05 RSUB2 REDEFINES RSUB GROUP-USAGE BIT ...`). Also reproduces on an Oct-13 build, with or without ALIGNED.
- Observed: backend CS0103 "'RSUB' does not exist" at the generated struct.
- Rule (reporter's citation; run `cite.py --check` before use): §13.18.44 REDEFINES over a group item.
- Code site (reporter): record-struct / Tier-B emission for a redefined bit group; not BitLayout. Look at PhysicalModel / GroupImageCodec naming of a redefined bit group.

## Landed 2026-10-14 (w1080 D)

Re-probed on a fresh build: the repro (`w1078e/p5.cob`, free form) reproduced backend CS0103 "'RSUB' does not exist" at the
record struct's `AsImage()` / `FromImage`. The note's code-site guess ("not BitLayout") was half right, and the defect is wider
than its title: no group and no ALIGNED needed. ANY redefined USAGE BIT item (leaf or GROUP-USAGE BIT group) that shares a
byte with a same-level bit neighbour reproduced it (`05 RA PIC 1(2) BIT. 05 RB PIC 1(6) BIT. 05 RB2 REDEFINES RB PIC 1(2)
BIT.`, and the same inside a GROUP-USAGE BIT group), while the same redefinition after a character item (no shared byte)
already compiled.

**Mechanism 1 (the note).** A Tier-B redefines class has no field of its canonical's name, only the class's string backing
`_redef_<canonical>` (packed bits of the canonical's own extent, windows at bit offsets, 13.18.44.4 GR1). The 8.5.1.6.3 run law
(`BitLayout.RunsOf`) still counted the canonical as a run member, so (a) `PhysicalModel.BuildPhysicals` yielded the backing as
an extra byte field beside the run's slice (the image one byte wider than the storage) and (b) `GroupImageCodec`'s run carrier
and distributor (`BitCarrierOf`, `EmitRunMemberFromBits`, hence `AsImage` / `FromImage` / `AsBits` / `FromBits`) named
`m.CsName` of a field that does not exist. Fix at the shared point: the backing IS the run member's field (leader: the run's
slice; continuation: width 0), and the two codec sites read and write it through one `BackingOf(m)` test (`CobolBits.ReadWindow`
/ `WriteWindow` at bit 0). Rejected alternative: merging the neighbours into the class (a union of classes in
`RedefinesModel`); the backing already holds exactly the canonical's bits and the run packer composes the rest.

**Mechanism 2 (sibling found in the same file, I9).** `BitLayout.RunsOf` ended a run AT a redefining sibling and started a new
run after it, while `Walk` (extent, `StartBitWithin`, `ChildStarts`) keeps its predecessor across the redefiner. For
`05 B PIC 1(6) VALUE B"101010". 05 B2 REDEFINES B PIC 1(2). 05 C PIC 1(2) VALUE B"11".` LENGTH and every window put C at bit 6
of the byte, but the image and the seed made C the leader of a run of its own, a byte later: C's VALUE fell off the group's
image (silent wrong answer: C read 00 and ORD of the byte 169, spec 172). `RunsOf` now scans the non-redefining siblings only.

Goldens: `2002/pb3166_redefines_bit_item_in_shared_byte` (group canonical after a bit leaf, leaf in mid run, a leader with a
continuation past the redefiner, a bit-group parent, group MOVE and a write through the shorter redefiner) and
`negative/pb3166-redefines-bit-item-below-2002` (COBOLNET0900 at 85). `BitRunImageDriftTests` rows BRD11 / BRD12 pin the
alias-vs-plain twin on both shapes. Docs: `COBOLNET_DATA_MODEL_DESIGN.md` run section. Probed unaffected: an OCCURS DEPENDING
holder, a table element struct, an FD record round trip. No inventory row claimed or closed.
