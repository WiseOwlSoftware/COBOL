# PB4061 — a SCREEN SECTION TO / USING item is not counted as written by the runtime

**Sites:** `scripts/fuzz_undefined.py#DataDivision`, `scripts/fuzz_undefined.py#undefined_results`

(The code lives on PR #773's branch `worktree-wf_484eb705-564-28` and reaches main when PB3862 lands. It is not on main at filing.)

PB3862's review-round fix (35b5937f0) makes a data item defined when a section the runtime acts on names it, and collects
those names in `DataDivision.preamble`, the tokens BEFORE WORKING-STORAGE (ENVIRONMENT DIVISION, FILE SECTION: FILE STATUS,
RELATIVE KEY, CRT STATUS, CURSOR). `undefined_results` touches each preamble word (`scripts/fuzz_undefined.py:536`).
The SCREEN SECTION follows WORKING-STORAGE, so it is outside that slice: an item named by a screen entry's TO or USING
clause, which `ACCEPT screen-name` writes at run time, is still reported `UNWRITTEN_STORAGE`, a false proof (a wrong answer of
the fuzz tool, not of the compiler). It is the sibling arm of the same rule: the runtime, not a statement, writes the item.

**Fix shape.** Collect the names the runtime acts on from every section that names data items for it, as one structure
(`DataDivision` slices by section, not "before WORKING-STORAGE"), so the next such section is automatic. Test arms, each seen
RED first: a screen entry with TO, one with USING, and the counter-case (an item no screen entry names stays reported). Which
screen clauses write (TO, USING) and which only read (FROM) comes from the ISO SCREEN SECTION and ACCEPT rules: whoever fixes
this derives them and runs `cite.py --check`; no clause is cited here.
