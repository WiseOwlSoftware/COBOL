# PB711 — OPEN — a correct rejection with the wrong rule written on it

Found 2026-09-05 by the `PB703` implementer (report, "New defect (note-ready paragraph)") while re-deriving the
Format-3 PERFORM syntax rules its own change touched. Confirmed here by reading the emit site.

## The facts

- The rule. `python scripts/spec/cite.py --check 14.9.28.3 "it shall not be specified more than once in any of
  the WHEN phrases"` → `OK §14.9.28.3 14) (Syntax rules)`. Printed: *"If file-name-1 or file-name-2 is specified
  in a WHEN phrase, it shall not be specified more than once in any of the WHEN phrases within the scope of a
  format 3 PERFORM statement unless all such instances are specified …"*. The boundary is the **whole format-3
  PERFORM** and the unit counted is an **occurrence**, not a phrase.
- The check implements exactly that. `EcBinder.CheckSr14Sr15`
  (`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/EcBinder.ExceptionPerform.cs:213-218`) groups the census by
  file-name and rejects a group of more than one that contains any bare (unpaired) instance. The census is built
  one row per OPERAND in `ResolveWhenOperands` — the `WHEN EXCEPTION file-name-1 …` arm (`:160-166`) adds
  `(null, file)` per file-name, so two file-names inside ONE `WHEN` phrase are two rows.
- The message does not. It reads `file-name 'F' is specified in more than one WHEN phrase without an
  exception-name pairing (ISO §14.9.28.3 SR14)`. `PERFORM … WHEN EXCEPTION F F … END-PERFORM` parses
  (`CobolControlFlow.g4#performWhenModeList` takes `fileName ({whenOperandAhead()}? fileName)*`), is correctly
  rejected by SR14, and has **exactly one** WHEN phrase — so the message states something the program does not
  do, about a rule that never mentioned phrase counts.
- There is no descriptor to correct. `DiagnosticCatalog.cs` does **not** carry COBOLNET1599 (or 1600): its own
  scope note says it catalogues the edition band, the 0899 split and the 1533 reuse, and that the
  "every compiler code → a descriptor" migration is the P7 follow-on. The text lives as a bare string literal at
  the emit site — and a second time, verbatim, in
  `docs/rearchitecture/evidence/PHASE-13-c5-perform-format3-DESIGN.md:268`. One sentence, two homes, no home that
  a drift test can read.
- The twin was checked and is fine. SR15 (`--check 14.9.28.3 "in conjunction with different file-names"` → `OK
  §14.9.28.3 15)`) prints *"All instances of an exception-name shall be specified only once in a format 3 PERFORM
  statement unless done so in conjunction with different file-names"*, and COBOLNET1600's message —
  `exception-name 'X' is specified more than once without a distinct file-name` — draws that boundary correctly.

## Why it matters

No program compiles differently. The harm is the one `feedback_a_real_clause_can_answer_a_different_question`
records in the message register instead of the citation register: the § is right, the rejection is right, and the
sentence a user reads to fix their program describes a different rule. A programmer given "in more than one WHEN
phrase" for a one-WHEN program deletes the wrong thing, or concludes the compiler is broken and reports a false
defect against a correct check. The design-doc copy makes the wrong wording the thing the next reader inherits.

## The fix shape

Say what the check enforces: *"file-name 'F' is specified more than once across the WHEN phrases of this PERFORM
without an exception-name pairing (ISO §14.9.28.3 SR14)"* — occurrences, PERFORM-scoped, matching both the rule
and the census. Prefer the structural fix over the string edit: give COBOLNET1599/1600 real
`DiagnosticCatalog` descriptors (the P7 shape that already exists for the codes it does carry), so the text has
ONE home, `docs/DIAGNOSTICS.md` generation picks it up, and the design-doc table stops being a second copy of a
sentence nothing checks. Update `PHASE-13-c5-perform-format3-DESIGN.md:268` in the same change set (rule 6).

## Sweep

Every diagnostic message that paraphrases its rule rather than quoting its boundary is the same shape. The
mechanical cut is the messages whose text names a SYNTACTIC CONTAINER (`phrase`, `clause`, `statement`,
`entry`) where the cited rule names a SCOPE and a COUNT — start with the Format-3 PERFORM band
(COBOLNET1599–1604) since they were written together, then the other census-style checks. The catalog migration
is what makes the sweep mechanical rather than a grep: a descriptor can be drift-tested against its clause; a
string literal cannot.
