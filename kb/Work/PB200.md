# PB200

Split out of [[PB199]] when that note landed (2026-08-31, DEVLOG 1412). PB199's *defect* — four records still
describing a screen the compiler had deleted — is fixed. This is the half a better filter does not fix.

## The shape

`DisplayUsageUnionDriftTests` was added by PB164 wave 1 for a good reason: a hand-rolled
`{ Category: Numeric, IsFloat: false, Usage: Display }` union had been copy-pasted into several subsystems, each
copy an independent screen nobody re-derived, and the drift test exists so a new copy "cannot appear silently".
It scans `src/`.

**Nothing scans the other side.** When a widening DELETES a screen, the tests that pinned that screen shut are,
by construction, now asserting the old behaviour — and they live in `tests/`, where no drift lock looks. PB164's
F8 widened `UdfBinder.UdfReturningResidue` off the union and onto `DataItem.ElementImageCapable`;
`UdfInvocationTests.ReturningCategories_CarriedVsStaged1510(tag: "BIN")` went on asserting `COBOLNET1510` for a
binary-leaf group, stayed GREEN in the wave's own filtered gate, and surfaced as battery #38's only red.

The sibling lock `TierCRejectionTests` WAS re-derived correctly by waves 1/2/R40 — so this is not a claim that
the project never sweeps its rejection locks. It is a claim that the sweep is currently a HABIT rather than a
MECHANISM, and the one copy that lived in a different subsystem is the one the habit missed.

## Why "pick a better filter" is not the whole answer

Plan §0's rule — *pick the filter from what the change TOUCHES, not from where the new goldens live* — would have
caught this instance, and PB199's landing follows it. But the rule is advice to a human at wave time, and it had
already been written down when PB164 filtered on its goldens anyway. A mechanism does not depend on remembering.

## Candidate shapes (none chosen — this is the analysis, not the design)

1. **Extend the existing drift test's reach.** `DisplayUsageUnionDriftTests` already knows the union's textual
   signature; the same scan over `tests/` would flag a test asserting a diagnostic whose screen no longer
   contains the union. Cheap, but string-shaped and therefore prone to the usual false negatives.
2. **Invert it: a diagnostic-reachability probe.** For each `COBOLNETnnnn` a test asserts is DRAWN, assert the
   emit site still exists and its predicate can still produce it. A test pinning a diagnostic no site can emit is
   a stale pin BY CONSTRUCTION — this generalises past the usage union to every deleted screen, and connects to
   the existing "a dead lookup is also unverified" lesson.
3. **Pair each residue screen with a named registry.** `UdfReturningResidue`'s per-shape reasons are already a
   closed set; if the set were data rather than prose, a test could enumerate it and every pin would have to name
   a member that still exists.

Option 2 is the one that makes the NEXT case automatic (CLAUDE.md rule 5) and is the only one whose cost does not
scale with the number of screens. It also has an obvious failure mode to check before adopting: a diagnostic
emitted from a site the probe cannot statically reach would read as stale when it is live.

## Next action

Decide between the three shapes (or reject the mechanism and record WHY, so the next occurrence is not
re-litigated), then implement with the failure branch fired once — a drift lock that has never gone red is not
evidence of anything (`feedback_green_gates_arent_evidence`).
