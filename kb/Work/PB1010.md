# PB1010 — LANDED

## Repro — measured
`scratchpad/w51a/om.cob --std 2014` → `error COBOLNET0899: class 'W51OC', method 'SHOW': DECLARATIVES inside a method (ISO
§14.2.1) are recognized but not yet implemented`. (At 2023 the probe also draws COBOLNET0902 for its method
WORKING-STORAGE, a separate and correct edition rule.)

## The rule
`OK  §14.2.2 10)` — "Formats 1 and 2 may be specified in a source element if and only if that source element is a
function definition, a function prototype definition, a method definition, a program definition, or a program prototype
definition."

## What the fixer owes
Method declaratives through the same declarative table programs use (USE AFTER EXCEPTION, USE FOR file conditions), with
the method's activation as the scope; goldens for an EC-OO condition and a file condition handled in a method. Not
PB956 (that is BASED data in a class).

## Landed (2026-09-22, wave 55 finisher A, worktree wf_aaa1a00f-895-2)
Re-probed on this build: `scratchpad/w51a/om.cob --std 2014` → COBOLNET0899 "DECLARATIVES inside a method (ISO §14.2.1)
are recognized but not yet implemented". It reproduced exactly. AFTER: `X-OMITTED` / `G-PRESENT G1=AB` /
`  CAUGHT 01=EC-OO-ARG-OMITTED` / `N=01` / `WG1=QQ`. The declarative ran, and RESUME AT NEXT STATEMENT skipped the
statement that referenced the omitted formal.
Rule (`cite.py --check`): OK §14.2.2 10) · OK §14.2.2 12) · OK §14.2.2 13) · OK §14.9.49.4 3) · OK §14.9.49.4 4) a)
· OK §14.2.3 1) · OK §14.9.49.3 4) · OK §14.6.13.1.4 3).
Fix — the method is its own selection scope:
- **Binding.** `StatementBinder.BindMethodRoster` collects each method's declarative sections with
  `ProcedureTableBuilder.CollectMethodDeclaratives`. That uses the same `DeclCollectSection` a program's declaratives
  use. The USE registers are per procedure division, and the sections are declared in the method scope. The sections
  sit at the head of the method's pc slice (`OoMethodBinding.DeclStartPc`/`EntryPc`/`Declaratives`).
  `BinderContext.DeclarativeAtCursor` no longer bounds the scan by the unit's EntryPc, which a class unit cannot supply.
- **Emission.** `OoEmitter.EmitMethod` points the per-unit selection state at the method and calls the ONE
  `DispatchEmitter.EmitUseMachinery` with `asLocal`. `__RunUse`, `__IoCheck`, `__IoCheckEc`, `__EcDispatch`,
  `__EcObjDispatch`, `__EcPerform` and `__RunF3` become local functions. They capture the method's data and shadow the
  class funnels. The method-F3 path's hand-written copy of this machinery is deleted.
- **Runtime-site raises.** A method activation installs its own `INonfatalSelector` (new runtime interface;
  `ICobolProgram` extends it). It installs `NonfatalSelectorFn.None` when it has no selection, and it restores the
  invoker's selector on exit. A method's runtime-site nonfatal raise therefore no longer selects its INVOKER's
  declaratives.
- **File keys.** `UseTierEmitter` labels an object-file key (a per-instance field) with a case guard (CS9135 otherwise).
- **Retired.** Descriptor `oo-method-declaratives` is deleted.
Goldens: `tests/conformance/2002/pb1010_method_declaratives` (PB1010EX/PB1010C/PB1010M) covers:
- Format 1 on an object file;
- Format 3 EC-SIZE with RESUME NEXT;
- Format 4 EO with RESUME AT a method paragraph;
- a sibling method whose failing OPEN runs no one's declarative;
- an invoker EC-ALL declarative that never fires.

The negative `tests/conformance/negative/pb1010-declaratives-outside-method` (reject-at 2002 2014 2023, COBOL0001) is
the "only if" half. Batch `scratchpad/w55a/PB1010/verdicts-pb1010.json` closes SR-14.2.2-10 (CONFORMS; GAP 2128 → 2127).
