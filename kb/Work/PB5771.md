# PB5771 - at --std 85 a relation on a BLANK WHEN ZERO item that holds spaces is evaluated as if the item were zero, where 1985 compares characters

**What is wrong.** A program that tests a blanked item against zero takes the wrong branch. At `--std 85` a relation whose operand is a BLANK WHEN ZERO item holding spaces (`01 WP PIC 9(5) BLANK WHEN ZERO.` after `MOVE 0 TO WP`) is evaluated as if the item were zero, so `IF WP = WZ` (WZ `PIC 9(5) VALUE 0`) is TRUE. 1985 makes the item numeric edited (`§1985:VI.5.4.4 GR2`), a nonnumeric operand, so the relation is the nonnumeric comparison of the characters `     ` and `00000`, which are not equal. The control `IF WX = WZ` (WX a `PIC X(5)` holding the same five spaces) prints `X-NE`, so the compiler compares characters for an alphanumeric item and treats the BLANK WHEN ZERO item differently. The same mechanism was found twice: by a refuter of the witness of `1985-GR-VI.5.4.4-2` and by the reader of that row in the batch-1 code reads (reader's repro `b2e.cob`, `IF W = Z0` prints `EQ`).

**Sites:**
- `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/ConditionRenderer.cs#BlankWhenZeroSenderTest` (the refuter's reading, not re-read line by line by the adjudicator), called from `#RenderRelational` with no test of the edition; other 1985 differences in the same file are gated on `ctx.Data.DialectLevel < 2002`

**1985 rows this note blocks.** `1985-GR-VI.5.4.4-2` (the item is numeric edited) and `1985-GR-VI.6.3.1.1.2-1` (the comparison rule the compiler does not apply to this operand; that row is PARTIAL for another reason too). `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094), so the rows are named here.

**2023 rows whose stored verdict is wrong.** None named: the cause is (a), wrong at 85. The same program prints `EQ` at `--std 2023` too; whether the all-spaces rule (`§2023:13.18.8.4 GR3`) reaches a relation condition at 2023 is 2023's question and is not decided here.

**Rules (each citation checked again with `python scripts/spec/cite.py --check`, verdict OK).**
- `§1985:VI.5.4.4 GR1`: "When the BLANK WHEN ZERO clause is used, the item will contain nothing but spaces if the value of the item is zero."
  `OK  §1985:VI.5.4.4 GR1  (5.4.4 General Rules)  the text is in GR1`
- `§1985:VI.5.4.4 GR2`: "When the BLANK WHEN ZERO clause is used for an item whose PICTURE is numeric, the category of the item is considered to be numeric edited."
  `OK  §1985:VI.5.4.4 GR2  (5.4.4 General Rules)  the text is in GR2`
- `§1985:IV.4.3.3`: "The alphanumeric class includes the categories of alphanumeric edited, numeric edited, and alphanumeric (without editing)." So the item is of class alphanumeric, a nonnumeric operand.
  `OK  §1985:IV.4.3.3  (4.3.3 Concept of Classes of Data)  the text is in the clause`
- `§1985:VI.6.3.1.1.2 GR1` (one numeric and one nonnumeric operand): "the numeric operand is treated as though it were moved to an elementary alphanumeric data item of the same size as the numeric data item (in terms of standard data format characters), and the content of this alphanumeric data item were then compared to the nonnumeric operand."
  `OK  §1985:VI.6.3.1.1.2 GR1  (6.3.1.1.2 Comparison of Nonnumeric Operands)  the text is in GR1`
- Clause VI.5.4.4 has two general rules and no other. 1985 has no rule that an all-spaces item counts as zero. 2023 has one, for a sending item of an operation: `§2023:13.18.8.4 GR3`: "the content of the sending data item is all spaces, the value of the sending data item is considered to be zero".
  `OK  §2023:13.18.8.4 GR3  (General rules)  the text is in GR3`

**Repro** (`E:/COBOL-coord/scratch/my-20261115/about-row-refute/runs/bwzmin/bwzmin.cob`):

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. BWZMIN.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 WP  PIC 9(5) BLANK WHEN ZERO.
       01 WZ  PIC 9(5) VALUE 0.
       01 WX  PIC X(5).
       PROCEDURE DIVISION.
       P1.
           MOVE 0 TO WP.
           MOVE WP TO WX.
           DISPLAY "WP=[" WP "] WX=[" WX "]".
           IF WP = WZ DISPLAY "EQ" ELSE DISPLAY "NE".
           IF WX = WZ DISPLAY "X-EQ" ELSE DISPLAY "X-NE".
           STOP RUN.
```

**Derived for the program.** WP holds five spaces (GR1) and is numeric edited (GR2), so the relation is the nonnumeric comparison; WZ is an integer item, so the relation is legal, and it is compared as the characters `00000`. Five spaces are not equal to `00000` in any collating sequence. **1985 requires the false branch: `NE`.**

**Expected at `--std 85`:** `WP=[     ] WX=[     ]`, then `NE`, then `X-NE`.
**Observed at `--std 85`** (`run_case.py`, exit 0): `WP=[     ] WX=[     ]`, then `EQ`, then `X-NE`.
**At `--std 2023`:** the same observed output; the expectation at 2023 is not decided here (see the 2023 rows paragraph).

**The witness.** `conformance-suite/cases/.../pb509_blank_when_zero_relation` has carried `accept: [85]` since 369468ccc6 (2026-10-16) and expects TRUE for three relations, so it pins the wrong behaviour at 85. Its band loses 85 with the fix (a registrar change). Its 85 expectation is derived from the 1985 text: EQ-NUMITEM, EQ-EDITED and GT-NEG all FALSE by the refuter's derivation; GT-NEG because `§1985:VI.6.3.1.1.2` compares the unsigned characters `00003`. It is not an 85 witness of anything until the fix lands.

**Leads.** What the fix must settle from each edition's own text: which edition first states the all-spaces rule (the 2002 text of the clause was not read), and whether that rule covers a relation condition at all, at 2002 and at 2023.
