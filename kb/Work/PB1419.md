# PB1419 — LANDED

## Landed (wave 1005, group C) - the RETURNING residue list is deleted

**Root cause.** `UdfBinder.UdfReturningResidue` refused whole RETURNING categories with COBOLNET1510 as "named residues", while
every one of them is carried by the CALL RETURNING path the activation shares (`CallEmitter.CrossingOf`,
`CobolArgAdapt.StoreReturn`). Re-probed on the wave tree: with the refusal removed FLOAT, BOOLEAN, INDEX, data pointer, object
reference, strongly typed, internal-REDEFINES and OCCURS DEPENDING group results all activate and read correctly. The residue
text for BOOLEAN predicted a half-wired channel ("MOVE/relations would work while IF f(x) and COMPUTE Format 2 would not") and
that part was real: `ConditionBinder` knew a boolean FUNCTION only through the intrinsic catalog, so a boolean-returning user
function drew COBOLNET1511 in a boolean expression and was not routed as a boolean operand.

**Fix.** The residue method and its caller are deleted (no wrapper, no replacement list). `ConditionBinder.BindBoolOperandValue`
reads a user function's boolean result temp as a `BoundBoolRef` beside the intrinsic `BoundBoolCall`, and
`IsBooleanValueOperand` asks `IsBooleanUserFunction` (the definition `UdfActivate` clones). The green test that held the gap open,
`UdfInvocationTests.ReturningCategories_CarriedVsStaged1510`, is now `ReturningCategories_AreAllCarried` over thirteen categories.
`scripts/semgrep/baseline.json` raw-diagnostic-code-literal 291 to 290.

**Goldens.** `conformance:2002/udf_returning_every_category` (FLT, BOOL, NOT, AND, BIT, IDX, PNUL, PSET, RED, ODO, STR legs) +
negative `pb1419-udf-float-returning-at-85`.

**Not part of this note (leads, consumer routing).** A function-identifier of class pointer / object / index is not accepted as
the SENDER of SET (Formats 1, 5, 7, 8: `SetBinder.BindSetTo` extracts a bare reference, so a function sender is refused as a
literal or expression; the index case is PB1399) and a function-identifier of class object is refused as a CALL USING argument
(the BY CONTENT expression arm). Those are the SET and CALL operand classifiers, not the result temporary.

## Finding — `function-identifier` (rejects-legal-source; rows `GR-8.4.3.2.4-1`)

**Mechanism.** UdfReturningResidue refuses whole RETURNING categories with COBOLNET1510 as 'named residues': FLOAT, BOOLEAN, data-pointer, object-reference, index, strongly-typed group, group with internal REDEFINES, variable-length group, and a group with a pointer or object leaf. These are implementation capability limits shipped as compile errors on legal source. The refusal is pinned GREEN by UdfInvocationTests.ReturningCategories_CarriedVsStaged1510, and no open kb/Work note owns it.

**Repro.** out/probe/function-identifier/p5_gr1_float.cob: FUNCTION-ID FIP5F ... 01 L-R FLOAT-LONG ... RETURNING L-R; COMPUTE WR = FUNCTION FIP5F(3) with WR PIC 9(4)V99 -> COBOLNET1510 'a FLOAT RETURNING item ... is not yet carried'. out/probe/function-identifier/p5b_gr1_bool.cob: RETURNING L-R PIC 1(4) -> COBOLNET1510 'a BOOLEAN RETURNING item is not yet carried'.

**Expected from the spec.** §8.4.3.2.4 GR1: the temporary data item's description, class and category ARE those of the RETURNING item, with no category excluded. p5 compiles and prints R=0001.50, and p5b prints R=1010.

**Observed / reasoning.** UdfActivate calls UdfReturningResidue before building the temp, and every non-null reason becomes COBOLNET1510. COBOLNET1510 has no docs/DIAGNOSTICS.md row. The function-pointer form shares UdfActivate, so it inherits every residue.

**Code site.** src/Cobol.Net.Compiler/Binding/Procedure/Verbs/UdfBinder.cs#UdfReturningResidue

## What the fixer owes

Implement the returning temp for every category (the CALL RETURNING path already carries most of them), delete the residue list and the green tests that pin it (feedback: a green test can hold a gap open).
