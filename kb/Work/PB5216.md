# PB5216 - a reference-modified group item as identifier-3 ... identifier-n of INSPECT (FOR ALL G (1:2), BY G (1:2), CONVERTING G (1:1) TO G (2:1)) is refused COBOL0847: CheckInspectOperandUsage asks whether the BASE item is elementary, where a reference-modified item is an elementary item

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/Validation/StatementValidation.cs` (`CheckInspectOperandUsage`, `IsInspectElementaryCharacterItem`)

**Mechanism.** "Identifier-3, ... , identifier-n must reference an elementary item described, implicitly or explicitly, as USAGE IS DISPLAY." (§1985:VI.6.18.3 SR2), and a reference-modified identifier references a unique data item that "is considered an elementary data item without the JUSTIFIED clause" (§1985:IV.4.3.8.4.4 GR5). A group may be reference modified when its usage is DISPLAY (§1985:IV.4.3.8.4.3 SR1: "Data-name-1 must reference a data item whose usage is DISPLAY."). `StatementValidation.CheckInspectOperandUsage` takes the operand's `Place` but asks `IsInspectElementaryCharacterItem(p.Item)`, the BASE item, so G (1:2) over a group is judged a group and refused. The same G (1:2) is accepted as identifier-1 and as a MOVE sender, and an elementary item reference-modified is accepted in the same position, so only this screen reads the base item. `StatementValidation.AdmitsIntoOperand` in the same file reads the place (`p is RefModPlace`), so the two operand screens disagree on what a reference-modified operand is (kb/Work PB5211 is that screen's own 1985 defect). No edition arm: refused the same at `--std 2023`.

**Found by.** The 1985 refuter pass (2026-11-10; records `E:/COBOL-coord/scratch/refute-85/out/r14.json`, probes `probes-r14/i1.cob`, `i5.cob`, `i6.cob`, `i7.cob`, `i8.cob`): a refuter attacked the CONFORMS verdict of the row below, OVERTURNED it, and the repro was rerun on current main for this note.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the row this note claims is the rule id below.

**Rules (1; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-SR-VI.6.18.3-2` - `§1985:VI.6.18.3 SR2` (refuter: OVERTURNED, harm: rejects-legal-source). "must reference an elementary item described, implicitly or explicitly, as USAGE IS DISPLAY"; §1985:IV.4.3.8.4.4 GR5: "The unique data item is considered an elementary data item without the JUSTIFIED clause". G has implicit usage DISPLAY, so G (1:2) satisfies the rule.

**Observed (current main, the build at 3d12682fd2, rerun 2026-11-10).** exit 65; four diagnostics, at lines 12, 14 and 15 (twice): `error COBOL0847: INSPECT operand 'G(1:2)' shall reference an elementary item described implicitly or explicitly as usage display or national (ISO §2023:14.9.22.3 SR2)` (and `'G(1:1)'`, `'G(2:1)'`). The same at `--std 2023`. Control (`in0.cob`): `INSPECT X TALLYING N FOR ALL Z (1:2)` with Z PIC X(2) runs (`N 04`), and `INSPECT G (1:2) TALLYING N FOR ALL "A"` runs (`N 05`).

**Expected (from the 1985 text).** The program compiles and prints `N 04` and `X BBBBCBBBBB`: G (1:2) is the elementary alphanumeric item "AB" (§1985:IV.4.3.8.4.4 GR5), so it is a valid identifier-3, identifier-5, identifier-6 and identifier-7 (§1985:VI.6.18.3 SR2).

**Fix direction (root cause, CLAUDE.md rule 4).** The operand screens must ask what the REFERENCE is, not what its base item is: a reference-modified place is an elementary item of the base item's usage. Give the place model one reader for "the item this reference denotes" (elementary-ness, usage and, per kb/Work PB5211, the edition's category), and have `CheckInspectOperandUsage`, `AdmitsIntoOperand` and the other operand screens that take a `Place` read it, never `p.Item` directly. Sweep the screens that take a Place and read `.Item` for the same mistake.
