# R30 — an undeclared data-name in a sending position compiles with ZERO diagnostics and throws at run time (the generic unresolved-reference staging)

> Found 2026-08-08 while probing R22's name-collision control (the R22 fix is the CATALOGUED-NAME arm
> only; this is the generic arm it fell through to, measured on the R21-landed tree).

PROBE (2026-08-08): `MOVE NO-SUCH-NAME TO WS-R.` and `DISPLAY NO-SUCH-NAME.` — a name declared NOWHERE —
both compile with zero diagnostics, exit 0, and throw `NotImplementedCobolFeatureException` out of
`Activate()` at RUN time. `MOVE SQRT TO WS-R` (an undeclared name that happens to be a catalogued
intrinsic, MinArgs 1, no argument list) takes the same path. This is the "generic unresolved-reference
staging" the R22 note named in passing: the PB7/DA7 wrong-stage family generalized to ITS ROOT — an
unresolvable reference becomes a staged BoundOperandError/BoundExprError instead of a bind-time
diagnostic, a greenfield development-era posture that is now simply a defect by the product bar. A user
typo in any sending position ships a program that dies in production.

SCOPE TO MEASURE BEFORE FIXING (rule 4 — sweep the family): which reference positions stage rather than
report — MOVE sender (measured), DISPLAY operand (measured), arithmetic operands, subscripts,
conditions, receiving positions (an undeclared RECEIVER may already report — measure, don't assume),
CALL/argument positions. FIX SHAPE: the unresolved-reference fallthrough emits a real diagnostic
(existing family: COBOLNET15xx binder range) at the ONE chokepoint where staging happens today —
never per-position patches; keep any genuinely-unimplemented-feature staging distinct from
"the name does not exist", which is never a feature gap.

## LANDED 2026-08-08

MEASURED FIRST: all ten probed positions staged — MOVE sender/receiver, DISPLAY, COMPUTE operand, IF
relation, ADD, STRING sender, CALL USING, subscript, PERFORM UNTIL — every one compiled exit 0 and died
at run time. The mechanism was ONE line: `ReferenceResolver.Resolve` line ~197, where a name that
resolves to NO item (after unqualified/qualified/OO-property attempts) returned silent null into the
"references then fail loud" staging that is only the right posture for unsupported SHAPES of names that
DID resolve.

THE FIX SPLITS THE QUESTION, not the callers' sites: `Resolve` (demanding) now reports **COBOLNET1639**
at that one arm — "'X' is not defined" when the bare name exists nowhere, "does not uniquely identify"
when qualifiers or an unqualified ambiguity defeat it (§8.4.2.1 "a statement shall contain a reference
that uniquely identifies that resource" / §8.4.2.2; both cite.py-checked) — deduped per source
reference. A new `Probe` form keeps silent null for the NINE call sites that ask "is this a data item?"
with a legal alternative on no: the SET format sniffs (3), the COMPUTE boolean reroute sniffs (3), the
boolean-operand and float-sign predicates (documented diagnostic-free), INVOKE's class-name receiver,
SET's EXCEPTION-OBJECT sender, CALL BY CONTENT's expression arm, and PtrBinder's pointer peek.
`DynTrySetSize` gained the `IndexFieldOf` pre-guard its peek was missing — without it, legal
`SET index-name TO n` would have drawn 1639 through `ResolveReceiving`. Rejected-tier (Tier-C) items
resolve to an ITEM and only fail later at `PlaceForItem`, so the feature-debt staging never reaches the
report arm — a typo and a deferral stay distinct channels by construction.

Probes: all ten positions draw exactly one 1639 (85 and 2023 both); controls stay green — index-name
subscripting, level-88 in IF, float sign condition, INVOKE. Negative fixture `undefined-name-reference`
(reject-at 85 2002 2014 2023, registered). DIAGNOSTICS.md regenerated. Gate: full Unit + full
Conformance + characterization all green (the full legs, not the filtered ones — this change stares at
every reference in the corpus).
