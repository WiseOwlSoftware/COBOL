# PB5354 - numeric-edited receiver of an ALL literal is unpinned at 2002 and later

**Site:** `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/MoveEmitter.cs` (`ConvertSource`, line 871 in the report; `AllLiteralNumber`).

**Source:** review lead R1-2 (low, not blocking at round 1), from `E:/COBOL-coord/scratch/reports/w20262000b-PB5141-report.md` "Review findings".

The PB5176 landing (`AllLiteralNumber`, "numeric-edited now edited at every edition") changed what a digit-only `ALL` literal moved to a numeric-edited receiver stores at 2002, 2014 and `--permissive` 2023: it is now edited from the value the move rule gives, not stored as the repeated characters. The 85 arm has goldens (`1985-GR-VI_6_19_4-4-all-literal`); no golden or test pins the result at any edition above 85, so a regression there passes the gate. The lead does not say the new result is wrong, only that it is unpinned.

**Fix direction:** a golden per edition above 85 for `MOVE ALL "5"` and `MOVE ALL "12"` into ZZ9.99 and 9(3).99, with expected values derived from the cited rule (see PB5351 for the open question on which value the rule gives); confirm the behaviour change against the rule first.
