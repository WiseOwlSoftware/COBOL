# PB447 — Format 1's licensed overshoot, inherited by the format the standard forbids it to

Adjudicated in lane-3 batch b2 (`search-statement` part 2, finding search-p2-F1). **Re-measured on HEAD
89044aa0**, with the Format-1 counterpart that shows the same bytes are correct there.

## 1. The mechanism

`ControlFlowEmitter`'s SEARCH scan advances with `IndexField += 1;` and **then** tests
`if (IndexField > bound)` (`src/Cobol.Net.Compiler/CodeGen/Verbs/ControlFlowEmitter.cs:448-453`); on the
failing test it raises EC-RANGE-SEARCH-NO-MATCH and jumps to the shared AT-END funnel, **leaving the index at
N+1**.

For Format 1 that is exactly right and is positively sanctioned: the serial general rule says the process
repeats *unless the new value for the search index corresponds to a table element outside the permissible
range*, so it contemplates the index holding an out-of-range value at the moment the scan fails.

For Format 2 it is not. The ninth general rule constrains the implementation's **own** varying of the SEARCH
ALL index, and one of its sentences is an explicit range bound. Format 2 reaches the same loop because
`BindSearchAll` sets `BoundSearch.FromStart` (`SearchBinder.cs:111`), and `FromStart` changes only the
**pre-loop** behaviour — `IndexField = 1` at `ControlFlowEmitter.cs:383` and the one-sided initial guard at
`:428-429`. The advance step is untouched by the format. So an unsuccessful SEARCH ALL parks the search index
one past the last occurrence and hands that value to the AT END phrase, which the first general rule makes
part of the SEARCH statement's own execution.

The lower bound is safe (forced to 1, only ever incremented), and the empty-table case is right **by
accident**: the pre-loop guard `1 > 0` fires before any increment.

⛔ This is the register's recurring two-arm shape **inverted**: not one arm fixed and one forgotten, but one
arm's correct behaviour inherited by an arm the standard forbids it to.

```
$ python scripts/spec/cite.py --check 14.9.37.4 "At no time is it set to a value that exceeds the value that corresponds to the last element of the table"
OK  §14.9.37.4 9)  (General rules)

$ python scripts/spec/cite.py --check 14.9.37.4 "unless the new value for the search index corresponds to a table element outside the permissible range of occurrence values"
OK  §14.9.37.4 4)  (General rules)

$ python scripts/spec/cite.py --check 14.9.37.4 "control is transferred to imperative-statement-1 and execution continues according to the rules for each statement specified in imperative-statement-1"
OK  §14.9.37.4 1) b) 1.  (General rules)
```

The two clauses that make this a defect rather than a preference are the second and third: **the same
behaviour is required of Format 1 and forbidden of Format 2**, and one emitter serves both.

**The bound on the claim, stated plainly.** The ninth general rule's later sentence declares the **final
setting** of the search index undefined after an unsuccessful search (Annex A repeats it as an undefined item),
so **no program may RELY on the value**. What the rule does *not* license is the implementation putting the
index outside the table at all, and the difference is concrete and observable: a conforming implementation
leaves a subscript that still addresses a real element; this one leaves a subscript that does not. The
observable below is a value read from outside the table's storage on legal source — that is the wrong answer
being charged, not a claim about *which* in-range value the index should hold.

## 3. Expected vs observed, re-measured on HEAD

Compiler at 89044aa0, `--std 2023 --run`. A five-occurrence table
`05 EL OCCURS 5 ASCENDING KEY IS K INDEXED BY KX. 10 K PIC 9.` filled with K = 1,3,5,7,9, then a SEARCH ALL
for a key that is not present:

```
$ cobol gr9_nomatch_index.cob --run
exit=0
ATEND KX=06        ← inside the AT END phrase.  EXPECTED: a value in 01..05
AFTER KX=06        ← and the value survives the statement

$ cobol gr9_out_of_range_read.cob --run
exit=0
ATEND KX=06
READ K(KX)=[0]     ← `K(KX)` inside AT END silently reads storage OUTSIDE the table
                     EXPECTED: a real element of the table
```

**The Format-1 counterpart, same emitter, and CORRECT there:**

```
$ cobol gr4_serial_final_index.cob --run
exit=0
ATEND IX1=06       ← a serial SEARCH over OCCURS 5; the fourth general rule permits exactly this
```

**Three propositions of the same rule that HOLD, measured:**

```
$ cobol gr8_gr9_all_initial.cob --run   ← KX pre-set to 5 on a 5-element table
exit=0   HIT B / KX=02 KY=08            ← "the initial setting is ignored" holds
$ cobol gr9_empty_odo.cob --run         ← an empty (ODO) table
exit=0   ATEND-EMPTY KX=01 / ES[EC-RANGE-SEARCH-NO-MATCH]
                                        ← the empty case is in range, and the EC is right
```

No diagnostic and no EC-BOUND-SUBSCRIPT appear on the out-of-range read, which is correct — bound checking is
off by default — and is exactly what makes the defect silent.

⚠ Note that `conformance:2023/ec_range_search` does **not** cover the ignored-initial-setting leg: it never
SETs the index before the SEARCH ALL. That leg is measured only by probe.

## 4. The code site and the shape of the repair

* `.../CodeGen/Verbs/ControlFlowEmitter.cs:448-453` — the **shared** advance-and-test step.
* `.../CodeGen/Verbs/ControlFlowEmitter.cs:383` — `if (s.FromStart) w.Line($"{s.IndexField} = 1;");`, the
  initial setting ignored (correct).
* `.../CodeGen/Verbs/ControlFlowEmitter.cs:428-429` — the one-sided initial guard, the *only* place the format
  currently changes the loop's behaviour.
* `.../Binding/Procedure/Verbs/SearchBinder.cs:111` — where Format 2 enters that path via `FromStart: true`.

The repair belongs **in the shared loop and must stay two-armed on purpose**: test the bound *before*
incrementing on the `FromStart` arm (or restore `bound` on its no-match exit) while the serial arm keeps the
N+1 the fourth general rule sanctions. Writing one behaviour for both is what caused this, so the fix is not
"pick the safe one" — it is to make the format's difference explicit at the advance step, where today the
format is invisible.

Pair it with a **drift test**: assert that the search index after an unsuccessful SEARCH ALL is ≤ the
occurrence count. Nothing in the suite looks at that value today, which is why an emitter shared by two rules
with opposite requirements has stayed green.

## 5. The sibling sweep the fixer must do

* **Every place `FromStart` is (or is not) consulted.** It currently reaches `:383` and `:428-429` only. Any
  other behaviour the two formats must differ on is, by construction, currently identical — enumerate them
  against the Format-1 and Format-2 general rules rather than assuming the list is these three.
* **The `AlsoVaried` operand at `:449`.** The VARYING item is incremented in step with the index, so if the
  index overshoots, so does it. That is Format 1 only, where the overshoot is licensed — but confirm, because
  the increment sits between the advance and the test.
* **Other emitters that advance-then-test.** PERFORM VARYING and the INSPECT/STRING scans have the same
  shape; each has its own rule about what the control variable holds on exit. Grep `CodeGen` for `+= 1;`
  immediately followed by a bound test and check each against its clause.
* **Editions.** Measured identical at 85, 2002, 2014 and 2023 — Format 2 is COBOL-85, so this is not
  edition-gated.

## 6. Rows

* `GR-14.9.37.4-9` — PARTIAL. Three of the rule's four normative propositions hold and were measured: the
  implementor latitude for a non-serial technique (a serial probe is inside it, and Annex A says the internal
  procedure need not be documented, so nothing is owed to `docs/CONFORMANCE.md`); the ignored initial setting;
