# PB480 — OPEN — equal signatures imply compatibility; the converse is what the descriptor assumes

Found 2026-09-04 by the `PB204` implementer, which added the third delta and documented it on
`VariableLengthCompatibility.Signature` rather than widening the descriptor inside a mechanism about
something else. Re-derived on this tree for this note.

## The mechanism

`OoConformance.ConformanceDescriptor` (`src/Cobol.Net.Compiler/Oo/OoConformance.cs`) renders each formal
parameter and returning item to a string; the generated `__CobolInvoke` switch compares the caller's
descriptor to the method's for STRING EQUALITY and raises EC-OO-UNIVERSAL on any mismatch
(`src/Cobol.Net.Runtime/Control/CobolInvokeArg.cs`, `CobolObject.cs` — §14.9.23.4 GR7c, runtime conformance
through a universal object reference). Equality of two descriptors is SUFFICIENT for §14.8.2/§14.8.3
conformance and is NOT necessary; every case where the relation accepts two operands whose descriptors differ
is a legal program that raises an exception condition the standard does not specify. Three such cases are
now documented in the code:

1. §14.8.2.2 rule 1's by-reference group-prefix leniency (a smaller formal group) — recorded before PB204.
2. An ANY LENGTH argument meeting a fixed formal — recorded before PB204.
3. (PB204) §8.5.1.12.3 sentence 3 — `python scripts/spec/cite.py --check 8.5.1.12.3 "If one of the
   corresponding tables is not a dynamic-capacity table, that table is treated as though it were a
   dynamic-capacity table"` → OK §8.5.1.12.3 — so a dynamic-capacity table corresponding to a FIXED table is
   compatible, and so are two variable-length groups whose trailing fixed runs differ in length; the `V:`
   descriptor separates both.

Three deltas is the signal that the descriptor wants to become a STRUCTURAL comparison — the same relation
the typed path applies at bind (`OoConformance.DescriptionMismatch`, now routed through
`VariableLengthCompatibility` for variable-length groups) evaluated at run time over a carried description —
rather than a growing list of documented corners where equality is too strict.

## Fix shape

Carry a structured description (the atom sequence `VariableLengthCompatibility` already walks, plus the
elementary facts `DescriptionMismatch` compares) across the universal box instead of a rendered string, and
apply the ONE relation on both sides; the string form may remain as a fast-path equality check that
short-circuits to "conforms" but never to "mismatch". A golden per delta (each currently raising
EC-OO-UNIVERSAL and expected to run) proves the failure branch before the change; the typed-path goldens
prove no wrong acceptance is introduced.
