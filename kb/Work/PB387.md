# PB387 — 45 green tests that cannot fail, and the two IF rows they were supposed to be watching

⚠ **Read the severity as "what one row does", not "how big this is".** The two rows this note owns are
under-rejections (MINOR by the ladder). The mechanism is a *gate that structurally cannot fail*, spanning 15
constructs; two of its 45 name-only claims are measured FALSE against HEAD below, and the other 42 are simply
unmeasured. Fix it at the gate level, not one file at a time.

## THE MECHANISM

`tests/CobolSharp.Tests.Unit/Overlenient/` holds 15 files, each exactly 21 lines: a `using Xunit;`, a namespace,
a sealed class, and three `[Fact]` methods whose bodies are `{ }`. Measured on this tree
(`89044aa0`): **45 facts, 45 empty**. The project is in the solution at `CobolSharp.sln:14`, so xUnit
discovers, runs and reports all 45 as PASSING in every gate run. Every method is named `Rejects_<construct>` —
i.e. every name is a *conformance claim that the compiler refuses something* — and no body ever compiles a
program, so nothing in the suite can distinguish "the compiler rejects it" from "the compiler accepts it
silently". That asymmetry is the defect: a name-based reader (a human checking coverage, this campaign's own
dossier tooling, or any test-map query) sees a green test named for the exact rule it is looking for and stops.
An empty test is the one defect a test suite structurally cannot report about itself.

The corroborating instance of the same shape is
`tests/CobolSharp.Tests.Integration/ConditionTests.cs:122` — a `// ── NEXT SENTENCE ──` section banner with **no
test under it at all**; the next member is an unrelated abbreviated-relation test. Same reading error, different
mechanism: the file looks like it covers NEXT SENTENCE and does not.

A second, quieter fact the fixer must know: this suite lives in `CobolSharp.Tests.Unit`, the **legacy** assembly.
Even fully written, characterization there is against the legacy oracle and cannot close a P14 traceability row
on its own (CLAUDE.md rule 1 — the oracle is a regression net, never authority). The bodies belong in the
greenfield assemblies (`tests/Cobol.Net.Tests.*` / the conformance corpus) with spec-computed expectations.

## THE RULES, QUOTED, EACH `--check`ED ON THIS TREE

The claimed rows are IF's, so both citations are re-derived here, not inherited:

* `python scripts/spec/cite.py --check 14.9.19.3 "Statement-1 and statement-2 represent either one or more
  imperative statements or a conditional statement optionally preceded by one or more imperative statements"`
  → **`OK §14.9.19.3 1)  (Syntax rules)`** — the rule number returned (1) is the one cited, SR1.
* `python scripts/spec/cite.py --check 14.9.19.2 "NEXT SENTENCE is an archaic feature"` →
  **`OK §14.9.19.2  (General formats)`**, which anchors the clause; the format text itself reads
  `IF condition-1 THEN statement-1 [ ELSE statement-2 ] END-IF` (Format 1, `specs/ISO_COBOL.md:24334`), with
  statement-1 **unbracketed** and Format 2 offering it as a **brace alternative**.
* `python scripts/spec/cite.py --check 5.2.6.3 "enclosing a portion of a general format indicate that the syntax
  element contained within the braces or one of the alternatives contained within the braces shall be explicitly
  specified"` → **`OK §5.2.6.3  (Braces)`** — so Format 2's braced arm is not optional either.

So: **statement-1 is required in both formats, statement-2 is required whenever ELSE is written, and SR1 states
the same obligation as a cardinality — "one or more".** Neither is enforced.

## THE CODE SITE, AND THE SHAPE OF THE REPAIR

* `tests/CobolSharp.Tests.Unit/Overlenient/M412…M426*.cs` — 15 files, `:7-20` in each, 45 empty `[Fact]`s.
* `CobolSharp.sln:14` — the project is built and run, so these are counted as passing tests, not dead files.
* `tests/CobolSharp.Tests.Integration/ConditionTests.cs:122` — empty `── NEXT SENTENCE ──` banner.

**Two repairs, and the second is the durable one (CLAUDE.md rule 5 — the shape that makes the next case
automatic):**

1. **A gate that fails on a no-op test.** An `[Fact]`/`[Theory]` whose body contains no `Assert`, no `Throws`,
   and no compile-and-run helper call must be a BUILD ERROR, not a green test. The natural home is a Roslyn
   analyzer or a reflection-based meta-test in `tests/Cobol.Net.Tests.Unit` that enumerates every discovered
   test method in the solution and asserts a non-vacuous body. Write it so it FAILS ONCE against these 45 before
   they are filled (project doctrine: a passing check proves nothing if it never looked at what changed).
2. **Then give the 45 claims real homes** — each as a spec-derived negative expectation naming the exact
   diagnostic code and the exact rejected spelling, in the greenfield/conformance corpus, with the row-closing
   evidence a P14 verdict needs. A claim that turns out to be TRUE today (like `Rejects_ExtraElseBranch`) still
   becomes a real pinned test; a claim that turns out FALSE becomes a `kb/Work/` defect note first.

Deleting the 45 stubs *without* (1) is not a fix — it removes the false green but leaves the shape free to
recur, and the shape has already recurred once inside `ConditionTests.cs`.
