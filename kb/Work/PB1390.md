# PB1390 — LANDED

## Landed (wave 68 s, 2026-09-27, with PB1371 and PB1392)

Re-probed first on the w68s build: all five repro shapes were COBOL0001 / COBOLNET0901 exactly as filed. The fix is
the note's own shape — ONE tail, reachable at every tier's non-first operand:

- **Grammar (`CobolExpressions.g4`).** The condition tiers now come in two spellings that differ in the LEADING element
  only. The leading tiers (`logicalOrExpression` / `logicalXorExpression` / `logicalAndExpression`) hold the first
  simple condition; the operand of EVERY connective is a succeeding tier (`succeedingXorExpression` /
  `succeedingAndExpression` / `succeedingCondition = abbreviatedRelation | unaryLogicalExpression`).
  `abbreviatedAndChain` is deleted. The EVALUATE partial spine takes the same succeeding tails, so its OR tail
  (which reused `abbreviatedAndChain`) inherited the fix. XOR / EXCLUSIVE-OR became the one `xorOperator` rule.
- **Binder.** `ConditionBinder.BindCondition` folds the succeeding tiers with the same `BindFlatSequence`
  (`BindXorSequence` was a one-line wrapper and is gone), so `AbbrevCarry` threads GR1's insertion through every
  shape in source order. The note's premise held: no carry change was needed for the INSERT half.
- **The TERMINATE half had a hole the note did not name.** `A = 1 OR B IS NUMERIC OR < 2` (an abbreviated
  relation after GR1's insertion has terminated) was refused with NO diagnostic and reached the COBOLNET2319
  internal-error net. It is now **COBOLNET2552** `abbreviated-relation-without-subject` (§8.8.4.12.1;
  §8.8.4.12.4 GR1).
- **Siblings.** `SearchAllFormat2Rules.TryConjuncts` read the tier accessors (it names a succeeding tier as the
  connective it is). The legacy oracle's `ConditionBinder` and `ControlFlowBinder` were moved onto the new
  context types. **PB1392** (the XOR gate keyed to one tier, so a partial-expression XOR was ungated below
  2023) is fixed by the same change: the gate now recognizes the `xorOperator` node (`LogicalOperatorGate`).

Probes after the fix (A=1 B=2 C=3 D=1): `OR < C AND D` → F, `OR < C AND NOT D` → T, `XOR < C` → T,
`XOR NOT < C` → F, `OR < C XOR = D` → F, `OR < D AND C = 1` → F, `A = 1 XOR = 2` → T. Each matches its §8.8.4.12.4
expansion. Goldens: `conformance/85/pb1390_abbreviated_tail_and_or` and `conformance/2023/pb1390_abbreviated_tail_xor`
run every shape over all 81 tuples of A..D in 1..3 against the written-out expansion, with 0 disagreements. The
negatives are `pb1390-abbreviated-relation-without-subject` (COBOLNET2552) and `pb1392-partial-xor-below-2023`.
Drift: `PartialExpressionSpineDriftTests` derives the succeeding tiers' tails from the leading tiers, and
`ConditionTierConnectiveDriftTests` pins the one `xorOperator` spelling. Rows closed (batch `w68s`): all four.

**For the next implementer.**
- `CobolExpressions.g4#succeedingCondition`: the operand of every connective. A new connective or condition form goes
  into the leading tier and its succeeding twin together, and `PartialExpressionSpineDriftTests` fails if the tails
  differ. `xorOperator` is the only place the XOR / EXCLUSIVE_OR tokens may appear.
- `ConditionBinder.cs#BindCondition`: every tier folds through `BindFlatSequence`, which skips connective tokens AND
  `XorOperatorContext`. A new rule node placed between operands must be skipped there too.
- `ConditionBinder.cs#BindAbbreviatedRelation`: COBOLNET2552 is where a missing subject is reported. The carry is
  reset by class/sign/88/boolean/parenthesized conditions.
- `SearchAllFormat2Rules.cs#TryConjuncts`: reads the tier accessors directly, so it must move with any tier reshape.
  The legacy `CobolSharp.Compiler` `ConditionBinder` / `ControlFlowBinder` do the same.
- Trap: `XOR (` is mis-lexed (PB1162). Write test expansions without a '(' after XOR.

⚠ **Not this mechanism:** a '(' directly after XOR / EXCLUSIVE-OR (`A = B XOR (C + 1)`) is still lexed as a
subscript opener. That is kb/Work **PB1162** (the lexer's edition-blind subscript trigger), which owns
FMT-8.8.4.11.2. The goldens write XOR's expansion without the operator so that they do not depend on it.

## Finding — `abbreviated-combined-relation-conditions` (rejects-legal-source; rows `FMT-8.8.4.12.2`, `SR-8.8.4.12.1-1`, `SR-8.8.4.12.1-2`)

**Mechanism.** The abbreviated tail is spelled non-uniformly across the three logical tiers of the condition grammar: AND admits `abbreviatedRelation | unaryLogicalExpression`, OR admits `logicalXorExpression | abbreviatedAndChain` where abbreviatedAndChain = abbreviatedRelation (AND abbreviatedRelation)* (no bare / NOT-bare continuation, no XOR), and XOR's right operand is logicalAndExpression, which cannot LEAD with an abbreviatedRelation. The printed format repeats ONE group `{AND|OR|EXCLUSIVE-OR|XOR} {NOT|simple-rel-op|extended-rel-op} object-1` with any connective in any position, so several legal mixes are unparseable.

**Repro.** 01 A PIC 9 VALUE 1. 01 B PIC 9 VALUE 2. 01 C PIC 9 VALUE 3. 01 D PIC 9 VALUE 1.  IF A = B OR < C AND D DISPLAY "T" ELSE DISPLAY "F" END-IF (also --std 85); IF A = B OR < C AND NOT D ...; IF A = B XOR < C ...; IF A = B XOR NOT < C ...; IF A = B OR < C XOR = D ...

**Expected from the spec.** All compile. §8.8.4.12.4 GR1 expansions: (A=B) OR ((A<C) AND (A<D)) = F; (A=B) OR ((A<C) AND NOT (A<D)) = T; (A=B) XOR (A<C) = T; (A=B) XOR (A NOT< C) = F; (A=B) OR ((A<C) XOR (A=D)) = F (XOR binds tighter than OR, §8.8.4.9 precedence).

**Observed / reasoning.** Pinned cobol.exe: COBOL0001 unexpected 'D' / cannot parse near 'D' / unexpected '<' for the first four; COBOLNET0901 "'XOR' is a reserved word in COBOL-2023 and cannot be used as a user-defined word" for the OR<C XOR shapes. The tier shape partialExpression / partialXorExpression / partialAndExpression already demonstrates the fix pattern (a leading-element variant per tier); the abbreviated tail needs the same: every tier's non-first operand may begin with an abbreviatedRelation and continue through the ordinary AND/XOR tiers. EVALUATE partial-expressions reuse abbreviatedAndChain as their OR tail and inherit the same gap (sweep).

**Code site.** src/Cobol.Net.Frontend/Grammar/Core/CobolExpressions.g4#logicalOrExpression / #logicalXorExpression / #logicalAndExpression / #abbreviatedAndChain; mirrored in #partialExpression

## Finding — `complex-combined-conditions` (rejects-legal-source; rows `FMT-8.8.4.12.2`)

**Mechanism.** OUT-OF-SLICE LEAD (row FMT-8.8.4.12.2, not adjudicated here): logicalXorExpression's right operand is logicalAndExpression, which has no abbreviatedRelation / abbreviatedAndChain alternative at its left edge (only the OR tier carries abbreviatedAndChain), so an abbreviated combined relation after XOR / EXCLUSIVE-OR cannot parse although §8.8.4.12.2's format lists EXCLUSIVE-OR and XOR as its connectives.

**Repro.** IF A = 1 XOR = 2 DISPLAY "T" ELSE DISPLAY "F" END-IF / IF A = 1 XOR 2 ... / EVALUATE A WHEN > 5 XOR < 3 ... (probe/ccc/g5.cob, g3.cob, --std 2023).

**Expected from the spec.** With A=1: `A = 1 XOR = 2` means `A = 1 XOR A = 2` -> T; `A = 1 XOR 2` means `A = 1 XOR A = 2` -> T (§8.8.4.12.4 implied insertion).

**Observed / reasoning.** error COBOL0001: unexpected '=' (g5) / unexpected '<' (g3). Registrar should verify against the FMT-8.8.4.12.2 slice before filing.

**Code site.** src/Cobol.Net.Frontend/Grammar/Core/CobolExpressions.g4#logicalXorExpression; src/Cobol.Net.Frontend/Grammar/Core/CobolExpressions.g4#partialXorExpression
