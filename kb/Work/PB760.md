# PB760 — CHARACTER CLASSIFICATION — one rule, two copies, and both read the picture a group does not have

Found 2026-09-06 by **two independent implementers on the same day**, each from its own end and neither aware of
the other's find: the PB741 lander's report ("New defects", item 1 — the class-condition site) and the PB728
implementer's report (`New defects (a)` — the intrinsic site). Two agents in one day is a rate, not an anecdote.
**Filed as ONE note because it is ONE mechanism**: a private two-case copy of the operand-category rule, spelled
identically in two files, each feeding a `__CLASSIFY.For(...)` argument. Fixing either alone leaves the other
answering the opposite way for the same operand.

## The mechanism, at main's line numbers

**Copy 1** — `src/Cobol.Net.Compiler/CodeGen/Emit/ConditionRenderer.cs:77-82`:

```csharp
private static bool IsNationalOperand(BoundOperand op) => op switch
{
    BoundStringLiteral { Category: PicCategory.National } => true,
    BoundFieldOperand { Place.Item.Pic.Category: PicCategory.National } => true,
    _ => false,
};
```

**Copy 2** — `src/Cobol.Net.Compiler/CodeGen/Emit/IntrinsicRenderer.cs:1245-1250` — is the same three lines,
character for character, under a doc comment that states the rule correctly and then does not implement it:
*"Is the operand of class national (its category National) — the CHARACTER CLASSIFICATION's national phrase
governs it (ISO §12.3.6.4 GR5 f–j), the alphanumeric phrase everything else."*

**The consumers**, one per copy:

- `ConditionRenderer.cs:421` —
  `string classify = ctx.Data.Classification is not null ? $", __CLASSIFY.For({(IsNationalOperand(c.Operand) ? "true" : "false")})" : "";`
  threaded into `CobolClass.IsAlphabetic` / `IsAlphabeticUpper` / `IsAlphabeticLower` at `:425-427`.
- `IntrinsicRenderer.cs:1144` — the `UPPER-CASE` / `LOWER-CASE` arm taken *when a CHARACTER CLASSIFICATION is in
  effect and no explicit `LOCALE` phrase overrides it*:
  `RuntimeApi.LocaleFn(sig.RuntimeMethod, $"{Str(ic.Args[0])}, __CLASSIFY.For({(IsNationalArg(ic.Args[0]) ? "true" : "false")})")`.

**Why `Pic` is the wrong reader** — `src/Cobol.Net.Compiler/Binding/Model/DataItem.cs`:

- `:88` — `public bool IsAsIfElementary => Pic is null && GroupUsage is not GroupUsage.None;` — **`Pic` is null
  for every group, by construction**.
- `:69-74` — `AsIfPic` yields `PicCategory.National` for `GroupUsage.National` (and `Boolean` for `Bit`).
- `:83` — `public PicInfo? OperandPic => Pic ?? AsIfPic;`
- `:76-82` — the D20 doc comment on `OperandPic` **forbids exactly these two lines, in so many words**:

  > ⛔ THE ONE READER for an item's OPERAND category (D20) … Every site that decides class, category, a Table 16
  > row, LENGTH positions, ref-mod admissibility, comparison class or string-operand-ness reads THIS — never
  > `Pic` guarded by `IsGroup`.

  The callee was right and two callers ignored it — the same finding PB728's landing records for its own five
  sites. This note is the sixth and seventh.

**And the correct reader is already in the same file.** `ConditionRenderer.cs:287-301`, `StringCategoryOf`, has
**five** arms where the copy has two:

```csharp
BoundStringLiteral sl => sl.Category,
BoundAllLiteral al => al.Category,
BoundFieldOperand { Place: RefModPlace rm } => rm.Category,          // the ONE ref-mod category reader (PB70/PB73)
BoundFieldOperand f => f.Place.Item.OperandPic?.Category,            // THE ONE category reader (D20/PB79)
BoundComputedOperand { Expr: BoundIntrinsicCall { ResultCategory: … } ic } => ic.ResultCategory,
```

So **three operand shapes are invisible to the copy** and visible to the reader twelve lines below it: a national
**GROUP** (`OperandPic`), a national **ref-mod slice** (`RefModPlace.Category`, which carries §8.4.3.3's GR6
rewrites including numeric-national → national), and a national **function result** (`ResultCategory`, e.g.
`FUNCTION NATIONAL-OF(...)`). All three take the alphanumeric classification phrase.

### ⛔ Premise correction — §8.8.4.4.4 GR3 does NOT say what both reports say it says

Both source reports gloss the citation as *"§8.8.4.4.4 GR3 b1/c1/d1 select the classification by the operand's
class"*. **They do not.** Their printed text says only *"LC_CTYPE of the current locale"* — one locale, no
national/alphanumeric split anywhere in §8.8.4.4.4. The split lives in §12.3.6.4 GR5, which establishes the two
classifications, and GR7, which names which operations consume them.

This is precisely `feedback_a_real_clause_can_answer_a_different_question` — a real clause, quoted accurately,
answering a neighbouring question — the shape memory records as hit **3× in one session**. The citation would
have passed `--check` and shipped as the justification. **Cite §8.8.4.4.4 GR3 b) 1. for WHAT the class test
computes, and §12.3.6.4 GR5 f)–j) + GR7 a)/b) for WHICH table it computes it from.** Do not let the first
carry the second's weight.

## The fix shape

⛔ **Not "add a group case to each switch."** Two copies each grown a third arm is the same defect with a longer
body, and CLAUDE.md rule 5 asks for the shape that makes the NEXT case automatic.

1. ⭐ **Preferred — delete both copies and route both sites through the ONE operand-category reader**
   (`feedback_one_rule_one_place`: the extraction IS the fix). `StringCategoryOf` is already that reader, and
   is already correct for all five shapes; it is `private static` inside `ConditionRenderer` where a second file
   needs it. Lift it to the shared operand-text/category surface both renderers already depend on
   (`OperandText` is the natural home — both files call it), and both sites become
   `category is PicCategory.National`. This is exactly the move PB728's landing makes for
   `ConditionRenderer.IsNationalOperand` (*"collapsed … to `StringCategoryOf(op) is PicCategory.National` — one
   line, and strictly more correct"*); **PB760 is that same move for the site PB728 did not reach and for the
   file it could not see from.**
2. **Fallback, if lifting proves to pull too much** — give `IntrinsicRenderer` the delegation and leave
   `StringCategoryOf` where it is. This closes the harm and leaves the *duplication* standing, so it is the
   fallback and not the answer.

**Whichever is chosen, the preventive is the deliverable.** PB728's landing already establishes the mechanism —
a semgrep invariant `cobolnet-condition-category-from-raw-picture` scoped to `ConditionRenderer.cs` — and the
lesson of this note is that a **file-scoped** invariant does not travel: the identical line survived in
`IntrinsicRenderer.cs` because the rule was scoped to the file where it was found, not to the property being
misread. Widen it to every `CodeGen` file: **no `…Item.Pic…Category` read where a group can reach the operand**,
with the category-impossible reads (below) as named, reasoned exemptions rather than silence.

## Goldens

The pair, not the case (`feedback_probe_the_shape_the_subject_hides`): a `CHARACTER CLASSIFICATION` locale whose
**national and alphanumeric LC_CTYPE genuinely differ** — otherwise every leg passes for the wrong reason, which
is exactly why this has been invisible — and, at each of the two sites, a `GROUP-USAGE NATIONAL` group beside its
elementary `PIC N(n)` twin, which must AGREE:

- `IF NG IS ALPHABETIC` / `ALPHABETIC-UPPER` / `ALPHABETIC-LOWER` (all three of GR3 b/c/d take the argument).
- `FUNCTION UPPER-CASE(NG)` and `FUNCTION LOWER-CASE(NG)` (§12.3.6.4 GR7 a).
- The two shapes the copy cannot see and `StringCategoryOf` can: a **ref-mod slice** `NG(1:2)` and a
  **function result** `FUNCTION NATIONAL-OF(...)` in each position.
- **The alphanumeric control that must NOT move** — a plain `PIC X` operand keeps `__CLASSIFY.For(false)`.
- ⛔ **Prove it fails once** (`feedback_green_gates_arent_evidence`): reinstate the two-case switch and watch the
  group legs flip. A golden that never went red against the defect has not been shown to test it.
