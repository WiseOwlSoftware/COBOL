# PB5352 - the READ INTO refusal at 85 cites a 2023 rule

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Model/EditionCite.cs` (`EditionCite.At`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/MoveBinder.cs` (`FromPhraseRules`, `BindIntoPhrase`, `BindFromPhrase`), `src/WiseOwl.Cobol.Compiler/Binding/Bound/BoundTree.cs` (`IntoPhraseRules`; the cite parameter is at line 1401) and `src/WiseOwl.Cobol.Compiler/Binding/Validation/StatementValidation.cs` (`CheckIntoReceiver`, line 1197, which writes the cite into the message). The cite read there is "§2023:14.9.30.3 SR1 / §2023:14.9.34.3 SR2".

**Source:** lead of the PB5141 implementer's report (`E:/COBOL-coord/scratch/reports/w20262000b-PB5141-report.md`, "New defects / leads", second paragraph). Shares its root with PB5211, which added the 85 refusal of `READ INTO WA(1:5)` over PIC A.

The message of the refusal at `--std 85` names the 2023 rule although the 1985 rule is the one in force for that compile; `IntoPhraseRules` carries one cite per verb and no per-edition arm. The behaviour is right and the refusal names the offending item; only the cited rule misattributes (cosmetic; `misleads_diagnosis` is set because the message names a rule of the wrong edition).

**Fix direction:** give `IntoPhraseRules` the edition's own citation (the 1985 READ INTO and RETURN INTO rules; locate each with `scripts/spec/where.py`, check each with `cite.py --check` in the 1985 edition form), so a diagnostic cites the edition it compiles under; sweep the other `*Cite` members of the record for the same shape. Unverified: the locator "§2023:14.9.30.3 SR1" itself, because `cite.py --check` refuses a quotation under four words and none was available; re-derive it when fixing.
