# PB3117 — the landing lane's runner opened console windows on the owner's desktop

> ⚙ **flags:** process-only

Source: the owner, 2026-10-12 ~22:20, to the operator: "You keep spawning terminal windows. Two issues: First, they
steal focus from what I'm working on . Second, one of them is hung on my desktop", and "Usually, the terminal windows
briefly appear for less than a second, then go away".

## Cause

`scripts/orchestrator/land_lane.py#spawn` (PB3103, landed PR 18, live from 18:25) started each landing runner with
`DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP`. A `DETACHED_PROCESS` child has no console at all. Windows therefore
gives every console program that runner starts a NEW console, and the machine's default terminal is Windows
Terminal, so each new console opens a window and takes the foreground:

- a brief flash for each short command (`git`, `python`, `pwsh`);
- one long-lived blank window titled `python.exe` for `enqueue.py land` itself, whose output goes to the attempt
  log. At 22:20 the window over `notes-PB3114-w1070`'s gate (`OpenConsole.exe -Embedding`, started 22:13:28, the
  second the lane logged that attempt) was the one that looked hung.

The self-test's case 10 starts a real runner through `spawn`, so every gate that ran the self-test, rather than
reusing a recorded PASS, flashed windows the same way.

## Fix

`spawn` starts the runner with `CREATE_NO_WINDOW | CREATE_NEW_PROCESS_GROUP` (plus `CREATE_BREAKAWAY_FROM_JOB` where
the job allows it). The runner gets a console of its own with no window: it still leaves the supervisor's console,
which is what `DETACHED_PROCESS` was there for. Every program it starts inherits that windowless console. Measured on
this workstation: a child started with the new flags reports `GetConsoleCP() = 437` and no visible console window. A
child started with `DETACHED_PROCESS` reports `GetConsoleCP() = 0`, i.e. no console.

Self-test case 13 spawns that probe through `spawn` and requires a console code page other than 0 and no visible
window, so a return to `DETACHED_PROCESS` fails it. `python scripts/orchestrator/land_lane.py --self-test`:
`=== land_lane.py self-test: PASS (0 failure(s)) ===`.

Swept: the only other `DETACHED_PROCESS` launch, `scripts/telemetry/otlp_sink.py --ensure`, starts an HTTP server
that runs no child process, so it opens no window. It is left as it is. Every `Start-Process` in a tracked `.ps1`
already passes `-WindowStyle Hidden` or `-NoNewWindow`.
