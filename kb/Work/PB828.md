## The question

```cobol
01 A VALUE SPACE.                 *> PICTURE-less, USAGE-less
01 E USAGE DISPLAY VALUE SPACE.   *> PICTURE-less, USAGE carries no length
```

§13.16.3 SR8 makes a PICTURE mandatory for an elementary item "except as indicated in Syntax rule 9"; SR9's
grant is worded for "a literal". Is a figurative constant one of those literals?

## READING 1 — ACCEPT (and flag). The tree's reading, and the better-evidenced one

1. **A figurative constant IS a literal, by the standard's own definition.** §8.3.3.1, first sentence:

   > *"A literal is defined by a reserved word that references a figurative constant or is a character-string
   > representing a data value derived from the ordered set of characters of which the literal is composed. Each
   > literal possesses a class and category: alphanumeric, boolean, national, or numeric."*

   SR9 asks for "an alphanumeric, boolean, or national literal"; §8.3.3.1 says every literal has one of exactly
   those categories plus numeric, and that a reserved word referencing a figurative constant is a literal.

2. **SR9's own length reference RESOLVES for a figurative constant.** SR9 says the length is "as specified in
   8.3.3, Literals" — and §8.3.3.6, *Figurative constant values*, is a subclause **of §8.3.3**
   (`##### 8.3.3.6` under `#### 8.3.3 Literals`). Inside it, §8.3.3.6.4 GR3:

   > *"When a figurative constant represents a string of one or more characters and the length of the string is
   > not specified in the rules for the context in which the figurative constant is used, the length of the
   > string is determined from context by applying the following rules in order: … b) When a figurative constant
   > is other than ALL literal-1, the length of the string is one character. … c) The length of the string is
   > the length of literal-1."*

   ⛔ **This refutes the premise both source reports rest on** — *"a figurative constant has no intrinsic
   length"*. It has no length **specified by its context** here, which is exactly the case GR3 is written for,
   and GR3 then supplies one: **one character** for a bare `SPACE`, and **the length of literal-1** for
   `ALL "AB"`. SR9's implied PICTURE is therefore computable: `PIC X(1)` for `01 A VALUE SPACE.` and `PIC X(2)`
   for `01 G VALUE ALL "AB".`

3. **§8.3.3.6.3 SR1's gate is a PROHIBITION test, not a format test.** The source reports quote it as permitting
   a figurative constant only *"whenever 'literal' appears in a format"* and conclude that SR9, being a syntax
   rule, is outside the permission. The transcription's actual sentence is *"whenever 'literal' appears in a
   format **or when a rule allows it**"*, and its restriction b) is *"A figurative constant shall not be
   specified where a **syntax rule prohibits** it."* SR9 is a rule that allows a literal, and no syntax rule
   prohibits a figurative constant here. The quoted-clause-answering-a-different-question shape
   (`feedback_a_real_clause_can_answer_a_different_question`) is what the shortened quotation produced.

4. **`>>FLAG-14 VALUE-FIG-CON-NO-LENTH` presupposes acceptance.** §7.3.15.1:

   > *"The FLAG-14 directive specifies options to flag certain syntax for which the behavior might be
   > incompatible between the previous COBOL standard and this Working Draft International Standard."*

   A compatibility flag is for syntax a conforming compiler **compiles**; syntax that is rejected has no
   behavior to be incompatible. GR4 k names our exact construct.

## READING 2 — REJECT (SR8 governs, hard error). What can honestly be said for it

1. **SR9's arms are keyed on the literal's CATEGORY, and a figurative constant's category is contextual.**
   §8.3.3.6.4 GR1: *"When a figurative constant is used in a context requiring national characters, the
   figurative constant represents a national character value. Otherwise … an alphanumeric character value."*
   The only context available for `01 A VALUE SPACE.` is the item being described — whose category is what SR9
   is being asked to supply. A reader who takes that circularity as fatal concludes SR9 cannot be applied, and
   SR8's "shall be specified" then governs. (Reading 1's answer: GR1's "otherwise" arm is total, so the
   circularity resolves to alphanumeric by default rather than failing.)

2. **§8.3.3.6.4 GR2 is the VALUE-clause rule, and it assumes a sized receiver.** GR2 governs the case where
   *"the length of the string **is** specified in the rules for the context"* and explicitly mentions "specified
   in a VALUE clause": it repeats the character *"until the size of the resultant string is greater than or
   equal to the number of character positions in the associated data item"*. On this reading GR2 is the rule for
   a figurative constant in a VALUE clause, GR3 is a fallback for other contexts (its NOTE 2 names DISPLAY,
   STOP, STRING, UNSTRING and concatenation — not a PICTURE-less VALUE), and a VALUE clause with no sized
   receiver simply has no rule.

3. **The option's own name asserts the premise.** `VALUE-FIG-CON-NO-LENTH` names the construct as one with *no*
   length. A reader can take the flag as a diagnostic aid for a construct the previous standard tolerated and
   this one does not, rather than as a licence.

## Two spelling divergences in the standard's own text — recorded, not "corrected"

* The **format** (§7.3.15.2, inside the FLAG-14 syntax diagram) spells the option `VALUE-FIG-CON-LENGTH`; the
  **general rule** (§7.3.15.4 GR4 k) spells it `VALUE-FIG-CON-NO-LENTH`. The transcription's figure note records
  that all twelve option names were read as underlined on the printed page, so this is very likely the
  standard's own divergence rather than an OCR artifact — but it is a DIAGRAM, and CLAUDE.md rule 1 says a
  load-bearing general format is settled by rendering the page (`scripts/render-spec-page.py`), not by reading
  the Markdown. **Do that before either spelling reaches a new code comment.** The compiler accepts and emits
  the FORMAT spelling (`VALUE-FIG-CON-LENGTH`), which is what a programmer writes, and that is correct
  regardless of how the rule sentence spells it.
* The PB487 report's "**Annex E.2 item 11**" pointer for this option could not be located in the transcription
  (`grep` for `VALUE-FIG-CON` returns only §7.3.15.2's figure lines, §7.3.15.4 GR4 k, and one Annex table row at
  `specs/ISO_COBOL.md:9742`). It is therefore **not carried into this note**. An inherited citation nobody
  re-derived is the exact failure CLAUDE.md rule 1 names.
