# PB4041 — leading-comma-insertion-replaced-by-space: MOVE to numeric-edited: a comma insertion symbol left of all digit positions is replaced by a space (PIC ,999)

Filed 2026-10-29 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-20261028-210601`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

In a MOVE to a numeric-edited item, GnuCOBOL 3.2 replaces a comma simple-insertion symbol that stands to the left of
every digit position (`PIC ,999`, `PIC $,ZZZ,ZZ9.99`) with a space. ISO places a simple insertion character in the
position its symbol occupies; only insertion symbols embedded in a zero-suppression string, or to its immediate right,
belong to that string and take the replacement character. The `0` and `/` insertion symbols in the same position are
kept, so only the grouping separator (the comma, or the period when DECIMAL-POINT IS COMMA is in effect: `PIC .999`
then also gives ` 012`) and `B` (whose replacement is invisible) are affected. Class: wrong output, silent. Fuzz
program fz02040 (`G NORM`, `PIC $,ZZZ,ZZ9.99` holding 123.45).

## Minimal test case

Free reference format (`-free`), `records/leading-comma-insertion-replaced-by-space.cob`:

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. LCOMMA.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 E1 PIC ,999.
01 E2 PIC $,ZZZ,ZZ9.99.
01 E3 PIC 0ZZ9.
PROCEDURE DIVISION.
    MOVE 12 TO E1
    MOVE 123.45 TO E2
    MOVE 12 TO E3
    DISPLAY "[" E1 "]"
    DISPLAY "[" E2 "]"
    DISPLAY "[" E3 "]"
    STOP RUN.
```


## Expected result (per ISO)

ISO/IEC 1989:2023, each citation checked with `scripts/spec/cite.py --check`:

- §13.18.40.4 rule 14): "Each symbol ',' (comma) represents a character position into which the character comma will
  be inserted during editing."
- §13.18.40.5 rule 3): "Simple insertion editing results in the insertion character occupying the same character
  position in the edited item as the associated symbol occupies in character-string-1." The comma is a simple
  insertion symbol (same rule: "the symbols 'B', '0', '/', ','").
- §13.18.40.5 rule 7): "Zero suppression with replacement is indicated by specifying a string of one or more identical
  zero-suppression characters. Any of the simple insertion editing symbols embedded in this string or to the immediate
  right of this string are part of the string." A comma to the LEFT of the string is not part of it; `PIC ,999` has no
  zero-suppression string at all.
- §13.18.40.6 (Table 10, Format 1 picture symbol order of precedence; PDF pages 489 and 490 rendered and read): the `,`
  column marks the `9` and the left-of-point `Z *` rows, and the first-position `cs` column marks the `,` row, so `,999`
  and `$,ZZZ,ZZ9.99` are legal pictures.

The 2009 committee draft for ISO/IEC 1989:2014 (CD 1.2) has the same comma rule, the same simple insertion rule and the
same zero-suppression rule, so the 2014 answer is the same. Expected output:

```
[,012]
[$,    123.45]
[0 12]
```

## Our compiler

WiseOwl COBOL (fresh judge `E:\tmp\fuzz-judge-20261029\cobol.exe`, `--std 2014 --source-format free`): compile exit 0
with no diagnostic, run exit 0, output `[,012]`, `[$,    123.45]`, `[0 12]`, the expected result.

## Fix site

`libcob/move.c`, function `cob_move_display_to_edited` (line 878). `suppress_zero` starts at 1 (line 898) and is
cleared only by the first `9` or nonzero digit. In the editing loop the `'.'`/`','` case (line 1015) writes `pad` in
place of a non-decimal comma (or period, under DECIMAL-POINT IS COMMA) whenever `suppress_zero` is still set (line
1020), whether or not the symbol follows a zero-suppression symbol; the `'B'` case (line 1038) does the same, while
`'0'`/`'/'` (line 1033) always keep the symbol. A fix replaces a grouping separator (or `B`) with the pad character
only once a zero-suppression or floating-insertion symbol has been met to its left.

## Draft issue

**Title:** MOVE to numeric-edited: a comma insertion symbol left of all digit positions is replaced by a space (PIC ,999)

Environment: GnuCOBOL 3.2.0 (`cobc (GnuCOBOL) 3.2.0`), Ubuntu on WSL2, `cobc -x -free -std=cobol2014`.

Steps: compile and run the program below.

Observed: `[ 012]`, `[$     123.45]`, `[0 12]`.

Expected: `[,012]`, `[$,    123.45]`, `[0 12]`. ISO/IEC 1989:2023 §13.18.40.4 rule 14 makes each comma symbol a
position into which a comma is inserted, and §13.18.40.5 rule 3 places a simple insertion character (B 0 / ,) in the
position its symbol occupies; §13.18.40.5 rule 7 makes only the insertion symbols embedded in or immediately right of a
zero-suppression string part of that string. A comma before the first digit position is neither, and `PIC ,999` has
no zero suppression at all. The `0` in `PIC 0ZZ9` is already kept. The same happens to the period under
DECIMAL-POINT IS COMMA (`PIC .999` gives ` 012`).

is set, and `suppress_zero` starts at 1 before any `Z`, `*` or floating symbol has been seen.

```cobol

PROGRAM-ID. LCOMMA.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 E1 PIC ,999.
01 E2 PIC $,ZZZ,ZZ9.99.
01 E3 PIC 0ZZ9.
PROCEDURE DIVISION.
    MOVE 12 TO E1

    MOVE 12 TO E3
```
