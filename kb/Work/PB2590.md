## Code site

`scripts/orchestrator/orchestrate.ps1` lines 386-387 and 496-500 call `checkpoint.py synthesize`, which runs
`git worktree list --porcelain` and per-worktree git probes (`checkpoint.py#synthesize` → `worktrees(repo)`); a `catch` turns any failure into
"handoff not synthesized". Under 60 parallel self-tests that call (or the fake unit's timing around it) does not
finish in time. Fix: find which step times out under load and either give it a deadline the test controls or mark
the two tests serial in `self_tests.py` (the CI invariant needs the gate's run and CI's run to agree).

## 2026-10-10 22:30 PDT: root cause and fix (operator)

**The startup arm, again, and what it showed.** Gate `20261011T041736Z-d08bb8` (branch `land-train-cap-r2100`, a
scripts-only change) went RED in SELF-TESTS on `test_orchestrate_startup.ps1` after 1147 s: "a unit silent at start is
killed by the watchdog: got 'False'", "the watchdog says so: got 'False'", "the supervisor did not wait out the 600 s the
unit would have slept: got 'False'". Alone it passed 7/7. The owner: "A timing sensitive watchdog failure is still a
failure to be fixed".

**Root cause, one for every arm.** No orchestrate self-test passed `-RepoDir`, so the supervisor under test read the
machine's REAL repository, and `orchestrate.ps1#Write-Checkpoint` ran `checkpoint.py write` SYNCHRONOUSLY from the unit's
event loop. `checkpoint.py#worktrees` runs `git status` and `git rev-list` in every linked worktree: 33 of them on
2026-10-10, 8 s on an idle host, minutes with six gates building. While it ran the loop read no stdout, ticked no
startup watchdog and checked no STOP or context cap. In the red run the FIRST checkpoint (written before the read loop
starts) outlasted the silent fake's 600 s sleep, so the watchdog found the process exited and killed nothing. The
handoff-synthesis arms above call `checkpoint.py synthesize`, the same probe of the same real worktrees. It was a product
defect as well: the real loop stalls the same way on a loaded host.

**Fix.**
- `orchestrate.ps1#Write-Checkpoint`: the loop's checkpoint writes run in the BACKGROUND, one at a time (a write due
  while one runs is skipped; the next carries the newer state). Only the final write, after the unit exits, waits
  (`-Wait`), because a successor reads it.
- The self-test harness (`testdata/orchestrate_test_lib.ps1`) gives every supervisor a scratch `-RepoDir` that is not a git
  tree (`$FxRepo`, as the campaign part already did), so no case's timing or unit choice depends on the machine's
  repository. The ledger part passes `-RepoDir $RealRepo` explicitly (its stamp is the real ledger inputs' last commit).
- Sibling: `next_unit.py#fresh_unlanded` listed the branches of the repository it was given but classified them against
  prune_worktrees' default repository; it passes the repository now.
- Drift guard: `test_orchestrate_startup.ps1` 4k': with `-Python testdata/fake-python.ps1` the FIRST checkpoint write
  takes 40 s, and the fake unit (`silentshort`) is hung at start for 20 s and then exits. The watchdog must kill it.
  Proven to fail: with the synchronous write restored, 4k' went RED (8/10: "the hung unit is killed: got 'False'"). A
  slower host only lengthens the unit's 20 s, so the case cannot go red without the regression.
- Evidence: all 12 `test_orchestrate_*.ps1` parts run AT ONCE: 203/203 checks OK; the startup part 10/10.
