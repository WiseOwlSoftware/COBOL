# PB5972 - at `--std 85` a condition-name and a data-name spelled alike are refused at declaration

## The requirement
§1985:IV.4.2.2.1.1 groups the user-defined words of a program into disjoint sets, and set 4 is "condition-names, data-names,
and record-names": one set. Within a set, duplicates are allowed "as specified in the rules for uniqueness of reference", and
§1985:IV.4.3.8.1 SRL2.1 says "uniqueness must be established through a sequence of qualifiers which precludes any ambiguity of
reference". So a level-88 `X` under one record and a data item `X` in another record are legal at 1985 when every reference
is qualified.

## What the compiler does
```
01 R1. 05 F PIC 9. 88 X VALUE 1.
01 R2. 05 X PIC 9.
... IF X OF F ... IF X IN R1 ... DISPLAY X OF R2
```
`--std 85`: exit 65, `cn4.cob(9,12): error COBOL2692: 'X' names two types of user-defined word in this source element
(condition-name and data-name)`, citing §1985:IV.4.2.2.1.1 for a restriction that text does not state for this pair. The
program is refused at the declaration, before qualification is applied (re-run 2026-11-20 through run_probe on a compiler built
at 832bc39c61).

## The mechanism
`src/WiseOwl.Cobol.Compiler/Binding/UserWordKind.cs#MayBeOneWord`, called by `DataBinder.CheckOneTypePerWord` through
`SymbolTable.UserWordCensus`, applies the latest edition's sharing list (`MayShareOneName`: constant-name, data-name,
property-name, record-key-name, record-name) at every edition; only `ConflictMessage`'s citation text switches by edition.
The 1985 arm (a condition-name shares one set with data-names and record-names) is missing. The same program is refused at
`--std 2002` and `--std 2023`; whether those editions' own texts allow it is NOT decided here (each edition stands on its own
text; 2002 work is frozen until 1985 is complete).

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/UserWordKind.cs` (`UserWordKinds.MayBeOneWord`, `UserWordKinds.MayShareOneName`), `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs:2076` (`DataBinder.CheckOneTypePerWord`), `src/WiseOwl.Cobol.Compiler/Binding/SymbolTable/SymbolTable.UserWordCensus.cs` (`SymbolTable.UserWordCensus.Record`, `SymbolTable.UserWordCensus.ConflictMessage`)

## Fix shape
The sharing rule belongs to the edition: the census asks the edition which kinds share one disjoint set, and the 1985 answer
puts condition-name with data-name and record-name; references are then resolved by the ordinary qualification rule, which
already refuses an unqualified ambiguous `X` (COBOL1639). Witnesses at `--std 85`: cn4's shape (runs), and the same program
with one unqualified `X` (refused COBOL1639).
