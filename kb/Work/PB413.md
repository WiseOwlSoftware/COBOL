# PB413 — the classic COBOL escape idiom is silently a no-op

**Row:** `GR-14.9.17.4-1`. The b2 adjudicator scored this row CONFORMS on three probes that all placed the
GO TO at paragraph top level; the refuter flipped it to DIVERGES on the class of GO TOs those probes could not
reach. **Every measurement below was re-run on this worktree's HEAD `cobol.exe` (base 89044aa0)**, and the
defect still reproduces.

## THE MECHANISM

`src/Cobol.Net.Compiler/CodeGen/StatementEmitter.cs:111` emits a format-1 GO TO as

```csharp
public bool Visit(BoundGoTo n) { … w.Line($"__pc = {n.TargetPc};"); w.Line("break;"); return true; }
```

The `break` is meant to leave the dispatcher's `switch (__pc)` so the outer `while` re-dispatches at the new pc.
But C# `break` binds to the NEAREST enclosing breakable construct, and
`src/Cobol.Net.Compiler/CodeGen/Verbs/ControlFlowEmitter.cs#EmitPerformLoop` (`:249-282`) emits every inline
PERFORM as a **real C# loop**: `for` for TIMES (`:260`), `do{}while` for UNTIL TEST AFTER (`:262-264`), `while`
for UNTIL (`:267`), nested `while`s for VARYING (`EmitVarying`), `while (true)` for UNTIL EXIT (`:275`), and
`do{}while(false)` for the bare inline PERFORM (`:278`). Inside any of those the `break` exits the **PERFORM
loop**, not the dispatcher; `__pc` has already been assigned and is then overwritten by the ordinary
fall-through increment when the `case` ends. The transfer is silently discarded.

The proof that this is a known-shape omission and not a design choice sits three lines away:
`ControlFlowEmitter.cs#EmitPerform` (`:239-247`) emits an inline PERFORM with a real `__pexit{pid}` label at
`:246` **precisely because** `break` cannot cross the loop, and `StatementEmitter.cs:130`'s `BoundExitPerform`
leaves via `goto __pexit`. EXIT PERFORM was given a label; GO TO was left on `break`.

It is the two-arm-dispatch shape again: the Format-3 (exception-checking) PERFORM arm emits
imperative-statement-1 INLINE with no enclosing loop, so a GO TO out of imp-1 transfers correctly — one arm
right, the other wrong, and only the right one was ever probed.

⛔ **[[PB405]] is the same root shape and the two must be repaired together.** PB405 is EXIT PARAGRAPH / EXIT
SECTION written inside an inline PERFORM, whose bare `break` binds to the PERFORM's C# loop instead of the
paragraph dispatcher; this note is GO TO out of an inline PERFORM never transferring at all. One cause: **an
inline PERFORM lowers to a real C# loop, so EVERY dispatcher-level control transfer written inside one is
suspect until measured.** The "six inline-PERFORM shapes broken, three control shapes correct" table below is
the population for that repair, not for GO TO alone — a fix that lands one verb and leaves the other on `break`
is the same defect a third time.

## THE RULE, QUOTED, WITH ITS `--check` LINE

- `--check 14.9.17.4 "control is transferred to procedure-name-1"` → `OK §14.9.17.4 1)`. GR1, in full and
  unconditional: "When a GO TO statement represented by format 1 is executed, control is transferred to
  procedure-name-1."

**The premise was validated before this was called a defect** — nothing in the standard licenses the omission:

- `--check 14.9.28.4 "The results of executing the following sequence of PERFORM statements are undefined"` →
  `OK §14.9.28.4 2)`. GR2 makes only OVERLAPPING PERFORMs undefined (a second PERFORM executed inside the
  first's range whose execution passes through the first's exit). Every probe below contains ONE PERFORM and a
  GO TO, so GR2 does not reach them.
- `--check 14.9.28.4 "the specified set of statements consists of all statements contained within the PERFORM statement"`
  → `OK §14.9.28.4 4)`. GR4 puts the inline PERFORM's statements squarely in the statement stream.
- `--check 14.9.28.4 "GO TO"` → `OK §14.9.28.4 6)`, the NOTE to GR6, which expressly contemplates a GO TO in the
  flow of execution of the specified set of statements.

## EXPECTED vs OBSERVED — re-measured on HEAD

`cobol.exe <src> --std 2023 --run`, probes in `scratchpad/probe-g3-goback-goto/refute-go-to/`.

`g5-goto-out-of-inline-perform.cob` is the minimal case:

```cobol
       MAIN-P.
           DISPLAY "START".
           PERFORM 5 TIMES
               ADD 1 TO N
               IF N = 2
                   GO TO OUT-P
               END-IF
               DISPLAY "ITER " N
           END-PERFORM.
           DISPLAY "AFTER-LOOP-MUST-NOT".
       OUT-P.
           DISPLAY "OUT " N.
           STOP RUN.
```

**Expected (GR1):** `START`, `ITER 0001`, `OUT 0002`. **Observed on HEAD:** `START`, `ITER 0001`,
**`AFTER-LOOP-MUST-NOT`**, `OUT 0002` — the transfer did not happen; execution resumed after END-PERFORM and
reached `OUT-P` only by falling through. Identical at `--std 85`.

| probe | PERFORM shape | OBSERVED on HEAD | verdict |
|---|---|---|---|
| `g5-goto-out-of-inline-perform` | `PERFORM 5 TIMES` | `AFTER-LOOP-MUST-NOT` printed | broken |
| `g12-goto-out-bare-inline` | bare inline `PERFORM … END-PERFORM` | `AFTER-PERFORM-MUST-NOT`, `MIDDLE-MUST-NOT` | broken |
| `g13-goto-out-varying` | `PERFORM VARYING` | `AFTER-VARY-MUST-NOT`, `MIDDLE-MUST-NOT` | broken |
| `g6-goto-out-of-evaluate-in-loop` | EVALUATE nested in an inline PERFORM | `AFTER-LOOP-MUST-NOT` | broken |
| `g8-goto-out-nonadjacent-target` | forward, non-adjacent target | `AFTER-LOOP-MUST-NOT`, `MIDDLE-MUST-NOT` | broken |
| `g9-goto-out-backward-target` | backward target | `AFTER-LOOP-MUST-NOT` | broken |
| `g7-goto-out-of-f3-imp1` | GO TO in a Format-3 PERFORM's imp-1 | `START`, `OUT 0001` | **correct** |

**Blast radius measured, not assumed:** EVALUATE and SEARCH…WHEN transfer correctly on their own, and the
Format-3 PERFORM arm transfers correctly. The defect is confined to — and universal within — the inline PERFORM
body, at every control shape and at `--std 2023` and `--std 85` alike.

## THE SHAPE OF THE REPAIR

⛔ Not "special-case GO TO inside a loop" (CLAUDE.md rule 5). Two constructs already need to cross the emitted
loop nest — EXIT PERFORM and GO TO — and only one of them was given a mechanism. **There is exactly one
question here: how does a bound statement leave the emitted C# control structure and re-enter the `__pc`
dispatcher?** Answer it once — a `goto __dispatch;` label emitted at the top of the dispatcher loop, used by
every pc-assigning statement — and both constructs, plus any future one (a RESUME target, an EXIT SECTION out
of a loop), get it for free. Then delete the `break` idiom from `StatementEmitter` entirely so it cannot be
written again, and add a drift test asserting that no emitted `__pc = …` is followed by a bare `break`.

**`GR-14.9.17.4-2` inherits the identical bug and is fixed by the same change:**
`ControlFlowEmitter.cs#EmitGoToDepending` (`:34-48`) ends at `:47` with the same bare `break`, so an in-range
`GO TO … DEPENDING` inside an inline PERFORM is lost the same way. That row is already PARTIAL so it does not
move the burn-down, but the fixer must re-probe it and must not leave it on the old idiom.

## THE SIBLING SWEEP

1. **Every `break` emitted as a dispatcher exit** — grep `__pc = .*break` and probe each one inside an inline
   PERFORM: `StatementEmitter.cs:111` (GO TO), `:112` (`BoundExitParagraph`), `:185` (RESUME AT);
   `ControlFlowEmitter.cs:47` (GO TO DEPENDING) and `:465` (SEARCH's RESUME pickup);
   `CallEmitter.cs:238`, `:260`, `:265`, `:274` (the RESUME AT and propagation-pickup exits). **Each is wrong
   inside an inline PERFORM by the same mechanism** — a RESUME AT that lands in a loop body, or an EXIT
   PARAGRAPH written inside an inline PERFORM, has never been probed
   (`feedback_reachability_is_measured_not_deduced`). Note `ControlFlowEmitter.cs:377`'s comment states the
   assumption explicitly for SEARCH's WHEN body — it holds there (`g11` measured correct) and is exactly what
   fails once a real C# loop intervenes.
2. **No test on disk can catch this.** The only GO TO tests are legacy-oracle differentials
   (`AlterSwitchesDifferentialTests`, `SectionDifferentialTests`, `ControlFlowDifferentialTests`), which by
   schema cannot close a row, and none of them puts a GO TO inside an inline PERFORM. The fix must ship a
   conformance golden per PERFORM shape in the table above.
3. **A separate defect, found while probing this row and NOW OWNED BY [[PB466]] — do not fold it back in.**
   §8.4.2.2.1, not §14.9.17.4: `Binding/Procedure/ProcedureTableBuilder.cs#ResolveProcedure` (`:174-197`) falls
   through at `:195` to `_paraIndex` — the globally FIRST-DEFINED paragraph of that name — with no ambiguity
   check, because `AddParagraph:52`'s `TryAdd` has already discarded the later definitions. Measured on HEAD
   (`probe/refute-go-to/g3-ambiguous-dup.cob`): compiles clean and prints `ONE` where §8.4.2.2.1 requires
   qualification. It reaches PERFORM, ALTER, RESUME and SORT as well as GO TO; PB466 carries the citations, the
   repair shape and the full caller sweep.

## Rows

`GR-14.9.17.4-1` — DIVERGES, and specifically a WRONG-ANSWER defect on legal source with no diagnostic, not an
under-rejection. The verdict rests on six measured runs on HEAD in which the transfer does not occur (every
inline-PERFORM shape the emitter produces, at 2023 and 85) and three in which it does (Format-3 imp-1,
EVALUATE, SEARCH…WHEN), which localise the mechanism to `EmitPerformLoop`'s real C# loops rather than to GO TO
itself. The adjudicator's three original probes (`p2`, `p10`, `p17`) are all still correct and are retained
above as controls — the row's edge is not unverified, it is verified broken.
