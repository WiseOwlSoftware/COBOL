# PB6283 — the planner re-bundles notes a SPLIT recorded as separate mechanisms

**Measured.** PB2622 (the §8.3 (2) diagnostics generator and its emit-site migration) and PB3231 (the forged parse contexts)
were recorded as a mechanism each by wave 20262161 group A (`kb/Work/PB2622/2026-11-23-split-from-group-a-w20262161.md`: "the
planner should dispatch it as its own group, not bundled with PB2724/PB3231"). The planner bundled them again:

1. wave 20262161 group A (the SPLIT that recorded it),
2. wave 20262164 group A (PB2622, PB2627, PB2724, PB3227, PB3231; the second implementer re-carried the same commits and did not
   start PB2622 or PB3231, `kb/Work/PB2622/2026-11-24-not-done-w20262164a-surface-measured.md`),
3. wave 20262172 group A (PB2622, PB3231, PB6169, PB6172, PB6173; only PB6172 and PB6173 were done, PB6169, PB3231 and PB2622
   were not started, each being a mechanism of its own).

**Root.** `scripts/orchestrator/plan_wave.py` group formation does not read a "split-from-group" addendum
(`kb/Work/<id>/<date>-split-from-group-*.md` or `-not-done-*.md`), so a note a finished wave marked "its own dispatch" is grouped
by area and cluster again. Each re-bundling costs an implementer dispatch that ends SPLIT or DONE for a fraction of its group.

**Fix shape.** Group formation reads the addenda of each candidate note for a split marker (a frontmatter key on the addendum,
not prose) and keeps a marked note out of any group with another marked note; the marker is the one place the rule lives. A
test pins it with the PB2622/PB3231 pair. Same family as PB6129 (the planner offering a note with nothing to do).
