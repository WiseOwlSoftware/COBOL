# PB1312 — OPEN — a derived picture fact is read as a written one

## Measured (`diag1.cob`, `--std 2023`)

```cobol
       01 G USAGE INDEX.
          05 A VALUE "AB".
       01 H COMP.
          05 B PIC 999 BLANK WHEN ZERO.
```

```
diag1.cob(8,11): error COBOLNET2168: data item 'A': the VALUE clause shall not be specified with USAGE INDEX,
  inherited from its group 'G' (… ISO §13.16.3 SR10; §13.18.60.4 GR1)                       ← correct
diag1.cob(8,11): error COBOLNET0881: data item 'A': PICTURE may not be specified with USAGE INDEX … (ISO §13.16.3
  SR8; §13.18.60.4 GR10) — the usage is the one written for the group item 'G' …              ← no PICTURE was written
diag1.cob(10,11): error COBOLNET0881: data item 'B': USAGE BINARY requires a PICTURE that describes a numeric
  item — PICTURE 999 is numeric-edited (ISO §13.18.60.3 SR3)                                  ← wrong rule named
```

## The rules

```
$ cite.py --check 13.18.8.3 'The subject of the entry shall be implicitly or explicitly described as usage display or usage national'
  OK  §13.18.8.3 2)  (Syntax rules)
```

The user wrote `PIC 999`, which is numeric. It becomes numeric-edited only through the BLANK WHEN ZERO clause's
own promotion. The rule the entry breaks is BWZ's SR2: the inherited usage is BINARY, not display or national.
The item A has no PICTURE clause. §13.16.3 SR9 implies one only so that the VALUE has a picture to be checked
against. The only real defect in A's entry is SR10, the VALUE under an index usage, and 2168 already reports it.

## Mechanism
- `src/Cobol.Net.Compiler/Binding/Passes/BindPipeline.cs:45-46` runs `SynthesizeImpliedPictures`
  (`DataBinder.ImpliedPicture.cs:87`) BEFORE `UsageInheritancePass`, and it has to: see the ordering comment at
  lines 39-43.
- `UsageInheritancePass` → `DataBinder.cs:5694` `UsageInheritanceElementary`. Its picture-bearing acquired-usage
  arm asks "is there a PICTURE" and "what category is it". It cannot tell an implied picture, or a
  GR2-promoted category, from a written one.
- `CheckClauseSubjects` (`BindPipeline.cs:80`) is the pass that owns §13.18.8.3 SR1/SR2 over the inherited usage.
  It runs AFTER this pass, so the SR3 message wins and SR2 never gets to speak.

## What the fixer owes
- The acquired-usage arm reads the WRITTEN picture fact: whether the entry wrote PICTURE, and the category of the
  written character-string before any clause promotion. That is the same "written clause" discipline
  `ValuePlacement` uses (PB586).
- The BWZ case is reported once, under §13.18.8.3 SR2.
- The implied-picture case draws 2168 alone.
- **Sibling sweep** covers every derived picture fact that `UsageInheritanceElementary` or `CheckPictureUsage`
  reads: the SR9 implied picture, BWZ's GR2 promotion, and the §13.18.40 float-edit promotion.
- **Related cascade (same class, measured):** `05 B REDEFINES A TYPE T.` is correctly refused by COBOLNET2150
  (§13.16.3 SR14: TYPE may not be written with REDEFINES). It is then ALSO given COBOLNET0881 "a PICTURE clause
  shall be specified for an elementary item". The refused TYPE leaves a picture-less elementary item that the SR8
  arm judges as written.
- Negative goldens pin the exact code set for both entries.
