# PB4976 - citation forms that cite.py refuses

CLAUDE.md rule 1: every citation is `§<edition>:<locator>[ <rule>]` and was run through `cite.py --check`. Three reports found citations that are not.

**Sites (from the reports).**
- `conformance-suite/cases/8.8.1.2-Native-standard-binary-and-standard-decimal/pb4641_float_edited_narrow_receiver_quotient.cob:9` cites a bare `13.18.40.3 SR15`; `pb4641_float_edited_receiver_quotient.cob:9` the same; `DEVLOG/3306-pb4641-a-native-final-transfer-quotient-of-two-sdidi-values.md` writes `2023:13.18.40.3 SR15` with no `§`. The code comments in the same diff use `§2023:13.18.40.3 SR15`.
- The spelling `11.9.11.2 r3d` (the PB4641 round fixed its own DivFinal comment to `§2023:11.9.11.2 GR3d`): at least `src/WiseOwl.Cobol.Compiler/CodeGen/EcEmitter.cs:585`, `CodeGen/Emit/NumericRenderer.cs:1228` and `src/WiseOwl.Cobol.Runtime/Values/Numeric/CobolDec.cs` (lines 36, 70, 472, 1246, 1250, 1310 and more); the PB4641 report called these "the clerk's sweep". The correct rule designator is not guessed here: re-derive it with `cite.py --check` against the text each comment quotes.
- `src/WiseOwl.Cobol.Compiler/Binding/Model/RecordLayout.cs:57` and `docs/CONFORMANCE.md:2330` cite `§2023:8.5.1.9.1 2`; `cite.py --check` refuses it ("2 is not a rule designator"). The text meant (8.5.1.9.1 list item 2, "it may have an unlimited capacity") is genuine, so only the designator form needs deriving.

**Needed.** Fix every site (re-run `cite.py --check` on each; do not inherit a rule number), then sweep the tree for the same patterns (`r3d`, bare dotted clause followed by SR/GR, `§<edition>:<clause> <digit>`), and decide whether a tree audit should refuse the form so the next case is automatic (CLAUDE.md rule 5).
