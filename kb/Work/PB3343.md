# PB3343 — the declined-facility register guard iterates the wrong side

Source: the PB1784 + PB745 branch (`worktree-wf_9e52adb3-fa2-7`, PR #188), report `E:/COBOL-coord/scratch/reports/w1108a-PB1784-report.md`, "New defects / leads". Related: PB745 (COBOL0849 and COBOL0822 had no descriptor), PB709 (the annex datum).

**What is wrong.** `tests/Cobol.Net.Tests.Unit/DeclinedFacilityAnnexDriftTests.cs`, `EveryDeclinedDescriptor_AgreesWithTheConformanceRegisters` (about lines 136-153), iterates `Declined()`, the descriptors that already carry a `DeclinedAnnex`. A code that `docs/CONFORMANCE.md` section 2 (the Annex A.3 register) or section 5 (the Annex A.4 register) names, but whose descriptor carries no annex or which has no descriptor at all, is never visited. That is the exact shape PB745 found: COBOL0849 and COBOL0822 had no descriptor, and 0849 was reused for an ordinary syntax rule.

**Harm.** None to a user's program; a guard hole in a test (process_only: true).

**Fix.** Iterate the register codes too (parse them from the two CONFORMANCE sections the test already reads) and fail when a registered code's descriptor is missing or claims no annex. Then prove the guard fails: remove one descriptor's annex on the live catalog and confirm the new direction goes red (`prove_the_watchdog_fails`). Sibling sweep: any other drift test that iterates the "already marked" side of a register instead of the register.
