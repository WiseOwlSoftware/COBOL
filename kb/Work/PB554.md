# PB554

## Mechanism — value-clause-p1
value-p1-F10-ValidateValueCategory-has-no-NationalEdited-arm-so-national-edited-falls-into-the-wrong-category-catch-all

### Expected, from the standard
`01 Z PIC NNBNN USAGE NATIONAL VALUE N"ABCDE".` is CONFORMING: SR5 requires a national literal for a national-edited item, and SR11 sentence 2 says the B is not applied at initialization, so Z shall hold the five national characters ABCDE verbatim. It shall NOT draw a literal-category diagnostic.

```
(the finding quotes no rule sentence verbatim, so there is nothing to --check; the implementer MUST quote §13.18.63.3 and re-run `cite.py --check` before writing a code comment)
```

### Observed
It draws COBOLNET0898 -- "data item 'Z': a national (N\"...\") literal may seed only a data item of its own category (ISO 13.18.63 SR5/SR10)" -- alongside the COBOLNET0899 that stages national-edited data itself (probe sr11_natedit_noedit, --std 2023). LATENT TODAY: the 0899 stage ("national-edited data (PICTURE N with B 0 /) is recognized but not yet implemented ... Phase 4a residue") refuses the program anyway, so no user sees the wrong reason yet -- but the moment national-edited representation lands, this arm rejects every conforming national-edited VALUE, and the opposite mistake (an ALPHANUMERIC literal on a national-edited item, which SR5 forbids) is accepted. The row this primarily belongs to is SR-13.18.63.3-5, which is adjudicated in a sibling part of this subject; it is recorded here because SR11 sentence 2 is the rule that reaches national-edited items and is where the probe found it. The fix is one arm: fold NationalEdited in beside National in both the positive test and the catch-all's exclusion list.

## Landed — wave 39 (2026-09-19): DOES NOT REPRODUCE; fixed by PB492

Re-probed on a freshly built `cobol.exe` from main @ 01062f29: `01 Z PIC NNBNN USAGE NATIONAL VALUE
N"ABCDE".` compiles clean and DISPLAYs `[ABCDE]`. Neither COBOLNET0899 (the Phase-4a national-edited
stage) nor the COBOLNET0898 this note is about is raised. The opposite direction is correctly refused:
an ALPHANUMERIC literal on the same item draws COBOLNET0898 quoting §13.18.63.3 SR5.

THE NOTE'S PREMISE IS STALE. It says "`PicCategory.NationalEdited` is a distinct member", and it is not:
`src/Cobol.Net.Compiler/Binding/Model/ItemCategory.cs` records the data-model decision D-N6 — `PicCategory`
has no `AlphanumericEdited` or `NationalEdited` member, a national-edited item carries category
`PicCategory.National` distinguished only by `PicInfo.EditMask` — so `ValidateValueCategory`'s
cross-category catch-all cannot reach a national-edited receiver. The landing is `fafeadb8` ("PB492:
category national-edited is real; one edited-symbol set"); `609e1e71` (PB646) added the sibling
NumericEdited exclusion on the same arm.

Row SR-13.18.63.3-11: PARTIAL → CONFORMS. The national-edited half of SR11 sentence 2 is pinned by the
existing `tests/conformance/2002/pb492_national_edited` (`VAL=[AB CD]` — the literal stored exactly as
written), with `tests/conformance/negative/pb492-national-edited-value-literal-class` for SR5's other
direction. No new golden was owed.
