# PB2836 — RETIRED — CALL BY CONTENT (C) does not cross as C's place

The w1047e implementer (report lead 2) raised it as PLAUSIBLE, not probed: `CallBinder.ExpressionOperand`
(`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/CallBinder.cs` ~613-618) maps a parenthesized identifier through
`IntrinsicBinder.OperandOf`, so `(C)` might cross as C's place, while §14.9.4.4 8) regards only an argument that
"consists merely of a single identifier" as an identifier (`cite.py --check 14.9.4.4 "consists merely of a single
identifier"` → OK). Filed by the train 1047 lander, 2026-10-08 20:53 PDT.

## Probe (train 1047 tree, `E:\COBOL-coord\scratch\t1047\p2836\`)
- `a.cob`, Format 1 (`CALL "S2836" USING BY CONTENT (C) (N)`): refused, COBOLNET0899 "an expression operand belongs
  to the program-prototype CALL (ISO §14.9.4.2 Format 2)" — correct, Format 1's BY CONTENT admits identifier-2 only.
- `b.cob`, Format 2 (`CALL P2836 USING BY CONTENT (WX)` with `WX PIC 9(2) VALUE 42` and formal `LK PIC 9(4)`): the
  callee prints `LK=0042`, exactly what `(WX + 0)` prints, so the parenthesized operand crosses as the expression's
  value in the formal's description, not as WX's 2-byte place.

Neither arm reproduces the lead. The one defect the probe did show is diagnostic quality, the operand text
`BYCONTENT(C)`, which is PB2838's mechanism and is recorded there.
