# PB3810 — the sparse-checkout audit under-approximates

**Sites:** `tests/Cobol.Net.Tests.Unit/SparseCheckoutAudit.cs#ModuleLevelImports`, `tests/Cobol.Net.Tests.Unit/SparseCheckoutAudit.cs#Jobs`, `tests/Cobol.Net.Tests.Unit/DotnetSdkInstallDriftTests.cs#Jobs`, `tests/Cobol.Net.Tests.Unit/DotnetSdkInstallDriftTests.cs#JobShape`, `tests/Cobol.Net.Tests.Unit/SparseCheckoutDriftTests.cs`, `.github/workflows/build-and-test.yml` (the `supersede` job's sparse list)

## Measured

1. `ModuleLevelImports` skips every import inside a function body (`if (defs.Count > 0) continue;`), so a repository module
   a job script imports lazily on its executed path (for example from `main()`) is never demanded of the sparse list.
   PB3787's acceptance asks for the transitive repository imports of every script, and `scripts/` holds 176 function-body
   imports of repo modules (enqueue.py, land_lane.py, devlog.py ...), so the idiom is the common one. Scenario: add
   `def main(): import coord` style lazy import of a `scripts/` module (outside scripts/orchestrator) to
   `cancel_superseded.py`: `SparseCheckoutDriftTests` stays green, the supersede step raises ModuleNotFoundError on the
   runner, continue-on-error hides it and the job cancels nothing, the PB3787 failure. Today only
   `standard_streams.live_python -> live_tools` is on the closure (scripts/live_tools.py imports nothing further).
   Fix as the reviewer proposed: follow function-body imports too (over-approximation is loud, under-approximation
   silent), add `scripts/live_tools.py` to the supersede sparse list, turn the lazy arm of `ALazyImport_...` into a
   reached arm, and correct the remarks in `SparseCheckoutAudit`, `SparseCheckoutDriftTests`, DESIGN-test-build-ci.md
   3.17.8 and PB3787.
2. `SparseCheckoutAudit.Jobs` runs the shared `JobShape` regex over the WHOLE workflow, while
   `DotnetSdkInstallDriftTests.Jobs` (private, line 286) first slices to the text under `jobs:`. On
   build-and-test.yml `SparseCheckoutAudit.Jobs` returns the `on:` triggers push, pull_request and merge_group as jobs
   (verified). Harmless today (none carries sparse-checkout), but the two readers can drift apart; the right share is the
   `Jobs` function, not only the regex.

## Acceptance

- Function-body imports are followed; a test fails when a lazily imported repository module is missing from a sparse list,
  and `live_tools.py` is in the supersede list.
- One workflow job reader (`DotnetSdkInstallDriftTests.Jobs` made internal or moved to a shared reader) is used by both;
  `JobShape` is private again.
