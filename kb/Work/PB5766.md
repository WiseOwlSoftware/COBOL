# PB5766 - a separately compiled EXTERNAL describer's ADVANCING reaches the connector only at its activation

**Sites:**
- `src/WiseOwl.Cobol.Runtime/IO/FileRegistry.cs` (`FileRegistry.Register`: the print-file fact of a separately compiled
  describer is merged into the shared connector only when that program registers its files at its activation)
- `src/WiseOwl.Cobol.Runtime/IO/SequentialConnector.cs` (`SequentialConnector.AdvancingDeclared`,
  `SequentialConnector.SupportsVerticalPositioning`)
- `src/WiseOwl.Cobol.Compiler/Binding/ExternalFileConnectorRules.cs` (`ExternalFileConnectorRules.ShareAdvancing`: shares
  the fact across the describing units of ONE compilation group only)

**Rule.** §1985:VII.4.7.4 GR16: "If the ADVANCING phrase is not used, automatic advancing will be provided by the
implementor to act as if the user had specified AFTER ADVANCING 1 LINE" (`cite.py --check` OK). The same sentence is
§2023:14.9.51.4 GR25 ("automatic advancing shall be provided by the implementor to act as if the user has specified AFTER
ADVANCING 1 LINE", `cite.py --check` OK). Whether a file supports vertical positioning is the implementor's
determination (docs/CONFORMANCE.md section 4, Annex A.3 item 37, as the 2023 row GR-14.9.51.4-25 records it): a file
with a LINAGE clause, or one that an ADVANCING phrase is written to. An EXTERNAL file has ONE connector in the run unit,
so the fact is the connector's, and PB5570 made it so within a compilation group.

**Repro** (`E:/COBOL-coord/scratch/op-20261115/open-rows-1985/work-a/r6/exta.cob` + `extb.cob`). `EXTB` (`FD P-FILE IS
EXTERNAL`, `WRITE P-REC AFTER ADVANCING 2 LINES`) is compiled on its own to `EXTB.dll`; `EXTA` describes the same
EXTERNAL file, OPENs it OUTPUT, writes P1 and P2 with plain WRITEs, CALLs "EXTB", writes P3 and CLOSEs. Re-run
2026-11-15 on this branch's build (`registrar-1985-reread/extprobe.py`, run directories `runs/ext-85-001`,
`runs/ext-85-002` and `runs/group-85-001`):

- separately compiled, `--std 85`: `advext.txt` is `50-31-20-20-50-32-20-20-0A-0A-41-32-20-20-0A-50-33-20-20-0A`
  (P1 and P2 share one line with no advance before either);
- the same two programs in one compilation group (`work-a/r6/group.cob`), `--std 85`:
  `0A-50-31-20-20-0A-50-32-20-20-0A-0A-41-32-20-20-0A-50-33-20-20-0A` (each plain WRITE after a line feed), the
  expected file.

**Expected** (GR16): the plain WRITEs act as AFTER ADVANCING 1 LINE, so the file is the group's bytes whatever the
compilation boundary. **Actual:** P1 and P2 are bare records. Harm: a print file's first lines are welded together,
silently.

**At 2023 the same.** The repro's `FILE STATUS IS FS` is refused at 2023 (COBOL1624, an EXTERNAL file's status item must
be external), so the 2023 run used the same programs without it (`registrar-1985-reread/src-nofs/`): separately compiled
gives the same welded bytes, the group the advancing bytes (`runs/ext-2023-002`, `runs/group-2023-002`). So this also
contradicts the 2023 row `GR-14.9.51.4-25`, recorded CONFORMS; that row is not re-recorded here (its witnesses are single
compilation groups and stay true) and the fix's landing should name it.

**Why the compile time cannot see it.** `ExternalFileConnectorRules.ShareAdvancing` reads the units of one compilation
group; a separately compiled describer is reached only by `FileRegistry.Register` when its program is activated, after the
opener's plain WRITEs are already on the file.

**Fix direction (root).** The print-file fact of an EXTERNAL connector must be known when the connector is OPENed, so it
cannot come from activation order: either a determination that an EXTERNAL sequential file is a print file whenever any
describer COULD write ADVANCING (the external repository carries each unit's signature, `--repository-update on`, and
could carry the fact), or a documented implementor determination in docs/conformance/ that the run unit's separately
compiled units are not consulted (then the 1985 and 2023 rows record it). Decide which with a docs/conformance entry, then
add a two-unit conformance case (the build-step options carry the second unit) at 85 and 2023. Sibling to check: the
other connector facts PB5570 shares (`ShareAdvancing` is the one merge; the run time's `Register` merge is the second
path for the same fact).
