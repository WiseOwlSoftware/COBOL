**Symptom.** `census.CensusFailure` raised from scripts/arch/member_index.py:145 (`record`) via
tools/ArchCensus/LoadedSolution.cs:93: "ArchCensus: REFUSED - WiseOwl.Cobol.Tests.Unit does not compile in the workspace:

E:\COBOL\src\WiseOwl.Cobol.Analyzers\bin\Release\netstandard2.0\WiseOwl.Cobol.Analyzers.dll".

**Cause.** Commit f4d2ba92a0 (PB2743, landed in #1938) raised Directory.Build.props `<Version>` 31.0.0 to 32.0.0.
tests/WiseOwl.Cobol.Tests.Unit/WiseOwl.Cobol.Tests.Unit.csproj:28 references the analyzer with
`SetConfiguration="Configuration=Release"`. The main checkout's bin/Release analyzer (built 2026-11-19, version 31) was not
rebuilt by `dotnet build WiseOwl.Cobol.sln` (Debug), so MSBuildWorkspace imported both the project reference (version 32)
and the stale Release dll (version 31): two assemblies of one simple name.

**Proof by workaround.** `dotnet build src/WiseOwl.Cobol.Analyzers/WiseOwl.Cobol.Analyzers.csproj -c Release`, then
plan_wave succeeded.

**Root fix (to decide and implement by the owner of this note; nothing implemented here).**
1. The census must not load inputs it did not build or verify. Either `member_index.record` / ArchCensus builds the
   Release analyzer itself before opening the workspace, or it compares the analyzer dll's assembly version to
   `<Version>` and fails naming the stale file and the exact command that rebuilds it (rule: an unresolvable input fails
   loudly, never a default). The first is preferred: it makes the next stale input automatic.
2. The Debug solution build should rebuild a `SetConfiguration=Release` reference when `<Version>` changes, so a stale
   Release dll cannot exist beside a fresh project reference. Check how the solution configuration mapping (see the
   Directory.Build.props PB4950 comment) interacts, and extend AnalyzerBuildsOnceDriftTests or add a drift test pinning it.

**Sibling sweep.** `git grep SetConfiguration` finds two references: src/Directory.Build.props:34 (every src project's
analyzer reference) and tests/WiseOwl.Cobol.Tests.Unit/WiseOwl.Cobol.Tests.Unit.csproj:28. Both name the analyzer; the fix
must cover the test project's reference, which is the one that surfaced, and any other tool that opens the solution in
MSBuildWorkspace.
