# PB3565 — COMPUTE boolean-receiver = FUNCTION boolean-function is refused

## Scenario

Fuzz programs fz00030 and fz02828 (`WE_REJECT:COBOL1511`, 2 programs). `COMPUTE B8 = FUNCTION BOOLEAN-OF-INTEGER(5, 8)`
with `B8 USAGE BIT PIC 1(8)` is refused. The same function under B-OR or B-AND, or as a MOVE sender, compiles and runs correctly.

### Reduced repro (the C2 adjudicator's probe, verbatim: `adj\C2\probes\boolfn\boolfn.cob`)

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. BOOLFN.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 B8 USAGE BIT PICTURE 1(8).
PROCEDURE DIVISION.
    COMPUTE B8 = FUNCTION BOOLEAN-OF-INTEGER(5, 8)
    DISPLAY B8
    STOP RUN.
```

## Expected (spec)

Each citation was re-run through `python scripts/spec/cite.py --check` from the worktree on 2026-10-23 (all OK).

- §8.8.2 "Boolean expressions" (OK): a boolean expression may be "an identifier referencing a boolean data item".
- §8.5.2.5 4) "Boolean category" (OK): "A boolean function." is of the boolean category.
- §15.2 2) (OK): "Boolean functions. These are of the class and category boolean. Boolean functions have an implicit usage
  bit."
- §8.4.3.2.4 1) (OK): "A function-identifier references a temporary data item whose value is determined when the function is
  referenced at runtime."
- §15.13.4 1) (OK): BOOLEAN-OF-INTEGER returns "a boolean item of usage bit".
- §14.9.8.2 (OK): the COMPUTE general format 2 is `COMPUTE { identifier-2 } … = boolean-expression-1 [ END-COMPUTE ]`.

So a sole boolean function-identifier is a boolean expression and Format 2 accepts it. Expected: the program compiles and
prints `00000101`.

## Actual (judge e7cf38ce4)

Error COBOL1511: "a boolean COMPUTE receiver takes a boolean expression, not 'FUNCTIONBOOLEAN-OF-INTEGER(5, 8)'". Refused too:
a function-identifier alone with or without parentheses (`= (FUNCTION BOOLEAN-OF-INTEGER(3, 8))`).

Accepted and correct, probed by the adjudicator: `MOVE FUNCTION BOOLEAN-OF-INTEGER(5, 8) TO B8` gives `00000101`;
`FUNCTION … B-OR C8` gives `11110101`; `C8 B-AND FUNCTION …(255, 8)` gives `11110000`; `B-NOT FUNCTION …` gives `11111010`;
`COMPUTE B8 = B"00000101"` gives `00000101`.

## Mechanism and code site

`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/ArithmeticBinder.cs:274` (the reroute else-arm; the sole-operand check is at
`:262-:265`). The reroute from Format 1 to Format 2 (lines 256-280) recognizes only a sole data reference
(`ConditionBinder.SoleDataRef`), never a boolean function-identifier.

## Witnesses

fz00030, fz02828.

## Sibling sweep and golden to require

- Not probed: a user-defined boolean function alone on the right-hand side (the PB1419/PB1928 routing). The implementer
  checks it.
- Other places that decide "is this sole operand a boolean expression" from a data reference only (a boolean function as the
  sole operand of a relation, of EVALUATE and of a COMPUTE inside a SIZE ERROR phrase).
- Golden: the repro as a conformance case (`00000101`), the parenthesised form, and a user-defined boolean function leg.

## Orchestrator decision

§8.8.2 (a boolean expression is, among others, an identifier referencing a boolean data item) with §8.5.2.5 4) (a boolean function is of category boolean): a sole boolean function-identifier is a boolean expression, so §14.9.8 Format 2 accepts it. The F1→F2 reroute (`ArithmeticBinder.cs:262-274`) recognizes only a sole DATA reference.

## Landing

- **Code site:** src/Cobol.Net.Compiler/Binding/Procedure/Verbs/ConditionBinder.cs#BindSoleBooleanOperand (binds a sole boolean data reference, boolean constant-name or boolean function-identifier through enclosing parentheses) and #IsSoleBooleanOperand (the diagnostic-free routing twin); REUSE them for any host of a sole boolean operand, never re-read SoleDataRef/SoleFunctionCall.
- **Code site:** src/Cobol.Net.Compiler/Binding/Procedure/Verbs/ArithmeticBinder.cs#BindCompute (the Format 1 to Format 2 reroute asks the pair; the non-identifier refusal is #RefuseNonBooleanComputeOperand).
- **Trap:** a sole RHS parses as Format 1's arithmeticExpression, so `(X)` and `FUNCTION F(..)` arrive wrapped; SoleOperand.Unparenthesized strips the grouping parentheses only, never the function-argument ones.

Re-probed on the worktree build: the repro, the parenthesised form and a user-defined boolean function all reproduced
COBOL1511. The sibling sweep found two more forms refused by the same reroute: a parenthesised boolean item
(`COMPUTE B8 = (C8)`) and a boolean constant-name (`COMPUTE B8 = KB`, `KB CONSTANT AS B"00001111"`, §13.10.4 GR1).

Root cause: the reroute classified its sole right-hand operand with its own copy of the rule (an unparenthesized data
reference probed for category boolean), while the boolean expression's own leaf (`ConditionBinder.BindBoolOperandValue`)
already knew all three sole-identifier forms through parentheses. Fix: `ConditionBinder.BindSoleBooleanOperand` and its
diagnostic-free twin `IsSoleBooleanOperand` are now the only readers of the sole-identifier forms; the leaf, the routing
predicate `IsBooleanValueOperand` and `ArithmeticBinder.BindCompute` all call them, and `SoleBooleanOperandDriftTests`
pins the wiring. A numeric receiver with a sole boolean function now reports the Format 2 SR2 receiver refusal
(COBOL1511), as a numeric receiver with a sole boolean item already did.

Goldens: `cases/14.9.8-COMPUTE/pb3565_compute_boolean_sole_identifier` (2002: intrinsic, parenthesised, multi-receiver,
user function, parenthesised item, constant-name), refused `pb3565-compute-boolean-function-below-2002` (85),
`pb3565-compute-numeric-receiver-boolean-function` and `pb3565-compute-boolean-receiver-numeric-function` (2002 to 2023).
Sibling contexts probed clean: IF, EVALUATE subject and WHEN object, a COMPUTE inside ADD's SIZE ERROR phrases.
