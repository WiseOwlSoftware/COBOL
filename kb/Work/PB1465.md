# PB1465 — OPEN

## The rule (every citation re-run by the registrar through `cite.py --check`)

> The condition NOT boolean-expression-1 evaluates to the reverse truth-value of boolean-expression-1

`python scripts/spec/cite.py --check 8.8.4.3.4 "…"` → `OK  §8.8.4.3.4 2)  (General rules)`

## Refuter evidence — row `GR-8.8.4.3.4-1` (PARTIAL)

PARTIAL — GR1 covers every legal boolean-expression-1, and three legal shapes never reach evaluation. (a) The 2023 shift-only forms (IF BW B-SHIFT-L 1, B-SHIFT-LC, (BW B-SHIFT-RC 1)) are refused with COBOLNET2318, which calls them an arithmetic expression. The cause is in the cited file: ConditionBinder.BindPrimaryBoolean dispatches to BindSimpleBooleanCondition only when HasBoolOp(be[0]) is true, and HasBoolOp recognizes only B_AND/B_OR/B_XOR/B_NOT, not the four B-SHIFT tokens. A shift-only expression therefore falls into the 'defensive' bare-operand arm, where UnwrapBareBool returns null because of the shift suffix, and it is refused. COMPUTE BR = BW B-SHIFT-L 1 works (0) and IF BZ B-OR BW B-SHIFT-L 1 compiles, so the defect is only in the condition dispatch. (b) A parenthesized bare operand IF (BW) / IF ((BW)) is refused with 2318 through the same arm. (c) A parenthesized sub-expression after a binary operator or B-NOT (IF BZ B-OR (BW B-AND BW), IF B-NOT (BW B-XOR BZ)) fails to parse (COBOL0001), which Table 4 of 8.8.2 permits; it also fails in COMPUTE, so that is a grammar defect. Where the rule is reached the truth mapping is right, but an edge is unverified, so the verdict is PARTIAL.

**Code site.** src/Cobol.Net.Compiler/CodeGen/Emit/ConditionRenderer.cs; src/Cobol.Net.Runtime/Values/Text/CobolBool.cs; src/Cobol.Net.Frontend/Expressions/BitString.cs; src/Cobol.Net.Compiler/Binding/Procedure/Verbs/ConditionBinder.cs#BindSimpleBooleanCondition

## Refuter evidence — row `GR-8.8.4.3.4-2` (PARTIAL)

PARTIAL — GR2 has the same domain as GR1, 'NOT boolean-expression-1' for every legal boolean-expression-1. The reversal is correct wherever it is reached, and the adjudicator's probes plus mine (r1/r2 NOT BW OR BZ -> F, BZ OR NOT BZ -> T, BZ AND NOT BZ -> F, r4 NOT (BW B-XOR BZ) -> F) confirm it. But legal NOT forms are refused before evaluation: IF NOT BW B-SHIFT-L 1 at 2023 (COBOLNET2318, the HasBoolOp dispatch hole in ConditionBinder that omits the B-SHIFT tokens), IF NOT (BZ) (2318, the bare-paren arm), and NOT over a B-op followed by a parenthesized sub-expression (COBOL0001). The NOT-over-shift edge (2023) and the NOT-over-parenthesized-operand edge are unverified, so the verdict is PARTIAL. The test-ref l1_search_when_boolean_omitted pins only NOT over a bare subscripted item.
