cease to exist because the actual data no longer exists, as specified 8.6.4 …" (OK). §8.6.4: local-storage items —
"Each activated instance of the runtime element has its own copy of the item that persists while that instance of the
runtime element is in active state"; initial items (WS/FILE of an INITIAL program) — "An initial item persists while
the program is in active state"; static items persist to the first of "the end of the run unit", "the execution of a
CANCEL statement of a program that directly or indirectly contains the items", "the end of the object's life cycle in
the case of object data" (each OK §8.6.4).

## Landed 2026-09-30 (exceptions-batch, DEVLOG 1818)

generation it was taken in and `CobolPtr.Deref` raises EC-BOUND-PTR (reason in the detail) when it no longer matches; `Free` and `UpBy` adapted;
`Reinitialize` (static cells at CANCEL) ends the old life in place. `DataBinder.LifetimeOfCell` (`CellLifetime` Static / Activation / Instance) is the
ONE classification: Activation cells end in `Call`'s `finally` (programs) and the method activation's `finally` (`ActivationPointerSeeds` gained an `End`
element); Instance cells end via the emitted `ICobolProgram.EndStorage` (called by `ProgramTable` at the return of an INITIAL/RECURSIVE activation and at
CANCEL); Static cells via `__ResetStatics`. Goldens `2002/pb1216_{ls_and_cancel,recursive_initial,method}_pointer_lifetime` (main build reproduced every
dead-pointer shape silently). **Not done:** the brief's drift test over the GENERATED program (every `StorageCell` field named by exactly one end
mechanism) - see PB1860. OO object/factory data cells end at object death (GC) - unchanged, not modelled.
