# PB4066 — the Linux gate's tripwire calls the worktree's own commit an escape

## Sites

- `scripts/linux-gate.sh#repo_state` (about line 671) snapshots `HEAD|core.worktree` of the gated tree through `wgit` (the
  Windows worktree that started the gate), and `state_before` is taken once, before the clone (about line 672).
- `scripts/linux-gate.sh#repo_written` (about line 673) returns RED on ANY difference after the legs and prints `repository: RED —
  something wrote to the REAL repository (...). Undo it, then find what escaped the clone.`
- Both arms call it: the inert lane (about line 769, `bad="$bad repository-written"`) and the full legs (about line 993).

The tripwire exists for PB1719's breach (a test acting on the caller's REAL repository from inside the run). It cannot tell that
breach from the worktree's own agent committing on Windows while its gate's Linux half runs: both move `HEAD`.

## Witness (2026-10-29)

`E:\COBOL\.claude\worktrees\notes-leads-1029f\TestResults\build-local\000001-20261029T221136Z`: the clerk's gate of `c21a207cd`
(an inert lane: `DEVLOG/` and `kb/` only). While the Linux self-tests ran (1203 s), the clerk committed `12214f14f`, a child of
`c21a207cd`, in the same worktree, because the enqueue unit had sent it one more lead mid-run. `linux-leg.log`:

```
leg selftests: GREEN in 1203s — === SELF-TESTS: GREEN — 113 ran in 1201s ...
repository: RED — something wrote to the REAL repository (HEAD|core.worktree before: c21a207cd69dcc238a8372dc026746e8d12cb742|, after: 12214f14f55deeec3cbfec97b7ba4d93fa6ccc22|). Undo it, then find what escaped the clone.
=== LINUX GATE: RED (inert lane; failed or not run: repository-written; HEAD c21a207cd; logs in TestResults/linux-gate/) ===
```

and the gate's verdict `=== BUILD-LOCAL GATE: RED — LINUX HALF RED ...`. Nothing escaped the clone, and every leg passed.

## Consequence

The gate records RED at a head that was GREEN in every leg, and its message sends the reader after an escape that did not happen.
The verdict is also stale in a second way that the message does not say: the gate measured a head that is no longer the tip. A
finisher or an enqueue unit that trusts the line chases a breach. The commit itself was a process slip (an agent should not commit
in its worktree while its own gate runs, and a dispatcher should not send a running agent work that adds commits mid-gate), but the
gate should name that case, not misreport it.

## Direction (not a fix)

Classify the tripwire's two cases separately. When `core.worktree` is unchanged and the new `HEAD` descends from `state_before`, the
tree moved under the gate: report the gate NOT RUN for a superseded head (the gate no longer gates the tip, so nothing is red),
naming the new commit. Keep RED with the escape message for anything else (a `core.worktree` change, a `HEAD` that does not descend,
a rewritten branch). Add a self-test arm for each case. Separately, decide whether MANDATORY-PRACTICES should state the process rule
(no commit in a worktree while its gate runs) for agents and for whoever messages them.
