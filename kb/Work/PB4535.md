# PB4535 — inspect-operands-not-one-comparison-cycle: INSPECT with LEADING among several operands: wrong counts and replacements (operands evaluated pass by pass)

Filed 2026-11-03 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-batch-3000-20261103`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

When an INSPECT TALLYING or REPLACING phrase has several operands and one of them is LEADING, cobc's results differ from
ISO's single left-to-right comparison cycle. `TALLYING C1 FOR LEADING "A" C2 FOR CHARACTERS BEFORE INITIAL "B"` on
"AABCD" counts one CHARACTERS position although LEADING "A" consumed every position before the "B"; and
`REPLACING FIRST "A" BY "x" LEADING "A" BY "0" BEFORE INITIAL "B"` on "AAAAB" replaces positions 2 to 4 as leading,
although the comparison at position 1 was taken by FIRST, so no leading occurrence exists.

## Minimal test case

Free reference format (`-free`).
```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. INSPCH.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 T PIC X(5) VALUE "AABCD".
01 C1 PIC 9 VALUE 0.
01 C2 PIC 9 VALUE 0.
01 U PIC X(5) VALUE "AAAAB".
PROCEDURE DIVISION.
    INSPECT T TALLYING C1 FOR LEADING "A"
        C2 FOR CHARACTERS BEFORE INITIAL "B"
    DISPLAY "LEADING " C1 " CHARACTERS " C2
    INSPECT U REPLACING FIRST "A" BY "x"
        LEADING "A" BY "0" BEFORE INITIAL "B"
    DISPLAY "REPLACED " U
    STOP RUN.
```

## Environment

cobc (GnuCOBOL) 3.2.0 on WSL2 Ubuntu. `cobc -x -free -std=cobol2014 -o p prog.cob && ./p`.

## Observed result

Exit code 0:
```
LEADING 2 CHARACTERS 1
REPLACED x000B
```

## Expected result (per ISO)

§14.9.22.4 8) defines one left-to-right comparison cycle: a) "The operands of the TALLYING or REPLACING phrase are
considered in the order they are specified in the INSPECT statement from left to right."; b) "If no match occurs in the
comparison of the first literal-1, the comparison is repeated with each successive literal-1, if any, until either a
match is found or there is no next successive literal-1."; c) after a match the position moves past the matched
characters and "the comparison cycle starts again with the first literal-1"; e) the CHARACTERS operand's implied
character "is considered always to match the leftmost character of the content of the data item referenced by
identifier-1 participating in the current comparison cycle." §14.9.22.4 9) b): an operand with BEFORE "participates
only in those comparison cycles that involve that portion of the content of the data item referenced by identifier-1
the first character position that is eligible to participate up to, but not including, the first occurrence
encountered of literal-2", and "If, on any comparison cycle, literal-1 or the implied operand of the CHARACTERS phrase
is not eligible to participate, it is considered not to match the content of the data item referenced by
identifier-1." Eligibility is this BEFORE/AFTER region (§14.9.22.4 9) a): with neither phrase, "Literal-1 or the
implied operand of the CHARACTERS phrase is first eligible to participate in matching at the leftmost character
position"), not whether an earlier operand took the cycle. LEADING tallies, by §14.9.22.4 12) b), each contiguous
occurrence "provided that the first such occurrence encountered is at the point where comparison began in the first
comparison cycle in which literal-1 was eligible to participate", and replaces, by §14.9.22.4 17) c), under the same
proviso ("provided that the first such occurrence encountered is at the point where comparison began in the first
comparison cycle in which literal-1, was eligible to participate").

First INSPECT: positions 1 and 2 match LEADING "A" (C1 = 2); position 3 is the "B", outside the CHARACTERS operand's
region; positions 4 and 5 are also outside it, and LEADING no longer matches. C2 = 0.
Second INSPECT: the LEADING operand's region (BEFORE INITIAL "B") is positions 1 to 4, so its first eligible comparison
cycle is the one at position 1. In that cycle the FIRST "A" operand is considered first and matches (x), so the cycle
ends without comparing LEADING. The first occurrence LEADING encounters is at position 2, not at position 1 where
comparison began in its first eligible cycle, so it matches nothing and positions 2 to 4 stay "A". The rules are in
the 2014 edition. Expected output:
```
LEADING 2 CHARACTERS 0
REPLACED xAAAB
```

## Our compiler

WiseOwl COBOL (fresh judge, `--std 2014 --source-format free`) compiles it with no diagnostic and prints the expected
two lines, exit 0.

## Fix site

libcob/strings.c (read in the GnuCOBOL 3.2 source): `inspect_common` (reached through `cob_inspect_leading`,
`cob_inspect_first` and `cob_inspect_all`), `inspect_common_no_replace` and `cob_inspect_characters` process each
operand in its own pass over the region, using a per-position mark array (`set_inspect_mark`, `is_marked`) to avoid
counting a position twice, instead of one comparison cycle that tries the operands in order at each position. A
LEADING operand therefore starts at the first unmarked position, and the CHARACTERS pass sees a region that does not
agree with the cycle. Not located to a single line. The defect is specific to LEADING: with ALL in place of LEADING,
cobc 3.2.0 gives the ISO results for both shapes (`TALLYING C1 FOR ALL "A" C2 FOR CHARACTERS BEFORE INITIAL "B"` on
"AABCD" counts C2 = 0; `REPLACING FIRST "A" BY "x" ALL "A" BY "0" BEFORE INITIAL "B"` on "AAAAB" gives x000B).

## Vetting (2026-11-04)

Verdict SOUND (to be reported), medium confidence; kept open as a comment candidate on bugs #992. The tallying half (LEADING plus CHARACTERS) is the bugs #992 mechanism and is correct in 3.3-dev, while #992 is still open. The residue is real on both versions, in TALLYING and REPLACING: libcob/strings.c skips positions an earlier operand already matched and keeps counting instead of ending the leading run (14.9.22.4 8) and 9) a) and b), 12) b), 17) c); the rival reading is refuted by Annex D.25 Example 3, cite.py --check OK). Probe v ('TALLYING C1 FOR ALL "AA" C2 FOR LEADING "A"' on AAAB gives 1, expected 0) fails on 3.2.0 and 3.3-dev. A comment on #992 built on probe v, not a new ticket, is the most to do.

## Draft issue

**Title:** INSPECT with LEADING among several operands: wrong counts and replacements (operands evaluated pass by pass)

GnuCOBOL 3.2.0, WSL2 Ubuntu, `cobc -x -free -std=cobol2014 -o p prog.cob && ./p`.

ISO/IEC 1989:2014 (INSPECT general rules 8, 9, 12 and 17) defines one left-to-right comparison cycle in which the operands
are tried in order at each position; LEADING matches only occurrences that start where comparison began in the first
cycle in which the operand was eligible. Two results differ:

1. `INSPECT T TALLYING C1 FOR LEADING "A" C2 FOR CHARACTERS BEFORE INITIAL "B"`, T = "AABCD": LEADING takes positions 1
   and 2, so CHARACTERS (region: positions before the "B") counts nothing. cobc gives C2 = 1.
2. `INSPECT U REPLACING FIRST "A" BY "x" LEADING "A" BY "0" BEFORE INITIAL "B"`, U = "AAAAB": FIRST takes position 1,
   so no leading occurrence of the second operand exists. cobc replaces positions 2 to 4.

Observed:
```
LEADING 2 CHARACTERS 1
REPLACED x000B
```
Expected:
```
LEADING 2 CHARACTERS 0
REPLACED xAAAB
```
libcob/strings.c handles each operand in a separate pass with a mark array rather than one comparison cycle.

Program (free format):
```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. INSPCH.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 T PIC X(5) VALUE "AABCD".
01 C1 PIC 9 VALUE 0.
01 C2 PIC 9 VALUE 0.
01 U PIC X(5) VALUE "AAAAB".
PROCEDURE DIVISION.
    INSPECT T TALLYING C1 FOR LEADING "A"
        C2 FOR CHARACTERS BEFORE INITIAL "B"
    DISPLAY "LEADING " C1 " CHARACTERS " C2
    INSPECT U REPLACING FIRST "A" BY "x"
        LEADING "A" BY "0" BEFORE INITIAL "B"
    DISPLAY "REPLACED " U
    STOP RUN.
```
