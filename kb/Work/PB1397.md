## Finding — `character-sets` (silent; rows `GR-8.1.2-3`)

**Mechanism.** Two required-and-documented §8.1.2 implementor specifications have no documentation: the one-and-only-one coded character values for SPACE/QUOTE/ZERO, space fill and the editing characters in both the alphanumeric and national sets (Annex A.1 item 32), and the implementor-defined additional characters prohibited as a currency symbol (A.1 item 44, whose implemented answer is the empty set - DataBinder.ValidateCurrencyChar enforces only SR22/SR27). Bits-per-byte (A.1 item 12) is stated only inside the USAGE BIT prose, with no DOC-A.1-12 register row.

**Repro.** grep docs/ for a coded-character-value statement for SPACE/QUOTE/ZERO/'B'/'0' or a currency-symbol prohibition beyond §12.3.7.3 SR22/SR27: none; no DOC-A.1-12/-32/-44 rows exist in docs/CONFORMANCE.md.

**Expected from the spec.** §8.1.2 (cite.py OK): "The implementor shall specify one and only one alphanumeric coded character value associated with each of the following COBOL elements" (and the national twin), and "the implementor shall specify any such additional characters that are prohibited from use as a currency symbol"; Annex A.1 items 12, 32 and 44 are each required and shall be documented in the implementor's user documentation.

**Observed / reasoning.** The behaviour is consistent (' ' U+0020, '0' U+0030, quote U+0022 in both classes; no extra currency prohibitions) but the documentation obligation is unmet, so the conformance claim for these items is unevidenced.

**Code site.** docs/CONFORMANCE.md (missing DOC-A.1-12, DOC-A.1-32, DOC-A.1-44 rows); src/Cobol.Net.Compiler/Binding/DataBinder.Switches.cs#DataBinder.ValidateCurrencyChar

## Finding — `cobol-character-repertoire` (silent; rows `GR-8.1.3.2-1`, `GR-8.1.3.2-2`)

**Mechanism.** The source-text encoding determination (per-file BOM detection, default UTF-8, invalid bytes silently replaced by U+FFFD, several encodings allowed in one compilation group) exists only in CompilationInputs.ReadAllText and is not documented anywhere in docs/CONFORMANCE.md, so the required A.1 item 25 (and the conditionally required item 26) have no determination

**Repro.** (1) A fixed-form source saved as Latin-1 containing DISPLAY "caf<0xE9>". -> pinned cobol.exe --run prints bytes 63 61 66 EF BF BD with no diagnostic. (2) A UTF-8 source (no BOM) that COPYs a copybook saved UTF-16LE with BOM containing 01 CPY-ITEM PIC X(3) VALUE "é1". -> compiles and prints 'é1'.

**Expected from the spec.** 8.1.3.2 GR1 and Annex A.1 item 25 require the implementor to define AND document the mapping of the repertoire to its coded character set(s) (and substitute graphics, here none); GR2 and A.1 item 26 require specifying the method that distinguishes encodings when more than one is permitted in a compilation group. The user documentation must state: source decoded per file by byte-order mark (UTF-8/UTF-16LE/BE/UTF-32), UTF-8 when none; what happens to bytes invalid in that encoding.

**Observed / reasoning.** grep of docs/CONFORMANCE.md for source encoding, UTF-8 source, byte-order mark, 'repertoire (encoding' finds nothing; no DOC-A.1-25/-26 row. The behavior itself is a legitimate implementor choice, but the silent U+FFFD replacement of a non-UTF-8 byte in a literal changes program output without any indication -- the determination should either document it or make an undecodable byte a diagnostic (a strict UTF8Encoding(throwOnInvalidBytes: true)).

**Code site.** src/Cobol.Net.Frontend/Pipeline/CompilationInputs.cs#CompilationInputs.ReadAllText (File.ReadAllText); src/Cobol.Net.Frontend/Preprocessor/CopyProcessor.cs (~line 430)
