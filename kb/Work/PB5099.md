# PB5099 - a re-gate at an unchanged tree re-runs only what did not pass

**Owner (2026-11-09 23:40):** "This makes no sense. If only one test failed, any retry should test only that one case."

**Sites:** `scripts/gate.py` (the run planner and the GREEN record `enqueue.py land` reads), `scripts/build-local.ps1`.

**Found.** Wave 20261972's implementer (PB5060, worktree wf_14a80b82-683-1) finished its change in 13 minutes and then spent
three hours gating one commit, 6bede3198b (tree fc15c9ace5f9e0c108efced6cd679194098a6ab2). Run 000002 ran all of Conformance
(22,783 passed), Characterization (37 passed) and Unit (40,729 passed) and went RED on ONE case,
`ArchReviewFleetDriftTests.EachFleetInstrument_PassesItsSelfTest(file_census_notes.py)`, a HARNESS NON-OBSERVATION (its
process budget ran out under host load; no output was compared). Run 000003 at the SAME tree waited 1,448 s for a slot and then
re-ran the whole population for 58 minutes (Conformance 1,948 s, Unit 891 s) to turn that one case GREEN; `first-classes`
only ordered the red class first. Both `verdict.json` files record `tree` = `head_tree` = `tree_end` = fc15c9ace5.

**The decision.** THE RULE (owner 2026-10-31) asks that every case the merge group runs on Windows already ran green AT THE
PUSHED HEAD on this host under the same toolchain, not that it ran green in one run. So a re-gate whose tree equals an earlier
run's tree (and toolchain) re-runs only that run's reds, non-observations and unrun cases (and any audit or self-test whose
inputs changed, which `self_tests.py --reuse` already does), and the GREEN record names the earlier run's passes it composes
with. A changed tree re-runs everything, as today. Owed: the composition in gate.py's record, `enqueue.py land`'s reading of a
composed record (exit 14 stays the refusal for a tip no record covers), the drift test (a planted two-run composition at one
tree is GREEN; a composition across two trees is refused), and the gate skill and DESIGN-test-build-ci.md text.

**Sibling case: an inert-only commit on top of a GREEN code-lane run (Mythos, 2026-11-09 23:59).** Mythos's
readjudicate-pb5062 branch had a GREEN code-lane gate, then took a review fix that changed only inert paths (`*.md`,
`kb/`). The next gate re-ran the whole population at the new tree, and Mythos killed it. The trees differ, but only in paths
`inert_lane.py classify` calls inert, which no compiler test reads. So the earlier run's passes stand for the new tree too:
the gate runs the inert lane's audits and composes them with the earlier run's record. This is the same composition,
keyed on "the code-lane inputs are unchanged" rather than "the tree is unchanged". The drift test adds this case: a GREEN
code run, then an inert-only commit, composes to GREEN with no host run, while a commit that touches one code path re-runs
everything.

## Landed (w20261976 group A)

**Sites:** `scripts/gate.py` (`ONLY_CASES`, `host_env`, `Host.code_state_diff`, `Carry`, `measuring_runs`, `Gate.carry`,
`Gate._composed`, `Gate._retry`, `Gate._tested`, `Gate._run_hosts`, `Gate._check_populations`, `Gate._verdict`, `Gate._record`,
`Gate._record_growth`, `Outcome`), `scripts/test_population.py` (`passed_cases`, `not_passed`, `check`, `Population`),
`tests/_shared/GateLegs.cs` (`GateOnly`, `GateExecutor.Select`), `tests/WiseOwl.Cobol.Tests.Unit/GateLegDriftTests.cs`
(`Only_RunsExactlyTheNamedCases_AndRefusesAFileThatNamesNone`), `scripts/orchestrator/land_lane.py` (`red_facts`),
`scripts/arch/perf_baseline.py` (`gate_rows`), `scripts/self_test_arms.py` (`DECLARED`),
`docs/rearchitecture/DESIGN-test-build-ci.md` (§3.14.12 item 5), `.claude/skills/gate/SKILL.md`.

**What it was.** A re-gate of a tree an earlier run measured re-ran the whole population, because the reuse rule answered only
from a GREEN record. THE RULE asks that every case ran green at the pushed head under one toolchain, not in one run.

**The fix.** `Gate.carry` composes with earlier runs of the SAME CODE STATE (the same tree, or one that differs only in inert
paths by `inert_lane.py`, under the same toolchain, full lane, tree unchanged while it ran). A GREEN one answers with the
audits alone (`COMPOSED`: this is the Mythos inert-only sibling case, and the same tree under another base). A RED one's passes
are carried: the gate lists the population, writes the names the passes do not cover to `only-<assembly>.txt`, and the host's
`GateOnly` hook (`WISEOWL_COBOL_GATE_ONLY`) runs exactly those cases; `test_population.check(carried=)` composes the rest and
keeps NEVER RAN honest. The record names `composed_from` and `carried`; `gate.measuring_runs` is the one resolution of the runs
holding a verdict's evidence (the landing lane's red classification reads through it). Probed on this build: the hook ran
exactly the named cases of Characterization and of Unit (escaped and truncated names, a `file_census_notes.py` theory row), and
the names equalled the trx definitions.

**Not changed (stated).** The slot wait before a retry (1,448 s in the note) is the gate cap's, not the composition's.
