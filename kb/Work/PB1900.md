# PB1900 — OPEN

Found by the 2026-09-30 read-only adjudication of the numeric cluster's documented limits (checked citations; see the session scratchpad report `w0930-limits-adjudication.md`, item 3). It is NOT an ISO divergence:
8.8.1.3 "Native arithmetic is an implementor-defined method of evaluating an arithmetic expression", 14.7.7 4) a) "Otherwise, an implementor-defined intermediate data item is used", Annex A.1 item 123
(documented in DOC-A.1-123); under STANDARD-DECIMAL 8.8.1.5.2 REQUIRES decimal128 results, so 34 digits is correct there. It IS a departure from CLAUDE.md rule 1, which makes the implementor latitude follow GnuCOBOL
(`cob_decimal_mul` is `mpz_mul`, exact: libcob/numeric.c:2232-2237; DOC-A.1-123 itself says so).

**Wrong answer, plain ISO code.** All operands `PIC 9(21)` (within the 13.18.40.3 SR14 limit of 31 digits), A = B = 10^20+1, C = 10^20, D = 10^20+2, R `PIC 9(9)`:
`COMPUTE R = A * B - C * D`. The exact result is 1. The 41-digit `A * B` goes through `MulToOdd` (`NumericRenderer.cs` ~L745) and becomes 10^40 + 2*10^20 + 10^7, so R stores **10000000**. The adjudicator derived this from
the code and DOC-A.1-123 and did not run it: **probe it first.** Only cancellation exposes the loss; the original COMP-5 repro in the train review uses a non-ISO usage.

**Fix design.** In NATIVE mode carry a nested product that exceeds the Int128 bound as an EXACT scaled wide integer (the 256-bit product `CobolDec.MulAtScale` already forms) and do the additions and subtractions on that
exact form; round ONCE, at the final transfer to the receiver. Reserve the 34-digit SDIDI for STANDARD-DECIMAL, where 8.8.1.5.2 requires it. Then rewrite the DOC-A.1-123 sentence that names the 34-digit nested intermediate as the
determination. Quotients may stay on round-to-odd: GnuCOBOL's own divide is inexact too (`shift_decimal` then a truncating `mpz_tdiv_q`, numeric.c:2259-2261), so the precedence does not demand exactness there.
Sibling sweep: every other native place that rounds an intermediate to 34 digits (SUM / RANGE / MEAN / MEDIAN / MIDRANGE, DOC-A.1-92, whose rounding the same adjudication found licensed as an approximation under 15.4.1).
