# PB3361 — the finished test trusts the implementer's `report` field instead of the report's canonical path

Found by the wave-1115 unit, 2026-10-17 ~23:00 PDT. Sibling of PB3260 (the same finished test misreads a DONE, there
because a review finisher's rewrite dropped the Status line); this one is a different input to the same test. Grepped
`kb/Work` for `UNREADABLE`, `not a fix-lane report name`, `finishedReport`, `--finished`: PB3125, PB3181 and PB3260 name
the test, none this input.

**What happened.** Group E (PB2849, Sonnet) gated GREEN and returned `status: DONE` with `report: "DONE. PB2849 landed as
a tests-only change; the report is at E:\COBOL-coord\scratch\reports\w1115e-PB2849-report.md."`. `finishedReport`
(`.claude/skills/workstream/templates/wf_rolling_wave.js`, line 194) ran `plan_wave.py --finished "<that sentence>"`,
which answered exit 2 `=== REPORT: UNREADABLE … not a fix-lane report name (w<wave><letter>-PB<lead>-report.md) ===`,
and the wave logged the group SPLIT with no reviewer dispatched. The report itself was correct, at the path the dispatch
spec named (`msg-w1115-e.txt` line 7, `Report: E:\COBOL-coord\scratch\reports\w1115e-PB2849-report.md`), with a valid
`**Status:** DONE` header.

**The defect.** The report's path is not the agent's to say: it is `<coord>\scratch\reports\w<wave><letter>-<lead>-report.md`
(`plan_wave.py` `REPORT_NAME`, `coord.reports_dir()`), which the workflow knows from its own args (`S`, `W`, the group's
letter and lead) and which the renderer wrote into the spec. Yet `IMPL_SCHEMA` (line 50) types `report` as a bare
string with no pattern, and the finished test, the reviewer prompt (`reviewBranch`, `r.report`) and the wave's `ready`
list (line 323) all take the agent's text. One model's paraphrase drops a branch out of the wave's review.

**Failure scenario.** A DONE, gated branch whose implementer writes its `report` as prose (as group E did) is never
reviewed inside the wave; it waits for an `enqueue` unit to review it by hand, costing a unit and the branch's landing
latency, and the wave's own log calls a finished branch SPLIT.

**The shape the fix should take.** The workflow computes the report path from its args (one function, the same rule as
`plan_wave.REPORT_NAME`, pinned by a drift test that the two agree) and passes that to the finished test, the reviewer
and the `ready` list; the agent's `report` field is dropped from the schema, or kept only as a cross-check that must
equal the computed path.

**Second witness: wave 1117 group F (PB675), 2026-10-18 ~02:50 PDT.** The REVIEW FINISHER (fix-F-r1, branch
`worktree-wf_938f9825-cf4-15`, head `1b263f2ec`) returned DONE with a GREEN leg-1 gate and `report: "Report at
E:\COBOL-coord\scratch\reports\w1117f-PB675-report.md"`. The finished test ran `plan_wave.py --finished` on that
sentence and got `=== REPORT: UNREADABLE ... [Errno 22] Invalid argument ===`, so F had no round-2 review inside the
wave, although its rewritten report sat at the canonical path with a correct header. The defect reaches the review
finisher's return as well as the implementer's, so the computed path must feed both.

**Third witness: wave 1119 group F (PB1154), 2026-10-18 ~07:40 PDT.** The REVIEW FINISHER (fix-F-r1, branch
`worktree-wf_25c91241-1f8-20`, head `c246ad70b`) returned DONE with a GREEN leg-1 gate and a `report` that was a
sentence ("PB1154 review finisher, round 1: both findings (R1-1, R1-2) answered "fixed" in commit 01323eb5d. ...").
The finished test refused it, the wave logged F as SPLIT, and round 2 never reviewed the tip, although
`plan_wave.py --finished E:\COBOL-coord\scratch\reports\w1119f-PB1154-report.md` exits 0 (`FINISHED status=DONE
head=c246ad70b`). That makes three witnesses in three waves (1115 E, 1117 F, 1119 F), and each one costs a later unit a
review dispatch that the wave should have made itself.
