# PB4516 — One approximate intrinsic result lands two ways: COMPUTE R = FUNCTION EXP10(-6) and MOVE store 0.000000 (FromDouble) while COMPUTE R = 0 + FUNCTION EXP10(-6) stores 0.000001 (LiftApproximation)

**Found:** 2026-11-03 by the Sonnet-written fuzz batch; adjudicated WISEOWL-DEFECT (Opus adjudicator, billed to the API key), and its reduced repro re-run on a judge built from main a0e05167d (`fuzz_triage.py verify`) still shows it.

**The adjudicator's finding.** One returned value lands two ways: COMPUTE R = FUNCTION EXP10(-6) and MOVE store 0.000000 (FromDouble truncates the binary64 9.99999999999999955e-7 by its exact expansion), while COMPUTE R = 0 + FUNCTION EXP10(-6) stores 0.000001 (LiftApproximation: shortest round-trip). The temporary data item of §2023:15.4 has one value; WiseOwl's own determination (CONFORMANCE.md: an approximation enters through CobolDec.FromApproximation) and the PB1641 comment both say the result must not depend on the receiver shape. # PB4516 — LANDED

**Mechanism.** A binary64 returned by an intrinsic (`NumX.Approximate`) is an engine approximation whose value is its shortest round-trip decimal (`CobolDec.FromApproximation`, CONFORMANCE.md). Only the operand lift (`LiftApproximation`) and the text/edit channels read it so; every FLOAT-TO-FIXED LANDING (`FromDouble`, `CobolFloat.ToScaled*` through `StoreArgs`, `EditedLanding`, `Align`, `AlignRoundedUp`, `MoveSending.AtScale`, the DIVIDE REMAINDER quotient) read the binary EXPANSION, so EXP10(-6) landed 0.000000 alone and 0.000001 beside an operator (and PROHIBITED refused it). **Fix.** Three runtime twins `CobolFloat.ToScaledApproximation{,Unchecked,Intermediate}` (the decimal lane's `ToUnscaled*` after `FromApproximation`; a non-finite value keeps its binary64 disposition), `FromDouble` lands through them, and `RuntimeApi.FloatToScaled` / `FloatToScaledIntermediate` take the value's kind as a required argument that every emitter site reads off `NumX.Approximate` (`CarrierLandingFormTests.EveryFloatToScaledSite_PassesTheValuesApproximateFlag`). A float DATA ITEM still lands by its exact expansion. Re-probe on the branch: ALONE / PLUS0 / MOVE all `+000000000.000001`.
