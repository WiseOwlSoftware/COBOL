**The rule it breaks:** `DESIGN-backend-abstraction.md` §1.1 (what a bound node MAY contain: resolved symbols, a
structural `Place`, categories and numeric facts, literal values, neutral runtime-data strings, control-flow shape) —
neither a binder nor a parse context is on it; §1.3 lists the leaks L1–L5 and records L5 ("`RoslynBackend` …
performs no binding") as DONE, while the emitters run the `Place` builder at emit time. A CIL backend implementing
`ICodeGenBackend` would have to drive the C# compiler's binder to emit anything.

**Scenario:** a second backend (P16) is written against `BoundCompilation`; it cannot compute a `Place` without calling
`ReferenceResolver.ResolveItem`, i.e. without the binder and the parse tree — the seam §1 promises does not exist.

**The front-end review's AST verdict, reconsidered against this seam (Mythos session, 2026-10-31).** The Mythos
front-end review (GRAMMAR-REVIEW.md §5, S8; artifact https://claude.ai/artifact/VpxTVcaFUsArrq59EvUe5r) recommends
keeping the binder on the generated parse contexts and building no separate AST between parser and binder. Weighed
against the requirement that a direct-IL backend can replace the Roslyn one, the verdict stands: a backend consumes the
bound tree (DESIGN.md §1.1, PIPELINE_DESIGN.md D1, "the bound tree IS the model"), and a tree inserted upstream of the
binder is invisible to it. But the verdict holds only once the parse tree stops at the binder, which is this campaign's
job: the bound tree is the project's AST for every backend, and it is not context-free yet (PB2398: the tolerated
edges `Binding.Bound → Frontend.Generated`, `Binding.Model → Frontend.Generated` and `CodeGen → Frontend.Generated`).
Two consequences: (1) the work an AST would buy is completing the bound tree, not adding a tree, and PB4266's contract
test is what keeps it complete; (2) bound nodes keep only `int SourceLine` (9 declarations under `Binding/Bound`), which
gives a CIL backend line-level sequence points; statement-level stepping on a line holding several statements would
need a column too, which the CIL backend's design (DESIGN-backend-abstraction §7 item 2, portable PDB via Cecil) should
decide when it is written.
