# PB3526 — a held gate lock is not a red gate

## What happened (2026-10-22 12:29–12:30 PDT)

The Mythos session ran `enqueue.py land` on PB3511's branch `worktree-wf_8c44feac-62f-10` at 12:29; the loop's landing
lane (`land_lane.py` attempt `20261022T193024308865Z`) started its own at 12:30:24. One gate held the worktree's gate
lock; the other's `build-local` ended NOT RUN ("another gate holds this worktree's gate lock",
`scripts/run_gate_legs.py`), and `enqueue.py` printed `=== ENQUEUE: GATE RED (Windows) ===` and recorded BLOCKED.

## Mechanism

`scripts/orchestrator/enqueue.py` step 3 (`land`): every `(host, green, line)` the gates return that is not green becomes
`blocked(branch, wt, "BLOCKED: enqueue — the <host> gate is not GREEN …")` and `EXIT_GATE` — NOT RUN included. A NOT RUN
for a held lock says nothing about the branch; it says another run is gating the same tree.

## Harm

A healthy branch is stamped BLOCKED, and a BLOCKED report is exactly what makes a finisher dispatcher act (PB3379's
recurrence of the same morning: two finishers on this branch). The duplicate `enqueue.py land` is itself the PB3379
ownership gap; this note is the separate defect that the second run's failure is reported as the branch's failure.

## The bar for the fix

- `enqueue.py` tells a lock-held NOT RUN apart from a red (from the gate's own verdict, never a text guess if a structured
  verdict exists: `run_gate_legs.py`'s `verdict.json`) and ends with its own exit (busy: another run gates this tree),
  writing NO BLOCKED line; `land_lane.py` treats that exit as "retry later", never as a stop.
- Sweep (rule 4): every other NOT RUN cause the gate reports (malformed gate settings, an unlistable population) is
  classified on purpose — a NOT RUN the branch caused may block; one the environment caused may not.
- A test in `test_enqueue.py` pins: a lock-held NOT RUN writes no BLOCKED and returns the busy exit.

## Landing (wave 1150 group A, with PB3527; review round 1's finisher)

PB3527's branch fixed this as its mechanism 2 (one verdict reader): the gate driver's verdict for a held gate lock is
`BUSY` (exit 3), `run_gate_legs.read_verdict` is the one reader of a verdict line, and `enqueue.py land` ends a BUSY
gate `GATE BUSY`, exit 12, with no `BLOCKED:` report line; the landing lane retries it at the same head once the
worktree's gate lock is free (`land_lane.WAITS`, `wait_free`). Its self-test pins it (`enqueue.py`: "land: a gate BUSY
... is exit 12, never a red: no report line").

The sweep the bar asks for (review R1-1 found it missing; review R2-1 found the first sweep read every cause as the
environment's): every other NOT RUN cause is classified ONCE, in `run_gate_legs.NOT_RUN_CAUSES`, and printed by tag,
`NOT RUN [<cause>]`; `read_verdict` returns the cause with the reading and `enqueue.py` reads the class, never
re-deriving it. ENVIRONMENT (no finisher can fix it): `[settings]` malformed shared gate settings (at the start or while
the gate queued), `[interpreter]` no runnable Python or no PyYAML, `[host]` no WSL, `[sdk]` no .NET SDK in the Linux
environment, `[tree]` the tree's git state unreadable or its clone failed: `land` ends `GATE NOT RUN (<host>)`, exit 2,
with no report line; the lane retries it once and a second at the same head is the operator's handoff. BRANCH (a failure
of code the gated tree carries, since a landing runs the merged tree's own build-local, run_gate_legs.py and
linux-gate.sh): `[driver]` the gate driver failed, `[population]` the population could not be listed after a GREEN
build, `[arguments]` the gate script refused its arguments, `[verdict]` no verdict line, `[unslotted]` a gate row that
would run outside the shared slot, and `[unclassified]` a NOT RUN naming no known cause. That is the bar's "a NOT RUN the
branch caused may block": `land` measures MAIN at the same step (`enqueue.gate_main`: the same gate row in a clean
detached checkout of the origin/main the branch merged, once per main head and host, recorded in the common git dir's
`enqueue-main-gate.json` and read by the next landing at that head), and a main failing with the same cause is exit 2
with no report line (main's defect, the operator's), while any other main reading, or a main that could not be
measured, blocks: exit 5, `BLOCKED: enqueue — the <host> gate was NOT RUN … by code the branch carries ([<cause>] …);
main … reads …`, a finisher's. A red the branch caused (RED, RED/INCOMPLETE, LEG 1 ONLY: RED, BUILD FAILED, a GREEN line
with a non-zero exit) still blocks, exit 5. Witnesses: `run_gate_legs.py` ("the one verdict reader ...", "a population
that cannot be listed ... is NOT RUN [population]", "every NOT RUN verdict a gate prints names a cause NOT_RUN_CAUSES
classifies"), `enqueue.py` ("land: a gate NOT RUN for a cause in the ENVIRONMENT ...", "land: a BRANCH-carried NOT RUN
...", "land: an UNCLASSIFIED NOT RUN ...", "gate_main: main is measured in a clean checkout of its head ...").
