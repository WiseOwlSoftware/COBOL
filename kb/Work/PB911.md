# PB911 — LANDED — one format got the message, its twin got COBOL0001

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs` (`CobolErrorStrategy.SingleTokenDeletion`), `tests/WiseOwl.Cobol.Tests.Unit/RequiredImperativeStatementDriftTests.cs` (`RequiredImperativeStatementDriftTests.EveryRuleThatCallsStatementBlock_HasAnEmptyBlockWitness`, `RequiredImperativeStatementDriftTests.AnEmptyRequiredBlock_AtEveryRulePosition_DrawsExactlyOneCOBOL2072`), `docs/rearchitecture/DESIGN-frontend-grammar.md` (§3.9 recovery bullet), `conformance-suite/cases/14.9.28-PERFORM/pb911-perform-f3-empty-imperative-1.cob`

## Landed (re-probe, 2026-10-30)

The headline no longer reproduced on the wave-20261769 build. Format 3 `PERFORM WHEN EC-ALL …` (empty
imperative-statement-1) draws `COBOL2072: cannot parse construct near 'WHEN'. The PERFORM statement's general format
shows an imperative-statement here …`: kb/Work PB3832 (commit `70be735c0`, "the parse hints read the offending token's
position") made the ATN detector read the parse at the offending token, which the Format-3 head had defeated. The
detector was never a per-format table; `EmptyBlockOwner` is structural, so the note's "format table" premise was
already met. What the re-probe DID find, in both formats alike: `PERFORM UNTIL X = 0 END-PERFORM STOP RUN.` (and every
Format-3 phrase with an empty body, and `PERFORM 3 TIMES END-PERFORM`) drew a SECOND, false `COBOL0001: unexpected '.'`
at the next sentence's period. Root cause: ANTLR's single-token deletion removed the END-PERFORM because the token after
it begins a statement, so STOP RUN became the body and the PERFORM, whose END-PERFORM is required, found none. IF,
EVALUATE and SEARCH have optional terminators and hid it. Fix: `SingleTokenDeletion` declines when
`OffendingPosition.EmptyBlockOwner()` names an owner at the token (the token is the owner's terminator or next phrase,
not a stray). The drift test reads every rule that calls `statementBlock` from the ATN (11) and requires an empty-block
witness for each, exactly one COBOL2072, at depth 0 and inside the open nest.

Source: the `PB432` report, "New defects" item 2. Re-measured here, both arms.

## The measurement

```
f_perform_fmt3_empty.cob(5,15): error COBOL0001: cannot parse construct near 'WHEN'
```

`<scratch>/reg7/probe/f_perform_fmt2_empty.cob` — Format 2 (`PERFORM UNTIL …`), the same omission:

```
f_perform_fmt2_empty.cob(8,12): error COBOL2072: unexpected 'END-PERFORM'. The PERFORM statement's
general format shows an imperative-statement here that is not bracketed, so at least one statement shall be
specified: brackets are what license an omission (ISO §5.2.6.2), and one alternative of a brace group shall
be explicitly specified (ISO §5.2.6.3).
```

Same statement, same omission, same rule — one user is told exactly what is wrong and where the rule is,
the other is told the parser gave up.

## The rule

```
$ python scripts/spec/cite.py --check 5.2.6.2 "Brackets"
OK  §5.2.6.2   (Brackets)
$ python scripts/spec/cite.py --check 5.2.6.3 "Braces"

```

Both PERFORM formats print imperative-statement-1 UNBRACKETED, so §5.2.6.2's licence to omit does not
apply to either, and COBOL2072's text is correct for both.

## The code site

The ATN expected-set detector behind `DiagnosticCatalog.RequiredImperativeMissing` — the machinery
**PB396** (landed) built when it closed the Format-2 arm. It does not fire on the Format-3 alternative.

## Why this is filed rather than folded into PB396

PB396 is `landed`. This is its residue, and it is the repo's most reproducible defect shape
(`feedback_two_arm_dispatch`, 5x): a dispatch with two arms, one arm fixed. The fix is not "add Format 3" —
that is the same shape one alternative further along. The detector should be driven from the PERFORM
statement's FORMAT TABLE (whatever selects among §14.9.28.2's formats) so every format's unbracketed
imperative slot is covered by construction, with a drift test that enumerates them.
