# PB849 — LANDED — one level-88 alternative where the standard prints four formats

Source: the `PB488` implementer report, items (A) and (B). PB485 (the level-number/format domain) is LANDED, so
these have no live owner; they are one mechanism — the entry's FORMAT is never selected, so neither the name's
obligation nor the validation format's syntax exists.


## The formats, quoted

```
$ python scripts/spec/cite.py --check 13.16.2 "condition-name-1"
  OK  §13.16.2   (General formats)
      88 condition-name-1 value-clause .
$ python scripts/spec/cite.py --check 13.16.2 "condition-name-2"
  OK  §13.16.2   (General formats)
      88 [ condition-name-2 ] value-clause .
$ python scripts/spec/cite.py --find "content-validation-entry format"
  §13.16.2   (General formats)
      where value-clause is described in 13.18.63, VALUE clause (content-validation-entry format).
```

Format 3's condition-name is **not** bracketed; only Format 4's is, and Format 4's value-clause is the
content-validation form (VALID / INVALID), not the condition-name form. So a nameless entry carrying a
condition-name-format VALUE clause is NEITHER format, and the validation entry — obsolete, therefore a §4.2
conformance obligation with an obsolescence warning, not an omission — has no syntax at all.

⚠ Both are `<pre>` general-format blocks: render the page (`scripts/render-spec-page.py`) before either text
reaches a code comment, per CLAUDE.md rule 1.

## Code sites

`src/Cobol.Net.Frontend/Grammar/Core/CobolData.g4` — `dataDescriptionEntry : levelNumber dataName?
dataDescriptionBody DOT` makes the name optional for EVERY level, and `valueClause` has no VALID/INVALID
alternative; `src/Cobol.Net.Compiler/Validation/LevelNumberPass.cs#BodyForm` classifies the body as `ValueOnly`
without asking whether the format that admits that body requires a name.

## Shape of the fix

`BodyForm` already computes the body's shape; the missing half is selecting the FORMAT from (level, name
presence, body shape) and then enforcing that format's own rules. That structure makes Format 4 an added arm
rather than a special case, and it is what stops the next level-88 rule from being written twice.

## Sibling sweep the fixer owes

* Every other level whose name is optional by grammar and mandatory by format (levels 1-49 take FILLER by
  §13.18.20.3 SR2, level 66 and level 77 do not).
* The obsolescence warning path (`>>FLAG-14` / the ARCHAIC list in `docs/VERSION_CHANGE_REFERENCE.md`) must carry
  the validation format once it parses.

## Landed (2026-09-22, wave 48 group U)

**Re-probed on this tree first; the note did not hold as written.**

* **(A) no longer reproduced.** `88 VALUE "AB".` is refused with COBOLNET1747 since PB501 landed
  (`0c98c143c`, `git log -S HasContentValidationPhrase`).
* **(B) is not legal source.** `88 VALID 1 THRU 9.` omits the VALUE / VALUES word, and §13.18.63.2 format 5
  prints `{ VALUE | VALUES }` as a REQUIRED, underlined choice (PDF p546 / folio 516 rendered), so COBOL0307 there is
  the right answer. The legal spelling, `88 VALUE 1 THRU 9 VALID.`, parses and is refused BY NAME with COBOLNET1708
  (the owner-declined A.4.14 VALIDATE facility, docs/CONFORMANCE.md §5). Format 4 is modelled, not missing.
* **The note's own sibling sweep was the live defect.** Two more formats have an UNBRACKETED name and neither
  had a check: `66 RENAMES A THRU B.` and `66 FILLER RENAMES A THRU B.` (§13.16.2 format 2, §13.18.45.2 —
  `66 data-name-1 RENAMES …`, no entry-name clause) and `88 FILLER VALUE "A".` (formats 3 and 4 name a
  condition-name; FILLER is the entry-name clause's filler format, §13.18.20.2 format 3, which only format 1
  carries). All three compiled clean at every edition and the entry evaporated.

**Fix — one table for the name slot.** `LevelNumberRules.EntryNameObligation(entry, level)` is now the ONE place
the (level, format) name obligation lives: 77 (§13.16.3 SR2/SR4), 66 (format 2), 88-FILLER and nameless-88 without
VALID/INVALID (formats 3/4, SR24). `LevelNumberPass.CheckEntryFormat` has one arm, `case (_, 66 or 77 or 88)`,
replacing the two hand-written arms (77 and the PB501 nameless 88) — the third format had simply never been written.
Goldens: `negative/pb849-renames-entry-has-no-name`, `negative/pb849-condition-name-entry-filler` (COBOLNET1747,
reject-at 85 2002 2014 2023). Rows: FMT-13.18.45.2 GAP → CONFORMS; FMT-13.16.2 and SR-13.16.3-24 gained the witnesses.

`rejects_legal_source` flipped to false: the only rejection the note measured, (B), is of source format 5 does not admit.
