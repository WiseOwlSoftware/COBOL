# PB176

Found 2026-08-30 by the PB164 VLG-display landing probes, and PROVEN PRE-EXISTING at `4006248f` by
stash/build/probe/pop — the VLG slice neither introduced nor changed it. Repro (legal source, compiles
under GnuCOBOL):

    01 G.
       05 N PIC 9(1) VALUE 2.
       05 GD PIC X DYNAMIC LENGTH.
       05 T PIC X(3) OCCURS 1 TO 5 DEPENDING ON N.
    ...
       DISPLAY "G=[" G "]"

→ `error: backend compilation failed ... CS1061: '_T_0' does not contain a definition for 'AsImage'`.

MECHANISM: a group operand with an ODO beneath takes the OdoGroupPlace sender (the §13.18.38 GR8
current-count slice), which composes over the group's `AsImage()` — but the struct-method emission gate
(`ElementImageCapable`, and `IsImageCapable` before it) refuses a group with a dynamic member, so the
call site references a method the struct never gets. The failure is at BACKEND compile on the
DECLARATION+use, not a runtime Tier-C loud — the loud-failure rule violated in the worst direction
(uncompilable output on legal input).

WHAT WOULD CLOSE IT: the OdoGroupPlace sender must consult the same image-capability predicate every
other sender consults and stage the Tier-C loud (TierCIsland.Reason — the derived offender text now
names the dynamic mechanism) when the group has no AsImage — or, the complete fix, compose the GR8a
slice over the PB164 current-extent machinery where `GroupImageCodec.CurrentExtentImageCapable` holds
(an ODO group WITHOUT other dynamics is image-capable and already works; the broken shape is exactly
ODO ∧ dynamic-member). Sweep: every OdoGroupPlace consumer (DISPLAY/MOVE/WRITE senders), and any other
sender path that calls `AsImage()` without consulting the emission predicate — the PB164 family's
two-arm-dispatch shape, one more time.
