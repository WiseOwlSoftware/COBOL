## The three causes

1. **Scripts that do several jobs.** Each pipeline fix added its rule to the script that already existed; `plan_wave.py` plans, partitions, keeps the dispatch ledger, reads reports, numbers waves and releases dispatches. The standard is one mechanism per module.
2. **One self-test function per script, 32-49 % of the file.** Every fix appends a case at one place: wave 20261107's E and F met only there (PB3723).
3. **Single shared documents.** Rule 6 makes each change update its design doc and often `CONFORMANCE.md`.

## The bar

- **Tests out of the scripts, one test per case,** in their own files, so a new case is a new function or file, never an edit of someone else's lines; every gate and CI leg still runs them (the gate plan's selftests leg, the drift tests that declare self-test arms, `MergeDriverDriftTests`'s arm list), with a drift test that no script regrows an in-file case list. This replaces PB3723's test-arm half.
- **The large scripts split by job,** hottest first, each split behavior-neutral (the self-tests, the gate, the loop's own runs as the oracle), every caller moved and the old entry point deleted in the same change (CLAUDE.md rule 4: no wrappers, shims, forwarders or aliases).
- **`CONFORMANCE.md` one file per determination** with a generated index, the shape DEVLOG and kb/Work already have; **`PublicAPI.Unshipped.txt`** merged by a keyed driver (a sorted set of symbols).
- **Design first, by a Mythos model:** the target module map, the order, and the doc that owns it (extend the canonical design doc, never fork a second: `docs/DOC_INDEX.md`). Implementation by Opus implementers through the workstream skill.
