# PB5206 - a zombie read as a live member of a killed tree

**Sites:** `scripts/process_job.py` (`ProcessJob.alive`, `_self_test`); `scripts/detached.py` (`pid_alive`, `proc_stat`, `self_test`).

**What was wrong.** PB5098's `ProcessJob.alive()` answered on POSIX with `os.killpg(pgid, 0)`: [pgid] if the call succeeded,
[] if not. `killpg` succeeds while the group has ANY member, a zombie included. A killed orphan is reparented to init or to the
nearest child subreaper and stays a zombie until that process reaps it. The scripts' one liveness probe,
`detached.pid_alive` (kb/Work PB4008), already counts a zombie as dead, so the module held two answers to "is it running":
the self-test's `until_dead(grand)` returned (the grandchild was a zombie) and the next check, `job.alive()`, still said
`[19238]`. On a host whose init reaps at once (WSL's systemd: 8 of 8 runs GREEN) the race is never seen; on GitHub's runner
it went RED and bounced #1475 out of the merge queue, where it sat unnoticed for two hours (no lane watches a pull request
it did not queue).

**Reproduced.** Under a child subreaper that does not reap (`prctl(PR_SET_CHILD_SUBREAPER)` then waiting only on its direct
child) the old code fails every run in WSL: `got [855], want []`.

**Fix (landed).** On Linux `alive()` reads the group's members from `/proc/<pid>/stat` (pgrp field) and keeps those
`pid_alive` calls running, so one probe answers everywhere and the result names the live pids. Where there is no `/proc`
(macOS) the group signal is all there is. The self-test, on Linux, makes itself a child subreaper so the killed orphan is
ALWAYS an unreaped zombie when `alive()` is asked, checks that it is (`state == "Z"`), then reaps it.

**Review R1-1 (fixed).** `detached.pid_alive` parsed `/proc/<pid>/stat` by splitting at the FIRST `) ` and decoding
strict ASCII, so a running process named `x) Z q` read as a zombie and a non-ASCII name raised `UnicodeDecodeError`. The one
parse is now `detached.proc_stat` (bytes, after the LAST `) `), used by `pid_alive`, `ProcessJob.alive` and the self-test;
`detached`'s self-test runs a child whose name holds `) Z ` and a non-ASCII byte (PR_SET_NAME) and asks that it read as running.

**Evidence.** New self-test: GREEN on Windows, GREEN in WSL plain and under the non-reaping subreaper. The same self-test with
`alive()` reverted to the killpg body: RED in WSL on every host (`got [832], want []`), the merge group's failure.
