# PB3506 — the bare completion-idiom transfer renderers: stale doc and an unpinned caller list

One mechanism: after PB3491 and PB1148, a transfer that is not a completion leaves through `ExplicitTransferOut` /
`ExplicitTransferJump`, and the bare `TransferOut` / `TransferJump` are the COMPLETION idiom (design doc D1a). Two places
still describe or pin the older shape. Both are low and non-blocking; neither changes generated code.

## R1-1 — stale doc comment

`src/Cobol.Net.Compiler/CodeGen/EmitterState.cs:187` (the `TransferOut(string,string)` summary) still calls it the
"single place a transfer of control out of a paragraph becomes C#" for GO TO and its alterable/DEPENDING forms, EXIT
PARAGRAPH, EXIT SECTION, NEXT SENTENCE and every RESUME AT landing. GO TO (all forms) and RESUME AT now leave through
`ExplicitTransferOut`; the adjacent docs and design doc D1a already say bare `TransferOut` is the completion idiom, so
the two contradict each other in the same file. Fix: rewrite the summary to the completion idiom only (EXIT PARAGRAPH,
NEXT SENTENCE in a last sentence) and point at `ExplicitTransferOut` for the rest.

## R1-2 — unpinned callers of the other bare renderer

`tests/Cobol.Net.Tests.Unit/DispatcherTransferIdiomDriftTests.cs:308` `OnlyACompletionCallsTheBareTransferJump` closes
the callers of bare `TransferJump()` only. The other bare completion renderer, `TransferOut(...)`, has callers at
`src/Cobol.Net.Compiler/CodeGen/StatementEmitter.cs:152` (EXIT PARAGRAPH) and `:280` (NEXT SENTENCE) that no test pins,
though design doc D1a and the PB3491 DEVLOG entry say the test closes the list of bare-jump callers and that the
flag-clear cannot be forgotten by one arm. A new non-completion arm calling bare `TransferOut` would reintroduce the
PB3491 shape (a transfer out of a PERFORM range silently ending the PERFORM) and pass every test.

Fix: extend the drift test (or add a sibling in the same file) so the set of files/members calling bare
`TransferOut(` is closed to the completion statements, with the same shape as the existing `TransferJump()` pin, and
make the failure message name which kind of transfer a new caller must declare.
