# PB5802 - at --std 85 ASSIGN TO NULL is refused, though NULL is not a reserved word in 1985

**What is wrong.** `ASSIGN TO NULL` is refused at `--std 85` (COBOL1639 "not defined"). NULL is not a reserved word in 1985, so there it is an implementor-defined file name, as `ASSIGN TO NULLS` already is. Ruling: UPHELD (a), wrong at 85 only (at 2023 NULL is reserved and COBOL2576 is right). Harm: rejects_legal_source, misleads_diagnosis (the message tells the user to declare an item). The checker's confidence: high.

**Mechanism (the checker's reading).** NULL is not a 1985 reserved word (the compiler's own message says so), so in ASSIGN TO it is implementor-name-1, a system-name whose allowable content is the implementor's (`§1985:VII.2.3.3 SR3`); the documented determination (`docs/conformance/7/DOC-A.1-71.md`, held at COBOL-85) takes the word as the file name, and `ASSIGN TO NULLS` compiles. `AssignTargetRule.Text` routes the `predefinedNull` token to `PredefinedNullRule.Report` at every edition; its 85 arm reports COBOL1639 "not defined ... declare the item".

**Sites:**
- `src/WiseOwl.Cobol.Compiler/Binding/AssignTargetRule.cs#Text` (the `predefinedNull` arm, with no edition test)
- `src/WiseOwl.Cobol.Compiler/Binding/PredefinedNullRule.cs#Report` (the 85 arm treats the word as a data reference)

**1985 rows this note blocks.** `1985-SR-VII.2.3.3-3`. `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094), so the row is named here.
