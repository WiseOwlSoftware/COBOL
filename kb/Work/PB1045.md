# PB1045 — LANDED

## Landing (wave 1032, group E)

**Re-probed on the w1032e Debug build of `d625d3b84`.** The SR1 arm did not reproduce: `77 X77 PIC X GLOBAL.` and
`05 X05 PIC X GLOBAL.` draw COBOLNET2404 (PB518's clause-placement row), and `SR-13.18.27.3-1` was already OK on that
evidence, so this landing does not claim it. The SR4 arm reproduced, and wider than the note said: a GLOBAL constant
entry compiled clean in a class OBJECT, in a FACTORY, in a method's LOCAL-STORAGE and in an interface method
prototype's LINKAGE; a `TYPEDEF … GLOBAL` in object or factory working storage compiled clean (a type declaration is
never one of `CallGlobalRoots`); and the refusals that did fire carried no source position.

**Root cause.** SR4 had two private reporters, each asking a different subset of SR1's entry kinds: the class arm
`OoDriver.OoGateClassGlobal` asked the BOUND model (files, reports, level-1 data roots) and the method arm in
`DataBinder.OoBindMethodData` asked the written data description entries of LOCAL-STORAGE and LINKAGE. Neither asked a
constant entry. **Fix:** both are deleted. `OoDefinitionRules.Screen`, already called once for every factory, instance
and method data division (a prototype included, §10.6.1 NOTE), now walks the written data division for every GLOBAL
clause over `OoDefinitionRules.GlobalClauseSites`, the grammar rules that carry it (SR1 a) constant entry body, b)
`globalClause`, d) the FD's `fileGlobalExternalClause` GLOBAL arm, e) `reportGlobalClause`; c) has no grammar site, as
the screen module is declined), and reports COBOLNET1520 (now `DiagnosticCatalog.GlobalInOoDefinition`) at the clause,
naming the entry. `OoDefinitionRulesDriftTests.TheGlobalClauseSites_AreTheGrammarsGlobalRules` holds the list equal to
the parser rules whose ATN matches GLOBAL (less `useStatement`'s GLOBAL phrase), and `NoSiteSpellsTheGlobalRefusalOfItsOwn`
keeps it the only reporter. Found on the way and deleted: `DataBinder.OoGateUnsupportedShapes`, a recursive walk whose
every gate had been lifted (M2-OO-1h) and which did nothing.

**For the next implementer.**
- `src/Cobol.Net.Compiler/Binding/OoDefinitionRules.cs#ScreenGlobalClauses`: the one SR4 reporter; extend
  `GlobalClauseSites` (the drift test forces it) when the grammar grows a GLOBAL clause. Trap: the rule is about the
  WRITTEN clause, so ask the parse tree; the bound model misses type declarations and constants.
- `src/Cobol.Net.Compiler/Oo/OoDriver.cs#BindClassData`: no GLOBAL logic left; the factory/instance screen is the
  `OoDefinitionRules.Screen` call at the top.
- `src/Cobol.Net.Compiler/Binding/DataBinder.Oo.cs#OoBindMethodData`: no GLOBAL logic left; the method screen is its
  `OoDefinitionRules.Screen(OoDefinition.Method, …)` call.

Goldens: `negative/pb1045-global-constant-in-object` (reject-at 2002 2014 2023, COBOLNET1520) and
