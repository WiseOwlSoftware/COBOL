# PB3516 — stale expected-value comments in re-blessed goldens

PB3505 re-blessed about 200 conformance-suite `.out` files to the decimal DISPLAY form but left the hand-derived expected
values in their `.cob` header comments in the old digit-image form. The R1 review measured it by matching each removed
`.out` value against the `.cob` comments: 58 comment lines in 36 goldens now contradict the golden they document. Example:
`conformance-suite/cases/14.9.11-DISPLAY/pb148_display_forms.cob:12`. No generated code and no test result changes; the
comments mislead the next reader who derives an expected value from them (CLAUDE.md rule 1: the derivation, not the
output, is the authority).

Fix: re-derive each comment from the picture under the decimal form (where the golden is the digit-image twin under
`options.json` `digits`, say so), then add a mechanical sweep that fails when a `.cob` comment names a digit-image value
its `.out` does not contain, if one can be written as a test rather than a hand-kept list.

**Sites:** conformance-suite/cases/14.9.11-DISPLAY/pb148_display_forms.cob and the other 35 `.cob` files whose `.out` the PB3505 commits re-blessed (git diff --name-only fd407980f^1 fd407980f -- 'conformance-suite/cases/*.out' names them).
