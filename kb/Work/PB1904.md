# PB1904 — LANDED (wave 1007 A)

Filed 2026-10-01 by the train-1001 lander from the wave-1001 group B implementer report
(`w1001b-PB1572-report.md`, new defect 2). The implementer did NOT probe it; the first step is a repro.

**Shape.** Wave 1001 B (kb/Work PB1653) split a Tier-B REDEFINES view into a VALUE channel (`Read`/`Write`, the
window's coding) and a STORAGE channel (`ByteWindowRead`/`ByteWindowWrite`), and routed `GroupImage` /
`WriteGroupImage` to the storage channel for a NATIONAL group view. A BIT group view (`BitWindow`) still takes the
`RedefViewPlace => Read(group)` arm, which is the boolean-position string, not its packed storage bytes
(§13.18.44.4 GR1: the redefinition is the same storage area).

**Code site.** `src/Cobol.Net.Compiler/CodeGen/Roslyn/PlaceRenderer.cs#GroupImage` and `#WriteGroupImage` (the
`RedefViewPlace { Coding: NationalWindow, ViewItem.IsGroup: true }` arms are the shape to extend).

**Probe to write.** A record redefined by `05 BG GROUP-USAGE BIT` with `PIC 1(8) USAGE BIT` members, then
`MOVE BG TO X` (alphanumeric group sender = storage image) and a CALL BY REFERENCE of `BG`; compare against the
packed bytes §8.5.1.6.3 places.

## Landing — wave 1007 implementer A, 2026-10-03

**Re-probed first.** The note's two named probes do NOT show the defect, and correctly so: `MOVE BG TO X` is a
VALUE transfer (§13.18.29.4 GR1 b) — a bit group is "treated as though it were an elementary data item of usage bit
… described with PICTURE 1(m)", so X receives the 32 boolean positions), and a CALL BY REFERENCE of a bit group
crosses as that elementary value by design (kb/Work PB1166, §14.8.2.1 NOTE). The STORAGE channel is what is wrong,
measured on this worktree's own base build (HEAD PlaceRenderer, rebuilt for the comparison):
`FUNCTION CONVERT (GV ANY ANUM HEX)` over `01 GV REDEFINES X GROUP-USAGE BIT` holding B"10110" returned
`3130313130` (the five boolean CHARACTERS) where the plain group returns `B0`; and `WRITE FB FROM BG`, FB the bit-group
second record of an FD, wrote `0100` (the first four boolean characters) where the standard places the bytes `AB12`.

**Fix.** `PlaceRenderer.cs#GroupImage` / `#WriteGroupImage` gained the BIT twin of PB1653's national arm:
`RedefViewPlace { Coding: BitWindow, ViewItem.IsGroup: true }` reads `CobolBits.Pack(Read(v), m)` and stores
`Write(v, CobolBits.Unpack(image, m))` — the §13.18.60.4 GR5 packing a record-struct bit group's `AsImage` /
`FromImage` already use. Sibling sweep: the ELEMENTARY bit view's storage read (`OperandText.ElementaryCharacterImage`,
`BitsPack`) and write (`ReceivingStore.StorageArea`, `BitsUnpack`) were already right; the national group arms were
right (PB1653); the CALL crossing is the value channel by rule.

**For the next implementer.** `PlaceRenderer.cs#GroupImage` / `#WriteGroupImage` own a view's STORAGE channel, one arm
per window coding; `Read`/`Write` own its VALUE channel. `GroupViewAliasDriftTests.ViewOfGroup_StorageImage_IsThePlainGroups`
pins the storage channel view-vs-plain for bit and national groups (CONVERT, so at 2023). Trap: the E:\COBOL main
build can be stale — a BEFORE probe there showed a national view wrong that this tree already fixed; probe BEFORE on
your own base.

Golden: `conformance:2002/pb1904_bit_group_view_storage_image` (FR=[AB12]).
