# PB2506

Filed by the w1033 clerk from the PB1643 refuter (`E:\COBOL-coord\scratch\w1033-adj\PB1643-refute.md` section 3.3), which names it a new wrong-answer defect with a different mechanism from PB1643.

**Observed (pinned build `pin-97006f3`, DECIMAL-POINT IS COMMA).**

| Source | WiseOwl | GnuCOBOL 3.2.0 |
|---|---|---|
| `FUNCTION MIN(-1,5 2)` | `-1.0`, computed as MIN(-1, 0,5, 2) | `-1,5` |
| `FUNCTION ABS(-1,5)` and `ABS(+1,5)` | false COBOLNET1504 "takes 1 argument(s); 2 given" | `+1,5` |

Sources `PB1643-refute\negs.cob`, `negarg.cob`, output `wiseowl-negs.txt`; emitted `wo_negs_2023\negs.g.cs:43-45` (`new Int128[] { -1L, 5L, 2L }`, scales `{0,1,0}`).
Controls (correct): `ABS(-1.5)` without DPC, `COMPUTE X = -1,5`, `IF X = -1,5`, `ABS(- 1,5)`.

**Expected from the spec.** `§8.3.5 2)` (cite.py --check OK): the COBOL characters comma and semicolon, immediately followed by a space, are separators; a comma not followed by a space is not,
so under `§12.3.7.4 GR14 a)` (comma is the decimal separator in numeric literals) `-1,5` is one signed numeric literal and one argument.

**Mechanism and site (refuter).** `src/Cobol.Net.Frontend/Grammar/CobolLexer.g4` lines 1134-1137 have signed argument-region twins for the dot-decimal, integer, float and comma-float shapes but none for
the comma fixed-point shape, so `-1,5` lexes as SIGNED_INTEGERLIT(-1) followed by the contiguous COMMA INTEGERLIT; `numericLiteralCore` (`CobolExpressions.g4:837`) assembles only the unsigned
`INTEGERLIT COMMA INTEGERLIT`, so `,5` becomes a second argument. Same family as kb/Work R17 (the missing float twin, which also produced two arguments). Fix: add the missing twin and a drift test
that every numeric-literal lexer shape has a signed argument-region twin. Related: `PB1643`.
