# PB2506

Filed by the w1033 clerk from the PB1643 refuter (`E:\COBOL-coord\scratch\w1033-adj\PB1643-refute.md` section 3.3), which names it a new wrong-answer defect with a different mechanism from PB1643.

**Observed (pinned build `pin-97006f3`, DECIMAL-POINT IS COMMA).**

| Source | WiseOwl | GnuCOBOL 3.2.0 |
|---|---|---|
| `FUNCTION MIN(-1,5 2)` | `-1.0`, computed as MIN(-1, 0,5, 2) | `-1,5` |
| `FUNCTION ABS(-1,5)` and `ABS(+1,5)` | false COBOLNET1504 "takes 1 argument(s); 2 given" | `+1,5` |

Sources `PB1643-refute\negs.cob`, `negarg.cob`, output `wiseowl-negs.txt`; emitted `wo_negs_2023\negs.g.cs:43-45` (`new Int128[] { -1L, 5L, 2L }`, scales `{0,1,0}`).
Controls (correct): `ABS(-1.5)` without DPC, `COMPUTE X = -1,5`, `IF X = -1,5`, `ABS(- 1,5)`.

**Expected from the spec.** `§8.3.5 2)` (cite.py --check OK): the COBOL characters comma and semicolon, immediately followed by a space, are separators; a comma not followed by a space is not,
so under `§12.3.7.4 GR14 a)` (comma is the decimal separator in numeric literals) `-1,5` is one signed numeric literal and one argument.

**Mechanism and site (refuter).** `src/Cobol.Net.Frontend/Grammar/CobolLexer.g4` lines 1134-1137 have signed argument-region twins for the dot-decimal, integer, float and comma-float shapes but none for
the comma fixed-point shape, so `-1,5` lexes as SIGNED_INTEGERLIT(-1) followed by the contiguous COMMA INTEGERLIT; `numericLiteralCore` (`CobolExpressions.g4:837`) assembles only the unsigned
`INTEGERLIT COMMA INTEGERLIT`, so `,5` becomes a second argument. Same family as kb/Work R17 (the missing float twin, which also produced two arguments). Fix: add the missing twin and a drift test
that every numeric-literal lexer shape has a signed argument-region twin. Related: `PB1643`.

## Landed - 2026-10-08 (wave 1039 group E)

Re-probed on the wave-1039 build (main `44a1b5eac`): `negs.cob` printed `B[-1.0]`, `H[-1.0]`, and `negarg.cob` drew the
false COBOLNET1504 - confirmed.

- **Mechanism.** The comma fixed-point shape had no lexer body, because its UNSIGNED form is assembled by
  `numericLiteralCore` from contiguous `INTEGERLIT COMMA INTEGERLIT` / `COMMA INTEGERLIT`. Inside a list region the
  sign and the integer part were already one `SIGNED_INTEGERLIT`, which no parser alternative could extend, so `,5`
  became the next argument. `CobolLexer.g4` gains `fragment DEC_COMMA_BODY` and the twin `FN_SIGNED_COMMA_DECIMALLIT`
  (retyped to `SIGNED_DECIMALLIT` by the same `OnSignedLiteral` action, so outside a list region the sign is still cut
  off as the operator). The token text goes through the binder's one normalizer, so DPC programs read `-1,5` as -1.5
  and a program without DECIMAL-POINT IS COMMA gets COBOLNET0895 for `-1,5`, the answer the unsigned `1,5` gets.
  `-,5` and `+1,5` are covered by the same body.
- **Why the drift test missed it, and the fix.** `SignedLiteralShapeDriftTests` demanded a twin per `*_BODY`
  fragment, and the parser-assembled shape had none. New `EveryParserAssembledNumericShape_HasALexerBody` translates
  each contiguous alternative of `numericLiteralCore` into lexer spelling and requires it to be an alternative of a
  numeric body (seen failing once with the leading-comma alternative removed). `CobolLexerModeDriftTests` pins the
  token streams (`SignedCommaDecimal_IsOneTokenInAListRegionOnly`).
- **Spec.** `§8.3.5 2)`, `§8.3.3.3.2 2)`, `§12.3.7.4 GR14 a)` (cite.py --check OK).
- **Goldens.** `85/pb2506_signed_comma_decimal_argument` (MIN, MAX, a leading-comma `-,5`, a comma-space separator
  before the literal, ORD-MAX's ordinal; results moved to an edited item so PB2507's DISPLAY image is not pinned);
  negative `pb2506-signed-comma-decimal-argument-without-comma-mode` (COBOLNET0895 at all four editions). The rule does
  not differ by edition.
- **Sibling sweep.** `tokensAreContiguous` is used only in `numericLiteralCore` (two alternatives, both now with a
  body). `SeparatorRule`'s numeric-comma exemption no longer sees a COMMA token for the signed form (doc comment
  updated). Not this defect: `FUNCTION` results still DISPLAY with `.` under DPC (`PB2507`).
