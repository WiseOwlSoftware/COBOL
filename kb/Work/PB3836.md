# PB3836 — no harm class for a misleading diagnostic

**Sites:** `scripts/spec/work.py#HARM_LABELS`, `scripts/spec/work.py#HARM_FLAGS`, `scripts/spec/work.py#FINDING_HARMS`, `scripts/spec/work.py#harm_rank`, `scripts/spec/work.py#actionable`, `scripts/spec/work.py#process_only_problems`, `scripts/spec/work.py#register_problems`, `scripts/spec/work.py#harm_vocabulary_findings`, `scripts/spec/work.py#process_only_findings`, `scripts/spec/work.py#self_test`, `scripts/arch/r2_collect.py` (`HARMS`), `scripts/arch/file_census_notes.py` (`R2_HARM`, `R2_FRONTMATTER`), `scripts/fuzz_triage.py` (`render_note`), `scripts/spec/gen_ledger.py` (`HARM_WORDS`), `scripts/orchestrator/clusters.py` (`harm_weights`), `.agent-fleet.json`, `.claude/skills/workstream/templates/registrar-brief.md`, `.claude/skills/workstream/templates/golden-lane-brief.md`, `.claude/skills/workstream/templates/cloud-adjudicate-brief.md`, `.claude/skills/workstream/templates/wf_lane3_adjudicate.js`, `.claude/skills/workstream/templates/wf_lane3_refute.js`, `.claude/skills/workstream/templates/wf_r2_review.js`, `.claude/skills/session-start/SKILL.md`

## The defect

`work.py check` refuses an open defect with no harm flag (`HARM_FLAGS = wrong_answer, crashes, rejects_legal_source,
under_rejects`) and offers `process_only: true` as the only other way through, defined as an item that "does nothing
to a user's program". A compiler message that names the wrong fault (PB3831: `CLASS IS BOOLEAN` reported as a
reserved word misused; PB3832: COBOL2072 claiming a missing imperative-statement) refuses correctly but sends the
user to the wrong place to fix their program. That is harm to the user's program, and the vocabulary has no word for
it, so the filer satisfies the check with a false flag: making the check pass instead of fixing its cause.

Measured 2026-10-26: 23 open or owner-held notes carry `process_only: true` while their Sites name `src/WiseOwl.Cobol.*`
(PB2469 PB3453 PB3515 PB3593 PB3594 PB3599 PB3615 PB3616 PB3633 PB3634 PB3679 PB3680 PB3698 PB3726 PB3756 PB3766
PB3767 PB3768 PB3796 PB380 PB3816 PB438 PB464), plus PB906, PB911, PB3831, PB3832. Some are true process items with
a compiler site (a test or a drift arm); each needs re-reading, not a bulk edit.

## Fix

Add the missing harm class (for example `misleads_diagnosis`: the program is refused or warned about correctly, and the
message names the wrong cause, position or rule) to `HARM_FLAGS`, to the frontmatter schema, to `kb/Work.base`'s
filters and to the ranking of `work.py next` (below the four existing classes, above none), with the drift arm that
already holds `Fix next` equal to `HARM_FLAGS`. Then re-read every note listed above and set its true flag:
`process_only` stays only where the item really does nothing to a user's program. Make `check` refuse
`process_only: true` on an item whose Sites are all under `src/` unless the note says why (a sited drift test).

## Acceptance

- PB3831, PB3832, PB906 and PB911 carry the new flag and appear in `work.py next`.
- No open note under `src/` is `process_only` without a stated reason; `work.py check` enforces it.

## Witness (2026-10-30)

The closed set of harm flags lacks a second class. A performance defect (work done twice, a slow path, no wrong answer and no crash) has no harm flag either, so it is filed `process_only: true` or a reason is invented, exactly as the misleading diagnostic is. The review of PB3797 (report `w20261752a-PB3797-report.md`, "New defects") lists it as "no performance harm class". When this note adds `misleads_diagnosis` to `HARM_FLAGS`, decide a `performance` class in the same change (the CLAUDE.md product bar names performance as one of four review dimensions), and re-read the `process_only: true` notes whose Sites are under `src/` for it. The branch `worktree-wf_484eb705-564-32` (PR #791, reviewed head `e1b97d1ed`) already carries the `process_only_reason` escape for notes such as PB4073 and PB4074; a performance class would make that escape rarer.
## Landed (wave 20261752 group A)

`misleads_diagnosis` is the fifth class of `HARM_LABELS` (flag to listing word, in rank order; `HARM_FLAGS` is its keys),
ranked last: `next` sorts by severity, then by the rank of the note's highest harm, then by id (it sorted by severity and
id alone, so the four classes did not rank among themselves). `kb/Work.base`, the filters this note named, was deleted by
PB3799 in the same change set, so the Bases copy of the predicate needed no edit; the views are `work.py` subcommands over
the one table.

already right), or a restructuring `**Wave kind:**` (the architecture review's behavior-neutral waves). The 289 notes it
