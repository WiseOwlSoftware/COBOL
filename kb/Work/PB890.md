# PB890 — LANDED — a syntax rule disarmed by the golden that violates it

## The rule

```
$ python scripts/spec/cite.py --check 13.18.63.3 "Alphabet-name-1 may be specified only when the literals specified in the THROUGH phrase are of class alphanumeric or national"
  OK  §13.18.63.3 31)  (Syntax rules)
      31) Alphabet-name-1 may be specified only when the literals specified in the THROUGH phrase are of
      class alphanumeric or national. If literal-2 and literal-3 or literal-5 and literal-6 are of class
      national, alphabet-na...
```

With no THROUGH phrase there are no "literals specified in the THROUGH phrase", so the permission the
"only when" grants is never satisfied. SR31 is a SYNTAX rule: it constrains what may be **written**, whether
or not the phrase would have an effect at run time. The `inert, not erroneous` comment at the guard is a
GENERAL-RULE argument answering a SYNTAX-RULE question.

## The code site and the repair

`src/Cobol.Net.Compiler/Binding/DataBinder.cs#BindCondition` — the guard
`&& cond.Values.Any(v => v.High is not null)` on the `TryResolveRangeAlphabet` call.

The repair is **not** to delete the guard alone. `tests/conformance/2002/pb695_value_false_optional_words.cob`
line 32 is the reason the guard exists, and that golden's real subject is the bracket ORDER (PB695), not the
operand. Rewrite line 32's operand as a conforming alphanumeric THROUGH range, keep its bracket order intact,
THEN drop the guard, then add a negative for each excluded shape (no-THROUGH, numeric-THROUGH). This is
memory `green_test_can_hold_a_gap_open` exactly — a green test pinning a hole reads as a decision.
