# PB5984 - a phantom record after AFTER ADVANCING on a line-sequential file?

The reviewer of PB5914 read `SequentialConnector.cs` near line 1739 and reports that at `--std 85` the AFTER ADVANCING
positioning on a RECORD DELIMITER IS LINE-SEQUENTIAL file writes a bare line end before the record, which a later READ of the
file returns as a record of length 0 with status 04. A program that writes N records with AFTER ADVANCING and reads the file
back would then read more records than it wrote: a wrong answer.

First step: reproduce. Write three records AFTER ADVANCING 1 LINE (and 2 LINES) at `--std 85`, CLOSE, OPEN INPUT, READ to end,
DISPLAY each status and length. If extra records appear, set `kind: defect`, `wrong_answer: true`, `process_only: false`, and
fix it at its root in the connector, beside PB5914's golden; if not, retire this note with the run's output.

**Sites:** `src/WiseOwl.Cobol.Runtime/IO/SequentialConnector.cs:1739` (whole: the reviewer named a line, not a member; the reproduction names it)
