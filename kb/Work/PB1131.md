`conformance:85/pb1131_control_break_collating_85` (`ALPHABET … "A" ALSO "B"`: A→B is no break, B→C is one).

## Measured (adjudicator / refuter evidence, verbatim)
### GR-14.9.16.4-3 (PARTIAL)
|| REFUTED: PARTIAL — GR3 is the save-and-COMPARE step, and the compare is wrong. §12.3.6.4 GR11 c) says the program collating sequence determines the truth value of alphanumeric comparisons 'Implicitly specified by the presence of a CONTROL clause in a report description entry'. §13.18.16.4 GR3 makes the test one 'for equality with the corresponding prior control'. CobolReport.DetectBreakLevel instead compares the character images with string.Equals(..., StringComparison.Ordinal). So under a PROGRAM COLLATING SEQUENCE with ALSO, or a locale-based one, two values the program itself treats as equal still sense a control break. The save half and the major-to-minor stop-at-first-change half are correct.
- **Code location (record):** src/Cobol.Net.Runtime/IO/ReportWriter.cs#CobolReport.GenerateCore; src/Cobol.Net.Runtime/IO/ReportWriter.cs#CobolReport.DetectBreakLevel; src/Cobol.Net.Runtime/IO/ReportWriter.cs#CobolReport.AddControl
