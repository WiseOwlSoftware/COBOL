# PB4424 — DataItem.ActivationLocal is set on every method root, not only those with a local

**Found:** by the round-1 review of the PB4416 branch (R1-1 LEAD, low, not blocking). PB4416 is landed; this is a model-invariant gap in what it added.

**Sites:**
- `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.Oo.cs#OoBindMethodData` (about line 470): sets `DataItem.ActivationLocal` on every method LOCAL-STORAGE and LINKAGE root.
- `src/WiseOwl.Cobol.Compiler/Binding/Model/DataItem.cs#ActivationLocal` (its doc) and `docs/rearchitecture/DESIGN-backend-abstraction.md` 1.2: "the local that holds the root's own storage".
- `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/OoEmitter.cs#EmitMethod` (the carrier-resident / IsArea / Tier-B / Tier-A arms): the only place that decides which roots actually get a declared root local.

**Finding.** The set includes roots whose storage is not a local holding the root: an AREA formal laid over its argument cell through the member `AreaPointerClrName`, a carrier-resident formal, a Tier-B canonical or redefiner whose storage is the class backing local, a Tier-A view. For those, `ActivationLocal` names a local that is not the root's storage, so a backend reading it as the root's storage would pick the wrong slot. Today only `EmitMethod`'s own arms keep that from mattering.

**Fix direction.** Decide the storage kind of a method root once, in the binder (a typed value: declared local, carrier, area over a cell, backing local, view), set `ActivationLocal` only for the declared-local kind, and have `EmitMethod` switch on that value instead of re-deriving the arms. Add a drift test that every non-null `ActivationLocal` is declared by the emitter. Correct 1.2 in the same change.
