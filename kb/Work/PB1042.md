# PB1042 — OPEN

## Measured
```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. B16ED.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 XR EXTERNAL.
          05 T PIC X(2) OCCURS DYNAMIC CAPACITY IN XC.
          05 XC PIC 9(4) COMP.
       PROCEDURE DIVISION.
           DISPLAY "RAN"
           STOP RUN.
```

→ `error COBOLNET0899: EXTERNAL record 'XR' cannot be cell-backed — EXTERNAL record 'XR' has a dynamic-capacity table
('T', ISO §8.5.1.9) with no fixed extent — the shared byte cell cannot carry it — recognized but not yet implemented`.
(The probe's COBOLNET1523 is the probe's own fault — `XC` is also declared — and is not part of this defect.)

## The rule
`cite.py --check 8.5.1.9.1 "it may be defined in any place, other than the file section, in which a fixed-capacity table may be defined"` → `OK §8.5.1.9.1 3)`.

## Code site
`DataBinder.VariableLengthCellResidueOf` (the refusal); the root is the struct composer's A.1 item 57 exclusion, not
PB1026's (PB1026 carried out-of-line RECORDS of an EXTERNAL FD in the cell's dyn slots).

## What the fixer owes
Give the run-unit EXTERNAL cell a slot per dynamic table (or per occurrence of a dynamic-length item in a table
element), the PB1026 dyn-slot mechanism generalized from records to members. Same for the BASED/ADDRESS-OF record
arm. Golden: two programs sharing the EXTERNAL record, one growing the table, the other reading it.
