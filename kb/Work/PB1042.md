# PB1042 — LANDED

## Measured
```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. B16ED.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 XR EXTERNAL.
          05 T PIC X(2) OCCURS DYNAMIC CAPACITY IN XC.
          05 XC PIC 9(4) COMP.
       PROCEDURE DIVISION.
           DISPLAY "RAN"
           STOP RUN.
```

→ `error COBOLNET0899: EXTERNAL record 'XR' cannot be cell-backed — EXTERNAL record 'XR' has a dynamic-capacity table
('T', ISO §8.5.1.9) with no fixed extent — the shared byte cell cannot carry it — recognized but not yet implemented`.
(The probe's COBOLNET1523 is the probe's own fault — `XC` is also declared — and is not part of this defect.)

## The rule
`cite.py --check 8.5.1.9.1 "it may be defined in any place, other than the file section, in which a fixed-capacity table may be defined"` → `OK §8.5.1.9.1 3)`.

## Code site
`DataBinder.VariableLengthCellResidueOf` (the refusal); the root is the struct composer's A.1 item 57 exclusion, not
PB1026's (PB1026 carried out-of-line RECORDS of an EXTERNAL FD in the cell's dyn slots).

## What the fixer owes
Give the run-unit EXTERNAL cell a slot per dynamic table (or per occurrence of a dynamic-length item in a table
element), the PB1026 dyn-slot mechanism generalized from records to members. Same for the BASED/ADDRESS-OF record
arm. Golden: two programs sharing the EXTERNAL record, one growing the table, the other reading it.

**Design the note's "What the fixer owes" implies, with the traps found:** the cell needs a second managed-slot family
(keys disjoint from both pointer offsets ≥ 0 and `DynKey` = −1−ordinal, e.g. a separate dictionary) holding one
`CobolDynTable` per dynamic table, numbered like `ClassDynOrdinal` (`ClassDynTableOrdinal`); the fixed run of the class
must exclude the table (zero bytes, as a dynamic-length item), so the group-image composers (`VarGroupWindow`,
`ContiguousAt`, MOVE of the group) must carry the table's CURRENT extent as a component, which is §8.5.1.12's atom model
(`VariableLengthCompatibility.Atoms` already treats a dynamic table as a `T` atom — reuse, do not re-derive). Growth
must be visible through every description that shares the cell (that is the golden the note asks for: two programs
sharing the EXTERNAL record, one growing the table, the other reading it). The dynamic-length-item-inside-a-table-element
arm needs a slot per OCCURRENCE (so the key is (ordinal, subscripts), not an ordinal) — or the same `CobolDynTable`-style
element storage — and is the larger half; decide whether to take it with the table slot (one mechanism: "a managed
component of the cell addressed by path") rather than twice. Then the ADDRESS-OF half (row GR-8.4.3.11.4-1, COBOLNET0869
"could not be placed on addressable cell storage") is the same forcer and closes with it.

**Not done, deliberately:** no change was made here because a half-built slot family in `StorageCell` that the
composers do not read is exactly the "a table nothing reads has never been checked" state the project's drift tests
exist to refuse. Rows `SR-8.5.1.9.1-3` and `GR-8.4.3.11.4-1` stay in `inventory_rows`.

## Wave 1015 Y — re-probed, NOT started (SPLIT at this note, I9 redesign beyond the slice)

**Re-probe (own build, wave 1015 Y, after PB1674/PB1263/PB1261/PB1265 landed in the same group).** Both arms
still reproduce: `01 XR EXTERNAL. 05 T PIC X(2) OCCURS DYNAMIC CAPACITY IN XC.` draws COBOLNET0899 ("has a
dynamic-capacity table ('T', ISO §8.5.1.9) with no fixed extent"); `01 DT. 05 DX OCCURS DYNAMIC. 10 DY PIC X(2).`
with `SET P TO ADDRESS OF DT` draws COBOLNET0869.

**Why it was split rather than started.** The fix is not a refusal to lift. It is a new storage family that crosses
three layers, so it is a redesign beyond a fix-lane slice:
1. **Runtime.** `StorageCell` needs a managed slot holding one `CobolDynTable<T>` per dynamic table, keyed apart
   from both pointer slots and `DynKey`. For the dynamic-length-item-in-a-table-element arm it also needs a slot per
   OCCURRENCE, keyed by (ordinal, subscripts).
2. **Emitter.** A `DynTablePlace` in a cell-backed class has no stored field. It has to render the cell's slot, and
   the table's element struct still has to be emitted for a class whose members are windows.
3. **Composers.** `VarGroupWindow`, `ContiguousAt`, group MOVE and INITIALIZE have to carry the table's current
   extent as a §8.5.1.12 `T` atom (reuse `VariableLengthCompatibility.Atoms`). Growth then has to be visible to every
   program sharing the EXTERNAL cell.

The wave 1011 B design above stands. Start it as its own slice, sized by the design-first rule (CLAUDE.md rule 5),
and update `docs/COBOLNET_DATA_MODEL_DESIGN.md` (the CONFORMANCE.md A.1 item 57 exclusion) in the same change.

**Mechanism — the wave 1011 B design, built as ONE model (`Place.CellComponents`).** A cell-backed area's
COMPONENTS are its dynamic-length items and its dynamic-capacity tables, numbered in storage order with one ordinal
per OCCURRENCE of every enclosing fixed table (`CellComponents.PerOccurrence` is the subscript stride;
`DataBinder.AssignCellComponents` replaced `VariableLengthCellResidueOf` and is the one writer of `ClassDynOrdinal`).
A table's slot is a `CobolDynTable<StorageCell>` (`StorageCell.DynTableAt` / `SeedDynTable`, a key family apart from
the dynamic-length and pointer slots) whose occurrences are ELEMENT CELLS, each a scope of its own (members re-laid
out from offset 0, ordinals from 0) — so a table, or a dynamic-length item, inside a table element is the same
mechanism one level down, and every capacity rule stays `CobolDynTable`'s. The table reserves its one-element
`ByteWidth` in the fixed run (the D-SLOT pointer reason) and the cell composers cut the reservations out
(`VarGroupWindow.DynTable`). References walk ONE scope walk (`ReferenceResolver.WindowScopeOf`; `CellTableSegment`);
the whole-table path is `BuildTablePath` — its string twin `ReferenceResolver.TablePath` was deleted (SEARCH could not
see a cell table through it). Cursors (INITIALIZE, MOVE element moves, CORRESPONDING) re-anchor on the window's scope
(`RedefViewPlace.Cell` / `DynOrdinal`, `PlaceCursor.DynamicElement`); `FUNCTION LENGTH` walks per occurrence in a cell
too. `GroupImageCodec.CellDynSeeds` seeds every table (FROM, TO, INITIALIZED, Format 2 VALUE through the now-shared
`ValueInitializer.OccurrenceSwitch`). The composer's exclusion is the declared group's (`CurrentExtentImageCapable`).
Design doc: DATA_MODEL D-SLOT "cell components"; CONFORMANCE.md DOC-A.1-57.
