# PB1939 — OPEN

Filed by the train-1006 lander from wave 1006 group D's report (`w1006d-PB1144-report.md`, "New defects", item 3).

## Defect

§14.6.9.2 rule 2 leaves the receiving elements past the sender's capacity space filled, and §14.6.9.4 space-fills a
dynamic table's elements. For an elementary NUMERIC element the typed-native carrier holds a number, so
`CobolDynTable.SpaceFillElements` stores zero and the element later displays `0000` where its storage holds spaces.
This is the familiar typed-native question (a numeric item whose storage is not a valid number): the answer must come
from the design's invalid-content model, never from a byte substrate (CLAUDE.md, typed-native only).

**Repro.** `scratchpad/w1006d/p2b.cob` (wave 1006 group D scratchpad): line A prints `RT(3)` as `[0000]`; the
expected output is `[    ]`.

**Site.** `src/Cobol.Net.Runtime/Values/Tables/CobolDynTable.cs#SpaceFillElements`.
