# PB3458 — the refusal theory runs on one host, the text says two

Low, non-blocking lead from the branch review of PB3414 (report `E:\COBOL-coord\scratch\reports\w1132e-PB3414-report.md`,
`## Review findings` R1-1; findings file `E:\COBOL-coord\scratch\review-w1132-e.jsonl`). Finding, verbatim:

> tests/Cobol.Net.Tests.Unit/ReadOnlyKeyedWriterStoreMutexTests.cs:265 The refusal theory
> A_refusal_at_every_page_write_of_a_WRITE_is_30_and_gives_the_store_mutex_back (and its OperationsOfAWrite measurement)
> never calls RegionHostSeam.Use, so it runs on the machine region host only, while DEVLOG/pending-pb3414-...md line 7
> and kb/Work/PB3414.md line 64 say both cases run on the machine region host and the lock-file host.

**Two ways out, neither decided here.** Either the theory (and its `OperationsOfAWrite` measurement) runs on both hosts
through `RegionHostSeam.Use`, or the DEVLOG entry and `kb/Work/PB3414.md` say it runs on the machine region host only.
The implementer chooses; the choice follows whether the refusal path differs between the two hosts (the lock-file host's
mutex is a different object).

**Sites:**
- `tests/Cobol.Net.Tests.Unit/ReadOnlyKeyedWriterStoreMutexTests.cs:265`
- `kb/Work/PB3414.md:64`
- `DEVLOG/pending-pb3414-*.md:7` (stamped to a numbered entry when PR #324 lands)

## Landed (wave 1134 B)

Re-probed on this build: the theory never called `RegionHostSeam.Use`, so it ran on the machine region host only. The
lock-file host's store mutex is a different object from the machine host's, and "the refused statement gave it back" is
a claim about that object, so the choice was to run the theory on both hosts, not to narrow the text.
`A_refusal_at_every_page_write_of_a_WRITE_is_30_and_gives_the_store_mutex_back` now takes `Shapes()` (organization,
sharing mode, region host), forces the host with `RegionHostSeam.Use` before its `OperationsOfAWrite` measurement and
its loop over every refused page write and sync, and runs 8 cases, all green. The PB3414 DEVLOG entry and note are now
true as written. `closes_rows: []` stands: no inventory row.
