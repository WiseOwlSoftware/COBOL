**Rule it breaks:** DESIGN-external-repository section 4.3 (the host-type table's fixed-group row and its prose at lines 619-620: FILLER is kept privately so FromImage to AsImage round-trips; the positions no member covers keep the image FromImage or the entry's write-back read), PublishedRecordEmitter's own class summary (lines 24-26), and ISO 14.2.3 GR8 for the BY REFERENCE crossing the record carries

**Scenario:** 01 G USAGE BIT. 05 A PIC 1(3). 05 FILLER PIC 1(5). as a BY REFERENCE group formal of a host entry: the generated __TryGet assigns __r.__image = __s.Substring(__at / 8, width) only when !BitLayout.IsBitItem(group) (lines 225-226), so for the bit ROOT __image stays null after FromImage and after the entry's write-back; the next AsImage() (the next call's argument) lands the members into BlankImage(GroupUsage.Bit), zero bits (lines 206, 287). A program that sets G to all ones, returns, and is called again with the record the host got back sees its FILLER bits as 0, which no statement stored, where the same description under USAGE DISPLAY or NATIONAL keeps them. The guard is right only for a nested bit group, whose __image nothing reads (only the root's __Land, a scope root's __Var and a dynamic-capacity element's __Land read it, each at __at = 0, byte-aligned); for the root and a bit-group element of a dynamic-capacity table the change is silent.

**Measured how:** R2 batch finding `codegen-4--code--f1#1` (pair codegen-4--code), read in the pinned tree at 9e65164eb3a9; skeptics rule upheld, scenario upheld, site upheld.

**Spec:** §2023:14.2.3 "operates as if the formal parameter occupies the same storage area as the argument" (`cite.py --check` passed at collection)

**Target:** keep the image read for every record whose __image is read (the published root and a dynamic-capacity table element, both at __at = 0), whatever its usage: guard the Substring on the record being one whose __Land is called rather than on BIT usage, and pin a bit-group FILLER round trip beside HostEntryShapeDriftTests
