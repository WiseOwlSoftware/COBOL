# PB2040 — OPEN — `OPEN OUTPUT A OF B` opens the file `AOFB`

Filed 2026-10-05 by the train-1020b lander from the PB1281 implementer's report (wave 1020 group H, `New defects`).

**What happens.** Repro `E:\COBOL-coord\scratch\w1020h\p\fn1.cob`: `SELECT AOFB ASSIGN TO "fn1.dat"`, then
`OPEN OUTPUT A OF B.` compiles clean, opens AOFB, writes `WXYZ` and prints `DONE`. The operand reaches the binder as
`spec.dataReference().GetText()`, which glues `A OF B` into `AOFB`, and `ResolveFile` finds the file of that name.

**What the standard requires.** §8.4.2.2.2 prints qualified formats for data-names, condition-names, index-names,
paragraph-names and the other qualifiable names; a file-name has none, so `A OF B` in a file-name position names
no file and shall be refused (by name, quoting the qualifier). `cite.py --check 8.4.2.2.1 "Qualification is used to
allow unique reference of user names"` → OK.

**Code sites.** `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/SequentialIoBinder.cs:47` (`dataReference().GetText()`
→ `ResolveFile`), and every other `ResolveFile(name, …)` caller fed the same way: `SequentialIoBinder.cs:102,254` ·
`KeyedIoBinder.cs:202,247,277` · `FileLockBinder.cs:35` · `SortBinder.cs:364,503,732`.

**Fix shape.** One file-name operand reader (the PB1281 pattern: hand the binder the written `dataReference`, refuse a
qualifier, subscript or reference modifier, resolve only the base word) used by every caller above, so the next verb
gets it automatically. Related: PB682 (the diagnostic-quoting half of the same `GetText()` convention).
