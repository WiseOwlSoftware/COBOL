# PB3929 — universal-object-reference-not-supported--usage-word-required: USAGE clause: 'OBJECT REFERENCE' without the optional word USAGE gives 'syntax error, unexpected OBJECT'

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S9) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\universal-object-reference-not-supported--usage-word-required.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\universal-object-reference-not-supported--usage-word-required\`.

## Summary

GnuCOBOL 3.2 refuses a data description entry whose USAGE clause is written `OBJECT REFERENCE` without the optional
words `USAGE IS`: `syntax error, unexpected OBJECT`. The same entry written `USAGE OBJECT REFERENCE` compiles, with the
warning `OBJECTS is not implemented [-Wpending]`, and a program that only declares the item runs. In the USAGE clause
general format `USAGE IS` is optional for every usage, OBJECT REFERENCE included (ISO/IEC 1989:2002, 2014 and 2023).
cobc's grammar requires the word USAGE for this one usage because of a parser conflict, which its source records.
Legal source of the claimed edition is refused with a syntax error. Class: GnuCOBOL defect.

## Minimal test case

Free reference format (`-fformat=free`), 8 lines, written for this record. Five fuzz witnesses (nights 2, 3 and 5:
fz00123, fz00823, fz00856, fz02971, fz04665) stop at such a declaration on line 5.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. OBJB.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 R1 OBJECT REFERENCE.
PROCEDURE DIVISION.
DISPLAY "OK"
STOP RUN.
```

File: `E:\COBOL-coord\scratch\op\pb3838\records\universal-object-reference-not-supported--usage-word-required.cob`.

The program is legal: `OBJECT REFERENCE` with no class phrase declares a universal object reference (§13.18.60.4 22)
b)) at level 1 in working-storage (§13.18.60.3 14), 15)); the item is never referenced.

## Observed result

`objb.cob`, `-std=cobol2014`, exit code 1 (default dialect: exit 1, same error):

```
objb.cob:5: error: syntax error, unexpected OBJECT
    3 | DATA DIVISION.
    4 | WORKING-STORAGE SECTION.
    5 > 01 R1 OBJECT REFERENCE.
    6 | PROCEDURE DIVISION.
    7 | DISPLAY "OK"
```

`obju.cob` (the same program with `USAGE`): exit 0 after `obju.cob:5: warning: OBJECTS is not implemented
[-Wpending]`; `./obju` prints `OK`, exit 0.

## Expected result (per ISO)

The program compiles and prints `OK`. ISO/IEC 1989:2023, each citation checked with `scripts/spec/cite.py --check`:

- §13.18.60.2, the USAGE clause general format: `[ USAGE IS ] { BINARY | ... | OBJECT REFERENCE [ interface-name-1 |
  [ FACTORY OF ] ACTIVE-CLASS | [ FACTORY OF ] object-class-name-1 [ ONLY ] ] | ... }`. The diagram was verified on the
  printed page (PDF page 533, printed page 503): the bracketed `[ USAGE IS ]` precedes the whole choice, which holds
  OBJECT REFERENCE.
- §13.18.60.4 22): "A data item described with a USAGE OBJECT REFERENCE clause is called an object reference."
  22) b): "If none of the optional phrases is specified, this data item is called a universal object reference."
- §13.18.60.3 14): "A USAGE clause with the MESSAGE-TAG, OBJECT REFERENCE, POINTER, FUNCTION-POINTER, or
  PROGRAM-POINTER phrase may be specified only for an elementary data item at level 1 or ...". R1 is at level 1.

No syntax rule makes the word USAGE required for OBJECT REFERENCE.

Edition: the 2001-12-04 text headed "ISO/IEC 1989:2002(E)" prints the same USAGE format, `[ USAGE IS ]` before a choice
that includes `OBJECT REFERENCE`, and the 2009 committee draft CD 1.2 that led to 2014 prints it again (its
§13.18.59); object references are not optional elements in the 2009 committee draft that led to
2014 (its A.4.9 lists only multiple inheritance) or in 2023 (§A.4.10 lists only multiple inheritance and parametric
polymorphism).

Edition as recorded by the adjudicator: 2002 (carried into 2014). `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Class

GNUCOBOL-DEFECT: legal 2002/2014 source refused with a syntax error, where the equivalent form with the optional word
compiles. The broader absence of object-reference statements is
`universal-object-reference-not-supported--feature`.

## Our compiler (WiseOwl)

WiseOwl COBOL (built from main 6ed90bd1c), `cobol objb.cob --std 2014 --source-format free -o objb.dll`, then
`dotnet objb.dll`: compile exit 0, run exit 0, output `OK`.

## Fix site (GnuCOBOL 3.2 source, read observationally)

- `cobc/parser.y`, rule `usage_clause` (line 7912): its alternatives are `_usage_is usage` (USAGE IS optional) and
  `USAGE _is conflict_usage` (USAGE required).
- `cobc/parser.y`, rule `conflict_usage` (line 8269): holds `OBJECT REFERENCE _object_reference_type`, under the source
  comment that its tokens "explicit need USAGE _is (because of reduce/reduce conflicts)". Moving OBJECT REFERENCE into
  `usage`, with the conflict resolved, accepts the ISO format.
