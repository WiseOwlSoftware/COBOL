# PB915 — OPEN — an ordinal counted, where the format repeats one

Source: the `PB246-intrinsics` report (wave 40), "New defects" item 1. Re-measured here.

## The measurement

`<scratch>/reg7/probe/o_trim_ord.cob`, `--std 2023`:

```
o_trim_ord.cob(8,12): error COBOLNET1627: FUNCTION TRIM argument-3 is 2 character position(s) in length;
ISO §15.96.3 r2 requires exactly 1. --permissive accepts it as a coercion extension
```

## The rule

```
$ python scripts/spec/cite.py --check 15.96.3 "argument-2 shall be a single character"
OK  §15.96.3 2)  (Argument rules)
    2) When argument-1 is class alphabetic or alphanumeric, argument-2 shall be a single character that is
       either class alphabetic or class alphanumeric. When argument-1 is class national, argument-2 shall
       be a single character …
```

§15.96.2's general format names **argument-1** and a repeated **[ argument-2 ]**. There is no argument-3.
The rule the message cites — r2 — is the right rule, and it is written about argument-2; the message then
tells the user that a thing the standard does not name violates it.

## The code site

`src/Cobol.Net.Compiler/Binding/IntrinsicArgumentRules.cs#PredicateViolation` and `#CrossViolation` build
the ordinal from the operand's position in the call. That is correct for a fixed-arity schema and wrong for
every schema whose tail REPEATS one ordinal.

## The fix, and why it is a schema property and not a special case

`SUBSTITUTE` already words its own pair message by hand — the same problem solved locally, once. The
repair is on the SCHEMA: the argument schema should record, per slot, whether the slot is a repetition of
the previous ordinal, and the renderer should say `argument-2 (occurrence 2)` when it is. Every future
variadic-tail function then gets it for nothing, and `SUBSTITUTE`'s hand-written message can be deleted
rather than copied. `feedback_model_the_rule_shape_not_one_case`.

## The sweep

Every intrinsic whose §15.x general format prints a repeated argument: TRIM, SUBSTITUTE, CONCAT, MAX, MIN,
SUM, and the statistical family. `scripts/spec/` already derives the intrinsic tables, so the repetition
flag can be derived rather than typed.

## Rows

None — the §15.96 rows record the RULE, which is enforced correctly. This is the message.
