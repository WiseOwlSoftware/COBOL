# PB2914 — the self-tests' wall-clock limit fails every gate of a concurrent fleet

**Found by:** the wave-1051 orchestrator unit (2026-10-10, account 2), supervising the rolling wave.

## Defect

Wave 1051 started six implementers at 10:20 PDT; another session gated two branches of its own (`w1051y-pb2707`,
`w1051z-pb2515`) at the same time. By 12:17 PDT the eight worktrees had run 15 implementer gates and **every one ended**
`=== BUILD-LOCAL GATE: RED — SELF-TESTS RED — fail-fast: the audits run before the slot and the build and NO LEG RAN`.
No gate reached the slot or ran a test leg. The red self-tests were always from the same set, each
`RED (exit 124) … ⛔ TIMED OUT after 900 s`: `landing_check.py --self-test` (every gate),
`test_orchestrate_stop.ps1` (every gate), and `test_orchestrate_steer.ps1`, `test_orchestrate_breaker.ps1`,
`test_orchestrate_handoff.ps1` in the more crowded runs. The other orchestrator parts passed in 447–780 s
(`scratch/w1051e/gate2.log`).

**Measured:** `landing_check.py --self-test` run by itself (its own `COBOL_COORD_DIR`, as `self_tests.py` runs it),
while the fleet ran: **PASS 25/25 in 955 s**. PB2882 measured the same test at 93–174 s without a fleet. It has
no defect. It is slow, and under load it takes longer than the limit.

**Mechanism:** `scripts/self_tests.py` gives every self-test a fixed wall-clock limit (`TIMEOUT_S = 900`,
`run_one`) and runs them in a pool `min(len(tests), jobs or os.cpu_count())` wide (`run_all`), i.e. 32 workers here.
`run_gate_legs.py` runs that phase in implementer mode BEFORE the gate slot (PB2524, so a red audit fails fast without
queueing), and since PB2563 (2026-10-08) every gate runs all 68 self-tests. Nothing bounds the self-tests across gates.
Eight gates in the audit phase together mean up to 8 × 32 self-tests, each spawning git, python or pwsh children (the
machine sat at ~41 % CPU, so the cost is mostly process creation and the file system, not compute). The slowest tests
then exceed 900 s and the gate ends RED. An implementer that re-gates runs into the same contention, so the wave
livelocks: every slot is busy re-running self-tests and no change is ever verified.

This is the wall-clock test the owner forbids (a test that can fail with no regression because of a fixed time
limit, memory `no-wall-clock-tests`, 2026-09-25), here sitting in the gate itself. Wave 1045 ran eight groups after
PB2563 without a timeout, so the concurrency at which it trips is near the fleet's size. PB2882 (the same tests' serial
chains) would raise the threshold but would not remove the cliff.

## Code sites

- `scripts/self_tests.py#run_one` (`TIMEOUT_S = 900`, `subprocess.run(..., timeout=TIMEOUT_S)`)
- `scripts/self_tests.py#run_all` (the per-gate pool width, `jobs or os.cpu_count()`)
- `scripts/run_gate_legs.py` (the implementer-mode audit phase ahead of the slot; `AUDITS` "SELF-TESTS")
- the slow arms: `scripts/orchestrator/landing_check.py:276` (`self_test`), `scripts/orchestrator/test_orchestrate_*.ps1`

## What closes it

One mechanism: no self-test may be judged RED by the clock because of load from other gates. Repair it at the root,
not by raising the number: bound the self-tests' concurrency machine-wide (one shared budget, as `gate_slot.py` bounds
builds and legs) so a gate's self-test time does not grow with the number of gates; keep a limit only as a hang
detector that scales with the measured load, or that reports a hang distinctly from a red. Add a drift or self-test that
runs the self-test phase from N concurrent gates and requires no timeout. Take PB2882's serial chains in the same
cluster. Repro: start the rolling wave with six or more implementers, as wave 1051 did, and read the
`=== SELF-TESTS:` line of each `scratch/w1051*/gate*.log`.

**Rule:** none (gate tooling, no ISO clause).

## Landing (2026-10-10, wave 1051 V; PB2897 retired into this note)

**Re-probed.** Baseline implementer gate `20261010T193556Z-4a8306` beside four other gates: `=== SELF-TESTS: GREEN — 68
ran in 467s` (test_orchestrate_stop 466.5 s, steer 461.1 s, handoff 444.8 s, landing_check 400.3 s): the phase grows
with the number of gates, and 900 s was two more gates away.

**Fixed at the root, one mechanism in three parts** (DESIGN-test-build-ci.md §3.14.10):
1. **Reuse.** `scripts/self_tests.py` traces every self-test it runs and records each PASS with the content of what it
   read in ONE store, `<git common dir>/cobol-self-test-passes/`; `--reuse` (the implementer gate only) reports a
   self-test REUSED while all of it is unchanged. What "read" means lives in one new module,
   `scripts/self_test_inputs.py`: the Python audit-hook tracer (files opened, directories listed, paths handed to a
   child), the static inputs no hook sees (own file, the runner, `SELF-TEST-READS`, a PowerShell/bash script's
   mentioned files), and `git_reads` (a git command's pathspec, names or content). The lander's gate, CI and the Linux
   gate never reuse: they run and record.
2. **One machine-wide budget.** Each self-test that runs takes one of `os.cpu_count()` places
   (`<git common dir>/cobol-self-test-slots/`, gate_slot's `ExclusiveLock`), so N gates share the cores. The phase stays
   ahead of the gate slot (PB2524's fail-fast), on its own budget.
3. **No verdict from the clock.** `TIMEOUT_S = 900` is deleted. A self-test still running 3,600 s after taking its place
   is HANG — its own state, verdict (`=== SELF-TESTS: HANG`), exit 3 and gate reason (`SELF-TESTS HANG`).

**Measured on this tree:** record run 69 ran in 71-76 s; `--reuse` on the same tree 0 ran, 69 reused in 0.9 s; a one-line
`src/` edit re-ran 2 (test_dispatch_guard.py and test_plan_wave.py, which both READ `src/`) in 10 s; a `kb/Work` edit
re-ran 4 in 10 s.

**Proof.** `self_tests.py --self-test` `fleet_arms`: four concurrent simulated gates; no re-run on an unchanged tree,
exactly the reader re-run on a changed input, at most the budget at once, HANG never RED, a malformed record skipped —
each arm seen RED once with its mechanism disabled. PB2882's long poles were not shortened (each a fixture redesign);
that note now carries what remains.
