# PB3796 — FunctionValuePic has a third reader than its documentation names

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/SendingValueTemp.cs#FunctionValuePic` (the remarks paragraph, around line 98) and `#IntermediatePic` (line 199), `src/WiseOwl.Cobol.Compiler/Binding/OoBinder.cs` (line 1334, the `ValueUse.Text` INVOKE argument into a character formal), `docs/CONFORMANCE.md` (line 503, D-FNUSE), `kb/Work/PB3691.md`

## Measured

The paragraph on `FunctionValuePic` says its USAGE DISPLAY representation "only SIZES that item", and docs/CONFORMANCE.md:503
and kb/Work/PB3691 say its only readers are the `FUNCTION LENGTH` fold and IN-ARITHMETIC-RANGE. But
`SendingValueTemp.IntermediatePic` line 199 also returns `FunctionValuePic` (`use.AsText ? FunctionValuePic :
ValueOperandPic`) as the carrier of a non-integer numeric function read AS TEXT (`ValueUse.Text`, OoBinder.cs:1334, an
INVOKE argument into a character formal), and there the Display representation PRODUCES the characters the callee reads. A
later change that varies the representation because "it only sizes" would alter the text a callee receives.

Whether the text a callee reads is spec-governed (section 15.4.1 leaves the returned value's representation to the
implementor, but the character image of a numeric function result passed to a character formal is a conversion the
standard may rule) is a judgment this note does not make: the implementer derives it from the spec first.

## Acceptance

- The remarks, D-FNUSE and PB3691 name all three readers, or the third reader is moved off `FunctionValuePic` onto its
  own description if the text image must not depend on the sizing representation.
- A test pins the text a callee reads for a non-integer numeric function argument into a character formal (value
  derived from the spec with `cite.py --check`, not from the current output).
