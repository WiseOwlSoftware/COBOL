# PB2074 — DISCHARGED — a permissive coercion can reach a LOUD render of an address-identifier

## Mechanism

PB1060 admitted an address-identifier as an intrinsic-function argument where the function's rule takes a pointer.
`src/Cobol.Net.Compiler/CodeGen/Emit/IntrinsicRenderer.cs:1749`
(`public string Visit(BoundAddressOperand n) => EmitText.LoudValue("string", "address-identifier as a character argument");`)
assumes the binder never admits one as a character argument. Under `--permissive` the argument "coercion extension"
may still hand one through to a class-alphanumeric function (e.g. `FUNCTION UPPER-CASE (ADDRESS OF X)`); the program
would then compile and fail at run time instead of being refused at compile time.

## Repro to write

`MOVE FUNCTION UPPER-CASE (ADDRESS OF X) TO Y` compiled with `--permissive` at `--std 2023`. Expected: a compile-time
refusal (an address-identifier is class pointer; no coercion makes it alphanumeric). If it compiles, the binder's
permissive coercion must exclude the pointer class; if it is already refused, discharge this note with the probe.

## Discharged (wave 1045 group E, 2026-10-08)

Re-probed on a fresh build of the wave-1045 base (685b44315): `MOVE FUNCTION UPPER-CASE (ADDRESS OF X) TO Y` is refused
at compile time with COBOLNET1627 ("argument-1 is of class pointer; ISO §15.3 requires class alphabetic, alphanumeric
... or national (§15.97.3 r1)") both strict and under `--permissive`, and the error does not offer the coercion. The
same holds for REVERSE, TRIM, ORD, CONCAT, NUMVAL, MAX / ORD-MAX (§15.59.3 r1's exclusion), BASECONVERT (COBOLNET1642)
and CONVERT ANY (COBOLNET1514); LENGTH and BYTE-LENGTH fold an address-identifier to the pointer width at bind time.

The landing that closed it is 3ead74dcf (kb/Work PB2079): `IntrinsicBinder.CheckArgumentClasses` reports a class
violation through `ReportClass`, which offers the `--permissive` coercion only for an operand that holds characters
(`IntrinsicArgumentRules.IsDigitDecodable`, false for class pointer and object). So no address-identifier reaches
`IntrinsicRenderer.StrArgVisitor`'s LOUD arm, whose comment now says so.

Pinned: negative `pb2074-upper-case-address-of` (reject-at 85 2002 2014 2023, COBOLNET1627) and the same fixture added to
`conformance:IntrinsicPointerArgumentPermissiveTests.PointerArgument_IsRefusedUnderPermissive_WithoutOfferingTheCoercion`,
which compiles it under `--permissive`.
