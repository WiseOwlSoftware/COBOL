# PB5785 - READ INTO where every record description is shorter than RECORD CONTAINS gives status 00 and a short move (every edition); which of the two results the text supports is right is decided before the fix

**What is wrong.** READ INTO where every 01 record is shorter than RECORD CONTAINS gives status 00 and a short move. **The expected result is not ruled here: WHICH result is right is decided before the fix.** The text supports two results, and the compiler gives neither. `FD FR RECORD CONTAINS 12` with one `01 RR PIC X(5)` (legal: `§1985:VII.3.8.3 SR1` only bars a description LARGER than integer-1) reads a file of 12-character records. The compiler delivers `W=[ABCDE       ]` with status 00. Under (A) GR3 makes every record 12 positions and READ GR8b moves the current record, whose size "is determined by rules specified in the RECORD clause", so `W=[ABCDEFGHIJKL]`, status 00. Under (B) READ GR13 (level 2): a record read that is longer than the maximum size the record descriptions specify is truncated to it and an I-O status indicating a record length conflict (04) is set, so `W=[ABCDE       ]` with 04. Under either the run is wrong (the data under A, the status under B). The output is the same at `--std 2023`, whose READ GR14 carries the same truncation-and-04 text, so the cause is (b). The adjudicator's lean (the checker's, not a ruling): B, because GR13 is the rule for exactly this case and GR8a applies the READ without INTO first.
