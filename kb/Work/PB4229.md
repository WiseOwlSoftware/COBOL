# PB4229 — `PERFORM READ.` is not named as a reserved-word misuse

Related: PB4206, PB4132.

**Sites:** `src/WiseOwl.Cobol.Frontend/Grammar/CobolParserCore.g4:902` (`procedureName`: it admits only the reservation-gated token set),
`src/WiseOwl.Cobol.Frontend/Parsing/CobolLexerWordSet.g.cs:222` (`CobolLexer.IsReservationGated`: the set that rule consults),
`src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolControlFlow.g4` (`performStatement`: the inline alternative that wins).

**The rule.** §8.3.2.1 1) "Reserved words shall not be used as user-defined words or system-names." (the report cites it as OK under
`python scripts/spec/cite.py --check`). A paragraph named READ or DISPLAY is a reserved-word misuse, and every other operand slot
reports it as COBOL0901.

**The defect.** `PERFORM READ.` and `PERFORM DISPLAY.` (probe `cases.txt` rows 6 to 9, probe dir `E:/COBOL-coord/scratch/w20261786a/probe`)
draw `COBOL0001: unexpected '.'` at every edition, never COBOL0901. Recorded as the report gives it; this clerk did not re-run it (R2).

**Mechanism.** `procedureName` admits only the reservation-gated set (`CobolLexer.IsReservationGated`). A word reserved at EVERY edition
is a plain keyword token, outside that set, so the name slot cannot take it and the inline PERFORM reading (a READ or DISPLAY statement
that the period then breaks) wins. Distinct from PB4206 (there a gated token is involved); it shares the "statement reading competes
with the name slot" shape with PB4132.

## Landed (wave 20261788 B, 2026-10-31)

**Sites (as changed):** `src/WiseOwl.Cobol.Frontend/Parsing/CobolParserCoreBase.cs` (`ReservedProcedureName` new,
`ReservedWordHere` new, `NamesAProcedure` new, `Reading` new, `ReadingParses` now through `Reading`),
`src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs` (`Report`),
`tests/WiseOwl.Cobol.Tests.Conformance/ReservedWordPositionConformanceTests.cs` (three new theories),
`docs/rearchitecture/DESIGN-frontend-grammar.md` (the reservation-gate paragraphs). The filed site
`CobolParserCore.g4#procedureName` is unchanged, and on purpose (below).

**Re-probe** (build of 11e8949be, --std 2023): `PERFORM READ.` and `PERFORM DISPLAY.` -> `COBOL0001: unexpected '.'`, as
filed, at every edition. The sweep showed the mechanism covers every procedure-name slot a statement or header reading can
take: `PERFORM MOVE.` / `STOP.` / `ADD.` / `IF.` / `SECTION.`, `PERFORM READ 2 TIMES.` / `UNTIL` / `VARYING` / `THRU P1` / `OF
S1`, `PERFORM P1 THRU READ`, `PERFORM P1 OF READ`, `GO TO READ.`, `GO READ.`, `GO TO P1 READ DEPENDING ON N`, `ALTER READ TO P1`,
the header `READ.` and `DISPLAY SECTION.` — each a COBOL0001 (several with a second COBOL5506 for the misreading's tail) that
never named the word. The note's premise that "every other operand slot reports it as COBOL0901" holds for the
reservation-gated words only: `MOVE READ TO W-X` is also a bare COBOL0001 (a data-reference slot, a different arm, reported as
a lead).

**Why not a grammar arm.** A keyword alternative in `procedureName` for every word reserved at every edition would compete with
every statement and header reading the word is one of (`EXIT.` is both a statement and, so, a header), and would put the whole
keyword set into the PERFORM / GO TO prediction of every program. So the slot answers after the fact, on an error only:
`ReservedProcedureName` re-reads the sentence with one candidate word (the offending token, the first token of each open rule and
of the rule each matched last) retyped to IDENTIFIER, as a `sentence` and, when the word begins it, as a `procedureUnit`; a
complete reading with the word under `procedureName` names it (COBOL0901, the §8.9 sentence `ReservedWordSet` owns), the one
fault covering the sentence through its period and its tail discarded as orphaned. A fault elsewhere fails every re-read:
`PERFORM DISPLAY W-N.` (no END-PERFORM), `PERFORM READ W-N.`, `MOVE W-N TO` before a DISPLAY, `PERFORM P-END THRU` before a
DISPLAY keep their own reports.
