# PB1709 — RETIRED (2026-09-28)

**Owner:** "Don't record an impact map on every main commit, as I assume it shouldn't change substantially each
commit." Under PB1708's "order, don't skip" gate, a stale map only mis-orders tests, never skips one, so per-commit
recording buys nothing that correctness needs. Maps are recorded on demand.

## Original filing

Filed by the train-70b lander from wave 70 group I's report (`w70i-PB1683-report.md`, new defect 2).

## Finding

`scripts/spec/impacted_tests.py --base <sha>` looks up `<git common dir>/cobol-impact/<sha>.json.gz`; no step records
one. The maps recorded by the PB1683 implementer (at `dbea12428` and `4b0f3e22a`) sit in its scratch store, not the
shared store. Until a map is recorded at each main head, every implementer's derived filter is `FullyQualifiedName~.`
with the reason "no impact map recorded for the base".

**Sites.** `scripts/battery.sh` (no record call) and the lander-train brief (no record step). A recording takes about
19 min at BelowNormal; the map is about 5 MB. Decide together with PB1708 (whether the derived filter is worth
recording for, given it selects the whole assembly for every replayed cluster).

**Under the PB1708 pivot (2026-09-28, `DESIGN-test-build-ci.md` section 3.14.8).** The map now only ORDERS a
whole-population gate, so a missing or stale map costs ordering quality, never soundness, and the gate falls back to
one leg in the plain order. The replay of 68b X (`docs/rearchitecture/evidence/impact-map-pb1708/b4`) put the first
red after 0.32 % of the work ordered cheapest first inside the map's tiers (9,144 of 9,190 tests shared one tier),
against 62 % ordered by map specificity and 14 % in the plain order. Whether a map
is still worth recording per main commit (~19 min each) or only on demand is an open owner question.
