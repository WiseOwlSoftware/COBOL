## Measured

### Finding sum-clause — ISO/IEC 1989:2023 13.18.54.3 SR2; 14.9.25.3 SR10 Table 16 (under-rejects; rows SR-13.18.54.3-2)

**Mechanism.** SR2 (the SUM entry's category must be a legal MOVE receiver for a numeric sender) has no screen: BindSumClause accepts any PICTURE category for the subject of the entry.

**Repro.** out13/probe/sum-clause/p3.cob with `03 COLUMN 1 PIC A(4) SUM WS-K.` (and again with `PIC 1(4)`), --std 2023.

**Expected, from the standard.** 13.18.54.3 SR2 + 14.9.25.3 SR10 Table 16: numeric -> alphabetic = No, numeric -> boolean = No, so both entries shall be rejected at compile time.

**Observed.** Both compile and run silently (print '4' and '4000'). No diagnostic cites 13.18.54.3 SR2 anywhere in src.

**Code site.** src/Cobol.Net.Compiler/Binding/DataBinder.Reports.cs#BindSumClause

### Finding sum-clause — ISO/IEC 1989:2023 13.18.54.2 (under-rejects; rows FMT-13.18.54.2)

**Mechanism.** reportSumClause attaches reportSumReset? and roundedPhrase? to EACH `SUM ... [UPON ...]` group, so a RESET phrase or ROUNDED phrase written BETWEEN repeated SUM groups is accepted, although the general format admits them only once, after the whole repetition.

**Repro.** out13/probe/sum-clause/p6.cob with `SUM WS-A RESET ON FINAL SUM WS-B` or `SUM WS-A ROUNDED SUM WS-B` (--std 85 and 2023).

**Expected, from the standard.** 13.18.54.2: `{ SUM OF {...}... [ UPON {data-name-2}... ] }... [ RESET ON {data-name-3|FINAL} ] [ rounded-phrase ]` — the RESET group and rounded-phrase follow the repeated group; the forms above are not derivable and shall be rejected.

**Observed.** Both compile and print 006. The grammar comment says the binder diagnoses a SECOND RESET/ROUNDED; a single one in the middle is not diagnosed.

**Code site.** src/Cobol.Net.Frontend/Grammar/Core/CobolReportWriter.g4#reportSumClause; src/Cobol.Net.Compiler/Binding/DataBinder.Reports.cs#BindSumClause

### Row SR-13.18.54.3-6 — DIVERGES (no separate finding; the adjudicator's / refuter's record)

Code location: `src/Cobol.Net.Compiler/Binding/DataBinder.Reports.cs#ResolveSumAddend; src/Cobol.Net.Compiler/Binding/DataBinder.Reports.cs#ReportSectionNameIn`

SR6 'any identifiers it contains may reference entries in any section of the data division other than the report section' (cite.py --check 13.18.54.3 OK). ReportSectionNameIn walks the expression; a sum counter (negative golden) and LINE-COUNTER (probe p5: COBOLNET2144) are refused; WS identifiers are admitted (conformance:85/pb883_report_sum_expression). An unprintable NAMED report entry (DET-U, no COLUMN) is refused too but with COBOLNET1639 'not defined' rather than 2144 - rejection correct, diagnostic imprecise. || REFUTED: DIVERGES — ReportSectionNameIn returns as soon as it reaches a DataReferenceContext, so it never walks that reference's subscripts. A report-section identifier used as a subscript inside the expression addend passes the screen. SUM WS-K + WS-E(SC), where SC is a sum counter of the same report, compiles clean. SR6 bars every identifier the expression contains from the report section, and §8.4.2.3.3 SR8 separately forbids a sum counter as a subscript in the report section. Result: invalid source is accepted. The top-level cases (a bare sum counter, PAGE-COUNTER, LINE-COUNTER) are rejected correctly with COBOLNET2144.
