# PB6081 - the edition passed as loose values below the driver (CLAUDE.md rules 4, 5, 6)

**Mechanism.** PB2619 made `CompilerDriver.Options` carry a required `EditionInfo Edition`. Below it,
`src/WiseOwl.Cobol.Frontend` `Frontend.DialectLevel { get; init; } = 85` plus `Frontend.Permissive`, and
`Binding.EditionContext(int dialectLevel, bool permissive)`, still take the edition as two loose values; the front end
defaults to 85 by itself (a fourth default edition). The driver hands both the parts of `options.Edition`.

**Target.** Both take `EditionInfo`, with no default; every caller changes in the same change (rule 4).

**Doc owed in the same change (rule 6).** `docs/rearchitecture/DESIGN-edition-framework.md:39`, problem P5, still describes
the edition as set from `Options.DialectLevel` with a fourth default (`Options = 2023`) at `CompilerDriver.cs:38`; after
PB2619 `Options` carries a required `EditionInfo Edition` with no default, so the row describes code that no longer exists.
PB2619's landing updated four other docs and missed this one.
