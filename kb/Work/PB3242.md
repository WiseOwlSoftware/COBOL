# PB3242 — a note's declared file set is its structured sites, read by one reader

**Found by:** the Mythos session's Finding B (2026-10-15 14:45 PDT, revised 2026-10-16 02:45 PDT,
`E:/COBOL-coord/scratch/mythos-item1/decisions-item1-20261015.md`), measured on the PB2807 branch (198-4) and main.

**Harm (process only):** the file-set partition (DESIGN-architecture-review §8.7) declared every path a note's TEXT
named, so a note that only DISCUSSES a file held it. 57 of PB1754's 63 ready R2 notes discuss
`scripts/orchestrator/landing_check.py` and `plan_wave.py`, and every PB3160 slice says "cite.py --check", so the
two campaigns' dry runs (`plan_wave.py --cluster PB1754 --dry-run`, `--cluster PB3160 --dry-run`) planned one
campaign group each, the rest waiting on collisions with one another's prose.

**Mechanism: three text scans, no reader of the structure.**
(a) `plan_wave.note_file_set` was `fix_clusters.sites(text)` (the public base's scored clustering heuristic over the
whole text: every path, bare file name, `Type.Member` and CamelCase type) plus `member_callers(text)`;
(b) `scripts/arch/member_index.py`'s `folder_files` and `note_names`' fallback ran `SITE_PATH` over the whole text, and
its `DOC_ID` read every `` `E:\...` `` drive path in prose as an event documentation id;
(c) `scripts/spec/work.py` `note_sites` read only the first **Sites** block (the right shape) but its `_SITE_PATH`
accepted only `(src|tests|docs)/`, so a `scripts/` site (PB3203's own) declared nothing, although `scripts/` is a
campaign root (`model_rules.json` `campaign.src`).
A sibling: `member_index.callers` widened UNKNOWN names by drift, so PB3203's six Python names (unknown to the C#
index) matched `main` and `partitioned` as words in every drifted C# file: 57 `src/` files, none of its own two.

**Repro:** `python scripts/arch/member_index.py --note PB3203` (57 C# files, no `scripts/` file) and the two dry runs
above (`E:/COBOL-coord/scratch/w1090/w1090a/before-PB1754.txt`, `before-PB3160.txt`).

**Decision (Finding B revised, verbatim in the dispatch):** a note's DECLARED file set = its STRUCTURED sites only (the
paths of its Code site / Site / Sites blocks, suffixes dropped; the members of its `**Moves or changes:**` line,
`r2_members:` and doc-id spans resolved through the member index, plus their callers and the tracked code files under
a site folder); never a path in prose, a `Gate:` line, a tool command or a bare type name; path prefixes from
`model_rules.json`; ONE reader owned by the register; the planner's collision set for any group is its notes' declared
sets plus its primary file; fix_clusters' prose sites only rank and group the fix lane.

## Landed (wave 1090 group A, branch `worktree-wf_b14ea906-c69-1`)

**Re-probed first** on the branch's base 173dc4f35: `member_index.py --note PB3203` gave 57 `src/` files and neither of
its two `scripts/` sites; the PB1754 dry run planned 2 groups (one campaign cluster, one finisher) with 101 notes
waiting on collisions, the PB3160 run 2 (one cluster, one finisher) with 4.

**Fix (one reader, one computation, one policy).** `scripts/spec/work.py` `note_sites(text) -> NoteSites` is THE reader
of a note's structured sites: the site blocks (a bold `Code site` / `Site` / `Sites` label's paragraph and the list
under it, or a heading's section), each path under a `model_rules.json` campaign root (`coord.campaign()`, the
campaign domain parsed once, `coord.CampaignDomain`), suffixes dropped, placeholders and globs refused; the names of
the `**Moves or changes:**` and `r2_members:` lines and the site blocks' documentation ids; and the `**Wave kind:**`.
`member_index.note_file_set` reads through it (no whole-text `SITE_PATH`, `MOVES_LINE` or `DOC_ID` remains), returns
the whole declared set (site files, code files under site folders, callers), reads the index only for a note that
names a member or restructures (a fix-lane note declares its sites only), and widens only KNOWN names by drift.
`plan_wave.declared_sets(repo, IndexPolicy)` is the one computation; `computed_file_set(repo, ids, policy)`,
`collision_set` (a group's notes' declared sets plus its primary file) and `declare_fix_lane` (the fix lane's
clusters take that set instead of fix_clusters' prose `files`) use it; `campaign_clusters` clusters on the declared
site files (`fix_clusters.cluster` over `{site: 3}`) and no longer builds a `source_index`.

**After:** `member_index.py --note PB3203` declares its two files; PB2296 step 1 declares 69 files with all six
`DataBinder.Options` users; the PB1754 dry run plans 8 groups (6 campaign clusters, 2 finishers), every one of its 78
