# PB4049 — the torn-file hold and the lane's own findings file: a second reviewer of the same round

Filed from a lead of the PB3608 review. Pull request #760 was not on main when this was filed; the sites below are as on that
branch (`worktree-wf_e06e2377-556-4` at `12efd4325`). Reproduce against the branch until #760 lands.

## Sites

- `scripts/orchestrator/units/enqueue.md` Step 2 (line 34): for a hold of "a findings file torn other than by a cut-off append" the
  unit dispatches ONE read-only `cobol-reviewer` by hand and gives it the hold's own findings file, which `review_lane.py status`
  prints on the HOLD line (the R1-5 fix). For a torn-file hold that path is the lane's own file, `review_lane.py#findings_path`.
- `scripts/orchestrator/review_lane.py#plan_review` (the `rounds is None` arm, `repair_interrupted_append`, then `done` / `open_` /
  `rnd`): after the operator mends the own file, an open round (a `start` with no verdict) in it reads as the lane's own killed round,
  "the round to start again".
- `scripts/orchestrator/review_lane.py#standing`: grants a lease to a reviewer's open round only in a file that is NOT the lane's own
  (`os.path.normcase(str(path)) != os.path.normcase(str(own))`), and a torn-file hold is a `Plan(hold=True)` from `plan_review`, so it
  does not gate the lane's start of that branch once the file reads again.

## The defect

The hand-dispatched reviewer writes its `start` into the lane's own file. When that file is mended, the lane finds an open round at the
branch's tip in its own file, finds no live runner of its own, and `standing` refuses it a lease because the file is the lane's own.
`plan_review` therefore starts the round again: a second reviewer of the same round, beside the unit's live one, appending to the same
file.

The R1-5 fix answered the missing path; it did not answer the duplicate its scenario named. An ATTEMPT_LIMIT hold is safe: the count
of failed lane reviewers (`failed` in `plan_review`) still holds it. Only the torn-file hold lacks that second guard.

## Direction (not a fix; the implementer chooses)

Either send the hand-dispatched reviewer to a file the lane does not treat as its own (so `standing` leases it like a wave
reviewer's), or record a torn-file hold as held at the head (as the ATTEMPT_LIMIT hold is) so the lane does not start the branch until
the enqueue unit collects it (`review_lane.py collect`). Add a `--self-test` arm: tear the own file, hold, mend, add an open round by
a second reviewer name, tick, and expect no second start.

## Landed

`review_lane.py#plan_review` now returns a hold plan while the branch carries an UNCOLLECTED hold at its head (any reason): the lane
starts no review until the enqueue unit runs `review_lane.py collect`, so the unit's hand-dispatched reviewer is the only one of its
round even in the lane's own file once the operator has mended it. This is the note's second direction: one rule for every hold the unit
answers by hand, and the lane's own findings file stays the one place a branch's rounds live. Two `--self-test` arms (tear, hold, mend,
open round by a second reviewer name, tick: no second start; then collect: the round starts again), both declared in
`ReviewLaneDriftTests`.
