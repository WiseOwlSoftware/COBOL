# PB3921 — boolean-class-condition-not-supported--boolean-compute: Boolean COMPUTE 'R = A B-AND B' over PIC 1 items is refused: 'A should be COMP-X/COMP-5 for logical operator'

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S8) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\boolean-class-condition-not-supported--boolean-compute.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\boolean-class-condition-not-supported--boolean-compute\`.

## Summary

GnuCOBOL 3.2 refuses a format-2 (boolean) COMPUTE whose binary boolean operator (B-AND, B-OR, B-XOR) has boolean
data items of usage display (PICTURE 1) as operands: `A should be COMP-X/COMP-5 for logical operator`, under
`-std=cobol2014` and under the default dialect. cobc treats B-AND, B-OR and B-XOR as integer bit-wise operators that
need COMP-X or COMP-5 operands; ISO defines them over boolean values "without regard for the usage of the operands".
Boolean expressions over boolean items are part of ISO/IEC 1989 since 2002 and are in the 2014 edition that
`-std=cobol2014` claims. Class: rejects legal ISO source. This is one of the mechanisms filed together as
boolean-class-condition-not-supported (witness fz04838); its sibling boolean-class-condition-not-supported--boolean-held-as-number
records the unary B-NOT, which cobc accepts and computes wrongly.

## Minimal test case

Free reference format (`-fformat=free`), 11 lines, written for this record. File:
`E:\COBOL-coord\scratch\op\pb3838\records\boolean-class-condition-not-supported--boolean-compute.cob`. The night-4

```cobol

01 R PIC 1(4).
PROCEDURE DIVISION.
COMPUTE R = A B-AND B
DISPLAY R
STOP RUN.
```

## Observed result

`-std=cobol2014`, exit code 1 (the default dialect prints the same, exit code 1):

```
bcmp.cob:9: error: A should be COMP-X/COMP-5 for logical operator
```

(cobc also prints its source-context lines.) The PICTURE 1 entries and the boolean literals on lines 5-7 draw no
diagnostic.

## Expected result (per ISO)

The program is legal, compiles, and stores the boolean value 1000 in R (DISPLAY shows `1000`).

- ISO/IEC 1989:2023 §14.9.8.2 (checked), format 2: `COMPUTE { identifier-2 } … = boolean-expression-1 [ END-COMPUTE ]`;
  §14.9.8.3 2) (checked): "Identifier-2 shall reference an elementary boolean data item." R is one.
- §8.8.2 (checked): a boolean expression may be "an identifier referencing a boolean data item" and two boolean
  expressions separated by a binary boolean operator; §8.7.2 (checked) lists B-AND, "AND operation (boolean
  conjunction)".
- §8.8.2 9) (checked): "Binary boolean operations shall be performed without regard for the usage of the operands."
  For operands of equal length the operation proceeds "by operation on boolean values in corresponding boolean
  positions starting from the leftmost boolean position". 1100 B-AND 1010 is 1000.
- §14.9.8.4 3) (checked): "The number of boolean positions in the value resulting from the evaluation of
  boolean-expression-1 is the number of boolean positions in the largest boolean item referenced in the expression."
  Four positions.

Nothing in the standard requires a particular usage for the operands of a boolean operator; the COMP-X/COMP-5
requirement is GnuCOBOL's, from its integer bit-wise extension.

Edition: a 2002 feature, present in 2014. The ISO/IEC 1989:2002 text and the 2009 committee draft that became
ISO/IEC 1989:2014 (CD 1.2) both carry the boolean-expression rule "Binary boolean operations shall be performed
without regard for the usage of the operands" and COMPUTE's rule "Identifier-2 shall reference an elementary boolean
data item"; Annex E of the 2023 standard adds only the B-SHIFT operators (E.2 item 3), not used here.

Edition as recorded by the adjudicator: 2014 (introduced 2002). `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Class

GNUCOBOL-DEFECT, rejects legal ISO source (edition 2014; introduced 2002).

## Our compiler (WiseOwl)

WiseOwl COBOL (built from main 6ed90bd1c), `cobol bcmp.cob --std 2014 --source-format free -o bcmp.dll`, then
`dotnet bcmp.dll`: compile exit 0, run exit 0, output `1000`.

## Fix site (GnuCOBOL 3.2 source, read observationally)

- `cobc/tree.c`, `cb_build_binary_op` (line 5798), the bit-wise operator arm for `'a'`, `'o'`, `'e'` (and the shifts
  `'l'`, `'r'`) at lines 5986-6010: both operands go through `cb_check_numeric_value`, any field operand whose usage is
  not `CB_USAGE_COMP_5` or `CB_USAGE_COMP_X` draws the "should be COMP-X/COMP-5 for logical operator" error, and the
  result category is set to numeric. A boolean-category operand (`CB_CATEGORY_BOOLEAN`) needs a boolean evaluation path
  instead of the integer one.
- `cobc/scanner.l`, `scan_b` (line 1844): a boolean literal is built as a numeric literal (its source carries a
  "FIXME: we should likely build a boolean literal" comment), which is why the operators see integers.
