# PB2983 — column units disagree for supplementary characters

Filed 2026-10-10 by the train 1055 lander from the wave 1055 B report
(`E:\COBOL-coord\scratch\reports\w1055b-PB1688-report.md`, lead 2; first seen as w1053c lead 2). PB1966 (landed)
made the reference-format AREAS count character positions, not UTF-16 code units; the COLUMN a diagnostic reports was
not unified with it.

**Repro:** a fixed-form line whose Area B holds a word or national literal with a supplementary-plane character
(for example U+1D400) ahead of a syntax error. A parser diagnostic (ANTLR's char index, mapped by the source map)
counts the supplementary character as two columns; a reference-format gate diagnostic on the same line counts it
as one. The two report different columns for one source position.

**Sites:** `src/Cobol.Net.Frontend/Preprocessor/ReferenceFormatProcessor.LogicalLineBuilder.cs:371` (`TextSite.Col`,
character positions through `CharacterPositions.PositionAt`) against `src/Cobol.Net.Frontend/Common/SourceLineMap.cs:73`
(`LineOrigin.Locate(int column)`, fed the parser's UTF-16 index).

**Fix shape:** one column unit for every diagnostic: the map converts the parser's code-unit index to a character
position (the PB1966 measure) before it reports, with a golden that puts a supplementary character ahead of both a
parser error and a gate error on one line.
