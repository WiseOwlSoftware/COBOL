# PB3582 — the script self-tests are git-process-bound on Windows

**Sites:** the code each hot self-test drives, per its own GIT_TRACE2: `scripts/orchestrator/landing_check.py`, `scripts/orchestrator/enqueue.py`, `scripts/devlog.py`, `scripts/prune_worktrees.py`, `scripts/guard-verify.sh` (and `scripts/guard-compiler.sh`), `scripts/orchestrator/orchestrate.ps1` and its `test_orchestrate_*.ps1` parts, `scripts/orchestrator/plan_wave.py`, `scripts/hooks/forbidden_commands.py`, `scripts/run_gate_legs.py`.

## Measured (merge group run 40004159292, the same commit on both runners)

Sum of the per-self-test times: Windows 1,444 s over 95 self-tests, Linux 144 s over 81. The ones that run on both:

| self-test | Windows CI | Linux CI |
|---|---|---|
| scripts/prune_worktrees.py | 168.3 s | 7.2 s |
| scripts/guard-verify.sh | 148.7 s | 8.4 s |
| scripts/orchestrator/landing_check.py | 127.4 s | 3.2 s |
| scripts/orchestrator/enqueue.py | 62.9 s | 2.7 s |
| scripts/devlog.py | 47.2 s | 1.9 s |
| scripts/orchestrator/test_plan_wave.py | 36.6 s | 13.0 s |
| scripts/hooks/test_forbidden_commands.py | 33.8 s | 14.5 s |
| scripts/line_endings.py | 10.1 s | 0.2 s |

The Windows-only `scripts/orchestrator/test_orchestrate_*.ps1` parts add about 560 s (steer 131, stop 124, startup 61,
ledger 54, campaign 49, …).

## The mechanism (measured)

`GIT_TRACE2` over `prune_worktrees.py --self-test`: **4,636 git processes**, 1,746 of them one `merge-base
--is-ancestor <sha> <sha>` per (candidate, carrier) pair (PB3583, fixed). A Windows process start costs tens of
milliseconds where Linux pays about one, so a self-test that drives git thousands of times is bounded by process
creation, not by its own logic. The ratio above (20 to 50 times) is that cost, not slow Python.

## What remains

Trace each remaining hot self-test the same way (`GIT_TRACE2=<file>`, count ` start ` lines by subcommand) and remove
the per-item git calls in the code under test: one `for-each-ref`/`rev-list`/`cat-file --batch` over many objects
instead of one process per object. Code under test first (it is the loop's and the session probe's runtime too), then
the fixtures (PB3584). Measure on CI's `windows-self-tests` job (PB3581), never on a loaded local host.
