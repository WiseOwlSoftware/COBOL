# PB3582 — the script self-tests are git-process-bound on Windows

**Sites:** the code each hot self-test drives, per its own GIT_TRACE2: `scripts/orchestrator/landing_check.py`, `scripts/orchestrator/enqueue.py`, `scripts/devlog.py`, `scripts/prune_worktrees.py`, `scripts/guard-verify.sh` (and `scripts/guard-compiler.sh`), `scripts/orchestrator/orchestrate.ps1` and its `test_orchestrate_*.ps1` parts, `scripts/orchestrator/plan_wave.py`, `scripts/hooks/forbidden_commands.py`, `scripts/run_gate_legs.py`.

## Measured (merge group run 40004159292, the same commit on both runners)

Sum of the per-self-test times: Windows 1,444 s over 95 self-tests, Linux 144 s over 81. The ones that run on both:

| self-test | Windows CI | Linux CI |
|---|---|---|
| scripts/prune_worktrees.py | 168.3 s | 7.2 s |
| scripts/guard-verify.sh | 148.7 s | 8.4 s |
| scripts/orchestrator/landing_check.py | 127.4 s | 3.2 s |
| scripts/orchestrator/enqueue.py | 62.9 s | 2.7 s |
| scripts/devlog.py | 47.2 s | 1.9 s |
| scripts/orchestrator/test_plan_wave.py | 36.6 s | 13.0 s |
| scripts/hooks/test_forbidden_commands.py | 33.8 s | 14.5 s |
| scripts/line_endings.py | 10.1 s | 0.2 s |

The Windows-only `scripts/orchestrator/test_orchestrate_*.ps1` parts add about 560 s (steer 131, stop 124, startup 61,
ledger 54, campaign 49, …).

## The mechanism (measured)

`GIT_TRACE2` over `prune_worktrees.py --self-test`: **4,636 git processes**, 1,746 of them one `merge-base
--is-ancestor <sha> <sha>` per (candidate, carrier) pair (PB3583, fixed). A Windows process start costs tens of
milliseconds where Linux pays about one, so a self-test that drives git thousands of times is bounded by process
creation, not by its own logic. The ratio above (20 to 50 times) is that cost, not slow Python.

## What remains

Trace each remaining hot self-test the same way (`GIT_TRACE2=<file>`, count ` start ` lines by subcommand) and remove
the per-item git calls in the code under test: one `for-each-ref`/`rev-list`/`cat-file --batch` over many objects
instead of one process per object. Code under test first (it is the loop's and the session probe's runtime too), then
the fixtures (PB3584). Measure on CI's `windows-self-tests` job (PB3581), never on a loaded local host.

## Landing (wave 20261025, group A2)

**Re-probe** (GIT_TRACE2 over each self-test on this branch, counting git `start` events; wall time on this loaded
host is no measure): `prune_worktrees.py` 3,048 git processes, `landing_check.py` 1,471, `enqueue.py` 646, `devlog.py`
363, `line_endings.py` 51, `test_plan_wave.py` 42, `run_gate_legs.py` 65. Four of the note's hot self-tests are NOT
git-bound: `guard-verify.sh` (0 git processes; bash forks), `hooks/test_forbidden_commands.py` (0; a Python process per
case), `guard-compiler.sh` (0), and the `test_orchestrate_*.ps1` parts (17 to 82 each; pwsh starts). Their Windows time
is another mechanism (non-git process starts), returned as leads, not fixed here.

**The fix.** `scripts/git_batch.py`, one git process per question kind: `Ancestry` (one `cat-file --batch-check`
resolve, one `git log --format=%H %T %ct %P%x00%s --stdin <tips> --not <base>`; `on_base`, `beyond`, `is_ancestor`,
`parents`, `tree`, `subject`, `time`, `newest_first`, `base_tree`, `extend`), `diff_names` / `diff_patches`
(`diff-tree --stdin --always --root` over `<commit> <parent>` pairs), `object_ids`, `resolve`; each takes the
caller's runner (`git=`) so a self-test's fake answers the batched commands. Moved onto it:
- `prune_worktrees.survey`: one `for-each-ref` (tips, last commits), one graph (`branch_graph`) for MERGED, ahead,
  `review_holds` / `unreviewed_since`, `contained`, `carrying_findings`; `mechanical` batched (parents and trees from
  the graph, one `diff-tree --stdin` for every one-parent commit); `merges_to_main_unchanged` reads main's tree once;
  `worktree_git_dir` reads the `.git` file (no `rev-parse --absolute-git-dir`); `review_coverage` one lazy graph.
- `landing_check.check`: `commit_work` through two batched diffs, `work_notes` subjects and `first_commit_time` from the
  graph, `depends` and the contained-ancestor test from the graph, `contained` and `existed` through `object_ids`.
- `plan_wave.inflight_file_sets`: one `--no-optional-locks status -z` per worktree (was `diff HEAD` + `ls-files`),
  HEAD from `worktree list --porcelain`, one `for-each-ref --no-merged` for the loose branches, `_still_differs` as one
  merge base per commit plus ONE `diff-tree --stdin`; `local_branches` gives the classifier, `branch_carrier`,
  `add_closed_notes` and `unlanded_branch_notes` one graph (no pairwise `merge-base`, no `git log` per branch);
  `next_unit.fresh_unlanded` one graph.
- `enqueue`: `worktree_state` (one `status --porcelain=v2 --branch -z`: branch, HEAD, dirty).
- `devlog`: `listing` (`ls-tree <rev>^{commit}`, no `rev-parse --verify`), no `git show` without a monolith.

**Measured after** (same counting): prune 1,246, landing_check 846, enqueue 510, devlog 286 (all self-tests GREEN;
plan_wave 338/338). CI's `windows-self-tests` job (PB3581) gives the wall time once this lands.

**For the next implementer.**
- `scripts/git_batch.py#Ancestry`: REUSE for any ancestry, count-ahead or subject question over many branches; read it
  once a pass (`Ancestry.read`, `extend`) and pass it down. `on_base`/`beyond` hold only for tips it read; `is_ancestor`
  asks git only when the ancestor is on the base. Trap: `diff-tree --stdin` takes hex ids only, never a ref name.
- `scripts/git_batch.py#diff_names`: `--always` is what makes the blocks line up with the pairs; a root commit's pair
  is `(commit, EMPTY_TREE)`.
- `scripts/prune_worktrees.py#classify`: takes the graph (`branch_graph`); every caller builds one for all its branches.
- `scripts/orchestrator/plan_wave.py#inflight_file_sets`: the fake git in `test_plan_wave.py` answers the batched
  shapes (status `-z`, `for-each-ref --no-merged`, `diff-tree --stdin` from its stdin); change both together.
- `tests/Cobol.Net.Tests.Unit/GitBatchDriftTests.cs`: no `merge-base --is-ancestor`, `rev-list --count` or `log -1` in
  the survey, landing check or planner code outside self-tests (`drop_remote` excepted).
