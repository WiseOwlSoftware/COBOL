# PB6165 — LANDED — 1985-GR-VII.4.3.4-5 is CHANGED into 2023, not KEPT

The record said KEPT with the reason "(41, §2023:9.1.13.7 GR1, as in 1985) ... Every reopen sequence both editions accept behaves
the same". Under PB6161 that is not so: 1985's "file" is "the physical file regardless of the file-name used in the COBOL program"
(§1985:II.2), so the OPEN through a second file-name of a file the run unit holds open is 41 (§1985:VII.1.3.5), while 2023 keys 41 to
the file connector (§2023:9.1.13.7 GR1) and arbitrates the second connector by the sharing facility (§2023:9.1.15).

Fixed on PB6161's branch: one `record_verdicts --edition 1985` record makes the change record CHANGED (same `to` rows, the reason
above) and gives the row its own verdict, CONFORMS, with code-location `FileRegistry.SharedOpenAttempt` and
`FileRegistry.RefusedAsAlreadyOpen`; its code read was re-read on the branch (reader and refuter) and imported with `--replace`.
