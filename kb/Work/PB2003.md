# PB2003 — the downstream-stage directives skip their syntax check in an omitted branch

Lead from wave 1018 group C (PB1363 / PB1364 / PB1367 / PB806, landed by train 1018, DEVLOG 1878), filed by the
train-1018 lander.

## The rule

§7.2.1: "The following elements and the separators required to distinguish them shall be syntactically correct in the
initial source text and library text:", and compiler directives are among them
(`cite.py --check 7.2.1 "syntactically correct in the initial source text and library text"` → OK). The false path of
an IF or EVALUATE directive is part of that text, so a malformed directive there is as malformed as in a compiled
branch.

## What happens

Group C made `ConditionalCompilationProcessor.Run.Render` check every directive line's operand in every branch, and
the IF / EVALUATE / WHEN / DEFINE / DISPLAY arms parse (without evaluating) their operands in an omitted branch. The
directives whose operand a DOWNSTREAM stage parses were left out: the catalog row is a declared no-op for them, the
default arm consumes the line in an omitted branch (`if (!emitting) emit = "";`), and the stage that would parse the
operand never sees it.

Repros (`E:\COBOL-coord\scratch\w1018c\p\`, fixed form, default `--std`):

- `c1.cob`: `>>IF 1 = 2` / `>>TURN GARBAGE ON` / `>>END-IF` → rc 0 (the same line compiled is COBOLNET0718).
- `c2.cob`: `>>FLAG-14 GARBAGE` in the omitted branch → rc 0 (compiled: COBOLNET1622).
- `c3.cob`: `>>COBOL-WORDS GARBAGE` → rc 0 (compiled: COBOLNET1623).
- `c5.cob`: `>>FLAG-02 GARBAGE` → rc 0 (compiled: COBOLNET1622).

## Code sites

- `src/Cobol.Net.Frontend/Preprocessor/ConditionalCompilationProcessor.cs:452` — the default arm,
  `if (!emitting) emit = "";`.
- `src/Cobol.Net.Frontend/Preprocessor/TurnDirectiveProcessor.cs:66` — `ParseTurn`.
- `src/Cobol.Net.Frontend/Preprocessor/FlagDirective.cs:172` — `FlagDirectiveLine.TryParse` (called from
  `ConditionalCompilationProcessor.cs:461`).
- `src/Cobol.Net.Frontend/Preprocessor/CobolWordsDirectiveProcessor.cs:118` — `TryParseOption` (reads the DEFINE
  timeline through `definitions.DefinitionAt`).

## Fix shape

Each of the three stages needs a check-only entry the conditional-compilation driver can call on an omitted line: it
parses the operand and reports a syntax violation without applying anything. COBOL-WORDS is the awkward one because its
option parse reads the compilation-variable timeline. The drift test
`CompilerDirectiveCatalogDriftTests.EveryClosedOperandDirective_IsCheckedInAnOmittedBranchToo` derives its cases from
the catalog rows; extend it to the Stage rows once they are checked, so the complement it prints becomes empty.

## Why group C did not fix it

It needs a check-only seam in three stages, one of which reads the DEFINE timeline. That was too large for the slice.
