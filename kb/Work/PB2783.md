# PB2783 — test-only census findings are never filed or re-checked

**Found by** the wave 1043 F implementer (PB2200), filed by the train-1043 lander.

**What.** `scripts/arch/file_census_notes.py` deliberately files no `test-only-family` or `test-only-type` finding
(`NOT_FILED`, about :110: "NEEDS-OPUS: 'only tests use it' is a judgment"). That is right for the judgment, but nothing
re-examines those findings later. Census R0-0088 at a02b165da classified `CopyProcessor.Process(string, string)` as
test-only: its one caller was the legacy `tests/CobolSharp.Tests.Unit/Preprocessor/FixedFormTests.cs:69`. The legacy
test tree was then deleted with the legacy engine (PHASE 15 Cut 2), which made `Process` fully unreferenced, yet no note existed for it; only
PB2200's sibling sweep found it. PB2200's branch deletes it with the string-only helpers it alone kept alive
(`worktree-wf_2ca5e648-fef-6`; train 1043 could not land it, see PB2679's train-1043 occurrence).

**Code site.** `scripts/arch/file_census_notes.py` `NOT_FILED` (about :110); the census classes in
`scripts/arch/census.py` / `tools/ArchCensus`.

**Fix direction.** Either re-run the census after any deletion of a test tree (the newer census reclassifies such a
member as `unreferenced`, which IS filed), or route the test-only findings to a judgment role (Opus) that decides,
per finding, "a test-only seam that should stay" versus "dead product code with a test", and files the latter as Delete
notes. Then sweep the current census's test-only findings once for members whose test callers are gone.

**Repro.** In the a02b165da census record, find R0-0088 (`test-only-family`, `CopyProcessor.Process`); on the tree
before train 1043, `git grep -n "\.Process(" -- src tests` found no `CopyProcessor` caller.
