# PB78 — LANDED 2026-08-18 — `OBJECT-COMPUTER. PROGRAM COLLATING SEQUENCE IS REV.` was a parse error (`unexpected 'PROGRAM'`)

**Landed (2026-08-18, DEVLOG 1313).** `objectComputerParagraph : OBJECT_COMPUTER DOT ((computerName computerAttributes?)?
objectComputerClause* DOT)?` — the name optional, the clauses (`programCollatingSequenceClause |
characterClassificationClause`) any order, each at most once (a duplicate → COBOLNET1652). The '85 attribute sink stays
BEHIND the name (reachable without one it swallowed the next paragraph header — the first cut proved it) and stops at
CHARACTER as well as PROGRAM. The name-less clause form is the 2002 relaxation: `computer-name-optional-2002` (0900 below
2002, `VisitObjectComputerParagraph`; X3.23-1985 hung MEMORY SIZE / PROGRAM COLLATING SEQUENCE / SEGMENT-LIMIT off a
required name — the empty paragraph was legal there). CHARACTER CLASSIFICATION (`CHARACTER {classificationAhead()}?
cobolWord …` — CLASSIFICATION is a plain word) is parsed so it can be diagnosed: COBOLNET1518, A.4.9 item 7 documented
non-support, the LOCALE clause's shape; its words are exempt from the §8.9 funnel (SYSTEM-DEFAULT drew a false 0901
first). `SOURCE-COMPUTER.` keeps the same shape (`((computerName computerAttributes?)? DOT)?`); the legacy oracle reads the
clause list. GnuCOBOL: accepts the name-less form (its grammar has `OBJECT-COMPUTER. [WORD] [clauses]`). Measured: golden
`pb78_object_computer_optional_name` (SOURCE-COMPUTER. / OBJECT-COMPUTER. PROGRAM COLLATING SEQUENCE IS REV → PCS=REV);
negatives `pb78-object-computer-clause-without-name-85` (0900), `-character-classification` (1518, exactly one
diagnostic), `-duplicate-clause` (1652). Verdicts FMT-12.3.6.2, FMT-12.3.5.2, SR-12.3.6.3-4, SR-12.3.5.3-1,
GR-12.3.6.4-1/-2/-3/-4/-6/-9/-11 → CONFORMS, GR-12.3.6.4-5/-7/-8 → DOCUMENTED-NON-SUPPORT (GAP 4003 → 3989).
**Sibling registered as [[PB92]]:** the SET LOCALE formats 11/12 (A.4.9 item 9) are still 1639/0901 noise or a parse
error, not the 1518 disposition.

**Measured repro** (`--std 2023`): an OBJECT-COMPUTER paragraph whose first word after the period is a clause
(`PROGRAM COLLATING SEQUENCE …`, or `CHARACTER CLASSIFICATION …`) with no computer-name-1 → `COBOL0001:
unexpected 'PROGRAM'`. §12.3.6.2's general format is `OBJECT-COMPUTER. [ computer-name-1 ] ⎡ | character-
classification-clause | program-collating-sequence-clause | ⎤ .` — computer-name-1 is bracketed OPTIONAL and the
clauses may follow it directly (the figure notes confirm the reading). Every existing golden writes a name
(`OBJECT-COMPUTER. XX PROGRAM COLLATING SEQUENCE AL.`), which is why the restriction never surfaced.

**Mechanism:** `CobolParserCore.g4` `objectComputerParagraph: OBJECT_COMPUTER DOT (computerName
computerAttributes? programCollatingSequenceClause? DOT)?` — the whole optional group is anchored on
`computerName`. `sourceComputerParagraph` has the same shape (`SOURCE-COMPUTER. WITH DEBUGGING MODE.` without a
name — check §12.3.5.2's bracketing before changing it: its format is `SOURCE-COMPUTER. [ computer-name-1 ] .`
with the DEBUGGING MODE clause hanging off computer-name-1 in some editions).
**Fix shape:** make computer-name-1 optional before the clause set at the editions whose format has it
optional (2023 certainly; 2002/2014 — read their formats; COBOL-85 REQUIRED the name — X3.23-1985's
`OBJECT-COMPUTER. computer-name [MEMORY SIZE …] [PROGRAM COLLATING SEQUENCE …] [SEGMENT-LIMIT …]` — so the
name-less form needs the introduction gate + a VCR row + `constructs.json` row + the edition-gate sweep (the
`new-construct` skill), never a bare grammar loosening. Also admit CHARACTER CLASSIFICATION (an §A.4.9 locale
element — diagnose it as documented non-support like the LOCALE clause, never a parse error). Survey GnuCOBOL.
