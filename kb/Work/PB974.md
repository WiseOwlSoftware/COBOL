## Reproduced

`reg11/i3as.cob`: a class `R11ASBOX` with one method, and a program whose repository says
`CLASS BOXY AS "R11ASBOX".`, then `01 B USAGE OBJECT REFERENCE BOXY.` `INVOKE BOXY "NEW" RETURNING B` →
**`i3as.cob(17,23): error COBOLNET0901: 'AS' is a reserved word in COBOL-2023 and cannot be used as a user-defined
word (ISO §8.9)`**. Expected: BOXY binds to the class whose externalized name is `R11ASBOX` and the program prints
`SHOWN`.

## Rule

The transcription's §12.3.8.2 diagrams print, with their figure notes, `CLASS object-class-name-1 [ AS literal-1 ]`,
`INTERFACE interface-name-2 [ AS literal-2 ]`, `PROGRAM program-prototype-name-1 [ AS literal-3 ]` ("`AS` … underlined
in the printed standard"), and the property and user-defined-function specifiers carry literal-5 (see GR2's list).
The fixer renders the printed page (`scripts/render-spec-page.py`) before writing the grammar, per CLAUDE.md rule 1.

- `python scripts/spec/cite.py --check 12.3.8.4 "If the AS phrase is specified, literal-1, literal-2, literal-3, or literal-5 is the externalized name"` → OK §12.3.8.4 2)

§12.3.8.4 GR2 also says "The implementor shall specify when the AS phrase is required" — the fixer checks
CONFORMANCE.md's Annex A register for that row while in the clause.

## What the fixer owes

- The grammar arm for each of the four specifiers (pre-authorized), sharing ONE `asPhrase` production with PROGRAM
  (landed PB237/PB303) rather than four copies.
- Binding: the externalized name the specifier's literal gives is what resolution matches (the class-name in the
  source is only the local name) — the same two-name model §12.3.8.4 GR10 gives the PROGRAM specifier.
- Goldens at 2002 (class, interface) and at the property / user-function specifiers' introducing editions, and the
  `EXPANDS` phrase after `AS` (the class-specifier diagram places `AS` before `EXPANDS`).

## Landed (wave 51 group D)

Re-probed on the implementer's own build: `i3as.cob` COBOLNET0901 on `AS`; after the fix it prints `SHOWN`. The
printed §12.3.8.2 (PDF p334-335 / folios 304-305) carries `[ AS literal-n ]` on all five externalized specifiers, AS
before the class and interface specifiers' EXPANDS phrase.

- **Grammar:** the ONE `externalizedNamePhrase` on the class, interface, property and user-defined-function
  specifiers (PROGRAM already had it, PB237). ⛔ **Sibling found by rendering the same page:** the
  intrinsic-function-specifier is `FUNCTION { intrinsic-function-name-1 } … INTRINSIC` and the grammar took ONE name —
  `FUNCTION PI E INTRINSIC` died COBOL0307. Now `FUNCTION functionName+ INTRINSIC`; the binder registers every name.
- **One screen:** `DataBinder.BindSpecifierExternalizedName` — §12.3.8.3 SR2 (the literal's class, the one
  `ExternalizedName.Screen`) and SR1 (a repeated name specified identically) for all five kinds, COBOLNET1761 (its
  description generalized from the program specifier). `BindProgramSpecifier` now calls it.
- **Resolution, each at its consumer:** class / interface — `OoRepositoryScope` is now a map declared word →
  externalized name (read by the pure `ExternalizedName.Peek`), and `OoNameResolution.Lookup` finds the definition by
  `OoClassTable.FindByExternalizedName` when a literal was written; a USAGE OBJECT REFERENCE descriptor carries the
  RESOLVED class's name so every descriptor re-lookup still hits the group table. Function —
  `BinderDriver.UserFunctionsOf` (the `ProgramPrototypesOf` twin, §12.3.8.4 GR11 NOTE 2) maps the local name to the
  group function whose externalized name is literal-5. Property — `OoRepositoryProperties` maps property-name-1 →
  literal-4, and `OoTryBindPropertyReference` looks the accessors up under it (§12.3.8.3 SR16 a)).
- **DOC-A.1-163** ("when the AS phrase is required", GR2's last sentence): determination written into
  `docs/CONFORMANCE.md` §7 — never required; `audit_annex_a1.py --check` clean.
- Golden `2002/pb974_repository_as_phrase` (class, interface, property, function each reached ONLY through the literal
  — every definition is declared with a different word — plus `FUNCTION PI E INTRINSIC`); negative
  `pb974-repository-class-as-zero-length` (COBOLNET1761 — SR2 forbids the zero-length literal-1 that CLASS-ID's own
  §11.3.3 SR1 allows). Rows FMT-12.3.8.2, GR-12.3.8.4-2, SR-12.3.8.3-2, DOC-A.1-163 GAP → CONFORMS. SR-12.3.8.3-1 stays
  open: "identical" also covers a repeated class specifier's EXPANDS phrase, which is not compared.
