# PB1982 — OPEN: the Guard job sets the wall time of every code-change CI run

Owner 2026-10-04: "Why does the CI Guard take so long? I thought we previously optimized it?" (the earlier optimization is
`scripts/guard-fast.sh`: the 364-program NIST suite runs across cores in 332 isolated groups derived from the declared chain graph, and
the exact per-program audit is kept).

## Measured (13 code-change runs on `ci/*` branches, 2026-10-03 to 2026-10-04; `gh api .../actions/runs/<id>/jobs`)

Guard job seconds: 750, 531, 547, 705, 712, 522, 712, 526, 717, 740, 408, 740, 748. Run wall time is about the guard plus 20 s (9 to
13 minutes); the next-slowest job (Windows conformance corpus-nist) is 240 to 490 s and everything else is under 360 s. The distribution
is bimodal (about 520-550 s and 705-750 s) and did not change when CI moved from `ubuntu-latest` to the pinned `ubuntu-26.04`
(2026-10-04 18:32), so it follows the runner host, not the commit: in the slow run the unchanged legacy unit tests took 7 s against 2 s and the
integration tests 39 s against 25 s.

Inside a slow run (job 111541886846): self-tests 2 s, build 69 s, NIST compile and grouped run 661 s (`JOBS=4 compile=4 run=4`),
unit 7 s and integration 39 s running alongside. Average cost about 3.8 CPU-seconds per NIST program on the runner; the same leg runs in
about 75-95 s in the local Linux gate (32 cores).

## Options (profile first; none is built)

1. **Profile one NIST program**: how much of its 3.8 CPU-seconds is process, .NET and Roslyn start-up against the compile and the run.
   If the warm-up dominates, compile many programs in ONE process (a batch mode of the `cobol` CLI) and keep the per-group isolation of
   the RUN step.
2. **Shard the NIST step** across two or three CI jobs with a merge job that runs the exact-population audit over the union
   (`test_population.py`); needs the audit to accept partial verdict lists per shard.
3. **Check the runner's cores against the hard-coded `JOBS=4`** (`nproc` on the job).
4. **Larger runners** are a billing decision (note A14).

Wall time only: agents blocked on CI cost almost no tokens, but every landing waits on it. Related: [[PB1957]], [[A14]].
