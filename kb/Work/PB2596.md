# PB2596 — one validated operator steering path for the loop's next unit

## Facts (verified by the operator 2026-10-08)

- `scripts/orchestrator/orchestrate.ps1:90` sets `$LastHandoff = handoff.last.json`; `:415` passes ONLY `$LastHandoff`
  to `next_unit.py`; `:447` deletes `handoff.json` at every unit start.
- `docs/rearchitecture/DESIGN-orchestrator-loop.md:57` lists `handoff.last.json` as written by the supervisor and
  documents no operator steering path.
- 2026-10-07 23:50 PDT the operator wrote its instruction (run a wave; hold push-main) into `handoff.json`: silently
  ignored. `handoff.last.json` still held the supervisor-synthesized handoff of a failed `meter` unit (`next_unit:
  resume`), so at the 23:53 restart a `resume` unit ran, and its handoff named a `land` unit (23:57) that would have
  raced the operator's R2 lander at push-main. The operator stopped both by hand and then wrote `handoff.last.json`
  directly.

## Harm

The attended operator has no way to tell the loop what to run next. A hand-written file is ignored without a word
(silent), and the only workaround (overwriting `handoff.last.json`) is lost the moment a running unit ends and the
supervisor copies its handoff over it. The loop then runs a unit the operator explicitly did not want, here one that
would have raced an attended landing on main.

## Done

ONE validated operator steering path: a command that writes the operator's handoff where the next unit reads it,
validated against `handoff.schema.json`, with a stated precedence over a supervisor-synthesized handoff; documented in
the design doc's operator section; a test in `test_orchestrate.ps1`; and no second way left (CLAUDE.md rule 4: delete
or redirect whatever wrote `handoff.json` for the operator).

## Landed (branch w1038t-loop-control, wave 1038 group T)

Re-probed first on the worktree: a coordination dir holding the operator's `handoff.json` (`next_unit: wave`) and a
synthesized `handoff.last.json` (`next_unit: resume`) made `orchestrate.ps1 -DryRun` say `would run unit 'resume'`.

- ONE path: `scripts/orchestrator/steer.ps1 -Unit <unit> -Reason <why> [-Summary <instruction>]` writes
  `<coord>\handoff.operator.json` (`unit: operator`, `outcome: done`, `next_unit`, `next_unit_reason`, `summary`),
  validated with `Test-Json` against `handoff.schema.json` (which now admits unit `operator` and requires its
  `next_unit` and reason) and written atomically; `-Show`, `-Withdraw`; `stop.ps1 -Status` shows it, `-Clear` keeps it.
- Precedence: `next_unit.py --operator-handoff` is rule 0, ahead of the last handoff (synthesized or not), an unanswered
  owner question and every deterministic check; its JSON carries `operator: true`.
- `orchestrate.ps1` validates the steer again before passing it (a hand-edited invalid one is moved to
  `logs\<time>-handoff.operator.invalid.json` and said), and when the chosen unit starts archives it as
  `logs\<time>-<unit>.handoff.operator.json` and moves it to `handoff.last.json`, so the unit reads the instruction as
  `{PREV_HANDOFF}`; a steer written while a unit runs survives that unit's handoff.
- No second way: `-Unit` is written through `steer.ps1` (a dry run uses a temporary file it removes); the
  first-iteration bypass of `next_unit.py` is gone; a `handoff.json` present when a unit starts (the 23:50 hand edit) is
  archived as `.handoff.orphan.json` with a log line instead of being deleted in silence.
- Docs: `DESIGN-orchestrator-loop.md` section 4.8 (new; 4.7 is the landing lease), sections 2, 3.2, 4 and 5; the workstream SKILL; DOC_INDEX.
- Tests: `test_orchestrate.ps1` section 10 (validation and refusal, precedence over a synthesized handoff, a steer
  written mid-unit beating that unit's `land`, consumption and archive, the unit reading it, an orphan `handoff.json`,
  an invalid steer set aside, `-Unit` as a steer, a dry run leaving nothing, rule 0 over an owner question).
- For the next implementer: `scripts/orchestrator/steer.ps1` is the only writer of `handoff.operator.json` (reuse it,
  `-OutFile` is the seam); `scripts/orchestrator/next_unit.py#choose` owns the precedence (rule 0, `operator` arg) and
  `#read_handoff` reads both files; `orchestrate.ps1` consumes the steer next to the orphan check before `Invoke-Unit`.
  Trap: `test_orchestrate.ps1` takes about 25 minutes (each case starts pwsh and python several times), so probe one
  case with a scratch script first.

**Train 1039b review (lander).** A `campaign` steer with no campaign lane was rewritten to a wave without its `operator` flag, so it was never consumed and rule 0 chose it on every later iteration; the replacement keeps the flag (`test_orchestrate_steer.ps1`).
