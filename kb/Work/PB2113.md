# PB2113 — D10, the SUBSCRIPT lexer-mode removal (R69 unblocks it)

## Landed (wave 1029, group C) — D10's first half

**§9.4 resolved from the spec, Option A.** ISO §8.3.5 1) "The COBOL character space is a separator" and 2) "The COBOL
characters comma and semicolon, immediately followed by a space, are separators that may be used anywhere the separator
space is used" (`cite.py --check 8.3.5` OK, both): space-separated subscript and argument lists are legal, so a scoped
lexer assist is unavoidable — but no lexer MODE. Recorded in DESIGN-frontend-grammar §9.4 with the mechanism as built.

**Mechanism.** `CobolLexer.g4`: `mode SUBSCRIPT` and every `SUB_*` token are deleted. The '(' after a
data-name-capable word (the same `PreviousTokenCouldBeDataName` trigger) is the virtual token `REF_LPAREN`, its ')'
`REF_RPAREN`; the paren stack (`_parenRegions`) marks it a LIST REGION like a FUNCTION argument list, where the §8.3.5
2) separator survives as `FNARG_SEPARATOR` and a sign touching its digits after a separator is `SIGNED_INTEGERLIT` /
`SIGNED_DECIMALLIT` (§8.3.3.3.2 2), §8.7.1). Grammar: `subscriptPart : REF_LPAREN subscriptList? REF_RPAREN`,
`subscriptItem : ALL | functionArgument`; `refModPart` accepts `REF_LPAREN`; `refModSpec`'s leftmost position is
optional so COBOLNET2876 still names `X (:2)`. Binder: `ReferenceResolver.SegmentsOf` (one segment per parsed item,
PB136's declaration-informed cut asked of the tree) replaces `SplitSubscriptTokens`; `HasDepth0Colon`, the captured
ref-mod reader and `ReadCapturedLiterals` are deleted; `IntrinsicBinder.ArgumentsOf` binds the keyword-omitted
arguments from the parse (`FunctionArgFragment`, `functionArgListFragment`, `PrimeFunctionArgs` deleted); the
`FlagConformancePass`, `ExpressionFormationPass`, `SearchAllFormat2Rules`, report-subscript, constant-entry and
object-property readers read nodes. `ParenTokenTwinDriftTests` now requires every plain-paren site to consider BOTH
twins (FNARG_ and REF_).

**Proof.** Every program of the D10.1 corpus (`85/pb2113_subscript_list_separators`,
`2002/pb2113_subscript_expressions_and_arguments`, `negative/pb2113-keyword-omitted-arguments-85`) gives the same
output on the pre-change compiler (main d5fc9c998's build) and this one; the whole-population gate and the Linux gate
are in the wave-1029 report. `scripts/arch/compare_oracle.py` was not on main when this started (wave 1026's), so the
emitted-C# oracle comparison is OWED; the gate is the proof here.

**Behaviour changes, each spec-correct:** `X (- - 2)` is now refused by §8.8.1.2 Table 3 (COBOLNET1719 — kb/Work
PB1968, landed with this); `X ((I -1))` is refused as two juxtaposed operands, as `MAX((A -1))` always was; a bare
`X(1,2)` reads `1,2` as the comma-decimal literal it is (§8.3.5 2): no space, no separator) instead of two subscripts.

**Remaining (D10's second half, not this note):** subscript and ref-mod positions still reach the code generator as
the transitional string carrier (`RenderSegment`, the D18 `subscriptExpressionFragment` text re-parse); moving them
onto `BoundExpr` deletes both (DESIGN-frontend-grammar §9 status).

The owner's D10 ruling (plan §6 D10): FULLY remove the lexer `SUBSCRIPT` mode (`CobolLexer.g4` line 1275, `SUB_LPAREN`
at line 1338, 35 grammar lines) and the binder's subscript re-parse (about 250 lines of hand-rolled C#), replacing
them with interpreted grammar rules. It could not land while the legacy compiler consumed `SUB_*` /
`SubscriptEntryContext`; PB2110 deleted that consumer.

Implement FROM `docs/rearchitecture/DESIGN-frontend-grammar.md` §9, including the §9.4 ISO §8.3.5 space-separator
decision the executing implementer must resolve first (from the spec, cited and checked with `cite.py --check`).
**Prerequisite:** PB2110 landed. **Model:** Opus (grammar is design-heavy; `model_rules.json` routes it).

## Rules

- The token-stream differential (the PB1715 form) and the parse-tree shape differential over every lexer input the
  suites use are the neutrality proof for a grammar change (DESIGN-architecture-review §4 item 3), beside the
  whole-population gate.
- `LexerDfaCacheDriftTests`: no left-edge semantic predicate in a lexer mode.
- The §9.5 D10.1 corpus (subscripts, reference modification, space-separated arguments, nested FUNCTION) ships with
  the change as goldens.
- Every citation mechanically checked; the design doc corrected in the same change where implementation proves it
  wrong (rule 5).
