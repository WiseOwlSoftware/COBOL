# PB478 — OPEN — the register checks the label on the box, never whether the box is empty

Found 2026-09-04 by the `PB473` implementer, whose first act was to read its contract and find it ended at
"Made to fail once, with the compare block verbatim (…):" — everything from the reproduction onward, including
the seven-item fix contract, was absent. The implementer restored the body from the attribution report (that
restoration lands with PB473). Re-derived on this tree: `kb/Work/PB473.md` on `main` is 53 lines and its last
line is that fragment.

## How it happened

The orchestrator filed the note by extracting the "READY-TO-FILE" section of
`scratchpad/reports/IF141A-attribution.md`: it located the opening ```` ```markdown ```` fence and cut at the
FIRST following ```` ``` ````. The note body carries its own fenced code blocks, so the first closing fence
found was the note's INNER one, and the copy stopped there. The filing then ran `python scripts/spec/work.py
check` and got `✓ 529 work items, all well-formed` — which was true of what it checks.

## Why nothing noticed

`scripts/spec/work.py check` parses each note's frontmatter (`id`, `kind`, `status`, `severity`, the harm
flags, `inventory_rows`, `blocked_by`) and validates those. It never reads the body. A note whose body is
empty, ends mid-sentence, or has an unbalanced code fence is "well-formed". The same is true of
`gen_conformance_notes.py` and of `work.py next`, which rank on the frontmatter alone — so the truncated note
sat at the top of `Fix next` with a contract nobody could execute, and only a reader found it.

## Fix shape

Two layers, both mechanical. (1) `work.py check` validates BODY STRUCTURE per note: the file ends with a
newline; code fences are balanced; the last non-blank line is neither a heading, a table header, a line ending
in `:` or `(`, nor a bare fence; and a `kind: defect` or `kind: analysis` note has at least one `## ` section
after the title heading. Each rule gets a fixture note that fails it (`feedback_prove_the_watchdog_fails`).
(2) Any script that FILES a note from a larger document asserts what it extracted — the closing fence it cut
at is the one that matches the opening fence's nesting, and the extracted body's line count is reported beside
the source section's — so the filing tool, not the next reader, is the first to notice.
