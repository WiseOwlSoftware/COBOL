# PB5534 - docs/CONFORMANCE.md section 8's heading and comments in SpecTraceabilityInventoryDriftTests.cs still call the derivations owner-signed

**Sites:** `docs/CONFORMANCE.md` line 5067 (`## 8. Rules with no observable obligation - owner-signed derivations (§2023:4.4 / Annex A.2)`); `tests/WiseOwl.Cobol.Tests.RepoDrift/SpecTraceabilityInventoryDriftTests.cs` lines 120, 167, 444, 781 and 1355 (lines 1418, 1478 and 1481 say "owner-signed" of a determination).

**State on main (checked 2026-11-14).** `docs/conformance/` does not exist on origin/main: PB5395's split is not landed, so `docs/CONFORMANCE.md` is still the single source file and the heading is in it. PB5373 already changed one message (`record_verdicts.py`'s derivation-closure message no longer says owner-signed), which left these places saying a different thing.

**Mechanism.** The label "owner-signed" is stale: a §8 derivation closes a rule on a recorded derivation checked by `cite.py` and a refuter, not on an owner signature. The heading is a parser key (`derivation.heading` in the inventory schema), so renaming it is a schema change: the heading, the schema's key, every reader of it and the generated views move together. A comment-only edit would leave the key saying the old word.

**Fix direction.** Rename the heading and the schema's `derivation.heading` in one change, update the test comments, and sweep `owner-signed` across `scripts/` and `docs/`. After PB5395 lands the heading lives in the `docs/conformance/` source, not in the generated view, so doing this after that landing avoids a second move.

**Found by.** PB5373's lane, report `w20262028a-PB5373-report.md`.
