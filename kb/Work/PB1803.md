# PB1803 — OPEN

Found 2026-09-30 by the reference-format research agent (tree 4a1dda60e) while mapping every raw-line consumer for
PB1800. Read from code; the harm is narrow (the markers are never valid COBOL, so this only turns a diagnostic into
silence), but it is exactly the "every leniency is dialect-gated" breach PB1494 fixed for the column-7 letters.

**Code site.** `src/Cobol.Net.Frontend/Pipeline/Frontend.cs#Normalize` calls
`src/Cobol.Net.Frontend/Preprocessor/ReferenceFormatProcessor.cs#StripNistArchiveMarkers` unconditionally (so do the
legacy `src/CobolSharp.Compiler/Compilation.cs:339` and `src/CobolSharp.CLI/Program.cs:131`); the method tests
`line.TrimStart().StartsWith("*HEADER,")` / `"*END-OF,"`, so it matches in any reference format and at any column.

**Rule.** §6.3.3 "The indicator area identifies the type of a source line in accordance with the indicators specified
in 6.2.2" (`cite.py --check 6.3.3` OK): a fixed-form line `*HEADER,COBOL,SM102A` has `R` in column 7, not a fixed
indicator — COBOLNET2616 outside `--nist`; in free form the line is program text that does not parse.

**Repro to write.** A fixed-form program (no `--nist`) with the line `*HEADER,COBOL,X` before IDENTIFICATION DIVISION:
expected COBOLNET2616 (column 7 holds `R`); observed (by reading) compiles clean.

**Fix.** Fold the strip into the ONE line-entry stage (PB1800 `PhysicalLines.Read(…, ccvsIndicators)`) and apply it
only when `ccvsIndicators` (the `--nist` dialect — `Frontend` already passes `NistTestName is not null`); delete
`StripNistArchiveMarkers` and change its three callers (the legacy oracle keeps it on, as it keeps `ccvsIndicators`).
Negative golden: the repro above at `--std 2023`; the NIST corpus (newcob.val members) stays green under `--nist`.
Half slot; rides PB1800.
