# PB4527 — group-sign-clause-ignored-in-add: SIGN clause on a group: ADD reads a subordinate item's separate sign wrongly (-5 + 12 gives 75)

Filed 2026-11-03 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-batch-3000-20261103`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

When the SIGN clause is written on a group (`01 G SIGN IS TRAILING SEPARATE CHARACTER.`), a subordinate `PIC S9(3)` item
is stored and displayed correctly, and MOVE reads it correctly, but `ADD item TO x` with a `SIGN LEADING SEPARATE`
receiver reads it wrongly: -5 added to 12 gives 75. The receiver's own SIGN clause does not matter (a plain `PIC S9(3)`
receiver also gets 75). Writing the same SIGN clause on the elementary item gives 7.

## Minimal test case

Free reference format (`-free`).
```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. GRPSIGN2.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 WS-GRP SIGN IS TRAILING SEPARATE CHARACTER.
   05 WS-A PIC S9(3) VALUE -5.
01 WS-B PIC S9(3) SIGN IS LEADING SEPARATE VALUE 12.
01 WS-C PIC S9(3) VALUE 0.
PROCEDURE DIVISION.
    DISPLAY "A [" WS-A "] GRP [" WS-GRP "]"
    ADD WS-A TO WS-B
    DISPLAY "B [" WS-B "]"
    MOVE WS-A TO WS-C
    DISPLAY "C [" WS-C "]"
    ADD 1 TO WS-A
    DISPLAY "GRP [" WS-GRP "]"
    STOP RUN.
```

## Environment

cobc (GnuCOBOL) 3.2.0 on WSL2 Ubuntu. `cobc -x -free -std=cobol2014 -o p prog.cob && ./p`.

## Observed result

```
A [005-] GRP [005-]
B [+075]
C [-005]
GRP [004-]
```
Exit code 0.

## Expected result (per ISO)

§13.18.52.4 rule 1 (2014, 2023): the SIGN clause specifies the sign's position and representation "for the
numeric item to which it applies, or for each numeric item subordinate to the group to which it applies". Rule 7: "If
a SIGN clause applies to such an item and conversion is necessary for purposes of computation or comparisons, conversion
takes place automatically." WS-A is -5 with a trailing separate sign, so 12 + (-5) = 7. Expected:
```
A [005-] GRP [005-]
B [+007]
C [-005]
GRP [004-]
```
With `SIGN TRAILING SEPARATE` written on WS-A itself (and none on the group), cobc prints `B [+007]`.

## Our compiler

WiseOwl COBOL (fresh judge) prints the expected output above.

## Fix site

Not located precisely. cobc/field.c `validate_pic` copies a parent's `flag_sign_separate` / `flag_sign_leading` to a
numeric child that has neither (the loop over `f->parent`), and `cb_build_field_tree` also copies the parent's flags; the ADD code generation in cobc/typeck.c (`cb_build_add` and
the DISPLAY-arithmetic optimisations, which compare these flags, for example in the same-picture test near
`flag_sign_separate == field_2->flag_sign_separate`) appears to see the child's flags before or without that inheritance.
Read observationally in a 3.3-dev tree.

the numeric item shows `+` and three spaces).
