# PB4931 - fuzz_batch does not use the restartable batch state

**Sites:** `scripts/fuzz_batch.py` (`submit`, `collect`, `client_for`), `scripts/spec/message_batches.py` (`BatchRun`, the restartable state this tool should use)

**Report (process harm only).** PB4886 moved the restartable batch state out of `transcribe_pdf.py` into `scripts/spec/message_batches.py` as `BatchRun` (an INTENT record written before
`create`, adopted on the next run if the process dies between the create and the state write; `collect` takes each ended batch; usage keyed per billed reply),
and `audit_batch.py` and `transcribe_pdf.py` use it. `scripts/fuzz_batch.py` (`submit`, `collect`) still creates a batch and later collects one reply file
per batch with no intent record: a crash between `create` and the reply file loses track of a BILLED batch (money, not just time), and the same account rule
(`api_key.read_run_key`, PB4916) must hold through the shared state. Expected: `fuzz_batch` runs on `BatchRun` like its siblings (one mechanism per job; no
copy), with its self-test planting a crash after create, adopted on resume. Per the "one mechanism" rule the fixer deletes `fuzz_batch`'s own state handling in the
same change. Not probed.
