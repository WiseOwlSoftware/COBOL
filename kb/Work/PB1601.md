# PB1601 - LANDED (wave 20261501 E)

## Landed 2026-10-25 (wave 20261501 E, with PB1615)

**Re-probe (w20261501e build).** `COPY "CB1.cpy".` and `COPY CB1 SUPPRESS PRINTING.` compiled clean at `--std 85`, 2002 and 2014 (probes `c1.cob`, `c2.cob`): the note reproduced. Neither phrase is in the NIST CCVS-85 suite (`grep` over `tests/nist`: no `COPY "..."`, no SUPPRESS but message text).

**Edition evidence (derived, VCR row 7.44).** `cite.py --check 7.2.3.2 "SUPPRESS"` OK (the general format prints `literal-1`, `literal-2` and `[ SUPPRESS PRINTING ]`); 7.2.3.3 SR4, SR5 and 7.2.3.4 GR1, GR4 OK. The repo holds no 1985, 2002 or 2014 text, so the edge is derived as the note's adjudication states: absent from ANSI X3.23-1985 (CCVS-85 usage; Micro Focus marks both as dialect extensions, not ANS85), present by 2014 (Annex E lists neither), put at 2002, the edition that rewrote COPY as a compiler-directing statement (row 7.33's partial-word phrases are of the same rewrite). The row says so in one line, so it can be overturned in one line.

**Fix.** One gate method, `CopyProcessor.GateCopyPhrase`, asking `ConstructRegistry.Check` for constructs rows `copy-literal-name-2002` (asked by `ReadCopyName` for every literal written as text-name-1/literal-1 or library-name-1/literal-2) and `copy-suppress-2002` (asked by `ParseCopyStatement`): COBOLNET0900 below 2002, an error under `--permissive` too (the version matrix's introduction theory samples both rows at every edition). A name written as a WORD is 1985's own form and is never gated.

**Goldens.** Positives: `7.2.2.5-Text-words/pb1354_copy_header_2002` (both phrases, now naming both constructs) and the new `wiseowl/cases/7.2.3-COPY/pb1355_library_text_literal` (a literal name holding a period, accepted 2002+). Negatives `pb1601-copy-literal-name-below-2002`, `pb1601-copy-suppress-below-2002` (COBOLNET0900 at 85). Sibling found and fixed: `wiseowl/cases/7.2.3-COPY/pb1355_library_text_located` (accept [85]) wrote `COPY "pb1355c.txt"` and would have been refused at 85; its literal leg moved to the new 2002 case, the 85 case keeps its three word legs.

**Siblings swept.** `grep` over `tests` and `conformance-suite` for `COPY "`, `COPY '` and SUPPRESS: the only other literal-name users are accepted at 2002+ (`pb82_exception_location_source_line` [2023], `l1c03_cobol_words_directing_unaffected` [2023]); the unit tests run at the 2023 default. The REPLACING phrase's own edition gates (`OperandScreen.PartialWord`, `OnNonPseudoTextOperand`) are the other arm of the statement and were already gated.

**Merge-queue bounce (PR #602, run 40237769279).** The sweep's `grep` for `COPY "` missed the C#-escaped form `COPY \"`: `DiagnosticPositionTests` compiles two COBOL-85 units that wrote `COPY \"dbg.cpy\"` (PB2490) and `COPY \"nc.cpy\"` (PB2986), and the gate refused the first (COBOLNET0900, both conformance `rest` shards). Both now name their library text by a WORD (`COPY DBG`, `COPY NC`, the 1985 form) and assert no COBOLNET0900. A re-sweep for `COPY \"`, `COPY ""` and `COPY '` in every `.cs` under `tests` and `src` found no other unit below 2002.
