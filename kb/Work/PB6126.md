# PB6126 - the unified power-rule screen lost the operand values in its messages

`src/WiseOwl.Cobol.Runtime/Values/Numeric/CobolPower.cs:31` `ScreenRule6(bool, bool, bool, bool)` takes four booleans, so its texts cannot
name the operands. The deleted `CobolIntrinsics.CheckPowRule6` said "a zero base requires an exponent greater than zero, not {e}" and "a
negative base ({b}) requires an integer exponent, not {e}". At run time `0 ** -1` or `(-2) ** 0.5` now reports the rule but not which operand
broke it.

**Fix.** Pass the base and exponent (or their formatted text) to the screen so the message names them, with a test of both texts.

**Sites:** `src/WiseOwl.Cobol.Runtime/Values/Numeric/CobolPower.cs` (`ScreenRule6`, `Classify`, `Rule6Error`, `Binary64(double, CobolExact)`), `src/WiseOwl.Cobol.Runtime/Values/Numeric/CobolDec.cs` (`PowDeveloped`), `tests/WiseOwl.Cobol.Tests.Unit/PowerRule6MessageTests.cs`.

**Landed.** `ScreenRule6` now has a binary64 and a standard-decimal overload that classify the refusal once and name the base and exponent in the message, formed only on refusal; the COBOL-85 refusal formats invariantly.
