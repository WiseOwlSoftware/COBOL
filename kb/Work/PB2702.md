**Found by the train 1042b lander** (2026-10-08): its whole-population gate (`build-local.ps1 -Mode lander`, run
`20261008T184406Z-f9dda0`) ran every Conformance, Unit and Characterization case green and still printed
`=== BUILD-LOCAL GATE: RED — SELF-TESTS RED`, on one case:
`FAIL: expected PASS: attended session, the loop's STOP-UNIT present: Workflow passes` (24/25).

**Mechanism.** `scripts/hooks/test_dispatch_guard.py` built its base environment as `dict(os.environ, ...)`. Its
STOP-UNIT cases choose the session kind themselves (`UNIT_ENV` adds `COBOL_LOOP_UNIT`; the "attended session" case
uses the base `ENV` without it), but the base inherited the CALLER's `COBOL_LOOP_UNIT`. The land unit runs its lander
with `COBOL_LOOP_UNIT=land`, so the "attended" case was a loop unit, the hook (correctly, rule 0 of PB2597) refused the
Workflow, and the self-test went red. `env -u COBOL_LOOP_UNIT python scripts/hooks/test_dispatch_guard.py`: 25/25.
CI never sets the variable, so CI could not see it: the hole is local-only, and every lander the loop dispatches
would have hit it.

**Fix (train 1042b).** The base `ENV` drops `COBOL_LOOP_UNIT` from the inherited environment, so each case's session
kind is the one the case names. Sweep: the other files that read `COBOL_LOOP_UNIT` (`dispatch_guard.py`, `coord.py`,
`orchestrate.ps1`, `test_orchestrate_stop.ps1`, `testdata/fake-claude.ps1`) are the producers and the supervisor's own
tests, which set it explicitly; every other self-test in the same gate run was green under the inherited variable.
