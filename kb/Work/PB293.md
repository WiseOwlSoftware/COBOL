# PB293 — the split-key form refuses by accident, not by determination

Split out of [[PB144]] when its (A) leniency-gate and (B) indexed-DELETE-coverage halves landed with cluster E.
This half was deliberately **not** started there. It is the single note for the RECORD KEY / ALTERNATE RECORD KEY
`SOURCE`-phrase witness debt: cluster E raised it from the grammar side, and the module-witness sweep reached the
same construct independently from the Annex A.3 side. **Do not open a second note for it.**

## ⛔ The premise inverts on the spec — this is not an undetected gap

The finding this came from reads as "the split prime-key form has no grammar and `IndexedConnector` models one
contiguous slice", i.e. a missing feature. **The standard says otherwise.** `cite.py --check A.3` confirms item
40: *"The capability of specifying the SOURCE phrase of the RECORD KEY clause and ALTERNATE RECORD KEY clause is
dependent on the capabilities of the processor."* It is a **processor-dependent** element — optional for a
conforming implementation — and `docs/CONFORMANCE.md` row 40 **already records it as Not claimed**. A sweep of
Annex E.2/E.3 finds no entry for it, so no edition gate is implicated either.

## What is actually defective: the refusal has no name

`CobolIO.g4`'s `recordKeyClause` and `alternateKeyClause` carry only the `data-name-1` alternative. `SOURCE` is a
hard lexer token and is **not** in the `cobolWord` alternation, so `RECORD KEY IS K SOURCE IS A B` consumes
`RECORD KEY IS K` and then `SOURCE` matches no `fileControlClauses` alternative — not even the
`vendorFileControlClause` wildcard sink, which requires IDENTIFIER. The result is a raw ANTLR syntax error at
`SOURCE`.

So the refusal is **loud** (not a silent mis-bind — that worse hypothesis is ruled out) but **anonymous**: it
names a token, not the determination. The tree's own precedent shows the required shape — `DataBinder.cs`'s
CODE-SET refusal under `COBOLNET1672` names *"Annex A §A.3 item 27 — documented non-support"*.

## ⛔ The posture is SETTLED: stand on the A.3 item 40 non-support; no owner question is opened

The earlier draft of this note ended with a bare owner question — *provide the SOURCE split-key form, or stand on
the documented non-support?* **That question is withdrawn and must not be re-asked.** Under the owner-decision
protocol (`feedback_owner_decision_protocol`, 2026-08-30) an owner-reserved question is only opened for a
*significant consideration*; here the standard itself grants the standing-pat position, `CONFORMANCE.md` row 40
already records it, and the surveyed implementations do not force the other way. Nothing about the compiler's
conformance claim turns on the answer, so there is nothing significant to reserve.

What providing it *would* cost is recorded here only so a future proposal does not have to re-derive it, **not**
as a proposal: a record key would become a LIST of windows end-to-end — `FileModel`'s key model,
`KeyedIoEmitter.EmitRegistration`, `RuntimeApi.FileRegisterIndexed`/`FileAddAlternateKey`, `IndexedConnector`'s
`_primeOff`/`_primeLen`/`_alts` and `KeyOf`, plus `RecordLayout.KeyIndexByPosition` (which matches by STORAGE
POSITION and cannot express a concatenation, and is what READ … KEY and START … KEY resolve through), plus
§8.3.2.2.24's `record-key-name` word class, §8.4.6.2.4's scope rule, and the §12.4.5.7 Format-2 key-level
COLLATING SEQUENCE seam. The single-window case would become a one-element list, so the contiguous key would stop
being a special shape; a parallel split-key path beside the scalar one would be the two-mechanisms anti-pattern.

## The debt, therefore, is exactly the NAMED refusal

1. Widen both clauses to PARSE the SOURCE form as a superset (grammar changes are pre-authorized), so the
   construct is recognised rather than tripped over; register both in `constructs.json`.
2. Refuse at BIND with a new diagnostic modelled on `COBOLNET1672`, naming §12.4.5.12 / §12.4.5.6 and
   *"Annex A §A.3 item 40 — documented non-support"*.
3. ⚠ Correct the `CONFORMANCE.md` row-40 citation: it reads **"13.x"**, a placeholder. The clauses are
   §12.4.5.12 and §12.4.5.6 (both `--check`ed). This is the inherited-citation failure mode and it is mechanical
   to fix.
4. Negatives for **both** clauses — `record-key-source-split` and `alternate-key-source-split`. ⚠ The original
   finding named only the prime key; §A.3 item 40 and §12.4.5.6.2 cover both clauses in one sentence, so a fix
   touching only `recordKeyClause` is the two-arm defect shape repeating.

## Follow-on measurement — RUN, and it found a worse sibling

Cluster E left this as "a measurement to run" for the other A.3 *Not claimed* rows. The A.4.8/A.4.13
module-witness sweep ran it independently and reached this same construct from the Annex A.3 side, confirming the
mechanism above: `RECORD KEY … SOURCE IS` has **no grammar surface at all**, so the user gets an unnamed ANTLR
parse error rather than the determination `CONFORMANCE.md` §2 row 40 has already made. Two things the sweep adds:

- **This is the BETTER of the two shapes a declined element can have here.** Its sibling, item 26
  (`RECORD DELIMITER IS STANDARD-1`), is *worse*: it parses, binds, and **runs clean with no diagnostic at all**
  — registered as [[PB292]]. Loud-but-anonymous is a naming debt; silent-accept contradicts §4.2.6 ¶3's
  mandatory warning mechanism outright. Fix order should follow that, not the note order.
- **The posture A.4.8 had before witness cluster A is exactly this one**, which is why the fix shape is now
  settled rather than open: A.4.8's clauses had no surface either, the refusal was an unnamed syntax error, and
  the answer was a parse surface plus one `EditionContext.Declined` call on a descriptor naming the Annex item.
  That seam exists on main now, so this note's step 2 is no longer a design question — only work.

⚠ Row 40's `13.x` citation placeholder is one of **five** in `CONFORMANCE.md` §2 (rows 5, 12, 13, 26, 40);
[[PB292]] carries the sweep.
