# PB704 — LANDED — an OPTIONAL word of the format that the grammar treated as a name

Found 2026-09-05 by the `PB678` implementer (report §"New defects" N1) while writing its SORT goldens: any SORT
with the phrase, at `--std 2002/2014/2023`, draws `error COBOLNET0901: 'ORDER' is a reserved word in COBOL-2002 and
cannot be used as a user-defined word (ISO §8.9)`. It compiles at `--std 85`, where ORDER is not yet reserved.

## The rule

§14.9.40.2 (`cite.py --check 14.9.40.2 "DUPLICATES"` → OK; the format prints `[ WITH DUPLICATES IN ORDER ]`, DUPLICATES
underlined) and MERGE's §14.9.24.2 twin make ORDER a required word of the phrase; §8.9 (`--check 8.9 "ORDER"` → OK)
reserves it from 2002. A reserved word appearing in its own general format is not a user-defined word. The phrase is
the only way a program can demand §14.9.40.4 GR3's release-order tie-break over GR4's undefined order.

## The mechanism

`src/Cobol.Net.Frontend/Grammar/Core/CobolIO.g4` ≈725: `sortDuplicatesPhrase : WITH? DUPLICATES IN? cobolWord?` with
the comment "cobolWord matches ORDER (not a lexer token)"; it parses, then the reserved-word screen refuses the
matched `cobolWord`. Same family as [[PB693]] (a reserved word admitted to the name slot unguarded — there the word IS
a token; here it is not one at all) and [[PB655]]/[[PB657]] (the reserved-word funnel's reach).

## Fix

An ORDER token in this position (the lexer/`cobol-words.json` row with the 2002 reservation, `reservationGated` so
the 85 lane keeps accepting it as a name elsewhere — PB693's drift test then covers it), or an exemption at the
screen for a word matched inside its own format; the token is the honest shape. Sweep (rule 4): every other
general-format position where a RESERVED word is spelled as `cobolWord` in the grammar — `grep -n "cobolWord" src/
Cobol.Net.Frontend/Grammar/Core/*.g4` against §8.9's list — and pin each with a positive golden at 2002+ and the 85
behaviour measured. A positive golden with `WITH DUPLICATES IN ORDER` whose expected order is GR3's (records equal on
every key in release order), at 2002 and 2023.

## Landed 2026-09-06 — ORDER is a lexer token, and the sweep that missed it had the wrong axis

**Reproduced first, on the fix branch's own build**, before anything was changed: `sortdup.cob(24,35): error
COBOLNET0901: 'ORDER' is a reserved word in COBOL-2002 …` at 2002, 2014 and 2023; clean at 85. Column 35 is
the word ORDER.

### The rule, RE-DERIVED and MEASURED (not inherited)

The note said ORDER is a **required** word of the phrase. **It is not.** The printed general format was
rendered from the licensed PDF (Format 1 and Format 2 both print the line) and the underline rules were
measured against each word's bounding box: of `[ WITH DUPLICATES IN ORDER ]` **only DUPLICATES carries an
underline**, so WITH, IN and ORDER are all OPTIONAL words (§5.2.3) and all eight subsets are conforming
spellings. The transcription is faithful here. `--check 14.9.40.2 "DUPLICATES"` → OK; `--check 14.9.40.4 "the
order in which these records are released by an input procedure"` → OK §14.9.40.4 3) b); `--check 5.2.3
"optional words"` → OK; `--check 8.3.2.1 "Reserved words shall not be used as user-defined words"` → OK.

**The note's "MERGE's §14.9.24.2 twin" does NOT hold.** §14.9.24.2 has no DUPLICATES phrase at all (the
phrase appears on exactly two PDF pages, both SORT), and `mergeStatement` already omits it. Nothing to fix
there.

### The mechanism, corrected

The note (and `DESIGN-frontend-grammar.md`) said ORDER "has NO lexer token, arrives as IDENTIFIER, and no gate
can reach it". The second half was never measured and is FALSE: the reservation GATE inside `cobolWord` cannot
reach an IDENTIFIER, but the §8.9 **funnel** can — `VersionConformancePass.VisitCobolWord`'s
`CheckedTokenTypes` holds `IDENTIFIER` and screens it POSITION-BLIND, exactly because the 2023 additions all
lex as IDENTIFIER. Having no token is not safety; it is the same defect by the other route
(`feedback_reachability_is_measured_not_deduced`). The remedy in place was a HAND LIST of per-site exemptions
inside that funnel — LOCALE clause, ORDER TABLE slot [0], ALPHABET `IS LOCALE`, PICTURE LOCALE, CHARACTER
CLASSIFICATION, SET LOCALE, `CALL … AS NESTED`, the declined constructs — and SORT's ORDER was simply never
added to it (`feedback_two_arm_dispatch`: the same word ORDER got its ORDER TABLE arm patched at PB101 and its
SORT arm left).

### The fix (root, in the borrowing rule — never an exemption)

- `Grammar/Core/CobolLexer.g4` — `ORDER : 'ORDER' ;`.
- `tests/version-matrix/cobol-words.json` — an ORDER row (`nameSlot`, `subscriptTrigger`), regenerated through
  `gen-cobol-words.ps1` into `CobolWords.g4` (`{userWordHere("ORDER")}? ORDER` + the inverse-gated
  `reservedGatedWord` twin) and `CobolLexerWordSet.g.cs`. The FORMAT precedent exactly: the reservation gate is
  DERIVED from `reserved-words.json`, so `01 ORDER PIC X.` stays legal at 85 and draws COBOLNET0901 at 2002+
  with no hand-written list anywhere.
- `Grammar/Core/CobolIO.g4` — `sortDuplicatesPhrase : WITH? DUPLICATES IN? ORDER?`. This also ends an
  UNDER-rejection the name slot allowed: `WITH DUPLICATES IN <any word>` no longer parses.
- `Grammar/Core/CobolSpecialNames.g4` — `orderTableClause : ORDER TABLE cobolWord IS? literal` (both keywords
  are underlined on the printed page). `orderTableAhead()` is DELETED from `CobolParserCoreBase`, and
  `DataBinder.OrderTableBind` now reads the clause's ONE `cobolWord` (ordering-name-1) instead of slot [1].
- `VersionConformancePass.VisitCobolWord` — the ORDER TABLE exemption is DELETED. Neither ORDER position
  reaches the funnel any more, and its absence is commented as the point.

### The sweep (`feedback_scan_all_similar`), re-run on the CURRENT grammar with the RIGHT axis

PB693's finisher swept on "is §8.9-reserved AND has a lexer token", which is why ORDER escaped. The axis is
"is the word §8.9-reserved at any edition", token or not. Of the words the grammar routes through `cobolWord`
as a KEYWORD, `reserved-words.json` reserves six: LOCALE, ORDER, COBOL, NESTED, SYSTEM-DEFAULT, USER-DEFAULT
(CLASSIFICATION, ATTRIBUTE, RELATION, NONE, RECEIVED, LC_*, UCS-4/UTF-8/UTF-16 are in no §8.9 list, so
`RejectsAt` is false and the funnel is inert on them). Every one of the six except ORDER already had a named
funnel exemption, and all of them were MEASURED at `--std 2023` on the fixed build — SPECIAL-NAMES LOCALE +
ALPHABET IS LOCALE + CHARACTER CLASSIFICATION IS SYSTEM-DEFAULT, PICTURE format 2 LOCALE, SET LOCALE formats
11/12, ENTRY-CONVENTION IS COBOL, CALL … AS NESTED, ORDER TABLE — **no COBOLNET0901 anywhere**. SORT
DUPLICATES was the only live one.

⚠ **The exemption list is still a hand list**, and therefore still the next PB704; the design doc now says so
and says why retiring it is a design change rather than a sweep (LOCALE must keep arriving as a bare word for
`IntrinsicBinder.KeywordWordOf`).
