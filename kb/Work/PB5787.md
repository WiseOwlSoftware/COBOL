# PB5787 - at --std 85 an unqualified LINAGE-COUNTER in a contained program is refused on a 2023 rule

**What is wrong.** An unqualified LINAGE-COUNTER in a contained program with no LINAGE file of its own, under containers at two levels that each declare a GLOBAL LINAGE file, is refused at `--std 85` (COBOL5997, citing §2023), while the containing program's own unqualified reference is accepted. It is an unswept sibling of the landed kb/Work PB5166. Each GLOBAL LINAGE file's LINAGE-COUNTER is a global name (X.4.2.4 GR1). SRL2.8 requires a qualifier only if more than one LINAGE file description is specified "in the source program", and a source program ends at its end program header (III.2), so D, which has none, need not qualify; X.1.3.8.2 GR1/GR3b.1 then resolve to the nearest container's (B's) counter. The compiler refuses D's reference (COBOL5997, citing §2023 at 85) while accepting B's unqualified reference beside A's global file: under the other reading of "source program" (the whole nest) B's must be refused, so the code fails under either reading. At 2023 both refusals are right (`§2023:8.4.2.2.3 SR8`: "may be referenced within the source element"), so the cause is (a).

**Sites:**
- `src/WiseOwl.Cobol.Compiler/Binding/CounterResolver.cs#LinageFileOf` (the pre-2014 arm narrows to the program's own LINAGE files only when it has some; with none it counts every visible one instead of taking the nearest declaring program's, as ReportOf does through Reports.NearestInScope)

**1985 rows this note blocks.** `1985-GR-X.4.2.4-1`. `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094), so the row is named here.

**2023 rows whose stored verdict is wrong.** None: the cause is (a), wrong at 85 only.
