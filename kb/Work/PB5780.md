# PB5780 - a reference-modified numeric item compares as a number

**Site:** `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/OperandText.cs#IsStringVisitor.Visit(BoundFieldOperand)` reads
`n.Place.Item.Pic?.Category`, the category of the INNER item, for every place. For a `RefModPlace` that is the numeric
item's own category, so `ConditionRenderer.RenderRelationalCore` takes the numeric arm. The category of a
reference-modified operand lives on `RefModPlace.CategoryOf` (kb/Work PB20); this predicate does not ask it.

**The rule.** §1985:IV.4.3.8.4.4 GR5: "When data-name-1 is specified, the unique data item has the same class and
category as that defined for the data item referenced by data-name-1 except that the categories numeric, numeric
edited, and alphanumeric edited are considered class and category alphanumeric."

```
python scripts/spec/cite.py --check "§1985:IV.4.3.8.4.4 GR5" "the categories numeric, numeric edited, and alphanumeric edited are considered class and category alphanumeric"
OK  §1985:IV.4.3.8.4.4 GR5  (4.3.8.4.4 General Rules)  the text is in GR5
python scripts/spec/cite.py --check "§1985:VI.6.3.1.1.2" "For nonnumeric operands, or one numeric and one nonnumeric operand, a comparison is made with respect to a specified collating sequence of characters"
OK  §1985:VI.6.3.1.1.2  (6.3.1.1.2 Comparison of Nonnumeric Operands)  the text is in the clause
```

So `N3 (1:3) = 5` compares an alphanumeric operand with an integer literal: the literal is treated as moved to an
alphanumeric item of its own size ("5"), and "005" is compared with "5  " after space padding (§1985:VI.6.3.1.1.2
item 1). The relation is false.

**Repro** (`E:/COBOL-coord/scratch/gl1985/lane1/run/g1985b-iv-4-3-concept-computer-independent/q1/q1.cob`; kept out
of the tree):

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. Q1.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 XX PIC X(3) VALUE "005".
       01 N3 PIC 9(3) VALUE 5.
       01 G.
           05 GN PIC 9(3) VALUE 5.
       01 W-X3 PIC X(3).
       PROCEDURE DIVISION.
       P1.
           IF XX = 5 DISPLAY "XX=5 YES" ELSE DISPLAY "XX=5 NO".
           IF N3 (1:3) = 5 DISPLAY "RM=5 YES" ELSE DISPLAY "RM=5 NO".
           IF N3 (2:2) = 5 DISPLAY "RM2=5 YES" ELSE DISPLAY "RM2=5 NO".
           IF G = 5 DISPLAY "G=5 YES" ELSE DISPLAY "G=5 NO".
           IF N3 (1:3) < 6 DISPLAY "RM<6 YES" ELSE DISPLAY "RM<6 NO".
           IF N3 (1:3) = N3 DISPLAY "RM=N3 YES" ELSE DISPLAY "RM=N3 NO".
           MOVE N3 (1:3) TO W-X3.
           IF W-X3 = 5 DISPLAY "WX=5 YES" ELSE DISPLAY "WX=5 NO".
           STOP RUN.
```

**Expected (from the 1985 text):** `XX=5 NO`, `RM=5 NO`, `RM2=5 NO`, `G=5 NO`, `RM<6 YES` ("005" against "6  ":
"0" precedes "6" in the native sequence, so the two arms agree here), `RM=N3 YES` ("005" with N3 moved to "005"),
`WX=5 NO`.

**Observed** at `--std 85` (and identically at `--std 2023`), `cobol.exe q1.cob --std 85 --run`, exit 0:
`XX=5 NO`, `RM=5 YES`, `RM2=5 YES`, `G=5 NO`, `RM<6 YES`, `RM=N3 YES`, `WX=5 NO`. The plain `PIC X(3)` operand, the
group and the moved copy compare as text; only the reference-modified operand compares by algebraic value. `RM2` shows
it plainly: "05" against "5 " is unequal.

**Not 85-specific.** §2023 states the same category rule for reference modification, and the 2023 run gives the same
wrong answer, so the 2023 rows of reference modification and of the relation condition that are recorded CONFORMS
deserve the re-probe PB5678's finding gave its 2023 row. The fix lands a 1985 golden for `1985-GR-IV.4.3.8.4.4-5`.
