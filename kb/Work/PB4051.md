# PB4051 — the landing lane's status counts and promises retries for branches that no longer exist

## Sites

- `scripts/orchestrator/land_lane.py#view` builds `Lane.latest` as the latest attempt of EVERY branch the lane ever recorded
  (`by_branch(attempts(cdir, unreadable)).values()`, each `atts[-1]` with `effective(atts)`). It consults neither the survey
  (`Lane.rows`) nor git.
- `scripts/orchestrator/land_lane.py#status_lines` counts `n` over `lane.latest` (the header's "N to retry" is `n[FREE] + n[ONCE]`)
  and prints one row per `lane.latest` entry with `ACTION[cls]` ("the lane retries it once at this head", "once what it waits on is
  free"). Those promises are false for a branch that is gone.
- `scripts/orchestrator/land_lane.py#drop_stale_rearms` drops a re-arm whose branch "left the survey" (`tips.get(branch) !=
  rec["head"]`, "no longer surveyed"); `status_lines` has no such check.
- Sibling readers of `lane.latest` with the same assumption: `land_lane.py#agent_work` (`landing`, `stopped`, `queued`: a STOPPED
  uncollected attempt of a deleted branch counts as the unit's work, and a DONE uncollected one as "landed by the lane, leads and
  records to complete"); the lookup near line 450 (`last = next((at for at, _ in lane.latest if at["branch"] == branch), None)`);
  and the list built near line 2241. `scripts/orchestrator/next_unit.py` reaches the lane only through `land_lane.agent_work` (about
  line 294), so it inherits the `agent_work` reading and has no count of its own.

## Witness (2026-10-29 ~19:00Z)

The header read "6 to retry". Three of those rows named branches that no longer exist (`git rev-parse --verify refs/heads/<b>` fails)
and that `scripts/prune_worktrees.py` does not survey:

- `impl-sonnet-default`, exit 2 REFUSED (uncommitted worktree path), attempt of 2026-10-27;
- `notes-fuzz6`, exit 2 REFUSED, attempt of 2026-10-27;
- `worktree-wf_e323943e-6df-4`, exit 13 REFUSED, a land-lock pid recorded on 2026-10-28.

Each prints "the lane retries it once at this head" or "once what it waits on is free". The lane never will: no branch, no candidate.
The same listing carries 426 historical DONE rows that bury the live ones; the enqueue unit filtered `[collected]` by hand to read it.

Reproduce: `python scripts/orchestrator/land_lane.py status | grep -v '\[collected\]'`, then `git rev-parse --verify refs/heads/<b>`.

## Consequence

An enqueue unit or the operator reads a stale retry as live work, or chases a lock pid that died days ago. `agent_work` can keep the
loop starting an enqueue unit for a stopped or uncollected attempt of a branch that is gone.

## Direction (not a fix)

Decide ONE definition of "an attempt the lane still owns" (branch present in the survey, or its attempt running) beside `view`, and
read `latest` through it in `status_lines`, `agent_work` and the sites above; keep a separate `--all` listing for history. Pair it
with a `--self-test` arm: an attempt of a branch absent from the survey is neither counted in "to retry" nor printed as RETRY-*.
