## Landed (wave 20262161, group A)

Re-probed at 3b5bca46e4 (main ddf3400a61 with PB2627, PB5709 and PB3227 replayed): the grammar spelled GLOBAL in four
rules (`globalClause`, the GLOBAL arm of `fileGlobalExternalClause`, `reportGlobalClause`, and `IS? GLOBAL` inline in
`constantEntryBody`) and EXTERNAL in two (`externalClause` and the EXTERNAL arm of the fused FD rule). The FD and the data
description entry each screened the EXTERNAL clause's `AS literal-1` with their own copy of the `ExternalizedName.Screen`
call, and §2023:13.18.22.4 GR5's default was written twice (`CobolNames.UpperFold(name)` at the FD,
`DataItem.ExternalizedRecordName` for a record). `OoDefinitionRules.GlobalClauseSites` carried one row per spelling with a
per-type `GLOBAL()` predicate, and `ClauseCardinalities.KindOfFileDescriptionClause` split the fused FD rule back into the two
printed brackets.

The fix: one `externalClause` and one `globalClause` rule. `fileDescriptionClause` references both, `reportDescriptionClause`
and `constantEntryBody` reference `globalClause`. `fileGlobalExternalClause`, `reportGlobalClause`,
`KindOfFileDescriptionClause` and the `ClauseList.KindOf` column it was the only user of are deleted, and a clause list's
element is now a `Type`. `GlobalClauseSites` keys on the HOST rule of the one `globalClause`; the drift test holds it equal to
the rules whose ATN calls `globalClause` and holds `globalClause` to be the only rule that matches the GLOBAL token (the USE
statement's GLOBAL phrase apart). The screen description entry, which already referenced `globalClause`, now has its own
SR1 c) row; before, the data-description row matched it and named it a data description entry. The EXTERNAL `AS literal-1` is
read by one method, `ExternalizedName.AsLiteralOf` (§2023:13.18.22.3 SR3), and GR5's default by one,
`ExternalizedName.OfExternalSubject`, for both hosts.

`VersionConformancePass.VisitGlobalClause` (F.2 item 61, the linkage-section GLOBAL) now asks that the host be a data
description clause, because the constant entry's GLOBAL reaches it too and a constant entry is not the item's subject.
