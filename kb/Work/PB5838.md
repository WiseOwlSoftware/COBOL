# PB5838 - an own verdict that comes from a read cannot close on a derivation, and the widening planner plans a rule whose stored row is already OK: lineage_reads.own_stored_errors and lineage_reads.unwitnessed do not read the row's state

**Sites:**
- `scripts/spec/lineage_reads.py#own_stored_errors` (refuses a stored own verdict whose rule's read decides own-verdict-from-pointer when it carries no test-ref)
- `scripts/spec/lineage_reads.py#unwitnessed` (plans every OWN_VERDICT_FROM_POINTER decision refused for evidence without reading the row's state)

Both come from the report of the implementer of kb/Work PB5822 (chained rows close on their own derivation), which found them while building that change (`lineage_reads.py` lines touched there: `bare_kept` only). Both are process-only: no compiled program's behavior changes.

1. **Own-verdict-from-read rows cannot close on a derivation.** `lineage_reads.py#own_stored_errors` refuses a stored own verdict whose rule's read decides own-verdict-from-pointer when it carries no test-ref ("an own verdict from a read carries no test-ref of its own"), even if a derivation closes it (`Schema.state_for` OK). Same root as (2). Process-only.
2. **The widening planner plans a rule that is already closed.** `lineage_reads.py#unwitnessed` plans every OWN_VERDICT_FROM_POINTER decision refused for evidence without reading the row's state, so a rule already closed in the store (on a test or a derivation) is still planned by `widen`. Asked by the coordinator: own-verdict rows closed on a derivation are NOT left out. Fix: skip a decision whose row state is OK.
