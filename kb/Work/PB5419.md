# PB5419 - at --std 85 a signed numeric literal compared with a group item is compared as its source text with the sign: IF G2 = -5 is true for G2 = '-5' and false for '5 ', where the literal is a group image of its digits as MOVE produces it

**Sites:**

- `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/ConditionRenderer.cs#ComparisonText`
- `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/OperandText.cs#AsItemSizeTemporary`

**Mechanism.** Opposite a group, the numeric operand is treated as though moved to a group of its own size in standard data format characters, and a numeric literal's size is its digit count. The generated code compares the group's image with the literal's source text: `CobolString.Compare(G2.AsImage(), "-5")`. A one-digit literal is a one-character image (padded with a space opposite a two-character group), which can never equal `-5`, yet the comparison is true for G2 = `-5`. The compiler's own `MOVE -5 TO G2` stores `5 `, so the comparison does not behave as the move. The refuter saw the same IF, nested in an ELSE, compile to `Compare(G2.AsImage(), "5")`, so the rendering also depends on context.
