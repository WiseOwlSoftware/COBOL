# PB675 — OPEN — a witness whose subject moved out from under it

Found 2026-09-05 by the train 9 lander while attributing the train's one red: `pb316_open_group_scope` printed
`REF-A=61` where its `.out` pinned `00`. The lander bisected it to PB321 and re-trued the golden inside PB321's commit,
correctly — F-SEED carries neither a SHARING nor a LOCK MODE clause, F-A declares `SHARING WITH NO OTHER`, and
§9.1.15 1) (`cite.py --check` OK: *"Associating this file connector with the physical file will be unsuccessful if
the physical file is currently open through other file connectors"*) makes '61' the conforming answer; the golden's
'00' was the hole PB321 closed. What the re-truing exposed is this note.

## The shape

[[PB316]] fixed the OPEN statement's repeated group as the bound tree's shape: a RETRY or SHARING phrase written
inside one `file-name` group must not leak into the next. Its golden proves that by opening a phrase-bearing file
and a phrase-less one in one statement and printing both statuses. Parts (3)/(4) (the SHARING phrase) and part (5)
(§14.9.27.3 SR8, at compile time) still discriminate their leaks. Parts (1)/(2) (the RETRY phrase) do not, since
[[PB321]]: before it, only a connector with a phrase was registered for arbitration, so a leaked RETRY registered
F-SEED and changed its status; now EVERY connector is arbitrated under the same UNDETERMINED implementor default, so
F-SEED's printed status is identical whether the phrase leaked or not. The pair is green for a reason unrelated to
what it asserts — the shape of a green test holding a gap open, here holding a *regression* open. The `.cob` header
says so (lines 49–54) but a header is not a register.

## Fix

Give the RETRY leak an observable consequence again, or move the assertion to where the shape lives. Two candidates,
pick by measuring: (a) make F-SEED's group carry a distinguishing clause (a `LOCK MODE` or a `SHARING` that an
inherited RETRY would interact with visibly — §14.9.27.4's RETRY rules decide what a leaked count would change), so a
leak prints a different status; (b) since the defect PB316 fixed is in the BOUND TREE, assert the bound shape
directly — `OpenGroupScopeDriftTests` already exists on the merged tree; extend it to the RETRY arm with a
two-group statement and assert `BoundOpenFile.Retry` per file. Do (b) in any case; do (a) only if the runtime effect
of a leaked RETRY is observable at all after PB321. Re-measure which inventory rows parts (1)/(2) were the witness for
(PB316's `inventory_rows`) and confirm each still has a discriminating witness; if not, that row is CONFORMS on a
vacuous test and goes back to test-needed until the new witness lands.
