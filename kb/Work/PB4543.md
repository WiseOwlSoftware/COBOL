# PB4543 — report-line-counter-after-page-footing: Report Writer: LINE-COUNTER is 1 after TERMINATE prints the page footing

Filed 2026-11-03 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-batch-3000-20261103`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

Report Writer: after TERMINATE prints the last page's page footing, LINE-COUNTER is 1 instead of the line number of the
page footing's last line. ISO keeps LINE-COUNTER at the line number of the last line printed; no page advance follows the
last page footing, so nothing resets it.

## Minimal test case

Free reference format (`-free`). The program writes the report to the file `lc.out`.
```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. LC.
ENVIRONMENT DIVISION.
INPUT-OUTPUT SECTION.
FILE-CONTROL.
SELECT F-RPT ASSIGN TO "lc.out".
DATA DIVISION.
FILE SECTION.
FD F-RPT REPORT IS R-ONE.
WORKING-STORAGE SECTION.
01 WS-AMT PIC 999 VALUE 7.
REPORT SECTION.
RD R-ONE
PAGE LIMIT IS 14 LINES HEADING 1 FIRST DETAIL 3 LAST DETAIL 10 FOOTING 12.
01 R-DET TYPE DETAIL LINE PLUS 1.
05 COLUMN 1 PIC 999 SOURCE WS-AMT.
01 R-PF TYPE PAGE FOOTING LINE 13.
05 COLUMN 1 PIC X(8) VALUE "PAGE FTR".
PROCEDURE DIVISION.
MAIN-PARA.
OPEN OUTPUT F-RPT
INITIATE R-ONE
GENERATE R-DET
DISPLAY "AFTER GENERATE LINE " LINE-COUNTER
TERMINATE R-ONE
DISPLAY "AFTER TERMINATE LINE " LINE-COUNTER
CLOSE F-RPT
STOP RUN.
```

## Environment

cobc (GnuCOBOL) 3.2.0 on WSL2 Ubuntu. `cobc -x -free -std=cobol2014 -o p lc.cob && ./p`. GnuCOBOL 3.3-dev.0 gives the
same result.

## Observed result

```
AFTER GENERATE LINE 0000000003
AFTER TERMINATE LINE 0000000001
```
Exit code 0. The report file is correct: the detail on line 3 and `PAGE FTR` on line 13.

## Expected result (per ISO)

§13.18.57.4 rule 6 f) (2014 and 2023): "The page footing, if defined, is printed as the last report group on each page
of the current report", so TERMINATE prints it on line 13. §8.4.3.15.4 rule 4: "The value of LINE-COUNTER after the
printing of a report group is the same as the line number of the last line printed". §8.4.3.15.4 rule 3 resets
LINE-COUNTER to zero only "whenever a page advance takes place", and none takes place after the
last page footing: a page advance is the sequence §14.9.16.4 rule 6 gives for a GENERATE whose page fit fails (page footing, advance to the next physical page,
"LINE-COUNTER is set to zero.", page heading), and no GENERATE follows the TERMINATE. Even if one were assumed, LINE-COUNTER
would be 0, never 1.
Expected:
```
AFTER GENERATE LINE 0000000003
AFTER TERMINATE LINE 0000000013
```

## Our compiler

WiseOwl COBOL (fresh judge) prints the expected output (`AFTER TERMINATE LINE 0000000013`), with the same report file.

## Fix site

libcob/reportio.c (read in the GnuCOBOL 3.2 release source (gnucobol-3.2.tar.xz)), function `do_page_footing`: after
`report_line_type` prints the page footing it moves `curr_line` to the end of the page (`def_lines`), or to 1 when the
footing already reached it, and `saveLineCounter` publishes that value as LINE-COUNTER. `cob_report_terminate` calls
`do_page_footing` last, so the program sees 1 (or the page length) instead of the footing's last line.
