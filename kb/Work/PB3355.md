# PB3355 — LANDED (wave 1120, group E) — class of a strong group outside an argument position

Filed 2026-10-18 by the clerk. Source: `E:\COBOL-coord\scratch\reports\w1112a-PB3192-report.md` "New defects" (branch
worktree-wf_fd382c69-29a-5, PR #202). Grep of kb/Work for `ScreenRangeOperands` and `CallBinder` with
strong/StrongTypeModel/alphanumeric found no open note. Related landed note: PB1901.

## Lead (semantic, not message text)
Outside a function argument, a strongly-typed group passes screens that need class alphanumeric, because `ClassOfItem`
answers alphanumeric (that answer is the §15.3 item 2 reading, which governs FUNCTION ARGUMENTS only, per PB1901). Examples:
- a CALL target: §14.9.4.3 SR1 ("Identifier-1 shall be defined as an alphanumeric, national, or program-pointer data
  item"), `CallBinder.cs` ~line 178 (a CANCEL target is the same shape; its clause was not re-derived here);
- an EVALUATE range whose other end is an alphanumeric item: §14.9.13.3 SR4 ("The two operands in a range-expression shall be
  of the same class ..."), `EvaluateBinder.ScreenRangeOperands`.
By §8.5.2.1 the class of a strongly-typed group is its type-name. Each citation above was run through `cite.py --check` on
2026-10-18 and read OK (§15.3 2, §8.5.2.1, §14.9.4.3 1, §14.9.13.3 4).

## Landed

**Adjudication (the question the note left).** §15.3 item 2 ("Strongly-typed group items are treated as though they were of
class and category alphanumeric, unless they are prohibited as arguments of a function") governs a FUNCTION ARGUMENT only;
every other position falls under §8.5.2.1 ("Both the class and the category of a strongly-typed group item are the type-name
specified in the TYPE clause"). Each citation re-run through `cite.py --check` on 2026-10-18. A second fact decided the CALL
shape: §8.5.2.1's closing sentence ("Use of the name of a data class or data category in the rules of COBOL refers to the
category unless class is specifically indicated") makes "an alphanumeric, national, or program-pointer data item" (§14.9.4.3
SR1), "an alphanumeric or national data item" (§14.9.5.3 SR1) and "an alphanumeric data item" (§13.18.12.3 SR2) CATEGORY rules,
the reading `ItemCategory` already holds for ASSIGN USING, FILE STATUS, the record keys and SET ... ADDRESS OF (PB337, PB850,
PB1417). §14.9.13.3 SR4 says "the same class" outright, so the range is a CLASS pair rule.

**Re-probed on this build.** `CALL V` and `CANCEL V` over a strongly-typed group compiled clean (CALL then read the group's
characters as a program-name at run time); a report `RD ... CODE IS V` over one compiled clean (a third arm of the same shape,
found by the sibling sweep). The EVALUATE range `WHEN V THRU Y` did not under-reject: the relation the range lowers to refused
it (COBOL1533), so the defect there was the missing SR4 diagnostic, not an accepted program.

**Fix.** CALL, CANCEL (`CallBinder.NameTargetRefusal`) and the CODE clause (`DataBinder.Reports`) ask `ItemCategory`, whose
alphanumeric-group definition excludes a strongly-typed and a variable-length group (§13.18.29.4 GR3); the refusal prints
`ItemCategory.Face(Place)` (new, and `SetBinder.AddressNameFace` is deleted for it: one face for the same refusal). The range
screen asks `IntrinsicArgumentRules.SameClass`, which takes a strongly-typed group to be of another operand's class only when
that operand is a strongly-typed group of the same type, so SR4 itself (COBOL2107) refuses V THRU alphanumeric and two
groups of two types. Consequence of the category reading, a determination: an alphanumeric-edited, numeric-edited,
national-edited and variable-length-group CALL / CANCEL / CODE operand is now refused too (before: accepted through class).
`StrongGroupClassScreenDriftTests` keeps `CobolClass.Alphanumeric` / `National` out of every Binding source that is not a
function-argument position or a listed lattice consumer.

**Sibling sweep (variant-analysis).** Mechanism: a rule worded in category or in class asked of the class lattice, whose
alphanumeric answer for a strongly-typed group is the argument reading. Queried every `ClassOf` / `ClassOfItem` / `ClassOfPlace` /
`CandidateClasses` consumer and every `CobolClass.Alphanumeric|National` mention: ARM-fixed CALL, CANCEL, CODE, the
range; the other arms already ask `ItemCategory` / `StrongTypeModel` (ASSIGN USING, FILE STATUS, record keys, INVOKE method name,
SET ... ADDRESS OF, STRING / UNSTRING, INSPECT identifier-1, ACCEPT, MOVE, the relation checkpoint) or are function-argument
positions. START's generic-key SR6 b) 2 (`RecordLayout.SameClassCategoryUsage`) has the same lattice read but is unreachable for
a strongly-typed operand: a strong group can be level 1 or sit inside a strong type, so a second record description sharing the
key's bytes is refused (COBOL1532) and a group inside the record covers at least the key (the identity arm, not SR6 b), takes it).

Goldens: refusals `pb3355-call-target-strong-group` (COBOL1681), `pb3355-cancel-target-strong-group` (COBOL1696),
`pb3355-code-identifier-strong-group` (COBOL2713), `pb3355-evaluate-range-strong-group-and-alphanumeric` and
`pb3355-evaluate-range-strong-groups-of-two-types` (COBOL2107), `pb3355-call-target-alphanumeric-edited` (COBOL1681);
accepted `pb3355_call_cancel_group_targets` (alphanumeric group CALL / CANCEL target, `COUNT=1` twice by §14.9.5.4 GR3) and
`pb3355_evaluate_range_same_type_strong_groups` (`BB=IN`, `ZZ=OUT`).
