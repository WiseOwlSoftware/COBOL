# PB3355 — class of a strong group outside an argument position

Filed 2026-10-18 by the clerk. Source: `E:\COBOL-coord\scratch\reports\w1112a-PB3192-report.md` "New defects" (branch
worktree-wf_fd382c69-29a-5, PR #202). Grep of kb/Work for `ScreenRangeOperands` and `CallBinder` with
strong/StrongTypeModel/alphanumeric found no open note. Related landed note: PB1901.

## Lead (semantic, not message text)
Outside a function argument, a strongly-typed group passes screens that need class alphanumeric, because `ClassOfItem`
answers alphanumeric (that answer is the §15.3 item 2 reading, which governs FUNCTION ARGUMENTS only, per PB1901). Examples:
- a CALL target: §14.9.4.3 SR1 ("Identifier-1 shall be defined as an alphanumeric, national, or program-pointer data
  item"), `CallBinder.cs` ~line 178 (a CANCEL target is the same shape; its clause was not re-derived here);
- an EVALUATE range whose other end is an alphanumeric item: §14.9.13.3 SR4 ("The two operands in a range-expression shall be
  of the same class ..."), `EvaluateBinder.ScreenRangeOperands`.
By §8.5.2.1 the class of a strongly-typed group is its type-name. Each citation above was run through `cite.py --check` on
2026-10-18 and read OK (§15.3 2, §8.5.2.1, §14.9.4.3 1, §14.9.13.3 4).

## Status
These need a SPEC ADJUDICATION before any fix: which positions fall under the §15.3 "treated as alphanumeric" rule and which
under §8.5.2.1. PB1901 refuted adding a new class member (it would reach `MoveTable16` and the relation gates and REJECT
legal source); its consumers must ask `StrongTypeModel`.
