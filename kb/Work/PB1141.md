## Measured (adjudicator / refuter evidence, verbatim)
### GR-14.9.24.4-9 (PARTIAL)
|| REFUTED: PARTIAL — GR9 says the inserted return mechanism, reached after the last statement of the output procedure, 'provides for termination of the merge'. GR7 c) defines part of that termination: the as-if CLOSE of each USING file, which 'is not performed until after control passes the last statement in the output procedure'. EmitMerge instead runs EmitInputFile, including its FileClose and CLOSE USE hook, for every USING file BEFORE SortEnterProcedure and the output procedure. So the termination the mechanism provides is missing the USING CLOSE, which has already happened, and the difference is observable. Inside the output procedure the USING file's FILE STATUS holds the as-if CLOSE's '00' instead of the at-end '10' left by the as-if READ with AT END. Any CLOSE USE procedure also runs before the output procedure instead of after it. The adjudicator named this timing and sent it to GR7 c). But it is the same event GR9's mechanism is required to perform, so the half of GR9 about what happens on entry and on RETURN is verified and the termination half is not.
- **Code location (record):** src/Cobol.Net.Compiler/CodeGen/Verbs/SortEmitter.cs#EmitMerge; src/Cobol.Net.Runtime/IO/CobolSort.cs#EnterProcedure; src/Cobol.Net.Runtime/IO/CobolSort.cs#ReturnStatement

## What the fixer owes
Defer the USING files' as-if CLOSE (GR7 c)) to the return mechanism after the output procedure's last statement; sweep SORT's GIVING/USING twin and PB749's status-store placement in the same EmitInputFile.
