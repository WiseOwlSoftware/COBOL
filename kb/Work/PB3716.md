# PB3716 — the bounce-results download destroys what it promises to leave

**Sites:** `scripts/orchestrator/queue_facts.py` (`fetch_bounce_results`, `_holds`, `_swap_in`, `STAGING_SUFFIX`, `self_test`), `docs/rearchitecture/DESIGN-test-build-ci.md` (the tier 0a paragraph on the bounce's results directory).

## What happens

`fetch_bounce_results(branch, dest)` downloads the failed merge-group run's test results into `dest` for the gate planner (tier 0a). Its
unreadable-answer paths return messages ending `dest left as it was`, but the function calls `shutil.rmtree(dest, ignore_errors=True)`
(branch line 263, again at 280) BEFORE the `gh run download` that can fail: when the download then fails (network, a rate limit, a removed
artifact), the earlier results are already deleted and the caller is told they were left. The next gate plans without the reds it should
run first, and nothing says so.

## Fix

Download into a fresh sibling directory and swap it in only on success (rename over `dest`), so a failed download leaves `dest` exactly as
it was. Self-test arm: a failing `gh run download` with a populated `dest` leaves every file in place. Sweep `scripts/` for another
delete-then-fetch of a cache directory.

## Landed

Re-probe on the landed code: the message had already become "`dest` is empty" (true, after the rmtree), so the note as worded no longer reproduced, but the root did: `shutil.rmtree(dest)` ran BEFORE `gh run download`, so a transient failure destroyed the previous results, and a download that died half-way left partial artifacts (no provenance marker) in `dest` under a message saying it was empty. Fixed at the root: the download lands in the sibling `<dest>.fetching`, which replaces `dest` only once whole (`_swap_in` renames the old one aside and restores it if the move fails); a failed download leaves `dest` exactly as it was and the line names what it still holds (`_holds`: the run its marker names). The contract now matches the docstring and the design doc ("left as it was when GitHub cannot be asked"). Self-test arms: failed and partial download over a populated directory, the same over a never-fetched one, a newer bounce replacing the older whole, a swap that cannot complete restoring the old directory. Sibling sweep: `shutil.rmtree` of a directory followed by a fetch/produce step across scripts/ finds `capture_oracle` (its out directory is rebuilt by contract, no earlier content is promised) and `compare_oracle` (already copies after success); no other cache directory is deleted before its fetch. Closes no inventory row: gate tooling, no ISO rule.

For the next implementer: `scripts/orchestrator/queue_facts.py#fetch_bounce_results` downloads into `<dest>.fetching` (`STAGING_SUFFIX`) and `_swap_in` replaces `dest` only once whole; REUSE `_swap_in` for any other directory that must keep its old content when its refill fails, and `_holds` to say what a left-as-it-was directory holds. The trap: the self-test fake of `gh run download` must write into the `--dir` it is given (staging), never into `dest`.
