# PB3716 — the bounce-results download destroys what it promises to leave

**Sites:** `scripts/orchestrator/queue_facts.py:263` and `:280` (`fetch_bounce_results`; the function is on branch `worktree-wf_5669d89a-9c0-19`, A3, PB3644/PB3660, and lands after A2).

## What happens

`fetch_bounce_results(branch, dest)` downloads the failed merge-group run's test results into `dest` for the gate planner (tier 0a). Its
unreadable-answer paths return messages ending `dest left as it was`, but the function calls `shutil.rmtree(dest, ignore_errors=True)`
(branch line 263, again at 280) BEFORE the `gh run download` that can fail: when the download then fails (network, a rate limit, a removed
artifact), the earlier results are already deleted and the caller is told they were left. The next gate plans without the reds it should
run first, and nothing says so.

## Fix

Download into a fresh sibling directory and swap it in only on success (rename over `dest`), so a failed download leaves `dest` exactly as
it was. Self-test arm: a failing `gh run download` with a populated `dest` leaves every file in place. Sweep `scripts/` for another
delete-then-fetch of a cache directory.
