# PB4330 — step 7 of PB4323: PR and push events shrink

**Sites:** `.github/workflows/build-and-test.yml` (job `audits`: `if: github.event_name == 'merge_group' || needs.changes.outputs.run_matrix == 'true'` and its DEVLOG step on `merge_group` alone; job `changes`: the `pull_request` arm no longer computes a base; the banners above `on:` and `audits`), `tests/WiseOwl.Cobol.Tests.Unit/InertLaneDriftTests.cs` (`TheAuditsJob_RunsTheLinuxSelfTestsInEveryMergeGroup_AndOnNoPullRequest_AndTheLocalInertLaneRunsNone`) and `tests/WiseOwl.Cobol.Tests.Unit/LandingPipelineDriftTests.cs` (class summary). The push run's `toolchain-cache` and `package-cache` restore-or-save jobs were already in place from PB4324 and are kept.

**Change.** The audits job runs 3 times per landing today (PR, push, merge group); it runs once, in the merge group, which runs the tree audits plus all Linux script self-tests (126 s).

**Adds / deletes.** 0 / about -40.

**Effect.** 4.7 to 5.7 min less latency per landing (PR event 5.72 to about 1 min, push 5.70 to 1 to 1.5 min).

**Closes.** Nothing.

**Landed (w20261794a).** The `audits` job runs in every merge group (not behind `run_matrix`, so the inert lane keeps its audits) and in any other event only when its matrix runs: a dispatch run, or a push no merge group verified. A pull request's run is `changes` + `ci-gate`; a verified push's is `changes` + `ci-gate` + the two cache jobs. Judgment call: the review writes `toolchain-cache` for the push, and `package-cache` (PB4324's NuGet and GnuCOBOL tarball save under main) is kept beside it, since deleting it would stop main from saving the packages every matrix job restores. The cost this removes shows in the next merge-queue measurement, not here.

**Order.** After step 1 (PB4324, the cache scope: caches are saved from main by the push run). Any order with steps 2 and 9.
