# PB4067 — CiWorkflow.Jobs appends a non-block job line to the previous job

Code only on the branch `worktree-wf_484eb705-564-18` (PR #777, tip 9c0c240a0, PB3819); `tests/_shared/CiWorkflow.cs` is NOT on origin/main yet. Checked against origin/main 2026-10-29: the file is absent there.

## Lead (verbatim, review-worktree-wf_484eb705-564-18.jsonl round 1, R1-1)

> tests/_shared/CiWorkflow.cs:74 CiWorkflow.Jobs refuses a line two spaces under `jobs:` that is not a block job id only when no job
> precedes it; after a job the same line (a quoted id such as `lint` in quotes, or a flow-style job `b: { ... }`) is silently appended to
> the previous job, contrary to the reader contract in its own summary (REFUSED where it can be told apart, never read as empty) and the
> DESIGN-test-build-ci.md _shared row.

## Mechanism

In `Jobs`, a non-trivia line that does not match `JobHeader` throws only under `if (id is null)`; with a job already open it falls to
`body.Add(line)`. A job written in a shape the header regex does not read is merged into its predecessor and no drift test sees a job
missing. Fix shape: refuse a line at job-key indentation that is not a header, whatever precedes it; self-test arms for a quoted id and a
flow-style job after a job.
