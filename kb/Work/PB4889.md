# PB4889 - a report group entry has no entry-name predicate, so a gated USAGE word is taken as the name

**What the report says (the implementer's words).** An unnamed report item with a gated USAGE word is read as a name, so legal
source draws COBOL0901. Flags: rejects_legal_source. Repro: `E:/COBOL-coord/scratch/w20261887h/p4.cob`,
`10 NATIONAL COLUMN 1 PIC N(3) VALUE N"ABC".` draws `COBOL0901: 'NATIONAL' is a reserved word` (the same file's COBOL2199 is
its own LINE 1). §2023:13.18.60.2 prints `[ USAGE IS ]` as optional and §2023:13.15.2 prints `[ entry-name-clause ]`.

**Citations re-checked** (`python scripts/spec/cite.py --check`): `13.15.2 "entry-name-clause"` OK (General format,
`level-number [ entry-name-clause ]`); `13.18.60.2 "USAGE"` OK (`[ <u>USAGE</u> IS ]`, and `<u>NATIONAL</u>` is one of the
usage alternatives). The plain words `USAGE IS` fail `--check` only because the OCR text carries underline tags.

**Mechanism.** `reportGroupEntry` (`levelNumber dataName? reportGroupClause* DOT`) lacks the data entry's `entryNameHere()`
predicate (`CobolData.g4:251`). That predicate reads `RULE_dataDescriptionBody`, so the report entry needs a body rule or a rule
argument, which changes the binders' access to `reportGroupClause`. A different mechanism from PB4818 (PB845's, the entry-name
slot yielding to the clause), and more harmful: PB4818 only moved a diagnostic, this refuses legal source. It shares a root with
PB4890 only in that each slot writes its own name reading.

**Not probed here.** The clerk ran nothing; the implementer's repro is the witness. Re-run it against a fresh build first.

**Sites:** `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolReportWriter.g4` (`reportGroupEntry`, `reportGroupBody`, `reportGroupClause`), `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolData.g4` (`dataDescriptionEntry`), `src/WiseOwl.Cobol.Frontend/Parsing/CobolParserCoreBase.cs` (`CobolParserCoreBase.entryNameHere`, `CobolParserCoreBase.ReadingParses` doc comment), and the readers of the report entry's clauses, now reached through `reportGroupBody()`: `src/WiseOwl.Cobol.Compiler/Binding/ReportSectionBinder.cs` (24 sites), `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.ReportItemDescription.cs` (`DescribeReportItem`), `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.SignClause.cs` (`ScreenReportSignClauses`), `src/WiseOwl.Cobol.Compiler/Binding/ReportModel.cs` (`ReportNamedEntry.ReadAll`).

## Landing (wave 20261905 group E)

**Re-probe (fresh Debug build at dec152346c).** `p4.cob` at 2002, 2014 and 2023: `COBOL0901: 'NATIONAL' is a reserved word …`
at the 10-level entry (beside the file's own COBOL2199 for its absolute LINE 1); at 85 the name reading is right (NATIONAL is a
user word) and COBOL0900 refuses the national item. Reproduced as filed.

**Fix.** The predicate is the data entry's, generalized rather than copied: `entryNameHere(int bodyRule)` asks
`ReadingParses(bodyRule)`, the data entry passes `RULE_dataDescriptionBody` and the report entry `RULE_reportGroupBody`. The
report entry's clause list became its own rule (`reportGroupBody : reportGroupClause*`, the screen entry's
`screenDescriptionBody` shape) because the speculative parse needs a rule to parse; every binder reading the clauses goes
through `reportGroupBody()`. `ReadingParsesFollowDriftTests` now reads every `entryNameHere(RULE_…)` the grammar writes and
holds each rule to the period-alone FOLLOW set, so the next entry that asks the predicate is held without an edit.
`EditionReadDriftTests` records the new word-status site; `PointerUsageOperandDriftTests`' report chain gains the body rule.

**Sibling sweep.** Every rule beginning with `levelNumber`: `dataDescriptionEntry` (had the predicate), `reportGroupEntry`
(fixed), `constantEntry` (its body begins with CONSTANT, which no gated word's clause reading can, so the name is the only
reading), `screenDescriptionEntry` (`screenName` is `cobolWord | FILLER`, no reservation-gated word reaches it). Inside the
report entry the predicate covers every gated clause-leading word by construction (NATIONAL; a non-report USAGE word such as
BINARY-LONG now reaches the binder's §2023:13.18.60.3 SR7 refusal instead of COBOL0901).

**Goldens.** `conformance-suite/cases/13.15-Report-group-description/pb4889_report_unnamed_national_item` (accept 2002, 2014,
2023: an elementary item and a group entry whose first clause is NATIONAL, and `USAGE IS NATIONAL` spelt in full) and
`pb4889-report-unnamed-national-at-85` (refused at 85 by COBOL0900, where NATIONAL is the entry's name).
