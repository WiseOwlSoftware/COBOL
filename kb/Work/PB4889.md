# PB4889 - a report group entry has no entry-name predicate, so a gated USAGE word is taken as the name

**What the report says (the implementer's words).** An unnamed report item with a gated USAGE word is read as a name, so legal
source draws COBOL0901. Flags: rejects_legal_source. Repro: `E:/COBOL-coord/scratch/w20261887h/p4.cob`,
`10 NATIONAL COLUMN 1 PIC N(3) VALUE N"ABC".` draws `COBOL0901: 'NATIONAL' is a reserved word` (the same file's COBOL2199 is
its own LINE 1). §13.18.60.2 prints `[ USAGE IS ]` as optional and §13.15.2 prints `[ entry-name-clause ]`.

**Citations re-checked** (`python scripts/spec/cite.py --check`): `13.15.2 "entry-name-clause"` OK (General format,
`level-number [ entry-name-clause ]`); `13.18.60.2 "USAGE"` OK (`[ <u>USAGE</u> IS ]`, and `<u>NATIONAL</u>` is one of the
usage alternatives). The plain words `USAGE IS` fail `--check` only because the OCR text carries underline tags.

**Mechanism.** `reportGroupEntry` (`levelNumber dataName? reportGroupClause* DOT`) lacks the data entry's `entryNameHere()`
predicate (`CobolData.g4:251`). That predicate reads `RULE_dataDescriptionBody`, so the report entry needs a body rule or a rule
argument, which changes the binders' access to `reportGroupClause`. A different mechanism from PB4818 (PB845's, the entry-name
slot yielding to the clause), and more harmful: PB4818 only moved a diagnostic, this refuses legal source. It shares a root with
PB4890 only in that each slot writes its own name reading.

**Not probed here.** The clerk ran nothing; the implementer's repro is the witness. Re-run it against a fresh build first.

**Sites:** `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolReportWriter.g4` (`reportGroupEntry`, `reportGroupClause`), `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolData.g4` (`dataDescriptionEntry`), `src/WiseOwl.Cobol.Frontend/Parsing/CobolParserCoreBase.cs` (`CobolParserCoreBase.entryNameHere`).
