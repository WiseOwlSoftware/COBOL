# PB5463 - `GrammarDiagramGeneratorDriftTests.Generator_RunsClean` is red at random on Linux in the merge group since PB5447 rewrote it: its liveness witness counts files an asynchronous watcher caught, and two landings bounced on it in twelve hours

**What happened (read by the Mythos session, 2026-11-13).** Merge-group run 43412496532 of pull request #1590 (the PB5460 fix, whose diff touches neither the generator nor this test), job `Linux shard 5/5`, 2026-11-13T10:56:15Z: `Failed WiseOwl.Cobol.Tests.Unit.GrammarDiagramGeneratorDriftTests.Generator_RunsClean [53 s]`, with the message `no file appeared under /tmp/wiseowl-cobol-tests/2834-44f11493ad1f/grammar-diagram-held-09ba4e01ac2b: the generator did not write where this test held files`, at `GrammarDiagramGeneratorDriftTests.cs:line 65`; the shard's Unit run was `Failed: 1, Passed: 3071, Total: 3072`. The landing record (`E:\COBOL-coord`, `landing_measure`) holds exactly two reds that name this test: #1580 at 2026-11-12 15:38 PST and #1590 at 2026-11-13 03:30 PST, both classed RUNNER (the case ran GREEN in each branch's Windows gate) and re-queued once. #1580 merged on its second run. PB5447's rewrite of the test merged as #1579 at 2026-11-12T23:17:51Z, before both. The session did not read #1580's failing message; the fixer does (`gh run list --event merge_group` for `pr-1580-`).

**The assertion that failed** is the test's own liveness witness, `Assert.True(held > 0, ...)`: `held` is the number of files a `FileSystemWatcher` callback had open when the generator exited. The generator's exit code and its summary line had already passed, so the generator ran clean and the test still failed.

**Harm.** A landing whose diff cannot reach the test is bounced out of the merge queue about once in every several code-lane runs (2 reds since the rewrite; the fixer counts the code-lane merge groups since #1579 for the rate). Each bounce costs one more merge-group run and delays every landing behind it, and the landing lane re-queues it with no agent woken, so nothing but this note says it is a flake (CLAUDE.md, Testing: "a flake is a kb/Work defect fixed at its root, never retried inside the run").

**Leads, each from reading the test on main at 767f220e12, none tested.**
1. On Linux a file can be unlinked while another process has it open, and `Take` returns on `FileNotFoundException`. If the `-Check` run deletes its notes before the watcher's callback reaches them, `held` is 0 with a correct generator. On Windows the hold blocks or outlives the delete, which is why the Windows gate is green.
2. .NET's `FileSystemWatcher` on Linux is inotify: with `IncludeSubdirectories` a new subdirectory is watched only once its own create event is processed, so files created in it before that raise no event.
3. `Take` spins on `IOException` on the watcher's callback thread; on Linux the events are delivered from one thread, so one file its writer keeps unshared for the run stalls every later event until `Stop()`.
4. The watcher has no `Error` handler: an inotify queue overflow or a watch-limit refusal on a busy runner drops events silently.

**Shape (the fixer decides after reproducing it; CLAUDE.md rule 5, and the testing rule that no test may fail with no regression).** The hostile-directory half must be DETERMINISTIC: whether the hold was live cannot depend on a race between an asynchronous observer and the process it observes, on either OS. The witness that the generator wrote under the directory the test named must be something the test can read for certain (what the generator itself reports or leaves, or a hold placed before the write and not after it). The test must still fail against the pre-PB5447 generator (the named-file handoff) on Windows, which is the defect it exists to catch.

**Second defect, same root as the silence:** a RUNNER-class red is re-queued and recorded as an `infrastructure` bounce, and nothing surfaces that the SAME test case reddened two landings in twelve hours. The session probe prints no line for it. Whether `landing_measure` has a view that does is for the fixer to read; if none does, the record that "holds its rate" is read by nobody.

## Measured (the implementer, wave 20262018 group A)

**Reproduced on Linux.** A WSL clone of the branch at 27178041b6, built Release, ran the unchanged test 40 times (4 copies
at once beside 32 busy-loop workers, 32 CPUs; `wsl-loop.sh 10 stock-loaded 4 32` in
`E:/COBOL-coord/scratch/w-mythos-gdflake/w20262018a`): 1 red, `no file appeared under /tmp/wiseowl-cobol-tests/27385-de6a86e4ece1/grammar-diagram-held-7a219fbba367`.

**The mechanism, from an instrumented throwaway copy** (every event and take logged; 2 runs, `held=4` each). The first
Created event is pwsh's own `dotnet-diagnostic-<pid>-<n>-socket` in `TMPDIR`. Its open fails with ENXIO ("No such device
or address"), an `IOException`, which `Take` read as a writer refusing the share and retried on the watcher's one event
thread for 22 to 24 s, the whole run. On Linux that thread also reads inotify, so nothing more was read: the generator's
`wiseowl-cobol-grammar-check-*` subdirectory was never watched, and no note was ever seen (no Created line for any). When
pwsh exited, the socket's take ended in FileNotFound and the queued events for the runtime's `clr-debug-pipe-*-in`/`-out`
FIFOs were taken in the same millisecond, before pwsh removed them. All 4 held files were runtime FIFOs, and the red is
pwsh removing them first. Leads 3 (the event thread stalls) and 2 (a subdirectory is watched only once its event is read)
are the mechanism together, with the socket as the stalling file. Leads 1 (the notes' delete) and 4 (no `Error` handler)
are not: no note was ever reached, and the instrumented `Error` handler never fired. On Windows the runtime's diagnostics
use named pipes outside `%TEMP%`, so the notes were the held files there.

## The fix

`tests/WiseOwl.Cobol.Tests.Unit/GrammarDiagramGeneratorDriftTests.cs#Generator_RunsClean`: nothing asserted depends on when
the watcher's events arrive. The witness that the generator wrote where the test held files is the generator's own
summary line (`generated <n> grammar-diagram note(s) into <dir>`, `<dir>` under the test's temp directory). The holder
proves itself live before the child starts (`FreshFileHolder.ProveAsync`: a probe file planted after the watch is in
place, its take awaited). Each Created event is taken on a thread-pool work item; only a Windows sharing or lock violation
is waited out; a gone file, a directory or a socket is skipped; a watcher `Error` fails the test. On Unix a shared hold
refuses no reader (.NET's share modes are an advisory `flock`), so the hostile half bites on Windows only.

- The proof is the mechanism (measured above) and that no assertion now depends on when a watcher event arrives. The
  counts are consistent with the fix, not proof of it: at the old rate of 1 in 40, 0 reds in 60 runs has chance
  (39/40)^60, about 0.22.
- Linux, the same load, after the fix: 0 reds in 60 runs (`wsl-loop.sh 15 fixed-loaded 4 32`).
- Review R1-1: every way the probe can fail to be taken (watcher `Error`, probe gone, a take that threw on its work item,
  the holder stopped) faults the wait with its cause. Throwaway copies: `Error` raised through `FileSystemWatcher.OnError`
  failed in 77 ms, "the holder's probe was not taken: the watcher reported an error ---- InternalBufferOverflowException";
  a take that threw failed in 26 ms, "taking ...holder-probe threw ---- ArgumentException"; neither hung or ended the host.
- Linux, the pre-PB5447 generator (`git show 2352eff5df:scripts/gen-grammar-diagrams.ps1`) under the fixed test: passes (1 run), as the advisory lock predicts.
- Windows, the current generator: `Passed!  - Failed: 0, Passed: 1` (50 s).
- Windows, the pre-PB5447 generator swapped in uncommitted: `Failed!  - Failed: 1`, "exited 1 while this test held every
  fresh file ... (held 23 file(s), skipped 2, watcher errors 0)", `ReadAllText` of `ccf-<guid>/CobolWords.md` "being used by another process".

**Sibling sweep** (`FileSystemWatcher|inotify|ReadDirectoryChanges` and `OutputDataReceived|ErrorDataReceived|EnableRaisingEvents|.Exited +=` over `tests/`):
`DirectoryNameWatch` (RegionLocksDriftTests, SidecarColumnLockHostDriftTests) waits for the one report it needs, reads a
watcher `Error` or a missing report as a non-observation and watches no subdirectory: not this defect. `LiveProcess`'s
`ErrorDataReceived` is read after the parameterless `WaitForExit`, which waits for the asynchronous readers' end of file:
not this defect. No other test uses a watcher.

**The second defect** (a repeated RUNNER red of one case is surfaced by nothing) is kb/Work PB5464.
