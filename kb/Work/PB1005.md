# PB1005 — LANDED

## Landed (wave 54, 2026-09-22)

Re-probed first on the implementer's own build: `p3_sr3` compiled silently and printed `SR3-NOT-DIAGNOSED`. After the
fix its `>>PUSH ALL` (line 1, before IDENTIFICATION DIVISION) draws COBOLNET2344 "outside every compilation unit";
its `>>POP ALL` after the last statement of a program with NO END PROGRAM header is inside that program (it runs on
to the end of the text) and is correctly not diagnosed — the note's "after the last END" arm is the END PROGRAM case,
pinned by `PushPopAllPlacementTests.AfterEndProgram_IsOutside_…`.

`PushPopAllPlacementPass` (Validation, run by `BinderDriver` beside the level-number screen) decides the rule from
the parse tree and the directive sites: `DirectiveSite` now records `AllForm`, and a directive's position is the GAP
between the last token before its line and the first after it. Arm 1 — outside every top-level unit's token span
(a program without END PROGRAM stays open). Arm 2 — inside the innermost `…Clause` rule or `StatementContext`
spanning the gap, unless the gap is a boundary of a nested one (the next token starts one or the previous token
ends one), so `IF A = 1 >>PUSH ALL DISPLAY …` is between statements and `MOVE A >>PUSH ALL TO A` is not. Gaps at an
entry name or a header are not inside a clause and are not diagnosed. The disposition is a §4.2.2 WARNING, like the
sibling SR4 bans (D20, COBOLNET2187); the directive is still processed. `PushPopAllPlacementTests` pins both arms,
both words and a legal-position control for each; pb941's golden (every ALL between statements) draws none.

Sibling rules with the same "between clauses … between statements" shape, NOT in this group: §7.3.14.3 SR1
(FLAG-02) and §7.3.15.3 SR1 (FLAG-14) — reported as a lead; the pass's gap test is the one they need.

## The rules
`OK  §7.3.20.3 3)` — "If ALL is specified, the POP directive shall be specified only in a compilation unit, between
clauses in divisions other than the procedure division, and between statements in the procedure division."
`OK  §7.3.22.3 3)` — the same for PUSH.

## What the fixer owes

statements); the "between clauses" half needs the parser's clause boundaries, so check where the other placement-bound
directives (>>CALL-CONVENTION, >>PROPAGATE) get theirs. Negative goldens for each arm.
