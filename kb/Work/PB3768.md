# PB3768 — ResolveAssignUsing still says a report entry is not described

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs#ResolveAssignUsing` (the `AssignUsingNotAlphanumeric` error, about line 2740 on the PB1046 branch), `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.Reports.cs#ReportEntryReferenceRefused`

PB1046 (PR #596, branch worktree-wf_1341dc87-1c4-11) routes FILE STATUS / RELATIVE KEY / LINAGE / APPLY COMMIT (`ResolveClauseOperand`) and data-division ODO through `ReportEntryReferenceRefused`, so a report-section entry named there draws COBOL5092. The sweep missed `ResolveAssignUsing`: a report entry named in ASSIGN ... USING is still told "and no such data item is described" (COBOL1810), the same false not-declared wording. §13.15.3 SR7 ("The data-name shall not be referenced in any other way", PB1046 cite OK) covers this reference too, and §13.8.6.2.3 forbids it in any other section of the data division. Harm: wrong message only; refused either way. Fix: ask `ReportEntryReferenceRefused` first, as `ResolveClauseOperand` does, and extend the PB1046 drift test `ReportItemReferenceTests.EveryUndefinedNameArm_AsksTheOneRefusal` to name this arm.

Not the same fix as PB3766 (that is the inheritance order; this is a missed arm), so two notes.

(2026-10-25, PB1046 review R1-2, severity low, not blocking at round 1.)

## Landed (wave 20261780 group D)

**Re-probe.** `SELECT DAT ASSIGN USING PN` with `PN` a printable item of an RD still drew `COBOL1810 … shall reference an alphanumeric data item and no such data item is described`. The sweep of the file-control clauses that name a data item found the SAME false verdict on a second arm: `RECORD KEY IS PV` drew SR2's `COBOL0863 … references nothing described in this program` (the key resolver `InRecords` returns no item and the SR2 row then speaks).

**Fix.** `DataBinder.ResolveAssignUsing` asks `ReportEntryReferenceRefused` when the operand resolves to nothing and is not ambiguous, as `ResolveClauseOperand` does; the record-key resolver `InRecords` (prime and alternate keys, and a SOURCE phrase's operands) asks it when no candidate exists and, on a refusal, records the name in `refusedKeys` so `FileControlKeyRules` stays silent about an operand already refused. `ReportItemReferenceTests.EveryUndefinedNameArm_AsksTheOneRefusal` now names the three data-division arms BY MEMBER (`ResolveClauseOperand`, `ResolveAssignUsing`, `InRecords`) where it asked the file for the substring.

**Witnesses.** Conformance negatives `pb3768-assign-using-names-report-item` and `pb3768-record-key-names-report-item` (COBOL5092 at 85, 2002, 2014, 2023).
