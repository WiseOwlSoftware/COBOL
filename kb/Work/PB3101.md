## The mechanism

A rule written twice, in two currencies: the bind-time comparator re-derives each rule from `DataItem` fields and the
run-time relation reads the `ActivationDescription` the compiler builds from the same fields. The divergences are
exactly where one copy was corrected and the other was not (the reference-modified item's PICTURE-less description,
PB480; the group's absent clauses, PB1780's wave-73 paragraph). `PictureClauseIdentityDriftTests.ActivationMatch_AgreesWithTheComparator_OverEveryElementaryPair`
holds the two together over elementary pictures only (PB1576 names the uncovered axes: groups, pointers, object
references, strong types, as-if-elementary groups, reference-modified items) — a drift test over a duplicate is the
shape that cannot cover the next axis. The owner's rule (2026-10-12): the decade-long bar wants ONE representation,
and the cost is one restructure now against a repeat of this note at every new axis.

## Fix shape (apply-ready) — the design is docs/COBOLNET_OO_DESIGN.md D6 item 7

1. **The relation family is complete in the runtime.** `ActivationRelations` already holds the activation half:
   `Matches` / `ReturningMatches` (§9.3.6), `ParameterViolation` / `ReturningViolation` (§14.8.2 / §14.8.3 for a bound
   method), `CallArgumentViolation(mode, argument, formal, specifiedProgram)` / `CallReturningViolation` (§14.8.2.3.2
   rule 1 or 2, §14.8.2.3.3's SET / COMPUTE / MOVE regime through `MayMove` / `MaySet`, §14.8.2.2). It gains:
   `MatchViolation(argument, formal)` (PB2077 item 1: the match's description half, the ACTIVE-CLASS value half
   staying in `Matches`; landed with PB2077, where GR7 c)'s ANY LENGTH ban left `ParameterViolation` for the universal
   switch's unconditional stop, so the typed lane asks the same `ParameterViolation`); and
   `SameSignature(a, b)` — the symmetric identity of §9.3.8.2.3 rules 1-6, §11.7.3 SR3/SR4 and §13.7.3 SR2 over two
   descriptions: class and category, the `Clauses` key, ANY LENGTH, the LOCALE identification, the object-reference
   phrases, OPTIONAL and BY VALUE, the strong type, and for a group its subordinate layout. For that last item
   `GroupAtom` gains the leaf's identity (`Category`, `Clauses`), so `SameSignature` is total over descriptions and
   `StrongTypeModel.SameElementaryLayout` is asked by nothing (§8.5.3.1's "essential characteristics" are those
   atoms).
2. **One bind-time entry.** `ParameterConformance.CheckArgument(formal, arg, position, site)` serves CALL Format 2,
   function references AND INVOKE: it builds the argument's description (`ActivationDescriptions.OfCallArgument` /
   `OfPlace` / `OfValue` — the sender description in ONE place, which already carries the §14.9.4.4 GR8 reduction
   through `Gr8ArgumentLiteral`, so `CallBinder.Gr8Classify` and `OoBinder`'s inline block go: PB613 closes here) and
   the formal's (the same builder the class half renders into its static field), then asks `CallArgumentViolation`
   for a program or function and, for a method, `MatchViolation` then `ParameterViolation` — the match first, as §14.9.23.4 GR7 b) orders it. The `ActivationSite` record carries the importing
   rule and the diagnostic (COBOLNET0828 for INVOKE keeps its code and its remedy text). `OoBindInvocationArg` keeps
   what is INVOKE-specific: SR9/SR10 mode selection, SELF / NULL / address / OMITTED arguments, the BY VALUE header
   rules. RETURNING delivery asks `ReturningMatches` + `ReturningViolation` (method) or `CallReturningViolation`
   (program / function) through the same entry's returning arm.
3. **Pair mode asks `SameSignature`.** `OoConformance.MethodConformanceMismatches` (override §11.7.3, implements
   §9.3.11, interface-to-interface §9.3.8.2.3), the property accessor check, `PrototypeSignatures.SameDescription`
   (§13.7.3 SR2) and `MoveBinder.ElementMovesOf`'s identity-conversion test ask it over the two descriptions; each
   caller keeps its own message wording (the rule it imports) around the relation's reason.
4. **Deleted, not shimmed (CLAUDE.md rule 4):** `OoConformance.DescriptionMismatch`, `ContentMismatch`,
   `MoveContentMismatch`, `ContentValueMismatch`, the `Content*Mismatch` literal arms, `AsIfElementaryGroupMismatch`,
   `CategoryArmMismatch`, `StrongTypeMismatch`'s comparator copy, `CallBinder.Gr8Classify`, `OoBinder`'s GR8 block,
   `StrongTypeModel.SameElementaryLayout`. `PictureClauseIdentity` stays as the ONE builder of the `Clauses` key
   (the currency string, DECIMAL-POINT IS COMMA, the LOCALE phrase) that `ActivationDescriptions.ElementaryClauses`
   reads; `DescriptionClauses` folds into it.
5. **Goldens.** `conformance:2002/pb3101_activation_lanes_one_relation`: the three measured lanes, PB3098's eight rows
   typed and universal, BY CONTENT / BY VALUE rows per formal category (COMPUTE, SET, MOVE), RETURNING delivery; a
   negative per refused pair per lane (`pb3101-prototype-call-refmod-by-reference`, `pb3101-function-refmod-by-reference`,
   `pb3101-typed-invoke-elementary-into-group`, …).
6. **Drift tests.** `ActivationConformanceDriftTests` (exists: CALL and function both ask `CheckArgument`) gains the
   INVOKE lane; `PictureClauseIdentityDriftTests.ActivationMatch_AgreesWithTheComparator_OverEveryElementaryPair` is
   deleted with the comparator (PB1576 closes: one representation has no second axis); `ActivationDescriptionFieldDriftTests`
   (exists) keeps every description field read by a relation; new `OneRelationDriftTests`: a Roslyn walk over
   `src/Cobol.Net.Compiler` asserting that no member outside `ActivationDescriptions` reads two `DataItem`s' `Pic.Clause`,
   `Usage`, `IsAnyLength` or `Pic.Category` against each other — the conformance question has one asker.
7. **Carriers stay carriers.** PB1113's float conversion and PB1116's strong-group leaf vector are landed in the
   emitters; PB1014's BY CONTENT boolean store through the MOVE path stays its own note.
8. **Docs** are in this change (D6 item 7). The implementer corrects the design where implementation proves it
   wrong, and says so in the note.

**Cost.** One Opus slot plus a review round: `OoConformance.cs` is 1,200 lines with 30 callers, and the deletion
touches CALL, function, INVOKE, RETURNING, override, implements, prototype and MOVE binders. The trade-off the owner
set on 2026-10-12 — a decade-long production compiler, rearchitecture allowed where the principle needs it — is met
by one landing instead of a comparator correction per axis (PB480, PB1113, PB1116, PB1164, PB2077 so far).

**Item 3 is a design question, not a mechanical move (for the next implementer).** `SameSignature` over descriptions
cannot simply replace `OoConformance.DescriptionMismatch` in `PrototypeSignatures.SameDescription`: a restricted
program- or function-pointer's description carries its type as the SIGNATURE CLASS identity
(`PrototypeSignatures.RestrictionIdentity`, `DataItem.PointerRestrictionIdentity`, PB2464), and those classes are
computed BY `PrototypeSignatures.Same` (the greatest fixed point over mutually recursive prototypes,
`PrototypeBisimulation`, PB2495). Asking a description-level relation from inside the computation that produces the
descriptions' identities is circular. The shapes to choose between, before any code moves: (a) `SameSignature` takes the
pointer-identity equivalence as a parameter (the assumed pairs while the classes are built, identity equality after),
so `PrototypeSignatures` describes each side with the prototype NAME as the provisional identity; or (b) the signature
class partition stays a compile-time computation over `DataItem`, and only the four post-partition askers
(`MethodConformanceMismatches`, the property accessors, `MoveBinder.ElementMovesOf`, and `PrototypeSignatures.SameType`'s
callers) ask `SameSignature`. Two more axes `SameSignature` must carry that no description carries today: a
parameterized class's formal parameter-name standing for its actual (`ObjectRefDescriptor.TurnsOnFormal`, PB2937), and
§8.5.3.1's type-declaration equivalence across source elements for two strong groups (`StrongTypeModel.SameType`, with
the bisimulation for restricted-pointer members, PB3120). Settle the shape against docs/COBOLNET_OO_DESIGN.md D6 item 7
(it says `GroupAtom` gains the leaf identity; it does not yet say how the pointer identity is decided during the
partition) and record it there.

**NEXT.** Item 3 (pair mode on `SameSignature`, after the design choice above), item 4's remaining deletions
