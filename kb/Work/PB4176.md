## Landed (wave 20261788 B, 2026-10-31)

**Sites (as changed):** `src/WiseOwl.Cobol.Frontend/Preprocessor/CopyProcessor.cs` (`StatementCursor`: constructor,
`Advance`, `TryTake`, `ScreenLiteral` new, `Error`; `ReadCopyName`; `ApplyReplaceStatements` and `ParseCopyStatement`, the
two constructions), `src/WiseOwl.Cobol.Frontend/Parsing/LiteralScreen.cs` (`ReportUnterminated(string, …)` new,
`UnterminatedMessage` new), `tests/WiseOwl.Cobol.Tests.Unit/LiteralScreenDriftTests.cs` (the one-site row),
`tests/WiseOwl.Cobol.Tests.Unit/TextManipulationStatementTests.cs`, `docs/rearchitecture/DESIGN-frontend-grammar.md` (3.12
literal paragraph), `docs/rearchitecture/DESIGN-cc-in-copy.md`.

**The rule.** `cite.py --check 6.3.5 "A line terminates within an alphanumeric or boolean literal without a closing delimiter
and the next line that is not a comment line or a blank line contains a fixed continuation indicator"` -> OK §6.3.5 1): a
literal left open at a line's end is continued only so, and the reference-format stage has joined every continued one, so a
literal still open when COPY is read was never closed: the lexer's own COBOL5563 case (PB3245), met before the lexer runs.

**Re-probe** (build of 11e8949be, `COPY "ABC` then `STOP RUN.`): COBOL2450 "is not an alphanumeric literal" at the literal and
COBOL2449 "'STOP' is out of place" at the next line, as filed; the same for `COPY bk OF "LIB`, `COPY X"41` and `COPY "ABC` at
the end of the text (COBOL2449 "no terminating separator period").

**Fix.** The statement cursor is the one place a COPY or REPLACE statement consumes a text-word (`Advance`, `TryTake`), so it
asks `LiteralScreen.ReportUnterminated` of every literal text-word there (operand, library name, REPLACING operand, a
literal inside pseudo-text) and the report is the statement's first error, so the swallowed rest of the line draws nothing.
`ReadCopyName` no longer calls an open literal "not alphanumeric". The cursor now takes the mapped text, the bag and the
statement's name and clause, so the two constructions no longer each spell the COBOL2449 lambda. The open literal is shown
without the spaces a fixed-form line pads it with (both the lexer's and this report).

**Witnesses.** Golden `cases/7.2.3-COPY/pb4176-copy-literal-not-closed` (refused at 85, 2002, 2014, 2023, COBOL5563);
`TextManipulationStatementTests.AnOpenLiteral_InACopyOrReplaceStatement_IsNamedAsNotClosed` (5 rows, each exactly one
diagnostic, COBOL5563).
