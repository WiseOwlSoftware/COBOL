## Leads folded here

- R1-2 LEAD (low): the new unconditional `AmbientRaises` row `new("EC-DATA-CONVERSION")` (line 378) yields the name for
  every statement in `LeafRaisableNames`, so the `OperandRaises` row at line 313 can no longer change any statement's
  raisable set; the comment at 376-377 says the intrinsic arm "stays an OperandRaises row" as if it still did work.
  Delete the dead row (no shim) and correct the comment.
- R1-3 LEAD (low): the EC-DATA-CONVERSION gate docs (`ExceptionState.cs` 621, 631-637; `EcEmitter.cs` 248) describe
  only CONVERT / DISPLAY-OF / NATIONAL-OF, but the only caller of `DataConversionError` is now `StorageByte.ImageByte`,
  which every REDEFINES bit, national, binary, packed and float view reaches.

A drift test that no `OperandRaises` row is subsumed by an `AmbientRaises` row would keep the first from recurring.
