# PB5169 - at --std 85 a comment-entry continued with a hyphen in the indicator area compiles: CommentEntryOf reads a continuation line inside an open comment-entry as one more body line

**Sites:**

- `src/WiseOwl.Cobol.Frontend/Preprocessor/ReferenceFormatProcessor.LogicalConversion.cs` (`CommentEntryOf`, `ConvertLine`)
- `src/WiseOwl.Cobol.Frontend/Preprocessor/ReferenceFormatProcessor.cs` (`CommentEntryParagraphs`)

**Mechanism.** §1985:VI.3.2.1.2 SR1 (and §1985:VI.3.4.3 SR1 for DATE-COMPILED) forbids continuing a comment-entry by a hyphen in the indicator area; the entry may instead take several lines. `CommentEntryOf`'s first statement treats a continuation line inside an open comment-entry as another body line, so the hyphen is discarded with the commentary and the program compiles with no diagnostic (AUTHOR, DATE-COMPILED and SECURITY probed).

**Found by.** The 1985 code read (2026-11-10; its records are `E:/COBOL-coord/scratch/coderead-85/for-register.json`): each rule below was read against the code sites it names and probed at `--std 85`, and found non-conforming. Verdict, harm, evidence, repro and observed text are the records'; the rows' verdicts are recorded on another branch.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids of the list below.
