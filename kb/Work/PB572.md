# PB572

## Mechanism
a NATIONAL leaf reached through a REDEFINES view is refused as a MOVE receiver (COBOLNET0899) while the byte-identical DISPLAY spelling compiles, so the USAGE clause does affect the use of the data item - the sentence GR2 says it does not

### The refutation this note is written from
Row `GR-13.18.60.4-2` was adjudicated CONFORMS and OVERTURNED to `PARTIAL` by the refuter. Its reasoning, verbatim:

> Sentence 2 - 'It does not affect the use of the data item, although the specifications for some statements in the procedure division may restrict the USAGE clause of the operands referred to' - is measurably FALSE for at least one usage, and the adjudicator's own probes could not see it because every one of them held the usage axis inside the NUMERIC family (DISPLAY / COMPUTATIONAL / PACKED-DECIMAL / COMP-5, probes p27 and p32). Flip the axis to USAGE NATIONAL and the same construct that works for a DISPLAY item is refused: `01 G. 05 A PIC N(3) USAGE NATIONAL. 01 H REDEFINES G. 05 B PIC X(6). ... MOVE N"ABC" TO A` draws COBOLNET0899 'receiving operand A names a declared item in a reference shape COBOL.NET does not yet implement as a receiver (COBOLNET_DESIGN 1.4 - rejected rather than dropped)', while the byte-identical program with `05 A PIC X(6) USAGE DISPLAY` compiles and runs, and the same national item WITHOUT the REDEFINES also compiles and runs. The single differing factor is the USAGE clause, so the USAGE clause here does affect the use of the data item - and the refusal is not one of the procedure-division restrictions the sentence licenses (SS14.9.25 admits a national receiver for a national sender; nothing in the MOVE statement restricts the USAGE of its operands here). The compiler's own model records this as a KNOWN deferral, not an accident: PicInfo.cs's PicCategory.National doc comment says byte-addressed surfaces (REDEFINES / cells / file records) 'REFUSE national leaves loud (D-N2) until the 2-byte layout residue lands'. A self-declared open residue inside the rule's own scope is exactly what CONFORMS may not cover. Sentences 1, 3 and 4 do hold (ByteForm/StorageWidth are the single representation table; the SR10 / SR14 / usage-display screens are real restriction sites; the radix-2 / radix-10 / one-byte-per-digit arms exist). Two halves, one verified => PARTIAL.

### Inventory row `GR-13.18.60.4-2` (PARTIAL)
Three claims, all held. (1) "specifies the manner in which a data item is represented in the storage of a computer" - PicInfo.ByteForm is the single table mapping each usage to its byte representation (Zoned / Binary / Packed / PackedNoSign / Ieee32 / Ieee64) and PicInfo.StorageWidth the width that representation implies; PicInfo's own doc comment names GR4/GR11 as the licence and §4.2.16 as the documentation duty, and the forms are documented at docs/CONFORMANCE.md §7 items 205/208/211/215. (2) "It does not affect the use of the data item" - measured, not assumed: probe p32 uses the SAME `PIC 9(3)` item at usage DISPLAY, COMPUTATIONAL, PACKED-DECIMAL and COMP-5 as a subscript (`TE(KD)` … `TE(K5)` all yield ABC), as a PERFORM VARYING control identifier, as the operand of a class condition (`IS NUMERIC` true for the packed and binary forms) and as a MOVE sender; probe p27 shows a signed `PIC S9(5)V99` at DISPLAY / COMP / PACKED / COMP-5 comparing equal, summing to the same value and editing to the same `-123.45` through a `PIC ---9.99` receiver. The representation still shows through DISPLAY's own conversion (usage-display renders the trailing overpunch `001234N`, the binary forms `-0012345`) - that is §14.9.11 GR1's implementor-defined conversion reading the representation this clause pins, documented at docs/CONFORMANCE.md §7 item 56, and it is what sentences 1 and 3 license, not a contradiction of sentence 2. (3) "although the specifications for some statements in the procedure division may restrict the USAGE clause of the operands referred to" - the restriction sites exist and are named: §13.18.60.3 SR10 for a class-index item (probe p6: `MOVE 3 TO IX` draws COBOLNET0809), §13.18.60.3 SR14 for the pointer/object family (COBOLNET1724), the INSPECT/STRING/UNSTRING usage-display screens (conformance:negative/da7-inspect-binary-operand and its two siblings). (4) "may affect the radix or type of character representation" - PicInfo.ByteForm's radix-2/radix-10/one-byte-per-digit arms are exactly that.
