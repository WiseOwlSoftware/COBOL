# PB2016 — LANDED: an owed ledger publish is detected and announced, and a unit is no longer started for it

Owner 2026-10-04: "Publish ledger each time." Two defects sat under that instruction.

1. `next_unit.py` rule 7 ("the ledger page is older than the newest inventory commit on `origin/main` -> `land`") compared
   `docs/rearchitecture/evidence/conformance-ledger.html`, a path no generator writes (the page lives only as the artifact).
   `not page.exists()` was always true, so an idle loop always chose `land`, and every `-DryRun` said "would run unit 'land'".
   Worse, a `land` unit cannot cure the condition: a headless session has no `Artifact` tool (probed 2026-10-04 on Haiku:
   asked whether the tool is available, it answers NO). The rule is deleted, not repaired.
2. Nothing recorded WHAT had been published, so "stale" could not be asked of the page that matters. `ledger_state.py owed`
   compares the page's own stamp (the last commit touching `gen_ledger.STAMP_PATHS`, imported so the two cannot disagree) with
   `ledger-published.json`; `mark-published` is run by the attended session right after its `Artifact` publish. The supervisor
   prints `LEDGER PUBLISH OWED` after every unit, `stop.ps1 -Status` shows the state, and the `wave` and `land` units render
   `{COORD}\ledger.html` instead of claiming to refresh the artifact.

Not fixable from a headless run: the publish itself. In a fully unattended run it waits for the next attended session, and the log
line is how it is seen (design doc section 14). Tests: `test_ledger_state.py` (owed, current, unrelated commit, input commit) and
`test_orchestrate.ps1` 4i (announced when owed, silent once marked).
