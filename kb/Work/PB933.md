# PB933 — HALF — arm 1 folded 2026-09-21; arm 2 (the level-88 parse text) is what remains

Source: the `PB461` report, "New defects" items 1 and 2. They are ONE note because the second is the
first's precondition, which is what makes the fix a single change of shape rather than a deletion.

## Arm 1 — the sixth reading

`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/InitializeBinder.cs:795-827`
(`InitializeValueOperand`) has its own ALL strip and its own figurative word map, and that map sends
`NULL` / `NULLS` to `'N'` where the shared `FigurativeConstants.KindOf` sends it to `'L'`.

**PB461** (landed) folded three emitter copies into one recipe. This is the copy it did not fold, and the
reason is recorded in the drift test itself: the INITIALIZE binder was in flight in the same wave. The
note's fix is therefore known and small — delete `InitializeFigurativeKind`, call `Classify`, remove the
drift test's exemption.

⚠ **The divergence is not yet shown to be OBSERVABLE, and this note does not pretend it is.** Reading the
two maps side by side is the repro the report gives; whether a program can reach the `'N'`/`'L'`
disagreement through INITIALIZE REPLACING is a probe the fixer runs FIRST
(`feedback_reachability_is_measured_not_deduced`). If it is reachable it is a wrong answer and this note's
severity moves; if it is not, the fold still lands, because a divergent private copy of a rule is how the
next wrong answer is built.

## Arm 2 — why there were ever six

`Condition88.Values[].Low` is **the parse text**. The bound tree carries the characters the user typed, so
three CodeGen sites re-parse COBOL during emission — and every site that needs to know what a level-88
VALUE MEANS has to write its own reading of §8.3.3.6.2. That is the precondition for PB461 existing, and
for this sixth copy existing, and for the seventh.

```
$ python scripts/spec/cite.py --check 13.18.63.4 "condition-name"
OK  §13.18.63.4 19)  (General rules)
    19) The characteristics of a condition-name are implicitly those of its conditional variable.
```

A VALUE is a value — GR19 makes its characteristics those of the conditional variable — and a bound tree
that stores it as text has thrown that away and asked every consumer to recover it.

to re-parse; then the figurative reading has exactly one site because there is exactly one place the
question can be asked. CLAUDE.md rule 5: the restructuring IS the fix, and deleting the sixth map without

### The standard is with the shared reading

§8.3.3.6.2 prints SEVEN figurative-constant formats — ZERO, SPACE, HIGH-VALUE, LOW-VALUE, QUOTE, `ALL
literal-1`, `ALL symbolic-character-1` — and NULL is none of them; `NULLS` does not occur in the standard at
all (`grep -n NULLS specs/ISO_COBOL.md` → no match), and the lexer has only `NULL_ : 'NULL'`, so both maps'
plural arm was dead. NULL is §8.4.3.10's predefined address, and §14.9.20.4 GR6c's own fill table draws the
distinction the private map lost: the character rows read "Figurative constant …" and the pointer rows read
"Predefined address NULL". A pointer-category receiver never reaches this method — §14.9.20.4 GR4 routes it to
the SET arm, whose sender is GR6a1/GR6a2's predefined NULL.


### The evidence, and why it is a drift test and not a golden

`FigurativeOperandClassifierDriftTests.NoSecondPrivateFigurativeWordMap_ExistsInTheTree` is new. The existing
`NoSecondPrivateAllStrip_…` fact could not have caught this copy: `InitializeFigurativeKind` was a WORD map, not
an ALL-strip, so the sixth reading lived in the one half the drift test did not measure
(`feedback_measure_the_selectors_complement`). The new fact keys on the singular/plural alternative every copy
writes — `"ZERO" or "ZEROS"`, `"HIGH-VALUE" or "HIGH-VALUES"` — which the REVERSE direction (a kind rendered
back into a diagnostic's word, as `VersionConformancePass.GateMove` does) never writes. **Its failure branch was
fired once** before it was trusted (`feedback_green_gates_arent_evidence`): a temporary private map in
`InitializeBinder.cs` produced `Failed: 1` naming the file and offset, and was then removed.
`InitializeBinder.cs` is gone from the ALL-strip `Sanctioned` list.

No conformance golden ships with this change because there is no legal program whose behaviour it alters; the
note's own "Rows" section already said the evidence is the reader count.
