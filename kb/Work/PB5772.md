# PB5772 - at --std 85 a level 66 entry may rename another level 66 entry, where §1985:VI.5.11.3 SR4 forbids it

**What is wrong.** At `--std 85` a level 66 RENAMES entry may name another level 66 entry as data-name-2 (or 3) and the program compiles and runs, against `§1985:VI.5.11.3 SR4` ("A 66 level entry cannot rename another 66 level entry"). The PB5165 whole-scope candidate arm reaches the alias, and `ScreenRenamesOperand` does not refuse level 66. At `--std 2023` the same program is refused (COBOL1655). The program is otherwise legal 1985 (`66 R1 RENAMES A THRU B` in the same record). The Mythos lane ran it: `m1ren.cob` printed `R2=[ABCD]` at `--std 85`.

**Sites:**
- `src/WiseOwl.Cobol.Compiler/Binding/Passes/ResolveRedefinesPass.cs#ScreenRenamesOperand` (no level-66/88 test: it tests only levels 1/77 on the assumption 66/88 are unreachable, true only on the 2002+ `SubtreeCandidates` arm)
- `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs#RegionClauseCandidates` (switch `ClauseOperandsTakeImplicitQualifiers`, `DialectLevel >= 2002`; at 85 it takes `QualifiedCandidates` over the whole scope, and a level-66 alias passes `IsWithinRegion`, Parent = record)

**1985 rows this note blocks.** `1985-FMT-VI.5.11.2` and `1985-GR-IV.4.3.2.1-1` (the reader's PARTIAL on the second is the same mechanism). `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094), so the rows are named here.

**2023 rows whose stored verdict is wrong.** None: cause (a), wrong at 85 and right at the latest edition. The 2023 rows `FMT-13.18.45.2` and `GR-8.5.1.3.2-1` stand (2023 behaviour correct, COBOL1655).

**Rules (checked again with `python scripts/spec/cite.py --check`, verdict OK).**
- `§1985:VI.5.11.3 SR4`: "A 66 level entry cannot rename another 66 level entry"
  `OK  §1985:VI.5.11.3 SR4  (5.11.3 Syntax Rules)  the text is in SR4`

**Repro** (`E:/COBOL-coord/scratch/my-20261115/contradictions-b1/src/m1ren.cob`):

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. M1REN.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 REC1.
          05 A PIC X(2) VALUE "AB".
          05 B PIC X(2) VALUE "CD".
       66 R1 RENAMES A THRU B.
       66 R2 RENAMES R1.
       PROCEDURE DIVISION.
```

**Expected at `--std 85`:** refused (`§1985:VI.5.11.3 SR4`).
**Observed at `--std 85`:** exit 0, prints `R2=[ABCD]`.
**At `--std 2023`:** exit 65, `COBOL1655 'R2' RENAMES R1: 'R1' does not name an item of the record (ISO §2023:13.18.45.3 SR4)`, which is right.

**Leads.** Also observed by a refuter (`rn_d2`): `66 X RENAMES A THRU R1` is refused with a misleading PB96 tiling message instead of SR4.
