# PB2019 — OPEN: the END PROGRAM diagnostic names the wrong rule

The rejection is right; the rule it cites is not. Found by the adjudication of battery #88's flip `syn_definition:1444`
(DEVLOG 1883): three programs with one END PROGRAM that names the FIRST of them. §10.7.3 1): "An end marker shall be present
in every source unit that contains, is contained in, or precedes another source unit"; SR2 requires only that the marker's name
match "a preceding PROGRAM-ID paragraph", and `prog` does precede; SR3 requires the inner programs' markers to come first. The
compiler reports SR2.

Site: `src/Cobol.Net.Compiler/Validation/EndMarkerPass.cs`, `ScreenProgram`, about lines 99-121. SR3 is chosen only when the
marker's name is in the grammar's own nesting chain (`containers` plus `ContainedNames`); when the name matches an earlier program
that was parsed as a SEPARATE top-level unit the code falls into the SR2 branch. Minimal repro: PA, PB and PC each have a
PROGRAM-ID, PA and PB each have an empty PROCEDURE DIVISION, and a single `END PROGRAM PA.` comes last; expected SR1 and SR3,
actual SR2 at the last marker.

Fix at the dispatch: decide the rule from the marker's relation to the source units that ACTUALLY precede it, not from the
nesting chain the grammar built, then sweep the other branches of `ScreenProgram` for the same two-arm shape.
