# PB1243 — OPEN

## Measured

**GR-13.18.27.4-2** (DIVERGES, refuter-corrected where marked) — Rule: "A statement in a program contained directly or indirectly within a program that describes a global name may reference that name without describing it again." (cite.py --check 13.18.27.4 -> OK GR2). BinderDriver injects the containers' GLOBAL names nearest-container-first; the emitter bridges through __outer ref properties so the containee reads and writes the container's storage. Probes: p1 indirect (grandchild) reference and write-back seen by the container (OUT XYZ); p8 a containee's own 01 G shadows the container's GLOBAL G (C G=INNER, OUT G=OUTER) per 8.4.6; p2/p3 non-global names stay invisible. LINKAGE/LS/file arms also covered by conformance:2002/pb1009_global_linkage_formal, conformance:2023/pb163_global_local_storage, conformance:85/pb369_global_file_use_selection. The file-section record that fails to become global is a GR1/SR1 naming defect (GR-13.18.27.4-1), not a reference-resolution defect. || REFUTED: DIVERGES — GR2 defers to 8.4.6 for resolution; 8.4.6.2.1 rule 3a says that when a name matches both an item local to the containee and a container's global item, the reference is to the containee's own item. The compiler instead injects the container's GLOBAL subordinate data-names into the same unit-map tier as the containee's local names (BinderDriver.cs:588 shadows only a matching 01 CobolName), so ReferenceResolver.ResolveUnqualified sees a plural list and rejects the reference as ambiguous. That rejects legal source. The adjudicator's p8 only tested a same-named 01 shadowing an 01 GLOBAL, the one case the 01-level ContainsKey check handles.
