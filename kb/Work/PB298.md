# PB298

Registered 2026-09-02 while landing [[PB152]], whose whole defect shape was "the binder built the fact and
nothing consumed it".

## The observation

`OptionsModel` (`src/Cobol.Net.Compiler/Binding/OptionsModel.cs`) carries these fields, each set by
`OptionsBinder` from a real clause of §11.9:

| field | clause | consumed? |
| --- | --- | --- |
| `Arithmetic` | §11.9.5 ARITHMETIC | YES — drives the SDIDI numeric path |
| `DefaultRounding` | §11.9.6 DEFAULT ROUNDED | YES — the bare-ROUNDED mode |
| `Initialize` | §11.9.10 INITIALIZE | YES as of PB151 + [[PB152]] |
| `EntryConvention` | §11.9.7 ENTRY-CONVENTION | **not swept** |
| `FloatBinaryEndianness` | §11.9.8 FLOAT-BINARY | **not swept** |
| `FloatDecimalEncoding` | §11.9.9 FLOAT-DECIMAL | **not swept** |
| `FloatDecimalEndianness` | §11.9.9 FLOAT-DECIMAL | **not swept** |
| `IntermediateRounding` | §11.9.11 INTERMEDIATE ROUNDING | **not swept** |

The model's own class comment says as much — "Still capture-only: FLOAT-BINARY/DECIMAL (standard-float USAGE
encodings)" — so this is not hidden. What makes it worth a note is that PB152 proved the failure mode is not
benign: a producer-only OPTIONS field is a clause the programmer WROTE, accepted without diagnostic, that
changes nothing. That is a silent wrong answer whenever the clause's whole purpose is to change something.

⛔ **This note deliberately does NOT assert that all five are unconsumed.** `IntermediateRounding` in particular
has a plausible consumer in the standard-arithmetic path and may well be live; the 2026-08-30 analysis that
flagged this family listed it from a `grep` of the model, not from a consumer search. Each field needs its own
`grep -rn` for reads outside `OptionsBinder`/`OptionsModel` — the same measurement that found PB152's
`Sections` dead — before any of them is called defective. [[a_dead_lookup_is_also_unverified]] and
[[reachability_is_measured_not_deduced]] both apply: "nothing reads this" is a probe to run.

## What settling it looks like

Per field: (1) grep for reads outside the producer; (2) if there are none, derive from §11.9.x what the clause
is supposed to change and write the probe that shows it does not; (3) register the result — a defect note with a
repro, or a CONFORMS row in the traceability inventory (§11.9.7/8/9/11 rows are all GAP today). The five are
independent, so this is five small items rather than one wave.

## Why the FLOAT ones may be the sharpest

`FLOAT-BINARY` / `FLOAT-DECIMAL` set the ENDIANNESS and ENCODING of standard floating-point USAGEs — facts that
appear directly in a byte image (a REDEFINES window, a file record, a SORT key). PB152's sibling work pinned
those byte forms (`NumericByteForm`, big-endian IEEE), so if the clause is unconsumed the compiler has ONE
pinned answer where the program asked for the other. That is the same "clause written, nothing changed" shape
with an observable byte-level consequence, which makes it the one to measure first.

### Finding — `float-decimal-clause` (silent; rows `FMT-11.9.9.2`)

**Mechanism.** A processor-dependent element CONFORMANCE.md declares Not claimed (A.3 item 13, the FLOAT-DECIMAL clause) is accepted silently: OptionsBinder stores the phrases into OptionsModel fields nothing reads (PB298's producer-only shape) and no compile-time non-support warning is issued, although §4.2.6 requires one.

**Repro.** IDENTIFICATION DIVISION. PROGRAM-ID. FDA. OPTIONS. FLOAT-DECIMAL DEFAULT IS BINARY-ENCODING HIGH-ORDER-LEFT. PROCEDURE DIVISION. DISPLAY "OK". STOP RUN.  (cobol FDA.cob --std 2023 --run)

**Expected from the spec.** §4.2.6: 'An implementation shall provide a warning mechanism at compile time to indicate use of syntactically-detectable processor-dependent language elements not supported by that implementation.' The clause is syntactically detectable and A.3 item 13 makes it processor-dependent, so a compile-time warning naming the non-support (accept-inert, the RECORD DELIMITER COBOLNET1778 precedent) is required.

**Observed / reasoning.** Compiles with no diagnostic and prints OK. COBOLNET0900 fires only below 2014 (the edition gate), never a §4.2.6 warning at 2014/2023.

**Code site.** src/Cobol.Net.Compiler/Binding/OptionsBinder.cs#ApplyFloatDecimal
