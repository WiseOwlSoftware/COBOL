# PB3411 — the files design doc names a host-failure predicate the branch no longer has

A lead from round 2 of the PB3336 branch review (`mythos-a6-review-r2`, report
`E:\COBOL-coord\scratch\reports\w1118a6-PB3336-report.md`, `## Review findings`, "LEAD (low, stale doc, the
predecessor's text)"). The code is on branch `worktree-wf_14a1e62b-326-31` (PR #268), not yet on main, so the note is
blocked by PB3336; the sites below are read at c1421bf44.

**Mechanism.** `docs/COBOLNET_FILES_DESIGN.md:2502` lists "`IOException`, `UnauthorizedAccessException`,
`OutOfMemoryException` — one predicate, `KeyedConnector.IsHostStoreFailure`". On the branch the predicate is
`failure is IOException or UnauthorizedAccessException` (`src/Cobol.Net.Runtime/IO/KeyedConnector.cs:455-456`) and its
own comment says the OOM reason left with the whole-store model (kb/Work PB3335). The branch's cleanup section ("nothing
was left to delete") missed this doc line; it came from `-326-19`, not from the PB3336 branch. On main the doc also says (about line 2507) that
`FileConnector.Close` maps "the same host failures as OPEN, `OutOfMemoryException` included"; the branch's doc has no
`OutOfMemoryException` there, so line 2502 is the only stale mention on the branch.

**Timing.** On main today the doc and the code both still carry `OutOfMemoryException` (main's `KeyedConnector.cs:297`:
`IOException or UnauthorizedAccessException or OutOfMemoryException`), so the doc goes stale exactly when PB3336 lands.
Fix in the PB3336 landing or right after it: rewrite the doc lines in place to the current predicate (CLAUDE.md rule 6:
docs describe the current compiler; no annotation). PB2842 describes the older predicate in its history only.
