# PB1633 — OPEN

Found 2026-09-27 while sweeping PB1632's pointer-argument crossing.

## Repro
`E:\Temp\claude\E--COBOL\eb162d4b-e0bb-4027-b8a0-86fd190d20be\scratchpad\pb1632\sweep3.cob`: PB1632U contains the
nested programs PCMP and PPTR. `SET PP TO ADDRESS OF PROGRAM "PCMP"`, then `CALL "PPTR" AS NESTED USING BY CONTENT
PP`, and PPTR's `IF LPP = NULL` prints `PP-NULL`. `SET PP TO ENTRY "PCMP"` (`sweep.cob`) does the same. When the
literal names a separately compiled program in the same source file (`pp.cob`, PB1632Q), the pointer is set, and
both BY CONTENT and BY REFERENCE deliver `PP-SET`. So only resolution of a CONTAINED program's name is wrong.
Passing the pointer is not.

## Rule (to derive before fixing)
§14.9.39 Format 9 (program-pointer-assignment) with identifier-8 = `ADDRESS OF PROGRAM`. Derive and `cite.py
--check` the name-scope rule the literal follows: is it the CALL rule, under which a directly contained program is
callable, or only the separately compiled programs? If contained programs are in scope, NULL is a wrong answer. If
they are not, the source violates a rule, and the answer is a diagnostic, never a silent NULL. Also settle whether
the `ENTRY` spelling is ISO at the targeted edition, or an extension that leaks at `--std 2023` (R43).

## Derivation (2026-09-27): the premise is in doubt
- §8.4.3.13.4 GR2 (checked): "For a COBOL program, the address is that of the **outermost** program identified by
  the externalized program-name in its PROGRAM-ID paragraph."
- GR4 (checked): "If the runtime system cannot locate the program, the EC-PROGRAM-NOT-FOUND exception condition is
  set to exist and the value of the address-identifier is the predefined address NULL."
- §8.4.6.3 (the scope of program-names) lists the program-address-identifier beside CALL and CANCEL: a directly
  contained program's name "may be referenced only by statements included in that containing program". That rule
  scopes a name's use. GR2 decides which program's ADDRESS the identifier yields, and it names only outermost
  programs.

On GR2's reading, NULL for a contained program is the CONFORMING value, and the remaining obligation is GR4's
exception: does `SET PP TO ADDRESS OF PROGRAM "PCMP"` set EC-PROGRAM-NOT-FOUND? Probe that (with the EC checking
on, and `FUNCTION EXCEPTION-STATUS`) before anything else. If the EC is raised, this note is NOT a defect: refute
it, keep the probe as a golden pinning GR2/GR4, and settle the ENTRY-spelling question separately. If it is not
raised, the defect is the missing EC, not the NULL. Also worth a GnuCOBOL survey, since contained programs are
static functions there and are never dynamically resolvable.
