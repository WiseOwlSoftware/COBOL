# PB1633 — OPEN

Found 2026-09-27 while sweeping PB1632's pointer-argument crossing.

## Repro
`E:\Temp\claude\E--COBOL\eb162d4b-e0bb-4027-b8a0-86fd190d20be\scratchpad\pb1632\sweep3.cob`: PB1632U contains the
nested programs PCMP and PPTR. `SET PP TO ADDRESS OF PROGRAM "PCMP"`, then `CALL "PPTR" AS NESTED USING BY CONTENT
PP`, and PPTR's `IF LPP = NULL` prints `PP-NULL`. `SET PP TO ENTRY "PCMP"` (`sweep.cob`) does the same. When the
literal names a separately compiled program in the same source file (`pp.cob`, PB1632Q), the pointer is set, and
both BY CONTENT and BY REFERENCE deliver `PP-SET`. So only resolution of a CONTAINED program's name is wrong.
Passing the pointer is not.

## Rule (to derive before fixing)
§14.9.39 Format 9 (program-pointer-assignment) with identifier-8 = `ADDRESS OF PROGRAM`. Derive and `cite.py
--check` the name-scope rule the literal follows: is it the CALL rule, under which a directly contained program is
callable, or only the separately compiled programs? If contained programs are in scope, NULL is a wrong answer. If
they are not, the source violates a rule, and the answer is a diagnostic, never a silent NULL. Also settle whether
the `ENTRY` spelling is ISO at the targeted edition, or an extension that leaks at `--std 2023` (R43).
