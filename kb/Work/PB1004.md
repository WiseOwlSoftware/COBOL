# PB1004 — LANDED

## Landed (wave 54, 2026-09-22)

Re-probed first on the implementer's own build (base train-50 head `25faf9f60`, which carries PB941): `p4_gr14`
printed `LEN0=[]` / `GR14-RMZL-ESCAPED` while `p4_ctl` aborted on EC-BOUND-REF-MOD — the note held. A TURN
sibling held too: a `>>TURN … CHECKING ON` written in a WHEN phrase stayed in force after END-PERFORM (the new
golden's L3 printed `OVF=1` on the pre-fix build).

The two implicit ops of §14.9.28.4 GR14 are now ordinary `DirectiveStackOp`s through the ONE directive-state stack.
`ExceptionPerformDirectiveScope.ImplicitOps` (Binding) walks the parse tree once before binding and places, for
every exception-checking PERFORM (the shared `ControlFlowBinder.IsFormat3` discriminator), a PUSH ALL at
imperative-statement-1's last line and a POP ALL at the END-PERFORM line, in token order. `DirectiveResults.
WithStackOps` replays them with the written >>PUSH/>>POP into EVERY `DirectiveTimeline` (TURN, REF-MOD-ZERO-LENGTH,
FLAG-02/14). To make that a replay and not a patch, a timeline now keeps its events AND its op program: the three
post-COPY stages only COLLECT (`DirectiveEventLog.Add(row, line, ev)`) and `ToTimeline(ops)` replays through
`DirectiveStateStack` — the same code path the binder's `WithStackOps` re-runs with the merged program.
`ExceptionPerformDirectiveScopeTests` pins handler / imperative-statement-1 / FINALLY / nested / explicit-pairing /
Format-2 cases and a DRIFT test that every `DirectiveTimeline` member of `DirectiveResults` is replayed. After the
fix `p4_gr14` aborts exactly as `p4_ctl` does. Golden `2023/pb1004_gr14_implicit_push_pop_all` (L1 RAISED, L2 NONE
control, L3 OVF=0). Row GR-14.9.28.4-14 re-verdicted CONFORMS with the new witnesses.

Not in this note's mechanism (reported as a lead): the PRE-PARSE directive states — SOURCE FORMAT in the normalizer,
DEFINE and the frontend-inline FLAG options in the conditional-compilation driver — are settled before any parse
tree exists, so the implicit POP ALL cannot restore a `>>SOURCE` or `>>DEFINE` written in a WHEN phrase.

covers (§7.3.22), not only TURN.
