# PB1194 — OPEN

## The rule (every citation re-run by the registrar through `cite.py --check`)

> 3) The rewrite file connector shall have an open mode of I-O. If the open mode is some other value or the file is not open, the I-O status in the rewrite file connector is set to '49' …

`python scripts/spec/cite.py --check 14.9.35.4 "…"` → `OK  §14.9.35.4 3)  (General rules)`

## Refuter evidence — row `GR-14.9.35.4-3` (PARTIAL)

PARTIAL — The adjudicator's 'all three connector bodies test IsOpen FIRST' is true of the connector bodies but not of the statement: FileRegistry.RewriteShared runs ReleasePriorRecordLocks and the GR11 ConflictOnLockedRecord check BEFORE RewriteAnyOrg reaches the '49' test. For a connector that is NOT OPEN no sharing mode is in effect (9.1.15: 'Record locks are in effect' is a property of the opened sharing mode), so GR11's premise 'record locking is enabled for the rewrite file connector' does not hold and '49' is the only applicable status; the code returns '51' instead. (The INPUT-mode arm returning 51 is acceptable: there both GR3 and GR11 apply and 9.1.13.1 lets the implementor choose.) The goldens cited pin only the no-other-connector case.

**Code site.** src/Cobol.Net.Runtime/IO/SequentialConnector.cs#SequentialConnector.Rewrite; src/Cobol.Net.Runtime/IO/RelativeConnector.cs#RelativeConnector.Rewrite; src/Cobol.Net.Runtime/IO/IndexedConnector.cs#IndexedConnector.Rewrite; src/Cobol.Net.Runtime/IO/FileStatus.cs#FileStatusCode.DeleteRewriteNotOpenForIO

## What the fixer owes

In FileRegistry.RewriteShared test 'connector not open' (→ '49') before the lock-release and GR11 conflict path; the INPUT-mode arm returning '51' is acceptable (both GR3 and GR11 apply there; §9.1.13.1 lets the implementor choose). Sweep DeleteShared / WriteShared / ReadShared for the same ordering. The cited goldens pin only the no-other-connector case — add the not-open-with-another-holder leg.
