# PB1194 — LANDED

## The rule (every citation re-run by the registrar through `cite.py --check`)

> 3) The rewrite file connector shall have an open mode of I-O. If the open mode is some other value or the file is not open, the I-O status in the rewrite file connector is set to '49' …

`python scripts/spec/cite.py --check 14.9.35.4 "…"` → `OK  §14.9.35.4 3)  (General rules)`

## Refuter evidence — row `GR-14.9.35.4-3` (PARTIAL)

PARTIAL — The adjudicator's 'all three connector bodies test IsOpen FIRST' is true of the connector bodies but not of the statement: FileRegistry.RewriteShared runs ReleasePriorRecordLocks and the GR11 ConflictOnLockedRecord check BEFORE RewriteAnyOrg reaches the '49' test. For a connector that is NOT OPEN no sharing mode is in effect (9.1.15: 'Record locks are in effect' is a property of the opened sharing mode), so GR11's premise 'record locking is enabled for the rewrite file connector' does not hold and '49' is the only applicable status; the code returns '51' instead. (The INPUT-mode arm returning 51 is acceptable: there both GR3 and GR11 apply and 9.1.13.1 lets the implementor choose.) The goldens cited pin only the no-other-connector case.

**Code site.** src/Cobol.Net.Runtime/IO/SequentialConnector.cs#SequentialConnector.Rewrite; src/Cobol.Net.Runtime/IO/RelativeConnector.cs#RelativeConnector.Rewrite; src/Cobol.Net.Runtime/IO/IndexedConnector.cs#IndexedConnector.Rewrite; src/Cobol.Net.Runtime/IO/FileStatus.cs#FileStatusCode.DeleteRewriteNotOpenForIO

## What the fixer owes

In FileRegistry.RewriteShared test 'connector not open' (→ '49') before the lock-release and GR11 conflict path; the INPUT-mode arm returning '51' is acceptable (both GR3 and GR11 apply there; §9.1.13.1 lets the implementor choose). Sweep DeleteShared / WriteShared / ReadShared for the same ordering. The cited goldens pin only the no-other-connector case — add the not-open-with-another-holder leg.

## Landed (wave 73 group B, 2026-09-29)

**Re-probed first** on the w73b build, before the fix. Indexed connector FB (`LOCK MODE AUTOMATIC`) READs K001 and
so locks it. FA, on the same file, is never opened. `REWRITE RA` gave `51`, and the sibling `DELETE FA` gave `51`
too. After the fix both give `49`.

**Root cause.** The governed verbs ask `FileConnector.MutationTargetRecordId` which record the statement targets,
and then run the §9.1.16 conflict check against that record. The keyed arms named the key-area record whatever the
open state. The READ peeks already kept the opposite contract ("" when the read would fail before touching a
record, via `ReadOpenModeGuard`).

**The fix, in one place.** `MutationTargetRecordId` is now a non-virtual template on `FileConnector`, and it
answers "" unless the connector is open in the I-O mode. The organizations override `MutationTargetRecordIdCore`.
The rule itself is `FileConnector.MutationOpenModeGuard` (§14.9.35.4 GR3, §14.9.10.4 GR1, §9.1.13.7 9); each
`cite.py --check` OK). It replaces the five hand-written `!IsOpen || Mode != FileOpenMode.IO` copies in the
REWRITE and DELETE bodies of all three organizations.

**Sibling sweep (the other arms).**
- READ Format 1 and Format 2: already guarded, because the peeks return "" through `ReadOpenModeGuard`.
- DELETE RECORD: the same defect, fixed by the same template.
- WRITE: its lock pre-flight read `LocksEffective`, which ignored the open state. `LocksEffective` now answers
  false for a connector not registered open, per §9.1.15: the sharing mode holds "throughout the duration of this
  OPEN" (`--check` OK).
- DELETE FILE: its sharing retry now runs after GR13's '41'. Otherwise the host probe could not tell the
  connector's own handle from a foreign one, and `RETRY FOREVER` on an open connector would wait for ever. This
  sibling is the PB1163 change's own.

**For a connector open INPUT**, '49' and '51' both apply (§9.1.13.1). DOC-A.1-104 (2) ("preconditions in the order
the general rules state them") now names REWRITE and DELETE explicitly, so '49' is placed.

**Golden.** `2002/w73b_pb1194_mutation_open_mode_first` (indexed and relative; closed, INPUT, and the I-O `51`
control) is the positive. `negative/w73b-pb1194-lock-mode-at-85` is its edition floor. Row `GR-14.9.35.4-3` is
re-verdicted CONFORMS, and `GR-14.9.10.4-1` gained the witness (batch `w73b-pb1194-mutation-open-mode-first`, GAP
863 → 862).
