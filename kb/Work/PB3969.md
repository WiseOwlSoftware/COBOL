# PB3969 — a Format-1 CALL sends a computed numeric operand to a numeric formal as zero

**Sites:** `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/CallEmitter.cs#ArgCarrierText` (the `BoundComputedOperand expr` arm
with `ReceiverContext.None`) and the callee's `CobolArgAdapt` Format-1 adaptation (`src/WiseOwl.Cobol.Runtime/Control/CallAbi.cs`).

Filed 2026-10-27 by the enqueue unit's clerk from the PB3760 branch review report (the implementer's lead, carried
unchanged). Not re-probed by the clerk.

## Repro (measured by the PB3760 implementer)

- `E:/COBOL-coord/scratch/w20261720e/q6.cob`: `CALL "Q6X" USING BY CONTENT FUNCTION MAX(W 0)` with `W` = 1.25; the
  callee's formal `PIC S9V99` shows `+0.00`.
- `E:/COBOL-coord/scratch/w20261720e/q5.cob` and `q5b.cob` (`--permissive`): `BY CONTENT (1.25 + 0)` gives `+000.00`.

## Mechanism (suspected, from the report's named site)

The computed operand is rendered without a receiver (`ReceiverContext.None`) and adapted by `CobolArgAdapt`'s Format-1
path; the value is lost between the two. Pre-existing on main.

## Related, distinct (both landed)

- PB3677: a STANDARD-DECIMAL function evaluated receiver-less with 6 fraction digits (the same arm, a different loss).
- PB1113: cross-reference only; a different mechanism at the same call-argument carrier.

Fix at the root: one Format-1 numeric-operand path, a golden per repro above, and a sweep of the sibling arms.

## Landed (2026-10-27, wave 20261728 group H)

Re-probed on a fresh build: `q6.cob` showed `F [+0.00]` for `FUNCTION MAX(W 0)` (and `+0.00` for `FUNCTION INTEGER(W)`, which
should be 1.00); a wider probe showed `B [000.00]` (PIC 9(3)V99), `C [+8084644.32]` (COMP) and `D [00000]` (PIC X(5)) for the same
value. `q5b.cob` (`--permissive`, an expression BY CONTENT) shows the same `+000.00`; the note's `q5.cob` is refused without
`--permissive` (COBOL0899, an expression is Format 2), as 14.9.4.2 says.

**Mechanism (the suspicion was wrong about the emitter).** `ArgCarrierText`'s computed arm is right: the value crosses as an
`Int128` cell at its scale with a 38-digit profile. The loss is in the callee: a Format-1 CALL is GR9's FIRST regime, whose BY
CONTENT argument "passes untouched" (`ProgramTable.LandArguments` skipped it unless the program had a program-specifier), and a
DISPLAY numeric formal's adapter (`CobolArgAdapt.Text`) reads the argument's IMAGE, here the first 3 characters of a 38-digit
zoned image, all zeros. A COMP formal read the same image's bytes as a binary number (garbage) and a PIC X formal read the zeros.

**Spec.** 14.2.3 GR9 moves an argument "without conversion" into a record "of the same length as the argument", but a numeric
function's returned value has no representation to move: 15.4 "a returned value in a temporary elementary data item", 15.4.1
"the characteristics and representation of the returned value are defined by the implementor" (native arithmetic). Implementor
latitude, so the owner's precedence applies (ISO controls only up to the latitude; GnuCOBOL's function field is its internal
representation, no rule). The determination (CONFORMANCE D-B4): the value is the sender and the formal the receiver, as in the
second regime (a COMPUTE without ROUNDED for a numeric formal) and in GR10.

**Fix at the root.** `MoveSending.Computed` marks a computed numeric value (`CobolArgAdapt.WithValueSending`'s fixed-point and
binary64 arms, `NumericSending`, hence `SdidiValue`); `ProgramTable.LandArguments` lands a BY CONTENT argument so marked through
the formal's registered landing in both regimes, as it lands every BY VALUE one. A plain-group formal registers no landing and
keeps the value's digits (D-B4, unchanged). Sweep: every producer of an evaluated cell (`ArgWithValueSending` is called from
`WithMoveSending` only; the INVOKE lane and a compile-time-known CALL formal land at the caller), the SDIDI cell, the binary64 cell,
dynamic `CALL name`, float / edited / packed / PIC X / group formals (all probed correct).

Golden: `pb3969_format1_numeric_function_value` (accepted from COBOL-85, the CALL BY CONTENT of 14.2.3 GR9 is an 85 rule; no
program is refused below it). `ComputedArgumentSendingTests` (5 facts). Docs: CONFORMANCE D-B4, INTERPROGRAM_DESIGN. Closes no
inventory row.
