# PB2502

Filed by the w1033 clerk from the PB850 refuter (`E:\COBOL-coord\scratch\w1033-adj\PB850-refute.md` section 5, "A new lead outside PB850").
The refuter did not decide whether the RENAMES key is legal; either answer leaves a defect (a crash). If the adjudication finds the THRU form
legal, the fix is to implement it; if not, the fix is a compile-time refusal. The file states no severity; MINOR is the register default
and the operator may raise it (the harm is a run-time abort).

**Observed (pinned build `pin-97006f3`).** Naming a level-66 RENAMES item in RECORD KEY compiles clean, then aborts at run time:

    NotImplementedCobolFeatureException: ... indexed file '...::F': RECORD KEY missing or not locatable in the record image (ISO §12.4.5.12)

It happens with the THRU form and the alias form (no THRU), and with an edited item or a plain `PIC X(5)` item. Probes in
`E:\COBOL-coord\scratch\w1033-adj\PB850-refute\`: `rk_renames_thru.cob`, `rk_renames_alias.cob`, `rk_renames_plain.cob`,
`rk_renames_alias_plain.cob` (`probe-renames-control.txt`). The abort is raised from `KeyedIoEmitter.cs:65`.

**Spec (cite.py --check OK per the refuter).** `§13.18.45.4 GR2`: "When the THROUGH phrase is specified, data-name-1 defines an alphanumeric group
item", so a THRU alias meets `§12.4.5.12.3 2)` ("category alphanumeric or category national within a record description entry"). Two rules treat a
RENAMES entry as part of the record description entry: `§13.18.24.3 SR2` and `§13.18.45.3 SR2` (the entries "immediately follow the last data
description entry of the associated record description entry"). So the THRU-form key is plausibly legal source. The alias form (no THRU) is a
different data item over the same storage (compare PB602); its legality as a key is not decided in the file. Related: `PB850`.
