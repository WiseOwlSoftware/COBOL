# PB3541 — a retired connector stays CommitControlled

## Lead

A connector stays `CommitControlled` after its clause is retired (the file closed, then a COMMIT executed) and the clause
is deactivated, so "item 8" (the unconditional ROLLBACK of a fatal exception condition on a file subject to an active
APPLY COMMIT clause, §14.6.13.1.3 item 8) and the AUTOMATIC lock posture still apply to it.

Code site: `src/Cobol.Net.Runtime/IO/TransactionControl.cs#Commit` and `src/Cobol.Net.Runtime/IO/FileRegistry.cs#RegisterCommitControl`
(there is no inverse of the registration).

The report gives no separate repro; the implementer or adjudicator writes one when taking the note.

## Repro (wave 1157, group A)

`E:/Temp/claude/E--COBOL/8bd1c3d3-6c48-4db9-ada1-5e4edea40828/scratchpad/w1157/w1157a/p3541/p1.cob`: a main program whose
clause names only WS-X calls a subprogram whose clause names the EXTERNAL RELATIVE file RELF, CANCELs it and COMMITs (the
COMMIT deactivates the subprogram's clause), then writes record 1 of RELF and executes a ROLLBACK. On 07bfc3606:
`AFTER ROLLBACK WS-X=0001` / `RECORD 1 ABSENT FS=23`: the ROLLBACK undid a change made through a connector no active clause
names. Expected (§14.9.36.4 GR3, *"All files and data-items referenced in active APPLY COMMIT clauses are restored"*):
record 1 present.

## Landed (wave 1157, group A)

`TransactionControl` keeps the file connectors each participant put under commit control, and its one
`DeactivateRetired` (run by a successful COMMIT, §14.9.7.4 GR3, and by every ROLLBACK, §14.9.36.4 GR6) takes each file a
deactivated clause named that no remaining active clause names out of commit control through
`FileRegistry.ReleaseCommitControl`, the new inverse of `RegisterCommitControl`: `KeyedConnector.CommitControlled` cleared
and the file control entry's own record-locking posture put back (the registration now records it). A transaction whose
rollback the medium refused stays owed (it is found by its open transaction id, not by the flag). Witnesses:
`unit:TransactionControlTests.A_file_whose_last_clause_is_deactivated_is_no_rollbacks_and_no_item_8s` (COMMIT and ROLLBACK
arms, RELATIVE and INDEXED: the file's later changes survive a ROLLBACK, item 8 is not due on its fatal status, the other
clause's file and item are rolled back), `unit:TransactionControlTests.A_deactivated_clause_gives_the_file_its_declared_lock_posture_back`
(the entry's LOCK MODE IS MANUAL back: another connector reads the record '00' where the AUTOMATIC posture answered '51';
RED on a mutant that keeps the AUTOMATIC share), the deactivation assertions added to
`unit:TransactionControlTests.A_retired_clause_is_not_restored_and_the_next_statement_deactivates_it`, and
`conformance:cases/14.9.7-COMMIT/pb3541_deactivated_clause_releases_its_file` (RED on a mutant that skips the release:
`RECORD 1 ABSENT`).

## Landing

- `src/Cobol.Net.Runtime/IO/TransactionControl.cs#DeactivateRetired` — the ONE deactivation (successful COMMIT, every
  ROLLBACK, refused or not); a participant carries `Files`, the connectors it registered; reuse it for any other
  per-clause state that must end with the clause. Trap: `HostFileProbeDriftTests` reads any `.Exists(` under
  `Runtime/IO` as a presence probe, so a collection test there is written as a loop (`NamedByAnActiveClause`).
- `src/Cobol.Net.Runtime/IO/FileRegistry.cs#ReleaseCommitControl` — the inverse of `RegisterCommitControl`, which now records
  the entry's own share in `_shareBeforeCommitControl` (forgotten by `CloseDisplaced`). An owed transaction is found by
  `TransactionHolders` (open transaction id), never by `CommitControlled`, so clearing the flag cannot strand it.
- Witnesses: `TransactionControlTests.A_refused_rollback_that_deactivates_the_clause_leaves_the_files_transaction_owed` (the
  refused arm) beside the three named above.
