# PB1942 — OPEN

Filed by the train-1007 lander from wave 1007 group C's report (`w1007c-PB1231-report.md`, "New defects" item 2).
Same root as [[PB780]] (SR-13.10.3-2 is a whole-language admission; each violating literal position is its own
defect, as [[PB778]] is for EDITING).

## Defect

```
       SPECIAL-NAMES.
           CURRENCY SIGN IS KC.
       ...
       01 KC CONSTANT AS "E".
```

draws COBOL0305 (parse error) at `KC`. §13.10.3 SR2: "Except in a compiler directive, constant-name-1 may be used
anywhere that a format specifies a literal of the class and category of constant-name-1" (`cite.py --check 13.10.3`
→ `OK §13.10.3 2)`), and the CURRENCY SIGN clause of the SPECIAL-NAMES paragraph (§12.3.7) writes its operand as a
literal. The fixer confirms the literal's class and category in the rendered §12.3.7 general format. Note the ordering question too: SPECIAL-NAMES precedes the DATA DIVISION, so the constant is declared
after its use — [[PB1231]]'s declare-before-bind walk covers data-division readers, not the environment division.

[[PB1231]]'s note (sweep item 5) routed these SPECIAL-NAMES positions here rather than to its ordering fix; the
same probe applies to `SYMBOLIC CHARACTERS` and `CLASS … IS` with a constant operand, which the fixer sweeps with it.

## Repro

A program with `CURRENCY SIGN IS KC.` in SPECIAL-NAMES and `01 KC CONSTANT AS "E".` in WORKING-STORAGE.

## Code site

The SPECIAL-NAMES currency clause in `src/Cobol.Net.Frontend/Grammar/Core/` (the CURRENCY SIGN rule accepts a
literal only) and its binder in the SPECIAL-NAMES binding (DataBinder.Switches.cs / the currency-sign reader).
