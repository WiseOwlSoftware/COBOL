# PB3453 — staged-source publish race: sharing violation reading a content-hashed source

> ⚙ **flags:** process-only

**Sites:** `tests/Cobol.Net.Tests.Conformance/CompiledProgramCache.cs` (`StageSource`, `StageFile`), `src/Cobol.Net.Frontend/Pipeline/CompilationInputs.cs` (`ReadAllText`, line 43).

**Witness (measured).** The clerk branch `notes-enqueue-leads-20261019-1915` (notes only: kb/Work/PB3452.md, kb/Work/PB3124.md, one DEVLOG pending file) at tip 545262d6b, gate run `20261020T020928Z-40c4d5` (2026-10-20 about 02:10Z): `BUILD-LOCAL GATE: LEG 1 ONLY (batched gating, PB2515): RED — Conformance leg 1 RED`. Exactly one failed case (leg-1-Conformance.trx): `ConformanceSuiteTests_P3.WiseOwlRefusal_RefusesTheSourceWithItsDiagnostic(id: "pb1078-assign-literal-shape", edition: "2002")`, `SuiteHarnessException: the compiler crashed on pb1078-assign-literal-shape at 2002: System.IO.IOException: The process cannot access the file '...\.cache\compiled-programs\src\09bddb74555a8f544965469d8d77f919\pb1078-assign-literal-shape.cob' because it is being used by another process.` Stack: `File.ReadAllText` <- `CobolNet.Frontend.CompilationInputs.ReadAllText` (CompilationInputs.cs:43) <- `Frontend.Parse` (Frontend.cs:92) <- `CompilerDriver.Compile` (CompilerDriver.cs:136) <- `CompiledProgramCache.CompileCold` (CompiledProgramCache.cs:110) <- `ConformanceSuiteRunner.Compile` (ConformanceSuiteRunner.cs:200). The branch changes no code, so the red is not its own.

**Mechanism (hypothesis for the implementer to confirm with a stress repro).** `CompiledProgramCache.StageSource` (CompiledProgramCache.cs:130-169) keys the staged directory on the file name and the program text only (lines 143-146), so every edition of one case stages into ONE directory. `StageFile` (lines 160-168) returns at once when `File.Exists(target)` and otherwise writes a temp file and `File.Move`s it into place. On Windows the rename runs on a handle opened with DELETE access, and the new name is visible before that handle closes. A second case in that window sees the file exist, compiles it, and `File.ReadAllText` opens it with `FileShare.Read` only. A file another handle holds with DELETE access can be opened only with FILE_SHARE_DELETE, so the open fails with a sharing violation. No code in the harness or the compiler holds the file exclusively (grep of `FileShare.None`, `new FileStream(`, `File.Open(` across the conformance test project, src/Cobol.Net.Frontend and src/Cobol.Net.Compiler found only `maintain.lock` exclusive). An antivirus or indexer handle is the alternative cause; the repro decides between them.

**Harm.** A gate red that passes alone (a timing failure is a failure, owner rule): it stopped a notes-only landing and cost a re-gate. No user program is affected.

**Fix shape (for the implementer to confirm).** The read side tolerates the publish: the harness and the compiler's input reader open with `FileShare.ReadWrite | FileShare.Delete`, the same rule PB1583 applied to the drift test's sweep. Whether the compiler's own inputs need it (a source renamed into place by a build tool while the compiler reads it) is a product question to settle in the fix; or the stager publishes so that no reader can see the name before the rename handle closes. The fix needs a self-test that stages one program from N parallel tasks and compiles each the moment it returns, run enough times to show the red before the fix. No retry loop that hides the cause (CLAUDE.md rule 4).
