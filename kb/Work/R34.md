# R34 — COPY REPLACING does not reach text included by a NESTED COPY: the §7.2 recursive replacement never materializes the replaced name

> Found by the R21+R22+R30 battery's differential leg (2026-08-08): flips `syn_copy:630` ("COPY:
> recursive replacement") and `listings:996` (same construct in the listings family), AGREE_ACCEPT →
> WE_REJECT_THEY_ACCEPT carrying COBOLNET1639 "'COPY-VAR' is not defined".

THE CASE: `copy-1.inc` contains only `COPY "copy-2.inc".`; `copy-2.inc` declares `01 TEST-VAR PIC X(2)`.
The program writes `COPY "copy-1.inc" REPLACING ==TEST-VAR== BY ==COPY-VAR==.` and references COPY-VAR.
ISO §7.2.3: the REPLACING phrase operates on the library text the COPY statement introduces — including
text a nested COPY brings in — so TEST-VAR must arrive as COPY-VAR. Our preprocessor either does not
recurse under REPLACING or recurses without applying the outer replacement to the inner text: COPY-VAR
never exists, the reference is undefined, and since R30 the program is REJECTED (before R30 it compiled
clean and was silently broken — the reference staged and would have thrown at run time, so the defect
predates the diagnostic that exposed it).

MEASURE FIRST: which of the two mechanisms it is (no recursion vs. recursion outside the replacement
scope), and whether the plain nested COPY WITHOUT replacing works. Cite §7.2.3's operative GR on the
replacement scope before fixing.
