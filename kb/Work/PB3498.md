# PB3498 — the refused second attempt of FileConnector.Open is unpinned

Lead R1-1 (low) of the branch review of PB3482 (`E:/COBOL-coord/scratch/reports/w1140c-PB3482-report.md`).

`src/Cobol.Net.Runtime/IO/FileConnector.cs` about line 802: the path where the SECOND attempt of `FileConnector.Open` is itself refused has no test. The report's owner test requirement says "no constructible case"; the reviewer showed it is constructible. Unpinned: status 61 after two attempts, `RetakeKeptFileLock` on the second failure only, and no third attempt.

**Fix shape (I11, abnormal path).** Construct the case; assert the '61', the restored kept lock and that no third attempt is made (count the host's requests). Sweep the sibling attempt loops for the same unpinned arm.

**Sites:**
- `src/Cobol.Net.Runtime/IO/FileConnector.cs` (read; unchanged: the behaviour was correct)
- `src/Cobol.Net.Runtime/IO/Sharing/RunUnitFileLock.cs` (the `HostObserver` test seam)

## Landed

Re-probed: the behaviour was already right; the witnesses were missing, and the PB3482 report's "no constructible case"
was wrong. On a real host no outside handle can refuse the second attempt (its `ReadWrite` share mode admits everything
compatible with the INPUT opener it needs), so the case is built where it can occur: a third run unit publishing a column
between the attempts, and a kept-handle re-OPEN refused by an outside reader's share mode on both attempts. A new seam,
`RunUnitFileLock.HostObserver` (with the test helper `ColumnRequestLog`), counts the host's column requests.

- `FileLockPostureDriftTests.AnOpenWhoseSecondAttemptIsRefusedTooAnswers61AfterExactlyTwoRequestsAndLeavesNothingBehind`
  (all three organizations): '61', exactly two requests, the file as it was, nothing left behind; the control succeeds.
- `CommitRollbackRuntimeTests.A_reopen_refused_on_its_second_attempt_too_keeps_what_the_close_kept_and_makes_no_third_attempt`
  (both keyed organizations, with and without a third run unit racing the second attempt): '61', four requests (replace,
  restore, replace, restore) or three, the kept column and handle as the CLOSE left them, no third attempt.
- Sibling sweep: `HandleColumnLockHostDriftTests.APublicationThatEveryTryCollidesInIsUnavailableAndLeavesWhatWasHeldStanding`
  (the publication's 64 tries exhausted: `Unavailable`, not a refusal; nothing leaked; the superseded column stands).
  `SidecarLockFiles.Publish` exhaustion and `FileRegistry.RetryLoop` were pinned already.

Mutations run: a third attempt, the kept column not restored after an unsuccessful attempt, and the exhausted publication
answering `Refused` each turn the matching witness red.
