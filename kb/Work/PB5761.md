# PB5761 - a TYPE-declared pointer record in a shared record area is refused COBOL0899

**Sites (lead, from the writer):**
- `src/WiseOwl.Cobol.Compiler/Binding/CommunicationSectionBinder.cs#BindEntry` line 166-167: `written.Append(area).Where(r => !FileModel.IsOutOfLineRecord(r))` decides which CD records implicitly redefine the area.
- `src/WiseOwl.Cobol.Compiler/Binding/Model/FileModel.cs#IsOutOfLineRecord` (`record.IsElementary && SlotWindow.CarriedBySlot(record)`), and the FD record-area path that asks the same: the suspected cause is that a pointer usage which arrives through a TYPE clause is not yet visible when the question is asked, so the record stays on the implicit-redefinition path and the shared-area screen refuses it. PB5604 fixed the `USAGE POINTER` spelling only.

**Rules (each checked with `python scripts/spec/cite.py --check`, verdict OK).**

- `§2002:14.8.3.2 SR4`: "If data-name-2 references a restricted data-pointer, data-name-1 shall be specified and shall reference a typed data item, and the data item referenced by data-name-2 shall be restricted to the type of data-name-1."
- `§2002:A.1.2.2 SR9`: "Record description entries subordinate to an output CD entry implicitly redefine the record area"
- `§2002:13.16.55.2 SR4`: "the subject of the entry shall not be implicitly or explicitly redefined" applies only "If type-name-1 is described with the STRONG phrase"; PTR-T is not STRONG, so CP may be a CD record.

**Expected (2002 text):** accepted; the run prints `CP SET` and `F=0000`.

**Observed**, on the golden-2002-8 build (main 5e49d46678), `cobol.exe sr4cd_ok.cob --std 2002 --run`: rc 65,
`sr4cd_ok.cob(10,8): error COBOL0899: the record area of 'CP' is shared — the record description entries following a CD entry implicitly redefine its record area (ISO/IEC 1989:2002 A.1.2.2) — and 'CP' is of a pointer class, whose value rides the storage area's managed slots ... a shared record area of that shape is recognized but not yet implemented`.
The FD sibling `fdtyped.cob` (`01 RP TYPE PTR-T` as a second FD record) is refused the same way (COBOL0899, then COBOL2364 at each reference), while `fdusage.cob` (`01 RP USAGE POINTER` there) runs and prints `RP NULL`.

**Repro** (`E:\COBOL-coord\scratch\gl2002\integrate-8\repro\alloc\`, from the writer's `lane1\run\g2002u-14-8-3-allocate\src\`): `sr4cd_ok.cob`, `fdtyped.cob`, `fdusage.cob`.

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. G2ALC4C.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 TPT TYPEDEF STRONG.
          05 F PIC 9(4).
       01 PTR-T TYPEDEF USAGE POINTER TO TPT.

       MAIN.

```

**The golden this blocks.** `2002-SR-14.8.3.2-4`, whose CD reach this refusal blocks (its writer drafted no golden for it); golden-2002-8 landed the neighbouring `g2-allocate-strong-group-cd-unrestricted` for `2002-SR-14.8.3.2-5` only. The fix's golden is `sr4cd_ok.cob` with its output and the FD sibling at 2002 and 2023.
