# PB1566

Found 2026-09-24 by the w59d (PB1041) implementer; a result-RANGE mechanism, distinct from PB1041's argument
narrowing. Repro `<scratchpad 9db39f61…>\w59d\b19ex.cob`. Derive from §15.34.1 / §15.35.1 (cite.py --check) what the returned value's type is and
whether a value past binary64 is representable there, or is an EC (EC-SIZE / EC-ARGUMENT-FUNCTION); then fix the carrier or
raise the EC — never print Infinity for a COBOL numeric result.

## Landed (wave 59, w59l)

Re-probed on the w59l build first: `DISPLAY FUNCTION EXP(1000)` printed `Infinity`, and `COMPUTE F = FUNCTION EXP(-1000)
ON SIZE ERROR` (COMP-2 F) took NOT ON SIZE ERROR with F = 0. DETERMINATION, derived rather than inherited: §15.34.1 /
§15.35.1 fix no representation ("returns an approximation of the value"), and under native arithmetic §15.4.1 makes
"the characteristics and representation of the returned value" the implementor's — COBOL.NET's is binary64
(CONFORMANCE.md DOC-A.1-92). So this note's premise that the result carrier is the SDIDI does not hold under native;
a value past binary64 is outside the native intermediate's range, which §14.7.5 case 5 makes the size error condition
(checked — DOC-A.1-179), EC-SIZE-OVERFLOW / EC-SIZE-UNDERFLOW by the no-phrase rule 3. Under a standard mode the
SDIDI's own range already answers that way (§8.8.1.5.2 r2). ISO controls, so the precedence rule's GnuCOBOL latitude
step was not reached. FIX: ONE check, `CobolIntrinsics.InBinary64Range`, raising `CobolSizeError` exactly as FACTORIAL
does past the Int128 intermediate — on every EXP / EXP10 carrier (a finite argument's ±∞ is the overflow; e^x is never
zero, so its 0 is the underflow; a subnormal is in range; a non-finite ARGUMENT keeps DOC-A.1-70) and on every PB1565
list body's narrowed result. DOC-A.1-179 gains the fifth checked place. Golden
`tests/conformance/2002/pb1566_exp_result_range`; the existing `negative/pb1041-exp-before-2002` is the edition
negative. ⚠ General native binary64 ARITHMETIC (`COMPUTE F = C * C`, `C ** 2`, `C / 1E300 / 1E300 / 1E300` over COMP-2
items) still stores ±Infinity / 0 with NOT ON SIZE ERROR — a separate mechanism (NumericRenderer's Real lane), reported
as a lead, not fixed here.
