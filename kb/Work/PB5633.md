# PB5633 - an empty section's DEBUG-LINE has no test

**Sites:**
- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/ProcedureTableBuilder.cs:102` (`ProcedureTableBuilder.AddEmptyAnonymousParagraph`)
- `docs/conformance/3/D-DEBUG-PROCEDURE.md` (whole: the entry that records the choice)

**Gap.** kb/Work PB5568 (landed) gives an empty section a paragraph-name-omitted paragraph so a USE FOR DEBUGGING section
runs before it. §1985:XV.3.2.4 GR12 leaves the identification of the subject's line to the implementor; the implementor
choice, recorded in `docs/conformance/3/D-DEBUG-PROCEDURE.md` and the code (`_paraLine[^1] = section.HeaderLine`), is that
DEBUG-LINE is the section header's line. Both PB5568 goldens display only `DEBUG-NAME(1:2)` and `DEBUG-CONTENTS(1:5)`, so
no test names DEBUG-LINE of an empty section, and changing the value leaves the gate green.

**Fix direction.** Add a golden (or a unit test over the table builder) whose debugging section displays DEBUG-LINE for a
PERFORM of an empty section and for fall-through into it, with the expected value derived from the choice file. A
documented choice must have a test that would fail if it changed (CLAUDE.md rule 1, implementor-latitude entries).

**Not filed.** Whether the empty-section pc should be uniform across every program so `PcRange.IsEmpty` for sections can
retire: it redesigns PB440's pinned contract and nothing observable needs it.
