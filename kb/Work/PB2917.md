# PB2917 — an unreadable foreign lock file counts as free

Filed 2026-10-10 by the train 1052 lander (phase 1b) from the wave 1052 B implementer's report
(`E:\COBOL-coord\scratch\reports\w1052b-PB2484-report.md`, "New defects" item 2; its self-review: "unreadable foreign
lock file counts as free").

**Where.** PB2484 (landing in train 1052) gave the §9.1.15 file lock a lock-file expression on every Unix other than
Linux: `SidecarColumnLockHost` publishes one file per holder beside the physical file and tests the others with an
exclusive open. The test is `HostFile.IsHeldByAnother`
(`src/Cobol.Net.Runtime/IO/FileSupport.cs#IsHeldByAnother`, about line 322), whose last arm is
`catch (UnauthorizedAccessException) { return false; }` (about line 333). Its caller
`SidecarColumnLockHost.TestOthers` (`src/Cobol.Net.Runtime/IO/Sharing/SidecarColumnLockHost.cs`, about line 133) reads
`false` as "a holder that was killed" and DELETES the file (`TryDelete`) and goes on.

**Failure scenario.** Two users share a directory they can both enter; user A's run unit opens the file with a sharing
mode that refuses B's request, under a umask of 077, so A's holder file is unreadable to B. B's OPEN reaches
`TestOthers`, the exclusive open throws `UnauthorizedAccessException`, the arm answers "not held", B tries to delete
A's holder file (and may succeed where the directory is writable to B) and B's OPEN is granted: the §9.1.15 1)-3) file
lock does not bind, silently. Cross-user only; same-user run units are unaffected.

**Repro.** Needs two OS accounts on a non-Linux Unix (or a Linux host forced onto the sidecar host through
`RunUnitFileLock.Take(host, ...)`, the overload the witness uses): account A opens a file `SHARING WITH NO OTHER` and
holds it with umask 077; account B opens the same file. Expected: B's OPEN fails with the sharing refusal; observed: it
succeeds. `SidecarColumnLockHostDriftTests` (tests/Cobol.Net.Tests.Unit) is the place for a unit witness: create a
holder file and deny read on it.

**Fix shape (one mechanism).** An access-aware variant for the lock-file host: an unreadable holder file is neither
free nor swept; `TestOthers` answers `RunUnitFileLock.Outcome.Unavailable` (as `Establish` already does for an
unauthorized directory, line 81) or refuses, by a determination recorded in CONFORMANCE.md. `IsHeldByAnother`'s other
caller (the delete path, §14.9.10.4 GR16) keeps its current answer, so the variant is the sidecar host's, not a change
of the shared probe.

**A second cross-user arm, the same mechanism (train 1052 lander's review, 2026-10-10; findings file
`E:\COBOL-coord\scratch\t1052\review-runtime.md`, C1).** The lock DIRECTORY is the first holder's:
`SidecarColumnLockHost.Publish` (`src/Cobol.Net.Runtime/IO/Sharing/SidecarColumnLockHost.cs`, about line 101) creates
`.wolk-<16hex>` with `Directory.CreateDirectory`, so at the default umask 022 it is mode 0755 and owned by user A. User B
can write the physical file's directory but not A's lock directory, so B's `Publish` fails, `Take` answers
`Unavailable` (the catch at about line 80) and B's OPEN is granted where §9.1.15 2) requires the refusal ('61',
§9.1.13.9 1)); Linux gives '61' for the same two users. The degradation the class documents ("a directory you may not
write") is the PHYSICAL directory's, not this one. Fix shape, with this note's: one determination of the sidecar host's
cross-user model (CONFORMANCE.md), then the lock directory takes the physical directory's permission bits when it is
created (`File.SetUnixFileMode` from the parent's `UnixFileMode`, about 8 lines) and an unreadable holder file is
refused, never swept. Repro: two OS accounts on macOS sharing a group-writable directory; A opens a file `SHARING WITH
ALL OTHER` and holds it, B opens it `SHARING WITH READ ONLY` for INPUT; expected '61', observed '00'.

**A third arm, the opposite answer: another tester's sweep read as a live holder (train 1052 lander's review, shard
runtime C2, 2026-10-10; findings file `E:\COBOL-coord\scratch\t1052\review-runtime.md`, C2).** Run unit X opens a
file clause-less I-O (column 0, NO OTHER) and is killed, leaving `.wolk-<16hex>/0-<guid>` with no lock behind it. Two
run units T1 and T2 then `OPEN INPUT` the file at the same moment; both request rows refuse column 0. T1's exclusive
test (`HostFile.IsHeldByAnother`, `src/Cobol.Net.Runtime/IO/FileSupport.cs`, about line 322) succeeds and holds
`LOCK_EX` while its probe stream is open; T2's exclusive test in that window is refused, so `IsHeldByAnother` answers
true and `SidecarColumnLockHost.TestOthers` (`src/Cobol.Net.Runtime/IO/Sharing/SidecarColumnLockHost.cs`, about line
134) returns `Refused`: T2's OPEN gets '61' where §9.1.13.9 1) requires a file "already open by another file connector
in a manner that conflicts", and a tester is not a connector. Narrow window, off Linux only (the Linux host uses OFD
locks), and it needs a crashed holder first. Harm: a spurious refusal (an OPEN that should succeed fails), never a
lost update.

*Fix tried and WITHDRAWN in the train.* The review's shape: a live holder only ever holds the SHARED lock
`HostFile.OpenLockHolder` takes and only a tester takes the exclusive one, so when the exclusive request is refused,
ask once more with a shared request (`HostFile.IsLockFileUnderSweep`: refused too, or the file already gone, means a
dead file under a sweep, skipped). Commit cc42e84c8 (train 1052 phase 2) added it in `TestOthers` before the
`if (!pending) return Refused` line, with the witness
`SidecarColumnLockHostDriftTests.ALeftoverFileUnderAnotherTestersSweepRefusesNobody`. It turned
`SidecarColumnLockHostDriftTests.TwoSimultaneousExclusiveTakes_NeverBothHold` RED on Linux in 10 of 10 reruns
(outcomes `[Unavailable, Held]`: one take's `Establish` answered Unavailable; repro
`E:\COBOL-coord\scratch\t1052\race.sh`, which reruns the test in the WSL gate clone), green before it, so commit
8dd7c0f88 withdrew the code. The mechanism was not found in that phase's budget. Leads for the next fixer: (a) the
re-probe also runs for a PENDING file (the line sits before the `pending` test), so a tester now holds a second,
shared stream on a racing publisher's half-published file while that publisher's own self-test (`Publish`'s
`IsHeldByAnother(pending)`) and rename run; (b) `Unavailable` from `Establish` means `Publish` returned null (its
self-test answered "not held", or all eight attempts lost) or an `IOException` escaped `TestOthers`; (c) rerun the
race test with the re-probe confined to non-pending files first. The fix belongs with this note's other two arms: one
determination of what the sidecar host's holder test reads as a holder.
