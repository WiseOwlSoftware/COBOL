## Finding — `sort-statement-p2` (rejects-legal-source; rows `GR-14.9.40.4-18`, `GR-14.9.40.4-24`)

**Mechanism.** A Format-2 table SORT whose SUBJECT lies in a REDEFINES group (table.Class is not null) binds to BoundUnsupported -- a COBOLNET1756 deferral that aborts the run unit with NotImplementedCobolFeatureException when reached -- although 14.9.40.3 places no REDEFINES restriction on data-name-2. Open PB599 owns only the KEY arm (a REDEFINES-view key), and PB1055 owns only the nested-OCCURS subject; this subject arm has no note.

**Repro.** 01 RAW PIC X(4) VALUE "3142". 01 VIEW1 REDEFINES RAW. 05 D PIC 9 OCCURS 4. -- SORT D ASCENDING. DISPLAY "R=" RAW. (out/probe/sort-statement-p2/predef.cob)

**Expected from the spec.** 14.9.40.4 GR18 'The SORT statement sorts the table referenced by data-name-2 and presents the sorted table in data-name-2 ... in the order determined by the ASCENDING or DESCENDING phrases' and GR24 (sorted elements placed in data-name-2); the storage is shared with RAW, so R=1234.

**Observed / reasoning.** Unhandled exception CobolNet.Runtime.NotImplementedCobolFeatureException: 'SORT of table D inside a REDEFINES class (typed-array Format-2 sort over a shared-storage view -- deferred)'.

**Code site.** src/Cobol.Net.Compiler/Binding/Procedure/Verbs/SortBinder.cs#SortBindTable (`if (table.Class is not null) return new BoundUnsupported(...)`)
