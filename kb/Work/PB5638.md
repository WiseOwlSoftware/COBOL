# PB5638 - the 1985 external-file FD agreement rule misses a clause present in only one describer

**Sites:**
- `src/WiseOwl.Cobol.Compiler/Binding/ExternalFileConnectorRules.cs:142` (`ExternalFileConnectorRules.CheckFileDescriptions`)
- `src/WiseOwl.Cobol.Compiler/Binding/FileDescriptionIdentity.cs` (whole: the one row per 1985 FD agreement rule)

**Why a new note and not PB5300.** kb/Work PB5300 (landed) is closed: `CheckFileDescriptions` now compares, across the
describers of one external file connector at `--std 85`, the FD clauses its rows name. This lead is a hole in that closed
mechanism, a different case: the comparison fires when both describers write the clause with different values, not when
one describer writes LINAGE and the other writes none.

**1. LINAGE in one describer only.** The PB5570 report: at `--std 85` a LINAGE clause present in only one describer of an
external group compiles with no diagnostic, and the program that writes a page-formatted file shares its connector with a
program that sees it as an unformatted one. Shares its root with `CheckFileDescriptions` (a clause absent from a describer
reads as "no value": `CheckFileDescriptions` does `if (FileDescriptionIdentity.Of(f, rule) is not { } mine) continue;`, so
a describer without the clause is skipped rather than compared). The 1985 rule is §1985:VII.3.7.4 GR11b ("the same
corresponding values for integer-1, integer-2, integer-3, and integer-4", `cite.py --check` OK; `FileDescriptionIdentity`
row `Linage`): a describer with no LINAGE is not the same specification as one with it. Whether an absent clause counts
as a disagreement is a reading of GR11 for the adjudicator. Repro: no probe path was kept; two programs in one source, the first with a
`LINAGE IS 10 LINES` FD, the second with none, both `EXTERNAL`, at `--std 85`.

**2. A separately compiled EXTERNAL describer.** An EXTERNAL describer in a separately compiled program is still compared
only when the connector is activated at run time, not at compile time, since no compilation group holds both. The same
holds for every row `CheckFileDescriptions` carries; record it as the documented limit in `docs/conformance/` or give the
runtime an agreed identity digest the activation compares.

**Fix direction.** After the adjudication of (1), compare an absent clause in `FileDescriptionIdentity` (one row each), then decide
(2) in a recorded decision note.
