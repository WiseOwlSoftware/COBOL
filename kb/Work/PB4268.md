# PB4268 — the BoundDeferredToExpansion exception opens with the construct's text

**Sites:** `src/WiseOwl.Cobol.Compiler/CodeGen/StatementEmitter.cs#Visit` (the `BoundDeferredToExpansion` overload: `$"{n.Construct}: a statement of an unexpanded parameterized definition ..."`),
`src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/OoBinder.cs#OoBindSetObjectRef` (records `SET … TO {sname}` as `BoundDeferredToExpansion.Construct`),
`tests/_shared/ElidedMessageOpening.cs#Source` (the head regex), `tests/WiseOwl.Cobol.Tests.Unit/DiagnosticOpeningElisionDriftTests.cs`.

**The defect (a lead from the PB4212 branch review, R1-1, low).** "R1-1 LEAD (low, not blocking at round 1): src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/OoBinder.cs:1983 The report says the sibling sweep left only mid-sentence labels and registry titles, but OoBinder records `SET … TO {sname}` as BoundDeferredToExpansion.Construct, and StatementEmitter.Visit(BoundDeferredToExpansion) (StatementEmitter.cs:288) puts that string at the head of its InvalidOperationException. That is the same class as FileRegistry.MisroutedVerb, a message raised only by a pipeline defect, which this branch did repair. The widened ElidedMessageOpening.Source cannot see it, because the head is a `{n.Construct}` hole followed by a colon."

**Fix direction.** Repair the message as the branch did FileRegistry.MisroutedVerb (the same class, raised only by a pipeline defect), and make the drift test able to see a head that is a `{n.Construct}` hole followed by a colon.

## Landed (wave 20261824 group B)

**Re-probe (2026-11-02, main 273328079).** The exception is raised only by a pipeline defect, so no source program reaches it; the defect read off the code is exact: `StatementEmitter.Visit(BoundDeferredToExpansion)` opened its message with `{n.Construct}:`, and `OoBinder.OoBindSetObjectRef` recorded the construct as `SET … TO {sname}` (an elided statement; the renderer prints U+2026 as `.`). `ElidedMessageOpening.Source` had no pattern for a hole head and did not read `NoteExpansionDeferred(` or `BoundDeferredToExpansion(` at all.

**Fix.** Two causes, both repaired. The message now opens with its own words and carries the construct mid-sentence, as the sibling `BoundRejected` message beside it does: `a statement of an unexpanded parameterized definition ({n.Construct}) reached code generation (kb/Work PB2937)`. The construct names its receivers as written (`SET {SetFormatSelection.Written(targetRefs)} TO {sname}`), the PB388 repair, since the text still reaches the message. `ElidedMessageOpening.Source` reads `NoteExpansionDeferred(` and `BoundDeferredToExpansion(` and has a second head, `ConstructHole` (a lone hole named for a construct, then its colon); `DiagnosticOpeningElisionDriftTests.ThePatternFiresOnEveryDefectShapeTheTreeCarried` pins the three defect lines the tree carried, their repaired twins and a `{where}:` label that must stay legal.

**Sibling sweep.** Every other `NoteExpansionDeferred(` / `BoundDeferredToExpansion(` construct (`INVOKE {predefined} "m"`, `the object property 'x' OF 'y'`, `an object property of SUPER`) names its words; the only `{…Construct}:` head in the tree was this one. The drift test passed over the whole tree after the pattern widened.

**Sites (landed):** `src/WiseOwl.Cobol.Compiler/CodeGen/StatementEmitter.cs` (`Visit(BoundDeferredToExpansion)`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/OoBinder.cs` (`OoBindSetObjectRef`), `tests/_shared/ElidedMessageOpening.cs` (`ElidedMessageOpening.Source`, `ConstructHole`), `tests/WiseOwl.Cobol.Tests.Unit/DiagnosticOpeningElisionDriftTests.cs` (`ThePatternFiresOnEveryDefectShapeTheTreeCarried`).
