# PB4500 — GnuCOBOL: an unanswerable REPOSITORY PROGRAM specifier is silent, and -Wprototypes reads the wrong option

## Summary

ISO/IEC 1989:2023 §12.3.8.3 SR14 (the same rule in 2014): the program-prototype-name of a REPOSITORY program-specifier
"shall be one of the following: the name of a program prototype specified in this compilation group; the name of a
program definition specified previously in this compilation group; the name of a program for which information exists in
the external repository." cobc 3.2 under `-std=cobol2014` compiles a specifier that is none of the three with no
diagnostic. Its own check exists (`-Wprototypes`, "no definition/prototype seen for PROGRAM") but is reached only when
`-Winitial-value` is also enabled, so `-Wprototypes` alone prints nothing; only `-Wall` shows it.

## Minimal test case

Written for this note (not taken from the GnuCOBOL testsuite):

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. REPOPROG.
       ENVIRONMENT DIVISION.
       CONFIGURATION SECTION.
       REPOSITORY.
           PROGRAM NOSUCHPROG.
       PROCEDURE DIVISION.
       MAIN-PARA.
           STOP RUN.
```

## Environment

GnuCOBOL 3.2.0 (`cobc (GnuCOBOL) 3.2.0`), Ubuntu under WSL2 on Windows 11, 2026-11-03.

## Observed result

- `cobc -fsyntax-only -std=cobol2014 repo.cob`: no output, exit 0 (also `-std=cobol2002`).
- `cobc -fsyntax-only -std=cobol2014 -Wprototypes repo.cob`: no output, exit 0.
- `cobc -fsyntax-only -std=cobol2014 -Wprototypes -Wno-initial-value repo.cob`: no output, exit 0.
- `cobc -fsyntax-only -std=cobol2014 -Wall repo.cob`: `repo.cob:6: warning: no definition/prototype seen for PROGRAM
  'NOSUCHPROG' [-Wprototypes]`, exit 0.

## Expected result (per ISO)

SR14 is a syntax rule (`cite.py --check 12.3.8.3 "the name of a program for which information exists in the external
repository"`: OK), so a conforming implementation reports its violation under the ISO dialect; and at the least
`-Wprototypes` alone should produce the warning that `-Wall` produces.

## Our compiler (WiseOwl)

COBOL5962 (REPO-1): "REPOSITORY PROGRAM NOSUCHPROG names no program: no program prototype of this compilation group and
no program definition specified before this paragraph is externalized ..., and no information exists for it in the
external repository ... — ISO §12.3.8.3 SR14", from the repository resolver (kb/Work PB2103).

## Fix site (GnuCOBOL 3.2 source, read observationally)

`cobc/tree.c`, `warn_if_no_definition_seen_for_prototype`: the warning is emitted under `cb_warn_prototypes`, but the
whole body sits inside `if (get_warn_opt_value (cb_warn_ignored_initial_val) != COBC_WARN_DISABLED)`, the option of
`-Winitial-value` (warning.def), which `cobc.c` disables unless it was enabled explicitly. The guard should read
`cb_warn_prototypes`. Whether the ISO dialects should make the finding an error is the second, separate question.

## Draft issue

**Title:** -Wprototypes alone never reports "no definition/prototype seen": the check is gated on -Winitial-value

In cobc 3.2, `warn_if_no_definition_seen_for_prototype` (cobc/tree.c) issues its warning under `cb_warn_prototypes`
but only inside `if (get_warn_opt_value (cb_warn_ignored_initial_val) != COBC_WARN_DISABLED)`, so `-Wprototypes` by
itself prints nothing for a REPOSITORY `PROGRAM NOSUCHPROG` that names no known program; only `-Wall` (which also turns
on `-Winitial-value`) shows "no definition/prototype seen for PROGRAM 'NOSUCHPROG' [-Wprototypes]". The guard looks like
it should test `cb_warn_prototypes`.

Related: ISO/IEC 1989:2014 (§12.3.8.3 SR14 in the 2023 numbering) requires the name to be a prototype or an earlier
definition of the compilation group or a program known to the external repository, so under `-std=cobol2014` this could
reasonably be an error rather than an opt-in warning.

Repro (9 lines) as above; compare `cobc -fsyntax-only -std=cobol2014 -Wprototypes repo.cob` with `... -Wall repo.cob`.
