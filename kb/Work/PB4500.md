# PB4500 — GnuCOBOL: an unanswerable REPOSITORY PROGRAM specifier is silent, and -Wprototypes reads the wrong option

## Summary

ISO/IEC 1989:2023 §2023:12.3.8.3 SR14 (the same rule in 2014): the program-prototype-name of a REPOSITORY program-specifier
"shall be one of the following: the name of a program prototype specified in this compilation group; the name of a
program definition specified previously in this compilation group; the name of a program for which information exists in
the external repository." cobc 3.2 under `-std=cobol2014` compiles a specifier that is none of the three with no
diagnostic. Its own check exists (`-Wprototypes`, "no definition/prototype seen for PROGRAM") but is reached only when
`-Winitial-value` is also enabled, so `-Wprototypes` alone prints nothing; only `-Wall` shows it.

## Minimal test case

Written for this note (not taken from the GnuCOBOL testsuite):

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. REPOPROG.
       ENVIRONMENT DIVISION.
       CONFIGURATION SECTION.
       REPOSITORY.
           PROGRAM NOSUCHPROG.
       PROCEDURE DIVISION.
       MAIN-PARA.
           STOP RUN.
```

## Environment

GnuCOBOL 3.2.0 (`cobc (GnuCOBOL) 3.2.0`), Ubuntu under WSL2 on Windows 11, 2026-11-03.

## Observed result

- `cobc -fsyntax-only -std=cobol2014 repo.cob`: no output, exit 0 (also `-std=cobol2002`).
- `cobc -fsyntax-only -std=cobol2014 -Wprototypes repo.cob`: no output, exit 0.
- `cobc -fsyntax-only -std=cobol2014 -Wprototypes -Wno-initial-value repo.cob`: no output, exit 0.
- `cobc -fsyntax-only -std=cobol2014 -Wall repo.cob`: `repo.cob:6: warning: no definition/prototype seen for PROGRAM
  'NOSUCHPROG' [-Wprototypes]`, exit 0.

## Expected result (per ISO)

SR14 is a syntax rule (`cite.py --check 12.3.8.3 "the name of a program for which information exists in the external
repository"`: OK), so a conforming implementation reports its violation under the ISO dialect; and at the least
`-Wprototypes` alone should produce the warning that `-Wall` produces.

## Our compiler (WiseOwl)

COBOL5962 (REPO-1): "REPOSITORY PROGRAM NOSUCHPROG names no program: no program prototype of this compilation group and
no program definition specified before this paragraph is externalized ..., and no information exists for it in the
external repository ... — ISO §2023:12.3.8.3 SR14", from the repository resolver (kb/Work PB2103).

## Fix site (GnuCOBOL 3.2 source, read observationally)

`cobc/tree.c`, `warn_if_no_definition_seen_for_prototype`: the warning is emitted under `cb_warn_prototypes`, but the
whole body sits inside `if (get_warn_opt_value (cb_warn_ignored_initial_val) != COBC_WARN_DISABLED)`, the option of
`-Winitial-value` (warning.def), which `cobc.c` disables unless it was enabled explicitly. The guard should read
`cb_warn_prototypes`. Whether the ISO dialects should make the finding an error is the second, separate question.

## Draft issue

**Title:** -Wprototypes alone never reports "no definition/prototype seen": the check is gated on -Winitial-value

As posted (owner-reviewed, 2026-11-03):

`-Wprototypes` does not turn on the warning it controls. For a REPOSITORY specifier that names a program cobc has never seen, the warning "no definition/prototype seen", tagged `[-Wprototypes]`, appears only when `-Winitial-value` is also enabled, either directly or through `-Wall`. The check that decides whether to warn tests the `-Winitial-value` option, so a user who passes `-Wprototypes` to get this warning gets nothing.

## To reproduce

`repo.cob` (attached):

~~~~
       IDENTIFICATION DIVISION.
       PROGRAM-ID. REPOPROG.
       ENVIRONMENT DIVISION.
       CONFIGURATION SECTION.
       REPOSITORY.
           PROGRAM NOSUCHPROG.
       PROCEDURE DIVISION.
       MAIN-PARA.
           STOP RUN.
~~~~

    cobc -fsyntax-only -std=cobol2014 -Wprototypes repo.cob
    cobc -fsyntax-only -std=cobol2014 -Wall repo.cob

## What happens

With `-Wprototypes`, 3.2.0 and 3.3-dev r5751 print nothing and exit 0. Adding `-Wno-initial-value` changes nothing.

With `-Wall`, both versions print the warning and exit 0:

~~~~
repo.cob:6: warning: no definition/prototype seen for PROGRAM 'NOSUCHPROG' [-Wprototypes]
    4 |        CONFIGURATION SECTION.
    5 |        REPOSITORY.
    6 >            PROGRAM NOSUCHPROG.
    7 |        PROCEDURE DIVISION.
    8 |        MAIN-PARA.
~~~~

On both versions, `-Wprototypes -Winitial-value` also prints it.

## What should happen

`-Wprototypes` alone prints the same warning as `-Wall`, and `-Winitial-value` has nothing to do with it.

The program does not conform. ISO/IEC 1989:2023 says (the 2014 edition has the same rule):

- §2023:12.3.8.3 syntax rule 14: "Literal-3, if specified, or program-prototype-name-1, if literal-3 is not specified, shall be one of the following:" the name of a program prototype in the compilation group, the name of a program definition earlier in the compilation group, or the name of a program for which information exists in the external repository.

`NOSUCHPROG` is none of these. So under `-std=cobol2014` the finding could be reported without a warning option at all, or as an error, which `-fprogram-prototypes=error` already makes it. That is a separate question from this bug.

## Why it happens

In `cobc/tree.c`, `warn_if_no_definition_seen_for_prototype` issues the warning with `cb_warning_x (cb_warn_prototypes, ...)`, but the whole body sits inside

~~~~
if (get_warn_opt_value (cb_warn_ignored_initial_val) != COBC_WARN_DISABLED) {
~~~~

`cb_warn_ignored_initial_val` is the option of `-Winitial-value` (`warning.def`). Both options are off by default and `-Wall` turns both on, so the mistake shows only when `-Wprototypes` is used without `-Wall`. These two `cb_warning_x` calls, one for a PROGRAM and one for a FUNCTION specifier, are the only uses of `cb_warn_prototypes` in 3.2.0 and in r5751, so the FUNCTION case is gated the same way (read from the source; the repro above covers PROGRAM).

## Proposed fix

The attached `prototypes-warning-gate.patch` is against 3.3-dev r5751 and applies with `patch -p1` at the top of the tree. It changes that one condition to test `cb_warn_prototypes`, the option the warning is issued under.

With the patch, `cobc -fsyntax-only -std=cobol2014 -Wprototypes repo.cob` prints the warning shown above and exits 0, and `cobc -fsyntax-only -std=cobol2014 -Winitial-value repo.cob` prints nothing and exits 0.

make check on 3.3-dev r5751 with the patch: 1373 behaved as expected, 9 skipped, 0 failed, as unpatched (1372) plus the new test 345, which passes; unpatched it fails. The patch adds the test "-Wprototypes without -Wall" to `tests/testsuite.src/syn_misc.at` (after "use of program-prototype-names"; it checks `-Wprototypes`, `-Wprototypes -Wno-initial-value` and `-Winitial-value`) and entries to `cobc/ChangeLog` and `tests/ChangeLog`.
