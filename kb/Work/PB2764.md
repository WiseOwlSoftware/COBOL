**Rule it breaks:** docs/CONFORMANCE.md DETERMINATION L12 (generalizing L10, kb/Work PB112 / PB64 T6): every LC_TIME pattern and LC_MONETARY string is normalized, Unicode Cf removed and U+00A0/U+202F/U+2009 mapped to the plain space, so a fixed COBOL text field never carries host-varying bytes; LocaleFacts.NormalizeLocaleText claims to be THE ONE normalization of locale-sourced text (LocaleFacts.cs:143-155)

**Scenario:** Measured on the pin build host (.NET 10.0.12, ICU): after NormalizeSpacing strips U+200F from the ar-* ShortDatePattern, the remaining d/M/yyyy pattern is formatted through the raw DateTimeFormat whose DateSeparator is U+200F + slash, so FUNCTION LOCALE-DATE("20261008" ar-EG) returns 8 U+200F / 10 U+200F / 2026 (28 ar-* cultures). FormatTime appends dtf.AMDesignator/PMDesignator raw, so FUNCTION LOCALE-TIME("093000" es-US) returns 9:30:00 a.<U+00A0>m. (es-CO, es-DO, es-PA, es-PH, es-PR, es-US, es-VE, yrl-CO, yrl-VE). The documented determination says those bytes are normalized; the program prints the invisible format character and the NBSP, which is exactly PB112 disease L10 was written to remove (the bytes follow the host ICU), and in a fixed-width alphanumeric receiver the U+200F consumes character positions. The time-fraction separator (facts.NumberFormat.NumberDecimalSeparator, CobolLocale.cs FormatTime) and TimeSeparator are read raw the same way.
