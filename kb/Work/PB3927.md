# PB3927 — numval-c-anycase-locale-keywords-not-supported--numval-c-locale: NUMVAL-C: LOCALE keyword refused ('syntax error, unexpected LOCALE')

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S9) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\numval-c-anycase-locale-keywords-not-supported--numval-c-locale.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\numval-c-anycase-locale-keywords-not-supported--numval-c-locale\`.

## Summary

GnuCOBOL 3.2 refuses the LOCALE keyword in the argument list of FUNCTION NUMVAL-C with
`syntax error, unexpected LOCALE`. The LOCALE form of NUMVAL-C (evaluate argument-1 by the LC_MONETARY category of the
current or a named locale) is in the NUMVAL-C general format of ISO/IEC 1989:2002 and of the 2014 committee draft, and
neither edition's optional-element list (Annex A.4) names it, so it is a required element of the edition
`-std=cobol2014` claims. Class: feature missing.

The fuzz witnesses hit the same refusal through TEST-NUMVAL-C (fz02040, fz04035, fz05446); that keyword is an optional
element and has its own record, `numval-c-anycase-locale-keywords-not-supported--test-numval-c-locale.md`. This record
covers NUMVAL-C, found by reducing them.

## Minimal test case

Free reference format (`-fformat=free`), 9 lines, written for this record.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. NVLOC.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 R PIC 99.99.
PROCEDURE DIVISION.
COMPUTE R = FUNCTION NUMVAL-C("12.50" LOCALE)
DISPLAY R
STOP RUN.
```

File: `E:\COBOL-coord\scratch\op\pb3838\records\numval-c-anycase-locale-keywords-not-supported--numval-c-locale.cob`.

The program is legal: the general format (§15.68.2, checked against the printed page) is
`FUNCTION NUMVAL-C ( argument-1 [ LOCALE [ locale-name-1 ] | argument-2 ] [ ANYCASE ] )`; LOCALE without locale-name-1
needs no SPECIAL-NAMES LOCALE clause.

## Environment

- `cobc (GnuCOBOL) 3.2.0`, Ubuntu package `gnucobol3 3.2-4build1`, WSL2 (Linux 6.18.54.1-microsoft-standard-WSL2 x86_64).
- Command: `cobc -std=cobol2014 -fformat=free -x nvloc.cob` (the default dialect gives the same).

## Observed result

Exit code 1:

```
nvloc.cob:7: error: syntax error, unexpected LOCALE
    5 | 01 R PIC 99.99.
    6 | PROCEDURE DIVISION.
    7 > COMPUTE R = FUNCTION NUMVAL-C("12.50" LOCALE)
    8 | DISPLAY R
    9 | STOP RUN.
```

## Expected result (per ISO)

The program compiles. At run time R receives the value of "12.50" read by the LC_MONETARY category of the current
locale: 12.50 under a locale whose mon_decimal_point is "." (for example en_US.UTF-8).

- §15.68.1 (checked): "the currency string, the sign convention, the grouping separator, and the decimal separator
  permitted in the character string may be specified by locale category LC_MONETARY" (the clause's general text).
- §15.68.3 5) a) (checked): "If locale-name-1 is not specified, category LC_MONETARY in the current locale is used."
- §15.68.4 1) (checked): "The returned value is the numeric value represented by argument-1."
- §A.4.1 (checked): "An implementation shall accept the syntax and provide the functionality for an optional element
  only when support for that language element is claimed by the implementor." §A.4.9 (Locale support and related
  functions) lists the LOCALE keyword of TEST-NUMVAL-C (item 12), checked) and of LOWER-CASE and UPPER-CASE, but not
  the LOCALE keyword of NUMVAL-C, so as written it is not optional.

Edition: the 2001-12-04 text headed "ISO/IEC 1989:2002(E)" (its §15.55.1) and the 2009 committee draft CD 1.2 that
led to 2014 (its §15.63.1) both give `FUNCTION NUMVAL-C ( argument-1 LOCALE [ locale-name-1 ] / argument-2 [ ANYCASE ] )`.
The CD 1.2 optional list (its A.4.8 "Locale support and related functions") names "TEST-NUMVAL-C function, LOCALE
keyword and locale-name-1" and not NUMVAL-C, the same as 2023. A maintainer may read the asymmetry as an oversight in
the standard; as written, NUMVAL-C LOCALE is required.

Edition as recorded by the adjudicator: 2002 (carried into 2014). `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Class

FEATURE-MISSING (edition 2002, carried into 2014): a phrase of the NUMVAL-C general format refused as a syntax error.

## Our compiler (WiseOwl)

WiseOwl COBOL (built from main 6ed90bd1c), `cobol nvloc.cob --std 2014 --source-format free -o nvloc.dll`, then
`dotnet nvloc.dll`: compile exit 0, run exit 0, output `12.50`.

## Fix site (GnuCOBOL 3.2 source, read observationally)

- `cobc/parser.y`, rule `numvalc_args` (line 19987), used by the `NUMVALC_FUNC` alternative (line 19862) for NUMVAL-C
  and TEST-NUMVAL-C: `expr_x` or `expr_x _e_sep expr_x`, with no LOCALE alternative. The `LOCALE` token exists
  (line 2953) and the LOCALE-DATE / LOCALE-TIME functions take a locale argument through `locale_dt_args`, so the
  grammar has a model to follow.
- `libcob/intrinsic.c`, `cob_intr_numval_c` (line 4944) and the shared `numval` (line 1482): no path that reads
  LC_MONETARY (`localeconv` fields mon_decimal_point, mon_thousands_sep, currency_symbol, int_curr_symbol,
  positive_sign, negative_sign) for the argument format.

**Refutation (UPHELD).** Rerun on cobc 3.2.0 matches verbatim ('nvloc.cob:7: error: syntax error, unexpected LOCALE', exit 1, -std=cobol2014 and default). Legal: 15.68.2 carries LOCALE [ locale-name-1 ] as the alternative to argument-2 (printed page checked); 15.68.1, 15.68.3 5) a) ('If locale-name-1 is not specified, category LC_MONETARY in the current locale is used', so no SPECIAL-NAMES LOCALE clause, the optional A.4.9 10), is needed), 15.68.4 1), A.4.1 and A.4.9 all --check OK. The record already flags that a maintainer may call the asymmetry an oversight. Sites verified: parser.y numvalc_args 19987 (no LOCALE arm), token LOCALE 2953, locale_dt_args 20004; libcob numval (1482) has no localeconv/LC_MONETARY path.
