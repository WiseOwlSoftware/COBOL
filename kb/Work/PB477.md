# PB477 — OPEN — one rule, two scripts, no drift test

Found 2026-09-04 by the `PB473` implementer while moving the guards' verdict rules into the one shared
`scripts/guard-verdict.sh`; re-derived on this tree for this note.

## The two copies

`scripts/guard-fast.sh:223-231` — "(5) Baseline-cleanliness check (parity with guard.sh): no 0-byte / FAIL* /
nonzero-footer baselines" — counts into `BASE_FAILS` and prints `=== ERROR: <file> is EMPTY ===`,
`… has N FAIL* ===`, `… footer N TEST(S) FAILED ===`. `scripts/guard.sh` carries the same three tests over the
same `tests/nist/valid/` files, counting into `FAILURES` with its own messages. Two variables, two message
sets, one rule — and the word "parity" in the comment is the only thing holding them together. That is the
shape `kb/Work/PB473` names as this repository's most reproducible defect (a rule with arms, one arm fixed):
the previous hardening had to be written twice, the compare-arm hole existed twice, and this check will drift
the first time either guard is tightened alone.

## Fix shape

A `guard_baseline_check` in `scripts/guard-verdict.sh` beside the verdict rules (the file both guards already
source since PB473), returning its findings through the same `GUARD_*` reporting so each caller keeps its own
counter and message plumbing; both guards call it. A witness per rejection in `scripts/guard-verify.sh`
(empty golden · a `FAIL*` line · a nonzero footer · a clean golden that passes), each proved red once against
the pre-fix copies, and the existing structural witness — "scripts/guard.sh (and guard-run-group.sh) score
through the shared rules and define none of their own" — extended to the baseline rule so a third copy cannot
reappear.
