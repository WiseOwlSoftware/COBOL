# PB875 — LANDED — a claim written in the register and invisible to the gate that enforces claims

## What happened, measured

`kb/Work/PB390` (open) claims four rows. Extending it to seven, the list was wrapped to a second line in the
normal YAML way — the same shape `kb/Work/PB205` has carried for months:

```yaml
inventory_rows: ["SR-14.9.25.3-12", "SR-14.9.28.3-12", "SR-14.9.28.3-13", "SR-14.9.39.3-6",
  "SR-14.9.16.3-1", "SR-14.9.21.3-1", "SR-14.9.46.3-1"]
```

`python scripts/spec/work.py check` → `✓ 907 work items, all well-formed`. The drift gate, on the same tree:

```
Failed CobolNet.Tests.Unit.DefectiveRowCoverageDriftTests.EveryDefectiveRow_IsClaimedByALiveWorkNote
  SR-14.9.25.3-12: verdict PARTIAL,  and no open kb/Work note names it in `inventory_rows` ...
  SR-14.9.28.3-12: verdict DIVERGES, and no open kb/Work note names it in `inventory_rows` ...
  SR-14.9.28.3-13: verdict DIVERGES, and no open kb/Work note names it in `inventory_rows` ...
  SR-14.9.39.3-6:  verdict DIVERGES, and no open kb/Work note names it in `inventory_rows` ...
```

Not the three new rows — **the four that had been claimed all along**. The whole key was discarded. Re-joining
the list onto one line, with no other change: `Passed! - Failed: 0, Passed: 47`.

## The mechanism

`tests/Cobol.Net.Tests.Unit/DefectiveRowCoverageDriftTests.cs:115-121`:

```csharp
case "inventory_rows":
    rows = value.StartsWith('[') && value.EndsWith(']')
        ? [.. value[1..^1].Split(',', ...).Select(x => x.Trim('"'))]
        : [];
    break;
```

A wrapped list's first line starts with `[` and does not end with `]`, so the ternary takes the `: []` arm and
the note claims nothing. It is a line-oriented reader for a value that YAML allows to span lines.

## Why this is worth a note rather than a one-line fix in passing

**It fails OPEN, in the one place the file's own doc comment promises it fails closed.** Twenty lines above, at
`:36-38`, the same class explains its status handling:

> only `landed` and `retired` are TERMINAL, and every other status ... counts as live. That default is chosen to
> fail SAFE: an unrecognized status keeps a note holding its rows rather than silently dropping them out of
> coverage.

The very next field does the opposite for a shape a human will write without thinking. A note that wraps its
list goes on *reading* as the owner of its rows in `kb/Work.base`, in `work.py`, and to every human — while the
gate counts those rows as unowned. In this instance the gate went RED, which is the lucky direction; the unlucky
direction is a note that wraps its list on the same commit that a row's verdict is recorded, where the gate then
has nothing to complain about and the claim is simply gone.

**And the two readers of one file format disagree.** `scripts/spec/work.py` parses the wrapped list correctly
and reports the note well-formed; the drift test does not. `work.py check` is the command every brief tells an
agent to run by hand, so the permissive reader is the one a human sees. `feedback_one_rule_one_place`.

## Code site and the shape of the fix

`tests/Cobol.Net.Tests.Unit/DefectiveRowCoverageDriftTests.cs` (the `ParseNote` frontmatter reader) — and NOT
only there. The structural answer is one frontmatter reader shared by the gate and `scripts/spec/work.py`, so a
register file has exactly one grammar; the narrow answer (accumulate continuation lines until the `]`) leaves
two parsers that will disagree again on the next YAML shape someone writes — a block list, a quoted string with
a comma, a `>`-folded title.

**Whichever is chosen, the gate must be made to fail once before it is trusted** (`feedback_green_gates_arent_evidence`):
the existing `TheseChecks_ActuallyFail_OnAFabricatedRegister` fabricates a register, so add a wrapped-list note
to that fabrication and assert its rows ARE seen. Without that, the fix is unmeasured.

## Sibling sweep the fixer owes

## 2026-09-20 — LANDED: one reader per language, held together by a parity fixture

Fixed at the root while building PB245's back-link gate, because a new gate reading this register would have
inherited the bug.

**The mechanism.** There is now exactly ONE C# reader — `tests/_shared/WorkRegister.cs`, linked into every test
project by `tests/Directory.Build.props` — and `DefectiveRowCoverageDriftTests`' private parser is deleted.
`scripts/spec/work.py`'s reader was rewritten to the same grammar. Both now treat a value that opens with `[`
as a list whatever its key, accumulate continuation lines until the bracket closes, and — the half that made the
old behaviour dangerous — report a value the grammar cannot finish as an ERROR CODE
(`unterminated-list:<key>`) with the key left ABSENT, never silently empty. Both failed OPEN before: emptiness
reads exactly like a note that claims nothing, which is the one answer a register must never invent.

**A runaway is bounded by the next key, and that is measured.** The first cut let an unterminated list keep
eating lines until some later line happened to end in `]`, so `tags: [cobolsharp, work, defect]` silently became
three members of `inventory_rows`. The parity fixture's unterminated-list case is what caught it.

**The two readers cannot be one, so something holds them together.**
`tests/version-matrix/work-frontmatter-parity-cases.json` — 12 cases covering LF and CRLF, quoted and bare
members, a list wrapped across two and three lines, a reason carrying a colon and brackets, an absent key, an
unterminated one, a file that is not a note, a frontmatter-only file and a title carrying `[`. Both engines
evaluate it, and `ClosesRowsBackLinkDriftTests.TheFrontmatterReader_AgreesWithTheFixtureAndWithPython` also RUNS
`work.py parity --json` and compares the answers field by field, so an engine whose behaviour and whose fixture
were edited together still fails. `work.py parity` asserts its own population (a wrapped list, an error, a
non-note, CRLF) and falsifies its own comparison on a corrupted copy of the fixture.

**Measured, not assumed.** Old reader vs new over all 939 notes: exactly ONE difference — `kb/Work/PB205`, read
as 4 inventory rows where it names 12. The C# side had been reading NONE of the 12. All twelve resolve to real
rule-ids and all twelve are CONFORMS, so no gate changed colour; the claim had simply been invisible. The
back-fill now WRAPS every `closes_rows` list it writes at the register's own width, so three hundred notes carry
the shape that used to be dropped — a reader that regresses fails loudly on the next build instead of quietly.
