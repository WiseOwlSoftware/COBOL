# PB4518 — OoDriver.ElementBinder does not hand the session's ClaimScans to each class-half and interface DataBinder, so each one walks the storage claims again with a fresh StorageClaimScan, contradicting BindSession.ClaimScans (kb/Work PB4302)

**Found:** 2026-11-03 by the PB2293 backend-seam wave-2 implementer (a lead, outside its group). `OoDriver.ElementBinder` (src/WiseOwl.Cobol.Compiler/Oo/OoDriver.cs) does not set `ClaimScans = session.ClaimScans`, so every class-half and interface `DataBinder` builds a fresh `StorageClaimScan` (DataBinder.Ptr.cs:24) and walks the storage claims again. PB4302 made the scans the bind session's, so one walk serves every binder.

**Harm:** performance only; the output is the same (no user program changes). It is process work in a compiler file, so a performance test or the census of scans per compilation should pin it once fixed.
