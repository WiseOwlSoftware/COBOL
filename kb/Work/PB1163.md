# PB1163 — OPEN

## The rule (every citation re-run by the registrar through `cite.py --check`)

> 3) If the FOREVER phrase is specified, the mass storage control system shall attempt to gain access to a locked resource until the input-output operation has been completed.

`python scripts/spec/cite.py --check 14.7.9.3 "…"` → `OK  §14.7.9.3 3)  (General rules)`

## Finding — `retry-phrase` (wrong-answer; rows `GR-14.7.9.3-3`, `GR-14.7.9.3-2`)

**Mechanism.** RETRY FOREVER gives up after one re-attempt on a file-sharing conflict held by ANOTHER run unit (the 'no releaser exists' premise of D8 / A.1-109/165/166 was falsified by PB860's cross-run-unit detection)

**Repro.** SELECT F ASSIGN "held.dat" ORGANIZATION SEQUENTIAL FILE STATUS ST. ... DELETE FILE F RETRY FOREVER. DISPLAY ST.  Run while another process holds held.dat open with FileShare.None and releases it 4 s later (probe: out/probe/retry-phrase/forever.cob + hold.ps1). Same with OPEN INPUT RETRY FOREVER F (SHARING WITH NO OTHER).

**Expected from the spec.** §14.7.9.3 GR3 (cite.py --check OK 3)): 'shall attempt to gain access to a locked resource until the input-output operation has been completed' — the DELETE FILE completes after the holder releases: status '00', file deleted (OPEN: '00').

**Observed / reasoning.** DELFOREVER=62 after 72 ms, file still present; OPENFOREVER=61 after 72 ms. RetryLoop's Forever arm makes one re-attempt then lands the conflict's status, justified in D8/DOC-A.1-109 by 'the holder is a connector of the executing run unit and cannot release' — true for record locks, false for the host-level sharing conflicts PB860 added (FileRegistry.DeleteFile comment: 'another run unit CAN close mid-loop'). The same false premise is the stated ground of DOC-A.1-165/166 (zero interval, zero maximum meaningful timeout); the probe `RETRY 100000000 TIMES` -> '00' vs `RETRY FOR 30 SECONDS` -> '62' on one holder shows a positive timeout DOES change the outcome. The A.1-166 value itself is letter-legal and the owner's to keep or revise; the GR3 behaviour is not latitude. Fix: FOREVER (and, if the owner revises A.1-166, SECONDS) must actually wait/poll when the conflict's holder is outside the run unit, keeping the in-run-unit deadlock detection; correct D8 and the three CONFORMANCE rows.

**Code site.** src/Cobol.Net.Runtime/IO/FileRegistry.cs#RetryLoop (Forever arm), #ExhaustionStatus, #DeleteFile, #OpenCore; docs/COBOLNET_FILES_DESIGN.md D8; docs/CONFORMANCE.md DOC-A.1-109/165/166
