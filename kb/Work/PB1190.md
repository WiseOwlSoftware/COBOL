## Finding — `write-statement-p2` (wrong-answer; rows `GR-14.9.51.4-14`)

**Mechanism.** The print-control WRITE arm has no record-length parameter: SequentialConnector.WriteAdvancing(image, lines, before, page) is reached from FileRegistry.WriteAnyOrg for every ADVANCING phrase, and SequentialConnector.Write reroutes to it (WriteAdvancing(image, 1, ...)) whenever the connector has seen print control or has a LINAGE page — before its IsVarying branch. So on a record-sequential RECORD IS VARYING file the §14.9.51.4 GR14 '44' bound check and the §13.18.43 DEPENDING length (and its length-prefix framing) are skipped on every write once any ADVANCING write has occurred. The two-arm dispatch shape: the plain arm was given the varying rule, the print arm never was.

**Repro.** FD VF RECORD IS VARYING IN SIZE FROM 3 TO 8 DEPENDING ON VL. 01 VR PIC X(8). OPEN OUTPUT VF. MOVE ALL 'X' TO VR. MOVE 9 TO VL. WRITE VR AFTER ADVANCING 1 LINE. DISPLAY FS. MOVE 2 TO VL. WRITE VR BEFORE ADVANCING 1 LINE. DISPLAY FS. MOVE 5 TO VL. WRITE VR. (E:/Temp/claude/E--CobolSharp/a700c052-f9e4-4942-84ff-a13c7505d6ec/scratchpad/adj-d1/out/probe/write-p2/pa.cob)

**Expected from the spec.** Both ADVANCING writes are unsuccessful with I-O status '44' and write nothing (§14.9.51.4 GR14, GR15); the VL=5 WRITE writes a 5-character record.

**Observed / reasoning.** Measured with the pinned cobol.exe: both ADVANCING writes report '00' and put 8 X's on the medium; the following plain VL=5 WRITE also reports '00' and writes all 8 X's with no length prefix. The plain arm without prior print control does report '44' for VL=9 and VL=2, so the defect is confined to the print/LINAGE arm.

**Code site.** src/Cobol.Net.Runtime/IO/SequentialConnector.cs#SequentialConnector.WriteAdvancing; src/Cobol.Net.Runtime/IO/SequentialConnector.cs#SequentialConnector.Write (the `(_printControl || page is not null) && !_lineSequential` reroute); src/Cobol.Net.Runtime/IO/FileRegistry.cs#FileRegistry.WriteAnyOrg

## Refuter evidence — row `GR-14.9.51.4-15` (PARTIAL)

PARTIAL — The write-does-not-take-place half fails on the print-control arm. On a record-sequential RECORD VARYING file, a WRITE with an ADVANCING phrase whose DEPENDING length is outside the VARYING bounds is UNSUCCESSFUL under GR14 ('44'), and GR15 then requires that the write operation not take place. The runtime skips the bound check on that arm (the mechanism the adjudicator filed under GR14), so the record reaches the medium. The observable file content therefore breaks GR15 as well as GR14's status. The other unsuccessful arms verified: 48/44 plain/24/22/21/71/53-54. One mechanism (the print arm with no length parameter), so a fix of the GR14 finding closes this too.

**Code site.** src/Cobol.Net.Runtime/IO/SequentialConnector.cs#SequentialConnector.Write; src/Cobol.Net.Runtime/IO/RelativeConnector.cs#RelativeConnector.Write; src/Cobol.Net.Runtime/IO/FileRegistry.cs#FileRegistry.WriteShared; src/Cobol.Net.Compiler/CodeGen/Verbs/SequentialIoEmitter.cs#SequentialIoEmitter.EmitWrite
