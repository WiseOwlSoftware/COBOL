# PB4863 - a destination renamed only by case leaves a stale DeviceEnds row in McsStore (known compares Ordinal), so on a case-insensitive host the cut loop cuts delivered output

**What the report says (the reviewer's words).** R2-3 LEAD (low, not blocking at round 2): `McsStore.cs:160` The cut loop cuts by every DeviceEnds row and seeding never retires one, while `known` compares Ordinal: a destination renamed only by case leaves a stale row naming the same file on a case-insensitive host, so delivered output is cut.

**Not probed.** The clerk reproduced nothing; no program or host run is named.

**Sites:** `src/WiseOwl.Cobol.Runtime/Communication/McsStore.cs` (`McsStore (line 160, the cut loop and `known`)`), `src/WiseOwl.Cobol.Runtime/Communication/McsTables.cs` (`RetireDeviceEnd`, `DeviceEnd`), `src/WiseOwl.Cobol.Runtime/Communication/McsStore.cs` (`Prepare`, `CutDevice`, `Transmit`), `tests/WiseOwl.Cobol.Tests.Unit/McsStoreCrashMatrixTests.cs`.

Filed from review leads of waves 20261884 and 20261885 by the enqueue clerk; the lead's claim is the reviewer's, not adjudicated here.

**Landed (wave 20261887 group C).** Reproduced on Windows by `McsStoreCrashMatrixTests.DeviceRenamedOnlyByCase_LeavesNoStaleRow_AndItsDeliveredOutputIsNotCut`: `dev` renamed `DEV` left the `dev` row at the old end, and the next run unit's first statement cut `DEV.out` (the same file) to it. Fix: seeding retires the `DeviceEnds` row of every device the definitions no longer name (`McsTables.RetireDeviceEnd`, `McsStore.Prepare`), so the store claims exactly its defined devices' files; the new name is seeded at the file's length. A removed device's file is left alone. Sites also: `src/WiseOwl.Cobol.Runtime/Communication/McsTables.cs` (`RetireDeviceEnd`), `tests/WiseOwl.Cobol.Tests.Unit/McsStoreCrashMatrixTests.cs`.

Review round 1: a live run unit holding the old definitions could send to a retired device and, with no row, overwrite its file from offset 0. `McsTables.DeviceEnd` now answers null for no row and `Transmit` takes the file length as the committed end (the seeding rule); the dead tail is cut to the old row end before the row retires (`CutDevice`). Witnesses `RunUnitHoldingARetiredDevice_AppendsToItsFile_NeverOverwrites`, `RetiredDevice_HasItsDeadTailCut_BeforeItsRowGoes`.
