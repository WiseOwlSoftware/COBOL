# PB5203 - ADD Format 2 with no operand before GIVING (ADD A GIVING D) compiles at every edition and stores A: addToPhrase is optional and BindAdd adds the TO operand only when it is written

**Sites:**

- `src/WiseOwl.Cobol.Frontend/Grammar/CobolParserCore.g4` (`addStatement`, `addToPhrase`)
- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/ArithmeticBinder.cs` (`BindAdd`, `GivingSendingOperand`)

**Mechanism.** §1985:VI.6.6.2 Format 2 is ADD {identifier-1 | literal-1} ... TO {identifier-2 | literal-2} GIVING ..., with only the word TO optional; the operand after it is required (braces, §1985:IV.2.1.4), so at least two operands precede GIVING. `addStatement` writes `addToPhrase` as optional and `ArithmeticBinder.BindAdd` adds the TO operand only when written, so ADD A GIVING D compiles and stores A. The 2023 Format 2 prints the same braces, so the gap has no edition arm: it is wrong at every edition. Found by the code read on row 1985-FMT-VI.6.6.2, which kb/Work PB5158 claims (its main defect is the phrase order); the row closes when both land.

**Found by.** The 1985 code read (2026-11-10; its records are `E:/COBOL-coord/scratch/coderead-85/for-register.json`): each rule below was read against the code sites it names and probed at `--std 85`, and found non-conforming. Verdict, harm, evidence, repro and observed text are the records'; the rows' verdicts are recorded on another branch.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids of the list below.

**Rules.** No inventory row of its own: the code read found it on `1985-FMT-VI.6.6.2`, which kb/Work PB5158 claims. The record's words: "Format 2's second operand: addStatement writes addToPhrase as optional and BindAdd adds the TO operand only when it is written, so ADD A GIVING D, one operand before GIVING, compiles and stores A; the format makes only the word TO optional, and this gap has no edition arm (the 2023 Format 2 prints the same two braces)."

**Repro (from the record; not re-run here).** In any program with numeric items A and D, `ADD A GIVING D` compiles at `--std 85` (and at every edition) and stores the value of A in D; the format requires a second operand before GIVING.

**Fix direction (root cause, CLAUDE.md rule 4).** Require at least two sending operands in Format 2 in BindAdd (GivingSendingOperand already narrows Format 2), refusing one with COBOL1689 like the other Format 2 shape errors.
