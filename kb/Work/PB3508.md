# PB3508 — a successor's report took its predecessor's closed note

**Sites:** `scripts/orchestrator/plan_wave.py` `add_closed_notes`, `scripts/orchestrator/test_plan_wave.py`

## What happens
`add_closed_notes` (kb/Work PB3473) adds to each unlanded report's `notes` every note its branch flipped to a terminal
status since it left origin/main (`closed_by_branch`). A same-file successor merges its predecessor's head, so the
predecessor's flip is in the successor's diff from main too. The successor's report is newer, so `plan()`'s
`newest[note]` became the successor's report. That report is DONE, so the note went to `awaiting landing` with the
successor, and the predecessor's FINDINGS report, the only thing that plans its review finisher, was superseded. That
contradicts `plan()`'s own carrier rule ("a branch that merely contains it does not [supersede]").

The branch survey (`prune_worktrees.carrying_findings`, through `review_findings.last_verdict`) holds the successor
until the predecessor's findings are answered. Neither side could move. The planner waited for the enqueue unit, and
the enqueue unit waited for a finisher the planner would not plan.

## Witness (wave 1143, 2026-10-21 23:48 PDT)
fix-pb3489-nested-fn-hang: review round 1 FINDINGS (1 blocking) at 37aafe9c7. fix-pb3504-antlr-sll-merge-cache
contains it, and round 2 reviewed it CLEAN. The enqueue unit's handoff said "PB3489 needs its review finisher (next wave
via plan_wave)". `plan_wave.py --from-budget --borrow-days 1` printed `WAVE 1143 PLAN: 0 groups` and
`awaiting landing (excluded; an enqueue unit first): fix-pb3504-antlr-sll-merge-cache: PB3489`.

## Fix
`add_closed_notes` gives no report a note that a CONTAINED unlanded report branch (`git merge-base --is-ancestor`)
also closes: the contained branch's own report decides it. The same live run with the fix lists no `awaiting
landing`, and PB3489 waits only on the survey's `--min-age` (its worktree was touched 105 minutes earlier). Once that
age has passed, its review finisher is planned with the carrier named in its pred.

## Landed
Branch `fix-plan-carried-closed-notes`. `test_plan_wave.py` check 6b'''00 (PB3508): a predecessor FINDINGS report
(PB13) and a successor DONE report (PB14) whose branch contains it. The successor answers PB14 alone, the predecessor
keeps its finisher, and `awaiting landing` holds only the successor's own note. The self-test passes 329/329.
