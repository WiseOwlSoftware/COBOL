# PB1035 — LANDED

## Landed with PB1171 (wave 68, group Y) — the same mechanism

The one screen this note asked for is `StatementValidation.ScreenReportFileReference` (COBOLNET2577), asked by
`ResolveFile` for every procedure-division file-name statement except OPEN and CLOSE, by SORT / MERGE USING-GIVING
(through `ResolveFile`, with §14.9.40.3 SR8 / §14.9.24.3 SR9), by WRITE / REWRITE of a record's file, and by FUNCTION
EXCEPTION-FILE. This note's probes (`READ RPTF` after OPEN EXTEND, `UNLOCK RPTF`) are COBOLNET2577 now. WRITE cannot
name a report file except through a record, which §13.4.5.3 SR8 refuses at the entry (COBOLNET2578). The rows
`SR-13.18.46.3-3` and `SR-14.9.24.3-9` close in batch `w68y-pb1171-verdicts.json`; the forensic detail is in PB1171.

## Measured
```cobol
       FD RPTF REPORT IS RR.
      ...
           OPEN EXTEND RPTF
           READ RPTF AT END DISPLAY "EOF" END-READ
```
compiles clean and prints `RAN`; so does `UNLOCK RPTF`. `OPEN INPUT RPTF` IS refused (COBOLNET2371, PB318, which cites
this rule). `DELETE RPTF RECORD` is refused, but for an unrelated reason (sequential organization, COBOLNET0865).

## The rule
`cite.py --check 13.18.46.3 "may be referenced in the procedure division only by the USE statement, the WHEN phrase of a PERFORM statement, the CLOSE statement, or the OPEN statement with the OUTPUT or EXTEND phrase"` → `OK §13.18.46.3 3)`.

## What the fixer owes
One screen, asked where a FILE-NAME operand is resolved for a procedure-division statement (not per verb): a file
whose FD carries a REPORT clause is admissible only in USE, a PERFORM WHEN phrase, CLOSE and OPEN OUTPUT/EXTEND.
Sweep READ, WRITE (a report file has no record-name, so WRITE cannot name it — confirm), REWRITE, START, DELETE,
UNLOCK, SORT/MERGE USING/GIVING, and the file-name forms of I-O status functions. Negative golden per verb.
