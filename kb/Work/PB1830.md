# PB1830 — LANDED

## The rule
> "the addend shall specify a numeric data item" — §13.18.54.3 SR5 (the diagnostic's own citation, `ReportSumAddendNotNumeric`)

§8.5.2.1 Table 2 makes a USAGE INDEX item class INDEX, never numeric.

## What the sweep found
PB1127 fixed `StatementValidation.CheckInspectTallyCounter` (SR5 of INSPECT), which tested `counter.Item.Pic is { Category: PicCategory.Numeric }`; a USAGE INDEX item's storage `PicInfo` (`PicInfo.IndexItem`) carries category `Numeric` with zero digits, so it passed. The same test stands for "numeric data item" at:

| site | verdict |
|---|---|
| `DataBinder.Reports.cs` (the SUM addend SR5 screen, `item.Pic is not { Category: PicCategory.Numeric }`) | **the same hole** — an index item as a SUM addend is accepted; its content is then added through a zero-digit profile |
| `DataBinder.cs#LinageOperandShapeFault` | correct — asks `pic.Usage is Usage.Index` right after the category |
| `SetBinder.cs` (SET … content SR31) | correct — `pic.Usage is Usage.Index` in the same condition |
| `FileControlKeyRules.cs` (RELATIVE KEY) | correct by construction — `Signed: false` rejects `PicInfo.IndexItem` (signed) |
| `IntrinsicArgumentRules.cs:1303`, `ExpressionBinder.cs:863` | correct — `Usage: not Usage.Index` |
| `ParameterConformance.cs:188/229`, `OoBinder.cs:966`, `MoveClassifier.cs:283` | receive a formal/target whose index usage is excluded earlier by the class screens (not re-derived) |

## Landed

The SUM addend SR5 screen now asks `Pic is { Category: Numeric, Usage: not Index }` (`DataBinder.Reports.cs`, beside the existing PB482 screen), witnessed by `conformance:negative/pb1830-report-sum-addend-index-item` (COBOLNET2045 at 85 / 2002 / 2014 / 2023, verified by running each). The remaining table rows are correct by reading; `ParameterConformance.cs:188/229`, `OoBinder.cs:966` and `MoveClassifier.cs:283` were not re-probed — they receive places whose index usage the class screens exclude earlier.
