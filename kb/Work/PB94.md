# PB94 — OPEN — `01 V PIC 9 VALUE "abc".` fails in the C# backend; `01 X PIC X(2) VALUE 12.` compiles clean

> ⚙ **flags:** crashes (a compiler-internal failure surfaced to the user as `error CS0103: The name 'abcL' does not
> exist`), under-rejects, silent · found 2026-08-18 writing [[PB82]]'s entry-cursor test with a VALUE-category
> violation that turned out not to be diagnosed at all.

**Measured** (`scratchpad/pb82/val.cob`, `val2.cob`, `--std 2023`):
- `01 V PIC 9 VALUE "abc".` → exit 70, "backend compilation failed … (14,22): error CS0103: The name 'abcL' does not
  exist in the current context" — the alphanumeric literal is rendered as a numeric initializer.
- `01 W PIC 99 VALUE "7".` → accepted, prints `W=07`.
- `01 X PIC X(2) VALUE 12.` → accepted, prints `X=12`.

**Spec:** §13.18.63.3 SR2 — "If the category of the subject of the entry is numeric, all literals in the VALUE
clause shall be numeric and shall be permissible values within the range indicated by the PICTURE clause or the
USAGE clause"; SR4 — "If the item is of category alphabetic, alphanumeric, or alphanumeric-edited literals in the
VALUE clause shall be alphanumeric literals". Both are syntax rules at every edition; the first case is a REJECT
(and must never reach the backend — rearch exit criterion 9: no codegen on an errored tree), the second and third
are rejects under strict and, if the owner wants the common-extension leniency (IBM/GnuCOBOL accept a numeric
literal for an alphanumeric item as an alphanumeric MOVE of its digits), a `--permissive`-gated warning with the
MOVE semantics — a [[dialect_two_axes]] decision, not a default.

**Mechanism:** `DataBinder.ValidateValueCategory` (the §13.18.63 SR10/SR5 national + boolean receiver checks) and
the SR2/SR3 numeric-RANGE check (`PIC 9 VALUE 123` IS rejected) exist, but the numeric-subject CLASS test and the
alphanumeric-subject class test are missing — the literal's category is never compared with the subject's for the
display categories. `pb82_exception_location_source_line` and `DiagnosticPositionTests.DataEntryError_NamesTheEntryLine`
had to use the range violation instead.

**Fix shape:** one category-conformance funnel for EVERY VALUE literal (elementary AND the table-format literals),
keyed on the subject's category × the literal's class per SR2/SR4/SR5/SR6/SR7/SR10 — the SAME table the MOVE
binder's Table 16 already encodes for sending/receiving categories (`MoveTable16` — reuse, do not re-list), with the
numeric-edited SR6/SR7 leg and the figurative-constant §8.3.3.6 leg included; a permissive-gated leniency ONLY if
the owner decides so. Negatives per leg; a positive golden that every legal (category, literal) pairing initializes.
