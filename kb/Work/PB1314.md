# PB1314 — OPEN

## Measured (`setf.cob`, `--std 2023`)

```cobol
       01 U PIC 9.
       PROCEDURE DIVISION.
           SET U TO FALSE.
```

```
setf.cob(7,12): error COBOLNET1639: SET 'U' TO TRUE — 'U' is not a condition-name: … §14.9.39.3 SR6 requires a
  condition-name associated with a conditional variable.
```

The user wrote `TO FALSE`.

```
$ cite.py --check 14.9.39.3 'If the FALSE phrase is specified, the FALSE phrase shall be specified in the VALUE clause'
  OK  §14.9.39.3 7)  (Syntax rules)
```

Format 4 is `SET condition-name-1 … TO { TRUE | FALSE }`. The refusal is right, but the message quotes a phrase
that is not in the source.

## Site
`src/Cobol.Net.Compiler/Binding/Validation/StatementValidation.cs:389` `RejectSetConditionName(string refText,
string? switchName)`. Both arms format `$"SET '{refText}' TO TRUE — …"`. The caller is `SetBinder.cs:1356`.

## What the fixer owes
- Pass the written TRUE/FALSE keyword, or better the written statement tail, into the helper.
- Sweep the other SET format helpers in `StatementValidation` and `SetBinder` for a hard-coded phrase: ON/OFF in
  Format 3, UP BY/DOWN BY in Format 2, and TO in Format 1.
- Add a negative golden for `SET U TO FALSE` that pins the message text.
