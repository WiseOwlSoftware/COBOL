# PB4487 - comment-entry pins are never re-decided

**Where.** `src/WiseOwl.Cobol.Frontend/Pipeline/Frontend.cs` (`RunTextStages`, ~line 199) with `CommentEntryPins` and `CommentEntryResolver` (PB4281). `CommentEntryResolver`
names a candidate that proved to be program text (`Resolution.ProgramText`); `RunTextStages` reruns the normalizer and `Preprocess` with the candidate pinned, to a fixed
point. A pin is monotone: it is added and never withdrawn, and the decision for a LATER candidate is taken on the cursor as it reads with the earlier pins.

**Failure.** When a pinned (program-text) candidate COPY-brings text into an IDENTIFICATION DIVISION, the division the later candidate sits in changes after the pin was
taken, but the later candidate is not re-decided: it stays read as program text for good, where the finished text makes it a comment-entry paragraph (or the reverse). Repro
`np1.cob` with `NPBOOK.cpy` at `--std 85`, per the PB4281 review.

**Fix direction (needs a design choice, hence this note).** Make the fixed point re-decide every candidate from scratch on each round with only the pins the round itself
proves (non-monotone), or order the decision so a candidate is settled after the COPY that can bring text before it; add a golden for the np1 shape and update the D-CE2
determination in docs/CONFORMANCE.md. PB4281 (landed) is the parent.
