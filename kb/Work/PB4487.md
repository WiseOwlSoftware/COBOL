# PB4487 - comment-entry pins are never re-decided

**Where.** `src/WiseOwl.Cobol.Frontend/Pipeline/Frontend.cs` (`RunTextStages`, ~line 199) with `CommentEntryPins` and `CommentEntryResolver` (PB4281). `CommentEntryResolver`
names a candidate that proved to be program text (`Resolution.ProgramText`); `RunTextStages` reruns the normalizer and `Preprocess` with the candidate pinned, to a fixed
point. A pin is monotone: it is added and never withdrawn, and the decision for a LATER candidate is taken on the cursor as it reads with the earlier pins.

**Failure.** When a pinned (program-text) candidate COPY-brings text into an IDENTIFICATION DIVISION, the division the later candidate sits in changes after the pin was
taken, but the later candidate is not re-decided: it stays read as program text for good, where the finished text makes it a comment-entry paragraph (or the reverse). Repro
`np1.cob` with `NPBOOK.cpy` at `--std 85`, per the PB4281 review.

**Fix direction (needs a design choice, hence this note).** Make the fixed point re-decide every candidate from scratch on each round with only the pins the round itself
proves (non-monotone), or order the decision so a candidate is settled after the COPY that can bring text before it; add a golden for the np1 shape and update the D-CE2
determination in docs/CONFORMANCE.md. PB4281 (landed) is the parent.

**Re-probe (wave 20261849, base 32d4e4db1).** `np1.cob` + `NPBOOK.cpy` at `--std 85` still drew CBL3620 (NOSUCHBOOK not found), COBOL1971
and COBOL0001; `np2.cob` (NPBOOK inlined) and `np4.cob` (the paragraph renamed) printed `1` / `INNER`. After the fix all three print `1` /
`INNER`.

**Resolution (as landed).** Both halves of the design question were settled, against docs/CONFORMANCE.md D-CE2 (corrected in the same
change) and §2023:6.5 "The rules of logical conversion are applied to each line of a compilation group in the order that lines of source text
and library text are obtained by the compiler" (cite-checked). (1) ORDER: a run pins ONE candidate, the EARLIEST of the finished text that
is program text. Reading a pinned candidate as program text changes the text after it and never the text before it, so that candidate and
every comment-entry before it were decided on text no later pin can change; the later candidates are decided again by the next run. The
pins stay monotone, each run settles one more candidate, and `CommentEntryPins.With` refuses a second naming of a pinned candidate (which is
never carried again), so the iteration ends. (2) IDENTITY: the old one-pin-per-physical-line rule could not serve a library text two COPY
statements bring in and decide differently, which it therefore left converted late (hidden from REPLACE and COPY). A pin is now a
`CommentEntryPin` (file, INCLUSION, line): the source text is inclusion 0 and the COPY driver numbers each library text it normalizes 1,
2, ... in text order, the number travelling in the carrier; the numbers up to the earliest undecided candidate agree in every run.
Goldens: `cases/6.5-Logical-conversion/pb4487_paragraph_a_program_text_candidate_copies_in_is_a_comment_entry` (the np1 shape) and
`cases/6.5-Logical-conversion/pb4487_library_text_copied_twice_is_decided_per_inclusion`, both accepted at 85 (COBOL0902 refuses the
comment-entry paragraph from 2002, as for every such program).

## Landing

- `src/WiseOwl.Cobol.Frontend/Pipeline/Frontend.cs#RunTextStages` owns the fixed point: one pin per run (`pins.With(pin)`), and it ends when the resolver names none. The trap: a pin decided on a text that a still-hidden earlier candidate can change is never safe; only the earliest program-text candidate is.
- `src/WiseOwl.Cobol.Frontend/Preprocessor/CommentEntryResolver.cs#Resolve` names the earliest header-opened program-text candidate (`Resolution.ProgramText`); never aggregate pins over a run again.
- `src/WiseOwl.Cobol.Frontend/Preprocessor/CommentEntryPins.cs#CommentEntryPin` is (file, inclusion, line); `CommentEntryPins.With` throws on a second naming.
- `src/WiseOwl.Cobol.Frontend/Preprocessor/CopyProcessor.cs#NormalizeCopybookMapped` numbers each library-text inclusion (`_inclusions`, text order); the source text is `CommentEntryPins.SourceText` (0).
- `src/WiseOwl.Cobol.Frontend/Preprocessor/CommentEntryCarrier.cs#Encode` carries the inclusion (`<inclusion>:<line>;`); the converters in `ReferenceFormatProcessor.LogicalConversion.cs` pass it and read pins through `Contains(file, inclusion, line)`.
