# PB1471 — OPEN

## The rule (every citation re-run by the registrar through `cite.py --check`)

> false if the value is zero

`python scripts/spec/cite.py --check 8.8.4.7.4 "…"` → `OK  §8.8.4.7.4 1) a)  (General rules)`

## Finding — `simple-sign-condition` (wrong-answer; rows `SR-8.8.4.7.3-2`, `GR-8.8.4.7.4-1`, `SR-8.8.4.7.3-1`, `GR-8.8.4.7.4-2`)

**Mechanism.** The Format-1/Format-2 sign-condition partition is decided by PicInfo.IsFloat, which covers every floating usage including the implementor-defined FLOAT-SHORT/FLOAT-LONG/FLOAT-EXTENDED and COMP-1/COMP-2. It should be decided by PicInfo.IsStandardFloat (the §3.166/§3.167 set). As a result, a bare implementor-float name gets the IEEE sign-BIT test of §8.8.4.7.4 GR2 instead of GR1's algebraic test.

**Repro.** 01 FL USAGE FLOAT-LONG.  PROCEDURE DIVISION.  MOVE 0 TO FL  IF FL IS POSITIVE DISPLAY 'POS' ELSE DISPLAY 'NOTPOS'.  COMPUTE FL = FL * -1  IF FL IS NEGATIVE DISPLAY 'NEG' ELSE DISPLAY 'NOTNEG'.  The same happens for FLOAT-SHORT and FLOAT-EXTENDED, and for EVALUATE FL WHEN POSITIVE. The pinned cobol.exe prints POS / NEG under both --std 2023 and --std 2002.

**Expected from the spec.** NOTPOS / NOTNEG. FLOAT-LONG is not a standard floating-point usage (§3.166 'usages float-binary-32, float-binary-64, and float-binary-128'; §3.167 'usages float-decimal-16 and float-decimal-34'). So FL is arithmetic-expression-1 under §8.8.4.7.3 SR1 and cannot be data-name-1 under SR2. §8.8.4.7.4 GR1a: POSITIVE is 'false if the value is zero', and GR1b says the same for NEGATIVE.

**Observed / reasoning.** ConditionBinder.IsFormat2FloatSign returns ctx.Refs.Probe(dref) is { Item.Pic.IsFloat: true }. PicInfo.IsFloat (PicInfo.cs ~749) = Float|Double|FloatShort|FloatLong|FloatExtended|FloatBinary*|FloatDecimal*. BoundSignCondition.Format2Float=true then makes ConditionRenderer.RenderSign emit !double.IsNegative(v) for POSITIVE, which is true for +0.0. Fix: test PicInfo.IsStandardFloat(Item.Pic.Usage) (PicInfo.cs ~204). Both call sites (the written form via BindSignConditionOn and the EVALUATE partial via BindPartialComparison) share IsFormat2FloatSign, so one change covers both. The golden tests/conformance/2002/ca8_float_sign_format2.cob/.out pins the wrong answer on FLOAT-LONG and must be rewritten. Format 2 needs a FLOAT-BINARY-64 item and --std 2014+, and a FLOAT-LONG Format-1 witness should expect NOTPOS/NOTNEG.

**Code site.** src/Cobol.Net.Compiler/Binding/Procedure/Verbs/ConditionBinder.cs#IsFormat2FloatSign (line ~1097); tests/conformance/2002/ca8_float_sign_format2.out

## What the fixer owes
