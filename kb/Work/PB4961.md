# PB4961 - a stale bit count in a summary

**Sites:** `src/WiseOwl.Cobol.Runtime/Messaging/MessageTagImage.cs` (line 10, the class summary), `src/WiseOwl.Cobol.Runtime/Messaging/SlotImageTable.cs` (`SerialBits`)

**Report (round-2 review LEAD, low).** The PB4926 finisher changed `SlotImageTable.SerialBits` from 12 to 8 (a party costs one entry per 256 messages; the process holds 2^24-1 blocks) but left the `MessageTagImage` summary saying "the low 12 bits of the message serial number". Verified on main: the summary still reads "low 12 bits".

Expected: the summary states the figure from `SerialBits` (better, names the constant rather than a number, so the next change cannot strand it); sweep `git grep -n "12 bits\|low 12"` in Messaging and the design doc DESIGN-message-control.md for the same figure.

The report's "Residual" (TagId throws after 2^24 block numbers per process, where it was a silent 2^32 wrap) is not filed: the limit and the throw are the stated design in DOC-A.1-212 (never a silent reuse of a live block), so it is not a defect by the note's own terms.
