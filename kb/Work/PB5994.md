# PB5994 - the Completion Ledger, rebuilt per edition

## Why
The ledger (scripts/spec/gen_ledger.py, ledger_plan.py; kb/Work PB2912) was designed around one goal, 2023 v1.0: rules
closed with GAP and the known compiler notes. The mission is four editions, 1985 first (owner 2026-11-15), and every 1985
completion claim of 2026-11-18 to 11-20 rested on the inventory's GAP, which counts neither open kb/Work notes nor normative
text the catalog has no row for (kb/Work PB5924; PB479 measured 871 such 1985 paragraphs). ledger_plan.py names 1985 nowhere.

## Decided
1. **One measure, one function.** Each edition's state on the page is `scripts/spec/edition_status.py`'s output (inventory
   GAP; code reads owed, owed a re-read, contradicted, undecided; open notes touching the edition by HARM / QUESTION /
   TOOLING with ids; normative text in no row, from PB479's measurement and, once PB5452 mints them, the new rows). The
   ledger computes nothing of its own about an edition.
2. **Layout.** Top: one line per edition in the owner's order (1985, 2002, 2023, 2014), its verdict (COMPLETE / NOT
   COMPLETE and why) and the blocking counts. Then per edition: the open notes (harm first), the uncovered text, and the
   work in flight (each wave's branch and state: implementing, gating, review, queued, landed: from the branch survey,
   prune_worktrees.py, and the merge queue). Then pacing: quota against the allowance (budget.py) and each lane's
   throughput measured from landings. No estimate without a measured input (UNMEASURED otherwise).
3. **Removed, not kept beside it.** The 2023-only v1.0 buckets, the GAP burn-down as the headline, and every figure that
   is not one of the above (CLAUDE.md rule 4: no compatibility layer). What survives must name its input.
4. **Proof.** A self-test that renders NOT COMPLETE whenever any input is nonzero or unmeasured, and COMPLETE only when
   all are zero; the page's verdict line equals `edition_status.py --edition N`'s for every N.

Implemented on the branch ledger-per-edition, which carries the edition_status branch (the function this consumes): one implementer (design-heavy: opus),
reviewed, one landing, and a publish to the artifact URL `ledger_state.py url` names.

**Sites:** `scripts/spec/gen_ledger.py` (whole: rewritten on edition_status), `scripts/spec/ledger_plan.py` (whole: replaced)
