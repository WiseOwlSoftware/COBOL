- Refusing is correct: CLASS is declined along with the optional VALIDATE facility (PB375; the 10-23 record settled the

## The rule (checked)

`python scripts/spec/cite.py --check 13.18.11.2 "BOOLEAN"` is OK. §13.18.11.2's general format prints BOOLEAN as an
underlined keyword alternative of the CLASS clause, so the word is the clause's own keyword and never a user-defined
word.

## Mechanism

`validateClassOperand` has arms for NUMERIC, ALPHABETIC and the other keywords but none for BOOLEAN, so BOOLEAN falls to
`cobolWord`, which at 2002 and later does not admit a reserved word, and the generic reserved-word diagnostic wins. The
grammar comment at CobolDeclined.g4 lines 115 to 123 says the result is "a plain syntax error"; it is not. Sibling of
landed [[PB857]] (the class CONDITION's BOOLEAN drew COBOL0901).

## Acceptance (when the owner approves)

- `CLASS IS BOOLEAN` draws COBOL1708 at every `--std` that reserves BOOLEAN, and the user-word reading below 2002 is
  unchanged.
- The comment at lines 115 to 123 is corrected in the same change, and `ClassConditionTableDriftTests`'s named
  exemption of this rule still holds.
- A diagnostic case per keyword of §13.18.11.2's brace group pins the code.

## Landed (wave 20261707 group B)

Re-probed on the branch build: `r0901.cob` drew COBOL0901 at 2002, 2014 and 2023 before the fix and draws
COBOL1708 alone after it. `--std 85` is unchanged: the clause does not exist there, so `CLASS` stays the existing
plain syntax error.

- **The root.** A declined rule's keyword arms were a hand transcription, and the file's "permissive inside" posture
  was read as licence to leave a printed keyword out. A keyword with its own lexer token that no arm names reaches
  only `cobolWord`, which refuses a reserved word, so the parse fails inside the declined construct and the error
  listener says the word is a reserved word "used as a user-defined word". The same mechanism hit FORMAT in
  `validateStatusStage` ([[PB693]]) and the class condition's BOOLEAN ([[PB857]]).
- **The fix.** `validateClassOperand` gains its BOOLEAN arm, and the comment that justified the omission is
  replaced. `DeclinedFacilityDriftTests.EveryPrintedKeyword_IsAnArmOfItsRule` reads each declined rule's cited
  general format from `specs/ISO_COBOL.md` (its `<pre>` figure, Format k where the comment names one) and requires
  every printed word with its own lexer token to be an arm the rule reaches, never through `cobolWord`. A tail rule
  (`validateValidPhrase`) also counts what its host `valueClause` parses.
  `EveryKeywordWritingRule_IsReachedFromACitedFormat` holds every keyword-writing rule of the file to a citation, and
  `ThePrintedKeywordGuard_ReportsAnOmittedArm` proves the guard fails on a removed BOOLEAN arm and on a removed tail
  VALID arm.
- **Witnesses.** `DeclinedFacilityTests.ClassClause_EveryPrintedOperand_DrawsTheDeclinedRefusalAlone` (all seven
  printed operands: COBOL1708, and no COBOL0901 or COBOL0001) and the refusal
  `conformance:wiseowl/cases/13.18.11-CLASS/declined-validate-class-boolean`.
- **Sibling sweep.** Every grammar rule whose top-level alternation mixes keyword tokens with `cobolWord`:
  `acceptSource` (ACCEPT Format 2, complete), `validateStatusStage` (RELATION is tokenless, correct),
  `classConditionName` (complete since PB857 and PB225), `concatOperand` and `screenName` (no printed keyword group).
  Only `validateClassOperand` was short.
