# PB5114 - the review lane's agent stop cannot reach an orphan

**Sites:** `scripts/orchestrator/review_lane.py` (`run_agent`), `scripts/detached.py` (`kill_tree`).

**Found.** PB5098 made `scripts/process_job.py` the one way to hold and stop a whole process tree: a Job object on
Windows, so a kill reaches an orphaned grandchild that `taskkill /T` (which walks parent ids) cannot. `review_lane.run_agent`
still stops a reviewer or finisher past its ceiling (STALLED) or at a loop stop (STOPPED) with `detached.kill_tree`, so a
process the agent started whose parent has already exited lives on after the stop. That leaves two mechanisms for one job.

**Why it is not a one-line swap.** The agent's gates are started through `detached.spawn_detached` precisely so they OUTLIVE
the agent (kb/Work PB3536: a workflow agent's return killed its gate mid-audit). A ProcessJob around the agent would hold
those gates too, unless the launcher breaks them away (`CREATE_BREAKAWAY_FROM_JOB`, which the job must then allow with
`JOB_OBJECT_LIMIT_BREAKAWAY_OK`). The fix decides that: a job with breakaway allowed and detached.py's launcher breaking away,
so the stop kills exactly what the agent did not detach. Its self-test plants an agent that starts an orphan and a detached
gate, stops it, and checks that the orphan dies and the gate lives.
