# PB4712 — parenthesized numeric or boolean function-identifier passes LENGTH and BYTE-LENGTH

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs:2142` (`IntrinsicBinder.BindLengthFold`, `IntrinsicBinder.BindByteLengthFold`, `IntrinsicBinder.WrittenForm`)

Reported by the branch review, not probed. R1-4, copied: a parenthesized numeric or boolean function-identifier still passes LENGTH and BYTE-LENGTH while the PB4635 branch refuses the parenthesized item and alphanumeric function there; pre-existing sibling, left for the clerk.

## Landed (wave 20261872 G)

Re-probe on the wave's build (`E:/COBOL-coord/scratch/w20261872g/p1.cob`): `LENGTH((FUNCTION ABS(I2)))`, `BYTE-LENGTH((FUNCTION ABS(I2)))` and
`LENGTH((FUNCTION BOOLEAN-OF-INTEGER(5 4)))` all compiled and printed 0004, 0004, 0004 (reproduced), while `LENGTH((FUNCTION TRIM(X9)))` and
`LENGTH((X9))` were COBOL0844. After the fix the three are COBOL1627 ("is an arithmetic expression" / "is a boolean expression"); the bare
spellings still return 4, 4, 4, 1 (BYTE-LENGTH of the boolean), 9. `cite.py --check` OK for 15.50.3 1), 15.14.3 1), 8.8.1.1, 8.8.2, 8.4.3.2.4 1).

- **The mechanism.** The LENGTH and BYTE-LENGTH folds recognised a function-identifier argument by the tree's shape
  (`BoundComputedOperand { Expr: BoundIntrinsicCall }`). The expression binder drops grouping parentheses, so `(FUNCTION ABS(I2))` binds to the same call the
  sole function does, and the arm admitted an arithmetic (or boolean) expression as "a data item". The binder already states the written shape
  (`IsSoleFunctionIdentifier` sets `BoundComputedOperand.FunctionValue`, PB3678); both arms now read it. The parenthesized alphanumeric and
  national functions were already refused (by the 8.8.1.1 class screen).
- **Siblings.** Every other reader of `{ Expr: BoundIntrinsicCall }` was swept: the data-item screens ask `IsDataItem`, which already
  reads `FunctionValue`; the rest read the call's category. `WrittenForm` now names a parenthesized boolean function a boolean expression.
- **Goldens.** Accept `pb4712_function_identifier_length_arguments` (2002); refusals `pb4712-length-parenthesized-numeric-function`,
  `pb4712-length-parenthesized-boolean-function`, `pb4712-byte-length-parenthesized-numeric-function`.
- **Lead (not fixed, same arm).** A bare `FUNCTION LENGTH(FUNCTION LENGTH(VG))` over a variable-length group (a function-identifier whose tree is the `BoundBinary` sum
  `VariableLengthGroupSum` builds) is refused COBOL1627 "an arithmetic expression" although it is legal source (`FunctionValue` is true).
  Widening the arm to `FunctionValue` alone compiled it and died at run time in `IntrinsicRenderer.StrArgVisitor.Visit(BoundComputedOperand)`;
  `FunctionDeviceText.IsNumericFunctionResult` needs a BoundBinary arm and the size of GnuCOBOL's run-time LENGTH temporary (DOC-A.1-92) must be measured first.
  Repro `E:/COBOL-coord/scratch/w20261872g/p2.cob`; site `IntrinsicBinder.BindLengthFold` / `BindByteLengthFold` (the function-identifier arm).
