# PB847 — LANDED — Format 8's consumer

Source: the `PB452` finisher report, item (1) — "the single most valuable follow-up to this landing" — and the
`PB452` implementer report item 2. Named again by the train-28 lander as lead (5).

## Repro — re-run on this tree

`scratchpad/reg4/probe/p31_funcptr_deref.cob` (PROGRAM-ID `R4P31`), `--std 2023`:

```cobol
       01 FP USAGE FUNCTION-POINTER.
       01 R PIC 9(4).
           MOVE FUNCTION FP(3) TO R
```
```
(5,8): error COBOLNET1958: data item 'FP': USAGE FUNCTION-POINTER shall be followed by TO function-prototype-name ...
(8,12): error COBOLNET1501: FUNCTION FP is not an intrinsic function of ISO/IEC 1989 (§15.6 summary of functions)
```

The second diagnostic is the finding: `FUNCTION <function-pointer-name>` is routed to the intrinsic catalog and
there is no other arm. (The first is the correct enforcement of the mandatory TO phrase and is not a defect —
it is the reason a well-formed probe must name a prototype.)

## The rules, quoted

```
$ python scripts/spec/cite.py --check 8.4.3.2.3 "Function-pointer-name-1 shall be defined as a function-pointer data item"
  OK  §8.4.3.2.3 4)  (Syntax rules)
$ python scripts/spec/cite.py --check 14.6.13.1.6 "Function pointer used in calling a function is NULL"
  OK  §14.6.13.1.6   (Exception-names and exception conditions)
      | EC-FUNCTION-PTR-NULL | Fatal | Function pointer used in calling a function is NULL |
```

§8.4.3.2 lets a function-pointer be DEREFERENCED: the prototype named by the pointer's own TO phrase supplies
the result's description and the characteristics of the activated element, and EC-FUNCTION-PTR-NULL is set when
the pointer holds NULL. `grep -rn "EC-FUNCTION-PTR-NULL" src/` finds it only in the catalog and in `EcBinder`'s
own comment, which records it as having "no raise site yet" — a GAP now that the category IS declarable.

## Landed — 2026-09-22, wave 46 group H, worktree `wf_f206ae6d-3b7-1`, base `8fe62bd1f`

Re-probed first: `MOVE FUNCTION FP(3) TO R` (FP `USAGE FUNCTION-POINTER TO` a real prototype) still drew
`COBOLNET1501 FUNCTION FP is not an intrinsic function`, and the keyword-omitted `FP(4)` drew COBOLNET2096 (a
subscript on a non-table). The dereference is now end to end:

* Binder — `IntrinsicBinder.FunctionPointerNamed` is the ONE §8.4.3.2.3 SR4 test, asked by the FUNCTION-keyword
  form (`BindIntrinsicCore`, after the prototype arm) and the keyword-omitted `fp (args)` form
  (`KeywordOmittedFunction`); SR5 (parentheses required) is COBOLNET2234, decided from the parse like SR6.
  `UdfBinder.UdfBindPointerCall` takes the prototype from the pointer's `RestrictedPrototypeName` and lowers
  through `UdfActivate` — the prototype activation `UdfBindCall` now also calls, so arguments, §14.8.2
  conformance and the GR1 result temporary are one code path.
* Emitter — `CallEmitter.InvocationText` is now the ONE renderer for the statement-position `EmitCall` and the
  per-evaluation `FunctionActivationText` (the latter read `c.LiteralName!` and had no pointer arm — the
  two-arm dispatch); `IsFunction` + `IsPointerTarget` renders `ProgramRegistry.CallFunctionPointer`.
* Runtime — `ProgramTable.CallFunctionPointer`: NULL raises EC-FUNCTION-PTR-NULL (GR6c, Fatal), otherwise the
  held function runs through the same `CallProgram` lookup with GR6b's EC-FUNCTION-NOT-FOUND.
  `CobolCallException.CarriedNames` gains the name (CallExceptionCarrierDriftTests re-derives it).
  SIBLING FIXED: `CallPointer` (the program-pointer twin) threw on NULL before consuming the site's pending
  EC-EXTERNAL mask, which then leaked into the next statement's activator latch; both twins now consume it.
* EcBinder queries EC-FUNCTION-PTR-NULL precisely for a pointer function activation.
* Sweep answered: `CALL <program-pointer>` (§14.9.4) already had its consumer (`CallPointer`, P10 Step 7).
  EC-FUNCTION-ARG-OMITTED (GR8) still has no raise site — OMITTED arguments to functions are staged loud
  (COBOLNET1506) for BOTH name forms, a pre-existing residue not widened here. EC-PROGRAM-RESOURCES (GR6c) is
  implementor-defined resource checking with no model on either form.
* Goldens: `2014/pb847_function_pointer_call` (keyword and keyword-omitted forms, re-pointing to a same-signature
  function, IF and PERFORM UNTIL per-evaluation sites, a zero-argument pointer, NULL under checking with a
  RESUMEd declarative); negatives `pb847-function-pointer-no-parentheses` (COBOLNET2234),
  `pb847-function-pointer-call-below-2014`; the fatal no-handler arm is
  `ExceptionConditionConformanceTests.FunctionPointerNull_Enabled_NoHandler_FatalTerminates`.
* Rows: SR-8.4.3.2.3-4, SR-8.4.3.2.3-5, GR-8.4.3.2.4-4 CONFORMS (GAP 2274 → 2271). NOT claimed: SR2 (the
  keyword-omitted EMPTY list `fp ()` is still a parse error — a lead), GR1/GR6 and FMT-8.4.3.2.2 (OMITTED
  arguments are staged for functions, so the whole format is not yet conformed).
