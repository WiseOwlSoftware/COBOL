# PB5002 - the conflict brief's command line grew with the conflict

**Observed.** Bringing main into PB4995's branch left 763 files in conflict (759 of them 1985 inventory store files that
PB4993 and PB4995 both recorded). `python scripts/orchestrator/land_lane.py conflict-brief worktree-wf_d1103feb-c82-1`
died with `FileNotFoundError: [WinError 206] The filename or extension is too long`: `conflict_brief` ran
`git log ... <base>..<main> -- <every conflicted file>`, one argument per file, and Windows caps a command line at 32,767
characters. The finisher was dispatched with a hand-written brief.

**Root cause and fix.** The pathspec made the command line as long as the conflict. `conflict_brief` now runs ONE
`git log --name-only` of the range with no pathspec and keeps, per commit, only the files in the conflicted set (a commit
that touches none contributes neither a line nor its note ids, as before). Swept: no other `land_lane.py` git call
passes the conflicted files as arguments.

**Test.** land_lane.py's self-test, case 17, briefs 2,001 conflicted files and asserts no git call's argument count
grows with them (fewer than 20); the existing checks (main's commit under the conflicted file only, not a file only main
added) hold.

**Sites:** `scripts/orchestrator/land_lane.py#conflict_brief`, `scripts/orchestrator/land_lane.py#self_test` (case 17).
