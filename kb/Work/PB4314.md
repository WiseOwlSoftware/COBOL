# PB4314 - `CobolErrorListener.MaxErrors = 20` truncates syntax errors with no notice; GnuCOBOL caps at 128 and announces the cut

Found by the Mythos front-end review, gap pass, 2026-10-31 (GAP-REVIEW.md, G4-5; artifact https://claude.ai/artifact/KaxkLe85tfZBZ3nZ1tDGTs). Pin d7daee1cf.

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorListener.cs` (`MaxErrors`: doc comment :18-19, constant :21, the silent returns :41-42).

**Finding.** `CobolErrorListener.MaxErrors = 20` (:21; :41-42 return silently; doc comment :18-19 "silently dropped"): `m6` with 25 independent `MOVE A B.` faults reports lines 9-28 and nothing for 29-33. Not a conformance defect (section 4.2.2); by rule-1 precedence the latitude follows GnuCOBOL, which caps at 128 by default and ANNOUNCES the cut (cobc `-fmax-errors`, "too many errors [-fmax-errors=N]"). The rejected unit is rejected either way, so nothing false is reported. The first review mentioned it in prose (GRAMMAR-REVIEW.md:331) and filed nothing; kb/Work names MaxErrors only as PB693's budget.

**Fix direction.** Keep a cap, emit ONE closing diagnostic when it trips, record the choice in `docs/CONFORMANCE.md`.

**The default's size waits on owner question 6** (GAP-REVIEW.md section 5.3): "Keep the syntax-error cap at 20, or move the default toward GnuCOBOL's 128?" The closing notice is owed either way. 20: cascades are bounded structurally now (PB3832/PB3843/PB4134), so 20 real faults is a long list. 128: the rule-1 precedence for a latitude is GnuCOBOL, and m6 shows 25 independent faults are plausible in a file under repair.

**Citations checked** (`python scripts/spec/cite.py --check`): section 4.2.2 "violations of the general formats and the explicit syntax rules of standard COBOL".

**Evidence.** E:/COBOL-coord/scratch/w-gr2/GAP-REVIEW.md (sections 2 and 5.1); G4/m6; review-G4.md. Probe names are copied from the shard reports; the refuter folders are E:/COBOL-coord/scratch/w-gr2/G*-refute/. Shard reports: E:/COBOL-coord/scratch/w-gr2/review-G*.md.
