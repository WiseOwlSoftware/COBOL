# PB5535 - the edition gate for a national or boolean literal names the data construct because the literal shares the national-data-2002 catalogue row

**Sites:** `src/WiseOwl.Cobol.Editions/ConstructRegistry.g.cs:164` (row `national-data-2002`, display "national data (PICTURE symbol N / USAGE NATIONAL)", code COBOL0900; generated from the construct catalogue), and the literal gate that reaches it (`LiteralScreen`, `GateFormat`). Fix: `tests/version-matrix/constructs/national-literal-2002.json`, `tests/version-matrix/constructs/boolean-literal-2002.json` (new rows; `ConstructRegistry.g.cs`, `Constructs.g.cs` regenerated), `src/WiseOwl.Cobol.Frontend/Parsing/LiteralScreen.cs` (`GateFormat`), comments in `src/WiseOwl.Cobol.Compiler/Binding/Procedure/ExpressionBinder.cs` (`NationalLiteralOperand`, `BooleanLiteralOperand`) and `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/ConditionBinder.cs`.

**Mechanism.** The literal N"AB" is gated through the `national-data-2002` row, so at an edition before 2002 the message reads "national data (PICTURE symbol N / USAGE NATIONAL) requires COBOL-2002 - the national literal N"AB"". The text names a data construct the program may not use; the construct that is not available is the literal. Pre-existing: `MOVE N"AB" TO X` reads the same.

**Fix direction.** Add a `national-literal-2002` and a `boolean-literal-2002` row to the construct catalogue (the generator emits `ConstructRegistry.g.cs`; do not edit it by hand) so each names exactly what is gated, point the literal gate at them, and add the edition-gate sweep tests (one test per edition either side of 2002). The test reads the diagnostic text, since the bug is only in the words.
