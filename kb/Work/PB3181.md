1. **A DISCHARGED report whose branch carries commits** (the note's retirement and its DEVLOG entry) is finished work
   by the wave's own rule (`wf_rolling_wave.js` `hasWork()`, line 184:
   `r.status === 'DONE' || (r.status === 'DISCHARGED' && r.head && r.head !== r.base)`), and the wave reviews it. The
   survey admits only DONE, so the reviewed branch can never read WAITING TO LAND and the lane never lands it.
   Repro: `worktree-wf_15ec6338-3a0-11` (PB934 retired as superseded by PB3102), report `w1078h-PB934-report.md`

   lists it DECISION. Two arms of one dispatch (memory `feedback_two_arm_dispatch`): one predicate "a finished branch"
   must be defined once, and the JS and Python arms pinned by a drift test.

   because the stamp commit is 11 to 15 min newer than the report: `worktree-wf_15ec6338-3a0-19` (last commit 16:31:57

   (exit 3), yet the survey lists them DECISION. Proposed fix: measure the report's freshness against the newest
   NON-mechanical commit (the `unreviewed_since()` classification `review_holds` uses), never the raw tip.

## Landing (wave 1083 group A, branch `worktree-wf_9b740cf9-198-1`; PB3181 and PB3125 land together)

ONE lifecycle rule for a finished branch, decided by the Mythos session from main f5fec711b
(`E:/COBOL-coord/scratch/mythos-item1/decisions-item1-20261015.md`, Decision 1), keyed on three coverages and never
on the report's age:

1. **The report.** `plan_wave.Report.finished` is THE predicate of a finished report (DONE, or DISCHARGED with a HEAD
   past its base; `Report.base` reads the header's `Base:` field). A finished report decides the branch only where its
   HEAD covers the tip: the tip itself, or only mechanical commits after it (`prune_worktrees.unreviewed_since`, the
   review stamp's and `enqueue.py land`'s coverage rule). `REPORT_SLACK_MIN` and the age test are deleted. A report
   naming no HEAD, or followed by a commit no report describes, is a DECISION with that evidence (IN FLIGHT while the
   branch is fresh). HEAD and BASE are read field-first (`plan_wave.sha_field`): w1080f's header named its
   predecessor's head in prose before its own `· head` field, and the old first-match rule read the wrong one.
2. **The review.** Unchanged: CLEAN covering the tip (or an older head the same coverage reaches).
3. **The landing lane.** `survey()` reads `land_lane.view()` (imported lazily) and passes it to the pure `lifecycle()`;
   `landing_state()` reads the newest attempt AT THE TIP: land_lane's STOPPED class makes the NEW state `STOPPED`
   (evidence: the attempt, its exit and verdict, `land_lane.ACTION[STOPPED]`), which is in `CARRIER_STATES`, so a
   contained predecessor reads IN FLIGHT; exit 0 reads ENQUEUED; a running, retryable (3, 2, 9, 8) or re-armed attempt
   reads WAITING TO LAND with the lane's own ACTION text. PB3125's rejected shape is honoured: a STOPPED branch never
   reads WAITING TO LAND.

The wave's JS copy of the predicate (`wf_rolling_wave.js` `hasWork`) is deleted: one `cobol-locator` runs
`plan_wave.py --finished <report>` (exit 0 finished, 1 not, 2 unreadable) on every DONE or DISCHARGED return, and a
refused return is treated as SPLIT, never reviewed. `review_findings.py stamp` refuses a report that is not finished
(shape 3: a header with no status line), instead of stamping under line 0.

Sibling arms of the same predicate (`status == "DONE"` meaning "finished"): `plan_wave.branch_carrier`,
`finisher_pred`, the `findings()` arm of `plan()`, `landing_measure`'s seed reports.
