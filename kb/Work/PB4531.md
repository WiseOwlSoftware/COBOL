# PB4531 — search-varying-item-set-to-occurrence: SEARCH ... VARYING integer-item stores the occurrence number instead of incrementing the item

Filed 2026-11-03 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-batch-3000-20261103`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

In a serial `SEARCH table VARYING n`, where `n` is an integer data item (not an index), cobc stores the search index's
occurrence number into `n` instead of incrementing `n` by one each time the search index is incremented. When `n` does
not start equal to the index's starting occurrence, the result differs: starting the index at 2 with `n` = 10 and
finding the match at occurrence 4, cobc leaves `n` = 4; ISO gives 12.

## Minimal test case

Free reference format (`-free`).
```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. SRCHVARY.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 T VALUE "ABCDE".
   05 E PIC X OCCURS 5 TIMES INDEXED BY X.
01 N PIC 99.
PROCEDURE DIVISION.
    SET X TO 2
    MOVE 10 TO N
    SEARCH E VARYING N
        AT END DISPLAY "NOT FOUND"
        WHEN E (X) = "D"
            DISPLAY "FOUND D, N = " N
    END-SEARCH
    STOP RUN.
```

## Environment

cobc (GnuCOBOL) 3.2.0 on WSL2 Ubuntu. `cobc -x -free -std=cobol2014 -o p prog.cob && ./p`.

## Observed result

Exit code 0:
```
FOUND D, N = 04
```

## Expected result (per ISO)

§14.9.37.4 3) b) 2.: "If identifier-2 references an integer data item, that data item is incremented by the value one
at the same time as the search index is incremented." The search starts at occurrence 2 (§14.9.37.4 4), "starting from
the occurrence number that corresponds to the value of the search index"); the WHEN is false at 2 and 3 and true at 4,
so the search index is incremented twice and N goes 10, 11, 12. The rule is in the 2014 edition. Expected output:
```
FOUND D, N = 12
```

## Our compiler

WiseOwl COBOL (fresh judge, `--std 2014 --source-format free`) compiles it with no diagnostic and prints
`FOUND D, N = 12`, exit 0.

## Fix site

cobc/codegen.c, `output_search_whens` (read in the GnuCOBOL 3.2 source): when a VARYING item other than the table's
index is given (`var && var != idx`), it emits `output_move (idx, var)`, a store of the index value, where an increment
of the VARYING item alongside the index increment is required. An index data item or another table's index-name
(§14.9.37.4 3) b) 1. and 3) c) 2.) needs the "same amount" or "one occurrence number" increment instead.
