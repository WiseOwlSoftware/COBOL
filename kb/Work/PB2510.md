# PB2510

Filed by the w1033 clerk from the PB1664 refuter (`E:\COBOL-coord\scratch\w1033-adj\PB1664-refute.md` section 2(a)), which struck the decision's claim that the compilers agree on PAGE for report files and says
"the report page advance is an open sibling question on the same file shape. Either decide it with this fix or file it as its own note."

**Observed (probe `PB1664-refute\rptpg`, report PAGE LIMIT 5, both hosts).**
- Pinned build `pin-97006f3`: `PH\r\nDD\r\nDD\r\nDD\fPH\r\nDD\r\n` (form feed ends the page).
- GnuCOBOL 3.2.0: `PH\nDD\nDD\nDD\nPH\nDD\n\n\n\n` (no `\f`): `libcob/reportio.c` contains no `COB_WRITE_PAGE`, and `do_page_heading` pages with `COB_WRITE_BEFORE|COB_WRITE_LINES|1` blank lines ("Skip to end of page").
- `docs/CONFORMANCE.md` DOC-A.1-159 pins the form feed: "Each line is followed by CR LF (0x0D 0x0A, on every host), except that when the next line begins a new page the line is followed by a form feed (0x0C) instead".

**Spec status (cite.py --check OK per the refuter).** `§14.9.16.4 GR6`: a failed page fit test "results in a page advance"; `§13.4.5.4 GR4`: the report writer logical record structure is implementor-defined; `§A.1 159)` (report file
record structure, required and documented). So the representation of the page advance is implementor latitude and the precedence order applies: ISO silent, GnuCOBOL represents it with blank lines. The decision's rule-1 reasoning for
`PB1664` reaches this too. Owed: an adjudication that picks blank lines or the form feed (and documents it), landed with or after `PB1664` since both rewrite DOC-A.1-159. Related: `PB1664`.
