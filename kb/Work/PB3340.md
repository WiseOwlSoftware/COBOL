# PB3340 — APPLY COMMIT on a SEQUENTIAL file

> flags: follows PB3330 (named out of scope in PB3338)

## The rule

§9.1.18.2 (`cite.py --check 9.1.18.2` → OK): *"Apart from sort-merge files and report writer files, any type of file on
a mass storage device may be specified."* An APPLY COMMIT clause may therefore name a SEQUENTIAL file on mass storage,
and COMMIT, ROLLBACK and abnormal run-unit termination (§9.1.18.3 to §9.1.18.5) then apply to its changes.

## Why it is its own note

PB3330's engine (`docs/rearchitecture/DESIGN-runtime-library.md` §2.2.1) is paged copy-on-write storage for RELATIVE and
INDEXED. PB3337 builds COMMIT and ROLLBACK on it, and PB3338 makes the compiler accept APPLY COMMIT. A SEQUENTIAL
file is written by streaming, not through that engine, so it has no page ledger to promote or discard. PB3338 records
the gap ("Out of scope, recorded here so it is not lost").

## What it needs

- A design section in `DESIGN-runtime-library.md`, written first and followed, covering how a sequential file under
  APPLY COMMIT keeps its last committed state. Examples: the committed length for OPEN OUTPUT and EXTEND (a ROLLBACK
  truncates back to it), and before-images for an I-O REWRITE. It must be crash-consistent in the same sense as
  §2.2.1, and a file not under APPLY COMMIT must pay nothing.
- Decide LINE SEQUENTIAL (an extension) explicitly in `docs/CONFORMANCE.md`, either covered or declined with its
  reason.
- Goldens computed from §9.1.18.3 to §9.1.18.5, and the PB3330 count-based witnesses extended to the sequential path.
