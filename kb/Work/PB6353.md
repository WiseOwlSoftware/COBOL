# PB6353 — the OO exception conditions ignore the checking switch

**What.** `CobolObject.RequireNonNull` (`CobolObject.cs`, near line 77, EC-OO-NULL), `CobolObject.__CobolInvoke` default arm (near line 37, EC-OO-METHOD) and `ActivationStack.RequireForMethod` (`ActivationStack.cs`, near line 106) throw a named `CobolFatalException` unconditionally. With checking off at the INVOKE and on in an enclosing IF, PERFORM or activator, the enclosing guard selects a condition that was never raised. This is the same root PB6298 fixed for RefModViolation, `CobolPtr.Deref`, `CobolIntrinsics.RequireArguments` and `CobolTable.RequireOccurrences`.

**Why PB6298 left it.** `EcEmitter`'s `FLAG = null` rows are an earlier owner decision (DESIGN-ec-oo-superbatch). Fixing these needs a per-INVOKE checking decision and a defined unchecked outcome: a null receiver has no result to return. The PB6298 drift test lists these three sites in its allowance with that reason; the fix removes the allowance.
