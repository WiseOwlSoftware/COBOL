# PB5000 - a merge landing's credit reads too many messages

**Found.** PB4992 made `backfill_closes_rows` walk main's first parents only, so a WIP commit inside a merged branch is
never read as a state. A merge landing is then credited with the messages of all the commits it brought in. Arm 3 of
`attribute` (a message that names exactly one note carries the row) now sees the union of those messages, and when any
other brought-in commit names a second note the arm fails. The reviewer measured it on real history (711 first-parent
commits against the old walk's 1,095): no real closure is lost except 6 rows on 2 notes, PB2104 at c36dfcbb2a and PB1086
at a97ddfb80f. Both notes already list those rows in `closes_rows`, so today the only effect is a spurious "differs"
warning; a future landing of the same shape would lose a closure.

**Owed.** Credit a merge with the messages of the brought-in commits that touch the inventory store (the row's own
files), not every brought-in commit. A self-test plants a merge whose other commit names a second note.

**Landed.** `closures_from_history` now credits a merge, row by row, with the messages of the brought-in commits that
changed THAT row's store file (`brought_in`, `message_for_row`; a commit touching the pre-PB4148 monolith counts for every
row, and a row no brought-in commit touched falls back to every brought-in message). Measured on real history against the
hand-written `closes_rows` of the terminal notes: rows missing from the derivation 370 to 366, rows it adds that the note
does not claim 518 to 510; PB2104's five missed rows (and `SR-13.10.3-2` on PB1544, PB2500, PB3173) are derived now.
PB1086 at a97ddfb80f is NOT this mechanism: the one brought-in commit that closed its rows (e821436484) names PB1086 AND
PB4185 in its own message, so arm 3 correctly refuses to divide it; its hand-written `closes_rows` stands and the
derivation reports "differs" for it. A self-test plants a merge whose other brought-in commits name a second note.

**Sites:** `scripts/spec/backfill_closes_rows.py` (`closures_from_history`, `brought_in`, `message_for_row`, `attribute`, `self_test`).
