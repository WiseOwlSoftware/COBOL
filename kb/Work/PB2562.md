# PB2562 — the wave planner ignored train labels when numbering a wave

## Defect

`scripts/orchestrator/plan_wave.py` `next_wave` returned one past the highest `wave NNNN` mention in the reports
directory and the newest 200 DEVLOG lines. `wf_rolling_wave.js` labels a wave's first train with the wave number
(`train ${W}`), and its later trains `${W}b`, `${W}c`. Trains 1035 and 1036 (DEVLOG 1921, 1926) came from waves
1031 and 1032, so on 2026-10-07 20:31 PDT the loop's wave unit was offered wave 1035: its first lander would have
written over `E:\COBOL-coord\scratch\train1035-manifest.json` and landed a second "Train 1035". The same collision had
already happened once: "Train 1034" is the title of both DEVLOG 1920 and DEVLOG 1924.

## Fix

`next_wave` counts `Train NNNN` labels as taken wave numbers too. `test_plan_wave.py` pins it: a DEVLOG naming
"Train 1036 (wave 1032)" and "wave 1034" yields 1037. The unit that found it ran as wave 1037 with `--wave 1037`.
