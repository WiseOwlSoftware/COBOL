# PB5295 - a debugging section runs at the wrong point of the statement that triggers it: after a failed DELETE or START it runs before the USE procedure, and after a RECEIVE WITH DATA (or READ NOT AT END) it runs before the WITH DATA (NOT AT END) statements, where 1985 runs it after the statement's execution

**Sites:**

- `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/KeyedIoEmitter.cs` (`EmitDelete`, `EmitStart`)
- `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/CommunicationEmitter.cs` (`EmitReceive`)

**Mechanism.** GR2 runs a file-name section "After the execution of any DELETE or START statement that references file-name-1", and the USE procedure of a failed statement with no INVALID KEY phrase is part of its execution (§1985:VIII.1.3.5 (3)); GR8 runs a cd-name section after a RECEIVE that does not run NO DATA, and the WITH DATA statements are inside that RECEIVE (§1985:XIV.3.5.4 GR4: "upon completion of the execution of imperative-statement-2, control is transferred to the end of the RECEIVE statement"). `EmitDelete` and `EmitStart` call `Debug.LandAfterAction` before `SeqIo.EmitUseHook`, and `EmitReceive` lands the fire ahead of the WITH DATA list (its comment says so deliberately; the golden pb4759_debug_cd_name_triggers.out pins that order). OPEN, CLOSE and READ already run the section after the USE procedure, and a data operand's section runs after NOT ON SIZE ERROR, so the emitters disagree with each other. docs/CONFORMANCE.md D-DEBUG-FILE (1) records the DELETE order from GnuCOBOL. The READ ... NOT AT END sibling the refuter saw is the same placement.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids below. None of them is recorded: the non-conforming verdicts wait in `E:/COBOL-coord/scratch/coderead-85/p2-for-register.json`.

**Rules (3 claimed; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-GR-XV.3.2.4-2` - `§1985:XV.3.2.4 GR2` (read: PARTIAL, harm: wrong-answer): "After the execution of any DELETE or START statement that references file-name-1"
- `1985-GR-XV.3.2.4-8` - `§1985:XV.3.2.4 GR8` (refuter: OVERTURNED, harm: wrong-answer): "that does not result in the execution of the NO DATA imperative-statement"
- `(supporting)` - `§1985:XIV.3.5.4 GR4` (places the WITH DATA statements inside the RECEIVE): "control is transferred to the end of the RECEIVE statement"

**Repro.** `E:/COBOL-coord/scratch/coderead-85/out-pipe/work-slice-68/p2/b.cob` (relative file, USE FOR DEBUGGING ON RFILE and USE AFTER ERROR on RFILE; START and DELETE of an absent key) and `E:/COBOL-coord/scratch/coderead-85/out-pipe/refute-slice-69/g8a.cob` with its mcs.json (`RECEIVE CIN MESSAGE INTO W12 WITH DATA DISPLAY "WITHDATA"`); `cobol.exe --std 85 --source-format fixed --run <file>`.

**Observed (a build of origin/main f2cf36fd15, rerun 2026-11-11; main has since changed only `IndexedConnector.cs` under `src/`, which none of these repros reaches).** `b`: `DEBUG RFILE [] STATUS 23` then `ERROR PROC 23` for DELETE (a failed READ in the same run prints `ERROR PROC 10` then `DEBUG`). `g8a`: `FIRE CIN` then `WITHDATA`.

**Expected (from the 1985 text).** `ERROR PROC 23` then `DEBUG ... 23`; `WITHDATA` then `FIRE CIN`.

**Fix direction (root cause, CLAUDE.md rule 4).** One rule for every verb: the after-statement fire lands at the end of the statement, after the USE hook and after the conditional phrase's statements; move the landings, update the golden and D-DEBUG-FILE (1), and test each verb.
