# PB1926 — LANDED (CONFORMS, w1033)

Filed by the train-1004 lander from wave 1004 group E's report (`w1004e-PB1226-report.md`).

## Question

Wave 1004 group E rendered PDF p524 (§13.18.57.2 Format 2) and read the OR PAGE phrase as sitting inside the one
optional bracket together with the control operand (`[ [ON|FOR] {data-name|FINAL} [OR PAGE] ]`), so `TYPE CH OR PAGE`
with no operand is a syntax error and is refused (COBOL0307). kb/Work PB1298's registrar (batch d1-14e) listed the probe
`fmt_or_page_nodata.cob` (`TYPE CH OR PAGE`) as conforming source. The two readings of one figure disagree.

**Site.** `src/Cobol.Net.Frontend/Grammar/Core/CobolReportWriter.g4#reportGroupType`. Negative golden
`conformance:negative/pb1298-control-footing-or-page-not-in-format` covers the footing; no golden pins the operand-less
heading either way.

**Verdict needed.** Render p524 (`scripts/render-spec-page.py 524`) and decide; if the operand-less form is legal, widen
the grammar and add a positive golden.

## Adjudication 2026-10-07 (w1033)

Decision `E:\COBOL-coord\scratch\w1033-adj\PB1926-decision.md`; refuter `PB1926-refute.md` (UPHELD, on narrower ground than the decision states). Pinned build `pin-97006f3` (main `97006f310`); probes `PB1926\`, `PB1926-refute\` (`r01`-`r15`).

**Outcome: CONFORMS, NO DEFECT. Closed as landed; no code change.** `TYPE CONTROL HEADING OR PAGE` (and `TYPE CH OR PAGE`) with no control operand is NOT legal; the pinned build refuses it at parse time (COBOL0307 / COBOL0001, exit 65), which is correct. PB1298's registrar was wrong to
list `fmt_or_page_nodata.cob` among the conforming probes. `inventory_rows` is empty, so no row is closed.

**Spec (cite.py --check OK; the refuter re-ran all).** The printed Format 2 of `§13.18.57.2` (PDF page 524, folio 494, rendered at 400 and 500 dpi; both files also read the PDF vector primitives) is
`{CONTROL HEADING | CH} [ [ ON | FOR ] { data-name-1 | FINAL } [ OR PAGE ] ]`: `[OR PAGE]` is nested INSIDE the one outer optional bracket whose brace operand is required (CF row: the bracket closes right after the operand, so the nesting is deliberate). The `specs/ISO_COBOL.md` transcription matches.
`§5.2.6.2` brackets (specified as a whole or omitted as a whole); `§5.2.6.3` braces. `§13.18.57.3 SR11` ("data-name-1, data-name-2, or FINAL may be omitted only if the CONTROL clause ... contains exactly one operand") omits the operand, i.e. the whole outer bracket, OR PAGE included.
`§13.18.57.3 SR12` (OR PAGE needs a PAGE clause); `§13.18.57.4 GR6 c) 2.` (OR PAGE prints the control heading after each page advance, at a control level). No latitude; GnuCOBOL 3.2.0 also refuses (`parser.y` 9418-9462 hangs `_or_page` only off the `identifier` and `FINAL` alternatives).

**Correction to the decision's reasoning (refuter).** Do NOT carry "a syntax rule that only says 'only if' cannot create a token sequence the general format does not produce" into comments or notes: `§5.3.2` (syntax rules may "relax restrictions") and `§5.2.1` show syntax rules CAN relax a format. SR11 does not, because
"only if" states a necessary condition (house style: `§14.9.40.3 SR15` KEY phrase; real relaxations read "may be omitted if/when": `§14.9.19.3 SR3`, `§12.3.7.3 SR31`), and because one sentence governs both CH and CF (for CF the format already brackets the operand phrase) and a relaxation would also admit `CH ON` and `CH FOR OR PAGE`.

**Code.** `src/Cobol.Net.Frontend/Grammar/Core/CobolReportWriter.g4#reportGroupType` (line 150): `(CONTROL HEADING | CH) (reportControlName (OR PAGE)?)?` with `reportControlName : (ON | FOR)? (FINAL | dataReference) ;`; CONTROL FOOTING is `reportControlName?` with no OR PAGE. Probes (all four editions): `CH OR PAGE`, `CONTROL HEADING OR PAGE`, `CH ON OR PAGE`, `CH FOR OR PAGE`, `CH OR PAGE` with CONTROL FINAL / CONTROLS, `CF OR PAGE`, `LINE PLUS 1 TYPE CH OR PAGE`: refused; `CH ON CTL OR PAGE`, `CH FINAL OR PAGE`, bare `CH`: accepted.
