# PB3671 — needs_settle matched the pin's header

**Sites:** `scripts/abi_pin.py` (`needs_settle`, `self_test`).

## Found (2026-10-24, the operator)

PB3664's branch (`worktree-wf_ae6946ad-ce4-1`) stopped at 18:59 PDT with `=== ENQUEUE: CONFLICT in
src/Cobol.Net.Runtime/RuntimeAbi.pin`. Neither side had changed the pin since the merge base (0ac850004).
`merge_drivers.merge` calls `abi_pin.needs_settle` after every clean `git merge --no-commit`. That function returned
`UNMEASURED in path.read_text(...)`, and the pin's header comment reads "the hashes read UNMEASURED and are measured on
the merged tree", so it was true on every tree. Every landing that brought main in therefore ran `abi_pin.settle`: a
solution build in the branch's worktree plus `RuntimeAbiPinDriftTests` in write mode. This time the build failed (the
attended session's C# language server held `Cobol.Net.Compiler.SourceGen.dll`, PB3672), and the failed settle was
reported as a conflict in the pin.

## Fixed

`needs_settle` reads the pin through `parse` and is true only when a hash LINE reads UNMEASURED, which is what
`merge_text` writes when both sides changed the pin. A pin `parse` refuses is not a settle's to fix, and
RuntimeAbiPinDriftTests reports it. The self-test gains a case built on the SHIPPED pin: its header names the word, and
that alone must not need a settle. The case fails on the old text search by construction. A landing now builds for the
pin only when two branches really both changed it.
