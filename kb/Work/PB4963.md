# PB4963 - untested EndIn arms after a failed Deliver

**Sites:** `src/WiseOwl.Cobol.Runtime/Messaging/MessagingProtocol.cs` (line 388, the failed-Deliver path; `EndIn`; `AdvanceReceive`), `tests/` (the PB4892 two-process messaging tests)

**Report (round-1 review LEAD, low).** The failed-Deliver path restores the RECEIVE and then `EndIn` decides it by kind. Only the RECEIVE FROM NULL waiting arm is tested. Two arms have no test: a RECEIVE FROM a requestor tag (which `EndIn` now completes EC-MCS-REQUESTOR-FAILED) and a poll or timed RECEIVE (which `AdvanceReceive` completes empty) after a failed ACK write.

Expected: a test per arm, each failing the ACK write (the Deliver seam PB4892 added) and asserting the RECEIVE's completion and exception state; the expected values come from the RECEIVE rules and the EC definitions, not from the observed output.
