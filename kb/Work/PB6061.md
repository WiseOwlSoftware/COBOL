# PB6061 - `env rm -rf "$X"`, `timeout 5 rm -rf "$X"` and `nice rm -rf "$X"` pass Rule 7

Rule 7 (no recursive delete of a variable path, PB5764 / the owner's rule against `rm -rf` on a variable) locates the step's command
word by skipping `NAME=value` assignments and the words of `_LEADERS` (`scripts/hooks/forbidden_commands.py:341`, `:351`). `env`,
`timeout` and `nice` run another command exactly as `sudo` and `nohup` do but are not in the set, so the command word the rule sees
is `env`, `timeout` or `nice` and the delete behind it is not examined. Neither the docstring nor PB5764's report lists the gap.

Probe: add the three prefixes to the hook's own self-test (`scripts/hooks/test_forbidden_commands.py`) as REFUSE cases next to the
existing bare `rm -rf "$X"` case and watch them fail. `timeout` and `nice` take an argument (a duration, `-n 5`) before the
command, so the fix is not only three more words: skip each wrapper's own options too, or find the command word structurally
rather than from a word list. Look for the same blind spot in every other rule that keys on the command word.

**Sites:** `scripts/hooks/forbidden_commands.py` (`_LEADERS`, the command-word finder), `scripts/hooks/test_forbidden_commands.py`.
