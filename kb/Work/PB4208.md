# PB4208 — a never-gated reserved verb as an operand draws two diagnostics

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs:229` (`CobolErrorStrategy.ConsumeUntil`),
`src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs:269` (`CobolErrorStrategy.IsReportedReservedOperand`, which keys on
`CobolParserCoreBase.ReservedUserWordViolation`, gated words only),
`src/WiseOwl.Cobol.Frontend/Parsing/CobolParserCoreBase.cs:675` (`CobolParserCoreBase.ReservedUserWordViolation`).

**The defect.** Same symptom as PB3248, different mechanism. PB3248 made a gated reserved verb (RECEIVE, SEND, VALIDATE) written
as an operand draw one COBOL0901. CONTINUE is reserved in every edition, so it is not reservation-gated and never reaches the
COBOL0901 path (`ReservedUserWordViolation` is null for it). At --std 2023, `MOVE CONTINUE TO W-X.` gives
`COBOL0001: cannot parse construct near 'CONTINUE'` plus `COBOL2269: unexpected 'TO'. The CONTINUE statement ends before this
token`: the recovery resumes at CONTINUE, parses it as the CONTINUE statement and refuses the next token. §8.3.2.1 1) ("Reserved
words shall not be used as user-defined words or system-names", `cite.py --check` OK) makes it a misuse like the gated ones.
Repro (originally `rv2/c1.cob` in a temp scratchpad, not durable):

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. RVW2.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 W-X PIC X(4).
       01 W-Y PIC X(4).
       01 W-N PIC 9(4).
       PROCEDURE DIVISION.
       MAIN-P.
           MOVE CONTINUE TO W-X.
           DISPLAY "A".
           STOP RUN.
```

**Fix direction.** One rule for "a reserved word was written where a user word is required", not the gated-word test alone;
sweep the other always-reserved statement verbs (GO, STOP, EXIT, EVALUATE, ...) in an operand slot. Rows go in
`ReservedWordPositionConformanceTests.AReservedVerbWrittenAsAnOperand_DrawsOneDiagnostic`. PB4132 is the open note for the gate
hijacking a keyword in statement position (the opposite direction).

## Landed (wave 20261788 D, 2026-10-31)

Re-probed on the tree first: `MOVE CONTINUE TO W-X.` at --std 2023 gave `COBOL0001: cannot parse construct near 'CONTINUE'` and
`COBOL2269` at TO, as filed; `MOVE EXIT TO W-X.` the same pair, `MOVE EVALUATE TO W-X.` three diagnostics. The sweep of the note
(every statement verb in twelve operand slots at 85, 2002 and 2023, scratch `E:/COBOL-coord/scratch/w20261788d/sweep.py`) printed 528
of 648 (verb, slot) cells that were not one COBOL0901 naming the word at 2023 before, 74 of 756 after; what remains is a verb that
is a complete statement by itself (`DISPLAY GOBACK.`, the PB4207 reading), ALTER and ENTRY (not reserved at 2023), `UNTIL EXIT`
(the grammar's own keyword) and `COMPUTE W-N = DISPLAY + 1.` (DISPLAY +1 parses as a statement).

**Mechanism.** `CobolParserCoreBase.ReservedUserWordViolation` answered only for a reservation-GATED token, so a verb reserved at
every edition was never named, and its cascade (a verb is in every statement-level recovery set) was the one PB3248 removed for the gated
verbs. **Fix.** One word class: a gated word or a verb, a token `statement` can begin with (`CobolParserCoreBase.StatementOpeners`, read off the
ATN once), that §8.9 reserves at the edition. `ReservedWord(token, includeVerbs)` is the one decision under `ReservedUserWordViolation`
and `ReservedGatedWord` (which `entryNameHere` and `procedureHeaderHere` keep asking gated-only). A reserved word that begins no
statement (`MOVE TO W-X.`) keeps the strategy's own diagnosis.

**Sibling consequence, fixed in the same change (I9).** The first run of the conformance project showed `PROPERTY WITH NO GET SET.`
(l1c21-property-no-get-and-set, COBOL1941 "unexpected 'SET'") now drawing COBOL0901: SET is a verb, a value clause before it could still take
a name, and the closed format's own refusal (hint 0g) lost to the new report. A word where a closed format's clause list stands is a clause the
format does not print, not a name: `ReservedWordUse` declines it when `ClosedFormatResidue` names it (the same test hint 0g uses), for the gated
words as for the verbs. (A first attempt, reading the expected set with the error productions left out, did not reach it and was removed.)
The same run found the `WordCharacterScreenTests` fixture `MOVE MOVE`, a generic parse error that is now the COBOL0901 it should be: it is `MOVE TO`,
spelled once (`NoSender`), with the parsed form a `parses` argument of the one `Program` helper, never a `Replace` of the tail: PB4234's tests,
written on main against the old tail, came in at the landing's merge with a `Replace(" MOVE MOVE", "")` that no longer matched, so its seven
parsed rows compiled the unparsed form and went red. The three `pb3845-*-unparseable` refusals take the same tail.
