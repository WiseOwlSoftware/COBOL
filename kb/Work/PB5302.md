# PB5302 - at --std 85 a format 1 SEARCH's advance test looks only at the upper bound; the 1985 text and its Figure 1 disagree

**Sites:** `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/ControlFlowEmitter.cs#EmitSerialScan`: the advance test after each increment, `{IndexField} > {bound}` (EC-RANGE-SEARCH-NO-MATCH), emitted at every edition. The start test is PB5121's (`BoundSearch.IndexBelowTableIsUnsuccessful`, VCR row 7.56).

**Question.** PB5121 made a format 1 SEARCH at `--std 85` start its scan with an index below the table. After each unsuccessful pass the index is incremented and the scan continues unless the new value is above the table; nothing tests the new value against occurrence 1. Which does COBOL-85 require?

- The text, §1985:VI.6.22.4 GR2 b): "The process is then repeated using the new index-name settings unless the new value of the index-name settings for identifier-1 corresponds to a table element outside the permissible range of occurrence values, in which case the search terminates as indicated in 2a above." Read literally, an incremented index of 0 or less is "outside the permissible range" and the search ends with AT END.
- The figure, §1985:VI.6.22.4 GR10: "A representation of the action of a format 1 SEARCH statement containing two WHEN phrases is shown in figure 1 on the next page. This figure is not intended to dictate implementation." Figure 1 loops back after the increment to the "greater than" test only.
- 2002 and later (§2023:14.9.37.4 GR4) word the advance the same as the 1985 text ("unless the new value for the search index corresponds to a table element outside the permissible range of occurrence values"), but from 2002 a start index below 1 is already unsuccessful, so the increment can never produce a value below 1 there and the question arises only at 85.

The text is normative and the figure disclaims dictating implementation, which favours the text; but the text's "outside the permissible range" may have been written with only the upper bound in mind, since GR2 a) and the start of b) test only "greater than". This needs a decision, not a silent pick.

**Observed.** The reviewer's probe `E:/COBOL-coord/scratch/review-w20261998-d/m1.cob` (ELT OCCURS 1 TO 5 DEPENDING ON N INDEXED BY IX; `PERFORM NULL-PARA VARYING IX FROM 3 BY -2 UNTIL IX < 1` leaves IX at -1; `SEARCH ELT AT END DISPLAY "AT END" WHEN IX = 2 DISPLAY "FOUND AT 2"`), built from PB5121's head ca4f3c37d9, re-run 2026-11-11: `dotnet m1-85.dll` prints `FOUND AT 2`, `dotnet m1-2023.dll` prints `AT END`. By the GR2 b) text the first increment gives 0, outside the range, so 85 would print `AT END`. A start index of exactly 0 is unaffected by the choice (0 becomes 1, inside the table).

**If the text wins.** Emit `index < 1 || index > bound` as the advance test when `BoundSearch.IndexBelowTableIsUnsuccessful` is false (at 85), add a golden at -1 beside `14.9.37-SEARCH/pb5121_search_index_below_table_85`, and correct VCR row 7.56, the `DialectBehavior.SearchIndexBelowTableUnsuccessful` summary ("incremented to occurrence 1") and the `EmitSerialScan` doc comment. **If the figure wins.** Record the reading in `docs/CONFORMANCE.md` with both quotations and pin the `FOUND AT 2` behaviour with the same -1 golden.
