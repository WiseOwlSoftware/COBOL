**Scenario:** ConditionBinder.AnalyzeBareOperand (ConditionBinder.cs:1514-1532) builds the BoundCondition88 for a bare level-88 object, including ResolveForItem over its subscripts, and BindBoolOperandValue for a boolean one, inside ClassifyPair after classifyMark. The boolean-expression arm (:769-771) attaches with classifyMark for that reason. The Condition-object arm at :661-664 calls ObjectAsCondition first and takes objMark afterwards. The Condition x Condition arm at :622-625 takes objMark2 before ObjectAsCondition, but for a bare object ObjectAsCondition only returns the analysis bound earlier. Both windows are empty, so every activation or function-bearing subscript temp of the object stays pending and the statement funnel hoists it. Repro (2002+): EVALUATE TRUE WHEN X = 1 DISPLAY "ONE" WHEN T-OK (FUNCTION INTEGER (FUNCTION RANDOM * 3) + 1) DISPLAY "OK" END-EVALUATE, with 05 T-FLAG PIC X OCCURS 3 and 88 T-OK VALUE "Y" under it, and X = 1. The first WHEN selects, but FUNCTION RANDOM is still called at the head of the statement, so a later DISPLAY FUNCTION RANDOM prints the next number in the sequence. A user-defined function in the subscript is activated with its side effects, and EC-ARGUMENT-FUNCTION or EC-BOUND-SUBSCRIPT from a phrase that is never analyzed is raised. An explicit condition object (:640-643) is bound after its mark and is correct, so the two spellings of one condition-2 disagree.
