# PB575

## Mechanism
every Format-3 VALUE guard in BindCondition reads `parent.Pic`, and a BIT or NATIONAL GROUP conditional variable has none - so the SR10 size limit, the class funnel and the national guard all fall through on null and an 8-bit literal on a 4-bit group compiles AND RUNS

### The refutation this note is written from
Row `SR-13.18.63.3-24` was adjudicated CONFORMS and OVERTURNED to `PARTIAL` by the refuter. Its reasoning, verbatim:

> SR24 pulls in TWO rules and only ONE of them fully reaches Format 3. The SR17 half does: `88 C-OK VALUES ARE 1 2 3.` compiles and takes its true branch for CV=2 at --std 2023 AND at --std 85 (r01) -- which incidentally shows the recorded edition band 2002/2014/2023 understates SR24, since Format 3 and the VALUE/VALUES spelling both predate 2002 and the compiler honours them at 85. The SR10 half does NOT. SR10 has three sentences; its third names a population by name -- "Boolean literals in the VALUE clause of a bit group item shall not exceed the size of the group item" (cite.py --check OK) -- and on a Format-3 entry whose CONDITIONAL VARIABLE is a bit group item NOTHING is checked. MEASURED, two wrong-acceptances: `01 BG GROUP-USAGE BIT. 88 C-BAD VALUE B"10101010". 05 E1 PIC 1(4) USAGE BIT.` -- an 8-bit literal on a 4-bit group -- compiles AND RUNS clean (r05), and the class arm `88 C-BAD VALUE "AB".` on the same bit group compiles and runs clean (r06). The ELEMENTARY twin of each is caught: the identical oversize literal on `05 E1 PIC 1(4) USAGE BIT` draws COBOLNET0898 (r34), and so does the alphanumeric literal (r02/r03). That is the [[two_arm_dispatch]] shape exactly -- elementary arm implemented, group arm absent. PREMISE VERIFIED before concluding: the 88 really is bound to the GROUP, not to the elementary -- `MOVE B"1010" TO E1` then `IF C-OK` takes the true branch (r12), so the condition-name's conditional variable is BG. The mechanism is in the very code the adjudicator cited: DataBinder.cs BindCondition guards the funnel with `if (parent.Pic is { } sp)` at :2154 (and `parent.Pic is { Category: ... }` at :2133), and the comment three lines above says in its own words "Group parents (Pic null) are a separate leg" -- that leg does not exist. Corroboration that the hole is the group leg and not something about BIT: a national group conditional variable takes an alphanumeric literal silently too (r33). The cited negative level88-alnum-value-boolean.cob pins `01 W-B PIC 1(2). 88 W-ON VALUE "01".` -- an ELEMENTARY conditional variable, so it pins the arm that works and cannot see the one that does not; the NationalBooleanDataTests case is likewise elementary.

### Inventory row `SR-13.18.63.3-29` (PARTIAL)
MEASURED at --std 2023 across all three ways to make the subject boolean -- and the third is the one a scalar guard usually misses. (a) `01 B PIC 1(4) USAGE BIT. 88 C VALUE B"0001" THRU B"0011".` -> COBOLNET0898 citing SR29 (v29a). (b) `01 B PIC 1(4).` with no USAGE clause -> same reject (c29_pic1_nobit). (c) A GROUP-USAGE BIT group as the conditional variable -- 13.18.29.4 GR1 gives a bit group "class and category boolean" (cite --check OK) -- `01 BG GROUP-USAGE BIT. 05 B1 PIC 1(4). 88 C VALUE B"0001" THRU B"0011".` -> same reject (v29b), i.e. the guard sees the group's category, not only an elementary PICTURE. The legal control (a boolean VALUE LIST, no THROUGH) compiles and evaluates TRUE (v29c), so the guard is scoped to the THROUGH phrase and does not over-reject. Covering test: tests/Cobol.Net.Tests.Conformance/NationalBooleanDataTests.cs:71-73 case NBDAT11, run by IllegalValueShape_Rejects0898 at edition 2002 -- spec-derived (the expectation is a rejection derived from SR29, not a legacy/NIST match). || REFUTED: PARTIAL — REFUTED. The adjudicator's CONFORMS rests on three measured shapes, and its shape (c) -- 'A GROUP-USAGE BIT group as the conditional variable ... the guard sees the group's category, not only an elementary PICTURE' -- is NOT what its probe measures. In probe/value-clause-p2/v29b_bit_group_thru.cob the 88 is written AFTER '05 B1 PIC 1(4).', so the conditional variable is the ELEMENTARY item B1, not the group BG; v29b therefore re-measures shape (a) and the bit-group subject was never reached. Reading the code confirms the miss: src/Cobol.Net.Compiler/Binding/DataBinder.cs:2120 guards on 'parent.Pic is { Category: PicCategory.Boolean }', and a bit GROUP has no PICTURE (Pic is null), so in BindCondition's valueClauseRange arm the boolean guard, the national guard AND the 'parent.Pic is { Category: not (Boolean or National) } rp' category funnel all fall through on null -- the range is stored unchecked. The spec makes the antecedent real, not hypothetical: 13.18.29.4 GR1 a) 'The subject of the entry is a bit group and also a bit data item; its class and category are boolean' (cite.py --check 13.18.29.4 -> OK), and SR10 -- applied to Format 3 by SR24 -- speaks explicitly of 'the VALUE clause of a bit group item', so a bit group is a contemplated Format-3 subject. This is the project's most reproducible defect shape (a scalar guard that sees only an elementary PICTURE) and the closing sentence of the adjudication is exactly where it hid. The elementary arm IS enforced, at every boolean-bearing edition, so the row is PARTIAL, not DIVERGES: one of two subject shapes. Keep test-ref conformance-test:NationalBooleanDataTests.IllegalValueShape_Rejects0898 -- I read it and case NBDAT11 ('01 WS-K PIC 1(2).' + '88 WS-K-RANGE VALUE B"00" THRU B"11".') really is spec-derived from SR29 and really does pin the elementary branch -- but it is a witness for one half only, which is itself the PARTIAL.
