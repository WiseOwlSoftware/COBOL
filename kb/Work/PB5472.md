# PB5472 - at --std 85 WITH DEBUGGING MODE a debugging line inside pseudo-text-2 that replaces a word in the middle of a library line is refused COBOL7061: the debugging-line check hides every token of the replaced library line

**Sites:**

- `src/WiseOwl.Cobol.Frontend/Pipeline/Frontend.cs` (`Frontend.ReportDebuggingLinesBreakingTheProgram`)
- `src/WiseOwl.Cobol.Frontend/Common/SourceLineMap.cs` (`OriginWriter.Append`)

**Mechanism.** Debugging lines "are permitted within library text and pseudo-text" (GR7), and whether the program is correct without them is decided "After all COPY and REPLACE statements have been processed" (§1985:VI.7.3). The COBOL7061 check hides each token whose line is a debugging line's, and a replacement's tokens carry the origin of the replaced library line (`OriginWriter.Append`), so hiding the D line that holds `QQ` also hides `DISPLAY "["` and leaves `"]".` unparseable. The same text written by hand compiles (`q19e`). The refuter named this mechanism as likely; the fix confirms it. kb/Work PB5313 is the area-A consumer of the same origin.

**Found by.** The 1985 code read, read 4 (`kb/Work/PB4996/2026-11-13-read-4.md`): the refuter of `E:/COBOL-coord/scratch/coderead-85/out-read4/rd-06-refute.json` OVERTURNED the read's CONFORMS of 1985-GR-XII.2.4-7.
