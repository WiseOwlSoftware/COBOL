# PB4936 - one cascade rule for a refused repository specifier, and a backstop that still checks

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/UdfBinder.cs` (`UdfBinder.UdfBindCall`, `UdfBinder.UdfBindPointerCall`), `src/WiseOwl.Cobol.Compiler/Binding/ConfigurationSlice.cs` (`ConfigurationSlice.RefusedFunctionSpecifiers`, `ConfigurationSlice.RefusedProgramSpecifiers`), `src/WiseOwl.Cobol.Compiler/Binding/EditionContext.cs` (`EditionContext.NoteCauseReportedEarlier`, `EditionContext.NoteSpecifierRefusalReported`, `EditionContext.ErrorsRecorded`, `EditionContext.NoteRefusal`), `src/WiseOwl.Cobol.Compiler/Binding/LinkageBinder.cs` (`RefusedSpecifierKind`), `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs` (the FUNCTION arm of the REPOSITORY binding), `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.Configuration.cs` (`DataBinder.BindProgramSpecifier`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CallBinder.cs` (`CallBinder.ResolvePrototype`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/SetBinder.cs` (the ADDRESS OF PROGRAM operand), `ConfigurationSlice.IsRefusedProgramReference` / `ConfigurationSlice.IsRefusedFunctionReference`

**Lead R1-1 (low).** PB4822 made a reference through a function specifier whose `AS` literal-5 was refused (`§2023:12.3.8.3 SR2`, checked by the implementer) a silent cascade:
`UdfBinder.UdfBindCall` asks `Configuration.RefusedFunctionSpecifiers` first, calls `Edition.NoteCauseReportedEarlier()` and returns a refused expression, so only
COBOL1761 at the specifier remains. Its named twin `RefusedProgramSpecifiers` (PB4708: a refused `AS literal-3` of a PROGRAM specifier) still reports a SECOND diagnostic
for the same cascade through a refused program reference. The two twins disagree on one posture and PB4822's sibling sweep did not reconcile the program arm
(it records only that class, interface and property specifiers are PB4773's). Expected: one rule for every refused specifier kind: the cause is reported where
the specifier is written and each reference is silent. Fix by making the program arm follow `NoteCauseReportedEarlier`, and add a theory over specifier kinds
(`ExternalRepositoryResolutionTests`) so the next kind is automatic. Not probed by the clerk; the reviewer read it from the two code paths.

**Lead R1-3 (low).** `EditionContext.ErrorsRecorded` is documented as counting every `Error(string,string)` call; `NoteCauseReportedEarlier` (line 224)
now increments it with NO Error call, and nothing checks the caller's guarantee that an earlier error really was recorded. So the PB1029 backstop in `NoteRefusal`
(`if (ErrorsRecorded == 0 && ...) Error(unreported, ...)`, which exists to catch a refusal that drew no diagnostic) can no longer catch a wrong caller: a caller that wrongly
claims "reported earlier" turns a silent refusal into a pass. Expected: `NoteCauseReportedEarlier` takes the node or key whose error was recorded and asserts the
ledger holds one for it (the refusal-ledger funnel is per refusal node), or the backstop keeps a separate counter; the doc comment states which. Source report and
leads: `w20261905h-PB4822-report.md`, R1-1 and R1-3.

**Landed.** `EditionContext` keeps a ledger of refusals reported at the specifier (`NoteSpecifierRefusalReported(RefusedSpecifierKind, word)`); `NoteCauseReportedEarlier(kind, word)` raises `ErrorsRecorded` only when the ledger holds one and returns false otherwise, so the PB1029 backstop stays honest (R1-3). The program arm (R1-1) asks `ConfigurationSlice.IsRefusedProgramReference` in `CallBinder.ResolvePrototype` and the ADDRESS OF PROGRAM operand: a reference through a refused AS literal-3 is silent, like the function twin. Witnesses: `ExternalRepositoryResolutionTests.AReferenceThroughAnyRefusedSpecifier_AddsNothingToItsRefusal` (a theory over kinds), the two reworked PB4708 facts, `EditionContextTests.NoteCauseReportedEarlier_AnswersOnlyForARefusalTheLedgerHolds`. The REPO-1 and repository-finding routes keep their COBOL1760 sentence.
