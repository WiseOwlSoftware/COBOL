# PB1572

Found 2026-09-25 by the w59m (PB1569) implementer's sibling sweep; reproduced on the main checkout (cdb084309) too.
Repro `<scratchpad 9db39f61…>\w59m\r3.cob` at `--std 2002`. Controls that work: a bit leaf at bit 1 (`r5.cob`) and the same
group WITHOUT the REDEFINES (`S4=11`).

Rules (cite.py --check before quoting): §13.18.44.4 GR1 (REDEFINES — one storage area) and §8.5.1.6.3 (bit placement).
Likely sites (unconfirmed): `src/Cobol.Net.Compiler/CodeGen/Roslyn/PlaceRenderer.cs:204` (the BitWindow write arm of
RedefViewPlace) and the bit-group member offset from `DataBinder.AssignClassOffsets` (~6410). After PB1569 lands, the one
placement predicate is `BitLayout.SharesByteWith` — the window write must derive its bit offset from the same layout, not
a second computation (variant-analysis: every Tier-B window read/write arm).

## Landed (wave 1001 B)

Re-probed on this wave's Debug build (`r3.cob --std 2002 --run`): `R3V=10000000 P1=0 S3=00`, as filed. Citations
re-run through `cite.py --check`: the note's "§13.18.44.4 'one storage area'" does NOT occur in §13.18.44.4 (FAIL);
the storage association is §13.18.44.4 GR1 ("Storage association for the subject of the entry starts at the first
bit of the data item referenced by data-name-2 ...", OK) and the bit placement is §8.5.1.6.3 (OK, both quoted rules).

**Mechanism (not the filed guess).** The write arm of `RedefViewPlace` was right; the OFFSET it was given was wrong.
`DataBinder.AssignClassOffsets` (the REDEFINES-class offset walk) kept its OWN §8.5.1.6.3 cursor, seeded with the
group's ABSOLUTE bit offset, and rounded THAT up to a byte before the first child: a bit group at bit 1 put its first
member at bit 8. It was the THIRD copy of the placement loop (`BitLayout.ExtentBits`, `BitLayout.StartBitWithin`);
the predicate had been shared (PB487) but the loops had not. Only a RELATIVE cursor can honor "the alignment of the
start of a group item and the alignment of the first item within that group, when the first item is a bit data item,
are at the same bit position in storage".

**Fix.** `BitLayout.Walk` is the ONE cursor walk (relative to the group); `ExtentBits`, `StartBitWithin` and the new
`ChildStarts` read it; `DataBinder.AssignClassBitOffsets` places each child at the group's absolute offset plus
`ChildStarts[i]` and runs no cursor. The `bitLaid` flag and `ClassExtentBits` are gone (a subtree without a USAGE BIT
leaf is whole bytes, so the round-up is the identity). Sweep: `SharesByteWith|RoundUpToByte` callers outside
`BitLayout.cs` = 0 after the fix (was 1: DataBinder.cs:7122); the EXTERNAL and BASED cell-backed classes share the one
function (probe `r3x.cob`: `X=1 10 1 0 1`, `Y=1 01 0 1 1`, correct).

Witnesses: `2002/pb1572_bit_group_redefines_offsets` (+ negative `pb1572-bit-group-redefines-below-2002`, COBOLNET0900
at `--std 85`); `BitRunImageDriftTests` shapes BRD07/BRD08 and `NoCodeOutsideBitLayout_RunsItsOwnPlacementCursor`
(each seen to FAIL on the pre-fix tree: 3 failed / 7 passed, then 10 / 10 on the fix).
