# PB5076 - at --std 85 AT END or INVALID KEY is not required when no USE AFTER STANDARD EXCEPTION procedure covers the file: READ, WRITE, REWRITE, DELETE and START all compile without the phrase

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/KeyedIoBinder.cs` (`BindRead`, `BindWrite`, `BindRewrite`, `BindDelete`, `BindStart`; line 240 holds only the sequential-access prohibition), `src/WiseOwl.Cobol.Compiler/Validation/FlagConformancePass.cs` (`AdmitsInvalidKey`, `FlagIoDeclarative` read a missing INVALID KEY only as a flag); SequentialIoBinder is named without a member.

**Mechanism.** Every 1985 I-O statement carries one syntax rule of the form "the AT END (or INVALID KEY) phrase must be specified if no applicable USE AFTER STANDARD EXCEPTION procedure is specified for file-name-1" (DELETE, REWRITE, WRITE and START for non-sequential access; READ with either phrase). No pass asks it at --std 85: the binders accept the statement without the phrase whether or not a covering USE procedure exists (the allowed arm, a covering USE procedure, compiles as the rule permits; the refused arm never refuses), and FlagConformancePass reads a missing INVALID KEY only for the 2023 FLAG-14 warning. One missing check across the five statements and the three file organizations.

**Found by.** The 1985 `--std=85` draft triage (kb/Work PB4995 item 3): each rule below is a conformance-suite draft that did not MATCH at `--std 85`, and its adjudicator decided COMPILER-DEFECT. Harm and observed text are the records'; nothing here was re-derived.
