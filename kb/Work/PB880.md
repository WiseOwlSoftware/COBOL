# PB880 — OPEN — a statement built after the passes that decide how its operands are stored

Source: the `PB425` report, "New defects" item 1. Same repro as `PB879`; different mechanism.

## The measurement

`<scratch>/reg6/probe/p03_init_space_num.cob`, `--std 2023 --run`:

```
Unhandled exception. CobolNet.Runtime.NotImplementedCobolFeatureException: ... MOVE of an alphanumeric
figurative constant into the numeric item 'N' **without image-backed storage** (a BINARY/PACKED/COMP-5/float
or Tier-A shared-storage receiver has no character image to fill ...)
rc=127
```

`01 G. 05 N PIC 9(3).` is an ordinary DISPLAY numeric. It has no image-backed storage **because nothing asked
for one**: `MarkFillImageStorage` collects `StoreAsImage` for `StorageFormPass` from the BOUND tree, and this
move does not exist yet when that runs.

## The code site

```
src/Cobol.Net.Compiler/CodeGen/Verbs/InitializeEmitter.cs:43
    move.Emit(new BoundMove(s.Source, [s.Target]));
```

`tests/Cobol.Net.Tests.Unit/.../ImplicitMoveConstructionDriftTests.cs` already carries the whole inventory:
its `EmitterBuiltMoves` dictionary names **the three NON-phrase implicit moves that remain emitter-built** —
MOVE CORRESPONDING's per-pair moves, INITIALIZE's REPLACING store, and GOBACK RETURNING — and its
`EveryEmitterBuiltBoundMove_IsOneOfTheKnownNonPhraseMoves` fails when a FOURTH appears. **A green test that
enumerates three known holes is a decision, not a gate** (memory `green_test_can_hold_a_gap_open`): it keeps
the count from growing and asserts nothing about the three.

## Expected, from the spec

```
$ python scripts/spec/cite.py --check 14.9.20.4 "MOVE sending-operand TO receiving-operand"
  OK  §14.9.20.4 4)  (General rules)
```

GR4 makes the implicit form the SAME statement as the explicit one. An explicit `MOVE SPACE TO N` at
`--std 85` stores `'   '` into N's image without difficulty, because the bind-time pass saw it. The implicit
one cannot, at any edition.

## The remedy — and why it is a restructuring, not a third `if`

The three moves must be BOUND, not emitted: built in the binder (where `MoveBinder.BindMoveOf` already
classifies, freezes and screens them) and carried on the bound node the emitter walks. The drift test then
changes from *"these three are known"* to *"there are none"*, which is a gate that cannot rot. Doing it for
one of the three leaves a dictionary with two entries and the same shape — take all three.

## The sibling sweep

Everything the bind-time passes decide is in scope, not only image storage: the version-conformance gate
(PB879 is the same program failing for that reason), `SendingValueTemp`'s carrier choice (PB886),
`MoveClassifier`'s length-freeze route, and EC arming. The fixer should list what `MoveBinder.BindMoveOf`
does that `new BoundMove(...)` skips and put the list in the design doc, because that list IS the defect.
