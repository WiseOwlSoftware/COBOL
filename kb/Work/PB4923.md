# PB4923 - does a nested selection of a float item count as "renders as floating-point" for SUM, MEAN, MIDRANGE and RANGE?

**Sites:** `src/WiseOwl.Cobol.Runtime/Intrinsics/CobolIntrinsics.ExactValue.cs` (`CobolIntrinsics.SumExact`, `CobolIntrinsics.MeanExact`, `CobolIntrinsics.MidrangeExact`, `CobolIntrinsics.RangeExact`, `CobolIntrinsics.TryBinary64Body`, `CobolIntrinsics.Median`), `src/WiseOwl.Cobol.Runtime/Values/Numeric/CobolExact.cs` (`CobolExact.Add`, `CobolExact.Sub`, `CobolExact.Mul`, `CobolExact.DivTruncated`, `CobolExact.DivToOdd`, `CobolExact.QuotientAtScale`, `CobolExact.Pow`, `CobolExact.TryBinary64Operands`, `CobolExact.AsBinary64`, `CobolExact.OfBinary64Result`), `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/IntrinsicRenderer.cs` (`IntrinsicRenderer.RenderDec`), `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/NumericRenderer.cs` (`NumericRenderer.Power`), `src/WiseOwl.Cobol.Compiler/CodeGen/Roslyn/RuntimeApi.cs` (`RuntimeApi.ExactPowReal`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/FunctionValueLane.cs` (`FunctionValueLane.NativeSdidiBodiesWithWholeResult`, `FunctionValueLane.NativeSdidiBodiesWithExactResult`), `src/WiseOwl.Cobol.Runtime/Values/Numeric/CobolExact.cs` (`CobolExact.TryBinary64`, `CobolExact.PowReal`)

**Report.** PB4891 made binary64-ness a property of the VALUE (`CobolExact.FromBinary64` marks a float item's content, `TryBinary64` reads it) so a
selection (MAX, MIN, MEDIAN) returns the mark whole; MEDIAN reads it. The implementer's second look found the other exact-lane bodies do not.
Repro `E:/COBOL-coord/scratch/w20261905b/p1/s.cob` (F FLOAT-LONG 0.1, M2 0.05, M 0.5): `SUM (MAX (F M2) M)` is .6000000000000000055... on both DISPLAY and
COMPUTE where `SUM (F M)` is the binary64 0.6; `MEAN` likewise 0.30000000000000000277 vs 0.3; `COMPUTE R = MAX (F M2) + M` 0.60000000000000000555
vs `F + M` 0.59999999999999997779; also `SUM (MAX (F M2) EXP10 (-6))` (`k.cob`). The two channels agree (no DISPLAY/COMPUTE split).

**The question for the adjudicator.** `docs/CONFORMANCE.md` DOC-A.1-92b keys the binary64 lane on an argument that "renders as floating-point"
(an argument-1 FLOAT-LONG/SHORT item or a function returning one: §2023:15.4.1 makes the result of native arithmetic an implementor-defined
approximation; the clerk checked that clause, `cite.py --check "§2023:15.4.1" "implementor-defined approximation"` OK). Does MAX (F M2)'s returned
value, whose content IS the float item's binary64, count? If yes, `SumExact`, `MeanExact`, `MidrangeExact`, `RangeExact` and their `...Whole` bodies read
`CobolExact.TryBinary64` as MEDIAN now does, and the arithmetic-expression arm (`MAX (F M2) + M`) gets the same mark through `CobolExact.Add`.
If no, DOC-A.1-92b states that a selection's content is the exact decimal and PB4891's MEDIAN rule gets the same sentence. Same root as PB4891: the
kind of a nested selection is a run-time fact, not a compile-time one. wrong_answer is the harm under the yes reading.

Source report and lead: `w20261905b-PB4891-report.md`, New defects 1.

## Determination and fix (landed)

YES: a nested selection's returned content that IS a float item's binary64 renders as floating-point (DOC-A.1-92b, §2023:15.4.1 "an implementor-defined
approximation of the value of that expression"; the same reading PB4891 gave MEDIAN). `SumExact`, `MeanExact`, `MidrangeExact`, `RangeExact` (and their
`...Whole` twins) are now one body per function with the SDIDI mode as the lane switch (the MEDIAN shape) and return `CobolExact`; each asks
`TryBinary64Body` whether any argument value is binary64 (`CobolExact.TryBinary64`, a run-time fact) and evaluates `SumReal`, `MeanReal`, `MidrangeReal`
or `RangeReal` over the arguments' doubles, the result a float item's content when a float item is among them, else an approximation
(`CobolExact.OfBinary64Result`, which MEDIAN's mean now uses too). The arithmetic-expression arm: `CobolExact.Add`, `Sub`, `Mul`, `DivTruncated`,
`DivToOdd`, `QuotientAtScale` and `Pow` evaluate in binary64 when an operand is a float item's content (an approximation beside fixed-point operands
stays exact: `NumericRenderer.FloatItemLane`). Re-probe before the fix: S1 `.6000000000000000055...`, MEAN `.30000000000000000277`, `MAX (F M2) + N` `0.80000000000000000555`
against `F + N` `0.79999999999999993338`; after: each pair equal. Golden `pb4923_arithmetic_over_a_nested_selection_of_a_float_is_binary64` (+ `_below_2002`).
