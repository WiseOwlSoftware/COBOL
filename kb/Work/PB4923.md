# PB4923 - does a nested selection of a float item count as "renders as floating-point" for SUM, MEAN, MIDRANGE and RANGE?

**Sites:** `src/WiseOwl.Cobol.Runtime/Intrinsics/CobolIntrinsics.ExactValue.cs` (`CobolIntrinsics.SumExact`, `CobolIntrinsics.MeanExact`, `CobolIntrinsics.MidrangeExact`, `CobolIntrinsics.RangeExact`), `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/IntrinsicRenderer.cs` (`IntrinsicRenderer.AnyRealArgument`, `IntrinsicRenderer.AnyFloatItemArgument`), `src/WiseOwl.Cobol.Runtime/Values/Numeric/CobolExact.cs` (`CobolExact.TryBinary64`)

**Report.** PB4891 made binary64-ness a property of the VALUE (`CobolExact.FromBinary64` marks a float item's content, `TryBinary64` reads it) so a
selection (MAX, MIN, MEDIAN) returns the mark whole; MEDIAN reads it. The implementer's second look found the other exact-lane bodies do not.
Repro `E:/COBOL-coord/scratch/w20261905b/p1/s.cob` (F FLOAT-LONG 0.1, M2 0.05, M 0.5): `SUM (MAX (F M2) M)` is .6000000000000000055... on both DISPLAY and
COMPUTE where `SUM (F M)` is the binary64 0.6; `MEAN` likewise 0.30000000000000000277 vs 0.3; `COMPUTE R = MAX (F M2) + M` 0.60000000000000000555
vs `F + M` 0.59999999999999997779; also `SUM (MAX (F M2) EXP10 (-6))` (`k.cob`). The two channels agree (no DISPLAY/COMPUTE split).

**The question for the adjudicator.** `docs/CONFORMANCE.md` DOC-A.1-92b keys the binary64 lane on an argument that "renders as floating-point"
(an argument-1 FLOAT-LONG/SHORT item or a function returning one: §2023:15.4.1 makes the result of native arithmetic an implementor-defined
approximation; the clerk checked that clause, `cite.py --check "§2023:15.4.1" "implementor-defined approximation"` OK). Does MAX (F M2)'s returned
value, whose content IS the float item's binary64, count? If yes, `SumExact`, `MeanExact`, `MidrangeExact`, `RangeExact` and their `...Whole` bodies read
`CobolExact.TryBinary64` as MEDIAN now does, and the arithmetic-expression arm (`MAX (F M2) + M`) gets the same mark through `CobolExact.Add`.
If no, DOC-A.1-92b states that a selection's content is the exact decimal and PB4891's MEDIAN rule gets the same sentence. Same root as PB4891: the
kind of a nested selection is a run-time fact, not a compile-time one. wrong_answer is the harm under the yes reading.
