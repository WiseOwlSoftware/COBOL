`TO` one is the UNDERLINING on the printed page of §13.18.60.2 — re-render it (`python
scripts/render-spec-page.py 503`) before writing the code comment, per CLAUDE.md rule 1.

## ⚠ The carrier of the defect is the AUDIT

`python scripts/spec/audit_grammar_optional_words.py` measures 320 general formats and reports **0 candidates**:
its heuristic cannot see the `KEYWORD <unstressed word> operand` shape, so fixing the three grammar rules
without fixing the audit leaves the whole family unmeasurable. kb/Work PB695 is the optional-word family's
landed repair of a DIFFERENT blindness (PB332's), which is why this is a new note and not an append: the shape
it misses is not the shape PB695 taught it to see.

## Landed — 2026-09-22, wave 46 group H, worktree `wf_f206ae6d-3b7-1`, base `8fe62bd1f`

Re-probed first: `01 P USAGE POINTER REC-T.` was still `COBOLNET1941 'REC-T' is not a clause`. Folio 503 was
RENDERED (PDF p533): the underline rule sits under POINTER / FUNCTION-POINTER / PROGRAM-POINTER and never under
TO, and under FACTORY but not OF in OBJECT REFERENCE's `[ FACTORY OF ]`.

* `CobolData.g4` — the three pointer usages are `KEYWORD (TO cobolWord | {pointerOperandHere()}? cobolWord)?`.
  The TO-less operand is a bare `cobolWord` at the end of a clause; `pointerOperandHere()` refuses any token in the
  FOLLOW set of `usageKeyword` computed off the GENERATED ATN. MEASURED: with no predicate, `USAGE POINTER BIT`
  bound BIT as a type-name (BIT / NATIONAL are gate-exempt §15 function names and bare USAGE keywords); with a
  FIRST(dataDescriptionClause) predicate, `USAGE POINTER HIGH-ORDER-RIGHT` bound the endianness phrase
  (UsageFloatFormatPhraseDriftTests, Unit). FOLLOW(usageKeyword) covers both.
* `CobolOO.g4#objectReferenceUsage` — `(FACTORY OF)?` → `(FACTORY OF?)?` (the sibling the note's sweep named).
* `DataBinder` — the SR18/SR19 screen and FUNCTION-POINTER's mandatory operand read the OPERAND's presence, never
  the TO token's; COBOLNET1958's text now says `[TO] function-prototype-name`.
* Screen / report usage positions: none has its own pointer rule — every USAGE reaches `usageKeyword`, so the
  one fix covers them.
* Goldens: `2014/pb848_pointer_usage_to_optional` (TO-less and TO-full twins of all three usages, copied between
  under §14.9.39.3 SR19/SR20/SR22 — admissible only if both name the same type/prototype) and negative
  `pb848-function-pointer-to-less-below-2014`; `OptionalWordSubsetDriftTests` rows `pointer-usage-to` and
  `object-reference-factory-of` (power set of the optional words).
* ⚠ THE AUDIT HALF IS kb/Work PB715, NOT A NEW MECHANISM. `audit_grammar_optional_words.py` misses these words
  because `scan_alternative` treats every token of a `( … )?` group as omittable — PB715's filed defect — so the
  audit was not changed here (one mechanism per implementer); the two drift rows are the mechanical guard until
  PB715 lands. A SECOND blindness was measured on the way (the anchor keyword USAGE is itself optional, so no rule
  "demands" it and the closure is empty) and is reported as a lead for the registrar.
