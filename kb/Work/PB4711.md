# PB4711 — adjudication: CONCAT's boolean-expression exemption has no supporting text

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/IntrinsicArgumentRules.cs:1444` (`IntrinsicArgumentRules.PredicateViolation`)

Reported by the branch review, not probed. R1-3, copied: the comment justifying the boolean-expression exemption from the "data item or literal" predicate cites 15.3 type 3 and CONCAT's class list, but 15.18.3 r1 says "data items or literals" and 15.12.3 r1 lists no boolean class; pre-existing acceptance, not a regression. The review left it as a determination: pb124's two CONCAT lines would change (the golden `pb124_boolean_argument_boundary` pins the acceptance today).

The question for the adjudicator: does a boolean expression, as opposed to a boolean data item or literal, satisfy CONCAT's argument rule? The citations above are the review's and have not been run through `cite.py --check` here.

## Decision (landed)

Re-probed on the branch build: CONCAT(WS-A B1 B-AND B0) compiled and ran. Determination: §2023:15.18.3 AR1 requires data items or literals; a boolean expression (§2023:8.8.2) is neither, and §2023:15.3 type 3 binds only positions whose class kind is boolean. Fix: IsBooleanExpression joins the arithmetic-expression test in PredicateViolation (COBOL1627); bare boolean items and literals stay legal. Goldens: pb124_boolean_argument_boundary (now adjacent items/literals), refusal pb4711-concat-boolean-expression.
