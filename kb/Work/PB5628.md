# PB5628 - a RELEASE or RETURN in a contained program called from the input or output procedure is refused at --std 85

**Sites:**
- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/SortBinder.cs` (`SortBinder.BindRelease`)
- `src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs` (`VersionConformancePass.GateReleaseReturnRange`)

**Rule.** §1985:XI.4.4.4 GR7 puts every statement the input procedure executes in the procedure's range, including those
reached by a CALL ("all statements in declarative procedures that are executed as a result of", `cite.py --check` OK for
the declarative half PB5572 landed; the CALL half is the same range sentence).

**Repro** (`E:/COBOL-coord/scratch/op-20261114/out-read6/work-rd-02/c5/r9.cob`). `SD SORT-A` with `01 REC-A IS GLOBAL`; the
input procedure CALLs the nested program `R9N`, which RELEASEs. At `--std 85` the compiler refuses it COBOL1757 (from
`SortBinder.BindRelease`), and `GateReleaseReturnRange` would refuse it too: `ProcedureReach.Closure` is per program, so a
RELEASE in a contained program has an empty range.

**Needs.** A cross-program reach (the input procedure's range through a CALL to a contained program) and a 1985 reading of
the GLOBAL record of a non-GLOBAL SD (§1985:X.4.6.3 SR1 per the reader). Needs an adjudication of that second half before
the fix. Shares no root with PB5564 or PB5573 (the other two PB5572 landings).

**Fix direction.** Make the range a property of the whole compilation group's reach graph, not of one program, and let
both `BindRelease` and `GateReleaseReturnRange` ask it.
