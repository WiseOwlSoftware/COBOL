# PB3720 — the workstream skill's files are outside every campaign root

**Sites:** `scripts/orchestrator/model_rules.json` (the `campaign` entry's `src` and `exclude_dir`), `scripts/orchestrator/coord.py` (`campaign`).

Found 2026-10-25 ~10:20 PDT by the wave unit of wave 20261107 (session 5ee3740f): `plan_wave.py --cluster PB1957`
planned group B (PB3701) `UNPARTITIONED`, although PB3701's `**Sites:**` paragraph names four files.

## Repro

    python -c "import sys,pathlib; sys.path.insert(0,'scripts/spec'); import work; print(work.note_sites(pathlib.Path('kb/Work/PB3701.md').read_text(encoding='utf-8')).paths)"

prints `()`. PB3701's sites are `.claude/skills/workstream/templates/dispatch-spec-implementer.md`,
`.claude/skills/workstream/check_practices.py`, `.claude/skills/workstream/templates/fix-lane-implementer-brief.md` and
`.claude/skills/workstream/templates/MANDATORY-PRACTICES.md`. `work.note_sites` keeps a path only under a campaign root
(`coord.campaign().roots`, from `model_rules.json` `campaign.src`), and the roots are `src`, `tests`, `scripts`,
`.github`, `docs`: `.claude` is not one, so every one of those paths is dropped and the note declares nothing.

## Harm

The process campaign PB1957 is largely work on `.claude/skills/workstream/` (the spec template, `check_practices.py`,
`make_dispatch_specs.py`, `wf_rolling_wave.js`, MANDATORY-PRACTICES) and `.claude/agents/`. Three open PB1957 notes are
sited there today (PB3701, PB3702, PB3706). Each is planned with an empty set, which by design (DESIGN-orchestrator-loop.md
section 9 item 1b, kb/Work PB3670) meets nothing in flight or in the wave, so two such notes run side by side on the same
template or check and the second landing needs a conflict finisher: the case the owner's 2026-10-24 correction was about
(PR #505). Wave 20261107 was safe only because no other group touched those files, which the planner did not know.

## Fix direction

The campaign domain covers the tracked process code: add the tracked `.claude` subtrees (`.claude/skills`,
`.claude/agents`, `.claude/workflows`; `git ls-files .claude` lists them) as roots, never `.claude` whole, because
`.claude/worktrees/` holds whole working copies of the repository (ignored in `.git/info/exclude`, but a root walk that does
not ask git would cluster over every one). A drift test pins it: every open note's site path that names a TRACKED file
yields that file in `note_sites(...).paths`. The guard against the silent drop itself (a site block that names files but
declares none) is PB3721's.
