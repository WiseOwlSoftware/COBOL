# PB6348: the enqueue handoff's `landed` shape, and a check every unit can run

**Evidence.** `Get-Content <file> -Raw | Test-Json -SchemaFile scripts/orchestrator/handoff.schema.json` on
`E:/COBOL-coord/logs/20261127-222954-enqueue.handoff.invalid.json` and `20261127-221657-enqueue.handoff.invalid.json`
fails with `Value is "array" but should be "object" at '/landed'`; the 11-23 13:41 and 11-27 18:03 invalid enqueue
handoffs carry `landed` as a list too. Each failure costs the loop a synthesized handoff, a resume unit that rebuilds the
state, and one count toward the three-failure circuit breaker (orchestrate.ps1).

**Cause.** `units/enqueue.md` step 8 said "Write the handoff (`landed`; the branches still pending ...)", which reads as
a list of landed branches; the schema's `landed` is an object (`commits`, `gap_before`, `gap_after`, `devlog_entry`).
The 22:29 unit tried to validate and could not: `import jsonschema` fails on the host, and no unit prompt named the
supervisor's own test.

**Fix.** `units/enqueue.md` step 8 states the shape of `landed` and that it is omitted when nothing landed;
`units/common.md` gives every unit the supervisor's exact check (`pwsh ... Test-Json -SchemaFile ...`) to run before it
ends, so any schema error, not just this one, is caught by the unit that made it.
