## Today's code

`ReferenceFormatProcessor.LogicalConversion.cs#FixedFormConverter` owns the latest-logical-line index (`_latest`),
the carried `LiteralState` (`_literal`), `Emit` / `Discard` / `Continue`. The free arm is
`#ConvertFreeFormMapped` / `#ConvertFreeLine`: per line, strip the comment, keep the line — no state crosses a line,
so a free-form `"ABC"-` can never be joined. `ScanProgramText` already carries the opening quotation symbol
(`LiteralState.Quote`) — PB1492's F2 half is gone — but nothing records the literal's KIND (alphanumeric / boolean /
national / hexadecimal), which SR4 and §6.3.5's national rule need.

## The design (rule 5 — "the next case is automatic", DESIGN-frontend-grammar §3.6.0 already promises it)

`LogicalLineBuilder` (extracted from `FixedFormConverter`): the resultant line list + origins (spans, PB1801), the
latest logical line, the literal state `(Quote, Kind, PendingClose, ContinuedBy: none|fixed|floating)`, and whether
the latest logical line is a COMPILER DIRECTIVE line. Operations: `Source(text, spans)`, `Discard(line)`,
`ContinueFixed(area, line)`, `ContinueFloating(text, line)`. Each reference format supplies only a per-line
classifier (fixed: `KindOf` + program-text area; free: whole line). Then:

- **PB1359** — a line whose program text ends, outside a comment, in an unterminated alphanumeric / boolean / national
  literal followed by `-` (§6.5 4)) ends before the indicator; the next non-comment, non-blank line is a continuation
  (either format); §6.2.3.2 SR4 (only those three kinds; one form per literal), SR5 (not on a column-7 continuation
  line), §6.3.7.3 / §6.4.4.3 (no inline comment on a floating-continued line) and §6.4.2's "at least one character on
  each line" are checks of the builder's state. `TextWord.cs#LiteralEnd` (pseudo-text) asks the same state instead of
  ending a literal at the line end.
- **PB1492** — `ContinueFixed` / `ContinueFloating` require the continuation's first non-space character to be the
  OPENING quotation symbol (§6.2.3.2 SR6), refuse the fixed indicator on a national literal (§6.3.5 2)), refuse a
  non-literal splice that forms `*>`, `==` or another multiple-character separator/indicator.
- **PB1360** — a continuation line whose latest logical line is a directive line is diagnosed and NOT joined (the
  flag is set when `DirectiveText` + `CompilerDirectiveLine.TryParse` recognizes the line; §7.3.3 1)); the >>EVALUATE
  operand half stays in `ConditionalCompilationProcessor`.

**Drift test.** Each continuation rule is a builder method with one table-driven unit test per format (the same case
through the fixed and the free classifier must give the same logical line), and a reflection test that
`ConvertFreeLine`-style line-for-line conversion no longer exists.

**Sizing.** Extracting the builder and moving the free arm onto it: one Sonnet slot (behaviour-neutral — the whole
battery is the oracle). PB1359, then PB1492's validation half, then PB1360 are each one Sonnet slot ON the builder;
PB1359 needs the edition row for the floating literal continuation indicator (check VCR; add the `constructs.json`
row with the `new-construct` skill). Independent of PB1800 (it consumes lines, whatever produced them) but it should
land after PB1800 to avoid a double rebase of the same two files.
