# PB1591

**What happened.** `build_lane1_inputs.py` named its input files by family alone (`misc-p1` … `misc-p10`), the same
slugs golden lane 1 used — and lane 1's input files are committed under `adjudication/golden-lane-1/scratch/in/`.
Lane 2's writer for `misc-p2` returned 12 rows, none of which were in its input file
(`<scratch>/lane1/in/in-misc-p2.json`, 13 rows); they are exactly lane 1's misc-p2 rows (BLOCK CONTAINS, DOC-A.1-16,
SR-11.3.3-4 …). The refuter and fixer then worked on the foreign drafts. The other ten files matched their inputs
13/13, 12/12 … exactly.

**Why it was nearly silent.** The tally counted 119 of 120 rows, which read as "one row dropped". Only a per-file
set comparison (input rule-ids vs returned rule-ids: overlap 0, foreign 12) showed the file was wholly wrong. The
writer did not report a deferral because, from its view, it finished its rows.

**The mechanism, and the fix.**
1. LANDED (golden lane 2): `build_lane1_inputs.py` now REQUIRES a lane prefix (`<prefix>-<family>[-pN]`) and refuses
   to run without one, so a slug can never again name another lane's file.
2. OPEN: the lane's integration step must assert, per slug, that the returned rule-ids are a SUBSET of that slug's
   input rule-ids and refuse (not filter silently) any foreign row — the population check this defect exposed as
   missing. Golden lane 2's landing applies it by hand; the template integrate script owes it.
3. Lane 2's misc-p2 was re-run as `gl2-misc-p2`; its foreign drafts are quarantined and are NOT landed.
