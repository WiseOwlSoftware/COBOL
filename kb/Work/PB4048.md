# PB4048 — no manifest pin for Microsoft.NET.ILLink.Tasks, so no automated trimmed-publish witness

**Sites:** `toolchain.env` (the manifest; `DOTNET_SDK_VERSION` is its .NET line); `scripts/toolchain.py` (`TOOLS`, `Tool`, `check`, `ci_installs`, `installer_problems`); `scripts/install-tool.sh` (`TOOL_INSTALLABLE`); `scripts/wsl/setup-wsl.sh`; `scripts/cloud/setup-env.sh`; `.github/actions/setup-toolchain/action.yml`; `docs/rearchitecture/DESIGN-external-repository.md` (§17.5).

**What.** `dotnet publish -p:PublishTrimmed` needs `Microsoft.NET.ILLink.Tasks`, whose version is matched to the SDK. MSBuild
restores it from NuGet at publish time. On this Windows box under SDK 10.0.403 that restore hangs on NuGet, so PB2101
(slice 5) landed no automated trimmed-publish witness. Nothing in `toolchain.env` names the package, so CI and the hosts
neither install nor check it, and a publish that works on one host resolves another version, or none, on another: the
skew PB4007 closed for the tools.

**Cure.** Pin the package in the one manifest (PB4007: one manifest names each version; the daily `toolchain.py latest`
run keeps it latest), install it from the manifest on CI (`setup-toolchain`), WSL and the cloud image into a package source
that publish restores from offline, and have `toolchain.py check` fail when it is absent or another version, with the
drift test (`ToolchainManifestDriftTests`) extended to the new row.

**Depends on PB4047.** The composed form of the witness, a trimmed .NET host referencing the main program's and the callee's
assemblies (`DESIGN-external-repository.md` §17.5), also needs PB4047: the emitted assemblies reference
`System.Private.CoreLib`, so such a host does not build. Landing this note alone unblocks only the single-assembly trimmed
publish.
