# PB5732 - at --std 85 the nested-COPY gate judges the library text BEFORE its REPLACING is applied, where §1985:XII.2.4 GR12 judges the text the complete processing produces: a COPY ... REPLACING whose produced text holds no COPY statement is refused COBOL0900 (and GR8's 'cannot be independently determined' is broken)

**Sites:**
- `src/WiseOwl.Cobol.Frontend/Preprocessor/CopyProcessor.cs#ResolveOneCopy` (tests the library text with `FindStatementKeyword` before `ApplyReplacements` and, below 2002, raises `Constructs.CopyNestedLibraryText2002`, COBOL0900, under GR12)
- `src/WiseOwl.Cobol.Frontend/Preprocessor/CopyProcessor.cs#ParagraphWordAsReplaced` and `#NormalizeCopybookMapped` (the spelling a COPY REPLACING phrase gives a library-text word, handed to the converter)
- `src/WiseOwl.Cobol.Frontend/Preprocessor/ReferenceFormatProcessor.cs#IsCommentEntryParagraph` (asked by `FixedFormConverter` and `FreeFormConverter` in `ReferenceFormatProcessor.LogicalConversion.cs`)

**Mechanism.** kb/Work PB5126 (landed) introduced the 85 gate for library text that holds a COPY statement. It asks the library
text as written. GR12's subject is the text produced by the complete processing of the COPY statement, so the 85 test belongs
after the replacements (where `ApplyReplacements`' `ForbiddenIn`, COBOL2574, already refuses a REPLACING that introduces COPY at
every edition). At 2002 and 2023 the library-text test is right: `§2002:7.1.2.3 GR11` ("If the REPLACING phrase is specified, the
library text shall not contain a COPY statement") and its 2023 successor judge the library text itself.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094), so the rows are named here:
`1985-GR-XII.2.4-12` (GR12's own row, which carried an OWN verdict CONFORMS; re-recorded PARTIAL naming this note by the
registrar landing records-sample-pb5692) and `1985-GR-XII.2.4-8` (a KEPT record into `GR-7.2.2.5-3`, whose 2023 verdict
stays right; a KEPT row holds no verdict of its own, so it stays closed through its chain until the lineage switch, kb/Work
PB5682, or a CHANGED re-record).

**Rules (each citation checked with `python scripts/spec/cite.py --check`, verdict OK).**
- `§1985:XII.2.4 GR12`: "The text produced as a result of the complete processing of a COPY statement must not contain a COPY statement"
- `§1985:XII.2.4 GR8`: "The syntactic correctness of the library text cannot be independently determined"
- `§1985:XII.2.3 SR10`: "If the word COPY appears in a comment-entry or in the place where a comment-entry may appear, it is considered part of the comment-entry"
- `§2002:7.1.2.3 GR11`: "If the REPLACING phrase is specified, the library text shall not contain a COPY statement"

The produced text is `AUTHOR. COPY ZZZ.`: an AUTHOR paragraph whose comment-entry holds the word COPY, so by SR10 it holds no
COPY statement and GR12 is met. The control `r4i.cob` writes that produced text directly.

comment-entry the replacement produced as a COPY statement, which SR10 says it is not.

COPY inside pseudo-text is barred at 1985 (§1985:XII.2.3 SR7) is a separate reading the adjudication left open.
