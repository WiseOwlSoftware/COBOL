# PB108 — LANDED 2026-08-19 — the three tooling gaps adopted before T1

> ⚙ **flags:** process-only — nothing here changes what a user's program does · registered 2026-08-19 from the
> owner's evaluation of two external "hard implementation mode" prompts (both written without knowledge of this
> repository: an opcode IR, invented COBOL syntax, appsettings, .NET 8, the legacy project names — all rejected;
> see DEVLOG 1329). **Owner decision 2026-08-19: do the three BEFORE T1, in this order, deliberately small** — CI
> diagnosability helps the locale wave directly; the registry stabilizes the knob surface T1 touches
> (`LocaleState`, `CollationRuntime`, `TailoringRules`, the CLDR paths, switches); the local wrapper is the exact
> loop the T1 wave runs.

## 1. CI — TRX + shard-log artifacts (`.github/workflows/build-and-test.yml`)

`--logger trx` + `--results-directory` on EVERY direct `dotnet test` step (both OSes' conformance shards, unit +
characterization, the nightly oracle cross-check, the differential, the legacy unit/integration), uploaded with
`if: always()` (a FAILING shard is the case the artifact exists for), `retention-days: 14`, names carrying OS AND a
per-job suffix (the shard id in the matrix jobs — the two OSes share shard names; `unit`/`nightly`/… elsewhere —
`${{ matrix.shard }}` is EMPTY outside a matrix job and would collide), `if-no-files-found: ignore` where
`shard.log` does not exist. NOT `scripts/guard-fast.sh` (its verdict is its own NIST-loop output, not a `dotnet
test` exit). Shard math untouched: the console logger stays when a TRX logger is added, so the `Total:` grep and the
population guard are unaffected.

## 2. `Control/RuntimeConfig.cs` — a REGISTRY, not a configuration system

Enumerates every environment variable the runtime reads — `COBOL_COLLATION_CACHE`, `COBOL_COLLATION_CACHE_EVICTION`,
`COBOL_COLLATION_WARMUP`, `COBOL_USER_LOCALE`, `COBOL_SYSTEM_LOCALE`, `COBOL_COLLATION_DIR`, `COBOL_CLDR_DIR`,
`COBOLNET_CLOCK`, and the dynamic family `COBOL_<SWITCH-NAME>` (`SwitchStore`) as a PATTERN entry — each entry
referencing the DECLARING constant (a rename breaks the build), with `All`, `Describe()`. No new knobs, no loading, no
mutation, no appsettings / `Microsoft.Extensions.Configuration` (the runtime is dependency-free). Two behavior-neutral
extractions make the constants exist: `SwitchStore.VariableNameFor(name)` (+ `Prefix`) and `SystemClock.PinVariable`.
Drift test (`tests/Cobol.Net.Tests.Unit/RuntimeConfigTests.cs`) in BOTH directions over the runtime SOURCES: every
`Environment.GetEnvironmentVariable(` call site and every identifier-shaped literal `"COBOL(NET)?_…"` is represented
(the selector is exact today: nine knobs + the `"COBOL_"` prefix, nothing else), and every registry entry has a live
call site (no stale entry). ⛔ A literal grep for `GetEnvironmentVariable("COBOL_` would find ZERO sites — every call
passes a constant — and be vacuously green.

## 3. `scripts/build-local.sh` / `build-local.ps1` — fresh build, then the filtered wave-local gate

`dotnet build CobolSharp.sln` (Debug — the same binaries `battery.sh` PHASE 0 builds) → Conformance `--no-build
--filter "<required>"` → Unit `--no-build` (full, ~2 min) → Characterization `--no-build`. The filter is REQUIRED
(error + non-zero exit without one): the wave-local gate is a filter chosen from what the change touches (plan §0
Gates, the PB36 `~Corpus`-only lesson), so a default filter would re-create that mistake. Never `battery.sh`, never
`guard-fast.sh`, never Release. The value: "build the SOLUTION before any `--no-build` run"
(`feedback_fresh_build_before_no_build_test`) becomes the path of least resistance.
