# PB4551 — open-no-rewind-not-implemented--per-file-position: -std=cobol2014: OPEN OUTPUT F1 WITH NO REWIND F2 is a syntax error; NO REWIND is accepted only after the last file-name

Filed 2026-11-03 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-batch-3000-20261103`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

Under `-std=cobol2014`, cobc 3.2 accepts `WITH NO REWIND` only after the last file-name of an OPEN mode phrase. `OPEN OUTPUT F-ONE WITH NO REWIND F-TWO` is refused with "syntax error, unexpected Identifier", while `OPEN OUTPUT F-ONE F-TWO WITH NO REWIND` compiles (with the -Wpending warning that NO REWIND is not implemented) and displays `OPEN 00 00`. ISO attaches the phrase to each file-name. Class: rejects legal source. This is the compile-time half of family open-no-rewind-not-implemented (slice B2 of the same night: where the phrase is accepted, the run sets status 00 instead of 07). Fuzz programs: fz00223, fz00224, fz00927, fz00928, fz01632, fz02339 (night fuzz-batch-3000-20261103, slice D2).

## Minimal test case

Free reference format.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. OPEN1.
ENVIRONMENT DIVISION.
INPUT-OUTPUT SECTION.
FILE-CONTROL.
SELECT F-ONE ASSIGN TO "open1a.dat" ORGANIZATION IS SEQUENTIAL FILE STATUS IS ST1.
SELECT F-TWO ASSIGN TO "open1b.dat" ORGANIZATION IS SEQUENTIAL FILE STATUS IS ST2.
DATA DIVISION.
FILE SECTION.
FD F-ONE.
01 R-ONE PIC X(4).
FD F-TWO.
01 R-TWO PIC X(4).
WORKING-STORAGE SECTION.
01 ST1 PIC XX.
01 ST2 PIC XX.
PROCEDURE DIVISION.
OPEN OUTPUT F-ONE WITH NO REWIND F-TWO
DISPLAY "OPEN " ST1 " " ST2
CLOSE F-ONE F-TWO
STOP RUN.
```

## Environment

`cobc (GnuCOBOL) 3.2.0`, WSL2 Ubuntu x86_64. Compiled with `cobc -x -free -std=cobol2014 -o p open1.cob` (`-fsyntax-only` gives the same diagnostics); no executable is produced, so nothing is run.

## Observed result

Compile, exit code 1:

```text
open1.cob:18: warning: OPEN WITH NO REWIND is not implemented [-Wpending]
   16 | 01 ST2 PIC XX.
   17 | PROCEDURE DIVISION.
   18 > OPEN OUTPUT F-ONE WITH NO REWIND F-TWO
   19 | DISPLAY "OPEN " ST1 " " ST2
   20 | CLOSE F-ONE F-TWO
open1.cob:18: error: syntax error, unexpected Identifier
rc=1
```

## Expected result (per ISO)

The program is legal and displays `OPEN 07 00`: F-ONE's NO REWIND does not apply to a disk file, so it is ignored and that OPEN sets I-O status '07'; F-TWO opens with '00'. The rules are quoted from ISO/IEC 1989:2023; the OPEN format with a NO REWIND phrase per file-name is unchanged from COBOL 1985 into 2023, so it is in 2014.

- §14.9.27.2 (checked): "file-name-1 [ WITH <u>NO</u> <u>REWIND</u> ] }"
- §14.9.27.3 (checked): "The NO REWIND phrase may be specified only for sequential files"
- §14.9.27.4 (checked): "The NO REWIND phrase will be ignored if it does not apply to the storage medium on which the file resides"
- §14.9.27.4 (checked): "If the NO REWIND phrase is ignored, the OPEN statement is successful and the I-O status associated with file-name-1 is set to '07'"

## Our compiler

WiseOwl COBOL (fresh judge, `cobol open1.cob --std 2014 --source-format free -o open1.dll`) compiles it with no diagnostic; `dotnet open1.dll` exits 0 with `OPEN 07 00`.

## Fix site

cobc/parser.y `open_file_entry` (line 15381 of the 3.2 source): the rule is `_open_exclusive open_mode _open_sharing _retry_phrase file_name_list _open_option`, so the option (`open_option_sequential`: `_with NO REWIND`, which also calls CB_PENDING ("OPEN WITH NO REWIND")) is parsed once after the whole list, not after each file-name.

## Upstream state

unreported; tracker not yet searched. cobc itself announces NO REWIND as not implemented (-Wpending); the position restriction is not announced.

## Vetting (2026-11-04)

Verdict LATITUDE (the refuter overturned the vetter's SOUND), retired as `withdrawn`. The source is legal (14.9.27.2 attaches NO REWIND to each file-name) and cobc refuses it, but A.3 33) makes OPEN WITH NO REWIND dependent on a reel or mass-storage device and cobc does not claim it: -Wpending "not implemented" is printed even on this failing compile and NEWS says "recognized, though not working". 4.2.6 (cite.py --check OK) then says an unclaimed element need not be implemented, the warning need not diagnose syntax errors within it, and no executable code is required, and cobc meets all three; the expected `07 00` is also device-dependent. Nothing to report, as with the runtime half the same refuter overturned (open-no-rewind-not-implemented).

GnuCOBOL 3.2.0 on Ubuntu (WSL2). Command: `cobc -x -free -std=cobol2014 -o p open1.cob`.

ISO/IEC 1989:2023 14.9.27.2 writes the OPEN file list as { file-name-1 [ WITH NO REWIND ] } ..., so the phrase belongs to each file-name and may follow any of them. cobc accepts OPEN OUTPUT F-ONE F-TWO WITH NO REWIND (with the -Wpending warning) but refuses the phrase after a file-name that is not the last.

Observed: open1.cob:18: warning: OPEN WITH NO REWIND is not implemented [-Wpending], then open1.cob:18: error: syntax error, unexpected Identifier. Exit code 1.

Expected: The program compiles and displays OPEN 07 00 (14.9.27.4 rule 11: NO REWIND that does not apply to the medium is ignored and the status is '07').

```cobol

SELECT F-ONE ASSIGN TO "open1a.dat" ORGANIZATION IS SEQUENTIAL FILE STATUS IS ST1.
SELECT F-TWO ASSIGN TO "open1b.dat" ORGANIZATION IS SEQUENTIAL FILE STATUS IS ST2.
```
