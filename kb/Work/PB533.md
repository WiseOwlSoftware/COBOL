# PB533

## Mechanism — picture-clause-p2
The PICTURE EDITING phrase's literal IDENTITY is erased one layer above the validator. DataBinder.DecodeEditLiteral (DataBinder.cs:3164-3174) decodes STRINGLIT, NATLIT and HEXLIT through the same CobolLiteral.Decode and returns a bare string, and EditingPhraseSpec (PictureAnalyzer.cs:14) carries only that decoded text -- so the literal's CLASS never reaches PictureAnalyzer.ValidateEditing and SR9's national-vs-alphanumeric half cannot be checked even in principle. The neighbouring character-1 test has the mirror-image defect at the character level: ValidateEditing (PictureAnalyzer.cs:426) uses `char.IsLetter(c1[0])` as the stand-in for SR8's 'any basic letter in the COBOL character set', and char.IsLetter admits every Unicode letter, i.e. all of the Annex B extended letters. One mechanism, two rules: the shape validation is done on a value from which the distinguishing property has already been dropped.

### Expected, from the standard
ISO/IEC 1989:2023 13.18.40.3 SR8 (cite --check OK): 'Character-1 shall be any basic letter in the COBOL character set except those specified in a CURRENCY-SIGN clause or a basic letter character A, B, C, D, E, N, P, R, S, V, X, Z or their lowercase equivalents.' 8.1.3.1 Table 1 (cite --check 8.1.3.1 OK on 'The COBOL character repertoire consists of the basic letters, basic digits, basic special characters, and extended letters') fixes the basic letters at A-Z and a-z; extended letters (Annex B) are a distinct row of the same table, so E-ACUTE is not a basic letter and shall be rejected. SR9 (cite --check OK): 'If USAGE IS NATIONAL is specified for the subject of the entry or if character-string-1 contains the symbol 'N', literal-1, literal-2, and literal-3 shall be national literals. Otherwise, literal-1, literal-2, and literal-3 shall be alphanumeric literals. The total number of characters in literal-1, literal-2, or literal-3 shall not exceed 50.' A national literal on a non-national, non-'N' item shall therefore be rejected.

### Observed
Both illegal programs compile and run. The halves that ARE implemented were measured and hold, so the fix is narrow: SR8's excluded-letter list and its CURRENCY-SIGN exclusion both reject correctly ('EDITING "R"' -> COBOLNET1591; and with CURRENCY SIGN IS "W" WITH PICTURE SYMBOL "W", `PIC 99W99 EDITING "W"` -> COBOLNET1591 -- probes sr8d, sr8a), and SR9's 50-character cap is exact at the boundary (51 -> COBOLNET1594, 50 -> no 1594; probes sr9b, sr9c). Note that the source comment at PictureAnalyzer.cs:452-453 asserts the class half is covered -- 'the national-vs-alphanumeric class matches the item's category; the national-literal sub-check rides the national-edited staging' -- and that is true only of the NATIONAL direction, where a PIC N or USAGE NATIONAL item is staged loud anyway (COBOLNET0899/0881); the ALPHANUMERIC direction, which is the ordinary case, has no check at all. The repair is structural in the same place for both rules: keep the literal's class on EditingPhraseSpec (a small enum or the LiteralContext's own kind) instead of only its decoded text, and replace char.IsLetter with an explicit basic-letter predicate over 8.1.3.1 Table 1 -- one that the existing COBOL-word lexer already needs and can share.
