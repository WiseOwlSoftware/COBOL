# PB5835 - at --std 85 a relation between a numeric function and an 18-digit literal is compared in binary floating point, the 2023 rule for native arithmetic, so IF FUNCTION SQRT (4) = 2.00000000000000001 is true; the 1985 rule for comparing numeric operands has no row in the 1985 catalog

**The row `1989-RV-A.2.8.4-1` itself is CONFIRMED.** It states ATAN's range, and ATAN's value is inside it. What fails is the relation condition, outside that row. **Ruling: UPHELD (a), harm wrong_answer.** At 85 a comparison of a numeric function with an 18-digit literal is made in binary floating point, so `IF FUNCTION SQRT (4) = 2.00000000000000001` is TRUE. The ruling's session ran it: `relbin.cob` printed `S2 SQRT(4) EQ 2.00000000000000001`. The checker's confidence: medium. Severity MAJOR: a wrong-answer defect is at least MAJOR.

**Mechanism 6, ruled (the ruling's paragraph, unchanged).** The row `1989-RV-A.2.8.4-1` states ATAN's range, and the value is inside it
(`ATAN (HUGE) + 0 < 1.57079632679489662` is true). The fault is in the relation condition, which at 85 applies the
2023 rule for native arithmetic with no edition arm. It is a defect at 85 and is filed. It contradicts no
inventory row: the checker found no row for `§1985:VI.6.3.1.1.1` in the 1985 catalog, and the note carries that as
a catalog gap, with the two sentences of kb/Work PB5826 that have none either.

**The catalog gap.** The 1985 rule for comparing numeric operands, `§1985:VI.6.3.1.1.1`, is unnumbered prose and the 1985 catalog holds no row for it (the checker searched the catalog for 'algebraic value' and the locator). kb/Work PB5826 holds the same kind of gap: two 1985 sentences with no row in the catalog. The lane should file the row.

**The checker's evidence.** `ATAN (HUGE)` returns binary64 1.5707963267948966 (below pi/2), so the returned-value rule holds (`§1989:A.2.8.4 RV1`), and `IF FUNCTION ATAN (HUGE) + 0 < 1.57079632679489662` is TRUE, i.e. the value compared exactly is inside the range. The false result of the bare `IF FUNCTION ATAN (HUGE) < 1.57079632679489662` is the relation condition's: the same fault appears with an exact function value, `IF FUNCTION SQRT (4) = 2.00000000000000001` is TRUE and `<` is FALSE (2 versus 2.00000000000000001). At 1985 a comparison is made with respect to the algebraic value of the operands (`§1985:VI.6.3.1.1.1`). `ConditionRenderer.RenderNumericRelational`'s native-float arm converts the exact decimal operand to double whenever either operand is binary64 and `StandardDecimal` is off, on the authority of the 2023 rule that comparison proceeds by the rules of native arithmetic when native arithmetic is in effect (`§2023:8.8.4.2.4`), applied at 85, where there is no native arithmetic and no edition switch; 2023's default mode is native (`§2023:11.9.5.2 GR4`). At 2023 the behaviour is covered by implementor latitude. Identical output at `--std 2023`.
