# PB1071 — LANDED — ⚠ OWNER VISIBILITY (it overturns the pb231 pin)

## The disagreement
DOC-A.1-216 (docs/CONFORMANCE.md, PB970, following GnuCOBOL) defines a pointer's storage image. The shared-area
cell keeps PB231's 'value not in the image' decision and fills the pointer's bytes with a reserved pattern, and the
golden `conformance:2002/pb231_based_pointer_leaf` PINS that fill.

## What the fixer owes
`CobolPtr.SlotWrite` writes the DOC-A.1-216 image; ALLOCATE seeds the NULL image at pointer-leaf class offsets and
`GroupImageCodec` renders it. This OVERTURNS the pb231 pin: re-derive the golden and name the overturn in the DEVLOG
entry so the owner sees it (PB970's implementer reverted the same change to keep the pin, pending this note).

## Landing (wave 1034 group F, 2026-10-07)
Re-probed on the implementer's build: `conformance:2002/pb231_based_pointer_leaf` read `PRE=33 33` (ORD of the
reserved space) for a NULL member, and a typed record's ALLOCATEd pointer members showed `ADDRESS` for NULL. The
journal of the mechanism, all against `PointerImage` as the only author of the image:
- `CobolPtr.SlotWrite<T>` (was `object?`) stores the slot AND splices `PointerImage.OfSlot(value)` into the cell's
  `Ref` at the member's offset; the carrier type is a generic argument because a null data-pointer and a null object
  reference are both `null` (an object member has no image and keeps its placeholder).
- `CobolPtr.Allocate(…, nullImageAt)` seeds the NULL image at `SlotWindow.PointerImageOffsetsOf(based)` (each OCCURS
  occurrence at the stride `ReferenceResolver.WindowScopeOf` applies) instead of the uniform fill (§14.9.3.4 GR9).
- The cell seeds (`GroupImageCodec.ImageInitOfOne` → `SlotSeedOf`) start the positions at `PointerImage.NullImage`,
  and the record struct's one-way `AsImage` renders the live image (`SlotImageOf`; `Physical.SlotLeaf` now carries the
  item). `SlotWindow.CarriesPointerImage` is the one test of which slot members have an image.
- OVERTURNS the pin of PB231's reserved fill: `pb231_based_pointer_leaf` re-derived (the window is asked
  `= LOW-VALUES`, and a BINARY-DOUBLE window shows `SET P UP BY 3` moving the image by 3, §14.9.39.4 GR20);
  `pb244_pointer_group_transfer` re-derived the same way (its control-character image bytes are not pinned in a
  fixture); new `2002/pb1071_pointer_member_image` + `negative/pb1071-pointer-member-image-85`. DOC-A.1-56 and
  DOC-A.1-216 in docs/CONFORMANCE.md, DATA_MODEL D-SLOT and INTRINSICS_DESIGN carry the new determination.
Sibling arms swept: BASED (ALLOCATE form 2 + SET ADDRESS OF), ALLOCATEd, ADDRESS-OF-taken and EXTERNAL cell seeds, the
record struct, program- and function-pointer members; a group MOVE INTO a pointer-bearing group is a separate staged
refusal (NotImplementedCobolFeatureException, the Tier-C byte island) and was not touched.
