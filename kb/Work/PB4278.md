# PB4278 — the hyphen at a word edge is not named under 8.3.2.1; the NAME_BODY comment lags PB4234

**Sites:** `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolLexer.g4` (whole: the NAME_BODY comment block at about :1149-:1165 and the hyphen edge handling; a grammar file is claimed whole), `src/WiseOwl.Cobol.Frontend/Parsing/WordCharacterScreen.cs` (`WordCharacterScreen.IsCandidate`, the screen that names a word's characters, if the fix reads the hyphen edge there).

## What happens

1. The hyphen edge (implementer lead of group G). `01 A- PIC X.` draws COBOL1941 / COBOL5506 near the word; ISO 8.3.2.1 (a COBOL word shall not begin or end with a hyphen) is never named. PB4234 named the underscore edge (COBOL2773) but the lexer cannot take the hyphen word whole: `-` is also the arithmetic minus and a sign, and `A -B` and `A - B` are valid, so reading `A-` as a word edge needs the 8.3.5 operator-spacing rule. `SeparatorPositionViolation` already handles the hyphen for directive words, a mechanism to reuse rather than copy. Repro: `01 A- PIC X.` at any `--std`.
2. The stale comment (review R1-1, low). The NAME_BODY comment block above PB4234's change still says (a) NOT-FIRST is structural because every alternative opens with a letter or a digit, (b) that NOR LAST is enforced for both separators, and (c) at about line 1165 that hyphen and underscore are barred from the ends here. The two new underscore alternatives make all three false for the underscore.

## Fix

Name 8.3.2.1 for the hyphen edge by the same route as the underscore (one rule for both separators, not a second list), validating the citation with `python scripts/spec/cite.py --check 8.3.2.1 "<text>"`. Rewrite the NAME_BODY comment to the current rule in the same change set.

## Landed

Re-probe on 2ce2e70a2: `01 A- PIC X.` drew only COBOL1941 at `PIC`, `01 -A PIC X.` only COBOL5506 at `A`, and `COMPUTE C = A -B` COBOL2993 (8.7.1). 8.3.1 ("A character-string is delimited by separators", and the hyphen is none) makes `A-` and `-A` one word each, but only the parse knows whether a hyphen touching a word is the minus. So the lexer keeps splitting it (IDENTIFIER MINUS) and `WordCharacterScreen` joins it back. Its one `WordScanner`, fed by both word sources (the token stream on a failed parse, the tree's terminals on a parsed one), groups ADJACENT tokens into chains; a run of word-character tokens that holds a MINUS is ONE word, judged by `CobolWordRule.CharacterViolation`, so `CobolCharacterRepertoire.SeparatorPositionViolation`, the one rule PB4234 wrote, names it as COBOL2773 at every edition. A run whose MINUS the tree made an `addOp` stays 8.7.1's (`SeparatorRule.ArithmeticOperatorViolations`, one report per boundary), and a hyphen followed by digits alone is a literal's sign. A word token inside a joined run is judged only as part of it (`MY_NAME-` is one report, not two). No new code: COBOL2773 is reused. The NAME_BODY comment block in `CobolLexer.g4` now states the current rule (the three well-formed alternatives, the two ill-formed underscore alternatives, the hyphen's edge as the screen's) and no longer names `VersionConformancePass.VisitCobolWord` as the underscore gate's site (the screen has owned it since PB3845). Goldens: `cases/8.3.5-Separators/pb4278-hyphen-inside-a-word` (accepted at every edition: interior hyphens, a spaced minus, signs), `cases/8.1.3-COBOL-character-repertoire/pb4278-trailing-hyphen-in-a-word` and `pb4278-leading-hyphen-in-a-word` (COBOL2773 at every edition). The COPY text-name half (`COPY BOOK-.` is accepted, probed) is PB4279's.
