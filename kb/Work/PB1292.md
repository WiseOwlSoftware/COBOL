## Measured

### Finding source-clause — ISO §13.18.53.2; §13.18.53.4 GR1 (rejects-legal-source; rows GR-13.18.53.4-1, FMT-13.18.53.2)

**Mechanism.** The SOURCE clause's identifier-1 arm (BindSourceReference) refuses a subscripted or reference-modified identifier as COBOLNET0899 'not yet implemented', although the same identifiers are accepted inside an arithmetic-expression operand

**Repro.** probe out13/probe/source-clause/n1.cob: WORKING-STORAGE `01 WS-T PIC X(2) OCCURS 3 VALUE "TT".`; RD entry `05 COLUMN 12 PIC X(2) SOURCE WS-T(2).` (and n1b.cob: `SOURCE WS-X(2:2).` over `01 WS-X PIC X(4) VALUE "WXYZ"`), --std 2023.

**Expected, from the standard.** §13.18.53.2 admits identifier-1 (any identifier, §8.4.3 - subscripted and reference-modified included) and §13.18.53.4 GR1 moves the referenced item to the printable item: n1 prints `TT` at column 12, n1b prints `XY`.

**Observed.** error COBOLNET0899: RD 'R2': SOURCE WS-T(2) - a subscripted or reference-modified SOURCE operand (ISO §13.18.53) is not yet implemented (likewise WS-X(2:2)). BindSourceReference returns null on any subscriptPart/refModPart; FieldDataSource stores only base name + qualifiers (KeyReference). The SUM clause's identical gap was closed by PB482 (the addend became a bound expression); the SOURCE identifier arm should bind through the same one expression/place binder the FieldComputeSource arm already uses, with the implicit MOVE (not COMPUTE) semantics kept. No kb/Work note owns this staging.

**Code site.** src/Cobol.Net.Compiler/Binding/DataBinder.Reports.cs#BindSourceReference; #FieldDataSource

### Finding source-clause — ISO §13.18.53.3 SR4 (rejects-legal-source; rows SR-13.18.53.3-4, FMT-13.18.53.2)

**Mechanism.** Two-arm dispatch on SR4: the identifier-1 arm resolves through LookupQualified, which cannot see sum counters, while the arithmetic-expression arm admits the current report's sum counters via ReportSectionNameIn

**Repro.** probe out13/probe/source-clause/p4.cob: RD R2 CONTROL IS FINAL. DE entry `05 RUNTOT COLUMN 18 PIC 9(4) SUM WS-AMT.`; CF FINAL entry `05 COLUMN 13 PIC 9(4) SOURCE RUNTOT.` Compare p7.cob where the same entry is `SOURCE (RUNTOT + 0).`

**Expected, from the standard.** §13.18.53.3 SR4: 'If identifier-1 specifies a report section item, it shall be a report counter identifier or a sum counter defined in the current report' - RUNTOT is such a sum counter, so p4 compiles, and the CF FINAL line prints the sum counter's current content exactly as p7 does (0000 here, since RUNTOT resets at the end of each DE, §13.18.54.4 GR2).

**Observed.** p4: error COBOLNET0899: RD 'R2': SOURCE 'RUNTOT' does not resolve to a data item (ISO §13.18.53.3 SR4). p7 (expression arm) compiles and prints 0000. The identifier arm (ResolveReports, FieldDataSource case -> LookupQualified) and the expression arm (FieldComputeSource case -> ReportSectionNameIn(countersOf: current report)) implement SR4 twice with different populations; the identifier arm should consult the same sum-counter table (model.Sums by name, current report only) and bind a FieldSumSource-style reader.

**Code site.** src/Cobol.Net.Compiler/Binding/DataBinder.Reports.cs#ResolveReports (FieldDataSource case); #ReportSectionNameIn

### Finding varying-clause — ISO §13.18.64.4 GR4 NOTE; §13.18.53 (rejects-legal-source; rows GR-13.18.64.4-4)

**Mechanism.** F4 - a subscripted SOURCE operand is refused wholesale (ReportSourceSubscripted, COBOLNET0899), so the VARYING counter cannot serve as a subscript to a source data item, the use §13.18.64.4 GR4's NOTE names first after the bare source. **Expected, from the standard.** GR4 NOTE 'this allows data-name-1 to be used ... as a subscript to a source data item'; K = 1, 3, 5 -> `A C E`.

**Observed.** error COBOLNET0899: RD 'R-V': SOURCE WS-C(K) - a subscripted or reference-modified SOURCE operand (ISO §13.18.53) is not yet implemented

**Code site.** src/Cobol.Net.Compiler/Binding/DataBinder.Reports.cs line ~2358 (ReportSourceSubscripted); DiagnosticCatalog.ReportSourceSubscripted line ~970

## Landed 2026-10-03 (wave-1009 implementer A)

Re-probed on a fresh Debug build: n1/n1b (subscripted and reference-modified SOURCE, COBOLNET0899), p4 (SOURCE RUNTOT, COBOLNET0899 'does not resolve'), vsub (COBOLNET0899) and a subscripted RD CODE identifier all reproduced; `SOURCE (RUNTOT + 0)` (p7) compiled, as the note said.

**Fix (the root: a two-arm dispatch with one arm never taught anything).** SOURCE's identifier arm captured name + qualifiers at data bind and looked the name up in ordinary storage; the expression arm bound through the ONE procedure-phase expression binder, so every shape an identifier can take that storage cannot say (subscript, reference modification, a report counter, a sum counter, a VARYING counter, a constant) was a separate staged refusal. identifier-1 is now `FieldReferenceSource` - the WRITTEN reference - bound in the procedure phase by `ExpressionBinder.FieldOperand`, the operand binder a MOVE's sending operand takes, which is GR1's "sending operand of an implicit MOVE" said as code. SR4 is screened by the same `ReportSectionNameIn` walk both arms use (COBOLNET2144; the walk now also descends into a subscript's identifiers), and a sum counter name two reports share resolves to the CURRENT report's (`ReferenceResolver.ReportScope` narrows `SumCounterFamilyFor`; train 1005 lead 3: SR4's "defined in the current report" scopes the resolution). The RD CODE clause's identifier-1 shared the arm and is converted with it: `ReportCodeModel.Reference` is the written reference, `ResolveReportCode` screens the BASE item's description (SR2), and `ReportCodeModel.Value` is the place the engine reads, so a subscripted or reference-modified CODE identifier is live (a reference-modified one needs integer-literal bounds, CONFORMANCE.md section 3 "RD CODE reference modification"). The KeyReference drift tests lose their SOURCE caller. Retired: `ReportSourceSubscripted`, `ReportSourceOtherReportCounter`, `ReportSourceOperandUnresolved` (all COBOLNET0899 stagings).

**Spec (cite.py --check OK).** 13.18.53.4 GR1; 13.18.53.3 SR4; 13.18.64.4 GR4 NOTE; 13.18.54.4 GR5; 13.18.12.3 SR2, 13.18.12.4 GR2/GR3.

**Goldens.** `conformance:85/pb1292_source_forms_85` (subscripted, reference-modified, relative-subscript identifier, own-report sum counter SOURCE incl. the control footing's 0000), `conformance:85/pb1292_rd_code_identifier_forms_85`, `conformance:2002/pb1292_source_operand_forms` (counter subscript), `conformance:negative/pb1292-source-names-report-section-item`.

**Rows.** GR-13.18.53.4-1, FMT-13.18.53.2, SR-13.18.53.3-4 and GR-13.18.54.4-5 CONFORMS; GR-13.18.64.4-4 closes with PB1306. The two PB1293 rows that named the deleted `BindSourceReference` (SR-13.18.53.3-2, -8) keep their verdicts and are re-sited to `FieldReferenceSource`.
