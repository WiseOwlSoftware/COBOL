# PB3849 — a notes-only commit pays a full gate and a full review

**Sites:** `scripts/prune_worktrees.py#mechanical`, `scripts/prune_worktrees.py#unreviewed_since`,
`scripts/orchestrator/enqueue.py#tested_locally`, `docs/rearchitecture/DESIGN-test-build-ci.md` (section 3.17.2, the
landing's coverage of a tip), `.claude/skills/workstream/templates/MANDATORY-PRACTICES.md` (I10, the review's coverage)

## The defect

A branch lands only under a CLEAN review stamp and a GREEN local gate at its tip, or at a head whose later commits are
mechanical. `prune_worktrees.mechanical` (the one coverage rule the review gate and the landing both read) counts a
commit as mechanical only when it is main's, a clean merge of main, or changes only `DEVLOG/`. A commit that changes
only `kb/Work/*.md` (with or without DEVLOG) is "a commit of the branch's own", so the tip is UNREVIEWED and, for
`enqueue.tested_locally`, untested: the finisher runs a new leg-1 gate and a reviewer is dispatched for it.

Measured on 2026-10-26: PB3837's merge review found one blocking line, a stale `**Sites:**` line in kb/Work/PB3830.md
the merge kept (PB3850). Deleting it cost a commit, a new gate and a new review: about 20 minutes, for a change no test
reads and no compiler behaviour depends on.

## Acceptance

- A commit that changes only `kb/Work/*.md` and `DEVLOG/` is covered at landing by what can actually be wrong with
  it: `work.py check` (the register is well-formed) and the read-only audits the landing checks already run (the
  rename audits among them), never by a new leg-1 gate or a new branch review. One coverage rule (`mechanical` or its
  successor) answers for the review gate, the landing and the survey alike; the design doc says which commits it
  covers and why.
- Decide, with the reason written in the design doc, whether a note's FRONTMATTER change (status, harm flags,
  `closes_rows`) is covered the same way or still reviewed: a frontmatter change can claim or close inventory rows.
- Self-test arms: a notes-only commit after a reviewed, gated head lands without a new gate or review; a commit that
  also touches anything else does not; each arm seen RED first.
- Measure: the next notes-only fix after a review lands in minutes, recorded with `landing_measure.py`.
- Standing owner rules: fix the root cause, never simply making the diagnostic pass; stay consistent with ourselves
  (DEVLOG-only and notes-only commits are one rule, not two).
