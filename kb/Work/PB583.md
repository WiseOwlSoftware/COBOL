# PB583 — OPEN — the dialect's second axis has no witness lane

Found 2026-09-04 by the `PB206` implementer; re-derived on this tree for this note.

## The gap

`project_dialect_two_axes` makes every leniency dialect-gated: strict rejects, `--permissive` warns and stores
the lenient value. The corpus runner (`tests/Cobol.Net.Tests.Conformance/CorpusRunnerTests.cs`) compiles every
negative fixture at `--std <year>` for each year in its `*> reject-at:` first line — strict only; the manifest
carries no dialect key. So a fixture proves the strict arm and nothing proves the permissive one: that the
diagnostic downgrades to a warning, that the program then compiles, and that the lenient store is the documented
one. PB206 pinned its group-subject "error on both axes" and its elementary "warning + `12  ` stored" claims by
hand probes recorded in its report, which the next change to that band can silently break.

## Fix shape

One mechanism, in the runner: a `*> reject-at: … --permissive` token (or a companion `<name>.permissive`
expectation file carrying the warning code and, for a runnable program, the expected output) makes the axis
mechanical — the runner compiles the fixture a second time with `--permissive` and asserts the warning code
where a `.permissive` file exists, or asserts the SAME rejection where the fixture declares the leniency does
not apply. Sweep every fixture whose diagnostic is registered `Edition.Removed` or carries a permissive arm in
`DiagnosticCatalog`, and give each its permissive expectation; the drift test is a catalog-vs-corpus check that
every permissive-capable descriptor has at least one fixture exercising its warning arm.
