The registration wave stamped these thirteen rows **DOCUMENTED-NON-SUPPORT** under Annex A.4.2, and every one of
them **stays a GAP**. That is not an oversight; it is the schema's rule, and it is the half of a non-support
verdict that is easy to skip:

> "The notes field carries the decision reference; closing still needs a test proving we **diagnose** (or, where
> the departure is a reported VALUE rather than a rejected construct, that the documented behaviour is what
> actually happens) rather than silently miscompile."

A declined facility that a program can still *write* and get a clean compile out of is not declined — it is
undiagnosed. This note owns the measurement that tells the two apart.

## The licence, verified rather than inherited

Every citation below was read at its source for this wave, not carried over from the proposal:

* **A.4.1** (`cite.py --check` OK): "This list identifies features, statements, formats (or parts of formats),
  clauses, or phrases that are optional. Any associated syntax rules, general rules, other rules, exception
  conditions, and I-O status values are also optional, even if not explicitly listed." — this is what extends
  the module licence from the named FORMAT to the syntax and general rules that hang off it, and it is the
  clause the thirteen rows actually need.
* **A.4.2 item 1** "ACCEPT statement, format 3: screen (14.9.1)"; **item 9** "DISPLAY statement, format 2:
  screen (14.9.10)"; **item 10** the EC-SCREEN exception conditions in the RAISING phrases, the USE statement,
  the WHEN phrase of PERFORM, RAISE and the TURN directive.
* `docs/CONFORMANCE.md` **§5** Annex A.4 table: `A.4.2 | ACCEPT/DISPLAY screen handling | Not claimed`, and
  **§4 item 4**: "Screen handling (§13.9, optional §4.2.7): the SCREEN SECTION, ACCEPT/DISPLAY format-3
  (screen), and the EC-SCREEN family. Not provided." — the §4.2.7 user documentation the verdict rests on.

⚠ **A defect in the STANDARD, recorded here so nobody re-derives it:** A.4.2 item 9's printed cross-reference
reads "(14.9.10)", but §14.9.10 is the DELETE statement and the DISPLAY statement is §14.9.11. This was checked
against the canonical PDF (page index 1004) as well as `specs/ISO_COBOL.md`, and **both read 14.9.10** — so the
transcription is faithful and the error is the standard's. The element is named unambiguously by its text
("DISPLAY statement, format 2: screen"), so the licence holds; only the number is wrong. Every other
cross-reference in A.4.2 and A.4.3 that this wave checked (item 24 → §14.9.39 SET, A.4.3 item 4 → §14.9.7
COMMIT, item 5 → §14.9.36 ROLLBACK) resolves correctly.

## What is owed, concretely

The posture §5's preamble commits to is "a parse error or a named error". The rows themselves record that this
is **not uniformly what happens today**, and that finding must not be lost in the disposition:

1. **`DISPLAY screen-name-1`** with no AT phrase and no exception phrases is the MINIMAL legal Format 2 and it
   **parses as a one-operand Format-1 device DISPLAY** — it is not a syntax error at all, and it will print
   something. (`GR-14.9.11.4-13`.)
2. **`DISPLAY SG COLUMN 5`** binds as a THREE-operand Format-1 DISPLAY and fails late, because
   `COL`/`COLS`/`COLUMN`/`COLUMNS` are `cobolWord` alternatives while `AT`/`LINE`/`NUMBER` are not — so
   `DISPLAY SG COLUMN NUMBER 5` is a clean parse error and `DISPLAY SG COLUMN 5` is not. The same construct,
   two postures. (`GR-14.9.11.4-16`, which carries the sharpest measured evidence of the gap.)
3. The four **EC-SCREEN** names are DECLARED in `ExceptionCatalog` with **zero setting sites and zero readers**,
   so `>>TURN EC-SCREEN-FIELD-OVERLAP CHECKING ON` and `RAISE EC-SCREEN-…` compile happily against a facility
   that does not exist. A catalogued name with no setter reads as implemented to every consumer that can see
   it. (`GR-14.9.11.4-19`.)

So the witness set is not one fixture. It is: a SCREEN SECTION source proving `COBOLNET1560` fires; a Format-3
ACCEPT and a Format-2 DISPLAY source shape each proving a NAMED refusal rather than a silent Format-1
reinterpretation; and an EC-SCREEN `>>TURN`/`RAISE` proving the catalogued names are not quietly accepted. Where
the measurement shows a silent reinterpretation instead, **that is a defect to register, not a fixture to
write around** — and it is the reason this note is `open` rather than a checklist item.

## 2026-09-02 — the VERDICT is no longer this note's, and the row count went from thirteen to 163

The derived selector **`screen-handling-only`** (`inventory-schema.json` → `derived-verdicts`) now owns the
A.4.2 **verdict** for every rule the facility conditions: **156 rows**, stamped from the ONE determination in
`CONFORMANCE.md` §5, and held there every build by
`DerivedVerdictDriftTests.NoScreenHandlingConditionedRow_Diverges`. Six of this note's original thirteen are
inside that set; the verdict on them is now re-derived rather than trusted, which is the point of a derived
verdict. **This note keeps the WITNESS debt, and `inventory_rows` widens to the selector's full set plus the
seven rows it cannot reach** — so ownership is explicit to `DefectiveRowCoverageDriftTests` and to anyone asking
who owes the test.

**The posture is worse than this note recorded, and the measurement is now in `CONFORMANCE.md` §5.** Only the
SCREEN SECTION header is diagnosed (COBOLNET1560, from `DataBinder`). Everything else is one of three things,
none of them "a parse error or a named error":

- a **silent reinterpretation** — `ACCEPT SCR-REC` has no screen alternative in the grammar
  (`acceptStatement : ACCEPT dataReference (FROM acceptSource)? END_ACCEPT?`) and binds as a Format-1 **device**
  ACCEPT, because `DataBinder.ScreenNames` deliberately exempts screen-declared names from the COBOLNET1639
  UNDEFINED diagnostic. `DISPLAY SG` prints; `DISPLAY SG COLUMN 5` binds as a three-operand device DISPLAY.
- a **generic COBOL0001 parse error** — the AT/LINE/COLUMN phrases, and `SET … ATTRIBUTE` (format 6 is absent
  from `setStatement`'s ten alternatives).
- **no diagnostic at all** — ⭐ NEW, beyond this note's original measurement: `crtStatusClause` and
  `cursorClause` DO parse (`CobolSpecialNames.g4`) and **no binder outside `Generated/` ever reads them**, so
  `CRT STATUS IS WS-CRT` compiles clean with zero diagnostics of any kind. The same is true of the four
  EC-SCREEN level-3 names, declared in `ExceptionCatalog` with no setting sites and no readers.

**And COBOLNET1560 is half-built**: it is emitted as a **bare string literal** with no `DiagnosticDescriptor` in
`DiagnosticCatalog` — which still calls the 1560 band "earmarked" — so `docs/DIAGNOSTICS.md` has **no COBOLNET1560
row**; its only appearance there is inside COBOLNET1677's message text. A row that closes on "we diagnose" must
have the diagnostic in the registry and the doc, or `DiagnosticRegistryDriftTests` is asserting over a code that
does not exist. Register a real `ScreenFacilityUnsupported` descriptor in the same change set as the witness.

⛔ **The witness harness does not exist yet, and that is the blocking prerequisite** — shared with [[PB283]] and
[[PB261]]. No test anywhere in `tests/` asserts COBOLNET1560; the negative corpus matches `.err` **ERROR** codes
only and the `.out` goldens capture stdout, while the whole 1560/1578/1579/1580 band rides the non-failing
compile channel. Every one of these rows is un-closeable until a `warn-at` mechanism (or a
`CompileFull`-based conformance assertion) exists and has been **proven to fail once**.

⚠ **Seven rows stay OUTSIDE the selector and therefore outside the drift test**: `SR-14.9.1.3-5`,
`SR-14.9.11.3-3`, `GR-14.9.11.4-12`, `GR-14.9.11.4-17`, `GR-14.9.11.4-18`, `GR-14.9.11.4-L2.1`,
`GR-14.9.11.4-L2.2`. They are scoped only by a printed "FORMAT n" band, carry no screen vocabulary, and live in
shared clauses; the catalog does not carry the band ([[PB284]]). They keep the hand verdicts this note gave them
— which nothing now protects from drift, and which is exactly why PB284 is a MAJOR.

⭐ **Five rows this note never held are now stamped, and they were missed by a mechanism nobody had named**:
`SR-12.3.7.3-4/-29/-30` (in §12.3.7, `data-name-1` and `data-name-2` ARE the CURSOR and CRT STATUS operands and
nothing else) and `SR-13.18.35.3-11/-12` (MINUS and identifier-1 exist only in LINE **format 2** — the report-
writer format has PLUS and no identifier operand). Scoping by **OPERAND NAME** is a third mechanism alongside
clause and text. The LINE pair is `feedback_two_arm_dispatch` verbatim: the COLUMN arm was inspected and the
LINE arm was not — and `SR-13.18.14.3-11/-12`, the COLUMN twins, had been *described* as protected while
carrying no verdict at all.

⚠ **One inherited mis-citation repaired**: `SR-13.17.3-9`'s note said the rule "rides the **A.4.13**
screen-handling posture". A.4.13 is REWRITE FILE and WRITE FILE; the screen module is A.4.2. The verdict was
right and the annex NUMBER propagated unchecked — CLAUDE.md rule 1's failure mode exactly. The same wrong number

⚠ **And two omissions in the STANDARD, recorded because they will be re-found.** A.4.2's 27-item list omits the
