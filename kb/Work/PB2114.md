# PB2114 — unify the grammar alternatives the legacy forced (R69)

Plan §0's standing caution: "A SHARED-GRAMMAR CHANGE MUST BE ADDITIVE UNTIL P15. Collapsing a rule to a shared one
deletes the generated `.dataReference()` / `.literal()` accessors and breaks the LEGACY compiler … Add an
alternative; unify at P15." Several landings did exactly that (DEVLOG 2288: PB1135's `callArgument` /
`callByContent` / `invokeArgument`; DEVLOG 20601 records them as ADDITIVE grammar alternatives placed so the legacy
compiler kept parsing). Each is a duplicated rule shape kept for a consumer that no longer exists.

**Prerequisite:** PB2110 landed. **Model:** Opus (grammar).

## Scope

1. Measure, never deduce: find every alternative added for the legacy — `grep -n -i "legacy\|additive" src/**/*.g4`
   and the DEVLOG mentions of "additive" grammar alternatives — and list each with the rule it duplicates in the
   implementer report (not in this note).
2. Unify each into one rule where the spec's general format has one shape; delete the accessor the legacy needed
   and change every greenfield binder caller in the same change.
3. Delete the caution from plan §0 and `DESIGN-frontend-grammar.md` where it is restated (if PB2111 has not).

## Verification

The token-stream and parse-tree shape differentials over the whole lexer-input population (DESIGN-architecture-review
§4 item 3), the whole-population gate, the Linux gate, CI. A unification that changes a parse is not a unification;
it is a finding for the fix lane.
