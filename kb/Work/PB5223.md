# PB5223 - a three-digit segment-number under --permissive breaks the generated C#

**Sites:** `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/AlterSwitchEmitter.cs#EmitSegmentState` (the `__SegOf` table);
`src/WiseOwl.Cobol.Compiler/Binding/Procedure/Segmentation.cs#ValueOf`.

**Witness.** `seg100.cob` (section `IND-A SECTION 100.` with an ALTERed GO TO) compiled with `--std 2023 --permissive`:
the generated C# fails with `CS0029: Cannot implicitly convert type 'int' to 'byte'`. At COBOL-85 the range screen
(COBOL6819) refuses the number first, so only the permissive migration mode reaches the emitter.

**Harm.** The user gets a C# compiler error about generated code instead of a COBOL diagnostic at the segment-number.
The fix belongs with the decision of what a removed construct out of COBOL-85's range means in the migration mode:
either the range screen applies in that mode too (the number has no COBOL-85 meaning to keep), or the emitter's table
carries the value's real type. Either way a test compiles the witness under --permissive.
