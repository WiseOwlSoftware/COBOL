# PB4764 - LENGTH of LENGTH over a variable-length group refused COBOL1627

**What the report says.** Bare `FUNCTION LENGTH (FUNCTION LENGTH (VG))` over a variable-length group is refused COBOL1627 though
legal. The report says it needs a `BoundBinary` arm in `FunctionDeviceText.IsNumericFunctionResult` / `Field` and the size of
GnuCOBOL's LENGTH temporary (DOC-A.1-92). The report names no probe path.

**R1.** No open note covers it. PB4712 (landed) carried the lead.

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs#BindLengthFold`, `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs#BindByteLengthFold`, `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/FunctionDeviceText.cs#IsNumericFunctionResult`, `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/FunctionDeviceText.cs#Field`, `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs#WrittenForm` (doc only), `docs/INTRINSICS_DESIGN.md` (the LENGTH argument paragraph).

## Landed (wave 20261879 E)

Re-probe (`E:/COBOL-coord/scratch/w20261879e/p1.cob`): `FUNCTION LENGTH (FUNCTION LENGTH (VG))` and `BYTE-LENGTH (FUNCTION LENGTH (VG))` were COBOL1627
"is an arithmetic expression" (reproduced). GnuCOBOL 3.2.0 (WSL, `p3.cob`) prints 3, 4, 4, 4, 4, a MOVE to PIC 9(4) 0004, ABS 000000003, LENGTH of ABS 4:
its run-time LENGTH temporary is a 4-byte binary item whatever the group's current length.
Root: both folds' function-identifier arm matched `Expr: BoundIntrinsicCall` by tree shape, though `FunctionValue` is already the binder's statement for
the `BoundBinary` the group's LENGTH lowers to. The arms now ask `FunctionValue` alone, and `FunctionDeviceText.IsNumericFunctionResult` admits the
`FunctionValue` BoundBinary, which `Field`'s default arm describes by its value (4 bytes). Output equals GnuCOBOL on every leg.
Goldens: `pb4764_length_of_variable_length_group_length` (accept 2002) and refusal `pb4764-length-parenthesized-variable-length-group-length` (2023, COBOL1627).
