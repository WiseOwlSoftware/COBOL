# PB5181 - a VALUE THRU range whose end is a figurative constant (other than numeric ZERO), an ALL literal or a symbolic-character is never checked for ascending order: CheckRangesAscending skips an operand with no string value

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs` (`CheckRangesAscending`, `BindCondition`)
- `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs` (`ConditionValueOf` now takes the comparison width and gives a figurative its character value; `ValueWidth`, `IsNumericLiteralOperand`, `CheckFalseValueDistinct`, which shares the reader)

**Mechanism.** §1985:VI.5.15.5 GR2 requires literal-2 to be less than literal-3 wherever THRU is used, and a figurative constant may stand wherever a literal appears (§1985:IV.4.2.2.2.3). `DataBinder.CheckRangesAscending` (kb/Work PB552) compares literal operands only; its StringValue reader returns nothing for HIGH-VALUE, SPACE, QUOTE, an ALL literal or a symbolic-character, and the member skips the pair. HIGH-VALUE THRU LOW-VALUE, "Z" THRU SPACE and ALL "Z" THRU ALL "A" compile at --std 85 and at --std 2023, and the condition-names are never true.

**Found by.** The 1985 code read (2026-11-10; its records are `E:/COBOL-coord/scratch/coderead-85/for-register.json`): each rule below was read against the code sites it names and probed at `--std 85`, and found non-conforming. Verdict, harm, evidence, repro and observed text are the records'; the rows' verdicts are recorded on another branch.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids of the list below.

**Rules (1; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-GR-VI.5.15.5-2` - `§1985:VI.5.15.5 GR2` (record verdict: PARTIAL, harm: under-rejects). Checked: §1985:VI.5.15.5 GR2: "Format 2 can be used only in connection with condition-names". Code sites read: src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs#CheckRangesAscending; src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs#BindCondition; src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs#ConditionOnlyPhraseOf; src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs#BindEntry; src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs#CheckValueConnective; src/WiseOwl.Cobol.Editions/Diagnostics/DiagnosticCatalog.cs#ValueThroughNotAscending. Code read: §1985:VI.5.15.5 GR2 requires "Format 2 can be used only in connection with condition-names" and "Wherever the THRU phrase is used, literal-2 must be less than literal-3". The first sentence conforms at 85: on a non-88 entry DataBinder.BindEntry refuses the THRU phrase (ConditionOnlyPhraseOf, COBOL2167), a list of literals (COBOL1585) and the VALUES ARE spelling (CheckValueConnective, COBOL2177), all probed. The second is implemented by DataBinder.CheckRangesAscending (called from BindCondition, no edition arm, COBOL2961) for literal operands only: numeric pairs, signed and non-integer pairs, ZERO on a numeric subject, nonnumeric literals in the program collating sequence, an equal pair and every pair of a list are refused (probed). Not implemented: a pair in which either end is a figurative constant other than a numeric ZERO, an ALL literal or a symbolic-character; the member skips it (its StringValue reader returns no value), although §1985:IV.4.2.2.2.3 says "A figurative constant may be used whenever 'literal' appears in a format" and the compiler fixes the program collating sequence at compile time. HIGH-VALUE THRU LOW-VALUE, SPACE THRU SPACE, "Z" THRU SPACE, QUOTE THRU SPACE, ZERO THRU SPACE on a PIC X item and ALL "Z" THRU ALL "A" all compile clean at --std 85 (and at --std 2023, the same member). The witness is the refusal of 9 THRU 1 on a PIC 99 item.

**Repro (`1985-GR-VI.5.15.5-2`).** `cobol.exe <file> --std 85 --source-format fixed --run`

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. THRUFIG.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  X PIC X VALUE "M".
           88 C1 VALUE HIGH-VALUE THRU LOW-VALUE.
           88 C2 VALUE SPACE THRU SPACE.
           88 C3 VALUE "Z" THRU SPACE.
       PROCEDURE DIVISION.
       MAIN-PARA.
           IF C1 DISPLAY "C1 TRUE" ELSE DISPLAY "C1 FALSE".
           IF C2 DISPLAY "C2 TRUE" ELSE DISPLAY "C2 FALSE".
           IF C3 DISPLAY "C3 TRUE" ELSE DISPLAY "C3 FALSE".
           STOP RUN.
```

**Expected (from the 1985 text, the record's).** A diagnostic on each of lines 6, 7 and 8 and no object program: §1985:VI.5.15.5 GR2 "Wherever the THRU phrase is used, literal-2 must be less than literal-3." HIGH-VALUE is the character with "the highest ordinal position in the program collating sequence" and LOW-VALUE the lowest (§1985:IV.4.2.2.2.3), so literal-2 is greater than literal-3 on line 6, equal to it on line 7, and greater on line 8 ("Z" follows the space in the native sequence).

**Observed (the record's).** exit 0, no diagnostic; the program displays C1 FALSE, C2 FALSE, C3 FALSE. The same ranges written with nonnumeric literals ("Z" THRU "A", "A" THRU "A") are refused with COBOL2961.

**Fix direction (root cause, CLAUDE.md rule 4).** Give figurative constants, ALL literals and symbolic-characters a compile-time value under the program collating sequence (the binder fixes the sequence at compile time) and let CheckRangesAscending compare every operand through that one value reader.
