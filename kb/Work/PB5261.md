# PB5261 - a failed CLOSE leaves the open mode known

`KeyedConnector.CloseCore` keeps `FileConnector.ModeKnown` true when the CLOSE fails ("ModeKnown then stays true for
the USE-declarative scoping", `FileConnector.CloseCore`, `src/WiseOwl.Cobol.Runtime/IO/FileConnector.cs:1481`), and
`OpenModeView` (`FileConnector.cs:647`) answers `(int)Mode` while `ModeKnown`. For every statement after a CLOSE that
did not complete, the open-mode USE selection therefore sees the mode the file WAS open in, the stale-mode shape
PB5200 fixed on the OPEN side. Reaching it needs a refused promotion or a host failure at CLOSE; no repro was built
(the implementer's note). Required before a fix: a repro (a CLOSE that fails, then a statement under an open-mode USE),
the §2023 clause stating the file's state after an unsuccessful CLOSE (cite.py --check), then the fix: the CLOSE's
USE scoping takes its own being-closed view, as PB5200's `BeginOpen`/`EndOpen` did for OPEN, instead of leaving the
file's mode recorded.

**Sites:** `src/WiseOwl.Cobol.Runtime/IO/FileConnector.cs:1481` (`FileConnector.CloseCore`, `FileConnector.OpenModeView`)
