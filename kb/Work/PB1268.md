## Measured

### Finding occurs-clause-p2 — §13.18.38.4 GR7 (silent; rows GR-13.18.38.4-7)

**Mechanism.** F2 — EC-BOUND-ODO is raised only when the SUPERORDINATE occurs-depending group's extent is computed (CobolTable.OdoExtent). A reference to the subject of the entry, or to an item subordinate to it, goes through CobolTable.At, which checks the subscript against the table's allocated maximum and never reads data-name-1. So an out-of-bounds DEPENDING value is silent on every element reference.

**Repro.** --std 2023 and --std 2002 (E:\Temp\claude\E--CobolSharp\a700c052-f9e4-4942-84ff-a13c7505d6ec\scratchpad\adj-d1\out13\probe\occurs-p2\gr7.cob): >>TURN EC-BOUND-ODO CHECKING ON; 01 N PIC 99. 01 G. 05 H PIC X. 05 T OCCURS 2 TO 5 DEPENDING ON N. 10 TX PIC X. 10 TE PIC Z9.  A declarative USE AFTER EXCEPTION CONDITION EC-BOUND-ODO counts calls and ends with RESUME AT NEXT STATEMENT. MOVE 7 TO N. DISPLAY TX(1). MOVE G TO IMG. MOVE 1 TO N. MOVE "Z" TO T(1). DISPLAY CNT.

**Expected, from the standard.** CNT=3 — §13.18.38.4 GR7: 'At the time the subject of entry is referenced or any data item subordinate or superordinate to the subject of entry is referenced, the value … shall fall within the bounds from integer-1 through integer-2. If the value … does not fall within the specified bounds, the EC-BOUND-ODO exception condition is set to exist.' TX(1) is subordinate to the subject (N=7 > 5), G is superordinate (N=7), and T(1) is the subject (N=1 < 2). All three raise.

**Observed.** CNT=1: only MOVE G TO IMG raises. The OdoError call site is CobolTable.OdoExtent alone (grep: CobolTable.cs:129 is the only caller). kb/Work PB3 (landed) wired the extent path only. Fix direction: at each element reference whose chain includes an occurs-depending table, test the DEPENDING value against integer-1..integer-2 when EC-BOUND-ODO checking is on (the Place already carries Depending/Min/Max for the extent). Under checking-off the lenient continuation stays valid.

**Code site.** src/Cobol.Net.Runtime/Values/Tables/CobolTable.cs#CobolTable.At; src/Cobol.Net.Runtime/Values/Tables/CobolTable.cs#CobolTable.OdoExtent

### Finding occurs-clause-p2 — §8.5.1.9.2 (via §13.18.38.4 GR14); §8.4.2.3.4 2) (silent; rows GR-13.18.38.4-14)

**Mechanism.** F4 — A dynamic-capacity table's element accessors never set EC-BOUND-SUBSCRIPT. RefSending returns a scratch slot for an occurrence outside 1..current capacity, and RefReceiving does the same for an occurrence < 1, with no SubscriptError call (RefSending's own doc: 'EC-BOUND-SUBSCRIPT under CHECKING ON is a later wiring'). The fixed-table accessor CobolTable.At does raise.

**Repro.** --std 2023 (E:\Temp\claude\E--CobolSharp\a700c052-f9e4-4942-84ff-a13c7505d6ec\scratchpad\adj-d1\out13\probe\occurs-p2\gr14b.cob / gr14.cob): >>TURN EC-BOUND CHECKING ON; 01 I PIC S9(3) VALUE 5. 01 T. 05 R PIC X OCCURS DYNAMIC CAPACITY IN RCAP FROM 2 TO 3. 01 F. 05 FR PIC X OCCURS 2.  With a declarative on EC-BOUND: DISPLAY FR(I) -> EC-BOUND-SUBSCRIPT; DISPLAY R(I) -> nothing; MOVE "Q" TO R(0) (Z=0) -> nothing.

**Expected, from the standard.** EC-BOUND-SUBSCRIPT for R(5) at current capacity 2 and for R(0). §8.5.1.9.2: 'When a data item in a dynamic-capacity table is referenced as a sending operand, the result of the operation is the same as for a fixed-capacity table whose number of occurrences is the current capacity of the table', and §8.4.2.3.4 2) sets EC-BOUND-SUBSCRIPT for a subscript less than one or greater than the highest permissible occurrence number. A receiving subscript < 1 is not a growth case under §8.5.1.9.3, so the fixed-table rule applies.

**Observed.** The dynamic references print '[ ]' and continue with no exception, while the fixed FR(5) in the same program raises EC-BOUND-SUBSCRIPT. Fix direction: call ExceptionState.SubscriptError in RefSending's out-of-range arm and in RefReceiving's occ<1 arm, before the scratch fallback, the same way CobolTable.At does. This is the sibling arm the At fix did not reach (two-arm dispatch).

**Code site.** src/Cobol.Net.Runtime/Values/Tables/CobolDynTable.cs#CobolDynTable.RefSending; src/Cobol.Net.Runtime/Values/Tables/CobolDynTable.cs#CobolDynTable.RefReceiving
