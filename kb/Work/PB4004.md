# PB4004 — national-items-displayed-as-utf-16-bytes--unstring-counts-bytes: UNSTRING of a national item stores byte counts in COUNT IN and POINTER (N"AB,CD" gives COUNT 4, POINTER 7)

Filed 2026-10-28 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-20261027-215606`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

Under `-std=cobol2014`, UNSTRING of a national (PIC N) sending item counts bytes, not national characters, for the
COUNT IN item and the POINTER item. `UNSTRING N"AB,CD" DELIMITED BY N"," INTO R1 COUNT IN CNT WITH POINTER PTR` (PTR
starting at 1) leaves CNT 4 and PTR 7 where ISO gives 2 and 4. The receiving item itself is right. Class: wrong output.
One more mechanism of the "national items handled as UTF-16 bytes" group (PB3894 to PB3898, PB3937 record the others).
Fuzz program fz01576 (night fuzz-20261027-215606).

## Minimal test case

Free reference format.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. NUNSTR.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 SRC PIC N(5) VALUE N"AB,CD".
01 R1 PIC N(5).
01 CNT PIC 9(3) VALUE 0.
01 PTR PIC 9(3) VALUE 1.
PROCEDURE DIVISION.
    UNSTRING SRC DELIMITED BY N","
        INTO R1 COUNT IN CNT
        WITH POINTER PTR
    END-UNSTRING
    DISPLAY "CNT " CNT " PTR " PTR
    IF R1 = N"AB" DISPLAY "R1 EQUAL" ELSE DISPLAY "R1 NOT EQUAL" END-IF
    STOP RUN.
```

## Environment

`cobc (GnuCOBOL) 3.2.0`, WSL2 Ubuntu, x86_64. Compiled with `cobc -x -free -std=cobol2014 -o p prog.cob`, run as
`timeout 10 ./p`.

## Observed result

Compile, exit code 0: cobc's only diagnostics are the `-Wunfinished` warnings "handling of USAGE NATIONAL is
unfinished" and "handling of national literal is unfinished". Run, exit code 0:

```text
CNT 004 PTR 007
R1 EQUAL
```

## Expected result (per ISO)

A character position of a national item is the "location within a national data item of a national character"
(§3.124), so the UNSTRING counts are in national characters. §14.9.48.4 11) e): "a value equal to the number of
characters examined, excluding any delimiter characters, shall be moved into the area referenced by identifier-6" (A
and B: 2). §14.9.48.4 13): the POINTER item "will be incremented by one for each character examined in the data item
referenced by identifier-1" (A, B and the comma: 1 + 3 = 4). National items and UNSTRING of them are in the 2002 and
2014 editions: the 2002 text and the 2009 committee draft that led to 2014 carry the same UNSTRING rules. Expected
output:

```text
CNT 002 PTR 004
R1 EQUAL
```

## Our compiler

WiseOwl COBOL (fresh judge, `--std 2014 --source-format free`): no diagnostic; prints `CNT 002 PTR 004` and
`R1 EQUAL`, exit code 0.

## Fix site

`libcob/strings.c` (3.2 tree): `cob_unstring_init` sets the static `unstring_offset` from the POINTER item
(`cob_get_int (unstring_ptr) - 1`) and checks it against `unstring_src->size`; `cob_unstring_into` advances
`unstring_offset` by byte sizes (`match_size`, `dlsize`) and stores the byte `match_size` under "set COUNT IN"; and
`cob_unstring_finish` stores `unstring_offset + 1` into the POINTER item. All are byte quantities. For a national sending
field they need converting between bytes and national character positions (two bytes each) when read from and stored
into the POINTER and COUNT IN items.

## Draft issue

**Title:** UNSTRING of a national item stores byte counts in COUNT IN and POINTER (N"AB,CD" gives COUNT 4, POINTER 7)

Environment: GnuCOBOL 3.2.0, WSL2 Ubuntu x86_64; `cobc -x -free -std=cobol2014 -o p prog.cob && ./p`.

Program:

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. NUNSTR.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 SRC PIC N(5) VALUE N"AB,CD".
01 R1 PIC N(5).
01 CNT PIC 9(3) VALUE 0.
01 PTR PIC 9(3) VALUE 1.
PROCEDURE DIVISION.
    UNSTRING SRC DELIMITED BY N","
        INTO R1 COUNT IN CNT
        WITH POINTER PTR
    END-UNSTRING
    DISPLAY "CNT " CNT " PTR " PTR
    IF R1 = N"AB" DISPLAY "R1 EQUAL" ELSE DISPLAY "R1 NOT EQUAL" END-IF
    STOP RUN.
```

Observed: `CNT 004 PTR 007` and `R1 EQUAL`.

Expected: `CNT 002 PTR 004` and `R1 EQUAL`. ISO/IEC 1989:2023 §14.9.48.4 rules 11 e) and 13: COUNT IN receives the
number of characters examined (2) and the POINTER item is incremented once per character examined (1 + 3); a character
position of a national item is one national character (§3.124). The counts look like byte counts of the UTF-16 storage.
