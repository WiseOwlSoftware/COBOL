# PB1744 — parameter-names escape the REPOSITORY intrinsic screen

## The rule

§12.3.8.3 SR12 (`cite.py --check 12.3.8.3 "shall not be specified as a user-defined word"` → OK §12.3.8.3 12)):
"Intrinsic-function-name-1 shall not be specified as a user-defined word within the scope of this REPOSITORY
paragraph." A parameter-name is one of the §8.3.2.2 user-defined word types.

## What the code does

PB1083 (wave 73 F) made every §8.3.2.2 type declare its word through `DataBinder.DeclareUserWord`, which asks the one
REPOSITORY-intrinsic membership (`DataBinder.RepositoryIntrinsicSpecifier`). `UserWordDeclarationDriftTests` pins that,
and exempts exactly one type that a source element can declare: `UserWordKind.ParameterName`, because a parameterized
class's parameter-names are substituted by `src/Cobol.Net.Compiler/Oo/OoExpansion.cs` before any binder exists. So a
parameterized class that writes `FUNCTION ALL INTRINSIC` (or `FUNCTION SQRT INTRINSIC`) and names a parameter `SQRT`
compiles clean, where SR12 requires a diagnostic.

## Repro (to build)

A parameterized class (`CLASS-ID. C USING SQRT.`) whose REPOSITORY paragraph has `FUNCTION ALL INTRINSIC`: expected
COBOLNET1649 (the SR12 diagnostic PB1083 draws for every other type); observed a clean compile (per the report).

## Fix direction

The screen has to run where the parameter-names are known: either `OoExpansion` asks the same membership
(`RepositoryIntrinsicSpecifier`, never a second copy of it), or the parameter-names are declared through
`DeclareUserWord` when the class's REPOSITORY is bound. Remove the drift test's `ParameterName` exemption in the same
change. Row: SR-12.3.8.3-12 was verdicted CONFORMS by PB1083; the fix should restate it with this case's witness.
