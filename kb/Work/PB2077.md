# PB2077 — the typed and universal lanes disagree on a reference-modified argument

Found by the train 1021 review of cluster D (finding 5); verified 2026-10-05 on `43fd36bd8` (train1021 tree).

**Blocked on an owner adjudication** (moved here from `blocked_by`, which names blocking NOTES only, PB2120 2026-10-07):
does a reference-modified unique data item carry a PICTURE clause for §9.3.6 3 e) / §14.8.2.3.2 rule 2? Until a
decision note records the answer, `blocked: true` holds this note out of the fix lane.

## Measured

## Spec

- §8.4.3.3.4 6) (OK): "The unique data item is considered to be an elementary data item without the JUSTIFIED clause.
  The unique data item has the same class, category, and usage as that defined for identifier-1, except that ..."
  Nothing gives it, or denies it, a PICTURE clause.
- §9.3.6 (OK): method resolution applies to EVERY invocation ("it is the class of the actual object referenced at
  runtime that is used in resolving a method invocation"), so the typed and the universal lane ask the SAME match
  question 3 e) ("the same ALIGNED, ANY LENGTH, BLANK WHEN ZERO, DYNAMIC LENGTH, JUSTIFIED, PICTURE, SIGN, and USAGE
  clauses"); they may not answer it differently. That half is SETTLED: the divergence is a defect whichever reading wins.
- §14.8.2.1 (OK): an elementary argument opposite a group formal takes the GROUP rules, and §14.8.2.2 1) (OK) admits an
  elementary alphanumeric argument into a formal group no larger — but for a METHOD the §9.3.6 3 e) match decides
  first, and it turns on the same PICTURE question. (The review's "14.8.2.2 rule 1 accepts the group formal" is the
  conformance half only.)
- NOT settled: whether the slice "has the same PICTURE clause" as a `PIC X(5)` formal. Reading A (the slice is
  PICTURE-less, as the universal lane and `ActivationDescriptions.OfReferenceModification` assume): a slice matches
  only a group formal, so a typed `INVOKE C "M" USING X(1:5)` into `PIC X(5)` is EC-OO-METHOD at run time / a
  compile-time refusal. Reading B (the slice is described as if `PIC X(len)` of its class — §8.4.3.3.4 2)'s "as if it
  were redefined as a data item of class and category alphanumeric of the same size" framing): a slice matches an
  equal-length `PIC X(n)` (and an ANY LENGTH formal is still excluded by 3 e)'s ANY LENGTH clause), never a group.
  Owner precedence (CLAUDE.md rule 1): the ISO text does not control -> GnuCOBOL (it does no method-signature match,
  so it has no answer) -> IBM Enterprise COBOL / Micro Focus.

## Code sites

- Typed: `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/OoBinder.cs` L1099-1124 (the `RefModPlace rmp` arm: refuses
  every group / non-alphanumeric formal; requires literal start and length BY REFERENCE).
- Universal: `src/Cobol.Net.Compiler/Oo/ActivationDescriptions.cs` `OfReferenceModification` (empty `Clauses`) read by

## Why it is not a train-sized fix

It needs (1) the owner's answer to the PICTURE question, then (2) ONE mechanism for the method-argument match that both
lanes ask — the typed binder's hand-written ref-mod arm deleted in favour of the relation (or a shared compile-time
predicate the relation is generated from), with a drift test that pairs every typed-lane verdict with the universal
one. That is a restructure of where the §9.3.6 / §14.8.2 rule lives, not an edit to either arm.

## Settled 2026-10-12 — kb/Work PB3098 (the text decides; the owner is not asked)

Reading A holds. The unique data item of §8.4.3.3.4 GR5/GR6 has no PICTURE clause, so passed BY REFERENCE it never
matches an elementary formal (§9.3.6 3 e)) and matches an alphanumeric group formal of no more bytes (3 c), §14.8.2.2
rule 1); an elementary formal takes it BY CONTENT (4 d)). Both lanes ask the match (§14.9.23.4 GR7 b) locates the
method by §9.3.6 for every INVOKE) and the conformance (§14.9.23.3 SR5 c) at compile time for a typed receiver,
GR7 c) at run time for a universal one): one relation, read at two times. PB3098 carries the citations, the eight-row
verdict table, the GnuCOBOL probe (its prototype conformance check ignores the modifier, so it has no answer) and the
two readings the text leaves open (docs/CONFORMANCE.md D-RM1: a run-time slice length takes rule 1 on its MAXIMUM
extent at compile time; the ANY LENGTH item of 3 e) is read through §14.8.2.3.2 d)/e)).

Of the measured table above, the universal column is right in every row. The typed column is wrong in rows 1 and 3
(it accepts a slice into `PIC X(5)`, an under-reject) and rejects legal source in row 2 (a slice into a group formal
of fewer bytes). `under_rejects` is now true.

**Sibling the settlement found.** A whole elementary `PIC X(n)` argument into a group formal: the typed lane accepts it
(`DescriptionMismatch`'s group arm asks §14.8.2.2 rule 1 alone) and the universal lane refuses it (3 e); golden
`pb480_universal_match_relations`). The one relation refuses it on both.

## Fix shape (apply-ready) — the design is docs/COBOLNET_OO_DESIGN.md D6 item 6

**Carried by PB3101 (2026-10-12).** D6 item 7 makes the relation family the only comparator at bind time and deletes
`OoConformance.DescriptionMismatch`; this note is that design's INVOKE step. Land it inside PB3101, or first on its own
with item 2's pair-mode allowance transitional: PB3101 then deletes the comparator and item 6's name list with it.

1. **The relation grows its description half.** `ActivationRelations.DescriptionMatches(argument, formal)` (runtime)
   is §9.3.6 match rules 3 a)-c), 3 d) 1.-3. and 3 e), with the ANY LENGTH item read as §14.8.2.3.2 d)/e); `Matches`
   keeps the ACTIVE-CLASS value half (3 d) 4./5.) on top of it. `ParameterViolation(argument, formal,
   bool universalReceiver)`: GR7 c)'s ANY LENGTH arm fires for a universal receiver only; nothing else changes.
2. **The typed lane asks it.** In `OoBinder.OoBindInvocationArg`'s BY REFERENCE arm, delete the `RefModPlace rmp` arm
   and the `OoConformance.DescriptionMismatch(formal, place.Item, byRefGroupPrefix: true, anyLengthActivationRelax:
   true, invokedWith)` call. Build the argument's description with `ActivationDescriptions.OfPlace(place,
   host.OoClasses)` and the formal's with the same builder the class half renders into its static field; ask
   `DescriptionMatches` (an ACTIVE-CLASS formal keeps the static §14.8.2.3.2 rule 4 arm with `invokedWith`), then
   `ParameterViolation(…, universalReceiver: false)`. A reason is COBOLNET0828 carrying that reason; for a slice into
   an elementary formal the message names the remedies (BY CONTENT, or a group formal). `DescriptionMismatch`'s pair-mode
   callers (override, implements, property, RETURNING) are untouched here; PB3101 deletes the comparator and sends them
   to `SameSignature`.
3. **A run-time slice length.** `ActivationDescriptions.OfReferenceModification` sets `Positions` to `StaticLength`
   when static, else to the slice's maximum extent (D-RM1): identifier-1's `PositionCount` less a static leftmost
   position plus one, or all of them. The run-time box keeps the evaluated length (`CobolInvokeArg.ReferenceModified`).
4. **The typed crossing of a slice into a group formal** carries the formal's prefix window over the evaluated slice
   and writes back through the slice's own receiving store (which truncates to the window), as the universal carrier
   does. The implementer measures whether `BoundInvokeArg(formal, place, WriteBack: true)` already does this for a
   `RefModPlace` and keeps the one path that does.
5. **Goldens.** `conformance:2002/pb2077_refmod_argument_both_lanes`: the eight rows of PB3098's table, typed and
   universal in one program under EC-OO declaratives, expected values from the table. Negatives:
   `pb2077-refmod-into-elementary-by-reference` (typed `X(1:5)` into `PIC X(5)`: COBOLNET0828 naming §9.3.6 3 e) and
   the remedy), `pb2077-refmod-shorter-than-group-formal` (rule 1), `pb2077-elementary-into-group-formal` (the sibling).
6. **Drift test** `TypedAndUniversalInvokeVerdictsAgree` (Unit): (a) structural, a Roslyn walk over `OoBinder.cs`
   asserting it holds no `RefModPlace` conformance arm and no `DescriptionMismatch` call for an INVOKE argument (the
   pair-mode callers are allowed by name until PB3101 deletes the comparator and the list with it); (b) behavioral, a table of argument × formal descriptions (PB3098's rows plus
   the elementary pairs `PictureClauseIdentityDriftTests` enumerates) asked of the binder's verdict entry and of
   `ActivationRelations` side by side; it goes red the day a second comparator reappears.
7. **Sibling sweep.** `ParameterConformance.CheckArgument` for a program-prototype CALL and a user-defined function
   with a slice BY REFERENCE asks the same §14.8.2.3.2 rule 2 sentence: measure both; align through PB1780's one entry
   or file the note.
8. **Docs** are in this change (D6 item 6, D-RM1); the implementer updates them only where implementation proves the
   design wrong, and says so.

## Landed (wave 1070 group D, 2026-10-12)

Re-probed on `92cfea452` with the worktree's Debug `cobol.exe`: the typed lane accepted `X(1:5)` into `PIC X(5)` and
ran it (`TP:ABCDE`), refused `X(1:6)` into the 4-byte group (COBOLNET0828 "does not conform"), refused `X(1:N)`
("needs a compile-time (start:length)"), and ran a whole `PIC X(10)` into the group (`TG:ABCD`); the universal lane
answered every row as PB3098's table does.

**Mechanism.** The typed lane's BY REFERENCE INVOKE argument had its own comparator: a hand-written `RefModPlace` arm
and `OoConformance.DescriptionMismatch(…, byRefGroupPrefix: true, anyLengthActivationRelax: true, invokedWith)`. Both
are deleted. `OoBinder.ByReferenceArgumentReason` (the one typed-lane entry) builds the argument's and the formal's
descriptions with `ActivationDescriptions.OfPlace` / `OfFormal` and asks `ActivationRelations.MatchViolation` (new:
the description half of §9.3.6 match rule 3, which `Matches` now builds on, adding only the ACTIVE-CLASS value half)
then `ParameterViolation`; an ACTIVE-CLASS
formal keeps the static §14.8.2.3.2 rule 4 arm with `invokedWith`. A slice BY CONTENT now takes `ContentMismatch`'s
MOVE rules like any operand (§9.3.6 4 d)): a slice BY CONTENT into a group formal, refused before, binds.

**Pieces the one relation needed.** (1) §9.3.6 3 e)'s ANY LENGTH item read through §14.8.2.3.2 "Additionally" d)
(D-RM1 b)) on both lanes: `ActivationDescription.AnyLengthClauses`, the clauses an item would carry at ANY LENGTH, so
only the length is relaxed. The universal lane's `PIC X(4)` into `PIC X ANY LENGTH` is now EC-OO-UNIVERSAL (GR7 c))
instead of EC-OO-METHOD (golden `pb480_universal_any_length_omitted` row 1 re-derived). The CALL lane's run-time rule 2 d) and
returning 5) arms still compare category and usage only (a JUSTIFIED or sliced argument conforms there); reading
the any-length form makes an old caller's description refuse what it passed, a call-ABI change, so it is left to
the report's lead. (2) `OfReferenceModification` takes GR6's category from the one reader (`ItemCategory.CategoryName(Place)`:
an alphabetic slice stays alphabetic, so it does not match an alphanumeric group, 3 c)) and its compile-time positions
from the maximum extent when the length is a run-time value (D-RM1 a)). (2b) A bit / national group's description carried no clauses, so the universal
lane refused a national group into an elementary `PIC N(5)` formal (and the typed lane, asking the relation, began
to: the full conformance run's `w61b_pb1166_picture_identity`); §13.18.29.4 GR1 b) / GR2 b) describe it "with
PICTURE 1(m)" / "N(m)", so its `Clauses` are that picture's now, and two national groups of different lengths no
longer match (`pb480_universal_match_relations` row TQ re-derived: EC-OO-METHOD). (3) `CallEmitter.AreaOf`: a slice whose
length is a run-time value states no area, so a group formal holds the slice padded to its width and writes back
through the slice, truncated (measured: `X(3:N)` with N = 2 into a 4-byte group read `CDEF` and wrote four bytes
before; now `CD  ` and `X = ABwxEFGHIJ`).

**Goldens.** `conformance:2002/pb2077_refmod_argument_both_lanes` (six typed rows that run, eight universal rows);
negatives `pb2077-refmod-into-elementary-by-reference`, `pb2077-refmod-shorter-than-group-formal`,
`pb2077-elementary-into-group-formal` (COBOLNET0828). Drift test `TypedAndUniversalInvokeVerdictsAgreeDriftTests`:
a Roslyn walk (no `DescriptionMismatch` call in `OoBinder`, no `RefModPlace` branch in `OoBindInvocationArg`, the
entry asks both relations) and the binder-vs-relation agreement over every elementary, sliced and ANY LENGTH pair,
plus PB3098's typed rows compiled.

**Sibling sweep.** A program-prototype CALL and a user-defined function with a slice BY REFERENCE ask §14.8.2.3.2
rule 2 through `ParameterConformance.CheckArgument` → `DescriptionMismatch` and still accept it (measured in PB3101's
table); that lane is PB3101's restructure (one bind-time entry), which deletes the comparator — not re-filed. Pair
mode (override, implements, property, RETURNING) keeps `DescriptionMismatch` until PB3101.

**Design correction (fix shape items 1-2).** `ParameterViolation` did not grow a `universalReceiver` parameter: GR7 c)'s
ANY LENGTH ban bans the bound method's DESCRIPTION, not a pair, and the universal switch already raised it
unconditionally for such a method (`OoEmitter.EmitCobolInvokeCase`), so the arm left the relation and the typed lane
asks the same `ParameterViolation`. Changing the shipped signature would have moved the runtime ABI pin
(`RuntimeAbiPinDriftTests`) and needed a runtime major; the new members (`MatchViolation`, `AnyLengthClauses`) are
unshipped additions. `DescriptionMatches` is named `MatchViolation` (null or the reason, as `ParameterViolation`).
