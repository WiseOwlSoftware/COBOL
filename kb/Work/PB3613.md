# PB3613 — a numeric FUNCTION value sent to a group keeps its sign and decimal point

**Sites:** `src/Cobol.Net.Compiler/CodeGen/Emit/OperandText.cs` (`NonElementaryMoveSender`, the last arm: `AsString(op, num, deSign:false)` on a numeric `BoundComputedOperand`).

## Found

Source: `w20261024c-PB3570-report.md`, new defect (unchanged from the reviewed report). PB3570 decided that a numeric
literal sent to a group stores its digits only (no sign, no decimal point). The function-value sender was not brought
along.

Repro (the reporter's file): `E:\COBOL-coord\scratch\w20261024c\fn.cob`.

- `MOVE FUNCTION MIN(N 3) TO G` with N = -15 stores `-15` in the group.
- `MOVE FUNCTION MIN(M 3) TO G` with M = -1.5 stores `-1.5`.
- A numeric literal sent to the same group stores digits only (the PB3570 rule).

## The fix

Decide the function sender with the PB3570 decision (the documented latitude of 14.9.25.4), then add the arm to
`OperandText.NonElementaryMoveSender` so a numeric computed operand is sent through the same codec as the literal.
Sibling sweep: every caller of `NonElementaryMoveSender` (see PB3562, which already lists them and handled the boolean
and national function senders) with a numeric function sender, including CALL BY CONTENT to a group formal.
