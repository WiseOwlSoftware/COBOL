# PB3367 — OPEN — a failed `git add` mid-stamp strands the branch

Reported 2026-10-18 by the coordinator (wave-1115 clerk lead 6). Register check: PB3023, PB3107, PB3123 and PB3125 are landed and cover other faults.

**Measured.** Branch `worktree-wf_968a1070-783-42` (kb/Work PB3314), attempt log `E:\COBOL-coord\logs\land-lane-worktree-wf_968a1070-783-42-20261018T073428235097Z.log`: `git add -- DEVLOG/2182-pb3314-a-lock-directory-in-the-middle-of-its-rmdir-refuses.md` returned 128 after both gates were GREEN. The same command run by hand minutes later succeeded. Likely cause: a concurrent git process holding the worktree's `index.lock`; UNMEASURED, because stderr was dropped.

**Mechanism.** `scripts/devlog.py#stamp` (about lines 383-412) writes `DEVLOG/<number>-<slug>.md` and unlinks each pending file BEFORE `_git(wt, "add", ...)` with `check=True`. When git fails, the pending file is gone, the numbered file is untracked and the allocator's number is consumed. `#run_stamp` (line 421) then refuses ("has no pending entry to stamp"), so every rerun fails. `#_git` (line 143) captures stderr and `CalledProcessError` hides it.

**Fix direction.** Stage in an order a retry can repeat (or detect and resume a half-done stamp that already holds the number), retry index.lock contention, and print git's stderr on failure. Add a test that fails the add and then reruns the stamp.

**Recurrence 2026-10-18 (branch `worktree-wf_e873df80-6b5-22`, PB1587).** Landing attempt `20261018T224407764780Z`, log `E:\COBOL-coord\logs\land-lane-worktree-wf_e873df80-6b5-22-20261018T224407764780Z.log`: both gates GREEN, then `devlog.py stamp` failed at `git add -- DEVLOG/2225-pb1587-...md` with exit 128 and no stderr in the log (the `_git` capture). The tree was left half-stamped: the pending entry unlinked, 2225 untracked, number 2225 consumed. The same `git add -n` succeeded minutes later, so the cause was transient; no `index.lock` was left behind. The enqueue unit restored the pending entry, removed the untracked file by hand and re-armed the branch.

**Sibling.** `scripts/orchestrator/enqueue.py`'s verdict line misnames the cause as "the branch needs one `DEVLOG/pending-<slug>.md`" when the branch has one and git failed.
