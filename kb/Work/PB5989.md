# PB5989 - the 1985 spacing rules around operators are not enforced at `--std 85`: a unary operator beside a left parenthesis, a relation character and a logical operator written without the required spaces all compile (§1985:VI.6.2.2, §1985:VI.6.3.1.1, §1985:VI.6.3.2)

§1985:VI.6.3.2: "The logical operators must be preceded by a space and followed by a space" (cite.py OK). Probes (slice 85p-11):
`IF (A = 1)AND(B = 2)` compiles and runs at `--std 85` (exit 0); no code cites the rule; the lexer splits `)AND(` on the
parenthesis separators. The arithmetic-operator sibling IS enforced (COBOL2993 on `A+B`). Slice 85p-10: `COMPUTE N = -(M) + 9`
and `(- M) + 9` compile at 85, where 1985 has no exception for a unary operator beside a parenthesis (§2023:8.7.1 added it); and
a relation character, a special character word, written without its spaces compiles (§1985:IV.4.2.2.1.3.1, VI.6.3.1.1 s3).
One mechanism: the 1985 separator rules for operator words, applied by the arithmetic arm only. Fix at the root where COBOL2993
is decided, for all three operator kinds, edition-keyed; goldens drafted in work/85p-10 and work/85p-11.

**Sites (as changed):** `src/WiseOwl.Cobol.Frontend/Parsing/SeparatorRule.cs:201` (`ArithmeticOperatorViolations`, the unary arm keyed by `EditionInfo.UnaryOperatorMayTouchParenthesis`), `src/WiseOwl.Cobol.Frontend/Parsing/SeparatorRule.cs:244` (`ConditionOperatorViolations`, new), `src/WiseOwl.Cobol.Frontend/Pipeline/Frontend.cs:658` (`LexAndParse`, the call), `src/WiseOwl.Cobol.Editions/EditionInfo.cs` (`UnaryOperatorMayTouchParenthesis`, `ConditionOperatorsNeedSeparatorSpaces`), `src/WiseOwl.Cobol.Editions/Diagnostics/DiagnosticCatalog.cs` (`SeparatorConditionOperatorSpacing`, COBOL7672). The note named `Lexing/`; the spacing is decided after the parse, in `SeparatorRule`, as COBOL2993 always was.
