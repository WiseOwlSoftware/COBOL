# PB31 — LANDED — the CROSS-ARGUMENT rule, expressed as a set intersection

> ⚙ **flags:** under-rejects
> §15.59.3 r2 / §15.63.3 r2 (MAX/MIN) require all arguments to be of the same class family. `CheckArgumentClass`
> screens each argument INDEPENDENTLY, so `MAX(1, "A")` is accepted. ⛔ **Adding a `Verified` row cannot fix
> this** — the screen has no cross-argument shape at all, which is why it is its own item and not part of PB30.


## ⚙ LANDED 2026-08-06 — and it cost three lines, because [[PB48]] had already built the model

§15.59.3 r2 / §15.63.3 r2: "All arguments shall be of the same class with the exception that mixing of arguments
of alphabetic and alphanumeric classes is allowed." (`--check`ed. The exception is free here — `PicCategory`
folds alphabetic into alphanumeric, so the two ARE one class in this model.)

⭐ **THE CANDIDATE-CLASS SET MAKES IT AN INTERSECTION.** PB48 replaced "the ONE class this operand has" with "the
SET of classes it can present", to admit a figurative constant. "All arguments shall be of the same class" is
then exactly "some class is available to every argument":

| list | intersection | verdict |
|---|---|---|
| `MAX(1 7 3)` | {numeric} | legal |
| `MAX("A" "B")` | {alphanumeric} | legal |
| `MAX(ZERO 5)` | {numeric} | legal — §8.3.3.6.4 GR4 lets ZERO be either |
| `MAX(ZERO "A")` | {alphanumeric} | legal |
| `MAX(1 "A")` | ∅ | **rejected** (was accepted) |
| `MAX(SPACE 5)` | ∅ | **rejected** (was a RUN-TIME abort) |

A model built for a different question answered this one for free — CLAUDE.md rule 5's "prefer the shape that
makes the NEXT case automatic", observed rather than asserted.

⚠ FAIL-OPEN like every other arm: an operand whose class is not statically decidable contributes no constraint,
so an undecidable argument can never turn a legal list into a rejected one.
⚠ `CrossArgRule.MatchArgument1` (§15.37.3 r2, §15.68.3 r2) governs the positions DECLARING argument-1's kind,
derived from the table so a new row cannot forget to say which positions participate — FIND-STRING's integer
argument-3 is governed by its own rule, not by this one.
