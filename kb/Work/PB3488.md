# PB3488 — the fuzz harness's yield: the judge's gaps were counted against the model

## What the first bake-off showed (2026-10-20 20:36–21:2x PDT; `--bake-off` of five models, 20 programs each, seed 20261020)

| Model | GnuCOBOL accepted | Median model s | Lead rows |
|---|---|---|---|
| qwen3.6:35b | 10/20 | 7 | 9 |
| qwen3-coder:30b | 8/20 | 39 | 6 |
| laguna-xs-2.1 | 8/20 | 20 | 6 |
| qwen3.8:27b | 4/20 | 27 | 2 |
| nemotron-3.5-bolt | 3/20 | 22 | 3 |

The owner read the table as "the models majoritively generate incorrect programs". The tally of GnuCOBOL's own messages over
the 48 refusals (its `error:` lines, counted mechanically from the five `results.jsonl` files) said otherwise for a large
part of them:

- **The judge lacking the feature, about 20 of 48:** `FUNCTION 'HIGHEST-ALGEBRAIC' has invalid argument` ×6, `FUNCTION
  'TRANSLATE' unknown` ×4, `FUNCTION 'NATIONAL' unknown` ×2, `'COMP-3' is not defined, but is a reserved word in another
  dialect` ×1, and the rest of that kind. The seeds are clauses of the 2023 standard; the judge is GnuCOBOL 3.2 at
  `-std=cobol2014`, which does not implement all of 2014 either. The model wrote legal ISO COBOL and lost the program.
- **The model's slips, the rest:** `syntax error, unexpected Identifier` ×9 (two spellings), `unexpected IS` ×4, `unexpected
  SIZE ERROR` ×2, `expecting TIMES`, `duplicate VALUE clause`, an invented `FUNCTION 'YEAR'`: ordinary syntax errors on a
  language the models have seen little of.

The harness's `classify` judged GnuCOBOL's refusal FIRST ("a program it does not compile is the model's failure, whatever
WiseOwl did with it", PB3463) and never compiled such a program with WiseOwl at all. That design choice, taken on
2026-10-20 ~11:00 to filter PB2886's failure mode (a test program using constructs the standard does not have), threw away
the one class of program where WiseOwl is the better-informed compiler.

## The four changes (`scripts/differential_fuzz.py`; the owner's items 1 to 4, verbatim: "Do items 1 through 4 and rerun the bake-off")

1. **A program GnuCOBOL refuses is compiled by WiseOwl before anything else.** WiseOwl compiles it → `THEY_REJECT`, a LEAD
   class (grouped by clause; the report prints GnuCOBOL's first error): GnuCOBOL 3.2 lacks the construct, or WiseOwl
   accepts a program the standard forbids (an under-rejection), and the spec decides at triage. It is NOT sent back for a
   correction: a correction would replace the very construct under test. Both refuse → `BOTH_REJECT`, the model's failure;
   a reply with no program after every correction → `NO_PROGRAM`. The class `GNU_REJECTS` is gone (CLAUDE.md rule 4: no
   alias); `MODEL_FAILURE_CLASSES = (BOTH_REJECT, NO_PROGRAM)` is the one definition the report and the bake-off score read.
   `classify` now orders: an unobserved compiler on either side (RUNNER_ERROR / a hang), a crash of ours, GnuCOBOL's
   refusal (THEY_REJECT or BOTH_REJECT), then the compiled-by-both classes as before.
2. **Three correction rounds, each quoting the first errors only** (`--repairs` default 1 → 3; `repair_request()`):
   GnuCOBOL's first six `error` lines (its cascade ran to thirty lines of `unexpected Identifier`, and a model given the
   cascade fixes the wrong line) and WiseOwl's first four (they cite the standard's clause, which tells the model the rule).
   One round lifted qwen3.6 from 5 to 10 accepted at 7 model-seconds a round; three rounds cost less than one discarded
   program.
3. **The prompt names what the judge lacks** — `JUDGE_LACKS`, DERIVED from the tally above (each entry is a message GnuCOBOL
   itself reported), with the exception "unless the clause under test is one of these": a program on such a clause is the
   THEY_REJECT lead item 1 exists for. Also: "close every conditional statement with its END- word; use only intrinsic
   functions the 2014 standard defines, spelled as it defines them".
4. **One worked example in the prompt** (`EXAMPLE_PROGRAM`): PERFORM VARYING with UNTIL and END-PERFORM, COMPUTE with ROUNDED
   and both SIZE ERROR arms, PICTURE with S, V and editing, an intrinsic function, IF/ELSE/END-IF, free format from column 1,
   PROGRAM-ID FUZZ. Compiled and run by both compilers with identical output before it was written into the prompt
   (2026-10-20 21:4x PDT). The self-test holds it to every rule the prompt states. Temperature default 0.6 → 0.3: the
   slips are a sampling error, not a shortage of ideas.

The bake-off table gained the columns the decision needs: `Usable` (judged minus the model's failures), `Both refuse`,
`GnuCOBOL alone refuses`. The report's header reads `usable … · the model's failures … · GnuCOBOL alone refused (THEY_REJECT
leads)`. `--self-test`: 30 → 40 checks (the three new classes and their precedence, the signature of a THEY_REJECT, the
correction text and its cap, the example's rules, the prompt's contents, the report's new header and group, the score, observe_fresh).

## The second bake-off (the three models still installed; the owner removed the two the first bake-off ranked last)

The first run of the changed harness lost 3 of qwen3.6's first 16 programs to `FileExistsError`: the final WiseOwl compile
(after a correction round GnuCOBOL accepted) re-staged the program into the work directory the round's WiseOwl compile had
left, and `Run.stage` refuses an existing directory. Fixed at the root with ONE mechanism, `observe_fresh(run, entry, name)`
(removes the directory, raises on a held file so the row is a RUNNER_ERROR naming the cause, then observes), used by all
three observations; the two `shutil.rmtree(..., ignore_errors=True)` calls that each caller had carried are gone. Self-test
check 40 stages into a directory holding a left-over file.

The owner added `minimax-m3.1-flash:cloud` (Ollama's US-hosted cloud model, free until 2026-10-22 23:59 UTC, zero data
retention per Ollama's notice) to the bake-off at ~21:55 PDT. The harness reaches it through the same local API; it answered a
probe in 0.8 s with thinking on. What it receives is the system prompt and one clause of `specs/ISO_COBOL.md`, which is
tracked in the PUBLIC repository (only the PDF submodule is private), so nothing leaves the machine that is not already public.

See the evidence record `docs/rearchitecture/evidence/fleet-optimization/2026-10-20-differential-fuzz.md`, section
"The yield changes (PB3488)". The numbers there are the measurement of these four changes.
