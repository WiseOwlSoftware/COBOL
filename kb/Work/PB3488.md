# PB3488 — the fuzz harness's yield

## What the first bake-off showed (2026-10-20 20:36–21:2x PDT; `--bake-off` of five models, 20 programs each, seed 20261020)

| Model | GnuCOBOL accepted | Median model s | Lead rows |
|---|---|---|---|
| qwen3.6:35b | 10/20 | 7 | 9 |
| qwen3-coder:30b | 8/20 | 39 | 6 |
| laguna-xs-2.1 | 8/20 | 20 | 6 |
| qwen3.8:27b | 4/20 | 27 | 2 |
| nemotron-3.5-bolt | 3/20 | 22 | 3 |

The owner read the table as "the models majoritively generate incorrect programs". The first reading of GnuCOBOL's messages
over the refusals (`FUNCTION 'TRANSLATE' unknown` ×4, `FUNCTION 'NATIONAL' unknown` ×2, `FUNCTION 'HIGHEST-ALGEBRAIC' has
invalid argument` ×6, `'COMP-3' is … a reserved word in another dialect` ×1) was that about two fifths of them were the
JUDGE lacking a 2014 feature, not the model. **That reading was wrong**, and the measurement that showed it is below: every
one of those constructs is outside the standard or breaks one of its rules, and WiseOwl refuses the same programs citing it.

## ⛔ The premise, measured (the recount, 2026-10-20 21:5x PDT)

Every program GnuCOBOL refused in the first bake-off, compiled with WiseOwl (`--std 2014 --source-format free`, the build of
main at 0421be4df): **1 of 68 compiles.** The 67 others are the model's: 37 parse errors (COBOL0001 ×19, COBOL0307 ×18), 6
non-national VALUE literals on national items (COBOLNET0898), 4 HIGHEST-ALGEBRAIC on a literal (COBOLNET1516; §15.43.3
argument rule 1: "Argument-1 shall be a data item of category numeric or numeric-edited"), 3 unary `-` without a space
(COBOLNET2993), 3 PICTURE over 31 digits (COBOLNET0801), 3 ×COBOLNET1941, 2 replies with no program, and eight single
codes; the invented FUNCTION TRANSLATE / NATIONAL / SUBSTRING / YEAR are refused as "not an intrinsic function of ISO/IEC
1989 (§15.6 summary of functions)" (COBOLNET1501). `COMP-3` is not in the standard (0 occurrences in `specs/ISO_COBOL.md`;
PACKED-DECIMAL is). So the models' programs WERE incorrect, by the standard, and GnuCOBOL's refusals were right in 67 of 68.

Both citations passed `cite.py --check` (15.6 "Summary of functions"; 15.43.3 1\)). The lesson for the record
([[a_remembered_pattern_is_a_hypothesis]]): a tally of a compiler's messages says what IT refused, never whether the standard
agrees; the measurement was one WiseOwl compile per program and should have come before the reading, not after.

## The changes (`scripts/differential_fuzz.py`)

1. **A program GnuCOBOL refuses is compiled by WiseOwl before anything else** (the owner's item 1). WiseOwl compiles it →
   `THEY_REJECT`, a LEAD class (grouped by clause; the report prints GnuCOBOL's first error): GnuCOBOL 3.2 lacks the
   construct, or WiseOwl accepts a program the standard forbids (an under-rejection), and the spec decides at triage. It
   is NOT sent back for a correction: a correction would replace the construct under test. Both refuse → `BOTH_REJECT`,
   the model's failure; a reply with no program after every correction → `NO_PROGRAM`. `GNU_REJECTS` is gone (CLAUDE.md rule
   4: no alias); `MODEL_FAILURE_CLASSES = (BOTH_REJECT, NO_PROGRAM)` is the one definition the report and the bake-off score
   read. `classify` orders: an unobserved compiler on either side, a crash of ours, GnuCOBOL's refusal (THEY_REJECT or
   BOTH_REJECT), then the compiled-by-both classes as before. The recount says this class is rare (1 in 68); it costs one
   WiseOwl compile per refused program and loses nothing, so it stays.
2. **Three correction rounds, each quoting the first errors only** (item 2; `--repairs` 1 → 3; `repair_request()`):
   GnuCOBOL's first six `error` lines (its cascade ran to thirty lines of `unexpected Identifier`) and WiseOwl's first four
   (they cite the standard's clause). Both compilers' observations are recorded for every round.
3. **The prompt carries the standard's own intrinsic-function list** (item 3, re-derived): `spec_functions()` reads the
   `15.n NAME function` headings of `specs/ISO_COBOL.md` (94 functions, the ones §15.6's table summarizes) and the system
   prompt says "The ONLY intrinsic functions are these; any other FUNCTION name is an error", plus two rules the recount
   showed broken most: HIGHEST-ALGEBRAIC and LOWEST-ALGEBRAIC take a numeric DATA ITEM (§15.43.3 AR1), and USAGE is one of the
   standard's (no COMP-n). The first version of this item was a hand-written `JUDGE_LACKS` list naming TRANSLATE, NATIONAL,
   HIGHEST-ALGEBRAIC and COMP-3 as "features GnuCOBOL lacks"; it was withdrawn the same evening when the recount showed the
   standard lacks them too. Nothing is typed that the spec can supply ([[model_the_rule_shape_not_one_case]]).
4. **One worked example in the prompt** (item 4; `EXAMPLE_PROGRAM`): PERFORM VARYING with UNTIL and END-PERFORM, COMPUTE
   with ROUNDED and both SIZE ERROR arms, PICTURE with S, V and editing, an intrinsic function, IF/ELSE/END-IF, free format
   from column 1, PROGRAM-ID FUZZ. Compiled and run by both compilers with identical output before it was written into the
   prompt (21:4x PDT); the self-test holds it to every rule the prompt states. Also "close every conditional statement with
   its END- word". Temperature 0.6 → 0.3.
5. **The seed folding missed the spec's rules sub-clauses** (found in MiniMax's thinking: "clause 15.66.3 likely NATIONAL-OF?
   Need infer"). `STRUCTURAL` folded "Arguments" and "Returned value(s)" but the spec writes "Argument rules" (45), "Returned
   value rules" (49), "Returned value rule" (43), "Argument rule" (37), "Arguments rules" (2), "Returned values rules" (1),
   "Returned Value rule" (1), "Syntax rule" (2): every function's argument and returned-value rules were seeds of their own,
   titled without the function's name, and every model guessed the function (the first bake-off's `GNU_REJECTS:15.66.3` ×3
   and `15.42.4` ×3 in every model's table are those seeds). Fixed in the regex, case-insensitive, with a DRIFT TEST over the
   real spec (no nested seed under the default prefixes may be a bare structural title); 394 → 275 seeds. A seed nested under
   a clause of its own now carries its ancestors' titles ("PICTURE clause > Editing rules"), so the model is told whose rules
   they are.
6. **`observe_fresh(run, entry, name)`** is the one mechanism for "observe in a fresh work directory" (the first run of the
   changed harness lost 3 of 16 programs to `FileExistsError`: the final WiseOwl compile re-staged into the directory a
   correction round's compile had left; `Run.stage` refuses an existing directory). A directory that cannot be removed
   raises, and the row is a RUNNER_ERROR that names the cause.
7. **`cut_off_reason()`**: a NO_PROGRAM row whose reply spent every output token thinking with empty content says so
   ("think=false was not honoured"). Found with `minimax-m3.1-flash:cloud` (Ollama's US-hosted cloud model, free until
   2026-10-22 23:59 UTC; the owner proposed it at ~21:55 PDT): on a 60-token prompt it honours `think: false` and answers in
   0.9 s; on the harness's full-size prompt (1,455 prompt tokens) it thinks regardless, 28,000 characters, every one of the
   6,000 output tokens, 69 s, empty content — with and without the field. Its one program that compiled took 387 s over four
   rounds. Unusable through this harness until Ollama honours the field for it, or `NUM_PREDICT` is raised for it alone (a
   lead, not done: a 3-minute program is 25 times qwen3.6's). What it receives is public: the system prompt and a clause of
   `specs/ISO_COBOL.md`, tracked in the PUBLIC repository (only the PDF submodule is private).

The bake-off table gained the columns the decision needs: `Usable` (judged minus the model's failures), `Both refuse`,
`GnuCOBOL alone refuses`. The report's header reads `usable … · the model's failures … · GnuCOBOL alone refused (THEY_REJECT
leads)`. `--self-test`: 30 → 46 checks.
