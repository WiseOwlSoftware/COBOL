# PB4934 - the signature gate stops at CALL

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Bound/StatementBinder.cs` (`StatementBinder.NamesGatedMessageTag`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CallBinder.cs` (`CallBinder.BindCall`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CallBinder.cs` (`CallBinder.CalleeSignatureOf`), `src/WiseOwl.Cobol.Compiler/Binding/LinkageBinder.cs` (`CalleeSignature.SignatureItems`), `tests/WiseOwl.Cobol.Tests.Conformance/MessageTagIntroductionGateTests.cs` (`AFormatTwoCallToAMessageTagFormal_IsTheGateAloneBelowTheIntroduction`)

**Repro.** `E:/COBOL-coord/scratch/w20261911c/probe/callnest.cob --std 2014`: a CALL (Format 2, the 2002+ AS-phrase/prototype form) that passes a non-tag argument to a
same-file program whose formal is a message tag draws COBOL1688 plus COBOL0900. Expected: COBOL0900 alone (the tag's entry is the gated construct below 2023; the gate funnel
`NamesGatedMessageTag` makes the statement a no-op so no class diagnostic follows, DESIGN-message-control section 7.1). PB4893 extended that funnel to a function's or method's
signature through data references, keyword-omitted functions, function-identifiers, inline invocations and INVOKE; the CALL arm was NOT added: the callee's signature is
known only inside `CallBinder.BindCall`'s callee resolution, whose literal-1 reading (`Literal1Of`, through `ExpressionBinder.NonNumericLiteralOperand`) REPORTS, so a pure
`CalleeSignatureOf` needs a non-reporting literal-1 reader first. Same root as PB4893 (the funnel's signature reach), the CALL arm. Fix: add that reader, the CALL arm in
`NamesGatedMessageTag`, and the 2014 witness `callnest.cob` as a MessageTagIntroductionGateTests row.

Source report and lead: `w20261911c-PB4893-report.md`, New defects.
