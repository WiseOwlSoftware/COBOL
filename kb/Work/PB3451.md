# PB3451 — the fleet-path check crashes in a drive-top main checkout

> ⚙ **flags:** crashes · process

Found by the loop's wave unit on 2026-10-19 at 19:00 PDT, on its first planner run (step 2 of `units/wave.md`).

**What happened.** `python scripts/orchestrator/plan_wave.py --from-budget --borrow-days 6 --scratch
'E:\COBOL-coord\scratch' --stop-file 'E:\COBOL-coord\scratch\STOP-loop'`, run in the main checkout, exited 1 with

```
File "E:\COBOL\scripts\orchestrator\coord.py", line 144, in scratch_problem
    checkouts = [here] + ([here.parents[2]] if (here.parent.name, here.parents[1].name) == ("worktrees", ".claude") else [])
IndexError: 1
```

**Root cause.** PB3114's self-review (`be46f2427`, landed with PR #308 at 2026-10-20 00:20 UTC) taught
`scratch_problem` to refuse a scratch inside the MAIN checkout when the caller runs in one of its agent worktrees
(`<main>/.claude/worktrees/<name>`). It asked the question by indexing the checkout's parents: the tuple
`(here.parent.name, here.parents[1].name)` is built before it is compared, and the main checkout `E:\COBOL` has a
single parent (`E:\`), so `parents[1]` raises. Every caller of the check dies there: `plan_wave.main`,
`make_dispatch_specs.main` and `check_practices.py`'s groups-file check. The loop's planner therefore could not plan
a wave from the main checkout from the moment #308 merged.

**Why no gate saw it.** The self-test (`coord.py --self-test`) only ever ran in an agent worktree (four levels deep)
or on a CI runner (`/home/runner/work/COBOL/COBOL`), where `parents[1]` exists; the main checkout is the one shape
it never ran in, and its own "inside the main checkout, from a worktree" case derived the main checkout with a
SECOND, different rule (`REPO.parent.name == "worktrees"`).

**The fix.** One rule in one place: `coord.main_checkout(checkout)` answers "which main checkout is this an agent
worktree of" from the path's PARTS (`parts[-3:-1] == (".claude", "worktrees")`), never its parents by index, and
`scratch_problem` takes the checkout as a parameter (default `REPO`) so the self-test can put it at a drive's top
level on any host. The self-test now pins `main_checkout` on a drive-top checkout, its worktree and a path under the
worktree, and runs `scratch_problem` from a drive-top checkout and from its worktree (accepted outside, refused
inside); its old worktree case uses `main_checkout` instead of its own rule. Verified against the real shape:
`scratch_problem('E:\COBOL-coord\scratch', Path('E:/COBOL'))` is None, and a scratch under `E:\COBOL` is refused from
the checkout and from `E:\COBOL\.claude\worktrees\w`.

**Sibling sweep.** `parents[N]` indexing in `scripts/` and `.claude/` on a path that is not file-relative
(`Path(__file__).parents[N]` is a fixed depth inside the tree): `scripts/self_tests.py:154`
(`Path(git --exec-path).parents[2]`, always `<root>/mingw64/libexec/git-core`, three deep by construction) and the
new helper itself. No other sibling.
