# PB3555 — a declined SEQUENTIAL file's status item still joins the commit clause (--permissive)

## Lead (R1-4, low, not blocking at round 1; from the PB3338 report)

`src/WiseOwl.Cobol.Compiler/Binding/DataBinder.IoControl.cs:221` (the review read it at `ResolveApplyCommit`, about line 201 in
the branch): under `--permissive`, a SEQUENTIAL file named in an APPLY COMMIT clause stays outside commit control, but its
FILE STATUS, LINAGE and RECORD items still join the clause's item list. COMMIT then saves those items and ROLLBACK
restores them, although the file itself is neither committed nor rolled back. The reviewer's probe: `sq.cob`; the
permissive sequential case printed FS=00 after ROLLBACK.

The report records the finisher's reply "fixed in passing (d79d98771, I9: SR9 over CommitControlledFiles; test
`A_declined_sequential_operand_puts_neither_the_file_nor_its_status_item_under_commit_control`)" on the wave-1154 branch; the
FS now stays 10. That commit was not on main when this note was filed, so the note stays open until the branch lands, when
it is closed with that test as its witness.

**Sites:**
- `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.IoControl.cs:221 (ResolveApplyCommit)`

## Landed (w1157 group D, 2026-10-23) — closed with the PB3338 branch's witness

The wave-1154 commit carrying the fix (d79d98771, "SR9 over CommitControlledFiles") is on main: it is an ancestor of this
wave's base, and `ResolveApplyCommit` walks `clause.CommitControlledFiles` (the files `FileModel.IsCommitControlled`
admits, so a declined SEQUENTIAL operand contributes no FILE STATUS, LINAGE or RECORD DEPENDING item to the clause).

READ AT END, then ROLLBACK): `READ 10` then `ROLLBACK 10 CHGD` (the status item stays 10, the commit-controlled item W is
restored to "CHGD"; COBOL1709 is the warning). The witness is
`CommitRollbackRefusalWitnessTests.A_declined_sequential_operand_puts_neither_the_file_nor_its_status_item_under_commit_control`.
No code change here.
