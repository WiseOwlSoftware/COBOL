# R52 — HIGH-VALUE in a UTF-16 alphanumeric repertoire

**Asked 2026-09-29** (PB1093): the native alphanumeric repertoire is UTF-16 (65,536 code units, owner: charset_utf16)
but HIGH-VALUE was pinned to U+00FF, so U+0100..U+FFFF compared GREATER than "the character with the highest
ordinal position" (§8.3.3.6.4 GR6, §12.3.7.4 GR8). GnuCOBOL 3.2 has no such gap because its repertoire is 256 bytes
(HIGH-VALUE `0xFF`). **Owner: option (A) — HIGH-VALUE = U+FFFF everywhere the native alphanumeric sequence answers**
(`CollatingModel.Extremes`, `AlphabetFigurative` / `DataBinder.NativeHighValue`, `FigurativeConstants` 'H', the
no-PCS fill, the file collating FINGERPRINT over the whole sequence), consistent with the national arm.

## The consequence the owner then confirmed (R51), and the mechanism as built

R47 makes a fixed-record file's alphanumeric character 8859-1, one byte, and refuses a character above U+00FF — so `MOVE HIGH-VALUES TO REC` then `WRITE REC` would be refused. The answer is not a connector-wide table (the record image carries numeric byte forms as characters, so a connector cannot tell a text 0xFF from a binary 0xFF) and, as measured in PB1759 step 0, not a per-leaf codec either (leafless record areas exist, and HIGH-VALUE would turn `IF REC = HIGH-VALUES` false after a group MOVE over a binary field). It is ONE law about bytes and characters: byte 0xFF IS the character U+FFFF; every other byte b is U+00bb; a character's byte is its low byte (`StorageByte`; the medium channel `FileCharacterSet.ToChannel/FromChannel`). **Accepted cost (DOC-A.1-31): a real `ÿ` (U+00FF) that passes through a byte — the record medium or a byte-form storage position — returns as HIGH-VALUE; an in-memory `X"FF"` literal and an alphanumeric leaf in memory stay U+00FF.**

## Landing (2026-09-29, PB1759)

HIGH-VALUE = U+FFFF at every site, from ONE member (`CobolNet.Runtime.NativeCollatingSequence`). The medium mapping is
not per alphanumeric leaf, as proposed above, but the storage-byte law (byte 0xFF <-> U+FFFF for every byte image, in
memory and at the medium) — the per-leaf codec could not reach leafless record areas (Tier-B backings, multi-01 FD
areas, elementary records) and would have turned `IF REC = HIGH-VALUES` FALSE after `MOVE HIGH-VALUES TO REC` for
any record with a binary field (measured; PB1759 step 0). The accepted cost is the one decided above, generalized:
a real U+00FF that passes through ANY byte (the medium or a byte-form storage position) returns as HIGH-VALUE.
