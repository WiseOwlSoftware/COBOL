# PB5914 - at --std 85 a WRITE ... ADVANCING to a line-framed file drops trailing spaces

Filed from the lead of wave 20262102 group A (kb/Work PB5903 is that branch's note; its branch is not on main as of this note). The implementer's words, unchanged:

> The print arm (`WriteAdvancingRecord`) still trims trailing spaces of a LINE-SEQUENTIAL-delimited file at 85 (WRITE ... ADVANCING); §1985:VII.2.8.4 GR1 may reach it too. Print files are a separate determination (DOC-A.1-146 (c')); to adjudicate.

The reviewer's words (R1-1, round 1, severity low, not blocking), unchanged:

> LEAD (named by the charge and the report, lead 1): the print-control WRITE arm (WRITE ... ADVANCING) of a RECORD DELIMITER IS LINE-SEQUENTIAL file still drops trailing spaces at 85 (TrimRecordEnd unconditionally for a non-record print stream), and once a file has taken an ADVANCING write the plain WRITE of the same file also goes through that arm, so the §1985:VII.2.8.4 GR1 record-keeps-its-size rule PB5903 applies to WriteRecord is not applied there.

- `§1985:VII.2.8.4 GR1`: "Any method used will not be reflected in the record area or the record size used within the program"
  `OK  §1985:VII.2.8.4 GR1  (║2.8.4 General Rules║)  the text is in GR1`

**Not ruled:** whether GR1 reaches a print file written with ADVANCING. The source says it "may"; the print-file decision DOC-A.1-146 is a separate determination. The clerk has not judged it.

**Sites** (the reviewer's names line 1727 of the PB5903 branch, worktree-agent-a09aac01fba0863ba, the print-control arm): `src/WiseOwl.Cobol.Runtime/IO/SequentialConnector.cs#WriteAdvancingRecord`; the trim is `TrimRecordEnd`. `WriteAdvancingRecord` is also named by kb/Work PB2509 and PB5860.

**Rows.** None claimed. The same branch's witnesses: 1985-GR-VII.4.4.4-13 and 1985-GR-VII.2.8.4-1.

**Scope.** `--std 85`, a file with RECORD DELIMITER IS LINE-SEQUENTIAL that takes a WRITE with ADVANCING.
