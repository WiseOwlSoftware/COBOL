# PB664 — OPEN — the MOVE arm of a screen the other statements have

Found 2026-09-05 by the `PB231` pointer-third implementer (report §"New defects" (2)), reproduced on the pristine
main-tree compiler; pre-existing.

## Repro (`--std 2002`+; `<a9d94900 scratch>/PB231-pointer/probe13.cob`)

```cobol
       01 P   USAGE POINTER.
       01 A66 PIC X(4).
           MOVE P TO A66
           DISPLAY A66                 *> the first four characters of a .NET type name
```

Emitted: `A66 = CobolString.Store(P.ToString(), 4);`.

## The rule

§14.6.8 (the MOVE statement's rules) defines the transfer by the sending and receiving CATEGORIES in Table 16, and
Table 16 has no row for a class-pointer sender (`cite.py --find "Table 16"` and read the row list before acting);
§13.18.60.4 GR22/GR23 put an object reference in class object and a data-pointer in class pointer. A MOVE with an
undefined meaning is nonconforming source and must be rejected at bind, exactly as its siblings are: DISPLAY of a
pointer is refused under §14.9.11.3 SR1 "Identifier-1 shall not reference …" (`OK §14.9.11.3 1)`, COBOLNET1694) and
INSPECT under §14.9.22.3 SR1 (COBOLNET1626).

## The mechanism

`src/Cobol.Net.Compiler/CodeGen/Emit/OperandText.cs`, the sending-image switch's fall-through
`_ => $"{PlaceRenderer.Read(p)}.ToString()"` — reached only by the pointer/object categories, and it should be
unreachable behind a bind-time screen that `MoveClassifier` / `MoveEmitter` do not have. [[two_arm_dispatch]]:
DISPLAY and INSPECT got the screen, MOVE did not.

## Fix shape

One category-admissibility table for a MOVE sender, derived from Table 16's row list (the same source PB305's
`TableTwoClass` projection reads), consulted at bind in `MoveClassifier` with one descriptor (next free code) naming
§14.6.8's table; delete the `.ToString()` fall-through so a pointer reaching the renderer is a loud bind-phase
invariant failure, never text. Sweep the other receiving/sending statements for the same missing arm (STRING,
UNSTRING, the EVALUATE subject, a relation condition's operand — measure each with a pointer operand). Negatives at
2002/2014/2023 for MOVE pointer → alphanumeric, MOVE object-reference → alphanumeric, MOVE program-pointer →
numeric; positive control: `SET` between pointers, the only conforming transfer.
