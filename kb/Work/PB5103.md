# PB5103 - at --std 85 INSPECT REPLACING and CONVERTING size rules are enforced for literals only: a mis-sized identifier in REPLACING ALL, a CHARACTERS BY identifier of two characters and a CONVERTING of unequal-size identifiers compile and use the first character

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/InspectBinder.cs` (whole: the records name no site; PB5089 names this file and its `CheckInspectLiteralSizes`, the literal-size check that the identifier operands do not reach)

**Mechanism.** The 1985 size rules of INSPECT (SR7, SR8, SR9 of §1985:VI.6.18.3) are checked when the operands are literals (COBOL0846) and not when an operand is a data item: the statement compiles with no diagnostic and the run silently skips the replacement or uses only the first character of the longer operand. Same family as PB5089 (SR10, a repeated CONVERTING character), a different rule.

**Found by.** The 1985 MATCH confirmation pass (kb/Work PB4995 item 3): each rule below is a corrected draft (a "redraft") that the compiler at `--std 85` still fails (redraft_run MISMATCH). Harm and observed text are the records; nothing here was re-derived.

**Inventory.** The traceability inventory carries no 1985 rows yet (PB5094: work.py refuses 1985 ids), so `inventory_rows` is empty; the rows this note covers are the 1985 rule ids listed below (catalog `docs/rearchitecture/spec-rule-catalog-1985.json`).

**Rules (3; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-SR-VI.6.18.3-7` - `§1985:VI.6.18.3 SR7` (record harm: under-rejects, slice-21): "The size of literal-3 or the data item referenced by identifier-5 must be equal to the size of literal-1 or the data item referenced by identifier-3" . The corrected draft replaces a two-character identifier-3 by a one-character identifier-5 (REPLACING ALL WS-F BY WS-T1). Observed: compiles; the replacement is silently skipped; ALL "AB" BY "X" with literals is refused with COBOL0846.
- `1985-SR-VI.6.18.3-8` - `§1985:VI.6.18.3 SR8` (record harm: under-rejects, slice-21): "literal-3 or the size of the data item referenced by identifier-5 must be one character in length" (the rule as Amendment 2 corrects it: "When the CHARACTERS phrase is used, ..."). The corrected draft is CHARACTERS BY a two-character data item. Observed: compiles; the first character is used; CHARACTERS BY the literal "XY" is refused with COBOL0846.
- `1985-SR-VI.6.18.3-9` - `§1985:VI.6.18.3 SR9` (record harm: under-rejects, slice-21): "The size of literal-5 or the data item referenced by identifier-7 must be equal to the size of literal-4 or the data item referenced by identifier-6" . Format 4 CONVERTING written with data items of unequal size. Observed: compiles; only the first character is converted; CONVERTING "AB" TO "X" with literals is refused with COBOL0846.

**Repro (`1985-SR-VI.6.18.3-7`, slice-21).** cobol.exe p.cob --std 85 --source-format fixed --flag-extensions -o p.dll; dotnet p.dll

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. INSP7.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WS-X  PIC X(6) VALUE "ABCDAB".
       01  WS-F  PIC XX VALUE "AB".
       01  WS-T1 PIC X VALUE "0".
       01  WS-T2 PIC XX VALUE "00".
       PROCEDURE DIVISION.
       P1.
           INSPECT WS-X REPLACING ALL WS-F BY WS-T1.
           INSPECT WS-X REPLACING ALL "CD" BY SPACE.
           DISPLAY WS-X "|".
           STOP RUN.
```

**Expected (from the 1985 text).** Refused at line 11. The deciding words: "The size of literal-3 or the data item referenced by identifier-5 must be equal to the size of literal-1 or the data item referenced by identifier-3" (§1985:VI.6.18.3 SR7).

**Observed (copied from `1985-SR-VI.6.18.3-7`).** compile exit 0 with no diagnostic; the run prints 'AB  AB|' (the mis-sized REPLACING ALL WS-F BY WS-T1 is silently skipped; the control prints '00  00|'). The same statement with literals (ALL "AB" BY "X") is refused with COBOL0846; ALL "AB" BY a one-character item and ALL a one-character item BY "XY" are also accepted.
