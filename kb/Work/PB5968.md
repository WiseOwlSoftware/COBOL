# PB5968 - the filter_population self-test is the longest single step of the gate's self-test phase

**Evidence:** `scripts/filter_population.py --self-test`: "GREEN in 1314.1s" (gate log of
`E:/COBOL/.claude/worktrees/listing-step-6b-r1/TestResults/build-local/000001-20261120T045134Z/gate.log`; the phase line reads "1 deferred to
--built: scripts/filter_population.py"). `scripts/self_tests.py:46` and `scripts/lane_classification.py:432` explain why: it reads the BUILT test
assemblies (it asks vstest which tests a filter selects), so it is keyed on the assemblies and cannot run before the build.

**Cause (not yet measured; to establish first):** the self-test probably calls vstest discovery over the full 28,000-case Conformance and 42,000-case
Unit assemblies once per case of its own table. Profile it (`performance-diagnosis`: scaling curve, stack sampling) before changing anything.

**Fix shape:** discover each assembly's population once and let every self-test case read the cached listing (or a small fixture assembly), keeping one
real-assembly case; a structural guard (a count of vstest launches), never a wall-clock limit.
