## Row `GR-9.3.6-L5.1` — NEEDS-OWNER-DECISION (editions 2002, 2014, 2023 (OO method invocation, §9.3.6, is introduced by ISO 2002; absent from X3.23-1985))

Rule (§9.3.6 exact-match criterion 1, cite.py OK §9.3.6 1)): same class and category is an EXACT match for a by-value/by-content parameter or returning item. The exact-match distinction only selects between two or more candidate methods of one name (resolution steps 1/2 vs 3/4 and the preference paragraph) - i.e. parametric polymorphism (§9.3.5.3, cite.py OK). COBOL.NET does not claim it: CONFORMANCE.md A.4.10 item 3 'Not claimed', §2 row 45 'N/A'; OoClassTable refuses a same-named method COBOLNET0822 and OoClassSymbol.FindMethod resolves by NAME alone, so there is never a second candidate and the criterion is unobservable. No derived selector covers this row (inventory-schema `oo-optional-items-only` holds only SR-8.4.3.8.3-5, SR-11.3.3-7, GR-11.3.4-4). Owner: disposition as documented non-support under A.4.10 item 3 (widen the selector) or claim parametric polymorphism.

## Row `GR-9.3.6-L5.2` — NEEDS-OWNER-DECISION (editions 2002, 2014, 2023 (OO method invocation, §9.3.6, is introduced by ISO 2002; absent from X3.23-1985))

Rule (§9.3.6 exact-match criterion 2 a)-e), cite.py OK §9.3.6 for d) 'shall evaluate to an object reference of the same class specified in the invocation'): the object-reference exact-match criteria. Same determination as GR-9.3.6-L5.1: exact-vs-inexact only selects among several same-named candidates (parametric polymorphism, A.4.10 item 3, not claimed; COBOLNET0822; name-only FindMethod), so it is unobservable here and no derived selector covers the row. Related but separately reported: the ACTIVE-CLASS legs d)/e) share their substitution with §14.8.3.3 rule 2, whose RETURNING arm is defective (see GR-9.3.6-L3.6's finding - an ACTIVE-CLASS returning item is typed as the declaring class, not the invocation's class). Owner: document under A.4.10 item 3 or claim it.

## Row `GR-9.3.6-L5.3` — NEEDS-OWNER-DECISION (editions 2002, 2014, 2023 (OO method invocation, §9.3.6, is introduced by ISO 2002; absent from X3.23-1985))

Rule (§9.3.6 exact-match criterion 3 + the literal-equivalence paragraph + 'All parameters passed by reference are exact matches' + the tie-break 'If two or more methods in a class match, preference is given to the method that has the greatest number of parameters that match exactly' - cite.py OK §9.3.6).
