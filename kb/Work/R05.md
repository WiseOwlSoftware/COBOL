# R05 — LANDED — `EXCEPTION-STATUS` "truncation" was the rule itself; the defects were the missing record, the missing advisory, and a directive-word hole this item's own fact discovered

> Migrated from the fix queue's RESIDUE block. Original finding: Phase-B F6
> (`docs/rearchitecture/evidence/PHASE-B-15.32-15.44-findings.md`).

## The premise did not survive the spec (again)

The one-line summary said "silently truncates an exception-name at 31 characters" as if the width were the
defect. **§15.33.3 r1 prescribes the width**: "A 31-character, left-justified, alphanumeric character string
that is the exception-name…" (cite-checked). The collision is the STANDARD's own — §8.3.2.1 lets 2023 words run
to 63 and §14.6.13.1.1 leaves EC-USER-/EC-IMP- suffixes unbounded, so 32..63-character level-3 names are legal
yet indistinguishable through this one function. F6's real complaint: the choice was recorded NOWHERE.

## LANDED (2026-08-07)

1. **The runtime stays r1-exact** (`EcFunctions.Status` unchanged); the choice is now RECORDED in
   `COBOLNET_CONDITIONS_EXCEPTIONS_DESIGN.md` (Resolved questions).
2. **COBOLNET1636 advisory** (Warning — legal source stays legal): an over-31 level-3 name is flagged once per
   spelling, with the §15.33.3 r1 / §8.3.2.1 collision named. Checking/declarative selection/WHEN matching use
   the full name (`ExceptionState.LastName`) — only the FUNCTION narrows.
3. **⛔ THE ADVISORY FORCED THE EXTRACTION `feedback_one_rule_one_place` DEMANDS.** Written exception-names
   resolved at SIX sites — four with verbatim copies of the unknown-name (0711) and introduction-gate (0878)
   diagnostics. All resolution now funnels through **`EcNameResolution`** (0711/0878 became catalog
   descriptors); the two RAISING partitions (PD header, METHOD-ID — where an unresolved word may be a CLASS
   name) call `Advise` directly. `EcNameResolutionDriftTests` pins every `ExceptionCatalog.TryGet` call site
   with its adjudicated reason and call count, and bans bare 0711/0878/1636 literals.
   - The funnel closed a pre-existing hole: `USE AFTER EC EC-MCS` (a LEVEL-2 name of a 2023-only family) slipped
     the old USE-site gate at 2002/2014 because its copy guarded `Level == 3`. Fact ECT052 pins the fix.
4. **⭐ THIS ITEM'S OWN FACT FOUND A NEW DEFECT: the §8.3.2.1 word-length ceiling never covered
   DIRECTIVE-carried words.** The "at 2002 the long word is rejected" fact FAILED when written — the ledger's
   "correctly rejected with COBOLNET1567" was measured on the RAISE spelling only. A 44-char exception-name in
   `>>TURN` and a 44-char `>>DEFINE` variable name both compiled clean at `--std 2002` (the DEFINE case probed,
   not inferred). **`CobolWordRule`** (Frontend.Common) now owns the ceiling — the tree-walk funnel
   (`VisitCobolWord`), the TURN stage, and the DEFINE stage all report the SAME rule through the same text; 1567
   gained the catalog descriptor it never had (`DiagnosticRegistryDriftTests` caught the bare literal).
   `>>COBOL-WORDS` needs no site: the words its literals introduce reach the tree wherever used.
