# PB3906 — evaluate-boolean-subject-when-true: One-character boolean item as a condition is refused: 'incomplete expression' for EVALUATE flag WHEN TRUE and IF flag

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S6) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\evaluate-boolean-subject-when-true.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\evaluate-boolean-subject-when-true\`.

## Summary

GnuCOBOL 3.2 refuses a boolean data item of length 1 wherever the standard treats it as a boolean condition. The
family's case is `EVALUATE flag WHEN TRUE ... WHEN FALSE ...`, where 14.9.13.3 6) b) makes the subject a boolean
condition; cobc reports `incomplete expression` and `invalid expression: boolean expected with logical operator`. The
same item as the condition of an IF (`IF flag`, the simple boolean condition of 8.8.4.3) draws `incomplete expression`
too, so the root is that cobc's condition builder has no case for a boolean condition. Both forms are in the 2002 and
2014 editions. The relation forms `IF flag = B"1"` and `EVALUATE flag WHEN B"1"` compile and run. Class: rejects legal
ISO source.

## Expected result (per ISO)

The program is legal and prints `T`.

- §14.9.13.3 6) b) (checked): "If the selection object is TRUE or FALSE and the selection subject is a boolean
  expression that results in one boolean character, the selection subject is treated as a boolean condition and
  therefore condition-1."
- §8.8.2 (checked): a boolean expression may be "an identifier referencing a boolean data item". FLAG is PIC 1, usage
  display, one boolean character.
- §14.9.13.4 4) a) 4. (checked): "If the selection object is either TRUE or FALSE, the selection subject is
  condition-1. If the truth value of the selection subject and selection object match, the result of the analysis is
  true."
- §8.8.4.3.3 1) (checked): "Boolean-expression-1 shall reference only boolean items of length 1." §8.8.4.3.4 1)
  (checked): "Boolean-expression-1 evaluates true if the result of the expression is 1 and evaluates false if the
  result of the expression is 0." FLAG is 1, so WHEN TRUE is selected (and `IF FLAG` is true).

Note on 14.9.13.4 3) a) (a subject that is "a boolean data item whose length is one boolean position ... is treated as
identifier-1"): that rule assigns the subject's value for the pairs compared as relations (syntax rule 6) d)); for a
WHEN whose object is TRUE or FALSE, syntax rule 6) b) reclassifies the subject as condition-1 "for a particular WHEN
phrase", and general rule 4) a) 4. evaluates it as a condition. The IF form in the sibling program does not depend on
that reading at all.

Edition: 2014. The 2009 committee draft that became ISO/IEC 1989:2014 (CD 1.2) carries the same EVALUATE syntax rule
6) a) to e) (14.9.13 in that draft, with Table 16) and the boolean condition as 8.8.4.1.2 with the same syntax rule 1
and general rule 1. Boolean items and the boolean condition are 2002 features; Annex E of the 2023 standard lists no
change to them.

Edition as recorded by the adjudicator: 2014 (introduced 2002). `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Fix site (GnuCOBOL 3.2 source, read observationally)

- `cobc/typeck.c`, `cb_build_cond`: the `CB_TAG_REFERENCE` arm turns a reference into a condition only when it names a
  level-88 item or a non-field; a reference to a boolean field of length 1 falls through to the `incomplete expression`
  error at the end of the function. A boolean-condition arm (test the item for 1, per 8.8.4.3.4) is the missing case.
- `cobc/typeck.c`, `evaluate_test`: for a TRUE object it returns the subject unchanged (and its negation for FALSE),
  which then reaches `cb_build_cond` as the bare reference; `cobc/tree.c`, `cb_build_binary_op`, the logical-operator
  case, then reports `boolean expected with logical operator` for the same operand.
- `cobc/parser.y`, `evaluate_subject` (the `expr` alternative) and `evaluate_object`: the subject is kept as an
  expression, and no reclassification per 14.9.13.3 6) happens at parse time.
