# PB3892 — national-of-function-not-supported: FUNCTION NATIONAL-OF (ISO 2002/2014) is not implemented; -std=cobol2014 reports a syntax error

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S4) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\national-of-function-not-supported.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\national-of-function-not-supported\`.

## Summary

GnuCOBOL 3.2 refuses every reference to the standard intrinsic function NATIONAL-OF. Under `-std=cobol2014` the
diagnostic is `syntax error, unexpected FUNCTION NATIONAL-OF`; under the default dialect it is
`FUNCTION 'NATIONAL-OF' is not implemented`. NATIONAL-OF is part of ISO/IEC 1989 since the 2002 edition, so this is a
missing feature of the edition `-std=cobol2014` claims. Class: feature missing.

## Minimal test case

Free reference format (`-fformat=free`), 10 lines, written for this record (the fuzz witnesses fz00092, fz00382,
fz00606 and 6 others, nights 3 to 5, all reduce to it).

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. NATOF.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 ALN PIC X(3) VALUE "ABC".
01 NAT PIC N(3).
PROCEDURE DIVISION.
MOVE FUNCTION NATIONAL-OF(ALN) TO NAT
IF NAT = N"ABC" DISPLAY "OK" ELSE DISPLAY "BAD" END-IF
STOP RUN.
```

File: `E:\COBOL-coord\scratch\op\pb3838\records\national-of-function-not-supported.cob`. The two-argument form
`FUNCTION NATIONAL-OF(ALN N"?")` draws the same diagnostics.

## Observed result

`-std=cobol2014`, exit code 1:

```
natof.cob:6: warning: handling of USAGE NATIONAL is unfinished; implementation is likely to be changed [-Wunfinished]
natof.cob:8: error: syntax error, unexpected FUNCTION NATIONAL-OF
natof.cob:9: warning: handling of national literal is unfinished; implementation is likely to be changed [-Wunfinished]
```

Default dialect, exit code 1: `natof.cob:8: error: FUNCTION 'NATIONAL-OF' is not implemented`.

`cobc --list-intrinsics` prints `NATIONAL-OF                     No              1 - 2`; `cobc -std=cobol2014 --list-intrinsics` prints
`NATIONAL-OF                     Yes             1 - 2` (re-run for this note on cobc 3.2.0, 2026-10-27; corrected by the refuter: the
record had reported only the default dialect's No).

## Expected result (per ISO)

The program is legal and prints `OK`.

- ISO/IEC 1989:2023 §15.66.1 (checked): "The NATIONAL-OF function returns a character string containing the national
  character representation of the characters in the argument."
- §15.66.3 1) (checked): "Argument-1 shall be of class alphabetic or class alphanumeric." ALN is alphanumeric.
  §15.66.3 2) (checked) bounds the optional argument-2 ("shall be of category national and shall be one character in
  length"); §15.66.3 3) (checked): "Argument-1 shall not be a zero-length literal." The program satisfies all three.
- §15.66.4 1) (checked): "A character string is returned with each alphanumeric character in argument-1 converted to
  its corresponding national coded character set representation." The implementor defines the correspondence, but A,
  B and C have national counterparts in any national character set built on ISO/IEC 10646, so the result equals
  N"ABC".

Edition: NATIONAL-OF is a 2002 feature, present in the 2014 edition. The 2002 final committee draft (§15.53) and the
2009 committee draft that became ISO/IEC 1989:2014 (CD 1.2, §15.61, with the same argument rules 1 and 2) both define
it, and Annex E of the 2023 standard does not list it as new.

Edition as recorded by the adjudicator: 2014 (introduced 2002; in the 2002 FCD and the 2009 CD; not in 2023 Annex E). `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

FEATURE-MISSING (edition 2014; introduced 2002): a standard intrinsic function refused as not implemented.

## Fix site (GnuCOBOL 3.2 source, read observationally)

- `cobc/reserved.c`, `function_list` entry "NATIONAL-OF" (line 3672): marked `CB_FEATURE_NOT_IMPLEMENTED`, which
  `cobc/tree.c` `cb_build_intrinsic` turns into "is not implemented" and `cb_list_intrinsics` into "No".
- `config/cobol2014.words`: line 535 `not-intrinsic-function: DIALECT-ALL`, then line 590 re-activates NATIONAL-OF.
  `cobc/reserved.c` `set_intrinsic_mode` (about line 4980, with its own FIXME) lets that sequence move the entry
  from `CB_FEATURE_NOT_IMPLEMENTED` to `CB_FEATURE_DISABLED` to `CB_FEATURE_ACTIVE`, so under `-std=cobol2014`
  `cb_list_intrinsics` reports Yes and the not-implemented check of `cb_build_intrinsic` is bypassed (refuter, S4).
- `cobc/parser.y`, token `NATIONAL_OF_FUNC` (line 2997), declared with the remark "not used here": no grammar rule
  consumes it, so the re-activated function reaches the grammar as a token it cannot parse: the
  `-std=cobol2014` syntax error. The flip above, not the token alone, is why only `-std` gives the syntax error.
- `libcob/intrinsic.c`, `cob_intr_national_of` (line 7135): a stub that calls `error_not_implemented`.
- The conversion needs the alphanumeric-to-national correspondence (ISO A.1 item 33, implementor-defined) that the
  national MOVE already uses (`cobc/typeck.c` `validate_move` / the libcob move routines).

## Draft issue

**Title:** FUNCTION NATIONAL-OF (ISO 2002/2014) is not implemented; -std=cobol2014 reports a syntax error

**Body:**

Environment: GnuCOBOL 3.2.0 (Ubuntu gnucobol3 3.2-4build1), x86_64 Linux.

Steps: `cobc -std=cobol2014 -fformat=free -x natof.cob` with

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. NATOF.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 ALN PIC X(3) VALUE "ABC".
01 NAT PIC N(3).
PROCEDURE DIVISION.
MOVE FUNCTION NATIONAL-OF(ALN) TO NAT
IF NAT = N"ABC" DISPLAY "OK" ELSE DISPLAY "BAD" END-IF
STOP RUN.
```

Observed: `natof.cob:8: error: syntax error, unexpected FUNCTION NATIONAL-OF` (exit 1). Without `-std`:
`FUNCTION 'NATIONAL-OF' is not implemented`. `cobc --list-intrinsics` lists it as "No", but `cobc -std=cobol2014
--list-intrinsics` lists it as "Yes".

Expected: the program compiles and prints `OK`. NATIONAL-OF is a standard intrinsic function since ISO/IEC 1989:2002
and is in ISO/IEC 1989:2014 (2023 §15.66): "A character string is returned with each alphanumeric character in
argument-1 converted to its corresponding national coded character set representation." Argument-1 is alphabetic or
alphanumeric; the optional argument-2 is a one-character national substitution character.

Secondary: under `-std=cobol2014` the diagnostic is a syntax error rather than the "is not implemented" message the
default dialect gives. config/cobol2014.words disables every function (`not-intrinsic-function: DIALECT-ALL`)
and then re-activates NATIONAL-OF; set_intrinsic_mode in cobc/reserved.c turns the not-implemented entry into disabled
and then into active (its FIXME notes this), so the not-implemented check is bypassed and the scanner returns
the `NATIONAL_OF_FUNC` token, which no grammar rule uses.
