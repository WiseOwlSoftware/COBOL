# PB5376 - DISABLE or ENABLE OUTPUT with a destination named in two DESTINATION TABLE occurrences answers status 15 (already disabled or enabled) for a destination that was connected when the statement began: SetOutput tests each occurrence against the state the same statement has just changed

**Sites:**

- `src/WiseOwl.Cobol.Runtime/Communication/MessageControlSession.cs#SetOutput`

**Mechanism.** `SetOutput` walks the DESTINATION TABLE occurrences one at a time and asks, for each, whether the destination is already in the requested state. The second occurrence of a destination named twice sees the change the first occurrence made, so a destination that was enabled when DISABLE began is reported already disconnected (15), and a table with an unknown destination as well reports the combination 80. kb/Work PB5340 (open) asks only for a witness of the PURGE and error-key arms; it does not hold this reading.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids below. Its row is not recorded: the refuter's OVERTURNED verdict is held for adjudication in `E:/COBOL-coord/scratch/coderead-85/held-7.json`.

**Rules (1 claimed; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-GR-XIV.3.2.4-1` - `§1985:XIV.3.2.4 GR1` (refuter: OVERTURNED the read's CONFORMS, harm: wrong status): "No action is taken when a DISABLE statement is executed which specifies a source or destination which is already disconnected"; the deactivation covers "all destinations specified by the content of each occurrence of data-name-5" (`§1985:XIV.3.2.4 GR6`). ENABLE has the same rule: "No action is taken when an ENABLE statement is executed which specifies a source or destination which is already connected" (`§1985:XIV.3.3.4 GR1`).

**Repro.** `E:/COBOL-coord/scratch/coderead-85/out-reread2/refute-rr-05/r1.cob` and `r2.cob` with `mcs-r1.json` (D3 enabled), copied into a fresh directory as `mcs.json`; `WISEOWL_COBOL_MCS=<dir> cobol.exe --std 85 --source-format fixed --run <file>`. DESTINATION COUNT 2 with D3 in both occurrences, then `DISABLE OUTPUT` and `ENABLE OUTPUT`; r2 names D3, D9 (unknown), D3.

**Observed (the pinned compiler of `E:/COBOL-wt/coderead85-tree-b` (origin/main 8147f008b3; `git diff --stat 8147f008b3 origin/main -- src` is empty at 5237495315), rerun 2026-11-12; `E:/COBOL-coord/scratch/coderead-85/reprobe-85f/log.txt`).** r1 prints `DIS D3D3 15 05` and `ENA D3D3 15 05`; r2 prints `DDD 80 015`.

**Expected (from the 1985 text).** D3 was connected when the DISABLE began, so it is deactivated with status 00 and error keys 0 and 0; D3, D9, D3 gives 20 (unknown destination) with error keys 0, 1, 0. The same holds for ENABLE.

**Fix direction (root cause, CLAUDE.md rule 4).** Judge "already disabled or enabled" against each destination's state when the statement starts (take the set of distinct destinations first, then change them), in the one routine both DISABLE and ENABLE OUTPUT use.
