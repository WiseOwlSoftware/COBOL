# PB5286 - ENABLE and DISABLE INPUT do not act on the logical paths between a queue and its sources: the MCS keeps one enabled flag per endpoint, so DISABLE INPUT of a queue leaves its sub-queues open, ENABLE INPUT of a queue cannot reopen a path DISABLE INPUT TERMINAL closed, and ENABLE INPUT TERMINAL cannot reopen one DISABLE INPUT closed

**Sites:**

- `src/WiseOwl.Cobol.Runtime/Communication/MessageControlSession.cs` (`SetPath`, `SetOne`)
- `src/WiseOwl.Cobol.Runtime/Communication/MessageStoreState.cs` (`Deliver`)
- `src/WiseOwl.Cobol.Runtime/Communication/McsTables.cs` (`Path`, `PutPath`, `DeleteEndpoint`)
- `src/WiseOwl.Cobol.Runtime/Communication/MessageStoreState.cs` (`SetQueuePaths`, `SetSourcePaths`, `PathOpen`)

**Mechanism.** The 1985 statements act on logical PATHS: DISABLE INPUT deactivates "the logical paths between the queue and sub-queues specified ... and all the associated enabled sources" (§1985:XIV.3.2.4 GR3), ENABLE INPUT activates "the logical paths between the queue and sub-queues ... and all the associated sources" (§1985:XIV.3.3.4 GR2), and ENABLE INPUT TERMINAL those between a source "and all of its associated queues and sub-queues" (GR3). The MCS keeps one enabled flag per endpoint: `SetPath`/`SetOne` flip only the named node, and `Deliver` admits a message only when its target node and its source are both enabled. So a queue disabled with blank sub-queue names still takes messages into its sub-queues, and a path closed from one end cannot be reopened from the other (status 15, "already enabled"). DESIGN-communication-facility.md section 6 records the per-endpoint model; the fix changes the design.
