# PB349 — three catalogued names, one missing field

**Rows:** `GR-14.9.32.4-1`, `GR-14.9.34.4-1`, `GR-14.9.34.4-3`. RELEASE and RETURN reported this separately; it
is one absent piece of state.

## The programs

**EC-FLOW-RELEASE** (`out-b1/probe/gr1turn/gr1turn.cob`): `>>TURN EC-FLOW-RELEASE CHECKING ON` at column 8 before
the PROCEDURE DIVISION, then in `MAIN-P` — outside any input procedure — `MOVE "ZZZ" TO SR-KEY. MOVE "zzzzz" TO
SR-DATA. RELEASE SRT-REC.` followed by a SORT with INPUT/OUTPUT PROCEDUREs. Observed: compiles clean, prints
`RELEASE-OUTSIDE-ACCEPTED-UNDER-TURN-ON`, run completes normally — and **the stranded record is silently
discarded** when the later SORT's `CobolSort.Init` clears the buffer, so the program's answer is wrong and
nothing says so.

**EC-FLOW-RETURN** (`out-b1/probe/p4/p4.cob`): `>>TURN EC-FLOW-RETURN CHECKING ON` at column 8 of line 1, then a
bare `RETURN SF AT END ... NOT AT END ... END-RETURN. DISPLAY "AFTER".` in MAIN with no SORT or MERGE executing.
Prints `AT END` / `AFTER`, exit 0 — **byte-identical to `p3.cob`, the same program with no TURN directive.**

**The controls prove the directive pipeline works.** `out-b1/probe/turnctl/turnctl.cob` and `probe/p5/p5.cob`
put `>>TURN EC-BOUND-SUBSCRIPT CHECKING ON` at the identical position with an out-of-range subscript, and both
fire: *abnormal run-unit termination: EC-BOUND-SUBSCRIPT (fatal): subscript 7 is outside 1..3 (ISO 8.4.2.3.4
GR2)*.

## The rules

> §14.9.32.4 GR1: A RELEASE statement may be executed only when it is within the range of an input procedure
> being executed by a SORT statement that references the file-name associated with record-name-1. If it is
> executed at any other time, the EC-FLOW-RELEASE exception condition is set to exist.

`--check 14.9.32.4 "the EC-FLOW-RELEASE exception condition is set to exist"` → **OK**; §14.9.34.4 GR1
(EC-FLOW-RETURN) and GR3 (EC-SORT-MERGE-RETURN) `--check 14.9.34.4` → **OK** for both. All three names are Fatal
in Table 13, so with checking enabled §14.6.13.1.3 item 7 terminates the run unit abnormally after item 5's
USE-declarative dispatch and item 4's PERFORM WHEN.

**The default is NOT the finding.** §14.6.13.1.1 — *By default, checking is not enabled for any exception
condition* (`--check` → **OK**) — and §7.3.25.4 make the checking-OFF behaviour conformant. Only the
checking-ON path is at issue.

## What the compiler does

The names exist and nothing else does. `ExceptionCatalog.cs:101` registers `L3("EC-FLOW-RELEASE",
EcFatality.Fatal)` and `:103`/`:196` register both RETURN names; `CobolSort.cs:34` and `SortBinder.cs:220-221`
describe the seam in prose. There is **no row in `EcEmitter.FatalAmbientGates`** (lines 144-190, the table that
gives a fatal condition its per-statement guard and names its `ExceptionState` checking flag), **no member in
`Runtime/Exceptions/CheckingFlags.cs`**, **no `QueryFor` case in `EcBinder.EcWrap`** for `BoundReturn` or
`BoundRelease`, and **no raise site**: a repo-wide grep returns the catalog lines and comments and nothing else.

**And there is no phase state to check against.** `CobolSort.Store` (`CobolSort.cs:26-36`) carries records, stream
starts, a cursor and a collation, and its own comment concedes that *the EC-FLOW-RELEASE / EC-FLOW-RETURN /
EC-SORT-MERGE-ACTIVE phase tracking ... attaches here when the EC model lands*. So implementing GR1 needs an
active-SORT phase marker per SD, not just a raise call.

## Nothing relieves this

Sort-merge is required normative surface, not an A.3 processor-dependent or A.4 optional element, so
§14.6.13.1.1's proviso (*The implementor is not required to raise any exception conditions for level-3
exception-names that are associated with optional language elements or processor-dependent language elements that
the implementor has not implemented*) does not reach it, and `docs/CONFORMANCE.md` §5 declares no sort-merge
module Not claimed. `kb/Work/PB3` owns EC-FLOW-SEARCH (which IS raised but bypasses handler dispatch) and
`PB137` owns the COMMIT/ROLLBACK EC-FLOW names; neither owns any §14.9.32 or §14.9.34 row.

## The fix shape, and the drift test the whole family needs

A phase field on `CobolSort.Store` — which SORT/MERGE already bracket with `Init`/`Close` — plus a precise
`QueryFor` case for `BoundReturn`/`BoundRelease` and the `FatalAmbientGates` rows. That also lights up
**EC-SORT-MERGE-ACTIVE**, the fourth name sitting on the same missing field.

⛔ **The invariant that would have caught all of this, and PB326 and PB368 with it: every turnable name in
`ExceptionCatalog` has a raise site.** Five catalogued conditions across three subsystems were found inert in one
batch; a drift test asserting that correspondence is what makes the next one impossible, and it belongs with this
note because this is the widest family.

**Code sites:** `ExceptionCatalog.cs` (lines 101, 103, 196) · `EcEmitter.cs#FatalAmbientGates` ·
`Runtime/Exceptions/CheckingFlags.cs` · `EcBinder.cs#EcWrap` · `CobolSort.cs#Store`, `#Release`, `#Return`.

## Landed 2026-09-23 (wave 56, w56d)

**Re-probe before the fix** (the pre-fix build, on the golden `tests/conformance/2002/pb349_sort_merge_flow_ec.cob`
with all three names under `>>TURN … CHECKING ON`): `MAIN-NOT-AT-END` / `R=AAA` / `R=BBB` / `AT-END` /
`SECOND-AT-END` / `AFTER-SORT N=2` — nothing raised, and worse than the note measured: MAIN's out-of-range RETURN
handed back the record the out-of-range RELEASE had stranded. **After:** `HANDLED=EC-FLOW-RELEASE` /
`HANDLED=EC-FLOW-RETURN` / `R=AAA` / `R=BBB` / `AT-END` / `HANDLED=EC-SORT-MERGE-RETURN` / `AFTER-SORT N=2`.

**Fix (the shape this note named):** `CobolSort.Store` carries the executing statement's procedure `Phase`
(`None`/`Input`/`Output`) and GR3's `AtEndReached` latch; the emitter renders `CobolSort.EnterProcedure` before the
INPUT PROCEDURE range (SORT) and the OUTPUT PROCEDURE range (SORT and MERGE), and `Sort` ends the input phase. The
program's RELEASE / RETURN statements render the new checked entries `ReleaseStatement` / `ReturnStatement`, which
test the phase BEFORE acting; the implicit USING release and GIVING return keep the unchecked `Release` / `Return`
primitives (each verb's GR1 governs the STATEMENT). The EC model's five declarations per name: `CheckingFlags`
fields, `ExceptionEngine` properties + `FatalIfEnabled` helpers, the static shims, three `FatalAmbientGates` rows,
and `QueryFor` arms for `BoundRelease` / `BoundReturn` — `ExceptionRaiseHelperDriftTests` pins the flag↔name pairing.
Checking OFF: nothing is raised (§14.6.13.1.1); per §14.6.13.1.3 item 8 the statement proceeds, except that a
RELEASE with no SORT executing now has no store to release to (it used to strand a record in a store only the next
`Init` cleared).

**Not in this landing:** EC-SORT-MERGE-ACTIVE (§14.9.40.4 GR10/GR13, §14.9.24.4 GR8), EC-SORT-MERGE-RELEASE,
EC-SORT-MERGE-SEQUENCE and EC-SORT-MERGE-FILE-OPEN remain catalogued with no raise site, as does the general
"every turnable name has a raise site" drift test — reported as leads (w56d report), not fixed here.
