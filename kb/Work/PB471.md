# PB471 — OPEN — a determination whose rule and whose list do not agree

Found 2026-09-04 by the `PB383` implementer alongside `kb/Work/PB470` (its report, §"New defects found outside
this item", finding 2). **Documentation precision only — no behaviour change is proposed here**, and the behaviour
is witnessed green by `conformance:2023/l1_formatted_date_integer_date_form` and
`conformance:2023/l1_fdt_argument2_integer_date_form`. It is filed because the row is meant to be a rule that
derives its own membership, and today it is a rule plus a list that contradict each other.

## The disagreement

`docs/CONFORMANCE.md` §7 row `DOC-A.1-90` closes with:

> And where the returned LENGTH is itself derived from the rejected argument — `FORMATTED-DATE`,
> `FORMATTED-DATETIME`, `FORMATTED-TIME`, `BASECONVERT`, and `BOOLEAN-OF-INTEGER` when it is **argument-2 itself**
> that is rejected … — it is a **zero-length value** … **The clause is a RULE, not a closed list:** any function
> whose returned length derives from the rejected argument is in the zero-length class.

`BOOLEAN-OF-INTEGER` is qualified — *"when it is argument-2 itself that is rejected"* — and the FORMATTED-\*
family is not, so it is in the class wholesale. But the family's returned length derives from **argument-1**:

```
python scripts/spec/cite.py --check 15.39.4 "The returned value is a representation of the date contained in argument-2 according to the format in argument-1."
OK  §15.39.4 1)  (Returned value rule)

python scripts/spec/cite.py --check 15.39.3 "The content of argument-1 shall be a date format."
OK  §15.39.3 2)  (Argument rules)
```

Argument-1 is the format and argument-2 is the integer date. When it is **argument-2** that is rejected —
`FUNCTION FORMATTED-DATE("YYYYMMDD", 0)`, which returns a zero-length value today — argument-1 is *valid*, and the
length the standard derives from it survives the rejection intact. **By the clause's own words that case is not in
the zero-length class**, while the list puts the whole family in it. The `BOOLEAN-OF-INTEGER` entry beside it
shows the row's author knew the distinction and applied it there and not here.

Code sites, re-read on this tree: `src/Cobol.Net.Runtime/Intrinsics/CobolDate.cs#FormattedDate` and
`#FormattedDatetime` — the `integerDate is < 1 or > 3067671` arms.

## Why it matters even though nothing is behaving wrongly

The row states in its own words that it is *"a RULE, not a closed list"*. A rule whose stated condition does not
select its own listed members cannot be applied to a function that is **not** listed — which is precisely the
failure `kb/Work/PB470` records for `LOCALE-DATE` / `LOCALE-TIME` / `LOCALE-TIME-FROM-SECONDS`, where the length
derives from the locale and neither the rule nor the list decides the case. The two notes are one wording problem
seen from two sides, and fixing PB470's determination without fixing this leaves the same ambiguity in place for
the next intrinsic.

## The fix is exactly one of two wordings, chosen so the rule derives its own list

* **(a) Widen the rule** to *"where no length survives the rejection"* — i.e. the returned length is derived from
  a rejected argument **or is otherwise undeterminable once the argument is rejected** — and then check every
  listed member against it. This keeps the FORMATTED-\* family in the class only if a reason is stated for why an
  argument-1-derived length does not survive an argument-2 rejection.
* **(b) Qualify the list** the way `BOOLEAN-OF-INTEGER` is already qualified — FORMATTED-\* in the zero-length
  class only when it is the **format argument** that is rejected — and give the argument-2 case the general
  clause's answer (spaces, of the argument-1-derived length).

Whichever is chosen, the outcome must be that **the list is derivable from the rule and is present only as
illustration**, and the goldens named above are re-read to confirm which arm they actually pin.
