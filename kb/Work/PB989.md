# PB989 — LANDED

## Landed (wave 1031, group F) — DESIGN-external-repository slice 6 (kb/Work PB2102)

**The mechanism, from the approved design (§8.2, §8.3, §12, §21 item 6).** The two order-blind group tables
(`BuildProgramDetailsTable`, keyed by externalized name; `BuildUserFunctionTable`, keyed by WORD) are DELETED. One class,
`src/Cobol.Net.Compiler/Binding/GroupRepository.cs`, holds the group's function units and outermost program units and
answers GR10 / GR11 through ONE search, `Find`: the first DEFINITION with the matching name that starts strictly BEFORE the
referencing source element (a), else the first PROTOTYPE definition with that name (b), else nothing (c, the external
repository, which does not exist yet). The position is `BoundUnit.SourcePosition` (the character offset of the unit's first
token; a class's own start for a REPOSITORY of a CLASS-ID) — "specified PREVIOUSLY" is a position, not a membership.
Both twins ask it: `ProgramDetails(externalized, position)` and `ResolveFunction(word, externalized, position)`.

**Externalized name, never word (inventory row GR-11.5.4-2).** §12.3.8.4 GR10 a) and GR11 a) say "the externalized name" three times; the function
table merged a prototype with a definition by WORD, so a definition that merely shared the prototype's word replaced it
and its `AS literal-1` was dropped (`FUNCTION-ID. FIDDEF AS "NOPE" IS PROTOTYPE` + a following `FIDDEF` that squares its
argument activated `FIDDEF`: `P=000049`; now the run ends in EC-FUNCTION-NOT-FOUND for 'NOPE', which the AS literal demands).

**D-R3 (design §8.3, owner decision 2026-10-05).** Step 1 is `Find` by externalized name (literal-5, or the name itself:
GR11 NOTE 2); step 2, when it misses, takes the function the WORD names (SR10, §8.4.6.7) — the previous definition of that
user-function-name, else the prototype of that name (the design names the definition; the prototype is the same word's
other legal SR10 alternative, and without it `FUNCTION F` naming only a prototype `F AS "G"` would be refused as
unresolved while the pre-slice code resolved it — the design text is corrected in the same change); step 3 — a hit by
step 1 while a DIFFERENT function carries the word — warns **COBOLNET2969** and the externalized name wins
(`FunctionWordNamesAnotherFunction`; design placeholder REPO-13). `DataBinder.FunctionSpecifiers` now carries a
`FunctionSpecifier(Name, ExternalizedName, At)`, the entry the warning is reported at. A function definition's own name is
always referable inside it (§8.4.6.6) and is registered by `UserFunctionsOf` whether or not a specifier writes it, because a
definition does not start strictly before itself.

**Consequence that is the fix.** A definition that FOLLOWS its caller and has no prototype ahead is neither a) nor b): a
function draws COBOLNET1505 at its use (it cannot be bound without its RETURNING description) and a program is the arm-c)
program with no compile-time signature (kb/Work PB1086; design slice 7 turns both into REPO-1). 26 corpus programs (25 positives, 1 negative), the
UdfInvocationTests sources, 1 OperandActivationDriftTests source and 2 version-matrix constructs had the function AFTER
the program that calls it; each now has it BEFORE (the compilation-group order of the standard's own examples: §D.6.1.1 starts
its group with `FUNCTION-ID. F-1`, and §D.6.1.3's factorial function precedes the programs that use it; both
`cite.py --find` OK) by moving whole units, never editing one (tests with a prototype ahead are untouched). The
9 goldens and 6 negatives that named a later PROGRAM definition (design §8.2's list, plus pb609 and l1c24, which the
design did not name and the temporary trace found) and `OptionalWordSubsetDriftTests`' pointer-usage program gained a
program prototype ahead of every other unit (10.6.2 SR1), keeping each test's subject under GR10 b).

**Goldens and tests.** `2002/pb989_function_prototype_externalized_name`, `2002/pb989_function_externalized_name_wins`,
`negative/pb989-function-definition-follows-the-specifier` (COBOLNET1505), `negative/pb989-call-previous-definition-

## Landing

  then b), as of a position; REUSE `ProgramDetails` / `ResolveFunction` / `FunctionsAt`, never walk `units` to match an
  externalized name. Trap: "previously" is `SourcePosition <` the element's position, so a definition is never previous
  to itself — `UserFunctionsOf` registers a function's own name unconditionally for that reason.

  the D-R3 steps live in `GroupRepository.ResolveFunction` and COBOLNET2969 is reported from `UserFunctionsOf` at the
  entry's own context (`FunctionSpecifier.At`). Trap that cost the most turns: the corpus idiom "program first,
  FUNCTION-ID after" (about 40 tests) is nonconforming under §12.3.8.3 SR10; a new UDF golden writes the function ahead

## The rule
`OK  §12.3.8.4 10) a)` — "if the externalized name of the program prototype is the externalized name of a program
definition specified previously in the same compilation group, the details are taken from that program definition …;
otherwise," b) takes them from a program-prototype definition in the group, then the external repository. GR11 a) is the
same sentence for function prototypes.

## Expected vs observed
A REPOSITORY `PROGRAM P` entry whose program definition comes LATER in the compilation group must take its details from
b)/c) (a prototype definition, or the repository), not from the later definition. The details tables are built once
over the whole group, order-blind.

## Code site
`BuildProgramDetailsTable` and the user-function details table (binder) — keyed by name only.

## What the fixer owes
Record each definition's position in the compilation group and resolve GR10/GR11 a) against definitions strictly
before the referencing source element; fall through to b)/c) otherwise. Measure with a two-program group where the
callee follows the caller and its USING list disagrees with a prototype definition that precedes both.
