# PB6360 — AcceptLoopAsync's accepted.Dispose() is not pinned by a test

**Sites:** `tests/WiseOwl.Cobol.Tests.Unit/SocketTransportTests.cs` (`SocketTransportTests.AnAcceptedSocketThatCannotBeAdoptedIsClosedAndLeavesTheServerAcceptingAndTheBellRinging`, `SocketTransportTests.DeliversAnUnadoptableSocketOnce`)

`AnAcceptedSocketThatCannotBeAdoptedIsClosedAndLeavesTheServerAcceptingAndTheBellRinging` captures the bell's unadoptable socket (`bellSocket`) and asserts its handle is closed, which witnesses the PB6218 `finally`. Its server half (line 310) calls `DeliversAnUnadoptableSocketOnce(serverDelivered.Set)` with no `deliveredSocket` callback and asserts only that the next connect is accepted. Nothing pins that the `catch` in `SocketTransport.AcceptLoopAsync` (`src/WiseOwl.Cobol.Runtime/Messaging/SocketTransport.cs:348`, `accepted.Dispose()`) closes the dropped socket, which the test name claims. The PB6218 report's sibling sweep says the server arm "is covered by the AcceptLoopAsync catch (PB6134)", but no assertion covers it: delete the dispose at line 348 and the test still passes (a reading of the test, not a run).

**Expected:** the server half captures its unadoptable socket the way the bell half does and asserts its handle is closed; remove the line-348 dispose, run the test, and record that it fails. No harm observed in the transport; the gap is test coverage.
