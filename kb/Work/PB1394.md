## Finding — `alphanumeric-literals` (under-rejects; rows `SR-8.3.3.2.3-5`)

**Mechanism.** HEX_BODY accepts only [0-9a-f]* between X" and the closer, so a Format 2 literal with a non-hexadecimal body (X"GG", X"4G") is not a HEXLIT: it silently re-lexes as IDENTIFIER `X` + a Format 1 STRINGLIT -- the same silent-split hole R03/PB59 closed for zero length and NX/BX. Where a data item named X exists the split is legal-looking and the program compiles and runs; elsewhere it dies on misleading generic diagnostics.

**Repro.** `01 X PIC X(3) VALUE "ZZZ".` + `DISPLAY X"GG".` -- compiles clean, prints ZZZGG (probe p8). Without an item X, `MOVE X"GG" TO W` draws only COBOL0301 'unexpected "GG". Missing space before string literal.' (p2/p9); `VALUE X"4G"` draws COBOLNET1639 'the VALUE operand X is not a literal' + COBOLNET1585 (p7).

**Expected from the spec.** "Hex-character-sequence-1 shall be composed of hexadecimal digits" (8.3.3.2.3 SR5); hexadecimal digit = 0-9, A-F with a-f equivalent (3.98). X" is an opening delimiter and a separator (8.3.5 rule 5: "the two contiguous characters B", B', N", N', X", and X'"), so X"GG" can only be a malformed hexadecimal-alphanumeric literal: every such source shall be rejected with a diagnostic naming SR5.

**Observed / reasoning.** Lexer HEX_BODY/HEXDIGITS in CobolLexer.g4 (the R03 comment says the grouping rule was moved to bind precisely so the lexer would not reintroduce the silent split -- the same reasoning applies to the digit repertoire: lex X"<any>" whole and have the binder/VersionConformancePass report SR5, as HexGroupViolation does for SR6). Sibling in the same mechanism, same fix: NX"<non-hex>" (8.3.3.5.3 SR4) and BX"<non-hex>" (8.3.3.4.3 SR3) share HEXDIGITS and fall back to IDENTIFIER NX/BX + STRINGLIT. Related separator hole (8.3.5 rule 5 -- opening delimiter shall be preceded by a space): `DISPLAY W"AB"` with an item W compiles and prints QQQAB (probe p13).

**Code site.** src/Cobol.Net.Frontend/Grammar/Core/CobolLexer.g4#HEX_BODY / HEXDIGITS (line ~886-895)

## Finding — `lexical-elements` (under-rejects; rows `SR-8.3.5-2`)

**Mechanism.** Bare comma / semicolon accepted as a separator: COMMA (',' not followed by a space) is admitted by ~12 `(COMMA? x)*` list rules, and SEMICOLON : ';' -> skip discards every semicolon regardless of what follows

**Repro.** PROCEDURE DIVISION. MOVE 1 TO N,M. MOVE 1 TO N;M. (N, M PIC 9(3); no DECIMAL-POINT IS COMMA) — compiles and runs, prints 001001

**Expected from the spec.** §8.3.5 2): comma and semicolon are separators only when 'immediately followed by a space'; 'N,M' and 'N;M' therefore contain no separator and are not valid COBOL words — a compile-time diagnostic.

**Observed / reasoning.** Accepted at every edition; the operand lists treat the bare comma as a separator. Sibling FUNCTION MAX(N,M) IS rejected (COBOL0001), so the two arms disagree. The lexer must distinguish a separator comma (COMMA_SEP) from a bare comma, which is legal only inside a DECIMAL-POINT IS COMMA numeric literal / PICTURE string; the list rules should not accept COMMA, and ';' not followed by a space needs a token and a diagnostic rather than skip.

**Code site.** src/Cobol.Net.Frontend/Grammar/Core/CobolLexer.g4#SEMICOLON, #COMMA; src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4:642,670; Core/CobolData.g4:774,833-835,887; Core/CobolExpressions.g4:620; Core/CobolIO.g4:332,338; Core/CobolReportWriter.g4:219-220

## Finding — `lexical-elements` (under-rejects; rows `SR-8.3.5-3`)

**Mechanism.** Separator period not required to be followed by a space: DOT : '.' matches any period, so 'N.DISPLAY' ends a sentence

**Repro.** PROCEDURE DIVISION. DISPLAY N.DISPLAY M. STOP RUN. — compiles, prints 005 and 007

**Expected from the spec.** §8.3.5 3): 'The COBOL character period, when followed by a space, is a separator.' A period not followed by a space is not a separator; 'N.DISPLAY' is not a valid character-string — a compile-time diagnostic.

**Observed / reasoning.** DEFAULT-mode DOT has no following-character condition (PICMODE handles picture periods separately). Accepted at all editions.

**Code site.** src/Cobol.Net.Frontend/Grammar/Core/CobolLexer.g4#DOT

## Finding — `lexical-elements` (under-rejects; rows `SR-8.3.5-5`)

**Mechanism.** Literal opening/closing delimiter adjacency not checked: no lexer rule or post-lex pass verifies that an opening delimiter is preceded by space / '(' / opening pseudo-text delimiter, or that a closing delimiter is followed by space, comma, semicolon, period, ')' or closing pseudo-text delimiter

**Repro.** DISPLAY "AB"N.  (prints AB005)   MOVE"AB" TO A.  (compiles)   IF "AB"=A DISPLAY "Y" END-IF.  (compiles)

**Expected from the spec.** §8.3.5 5): 'The opening delimiter shall be immediately preceded by a space, left parenthesis, or opening pseudo-text delimiter. The closing delimiter shall be immediately followed by one of the separators space, comma, semicolon, period, right parenthesis, or closing pseudo-text delimiter.' Each repro is a compile-time error.

**Observed / reasoning.** WS is skipped and STRINGLIT/HEXLIT/NATLIT/BOOLLIT are matched by maximal munch with no context check; the parser sees the same token run whether or not the separator is present. Some violations fail only by accident of the parse ("AB":N, MOVE"X"X"41").

**Code site.** src/Cobol.Net.Frontend/Grammar/Core/CobolLexer.g4#STRINGLIT, #HEXLIT, #NATLIT, #BOOLLIT (STR_BODY/HEX_BODY/NAT_BODY/BOOL_BODY)

## Measured (rows this note claims beyond the findings above)

### `SR-8.3.3.4.3-2` — PARTIAL (adjudicator + refuter record, verbatim)

'Boolean-character-1 shall be a boolean character, '0' or '1', from the computer's coded character set' (cite.py --check 8.3.3.4.3 SR2 OK). Enforced lexically: Format 1 admits only [01]*. B"012" does not form a BOOLLIT; it lexes as IDENTIFIER B + STRINGLIT and is rejected: probe bl2 MOVE B"012" TO B1 -> COBOL0301 unexpected '"012"'; bl3b VALUE B"12" -> COBOLNET1639/1585. Rejected in both divisions (no silent split), though the diagnostic does not name SR2 (message quality only). No spec-derived negative test pins it -> test-ref empty. || REFUTED: PARTIAL — The rule is enforced only where the parser happens to reject the split. The lexer does not form BOOLLIT for B"012" and falls back to IDENTIFIER B + STRINGLIT "012". §8.3.5 r5 makes B" itself an opening delimiter, and an opening quote must be immediately preceded by a space, left parenthesis or pseudo-text delimiter. When a data item named B exists, DISPLAY B"012" compiles and runs silently as B followed by "012". The adjudicator's 'no silent split' claim is false. B"""" (content = an embedded quote, not '0'/'1') is also accepted silently as B"" followed by "" with no separator. MOVE B"2" TO A is rejected (COBOL0301 'Missing space before string literal'), so the separator check exists but is not applied in every statement.

### `SR-8.3.3.4.3-3` — PARTIAL (adjudicator + refuter record, verbatim)

'Hexadecimal-digit-1 shall be a hexadecimal digit' plus NOTE 'Hexadecimal-boolean literals can be of zero length' (cite.py --check 8.3.3.4.3 SR3 OK). HEXDIGITS=[0-9a-f]* case-insensitive: probe bl3 MOVE BX"G1" TO B1 -> COBOL0301 rejected; NOTE half: BX""/BX'' accepted (bl12). No grouping rule is imposed on BX (HexGroupViolation returns null for BX; BX"5"/BX"5AB" legal, r03 rows 11-12) - correct, SR3 states none. No spec-derived negative test for a non-hex digit -> test-ref empty. || REFUTED: PARTIAL — The rule has two halves. The zero-length NOTE half holds (BX""/BX'' accepted). The 'shall be a hexadecimal digit' half is enforced only by accident of the parse. BX"G1" does not form BOOLLIT and falls back to IDENTIFIER BX + STRINGLIT "G1". §8.3.5 r5 names BX" as a three-character opening delimiter. With a data item named BX in scope, DISPLAY BX"G1" compiles silently and prints the item followed by G1. The earlier probe bl3 (MOVE BX"G1" TO B1, no BX item) was rejected only because the MOVE parse failed.

## What the fixer owes

One post-lex separator pass (or lexer actions) enforcing §8.3.5 rules 2/3/5 over the token stream: comma/semicolon/period followed by a space (or end of line), an opening literal delimiter (" ' X" N" NX" B" BX" …) preceded by a space, '(' or pseudo-text delimiter, a closing delimiter followed by a separator. The prefix-literal split (IDENTIFIER X immediately followed by STRINGLIT) is the same missing check: R03/PB59 closed it for zero length and NX/BX only. Note the check already exists in ONE place (COBOL0301 'Missing space before string literal' on MOVE B"2" TO A) — find it and make it the one mechanism. Negative goldens per delimiter family; the positive corpus must stay green (NIST uses `,` and `;` heavily).
