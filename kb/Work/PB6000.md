# PB6000 - the spaced sub-item designator `SR<n> <x>)` outside the five files PB5997 fixed

A citation of a lettered sub-item of a syntax rule is written `§<edition>:<clause> SR<n><x>` (`SR1b`): that is the form
`scripts/spec/citation.py` parses and `scripts/spec/cite.py --check` validates, sub-item included (kb/Work PB4887, PB5317).
Lead 5 of the PB5997 train rewrote `SR1 b)` as `SR1b)` in the five files it named (DataBinder.cs, InheritedGlobals.cs,
LinkageBinder.cs, SymbolTable.Declarations.cs, StatementValidation.cs, two diagnostic strings among them). The same spaced
spelling stands at the sites below: compiler and runtime comments, diagnostic message text (DiagnosticCatalog.cs and the
runtime's ObjectReferenceSet.cs messages, which drift tests and goldens pin, so the message, its drift test and its golden
change together), test comments, conformance-case comments and golden texts, design docs and note bodies. A spaced
designator is not a citation cite.py reads, so none of these is checked.

**Fix:** rewrite each as `SR<n><x>`, run `cite.py --check` on each distinct citation (an inherited clause number is re-derived,
CLAUDE.md rule 1), and update the drift tests and goldens that pin a changed message. Add a tree audit refusing the spaced
form so it does not return. `DEVLOG/` is history and is left as written (8 entries); a kb/Work note body is changed by its
own owner or in a dated addendum (CLAUDE.md rule 8).
