# PB3743 — an interrupted stamp's staged index blocks the next land's merge

**Sites:** `scripts/orchestrator/enqueue.py#land`, `scripts/orchestrator/enqueue.py#merge_main`, `scripts/devlog.py#stamp`.

PB3367's stamp fix completes an interrupted stamp on the rerun. A stamp killed before its commit leaves the entry and the removal of the `pending-` file STAGED. `land` lets those paths past its dirty check, then runs `merge_main` (before the stamp); git refuses a non-fast-forward merge with a dirty index, so when main has moved the rerun does not complete the stamp. The self-tests plant only the pre-fix UNSTAGED shape.

Fix: complete the stamp (commit the staged entry) before `merge_main`, or have `merge_main` start from a clean index by committing the recognised stamp paths first; add a self-test that plants the STAGED shape with main moved.

(2026-10-25, review R1-1, severity low.)
