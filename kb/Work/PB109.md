# PB109 — LANDED 2026-08-19 (DEVLOG 1336) — `IF X IS alphabet-name` (§8.8.4.4.4 GR3 a) was a loud staged value

> ✅ **As built:** `BoundCodedSetClassCondition(operand, kind, not)` — the binder maps the alphabet's phrase to
> the membership KIND per Table 6 + the `CodedCharacterSet` determinations (STANDARD-1/2 → Ascii, the 128
> ISO 646 IRV characters; UCS-4/UTF-8 → ScalarValues, well-formed UTF-16; NATIVE / UTF-16 / a literal-phrase
> alphabet → AllNative — GR7 k4 puts EVERY native character in a literal alphabet's set, so the test is true
> for any content, deliberately) — rendered as `CobolClass.IsInCodedSet(s, kind)` (zero-length false per GR1;
> NOT per GR2); SR3's usage screen rides the existing class-condition operand check. Golden
> `2023/pb109_class_condition_alphabet`; `CodedCharacterSetTests.IsInCodedSet_ThreeKinds`; the
> `GR-8.8.4.4.4-3` row is PARTIAL on the float items g)–m) alone now (no binder arm — loud, registered fact,
> not this note's scope).

> ⚙ **flags:** crashes (a LOUD `NotImplementedCobolFeatureException` at the condition's first evaluation — the program
> compiles clean) · found 2026-08-19 while landing [[PB64]] T5 (the LOCALE-alphabet refusal of §8.8.4.4.3 SR2,
> COBOLNET1669, sits on the SAME arm and made the missing sibling visible) · inventory row `GR-8.8.4.4.4-3` is
> PARTIAL on this item alone.

**Spec:** §8.8.4.4.2 format 1 — `identifier-1 IS [NOT] { NUMERIC | ALPHABETIC | ALPHABETIC-LOWER | ALPHABETIC-UPPER |
BOOLEAN | class-name-1 | alphabet-name-1 | … }`; §8.8.4.4.4 GR3 a) (`--check` OK: "If alphabet-name-1 is specified,
the condition is true if the content of the data item referenced by identifier-1 consists entirely of characters in the
coded character set identified by alphabet-name-1 in the SPECIAL-NAMES paragraph"); §8.8.4.4.3 SR2 (`--check` OK:
"Alphabet-name-1 shall not reference an alphabet associated with a locale" — LANDED, PB64 T5, COBOLNET1669) and SR3
(the usage-display/national operand rule — the existing `CheckClassConditionOperand` arm covers the keyword classes,
not this one); §12.3.7.4 GR7 / Table 6 for WHICH coded character set each alphabet phrase identifies (NATIVE,
STANDARD-1, STANDARD-2, UCS-4, UTF-8, UTF-16 — and the literal phrase, which defines a collating sequence over the
native set).

**Measured** (`--std 2023`, `scratchpad/probe109.cob`):
```
       SPECIAL-NAMES. ALPHABET STD IS STANDARD-1.
           IF X IS STD DISPLAY "STD=yes" ELSE DISPLAY "STD=no" END-IF
   -> compiles clean; at run time:
      Unhandled exception. CobolNet.Runtime.NotImplementedCobolFeatureException: ... class condition 'STD'
```

**Mechanism:** `ConditionBinder.BindComparison` — the `cmp.className()` arm handles the four keyword classes, the SR2
LOCALE-alphabet refusal (`ctx.Data.IsLocaleAlphabet`) and a SPECIAL-NAMES `CLASS` name (`UserClasses`), then falls to
`new BoundConditionError($"class condition '…'")`, which `ConditionRenderer` renders as `EmitText.LoudValue("bool",
…)` — the staged-loud posture (COBOLNET0899 band at run time), so the defect is LOUD and cannot produce a wrong
answer. `Alphabets` / `NationalAlphabets` carry `AlphabetDef.Phrase` ("NATIVE", "LOCALE", a literal …), so the
binder CAN tell which coded character set a name identifies; nothing consumes that for a class test.

**Fix shape:** a `BoundCodedSetClassCondition(operand, set, not)` whose set is derived from the alphabet's phrase per
Table 6 — STANDARD-1 = ISO/IEC 646 (the 128 ASCII code points), STANDARD-2 = ISO/IEC 646 IRV, NATIVE / a literal
phrase = the native coded character set (every UTF-16 code unit under the D-N1 substrate — the test is then TRUE
for any well-formed content, which is correct and worth a comment), UTF-8 / UTF-16 / UCS-4 = every well-formed
scalar value (the national set) — rendered as one runtime predicate `CobolClass.IsInCodedCharacterSet(s, set)`;
SR3 enforced through the existing `CheckClassConditionOperand` arm (kind 'S'); a golden over STANDARD-1 with an
accented operand (false) and a plain one (true), plus the NOT form; inventory `GR-8.8.4.4.4-3` re-adjudicated.
