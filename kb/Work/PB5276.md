# PB5276 - at --std 85 two GIVING files of one SORT may be named in one SAME RECORD AREA clause: SortBinder.ScreenSameClauses reads 1985 SR9's "the same SAME clause" as the 2023 SAME AREA only

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/SortBinder.cs` (`ScreenSameClauses`)

**Mechanism.** §1985:XI.4.4.3 SR9: "File-names associated with the GIVING phrase may not be specified in the same SAME clause", and the 1985 SAME clause it refers to is `SAME [ RECORD ] AREA` (§1985:VII.2.13.2). `SortBinder.ScreenSameClauses` refuses GIVING files only in a SAME AREA clause (the 2023 form), with no edition arm, so a SAME RECORD AREA naming two GIVING files compiles at 85. MERGE's §1985:XI.4.1.3 SR8, by contrast, lets GIVING files share a SAME RECORD AREA, so the arm is SORT-only.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids below. None of them is recorded: the non-conforming verdicts wait in `E:/COBOL-coord/scratch/coderead-85/p2-for-register.json`.
