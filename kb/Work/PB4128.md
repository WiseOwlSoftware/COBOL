# PB4128 — stale line-number citations in older inventory notes (`File.cs

**Sites:** `tests/version-matrix/traceability-inventory.json` (rows whose notes cite `File.cs:NNN` line ranges), `tests/WiseOwl.Cobol.Tests.Unit/SpecTraceabilityInventoryDriftTests.cs` (`SpecTraceabilityInventoryDriftTests.NoRowsProse_NamesAGrammarRule_ARetirementRecordsAsDeleted`).

LEAD carried from PB3848's implementer ("Not fixed; note-ready if the owner wants it, sharing PB3848's root"). PB3848 made the
inventory's prose follow the deleted grammar names mechanically (the drift test reads the rows' retirement marks). A citation of the
form `File.cs:NNN` (a line range) rots the same way but one kind down: a line number names no symbol, so no resolver can tell whether
it still points at what the row means.

**Measurement owed (kind analysis):** count the rows whose prose carries a `path:NNN` citation, and for a sample check how many still
point at the cited construct. If rot is common the fix is a structure (rows cite `path#Member`, resolved by `source_units.py`, as R3
notes already do) with a drift test that fails on a `path:NNN` in a row's prose, never a hand-maintained list.
