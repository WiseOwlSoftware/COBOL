# PB4948 - a qualified, reference-modified VALIDATE operand escapes SR1

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/DeclinedFacilityBinder.cs` (`DeclinedFacilityBinder.ScreenValidateOperand`), `src/WiseOwl.Cobol.Frontend/Cst/DataReferenceCst.cs` (`DataReferenceCst.IsReferenceModified`, the one reader), `src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs` (`VisitUnstringStatement`)

**Probe** (E:/COBOL-coord/scratch/analyses-audit/probes/PB4248/val.cob and val.out):
- `VALIDATE X OF G (1:3).` gets only the COBOL1580 facility warning; no SR1 error.
- `VALIDATE X (1:3).` gets `error COBOL4777 ... shall not be reference-modified ...` (the message names SR1 of §2023:14.9.50.3).

§2023:14.9.50.3 SR1: "Identifier-1 shall not be reference-modified." One violation is refused in one spelling and accepted
in the other.

**Cause.** `qualification : (OF | IN) cobolWord (subscriptPart | refModPart)*` (CobolParserCore.g4:756-758, PB4248's second
tree shape) makes the `(1:3)` of `X OF G (1:3)` a child of the qualification. `ScreenValidateOperand` (line 42) tests only
`dref.dataReferenceSuffix()`; the next check returns early for a reference-modified place with the comment "SR1 spoke
above", but SR1 never reported. Every other reader checks both shapes (ReferenceResolver.cs:508-513, RefModBinder.cs:358-362,
FlagConformancePass.cs:645-646, VersionConformancePass.cs:955 and 984, ProcedureTableBuilder.cs:809-810); the audit's sweep
found no other flat-only reader that misses it.

**Caveat.** PB3593 argues a declined facility's syntax rules need not be diagnosed. The compiler enforces SR1 today, so this
is an inconsistent under-rejection inside an enforced rule; if PB3593's resolution withdraws the SR1 screen, this note
retires with it. Check the citation with `scripts/spec/cite.py --check`.
