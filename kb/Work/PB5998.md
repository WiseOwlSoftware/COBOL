**What the pilot found** (kb/Work PB5452, 2026-11-21, `E:/COBOL-coord/scratch/pb5452/campaign.md`):

1. **A numbered list printed one item per line is one unit.** `text_units.segment` started a numbered item only on a
   fresh candidate (after a blank line). The 1985 transcription prints §1985:IV.4.2.2.1.1's two lists as the PDF does
   (page 152), one item per line with no blank line between, so each list became ONE unit labelled `1` holding all its
   items: all 15 numbered-item units of the 1985 catalog's 956 hold a whole list. And two lists in one clause both took
   the printed numbers of their items, so §1985:IV.4.2.2.1.1's two lists and §1985:X.1.3.8's five each produced the
   label `1` more than once: their row ids (`1985-SR-IV.4.2.2.1.1-1`) would collide at the mint.
2. **A table continued across pages restarts its row ids.** §1989:A.2.4's Table 1 prints on three pages, each page
   repeating the header, so the segmentation read three tables all numbered 1 and `T1.1` to `T1.15` occur up to three
   times. The 2002 text has the same shape three times (§2002:14.4 Table 13, §2002:14.5.12.1.5 Table 14, §2002:15.5
   Table 22).
3. **The cross-reference test cannot read 1985's pointer.** The 1985 text points by folio ("(See page VI-13, The
   SPECIAL-NAMES Paragraph.)", about 540 times). `text_units.POINTER` reads only `See <locator>` with a locator in
   `citation.universe(1985)`, so every pure 1985 pointer fails the `cross-reference` class test and could never be
   disposed `not-a-rule`.

**Fix.** At the root, in the one segmentation and the one test: a numbered item starts at its own marker (a fresh
candidate, or the next number of the open list); each list of a clause is numbered, its items labelled by printed
number in the first list and `L<m>.<n>` in the m-th, the form numbered rule lists already have (PB5448 addendum); a
table fragment with the number and header of a table already read continues it, its rows numbered on; `segment` refuses
a clause whose units share a label; and the pointer grammar reads `page <folio>, <title>` (one or more), a folio
resolving when the page exists and its text prints the title. Row-neutral for these three: every rules array regenerated byte-identical.

**Added to the same landing (the coordinator, 2026-11-21): the 72 unread 1985 paragraphs.** PB5449's second landing left
72 paragraphs after a rule unread (9 ambiguous, 63 not found). Each was read on its rendered page
(`E:/COBOL-coord/scratch/pb5452/margins/decisions.json`: 60 continuations, 4 at level 0, 8 no paragraph), and each
cause is fixed at its root:

4. **Two page-furniture strippers had drifted.** `parse` ended a printed page at a folio and resumed one after a
   reconstruction; `_bodies` did neither, and began each region's walk without the page state, so a running header after
   a folio inside a page (`Report Writer - Body Group Presentation Rules`, folio XIII-32), after a reconstruction
   (`Report Writer - TYPE`) or on the `## Page 529` line a region after the repeated pages 527-528 opens with was read as
   a paragraph of the rule above it. `rule_catalog_1985.furniture` is now the ONE reading, made once over the whole
   transcription; both read it (CLAUDE.md rule 4).
5. **A sentence broken inside a parenthesis across a page** (§1985:VI.4.5.4 rule (3), "(see page VI-127," / "The SET
   Statement). ...") was cut, because the join took only a lowercase or continuation-word opening: `continues` now also
   joins after a unit whose parenthesis is open (a trailing comma alone is not enough: 2023 Annex B.3's data lines end
   in one at each wrap).
6. **Two transcription markup slips**: page 599's running header wrapped in `<p>` (which `running_header` refuses), and
   Figure 4's caption wrapped onto a line opening with a parenthesis (page 298). Pure markup, so no correction note.
   The header had been the last line of `1985-GR-XIII.3.7.4-4`'s text; that row was decided again against its corrected
   text (the KEPT chain to GR-13.18.16.4-2 restated), and its stored code read is stale until read again (code reads:
   1 KEPT row owed a read, 0 before).
7. **The measurer's band and match**: the 60 pt head band dropped a page's first body line (1985 prints it from 41 pt:
   `HEAD_Y_OF`, 40 for 1985; 2023's sublist measurement keeps 60), and the first fuzzy match was taken where a sibling's
   near-identical line also matched (`best`: highest ratio, then most characters compared). 16 of the 72 now measure,
   each as the page reading says.
8. **The other 48 are readings**, recorded by hand in `scripts/spec/data/margin-readings-1985.json` with page and
   evidence; `--write` carries each into the data (`level` 0 or `continues the rule (read on the page)`, `read_on_page`)
   and refuses a reading the measurement now places or no paragraph has; `--check` refuses a reading the data does not
   carry. The 1985 data records 373 paragraphs, 52 at level 0, none unread.
