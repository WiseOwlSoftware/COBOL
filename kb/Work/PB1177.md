# PB1177 — LANDED

## Landed (wave 1084, group F)

**Re-probe (this worktree's build, before the fix).** The arm the note left unverified diverged: a USE procedure
invoked by an EXPLICIT statement of the procedure, ending in RESUME AT NEXT STATEMENT, let the SORT run on — an
`OPEN` of a missing file in the input procedure printed `DECL-RAN 35 / IN-AFTER-OPEN / SORTED=A / SORTED=B /
AFTER-SORT`; the same in the output procedure printed the procedure's remaining RETURN; PB1036's widening (a RETURN in
the input procedure raising EC-SORT-MERGE-ACTIVE, its declarative RESUMEing) printed `IN-AFTER-RETURN` and both
records. RESUME AT procedure-name transferred inside the procedure's nested dispatch, so the SORT stayed active under
the rest of the program, and a later SORT with EC-SORT-MERGE-ACTIVE checking on was refused (its `SORTED=Z`
vanished). Hence `wrong_answer: true`.

**Determination** (`docs/CONFORMANCE.md` §3): GR17 governs. A USE procedure an explicit statement of the input or
output procedure invokes is in that procedure's range (§14.9.40.4 GR10, GR13: `OK §14.9.40.4 10)`, `13)`), so it is
"invoked while a format 1 SORT statement is active"; terminating the SORT ends the procedure with it, and §14.9.33.4
GR2 a)'s "unless general rules associated with the applicable statement specify otherwise" yields to it — RESUME AT
NEXT STATEMENT and a not-normal fall-off land after the SORT, as for the implicit transfers; RESUME AT procedure-name
is a GO TO (GR3) taken after the SORT has ended. MERGE's rules (§14.9.24.4) carry no such sentence: its output procedure's statement is
its own applicable statement, and the MERGE continues.

**Fix — one run-time mechanism for every USE procedure the rule reaches.** Every format 1 SORT registers itself as
the run unit's active format 1 SORT first in its body, with its scope's `__useActive` or null
(`CobolSort.RegisterFormat1Sort`; `EcEmitter.SortUseScope`); the generated `__RunUse` of every EC-model element
(`DispatchEmitter.EmitRunUseBody`) hands every DECLARATIVE's action to `CobolSort.AfterUseProcedure`, which throws
`SortTerminationSignal` for the innermost active format 1 SORT when the completion was not normal
(`DispatchResult.CompletedNotNormally`) — carrying the action for the SORT's own declaratives, `NotNormal` for another
element's; `SortEmitter.TerminationLanding`'s `catch` ends the statement after its `finally`.

**Review finding R1-1 (w1084f-review-r1) — widened to every element's USE procedure.** The first landing matched the
declarative's scope against the SORT's own, so a USE procedure of a program CALLed from the range (reviewer probe:
