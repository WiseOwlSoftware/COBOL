# PB1932 — OPEN

Filed by the train-1005 lander from wave 1005 group C's report (`w1005c-PB1423-report.md`, lead 4). No repro yet.

## The defect

§8.4.3.2.4 GR2: a function's arguments "are evaluated individually in the order specified in the list of arguments,
from left to right" (`cite.py --check 8.4.3.2.4 "from left to right"` → `OK §8.4.3.2.4 2)`). PB1423 made the
user-function and intrinsic arguments obey it through `ArgumentOrder`. An object property used as a sending item is
temp-1, "determined as though the associated get property method were invoked" (§8.4.3.9.4 GR1), but its GET is
drained by the OUTER property-op wrap (`OoPendingPropertyOps`, `OoBinder.OoWrapPropertyOps`) ahead of every pre-op of
the statement. So in `FUNCTION F(A, P OF OBJ)` a GET that changes A is seen by the first argument, which is evaluated
before the property under GR2.

**Repro to write.** A class whose property GET adds 1 to a working-storage item that the same statement also passes as
an earlier argument of a user function; expected: the earlier argument reads the value before the GET.

**Sites.** `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/UdfBinder.cs#UdfWrapCalls`,
`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/OoBinder.cs#OoWrapPropertyOps`,
`src/Cobol.Net.Compiler/Binding/Procedure/ArgumentOrder.cs` (the window a property GET should register in).
