# PB4493 - two descriptor registries

**Defect.** `src/WiseOwl.Cobol.Frontend/Diagnostics/DiagnosticDescriptors.cs` (`DiagnosticDescriptors`) holds the frontend's
descriptors: the generic parse error COBOL0001, the parser's syntax hints COBOL0100-0313 (chosen in `CobolErrorStrategy`), the
parse-layer twins of catalogue descriptors and the COPY errors CBL3620-3622. Every other diagnostic is a `DiagnosticCatalog`
descriptor. PB4463 made the catalogue the one registry (no `"COBOLnnnn"` literal anywhere in `src/`) and the drift fact
`DiagnosticRegistryDriftTests` (`CodeLiteralFiles`) allow-lists this file, with its header as the reason. A code owned by this file
has no catalogue rule text, no suppress key and no ISO reference, the failure PB914 and PB2023 named for the OO codes, and cannot
appear in the generated diagnostics document by the catalogue's route.

**Fix direction.** Decide the layering: `Frontend` cannot reference `Editions` today, which is why the file exists. Either move the
descriptor records and the 0001-0313 band into the catalogue's assembly with the frontend reading them through the dependency it
already has, or state in `docs/DESIGN.md` why a layer below the catalogue owns its own band and have the drift test check that band
against the catalogue (a code in both is the drift). The twins already take their code from the catalogue descriptor; the hint band
and the CBL codes are the open part. One registry, or two with a stated boundary and a test that holds it.

**Sites:** `src/WiseOwl.Cobol.Frontend/Diagnostics/DiagnosticDescriptors.cs` (`DiagnosticDescriptors`), `tests/WiseOwl.Cobol.Tests.Unit/DiagnosticRegistryDriftTests.cs` (`DiagnosticRegistryDriftTests.CodeLiteralFiles`).
