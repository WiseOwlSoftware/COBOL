# PB3023 — landing is a deterministic script; agents only resolve conflicts and bounces

**Owner decisions 2026-10-11 (kb/Work PB3015):** Q1b "GitHub merge queue (Recommended)"; Q3 "One PR per finished branch
(Recommended)": every finished implementer branch is its own pull request; the loop reviews it, rebases it, runs the
targeted local gate, verifies its DEVLOG entry file and enqueues it; GitHub tests the queued pull requests together and
lands them in order; a CI red bounces one branch to a finisher while the others land.

replaces the hand steps with `enqueue.py`; PB3016 closes with it. **PB3024 phase 1 landed `enqueue.py` with its tail half** (wave 1062 C): `queue` = the queue guard (exit 8 unless `ruleset.py check` is ACTIVE), `checks` (devlog 6, oracle 7, landing_check 3, unreadable 2), push, open-or-reuse the PR, `gh pr merge --auto` (exit 9 on a GitHub refusal); this note ADDS the fetch/rebase (choose a rebase-conflict code other than 3, which is the landing check STOP), the gate under a slot (exit 5) and `devlog.py stamp` to it, and must keep the guard first (LandingPipelineDriftTests).
