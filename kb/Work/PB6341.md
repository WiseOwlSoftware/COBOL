# PB6341 — RETIRED — the VALUE literal reaches the rolled-value reader already normalized

## Retired (wave 20262177, group J)

The note's scenario (`05 X COLUMN 10 PIC 9,9 VALUE 1,5.` under DECIMAL-POINT IS COMMA, summed by `SUM X`) cannot be written: a numeric-edited entry is no `SUM` addend (§2023:13.18.54.3 SR4, COBOL2730). With a numeric picture the same literal is accepted and summed correctly on the unchanged tree: `05 X COLUMN 1 PIC 9V9 VALUE 1,5.` and `05 Y COLUMN 5 PIC 9V99 VALUE 2,25.` under `SUM X Y` print `15  225` and `0375` (1.5 + 2.25 = 3.75), at `--std 2002` and `--std 2023`. The note's "raw text is stored unnormalized" is wrong: `DataBinder.RawValueOperandText` returns `SpecialNames.NormalizeIfNumericLiteral(op.GetText())` (the comma becomes the dot, `NumericLiteral.Normalize`, the one normalizer, since commit 7e0598be1b), and the report entry's `ValueRaws` are that text, so `ReportWriterBinder.RawNumber` filters an already canonical literal. A floating-point VALUE is not admitted on a report entry (COBOL2198, §2023:13.18.60.3 SR7), so no form is lost to the character filter. The golden `13.18.54-SUM/pb6341_report_rolled_value_decimal_point_comma` pins the behaviour.
