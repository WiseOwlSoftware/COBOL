# PB5176 - at --std 85 (and every edition) MOVE of a figurative constant or an ALL literal to a noninteger numeric or a numeric edited item fills the image by position: ALL 12 into PIC 9(3)V99 holds 121.21 and into PIC 9(3).99 holds 121212, with no decimal point and no editing

**Sites:**

- `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/MoveEmitter.cs` (`ConvertSource`, `AllLiteralNumber`, `IsNumericOperand`, `FigurativeToNumericImageStore`)

**Mechanism.** 1985 moves a figurative constant as if it were the literal it stands for (§1985:IV.4.2.2.2.3; §1985:VI.6.19.4 GR4 b: alignment by decimal point, zero filling, editing), and still admits ALL literal with a numeric or numeric edited receiver (§1985:IV.4.2.2.2.3 SRL3.2, an obsolete element). `MoveEmitter.ConvertSource` returns the repeated characters as the receiver's image for any figurative source whose receiver is not of category numeric, and `AllDigitFill` repeats the digits over a numeric receiver's positions at its own scale. For an integer numeric receiver that equals the rule; for a noninteger receiver the digits land in the fraction (121.21), and for a numeric edited receiver the image is never edited (121212 in PIC 9(3).99, 555555 for ALL 5 in an edited item). kb/Work PB426 (landed) recorded the positional fill as the 2023 reading; whether 2023 differs is that note's question, and 1985 is unambiguous.

**Found by.** The 1985 code read (2026-11-10; its records are `E:/COBOL-coord/scratch/coderead-85/for-register.json`): each rule below was read against the code sites it names and probed at `--std 85`, and found non-conforming. Verdict, harm, evidence, repro and observed text are the records'; the rows' verdicts are recorded on another branch.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids of the list below.

**Expected (from the 1985 text, the record's).** 555.00 / 555.00 / 555.00 / 555.00. §1985:IV.4.2.2.2.3: 'the string of characters specified by the figurative constant is repeated character by character on the right until the size of the resultant string is greater than or equal to the number of character positions in the associated data item' (55555, and 555555 for the edited item); §1985:VI.6.19.4 GR4 b: 'alignment by decimal point and any necessary zero filling takes place as previously defined except where zeros are replaced because of editing requirements' and 3) 'When the sending operand is described as being alphanumeric, data is moved as if the sending operand were described as an unsigned numeric integer'. The integer 55555 in a 9(3)V99 item is 555.00, and 555555 edited into ZZ9.99 is 555.00.

**Observed (the record's).** 555.55 / 555.00 / 555555 / 555.00 (exit 0, no diagnostic): the figurative fills the digit positions of the noninteger item and the whole image of the edited item; the literal and the data item of the same characters are moved as the rule says. MOVE LOW-VALUES TO a PIC S9(4) COMP item compiles with no diagnostic and ends the run with an unhandled NotImplementedCobolFeatureException ('MOVE of an alphanumeric figurative constant ... into the numeric item C4 without image-backed storage'), exit 127.

**Fix direction (root cause, CLAUDE.md rule 4).** Route a figurative constant to a numeric or numeric edited receiver through the one numeric MOVE path, as a literal of the receiver's size aligned at the decimal point and then edited, instead of the image store; keep the positional fill only where the edition's rule requires it, decided in one place in ConvertSource.
