# PB5975 - cross-program name resolution is still per class

PB5973's note decided the shape (CLAUDE.md rule 5): resolve a reference in a contained program over GR1's set, B's own
condition-, data-, file-, record- and report-names and sum counters plus the containers' GLOBAL ones, apply qualification over
that set, then GR2 and GR3 by declaring depth, so a new class pair needs no code. The landing fixed every probed outcome by
teaching each class's path to ask the other classes' "declared nearer" predicates instead. The review's R1-1 (a hidden GLOBAL
report-name or file-name could not qualify LINE-COUNTER, PAGE-COUNTER or LINAGE-COUNTER) was one more class path that applied
hiding before qualification; it was fixed with `NameReach.Qualifier`. The next class pair will need the same hand edit.

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/SymbolTable/SymbolTable.cs:126` (`SymbolTable.NearestDeclaringData`), `src/WiseOwl.Cobol.Compiler/Binding/SymbolTable/SymbolTable.Declarations.cs:205` (`SymbolTable.Declarations.DeclaredNearerThan`), `src/WiseOwl.Cobol.Compiler/Binding/SymbolTable/SymbolTable.Reports.cs:174` (`SymbolTable.ReportSymbolNamed`, `SymbolTable.ReportNameDeclaredNearerThan`)

## Fix shape
One resolver over GR1's set, qualification first, GR2/GR3 by depth; the per-class predicates and `NameReach.Qualifier` fold
into it. Behavior-neutral: the PB5973 goldens (`pb5973-*-85`) and the class-pair matrix the PB5973 note describes are its
oracle.
