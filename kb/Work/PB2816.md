## As filed (OPEN before the fold)

# PB2816 — nothing re-arms or reports the mailbox inbox watcher after a CLI restart

Severity MINOR: no wrong output; a 100-minute coordination delay with quota idle on both accounts.

## Found by

The Mythos session on 2026-10-08 (the owner's 15:05 "coordinate with the operator session"; the operator's 16:47 answer:
"my inbox watcher was not armed after my 00:20 and 14:50 restarts").

## Evidence

`E:\COBOL-coord\mailbox\README.md` makes each session's `until ls <inbox>/*.json; do sleep 10; done` background task the
ONLY wake-up (the ListAgents doorbell is per config dir, so it cannot cross the two lanes). The task dies with the CLI
(every restart: 23:45, 00:20, 14:50, 14:53, 14:55); `session-probe.ps1` and `scripts/hooks/tooling_check.py` print nothing
about the inbox, so a restarted session does not know messages wait. At 15:00 the operator inbox held four `publish`
messages from the loop (04:59, 05:50, 12:09, 13:12) and one `info` (14:53) untaken; the Mythos session's own watcher died at
its 14:55 restart.

## Sites

`E:\COBOL-coord\mailbox\README.md` (the wake-up protocol), `scripts/orchestrator/mailbox.py` (`watch` exists, PB2482, but
nothing starts it), `scripts/session-probe.ps1` and `scripts/hooks/tooling_check.py` (no inbox line), the memory note
`two-sessions-2026-10-07` (the hand protocol).

## Fix shape

(a) The SessionStart hook / `tooling_check.py` prints an `INBOX` line for this lane (`mailbox.py list --inbox <lane>
--json`: count untaken, oldest age) and marks it `ASK-OWNER`-grade when a message is older than the digest cadence, so a
restarted session cannot miss it; (b) the first act after the probe is `mailbox.py watch` in the background, written into
the README and both sessions' resume notes; (c) `mailbox.py send` warns the sender when the peer inbox already holds
untaken messages older than 30 minutes (the peer is probably not watching). Related: PB2482 (mailbox.py), PB2778 (watcher
lifetime inside a loop unit).

## Test

`scripts/hooks/test_tooling_check.py` (or the probe's self-test) pins the INBOX line: with two files in the lane's inbox the
hook prints their count and the oldest age; with none it prints `INBOX: empty`.
