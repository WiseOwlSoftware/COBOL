# PB3890 — date-to-yyyymmdd-zero-year-check--checking-not-honored: >>TURN EC-ARGUMENT-FUNCTION CHECKING ON (and -debug) does not stop the run on an incorrect function argument

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S3) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\date-to-yyyymmdd-zero-year-check--checking-not-honored.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\date-to-yyyymmdd-zero-year-check--checking-not-honored\`.

## Summary

With checking for EC-ARGUMENT-FUNCTION enabled, ISO ends the run unit abnormally when a function argument is incorrect
(the condition is fatal). GnuCOBOL 3.2 accepts `>>TURN EC-ARGUMENT-FUNCTION CHECKING ON` (and `-debug`, and
`-fec=EC-ARGUMENT-FUNCTION`) without a diagnostic, detects the incorrect argument (it returns 0 and EXCEPTION-STATUS
reports EC-ARGUMENT-FUNCTION), and continues. cobc generates no check for this exception condition: no code path tests
whether checking for it is enabled. Found while reducing the DATE-TO-YYYYMMDD family; the control program uses an
argument-3 that GnuCOBOL does detect, so this record is independent of
`date-to-yyyymmdd-zero-year-check--argument-1-range`.

## Minimal test case

Fixed reference format (cobc's default; the directive starts in column 8), 7 lines,
`records/date-to-yyyymmdd-zero-year-check--checking-not-honored.cob`:

```cobol
       >>TURN EC-ARGUMENT-FUNCTION CHECKING ON
       IDENTIFICATION DIVISION.
       PROGRAM-ID. DTTURN.
       PROCEDURE DIVISION.
           DISPLAY FUNCTION DATE-TO-YYYYMMDD (851003 10 1500)
           DISPLAY "CONTINUED [" FUNCTION EXCEPTION-STATUS "]"
           STOP RUN.
```

## Environment

- `cobc (GnuCOBOL) 3.2.0`, Ubuntu package `gnucobol3 3.2-4build1`, WSL2 Ubuntu (kernel 6.18.54.1-microsoft-standard-WSL2)
  on Windows 11.
- `wsl -d Ubuntu -e bash -lc "cd /mnt/e/COBOL-coord/scratch/op/pb3838/work/date-to-yyyymmdd-zero-year-check && cobc -std=cobol2014 -x dtturn.cob && ./dtturn"`
- Also run, same result: `d_neg4.cob` (`DATE-TO-YYYYMMDD (-10000 10 2026)` then `DISPLAY "CONTINUED"`) compiled with
  `cobc -std=cobol2014 -x`, with `-debug`, and with `-fec=EC-ARGUMENT-FUNCTION`.
- The compile prints two lines from the C compiler on this Ubuntu build (`<command-line>: warning: '_FORTIFY_SOURCE'
  redefined` and its note); they are not part of this finding.

## Observed result

Compile exit 0. Run output:

```
000000000
CONTINUED [EC-ARGUMENT-FUNCTION           ]
```
run exit 0. `d_neg4` under all three option sets: `000000000`, `CONTINUED`, exit 0.

## Expected result (per ISO)

ISO/IEC 1989:2023, all checked:

- 15.23.3 rule 4: "Argument-3 shall be an integer greater than 1600 and less than 10000." 1500 is incorrect.
- 15.3: an incorrect argument value means "the EC-ARGUMENT-FUNCTION exception condition is set to exist".
- 7.3.25.4 rule 6: with the ON phrase "checking for the exception condition associated with exception-name-1 is
  enabled for the procedure division statements ... that follow".
- 14.6.13.1.6, Table 13: `EC-ARGUMENT-FUNCTION | Fatal | Function argument error`.
- 14.6.13.1.3 rule 7: "If checking for the exception condition is enabled, execution of the run unit is terminated
  abnormally" (no declarative, no PERFORM ... WHEN, no PROPAGATE in the program).

Expected: the run unit ends abnormally during the first DISPLAY; `CONTINUED` is never displayed; the exit status
reports abnormal termination.

EC-ARGUMENT-FUNCTION is not listed among the optional exception conditions of A.4 (it is part of the intrinsic function
facility, not an optional module), so the implementor-not-required clause of 14.6.13.1.1 for optional elements does not
apply.

Edition: the TURN directive and EC-ARGUMENT-FUNCTION are ISO/IEC 1989:2002 features (GnuCOBOL's own NEWS calls >>TURN
"COBOL 2002"); the 2009 committee draft that led to 2014 (CD 1.2) carries the same argument-3 rule, and Annex E of 2023
lists no change. The requirement holds for `-std=cobol2014`.

Edition as recorded by the adjudicator: 2014. `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Class

Compiles but is not implemented at run time (the enabled checking of a fatal exception condition has no effect).

## Our compiler (WiseOwl)

`cobol dtturn.cob --std 2014 --run` (WiseOwl, built from main 6ed90bd1c): `abnormal run-unit termination:
EC-ARGUMENT-FUNCTION (fatal): YEAR-TO-YYYY argument-3 1500 is not greater than 1600 and less than 10000 (§15.100.3 r4)`,
exit 1; `CONTINUED` not displayed. It matches the ISO expectation (WiseOwl reports the condition through YEAR-TO-YYYY,
which 15.23.4 defines DATE-TO-YYYYMMDD by).

## Fix site (GnuCOBOL 3.2 source, read observationally)

- `cobc/typeck.c` and `cobc/codegen.c`: the enabled-checking tests (`CB_EXCEPTION_ENABLE (...)`) exist for
  EC-BOUND-SUBSCRIPT, EC-BOUND-REF-MOD, EC-DATA-INCOMPATIBLE, EC-DATA-PTR-NULL, EC-PROGRAM-ARG-* and EC-I-O, and for no
  EC-ARGUMENT condition. The intrinsic-function call that cobc generates is not followed by a test of the exception
  that the libcob routine set. A fix generates, after an intrinsic function reference compiled with EC-ARGUMENT-FUNCTION
  checking enabled, a test of the exception code that hands a set EC-ARGUMENT-FUNCTION to the fatal-exception path
  (declarative, else abnormal termination).
- `libcob/intrinsic.c`: the function routines (here `cob_intr_date_to_yyyymmdd`, via its argument-3 test) already call
  `cob_set_exception (COB_EC_ARGUMENT_FUNCTION)` and return 0.
- `libcob/exception.def` marks EC-ARGUMENT-FUNCTION fatal (the last field of its `COB_EXCEPTION` entry is 1).

## Upstream state

Unreported; tracker searched 2026-10-29 (below): no ticket reports it. Partly known: 3.2 `NEWS` says ">>TURN (COBOL 2002) directive implemented,
allowing some exception checks to be turned on/off per source as desired", which implies not every exception check is
implemented, but names none. The three `ChangeLog` files and `TODO` do not name EC-ARGUMENT-FUNCTION checking. Not
re-run on the current development branch. Other exception conditions without a `CB_EXCEPTION_ENABLE` site likely share
the gap; that sweep is not part of this record.

**Tracker search (2026-10-29).** All 1,801 tickets of GnuCOBOL's SourceForge trackers (bugs, feature-requests, patches;
harvested through the Allura REST API) were searched for: >>TURN, TURN EC, EC-ARGUMENT-FUNCTION, CHECKING ON, -fec=,
CB_EXCEPTION_ENABLE, fatal. A matcher decided each candidate and an independent skeptic re-read every claimed duplicate
(kb/Work PB3838 tier 6).

- No ticket reports this defect.
- Related: [feature-requests #284](https://sourceforge.net/p/gnucobol/feature-requests/284/) (accepted (GC 3.x), no

- Related: [bugs #485](https://sourceforge.net/p/gnucobol/bugs/485/) (closed (fixed r2349 for the exception-name part)):

  corrected which exception REM/MOD raise.
- Related: [bugs #728](https://sourceforge.net/p/gnucobol/bugs/728/) (accepted (GC 4.0)): Same gap for
  EC-SIZE-ZERO-DIVIDE: an enabled fatal exception is not handled as fatal. Deferred to 4.x.

- 3.2.0: dtturn: '000000000' / 'CONTINUED [EC-ARGUMENT-FUNCTION ]' exit 0; d_neg4 plain, -debug and -fec=EC-ARGUMENT-FUNCTION: '000000000', CONTINUED, exit 0.

## Draft issue

**Title:** `>>TURN EC-ARGUMENT-FUNCTION CHECKING ON` (and -debug) does not stop the run on an incorrect function argument

**Body:**

Environment: GnuCOBOL 3.2.0 (Ubuntu gnucobol3 3.2-4build1), `cobc -std=cobol2014 -x`.

Program (fixed format):

```cobol
       >>TURN EC-ARGUMENT-FUNCTION CHECKING ON
       IDENTIFICATION DIVISION.
       PROGRAM-ID. DTTURN.
       PROCEDURE DIVISION.
           DISPLAY FUNCTION DATE-TO-YYYYMMDD (851003 10 1500)
           DISPLAY "CONTINUED [" FUNCTION EXCEPTION-STATUS "]"
           STOP RUN.
```

Steps: `cobc -std=cobol2014 -x dtturn.cob && ./dtturn` (same with `-debug` or `-fec=EC-ARGUMENT-FUNCTION`).

Observed: `000000000`, then `CONTINUED [EC-ARGUMENT-FUNCTION           ]`, exit 0. The runtime detects the incorrect
argument-3 but the program continues.

Expected: abnormal run-unit termination at the first DISPLAY. ISO/IEC 1989:2014 (and 2023): DATE-TO-YYYYMMDD argument
rule 4 (argument-3 greater than 1600 and less than 10000); 15.3, an incorrect argument sets EC-ARGUMENT-FUNCTION to
exist; Table 13 lists EC-ARGUMENT-FUNCTION as fatal; 14.6.13.1.3 rule 7, "If checking for the exception condition is
enabled, execution of the run unit is terminated abnormally".

Cause: cobc generates no enabled-checking test for EC-ARGUMENT-FUNCTION (no `CB_EXCEPTION_ENABLE
(COB_EC_ARGUMENT_FUNCTION)` site in cobc), so the exception that libcob sets is never acted on.
