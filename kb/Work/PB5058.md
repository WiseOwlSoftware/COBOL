# PB5058 - the quota estimator's price ratios were stale

**Sites:** `scripts/orchestrator/model_rules.json` (`calibration.tokens_per_point`, `calibration.tokens_per_point_frontier_source`), `.claude/skills/workstream/templates/MANDATORY-PRACTICES.md` (P1).

**Found.** The owner pasted the current per-MTok prices: Fable 5.2 $8 input / $40 output / $10 cache write / $0.20 cache
read; Opus 5.5 $4 / $20 / $5 / $0.20; Sonnet 5.5 $2 / $10 / $2.50 / $0.10; Haiku 5.5 $0.10 / $0.50 at prompts of 100K
tokens or less and $0.50 / $2.50 above. `model_rules.json` priced Fable at 2.5x the Opus cost (640,000 tokens per weekly
point, from the $10/$50 of 2026-10-06) and Sonnet at 1/2.5 (4,000,000), so `budget.py` and `plan_wave.py` overstated a
Fable dispatch's draw by 25 % and understated a Sonnet group's by 25 %. MANDATORY-PRACTICES P1 restated a third, older
figure (160,000 tokens per point).

**Landed.** Fable 800,000 (2x the Opus cost), Sonnet 3,200,000 (half), Haiku 12,800,000 (1/8, the over-100K tier every
agent turn is in), Mythos 800,000 (Mythos 5.2, the newest Mythos, is priced as Fable 5.2 on the docs' pricing table), Opus 1,600,000 unchanged; the source string restates
the date and prices. P1 now points at `model_rules.json` instead of restating a number. `message_batches.py` prices only
Opus 5.5, whose batch prices are unchanged. `test_budget.py` 60/60.
