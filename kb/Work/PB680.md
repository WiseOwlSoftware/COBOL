# PB680 — LANDED — a fix without its witness

Found 2026-09-05 by the `PB327` implementer (report §"New defects" C). Routing every record-area send through
`OperandText.RecordAreaImage` (= `AsStorageImage`, whose `BitsPack` arm packs a bit leaf per §13.18.60.4 GR5 —
`cite.py --check 13.18.60.4 "BIT"` → `OK 5)`: *"The USAGE BIT clause specifies that bits shall be used to represent
a boolean data item"*) fixed an elementary BIT record area that had been writing its character carrier. The
implementer added a golden only for the national shape it was dispatched for.

## Why this is a note

Goldens ship with the feature: a behaviour that changed without a test pinning it can change back without one
noticing, and the byte-window residue guard (`ByteWindowResidueOf`) is now vacuous (PB327 folded the FD gate into
it and PB231's pointer third emptied its refusal list), so nothing else observes the shape. D19/PB43 own the BIT
packing; this note owns the file-record witness.

## Fix

A spec-derived golden: an FD whose record is `01 R PIC 1(8) USAGE BIT.` (and a group with a BIT leaf beside an
alphanumeric one), WRITE then READ back, expected bytes computed from §13.18.60.4 GR5 and §8.5.1.6.3's packing,
printed as ORDs so the output carries no unprintable byte. Register it; close on `unit`/`conformance` refs only.
Dispatchable after train 11 lands (PB327's channel).

Owner 2026-10-17: addressed in the SORT and file I/O campaign (kb/Work PB3353).

## Landed (wave 1117, group G)

Re-probed on a fresh build: the defect no longer reproduces. An elementary `01 R PIC 1(8) USAGE BIT.` under an FD
writes its one packed byte (`B"01000001"` reads back through a `PIC X(1)` connector as ORD 66), and every sibling arm
sends and receives the packed image: a 5-bit and a 12-bit record (ceil(bits/8) bytes, trailing filler zero), a bit
leaf beside an alphanumeric one (including a trailing partial byte), LINE SEQUENTIAL, RELATIVE and INDEXED records,
WRITE FROM and READ INTO, REWRITE, and SORT and MERGE records (USING/GIVING and RELEASE/RETURN). There is one channel
(`OperandText.RecordAreaImage`, `SequentialIoEmitter.EmitRecordAreaStore`), so no second arm needed a fix. Landed as
witnesses only, under `conformance-suite/cases/13.18.60-USAGE/`: `pb680_bit_record_area_file_io` (success), `pb680_bit_record_area_line_sequential` (2023),
`pb680_bit_record_area_file_exceptions` (I-O statuses 04, 10, 35, 41, 42, 46, 47, 48 and a USE declarative against the
AT END phrase on a bit-record file) and the negative `pb680-bit-record-area-below-2002` (COBOL0900 at 85).
`docs/CONFORMANCE.md`'s USAGE BIT determination now states the file-record image.
