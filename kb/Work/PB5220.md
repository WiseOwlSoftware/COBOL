# PB5220 - the host moved past the toolchain manifest

**Sites:** `toolchain.env` (whole: the version block); `scripts/cloud/setup-env.sh` (whole: its byte-identical copy of the block).

**What happened.** `C:\Program Files\dotnet\sdk\10.0.404` is dated 2026-11-10 16:49 and `pwsh` reports 7.6.10: the dev box
updated itself. `toolchain.env` pinned `DOTNET_SDK_VERSION=10.0.403` and `PWSH_VERSION=7.6.9`, and the gate refuses to run while
a tool it runs reports another version, so every gate started after 16:49 ended NOT RUN [toolchain]. The wave-20261989
implementer of PB5158 committed its fix and could not gate it.

**Fix (landed).** Owner 2026-11-10 17:40: "We want the latest versions. Plan the upgrade so it doesn't disrupt anything. The
updates are fast", then "CI should update to the same later versions". The manifest and its cloud copy name the newest stable
releases (`python scripts/toolchain.py bump`): dotnet-sdk 10.0.404, pwsh 7.7.0, semgrep 1.185.0. CI installs from the manifest
(`.github/actions/setup-toolchain`), so its runners move in the same change. The dev box: dotnet 10.0.404 was already installed;
semgrep 1.185.0 by `uv tool install semgrep==1.185.0 --python 3.14.10 --managed-python --force`; pwsh 7.7.0 by winget once the
session windows that hold `C:\Program Files\PowerShell\7` were closed (the owner's choice: a silent upgrade can close them through
Windows' Restart Manager). The three gates running at the time were stopped first: a manifest change re-gates every branch.
PB5219 (the campaign unit's question to the owner for the same install) is this item.
