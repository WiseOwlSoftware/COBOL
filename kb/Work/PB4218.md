# PB4218 — the word is the whole operand, so deleting it cannot repair the condition

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs#SingleTokenDeletion`,
`src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs#IsReservedOperand` (added by PR #890, the PB4133 landing),
`src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs#ConsumeUntil`.

**Repro.** `PERFORM UNTIL RECEIVE = 1 DISPLAY "X" END-PERFORM.` and the same with `GOBACK` in place of `RECEIVE` draw the
true COBOL0901 (reserved word used as a user word) and then a false COBOL5506 "missing token before 'DISPLAY' ... expected
TIMES". Main (c6e25ffb7) and the PB4133 branch (d63f0d674) print the identical pair, so the PB4133 review (round 4) found it
pre-existing, not a regression. Probes: `E:\Temp\claude\E--COBOL\0f9b6a03-8435-40e4-aa37-7999eefeeb81\scratchpad\r4p`.

**Mechanism.** With the reserved word as the whole operand, nothing remains of the condition once the word is dropped. PB3248
(and PB4133's `IsReservedOperand` yield) repair the case where more condition text follows the word (`RECEIVE W-X = 1`), where
ANTLR's single-token deletion removes the verb and `W-X` stands in as the operand. Here single-token deletion cannot repair
the condition, the recovery cannot keep the PERFORM's UNTIL reading, and it falls to the `PERFORM ... TIMES` alternative.

**Fix direction.** The recovery must read the word as the user name it stood for (single-token substitution: one COBOL0901,
then a continued parse), instead of deleting it. Sweep the sibling shapes the finisher probed with a following operand (IF,
EVALUATE, PERFORM VARYING ... UNTIL, `OR SEND ...`, WITH TEST AFTER) with the word alone as the operand. A golden pins
exactly one diagnostic for each verb.

## Landed (wave 20261788 D, 2026-10-31)

Re-probed on the tree first: `PERFORM UNTIL RECEIVE = 1 DISPLAY "X" END-PERFORM.` and the GOBACK twin drew COBOL0901 and the false
`COBOL5506: missing token before 'DISPLAY' ... expected TIMES`, as filed. Traced (a temporary trace of the strategy's report, deletion and
resynchronization): the failure is a loop/decision `Sync` at the start of the condition (`performUntilTarget`), an InputMismatch; the
deletion declines (the token after RECEIVE is '='), the resynchronization consumes RECEIVE and stops at the `1`, because an integer begins
a TIMES phrase and is in the recovery set of the enclosing `performOptions*`; the PERFORM then reads `1 DISPLAY` as `performTimes` and
conjures TIMES. The note's fix direction held: the word must be read as the name it stood for.

**Fix: single-token SUBSTITUTION, ANTLR's missing third repair.** After the report names the word (COBOL0901) it is retyped `IDENTIFIER`
in the stream (`CobolParserCoreBase.ReadAsUserWord`, the same retype the reservation gate does for a free word) and the parse goes on with
the name: in `CobolErrorStrategy.SingleTokenDeletion` (reached by `Sync` and `RecoverInline`, so the mismatch and the loop recovery) where
the parse expects an IDENTIFIER, and in `CobolErrorStrategy.Report` for a failed PREDICTION that died at the word ahead of the parser
(`PERFORM VARYING RECEIVE FROM 1 BY 1 UNTIL …`: the recovery resumes at the PERFORM and the second parse finds the name). Both only where
the name lets the source go on (`OffendingPosition.NameLetsTheSourceContinue`: a walk that takes an IDENTIFIER at the word, then the token
after it); `MOVE W-X TO` then `SEND TO W-X.` keeps the consumption of PB3248. The repair is the PASS's own: `RestoreWordsReadAsNames`
puts the types back after every pass of `ReservationGateRewriter.ParseToFixpoint` and in `Reset` (found by the version matrix's
`user-word-as-2002` permissive row: the gate looks for keyword tokens to retype between passes, and a repair left standing hid them).

**Sweep.** IF, EVALUATE, `PERFORM VARYING … UNTIL`, `OR SEND`, `WITH TEST AFTER`, a VARYING identifier, SET, CALL USING, COMPUTE, with the
word alone as the operand: one COBOL0901 each for every verb that is not a complete statement by itself (see PB4208's sweep).
