# PB4218 — the word is the whole operand, so deleting it cannot repair the condition

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs#SingleTokenDeletion`,
`src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs#IsReservedOperand` (added by PR #890, the PB4133 landing),
`src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs#ConsumeUntil`.

**Repro.** `PERFORM UNTIL RECEIVE = 1 DISPLAY "X" END-PERFORM.` and the same with `GOBACK` in place of `RECEIVE` draw the
true COBOL0901 (reserved word used as a user word) and then a false COBOL5506 "missing token before 'DISPLAY' ... expected
TIMES". Main (c6e25ffb7) and the PB4133 branch (d63f0d674) print the identical pair, so the PB4133 review (round 4) found it
pre-existing, not a regression. Probes: `E:\Temp\claude\E--COBOL\0f9b6a03-8435-40e4-aa37-7999eefeeb81\scratchpad\r4p`.

**Mechanism.** With the reserved word as the whole operand, nothing remains of the condition once the word is dropped. PB3248
(and PB4133's `IsReservedOperand` yield) repair the case where more condition text follows the word (`RECEIVE W-X = 1`), where
ANTLR's single-token deletion removes the verb and `W-X` stands in as the operand. Here single-token deletion cannot repair
the condition, the recovery cannot keep the PERFORM's UNTIL reading, and it falls to the `PERFORM ... TIMES` alternative.

**Fix direction.** The recovery must read the word as the user name it stood for (single-token substitution: one COBOL0901,
then a continued parse), instead of deleting it. Sweep the sibling shapes the finisher probed with a following operand (IF,
EVALUATE, PERFORM VARYING ... UNTIL, `OR SEND ...`, WITH TEST AFTER) with the word alone as the operand. A golden pins
exactly one diagnostic for each verb.
