# PB859 — OPEN — the half of §5.5 that is enforced by construction, and the half that is enforced nowhere

Source: the `PB721` implementer report, item (b), plus a measurement this pass added.

## Repro — re-run on this tree

`scratchpad/reg4/probe/p38_occurs_zero.cob` (PROGRAM-ID `R4P38`), `--std 2023`:

```cobol
       01 T.
          05 E PIC X OCCURS 0 TIMES.
```
```
error: backend compilation failed (generated C# at ...p38_occurs_zero.g.cs):
  (15,45): error CS0029: Cannot implicitly convert type 'string[]' to 'string'
  (19,17): error CS0029: Cannot implicitly convert type 'string' to 'string[]'
```

So the zero is not merely accepted: it is accepted, lowered, and the failure reaches the user as two Roslyn
errors naming generated C#. (`crashes` is set for that reason — a raw backend failure is the compiler's own
abort, not a diagnosis.)

## The rule, quoted

```
$ python scripts/spec/cite.py --check 5.5 "it refers to a fixed-point integer literal that shall be unsigned and nonzero unless otherwise specified in the associated rules"
  OK  §5.5 1)  (Integer operands)
      1) When the term 'integer-n' (n = 1, 2, …) is used in a general format and associated rules, it refers to a fixed-point integer literal that shall be unsigned and nonzero unless otherwise specified in the associated rules.
```

The UNSIGNED half is enforced by construction (the grammar's `integerLiteral` is `[0-9]+`). The NONZERO half has
no site anywhere.

## Shape of the fix (explicitly NOT a per-clause `if`)

One screen over the `integer-n` operands of every general format, keyed by a per-clause "this rule expressly
permits zero" exception set derived from the rule text — a per-clause `if` is exactly the hand-maintained list
CLAUDE.md rule 5 forbids. The generator that builds the rule catalog already parses the formats, so the operand
census is available to it; the exception set is small and citable (RECORD's integer-1 under SR3, the ref-mod
length, LINAGE's footing, and whatever the census finds).

## Code site

`src/Cobol.Net.Compiler/Validation/` (no site today); the census belongs beside `scripts/spec/` where the
general formats are already parsed.

## Sibling sweep the fixer owes

* For the RECORD clause the residue is unreachable (a zero integer-1 or integer-3 is already caught by SR3/SR4
  or by COBOLNET1836) — PB721 measured that, so it is a control, not a case.
* After the screen lands, re-run the OCCURS 0 probe: it must draw a NAMED diagnostic and never reach Roslyn.
* Sweep for the sibling shape: any other construct whose illegal operand reaches the backend as generated C#
  rather than a diagnostic.
