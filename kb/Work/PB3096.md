# PB3096 — a pull request's red before the queue was a silent zero

## The finding (the operator's train-1067 land unit, 2026-10-11, lead 3)
`scripts/orchestrator/landing_measure.py#complete` read one `gh run list --event merge_group` listing and counted a
pull request's FAILED merge-group runs as its bounces. A pull request's own run (event `pull_request`: the cheap jobs,
`audits` and `ci-gate`) that went red before the queue took it never reaches a merge group, so the record said 0 bounces
for a landing that had in fact gone red and been fixed. The module's own rule is that a MISSING observation is not a
zero; the after column of `summary` read better than the truth.

## Landed (wave 1068 A, branch of PB3024's closing change; MANDATORY-PRACTICES I9)
- A field `pre_queue_reds`: `complete` asks `gh run list --workflow build-and-test.yml --event pull_request --branch
  <the record's branch> --json conclusion` per record and counts the `failure` / `timed_out` runs (a run cancelled
  because its head moved is superseded, not a red). Every pull request has at least one such run, so an empty listing is
  an observation missed: the field stays null and `complete` warns `pre-queue reds UNMEASURED`, never 0. A failed
  listing leaves the record unmerged (exit 2), like a failed `gh pr view`.
- `validate` refuses a negative count; `patch_record` carries the field; `record --pre-queue-reds N` sets it by hand.
- `summary` prints "pull-request reds before the queue per landing" beside bounces (the before column is UNMEASURED: a
  train opened no pull request), and names the landings it could not observe.
- `--self-test` arm 9 (two reds, a cancelled and a green run on one branch → 2; a branch with no run → null and the
  warning; a failed listing → exit 2, nothing completed), pinned by `LandingMeasureDriftTests`; a mutation that always
  records the count fails it. `DESIGN-test-build-ci.md` §3.17.5 describes the field.
- Code sites: `scripts/orchestrator/landing_measure.py` (`complete`, `validate`, `patch_record`, `after_figures`,
  `summarize`, `parser`, `patch_from_args`, `_self_test`), `tests/Cobol.Net.Tests.Unit/LandingMeasureDriftTests.cs`.

## Landing (for the next implementer; orient.py reads it)
- `scripts/orchestrator/landing_measure.py#complete` makes one `gh run list --event pull_request --branch <branch>` call
  per record after `gh pr view`; a failed listing is a `bad` record (exit 2, nothing completed), an empty one a null
  field. A new arm goes at the END of `ARMS` and into `LandingMeasureDriftTests` (the unpack in `_self_test` names each).
