# PB3370 — a reserved word after a computer-name is not named

Filed 2026-10-18 from wave 1117 group A's report (`E:\COBOL-coord\scratch\reports\w1117a-PB2533-report.md`,
"New defects" item 1).

## What happens

A reserved word written after the computer-name of a SOURCE-COMPUTER or OBJECT-COMPUTER paragraph is not named by the
diagnostic. Harm: message quality only; the source is refused, as it must be.

## Repro

`E:\COBOL-coord\scratch\w1117a\p\p07_src.cob` (scratch is not durable, so the contents are copied here):

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. P07.
       ENVIRONMENT DIVISION.
       CONFIGURATION SECTION.
       SOURCE-COMPUTER. XYZ GLOBAL.
       PROCEDURE DIVISION.
           DISPLAY "RAN"
           STOP RUN.
```

`p08_obj.cob`:

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. P08.
       ENVIRONMENT DIVISION.
       CONFIGURATION SECTION.
       OBJECT-COMPUTER. XYZ GLOBAL.
       PROCEDURE DIVISION.
           DISPLAY "RAN"
           STOP RUN.
```

Both give COBOL0307.

## Cause

The outer optional group's adaptive prediction fails at GLOBAL, and ANTLR's error-recovery prediction takes the exit
alternative, reading XYZ through configurationParagraph's unrecognizedClause.

## Code site

`src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4#sourceComputerParagraph` and `#objectComputerParagraph`.

## Family

The same family as PB2533, a different mechanism: the optional-group exit on error recovery, not genericClause's
IDENTIFIER start. The fix needs a grammar restructure of the optional group.

## Landed (w1119a, 2026-10-18) — the second period is superset-parsed, and the residue continues inside the production

**Re-probe (worktree build, before).** `SOURCE-COMPUTER. XYZ GLOBAL.` and `OBJECT-COMPUTER. XYZ GLOBAL.` drew
`COBOL0307: unexpected 'GLOBAL'. A period may be missing`, as did `XYZ GLOBAL EXTERNAL.`, `XYZ WIBBLE GLOBAL.` (both
paragraphs) and the SOURCE-COMPUTER form before an OBJECT-COMPUTER paragraph (scratch `w1119a\probe.sh`). The note's
cause held: the paragraph's optional-group decision fails at GLOBAL, and ANTLR's error-time choice
(`ParserATNSimulator.GetSynValidOrSemInvalidAltThatFinishedDecisionEntryRule`, not virtual in the 4.13.1 C# runtime)
returns the lowest alternative that has already LEFT the decision's rule. With the second period required only the
exit alternative had (through the configuration section's `unrecognizedClause`). A semantic predicate cannot steer it:
the fallback takes a semantically invalid finished alternative too.

**Fix.** (1) Grammar: `sourceComputerParagraph : SOURCE_COMPUTER DOT (computerName debuggingModeClause?
unrecognizedClause?)? DOT?` and `objectComputerParagraph : OBJECT_COMPUTER DOT ({!objectComputerClauseAhead()}?
computerName)? objectComputerClause* DOT?`. The name's alternative now leaves the rule as well, so it is the lowest
finished alternative and wins; CobolErrorStrategy's existing Sync names GLOBAL (COBOLNET1970). (2) The superset is
refused back through the ONE table: `ParagraphPeriods.ByContext` gains the two rows (§12.3.5.3 SR1, §12.3.6.3 SR4: a
paragraph with nothing after its header has no sentence), and a missing period after a name or clause is COBOLNET3408
at it, where it was a bare COBOL0307 at the next header. (3) CobolErrorStrategy: a Sync inside the word run
(`genericClause`) is a residue position, and the 0g closure records the list whose call of the production the PARSER
is still inside when it pops that context. `SOURCE-COMPUTER. XYZ WIBBLE GLOBAL.`, `CONFIGURATION SECTION. WIBBLE
GLOBAL.` and `IDENTIFICATION DIVISION. … WIBBLE GLOBAL.` (the three formats whose production is not in a list loop)
are now named. No new code (COBOLNET4376-4378 returned).

**Goldens.** Positive `12.3.5-SOURCE-COMPUTER/pb3370_computer_paragraph_second_period` (accept 85: a name-less
SOURCE-COMPUTER without its second period, then a named OBJECT-COMPUTER whose collating sequence takes effect).
Negatives at 85 2002 2014 2023: `pb3370-source-computer-reserved-word-clause`, `pb3370-object-computer-reserved-word-clause`
(COBOLNET1970), `pb3370-source-computer-period-missing`, `pb3370-object-computer-period-missing` (COBOLNET3408). Unit
`ClosedFormatReservedWordTests` (five cases and one control); the `ParagraphPeriodDriftTests` probe asserts both rules.

**Not closed here (reported as a lead).** A LITERAL after the computer-name (`SOURCE-COMPUTER. XYZ "LIT".`,
`OBJECT-COMPUTER. XYZ "LIT".`) is still misattributed: `genericClause` opens only at an IDENTIFIER, so the name-less
reading is the only viable parse, and XYZ is reported as a configuration paragraph or an OBJECT-COMPUTER clause (with a
false COBOLNET0900 or COBOLNET3734 at 85). Widening the one error production's left edge touches all ten closed formats.

**For the next implementer (w1119a):**
- `src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4#sourceComputerParagraph` / `#objectComputerParagraph` — the
  trailing `DOT?` is load-bearing for PREDICTION, not only punctuation: requiring it again brings PB3370 back. Trap:
  ANTLR's error-time fallback prefers an alternative that has left the rule, so an optional slot followed by a required
  token loses to the follow's error production.
- `src/Cobol.Net.Frontend/Cst/ParagraphPeriods.cs#ByContext` — the one table for a superset-parsed period; a row and
  the `DOT?` go together, and `ParagraphPeriodDriftTests` holds both directions.
- `src/Cobol.Net.Frontend/Parsing/CobolErrorStrategy.cs#IsClosedFormatResidueAhead` / `#Closure` — the genericClause
  state check and the context-pop `Found`; reuse them, never a per-format case.
