# PB185 — LANDED — the fleet build guard's own-transcript exclusion never matched a subagent

> ⚙ **flags:** process · found 2026-08-30/31 by two agents of session `01PEJTGVQX17pwVbXZq7mYxS` ·
> **landed 2026-08-31** (DEVLOG 1407), root cause MEASURED from the live hook payload rather than inferred.

**The third self-block mode of the same guard** — after [[PB101]] (an agent inside its own
`.claude/worktrees/` checkout) and [[PB103]] (a main-tree agent counting its own transcript). Both earlier modes
were fixed at `fleet_active_build.py:82-89` (the worktree bail) and `:100-105` (the own-transcript filter). The
`:100-105` filter is the one that did not work.

**WITNESSED TWICE** before the fix, by two different agents, both alone in `E:\CobolSharp` with no fleet running:

```
BLOCKED — 1 subagent transcript(s) were written in the last 120s, so a fleet is LIVE: subagents.
```

`detail` is `subagents`, i.e. the one "live" transcript is the CALLER's own
`~/.claude/projects/*/<session>/subagents/agent-*.jsonl`. The guard globbed it at `:64`, and `:103-105` was
supposed to drop it:

```python
own = (data.get("transcript_path") or "").replace("\\", "/").lower()
if own:
    live = [p for p in live if str(p).replace("\\", "/").lower() != own]
```

## Root cause, measured (the note's original hypothesis was close but not exact)

The note guessed "a differently-rooted / differently-cased spelling of the agent file". It is not a spelling
difference at all — the two paths name **different files**. The live payload was captured 2026-08-31 by
instrumenting the hook and re-firing it from a subagent:

```
"session_id":      "17d093ad-48d4-41f7-acc0-cfc45e58b424"
"transcript_path": "C:\\Users\\brent\\.claude\\projects\\E--CobolSharp\\17d093ad-….jsonl"   ← the SESSION transcript
"agent_id":        "acc9d0d75b870eb9d"
```

while the file the glob found — and the one the caller actually writes — was
`…\projects\E--CobolSharp\17d093ad-…\subagents\agent-acc9d0d75b870eb9d.jsonl`. A subagent's `transcript_path`
is the SESSION transcript, exactly as the main session's is. No normalization of either string could ever have
made the equality hold. Because the caller rewrites its own transcript on EVERY tool call, the 120-second window
never cleared: the block was permanent for the whole agent, not merely for the next two minutes.

**WHAT IT COST.** An agent could not build, test, run a probe, or run its own wave gate — `dotnet
build|test|clean|publish|run|msbuild` are all in `BUILD_VERBS`. It cost the PB164 finisher the
`SpecTraceabilityInventoryDriftTests` reference check after a verdict batch and a three-shape CLI probe of
[[PB190]]; the lander and the fixer each hit it earlier. The guard's harm model applied to none of them: there
was no fleet, and the only binary being changed was the one the agent itself was about to test.

## The fix — identity, not a third string comparison

Two exclusions had been bolted on for two spellings of the same question, and a third comparison would have been
the fourth. The guard's real question is *"is any transcript OTHER THAN MINE live?"*, so the exclusion now keys
on the caller's **identity**:

- `caller_identity(payload)` reads `agent_id`, which **is** the caller's transcript identity by construction —
  the file is named `agent-<agent_id>.jsonl` wherever in the `subagents/` tree the host puts it (including
  `subagents/workflows/wf_*/`). No path string has to match, so a new host layout cannot reopen this defect.
- `transcript_path` is retained as a second, independent spelling for hosts that DO point it at the agent file,
  compared on a **resolved** `pathlib.Path` rather than on raw text.
- A payload with neither (the main session) excludes nothing — correct, because the main session's transcript is
  not under `subagents/` and never enters the candidate set.
- The decision is now a pure function, `foreign_transcripts(payload, candidates)`, with all I/O at the edges.

**Real fleet protection is intact and was proven, not assumed** ([[feedback_prove_the_watchdog_fails]]):

- `python scripts/hooks/fleet_active_build.py --self-test` — a new mode firing BOTH branches with no fleet
  needed: subagent-alone → allow, own file nested under `workflows/` → allow, subagent inside a real fleet →
  deny, main session + fleet → deny, case-folded agent id → allow, no identity → deny, plus the verb matcher
  both ways (`dotnet --version` must stay out of scope). 12/12 ok. It caught one defect in its own first
  draft — a `PurePosixPath` that never reached the `resolve()` line.
- End-to-end against the live script over stdin, while this agent's transcript was genuinely fresh: a
  main-session payload was DENIED and the subagent payload ALLOWED, same run.
- Empirically in the harness: `dotnet build --help` was BLOCKED twice before the change and returned exit 0
  after it.

The `dotnet.exe` spelling remains uncaught, deliberately, as in PB103: the guard is a reminder for the model,
fail-open by construction, not a security boundary.
