# PB5755 - the harness gives no case a standard input

**Sites:** `conformance-suite/harness/run.py#execute` (the test's process: `stdin=subprocess.DEVNULL`), `conformance-suite/harness/generate.py` (whole: the header reader and the manifest gain the declared input), `tests/_shared/SuiteManifest.cs` (whole: the C# Conformance runner reads the manifest's new field and feeds it), `docs/rearchitecture/DESIGN-conformance-suite.md` (whole: the header field of its section 3.1 and the runner's contract of its section 5).

## The defect

`conformance-suite/harness/run.py` runs every test "with its declared files and stdin closed" (its module docstring,
and `stdin=subprocess.DEVNULL` on the run). WiseOwl's ACCEPT devices (CONSOLE, SYSIN and the device used when FROM is
omitted) are all standard input (docs/conformance/7/DOC-A.1-2.md; `src/WiseOwl.Cobol.Runtime/IO/AcceptSource.cs`).
So a suite case can only ever ACCEPT at end of input. What it then stores is WiseOwl's determination for end of input
(DOC-A.1-5: spaces), which the 1985 text does not state. No expected line of such a case derives from the 1985 rules.

That leaves five 1985 KEPT rows without an own-edition witness of the kind they need (an accepted case at 85):

| Row | Rule (each `cite.py --check` OK on 2026-11-15) |
|---|---|
| 1985-GR-VI.6.5.4-1 | §1985:VI.6.5.4 GR1 "The ACCEPT statement causes the transfer of data from the hardware device" |
| 1985-GR-VI.6.5.4-2 | §1985:VI.6.5.4 GR2 "The implementor will define, for each hardware device, the size of a data transfer" |
| 1985-GR-VI.6.5.4-3 | §1985:VI.6.5.4 GR3 "the transferred data is stored in the receiving data item" |
| 1985-GR-VI.6.5.4-4 | §1985:VI.6.5.4 GR4 "the transferred data is stored aligned to the left in the receiving data item" |
| 1985-GR-VI.6.5.4-5 | §1985:VI.6.5.4 GR5 "the device that the implementor specifies as standard is used" |

This is a gap in the tooling, not a property of the rules. The ACCEPT value pins live today only in the C# tests that
pipe stdin (`AcceptDifferentialTests`, kb/Work PB3513), and those are not suite cases, so PB5675's own-witness rule
(`lineage_reads.Witnesses.own_problems`) cannot count them. The ACCEPT rows of every edition (2002 and 2023 format 1
ACCEPT) are in the same position.

## What the fix needs

1. A header field that declares a case's standard input. It could be `stdin: <file>`, naming a file beside the case,
   like the declared files. `generate.py` reads it, refuses a missing or non-LF file, and carries it into the manifest.
2. `run.py` feeds that file as the process's stdin, and keeps DEVNULL for a case that declares none. The C# Conformance
   runner (`SuiteManifest`) does the same, so the gate and the harness agree.
3. The generator's `--check` refuses a case that ACCEPTs FROM a device bound to stdin, declares no stdin and names an
   ACCEPT rule of the device form in its `rules`. Without this check a case could pin the end-of-input determination
   and claim a transfer rule.
4. Then a 1985 ACCEPT case, accepted at 85, citing GR1-GR5 with output derived from the 1985 text. The writers'
   hand probe (`E:\COBOL-coord\scratch\gl1985\lane1\run\g1985-vi-6-5-accept-p2\dev\dev.cob < in.txt`, `--std 85`) is
   a lead for it, not evidence.

Not built in branch golden-1985-1: that branch lands goldens and records only.
