# PB6023 ruling (controller, account 2, 2026-11-21): the descriptor half is withdrawn; the one decision point stands

The PB6019 decision asked for each function's argument constraints as data on its descriptor, checked by one emitter. The
implementer found that many constraints are not ranges (calendar validity, collating-sequence size, text formats), so a data
form would either be a second, partial description of rules the function's own code must still check, or grow into a small
language. What the 1985 rule needs is ONE ANSWER to a broken constraint, and that is now structural: every breach goes
through `ExceptionEngine.ArgumentError` (and its two text twins), which decides by the running program's edition, and the
drift test `EveryBreach_TakesTheOnePath` refuses a runtime site that bypasses it. Detection stays beside each function's
evaluation, where its rule is implemented. DECIDED: the descriptor form is not built (option 2 of the note, in its words:
detection local, the response single).

Still owed under this note (1985 harm: misleading diagnostics), for the next fix group: about 15 functions' run-time messages
cite the §2023 clause at --std 85; a zero-length reference modification at 85 names EC-BOUND-REF-MOD, an exception-name the
1985 standard does not have. Both route through the edition's citation and naming (EditionInfo.CiteRule / the edition's
exception vocabulary), not hand-written strings.
