**Scenario:** GenerateIfNewer.ps1:46 dot-sources Invoke-Antlr4CSharp.ps1; inside a dot-sourced script $MyInvocation.MyCommand.Path equals $PSCommandPath (InvocationName is '.'), so line 128's guard fires, runs Invoke-Antlr4CSharp with PackageName defaulted to the literal 'CobolNet.Frontend.Generated' (line 36), and its 'exit' returns to the caller, which then runs the whole generation again at line 47 with the csproj value. Measured on a scratch copy of the pin's src/Cobol.Net.Frontend with Generated/ absent: 'Generating C# from: CobolLexer.g4' and 'CobolParserCore.g4' each print TWICE and 'All ANTLR generation completed successfully.' twice (6.2 s wall for both runs). A repro with two 5-line scripts shows the same: InvocationName=[.], MyCommand.Path == PSCommandPath, guard TRUE. Consequences: every grammar edit pays the generation twice; the namespace is written in three places (csproj:13, GenerateIfNewer.ps1:12, Invoke-Antlr4CSharp.ps1:36) and the first run uses the script default, so changing <AntlrNamespace> alone writes the old namespace first; and a failing first run prints its errors and is then masked by a second run whose result alone reaches MSBuild.

**Landed (wave 1092 C, with PB2719 — one change: the generation's one entry point).** Re-probe on this worktree's own
build before the change: a fresh `dotnet build Cobol.Net.sln` printed `Generating C# from: CobolLexer.g4` and
`CobolParserCore.g4` TWICE and `All ANTLR generation completed successfully.` twice (the dot-sourced guard fired, then
GenerateIfNewer.ps1 ran the generation again). `GenerateIfNewer.ps1` is deleted (PB2719), and `Invoke-Antlr4CSharp.ps1`
is no longer a function library with an entry point: it is a plain script the csproj's `EnsureGeneratedFiles` target
runs once with `pwsh -File`, with `-PackageName`, `-JarPath` and `-OutputDir` MANDATORY and without defaults, so the
csproj's `<AntlrNamespace>` and `<AntlrJar>` are the only spellings of the namespace and the jar. After: one
`Generating C# from:` per grammar, and the generated files are byte-identical to the baseline (`diff -r` of
`Generated/` before and after). Found on the way and fixed here (I9): the generator's failure path. ANTLR writes its
files and THEN reports a warning (exit 0), so a `warning(125)` run left fresh outputs the next build's staleness check
took for up to date; the generator now empties `Generated/` before generating and again on any failure (probe: an
appended `probeBogusRule : PROBE_UNDEFINED_TOKEN ;` fails the build with MSB3073 and leaves 0 files), and runs under
`$ErrorActionPreference = 'Stop'` with a trap, so a failed copy or delete fails the build instead of continuing.
Pins: `AntlrGenerationDriftTests` (no self-invocation guard, mandatory parameters, no csproj value repeated in the
script).

## Landing
- `src/Cobol.Net.Frontend/Invoke-Antlr4CSharp.ps1` — the ONE generator: a plain script with mandatory `-PackageName`,
  `-JarPath`, `-OutputDir`; it always generates (the csproj decides staleness), empties the output first and on failure.
  Never add a `$MyInvocation`/`$PSCommandPath` entry guard or a default that repeats a csproj value.
- A dot-sourced script sees `$MyInvocation.MyCommand.Path -eq $PSCommandPath` (InvocationName is `.`), so a "called
  directly" guard is true for its caller too.
