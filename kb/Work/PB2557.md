# PB2557

Filed by the train 1037b lander so that the owner question PB1027 left in its landed note stays visible in the register
(wave-1037 group C report, lead 1). The full analysis is in `kb/Work/PB1027.md` (section "Owner question, not decided here").

**The landed determination** (`docs/CONFORMANCE.md` §4, "which files support vertical positioning"): §14.9.51.4 GR25 makes
"the physical file supports vertical positioning" the implementor's question; the compiler answers yes when the file's
description has a LINAGE clause, or once a WRITE has carried an ADVANCING phrase since the OPEN
(`src/Cobol.Net.Runtime/IO/SequentialConnector.cs#SupportsVerticalPositioning`, `_printControl`). A plain-only file is
unchanged (GnuCOBOL's default `cobc` 3.2.0 shape).

**Question (a).** A plain WRITE that PRECEDES the file's first ADVANCING write is not positioned, so the file reads
`A LF LF B LF`; a compile-time capability (any ADVANCING write of the file in the compilation unit) would give
`LF A LF B LF`. Repro: `E:\COBOL-coord\scratch\w1037c\p1027\src3\ls-plainafter.cob`.

**Question (b).** Whether to take the w1033 decision's literal consequence for plain-only files after all: a leading empty
line on every such file, and an empty first record when it is read back.
