# PB5082 - at --std 85 DISABLE and ENABLE accept a numeric KEY literal: the key operand is bound with no alphanumeric class check

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CommunicationBinder.cs#BindPath` (binds the KEY operand as LiteralOperand or FieldOperand with no class check; COBOL6171 covers only RECEIVE and SEND operands).

**Mechanism.** 1985 requires the key literal or the content of the key data item of DISABLE and ENABLE to be defined as alphanumeric. BindPath binds the operand without asking, and the one communication operand diagnostic (COBOL6171) does not reach DISABLE and ENABLE.

**Found by.** The 1985 `--std=85` draft triage (kb/Work PB4995 item 3): each rule below is a conformance-suite draft that did not MATCH at `--std 85`, and its adjudicator decided COMPILER-DEFECT. Harm and observed text are the records'; nothing here was re-derived.

**Inventory.** The traceability inventory carries no 1985 rows yet, so `inventory_rows` is empty; the rows this note covers are the 1985 rule ids listed below (catalog `docs/rearchitecture/spec-rule-catalog-1985.json`).

**Rules (2; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-SR-XIV.3.2.3-4` - `§1985:XIV.3.2.3 SR4` (record harm: under-rejects, slice-11): §1985:XIV.3.2.3 SR4: "Literal-1 or the content of the data item referenced by identifier-1 must be defined as alphanumeric." DISABLE OUTPUT CD-OUT WITH KEY 123 writes a numeric literal as literal-1, which is not alphanumeric, so the 1985 text forbids the statement; the draft reads the rule correctly and its control (KEY "ABC") conforms.
- `1985-SR-XIV.3.3.3-4` - `§1985:XIV.3.3.3 SR4` (record harm: under-rejects, slice-11): §1985:XIV.3.3.3 SR4: "Literal-1 or the content of the data item referenced by identifier-1 must be defined as alphanumeric." ENABLE INPUT CDIN WITH KEY 12345 writes a numeric literal as literal-1, which is not alphanumeric, so the 1985 text forbids the statement; the draft reads the rule correctly and its control (KEY "ABCDE") conforms.

**Expected (from the 1985 text).** --std 85 refuses `DISABLE ... WITH KEY 123` and `ENABLE ... WITH KEY 12345`, at the key operand. The deciding words: "Literal-1 or the content of the data item referenced by identifier-1 must be defined as alphanumeric." (§1985:XIV.3.2.3 SR4).
