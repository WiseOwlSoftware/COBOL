# PB654 — LANDED — one evaluation, two spellings of it — and one gate, three arms

Found 2026-09-05 by the `PB647` implementer (report §"New defects" (2)), which moved §14.7.4.3 r7's PROHIBITED raise
into the float quantizer for the arm it owns and measured that the older gate — the one a genuinely-float
right-hand side still reaches — spells the right-hand side twice. Pre-existing; not taken there because it is a
statement-emitter mechanism, not the landing's.

## The mechanism

`src/Cobol.Net.Compiler/CodeGen/Verbs/ArithmeticEmitter.cs`, `StoreArith` — at the D16 review's gate (`:462`–`:465`
on main: `if ({RuntimeApi.FloatInexactAtScale(value.Expr, recvScale)}) {onFail}`) the emitter writes `value.Expr`
into the test, then writes `value.Expr` again into the store that follows. When `value.Expr` is a pure expression
(a data item) the two spellings evaluate to the same value; when it is a function reference whose returned value
is not the same on every reference — `FUNCTION RANDOM` with no argument, whose successive references are
successive elements of a pseudo-random sequence (⛔ §**15.75.3 r5**, `cite.py`-verified: "In each case,
subsequent references without specifying argument-1 return the next number in the current sequence". This note
originally cited §15.75.4 r2, which is a REAL sentence about something else — "For a given seed value on a given
implementation, the sequence of pseudo-random numbers will always be the same" — the inherited-citation failure
CLAUDE.md rule 1 names) — the representability test sees one returned value
and the store lands the next one. The same double spelling costs a second evaluation even where the value is
stable (a second `SQRT`, a second `CURRENT-DATE` conversion).

## The rule

§14.7.7 r4 a): "The initial evaluation of the statement is done and the result of this operation is placed in an
intermediate data item" (`OK §14.7.7 4) a)`); r4 b): "If the size error condition was not raised during the
initial evaluation, the intermediate data item is stored in or combined with and then stored in each single
resulting data item" (`OK §14.7.7 4)` — `cite.py` files both sentences under rule 4's first item) — ONE evaluation,
held in an intermediate, tested and then stored.
§14.7.4.3 r7's PROHIBITED test ("the arithmetic value cannot be represented exactly in the resultant identifier")
is a test on THAT intermediate. Two evaluations violate r4 a) directly and, for RANDOM, produce a stored value the
test never examined.

## Fix shape

Materialise the initial evaluation once: `StoreArith` binds `value.Expr` to a local (the intermediate data item r4
a) names — the C# `var` the emitter already introduces on other paths) and both the `InexactAtScale` test and the
store read the local. Sweep every emitter site that writes `value.Expr` more than once into the same statement's
output (`grep -n "value.Expr" src/Cobol.Net.Compiler/CodeGen/Verbs/*.cs` and count per statement), because the
ROUNDED-mode and SIZE ERROR gates are the natural places for the shape. Goldens at 2014/2023: `COMPUTE R ROUNDED
MODE IS PROHIBITED = FUNCTION RANDOM(7)` twice in a row asserting the stored value is the sequence's element the
test examined (seeded so the sequence is reproducible), and a `FUNCTION RANDOM` no-argument program that counts
references through a side channel (`RANDOM(seed)` restarts, so two references after a restart must yield the
first two elements exactly once each); a drift test that the emitted C# for a PROHIBITED store of a function
reference contains the function's call text exactly once.

## Landed 2026-09-22 (wave 44, fix-lane group B)

RE-PROBED FIRST on this worktree's own build. It reproduces, and the repro is measurable without reading the
emitted C#: seed 7, then a gated statement, then one more reference.

```
COMPUTE R = FUNCTION RANDOM(7)                                     *> element 1
COMPUTE R ROUNDED MODE IS PROHIBITED = C2 ** FUNCTION RANDOM       *> should consume element 2
    ON SIZE ERROR CONTINUE END-COMPUTE
COMPUTE R = FUNCTION RANDOM                                        *> should be element 3
```
Before: the last reference returned element **4** — the gated statement had consumed two. After: element 3.

**The note's own §15.75.4 r2 citation was MISFILED and is corrected above** to §15.75.3 r5. §14.7.7 r4 a) and
r4 b) both `--check` clean against §14.7.7, and §14.7.4.3 r7's sentence `--check`s clean against §14.7.4.3.

**And the sibling sweep found the other arms of the same dispatch.** The note treats this as one statement-emitter
site; it is a THREE-ARM dispatch and only the plain-numeric arm had the §14.7.4.3 r7 gate at all. Measured:

```
01 ED PIC ZZ9.999.
COMPUTE ED ROUNDED MODE IS PROHIBITED = C2 * 1  *> C2 = FUNCTION SQRT(3)
    ON SIZE ERROR DISPLAY "SIZE-ERROR" END-COMPUTE
```
stored `  1.732` and raised NOTHING, where r7 requires the size error condition and the receiver UNCHANGED.
`CobolFloat.ToScaled` lands a PROHIBITED transfer TRUNCATED by design — its own doc comment says the emitter
gates the store — so an ungated arm cannot see the discarded fraction. The LOCALE-edited arm had the same hole.

**The fix is therefore one mechanism, written once.** `StoreArith` now, at its top and before the receiver-category
dispatch: materialises the value through `Snapshot` (rule 4 a)'s "intermediate data item" — the same helper
`EmitCompute`'s multi-receiver arm already used for the same rule), and prepares the r7 test keyed on the ONE
receiver-scale rule (`RuntimeApi.ReceiverScaleOf` via `ScaleOf`). Each fixed-scale arm then asks `Gate(onFail)`
for the keyword its own first test opens with — `if`, or `else if` once the gate has written the leading `if`.
A FLOATING-POINT numeric-edited receiver is deliberately OUT (it has no fixed fraction scale; r7's
"represented exactly in the resultant identifier" is a different predicate there) — that leak is a separate lead.

Guards: `ArithmeticOneInitialEvaluationDriftTests` (Unit) reads the EMITTED C# for six receiver/phrase shapes and
asserts (1) each right-hand side is spelled once per source reference, (2) the gate's operand is always the
materialized `__ie` intermediate, (3) the gate is emitted for the numeric AND the numeric-edited receiver. Its
first two invariants were PROVED RED by removing the `Snapshot` line and rebuilding before being trusted.
Golden: `2014/pb654_prohibited_gate_one_evaluation` — which pins NO raw pseudo-random value (§15.75.4 r2 promises
only that a given seed gives the same sequence, which is exactly enough to compare element 3 of one run against
the element the next reference returns in another), and whose A1 line proves the measurement is not vacuous.
Design: `docs/COBOLNET_NUMERIC_DESIGN.md` D20.
