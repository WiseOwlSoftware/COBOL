# PB5987 - a DECLARATIVES portion that follows a nondeclarative section is refused as 'a reserved word used as a user-defined word' (COBOL0901), never saying the declaratives must come first (§1985:II.6.1, §1985:IV.6.4.1.1)

Two campaign sentences (slices 85p-04 and 85p-08) found the same mechanism: the refusal is right, but the parser takes the
late DECLARATIVES as a paragraph-name and the message blames a reserved word; no diagnostic names the ordering rule. Sibling
of PB1146 / COBOL2797 ("The procedure division body is neither ..."). The same at 2023. Goldens drafted in work/85p-04 and
work/85p-08 expect the ordering message and fail until fixed.

**Sites (as landed):** `src/WiseOwl.Cobol.Frontend/Grammar/CobolParserCore.g4` (`procedureDivision`: the trailing loop is `(sectionDefinition | declarativePart)*`, so a DECLARATIVES portion after a nondeclarative unit parses), `src/WiseOwl.Cobol.Compiler/Validation/ProcedureFormatPass.cs` (`ProcedureFormatPass.VisitProcedureDivision`, `ProcedureFormatPass.FollowsANondeclarativeUnit`: COBOL2797 names the ordering rule). Not `CobolErrorStrategy.cs`: the refusal was the parser's failure to read the portion at all, so the fix is the grammar shape PB1146 already uses (parse the union, refuse by name in the format pass), not a strategy special case; the strategy is unchanged.
