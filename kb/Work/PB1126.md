- **Expected (spec):** Each statement sets EC-RANGE-INSPECT-SIZE (GR14: 'If these sizes are not equal, the EC-RANGE-INSPECT-SIZE exception condition is set to exist'; GR15 likewise for a non-one-character identifier-5); with checking enabled and no declarative, the fatal EC terminates the run unit (§14.6.13.1). ### [inspect-statement-p2] A figurative literal-3 is sized to identifier-3 only when identifier-3's width is static (InspectStaticWidth); for a function-identifier (or other dynamic-width) identifier-3 the one-character figurative survives binding and the runtime size check then silently drops the operand
- **Rows:** GR-14.9.22.4-14 — harm `wrong-answer`
- **Repro:** 01 S1 PIC X(4). 01 P PIC X(4) VALUE 'AB'. MOVE 'XABX' TO S1. INSPECT S1 REPLACING ALL FUNCTION TRIM(P) BY SPACES. DISPLAY '[' S1 ']' -> [XABX]. (E:/Temp/claude/E--CobolSharp/a700c052-f9e4-4942-84ff-a13c7505d6ec/scratchpad/adj-d1/out/probe/inspect-p2/p1.cob T16)
- **Expected (spec):** [X  X]: 'When a figurative constant is used as literal-3, the size of the figurative constant is equal to the size of literal-1 or the size of the data item referenced by identifier-3' (GR14) - here FUNCTION TRIM(P) = 'AB', size 2.
- **Observed:** InspectBinder.BindPhraseOperands expands only when `InspectStaticWidth(pat) is { } wp`; InspectStaticWidth returns null for a BoundFunction operand, so rep2 stays ' ' (1 char) and CobolInspect.Replace skips the operand for pat.Length != repl.Length. The expansion has to happen where the width is known - at run time for a dynamic identifier-3 (e.g. pass the figurative character and let the runtime fill it to the pattern's size).
- **Code site:** src/Cobol.Net.Compiler/Binding/Procedure/Verbs/InspectBinder.cs#BindPhraseOperands; src/Cobol.Net.Compiler/Binding/Procedure/Verbs/InspectBinder.cs#InspectStaticWidth; src/Cobol.Net.Runtime/Verbs/CobolInspect.cs#Replace

### [inspect-statement-p3] INSPECT size rule GR22 is half-implemented: EC-RANGE-INSPECT-SIZE is catalogued but never raised (Convert clamps to the common prefix; the Replace twin skips the operand), and a figurative literal-5 is expanded to identifier-6's size only when that size is statically known, so a function-identifier identifier-6 gets a ONE-character figurative
- **Rows:** GR-14.9.22.4-22 — harm `wrong-answer`
- **Repro:** >>TURN EC-RANGE-INSPECT-SIZE CHECKING ON / 01 X PIC X(6) VALUE "abcdef". 01 F PIC X(3) VALUE "abc". 01 T2 PIC X(2) VALUE "XY". 01 W PIC X(6) VALUE "abcdef". INSPECT W CONVERTING FUNCTION TRIM(F) TO ZEROS. DISPLAY W. INSPECT X CONVERTING F TO T2. DISPLAY X FUNCTION EXCEPTION-STATUS.
- **Expected (spec):** W=000def: the figurative literal-5 has the size of identifier-6, which is 3. The second INSPECT sets the fatal EC-RANGE-INSPECT-SIZE, and with no declarative the run unit terminates abnormally (§14.6.12). INSPECT is nucleus, so the §14.6.13.1.1 optional-element exemption does not apply.
- **Observed:** Pinned cobol.exe prints W2=0bcdef, then X=XYcdef with a blank EXCEPTION-STATUS, and the run continues. The binder expands a figurative only when `InspectStaticWidth(from) is { }`, which is null for a function-identifier or an inline method invocation. The runtime Convert uses `Math.Min(fromSet.Length, toSet.Length)` and nothing raises the EC. The sibling GR14/GR15 (REPLACING, another part) has the same mechanism: Replace `continue`s on a size mismatch, and a function-identifier pattern with a figurative BY is silently skipped. Fix both at once: size a figurative at run time from the evaluated identifier-6/identifier-3 image, and raise EC-RANGE-INSPECT-SIZE under checking.
- **Code site:** src/Cobol.Net.Compiler/Binding/Procedure/Verbs/InspectBinder.cs#BindPhraseOperands (L264-268, L233-239); #InspectStaticWidth; src/Cobol.Net.Runtime/Verbs/CobolInspect.cs#Convert (L296), #Replace (L222)

## What the fixer owes
Raise EC-RANGE-INSPECT-SIZE (Fatal per ExceptionCatalog) in CobolInspect.Replace and Convert on the size mismatch; size a figurative literal-3/-5 at RUN time against the operand's current width when InspectStaticWidth has no answer. Goldens with checking on for REPLACING, CHARACTERS BY identifier-5 and CONVERTING.
