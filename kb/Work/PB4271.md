# PB4271 — merge-queue reds are not classified, so selection misses are not counted

**Sites:** `scripts/orchestrator/land_lane.py` (`watch_queue`, `watch_step`, `RedFacts`, `classify_red`, `red_facts`, `bounce_step`, `classify_bounce`, `agent_work`), `scripts/orchestrator/enqueue.py` (`tested_locally`, `Tested.run`: the gate record a bounce is compared with), `scripts/orchestrator/landing_measure.py` (`record_red`, the `reds` field), `scripts/orchestrator/queue_facts.py` (`bounce_source`), `scripts/test_population.py` (`red_cases`).

## What happens

The CI invariant (owner 2026-10-04) makes every CI red also a defect in the local gates. When a pull request leaves the
merge queue, the landing lane records BOUNCED and a finisher fixes the branch. Whether the local gate SHOULD have seen
the red is answered only if the finisher thinks to look: Mythos's finisher on PR #880 did, the operator on PR #894 did.
Nothing counts it, and nothing files it. On 2026-10-31 three bounces had three different causes:

- **PR #880, a selection miss.** The 11 failed cases are in the GREEN gate's `not-run-Conformance.txt`, because the
  stale map left the plan unattributed (PB2696, PB4270).
- **PR #894 (twice) and PR #896 with it, a selection miss.** A reflection sweep in `not-run-Unit.txt` (PB4228).
- **PR #893, infrastructure.** A Linux job hung 45 min in `actions/checkout`, with no test run.

## The fix's shape

When the lane reads BOUNCED, it fetches the failed run's failed case names (the trx or the `--log-failed` lines) and
reads the branch's covering gate record. Each red is classed as: SELECTION MISS (a failed case is in a `not-run-*.txt`
of the GREEN run), LOCAL-PASSED (the case ran GREEN locally: a host or tool difference, PB1957's survey), MERGE (the
case is not in the branch's population, or it passes at the branch head: an interaction with main), or INFRASTRUCTURE
(no test failed). The class goes on the BOUNCED line and in `landing_measure.py`. A SELECTION MISS also writes a ready
note body naming the case, the tier that left it out and the plan's attribution state, for the clerk to file.

## Pipeline redesign pointer 2026-10-31 (PB4323)

The pipeline redesign PB4323 keeps this note and implements it in step 8 (PB4331): the landing lane's classification of every merge-group red against the branch's gate record, and the INFRA/RUNNER re-queue once. Status unchanged until that step lands.

**Landed (kb/Work PB4331, step 8 of PB4323).** The classes are the review's section 5.1 ones, not this note's first four: the population gate leaves no SELECTION MISS on Windows, so a red case that ran GREEN in the record is RUNNER (this note's LOCAL-PASSED), one the record lists but did not run is GENUINE, one it lacks is MERGE, and no failed case or a timed-out run is INFRA (this note's INFRASTRUCTURE); unreadable results or record is UNCLASSIFIED. The class is on the watch's BOUNCED line (`land_lane.py status`) and in `landing_measure.py`'s `reds`; INFRA and RUNNER are re-queued once by the lane.
