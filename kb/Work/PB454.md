# PB454 — an Option-2 switch-name is accepted where SET Format 3 admits only a mnemonic-name

Lane-3 adjudication batch b2, group g7-set-a. **Re-run on HEAD `89044aa0`**; still reproduces.

## 1. THE MECHANISM

The SPECIAL-NAMES switch clause has two shapes: **Option 1** names a mnemonic (`SWITCH-1 IS SW1 …`) and
**Option 2** declares only the ON/OFF status condition-names (`SWITCH-1 ON STATUS IS SW-ON …`). SET Format 3
takes `{ mnemonic-name-1 } …`, and Option 2 declares no mnemonic — so **an Option-2 switch cannot be the operand
of a conforming SET statement at all**.

`DataBinder.Switches.cs:499` registers it anyway:

    SwitchMnemonics.TryAdd(ids.Length >= 2 ? ids[1].GetText() : implName, implName);

When there is no mnemonic (`ids.Length < 2`) the **implementor switch-name itself** goes into the mnemonic map,
so `SET SWITCH-1 TO ON` resolves and executes. The choice is documented at `DataBinder.Switches.cs:23-26` as
"legacy-parity leniency (the conforming program cannot SET an Option 2 switch at all, so no conforming program
changes meaning)". That reasoning is sound as far as it goes — nothing *legal* changes meaning — but **the
leniency is unconditional**: it is not gated on `--permissive`, not gated on any dialect axis, and produces no
diagnostic at any `--std`. The strict compiler therefore has no way to refuse a non-conforming program, which
is precisely what `dialect_two_axes` says every leniency must not do.

**Second, smaller half of the same row.** SR5's closing sentence makes the referenceable switch set an
implementor definition, and Annex A.1 item 191 makes it a documentation obligation. `DataBinder` accepts **any**
`cobolWord` as switch-name-1, so the referenced set is simultaneously unbounded and unstated:
`grep -ci switch docs/CONFORMANCE.md` → the word does not appear.

      #     IF SW-ON DISPLAY 'ON' ELSE DISPLAY 'OFF' END-IF.
      ON                                    ← exit 0, NO diagnostic at any --std
      expected: under the default strict dialect, diagnosed — SWITCH-1 is a switch-name (§8.3.2.3.11), an

The control is what makes the leniency safe to gate: it is **not load-bearing for any conforming program**, so
gating it carries no regression risk.

## 4. THE CODE SITE AND THE SHAPE OF THE REPAIR

| arm | file:line |
|---|---|
| the Option-2 registration | `src/Cobol.Net.Compiler/Binding/DataBinder.Switches.cs:499` |
| the comment recording the choice | `DataBinder.Switches.cs:23-26` |
| the SET Format-3 binder | `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/SetAlterBinder.cs:167` `SwitchBindSet` |

⛔ **Do not delete the entry — record its KIND** (CLAUDE.md rule 5). `SwitchMnemonics` is a
`Dictionary<string,string>` whose key silently means two different things: a mnemonic-name (conforming) and a
switch-name (a leniency). A dictionary value carrying `(SwitchName, IsMnemonic)` makes the difference
*expressible*, and then `SwitchBindSet` refuses a non-mnemonic key under the strict dialect and accepts it with
a warning under `--permissive` — the shape every other leniency in this compiler already has. A scalar key
where the rule distinguishes two kinds is the same `model_the_rule_shape_not_one_case` failure as elsewhere in
this group.

The A.1 item 191 half is one documentation row plus a decision about which switch-names are *available*:
today `DataBinder` accepts any `cobolWord`, so either the accepted set is bounded (and documented) or the
unbounded acceptance is itself the documented implementor definition — but it has to be written down.

## 5. THE SIBLING SWEEP THE FIXER MUST DO

* `SwitchConditions` (`DataBinder.Switches.cs:500-501`) is registered from the same loop and is **correct** for
  both options — the condition-names are legal in Option 2. Do not gate those.
* The mnemonic map is also read by DISPLAY/ACCEPT's `UPON`/`FROM` mnemonic route and by the switch-status
  condition binder; a kind-carrying value must be threaded through all of them, not just SET.
* §12.3.7.3 SR8 ("The implementor shall specify the names that are available for switch-name-1, feature-name-1,
  and device-name-1") applies identically to feature-names and device-names — the same unbounded acceptance,
  the same missing documentation row, in the same file.
* [[PB450]] owns Format 3's grammar shape; if the two Formats 3/4 productions are merged there, this note's
  binder change lands in the merged splitter.
