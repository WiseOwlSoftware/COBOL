# PB5692 - is a shared verdict enough to close a row?

**Sites:** none (a measurement by the code-read pipeline; no code file changes).

**The question.** PB5679 D3 records a verdict's provenance: `adjudicated` (the code judged against this rule at this
edition) or `shared` (a line-mate's adjudication, through read-backed as-is relations, with this row's own witness). A
text read sees whether two rules state the same requirement; it cannot see code that branches on `--std` where the
words do not differ, and one witness may not exercise the branch. Today 704 2002 rows (their KEPT records, all from
`tests/version-matrix/lineage-reads-2002/`) and the 1985 KEPT rows close on such a basis; PB5675's measurement found 570
of the 1,373 1985 KEPT records witnessed at 85 for every target.

**Three possible answers.**
1. A shared verdict closes a row, as today, its provenance shown.
2. A shared verdict closes a row only after a mechanical check that the code sites its line-mate's adjudication names do
   not consult the edition (the dialect behaviours and edition checks the compiler facts list).
3. Every row needs its own adjudication on the code at its own edition, at about 0.06 point a row (the 1985 code read's
   rate, as the lead reports it).

**The measurement that decides.** A blind random sample of rows closed today on a shared basis, drawn from the 704 2002
rows and the 570 witnessed 1985 rows (seed recorded), each adjudicated on the code at its own edition by the code-read
pipeline (reader and refuter), counting how many shared verdicts the adjudication contradicts, with a 95 % interval.
The landing paragraph of this note records the sample, the rate, the answer chosen and why.

**Until it is decided.** Rows closed today on a shared basis stay closed as PB5597 and PB5675 close them, and every view
shows their provenance once the switch records it.

**Rows.** None claimed.
