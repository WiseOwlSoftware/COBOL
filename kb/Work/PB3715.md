# PB3715 — an unmeasured worktree reads as a clean one in the synthesized handoff

**Sites:** `scripts/orchestrator/checkpoint.py:117` (`synthesize`, `unmeasured`, `holds_work`; `worktrees` produces the `None` states), `scripts/orchestrator/test_checkpoint.py`, `docs/rearchitecture/DESIGN-orchestrator-loop.md`

## What happens

PB3250 made `worktrees()` report `ahead_of_main: None` when the ahead count is not a number and `uncommitted: None` when git could not read the
status (an existing directory git refuses, a corrupt index, a dubious-ownership refusal): "unknown, never a clean 0". `synthesize()` builds
`branches_pending` from `[t for t in trees if t["ahead_of_main"] or t["uncommitted"]]`, and `None` is falsy. A worktree whose state is
unknown is therefore dropped from the handoff a unit that ended with no valid handoff gets synthesized, the one place that must not lose
an unmeasured branch (its work may be exactly what the crash left uncommitted).

## Fix

Test the states explicitly: include the worktree when either field is `None` or non-zero (`t["ahead_of_main"] is None or t["ahead_of_main"]`,
likewise `uncommitted`), and mark such an entry `unknown` in its report line. Self-test arm in `test_checkpoint.py`: a tree whose status git
cannot read is in `branches_pending`. Sweep the other readers of `worktrees()` for a truthiness test on these two fields.

## Landed (2026-10-25)

Re-probed on the implementer's tree: the self-test's new case (a linked worktree whose `.git` pointer is unreadable, so git
reports neither an ahead count nor a status) showed `synthesize` returning `branches_pending` of `['committed', 'dirty']`
only, the unmeasured `broken` worktree missing, with the old filter put back. Root: `t["ahead_of_main"] or t["uncommitted"]`
reads the unknown state PB3250 introduced (`None`) as clean. Fix: two named predicates in `checkpoint.py`, `unmeasured`
(either field is `None`) and `holds_work` (`unmeasured`, or a non-zero ahead count or uncommitted count); `synthesize`
filters through `holds_work`, and its summary says `N worktree(s) hold work or could not be measured` and names the
unmeasured branches (the handoff schema permits no extra key on a `branches_pending` entry, so the summary carries the
mark). Sibling sweep: `worktrees()` is read only by `build` (writes the rows raw) and `synthesize`; no other reader of
`ahead_of_main` or `uncommitted` exists under scripts/ (the `landing_check.py` and `plan_wave.py` `uncommitted` keys are
their own file sets); `next_unit.py` reads only the `status` of a pending entry. Witness: `scripts/orchestrator/test_checkpoint.py`
(an end-to-end unreadable worktree plus every arm of the state table through both predicates).
