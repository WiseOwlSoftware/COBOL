# PB2564 — one Windows share-retry rule, two copies

Windows refuses to replace, remove or open a file that another process holds open at that instant, because Python
opens files without FILE_SHARE_DELETE. The refusal lasts milliseconds, so readers and writers of shared JSON files
retry it. The rule is written in two places:

- `scripts/gate_slot.py:343-372`: `_SHARE_RETRIES, _SHARE_PAUSE_S = 100, 0.02`, `_read_shared(path)` and
  `_replace_shared(path, text)`. These cover the gate settings file (kb/Work PB2514; callers at lines 277 and 339).
- `scripts/orchestrator/coord.py:130-145`: `_SHARE_RETRIES, _SHARE_PAUSE_S = 100, 0.02`, `sharing_retry(fn)`, used by
  `read_json`, `write_json`, `locked`'s lock removal and `landing_lease.py#release`. Wave 1037 group P (PB2537) added it
  after its silent-failure review measured `os.replace` failing with WinError 5 and `unlink` with WinError 32 while a
  reader held the lease file open. It was not taken from gate_slot.py because those helpers are private and gate_slot
  (a gate script) does not import the orchestrator package, nor the orchestrator gate_slot.

Measured: `grep -rn "_SHARE_RETRIES" scripts` finds exactly these two definitions. No other script under `scripts/`
retries PermissionError around a shared-file replace.

## Harm

The harm is low today, because the two copies are identical. It is the duplication shape of CLAUDE.md rule 4:
lengthen one window, or narrow it to the two winerrors, and the other copy drifts.

## Shape

The retry lives in ONE module that both the gate scripts and the orchestrator may import, for example a small
`scripts/sharedfile.py` (read, replace and remove with the share retry) on the import path both already add.
`gate_slot.py` and `coord.py` call it and delete their copies in the same change, with no forwarder. A drift test
fails on a second `PermissionError` retry loop around `os.replace`, `read_text` or `unlink` under `scripts/`.
