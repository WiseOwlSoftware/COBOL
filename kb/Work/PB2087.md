# PB2087 — group formals copy in and out

**Defect.** `LinkageFormal.CarrierResident` is true only for an elementary, non-REDEFINED formal. A group formal, or a REDEFINED elementary formal, keeps a
callee-local field and round-trips the caller's character image at the activation boundary: copied in at entry, copied out at return
(`DataBinder.Linkage.cs`, the `CarrierResident` remark; `ProgramEmitter.cs` ~575-593 and ~609-623). ISO §14.2.3 GR8 makes a BY REFERENCE formal
and its argument occupy the same storage for the whole call.

**Failure (found by the round-3 to round-5 reviews of DESIGN-external-repository.md; to be reproduced as the first golden).** `CALL "SUB" USING WS-REC WS-REC`;
SUB does `MOVE 5 TO F1 OF LK-1` then `DISPLAY F1 OF LK-2`: prints the old value, must print 5. The same holds for a callback that reads WS-REC while SUB
is active, and for an EXTERNAL record also passed BY REFERENCE.

**Fix (proposed; reuse the existing cell machinery, add no second mechanism).** The repository already has ONE shared, aliasable character storage:
`StorageCell` (`Cobol.Net.Runtime/Control/StorageCell.cs`; its `Ref` image plus its managed SLOTS, PB231), claimed by the one forcer in
`DataBinder.Linkage.cs` (`cls.IsCellBacked = true`) for EXTERNAL records, ADDRESS OF-taken items and ALLOCATEd areas, each reached through Tier-B windows.
1. **Trigger.** A group (or REDEFINED class) that appears as a BY REFERENCE operand of a CALL USING, or a LINKAGE formal group/REDEFINED formal, is claimed
   by the same forcer ("boundary-aliased"): it lives in a StorageCell. Nothing else changes storage, so programs that never pass a group pay nothing.
2. **Crossing.** The argument for such an item carries the StorageCell plus the item's offset and width (a new `CobolArg` shape for areas). It is a
   handle onto the caller's storage, not an image copy.
3. **Callee.** The formal group is a Tier-B window over that cell and offset (its own description laid over the same bytes, so a differently structured
   LINKAGE group of the same length works as §14.8.2.3.2 rule 1 requires). The round-trip loops and `CarrierResident = false` are deleted.
4. **Lenient arms.** A non-cell argument (an elementary item, a literal BY CONTENT, a CALL by data-name carrying an image) keeps today's image copy; that is a
   copy by definition (BY CONTENT/VALUE), or an elementary item that already aliases through its accessors.
5. **Pointer/object leaves.** The cell carries managed slots, so a group with pointer or object leaves aliases too. `ParameterConformance.cs:58-71`
   refuses such groups today; the refusal is removed by this fix.
6. **Cost.** `StorageCell.Ref` is a `string`, so a store into a cell-backed subordinate rebuilds the string, O(width). The author's benchmark: 35 ns at 20
   characters, 273 ns at 2,000, 677 ns at 8,000, 4,041 ns at 32,000, against 11 to 18 ns for an image-leaf today. Only boundary-aliased groups pay, and the
   same price is paid today by every EXTERNAL record. A separate item (not this fix) is a mutable image for large cells; measure real record sizes first.

**Slices.** (a) reproduce the golden and file the failing aliasing set (WS-REC twice, callback, EXTERNAL, REDEFINED formal, ref-mod window); (b) the trigger and
the area crossing in the binder, emitter and runtime; (c) delete the round trip; (d) re-baseline `char_group_move` and `char_redefines` snapshots; (e) the
INVOKE copy-back at `OoEmitter.cs` ~1700 follows in the same slice because methods share the formal convention.
