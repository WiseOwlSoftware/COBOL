# PB2087 — group formals copy in and out

**Defect.** `LinkageFormal.CarrierResident` is true only for an elementary, non-REDEFINED formal. A group formal, or a REDEFINED elementary formal, keeps a
callee-local field and round-trips the caller's character image at the activation boundary: copied in at entry, copied out at return
(`DataBinder.Linkage.cs`, the `CarrierResident` remark; `ProgramEmitter.cs` ~575-593 and ~609-623). ISO §14.2.3 GR8 makes a BY REFERENCE formal
and its argument occupy the same storage for the whole call.

**Failure (found by the round-3 to round-5 reviews of DESIGN-external-repository.md; to be reproduced as the first golden).** `CALL "SUB" USING WS-REC WS-REC`;
SUB does `MOVE 5 TO F1 OF LK-1` then `DISPLAY F1 OF LK-2`: prints the old value, must print 5. The same holds for a callback that reads WS-REC while SUB
is active, and for an EXTERNAL record also passed BY REFERENCE.

**Fix (proposed; reuse the existing cell machinery, add no second mechanism).** The repository already has ONE shared, aliasable character storage:
`StorageCell` (`Cobol.Net.Runtime/Control/StorageCell.cs`; its `Ref` image plus its managed SLOTS, PB231), claimed by the one forcer in
`DataBinder.Linkage.cs` (`cls.IsCellBacked = true`) for EXTERNAL records, ADDRESS OF-taken items and ALLOCATEd areas, each reached through Tier-B windows.
1. **Trigger.** A group (or REDEFINED class) that appears as a BY REFERENCE operand of a CALL USING, or a LINKAGE formal group/REDEFINED formal, is claimed
   by the same forcer ("boundary-aliased"): it lives in a StorageCell. Nothing else changes storage, so programs that never pass a group pay nothing.
2. **Crossing.** The argument for such an item carries the StorageCell plus the item's offset and width (a new `CobolArg` shape for areas). It is a
   handle onto the caller's storage, not an image copy.
3. **Callee.** The formal group is a Tier-B window over that cell and offset (its own description laid over the same bytes, so a differently structured
   LINKAGE group of the same length works as §14.8.2.3.2 rule 1 requires). The round-trip loops and `CarrierResident = false` are deleted.
4. **Lenient arms.** A non-cell argument (an elementary item, a literal BY CONTENT, a CALL by data-name carrying an image) keeps today's image copy; that is a
   copy by definition (BY CONTENT/VALUE), or an elementary item that already aliases through its accessors.
5. **Pointer/object leaves.** The cell carries managed slots, so a group with pointer or object leaves aliases too. `ParameterConformance.cs:58-71`
   refuses such groups today; the refusal is removed by this fix.
6. **Cost.** `StorageCell.Ref` is a `string`, so a store into a cell-backed subordinate rebuilds the string, O(width). The author's benchmark: 35 ns at 20
   characters, 273 ns at 2,000, 677 ns at 8,000, 4,041 ns at 32,000, against 11 to 18 ns for an image-leaf today. Only boundary-aliased groups pay, and the
   same price is paid today by every EXTERNAL record. A separate item (not this fix) is a mutable image for large cells; measure real record sizes first.

**Slices.** (a) reproduce the golden and file the failing aliasing set (WS-REC twice, callback, EXTERNAL, REDEFINED formal, ref-mod window); (b) the trigger and
the area crossing in the binder, emitter and runtime; (c) delete the round trip; (d) re-baseline `char_group_move` and `char_redefines` snapshots; (e) the
INVOKE copy-back at `OoEmitter.cs` ~1700 follows in the same slice because methods share the formal convention.

**Progress — wave 1022 A (the CALL / function arm landed; the INVOKE arm is the open remainder).**
- *Callee.* Every non-resident formal whose area a cell can carry is an AREA formal (`LinkageFormal.IsArea`):
  `DataBinder.PtrBindBasedAndAddressables` claims its class through `ForceStringCanonical` and describes it as a BASED item
  whose implicit data-address pointer IS the formal's carrier field (`__lnk{Uid}`). `CobolArgAdapt.Area` sets that pointer to
  the argument's own area (`CobolArg.Area` — the cell and the offset), so nothing is copied. A fresh cell, filled at entry
  and stored back at return, is used only when the argument has no cell area (BY CONTENT, a BY VALUE formal, a native numeric
  or pointer elementary argument, non-cell storage); `CobolArgAdapt.Aliased` tells the two apart. An omitted argument gets a
  blank cell whose pointer answers `IsNull` (`CellPointer.OmittedArgument`). A variable-length group formal keeps the
  §8.5.1.12 image round trip (`DataBinder.CellCanCarry`).
- *Caller.* The same pass claims onto a per-instance cell every group and every character-class elementary item named as a
  BY REFERENCE CALL USING operand or a user-defined function argument (`CallScanByReferenceOperands`; PB2089 widened it to every item), and
  `CallEmitter.AreaFact` states the area (subscripted and reference-modified operands included); a forwarded area formal
  passes its own pointer.
- *Found and fixed on the way.* A RECURSIVE program's ADDRESS-OF-taken WORKING-STORAGE record failed its type initializer
  (the static cell was declared above the profile fields its seed reads; `ProgramEmitter` now emits the pointer backings after
  the data fields). `ParameterConformance` refuses a strong pointer-leaf group only when it does not cross BY REFERENCE from a
  cell.

**Landed (wave 1024 A — the INVOKE arm, finishing wave 1023 A).** A method formal crosses as its argument's carrier,
area and presence flag (`OoSignatureOf` / `OoArgPair`), a resident formal aliases per access through its carrier and an
area formal is laid over the argument's cell (`CobolArgAdapt.Area`), typed and universal lanes alike (wave 1023 A's
commits, re-applied on main). The four reds that held it back, each fixed at its root:
- *A strong group with an object-reference leaf in a cell* (`pb1116_strong_group_object_leaf`, `pb177_method_group_boundary`):
  `PlaceRenderer.GroupLeaves` / `WriteGroupLeaves` rendered `Read(place).AsLeaves()`, which only a record struct has. A
  cell-backed group (an area formal, a group claimed because it is passed BY REFERENCE) now composes and distributes its
  leaf vector member by member through `PlaceCursor`, in the record struct's field order (native numerics through
  `NumericRenderer.CarrierOfImage` / `ImageOfCarrier`, object references through the managed slots); §13.18.44.3 SR14
  keeps every REDEFINES out of a strongly-typed group, so the field order is fixed.
- *Recursion* (`OoSpineTests.MethodRecursion_ViaObjectRefFormal_ReentrantLocals`): a method's per-activation cell
  (LOCAL-STORAGE claimed onto a cell) and an area formal's pointer are instance members re-seated at every activation
  (§8.6.4), and the caller's view rendered them at each access, so the inner activation of the same method read ITS OWN
  item through the outer formal (`AT-03 / AT-00`). Root: the cell is a run-time address fragment, so
  `PlaceIdentification.Freeze` (§14.6.4 7; §14.9.23.4 GR7 a; §14.9.4.4 GR3 a) now holds a cell-backed class's
  `StorageCell` in a statement-local and re-anchors the backing and the codings on it — CALL, INVOKE, INSPECT, STRING and
  UNSTRING alike. The CALL twin (a method passing a LOCAL-STORAGE item to a program that INVOKEs it again) was the same
  defect on main and is fixed by the same change.
- *A fixed group in a cell meeting a variable-length group* (`pb965_fixed_group_vlg_invoke`): `OoEmitter.FixedArgumentSpans`
  excluded every `RedefViewPlace`, so a fixed argument claimed onto a cell lost its §8.5.1.12 correspondence (the CALL
  twin `CallEmitter.BoundaryLayout` already admitted views). Sibling fixed in the same change: the RETURNING delivery of a
  variable-length returning item into a fixed receiver in a cell (`recv is not RedefViewPlace`).
- *Witnesses.* `conformance:2002/pb2087_invoke_by_reference_aliasing` (wave 1023 A),
