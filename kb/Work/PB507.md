# PB507

## Mechanism — blank-when-zero-clause
bwz-syntax-rules-unenforced - the BLANK WHEN ZERO clause has NO validator anywhere in the typed-native compiler. DataBinder.BindEntry consumes blankWhenZeroClause as a bare `blankWhenZero = true` (src/Cobol.Net.Compiler/Binding/DataBinder.cs:2306-2307) and every later reader only USES the flag (PictureAnalyzer's GR2 promotion, ArithmeticEmitter.BwzFlag, RuntimeApi.EditCompose, ValueInitializer, GroupImageCodec). Nothing checks the subject's category, its elementary-ness or its usage, so BOTH syntax rules of 13.18.8.3 are unenforced. The rule was written down once, in the LEGACY engine (src/CobolSharp.Compiler/Semantics/DataItemClassifier.cs:118-135, CBL0802 for the category/usage rule and CBL0804 for the JUSTIFIED combination), and was never ported to the greenfield binder - the classic two-arm shape, and the reason the legacy differential net cannot see it either: the legacy arm rejects, the greenfield arm accepts, and no greenfield test asserts a reject.

### Expected, from the standard
ISO/IEC 1989:2023 13.18.8.3 SR1 - "The BLANK WHEN ZERO clause may be specified only for an elementary item described by its picture character-string as category numeric-edited or as numeric without the picture symbol 'S'." - and SR2 - "The subject of the entry shall be implicitly or explicitly described as usage display or usage national." (both validated with scripts/spec/cite.py --check 13.18.8.3). Each of a1 (category alphanumeric), a2 (numeric WITH 'S'), a3 (usage COMP - neither display nor national) and a4 (a group, not an elementary item) is a syntax-rule violation and shall be diagnosed at every edition. At COBOL-85 SR2 admits usage display only, so a3 is a violation there too.

```
$ python scripts/spec/cite.py --check 13.18.8.3 "The BLANK WHEN ZERO clause may be specified only for an elementary item described by its picture character-string as category numeric-edited..."
  OK  §13.18.8.3 1)  (Syntax rules)
```

### Observed
All four compile clean with NO diagnostic at all four editions and the clause is silently ignored: a1 prints `A1     `; a2 prints `A2[0000{]` (MOVE 0 stored a signed display zero, no blanking); a3 prints `A3[00000]`; a4 prints `A4[000000]`. c1 prints `J[     ]` where the legacy engine reports CBL0804. Grep of `blankWhenZero|BlankWhenZero|BLANK WHEN ZERO` over src/Cobol.Net.* returns producers and consumers only - no diagnostic site - and DiagnosticCatalog has no BLANK WHEN ZERO descriptor. The clause's own DECLINED arm (a screen description entry, COBOLNET1560 / Annex A.4.2 / kb/Work PB260, witness tests/conformance/negative/a42-screen-blank-when-zero.cob) is unaffected and is not what this finding is about.
