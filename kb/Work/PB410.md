# PB410 — two arms, both wrong, in opposite directions

**Row:** `SR-14.9.18.3-5`. Both measurements below were re-run on this worktree's HEAD `cobol.exe`
(base 89044aa0).

## THE MECHANISM

`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/CallBinder.cs#BindGoback` (`:492-494`) forks on
`host.InMethod`, and SR5 is answered differently on each side of that fork:

- **Non-method arm** — `Binding/Procedure/Verbs/EcBinder.cs#EcBindRaising` (`:159`) handles
  `raising.LAST()` at `:163` by returning a `BoundRaising` immediately. There is no placement test anywhere on
  this path, in the grammar, or in `VersionConformancePass`. `RAISING LAST` is accepted in any paragraph of any
  program.
- **Method arm** — `Binding/Procedure/Verbs/OoBinder.cs#OoBindMethodRaising` (`:1056`) tests
  `raising.LAST() is not null` at `:1059` and **always** raises `DiagnosticCatalog.OoMethodRaisingLast`
  (COBOLNET0899), whose message text names the two positions SR5 admits and then rejects the statement anyway.

So the rule is enforced nowhere it applies and enforced everywhere it does not. The extra twist is that
**the correct answer is the SAME predicate on both arms** — SR5 has no method qualifier — so the repair is one
placement test at the shared bind site, not two.

The inputs a correct test needs are already tracked and already read by the sibling verb for the identical
rule: `EcBinder.cs:104` reads `ctx.EcState.InF3When` for the PERFORM-WHEN case and `:113` looks up
`ctx.Table.Declaratives` for the declarative case, both in the service of RESUME's placement rule.

## THE RULE, QUOTED, WITH ITS `--check` LINE

- `--check 14.9.18.3 "The LAST phrase may be specified only in a declarative procedure"` →
  `OK §14.9.18.3 5)`. Rule 5, in full: "The LAST phrase may be specified only in a declarative procedure or WHEN
  phrase of a PERFORM statement."
- `--check 14.9.33.3 "declarative"` → `OK §14.9.33.3 1)`. RESUME's rule 1: "The RESUME statement may be
  specified only in a declarative or in an imperative statement in a WHEN phrase of an exception-checking
  PERFORM statement. …" — the same two positions, already implemented, at `EcBinder.cs:104` and `:124`.
  (⚠ the b2 finding attributed RESUME's rule to SR2; it is rule 1. Re-derived here.)
- `--check 4.2.2 "syntax"` → `OK §4.2.2` — a syntax-rule violation owes a compile-time indication.

Note SR5 says "declarative procedure", not "declarative procedure of a program": nothing in §14.9.18.3 makes
the rule weaker or stronger inside a method, and §14.9.18.4 GR4 makes a method's GOBACK a GOBACK.

## EXPECTED vs OBSERVED — re-measured on HEAD

`cobol.exe <src> --std 2023`.

**(a) Non-method arm — illegal source accepted.**
`scratchpad/probe-g3-goback-goto/fmt/sr5.cob` is a five-line main program whose paragraph `MAIN` contains
`DISPLAY "ran".` and `GOBACK RAISING LAST EXCEPTION.` — an ordinary nondeclarative paragraph, neither of SR5's
two admitted positions.
**Expected:** rejected, citing §14.9.18.3 rule 5. **Observed:** compiles CLEAN, no diagnostic.

**(b) Method arm — legal source rejected.**
`scratchpad/probe-g3-goback-goto/sr/sr5m2.cob` puts `GOBACK RAISING LAST EXCEPTION` inside
`PERFORM RAISE EXCEPTION EC-USER-DEMO WHEN EC-USER-DEMO … END-PERFORM` in method `M1` of class `CSR52` — a WHEN
phrase of a PERFORM statement, one of the two positions SR5 names.
**Expected:** accepted. **Observed:**

```
sr5m2.cob(29,9): error COBOLNET0899: GOBACK RAISING LAST EXCEPTION inside a method: LAST is legal only
within a declarative or a PERFORM WHEN (ISO §14.9.18.3 SR5) — method declaratives are a later refinement
of the EC-OO wave
```

The diagnostic states the rule the source obeys and rejects the source for obeying it.

## THE SHAPE OF THE REPAIR

⛔ Not two `if`s (CLAUDE.md rule 5). SR5 and §14.9.33.3 rule 1 are **the same predicate over the same two
tracked inputs**, asked today by two different verbs in two different files — and PB410's own evidence is that
writing it a second time is how it got written wrong. Extract one placement predicate
(`InDeclarativeOrPerformWhen`, over `ctx.EcState.InF3When` + `ctx.Table.Declaratives`) and have RESUME, the
non-method GOBACK arm and the method arm all call it, each supplying its own citation for the diagnostic.
`feedback_one_rule_one_place`: a single construct failing usually means one rule written down in more than one
place, and the extraction IS the fix.

`OoBindMethodRaising`'s unconditional reject then deletes; what remains behind it — "method declaratives are a
later refinement" — is a genuine and separate gap (the declarative position is unavailable inside a method
until method declaratives land), but it must not swallow the PERFORM-WHEN position, which works today.

## THE SIBLING SWEEP

1. **`EXIT … RAISING LAST`** — §14.9.14 Format 2 carries the same raising phrase through the same
   `EcBinder.cs#EcBindRaising`, so the non-method under-enforcement is two verbs wide. `probe/sr6-raising-last-outside`
   and `probe/sr6b-goback-raising-last-outside` are the existing shapes.
2. **The method arm of EXIT** — `OoBinder.cs#OoBindMethodRaising` is called with `verb` for both GOBACK and the
   method EXIT forms; one predicate fixes both.
3. **A green test stands on the illegal shape and must be re-pointed, not preserved.**
   `tests/Cobol.Net.Tests.Conformance/ExceptionConditionConformanceTests.cs:769`
   (`GobackRaisingLastException_PropagatesTheLastStatus`, ECT028) writes `GOBACK RAISING LAST EXCEPTION.` in the
   ordinary paragraph `SUB-PARA` — exactly probe (a). It is also the fixture [[PB408]] must re-baseline for a
   different reason; the two fixes meet in that file and should be sequenced.
4. Edition sweep at 2002/2014/2023 for the new diagnostic; RAISING is a 2002 introduction, so 85 must be
   unaffected.
5. Goldens: a negative fixture for probe (a), and a POSITIVE golden for probe (b) plus the declarative position,
   in both a program and a method — the positive half is what would have caught the method arm.
