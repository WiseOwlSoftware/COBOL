# PB1652 — OPEN

Filed 2026-09-27 by the train-66 lander from the wave-66 J implementer report (PB1244 + PB1245).

**The determination.** PB1244 made GROUP INDICATE a per-detail-group condition (`ReportGroup.GroupIndicatePending`,
`src/Cobol.Net.Runtime/IO/ReportWriter.cs`, `GenerateCore`'s detail arm). The condition is consumed by every
GENERATE of the group, including one whose presentation is suppressed by SUPPRESS (§14.9.45) or whose lines are all
absent under PRESENT WHEN. The reading is §13.18.28.4 GR1's own words: the condition is "true only on the first
occasion that a GENERATE is issued for the current detail group" (`cite.py --check 13.18.28.4` OK 1)), which counts
GENERATEs issued, not presentations printed. It is a spec reading, not implementor latitude.

**The gap.** No golden exercises that arm. `tests/conformance/2002/pb1244_group_indicate_per_detail_group` covers
two details, relative COLUMN and all three re-arming events, but never a GENERATE that prints nothing.

**Work.** Add a golden in which a detail's first GENERATE after INITIATE is SUPPRESSed (a USE BEFORE REPORTING
declarative that executes SUPPRESS PRINTING), and its second GENERATE prints the line with the indicated item
absent; add the matching PRESENT WHEN variant. Derive every expected line in the header from GR1.
