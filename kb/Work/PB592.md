# PB592 — OPEN — a determination that denies an element the compiler provides

Found by the golden-lane round-3 `dns-witness` writer while deriving `DOC-A.1-206`'s witness, and **re-derived
independently by the lander before this note was filed** (the writer's reading of the rendered PDF, the lander's
reading of the Markdown transcription, and the lander's runtime probe agree). This blocks the witness the
`PB373` row owes, so the draft `pb373_binary_usage_range_bounds.cob` / `.out` was **NOT landed**; it is parked in
`E:\Temp\claude\E--CobolSharp\a9d94900-79fe-4a38-89f0-921976861543\scratchpad\lane1\out\dns-witness\tests\conformance\2023\`.

⚠ **The compiler is CONFORMING either way.** GR12 says in terms *"The implementor may allow a wider range"*.
The defect is in the DETERMINATION, and the consequence is a documentation duty, not a miscompile.

## Mechanism 1 — the band's lower bound is EXCLUDED, so -2\*\*(w-1) is already wider than the minimum

`specs/ISO_COBOL.md` §13.18.60.4 GR12: *"The minimum range requirements for each of these usages are shown
below. Any integer value of n within the specified range shall be expressible in the given usage. The
implementor may allow a wider range."* The table it introduces is **asymmetric**, and the asymmetry is the whole
content of the rule:

```
| BINARY-CHAR   SIGNED   | -128 [-2**7]   | < n < | 128 [2**7]   |
| BINARY-CHAR   UNSIGNED | 0              | £ n < | 256 [2**8]   |
| BINARY-SHORT  SIGNED   | -32768 [-2**15]| < n < | 32768 [2**15]|
| BINARY-SHORT  UNSIGNED | 0              | £ n < | 65536 [2**16]|
| BINARY-LONG   SIGNED   | -2147483648    | < n < | 2147483648   |
| BINARY-LONG   UNSIGNED | 0              | £ n < | 4294967296   |
| BINARY-DOUBLE SIGNED   | -2**63         | < n < | 2**63        |
| BINARY-DOUBLE UNSIGNED | 0              | £ n < | 2**64        |
```

Every SIGNED row prints a **strict** `<` on BOTH sides; every UNSIGNED row prints the unmapped Adobe-Symbol
`lessequal` (transcribed `£`) on the left. The writer rendered the canonical PDF page 537 (printed 507) with
`scripts/render-spec-page.py` and confirmed by PyMuPDF `rawdict` that the SIGNED rows' left operator is a real
U+003C while the UNSIGNED rows' is the unmapped 0xA3 — the lander re-read the Markdown transcription, which shows
the identical `< n <` / `£ n <` split, so the two independent readings agree.

The standard corroborates the reading from inside its own text: §15.58.4's NOTE tabulates
*"BINARY-CHAR SIGNED | -128 (assuming an 8-bit twos-complement representation)"* — the "assuming" is the standard
conceding that -128 is representation-DEPENDENT, which is exactly what an open interval says. The asymmetry is
deliberate: it admits sign-magnitude and ones'-complement machines.

**So the required minimum SIGNED bands are -127..+127, -32767..+32767, -(2\*\*31-1)..+(2\*\*31-1),
-(2\*\*63-1)..+(2\*\*63-1)**, and `-2**(w-1)` is OUTSIDE every one of them.

**What the compiler does.** Probed on this tree (2026-09-05, `--std 2023`):

```cobol
01 BCS  USAGE BINARY-CHAR.
01 BSS  USAGE BINARY-SHORT.
01 WS-N PIC S9(21) SIGN IS LEADING SEPARATE.
MOVE -128 TO WS-N.
COMPUTE BCS = WS-N ON SIZE ERROR DISPLAY "OUT-OF-RANGE"
                   NOT ON SIZE ERROR DISPLAY "IN-RANGE" END-COMPUTE.
```
```
CHAR-M128=IN-RANGE          CHAR-M128-VALUE=-128
SHORT-M32768=IN-RANGE       SHORT-M32768-VALUE=-32768
```

Three independent sites make it the native two's-complement band, so this is a deliberate design, not a slip:
`src/Cobol.Net.Runtime/Values/Numeric/CobolNum.cs` `InBinaryRange` (`value >= -half && value < half`) and
`WrapBinary`; `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs` `BindAlgebraicFold`
(`LOWEST-ALGEBRAIC = -(BigInteger.One << (bits - 1))`); and two landed goldens already ship the proof —
`tests/conformance/2002/binary_usage.out` (`BCNEG=-128`) and
`tests/conformance/2023/l1_lowest_algebraic_value_rule.out` (`BINCHAR-SIGNED=-000128.000`).

Each SIGNED usage therefore expresses **exactly one value beyond the GR12 minimum**. Annex A.1 item 206's
optional element *is* provided. A.1's preamble (*"Documentation required: If the element is provided by the
implementor, the implementor's user documentation shall document the element …"*) plus §4.2.5 then make
documenting it an obligation — and line 980 currently denies it.

## Mechanism 2 — `±128` is not a range, so nothing can be derived from the cell

The cell reads `CHAR ±128 / 0–255 · SHORT ±32768 / 0–65535 · LONG ±2^31 / 0–2^32 · DOUBLE ±2^63 / 0–2^64`. Read
as an inclusive range, `±128` is -128..+128 and admits **+128**, which no container holds; read as GR12's band it
**excludes -128**, which the compiler stores. The same ambiguity admits +32768, +2\*\*31, +2\*\*63, 2\*\*32 and
2\*\*64. A determination that pins a RANGE has to state its endpoints unambiguously, because whether the endpoints
exceed GR12's *is* the whole content of item 206.

## The repair (owner decision — the VERDICT is not the lander's to change)

Replace line 980's determination cell with:

> **Provided, minimally.** GR12's minimum bands are SIGNED `-2**(w-1) < n < 2**(w-1)` and UNSIGNED
> `0 <= n < 2**w` (both upper bounds, and the signed lower bound, excluded — ISO/IEC 1989:2023 printed page 507).
> COBOL.NET provides the native two's-complement band: BINARY-CHAR SIGNED -128..+127, UNSIGNED 0..255;
> BINARY-SHORT SIGNED -32768..+32767, UNSIGNED 0..65535; BINARY-LONG SIGNED -2147483648..+2147483647,
> UNSIGNED 0..4294967295; BINARY-DOUBLE SIGNED -9223372036854775808..+9223372036854775807,
> UNSIGNED 0..18446744073709551615. Each SIGNED usage therefore expresses exactly one value beyond the GR12
> minimum, `-2**(w-1)`; the four UNSIGNED usages are exactly the minimum.

⛔ **The row's VERDICT is an owner decision.** `DOCUMENTED-NON-SUPPORT` was recorded by owner decision
`kb/Work/PB280` Q1 on the premise that the optional element is *not provided*; mechanism 1 says it **is**. Whether
the row becomes a support claim or stays a declined row with a corrected cell is not an agent's call, so nothing
here has been changed in `docs/CONFORMANCE.md` or in the inventory row.

Once the cell is repaired the held draft is landable essentially as written: its Part A measures GR12's own
requirement at both edges of all eight bands through a data-item round trip, Part B measures GR12's nesting
sentence against each narrower usage's `LOWEST-ALGEBRAIC`, and Part C reports the twenty dispositions the
determination fixes — with §14.7.5 case 3 and GR2 making an ON SIZE ERROR firing mean *"this value is not
expressible in this usage"*.
