# PB138

Rows: GR-14.9.9.4-1 (DIVERGES), SR-14.9.9.3-1 (DIVERGES), SR-14.9.9.3-2, findings [CONTINUE statement]/[continue-statement].

(1) Visit(BoundContinueAfter) emits only CobolTiming.ContinueAfter; ExceptionState.Set records but never routes through EcDispatchExpr — exception_statement_ambient.g.cs's matcher returns pc 1 for the EC and __EcPerform is called once, on the SEARCH path: the handler is dead code, invisible because the golden's WHEN body is CONTINUE (green test holding the gap open). EC-RANGE-SEARCH-NO-MATCH proves the per-site omission. (2) ContinueAfter clamps AFTER `(long)seconds` — the refuter corrected the adjudicator's x64 claim (.NET 9+ saturates, so the 1e20 case DOES sleep) but the clamp order stays wrong for NaN ((long)NaN → 0 → silent no-suspend instead of EC-DATA-NOT-FINITE) — clamp in double, screen non-finite. (3) The interval is delivered as binary64 on every path, so 0.999… rounds to a 1-second suspension where GR1's implicit COMPUTE WITHOUT ROUNDED truncates to 0 — truncate at the emitter where the scale is known. (4) DeclIsTrivialExit classifies `st.continueStatement()` — including CONTINUE AFTER, a SUSPENSION — as a pure exit, and DeclHandlerEndPc then ends a USE handler's dispatch AT that paragraph: 'HANDLER RAN' never prints in the row's repro; the code comment calls it a 'documented deviation' but it is registered NOWHERE. Also EcBinder.cs:376 cites §14.9.8.4 GR4 (COMPUTE) for CONTINUE — the citation sweep (PB159).
