# PB211

Found by the PB169–PB172 burn-down cluster's funnel-entry sweep (2026-08-31), in the same pass that found
[[PB210]]. `SearchBinder` resolves the VARYING operand with `ctx.Refs.Resolve(v)` and applies no class rule.
ISO §14.9.37.3 syntax rule 5 (`cite.py --check 14.9.37.3 "Identifier-2 shall reference a data item whose usage
is index or a data item that is an integer"` → OK) closes the list to exactly two shapes.

⚠ MEASURE BEFORE BELIEVING: the sweep located the mechanism by reading the call chain, and the cluster's own
re-verification found TWO of four such reading-derived claims wrong on the tree they were derived from. Probe
`SEARCH … VARYING <PIC X item>` and `SEARCH … VARYING <scaled numeric item>` before writing the fixture's
expected verdict — if a later pass already special-cases it, the fixture would pin the wrong answer.

WHAT WOULD CLOSE IT: the position's screen at the SEARCH binder over the ONE classifier (usage index OR a
scale-0 numeric item), negative fixtures for the excluded shapes, a golden for both legal ones, and a row in
the funnel entry-point table (`DESIGN-binder-bound-tree.md` §3.6).

## 2026-09-04 — lane-3 adjudication batch b2 discharged this note's "measure before believing"; the row stays PB211's

**Row claimed: `SR-14.9.37.3-5`.** This note's own ⚠ warned that the gap was located by READING the call chain
and demanded measurement before a fixture pinned an expected verdict. The b2 SEARCH adjudication did that, and
every probe below was then **re-measured on this worktree's HEAD `cobol.exe` (base 89044aa0)**. The
reading-derived claim is confirmed. No second note was opened; the row is PB211's.

`--check 14.9.37.3 "Identifier-2 shall reference a data item whose usage is index or a data item that is an integer"`
→ `OK §14.9.37.3 5)`, and
`--check 14.9.37.3 "shall not be subscripted by the first or only index-name"` → `OK §14.9.37.3 5)` — the same
rule 5, which is **two sentences**.

**Sentence 1, measured** (`cobol.exe <src> --std 2023 --run`, probes in `probe/search1/`):

- `sr5_nonint.cob` — `01 NONINT PIC 9(2)V9`, numeric but NOT an integer: compiles clean, prints `HIT` / `DONE`.
  Same at 85 (`sr5_nonint_85.cob`).
- `sr5_float.cob` — `01 FLT USAGE FLOAT-SHORT`, neither index nor integer: compiles clean, prints `HIT` / `DONE`
  (at 85 it is blocked only by the unrelated COBOLNET0900 edition gate on FLOAT-SHORT).
- `sr5_alnum.cob` (`PIC X(4)`) and `sr5_group.cob` (a group) are not diagnosed either — they reach a RUN-TIME
  `NotImplementedCobolFeatureException: arithmetic into a non-fixed-point target`, which names the wrong problem
  at the wrong stage.

**Sentence 2 is a half this note does not mention, and it is the one that changes an answer.**
`sr5_selfsub.cob` writes `SEARCH E VARYING K(IX)` where `IX` is `E`'s own first index: it compiles clean at
2023 (and 85, `sr5_selfsub_85.cob`) and the run prints `NONE` where the same program with a legal VARYING
operand prints `HIT`. The illegal spelling silently produces a different result.

**When this note is landed its scope must cover BOTH sentences** — the usage/integer screen AND the
self-subscript prohibition, which needs the OCCURS INDEXED BY list of identifier-1, not just a class test. A
screen written to this note's title alone would leave sentence 2 open. §4.2.2 owes the compile-time indication
for both.
