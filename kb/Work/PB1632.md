# PB1632 — LANDED 2026-09-27

Filed 2026-09-26 by the train-64 lander from the wave-62 P (PB1630) implementer's report, lead 1.

## Repro
`E:\Temp\claude\E--CobolSharp\ba65f072-4d30-4868-9bd3-4e5c60087107\scratchpad\w62p\probe\lead-addr-self.cob`:
`SET WP TO ADDRESS OF WP` then `CALL "PLA2" AS NESTED USING BY CONTENT WP` → the COMPILER throws
`InvalidOperationException: no character image for category Pointer on 'WP'`.

## Rule
§14.8.2.3.3 2): "If the formal parameter is of class pointer or an object reference described without the
ACTIVE-CLASS phrase, the conformance rules shall be the same as if a SET statement were performed" — a pointer
argument BY CONTENT into a pointer formal is legal; §14.2.3 GR9/GR10 give it a copy.

## Code sites
`src/Cobol.Net.Compiler/CodeGen/Verbs/CallEmitter.cs:898` `CallPlaceIsManaged` (`p is not RedefViewPlace`): once
the pointer's address is taken it is cell-backed (addressable storage), the predicate answers false and the argument
goes to the Text crossing, which asks `OperandText` (`src/Cobol.Net.Compiler/CodeGen/Emit/OperandText.cs:513`) for a
character image a pointer does not have. Own root; not PB1630's. Sweep the object-reference / program-pointer /
function-pointer twins and BY VALUE.

## Landing (2026-09-27)

**Root.** A cell-backed area (BASED, EXTERNAL, or ADDRESS OF taken) renders EVERY member as a `RedefViewPlace`,
and a managed member's view carries the `SlotWindow` coding: it is the item's own storage. `CallPlaceIsManaged`
excluded every `RedefViewPlace` by shape, so the ONE classifier `CrossingOf` fell through to Text. That affects
every crossing it drives: BY CONTENT snapshots, the BY REFERENCE/RETURNING accessor, and INVOKE.
**Fix.** The predicate now asks the coding: `(not RedefViewPlace and not RefModPlace || RedefViewPlace { Coding:
SlotWindow }) && SlotWindow.CarriedBySlot`, which is the rule `CallPlaceIsVarGroup` already applies to
`VarGroupWindow`. `PlaceRenderer.Read`/`Write` already render the slot window, so no new rendering was needed.
The design doc (`COBOLNET_INTERPROGRAM_DESIGN.md`, managed-slot section) now states the rule.
**Sweep.** Data pointer (self-addressed, and BASED), program-pointer with ADDRESS taken, BY CONTENT and BY
REFERENCE: all cross correctly. Object references ride the same predicate (`CarriedBySlot` includes
ObjectReference). BY VALUE takes the same snapshot arm as BY CONTENT. An EXTERNAL pointer is illegal source
(COBOLNET1796, §13.18.22.3 SR4), and so is a pointer subordinate to a BASED group (COBOLNET1724).
**Golden.** `tests/conformance/2002/pb1632_pointer_arg_cell_backed` (the expected lines are derived from
§14.8.2.3.3 2) and §14.2.3 GR8/GR9).
