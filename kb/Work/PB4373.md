# PB4373 - The margin-R note can state a margin other than 72

**Sites:** `src/WiseOwl.Cobol.Frontend/Common/MarginRCut.cs` (`MarginRCut.Margin`, line 20 at the filing; computed through `PhysicalLine.ColumnOf`) and the message text that calls it "position". PB2555 is OPEN and BOUNCED (PR #961); the file lands with it.

`Margin` is the PHYSICAL column of margin R, as `PhysicalLine.ColumnOf` counts characters. Its doc comment calls it "equally the 1-based POSITION of the last position of the program-text area (72)". On a line holding a tab or a supplementary-plane character the column and the position differ, so the note prints a margin other than 72, which contradicts the descriptor's "position 72 here".

Fix: state the margin as the position (72 by the format's definition, per the fixed-form position rule), or carry both and print the one the user can count in their editor. Pin with a line holding a tab before margin R.

## 2026-11-01 - landed

Re-probed on the wave-20261808 build: a CALL line opening with a tab (the tab fills positions 1-8, DOC-A.1-157) and cut at margin R
printed "it ends at position 65 ... (positions 66 to 81)" for a margin the format fixes at 72. Fixed at the root: `MarginRCut` now
carries the physical `Column` (the location's unit, PB2983) and the `LastProgramTextPosition` the reference format fixes (72,
`FixedFormLine.MarginR`), so the message states position 72 and positions 73 to 88; a line whose column differs from its position
says so ("a tab counts the positions it fills, so the column this warning names, where the file holds the cut, is less than that"). Siblings fixed in
the same change: `LastCutPosition` and the 24-character quote of the cut text counted UTF-16 units, so a cut holding a
supplementary-plane character stated one position too many and could quote half a surrogate pair; both now count characters
(`CharacterPositions`). Pinned by three tests in `MarginRCutNoteTests`.
