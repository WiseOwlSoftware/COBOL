# PB900 — LANDED — the audit that can say the wrong thing, and the quotation no audit reads

## LANDED — 2026-09-21 (wave 42 group G, worktree `wf_031fc86a-7dd-6`, base main `4da7ba02d`)

**Both arms built; arm A was built as a VETO rather than as `_owning_cite`, and the difference is measured
rather than argued.**

* **Arm A — the ordinal arm's attribution.** The note asked for `_owning_cite`, the format-name arm's
  repair, applied to rule designators. It was implemented instead as `_another_clause_admits` — a VETO —
  because the two citations are not the same kind of claim and the measurement says so. Spelling a format's
  three-part NAME is a claim about ONE citation, so re-attributing by position is right for it. A rule
  designator is written once and REFERRED BACK TO in the same sentence (`§14.9.18.4 GR1 b) asks the
  ACTIVATOR; the >>TURN directive (§7.3.25.4) records it, and GR1 b) is therefore …`) and it is chained
  (`GR4/GR6/GR9`), so position cannot separate the claim from the back-reference. Three readings of the same
  corpus, measured on this tree:

  | attribution | findings |
  | --- | --- |
  | nearest-left, no veto (as shipped) | **209** |
  | nearest-left + the veto (landed) | **170** |
  | JOIN-ONLY — attribute only when nothing but punctuation or a `Format n` separates the designator from its clause | **54** |

  A narrowing of the attribution can only DROP a finding, never add one, so join-only's 54 are a SUBSET of the
  170: it buys its quiet by discarding 116 accusations that no second clause on the line can rescue. The veto
  drops exactly the 39 sentences where some clause the line already names admits the ordinal — the shape train
  37 measured on PB408's comment (203 → 204, then re-spelled to work around the audit). **The workaround can
  now be un-spelled; the defect is out of the audit.** `ORDINAL_SELF_TEST` carries that exact line as a firing
  SUBITEM defect and its two-clause twin as the silent case.

* **Arm B — the elided quotation.** Built in `audit_doc_citations.py`, not as a new "VERBATIM arm over src":
  that audit ALREADY reads `src` through `citation_corpus.all_files()` (the note's "it does not read src" was
  stale — PB3's fabricated GR7 k3 put the source comments in that glob), and the two sites were invisible for a
  different reason. A quotation `--find` locates NOWHERE lands in `absent`, the bucket this audit deliberately
  does not gate on, because a doc quotes labels and paraphrases too. `elided_window` decides the one shape
  inside that bucket that IS decidable: the clause's OWN sentence with words dropped — the quote's words appear
  IN ORDER inside the clause, in a window no more than half again as long. A paraphrase cannot pass it (its
  words are not in order) and neither can a label (the 5-word floor), which is what makes the arm gateable.

  **Its first harvest was eight sites, six of them real** — the two the note names plus four it did not know
  about, each repaired against the standard's own words and each `--check`ed:

  depends on which of two identical-looking characters the author typed is not a convention, so both spellings
  are now the marker.

* **⛔ AND THE ARM WAS DRIVEN BY NOTHING WHEN IT WAS WRITTEN** — the finding of this note's own landing.
  `audit_doc_citations.py --self-test` re-implemented the MISFILED ruling in four lines of its own beside

## Arm A — the ordinal arm's attribution is LINE-scoped

Train 36 found the same shape for FORMAT NAMES: PB388's new check tested whether the WHOLE LINE spelled any

work around it and the count returned to 203. **The workaround is in the comment; the defect is in the
audit.**
