## 1. The mechanism

`initializeCategory` (`src/Cobol.Net.Frontend/Grammar/Core/CobolData.g4:708-716`) is a **single-alternative rule
naming five words** — ALPHABETIC, ALPHANUMERIC, NUMERIC, ALPHANUMERIC[-]EDITED, NUMERIC[-]EDITED. The printed
general format draws category-name as **thirteen** alternatives enclosed by a brace with a pair of choice
indicators immediately inside it. Two axes are wrong at once, from one scalar-where-a-set-belongs shape:

* eight legal category words cannot be written at all (BOOLEAN, DATA-POINTER, FUNCTION-POINTER, MESSAGE-TAG,
  NATIONAL, NATIONAL-EDITED, OBJECT-REFERENCE, PROGRAM-POINTER);
* **no** category-name may name more than one category, at any edition including 85, where the classic five
  already exist — so `REPLACING NUMERIC ALPHANUMERIC DATA BY SPACE` is a parse error at 85 too.

The rule's own comment blames "lexer tokens not yet defined". That is **stale**: `NATIONAL`
(`CobolLexer.g4:587`), `PROGRAM_POINTER` (`:393`) and `FUNCTION_POINTER` (`:394`) are already tokens. The bound
model is ahead of the grammar in one direction and behind in another —
`BoundInitialize.cs:54 enum InitializeCategory` carries ten of the thirteen (no NationalEdited, no
FunctionPointer, no MessageTag), and `PicInfo.cs enum PicCategory` has no NationalEdited member at all.

Two further shape inversions sit in the same two rules, in opposite directions:

* `initializeCategoryToValue` (`CobolData.g4:682-684`) is written `(ALL | initializeCategory)? TO VALUE`. The
  `?` makes a **braced required choice optional** — a bare `INITIALIZE G TO VALUE` compiles. The binder's own
  comment defends this at `InitializeBinder.cs:24` by citing a "note 2" of the general-format clause **that
  does not exist** — that clause carries no notes, and the general rule that does mention ALL answers a
  different question (what ALL *means*, not whether the choice may be omitted). It is additionally **pinned
  green**: `tests/conformance/2002/initialize_phrases.cob` contains the line `INITIALIZE GRP TO VALUE.` and its
  `.out` golden records the result, so the corpus currently defends the over-acceptance.
* `TO` is required in both `initializeCategoryToValue` and `initializeDefaultPhrase`
  (`CobolData.g4:693-695`, `THEN? TO DEFAULT`). `TO` is **not underlined** in either phrase of the printed
  format, so it is an optional word — `ALL VALUE`, `THEN DEFAULT` and `DEFAULT` are all conforming spellings
  the compiler refuses.

**The SR8 sending-operand hole (refuter correction, re-measured on HEAD).**
`InitializeBinder.cs:164` picks the sending operand and `:167` throws it away one line later —
`if (item.IsDynamicLength) source = new BoundStringLiteral("");`. So for a dynamic-length elementary item the
operand actually stored is an empty literal, not literal-1 / identifier-2. Probe
`run/misc/sr8_dyn.cob` on HEAD:

```
$ cobol sr8_dyn.cob --std 2023 --run
exit=0
PRE-LEN=5 VAL=[hello]
POST-LEN=0 VAL=[]              ← INITIALIZE D REPLACING ALPHANUMERIC DATA BY "ABC"
GRP-LEN=0 DG=[] FX=[QQ  ]      ← same statement over a group: the FIXED sibling FX takes QQ,
                                 the DYNAMIC sibling DG — same category, same REPLACING entry — goes empty
```

The item **does** qualify as a receiving operand through the REPLACING phrase and **is** written; only the
sending operand is substituted. That is the difference between this and a legitimately-skipped item. The
defence available to the code is general rule 7, which is written unconditionally and which the code cites;
the conflict between it and the sending-operand designation is genuine, unadjudicated, and owned by
`GR-14.9.20.4-7` on PB418 — this row depends on that resolution.

**Latent second break of the same shape, flagged not charged:** `InitializeBinder.cs:158-162` discards the
operand outright for a data-pointer / program-pointer / object-reference receiver and always emits a SET to
NULL. Syntax rule 4 of the same clause explicitly contemplates `REPLACING DATA-POINTER … BY identifier-2` with
identifier-2 as the SET sending operand, so that arm will violate the sending-operand designation **the moment
the missing category words land**. It is unreachable today only because the grammar cannot spell them.

## 4. The code site and the shape of the repair

* `src/Cobol.Net.Frontend/Grammar/Core/CobolData.g4:708-716` — `initializeCategory`, five alternatives where
  thirteen belong.
* `src/Cobol.Net.Frontend/Grammar/Core/CobolData.g4:682-684` — `initializeCategoryToValue`: takes **one**
  `initializeCategory` (a set belongs here), the choice is `?`-optional (it must not be), `TO` is required
  (it must not be).
* `src/Cobol.Net.Frontend/Grammar/Core/CobolData.g4:693-695` — `initializeDefaultPhrase`, `THEN? TO DEFAULT`.
* `src/Cobol.Net.Frontend/Grammar/Core/CobolData.g4:702` — `initializeReplacingItem`, one category per item.
* `src/Cobol.Net.Compiler/Binding/Bound/BoundInitialize.cs:54` — the 10-of-13 enum.
* `src/Cobol.Net.Compiler/Binding/Model/PicInfo.cs` — `enum PicCategory`, no NationalEdited member.
* `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/InitializeBinder.cs:254` — `InitializeCategoryOf`, the decoder.
* `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/InitializeBinder.cs:24` — the phantom "note 2" comment.

**CLAUDE.md rule 5 applies: this is not five more alternatives.** The standard names a SET of categories; the
grammar, the bound model and the binder all carry a SCALAR. Model the set: `initializeCategory` becomes a
one-word rule, the REPLACING item and the TO VALUE phrase each take `initializeCategory+`, `InitializeSpec`
carries a category SET rather than a nullable scalar, and `InitializeSender` matches on membership. Then the
thirteenth word is a table row, and the duplicate-category ban (syntax rule 6 of the same clause) becomes one
check over that set rather than a shape nobody can express. Add the missing lexer tokens (BOOLEAN,
DATA-POINTER, MESSAGE-TAG, NATIONAL-EDITED, OBJECT-REFERENCE) and the missing `PicCategory` /
`InitializeCategory` members in the same change; admitting the eight words **without** adding syntax rule 3's
identifier-2-only screen would trade a false rejection for a false acceptance.

The over-acceptance and the required `TO` are one edit each, but the green test that pins the over-acceptance
(`tests/conformance/2002/initialize_phrases.cob` + its `.out`) has to be corrected in the same commit, or the
fix lands red.

## 5. The sibling sweep the fixer must do

* **Both phrases, not one.** The category set reaches `initializeReplacingItem` *and* `initializeCategoryToValue`;
  this is the two-arm shape the register keeps recording.
* **Every edition.** The five classic words are COBOL-85, so the multi-category spelling must work at `--std 85`
  as well as 2023 — measured broken at both. The eight new words are 2002+ (MESSAGE-TAG is 2023 and sits in the
  MCS facility `docs/CONFORMANCE.md` records as not claimed — an owner posture, not this note's call), so each
  needs an edition gate and the gate sweep that goes with a new construct.
* **The `TO`-optional sweep.** Check every other optional word the INITIALIZE format carries — `WITH` before
  FILLER, `THEN` before REPLACING, `DATA` before BY are all correctly optional today; `TO` is the outlier.
* **Reserved-word fallout.** Seven of the eight new words are already reserved, so a program using one as a
  data-name is already refused; adding them as category words must not change that.
* `PicCategory.NationalEdited` is absent, so `InitializeItemCategory` would classify a national-edited receiver
  as National. That is unobservable today only because national-edited PICTUREs are themselves staged loud
  (COBOLNET0899) — a separate subject that will surface the moment either lands.
