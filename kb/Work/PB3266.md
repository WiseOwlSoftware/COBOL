# PB3266 — rule_path misnumbers §6.3.5 trailing paragraphs

**Mechanism.** In §6.3.5 the numbered items are `1)` and `2)`, followed by unnumbered paragraphs ("In the case of continuation with a fixed continuation indicator, any spaces ...", "In the case of continuation with either ... the next line that is not a comment line or a blank line is the continuation line ..."). `scripts/spec/cite.py` `rule_path` (line 86) returns the last `N)` label above the line, so those paragraphs print as `§6.3.5 2)`. Probe: `python scripts/spec/cite.py --check 6.3.5 "Comment lines and blank lines may be interspersed"` answers `2)`. The docstring's rule (an unlettered paragraph at the sub-items' own indentation reports the bare rule) covers lettered sub-items under a rule; a trailing paragraph after a top-level `N)` item in a clause with no parent rule is not covered, so it inherits the last item's number.

**Effect.** `git grep -nE '6\.3\.5 ?2\)'` finds 43 hits outside kb/ and DEVLOG/ (docs/CONFORMANCE.md:1437,1443, docs/VERSION_CHANGE_REFERENCE.md:367, docs/rearchitecture/DESIGN-frontend-grammar.md:904, source and golden comments), plus register notes (PB1359, PB1491, PB1492). Some are right (the floating indicator IS item 2)); the ones citing the trailing paragraphs are not. The clerk did not classify each hit.

**Source.** Carried from PB3168's review rounds (report `w1093c-PB3168-report.md`); not widened into that branch.

**Fix shape.** Fix `rule_path` so a paragraph after the last numbered item at the item's own indentation reports a distinct path (for example the bare clause), then re-derive every hit with `cite.py --check` and correct the citation, with a drift test that every `§N.N.N k)` citation passes `--check` (CLAUDE.md rule 1: validate mechanically).
