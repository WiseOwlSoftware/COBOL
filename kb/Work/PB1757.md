# PB1757 — OPEN

Found 2026-09-29 while probing PB1684: `tests/conformance/2023/ec_data_not_finite.cob` (and `ec_oo_universal_both.cob`, `pb204`-family neighbours) start a directive line `      >>TURN ...` with the `>>` in column 7. `cobol.exe ec_data_not_finite.cob` fails `COBOLNET2616: the indicator area (column 7) holds '>'` and `COBOL0001 unexpected '>'`, while the conformance harness compiles it (`CompilerUnderTest` / `CompiledProgramCache` pass `SourceFormat: InitialReferenceFormat.Auto`, whereas the CLI default is fixed). `grep -l "^      >>" tests/conformance/*/*.cob` finds **58** such files.

**What is unresolved (revisit before anything is changed):** (1) does `Auto` accept a column-7 `>>` directive BECAUSE it decides the file is free-form, or by a fixed-form special case — the memory note `reference_fixed_form_directive_column8` says a fixed-form directive starts at column 8, and §7.3.3 / §6.2.2 give the rule; read the Auto detector (`ReferenceFormatProcessor.IsFixedForm`, `FirstSourceDirectiveCandidate`) and record what it actually does; (2) if Auto reads these files as FREE form, every other line of them is being compiled as free-form text, so the goldens do not test what their headers claim (fixed-form column rules, sequence area, indicator column); (3) decide the golden convention — rewrite the 58 files with the directive at column 8 (as this session's new goldens are) and give the harness the same default as the CLI, or document Auto as the harness contract in `tests/conformance/README.md` — and add a drift test so a new golden cannot rely on it silently.
