# PB1757 — OPEN

Found 2026-09-29 while probing PB1684: `tests/conformance/2023/ec_data_not_finite.cob` (and `ec_oo_universal_both.cob`, `pb204`-family neighbours) start a directive line `      >>TURN ...` with the `>>` in column 7. `cobol.exe ec_data_not_finite.cob` fails `COBOLNET2616: the indicator area (column 7) holds '>'` and `COBOL0001 unexpected '>'`, while the conformance harness compiles it (`CompilerUnderTest` / `CompiledProgramCache` pass `SourceFormat: InitialReferenceFormat.Auto`, whereas the CLI default is fixed). `grep -l "^      >>" tests/conformance/*/*.cob` finds **58** such files.

**What is unresolved (revisit before anything is changed):** (1) does `Auto` accept a column-7 `>>` directive BECAUSE it decides the file is free-form, or by a fixed-form special case — the memory note `reference_fixed_form_directive_column8` says a fixed-form directive starts at column 8, and §7.3.3 / §6.2.2 give the rule; read the Auto detector (`ReferenceFormatProcessor.IsFixedForm`, `FirstSourceDirectiveCandidate`) and record what it actually does; (2) if Auto reads these files as FREE form, every other line of them is being compiled as free-form text, so the goldens do not test what their headers claim (fixed-form column rules, sequence area, indicator column); (3) decide the golden convention — rewrite the 58 files with the directive at column 8 (as this session's new goldens are) and give the harness the same default as the CLI, or document Auto as the harness contract in `tests/conformance/README.md` — and add a drift test so a new golden cannot rely on it silently.

## Measured 2026-09-30 (research agent, tree 4a1dda60e) — the open facts, established

1. **What `Auto` does with a column-7 `>>` file: it reads the WHOLE FILE AS FREE FORM** — not a fixed-form special
   case. A faithful re-implementation of `ReferenceFormatProcessor.cs#IsFixedForm` + `#FirstSourceDirectiveCandidate`
   run over the 58 files classifies all 58 as FREE, every one by the `hasContentPastSourceArea` veto: their `*>` header
   comment lines run past column 72 and the sequence area is blank, so the numeric-sequence override never applies.
   The CLI (`--source-format` default `fixed`) rejects the same file with COBOLNET2616 + COBOL0001 (`dir7.cob` probe:
   `      >>DEFINE X AS 1` → `(1,7) COBOLNET2616 … holds '>'`); the same directive at column 8 compiles (`dir8.cob`).
   §7.3.3 3) "When the reference format is fixed-form, a compiler directive shall be written in the program-text
   area" (`cite.py --check 7.3.3` OK) — the CLI is right.
2. **The scope is far wider than 58.** Over all 3,576 `tests/conformance/**/*.cob`, `Auto` reads **2,905 as FREE**
   and 671 as fixed — 2,767 of the free ones by the same past-column-72 veto. For a file laid out in columns 8–72 that
   uses only `*>` comments the two readings coincide, but no golden the harness reads as free exercises a fixed-form
   rule (sequence area, indicator area, margin R, column-7 continuation), so the headers' claims are untested there.
3. **What breaks under the CLI default** (`cobol check-batch`, edition = the directory, CheckOnly): of the 1,772
   POSITIVE goldens, **181 at 2002/2014/2023 fail in fixed form and pass when forced free** (`>>SOURCE FORMAT FREE`
   prepended): 55 are the column-7 `>>` files (COBOLNET2616), the other 126 have program text past column 72
   (truncated — COBOL0001 / COBOL0307 / COBOLNET1639 at program-text columns ≥ 55, e.g. `2002/allocate_initialized.cob
   (43,60)`) or text in columns 1–7 (`2002/exception_file_n.cob(13,1)`, `2002/conditional_compilation.cob` column 7 =
   `N`). At `--std 85`, 16 of 318 fail in fixed form (not re-run free: `>>SOURCE` is gated at 85) — e.g.
   `85/pb248_integer_arg_float_admitted.cob(1,7)` (a column-1 `*>` header: column 7 = `W`), `85/pb556_…(22,62)`
   (truncation). 15 fail both ways for reasons outside the format (copybook search paths in the batch run). 3 pass only
   in fixed form, correctly: `2002/pb1361_directive_in_format_in_effect.cob`, `2002/pb1493_floating_comment_fixed.cob`,
   `2023/l1_margin_r_program_text_area.cob`. Negative goldens were not measured (a negative can pass for the wrong
   reason under the other reading — the task measures them). Lists: research scratchpad `firsterr.out`, `cmp.out`.

## Task brief (research 2026-09-30)

**⚖ OWNER DECISION — the harness's initial reference format.** (A, recommended) the harness uses the CLI default
(fixed, §7.3.24.3 2) "The default reference format of a compilation group is fixed form", `OK §7.3.24.3 2)`): delete
`SourceFormat: InitialReferenceFormat.Auto` from every harness call site (`tests/Cobol.Net.Tests.Conformance/
CompilerUnderTest.cs` ×5, `CompiledProgramCache` callers, `EditionHarness.cs`, `CorpusRunnerTests.cs`, … ~30 sites —
`grep -rn "InitialReferenceFormat.Auto" tests/`; `tests/Cobol.Net.Tests.Characterization/CharacterizationCorpus.cs`
too), and fix the ~200 goldens that need it: a golden that IS free form says so with the existing header
`*> options: source-format=free` (at `--std 85` the only way — `>>SOURCE` is gated there); a golden meant to be fixed
form moves its `>>` to column 8 and keeps program text within 8–72. (B) keep `Auto` and document it as the harness
contract in `tests/conformance/README.md` (done 2026-09-30 as the CURRENT state) — the goldens then never test the
CLI's reading. **Drift test (A):** `InitialReferenceFormat.Auto` appears under `tests/` only in the auto-detector's own
unit tests, and a corpus test compiles every positive golden with `CliOptions` defaults. Estimate: one Sonnet slot
(mechanical, re-run the whole battery; expect negatives to move). Do it BEFORE PB1800 lands so the reference-format
changes are gated by goldens that are actually read in fixed form.

## Finding 2026-09-30 (PB1800 implementer, DEVLOG 1814) — goldens that depended on the old Auto behaviour

The new free-form 255-position check (COBOLNET2653, PB1496) is asked wherever a line is read as free form, so the harness's
`Auto` exposed every source it reads as free that has a line over 255 positions. **Found by the gate and fixed in this
change** (nothing is switched here — R57's harness default stays for the PB1757 implementer): (a) `negative/pb63-exception-file-no-fd`
is a FIXED-form-authored file (`      *>` comment lines, sequence-free) whose long comment lines run past column 72, so `Auto` read
it as FREE form; (b) `negative/pb10-inspect-fn-tallying-replacing` is free-form authored but had one 275-position comment line;
both were re-wrapped to ≤ 120 positions (text unchanged). (c) `LiteralScreenTests` and `NationalBooleanLiteralTests` wrote an
8,192-position literal on one free-form line — not a program §6.1 3) a) allows — and now lay the program out in fixed form
(`tests/Cobol.Net.Tests.Conformance/FixedFormLayout.cs`: §6.3.5 literal continuation), which also keeps them valid under a
FIXED-by-default harness. A scan of every `.cob` / `.cbl` / `.cpy` under `tests/` and `samples/` for lines over 255 expanded
positions finds no other. The Auto DETECTOR itself now reads the tab-EXPANDED lines (GnuCOBOL's probe does), so a
tab-bearing source can move between fixed and free form; none of the corpus did (the gate's populations are EXACT and green).

## Decided 2026-09-30 (owner) — kb/Work R57

The harness defaults to FIXED source format like the CLI; tag the goldens that need free form (`source-format` option, tests/conformance/README.md). Decision note R57.
