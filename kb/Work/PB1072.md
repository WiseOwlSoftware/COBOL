# PB1072 — OPEN — the ALTERNATE RECORD KEY `SUPPRESS WHEN literal-1` is mis-decoded AND unscreened: `CobolLiteral.Decode` hands a figurative constant or ALL literal to the runtim

## Rule text (every citation re-run by the registrar)
- `python scripts/spec/cite.py --check 12.4.5.6.4 "when the value of data-name-1 or record-key-name-1 in that record is equal to literal-1"` → `OK  §12.4.5.6.4 6)  (General rules)`
- `python scripts/spec/cite.py --check 12.4.5.6.3 "Literal-1 shall be an alphanumeric literal, a national literal, or a figurative constant"` → `OK  §12.4.5.6.3 7)  (Syntax rules)`

### Adjudicator finding (alternate-record-key-clause, harm wrong-answer)
- **Mechanism:** SUPPRESS WHEN value is mis-decoded and compared byte-exact: DataBinder.BindFileControl stores CobolLiteral.Decode(literal.GetText()), which returns a figurative constant or ALL literal UNCHANGED as its source text ("SPACES", "ALL\"*\""), and IndexedConnector.IsSuppressed -> KeyEq -> KeyCompare is string.CompareOrdinal for a key with no collating weights, so a literal shorter than the key is never space-extended and a figurative is never repeated to the key length. Only an exact-length quoted literal suppresses.
- **Repro:** --std 2023: SELECT F ... ORGANIZATION INDEXED ACCESS DYNAMIC RECORD KEY IS R-KEY ALTERNATE RECORD KEY IS R-A1 SUPPRESS WHEN SPACES; FD F. 01 R. 05 R-KEY PIC X(2). 05 R-A1 PIC X(6). WRITE 01/"SPACES", 02/SPACES, 03/SPACES; then READ F KEY IS R-A1 with R-A1 = "SPACES" and with R-A1 = SPACES (probe out/probe/alternate-record-key-clause/gr6b.cob). Also gr6.cob: SUPPRESS WHEN "X" on PIC X(3), ALL "*" on PIC X(3), N"Q" on PIC N(2).
- **Expected (spec):** §12.4.5.6.4 GR6: no alternate access path when the key equals literal-1 ("as if they did not exist"); §14.9.51.4 GR41: a suppressed key's access path is not provided, so it cannot duplicate. gr6b: W2 '00', W3 '00', READ "SPACES" -> FOUND 01, READ spaces -> INVALID KEY '23'. gr6: key "X  " = "X", "***" = ALL "*", N"Q " = N"Q" are all suppressed; the alternate walks omit them.
- **Observed:** gr6b: W2 00, W3 22, READ "SPACES" -> 23, READ spaces -> FOUND 02 - exactly inverted. gr6: all three short/figurative/ALL/national suppression values fail to suppress (walks show records 01 and 03 on every key; READ KEY R-A2="X" finds 01), a spurious '22' on a unique key whose value is SPACES, a spurious '02' on a DUPLICATES key whose value equals the suppression value. IsSuppressed's own summary claims 'the shorter operand space-extended' - the code does not.
- **Code site:** src/Cobol.Net.Compiler/Binding/DataBinder.cs (BindFileControl, the `CobolLiteral.Decode(sl.GetText())` line in the alternateKeyClause arm); src/Cobol.Net.Runtime/IO/IndexedConnector.cs#IsSuppressed / #KeyCompare
- **Clause (adjudicator):** ISO/IEC 1989:2023 §12.4.5.6.4 GR6; §14.9.51.4 GR41; §12.4.5.6.3 SR7 (figurative constants and ALL literals are legal literal-1)

## Finding — `rewrite-statement-p2` (wrong-answer; rows `GR-14.9.35.4-L4.1`, `GR-14.9.35.4-L4.2`)

**Mechanism.** IndexedConnector.IsSuppressed decides 'key equals its SUPPRESS WHEN value' with a raw ordinal string compare of the key window against the undecorated decoded literal: no space-extension of a shorter literal (8.8.4.2.7 2)) and no expansion of a figurative constant to the key's length (8.3.3.6.4 GR2) - so every SR7-legal suppression literal that is not exactly the key's length (SUPPRESS WHEN SPACE/ZERO/ALL "x", or "XX" on PIC X(3)) never suppresses

**Repro.** INDEXED DYNAMIC file, RECORD KEY X-KEY PIC X(2), ALTERNATE RECORD KEY X-A1 PIC X(3) SUPPRESS WHEN "XX", ALTERNATE RECORD KEY X-A2 PIC X(3) SUPPRESS WHEN SPACE (neither WITH DUPLICATES). WRITE 01AAAP01, 02BBBP02; OPEN I-O; READ 01, MOVE "XX" TO X-A1, MOVE SPACES TO X-A2, REWRITE -> 00; READ 02, same moves, REWRITE; then READ KEY X-A1 with X-A1 = "XX"; START X-A1 >= LOW-VALUES + READ NEXT x3; same on X-A2. (scratchpad adj-d1/out/probe/rewrite-statement-p2/p3.cob, pinned cobol.exe --std 2023)

**Expected from the spec.** Both keys of both rewritten records equal their suppression value under the relation-condition rules, so: second REWRITE -> '00' (suppressed entries shall not cause a duplicate key condition, 14.9.35.4 GR24); READ KEY X-A1 = "XX" -> '23' (no access path, 12.4.5.6.4 GR6); the X-A1 and X-A2 walks deliver only the records whose key is not suppressed, then '10'.

**Observed / reasoning.** RW2=22 (legal REWRITE refused, INVALID KEY path taken); A1RAND=00; A1 walk returns 02BBBP02 then 01XX; A2 walk returns 01XX then 02BBBP02 - SUPPRESS WHEN SPACE never suppresses and the short "XX" literal never matches the 3-char key. Cause: IsSuppressed -> KeyEq -> KeyCompare -> string.CompareOrdinal("XX ", "XX") != 0 when no COLLATING SEQUENCE applies; the doc comment on IsSuppressed claims 'the shorter operand space-extended', which the code does not do. The suppress value arrives as CobolLiteral.Decode(literal text) from DataBinder and is emitted unpadded by KeyedIoEmitter via FileAddAlternateKey. PB702's golden l1_rewrite_alt_key_suppress uses literals exactly as long as their keys, so it passes. Siblings sharing the predicate: WRITE (14.9.51.4 GR41 uniqueness skip), READ/START skip of suppressed records (12.4.5.6.4 GR6 NOTE) - one fix (expand the suppression value to the key's width once, at registration or in IsSuppressed, figuratives included; national keys in national spaces) covers all.

**Code site.** src/Cobol.Net.Runtime/IO/IndexedConnector.cs#IndexedConnector.IsSuppressed (+ KeyCompare); src/Cobol.Net.Compiler/Binding/DataBinder.cs (suppress = CobolLiteral.Decode(...)); src/Cobol.Net.Compiler/CodeGen/Verbs/KeyedIoEmitter.cs (FileAddAlternateKey suppress arg)

## Finding — `write-statement-p3` (wrong-answer; rows `GR-14.9.51.4-41`, `GR-14.9.51.4-35`)

**Mechanism.** The WRITE-side SUPPRESS WHEN test compares the alternate key with the suppression value byte for byte. DataBinder.BindFileControl stores CobolLiteral.Decode(literal text), which leaves a figurative constant or ALL literal as its source text. IndexedConnector.IsSuppressed then calls KeyEq, and for a key with no collating weights that is string.CompareOrdinal, so the literal is not extended with spaces and a figurative is not repeated to the key's length. Only a quoted literal of exactly the key's length suppresses. In IndexedConnector.Write, the `if (IsSuppressed(image, i)) continue;` skip therefore never fires for SPACES / ZERO / ALL "x" / a shorter literal, and a suppressed key raises a false duplicate-key '22'.

**Repro.** out/probe/alternate-record-key-clause/gr6.cob (re-run for this part): INDEXED DYNAMIC file with ALTERNATE RECORD KEY R-A1 PIC X(3) SUPPRESS WHEN SPACES (no DUPLICATES), R-A2 PIC X(3) WITH DUPLICATES SUPPRESS WHEN "X", and R-A3 PIC X(3) WITH DUPLICATES SUPPRESS WHEN ALL "*". OPEN OUTPUT; write record 01 with R-A1 SPACES, R-A2 "X", R-A3 "***"; write record 02 with R-A1 SPACES; write record 03 with R-A2 "X", R-A3 "***". Then walk each alternate key with START KEY >= LOW-VALUES and READ NEXT.

**Expected from the spec.** §14.9.51.4 GR41: 'Key entries that are suppressed shall not cause a duplicate key condition to exist', and a suppressed record 'shall be logically positioned so that it will not be found when accessed using the alternate record key'. GR35 and §8.8.4.2.7 2) make the equality test a relation condition, which extends the shorter operand with spaces; §12.4.5.6.3 SR7 admits a figurative constant or ALL literal as literal-1. Expected: W2 = '00' (both R-A1 entries are suppressed), and records 01 and 03 absent from the R-A2 and R-A3 walks.

**Observed / reasoning.** Measured with the pinned build: 'W2 22'. Record 02 is refused and lost, and its INVALID KEY path would run. The R-A2 and R-A3 walks both return 01 and 03. An exact-length quoted literal does suppress. The sibling adjudications (alternate-record-key-clause GR-12.4.5.6.4-6; rewrite-statement-p2 GR-14.9.35.4-L4.x) found the same mechanism, and none of the dossier's kb/Work notes owns it yet. The fix belongs at the one suppression-value decode and comparison, shared by WRITE, REWRITE, READ and START: decode the literal to the key's length and class, with figurative repetition and space extension, then compare with the collation-aware KeyEq.

**Code site.** src/Cobol.Net.Runtime/IO/IndexedConnector.cs#IsSuppressed; src/Cobol.Net.Runtime/IO/IndexedConnector.cs#Write; src/Cobol.Net.Compiler/Binding/DataBinder.cs#BindFileControl (alternateKeySuppressWhen -> CobolLiteral.Decode)

## Refuter evidence — row `GR-14.9.35.4-25` (DIVERGES)

DIVERGES — GR25 c) requires '22' when a no-DUPLICATES alternate key of the replaced record equals another record's. With SUPPRESS WHEN SPACE the runtime's suppression value is the raw word 'SPACE' (figurative not expanded), so two records whose key is the non-suppressed value 'SPACE' are both skipped by pass 1 as 'suppressed' and the duplicate REWRITE succeeds with '00'. This is not the L4.2 'suppressed entries do not duplicate' exemption: per spec neither key is suppressed (neither equals spaces).

**Code site.** src/Cobol.Net.Runtime/IO/IndexedConnector.cs#IndexedConnector.Rewrite; src/Cobol.Net.Runtime/IO/IndexedConnector.cs#IndexedConnector.KeyEq; src/Cobol.Net.Runtime/IO/IndexedConnector.cs#IndexedConnector.IsSuppressed

## Refuter evidence — row `GR-14.9.35.4-L3.1` (DIVERGES)

DIVERGES — The adjudicator's 'code equality is strictly narrower, so it can only miss a suppression' premise is false for a FIGURATIVE suppression value (legal per 12.4.5.6.3 SR7). DataBinder passes the SUPPRESS WHEN literal through CobolLiteral.Decode, which returns raw token text for a figurative, so SUPPRESS WHEN SPACE stores the 5-char word 'SPACE' as the suppression value. A key that LEAVES suppression (spaces -> the word SPACE) is then treated as newly suppressed and no access path is provided, contrary to GR24 1.

**Code site.** src/Cobol.Net.Runtime/IO/IndexedConnector.cs#IndexedConnector.Rewrite; src/Cobol.Net.Runtime/IO/IndexedConnector.cs#IndexedConnector.IsSuppressed

## Refuter evidence — row `GR-14.9.35.4-L3.2` (DIVERGES)

DIVERGES — Same mechanism as L3.1: with SUPPRESS WHEN <figurative> the suppression value is the raw token text, so a record whose key leaves suppression into a value equal to that text (e.g. the word SPACE) is NOT 'logically positioned so that it will be found when accessed using the alternate record key'. The golden leg C uses a quoted literal, which the Decode path handles, so it does not pin the figurative arm.

**Code site.** src/Cobol.Net.Runtime/IO/IndexedConnector.cs#IndexedConnector.Rewrite; src/Cobol.Net.Runtime/IO/IndexedConnector.cs#IndexedConnector.Stamp
