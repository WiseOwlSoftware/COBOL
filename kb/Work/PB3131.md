# PB3131 — a change to the inventory does not pull `SpecTraceabilityInventoryDriftTests` into leg 1

**Sites:** `scripts/spec/drift_rules.py` (`Removal`, `removal_of`, `data_files`, `Citations`, `citing`),
`scripts/spec/impacted_tests.py` (`removals`, `reach_of`, the self-test arms), `tests/Cobol.Net.Tests.Unit/ImpactedTestsDriftTests.cs`
(the arms pinned), and the tier-0d prose in `scripts/gate_plan.py`, `scripts/run_gate_legs.py`, `scripts/build-local.ps1`,
`docs/rearchitecture/DESIGN-test-build-ci.md`, `.claude/skills/gate/SKILL.md` and MANDATORY-PRACTICES I1.

Source: wave 1071 (unit `w1071b`, PB546 round 1 lead 2, restated in round 3). PB546 is held by its branch and not edited.

**What was seen.** PB546's change edited the traceability inventory; its gate ran `LEG 1 ONLY (batched gating, PB2515): GREEN` and left the Unit population to CI, with the drift class `SpecTraceabilityInventoryDriftTests` planned into leg 2. The same observation is recorded in earlier reports: `w1040w-PB2650-report.md:21` ("`EveryCodeLocation_ResolvesInTheTree`, which runs in leg 2 and so does not run in the trial") and `w1041p-PB1636-report.md:25` (leg 1 did NOT run it: "run the drift class filtered after any §8 batch"), and `w1069a-PB3018-report.md:64`. Those wrote the workaround (run it by hand) into reports; none made the planner do it. The implementer's report for PB546 ran its "related Unit drift tests by hand: 54/54".

**Why (a hypothesis read from the planner's header, not yet measured: the implementer confirms it with `gate_plan.py` on the PB546 diff).** `scripts/gate_plan.py` orders by the impact map's tiers (`:37`: "with no map, every case is tier 1") and by `[Trait("Sweep", ...)]` for the cheap tree-wide classes (tier 0c, `:31`, `:97`). The inventory-reading drift classes carry neither: the reach analysis (`impacted_tests.py`) follows C# call edges, and a data-file change (`docs/rearchitecture/...` inventory) has no edge to the test that reads it, so the class falls to the default tier and, being long, to leg 2.

**Fix.** The root cause is that a test's data inputs are not part of its impact edge. Make a test class name the files it reads (a trait such as `[Trait("Reads", "<path glob>")]`, or the planner discovering `File.ReadAll*` literals) so `impacted_tests.py` puts it in tier 1 when a file it reads changed; do NOT add this class to a hand list (CLAUDE.md rule 5). Add a drift test that every `[Trait("Reads", ...)]` path exists, and one that every test reading the inventory carries it. Sweep: the other classes that read `docs/`, `specs/`, `kb/` or `tests/version-matrix` data (e.g. the `Spec*DriftTests`, `ConstructsJson*`), which share the gap.

**Correction to the hypothesis above.** The class DOES carry `[Trait("Sweep", "tree")]` (`tests/Cobol.Net.Tests.Unit/SpecTraceabilityInventoryDriftTests.cs:50`). The mechanism is the tier-0c cost cap: a Sweep case is tier 0c only while its recorded time is at most `SWEEP_CHEAP_SECONDS` (2 s, `scripts/gate_plan.py:100`, tier test at `:342`), and tier 0c cases enter leg 1 cheapest first only while the collection stays within `LEG_ONE_COLLECTION_CAP` (15 s, `:87`; the loop at `:387-392`). Whether the class runs locally therefore depends on the shared timings, not on the diff. The fix must also cover a deleted or renamed C# member that an inventory code-location names, not only an inventory edit. Cross-link PB3112 (the same cap).

drift classes govern a REGISTER that cites what the diff removes. `impacted_tests.removals` reads one `git diff -U0`

the file's new text lacks; the types it declares); `drift_rules.citing` indexes every non-C# file a drift test names

`path#Member` chain, a dotted `Class.Member` name) and returns the classes that govern each citing register
specifically; `reach_of` adds them to `Reach.drift_tests` (tier 0d), with a note naming the citation. Nothing is
listed by hand: a new register is covered the day a drift test names it. Replayed with no map, all four landing
stops now name the class with the citation they broke: 611bdb3a2 `TurnStateTests.UnknownName_DiagnosedAndIgnored`,
684d01b4b `OptionsBinder.cs#Bind`, 1a473341f `OoDriver.cs#DeclareMethodWords`, c3c6879ab `RecordFraming.cs#PrefixLength`;
plan cost about 2-5 s (one diff, the index of 18 MB of registers). Self-test arms: the three shapes, a deleted suite
test, a removal no register cites, the diff reader, the `reach_of` wiring with no map, and the real inventory; each arm that expects a citation fails with
`Citations.broken_by` stubbed out. `ImpactedTestsDriftTests` now pins these arms and PB3531's two tier-0d arms, which
it did not.
