**Rule it breaks:** §2023:11.7.3 SR3 ("If the OVERRIDE phrase is specified, there shall be a method with the same method resolution signature ... defined in a superclass. The method in the superclass shall not be defined with the FINAL clause"), SR4a and §2023:13.18.42.3 SR4 are syntax rules of the method definition, which OoDriver.BindParameterized says govern a parameterized definition "whether or not anything expands it" (kb/Work PB2051, PB2937). The interface twin is asked of both lists (OoClassTable.Build line 676: _interfaces.Concat(_parameterizedInterfaces) for SR4b); the class arm is not.

**Scenario:** CLASS-ID. P INHERITS FROM B USING T. with B a written (non-formal) class that defines no M, and METHOD-ID. M OVERRIDE. in P; nothing in the group writes EXPANDS P. Build puts P in _parameterizedClasses and links sym.Base = B (OoClassTable.cs:920), BinderDriver calls table.ResolveOverrides(edition) (BinderDriver.cs:145), which iterates _classes only (OoClassTable.cs:1030-1037), then binds P through OoDriver.BindParameterized, which never marks a roster. So COBOL0838 (SR3) is not reported, nor 0839 for overriding a FINAL method of B, nor the SR4a 0837 for M redefining B.M without OVERRIDE, nor 13.18.42.3 SR4 for a PROPERTY clause subject spelled like a property of B. The same class with no USING clause draws each of them. The same holds with no INHERITS clause at all (sym.Base null, FormalBaseName null): METHOD-ID. M OVERRIDE. is refused in an ordinary class and accepted in an unexpanded skeleton.
