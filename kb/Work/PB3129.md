# PB3129 — a non-strong group holding a pointer leaf cannot cross a CALL or form a prototype/definition pair

Source: wave 1071 (unit `w1071f`, PB3120 round 3), carried from `w1070f`. The report asked whether an open note owns it: the grep of `kb/Work/` found none. PB1112, PB1115, PB1116, PB1144 and PB1164 are all LANDED and each concerns strongly-typed groups or the comparator itself; PB1527 (landed) refused STRING of such a group. `PB3120` is held by its branch and shares no root with this (the report says so).

**Repro (R2, run on the notes worktree's built CLI, `cobol grouppairs.cob`):** `E:\COBOL-coord\scratch\w1070f\probe\grouppairs.cob` (a PX prototype and definition each with `01 L-G. 05 L-P TYPE T1/T2` where T1/T2 are PROGRAM-POINTER TYPEDEFs to different programs, called by `CALL PX USING G`). Both errors reproduce:

```
grouppairs.cob(16,20): error COBOLNET1513: program prototype 'PX' and the program definition 'PX' share the externalized name "PX" but not a signature ... (ISO §10.6.2 SR2; §13.7.3 SR2)
grouppairs.cob(59,12): error COBOLNET1688: CALL ... program-prototype 'PX' argument 1 ('G') does not conform to formal parameter 'L-G': argument group 'G' with a pointer/object-class leaf (no character image) — the Tier-C byte island (no whole-group character image), deferred; COBOLNET_DESIGN §4.2 (ISO §14.8.2 via §14.9.4.3 SR25)
```

(The pair differs in the pointee program Q1 vs Q2, so the 1513 arm may be CORRECT for that source; the implementer must separate it from 1688 with a pair that has the SAME pointee, which this probe does not isolate.)

**Rule.** `python scripts/spec/cite.py --check 10.6.2 "the signatures of these two compilation units shall be the same"` -> OK, §10.6.2 2). `--check 14.9.4.3 "The rules for conformance specified in 14.8.2, Parameters and 14.8.3, Returning items apply"` -> OK, §14.9.4.3 25). The group-description comparison itself is §14.8.2.3.2 / §14.8.2.2 and was not re-derived here: that is a spec judgment for the implementer (`spec-lookup` first).

**Sites.** `src/Cobol.Net.Compiler/Binding/Model/TierCIsland.cs:50-55` (`Reason`, `HasImagelessLeaf`) is the refusal: it treats "no whole-group character image" as "cannot cross a CALL", though an argument passed BY REFERENCE needs no image (the group's leaves are addressed). `src/Cobol.Net.Compiler/Oo/OoConformance.cs:561` `DescriptionMismatch` (the §14.8.2.3.2 comparator: the group arm) and `Binding/Procedure/Verbs/CallBinder.cs:1228,1269` (the CALL conformance loop). PB1116 already taught the group path an object-reference leaf for the STRONG case; the non-strong case is the sibling it left.

**Sweep.** Every `HasImagelessLeaf` caller (DISPLAY / STRING / SORT keys have their own, deliberate, refusals: PB1527, PB1173); CALL, INVOKE and the prototype pair must instead compare the group by leaf descriptions.

## Landing (wave 1072 group F, w1072f)

**Re-probed** on the worktree build (base `2da05a28a`): `grouppairs.cob` gives COBOLNET1513 and COBOLNET1688 as filed.
`01 G. 05 A TYPE PT.` with `PT IS TYPEDEF USAGE POINTER` (and the PROGRAM-POINTER and OBJECT REFERENCE spellings, and a
weak template `01 W IS TYPEDEF. 05 WP TYPE PT.`) compiled CLEAN, while `01 P USAGE POINTER. 01 G. 05 Q SAME AS P.` was
already COBOLNET1724.

**Determination (the premise did not hold).** The group the note calls legal is not conforming source. §13.18.60.3 SR14
(`cite.py` OK 14): a USAGE clause with the POINTER, PROGRAM-POINTER, FUNCTION-POINTER or OBJECT REFERENCE phrase "may be
specified only for an elementary data item at level 1 or an elementary data item subordinate to a type declaration that
includes the STRONG phrase". §13.18.57.4 GR1 (`cite.py` OK 1): "The effect of the TYPE clause is as though the data
description identified by type-name-1 had been coded in place of the TYPE clause", so `05 L-P TYPE T1` in an ordinary
group IS the level-05 spelling SR14 forbids. SAME AS states the same effect in the same words (§13.18.49.4 GR1,
`cite.py` OK 1), and the compiler always rejected that copy: the TYPE spelling was the one route that escaped. On
conforming source a group holding a pointer- or object-class leaf is therefore always strongly typed, the case PB1116 /
PB1940 carry across CALL and INVOKE. The defect was an UNDER-rejection at the declaration (flags corrected:
`rejects_legal_source: false`, `under_rejects: true`); the CALL and pair diagnostics were its late symptom.
⚠ A reading the owner may overturn: that SR14 binds only a WRITTEN USAGE clause (TYPE's own SR8 restates the
file-section rule SR15 for the TYPE route and restates nothing for SR14). Rejected, because it would make the TYPE and
SAME AS twins disagree under identical general rules.

**Fix.** `DataBinder.ScreenSr14ElementaryPlacement` (`src/Cobol.Net.Compiler/Binding/DataBinder.UsageDeclaration.cs`) is
SR14's arm B, now ONE helper called by both loops of `CheckUsageDeclarations`: the written-entry loop as before, and the
composed-entry loop (PB1212's, which asks the EXTERNAL / BASED class rules of each entry carrying a TYPE clause) for
every WRITTEN TYPE entry: a site entry or a TYPE entry written inside a template, never a clone a TYPE expansion
composes beneath one. The message names the route ("by TYPE PT, ISO §13.18.57.4 GR1"). The legal sibling, a STRONG group
with a program-pointer leaf of the same pointee crossing `CALL PX USING G` through a prototype pair, compiles and runs
right (no change needed in `TierCIsland`, `OoConformance` or `CallBinder`).

**Goldens.** `2002/pb3129_type_pointer_placement_ok` (level-1, level-77 and STRONG-member TYPE pointers; the strong pair
crossing BY REFERENCE, §14.2.3 GR8); `negative/pb3129-type-pointer-in-weak-group` (reject-at 2002 2014 2023,
COBOLNET1724). `2002/pb1408_address_of_restricted_pointer` held the shape as a side case (`01 G-T IS TYPEDEF. 05 GP TYPE
PT.` and `ADDRESS OF GP OF G`); it has no conforming spelling (in a STRONG group, ADDRESS OF a member is COBOLNET2785),
so that one case was removed and the program's output is unchanged.

**Rows.** `SR-13.18.60.3-14` re-verdicted CONFORMS with the TYPE-route witnesses (batch
`E:\COBOL-coord\scratch\w1072f\batch-PB3129.json`; GAP 103 → 103).

**For the next implementer.** `src/Cobol.Net.Compiler/Binding/DataBinder.UsageDeclaration.cs#ScreenSr14ElementaryPlacement`
is SR14's elementary arm. `ConformanceForest` prunes every entry that carries a TYPE clause, so a rule about the TYPE
entry's OWN placement must be asked in the composed-entry loop, filtered to written entries (`IsWrittenEntry(Parent)`).
