## Finding — `terminate-statement` (wrong-answer; rows `GR-14.9.46.4-3`)

**Mechanism.** TerminateCore restores the control data items (GR3 d) before producing the last page footing and the report footing (GR3 c), so the report footing is composed from the CURRENT control values instead of the prior ones

**Repro.** RD R-1 CONTROL IS FINAL WS-A WS-B; DE/CF WS-B/CF WS-A/CF FINAL groups; 01 RF-1 TYPE RF LINE PLUS 1 with COLUMN 4 PIC 9 SOURCE WS-A and COLUMN 6 PIC 9 SOURCE WS-B. WS-A=1 WS-B=1; OPEN OUTPUT; INITIATE R-1; GENERATE DET-1; MOVE 3 TO WS-A; MOVE 4 TO WS-B; TERMINATE R-1; CLOSE. (out/probe/terminate-statement/p1.cob)

**Expected from the spec.** §14.9.46.4 GR3 orders the actions a) control items <- prior values, b) control footings, c) report footing, d) control items restored. The RF is produced between a) and d), so it shows the prior values: last line `RF 1 1`. The last page's page footing (printed before the RF per §13.18.57.4 GR6f) likewise precedes d).

**Observed / reasoning.** Report file: `DE 1 1 / CFB 1 1 / CFA 1 1 / CFF 1 / RF 3 4` at --std 2023, 2002 and 85. In ReportWriter.TerminateCore the GR3d loop `for (...) _controls[i].Set(current[i]);` sits inside the `if (_controls.Count > 0 && ...)` block, before `PresentPageFooting()` and `PresentHeadingFooting(rf)`. Fix: move the save/restore to bracket the PF and RF presentations too (d executes last), and pin it with a golden whose RF and PF SOURCE a control item changed after the last GENERATE.

**Code site.** src/Cobol.Net.Runtime/IO/ReportWriter.cs#TerminateCore (the GR3d restore loop placed before the PF/RF presentation)

## What the fixer owes
