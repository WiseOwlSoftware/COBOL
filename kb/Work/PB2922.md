# PB2922 — the steer self-test reads a machine-global path

Filed 2026-10-10 by the train 1052 lander (phase 1b) from the wave 1051 F implementer's report
(`E:\COBOL-coord\scratch\reports\w1051f-PB2846-report.md`, "New defects" item 2: its gate 1 went red on this check
with one file in TEMP, and passed on re-run).

**Where.** `scripts/orchestrator/orchestrate.ps1` (about line 419) writes a dry run's steer to
`[IO.Path]::GetTempPath()/orchestrate-dryrun-$PID.handoff.operator.json` and removes it at the end of the dry run.
`scripts/orchestrator/test_orchestrate_steer.ps1` (line 52) checks "a dry run leaves no steer behind" by counting
EVERY `orchestrate-dryrun-*.handoff.operator.json` in the machine-global TEMP. Any other dry run in flight on the
machine (another gate's self-test, the loop, another session) is counted: `got 'False 1'`, RED.

**Relation to PB2590.** PB2590 records this same symptom (w1045e gate `20261009T001725Z-be7812`: "a dry run leaves no
steer behind: got 'False 1'") and attributes it to the load-sensitive handoff-synthesis path. This arm is a different
mechanism: a fixed shared path, red whenever two dry runs overlap, whatever the load.

**Repro.** Run `pwsh scripts/orchestrator/test_orchestrate_steer.ps1` while another `orchestrate.ps1 -DryRun` is
paused inside its unit (or create an `orchestrate-dryrun-1.handoff.operator.json` in TEMP by hand): the check fails.

**Fix shape (rule 4, no shared fixed path).** The dry run's steer goes under the run's own coordination directory (or a
temp name the caller passes), and the test checks that place only; failing that, the test counts only the name with
the orchestrate process's own PID.

## Second arm (enqueue unit 2026-10-14; wave 1072 F, PB3129): a LEAKED file, not only a concurrent one

The same check (`scripts/orchestrator/test_orchestrate_steer.ps1:52`, which counts every
`orchestrate-dryrun-*.handoff.operator.json` in the machine-wide TEMP) also fails permanently after a dry run that was
killed rather than finished. `scripts/orchestrator/orchestrate.ps1:500` writes
`%TEMP%\orchestrate-dryrun-$PID.handoff.operator.json` and removes it only in the `finally` at `:701`; a process-tree
kill (build-local's PB3061 fail-fast) skips `finally`. One leaked file then reds the SELF-TESTS audit of EVERY later
gate on the host until it is deleted by hand. Repro: kill a gate during its SELF-TESTS audit, then re-gate. Harm: every
gate on the host red (no user program affected).

The fix shape above covers it only if it removes the shared path altogether (a steer under the run's own coordination
directory dies with that directory). The weaker option, counting only the orchestrate process's own PID, fixes the
concurrent arm but leaves the leaked file on disk; if the implementer keeps a TEMP file at all, it must also reap files
of dead pids at the start of a dry run. Add a case that creates a stale
`orchestrate-dryrun-<dead pid>.handoff.operator.json` and expects the self-test green.

No leftover `orchestrate-dryrun-*` file remained in `E:\Temp\` afterwards, which fits the concurrent-session arm (another session's live dry run counted), not the leaked-file arm.

## Landing (2026-10-16, wave 1089 A)

Measured first (2026-10-16 03:38 PDT): ten landings started in one second and four went GATE RED in the SELF-TESTS audit
on this one check (`got 'False 1'`, one `'False 2'`), before any slot or leg. Both arms are one mechanism: a FIXED name
in the machine-wide temp directory is one file for every run on the host.

- **The dry run's steer** (`scripts/orchestrator/orchestrate.ps1`, after `Take-Lock`): `-DryRun -Unit` writes it to
  `<CoordDir>\scratch\dryrun-<pid>\handoff.operator.json`, removed with that directory in the `finally`. Every start

  plants the directory of a pid that has exited and expects it reaped, said, and its steer never read; with the reap
  disabled it went RED (`got 'False True 1'`), 23/23 with it.

  `semgrep/verify.py` (a `TemporaryDirectory`), `arch/r2_inputs.py` (an anchored fixture root that is never written),
