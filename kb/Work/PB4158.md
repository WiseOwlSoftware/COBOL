# PB4158 — the entry-spelling directory listing is an unrecorded ambient read

**Sites:** `src/WiseOwl.Cobol.Frontend/Pipeline/CompilationInputs.cs:110` (`CompilationInputs.LocateFile`).

Review lead R1-2 (low, not blocking at round 1) of the PB1680 branch (PB1680 is held by an in-flight group, so this is a new note
that names it). The gateway contract of `CompilationInputs` is that every ambient read is performed AND recorded, so the
compiled-program cache (PB985) and a depfile can see it. `LocateFile` now enumerates a directory
(`Directory.EnumerateFiles(directory, name, CaseInsensitive)`) to learn the entry's real spelling, and the diagnostics, line map
and dependency record name the file by that spelling, so the compiler's output depends on a directory listing that is not
recorded. The cache re-validates only `File.Exists` probes and file hashes, which are case-blind on Windows: renaming a copybook
file's case alone (`gr9dbook.CPY` to `gr9dbook.cpy`) leaves every recorded probe and hash valid while the diagnostics' text for it
would now differ, so a cached compile can serve text that names the old spelling.

This is an unverified reading: the first step is to measure it (compile a program whose diagnostic names a copybook, rename the
file's case only, recompile with the cache warm, compare the diagnostic text), then either record the listing as a probe kind the
cache and depfile re-validate, or decide the stale spelling is acceptable and say so in the gateway's contract and the cache
design (`docs/rearchitecture/DESIGN-*` for the cache). Read the PB985 cache design before choosing.
