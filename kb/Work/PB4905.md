# PB4905 - where.py does not catch CitationError

**What the report says (the reviewer's words).** R1-3 LEAD (low, not blocking at round 1): `scripts/spec/where.py:31` where.py
calls citation.parse on an argument starting with the section sign without catching CitationError, so a malformed citation ends
in a Python traceback instead of the parser reason, unlike cite.py and citation.py which print FAIL: <reason>. Left for the clerk
(where.py is not in that change).

**Read on main (2026-11-06).** `where.py` `main`: `cited = citation.parse(a.clause) if a.clause.startswith('§') else
citation.Citation(2023, a.clause)`, with no handler. Repro: `python scripts/spec/where.py "§2023:"` (any malformed `§` argument).

**Sites:** `scripts/spec/where.py` (`main`).
