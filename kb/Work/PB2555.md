# PB2555

Filed by the train 1037b lander from the wave-1037 group H report (lead 4: found while writing the PB1930 golden).

**What a user sees.** In fixed-form reference format the program-text area ends at margin R (§6.3.1, cite.py --check OK:
"Margin R is immediately to the right of the rightmost character position of the program-text area"; the position is
the implementor's, column 72 here), so the compiler is right to drop what lies past it. But when the dropped text was part of a statement (a 74-column
CALL line), the statement ends early and the parser reports `cannot parse construct near STOP` on the NEXT statement, with
nothing pointing at the truncation. Repro: `E:\COBOL-coord\scratch\w1037h\p\gb.cob`.

**Owed.** A diagnostic quality fix: when the parse fails on a line whose predecessor carried non-blank text in the
area past margin R, add a note (or a warning, at the reference-format stage) naming the line and the column where
its program text was cut. It must not fire for the ordinary sequence-and-identification use of those columns (a numeric or
blank area, or a comment line), which PB1757 / R57 measured on the conformance corpus. Related: PB1950 (a golden that
silently changed meaning under the CLI's fixed default for the same reason).

## 2026-10-31 — a second repro: a word cut by the margin is named as an ordinary unexpected token

**Sites:** the fixed-form program-text-area cut named above (this note's reference-format stage), plus
`src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorListener.cs` (`CobolErrorListener.SyntaxError`, the message that must carry the note).

Found by the PB3148/PB3248 implementer (E:/COBOL-coord/scratch/reports/w20261780c-PB3148-report.md, 'New defects' 1; filed by the
lead-filing clerk, who found this open note covers it and filed no new one). When the cut lands INSIDE a word, the word is
reported as an ordinary unexpected token: `END-SEND` written with its last two characters past column 72 reaches the parser
as `END-SEN`, and the diagnostic is `COBOL2269: unexpected 'END-SEN'`, with nothing naming the truncation. Same class as PB1950.
Repro (originally `probe/reg.cob` under E:/COBOL-coord/scratch/mythos/w-g7/w20261780c/, not durable; the SEND line is
72+ columns long, so `END-SEND.` loses its tail in fixed form, `misleads_diagnosis` in effect):

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. PREG.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 WS-MSG PIC X(8) VALUE "MSG".
       01 WS-REPLY PIC X(8).
       01 A.
          05 TBL PIC X(8) OCCURS 3.
       01 B.
          05 C PIC X(8).
       01 D.
          05 C PIC X(8).
       PROCEDURE DIVISION.
       MAIN-P.
           SEND TO LINAGE-COUNTER FROM WS-MSG RETURNING WS-REPLY END-SEND.

```

The owed note should also fire when the cut falls inside a word, not only between words.

## 2026-11-01 — LANDED (wave 20261799, group H): a syntax error beside a margin-R cut names the cut (COBOL5788)

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorListener.cs` (`CobolErrorListener.SyntaxError`, `CobolErrorListener.NoteMarginRCut`,
`CobolErrorListener.PreviousToken`, `CobolErrorListener.ReportMarginRCut`), `src/WiseOwl.Cobol.Frontend/Common/MarginRCut.cs` (`MarginRCut`,
`LocatedMarginRCut`, `IMarginRCutLocator`), `src/WiseOwl.Cobol.Frontend/Preprocessor/ReferenceFormatMap.cs` (`ReferenceFormatMap.CutAt`,
`ReferenceFormatMap.CutOf`), `src/WiseOwl.Cobol.Frontend/Preprocessor/AreaPlacement.cs` (`FixedFormAreas.MarginRCutAt`),
`src/WiseOwl.Cobol.Frontend/Preprocessor/FixedFormLine.cs` (`FixedFormLine.MarginRIndex`), `src/WiseOwl.Cobol.Frontend/Pipeline/Frontend.cs`
(`Frontend.Parse`, `Frontend.LexAndParse`, `Frontend.LexAndParseOnce`, `Frontend.ParsePass`),
`src/WiseOwl.Cobol.Editions/Diagnostics/DiagnosticCatalog.cs` (`DiagnosticCatalog.ProgramTextPastMarginR`).

**Re-probe (2026-11-01, build of this tree).** Both repros reproduced: a CALL cut after `BY` drew only `cannot parse construct near 'STOP'`
at the STOP line, and `END-SEND` written across position 72 drew only `unexpected 'END-SEN'` (a reconstruction of the first repro, a 74-column CALL
whose last argument is cut, parses WITHOUT error, since the repro file is gone: only a cut that leaves the statement incomplete
is a symptom).

**Fix shape.** The reference format RECORDS the cut and the syntax-error listener ASKS (the same split as the COBOL-85 areas, PB3147):
`ReferenceFormatMap` keeps per fixed-form physical line the text past margin R (`MarginRCut`: none for blank text, a comment line, a line
that ends in an inline comment (§6.3.7.3), nor for the identification tags of a file that labels most code lines with one word of at most
eight characters), `FixedFormAreas` composes it with the resultant-line map, and the listener reports COBOL5788 (a warning, BEFORE the
error: the cause first, PB4131) once per cut when the offending token ends at margin R with the cut text right behind it, or when the
token before the offending one is the last of a cut line and the offending token is on a later line. A numeric area never fires it. The
listener reaches the cut through `IMarginRCutLocator`, in `Frontend.Common`, so `Parsing` gains no edge to `Preprocessor` (architecture
edges file unchanged).

**Not covered, deliberately.** A whole statement written ONLY past margin R on a line with no program text: the lines between the
predecessor token and the offending token are not consulted (no token stands on them). A lone identification-tag-shaped word on a
minority of lines is indistinguishable from a cut word and fires.

**Witnesses.** `unit:MarginRCutNoteTests` (10 cases), `conformance:cases/A.1-Implementor-defined-language-element-list/pb2555_text_past_margin_r_is_ignored`,
`pb2555-statement-cut-at-margin-r` and `pb2555-word-cut-by-margin-r` (the refusals pin the error; the note is in `result.Warnings`, which the
refusal harness does not match, so `MarginRCutNoteTests` pins it).
