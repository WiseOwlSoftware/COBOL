## Finding — `cobol-words` (wrong-answer; rows `GR-8.3.2.2-L4.1`, `GR-8.3.2.2-L4.2`)

**Mechanism.** Two-arm INVOKE dispatch: the TYPED (static) path resolves a method by its EXTERNALIZED name (PB303), but the UNIVERSAL / identifier-2 (dynamic) path dispatches through the generated __CobolInvoke switch whose case labels are the DECLARED method-name uppercased (OoEmitter.EmitCobolInvoke: m.Name.ToUpperInvariant()), so a method declared with METHOD-ID m AS "lit" is reachable through a universal reference only by its declared word and never by its externalized name

**Repro.** out/probe/callconv/mi_*.cob: CLASS-ID. MICLS. OBJECT with METHOD-ID. M1. and METHOD-ID. M2 AS "MixedExt".; main: 01 U USAGE OBJECT REFERENCE. 01 T USAGE OBJECT REFERENCE MICLS.; INVOKE MICLS "NEW" RETURNING T, SET U TO T. `INVOKE U "M2"` -> prints M2 RAN (mi_a, 2002 and 2023); `INVOKE U "MixedExt"` -> abnormal run-unit termination: EC-OO-METHOD (fatal) ... does not implement a method named 'MIXEDEXT' (mi.cob; same for U "MIXEDEXT" and for identifier-2 = "MixedExt"); typed `INVOKE T "MixedExt"` -> M2 RAN and `INVOKE T "M2"` -> COBOLNET0825.

**Expected from the spec.** Under the (default, always-in-force) COBOL call convention the universal INVOKE's method-name maps to the method's EXTERNALIZED name exactly as the typed INVOKE does (the class's entry convention is COBOL, so both sentences give the same mapping): INVOKE U "MixedExt" prints M2 RAN, and INVOKE U "M2" raises EC-OO-METHOD (no method is externalized as M2) — the mirror image of what is observed.

**Observed / reasoning.** A legal program terminates abnormally (EC-OO-METHOD, fatal) where the typed spelling of the same call runs, and a name that is not the method's externalized name activates it. Fix at the ONE dispatch table: emit the case label from the method's externalized name under the same case-insensitive mapping NormalizeMethodName applies (the method symbol already carries the AS literal for the typed path), and sweep the other dynamic surfaces (inline method invocation on a universal reference, property access by name) for the same declared-name key; add a golden with an AS method invoked through a universal reference.

**Code site.** src/Cobol.Net.Compiler/CodeGen/Verbs/OoEmitter.cs#EmitCobolInvoke (case label m.Name.ToUpperInvariant()); src/Cobol.Net.Runtime/Control/CobolObject.cs#__CobolInvoke

## What the fixer owes

Emit __CobolInvoke's case labels from the SAME externalized-name function the typed path uses (one mapping), comparing per the §8.3.2.2 externalization rule; drift test pairing the two dispatch arms.

## Landed — 2026-09-27, wave 67 Q (branch `worktree-wf_475f7239-eda-5`)

**The universal case label is the externalized name, through the one word mapping.** `OoMethodSymbol.DispatchKey` is `CobolObject.NormalizeMethodName(ExternalizedName)`, and `OoEmitter.EmitCobolInvoke` labels every `__CobolInvoke` case with it; the bound INVOKE literal is normalized through the same `NormalizeMethodName` (it was a hand-copied `TrimEnd().ToUpperInvariant()`), and identifier-2 already was — so the literal, the run-time value and the case label are one mapping, and the key is the roster key the typed path resolves by (PB303). §8.3.2.2 1) (`cite.py --check 8.3.2.2 "that method-name is treated as a COBOL word that maps to the externalized name of the method to be invoked"` → OK). Sweep: the inline method invocation is barred on a universal receiver (§8.4.3.4.3 SR2), and no other dynamic surface keys a method by name — `__CobolInvoke` is the one. Re-probed: `INVOKE U "MixedExt"` / `"MIXEDEXT"` / identifier-2 `"mixedext"` → M2 RAN; `INVOKE U "M2"` → EC-OO-METHOD.
