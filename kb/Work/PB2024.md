# PB2024 — OPEN: the grammar audit is blind to an underlined (required) word made optional

Raised by kb/Work PB755's sweep section and by the wave-1019 group F report; filed by the train-1019 lander when
PB755, PB756 and PB1183 landed (the lead would otherwise live only in a landed note's prose).

## The gap

§5.2.2: keywords "are shown in uppercase and underlined in general formats" and are required; §8.3.2.4.3: "uppercase
words that are not underlined are called optional words". `scripts/spec/audit_grammar_optional_words.py` joins every
measured general format (`figure_extract.py`, 320 formats) to the grammar in ONE direction: a token the grammar
REQUIRES that the page prints plain (the PB695 family). It never asks the inverse: a token the grammar makes
OPTIONAL (`X?`) that the page UNDERLINES. That inverse is how three over-acceptances lived unseen until each was
found by hand:

- PB755: `lockOnPhrase : WITH? LOCK ON? …` accepted `WITH LOCK MULTIPLE RECORDS` (fixed train 1019).
- PB756: `alternateKeyClause : ALTERNATE RECORD? …` accepted `ALTERNATE KEY IS k` (fixed train 1019).
- PB758 (landed earlier): `END_INVOKE?`, an optional token for a word the standard does not print at all. PB755's
  sweep names it as the third catch of the same join (a grammar token with no printed word).

A repeated KEYWORD where the ellipsis repeats only a braced operand group (PB1183, `unstringIntoPhrase+`) is the
sibling shape (the `+` placed outside the keyword) and belongs in the same audit as a third candidate class.

## Fix shape

Add the inverted join to `audit_grammar_optional_words.py` as a second candidate class (never a hand-kept list): for
each measured format, every grammar token under a `?` (or inside an optional sub-rule) whose word the format prints
underlined and NOT inside brackets. Brackets legitimately make an underlined word optional (MULTIPLE in LOCK ON), so
the join must read the bracket structure from the rendered figure, not the underline alone. Each candidate is then
adjudicated against the rendered page (`scripts/render-spec-page.py`), and each confirmed one becomes a
tightening with a negative golden and a positive golden for every printed spelling (the PB755/PB756 pattern). Wire
the audit's zero-candidate count into the existing CI audit step.
