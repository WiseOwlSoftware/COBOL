# PB5314 - a RECEIVE that takes its NO DATA branch sets TEXT LENGTH to 0 but leaves END KEY at the previous RECEIVE's value

**Sites:**

- `src/WiseOwl.Cobol.Runtime/Communication/MessageControlSession.cs` (`Receive`)

**Mechanism.** "If less than a message is transferred, the content of the data item referenced by data-name-9 is set to 0" (§1985:XIV.2.2.4 GR12), and the CD's items "are appropriately updated by the message control system (MCS) at each execution of a RECEIVE statement" (§1985:XIV.3.5.4 GR6). The no-data branch of `Receive` sets the text length to 0 and does not touch the end key, so a program that tests END KEY after NO DATA sees the last message's 2.

None of them is recorded: the adjudicated non-conforming verdicts wait in `E:/COBOL-coord/scratch/coderead-85/held-for-register.json`.
