# PB3883 — integer-of-boolean-not-implemented-at-run-time: FUNCTION INTEGER-OF-BOOLEAN compiles under -std=cobol2014 but the run aborts: 'attempt to use non-implemented function'

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S2) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\integer-of-boolean-not-implemented-at-run-time.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\integer-of-boolean-not-implemented-at-run-time\`.

## Summary

GnuCOBOL 3.2 under `-std=cobol2014` compiles a reference to the standard intrinsic function INTEGER-OF-BOOLEAN with no
diagnostic, and the run ends at the call with `libcob: error: attempt to use non-implemented function`, exit code 1.
The default dialect refuses the same source at compile time (`FUNCTION 'INTEGER-OF-BOOLEAN' is not implemented`): the
`-std=cobol2014` (and `-std=cobol2002`) word list re-activates a function that cobc's own table marks as not
implemented. Verdict: GNUCOBOL-DEFECT. Class: compiles but is not implemented at run time. Edition: 2014.

## Expected result (per ISO)

The program is legal and its run displays `[5]` and then `END`.

- §8.5.2.5 1) (checked): "An elementary data item described as boolean by its PICTURE character-string" is of category
  boolean; §13.18.40.4 14) (checked): "Each symbol '1' represents a boolean position that shall contain a boolean
  character". §8.3.3.4.1 (checked): "Boolean literals are of the class and category boolean", so `VALUE B"101"` is a
  boolean VALUE for a PIC 1(3) item.
- §15.45.3 1) (checked): "Argument-1 shall be of class boolean." WS-BOOL is.
- §15.45.4 1) b) and c) (checked): "The unsigned binary value represented by the same bit configuration as the bit
  configuration of that temporary boolean data item is determined." and "The numeric value determined in subrule 1b is
  the returned value." B"101" is 5; COMPUTE stores 5 in PIC 9.
- §4.2.2 (checked): the implementation shall provide the functionality of every required element; INTEGER-OF-BOOLEAN
  is not listed in A.3 or A.4.

Edition: INTEGER-OF-BOOLEAN is part of the 2014 edition: Annex E (§E.1, checked) lists every 2023
addition as added (§E.3.3 22), checked) and does not list it. (Derived; the repository holds no 2014 text. GnuCOBOL's
`cobol2002.words` and `cobol2014.words` activate the function, which agrees; WiseOwl's catalog windows it from 2002.)

Citations inherited from the night records: The slice carried `§15.43.4 2)` for this function; §15.43 is HIGHEST-ALGEBRAIC and the check fails for INTEGER-OF-BOOLEAN. The function is §15.45; §15.45.4 1) b) and c) are used instead.

Edition as recorded by the adjudicator: 2014. `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Fix site (GnuCOBOL 3.2 source, read observationally)

In `gnucobol-3.2` (read observationally; identifiers only):

The function is declared in the compiler's intrinsic table as known but not implemented, and libcob carries only a
stub, but the `-std=cobol2014` word list re-activates it, so the compile-time refusal that cobc has for such functions
never fires:

- `cobc/reserved.c`, `function_list[]`, the `INTEGER-OF-BOOLEAN` entry (line 3510): its `active` member is `CB_FEATURE_NOT_IMPLEMENTED`.
- `cobc/tree.c`, `cb_build_intrinsic` (line 7030): a function whose entry is `CB_FEATURE_NOT_IMPLEMENTED` is refused with
  `FUNCTION '%s' is not implemented`. This is the diagnostic the default dialect prints.
- `config/cobol2014.words`: line 535 `not-intrinsic-function: DIALECT-ALL`, then line 570 `intrinsic-function: INTEGER-OF-BOOLEAN`
  (`config/cobol2002.words` has the same pair, line 534 and line 564).
- `cobc/reserved.c`, `change_intrinsic` / `set_intrinsic_mode` (line 4979): the DIALECT-ALL deactivation moves the
  entry from `CB_FEATURE_NOT_IMPLEMENTED` to `CB_FEATURE_DISABLED`; the later activation then moves it from
  `CB_FEATURE_DISABLED` to `CB_FEATURE_ACTIVE`. The function's own FIXME comment (line 4981) names this
  not-implemented, disabled, active sequence as unhandled. After it, `cobc -std=cobol2014 --list-intrinsics` reports
  the function as implemented ("Yes") and `cb_build_intrinsic` accepts it.
- `libcob/intrinsic.c`, `cob_intr_integer_of_boolean` (line 7127): calls `error_not_implemented` (line 3135), which sets
  `EC-IMP-FEATURE-MISSING` and calls `cob_fatal_error (COB_FERROR_FUNCTION)`; `libcob/common.c`, `cob_fatal_error`
  (line 9109) prints `attempt to use non-implemented function` and ends the run with exit code 1.

Two fixes are possible, and they are independent: (a) make `set_intrinsic_mode` keep `CB_FEATURE_NOT_IMPLEMENTED`
through a DISABLED-then-ACTIVE sequence, so that every dialect refuses the function at compile time, as the default
dialect already does; (b) implement `cob_intr_integer_of_boolean`. 

The same mechanism covers all six functions of this group (BOOLEAN-OF-INTEGER, CHAR-NATIONAL, EXCEPTION-FILE-N,
EXCEPTION-LOCATION-N, INTEGER-OF-BOOLEAN, STANDARD-COMPARE; records in this directory), so fix (a) is one change
for all of them and one upstream ticket can carry all six repros.

## Draft issue

**Title:** FUNCTION INTEGER-OF-BOOLEAN compiles under -std=cobol2014 but the run aborts: 'attempt to use non-implemented function'

**Body:**

Environment: GnuCOBOL 3.2.0 (Ubuntu gnucobol3 3.2-4build1), Linux x86_64.

Steps:

    cobc -std=cobol2014 -fformat=free -x -o iob iob.cob
    ./iob

with iob.cob:

```
IDENTIFICATION DIVISION.
PROGRAM-ID. IOB.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 WS-BOOL PIC 1(3) VALUE B"101".
01 WS-NUM  PIC 9.
PROCEDURE DIVISION.
    COMPUTE WS-NUM = FUNCTION INTEGER-OF-BOOLEAN(WS-BOOL)
    DISPLAY "[" WS-NUM "]"
    DISPLAY "END"
    STOP RUN.
```

Observed: the compile succeeds with no diagnostic (also with -fsyntax-only -Wall). The run prints nothing from the
DISPLAY statement and ends with exit code 1:

    libcob: error: attempt to use non-implemented function

Without -std (default dialect), the same source is refused at compile time:
`iob.cob:8: error: FUNCTION 'INTEGER-OF-BOOLEAN' is not implemented`. `cobc -std=cobol2014 --list-intrinsics` lists INTEGER-OF-BOOLEAN as
implemented ("Yes"); plain `cobc --list-intrinsics` lists it as "No".

Expected: the program is valid COBOL 2014 (FUNCTION INTEGER-OF-BOOLEAN, ISO/IEC 1989 15.45). Per
15.45.4 rule 1 the result is the unsigned binary value of the bit configuration, B"101" = 5; the run should display
`[5]` and then `END`.

Cause, as far as we can see: config/cobol2014.words (and cobol2002.words) first deactivates all functions with
`not-intrinsic-function: DIALECT-ALL` and then activates INTEGER-OF-BOOLEAN; set_intrinsic_mode in cobc/reserved.c turns the
not-implemented entry into disabled and then into active (its FIXME notes this), so cb_build_intrinsic's
"is not implemented" check is bypassed and the call is generated against the libcob stub cob_intr_integer_of_boolean, which calls
error_not_implemented. Either keeping the not-implemented state through that sequence (compile-time refusal in every
dialect) or implementing the function would remove the run-time abort. The same applies to BOOLEAN-OF-INTEGER,
CHAR-NATIONAL, EXCEPTION-FILE-N, EXCEPTION-LOCATION-N, INTEGER-OF-BOOLEAN and STANDARD-COMPARE.
