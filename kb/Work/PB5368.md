# PB5368 - commit 1a7a5bdb2b committed generated .dll, .g.cs and runtimeconfig files into conformance-suite/cases/14.9.30-READ: a probe built beside its case source, and nothing ignores or refuses them

**Sites:**

- `.gitignore` (the conformance-suite section, lines about 156-161, which ignores `conformance-suite/suites/` and `conformance-suite/results/` but not the case folders)
- `scripts/audit_suite_case_files.py` (a new tree audit, created by the change, that refuses a compiler output under `conformance-suite/cases/`; the name is a proposal)

**Evidence gathered (this session, origin/main 4792ae4c9c).** Commit 1a7a5bdb2b (PB5117) added `WiseOwl.Cobol.Runtime.dll` (4.9 MB), `pb5117_random_read_dup_status.dll`, `.g.cs`, `.runtimeconfig.json` and the `_1985` pair under `conformance-suite/cases/14.9.30-READ`. It is an ancestor of origin/main. The files are no longer in the tree: `git log --diff-filter=D` shows 30fa8cc32d "PB5117: drop probe build artifacts from the golden folder" removed them, so the cleanup is done and is not owed. Today `git ls-files conformance-suite/cases/14.9.30-READ` lists only `.cob` and `.out` files.

**Mechanism.** The compiler writes its outputs (`.dll`, `.g.cs`, `.runtimeconfig.json`, and a copy of the runtime dll) beside the source it compiles, so a probe run on a file inside a case folder leaves build output in the golden folder, and `git add` of the folder takes it. `.gitignore` covers `samples/` and `tests/nist/programs/` the same way but has no pattern for `conformance-suite/cases/`, and no audit refuses a binary or generated file there, so the first mistake commits 4.9 MB of binaries and the next one will too. The history keeps the blob regardless of the later removal.

**Fix direction.** Ignore the generated suffixes under `conformance-suite/cases/` and add a tree audit (run by the inert and tooling gates) that fails when a tracked file under `conformance-suite/cases/` is not a source, golden or manifest kind; the allow-list is derived from the suite's own generator, not hand-kept. Whether to purge the blob from history is deleting history, which stays the owner's; not proposed.

**Source.** PB5197's report, cleanup lead.
