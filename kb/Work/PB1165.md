# PB1165 — OPEN

## The rule (every citation re-run by the registrar through `cite.py --check`)

> 1) If the returning item in the activated element is not described with an ACTIVE-CLASS phrase, the conformance rules are the same as if a SET statement were performed … (rule 2 gives the ACTIVE-CLASS case, re-describing the sender from the invocation form)

`python scripts/spec/cite.py --check 14.8.3.3 "…"` → `OK  §14.8.3.3 1)  (Elementary items)`

## Finding — `returning-items` (rejects-legal-source; rows `GR-14.8.3.3-2`)

**Mechanism.** An ACTIVE-CLASS returning item is compared as an ACTIVE-CLASS sender of the declaring class; §14.8.3.3 rule 2's re-description of the sender from the invocation form (class-name -> ONLY, other reference -> its description) is not implemented

**Repro.** RIB2 instance method MK 'LINKAGE SECTION. 01 R USAGE OBJECT REFERENCE ACTIVE-CLASS. PROCEDURE DIVISION RETURNING R.' 'SET R TO SELF'; RID2 INHERITS FROM RIB2; main '01 D USAGE OBJECT REFERENCE RID2. 01 D2 USAGE OBJECT REFERENCE RID2.' 'INVOKE RID2 "NEW" RETURNING D' 'INVOKE D "MK" RETURNING D2' 'INVOKE D2 "WHO"' (p2.cob). Also RIB3 FACTORY method MAKE returning ACTIVE-CLASS, 'INVOKE RID3 "MAKE" RETURNING DO' with DO 'OBJECT REFERENCE RID3 ONLY' (p3.cob).

**Expected from the spec.** Rule 2 b) 4.: invoked with the RID2-typed reference D, the sender is described RID2, and SET D2 TO it is §14.9.39.3 SR12 a)2. -> compiles, prints DERIVED. Rule 2 b) 1.: invoked with object-class-name RID3, the sender is 'RID3 ONLY' (FACTORY absent as in the returning item) -> SR12 a)1. admits the RID3 ONLY receiver -> compiles, prints DERIVED.

**Observed / reasoning.** p2: COBOLNET0828 'the class containing the ACTIVE-CLASS sender (RIB2) is not RID2 or one of its subclasses (ISO §14.9.39.3 SR12 b)2.)'. p3: COBOLNET0828 'the receiver is described with the ONLY phrase, so an ACTIVE-CLASS sender is not permitted (SR12 b)1.)'. OoBindResolvedInvoke passes m.Binding.Returning.Pic unchanged to ObjectRefAssignmentMismatch; the invocation site (class-name / SELF / SUPER / typed reference) is known there but never used to derive the sending description. The C# projection must also cast the declaring-class-typed result to the invoking description.

**Code site.** src/Cobol.Net.Compiler/Binding/Procedure/Verbs/OoBinder.cs#OoBindResolvedInvoke (§14.8.3.3 rule-1 block near :533)

## What the fixer owes

In OoBinder.OoBindResolvedInvoke (the §14.8.3.3 rule-1 block near :533) derive the SENDING description from the invocation site (class-name / SELF / SUPER / typed reference) per rule 2 b) 1.-4. and the FACTORY sentence before calling ObjectRefAssignmentMismatch, and have the C# projection cast the declaring-class-typed result to the invoking description. Goldens p2.cob (DERIVED) and p3.cob (FACTORY MAKE into `RID3 ONLY`).
