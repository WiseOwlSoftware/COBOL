# PB3808 — an emptied owed entry still counts

**Sites:** `scripts/spec/audit_witness_loss.py#owed_statements`, `scripts/spec/audit_witness_loss.py#restore_records`, `scripts/spec/audit_witness_loss.py#run_history`

## Measured

`owed_statements` strands a row by popping notes from `owed[rid]` but leaves the emptied dict. Probed by the reviewer:
`Erasure(c1, notes, verdict CONFORMS)` then `Erasure(c2, notes, verdict PARTIAL)` on a row now CONFORMS with empty notes
gives `({R: {}}, {R: PARTIAL})`; `restore_records` emits `[{rule-id R, verdict CONFORMS, editions 2023}]` and
`run_history` prints "rows OWED a statement back: 1 (notes 0, derivation 0)". The record is a no-op (omitted notes are
kept), so nothing is corrupted, but the count and the batch mislead. Live `--history` has 0 such rows today.

## Acceptance

- `owed[rid]` is dropped when the pop leaves it empty, or `owed` is built from the latest erasure per (rid, field) after
  the loop (one rule, not a clean-up pass).
- A self-test arm with the two-erasure scenario: the row is STRANDED only, `rows OWED` is 0 and no restore record is
  emitted.

## Landed

`owed_statements` now builds `latest[(rid, field)]` (the nearest erasure to the present wins, rows that vanished or say
something again are skipped) and partitions it once into `owed` and `stranded`, so a stranded row never gets an emptied
`owed` entry (no pop, no clean-up pass). Self-test arm "a later erasure under another verdict strands the row only"
pins the two-erasure scenario: `owed` is empty, `stranded` is `{rid: PARTIAL}`, `restore_records` emits nothing.
