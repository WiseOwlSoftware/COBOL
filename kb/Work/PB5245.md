# PB5245 - at --std 85 TERMINATE discards a saved next group integer, so the final control footing prints on the page the NEXT GROUP clause had finished: TerminateCore applies the 2023 rule (no effect if TERMINATE is next) where 1985 presents the footings as body groups through the fit tests

**Sites:**

- `src/WiseOwl.Cobol.Runtime/IO/ReportWriter.cs` (`TerminateCore`: discards the saved integer and restores LINE-COUNTER; `PresentBody`, `PlaceAfterSavedNextGroup`)
- `src/WiseOwl.Cobol.Runtime/Control/DialectBehavior.cs` (`TerminateDiscardsSavedNextGroup`, VCR row 7.58)

**Mechanism.** §1985:XIII.3.10.8 GR3 makes every body group pass the fit test, and after a page advance the RWCS "moves the saved next group integer into LINE-COUNTER" before the trial; 1985's TERMINATE produces the control footings as body groups (§1985:XIII.4.7.4 GR1). `PresentBody` and `PlaceAfterSavedNextGroup` implement the saved-integer arms for every group a GENERATE presents (the read's trace matched the 1985 rules for five groups across seven pages). But `TerminateCore` discards the saved integer and restores LINE-COUNTER first, by the 2023 rule that a saved next group has "no effect at all if a TERMINATE is next executed" (kb/Work PB957 landed it at every edition), so at 85 the final footing is placed as if the last detail's NEXT GROUP had not been processed.

**Found by.** The 1985 code read, slice 51.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids below. None of them is recorded: the code read's non-conforming verdicts of slices 36-56 wait in `E:/COBOL-coord/scratch/coderead-85/pipe-for-register.json`.

**Rules (1 claimed; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-GR-XIII.3.10.8-3` - `§1985:XIII.3.10.8 GR3` (read: PARTIAL, harm: wrong-answer): "moves the saved next group integer into LINE-COUNTER"; `§1985:XIII.4.7.4 GR1` (TERMINATE produces the control footings).

**Repro (`E:/COBOL-coord/scratch/coderead-85/reprobe-85c/rw_termng.cob`).** `RD RPT CONTROL IS FINAL PAGE LIMIT IS 20 LINES HEADING 1 FIRST DETAIL 5 LAST DETAIL 12 FOOTING 16.`, `01 DL TYPE IS DETAIL LINE PLUS 1 NEXT GROUP 10.` (`ITEM`), `01 CFF TYPE IS CONTROL FOOTING FINAL LINE PLUS 1.` (`TOTAL`); INITIATE, GENERATE DL twice, TERMINATE, DISPLAY PAGE-COUNTER and LINE-COUNTER; `cobol.exe --std 85 --source-format fixed --run rw_termng.cob`.

**Observed (the records-85c build of origin/main f2cf36fd15, rerun 2026-11-10).** `T PAGE 0000000001 LINE 0000000012`; the report file has ITEM on lines 5 and 11 and TOTAL on line 12 of page 1.

**Expected (from the 1985 text, the read's trace).** The second detail ends on line 11, past the NEXT GROUP integer 10, so LINE-COUNTER becomes FOOTING (16) and 10 is saved; the CF FINAL TERMINATE produces fails the fit test (17 > 16), the page advances, the saved 10 goes into LINE-COUNTER, and TOTAL prints on page 2 line 11: `T PAGE 2 LINE 11`.

**Fix direction (root cause, CLAUDE.md rule 4).** The discard is an edition rule; give `TerminateCore` the 1985 arm that leaves the saved integer for the fit test of the footings it produces, beside the 2023 arm, with a test of each edition on this program.
