# PB5364 - McsStore.DrawRunUnit retries without bound on RegionLockResult.Held: the McsStore constructor can hang on the sidecar host instead of answering status 92

**Sites:**

- `src/WiseOwl.Cobol.Runtime/Communication/McsStore.cs:57` (`McsStore.DrawRunUnit`)
- `src/WiseOwl.Cobol.Runtime/IO/Sharing/HostRegionLocks.cs` (`RegionLocks.Hold`, and the sidecar hold and look members that return Held: read, unchanged)
- `src/WiseOwl.Cobol.Runtime/Communication/McsStore.cs` (`MaxRunUnitDraws`, `Statement`, `_runUnit`)
- `tests/WiseOwl.Cobol.Tests.Unit/MessageControlTests.cs` (`HostThatAnswersEveryLivenessByteHeld_IsStatus92_ForEveryStatement_AndDoesNotHang`, `UnlistableLockDirectory_AnswersALivenessByteHeld_AndTheWaitingMutexUnavailable`, `UnobservableHost`)
- `docs/rearchitecture/DESIGN-communication-facility.md` (§6, the 92 paragraph and the witness list)

**Mechanism.** `DrawRunUnit` draws a random run unit id and takes a lock on it, retrying while the result is `RegionLockResult.Held`, on the reading that Held means a 2^-60 id collision. The report states that the sidecar host (macOS, the other Unixes) returns Held for a non-waiting Hold whenever the lock directory is unobservable (`Look` throws `UnauthorizedAccessException` on the listing) or every publish try lost its race. Neither is a collision, so the loop never ends and the `McsStore` constructor spins forever, where the first statement should answer I-O status 92.

**Fix direction.** Bound the retry, and make the unobservable-directory case a distinct result that the caller answers as 92 (CLAUDE.md: an unresolvable input fails loudly). A test with an unlistable lock directory pins it (a Unix-only witness).

**Repro.** Not run on the sidecar host (Windows clerk host); code site given by the report.
