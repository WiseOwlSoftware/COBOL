# PB913 — OPEN — the compiler's private spelling, printed to the user

Source: the `PB457` report, "New defects" item 1. Re-measured here.

## The measurement

`<scratch>/reg7/probe/n_refmod_enum.cob`, `--std 2023`:

```
n_refmod_enum.cob(8,12): error COBOLNET1647: 'WS-CAP(1:2)': reference modification of a numeric item of
USAGE BinaryLong (SR1 admits usage DISPLAY or NATIONAL only) is not permitted (ISO §8.4.3.3.3 SR1)
```

The user wrote `USAGE BINARY-LONG` (or `COMP-5`). **`BinaryLong` is a C# identifier** — `Usage.BinaryLong`
— and it appears in a message that is otherwise written in COBOL. There is no COBOL word `BinaryLong`, so
a reader searching the standard or their own source for it finds nothing.

## The rule is RIGHT; only the rendering is not

```
$ python scripts/spec/cite.py --check 8.4.3.3.3 "a numeric data item of usage display or national that is not subordinate to a strongly-typed group item"
OK  §8.4.3.3.3 1)  (Syntax rules)
    — a numeric data item of usage display or national that is not subordinate to a strongly-typed group
      item,
```

The refusal is correct and the clause is correct. This note is about the seven characters between "USAGE "
and " (SR1".

## The code site

`src/Cobol.Net.Compiler/Binding/ReferenceResolver.cs#RefModExclusion`, the `$"a numeric item of USAGE
{p.Usage}"` arm. It is PRE-EXISTING and reached by every binary and packed item, not only by the dynamic
table work that found it.

## The sweep, and the shape that ends it

`grep -rnE '\{[A-Za-z_.]*\.(Usage|Category|PicCategory)[^}]*\}' src/Cobol.Net.Compiler/` over the strings
that reach `Edition.Error` / `Edition.Warning`. Every hit is this defect.

⛔ The fix is NOT a `switch` at the call site. It is ONE renderer — `Usage.ToCobolWord()` and its
`PicCategory` twin, driven from the same table the LEXER and `PictureAnalyzer.ParseUsage` already use to
RECOGNISE those words, so a usage cannot be added with a reserved-word spelling and no rendering — plus a
semgrep rule (the repo already ratchets `cobolnet-raw-diagnostic-code-literal` and
`bound-node-carries-rendered-text`, so the mechanism exists) forbidding a raw enum interpolation inside a
diagnostic string. That is what makes the NEXT usage automatic; a per-site cast is what made this one
possible.
