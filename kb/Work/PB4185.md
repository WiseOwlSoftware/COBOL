# PB4185 — PB4147's registry split left two descriptions stale

Both sites are read on the PB4147 branch (`origin/worktree-wf_adb70c0b-786-1`, pull request #860); main still has the pre-split harness, so the note is open until that pull request merges and then fixes both. They are two sites of ONE mechanism: the registry split changed what the harness carries and two descriptions of it were not updated.

**Sites:** `conformance-suite/harness/generate.py` (`repository_inputs`, line 1161, annotated `-> tuple[Inputs, list[str]]`; `generate`, line 1189, `problems: list[str]`); `conformance-suite/README.md` (line 75, the sentence on a WiseOwl compile option).

**Site 1 (R1-1).** The registries' problems changed from strings to `Problem` tuples (path, message). `repository_inputs()` is still annotated `-> tuple[Inputs, list[str]]` and `generate()` still takes `problems: list[str]`, so both signatures misstate what they carry.

**Site 2 (R1-3).** The README sentence lists `sign-encoding`, `numeric-display` and `flag-extensions`, while `generate.WISEOWL_OPTIONS` (line 87) also accepts `repository-update` (`on` / `off`), which `wiseowl/options/` files and the per-step files use (`DESIGN-conformance-suite` section 3.1 build).

**Fix direction.** Annotate with the `Problem` type; derive the README list from `WISEOWL_OPTIONS` or add the option, and say which in `docs/rearchitecture/DESIGN-conformance-suite.md`. Sweep the other prose that lists the options.
