# PB692 — OPEN — a file control entry rule with no home

Found 2026-09-05 by the `PB334` implementer (report §"New defects" 2): `grep -rn "12.4.5.5.2" --include=*.cs src/`
returns nothing but generated-parser noise, and the entry compiles.

## The rule

§12.4.5.5.2 SR2 (`cite.py --check 12.4.5.5.2 "The DYNAMIC and RANDOM phrases shall not be specified for a
sequential file"` → OK 2)). It is a rule about the FILE CONTROL ENTRY, so it cannot live on a verb: PB334 enforces
§14.9.30.3 SR6 on the sequential READ arm through the shared check precisely because `file.AccessMode == Random` is
reachable there today — a screen at the statement, not a substitute for SR2 at the entry.

## Fix

In the FILE-CONTROL binder (`DataBinder`'s file control entry handling, where ORGANIZATION and ACCESS MODE are both
captured onto `FileModel`): refuse RANDOM/DYNAMIC when the organization is sequential (the default organization is
sequential — cover the OMITTED clause too), at every edition (the 1985 text has the same rule; confirm in the version
reference), through an existing entry-rule descriptor if one fits or one new code. Sweep the sibling entry rules of
§12.4.5.5.2 while there (the RELATIVE KEY phrase's organization conditions, the same clause) and measure which have a
home; negatives at four editions. Note for whoever lands it: once SR2 is enforced, PB334's SR6 screen on the
sequential arm becomes unreachable — keep it (cheap, and it is the statement's own rule), but say so beside it.
