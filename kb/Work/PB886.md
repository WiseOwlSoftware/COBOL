# PB886 — LANDED — the intermediate that exists to preserve the sender destroys it

Source: the `PB411` report, "New defects".

## The measurement

`<scratch>/reg6/probe/p31_bitrefmod.cob` (PROGRAM-ID `R6P31`), `--std 2023 --run`:

```cobol
01 BE PIC 1(8) USAGE BIT VALUE B"10110011".
01 B1 PIC 1(4) USAGE BIT.
01 B2 PIC 1(4) USAGE BIT.
PROCEDURE DIVISION.
    MOVE BE(1:4) TO B1
    DISPLAY "ONE=[" B1 "]"
    MOVE BE(1:4) TO B1 B2
    DISPLAY "TWO=[" B1 "][" B2 "]"
```

```
ONE=[1011]
TWO=[1000][1000]
rc=0
```

The single-receiver form is correct. The multi-receiver form — the one that MATERIALISES the intermediate —
keeps the leading bit and zeroes the rest, into both receivers.

## The rule

```
$ python scripts/spec/cite.py --check 14.9.25.4 "is evaluated only once, immediately before data is moved to the first of the receiving operands"
  OK  §14.9.25.4 1)  (General rules)
      If identifier-1 is reference-modified, subscripted, or is a function-identifier, the reference modifier,
      subscript, or function-identifier is evaluated only once, immediately before data is moved to the first
      of the receiving operands.
```

GR1's own equivalence makes `MOVE temp TO B1` / `MOVE temp TO B2` identical to the single-receiver move, so
`1011` is owed in BOTH forms. §8.4.3.3.4 GR6 makes the reference-modified operand an ELEMENTARY item of the
sender's own class — boolean here, not alphanumeric.

## The code site

`src/Cobol.Net.Compiler/Binding/Procedure/SendingValueTemp.cs#OfPlace`, the `place is RefModPlace` arm: the
intermediate is built as `PicInfo(rm.Category, ..., Length: 0, ...)` with a `DynLimit` CHARACTER carrier.
A character carrier has no boolean positions, so four bits round to one.

**Measured independent of PB411's change**: the byte-identical elementary case takes the identical path in
the pre-change code (its `Pic` is non-null, so PB411's `UsageOf` edit does not touch it) and gives the same
wrong answer.

## Why it clusters with PB394 and is not folded into it

`kb/Work/PB394` (status `half`, claims `GR-14.9.25.4-1`) owns the OTHER half of the same GR1 sentence — the
sending operand re-rendered once per receiver — and it records a variable-length group's

## The sibling sweep

`SendingValueTemp.OfPlace`'s carrier choice must be asked for every CLASS a reference-modified or whole-item
sender can have, not only alphanumeric: boolean (measured wrong), national, and the zero-length /
variable-length group route `PB896` files. The structural remedy is for the intermediate's `PicInfo` to be
DERIVED from the sender's own item (one classifier) rather than assembled from a category plus a fixed
carrier — the shape that makes the national case automatic instead of the next bug.


## LANDED — 2026-09-21, wave 42 (group MOVE OPERANDS)
