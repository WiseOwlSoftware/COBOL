# PB4586 — the directive's COBOL1623 is lost behind any parse error

**Sites:** `src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs#ValidateCobolWords` (the SR3 / SR4 category check, which needs no tree).

**Found by** the determination of PB4239 (wave 20261861 d, pin fb6fcc048), sibling S3. `ValidateCobolWords` runs in
`VersionConformancePass`, which needs a parsed group, so the directive's SR3 and SR4 verdict (COBOL1623) is never reported when
the parse fails. Evidence (probes under `E:/COBOL-coord/scratch/op-w20261861/d/p/`):
- r19: `>>COBOL-WORDS UNDEFINE "AUTHOR"`, where AUTHOR is in none of the 2023 word lists (so §7.3.10.3 SR3 refuses the literal),
  plus a `MOVE TO.` statement error. The compile reports only COBOL5506 and no COBOL1623.
- r17 and r10 (before the PB4239 fix) show the same masking. r10 even prints the COBOL5926 warning "withdrew COMP-3" for a
  directive the compiler holds illegal.

**Owed.** The category check needs no tree, so it can run with the directive stage or before the parse gate, and the violation
of §7.3.10.3 SR3 / SR4 is indicated whether or not the parse succeeds. The determination judged it neither PB4239's question nor
PB4488's, PB4572's or PB4573's.

## Landed (wave 20261863 A)

`CobolWordsCategoryPass` (new, `src/WiseOwl.Cobol.Compiler/Validation/`) holds the SR3/SR4 verdict and its one population; `CompilerDriver.Compile`
runs it on the directive stage's `CobolWordsMap` right after the parse and before the frontend gate (the edition context is built
first), and the frontend-error result carries the edition sink's diagnostics beside the parse errors. `VersionConformancePass` no longer
holds `ValidateCobolWords`, `IsReservedContextOrIntrinsic` or `ReportCobolWordsInvalid`. A directive that fails SR3/SR4 in a program
that parses reaches the bind as before. Golden (negative): `conformance:cases/7.3.10-COBOL-WORDS/pb4586-cobol-words-sr3-verdict-beside-a-parse-error`;
unit: `CobolWordsDirectiveTests.TheCategoryVerdict_IsReportedBesideAParseError`, `ALegalDirective_BesideAParseError_DrawsNoCategoryVerdict`.

**Sites:** `src/WiseOwl.Cobol.Compiler/Validation/CobolWordsCategoryPass.cs` (`Run`), `src/WiseOwl.Cobol.Compiler/CompilerDriver.cs`
(`Compile`), `src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs` (`Run`: the call is gone).
