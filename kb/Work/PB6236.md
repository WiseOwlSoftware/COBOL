**Rule it breaks:** §2023:11.8.3 SR2 ("Each method prototype in each implemented interface shall be such that the object interface of this class conforms to all implemented interfaces"), §2023:11.7.3 SR9, §2023:8.4.3.9.3 SR7 and §2023:11.6.3 SR5 are syntax rules of the definition text; OoDriver.BindParameterized states that every syntax rule governs a parameterized definition whether or not anything expands it, and binds its formals (kb/Work PB2051, PB2937). The SR4b loop in OoClassTable.Build asks _parameterizedInterfaces; ValidateInterfaceInheritance, the next rule over the same INHERITS closure, does not.

**Scenario:** CLASS-ID. P USING T. ... OBJECT IMPLEMENTS I. with I an ordinary interface of the REPOSITORY declaring METHOD-ID. M, and P writing no method M; nothing writes EXPANDS P. BinderDriver.cs:207-210 call ValidateInterfaceInheritance, ValidateOverrideSignatures, ValidatePropertyAccessorPairs and ValidateImplements, whose loops read table.Classes (OoConformance.cs:34, 59, 103) and table.Interfaces (OoConformance.cs:380); P is in ParameterizedClasses only, so no COBOL0841 (interface not implemented) is reported, where the same class without USING T is refused. Likewise a P method M with PIC 9(4) USING where I.M has PIC X(4), a GET RETURNING PIC 9(5) with a SET USING PIC X(3) in P (SR7), and an unexpanded parameterized INTERFACE inheriting two non-conforming M prototypes (SR5, COBOL2762) all compile clean. Only the pairs that involve no formal are decidable on the skeleton, and none of these does.
