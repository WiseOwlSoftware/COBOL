# PB3864 — the gate command can run in a different worktree than the agent's own

**Sites:** `.claude/skills/workstream/templates/dispatch-spec-implementer.md` (the GATE paragraph that gives
`pwsh <repo>/scripts/build-local.ps1 -Priority BelowNormal`), `.claude/skills/workstream/templates/finisher-brief.md` (the
finisher's gate command), `scripts/build-local.ps1` (whole: its repository-root resolution is top-level script code)

## The defect

The implementer and finisher templates give the gate as the relative `pwsh scripts/build-local.ps1 -Priority
BelowNormal`. A relative script path resolves against the shell's current directory, and a PowerShell session shared
between background calls keeps a cwd that is not the agent's worktree. In wave 20261711 group A the agent's first gate
launch ran in sibling worktree `wf_8f6f9b6c-5d5-13` instead of its own `wf_8f6f9b6c-5d5-15`: leg 1 was green THERE. The
agent noticed and discarded it. An agent that did not would report a GREEN gate whose evidence covers the sibling's tree,
not its own head.

## Failure scenario (verbatim from the report)

"my first gate launch ran in a sibling worktree (`wf_8f6f9b6c-5d5-13`, a relative script path resolved from a shared
PowerShell cwd): leg 1 green there, harmless to it, discarded; the gate above is the one for this head."

## Acceptance

- The templates give the gate with the worktree's ABSOLUTE script path (the dispatch spec renders it per worktree), and
  say why.
- `scripts/build-local.ps1` refuses to run when its own repository root is not the caller's current worktree (the cwd's
  `git rev-parse --show-toplevel`), naming both paths and exiting non-zero, so a relative call from the wrong directory
  can never produce a record. A self-test arm seen RED first.
- Sweep the other scripts the templates tell an agent to run by a relative path (`linux-gate.sh`, `enqueue.py`,
  `gate_slot.py`) for the same confusion.
- Standing owner rules: fix the root causes, never simply making the diagnostic pass; always be consistent with
  ourselves barring an explicit requirement differently.
