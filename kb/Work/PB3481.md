# PB3481 — two gaps in the PB3337 transaction witnesses

Low, non-blocking leads from the branch review of PB3337 (`E:\COBOL-coord\scratch\reports\w1137a-PB3337-report.md`). PB3337 has landed (PR #351, main 2353545b2), so this note is ready.

**R1-5. The abnormal-ending wiring is untested.** `RunUnit.NoteEnding` is an exception filter at `ProgramTable.RunOnThisThread`, `RunUnit.Run` and `CallFromHost`, and `RunUnit.Terminate` chooses the file-only ROLLBACK by `EndedAbnormally`. `RunUnit.Run`'s boundary has a witness. The ProgramTable boundaries need a compiled program (relate to PB3338, which makes the facility reachable from source).

**R3-2. The retake witness cannot fail.** `An_unsuccessful_reopen_leaves_the_kept_file_lock_standing` (CommitRollbackRuntimeTests.cs, about line 630) is the witness the DEVLOG names for the `RetakeKeptFileLock` fix. A holds SHARING WITH NO OTHER, so its kept handle is FileShare.None and refuses B's OPEN with '61' by itself on every host (Windows: the mandatory share mode, where `RunUnitFileLock.HostOfThisProcess` is null and the retake is a no-op; Unix: the LOCK_EX flock .NET takes for FileShare.None). Removing both `RetakeKeptFileLock` calls leaves it green. Give A a sharing posture whose kept handle admits B, so only the retaken column lock refuses. **Answered by PB3483:** `RetakeKeptFileLock` and `RunUnitFileLock.Retake` are gone (the kept column is replaced on its own hold, `RunUnitFileLock.Amend`, and put back by `Revert`), and the witness re-OPENs INPUT under SHARING WITH ALL OTHER and asks for a READ ONLY I-O OPEN, which only the restored column refuses on a host that carries the column lock. Only R1-5 remains open here.

**R1-3 (from the branch review of PB3483, `E:/COBOL-coord/scratch/reports/w1140d-PB3483-report.md`). Two exception arms of the column-lock replacement have no test (MANDATORY-PRACTICES I11).** `RunUnitFileLock.cs` about line 140: `Revert`'s refused re-publication (Dispose, return false, so `FileConnector.ReleaseRunUnitFileLock` ends the kept lock entirely) and `TakeRunUnitFileLock`'s Amend `Unavailable` arm (the default: the kept lock stands and the late take runs after `CarryKeptOver` disposed it). `RunUnitFileLockAmendTests` already has a wrapping host (`RacingHost`) that could answer `Unavailable` on the second establishment.

## Landed

Both gaps are closed; no runtime code changed here (the wiring was already correct).

**R1-5.** `CommitRollbackRuntimeTests.A_program_boundary_commits_a_normal_ending_and_rolls_back_an_abnormal_one` (9 cases) drives
`ProgramTable.RunMain` (the `RunOnThisThread` filter, shared by `RunModule`) and the host boundary `CallFromHost` through stub
programs registered by `RegisterModule`, so no compiled program (PB3338) is needed. With the `RunOnThisThread` filter removed
four main-boundary cases fail; with the `NoteEnding` call in `CallFromHost` removed the two host cases fail.

**R3-2.** Answered on main by PB3483 (above), which deleted the give-back-and-retake this lead's witness was for:
`An_unsuccessful_reopen_leaves_the_kept_file_lock_standing` is PB3483's discriminating form, and
`RunUnitFileLockAmendTests` witnesses `RunUnitFileLock.Amend` and `Revert` on the lock-file host (and the OFD host where the
process has it). This branch's own R3-2 witnesses (a READ ONLY variant of that case and two `SidecarColumnLockHostDriftTests`
cases over `RunUnitFileLock.Retake`) were dropped at the merge of origin/main, because the method they witnessed is gone.
