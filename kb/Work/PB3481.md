# PB3481 — two gaps in the PB3337 transaction witnesses

Low, non-blocking leads from the branch review of PB3337 (`E:\COBOL-coord\scratch\reports\w1137a-PB3337-report.md`). PB3337 has landed (PR #351, main 2353545b2), so this note is ready.

**R1-5. The abnormal-ending wiring is untested.** `RunUnit.NoteEnding` is an exception filter at `ProgramTable.RunOnThisThread`, `RunUnit.Run` and `CallFromHost`, and `RunUnit.Terminate` chooses the file-only ROLLBACK by `EndedAbnormally`. `RunUnit.Run`'s boundary has a witness. The ProgramTable boundaries need a compiled program (relate to PB3338, which makes the facility reachable from source).

**R3-2. The retake witness cannot fail.** `An_unsuccessful_reopen_leaves_the_kept_file_lock_standing` (CommitRollbackRuntimeTests.cs, about line 630) is the witness the DEVLOG names for the `RetakeKeptFileLock` fix. A holds SHARING WITH NO OTHER, so its kept handle is FileShare.None and refuses B's OPEN with '61' by itself on every host (Windows: the mandatory share mode, where `RunUnitFileLock.HostOfThisProcess` is null and the retake is a no-op; Unix: the LOCK_EX flock .NET takes for FileShare.None). Removing both `RetakeKeptFileLock` calls leaves it green. Give A a sharing posture whose kept handle admits B, so only the retaken column lock refuses.

**Sites:**
- `src/Cobol.Net.Runtime/Control/RunUnit.cs`
- `src/Cobol.Net.Runtime/Control/ProgramTable.cs`
- `tests/Cobol.Net.Tests.Unit/Store/CommitRollbackRuntimeTests.cs`

## Landed

Both gaps are closed by witnesses; no runtime code changed (the wiring and the retake were already correct).

**R1-5.** `CommitRollbackRuntimeTests.A_program_boundary_commits_a_normal_ending_and_rolls_back_an_abnormal_one` (9 cases) drives
`ProgramTable.RunMain` (the `RunOnThisThread` filter, shared by `RunModule`) and the host boundary `CallFromHost` through stub
programs registered by `RegisterModule`, so no compiled program (PB3338) is needed. With the `RunOnThisThread` filter removed
four main-boundary cases fail; with the `NoteEnding` call in `CallFromHost` removed the two host cases fail.

**R3-2.** `An_unsuccessful_reopen_leaves_the_kept_file_lock_standing` now holds SHARING WITH READ ONLY, whose kept handle
(`FileShare.Read`, `LOCK_SH`) admits the second run unit on an advisory-lock host, so only the retaken Table 19 column lock
refuses it. On Windows the mandatory share mode refuses it and `RunUnitFileLock.HostOfThisProcess` is null, so the connector
case cannot discriminate there; `SidecarColumnLockHostDriftTests.ARetakenLockRefusesAsTheOneFirstTakenDid` (144 cases) and
`ARetakeThatMeetsARefusedColumnIsRefusedAndHoldsNothing` witness `RunUnitFileLock.Retake` itself on every host (a no-op
Retake fails 145 of them).
