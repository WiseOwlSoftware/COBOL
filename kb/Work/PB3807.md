# PB3807 — the prune race that find_map guards only half of

**Sites:** `scripts/spec/impact_store.py#mtime`, `scripts/spec/impact_store.py#stale`, `scripts/spec/impact_store.py#maps`, `scripts/spec/impact_store.py#nearest`, `scripts/spec/impact_store.py#prune`, `scripts/spec/impact_store.py#clean_work`, `scripts/spec/impacted_tests.py#find_map`, `tests/WiseOwl.Cobol.Tests.Unit/ImpactMapLaneDriftTests.cs`

## Measured

`maps()` stats every globbed map with no guard. `find_map` guards only the later `load_map` read, for exactly this prune
race (its comment: a map pruned or replaced between the choice and the read). Scenario: the worker finishes a recording
and `impact_store.prune` unlinks an old map while a gate's `gate_plan -> impacted_tests.analyse -> find_map -> nearest ->
maps()` has globbed that file but not yet called `p.stat()`: `FileNotFoundError` propagates out of `analyse`
(gate_plan.py:1100 does not catch it) and the gate dies planning instead of going on unaimed. The window is milliseconds
per prune, so it is rare.

## Acceptance

- `maps()` skips a path whose stat raises `FileNotFoundError`/`OSError`, as `find_map` already treats a vanished map; the
  same for `prune`'s temp-file stat and `clean_work`'s directory stat.
- A self-test removes a globbed map between the glob and the stat (a monkeypatched `stat`) and asserts the plan completes
  unaimed. Sweep: every other glob-then-stat pair in `scripts/spec/impact_*.py` (result reported).
