# PB4374 - Three weak witnesses of PB2555

**Sites** (all land with PB2555's bounced PR #961, not on main at filing):

- (a) `tests/WiseOwl.Cobol.Tests.Unit/MarginRCutNoteTests.cs` (`MarginRCutNoteTests.ACommentLinePastMarginR_IsNotACut`, line 146).
- (b) `conformance-suite/cases/A.1-Implementor-defined-language-element-list/pb2555-statement-cut-at-margin-r.cob` (header, line 8).
- (c) `conformance-suite/cases/A.1-Implementor-defined-language-element-list/pb2555_text_past_margin_r_is_ignored.cob` (line 21).

(a) The comment line (line 9) holds no token. The error's previous token, `BY`, stands on line 10, which has no text past margin R, so the listener never asks about the comment line. The test passes with the comment-line exclusion in `ReferenceFormatMap.CutOf` removed, so it cannot fail for what its name says. Fix: put the offending token's predecessor on a comment line that holds text past margin R, and prove the test red by removing the exclusion once.

(b) The header says `BY CONTENT WS-REPLY` "stands from position 73". BY stands at positions 70-71, inside the program-text area; only `CONTENT WS-REPLY` starts at 73.

(c) This positive golden pins what `l1_margin_r_program_text_area` already pins more strongly (a DISPLAY wholly past margin R, a statement ending exactly at 72, a literal with characters right past 72, identification tags). It adds only the COBOL-85 acceptance edition. Either fold the 85 edition into the stronger case's edition list or keep it with a header that says that is its only job.
