## Landing (wave 20261702 group A)

The split is the design's §16.3 table as built, with the deviations §16.3 now records and why (each from the import DAG
or the code): the notes a branch carries (`branch_lead_notes`, `closed_by_branch`, `add_closed_notes`) are the
population's (`clusters.py`), `ledger_slug` is the report reader's, `DISPATCH_LEDGER` and `ledger_groups` stay `coord.py`'s
(they were never `plan_wave.py`'s), `report_since` stays for `review_coverage.py` (PB3731), `MAKE_SPECS` stays with the
CLI, and the survey's branch matcher keeps its own rule as `reports.BRANCH_MENTION` beside the header's `BRANCH_FIELD`
(206 of the 802 live headers name another branch set under it, so unifying them is a behavior change for its own note).
`plan()` runs five stages over one `PlanState`: `plan_held`, `plan_finishers`, `plan_fill`, `plan_partition` (which
letters each group as it places it) and `plan_budget`. The planner's line of the DAG is a chain (coord, reports,
branch_classify, inflight, clusters, groups, dispatch_ledger, plan_wave), declared once in `scripts/script_layering.py`
with every later split's modules and the stand-in rule for a module whose split has not landed; `ScriptLayeringDriftTests`
runs its `--check`.

  `Report`, never a second parse. The survey matches a report to a branch through `newest_report` (`BRANCH_MENTION`), a
  DIFFERENT rule from `BRANCH_FIELD` on purpose (206 live headers disagree); do not unify them inside a split.
- `scripts/orchestrator/inflight.py#collision`: THE meeting rule; `inflight_file_sets` and the branch readers lazily

  re-points them to `branch_classify`, and script_layering then refuses the old import.
- `scripts/orchestrator/clusters.py#note_of`: the one note reader on the one frontmatter reader; the notes a branch
  closes (`closed_by_branch`) live here because they read a note.
- `scripts/orchestrator/groups.py#finisher_pred`: every predecessor-merge instruction (MergeDriverDriftTests reads this
  file for `merge_drivers.py merge`).
- `scripts/orchestrator/plan_wave.py#plan`: builds a `PlanState` and runs `plan_held`, `plan_finishers`, `plan_fill`,
  `plan_partition`, `plan_budget`; a new rule goes inside one stage. `test_plan_wave.py` patches `pw.plan` and
  `pw.MAKE_SPECS`, so both stay plan_wave's.

  declared, and only a moved file changes `NODES`.
