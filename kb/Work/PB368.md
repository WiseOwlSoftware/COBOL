# PB368 — the right consequence without the condition

**Rows:** `GR-14.9.49.4-2`.

## The program

`<lane3 scratch>/out-b1/probe/gr2-flow-use/p1.cob` — `>>TURN EC-FLOW-USE CHECKING ON`; `SELECT F1` on an absent
file;
`DECLARATIVES D1 SECTION. USE AFTER STANDARD ERROR PROCEDURE ON F1. / D1-P. DISPLAY "D1-ENTER". OPEN INPUT F1.
DISPLAY "D1-EXIT FS=" FS1.` and `DFU SECTION. USE AFTER EC EC-FLOW-USE. / DFU-P. DISPLAY "FLOW-USE-HANDLER".
RESUME AT NEXT STATEMENT. END DECLARATIVES`; MAIN does `OPEN INPUT F1` then `DISPLAY "AFTER"`.

Observed: `D1-ENTER` / `D1-EXIT FS=35` / `AFTER` — **the condition does not exist at all.**

## The rule

> §14.9.49.4 GR2: [if the execution of a USE procedure would be caused while that procedure had previously been
> activated and had not yet returned control] the EC-FLOW-USE exception condition is set to exist

`--check 14.9.49.4 "the EC-FLOW-USE exception condition is set to exist"` → **OK**. The inner OPEN fails on the
same file, so EC-FLOW-USE is set; checking is enabled and a level-3 Format-3 declarative names it, so the GR3 e)
tier selects DFU: `D1-ENTER` / `FLOW-USE-HANDLER` / `D1-EXIT FS=35` / `AFTER`. With no such declarative
EC-FLOW-USE is Fatal (Table 13) and the run unit terminates abnormally.

## What the compiler does

`DispatchEmitter.EmitRunUseBody` (line 284) emits `if (__useActive[__id]) return -1;` and returns quietly. A
tree-wide grep for EC-FLOW-USE finds it ONLY as a catalog row (`ExceptionCatalog.cs`, `L3("EC-FLOW-USE",
EcFatality.Fatal)`) and in the frozen legacy comment `src/CobolSharp.Runtime/FileRuntime.cs:26`.

**The guard is the right consequence, but the rule's sole normative content is the RAISE** — and without it a
program cannot detect its own declarative recursion, and the Table 13 fatal default never fires.

## The fix shape

The fix belongs at the ONE place that knows the guard fired: `EmitRunUseBody`'s early return. That is also the
seam the `>>PROPAGATE` / EC-FLOW-GLOBAL-EXIT / EC-FLOW-GOBACK residue needs — §14.6.13.1.3 item 6 must EXCLUDE
those names from propagation, which is impossible while none of the three conditions exists.

**PB349** owns the drift test this belongs under: every turnable name in `ExceptionCatalog` has a raise site.
This is the third of five such names found inert in one batch (with **PB326**'s two).

**Code sites:** `DispatchEmitter.cs#EmitRunUseBody` (line 284), `#EmitUseMachinery` (line 218, where the guards
are allocated) · `OoEmitter.cs:589` · `ExceptionCatalog.cs`.
