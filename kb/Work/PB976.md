Filed 2026-09-22 by **REGISTRAR #11** from wave 46 group J's lead 1 (PB716 implementer report, lander lead J1:
"CLASS FOR NATIONAL is not carried into codegen … latent wrong answer"). **Re-measured on this registrar's own build
of main `6871b6e10`** (0/0). The latent wrong answer did NOT reproduce, because COBOL.NET's native alphanumeric and
national sets are the same UTF-16 repertoire (memory `charset_utf16`), so an unmarked class built over "the relevant
native character set" happens to be the right set. What the ignored phrase DOES cost today is every syntax rule keyed
on it.

## Reproduced

- `reg11/j1.cob` and `j1b.cob` (control, correct): `CLASS HN FOR NATIONAL IS "0" THRU "9"` + `IF NX IS HN` over
  `PIC N(2) VALUE N"12"` → `NX-IN`; `CLASS GREEK FOR NATIONAL IS 946 THRU 970` over `N"αβ"` → `NX-IN`, `N"ab"` → `NY-OUT`.
  (`j1.cob` itself is the SR17 c) 3. violation below — it should not have compiled.)
- `reg11/j1c.cob`, all four under one SPECIAL-NAMES, compiles clean and runs (`AX-IN`):

```cobol
           ALPHABET AA IS NATIVE
           ALPHABET NA FOR NATIONAL IS NATIVE
           CLASS C1 IS N"0" THRU N"9"                     *> SR17 b) 3.
           CLASS C2 FOR NATIONAL IS 1 THRU 5 IN AA        *> SR17 c) 1.
           CLASS C3 FOR ALPHANUMERIC IS 1 THRU 5 IN NA.   *> SR17 b) 1.
```

## Rules (SR17 = "When the CLASS clause is specified:"; the cite tool's path print is approximate below two levels)

- `python scripts/spec/cite.py --check 12.3.7.3 "When the IN phrase is specified, alphabet-name-4 shall reference an alphabet that defines an alphanumeric character set"` → OK §12.3.7.3 17) (b) 1.)
- `… --check 12.3.7.3 "When the IN phrase is specified, alphabet-name-4 shall reference an alphabet that defines a national character set"` → OK §12.3.7.3 17) (c) 1.)
- `… --check 12.3.7.3 "Each noninteger literal shall be a national literal"` → OK (c) 3.; `"Each noninteger literal shall be an alphanumeric literal"` → OK (b) 3.
  Both literal rules print identically inside SR14 (the ALPHABET literal-phrase) too; the fixer confirms the SR17
  occurrences by line (`specs/ISO_COBOL.md` ≈12552–12583).
- `… --check 12.3.7.4 "The characters specified by the values of the literals in this clause define the exclusive set of characters of which class-name-1 consists"` → OK §12.3.7.4 12)

## What the fixer owes

`SwitchBindClass` (`src/Cobol.Net.Compiler/Binding/DataBinder.Switches.cs:1440`) reads the FOR phrase once, as
`SwitchBindSymbolic` already does for SYMBOLIC CHARACTERS (SR16 — the adjacent method checks `inSet.National !=
national`), and all of SR17 b) 1.–5. / c) 1.–5. are enforced from that one reading, including the numeric-literal
ordinal ranges (b) 2. / c) 2.) and the THROUGH single-character rule. The class's member set is recorded with its
class so a future non-UTF-16 native alphanumeric set (a code-page locale) cannot silently use the wrong one. Re-verdict
SR-12.3.7.3-17 and GR-12.3.7.4-12 (both CONFORMS on evidence that never exercised the phrase). One negative per SR17
arm, one golden per class.
