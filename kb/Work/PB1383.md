## Finding — call-convention-directive (under-rejects)

call-convention-name-1 accepted with no defined convention: the >>CALL-CONVENTION operand screen admits any COBOL word (DirectiveOperand UserWord=true) while the compiler defines no call-convention-name and holds no call-convention state, so an arbitrary name is silently processed as COBOL

**Rows:** GR-7.3.9.3-2

**Repro:**

```
>>SOURCE FORMAT FREE
>>CALL-CONVENTION XYZZY
IDENTIFICATION DIVISION.
PROGRAM-ID. CCMAINC.
PROCEDURE DIVISION.
    CALL "ccsubC".
    STOP RUN.
END PROGRAM CCMAINC.
IDENTIFICATION DIVISION.
PROGRAM-ID. CCSUBC.
PROCEDURE DIVISION.
    DISPLAY "IN SUB".
    GOBACK.
END PROGRAM CCSUBC.
(cobol C.cob --run, pinned adj-d2)
```

**Expected from the spec:** §8.3.2.3.2: a call-convention-name identifies an implementor-defined convention; §7.3.9.3 GR2 b): under call-convention-name-1 the program-name is treated as a LITERAL mapped in an implementor-defined (A.1 item 68: documented) manner. XYZZY identifies no convention COBOL.NET defines, so the compiler must diagnose it (or, if the owner defines conventions -- GnuCOBOL precedence -- process names under that convention's documented literal mapping). Silently applying the COBOL-word mapping is neither.

**Observed:** Compiles clean with no diagnostic and prints 'IN SUB': the lower-case literal still resolves case-insensitively to CCSUBC under the COBOL-word mapping. Operand-shape errors are caught (a literal operand, no operand, two operands -> COBOLNET1911), but any single COBOL word passes. docs/rearchitecture/PHASE-13-plan-vs-spec-review.md V32 flagged this 'sharp edge' and routed it to Wave D; no kb/Work note owns it.

**Code site:** src/Cobol.Net.Editions/ConstructRegistry.g.cs:39 (call-convention-directive-2002 DirectiveOperand UserWord=true); src/Cobol.Net.Frontend/Preprocessor/DirectiveStateRegistry.cs:63 (NONE HELD)

## What the fixer owes (and the sibling sweep)

Diagnose a call-convention-name the implementation does not define; if conventions are defined, hold CALL-CONVENTION state and apply the literal mapping in CALL/CANCEL/INVOKE/program-address binding; document A.1 item 68. Negative golden: `>>CALL-CONVENTION XYZZY`.
