# PB5631 - the SD arm of the repeated-description refusal reports the wrong entry and has no test

**Sites:**
- `src/WiseOwl.Cobol.Compiler/Binding/FileControlBinder.FileSection.cs:172` (`FileControlBinder.BindFileSection`, `FileControlBinder.DescriptionRepeated`)
- `src/WiseOwl.Cobol.Editions/Diagnostics/DiagnosticCatalog.cs:3389` (`DiagnosticCatalog.SpecialNameDeclaredTwice`: the doc comment)
- `conformance-suite/wiseowl/diagnostics/pb5541-fd-declared-twice.json` (whole: the only witness, FD plus FD)

**Mechanism.** kb/Work PB5541 (landed) made a second file description entry of one file-name refuse COBOL4250 through
`DescriptionRepeated`, "the first stands". `BindFileSection` binds every FD before any SD (the SD loop starts at line 172),
so when an SD of a file-name PRECEDES its FD in source, COBOL4250 is reported at the SD (the first entry in source), saying
it describes the file a second time and that the first stands, while the FD that follows is the one the binder kept. The
message names the wrong entry as the repeat and the user is told to remove the first of two.

**Gaps beside it.**
1. The SD arm's call of `DescriptionRepeated` (SD plus SD, FD plus SD) has no test: deleting that line leaves the gate
   green. Add diagnostics JSONs for SD plus SD, FD plus SD and SD plus FD, expecting the entry later in source to be the
   one reported.
2. The COBOL4250 doc comment (DiagnosticCatalog.cs:3383-3390) still says the refusal is decided at the ONE declaration
   funnel (`DataBinder.DeclareUserWord` / `UserWordKinds.DeclaredUnqualifiable`) so every declaring clause is covered,
   but the file-name case added by PB5541 is reported outside it, by `FileControlBinder.DescriptionRepeated`.

**Fix direction.** Make the repeat the later entry in SOURCE order whatever the entry kind (walk the FD and SD entries in
one source-ordered loop, or key `DescriptionRepeated` on the entry's position), correct the doc comment, and pin the three
mixed orders.
