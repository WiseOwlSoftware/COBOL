# PB3146 — the licensed work's name and the package license disagreed with the product and with LICENSE

> flags: process-only · silent

Source: the owner, 2026-10-14 ("update the current repo LICENSE to use the correct name for the product"), after the
operator pointed out the name while answering a commercial-licensing inquiry.

**Mechanism.** `LICENSE` (Business Source License 1.1) named the Licensed Work `CobolSharp`, the legacy engine that
PHASE 15 Cut 2 deleted from main (kb/Work PB2110). The product is WiseOwl COBOL (repository `WiseOwlSoftware/COBOL`,
executable `cobol`, package `WiseOwl.COBOL`). A license grant whose Licensed Work names a product that no longer
exists leaves a licensee unsure what the grant covers.

**Sibling found in the same sweep.** `Directory.Build.props` set `<PackageLicenseExpression>MIT</PackageLicenseExpression>`
for every project, so every package `dotnet pack` produced declared MIT, while the repository is licensed under the
BSL with an Additional Use Grant, a Change Date and a Change License. Nothing was ever published under it: the
nuget.org flat container has no `wiseowl.cobol` package (checked 2026-10-14). That is the silent part: a package would
have offered the whole product under MIT with no error anywhere.

**Fix.**
- `LICENSE`: the Licensed Work is `WiseOwl COBOL`.
- `Directory.Build.props`: `<PackageLicenseFile>LICENSE</PackageLicenseFile>`, and the LICENSE file packed at the
  package root for every project whose `IsPackable` is not false (every test and tool project sets it false). A license
  file, not an expression: nuget.org takes an expression only for an OSI- or FSF-approved license, and a bare SPDX id
  (`BUSL-1.1`) would drop the BSL's parameters.

**Verified.** `dotnet pack src/Cobol.Net.Runtime -c Release -p:CobolRuntimeReadyToRun=false` on this branch: the
package holds `LICENSE` (its line 6 reads `Licensed Work:        WiseOwl COBOL`) and its nuspec declares
`<license type="file">LICENSE</license>`.

**Swept.** `README.md`'s License section names no product. `CLA.md` names the BSL and grants sublicensing under any
terms, so it needs no change. No other `.props`, `.targets` or `.csproj` sets a package license.

**Open, the owner's.** Whether the BSL is the right license before the compiler is complete (owner 2026-10-14: "We
should rethink whether the business source license is the appropriate one"). This note fixes the name and the metadata
only. `PackageLicenseFile` follows `LICENSE`, so a later change of license is one file.
