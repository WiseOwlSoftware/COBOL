# PB3575 — DECISION (owner, 2026-10-23): the diagnostic code prefix COBOLNET#### is renamed COBOL####, one prefix and one number space, in one scripted landing between waves

## The owner's words

2026-10-23 ~12:00 PDT: "At some point, we should rename/renumber error message identifiers. Currently they are COBOLNET#### using the old COBOL.NET naming. Suggestions encouraged but COBOL#### seems appropriate."

## Facts

Measured by the Mythos session on main, 2026-10-23.

- Codes in use: `grep -rhoE 'COBOLNET[0-9]{4}' src --include=*.cs | sort -u | wc -l` gives 704 distinct codes, numbered from the 0400s to COBOLNET4733 with holes (`alloc.py` reserves up to 4779).
- The parser's own series, `grep -rhoE '\bCOBOL[0-9]{4}' src --include=*.cs | sort -u`, is COBOL0001, COBOL0100-COBOL0107, COBOL0200-0201 and COBOL0300-COBOL0313 (COBOL2002 in that output is an edition name, not a code).
- The two series do not overlap: no COBOLNET code is below 0400 (`grep -rhoE 'COBOLNET0[0-3][0-9]{2}' src --include=*.cs` prints nothing).
- Files mentioning `COBOLNET####` (`grep -rlE 'COBOLNET[0-9]{4}' <dir> | wc -l`): src 271, tests 326, conformance-suite 1,677, docs 86, kb/Work 1,222, scripts 13. The DEVLOG is history and is never rewritten (CLAUDE.md rule 6).
- The catalog and its consumers: `src/Cobol.Net.Editions/Diagnostics/DiagnosticCatalog.cs`, the rendered diagnostics table (`scripts/rendered_views.py`), `alloc.py peek code` and session-probe's "next free" line, the goldens' expected diagnostics, `docs/CONFORMANCE.md`, and the kb/Work notes (code sites).

## Options

Recommendation of the Mythos lane: (a).

- (a) `COBOL####`, keeping every number (COBOLNET4733 becomes COBOL4733). The parser series already uses this prefix and the number spaces do not overlap, so the catalog gains one prefix and one number space with no renumbering. Users read "COBOL" at once, and the DEVLOG keeps the old spelling as history.
- (b) A short .NET-style prefix such as `WOC####` (WiseOwl COBOL, like CS1234 or CA1234). It is shorter in output and unique on the web, but it is a brand code rather than the language's name, and the parser series must be renamed too.
- (c) Renumbering into a dense sequence. This is churn with no value, since every note and golden is re-keyed. Not recommended.

## Execution (whatever the prefix)

One scripted rename: a Python script rewrites `COBOLNET(\d{4})` to the new prefix across src, tests, conformance-suite, docs, scripts, kb/Work and the skills, never DEVLOG/. The catalog's prefix constant and `alloc.py`'s code kind change with it, the diagnostics table is re-rendered, and the goldens are re-run (the catalog drift tests and `check_practices.py` are the net). It lands as one branch with the loop drained, because every in-flight branch would conflict on its goldens. There is no alias and no compatibility reader of the old spelling (CLAUDE.md rule 4). The session-probe's "next free" line and the kb/Work code sites follow.

## Owner question (bare)

"Prefix: COBOL#### keeping the numbers (recommended), or WOC####?"

## Timing

After the current campaign waves, when the loop is drained for it; not before 100 % unless the owner says so.
