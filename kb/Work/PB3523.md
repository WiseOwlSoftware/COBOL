# PB3523 — the fuzz generator's first-attempt validity

## Owner instruction (2026-10-22, verbatim)

About 12:05 PDT: "Ideally, we update the prompt to correct COBOL code is generated initially, not requiring any, or at
least fewer, repair attempts."

Earlier the same hour: "the fuzz test returned many BOTH_REJECT outcomes. I assume that implies the local model generated
incorrect COBOL programs. If so, reducing the invalid program production would notably improve the useful fuzz throughput".

## The measurement (run fuzz-20261021-211424, 4,931 programs, qwen3.6:35b, seed 20261022)

- BOTH_REJECT 2,326 of 4,931 (47 %). Every one of them used all 3 repair rounds (`repairs: 3` on all 2,326 rows), so each
  cost 4 generations and 8 compiles. Usable programs: 2,592, of which 1,646 needed a repair round. Generations spent:
  about 9,300 of about 14,400 (65 %) went to programs that never compiled. (The first night: 40 % BOTH_REJECT.)
- WiseOwl's first diagnostic on the BOTH_REJECT rows: COBOL0001 unparseable construct 734 (`INTEGER-OF-BOOLEAN(TRUE)`,
  `PIC B VALUE TRUE`, `SPECIAL-NAMES SECTION`); COBOL0307 a statement with an invented phrase 322 (`ALLOCATE X GIVING X`,
  `VALIDATE X CLASS IS ALPHABETIC`, `ACCEPT X FROM DATE YYYYDDD`); COBOL0901 a reserved word used as a name 294
  (`ACCEPT X FROM SCREEN`, `IF X IS NOT NULL`, `FUNCTION NULL`); COBOL1941 invented data-description clauses 133
  (`REFERENCE VALUE NULL`, `DYNAMIC LENGTH LIMIT 10 PREFIXED BY`); COBOL1639 undefined names 107 (screen attributes,
  locale words used as items); then COBOL0306 47, COBOL1934 44, COBOL2072 39, COBOL2404 33, COBOL1757 32.
- GnuCOBOL's first error on the same rows: "is not defined" 215; "syntax error, unexpected Identifier" 150;
  "PROCEDURE DIVISION header missing" 83; PICTURE string invalid 71; "01/77 OCCURS does not conform" 52.
- By seed family (BOTH_REJECT / programs): §13.18 719/1187 (61 %), §14.9 530/918 (58 %), §8.4 316/594 (53 %), §14.7
  70/144 (49 %), §8.5 286/774 (37 %), §8.8 224/720 (31 %), §14.6 181/594 (30 %). It is hallucinated syntax,
  concentrated where the model knows the language least: data-description clauses and the rarer statements.
- What the harness does NOT record: each repair round's first diagnostic, so "the repair repeated the same error" is not
  measurable from this run.

## Scope for the implementer (CLAUDE.md rules 4 and 5: the root is the prompt's lack of the clause's syntax, not the repair loop)

1. **The generation prompt carries the seed clause's GENERAL FORMAT** from `specs/ISO_COBOL.md` (the harness already
   indexes clauses by number; the format block of the clause, or the whole clause text when short, goes in verbatim,
   rendered from the PDF page when the OCR'd diagram is lossy, CLAUDE.md rule 1), plus the standing rules the refusals
   show the model lacks: the reserved words it may not use as names (the COBOL-2014 list the compiler already has, or at
   least the ones the run tripped on: NULL, SCREEN, TRUE, FUNCTION as a data name), no figurative TRUE/FALSE as values,
   `--std 2014` only (no 2023 words: XOR, LINE SEQUENTIAL …), the required division headers, and one worked example per
   seed FAMILY (data description, statement, intrinsic, conditional) that compiles on both judges.
2. **The repair prompt quotes the refused source LINE** (the diagnostic names line and column) beside the diagnostic, and
   asks for the smallest change; it already carries both compilers' messages.
3. **Record each round's first diagnostic code and message on the row** (`repair_rounds: [{code, message}]`) so the next
   report measures repair effectiveness.
4. **Stop a hopeless repair early**: when a round's first diagnostic (code, or GnuCOBOL message family) repeats the
   previous round's, the program is BOTH_REJECT without further rounds. The repair budget stays 3 for a program whose
   errors change.
5. **Measure before and after** with the bake-off path (`--bake-off qwen3.6:35b --count 40` over the three worst
   families §13.18, §14.9, §8.4, same seed): report first-attempt validity (usable without repair) and BOTH_REJECT share
   on the old and the new prompt. The GPU is shared with the owner: run the bake-off at a small count, and say in the
   report when it ran. The self-test (`differential_fuzz.py --self-test`) covers the new recording and the early stop with
   a stubbed model.
6. Keep the prompt's clause text within the model's context: measure the longest clause; a clause over the budget is cut
   at its format and syntax rules (the general rules are not what the model gets wrong).

## Golden / drift

The harness self-test: the prompt for a seed contains its clause's format; a repaired row records its rounds; a repeated
diagnostic ends the rounds. The bake-off numbers go in the DEVLOG entry and in `docs/rearchitecture/evidence/fleet-optimization/`
as the third fuzz record.

## Landed (wave 1149 group A, 2026-10-22)

All six items, in `scripts/differential_fuzz.py`. (1) `seed_text` gives the model the clause cleaned of the transcription's
markup and, over `CLAUSE_BUDGET` (6,000 characters), cut by STRUCTURE: the general formats first (at most two thirds of
the budget), then the syntax or argument rules, then the introduction, then the general rules, each cut part marked and
each omitted part named. The system prompt carries the division skeleton, the naming rule with the reserved words the
night misused (each held to §8.9's list by the self-test), TRUE, FALSE and NULL, the OCCURS level (§13.18.38.3 rule 1),
SEARCH on the OCCURS entry (§14.9.37.3 rule 2), the general-format notation, the words 2023 reserved (Annex E.2 item 25)
and the Foreword's other 2023 changes (LINE SEQUENTIAL, PERFORM UNTIL EXIT, …), read from the spec, and one worked example
per seed family (`FAMILIES`: statement, data description, intrinsic function, expression), each compiled and run by both
judges with identical output. (2) A correction quotes the source line each diagnostic names and asks for the smallest
change. (3) `repair_rounds` records each refusal round's WiseOwl code and message and GnuCOBOL's first error. (4) A round
whose WiseOwl code AND GnuCOBOL message family repeat the previous round's ends the corrections (`stopped_early`). (5)
Measured: the report and the bake-off table give first-attempt validity. (6) The longest clause (14.9.39 SET, 40,522
characters cleaned) fits the budget, and the self-test holds the whole exchange inside `NUM_CTX`.

Beyond the six: the owner's run cadence (12:15 PDT) is the module docstring's, and a `--model` run REFUSES to start while a
note tagged `fuzz` that is not `process_only` is open (`--force-open-notes` overrides and names them; exit 3). And a
measured second root: a clause of an optional module docs/CONFORMANCE.md §5 records as Not claimed (the screen section,
VALIDATE, COMMIT and ROLLBACK, FORMAT and SELECT WHEN; 25 titles read from Annex A.4, less any title a module §5 does not
decline also lists, as A.4.11 Report Writer lists PRESENT WHEN and VARYING: branch review R1-1) is no longer a seed,
because WiseOwl refuses it by name: in the second night they were 450 programs, 330 of the 2,326 BOTH_REJECT rows and
1,613 of the 14,479 generations.

**The hypothesis did not hold.** Six bake-off arms (40 programs each, qwen3.6:35b, 12:24 to 12:59 PDT, the record
`docs/rearchitecture/evidence/fleet-optimization/2026-10-22-differential-fuzz-prompt.md`): on one seed walk the old
prompt wrote 10 of 40 programs usable at the first attempt and the new prompt 10, 9 and 8, inside a run-to-run noise of
about 6 programs. The early stop saved 12 % of the generations; the new prompt's usable programs stayed on topic as often
or more. The old prompt already carried most clauses' general format; what stays refused is a 35B model writing
constructs it does not know (ALLOCATE … GIVING, EXIT PERFORM outside an inline PERFORM, SET … TO FALSE without WHEN SET TO
FALSE, SORT without an SD file), each against a rule the clause text it was given states. The next levers are leads in the
wave-1149 report: the generator's thinking mode, and seeds weighted by their measured yield.

For the next implementer: `scripts/differential_fuzz.py#seed_text` owns what of a clause the model sees (reuse
`seed_parts` and `clean_spec_text`; a "Format n" line is CONTENT of the formats part, never a part, or every rule list
splits wrongly); `#system_prompt` with `PromptFacts.read` owns everything the prompt states that is read from the spec or
docs/CONFORMANCE.md (add a fact there, never a typed list); `#declined_seed_titles` owns which clauses are not seeds;
`#refusal_key` owns what counts as the same refusal; `#cadence_gate` owns the run cadence. A new worked example is
compiled and run by BOTH judges with identical output before it goes in `EXAMPLES` (the scratch helper that did it
judged each through `load_compiler` and `observe_fresh`). Measure a prompt change with at least two arms per side:
40 programs carry a noise of about 6 usable programs.
