# PB3428 — a predicate-tested word inside a printed clause has no named refusal

Filed 2026-10-19 by the enqueue clerk. PB3391 (landed) names this under "Not closed here (reported as a lead)"; no note
tracked it.

**Repro.** At `--std 85`, `OBJECT-COMPUTER. XYZ MEMORY SIZE 12 FOO.` answers COBOL0001 "cannot parse construct near
'FOO'"; `OBJECT-COMPUTER. XYZ SEGMENT-LIMIT IS.` answers "near '.'". The expected set cannot name a word a text predicate
tests, so the message is the bare parse error rather than the pass's own code and sentence.

**Code sites.** `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolParserCore.g4:619` (`{memoryUnitAhead()}? IDENTIFIER`) and
`src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs#BuildMessage`. The token is not at a residue position, so PB3391's
`ClosedFormatResidue` arm does not see it. Siblings to sweep: every `{...}? IDENTIFIER` predicate inside a printed clause.

## Landing (wave 20261769 group C, with PB3861)

**Re-probe** (`cobol.exe` on 802352531, `--std 85`): `OBJECT-COMPUTER. XYZ MEMORY SIZE 12 FOO.` drew `COBOL0001: cannot
parse construct near 'FOO'`, and `OBJECT-COMPUTER. XYZ SEGMENT-LIMIT IS.` `COBOL0001: cannot parse construct near '.'`.

**Root.** Two predicate-blind readings of the parse at the offending token. (1) The expected set: `(CHARACTERS |
{memoryUnitAhead()}? IDENTIFIER)` shows the IDENTIFIER the predicate guards, so FOO looks taken, and no hint could
name the words the predicate tests (WORDS, MODULES are no lexer tokens). (2) The re-simulation walk itself: it evaluated
no predicate at any token, so past `SEGMENT-LIMIT` the CHARACTER CLASSIFICATION clause's path (its left-edge
predicate refuses SEGMENT-LIMIT) stayed open and the period seemed to take a locale-name.

**Fix.** `ResimulationWalk.AdmittedAt`: the same full-context walk with every closure evaluating its predicates at the
token it precedes (ANTLR's own `PredTransition`/`EvalSemanticContext`, `startIndex` set per closure). Its
`EvalSemanticContext` runs each predicate through `CobolParserCoreBase.EvaluateTestingWords`, which records every word
the one `Word` funnel compares against the token; a predicate that refuses with no word matching contributes its words.
`AdmittedKinds` names the result; hint 0i reports it as COBOL5506. Now: "The word 'FOO' is not expected here: expected
CHARACTERS, MODULES or WORDS" and "The separator period is not expected here: expected an integer literal". Siblings
swept: `dynamicLengthShortWord`/`dynamicLengthPrefixedWord` (`… IS SIGNED FOO` expects PREFIXED or SHORT), every
`{wordAhead(…)}? IDENTIFIER` keyword rule (`messageKeyword`, `methodKeyword`, `multipleKeyword`, `orderKeyword`,
`constantByteLengthWord`, `dynamicLengthStructureWord`) through the same funnel. `orderKeyword` after `WITH
DUPLICATES IN` stays unnamed: the table SORT may end there, so a statement may begin and the position is open.

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs#ResimulationWalk.AdmittedAt`,
