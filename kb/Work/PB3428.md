# PB3428 — a predicate-tested word inside a printed clause has no named refusal

Filed 2026-10-19 by the enqueue clerk. PB3391 (landed) names this under "Not closed here (reported as a lead)"; no note
tracked it.

**Repro.** At `--std 85`, `OBJECT-COMPUTER. XYZ MEMORY SIZE 12 FOO.` answers COBOL0001 "cannot parse construct near
'FOO'"; `OBJECT-COMPUTER. XYZ SEGMENT-LIMIT IS.` answers "near '.'". The expected set cannot name a word a text predicate
tests, so the message is the bare parse error rather than the pass's own code and sentence.

**Code sites.** `src/Cobol.Net.Frontend/Grammar/Core/CobolParserCore.g4:619` (`{memoryUnitAhead()}? IDENTIFIER`) and
`src/Cobol.Net.Frontend/Parsing/CobolErrorStrategy.cs#BuildMessage`. The token is not at a residue position, so PB3391's
`ClosedFormatResidue` arm does not see it. Siblings to sweep: every `{...}? IDENTIFIER` predicate inside a printed clause.
