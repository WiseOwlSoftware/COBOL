# PB3517 — SIGNED / UNSIGNED accepted on every USAGE

## Scenario

Confirmed by the slice-C adjudicator (Opus) on the fresh build of origin/main at fd407980f and read against the rendered
general format of §13.18.60.2 by the Mythos session: the SIGNED / UNSIGNED choice appears ONLY inside the BINARY-CHAR,
BINARY-SHORT, BINARY-LONG and BINARY-DOUBLE alternatives of the USAGE clause's format. Harm: an illegal program compiles
clean, and a `PACKED-DECIMAL UNSIGNED` item with a signed PICTURE keeps its sign as if the word were not there (the
program prints `-005`). GnuCOBOL 3.2 refuses the fuzz program (fz00950) at the clause. Related: PB174 (the one block that
adjudicates §13.18.60.2's per-usage phrases).

### Reduced repro (the adjudicator's probe, verbatim)

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. COMPU2.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 WS-U PIC 9(2) USAGE COMP UNSIGNED VALUE 7.
01 WS-X PIC X(2) USAGE DISPLAY SIGNED VALUE "AB".
01 WS-P PIC S9(3) PACKED-DECIMAL UNSIGNED VALUE -5.
PROCEDURE DIVISION.
DISPLAY WS-U " " WS-X " " WS-P
STOP RUN.
```

Expected: a syntax error on each of the three entries (SIGNED / UNSIGNED is not a phrase of USAGE COMP, USAGE DISPLAY or
USAGE PACKED-DECIMAL). Actual on main fd407980f, `--std 2014 --source-format free`: compiles clean, prints `07 AB -005`.

## Expected (spec)

- §13.18.60.2 (General format of the USAGE clause): a format DIAGRAM, so it cannot be text-checked with `cite.py
  --check`; the page was rendered and read, and the SIGNED / UNSIGNED choice sits only inside the four fixed-width binary
  alternatives. `cite.py --check 13.18.60.2 "USAGE"` confirms the clause and its heading exist (OK); the printed
  specification text carries the four `UNSIGNED` branches in the diagram (one per BINARY-CHAR, BINARY-SHORT, BINARY-LONG,
  BINARY-DOUBLE alternative) and no other alternative has one.
- §13.18.60.4 GR12 (OK): the standard has no prose sentence about SIGNED / UNSIGNED (a search of the section for
  "UNSIGNED" finds none); the rule is a table whose rows are the four binary usages, each with an UNSIGNED row, for
  example `BINARY-CHAR UNSIGNED | 0 <= n < 256 [2**8]`. The check on `BINARY-CHAR UNSIGNED` passes inside that table;
  there is no row for any other usage.

## Mechanism (read on main)

- `src/Cobol.Net.Frontend/Grammar/Core/CobolData.g4` about line 731: `binarySign : SIGNED | UNSIGNED` is a child of the whole
  usage clause (both the `USAGE IS …` and the bare alternatives), not of the four fixed-width binary alternatives; a
  comment there says the compiler rejects the misuse elsewhere.
- `src/Cobol.Net.Compiler/Binding/DataBinder.cs` about line 5475: `binaryUnsigned = usage.binarySign()?.UNSIGNED() is not
  null;` reads the word for every usage and nothing reports it when the usage is not one of the four (the comment cites
  §13.18.60.4 GR12 for the binary usages only).

## Fix shape (for the implementer)

Root-cause shape to require (CLAUDE.md rules 4 and 5): the phrase's applicability is a per-usage fact of §13.18.60.2's
format, adjudicated in the ONE block that already decides the other per-usage phrases (kb/Work PB174: the float format
phrases), with a diagnostic naming the usage and the clause; the grammar comment is corrected or the grammar made to
match. Sibling sweep: every other usage-clause phrase the grammar admits more widely than the format does (the float
phrases on a non-float usage, NATIVE on a non-binary usage, …), and `--std 85/2002` where the words do not exist at all.

## Golden to require

The repro above expecting three diagnostics (one per entry) and no run; a sibling case per swept phrase.

## Why the fuzz saw it

The differential (PB3463/PB3488) classified fz00950 `THEY_REJECT:13.18.60`: GnuCOBOL rejected the clause, WiseOwl
compiled it. The evidence record is `docs/rearchitecture/evidence/fleet-optimization/2026-10-22-differential-fuzz-second-night.md`.

## Landed (w1148a, 2026-10-22) — one table decides which usage each optional USAGE-clause phrase may follow

**Re-probe** on the worktree's own build (base b37c551fe): the repro compiled clean at `--std 85`, `2002`, `2014`
and `2023` and printed `07 AB -005`, exactly as the note said.

**Spec.** The rendered folio 503 (PDF p.533) prints `{ SIGNED | UNSIGNED }` after BINARY-CHAR, BINARY-SHORT,
BINARY-LONG and BINARY-DOUBLE only, with SIGNED NOT underlined (`figure_extract.py 533` measures 33 underlined words,
SIGNED not among them) and UNSIGNED underlined. The transcription's figure note listed SIGNED as underlined; it is
corrected in `specs/ISO_COBOL.md`. §13.18.60.4 GR12 (`cite.py --check 13.18.60.4 "BINARY-CHAR UNSIGNED"` OK) reads
the phrase only on those four usages.

**Mechanism and the pattern.** The grammar parses all four optional phrases (`binarySign`, `noSignPhrase`, the two
`floatFormatPhrase` kinds) after every usage word; the binder narrowed three of them with three hand-written arms in
`DataBinder.BindEntry` and never wrote the fourth. The fix is the shape that makes the next phrase automatic:
`UsagePhraseRules` (`src/Cobol.Net.Compiler/Binding/Model/UsagePhrase.cs`) is the ONE table of which resolved usage
each phrase may follow, with each phrase's refusal (COBOLNET4733 SIGNED / UNSIGNED, new; COBOLNET1565 WITH NO SIGN,
moved from a bare string onto `DiagnosticCatalog`; COBOLNET1716 / 1717 for the float phrases), and
`DataBinder.ScreenUsagePhrases` (`DataBinder.UsagePhrases.cs`) is the ONE reader of the clause's phrases: it asks the
table for each written phrase, screens a repeated float phrase (COBOLNET1718), and hands back only the admitted ones,
so a refused phrase can never change a representation (`OwnNoSign`, `PicInfo.BinaryItem`'s sign, the float
endianness). The grammar keeps the superset parse (a phrase inside `usageKeyword` would glue into the keyword text)
and its comments now say where the narrowing is. Sibling sweep: every phrase of the clause (all four now in the
table), every edition (the phrase is refused off the binary usages at 85 too; it needs no gate of its own because
the four usages carry theirs), the group-level spelling (`01 G USAGE BINARY-CHAR UNSIGNED. 05 A.` already held 200
in A), and the four copies of the fixed-width binary usage set, now `UsageFamilies.IsFixedWidthBinary`.
`UsageClausePhraseDriftTests` (the renamed `UsageFloatFormatPhraseDriftTests`) reads the grammar's usage words and
phrase rules, checks the table against the printed figure for every usage word through `ParseUsage`, and pins the
table as the only reader of the four refusals.

**Goldens.** `conformance-suite/cases/13.18.60-USAGE/pb3517-sign-phrase-on-non-binary-usage` (the repro, refused at
all four editions with COBOLNET4733; the unit test asserts one refusal per entry),
`pb3517-no-sign-phrase-on-binary-usage` (COBOLNET1565, which had no witness), and the positive
`pb3517_binary_sign_phrase` at 2002 (each binary usage at its GR12 range ends, with SIGNED, UNSIGNED and neither).
FMT-13.18.60.2 is re-verdicted CONFORMS with these witnesses; GR-13.18.60.4-12 gains the positive.
