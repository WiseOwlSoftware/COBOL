# PB87 — LANDED 2026-08-18 — `WRITE PRINT-REC BEFORE ADVANCING ZERO` repositioned the page by one line

> ⚙ **flags:** wrong-answer, silent · found 2026-08-18 by the PB86 sweep of raw integer-identifier reads (the
> `SequentialIoEmitter.LinesExpr` swallow) — surfaced as a NIST SQ101M diff once the count was evaluated · fixed in
> the PB86 commit (DEVLOG 1303).

**Measured** (NIST SQ101M WRT-TEST-GF-25, `--std 85`): `WRITE PRINT-REC BEFORE ADVANCING ZERO` — the figurative
constant ZERO is admissible where integer-1 is a numeric literal (§8.3.3.6.3 r1a) and §14.9.51.3 SR15 admits zero;
§14.9.51.4 GR (c): "If integer-1 or the value of the data item referenced by identifier-2 is zero, no repositioning of
the representation of the printed page is performed." The emitter's `LinesExpr` had arms for a literal and a field
and a `_ => "1"` default, so the figurative advanced ONE line — and `tests/nist/valid/SQ101M.txt` line 249 (a blank
line between the GF-25 test line and the GF-26 bracket line) encoded exactly that legacy behavior. The CCVS's own
text says the test line "SHOULD BE 1 LINES BELOW AND 1 LINES ABOVE THE BRACKETING WRT-TEST LINES" and its comment
"THIS TEST ADVANCES THE PRINT POSITION 2 LINES, TO LINE 28" — no gap.

**Fix:** `LinesExpr` renders every non-literal operand through the ONE integer landing
(`NumericRenderer.Align(num.AsNum(lines), 0)` — a figurative ZERO reads as 0, a P-scaled or unsigned-wide item by
value), the swallow is gone (an error operand is loud). The golden's blank line 249 is removed with the citation in
`tests/nist/corpus.tsv` (SQ101M was already a `divergent` row over legacy holes — DEVLOG 573 re-baselined the
identifier operands; this is the figurative one it left). Sibling shape of [[PB86]].
