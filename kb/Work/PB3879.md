# PB3879 — boolean-of-integer-not-implemented-at-run-time: FUNCTION BOOLEAN-OF-INTEGER compiles under -std=cobol2014 but the run aborts: 'attempt to use non-implemented function'

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S2) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\boolean-of-integer-not-implemented-at-run-time.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\boolean-of-integer-not-implemented-at-run-time\`.

## Summary

GnuCOBOL 3.2 under `-std=cobol2014` compiles a reference to the standard intrinsic function BOOLEAN-OF-INTEGER with no
diagnostic, and the run ends at the call with `libcob: error: attempt to use non-implemented function`, exit code 1.
The default dialect refuses the same source at compile time (`FUNCTION 'BOOLEAN-OF-INTEGER' is not implemented`): the
`-std=cobol2014` (and `-std=cobol2002`) word list re-activates a function that cobc's own table marks as not
implemented. Verdict: GNUCOBOL-DEFECT. Class: compiles but is not implemented at run time. Edition: 2014.

## Expected result (per ISO)

The program is legal and its run displays `[0101]` and then `END`.

- §15.13.3 1) and 2) (checked): "Argument-1 shall be a positive integer." and "Argument-2 shall be a positive nonzero
  integer." The arguments 5 and 4 satisfy both.
- §15.13.4 1) (checked): "The returned value is a boolean item of usage bit that has the same bit configuration as the
  binary representation of the value of argument-1, where the rightmost boolean position is the low-order binary
  digit. The boolean value is zero-filled or truncated on the left ..." 5 is binary 101; zero-filled on the left to
  4 boolean positions it is B"0101".
- §14.9.11.3 1) (checked): DISPLAY's identifier-1 "shall not reference a data item of class message-tag, object, or
  pointer"; a boolean function result is none of these. §14.9.11.4 1) (checked): the conversion to the device is
  implementor-defined, so the exact rendering of the boolean value is the implementor's; it is not an abort.
- §4.2.2 (checked): "An implementation shall accept the syntax and provide the functionality for all standard
  language elements required by this Working Draft International Standard". BOOLEAN-OF-INTEGER is not listed in
  A.3 (processor-dependent) or A.4 (optional).

Edition: BOOLEAN-OF-INTEGER is part of the 2014 edition that `-std=cobol2014` claims. Annex E lists the
substantive changes between the previous standard (2014) and the 2023 text (§E.1, checked), and every function new in
2023 appears there as added (for example §E.3.3 22), checked: "FUNCTION BASECONVERT. This function has been added
..."); BOOLEAN-OF-INTEGER is not among them, so it predates 2023. (The repository holds no 2014 text; the edition is
derived from Annex E, and GnuCOBOL's own `cobol2002.words` and `cobol2014.words` activate the function, which agrees.
WiseOwl's catalog windows it from 2002.)

Citations inherited from the night records: The slice carried `§15.43.4 2)` as a cited rule; §15.43 is HIGHEST-ALGEBRAIC and the check fails for it as a BOOLEAN-OF-INTEGER rule (it concerned the HIGHEST-ALGEBRAIC lines of fz04104, not this function). It is not used here. The slice's `§15.13.4 1)` checks and is used.

Edition as recorded by the adjudicator: 2014. `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Fix site (GnuCOBOL 3.2 source, read observationally)

In `gnucobol-3.2` (read observationally; identifiers only):

The function is declared in the compiler's intrinsic table as known but not implemented, and libcob carries only a
stub, but the `-std=cobol2014` word list re-activates it, so the compile-time refusal that cobc has for such functions
never fires:

- `cobc/reserved.c`, `function_list[]`, the `BOOLEAN-OF-INTEGER` entry (line 3296): its `active` member is `CB_FEATURE_NOT_IMPLEMENTED`.
- `cobc/tree.c`, `cb_build_intrinsic` (line 7030): a function whose entry is `CB_FEATURE_NOT_IMPLEMENTED` is refused with
  `FUNCTION '%s' is not implemented`. This is the diagnostic the default dialect prints.
- `config/cobol2014.words`: line 535 `not-intrinsic-function: DIALECT-ALL`, then line 541 `intrinsic-function: BOOLEAN-OF-INTEGER`
  (`config/cobol2002.words` has the same pair, line 534 and line 540).
- `cobc/reserved.c`, `change_intrinsic` / `set_intrinsic_mode` (line 4979): the DIALECT-ALL deactivation moves the
  entry from `CB_FEATURE_NOT_IMPLEMENTED` to `CB_FEATURE_DISABLED`; the later activation then moves it from
  `CB_FEATURE_DISABLED` to `CB_FEATURE_ACTIVE`. The function's own FIXME comment (line 4981) names this
  not-implemented, disabled, active sequence as unhandled. After it, `cobc -std=cobol2014 --list-intrinsics` reports
  the function as implemented ("Yes") and `cb_build_intrinsic` accepts it.
- `libcob/intrinsic.c`, `cob_intr_boolean_of_integer` (line 7077): calls `error_not_implemented` (line 3135), which sets
  `EC-IMP-FEATURE-MISSING` and calls `cob_fatal_error (COB_FERROR_FUNCTION)`; `libcob/common.c`, `cob_fatal_error`
  (line 9109) prints `attempt to use non-implemented function` and ends the run with exit code 1.

Two fixes are possible, and they are independent: (a) make `set_intrinsic_mode` keep `CB_FEATURE_NOT_IMPLEMENTED`
through a DISABLED-then-ACTIVE sequence, so that every dialect refuses the function at compile time, as the default
dialect already does; (b) implement `cob_intr_boolean_of_integer`. 

The same mechanism covers all six functions of this group (BOOLEAN-OF-INTEGER, CHAR-NATIONAL, EXCEPTION-FILE-N,
EXCEPTION-LOCATION-N, INTEGER-OF-BOOLEAN, STANDARD-COMPARE; records in this directory), so fix (a) is one change
for all of them and one upstream ticket can carry all six repros.

## Draft issue

**Title:** FUNCTION BOOLEAN-OF-INTEGER compiles under -std=cobol2014 but the run aborts: 'attempt to use non-implemented function'

**Body:**

Environment: GnuCOBOL 3.2.0 (Ubuntu gnucobol3 3.2-4build1), Linux x86_64.

Steps:

    cobc -std=cobol2014 -fformat=free -x -o boi boi.cob
    ./boi

with boi.cob:

```
IDENTIFICATION DIVISION.
PROGRAM-ID. BOI.
PROCEDURE DIVISION.
    DISPLAY "[" FUNCTION BOOLEAN-OF-INTEGER(5, 4) "]"
    DISPLAY "END"
    STOP RUN.
```

Observed: the compile succeeds with no diagnostic (also with -fsyntax-only -Wall). The run prints nothing from the
DISPLAY statement and ends with exit code 1:

    libcob: error: attempt to use non-implemented function

Without -std (default dialect), the same source is refused at compile time:
`boi.cob:4: error: FUNCTION 'BOOLEAN-OF-INTEGER' is not implemented`. `cobc -std=cobol2014 --list-intrinsics` lists BOOLEAN-OF-INTEGER as
implemented ("Yes"); plain `cobc --list-intrinsics` lists it as "No".

Expected: the program is valid COBOL 2014 (FUNCTION BOOLEAN-OF-INTEGER, ISO/IEC 1989 15.13). Per
15.13.4 rule 1 the result is the binary representation of argument-1 (5 = 101), zero-filled on the left to argument-2
(4) boolean positions, B"0101"; the run should display it (for example `[0101]`) and then `END`.

Cause, as far as we can see: config/cobol2014.words (and cobol2002.words) first deactivates all functions with
`not-intrinsic-function: DIALECT-ALL` and then activates BOOLEAN-OF-INTEGER; set_intrinsic_mode in cobc/reserved.c turns the
not-implemented entry into disabled and then into active (its FIXME notes this), so cb_build_intrinsic's
"is not implemented" check is bypassed and the call is generated against the libcob stub cob_intr_boolean_of_integer, which calls
error_not_implemented. Either keeping the not-implemented state through that sequence (compile-time refusal in every
dialect) or implementing the function would remove the run-time abort. The same applies to BOOLEAN-OF-INTEGER,
CHAR-NATIONAL, EXCEPTION-FILE-N, EXCEPTION-LOCATION-N, INTEGER-OF-BOOLEAN and STANDARD-COMPARE.
