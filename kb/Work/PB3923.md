# PB3923 — nearest-to-zero-class-condition-not-supported: Class conditions NEAREST-TO-ZERO, FARTHEST-FROM-ZERO, IN-ARITHMETIC-RANGE (ISO 2014) are not supported

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S8) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\nearest-to-zero-class-condition-not-supported.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\nearest-to-zero-class-condition-not-supported\`.

## Summary

GnuCOBOL 3.2 refuses the numeric class conditions `IS NEAREST-TO-ZERO`, `IS FARTHEST-FROM-ZERO` and
`IS IN-ARITHMETIC-RANGE` under `-std=cobol2014` with `'<word>' is a reserved word, but isn't supported` (and, under the
default dialect, where the words are not reserved, with `syntax error, unexpected Identifier`). These class
conditions are part of ISO/IEC 1989:2014, the edition `-std=cobol2014` claims. Class: feature missing.

## Expected result (per ISO)

The program is legal and prints `N NEAREST`, `F FARTHEST`, `F IN RANGE`.

- ISO/IEC 1989:2023 §8.8.4.4.2 (checked): the class condition's general format lists `FARTHEST-FROM-ZERO`,
  `IN-ARITHMETIC-RANGE` and `NEAREST-TO-ZERO` among its alternatives.
- §8.8.4.4.3 6) (checked): "If FARTHEST-FROM-ZERO, IN-ARITHMETIC-RANGE, or NEAREST-TO-ZERO is specified, identifier-1
  shall reference a data item whose category is numeric." N and F are numeric.
- §8.8.4.4.4 3) m) (checked): "If NEAREST-TO-ZERO is specified, the condition is true if the content of the data item
  referenced by identifier-1 is the nonzero numeric value nearest to zero that may be contained in that data item,
  whether that value is positive or negative." For PIC S9V99 that value is 0.01 in magnitude; N is -0.01.
- §8.8.4.4.4 3) g) (checked): "If FARTHEST-FROM-ZERO is specified, the condition is true if the content of the data
  item referenced by identifier-1 is the numeric value farthest from zero that may be contained in that data item,
  whether that value is positive or negative." For PIC S9V99 that is 9.99 in magnitude; F is 9.99.
- §8.8.4.4.4 3) l) (checked): IN-ARITHMETIC-RANGE is true "if the numeric content of the data item referenced by
  identifier-1 is neither farther from zero nor closer to zero than is permitted for the form of an intermediate data
  item appropriate to the mode of arithmetic in effect." 9.99 is representable in any intermediate form.

Edition: introduced in 2014. The 2009 committee draft that preceded ISO/IEC 1989:2014 (CD 1.2, §8.8.4.1.3) has the
earlier INFINITY and REPRESENTS-NOT-A-NUMBER alternatives and not these three, so they arrived between that draft and
the 2014 standard. They are in the 2014 standard: Annex E of the 2023 standard, which lists every reserved word 2023
added (§E.2 25), checked: "The following reserved words have been added"), does not list NEAREST-TO-ZERO,
FARTHEST-FROM-ZERO or IN-ARITHMETIC-RANGE, and GnuCOBOL's own `config/cobol2014.words` marks all three as reserved
words of COBOL 2014. The repository table `tests/version-matrix/reserved-words.json` records the same 2014 edge.

Edition as recorded by the adjudicator: 2014 (introduced 2014). `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Fix site (GnuCOBOL 3.2 source, read observationally)

- `config/cobol2014.words` lists `FARTHEST-FROM-ZERO` (line 200), `IN-ARITHMETIC-RANGE` (line 254) and
  `NEAREST-TO-ZERO` (line 319) as reserved; `cobc/reserved.c` has no entry with a token for them, so
  `lookup_reserved_word` (line 4902) reports "is a reserved word, but isn't supported".
- `cobc/parser.y`, rule `condition_or_class` (line 18532), has no arm for the three words; the run-time test would
  need the item's PICTURE (digits and scale) for NEAREST-TO-ZERO and FARTHEST-FROM-ZERO, and the intermediate form of
  the arithmetic mode for IN-ARITHMETIC-RANGE. The SET numeric-content statement (2023 §14.9.39.2, checked, the format
  with `NEAREST-TO-ZERO [ IN-ARITHMETIC-RANGE ]`) uses the same words and is not implemented either:
  `SET CONTENT OF N TO NEAREST-TO-ZERO` under `-std=cobol2014` gives `syntax error, unexpected CONTENT` and the same
  "isn't supported" error (a separate gap, not filed here).
