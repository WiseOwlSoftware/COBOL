# PB5737 - adjudication: at --std 85, is an OCCURS entry inside an OCCURS DEPENDING ON table that has a subordinate entry (05 T OCCURS 1 TO 3 DEPENDING ON N. 10 U OCCURS 2. 15 V PIC X.) refused by §1985:VI.5.8.3 SR1b? The compiler accepts it; the two readings of 'variable occurrence data item' differ

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Passes/OdoResolvePass.cs#Run` (under the broad reading: its test is "an ODO entry below an OCCURS entry", and it never asks whether an OCCURS entry inside an ODO table has subordinates)

**The question.** `1985-SR-VI.5.8.3-1` (KEPT into `SR-13.18.38.3-1`, recorded CONFORMS; a 1985 id is refused in `inventory_rows`,
kb/Work PB5094, so the row is named here) forbids OCCURS on an entry that "Has a variable occurrence data item subordinate to it".
Whether `U` below is such an entry turns on what "variable occurrence data item" covers at 1985.

**Rules (each citation checked with `python scripts/spec/cite.py --check`, verdict OK).**
- `§1985:VI.5.8.3 SR1b`: "Has a variable occurrence data item subordinate to it"
- `§1985:III.2`: "A variable occurrence data item is a table element which is repeated a variable number of times" (the definition continues: "Such an item must contain an OCCURS DEPENDING ON clause in its data description entry, or be subordinate to such an item")
- `§1985:VI.5.15.6 GR5c`: "It is a data item that is subordinate to a variable occurrence data item" (listed apart from GR5b, "It is a variable occurrence data item")

**Reading A (the refuter's: refuse).** By III.2 every table element repeated a variable number of times, and every item
subordinate to an ODO entry, is a variable occurrence data item. `V` is subordinate to the ODO entry `T` and is repeated a
variable number of times, so `U` has a variable occurrence data item subordinate to it and SR1b forbids its OCCURS. The compiler
must refuse `g1.cob` at `--std 85`.

**Reading B (the counter-reading: accept).** III.2's second sentence is a NECESSARY condition ("must contain ... or be
subordinate"), not a definition of every subordinate item, and GR5 lists "a variable occurrence data item" (b) apart from "a data
item that is subordinate to a variable occurrence data item" (c), which is redundant if every subordinate item is one. On this
reading only the ODO entry itself is the variable occurrence data item, SR1b forbids an OCCURS above an ODO entry, which is what
2023 states (`SR-13.18.38.3-1`: "Has an occurs-depending table subordinate to it"), and `g1.cob` is legal. Reading A also gives
an asymmetric result: an elementary fixed OCCURS inside an ODO table stays legal while a group one is refused.

The text does not settle it; this note decides nothing. If reading A is adopted, this becomes a defect (under_rejects) at 85
only, at the site above; at 2023 the compiler is right on either reading.
