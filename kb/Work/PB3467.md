# PB3467 — should DISPLAY of a scaled numeric item print the decimal point?

Source: PB3463 implementer report (`E:\COBOL-coord\scratch\reports\w1134a-PB3463-report.md`, "New defects").
Repro: `E:\COBOL-coord\scratch\w1134a\p\d1.cob`; fuzz cases fz00019, fz00030, fz00032.

Observed: DISPLAY of `PIC 9(5)V99` holding 12.5 prints `0001250`; signed prints `000125{`. GnuCOBOL's pretty-display
prints `00012.50` and `+00012.50`.

Governing text: §14.9.11.4 GR1 leaves the representation to the implementor. PB803 settled the SIGN convention
(IBM / Micro Focus over-punch, option `--sign-encoding`). CLAUDE.md rule 1 orders latitude as ISO, then GnuCOBOL, then
IBM / Micro Focus, which would put the decimal point with GnuCOBOL; PB803 put the sign with IBM by owner decision, so
the two precedents pull apart.

Question for the owner: print the decimal point for a scaled item (GnuCOBOL), or keep the unpunctuated digit image
(IBM / Micro Focus)? Consequence: either answer is a default for every program; changing it alters every golden that
displays a scaled item, and the answer may warrant a compile option like PB803's. No code change until decided.
