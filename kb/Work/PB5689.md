# PB5689 - a hand dispatch learns the report-name rule when the stamp is refused

**Sites:** `scripts/orchestrator/coord.py` (`REPORT_NAME`, line 162), `scripts/orchestrator/reports.py` (`parse_report`),
`scripts/orchestrator/review_findings.py` (`stamp`, the refusal at line 483), `scripts/orchestrator/enqueue.py` (`land`),
`.claude/skills/workstream/make_dispatch_specs.py` (whole: renders the implementer spec that names the report).

**What happened.** `review_findings.py stamp` refused the reviewed branch `adjudication-pb5625`: "REFUSED:
E:\COBOL-coord\scratch\reports\adjudication-pb5625-report.md is not a finished fix-lane report (not a
w<wave><letter>-PB<lead>-report.md name)". The reviewer's findings file is
`E:/COBOL-coord/scratch/my-20261115/review-adjudication-pb5625.jsonl`. Two workers' reports were rewritten under new names
(`E:/COBOL-coord/scratch/reports/w20262046b-PB5625-report.md`, `w20262048a-PB5679-report.md`) before a stamp could be written;
`adjudication-pb5625-report.md` is still in that directory.

**Evidence.** `scripts/orchestrator/coord.py` line 162: `REPORT_NAME = re.compile(r"^w(?P<wave>\d+)(?P<letter>[a-z0-9]*)-(?P<lead>PB\d+)-report\.md$")`.
`scripts/orchestrator/review_findings.py` line 483: the `RecordError` "... is not a finished fix-lane report (". `REPORT_NAME`
and `reports.parse_report` define the only report a stamp and `enqueue.py land` accept. `make_dispatch_specs.py` tells a
rendered implementer the name; a records, documents or design job dispatched with a hand-written brief has no rendered spec,
and that worker was not told the name.

**The question this note asks.** Where should a hand-dispatched job learn the report-name rule, before the stamp refuses it.
