# R02 — LANDED — one sentence, two halves, and both were wrong

> Migrated from the fix queue's RESIDUE block, which never itemised these — so no work list could see them.

## ⛔ §8.3.2.1 IS ONE SENTENCE AND IT SAYS TWO THINGS

> "Each character of a COBOL word … shall be selected from the set of basic letters, basic digits, extended
> letters, and the basic special characters **hyphen and underscore**. The hyphen or underscore **shall not
> appear as the first or last character** in such words."

**HALF ONE — the underscore was not a word character at all.** `01 MY_NAME PIC X(6).` is legal at three of the
four editions this compiler targets, and it parsed at NONE of them:

```
r02.cob(6,13): error COBOL0001: no viable alternative at input 'MY_'
```

An unexplained rejection, not a named edition diagnostic — CLAUDE.md rule 4's red line.

**HALF TWO — "nor last" was unenforced for the HYPHEN, and predates this item.** `NAME_BODY`'s ALPHA-start
alternative ended `[a-z0-9]`, so `AB-` was correctly refused; the two DIGIT-start alternatives ended in a `*`
over the separator class, so **`1A-` and `42-X-` were ACCEPTED**. Adding the underscore to that class without
looking would have silently inherited the hole for the new character.

## ▶ THE FIX

**Lexer** — the tail is factored into `NAME_TAIL : [a-z0-9_-]* [a-z0-9]`, which cannot end on a separator, and
all three alternatives share it. That admits the underscore and closes "nor last" for BOTH characters in one
edit. Verified as a matrix, legal and illegal together:

```
MY_NAME  MIXED_A-B  A  WRK-DS-01V00  42-DATANAMES  11A   → accepted
1A_  1A-  42-X-  _ABC  ABC_                              → rejected
```

**Edition gate** — the underscore is admitted at EVERY edition by the lexer (superset-parse / bind-narrow) and
the COBOL-85 rejection is the construct `user-word-underscore-2002` → **COBOLNET0900**, raised in
`VisitCobolWord` **beside the §8.3.2.1 word-LENGTH check** — the same clause, the same visitor, deduped through
the same per-word set. Measured across all four: `--std 85` names the gate, 2002/2014/2023 compile clean.
⚠ A lexer that refused the underscore below 2002 would have produced `no viable alternative` again — the very
symptom being fixed. **The token must lex so the gate can name the edition.**

## ⚙ THE SWEEP THE NOTE ASKED FOR, measured rather than reasoned

`PROGRAM-ID. R02_SWEEP`, group and elementary names, **subscripts** (`EL_M(IDX_1)` — the SUBSCRIPT-mode twin
shares the fragment, so it came free), intrinsic arguments, and **paragraph names** all work. `MOVE_X` is NOT
flagged by the §8.9 reserved-word funnel — a user word that merely begins with a reserved one, which the
underscore must not make look reserved.

## ⚠ THE BLAST RADIUS IS EVERY IDENTIFIER IN EVERY PROGRAM

`NAME_BODY` is how every COBOL word in the compiler is lexed, in both lexer modes. A filtered gate cannot speak
to that, so this landed on the FULL battery — including NIST's 353 real CCVS programs and the GnuCOBOL
differential's 1,323 — which is the only instrument that can answer "did identifier lexing change anywhere it
should not have". The "nor last" tightening in particular REMOVES acceptances, so the differential's per-case
flips are the load-bearing evidence, not the conformance count.

## ▶ PINNED

`r02_underscore_in_cobol_words` — 9 assertions: underscored data/paragraph/program names, an underscored
subscript variable used to both read and write, an underscored intrinsic argument, the reserved-word-lookalike
`MOVE_X`, and the LEGAL digit-start shapes (`42-DATANAMES`, `11A`) that the "nor last" fix must not break.
Negative `r02-word-trailing-separator` (`1A-`). The COBOL-85 gate is pinned by the version matrix through the
construct row's own `source` program.
