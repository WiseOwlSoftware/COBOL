# R02 — no COBOL word may contain an UNDERSCORE though the standard has permitted it since COBOL-2002

no COBOL word may contain an UNDERSCORE though the standard has permitted it since COBOL-2002

> Migrated from the fix queue's RESIDUE block, which never itemised these — so no work list could see them.

## ▶ TRIAGE (2026-08-06) — `rejects_legal_source`

Flagged while fixing the ranker that had been hiding this class of item ([[PB48]]'s sweep). The note carried NO
harm flag, so it could never appear in `work.py next` whatever the ranker's predicate was.

§8.3.2.1 admits the underscore in a user-defined word from COBOL-2002 onward, so a program written with
`MY_NAME` is legal at three of the four editions this compiler targets and does not compile. That is
CLAUDE.md rule 4's red line, not residue trivia — hence the flag.
⚠ It is a LEXER change (`NAME_BODY`), so it interacts with the §8.9 reserved-word funnel and with `cobol-words.json`;
and it is edition-gated (an underscore is NOT admitted at 85), so [[feedback_edition_gate_sweep]] applies.
