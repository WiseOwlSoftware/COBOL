# PB663 — OPEN — a formal with no arm for its class

Found 2026-09-05 by the `PB231` pointer-third implementer (report §"New defects" (1)), reproduced on the pristine
main-tree compiler, so pre-existing and independent of the byte-window work.

## Repro (`--std 2002`+; `<a9d94900 scratch>/PB231-pointer/probe9.cob`)

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. PROBEP9.
       DATA DIVISION.
       LINKAGE SECTION.
       01 L-P USAGE POINTER.
       PROCEDURE DIVISION USING L-P.
       SUBMAIN.
           IF L-P = NULL DISPLAY "SUB NULL" ELSE DISPLAY "SUB SET" END-IF
           GOBACK.
```

```
error CS1503: cannot convert from 'string' to 'CobolNet.Runtime.ManagedPointer?'
```

Generated: `private ManagedPointer<string> __lnkp0 = ManagedPointer<string>.Cell(new string(' ', 1));` and then
`ManagedPointer.SameTarget(__lnkp0.Value, null)` — a string-cell carrier where the value is a pointer.

## The rule

§13.18.60.4 GR23: "Each implementor defines the precise effect of the USAGE POINTER clause upon alignment, size,
representation, and range of values of the data item in the storage of the computer." (`OK §13.18.60.4 23)`) —
this implementation's representation of a data-pointer is the pointer carrier (`CobolPtr`, per the DATA_MODEL
design); §14.2.3 GR8 makes a BY REFERENCE formal the same storage as the caller's argument, so the formal must be
carried by the class's own carrier, exactly as a numeric formal is.

## The mechanism

`src/Cobol.Net.Compiler/CodeGen/ProgramEmitter.cs:234` (the formal-carrier loop): `isNum ? … :
ManagedPointer<string>.Cell(new string(' ', Math.Max(1, f.Item.ImageWidth)))` — two arms, numeric and
"everything else as a string cell". A pointer, program-pointer or object-reference formal falls into the string
arm; the binder then emits pointer operations against it.

## Fix shape

The formal-carrier loop dispatches on the item's CLASS through the same classification `PB231`'s
`SlotWindow.CarriedBySlot` now defines (the one population test for pointer/object-class items): a pointer-class
formal gets the pointer carrier (`ManagedPointer<CobolPtr>`-shaped, matching how a BY REFERENCE pointer argument is
passed at the call site — read `CallAbi`/`CobolArgAdapt` for the argument side first, since the carrier must agree
at both ends), an object-reference formal its reference carrier. Goldens at 2002/2014/2023: a subprogram with a
`USAGE POINTER` formal tested for NULL and dereferenced (called BY REFERENCE with a NULL pointer and with a real
address), a `PROGRAM-POINTER` formal, and an `OBJECT REFERENCE` formal; a drift test over `LinkageCarrierTests`
(or the nearest existing class) that every `PicCategory` a LINKAGE item can have maps to a carrier arm — derived
from the category enum, so a new class is a red test rather than a string cell.
