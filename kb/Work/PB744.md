# PB744 — OPEN — the conformance record states one decline twice, two ways

Reported 2026-09-06 by the `PB702` fix-lane implementer (report
`…\a9d94900…\scratchpad\reports\PB702-report.md`, "New defects", item 1). Verified line by line against main
(`89555b09`).

## Measured

`grep -n "Screen handling" docs/CONFORMANCE.md` → **two hits**, `498` and `520`, both inside `## 4. Documented
non-support facilities (§4.2.6 / §4.2.7 / §4.2.13)` (heading at `:430`), whose other items are `1.` at `:456`,
`2.` at `:461`, `3.` at `:474`. So the section's item numbers run **1, 2, 3, 4, … 4** — one item number used
twice, in source and in render (CommonMark keeps a list's start number, so the second block renders as "4." as
well).

**`docs/CONFORMANCE.md:498` — the stale entry (pre-PB260):**

> 4. **Screen handling** (§13.9, optional §4.2.7 / Annex A.4.2): the SCREEN SECTION, ACCEPT/DISPLAY format-3
>    (screen), and the EC-SCREEN family. Not provided; the section draws **COBOLNET1560**. ⚠ The EC-SCREEN-\*
>    names are still ACCEPTED against a facility with no setting sites (`kb/Work PB260`) — owed with this module's
>    own witnesses, one row in the `EcNameResolution` declined-family table.

**`docs/CONFORMANCE.md:520` — the current entry:**

> 4. **Screen handling** … Not provided — and **REFUSED, not accepted inert** (2026-09-02, kb/Work PB260). …
>    every one of the seven source shapes draws a named **Error**: `COBOLNET1560` for the data / environment
>    surface and `COBOLNET1707` for the procedure surface … Witnessed by 41 negative-corpus programs
>    `tests/conformance/negative/a42-*` …

Two paragraphs separate them: `:503-509`, the Annex A.4.10 optional-items paragraph, and `:511-518`, the
"⚠ **A warning nothing asserts…**" paragraph — whose own closing sentence, *"Item 4 is no longer exposed to this
at all: a refusal fails the compile, so its 41 witnesses are ordinary negative-corpus entries"*, already
contradicts the entry at `:498`, from between the two copies.

**The compiler agrees with the SECOND entry.** `src/Cobol.Net.Compiler/Binding/ScreenFacility.cs:202-209`:
*"⛔ THE EC-SCREEN EXCEPTION-NAMES ARE NOT REFUSED HERE … the refusal lives in the ONE resolution funnel that
serves them all: `EcNameResolution.Advise`, over the `DeclinedEcFamilies` table, where this module is one row
carrying COBOLNET1707 as its descriptor."* They are refused — by a different site, which is exactly what the
stale entry's ⚠ said was still owed. So `:498` describes a compiler that has not existed since 2026-09-02.

## Why it matters — this is not a typo in an ordinary doc

`--check 4.2.16 "An implementation shall satisfy the user documentation requirements specified in 4.2.3, 4.2.4,
4.2.5, 4.2.6, 4.2.10, 4.2.12, and 4.2.13 by specification in at least one form of documentation"` → **OK
§4.2.16**, and `docs/CONFORMANCE.md` is that form; `--check 4.2.7 "An implementor shall identify in user
documentation the optional language elements"` → **OK §4.2.7** — the clause that *obliges* this very section. A
reader discharging §4.2.7 by reading §4 finds two mutually exclusive statements about the same optional module
and cannot tell which one is the claim. CLAUDE.md rule 6 says every doc except `DEVLOG.md` describes the CURRENT
compiler; a conformance record is the one document whose wrongness a user cannot detect by testing (the same
argument PB721 makes about A.3 row 43).

`process_only: true` by the register's definition — no user program behaves differently — but it is the
process-only class that damages the §4.2.16 claim rather than a developer's convenience.

## How it survived — and the drift test that closes it

**Nothing mechanical reads §4's items.** The drift guards over this document parse other sections by heading:
`tests/Cobol.Net.Tests.Unit/AnnexA3RegisterDriftTests.cs:34` pins `private const string SectionHeading = "## 2.
Annex A.3"` and walks that table; `AnnexA1RegisterDriftTests` does the same for §7 and cross-checks it against
the traceability inventory. §4 is prose with numbered items and has **no** parser at all —
`tests/Cobol.Net.Tests.Conformance/DeclinedFacilityTests.cs:38` only *mentions* "§4 item 3" in a doc comment.
`feedback_a_dead_lookup_is_also_unverified` at the document level: a section nothing reads has never been
contradicted.

## The fix

1. **Delete `docs/CONFORMANCE.md:498-501`** — the stale block, whole. Nothing in it survives the PB260 posture:
   its diagnostic list is short by COBOLNET1707, and its ⚠ is the exact statement PB302 closed.
2. **Add the drift test the deletion needs to stay deleted.** Beside `AnnexA3RegisterDriftTests`, a check over
   `## 4.`'s numbered items asserting they are **unique and consecutive from 1** — six lines of parsing, and the
   only guard §4 would have. ⛔ Make it fail once before trusting it (`feedback_green_gates_arent_evidence`): on
   the pre-fix document it must report the duplicate `4`.
3. **While the parser exists, assert the cheap invariant beside it**: every diagnostic code named in a §4 item is
   a `DiagnosticCatalog` descriptor. That fails today for a different reason and is PB745's — recorded here so
   the two are landed as one test rather than two.
