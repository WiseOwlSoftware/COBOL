# PB1230 — OPEN

## Measured

**constant-entry** — F-SR9-VALUE-NOT-SPEC — the duplicate-constant check compares the folded value, not the written specification

- **Repro:** 01 K CONSTANT AS 5. 01 K CONSTANT AS 2 + 3.  (also: 01 W PIC X(7). 01 K CONSTANT AS LENGTH OF W. 01 K CONSTANT AS 7.)
- **Expected (spec):** Rejected: SR9 requires 'the specification of arithmetic-expression-1, literal-1, data-name-1, data-name-2, or compilation-variable-name-1 shall be the same as specified in the other constant-name' — a literal vs an expression, or LENGTH OF W vs a literal, are different specifications.
- **Observed:** Both compile; DISPLAY K prints 5 / 7. BindConstantEntry: `if (prior.Category != def.Category || prior.Text != def.Text)` — Text is the evaluated value. (5 vs 05 is rejected only because the texts differ.)
- **Code site:** src/Cobol.Net.Compiler/Binding/DataBinder.Constants.cs#BindConstantEntry
- **Clause (adjudicator):** §13.10.3 SR9

**SR-13.10.3-1** (PARTIAL, refuter-corrected where marked) — SR1 (cite OK). AS 0.25 -> 0.25 (golden FRAC=0.25, FCOMP=200); AS -2.5 (sign adjacent, one literal per §8.3.3.3.2) -> -2.5; AS - 2.5 (separated sign = unary operator, an expression) -> -2; AS (0.5) -> 0; AS 1.5E2 (floating literal, single) accepted as literal = 150 while 1.5E2 + 1 is rejected by §7.3.6.2 SR1b. || REFUTED: PARTIAL — The classification half is right: a single numeric literal is not truncated (0.25, -2.5 and 1.5E2 are kept; '- 2.5' and '(0.5)' are expressions). But what the constant carries forward is not literal-1 as written. EvaluateArithmeticOperand returns the NORMALIZED text: the '+' is stripped and a comma decimal separator becomes '.'. BindConstantArithmetic stores that text as the substitution. Under DECIMAL-POINT IS COMMA the stored '1.5' is re-checked as a literal at the reference point and rejected, so a LEGAL program fails to compile. With AS +5 the constant displays '5' while the literal +5 written directly displays '+5', so the constant is not treated 'as if literal-1 were written' (§13.10.4 GR1). The defect is in the SR1 single-literal path the adjudicator cites, and it surfaces through GR1. File it as a defect.

- **Code site:** src/Cobol.Net.Frontend/Expressions/SoleOperand.cs#NumericLiteral; src/Cobol.Net.Frontend/Expressions/CompileTimeExpressionEvaluator.cs#EvaluateArithmeticOperand
