PB1147's and is landed (EC-SIZE-ZERO-DIVIDE); this is the path with checking off.

## Landed (w62m, 2026-09-26)
**Determination: the CODE was wrong, DOC-A.1-70 right.** §14.7.5 no-phrase rule 2 sets EC-SIZE-ZERO-DIVIDE for any
zero divisor (`cite.py --check 14.7.5` → `OK §14.7.5 2)`), Table 13 makes it Fatal (`OK §14.6.13.1.6`), and with
checking off §14.6.13.1.3 item 8 (`OK §14.6.13.1.3 8)`) leaves the disposition to the implementor. Survey under the
owner's precedence: GnuCOBOL 3.2 continues with the resultant unchanged (its decimal divide marks the quotient
not-a-number and the store skips it), but its source flags that as a known defect whose intended handling is to abort
on the fatal condition — no settled model — so the family determination DOC-A.1-70 already carried (termination; the
SDIDI zero divisor and the exponentiation-rule violation already took it) stands. ⚠ The rejected reading
(GnuCOBOL's current continue-with-receiver-unchanged) is recorded in DOC-A.1-70 for the owner.

**Fix — one rule, three arms.** `CobolSizeError.ZeroDivide()` is the one raise; `CobolNum.Divide` (scaled Int128),
the new `CobolFloat.Div` (binary64 — `NumericRenderer.CombineReal`'s unchecked quotient) and `CobolDec.Div` (SDIDI)
throw it checked or not; the checked twins (`DivideOrThrow`, `DivChecked`) call the unchecked kernel and add only
what a checked context owes (PROHIBITED-inexact; binary64 range). Before: `COMPUTE A = B / Z` stored 000,
`COMPUTE FR = FL / FZ` stored +Infinity (NaN for 0 / 0), both ran on; after: "abnormal run-unit termination:
EC-SIZE-ZERO-DIVIDE (fatal)", exit 1, for COMPUTE, DIVIDE INTO, DIVIDE GIVING REMAINDER, a nested quotient and a
condition, on all three lanes. Pinned by `SizeErrorDispositionTests.ZeroDivisor_*` (10 unchecked rows + 3 phrase-path
controls) and `ZeroDivisorLaneTests` (every arm and twin).
