# PB3937 — national-items-displayed-as-utf-16-bytes--n6-usage-national-doubles-size: PIC N(n) with an explicit USAGE NATIONAL is allocated 4*n bytes: LENGTH is 2*n and MOVE does not truncate

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S11) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\national-items-displayed-as-utf-16-bytes--n6-usage-national-doubles-size.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\national-items-displayed-as-utf-16-bytes--n6-usage-national-doubles-size\`.

## Summary

**Reading overturned (refuter): night 5 recorded this size (fz01088) as encoding latitude; that reading is wrong.** The standard makes `PIC N(n)` and `PIC N(n) USAGE NATIONAL` the same item (13.18.60.3 13) a), 20); 13.18.40.4 14); 8.1.2 2); all checked), so doubling the storage of the explicit form is the item's size, not its encoding. The witnesses are night 6's fz05199 and fz03419 and night 5's fz01088.

Record text as adjudicated:

Under `-std=cobol2014`, an elementary `PIC N(n)` item whose USAGE NATIONAL is written explicitly (`PIC N(4) USAGE
NATIONAL`, `NATIONAL PIC N(4)`, `USAGE NATIONAL PIC N(4)`) is allocated twice the storage of the same item without the
USAGE clause: 16 bytes for N(4) instead of 8. `FUNCTION LENGTH` reports 8 national character positions for it, a MOVE
of an 8-character national literal is not truncated to 4, and the item then compares unequal to the first 4
characters. With no USAGE clause, `PIC N(4)` is 8 bytes, length 4, and is truncated correctly. The standard makes the
two descriptions the same item (a PICTURE containing 'N' implies USAGE NATIONAL). Class: wrong output.

Found while triaging night 6's members of the family "national items displayed as UTF-16 bytes": the TRIM witness
fz03419 (`WS-NATIONAL-RES NATIONAL PIC N(10)`, 40 bytes displayed) and the FORMATTED-DATE witness fz05199
(`WS-NAT-RES NATIONAL PIC N(8)`, 32 bytes displayed). Night 5 saw the same size (fz01088, BYTE-LENGTH of `NATIONAL PIC
N(10)` is 40) and filed it as encoding latitude; the character count of `FUNCTION LENGTH` and the missing truncation
show it is the item's size, not its encoding.

## Minimal test case

Free reference format (`-fformat=free`), file `national-items-displayed-as-utf-16-bytes--n6-usage-national-doubles-size.cob`:

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. NATUSE.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 IMPLICIT-N PIC N(4).
01 EXPLICIT-N PIC N(4) USAGE NATIONAL.
PROCEDURE DIVISION.
MOVE N"ABCDEFGH" TO IMPLICIT-N EXPLICIT-N
DISPLAY FUNCTION LENGTH(IMPLICIT-N) " " FUNCTION LENGTH(EXPLICIT-N)
IF IMPLICIT-N = N"ABCD" DISPLAY "IMPLICIT EQUAL" ELSE DISPLAY "IMPLICIT NOT EQUAL" END-IF
IF EXPLICIT-N = N"ABCD" DISPLAY "EXPLICIT EQUAL" ELSE DISPLAY "EXPLICIT NOT EQUAL" END-IF
STOP RUN.
```

The 8-character sender fills the 4-position receiver exactly after truncation, so the space-fill defect of
`--national-space-fill` plays no part.

## Expected result (per ISO)

Output `4 4`, `IMPLICIT EQUAL`, `EXPLICIT EQUAL`.

- ISO/IEC 1989:2023 §13.18.60.3 13) a) (checked): when no USAGE clause is specified, "if the explicit or implicit
  picture character-string contains the symbol 'N', a USAGE NATIONAL clause is implied". `PIC N(4)` and `PIC N(4)
  USAGE NATIONAL` therefore describe the same item.
- §13.18.40.4 14) (checked): "Each symbol 'N' represents a national character position ... Each symbol 'N' is counted
  in the size of the item." Both items are 4 national character positions.
- §15.50.4 2) (checked): for an elementary data item of usage national "the returned value is an integer equal to the
  length of argument-1 in national character positions": 4.
- §14.6.8.5 (checked): the sending data are "aligned at the leftmost character position in the data item with space
  fill or truncation to the right, as required": N"ABCDEFGH" moved to a 4-position item leaves N"ABCD".

Edition: national data (PICTURE symbol 'N', USAGE NATIONAL, national literals) is a 2002 feature and is present in
ISO/IEC 1989:2014; the rules above are not among the 2014-to-2023 changes the version reference lists
(`docs/VERSION_CHANGE_REFERENCE.md` names no change to PICTURE 'N', the implied USAGE NATIONAL or LENGTH of a national
item). The program is legal under 2014.

Edition as recorded by the adjudicator: 2014. `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Fix site (GnuCOBOL 3.2 source, read observationally)

- `cobc/tree.c`, `cb_build_picture`, the "Calculate size" step: each symbol 'N' already adds `COB_NATIONAL_SIZE` bytes to
  the picture's size.
- `cobc/field.c`, `compute_size`, the `CB_USAGE_NATIONAL` case: the field size is the picture size multiplied by
  `COB_NATIONAL_SIZE` again. An item without the USAGE clause keeps usage DISPLAY (the TODO in `field.c` near the ANY
  LENGTH check says "Currently NATIONAL items are marked as having USAGE DISPLAY") and takes the DISPLAY case, which
  uses the picture size once; so only the explicit USAGE NATIONAL item is doubled. Intrinsic LENGTH then divides the
  doubled byte size by `COB_NATIONAL_SIZE`.
- `cobc/ChangeLog`, 2023-01-30: "parser.y, reserved.c: ... actually pass NATIONAL usage if specified" and "field.c
  (compute_size), tree.c (cb_tree_type): handle CB_USAGE_NATIONAL", the change that sends the explicit form down the
  doubling case.

(cobc/field.c), case `CB_USAGE_NATIONAL`, multiplies that size by `COB_NATIONAL_SIZE` again. Without the USAGE clause
the item keeps usage DISPLAY and is sized once. The explicit-usage path dates from the 2023-01-30 ChangeLog entry
"actually pass NATIONAL usage if specified".
