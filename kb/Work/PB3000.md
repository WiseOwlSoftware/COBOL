# PB3000 — the Linux gate's WSL hand-off assumes the caller is at the tree root

**Found by:** the train 1058 lander's review of PB2999 (2026-10-11), reading `scripts/linux-gate.sh#run_on_linux`.

**Mechanism.** `run_on_linux` (PB2999) runs on a host that is not Linux and hands the gate to WSL as
`wsl.exe -d Ubuntu --cd "$(cygpath -w "$(pwd)")" --exec bash -lc 'bash scripts/linux-gate.sh "$@"' linux-gate "$@"`.
The script path it re-runs is RELATIVE to the caller's working directory. Started from a subdirectory of the tree
(for example `cd scripts && bash linux-gate.sh`), WSL's bash looks for `scripts/linux-gate.sh` under that subdirectory,
does not find it, and exits 127 with bash's own "No such file or directory". No `=== LINUX GATE:` line is printed.
On a Linux host the same start reaches the script's own check and prints
`=== LINUX GATE: NOT RUN (not at a repository root: …) ===` with exit 2.

**Harm.** None silent: a missing verdict line is not a pass under the gate skill, and the documented command runs at the
tree root. But the verdict's shape differs by host, and a caller that reads only the exit code sees 127, not the NOT RUN
code 2 every other refusal uses.

**Fix shape.** In `run_on_linux`, before the hand-off, either refuse the same way the Linux arm does
(`[ -f WiseOwl.Cobol.sln ] || { echo "=== LINUX GATE: NOT RUN (not at a repository root: $(pwd)) ==="; exit 2; }`), or hand
WSL the tree root (`git rev-parse --show-toplevel`) instead of `pwd`. Add a `--self-test` check with a stand-in
`uname` for the subdirectory case. Code site: `scripts/linux-gate.sh` `run_on_linux` (about line 51).

**Repro.** From Git Bash in a worktree: `cd scripts && bash linux-gate.sh; echo "EXIT=$?"`.
