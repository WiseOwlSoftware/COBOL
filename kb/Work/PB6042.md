**Found by:** the branch review of w20262133a (review-a round 1, finding R1-4) on PB2635's unified selection rule; the
finding is older than that branch, which only changed WHICH argument a NaN-bearing MAX / MIN selects.

**Spec.** §2023:14.6.13.2 GR3: "When a sending operand is described with a standard floating-point usage, and the content
of the sending operand would evaluate to true in an infinity class condition or to true in a FLOAT-NOT-A-NUMBER class
condition, the EC-DATA-NOT-FINITE exception condition is set to exist", except in a class condition, a sign condition, a
MOVE between the same standard floating-point usage, or VALIDATE. A function argument is none of those. The table of
§2023:14.6.13.1.6 makes EC-DATA-NOT-FINITE FATAL ("Attempt to use a data item described with a standard floating-point
usage when its contents are either a NaN or a representation of infinity"). `cite.py --check` OK on §2023:14.6.13.2 GR3.

**Repro** (runs `nanmax2-005` (branch at 09e63d3f68) and `nanmax2-006` (main e29344556a) under
`E:/COBOL-coord/scratch/w20262133/review-a/runs`):

```
       01 B PIC X(8).
       01 X REDEFINES B USAGE FLOAT-BINARY-64.
       01 Y USAGE FLOAT-BINARY-64 VALUE 1.
       01 S USAGE FLOAT-BINARY-64.
           MOVE X"7FF8000000000000" TO B.
           COMPUTE S = FUNCTION MAX(X Y).   *> branch: S = 0; main: S = 1
           COMPUTE S = FUNCTION MIN(Y X).   *> branch: S = 1; main: S = 0
```

`MOVE X TO R` keeps the NaN (the GR3 MOVE exception). Neither COMPUTE raises EC-DATA-NOT-FINITE, and whichever form selects
the NaN stores 0: the emitted `FloatResultant.FromReal(CobolIntrinsics.RealResult(CobolIntrinsics.MaxReal(...)))` passes
the selected NaN to `CobolIntrinsics.RealResult` (`src/WiseOwl.Cobol.Runtime/Intrinsics/CobolIntrinsics.cs:297`), which
reads every NaN RESULT as an out-of-domain function result (`ExceptionState.ArgumentError`, EC-ARGUMENT-FUNCTION) and,
with checking off, answers 0.

**Expected.** With EC-DATA-NOT-FINITE checking enabled, the reference to X as an argument sets that fatal condition and
§2023:14.6.13.1.3 governs what follows; with checking off, §2023:14.6.13.1.3 GR8's latitude, as DOC-A.1-70 determines it
for a non-finite value, decides whether execution continues and with what value. Neither is a 0 reached by naming the
condition EC-ARGUMENT-FUNCTION.

**Root cause to fix.** The not-finite test belongs at the REFERENCE of a standard floating-point sending operand
(`CobolFloat.Sending`, which every argument above passes through), not at the function's result; `RealResult`'s NaN screen
is right only for a NaN the function body itself produced from finite arguments (ACOS 2, SQRT -1). Sweep every
floating-point sending position (arithmetic operands, comparisons other than class and sign conditions, MOVE to a different
usage, every intrinsic argument), not only MAX and MIN.

**Pinned so far.** `conformance-suite/cases/15.63.4-Returned-value-rules/pb2635_nan_selection_agrees_with_ordinal` pins the
selection (MAX / MIN and ORD-MAX / ORD-MIN name one argument) only where a finite argument is selected; the cases that
select the NaN are this note's.
