# PB5833 - a reference-modified element under an ALL subscript is classed as its numeric element by the argument-class screen: MAX and MIN refuse legal lists, MEAN, MEDIAN and MIDRANGE compute from digit slices, an illegal mix compiles and fails at run time (every edition)

**Ruling: UPHELD (b), harm rejects_legal_source, under_rejects, wrong_answer and crashes.** A reference-modified element under an ALL subscript (`N-EL (ALL) (1:1)`) is class alphanumeric by the 1985 text, and the argument-class screen classes it as its numeric element. MAX and MIN refuse legal lists; MEAN, MEDIAN and MIDRANGE compute from digit slices; an illegal MAX mix compiles and fails at run time. Cause (b): wrong the same way at 2023. The checker's confidence: high. Severity MAJOR: a wrong-answer defect is at least MAJOR.

**This is NOT the mechanism of kb/Work PB5780 or PB5813:** `ClassOfPlace` classes a bare reference-modified place correctly (`rmctl.cob`), the miss is the `TableAllPlace` wrapper that `TryBindAllArgument` puts around it, whereas PB5780 is a relation on a bare reference-modified numeric item and PB5813 is INITIALIZE REPLACING on a reference-modified alphabetic item. kb/Work PB5544 is a neighbour on the same ALL plus reference-modifier tail (a reference modifier after a qualifier) but a different defect.

**What happens (the checker's evidence).** The form is legal 1985 as amended: the reference-modifier is applied to each of the implicitly specified elements of the table (`§1985:IV.4.3.8.4.4 GR3a`), and each reference-modified numeric element is class and category alphanumeric (`§1985:IV.4.3.8.4.4 GR5`). MEAN, MEDIAN and MIDRANGE require class numeric (`§1989:A.2.24.3 AR1`, and AR1 of A.2.25.3 and A.2.26.3), so `N-EL (ALL) (1:1)` must be refused there; the compiler computes from digit slices (MEAN 0003.6666 = (1+7+3)/3, MEDIAN 0002.0000, MIDRANGE 0004.0000: `allrmstat.cob`). MAX and MIN admit an all-alphanumeric list or a mix of alphabetic and alphanumeric (`§1989:A.2.23.3 AR1`, `§1989:A.2.27.3 AR1`); the compiler refuses `MAX (N-EL (ALL) (2:1) "1")` and `MIN (N-EL (ALL) (1:1) A-ITEM)` with COBOL1627 (`allrmmax.cob`, exit 65), and it admits the illegal numeric/alphanumeric mix `MAX (N-EL (ALL) (1:1) N-ITEM)` where an alphanumeric function may stand (`allrmmv.cob`), which then crashes at run time (`NotImplementedCobolFeatureException`, "FUNCTION MAX in a string context", exit 82) at 85 and 2023. In a COMPUTE the same mix is refused, but by COBOL0844 (MAX typed alphanumeric), not by the class rule (`allrmmix.cob`, exit 65). Control: the non-ALL form `MEAN (N-ITEM (1:2) 5)` is refused COBOL1627 (`rmctl.cob`, exit 65, "FUNCTION MEAN argument-1 is of class alphanumeric"). Same code and output at 2023. Cause: `IntrinsicBinder.TryBindAllArgument` wraps the `RefModPlace` view in a `TableAllPlace` (about line 3433) and `ClassOfPlace` tests only `p is RefModPlace`, falling to `ClassOfItem(p.Item)`, the numeric element; the function-type resolver reads the reference modifier (MAX typed alphanumeric), so two readers of one class disagree.

**Siblings to sweep (the checker's list).** Every function whose screen reads `ClassOfPlace` over an ALL argument: ORD-MAX, ORD-MIN, RANGE, SUM, VARIANCE, STANDARD-DEVIATION, PRESENT-VALUE.

**Sites:**
- `src/WiseOwl.Cobol.Compiler/Binding/IntrinsicArgumentRules.cs#ClassOfPlace` (does not see the `RefModPlace` inside a `TableAllPlace`)
