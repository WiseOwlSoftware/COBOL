# PB5935 - an inline int choice spliced into a citation escapes the edition-cite analyzer

**Sites:** `src/WiseOwl.Cobol.Analyzers/EditionCiteAnalyzer.cs#HeadsOf` (was `HeadOf`), `#Unwrap`, the candidate switch in
`State.Collect` (`ConditionalExpressionSyntax`, `SwitchExpressionSyntax`, `InterpolationSyntax` arms), `#Str`, `#SplicedIntoCitation`,
`tests/WiseOwl.Cobol.Tests.Unit/EditionCiteAnalyzerTests.cs#TheAnalyzer_ReportsEachShape_AndEachAlias` (the planted source and its six new holes).

**The lead (PB4950 review round 6, R6-2, low).** The interpolation-hole rule caught a hole whose head is a derived MEMBER (`§{Printed(edition)}:8.12`)
but not the same choice written inline: `HeadOf` returned null for a `ConditionalExpressionSyntax` (and for a switch expression), and the
conditional/switch detectors refused only string arms, so an int choice spliced into a citation escaped both. The old drift test was deleted when
PB4950 moved the check into the analyzer (`EditionCiteAnalyzer`, kb/Work/PB4950/2026-11-18-the-check-is-a-build-analyzer.md), so the question is
whether the analyzer inherited the hole. It did.

**Evidence (read this session on origin/main 0d4042678a; no probe was built, the cheapest probe is the planted test below).**
- `EditionCiteAnalyzer.cs:268-270`: a conditional expression is a candidate only `when Str(c.WhenTrue) && Str(c.WhenFalse)`; `Str` is true for a
  string literal, an interpolated string, a `+` with a string side, or an expression whose type is `string`. An `int` arm (`1985 : 2023`) is none.
- `EditionCiteAnalyzer.cs:271-272`: a switch expression is a candidate only when at least two arms are strings.
- `EditionCiteAnalyzer.cs:295-297`: an interpolation hole is a candidate when `HeadOf(h.Expression)` is non-null and the hole is string-typed or
  `SplicedIntoCitation(h)` (text before it ends in "§" or text after it starts with ":"). `HeadOf` (line 407) answers only for a parenthesized
  expression, an invocation, a member access or an identifier; a `ConditionalExpressionSyntax` or `SwitchExpressionSyntax` falls to `_ => null`, so
  the hole is never a candidate. A parenthesized conditional recurses into the same null.
- `tests/WiseOwl.Cobol.Tests.Unit/EditionCiteAnalyzerTests.cs`: `grep -n "1985 :\|? 1985\|Year ==" ` finds no planted inline int choice in a hole;
  the only hole test (line 345) is `$"§{Printed(edition)}:8.12"` through a derived member.

**Fix shape.** Treat an inline conditional or switch expression in a citation-spliced hole as a candidate whose reads are its condition's reads
(the same `Add`/`Candidate` the string forms use, with `derivedOnly: true` semantics for the hole), and add planted tests: `$"§{(e.Year < 2002 ? 1985
: 2023)}:8.12"` and the switch-expression form, each expected WOCA0001, plus a legal twin that prints the compile edition itself. Sweep the sibling
shapes with the same `HeadOf` null: a hole that is a cast, a `!` suppression, a null-coalescing `??` or a method-group conversion.
