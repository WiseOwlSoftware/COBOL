## Finding — `objects-p1` (wrong-answer; rows `GR-9.3.6-L2.6`, `GR-9.3.6-L3.1`, `GR-9.3.6-L3.3`)

**Mechanism.** Universal-receiver dispatch binds by NAME and treats a failed signature match as a §14.9.23.4 GR7c conformance violation, so the §9.3.6 step-6 'no match' outcome (EC-OO-METHOD, via GR7b) is never set: an EC-less implementor fatal (or EC-OO-UNIVERSAL when that checking is on) is raised instead

**Repro.** E:\Temp\claude\E--CobolSharp\a700c052-f9e4-4942-84ff-a13c7505d6ec\scratchpad\adj-d2b\out\probe\objects-p1\e_ARITY.cob: U USAGE OBJECT REFERENCE holds an instance of a class whose method T has PROCEDURE DIVISION USING LN LX (PIC 9(3), PIC X(3)); `INVOKE U "T" USING N3.` then `DISPLAY "AFTER " FUNCTION EXCEPTION-STATUS`. Siblings: e_RET.cob (`INVOKE U "M" RETURNING N3` where M declares no RETURNING) and e_DESC.cob (`INVOKE U "T" USING X3 N3`, descriptions swapped). Pinned cobol.exe, --std 2023.

**Expected from the spec.** §9.3.6 match rule 1 (equal parameter count; RETURNING presence both ways) and rule 3 (BY REFERENCE description identity) are conditions of METHOD RESOLUTION; the sole candidate T does not match, steps 1-5 find nothing, and step 6 applies: 'otherwise, the EC-OO-METHOD exception condition is set to exist' (§9.3.6 6)). §14.9.23.4 GR7b runs that search first ('If the method is not found ... the EC-OO-METHOD exception condition is set to exist') and only then does GR7c's conformance check apply. Expected: EC-OO-METHOD (fatal), EXCEPTION-STATUS = EC-OO-METHOD.

**Observed / reasoning.** All three probes terminate with 'abnormal run-unit termination: INVOKE 'OBJEARITYA' 'T': 1 argument(s) for 2 formal(s) (ISO §14.9.23.4 GR7c/§14.8.2.1 ...)' and the like: an EC-less CobolImplementorFatalException, because OoUnivStop raises EC-OO-UNIVERSAL only when that checking is enabled in both elements. The unknown-NAME case is right (e_NOPE.cob: EC-OO-METHOD). EmitCobolInvoke emits `case "T":` and stops inside it rather than falling through to `default: base.__CobolInvoke` -> the CobolObject root's EC-OO-METHOD. GR7c keeps content under the spec's reading (ANY LENGTH formals, the §14.8.2/§14.8.3 residue that §9.3.6 does not restate). Counter-reading noted: §9.3.5.3 lets a PROVIDER of overloading choose its resolution methodology, and this compiler declines overloading. But §9.3.6 is unconditional, and GR7 is an ordered sequence. OoSpineTests.Universal_ArityMismatch_EcOoUniversal and Universal_ReturningPresenceMismatch_EcOoUniversal pin the current answer, so these green tests hold the gap open. No open kb/Work note owns this.

## What the fixer owes

OoEmitter.EmitCobolInvoke's universal arm must run §9.3.6's match rules (1)–(7) against the runtime class's method of that name and, when none matches (arity, descriptor, RETURNING presence), set EC-OO-METHOD (GR7 b)) — not the GR7 c) conformance path and not an EC-less fatal. Keep EC-OO-UNIVERSAL for the rule it names. Golden: e_ARITY with a USE/WHEN on EC-OO-METHOD; plus the descriptor-mismatch and RETURNING-mismatch legs.
