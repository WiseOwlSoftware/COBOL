# PB4284 — ZERO. / FILLER. as a paragraph header is not named COBOL0901

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/CobolParserCoreBase.cs` (`CobolParserCoreBase.ReservedProcedureName`: `first` is null because the error context has already left `procedureDivision`, so `inProcedureDivision` is false).

## What happens

A paragraph header named by a reserved word that begins no statement (`ZERO.` or `FILLER.` after `STOP RUN.`) draws `COBOL0001 unexpected 'ZERO'` and never COBOL0901, the diagnostic that names a reserved word used as a procedure-name (the one every other reserved header draws). In `ReservedProcedureName` the `first` token is null because the parse has already left `procedureDivision` when the error context is read, so `inProcedureDivision` is false and the reserved-name arm is skipped.

Repro: `E:/COBOL-coord/scratch/w20261788b/fin/h3.cob` (`ZERO.`) and `h4.cob` (`FILLER.`).

## Fix

Read "in the procedure division" from a fact that survives the error context's exit (the parser's own division state), not from the context stack at the failed prediction, and compare with the words that do begin a statement, which draw COBOL0901 today. Golden for both words; sweep the other words reserved in 8.9 that begin no statement.

## Landed (wave 20261826 group A)

**Re-probe** (built tree 03ec1b251, `--std 2023`): `h3.cob` (`ZERO.` after `STOP RUN.`) drew COBOL5506 "a statement may
begin at this position ... which a literal is not", `h4.cob` (`FILLER.`) COBOL0001 "unexpected 'FILLER'"; `TALLYING.`
and `SPACE.` the same. Never COBOL0901.

**Rule.** §8.3.2.1 1): "Reserved words shall not be used as user-defined words or system-names"; a paragraph-name is a
user-defined word, and §14.4.3: "A paragraph consists of a paragraph-name followed by a separator period".

**Fix.** `CobolParserCoreBase.ReservedProcedureName` reads "in the procedure division" also from the division the parse
completed last (`EndsWithAProcedureDivision`: the context's last rule child, down the chain), the fact that survives the
error context's exit. The word then stands where the division's next paragraph header would, the re-read with the word
retyped finds the paragraph header, and COBOL0901 names it. A bare verb (`DISPLAY.` after `STOP RUN.`) keeps its
incomplete-statement report (`IsIncompleteStatement`, unchanged). The fix is generic: every word §8.9 reserves that begins
no statement is covered, which the four rows below sample.

**Goldens.** `8.3.2-COBOL-words/pb4284-reserved-header-after-the-last-sentence` (COBOL0901 'ZERO' at every edition);
`ReservedWordPositionConformanceTests.AWordReservedAtEveryEdition_DefinedAsAProcedure_IsNamedByCobol0901` gains `ZERO.`,
`FILLER.`, `TALLYING.` and `SPACE.` (exactly one diagnostic each). `WrittenKindRefusalTests`' row "figurative-after-a-paragraph-header" (PB4224) wrote
`SPACES.` alone after `P1.`, which is now this header: the row writes `SPACES DISPLAY "A".`, a figurative that begins a
sentence going on, so it keeps the PB4224 refusal.
