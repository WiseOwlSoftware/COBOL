# PB5262 - rule 2b reads `--repo=<url>` as no remote

`scripts/hooks/forbidden_commands.py:170` (`_pushes_elsewhere`, at ba1189f04b): `positional = [a for a in call.args if
not a.startswith("-") and ...]`; `remote = positional[0] if positional else "origin"`. A push that names its
destination as `git push --repo=<url> HEAD:main` (git documents `--repo` as equivalent to the repository argument) has
no positional remote, so it is judged as `origin`, this repository, and a unit pushing to another repository by that
spelling is not recognised. The docstring and the block message claim any flags. Fix at the root: one parser of git
push's own options (`--repo=`, `--repo <x>`, and the value-taking short options) instead of "drop every dash word";
add the cases to `UNIT_CASES`. Sweep: the same "drop every dash word" idiom elsewhere in the hook rules.

**Sites:** `scripts/hooks/forbidden_commands.py` (whole: `_pushes_elsewhere` exists only on the PB5234 branch, PR #1495, until it lands; at ba1189f04b it is lines 165-178), `scripts/hooks/test_forbidden_commands.py` (`UNIT_CASES`)
