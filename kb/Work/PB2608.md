# PB2608 — COBOL run output tracked at the repository root

Found by the w1037s implementer (PB2560 report, "New defects"); filed by the train 1037t lander.

`git ls-files ':(glob)*'` lists fourteen files that are program OUTPUT, not source: `db101a.txt`, `pb1044.txt`,
`pb1137ia.txt`, `pb673oo.dat`, `oo-ext.dat`, `oo-fac.dat`, `oo-obj.dat`, `oo-sort-in.dat`, `oo-sort-out.dat`,
`oo-two.dat`, `l1m8rp-f.rpt`, `l1m8rp-fn.rpt`, `l1m8rp-o.rpt`, `l1m8rp-p.rpt`. Each is the file a conformance golden's
relative `ASSIGN` names, for example `tests/conformance/2002/pb1137_invoke_argument_forms.cob:35`
(`SELECT RPTF ASSIGN TO "pb1137ia.txt"`) and `tests/conformance/2023/l1m8_report_section_placements.cob:46,77,119`.
`git log --diff-filter=A` dates them to `27d579574` (PB1705, `db101a.txt`) and `d8f9168e7` (PB1051, the rest).

The suites do not write there: `tests/Cobol.Net.Tests.Conformance/CompilerUnderTest.cs:51` and
`AcceptDifferentialTests.cs:38` run each program with `WorkingDirectory` set to its own directory. The likely source
is a by-hand `cobol run` of a golden from the repository root, followed by the commit's `git add -A`. That is not
confirmed; the fix must first find which run wrote them.

## Harm
Process only. The repository root carries stale run output that no test reads. A later run from the root overwrites
it, and the next `git add -A` commits the new bytes as an unexplained change.

## Fix shape
Delete the fourteen files. Then make the class impossible: either a `.gitignore` rule for run output at the root
(`/*.dat`, `/*.rpt`, and the `.txt` names), or a drift test that fails when a tracked root file matches a name a golden
`ASSIGN`s. The drift test is the shape that also catches the next golden. PB2230 (Delete program PB2119) covers one
dead root artifact from the census; check it for overlap when this lands.

**Overlap (w1041a, 2026-10-08):** `db101a.txt` was deleted by PB2230; thirteen tracked root run outputs remain for this note.
