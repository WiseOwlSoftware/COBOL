# PB420 — a deferral whose premise stopped being true

Adjudicated in lane-3 batch b2 (`initialize-statement` part 2, finding INIT-P2-F6). **Re-measured on HEAD
89044aa0** with the two controls that isolate it.

## 1. The mechanism

`InitializeEmitter.EmitAction`'s **first** switch arm
(`src/Cobol.Net.Compiler/CodeGen/Verbs/InitializeEmitter.cs:30-45`) intercepts every `InitializeStore` whose
receiver has `Pic.IsFloat`. If the sender is the figurative ZERO it stores the item's default initializer
(correct, and it carries the windowed-float image-store shape that landed under PB164 — that half must
survive). Otherwise it emits

```csharp
LoudStmt($"INITIALIZE REPLACING/VALUE into floating-point item '{…}' (float MOVE path deferred)")
```

The arm's own comment says the float MOVE path is "deferred backend-wide". **That premise no longer holds.**
The MOVE emitter's float-receiver path is live and checked — PB271 (status: landed) hardened the float store's
overflow behaviour, which presupposes the path exists — and the identical explicit statement compiles and runs
in the same data division.

The general rule grants the implicit MOVE no exemption of any kind: it says the implicit statement *is* a MOVE
for every category except the five pointer-ish ones, so a COMP-2 receiver is category numeric and the MOVE
clause governs it. The cost of leaving the arm in place is out of proportion to the case it guards: **one
COMP-1/COMP-2 leaf anywhere in the group makes the whole statement throw**, including for the items that have
nothing to do with floats, because the loud statement is emitted inline in the per-elementary run.

not an adjudication.

## 4. The code site and the shape of the repair

* `.../CodeGen/Verbs/InitializeEmitter.cs:30-45` — the `case InitializeStore { Target.Item.Pic: { IsFloat: true } fp } s:`
  arm and its `LoudStmt` else-branch.
* `.../CodeGen/Verbs/InitializeEmitter.cs:46-48` — `case InitializeStore s: move.Emit(new BoundMove(s.Source, [s.Target]));`,
  the ordinary path this should fall into.
* `.../CodeGen/Verbs/InitializeEmitter.cs:49-55` — `case InitializeSetNull s:`, the SET arm.
* `.../Binding/Model/PicInfo.cs` `enum PicCategory` — no FunctionPointer / MessageTag member.

The special arm should **collapse into the ordinary `move.Emit` line** — that is the whole point of routing
every store through one MOVE emitter, and it is what makes conversion, editing, JUSTIFIED and truncation
identical to an explicit MOVE. The one thing that must survive the collapse is the **windowed-float
image-store** shape the arm also carries: a windowed (image-stored) float receiver stores its IEEE window
bytes, which is exactly what `MoveEmitter`'s float-receiver arm already does. So the correct repair is to
delete the arm and verify that `MoveEmitter` handles both the raw-carrier and image-stored cases — not to add
a second float path inside `InitializeEmitter`.

## 5. The sibling sweep the fixer must do

* **Grep `CodeGen/Verbs` for every other `LoudStmt` whose comment names a "deferred" backend path**, and
  re-check each premise. This one was true when written and silently stopped being true; there is no mechanism
  that notices.
* **Both senders.** The arm fires for the REPLACING sender *and* the TO VALUE sender; a fix tested only on
  REPLACING leaves the other arm.
* **Both float shapes.** Raw-carrier COMP-1/COMP-2 and windowed/image-stored floats must both be measured
  after the collapse; the image-store shape is the reason the arm exists at all.
* **`InitializeSetNull` and the missing categories.** Once PB415 lands the eight missing category words, a
  function-pointer or message-tag receiver becomes expressible and the SET arm's three-of-five coverage
  becomes observable. `PicCategory` needs those members, or the new words will classify wrongly.
* Editions: REPLACING and COMP-1/COMP-2 are COBOL-85, so the crash is reachable at every edition; the TO VALUE
  arm is 2002+.

  for program-pointer by `conformance:2002/initialize_program_pointer`). (1) The float interception, measured
