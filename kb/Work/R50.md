# R50 — user documentation, site, and distribution

**Asked 2026-09-26** (after the GitHub community-standards files): should the compiler's documentation be a GitHub
wiki or something else, given that it must cover installation, use, and every user-documentation obligation of
ISO/IEC 1989:2023 §4.2.16 (which names §4.2.3, 4.2.4, 4.2.5, 4.2.6, 4.2.10, 4.2.12 and 4.2.13)?

**Recommended:** not a wiki — the §4.2.16 documentation describes one compiler version, so it must be versioned,
reviewed and CI-checked with the code; the rustc book, CPython's `Doc/`, GnuCOBOL's Texinfo manual and dotnet/docs
all keep their manuals in version control. The conformance-bearing sections are GENERATED from the compiler's own
data with drift tests.

## Decisions (owner, 2026-09-26)

1. **Site generator: Astro Starlight.**
2. **Hosting: wiseowlsoftware.com** — the existing Astro site that already carries the Demeanor docs.
3. **Home page reworked to BIFURCATE into two products, COBOL and Demeanor; Demeanor remains the PRIMARY product.**
4. **Distribution: NuGet, exactly as Demeanor ships** — package ids carry the **`WiseOwl.` prefix** (Demeanor ships
   `WiseOwl.Demeanor`, `WiseOwl.Demeanor.MSBuild`, `WiseOwl.Inspector`).

## Consequences

- The design lives in `docs/rearchitecture/DESIGN-USER-DOCUMENTATION.md` (CLAUDE.md rule 2); the generators, drift
  tests, packaging and site work are separate `kb/Work` notes filed from it.
- Package names, the site's URL layout and the versioning scheme are proposals in that design doc until landed.
