# PB3820 — housekeeping that can fail the verdict

**Sites:** `.github/workflows/build-and-test.yml` (job `supersede`, its `actions/checkout@v7` step, about line 262; the
`continue-on-error: true` sits only on the "Cancel the superseded merge-group runs (cancel_superseded.py)" step),
`tests/Cobol.Net.Tests.Unit/LandingPipelineDriftTests.cs#TheMergeGroupRun_CancelsTheRunsTheQueueSuperseded_AndNothingElse`.

## Measured

Re-read on origin/main 33e3dcf21: `supersede` runs on every merge group, is a `needs` of `ci-gate`, and only its script step
is `continue-on-error`. A failed checkout (a runner or network error, a sparse-checkout error) fails the job and so
`ci-gate`, contradicting the stated rule that housekeeping never decides a verdict (the workflow comment,
`cancel_superseded.py`'s docstring and DESIGN-test-build-ci.md 3.17.2 step 4).

## Acceptance

- Either the checkout step is `continue-on-error: true` and the script step is skipped when it failed
  (`if: steps.<id>.outcome == 'success'`), or `ci-gate` does not read the job's result; pick the one the design 3.17.2 step 4
  states and say which.
- The landing-pipeline drift test asserts that every step of the job is non-fatal (not only the script step).
