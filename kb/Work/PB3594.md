# PB3594 — PB3568's MCS operand binding beyond FROM/GIVING identifier-1 is untested

**Blocked on PB3568:** the test file and goldens exist only on PB3568's branch (`worktree-wf_37d4041f-6f7-25`) until it lands.

## What the review found

The roster in `DeclinedFacilityOperandDriftTests.cs` (about line 40) has a Resolved column (VALIDATE 1, RECEIVE 3, SEND 2) documented as the number of operands `DeclinedFacilityBinder` resolves, but the test asserts only `resolved <= inGrammar`. Raising or lowering a Resolved figure, or dropping a resolution from the binder, fails nothing. The goldens pin only the FROM operand of SEND, the GIVING operand of RECEIVE and the exception phrases. No golden pins SEND RETURNING, RECEIVE FROM data-name-1, RECEIVE data-name-2 or the CONTINUE AFTER expression. A binder regression that stops resolving any of them passes the whole gate.

## Fix

1. Make the roster test assert equality between the Resolved column and a count the binder exposes (the binder's own operand list or a ledger it fills while binding), so the figure cannot drift from the code.
2. Add refusal goldens, each with a legal-operand control that stays inert, for an undefined name in each of: SEND RETURNING, RECEIVE FROM data-name-1, RECEIVE data-name-2 and the CONTINUE AFTER expression. Expected diagnostics come from the operand clauses of §14.9.31 and §14.9.38 and the identifier rules; the implementer runs `cite.py --check` on each clause before writing the golden.
