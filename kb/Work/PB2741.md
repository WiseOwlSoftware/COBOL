**Rule it breaks:** ExternalizedNames is 'written ONCE here so that the side that REGISTERS a name ... and the side that LOOKS ONE UP ... can never disagree' (ExternalizedNames.cs:5-25; DOC-A.1-68 / DOC-A.1-219, kb/Work PB1402: the host case mapping 'disagrees with Annex C on the extended letters'); DOC-A.1-216 'a program-pointer / function-pointer = a base from the same allocator per (category, case-folded externalized name)' and its pinned relation 'equal addresses have equal images'

**Scenario:** PointerImage.NameBase (PointerImage.cs:98-107) keys the base on category + name.ToUpperInvariant(), while ProgramPointer.SameTarget / FunctionPointer.SameTarget (the 8.8.4.2.16 equality) and ProgramTable's resolution use ExternalizedNames.Same, the Annex C fold (CobolNames.Fold). The two disagree, measured with .NET on this host: ToUpperInvariant maps U+017F (LATIN SMALL LETTER LONG S) to 'S', and Annex C lists no mapping for U+017F (CobolNames.Table.cs has none), so 'P' + U+017F and 'PS' are two different program-names whose pointers SameTarget calls unequal, yet NameBase gives them ONE key and ONE image: a BY CONTENT pass of either pointer into a PIC X(8) formal (the GR9 storage-image path, CallAbi.cs WithPointerContent) delivers identical bytes for two different programs, the image the codec says 'IS the address'. The other direction: Annex C folds U+212A (KELVIN SIGN) to 'k' (CobolNames.Table.cs:142) while ToUpperInvariant leaves it as U+212A, so ENTRY 'K' and ENTRY U+212A are the same program and SameTarget-equal (8.8.4.2.16, 'equal if they reference the same address'), yet their images differ. Silent: no condition is raised and the run continues on the wrong bytes.
