# PB324 — the record lands in a file named after the file-name

**Rows:** `GR-14.9.27.4-26`.

## The program

`<lane3 scratch>/out-b1/probe/assign-using/p.cob` — `SELECT FU ASSIGN USING WS-NAME` with
`01 WS-NAME PIC X(11) VALUE "target1.dat"`; OPEN OUTPUT, WRITE, CLOSE; then list the directory.

## The rule

§14.9.27.4 GR26 routes to §12.4.5.3 GR3/GR4. GR3 b):

> When the USING phrase of the ASSIGN clause is specified, the file connector referenced by file-name-1 is
> associated with a physical file identified by the content of the data item referenced by data-name-1 in the
> runtime element that executes the OPEN, SORT, or MERGE statement.

and GR3's lead sentence fixes the TIMING:

> The association occurs at the time of execution of an OPEN, SORT, or MERGE statement that referenced
> file-name-1.

`--check 12.4.5.3 "The association occurs at the time of execution of an OPEN, SORT, or MERGE statement"` →
**OK**. The record must therefore land in `target1.dat`, re-resolved at every OPEN.

## What the compiler does

The program compiles with no diagnostic, OPEN OUTPUT reports '00', and the record lands in **`fu.txt`** —
`CobolFile.ResolveHostPath` applied to the FILE-NAME, which is `FileModel.AssignTarget`'s constructor default
when no `assignTarget` node is present. `target1.dat` is never created. `DataBinder.BindFileControl` (line 792)
reads only `assignClause().assignTarget()`; the USING `dataReference` child is read nowhere in `src`.

The TIMING half is broken independently: `FileRegistry.Register` (line 104) calls `ResolveHostPath` at unit
activation and stores the result in the get-only `FileConnector.HostPath`, so a MOVE into data-name-1 between
two OPENs cannot change the association — the standard's concepts annex states the intended behaviour outright
(*the MOVE statements only have an effect on the dynamic assignment when a subsequent OPEN statement for the
file connector is executed*).

**Code sites:** `DataBinder.cs#BindFileControl` (line 792) · `CobolIO.g4#assignClause` (lines 36-39) ·
`FileRegistry.cs#Register` (line 104) · `CobolFile.cs#ResolveHostPath` (lines 233-237).

## The fix shape

Carry the USING data item on `FileModel`, and make the connector's host path SETTABLE at OPEN through a
per-OPEN re-resolution entry point — which §12.4.5.3 GR3 requires for every ASSIGN form, not just USING — then
state GR4's allowable-content and consistency rules in `docs/CONFORMANCE.md`. `kb/Work/A2` already lists ASSIGN
USING as a proved silently-unenforced SYNTAX rule; this is the general-rule semantic half.
