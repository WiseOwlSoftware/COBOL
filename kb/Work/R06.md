# R06 — `EcBinder.EcWrap` collapses per-CONDITION `WITH LOCATION` into ONE per-STATEMENT bool, so one stray directive 

`EcBinder.EcWrap` collapses per-CONDITION `WITH LOCATION` into ONE per-STATEMENT bool, so one stray directive contaminates every other condition's §15.32.3 r1 answer

> Migrated from the fix queue's RESIDUE block, which never itemised these — so no work list could see them.

## Analysis (2026-08-07 — banked before implementation; R05's commit precedes this work)

**The premise HOLDS this time, and the citation is validated.** §15.32.3 r1 (cite.py OK): *"If the LOCATION
option of the TURN directive or PERFORM statement that enabled checking for **the exception condition associated
with the last exception status** is not specified … the returned value is 63 spaces."* — the option is
per-CONDITION. The collapse: `EcBinder.EcWrap` computes
`bool withLoc = enabled.Any(e => ctx.EcState.Turn.WithLocation(e.Ec, e.File?.CobolName, line))` — ANY. A
statement checked for EC-SIZE (`>>TURN EC-SIZE CHECKING ON WITH LOCATION`) and EC-BOUND-SUBSCRIPT (enabled
WITHOUT location) records statement/location for a BOUND-SUBSCRIPT raise too; EXCEPTION-STATEMENT then returns
the name where r1 requires 63 spaces. Same for §15.30.3 r1 (EXCEPTION-LOCATION → one space).

**Repair shape.** `EcStatementInfo.Enabled` becomes `(string Ec, FileModel? File, bool WithLocation)` triples
(the per-pair bit `TurnState.WithLocation` already computes); drop the statement-level bool.

**Consumer map (all of them, measured):**
- `EcEmitter.EcStmtLoc(info)` — the single (stmt, loc) rendering; callers at `EcEmitter.cs:147/230/255`,
  `CallEmitter.cs:142`, `PtrEmitter.cs:134/161`, `SequentialIoEmitter.cs:38`.
- `PtrEmitter` / `SequentialIoEmitter` / `CallEmitter` know WHICH ec (and file) they guard statically → consult
  the per-pair bit directly.
- The generic paths (`EcEmitter.cs:147/230/255`) know the name only at RUNTIME (the caught exception carries
  it). When the statement's enabled set is UNIFORM (all-with or all-without — the overwhelmingly common case),
  emit the constant pair exactly as today (byte-stability). Only a MIXED set needs a per-name conditional in the
  emitted guard (a name→(stmt,loc) switch, or a generated withLoc name-set test).
- `BoundRaise` (`EcEmitter.cs:197`) is ALREADY per-condition — RAISE names one ec; untouched.

**Verification bar:** the golden is the MIXED statement — two conditions enabled at one statement, one WITH
LOCATION, one without; raise each; EXCEPTION-STATEMENT must answer the Table-12 name for the first and 63
spaces for the second, and EXCEPTION-LOCATION the three-part string / one space respectively. Plus a
byte-stability check that a uniform statement's generated wrapper is unchanged.

## LANDED (2026-08-07) — exactly the repair shape above

`EcStatementInfo.Enabled` → (Ec, File, WithLocation) triples, statement-level bool DELETED (the compiler
enumerated the consumers). `EcStmtLoc(info, ec[, file])` for static names; `EcStmtLocExpr(info, names,
nameExpr)` for runtime names — constants when uniform (byte-identical), per-name conditional when mixed.
`__IoCheckEc` gained `__locMask` (bit-aligned with `__mask`; `IoLocMaskFor`) because the raised EC-I-O name is
chosen inside by the §9.1.13.1 status mapping. `BoundRaise` untouched (already per-condition). Fact ECT053 is
the mixed DIVIDE — its first line read `S=[DIVIDE…]` under the old bool, `S=[63 spaces]` now.
