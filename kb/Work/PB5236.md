# PB5236 - replace the harness's worktree-isolation guard with a dispatch shape

**What it is.** Not a repository file. Claude Code refuses a shell command of an agent started with
`isolation: 'worktree'` when it cannot prove the command stays inside that worktree ("too complex to verify that it stays
inside the worktree"). The rolling wave starts its implementers that way
(`.claude/skills/workstream/templates/wf_rolling_wave.js`, the `gatefix-`, `impl-` and `fix-` agents).

**Measured (kb/Work PB5234's addendum, window 2026-11-08..10).** 282 refusals in 107 transcripts, every one in a Workflow
subagent: the second-largest refusal family after the heredoc rule. Ten sampled, none true: reads, probes inside the
agent's own worktree, and writes to the coordination scratch directory its brief names. Each refusal costs a turn and,
for a file outside the worktree, a detour through the Write tool (MANDATORY-PRACTICES P12, kb/Work PB4900).

**The decision (PB5207's "Guards").** The harm the isolation guard prevents, an agent acting on another tree, is
prevented by the dispatch shape instead: the dispatcher creates each agent's worktree (`git worktree add`, the shape every
attended brief already uses: "Work ONLY in the worktree ..."), starts the agent without `isolation: 'worktree'`, and the
project's permission rules and hooks bound what it may not do (never `git stash`, never a push to main, never another
repository from a loop unit; `forbidden_commands.py`).

**Why it is not in PB5234.** The harness-made worktree and its `worktree-wf_*` branch names run through
`scripts/orchestrator/plan_wave.py`, `scripts/prune_worktrees.py`, `scripts/orchestrator/landing_rules.py`,
`review_lane.py`, `coord.py`, `scripts/orchestrator/units/wave.md` and the orchestrator tests (`test_rolling_wave.py`,
`test_plan_wave.py`), which another lane is editing (`E:/COBOL-coord/scratch/build-plan/stages-in-parallel.md`). It is
made after those land: the worktree a wave creates is named and found by the same code that names and finds it today.

**Done when.** No dispatch template passes `isolation: 'worktree'`; the wave creates and records each agent's worktree;
every reader of a `worktree-wf_*` name reads the recorded one; MANDATORY-PRACTICES P12 and
`dispatch-spec-implementer.md` no longer describe the isolation refusal; the next window's isolation refusals are 0.
