# PB2479 — the loop's helper paths hardcode the default config dir

Owner, 2026-10-07 13:17 PDT: a second Claude Code session, logged into a second Max 20x account (`CLAUDE_CONFIG_DIR=C:\Users\brent\.claude-acct2`), runs every Opus/Sonnet dispatch, the orchestrator loop and the landings (the OPERATOR); the first account's session keeps Mythos work. The owner seeded the second config dir by hand. Owner 13:36 PDT: account 2's week resets Saturday 2026-10-10 10:00 PDT and must be spent to 100 % before then, so every hour the tooling stops dispatch wrongly is quota lost.

**Model:** Opus (tooling with self-tests). All six notes are one mechanism (the account is a parameter of the coordination tooling, never an assumption) and are dispatched as one group.

## Defect

`scripts/orchestrator/orchestrate.ps1:159-162` `Get-ProjectTranscriptDir` returns `$HOME/.claude/projects/<key>/<sid>`;
under `CLAUDE_CONFIG_DIR=C:\Users\brent\.claude-acct2` the unit transcripts live under that dir, so `-Watch`'s
`open-watchers.ps1 -SessionDir` watches an empty folder. The same assumption is in `scripts/telemetry/otlp_sink.py:28`
and `usage_report.py:19` (`~/.claude/telemetry`) — decide whether telemetry is per-machine (keep, and PB2478 filters by
account) or per-account, and state it. The log header names no account, so a reader of
`E:\COBOL-coord\logs\orchestrate-*.out.log` cannot tell which quota a unit spent.

## Shape

One resolver of the config dir (`CLAUDE_CONFIG_DIR` or `$HOME/.claude`) used by every script that reads Claude's own
files (sweep `scripts/` for `.claude/projects`, `.claude/telemetry`, `.claude\\`); `orchestrate.ps1` and
`start-session.ps1` take `-ConfigDir` (default: the resolver), set `CLAUDE_CONFIG_DIR` explicitly in each child
`claude -p` environment, and print the account in the log header. Test in `test_orchestrate.ps1`.


## Landed (branch acct2-tooling, wave 1033 group T)

- The one resolver is `scripts/orchestrator/account.py` (PB2478): config dir, global config, account id, transcript
  dir (`project_dir`), and `child_config_dir`, the value a child must carry to run as the account (the dir for a named
  account; UNSET for the default one, because `CLAUDE_CONFIG_DIR=~/.claude` makes Claude Code look for its sign-in in
  `~/.claude/.claude.json`).
- `orchestrate.ps1 -ConfigDir` (default: the resolver): an unknown dir exits 2 before anything starts; the process and
  every `claude -p` child get exactly the account's `CLAUDE_CONFIG_DIR`; `Get-ProjectTranscriptDir` reads the
  account's `project_dir`; the log header (`account: account2 (config dir ...)`), the budget line and every
  `units.jsonl` line name the account. `start-session.ps1 -ConfigDir` the same. `test_orchestrate.ps1` 110/110 (the
  account cases: `-ConfigDir` for each account, the child's variable recorded by the fake, the transcript dir, an
  unknown dir refused, start-session for both accounts).
- Telemetry is decided per MACHINE (stated in `otlp_sink.py`, `account.py`, the design's section 2.1): both accounts'
  settings export to the one sink, and the account is filtered on `user.account_uuid`. `usage_report.py` now takes the
  sink's `OUT_DIR` instead of a second copy of the path.
- Sweep (`.claude/projects`, `.claude/telemetry`, `CLAUDE_CONFIG_DIR`, `home() / ".claude"`): `fleet_active_build.py`
  dropped its private copy of the rule for `account.config_dir()`; `tooling_check.py` reads the account's
  `settings.json` and skill-doctor stamp; the watcher scripts' examples name `<config dir>`.
