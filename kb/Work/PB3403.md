# PB3403 — `devlog.py check` has no pre-landing mode

Filed at the Mythos lane's request (its mail of 2026-10-18 22:01, which carried this as a lead the owner asked about).

**The mechanism (`scripts/devlog.py`, on main at 49e1c6b79).** `check` is the landing rule on the trees of a range
(`check(base, …, rev, …)`). For every `DEVLOG/pending-<slug>.md` in `rev` it refuses with "is an unstamped entry: run
`python scripts/devlog.py stamp <branch>` before landing". `lint` accepts a pending entry ("a branch carries one until
its landing stamps it; `check` refuses it at the landing"). Only `enqueue.py land` runs `devlog.py stamp`, and it runs it
after its final merge of main, because the number must follow the allocator (PB3025, PB3123). `enqueue.py checks` runs
`devlog.py check` first among its landing checks (`CHECKS`, refusal exit 6).

**The harm.** Before its landing, a finished branch has no command that answers "will the DEVLOG check pass?". Run on
the branch, `devlog.py check` (and so `enqueue.py checks`) refuses a CORRECT branch, the one that carries exactly one
well-formed pending entry, the same way it refuses a broken one. An implementer or finisher therefore either skips the
check or learns to read past a red, and a real DEVLOG defect (no entry, a bad first line, an entry stamped by hand)
first shows up as a landing-lane attempt that ends in exit 6.

**The fix.** Give `check` a pre-landing mode, for example `devlog.py check --pending`. It holds the branch to the shape
`stamp` needs: at least one pending entry (a successor may carry its predecessor's too, and `stamp` folds them into one),
each with first line `## <Title>`, no new stamped entry, and `lint` clean. The landing keeps the strict mode. `enqueue.py checks`
gains the same switch, so an agent can run the whole landing-check set before handing a branch over, and
MANDATORY-PRACTICES names that run where it names the checks. The self-test should cover a correct pending branch
(passes the pre-landing mode, refused at landing), a branch with no entry (refused by both), a pending entry with a bad
first line, and a hand-stamped entry (both refused by the pre-landing mode).
