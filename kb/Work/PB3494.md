# PB3494 — kept transaction state is the connector's, not the physical file's

Lead R1-2 of the branch review of PB3483 (`E:/COBOL-coord/scratch/reports/w1140d-PB3483-report.md`).

`src/Cobol.Net.Runtime/IO/FileConnector.cs` about line 361: `Associate` may change `HostPath` (ASSIGN USING data-name, §12.4.5.3 GR3 b) between the CLOSE under commit control and the re-OPEN, and nothing releases or separates the kept state then. `TakeRunUnitFileLock` Amends the kept lock on the OLD file (`RunUnitFileLock._as.HostPath`) and the new file gets no column lock; `RetakeKeptHandle` opens the CURRENT `HostPath` with the old handle's access and share. The root pre-exists in PB3337: `TakeFileLock` adoption and `Attach` reuse `AttachedStore` whatever the path.

**Fix shape.** Key the kept state by the physical file: when `Associate` changes `HostPath` while state is kept, decide against §9.1.18 and §12.4.5.3 what happens to the transaction on the old file (cite-check the clauses first), then end or carry it deliberately.

**Sites:**
- `src/Cobol.Net.Runtime/IO/FileConnector.cs`
- `src/Cobol.Net.Runtime/IO/KeyedConnector.cs`
- `src/Cobol.Net.Runtime/IO/Sharing/RunUnitFileLock.cs`

**Second witness 2026-10-21 (w1140b-PB3484-report.md, `## New defects`).** A re-OPEN with a different dynamic ASSIGN after a CLOSE under commit control adopts the OLD file's kept handle and store. Repro `E:/COBOL-coord/scratch/w1140b/probe_dyn.cs.txt`: seed two Relative files (host1 with records, host2 with 3), declare the file under commit control with a dynamic ASSIGN, OPEN I-O on host1, read record 1, CLOSE, OPEN I-O on host2. The OPEN answers '00' and `HostPathOf("F")` is host2, yet READ of record 5 answers '00' with host1's record 5; host2 has 3 records, so the expected status is '23'. A wrong answer. Site `KeyedConnector.cs#TakeFileLock` / `#Attach`; the fix needs the kept state keyed by physical file, the PB3337 redesign this note already names. `InheritKept` does not widen it (it requires the same physical file).
