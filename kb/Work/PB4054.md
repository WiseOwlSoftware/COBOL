# PB4054 — the once-check read a one-file group's path as a sentence stated twice

## Sites

- `.claude/skills/workstream/check_practices.py#repeated_sentences` (called from `check_practices.py#check` for
  `dispatch-spec-implementer.md` and every rendered `msg-w<wave>-<letter>.txt`) splits the text after `. ! ? : ;` and
  counted every piece of `SENTENCE_MIN` (60) characters or more as a sentence.
- The text it read: `.claude/skills/workstream/templates/dispatch-spec-implementer.md` line 15 renders `THE GROUP IS ONE
  ROOT: {root}.`, and `scripts/orchestrator/groups.py#body_of` renders `CODE SITES the notes name: {sites}.`. For a group of
  ONE file with no claimed members, `groups.py#as_group_json` makes `root` the bare path and `groups.py#sites_text` makes
  `sites` the same bare path, so both pieces after the colons are `<path>.`.

## What happened

Wave 20261751 planned three groups: A (PB3953, NumericRenderer.cs and three more files), B (PB4031, one file:
`src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/ReportWriterEmitter.cs`, 62 characters) and C (PB4036, two files). A's and C's
roots carry an `(also …)` list, so their two pieces differ; B's are identical, and the 63-character piece
`src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/ReportWriterEmitter.cs.` counted as a sentence stated twice. `check_practices.py`
went RED, so `make_dispatch_specs.py` reserved no code, recorded nothing in the dispatch ledger and wrote no wf-args file, and
the wave unit launched no fleet. Every later plan holding a one-file group with a path that long would have gone RED the
same way, and PB4031 ranks third in `work.py next`.

## The fix

PB3777's rule is that the implementer's instruction file states each RULE once. A lone token (a path, an identifier) states
no rule: the spec names the same file in two roles, the group's claim and the note's code sites. `repeated_sentences` now
counts only a piece of two words or more. The two roles stay in the spec: for a group of more files or of claimed members
they differ, and the implementer reads each where it serves.

**Witness:** `scripts/orchestrator/test_plan_wave.py` §7c3 renders a one-file group whose file is the 62-character path of
the incident through the real template, checks that the spec ends both the root and the sites with it, and checks that the
once-check passes it. Without the fix that check fails with the incident's message (`PB3777: states twice:
src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/ReportWriterEmitter.cs.…`). With the fix the self-test is 488/488 and the wave's
three real specs (`msg-w20261751-a/b/c.txt`) pass `check_practices.check(…, SPEC)`. The existing §7c3 checks that the
once-check still refuses a spec that repeats a real sentence still pass.
