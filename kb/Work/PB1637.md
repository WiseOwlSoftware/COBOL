# PB1637 — LANDED 2026-09-27

**Observed.** Battery #87 (first attempt, pinned at 2b5f95282) reported "⛔ findings / misfiled / unmarked refuted
claims / inventory evidence lost". Its `citations.log` held four copies of "Python was not found; run without arguments
to install from the Microsoft Store". `python3` resolves to `WindowsApps\python3`, the app-execution alias: it is ON
PATH, so `command -v` finds it, and running it fails. The real interpreter is `python` (3.14.7) since the PATH change
of 2026-09-24. Battery #86 ran on 2026-09-23, before it.

**Blast radius.** In `scripts/battery.sh`: the four phase −1 audits and phase 3's `gnucobol_differential.py`. In
`scripts/guard-fast.sh`: the Unit and Integration leg reporters (`test_leg_report.py`), which would have turned green
legs red. No other shell script names `python3`; `setup-wsl.sh` names `python3.14` deliberately. CI (ubuntu) has a
real `python3`, which is why CI never showed it.

**Fix.** ONE resolver, `scripts/python-resolve.sh`, sourced by both scripts. It PROBES each candidate by running it:
`$PYTHON`, then `python3`, then `python`, requiring >= 3.12. It exports `$PY`, and it exits non-zero and loudly when
nothing runs, because a gate that cannot run its checks is red, never skipped. Verified: Windows → `python`; WSL →
`python3`; `PATH=/usr/bin` → the loud failure, rc 1. The rest of battery #87 was stopped and re-run from a head that
contains the fix.
