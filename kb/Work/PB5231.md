# PB5231 - the conformance suite is a generated target, and Conformance is keyed on its output

**Sites:** `scripts/buildgraph.py` (`Target`, `TestTarget`, `GeneratedTarget`, `Graph`, `Graph.of`, `_topological`,
`load_targets`, `key`, `keys`, `stored_outputs`, `output_digest`, `TRACER`, `traced_run`, `undeclared`, `Generation`,
`generate`, `bring_up_to_date`, `Scan.through`/`handed`, `scan`, `check`, the self-test), `scripts/build_targets.json`
(`conformance-suite`; `conformance`'s `depends`, inputs and exclusions; every target's `kind`), `scripts/gate.py`
(`Host.graph`, `Host.targets`, `Host.target_keys`, `Host.generate`, `Host.output_digest`, `Host.listing`, `host_env`,
`Outcome.generated`, `Gate._generate`, `Gate._handed`, `Gate._check_generated`, `Gate._generated_detail`,
`Gate.record_passes`, `Gate.rederive`, `Gate._listing_at`, `rederive_main`, `FakeHost` and the self-test),
`scripts/test_population.py` (`list_population(handed=)`), `scripts/self_test_arms.py`, `tests/_shared/SuiteManifest.cs`
(`HandedVariable`, `GenerateOnce`), `tests/WiseOwl.Cobol.Tests.Conformance/ConformanceSuite.cs` (its remarks),
`docs/rearchitecture/DESIGN-test-build-ci.md` section 3.14.12 item 5, `.claude/skills/gate/SKILL.md`.

**The decision.** PB5218 found that `conformance-suite/harness/generate.py`, which every Conformance host ran first, reads
the traceability inventory, so a records-only change re-ran all ~23,700 Conformance cases (about 870 to 2,600 s a host)
although it almost never changes the suite. Built here, as PB5207 stage 2 and in the general form the next stages extend:
- **The graph has kinds and dependencies.** A `test` target records a pass; a `generated` target is a Python command with
  declared OUTPUTS that records their DIGEST (`output_digest`: every file's relative POSIX path and content hash, in path
  order). A target may DEPEND on a generated target, and a dependency contributes its OUTPUT DIGEST to the dependent's key,
  never its inputs. The graph is checked at load (`Graph.of`): an unknown dependency, a dependency on a test target, a
  cycle (named, `a -> b -> a`), a program outside its own inputs or not Python, a hand-off variable the host scrub would not
  remove. `Graph.order` is topological.
- **`conformance-suite`** runs `generate.py --out {out}` into `<worktree>/TestResults/generated/conformance-suite/`, outputs
  `wiseowl/manifest.json` and `*/manifest.json`, facet the toolchain only. Its inputs come from reading the generator and a
  traced run (below): `conformance-suite/`, `tests/version-matrix/`, both rule catalogs, the ISO text, `scripts/spec/`,
  `standard_streams.py`, `live_tools.py`, `git_batch.py`, `.gitattributes`.
- **`conformance` depends on it.** The inventory, both rule catalogs, the ISO text, `scripts/spec/`, `git_batch.py` and
  `scratch_repo.py` left its inputs, and `harness/generate.py` and `cobol_source.py` are EXCLUDED from them. The BUILD TARGETS
  audit decides what stays: Conformance's sources read the construct catalogue directly, so `tests/version-matrix/constructs/`
  stays; they read nothing else of the generator's.
- **Soundness: the host runs the suite its key names.** The gate generates once and HANDS the directory to the Conformance
  host and to its `--list-tests` in `WISEOWL_COBOL_GATE_SUITE` (`host_env`; `list_population(handed=)`, set after the scrub).
  `SuiteManifest` reads a handed directory and generates its own only when it has none (a hand run, CI). After the hosts the
  gate digests the directory again (`_check_generated`): a change is RED (`GENERATED OUTPUT CHANGED`) and records no pass. The
  BUILD TARGETS audit requires the dependent assembly to name the variable, and treats a read of the dependency's PROGRAM
  (`SuiteManifest.Generator`) as reached through the dependency; a read of its inputs is still a finding.
- **Up to date, for a generated target,** is a store record of its output digest at its key AND outputs on disk with that
  digest; otherwise it runs. A first run at a key is recorded; a run that reproduces NOT the recorded digest is refused
  (`Nondeterministic`, the outputs kept to compare). The gate brings generated targets up to date before any key
  (`Gate._generate`), and the verdict line names each one (`conformance-suite generated in 11.7 s (output 01de7eeef7de, 5
  file(s))` or `… up to date …`).
- **Unresolvable is a failure** (owner 2026-11-10: "If it cannot be resolved, there is a problem/bug"): a dependency's output
  digest that is not known is `Unresolved`, naming it (a re-derivation that cannot resolve one refuses with that message); a
  declared output not written, a file written and not declared, a facet not given, each the same.

**Beyond the brief (decided here).**
1. **Every run of a generated target is TRACED, not only the one that derived its inputs.** `traced_run` runs the command
   under a stdlib-only audit hook (`TRACER`, `python -c`, so the repository modules it imports are opened after the hook):
   a TRACKED path it opens that its inputs do not match (an input excluded as `@inert` included), a tracked directory it lists
   that no input lies in or under, and any process it starts are refused by name (`UndeclaredRead`). PB5207 asked for "Python
   targets by the open-tracing"; this makes the generator's declaration verified at every gate that runs it, for about 1 s.
2. **The listing is handed the suite too**, not only the host: discovery reads the manifest (the theories' rows), so the
   listing and the run read one generation, and the listing no longer generates its own (~13 s).
3. **A generation while the working tree moved records nothing** (`TreeMoved`): the gate re-measures the tree after a
   generation that ran, so a store record is never the output of a different tree than its key.
4. **`KEY_VERSION` is unchanged.** A target with no dependency and every facet hashes byte-for-byte as in stage 1, so the
   stage-1 passes of `unit` and `characterization` stand; `conformance`'s key changes because its inputs changed.
5. **No declared seconds or timeout for the generator.** That is PB5232's model (stage 3) and should cover generated targets
   when it lands.

**Found by the first gate, fixed in this change: the trace judged nothing in a worktree spelled through a junction.** Under
`self_tests.py`, whose TEMP is a junction (`aliased_temp`, as CI's Windows TEMP is an 8.3 alias), the undeclared-read arm
FAILED: `generate.py` and the planted generator open `Path(__file__).resolve()` paths, the canonical spelling, and `undeclared`
compared them with the worktree's handed spelling only, so every read fell "outside the repository" and none was judged. A
false green of exactly the kind the trace exists to stop. `undeclared` now matches a read against both the handed and the
canonical spelling of the worktree. Reproduced by hand with a junction TEMP: the pre-fix `buildgraph.py --self-test` FAILS
that arm, the fixed one PASSES all 19.

**How the inputs were derived.** A traced run of `generate.py --out` (audit hook on open, listdir, scandir, Popen) on
2026-11-10: it opened 7,541 files of `conformance-suite/cases/`, 258 of `wiseowl/cases/`, 3,927 of `wiseowl/diagnostics/`,
7 of `wiseowl/options/`, the adapters, profiles, baseline and `implementor-defined.json`, 4,214 inventory records, 2,260 of
1985's, 310 constructs, `inventory-schema.json`, `reserved-words.json`, `annex-a2-undefined.json`,
`conformance-register.json`, both rule catalogs and `specs/ISO_COBOL_2023.md`; imported `harness/cobol_source.py`,
`config.py`, `scripts/spec/{construct_store, generated_output, inventory_schema, inventory_store, inventory_view, lineage}.py`,
`scripts/git_batch.py`, `scripts/standard_streams.py`; started no process. `scripts/spec/` is declared whole (it is on the
module path ahead of the standard library, so a file added there could shadow an import); `tests/version-matrix/` whole (the
schema names further files). Every gate's run of it is traced again.

**Proof.**
- `python scripts/buildgraph.py --self-test`: `=== buildgraph SELF-TEST: PASS (19 arms) ===` (stage 1: 7). The new arms, on a
  planted generator over a real scratch repository: a first run traced and recorded, a second at the same key runs nothing;
  an inventory edit that leaves the output unchanged re-runs the generator and leaves the dependent's key; one that changes
  the output changes it; a generator source edit re-runs it; outputs on disk tampered are generated again to the recorded
  digest; a second worktree at another path gives the same digest; a cycle, an unknown dependency and a dependency on a test
  target are refused; a missing dependency record is Unresolved; a planted nondeterministic output (the time) is refused; an
  undeclared read and a read of an `@inert` input are refused; an undeclared output and a run while the tree moved record
  nothing.
- `python scripts/gate.py --self-test`: `=== gate SELF-TEST: PASS (118 arms) ===` (stage 1: 109). The new arms drive the real
  gate over a planted graph and a real scratch repository, only the test hosts planted: the generator runs first and its
  directory is handed to Conformance's host and listing and to no other; an inventory edit whose output is unchanged leaves
  Conformance up to date while Unit runs; one that changes it runs Conformance; a generator edit with an unchanged output leaves
  every test target up to date; unchanged inputs run nothing; a deleted generator record re-runs the generator before
  Conformance counts as up to date; a host that writes into the handed output is RED and records nothing; a nondeterministic
  generator is RED before any host; a cycle in the targets file is RED naming it. With `_handed` and `_check_generated`

**What CI needs (for PB5235, not built here).** Nothing today: CI runs `dotnet test` with no hand-off, and `SuiteManifest`
generates its own as before. When CI computes keys and accepts local passes, its Conformance shards must take the suite from
the graph the same way (generate the `conformance-suite` target once, digest it, hand `WISEOWL_COBOL_GATE_SUITE` to each
shard), or its per-target file watch will see the generator's reads of the inventory and attribute them to Conformance.

**Remaining work.** A declared time bound for generated targets (with PB5232's per-target seconds). The `repo-drift` split of
Unit is PB5230's.
