# PB1529 — LANDED

## The rule

> 1) … If the value arithmetic-expression-1 is greater than this maximum meaningful value, the maximum meaningful value is placed into the temporary data item.

`cite.py --check 14.9.9.4 "the maximum meaningful value is placed into the temporary data item"` → OK §14.9.9.4 1).
The implementor's maximum is `CobolTiming.MaxSeconds` = 86,400 (A.1 item 39 documents it — its documentation half is PB160's).

## Repro (adjudicator `adj-a1-w1-s2`; re-probed by the registrar, Debug build of `0caa7d5`, `--std 2023`)

```cobol
       PROCEDURE DIVISION.
           CONTINUE AFTER 18446744073709551616 SECONDS.
           DISPLAY "D".
```

Observed: `D` printed and the run finished in 3 s wall-clock INCLUDING compilation (expected: an 86,400 s suspension). The adjudicator
also measured `…551619` (2^64 + 3) → ~3 s, and `01 BIG PIC 9(20) VALUE 18446744073709551616` / `CONTINUE AFTER BIG SECONDS` →
returns at once.

## Mechanism and code sites

`src/Cobol.Net.Compiler/CodeGen/StatementEmitter.cs#Visit` (the `BoundContinueAfter` arm, l.192) narrows the value with an
unchecked `(long)` cast (scale-0 lane `(long)(x.Expr)`; decimal lane `(long)(…).ToUnscaled(0, Truncation)`) BEFORE
`src/Cobol.Net.Runtime/Control/CobolTiming.cs` `SleepTruncated` applies `Math.Min(secs, MaxSeconds)`, so any interval ≥ 2^63
wraps to its low 64 bits. The float lane saturates and is safe. Fix: clamp in the value's own domain before narrowing (one
helper both lanes call).

## Sibling sweep

Every unchecked narrowing of a COBOL numeric value to a host integer before a range check — PB463 (SET … SIZE OF) is the recorded
sibling; grep the emitters for `(long)(` / `(int)(` on arithmetic-expression results.

18446744073709551616.` then `CONTINUE AFTER BIG * BIG SECONDS` emits
`ContinueAfterExact((double)((Int128)(BIG) * (BIG)), …)` — the unchecked Int128 product of 2^64 × 2^64 wraps to 0 —
and the program suspends 0 seconds (repro `doc2/out/run-refute/d1/r39b.cob`, pin 80de60472). The Scale-0 / scaled /

carrier before the clamp sees it. DOC-A.1-39's ⚠ names both.

## Revisit (2026-09-29, batch 9 — corrects the "Landed" paragraph above)

What this change actually fixed: the DOUBLE overload `CobolTiming.ContinueAfter` narrowed with an unchecked `(long)seconds`; it now compares with `MaxSeconds` first (`WholeSeconds`). The emitter lanes the mechanism section blames are ALREADY safe in the current tree: `StatementEmitter` (`BoundContinueAfter`) narrows every lane through `RuntimeApi.HostInt64` = `CobolNum.Position`, the saturating narrowing to `long`, and `SleepTruncated` applies `Math.Min(secs, MaxSeconds)` — verified by compiling `CONTINUE AFTER 18446744073709551616 SECONDS` and `CONTINUE AFTER BIG SECONDS` (`PIC 9(20)`) and reading the generated calls (`CobolTiming.ContinueAfterExact(..., CobolNum.Position((Int128)(...)), false)`). So the observed "3 s" in the note predates that narrowing. What remains before DOC-A.1-39 can be re-recorded: (1) an adjudicator re-probe that the huge-interval cases now suspend the documented maximum — by the no-wall-clock-tests rule the witness has to be the unit Theory over `WholeSeconds` plus the emitted-call shape, not a 24-hour run; (2) the row is a DOC row and DOC rows wait on PB1535 (owner decision). Nothing else is owed on the code.

## Landed in full (wave 1018, group G, 2026-10-04) — the open half, finished at its root

**Re-probe on a fresh build.** The revisit above was right about the emitter lanes it read (`RuntimeApi.HostInt64`
saturates) and wrong that "nothing else is owed": the SDIDI lane and the unsigned-wide lane were never the lanes it
probed. Measured from the generated C# of `CONTINUE AFTER` over each carrier: `BIG * BIG` (PIC 9(20), 2^128) rendered
`CobolDec.MulToOdd(...).ToUnscaled(0, Truncation)`, which keeps `sig % 10^(38 - shift)` for a value of 39 or more
digits (10^40 landed as 0 s: `CobolDec.ToUnscaledCore`, the documented unchecked-STORE disposition applied to a value
that is not a store), and a 16-byte unsigned COMP-5 item set to 2^128 - 1 rendered `CobolNum.Position((Int128)(U))`, whose
`(Int128)` cast of a `UInt128` at or above 2^127 is negative (0 s). The native-lane `Int128` product the doc-rows-2
refuter measured no longer exists as an arm: the renderer's digit-bound planner (kb/Work PB1143 / PB621) lifts a product that
can leave the carrier to the SDIDI (`HUGE * 100000000`, `BIG * BIG * 2` render `CobolDec.MulToOdd`/`Mul`), so the SDIDI
saturation is the one that matters.

**Fix (the shape that makes the next carrier automatic, CLAUDE.md rule 5).** The "exact lane" handed the runtime a
binary64 sign value beside an emitter-narrowed `long` and rendered the interval expression TWICE. Replaced by ONE
`CobolTiming.ContinueAfter` overload per carrier (`Int128` + scale, `UInt128` + scale, `CobolDec`, `double`), each taking the
sign and the whole seconds from the value in its own domain and narrowing through the carrier's saturating reader
`CobolNum.PositionOf` (new `PositionOf(UInt128, int)` beside the `Int128` / `CobolDec` / `double` readers), then one
private `Continue` body (GR1 a-c, the `Math.Min(.., MaxSeconds)` clamp, the observer seam). The emitter keeps one
total switch, `StatementEmitter.ContinueAfterCall`, over `NumXCarrier`; `ContinueAfterExact`, `SleepTruncated` and
`WholeSeconds` are deleted with every caller. `CobolDec.ToUnscaled` is untouched: its low-digit semantics are right for
the STORE it was written for.

**Witnesses (never timed, kb/Work PB1590).** `CobolTimingTests`: Theories over every carrier (2^63, 2^64, 2^64 + 3,
Int128.MaxValue, trailing-P scales, 2^127, 2^128 - 1, 10^40, 10^6000, double.MaxValue), the in-range and
negative-fraction legs, `ContinueAfterCall_IsTotalOverTheNumXCarriers_AndNarrowsNothing`, and two COMPILED programs
activated in process under `CobolTiming.SuspensionObserver` (literal 2^64, PIC 9(20), PIC 9(31), scaled, SDIDI product
and power, a 16-byte unsigned COMP-5 item = 2^128 - 1; and the STANDARD-DECIMAL variant) which see each emitted call request
exactly 86,400 s. No conformance golden: a program whose suspension is the maximum would run for a day, and the observer
is a unit-level seam.

**Register.** `DOC-A.1-39` PARTIAL -> CONFORMS (batch `w1018g-pb1529`); `docs/CONFORMANCE.md` DOC-A.1-39 loses its
"Not yet what the compiler does" warning and names its Pinned-by tests, and the §3 "Integer operands and host carriers"
paragraph now says where a CONTINUE AFTER period is saturated. Sibling sweep of the emitter for an unchecked
narrowing before a range check (`(long)(`, `(int)(`, `ToUnscaled(`): every other hit narrows an already-stored or
already-saturated value (`ArithmeticEmitter.Narrow`, `ReportSumAddress` over `CobolTable.Occ`) or is a STORE.
