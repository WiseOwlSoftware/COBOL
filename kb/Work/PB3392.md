# PB3392 — a re-rendered spec resets its group's dispatch time

**The site.** `scripts/orchestrator/plan_wave.py` `record_dispatch` (about lines 506-528 at main), THE writer of the
dispatch ledger (`inflight-groups.json`, kb/Work PB3186). It upserts one wave's groups keyed on (wave, letter), and
every entry it writes gets `"at": time.time() + k / 1000`, the moment of THIS recording. Its own docstring says "A
group recorded again (a re-rendered spec) replaces its entry", and `make_dispatch_specs.py` records every wave it
renders.

**Why `at` matters.** `landing_check.py` (its docstring, item 2) decides which of two in-flight branches that share a
file must re-plan: "A shared file stops the LATER of the two (by dispatch time: the ledger's `at`, else the branch's
first commit)". The comment in `record_dispatch` says `at` is exactly that order.

**What happened (2026-10-18).** Wave 1118 (the PB3330 engine) was dispatched at about 05:00. At 15:45 to 16:42 the
Mythos lane declared each wave-1118 group's file set from its branch's diff and re-rendered the specs (PB3263). The
ledger now reads wave 1118 A5 and A6 `at` 16:42, while wave 1126 C (PB1587, dispatched 14:02) reads 14:02. By the
ledger, the engine is the LATER dispatch. Where the partition applies (R3 work on one side), it would therefore stop
the engine branch and let the campaign branch through: the opposite of its rule. In this case it did not decide
anything, for two other reasons recorded in PB3263: wave 1126 C was recorded with 0 files (PB1587 has no site block),
and the shared files were not R3 work on either side.

**The fix.** `record_dispatch` keeps an existing entry's `at` when it records the same (wave, letter) again and only
replaces its notes, files and slug. A new group of an existing wave gets the time of its first recording. A self-test
pins it: record a group, record it again later with a wider file set, and its `at` is unchanged while its files grew.
It is in cluster PB3353 with PB3263, the campaign's planner prerequisite, in one `plan_wave.py` group.
