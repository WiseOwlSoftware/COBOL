# PB6073 - these need an adjudicator before an implementer

Each item is a lead the implementer or reviewer could not decide. This note files them so none is lost; a fix waits for a ruling
with a `cite.py --check`ed citation (rule 1).

1. **File-control clause operands and PIC A at 2002.** Record keys, ALTERNATE KEY, FILE STATUS, ASSIGN USING, SORT/MERGE keys and
   REPORT CODE take `ItemCategory`'s `DataItem` overloads and still refuse PIC A at 2002. Whether they are "operands" of §2002:8.5.2.1
   (the PB5615 rule that admits alphabetic operands) needs a ruling. Sites `FileControlBinder.cs`, `FileControlKeyRules.cs`,
   `ReportSectionBinder.cs` (~610). Shares the root with PB5615.
2. **STRING sender PIC A at 2014/2023.** `STRING TV DELIMITED BY SIZE INTO OUT` with TV PIC A compiles at `--std 2023`, whereas
   UNSTRING refuses it; STRING's rule names alphanumeric or national senders. Site: the STRING arm of `StringUnstringBinder`.
   Probe file in the scratch `w20262045g/multi.cob`.
3. **DISPLAY of `PIC 99 COMP-5 VALUE 4`** printed `004` (three digits), not `04`. Not verified against the DISPLAY rule for COMP-5
   (an implementor usage: the row to cite is the recorded implementor choice, not an ISO rule). PB3921 and PB3990 touch COMP-5
   display; check them first.
4. **`pb5607-string-pointer-binary-container.cob` (line 11)** credits the COMP-5 container capacity to ISO 13.18.60.4 GR12, but
   COMP-5 is not an ISO usage (absent from `specs/ISO_COBOL_2023.md`); GR12 covers only binary-char/short/long/double. The COMP-5
   range is the implementor choice recorded in `docs/conformance/3/D-INCOMPATIBLE-FIXED.md` (item 208). Re-cite the golden to
   the implementor decision.
5. **`2002-AR-15.77.2-1`**: the PB5615 finisher deleted `g2-testnumvalf-alphabetic-item` and rewrote the row note to say a PIC A
   TEST-NUMVAL-F argument is ADMITTED at 2002, but no case witnesses it (test-ref is still `g2-testnumvalf-argument-classes`;
   `pb5615-alphabetic-operands-2002` exercises TEST-NUMVAL, not TEST-NUMVAL-F). Add the witness or revise the note.

## Adjudicated 2026-11-23 (wave 20262150 group C)

Each lead re-probed on a build of main 7ea61d2e85 (`run_probe.py`, scratch `w20262150c`), each citation checked with `cite.py --check`.

1. **File-control clause operands and PIC A at 2002: a defect, fixed under PB5871.** §2002:8.5.2.1's second sentence is not limited to
   statement operands (see PB5871's ruling). Fixed at the root, `ItemCategory`'s DataItem overloads take the edition; goldens listed in PB5871.
2. **STRING sender PIC A at 2014/2023: not a defect, STRING is right.** §2023:14.9.43.3 SR1 (and §2002:14.8.39.2 SR1) require the identifiers to be
   "described implicitly or explicitly as usage display or national", a USAGE rule; SR8 even admits an elementary numeric integer sender. A
   PIC A item is usage display. UNSTRING's SR2 (§2023:14.9.48.3) is worded in CATEGORY, hence its refusal. Golden
   `14.9.43-STRING/pb6073-string-alphabetic-sender` (accepted at 2002, 2014 and 2023) pins STRING's acceptance beside the UNSTRING refusal
   `pb5615-alphabetic-operands-refused`.
3. **DISPLAY of `PIC 99 COMP-5 VALUE 4` printing `004`: not a defect, the recorded implementor choice.** §2023:14.9.11.4 GR1 leaves "any
   conversion of data" to the implementor; `docs/conformance/7/DOC-A.1-56.md` records that a BINARY-CAPACITY item (COMP-5) shows its CONTAINER's
   digits (3 for one byte), the form GnuCOBOL 3.2.0 prints (kb/Work PB3990 measured `007` for `PIC 99 COMP-5 VALUE 7`). The output is that
   recorded form; no change.
4. **The COMP-5 container golden's citation: fixed.** `pb5607-string-pointer-binary-container` now credits the COMP-5 range to the implementor choice
   of `docs/conformance/7/DOC-A.1-208.md` and only BINARY-CHAR to §2023:13.18.60.4 GR12.
5. **`2002-AR-15.77.2-1` witness: added.** `15.77@2002-TEST-NUMVAL-F-FUNCTION/pb6073-testnumvalf-alphabetic-2002` (a PIC A argument is admitted, returns 1).

6. **Found on the way (gate 000003 RED):** `WarningSuppressionTests.TheTurnWarning_IsReportedWithoutTheOption` passed only on a cold compiled-program
   cache: `CompiledProgramCache.StoredDiagnostic` did not store a record's catalog `Descriptor`, so any cache hit handed the test a record with
   `Descriptor == null` (the second gate of a worktree failed it). Fixed at the root: the entry stores the descriptor's stable id and a hit resolves it
   from `DiagnosticCatalog.All`, `FormatVersion` 6.
