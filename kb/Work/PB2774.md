**Evidence:** Pin build. CallEmitter's ReturningDelivery (ProgramEmitter.cs:694-713) passes no NumProfile for a USAGE INDEX returning item, so StoreReturn(CobolArg?, long) reaches StoreReturnNum's FitToReceiver(value.ToString(), r) (CallAbi.cs:1223) only when the RECEIVER also has no numeric profile, i.e. a non-index receiver. Probe cr2.cob: CR2SUB 'PROCEDURE DIVISION RETURNING V' with 01 V USAGE INDEX holding -1 (SET X TO 1, SET X DOWN BY 2, SET V TO X); CR2 'CALL "CR2SUB" RETURNING R' with 01 R PIC X(4). Generated: CobolArgAdapt.StoreReturn(__ret, V). Invariant host run prints '[-1  ]'. The same dll run from pwsh with CultureInfo.CurrentCulture = sv-SE (NegativeSign U+2212) prints '[U+2212 1 space space]'. But that pair violates §14.8.3.3 2) (cite.py --check OK: 'If the sending operand is not an object reference, the receiving operand shall have the same ALIGN, BLANK WHEN ZERO, DYNAMIC LENGTH, JUSTIFIED, PICTURE, SIGN, and USAGE clauses'), and §14.9.4.4 GR3 d) (cite.py --check OK) only defines EC-PROGRAM-ARG-MISMATCH when checking is enabled; unchecked, the content is unspecified. A conforming USAGE INDEX receiver takes the native-cell arm (WriteNumericCell) and never formats text. The UInt128 leg (CallAbi.cs:1171) formats an unsigned value, which has no culture-dependent character. The Int128.TryParse sibling (CallAbi.cs:1287) parses with the current culture, but .NET accepts hyphen-minus for cultures whose sign is U+2212, so it is not a demonstrated difference either. Not fixed on main (the code is unchanged in kind).
