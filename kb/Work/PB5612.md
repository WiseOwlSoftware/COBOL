# PB5612 - at --std 2002 a fatal EC-SORT-MERGE-FILE-OPEN on MERGE whose declarative completes normally lets the run unit continue

**Sites:**
- `src/WiseOwl.Cobol.Runtime/IO/CobolSort.cs#RaisedByTheStatement` (and the dispatch that reads RaisedBySortMerge)
- `docs/conformance/3/D-SMA.md` (b)

**Mechanism.** CobolSort.RaisedByTheStatement marks the SORT/MERGE statement's own raises so the 2023-only rule §2023:14.6.13.1.3 2) ('If the executed statement is a MERGE or SORT statement, then the rules for those statements apply') decides the disposition (D-SMA (b)) at every edition. 2002's fatal-exception procedure has no such item: a normally completing declarative terminates the run unit abnormally.

**Inventory.** No inventory row is claimed (`inventory_rows` is empty). adjacent rows 2002-GR-13.16.41.3-14 and -19 (refuter: DOUBTFUL on this same fatal-procedure difference); the governing 2002 text is §2002:14.5.12.1.2, a pending clause (PB5584).

**Rules (each citation checked with `python scripts/spec/cite.py --check`, verdict OK).**

- `§2002:14.8.23.3 GR7`: "the EC-SORT-MERGE-FILE-OPEN exception condition is set to exist and the execution of the MERGE statement terminates"
- `§2002:14.5.12.1.2`: "If execution of the declarative completes normally the execution of the run unit is terminated abnormally"
