# PB1250 — LANDED

## Landed (wave 1012, group F)

Reproduced (sr5.cob: `ADD 1 TO P-X`, `MOVE 3 TO P-X(1:1)` compiled clean). §13.7.3 SR5 is one arm of `ExpressionBinder.ReceivingPlaceBar`, the receiving-operand prohibition table every statement's receiver already asks (and §8.4.3.2.4 GR5's BY-CONTENT choice for an argument asks through `PermitsReceiving`): `DataBinder.IsFunctionFormal(place.Item)` is COBOLNET2747. The facts come from the same `SealLinkageRules` call as PB1249's (the function's formal items). Determination: the parameter is barred in any reference form (whole, or reference-modified: the note's own `P-X(1:1)` repro); an item SUBORDINATE to a group parameter is not "a formal parameter of a function" (the same clause's SR4 b) writes "subordinate to an operand of the USING phrase" when it means one), so it stays a legal receiver; the RETURNING item is no formal parameter. Witnesses: 2002/pb1250_function_formal_read_only (reads the formals, stores into RETURNING and a WORKING-STORAGE copy), negatives pb1250-function-formal-arithmetic-receiver and -refmod-receiver.

**Existing nets that broke, and were repaired (the standard decides, not the nets).** Six goldens and one differential test stored into a FUNCTION's formal, which SR5 forbids: `udf_by_value`, `udf_arg_order`, `udf_nested_args`, `pb1115_function_objref_conforming`, `pb1418_function_argument_manner` and `AcceptDifferentialTests.Device_AnyLengthFunctionFormal_TransfersTheArgumentsSize`. Each keeps its leg: the function now changes the argument's storage through an EXTERNAL item the caller describes too, and the formal (which occupies that storage, §14.2.3 GR8) reads the change, so BY REFERENCE versus BY CONTENT / BY VALUE is still observable and the argument-order legs still fail on a late read. `udf_by_value`'s `A1` is now 9999 (the function changed the caller's WS-A through the EXTERNAL item while the BY VALUE copy kept 7); `pb1115` lost its `A=NULL` line, since a SET of the formal is the illegal store and a BY REFERENCE crossing of an object reference is not observable without it. `pb1216_recursive_initial_pointer_lifetime` (PB1249's side) used a LINKAGE item as scratch (`OUTER-P`); it is LOCAL-STORAGE now.

**Found and fixed while repairing them (I9).** An EXTERNAL data item used as a SUBSCRIPT (`E (EXT-I)`) emitted its bare C# name and the backend refused the program with CS0103: `ReferenceResolver.HasPositionOverload` admitted a Tier-B class member (an EXTERNAL or BASED item, an ADDRESS-OF-taken record, a REDEFINES view), which owns no field of its own name. It now routes such an item to the D18 read through its place. Witness: `conformance:85/pb1250_external_item_subscript`.
