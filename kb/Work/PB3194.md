# PB3194 — the Linux gate's snapshots fill the WSL disk

> ⚙ **flags:** process-only. Blocks every landing while the distro is down.

Found by the enqueue unit, 2026-10-15 (filed by the clerk).

**Sites:** `scripts/linux-gate.sh` (the gate's footprint: `reap_gates`, `check_disk`, `begin_gate`, `remove_gate`,
`on_signal`, and the self-test arms that pin them) · `scripts/run_gate_legs.py` (`NOT_RUN_CAUSES`: the `disk` cause,
ENVIRONMENT) · `docs/rearchitecture/DESIGN-test-build-ci.md` §3.15 · the %TEMP% siblings the sweep found.

**Mechanism.** `scripts/linux-gate.sh` clones each gated tree into `~/linux-gate/<basename of tree>` (line ~181, `snap="$HOME/linux-gate/$(basename "$tree")"`) plus a `<snap>.guard-tmp` directory (line ~237), and removes a snapshot only when the SAME tree is gated again (`rm -rf "$snap"` before the clone). Nothing removes it when the worktree is pruned (`scripts/prune_worktrees.py` has no `linux-gate` reference), and the script never checks free space before a leg.

**Evidence** (2026-10-15). `~/linux-gate` held 345 entries; the distro's ext4 (`/dev/sdd`, 251 G, a 256 GB vhdx at `C:\Users\brent\AppData\Local\Packages\CanonicalGroupLimited.Ubuntu_79rhkp1fndgsc\LocalState\ext4.vhdx`, 219 GB on the host) stood at 211 G used. Concurrent landing gates at 20:39-21:10Z failed with `No space left on device` (guard leg: `/home/brent/linux-gate/wf_c0ed6078-78e-8.guard-tmp/gf_results.txt: No space left on device`; conformance 2,919 of 11,724 failed in one run). The next start failed `The distribution failed to start. Error code: 28` (ENOSPC). From then on WSL reports `An error occurred mounting the distribution disk, it was mounted read-only as a fallback` (`/dev/sdd ... ext4 (ro,...,errors=remount-ro)`), so every Linux gate ends `NOT RUN (could not clone HEAD ...)`.

**Landings this stopped:** worktree-wf_c0ed6078-78e-8, -f560587e-74d-1, -74d-2, -74d-8, -d6f41ebf-faa-4, -faa-5, -faa-10, -9b740cf9-198-4 (logs `E:\COBOL-coord\logs\land-lane-<branch>-20261015T2*.log`).

**Fix direction** (for an implementer, not designed here). The snapshot is a per-gate artifact, so delete it and its guard-tmp when the gate ends, or at the latest when `prune_worktrees.py --apply` removes the worktree. Add a free-space precheck to `linux-gate.sh` that ends `NOT RUN (WSL disk: N GB free, need M)` loudly before any leg. Pin both with a drift test. Recovery of the existing disk (reclaiming the 345 entries, the read-only remount, shrinking the vhdx) is the owner's hands-on step: the owner runs WSL changes by hand.

This is a CI-invariant note (PB1957 family): a host-capacity failure must never reach a gate as a red, and a red that says `No space left on device` mid-leg looks like 2,919 test failures.

## Witness 2026-10-19 (wave 1129 group D, PB3396): inode exhaustion

Added by the enqueue clerk. `/home/brent/linux-gate` held 430 clone directories (branch and `.guard-tmp`, about 35k files
each); the WSL filesystem's INODES reached 100% with 19G free, and `scripts/linux-gate.sh` answered NOT RUN ("No space left
on device" at the clone). The group removed clones untouched for 12 hours (400 directories; inodes 13%). The free-space
precheck in the fix direction must therefore also test inodes (`df -i`), and the prune step may be by age or count.

## Landing

Re-probed 2026-10-23 21:10 PDT on WSL: `~/linux-gate` held 42 entries (21 clones and their `.guard-tmp`), 2,421,479
inodes used (15 %), 45 G. The branch's own Linux gate (HEAD 45bd416c0) reaped 16 leftovers older than 3 h at its start,
built, ran every leg GREEN, and removed its own `pb3194.<pid>` directory at its end: 26 entries, 1,644,169 inodes (10 %),
36 G afterwards. The 26 left are pre-mechanism clones younger than 3 h; the next gates reap them as they age.

The `%TEMP%` sweep found the same leak on Windows: self-tests left 7,359 scratch directories (0.75 GB, read-only git
objects that `shutil.rmtree(..., ignore_errors=True)` silently could not delete, and three self-tests that removed
nothing). Fixed in the same change through one fixture; the 7,359 ended ones were removed by hand.

- `scripts/linux-gate.sh#begin_gate` - the gate's own directory `~/linux-gate/<tree>.<pid>/` (clone, `guard-tmp`,
  `owner` = pid + start time) and its removal on every exit path (`remove_gate` from the EXIT trap, `on_signal` for
  HUP/INT/TERM, which ends the legs' process trees first). Trap: bash runs a trap only after a FOREGROUND command
  returns, so a long step must run in the background and be `wait`ed (the build is); inside `$( )` `$BASHPID` is the
  subshell's, so capture it first.
- `scripts/linux-gate.sh#reap_gates` / `#check_disk` - the start: an ended gate's directory goes at once, a
  pre-mechanism one when it is this tree's or older than `LEGACY_MAX_AGE_S`; then `NOT RUN [disk]` below
  `MIN_FREE_INODES` / `MIN_FREE_KB`. Reuse `proc_field` for any `/proc/<pid>/stat` read (the command name may hold
  spaces). Trap: Cygwin's `/proc` costs ~0.5 s a read, so the signal arm of the self-test runs on Linux only.
- `scripts/run_gate_legs.py#NOT_RUN_CAUSES` - `disk`, ENVIRONMENT.
- `scripts/scratch_repo.py#scratch_dir` / `#remove_tree` - THE way a self-test makes and removes its scratch (atexit
  removal; read-only entries made writable; failures printed). The audit's SCRATCH arm (`_scratch_leak`) finds a
  self-test's `tempfile.mkdtemp` outside a directory it owns and any `rmtree(ignore_errors=True)` in self-test code.
