# PB2841 — LANDED — CONTINUE AFTER screens every non-finite double as EC-DATA-NOT-FINITE

Found by the train 1047 lander's review (step 5b) and filed by it, 2026-10-08 20:54 PDT. Reviewer finding on cluster 45G (PB2697+PB2647), PLAUSIBLE (traced in code, not run); outside 45G's diff.

## Mechanism
`src/Cobol.Net.Runtime/Control/CobolTiming.cs:42-46` sends every non-finite double to `FloatNotFiniteError`. Table 12
and §14.6.13.2 item 3 limit EC-DATA-NOT-FINITE to a STANDARD floating-point usage; PB2647's determination (an
infinity is a number in ISO/IEC 60559, a NaN is not) sends −∞ to a statement's less-than-zero leg.

## Repro to build
`CONTINUE AFTER F SECONDS` with F FLOAT-LONG holding −∞ or NaN through a REDEFINES (the shape of the golden
`2023/pb2647_set_size_not_finite`), `>>TURN EC-DATA-NOT-FINITE CHECKING ON`. Observed (by trace): fatal
EC-DATA-NOT-FINITE. Expected: −∞ takes CONTINUE's less-than-zero rule (`checkLessThanZero`); NaN takes the rule the
statement gives a value that is not a number.

## Fix shape
An `IsNaN` / `< 0` / `> max` branch mirroring `CobolDynString.SetSize`, plus one golden.

## Landed (wave 1052 group H, 2026-10-10)

Re-probed on this worktree's build (`E:/COBOL-coord/scratch/w1052h/p1.cob`): `CONTINUE AFTER F SECONDS` with F a
FLOAT-LONG holding -infinity ended `abnormal run-unit termination: EC-DATA-NOT-FINITE (fatal): CONTINUE AFTER interval
is -inf`. A FLOAT-BINARY-64 (standard) item in the same program raised from `CobolFloat.Sending` at the READ, with the
read's own message, so the screen in `CobolTiming.ContinueAfter(double, bool)` was redundant for the standard usage and
wrong for the others.

**Fix.** The non-finite screen is removed; the sign test and `CobolNum.PositionOf(double)` already give every non-finite
value the rule of its kind (PB2647's determination: an infinity is a number, a NaN is not). -infinity is a value below
zero (GR1 a-c), +infinity a number above the maximum (suspends 86,400 s, like 1E30) and a NaN a zero interval (the
disposition `CobolFloat.ToScaled` gives a NaN landing in a fixed-point item): no suspension, no condition. Cites checked
with `cite.py --check`: 14.9.9.4 (GR1) and 14.6.13.2 item 3. Sibling sweep: `FloatNotFiniteError` has exactly two
callers, both in `CobolFloat.Sending` (the read-site raise); every other double-taking runtime entry point
(`SetSize`, `SetAmount.Land`, `CobolPtr.AllocateReal`, `ReportWriter.VaryingInteger`) raises its own statement's condition.
The old unit test `NaNInterval_DataNotFiniteChecking_IsTheFatal` called `FloatNotFiniteError` directly and never reached
`ContinueAfter`, so it could not have failed; it is replaced by `NonFiniteInterval_TakesTheRuleOfItsKind_NeverEcDataNotFinite`.
Sites: `src/Cobol.Net.Runtime/Control/CobolTiming.cs#ContinueAfter(double,bool)`; docs/CONFORMANCE.md DOC-A.1-39.
Witnesses: golden `conformance:2023/pb2841_continue_after_non_finite`, negative
`conformance/negative/pb2841-continue-after-non-finite-below-2023`. `CobolDynString.cs` needed no change (PB2647 landed it).
