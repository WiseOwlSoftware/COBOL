# PB2678 — spurious code sites in the campaign planner's dispatch specs

## What happened (wave 1041, 2026-10-08)

Every one of wave 1041's rendered specs `E:\COBOL-coord\scratch\msg-w1041-{b..h}.txt` names, for a census Delete note
that declares ONE site, two more:

```
THE GROUP IS ONE ROOT: src/Cobol.Net.Frontend/Common/SourceLineMap.cs (also scripts/arch/compare_oracle.py,
tests/Cobol.Net.Benchmarks/BenchmarkDotNet.Artifacts/results/CobolNet.Benchmarks.Collation.CacheBenchmarks-report-github.md)
```

All five implementers of train 1041 (PB2168, PB2169, PB2179, PB2187, PB2189/PB2190) reported the two extra sites as
not sites, and group B's report raised it as a lead. Neither path appears in any of those notes' **Sites** blocks.

## Mechanism (two, both in the clustering index)

1. **An ignored build artifact is indexed.** `plan_wave.py` (`--cluster`, line ~402) builds its index with
   `fix_clusters.source_index(roots, exts, …)` over `model_rules.json` `campaign.src`
   (`src, tests, scripts, .github, docs`) and `campaign.ext` (which includes `.md`).
   `source_index` (`tools/claude-skills/skills/agent-fleet/references/fix_clusters.py:73`) walks with `rglob` and
   skips only `ALWAYS_SKIPPED` and `exclude_dir`, so it indexes
   `tests/Cobol.Net.Benchmarks/BenchmarkDotNet.Artifacts/results/*.md`, which `.gitignore:140`
   (`BenchmarkDotNet.Artifacts/`) ignores and only exists in a checkout where someone ran the benchmarks. Its stem
   `CobolNet.Benchmarks.Collation.CacheBenchmarks-report-github` keys the index under its base `CobolNet`. Then
   `fix_clusters.sites` (line ~108, the `Type.Member` arm) reads the census note's
   `CobolNet.Frontend.Common.SourceLineMap` as `CobolNet` + `.Frontend` and scores `idx["CobolNet"][0]`, the results
   file. This is the same mechanism `campaign._why` records for project files (`Cobol.Net.Cli.csproj`, PB2108), which
   was answered by dropping the extension rather than by indexing only tracked files, so it came back through `.md`.
2. **The wave contract names a script.** Every census-filed note carries "the §4 oracle
   (`python scripts/arch/compare_oracle.py`) proves neutrality" (`file_census_notes.py`'s template), and `.py` is a
   campaign extension, so `scripts/arch/compare_oracle.py` scores as a site of EVERY R3 note. Beyond the noise in the
   spec, it is a shared file in every R3 group's declared set, which the file-set collision check
   (`plan_wave.py` `file_set_collisions`) and `landing_check.py` read.

## Fix shape

- Index the TRACKED tree only (`git ls-files` under the roots, as `work.slice_file_set` already does through
  `tracked_paths`, PB1957 2026-10-07), so no build output or stray file can ever be a site; pair it with a test in
  `scripts/orchestrator/test_plan_wave.py` that plants an ignored `CobolNet.X.md` and asserts it is not a site.
- Read code sites from a note's **Sites** block when it has one (`work.note_sites`), so the contract boilerplate is not
  scanned; or have the clusterer ignore the contract paragraph.
- Repro: `python scripts/orchestrator/plan_wave.py --cluster PB2119 --dry-run` in `E:\COBOL` (where the benchmark
  results exist) and read any Delete group's ROOT line.
