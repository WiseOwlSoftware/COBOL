# PB657 — OPEN — the right verdict, reported from the wrong place

Found 2026-09-05 by the `PB300` implementer (report §"New defects" D3). PB137 had recorded the same shape ("the
reference position is structurally unparseable") and reshaped `user-word-commit-2023`'s probe to the declaration
screen to avoid it; PB300's generated `reservedGatedWord` made the DECLARATION draw the targeted §8.9 diagnostic
for every gated word, and left the REFERENCE as it was.

## The mechanism

A word §8.9 reserves at edition E is deliberately not a `cobolWord` at E (`OK §8.9` — "Reserved words shall not be
used as system-names or user-defined words", §8.3.2.4.1), so a reference to it in a statement has no parse; ANTLR
reports `COBOL0001` at the reference token, and because parse errors precede the conformance pass, the declaration's
COBOLNET0901 — which names the rule and the edition — is never reached. The program is correctly rejected; the user
reads a syntax error in the PROCEDURE DIVISION for a mistake in the DATA DIVISION.

## Fix shape

Error recovery, not the word slot: when a declaration has drawn 0901 for a gated word (or would, at this edition),
the parser's error strategy (`CobolParserCoreBase`) treats a later occurrence of that same token in a
reference position as a recoverable user-word and lets the conformance pass report the one 0901 with the
declaration's location; equivalently, run the reservation report from a pre-pass over the declaration entries so
it is emitted even when the parse of the PROCEDURE DIVISION fails. Negative goldens for COMMIT, CRT and PADDING at
the reserving edition asserting COBOLNET0901 (declaration line) and NO COBOL0001; the `.err` substring is the
assertion. Do not admit the word to `cobolWord` at the reserving edition to "fix" this — that would silently accept
the illegal program.
