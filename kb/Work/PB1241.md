# PB1241 — OPEN

## Measured

**file-section** — ValueInitializer.InitializerFrom's dynamic-length arm applies the VALUE clause to set the initial-state length of EVERY dynamic-length elementary item regardless of data-division section, citing only the general §8.6.4 sentence; §13.4.4 GR1 overrides it for the file section (VALUE ignored except in INITIALIZE; initial length zero). File-section records emit as Program fields through the same initial-state path as WORKING-STORAGE, so a file-section dynamic-length item with a VALUE clause starts at the VALUE's length.

- **Repro:** --std 2023 (same at 2014): SELECT OUTF ASSIGN TO "fsp4.dat" ORGANIZATION IS SEQUENTIAL. ... FILE SECTION. FD OUTF. 01 R. 05 D PIC X DYNAMIC LENGTH VALUE "HELLO". 05 E PIC X DYNAMIC LENGTH. PROCEDURE DIVISION. DISPLAY "LEN-D=" FUNCTION LENGTH(D) " LEN-E=" FUNCTION LENGTH(E). (probe/file-section/p4.cob)
- **Expected (spec):** LEN-D=0 LEN-E=0 before any INITIALIZE: §13.4.4 1) 'A data-item format or table format VALUE clause specified in the file section is ignored except in the execution of the INITIALIZE statement. ... The initial length of a dynamic-length elementary item is zero.' After INITIALIZE R ALL TO VALUE, LEN-D=5 D=[HELLO] (which the compiler already produces).
- **Observed:** Pinned cobol.exe prints LEN-D=5 LEN-E=0 at 2023 and 2014; the VALUE was applied at initial state. Fixed-length file-section items receiving their VALUE at initial state is admissible (their initial value is undefined, §13.18.63.4 GR2 / Annex undefined-item 12), but the dynamic-length LENGTH is defined as zero, so this is observable and wrong. The fix belongs at the one initial-state reader (section-aware: file-section items take no VALUE at initial state), not per consumer; sweep INITIAL-program re-activation and CANCEL re-initialization, which reuse the same path.
- **Code site:** src/Cobol.Net.Compiler/CodeGen/DataDivision/ValueInitializer.cs#InitializerFrom (IsDynamicLength arm); src/Cobol.Net.Compiler/Binding/DataBinder.cs#BindFileSection (records emitted as Program fields like WORKING-STORAGE)
- **Clause (adjudicator):** §13.4.4 GR1 (cite.py --check OK); overrides §8.6.4 for the file section; corroborated by §13.18.63.4 GR2
