# PB5123 - at --std 85 an abbreviated combined relation condition with a logical NOT before >= or <= (A > B AND NOT >= C OR D) is refused (COBOL0001); 1985 reads NOT before any word that is not GREATER, >, LESS, <, EQUAL or = as a logical operator

**Sites:** none (not located: the record names the grammar's `comparisonOperator` rule, which kb/Work PB1034 narrowed to the 2023 printed set at every edition, and no file; the implementer locates it)

**Mechanism.** The 1985 rule reads NOT by the next word: if it is GREATER, >, LESS, <, EQUAL or =, NOT is part of the relational operator; otherwise it is a logical operator and the implied subject or operator is inserted, negating the relation. `>=` is not one of those six words (§1985:IV.2.1.7 lists it as its own special character word; §1985:VI.6.3.1.1 prints "IS >=" as a relational operator), so `A > B AND NOT >= C OR D` means ((A > B) AND (NOT (A >= C))) OR (A >= D). The grammar accepts a relational-operator after NOT only in the 2023 set, so the 1985 form does not parse. `IF A > B AND NOT <= C` is refused the same way. The refusal is edition-blind: --std 2023, where it is correct (§2023:8.8.4.12.2), reports the same COBOL0001. With T8 to T10 removed the draft compiles and prints T1 to T7 as expected.
