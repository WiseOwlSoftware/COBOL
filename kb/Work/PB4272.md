# PB4272 — make the ICodeGenBackend contract Roslyn-free

**Found:** Mythos session 2026-10-31, weighing the owner's proposed refactoring (each code generator in its own DLL
behind one interface). Owner priority: the backend seam work is to be done "asap" (PB2293). The requirement is a
direct-IL backend beside Roslyn (DESIGN.md §1.1); there is no C/C++ backend requirement.

**Sites:** `src/WiseOwl.Cobol.Compiler/CodeGen/ICodeGenBackend.cs:55` (`BackendArtifact`, `BackendOptions`,

**What is Roslyn-shaped today (read on main 2026-10-31).**
- `BackendArtifact(bool Success, IReadOnlyList<Diagnostic> Diagnostics, …)` (`ICodeGenBackend.cs:55`): the seam's
  result type is Roslyn's `Microsoft.CodeAnalysis.Diagnostic`, and `CompilerDriver.cs:214` filters it by
  `Microsoft.CodeAnalysis.DiagnosticSeverity`. A CIL backend would have to reference Roslyn to report an error.
- `BackendOptions.WriteSource` ("write the generated intermediate source (the .g.cs)", `ICodeGenBackend.cs:31-41`)
  has no meaning for a backend that emits no source.
- `BackendFactory.For(BackendId id, CSharpEmitter bindHost)` (`ICodeGenBackend.cs:82`): the factory takes the
  binder host, an "INTERIM SHAPE" its own comment says disappears when binding leaves the emitter (PB2293's leak L6).
- `DataItem.cs:1495-1496` uses `SyntaxFacts.IsIdentifierStartCharacter` and `SyntaxFacts.GetKeywordKind` to prefix
  a C# keyword with `@`: `@class` is C# SOURCE spelling, the CLR name is `class`, so a name the model stores is not
  yet the CLR name PB4265 says both backends must emit. `StatementBinder.cs:10` imports
  `Microsoft.CodeAnalysis.CSharp` into the binder.

**Fix direction.** A backend-neutral diagnostic record at the seam (code, severity, message, source location), with
the Roslyn backend translating its own `Diagnostic`s into it and `CompilerDriver` reading only the neutral type;
`WriteSource` becomes a Roslyn-backend option, not a seam option; `BackendFactory.For` loses `bindHost` once PB2293's
leaks are gone; the model stores the CLR name and the Roslyn backend alone adds `@` when it renders a C# keyword
(with PB4265's rename); the binder drops its Roslyn import. Every caller changes in the same change (CLAUDE.md rule 4).
PB4273 depends on this: a backend assembly that must reference Roslyn to implement the interface is no seam.

**Landed (wave 20261800 C, 2026-11-01).** Re-probed on 2e48863d5: the four Roslyn uses outside the Roslyn backend were
there, and a fifth the note did not name, `CsNames.CSharpReservedKeywords` (`Binding/Model/CsNames.cs:88`, PB4265's
seed, read from `SyntaxFacts.GetReservedKeywordKinds`). The `@keyword` half was already gone (PB4265: an allocated CLR
name is never a C# keyword), leaving the identifier character classes as the model's one Roslyn question.
- The seam's diagnostic is `BackendDiagnostic(Code, Severity, Message, SourceLocation? Location)`: the compiler's one
  severity and one diagnostic line (`Diagnostic.Render`, which the front end's `Diagnostic.ToString` now calls too). The
  Roslyn backend translates its own (`RoslynBackend.Neutral`: the mapped position Roslyn's formatter prints, or none; a
  hidden diagnostic is not carried), and `CompilerDriver` reads `IsError`. The edges file allows
  `compiler.codegen -> frontend.diagnostics` for it (DESIGN-architecture-review §8.1).
- `BackendOptions.WriteSource` is deleted: no caller ever passed false, and the `.g.cs` is the Roslyn backend's own
  artifact, always written.
- The model states what it used to ask Roslyn: `CsNames.IsIdentifierStartCharacter`/`IsIdentifierPartCharacter` (the
  CLS and C# identifier classes) and the 81 reserved keywords. `RoslynFreeSeamDriftTests` pins the classes to
  `SyntaxFacts` for all 65,536 UTF-16 code units, pins the neutral diagnostics' text to Roslyn's `Diagnostic.ToString`
  (an in-source error and warning, an error with no position), and refuses any `Microsoft.CodeAnalysis` use in a
  compiler source outside `CodeGen/` or in `CodeGen/ICodeGenBackend.cs`; `CsNameReservationDriftTests` now pins the
  keyword set equal to Roslyn's.
- `StatementBinder.cs`'s Roslyn import was unused and is deleted.
- Behavior-neutral: `scripts/arch/compare_oracle.py` IDENTICAL over 15,712 cases against 2e48863d5.
- Not done here: `BackendFactory.For`'s `bindHost` parameter. `CSharpEmitter` holds no bind state (its `Bind` and
  `EmitBound` forward to `BinderDriver` and `ProgramEmitter`), so the parameter and the shim go together, and that is
  PB2290's mechanism, blocked by PB2103.
