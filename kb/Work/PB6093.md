# PB6093 - spec-reconcile launches its fleet before it knows a page renders

**Observed.** The worktree `E:/COBOL-wt/md85-pass3` was made with `git worktree add` and never ran
`git submodule update --init specs-private`, so the licensed PDF was absent. `.claude/workflows/spec-reconcile.js`
validated its arguments and dispatched all 20 compare agents. Each one hit the same render failure in its STEP 1,
reported FATAL and read nothing: 1.02M subagent tokens, 0 pages compared.

**Fix.** Before it dispatches the Compare phase, the workflow runs one cheap preflight agent that renders the run's
first page into `workDir` and confirms the image and its markdown slice exist. A failure ends the run with the
missing input named (the submodule, the PDF path, the page) and dispatches nothing. Better still, the render step
itself (the script STEP 1 calls) names the uninitialised submodule and its fix command in its error, so the one agent
that fails says why.

**Handled by hand.** `git submodule update --init specs-private` in the worktree, one probe render of page 227, then
the relaunch (wf_4dd43334-725) read all 240 pilot pages.
