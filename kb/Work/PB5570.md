# PB5570 - a WRITE with no ADVANCING phrase to an EXTERNAL sequential file whose ADVANCING writes are in another program writes a bare record (P1 and P2 share a line): the connector learns the file is positioned only when that program is activated

**Sites:** `src/WiseOwl.Cobol.Runtime/IO/FileRegistry.cs` (`FileRegistry.Register`); `src/WiseOwl.Cobol.Runtime/IO/SequentialConnector.cs` (`SequentialConnector.AdvancingDeclared`, `SequentialConnector.SupportsVerticalPositioning`)

**Mechanism.** "If the ADVANCING phrase is not used, automatic advancing will be provided by the implementor to act as if the user had specified AFTER ADVANCING 1 LINE." kb/Work PB5201 (landed) made a plain WRITE act as AFTER ADVANCING 1 LINE on a file that has LINAGE or to which the program writes an ADVANCING phrase (`SequentialConnector.SupportsVerticalPositioning`, fed by `AdvancingDeclared`). The compile-time fact reaches the connector per describing program: `FileRegistry.Register` sets `AdvancingDeclared` for a later describer of an EXTERNAL connector only when that program is activated. So when the opening program writes only plain records and a second program of the run unit, describing the same EXTERNAL file, writes with ADVANCING, the plain WRITEs made before the second program first runs are bare records with no line advance, and the ones after it are advanced. The same shape with an internal GLOBAL file (`nest.cob`) advances every record. PB5201's own decision note names this shape ("AAA BBB share a line") as what breaks GR16.
