**Landed (wave 20261858, group A).** Re-probed on the branch first: every leg above reproduced (OMAXF 1, OMINF 1, MODP / REMP 0, SUMF / RNGF
`…000100000`). The root is one intake: under native arithmetic every call `RenderWide` declines (an SDIDI argument beside the wide one, a binary64
beside a selection, work past its 77-digit bound, an alignment-escaping list) reaches `RenderDec`, whose arms took each argument through
`DecArgList`, a wide one as its round-to-odd image. Under native arithmetic those arms now take each argument as its EXACT value (`CobolExact`)
and evaluate with the `…Exact` bodies: a selection orders the exact values (`CobolExact.Compare`, which `FunctionValueField`'s mixed order now
shares, so DISPLAY and an operand select the same argument) and SUM, RANGE, MEAN, MEDIAN, MIDRANGE, MOD and REM form their value on the 256-bit wide
form and round it once to the SDIDI; values the wide form cannot align take the SDIDI body over the images (DOC-A.1-123 past 77 digits). No
`BigInteger` (DESIGN §1.2 invariant 2). Standard modes keep the Dec bodies. DOC-A.1-123's image sentence is re-decided (rule 1, GnuCOBOL exact).

P - 2000, 9.98999999999999998002E38)` 2000, MEAN / MIDRANGE / MEDIAN 499.5 (`conformance:cases/15.4.1-Numeric-and-integer-functions/pb4568_wide_argument_beside_sdidi`,
`unit:CobolExactIntrinsicsTests`). Still open, by PB4570's carrier question: the SDIDI is the returned-value carrier of such a call, so a value
of more than 34 digits (`SUM (P, 1, 2.0E0)`, MAX's 39-digit content as an operand) is rounded there once where GnuCOBOL keeps every digit.

**Observed.** With `P = BIG * BIG * K3` (39 digits), when any argument beside the wide one is SDIDI-carried or binary64, `RenderWide` returns null and `RenderDec` takes the
wide argument as its round-to-odd image through `DecArgList`. GnuCOBOL's answer in brackets:
- `ORD-MAX (P - 1, P, F2)` with F2 `COMP-2`: 1 [2]. `ORD-MAX (P - 1, P, 2.0E0)`: 1 [2]. `ORD-MAX (P - 1, P, 2 ** 0.5)`: 1 [2]. `ORD-MAX (P - 1, P, 2)`: 2 [2].
  Meanwhile the same compiler's `IF P - 1 < P` is TRUE. §15.71.4 2) ties the ordering to the simple-condition rules, so the answer contradicts the compiler's own relation.
- `ORD-MIN (P, P - 1, 1.0E50)`: 1 [2].
- `MOD (P, 2 ** 10)`: 0 [999], and `REM` the same, while `MOD (P, N)` with N = 1024 is 999. DOC-A.1-123 says MOD/REM "refuse loudly rather than answer an
  approximation"; here they answer 0 silently.
- `SUM (P, 1, 2.0E0)` is ...000100000 [...001002] and `RANGE (P - 1, P, 2.0E0)` is ...000100000 [...000997].
- MAX, MIN and MEDIAN DISPLAY exactly (`FunctionValueField`) but return the image as an operand.
