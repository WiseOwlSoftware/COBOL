# PB3747 — lock liveness accepts any live image for the holder's pid

**Sites:** `scripts/orchestrator/coord.py#loop_state`, `scripts/prune_worktrees.py#live_lock`, `scripts/orchestrator/coord.py#process_name`.

PB3113 made the driver-file lock check the holder's process command. Two siblings still accept ANY live image for a lock holder's pid: `coord.loop_state` (the loop's lock) and `prune_worktrees.live_lock` (a worktree lock). A dead holder's pid reused by another process reads as a live holder, and the lock is kept forever (the failure PB3032 records for `orchestrate.ps1`). Fix: reuse `coord.process_command` (the helper PB3113 adds in PR #580) to compare the holder's command, not only its liveness; sweep every other `process_name` caller for the same shortcut. Not fixed in PB3113's slice.
