# PB4745 — Messaging slice S5: server activation (ServerActivation, start/<NAME>.lock, the servers field)

A slice of `docs/rearchitecture/DESIGN-message-control.md` (§5, §9 S5), which the owner approved on 2026-11-04 (the owner, 2026-11-04: "yes, both approved" (the transports) and "Yes" (both documents and Q1-Q9 as recommended)). Build exactly what that section and the slice's entry say, with its goldens, tests and doc changes in the same landing.

**Prerequisites:** PB4744.

**Landed.** The requestor's side of `docs/rearchitecture/DESIGN-message-control.md` §5.4.5 and Q9. `mcs.json`'s `servers` member (`name`, `start` as a command line or an argument array, `maxLength`) is read by `ServerDefinitions` when the peer starts (so `maxLength` is live in production too: before this slice nothing but a test supplied a `ServerDefinition`), an unusable file is EC-MCS-IMP. `ServerActivation.Run` takes `start/<N>.lock` through `HostRegionLocks.McsStartByte`, enumerates again and, finding no server, `ServerActivation.Launch`es the command with `WISEOWL_COBOL_MCS`, `_SERVER`, `_NOTIFY` and `_LOG`, waiting for the server's connection to `n/<r>` or the process's end (EC-MCS-IMP). The process entry routes a started server's console to `WISEOWL_COBOL_MCS_LOG` (`StandardStreams.EnsureUtf8`). The conformance suite's wiseowl-only `servers` header field (Q9) starts the declared units through the same `Launch` (`RunningServers`).
