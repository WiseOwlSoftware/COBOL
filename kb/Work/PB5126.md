# PB5126 - at --std 85 library text that itself contains a COPY statement is processed (START OUTER INNER END); 1985 forbids a COPY statement in the text produced by processing a COPY

**Sites:** `src/WiseOwl.Cobol.Frontend/Preprocessor/CopyProcessor.cs` (`ResolveOneCopy`: the library text is asked for a COPY statement through the new constructs row `copy-nested-library-text-2002`, at the outer statement), `tests/version-matrix/constructs/copy-nested-library-text-2002.json`.

**Landed (2026-11-11).** At --std 85 the outer COPY draws COBOL0900 (the GR12 introduction gate); 2002 on is unchanged. Goldens: `1985-GR-XII_2_4-12`, `pb5126_nested_copy_two_levels`.

**Mechanism.** §1985:XII.2.4 GR12 (added by X3.23b-1993) forbids a COPY statement in the text produced by the complete processing of a COPY statement, so COPY g12outer. where g12outer.cpy holds COPY g12inner. must be refused at the outer COPY line. §2023:7.2.3.4 GR12 allows library text to hold a COPY statement when neither has a REPLACING phrase, and the compiler applies that at every edition. kb/Work PB1356 and R34 cover only the 2023 rules GR10/GR12/GR13, COBOL1640 fires only for nesting under REPLACING, and PB5085 is the word COPY as a REPLACING operand (§1985:XII.2.3 SR6): a neighbouring facet of the same 1985 principle, not this mechanism. The draft carries its library texts in a files member (text-name to file mapping is the implementor's).

**Found by.** The 1985 witness-drafting pass (kb/Work PB4995 item 3): each rule below is a witness program drafted from the 1985 text alone, run at `--std 85`, and its result differs from what the text requires (outcome MISMATCH). Harm and observed text are the record's; nothing here was re-derived.

**Inventory.** The traceability inventory carries no 1985 rows yet (PB5094: work.py refuses 1985 ids), so `inventory_rows` is empty; the row this note covers is the 1985 rule id listed below (catalog `docs/rearchitecture/spec-rule-catalog-1985.json`).

**Rules (1; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-GR-XII.2.4-12` - `§1985:XII.2.4 GR12` (record harm: under-rejects, slice-07): Checked quotation: "The text produced as a result of the complete processing of a COPY statement must not contain a COPY statement."

**Repro (`1985-GR-XII.2.4-12`, slice-07).** cobol --std 85 --source-format fixed --flag-extensions

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. G12NEST.
       PROCEDURE DIVISION.
       MAIN-P.
           DISPLAY "START".
           COPY g12outer.
           DISPLAY "END".
           STOP RUN.
```

Library text `g12outer.cpy` (working directory):

```cobol
           DISPLAY "OUTER".
           COPY g12inner.
```

Library text `g12inner.cpy` (working directory):

```cobol
           DISPLAY "INNER".
```

**Expected (from the 1985 text).** A diagnostic at line 6 (the one line of the source file that breaks the rule). The deciding words: "The text produced as a result of the complete processing of a COPY statement must not contain a COPY statement." (§1985:XII.2.4 GR12). The control copies g12inner, which holds no COPY statement, and compiles clean.

**Observed (copied from `1985-GR-XII.2.4-12`).** cobol.exe g12nest.cob --std 85 --source-format fixed --flag-extensions: exit 0, no diagnostic at all; the program runs and displays START / OUTER / INNER / END (the nested COPY was processed, as at --std 2023). The control compiles clean and displays START / INNER / END.
