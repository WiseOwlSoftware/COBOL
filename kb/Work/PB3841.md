# PB3841 — PB3829's landing left three descriptions stale

**Sites:** `docs/COBOLNET_NUMERIC_DESIGN.md`, `src/Cobol.Net.Compiler/CodeGen/Emit/NumericRenderer.cs#RenderFloatNative`, `src/Cobol.Net.Compiler/CodeGen/Roslyn/ReceiverContext.cs#FloatLandingDecision`, `src/Cobol.Net.Compiler/CodeGen/Roslyn/ReceiverContext.cs#FloatWorkingScale`

Read on origin/main 9e94246f6 (PR #657):

- `docs/COBOLNET_NUMERIC_DESIGN.md` near line 668 names the golden `15.10.4-Returned-value-rule/pb3829_rounded_bounded_returned_value`, which does not exist (the branch added `conformance-suite/cases/14.7.4-ROUNDED/pb3829_rounded_bounded_function_modes` and renamed `pb65_codomain_clamp` to `15.10.4-Returned-value-rule/pb65_bounded_returned_value_landing`). Near line 657 the same section still names the retired `2023/pb65_codomain_clamp` as the golden that moved.
- `NumericRenderer.cs` near line 1456, a Landed doc comment: "A float under NATIVE arithmetic stays binary64 - the consumer's own float arm applies (see `<see cref="FixedLane"/>` for the consumers that have none)". `FixedLane` was deleted by PB3829, so the cref dangles and the sentence points at a mechanism that no longer exists.
- `ReceiverContext.cs` near line 286, the `FloatLandingDecision` doc: "IT IS A THREE-ANSWER DECISION AND NOT A SCALE", while the `FloatLanding` doc PB3829 rewrote says there are exactly two answers. The `FloatWorkingScale` doc (near line 128) still calls it the working scale `CobolIntrinsics.FromDouble` uses, though after PB3829 `FromDouble` never lands at it (only the NUMVAL-F fixed-receiver arm reads it).

Sweep for siblings: every other doc or comment that names `FixedLane`, `FromDoubleBounded`, `IntrinsicCodomain`, `CodomainConst` or `pb65_codomain_clamp`.

## Acceptance

- The three sites describe the current two-answer FloatLanding and name goldens that exist; a grep for the deleted names over `src/`, `docs/` and `kb/Work/` finds only history lines marked as such.
- Fix the root cause, never simply making the diagnostic pass; be consistent with ourselves barring an explicit requirement differently.
