# PB61 — LANDED 2026-08-18 — LENGTH/BYTE-LENGTH bind-time folds mis-handled ref-mod, groups-with-ODO, dynamic-length and national literals

> ⚙ **flags:** wrong-answer, silent · **14 inventory rows** (triage 2026-08-09, probe+refute confirmed; the
> per-row mechanisms live in the triage record and each row's inventory notes)

> `IntrinsicBinder.BindLengthFold` / `BindByteLengthFold` fold at BIND time and their arm lists are
> incomplete: the ref-mod arm is missing (a `RefModPlace` operand falls through to the whole item's
> width), the group+ODO arm errors where SS15.50/SS15.14 define a runtime value, dynamic-length items
> return bound-time capacity, the national-literal arm folds `Math.Max(1, ...)` over the wrong unit, and
> `DataItem.ElementaryImageWidth` returns 0 for carrier categories. PHYSICAL landed on the LENGTH route
> only (two-arm; BYTE-LENGTH's catalog row lacks it). The grammar still has no groupUsage/GROUP-USAGE, so
> a bit group's boolean-length path is unreachable; a level-1 TYPEDEF is filed off RootItems so LENGTH OF
> a type-name mis-resolves; and the keyword-omitted depth-0-colon group arm routes wrong
> (SR-8.4.3.2.3-6 — shared with the FMT keyword-omitted family on PB63).
> **The fix**: enumerate the fold's arm matrix from the SS15.50/SS15.14 rule branches (never from the
> current arm list), route non-foldable shapes to runtime bodies, pin each branch with a golden.

### ✅ LANDED 2026-08-18 (DEVLOG 1296) — 14 of 14 rows adjudicated: 10 CONFORMS, 4 PARTIAL each naming its owner

> The arm lists were rewritten from the §15.50.4 / §15.14.4 rule branches (`BindLengthFamily` serves both
> functions; `LengthPositions` is the fixed fold; a type-name argument resolves from `DataBinder.TypeDecls`;
> PHYSICAL is consumed on both routes), a group with ANY runtime-length source beneath it goes to the ONE
> `VariableLengthGroupSum` (ODO extent as `BoundOdoExtent`, dynamic leaves, dynamic-capacity tables through a
> `CapacityRegisterPlace` — the register now minted for every dynamic table), and §8.4.3.2.3 SR6 is decided from
> the definition BEFORE any argument binds (`DefinitionPermitsArguments` / `Sr6ArgumentListError`; the
> catalog-driven `FunctionRefModSr6SweepTests`). Golden `pb61_length_byte_length_rule_branches` (one probe per
> rule branch), negatives `pb61-*`. Two green tests that held gaps open were corrected
> (`StagedLoudResidue_FailsLoud_NeverWrong`, `r03` rows 13/14/17 → 0).
> **PARTIAL rows and their owners:** RV-15.50.4-1 / RV-15.50.4-2 (the bit-group / national-group legs) → **PB79**
> (the GROUP-USAGE clause does not parse); RV-15.50.4-4 / RV-15.14.4-2 (the BASED-entry half of r4a/r2a) → **PB80**
> (a BASED ODO group is never wrapped as an ODO operand). The one shape the builder will not sum — a
> runtime-length item INSIDE a table element — stages loud with the shape in its message (the design doc names it).
