# PB5459 - a toolchain bump has no safe procedure while the orchestrator loop runs: between the host update and each branch's merge of the bumped main every gate stops `NOT RUN [toolchain]`, in both directions, and the refusal text tells a worker to reinstall tools

**Sites:** `scripts/gate.py` (`Host.toolchain` l.673-682, `reusable` l.1402-1406, the re-derive check l.1528), `scripts/toolchain.py` (`Tool.scopes` l.98-101), `scripts/orchestrator/enqueue.py` (`tested_locally` from l.724), `toolchain.env`

**Facts (toolchain worker's report, `E:\COBOL-coord\scratch\reports\toolchain-20261112-report.md`; the quoted code is a claim until the fixer re-reads it):**
- `scripts/gate.py` l.673-682 (`Host.toolchain`): `manifest = toolchain.load()`; `_, bad = toolchain.compare(manifest, "gate")`; a mismatch refuses the gate.
- `gh` is in the gate scope (`scripts/toolchain.py`, `Tool.scopes`, l.98-101); `uv` is host-only and never affects a gate.
- `gate.py` `reusable` (l.1402-1406) and the re-derive check (l.1528) refuse a record whose recorded toolchain differs.
- `enqueue.py` `tested_locally` (from l.724) reads recorded GREEN verdicts and has no toolchain check, so a landing on an existing GREEN record is not refused.

**Consequence.** The bump branch cannot get a GREEN record until the host has the new tools, and from that moment every other worktree on the old manifest is refused its gate until the bump has landed and that worktree has merged main. With a fleet in flight that is every implementer and finisher, for at least one merge-queue run. The refusal message (as CI printed it for git: "install the manifest's version (winget on the Windows dev box, ...), or move toolchain.env to the inst...") invites a worker to change the host or its branch's manifest, and two workers doing so would flip the host back and forth. No loop unit owns a bump, and `toolchain.env`'s header says only that the bump change carries the host update.

**State on 2026-11-12:** branch `toolchain-20261112` at 505c6a9cd2 (gh 2.103.3 to 2.104.0, uv 0.13.7 to 0.13.8, in `toolchain.env` and `scripts/cloud/setup-env.sh`) is pushed and waits. The Mythos session does the host update, the gate and the landing by hand at a moment when the loop has no fleet in flight.

**Shape (a design item, the fixer decides):** the loop owns the bump as a unit that runs with no fleet in flight (host update, gate, landing, then every worktree adopts main), and the gate scope holds only the tools whose version can change a test's result; the refusal text names that unit, never a reinstall.
