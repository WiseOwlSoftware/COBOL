# PB1296 — LANDED 2026-09-27 (wave 68 V2; the size error indicator itself landed with PB1130, wave 68 V)

## Landed (wave 68 V2, 2026-09-27) — GR1's digit count per category

- The size error indicator, the GR3 test and GR4's spaces landed with kb/Work PB1130 (wave 68 V). Re-probing on
  that tree showed the capacity it tests against was WRONG for every edited picture: `PicInfo.Digits` counts only
  the '9' symbols, so a `PIC ZZ9` total of 120 was a size error and printed as spaces — a wrong answer on nearly
  every real report. `DataBinder.SumCounterDigits` now derives GR1's count ("the corresponding number of digits,
  excluding insertion editing characters, in the PICTURE clause") per category: numeric — the 9s; numeric-edited —
  every digit position (`PicInfo.DigitPositions`: 9, Z, *, floating insertion); alphanumeric / national, edited or
  not — each character position except the B / 0 / / insertion characters (the old clamp read their zero '9's as
  ONE digit, the note's "prints '4' for a total of 24").
- **Golden:** `conformance:85/pb1296_sum_counter_digits_85` (ZZ9 120, Z(3) 120, $$$9 $120, 9,999 0,120, X(4) 0120,
  XXBX "12 0", 99 → spaces).
- **Not here:** a PICTURE of 19+ digits is still capped at the engine's 18-digit `long` carrier (reported as a lead).

## Measured

### Finding sum-clause — ISO/IEC 1989:2023 13.18.54.4 GR1, GR2, GR3, GR4 (wrong-answer; rows GR-13.18.54.4-4, GR-13.18.54.4-2)

**Mechanism.** The report engine has no sum-counter SIZE ERROR INDICATOR: SumEntry.Value is an unbounded long accumulated by `s.Value += t.Addend()` with no size-error test against the counter's GR1 digit count, so EC-REPORT-SUM-SIZE is never raised and an overflowed counter prints its MOVE-truncated low digits instead of spaces.

**Repro.** out13/probe/sum-clause/p1.cob: WS-K PIC 99 VALUE 60; CONTROL FOOTING FINAL `COLUMN 1 PIC 99 SUM WS-K`; INITIATE, GENERATE DET twice, TERMINATE.

**Expected, from the standard.** The counter has 2 integral digits (GR1); the second addition gives 120, a size error (GR3: 'Each addition is tested for size error; if a size error occurs, the EC-REPORT-SUM-SIZE exception condition is set to exist'), so at print GR4 applies: 'the printable item is filled with spaces' -> the footing shows two spaces in columns 1-2 (and the indicator is unset again at the end of the group, GR2).

**Observed.** Observed '20' in columns 1-2 (the 120 total truncated by the MOVE). ExceptionCatalog lists EC-REPORT-SUM-SIZE but no raise site exists (grep over src); ReportWriter.Initiate's comment calls it a 'seam'. PicInfo.SumCounterItem also clamps a 0-digit PICTURE (PIC X(4)/N(4)) to 1 digit, which prints '4' for a total of 24.

**Code site.** src/Cobol.Net.Runtime/IO/ReportWriter.cs#Generate (SUM accumulation loop); src/Cobol.Net.Runtime/IO/ReportWriter.cs#SumEntry; src/Cobol.Net.Runtime/IO/ReportWriter.cs#EndOfGroupSumReset
