# PB521

## Mechanism — data-description-entry-p2
F7 — §13.16.3 SR21's two exclusions have no owner. The b) leg (PROPERTY x TYPEDEF) fails through OoBindPropertyClauses' subject lookup: the PROPERTY subject is searched in `Roots`, and BindEntries deliberately keeps a TYPEDEF entry OFF Roots because it is a template, so `subject` is null, the guard `if (subject is null) continue;   // the entry failed to bind — already diagnosed` fires, and the comment's premise is FALSE — nothing diagnosed it. The a) leg (PROPERTY x BASED) is rejected today only because BASED data in a class definition is separately staged as 'not yet implemented', so the rule has no owner the moment that residue lands.

### Expected, from the standard
ISO/IEC 1989:2023 §13.16.3 SR21 (cite-checked): "The PROPERTY clause shall not be specified in the same data description entry as: a) a BASED clause, b) a TYPEDEF clause." Both entries shall be rejected at compile time. §13.18.42.3 (cite-checked, SR1-SR6) carries no BASED or TYPEDEF exclusion of its own, so §13.16.3 SR21 is the only home for either leg.

```
$ python scripts/spec/cite.py --check 13.16.3 "The PROPERTY clause shall not be specified in the same data description entry as: a) a BASED clause, b) a TYPEDEF clause"
  FAIL: §13.16.3 exists but does NOT contain 'The PROPERTY clause shall not be specified in the same data description entry as: a) a BASED clause, b) a TYPEDEF clause'
  ⛔ REGISTRAR: no quotation in this finding validated verbatim against §13.16.3. The MECHANISM below is measured and stands, but the QUOTATION is the finding's paraphrase — quote the clause and re-run `--check` before it reaches a code comment, a golden or the DEVLOG (CLAUDE.md rule 1).
```

### Observed
p_sr21_typedef.cob compiles with exit code 0 and no diagnostic. The mechanism is DataBinder.Oo.cs#OoBindPropertyClauses ~541-544: the subject is resolved out of `Roots.SelectMany(Flatten)`, and DataBinder.cs#BindEntries ~679-683 routes a TYPEDEF entry to RegisterTypeDecl and explicitly keeps it off Roots ('a named level-01 template that allocates NO storage — registered in TypeDecls, kept OFF Roots'). So the PROPERTY clause on a type declaration is dropped in silence rather than rejected. For the a) leg, COBOLNET0899 reads 'BASED data or ADDRESS OF in a class definition's data divisions is recognized but not yet implemented (the OO cell/bridge emission - a named Phase-4b residue; ISO §13.18.5 / §8.4.3.11)' — the right outcome for the wrong reason, and a green-looking rejection that will silently invert when the Phase-4b residue lands. This is the [[green_test_can_hold_a_gap_open]] shape: a loud stage standing in for a syntax rule.
