# PB4354 - Two sites still say exit 12 waits until no Linux gate of the tree runs

**Sites:** `docs/rearchitecture/DESIGN-orchestrator-loop.md` (section 4.9 exit table, the exit 12 row, line 598, which cites `wait_free` and kb/Work PB3649) and `scripts/orchestrator/land_lane.py` (`ACTION[FREE]`, line 1187, the text that `land_lane.py status`, `next_unit.py` and `session-probe` print).

Both say the lane retries an exit 12 "once the worktree's gate lock is free and no Linux gate of the tree runs". After kb/Work PB4327 deleted the Linux half of the per-change gate there is no Linux gate to wait on. `land_lane.wait_free` for `EXIT_GATE_BUSY` returns `gate_lock_free(worktree)` alone (`land_lane.py` lines 673-674; the docstring of `gate_lock_free`, about lines 599-606, says so), and the same design doc's line 1434 already states that the lock is exit 12's only source (PB4327). The two sites are the last copies of the PB3649 wording. The operator-facing text promises a wait on a condition nobody checks, so a reader looks for a Linux gate that cannot exist.

Fix: reword both to "once the worktree's gate lock is free", and cite PB4327 beside PB3649 in the table row. Sibling sweep: `git grep -n -i "linux gate" -- scripts docs .claude README.md` and read each hit for a present-tense claim about the per-change gate.
