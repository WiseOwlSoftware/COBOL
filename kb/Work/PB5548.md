# PB5548 - test gap: PADDING CHARACTER IS ALL symbolic-character with a NATIONAL symbolic-character has no golden

**Sites:**

- `conformance-suite/cases/_unassigned/pb5420-padding-national-symbolic.cob` (pins only the bare form `PADDING CHARACTER IS SYM1`).
- `src/WiseOwl.Cobol.Compiler/Binding/FileControlBinder.Padding.cs#OneCharacter` (the `ALL` arm, `FoldAllLiteral` / `SymbolicCharacter` path) and `#SymbolicCharacter` (`SymbolicOf(site, word) is { National: false }`).

**Gap.** PB5420's R1-2 negative refuses a NATIONAL symbolic-character as the bare PADDING CHARACTER operand. The `ALL SYM1` arm reaches `SymbolicCharacter` through a different caller in `OneCharacter`, and no golden runs it with a national symbolic-character. A regression that makes that arm read the value only (the PB5543 shape) would pass every test.

**Fix.** Add a refuse-at golden beside the existing one (same SPECIAL-NAMES `SYMBOLIC CHARACTERS SYM1 ... FOR NATIONAL` setup, `PADDING CHARACTER IS ALL SYM1`), with the expected code taken from what the bare form's golden asserts, plus the accepted counterpart for an alphanumeric symbolic-character at `--std 85` if one is missing. Prove the golden fails when the `National: false` test is removed.
