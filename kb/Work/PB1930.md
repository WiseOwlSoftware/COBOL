# PB1930 — LANDED

Filed by the train-1005 lander from wave 1005 group C's report (`w1005c-PB1423-report.md`, lead 2). Not re-probed by
the lander.

## The defect

A function-identifier is an identifier (§8.4.3.2.4 GR1), and CALL's BY CONTENT phrase takes an identifier as an
argument. When the function's RETURNING item is of class object or pointer, the BY CONTENT arm routes the operand to
the arithmetic-expression screen, which reports COBOLNET0844 ("not a numeric operand"). The numeric and alphanumeric
function results already cross (the CALL path PB1419 relied on); only the non-arithmetic classes are refused.

**Repro.** `CALL "S" AS NESTED USING BY CONTENT FUNCTION FOBJ(1)` with `FOBJ` returning `USAGE OBJECT REFERENCE`
(and the same with a `USAGE POINTER` RETURNING item).

**Sites.** `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/ExpressionBinder.cs` (~:1182, `ScreenIdentifierOperand`) and
the BY CONTENT arm of `CallBinder`. Sibling of PB1929 (the same "a function-identifier is not a bare reference" shape).

## Landed - 2026-10-07 (wave 1037 group H)

Re-probed on the wave-1037 build: `CALL "SO" AS NESTED USING BY CONTENT FUNCTION FOBJ(1)` (object reference) and the pointer twin were
refused COBOLNET0844 -- confirmed, and the note's claim that "numeric and alphanumeric function results already cross" on CALL was wrong
for the alphanumeric intrinsic: `BY CONTENT FUNCTION UPPER-CASE(X)` drew the same 0844 (only INVOKE had the recovery, PB923).

- **Root cause.** `arithmeticExpression` subsumes a function-identifier, an inline method invocation, an object-view and SELF, and
  the CALL binder's argument arms bound a sole one as arithmetic-expression-1, so §8.8.1.1 screened it. §14.9.4.4 GR8 says an argument
  that is merely a single identifier is an identifier. The BY CONTENT arm, the bare Format 2 arm, the bare arithmetic arm and the BY
  VALUE arm each had their own copy of the expression bind.
- **Fix.** `CallBinder` binds the sole function-/method-identifier (and the keyword-omitted repository function, §8.4.3.2.3 SR2)
  through its own door in ONE local pair, `ExpressionOperand` / `OperandArg`: a user function's or invocation's temporary crosses as a
  PLACE, an intrinsic's computed value as an OPERAND. A keyword-less one takes GR9 a)2's BY CONTENT or, with a BY VALUE formal, GR9 b)'s
  BY VALUE with SR22's class screen (`AddBareTemporaryArg`); Format 1's bare one is admitted only under a prevailing BY CONTENT (GR5; SR3
  makes a temporary no BY REFERENCE candidate, COBOLNET1677). The numeric-formal verdict is now the activation's conformance
  (COBOLNET1688), not the arithmetic screen's.
- **Sibling arm, the INVOKE twin.** `OoBinder.OoBindInvokeArg`'s recovery (PB923) re-routed an intrinsic's value but let a USER
  function's result (a `BoundFieldOperand` over its temporary) fall to the expression arm, so `INVOKE O "M" USING BY CONTENT FUNCTION
  FOBJ(1)` into an object-reference or pointer formal drew COBOLNET0828. It now crosses as that place, like the inline invocation.
- **Goldens.** `2002/pb1930_content_function_identifier_arguments` (10 lines: CALL BY CONTENT / keyword-less / keyword-omitted / BY VALUE
  / Format 1, INVOKE; object, pointer, numeric, alphanumeric) and negatives `pb1930-call-bare-function-identifier-by-reference`
  (COBOLNET1677) and `pb1930-call-content-alnum-function-numeric-formal` (COBOLNET1688).
