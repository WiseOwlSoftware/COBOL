# PB1930 — OPEN

Filed by the train-1005 lander from wave 1005 group C's report (`w1005c-PB1423-report.md`, lead 2). Not re-probed by
the lander.

## The defect

A function-identifier is an identifier (§8.4.3.2.4 GR1), and CALL's BY CONTENT phrase takes an identifier as an
argument. When the function's RETURNING item is of class object or pointer, the BY CONTENT arm routes the operand to
the arithmetic-expression screen, which reports COBOLNET0844 ("not a numeric operand"). The numeric and alphanumeric
function results already cross (the CALL path PB1419 relied on); only the non-arithmetic classes are refused.

**Repro.** `CALL "S" AS NESTED USING BY CONTENT FUNCTION FOBJ(1)` with `FOBJ` returning `USAGE OBJECT REFERENCE`
(and the same with a `USAGE POINTER` RETURNING item).

**Sites.** `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/ExpressionBinder.cs` (~:1182, `ScreenIdentifierOperand`) and
the BY CONTENT arm of `CallBinder`. Sibling of PB1929 (the same "a function-identifier is not a bare reference" shape).
