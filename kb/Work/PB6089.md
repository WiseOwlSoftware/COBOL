# PB6089 - one reader of a committed store

**Observed** (review of #1954): `scripts/spec/inventory_store.py#read_store_at`, added by PB6056 so the code-read
landing check reads the store at the revision it judges, lists a directory at a rev (`ls-tree`, not recursive) and fetches
its blobs through `git_batch.blobs`, then validates them (`_problems_of`). `#store_at` in the same file does the same
listing (`ls-tree -r`) and fetch without the checks. One mechanism is written twice, and a commit with a stray file in
the store reads differently through the two.

**Fix:** one reader of a committed store directory, with the validation decided once, called by both. Then sweep the
other store readers in scripts/spec for a third copy.

**Sites:** scripts/spec/inventory_store.py#read_store_at; scripts/spec/inventory_store.py#store_at
