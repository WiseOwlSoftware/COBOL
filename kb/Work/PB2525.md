# PB2525 — one cite.py process per citation

## Measured (w1033 gate performance diagnosis, section 1, `doccite-profile.txt`)

`python scripts/spec/audit_doc_citations.py --check` took 95.4 s serially at 25 % host load, the largest of the twelve
gate audits (113.7 s together). Under cProfile it spends **75 of its 79 s in 843 `subprocess.run` calls of
`cite.py`**, one fresh Python process per citation, each reloading `specs/ISO_COBOL.md`, about 89 ms each. The audit's own
logic costs about 3 s.

## Mechanism

`scripts/spec/audit_doc_citations.py#cite` shells out to `cite.py --check <clause> <text>` and parses its stdout,
although `cite.py` is a Python module in the same directory whose `check` function answers the same question.

## Shape

`cite.py` exposes its checker as a function over a spec loaded once (the same function its own `--check` CLI uses, so
there is one checker, not two), and `audit_doc_citations.py` calls it in-process. The differential: the audit's
`--check` output over the whole doc corpus is byte-identical before and after. Its `--self-test` still passes.

## Landed (wave 1033 group W, 2026-10-07, branch `gate-perf`)

- `scripts/spec/audit_doc_citations.py#verdict_of` calls `cite.check` and `cite.find` (the functions the `cite.py` CLI
  runs, so one checker) over `_spec()`, the standard loaded once per process; `_clause_words` reads the same load.
  The subprocess helper `cite()` and the `subprocess` import are deleted.
- `scripts/spec/cite.py#norm` is memoized (`functools.lru_cache`, 131,072 entries, above the transcription's ~47,500
  lines): in-process, `find` re-normalized every spec line per call, 25 of the first in-process run's 33 s.
- Differential: `audit_doc_citations.py --all` before and after, byte-identical (949 verbatim-shaped citations checked,
  886 correct, 0 misfiled, 0 elided; `docs/rearchitecture/evidence/w1033-gate-levers/doccite-all-{before,after}.txt`).
  Time 78.2 s to 2.5 s on the same host minutes apart.
- Self-test arm "in-process: every ruling made with no process spawned, the standard loaded once" makes process
  creation fail and still requires every ruling; seen RED on the subprocess checker (`FAIL … spawned [python.exe …]`);
  `CitationAuditSelfTestDriftTests.DocCitationAudit_ProvesEveryArmCanFail` asserts it.
- Sibling sweep: `grep "subprocess.(run|Popen)([sys.executable"` over `scripts/` — no other audit spawns a checker per
  item. The next audit cost is `audit_code_citations.py` (18.5 s, 1.36 M regex searches in `_ordinal_findings`); it
  no longer holds a slot, so it is a lead, not a fix here.
