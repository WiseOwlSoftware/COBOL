# PB1556

Found 2026-09-24 by the golden-lane-2 misc-p28 writer on pin f0d582ccd; **re-probe first**.

## Repro

`<scratchpad 9db39f61…>\gl\held\misc-p28\tests\conformance\85\l1c28_read_numeric_fd_record.cob` (FD record `01 R PIC 9`,
READ) and `l1c28_return_numeric_sd_record.cob` (SD record `01 R PIC 9`, RETURN). `cobol <f> --run --std 85` → Roslyn
CS0029 (cannot convert the record text to the numeric field type), exit 70. Legal: a record description entry may be a
single elementary item; READ/RETURN make the record available in the record area (§14.9.30.4, list item c) — cite.py
mislabels it 13) b), PB1554).

## Code site

`src/Cobol.Net.Compiler/CodeGen/…/SequentialIoEmitter.cs:706` `EmitRecordAreaStore`, called from `SortEmitter.cs:451`
and the READ arms. It assumes the record is a GROUP (alphanumeric image). Sweep every record-area store and load (WRITE
FROM, REWRITE, RELEASE, READ INTO, RETURN INTO) for the same assumption — every record kind (elementary numeric,
national, boolean, pointer) must round-trip through the record area's byte image (the typed-native codec boundary).

**Confirmed (golden-lane-2 misc-p28 refuter):** both repros fail on the pin with CS0029 "Cannot implicitly convert type
'string' to 'long'" (READ at (58,29), RETURN at (78,38)); both are legal source (an elementary 01 record is valid in an
FD or SD; SORT SR6 a) accepts it as a key). Expected output: `7` (READ) and `S2 3/2/1` (RETURN).
