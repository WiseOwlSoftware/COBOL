# PB4926 - the run unit's message-tag table only grows

**Sites:** `src/WiseOwl.Cobol.Runtime/Control/SlotImageTable.cs` (`SlotImageTable.TagId`, `SlotImageTable.TagOf`, `SlotImageTable.TagBlockCount`), `src/WiseOwl.Cobol.Runtime/Messaging/MessageTagImage.cs`, `tests/WiseOwl.Cobol.Tests.Unit/MessageTagImageTests.cs`, `docs/CONFORMANCE.md` (DOC-A.1-212)

**Report.** `SlotImageTable` assigns each distinct `(Mcs, Party, Name, Message)` message tag an id on first use and keeps both `_tagIds` and `_tags` for the
run unit's life, so a program that SENDs or RECEIVEs a long batch (the message serial number is part of the key) holds one entry per message for ever.
Harm: unbounded memory growth, eventually an out-of-memory crash, in a long-running messaging batch. Expected: the table drops an entry once its message is
no longer reachable from any slot image the run unit may still READ (the tag's lifetime ends with the message's), or the key excludes the serial and the
serial is stored in the token. Same root as the report's R1-2: the run unit table's lifetime. Not fixed in the PB4838 review round. The fix adds a unit test
that imaging N messages leaves the table bounded.

Source report and lead: `w20261905d-PB4838-report.md`, New defects 1.
