## 2026-11-17: landed — GR11a, GR11c and the report-file rule; part 2 moves to PB5912

**1. LINAGE in one describer only (GR11a).** §1985:VII.3.7.4 GR11 settles the adjudication the note left open: the entries
"must have: a. A LINAGE clause, if any file description entry has a LINAGE clause" (`cite.py --check "§1985:VII.3.7.4 GR11a"`
OK). An absent clause DOES disagree. `FileDescriptionIdentity.Rule` gained `AbsentCite`, the rule an entry that writes no
clause breaks when another entry writes one; `ExternalFileConnectorRules.CheckFileDescriptions` reports such an entry at its
file description entry, wherever the writer stands in the group (COBOL6847, "... does not write the LINAGE clause, and another
entry ... writes it (\"LINAGE 10\") ... (ISO §1985:VII.3.7.4 GR11a)").

**Sweep: GR11c.** "c. The same corresponding external data items referenced by data-name-1, data-name-2, data-name-3, and
data-name-4" (`cite.py --check` OK). A data-name operand was `Undecided` at compile time, so `LINAGE IS LN1 LINES` against
`LINAGE IS LN2 LINES` over one external record compiled. Each operand is now its external data item's identity
(`ExternalDataItemIdentity.Key`, the one the run time's `LinageRef` compares), escaped so the operands still split; a data-name
that names no external item stays undecided (its externality is a separate rule). A literal against a data-name in one position
disagrees, as the run time's comparison does.

**Sweep: the report-file rule.** §1985:XIII.3.3.4 GR3: "every file description entry in the run unit which is associated with
that file connector must describe it as a report file" (`cite.py --check` OK). It was not compared at all; it is a new row
(`Report`) whose `AbsentCite` is GR3. The report-names an entry writes are its own.

**The LINAGE value as a diagnostic shows it** is the clause as written (`LINAGE 10`, `LINAGE LN2 (external record X1, offset
2)`) instead of the internal `10|||`.
