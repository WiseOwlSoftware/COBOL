# PB4753 - unary minus and an even MEDIAN land one binary64 low

**What the report says (R2-1, low).** The R1-2 fix moved a list holding a float item beside an approximation onto the exact lane,
and only a whole selected value keeps the remembered binary64. Unary minus (`CobolExact.Negate`, reached from
`NumericRenderer.Negate`) and an even-count MEDIAN (the mean; `SelectionNeedsExactLane` is asked for `MedianScaled` whatever the
count, though its summary says an odd MEDIAN) form a new value that lands in a float receiver as the truncation of the shortest
decimal, one binary64 below what main stored.

**R1.** No open note covers it.

**Fix (landed).** Two roots. (1) `CobolExact.Negate` kept no memory of the binary64 an approximation came from; the sign flip of a
binary64 is exact, so it now negates the remembered double with the decimal. (2) An even-count MEDIAN is §15.61.4 r2's arithmetic
mean, a new value and not a selection, so `IntrinsicCarrierRules.ReturnsMeanOfMiddlePair` (new, asked by `IntrinsicRenderer.RenderNum`
and `FunctionValueLane` alike) takes it off the kind-preserving exact lane that `SelectionNeedsExactLane` opens for a float item
beside an approximation; it stays on the float lane, the binary64 value of its equivalent expression. A mixed fixed-point and float
list keeps the exact lane. Re-probe before: `- MAX (DS EXP10 (-3))` and `MEDIAN (DS EXP10 (-3))` into FLOAT-LONG compared NE to
`- EXP10 (-3)` and `(DS + EXP10 (-3)) / 2`; after, EQ. Golden `pb4753_negation_and_even_median_beside_a_float_item_land_by_the_binary64`.

**Sites:** `src/WiseOwl.Cobol.Runtime/Values/Numeric/CobolExact.cs#Negate`, `src/WiseOwl.Cobol.Compiler/Binding/Bound/IntrinsicCarrierRules.cs#SelectionNeedsExactLane`, `src/WiseOwl.Cobol.Compiler/Binding/Bound/IntrinsicCarrierRules.cs#ReturnsMeanOfMiddlePair`, `src/WiseOwl.Cobol.Compiler/Binding/Procedure/FunctionValueLane.cs#Of`, `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/IntrinsicRenderer.cs#RenderNum`.
