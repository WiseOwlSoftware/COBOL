# PB5315 - after DISABLE I-O TERMINAL a RECEIVE of the input-output CD takes NO DATA though the MCS already holds a message from that terminal: TakeFromTerminal tests the terminal's enabled flag where the program takes a message, where 1985 disables only the terminal's link to the MCS

**Sites:**

- `src/WiseOwl.Cobol.Runtime/Communication/MessageStoreState.cs` (`TakeFromTerminal`)

**Mechanism.** "The logical path for the transfer of data between the COBOL programs and the MCS is not affected by the DISABLE statement" (§1985:XIV.3.2.4 GR1), and the disconnection is at the terminal ("never cause the remaining portion of the message to be terminated during transmission to or from a terminal", GR2); GR5's "logical path between the source ... and the program" is that terminal-to-MCS link. `TakeFromTerminal` tests `Enabled` before taking a message the MCS already holds (its doc comment states the opposite reading), so the held message appears only after ENABLE. The input arm already behaves as 1985 says (after DISABLE INPUT TERMINAL a RECEIVE still returns a queued message). The test belongs where a terminal's new input enters the MCS. kb/Work PB5107 (landed) fixed the ENABLE half.

None of them is recorded: the adjudicated non-conforming verdicts wait in `E:/COBOL-coord/scratch/coderead-85/held-for-register.json`.
