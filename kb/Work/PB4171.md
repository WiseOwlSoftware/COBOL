# PB4171 — The golden pb1682_evaluate_null_subject_is_identifier cites 8.4.3.10.4 GR2 (the FUNCTION-pointer rule) for ...

**Sites:** `conformance-suite/cases/14.9.13-EVALUATE/pb1682_evaluate_null_subject_is_identifier.cob:16` (the comment "NULL is guaranteed not to be any item's address, 8.4.3.10.4 GR2").

The lead's text (PB1682 report, R1-1): the golden derives its expected values from "8.4.3.10.4 GR2" (NULL is guaranteed not to be any item's address), but P is USAGE POINTER, a data-pointer, and GR2 is the FUNCTION-pointer rule; the data-pointer rule is GR1. The clerk re-ran the check:

`python scripts/spec/cite.py --check 8.4.3.10.4 "guaranteed not to represent the address of any data item"` printed `OK  §8.4.3.10.4 1)  (General rules)` followed by the text "1) When associated with a data-pointer, the predefined address NULL references a data item of category data-pointer that contains the null address. The null data address is an implementor-defined value that is guarantee..." (the text sits at rule 1).

**Fix:** change `GR2` to `GR1` in the golden's comment (validate with the `--check` above). The DEVLOG entry for PB1682 repeats the wrong rule number, but DEVLOG is history and is not edited; the golden is the only site. Sweep the other `pb1682-*` goldens for the same inherited rule number.
