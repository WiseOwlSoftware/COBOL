# PB2987 — the owed-publish check reads a stale checkout

**Found by:** the operator, 2026-10-10 ~22:30 PDT. Train 1056 landed at 22:17 (main `190f3b88d`); the wave unit ended at
22:22:43 and the supervisor logged no `LEDGER PUBLISH OWED` and posted no `publish` message to the operator's mailbox.
`stop.ps1 -Status` read `ledger: current 4e4e38b54`.

**Mechanism.** `scripts/orchestrator/orchestrate.ps1` (after each unit) runs `ledger_state.py owed --repo $RepoDir`, and
`ledger_state.py#stamp` is `git log -1 --format=%h -- <gen_ledger.STAMP_PATHS>` in that directory's working tree: the
main checkout `E:\COBOL`. A lander lands through `push-main.sh` from its own worktree, so the main checkout stays at
the previous train until someone fast-forwards it by hand (the operator did at 22:30: `git merge --ff-only
origin/main`, after which `owed 190f3b88d` read correctly and ledger v34 was published). The same stale checkout also
feeds every other `--repo $RepoDir` reader in the supervisor.

**Fix direction.** Stamp `origin/main` (after the fetch the supervisor already does), not the checkout's HEAD:
`git log -1 --format=%h origin/main -- <paths>`; or have the supervisor fast-forward its own clean checkout after each
unit. Pair it with a self-test: a landing pushed from another worktree must make the next owed check read `owed`.

## Landed (wave 1062, group A)

`ledger_state.py` reads the stamp on MAIN: `state()` fetches `--main-ref` (default `origin/main`; `refresh()` fetches
only a ref of a configured remote) and stamps it with `git log -1 --format=%h <ref> -- <STAMP_PATHS>`; a ref that names
no input-touching commit is `NoMain` (exit 2), never read as `current`. The checkout's own stamp is reported beside it
(`checkout_stamp`, `checkout_current`), because the page is still RENDERED from the checkout: `owed` appends
`the checkout <repo> renders the ledger at <x>, not origin/main's <y>: fast-forward it first (git -C <repo> merge
--ff-only origin/main), then render`, `gen_ledger.py` prints the same as `NOT MAIN'S PAGE` after a render, and
`mark-published` REFUSES (exit 2) while the checkout's stamp is not main's, so a page that does not describe main is
never marked current. The supervisor's `--repo $RepoDir` call and `stop.ps1 -Status` need no change: both now read
main. Self-test `test_ledger_state.py`: the fixture is a clone of a bare origin; every landing is pushed; a landing
pushed from a SECOND clone reads `owed` while the checkout is behind, the mark refuses, a fast-forward lets it mark, and
an unknown main ref is refused. Design: DESIGN-orchestrator-loop.md section 14 (the announce and publish bullets).

Sibling sweep: the other `--repo $RepoDir` readers in `orchestrate.ps1` (`next_unit.py`, `checkpoint.py`,
`account.py`) read branches, worktrees and the coordination directory, not the checkout's tree; the one other reader of
the checkout's TREE is `gen_ledger.py`'s render, handled above. `next_unit.py`'s campaign lane reads `kb/Work` from
`work.WORK` (the scripts' own checkout), which is stale in the same way; it is reported as a lead (wave 1062 group A
report), not fixed here.
