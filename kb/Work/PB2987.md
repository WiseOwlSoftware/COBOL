# PB2987 — the owed-publish check reads a stale checkout

**Found by:** the operator, 2026-10-10 ~22:30 PDT. Train 1056 landed at 22:17 (main `190f3b88d`); the wave unit ended at
22:22:43 and the supervisor logged no `LEDGER PUBLISH OWED` and posted no `publish` message to the operator's mailbox.
`stop.ps1 -Status` read `ledger: current 4e4e38b54`.

**Mechanism.** `scripts/orchestrator/orchestrate.ps1` (after each unit) runs `ledger_state.py owed --repo $RepoDir`, and
`ledger_state.py#stamp` is `git log -1 --format=%h -- <gen_ledger.STAMP_PATHS>` in that directory's working tree: the
main checkout `E:\COBOL`. A lander lands through `push-main.sh` from its own worktree, so the main checkout stays at
the previous train until someone fast-forwards it by hand (the operator did at 22:30: `git merge --ff-only
origin/main`, after which `owed 190f3b88d` read correctly and ledger v34 was published). The same stale checkout also
feeds every other `--repo $RepoDir` reader in the supervisor.

**Fix direction.** Stamp `origin/main` (after the fetch the supervisor already does), not the checkout's HEAD:
`git log -1 --format=%h origin/main -- <paths>`; or have the supervisor fast-forward its own clean checkout after each
unit. Pair it with a self-test: a landing pushed from another worktree must make the next owed check read `owed`.
