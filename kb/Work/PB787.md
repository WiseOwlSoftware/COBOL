# PB787 — OPEN — the diagnostic tells the user how it was gated, and the how is stale

Filed 2026-09-06 by the registrar from the PB353 finisher's report (`PB353-report.md` §"New defects" (A)).
**Every number and every claim below was re-measured against `origin/main` at `07cbb2ad`**; the dispatch's count
and two of its supporting facts did not hold and are corrected here.

## The mechanism — why a catalogue field is user-visible at all

`src/Cobol.Net.Editions/ConstructRegistry.cs:43-44`:

```csharp
$"{c.Display} requires COBOL-{c.IntroducedIn} (targeting COBOL-{edition.Year}) — {where} ({c.Citation})",
where, c.Citation));
```

`c.Citation` is the `citation` string of the `tests/version-matrix/constructs.json` row, carried through
`ConstructRegistry.g.cs` (generated by `scripts/gen-constructs.ps1`) and appended in parentheses to the message
of `EditionCodes.Introduction` — `src/Cobol.Net.Editions/EditionCodes.cs:16`: `public const string Introduction =
"COBOLNET0900";`. The same field is appended to the removal and obsolescence messages (`:47-54`). So every word
of it is shipped text a user reads when their source is refused.

## ⛔ Premise corrections — the count, and two facts about what has landed

**(1) "About nineteen rows" is not the measured number.** Across the **209** rows of
`tests/version-matrix/constructs.json` on main, matching `grammar-gated|grammar gate|W1.5`:

`set-object-reference-2002`, `boolean-operators-2002`, `logical-xor-operator-2023`, `function-prototype-2002`.

**(2) PB353's two-row fix is NOT on main.** The dispatch says PB353 "fixed only the two rows it falsified
(`start-with-length-2002`, `invoke-2002`)". That fix is on the **train-20** branch; on main
`start-with-length-2002`'s citation still reads *"ISO §14.9.41 (provisional 2002 edge); grammar-gated

**(3) `EditionGateArmDriftTests` does not exist on main.** `grep -rln "EditionGateArmDrift" tests/` → nothing;
the Conformance project has `EditionGateDiagnosticTests.cs` and no arm-drift test. PB353's is arriving with
train 20. The fix shape below therefore *extends a test that is landing*, not one that is landed — sequence the
work after train 20 or the third assertion has nothing to attach to.

⚠ **The remaining six were NOT measured** (`currency-picture-symbol-2002`, `implements-clause-2002`,
`method-property-selector-2002`, `boolean-operators-2002`, `logical-xor-operator-2023`,
`function-prototype-2002`) and must not be assumed false: **21 version predicates still exist in the grammars**
(`grep -rn "is2002()\|is2014()\|is2023()" src/Cobol.Net.Frontend/Grammar/ --include=*.g4` → 21), so some
"grammar-gated" claims can be true. A sweep that rewrites all 15 on the strength of this table would be the
`feedback_a_dead_lookup_is_also_unverified` mistake in the other direction.

⭐ **The shape of the error is worse than "stale".** The three ways a row can be wrong are now distinguishable —
the gate is a grammar predicate, or `ParseArm`, or `GateStatement`'s bound arm — and the fifteen rows use one
vocabulary ("grammar-gated") for all three. `start-with-length-2002` and `set-object-reference-2002` are gated in
the arm PB353 exists to move things OUT of, and their own citation says "grammar".

## Why `process_only` when a user reads it

No program compiles differently and no value changes, so the harm flags are all false and `work.py check`
requires the `process_only` marker. ⚠ It is nonetheless **wrong information a user reads in a shipped
diagnostic** — the same classification `kb/Work/PB711` carries for COBOLNET1599's message, and the same reason
PB353's finisher fixed the two rows it falsified rather than leaving them: the memory
`feedback_a_real_clause_can_answer_a_different_question` applies to the sentence AROUND a citation as much as to
the clause number in it. Read the flag as "not a compilation defect", never as "not shipped".

## Fix shape — the field carries the SPEC citation; the gate SITE is derived

⛔ Not fifteen prose edits. That is the hand-maintained list CLAUDE.md rule 5 forbids where a structure belongs,
and it is exactly how these fifteen got here: the migrations moved the code and the prose stayed.

1. **`citation` carries the spec citation and nothing else.** It is the field printed to the user, and what a
   user needs is the clause that governs the construct — `cite.py --check 12.3.8 "REPOSITORY"` → **OK §12.3.8**
   (*REPOSITORY paragraph*), `cite.py --check 14.9.41.2 "General format"` → **OK §14.9.41.2** — not the
   compiler's internal plumbing. PB353's train-20 pair is the model of the target text (the printed general
   format and the syntax rule that confines the phrase, in place of "W1.5 parse-layer 0900 mapping") — not yet
   on main, so read it off that branch, and ⛔ re-run `cite.py --check` on every clause and syntax-rule ordinal
   before copying one across: the rows being repaired are themselves a case of prose that propagated unchecked.
2. **The gate site moves to a field that is DERIVED, not typed.** `EditionGateArmDriftTests` (train 20) already
   extracts every gated construct id from the pass's arms; a third assertion requires each row's stated gate
   site to agree with where the pass actually checks that construct. ⛔ **Three-valued, not two** — grammar
   predicate / `ParseArm` / `GateStatement` — because the table above shows all three in use and the current
   prose cannot tell them apart. The `.g4` comments already record the truth per rule, so the alternative
   (parsing the comments) is available if the pass alone is insufficient.
3. ⭐ **Prove it fails once** (`feedback_green_gates_arent_evidence`): the three `repositoryEntry` rows are a
   ready-made witness — the assertion must go red on them before they are corrected.
4. **Then sweep `description` and `vcr`** (17 and 10 rows). They are not user-visible and are therefore second
   priority, but they carry the same sentences and will be re-read as truth by the next migration.
