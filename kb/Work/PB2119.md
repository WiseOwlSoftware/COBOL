# PB2119 — dead and obsolete code (R69 §3; DESIGN-architecture-review §3 R3 "Delete")

**Owner:** "Included in the plan must be removal and deletion of dead/obsolete code." The legacy engine (the PB2108
cluster) is the first item; this note is the program for everything else. **Prerequisite:** PB2115's census, because
reachability is MEASURED (a probe, a reference query over the semantic model), never deduced from a name or a
comment. **Models:** the census (Opus-built, Sonnet-run) decides what is dead; a Delete wave whose item the census
has already measured dead is Sonnet work proven by the oracle; an item whose deadness needs a judgment (a
reflection target, a generator output, an ABI the emitted code reaches) returns `NEEDS-OPUS`.

## How it runs

1. PB2115's census lists unreferenced members and types. Each confirmed item, or each co-located family, becomes a
   `kind: analysis` note with wave kind **delete**, `cluster: ["PB1754"]`, its site and the measurement that says it
   is dead.
2. Candidates known before the census (each to be MEASURED, not assumed):
   - the P8 static runtime façades the P15 text keeps as the pre-G8 byte-stability scaffold (plan §PHASE-15 exit 4a):
     dead once emitted code reaches instances through `RuntimeApi`; measure what the emitted C# references today;
   - `GreenfieldOnly` / `LegacyDivergent` machinery left after PB2109;
   - scripts under `scripts/` with no caller in `scripts/`, `.github/`, `.claude/`, the hooks or the docs' command
     blocks (measure with a caller grep per script; `prune_worktrees.py`'s CHECK rows and `.claude/worktrees/*`
     leftovers are inventory for the same sweep);
   - diagnostic descriptors with no raising site (the `DiagnosticCatalog` → `docs/DIAGNOSTICS.md` generation keeps
     every LIVE code's identity; a descriptor nothing raises is dead by measurement);
   - duplicated or superseded design and evidence documents under `docs/rearchitecture/` (one canonical doc per
     subsystem, `DOC_INDEX.md`);
   - obsolete drift-test literals that pin paths of deleted things.
3. Every Delete wave: every caller changes in the same change (rule 4, no alias, no `[Obsolete]` twin), the §4
   oracle proves neutrality, the docs it touches are updated, and a drift test keeps the thing from returning where
   one exists (a deleted mechanism's drift test is deleted with it).
4. A deletion that turns out to change behavior is not a deletion: it is a `kind: defect` note for the fix lane.

## Rules

Measured, not deduced: the note for each item records HOW it was measured dead. Deletions ride between fix-lane
trains in subsystems the current train does not touch (R69 §2).

**Lead from wave 1028 (PB2111, filed by the train-1028 lander).** `src/Cobol.Net.Frontend/Preprocessor/CopyProcessor.cs#Process` has no product caller since the legacy engine was deleted: only the `preprocess` CLI path and the direct unit tests reach it. Measure it with the census and remove it with its callers, or record why the standalone path stays.
