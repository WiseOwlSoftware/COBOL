# PB5615 - at --std 2002 SET ... TO ADDRESS OF PROGRAM refuses an alphabetic identifier-1, which 2002 admits wherever alphanumeric is

**Sites:**
- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/SetBinder.cs` (`SetBinder.BindProgramAddressOperand`, `SetBinder.ScreenAddressName`; COBOL2157)
- `src/WiseOwl.Cobol.Editions/EditionInfo.cs` (`EditionInfo.AlphabeticIsAlphanumeric`, the one edition predicate)
- `src/WiseOwl.Cobol.Compiler/Binding/Model/ItemCategory.cs` (`ItemCategory.IsAlphanumericOrNational`, the Place overload now takes the edition)
- `src/WiseOwl.Cobol.Compiler/Binding/IntrinsicArgumentRules.cs` (`IntrinsicArgumentRules.Violation`, takes the edition) and `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs` (`IntrinsicBinder.CheckArgumentClasses`)
- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CallBinder.cs` (`CallBinder.NameTargetRefusal`, `CallBinder.OperandTargetRefusal`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/StringUnstringBinder.cs` (`StringUnstringBinder.Sr2OffendingCategory`, `StringUnstringBinder.UnstringSenderCategory`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/OoBinder.cs` (INVOKE identifier-2), `src/WiseOwl.Cobol.Compiler/Binding/Validation/StatementValidation.cs` (`StatementValidation.AdmitsIntoOperand`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CommunicationBinder.cs` (`CommunicationBinder.IsCommunicationAlphanumericArea`, `CommunicationBinder.BindSend`)

**Mechanism.** BindProgramAddressOperand applies §2023:8.4.3.13.3 SR1 (alphanumeric or national) on category alone. 2002 8.5.2.1 lets an alphabetic item stand wherever an elementary alphanumeric item is permitted; 2023 has no such rule (2014 E.2 item 2 withdrew it).

**Inventory.** Rows claimed: `2002-GR-8.4.2.12.3-4`.

**Rules (each citation checked with `python scripts/spec/cite.py --check`, verdict OK).**

- `§2002:8.4.2.12.2 SR1`: "Identifier-1 shall be of category alphanumeric or national."
- `§2002:8.5.2.1`: "An alphabetic data item may be specified wherever an elementary alphanumeric data item is"

**Repro.** Scratch originals under `E:/COBOL-coord/scratch/op-20261114/read-2002/defects-work/` (p/padalpha.cob); the text is inline. Command: `cobol.exe p/padalpha.cob --std 2002 --run`

`p/padalpha.cob`:

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. PADALPHA.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  NM  PIC A(8) VALUE "NOSUCHPG".
       01  PP  USAGE PROGRAM-POINTER.
       PROCEDURE DIVISION.
       P-PARA.
           SET PP TO ADDRESS OF PROGRAM NM.
           IF PP = NULL
               DISPLAY "NULL"
           ELSE
               DISPLAY "NOT-NULL"
           END-IF.
           STOP RUN.
```

**Observed.** error COBOL2157 (9,12): SET 'PP' TO ADDRESS OF PROGRAM NM: identifier-1 shall be of category alphanumeric or national (ISO §2023:8.4.3.13.3 SR1) — 'NM' is of category alphabetic, rc=65.

**Expected (from the 2002 text).** compiles; GR4 then governs the not-found case.

**Sibling sweep.** THE WIDE ONE: every operand screen that asks category alphanumeric at --std 2002 (CALL literal/identifier program names, function arguments, STRING/UNSTRING operands, CODE-SET, SEND/RECEIVE) must admit alphabetic; one helper for 'alphanumeric operand at this edition' is the shape that makes the next case automatic.

**Other editions.** 85: unknown (no ADDRESS OF PROGRAM; the 1985 alphabetic-as-alphanumeric reading is per rule). 2014, 2023: no.

**Landed (2026-11-15, wave 20262045 group G).** Re-probed on a fresh build: COBOL2157 and COBOL1627 reproduced at 2002. Fix: ONE edition predicate, `EditionInfo.AlphabeticIsAlphanumeric` (Year == 2002; §2002:8.5.2.1, withdrawn by §2014:E.2), read by `ItemCategory.IsAlphanumericOrNational(Place, EditionInfo)` and `IntrinsicArgumentRules.Violation(rule, op, edition)`; every statement-operand screen of the sweep asks them (SET ADDRESS OF PROGRAM/FUNCTION, CALL/CANCEL target, STRING/UNSTRING, INVOKE identifier-2, READ/RETURN INTO identifier-1, every intrinsic argument position whose class set holds alphanumeric, RECEIVE INTO, SEND FROM). Goldens at 2002 and refusals at 2014 and 2023 for SET, LOCALE-DATE, CALL/UNSTRING/TEST-NUMVAL, RECEIVE and SEND. Not touched, the file-control clause operands (record keys, FILE STATUS, ASSIGN USING, SORT keys), which take the DataItem overloads: a clause operand is not "an operand" of §2002:8.5.2.1's sentence in the way a statement's is; see the report's lead.
