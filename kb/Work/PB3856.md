# PB3856 — one repo-key rule that matches Claude Code's, and a self-test that does not share the regex

**Sites:** `scripts/orchestrator/account.py` (`Account.project_dir`, `memory_index`, `main`), `scripts/orchestrator/orchestrate.ps1` (`Get-ProjectTranscriptDir`, near line 404)

## The defect

R1-2: `Account.project_dir` builds `projects/<repo key>` with `re.sub(r"[:\\/]", "-", str(repo))`, while Claude Code
replaces EVERY non-alphanumeric character. On this machine `E:\Sites\wiseowl.com` lives at `E--Sites-wiseowl-com` and
`E:\COBOL\.claude\worktrees\r1-pb2118` at `E--COBOL--claude-worktrees-r1-pb2118`. `memory_index` (PB3779) and the unit
transcript lookup in `orchestrate.ps1` (`Get-ProjectTranscriptDir`) therefore name a directory that does not exist for
any repository path holding a `.`, a space or other punctuation. The PB3779 self-test derives its expected key with the
same regex, so it cannot catch it. Pre-existing in `project_dir`.

R1-1 (same finding set, code quality): `main` in `account.py` lost a space, `ap =argparse.ArgumentParser(`, in commit
15ae5eb46, an accidental edit outside that change.

## Acceptance

- ONE repo-key function, matching Claude Code's rule (every non-alphanumeric character becomes a dash), used by
  `account.py` and by `orchestrate.ps1` (which asks `account.py` rather than restating the rule).
- A self-test seen RED first whose expected keys are observed directory names under a projects dir (a fixture such as
  `E--Sites-wiseowl-com`), not derived by the implementation's own regex.
- R1-1: `ap = argparse.ArgumentParser(` restored, and the E225 lint over `scripts/orchestrator` passes.
- Sweep: every other place that derives a Claude Code project directory from a path (`git grep` the old regex and
  `projects`).
- Standing owner rules: fix the root causes, never simply making the diagnostic pass; always be consistent with
  ourselves barring an explicit requirement differently.
