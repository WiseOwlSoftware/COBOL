# PB3772 — the queue watch ends at IN_QUEUE

**Sites:** `scripts/orchestrator/land_lane.py` (`WATCH_DONE`, `watch_step`, `watch_queue`, `rearm_hold`), `scripts/prune_worktrees.py` (`not_queued`).

## What happens

- `land_lane.py` line ~723-724 on origin/main: `WATCHING, IN_QUEUE, MERGED, LEFT, ALERTED = ...` and `WATCH_DONE = (IN_QUEUE, MERGED, LEFT, ALERTED)`. `watch_queue` skips every branch whose latest attempt's watch state is in `WATCH_DONE`, and `watch_step` returns `IN_QUEUE` ("pull request #N is in the merge queue") the first tick it sees the pull request queued. From then on the watch never reads that pull request again.
- A pull request can leave the merge queue without merging and without a failed merge-group run: the 2026-10-25 ruleset toggle for the owner-approved PB3308 merge (#594, merged 20:25Z) dropped the queue's entries and turned their auto-merge off; GitHub's `merge_conflict` removal (a queued pull request that conflicts with an entry ahead of it, as #580 does with #579, kb/Work PB3723) has no failed run either.
- The entries that HAD a failed run read BOUNCED in the survey, and the enqueue unit re-armed them (attempts 000140-000149 landed all ten again). One that had none reads NOT QUEUED, and then nobody acts: the lane does not land it (`rearm_hold`: "the survey reads it NOT QUEUED: the queue owns its pull request, so the next tick does NOT land it (the queue watch acts on it)"), the watch does not act (it ended at IN_QUEUE), and the enqueue unit dispatches finishers only for STOPPED and BOUNCED rows.

## The witness (2026-10-25)

- `worktree-wf_1341dc87-1c4-8`, PR #593. Lane attempt `000137-20261025T195851Z-worktree-wf_1341dc87-1c4-8` ENQUEUED (attempt head 18694379509e); its watch read `queued` at 2026-10-25T20:03:42Z and never again.
- `land_lane.py rearm` at 20:28:49Z printed the `rearm_hold` text above, which is false here: the watch had ended.
- At ~21:01Z: `gh pr view 593` OPEN, merge state CLEAN, `ci-gate` success, auto-merge OFF, head fa158c1d0aab; not in the merge queue (GraphQL `mergeQueue(branch:"main").entries`); 62 minutes after it was handed to the queue. The survey row (`prune_worktrees.py --brief`, `not_queued`) printed "queue watch QUEUED (pull request #593 is in the merge queue)": a stale reading shown as current.

## Fix direction

- IN_QUEUE is not an end state: keep reading a queued pull request until it is MERGED or LEFT (closed); one that is out of the queue again, not merged, with no failed run, goes back to WATCHING and the existing grace/REQUEUE/ALERT steps apply to it (the requeue turns auto-merge back on).
- `rearm_hold` says what will actually act, and `not_queued` names the watch reading's time (`at`) and says when the watch has ended instead of presenting its last state as current.
- Self-tests (`land_lane.py --self-test`): queued, then out of the queue with no failed run and auto-merge off, then requeued past the grace; queued then merged ends the watch; the rearm text for a NOT QUEUED branch whose watch ended.
