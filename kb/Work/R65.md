# R65 — how PB1099's three items classify

**The owner's rule (2026-09-30):** "If the ISO specification requires it, we cannot decline it. If the ISO spec makes it part of an optional subsystem, then we implement it if we implement the subsystem, and otherwise not." Annex A.4.1 (cite-checked) says the same for optional elements: "An implementation shall accept the syntax and provide the functionality for an optional element only when support for that language element is claimed by the implementor."

| PB1099 | what it is in the standard | class | decision |
|---|---|---|---|
| **Q2** APPLY COMMIT (Annex A.4.3 item 2; FMT-12.4.6.3.2) | the Commit and Rollback module is an OPTIONAL subsystem (A.4.3; also the A.3 "commit and rollback facility" items 6-7) | optional subsystem, NOT claimed | **Decline and document non-support** (COBOLNET1709 stays; docs/CONFORMANCE.md A.4.3 row). Revisit only if the owner decides to claim the subsystem. |
| **Q1** the SOURCE phrase of RECORD KEY / ALTERNATE RECORD KEY (A.3 item 40) | listed in A.3 (processor-dependent: "dependent on the capabilities of the processor"), NOT in the A.4 optional list; part of the required indexed-file format (§12.4.5.6 / §12.4.5.12) | required element; the processor-dependence clause lets a processor that CANNOT do it decline, and ours can (a key is a composition of fields; the limitation is the current contiguous-window design, not the platform) | **Implement** the SOURCE form (concatenated keys): retire `DataBinder.DeclineRecordKeySource` (COBOLNET1954) and the PB358 negatives, a key-image composer in `KeyedIoEmitter` / `FileRegistry.RegisterIndexed`. Classification confidence: medium-high (the A.3 wording is a capability dependence, not an option) — if the owner reads A.3 as a licence to decline, say so here. |
| **Q3** §8.13 external repository (A.1 items 66, 161, 162; PB1086) | a required concept: §8.13 says the repository "contains all information required for activating programs, functions, or methods and for checking conformance"; A.1 161/162 are "required + documented" (how the class/interface specifier and the repository select the class) | required | **Implement** an external-repository mechanism and document A.1 66/161/162. Needs a DESIGN pass first (where the information lives: assembly metadata versus a sidecar; update and prototype-difference rules), then Sonnet tasks. GnuCOBOL has no OO and no repository, so rule 1 gives it nothing; the ISO text controls. |

PB1099 therefore leaves `owner` status: Q2 is closed as documented non-support; Q1 and Q3 become implementation work (Q3 after an Opus design pass).
