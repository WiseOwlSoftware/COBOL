# PB5253 - at --std 85 a SUM clause may name a sum counter of ANOTHER report (SUM ATOT OF RPT in RPT2): ScreenRolledAddend asks the control-hierarchy rule only for a counter of the same report, the 2023 SR4 relaxation applied at every edition

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/ReportSectionBinder.cs` (`ScreenRolledAddend`: `GroupCombinationPermitted` asked only when `ReferenceEquals(data.Report, target.Report)`; `ResolveSumAddend`)

**Mechanism.** §1985:XIII.3.19.3 SR1: with no UPON phrase, a sum counter named as an addend "must be defined either in the same report group that contains this SUM clause or in a report group which is at a lower level in the control hierarchy of this report". A counter of another report is in neither. `ScreenRolledAddend` applies the control-hierarchy test only when the counter belongs to the same report (the relaxation in §2023:13.18.54.3 SR4), with no edition arm, so the 1985 program compiles and runs. kb/Work PB5022, PB5047 and PB5048 hold this rule's crossfoot and SOURCE-addend arms, not this one.

**Found by.** The 1985 code read, slice 55.
