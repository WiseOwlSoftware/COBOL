# PB696 — OPEN — a clause quoted for more than it says

Found 2026-09-05 by the `PB332` implementer (report §"New defects" C), which corrected the wording in its own three
negatives and left the corpus sweep for its own change set. `cite.py --check 4.2.2 "warning mechanism that
optionally may be invoked by the user at compile time"` → OK: the standard requires the MECHANISM and leaves its
invocation to the user; this compiler provides it as strict mode, which is what a negative golden's header should
say. `grep -rln "4.2.2 makes the compile-time indication mandatory\|4.2.2 obliges" tests/conformance/negative/`
names the files (at least `pb347-release-refmod-record.cob` on main today). The class is the one the memory calls
"a real clause can answer a different question": the audits validate that the quoted fragment exists, not that
the sentence around it is true.

## Fix

Sweep the corpus (negative headers, `docs/CONFORMANCE.md`, `kb/Work` prose, code comments) for §4.2.2 cited as an
obligation and reword each to the mechanism-plus-strict-mode statement; while there, add the sentence to the
implementer brief's citation rule so the next negative does not inherit it. No expected output changes; the
corpus runner re-run proves it.
