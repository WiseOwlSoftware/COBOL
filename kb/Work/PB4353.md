# PB4353 — shard_weights.py's self-test read its planted runs against the wall clock

**Sites:** `scripts/shard_weights.py#report` (it called `measure_window(hours, max_runs, gh)` with no `now`, so
`measure_window` fell back to `datetime.datetime.now(datetime.timezone.utc)`) and `scripts/shard_weights.py#self_test`
(the `report()` arms, which planted runs dated 2026-10-31 07:00 to 09:00 UTC against a fixed `now` of 2026-10-31 12:00
UTC that the `measure_window` arms pass but the `report()` arms could not).

## What happened

PB4332 (pipeline step 9) added `shard_weights.py report` and its self-test. The `measure_window` arms pass the fixed
`now`, but `report()` took no clock, so its arm "the live report measures" read the planted listing through the real
24-hour window. The newest planted run is dated 2026-10-31T09:00Z. Once the real clock passed 2026-11-01T09:00Z the
window held no planted run, `report()` answered `NOT MEASURED` with exit 0, and the arm failed with
`the live report measures: got (0, False), want (1, True)`.

Every merge group whose self-tests ran after that time went red on this one self-test, on Linux (`audits`) and on
Windows (`Windows script self-tests`), whatever the pull request changed: #961's run 41292575983 and #960's run
41291432724 (both on main 2ce2e70a2), then the groups behind them. Main's own last run (2ce2e70a2) was green because it
ran before 09:00Z. The branches that bounced carry no fault.

## Why no gate saw it

The test was green on the day it was written and on every gate that ran it before 2026-11-01T09:00Z, including the
branch's own gate and its merge group. Nothing in the local gates or CI runs a self-test against any clock but the
current one, so a self-test whose planted data is dated close to its authoring time passes until the day it expires.

After the expiry the local gates did not run it at all. Every gate runs `self_tests.py --reuse`, and the PASS store keys
a recorded PASS on the self-test's file content only (`scripts/self_tests.py#PassStore.lookup`, the reuse key
`scripts/self_test_inputs.py` `Deps`; PB2914), never on the clock. So a pre-expiry PASS of `shard_weights.py` stayed
reusable after the test began to fail: the branch review verified a local gate at 09:39Z that read it REUSED and GREEN,
while every merge group ran it fresh and went RED. That reuse, not a CI-only setting, is the local gate's blind spot
here (CLAUDE.md Testing); kb/Work PB4358 carries it.

## Fix

`report()` takes `now` (the window's end; the wall clock when None) and passes it to `measure_window`; the self-test's
`report()` arms pass the fixed `now` their runs are dated against. The guard is the live-report arm: the wall clock is
past every planted run, so a `report()` that dropped `now` would answer `NOT MEASURED` there and fail it. A new arm reads
the same planted runs two days later and requires `NOT MEASURED`. It checks only that the window follows a clock it is
given, and on its own it would also pass with that regression (the branch review's R1-2).

## Sibling sweep

Every self-test `self_tests.py` runs (137; `filter_population.py` is deferred to `--built`), run with the wall clock shifted forward by 3 and by 45 days through a
`usercustomize` shim that moves `datetime.datetime.now`, `utcnow`, `today`, `datetime.date.today`, `time.time` and
`time.time_ns` in every Python process the runner starts (the runner's own `sitecustomize` tracer stays first; the
shim lives outside every tree, `E:\COBOL-coord\scratch\pb4353\shim\usercustomize.py`), on this branch at 369c66416.

- Unshifted: 137 of 137 GREEN (exit 0).
- +3 days: 6 RED. +45 days: 7 RED, the same six plus `scripts/orchestrator/test_alloc.py`.

Every one of the seven is an artifact of shifting ONE clock: each compares Python's shifted clock with a second, real
one that the shim cannot move. None plants a date that the wall clock overtakes, so no other self-test expires within
45 days:

| Self-test | The real clock it compares with |
|---|---|
| `scripts/spec/impact_store.py` | temp-file and work-directory mtimes (`tidy`'s age) |
| `scripts/gate_slot.py` | the holder process's start time (the long-hold arm reads 72.0 h) |
| `scripts/prune_worktrees.py` (15 arms) | scratch commits made at real time (`idle 72.0 h`, `--min-age`) |
| `scripts/orchestrator/test_plan_wave.py` | branch-touch and dispatch-ledger ages (`--min-age`) |
| `scripts/orchestrator/test_alloc.py` | the lock file's mtime (`coord.py` `LOCK_STALE_S`: every lock reads stale, so the parallel arm races) |
| `scripts/orchestrator/test_orchestrate_campaign.ps1` | the meter reading the PowerShell side wrote (`meter reading 72.0 h old`) |
| `scripts/orchestrator/test_orchestrate_meter.ps1` | the same meter path (a stale reading takes the branch that reads `OWNER-QUESTIONS.md`) |

The sweep is therefore no standing guard as it stands. A guard that catches the next fixture dated near its authoring
day needs a clock every timestamp source agrees on, and that is kb/Work PB4358's design question.

queue bounced on this self-test carry no fault of their own: #960 and #961 are re-armed once main carries this fix.
