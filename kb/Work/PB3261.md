# PB3261 — MOVE receiving-subscript evaluated before sending reference modifier

**Mechanism.** `MOVE X(1:L) TO T(I)` is emitted as `CobolTable.At(TB.T, CobolTable.Occ(I, _P_3)) = CobolString.Store(CobolString.RefMod(X, ...), 4)`. C# evaluates the ref-returning left operand first, so the receiving subscript is range-tested before the sending reference modifier is evaluated. When both are out of range the wrong exception condition is raised and the wrong USE declarative is selected.

**Repro.** `E:\COBOL-coord\scratch\w1091\w1091e\probe\p8gr11.cob` at `--std 2002`, I=9 (T OCCURS 3), L=50 (X is X(8)). `MOVE X(1:L) TO T(I)` runs `SEL EC-BOUND-SUBSCRIPT`; the correct result is EC-BOUND-REF-MOD. The mirror `MOVE T(I) TO X(1:L)` is already correct. Generated C#: `p8gr11.g.cs:220` in that probe folder.

**Rule.** §14.9.25.4 1): "the reference modifier, subscript, or function-identifier is evaluated only once, immediately before data is moved to the first of the receiving operands" (`cite.py --check 14.9.25.4` OK, re-run for this note). Declarative selection is §14.9.49.4 GR11 as cited by the PB370 implementer report w1091e; the clerk did not re-derive that number. Open question for the implementer: run `cite.py --check` on the GR11 clause before it enters a code comment or golden.

**Code site.** `src/Cobol.Net.Compiler/CodeGen/` MoveEmitter's store path (the `<ref> = <value>` shape); the store builder is the one place to fix (evaluate the sending operand, then the receiving address). The implementer locates the exact member (`python scripts/spec/where.py 14.9.25.4`).

**Siblings to sweep (every `<ref> = <value>` store whose receiver is subscripted, reference-modified or ODO).** `ReceivingStore`, the arithmetic GIVING/COMPUTE receivers, SET, STRING/UNSTRING INTO.

**Fix shape.** One store primitive that evaluates the sending side first, shared by every receiver arm (rule 5: not a per-verb patch). Goldens: a two-order MOVE (both out of range, each order), in a program and with the GIVING/COMPUTE siblings. Fixing it lets PB370's GR-14.9.49.4-11 close.
