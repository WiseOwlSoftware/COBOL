## What the code does today

- `src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4#objectReference` = `dataReference | predefinedNull | SELF | SUPER`,
  referenced only by `Core/CobolOO.g4#invokeTarget`, `inlineMethodInvocation`, `setObjectReferenceStatement` and
  `raiseStatement`. The `identifier`/`dataReference` tier never reaches SELF/SUPER; there is no object-view (`AS`)
  production and no `object-class-name OF SUPER` production; RAISE and INVOKE's receiver do not take an inline
  invocation (SET … TO does).
- Receiving-operand screens: `src/Cobol.Net.Compiler/Binding/Procedure/ExpressionBinder.cs#ResolveReceiving` names
  EXCEPTION-OBJECT (COBOLNET2196), LINAGE-COUNTER and constant-names; `OoBinder.cs#OoBindSetObjectRef` repeats the
  EXCEPTION-OBJECT arm (PB1008); `SetFormatSelection.cs` classifies EXCEPTION-OBJECT only; NULL/SELF/SUPER never
  reach either screen because they are not identifiers there, so they are refused by the §8.9 reserved-word check
  (COBOLNET0901) — the right verdict for the wrong rule, and the verdict flips to SILENT ACCEPTANCE the moment the
  identifier tier is widened (PB1425's refuter evidence for SR-8.4.3.8.3-2).
- INVOKE receiver screen: `OoBinder.cs#OoBindByReceiver` refuses NULL (COBOLNET0823, citing a rule that does not
  exist) where §14.9.23.4 GR5 makes it a run-time EC-OO-NULL; the inline-invocation SR2 screen runs on the first
  segment only (`OoBinder.InlineInvocation.cs#OoBindInlineInvocation`, PB1429 — a chained universal temp ends in the
  COBOLNET2362 internal error).

Measured (this tree): `INVOKE NULL "GREET"` → 0823; `SET U TO D AS UNIVERSAL` → 0901 'AS'; `INVOKE K26B OF SUPER
"SPEAK"` → 0901 'SUPER'; `IF O = SELF` → COBOL0001; `RAISE D :: "ME"` → COBOL0307 '::'; `SET NULL TO O` → 0901;
`MOVE A1 :: "UNIV" :: "GETNAME" TO W` → COBOLNET2362 (internal error).

## Proposed single structure

1. **Grammar**: one `objectIdentifier` alternative set inside the identifier rule — `inlineMethodInvocation`,
   `objectView` (`identifier AS {object-class-name [FACTORY OF] [ONLY] | interface-name | UNIVERSAL}` — a new
   UNIVERSAL token, edition-gated 2002), `predefinedObject` (`EXCEPTION-OBJECT | NULL | SELF | [object-class-name OF]
   SUPER`), so EVERY identifier position (relations, arguments, SET senders, RAISE, INVOKE receiver, property
   qualifier) is automatic. `objectReference` is deleted and its four users take `identifier` (rule 4: no alias).
2. **Binder**: each format binds to a `Place` with an `ObjectRefDescriptor` (SELF/SUPER: ACTIVE-CLASS, not universal —
   §8.4.3.8.3 SR7; NULL: class object, not universal — §8.4.3.7.3 SR2; object-view: the named description plus a
   run-time conformance check raising EC-OO-CONFORMANCE, declared in `ExceptionCatalog` and raised nowhere today).
   Position rules become predicates on the bound Place, asked by the ONE consumer of each position: SR3's
   SUPER-only-as-invocation/property-object; §8.4.3.4.3 SR2 on EVERY inline segment's receiver; §14.9.23.3 SR1 (an
   object reference) with NULL admitted and GR5's EC-OO-NULL at run time.
3. **ONE receiving-operand screen** (`ExpressionBinder.ResolveReceiving`) that enumerates every non-receivable
   identifier FORM with its rule and its own descriptor — EXCEPTION-OBJECT (§8.4.3.6.3 SR1), NULL (§8.4.3.7.3 SR1),
   SELF/SUPER (§8.4.3.8.3 SR2), object-view (§8.4.3.5.3 SR2), inline invocation (§8.4.3.4.3 SR1), function-identifier,
   ADDRESS OF PROGRAM (§8.4.3.13.3), constant-name, LINAGE-COUNTER — as a table keyed by the bound form, and every
   receiving position (SET targets included) resolves through it. Drift test: every identifier-form case of the
   binder's form enum has a row (a new form cannot be added without deciding its receiving rule).
