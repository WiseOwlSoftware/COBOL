# PB403 — two EXIT placement rules, each half-built, and an emitter invariant the binder never establishes

## 1. The mechanism

**(a) SR8 is two sentences and only the second is enforced.** The CYCLE prohibition inside an
exception-checking PERFORM is checked — `EcBinder.ExceptionPerform.cs:249-254` raises COBOLNET1604, with the
`ExitCyclesOfThisPerform` walker at `:308-319`. The **placement** sentence — EXIT PERFORM may be specified only
in an inline or exception-checking PERFORM — is checked nowhere. `ControlFlowBinder.BindExit`
(`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/ControlFlowBinder.cs:242`) returns
`new BoundExitPerform(e.CYCLE() is not null)` unconditionally, with no enclosing-PERFORM test at all.

The consequence is not a silent no-op. `StatementEmitter.Visit(BoundExitPerform)` dispatches on
`_dispatchState.F3Cur.Region`, and its `_ =>` arm (`src/Cobol.Net.Compiler/CodeGen/StatementEmitter.cs:143`)
emits a bare C# `break;` into the paragraph dispatcher's `switch (__pc)` **without advancing `__pc`**. The
emitted `break` leaves the switch, the enclosing `while` re-tests the unchanged `__pc`, and the paragraph runs
again forever. That arm's own comment calls it a "defensive fallback (SR8: never reached for a valid bind)" —
an invariant the binder never establishes, so the arm is **live production behaviour, not dead code**, and the
comment is false as written. This is the two-arm-dispatch shape with one arm fixed, and the fallback comment
is the tell.

**(b) SR7 confines EXIT PROGRAM to a program procedure division, and the binder rejects exactly one of the
non-program source elements.** 14.2.2 SR10 names five source elements that may carry a Format-1/2 procedure
division — function definition, function prototype, method definition, program definition, program prototype —
so a FUNCTION definition's procedure division is not a program's. `BindExit`'s PROGRAM arm
(`ControlFlowBinder.cs:243-257`, the `host.InMethod` test at `:245`) tests only that one predicate and lets the function-definition arm through, even
though the predicate it needs already exists as `host.UdfSelfName is not null`
(`src/Cobol.Net.Compiler/Binding/Bound/StatementBinder.cs:114`) and is used that way by
`CallBinder.cs:56`. The consequence is not only acceptance: the generated function class receives the
PROGRAM-activation machinery — a private `__asCalled` field and a `throw new ProgramReturn()` — so
program-shaped emission leaks into a function definition.

## 2. The rules, quoted, each `--check`ed on this tree

    python scripts/spec/cite.py --check 14.9.14.3 "The EXIT PERFORM statement may be specified only in an inline or exception-checking PERFORM statement"
      -> OK  §14.9.14.3 8)  (Syntax rules)
    python scripts/spec/cite.py --check 14.9.14.3 "An EXIT PROGRAM statement may be specified only in a program procedure division"
      -> OK  §14.9.14.3 7)  (Syntax rules)
    python scripts/spec/cite.py --check 14.2.2 "Formats 1 and 2 may be specified in a source element if and only if that source element is a function definition, a function prototype definition, a method definition, a program definition, or a program prototype definition"
      -> OK  §14.2.2 10)  (Syntax rules)
    python scripts/spec/cite.py --check 14.9.14.4 "The execution of an EXIT PERFORM statement without the CYCLE phrase causes control to be passed to an implicit CONTINUE statement immediately following the END-PERFORM phrase"
      -> OK  §14.9.14.4 5) a)  (General rules)

The GR5 a) line is quoted because it is what makes SR8 a *syntax* rule rather than a stylistic one: the
statement's meaning is defined only relative to a matching END-PERFORM, so outside one there is nothing for it
to mean — which is why the emitter had to invent something and invented an infinite loop.

## 3. Expected vs observed — RE-MEASURED ON HEAD (89044aa0), both parts

**SR8.** The probe is five lines: `PROGRAM-ID. PBXPRF08.` / `PROCEDURE DIVISION.` / `MAIN-PARA.` /
`DISPLAY "A".` / `EXIT PERFORM.` / `DISPLAY "B".` / `STOP RUN.` — no PERFORM of any kind anywhere.

    $ cobol.exe sr8-exit-perform-outside.cob --std 2023
      (no output — exit 0, empty diagnostic stream)

    $ dotnet sr8-exit-perform-outside.dll        # run with an 8-second hard timeout
      KILLED after 8s (did not terminate) — 112966 lines of output, every one "A"

The generated `p.g.cs` is verbatim `case 0: { System.Console.WriteLine("A"); break; System.Console.WriteLine("B"); throw new StopRun(); }`
— the `break` leaves the switch without changing `__pc`, and the dispatcher loop re-enters paragraph 0.
Expected: REJECTED at compile time with a diagnostic in the existing EXIT-placement family (COBOLNET0827, as
already used for SR7 and SR9). Observed: accepted with no diagnostic at all, and a program that never
terminates.

**SR7.** The probe is a program that calls `FUNCTION UXSR07`, whose FUNCTION-ID definition ends its procedure
division with EXIT PROGRAM.

    $ cobol.exe sr7-exit-prog-in-func.cob --std 2023 --run
      X=0014
      sr7-exit-prog-in-func.cob(29,12): warning COBOLNET0903: the EXIT PROGRAM statement is obsolete as of
      COBOL-2023 ... (warning only, the element remains conforming)                               [exit 0]

Expected: REJECTED, COBOLNET0827 exactly as it is raised for the method arm. Observed: accepted with only the
archaic warning, and it runs. The generated function class carries the `__asCalled` / `ProgramReturn` pair. The
existing conformance test `OoSpineTests.ExitPlacement_0827` is the 14.9.14.3 SR7 fact and covers the METHOD arm
only, which is why the row is PARTIAL rather than NOT-IMPLEMENTED — and why a green gate did not see this.

## 4. The code site and the shape of the repair

- `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/ControlFlowBinder.cs:242` — the unconditional
  `return new BoundExitPerform(...)`.
- `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/ControlFlowBinder.cs:243-257` — the PROGRAM arm, whose only
  context test is `host.InMethod` at `:245`.
- `src/Cobol.Net.Compiler/CodeGen/StatementEmitter.cs:130-143` — `Visit(BoundExitPerform)` and its `_ =>`
  fallback arm.
- The enforced half of SR8: `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/EcBinder.ExceptionPerform.cs:249-254`.
- The predicate SR7's missing arm needs: `src/Cobol.Net.Compiler/Binding/Bound/StatementBinder.cs:114`.

**Repair shape.** SR7's missing arm is genuinely one predicate — `host.UdfSelfName is not null` beside
`host.InMethod`, with the same COBOLNET0827 — because `UdfBinder` and `OoBinder` each already own the
mirror-image "only in a function/method definition" check for EXIT FUNCTION / EXIT METHOD; this is the third
corner of a square with three sides drawn. SR8 is not: the binder needs to know **whether it is inside an
inline or exception-checking PERFORM**, which is the same "where am I bound?" question PB404 names for the
declarative rules. Build it once (see PB404 §4) rather than adding a per-verb flag. Once SR8 is enforced,
the emitter's `_ =>` arm becomes genuinely unreachable and should be turned into a throw or an assertion — a
`break`/`continue` fallback that silently means something is how this survived.

## 5. The sibling sweep the fixer must do

- **`Visit(BoundExitPerform)`'s `_ =>` arm is not the only bare `break` aimed at the dispatcher's switch.**
  `Visit(BoundExitParagraph)` (`StatementEmitter.cs:112`), `Visit(BoundExitSection)` (`:121-129`) and
  `Visit(BoundNextSentence)` (`:199-207`) all emit `break;` too, and inside an inline PERFORM that `break`
  binds to the PERFORM's C# loop. Those are **measured live defects on conforming source** — see PB405 and
  PB414. This note's SR8 case is the same emitter mistake reached through a missing screen instead of through
  legal source, and the three should be fixed as one structural change to how the dispatcher is left.
- **Every other EXIT format's placement rule.** SR9 (EXIT SECTION only in a section) IS enforced
  (`ControlFlowBinder.cs:258-265`); check EXIT PARAGRAPH, and check that each raises the same COBOLNET0827
  family rather than inventing a code.
- **The other two source elements 14.2.2 SR10 names** — function *prototype* and program *prototype*
  definitions. A prototype carries only a header, so EXIT PROGRAM may be unreachable there; confirm it rather
  than assume it, because "unreachable" is a probe to run.
- **GOBACK is the sibling verb**: 14.9.18 has its own placement family and shares `EcBindRaising`; PB404 owns
  that half, but a single context probe serves both notes.

## 6. Rows

- **`SR-14.9.14.3-8`** (PARTIAL) — sentence 2 (CYCLE) enforced as COBOLNET1604; sentence 1 (placement) not
  enforced, and the accepted program hangs. Editions: EXIT PERFORM is a 2002 introduction so the placement half
  spans 2002/2014/2023; the exception-checking-PERFORM half and the CYCLE prohibition are 2023-only.
- **`SR-14.9.14.3-7`** (PARTIAL) — the METHOD arm is enforced and tested
  (`conformance-test:OoSpineTests.ExitPlacement_0827`); the FUNCTION-definition arm is not. Rule text is
  edition-stable; the function arm is reachable only from 2002, when user-defined functions arrive.
