# PB6038 - the 2002 and 2014 arms of the data-name-n screen's subscript sentence

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs` (`DataBinder.OperandSubscriptRule`, `DataBinder.ScreenDataNameShape`)

**What happens.** kb/Work PB2041 made every `ClauseDataName` / `ClauseDataNameSubscripted` caller pass its clause's own subscript rule
through `DataBinder.OperandSubscriptRule(y1985, y2023)`, which gives the oldest and the newest edition each clause's own
rule. At 2002 and 2014 that helper still returns the one fixed sentence, `NotSubjectToOccurs`,
with no citation, so `OCCURS ... KEY K(1)` at `--std 2002` reads "the operand shall not be subject to any OCCURS clauses", false
for a key. At 2002 a data-name-n includes "qualification and subscription if needed" (§2002:5.1.3), so which clauses refuse a
subscript at 2002 at all is the 2002 read's question (kb/Work PB5602 settled the file-control keys), and 2014 restricts it clause
by clause (§2014:E.2 item 25).

**Owed.** For each caller (OCCURS KEY / DEPENDING / CAPACITY, RENAMES, RECORD DEPENDING, LINAGE, APPLY COMMIT, PADDING,
ASSIGN USING, FILE STATUS, RECORD / ALTERNATE / RELATIVE KEY, their SOURCE phrase, COLLATING SEQUENCE OF, the SORT and MERGE
file keys): the 2002 and 2014 rule, quoted and cited (`cite.py --check`), or the finding that the edition admits the subscript
(then the screen accepts it, as `admitsSubscript2002` does for the PB5602 clauses). `OperandSubscriptRule` gains the two arms and
`NotSubjectToOccurs` goes. Frozen until 1985 is complete (owner, 1985 first).
