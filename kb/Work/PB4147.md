# PB4147 — one shared refusal registry serializes the merge queue

## Measured

- **Which file holds landings.** The landing lane's attempt logs record each `DRIVER FILE QUEUED` hold (kb/Work PB3642:
  the merge queue merges with git's plain line merge, without the repository's merge drivers, so `enqueue.py` admits one
  open pull request per driver-merged file). Counted over all 821 attempt logs: `conformance-suite/wiseowl/diagnostics.json`
  61, `tests/version-matrix/traceability-inventory.json` 10 (kb/Work PB4148), `kb/Work/PB*.md` 7 (same-note edits),
  `PublicAPI.Unshipped.txt` 1.
- **What it costs.** Since 2026-10-28, 112 landings: review CLEAN to enqueued median 7 min, p90 58; enqueued to merged
  median 21, p90 61, against the owner's 30- and 15-minute bars (kb/Work PB3638). The merge queue builds up to 5 groups
  at once (`ruleset-main.json`, `max_entries_to_build` 5), but a wave of N branches that each add a refusal lands one
  at a time, about 25 to 30 minutes apart (14.5 min median merge-group CI plus the queue's wait). On 2026-10-30 at
  13:18 PDT three branches (17b-15, 571-7, 339-21) waited behind one (#826) for exactly this reason.

## Why it is a design defect, not a tuning problem

`diagnostics.json` is one JSON object, test id -> `{"refuse-at": [...], "expect": "..."}`, read by
`conformance-suite/harness/generate.py` (`DIAGNOSTICS_PATH`) and written by every fix that adds a negative golden. Two
branches adding DIFFERENT refusals touch the same file, and only a merge driver (`merge=cobol-keyed-object`) can merge
them. The merge queue cannot run that driver. The DEVLOG had the same shape and was fixed the same way (kb/Work PB3025:
one file per entry). The shape that makes the next case automatic (CLAUDE.md rule 5) is the same here: **a refusal's
facts live in a file of their own, so two refusals never share a file and no merge driver is needed.** For example:

- one file per refusal (`conformance-suite/wiseowl/diagnostics/<test id>.json`), or
- the refusal's `refuse-at` / `expect` in the refused test's own header, which `generate.py` already reads.

The implementer chooses between these from `docs/rearchitecture/DESIGN-conformance-suite.md` (§4, the `wiseowl/` files),
and records the choice there. The acceptance is mechanical: `merge_drivers.DRIVERS` and `.gitattributes` no longer name
the registry; two branches adding different refusals merge with git's plain merge; `enqueue.py` no longer holds a
landing on a refusal; and a drift test keeps any single shared file from coming back.

## Landing

For the next implementer: `conformance-suite/harness/generate.py#sidecar_key` owns the rule for a registry file's name (reuse it, as `impacted_tests.registry_test` does; never re-split a name) and `#load_sidecars` the directory read, its problems a `(path, message)` `Problem`; `scripts/merge_drivers.py#Layout` keys the elements of ONE array only, so a new registry two landings both add to is one file per entry, not a driver (`MergeDriverDriftTests.TheSuiteRegistries_AreOneFilePerTest_AndNoDriverGovernsThem` fails on a shared file or a driver on a path of the suite); the dispatch-spec and other `str.format` templates in `.claude/skills/workstream/templates/` take no brace in their text (a `{"refuse-at": ...}` example is a KeyError in `make_dispatch_specs.render`, which the self-tests catch); a new registry file written by a Python self-test states `newline="\n"` (the line-endings audit).

The registries are one file per test: `conformance-suite/wiseowl/diagnostics/<id>.json` (3,062 refusals) and
`conformance-suite/wiseowl/options/<id>[.<step file>].json` (5 options), read by `generate.sidecar_key` / `load_sidecars`.
`merge_drivers.DRIVERS` lost `cobol-keyed-object` (and `Layout` its object form), `.gitattributes` lost both lines, and
`MergeDriverDriftTests.TheSuiteRegistries_AreOneFilePerTest_AndNoDriverGovernsThem` keeps a shared registry file, and a
driver on any path of the suite, from coming back. A branch cut before this landing that adds a refusal to the deleted
`diagnostics.json` meets a modify/delete conflict at its landing merge: its finisher writes the entry as the file
`wiseowl/diagnostics/<test id>.json` (`{"refuse-at": [...], "expect": "..."}`) and takes the old file's deletion.
