# PB4389 - the witness for the former access-text leaks does not reach the Reroot leak

**Sites:** `tests/WiseOwl.Cobol.Tests.Unit/ModelAccessStructureTests.cs:23` (`ModelAccessStructureTests`, its class summary at line 15 and its `Source` constant; `EveryFormerLeak_BindsToStructure_AndEveryNameIsAnIdentifier`), `src/WiseOwl.Cobol.Compiler/Binding/Model/AccessPath.cs:23` (`AccessPath.Reroot`), `src/WiseOwl.Cobol.Compiler/CodeGen/ProgramEmitter.cs:551` (`ProgramEmitter.AnchorPlace`).

**Read at:** commit 245092793, the tip of branch `worktree-wf_d2f43316-4ca-4` (PB4320, in the merge queue); the files are not yet on origin/main.

The witness's summary, and DEVLOG 2930, say its program group exercises every former leak. Its `Source` (PB4320A to PB4320D) has a carrier-resident GLOBAL linkage formal, a Format-2 table SORT and a RECURSIVE program with a GLOBAL item, but no GLOBAL file whose FILE STATUS item a contained program's I/O updates (ISO 12.4.5.8.4 GR1 NOTE 1, the case `AccessPath.Reroot` documents). No assertion reaches `AccessPath.Reroot` or `ProgramEmitter.AnchorPlace`. The second of the four leaks, `Reroot` joining `__outer.` or the container's class name onto `RootFieldSegment.CsField`, therefore has no structural pin: reintroducing it passes this class.

Fix direction: add a program to `Source` with a GLOBAL file and FILE STATUS item that a contained program reads or writes through, and assert on the bound `AccessPath` (a `RootFieldSegment` whose `CsField` is an identifier with no `__outer.` and no container class name), which is the check the other leaks already get. Mutate `Reroot` to join the text again and see the test fail. Run `python scripts/spec/cite.py --check 12.4.5.8.4 "NOTE 1"` on the GR1 note before writing it into the test comment (rule 1).

Harm: no user program is affected (`process_only`): the compiler is right today, the witness is incomplete.
