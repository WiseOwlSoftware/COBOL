# PB3514 — function-result DISPLAY text versus GnuCOBOL per-function widths

The report classes this a decision, not a bug. After PB3505, DISPLAY of a numeric DATA ITEM follows GnuCOBOL 3.2.0's
default form; DISPLAY of a numeric FUNCTION result still goes through `OperandText#NumericExprText` (DOC-A.1-92), whose
widths differ from GnuCOBOL's per-function widths. Precedence (CLAUDE.md rule 1): ISO §14.9.11.4 GR1 leaves the device
conversion to the implementor, so the order is ISO (silent), then GnuCOBOL; GnuCOBOL's non-ISO extensions are not copied.
PB3505 rejected copying GnuCOBOL's per-function widths, its 100-digit FUNCTION PI and its float image; the question to
adjudicate is whether the rejection stands for the widths.

## Repro (`s1.cob`, relevant lines; items `U1 PIC 9(5)V99 VALUE 12.5`, `S1N PIC S9(5)V99 VALUE -12.5`)

```cobol
    DISPLAY "FN1=" FUNCTION LENGTH(U1) "|"
    DISPLAY "FN2=" FUNCTION NUMVAL("12.50") "|"
    DISPLAY "FN3=" FUNCTION MAX(U1 S1N) "|"
    DISPLAY "FN4=" FUNCTION ABS(S1N) "|"
    DISPLAY "FN5=" FUNCTION PI "|"
    DISPLAY "FN6=" FUNCTION INTEGER(S1N) "|"
```

## Adjudication 2026-10-25 (mythos lane, pinned main 51103b9a1)

**Final verdict:** DEFECT (adjudicator said DOCUMENT; overturned by the refuter and settled by the orchestrator, below)  
**Checkpoint (full record):** `E:/COBOL-coord/scratch/mythos/adj-20261025/PB3514.json`

**Expected from the spec:** ISO leaves the DISPLAY text of a numeric function result to the implementor (14.9.11.4 GR1; 15.4; 15.4.1; A.1 items 56 and 92): no rule fixes its width. CLAUDE.md rule 1's precedence (owner 2026-08-08) then gives the latitude to GnuCOBOL 3.2.0, whose width is a deterministic function of the argument description (refuter probe E:/COBOL-coord/scratch/mythos/adj-20261025/refute-PB3514/p3.cob, output p3.gnu.txt). **Citations checked:**

- OK  §15.4 (Returned values): The evaluation of a function produces a returned value in a temporary elementary data item.
- OK  §15.4.1 (Numeric and integer functions): When native arithmetic is in effect, the characteristics and representation of the returned value are defined by the implementor.
- OK  §15.4.1 (Numeric and integer functions): the returned value for numeric and integer functions is contained in a temporary standard data item in the intermediate form defined for the arithmetic mode in effect
- OK  §A.1 56) DISPLAY statement (data conversion). This item is required. This item shall be documented in the implementor's user documentation.
- OK  §A.1 92) Function returned values (characteristics, representation, and returned value for native arithmetic). This item is required.

## Landed (wave 20261716, group C, 2026-10-26)

**Re-probe.** The note reproduced on the wave's own build (`FN2=12.50`, `FN3=12.50`, `FN4=12.50`, `FN6=-13` against GnuCOBOL's
`00000012.5`, `00012.50`, `+00012.50`, `-000000013`); a matrix over every numeric function family, argument shape and item
usage (the PB3514 probe matrix, run against `cobc` 3.2.0) agreed with the note and showed the cause is one: GnuCOBOL's returned
value is a temporary with a DESCRIPTION, and DISPLAY shows it as it shows any item of that description.

**The mechanism.** GnuCOBOL 3.2.0's source (`libcob/intrinsic.c`) gives each function's temporary one of three descriptions: a copy
of the argument it returns (ABS, MAX, MIN, odd MEDIAN, MEAN of one argument), an unsigned DISPLAY integer of fixed width
(DATE-OF-INTEGER eight digits, DAY-OF-INTEGER seven), or what `cob_alloc_field` derives from the value (trim the fraction's zeros;
a 4-byte item of 9 positions under 2**31 with a scale under 10; an 8-byte item of 20 under 2**63 with a scale under 19; else a
DISPLAY item of its digits; signed exactly when negative). One catalog column, `IntrinsicSig.DeviceForm` (`FunctionDeviceForm`:
`Value` the default, `Argument`, `FixedDigits`, `Literal`), says which; `OperandText.AsDeviceString` asks `FunctionDeviceText.Of`
under `--numeric-display decimal`, which builds one `FunctionValueField` (value and description) per argument of a selecting
function, so each argument is read once and a nested function hands its caller the temporary it made, and the runtime picks
(`FunctionValueField.Max/Min/Median/Abs`); every other function's text is `CobolNum.DeviceFunctionText` of its value (a scaled
integer and an SDIDI reach one rule). MOVE, STRING, INSPECT and the comparisons keep DOC-A.1-92's literal form (`AsString`), as a
numeric item's MOVE keeps GR6's digits; `--numeric-display digits` keeps the literal form in DISPLAY too. The binder names the
function it folded (`BoundNumLiteral.FoldedFunction`) so a LENGTH/BYTE-LENGTH fold shows as the literal (GnuCOBOL folds exactly these)
and the ALGEBRAIC family as its value's description (GnuCOBOL evaluates them at run time).

**Not copied (documented in DOC-A.1-92, pinned by `pb3514_function_result_device_form_not_copied`).** A 10-digit value in GnuCOBOL's
9-position item loses its high-order digit, and its DISPLAY item's digit count is a GMP size estimate that can exceed the true count
by one; the positions here are `max(container positions, the value's digits)`. A binary64 result (the float family natively, any
function given a COMP-1/COMP-2 item) keeps the floating-point image (PB3505): `SQRT(4)` is `2`, not `000000002`. The earlier
rejection of the 100-digit PI stands.

**Sweep.** The other arms of the dispatch: every numeric function of the catalog went through the probe matrix; the text channels
(`AsString`, `NumericExprText`, the MOVE hoist `SendingValueTemp`, CALL BY CONTENT) are untouched; the only DISPLAY reader is
`AcceptDisplayEmitter`. A side effect, an improvement: `DISPLAY FUNCTION MAX(BIG F)` over a 31-digit item no longer aligns its
arguments to a common scale and ends EC-SIZE-OVERFLOW for a value that is perfectly representable; it shows BIG. 138 conformance-suite
expected outputs and the expectations of 10 C# tests moved; every changed line was verified to keep its non-numeric skeleton and every numeric
value (a width, sign or point-spelling change only), and the new goldens were cross-checked line by line against `cobc`.

**Goldens.** `15.4.1-Numeric-and-integer-functions/pb3514_function_result_device_form` (the 1989 module), `…_abs` (2002-2014
functions, signs and usages), `…_comma` (DECIMAL-POINT IS COMMA), `…_standard_decimal` (the SDIDI lane), `…_not_copied`, and
`wiseowl/cases/14.9.11-DISPLAY/pb3514_function_result_digits_form` (`--numeric-display digits`). Unit: `FunctionDeviceTextTests`,
`FunctionDeviceFormDriftTests`, a reader pin in `NumericDisplayFormDriftTests`.

**Leads for the registrar.** `FUNCTION LENGTH(FUNCTION ABS(S))` is 30 here (PB1398's S9(30) item) where GnuCOBOL's is the size of the
temporary (7): DISPLAY now adopts the description, LENGTH of the same temporary does not (a run-time, value-dependent size for the
`Value` shape). `FUNCTION NUMVAL-F` of a text GnuCOBOL accepts but TEST-NUMVAL-F rejects (`"1.5E2"`: no sign in the exponent) answers 0 here
and 150 there: an invalid-argument value, not this note's.

**For the next implementer.** `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/FunctionDeviceText.cs#Of` owns what DISPLAY writes for a numeric
function's returned value (one entry, asked only by `OperandText.AsDeviceString`); the per-function shape is the catalog column
`IntrinsicSig.DeviceForm` (`Binding/IntrinsicCatalog.cs`, default `Value`), so a new function needs no edit and a new SHAPE needs a case in
`FunctionDeviceText.CallField` plus the drift test's list. `src/WiseOwl.Cobol.Runtime/Values/Numeric/CobolNum.DeviceFunction.cs#ReturnedValueProfile`
is the one statement of the value-derived description: REUSE it (`FunctionValueField.OfValue` already does), do not rewrite the 9/20/own-digits
rule. `FunctionValueField.cs` carries a value AND its description, so a nested function hands its caller the temporary it made (ABS of
INTEGER is signed). Traps: `CobolDec.FromApproximation` may be called only for a function's binary64 RESULT (`FloatItemSdidiLiftDriftTests`;
a float ITEM arrives through `OfFloatItem` with the one SDIDI lift); a hand-written `is not RefModPlace` is refused by
`PlaceDenotedItemDriftTests` (ask `Place.DenotedItem`); `dotnet test --filter` is hook-refused for a bare `~term`, use `FullyQualifiedName~`;
the conformance-suite `.out` files are re-blessed by compiling each failing (edition, id) as the runner does and accepting only a
skeleton-and-value-identical output; a display name with a long id is truncated by xunit (resolve it by prefix in the manifest).
GnuCOBOL's `libcob/intrinsic.c` (`cob_alloc_field`, `cob_intr_max`, `cob_intr_abs`, `cob_intr_median`) and `termio.c` (`pretty_display_numeric`)
are the references; the probe matrix lives with the PB3514 report.
