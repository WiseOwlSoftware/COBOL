# PB3514 — function-result DISPLAY text versus GnuCOBOL per-function widths

The report classes this a decision, not a bug. After PB3505, DISPLAY of a numeric DATA ITEM follows GnuCOBOL 3.2.0's
default form; DISPLAY of a numeric FUNCTION result still goes through `OperandText#NumericExprText` (DOC-A.1-92), whose
widths differ from GnuCOBOL's per-function widths. Precedence (CLAUDE.md rule 1): ISO §14.9.11.4 GR1 leaves the device
conversion to the implementor, so the order is ISO (silent), then GnuCOBOL; GnuCOBOL's non-ISO extensions are not copied.
PB3505 rejected copying GnuCOBOL's per-function widths, its 100-digit FUNCTION PI and its float image; the question to
adjudicate is whether the rejection stands for the widths.

## Repro (`s1.cob`, relevant lines; items `U1 PIC 9(5)V99 VALUE 12.5`, `S1N PIC S9(5)V99 VALUE -12.5`)

```cobol
    DISPLAY "FN1=" FUNCTION LENGTH(U1) "|"
    DISPLAY "FN2=" FUNCTION NUMVAL("12.50") "|"
    DISPLAY "FN3=" FUNCTION MAX(U1 S1N) "|"
    DISPLAY "FN4=" FUNCTION ABS(S1N) "|"
    DISPLAY "FN5=" FUNCTION PI "|"
    DISPLAY "FN6=" FUNCTION INTEGER(S1N) "|"
```

| Line | GnuCOBOL 3.2.0 (`s1.gnu.txt`) | WiseOwl (`s1.we.txt`, function arm untouched by PB3505) |
|---|---|---|
| FN1 | `7` | `7` |
| FN2 | `00000012.5` | `12.50` |
| FN3 | `00012.50` | `12.50` |
| FN4 | `+00012.50` | `12.50` |
| FN5 | 100-digit pi | `3.141592653589793` |
| FN6 | `-000000013` | `-13` |

## Options for the owner

(a) Keep the current text and record it in DOC-A.1-92 as the decided form. (b) Adopt GnuCOBOL's per-function widths (a
per-function table; FUNCTION PI and floats still not copied). Decide together with PB3513, which shares the latitude.

## Adjudication 2026-10-25 (mythos lane, pinned main 51103b9a1)

**Final verdict:** DEFECT (adjudicator said DOCUMENT; overturned by the refuter and settled by the orchestrator, below)  
**Checkpoint (full record):** `E:/COBOL-coord/scratch/mythos/adj-20261025/PB3514.json`

**Expected from the spec:** ISO leaves the DISPLAY text of a numeric function result to the implementor (14.9.11.4 GR1; 15.4; 15.4.1; A.1 items 56 and 92): no rule fixes its width. CLAUDE.md rule 1's precedence (owner 2026-08-08) then gives the latitude to GnuCOBOL 3.2.0, whose width is a deterministic function of the argument description (refuter probe E:/COBOL-coord/scratch/mythos/adj-20261025/refute-PB3514/p3.cob, output p3.gnu.txt). Observed by the adjudicator under GnuCOBOL 3.2.0 (p1.gnu.txt, p2.cob): ABS(S1N) = +00012.50, INTEGER(S1N) = -000000013, MAX(I1 I2) = 007, MAX(7 -14) = 7.

**Citations checked:**
- OK  §14.9.11.4 1)  (General rules): Any conversion of data required between literal-1 or the data item referenced by identifier-1 and the device is defined by the implementor.
- OK  §15.4 (Returned values): The evaluation of a function produces a returned value in a temporary elementary data item.
- OK  §15.4.1 (Numeric and integer functions): When native arithmetic is in effect, the characteristics and representation of the returned value are defined by the implementor.
- OK  §15.4.1 (Numeric and integer functions): the returned value for numeric and integer functions is contained in a temporary standard data item in the intermediate form defined for the arithmetic mode in effect
- OK  §A.1 56) DISPLAY statement (data conversion). This item is required. This item shall be documented in the implementor's user documentation.
- OK  §A.1 92) Function returned values (characteristics, representation, and returned value for native arithmetic). This item is required.

**Repro and observed:** E:/COBOL-coord/scratch/mythos/adj-20261025/PB3514/p1.cob (free format; FN1-FN6 are the note's lines, K1-K8 compare folded and computed references). **Code site:** src/WiseOwl.Cobol.Compiler/CodeGen/Emit/OperandText.cs#NumericExprText (unchanged); docs/CONFORMANCE.md DOC-A.1-92 (first row)

**Action:** DISPLAY of a numeric or integer function result follows GnuCOBOL 3.2.0's form. The 2026-07-29 "deliberately not matched" choice (commit 943cf30b3, DOC-A.1-92) predates the precedence and is withdrawn. The adjudicator's proposed CONFORMANCE.md text and its witness (12.50 / -13) are NOT used: the refuter found errors in the text (GnuCOBOL's widths are not unstable and do not depend on folding, only LENGTH folds; S9(30) and S9(21)V9(9) both have 30 digit positions; the temporary is native-arithmetic only, 15.4.1). Fix: make the function-result DISPLAY form follow the argument description as GnuCOBOL does, golden from the p1/p2/p3 probes, DOC-A.1-92 rewritten with the change.

**Refutation:** Refuted (journal wf_6cdd03d1-164): upheld=false, corrected verdict OWNER; settled by the orchestrator as DEFECT through CLAUDE.md rule 1's precedence (see Expected and Action).
