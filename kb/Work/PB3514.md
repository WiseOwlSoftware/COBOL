# PB3514 — function-result DISPLAY text versus GnuCOBOL per-function widths

The report classes this a decision, not a bug. After PB3505, DISPLAY of a numeric DATA ITEM follows GnuCOBOL 3.2.0's
default form; DISPLAY of a numeric FUNCTION result still goes through `OperandText#NumericExprText` (DOC-A.1-92), whose
widths differ from GnuCOBOL's per-function widths. Precedence (CLAUDE.md rule 1): ISO §14.9.11.4 GR1 leaves the device
conversion to the implementor, so the order is ISO (silent), then GnuCOBOL; GnuCOBOL's non-ISO extensions are not copied.
PB3505 rejected copying GnuCOBOL's per-function widths, its 100-digit FUNCTION PI and its float image; the question to
adjudicate is whether the rejection stands for the widths.

## Repro (`s1.cob`, relevant lines; items `U1 PIC 9(5)V99 VALUE 12.5`, `S1N PIC S9(5)V99 VALUE -12.5`)

```cobol
    DISPLAY "FN1=" FUNCTION LENGTH(U1) "|"
    DISPLAY "FN2=" FUNCTION NUMVAL("12.50") "|"
    DISPLAY "FN3=" FUNCTION MAX(U1 S1N) "|"
    DISPLAY "FN4=" FUNCTION ABS(S1N) "|"
    DISPLAY "FN5=" FUNCTION PI "|"
    DISPLAY "FN6=" FUNCTION INTEGER(S1N) "|"
```

| Line | GnuCOBOL 3.2.0 (`s1.gnu.txt`) | WiseOwl (`s1.we.txt`, function arm untouched by PB3505) |
|---|---|---|
| FN1 | `7` | `7` |
| FN2 | `00000012.5` | `12.50` |
| FN3 | `00012.50` | `12.50` |
| FN4 | `+00012.50` | `12.50` |
| FN5 | 100-digit pi | `3.141592653589793` |
| FN6 | `-000000013` | `-13` |

## Options for the owner

(a) Keep the current text and record it in DOC-A.1-92 as the decided form. (b) Adopt GnuCOBOL's per-function widths (a
per-function table; FUNCTION PI and floats still not copied). Decide together with PB3513, which shares the latitude.

**Sites:** none (adjudication; adopting (b) would change src/Cobol.Net.Compiler/CodeGen/OperandText.cs (NumericExprText) and docs/CONFORMANCE.md DOC-A.1-92)
