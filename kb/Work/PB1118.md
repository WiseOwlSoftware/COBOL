### [exception-condition-handling] §14.6.13.2 rules 5 and 6 have no raise site at all: nothing compares a dynamic-length item's current content length with THIS describer's DYNAMIC LENGTH maximum (or a dynamic-capacity table's capacity with its OCCURS clause) when the storage arrives from another description, so a mismatch is referenced silently.
- **Rows:** GR-14.6.13.2-5, GR-14.6.13.2-6 — harm `silent`
- **Repro:** >>TURN EC-DATA-INCOMPATIBLE CHECKING ON. Program A: 01 E EXTERNAL. 05 DX PIC X DYNAMIC LENGTH LIMIT 20. MOVE "ABCDEFGHIJKL" TO DX. CALL "B". Program B: 01 E EXTERNAL. 05 DX PIC X DYNAMIC LENGTH LIMIT 5. with a USE AFTER EXCEPTION CONDITION EC-DATA-INCOMPATIBLE declarative; DISPLAY DX FUNCTION LENGTH(DX). Also: 01 D PIC X DYNAMIC LENGTH LIMIT 20 (16 chars) passed BY REFERENCE to a formal PIC X DYNAMIC LENGTH LIMIT 5. (scratch: adj-d1/out/probe/dyn/d6b.cob, d5.cob)
- **Expected (spec):** §14.6.13.2 5): the item's content (12 / 16 characters) does not agree with the describer's DYNAMIC LENGTH clause (maximum 5), so referencing it sets EC-DATA-INCOMPATIBLE (fatal) and the declarative runs. Rule 6 states the same for a dynamic-capacity table against its OCCURS clause.
- **Observed:** Pinned cobol.exe prints 'SUB DX [ABCDEFGHIJKL] 12' and 'SUB [ABCDEFGHIJKLMNOP] 16': a LIMIT-5 item holding 12/16 characters, no condition. No DataIncompatibleError call exists in CobolDynString, CobolDynTable or CobolVarGroup. For rule 6 the three probed sharing paths (EXTERNAL dyn table COBOLNET0899, VLG CALL argument SR12, fixed group into a FROM-5 VLG formal which space-fills to the minimum) did not produce a disagreement, so rule 6 needs either the raise or a recorded determination that the crossing normalization makes it unreachable, pinned by a drift test.
- **Code site:** src/Cobol.Net.Runtime/Values/Text/CobolDynString.cs (no agreement check on the crossing/EXTERNAL cell read); src/Cobol.Net.Runtime/Values/Tables/CobolDynTable.cs; the BY REFERENCE / EXTERNAL dynamic-length binding in the interprogram emitters
