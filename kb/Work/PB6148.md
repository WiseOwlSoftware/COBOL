# PB6148 - a method's CALL in the CALL graph has no FROM unit

**Repro** (PB5714 branch worker): `E:/COBOL-coord/scratch/w20262158b/probes/oocall.cob --std 2023 --listing-sections xref`. The row for line 26 prints
`-  26  CALL MAINQ`, although the edge's source unit is class OOC's method M1. DESIGN-listing.md §6.7.1 says the FROM column is "the source unit the line
stands in".

**Mechanism.** `src/WiseOwl.Cobol.Compiler/Listing/CrossReferenceBuilder.cs`, `CrossReferenceBuilder.Calls`: `unitSymbol` maps only
`ListingSymbolKind.Program` symbols, so a statement whose enclosing unit is a method (or a factory method) gets no unit and the column falls back to `-`.
Not the same root as PB5963 (that note is the TARGET row being EXTERNAL; this is the SOURCE column).

**Fix shape.** Map a method symbol to its own unit name in the same lookup, with a listing golden of a method CALL and CANCEL (a CALL graph row whose FROM
names the method).
