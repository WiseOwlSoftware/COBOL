# PB4553 — reports-are-missing-from-cobol2014-words: -std=cobol2014 / -std=cobol2002: the REPORT clause spelled REPORTS ARE is refused; cobol2014.words and cobol2002.words list REPORT twice and omit REPORTS

Filed 2026-11-03 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-batch-3000-20261103`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

Under `-std=cobol2014` (and `-std=cobol2002`) cobc 3.2 refuses an FD whose REPORT clause is written `REPORTS ARE r1 r2`: "syntax error, unexpected Identifier, expecting EXTERNAL or GLOBAL". The same FD written `REPORT IS R1 R2` compiles and runs, and the default dialect accepts `REPORTS ARE`. `config/cobol2014.words` and `config/cobol2002.words` carry the line `reserved: REPORT` twice where `config/cobol85.words` has `REPORT` and `REPORTS`, so under those dialects REPORTS is a user word. Class: rejects legal source. Fuzz programs: fz00546 and 5 more (slice D3).

## Minimal test case

Free reference format.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. RPT1.
ENVIRONMENT DIVISION.
INPUT-OUTPUT SECTION.
FILE-CONTROL.
    SELECT RPTF ASSIGN TO "rpt1.out".
DATA DIVISION.
FILE SECTION.
FD RPTF
    REPORTS ARE R1 R2.
REPORT SECTION.
RD R1 PAGE LIMIT 10.
01 D1 TYPE DETAIL LINE 1.
   05 COLUMN 1 PIC X(3) VALUE "ONE".
RD R2 PAGE LIMIT 10.
01 D2 TYPE DETAIL LINE 1.
   05 COLUMN 1 PIC X(3) VALUE "TWO".
PROCEDURE DIVISION.
    OPEN OUTPUT RPTF
    INITIATE R1
    GENERATE D1
    TERMINATE R1
    CLOSE RPTF
    DISPLAY "DONE"
    STOP RUN.
```

## Environment

`cobc (GnuCOBOL) 3.2.0`, WSL2 Ubuntu x86_64. Compiled with `cobc -x -free -std=cobol2014 -o rpt1.x rpt1.cob` (the same diagnostics under `-fsyntax-only`); no executable is produced.

## Observed result

Compile, exit code 1:

```text
rpt1.cob:10: error: syntax error, unexpected Identifier, expecting EXTERNAL or GLOBAL
rpt1.cob:11: error: RECORD description missing or invalid
rpt1.cob:12: error: 'R1' is not defined
rpt1.cob:12: error: 'R1' is not a valid report name
rc=1
```

(cobc also echoes the source lines around each diagnostic; they are omitted here.)

With line 10 changed to `REPORT IS R1 R2.` the program compiles and prints `DONE` (rpt1.out holds `ONE`). `cobc -fsyntax-only -free rpt1.cob` (default dialect) exits 0, and `-std=cobol2002` gives the same line-10 error. With a copy of cobol2014.words whose second `reserved: REPORT` line reads `reserved: REPORTS`, loaded by a configuration file that includes cobol2014.conf and sets `reserved-words` to that copy, the unchanged program compiles, prints `DONE` and writes `ONE`.

## Expected result (per ISO)

The program is legal; it prints `DONE` and writes one report line `ONE` to rpt1.out.

- §2023:13.18.46.2 (checked): "<u>REPORTS</u> ARE". The general format offers `REPORT IS` or `REPORTS ARE`, each followed by one or more report-names.
- §2023:13.18.46.3 (checked): "Each report-name-1 shall be the subject of a report description entry in the report section of the same source element.". R1 and R2 each have an RD.

Edition: 2014. The REPORT clause with `REPORTS ARE` is in ANSI X3.23-1985 (cobc's own cobol85.words reserves REPORTS) and is unchanged through 2014; Annex E of the 2023 standard lists no report-writer change.

## Our compiler

WiseOwl COBOL (fresh judge, `--std 2014 --source-format free`): compiles with no diagnostic; the run prints `DONE`, exit code 0, and rpt1.out holds the line `ONE`.

## Fix site

`config/cobol2014.words` (lines 403 to 404 as installed by 3.2.0, `/usr/share/gnucobol/config`) and `config/cobol2002.words` (lines 401 to 402): two consecutive `reserved: REPORT` lines, where `config/cobol85.words` lists `REPORT` (line 300) and `REPORTS` (line 302). The second line presumably meant REPORTS: changing it to REPORTS in a copy of cobol2014.words makes the program compile and run. The 3.3-dev tree has the same lines.

## Draft issue

**Title:** REPORTS ARE in an FD is refused under -std=cobol2014 and cobol2002: the word lists have REPORT twice

As posted (owner-reviewed, 2026-11-04):

With `-std=cobol2014` or `-std=cobol2002`, cobc rejects the plural form of the FD's REPORT clause, `REPORTS ARE`.

### To reproduce

`rpt1.cob` (attached, free format):

~~~~
IDENTIFICATION DIVISION.
PROGRAM-ID. RPT1.
ENVIRONMENT DIVISION.
INPUT-OUTPUT SECTION.
FILE-CONTROL.
    SELECT RPTF ASSIGN TO "rpt1.out".
DATA DIVISION.
FILE SECTION.
FD RPTF
    REPORTS ARE R1 R2.
REPORT SECTION.
RD R1 PAGE LIMIT 10.
01 D1 TYPE DETAIL LINE 1.
   05 COLUMN 1 PIC X(3) VALUE "ONE".
RD R2 PAGE LIMIT 10.
01 D2 TYPE DETAIL LINE 1.
   05 COLUMN 1 PIC X(3) VALUE "TWO".
PROCEDURE DIVISION.
    OPEN OUTPUT RPTF
    INITIATE R1
    GENERATE D1
    TERMINATE R1
    CLOSE RPTF
    DISPLAY "DONE"
    STOP RUN.
~~~~

    cobc -x -free -std=cobol2014 -o rpt1 rpt1.cob

### What happens

3.2.0 and 3.3-dev r5751 both stop with

~~~~
rpt1.cob:10: error: syntax error, unexpected Identifier, expecting EXTERNAL or GLOBAL
~~~~

and three follow-on errors. The program compiles if line 10 says `REPORT IS R1 R2.`, and also without `-std` or with `-std=cobol85`.

### What should happen

The REPORT clause is `REPORT IS` or `REPORTS ARE`, followed by report-names, and REPORTS is a reserved word (ISO/IEC 1989:2023 13.18.46.2 and 8.9; the same in 2002 and in the 2014 FCD).

### Why it happens

This looks like a typo in the word lists: `config/cobol2014.words` (lines 403-404) and `config/cobol2002.words` (lines 401-402) list `REPORT` twice and leave out `REPORTS`, so REPORTS is not reserved under those dialects. The other dialect lists have `REPORT`, `REPORTING`, `REPORTS`.

### Proposed fix

The attached `reports-are-words.patch` (against 3.3-dev r5751) replaces the duplicate `REPORT` line with `REPORTS` in both files, after `REPORTING` as in `cobol85.words`, and adds a testsuite case, "REPORTS ARE in the FD with -std", to `syn_reportwriter.at`, with ChangeLog entries. With it the program compiles and runs under both dialects. `make check`: 1373 expected, 9 skipped, 0 failed (1372 unpatched); the new test fails without the patch.

### Related

[bugs #1270](https://sourceforge.net/p/gnucobol/bugs/1270/), case 6, is another typo in `cobol2014.words`; the two patches apply together.

### Details

GnuCOBOL 3.2.0 (Ubuntu `gnucobol3 3.2-4build1`) and 3.3-dev r5751 (CI snapshot 3.3-dev.138 of 2026-10-29), x86_64 Linux, both run 2026-11-04.
