# PB3190 — tier 0a holds added test methods, not edited ones

**Sites:** `scripts/spec/impacted_tests.py` (`tests_changed`, `reach_test_file`, `Hunk`/`parse_hunks`/`hunks`,
`method_ids`, `Reach.changed_tests`, `--audit-members`), `scripts/spec/cs_members.py` (new: the C# member reader),
`scripts/gate_plan.py` (`Context.changed_tests`, `tier_of`), `tests/Cobol.Net.Tests.Unit/ImpactedTestsDriftTests.cs`,
`docs/rearchitecture/DESIGN-test-build-ci.md` sections 3.13 and 3.14.2, `docs/DOC_INDEX.md`.

> ⚙ **flags:** process-only

Source: `w1085a-PB2099-report.md` "## New defects (note-ready)", bullet 2 (filed by the clerk, 2026-10-15). The clerk grepped PB3155 and PB3112 first: PB3155 is tier 0a's previous-red source (the Linux trx never read), PB3112 is the tier-0c cost cap. Neither names this input, so this is a separate mechanism in the same tier-0a family.

**The mechanism.** The report places it at `scripts/run_gate_legs.py` planning; `scripts/gate_plan.py:565-574` is the tier 0a admission and its self-test ("tier 0a: an added test method, a touched golden and a previous red lead leg 1"). A test method that the diff ADDS is tier 0a. A test method that already existed and whose BODY the diff changes is not: it runs only in leg 2 unless some other tier (the impact map, tier 0c) selects it. Verify the exact site before editing (lines as of origin/main 6452ed98a).

**Why it matters.** The CI invariant (CLAUDE.md, PB1957): a change to a test's body is the commonest way a branch breaks that test, and the batched-gating leg 1 is meant to run the change's own tests. With the edited test left to leg 2, its red surfaces first at the landing's Linux gate or in CI. This is a CI-invariant leak path of the same kind as PB3155.

**Fix direction** (not designed here). Tier 0a takes every test method whose source span intersects the diff (added, or a changed line inside its body), not only new methods; pin it with a planner self-test that edits one line inside an existing method and expects that method in tier 0a. Change the callers, no shim (rule 4).

## Landed (wave 20261026 C3)

**Re-probe** (worktree `wf_0e51b14b-ced-13`): one character changed inside the body of the existing
`ImpactedTestsDriftTests.GatePlanSelfTest_DrivesEveryArm`, then `impacted_tests.py --base HEAD --plan`: `tier0a` =
`{'added_tests': {'Unit': []}}`, so the edited test was tier 1, budgeted like any other case. Reproduced.

**Fix.** Tier 0a holds every test method the diff ADDS OR EDITS: `impacted_tests.tests_changed(text, hunks)` takes each
test method whose lines (attribute block, declaration, body) a `-U0` hunk's NEW side touches, and each theory whose
`[MemberData]` source a hunk touches; a hunk of blank and comment lines touches nothing; a new file (or one named
without a diff) gives all its test methods. The spans come from a new module, `scripts/spec/cs_members.py`: a lexer
that blanks comments, preprocessor lines, character literals and every string form (verbatim, interpolated with its
holes followed, raw) so the braces left are code, then a member-level reader (containers, block / expression /
initializer bodies). A source whose braces do not balance once lexed falls back to every test method of the file, and
`impacted_tests.py --audit-members` (new `ImpactedTestsDriftTests` fact) holds the lexer to every source of the gated
test projects: CLEAN over 6,078 test methods, no overlapping spans. `Reach.added_tests` / `Context.added_tests` are
renamed `changed_tests` with every caller (rule 4). Matching stays by method NAME, so a partition class
(`Family_P<k> : FamilyBase<…>`) that inherits its tests still matches.

**Found on the way (fixed here):** the old `test_methods` regex missed every same-line test (`[Fact] public void X()
=> …;`: 11 methods in `CobolBoolTests.cs` and `TierCRejectionTests.cs`), so even an ADDED one of that shape was never
tier 0a; and it counted test methods inside planted C# strings (`VacuousTestDriftTests.cs`). The new reader does
neither. The orphan comment in `reach_of` ("its classes are already tier 0a") claimed a coverage the code did not
have; a changed `[MemberData]` source now really puts its theories in tier 0a.

**Residue (not this mechanism):** an edited HARNESS (a helper or constructor a test calls, or a data file a test reads)
is still tier 1 through the map and budgeted — the same shape as any product change; reported as a lead.
