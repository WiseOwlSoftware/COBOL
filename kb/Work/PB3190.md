# PB3190 — tier 0a holds added test methods, not edited ones

> ⚙ **flags:** process-only

Source: `w1085a-PB2099-report.md` "## New defects (note-ready)", bullet 2 (filed by the clerk, 2026-10-15). The clerk grepped PB3155 and PB3112 first: PB3155 is tier 0a's previous-red source (the Linux trx never read), PB3112 is the tier-0c cost cap. Neither names this input, so this is a separate mechanism in the same tier-0a family.

**The mechanism.** The report places it at `scripts/run_gate_legs.py` planning; `scripts/gate_plan.py:565-574` is the tier 0a admission and its self-test ("tier 0a: an added test method, a touched golden and a previous red lead leg 1"). A test method that the diff ADDS is tier 0a. A test method that already existed and whose BODY the diff changes is not: it runs only in leg 2 unless some other tier (the impact map, tier 0c) selects it. Verify the exact site before editing (lines as of origin/main 6452ed98a).

**Why it matters.** The CI invariant (CLAUDE.md, PB1957): a change to a test's body is the commonest way a branch breaks that test, and the batched-gating leg 1 is meant to run the change's own tests. With the edited test left to leg 2, its red surfaces first at the landing's Linux gate or in CI. This is a CI-invariant leak path of the same kind as PB3155.

**Fix direction** (not designed here). Tier 0a takes every test method whose source span intersects the diff (added, or a changed line inside its body), not only new methods; pin it with a planner self-test that edits one line inside an existing method and expects that method in tier 0a. Change the callers, no shim (rule 4).
