# PB5983 probed and retired, 2026-11-20 (wave 20262115, group A)

**Probe** (tree da1183d215, `--std 85`, compiled separately in run directory
`E:/COBOL-coord/scratch/fleet-1985-rulings/w20262115a/runs/extsep-001`). `extb.cob` was compiled first. It describes
`FD EF IS EXTERNAL` with `EF-REC PIC X(100)` and `01 EXT-R IS EXTERNAL PIC X(100)`, stores 100 B characters into `EXT-R`,
writes 100 C characters to `EF`, and reads the record back. `exta.cob` describes both at 10 characters. It fills `EXT-R`
with A characters, calls `EXTB` (which it finds by name), and then displays the record and reads the file. Output:

```
B SEES [          ]        <- EXT-R (91:10) in EXTB
B READS [          ]       <- EF-REC (91:10) in EXTB after its READ
A SEES [BBBBBBBBBB]
A READS [CCCCCCCCCC]
EXTA EXIT 0
```

**Verdict: no crash, retired.** The result is undefined (`§1985:I.1.6`, cite.py OK), and the run time does not fault. The
shared storage keeps the first description's 10 characters. The longer description's positions beyond that read as spaces,
and its stores there are dropped. The behaviour is recorded in `docs/conformance/3/D-85-EXTERNAL-FD-AGREEMENT.md`.

**A separate finding (reported as a lead; no note allocated):** `extlen.cob`, the same pair as two programs of ONE
compilation group (EXT-R at 10 and at 100), compiles without a diagnostic at `--std 85` and at `--std 2023`
(`runs/extlen-001`, `runs/extlen-002`). §1985:X.4.5.4 GR2 requires that "the records must define the same number of
standard data format characters". The determination says WiseOwl checks the agreement rules "where both descriptions are
in one compilation group", and for the EXTERNAL record's size it does not.

**Sites:** none changed (an analysis); the determination text in `docs/conformance/3/D-85-EXTERNAL-FD-AGREEMENT.md`.
