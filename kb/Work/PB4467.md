# PB4467 - construct citations name C# members, and the citation reaches the user's diagnostic

**Sites:** `tests/version-matrix/constructs.json` (312 `citation` fields; 7 name code, among them the row at line 2543 that ends
`bind-site gate (DataBinder.TryResolveRang...`), `src/WiseOwl.Cobol.Editions/ConstructRegistry.cs:51-62` (the "requires COBOL-x",
"was removed in COBOL-x" and "is obsolete as of COBOL-x" messages interpolate `({c.Citation})` into the diagnostic text and pass it
as the diagnostic's citation), `src/WiseOwl.Cobol.Editions/ConstructDialectStatus.cs:31-34` (field doc: "ISO section / VCR row /
roadmap-D citation").

**Checked: it does reach a diagnostic.** `ConstructRegistry` builds the edition-gate message from `c.Citation` verbatim, so a user
who compiles a construct that row governs under the wrong `--std` reads a C# member name (in other rows, project history such as
"LIVE at the INTERFACE wave") in a compiler error. The DataBinder step extracts (PB2296 to PB2361) move such members; each move
silently edits a user-visible diagnostic, and a deleted member leaves a citation pointing nowhere.

**Fix shape.** The citation names the ISO rule (and VCR row) only; the implementation pointer (bind-site gate, member names, wave
history) moves to a separate non-user-visible field or to the row's notes. A drift test that every citation matches the `cite.py`
shape and contains no dotted identifier makes the next row automatic.

2026-11-03 (registrar, mythos-final leads, lead 11 and 12): (a) `scripts/spec/audit_code_citations.py` on the PB4467 finish branch (worktree-wf_b4b9fa8e-0ec-2; the arm is not on origin/main `ae067404f`), ~line 1056: the second alternative of the CONSTRUCT-CODE spec-line-pointer arm, `(?<!\w):\d{3,}`, never fires on the shape constructs.json carried (`(spec :10853)`); the self-test exercises only the `@NNNNN` alternative, so that alternative is dead and unwitnessed. Add a self-test row for the `:NNNNN` shape or delete the alternative. (b) The `description` fields of `tests/version-matrix/constructs.json` still name C# members, beside the `citation` fields this note covers: `range-in-alphabet-2002` names `DataBinder.TryResolveRangeAlphabet`, `sync-on-group-2023` names `DataBinder.UsageInheritanceWalk` where the `ConstructRegistry.Check` gate is `DataBinder.GateSynchronizedGroup` (`DataBinder.SynchronizedClause.cs`). They rot like code comments and no drift test scans them; extend the drift test of the fix shape to the description field.
**Landed (wave 20261841, group D).** Re-probe on the pre-fix build: `range-in-alphabet-2002`'s source at `--std 85` printed `... a COBOL-2002 addition (derived - no 85->2002 row in the 2023 Annex E, the A1 gap D18); bind-site gate (DataBinder.TryResolveRangeAlphabet))`. The note's count of 7 was low: 132 of the 312 `citation` fields (a row's and its two directive blocks') named a C# member, a grammar rule, a file, an emit-site or gate pointer, a "LIVE" status, a DEVLOG or register id, a decision id or a spec line pointer. Each now names the ISO rule and the VCR row only. The implementation pointers were dropped, not moved: they rot, the construct id and diagnostic code find the gate, and the rows' `description` fields keep the fuller notes. `ConstructRegistry.g.cs` is regenerated; no message changes except the dropped tails.

**The drift check** is `CONSTRUCT-CODE` in `scripts/spec/audit_code_citations.py` (the gate's CITATIONS audit). It reads `tests/version-matrix/constructs.json` and refuses any `citation` of a row or directive block that matches a code shape (C# member, source file, call, PascalCase, camelCase or SCREAMING_SNAKE identifier, generic type, leading underscore) or a project-history shape (LIVE, DEVLOG or register id, phase, wave or step marker, emit-site or gate pointer, decision id, spec line pointer). The patterns are shapes, not a member list, so the next moved member is refused without an edit. `--self-test` fires one arm per kind of token (fifteen, declared in `scripts/self_test_arms.py`) and stays silent on the repaired twins. Two characterization snapshots (`char_neg_occurs_dyn85`, `char_neg_typedef85`) held citation tails and were regenerated.

## Landing

- `scripts/spec/audit_code_citations.py#construct_citation_defects` owns the rule (the shapes in `CONSTRUCT_CODE` and `CONSTRUCT_HISTORY`); `construct_citation_scan` reads the JSON. To refuse a new kind of token, add one shape and one `CONSTRUCT_SELF_TEST` row, and its label to `scripts/self_test_arms.py`.
- `tests/version-matrix/constructs.json`: after any edit run `scripts/gen-constructs.ps1`, which regenerates `ConstructRegistry.g.cs`; a citation that names a member, file, status or register id fails the CITATIONS audit, so put that pointer in the row's `description`, never in `citation`.
- Trap: the audit's `.g.cs` scan applies the DIAG-UNQUALIFIED check to citations too (a bare `GR1` under a clause whose rules live in `.4` fails), so cite the clause that holds the rule.
- A diagnostic message snapshot (`tests/WiseOwl.Cobol.Tests.Characterization/Snapshots/*.diag.txt`) carries the citation text; regenerate with `WISEOWL_COBOL_UPDATE_SNAPSHOTS=1` and read the diff.
