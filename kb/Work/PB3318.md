# PB3318 — a landed branch whose pending DEVLOG file was stamped reads UNLANDED

## Found (loop resume unit, 2026-10-16 20:45 PDT)
The survey (`python scripts/prune_worktrees.py`) listed two branches as DECISION, UNLANDED:
- `worktree-wf_e3902303-54c-7`: "UNLANDED (1 added file(s) absent from main, e.g.
  DEVLOG/pending-pb3198-one-command-line-model-for-the-guard-hooks.md)". PB3198 landed through pull request #167.
- `worktree-wf_eaee9626-dc5-2`: "UNLANDED (1 added file(s) absent from main, e.g.
  DEVLOG/pending-pb242-delete-gr7-lock-release-observed.md)". PB242 is landed.

`git cherry origin/main <branch>` marks every commit of both branches `-`, so each one has a patch-equivalent commit on
main. The one "absent" file is the branch's own `DEVLOG/pending-<slug>.md`. The landing renamed it to
`DEVLOG/NNNN-<slug>.md` (`devlog.py stamp`, run by `enqueue.py land`). Both branches are LANDED by the survey's own
rule (kb/Work PB2708: every commit patch-equivalent and no declared name that main lacks). Instead they reached the
DECISION list, and a hand-written ABANDONED record (PB3317) was needed to delete them.

## Mechanism
`scripts/prune_worktrees.py` `classify()` runs its checks in this order:
1. MERGED (the tip is an ancestor of main).
2. `if absent: return 'UNLANDED', ...`, where `absent` is every file added since the merge base that main lacks now.
3. `merges_to_main_unchanged`.
4. `carried()`, the `git cherry` test.

Step 2 returns before step 4 can run. A file added by a patch-equivalent commit was on main once, so if it is absent
now, main moved or deleted it after the landing. That is exactly what the stamp does to every pending DEVLOG file. So
any branch whose work landed as OTHER commits (a finisher's successor branch, a re-applied twin) and that carries a
pending DEVLOG file can never read LANDED.

## Fix shape
Ask `carried()` before the absent-file return, or excuse an absent file that a patch-equivalent commit added. Add a
self-test case to the survey's own self-test: a branch whose only commit adds `DEVLOG/pending-x.md`, landed on main as
an equivalent commit followed by a rename to `DEVLOG/0001-x.md`, must read LANDED. Keep the PB2708 guard: a branch
that declares a C# name main lacks stays a DECISION.

## Sweep
- `scripts/orchestrator/enqueue.py` and `land_lane.py` read the survey's classes, so they need no change of their own.

  they were DECISION rows for that reason too.
