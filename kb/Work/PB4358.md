# PB4358 — no gate runs a self-test against a clock other than today's

**Sites:** `scripts/self_tests.py#Runner.run_one` (the runner: it starts every self-test with the real clock),
`scripts/self_tests.py#PassStore.lookup` and `scripts/self_test_inputs.py#Deps` (the reuse key: a recorded PASS is keyed
on file content only, never on the clock) and `scripts/self_test_inputs.py#TRACER` (the `sitecustomize` every
self-test's Python processes load, the one place a clock could be set for all of them); the nightly workflow PB4332
added (all self-tests on both OSes).
Changed by the fix: `scripts/self_test_clock.py` (new: `SHIM`, `reads_wall_clock`, `Clock`, `declared_real`, `shifted_env`),
`scripts/self_tests.py#Runner.run_one` / `#Runner._exec` / `#Runner._clock` / `#Runner._shifted` / `#Runner._record`,
`scripts/self_tests.py#PassStore.lookup` / `#PassStore.record` (schema 3, the `clock` field and its horizon),
`scripts/self_test_inputs.py#install_tracer` and `#RUNNER`, and the `# SELF-TEST-CLOCK: real` declarations of
`scripts/gate_slot.py`, `scripts/prune_worktrees.py`, `scripts/spec/impact_store.py`,
`scripts/orchestrator/test_alloc.py` and `scripts/orchestrator/test_plan_wave.py`.

## The gap

PB4353's self-test planted merge-group runs dated the day before it was written and read them through a real 24-hour
window. It passed on its branch, in its merge group and on main, then went RED for every pull request at
2026-11-01T09:00Z and bounced #960 and #961, which carried no fault. Nothing in the local gate, the merge group or the
nightly runs a self-test at any clock but the current one. A fixture dated near its authoring day that reaches the wall
clock therefore passes every gate until the day it expires. After the expiry the local gate and CI disagree for a second
reason: the local gate did not run the self-test at all. `self_tests.py --reuse` found a pre-expiry PASS keyed on
unchanged file content (`PassStore.lookup`, PB2914) and answered REUSED/GREEN (verified by PB4353's branch review on a
gate at 09:39Z), while CI ran it fresh and went RED. The design question therefore covers both: run self-tests that read
the wall clock against more than one clock, and make such a self-test's PASS non-reusable, or expire it, so a dated
fixture cannot stay green by reuse. PB1957, the survey of CI-versus-local differences, carries the map entry.

## What was measured

PB4353's sweep ran all 137 runnable self-tests with Python's clock (`datetime.now/utcnow/today`, `date.today`,
`time.time`, `time.time_ns`) shifted forward by 3 and by 45 days through a `usercustomize` shim. Unshifted it was all
GREEN; shifted it gave 6 and 7 REDs, every one a false red: each test compares Python's clock with a second real clock
the shim does not move (file mtimes, git commit times, process start times, a timestamp PowerShell wrote). PB4353's
note has the table. So a guard built on shifting one clock flags correct tests and cannot run in a gate as is.

## The question

Make the next expiring fixture fail on the day it is written, not on the day it expires. Candidates, each to be
measured before one is chosen:

1. A whole-process shifted clock on Linux (libfaketime with `FAKETIME` set to a forward offset, faking `stat` too), run
   by the nightly over every self-test. Then file mtimes, git commit times and child processes agree with Python's clock.
   Cost: one more self-test pass each night (about 8 minutes on this host) and libfaketime in the toolchain manifest
   (kb/Work PB4007: the same version locally and in CI).
2. A rule the runner proves for every self-test: a self-test that reads the wall clock while it holds dated fixtures
   passes a clock in (the tracer can see `datetime.now` and `time.time` calls through an audit hook or a wrapper, and
   the fixture dates through the self-test's own source). Cheaper, but it judges intent from the syntax tree.
3. Seed the fixtures relative to the clock the test runs at (`now - 3 h`) instead of literal dates. That is a coding
   rule, not a guard: it needs (1) or (2) to stay true.

Whichever is chosen pairs with a drift test that keeps it running (rule 5), and DESIGN-test-build-ci.md records it.

## Landed (wave 20261806, group A)

Chosen: a hybrid of candidates 1 and 2, measured first. A whole-process fake clock (libfaketime) would still leave the
process start times and PowerShell's own clock unmoved, and cannot run on the Windows host the implementers use; the
syntax-tree rule alone judges intent. The runner therefore (a) detects, from the tracked `.py` files a self-test's run
opened, whether the self-test CAN read the wall clock (an over-approximation; the second run is the semantic check),
(b) runs it a second time, in the same budget place, with the Python clock moved forward 400 days in every Python
process it starts (a shim at the head of the tracer's `sitecustomize`, one move per function, proved against the
unshifted clock), and (c) records a PASS only when both runs pass, with the last day that proof covers; `PassStore.lookup`
refuses a record past it. Re-measured through this runner on the branch (full run, Windows): 49 of 138 self-tests are
shifted and green (55 reach the clock), and the five Python ones PB4353's sweep found false (`impact_store.py`, `gate_slot.py`,
`prune_worktrees.py`, `orchestrator/test_plan_wave.py`, `orchestrator/test_alloc.py`) were red for the reason it gave
(a second, real clock: file modification times, a holder's start time, git commit times) and now declare
`# SELF-TEST-CLOCK: real — <why>`, as does the runner's own self-test (`scripts/self_tests.py`: its arms nest runners that
move the clock). The two PowerShell ones the sweep named are not shifted (residue: a PowerShell or bash
self-test, and any clock that is not Python's). DESIGN-test-build-ci.md §3.14.10 item 5 records the rule; PB1957 row 57
carries the CI-versus-local entry.

## Landing

- `scripts/self_test_clock.py#Clock.of` owns the rule (which self-tests are shifted, which declare the clock real);
  `#reads_wall_clock` is the detection (REUSE it, never a second list of clock functions) and `#SHIM` the one place the
  clock moves. The trap: the shim runs in the runner's own `sitecustomize`, so a runner that itself runs inside a shifted
  process must scrub `SHIFT_ENV` from its first run (`Runner.run_one` does).
- `scripts/self_tests.py#Runner.run_one` runs the proof run in the same budget place; `#PassStore.lookup` holds a reuse to
  the record's `clock.until`. The trap: a planted fleet-arm self-test that reads the clock (the span files) must declare
  `# SELF-TEST-CLOCK: real`, or it runs twice and its span counts double.
- A new self-test that fails only in the proof run is either a fixture dated near its authoring day (derive it from the
  clock the test runs at) or a comparison with a real clock (declare it, with the reason, among the first five lines).
