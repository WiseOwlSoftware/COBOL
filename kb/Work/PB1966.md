# PB1966 — LANDED (wave 1034 group E)

## Landing

LEARNED: `Preprocessor/CharacterPositions.cs#Count/IndexAt/PositionAt` is the ONE definition of a character position
(a code point; REUSE it, never `string.Length` for a column). `Preprocessor/FixedFormLine.cs` reads a fixed-form line's
columns (`Indicator` is a `Rune`, `ProgramText` is padded to 65 positions, `BeyondMarginR`). The trap: the DOC-A.1-157
row itself said "UTF-16 code unit", so the sites were faithful to a wrong determination; a test whose line is shorter in
characters than in units (Linear B / Adlam letters, supplementary digits U+1D7CE) is the only way to see it.

Re-probed on the wave-1034 build: `long40.cob` (40 Adlam letters, `PIC X.` ending at position 72) failed COBOL0001 near
PROCEDURE, as filed. **Root cause:** the DOC-A.1-157 determination itself said "a character outside the BMP is two
positions", and six sites implemented it by indexing the line string: `ProgramTextArea` (margin R), `DirectiveText`,
`ConvertLine` (the indicator), `IsFixedForm` (the Auto detector's indicator, sequence area and past-margin test), the
free-form 255 limit and `Frontend.LocateEndPerform`'s comment-indicator test — plus the tab expansion in
`PhysicalLines.Line` (tab stops counted `text.Length`) and every diagnostic column in `LogicalLineBuilder`
(`column + index`). **Fix:** the determination is now ONE CHARACTER (one code point; §6.1 1) a), and the standard counts
a word's length in characters, §8.1.3.2 GR4 c)). `CharacterPositions` is the one definition (count / index of a position
/ position of an index), `FixedFormLine` the one reader of a fixed-form line's columns (the margin constants moved into
it; `ReferenceFormatProcessor.IndicatorColumn` and friends deleted), `PhysicalLines` expands tabs by position, the builder
names diagnostic columns by position (`Col`), `OnInvalidIndicator` takes the whole indicator `Rune`.
`PhysicalLinesDriftTests.NoPipelineStage_ReadsAColumnAsAStringIndex` refuses the next `line[6]`. Witnesses:
`conformance:2023/pb1966_supplementary_letters_margin_r` (supplementary letters are Annex B letters from 2023 only, E.3.3
item 5, so the introducing edition is 2023 and there is no pre-2023 negative that differs),
`conformance:negative/pb1966-supplementary-letters-past-margin-r`, `unit:CharacterPositionsTests`.

Original filing:

Found by wave 1014 group R (PB1402: extended letters, including supplementary-plane Annex B letters, now lex as word
characters), filed by the train-1014 lander.

## Rule

§6.1 1) a): "Reference format is described in terms of character positions on a line on an input-output medium"
(`cite.py --check 6.1 "Reference format is described in terms of character positions"` -> OK §6.1 1) a)). A
supplementary-plane character is one character position. The documented determination is DOC-A.1-157 (the
character-position size of the source medium), which is CONFORMS today on BMP text only.

## Defect

`src/Cobol.Net.Frontend/Preprocessor/ReferenceFormatProcessor.cs` (`SourceAreaWidth`, `MarginR`) and
`ReferenceFormatProcessor.LogicalConversion.cs:223-225` index `line[...]` by UTF-16 unit, so a line holding N
supplementary characters has its margin R N positions early.

## Repro

`scratchpad\w1014r\p\long40.cob` (orchestrator scratchpad of session e8598e10): a word of 40 Adlam letters (U+1E900
block) in columns 11-50 by characters; `cobol long40.cob --std 2023` -> `COBOL0001` near PROCEDURE, because the word
occupies 80 UTF-16 units and the tail past unit 72 is dropped. A national literal holding a supplementary character
shifts the same way.

## Done when

The fixed-form column arithmetic counts code points (or text elements, per DOC-A.1-157's determination) at every
site, with a golden that places a supplementary-letter word ending exactly at column 72.
