# PB4162 — a table(ALL) argument is never held for GR2's order

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs:3175` (`IntrinsicBinder.TryBindAllArgument`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/ArgumentOrder.cs` (whole: the `Hold` method and its TableAllPlace guard are PB4124's new code, queued as pull request #845 and not on main when this was filed; the fix changes that guard and the members that record an operand).

New defect/lead 1 of PB4124's implementer (PB4124 is held by an in-flight group, so this is a new note that names it). Two faces of
one mechanism: an ALL argument has no held form.

1. `MAX (T (ALL), UDF (X))`: the ALL operand is enumerated where the call renders (`IntrinsicBinder.TryBindAllArgument:3175`, which
   makes no `Record` in the `ArgumentOrder` window), so T is read AFTER the user function's activation instead of in the order the
   function-argument evaluation rule (GR2) gives; if UDF changes T, the answer is wrong.
2. A nested call that names ALL, `LENGTH (MAX (MAX (T (ALL), 1), UDF (X)))`, is still held as a VALUE (`ArgumentOrder`'s Hold has a
   `TableAllPlace` guard that lets it through), so its LENGTH answers 4 where the unheld form answers 8.

Repro: `E:/COBOL-coord/scratch/w20261773a/p8.cob` (runs the direct and nested forms, each unheld with `0` and held with
`FUNCTION P8BUMP(WS-LO)`: the lines `directL-U` / `directL-F`, `nestL-U` / `nestL-F` differ where the two spellings of one call must
agree; WS-E is `PIC 9(8) OCCURS 3`).

**Fix shape (the report's):** an ALL argument needs a held form, an array of `FunctionValueField`, recorded in the window so GR2's
order holds for it too; the same freeze-loses-description root as PB4124 and PB4123, filed separately because the held form is
new. Derive the correct LENGTH and the evaluation order from the spec (GR2 of the function-argument rule; validate the clause with
`python scripts/spec/cite.py --check`) before picking the side that is wrong. When PB4124's code is on main, replace the whole-file
site with the `ArgumentOrder` members it names.
