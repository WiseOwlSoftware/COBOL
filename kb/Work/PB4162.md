# PB4162 — a table(ALL) argument is never held for GR2's order

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs:3175` (`IntrinsicBinder.TryBindAllArgument`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/ArgumentOrder.cs` (`ArgumentOrder.Hold`, `ArgumentOrder.StoreAt`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/SendingValueTemp.cs` (`SendingValueTemp.MaterializeTableAll`, `SendingValueTemp.FreezeTableAll`), `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.Oo.cs` (`DataBinder.CreateCompilerTempTable`, `DataBinder.CloneTempNode`), `src/WiseOwl.Cobol.Compiler/Binding/Bound/BoundHoldTableAll.cs` (`BoundHoldTableAll`), `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/TableHoldEmitter.cs` (`TableHoldEmitter.Emit`, `TableHoldEmitter.EmitWalk`), `src/WiseOwl.Cobol.Compiler/CodeGen/StatementEmitter.cs` (`StatementEmitter.Visit(BoundHoldTableAll)`), `src/WiseOwl.Cobol.Compiler/CodeGen/UnitEmitters.cs`, `src/WiseOwl.Cobol.Compiler/Binding/Bound/BoundStores.cs` (`StoreKindVisitor.Visit(BoundHoldTableAll)`), `src/WiseOwl.Cobol.Compiler/Binding/Passes/UsageCollectionPass.cs` (`Visitor.Visit(BoundHoldTableAll)`).

New defect/lead 1 of PB4124's implementer (PB4124 is held by an in-flight group, so this is a new note that names it). Two faces of
one mechanism: an ALL argument has no held form.

1. `MAX (T (ALL), UDF (X))`: the ALL operand is enumerated where the call renders (`IntrinsicBinder.TryBindAllArgument:3175`, which
   makes no `Record` in the `ArgumentOrder` window), so T is read AFTER the user function's activation instead of in the order the
   function-argument evaluation rule (GR2) gives; if UDF changes T, the answer is wrong.
2. A nested call that names ALL, `LENGTH (MAX (MAX (T (ALL), 1), UDF (X)))`, is still held as a VALUE (`ArgumentOrder`'s Hold has a
   `TableAllPlace` guard that lets it through), so its LENGTH answers 4 where the unheld form answers 8.

Repro: `E:/COBOL-coord/scratch/w20261773a/p8.cob` (runs the direct and nested forms, each unheld with `0` and held with
`FUNCTION P8BUMP(WS-LO)`: the lines `directL-U` / `directL-F`, `nestL-U` / `nestL-F` differ where the two spellings of one call must
agree; WS-E is `PIC 9(8) OCCURS 3`).

**Fix shape (the report's):** an ALL argument needs a held form, an array of `FunctionValueField`, recorded in the window so GR2's
order holds for it too; the same freeze-loses-description root as PB4124 and PB4123, filed separately because the held form is
new. Derive the correct LENGTH and the evaluation order from the spec (GR2 of the function-argument rule; validate the clause with
`python scripts/spec/cite.py --check`) before picking the side that is wrong. When PB4124's code is on main, replace the whole-file
site with the `ArgumentOrder` members it names.

Source: report `w20261773a-PB4124-report.md`, "New defects / leads (note-ready)" item 1; PB4124.

## Landed (branch worktree-wf_34371f8b-c21-1)

**Re-probe on the base build** (`E:/COBOL-coord/scratch/mythos/w-g7/w20261780b/p8.cob`, `p9.cob`): `nest-F`/`nestL-F` differed from `nest-U`/`nestL-U` (000000021 vs 00000021, LENGTH 4 vs 8), and with an EXTERNAL table the activation changed, `MAX (E (ALL), UDF (X))` answered 121 and `SUM` 333 where the elements held 21 5 7 when the argument was reached (21 and 33).

**Root.** An ALL argument was no argument of the list: `TryBindAllArgument` built a `TableAllPlace` and never recorded it in the `ArgumentOrder` window, and the backend enumerated it where the call renders, after every hoisted activation; `ArgumentOrder.Hold` carried a guard that let a nested call naming one be held AS A VALUE. Fix shape: the operand is recorded where it is built, and `StoreAt` holds it with `SendingValueTemp.MaterializeTableAll`, a PRE-op `BoundHoldTableAll` that copies the elements the enumeration yields, in section 15.3 14) order, into a compiler-temporary TABLE of the element's own description (`DataBinder.CreateCompilerTempTable`); the call's operand becomes a `TableAllPlace` over it. A table of the element's description makes every consumer (the lanes `AllArgs<CobolDec|double|string|Int128>`, `FunctionDeviceText.Field`, the `Hold` recursion) read what it read for the source table, so the report's `array of FunctionValueField` was not needed. Fixed ranges -> fixed table; OCCURS DEPENDING ranges -> a fixed table at the product of the maxima plus a count temporary (`AllCount.Odo`, minimum 0); a dynamic-capacity range -> a dynamic-capacity table sized by the copy (`TableHoldEmitter`: two walks). The `TableAllPlace` guard in `ArgumentOrder.Hold` is deleted.

**Goldens.** `15.3-Arguments/pb4162_table_all_argument_held_for_order` (2002+: fixed, two-level, partly subscripted, ODO, text, nested; 15 results hand-derived from sections 8.4.3.2.4 2), 15.3 14), 15.60.1, 15.61.4 2), 15.71.4 1), 15.72.4 1)), `pb4162_table_all_dynamic_capacity_held_for_order` (2014+: dynamic-capacity and nested dynamic-capacity), with their below-edition refusals (`pb4162_table_all_argument_held_below_2002`, `pb4162_table_all_dynamic_capacity_held_below_2014`). Unit: `HeldFunctionArgumentDescriptionTests` (six table(ALL) shapes join the 22) and `ArgumentOrderDriftTests.ATableAllArgument_IsRecordedWhereItIsBuilt_AndHeldByTheOneHolder`.

**No residual.** The one element `SendingValueTemp.Model` cannot describe, a section 8.5.1.12 variable-length group, is refused as a function argument (COBOL1627, section 15.3: only LENGTH and BYTE-LENGTH admit one; `--permissive` coerces it, and a coerced element is then not held), so no legal program reaches an un-held ALL operand.

## Landing

Trap: `AllCount.Capacity` / a product of maxima past `int.MaxValue` need a DYNAMIC-capacity table, whose CAPACITY register is minted by hand in `CreateCompilerTempTable` because `DynamicResolve` runs before procedure binding.
