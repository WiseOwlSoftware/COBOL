# PB3901 — floating-point-edited-picture-not-implemented--size: cobc 3.2: size of a floating-point numeric-edited item omits the exponent's '+' (PIC 9.99E+99 has LENGTH 7, expected 8)

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S5) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\floating-point-edited-picture-not-implemented--size.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\floating-point-edited-picture-not-implemented--size\`.

## Summary

cobc 3.2 gives a floating-point numeric-edited item described `PIC 9.99E+99` a size of 7 characters. Every symbol of
that PICTURE occupies a character position, so the size is 8. The `+` that follows `E` is skipped when the PICTURE is
parsed and never counted. A wrong size shifts every following item in a record and changes FUNCTION LENGTH,
BYTE-LENGTH and group sizes, independent of the missing run-time editing (sibling record
`floating-point-edited-picture-not-implemented--editing`).

## Minimal test case

Free reference format (`-fformat=free`), `records/floating-point-edited-picture-not-implemented--size.cob`:

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. FPESIZE.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 F PIC 9.99E+99.
PROCEDURE DIVISION.
    DISPLAY FUNCTION LENGTH(F)
    STOP RUN.
```

## Environment

- `cobc (GnuCOBOL) 3.2.0`, Ubuntu package `gnucobol3 3.2-4build1`, WSL2 Ubuntu on Windows 11.
- `cobc -std=cobol2014 -fformat=free -x -o fpesize fpesize.cob && ./fpesize`
- Witness: n3-fz04593 (`PIC 9.99E+99` and `PIC 9,99E+99` displayed uninitialized with 7 characters where WiseOwl has 8).

## Observed result

cobc exit 0, no diagnostic (only the toolchain's `_FORTIFY_SOURCE redefined` warning). Run, exit 0:

```
7
```

## Expected result (per ISO)

ISO/IEC 1989:2023 §13.18.40.4 rule 14), each citation checked with `scripts/spec/cite.py --check`:

- "E The symbol 'E' represents a character position into which the character 'E' will be inserted during editing.
  The symbol 'E' is counted in the size of the item."
- "+ - CR DB These symbols represent the character position(s) into which the editing sign control character(s) is
  (are) placed during editing. Each character used in the symbol is counted in the size of the item."
- Rule 13) b): "The exponent shall be '+9', '+99', '+999', '+9999', or '+9(n)' where n = 1, 2, 3, or 4." The `+` is a
  symbol of the exponent part.

`9.99E+99` is 9, `.`, 9, 9, `E`, `+`, 9, 9: eight character positions. Expected output `8`.

Edition: the floating-point numeric-edited PICTURE was introduced in ISO/IEC 1989:2002 (WiseOwl's edition registry row
`pic-external-float-2002`), so it is part of the 2014 edition `-std=cobol2014` claims.

Edition as recorded by the adjudicator: 2014. `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Class

Wrong output (wrong item size; silent).

## Our compiler (WiseOwl)

`cobol.exe fpesize.cob --std 2014 --source-format free -o fpesize.dll`: exit 0; `dotnet fpesize.dll`: `8`, exit 0.

## Fix site (GnuCOBOL 3.2 source, read observationally)

`cobc/tree.c`, function `cb_build_picture`: `case 'E'` (lines 3782-3787) recognises `E+`, sets the floating-point
edited category and advances past the `+` (`p++`); the size calculation after the switch (lines 3813-3815) then adds
the repeat count of `E` only, so the `+` is never counted. A fix adds one to `size` for the skipped `+` (or keeps it as
its own symbol).

the switch counts only the 'E'.
