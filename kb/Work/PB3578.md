# PB3578 - an ended kept state leaves the registry's unpublished record locks held

## Lead (PB3533 report, new defect 3; the implementer did not run it)

`FileRegistry.ReleaseKeptOf(name, k)` (FileRegistry.cs, near line 1229) is THE ONE GIVING BACK of a kept state: it calls
`ReleaseAllForConnector(name)` first (the table's locks by name, which covers a lock no host published, PB3480/PB3484) and then
`k.ReleaseKept()`. The paths that end a kept state from INSIDE the connector call `KeyedConnector.ReleaseKept()` alone: PB3493's
absent arms and PB3533's `EndWhatWasKeptOfAnotherFile` hook (`KeyedConnector.cs`, `ReleaseKept` at line 697, callers at lines
255, 278, 459 and 462). The connector does not know its registry name, so it cannot call `ReleaseAllForConnector(name)`.
`ReleaseKept` releases only the locks published through the kept endpoint (`PhysicalFileTable.ReleaseThrough`).

### Suspected failure (unverified)

Under APPLY COMMIT a record lock the host could not publish is held by the table alone, for the closed connector, by name
(PB3480). If the kept state then ends because the file vanished or was replaced, the unpublished lock stays in the run unit's
table for a connector with nothing left to release it, and another connector of the same run unit gets '51' on that record until
the run unit ends. Verify first: a keyed file under APPLY COMMIT where the host refuses to publish a lock (the fault-injecting
test medium), READ WITH LOCK, CLOSE, remove the file outside the run unit, re-OPEN, then lock the same record through a second
connector. Discharge with evidence if it does not reproduce (rule I3).

## Fix shape (for the implementer)

If it reproduces: end the kept state through the registry's one release, never the connector's own, either by giving the
connector its registry key or by routing the ending hooks through `FileRegistry.ReleaseKeptOf` (one release in one place; do not
add a second). Cover each ending path (the absent arms, the replaced-file hook, the `InheritKept` route).

**Sites:** `src/Cobol.Net.Runtime/IO/KeyedConnector.cs` (`ReleaseKept`, line 697), `src/Cobol.Net.Runtime/IO/FileRegistry.cs`
(`ReleaseKeptOf`, `ReleaseAllForConnector`).

## Landed (wave 20261024, group A3)

**Re-probe (Windows, the unfixed runtime).** The lead reproduces, through the arm Windows can reach (the Linux-only arms need a file removed under an open
handle): on a host whose region locks answer unavailable for record bytes (`RecordBytesUnavailableHost`), a commit-controlled connector READs record 2
(one lock in the run unit's table, none published), is CLOSEd (PB3480: the CLOSE keeps it) and re-OPENed OUTPUT, which creates the file anew and ends the
kept state (`KeyedConnector.Recreate` → `ReleaseKept`). `RecordLocksHeldBy("F")` stayed 1 for a connector with nothing left to release it
(`An_open_output_over_the_kept_file_gives_back_the_record_locks_the_host_could_not_publish`, red on both organizations before the fix).

**Fix (DESIGN-runtime-library.md 2.2.1.10).** `KeptFile.Release` is now the ONE giving back of a kept state: it releases ALL the record locks its connector holds
on the physical file by `KeptFile.LockOwner` (`PhysicalFileTable.ReleaseAllForConnector`), unpublished ones included, then the handle, the file lock and the
attachment. The connector learns the name its locks are held under from the registry with the physical-file state at every OPEN
(`FileConnector.AssociatePhysical(state, lockOwner, locksRecords)`, `FileConnector.LockOwner`), so the registry's duplicate by-name release of a retired
state (`ReleaseAllKept`) is gone; `ReleaseKeptOf` keeps its by-name release for the OPEN connector's READ locks (COMMIT and ROLLBACK). The other endings
inside the connector (the absent OPTIONAL arms, the replaced-file hook) no longer END the kept state at all: PB3576 retires it, and the registry's
`KeptFile.Release` gives its locks back at the COMMIT, the ROLLBACK or the run unit's end. Sibling sweep: the four `ReleaseKept` callers were the two absent
arms (now retire), the replaced-file hook (now retire) and `Recreate` (fixed here); `InheritKept`'s route reaches the same hook.

**Witnesses.** `CommitRollbackRuntimeTests.An_open_output_over_the_kept_file_gives_back_the_record_locks_the_host_could_not_publish` (both
organizations; `FileRegistry.RecordLocksHeldBy` is its seam) and PB3576's `A_retired_kept_states_unpublished_record_locks_belong_to_its_file_and_end_with_the_commit`.
