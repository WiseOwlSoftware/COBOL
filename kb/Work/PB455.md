# PB455 — SET condition-name TO FALSE: parsed twice, implemented nowhere

Lane-3 adjudication batch b2, group g7-set-a. **Re-run on HEAD `89044aa0`**; still reproduces.

## 1. THE MECHANISM

The FALSE arm of Format 4 is accepted by **both** grammars and carried by neither.

* **The data side.** `Grammar/Core/CobolData.g4:622` parses `(WHEN SET TO FALSE_ IS? literal)?` on the VALUE
  clause — and **discards the literal**. `Condition88` (`Binding/Model/Condition88.cs`) has exactly one value
  member, `Values`, documented as the TRUE set, whose "first entry's `Low` is what `SET … TO TRUE` stores".
  There is no `FalseValue`, and a grep of the binder for `FALSE_()` finds one hit, in `EvaluateBinder`.
* **The statement side.** `CobolParserCore.g4:1248` accepts `SET dataReference+ TO (TRUE_ | FALSE_)`, and
  `SetBinder.BindSetCondition` (`SetBinder.cs:451-453`) answers a FALSE with:

      if (b.TRUE_() is null)
          return new BoundUnsupported("SET condition-name TO FALSE (the VALUE … WHEN SET TO FALSE phrase, …)");

  which the emitter renders as a `NotImplemented.Run` call.

⛔ **`BoundUnsupported` is the worst of the three available answers here.** It is not an edition gate, not a
compile-time diagnostic, and not a working feature: it is a **clean compile** followed by a .NET exception with
a stack trace *after* the program has already run and produced output. The user's build is green.

And because the FALSE literal never reaches the model, the compiler **cannot distinguish the conforming program
from the one SR7 forbids** — an `88` with `WHEN SET TO FALSE` and an `88` without it take the identical path to
the identical throw. One rule, no discrimination.

## 4. THE CODE SITES AND THE SHAPE OF THE REPAIR

| arm | file:line |
|---|---|
| the discarded literal | `src/Cobol.Net.Frontend/Grammar/Core/CobolData.g4:622` (`(WHEN SET TO FALSE_ IS? literal)?`) |
| the model with nowhere to put it | `src/Cobol.Net.Compiler/Binding/Model/Condition88.cs` (`Values` only) |
| the statement's refusal | `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/SetBinder.cs:451-453` |
| the statement's grammar | `src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4:1248-1250` |

⛔ **This is a data-model change, not a one-line binder edit, and the estimate should say so** (CLAUDE.md
rule 5). Four pieces, in this order:

1. **`Condition88` gains `FalseValue`**, read from the group the grammar already parses. A binder-only attempt
   fails immediately — the literal is gone by then.
2. **The store**, sharing GR6's path: GR6 and GR7 are the same sentence with a different literal source,
   including the group-item length rule and the zero-length leave-unchanged case. Write it **once** and have
   both arms call it; two near-copies is how the group-item tail ends up implemented on one arm only.
3. **The SR7 screen** — a `SET … TO FALSE` whose `88` carries no FALSE phrase is a compile-time error. That
   check is only *possible* once step 1 lands, which is why the row is NOT-IMPLEMENTED rather than DIVERGES.
4. **The COBOL-2002 introduction gate on the VALUE-clause phrase** (recognition-fired in
   `VersionConformancePass`, as the sibling VALUE formats are), so `--std 85` refuses it by name.

Until 1-4 land, the interim posture must at minimum stop being a run-time abort on a clean compile: a
`BoundUnsupported` here should be a **loud named compile-time refusal**, per the project's own staging
doctrine. A green build that dies at run time is strictly worse than a red build.

## 5. THE SIBLING SWEEP THE FIXER MUST DO

* **Every other `BoundUnsupported` reachable from a clean compile.** This note's harm is the *shape*, not the
  rule: grep `BoundUnsupported` and ask, for each, whether a conforming program can reach it with no
  diagnostic. `SetBinder` alone has four more (`SetBinder.cs:357`, `:375`, and the two condition-resolution
  arms at `:459`/`:462`).
* The `88` FALSE phrase also feeds the **class condition** and `EVALUATE … WHEN condition-name` paths;
  `EvaluateBinder` is the one place that currently touches `FALSE_()`, and it must agree with the new model.
* `INITIALIZE … TO VALUE` and the VALUE clause's other formats read `Condition88.Values`; adding a member is a
  data-model change that has to be swept through every reader.
* [[PB450]] owns Format 4's missing **outer repetition**. Both notes touch `setBooleanStatement`; if the
  Formats 3/4 productions are merged there, the FALSE arm's grouping comes for free — which is the argument for
  landing PB450's grammar shape first.
