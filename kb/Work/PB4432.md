# PB4432 - non-data declaration ranking ignores depth against a condition-name

**Defect.** PB4219 (landed) ranks only file-name against condition-name by containment depth in `NonDataDeclarationOf`.
The constant-name answer (line 98) and the index-name answer (line 101) still return before the condition-name check
whatever their depth, so a container's GLOBAL index-name or constant beats a contained program's own level-88 of the
spelling. ISO/IEC 1989:2023 8.4.6.2.1 3) a) ("If the name is declared in source element B, the item in source element B
is the referenced item.", checked with `cite.py --check`) makes the contained program's own declaration the referenced one.
The finisher adds: `SymbolTable.IndexCandidates` (SymbolTable.cs:229) ranks an index-name only against a nearer
data-name, so the same contained 88 may also lose a SET or PERFORM VARYING index position to the container's index.
That second half was not probed.

**Witness.** `E:/COBOL-coord/scratch/reports/w20261821a-PB2103-report.md`, R1-3 (low, not blocking at round 1);
`src/WiseOwl.Cobol.Compiler/Binding/DataBinder.NonDataNames.cs:98-101` at origin/main. `misleads_diagnosis` is set
conservatively from the report's wording (a wrong declaration chosen); the report does not say whether legal source is rejected.

**Fix direction.** Rank constant-name and index-name against condition-name by `DeclaringDepth` as PB4219 does for
file-name (one ranking, not one arm per kind), and make `IndexCandidates` take the condition-name into the same ranking.

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.NonDataNames.cs#NonDataDeclarationOf`, `src/WiseOwl.Cobol.Compiler/Binding/Model/SymbolTable.cs#IndexCandidates`, `src/WiseOwl.Cobol.Compiler/Binding/Model/SymbolTable.cs#NearerDataOrConditionNameHides`, `src/WiseOwl.Cobol.Compiler/Binding/ReferenceResolver.cs#CapacityRegisterFor`

## Landed (wave 20261825 group C)

Re-probed on the base build, all reproduced (probes under the wave scratch `p2`..`p7`): `OCCURS DEPENDING ON RELF` over a
contained 88 RELF beside the container's GLOBAL constant-name or index-name said "declared as a constant-name" / "an
index-name" (COBOL0851); `SET RELF TO 2` and `PERFORM VARYING RELF` compiled clean, binding the container's INDEX; `DISPLAY RELF`
named the index; and the sibling the note did not name, a container's GLOBAL named CAPACITY register, was silently displayed
for the contained 88 of its spelling (`CapacityRegisterFor` asked only a nearer data-name). Fix: `NonDataDeclarationOf` ranks the
constant-name, index-name, file-name and condition-name of a spelling together by `DeclaringDepth` (one `Offer` ranking, ties
keep the old order); `SymbolTable.NearerDataOrConditionNameHides` is the one question the index-name and capacity-register
classes ask, over `NearerDataNameHides` and `NearerConditionNameHides`. The constant arm in the procedure division was already
right (`DropShadowedConstants` asks `DeclaredNearerThan`); only the data division's clause operands met it before that ran.
Goldens: `cases/8.4.6.2-Local-and-global-names/pb4432_*` (four refusals, one accepted control). Drift test:
`GlobalNameClassDriftTests.ADataNameNarrowing_RanksTheReportEntriesToo`.

### Review round 1, R1-1 (the reverse arm)

`SymbolTable.NearestDeclaringConditions` asked only `NearerDataNameHides`, so a contained program's OWN index-name,
constant-name, named CAPACITY register or file-name never hid a container's GLOBAL level-88 of the spelling (`IF RELF` and
`SET RELF TO TRUE` compiled clean and used the container's condition-name; probes r1..r6 under the wave scratch `fin/`).
Fix: `DataBinder.NonConditionDeclarationsOf` is the one list of the constant-name, index-name and file-name classes,
which `NonDataDeclarationOf` ranks beside the condition-name and `NonConditionDeclarationNearerThan` asks the other way
round for the condition lookup; the register keeps its ONE lookup (`CapacityRegisterReferenceDriftTests`), so
`ConditionBinder.ConditionOf` asks `CapacityRegisterFor` of it. The condition-only position names the hiding class
(`HiddenConditionText`, `NonDataDeclaration.ClassPhrase`), a bare `IF` operand leaves a hiding declaration to the value
arm, and SEARCH ALL's WHEN screen skips the condition-name verdict for the first three. Goldens `pb4432_if_names_own_*`,
`pb4432_set_to_true_names_own_*`, control `pb4432_container_global_condition_name_beside_other_index_name`.

**Sites (review round 1):** `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.NonDataNames.cs#NonConditionDeclarationsOf`, `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.NonDataNames.cs#NonConditionDeclarationNearerThan`, `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.NonDataNames.cs#ConditionNameHiddenByNearerNonDataName`, `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs#ConditionTier`, `src/WiseOwl.Cobol.Compiler/Binding/Model/SymbolTable.cs#NearestDeclaringConditions`, `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/ConditionBinder.cs#ConditionOf`, `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/ConditionBinder.cs#ReportMisqualifiedCondition`, `src/WiseOwl.Cobol.Compiler/Binding/ReferenceResolver.cs#HiddenConditionText`, `src/WiseOwl.Cobol.Compiler/Binding/Validation/SearchAllFormat2Rules.cs`

**Review round 2 (R2-1, R2-2): the reverse arm counted a declaration the written qualifiers do not reach.** ISO 8.4.6.2.1 2)
("If only one item is identified, it is the referenced item") applies qualification over the whole set before rule 3 ranks
it by source element. R2-1: `IndexCandidates` answers a non-null EMPTY set when the spelling is declared but no index survives the
qualifiers, and `NearestDepth` called that depth 0, so an own `INDEXED BY RELF` hid the container's GLOBAL `88 RELF` from
`RELF OF X` (legal; COBOL1637/COBOL1639). R2-2: `CapacityRegisterFor` answers the nearest register with
`CapacityRefFault.Qualifiers` when the qualifiers reach none, and `CapacityRegisterHides` took any answer, so an own
`CAPACITY IN CAP` hid `CAP OF X`. Both re-probed on the reviewed head (refused), both accepted after the fix. Fix:
`NonConditionDeclarationsOf` ranks an unreached index-name at `int.MaxValue` (it stays the declaration the refusal words, but
never beats a condition-name); `CapacityRegisterHides` requires `Reached.Count > 0`. R2-3 (comment) fixed. Goldens
`pb4432_qualified_condition_name_beside_own_{index_name,capacity_register}` (IF and SET, outputs NOT then COND).
