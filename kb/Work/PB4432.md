# PB4432 - non-data declaration ranking ignores depth against a condition-name

**Defect.** PB4219 (landed) ranks only file-name against condition-name by containment depth in `NonDataDeclarationOf`.
The constant-name answer (line 98) and the index-name answer (line 101) still return before the condition-name check
whatever their depth, so a container's GLOBAL index-name or constant beats a contained program's own level-88 of the
spelling. ISO/IEC 1989:2023 8.4.6.2.1 3) a) ("If the name is declared in source element B, the item in source element B
is the referenced item.", checked with `cite.py --check`) makes the contained program's own declaration the referenced one.
The finisher adds: `SymbolTable.IndexCandidates` (SymbolTable.cs:229) ranks an index-name only against a nearer
data-name, so the same contained 88 may also lose a SET or PERFORM VARYING index position to the container's index.
That second half was not probed.

**Witness.** `E:/COBOL-coord/scratch/reports/w20261821a-PB2103-report.md`, R1-3 (low, not blocking at round 1);
`src/WiseOwl.Cobol.Compiler/Binding/DataBinder.NonDataNames.cs:98-101` at origin/main. `misleads_diagnosis` is set
conservatively from the report's wording (a wrong declaration chosen); the report does not say whether legal source is rejected.

**Fix direction.** Rank constant-name and index-name against condition-name by `DeclaringDepth` as PB4219 does for
file-name (one ranking, not one arm per kind), and make `IndexCandidates` take the condition-name into the same ranking.

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.NonDataNames.cs#NonDataDeclarationOf`, `src/WiseOwl.Cobol.Compiler/Binding/SymbolTable.cs#IndexCandidates`
