# PB4758 - IntegralForm folds a non-terminating literal quotient exactly

**What the report says (R2-3, low; left for the clerk because `IntrinsicArgumentRules.cs` was not changed in that round).**
`IntegralForm` folds a literal-only non-terminating quotient exactly: `ABS (1 / 3 * 3)` is 1 where the compiler arithmetic
stores 0.9999. The report names no probe path.

**R1.** No open note covers it. PB4709 (landed) added `IntegralForm`.

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/IntrinsicArgumentRules.cs#IntegralForm`.

**Fix (landed).** `IntrinsicArgumentRules.ProvablyIntegral` takes an exact integral fold as proof only when `QuotientsTerminate` holds (every quotient of the literal-only subtree has a terminating decimal value, `ExactRational.IsTerminating`), so `ABS (1 / 3 * 3)` stays Numeric and returns what `COMPUTE` stores. Probe on the pre-fix build: `MOVE FUNCTION ABS (1 / 3 * 3) TO PIC 9V9999` displayed `1.0000`, `COMPUTE` of the same expression `0.9999`. Witness: `conformance-suite/cases/15.3-Arguments/pb4758_abs_literal_quotient_value.cob`.
**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/IntrinsicArgumentRules.cs#IntegralForm`, `#ProvablyIntegral`, `#QuotientsTerminate`, `#ExactRational.IsTerminating`.
