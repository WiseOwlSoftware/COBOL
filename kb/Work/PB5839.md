# PB5839 - an unparseable WISEOWL_COBOL_CLOCK is silently ignored and the run uses the real clock

**The Mythos lane reproduced it** on Monday 2026-11-16 at 01:48 PST, on a compiler built at main d7d3f99539, after a refuter listed "unparseable pin" among its attempts (`E:/COBOL-coord/scratch/my-20261115/unwitnessable/refute/refute.json`, rows `1989-RV-A.2.11.3-2` and `-3`). Harm flags: none of a compiled program's (it is the test seam's); the Mythos lane decided `silent: true` (a mis-set pin gets no message) and `misleads_diagnosis: true`. Severity: MINOR.

**Sites:**
- `src/WiseOwl.Cobol.Runtime/IO/Clock.cs#SystemClock.Now` (reads `PinVariable` and falls back to `DateTimeOffset.Now` when `DateTimeOffset.TryParse` fails)

## Repro
```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. CLK.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WD PIC X(21).
       PROCEDURE DIVISION.
       P1.
           MOVE FUNCTION CURRENT-DATE TO WD.
           DISPLAY "D[" WD "]".
           STOP RUN.
```
Run at `--std 85` through `scripts/orchestrator/run_probe.py`:
- with `WISEOWL_COBOL_CLOCK=2001-02-03T04:05:06.78+09:00`: `D[2001020304050678+0900]`, exit 0 (the pin is honoured);
- with `WISEOWL_COBOL_CLOCK=not-a-date`: `D[2026111601481148-0800]`, exit 0, nothing on standard error. That is the
  host's real time when the program ran (2026-11-16 01:48:11 PST).

## Why it is a defect
The variable exists so a test run can pin the clock across processes (`src/WiseOwl.Cobol.Runtime/IO/Clock.cs`,
`PinVariable`). A pin the runtime cannot parse is an input it cannot resolve. It answers with the real clock, so a
test that mistypes its pin runs against wall time and passes or fails by the hour it ran: a false green, or a flake
with no message. The owner's standing rule (2026-11-11 feedback, "unresolvable fails loudly"): an input a tool
cannot resolve is a bug that fails, never a "safe" default.

## What a fix must decide (not decided here)
- The failure: a run-unit start error that names the variable and its value, with a nonzero exit.
- Whether an EMPTY value means "no pin" (unset) or is refused like any other value that does not parse.
- The sibling inputs of the same class in the runtime's environment variables (`WISEOWL_COBOL_*`): none was probed.
