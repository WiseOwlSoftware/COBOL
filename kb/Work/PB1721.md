## Landed (wave 72 group H, 2026-09-29): the ordered gate, and the selection interface deleted with every caller

**The driver, `scripts/run_gate_legs.py`**, implements DESIGN-test-build-ci.md sections 3.14.1, 3.14.3 and 3.14.4 as
written. In order it does the following:
- takes the worktree's gate lock (`gate_slot.ExclusiveLock` on `<worktree git dir>/cobol-gate.lock`);
- takes a gate slot in implementer mode;
- runs the audits (now ONE list, `AUDITS`; the two build-local copies are gone), fetches the corpus and builds;
- hashes the binaries and lists the three populations (concurrently) into a fresh run directory;
- builds the order plan in-process (`gate_plan.build_plan`; any planning failure gives ONE leg, named);
- runs the legs, the three assemblies concurrently, through `leg_env` (the scrubbed environment plus all three
  handshake variables or none) and `test_leg_report.py`, and fails fast after a red leg 1;
- then runs the population check per assembly (a stopped assembly's remainder is NOT RUN, every case written to
  `not-run-<assembly>.txt`), the identity check (digest, content digest, binaries, `received`, own-leg keys) and prints
  one `=== BUILD-LOCAL GATE: … ===` line plus `verdict.json` (timings, first red, slot, plan).
A defect in the driver still ends in a `NOT RUN` verdict line, because every caller blocks on that line.
`build-local.ps1 -Mode implementer|lander` and `build-local.sh --mode …` only set the priority and call it.

**Deleted with every caller (rule 4):** `-Filter`, `impacted_tests.py`'s filter line and `--plus`. The callers changed
were MANDATORY-PRACTICES I1, I2, I7 and L2, the implementer, fix-lane, dispatch-spec, lander and lander-train briefs,
`check_practices.py` (the `impacted_tests\.py --base` patterns became `-Mode implementer` / `-Mode lander` /
`BUILD-LOCAL GATE` ones), the workstream and gate skills (line 29 rewritten), `cobol-implementer.md`,
`cobol-lander.md`, `forbidden_commands.py` and its fixture, `ImpactedTestsDriftTests`, `TestLegReportDriftTests`,
`FilterPopulationGuardDriftTests` (the population now names the three remaining filtered sites), `GateLegDriftTests`
(arm 3's driver half; arm 6's sites), `DRIFT_RULES.md`, `DOC_INDEX.md` (a new row for the gate), plan §0 and §9,
README, CONTRIBUTING, the PR template, the implementer report template, and `wf_rolling_wave.js` (`gate_filter`
became `gate_run`, the gate's run directory). CLAUDE.md "Testing" was updated under the owner's standing
authorization. The recorder takes a slot and spawns every child through `Slot.spawn_kwargs`. The gated-assembly list
now has one statement, `test_population.GATED_ASSEMBLIES`, which the recorder and `impacted_tests.py` import.
`gate_plan.read_listing` now reads through `test_population.parse_listing`, the one listing parser.

**A design correction** (DESIGN section 3.14.6): `Slot.spawn_kwargs` turns persistent build servers OFF
(`MSBUILDDISABLENODEREUSE=1`, `UseSharedCompilation=false`). A reused MSBuild node or VBCSCompiler started inside a
slot is one that other worktrees' builds connect to. On Windows the kill-on-close job would kill it mid-way through
another gate's build. On Linux it would hold the slot for its whole idle lifetime.

## Landing

- `scripts/run_gate_legs.py#Gate._gate`: the ONE gate sequence. Add a new check as a step here, never in
  `build-local.ps1`/`.sh` (they only set the priority). Every verdict goes through `Gate._finish`, which prints the one
  `=== BUILD-LOCAL GATE: ` line; a defect raises into `Gate.run`'s handler, which still prints `NOT RUN`.
- `scripts/run_gate_legs.py#leg_env`: the only place a test host's environment is made (scrubbed, plus all three
  handshake variables or none). `Host` is the machine; the self-test's `FakeHost` plants each arm. A new arm plants
  its defect there and asserts on `Outcome`.
- `scripts/run_gate_legs.py#AUDITS`: the gate's audit list, in order. battery.sh PHASE -1 and CI's `audits` job carry
  their own copies; change all three.
- `scripts/gate_slot.py#ExclusiveLock` (the worktree lock) and `#drop_git_local_env` (make a self-test's git calls
  hermetic): REUSE both. A self-test that builds git repos must call `drop_git_local_env()` first.
- `scripts/gate_slot.py#Slot.spawn_kwargs`: ALWAYS spawn a slot holder's children through it, since it carries the
  Linux fd and the build-servers-off environment. `test_population.list_population(**spawn)` accepts it.
- `scripts/test_population.py#GATED_ASSEMBLIES`: the one list of the gated test projects (the recorder and
  `impacted_tests.py` import it).
