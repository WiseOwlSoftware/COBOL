# PB2599 — the build guard does not speak either shell's location changes

**Model:** Opus (tooling with self-tests). Dispatched with PB2598 as one group (wave 1038 U).

## Defect

`scripts/hooks/fleet_active_build.py:102` `CD_PREFIX_RE = ^\s*cd\s+(dir)\s*(&&|;|&)`, and `effective_cwd` (:309) honours
only that prefix. Every other way the Bash and PowerShell tools change directory is read as "builds in the payload's
cwd", which for the operator and for a non-isolated agent is the main checkout, so while any main-tree fleet is live
the build is DENIED even though it runs in a worktree that fleet never touches (the false denial PB279 and PB474
removed for the leading-`cd` spelling).

Measured from the operator's transcripts (account 2, session 9a5c41bd and its subagents, 2026-10-07/08), every denial
by this hook, with its command:

| UTC | tool | command shape | why denied |
|---|---|---|---|
| 21:02 | PowerShell | `Set-Location E:\COBOL\.claude\worktrees\pin-97006f3; dotnet build …` | `Set-Location` not recognised: judged the main tree |
| 01:04 | PowerShell | `Set-Location …\runtime-r2r; (Measure-Command { dotnet publish … })` | the same |
| 03:31 | Bash | `git worktree add … pin-r2 … && cd /e/COBOL/.claude/worktrees/pin-r2 && dotnet build …` | `cd` not LEADING |
| 01:02, 06:06 | Bash | `mkdir -p … && cd /e/COBOL/.claude/worktrees/<wt> && dotnet build …` | the same |
| 07:00 | Bash | `ls …STOP… ; cd E:/COBOL/.claude/worktrees/selftests-gate && dotnet build …` | the same |
| 21:41 | Bash | `cd /e/COBOL-coord/scratch/w1031-refute7/walk; timeout 600 dotnet run walk.cs …` | recognised; the directory is in NO working tree, so UNKNOWN |
| 00:01, 00:04, 06:03, 06:11 | Bash | `cd <scratch probe or pinbuild copy> && dotnet build` | the same UNKNOWN arm |

The refuter's 14:40 PDT (21:41 UTC) `dotnet run`, recorded by the operator as "the same family", is NOT: its leading
`cd` was recognised, and the deny is the deliberate UNKNOWN arm (a scratch directory belongs to no working tree, and a
scratch project can `ProjectReference` a worktree's project: `w1033-perf/probe/Probe.csproj` references
`E:\COBOL\.claude\worktrees\perf-gate\src\Cobol.Net.Compiler`, so the trees such a build writes cannot be read off its
directory). That arm stays as designed.

## Siblings (the same question asked by other hooks)

- `scripts/hooks/worktree_rm_allow.py:35` `CD = ^(?:cd|Set-Location)\s+(\S+)\s*$`: a second, different parser of the
  same prefix (no quoted path with spaces, no `-Path`, no `sl`/`Push-Location`/`pushd`).
- `scripts/hooks/forbidden_commands.py:97` `cds = re.findall(r"(?:\bcd|\bSet-Location|\bgit\s+-C)\s+…")`: a third
  (no `sl`, `chdir`, `pushd`, `Push-Location`, `-Path`, quoted paths with spaces).
- `scripts/hooks/status_guard.py:69` reads the payload `cwd` only, so `cd <worktree> && git commit` (or
  `git -C <worktree> commit`) from the main checkout checks the MAIN tree's STATUS.md, finds none and stays silent:
  the guard fails open for exactly the agents that address their worktree by path.
- The build's own target: `dotnet build <path>.sln` / `--project <path>` writes the tree the PROJECT is in, whatever
  the cwd; the guard judged the cwd, so a worktree-cwd build of the main checkout's solution was ALLOWED while a
  main-tree fleet was live (the harmful direction).

## Landed (branch w1038u-session-checks, wave 1038 group U)

- ONE parser, `scripts/hooks/shell_location.py`: `steps(command, cwd, shell)` splits a Bash or PowerShell tool call
  into its simple commands and gives each the directory it runs in, following `cd` (any position, `-`, no argument),
  `pushd`/`popd`, `( … )` subshells (changes end at `)`), `{ … }` groups, `bash -c` payloads (a child), Bash `&` and
  pipes (no persistence); `Set-Location`/`sl`/`cd`/`chdir`/`Push-Location`/`Pop-Location` with a positional path or
  `-Path`/`-LiteralPath`/`-LP`/`-PSPath` (also `-Path:dir`), `pwsh -WorkingDirectory|-wd … -Command` (a child),
  `Start-Process -WorkingDirectory`; quotes, escapes, `$( )`, heredoc bodies and here-strings never split; literal
  variables set earlier in the call are substituted; anything the line does not determine is `None` (UNKNOWN), never
  the payload cwd. `location_targets` and `git_dir` (git's `-C`) answer the other hooks' questions from the same walk.
  `native_path` (PB474's MSYS drive mapping) and `is_absolute` (either platform, PB2142) moved here.
- `fleet_active_build.py`: `CD_PREFIX_RE`/`effective_cwd` deleted; `build_sites` judges every `dotnet <verb>` command
  where it runs, and on the project it NAMES (`dotnet build <x>.sln`, `--project`, `dotnet run walk.cs`), which also
  closes the harmful direction (a worktree-cwd build of the main checkout's solution was allowed while a main-tree
  fleet was live). Module code moved into `main()` so the functions import.
- Siblings, all on the one parser: `worktree_rm_allow.py` (its own `CD` regex and chain split deleted; the grant still
  covers only one location change joined by `&&`, never `;`, a subshell or a `-c` payload), `forbidden_commands.py`
  (its `cd|Set-Location` regex replaced by `location_targets`; git's `-C` stays its own), `status_guard.py` (checks the
  STATUS.md of the tree each `git commit` runs in, `commit_dirs`; it used to check the payload cwd and stayed silent
  for an agent committing in its worktree by path). `devlog_staged.py` asks the same wrong-tree question and is filed
  as PB2605 (its fix needs the owner's scope decision).
- The refuter's 2026-10-07 21:41 UTC `cd <scratch>; dotnet run walk.cs` is NOT this family: the leading `cd` was read,
  and a directory outside every working tree is the deliberate UNKNOWN arm (stated in the hook and in
  DESIGN-test-build-ci.md section 1.7, with the `ProjectReference` evidence above).
- Tests: `scripts/hooks/test_shell_location.py` 61 cases (every shape in the table above, Bash and PowerShell);
  `fleet_active_build.py --self-test` gained 17 scope cases (the six transcript shapes, the harmful direction, the
  UNKNOWN scratch arm); `status_guard.py --self-test` 4 (cd, -C, Set-Location, a subshell visit);
  `test_worktree_rm_allow.py` +12; `test_forbidden_commands.py` +10. All green on Windows and under WSL. The test file,
  `fleet_active_build.py --self-test` and `status_guard.py --self-test` run in every gate, CI and the Linux gate
  through `scripts/self_tests.py` discovery (kb/Work PB2563; train 1039b dropped the branch's hand-list entries; the
  last two ran nowhere before).

**Train 1039b review (lander).** `worktree_rm_allow.py` granted a `git rm -r` carrying a command substitution or a redirect (both run or write before git starts; the hole predates this rewrite); a git command with `$`, a backquote, `<` or `>` is now never covered (`test_worktree_rm_allow.py`).
