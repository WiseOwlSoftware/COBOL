```
$ python scripts/spec/cite.py --check 13.18.8.4 "the value being stored is zero"
OK  §13.18.8.4 1)  (General rules)
    1) When the BLANK WHEN ZERO clause is specified for a data item, the content of the data item is set
       to all spaces when the item is a receiving operand and the value being stored is zero.
```

## ⛔ (5) An INHERITED QUOTATION whose text is in NO clause, found by this pass

Recorded here because it is the same failure one level worse. The `PB425` report supports its lead with
§13.18.45.4 GR2 and quotes **"considered to be a group item"**:

```
$ python scripts/spec/cite.py --find "considered to be a group item"
NO CLAUSE contains 'considered to be a group item' — the citation names text the standard does not have
```

The clause number is right; the words are a paraphrase presented as a quotation. The real sentence —
"data-name-1 **defines an alphanumeric group item**" — is quoted in **PB907**. A `--check` against the
paraphrase FAILS, which is the system working; what failed is that the report shipped without running it.

## Why the audit passes all four

`audit_code_citations.py` verifies that the cited clause EXISTS. §8.5.1.3 exists. §13.18.7 exists. The
audit is therefore green on a citation that sends the reader to the wrong rule — which is precisely the
inheritance failure CLAUDE.md rule 1 describes, and precisely what **PB900** (registrar #6) asks the audit
to grow the ability to see. The two notes are one fill unit: PB900 builds the detector, this one is the
population it will find and the four that are already known.

## The sweep

`grep -rn "13\.18\.7" src/` for every other site that means BLANK WHEN ZERO, and `grep -rn "8\.5\.1\.3"
src/` for the §8.5.1.3 family — then, for each hit, `cite.py --check` the clause against the text the
comment actually asserts. Not the other way round.
