# PB2151 — D10's second half: subscript and ref-mod positions onto BoundExpr

## Landed (wave 1033 U and its finisher U2) — every position is a typed node

The repro grep (`grep -rn "RenderSegment\|SubscriptExpressionFragment.Parse" src`) is empty. The fix is the design the
measured scope below called for (rule 5), written first as `docs/rearchitecture/DESIGN-binder-bound-tree.md` §3.9: a
position is a typed `Position` node (`Binding/Model/Position.cs`) from the parse to the code generator, not a
`BoundExpr` per position. A position that renders directly as an ordinal (a constant, an index cell, an item read, `+ - *`,
a written parenthesis) is a node; every other arithmetic expression binds through the ONE expression binder into the §15.4
temporary and is a `PositionItemRead` of it, so §8.4.2.3.4 GR1 b) is still asked once, of the result. Every offset and
ordinal of the place model is one node, `PositionOffset(origin, (index − 1) × stride terms)`.

- Deleted: `RenderSegment` (5 sites), `SubscriptExpressionFragment` and the `subscriptExpressionFragment` grammar
  entry, the D18 text re-parse (`MaterializeSubscriptSegment(expr, text, …)` is `BindPositionTemporary(expr, …)`; the

## Mechanism

PB2113 landed D10's first half: the lexer `SUBSCRIPT` mode and the `SUB_*` tokens are gone, and every subscript,
reference modifier and keyword-omitted argument list is a parse node (`subscriptPart`, `refModPart`, `refModSpec`,
whose positions are the superset `functionArgument`). But the binder still reads those nodes as TOKEN RUNS:

- `src/Cobol.Net.Compiler/Binding/ReferenceResolver.cs#RenderSegment` renders a segment's tokens into a C# expression
  string at bind time (the transitional carrier `RefModSpec` / `RefModPlace.Start` / `Length` hold).
- Whatever that renderer cannot render goes to
  `src/Cobol.Net.Compiler/Binding/Bound/StatementBinder.SubscriptSegments.cs#MaterializeSubscriptSegment`, which
  re-parses the segment's TEXT through `src/Cobol.Net.Frontend/Parsing/SubscriptExpressionFragment.cs` (the D18
  route) to bind it into a temporary.

So one position is parsed twice (once by the grammar, once by the fragment parser) and carried as a string, which is
the shape D10 exists to remove (`docs/rearchitecture/DESIGN-frontend-grammar.md` §9 status, D10.3;
`StatementBinder.SubscriptSegments.cs` class remarks: "a mechanism designed to be deleted").

## Fix shape

Bind each position node (`functionArgument` under `subscriptItem` / `refModSpec`) through the ordinary expression
binder into a `BoundExpr`, carry `BoundExpr` in `RefModSpec` and the subscript place, and have codegen render it.
That deletes `RenderSegment`, `SubscriptExpressionFragment` and the `subscriptExpressionFragment` grammar entry, and
keeps the COBOLNET2363 refusal (a position that is not an arithmetic expression, kb/Work PB1030) as a binder check on
the node. Behaviour-neutral: prove it with the emitted-C# oracle (`scripts/arch/compare_oracle.py`) plus the corpus.

## Repro

Structural, not behavioural: `grep -n "RenderSegment\|SubscriptExpressionFragment.Parse" src -r` lists the carrier's
call sites on any tree after PB2113.

## Scope, measured (wave 1030 A, 2026-10-07 — the estimate above was one carrier; it is a position IR)

Re-probed on `a468b3dd1`: the repro still lists `RenderSegment` (5 sites) and `SubscriptExpressionFragment.Parse` (1).
But the string does not stop at `RefModSpec` / `RefModPlace`. A rendered position is spliced into SEVEN string
carriers of the place model, and codegen re-reads every one of them as text:
- `AccessPath` segments `FixedTableSegment.OneBasedIndex`, `DynTableSegment.OneBasedIndex`,
  `CellTableSegment.Ordinal` (`Binding/Model/AccessPath.cs`; rendered by `CodeGen/Roslyn/PlaceRenderer.cs` ~L313);
- `RedefViewPlace.OffsetExpr` and `BitWindow.OffsetExpr` / `ClassRelativeExpr` — the byte offset of a subscripted
  view is string ARITHMETIC over the subscripts (`0 + (Occ(I) + 1 - 1) * 3 + 1`, `RedefViewPlace.For`);
- `DynSlotWindow.Ordinal`, `VarGroupWindow.DynBase`, `TableAllPlace.IndexVar`;
- `RefModSpec` / `RefModPlace.Start` / `Length`.
`CodeGen/Roslyn/PlaceIdentification.cs#FreezePath` / `HoistFragment` hoists each of them AS A STRING (the §14.6.4
evaluate-once identification), deciding "is this a constant" by `All(char.IsAsciiDigit)`.

So the fix shape needs a design step first (rule 5): a typed POSITION carrier for the place model — a `BoundExpr` per
written position plus a structured offset (terms of `position × stride + constant`) for the view and window offsets,
rendered by codegen and hoisted by `PlaceIdentification` as nodes — written into `docs/rearchitecture/DESIGN-binder-bound-tree.md`
(its "subscripts as BoundExpr (D10's second half)" row) before code, then migrated carrier by carrier with
`compare_oracle.py` IDENTICAL (or explained by class) after each. Wave 1030 A landed PB2152 and SPLIT here at the note
boundary, as its dispatch required for a second mechanism.
