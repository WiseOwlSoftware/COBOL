# PB3978 — the inexact DivToOdd rows are computed and never asserted

**Sites:** `tests/WiseOwl.Cobol.Tests.Unit/CobolDecDivisionTests.cs` (`CobolDecDivisionTests.AnExactQuotient_IsHeldAtThePreferredExponent_AnInexactOneFillsTheDigits`).

Filed 2026-10-28 by the enqueue unit's clerk from the PB3954 branch review's R1-1 lead (low), carried unchanged.

The test's comment says round-to-odd reduces the same exact value the same way and that "the inexact ones differ only in
the last digit (odd), so they are compared by value below". No such comparison exists: for the rows whose `expected`
ends in `E-34`, `CobolDec.DivToOdd` is computed and the `if (!expected.EndsWith("E-34"))` guard skips the assertion, so
the inexact native-lane quotient is not checked. Assert the inexact rows (the value to 33 digits, the last digit odd, or
the stated value-equality) with expected values derived from the cited rule (ISO 8.8.1.5.3 division, via
`cite.py --check`), or delete the comment and say what the guard leaves unpinned.
