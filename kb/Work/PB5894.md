# PB5894 - crossfooting runs in dependency order, not in the order the sum counters are defined (--std 85)

Filed by the PB5789 branch from the Mythos lane's rulings on the printed folios, `kb/Work/PB5683/2026-11-17-rulings-pb5789-folios.md`. The ruling's bullet, unchanged:

- kb/Work PB5894 (wrong answer, 1985 only unless another edition's own text says the same; every edition's rule to be
  read): the compiler crossfoots in dependency order, not definition order. `SA SUM SB SC`, `SB SUM SC`,
  `SC SUM WS-A` prints `CF +006 +003 +003`, where definition order gives SA = SB (0) + SC (3) = 3. Programs:
  `E:/COBOL-coord/scratch/my-20261115/w20262099/f/probes/sumxo.cob` and
  `.../f/refute-sum/probes/rford.cob`.

**The rule.** `§1985:XIII.3.19.4 GR9a` (printed folio XIII-54, kb/Work PB5789): "Crossfooting is performed according to the sequence in which sum counters are defined within the control footing report group. That is, all crossfooting into the first sum counter defined in the control footing report group is completed, and then all crossfooting into the second sum counter defined in the control footing report group is completed." (`cite.py --check`: OK, the text is in GR9a.)

**The refuter's program** `rford.cob` (`E:/COBOL-coord/scratch/my-20261115/w20262099/f/refute-sum/probes/rford.cob`), in full:

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. RFX.
       ENVIRONMENT DIVISION.
       INPUT-OUTPUT SECTION.
       FILE-CONTROL.
           SELECT PF1 ASSIGN TO "RFX.OUT".
       DATA DIVISION.
       FILE SECTION.
       FD PF1 REPORT IS R1.
       WORKING-STORAGE SECTION.
       01 WS-KEY PIC 9 VALUE 1.
       01 WS-A   PIC 99 VALUE 0.
       REPORT SECTION.
       RD R1 CONTROL IS WS-KEY.
       01 D1 TYPE DE LINE PLUS 1.
          02 COLUMN 1 PIC 99 SOURCE WS-A.
       01 CFK TYPE CF WS-KEY LINE PLUS 1.
          02 SA COLUMN 1  PIC 999 SUM SB SC.
          02 SB COLUMN 5  PIC 999 SUM SC.
          02 SC COLUMN 9  PIC 999 SUM WS-A.
       PROCEDURE DIVISION.
       DECLARATIVES.
       CF-USE SECTION.
           USE BEFORE REPORTING CFK.
       CF-USE-P.
           DISPLAY "CF " SA " " SB " " SC.
       END DECLARATIVES.
       MAIN SECTION.
       P0.
           OPEN OUTPUT PF1.
           INITIATE R1.
           MOVE 1 TO WS-A. GENERATE D1.
           MOVE 2 TO WS-A. GENERATE D1.
           MOVE 2 TO WS-KEY.
           MOVE 4 TO WS-A. GENERATE D1.
           TERMINATE R1.
           CLOSE PF1.
           STOP RUN.
```

Printed at `--std 85` (run `.../f/refute-sum/runs/rford-001`, exit 0):

```
CF +006 +003 +003
CF +008 +004 +004
```

By GR9a: SC holds 3 (then 4) by subtotalling. Crossfooting into SA, the first counter defined, is completed first, while SB still holds zero. So SA = 0 + 3 = 3 (then 4). SB = 3 (then 4). Expected `CF +003 +003 +003` and `CF +004 +004 +004`.

**The proposer's program** `sumxo.cob` (`E:/COBOL-coord/scratch/my-20261115/w20262099/f/probes/sumxo.cob`), in full:

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. SUMXO.
      * GR9a: crossfooting in the order the counters are defined;
      * a counter that is its own addend contributes its value at
      * the time of summation.
       ENVIRONMENT DIVISION.
       INPUT-OUTPUT SECTION.
       FILE-CONTROL.
           SELECT PF1 ASSIGN TO "SUMXO.OUT".
       DATA DIVISION.
       FILE SECTION.
       FD PF1 REPORT IS R1.
       WORKING-STORAGE SECTION.
       01 WS-KEY PIC 9 VALUE 1.
       01 WS-A   PIC 99 VALUE 0.
       REPORT SECTION.
       RD R1 CONTROL IS WS-KEY.
       01 D1 TYPE DE LINE PLUS 1.
          02 COLUMN 1 PIC 99 SOURCE WS-A.
       01 CFK TYPE CF WS-KEY LINE PLUS 1.
          02 S3 COLUMN 1  PIC 999 SUM S2.
          02 S1 COLUMN 5  PIC 999 SUM WS-A.
          02 S2 COLUMN 9  PIC 999 SUM S1.
          02 S4 COLUMN 13 PIC 999 SUM S1.
       PROCEDURE DIVISION.
       DECLARATIVES.
       CF-USE SECTION.
           USE BEFORE REPORTING CFK.
       CF-USE-P.
           DISPLAY "CF " S3 " " S1 " " S2 " " S4.
       END DECLARATIVES.
       MAIN SECTION.
       P0.
           OPEN OUTPUT PF1.
           INITIATE R1.
           MOVE 1 TO WS-A. GENERATE D1.
           MOVE 2 TO WS-A. GENERATE D1.
           MOVE 2 TO WS-KEY.
           MOVE 4 TO WS-A. GENERATE D1.
           TERMINATE R1.
           CLOSE PF1.
           STOP RUN.
```

Printed at `--std 85` (run `.../f/runs/sumxo-001`, exit 0):

```
CF +003 +003 +003 +003
CF +004 +004 +004 +004
```

By GR9a: S3 is defined first, so crossfooting into it is completed while S2 still holds zero. Expected `CF +000 +003 +003 +003` and `CF +000 +004 +004 +004`.

**Every edition's rule to be read.** 2023 states the opposite order: `§2023:13.18.54.4 GR6`, "The additions necessary to compute its value are completed before the adding of the operand into the current sum counter". The fix is an edition behaviour for 1985. Each held edition's own text (2002, 2014) decides its arm.
