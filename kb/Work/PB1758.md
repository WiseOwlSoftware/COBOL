# PB1758 — OPEN

Found 2026-09-29 during PB1689. Measured on the current build: a program with `REMARKS. THIS IS THE OLD COMMENT ENTRY.` after PROGRAM-ID compiles clean (exit 0, no warning) at `--std 85`, `--std 2014` and the default 2023. `CobolParserCore.g4` (~line 406) says the REMARKS paragraph is "a COBOL-74 carryover, accepted at 85 for the CCVS and removal-gated at 2002+ — COBOLNET0902"; PB1494 made the comment-entry text scanning IDENTIFICATION-DIVISION-scoped in the preprocessor, which may now swallow the paragraph before the parser's gate can see it.

**What must be established before any change:** (1) which editions still print the AUTHOR / INSTALLATION / DATE-WRITTEN / DATE-COMPILED / SECURITY / REMARKS paragraphs — read the IDENTIFICATION DIVISION general format of ISO 2023 and 2002/2014, Annex E and `docs/VERSION_CHANGE_REFERENCE.md` (the spec decides; do not infer from the grammar comment); (2) whether the current silence is a defect (a removed element accepted with no diagnostic, so §4.2.10 nonstandard-extension flagging is also silent) or a deliberate acceptance that needs a `docs/CONFORMANCE.md` entry; (3) whether the gate exists and the preprocessor bypasses it (probe the same source with the paragraph in a position the preprocessor does not treat as a comment entry); then per-edition goldens (accept at the editions that keep it, COBOLNET0902-class rejection where removed).
