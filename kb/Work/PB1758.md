# PB1758 — OPEN

Found 2026-09-29 during PB1689. Measured on the current build: a program with `REMARKS. THIS IS THE OLD COMMENT ENTRY.` after PROGRAM-ID compiles clean (exit 0, no warning) at `--std 85`, `--std 2014` and the default 2023. `CobolParserCore.g4` (~line 406) says the REMARKS paragraph is "a COBOL-74 carryover, accepted at 85 for the CCVS and removal-gated at 2002+ — COBOLNET0902"; PB1494 made the comment-entry text scanning IDENTIFICATION-DIVISION-scoped in the preprocessor, which may now swallow the paragraph before the parser's gate can see it.

**What must be established before any change:** (1) which editions still print the AUTHOR / INSTALLATION / DATE-WRITTEN / DATE-COMPILED / SECURITY / REMARKS paragraphs — read the IDENTIFICATION DIVISION general format of ISO 2023 and 2002/2014, Annex E and `docs/VERSION_CHANGE_REFERENCE.md` (the spec decides; do not infer from the grammar comment); (2) whether the current silence is a defect (a removed element accepted with no diagnostic, so §4.2.10 nonstandard-extension flagging is also silent) or a deliberate acceptance that needs a `docs/CONFORMANCE.md` entry; (3) whether the gate exists and the preprocessor bypasses it (probe the same source with the paragraph in a position the preprocessor does not treat as a comment entry); then per-edition goldens (accept at the editions that keep it, COBOLNET0902-class rejection where removed).

## Measured and resolved (research 2026-09-30, tree 4a1dda60e)

The open question is answered — **the gate is right and the fixed-form converter bypasses it**:

| Probe | 85 | 2014 | 2023 |
|---|---|---|---|
| fixed form `REMARKS. THIS IS THE OLD COMMENT ENTRY.` | rc 0 | rc 0, **silent** | rc 0, **silent** |
| fixed form `AUTHOR. SOMEONE.` | rc 0 | rc 0, silent | rc 0, silent |
| free form REMARKS (`--source-format free`) | rc 0 | COBOLNET0902 "the REMARKS paragraph was removed in COBOL-2002", rc 70 | COBOLNET0902 |
| free form AUTHOR | rc 0 | COBOLNET0902 (identification comment paragraph) | COBOLNET0902 |

(1) ISO 2023 §11.2.1's general format lists only the seven source-unit paragraphs and `[ options-paragraph ]`
(`cite.py --check 11.2.1 "options-paragraph"` OK) — no comment-entry paragraph; VCR Table 7 row 7.10 records their
deletion at 2002 and `constructs.json` rows `identification-comments-removed-2002` / `remarks-removed-2002` gate them
(`VersionConformancePass.cs#VisitAuthorParagraph` … `#VisitRemarksParagraph`). (2) The fixed-form silence is therefore
a DEFECT (an under-rejection at 2002+, and a fixed/free divergence), not a deliberate acceptance: `FixedFormConverter
.IsCommentEntryText` discards the header with the body at every edition. (3) Yes — the gate exists and the
preprocessor bypasses it; free form reaches it. This is exactly PB1494's "a finisher owes (the EDITION scope)"; the
design is PB1802 A. The one residual edition question (REMARKS at 85 — a CCVS accommodation applied to every 85
compilation) is PB1802's evidence question 2.
