# PB5071 - at --std 85 an FD with a RECORD clause and no record description entry compiles (the 2023 implied-record rule applies at every edition), and an SD file-control entry accepts clauses after ASSIGN

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/FileControlBinder.FileSection.cs#MaterializeImpliedRecord` (called when `file.Records.Count == 0`; implements the 2023 rule at every edition). The SELECT-for-SD site is not named by the records.

**Mechanism.** 1985 says one or more record description entries must follow every file description entry, with no exception for a RECORD clause, and that only ASSIGN may follow the file-name of a sort or merge file in FILE-CONTROL. The compiler implements the later editions: an FD with a RECORD clause and no record entry gets an implied record (MaterializeImpliedRecord, no 85 arm), and an SD SELECT with other clauses is accepted.

**Found by.** The 1985 `--std=85` draft triage (kb/Work PB4995 item 3): each rule below is a conformance-suite draft that did not MATCH at `--std 85`, and its adjudicator decided COMPILER-DEFECT. Harm and observed text are the records'; nothing here was re-derived.

**Inventory.** The traceability inventory carries no 1985 rows yet, so `inventory_rows` is empty; the rows this note covers are the 1985 rule ids listed below (catalog `docs/rearchitecture/spec-rule-catalog-1985.json`).

**Rules (3; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-SR-VII.3.2.3-3` - `§1985:VII.3.2.3 SR3` (record harm: under-rejects, slice-06): §1985:VII.3.2.3 SR3: "One or more record description entries must follow the file description entry." The rule has no exception: in the 1985 text a RECORD clause does not stand in for a record description entry (the same sentence is §1985:VIII.3.2.3 SR3 and §1985:IX.3.2.3 SR3). The draft reads the rule correctly but marks line 11, a comment line (`*01  OUT-REC PIC X(10).`), where no compiler reports; a missing entry is on no line, and the entry it must follow is the FD (lines 9 to 10). The suite's own rule for a flagged test (docs/rearchitecture/DESIGN-conformance-suite.md section 3.2, 'The site') is that the site is 'the whole statement or entry, both places for a rule that relates two, the entry a required clause is missing from'; the standard gives a diagnostic no line. With the FD on one line and the mark on it, the draft's own program matches (refused at line 9). But the compiler refuses it by the 2023 rule (§2023:13.4.5.3 SR3 a), which lets a RECORD clause replace the record descriptions, so the corrected draft that holds the 1985 rule alone (an FD with a RECORD clause and no record description entry) is accepted: a program SR3 forbids (§1985:I.1.6: "A conforming source program is one which does not violate the explicitly stated provisions and specifications of Standard COBOL.").
- `1985-SR-VIII.3.2.3-3` - `§1985:VIII.3.2.3 SR3` (record harm: under-rejects, slice-07): §1985:VIII.3.2.3 SR3: "One or more record description entries must follow the file description entry." The rule has no exception: a RECORD clause in the file description entry does not stand in for a record description entry at 1985. The repro is the draft with LABEL RECORDS ARE STANDARD replaced by RECORD CONTAINS 10 CHARACTERS: its FD (lines 10 and 11) is followed by no record description entry, so the rule forbids it.
- `1985-SR-XI.2.3.3-2` - `§1985:XI.2.3.3 SR2` (record harm: under-rejects, slice-08): §1985:XI.2.3.3 SR2: "Since file-name-1 represents a sort or merge file, only the ASSIGN clause is permitted to follow file-name-1 in the FILE-CONTROL paragraph." The general format of §1985:XI.2.3.2 prints SELECT file-name-1 ASSIGN TO {implementor-name-1 | literal-1} and no other clause. SRT is described by an SD entry (line 9) and its file control entry (line 6) adds ORGANIZATION IS SEQUENTIAL.

**Expected (from the 1985 text).** --std 85 refuses an FD with no record description entry after it, and a SELECT for a sort-merge file with any clause after ASSIGN. The deciding words: "One or more record description entries must follow the file description entry." (§1985:VII.3.2.3 SR3).

Siblings, also exit 0 with no diagnostic, and each runs and displays OK: `FD  F1 RECORD IS VARYING IN SIZE FROM 1 TO 10 CHARACTERS.` with no record; `FD  F1 RECORD CONTAINS 10 CHARACTERS.` with OPEN OUTPUT / CLOSE. THE DRAFT'S OWN PROGRAM (FD with LABEL RECORDS only, no record): exit 65: c2draft.cob(9,8): error COBOL1836: file description entry 'OUT-FILE': it specifies no record description entries, so a RECORD clause establishing a maximum record size shall be specified (ISO §2023:13.4.5.3 SR3 a / §2023:13.18.43.3 SR1) [...] Write RECORD CONTAINS n CHARACTERS, or RECORD IS VARYING IN SIZE TO n CHARACTERS.
