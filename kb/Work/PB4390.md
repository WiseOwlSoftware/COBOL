# PB4390 - two inherited miscitations of the FILE STATUS syntax rules

**Sites:** `tests/WiseOwl.Cobol.Tests.Unit/PlaceStorageFormSwitchDriftTests.cs:74` (the `Exempt` entry `"ProgramEmitter.cs:p"`, its justification text) and `src/WiseOwl.Cobol.Compiler/CodeGen/ProgramEmitter.cs:562` (the comment in `ProgramEmitter.AnchorPlace`, near line 551).

**Read at:** commit 245092793, the tip of branch `worktree-wf_d2f43316-4ca-4` (PB4320, in the merge queue); the files are not yet on origin/main.

The exemption text says ISO 12.4.5.8.3 SR1 makes a FILE STATUS item a two-character alphanumeric elementary item, and ISO 12.4.5.8 SR1 forbids an OCCURS on it. Checked with `python scripts/spec/cite.py --check`:
- `--check 12.4.5.8.3 "two-character"` answers OK at SR2: "Data-name-1 shall reference a two-character data item of the category alphanumeric, defined in the working-storage, local-storage, or linkage section."
- `--check 12.4.5.8.3 "OCCURS"` answers OK at SR1: "Data-name-1 shall not be subject to any OCCURS clauses." 12.4.5.8 has no syntax rules of its own.

So the two-character rule is SR2 (not SR1) and the OCCURS ban is 12.4.5.8.3 SR1 (not 12.4.5.8 SR1). The `AnchorPlace` comment near line 562 repeats the SR1-for-two-character miscitation. `DataBinder.cs` near line 2622 cites SR1 correctly for the OCCURS ban and SR2 for the working-storage conjunct. The merge rewrote the exemption text (PrefixPlace to AnchorPlace) and kept the inherited citations unchecked.

Fix: correct the three citations, running `cite.py --check` on each clause written (rule 1), and sweep the tree for the same pair: `git grep -n "12.4.5.8 SR1"` and each `12.4.5.8.3 SR1` that sits beside "two-character" or "alphanumeric".

Harm: none to a user program (`process_only`); a comment misleads a reader about which rule governs.
