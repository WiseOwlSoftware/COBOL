# PB594 — OPEN — the EVALUATE range expression lost its alphabet-name

Reported by the golden-lane round-3 `misc-p1` writer while deriving `SR-14.9.13.3-1`'s golden; the round-3
refuter independently confirmed it by reading both grammar rules ("`valueRange` has no `IN alphabet-name-1`
tail, and no `evaluateWhenItem` alternative can absorb it for a LITERAL operand"). **Re-derived and re-probed by
the lander before this note was filed.**

## The rule

`specs/ISO_COBOL.md` §14.9.13.3 SR3 — checked here:

```
python scripts/spec/cite.py --check 14.9.13.3 "Alphabet-name-1 may be specified only when the literals or
    identifiers specified in the THROUGH phrase are of class alphabetic, alphanumeric, or national"
  -> OK  §14.9.13.3 3)  (Syntax rules)
```

A syntax rule that constrains *when* alphabet-name-1 may be specified presupposes that it may be specified at
all; §14.9.13.2's range-expression general format is
`{identifier-3|literal-3|arithmetic-expression-3} {THROUGH|THRU} {identifier-4|literal-4|arithmetic-expression-4}
[ IN alphabet-name-1 ]`, and the phrase selects the collating sequence the THROUGH comparison uses.

## The repro (this tree, 2026-09-05)

```cobol
       SPECIAL-NAMES.
           ALPHABET ALPHA-1 IS STANDARD-1.
       …
           EVALUATE W-X
               WHEN "A" THRU "F" IN ALPHA-1
                   DISPLAY "IN-RANGE"
               WHEN OTHER
                   DISPLAY "OUT"
           END-EVALUATE.
```
```
probeA.cob(14,34): error COBOL0001: no viable alternative at input 'IN'
probeA.cob(14,34): error COBOL0307: unexpected 'IN'. A period may be missing at the end of the previous sentence.
probeA.cob(15,20): error COBOL0001: unexpected 'DISPLAY'
probeA.cob(16,16): error COBOL0307: unexpected 'WHEN'. A period may be missing at the end of the previous sentence.
probeA.cob(18,12): error COBOL0306: unexpected 'END-EVALUATE'. …
exit 65
```

The cascade is the tell: the parser does not merely lose the phrase, it loses the rest of the EVALUATE.

## The mechanism

`src/Cobol.Net.Frontend/Grammar/Core/CobolExpressions.g4:37`

```antlr
valueRange
    : valueOperand (THRU | THROUGH) valueOperand
    ;
```

There is no optional `IN alphabet-name-1` tail, and no alternative of `evaluateWhenItem` can absorb the phrase
when the operand is a literal. The sibling `valueClauseRange` (line 42) is the VALUE-clause range and is
correctly tail-less — §13.18.63 has no alphabet phrase — so this is a one-rule fix, not a shared one.

## What the fix owes

⚙ **Do not stop at the grammar.** Adding the tail makes the source parse; SR3's *constraint* then has to be
enforced (alphabet-name-1 only when the THROUGH operands are class alphabetic, alphanumeric or national, with
SR3's national sub-case), and the binder has to make the range comparison actually USE the named alphabet's
collating sequence rather than the program collating sequence — otherwise the phrase parses and is silently
ignored, which is the worse defect. §8.8.4.2.7's relation-condition rule is the semantics to reuse — "Comparison is made with respect to the collating sequence of characters specified for the current alphanumeric program collating sequence" (`cite.py --check 8.8.4.2.7` → OK), with the national twin at §8.8.4.2.9 (`--check` → OK); the §8.8.4.1.2 this line carried until landing train 3 does not exist — §8.8.4.1 is General and has no sub-clauses;
`PROGRAM COLLATING SEQUENCE` already has a resolved-alphabet path from `DataBinder.Switches.cs`.

Sweep the sibling shape: any other general format with a trailing `[IN alphabet-name-1]` (the relation condition
and SORT/MERGE `COLLATING SEQUENCE` are the near neighbours) should be checked for the same omission before this
closes.

## Inventory

`SR-14.9.13.3-3` is the row this blocks. Round 3 closed `SR-14.9.13.3-1` (the THRU/THROUGH equivalence) on
`conformance:2023/l1_evaluate_thru_through_equivalent`, which deliberately writes no alphabet phrase; SR3's row
stays open and gets its golden with this fix.
