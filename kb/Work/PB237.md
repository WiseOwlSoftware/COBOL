# PB237

**Rows:** `SR-14.9.4.3-14`, `SR-14.9.4.3-16`, `GR-14.9.4.4-7`, `SR-14.9.5.3-3`, `GR-14.9.5.4-1`, `FMT-14.9.5.2`

no source can declare a program-prototype-name — the REPOSITORY grammar has no §12.3.8.2 PROGRAM specifier — so `CALL … AS <prototype>` is COBOLNET0899, a prototype CANCEL target is a RUN-time NotImplemented, and one unsupported CANCEL target silently discards the legal targets beside it.

Rows: SR-14.9.4.3-14, SR-14.9.4.3-16, GR-14.9.4.4-7 (CALL), SR-14.9.5.3-3, GR-14.9.5.4-1 (CANCEL). ONE absent declaration surface, five rule rows.

MECHANISM (from the rows' own READ evidence). `repositoryEntry : FUNCTION ALL INTRINSIC | FUNCTION functionName INTRINSIC? | CLASS className | INTERFACE interfaceName | PROPERTY propertyName ;` (CobolParserCore.g4:366) has no program-specifier, so no source this compiler parses can DECLARE the name every one of these rules takes as its subject. CallBinder.BindCall consequently rejects the entire non-NESTED AS arm with DiagnosticCatalog.CallAsPrototypeName (COBOLNET0899, category RecognizedNotImplemented) whose text quotes SR16 verbatim, then returns BoundNop. CallBinder.BindCancel has literal and dataReference arms only, so a prototype name arrives as a dataReference, fails ctx.Refs.Resolve, and becomes `BoundUnsupported($"CANCEL target '{dref.GetText()}'")` → StatementEmitter.cs:211 `Visit(BoundUnsupported n) { _ctx.Writer.Line(LoudStmt(n.Feature)); return false; }` → EmitCore.cs:93 LoudStmt → `NotImplemented.Run(...)`: a RUN-time failure naming nothing about prototypes, with no diagnostic channel touched.

PER-ROW RESIDUE.
- SR-14.9.4.3-16 (cite.py OK, §14.9.4.3 16, FORMAT 2): the obligation is to RESOLVE program-prototype-name-1 against the REPOSITORY and reject a name that is not there. No code does that because no name can be there. conformance:negative/pb46-call-as-prototype-name pins the loud NON-SUPPORT, not the rule — a green test holding a gap open.
- SR-14.9.4.3-14 (cite.py OK, rule 14): needs BOTH operands and neither exists — a restricted program-pointer (`USAGE PROGRAM-POINTER TO program-prototype-name-1`, §13.18.60 GR25) is refused at declaration (tests/conformance/negative/program-pointer-restricted), and the prototype name is unparseable. BindCall's only program-pointer logic is `if (place.Item.Pic?.Category is PicCategory.ProgramPointer) isPointerTarget = true;` — no signature model anywhere on the CALL path.
- GR-14.9.4.4-7 (FORMAT 2): with AS present and NESTED absent the prototype determines the called program's characteristics — its externalized name (§12.3.8), its SR14/SR25 signature, and the BY REFERENCE/BY VALUE mode of each formal that GR9 then consults. The arm binds no prototype at all.
- SR-14.9.5.3-3: CANCEL must validate that program-prototype-name-1 names a REPOSITORY prototype; BindCancel has no third arm and no registry lookup, so there is no subject to validate and no diagnostic to fire.
- GR-14.9.5.4-1: two of the rule's three identification forms ARE matched — identifier-1's CONTENT read at execution (a BoundFieldOperand rendered `({OperandText.AsString(dynamic, num)}).Trim()`), and literal-1 decoded through CobolLiteral.Decode with ConcatFolder.Fold for §8.8.3.3 GR3 — and §8.3.2.2 2)a)'s implementor-defined word mapping IS realized by ProgramTable.NameEquals (OrdinalIgnoreCase) plus the emit-site Trim (a COBOL word cannot contain a space, so the Trim is a word-mapping step, not a value change). Only program-prototype-name-1 is absent.

SECOND, INDEPENDENT DEFECT ON THE SAME PATH, carried here because it is the same statement and the same line: CallBinder.cs:242's `return new BoundUnsupported(...)` sits INSIDE the per-target loop, so ONE unsupported target discards the whole statement including targets already accumulated in `targets` — `CANCEL "A" <prototype-name>` loses the perfectly legal "A" cancel, silently at compile time and loudly only at run time. That is the `silent` flag; fix the loop even if the registry lands later.

WHAT WOULD CLOSE IT: the P13 program-prototype registry — the §12.3.8.2 PROGRAM specifier in repositoryEntry, a prototype signature model, CALL … AS <prototype-name> binding with §14.8.2/§14.8.3 conformance, an SR14 signature comparison for restricted program-pointers, a BindCancel arm resolving against the registry with its own diagnostic — plus a positive golden per row and negatives for a name not in the REPOSITORY and for a signature mismatch. Ground rule 6 keeps every one of these rows NOT-IMPLEMENTED rather than DOCUMENTED-NON-SUPPORT: program prototypes are mandatory 2002+ surface, not an Annex A.4 optional module, so no docs/CONFORMANCE.md §4 licence covers them.

SPEC REFS as carried by the rows: §14.9.4.3 SR14/SR16 (both cite.py OK); §14.9.4.4 GR7; §12.3.8.2 program-specifier; §13.18.60 GR25; §14.9.5.3 SR3; §14.9.5.4 GR1 with §8.3.2.2 (spec lines 4756-4764, the 1)/2)a)/2)b) split); §7.3.4 GR2 (CALL-CONVENTION, which is unimplemented, so 2)a) is the arm that applies).

## FMT-14.9.5.2, attached here by the registration wave

CANCEL's general format has three brace alternatives and the third is `program-prototype-name-1`, which has NO production: a bare prototype word falls into `dataReference`, `ctx.Refs.Resolve` fails, and `CallBinder.BindCancel` returns `BoundUnsupported`, emitted as `NotImplemented.Run(...)` — a RUN-time failure, not a compile diagnostic. That is one mechanism with this note's: no source can declare a program-prototype-name because the REPOSITORY grammar has no §12.3.8.2 PROGRAM specifier, so every prototype-shaped operand in every statement lands on the same staged-loud path. The row's second, SEPARABLE residue stays attached to it: `cancelTarget+` with two or more operands has no golden (`recursive_ws.cob` carries a single target), and the comma-separator half was probed and REFUTED — `CANCEL "A", "B".` parses, because `COMMA_SEP` skips a comma-space before the parser sees it.

## Mechanism

src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4#repositoryEntry (:366) + src/Cobol.Net.Compiler/Binding/Procedure/Verbs/CallBinder.cs#BindCall's non-NESTED AS arm (DiagnosticCatalog.CallAsPrototypeName, COBOLNET0899, RecognizedNotImplemented, then `return new BoundNop()`) and #BindCancel (:239-264, two arms only, with the per-target `return new BoundUnsupported(...)` at :242 inside the `foreach (var t in cancel.cancelTarget())`)
