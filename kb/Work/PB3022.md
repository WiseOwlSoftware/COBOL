# PB3022 — the gate has one shape: the ordered leg 1; CI is the whole-population run

**Owner decision 2026-10-11 ~11:30 PDT (kb/Work PB3015 Q1a, "Yes (Recommended)"):** the lander's local gate becomes the
targeted leg (its clusters' own tests, the likely reds, the Windows file-system race witnesses that reproduce only on
this box's ReFS drive); the local whole-population run and the WSL copy of CI's Linux legs are removed; CI stays the
whole-population regression net. Principle (owner ~11:20): local testing confirms the targeted change first; CI/CD
ensures no regression on the remaining codebase.

**Design:** `docs/rearchitecture/DESIGN-test-build-ci.md` §3.17.3 (and DESIGN §3.17.1 for the measurements).
**NEEDS-OPUS:** the gate driver is the one tool every agent's verdict depends on; its reshaping (one mode, two hosts, two
new tiers, the audits' reuse) needs judgment, not a mechanical edit.

## What changes (implement the whole of it; rule 3)
1. `scripts/build-local.ps1` / `build-local.sh` lose `-Mode` (one shape: a plan, leg 1, fail-fast, a gate slot);
   `scripts/run_gate_legs.py` loses its lander arm; `gate_slot.py`'s implementer scope `leg1` is the one scope and
   `whole` stays the owner's on-demand switch and the battery's form. Every caller (`units/*.md`, briefs, skills, the
   `gate` skill, MANDATORY-PRACTICES L2, plan §0 "Gates", CLAUDE.md Testing) says so in the same change.
2. `scripts/gate_plan.py`: `TIER_ORDER = ("0a", "0h", "0u", "1", "2", "3")`; a case is tier 0h when its class carries
   the xUnit trait `Host` with a value CI's runners lack (`ReFS` today; the set of such values is ONE table in the
   planner, documented). Tier 0h is leg 1 at every gate whatever the diff and exempt from the collection cap.
3. The file-system race witnesses (`SidecarColumnLockHostDriftTests`, `RegionLocksDriftTests`, the siblings
   `drift_rules.py` lists for `FileSupport.cs` / `SidecarLockFiles`) carry `[Trait("Host", "ReFS")]`; a drift test
   asserts every class in that set carries it (membership derived, never listed).
4. PB2914's reuse rule (a self-test with inputs unchanged since a recorded PASS is reused) applies to every audit at
   every gate: script self-tests, drift-rules regeneration, citation checks. CI's `audits` job runs them all.
5. The six drift-test files with seven fixed time limits (grep `FromSeconds(` in `tests/Cobol.Net.Tests.Unit/*DriftTests.cs`;
   `GateSlotDriftTests`' 120 s is the top recurring load red) are rewritten to deterministic witnesses, or to a limit
   scaled from a measured baseline on the same host where a process must be timed; a drift test refuses a new literal
   time limit in a test (owner rule 2026-09-25, no wall-clock tests).
6. Measured before/after: the gate's wall under fleet load (PB3015's evidence: 1,054 of 1,187 s were audits; the
   operator's train 1059, 2026-10-11 12:31: ~63 min, 4 whole-population runs ≈ 34 min of which 3 only re-verified
   seconds-long bookkeeping fixes, audits 460–534 s per run with no reuse, 15–20 min in push-main under the lease).
7. **Tier 0c — cheap tree-wide checks** (operator proposal 2, 2026-10-11 12:31): every discovered case whose class
   carries the `Sweep` trait (a drift test over the whole tree: the drift-rules index, inventory test-refs, the witness
   audit, citation sweeps) AND whose recorded time is under the planner's cheap threshold is in leg 1 at every gate, so
   an implementer catches the bookkeeping red the lander used to find — membership derived from the trait and the
   timings, never listed; a drift test asserts every `*DriftTests` class that reads the tree carries the trait.
   `TIER_ORDER = ("0a", "0h", "0c", "0u", "1", "2", "3")`.
8. **A re-gate after a fix runs leg 1, never the population** (operator proposal 3): with one mode, the previous reds
   are tier 0a and the fix's reach is tier 1, so verifying a bookkeeping fix costs seconds, not a 7–34 min population
   run; the whole population runs once, in CI's merge-group run. The brief text and the gate skill say so in words.
9. **Applied to the land units before this note lands (operator proposal 1, Mythos GO 2026-10-11 12:34, CHANGED 12:37
   on the owner's point):** the loop's lander runs `build-local.ps1 -Mode implementer` (leg 1) on the train head on
   Windows AND keeps today's whole-leg WSL gate (`linux-gate.sh`) until item 10 ships the Linux leg-1 run; `push-main.sh`
   still waits for `ci-gate`, which runs the whole population on both OSes before main moves, so no code changes. The
   one exposure until tier 0h exists: a Windows file-system race witness (ReFS-only) runs only when the diff reaches it
   or it was red before; a train whose clusters touch `FileSupport.cs` / `SidecarLockFiles` must run those classes by
   name in that train's steer (an operational steer, not code). Measured per landing by `landing_measure.py`.
10. **The targeted leg runs on BOTH hosts** (owner 2026-10-11 ~12:45, "Yes, both hosts, leg 1", after asking whether
   dropping the WSL gate pushes every Linux-only failure to CI): the one gate runs leg 1 natively on Windows and then,
   under the same gate slot, leg 1 of the SAME plan in a WSL clone of the committed head — `linux-gate.sh --plan <plan>`
   runs `build-local.sh --mode implementer` in the clone instead of CI's whole legs — in the implementer's gate and at
   enqueue alike; Windows first (fail-fast, no clone), Linux second; a Linux-only red names its host in the verdict
   line. Why (PB3015's evidence): 3 of 38 clusters on 2026-10-10 had Linux-only reds, all in their own tests (the 52F
   locale golden's Linux text, the 52B lock-race fix red 10 of 10 on Linux, 1055 D's host-path length test); the WSL run
   caught each before a CI round trip. Cost: the clone and build (~1–2 min) plus the leg, not the 5–10 min of CI's whole
   Linux legs. `linux-gate.sh`'s whole-leg form stays as the repro tool for a Linux CI red.
