# PB4265 — the backend-abstraction design contradicts the one name allocator

**Found:** Mythos session 2026-10-31, answering the owner's question about what keeping the Roslyn backend replaceable
by a direct-IL backend requires (the owner then removed any C/C++ backend requirement, the same day). The owner made
this seam work a priority ("elevate the priority to eliminate the seam leaks asap"); see PB2293.

**The contradiction.**
- `docs/rearchitecture/DESIGN-backend-abstraction.md` §1.2 ("Pre-mangled C# identifiers — no C# field/method names
  baked into a node"), leak row L4 (§1.3), §2.4 (a shared `NameMangler` "resolved from a symbol at render time") and
  §4's `Model/NameMangler.cs` row all say a target identifier is decided when rendering.
- `docs/rearchitecture/DESIGN-external-repository.md` (owner-approved 2026-10-05, the later decision) made ONE function,
  `CsNames.Allocate(baseName, scope)` (`src/WiseOwl.Cobol.Compiler/Binding/Model/CsNames.cs`), allocate every emitted
  name at bind time, with seeded scopes, so that "two compiles give the same names": the names are an ABI that other
  compilation units and assemblies bind to (PB2098, PB2093 landed).
- The code follows the later design: `DataItem.CsName` (`Binding/Model/DataItem.cs:81`), `BoundMethod.CsName`
  (`Binding/Bound/BoundTree.cs:64`), `BoundReportVaryingRef.CsName` (`BoundTree.cs:263`), `ModuleNamespace.CsName`
  (`Binding/Model/CsNames.cs:123`), `OoClassUnit.CsName` (`Binding/Model/OoClassUnit.cs:18`),
  `RedefinesModel.BackingCsName`/`BackingCellCsName` (`Binding/Model/RedefinesModel.cs:234,243`),
  `CallExternalBacking.BackingCsName`/`CellCsName` (`Binding/DataBinder.Linkage.cs:72`), the OO invoke's `ClassCsName`
  (`Binding/DataBinder.Oo.cs:658`), and `PositionLocal`/`LocalVector.CsName` (`Binding/Model/Position.cs:157,163`).

**Why it matters for the CIL backend.** Both backends target the CLR, and a CIL-emitted module must expose the SAME
type, field and method names as a Roslyn-emitted one, or a program compiled by one backend cannot call or inherit from
one compiled by the other (the external repository's cross-assembly OO, PB2104). So an allocated CLR name on a model
node is backend-neutral for this project, and a render-time `NameMangler` per backend would be the defect. What the
neutrality contract must still refuse is a C# FRAGMENT: an access path, a statement, a runtime call spelled as text.
The §6 contract test (PB4266) cannot be written against a §1.2 that the code rightly disobeys.

**Fix direction.** (1) Correct DESIGN-backend-abstraction §1.2, L4, §2.4, §4 and §6 assertion 2 to name `CsNames.Allocate`
as the one allocator of CLR identifiers, shared by both backends, and keep §1.2's refusal of C# fragments, runtime type
names as text and target literal formats. (2) Decide, one name at a time, which of the fields above are CLR names (an
ABI: keep, renamed so the name says CLR, e.g. `ClrName`, with every caller changed in the same change, CLAUDE.md rule 4)
and which are C#-only local names a CIL backend would not use (`PositionLocal`, `LocalVector`: method locals, which
CIL addresses by slot) — those belong to the Roslyn backend, not the model. (3) Check whether `CsNames` refuses C#
keywords or other C#-only spellings in a CLR name; that is harmless for CIL, but the design should say so.

## Landed (wave 20261790 B)

**Re-probe (the defect the design gap hid).** The model held the C# SPELLING of a name, not a CLR name:
`DataItem.Sanitize` appended `@` to a C# keyword, so a lowercase data-name `int` was `@int`, and every name DERIVED
from it was invalid C#. `01 int PIC X(4). 01 double REDEFINES int PIC 9(4).` drew CS1002/CS1519 on `_redef_@int`;
a GLOBAL redefinition read by a contained program failed the same way (its bridge names the backing). Siblings by the
same mechanism: `_scell_` (`BackingCellClrName`), `__cap_` (`NamingConvention.CapacityRegisterName`), `__sum_`
(`SumCounterName`), `__fk_` (`InstanceFileKeyName`), `_impliedRecord`, `<word>_Record` (`HostEntryEmitter`); and
`NamingConvention.AddressCarrierName` already stripped the `@` by hand (`TrimStart('@')`, deleted). So the note's
item (3) was not harmless: it rejected legal source.

**Fix.** (1) DESIGN-backend-abstraction §1.1, §1.2, L4, §2.4 (amended), §3.4, §4, §5 and §6 assertion 2 now name
`CsNames.Allocate` as the ONE bind-time allocator of the CLR names both backends emit; DESIGN-external-repository §4.5
says the same. (2) The CLR names are renamed `ClrName`: `DataItem`, `OoClassSymbol`, `OoInterfaceSymbol`,
`OoMethodSymbol`, `BoundMethod`; `FactoryClrName`, `BackingClrName`, `BackingCellClrName`,
`CallExternalBacking.BackingClrName`/`CellClrName`, `BoundInvoke.ClassClrName`/`MethodClrName`/`OwnerClrName`,
`OoPendingPropertyOp.ClassClrName`/`InterfaceClrName`/`OwnerClrNameOf`, `OoStandardClasses.NewClrName` /
`FactoryObjectClrName` / `BaseFactoryClrName`. `OoClassUnit.CsName`, a forwarder, is deleted. `ModuleNamespace` keeps
only `ClrName`; `ProgramEmitter.CSharpNamespace` writes its C# spelling. The C# locals keep `CsName` (they are the
Roslyn backend's names, §1.3 L8). (3) `Sanitize` returns the CLR base with no `@`, and every `CsNameScope` kind is
seeded with `CsNames.CSharpReservedKeywords` (derived from Roslyn), so `int` is allocated `int_2`, the same text in
metadata and in C#.

**Residue (new leaks, recorded as §1.3 L7 and L8, for the registrar).** L7: C# access text built from names in the
binder — a carrier-resident formal's `DataItem.ClrName` rewritten to `__lnk{Uid}.Value`, `AccessPath.Reroot`'s
`__outer.` text, `DataBinder.GlobalBridgesOf`'s `anchor + member` paths, `SortBinder.SortMemberPath`'s dotted text.
L8: C# method locals on model nodes — `PositionLocal.CsName`, `LocalVector.CsName`, `BoundReportVaryingRef.CsName`.
