# PB716 — OPEN — a bare word is a complete SPECIAL-NAMES entry, and it eats the next clause's tail

Found 2026-09-05 while filing [[PB715]] — the discriminator probe for that note (`CLASS DIGITS IS "0" ZOTZOT.`
compiling clean) proved the trailing word was being SWALLOWED rather than spelled. PB715 records the pointer;
this note is the defect. Measured on the solution built at `c34f01ad`.

## The facts

**What the standard prints.** Rendered off the canonical PDF, not read from the transcription
(`clause_page.py 12.3.7.2` → PDF page 320, printed folio 290; `render-spec-page.py 320`;
`cite.py --check 12.3.7.2 "FOR"` → `OK §12.3.7.2 (General format)`). The implementor-name entry has exactly
three printed alternatives, and **not one of them is a bare word**:

```
switch-name-1  { IS mnemonic-name-1 [ | ON STATUS IS condition-name-1 | OFF STATUS IS condition-name-2 | ]
               | { | ON STATUS IS condition-name-1 | OFF STATUS IS condition-name-2 | } }
feature-name-1 IS mnemonic-name-2
device-name-1  IS mnemonic-name-3
```

The switch-name arm's continuation is in **braces** — required, one of the two forms; the feature-name and
device-name arms require `IS mnemonic-name`. §12.3.7.3 8) (`--check 12.3.7.3 "device-name-1"` → OK) confirms the
three names are the entry's subjects: *"The implementor shall specify the names that are available for
switch-name-1, feature-name-1, and device-name-1."* A word standing alone spells no entry in this paragraph.

The same rendered page settles the CLASS row: `CLASS class-name-1 [ FOR { ALPHANUMERIC | NATIONAL } ] IS
{ literal-5 [ {THROUGH|THRU} literal-6 ] }… [ IN alphabet-name-4 ]`, with **`CLASS` underlined, `FOR` NOT
underlined, and `ALPHANUMERIC` / `NATIONAL` underlined**. By §8.3.2.4.3 (`--check` → OK: an un-underlined word
*"may be specified at the user's option with no effect on the semantics of the format"*) `CLASS X IS "0"
NATIONAL` is **conforming source**, and NATIONAL is a required word carrying the phrase's meaning — §12.3.7.4 12)
(`--check 12.3.7.4 "class-name-1"` → `OK §12.3.7.4 12)`) defines the class over *"the relevant native character
set"*, and §12.3.7.4 6) (`--check 12.3.7.4 "NATIONAL"` → OK) names the two native sets the FOR phrase chooses
between. §8.8.4.4.3 3) (`--check` → OK) then lets a class condition apply `class-name-1` to a display **or**
national item, so which set the class was built over is load-bearing.

**What the grammar spells.** `src/Cobol.Net.Frontend/Grammar/Core/CobolSpecialNames.g4:76-78`:

```
implementorSwitchEntry : cobolWord (IS cobolWord)? switchOnClause? switchOffClause? ;
```

Every element after the first `cobolWord` is optional, so the rule's minimum spelling is **one word**. It is
reached from `specialNameEntry`'s `| implementorSwitchEntry DOT?` alternative (`:43`), inside
`specialNamesParagraph : SPECIAL_NAMES DOT specialNameEntry*` (`:14-16`) — an unbounded loop of entries. Any word
left over after a clause ends therefore starts a new, complete, meaningless entry. `cobolWord` admits `NATIONAL`
unconditionally (`Core/CobolWords.g4:74`).

**Measured — which rule ate it, not a guess.** Probes in
`E:\Temp\claude\E--CobolSharp\49b17747-ce58-4386-8c49-ecb2ce644f8d\scratchpad\pb716*.cob`, `--std 2023`:

| probe | SPECIAL-NAMES entry | result |
|---|---|---|
| **e** | `CLASS DIGITS IS "0" NATIONAL IS MYMNEM.` + `DISPLAY "Z" UPON MYMNEM` | `COBOLNET0817: DISPLAY UPON 'MYMNEM': **device 'NATIONAL'** is not capable of receiving data (ISO 14.9.11.3 SR2 …)` |
| **g** | `CLASS DIGITS IS "0" ZOTZOT IS MYMNEM.` + same | same diagnostic, **device 'ZOTZOT'** |
| **f** | `CONSOLE IS MYMNEM.` + same (control) | prints `Z` |
| **b/c** | `CLASS DIGITS IS "0" NATIONAL.` / `… ZOTZOT.` | compile and run clean, no diagnostic |

The binder naming `NATIONAL` as a **device** is positive identification: the trailing word entered
`implementorSwitchEntry` as its `cobolWord`, not `classDefinitionClause`. The word is therefore **not applied to
the class** — it is bound as a separate SPECIAL-NAMES entry, silently when no `IS mnemonic` follows it.

`genericClause` (`Core/CobolExpressions.g4:15`, `IDENTIFIER (IDENTIFIER | literal)*`) is a second catch-all in the
same loop (`:44`), but it is not the sink here: `NATIONAL` is a keyword token, not `IDENTIFIER`, so only
`implementorSwitchEntry` can take it; for `ZOTZOT` (an `IDENTIFIER`, matched by both) ANTLR takes the first
matching alternative, which is `implementorSwitchEntry` at `:43`. Both need fixing; one is doing the damage.

**Edition-invariant.** `CLASS DIGITS IS "0" NATIONAL.` is accepted with no diagnostic at `--std 85`, `2002`,
`2014` and `2023`. No gate is involved and none would help.

**One thing measured that keeps this honest.** The dropped attribute is not yet observable in output: the emitted
C# for `FOR NATIONAL`, `FOR ALPHANUMERIC`, bare `NATIONAL` and `ZOTZOT` is **byte-identical**
(`diff` over the four `.g.cs` files the compiler writes beside the assembly), because the FOR arm is not carried
into codegen at all — a second, separate gap in the CLASS clause, named here and not filed. So today the harm is
a silent mis-bind that a user cannot see; the moment the FOR arm is implemented it becomes a wrong answer with no
warning, and the relaxation PB695 is landing (making `FOR` omittable) walks conforming programs straight into it.

## Why it matters

Two harms from one rule. **Illegal source is accepted:** any stray word in SPECIAL-NAMES — a typo, a
mis-transcribed clause name, a keyword from a clause the grammar does not yet spell — becomes a valid entry and
the paragraph reports nothing, at every edition. **Legal source is silently mis-bound:** `CLASS X IS "0"
NATIONAL` is conforming, and its NATIONAL becomes an implementor device-name. That combination is the worst shape
a sink can have — it converts every future under-spelled SPECIAL-NAMES clause from a loud parse error into a
silent acceptance, which is exactly how the six optional words in [[PB715]] stayed invisible to a green audit.
`feedback_green_test_can_hold_a_gap_open`: a paragraph that never rejects anything reads as a paragraph that is
finished.

## The fix shape

Spell the three printed alternatives and delete the bare-word one:

```
implementorSwitchEntry
    : cobolWord ( IS cobolWord (switchOnClause | switchOffClause)*
                | (switchOnClause | switchOffClause)+ )
    ;
```

— a continuation is REQUIRED (folio 290's braces), which alone makes `ZOTZOT.` a syntax error and stops the
CLASS clause's tail from being eaten. Then, following rule 5 rather than the smallest diff: `specialNameEntry`
should have **no catch-all at all**. `genericClause` at `:44` is a second bare-word sink over `IDENTIFIER`, and a
paragraph whose last alternative matches anything can never report an unspellable clause. Removing it will
surface whatever it has been absorbing — that surfacing is the point, and it is the mechanical way to find the
rest of PB715's population. Ship with negatives that pin the rejection (`CLASS X IS "0" ZOTZOT.`, a bare word
alone, a word after each of the paragraph's clauses) and a positive golden for `CLASS X IS "0" NATIONAL` binding
the NATIONAL attribute once PB695's `FOR` relaxation lands — the two changes must land together or the relaxation
is defeated by this sink.
