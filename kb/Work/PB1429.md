## Finding — `inline-method-invocation` (crashes; rows `SR-8.4.3.4.3-2`)

**Mechanism.** §8.4.3.4.3 SR2 screen runs only on the first segment's written receiver; a universal temp as the identifier-1 of a chained segment falls into the universal dynamic path and ends in an unreported refusal (internal error)

**Repro.** class PRBC method UNIV: LINKAGE 01 LK-U USAGE OBJECT REFERENCE. PROCEDURE DIVISION RETURNING LK-U. SET LK-U TO SELF. Program: MOVE A1 :: "UNIV" :: "GETNAME" TO W. (A1 USAGE OBJECT REFERENCE PRBC) -> probe p3_chainuniv.cob

**Expected from the spec.** §8.4.3.1.3 defines identifier recursively, so `A1 :: "UNIV"` is identifier-1 of the second invocation; §8.4.3.4.3 SR2: 'neither the predefined object reference NULL nor a universal object reference shall be specified' -> COBOLNET2138 naming SR2.

**Observed / reasoning.** error COBOLNET2362: inline method invocation of "GETNAME" was refused without a diagnostic naming the rule it breaks; this is a COBOL.NET internal error. The segment loop calls OoBindInstanceInvoke(site, prev, ...) which dispatches a universal receiver to OoBindUniversalInvoke; that never sets site.ImplicitReturningPlace and reports nothing. Fix: apply the SR2 universal screen to EVERY segment's receiver (the chained Place's description), one check for both arms.
