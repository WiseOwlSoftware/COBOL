# PB1033 — OPEN

## Measured
```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. W56IFN.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 A PIC 9 VALUE 1.
       01 B PIC 9 VALUE 2.
       01 G PIC 9(10) VALUE 4294967297.
       PROCEDURE DIVISION.
           IF A NOT >= B DISPLAY "LT" END-IF
           GO TO P1 P2 DEPENDING ON G
           DISPLAY "FELL-THROUGH"
           STOP RUN.
       P1.
           DISPLAY "WENT-P1"
           STOP RUN.
       P2.
           DISPLAY "WENT-P2"
           STOP RUN.
```

prints `LT` then **`WENT-P1`** (the `NOT >=` half is PB1034). And
```cobol
       >>TURN EC-BOUND-REF-MOD CHECKING ON
       IDENTIFICATION DIVISION.
       PROGRAM-ID. B01RM.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 X PIC X(5) VALUE "ABCDE".
       01 S PIC 9(10) VALUE 4294967297.
       PROCEDURE DIVISION.
           DISPLAY "RM=[" X(S:1) "]"
           STOP RUN.
```

prints **`RM=[A]`** — no EC-BOUND-REF-MOD, although checking is on and position 4294967297 is outside `X`.

## The rules
- `cite.py --check 14.9.17.4 "control is transferred to procedure-name-1, etc., depending on the value of identifier-1 being 1, 2"` → `OK §14.9.17.4 2)`. A value that is not 1…n transfers nowhere.
- `cite.py --check 8.4.3.3.4 "EC-BOUND-REF-MOD"` → `OK §8.4.3.3.4 5) c)`: an out-of-range leftmost position or length raises the condition.

## The mechanism
The one integer landing (`NumericRenderer.Align(num.AsNum(…), 0)`, PB86) yields a wide value, and every consumer then
casts it with `(int)(…)`:
- `CodeGen/Verbs/ControlFlowEmitter.cs:42` — `int __dep = (int)(…)` for the GO TO DEPENDING selector.
- `CodeGen/Roslyn/RuntimeApi.cs` `RefModStart` / `RefModLength` — `(int)(start)`, `(int)(length)`.
- `CodeGen/Verbs/SequentialIoEmitter.cs` `LinesExpr` (WRITE ADVANCING count, ~:824/:828), `RetryTimes` / `RetrySeconds`
  (~:386/:391), `LinageOpExpr` (~:303).
- `CodeGen/Verbs/AcceptDisplayEmitter.cs:95` — the ref-modified ACCEPT width.

## What the fixer owes
One range-checked narrowing helper in the runtime (`CobolInt.ToIndex(long/Int128)` or equivalent) that maps an
out-of-range value to the rule's out-of-range outcome (fall through; EC-BOUND-REF-MOD; the ADVANCING/RETRY/LINAGE
rule's own answer) instead of a wrapped `int`, and a semgrep or drift rule that bans a bare `$"(int)({…})"` around a
rendered numeric operand in `CodeGen/`. Sweep every `(int)(` in `CodeGen/` (the grep above found 20+). Row
GR-14.9.17.4-2 is CONFORMS on main and this contradicts it: re-verdict with the golden.
