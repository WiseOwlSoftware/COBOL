# PB5457 - the wave unit's {TASKS_DIR} names a directory the harness no longer writes

**Site.** `scripts/orchestrator/orchestrate.ps1#Build-Prompt` (line 407): `$tasksDir = Join-Path $env:TEMP "claude/E--COBOL/$sessionId/tasks"`,
substituted into `scripts/orchestrator/units/wave.md` step 4 (`{TASKS_DIR}/<workflow task id>.output`).
`scripts/orchestrator/test_orchestrate_prompt.ps1` (whole: a top-level script with no members; its line-23 check) pins the same guessed shape, so the self-test cannot fail on it.

**Evidence.** Wave unit 20262009's prompt named `E:/Temp/claude/E--COBOL/1f469668-647f-4c46-aee2-82b4d3da833a/tasks/`; that
directory does not exist (`ls`: No such file or directory). The harness wrote the Workflow's output (`wli3pt0jn.output`) and
every background Bash output to `E:/Temp/claude/a398860f1e7c5585/1f469668-647f-4c46-aee2-82b4d3da833a/tasks/`. The project
segment is now a hash, not the `E--COBOL` slug.

**Failure scenario.** A unit that follows step 4 literally runs `grep -q totalToolCalls <missing file>` until `timeout 580`
exits 124, every time, so it never sees the Workflow return. It either loops until the supervisor's 60-minute STOP-UNIT, or
relies on the task notification step 4 says not to rely on. Nothing fails loudly: a missing file reads as "still running".

**Direction.** The supervisor cannot guess the harness's private directory. Either resolve it from the harness (the
background-task notification names `output-file`), or have the unit derive it from the path the Bash tool prints for its
first background task, and make the wait loop refuse a directory that does not exist instead of polling it.
