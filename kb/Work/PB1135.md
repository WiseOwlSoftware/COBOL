## Measured (adjudicator / refuter evidence, verbatim)
### [invoke-statement-p1] invokeArgument's BY-less arms omit arithmetic-expression-1 and boolean-expression-1 (the two-arm sibling of PB130's CALL fix, which gave callArgument bare arithmeticExpression + boolExprAhead booleanExpression): a bare expression argument mis-parses into extra arguments or dies on a reserved word
- **Rows:** FMT-14.9.23.2 — harm `rejects-legal-source`
- **Repro:** Class CPRB instance method TAKEN (LINKAGE 01 P PIC S9(4). PROCEDURE DIVISION USING P. DISPLAY P). Caller: 01 N PIC S9(4) VALUE 5. INVOKE CPRB "NEW" RETURNING O. INVOKE O "TAKEN" USING N + 1. (also: USING BY CONTENT N N + 1 against a 2-formal method; USING B1 B-AND B2 against a PIC 1(4) BIT formal). Pinned cobol.exe --std 2023: COBOLNET0828 '2 USING argument(s) for 1 formal parameter(s)' / '3 ... for 2' / COBOLNET0901 'B-AND is a reserved word'. Files: scratchpad adj-d1/out/probe/fmt-invoke/bareexpr.cob, bareexpr2.cob, barebool.cob.
- **Expected (spec):** §14.9.23.2 prints [BY CONTENT] and [BY VALUE] as optional brackets over {arithmetic-expression-1 | boolean-expression-1 | identifier-5 | literal-2}, so a BY-less expression is a legal argument; §14.9.23.3 SR14 implies BY REFERENCE only for an argument valid for pass-by-reference, and §14.9.23.4 GR4 distinguishes a sole identifier/literal from an arithmetic or boolean expression, presupposing bare expressions. Expected: compiles; one argument per expression; the method displays 6 (N + 1), and the second probe P=5 Q=6.
- **Observed:** CobolOO.g4 invokeArgument bare arms = OMITTED | addressIdentifier | dataReference | literal. `N + 1` parses as dataReference N then a second argument `+ 1`, so the binder reports an arity error about a rule the program does not break; B-AND falls to the dataReference arm and hits the reserved-word check. CALL's callArgument (CobolParserCore.g4:1338-1348) carries `{boolExprAhead()}? booleanExpression` and `arithmeticExpression` as bare arms; the INVOKE copy was never brought along.
- **Code site:** src/Cobol.Net.Frontend/Grammar/Core/CobolOO.g4#invokeArgument (bare arms after `| OMITTED`); binder side src/Cobol.Net.Compiler/Binding/Procedure/Verbs/OoBinder.cs#OoBindInvokeArg must then classify a BY-less expression per SR14 (content, not reference)

### [invoke-statement-p3] F1 — invokeArgument has no keyword-less expression arm: an INVOKE argument written without BY CONTENT/BY VALUE that is an arithmetic or boolean expression is split into several arguments or is a parse error
- **Rows:** GR-14.9.23.4-6, GR-14.9.23.4-L2.2 — harm `wrong-answer`
- **Repro:** E:\Temp\claude\E--CobolSharp\a700c052-f9e4-4942-84ff-a13c7505d6ec\scratchpad\adj-d1\out\probe\invoke-p3\p3.cob: WS `01 N PIC S9(4) VALUE 41`; method TAKE `PROCEDURE DIVISION USING LK LK2` (both PIC S9(4)); `INVOKE OBJ \"TAKE\" USING N + 1.` Also p1.cob (one formal), e1.cob `USING N * 2`, e2.cob `USING (N + 1)`, b1.cob `USING B1 B-AND B2`.
- **Expected (spec):** §14.9.23.2 (rendered PDF p681): `[ BY CONTENT ] {arithmetic-expression-1 | boolean-expression-1 | identifier-5 | literal-2}` — BY CONTENT is optional, so `N + 1` is ONE argument; §14.9.23.3 SR14 and §14.9.23.4 GR6 a)2 then assume BY CONTENT (an expression does not meet SR9). p3 must be refused for arity (one argument for two non-OPTIONAL formals, §14.8.2.1); with one formal (p1) the method must display LK=0042; e1/e2/b1 must compile and pass 82 / 42 / the B-AND value.
- **Observed:** p3 compiles and runs: LK=004A LK2=000A — N and the literal +1 crossed as two arguments (silent wrong answer). p1: false COBOLNET0828 '2 USING argument(s) for 1 formal'. e1: COBOL0307 unexpected '*'. e2: COBOL0001 unexpected '('. b1: COBOLNET0901 'B-AND is a reserved word'. PB46 fixed exactly this split only for the explicit `BY CONTENT N + 1` spelling (its golden's header describes the same misparse); the keyword-less arms were left `addressIdentifier | dataReference | literal`. The CallBinder/`argument` rule (inline invocation) already takes a keyword-less arithmeticExpression.
- **Code site:** src/Cobol.Net.Frontend/Grammar/Core/CobolOO.g4#invokeArgument (keyword-less arms); src/Cobol.Net.Compiler/Binding/Procedure/Verbs/OoBinder.cs#OoBindInvocationArg (impliedContent is reached only by the inline form)
