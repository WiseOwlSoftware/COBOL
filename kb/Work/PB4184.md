# PB4184 — enqueue.py land decides NOTHING TO LAND by ancestry alone

**Sites:** `scripts/orchestrator/enqueue.py` (`land`, the NOTHING TO LAND tests at lines ~1105-1113; and `self_test` for the witness case); `scripts/prune_worktrees.py` (`classify`, which returns the content class; `LANDED_CONTENT`; `carried`; the member to share, not copy).

**The mechanism.** `enqueue.py land` answers "is there nothing to land" by ancestry only: the branch IS origin/main, or its tip is an ancestor of origin/main (the second test added by kb/Work PB3157). A branch whose work a CARRIER landed (a successor merged its head and the successor's pull request merged first) is not an ancestor once an earlier `enqueue.py land` attempt has merged main into it. A re-run falls through: it merges main in again, reads main's copy of the branch's own changes as a "true textual merge in a shared file" (PB3612's re-gate rule), runs a full gate in the shared gate slot, and ends exit 6 NO ENTRY (the carrier already stamped the branch's DEVLOG entry). `land_lane` reads exit 6 as STOPPED for an enqueue-unit finisher. Meanwhile `prune_worktrees.py` (module doc, the CONTENT class: LANDED = "not an ancestor, but MERGING it into origin/main would change nothing", `git merge-tree --write-tree` through the merge drivers) already reads the same branch LANDED. One question, two answers.

**Witness (measured 2026-10-31).** Branch `worktree-wf_4b00724e-f7f-29` (PB3245) was merged by `worktree-wf_1e77ed6a-468-1`, whose PR #856 merged at 2026-10-31T01:06:43Z. f7f-29 had stopped 7 times on exit 16 DRIVER FILE QUEUED (land-lane attempts 000418 to 000441, each merging origin/main in, so its tip carried only enqueue.py merge commits: `git log --oneline 11f8e2d1e --not origin/main` shows only "Merge origin/main into worktree-wf_4b00724e-f7f-29 (enqueue.py)"). Attempt 000444 started 01:10:19Z, logged "gating 11f8e2d1ec21 once: bringing main in changed 26 file(s) the branch also changes", ran the gate from 01:10:34Z to 01:23:02Z (verdict in `E:/COBOL/.claude/worktrees/wf_4b00724e-f7f-29/TestResults/build-local/000008-20261031T011034Z`, leg 1 GREEN), then ended `=== ENQUEUE: NO ENTRY — the branch adds no single stamped DEVLOG entry to title its pull request ===` (log `E:/COBOL-coord/logs/land-lane-000444-20261031T011019Z-worktree-wf_4b00724e-f7f-29.log`). At the same moment `prune_worktrees.py` read it `LANDED: its work is on main`. About 12 minutes of a gate slot, and a false STOPPED row for the enqueue unit.

**Fix direction.** `land` asks the same content test before it merges or gates, and ends `NOTHING TO LAND` (exit 0) when it holds. The test is ONE function shared with `prune_worktrees` (the `classify` content class, or a smaller extraction of its merge-tree-through-drivers proof), never a copy in enqueue.py. A `self_test` case plants the witness: a branch whose tip is not an ancestor but whose merge into main changes nothing.

**Sweep the fixer owes: every other place that answers "is this branch's work on main".** Read in this filing:

- `scripts/orchestrator/land_lane.py` queue watch (~line 959): already uses the content test (`r.get("content") in prune_worktrees.LANDED_CONTENT`), so it read #856 MERGED correctly. `drop_stale_rearms` (~line 737) and the watch step at ~line 847 use the survey `state == "LANDED"` only; `state` can read DECISION for a dirty worktree or IN FLIGHT for a merged branch with no commit of its own (PB3609), where `content` would not. The retry path (the retry-when-free class, `land_lane.py` ~line 504, `wait_free` ~line 680) was not seen to consult the survey before a retry: the witness shows the lane retried at 01:10:19Z, one second after its own queue watch read #856 MERGED at 01:10:18Z. The fixer decides whether a retry must refuse a branch whose content reads LANDED.
- `scripts/orchestrator/next_unit.py` (~line 104): uses `prune_worktrees.classify(...)[0]` (content), correct.
- `scripts/orchestrator/queue_facts.py`: reads GitHub's pull-request facts only and has no content test; confirm it answers no "is the work on main" question.
- `scripts/orchestrator/enqueue.py` lines ~863-864 and ~900 are other `--is-ancestor` tests with their own questions; confirm none asks this one.

This is a DIFFERENT mechanism from PB4051 (stale RETRY rows for deleted branches) and the open successor of PB3157 (which added the ancestor test).
