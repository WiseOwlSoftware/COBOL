# PB1728 — LANDED

Filed by the train-71b lander from wave 71 group A's report (`w71a-PB1715-report.md`, new defect 2). Not re-probed
by the lander. It predates PB1715: that landing's one-time differential replayed 9,955,488 tokens identical in
line AND column on the old and new lexers, so the old lexer carried the same offset.

## Finding

**Repro.** Lex `01 Y PIC 9, VALUE 1.` — `VALUE` is at input index 25 with column 26 (should be 25), and every later
token on that line is +1. A diagnostic anchored on any of those tokens points one column right.

**Code site.** `src/Cobol.Net.Frontend/Grammar/Core/CobolLexer.g4`, the PIC_STRING action's two
`InputStream.Seek(InputStream.Index - 1)` calls (lines 1129 and 1145 at train 71b): the seek moves the input back
over the separator but leaves the lexer's `Column` advanced.

**Sibling and fix shape.** `OnSignedLiteral` (same file, lines 228–229) does the same retreat correctly —
`InputStream.Seek(start + 1); Column = TokenStartColumn + 1;`. One shared retreat helper (seek AND column) would make
both sites one rule; sweep the grammar's other actions for a bare `Seek` when fixing. A `DiagnosticPositionTests`
case on a token after `PIC 9,` pins it.

## Landed (wave 73 group A, 2026-09-29)

Re-probed first: `01 Y PIC 9, VALUE X"414".` reported the literal at column 20 where `PIC 9  VALUE` (same width)
reported 19. `CobolLexer.g4` now has ONE way for an action to give back part of its match, `CutTokenTo(length)` —
it seeks the input AND sets `Column`, and the token's text follows from the cut — used by `OnSignedLiteral` and by
BOTH `PIC_STRING` trims (the trailing-period trim had the same bare `Seek`; the sweep found no other). The
token-stream differential over the 17,055 captured inputs changed 50 inputs, all column-only, all on a line after a
trimmed PICTURE string. Pinned by `DiagnosticPositionTests.TokenAfterTrimmedPictureSeparator_KeepsItsColumn` (a
§8.3.5 5) diagnostic on the VALUE literal reports the same column after `PIC X,` and after `PIC X `).
