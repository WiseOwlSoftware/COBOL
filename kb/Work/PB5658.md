# PB5658 - the other data-name-n callers at 2002

**The lead.** PB5602's final report ends "None new beyond the earlier report's list (remaining data-name-n callers at 2002)", and PB5602's own sibling sweep says
"every ScreenDataNameShape caller (FILE STATUS, LINAGE, RECORD DEPENDING, SORT keys, SAME AS, DEPENDING ON) at --std 2002, each against its own 2002 SR; FILE
STATUS FS(1) is refused in the same probe and needs its 2002 rule read before it is added." PB5602 (landed) did FILE STATUS, RELATIVE KEY, RECORD KEY, ALTERNATE
KEY, key-level COLLATING SEQUENCE, CONTROL / TYPE CH / CF / RESET ON and the READ/START key operand; the rest is not filed anywhere else (grep of open notes
for ScreenDataNameShape and for these clauses, 2026-11-15: only the landed PB1281, PB1431, PB1457, PB2041, PB2511, PB4118, PB481 and PB5602 name it).

**Mechanism (read, 2026-11-15).** In 2002 a data-name-n operand "includes subscription if needed (5.1.3)" and a clause's own SR1 says only "may be qualified"; the
no-subscript and no-OCCURS restrictions were added after 2002 (PB5602's note: 2014 Annex E.2 item 25). `DataBinder.ClauseDataName` screens through
`ScreenClauseOperandShape(dref, face)` with the 2023 rule for every caller; `DataBinder.ClauseDataNameSubscripted` is the 2002-admitting variant PB5602
introduced (`admitsSubscript2002: true`, `EditionInfo.SubscriptedClauseOperands`). Each caller below is still on the 2023 form. WHICH of them a 2002 rule
really lets carry a subscript is NOT decided here: that is the fixer's reading of each clause's 2002 SR1/SR rules (CLAUDE.md rule 1), and an operand a 2002
rule still forbids a subscript on stays refused. Unprobed.

**The callers** (the ten `ClauseDataName` calls and the five direct `ScreenDataNameShape` ones):
`DataBinder.BindRenames` (RENAMES and THRU), `DataBinder.OdoBindOccursSpec` (OCCURS KEY IS, OCCURS DEPENDING ON), `DataBinder.CapacityRegisterName` (OCCURS DYNAMIC
CAPACITY IN), `FileControlBinder.BindFileControl` (ASSIGN USING), `FileControlBinder.BindRecordClause` (RECORD DEPENDING ON), `FileControlBinder.BindLinageClause`
(LINAGE), `FileControlBinder.BindApplyCommitClause`, `FileControlBinder.CapturePadding`, `ReportSectionBinder.ReportOccursOf` (report OCCURS DEPENDING ON),
`FileControlBinder.ObsoleteFdClauses` (VALUE OF; its own 1985 SR says it "cannot be subscripted", so it stays), `SortBinder.SortBindTable` (SORT table key),
`SortBinder.SortAddFileKeys` (SORT/MERGE key), `KeyedIoBinder.RecordKeyNameOf` (record-key-name), `MessagingBinder.ScreenName` (SEND / RECEIVE operands),
`DataBinder.RedefinesDataName2` (REDEFINES: its own SR says "shall not be subscripted", so it stays).
SAME AS (named in PB5602's sweep) is not a `ScreenDataNameShape` caller in this tree: the fixer greps `SameAs` for where its operand is read.

**Sibling sweep and the shape of the fix (CLAUDE.md rule 5).** Per caller: the 2002 clause's SRs read with `cite.py --edition 2002 --find`, one golden
per arm (accepted at 2002 where the rule admits a subscript, refused at 2014/2023, refused at 2002 where its rule forbids it). The structure that makes the next
caller automatic: the caller declares its clause's per-edition rule once (a column in the table `EditionInfo.SubscriptedClauseOperands` reads), instead of
choosing `ClauseDataName` or `ClauseDataNameSubscripted` by hand, with a drift test that no caller reaches the screen without naming its rule.
