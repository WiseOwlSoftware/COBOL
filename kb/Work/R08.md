# R08 — LANDED — `FIND-STRING` truncates argument-3 from long to int

`FIND-STRING` truncates argument-3 from long to int

> Migrated from the fix queue's RESIDUE block, which never itemised these — so no work list could see them.

## LANDED (2026-08-07) — Phase-B F25's diagnosis held exactly

`CobolIntrinsics.Text.cs#FindString`: the comparison now stays in the LONG domain — `skip >= positions.Count`
returns 0 (rule 2 exhausts the matches, rule 3 requires zero) BEFORE any narrowing, and idx is a long. The old
`(int)skip` was an UNCHECKED C# narrowing applied after the negative clamp, so any argument-3 whose low 32 bits
fell in 0..Count-1 returned a match position — 2^32 printed 1 (and 7 for LAST); 2^31 and 2^32-1 missed the wrap
by luck, which is why sampling never caught it. Three theory rows pin 2^32 (both variants) and 2^32+3 (low bits
== Count, the boundary). Distinct from the recorded AsInt `(long)` GAP (AR-15.22.3-1): that bites above 2^63.
