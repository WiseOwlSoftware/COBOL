# PB4884 - next_unit.fresh_unlanded counts a branch another live session owns

**Seen, 2026-11-06.** After enqueue unit 528f3b82 ended done with `next_unit: null`, the supervisor started a resume unit at 15:53:17 with the reason "unlanded branches from the last unit: worktree-wf_2d1c5e41-4db-1". That unit did not make the branch. An attended session (claude pid 111472, started by `scripts/start-session.ps1`) owns it through wave 20261886 group a (PB4816, PB4848), committed to it at 15:30:29 during the enqueue unit, and holds its worktree lock. `prune_worktrees.py` read the same branch as IN FLIGHT.

**The mechanism.** `next_unit.after_handoff` takes every branch whose committer date is after the last unit's start from `fresh_unlanded`, which keeps those `prune_worktrees.classify` calls UNLANDED. Neither looks at the worktree lock or at who owns the branch, so `lifecycle`'s IN FLIGHT answer never reaches this rule. The branch committed again at 16:09:41, during that resume unit, so the next decision can repeat the resume for as long as the session keeps committing.

**The cost.** Each false resume runs the survey (`prune_worktrees.py` took over 590 s, PB4852) and spends an opus unit instead of the wave the handoff asked for. This one found work only because the last unit had left DECISION rows, which its handoff could have routed.

**The fix to weigh.** Leave out a branch whose worktree a live agent holds, using the same lock and process test `lifecycle` uses. That one test should answer both callers, with a case in `next_unit`'s self-test for a fresh commit on a branch locked by a live process.
