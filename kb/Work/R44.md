# R44

Answers PB1099 Q3. Asked 2026-09-24 after explaining that §8.13 says the implementor **shall** provide a mechanism to
choose whether compilation updates the external repository and a mechanism to flag differences between prototypes /
definitions and the repository (`cite.py` on §8.13), that the compiler has none today (PB1086: `REPOSITORY. CLASS
NOSUCHCL PROGRAM NOSUCHPG …` compiles clean), and that GnuCOBOL offers no model (no persistent repository; no
object-oriented classes in its testsuite). Owner chose **"Implement via assemblies"** (the recorded tool answer read
"Document not provided"; the owner corrected it at once — "I meant to answer #1").

## The decision

- The external repository IS the metadata of compiled COBOL.NET assemblies: a compiled program / function / class /
  interface assembly carries the §8.13 signature information (externalized name, kind, parameters with BY REFERENCE /
  BY VALUE and OPTIONAL, returning item, raised exceptions, entry convention, properties, methods, type declarations,
  DECIMAL-POINT IS COMMA, currency symbols, locale identification) — anything .NET metadata cannot express natively is
  carried in a COBOL.NET-owned attribute/metadata record, designed once.
- A compiler option REFERENCES repository assemblies; REPOSITORY-paragraph specifiers (§12.3.8.3 SR6/SR9/SR10/SR14/
  SR16) resolve against in-group definitions/prototypes and the referenced repository, and unresolvable names are
  diagnosed (fixes PB1086's under-reject).
- The two §8.13 "shall" mechanisms are user-visible options: whether this compilation updates the repository (emits the
  repository metadata for its source units) and whether differences from the repository are flagged.
- Annex A.1 items 66, 161, 162 get their `docs/CONFORMANCE.md` determinations from this design.
- Implement FROM a design doc (CLAUDE.md rule 2): a new deep-dive (or an extension of the OO design doc) lands first,
  per the engineering-standards bar (one mechanism for resolution — not a second resolver beside `OoNameResolution`).
