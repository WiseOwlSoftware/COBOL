# PB4594 — contained-program-ignores-program-collating-sequence: a contained program runs with the native collating sequence where its container names an alphabet

Filed 2026-11-04 from the second review of fuzz night 10's n10-sort-merge-collating draft (the PB4542 mechanism). While probing that draft, the reviewer found this separate defect and said to file it on its own: the patch for PB4542 does not touch it, and the generated C is the same with and without that patch. Upstream status `unreported`: the owner has not yet decided to report it. The review's probes are local (`~/gc-fix/review-n10-sort-merge-collating/r2/nested/nested.cob` and `nestcmp.cob`, WSL); the vetter's minimal program below combines both and drops the COLLATING SEQUENCE phrase that nested.cob carried, so the PB4542 mechanism cannot take part.

## Summary

Under `-std=cobol2014`, when a program's OBJECT-COMPUTER paragraph has a PROGRAM COLLATING SEQUENCE clause, cobc 3.2.0 applies it to the program itself but not to the programs it contains. A contained program compares and sorts in the native order instead. In the program below, OUTER and its contained INNER run the same two statements. OUTER gets the answers the reversed alphabet requires. INNER gets the native answers: `IF A1 > "B"` with A1 = "A" is false, and the table SORT with no COLLATING SEQUENCE phrase orders `BCA` as `ABC`. No diagnostic is issued. Class: wrong output.

## Minimal test case

Fixed reference format.

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. OUTER.
       ENVIRONMENT DIVISION.
       CONFIGURATION SECTION.
       OBJECT-COMPUTER. X PROGRAM COLLATING SEQUENCE IS AL-REV.
       SPECIAL-NAMES.
           ALPHABET AL-REV IS "ZYXWVUTSRQPONMLKJIHGFEDCBA".
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 A1 PIC X VALUE "A".
       01 T VALUE "BCA".
          05 E PIC X OCCURS 3 TIMES.
       PROCEDURE DIVISION.
           IF A1 > "B" DISPLAY "OUTER A>B" ELSE DISPLAY "OUTER A<B".
           SORT E ON ASCENDING KEY E
           DISPLAY "OUTER " T
           CALL "INNER"
           STOP RUN.
       IDENTIFICATION DIVISION.
       PROGRAM-ID. INNER.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 A1 PIC X VALUE "A".
       01 T VALUE "BCA".
          05 E PIC X OCCURS 3 TIMES.
       PROCEDURE DIVISION.
           IF A1 > "B" DISPLAY "INNER A>B" ELSE DISPLAY "INNER A<B".
           SORT E ON ASCENDING KEY E
           DISPLAY "INNER " T
           GOBACK.
       END PROGRAM INNER.
       END PROGRAM OUTER.
```

## Environment

`cobc (GnuCOBOL) 3.2.0` (`/usr/bin/cobc`) and `cobc (GnuCOBOL) 3.3-dev.0` (r5751 tree, tarstamp Oct 29 2026, run through `~/opt/gnucobol-3.3-dev/bin/cobc-dev` and `run-dev`), WSL2 Ubuntu x86_64. Compiled with `cobc -x -std=cobol2014 -o p32 ncmp.cob` and run as `./p32`. With 3.2.0 the C compiler prints a `_FORTIFY_SOURCE redefined` warning from the host's build flags; it has nothing to do with this program. `-std=default` prints the same lines.

## Observed result

cobc exits 0 with no diagnostic, and the program exits 0 and prints (3.2.0 and 3.3-dev alike):

```text
OUTER A>B
OUTER CBA
INNER A<B
INNER ABC
```

`cobc -C` shows the cause on both versions. OUTER's module gets `module->collating_sequence = s_AL_REV;` and its SORT `cob_table_sort_init (1, s_AL_REV);`. INNER's gets `module->collating_sequence = NULL;` and `cob_table_sort_init (1, 0);`.

## Expected result (per ISO)

```text
OUTER A>B
OUTER CBA
INNER A>B
INNER CBA
```

The OBJECT-COMPUTER clause of OUTER governs INNER too. In AL-REV, A ranks above every other letter and Z is the lowest (§2023:12.3.7.4 7) k) 1. b. and 3., both checked with `cite.py --check`: the literal assigns successive ascending positions from its leftmost character, and "Any characters of the native collating sequence that are not specified in the literal phrase shall assume a position in the collating sequence that is greater than that of the highest character specified in this literal phrase"), so in both programs A1 > "B" is true and the ascending SORT gives CBA. No line of the program compares a character that the literal of AL-REV does not name.

- §2023:12.3.6.4 1) (checked): "All clauses of the OBJECT-COMPUTER paragraph apply to the source unit in which they are explicitly or implicitly specified and to any source unit contained within that source unit."
- §2023:12.3.4 1) (checked): "The entries explicitly or implicitly specified in the configuration section of a source unit that contains other source units apply to each directly or indirectly contained source unit." §2023:12.3.3 1) (checked): "The configuration section shall not be specified in a program that is contained within another program", so INNER cannot state the clause itself; inheritance is its only source.
- §2023:12.3.6.4 9) (checked): "When the PROGRAM COLLATING SEQUENCE clause is specified, the initial alphanumeric program collating sequence is the collating sequence associated with alphabet-name-1". §2023:12.3.6.4 10) (checked) gives the native sequences only "When the PROGRAM COLLATING SEQUENCE clause is not specified and the source unit is not contained within a source unit for which a PROGRAM COLLATING SEQUENCE clause is specified"; INNER is contained in such a source unit.
- Comparisons: §2023:12.3.6.4 11) a) (checked): the program collating sequences "are used to determine the truth value of any alphanumeric comparisons and national comparisons, respectively, that are" "Explicitly specified in relation conditions". §2023:8.8.4.2.7 (checked): "Comparison is made with respect to the collating sequence of characters specified for the current alphanumeric program collating sequence."
- SORT: §2023:12.3.6.4 13) (checked): the program collating sequences "are applied to alphanumeric and national sort or merge keys, respectively, unless the sort or merge collating sequence has been modified by execution of a SET statement or a COLLATING SEQUENCE phrase is specified in the respective SORT or MERGE statement". §2023:14.9.40.4 5) b) (checked): "Second, the collating sequences established as the program collating sequences." The program has no SET statement and no COLLATING SEQUENCE phrase.

Edition: 2014. The 2009 committee draft that became the 2014 edition (CD 1.2, `t2009.txt`) has the same rules: the contained-program syntax rule 12.3.2 SR 1, 12.3.3 general rule 1 (line 12432), the OBJECT-COMPUTER general rules 1, 9, 10, 11 and 13 in 12.3.5.3 (lines 12524, 12604, 12608 and 12626; rule 11 governs the comparison half), and SORT general rule 5 b) (line 30393). The published 2014 text was not checked; it is inferred to agree, because the 2002 text (`t2002.txt`) and the 2023 text agree. In the 2002 text line 11141 is 12.2.3 GR1, line 11246 is OBJECT-COMPUTER GR1, line 11326 is OBJECT-COMPUTER GR10, rule 11 is at line 11330 and SORT 5 b) is at line 25405.

## Fix site

`cobc/parser.y`, `setup_program` (3.3-dev about line 1521; 3.2 about line 1405), observed in the source: it builds the new program with `cb_build_program (current_program, depth)`, and for a contained program `cb_build_program` (`cobc/tree.c` about line 2219; 3.2 about line 2206) copies `p->collating_sequence = last_program->collating_sequence;`. Then `setup_program` calls `setup_default_collation (current_program)` (parser.y about line 1044), which overwrites `program->collating_sequence` and `program->collating_sequence_n` with the `-fdefault-colseq` value. That value is NULL by default, so INNER runs natively. The overwrite is also observed in behavior: `cobc-dev -C -std=cobol2014 -fdefault-colseq=EBCDIC` gives INNER `module->collating_sequence = cob_ascii_ebcdic;` and `cob_table_sort_init (1, cob_ascii_ebcdic);` while OUTER keeps `s_AL_REV` (refuter probe `~/gc-notes/refute-PB4594/e33.c`). Inferred fix, not tested: call `setup_default_collation` only for an outermost program, and have a contained program take both `collating_sequence` and `collating_sequence_n` from its container (`container_progs[depth - 1]`). `last_program` is not the container, and it is not "the previous sibling" either: it is the program parsed just before, because `current_program` is not restored at END PROGRAM, so for MID2 after MID1-containing-DEEP it is DEEP. `cb_build_program` does not copy `collating_sequence_n` today. The fix must land with PB4542's: `setup_default_collation` calls `prepare_default_collation`, which also resets the file-static `alphanumeric_collation`. That reset is why INNER's SORT in the review's nested.cob gets 0 and not OUTER's sequence. If a contained program skipped `setup_default_collation` without PB4542's patch, OUTER's SORT COLLATING SEQUENCE phrase would leak into INNER's SORT.

## Draft issue

**Title:** A contained program ignores its container's PROGRAM COLLATING SEQUENCE: comparisons and table SORT use the native order

Environment: GnuCOBOL 3.2.0 (and 3.3-dev r5751), WSL2 Ubuntu x86_64; `cobc -x -std=cobol2014 -o p32 ncmp.cob`.

Program (fixed format):

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. OUTER.
       ENVIRONMENT DIVISION.
       CONFIGURATION SECTION.
       OBJECT-COMPUTER. X PROGRAM COLLATING SEQUENCE IS AL-REV.
       SPECIAL-NAMES.
           ALPHABET AL-REV IS "ZYXWVUTSRQPONMLKJIHGFEDCBA".
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 A1 PIC X VALUE "A".
       01 T VALUE "BCA".
          05 E PIC X OCCURS 3 TIMES.
       PROCEDURE DIVISION.
           IF A1 > "B" DISPLAY "OUTER A>B" ELSE DISPLAY "OUTER A<B".
           SORT E ON ASCENDING KEY E
           DISPLAY "OUTER " T
           CALL "INNER"
           STOP RUN.
       IDENTIFICATION DIVISION.
       PROGRAM-ID. INNER.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 A1 PIC X VALUE "A".
       01 T VALUE "BCA".
          05 E PIC X OCCURS 3 TIMES.
       PROCEDURE DIVISION.
           IF A1 > "B" DISPLAY "INNER A>B" ELSE DISPLAY "INNER A<B".
           SORT E ON ASCENDING KEY E
           DISPLAY "INNER " T
           GOBACK.
       END PROGRAM INNER.
       END PROGRAM OUTER.
```

Observed (no diagnostic, exit code 0): `OUTER A>B`, `OUTER CBA`, `INNER A<B`, `INNER ABC`. `cobc -C` gives INNER `module->collating_sequence = NULL;` and `cob_table_sort_init (1, 0);`.

Expected: `OUTER A>B`, `OUTER CBA`, `INNER A>B`, `INNER CBA`. ISO/IEC 1989:2023 §2023:12.3.6.4 general rule 1: "All clauses of the OBJECT-COMPUTER paragraph apply to the source unit in which they are explicitly or implicitly specified and to any source unit contained within that source unit". Rule 10 gives the native sequences only when "the source unit is not contained within a source unit for which a PROGRAM COLLATING SEQUENCE clause is specified". Rules 11 and 13 apply the program collating sequence to relation conditions and to sort keys without a COLLATING SEQUENCE phrase. A contained program may not have its own configuration section (§2023:12.3.3 syntax rule 1), so it can only inherit.

Fix site (observed): `cobc/parser.y`, `setup_program`. `cb_build_program` copies the container's `collating_sequence` into the contained program, and `setup_program` then calls `setup_default_collation`, which overwrites it with the `-fdefault-colseq` value (NULL by default).

Related: [bugs:#566] "Nested programs do not inherit the configuration section settings" (pending) covers other configuration settings and a different code path (a CLASS name in SPECIAL-NAMES, fixed in r2879); this report is the PROGRAM COLLATING SEQUENCE of the OBJECT-COMPUTER paragraph, which `setup_default_collation` overwrites. The owner may prefer to post it as a comment on #566.
