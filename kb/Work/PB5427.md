# PB5427 - at --std 85 (and 2023) an external record's data-name reused as the name of another external data item in a contained or containing program compiles, and the two programs then bind different external areas: the EXTERNAL half of the name-uniqueness rule has no check

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.NameUniqueness.cs#ScreenGlobalNameUniqueness`
- `src/WiseOwl.Cobol.Compiler/Binding/Passes/CheckGlobalNameUniquenessPass.cs#Run`

**Mechanism.** The rule has two bars. The GLOBAL half is `DataBinder.ScreenGlobalNameUniqueness` (COBOL6862). The EXTERNAL half ("as the name of an external record and as the name of any other external data item described in any program contained within or containing the program which describes that external data record") has no check: an outer `01 EXR EXTERNAL` and, in a contained program, `01 OTHER-EXT EXTERNAL. 05 EXR` compile, and the inner EXR is bound to a different external area.

**Found by.** The 1985 code read, read 3 (`kb/Work/PB4996/2026-11-12-read-3.md`): `E:/COBOL-coord/scratch/coderead-85/out-read3/rd-08.json`.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids below. Its rows are recorded PARTIAL naming this note.
