# R28 — DECIDE: the 2002 introduction window for FORMATTED-* / COMBINED-DATETIME / TRIM / NUMVAL-F cannot be derived from the 2023 text

> R00 ledger-audit orphan (2026-08-08): F43 of `PHASE-B-15.32-15.44-findings.md`, probe-verified OPEN
> against the R10-landed tree (`5312996a`). The probe programs are reproducible from the finding text.

The catalog gates the family IntroducedIn 2014 under a comment that itself says "windows provisional
pending the matrix wave"; --std 2002 rejects them with COBOLNET1502. Annex E fixes only the 2014→2023
boundary. If ISO/IEC 1989:2002 defines these functions, the gate rejects legal COBOL at --std 2002 for
eleven functions at once. Needs the 2002 standard's §15 function table (or an equivalent primary source) —
an owner/acquisition question. Until then the provisional window stands; the version matrix should carry
the provisional marker rather than asserting the boundary.

**VERIFIED AGAINST THE REPO PDF 2026-08-08** (owner asked whether the in-repo PDF's §15 table settles
this): the PDF is the **2023** edition only. Its §15.6 Table 21 (printed folios 807–815, all pages
text-extracted, page 811 image-rendered) is the 2023 INVENTORY — name/arguments/type/value columns, NO
edition history — and the markdown transcription of it is FAITHFUL (94 rows = 94 function clauses;
the one name mismatch was the printed standard's own LOCAL-TIME-FROM-SECONDS misprint, CORRECTED per
the transcription's errata convention as Addendum C5). Annex E's own §E.1 says it lists changes
"between the previous COBOL standard and
this" — 2014→2023 only — and its TRIM entry (E.3 item 31, p1227) says the function "has been ENHANCED",
which proves TRIM existed in 2014 but says nothing about 2002. **The 2023 PDF cannot settle the 2002
windows; the acquisition question stands** (the ISO/IEC 1989:2002 §15 inventory, or the 2014 edition's
own Annex E, either of which would close it).

## LANDED 2026-08-08 (decided by web-acquired primary evidence, owner-directed)

The owner directed a web search for the gap, and the research workflow (`wf_1d8f1ced-bfc`, four agents,
every verdict adversarially re-verified against a SECOND independent source, the key documents
DOWNLOADED and mechanically grepped) closed the decision:
- **The nine 2014 introductions, CONFIRMED**: COMBINED-DATETIME, the five FORMATTED-*,
  INTEGER-OF-FORMATTED-DATE, SECONDS-FROM-FORMATTED-TIME, TEST-FORMATTED-DATETIME, TRIM — the WG4/J4
  **CD 1.2 (2009-08-23) Annex D.2 item 4** ("New intrinsic functions … introduced in this committee
  draft International Standard") lists them verbatim (archive.org copy of cobolstandard.info's
  std.zip), corroborated by the published-2014 inventory.
- **NUMVAL-F and TEST-NUMVAL-F are 2002**: the COBOL Consortium's COBOL2002 introduction names both
  among the functions ADDED by COBOL2002, and both are ABSENT from the 2005/2009 draft new-function
  lists. **The provisional 2014 window was rejecting legal 2002 COBOL — fixed** (catalog → 2002).
- **The same D.2 list exposed the mirror error**: LOCALE-TIME-FROM-SECONDS and SECONDS-PAST-MIDNIGHT
  are 2014-NEW, and our catalog windowed them 2002 (over-accepting). Fixed (catalog → 2014); the
  edition-gate sweep caught the 2002 golden `intrinsics_date_window`'s SECONDS-PAST-MIDNIGHT leg,
  which SPLIT into the new 2014 golden `seconds_past_midnight` (the windowing trio keeps its 2002
  coverage). The "windows provisional pending the matrix wave" caveat is retired in the catalog;
  the matrix wave should re-verify these rows against its own sources when it runs.
