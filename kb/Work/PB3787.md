# PB3787 — a sparse-checkout CI job can lose an import silently

**Sites:** `.github/workflows/build-and-test.yml` (the `supersede` job's sparse-checkout list and its comment), `tests/WiseOwl.Cobol.Tests.Unit/SparseCheckoutDriftTests.cs` (`SparseCheckoutDriftTests`), `tests/WiseOwl.Cobol.Tests.Unit/SparseCheckoutAudit.cs` (`SparseCheckoutAudit`), `tests/WiseOwl.Cobol.Tests.Unit/DotnetSdkInstallDriftTests.cs` (`JobShape`, shared with the audit), `docs/rearchitecture/DESIGN-test-build-ci.md` (section 3.17.2 step 4, section 3.17.8)

## Measured

The reviewer reproduced it on head 82cfaeb29: a `git archive` of scripts/orchestrator plus scripts/standard_streams.py
runs `cancel_superseded.py --self-test` to PASS; delete standard_streams.py and it raises ModuleNotFoundError. PB3637's
merge had to add scripts/standard_streams.py to the sparse list by hand. In CI the step is continue-on-error, so a
future import of another scripts/ module makes the supersede job cancel nothing while the run stays green, and no test
fails: nothing under tests/ or scripts/ reads the sparse-checkout list.

## Acceptance

- A drift test resolves the transitive repository imports of every script a sparse-checkout job runs and requires each
  module to be inside that job's sparse list (the shape that makes the next job automatic, rule 5: every sparse job, not
  only `supersede`).
- The test fails today if standard_streams.py is removed from the list.

## Landed (wave 20261704, group F)

Re-probe on this build: a copy of `scripts/orchestrator` alone fails `cancel_superseded.py --self-test` with
`ModuleNotFoundError: No module named 'standard_streams'`; with `scripts/standard_streams.py` beside it the self-test
passes. Nothing under `tests/` or `scripts/` read the list.

Fix at the root, for every sparse job (rule 5), not for `supersede` alone: `SparseCheckoutDriftTests` (reader
`SparseCheckoutAudit`) takes each workflow job whose checkout has a `sparse-checkout` list (`supersede`,
`dotnet-sdk-cache`) and requires its list to cover every repository file the job reaches: a token of its steps that
names an existing file, a local action's `action.yml` and what that names, a shell script's tokens, and each repository
module a Python script imports as it starts, transitively (module-level `import` and `from … import`, relative and
package forms; a function body's import is lazy and not followed). The job must set `sparse-checkout-cone-mode: false`
(the action defaults to cone mode, where the same lines name directories only) and may not use a `!` pattern (not
modelled). Arms: the real workflow without `scripts/standard_streams.py` is flagged (the acceptance), the real
closures are measured (no vacuous pass), and planted arms hold a transitive import, a lazy import, a docstring and a
comment, relative imports and packages, a local action, the pattern forms, a cone-mode job and a negation.

Limits of the static read: an `importlib` import or a script path held in a Python string is not seen.
