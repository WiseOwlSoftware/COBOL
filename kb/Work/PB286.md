# PB286

Found while building the Phase-B dossier (`scripts/spec/phase_b_batch.py`), 2026-09-01.

## The defect

`base_slug` derived each agent's file name from the subject text by replacing only `' '` and `'/'` and passing
every other character through. Almost every subject in the catalog is bare words, so this held for eight batches.
The Annex A.1 subjects are not bare words — they are full sentences carrying parentheses, commas and **colons**:

```
Alignment of data for increased efficiency (special or automatic alignment: interpretation, rules)
  old slug -> in-alignment-…-automatic-alignment:-interpretation,-rules).json
```

On Windows that file name is **not an error**. `path:stream` is the NTFS alternate-data-stream syntax, so the
write succeeded against a stream hanging off a zero-byte visible file. Every observable said fine:

* the process **exited 0**;
* `is_file()` was **True** and `st_size` was **3,674** — the bytes really were written;
* the printed slug list still **promised** the subject to the workflow;
* and `Path.glob("in-*.json")` — which is how the workflow actually enumerates the batch — **returned nothing**
  for it.

So the batch ran **one agent short of what it announced: 674 promised, 673 on disk**, and no log line, exit code
or exception marked the difference. A missing item read as no item.

## The fix, and the invariant that was not good enough

`base_slug` now sanitises to `[a-z0-9-]` (`SLUG_UNSAFE`), truncates at `MAX_SLUG = 80` so
`<out>/in-<slug>.json` clears the 260-character path limit, and de-duplicates deterministically so two subjects
that sanitise to the same stem stay distinct.

⛔ **The first invariant written for this PASSED on the bug.** It asked, after the write, whether the file
existed and was non-empty — and on the alternate-data-stream defect Windows answered yes to both, because the
stream genuinely existed and genuinely held 3,674 bytes. *A check downstream of a defect can be satisfied BY the
defect.* It was replaced by two that sit where the defect is:

1. **A slug-shape check before the write** (`SLUG_OK.fullmatch`, `phase_b_batch.py:760`) — screens the NAME, on
   the side of the write where the answer is the same on every OS.
2. **A promised-vs-glob population comparison after** (`phase_b_batch.py:772`) — the batch is defined as what the
   glob can see, so the slug list and `glob("in-*.json")` are compared once, and any shortfall is a hard exit.

Both were fired against the real defect before being trusted (`feedback_green_gates_arent_evidence`): invariant 1
rejects the historical slug and accepts `open-statement-p1`; invariant 2, given a real NTFS write of that slug in
a temp directory, saw the write exit cleanly and the glob return an empty set, and reported the loss.

## Why it is only MINOR

Nothing shipped from the lost agent — the subject was simply never adjudicated, and re-running the batch now
produces it. The severity is in the SHAPE, which is the reason for the note: a generator that silently produces
fewer work units than it prints is indistinguishable from one that is complete, and Phase-B's whole burn-down is
counted in units this generator emits.
