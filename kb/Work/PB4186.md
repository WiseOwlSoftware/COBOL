# PB4186 — the test-id uniqueness check is case-sensitive but the registry files it names are not

Read on the PB4147 branch (`origin/worktree-wf_adb70c0b-786-1`, pull request #860); main still has the single `diagnostics.json` object, so the defect exists once that pull request merges.

**Sites:** `conformance-suite/harness/generate.py` (`check_cases`, line 729: the `by_id` uniqueness test compares `case.test_id` exactly); the registry file naming in the same file (`sidecar_path`, which builds `wiseowl/diagnostics/<id>.json` and `wiseowl/options/<id>.json`).

**The defect.** Every refusal now lives in ONE directory, named by its test id. `check_cases` accepts two ids that differ only in case, in different clause folders. Each needs its own file under `wiseowl/diagnostics/`, and the two names are the same file on NTFS and APFS (and so on a Windows or macOS checkout, a clone of a Linux-authored tree). The old single JSON object held both members without a collision. The failure scenario: a Linux author adds `Pb9-X` and `pb9-x`; the harness check is green; the Windows checkout holds one file, so one refusal is lost or overwritten and the run reads differently per host.

**Fix direction.** Compare ids case-folded (`str.casefold`) in `check_cases`, and refuse with the same message; sweep the other names a case folder or sidecar derives from an id (the `wiseowl/options/` files, the per-step files) for the same collision. A `generate.py --self-test` arm plants two ids that differ only in case.
