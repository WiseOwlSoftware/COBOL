# PB4442 — the two arms of the §9.3.8.2.3 signature relation disagree on a restricted pointer

**Defect.** PB4107 made a restricted program- or function-pointer's TO phrase compare BY NAME inside a group member
(§8.5.3.1: two type declarations are equivalent when they have the same type-name; `SameAnalyzedProfile` and
`EssentialCharacteristicsKey` read `PrototypeSignatures.NamedRestriction`). `ActivationRelations.SignatureDifference`'s
class-pointer arm still compares an ELEMENTARY pointer formal by SIGNATURE CLASS (§9.3.8.2.3 rules 3 / 6), so the
elementary arm and the member arm of one relation disagree.

**Repro.** `conformance-suite/cases/_unassigned/pb2495_pointer_type_in_signature_checks`: an override
`USING TO Q2` over a base `USING TO Q1`, where Q1 and Q2 have one signature, is ADMITTED. The same pair written as
strong-group members is refused (`conformance-suite/cases/10.6-COBOL-compilation-group/pb4107-group-formal-pointer-two-names`,
COBOL1513). Type: under_rejects.

**Needs an adjudication** of §8.13 / GR25's signature classes before any code moves: which relation the standard
requires of an elementary restricted pointer formal in a pair-mode conformance check, class or identity.

**Sites:** `src/WiseOwl.Cobol.Runtime/Control/ActivationRelations.cs` (`ActivationRelations.SignatureDifference`), `src/WiseOwl.Cobol.Compiler/Binding/PrototypeSignatures.cs` (`PrototypeSignatures.DescriptionKey`).

**Witness.** The finisher's report names this as implementer lead 1 of PB4107, "not blocking".

**Sites (added by the landing, wave 20261828 group B):** `src/WiseOwl.Cobol.Compiler/Oo/OoConformance.cs` (`OoConformance.SignatureDifference`),

`docs/rearchitecture/DESIGN-external-repository.md` (section 6.4).

## Landed (wave 20261828, group B)

**Adjudication (the spec decides; `cite.py --check` OK for each quote).** §9.3.8.2.3 rule 3 asks the corresponding formal "the same
ALIGNED, ANY LENGTH, BLANK WHEN ZERO, DYNAMIC LENGTH, JUSTIFIED, PICTURE, SIGN, and USAGE clauses", rule 6 the returning item the
same, and §11.7.3 SR9 makes an override obey them. They are the words of §9.3.6 3 e) and §14.8.3.3, which docs/CONFORMANCE.md D-RP1
(PB4107's deciding adjudication) reads as IDENTITY of the TO phrase's prototype name: a restricted pointer's USAGE clause is `USAGE
PROGRAM-POINTER TO program-prototype-name` and the standard lists the texts that match on meaning and none for the TO phrase. The
question the note posed (class or identity) is therefore answered by the same text and the same determination: pair mode asks the
name. §8.13 / GR25's signature classes answer what a pointer may CONTAIN (SET), a different question.

**Re-probe (cobol.exe on main 174ac1048).** `conformance-suite/cases/_unassigned/pb2495_pointer_type_in_signature_checks` compiled and
ran ("px null / override null / implements null"): the override `USING TO Q2` over `USING TO Q1` and the IMPLEMENTS pair were admitted.

**Fix.** The class-pointer arm of `ActivationRelations.SignatureDifference` (the ONE pair-mode relation) compared `ContentRestriction`;
it now reads that arm only when the caller asks `pointersBySignature`, which `PrototypeSignatures.SameDescription` alone sets (the
signature graph of `PrototypeSignatures.Same` / `DescriptionKey`, PB2464 / PB2495 / PB3101, unchanged). Every other asker (an override,
IMPLEMENTS, interface-to-interface, property accessors, `HostEntryEmitter`'s aliasing test, `MoveBinder.ElementMovesOf`) gets the TO
phrase by name through `ActivationDescription.Clauses`. The probe now draws COBOL0829 (override, formal and returning item) and
COBOL0841 (IMPLEMENTS). Goldens: `9.3.8.2.3-Conformance-between-interfaces/pb4442_override_pointer_same_prototype_two_type_names`
(accepted at 2002: the same prototype under two type-names conforms; M1 formal and M2 returning item) and the refusals
`pb4442-override-pointer-two-prototypes`, `pb4442-override-returning-pointer-two-prototypes`, `pb4442-implements-pointer-two-prototypes`;
`_unassigned/pb2495_pointer_type_in_signature_checks` lost its override and IMPLEMENTS legs (they asserted the under-rejection) and
keeps the SR2 prototype / definition pair and the BY CONTENT pass. Unit: `PointerRestrictionRelationsTests`.

**For the next implementer (code sites).**
- `src/WiseOwl.Cobol.Runtime/Control/ActivationRelations.cs#SignatureDifference`: the ONE pair-mode relation; a restricted pointer is `Clauses` (the TO phrase's name) unless `pointersBySignature`, whose only asker is `PrototypeSignatures.SameDescription`. Trap: a second copy of the class compare in `PrototypeSignatures` itself is refused by `OneRelationDriftTests`, so the mode must stay a parameter of the relation.
- `src/WiseOwl.Cobol.Compiler/Oo/OoConformance.cs#SignatureDifference` and `src/WiseOwl.Cobol.Compiler/Binding/PrototypeSignatures.cs#SameDescription`: the DataItem entry forwards the flag; `DescriptionKey` keys the class pointer by `ContentRestriction` as the flagged relation reads it, so the two move together (`SignatureIdentityDriftTests`).
- `PrototypePointerTypeDriftTests.OnlyThePrototypeSignatureGraphAsksTheSignatureClassOfAPairModePointer` pins that no other file sets the flag.

**Left open (registered in the report):** the signature graph itself still reads an ELEMENTARY pointer formal by class and a
strong-group MEMBER by name, so the §10.6.2 SR2 pair `PX` (prototype `USING TO Q1`, definition `USING TO Q2`) is admitted while
`pb4107-group-formal-pointer-two-names` is refused.
