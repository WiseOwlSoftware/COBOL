# PB4912 - the local backend gives up on the first error

**What happened.** `python scripts/spec/transcribe_pdf.py pages --edition 1985 --state <dir> --local qwen3.6:35b <224 pages>`
wrote 54 pages, then one `/api/chat` call returned HTTP 500 and the traceback ended the run (`local_pages` calls
`ollama_post`, which raises `urllib.error.HTTPError`; nothing catches it). A page-by-page driver with three tries a page then
wrote 218 of the remaining pages. Six pages failed all three tries on qwen3.6:35b. Three of those (243, 258, 389) went
through on qwen3.8:27b; 324, 444 and 463 fail on both models. So an error is sometimes transient (the first call of the
night failed while the model was loading) and sometimes repeatable for a page.

PB4816 asked for the tool to be "restartable with minimal loss". A rerun does skip the written pages, so nothing written is
lost, but one bad page stops every page after it. That is the loss that requirement is about.

**The fix.** In `local_pages`: retry a failed request a bounded number of times with a pause (a transient load or memory
error); then record the page as failed in `local.json` with the error and the model, and go on to the next page. Report the
failed pages at the end and exit nonzero if any failed. `status` lists them, and `pages <list> --local <another model>`
retries them on another model, keeping the per-page provenance. Self-test: a fake Ollama that fails once and then succeeds,
and one that always fails for one page. Run 3 pages; the first is written after a retry, the second is recorded failed, the
third is written, and the exit code is nonzero.

**Sites:** `scripts/spec/transcribe_pdf.py` (`local_pages`, `post_with_retries`, `ollama_post`, `LOCAL_TRIES`, `LOCAL_RETRY_SECONDS`, `LOCAL_ERRORS`, `Run.local_failed`, `print_status`, `main`); `scripts/spec/test_transcribe_pdf.py` (whole: the planted cases).

**Landed.** `local_pages` retries a failed request `LOCAL_TRIES` (3) times with a `LOCAL_RETRY_SECONDS` pause (`post_with_retries`), then records the page in `local.json` as `{model, error, at}` and goes on; a reply that did not stop and a stamp refusal are recorded the same way. It returns the failed pages, `main` exits 1 for any, and `status` lists them. `pages <list> --local OTHER` retries them (a failed page has no file) and the success replaces the failure record. Self-test: flaky page (fails once then succeeds), always-failing page, a torn reply, a non-JSON reply, the exit codes, status.
