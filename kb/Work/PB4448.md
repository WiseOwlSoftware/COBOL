# PB4448 — COBOL5506 "unexpected IF" where COBOL2072 belongs

**Repro (report text, verbatim).**
`PERFORM UNTIL W-N = 2 DISPLAY "A" IF W-K = 2 END-IF END-IF END-PERFORM.` draws COBOL5506 "unexpected IF" instead of
COBOL2072.

**Cause (report).** A separate mechanism from PB4436's, at `CobolErrorStrategy.GuessCobolIntent`: hint 0i is
chosen where hint 0a should be (the report names the hints only by number; PB4201 and PB4224 own hint 0i, PB3832
COBOL2072).

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs` (`CobolErrorStrategy.GuessCobolIntent`).

## Resolution

**Re-probed on the wave 20261828 build** (`PERFORM UNTIL W-N = 2 DISPLAY "A" IF W-K = 2 END-IF END-IF END-PERFORM.`
drew COBOL5506 "unexpected 'IF' ... expected END-PERFORM, FINALLY or WHEN" and nothing after it; the same without the
extra END-IF, and with `PERFORM 3 TIMES`). Not hint 0a losing to 0i by priority: hint 0a (`EmptyBlockOwner`) is right
to stay silent at the IF, a token that may begin a statement. The IF is the malformed statement and the parser left the
block before it (its prediction died inside the IF), so the parser's admitted set at the IF holds END-PERFORM, FINALLY
and WHEN and no statement start, and `AdmittedKinds.Refusal` named the IF "not expected here" against that set. Hint 0i
is structural (priority 0), so `Report` never carried the report into the closed block, where hint 0a names the fault
at the END-IF. Inside an IF the same shape already drew COBOL2072: the optional END-IF lets the IF end and the
sentence retries the statement.
**Fix.** `AdmittedKinds.Refusal` answers null first where the construct just before the token could have taken it
(`whatTheConstructBeforeCouldTake`, which only the operand arm of PB4426 asked): a token the closed block may continue
with is a fault further on. The report is carried to where the block's parse dies, COBOL2072 at the END-IF, and the
stray END-IF after it draws its COBOL0306.

**Sites (as landed):** `src/WiseOwl.Cobol.Frontend/Parsing/AdmittedKinds.cs` (`AdmittedKinds.Refusal`),
`docs/rearchitecture/DESIGN-frontend-grammar.md` (the PB4448 paragraph of 3.9),
`tests/WiseOwl.Cobol.Tests.Unit/ParseRecoveryCascadeTests.cs` (`AStatementThatDiesAfterAnotherInABlock_IsRefusedWhereItDies`),
`conformance-suite/cases/14.5.3.2-Explicit-scope-termination/pb4448-empty-if-after-a-statement-in-an-inline-perform.cob`.
