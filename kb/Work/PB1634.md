# PB1634 — LANDED 2026-09-27

Found 2026-09-27 while probing PB1631 (the INVOKE BY VALUE ZERO message).

## Repro (before the fix)
`scratchpad\pb1631\zeros.cob` (session eb162d4b). A nested `PB1631V` has `01 N PIC 9(4) BINARY` and `PROCEDURE DIVISION
USING BY VALUE N`. `CALL "PB1631V" AS NESTED USING BY VALUE ZERO` displayed `V 0048`, and so did the keyword-less
`USING ZERO`. BY CONTENT ZERO into a BY REFERENCE `PIC 9(4) BINARY` formal displayed `C 0048`. The literal `0` gave
`0000`. The generated argument was `LandForFormal<long>(new CobolArg(Content, ManagedPointer<string>.Cell(new
string('0', 1))))`: the figurative fill channel, whose one character the numeric landing read as a code point.

## Rule
§14.8.2.3.3 2) a): "If the formal parameter is numeric, the conformance rules are the same as for a COMPUTE statement
with the argument as the sending operand". §8.8.1.1 names the figurative ZERO among an arithmetic expression's
operands, and §8.3.3.6.3 SR1 a) makes it the one figurative a numeric literal's position admits. The argument is the
numeric value zero.

## Fix
The INVOKE lane already read it that way (PB1617, an inline rewrite in `OoBinder`). The rule now lives in ONE place,
`ParameterConformance.ArgumentForFormal`: an elementary numeric formal turns a figurative ZERO argument into
`BoundNumericLiteral("0")`, which takes the numeric-literal verdict and carrier. CALL applies it where it records each
argument's formal (`CallBinder`, the §14.2.3 GR2 correspondence loop), and INVOKE applies it where it did before.
A user-defined function argument was already correct (`FUNCTION F(ZERO)` + 1 = 1, probed).
Golden: `tests/conformance/2002/pb1634_zero_argument_numeric_formal` (BY VALUE ZERO, keyword-less ZEROS, BY CONTENT
ZEROES into BINARY, BY CONTENT ZERO into PACKED-DECIMAL, and the literal 0 as the control).

## Residue
`BoundFigurative { Kind: 'Z' }` is also what `ALL ZERO` binds to, so `ArgumentForFormal` cannot tell the two apart.
BY VALUE ALL ZERO is refused earlier, at the SR23/SR16 literal screen (PB1631). A BY CONTENT ALL ZERO into a numeric
formal still reads as zero, although §8.3.3.6.3 SR1 a) excludes ALL where a numeric literal is required. Whether rule
2a's COMPUTE restricts the argument that way is to be derived before anything changes.
