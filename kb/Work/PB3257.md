## Landed (wave 1112, group B)

**Re-probed** on base `e679ed0a9` by the unit witness `ActivationKeyCultureTests` (a clone of the invariant culture
whose negative sign is U+2212, sv-SE's on .NET 10, so the witness is the same on every host, ICU or not): on the
unfixed code all three keys of a `PIC 99P` item differ from their invariant text — `StrongTypeModel.TypeIdentityKey`
(the PicInfo record dump's negative Scale), `ActivationDescriptions.ElementaryClauses` (`DIGITS {Digits}.{Scale}`) and
a sibling the finding did not name, `PictureClauseIdentity.Key`, whose absent currency string is `-1` in EVERY picture
key, so every universal INVOKE argument description built on an sv-SE host differed from one built elsewhere.
**Fix:** `TypeIdentityKey`'s two appends take `CultureInfo.InvariantCulture`; `EssentialCharacteristicsKey`'s
interpolations are `string.Create(InvariantCulture, …)` and the record dump is `InvariantRecordText` (the current
culture set to invariant for the record's `ToString` and restored in `finally`: a record's `PrintMembers` takes no
format provider, and this keeps "every axis by construction"); `ActivationDescriptions.ClausesOf` / `PhrasesOf` and
`PictureClauseIdentity.Key` are `string.Create(InvariantCulture, …)`. `TypeRestriction.Key` is `TypeIdentityKey` and
needs nothing of its own. `RedefinesModel.RenamesSpanPart.SubscriptsFor` (`:28-29`) no longer formats text at all
(kb/Work PB2151 made its subscripts `Position` nodes), so that site is gone. Because every key is invariant by
construction, the bind-time caller key and the emit-time method key agree whatever scope kb/Work PB3239 puts around
the backend. Behavior-neutral on the invariant host the suite runs on. No row closed (`closes_rows_reason`); the
witness is recorded on GR-8.5.3.1-1 and SR-14.8.2.2-2.
