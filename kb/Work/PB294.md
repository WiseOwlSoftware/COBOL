# PB294 — the gate that looks at 2% of its subject and reports green

Found by the A.4.8 / A.4.13 module-witness sweep (2026-09-02) while asking why `COBOLNET1560` had been sitting as
a bare literal with no descriptor at all; **re-measured at landing time on the merged tree.**

## The gate

`tests/Cobol.Net.Tests.Unit/DiagnosticRegistryDriftTests.cs`, `EveryEmittedCode_IsACatalogDescriptor`:

```csharp
new Regex("Report(?:Error|Warning)\\(\\s*\"(COBOLNET\\d{4})\"|(?<![\\w.])(?:Error|Warning)\\(\\s*\"(COBOLNET\\d{4})\"");
```

Its docstring states the invariant correctly — *"Every COBOLNETnnnn id string EMITTED anywhere in src … must
exist as a catalog descriptor — a bare literal outside the catalog is invisible to the next-free allocation scan
and to DIAGNOSTICS.md, which is exactly how the shipped COBOLNET1573 two-meanings collision happened"*. The
**second alternative** is the one that would enforce it, and `(?<![\w.])` forbids a `.` immediately before
`Error`/`Warning` — i.e. it matches only an UNQUALIFIED call. Real emit sites are qualified:

```
src/Cobol.Net.Compiler/Binding/EcNameResolution.cs:46            edition.Error("COBOLNET0710", …
src/Cobol.Net.Compiler/Binding/Validation/StatementValidation.cs:161  data.Edition.Error("COBOLNET0805", …
```

Both are invisible to the gate.

## Measured (script over `src/`, skipping `Generated`/`obj`/`bin`)

| | |
|---|---|
| literal emit sites `(Error\|Warning\|Removed\|Declined)("COBOLNETnnnn"` | **487** (167 distinct codes) |
| sites the gate's own regex matches | **11** (7 distinct codes) |
| catalog codes (the generated `docs/DIAGNOSTICS.md` rows) | 132 |
| **emitted codes with NO catalog descriptor** | **151** |

So the gate examines **2.3%** of its subject and has never been able to see 151 of the codes it exists to police.
Everything downstream of the catalog is blind to those 151: `docs/DIAGNOSTICS.md` has no row for them, they carry
no `--suppress` identity, and — the failure the docstring itself names — the next-free allocation scan cannot see
them, which is how `COBOLNET1573` shipped with two meanings.

⚠ The one code the regex *can* reach and that is absent from `DiagnosticCatalog.cs` as a string literal
(`COBOLNET0902`, emitted via `ReportError` in `CopyProcessor.cs`) is nevertheless registered — through
`EditionCodes.RemovedConstruct` — so the test is green for a *real* reason on the only site it looks at. That is
what made the vacuity survive: the sample it takes is not merely small, it is unrepresentative.

## Fix shape

1. **Drop the lookbehind and match the receiver instead** — `(?:[\w.]*\.)?(?:Error|Warning|Removed|Declined)\(` —
   then the gate sees all 487 sites and fails with 151 offenders, which is the honest starting state.
2. **That red is the work**, not a reason to weaken the gate: each of the 151 needs a descriptor, or its emit
   needs routing through an existing one. Land it as a baseline the way `kb/Work/PB175` records the semgrep
   baseline, so the count can only go DOWN.
3. **Prove the repaired gate fails** before trusting its silence (`feedback_green_gates_arent_evidence`): plant
   one qualified `edition.Error("COBOLNET9999", …)` and watch it name that site.

⛔ The general lesson is `feedback_measure_the_selectors_complement`: a regex gate is evidence about what it
MATCHED and never about what it skipped, so a scan-shaped test owes a second assertion on its own POPULATION —
here, that the number of sites it inspected is within reach of the number of sites that exist. Without that, a
gate can be perfectly green and inspect nothing, which is the shape `work.py next` had (nine harmful items hidden
for months) and the shape `ExternalCorpusPopulationDriftTests` was built to refuse.
