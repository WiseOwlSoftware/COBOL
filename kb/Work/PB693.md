# PB693 — OPEN — a reserved word admitted to the name slot

Found 2026-09-05 by the `PB345` implementer (report §"New defects" 1) when its note's repro reproduced only WITH
the periods it printed: written period-less, the UNLOCK statement vanished into the MOVE before it.

## The shape

`moveReceivingPhrase : TO dataReferenceList` consumes `UNLOCK F1` as two more receivers, because the generated
`cobolWord` rule (`src/Cobol.Net.Frontend/Grammar/Core/CobolWords.g4`, ≈ line 107) admits `UNLOCK` unguarded.
§8.9 (`cite.py --check 8.9 "UNLOCK"` → OK) lists UNLOCK among the reserved words, and COBOLNET0901's own message
says so — the mechanism is the NAME-SLOT admission, not the gate. Any statement ending in a `dataReferenceList`
(DISPLAY, MOVE, …) followed by a period-less UNLOCK has the same shape.

**Repro** (`<a9d94900 scratch>\PB345\probe\unlockseq.cob`): `MOVE "ZZ" TO FS` then `UNLOCK F1` on the next line, no
period between, at `--std 2002/2014/2023` → `COBOLNET1639 'UNLOCK' is not defined`, `COBOLNET1639 'F1' is not
defined`, `COBOLNET0901 'UNLOCK' is a reserved word in COBOL-2023`.

## Fix

`tests/version-matrix/cobol-words.json`: give the `UNLOCK` row `"reservationGated": true` and regenerate
(`scripts/gen-cobol-words.ps1`); the 85 lane keeps working because that is what the predicate is for. ⛔ Sweep with
it (rule 4): the five gated rows are the COMPLEMENT — every other `nameSlot: true` word must be re-checked against
§8.9's list, because the same omission is invisible in exactly this way; make the check a drift test (every
`nameSlot: true` word that §8.9 reserves at some edition is `reservationGated`), so the next word cannot be admitted
by hand. A positive golden with the period-less spelling at 2002+, the existing 85 behaviour re-measured. Same
family as [[PB655]]/[[PB657]] (the reserved-word funnel's reach).
