# PB2920 — class run-unit keys rooted at the declared name

Filed 2026-10-10 by the train 1052 lander (phase 1b) from the wave 1051 B implementer's report
(`E:\COBOL-coord\scratch\reports\w1051b-PB2843-report.md`, "New defects" item 1).

**Same root as PB2843** (landing in train 1052): PB2843 roots every PROGRAM's run-unit path at its EXTERNALIZED name
(`ProgramTable.OutermostPath`, `src/WiseOwl.Cobol.Runtime/Control/ProgramTable.cs`, about line 90), because §8.3.2.2 2)
makes the externalized name the one that identifies an outermost unit in a run unit ("Within a run unit, all instances
of a given name that is externalized to the operating environment shall identify the same kind of entity or item").
A CLASS's keys were not converted: `BinderDriver.QualifyClassFiles`
(`src/WiseOwl.Cobol.Compiler/Binding/BinderDriver.cs`, about lines 1276-1300) keys a class's factory file connectors on
`cls.CsName`, and `OoEmitter` passes `csName` to `EmitExternalDescribes`
(`src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/OoEmitter.cs`, about line 491), both derived from the DECLARED name.

**Failure scenario.** Module 1 declares `CLASS-ID. ACCT.`, module 2 `CLASS-ID. ACCT AS "LEDGER-ACCT".`; both are loaded
into one run unit. Their factory file connectors share one key, so module 2's factory opens module 1's connector (a
wrong file or a wrong open state), and the EXTERNAL describer registered for one is read for the other. Silent.

**Repro (to write).** Mirror PB2843's `E:\COBOL-coord\scratch\w1051b\p2843\` (worker.cob, x.cob) with two class
modules as above, each with a factory FD; open in one, read in the other.

**Fix shape.** The class's run-unit key goes through the same former as a program's (the externalized class name,
`ExternalizedNames.Form` + the escape of `OutermostPath`), at both sites; a test in `ModuleRegistrationHostTests` beside
PB2843's.

## Landed (wave 1056 B, 2026-10-10)
Re-probed on the wave's own build with two compiled modules (`E:/COBOL-coord/scratch/w1056b/r/`: MAINPB with `CLASS-ID.
ACCT` and a factory FD, SUBPB with `CLASS-ID. ACCT AS "LEDGER-ACCT"` and its own factory FD, MAINPB calling SUBPB between
its factory OPEN and CLOSE): `A OPEN 00 / B OPEN 00 / B CLOSE 00 / A CLOSE 42` before the fix (both factories keyed
`ACCT::FACT::FF`, so B's CLOSE closed A's connector), `... A CLOSE 00` after.
**Root:** a class's run-unit keys are now formed in ONE place, the class sibling of PB2843's `OutermostPath`:
`ProgramTable.ClassPath` (the EXTERNALIZED name, §8.3.2.2 2) and §11.3.4 GR1, escaped the same way, behind a leading `/`
that no program path can begin with) and `ProgramTable.ClassHalfPath` (`/OBJECT`, `/FACTORY`). `OoClassSymbol.RunUnitPath`
and `.HalfPath` call them; `BinderDriver.QualifyClassFiles` roots the factory, instance and SORT keys at `RunUnitPath`
(was `cls.CsName`, the DECLARED name, which stays the C# wire contract with `PicInfo.ClrType`), and `OoEmitter.EmitTypeHalf`
passes `HalfPath` as the EXTERNAL describer identity to `EmitExternalDescribes` (was the half's C# name, so two modules'
classes were one describer and the §14.8.4 comparison skipped the second as "self": the sibling's method ran with no
EC-EXTERNAL-FORMAT-CONFLICT). **Sibling sweep:** every `"::"`-keyed run-unit key in the compiler (program files by
`unit.Path`, PB2843; class factory, instance, SORT and EXTERNAL keys, here) now reaches the externalized name; `KeyTail`
(the display fallback) reads the text after the last `::`, unaffected. The per-object instance key is a run-unit counter
suffix (`MintInstanceKey`), already unique. Tests: `ModuleRegistrationHostTests.TwoModulesDeclaringTheSameClassNameAsDifferentClasses_KeepTheirFactoryFileConnectorsApart`
and `..._AreTwoExternalDescribers` (both failed with the old roots, measured by reverting `RunUnitPath`/`HalfPath` to the
C# names), `ModuleRegistrationTests.AClassPath_IsRootedAtTheExternalizedName_AndNeverMeetsAProgramOrAHalf`. Design:
DESIGN-external-repository §11.2, OO_DESIGN.
