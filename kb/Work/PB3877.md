# PB3877 — call-returning-invalid-returning-field: Feature request: CALL ... RETURNING an alphanumeric item is refused with "invalid RETURNING field" (cobc models RETURNING as a C return value; program RETURNING is not implemented)

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S1) and refutation (RECLASSIFY). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\call-returning-invalid-returning-field.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\call-returning-invalid-returning-field\`.

## Summary

A FEATURE REQUEST (verdict FEATURE-MISSING, edition 2014; corrected by the refuter from `rejects legal ISO source`).
cobc 3.2 refuses every `CALL ... RETURNING identifier-3` whose identifier-3 is not of class numeric or pointer, with
"error: invalid RETURNING field", under `-std=cobol2014` and the default dialect. The source is legal ISO source: no
rule restricts the class of identifier-3 of a Format 1 CALL (14.9.4.3 7) 9), 14.9.4.4 4), 14.8.3.1, 14.8.3.3, 14.2.2
4) 5), all re-checked; the 2009 committee draft 14.9.4.2 has RETURNING in Formats 1 and 2 with the same identifier-3
rules). But the refusal in `cb_emit_call` (cobc/typeck.c, lines 8671-8678) is a deliberate numeric/pointer restriction
of cobc's model of RETURNING as a C return value, and accepting the source needs program RETURNING (parser.y, an `#if
0` block, a `CB_PENDING` feature) implemented first. The minimal program below is a complete, conforming pair: the
called program declares `PROCEDURE DIVISION RETURNING LK-R` with `LK-R PIC X(3)` and the caller receives into a `PIC
X(3)` item. The nights met it on 6 programs (nights 2, 4, 5), each a CALL RETURNING an alphanumeric item. The
called-program side (PROCEDURE DIVISION RETURNING in a program) is PB3878; the two are ONE upstream feature request,
whose draft is this note's Draft issue section.

## Minimal test case

Free reference format (`-fformat=free`), `records/call-returning-invalid-returning-field.cob`:

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. RETX.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 WS-R PIC X(3).
PROCEDURE DIVISION.
    CALL "SUBRX" RETURNING WS-R
    DISPLAY WS-R
    STOP RUN.
IDENTIFICATION DIVISION.
PROGRAM-ID. SUBRX.
DATA DIVISION.
LINKAGE SECTION.
01 LK-R PIC X(3).
PROCEDURE DIVISION RETURNING LK-R.
    MOVE "ABC" TO LK-R
    GOBACK.
END PROGRAM SUBRX.
END PROGRAM RETX.
```

## Expected result (per ISO)

ISO/IEC 1989:2023, all checked with `scripts/spec/cite.py --check`:

- §14.9.4.3 SR 7): "Identifier-3 shall reference a data item defined in the file, working-storage, local-storage, or
  linkage section." SR 9): "Identifier-3 is a receiving operand." No syntax rule of 14.9.4.3 restricts the class or
  category of identifier-3 (SR 8 concerns bit items, SR 11 ANY LENGTH); SR 25), which applies the conformance rules of
  14.8 at compile time, is a FORMAT 2 rule.
- §14.9.4.4 GR 4): "If a RETURNING phrase is specified, the result of the activated program is placed into
  identifier-3." GR 3) d) applies the conformance rules of 14.8.2 and 14.8.3 when the call is executed.
- §14.8.3.1: "A returning item shall be specified in the activating statement if and only if a returning item is
  specified in the procedure division header of the activated element." §14.8.3.3: for elementary items that are not
  object references, "the receiving operand shall have the same ALIGN, BLANK WHEN ZERO, DYNAMIC LENGTH, JUSTIFIED,
  PICTURE, SIGN, and USAGE clauses" — `PIC X(3)` against `PIC X(3)` conforms.
- The called program is legal: §14.2.2 SR 4): "The RETURNING phrase may be specified in a method definition, a
  program definition, or a program prototype."; SR 5): "Data-name-2 shall be defined as a level 01 entry or level 77
  entry in the linkage section."

Expected: the program compiles and displays `ABC`, exit 0. (That is what the standard specifies; cobc's departure from
it is a missing feature, not a misreading of the rules: see the Class section.)

Edition: CALL ... RETURNING and the RETURNING phrase of the procedure division header were introduced in ISO/IEC
1989:2002 and are in 2014, the edition `-std=cobol2014` claims; the rules above are unchanged in 2023 (Annex E lists no
change to them).

Edition as recorded by the adjudicator: 2014. `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Fix site (GnuCOBOL 3.2 source, read observationally)

`cobc/typeck.c`, function `cb_emit_call`, lines 8671-8678: when `returning` is present and not `cb_null`, a
`CB_TREE_CLASS` other than `CB_CLASS_NUMERIC` or `CB_CLASS_POINTER` is refused with "invalid RETURNING field". The
restriction reflects GnuCOBOL's CALL RETURNING model (the called routine's C return value), and program RETURNING is
itself unimplemented in 3.2 (`cobc/parser.y` lines 11211-11219, `CB_PENDING ("program RETURNING")`; see the
`--program-returning-crash` record). A fix accepts any receiving item for a CALL of a COBOL program once program
RETURNING passes the returning item's storage from the caller (14.2.3 GR 6 NOTE 1), or, until then, reports the
construct as not implemented rather than invalid.

## Draft issue

**Title:** Feature request: program RETURNING (PROCEDURE DIVISION RETURNING in a called program, and CALL ... RETURNING into a non-numeric item)

**Body:**

Environment: GnuCOBOL 3.2.0 (Ubuntu `gnucobol3 3.2-4build1`), Linux x86_64.

This is a request for a missing feature, not a claim that cobc misreads a rule: cobc models RETURNING as the called
routine's C return value, which serves user-defined functions, and program RETURNING is pending (`parser.y`, the
`#if 0` block around `current_program->returning`, `CB_PENDING ("program RETURNING")`). Two programs show the two
sides of the gap.

1. Caller side. Save as `retx.cob` and run `cobc -std=cobol2014 -fformat=free -x -o retx retx.cob`:

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. RETX.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 WS-R PIC X(3).
PROCEDURE DIVISION.
    CALL "SUBRX" RETURNING WS-R
    DISPLAY WS-R
    STOP RUN.
IDENTIFICATION DIVISION.
PROGRAM-ID. SUBRX.
DATA DIVISION.
LINKAGE SECTION.
01 LK-R PIC X(3).
PROCEDURE DIVISION RETURNING LK-R.
    MOVE "ABC" TO LK-R
    GOBACK.
END PROGRAM SUBRX.
END PROGRAM RETX.
```

Observed: `retx.cob:7: error: invalid RETURNING field` (plus the warning `program RETURNING is not implemented` for
line 15); exit 1. The same with the default dialect. The refusal is `cb_emit_call` in `cobc/typeck.c` (lines
8671-8678), which accepts only a numeric or pointer RETURNING item.

2. Called side. The same pair with `PIC 9(3)` items in both programs and `MOVE 123 TO LK-R` (the record `retn.cob`)
compiles with `warning: program RETURNING is not implemented [-Wpending]` and the run dies with SIGSEGV at the MOVE
(exit 139); the linkage-section returning item has no storage.

What the standard specifies: the source is legal ISO/IEC 1989 source (2002, 2014 and 2023), and the runs display
`ABC` and `123`. 14.2.2 syntax rule 4 allows RETURNING in a program definition; 14.9.4.3 syntax rules 7 and 9 require
only that identifier-3 of a format 1 CALL be a receiving item in the file, working-storage, local-storage or linkage
section, with no class restriction; conformance between identifier-3 and the called program's returning item (14.8.3:
same PICTURE, USAGE, ...) is checked when the call is executed (14.9.4.4 general rule 3 d); and 14.2.3 general rule 6,
NOTE 1, places the returning item's storage in the activating source unit.

Request: implement program RETURNING (the caller passes the returning item's storage), which lets `cb_emit_call`
accept any receiving item for a CALL of a COBOL program. Until then, a "not implemented" diagnostic would describe the
caller-side refusal more accurately than "invalid".
