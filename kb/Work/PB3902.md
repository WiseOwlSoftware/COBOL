# PB3902 — picture-implied-from-value-required--literal: cobc 3.2: "PICTURE clause required" for a level-01/77 item whose PICTURE is implied by an alphanumeric or national VALUE literal

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S5) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\picture-implied-from-value-required--literal.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\picture-implied-from-value-required--literal\`.

## Summary

ISO COBOL (2002 onward) lets an elementary item omit its PICTURE clause when its VALUE clause specifies an
alphanumeric, boolean or national literal; the PICTURE is then implied from the literal (`X(length)`, `1(length)`,
`N(length)`). cobc 3.2 refuses such an item at level 01 or 77 with "PICTURE clause required" under every `-std`
tried (`cobol2014`, `cobol2002`, `default`). The same entry at level 05 compiles and gets the implied `X(3)`, so the
implied-picture machinery exists and only the level test refuses it.

The night records grouped three other mechanisms under this family; they are decided separately (Split, below).

## Minimal test case

Free reference format (`-fformat=free`), `records/picture-implied-from-value-required--literal.cob`:

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. IMPPIC.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 A VALUE "ABC".
PROCEDURE DIVISION.
    DISPLAY "[" A "]" FUNCTION LENGTH(A)
    STOP RUN.
```

## Expected result (per ISO)

ISO/IEC 1989:2023 §13.16.3, each citation checked with `scripts/spec/cite.py --check`:

- Rule 8): "For any other entry describing an elementary item, a PICTURE clause shall be specified except as indicated
  in Syntax rule 9."
- Rule 9): "The PICTURE clause may be omitted for an elementary item when an alphanumeric, boolean, or national literal
  that is not a zero-length literal is specified in the data-item format of the VALUE clause. A PICTURE clause is
  implied as follows: a) if the literal is alphanumeric, 'PICTURE X(length)' ..." No level-number restriction applies
  (rule 1: "Level-number may be 77 or 1 through 49").

`01 A VALUE "ABC".` is legal and has the implied `PICTURE X(3)`. Expected: the program compiles and prints `[ABC]3`.

Edition: the rule is in the ISO/IEC 1989:2002 text (post-ballot draft headed "ISO/IEC 1989:2002(E)", 2001-12-04,
data description entry syntax rule 9: "The PICTURE clause may be omitted for an elementary item when an alphanumeric,
boolean, or national literal is specified in the VALUE clause") and in the ISO/IEC 1989:20xx CD 1.2 (2009-08-23) that
led to 2014 (same rule 9, "in the data-item format of the VALUE clause"). It is part of the edition `-std=cobol2014`
claims. (The public draft copies are the Wayback archives listed in the WiseOwl project's reference notes; 2023 added
only "that is not a zero-length literal".)

Edition as recorded by the adjudicator: 2014. `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

The national variant prints `3`.

## Fix site (GnuCOBOL 3.2 source, read observationally)

`cobc/field.c`, function `create_implicit_picture` (line 1075). It already builds an implied PICTURE from the first
VALUE literal (its `size_implied` from the literal's size, then a warning "defining implicit picture size %d" under
`-Wadditional`), but before that the test `f->level == 1 || f->level == 77 || !first_value` (line 1227) reports
"PICTURE clause required" and returns for every level-01/77 item. A fix drops the level condition when the first value
is a non-numeric literal (keeping the error for a numeric literal, which rule 9 does not cover, and for a figurative
constant if the maintainers read rule 9 as literal-only), and gives a national literal `N(length)` rather than
`X(...)`.

rule has no level-number restriction.

Cause: `create_implicit_picture` (cobc/field.c) reports "PICTURE clause required" for every item at level 1 or 77
before the implied-picture code that already handles the level-05 case.
