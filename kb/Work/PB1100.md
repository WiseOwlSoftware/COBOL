# PB1100 — OPEN — class units never get the REPOSITORY's user functions

## Rule text (re-run by the registrar)
- `python scripts/spec/cite.py --check 12.3.8.4 "Within the scope of the containing environment division, a reference to function-prototype-name-1 is a reference to a user-defined function"` → `OK  §12.3.8.4 12)  (General rules)`
- `python scripts/spec/cite.py --check 12.3.3 "The SOURCE-COMPUTER, OBJECT-COMPUTER, and REPOSITORY paragraphs shall not be specified in a factory definition or an instance definition"` → `OK  §12.3.3 3)` — SR3 bars the REPOSITORY in the FACTORY/OBJECT paragraphs only, so a CLASS definition's own environment division may carry one, and its scope reaches the methods.

## The measurement (refuter, row GR-12.3.8.4-12)
Program/function scope is verified (a user FUNCTION-ID CURRENT-DATE with no arguments beats the intrinsic, keyword
and bare; `FUNCTION LENGTH AS "MYLEN"` routes both spellings to MYLEN; a user MAX(3,9) = 309). But a CLASS
definition's `REPOSITORY. FUNCTION MAX` (or MYLEN), whose FUNCTION-ID is defined PREVIOUSLY in the group — legal per
§12.3.8.3 SR10 — is refused COBOLNET1505 when a method references it. Legal source rejected in half the rule's scope.

## Code site
`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/UdfBinder.cs#UdfBindCall` (the `host.UserFunctions is null ||
!TryGetValue` arm, ~line 91); the population side is `BinderDriver.UserFunctionsOf`, which runs for program and
function units only — the OO driver's class/factory/object/method units never receive the map.

## What the fixer owes
Populate `UserFunctions` for class units from the class-level REPOSITORY (the same `UserFunctionsOf` walk, so the
self-entry fix of PB1084 reaches them too), inherited by the factory/object halves and their methods; delete the
'separate follow-up' clause from the COBOLNET1505 message. Golden: a class whose method invokes a previously-defined
user function named in the class REPOSITORY, at 2002 (the OO introduction) — plus the COBOLNET1505 negative for a
genuinely undefined one. Shares row GR-12.3.8.4-12 with PB1085 (the inherited citation); the row closes when both land.
