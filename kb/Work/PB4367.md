# PB4367 - Which DESIGN section "pins" a drift test, and a wrong tool path

**Sites:**

- (a) `tests/WiseOwl.Cobol.Tests.Unit` (the 59 `DESIGN-*.md §` citations; the probe is `E:\COBOL-coord\scratch\w20261796b\probe_cites.py`) and `docs/rearchitecture/DESIGN-runtime-library.md` (sections 2.2.1.4, .7, .9, .13) and `docs/rearchitecture/DESIGN-test-build-ci.md` (3.13, 3.14.10, 3.14.11, 3.17.3, 3.17.5).
- (b) `tests/WiseOwl.Cobol.Tests.Unit/CiBoundsDriftTests.cs` (`CiBoundsDriftTests.TheSummaryCitesTheDesignSectionThatPinsThisClass`, line 213).

(a) PB4349 fixed one wrong citation. The probe over all 59 citations found 18 whose cited section does not name the citing class. Five cite headings that do not exist as headings, only as inline decision numbers inside a section: `FileBoundaryTests`, `FixedFileAttributeFormatTests`, `KeyedStoreReloadFailureDriftTests` and `SharedReadCoherenceDriftTests` all cite `DESIGN-runtime-library.md` 2.2.1.4, .7, .9, .13, which are decision numbers within section 2.2.1. The rest cite real sections that never name the class: `GateLegDriftTests` 3.17.3, `LandingMeasureDriftTests` 3.17.5, `MergeDriverDriftTests` 3.14.10 (named at line 2632), `PythonInterpreterDriftTests` 3.14.11 (named at line 2208), `HeldAnalyzerOutputDriftTests` 3.14.10, `ImpactMapLaneDriftTests` 3.13. Most are legitimate (the doc describes the rule the test pins). **Decision owed before any generic check:** what "pins" means (the section names the class, or the section states the rule the class enforces). A generic drift test written first would either fail 18 correct citations or pass none of the wrong ones.

(b) The test's text says the summary reaches implementers through `scripts/drift_rules.py`; the tool is `scripts/spec/drift_rules.py`. The same wrong path was in the body of `kb/Work/PB4349.md`, corrected in this change set (prose only).
