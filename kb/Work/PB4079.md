# PB4079 — `work.py` carries invisible characters raw in its source

**Sites:** `scripts/spec/work.py` (`_YAML_ESCAPES`, `_scalar`)

**Where the code is.** On branch `worktree-wf_484eb705-564-32` (PR #791, PB3797, reviewed head `e1b97d1ed`), not yet on origin/main (`git show e1b97d1ed:scripts/spec/work.py`): `_YAML_ESCAPES` (line 253) writes the values of the YAML escapes L and P as the raw U+2028 and U+2029 characters, and the `_scalar` docstring (line 259) shows its code-point example as a literal U+2032 prime instead of the escape text. The reviewer cites it as `scripts/spec/work.py:64` (R1-4).

**Why a note of its own.** PB4078 is a reader that accepts invalid YAML; this is source text a person cannot see in a diff or an editor (U+2028 and U+2029 are line separators that some tools break lines on). The two sites share one cause (a character written raw where an escape belongs), so they are one note, separate from PB4078 because the fix changes no reader behaviour.

**Fix.** Write the two values as `\u2028` and `\u2029` string escapes, and spell the docstring's example as the escape text (the docstring is already raw). Add a `--self-test` arm that refuses a line-separator, format or non-ASCII control character in the source of `work.py`, so the next one is caught.
