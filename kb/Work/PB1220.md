# PB1220 — OPEN

## Measured

**column-clause-p1** — F1 — the COLUMN clause's LEFT/CENTER/RIGHT alignment brace has no grammar surface (Format 1), so every aligned COLUMN clause is a parse error and SR9's absolute-only screen and GR6b-d's placement cannot exist

- **Repro:** `03 COLUMN CENTER 5 PIC X(3) VALUE "ABC".` (03 lines inside `RD RR.` / `01 DET TYPE DE LINE PLUS 1.`, --std 2023, pinned adj-d1 cobol.exe) -> COBOL0309 unexpected 'CENTER'; `COLUMN LEFT 5` / `COLUMN RIGHT 5` -> COBOL0001
- **Expected (spec):** §13.18.14.2 Format 1 admits `{LEFT|CENTER|RIGHT}` between the COLUMN spelling and IS/ARE. CENTER 5 with printable-size 3 (odd) places leftmost = 5 - (3-1)/2 = 4, so 'ABC' in columns 4-6 (§13.18.14.4 6) d) 1.); RIGHT 5 puts it in columns 3-5 (6) c)); LEFT 5 in 5-7 (6) b)). `COLUMN RIGHT PLUS 5` must be refused BY SR9 (all operands absolute when an alignment word is written).
- **Observed:** reportColumnClause is `(COLUMN|COLUMNS|COL|COLS) (NUMBER|NUMBERS)? (IS|ARE)? reportColumnOperand+`; the grammar comment and COBOLNET_REPORT_WRITER_DESIGN §5 record the omission; CONFORMANCE.md A.4.11 calls it 'tracked' but no kb/Work note owns it (PB1059 only says its fixer should file it).
- **Code site:** src/Cobol.Net.Frontend/Grammar/Core/CobolReportWriter.g4#reportColumnClause (L165); DataBinder.Reports.cs#BindReportEntry ReportColumnSpec (L1622-1624) carries no alignment; runtime CobolReport.Place
- **Clause (adjudicator):** §13.18.14.2 Format 1; §13.18.14.3 SR9; §13.18.14.4 GR6

- **Repro:** RD R1. 01 DET TYPE DE. 02 LINE PLUS 1. 03 COLUMN RIGHT 10 PIC XXX VALUE "RRR". 03 COLUMN CENTER 20 PIC XXXX VALUE "CCCC". 03 COLUMN LEFT 30 PIC X VALUE "L". (GENERATE DET; --std 2023, also 2002/2014)

- **Observed:** COBOL0001 unexpected 'RIGHT' / COBOL0309 unexpected 'CENTER' / COBOL0001 unexpected 'LEFT' (probe p2.cob). reportColumnClause is `(COLUMN|COLUMNS|COL|COLS) (NUMBER|NUMBERS)? **GR-13.18.14.4-9** (PARTIAL, refuter-corrected where marked) — Rule: 'The rightmost column position of each printable item becomes the new value of the horizontal counter.' (cite.py --check 13.18.14.4 -> OK 9)). Absolute arm: `__hc = integer-1 + width - 1` (set, not max - so an absolute item left of the counter resets it, as 'becomes' requires); Relative: `__hc += width - 1`; AnchorSeed/AnchorStep likewise. Probe p1 line 5: absolute C at 12 then PLUS 1 -> D at 13 (counter became 12); p5 boundaries exact for every picture kind. Absent items (PRESENT WHEN) not advancing the counter is §13.18.41.4 GR3f, not this rule. || REFUTED: PARTIAL — GR9 applies to EVERY printable item. The emitter always takes an absolute item's rightmost column as integer-1 + printable-size - 1, the LEFT formula (GR6b). The alignment phrase that GR6c/GR6d give a different rightmost (RIGHT: integer-1; CENTER: integer-1 + size/2) has no grammar surface. CobolReportWriter.g4 reportColumnClause is `(COLUMN|COLUMNS|COL|COLS) (NUMBER|NUMBERS)? (IS|ARE)? reportColumnOperand+`, with no LEFT/CENTER/RIGHT. So legal source such as `COLUMN RIGHT 10 PIC XXX` followed by `COLUMN PLUS 1` cannot be compiled, and the counter update for right- or center-aligned items is not implemented. The left-aligned and relative halves are verified. The 13.18.14.3 SR9 legality of the phrase was checked. PB1059's body records the missing LEFT/CENTER/RIGHT surface with 'no note', so a register note is needed.

- **Code site:** src/Cobol.Net.Compiler/CodeGen/Verbs/ReportWriterEmitter.cs#EmitFieldPlacements (all four arms set __hc to the rightmost column)
