# PB1013 — LANDED

## Repro — measured
`printf 'QRSTUV\n' | cobol scratchpad/w51b/probe/acc.cob --run` → `L=[Q     ]` / `X6=[Q     ]`. Expected `L=[QRSTUV]`.
GR-14.9.1.4-3 is CONFORMS today on fixed-size witnesses only.

## The rule
`OK  §14.9.1.4 3)` — "If a device is capable of transferring data of the same size as the receiving data item, the
transferred data is stored in the receiving data item." The receiving item's size is the argument's (ANY LENGTH).

## Code site
`AcceptDisplayEmitter.EmitAcceptDevice` reads `DisplayTextWidth` (the declared width, 1 for ANY LENGTH). Same shape as
PB887 (ACCEPT kept a private list of receiver arms instead of going through the MOVE store): the size must come from
the receiver's Place at run time.

## What the fixer owes
Size the device transfer from the receiver's run-time length (ANY LENGTH, dynamic-length, ODO-bearing group); sweep
ACCEPT FROM DATE/TIME/… (format 2) and DISPLAY UPON for the same static width. Golden with a separately-compiled callee.

## Landed 2026-09-22 (wave 54 group C)

Re-probed first on this worktree's build of main `57d36e4c6`: `acc.cob` gave `L=[Q     ]` / `X6=[Q     ]`, and a
PIC N ANY LENGTH on N(4) and a PIC 1 ANY LENGTH on 1(5) stored one position as well (the boolean one left the rest
of its argument as SPACES — outside the '0'/'1' invariant). After: `L=[QRSTUV]`, `N4=[wxyz]`, `B5=[10110]`.

- **One receiver-size reader.** `ReceivingStore.CharacterPositions(Place)` answers "the size of the receiving data
  item" (§14.9.1.4 GR3/GR4) at execution: a slice's evaluated length, a group's positions, a dynamic-length item's
  maximum (D-DL2), an ANY LENGTH item's carrier length (§13.18.2.4 GR1 b)), otherwise the elementary item's text
  positions (`DataItem.DisplayTextWidthOf`). `EmitAcceptDevice` computes it once and every elementary arm
  (numeric, boolean, character, dynamic-length) reads it; UNSTRING's `ExaminationSize` is now that reader less a
  numeric item's separate-sign position, so the two statements cannot disagree about one receiver.
- **Sweep (format 2 and the other receiving verbs):** ACCEPT FROM DATE YYYYMMDD into an ANY LENGTH receiver already
  goes through the MOVE chain (PB887) and stored correctly; MOVE ALL / ZERO / SPACES, INITIALIZE (with and without
  REPLACING), INSPECT REPLACING / CONVERTING, STRING INTO and a numeric MOVE into PIC X and PIC N ANY LENGTH
  receivers all stored at the argument's length (`scratchpad/w54c/sweep.cob`). DISPLAY UPON has no receiver.
- **Witnesses:** `AcceptDifferentialTests.Device_AnyLengthReceiver_TransfersTheArgumentsSize` (X / N / 1 ANY LENGTH in
  contained programs, GR4a and GR4b) and `…Device_AnyLengthFunctionFormal_TransfersTheArgumentsSize` (a user-defined
  function's BY REFERENCE formal); the conformance golden runner pipes no stdin, so the device facts live in the
  ACCEPT fact class beside the other device witnesses. `ReceivingStoreDriftTests.AcceptDevice_SizesEveryElementary
  TransferByTheOneReceiverSize` fails if a device read in `EmitAcceptDevice` sizes itself again.
- Rows: GR-14.9.1.4-3 and GR-14.9.1.4-4 re-verdicted CONFORMS with the new witnesses (both were already OK on
  fixed-size witnesses only; GAP unchanged). GR-13.18.2.4-1 (the ANY LENGTH general rule itself) stays GAP — its
  a) zero-length-argument half is not witnessed here.
