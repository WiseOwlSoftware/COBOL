# PB6053 - moved code silently re-opens 1985

**Observed** (operator, 2026-11-22, main 608ccf507c): `python scripts/spec/edition_status.py --edition 1985` prints
`=== EDITION 1985: NOT COMPLETE — 5 code reads ===`; at #1937 (963a391de3) it printed COMPLETE. `python
scripts/spec/code_reads.py plan --edition 1985` names five rows "whose code has moved since the read": 1989-RV-A.2.27.4-2,
1989-RV-A.2.32.4-3, 1989-RV-A.2.33.4-1, -2, -3, each with `code-location
src/WiseOwl.Cobol.Runtime/Intrinsics/CobolIntrinsics.Select.cs#SelectMin` (or `#SelectMax`), a member PB2635 (5f7b73d0df,
one MAX/MIN/ORD-MAX/ORD-MIN selection kernel `ExtremeIndex`, the PB1754 campaign) deleted. `code_reads.py --check 1985`
stays GREEN ("5 read(s) owed a re-read (information, never red)").

**Mechanism.** A re-read owed because the code moved is information to the landing's checks and a GAP term to the edition
status line, so a landing can turn a COMPLETE edition NOT COMPLETE with every check green, and nothing tells the lane
that landed it.

**Repair of the five rows:** re-read slice 1985-c05 (`E:/COBOL-coord/scratch/w20262136/coderead/`), imported with
`code_reads.py import --replace` on branch suite85-replan.

**Owed (root):** a landing that moves a member a code read names, at an edition whose status line reads COMPLETE on
main, is refused by the landing checks with the rows it re-opens (or carries their re-read), so "COMPLETE" cannot regress
silently; sweep `edition_status.py`'s other terms for the same information-versus-red split.
