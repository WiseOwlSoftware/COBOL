# PB320 — the citations a future reader re-derives a rule from

**Rows:** none of its own — every row these sites touch is owned by the note for its behavioural defect. This
note owns the citation repair, which CLAUDE.md rule 1 makes a defect in its own right.

## Why this is one note and not sixteen

Every entry is the SAME failure mode: **a real clause that answers a different question**, inherited rather than
re-derived, so nothing about the comment reads wrong and only running `cite.py` on the clause NUMBER catches it.
Four adjudication subjects found instances independently (open p2, return, start p1, unlock), and one of them
had already contaminated a discovery dossier.

## The sites

**1. OPEN/CLOSE on the sequential path — eleven sites, one lineage.** The spec's own headings:
§14.9.6 CLOSE · §14.9.7 COMMIT · §14.9.25 MOVE · §14.9.26 MULTIPLY · §14.9.27 OPEN. The keyed path next to it
(`FileConnector.cs:167`, `RelativeConnector.cs:84`, `IndexedConnector.cs:111`) carries the correct
`(ISO §14.9.27 / §14.9.6)` pair, so this is drift in ONE lineage, not a convention.

* `CobolIO.g4:250` — `// OPEN / CLOSE (§14.9.25, §14.9.7)`
* `CobolIO.g4:279` — `an obsolete tape phrase (ISO §14.9.25): REVERSED or WITH NO REWIND`
* `SequentialIoBinder.cs:13` — `ISO §14.9.27/.7/.51/.30/.35` (the `.7` is CLOSE, i.e. §14.9.6)
* `BoundTree.cs:855, 858, 887, 901` — OPEN cited as §14.9.25, CLOSE as §14.9.7
* `FileSupport.cs:5` — `§14.9.25 OPEN`
* `SequentialConnector.cs:195, 299` — `§14.9.25` / `§14.9.7`
* `tests/version-matrix/constructs.json`, construct `open-reversed-removed-2002`, BOTH its `description`
  (*NO REWIND survives into 2023 §14.9.26*) and its `citation` field — which GENERATES
  `src/Cobol.Net.Editions/ConstructRegistry.g.cs:96`, so the wrong number is minted into a build output and from
  there into the version-matrix reports.

Site 2 is the most consequential: it is the comment documenting the very NO REWIND phrase **PB317** shows is
unimplemented, and it points a reader at MOVE.

**2. RETURN / RELEASE in the grammar — two sites.**

* `CobolIO.g4:687` — `AT is optional in the AT END phrase (ISO 14.9.39 ...)`. §14.9.39 is the SET statement
  (`--check 14.9.39.1 "The SET statement provides a means for"` → **OK**). The rule actually invoked is
  §8.3.2.4.3 (`--check` → **OK**), with §5.2.3 as its conventions twin.
* `CobolIO.g4:698` — `// RELEASE (14.9.33)`. §14.9.33 is RESUME (`--check 14.9.33.1 "The RESUME statement
  transfers control to a procedure-name"` → **OK**); RELEASE is §14.9.32 (`--check 14.9.32.1 "The RELEASE
  statement transfers records to the initial phase of a sort operation"` → **OK**). A straight off-by-one
  against the neighbouring clause. `SortBinder.cs:13` and the emitter header both cite §14.9.32 correctly, so
  the grammar file is the lone drifted copy.

**3. WRITE's ADVANCING line count cites UNLOCK.** `SequentialIoEmitter.cs#LinesExpr` (line 477) reads
`// An integer identifier (§14.9.47.3 SR - identifier-2 an integer item)`. `cite.py --check 14.9.47.3
"identifier-2"` → **FAIL**: §14.9.47.3 has exactly two syntax rules, both about file-name-1, and no
identifier-2. The rule is WRITE's: `--check 14.9.51.3 "Identifier-2 shall reference an integer data item"` →
**OK** (§14.9.51.3 rule 14). This one is load-bearing for the tooling: the line is one of the twelve source hits
the §14.9.47 dossier returned, so an auditor of UNLOCK is handed a WRITE code site as evidence about UNLOCK.

**4. A shipped conformance golden cites START for SORT.** `conformance-suite/cases/14.9.40-SORT/sort_table_format2.cob` line 1
reads `*> ISO 14.9.41 Format 2 - COBOL-2002 table SORT`. §14.9.40 is SORT, §14.9.41 is START, and START has no
Format 2 at all. The error is load-bearing enough to have contaminated this subject's own discovery dossier: the
dossier's *citing tests* list offered this golden as evidence about the START statement.

**5. A test name asserts an indexed rule about a relative file.**
the legacy integration suite's `SpecFixTests.cs:652` (deleted, PB2110) pinned *the RELATIVE-file analog of
ReadPrevious_AfterOpen_RaisesAtEnd* while citing `ISO §14.9.30 GR21 d.1`, and `:695` cites `GR21 d.2` — d.1/d.2/
d.3 are the INDEXED block's rules and answer a different question about a different organization. The
behavioural half is **PB343**.

**6. Two comments defend a RELEASE size choice with a rule about the USING file.** The comments justifying
releasing at record-name-1's own description size cite *14.9.40 GR7c space-fills a short record into a
fixed-length sort file*; §14.9.40 GR7 is a rule about file-name-2, the USING file, not about a RELEASE statement
in an input procedure. The determination half is **PB322**.

## The repair

Fix all sixteen in one change set (the `constructs.json` edit regenerates `ConstructRegistry.g.cs`), and
`--check` each REPLACEMENT rather than copying it. Then sweep: re-run `cite.py` over every clause number in
`CobolIO.g4`, `SequentialIoEmitter.cs` and `tests/conformance/`, since an off-by-one in a statement clause
number is exactly the kind that repeats.

Owner 2026-10-17: addressed in the SORT and file I/O campaign (kb/Work PB3353).

## Landed (2026-10-18, wave 1117 group C)

Re-probed on the current tree before editing: eleven of the sixteen sites had already been repaired by earlier
landings (`CobolIO.g4` OPEN/CLOSE/tape/RETURN/RELEASE headers, `BoundTree.cs` OPEN/CLOSE arms at 855-901,
`constructs.json` and its generated registry, the SORT golden header, the two RELEASE-size comments, the deleted
legacy `SpecFixTests`). Repaired here, each replacement checked with `cite.py --check`: `BoundTree.cs` (`FileOpenMode`
summary OPEN `§14.9.25` to `§14.9.27`, `BoundClose` summary `§14.9.7` to `§14.9.6`), `FileSupport.cs:5`,

`SequentialIoEmitter.cs#LinesExpr` (UNLOCK `§14.9.47.3` to WRITE `§14.9.51.3 SR14`), and two knowledge-base rows
(`kb/Spec/Lookup/Construct Catalogue.md` OPEN REVERSED `§14.9.26` to `§14.9.27`; `IR Mapping.md` `BoundClose`
`§14.9.7` to `§14.9.6`, whose now-false "source comments are cross-wired" banner is removed).

Sweep: `audit_code_citations.py --check` read 0 findings before and after, which is the measurement that it cannot
see this shape (SUBJECT's +-30-line window suppresses a statement name that sits near a clause number). An adjacency

shapes, because most name the construct in prose ("the sequential OPEN body (ISO §14.9.25"), and the wide form reports
99 sites of which none is a defect.
