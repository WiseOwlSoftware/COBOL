## Landed (wave 20262113 group A)

**Re-probe** (`--std 85`, a build of 8244f1aa4b): `MOVE X OF T TO Y` over an index-name X printed COBOL1637 "references the
index-name 'XOFQ'". Reproduced; the same text came from every `GetText()` of a qualifiable operand a message quotes.

**Fix:** the renderer already existed (`WrittenSource.Of`, `DataBinder.WrittenText`); the defect was every site that did not call
it. 129 messages built from a parse node's `GetText()` (an interpolation hole, a `+` with a string literal, a local that feeds
either) and 47 `GetText()` calls of a data reference, receiving identifier or object reference now call it. A name quoted from a
local that is ALSO a lookup key keeps the key and gains a `<name>Written` twin for the message; a local only a message reads
takes the written text. `DataBinder.WrittenTextOr` is the optional-node form (`x?.GetText() ?? "…"`).

**The structure that keeps it fixed:** `tests/WiseOwl.Cobol.Tests.RepoDrift/MessageOperandTextDriftTests.cs` compiles the compiler's
sources against the built product and refuses a `GetText()` of a multi-token parse context in a message (the three shapes above)
and, anywhere, of a data reference, receiving identifier or object reference (a qualified name's text is never what was written,
whatever it is passed to). The one-token contexts exempt from the first rule are read from the grammar (a rule whose every
alternative is one token), so a new word-shaped rule needs no list edit. Red on its planted counterexamples.

**Witnesses:** `pb5979-qualified-index-name-printed-as-written-85` ('X OF T'), `pb5979-start-key-qualified-operand-printed-as-written-85`
('OTHER-PART OF IREC', §1985:IX.4.7.3 SR4), `pb5979-read-key-qualified-operand-printed-as-written-85` ('KA OF IREC1').

**Sites changed beyond the note's two:** every file under `src/WiseOwl.Cobol.Compiler/Binding/` that carried such a message; the
design statement is in `docs/rearchitecture/DESIGN-frontend-grammar.md`.

**Not covered by the rule (a lead, not a fix):** a `GetText()` of a multi-token context that is passed as an ARGUMENT to a method that
puts its parameter into a message (`ScreenIndexNameOperand(op, text, where)`) is not seen when the context is not a data reference;
the callers found (every data reference, receiving identifier and object reference) are fixed.
