# PB5234 - stage 5 of the build redesign: measure the guards, then delete or replace them

**Sites:** `scripts/guard-*.sh` (whole: each is measured and then deleted or kept); `scripts/hooks/forbidden_commands.py`
(whole: its shell-parsing halves go); `scripts/hooks/test_forbidden_commands.py` (whole); `scripts/hooks/*.py` (each
PreToolUse hook `.claude/settings.json` registers is measured the same way); `.github/workflows/nightly.yml` (`guard`, the
job that runs `scripts/guard-fast.sh`); `.claude/settings.json` (whole: the hook registrations and the permission rules
that replace the isolation guard). The worktree-isolation guard is not a repository hook: it is Claude Code's own worktree
isolation, which refuses a worktree agent's shell command it cannot prove stays inside the worktree ("too complex to
verify", MANDATORY-PRACTICES P12); its replacement is the dispatch shape and the permission rules, not a deleted file.

**Why.** kb/Work PB5207's measurement: 1,095 refusals in three days over 891 agent transcripts, 77 % of them from two
hooks that parse a shell command and refuse it (`forbidden_commands.py` 584, of which a heredoc with a backslash 439 and a
command chained after a verdict command 116; the worktree-isolation guard 258, "too complex to verify"). PB5207 decided the
shape: a guard that parses shell text to refuse it is replaced by a design in which the harm cannot happen. The
verdict-masking guard goes when stage 4's one command (`build.py check`, PB5233) owns the verdict; the isolation guard goes
to the harness's own permission rules; the heredoc guard is measured first, then deleted or its cause fixed. What remains is
a short deny-list matched on the command NAME (never `git stash`, never a push to main).

**The work, in this order.**
1. **Measure each guard**, one row per guard: what harm it prevents (the incident note it cites), what it proves when it
   passes, its seconds per run, who runs it (hook on every tool call, the nightly, a gate, by hand), how often it fired in
   the last three days of transcripts (the PB5207 friction survey, `E:/COBOL-coord/scratch/process-friction/friction.json`),
   how many of those refusals were true positives on a sample, and what else already proves the same. The measurement is
   the first commit, recorded in this note's directory as an addendum.
2. **The heredoc guard: measure whether the mangling still happens.** Run the command shapes it refuses (a heredoc whose
   body carries a backslash escape, through the Bash tool and through PowerShell) on the current harness, compare the bytes
   written with the bytes meant, and record the result. No mangling means delete the rule; mangling means fix the cause where
   it lives, not refuse the shape.
3. **Delete or replace**, one commit per guard, each naming its measurement row. A deleted guard's self-tests, CI steps,
   doc mentions and skill text go in the same commit (CLAUDE.md rule 4: no shims). The chained-verdict rule stays until
   PB5233 lands `build.py check` and is deleted by that change, unless the measurement shows it catches nothing.
4. **The `scripts/guard-*.sh` family**: the nightly's NIST guard (`guard-fast.sh` and its helpers) is a slow target of the
   graph in stage 6 (PB5235); each other script is either still called by something (keep, and say what) or dead (delete).

**Before and after** (the DEVLOG entry states both): refusals per agent transcript, hook seconds per tool call, guard lines.
