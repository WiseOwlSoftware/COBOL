# PB2703 — the landing check attributes R3 work per landing, and a train is mixed

**Found by:** the train 1042b lander and the orchestrator (2026-10-08). Train 1042b (E H G P R Q U V N T + PB2702) was
gated GREEN on every leg at `324dd92e8`; `bash scripts/push-main.sh` exited 3 at the LANDING CHECK with 7 stops
(`E:\COBOL-coord\scratch\t1042b\push-main.log`), main untouched.

   `scripts/hooks/test_dispatch_guard.py` (58a4af883, PB2702), `scripts/push-main.ps1` (1d183d12f, U), `scripts/push-main.sh`

2. Two dispatch-ledger stops, `w1039B` (`DataBinder.cs`) and `w1039F` (`DataBinder.cs`, `PicInfo.cs`): fix-lane

## Mechanism

`scripts/orchestrator/landing_check.py` `check()` decided R3-ness once for the whole landing (`mine_r3 = notes & r3`
over `base..rev`). A train is MIXED (one commit per cluster, lander-train-brief step 5), and that decision had three
consequences:

1. Step 1 compared the WHOLE landing's changed files (`mine`) with the R3 notes' declared set, so 7 of the 8 "outside"
   files were other clusters' files.
2. Step 1 drew the declared set from `ledger`, which drops every entry whose notes are all terminal. `work.load` reads
   the LANDING's tree, where U flips PB2230-PB2234 to landed, so U's own entry (`hand`, label "re-plan of
   train1041b-dropped-a-pb2230", 19 files, `scripts/push-main.ps1` among them) disappeared. A landing that flips its
   own R3 notes lost its own declaration. When the land unit later released the first lander's 400-file `hand` entry,
   no entry met the R3 notes at all, and the check fell back to the set computed now (15 files outside).
3. Step 2's exemption `if not mine_r3 and not their_notes & r3: continue` was also per landing, so every fix-lane file
   the train shares with older fix-lane work stopped it (stops 2 and 3).

## Fix (landed in train 1042b)

R3 work is attributed PER COMMIT. For each commit in `base..rev`, `work_notes(git, f"{sha}^", sha) & r3` (the ids
leading its subject, or an R3 status it flips) says whether it is R3 work. `mine_r3` is the union of those notes, and
`mine_r3_files` is the partition files those commits change (`plan_wave.changed_files`, `--no-renames`).

- Step 1: `existed` is taken from `mine_r3_files`. `recorded` is the dispatch-ledger entries meeting `mine_r3` from the
  FULL ledger, terminal or not, because the declaration recorded at planning time is the authority for the landing
  that makes those notes terminal. A note no entry records falls back to `declared_for`, per note: before the fix,
  one recorded note disabled the fallback for the others.
- Step 2: a shared file is exempt unless it is R3 on one side: `if not shared & mine_r3_files and not their_notes & r3`.
- A squashed commit naming an R3 id and a fix-lane id is R3 whole, which is conservative: it stops.
- The self-test went from 20 to 25 cases, with five plants. (a) A mixed two-commit landing whose fix-lane commit edits
  a file outside the R3 set passes. (b) Its fix-lane file shared with an earlier fix-lane branch passes, while (b')
  its R3 commit's file shared with an earlier branch stops. (c) An R3 commit that flips its own note to landed passes on
  its now-terminal ledger entry. (d) One commit naming both kinds stops. Run against the old `check()`, (a), (b), (b')
  and (c) fail (21/25); against the new one, `=== LANDING CHECK SELF-TEST: PASS (25/25) ===`.
- Docs: the module docstring, and DESIGN-architecture-review §8.7's "landing check is the GUARANTEE" paragraph
  (per-commit attribution, the full-ledger declared set, 25 cases).

After the fix, train 1042b's check prints 2 stops (908-1 and 908-6), and both come from PB2701's mechanism (below).
With the six wide `Workflow: ` hand entries left out of a copy of the coordination state, it prints 0 stops and
0 warnings.

## Sibling sweep (other places a landing's work is classified as a whole)

- **`my_at`** (`check()`, the landing's dispatch time). This is the SAME mechanism, and it is left unchanged because
  the brief's fix contract kept it. It is still the minimum over the WHOLE landing: ledger entries meeting any of its
  notes, read from the non-terminal `ledger`, plus the first commit and its members. In a mixed train, an R3 commit
  dispatched late therefore borrows a fix-lane cluster's early dispatch time. If it shares a file with in-flight work
  dispatched between the two, the landing reads as the EARLIER branch: it proceeds with a warning, and the other
  branch is told to rebase, when the R3 work should be the one that waits. Nothing lands unchecked (the other branch
  is named), but the order is wrong. The fix shape is per-file dispatch time: the minimum `at` over the commits that
  changed the shared file, with R3 entries read from the full ledger. Site: `landing_check.py` `check()`, the `my_at`
  assignment and the `their_at < my_at` comparison.
- **`identity()`** (the THEIR side). An in-flight branch is classified by the union of the notes of every train
  manifest, ledger entry and subject that meets it. That is deliberately by dispatch, not by commit (Draft 10's K2:
  implementers commit `WIP checkpoint: …`), so per-commit attribution does not apply. Its union over WIDE entries is
  PB2701, still open, and it causes the two stops left on train 1042b.
- **`plan_wave.inflight_file_sets`** classifies nothing. It yields one file set per worktree, branch or ledger entry,
  and an entry is one dispatch. Not a sibling.
- **`scripts/push-main.sh`** calls the check once (`--rev "$SHA" --base "$BASE"`) and classifies nothing itself. Its
  callers (landers, the land unit) pass a whole train, which is exactly what the check must handle. Not a sibling.
- **`scripts/hooks/dispatch_guard.py` `record_hand_dispatch`** records a lander dispatch as one `hand` entry naming
  every id in its brief (the first 1042b lander's: 34 notes, 400 files). That is PB2701's wide-entry mechanism, and it
  is appended there as an instance.
- **`scripts/spec/work.py`** (`R3_PROGRAM` in the R3 note validation) validates notes, not landings. Not a sibling.
