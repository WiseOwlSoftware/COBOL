## Review round 1 (2026-11-18): the weak path is gone, and a cell's per-life bases are bounded

Review of 85a57d893c (record `E:/COBOL-coord/scratch/my-20261115/review-w20262105-a.jsonl`, probes in `E:/COBOL-coord/scratch/my-20261115/review-PTR/`).

**R1-1 (blocking): the weak hold the first fix kept was the same defect.** `NoteIdentity` held an addressless pointer's identity weakly, on the
rule "once the program has let it go the table must not keep it alive". That rule is wrong, because a token on a file means the program is still holding
the reference. The reviewer's probe `locptr5d.cob` does this:
1. `SET P TO LOCALE LC_ALL`; `WRITE` P.
2. `SET P TO NULL`.
3. Loop until the allocations force collections.
4. `READ`; `SET LOCALE LC_ALL TO P`.

The run ended fatally with EC-LOCALE-INVALID-PTR. GR26 says the SET "saved and a reference to the saved locale is placed into the pointer data
item" (§2023:14.9.39.4 GR26), and after a collection the READ no longer restored that reference.

The ruling is by MEANING, not by type: an image that a program can write out and read back must resolve for as long as the thing it names lives.
`NoteIdentity` received every addressless data-pointer value that `PointerImage.Of` images through `AreaBase`:
- a `SavedLocalePointer`
- a `ManagedPointer<T>` carrier
- the `PredefinedNullArgument`

Each of these can be the value of a data-pointer item, so each can be moved into a record and written. None can stay weak, so the weak path is deleted.
Every entry is now a `PointerImage.ImagedEntry`. The addressless value is the new `Identity` record, which never ends and lives as long as the run unit
that owns the table. `SlotImageTable` holds no `WeakReference` at all, and `Note` is its one way in.

**R1-2 (lead, fixed): `CellLives` grew per life.** The process-wide per-cell memo kept a base, and a far base, for every life a cell was imaged in, and
`CellBase` scanned the list linearly. A static cell is re-seeded at each CANCEL, so it lives one life per CALL.

Both maps are now hashed. The bases of ENDED lives are dropped the first time the cell is imaged in its current life. A pointer into an ended life is
not a valid address of storage (§2023:13.18.5.4 GR4), and the run unit's table drops that life's entry too, so equal dangling pointers image equal
until the cell's next life is imaged. After that, a dangling pointer imaged again takes a fresh base.
