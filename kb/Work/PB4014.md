# PB4014 — PB3997's refusal goldens do not pin each out-of-band arm separately

**Sites:** `conformance-suite/cases/13.18.63-VALUE/pb3997-value-binary-usage-above-band.cob`, `conformance-suite/cases/13.18.63-VALUE/pb3997-value-binary-usage-condition-above-band.cob`, `conformance-suite/wiseowl/diagnostics.json`, `src/WiseOwl.Cobol.Compiler/Binding/AlgebraicRange.cs#Admits`

**Failure scenario (reviewer's).** Each refusal golden packs several out-of-band entries into one program, and
`WiseOwlRefusal_RefusesTheSourceWithItsDiagnostic` only asserts that SOME diagnostic contains the expect text
(`EditionHarness.AssertHasDiagnostic`). Break the negative branch of `AlgebraicRanges.Admits` (for example read `range.Farthest`
for a negative literal so `-129` against BINARY-CHAR is admitted): `BCN VALUE -129` compiles again, but `BC VALUE 255` in the same
program still raises COBOL1625, so `pb3997-value-binary-usage-above-band` stays green at 2002/2014/2023 and no test goes red.
The same holds for a regression that drops the band check from only the level-88 THRU arm (`B6-FAR 300` still refuses).

**Fix.** Split the arms into their own refusal programs (one negative-edge program, one per level-88 form: single value, THRU
end, WHEN SET TO FALSE), or pin the count and sites of COBOL1625 through a unit test. Prove each program goes red when its arm is
mutated.

**Acceptance.** Mutating any one arm of `Admits` or any one level-88 form turns exactly one golden red.
