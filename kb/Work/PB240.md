# PB240

**Rows:** `SR-14.9.4.3-6`, `SR-14.9.4.3-8`, `SR-14.9.4.3-11`

the §14.9.4.3 operand chokepoint under-enforces at two of its screens: SR6/SR8's bit alignment conservatively accepts a REDEFINES-view carrier it cannot prove aligned, and SR11/SR18's ANY LENGTH screen has never been reached by a spec-derived fixture.

Rows: SR-14.9.4.3-6 (a BY REFERENCE bit operand shall start on a character boundary and its address shall be statically provable), SR-14.9.4.3-8 (the same for the RETURNING identifier-3), SR-14.9.4.3-11 (identifier-2 and identifier-3 shall not be described with the ANY LENGTH clause). ONE binder method, three screens.

WHAT IS RIGHT. PB132 replaced scattered tests with ONE chokepoint — ScreenCallOperand — reached from every arm that can produce a Place (BY REFERENCE, the BY CONTENT identifier arm, the bare transitive arm, the RETURNING item) and applied over the RESOLVED mode after GR5's transitivity or GR9's formal derivation, so both arms of every dispatch meet the same law. For SR6/SR8 the referenced occurrence's start bit is computed by BitLayout.StartBitWithin — the SAME §8.5.1.6.3 cursor walk as ExtentBits, one walk and one law — plus constant subscripts times element stride plus a ref-mod's leftmost, and a non-literal subscript or ref-mod start is itself the rejection, because the rules' second clause makes the address statically provable. The legal side is pinned by conformance:2023/pb132_bit_byref_aligned (a record-leading bit item and a constant-subscripted 8-bit-stride element cross BY REFERENCE with the §14.2.3 GR8 writeback visible), and each negative has its own fixture.

RESIDUE 1 — THE UNPROVABLE CARRIER (SR-14.9.4.3-6 and -8, the under_rejects flag). An exotic carrier — a REDEFINES view of a bit item — has no start bit the cursor walk can compute, and the screen ACCEPTS it unproven. That posture is correct as a default (a screen must never reject what it cannot prove misaligned) but it means a genuinely misaligned bit operand can cross a CALL boundary undiagnosed through a REDEFINES view. It is one corner of one predicate, and identifier-3 inherits it through the isReturning arm without any code of its own — SR8's whole implementation is 'ride SR6's chokepoint', which is why the two rows move together.

RESIDUE 2 — THE UNREACHED SCREEN (SR-14.9.4.3-11, the process_only flag). The ANY LENGTH screen at :568-571 fires for every Place-carrying operand and for the RETURNING item, choosing its CITATION per format (Format 1 → SR11; Format 2 → SR18 for a USING argument, §14.8.3 via SR25 for the RETURNING item). ⚠ That per-format derivation was re-worked in the code AFTER this row was adjudicated — the row's finding was that the check is unconditional on format and therefore over-rejects `CALL 'C' AS NESTED USING BY REFERENCE ANYLEN-FORMAL`, and the adjacent SR12 screen now carries an explicit ⛔ comment forbidding a 'fix' of exactly that shape — so the over-rejection half must be RE-MEASURED against the current arm before anyone acts on it. What has NOT changed is the evidence: the only two .err files naming COBOLNET1542 are tests/conformance/negative/any-length-bad-picture.err and any-length-outermost.err, both §13.18.2.3 PICTURE/placement cases, so no spec-derived fixture reaches this screen in either format on either operand, and nothing would fail if the format scope were changed in either direction. The row's own sweep found no Format-1 operand the loop MISSES (BY REFERENCE and the bare arm both Resolve to a Place, the BY CONTENT identifier arm Probes one, and identifier-3 is the RETURNING Place), so the implementation half is complete; only its scope and its evidence are open.

WHAT WOULD CLOSE IT: extend BitLayout.StartBitWithin to a REDEFINES view (the redefining entry's own leftmost is known; the walk needs to compose it); re-derive the ANY LENGTH format scope against §13.18.2.3 SR2/SR3 and §14.8.3 and record the answer in the code comment; and ship the missing fixtures — a misaligned bit item reached through a REDEFINES view (negative), and Format-1 and Format-2 ANY LENGTH cases on both a USING argument and a RETURNING item, at least one a POSITIVE golden proving the arm the current derivation says is legal.

SPEC REFS as carried by the rows: §14.9.4.3 SR6, SR8, SR11 (cite.py OK), SR18, SR25; §8.5.1.6.3 (the bit cursor); §13.18.2.3 SR2/SR3 (where an ANY LENGTH item may exist); §14.8.3 (the Format-2 RETURNING conformance route); §14.2.3 GR8.
