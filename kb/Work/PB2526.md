# PB2526 — workstation GC in the test hosts

## Measured (w1033 gate performance diagnosis, section 2, `steady-1.txt`, `scale-1.txt`, `hostgc-1.txt`, `full-*.txt`, `unitgc-*.txt`)

Compile-only probe, 2,100 cases: 32 threads under workstation GC 29.5 s wall with **20.4 s GC pause (69 %)**; under
Server GC 16.9 s with 4.8 s pause. Four processes of 8 threads beat one process of 32, so the limit is inside the
process: one GC heap that suspends every allocating thread. Flipping `System.GC.Server` in the built test host's
runtimeconfig (untracked; the COBOL child programs keep their own config): `VersionMatrixTests` subset (2,472/2,472) 87 s
to 32 s and 80 s to 39 s; **whole Conformance leg (10,914/10,914) 5 m 18 s to 4 m 15 s, test-seconds 4,835 to 3,746**;
whole Unit leg 74 s to 56 s. Pass sets identical in both arms, under similar load.

## Mechanism

No test project sets `ServerGarbageCollection`, so every test assembly's runtimeconfig.json omits `System.GC.Server`
and the runtime defaults to workstation GC.

## Shape

`<ServerGarbageCollection>true</ServerGarbageCollection>` in `tests/Directory.Build.props` (one place, every test
project; DATAS, the .NET 10 default, bounds the heap count and memory). A drift test asserts that each test assembly's
built `*.runtimeconfig.json` carries `System.GC.Server: true`, so the setting cannot silently revert. The COBOL programs
the tests run are child processes with their own runtimeconfig, so the setting does not reach them.

## Landed (wave 1033 group W, 2026-10-07, branch `gate-perf`)

- `tests/Directory.Build.props` sets `<ServerGarbageCollection>true</ServerGarbageCollection>` for every project under
  `tests/` except the project BenchmarkDotNet generates; `Cobol.Net.Benchmarks` keeps its own pinned `false`. The built
  runtimeconfig of Unit, Conformance, Characterization and the ArchOracle host now carries `"System.GC.Server": true`.
- `tests/_shared/GateLegAudit.cs#AssertTestHostConfiguredForServerGc` asserts the CONFIGURED value
  (`AppContext.GetData("System.GC.Server")`, not `GCSettings.IsServerGC`, which a one-core host would turn false);
  each gated assembly's `GateLegDriftTests.ThisTestHost_IsConfiguredForServerGc` runs it over its own host. Seen RED
  in all three assemblies before the props change, green after (gate 2 trx: Passed in leg 1 of each).
- Measured, whole assembly, compile cache off, arms alternated on the same host: Conformance 171.9 s and 196.5 s
  before, 95.7 s and 68.0 s after (with PB2527's partitions); Unit 76.0 s and 92.8 s before, 49.0 s and 65.8 s after
  (`docs/rearchitecture/evidence/w1033-gate-levers/measure.txt`). Peak working set under several concurrent gates
  was not measured; DATAS bounds the heap count.
