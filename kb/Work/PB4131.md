# PB4131 — diagnostics print in report order, so on a failed parse the COBOL0001 effect precedes the COBOL2773 cause (PB3

**Sites:** `src/WiseOwl.Cobol.Frontend/Pipeline/Frontend.cs:428` (`Frontend.LexAndParseOnce`); `src/WiseOwl.Cobol.Frontend/Diagnostics/DiagnosticBag.cs` (`DiagnosticBag.AddBeforeEffects`); `tests/WiseOwl.Cobol.Tests.Conformance/WordCharacterScreenTests.cs`.

New defect 2 of PB3845's implementer (wave 20261764 group D; the note PB3845 is held by an in-flight group, so this is a new note that
names it). Diagnostics print in the order they were REPORTED. On a failed parse, the generic COBOL0001 (the effect) is reported by the
parser first and COBOL2773 (the word-character cause the screen finds afterwards) follows, so the cause reads after its effect.

**Fix:** order by the cause-before-effect rule where one diagnostic explains another (sort by source position then by causal rank, or
report the screen's diagnosis before the parser's error for the same word), once, in `LexAndParseOnce`'s sink; never per screen. Pin
with a golden whose two diagnostics share a position. Check the existing `.err` goldens for the same pair order before changing.

Source: report `w20261764d-PB3845-report.md`, "New defects" item 2; PB3845 (open, in-flight).

## Landed (wave 20261783 group C)

Reproduced: `pb3845-nbsp-word-unparseable` printed COBOL0001 (17,12) then COBOL2773 (16,8). `LexAndParseOnce` now screens into a
bag of its own and `DiagnosticBag.AddBeforeEffects` places each report before the first parse report of the same file at or
after its position (a tie to the cause). Pinned by two `WordCharacterScreenTests` facts (the refusal goldens compare codes, not
order). No `.err` golden carried the pair in the old order.
