# PB1756 — two spellings of one contained program

## Code site

`src/Cobol.Net.Compiler/Binding/BinderDriver.cs#NestedCallablesOf`:

```
map.TryAdd(c.Name, new CalleeSignature(...));            // children
... if (c.Common && ProgramNameScope.CommonProgramReferable(...)) map.TryAdd(c.Name, ...);  // COMMON ancestors' children
```

The map's comparer is already `ExternalizedNames.Comparer` (PB1539), but its KEY is the program-name, where
`src/Cobol.Net.Runtime/Control/ProgramTable.cs` resolves a CALL on the unit's `CallName` — the externalized name the
AS literal gives (§8.3.2.2, formed and mapped by the one `ExternalizedNames` function PB1539 introduced).

## Probe to build first

A containing program with `PROGRAM-ID. X AS "Y".` contained, and `CALL "Y" USING …` with a mismatched argument list:
if the bind-time signature check (COBOLNET for §14.9.4.3 argument compatibility) is silent while the run time
resolves "Y", the table is keyed on the wrong spelling; and `CALL "X"` should then bind against the signature but miss
at run time (EC-PROGRAM-NOT-FOUND). Whichever arm reproduces sets the harm flags; the fix keys the table on the same
`CallName` the run-time table uses — one key, one place (drift-pin it beside `ExternalizedNameFormationDriftTests`).

## Retired 2026-10-04 (wave 1015 group W, w1015w) - the two spellings cannot differ

Probed on a Debug build of this tree: `PROGRAM-ID. X AS "Y".` as a CONTAINED program is refused with COBOLNET1795
("literal-1 shall not be specified in a program that is contained within another program (ISO §11.10.3 SR2)").
`python scripts/spec/cite.py --check 11.10.3 "literal-1 shall not be specified in a program that is contained"` ->
`OK  §11.10.3 2)  (Syntax rules)`. `BinderDriver.NestedCallablesOf` keys exactly the programs CONTAINED in the caller or in an
ancestor (`unit.Children` and the COMMON children along the `unit.Parent` chain), and every such program is AS-less on legal
source, so its program-name IS its externalized name and the run-time `ProgramTable` match on `CallName` finds the same unit
under the same spelling. The note reasoned from the code and built no repro; no spelling pair exists that could disagree
(`CALL "Y" AS NESTED` is refused at bind with COBOLNET1676 and `CALL "X" AS NESTED` binds, on a program whose AS literal is
itself already an error). GnuCOBOL 3.2 agrees on the outer-program fact it can express: a nested `PROGRAM-ID. X AS "Y"` is
reached by `CALL "Y"` and not by `CALL "X"` (it has no NESTED phrase). No behaviour change; the invariant is now stated in
`NestedCallablesOf`'s summary so the next reader does not re-derive it.
