# PB4366 - CsNames.IsIdentifierStartCharacter's comment mixes the CLS and C# start sets

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Model/CsNames.cs` (`CsNames.IsIdentifierStartCharacter`, doc comment at line 104).

The comment says letters, Nl and the underscore are the identifier start characters of the CLS (ECMA-335 Partition I, CLS Rule 4, after Unicode TR15 Annex 7) and of C#. TR15 Annex 7 admits only Lu, Ll, Lt, Lm, Lo and Nl as a start character; the underscore (category Pc) extends an identifier and cannot start one. So the underscore start is a C# rule only, and a generated name that begins with an underscore is not CLS-compliant (the C# compiler warns CS3008 on a public or protected member). Both the comment and, if CLS compliance is a goal of the generated assemblies, the predicate need the correction; the second is a design question for whoever owns the naming scheme (the `__`-prefixed members are non-public, where CS3008 does not fire).

Fix: correct the comment to say which set each clause belongs to; decide and record whether a CLS-compliance claim exists.
