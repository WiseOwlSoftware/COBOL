# PB3811 — a command-line output path escapes the scratch-build arm

**Sites:** `scripts/hooks/fleet_active_build.py#build_sites`, `scripts/hooks/fleet_active_build.py#build_places`, `scripts/hooks/fleet_active_build.py#target_places`, `scripts/hooks/fleet_active_build.py#output_place`, `scripts/hooks/fleet_active_build.py#dotnet_arguments`, `scripts/hooks/fleet_active_build.py#output_directories`, `scripts/hooks/fleet_active_build.py#sets_output_by_environment`, `scripts/hooks/fleet_active_build.py#Site`, `scripts/hooks/fleet_active_build.py#Arguments`, `scripts/hooks/fleet_active_build.py#Redirect`, `scripts/hooks/fleet_active_build.py#agents_sharing_any`, `scripts/hooks/fleet_active_build.py#OUTPUT_PROPERTIES`, `scripts/hooks/fleet_active_build.py#IMPLICIT_IMPORTS`, `scripts/hooks/fleet_active_build.py#project_refs`, `scripts/hooks/fleet_active_build.py#self_test`, `docs/rearchitecture/DESIGN-test-build-ci.md` (1.7)

## Measured

The new scratch arm (PB3770) treats an output-path PROPERTY in a project file as UNKNOWN (`OUTPUT_PROPERTIES`,
`project_refs`) but not the same redirection on the command line: `build_sites` ignores `-o`/`--output`,
`-p:OutDir=`/`OutputPath=`/`BaseIntermediateOutputPath=` and `--artifacts-path`, so `build_places` reports only the scratch
directory. The module docstring and DESIGN-test-build-ci.md 1.7 both say a moved output path stays UNKNOWN.

Probe on the branch head (temp tree): an agent transcript whose first record has cwd `<main>/.claude/worktrees/wf_r-1`;
caller runs `cd <scratch>/probe && dotnet build -o <main>/.claude/worktrees/wf_r-1/src/App/bin/Debug/net10.0` (likewise
`-p:OutDir=<same>/` and `dotnet publish --output <same>`): `agents_sharing_any` returns no sharing agent, so the hook
ALLOWS a build that overwrites the binaries the live implementer executes. `cd <wf_r-1> && dotnet build` is DENIED, and at
base 70998ed98 the scratch builds were denied as UNKNOWN.

## Acceptance

- `build_sites` returns UNKNOWN (or adds the resolved output directory as a written place) for a dotnet step carrying
  `-o`/`--output`/`--artifacts-path` or a `-p:`/`-property:` whose name is in `OUTPUT_PROPERTIES`; self-test cases for each
  spelling, including a place inside a live agent worktree.
- Consider `Directory.Build.rsp` beside `Directory.Build.props`/`.targets` in `IMPLICIT_IMPORTS` (MSBuild reads it
  implicitly and it can carry the same `-p` switches); decide and record.

## Landed

Re-probe on the branch head (temp tree, `E:/COBOL-coord/scratch/w20261752e/probe.py`): from a scratch directory,
`dotnet build -o <wf worktree>/src/App/bin/Debug/net10.0`, `-p:OutDir=<same>/` and `dotnet publish --output <same>` all
printed `ALLOW`; `cd <wf worktree> && dotnet build` printed `DENY`. After the fix all four print `DENY`.

The fix is one mechanism. `build_sites` now returns `Site(target, outputs)`; `dotnet_arguments` reads the words after
`dotnet` (stopping at a bare `--`, which also stops a program's own `.cs` argument being read as a project) and
`output_directories` resolves `-o`/`--output`/`--artifacts-path` against the directory the command runs in and an
`OUTPUT_PATH_PROPERTIES` value against the project directory; `build_places` adds each directory's working tree (or plain
directory) to the places the project graph gave. What the line does not say is UNKNOWN: a variable in the path, `@x.rsp`,
`-p:UseArtifactsOutput=`, a property value that climbs out of the project directory, and an environment variable MSBuild
reads as an output property (`OutDir=x dotnet build`, `export`, `$env:OutputPath =`). Decision on the second acceptance
item: `Directory.Build.rsp` and `MSBuild.rsp` join `IMPLICIT_IMPORTS` (a response file carries the same `-p:` switches),
checked in every ancestor directory, a superset of where MSBuild looks. The `#:property` check of a file-based app now
ignores case, like the other property reads. Self-test: 39 new `output:` cases (every spelling, a place inside a live
agent worktree, relative and unresolvable values, the `--` boundary, the environment arm, the response files); they fail
when `dotnet_arguments` is made blind to redirections.
