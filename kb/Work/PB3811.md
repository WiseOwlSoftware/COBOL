# PB3811 — a command-line output path escapes the scratch-build arm

**Sites:** `scripts/hooks/fleet_active_build.py#build_sites`, `scripts/hooks/fleet_active_build.py#build_places`, `scripts/hooks/fleet_active_build.py#OUTPUT_PROPERTIES`, `scripts/hooks/fleet_active_build.py#IMPLICIT_IMPORTS`, `scripts/hooks/test_fleet_active_build.py`

## Measured

The new scratch arm (PB3770) treats an output-path PROPERTY in a project file as UNKNOWN (`OUTPUT_PROPERTIES`,
`project_refs`) but not the same redirection on the command line: `build_sites` ignores `-o`/`--output`,
`-p:OutDir=`/`OutputPath=`/`BaseIntermediateOutputPath=` and `--artifacts-path`, so `build_places` reports only the scratch
directory. The module docstring and DESIGN-test-build-ci.md 1.7 both say a moved output path stays UNKNOWN.

Probe on the branch head (temp tree): an agent transcript whose first record has cwd `<main>/.claude/worktrees/wf_r-1`;
caller runs `cd <scratch>/probe && dotnet build -o <main>/.claude/worktrees/wf_r-1/src/App/bin/Debug/net10.0` (likewise
`-p:OutDir=<same>/` and `dotnet publish --output <same>`): `agents_sharing_any` returns no sharing agent, so the hook
ALLOWS a build that overwrites the binaries the live implementer executes. `cd <wf_r-1> && dotnet build` is DENIED, and at
base 70998ed98 the scratch builds were denied as UNKNOWN.

## Acceptance

- `build_sites` returns UNKNOWN (or adds the resolved output directory as a written place) for a dotnet step carrying
  `-o`/`--output`/`--artifacts-path` or a `-p:`/`-property:` whose name is in `OUTPUT_PROPERTIES`; self-test cases for each
  spelling, including a place inside a live agent worktree.
- Consider `Directory.Build.rsp` beside `Directory.Build.props`/`.targets` in `IMPLICIT_IMPORTS` (MSBuild reads it
  implicitly and it can carry the same `-p` switches); decide and record.
