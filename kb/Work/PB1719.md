# PB1719 — LANDED (PB1708 pivot M12)

Filed by the orchestrator from the PB1708 pivot design (workflow wf_08642598-d3c, reviewed APPROVE_WITH_CHANGES, all eleven findings resolved by the reviser), 2026-09-28.
## Mechanism (`docs/rearchitecture/DESIGN-test-build-ci.md` section 3.14.3, section 3.14.9 row M12)

`tests/_shared/GateLegs.cs` is linked into the three test projects. `ImpactTestFramework` derives from it, and the
shared attribute is compiled out under `IMPACT_RECORDING`. With no handshake, every assembly behaves as today. With a
full handshake, the assembly runs exactly its leg's cases. A partial or stale handshake makes every case an execution
error, so the run is RED; b3 showed xunit catches a constructor throw and would run every case green. Each leg writes
an identity record. `ParenTokenTwinDriftTests` takes a repository-relative path argument, so that no display name
carries the repository root.

## Acceptance

- With no handshake, counts and verdicts are unchanged.
- With a full handshake, each leg's trx definitions are exactly its cases, and the union equals `--list-tests`.
- Each partial handshake is RED.
- A planted non-permutation throws.
- A recording at HEAD still records every test.

Depends on PB1717 (M11, the plan format).

## Built (wave 71 group F, 2026-09-28)

**Built** from `DESIGN-test-build-ci.md` section 3.14.3 and the M12 row of 3.14.9. The design was corrected in the
same change (see below).
- `tests/_shared/GateLegs.cs` (the `_shared` glob in `tests/Directory.Build.props` links it into every test project,
  so no `.csproj` changed). It holds `GateTestFramework` and its executor, which resolves the handshake once per run.
  With none of the three variables set it runs every case in xunit's order. With a consistent set it runs the leg's
  cases, in rank order, through the plan's orderers, and writes the identity record first. Anything else, including a
  defect while choosing the cases, turns every case into an `ExecutionErrorTestCase`. `GateNameKey` mirrors
  `gate_plan.py#name_key`. `GatePlan.Parse` reads schema 1 and refuses a plan that names no entry for the assembly
  or puts one key in both legs. `GateAssemblyPlan.LegOf` and `RankOf` are the leg function and the rank. The
  orderers check that their output is a permutation (`GateOrder.Permutation`). `GateIdentityRecord` writes
  `leg-<n>-<assembly>.json`.
- `tests/Directory.Build.props` writes the framework attribute for every project with `IsTestProject`, by
  `$(AssemblyName)`. xunit resolves the attribute by assembly name and silently falls back to its own framework on
  a miss. The attribute is dropped when `DefineConstants` holds `IMPACT_RECORDING`, which
  `tools/impact/ImpactRecording.targets` now defines. `ImpactTestFramework` derives from `GateTestFramework` and
  overrides only `WrapMessageBus`; its own executor and runner were deleted, so one executor remains.
- `ParenTokenTwinDriftTests` rows are `(project, repository-relative path)`. The 404 root-carrying Unit names are
  gone.
- `tests/_shared/GateLegAudit.cs` holds the per-assembly arms (4) and (5). `GateLegDriftTests` in Unit covers arms
  (1) and (2): the name key, the leg function, C#/Python parity through `gate_plan.py` itself, the permutation check
  against five planted non-permutations, and the orderers' plan order. It also covers every handshake arm and arm
  (4)'s structural half over every test `.csproj`. In Conformance and Characterization it covers (4) and (5).

**Design corrections** (rule 5; recorded in 3.14.3, 3.14.4 and 3.14.9):
- The attribute lives in the props file, not in a linked source file, because it must name the assembly.
- The orderers are installed by the executor's runner under a plan only, not as assembly attributes. The runner also
  receives the leg's cases in rank order, because xunit orders a collection's classes by first arrival.
- The refusal arms were widened to cover a wrong schema, a missing assembly entry, a key in both legs and any failure
  while choosing the cases.
- Arms (4) and (5) are per-assembly.

Linux, so only the planted-offender witness is platform-bound.

**Fix owed.** The witness must fire on every CI host. Two ways to do that:
- plant a root native to the running OS;
- stop `RootCarrying` normalizing through the host's path rules.

Either way the fix re-lands with the rest of this cluster. `GateLegAudit.cs` line 48 also joins two statements on
one line, which should be cleaned up in the same change. The M13 handoffs from this cluster's report are recorded in

## Landed (wave 72 group G, 2026-09-29): the Linux red fixed at its root

Group G cherry-picked `26fc0b85a` onto main and reproduced the red with the WSL unit leg:
`Arm5_TheRootAudit_FiresOnPlantedOffenders`, `Expected: 3, Actual: 0`. Then it fixed both halves.

- **The audit** (`GateLegAudit.RootCarrying`) matches the root as TEXT, in three forms: as written, with every `\` as
  `/`, and with every `\` doubled the way xunit escapes it. It no longer goes through `Path.GetFullPath`, which treats
  `E:\…` as RELATIVE on Linux. An empty root throws, because the empty string is contained in every name. The
  statement joined onto line 48 was split out.
- **The witness** is a theory over three roots, and each runs on every host:
  - `windows` (`E:\COBOL-wt\battery87`);
  - `posix` (`/home/runner/work/COBOL/COBOL`);
  - `host`, this run's own `TestRepo.Root`, which is the form real on the OS the test runs on. It is resolved
    inside the test, because as an argument it would put the root into the case's own name.

  For each root it checks the exact offender list: escaped, slashed, and a truncated name whose root survives only in
  its argument. It also checks that the clean case is excluded.
- **Sweep for the same Windows-only assumption.** It covered `GateLegs.cs`, `GateLegAudit.cs`, the three
  `GateLegDriftTests`, `ParenTokenTwinDriftTests` and `ImpactTestFramework.cs`, looking for drive letters,
  backslashes, `GetFullPath` on a literal, `DirectorySeparatorChar` and case-insensitive path comparison. Nothing
  else is host-bound:
  - `GateIdentityRecord.PathFor` applies `GetFullPath` to the host's own `COBOLNET_GATE_PLAN`, which is native, and
    the plan is read through the same relative resolution;
  - `ProductAssemblies` compares two strings derived from one directory listing.

**Found on the way (the Linux gate itself)**, and fixed in this change set because it blocked the I8 gate:

  `.gitattributes` now keeps `*.sh` LF.
- `linux-gate.sh` exports `GIT_DIR`/`GIT_WORK_TREE` for a Windows-made worktree. `gate_slot.py --self-test` inherited
  them, so its `init`, `commit --allow-empty -m self-test` and `worktree add` acted on the REAL repository:
  - a `self-test` commit landed on this branch (reset away);
  - a `/tmp` worktree was registered (pruned);
  - `core.worktree` was written into `E:/COBOL/.git/config`. The agent's sandbox refused to edit that shared
    file. It was reported to the orchestrating session and was gone by 10:11 PDT.

  Both in-repo self-tests that build their own repositories (`gate_slot.py`, `status_guard.py`) now drop every
  variable `git rev-parse --local-env-vars` names. `linux-gate.sh` is RED (`repository-written`) when `HEAD` or
  `core.worktree` changed during its legs. Recorded in `DESIGN-test-build-ci.md` section 3.15.
