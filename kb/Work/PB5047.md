# PB5047 - at --std 85 a SUM identifier-1 naming a SOURCE or VALUE report entry is accepted

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/ReportSectionBinder.cs` and `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.Reports.cs`, `ScreenRolledAddend`, `src/WiseOwl.Cobol.Editions/Diagnostics/DiagnosticCatalog.cs#ReportSumAddendNotSumCounter`.

**Found.** `§1985:XIII.3.19.3 SR1` requires the report-entry identifiers of a SUM clause to be sum counters (its sentence "If the UPON phrase is omitted, any identifiers in the associated SUM clause which are themselves sum counters must be defined either in the same report group ..." passes `cite.py --check`). At `--std 85` a SUM identifier-1 that names a SOURCE or VALUE report entry (not a sum counter) is accepted. The exact SR1 sentence that requires a sum counter is to be re-derived and `cite.py --check`ed by the implementer before it enters code.

**Owed.** Refuse it at 85, pin it with a golden, and sweep the other editions' arms in `ScreenRolledAddend`, `src/WiseOwl.Cobol.Editions/Diagnostics/DiagnosticCatalog.cs#ReportSumAddendNotSumCounter`.

**Landed.** Re-probe on the build: before the fix the golden source compiled at --std 85. Now COBOL6764 (ScreenRolledAddend, gated by Edition.DialectLevel < 2002, data is not a ReportSumFamily) refuses it at 85 only; 2002+ compile and run. Goldens: conformance 13.18.54-SUM/pb5047_report_sum_names_source_entry (accept 2002+) and negative pb5047-sum-addend-source-entry.
