# PB306 — the XML doc quotes the rule the code does not implement

## The rule

§15.18.4 r2: *"If argument-1 is of class **or usage** national, the function will return a national value"* — and
the §15.18.1 result-type table says the same in two rows, *"Numeric usage National → National"* and *"Boolean
usage National → National"*. §13.18.60.3 SR12 makes `PIC 9(4) USAGE NATIONAL` and `PIC 1(4) USAGE NATIONAL` legal
data items. A national sending operand into an alphanumeric receiving operand is **No** in Table 16, reached by
§14.9.25.3 SR10, so the MOVE below requires a diagnostic — the same `COBOLNET0819` "national sending operand"
that `conformance:negative/pb15-concat-national-result-to-an` already pins for the **class** limb.

## Repro

```cobol
       IDENTIFICATION DIVISION. PROGRAM-ID. L1CATUSGN.
       DATA DIVISION. WORKING-STORAGE SECTION.
       01 NN1 PIC 9(4) USAGE NATIONAL VALUE 1234.
       01 NN2 PIC 9(4) USAGE NATIONAL VALUE 5678.
       01 RX  PIC X(20).
       PROCEDURE DIVISION.
           MOVE FUNCTION CONCAT(NN1 NN2) TO RX.
           STOP RUN.
```

Boolean twin: `01 NB1 PIC 1(4) USAGE NATIONAL.` / `01 NB2 PIC 1(4) USAGE NATIONAL.`, same MOVE.

## Status: LATENT, not a live wrong answer — and the verdict deliberately does not change

Today the repro fails EARLIER, at bind, because the **data shape** is declined: `PictureAnalyzer.cs:211` raises
`DiagnosticCatalog.NationalData` for the boolean form and `:252` the numeric twin, with `DataBinder.cs:3181` doing
the same for the group-inherited form. `RV-15.18.4-2` is closed on its reachable (class) limb, and correctly.
**That upstream decline is the only thing making the row safe.**

## Root cause

`IntrinsicResultType.cs`:

```csharp
IntrinsicResultRule.FollowsConcatArguments =>
    CategoryOf(args, 0) is PicCategory.National ? IntrinsicType.National : IntrinsicType.Alphanumeric
```

— the **CATEGORY** only. `OperandCategory`'s field arm returns `f.Place.Item.Pic?.Category`, and `PicCategory`
carries no usage, so a `PIC 9(4) USAGE NATIONAL` item answers `Numeric` and a `PIC 1(4) USAGE NATIONAL` item
answers `Boolean` — both falling to the `Alphanumeric` arm. The same file's own XML doc **quotes r2's "class or
usage" sentence and states the rule is keyed on class and usage**: the comment and the code disagree, which is why
no reader caught it.

## Why it must be fixed before the Phase-4a national-form residue lands

The moment that residue lands, the upstream decline goes away and this becomes the exact PB15 silent
under-rejection again: a national result labelled alphanumeric walks straight through the Table-16 MOVE guard.

## The fix

Have `FollowsConcatArguments` consult `IntrinsicArgumentRules.StaticUsageOf` — which `CheckConcatArgs` in
`IntrinsicBinder` **already uses** for §15.18.3 r2 — or give the operand classifier a usage-aware companion, so
ONE reader answers "class or usage national" for both the argument screen and the result type. Land the repro
above as a negative golden **with** the residue, so the gate cannot go green on an unreachable branch.

## Landed

Wave 56 (implementer w56c, 2026-09-23). ⛔ **RE-PROBE OVERTURNED THE "LATENT" STATUS: the defect was LIVE.** The
upstream decline the note relied on (`PictureAnalyzer` / `DataBinder` raising NationalData for `PIC 9/1 USAGE
NATIONAL`) is gone on today's tree: the note's repro `MOVE FUNCTION CONCAT(NN1 NN2) TO RX` (NN1/NN2
`PIC 9(4) USAGE NATIONAL`, RX `PIC X(20)`) compiled clean and ran, printing `[12345678            ]` — the PB15
silent under-rejection on the usage limb. The boolean twin (`PIC 1(4) USAGE NATIONAL`) did the same, and so did
`MOVE FUNCTION BASECONVERT(NN1 10 16) TO RX` (`[4D2 ...]`) — the FollowsArgument1 sibling arm.

* `cite.py --check`: OK §15.18.4 2); OK §15.18.3 2); OK §13.18.60.3 12); OK §14.9.25.3 10); OK §15.12.3 1).
* ONE reader: `IntrinsicResultType.IsNationalArgument` — category national OR `IntrinsicArgumentRules.StaticUsageOf`
  national (the same usage reader `IntrinsicBinder.CheckConcatArgs` applies for §15.18.3 r2). Both
  `FollowsConcatArguments` and `FollowsArgument1` read it, so the argument screen and the result type cannot
  disagree about "class or usage national".
* ⚠ DETERMINATION (BASECONVERT): §15.12.1's table has only "Alphanumeric → Alphanumeric / National → National",
  while §15.12.3 r1 admits "a usage display or national data item"; a `PIC 9 USAGE NATIONAL` argument is read as
  argument type National (its characters are national characters, and CONCAT's table states the usage rows
  explicitly). Rejected reading: typing it Alphanumeric by its numeric category. For every other FollowsArgument1
  function the argument-class rules exclude a usage-national item that is not class national, so nothing changes.
* After: all three MOVEs to PIC X are COBOLNET0819; to PIC N they run: `[12345678  ]`, `[10100011  ]`, `[4D2  ]`.
* Goldens: `conformance:2023/pb306_concat_usage_national` (positive, r1 values over the numeric- and
  boolean-usage-national rows + BASECONVERT), `conformance:negative/pb306-concat-usage-national-to-an` (reject-at 2023,
  COBOLNET0819 "national sending operand").
