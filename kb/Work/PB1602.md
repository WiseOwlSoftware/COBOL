Filed 2026-09-26 by the **train-61 lander** from the w61d implementer report (PB1192/PB690/PB1098).

## Repro
`scratchpad\w61d\probe\sup.cob` (orchestrator session scratchpad): an indexed file with
`ALTERNATE RECORD KEY IX-A SUPPRESS WHEN "€€"`; OPEN OUTPUT, WRITE, CLOSE, then OPEN INPUT → status **`39`**
(`REOPEN 39`). Expected: `00` — the attributes the program declares are the ones it wrote.

## Mechanism
`src/Cobol.Net.Runtime/IO/RecordFraming.cs#WriteHeader` encodes each key's suppress value with
`Encoding.Latin1.GetBytes(k.Suppress)` and `DecodeHeader` reads it back through Latin-1. A character above U+00FF
becomes '?', so the decoded header's SUPPRESS value differs from the declaration and the fixed-file-attribute
comparison at OPEN (§12.4.5.3 1) k) — the same alternate record keys) fails with '39'.

Same family as PB690 (lossy Latin-1 at the store boundary), different artifact: this is header METADATA, not record
content, so the fix is a header-format question (encode the suppress value as UTF-16 / length-prefixed, with a format
version bump), not the record character-set refusal PB690 landed.

## Landing (2026-09-27)

**Fix.** The store header is now format VERSION 2. `RecordFraming.WriteCodeUnits`/`ReadCodeUnits` write the
SUPPRESS WHEN value as its exact UTF-16 code units, each little-endian, behind an Int32 count biased by one (0 = no
phrase). An `Encoding` was avoided on purpose: it replaces a lone surrogate, and `NX"D800"` is a legal national
literal. Version-1 stores are Foreign, so they are refused with '39'. No version-1 reader is kept (zero back-compat
baggage), and `COBOLNET_FILES_DESIGN.md` says so. Citations used: §12.4.5.6.3 7) and §12.4.5.3 1) k), both
checked with `cite.py`. The GR number on "§14.9.27.4 GR10" was not re-derived, so the golden cites only §14.9.27.4.
**Golden.** `2023/pb1602_suppress_value_beyond_latin1`: alphanumeric `"€€"`, national `N"€€"` and `NX"D800"` keys;
OPEN OUTPUT, WRITE, then reopen INPUT, READ and reopen I-O, all '00'. The unit test
`FixedFileAttributeFormatTests` pins version byte 2.

Citation to re-derive at implementation: the w61d report cited "§14.9.27.4 GR10" (OPEN); run
`python scripts/spec/cite.py --check` on the rule actually used before it enters code.
