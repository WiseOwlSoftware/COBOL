# PB4058 — the build guard misses sibling spellings and verbs that write bin/obj

**Sites:** `scripts/hooks/fleet_active_build.py#PROPERTY_OPTION_RE`, `scripts/hooks/fleet_active_build.py#OUTPUT_PATH_PROPERTIES`,
`scripts/hooks/fleet_active_build.py#OUTPUT_PROPERTY_RE`, `scripts/hooks/fleet_active_build.py#BUILD_VERBS`,
`scripts/hooks/fleet_active_build.py#is_build_command`, `scripts/hooks/fleet_active_build.py#project_refs` (docstring),
`scripts/hooks/fleet_active_build.py#self_test`

PB3811 taught the guard to read an output path given on the command line. The review of that landing found three gaps in the
same mechanism (the guard decides from what the command and the project files say about where a build writes):

1. `PROPERTY_OPTION_RE` matches `-p`/`-property` but not MSBuild's `-restoreProperty:`/`-rp:`, which move restore output.
2. `OUTPUT_PATH_PROPERTIES` (and so the project-file `OUTPUT_PROPERTY_RE`) lacks `MSBuildProjectExtensionsPath` and
   `RestoreOutputPath`, the properties that move `obj/` restore assets.
3. `BUILD_VERBS` omits `pack` and `restore`. `dotnet pack` builds by default and `dotnet restore` writes `obj/`, so
   `is_build_command` never consults the guard for them and the output-path reading never runs.
4. The `project_refs` docstring says a `Directory.Build.*` file stops the graph, although `IMPLICIT_IMPORTS` now also holds
   `Directory.Build.rsp` and `MSBuild.rsp`.

## Acceptance

- Each of the three spellings or verbs above is denied when it targets a live agent's worktree, with a self-test case that
  fails before the change; a `pack` and a `restore` case for the verb gap.
- The docstring names the files `IMPLICIT_IMPORTS` holds (derive from the constant, not a second list).
- Sweep: every other MSBuild switch and verb that writes `bin/` or `obj/` (`dotnet build-server`, `vstest`, `watch`,
  `-getProperty`) is decided and recorded.
