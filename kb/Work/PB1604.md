Filed 2026-09-26 by the **train-61 lander** from the w61f implementer report (PB1276/PB1277).

## Repro
```
FD F RECORD IS VARYING IN SIZE.
01 R. 05 A PIC X(2). 05 T OCCURS DYNAMIC FROM 2 TO 5. 10 E PIC X(3).
```
→ `VaryMax` = 2 while `VaryMin` = 8: every WRITE of R is out of range.

## Mechanism
`src/Cobol.Net.Compiler/Binding/Model/FileModel.cs#MaxDynamicExtent` takes a table's maximum from
`item.OccursSpec?.Max ?? 0`, and `DataBinder.Odo.cs:70` binds `Max = 0` for OCCURS DYNAMIC (no integer-5), so the
table adds nothing to the maximum. §13.18.43.4 8) b) (`OK §13.18.43.4 8)` in the w61f report) sizes the maximum
record from the maximum size of each item, and §8.5.1.9 gives a dynamic-capacity table an implementor-defined
MAXIMUM CAPACITY when TO integer-5 is absent (here `TO 5` is present and is still ignored).

## To close
Needs a maximum-capacity determination for `OCCURS DYNAMIC` without `TO` (shared with PB1410, which has no runtime
maximum either: only the constant `MaxOccurrences`), then one maximum read by both the record-sizing model and the
runtime. Not PB1277's unit (its landing was the byte model).
