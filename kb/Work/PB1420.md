# PB1420 — LANDED (wave 1009, group C)

Re-probed on the wave's own build: r1, r2 and r3 all reproduced (`CONCAT(INTEGER(3) "A")`, `CONCAT(ABS(3) "A")`,
`BASECONVERT(INTEGER(10) 10 16)` compile clean and abort with `intrinsic string argument 'BoundComputedOperand'`), and so did
the RANDOM half (`RANDOM(FUNCTION SQRT(4))` compiled). Three faces of one rule family, fixed at the root in
`IntrinsicArgumentRules`:

1. **SR12 had no screen** (`cite.py --check 8.4.3.2.3 "An integer function other than the integer form of the ABS function
   shall not be specified where an unsigned integer is required"` -> OK, rule 12). `IntrinsicArgumentRules.UnsignedIntegerViolation`
   is type-based like SR11's `IntegerViolation` (an integer function but the integer form of ABS, and any numeric function, is
   barred). It is asked at the two intrinsic positions that say "unsigned integer" and admit a function-identifier: CONCAT
   §15.18.3 r3 (`IntrinsicBinder.CheckConcatArgs`, COBOLNET1627) and BASECONVERT §15.12.3 r1 below base 11
   (`CheckBaseConvertArgs`, COBOLNET1642). The sweep of §15 for "unsigned" found no third intrinsic position; the statement
   operands that print "unsigned integer data item" (§14.9.1.3 SR5, §14.9.11.3 SR3, ACCEPT/DISPLAY LINE and COLUMN) are the
   screen facility, not claimed (PB260).
2. **The integer-position table was hand-maintained.** §15.6 Table 21 types RANDOM's argument and COMBINED-DATETIME's argument-1
   `Int`; both Verified rows said class numeric, so SR11 never ran on them. Both are kind `i` now, and
   `IntrinsicArgumentClassDriftTests.EveryTable21IntegerPosition_IsTypedInteger_InTheVerifiedTable` DERIVES every Int-only operand
   position from the standard's own table (37 positions; it found exactly those two, BASECONVERT excepted with its reason; proven
   to fail by reverting RANDOM to `n`).
3. **`StrArgVisitor` rendered a nested numeric function as `LoudValue`**, so the SR12-EXEMPT integer form of ABS (legal source)
   aborted at run time. The numeric-admitting visitor (CONCAT and BASECONVERT only, the pinned caller set) now renders it through
   `OperandText.AsString`, the one numeric-function text image (DOC-A.1-92): `CONCAT(ABS(-3) "A")` = `3A`.

## Finding — `function-identifier` (crashes; rows `SR-8.4.3.2.3-12`)

**Mechanism.** SR12 has no screen anywhere, and the numeric-admitting string-argument renderer (IntrinsicRenderer.StrArgVisitor, admitNumeric) renders a nested NUMERIC or INTEGER intrinsic as a LoudValue. So FUNCTION CONCAT / BASECONVERT over a nested integer function compiles clean and aborts at run time, both for the SR12-barred INTEGER form and for the SR12-exempt ABS form.

**Repro.** out/probe/function-identifier/r1_sr12_concat_int.cob: MOVE FUNCTION CONCAT(FUNCTION INTEGER(3) 'A') TO W -> compiles, run -> NotImplementedCobolFeatureException 'intrinsic string argument BoundComputedOperand'. r2_sr12_concat_abs.cob: CONCAT(FUNCTION ABS(3) 'A') -> same crash. r3_sr12_base_int.cob: BASECONVERT(FUNCTION INTEGER(10) 10 16) -> same crash.

**Expected from the spec.** §8.4.3.2.3 SR12: an integer function other than the integer form of ABS shall not be specified where an unsigned integer is required, and §15.18.3 r3 requires a numeric CONCAT argument to be an unsigned integer. So r1 and r3 are COMPILE-TIME errors, and r2 (ABS, exempt) is legal and yields W = '3A' (the §15.18.4 concatenation of the integer image and 'A').

**Observed / reasoning.** StrArgVisitor.Visit(BoundComputedOperand) renders only nested intrinsics whose ResultCategory is Alphanumeric, National or Boolean, and every other case (numeric or integer functions) becomes Loud(n). The binder admits the argument (class numeric is in CONCAT's list), so the failure surfaces at the wrong stage: the PB25 wrong-stage family, on an unowned shape. Two fixes are needed together: an SR12 screen at the unsigned-integer argument positions (sharing IntrinsicArgumentRules' type-based SR11 arm), and a numeric-function arm in StrArgVisitor for the legal ABS case.

**Code site.** src/Cobol.Net.Compiler/CodeGen/Emit/IntrinsicRenderer.cs#StrArgVisitor.Visit(BoundComputedOperand); src/Cobol.Net.Compiler/Binding/IntrinsicArgumentRules.cs (no SR12 arm)

### `SR-8.4.3.2.3-11` — PARTIAL (adjudicator + refuter record, verbatim)

SR11 (cite.py --check 8.4.3.2.3 'A numeric function shall not be specified where an integer operand is required' -> OK §8.4.3.2.3 11)). The screen is on the function's TYPE (IntrinsicResultType.Resolve == Numeric), not on its value. Probes: out/probe/function-identifier/r4_sr11_char.cob FUNCTION CHAR(FUNCTION SQRT(4)) -> COBOLNET1627 citing SR11; p1_sr11_perform.cob PERFORM X FUNCTION SQRT(4) TIMES -> COBOLNET1646. A user-defined function's temp is screened by its cloned RETURNING description (the NonIntegralItemReason field arm). The GO TO DEPENDING position (r5) refuses the numeric function too, but only because it refuses EVERY function-identifier at parse. That is a separate lead (see findings), and SR11's own outcome is correct there. || REFUTED: PARTIAL — The screen is sound where the argument table marks an integer slot (i). It fires for MOD (both arguments), FACTORIAL, CHAR, CHAR-NATIONAL, DAY-OF-INTEGER, INTEGER-OF-DAY, TEST-DAY-YYYYDDD, TEST-DATE-YYYYMMDD, YEAR-TO-YYYY (both), FORMATTED-DATE argument-2, PERFORM TIMES, and a user function with a PIC 9V9 RETURNING. Integer functions (INTEGER, INTEGER-PART, ORD-MAX, MAX of integers) pass. But the integer-operand positions come from a hand table that misses RANDOM: 15.75.3 rule 2 requires argument-1 to be zero or a positive integer, the same requirement FACTORIAL 15.36.3 r1 has and is screened for, yet RANDOM is typed class-numeric only, so FUNCTION RANDOM(FUNCTION SQRT(4)) compiles. Separately, WRITE ADVANCING, DISPLAY AT LINE and GO TO DEPENDING refuse every function at parse (over-rejection, a separate lead), so SR11 is not really exercised in those slots.

## What the fixer owes

Add the SR12 arm to IntrinsicArgumentRules, derive integer positions from the §15 argument rules (RANDOM 15.75.3 r2), and give StrArgVisitor a real rendering for the SR12-exempt integer ABS form (or refuse at bind time) — no LoudValue reachable from legal source.
