# PB4409 — a compiler change runs no script self-tests

**Owner decision (2026-11-01, Mythos session).** Shown that a compiler change's gate spends 10 to 38 minutes on script
self-tests, the owner answered: **"I see no reason why a compiler change should need to run script self-tests."**

**The measurement.** The PB4097 gate (runtime file I/O, worktree wf_01545e8c-f44-38, run 000002-20261101T212724Z) changed
`docs/CONFORMANCE.md`, a `TOOLING_READS` entry, so `inert_lane.classify` set the tooling flag in the full lane: the
SELF-TESTS audit ran 16 self-tests in 1,613 s and the post-build `--built` one in 644 s, beside 2,575 s of tests and after
1,837 s of slot wait (cap 6 that afternoon). On a quiet box the integration gate of #991 spent 535 s in audits against
436 s of tests: the self-tests, not the compiler tests, were the long pole.

**The change: two flags, one per consumer.** `inert_lane.Lane` carries `tooling` (the LOCAL gate's: in the full lane
`is_script_tree`, a TOOLING_UNDER tree or a TOOLING_SUFFIXES file, never a TOOLING_READS data file) and `reads_tooling`
(CI's: `is_tooling`, a script or a TOOLING_READS entry, the full-lane flag as it was before this decision). `tooling`
implies `reads_tooling`; the tooling lane and an empty or unlistable change set both, the inert lane neither, and `Lane`
refuses any other shape. `classify` prints `reads_tooling=` beside `tooling=`. The local gate's SELF-TESTS audit and its
post-build self-tests read `tooling`, so a compiler change that edits only a data file a self-test reads (docs/CONFORMANCE.md,
TestRepo.cs, the grammar, docs/REARCHITECTURE_PLAN.md) runs none; one that also edits a script still runs that half.
CI's `changes` job outputs `reads_tooling` and `windows-self-tests` runs on it, so the ~20 Windows-only self-tests
(`test_orchestrate_*.ps1`, `test_autostart.ps1`, ...) still run in the merge group whenever such a file changes (review
R1-1: the first version narrowed CI's flag too, and those self-tests would have run on no per-change run); the Linux
`audits` job runs every self-test in every merge group. CLAUDE.md "Testing" adds that first run to THE RULE's class (d).
Self-test arms in `inert_lane.py`: both flags on CONFORMANCE.md, TestRepo.cs, REARCHITECTURE_PLAN.md and a script, the
lane shapes `Lane` refuses, and the wiring arm (the `changes` job's `reads_tooling` output and the job's `if:`). The gate
skill, MANDATORY-PRACTICES I1, DESIGN-test-build-ci.md (the tooling flags), `gate.py`'s comments and the workflow's
comments say it.

**Also, same day:** the gate slot cap returned to its coded default 3 (owner choice), after 6 slots made that PB4097
gate wait 31 minutes and its test phase take 43 minutes against 7 on a quiet box.
