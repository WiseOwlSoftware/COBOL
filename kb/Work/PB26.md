# PB26 — OPEN — the ambient EC-ARGUMENT-FUNCTION gate is a HAND-MAINTAINED SWITCH

> ⚙ **flags:** wrong-answer · silent
> A domain guard such as LOG10's raises only when `ExceptionState.ArgumentFunctionChecking` is set, and that
> ambient gate is emitted **only for the statement kinds enumerated in `EcBinder#DirectIntrinsic`'s hand-written
> `switch`** — so the identical function reference raises in one statement and is silent in another. That is a
> hand-maintained list where a STRUCTURE belongs (CLAUDE.md rule 5), and it is the general form of the
> receiver-shape defect PB13 hit: **an exception's reachability must not depend on which statement encloses it.**

## ⛔ THE GOVERNING RULE, WHICH THE ENTRY DID NOT CITE

**§15.3 item 14** — *"If the evaluation of an argument results in an incorrect value for that argument or for the
returned value according to the rules specified in the function definition and no exception condition was raised
during item identification or expression evaluation, the EC-ARGUMENT-FUNCTION exception condition is set to
exist."* Read what it qualifies on: **the function reference**. There is no statement-kind qualification anywhere
in it, so the entry's instinct was right and now has a citation. (§15.56.3 AR2 gives the probe its violation:
LOG10's argument "shall be greater than zero".)

## 📐 MEASURED BEFORE (at `d88170ab`) — `FUNCTION LOG10(0)` under `>>TURN EC-ARGUMENT-FUNCTION CHECKING ON`

`COMPUTE` ✅ raised · `MOVE` ✅ · `DISPLAY` ✅ · `IF` ✅ · nested argument ✅ · **`STRING` ❌ SILENT** ·
**`UNSTRING` ❌ SILENT** · **`PERFORM UNTIL` ❌ SILENT**. The identical reference, a different verb.

## ✅ THE FIX — the list became a structure

`BoundStatementTree.OwnValueParts` is now GENERATED from the Roslyn semantic model beside the existing
`StatementChildren`, by reading every property of every statement leaf (through lists and single-depth helper
records). `EcBinder.DirectIntrinsic` is one line over it. A statement kind added tomorrow is covered without an
edit here.

⚠ **THE FIRST CUT WAS WRONG IN THE SAME SHAPE IT WAS FIXING, and that is the part worth keeping.** A
`[BoundNode]` root is not automatically a VALUE: `BoundPerformControl` and `BoundSetTarget` are CONTAINERS that
HOLD values. The first version yielded the container and stopped, so `PERFORM UNTIL FUNCTION LOG10(0)` stayed
silent — the same defect, one level in. The generator now emits a walker per container root, and
`BoundNodeRootPartitionDrift` pins the terminal/container partition so a NEW root forces a decision instead of
defaulting to silence.

**Guards:** `EcArgumentFunctionGateDriftTests` (three facts — the list-of-helper-records shape that broke, the
must-not-descend-into-nested-statements rule, and the root partition) and the behavioural golden
`tests/conformance/2023/pb26_ec_argument_function_every_statement`, which runs the violation through all eight
statement kinds. The unit guard was proven in the failing direction by disabling the helper-record branch in the
generator and watching it go red.

⚙ **Two findings fell out of the probe and are NOT part of this fix** — a function-identifier is still refused in
an `ADD` operand, an `EVALUATE TRUE` WHEN relation, and an `INSPECT … FOR ALL` operand. All three are legal source
under §8.4.3.1.2, and all three are [[PB45]].
