# PB999 — LANDED

## Repro — measured
`scratchpad/reg12/q03_log.cob`: `COMPUTE R = FUNCTION LOG10(1.0E-200 * 1.0E-200)` and `… FUNCTION LOG(…)` into
`01 R PIC S9(4)V9(4)`. Observed **`LOG10=0000000{`** and **`LOG=0000000{`** (zero). Expected −400.0000 and
−921.0340 (ln 10⁻⁴⁰⁰ = −921.03403…).

## The rule
`OK  §15.56.3 2)` — "The value of argument-1 shall be greater than zero." 10⁻⁴⁰⁰ is greater than zero; the argument is a
legal standard-decimal intermediate value (§8.8.1.5.2's range reaches far below binary64's ~10⁻³⁰⁸ — the registrar's §8.8.1.3 FAILED `cite.py --check`; corrected by wave 57), so the function must
return its logarithm (RV rows of §15.55.4 / §15.56.4).

## Code site
The LOG/LOG10 runtime bodies take `double` (`Log10(double x) => … Math.Log10(x)`); the argument's decimal value is
narrowed by ToDouble before the call.

## What the fixer owes
Compute the logarithm from the decimal's exponent and significand (log10(m·10ᵉ) = e + log10(m)) so no argument in the
SDIDI range underflows; LOG = LOG10 · ln 10. Sweep every intrinsic that narrows an argument to double before a
range-sensitive operation (EXP, EXP10, SQRT of tiny/huge values, the PB952 family).
