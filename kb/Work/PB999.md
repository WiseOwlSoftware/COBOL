# PB999 — OPEN

## Repro — measured
`scratchpad/reg12/q03_log.cob`: `COMPUTE R = FUNCTION LOG10(1.0E-200 * 1.0E-200)` and `… FUNCTION LOG(…)` into
`01 R PIC S9(4)V9(4)`. Observed **`LOG10=0000000{`** and **`LOG=0000000{`** (zero). Expected −400.0000 and
−921.0340 (ln 10⁻⁴⁰⁰ = −921.03403…).

## The rule
`OK  §15.56.3 2)` — "The value of argument-1 shall be greater than zero." 10⁻⁴⁰⁰ is greater than zero; the argument is a
legal standard-decimal intermediate value (§8.8.1.3's range reaches far below binary64's ~10⁻³⁰⁸), so the function must
return its logarithm (RV rows of §15.55.4 / §15.56.4).

## Code site
The LOG/LOG10 runtime bodies take `double` (`Log10(double x) => … Math.Log10(x)`); the argument's decimal value is
narrowed by ToDouble before the call.

## What the fixer owes
Compute the logarithm from the decimal's exponent and significand (log10(m·10ᵉ) = e + log10(m)) so no argument in the
SDIDI range underflows; LOG = LOG10 · ln 10. Sweep every intrinsic that narrows an argument to double before a
range-sensitive operation (EXP, EXP10, SQRT of tiny/huge values, the PB952 family).

## Train 53: dropped at landing — the fix collides with PB952's one domain screen
Wave 54 group I (branch `worktree-wf_e17d58be-cc0-9`, commit `00a0aa756`) built this fix on `57d36e4c6`, before
PB952 reached main. PB952 made `RuntimeApi.DomainArg` → `CobolIntrinsics.DomainScaled/DomainDec/DomainReal` THE
argument-1 domain screen (§15.3 rule 14) and REMOVED the `x <= 0` / `x < 0` tests from the LOG, LOG10 and SQRT
double bodies ("the runtime bodies carry no second test"). The branch's fix adds `Log/Log10/Sqrt(CobolDec)`
overloads that screen the domain THEMSELVES and a `MagnitudeSensitiveBodies` renderer arm that routes a Dec operand
to them AHEAD of the `DomainArg` arm — a second place deciding the same rule, and the double bodies' tests it
restores contradict PB952's. `git apply -3` conflicted in `IntrinsicRenderer.FloatBody` and
`CobolIntrinsics.Float.cs`, and the resolution is a design question, not a merge: `DomainDec` returns the
NARROWED binary64 (NaN on a violation), so the value half of this defect (10^-400 → +0.0 → −∞) is still open on
main, and the fix has to screen through the one screen while handing the body the UNNARROWED carrier (for example a
screen overload returning the admitted `CobolDec`, with the violation signalled the way `DomainDec`'s NaN is). The
branch's golden `pb999_log_sqrt_decimal_range` and its batch (`w54i\PB999\batch.json`) are the evidence to reuse.
Status stays `open`; the inventory rows stay claimed.
