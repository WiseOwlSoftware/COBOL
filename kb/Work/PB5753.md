# PB5753 - the 2023 repeated-parameter-name rule is applied at 2002

**Sites:** `src/WiseOwl.Cobol.Compiler/Oo/OoExpansion.cs` (`OoExpansion.Expand`): `Expand` passes the clause strings
`"ISO §2023:11.3.3 SR9"` (CLASS-ID) and `"ISO §2023:11.6.3 SR7"` (INTERFACE-ID) to its local function `AddSkeleton`, whose repeated-parameter-name screen issues COBOL2239 at every edition. The screen is not edition-gated.
The fix: `src/WiseOwl.Cobol.Compiler/Oo/OoExpansion.cs` (`OoExpansion.Expand` / `AddSkeleton`, `OoExpansion.HeaderRules`,
`OoExpansion.IsUserWordOccurrence`, `OoExpansion.UserWordOccurrences`, `OoExpansion.SubstitutedTokens`) and
`src/WiseOwl.Cobol.Runtime/Control/DialectBehavior.cs` (`DialectBehavior.ParameterNameAppearsOnceInUsingClause`).

**Repros** (`E:\COBOL-coord\scratch\gl2002\integrate-6\repro\`): `dupparm.cob` (the writer's,
`lane1\run\g2002u-11-3-factory\dupparm\`), `INTERFACE-ID. G2DUPI USING P P.` with `CLASS P.` in its REPOSITORY and one
prototype `PUT USING X`, X `OBJECT REFERENCE P`; and `dupclass.cob` (mine), `CLASS-ID. G2DUPC INHERITS FROM BASE USING P P.`

- `cobol.exe dupparm.cob --std 2002`: `(2,37): error COBOL2239: INTERFACE-ID 'G2DUPI' USING: the parameter-name 'P' is written more than once — a given parameter-name shall not appear more than once in a USING clause (ISO §2023:11.6.3 SR7)`, exit 65.
- `cobol.exe dupclass.cob --std 2002`: `(2,52): error COBOL2239: CLASS-ID 'G2DUPC' USING: ... (ISO §2023:11.3.3 SR9)`.

**The 2002 text.** §2002:11.5.2 has five syntax rules (SR1-SR5) and none forbids a repeated parameter-name; SR4:
"Parameter-name-1 shall be a name specified in a class-specifier or an interface-specifier in the REPOSITORY paragraph of
this interface definition." GR3: "The USING clause specifies that this is a parameterized interface. Parameter-name-1 is
the name given to the formal parameter."

- `python scripts/spec/cite.py --check "§2002:11.5.2 SR4" "Parameter-name-1 shall be a name specified in a class-specifier or an interface-specifier"` -> OK
- `python scripts/spec/cite.py --check "§2002:11.5.3 GR3" "Parameter-name-1 is the name given to the formal parameter"` -> OK

**Expected at `--std 2002`:** the program is accepted, or it is refused on a 2002 rule that the refusal cites (a reference
to P that is not unique, §2002:8.4.1, is the one candidate; which rule applies, if any, is this note's question).
**Observed:** refused on a rule that 2002 does not have, with a 2023 citation: either way a defect (a rule applied at an
edition without it, and a citation of the wrong edition). Rows: no 2002 row waits on it (2002-GR-11.5.3-3 closes on its
own witness). Each edition stands on its own text (kb/Work PB5574).

**Determination (2026-11-25, wave 20262171 F).** The repeated-parameter-name rule arrives in COBOL-2014: §2014:11.3.2 SR9 and
§2014:11.6.2 SR7 "A given parameter-name shall not appear more than once in a USING clause" (cite.py --check: OK). At 2002
`USING P P` names two formal parameters P (§2002:11.2.3 GR5, §2002:11.5.3 GR3), so the USING clause is accepted, and a
reference to P is the 2002 refusal: it identifies neither formal (§2002:8.4.1 "In order to use a resource, a statement shall
contain a reference that uniquely identifies that resource"; a parameter-name cannot be qualified), and an expansion would
have two "corresponding actual parameters" for it (§2002:12.2.7.3 GR5 / GR8). The references are exactly the occurrences an
expansion replaces, other than the formal's own REPOSITORY specifier (which §2002:11.2.2 SR9 / §2002:11.5.2 SR4 require and
which declares its kind).

**Landed.** `DialectBehavior.ParameterNameAppearsOnceInUsingClause` (VCR 7.129, from 2014) gates the USING-clause refusal;
below it `AddSkeleton` refuses each reference to a repeated formal, COBOL2239 citing §2002:8.4.1, through the substitution's
own occurrence predicate (`IsUserWordOccurrence`). Every header rule `AddSkeleton` cites (SR8 / SR4, SR9 / SR7, GR6 / GR4,
the EXPANDS-in-skeleton SR3) is now cited in the edition compiled under (`HeaderRules`). Re-probe of `dupparm.cob` /
`dupclass.cob` at 2002: COBOL2239 at the `OBJECT REFERENCE P` line citing §2002:8.4.1; at 2014: `ISO §2014:11.6.2 SR7` /
`ISO §2014:11.3.2 SR9`. Goldens `11.2@2002-CLASS-ID-PARAGRAPH/pb5753_repeated_parameter_name_2002` (accept 2002, refused
2014 and 2023) and `11.5@2002-INTERFACE-ID-PARAGRAPH/pb5753-repeated-parameter-name-referenced` (refused at every edition);
`ParameterizedClassTests` pins the citations per edition.
