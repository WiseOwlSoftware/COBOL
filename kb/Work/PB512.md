# PB512

## Mechanism — data-description-entry-p1
PICTURE, JUSTIFIED and BLANK WHEN ZERO are recorded on the entry with no group/elementary test. The entry ALREADY asks that question for GROUP-USAGE (13.18.29.3 SR1 -> COBOLNET1653, 'this entry has a PICTURE clause'), so the screen exists and these three clauses were never routed through it.

### Expected, from the standard
13.16.3 SR11: 'The PICTURE, JUSTIFIED, and BLANK WHEN ZERO clauses may be specified only for an elementary data item.' A group item carrying any of the three shall be rejected with a named diagnostic, in all four editions.

```
$ python scripts/spec/cite.py --check 13.16.3 "The PICTURE, JUSTIFIED, and BLANK WHEN ZERO clauses may be specified only for an elementary data item"
  OK  §13.16.3 11)  (Syntax rules)
```

### Observed
All three accepted at --std 2023 and --std 85. JUSTIFIED on a group is INERT -- the run is byte-identical to the twin without it, so the programmer gets neither the right-justified MOVE the clause names nor a diagnostic saying it is illegal. BLANK WHEN ZERO on a group is equally inert (G displays 000). The PICTURE leg is the dangerous one: the picture makes G elementary, BindEntries still attaches the 05 subordinates, the emitter then declares only `string G` and silently drops them, and the first reference to A surfaces as raw Roslyn CS1061 against generated C#. A group with TWO subordinates behaves the same (probe z_group_pic_multi).
