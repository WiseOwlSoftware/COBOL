# PB2146 — a second operand shape written three times, and a dead arm

Found by the PB2114 implementer (wave 1028 group D), filed by the train-1028 lander.

PB2114 named the `{identifier | literal}` sending operand once (`sendingOperand`). The identifier-only sending shape,
`functionCall | inlineMethodInvocation | dataReference`, is still written separately in three places:
`strUnstrSender`, `goToStatement`'s DEPENDING ON operand, and `inspectStatement`'s identifier-1.

Separately, `strUnstrOperand` (`src/Cobol.Net.Frontend/Grammar/Core/CobolIO.g4:1025-1031`) carries a
`figurativeConstant` arm that can never match, because `literal` comes first and already admits every figurative
constant (`nonNumericLiteral` → `figurativeConstant`). `StringUnstringBinder.cs:388` still reads it: the same dead
lookup PB2114 removed from INSPECT (`InspectBinder.InspectCharOperandOf`).

**Code sites:** `CobolIO.g4:1025-1031` (`strUnstrOperand`, `strUnstrSender`), `CobolParserCore.g4#goToStatement`,
`CobolParserCore.g4#inspectStatement`, `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/StringUnstringBinder.cs:388`.

**Fix shape:** one named rule for the identifier-only sending shape, read by every consumer, with a drift test like
`SendingOperandDriftTests`. Delete the dead `figurativeConstant` arm and its read, reaching figuratives through
`literal()` as INSPECT now does. Prove it with PB2114's token-stream and parse-tree differential, including error
trees.
