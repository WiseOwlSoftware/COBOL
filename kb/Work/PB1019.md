# PB1019 — LANDED

## Repro — measured
`scratchpad/w52e/lkf.cob` → `error: backend compilation failed … (60,55): error CS1003: Syntax error, '(' expected`,
CS1001, CS1026, CS1002, CS1519.

## Code site
`DataBinder.Ptr.cs` `PtrBindBasedAndAddressables` treats every `ADDRESS OF` target as a storage cell this program owns;
a LINKAGE formal's value lives in the caller's storage, so the forced cell's name is built from the formal's accessor
path. The OO path now refuses the same case with COBOLNET0869 (PB956's branch) — also wrong: `ADDRESS OF` a LINKAGE item
is the address of the argument.

## What the fixer owes
One addressable-formal mechanism for programs and methods: the address of a LINKAGE formal is the address of the
argument's storage (pin/handle through the carrier), with goldens for a program and a method; retire the 0869 refusal.

## Program arm landed (2026-09-22, wave 54 group B, worktree wf_e17d58be-cc0-2) — the note stays OPEN for the METHOD arm
Re-probed: `lkf.cob` reproduced exactly (CS1003/CS1001/CS1026/CS1002/CS1519). ⛔ The note's `spec_refs` carried
`8.4.3.1.2`, which is not the data-address-identifier clause — corrected to the §8.4.3.11 rules below
(`cite.py --check`: OK §8.4.3.11.3 1) "Identifier-1 shall reference a data item defined in the file section,
working-storage section, local-storage section, or linkage section"; OK §8.4.3.11.4 1) "…contains the address of
identifier-1"; OK §14.2.3 8)).
Fix: `DataBinder.CallBindLinkage` makes any formal named by an `ADDRESS OF` sender (the unit's own procedure
division or a contained program's — the SAME `PtrScanAddressOfSenders` scan the pointer pass forces cells from)
NON-resident, so it takes the boundary-copy arm every group formal already takes, over a callee-local cell;
the pointer pass then forces that cell like any other record. Golden `tests/conformance/2002/pb1019_address_of_linkage_formal`
(alphanumeric and numeric formals, a BY CONTENT argument, and a GLOBAL formal addressed from a contained
program); negative `tests/conformance/negative/pb1019-address-of-formal-at-85` (COBOLNET0900).
Known residue of the chosen shape (documented in COBOLNET_INTERPROGRAM_DESIGN): the formal's address is the
callee cell's, so it does not compare equal (§8.8.4.2.16) to the caller's `ADDRESS OF` the argument — the
group formals' boundary-copy limitation, now shared by addressed elementary formals.
OPEN: the METHOD arm. On this base a class unit's `ADDRESS OF` stages COBOLNET0899 (`OoBasedInClass`); PB956 (in
train 52, not on this base) replaces that and refuses a method formal's address with COBOLNET0869. The finisher
applies this same residency rule to `OoFormal` once PB956's OO cell emission is on main.

## Method arm landed (2026-09-22, wave 55 finisher A, worktree wf_aaa1a00f-895-2) — the note is CLOSED
