# PB4337 — nothing reads `DefaultConfig` through `CollationRuntime.Initialize`

**Found 2026-10-31** by the round-2 reviewer of the PB380 finisher (wave 20261791 group B, branch
`worktree-wf_15d43d1b-129-9`, report `E:\COBOL-coord\scratch\reports\w20261791b-PB380-report.md`, finding R2-1, a LEAD,
low, not blocking).

**Sites:** `src/WiseOwl.Cobol.Runtime/Collation/CollationRuntime.cs:105` (`CollationRuntime.s_cacheConfiguration`,
`CollationRuntime.Initialize`). The test belongs beside `CollationRuntimeInitializeTests`, a class that exists only
on branch 129-9 so far.

**What the report found.** On branch `worktree-wf_15d43d1b-129-9` the race test was moved onto a fresh
`CacheConfigurationLatch`, which left the runtime's own wiring,
`s_cacheConfiguration = new(config => CollationKeyCache.DefaultConfig = config, CacheConfig.FromEnvironment)`
(`CollationRuntime.cs:105`), with no test. The round-1 test drove `CollationRuntime.Initialize` with
`COBOL_COLLATION_CACHE` set and read `CollationKeyCache.DefaultConfig`; `TheRuntimeInitialize_Publishes_ItsLatch`
checks only `IsInitialized`; no other test reads `DefaultConfig` through the runtime.

**Two PB380 fixes are in flight, and this note applies to whichever design lands.** PR #934 (branch
`worktree-wf_e6e34c8b-638-1`) and branch `worktree-wf_15d43d1b-129-9` both fix PB380 (see PB4345). The `:105` site and
the wiring text above are quoted from 129-9; the implementer re-checks the site on main (what #934 left there) before
writing the test, and the test must read `DefaultConfig` through `CollationRuntime.Initialize` in whichever shape main
holds.
