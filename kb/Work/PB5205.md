# PB5205 - the populations are a step keyed by their inputs

**Sites:** `scripts/gate.py` (`Host.population_key`, `population_digest`, `populations_green`, `Carry`, `Gate.carry`,
`Gate._gate`, `Gate._composed`, `Gate._retry`, `Gate._tested`, `Gate._run_hosts`, `_Live.stopped_any`, `Gate._record`, the
`FakeHost` and the self-test's composition arms); `scripts/inert_lane.py` (`Classification.is_population_input`, which
`classify` now asks); `scripts/self_test_arms.py` (the gate's declared arms); `docs/rearchitecture/DESIGN-test-build-ci.md`
§3.14.12 item 5 and §3.14.1; `.claude/skills/gate/SKILL.md`.

**Report.** Owner, 2026-11-10: "We better not be running all those tests again, when only the self tests failed to run."
Run 000001 of worktree records-85 (tree 241f5fbb05, commit f675bc0099) ran every host green (Conformance 23,687, Unit 40,741,
Characterization 37; the Conformance host alone took 1,473.9 s) and its verdict was RED only for `SELF-TESTS HANG` (the
orchestrate self-tests, kb/Work PB5155). The branch then merged main, which brought 61 `kb/` files, 2 `DEVLOG/` files and
three scripts no compiler test or build reads (`scripts/orchestrator/test_orchestrate_account.ps1`,
`test_orchestrate_core.ps1`, `testdata/orchestrate_test_lib.ps1`). The re-gate at the merged head a3b30da281
(`E:\COBOL-coord\scratch\records-85-gate2.log` lines 5 and 14: "full lane", "the whole population") built and ran all 64,465
cases again. Then, owner 2026-11-10: "This is precisely what the Unix make and Windows MSBuild utilities are for. They rerun
only what is required due to changes."

**Cause.** Two defects, both verified on the record of run 000001.
1. `Host.code_state_diff` (PB5099's composition predicate) let an earlier run's passes stand only when every differing path
   was INERT. A tooling-lane path (no compiler test and no build reads it, `inert_lane.Classification.in_tooling_lane`) cannot
   change the result of any Unit, Conformance or Characterization case either, yet it returned None, so nothing was carried.
   The predicate was a hand-picked special case ("same tree or inert-only") of the real question: are the populations'
   INPUTS the same.
2. Run 000001 could not have been carried even by an equal tree. Its record has `populations: {}` and `tree_end: null`,
   and its line says the hosts were "STOPPED … partial and NOT measured", though every host had exited green. `_audits` calls
   `stop_hosts` on any red audit, which sets `_Live.stopping` even when no host is still running, and `_tested` and
   `_run_hosts` read `stopping` as "a host was killed". A self-test that hung past the last host therefore threw away a
   complete measurement of the populations.

**Fix.** The populations are a step keyed by a digest of their inputs, as a script self-test is by its recorded inputs
(kb/Work PB2914).
- `Classification.is_population_input` (neither inert nor tooling-lane) is the ONE definition of what a compiler test or the
  build may read; `classify` asks it for the code lane.
- `population_digest` / `Host.population_key`: sha256 of the toolchain and every `git ls-tree -r -z` entry of the measured
  tree whose path is a population input (object ids only, no file read; 0.7 s over the 35,590 entries of main measured
  2026-11-10). A full-lane gate sets `Outcome.population_key`, and every record keeps it and its `audit_reds`.
- `Gate.carry` matches earlier runs on `population_key` alone; `code_state_diff` and the separate toolchain comparison are
  removed. The same tree and an inert-only or tooling-only difference are cases of equal keys; one path a test or the build
  may read, or another toolchain, is another key and runs everything.
- `populations_green`: a run whose verdict is RED only for its audits (every reason in `audit_reds`, every host green, every
  population EXACT) measured its populations GREEN, so it answers for them (`_composed`) like a GREEN run.
- `_Live.stopped_any`: the hosts' results count as partial only when a stop KILLED one. An audit red after the last host
  exited leaves the populations measured and recorded, and the verdict RED for the audit alone.
- Audits are never carried. Every gate runs them at its own tree, and when the change touches a script the SELF-TESTS audit
  re-runs exactly the self-tests whose recorded inputs changed (SELF_TESTS_REUSE). A change that touches a script also owes
  the post-build self-tests, which need a build, so a run that did not run them is carried through the retry path instead (a
  gate that builds, runs them and starts no host).
- `_composed`'s verdict line names the run whose population passes were carried and what ran now ("what ran now: the audits,
  the script self-tests among them (each re-run where its recorded inputs changed), GREEN").

**Proof.** `python scripts/gate.py --self-test`, 97 arms, PASS. Six new arms: (a) an audit red after every host exited stops
none, and the run records EXACT populations, its `tree_end`, `audit_reds` and key; (b) a run RED only for a hung self-test,
then a tooling-only difference: populations carried, audits with the self-tests run, no fetch, slot, build or host; (c) the
same, then a difference in a path a test may read: everything runs; (d) a GREEN run, then a tooling-only difference: carried,
and the self-tests still run; (e) a GREEN run with no post-build self-test, then a script change: passes carried, a build,
no host; (f) the real key over a scratch repository: a docs/kb or tooling-lane edit leaves it equal, a `src/` edit, a
`CODE_READS` script edit and another toolchain change it. The existing arms now use keys for the inert-only cases. Against
main's `gate.py` production code with this self-test (a copy outside the tree; stubs: no key, and only a GREEN verdict is
population-GREEN): `=== gate SELF-TEST: FAIL (97 arms …)`, with arms (a), (b), (d), (e), (f) and the five inert-only
composition arms FAIL (the planted fake no longer plants the removed predicate). Arm (c) and the toolchain arm PASS on both:
they guard the "another key runs everything" side, which main already did.

**Remaining work (an id is needed; none was allocated here): population passes across worktrees.** The key is
worktree-independent, but the passes it finds still live in this worktree's `TestResults/build-local/<run>/*.trx`, which
`KEEP_RUNS` prunes and `prune_worktrees.py` deletes with the worktree. For a gate in worktree B to reuse a pass recorded in
worktree A at the same key (a branch re-cut from main, a landing's re-gate in a fresh worktree), the passes need a home in the
git common dir, as the self-tests' `cobol-self-test-passes/` store has: per key, each assembly's passed case names (from
`test_population.passed_cases`), the record that measured them, and the trx itself or a copy, because `measuring_runs` and the
landing lane's red classification (`land_lane.py`) read a verdict's evidence from run directories. That means a store with
its own pruning, a `measuring_runs` that resolves into it, and `enqueue.tested_locally` accepting a verdict whose evidence lies
outside the worktree. It is a redesign of the evidence model, not of the key, so it was not done here.
