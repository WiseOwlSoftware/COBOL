# PB379 — an audit nobody runs found six wrong clause numbers

<!-- audit-doc-citations: names-misfilings — this note IS the misfiling register; every row of the table below
     PAIRS a clause with a quotation that is NOT in it, which is the point of the note. Same whole-file opt-out,
     and the same 40-line window, that `audit-code-citations: names-phantoms` gives PB290. -->

Found at the battery #42 close (2026-09-03) while attributing the citations leg (PB378): `audit_code_citations.py`
(phantom clauses, in the battery) was at zero, but its sibling `audit_doc_citations.py --check` (a quoted
fragment against the clause it is filed under; NOT in `battery.sh`) reported, over 197 verbatim-shaped
citations, **6 MISFILED**. Rule 1's failure mode exactly: the text is genuinely in the standard, the number
above it was inherited and never re-derived. None was registered anywhere.

| file | says | quoted text | really |
|---|---|---|---|
| `docs/COBOLNET_INTRINSICS_DESIGN.md` | §15.38.1 | "depends on the type of argument-1" | §15.39.1 (General) |
| `docs/COBOLNET_INTRINSICS_DESIGN.md` | §15.39.1 | "depends upon the argument types" | §15.18.1 (General) |
| `docs/CONFORMANCE.md` | §14.9.25.3 | "no digits to the right of the decimal point" | §15.2 5) (Types of functions) |
| `docs/DIAGNOSTICS.md` | §8.6.6 | "shall not be specified in the input or output procedure of a MERGE or" | §14.9.7.3 2) (Syntax rules) |
| `src/Cobol.Net.Editions/Diagnostics/DiagnosticCatalog.cs` | §8.6.6 | "shall not be specified in the input or output procedure" | §14.9.7.3 2) (Syntax rules) |
| `src/Cobol.Net.Runtime/Values/Numeric/CobolSizeError.cs` | §14.7.5 | "if the SIZE ERROR phrase is specified" | §14.7.6 6) (CORRESPONDING phrase) |

The audit's "really" is where the fragment actually occurs — the mechanical check rule 1 demands — but it is
a LOCATION, not a judgement: a site may be quoting the right words from the wrong place (renumber), or the
right place with words that are not there (re-quote from the clause the site is about). `CONFORMANCE.md`'s
row is the suspicious one: MOVE (§14.9.25) may well carry its own digits-right-of-the-point rule in other
words, and the fix there is a faithful quotation of §14.9.25's text, not a pointer at §15.2. Two rows are in
`src/` doc comments, so a golden's expected diagnostic text may cite the clause too — sweep for the same
`§8.6.6`/`§14.7.5` strings across `src/`, `tests/` and `docs/` when fixing.

## What closes it

1. Each of the six sites read in context; `python scripts/spec/cite.py --check <clause> "<text>"` run for the
   corrected citation before it is written; renumber OR re-quote, per site, with the reason in the change.
2. Sweep siblings: every other occurrence of the wrong numbers with the same quoted text (the DIAGNOSTICS.md and
   DiagnosticCatalog.cs rows are one misfiling written twice — one rule, one place: fix the catalogue descriptor
   and make sure DIAGNOSTICS.md is rendered from it, or note why it is not).
3. Give the audit a gate seat: `battery.sh`'s citations leg runs `audit_doc_citations.py --check` beside
   `audit_code_citations.py --check`, both contributing to the leg's red (seconds, no build dependency — the
   same argument PB175 makes for semgrep). Prove the seat by a planted misfiling turning the leg red once.
4. `audit_doc_citations.py --check` at zero; wave-local gate `~Diagnostics|~SizeError` for the two src sites.

## Landed — 2026-09-03

⛔ **FIVE OF THE SIX WERE NOT INHERITED CLAUSE NUMBERS, AND THE PREMISE ABOVE IS WHAT HAD TO CHANGE.** The note
(and the audit) assumed a citation is written CLAUSE-then-QUOTE. This repository writes it three ways, and the
other two were unreadable to the checker, so it blamed whichever `§` happened to sit nearest BEFORE the quote:

- the POSTFIX order, `"depends on the type of argument-1" §15.39.1,` — two rows, both attributions CORRECT;
- the BACK-REFERENCE order, `§15.2 … "quote" (item 5)` / `§14.9.7.3 … "quote" (SR2 of both)` — three rows
  (CONFORMANCE.md, and DIAGNOSTICS.md + DiagnosticCatalog.cs, which are ONE site), correct in substance but
  spelling the citation as a pointer back into the sentence, which nothing can resolve.

Worse than the false positives was what they hid: a quote cited in the POSTFIX order was never checked against
its clause **at all**, so a real misfiling written that way was invisible. Reading both orders removed the two
false positives AND put ~15 previously-unchecked citations under the rule (236 checked · 193 correct · 0
misfiled, from 199 · 152 · 6). The back-reference order is deliberately NOT mechanised — a citation no tool can
resolve is a citation nothing checks, which is the state rule 1 exists to end — so those sites were repaired by
writing the clause number beside the quote it supports.

**Per site.**

| site | decision | why | `cite.py --check` |
|---|---|---|---|
| `COBOLNET_INTRINSICS_DESIGN.md` ×2 | **no change** | postfix order; both attributions already right — the AUDIT was wrong | (unchanged, now reported `ok`) |
| `docs/CONFORMANCE.md` | **re-cite** — `(item 5, …)` → `(ISO §15.2 item 5, …)` | the site is about §15.2 item 5, named earlier in the same sentence; MOVE's own rules do NOT carry this wording, so the brief's guess of a re-quote was wrong | `OK  §15.2 5)  (Types of functions)` |
| `DiagnosticCatalog.cs` (+ generated `DIAGNOSTICS.md`) | **re-cite** — `(SR2 of both)` → `ISO §14.9.7.3 SR2 — "…"` | one rule, one place: the descriptor is the source and the doc is rendered from it by `scripts/gen-diagnostics-doc.ps1`. The back-reference also hid a small infidelity: the quoted wording is §14.9.7.3 SR2's exactly (`a MERGE or **file** SORT statement`); §14.9.36.3 SR2 says `a MERGE or SORT statement`, which the message now states instead of claiming one quotation for both | `OK  §14.9.7.3 2)  (Syntax rules)` and `OK  §14.9.36.3 2)` |
| `CobolSizeError.cs` | **re-quote** — the one genuine defect | the site IS about §14.7.5; §14.7.5's own words are "the size error condition exists and the SIZE ERROR phrase is specified", and "if the SIZE ERROR phrase is specified" is §14.7.6's CORRESPONDING wording | `OK  §14.7.5 8)  (SIZE ERROR phrase and size error condition)` |

**The seat.** `battery.sh` PHASE -1 and `build-local.{sh,ps1}` now run `audit_doc_citations.py --check` beside
`audit_code_citations.py --check`, into the same log, contributing to the same red. Proven by planting a
misfiling in a tracked-looking `docs/` file: PHASE -1 `RC=1` with the code audit still at 0 (so the red is
attributable), in BOTH citation orders, and `RC=0` again with the plant removed.

**Three things the audit gained, each with a `--self-test` leg** (`--self-test` PASS, 9 legs): the postfix
order; per-SITE reporting with one cite.py call per pairing (the old global de-duplication reported ONE file per
pairing and silently hid its siblings — the `§15.38.1` pairing lives in three files); and the whole-file
`audit-doc-citations: names-misfilings` marker, mirroring `audit_code_citations`' `names-phantoms`, without
which THIS note's table would hold the gate red for ever.

⚠ **Known limit → `PB381`:** a two-segment clause (`§15.2`, `§13.16`) is invisible to both audits — the 2-dot
floor is what keeps a doc's own `§4.2` out — so the repaired CONFORMANCE.md citation is unchecked, merely no
longer misattributed. Widening that floor needs the sibling's `NOT_THE_STANDARD` guard; that is PB381's job, not a
paragraph here (rule 8).
