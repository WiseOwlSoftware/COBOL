## Measured
```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. B20OUT.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 G GLOBAL.
          05 X PIC X(3) VALUE "GLB".
       PROCEDURE DIVISION.
           CALL "B20IN"
           STOP RUN.
       IDENTIFICATION DIVISION.
       PROGRAM-ID. B20IN.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 L.
          05 X PIC X(3) VALUE "LOC".
       PROCEDURE DIVISION.
           DISPLAY "X=" X
           GOBACK.
       END PROGRAM B20IN.
       END PROGRAM B20OUT.
```

→ `error COBOLNET1639: 'X' does not uniquely identify a data item — 2 declarations share the name and no
qualification distinguishes them`.

## The rule
`cite.py --check 8.4.6.2.1 "If the name is declared in source element B, the item in source element B is the referenced item"`
→ `OK §8.4.6.2.1 3) a)`. Expected output `X=LOC`.

## What the fixer owes
Resolve data-names over the depth-tiered candidate set PB919 built for index-names (§8.4.6.2.1 1)–3)): local names
first, then each container outward, qualification applied within a tier. One resolution, shared by index-names,
data-names, condition-names, file-names and report-names — sweep them all. Golden: the probe plus a two-deep nest.

## Landed 2026-09-27 (wave 68 Z, with PB1243 — one rule, fixed once)

**Root:** a contained program's name map was ONE flat tier — its own names plus every container's GLOBAL names —
and the GLOBAL-root loop "shadowed" by skipping a container root whose SPELLING the unit already held, which both
over-included (a local `X` and the container's `G.X` were co-candidates → COBOLNET1639) and under-included (the
skipped root's whole subtree vanished → lg11 `Y` / lg12 `Z` 'not defined'). Now:
- `DataBinder.InheritGlobalSubtree` inherits EVERY global root whole (data-names, their 88s, RENAMES, index-names),
  tagging each item with the container's nesting depth; nothing is skipped.
- `SymbolTable.NearestDeclaring` is the ONE §8.4.6.2.1 3) rule for data- and condition-names: after qualification
  over the whole set (rule 1), the survivors of the nearest declaring element. Asked by
  `ReferenceResolver.ResolveUnqualified`, `DataBinder.QualifiedCandidates` (so every data-division clause resolver
  too) and `ConditionBinder.ConditionOf`. Two survivors in that element stay ambiguous.
- Every global root is now bridged, so `DataBinder.ReserveInheritedMemberNames` (before the unit binds) gives a
  local root spelled like one a distinct C# member name.
- **Siblings on the same rule, fixed (the other name classes):** a nearer DATA-name hid nothing from a farther
  global INDEX-name (`01 IX` in the containee vs the container's `INDEXED BY IX` → COBOLNET1637; now
  `SymbolTable.IndexCandidates` weighs the depths → `IX=7`), and an OUTER global CONSTANT beat the MIDDLE program's
  global data-name (`X=OUT`, expected MID; `DataBinder.DropShadowedConstants` is now depth-aware and runs once every
  tier is in place). File-names (`FilesByName.TryAdd`, nearest first) and report-names (`NearestInScope`) were
  already tiered — read, no change.
- Re-probe (own build): lg1, lg2b, lg8, lg9 → COBOLNET1639 ambiguous before; lg11, lg12 → 'not defined' before.
  After: lg1 `X=LOC`, lg2b `X=MID`, lg8 `LOCAL-C`, lg9 `MID-C`, lg11 `Y=GLY G=LOC`, lg12 `Z=OUZ W=MDW`; lg4/lg5
  (non-global) still 'not defined', lg6n (two globals in one element) still ambiguous — correct.
- Goldens `conformance:85/pb1047_nearest_declaring_element` (nine legs, incl. qualification-before-tiering
  `X OF G` → MID and the bridge write-back `O Y=NEW`), `conformance:2002/pb1047_global_constant_nearer_data_name`
  (T K=MDK / S K=OUK); negative `conformance:negative/pb1047-two-globals-one-element-ambiguous` (COBOLNET1639).

## Finished 2026-09-28 (wave 69 Z — the train-68b review's two findings on this rule)

The train-68b lander's review found two places the rule above was not yet whole; both are fixed at their root.
- **The member-name reservation missed the STEM.** `ReserveInheritedMemberNames` reserved the bridge members only,
  but a REDEFINES root's bridge is `_redef_G` — spelled from the root's C# name `G`, which stayed free, so a local
  `01 G` + `01 K REDEFINES G` kept stem `G` and its own class backing re-spelled the container's `_redef_G` bridge
  (CS0102 — legal source did not build; repro `t68b-probe\zc1.cob`). `DataBinder.InheritedMemberNamesOf` is now the
  one list of names a global root occupies: every bridge member plus the root's own (and its canonical's) C# name.
  Measured: zc1 CS0102 before → `IN G=INNR` / `OUT G=OUTR` after. **Sibling (swept, fixed):** every derived member
  family was checked for being spelled from that stem — `_redef_` / `_scell_` are (`RedefinesClass`), a carrier is
  Uid-keyed (`__lnk{Uid}`), a capacity register has no field — but a BASED root's `__addr_` pointer was spelled from
  the COBOL WORD (`NamingConvention.AddressCarrierName(root.CobolName)`), so a local BASED `B` beside a container's
  GLOBAL BASED `B` was CS0102 on `__addr_B` even with the stem renamed; it is now spelled from the root's C# name
  (probe `w69z\p\zc2.cob`: CS0102 before → `IN B=INNR` / `OUT B=OUTR`).
- **Kind-filtering lookups skipped the tier.** `IntrinsicBinder.FunctionPointerNamed` (§8.4.3.2.3 SR4) filtered the
  RAW candidate set for FUNCTION-POINTERs, so a local FP beside a container's global FP was "two rivals" → null →
  COBOLNET1501, and a local table `FQ` beside a global function-pointer `FQ` made `FQ(2)` a call through the hidden
  pointer. Sibling sweep over every `Symbols.TryResolve` caller that uses the candidates: `InitializeBinder`'s
  whole-dynamic-table arm had the same shape — a local `D-TAB` beside a container's global dynamic table `D-TAB`
  initialized the CONTAINER's table and left the local item alone (wrong answer, measured `IN [QQQQ]` / `OUT [  |  ]`).
  `SymbolTable.TryResolveUnqualified` (TryResolve + NearestDeclaring) is the unqualified lookup; both kind filters,
  `ReferenceResolver.ResolveUnqualified`, the property-receiver lookup and the ADDRESS OF pre-scan read it. The
  qualified paths keep the raw set (rule 1 qualifies first). Existence-only callers (`out _`) are tier-neutral.
