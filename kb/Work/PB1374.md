# PB1374 — LANDED (w1020f)

## Landed

Re-probed first on the w1020f build (FA..FI and the FLAG-02 forms: all reproduced), then the printed pages were
rendered from the canonical PDF (p.100 and p.102): ALL and ON carry no underline in either directive, so by §5.2.3
(optional words) and §5.2.6.3 (the alternative of optional words is the default) a bare directive is `ALL ON`, a lone
`OFF` is `ALL OFF` and a lone option list is `ON`. `FlagDirectiveLine.TryParse` (the one parser both collection sites
call) now takes the trailing ON/OFF as optional for BOTH directives (it was required for FLAG-14), takes no option
word as ALL, and refuses a repeated option word or repeated ALL (§5.2.6.4, "any single alternative shall be specified
only once") with COBOLNET1622 instead of merging it; an ON/OFF that is not the last word is refused too. The spec
transcription's own FLAG-14 figure note contradicted itself ("a separate, required one-of-two selection") and is
corrected. Goldens: `2023/pb1374_flag14_defaults`, `2014/pb1374_flag02_defaults`, negatives
`pb1374-flag14-option-repeated` and `pb1374-flag02-all-repeated`; unit `FlagDirectiveTests` (parse theory, repeat,
ON/OFF-not-last, and end-to-end default spellings for both directives). Siblings swept: the other directives whose
format prints an un-underlined ON (LISTING, LEAP-SECOND, REF-MOD-ZERO-LENGTH) already accept the bare form (probed).
DESIGN-flag-directives.md, CONFORMANCE.md A.1 items 79 and 80, the COBOLNET1622 catalog text and docs/DIAGNOSTICS.md
state the defaults. Rows closed: FMT-7.3.14.2, FMT-7.3.15.2, GR-7.3.15.4-1, -2, -3.

**Code location:** src/Cobol.Net.Frontend/Preprocessor/FlagDirective.cs#FlagDirectiveLine.TryParse — the ONE parse of both
directives (the ON/OFF brace, then the ALL-or-option-list brace; `Repeated` words the §5.2.6.4 refusal). Trap that cost a turn:

## Finding — flag-02-directive (rejects-legal-source)

FlagDirectiveLine.TryParse models the FLAG-02 outer braces as 'ALL or option words, one REQUIRED', but the printed format sets ALL as an optional (non-underlined) word, so §5.2.6.3 makes the ALL alternative the DEFAULT — and it models §5.2.6.4's 'each alternative only once' as a silent merge instead of a rejection

**Rows:** FMT-7.3.14.2

**Repro:**

```
>>FLAG-02 OFF (also `>>FLAG-02 ON`, bare `>>FLAG-02`) in the procedure division of any program, --std 2014 -> error COBOLNET1622 '>>FLAG-02 is malformed: no option or ALL is named'. Converse: `>>FLAG-02 I-O-STATUS-07 I-O-STATUS-07 ON` and `>>FLAG-02 ALL ALL ON` are accepted without a diagnostic.
```

**Expected from the spec:** PDF p.100 (folio 70), rendered: ALL and ON are not underlined. §5.2.3: optional words are 'shown in uppercase and not underlined'; §5.2.6.3: 'If one of the alternatives contains only optional words, that alternative is the default and is selected unless another alternative is explicitly specified'. So `>>FLAG-02` = `>>FLAG-02 ON` = ALL ON and `>>FLAG-02 OFF` = ALL OFF (the GR2 'directive ... that turns off all flagging options'). §5.2.6.4: 'any single alternative shall be specified only once' -> a repeated option word is a syntax error (COBOLNET1622).

**Observed:** TryParse returns false when no option word precedes the ON/OFF, and dedups repeats with `if (!picked.Contains(opt)) picked.Add(opt)` citing 5.2.6.4. Sweep (rule 4): the same parser REQUIRES ON/OFF for FLAG-14 although §7.3.15.2 prints ON bare too (its figure note says omission = ON), and has the same ALL-default and duplicate behaviour — one parser, both directives. The design doc DESIGN-flag-directives.md line 43-45 records 'ALL or one-or-more option words' and a 'required ON | OFF', so the fix updates it. If the owner prefers to read the bare ALL as a typesetting slip, that is an owner decision (the printed typography otherwise controls).

**Code site:** src/Cobol.Net.Frontend/Preprocessor/FlagDirective.cs#FlagDirectiveLine.TryParse

## Finding — flag-14-directive (rejects-legal-source)

FlagDirectiveLine.TryParse treats FLAG-14's ON/OFF braces as required and the option/ALL braces as required. Per 5.2.3 and 5.2.6.3, both un-underlined words (ON and ALL) are the implicitly selected defaults. Separately, a duplicated option word is silently de-duplicated instead of rejected.

**Rows:** FMT-7.3.15.2, GR-7.3.15.4-2, GR-7.3.15.4-3

**Repro:**

```
E:/Temp/claude/E--CobolSharp/a700c052-f9e4-4942-84ff-a13c7505d6ec/scratchpad/adj-d2/out/probe/flag14/FA.cob / FB.cob / FC.cob / FD.cob / FI.cob: '>>FLAG-14 VALUE-ZERO', '>>FLAG-14 ALL', '>>FLAG-14 OFF', '>>FLAG-14', '>>FLAG-14 ON' in WORKING-STORAGE before '01 X PIC ZZ9 VALUE ZERO.'. Also FE.cob: '>>FLAG-14 VALUE-ZERO VALUE-ZERO ON'.
```

**Expected from the spec:** All five are accepted. ON omitted means ON and ALL omitted means ALL (5.2.6.3: 'If one of the alternatives contains only optional words, that alternative is the default and is selected unless another alternative is explicitly specified'; GR2's 'explicitly or implicitly specified'). So FA flags VALUE-ZERO, FB/FD/FI flag every option, and FC turns every option off. FE draws a syntax diagnostic (5.2.6.4: 'any single alternative shall be specified only once').

**Observed:** FA/FB: error COBOLNET1622 'the ON or OFF phrase is required'. FC/FI: COBOLNET1622 'no option or ALL is named'. FD: COBOLNET1622 'no option and no ON/OFF phrase'. FE compiles clean with the warning. The unit test FlagDirectiveTests.Parse_Flag14_MissingOnOff_IsError pins the rejection, and DESIGN-flag-directives.md says 'FLAG-14 requires the choice', although the spec's figure note (checked against page 102 per PB808) says ON is optional. The FLAG-02 arm of the same parser already treats ON as implicit: one rule written two ways.

**Code site:** src/Cobol.Net.Frontend/Preprocessor/FlagDirective.cs#FlagDirectiveLine.TryParse (the 'directive == FlagDirective.Flag14' error arm; the 'end == 0' and 'picked.Count == 0' errors; 'if (!picked.Contains(opt)) picked.Add(opt)')
