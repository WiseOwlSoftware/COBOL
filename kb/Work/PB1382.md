## Finding — turn-directive (silent)

A SUCCESSFUL READ never runs the EC-I-O hook: the emitted READ calls __IoCheckEc only in the branch where the status's first character is not '0', so a nonzero successful status (04/06/09 ...) never sets EC-I-O-WARNING even when '>>TURN EC-I-O-WARNING CHECKING ON' is in effect (OPEN, by contrast, calls the hook unconditionally and raises it). The TURN rule itself conforms; the defect is the READ emitter's success branch.

**Rows:** GR-7.3.25.4-4

**Repro:**

```
F1 LINE SEQUENTIAL record PIC X(20) writes one 20-char line; F2 on the same file with record PIC X(5) and FILE STATUS FS; '>>TURN EC-I-O-WARNING CHECKING ON'; OPEN INPUT F2; READ F2 END-READ; DISPLAY FS FUNCTION EXCEPTION-STATUS; also a DECLARATIVES USE AFTER EXCEPTION CONDITION EC-I-O-WARNING.
```

**Expected from the spec:** §9.1.13.1: 'The exception-name for successful completion with an I-O status value that is not 00 is EC-I-O-WARNING' and it is raised when checking is enabled; with it explicitly enabled (§7.3.25.4 GR4) the READ's status 06 (§14.9.30.4 GR15) sets EC-I-O-WARNING: EXCEPTION-STATUS 'EC-I-O-WARNING' and the declarative runs.

**Observed:** TRNWD / TRNW3: 'FS=06 [spaces]', declarative not executed. Generated TRNWD.g.cs: `if (CobolFile.ReadShared(...)[0] == '0') { R2 = ...; FS = ...; } else { ...; __IoCheckEc("TRNWD::F2", ..., 256, ...) }` — the mask carries the WARNING bit (256) but the success branch never calls it. Sweep the other I-O emitters (START, REWRITE, WRITE, DELETE) for the same success-branch skip.

**Code site:** src/Cobol.Net.Compiler/CodeGen/Verbs/SequentialIoEmitter.cs (READ emission success branch); src/Cobol.Net.Compiler/CodeGen/EcEmitter.cs#EmitIoCheckEc

## What the fixer owes (and the sibling sweep)

Call the EC hook on every completion of READ (and sweep every I-O verb emitter in `SequentialIoEmitter` and its relative/indexed siblings for the same success-branch shortcut: WRITE, REWRITE, START, DELETE). Golden: READ returning 04 with EC-I-O-WARNING ON raises it.
