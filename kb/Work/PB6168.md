# PB6168 — C# 15 `closed` hierarchies

**The owner, 2026-11-24 (account 1 session):**
1. "evaluate C#15 new additions and determine what they provide and whether any would benefit us to adopting them in
   the compiler. Do not go ahead and adopt any without my approval".
2. On the evaluation's two open points: "We can't decide until we make this check".
3. After the check: "I approve closed".

## The evaluation

The sources were Microsoft Learn, "What's new in C# 15" (updated 2026-11-19), and the Roslyn language-feature status
page. C# 15 GA has six features usable without a preview setting:

| Feature | Measured against `src/` (1053 files) | Verdict |
|---|---|---|
| `closed` class modifier | 20 abstract records in the bound tree and the binding model, dispatched with `default: throw` arms (DESIGN-architecture-review §8.5 counted 48 to 74 such arms) | adopted |
| union types | they fit only a sum whose cases share no base type; for a `[BoundNode]` root they box the value, their `default` holds null, and the generator would have to change | a later candidate only |
| collection-expression arguments | 56 `new List<T>(n)` and 29 comparer constructions, none of them an initializer | no gain |
| extension indexers | no `extension` blocks in the code | no gain |
| labeled `break`/`continue` | no `goto` loop exits; one `goto Invalid` | take one only where a nested-loop flag is next touched |
| non-virtual static interface members on older runtimes | nothing targets an older runtime | no gain |

Memory safety is preview only. Dictionary expressions, null-conditional await and chained comparisons did not ship in
C# 15. None of the features is needed in the C# the compiler EMITS: emitting C# 15 syntax would only force C# 15 on
whoever builds the output.

## The check the owner asked for (2026-11-24, at main 9e65164eb, in a throwaway worktree)

1. **Roslyn treats a `closed` class as abstract.** A scratch compilation with Microsoft.CodeAnalysis.CSharp 5.12.0, the
   version the source generator compiles against, reports `IsAbstract = true` and a new `ITypeSymbol.IsClosed`. The
   emitted type is abstract in metadata and carries `System.Runtime.CompilerServices.IsClosedTypeAttribute`.
   - A switch that names every direct subclass needs no default arm.
   - A switch that misses one draws CS8509, which `TreatWarningsAsErrors` makes an error. This holds through an
     intermediate `closed` level.
2. **The source generator needs nothing.** A `netstandard2.0` project cannot DECLARE a `closed` type: CS0656, because
   `IsClosedTypeAttribute` and `CompilerFeatureRequiredAttribute` are missing. But `WiseOwl.Cobol.Compiler.SourceGen`
   only reads these symbols, and every hierarchy is declared in `WiseOwl.Cobol.Compiler` (`net11.0`).
3. **The real tree.** With all 20 records `closed`:
   - The solution built with 0 warnings and 0 errors.
   - A `--no-incremental` build's generator output (`EmitCompilerGeneratedFiles`) was byte-identical, 95 of 95 files.
   - `WiseOwl.Cobol.Tests.Unit` passed 43,099 of 43,099.
   - `WiseOwl.Cobol.Tests.RepoDrift` failed one test, `EveryCSharpFilesSymbols_AgreeWithThePythonResolver`, because
     `scripts/spec/code_location.py`'s modifier list did not know `closed`. With the keyword added, it passed.

## Wave 1 (this change)

`closed` replaces `abstract` on these 20 records:
- the eight bound roots: `BoundEoOperand`, `BoundExpr`, `BoundOperand`, `BoundBoolExpr`, `BoundCondition`,
  `BoundStatement`, `BoundPerformControl` and `BoundSetTarget`;
- the other bound records: `ReceiverBracketKey`, `InitializeAction`, `TableSortStorage` and `ValidateStep`;
- the binding model's `Place`, `PlaceDecorator`, `WindowCoding`, `CellWindowCoding`, `AllCount`, `AccessSegment`,
  `RootSegment` and `ContainerAnchor`.

Every C# modifier vocabulary in this repository's tools learned the keyword:
- `scripts/spec/code_location.py`;
- `scripts/spec/drift_rules.py`, three patterns;
- `scripts/arch/source_units.py`;
- `scripts/prune_worktrees.py`, two patterns;
- `scripts/gen-vault-reference.ps1`.

The same vocabulary written seven times is itself a finding, PB6170. The public skill submodule's
`tools/claude-skills/skills/agent-fleet/references/orient.py` has the same list. It is outside this repository's tree and is recorded in PB6170.

DESIGN-architecture-review §8.5 and §5.5 now name `closed` as the mechanism. The union plan they carried is withdrawn.
Wave 2 is PB6169.
