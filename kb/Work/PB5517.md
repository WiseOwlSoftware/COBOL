# PB5517 - the pack-time conformance statement target runs a bare `python`, the interpreter spelling PB1637/PB3197 retired for gate scripts, so `dotnet pack` fails on a host whose only interpreter is python3

**Sites:** `Directory.Build.props:42` (target `CobolPackConformanceStatement`, its `Exec`; XML, no member check), `scripts/python-resolve.ps1` (whole: the resolver the fix reads or exposes to MSBuild)

**Mechanism.** The target `CobolPackConformanceStatement` (kb/Work PB5431) runs `python "$(MSBuildThisFileDirectory)scripts/spec/conformance_doc.py" --out ...` through MSBuild `Exec`. kb/Work PB1637 and PB3197 retired the bare `python` spelling for gate scripts: `python-resolve.sh` and `python-resolve.ps1` probe `$PYTHON`, `python3` and `python` against `toolchain.env`. On a host whose only interpreter is `python3`, or where `python` is the Windows Store alias, `dotnet pack` fails at this step.

**Where the code is.** Not on main at filing: the target is on PB5395/PB5431's branches (`origin/worktree-wf_2e8662c7-06c-15`, `-27` and `-30`), where `Directory.Build.props` line 42 is the `Exec` (confirmed this session with `git show origin/worktree-wf_2e8662c7-06c-15:Directory.Build.props`). The line moves if main's file changes before it lands.

**Fix direction.** Resolve the interpreter through the same resolver the gate scripts use (or pass the resolved path as an MSBuild property from the toolchain manifest) rather than a second spelling in the props file.
