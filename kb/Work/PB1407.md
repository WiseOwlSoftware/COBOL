## Finding — `data-address-identifier` (under-rejects; rows `SR-8.4.3.11.3-2`, `SR-8.4.3.11.3-3`, `SR-8.4.3.11.3-4`, `SR-8.4.3.11.3-6`)

**Mechanism.** PtrBindAddressOf (the ONE binder of every data-address-identifier surface) applies no §8.4.3.11.3 operand screen: after ReferenceResolver.ResolveForAddressOf resolves the item it checks only that the record is cell-backed, so the prohibited operand kinds of SR2, SR3, SR4 and the dynamic-length half of SR6 are accepted and yield a live pointer

**Repro.** WORKING-STORAGE: 01 O USAGE OBJECT REFERENCE. / 01 T-REC TYPEDEF STRONG. 05 T-A PIC X(4). / 01 S TYPE T-REC. / 01 CR CONSTANT RECORD. 05 CR-A PIC X(4) VALUE "ABCD". / 01 BR. 05 B1 PIC 1(3) USAGE BIT. 05 B2 PIC 1(5) USAGE BIT. / 01 DR. 05 D1 PIC X DYNAMIC LENGTH. / 01 P USAGE POINTER. PROCEDURE: SET P TO ADDRESS OF O; SET P TO ADDRESS OF T-A OF S; SET P TO ADDRESS OF CR; SET P TO ADDRESS OF B2; SET P TO ADDRESS OF D1; also 05 BX PIC 1(8) USAGE BIT OCCURS 3 with SET P TO ADDRESS OF BX(I) and BX(2 ** 1). (probes N3 N4 N5 N6 N7A B2 under out/probe/dai/)

**Expected from the spec.** Each operand is a syntax-rule violation and shall be rejected at compile time: §8.4.3.11.3 SR2 (object reference; elementary item subordinate to a strongly-typed group item), SR3 (CONSTANT RECORD item or subordinate), SR4 a) (non-literal or exponentiated subscript of a bit item) and b) (bit item not byte-aligned), SR6 (dynamic-length elementary item, item subordinate to a group containing one).

**Observed / reasoning.** All compile clean and run (no diagnostic) at --std 2023 on the pinned adj-d2 cobol.exe. StrongTypeModel.AddressOfRestriction's doc comment even asserts ADDRESS OF a leaf of a strong record 'is UNRESTRICTED and must stay legal', the opposite of SR2's second half. The dynamic-capacity halves of SR6 are refused only by the resolver's generic 'unresolvable/mis-subscripted' arm, not by a rule screen. A CONSTANT RECORD address lets a BASED view write the constant record, and a strong-group leaf address lets a based untyped view bypass strong-type integrity (Annex D.9.2.2).

**Code site.** src/Cobol.Net.Compiler/Binding/Procedure/Verbs/PtrBinder.cs#PtrBindAddressOf (and StrongTypeModel.AddressOfRestriction doc comment)

### `FMT-8.4.3.11.2` — PARTIAL (adjudicator + refuter record, verbatim)

Format `ADDRESS OF identifier-1`, only ADDRESS underlined (cite.py --check 8.4.3.11.2 "OF identifier-1" -> OK). Grammar `dataAddressIdentifier : ADDRESS OF? dataReference` is the ONE rule reused by the SET sender, CALL/INVOKE arguments and the relation operand. Probe FM.cob: `SET P TO ADDRESS W` (OF omitted) and `CALL ... BY CONTENT ADDRESS W` compile and run at 2023 and 2002 (DISPLAY via BASED view prints ABC); --std 85 raises COBOLNET0900. The covering golden exercises the OF-present spelling only; the OF-omitted spelling is witnessed only by this probe (and the OptionalWordSubsetDriftTests grammar drift test). || REFUTED: PARTIAL — identifier-1 is a general identifier, and SR4 a) (cite.py OK 8.4.3.11.3 4) a)) speaks of 'subscripting and reference modification in identifier-1', so a reference-modified identifier-1 is legal source. The format therefore rejects legal source for one operand shape. The OF-omitted, qualified, subscripted, relation-operand and CALL/INVOKE shapes do work.
