# PB1629

Filed 2026-09-26 by the train-63 lander from the w62n (PB1604) implementer's lead. The harm is diagnostic quality
only: the refusal is correct (§8.5.1.9.1 3) — a dynamic-capacity table "may be defined in any place, other than the
file section").

**Repro** (w62n probes, `E:\Temp\claude\E--CobolSharp\ba65f072-4d30-4868-9bd3-4e5c60087107\scratchpad\w62n\`):
`t1.cob` (FD record `TYPE` of a typedef holding OCCURS DYNAMIC) reports `t1.cob(18,11)`, which is the working-storage
typedef line. `t2.cob` (SAME AS) does the same. The error should point at the FD / SD record entry whose TYPE or
SAME AS brought the table into the file section. It could also name that typedef line as a secondary location.

**Code site.** `DataBinder.Odo.cs:326-331`: `Edition.At(item)` uses the CLONED item's source position, which is
the typedef's. Pinned today by `OccursDynamicGuardTests.FileSectionDynamicTable_EveryRoute_Rejected1526`, which
checks the code and not the position.

Owner 2026-10-17: addressed in the SORT and file I/O campaign (kb/Work PB3353).

## Landed (wave 1126, group E)

**Re-probe.** On the w1126e build all six routes (TYPE on an FD record, TYPE on a group in it, SAME AS on a record, SAME AS
on a group, a SORT-MERGE record, an in-place table) reproduced the note: the four copy routes reported COBOLNET1526 at the
working-storage TYPEDEF / SAME AS source line, the in-place route at the table's own line.

**The root was wider than the note.** `CloneItem` gives a copy its template member's `DeclaredAt` on purpose (a rule the
DECLARATION breaks is reported where the declaration is), but every post-build rule about where an entry is PLACED then
reported a reference's fault at the declaration, a line the user is told to change though it is legal. Measured on the same
build, the OCCURS DEPENDING ON placement rules did the same for a TYPE or SAME AS copy: COBOLNET0851 / 0852 / 0853 / 0854 /
0855 / 0856 / 0857 (and the SR18/SR21 attribute rule that shares their loop).

**Fix.** One definition, `DataItem.ReferenceSite` (the nearest enclosing entry that is no copy: the subject of the TYPE or
SAME AS clause, or the item itself when it was written), asked by every placement rule: `DataBinder.DynamicResolve`
(1526), `OdoResolve` (every rule after SR16, which is a fact of the written phrase and stays at the declaration) and
`DataBinder.GroupValue` (COBOLNET1702, which asked the TYPE clause alone through `TypeAnchor`, so a SAME AS copy was still
positioned at its source). The message ends with the subject the clause belongs to (`ViaReference`), so the user sees why a
member they did not write is named.

**A sibling the sweep found and fixed (I9).** The seven-subscript limit (COBOLNET2646, §13.18.38.3 SR10) walked the
written-entry forest only, so a one-table type placed under seven tables compiled clean and produced an eighth dimension.
It now walks `CompositionForest` and reports the copy, once, at the reference site; a copy whose declaration already reaches
eight stays reported in the declaration only.

**Review round 1 (two findings, both fixed).** A fault whose every involved entry lies INSIDE one copied description is a
fact of the DECLARATION (a TYPE declaration, or the written record SAME AS copies), which is itself screened and reports it
where it is written; the legal reference that merely copies it must not report it again. `DataItem.IsCopiedUnder(site)` asks
it; `OdoResolve` skips 0852 / 0853 / 0854 / 0856 / 0857 when every involved entry (the table, its counter, the enclosing table)
is copied under the same site, and 0855 only when the declaration's own copy of the REDEFINES entry trips the same test
(a TYPE declaration's members form no REDEFINES class, so for a TYPE copy the reference is the one place the rule is asked).
The SR22 climb continues past a skipped entry, since an entry above the copy is the placement's. The SR10 depth skip asks the
IMMEDIATE source (`ClonedFrom`), not the written definition, so a copy of a copy whose eighth dimension arose one level up is
not reported at every further reference. Witness: `FactOfTheDeclaration_IsNotReportedAgainAtALegalReference` (counts equal
the declaration's alone, with one and with two references) and `PB1629WA`.

**Witnesses.** `ReferenceSitePositionTests` (every route, the in-place arm that must not move, the declaration that must not
be named), `OccursDynamicGuardTests.FileSectionDynamicTable_EveryRoute_Rejected1526` (the code), and the conformance cases
`pb1629-type-dynamic-table-in-file-section`, `pb1629-same-as-dynamic-table-in-file-section`,
`pb1629-type-table-needs-eight-subscripts` and its control `pb1629_type_table_at_seven_subscripts_is_legal`.
