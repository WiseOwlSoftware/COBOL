# PB4339 — the .tailor format docs omit PB4264's refusals

**Found** by the PB4264 finisher (wave 20261791 group A, report `E:\COBOL-coord\scratch\reports\w20261791a-PB4264-report.md`,
the second carried LEAD) and its round-2 reviewer (R2-1, LEAD, low, not blocking). PB4264 itself merged as PR #931.

**Sites:** `src/WiseOwl.Cobol.Runtime/Collation/README.md` (the `.tailor` paragraph "root primary (any of the 15 free
values)", line ~179, and the failure-contract list, line ~188), `src/WiseOwl.Cobol.Runtime/Collation/TailoringRules.cs:15`
(the file-format summary in the type's XML comment).

**What the docs must state** (the two refusals, both in `CollationTable.Rebuild` / `RefuseNumericLeadCarrier`, both a
`LocaleCollationException` naming the file and entry line):

1. a primary weight at the value just below the digit zero's primary: that value is the numeric-ordering lead, so it is
   not one of the "free values"; the CLDR builder keeps it free (`Slot.ReservesValueBelow`), a hand-written `.tailor`
   value may not use it. `TailoringRules.cs:15` names this one already;
2. a `U+0030` line that moves the digit zero onto a primary whose preceding value another character carries (the lead
   would then sit on that character). `TailoringRules.cs:15` and the README name neither this nor the CLDR contrast.

**Ordering.** The README edit puts the gate plan on whole tier 1 (the impact map has no entry for it), and a whole-tier-1
plan is falsely RED while PB4338 is open (astral theory names). `blocked_by: PB4338`; the TailoringRules.cs comment
alone does not wait for it but the two edits are one change. The PB4264 finisher marked the README lead "re-apply once
that is fixed".
