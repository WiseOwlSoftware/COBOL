# PB1368 — LANDED

## Landed (wave 1006 C, 2026-10-03) — the compilation-variable TIMELINE; both remaining pieces

Re-probed first on the worktree build: `p1.cob` drew COBOLNET0899 + a cascading COBOLNET1639; `s1.cob` drew COBOLNET1623.
Both now compile and run (`p1` prints 3; `s1`'s `SHOW "HI"` prints HI).

**The mechanism (the design recorded below, followed).** `ConditionalCompilationProcessor.Run` records every change a
`>>DEFINE` made to its table as a `CompilationVariableEvent` (line, name, `CtValue` or null for OFF / a value-less
PARAMETER, the operand as written) at the directive's encounter line; `Manipulate` carries the lines through REPLACE to the
resultant frame with the encounters (`ConditionalCompilationResult.CompilationVariables`); `Frontend.Preprocess` collects
them under the DEFINE row and replays the PUSH/POP program over them (`DirectiveEventLog.ToTimeline`), and
`DirectiveResults.CompilationVariables` — claimed by `DirectiveStateRegistry`'s `DefineDirective2002` entry, replayed by
`WithStackOps` for §14.9.28.4 GR14 — carries the timeline to the binder (`BindSession` → every `DataBinder`, the program
units' and all three OO constructions). THE fold is `CompilationVariableTimeline.DefinitionAt(name, line)`, the per-name
form of `DirectiveTimeline.TryLastInEffectBefore` (one new optional predicate; no second fold).

1. **`CONSTANT … FROM compilation-variable-name-1`** — `DataBinder.BindConstantFrom` (with PB1228): SR8 at the entry's
   own line, GR1 substitution, GR2 category; the 0899 descriptor `ConstantFromCompilationVariable` is deleted.
2. **`>>COBOL-WORDS` literal slots** — `CobolWordsDirectiveProcessor.Literal` reads a word as a variable defined before the
   directive; its value must be alphanumeric (GR1's "a literal of the category associated with the name"), and the literal
   its DEFINE wrote passes SR2 like a written one (a variable defined `AS X"41"` is still hexadecimal format).
   §7.3.10–§7.3.25 checked: COBOL-WORDS is the only directive with a literal slot that is not already an evaluator operand
   (DEFINE / DISPLAY / IF / EVALUATE read the live table).

Witnesses: `conformance:2002/pb1368_constant_from_compilation_variable`, `conformance:2023/pb1368_compilation_variable_timeline`
(PUSH/POP restore + COBOL-WORDS), negatives `pb1368-constant-from-after-define-off`, `pb1368-constant-from-defined-later`,
`pb1368-cobol-words-numeric-variable`, and the re-purposed `constant-from-compilation-variable` (SR8, never defined).
Design docs: `DESIGN-frontend-grammar.md` (the timeline bullet) and `DESIGN-cobol-words-directive.md` (SR2 bullet).

## Finding — define-directive (rejects-legal-source)

The compilation-variable store lives only in the text-manipulation stage, so the two non-conditional-compilation uses that GR1 permits are refused: CONSTANT ... FROM compilation-variable-name-1 is staged loud (COBOLNET0899), and a compilation-variable-name in another directive's literal position (>>COBOL-WORDS) is rejected as 'not an alphanumeric literal'.

**Expected from the spec:** §7.3.11.4 GR1: after a DEFINE without OFF the name 'may be used ... in any compiler directive where a literal of the category associated with the name is permitted, in a defined condition, or in a constant entry where the FROM phrase is specified'. §13.10.4 GR1: the constant behaves 'as if ... the text represented by compilation-variable-name-1 were written where constant-name-1 is written' - CN displays 3. ## Progress (wave 1004 B, 2026-10-02) — the DISPLAY half landed; two pieces remain, with the design

**Landed here (witness `conformance:negative/pb1368-display-name-after-define-off`, `unit:DisplayDirectiveTests.ANameAfterDefineOff_IsNotAnOperand`
and `ANameRedefinedAfterOff_IsAnOperandAgain`):** `>>DISPLAY X` after `>>DEFINE X OFF` is COBOLNET1619 — PB807's operand grammar
routes the DISPLAY operands through the same directive-context evaluator as DEFINE/IF/EVALUATE, so GR2's "shall not be used
except in a defined condition" is the evaluator's one check on every path (re-probed `s3.cob`: it compiled clean before).

**Still open, and why it is the next slice and not this one** (a stated scope is an estimate; this one is bigger than the note said):

1. **`CONSTANT … FROM compilation-variable-name-1`** (COBOLNET0899 today, `DataBinder.Constants.cs#BindConstantEntry`). Re-probed:
   `p1.cob` (`>>DEFINE N AS 3` / `01 CN CONSTANT FROM N.` / `DISPLAY CN`) still draws 0899 plus a cascading undefined-name error.
   The store lives only in `ConditionalCompilationProcessor.Run._defines`, a final map nobody outside the stage can read, and a
   constant sees the table AS OF its own line (§7.3.11.4 GR1 "in text that follows a DEFINE directive"), so the product is a
   TIMELINE, not a map. The shape the tree already has for this: a `DirectiveTimeline<CompilationVariableEvent>`
   (`DirectiveStateStack.cs`; an event is `(name, value | OFF, line)`) as a new `DirectiveResults` member claimed by the
   `Constructs.DefineDirective2002` entry of `DirectiveStateRegistry` (its `Products` is empty today — `DirectiveStateStackTests` goes
   red until a new member is claimed), fed by `ApplyDefine` in encounter order with the resultant line the way `TurnDirectiveProcessor`
   records its events (the driver's `_encounters` / `KeyImplicitOps` frame, `ConditionalCompilationResult`); PUSH/POP revocation
   comes with `WithStackOps`; `BindSession`/`DataBinder.Constants.BindConstantEntry` then folds the timeline at the constant's
   line (value ⇒ substitute "as if the text represented by compilation-variable-name-1 were written", §13.10.4 GR1; OFF or never
   defined ⇒ a named error), and `CtValue`'s category decides the constant's category. Delete the 0899 staging
   (`DiagnosticCatalog`, `docs/DIAGNOSTICS.md` regenerates) in the same change; goldens: FROM a DEFINEd numeric and alphanumeric name
   at the edition the CONSTANT entry arrived (`constructs.json`), FROM an OFF name and FROM a name DEFINEd AFTER the constant
   rejected, FROM after a POP restoring the older value.
2. **`>>COBOL-WORDS` literal slots accepting a compilation-variable-name** (`s1.cob`: COBOLNET1623 "must be an alphanumeric
   literal"). `CobolWordsDirectiveProcessor` runs after COPY on the final text and reads literals only; it needs the same
   timeline, read at the directive's own line (§7.3.10.3: the directive stands before the first IDENTIFICATION DIVISION, so the
   table in force there is the last event before it).
