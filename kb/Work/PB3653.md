# PB3653 — prune_worktrees.owned exposes no lock-only signal, so a hand-started agent on a SPLIT branch with no ledger entry is unseen by the finisher arm

**Sites:** `scripts/prune_worktrees.py` (`owned`, ~line 963), `scripts/orchestrator/plan_wave.py` (the finisher arm and its report arm, `finisher_by_rep`).

## What happens

The lock half of PB2974 (a live agent LOCK on a SPLIT branch against a recent touch) stayed open after PB2974's branch-as-unit fix: `owned` folds liveness into one set and has no lock-only signal, so a hand-started agent holding a SPLIT branch with no dispatch-ledger entry is unseen by the finisher arm, which then plans a second finisher.

## Fix direction

Expose a lock-only owner signal from `owned` (or beside it) and read it in the finisher arm's hold, with a scratch-repository witness of a locked SPLIT branch with no ledger row. Keep it inside PB2974's single branch-unit hold loop; do not add a second hold.

## Residual recorded here, not filed separately

Two DIFFERENT unfinished reports naming the same branch (`finisher_by_rep` is keyed by report) still plan two finishers in the plan_wave report arm; they share one hold but not one group. The PB2974 finisher could name no state that produces it, so it is not a defect note (PB3654 left unused). If a state is found, extend this note: the fix is to key the report arm by branch.

## Source

Report `w20261030b2-PB2974-report.md` (PB2974, PR #512), "New defects / leads", residuals 1 and 2. PB2974.md is not edited here (its PR is in flight).

## Landed (2026-10-24, wave 20261031 group B)

Re-probed: `plan()` with a SPLIT report's branch and `owned={branch}` still plans the finisher (correctly: a touch alone is
how a just-returned branch reads), and nothing in `plan()` could be told that a live agent holds the worktree. Fixed as the
note asks, inside PB2974's single branch-unit hold loop: `prune_worktrees.locked(rows)` is the lock-only half of `owned`
(the same `live_lock` rule `lifecycle()` reads first), `plan_wave.main` passes it as `plan(locked=...)`, and the loop that
holds a unit for an unanswered dispatch holds it for a lock too, the waiting text naming the branch and the lock; a unit is
keyed by `unit_of(branch)`, so every arm (report finisher, unreported unlanded branch, half note) is held the same. The
RESIDUAL the note recorded is a real state and is fixed here too: a note is decided by its newest report, so PB5 (w1090a)
and PB6 (w1090b), two SPLIT reports about ONE branch, planned two finishers over it; `finisher_by_rep` now merges the
unfinished reports of one branch into the group of the branch's newest unfinished report (a newer DONE report of another lead is no target), with the self-test
red on the old code. Tests: `test_plan_wave.py` (locked, normal and drain; owned alone holds nothing; another branch's lock
holds nothing; an unlanded branch with no report is held by its lock; two reports, one branch) and the survey self-test
(`locked` = {agent-live}, a subset of `owned`, none of the ledger or touch rows).
