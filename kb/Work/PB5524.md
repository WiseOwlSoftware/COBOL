# PB5524 - ResolveUponDetail continues after an AMBIGUOUS detail-name match with the first candidate, so a cascading COBOL2046 follows and the COBOL1920 hint suggests a report-name qualification SR2 forbids at 85

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/ReportGroupResolution.cs` (`ReportGroupResolution.Resolve`), `src/WiseOwl.Cobol.Compiler/Binding/ReportSectionBinder.cs` (`ReportSectionBinder.ResolveUponDetail`)

**Mechanism.** Since PB5474, below 2002 `ResolveUponDetail` (line 4315) resolves data-name-1 across the unit. It then tests only `Match.None`; for `Match.Ambiguous` the resolver has already reported COBOL1920 and returned the first candidate (`found[0]`), and the code goes on with it. When another report is declared first, the new own-report check (`ReferenceEquals(owner, model)`, `§1985:XIII.3.19.3 SR2`, checked with `cite.py --check`) then fires a second, cascading COBOL2046 on that first candidate. The COBOL1920 hint it follows suggests `DET OF RPT2`, a qualification SR2 forbids at 85 ("Data-name-1 may be qualified by a report-name" is a later edition's allowance; the 85 text asks for a detail "described in the same report as the control footing report group"). The pattern is the one `DataNameResolutionDriftTests` names: binding the first candidate of an ambiguous reference.

**Fix direction.** Stop at `Match.Ambiguous` as at `Match.None` (the ambiguity is already reported), and make the hint edition-aware so 85 does not suggest a report-name qualifier; witness: two reports below 2002 sharing a detail name, the other report first, with exactly one diagnostic. PB5474's landing file (`kb/Work/PB5474/2026-11-14-landing.md`) records the cross-unit resolution and the 2046 refusal, not this continuation.
