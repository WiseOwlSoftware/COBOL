# PB5544 - IntrinsicBinder's ALL-subscript walk still declines a reference modifier on a qualifier written after the ALL subscript, so the misleading COBOL2363 survives for that spelling

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs#TryBindAllArgument` (the qualification walk that finds the ALL subscript; the arm `else if (q.refModPart().Length > 0) return false;`, about line 3295). Its sibling arm one line above (`q.refModPart() is [{ } first, ..] && first.Start.TokenIndex < trailing.Start.TokenIndex`) was fixed by kb/Work PB5485.

**Mechanism.** PB5485/PB5509 made the walk recognise `name(ALL) OF q(...)` shapes so the argument is bound as an ALL-subscript table argument. For a qualifier that carries a reference modifier and no subscript, the walk still returns `false`, handing the argument to the ordinary data-reference bind, which refuses it with the misleading COBOL2363 that PB5485/PB5509 describe. So one spelling of the same construct keeps the old wrong diagnostic.

**Expected.** Every spelling of an ALL-subscript argument with a reference modifier on a later qualifier takes the same path as the spellings PB5485 fixed (accepted if legal, otherwise refused with the diagnostic that names the actual rule). Decide legality from the reference-modification and ALL-subscript rules of the 2023 standard (cite-check before quoting); the reviewer did not rule on it.

**Fix direction.** Make the walk classify each qualifier by one function (subscript part, reference modifier, position relative to the ALL group) rather than a chain of arms, and add a golden for the declined spelling.
