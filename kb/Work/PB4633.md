# PB4633 - lead from a landed branch's report

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CallBinder.cs:1133` (`CallBinder.ResolvePrototype`)

Pre-existing on origin/main (not introduced by PB4509), in the spelling-(b) arm it re-gated: the second arm calls ResolvePrototype, whose text (line 1144) says the word is neither declared by a PROGRAM specifier, but the word IS declared; no provider answered. Repro not named in the report. Misleading diagnostic.

**Fix (landed).** Re-probe on the wave build (CALL R2103P, CANCEL R2103P, CALL "ZZ" AS R2103P with PROGRAM R2103P declared and no provider): all three drew "neither declared by a PROGRAM specifier" beside the specifier own COBOL5962 (REPO-1, ISO 12.3.8.3 SR14). The one place that speaks the sentence is `CallBinder.ResolvePrototype`, so the fix is there, not at the three callers: it asks `CallBinder.DeclaresProgramSpecifier` (the table `BinderDriver.ProgramPrototypesOf` resolves) and says the word is declared but no program of the group and no external repository entry answers that specifier, which is itself refused (SR14); a word no specifier declares (CANCEL NOSUCH) keeps the "neither declared" sentence. The CALL spelling-(b) branch that tested the same table now asks the same helper. Witness: `ExternalRepositoryResolutionTests.ADeclaredSpecifierNoProviderAnswered_IsNotCalledUndeclaredByCallCancelOrCallAs`. The code and the refusal below 2002 are unchanged, so no golden or negative json changes (the existing pb237-cancel-prototype-undeclared and pb46-call-as-prototype-name pin the code).

**Sites (added by the landing):** `tests/WiseOwl.Cobol.Tests.Conformance/ExternalRepositoryResolutionTests.cs` (`ADeclaredSpecifierNoProviderAnswered_IsNotCalledUndeclaredByCallCancelOrCallAs`, `Refusal1760`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CallBinder.cs` (`CallBinder.DeclaresProgramSpecifier`, `CallBinder.BindCall` spelling-(b) arm), `docs/rearchitecture/DESIGN-external-repository.md` (section 8.2 step 4).
