# PB883 — LANDED — the SUM addend the general format prints and the grammar has never had

Source: the `PB482` report, "New defects" item 2.

## The rule

```
$ python scripts/spec/cite.py --check 13.18.54.3 "The whole clause is referred to as a SUM clause even though the SUM keyword may appear more than once."
  OK  §13.18.54.3 1)  (Syntax rules)
      1) Each data-name-1, identifier-1 or arithmetic-expression-1 is an addend. The whole clause is referred
      to as a SUM clause even though the SUM keyword may appear more than once.
```

SR1 names `arithmetic-expression-1` as one of the three addend forms; SR6 governs which identifiers it may
contain; GR3 gives it COMPUTE semantics with the entry's own size-error indicator (GR1, quoted in PB882).

## The code site

`src/Cobol.Net.Frontend/Grammar/Core/CobolReportWriter.g4` — `sumOperand : dataReference (OF reportName)?`.

Three pieces of work, in this order:

1. a grammar alternative for `arithmetic-expression-1` (and the `OF reportName` qualifier stays on the
   identifier form only);
2. SR6's REPORT SECTION screen over the expression's identifiers — the same screen the data-name form gets;
3. GR3's size-error posture, which is per-ENTRY (PB882's counter) and not per-addend.

## Landed - 2026-09-19, wave 39 (group REPORT-WRITER-SUM)

`status: landed`. The three pieces the note named are done, and the first of them is shared with PB852 as the
note asked: ONE grammar production `reportValueOperand : arithmeticExpression` is referenced by BOTH
`reportSourceClause` and `reportSumClause` (S8.4.3.1.2 Format 2 makes an identifier a primary, so the
identifier form is its degenerate case), `DataBinder.Reports.BareReferenceOf` is the ONE classifier that decides
which form was written, SR6's report-section screen runs through the one walk `ReportSectionNameIn`
(COBOLNET2144), and GR3's size-error posture stays per-ENTRY on PB882's counter. The SUM clause's
`rounded-phrase` came with it (SR3 screened by COBOLNET2143). The dead `sumOperand (OF reportName)?` is deleted:
`dataReference`'s own suffix loop already swallowed `OF word`, so the alternative was unreachable.
`SR-13.18.54.3-1` and `GR-13.18.54.4-3` recorded CONFORMS; `ReportValueOperandDriftTests` pins the sharing.

WARNING - RESIDUE, reported to the registrar rather than fixed here: an expression addend written with a LEADING
parenthesis (`SUM (A * B)`) is still refused, because the lexer's S8.4.3.2.3 SR2 keyword-omitted-intrinsic
subscript trigger on the SUM token pushes SUBSCRIPT mode at that `(` - a DIFFERENT mechanism from this note's,
governed by S13.18.54.3 SR9, and S13.18.54.3 states no parenthesization rule that would force the spelling.
