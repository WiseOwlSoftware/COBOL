# PB3863 — an empty "prediction aborted" reply on a repeated generation is unexplained

**Sites:** `scripts/fuzz_ollama.py#repeat_abort` (the module lands with wave 20261711 group A, so it is on main once
that branch lands)

## The defect

PB3488 counts Ollama's HTTP 500 "prediction aborted, token repeat limit reached" as the model's degenerate reply, not a
RUNNER_ERROR. A generation that was asked again once returned that abort with an EMPTY reply, and `repeat_abort` counted
it as a degenerate reply. Nothing explains why a repeat returned an abort with no text, and it was not reproduced, so
whether it is the model, the server's reload after a pause or the client's handling is unknown. If it is the reload, the
row blames the model for a runner fault: a silent mis-classification.

## Failure scenario (verbatim from the report)

"the unexplained empty 'prediction aborted' reply, site `scripts/fuzz_ollama.py:repeat_abort`". Repro:
`E:\Temp\claude\E--COBOL\7c0e73bd-efb8-4e3d-b25c-0cfc0a034c78\scratchpad\e2e.ps1`.

## Acceptance

- Find the cause by reproducing it (the repro above, a pause then a re-ask) and state it in this note: model, server
  reload, or client.
- An abort with an empty reply on a re-asked generation is classified by its cause, not as a degenerate reply, with a
  self-test arm seen RED first; a genuine repeat-limit abort with text still counts against the model.
- Standing owner rules: fix the root causes, never simply making the diagnostic pass; always be consistent with
  ourselves barring an explicit requirement differently.
