**Rule it breaks:** Every exact-family arm that consumes an argument's Expr must accept every NumX carrier (IntrinsicRenderer.cs:271-277, kb/Work PB2698; SecondsArg :1977-2002 handles U through NumericRenderer.DeU, kb/Work R24); §2023:15.17.3 AR2 constrains argument-2's VALUE only, so its USAGE cannot decide whether the call compiles

**Scenario:** WORKING-STORAGE: 01 D PIC 9(7) VALUE 143951. 01 S PIC 9(20) USAGE COMP-5 VALUE 18867 (an unsigned 16-byte binary-capacity item, PicInfo.IsUnsignedWideBinary, read as NumX.U by NumericRenderer.cs:724). COMPUTE R = FUNCTION COMBINED-DATETIME (D S) under native arithmetic: RenderDec returns null (not alwaysSdidi, no Dec/Real argument), RenderWide returns null (no computed operand), AnyRealArgument is false, so the switch arm at IntrinsicRenderer.cs:463-475 emits CobolDate.CombinedDatetime(<long>, <UInt128 field read>, 0) against the signature CombinedDatetime(long, Int128, int, bool) (CobolDate.cs:833). UInt128 has no implicit conversion to Int128, so the generated C# fails CS1503 and the user sees a backend error on a conforming program. The sibling PB2698 fixed exactly this for ABS/SIGN/INTEGER/INTEGER-PART/FRACTION-PART and SecondsArg for FORMATTED-TIME; CombinedDatetime_ScreensItsArguments_FromEveryCarrier names three carriers and omits the fourth.

**Measured how:** R2 batch finding `codegen-2--code--f2#1` (pair codegen-2--code), read in the pinned tree at 9e65164eb3a9; skeptics rule upheld, scenario upheld, site upheld.

**Spec:** §2023:15.17.3 "Argument-2 shall be in standard numeric time form." (`cite.py --check` passed at collection); §2023:15.17.4 "The equivalent arithmetic expression is as follows" (`cite.py --check` passed at collection)

**Target:** The CombinedDatetime arm takes argument-2 through NumericRenderer.DeU (the R10 Widen funnel, as SecondsArg does) before reading t.Expr/t.Scale, and the IntrinsicCarrierAgreementDriftTests carrier sweep derives its carrier list from NumX's flags for every switch arm that reads RawArg(..).Expr directly, so the next arm is covered automatically

**Design reference:** PB2698.

**Landed (PB6266):** `IntrinsicRenderer.RenderNum`'s `COMBINED-DATETIME` arm binds `NumericRenderer.DeU(RawArg(ic, 1))`. Sweep of the same root: a probe of every numeric intrinsic over an unsigned-wide and a scaled unsigned-wide COMP-5 argument found SQRT, ATAN and ANNUITY over the scaled item failing CS1503 in `NumericRenderer.Real` (its scaled arm handed the UInt128 to `CobolFloat.ScaledToDouble(Int128, int)`), fixed there through `DeU`; `NumericRenderer.ScaledSingle`, the binary32 twin, takes the same funnel. Guard `IntrinsicCarrierAgreementDriftTests.EveryRawArgBinding_EntersTheUnsignedWideFunnel_OrTakesEveryCarrier` (closed list of the two helper bindings that take every carrier). Goldens `cases/15.17.3-Argument-rules/pb6266_combined_datetime_unsigned_wide_comp5` and `cases/15.84.4-Returned-value-rules/pb6266_unsigned_wide_scaled_float_arguments`; negative `pb6266_combined_datetime_2002` (COBOL1502 at --std 2002).

## Landing
- `IntrinsicRenderer.cs#RenderNum` (CombinedDatetime arm): bind a raw argument through `NumericRenderer.DeU` before reading `.Expr`; the drift guard names any binding that does not. `NumericRenderer.cs#Real` / `#ScaledSingle`: an unsigned-wide operand converts to float only through `DeU` (scale 0 `Real` keeps the exact `(double)` cast). Trap: a probe over every numeric function, once per carrier, finds the sibling arms in one compile; `COMPUTE ... = FUNCTION F (S SS)` with `S PIC 9(20) COMP-5` and `SS PIC 9(18)V99 COMP-5`.
