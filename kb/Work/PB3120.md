# PB3120 — LANDED (wave 1071 group F)

**Landed.** The note's arm is reachable only through a STRONGLY-typed group (a plain group with a pointer leaf is refused earlier by the Tier-C island, a different mechanism), and the same record compare hid two siblings. `StrongTypeModel.SameAnalyzedProfile` no longer compares `PicInfo.RestrictedPrototypeName` / `RestrictedTypeName` by record equality: a restricted program- or function-pointer member is asked `PrototypeSignatures.SameType` (the signature, §13.18.60.4 GR25 / GR26, `cite.py --check`: OK), a restricted data-pointer member `StrongTypeModel.SameRestriction` (the declaration it names, GR23, OK), under one private `Comparison` that carries the enclosing signature comparison's `PrototypeBisimulation` and the declaration pairs assumed equivalent (the greatest fixed point; termination for a type restricted back to itself). Sibling arms fixed: the strongly-typed sentence of a signature comparison (`OoConformance.StrongTypeMismatch` -> `StrongTypeModel.SameType` / `EquivalentTypeDeclarations`) now receives the bisimulation (two prototypes naming each other through a strong group were two classes, COBOLNET1959), and `TypeIdentityKey` keys the signature class / folded type-name / declaration instead of the names as written. Code sites: `src/Cobol.Net.Compiler/Binding/Model/StrongTypeModel.cs#SameAnalyzedProfile`, `#Comparison`, `#TypeIdentityKey`; `src/Cobol.Net.Compiler/Binding/PrototypeSignatures.cs#SameDescription`; `src/Cobol.Net.Compiler/Oo/OoConformance.cs#StrongTypeMismatch`. Goldens `2002/pb3120_group_formal_pointer_type`; negatives `pb3120-group-formal-pointer-signature-mismatch`, `pb3120-group-formal-data-pointer-declaration-mismatch`, `pb3120-group-formal-pointer-type-below-2002`. `PrototypePointerTypeDriftTests.EveryPicInfoProfileProjectionElidesTheRestrictedNames` pins that no profile projection leaves a restricted name in the record compare.
