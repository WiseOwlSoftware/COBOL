# PB3120 — the group-formal arm compares the restricted prototype name

Source: the implementer report for PB2495 (merged to main as PR #26), `E:\COBOL-coord\scratch\reports\w1070f-PB2495-report.md`, "New defects", item 1.

**Repro:** `E:\COBOL-coord\scratch\w1070f\probe\grouppairs.cob` gives COBOLNET1513 (per the report; not re-run by the clerk).

**Code site:** `src/Cobol.Net.Compiler/Binding/Model/StrongTypeModel.cs:280` `SameAnalyzedProfile`: `(x with { EditingRules = null, RestrictedTypeDecl = null }) != (y with { ... })` is `PicInfo` record equality, which includes `RestrictedPrototypeName`. The group-formal arm therefore compares the prototype NAME, while PB2464 and PB2495 (both landed) moved the elementary pointer arm to signature comparison (`PrototypeSignatures.Same`).

**Relation:** PB1475 (landed) already rewrote `SameAnalyzedProfile`'s reading of PicInfo equality for the DPC and LOCALE halves; this is the same function and a third field. PB452, PB609, PB817 and PB847 (landed) introduced `RestrictedPrototypeName`. No open note owns this.

Sweep hint for the implementer: any other `PicInfo` field that carries a name which record equality compares.
