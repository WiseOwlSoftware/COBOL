# PB3579 - PB3533 left two reached OPEN paths without a witness

## Lead (PB3533 review lead R1-2, low)

`tests/Cobol.Net.Tests.Unit/Store/CommitRollbackRuntimeTests.cs` (around line 1404) covers a replaced file's re-OPEN in INPUT
and I-O for both organizations, an unsuccessful re-OPEN ('39', '61') and two connectors on a replaced path. Two OPEN paths the
change newly reaches have no witness:

1. **The GR16 write probe (status '37').** `KeyedConnector.RetireWhatWasKeptOfAnotherFile` (PB3576: it was `EndWhatWasKeptOfAnotherFile`) hands the kept state to the registry before
   `FileConnector.Open` asks `HoldsKeptHandle`, so the probe now runs for a replaced file where it used to be skipped. A replaced
   file the run unit cannot open for writing must answer '37' and leave nothing kept.
2. **The `InheritKept` route.** A CANCELled connector's retired kept state is inherited by its replacement; the hook runs after
   the reclaim (per the report). A replacement whose path names another file than the retired state's must retire it again (PB3576).

MANDATORY-PRACTICES I11 requires the abnormal and exception paths to be covered as fully as the success ones.

## Fix shape (for the implementer)

Add the two witnesses beside the existing ones in `CommitRollbackRuntimeTests` (Linux for the replacement itself, both hosts
where the host allows it), expected values from §14.9.27.4 (check each citation with `cite.py --check`).

**Sites:** `tests/Cobol.Net.Tests.Unit/Store/CommitRollbackRuntimeTests.cs` (line 1404 area); the paths under test are in
`src/Cobol.Net.Runtime/IO/KeyedConnector.cs` and `src/Cobol.Net.Runtime/IO/FileConnector.cs`.
