### Finding — `relational-operators` (under-rejects; rows `FMT-8.7.5.1`, `SR-8.7.5.2-2`)

**Mechanism.** comparisonOperator superset unscreened outside START: the one grammar rule shared by every condition admits five spellings outside §8.7.5.1 (IS NOT >=, IS NOT <=, NOT GREATER THAN OR EQUAL TO, NOT LESS THAN OR EQUAL TO, EQUAL THAN) and the only screen for them, ConditionBinder.InGeneralRelationFormat, is asked by the START KEY phrase alone (kb/Work PB333) - IF / EVALUATE / PERFORM UNTIL / SEARCH WHEN / abbreviated combined relations / >>IF accept them silently at strict mode in every edition

**Repro.** probe/relop/relneg.cob: 01 A PIC 9 VALUE 5. 01 B PIC 9 VALUE 3. ... IF A IS NOT >= B ... / IF A NOT <= B ... / IF A NOT GREATER THAN OR EQUAL TO B ... / IF A NOT LESS THAN OR EQUAL TO B ... / IF A EQUAL THAN B ...; also relabb.cob 'IF A > B AND NOT >= C' and relcce.cob '>>IF X NOT >= 3'. cobol relneg.cob --std 2023 --run (and --std 85).

**Expected from the spec.** §8.7.5.1 prints the complete operator set: Format 1 GREATER THAN, >, LESS THAN, <, EQUAL TO, =; Format 2 GREATER THAN OR EQUAL TO, >=, NOT LESS THAN, NOT <, LESS THAN OR EQUAL TO, <=, NOT GREATER THAN, NOT >, NOT EQUAL TO, NOT =, <> (IS/THAN/TO optional). §8.8.4.2.2 Format 1 brackets [NOT] on the first six alternatives only, and §8.8.4.12.4's NOTE states 'NOT cannot immediately precede an extended-relational operator'. None of the five extra spellings is a relational operator, so each program is non-conforming source: a strict-mode compile error (warning under --permissive) citing §8.7.5.1 / §8.8.4.2.2.

**Observed / reasoning.** All five compile with no diagnostic at strict --std 2023 and --std 85 and run (N1..N5 = F T F T F, i.e. MapOperator silently inverts the OR-EQUAL operator); 'A > B AND NOT >= C' prints X3 T; '>>IF X NOT >= 3' takes the ELSE branch. InGeneralRelationFormat already encodes exactly the right exclusion ('[NOT] is not printed on the OR-EQUAL four', 'EQUAL TO, never EQUAL THAN') and its doc comment names comparisonOperator a SUPERSET, but grep shows its only caller is KeyedIoBinder (START). The positive half is sound: every printed spelling evaluates correctly (relpos.cob). Root-cause fix: one screen at the comparisonOperator node for EVERY consumer (a validation pass visiting ComparisonOperatorContext, or the grammar narrowed to the printed set with the START-specific not-equal exclusion kept in KeyedIoBinder), plus a drift test; the >>IF evaluator's duplicated MapOperator (CompileTimeExpressionEvaluator) should ride the same classification.
