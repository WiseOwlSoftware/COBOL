# PB1034 — OPEN

## Measured
`scratchpad` probe `a01ifn.cob` (reproduced in PB1033): `IF A NOT >= B DISPLAY "LT"` compiles with no diagnostic
and prints `LT`.

## The rule
`cite.py --check 8.8.4.2.2 "Figure notes (relation condition Format 1 (General-relation) syntax diagram)"` → OK. The
rendered format prints `IS [ NOT ] GREATER THAN`, `>`, `LESS THAN`, `<`, `EQUAL TO`, `=` and then
`IS GREATER THAN OR EQUAL TO` / `>=` / `IS LESS THAN OR EQUAL TO` / `<=` / `<>` **without** the `[ NOT ]` bracket, and
there is no `EQUAL THAN` alternative. PB333 derived this for START and built the membership test
`ConditionBinder.InGeneralRelationFormat`; its landing section names this relation-condition half as a registrar lead.

## Decision already taken (no owner question)
The lander asked for a dialect decision. None is needed: CLAUDE.md rule 1 lets the GnuCOBOL/IBM precedence settle
implementor LATITUDE only, never a vendor extension, and vendor-dialect constructs are PARKED by owner decision 2
(`tests/version-matrix/vendor-constructs.json`). So strict mode rejects the spelling; `--permissive` is the
removed-construct migration lane and does not cover it either.
