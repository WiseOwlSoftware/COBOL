# PB5204 - the build guard timed transcripts it could have read

**Sites:** `scripts/hooks/fleet_active_build.py` (`is_live`, `finished`, `self_test`).

**What was wrong.** `is_live` called a subagent live when its transcript was written in the last 120 s, or ended on an
unanswered tool call written in the last 660 s (PB1702). Both are guesses for an agent whose state the transcript does not
state. But a transcript does state its agent's END: an Agent-tool subagent's last record is an assistant message with
`stop_reason: end_turn`, and a workflow agent's last record is its StructuredOutput tool result marked `toolEndsTurn: true`.
On 2026-11-10 the refute-85 workflow had returned all ten agents' results, yet the guard refused a build of a separate tree
("1 subagent(s) are LIVE") for the last refuter's write window, and the operator waited it out.

**Fix (landed).** `finished(path)` reads the transcript's tail: the last assistant or user record decides; an assistant
record with `stop_reason == "end_turn"` and no `tool_use`, or a tool result with `toolEndsTurn` true, is the end. `is_live`
returns False for a finished transcript before any window applies. An assistant record without a `stop_reason` is one block
of a message still being written, so it does not count; a resumed subagent appends records after its end, so it is live
again. Any parse problem leaves the windows in force.

**Evidence.** The self-test gains five arms (a final answer and a workflow return written 5 s ago are not live; a text
block with no stop_reason, an ordinary tool result 5 s ago, and a finished-then-resumed transcript are live); the first two
fail under the old rule (age 5 s is inside the 120 s window). Over the session's 20 real subagent transcripts (all ended),
`finished` is True for 20 and `is_live` for none.
