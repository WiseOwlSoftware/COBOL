# PB5204 - the build guard timed transcripts it could have read

**Sites:** `scripts/hooks/fleet_active_build.py` (`is_live`, `finished`, `self_test`).

**What was wrong.** `is_live` called a subagent live when its transcript was written in the last 120 s, or ended on an
unanswered tool call written in the last 660 s (PB1702). Both are guesses for an agent whose state the transcript does not
state. But a workflow agent's transcript does state its END: its last record is its StructuredOutput tool result marked
`toolEndsTurn: true`, and the workflow never wakes it again.
On 2026-11-10 the refute-85 workflow had returned all ten agents' results, yet the guard refused a build of a separate tree
("1 subagent(s) are LIVE") for the last refuter's write window, and the operator waited it out.

**Fix (landed).** `finished(path)` reads the transcript's tail: the last assistant or user record decides; a tool result
with `toolEndsTurn` true is the end, and `is_live` returns False for it before any window applies. An assistant message with
`stop_reason: end_turn` is NOT an end (review R1-1): an Agent-tool subagent ends a turn while its own background build or
test runs and is woken by that task's notification (41 such records in the project's 3692 subagent transcripts are followed
by more work, one 22 minutes later), so that shape keeps the windows. Over the same 3692 transcripts no `toolEndsTurn`
record is followed by more work. Any parse problem leaves the windows in force.

**Evidence.** The self-test gains six arms: a workflow return written 5 s ago is not live (fails under the old rule,
inside the 120 s window); an end_turn 5 s ago, a text block with no stop_reason, an ordinary tool result 5 s ago and a
finished-then-resumed transcript are live; an end_turn quiet 5 minutes is not (the window decides).
