# PB5300 - at --std 85 the file description entries of one external file connector are never compared: two EXTERNAL FDs that differ in LABEL RECORDS (STANDARD and OMITTED) compile and run, because ExternalFileConnectorRules.Check compares only the file control entry's FileEntryIdentity and no FD identity exists

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/ExternalFileConnectorRules.cs` (`Check`)
- `src/WiseOwl.Cobol.Compiler/Binding/FileEntryIdentity.cs` (`Segments`)

**What PB5069 fixed and what it left.** kb/Work PB5069 (landed) made `ExternalFileConnectorRules.Check` compare the FILE CONTROL entries of an external file connector across the units of a compilation group at every edition. It compares OPTIONAL, ASSIGN, RESERVE, organization, access mode, RELATIVE KEY and PADDING CHARACTER through `FileEntryIdentity.Segments` (COBOL6847, COBOL1575). Its landing paragraph states what it did not do: "the FILE DESCRIPTION entry's own run-unit agreement rules (§1985:VII.3.6.3 GR4 LABEL RECORDS, the BLOCK CONTAINS, CODE-SET, RECORD, LINAGE integer, VALUE OF and report-file rules) need an FD identity beside `FileEntryIdentity`; nothing compares them." This note holds that remainder.

**Mechanism.** Each 1985 FD clause that an external connector shares carries its own agreement rule, for example "all LABEL RECORDS clauses in the run unit which are associated with this file connector must have the same specification" (§1985:VII.3.6.3 GR4). The relative FD imports it (§1985:VIII.3.2.4 GR4). `ExternalFileConnectorRules.Check` compares only `FileEntryIdentity.Segments`, which describe the SELECT entry, so two EXTERNAL FDs of one connector that disagree in an FD clause compile, and the run unit shares the connector without complaint.

**Found by.** The operator's re-read of the rows fixed since their first read (`out-reread/reread-1.json`, at main eb2b01f730) read `1985-GR-VIII.3.2.4-4` PARTIAL on this rule.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty, and the rows this note claims are the rule ids below.

**Rules (1 read here, 5 siblings; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-GR-VIII.3.2.4-4` - `§1985:VIII.3.2.4 GR4` (re-read: PARTIAL, harm: under-rejects), with `§1985:VII.3.6.3 GR4`: "all LABEL RECORDS clauses in the run unit which are associated with this file connector must have the same specification".
- The sibling rows of the same mechanism. PB5069's 2026-11-10 addendum listed them, and its landing left them, as quoted above:
  - `1985-GR-VII.3.6.3-4` (`§1985:VII.3.6.3 GR4`, the sequential LABEL RECORDS twin)
  - `1985-GR-VII.3.3.3-5` (`§1985:VII.3.3.3 GR5`: "all BLOCK CONTAINS clauses in the run unit which are associated with that file connector must have the same value")
  - `1985-GR-VII.3.4.4-3` (`§1985:VII.3.4.4 GR3`: "all CODE-SET clauses in the run unit which are associated with that file connector must have the same character set")
  - `1985-GR-VII.3.8.4-2` (`§1985:VII.3.8.4 GR2`: "must specify the same values for integer-1 or integer-2 and integer-3")
  - `1985-GR-VII.3.9.4-2` (`§1985:VII.3.9.4 GR2`: "all VALUE OF clauses in the run unit which are associated with that file connector must be consistent"; the implementor specifies the rules)

  Only the LABEL RECORDS case was rerun here.

**Repro (`E:/COBOL-coord/scratch/coderead-85/out-reread/work-reread-1/c9/lx2.cob`).** Two programs in one source, MAINL and SUBL. Each has `SELECT RFILE ASSIGN TO "LX2.DAT" ORGANIZATION IS RELATIVE ACCESS MODE IS RANDOM RELATIVE KEY IS RK`, `FD RFILE IS EXTERNAL` and `01 RK PIC 9(4) EXTERNAL`. MAINL's FD says `LABEL RECORDS ARE STANDARD` and SUBL's says `LABEL RECORDS ARE OMITTED`. MAINL writes record 1 and CALLs SUBL, which reads it. Run: `cobol.exe --std 85 --source-format fixed --run lx2.cob`.

**Observed (the build of origin/main f2cf36fd15, rerun 2026-11-11; main changed only `IndexedConnector.cs` under `src/` up to eb2b01f730).** Exit 0, no diagnostic, prints `SUB EXT1`.

**Expected (from the 1985 text).** A diagnostic on SUBL's LABEL RECORDS clause, given within the compilation group as the file control entries' disagreement is (COBOL6847).

**Fix direction (root cause, CLAUDE.md rule 4).** Add an FD identity beside `FileEntryIdentity`, built from the FD clauses each edition's agreement rules name. `ExternalFileConnectorRules.Check` compares it in the same loop, so every FD rule above becomes one row of one table. Record the implementor's VALUE OF consistency rule in docs/CONFORMANCE.md. Test one disagreeing pair per clause.
