# PB602 — OPEN — a decorated place answers "which item" with the item underneath

Found 2026-09-05 by the `PB236` implementer (its report §12 D); the row moves here from PB236 so PB236 can land
whole. Re-derived on this tree for this note.

## Repro (`--std 2023`)

```cobol
       SELECT RLF ASSIGN … ORGANIZATION RELATIVE RELATIVE KEY IS WS-RK.
       01 WS-RK PIC 9(4).
       ...
           START RLF KEY IS = WS-RK(1:2)      *> compiles clean; positions on the number the first two characters spell
```

A key of `12` positions the file at relative record `0` — §12.4.5.13.4 GR1 makes `1` the first legal relative
record number — silently. A `66 ALIAS RENAMES WS-RK.` (no THRU) passes the same screen where the THRU form is
correctly rejected.

## The rule

§14.9.41.3 SR5 (quoted from `specs/ISO_COBOL.md`; `cite.py --check 14.9.41.3 "For relative files, data-name-1, if
specified, shall be the data item specified in the RELATIVE KEY clause in the associated file control entry."`
is the fix's first step). "Shall BE the data item" is an identity over DATA ITEMS; a reference-modified slice is
a different unique data item (§8.4.3.3.4), and a RENAMES alias is a different data item over the same storage.

## The mechanism

`PlaceDecorator.Item => Inner.Item` (`src/Cobol.Net.Compiler/…/Places`): a decorated place — a reference
modification, a RENAMES alias, a view — reports the UNDERLYING item as its `Item`, so every screen written as
"is `place.Item` the required item?" asks about storage where the rule asks about the data item. PB236 measured
it at START's SR5; PB128's `ScreenResultant` (the arithmetic resultant category screen) had already met it and
routed around it by testing `p is not RefModPlace` on the Place rather than the item — a fix at one caller for a
property of the Place model. The real fix is general: a decorated place must answer identity questions as
itself, and the screens that legitimately want the storage item (a few) must ask for it by a differently-named
member.

## Fix shape

Give `Place` two distinct questions — the data item the reference DENOTES (a ref-mod slice, an alias, a view each
denote their own) and the storage item it OCCUPIES — and sweep every `.Item` consumer in the binders to the one
it means (`grep -rn "\.Item\b" src/Cobol.Net.Compiler/Binding`), starting with START's SR5/SR6 and the
CORRESPONDING, arithmetic-resultant and file-key screens; PB128's Place test then collapses into the general
answer. Negative goldens for the START slice and the non-THRU alias (all four editions); positive controls for
the plain RELATIVE KEY item and the legal THRU cases.
