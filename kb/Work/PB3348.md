# PB3348 — inventory row notes are prose no check reads

Filed 2026-10-17 by the clerk from `w1111c-PB3339-report.md` "New defects (note-ready)", first bullet:

> Inventory notes that name a moved mechanism are checked by nothing, tree-wide. SpecTraceabilityInventoryDriftTests checks
> that anchors resolve, never that a row's notes describe the code it names. The general shape is a per-file version of this
> branch's witness wherever a file's citations mean "implements". That is a tree-wide design question.

Grep of kb/Work by `SpecTraceabilityInventoryDriftTests` found 20 notes. The closest are PB3278 (the code-location resolver
matches a whole-file word, so a deleted member still resolves while its name survives in a comment: the ANCHOR check is too
weak) and PB3122 (the test-ref resolver is written twice). Neither is this: PB3278 is about whether the anchor resolves;
this note is about the free-text `notes` that sit beside a resolving anchor and say what the mechanism does. They share
the test class and not the mechanism, so this is a separate note, related to PB3278.

## Mechanism
A traceability-inventory row carries a `code-location` (checked: it must resolve) and a notes string that names the
mechanism, the helper or the file that "implements" the rule. When a mechanism moves, is renamed or is replaced, the anchor
may keep resolving (PB3278) and the prose keeps naming the old place. Nothing compares the two. The report's example was
the PB3339 branch, which had to hand-correct row notes describing a sort/merge mechanism that had moved.

## Code sites
`tests/WiseOwl.Cobol.Tests.Unit/` `SpecTraceabilityInventoryDriftTests` (the class `drift_rules.py` names for
`traceability-inventory.json`); the resolver is the one PB3278 describes. Find the exact lines with
`python scripts/spec/where.py` or by `LSP workspaceSymbol`; not re-measured by the clerk.

## Fix shape (a design question, as the report says)
Give a row's mechanism reference a STRUCTURED field the resolver checks (a `mechanism` list of `file#Member` anchors, the
same grammar as `code-location`), and have the test refuse a notes string that names a `Type.Member` or a `file#Member`
that is not in the row's anchors or does not resolve. Then a moved mechanism fails the drift test instead of leaving
stale prose; the next case is automatic (CLAUDE.md rule 5). Decide with PB3278 whether the one resolver serves both.
