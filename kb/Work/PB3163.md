# PB3163 — a run unit writes the host process's exit code

Source: `E:\COBOL-coord\scratch\reports\w1078c-PB2099-report.md` (carried from `w1077e-PB2099-report.md`). The w1078c implementer did not re-probe it.

- Code site: `src/Cobol.Net.Runtime/Control/RunUnit.cs` (`ExitStatus` setter and `StartAfter`).
- Observed (as reported): a run unit writes the host process's exit code. Silent. An independent root from PB1178 (the int32 narrowing of the same value; landed) and part of the host-surface area of PB2099 (held by in-flight branches, not edited here).
- Expected: the exit status of a run unit is delivered to the host through the host surface; the run unit does not mutate the process-wide exit code of an embedding host.

## Landed (wave 1080, group F)

Re-probe on a fresh Debug build: a host (Roslyn-compiled C#, its own process) that set `Environment.ExitCode = 5` and then ran
`STOP RUN WITH ERROR STATUS 24` through `ProgramRegistry.RunMain` read `process=24`: the `RunUnit.ExitStatus` setter wrote the
host's cell at the write site. Two more writers shared the root: `StartAfter` (every `RunUnit.Begin`/`Run` restated the cell
to 0) and `ProgramTable.AbnormalTermination` (a fatal condition wrote 1), the abnormal arm the note did not name.

Root cause: the run unit's termination status was modelled as the PROCESS exit code instead of as the run unit's own state.
Fix: `RunUnit.ExitStatus` is plain run-unit state; `AbnormalTermination` sets it to 1; the one boundary that IS the process,
`ProgramTable.RunModule` (the generated `Main`'s single statement; DOC-A.1-167: a standalone executable is its own host),
delivers it to `Environment.ExitCode` once, in a `finally` so STOP RUN's unwind is covered, clamped by `CobolNum.Position32`.
`RunMain` (the host entry) and `RunUnit.Run` write nothing. Witness: `RunUnitHostExitCodeTests`. The Console-encoding
replacement in `StandardStreams.EnsureUtf8` (run on every `RunMain`) is a sibling host-process mutation of another kind and
is filed as a lead in the wave report.
