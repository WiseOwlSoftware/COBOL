# PB3644 — a merge-queue bounce's reds are not run first by the re-gate

**Sites:** `scripts/gate_plan.py` (`previous_gates`, `read_reds`), `scripts/run_gate_legs.py` (`Host.plan`), `scripts/orchestrator/queue_facts.py`.

## What happens

PB3155 made tier 0a (the reds of the previous gate) read build-local's previous run and `TestResults/linux-gate/*.trx`, and recorded as "not covered here, by design" that a merge-queue BOUNCE's reds live in GitHub's CI run, not in the worktree. A finisher's re-gate after a bounce therefore does not run the tests that failed in the queue first; it plans them by impact like any other test. That is the case tier 0a exists for, and no note owned it.

## Fix direction

Give `previous_gates` one more red source: the failing tests of the bounced pull request's `merge_group` run, downloaded (artifact or job log) by the one GitHub reader, `queue_facts.py`, and written where the planner reads reds. Pin it with a fixture beside PB3155's arms.
