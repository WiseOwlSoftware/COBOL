# PB3644 — a merge-queue bounce's reds are not run first by the re-gate

**Sites:** `scripts/gate_plan.py` (`previous_gates`, `read_reds`), `scripts/run_gate_legs.py` (`Host.plan`), `scripts/orchestrator/queue_facts.py`.

## What happens

PB3155 made tier 0a (the reds of the previous gate) read build-local's previous run and `TestResults/linux-gate/*.trx`, and recorded as "not covered here, by design" that a merge-queue BOUNCE's reds live in GitHub's CI run, not in the worktree. A finisher's re-gate after a bounce therefore does not run the tests that failed in the queue first; it plans them by impact like any other test. That is the case tier 0a exists for, and no note owned it.

## Fix direction

Give `previous_gates` one more red source: the failing tests of the bounced pull request's `merge_group` run, downloaded (artifact or job log) by the one GitHub reader, `queue_facts.py`, and written where the planner reads reds. Pin it with a fixture beside PB3155's arms.

Report `w20261029a-PB3112-report.md` (PB3112, landed in PR #500), new defect (PB3155's lead, unfiled).

## Landing (wave 20261104, group A3)

Re-probed on this build: `gate_plan.previous_gates` read only build-local's previous run and `TestResults/linux-gate/`,
so a bounced pull request's reds (in GitHub's merge-group run) never reached tier 0a. Probed against the real repository:
merge-group runs are on `gh-readonly-queue/main/pr-<n>-<sha>` and a failed one (run 40161989736, PR 549) keeps
`test-results-*` artifacts, one directory per artifact, that `gh run download --pattern` fetches (195 MB, 15 trx files) and
`gate_plan.read_reds` reads in 1.3 s (3 reds found). A failed run with no artifacts (run 40156159979) is handled as such.

- **One GitHub reader.** `queue_facts.fetch_bounce_results(branch, dest)` finds the branch's open pull request, its newest
  `merge_group` run, and, when that failed (`failure`, `timed_out`; a `cancelled` group is no bounce), downloads the test
  artifacts into `dest`; it replaces `dest` on a new bounce, downloads a run once (a provenance marker), empties it when
  there is none and leaves it as it was when GitHub cannot be asked.
- **One planner source.** `gate_plan.CI_BOUNCE_RESULTS` (`TestResults/ci-bounce`) is the third source of
  `previous_gates` (read deep: one subdirectory per artifact); `run_gate_legs.Host.fetch_bounce_results` fills it before
  `Gate._plan` plans, so every gate, an implementer's or a finisher's, plans a bounce's reds into tier 0a.
- Tests: `queue_facts` (9 arms: newest failed run of exactly this PR, once-only download, passed/cancelled/no-PR empty,
  expired artifacts, non-observation), `gate_plan` (deep read, tier 0a by name key, empty source), `run_gate_legs` (the real
  Host fetch feeding `previous_gates`, a dead GitHub, a detached HEAD).
