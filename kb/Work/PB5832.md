# PB5832 - at --std 85 an integer argument of an intrinsic function that is a product, an item quotient inside an argument list, or an expression holding a numeric function compiles and is silently truncated (FACTORIAL, MOD, RANDOM, CHAR, and the date functions' integer arguments)

**Ruling: UPHELD (a), harm under_rejects, and wrong_answer.** At `--std 85` an integer argument that is a product (`WN * 0.5`), a quotient of two items inside a larger argument list (`A / B`), or an expression holding a numeric function (`FUNCTION SQRT (N) + 64`) compiles and is silently truncated: FACTORIAL, MOD, RANDOM, CHAR. A quotient written alone is refused. The ruling's session ran it: `intarg.cob` printed `FACT(WN*0.5) 00000001` and `MOD(A/B,3) 00000000` with no diagnostic (WN is 3, A is 7, B is 2). The checker's confidence: high. Severity MAJOR: a wrong-answer defect is at least MAJOR.

**Mechanism 1, ruled, with three more rows (the ruling's paragraph, unchanged).** `§1989:A.2.2 AR4` requires of an integer argument "An arithmetic expression which will always result in an integer value" (cite.py OK), and `§1989:A.2.3 GR2` says "A numeric function may not be referenced where an integer operand is required" (cite.py OK). The landed kb/Work PB1526 left
this screen open by design because a run-time check (EC-ARGUMENT-FUNCTION) catches a non-integer value; that check
exists only from 2002, and the checker's `intec23.cob` shows it firing at 2023. At 85 nothing catches it. So the
2023 verdicts stand and 1985 lacks its own arm, as kb/Work PB5208 already ruled for the power shape of the same
screen. The checker also found the stored agreement on three rows of earlier slices wrong on the same mechanism:
`1989-AR-A.2.12.3-1`, `1989-AR-A.2.13.3-1` and `1989-AR-A.2.2-4`. I rule them contradicted with the four above:
their reader and refuter agreed without trying a product or a function term.

**Rows (SEVEN).** `1989-AR-A.2.14.3-1`, `1989-AR-A.2.28.3-1`, `1989-AR-A.2.35.3-1`, `1989-AR-A.2.9.3-1`, and the three of earlier slices `1989-AR-A.2.12.3-1`, `1989-AR-A.2.13.3-1`, `1989-AR-A.2.2-4`. `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094), so the rows are named here. The two format rows `1989-FMT-A.2.12.2` and `1989-FMT-A.2.13.2` of the same slice are REJECTED: the general formats of DATE-OF-INTEGER and DAY-OF-INTEGER are right, and the integer requirement is their argument rules', which this note covers.

**Why PB1526's "fail-open by design" does not reach 1985 (the checker's sentence).** PB1526's 'fail-open by design' does NOT reach 85: its stated premise is that the run-time EC-ARGUMENT-FUNCTION test makes the open screen safe (§2023:15.3), and that test exists only from 2002; intec23.cob shows it fires at 2023 (fatal EC-ARGUMENT-FUNCTION 'the intrinsic integer argument 1.5 is not an integer'), while 1985 has no exception condition at all. This note belongs with kb/Work PB5208 (the power shape of the same screen, an 85 under-rejection, landed) and kb/Work PB1526 (the fail-open ruling), both in `related`.

**The checker's evidence.** Each shape is a missing witness arm of `NotAlwaysIntegral`: no product arm; the quotient arm only at the root over item/literal; a numeric-function term clears `AdditiveSpine.RestIntegral`. The compiler refuses the root quotient `WN / 2` (COBOL1627, `intctl.cob`) but compiles the other shapes and truncates silently at 85 (`intarg.cob`). Observed at `--std 85` (exit 0): FACTORIAL(1)=1, MOD(3,3)=0, RANDOM seeded as RANDOM(1), CHAR(65)='@', DATE-OF-INTEGER(2)=16010102, DAY-OF-INTEGER(2)=01601002. The same at 2023 with checking off by default. `intec23.cob` at 2023 (exit 1): `abnormal run-unit termination: EC-ARGUMENT-FUNCTION (fatal): the intrinsic integer argument 1.5 is not an integer`. No 2023 row is wrong: at 2023 PB1526's ruling holds. The neighbours `AR-15.36.3-1`, `AR-15.64.3-1`, `AR-15.75.3-2`, `AR-15.15.3-1`, `AR-15.22.3-1` and `AR-15.24.3-1` keep their verdicts. A fix that adds the arms edition-free (as PB5208 did) also refuses them at 2023, which the 2023 "shall be specified" allows.

`intarg.cob` (compiles at `--std 85` and at `--std 2023`, exit 0; each integer argument below is truncated):

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. INTARG.
      * B9 MECHANISM 1: INTEGER ARGUMENTS THAT ARE NOT ALWAYS
      * INTEGRAL (A PRODUCT, AN ITEM QUOTIENT, A NUMERIC-FUNCTION
      * TERM). EACH MUST BE REFUSED BY 1989 A.2.2 TYPE 4.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  WN   PIC 9      VALUE 3.
       01  A    PIC 9      VALUE 7.
       01  B    PIC 9      VALUE 2.
       01  N    PIC 9(3)   VALUE 2.
       01  R    PIC 9(8).
       01  RF1  PIC 9V9(8).
       01  RF2  PIC 9V9(8).
       01  C    PIC X.
       PROCEDURE DIVISION.
       P1.
           COMPUTE R = FUNCTION FACTORIAL (WN * 0.5).
           DISPLAY "FACT(WN*0.5) " R.
           COMPUTE R = FUNCTION MOD (A / B, 3).
           DISPLAY "MOD(A/B,3) " R.
           COMPUTE RF1 = FUNCTION RANDOM (WN * 0.5).
           COMPUTE RF2 = FUNCTION RANDOM (1).
           IF RF1 = RF2
               DISPLAY "RANDOM(WN*0.5) = RANDOM(1) " RF1
           ELSE
               DISPLAY "RANDOM DIFFERS " RF1 " " RF2.
           MOVE FUNCTION CHAR (FUNCTION SQRT (N) + 64) TO C.
           DISPLAY "CHAR(SQRT(N)+64) [" C "]".
           COMPUTE R = FUNCTION DATE-OF-INTEGER (FUNCTION SQRT (N) + 1).
           DISPLAY "DOI(SQRT(N)+1) " R.
           COMPUTE R = FUNCTION DAY-OF-INTEGER (FUNCTION SQRT (N) + 1).
           DISPLAY "DAYOI(SQRT(N)+1) " R.
           STOP RUN.
```

**Expected:** each of FACTORIAL (WN * 0.5), MOD (A / B, 3), RANDOM (WN * 0.5), CHAR (FUNCTION SQRT (N) + 64), DATE-OF-INTEGER and DAY-OF-INTEGER (FUNCTION SQRT (N) + 1) refused at 85 as FACTORIAL (WN / 2) is (`§1989:A.2.2 AR4`, `§1989:A.2.3 GR2`). **Observed:** `FACT(WN*0.5) 00000001`, `MOD(A/B,3) 00000000`, `RANDOM(WN*0.5) = RANDOM(1) 0.24866858`, `CHAR(SQRT(N)+64) [@]`, `DOI(SQRT(N)+1) 16010102`, `DAYOI(SQRT(N)+1) 01601002`.
