# PB805 — OPEN — the migration mode's restored words have no rule about which reading wins

Filed 2026-09-09 by the registrar from the PB792 implementer's report (§"New defects", paragraph B), which was
never filed as a note. **Three of that paragraph's statements were re-derived on main at `d497f3c7` and two of
them do not hold** — see the premise corrections. The correction is the reason this is MAJOR rather than a
maintainability note: the paragraph filed it as *"Harm: none today"*, and the harm is live and reproducible.

## Reproduced on main — legal source, accepted strict, REJECTED permissive

`value_groupusage2.cob`, a COBOL-2002 national group item:

```cobol
       01 G VALUE N"AB" GROUP-USAGE NATIONAL.
          05 A PIC N(2).
```

The clause order is licensed by §13.16.3 4) — `cite.py --check 13.16.3 "The remaining clauses may be written in
any order"` → **OK, §13.16.3 4)**:

> If the entry-name clause is specified, either the data-name format or the filler format may be specified and
> the entry-name clause shall immediately follow the level-number. … **The remaining clauses may be written in
> any order.**

`cite.py --check 13.18.29 "GROUP-USAGE"` → **OK, §13.18.29** (GROUP-USAGE clause).

| invocation | exit | diagnostics |
|---|---|---|
| `cobol --std 2002 value_groupusage2.cob` | **0** | none |
| `cobol --std 2023 value_groupusage2.cob` | **0** | none |
| `cobol --std 2002 --permissive value_groupusage2.cob` | **70** | COBOLNET0901 (warning) + COBOLNET1639 ×2 + COBOLNET1585 |
| `cobol --std 2023 --permissive value_groupusage2.cob` | **70** | same |

```
value_groupusage2.cob(5,25): warning COBOLNET0901: 'GROUP-USAGE' is a reserved word in COBOL-2002 and cannot be
    used as a user-defined word (ISO 8.9)
value_groupusage2.cob(5,25): error COBOLNET1639: data item 'G': the VALUE operand 'GROUP-USAGE' is not a literal …
value_groupusage2.cob(5,37): error COBOLNET1639: data item 'G': the VALUE operand 'NATIONAL' is not a literal …
value_groupusage2.cob(5,8):  error COBOLNET1585: data item 'G': a data-item VALUE clause (Format 1) takes exactly
    one literal; a list of literals requires the Format 2 table form's FROM (subscript) phrase (ISO 13.18.63.2)
```

⛔ **The migration mode exists to accept MORE than the strict compiler, and here it accepts strictly less.** A
program `--std 2002` compiles clean fails under the flag whose documented purpose is to get older programs
through. That inverts the mode's contract, and it is the same greedy-operand-list mechanism [[PB792]] landed
against — [[PB792]] fixed *which words the mode restores*; it did not write down *which reading wins for the
ones it legitimately does restore*.

## Expected from the spec vs observed

`cite.py --check 8.3.2.1 "Reserved words shall not be used as user-defined words or system-names"` → **OK,
§8.3.2.1 1)**. At COBOL-2002 and later, §8.9 reserves GROUP-USAGE, so the ONLY conforming reading of the source
above is the §13.18.29 GROUP-USAGE clause; there is no reading in which `GROUP-USAGE` and `NATIONAL` are VALUE
operands. `--permissive` is not the standard — it is this compiler's migration axis — but the reading it picks
for a restored word has to be *decided*, and nothing decides it: ANTLR's ALL(\*) prediction does, by which
alternative happens to stay viable to the end of the entry.

Observed: the operand loop wins, both words are consumed, the entry loses its GROUP-USAGE clause, and three
errors are raised about operands the programmer never wrote.

## The code sites

**The admission** — `src/Cobol.Net.Editions/ReservedWords.cs:132` `AdmitsAsUserWord`, routed through
`EditionSeverityPolicy`. `UserWordVerdictAt` (`:100`) answers `Removed` for any spelling reserved at the target
edition but NOT at some older one, and `EditionSeverityPolicy` downgrades `Removed` to a warning under
`--permissive`, so the slot admits the word. That is [[PB792]]'s landed design and it is correct on its own
axis.

**The guards** — `src/Cobol.Net.Frontend/Grammar/Core/CobolData.g4`:

```
:642    | (VALUE | VALUES) (IS | ARE)? valueItem ({!(is2002() && TokenStream.LA(1)==PROPERTY)}? COMMA? valueItem)*
:698    | valueClauseOperand ({!(is2002() && TokenStream.LA(1)==PROPERTY)}? valueClauseOperand)*
```

One spelling, hand-written, twice. (⚠ the report cited `:642` and `:684`; on this tree the second site is
`:698` — an inherited line number, corrected here.)

**The operand rule that makes the swallow possible** — `CobolExpressions.g4:31` `valueClauseOperand :
unaryExpression | nonNumericLiteral`, and `unaryExpression` reaches `cobolWord`.

## ⛔ Measure the complement — FOUR more words carry the same verdict and no guard

`feedback_measure_the_selectors_complement`: the paragraph named PROPERTY and stopped. Derived from
`tests/version-matrix/reserved-words.json` + `CobolWords.g4`, over every word that can BEGIN a
`dataDescriptionClause` alternative:

| clause-initial word | user-word verdict at 2002/2014/2023 | rides `cobolWord`? | guarded? |
|---|---|---|---|
| `PROPERTY` | Removed | yes (`CobolWords.g4:86`) | ✅ `CobolData.g4:642`, `:698` |
| `GROUP-USAGE` | Removed | yes (`:61`) | ⛔ **no — the repro above** |
| `CONSTANT` | Removed | yes (`:33`) | ⛔ no |
| `DEFAULT` | Removed | yes (`:38`) | ⛔ no (guarded only at `initializeOperandList`, `CobolData.g4:751`) |
| `PRESENT` | Removed | yes (`:82`) | ⛔ no |
| `TYPEDEF`, `BASED` | Removed | **no** — dedicated tokens, not `cobolWord` alternatives | n/a |
| every other clause-initial word (PICTURE, USAGE, OCCURS, VALUE, SIGN, BLANK, EXTERNAL, GLOBAL, TYPE, SAME, ANY, DYNAMIC, SELECT, CLASS, DESTINATION, INVALID, VARYING, …) | NotYetIntroduced (reserved at every edition) | — | n/a, nothing to restore |

Measured, not deduced, for each of the four unguarded ones:

- **GROUP-USAGE — SWALLOWED** (the repro above). Its clause continues with `NATIONAL`, which is *also* a
  `cobolWord` alternative, so the swallowed reading stays viable to the closing period and greed wins.
- **DEFAULT — not swallowed today.** `05 A PIC X(2) VALUE "AB" DEFAULT IS "ZZ".` draws COBOLNET1708 (the
  declined VALIDATE facility) at `--std 2002` as an error and at `--std 2002 --permissive` as a warning: the
  clause is still recognized, because `IS "ZZ"` cannot continue an operand list and prediction backs off.
- **PRESENT — not swallowed today**, same reason (`WHEN N = 1` does not continue the list).
- **CONSTANT — not swallowed today**; `05 … VALUE "AB" CONSTANT RECORD.` draws COBOLNET1549 identically in both
  modes.

⛔ **Three of the four survive on ANTLR lookahead luck, not on a gate** — exactly [[PB792]]'s own finding #1
about the 31 revoked pairs, and exactly why the fix is a gate rather than three more predicates. Any change to
a clause's tail — or a new clause whose first two words can both ride `cobolWord` — moves a word from the
second column to the first, silently.

## ⚠ Premise corrections to the paragraph as received (CLAUDE.md rule 1: the failure mode is INHERITING)

1. ⛔ **"Harm: none today" is FALSE.** Measured above: legal source, accepted strict, rejected permissive, at
   every edition from 2002. `rejects_legal_source: true`.
2. ⛔ **"the ONLY per-word permissive disambiguation in the grammar" is too strong.** `grep "TokenStream.LA(1)"`
   over `src/Cobol.Net.Frontend/Grammar/` returns **three families over eight words**: PROPERTY (2 sites,
   keyed `is2002()`), DEFAULT (`initializeOperandList`, keyed `reservedHere("DEFAULT")` so the `>>COBOL-WORDS`
   overlay is honoured), and DELETE FILE's file-name list (`CobolIO.g4:690`, five phrase keywords, unkeyed at
   every edition). Three sites, three different keying schemes, no shared rule — which makes the paragraph's
   conclusion *stronger*, not weaker: this is a family of hand-written per-word predicates where one structure
   belongs (CLAUDE.md rule 5, `feedback_one_rule_one_place`).
3. **"load-bearing ONLY under `--permissive`" HOLDS.** `PROPERTY` is `r85:false, r2002:true` in
   `reserved-words.json`, so `UserWordVerdictAt` returns `Removed` at 2002+, and only the permissive downgrade
   admits it. At `--std 2002` strict the reservation gate keeps PROPERTY out of `cobolWord` and the loop stops
   on its own; both modes accept `05 A PIC X(2) VALUE "AB" PROPERTY.`, for two different reasons.

## The unwritten rule this note is really about

> **When the migration mode restores a word §8.9 took away, and that word can also begin a clause of the same
> entry, which reading wins?**

It is written down nowhere — not in `docs/rearchitecture/DESIGN-frontend.md`, not in the dialect design, not in
`CONFORMANCE.md`. Today it is answered per-word, by hand, for one word out of five, and by ALL(\*) lookahead for
the rest. Whatever the fix, **the answer is a stated rule plus a derived gate, and the rule belongs in the
design doc in the same change set** (CLAUDE.md rule 2).

The shape that makes the next case automatic: a restored word is admitted into the user-word slot **only where
it cannot also open a clause of the construct being parsed** — derivable, because the set of clause-initial
words per construct is already in the grammar and the `Removed` set is already in `reserved-words.json`. That
turns a hand-written predicate per word into one predicate over a derived set, and the accompanying drift test
(the shape of `ReservedWordMigrationGateDriftTests`) enumerates every (Removed word × clause-initial position)
pair so a new one cannot arrive unguarded. Prove it red first, on the GROUP-USAGE repro.

## Sweep the fixer must do

  subsumes `initializeOperandList`'s DEFAULT predicate and `deleteFileStatement`'s five, delete them; two
  coexisting mechanisms is the anti-pattern (`feedback_one_mechanism_per_job`).
- **Every greedy operand list that can reach `cobolWord`**, not only the ones in `CobolData.g4` — [[PB792]]'s
  drift test already enumerates 31 behavioural pairs and is the natural place to extend.
- **Re-run the four measurements above after the fix**, including the three that do NOT reproduce today: a fix
  that makes GROUP-USAGE parse while breaking the DEFAULT/PRESENT decline is the same defect with the arms
  swapped.
