# PB4521 — strongly-typed-group-compare-not-implemented: Feature request: TYPEDEF STRONG (announced by -Wpending as not implemented): comparison of strongly-typed groups is a byte compare

Filed 2026-11-03 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-batch-3000-20261103`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

GnuCOBOL 3.2 accepts `TYPEDEF STRONG` under `-std=cobol2014` with the warning `TYPEDEF STRONG is not implemented
[-Wpending]`, exits 0 and builds a program that runs. A relation condition between two strongly-typed group items is
then evaluated as a comparison of the groups' bytes, not item by item by each elementary item's own class: with equal
keys, a signed numeric item of -5 compares greater than one of 3. Class: feature missing (announced at compile time),
edition 2014 (the feature is in ISO 2002). Fuzz night 2026-11-03: fz00020, fz01430, fz02838, fz02840 (signature
OUTPUT_DIFFERS:8.8.4.2.12).

## Minimal test case

Free reference format (`-free`).

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. STGCMP.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 AMT-T TYPEDEF STRONG.
   05 AMT-KEY PIC X(2).
   05 AMT-VAL PIC S9(3).
01 WS-P TYPE AMT-T.
01 WS-Q TYPE AMT-T.
PROCEDURE DIVISION.
MAIN-PARA.
    MOVE "AA" TO AMT-KEY OF WS-P
    MOVE "AA" TO AMT-KEY OF WS-Q
    MOVE -5 TO AMT-VAL OF WS-P
    MOVE 3 TO AMT-VAL OF WS-Q
    IF WS-P < WS-Q DISPLAY "T1 LT" ELSE DISPLAY "T1 NOT LT" END-IF
    MOVE 10 TO AMT-VAL OF WS-P
    MOVE 9 TO AMT-VAL OF WS-Q
    IF WS-P > WS-Q DISPLAY "T2 GT" ELSE DISPLAY "T2 NOT GT" END-IF
    STOP RUN.
```

## Environment

`cobc (GnuCOBOL) 3.2.0` on WSL2 Ubuntu. Compiled with `cobc -x -free -std=cobol2014 -o p stg.cob` and run as `./p`.

## Observed result

Compile: `stg.cob:5: warning: TYPEDEF STRONG is not implemented [-Wpending]` (exit 0). Run:

```
T1 NOT LT
T2 GT
```

Exit code 0.

## Expected result (per ISO)

§8.8.4.2.12: "When two strongly-typed group items are compared, each elementary item of the first operand is compared
with the corresponding elementary item of the second operand, in accordance with the rules for comparison of
elementary items", until a pair is unequal. In T1 the keys are equal and AMT-VAL compares -5 with 3 numerically, so
WS-P is less than WS-Q: `T1 LT`. In T2, 10 > 9: `T2 GT`. The same rule is in the ISO/IEC 1989:2002 text (strongly-typed
group items are a 2002 feature), so `-std=cobol2014` claims it; it is unchanged in 2023.

## Our compiler

WiseOwl COBOL (fresh judge, `--std 2014 --source-format free`) prints `T1 LT` and `T2 GT`, with no diagnostic.

## Fix site

`cobc/parser.y`: the TYPEDEF rule announces `CB_PENDING ("TYPEDEF STRONG")`; the strong attribute is not carried to the
condition builder (`cobc/typeck.c`, `cb_build_cond` and `cb_build_cond_default`), which compares the two groups as
alphanumeric. Read observationally in the 3.3-dev tree; the 3.2.0 binary shows the behaviour.

## Upstream state

unreported; tracker not yet searched. The compiler names the gap itself (`-Wpending`); NEWS and TODO were not found to
name it.

## Vetting (2026-11-04)

Verdict DUPLICATE of an existing ticket, kept open as a comment candidate; the refuter agrees. The ISO reading is right (8.8.4.2.12 and 8.8.4.2.3 1), cite.py --check OK; not in Annex A.4), but feature-requests #193 "add COBOL 2002 TYPEDEF and SAME AS" (accepted, open) already carries the plan for TYPEDEF STRONG, and bugs #806 has the maintainer calling it unlikely to land soon. 3.2.0 and 3.3-dev both warn "TYPEDEF STRONG is not implemented [-Wpending]" and compare bytes (T1 NOT LT). ## Draft issue

**Title:** Feature request: TYPEDEF STRONG (announced by -Wpending as not implemented): comparison of strongly-typed groups is a byte compare

Environment: GnuCOBOL 3.2.0 (cobc), WSL2 Ubuntu; `cobc -x -free -std=cobol2014 -o p stg.cob`, then `./p`.

Steps: compile and run the program below. cobc warns `TYPEDEF STRONG is not implemented [-Wpending]` and exits 0.

Observed: `T1 NOT LT`, `T2 GT`.

Expected: `T1 LT`, `T2 GT`. ISO/IEC 1989 §8.8.4.2.12 (also in 2002 and 2023): two strongly-typed group items are
compared elementary item by elementary item, each by the rules for its own class, so the signed numeric -5 is less
than 3. The byte compare used now puts the signed display item -5 above 3. Until the feature is implemented,
an error instead of a warning under the ISO dialects would keep programs from running with this result.

PROGRAM-ID. STGCMP.
DATA DIVISION.

01 AMT-T TYPEDEF STRONG.

01 WS-P TYPE AMT-T.
01 WS-Q TYPE AMT-T.
PROCEDURE DIVISION.
MAIN-PARA.
    MOVE "AA" TO AMT-KEY OF WS-P
    MOVE "AA" TO AMT-KEY OF WS-Q
    MOVE -5 TO AMT-VAL OF WS-P
    MOVE 3 TO AMT-VAL OF WS-Q
