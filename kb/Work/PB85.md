# PB85 — LANDED 2026-08-18 — `DIVIDE F BY 2 GIVING Q REMAINDER R` (F FLOAT-LONG) was `CS0266` / `CS1503`

> ⚙ **flags:** crashes (backend compilation failure on legal source), rejects-legal-source · found 2026-08-18 by the
> PB84 consumer sweep (a probe over the DIVIDE REMAINDER path, which bypasses `Combine`) · fixed in the same commit
> (DEVLOG 1302).

**Measured** (`--std 2023`, `01 F USAGE FLOAT-LONG VALUE 7.5`): `DIVIDE F BY 2 GIVING Q REMAINDER R` →
`CS0266: Cannot implicitly convert type 'double' to 'System.Int128'` (the snapshot) and `CS0019` on the back-multiply;
`DIVIDE 17 BY F …` likewise. §14.9.12.3 SR1 admits any category-numeric elementary item as identifier-1/-2 — a
float is one — and GR7 defines the remainder for it.

**Mechanism:** `EmitDivideRemainder` snapshots both senders (`Int128 __ie = …` — total over Dec/Int128 only) and
calls the exact Int128 kernel directly (`CobolNum.Divide`), bypassing `Combine`'s float lane; a `Real` sender was
never landed.

**Fix:** `NumericRenderer.FixedLane(x, rcv)` — a float sender lands TRUNCATED at the quotient receiver's float
working scale (D16's one quantizer rule; under a standard mode it converts to SDIDI first — §8.8.1.5.1 — and lands
the same way), an unsigned-wide read funnels through `Widen`, everything else is `Landed`; the snapshot is total over
the four carriers. Measured 7.5 / 2 → Q 3, R 1.50 (GR6c truncates the subsidiary quotient at the receiver's scale;
GR7 remainder = 7.5 − 3 × 2); 17 / 7.5 → Q 2, R 2.00. Golden rows T12/T13 of `pb84_sdidi_intermediate_consumers`
and S10 of the STANDARD-DECIMAL twin.
