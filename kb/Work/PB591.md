# PB591 — OPEN — the audits validate what is quoted, not what is named

Found 2026-09-05 by the `PB230` implementer's four-lens self-review; re-derived on this tree for this note.

## The measurement

PB230's sweep corrected **25** references across `src/`, `docs/`, `tests/` and `kb/` that cited `§8.8.4.4 GR<n>`
— §8.8.4.4 is the *Class condition* heading; its general rules are `§8.8.4.4.4` — four of which predated
PB230 and had shipped. Two also carried the wrong ordinal: `CobolClass.IsNumeric` cited "GR2", which reads "If
the word NOT is specified, the truth value is reversed" — a real clause answering a different question — where
the numeric-class predicate is GR3 n)1.a / n)2. `audit_code_citations.py --check` and
`audit_doc_citations.py --check` were green across all 25 before and after: both validate a VERBATIM QUOTED
fragment against the clause it is attributed to (`cite.py --check <clause> "<text>"`), and a bare `§X GR<n>`
reference in prose or in a code comment carries no quotation to validate.

This is the complement `PB476` measured from the other side (a citation reworded out of the audit's reach
leaves the population silently): here the reference never entered the population at all.

## Fix shape

A third audit, or a mode of `audit_code_citations.py`: extract every `§<clause> (GR|SR|AR|RV|FMT)<n>[ ]?<sub>*`
spelling from code comments, docs and notes; resolve `<clause>` against `spec-rule-catalog.json`; report (a) a
clause that has no rules of that kind (the heading-vs-sub-clause error above), (b) an ordinal beyond the
clause's rule count, and (c) — where the surrounding line quotes any words — a quote that `cite.py --check`
places under a different ordinal. Baseline the current findings (PB476's population pattern) so the gate is
red only on growth; fire it once against a fixture carrying `§8.8.4.4 GR2` before trusting it.
