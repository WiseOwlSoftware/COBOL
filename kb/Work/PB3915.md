# PB3915 — constant-record-clause-not-supported: CONSTANT RECORD clause (ISO 2014 structured constant) is refused: 'syntax error, unexpected RECORD'

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S7) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\constant-record-clause-not-supported.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\constant-record-clause-not-supported\`.

## Summary

GnuCOBOL 3.2 refuses every data description entry that carries the CONSTANT RECORD clause. A group form
`01 CR CONSTANT RECORD.` draws `syntax error, unexpected RECORD`; an elementary form
`01 CE PIC X(4) CONSTANT RECORD VALUE "WXYZ".` draws `syntax error, unexpected CONSTANT`. Both come from the same gap:
the grammar has no CONSTANT RECORD clause. The clause (structured constants) is in ISO/IEC 1989:2014, the edition
`-std=cobol2014` claims, so this is a missing feature of that edition. Class: feature missing.

## Minimal test case

Free reference format (`-fformat=free`), 10 lines, written for this record. The 12 fuzz witnesses of nights 2 to 5
(for example fz00652, fz00675, fz00203; 52 programs across the nights) all reduce to it: 11 stop on
`unexpected RECORD` at a group `CONSTANT RECORD` entry, one (fz01304) on `unexpected CONSTANT` at an elementary one.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. CONREC.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 CR CONSTANT RECORD.
   05 CR-A PIC X(4) VALUE "ABCD".
   05 CR-N PIC 9(2) VALUE 12.
PROCEDURE DIVISION.
DISPLAY CR
STOP RUN.
```

File: `E:\COBOL-coord\scratch\op\pb3838\records\constant-record-clause-not-supported.cob`.

Elementary variant (same mechanism, different first failing token), free format, 8 lines,
`E:\COBOL-coord\scratch\op\pb3838\records\constant-record-clause-not-supported--elementary.cob`:

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. CONREC2.
DATA DIVISION.

01 CE PIC X(4) CONSTANT RECORD VALUE "WXYZ".
PROCEDURE DIVISION.

```

Both programs are legal: the clause is at level 1 (§13.16.3 6)), in the working-storage section (§13.18.15.3 1)),
it is combined with none of the clauses §13.16.3 13) excludes, and no statement names the record or a subordinate
item as a receiving item (§13.18.15.3 2)); `DISPLAY` only sends.

## Observed result

```

    3 | DATA DIVISION.
    4 | WORKING-STORAGE SECTION.

    7 |    05 CR-N PIC 9(2) VALUE 12.
```

Elementary variant, `-std=cobol2014`, exit code 1:

```
conrec2.cob:5: error: syntax error, unexpected CONSTANT
```

## Expected result (per ISO)

Both programs compile; the first prints `ABCD12`, the second `WXYZ`.

- ISO/IEC 1989:2023 §13.18.15.1 (checked): "The CONSTANT RECORD clause identifies a structured constant. The content
  of a structured constant cannot be modified." General format (§13.18.15.2): `CONSTANT RECORD`.
- §13.16.3 6) (checked): "The CONSTANT RECORD and GLOBAL clauses may be specified only in data description entries
  whose level-number is 1."
- §13.18.15.3 1) (checked): "The CONSTANT RECORD clause may be specified only in the local-storage or working-storage
  sections."
- §13.18.15.3 2) (checked): "Neither the data item described by the subject of the entry nor any data item subordinate
  to the subject of the entry shall be specified as a receiving data item."
- §13.18.15.4 1) (checked): "The content of a record described with the CONSTANT RECORD clause is as though the clause
  had been omitted and the record had been the subject of an INITIALIZE statement" with the FILLER, VALUE ALL and
  DEFAULT phrases. Every item here carries a VALUE clause, so CR holds `ABCD12` and CE holds `WXYZ`.

Edition: CONSTANT RECORD is in ISO/IEC 1989:2014. The 2023 standard's Annex E, which itemizes the 2014-to-2023
changes, presupposes it: §E.2 10) (checked) "Previously external items could be specified with the CONSTANT RECORD
clause", a 2023 restriction on EXTERNAL items only, which these programs do not use. The 2009 committee draft that led
to the 2014 edition (ISO/IEC 1989:20xx CD 1.2, 2009-08-23) carries the clause as §13.18.15 with the same two syntax
rules and general rule. It is not in the 2002 edition's text.

Edition as recorded by the adjudicator: 2014. `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Class

FEATURE-MISSING (edition 2014): a 2014 data-description clause refused as a syntax error.

## Our compiler (WiseOwl)

WiseOwl COBOL (built from main 6ed90bd1c), `cobol conrec.cob --std 2014 --source-format free -o conrec.dll`, then
`dotnet conrec.dll`: compile exit 0, run exit 0, output `ABCD12`. The elementary variant: compile 0, run 0, `WXYZ`.
WiseOwl enforces §13.18.15.3 2): `MOVE "WXYZ" TO WS-CR-A` with WS-CR-A subordinate to a constant record is refused
with COBOL1548 (night-4 probe `cr-recv`, re-run on this build, compile exit 65), so its acceptance here is not an
under-rejection.

## Fix site (GnuCOBOL 3.2 source, read observationally)

- `cobc/parser.y`, rule `constant_entry` (line 7364): matches `level_number user_entry_name CONSTANT` and then
  requires `constant_source` (the `AS`/`FROM` forms of the constant entry), so `01 CR CONSTANT RECORD` fails at
  `RECORD`.
- `cobc/parser.y`, rule `data_description_clause` (line 7472): no alternative for a CONSTANT RECORD clause, so an
  entry with a PICTURE before `CONSTANT RECORD` fails at `CONSTANT`.
- A fix needs a CONSTANT RECORD clause alternative (and a way for `constant_entry` to yield when `RECORD` follows
  `CONSTANT`), a field flag, the syntax checks (level 1; working-storage or local-storage; never a receiving item;
  the clauses §13.16.3 13) excludes), and storage initialized per §13.18.15.4 1).

**Body:**

Environment: GnuCOBOL 3.2.0 (Ubuntu gnucobol3 3.2-4build1), x86_64 Linux.

Steps: `cobc -std=cobol2014 -fformat=free -x conrec.cob` with

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. CONREC.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 CR CONSTANT RECORD.
   05 CR-A PIC X(4) VALUE "ABCD".
   05 CR-N PIC 9(2) VALUE 12.

DISPLAY CR
STOP RUN.
```

Observed: `conrec.cob:5: error: syntax error, unexpected RECORD` (exit 1); the same without `-std`. An elementary
entry `01 CE PIC X(4) CONSTANT RECORD VALUE "WXYZ".` gives `syntax error, unexpected CONSTANT`.

Expected: the program compiles and prints `ABCD12`. The CONSTANT RECORD clause is part of ISO/IEC 1989:2014
(§13.18.15 in the 2023 edition): "The CONSTANT RECORD clause identifies a structured constant. The content of a
structured constant cannot be modified." It is allowed at level 1 in working-storage and local-storage; neither the
record nor its subordinates may be receiving items; the content is as though the record had been the subject of an
INITIALIZE statement with the FILLER phrase, VALUE ALL and the DEFAULT phrase.

In the 3.2 parser, `constant_entry` takes `01 name CONSTANT` as the start of a constant entry (`CONSTANT AS literal`),
and `data_description_clause` has no CONSTANT RECORD alternative.
