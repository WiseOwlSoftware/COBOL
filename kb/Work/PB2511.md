# PB2511 — LANDED (wave 1045 A, 2026-10-08)

## Landed

Re-probed on the wave's Debug build of 685b44315 (`E:\COBOL-coord\scratch\w1045a\p\s_*.cob`, `--std 2023`):
`SORT TE(1:2)` and `SORT TE(2:)` printed `1234` (the whole table sorted), `SORT NE(2)(1:1)` sorted row 2 (`321456`),
`SORT BLK(1:3)` sorted every element, and `SORT NE(ALL)(1:1)` drew COBOLNET2097's subscript-count sentence instead
of naming the modifier. `SortBinder.SortBindTable` now asks `DataBinder.ScreenReferenceModifier(operand, "SORT table
subject", …)` before `ReadTableSubjectSubscripts`, so all five draw COBOLNET2024 with §8.4.3.3.3's NOTE
(`cite.py --check 8.4.3.3.3 "reference-modification is not permitted"` OK SR5; §14.9.40.3 SR13 "Subscripting shall
be specified in accordance with" the subscript clause, OK; `5.2.4 "reference-modification is not permitted"` OK). Negative
`negative/pb2511-sort-table-subject-refmod` (reject-at 2002 2014 2023; the table SORT is itself 2002+).

**Sibling sweep** (every procedure position whose format prints data-name-n, `grep ScreenDataNameShape|ScreenReferenceModifier`
plus the READ/START key binders): SORT/MERGE file KEY and table SORT KEY (`SortBinder.cs`, `ScreenDataNameShape`, PB481),
SEARCH ALL WHEN data-name-1 (`SearchAllFormat2Rules.cs`, PB1457), READ KEY and START KEY (`KeyedIoBinder.cs`, their
own reference-modifier refusals) were already screened; the SORT Format 2 subject was the one arm without it. MERGE
has no table format.

## Filed

Filed by the w1033 clerk from the PB1923 refuter (`E:\COBOL-coord\scratch\w1033-adj\PB1923-refute.md`, "The overturning finding"). Flags are the refuter's (under_rejects, silent); `wrong_answer: true` is added because the refuter
shows the whole table is sorted where a single modified range was written.

**Expected from the spec (cite.py --check OK per the refuter).** `§5.2.4`: "When the term data-name-n is used in a general format or syntax rule, then reference-modification is not permitted, while it is permitted when the term identifier-n
is used"; `§8.4.3.3.3 SR5` and its NOTE say the same; `§14.9.40.2` Format 2 prints `SORT data-name-2`, and `§14.9.40.3 SR13` adds only subscripting (`8.4.2.3`). So a reference modifier on the SORT subject is a syntax-rule violation that must be diagnosed.

**Mechanism and site (two-arm asymmetry).** `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/SortBinder.cs#SortBindTable`: the KEY arm calls `DataBinder.ScreenDataNameShape` (SortBinder.cs:283, COBOLNET2024; PB481), SEARCH screens identifier-1 (COBOLNET2075); the subject

code is needed. Negative golden: `SORT TE(1:2)`, `SORT E(2)(1:1)`, `SORT TE(ALL)(1:1)`, `SORT ROW(1:3)`, rejected at 2002, 2014 and 2023. Sweep the MERGE and other data-name-n subject positions for the same arm. Related: `PB1923`.
