# PB2511

Filed by the w1033 clerk from the PB1923 refuter (`E:\COBOL-coord\scratch\w1033-adj\PB1923-refute.md`, "The overturning finding"). Flags are the refuter's (under_rejects, silent); `wrong_answer: true` is added because the refuter
shows the whole table is sorted where a single modified range was written.

**Expected from the spec (cite.py --check OK per the refuter).** `§5.2.4`: "When the term data-name-n is used in a general format or syntax rule, then reference-modification is not permitted, while it is permitted when the term identifier-n
is used"; `§8.4.3.3.3 SR5` and its NOTE say the same; `§14.9.40.2` Format 2 prints `SORT data-name-2`, and `§14.9.40.3 SR13` adds only subscripting (`8.4.2.3`). So a reference modifier on the SORT subject is a syntax-rule violation that must be diagnosed.

**Observed (pinned build `pin-97006f3`; `PB1923-refute\wiseowl-out-r.txt`, `wiseowl-out.txt`).**

| probe | subject | 2002 / 2014 / 2023 | GnuCOBOL 3.2.0 |
|---|---|---|---|
| q07 / r01 | `TE(1:2)` | clean, whole TE sorted: `1234` | syntax error, unexpected `:` |
| r02 | `NE(2)(1:1)` | clean, row 2 sorted: `321456` | syntax error |
| r03 | `TE(ALL)(1:1)` | clean, `1234` | (ALL unsupported) |
| r04 | `TE(2:)` | clean, `1234` | syntax error |
| r08 | `BLK(1:3)` (group elements) | clean, sorted on the whole element | syntax error |
| r05 (control) | KEY `KK(2:1)` | COBOLNET2024 | n/a |
| s01 (control) | `SEARCH TE(1:1)` | COBOLNET2075 (§14.9.37.3 SR1) | n/a |

`--flag-extensions` on r01 and r02 draws no COBOLNET2894 and no extension is documented. The generated C# for q07 (`PB1923-refute\q07.g.cs:175-183`) is `CobolTable.SortInPlace(AsSpan(T1.TE, 0, 4), ...)`: the written `(1:2)` leaves no trace.

**Mechanism and site (two-arm asymmetry).** `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/SortBinder.cs#SortBindTable`: the KEY arm calls `DataBinder.ScreenDataNameShape` (SortBinder.cs:283, COBOLNET2024; PB481), SEARCH screens identifier-1 (COBOLNET2075); the subject
arm calls only `ReadTableSubjectSubscripts` (SortBinder.cs:199), which reads `SubscriptGroupOf(dref)` and never looks at the reference-modifier suffix. PB1457's sibling sweep ("SORT/MERGE/READ/START were already screened") measured only the KEY.
No existing kb/Work note covers it (the refuter searched).

**Fix shape (refuter).** Before `ReadTableSubjectSubscripts`, call `DataBinder.ScreenReferenceModifier(operand, "SORT table subject", ctx.Edition)`, the reference-modifier arm of the one data-name-n screen that PB1457 split out; it reports COBOLNET2024, so no new
code is needed. Negative golden: `SORT TE(1:2)`, `SORT E(2)(1:1)`, `SORT TE(ALL)(1:1)`, `SORT ROW(1:3)`, rejected at 2002, 2014 and 2023. Sweep the MERGE and other data-name-n subject positions for the same arm. Related: `PB1923`.
