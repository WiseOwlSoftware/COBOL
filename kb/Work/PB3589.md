# PB3589 - three argument shapes changed route in PB3562 with no golden

## Lead (PB3562 review lead R1-2, low)

`src/Cobol.Net.Compiler/CodeGen/Emit/OperandText.cs` (line 303 area), `CarrierDiffersFromStorage`, answers true for a bit group, a
national group and a reference-modified usage-bit or usage-national slice, as well as for the elementary items and function values it
was written for. For a Format-2 CALL / INVOKE into a plain-group formal that changes how those arguments cross BY CONTENT: from the
elementary-alphabet text of `CallContentRead` to the storage image. No golden pins any of the three shapes. The only golden,
`conformance:cases/14.2-Procedure-division-structure/pb3562_content_group_formal_usage_values`, sends an elementary item and a
function value. The implementer probed the bit group by hand and found it right, so this is a witness gap, not a known wrong answer.

## Fix shape (for the implementer)

Extend that golden (or add a sibling) with a bit group, a national group and a ref-modified usage-bit and a ref-modified
usage-national slice sent BY CONTENT to a plain-group formal, by CALL ... AS NESTED and by INVOKE, expected values derived from
section 14.9.25.4 4 and section 14.2.3 9 (run `cite.py --check` on each), not copied from output. Do the work together with PB3587
if that note's fix changes the same route.

**Sites:** `conformance-suite/cases/14.2-Procedure-division-structure/` (new or extended pb3562-family golden and its manifest rows);
the code under test is `src/Cobol.Net.Compiler/CodeGen/Emit/OperandText.cs` and `src/Cobol.Net.Compiler/CodeGen/Emit/CallEmitter.cs`.
