# PB681 — LANDED — a null that nobody reports

Found 2026-09-05 by the `PB347` implementer (report §"New defects" A) while checking the note's "no subscripting"
half: a level-01 record under an FD/SD cannot carry OCCURS, so `RELEASE SRT-REC(1)` fails in the reference
resolver before any record-name rule — and the failure is silent for every verb, not only RELEASE.

## The shape

```cobol
       01  A PIC X(8).
       01  B PIC X(8).
       …   MOVE A(1) TO B.
```

compiles with no diagnostic of any kind — not even the COBOLNET1756 deferral warning, because the enclosing
statement itself binds — and generates
`B = CobolString.Store(NotImplemented.Value<string>("reference 'A(1)'"), 8);`, which throws when the MOVE
executes. `ctx.Refs.Resolve` returns null for `A(1)` and no caller reports why. Through a record-name
(`RELEASE SRT-REC(1)`) the same failure does draw COBOLNET1756, because the whole statement becomes
`BoundUnsupported`; through an ordinary operand it draws nothing.

## The rule

§8.4.2.3 governs what a subscript may be written on and §13.18.38's OCCURS clause is what makes an item a table
(`cite.py --check` both before citing them in code — the implementer named the clauses, the fragments were not
checked here); §4.2.2 (`cite.py --check 4.2.2 "violations of the general formats and the explicit syntax rules of
standard COBOL"` → OK) requires the compile-time indication. A subscript on a non-table item is a syntax-rule
violation the compiler must report, not a run-time fault it may defer to.

## Fix

At the ONE place the resolver decides a subscripted reference (`src/Cobol.Net.Compiler/Binding/Model/ReferenceResolver`),
distinguish "no such name" (COBOLNET1639, §8.4.2.1, already reported) from "the name exists but is not a table at
this subscript depth" and report the second with its own §8.4.2.3 message; sweep every caller that turns a null
resolution into a `NotImplemented` value and make each either report or receive the diagnostic from the resolver
— a null with no diagnostic behind it must become impossible (a drift test over the resolver's return paths).
Negatives for a subscripted non-table item, too many subscripts, and too few (the last may already be
reported — measure), at four editions. General, not verb-specific.

## Landed — 2026-09-22, wave 48 (T), worktree `wf_ffdefe6a-659-3`

**Re-probed first.** The note's own repro (`MOVE A(1) TO B`, A with no OCCURS) NO LONGER REPRODUCES: `kb/Work/PB877`
(`86f459ff6`) landed COBOLNET2096 (§8.4.2.3.3 SR2) and COBOLNET2097 (SR3) at the resolver's one subscript screen.
But the note's third leg — "too few (the last may already be reported — measure)" — measured LIVE in its limiting
case: a table element written with NO subscripts (`MOVE E TO B`, E under two OCCURS) compiled with ZERO diagnostics
and aborted at run time with `NotImplementedCobolFeatureException: reference 'E'`. PB877 had deliberately left the
omitted list alone ("seven contexts only the owning binder can recognize").

**Rule**: §8.4.2.3.3 SR5 — "Each table element reference shall be subscripted except when such reference appears"
in seven contexts (`cite.py --check 8.4.2.3.3 "Each table element reference shall be subscripted except when such
reference appears"` → OK §8.4.2.3.3 5)). **Fix**: none of those seven reaches the screen — SEARCH resolves through
`ResolveTableOperand`, SORT through its own data-description walk, REDEFINES / OCCURS KEY / SUM through the data
binder — so `ScreenSubscriptArity` now screens `written == 0` too (COBOLNET2270 `table-element-not-subscripted`), and
it runs on ALL THREE identifier entries: `Resolve`, `ResolveForItem` (a level-88 under a table element, SET/IF with no
subscript — the same null through the second entry) and `ResolveForAddressOf`, which returned the table's FIRST
occurrence for `ADDRESS OF E` with no diagnostic; its caller no longer adds a second generic diagnostic after the
resolver named the rule. `SubscriptAdmissionDriftTests.TheOmittedSubscriptList_IsScreenedAtEveryIdentifierEntry`
pins the three wirings. Negative `pb681-table-element-not-subscripted` (all editions, MOVE + SET 88 arms).

**Residual (lead, not fixed here)**: the resolver's other silent-null returns (unsupported subscript form, RENAMES
with subscripts, Tier-C views, dynamic whole-table) still reach callers as unreported nulls; since PB909 the funnel
announces those as COBOLNET1756 deferrals rather than leaving them silent, but "a null with no diagnostic behind it
must become impossible" as a TYPE (a resolver result that is Place | Reported | Deferred) is the rest of this note's
Fix paragraph and is registered as a lead in the wave-48 T report.
