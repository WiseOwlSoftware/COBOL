# PB5241 - at --std 85 a CANCEL naming the active main program ends the run unit abnormally (EC-PROGRAM-CANCEL-ACTIVE): ProgramTable.CancelNode refuses any active program, the 2023 condition, where 1985 forbids only a program that has been called and has not exited

**Sites:**

- `src/WiseOwl.Cobol.Runtime/Control/ProgramTable.cs` (`CancelNode`: the `Active != 0` test)
- `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/CallEmitter.cs` (`EmitCancel`)

**Mechanism.** §1985:X.5.3.4 GR5 forbids a CANCEL that refers "directly or indirectly to any program that has been called and has not yet executed an EXIT PROGRAM statement", and a called program is the object of a CALL statement. The main program of the run unit is active but was never called, so a CANCEL naming it breaks no rule, and §1985:X.5.3.4 GR8 governs: "No action is taken when an explicit or implicit CANCEL statement is executed naming a program that has not been called in this run unit". `CancelNode` refuses to cancel any node whose active count is not zero (§2023:14.9.5.4 GR5, EC-PROGRAM-CANCEL-ACTIVE), and at 85 that ends the run unit.

**Found by.** The 1985 code read (slice 42, rule `1985-GR-X.5.3.4-5`) read CONFORMS; its Opus refuter OVERTURNED it (`E:/COBOL-coord/scratch/coderead-85/out-pipe/slice-42-refute.json`, probe `E:/COBOL-coord/scratch/coderead-85/out-pipe/refute-slice-42/K2.cob`).
