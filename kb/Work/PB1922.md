# PB1922 — OPEN

Filed by the train-1004 lander from wave 1004 group C's report (`w1004c-PB1175-report.md`).

## Finding

**Rule.** §14.9.40.4 GR24: the sorted elements are placed back in data-name-2. Legal source; reachable only through a
STRONG type declaration (§13.18.60.3 SR14 admits a pointer below level 1 only there).

**Site.** `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/SortBinder.cs#SortBindTable` — the `SlotWindow.CarriedBySlot`
guard keeps the COBOLNET1756 deferral for this shape after kb/Work PB1175 gave every other shared-storage table a
window sort (`SortEmitter.cs#EmitSharedAreaTableSort`, which reads and writes element IMAGES). A pointer's value lives
in a managed slot (`SlotWindow`, kb/Work PB231), not in the record bytes, so moving the image alone would separate
each pointer from its element.

**Repro.** Not written (the declaration needs a TYPEDEF STRONG element type holding a USAGE POINTER item, in a BASED or
EXTERNAL record, sorted with `SORT T ASCENDING KEY K`).

**Fix shape.** Carry the slot with the image in the shared-area sort (read every element's slot values before the
first write, write them back by the same permutation), then remove the guard; positive golden at 2002.
