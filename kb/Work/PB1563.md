# PB1563

Raised 2026-09-24 by the w59e (PB1053) implementer, who documented the current behaviour in docs/CONFORMANCE.md §3
D-FRA (v) as a limitation. GnuCOBOL, IBM and Micro Focus all refuse dynamic-length items in the file section, so there
is no model implementation (CLAUDE.md rule 1 precedence). Before anything reaches the owner, DERIVE: (1) what §8.5.1.11.2
('behaves as though contiguous') plus the READ general rules say the record area receives from a line — possibly the
contiguous characters with each member's length determined by its own rules (§8.5.1.10.4), which may be exactly the
take-step; (2) whether any encoding inside the line is licensed (§12.4.5.10.3 GR2); (3) whether a compile-time
warning is required. If the derivation shows today's result is what the standard requires, close this as a documented
determination with a golden; otherwise it becomes a defect. Repro: FD L in `<scratchpad 9db39f61…>\w59e\p1\fixedfmt.cob`; site `SequentialConnector.Write`
line-sequential branch.

Owner 2026-10-17: addressed in the SORT and file I/O campaign (kb/Work PB3353).

## Landed (wave 1119, group G)

Derived, not decided by owner: the standard asks of a READ only the contiguous image, and the image after a READ of a
line is exactly the line (padded or cut by §14.9.30.4 GR15). Where one dynamic member ends inside that image is stated
by no rule, so the take step stays, and docs/CONFORMANCE.md section 3 D-FRA (x) now carries the whole derivation
(plain text, §12.4.5.10.3 GR2 and §9.1.7.2; no in-line encoding; no diagnostic required; rejected readings). The
re-probe on the wave-1119 build reproduced the take step (`A=[AAKEYC] KY=[CCC] C=[]` for `AA|KEY|CCCC` under LIMIT
9 / X(3) / LIMIT 8) and every neighbouring status of the record: '00', '06', '10', '44', '46', '47', '48', '71'.

It found one real defect in the same arm (code site `SequentialConnector.NextFrame`, the line branch): the
"partial line" fact that §14.9.35.4 GR17 a) refuses a REWRITE on was measured against the character window
(`RecordWidth`, a variable-length group's 3-character fixed run) instead of §14.9.30.4 GR15's maximum size
(`MaxRecordSize`), so a REWRITE of any line-sequential variable-length-group record longer than its fixed run was '44'
after a READ that delivered it in full. Fixed at the one bound the READ's truncation asks. Witness:
`conformance:cases/12.4.5.10-ORGANIZATION/pb1563_line_sequential_dynamic_members` (accept 2023) and its refusal
`pb1563-line-sequential-dynamic-members-below-2023`.
