# PB3794 — a data item named MESSAGE breaks RECEIVE ... CONTINUE AFTER MESSAGE RECEIVED

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/ReservationGateRewriter` (the retype; `CobolLexerWordSet.g.cs:218` lists the word), `src/WiseOwl.Cobol.Frontend/Grammar/CobolParserCore.g4#mcsReceiveStatement` (line 1023 comment asserts the opposite and must be corrected with the fix), `tests/version-matrix/cobol-words.json` (the `keywordWhereFree` rows METHOD, MESSAGE, MULTIPLE, ORDER), `scripts/gen-cobol-words.ps1` (step 1 validation, step 5c), `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolWords.g4#messageKeyword` (`methodKeyword`, `multipleKeyword`, `orderKeyword`, generated), `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolOO.g4` (the hand `methodKeyword` deleted), `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolIO.g4#lockOnPhrase` (`multipleFileClause`, `sortDuplicatesPhrase`), `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolSpecialNames.g4#orderTableClause`, `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs#MapLockMode`, `tests/WiseOwl.Cobol.Tests.Unit/CobolWordsDriftTests.cs#KeywordRules_Are_Generated_From_The_KeywordWhereFree_Rows` (`A_KeywordWhereFree_Word_Is_Spelled_Only_Through_Its_Keyword_Rule`, `TheSpellingGuard_ReportsABareToken_AndPassesTheKeywordRule`, `Every_Gated_Word_A_2023_Format_Spells_Where_Section89_Frees_It_Carries_The_Determination`), `tests/WiseOwl.Cobol.Tests.Unit/UserWordSlotDriftTests.cs#StripActions` (`Comment`, `Rule`, `ParserGrammars` made internal for the reuse)

## Measured

Probe `recv4.cob`: `01 MESSAGE PIC 9.` then `RECEIVE ... CONTINUE AFTER MESSAGE RECEIVED` gives COBOL0307
`unexpected 'RECEIVED'`. It predates PB3751: it fails with AFTER written too. The word is declared, so the reservation-gate
rewriter retypes it to IDENTIFIER and `mcsReceiveStatement` (`MESSAGE cobolWord` as its second arm) never sees the MESSAGE
token.

Rule: section 8.9 does not reserve MESSAGE at 2023 (only MESSAGE-TAG), and section 14.9.31.2 prints `MESSAGE RECEIVED`, so a
program that declares MESSAGE and uses the phrase is legal source and is refused. The comment above `mcsReceiveStatement`
claims "a data item may bear the name ... the parser's lookahead tells the arms apart by the word after MESSAGE"; the
implementer's own probe and the review's show it does not.

The report calls this likely a FAMILY: any phrase keyword that is a reservation-gated word and can also be declared.

## Acceptance

- The root cause is fixed once in the gate/grammar interface (a phrase position where the grammar spells the word accepts
  both the keyword token and the retyped IDENTIFIER), not by a MESSAGE special case.
- Sweep result in the report: every other gated word that appears as a phrase keyword and can be declared (probe each, with
  a golden for the confirmed ones).
- Golden: `01 MESSAGE PIC 9.` plus `CONTINUE AFTER MESSAGE RECEIVED` compiles. The `mcsReceiveStatement` comment is
  corrected in the same change.

## Landed (wave 20261720 A, 2026-10-27)

**Re-probe** on the worktree's build (deae52c90): `recv4.cob` → `error COBOL2269: unexpected 'RECEIVED'` (the code
the parse-error funnel now gives; COBOL0307 in the filing). After the fix it compiles (COBOL1578 warnings only) and runs.

**Root.** The token-level gate retypes EVERY occurrence of a declared free word, so a format position that spells only
the token can never read the keyword of a program that declares the word. PB2623 had met this once (METHOD) and fixed it
with a hand rule in `CobolOO.g4`; the design doc then claimed METHOD was "the one live case". It was not.

**Fix (one mechanism, generated).** A `cobol-words.json` row carries the DETERMINATION `keywordWhereFree` (cited text:
the format that spells the word where §8.9 frees it); `gen-cobol-words.ps1` step 5c emits `<word>Keyword : TOKEN |
{wordAhead("WORD")}? IDENTIFIER` into `CobolWords.g4` for each, and the hand grammar spells such a word only through it.
The hand `methodKeyword` is deleted (it is now generated, same name, callers unchanged).

**Sweep** (every gated token × every hand-grammar rule that spells it, against its reservation pattern): four words
are spelled by a format at an edition where §8.9 leaves them free — METHOD (2023, END METHOD), MESSAGE (2023, RECEIVE
CONTINUE phrase), MULTIPLE (2002/2014/2023, LOCK ON phrase; §8.10 context-sensitive at 2023) and ORDER (85, SORT
`WITH DUPLICATES IN ORDER`). Re-probed: `01 MULTIPLE PIC 9.` + `LOCK MODE IS MANUAL WITH LOCK ON MULTIPLE RECORDS`
was `COBOL0001: unexpected 'MULTIPLE'` at 2002, 2014 and 2023; `01 ORDER PIC 9.` + `SORT … WITH DUPLICATES IN ORDER`
was `COBOL2269: unexpected 'ORDER'` at 85. All three compile and run after the fix. Every other gated word's formats
exist only at editions that reserve it (or only under `--permissive` for a construct the edition removed).

**Drift tests** (`CobolWordsDriftTests`): the generated rules are exactly the rows, of one shape, on gated words; no
hand rule spells a row's bare token (with a self-test that sees it fail); and the determinations are re-derived from
`specs/ISO_COBOL.md` — every gated word 2023 §8.9 leaves free that a 2023 general format underlines, and every gated
§8.10 word, must carry one (seen to fail with MESSAGE's row removed).

**Goldens.** `wiseowl/cases/14.9.31-RECEIVE/pb3794_message_data_item_continue_phrase` (accept 2023, four CONTINUE
spellings including the data item as arithmetic-expression-1), `cases/12.4.5.9-LOCK-MODE/pb3794_multiple_data_item_lock_on_multiple`
(accept 2002/2014/2023), `cases/14.9.40-SORT/pb3794_order_data_item_duplicates_in_order` (accept 85, GR3 b) release
order); refusals `cases/8.3.2-COBOL-words/pb3794-message-reserved-85-2002`, `pb3794-multiple-reserved-at-85`,
`pb3794-order-reserved-from-2002` (COBOL0901). `pb755-lock-on-omitted`'s expected text moves from `unexpected
'MULTIPLE'` to `missing token before 'MULTIPLE'` (same line and column, still refused: ANTLR's single-token insertion
of ON now succeeds through the keyword rule).
