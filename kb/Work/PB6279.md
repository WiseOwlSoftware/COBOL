**Rule it breaks:** single responsibility per type and a dependency direction a constructor can state (DESIGN-architecture-review §5.1); its own summary calls it the model of which C# fields a group emits and their image widths, and PhysicalChildrenOf states that every member of a Physical except Init is a property of the declaration alone (PhysicalModel.cs:88-94)

**Scenario:** Because BuildPhysicals computes Init (Values.FieldInit, PhysicalModel.cs:230, 241; Codec.ImageInitOf for a Tier-B backing, :163), PhysicalModel needs ValueInitializer and GroupImageCodec, which need PhysicalModel (GroupImageCodec and GroupValueSlicer take it in their constructors and walk it), so DataEmitter (DataEmitter.cs:23-35) has to build them in a fixed order and then close the cycle by assignment: phys.Values, phys.Codec and values.Slicer are `{ get; set; } = null!` (PhysicalModel.cs:43-44, ValueInitializer.cs:41). Any construction outside that order is a NullReferenceException at the first group, which no compiler check sees. And because Init varies with the occurrence context, the seed recipe, the OPTIONS clause and the activation LOCAL-STORAGE roots, the memo of a declaration-only layout is keyed on all four (PhysicalModel.cs:20, 112): kb/Work PB1134 was the defect this caused, a method-local group answered from the class-level entry with no background, fixed by widening the key rather than by separating the layout from the initializer.

**Measured how:** R2 batch finding `codegen-1--architecture--f1#3` (pair codegen-1--architecture), read in the pinned tree at 9e65164eb3a9; skeptics rule upheld, scenario upheld, site upheld.

**Target:** Split the two: a declaration-only physical layout (name, type, width, occurs and the leaf classifications, memoized per group with no recipe, options or activation in the key, and no reference to the initializers), and the initializer text asked of ValueInitializer and the image initializer at the point a field is written (RecordStructEmitter, GroupValueSlicer.ComposedInit). The layout then sits below both initializers, every dependency is a constructor parameter, and DataEmitter stops assigning back-edges. PB936 (one model per unit rather than per DataEmitter) is cheaper once the layout holds no context-dependent text.
