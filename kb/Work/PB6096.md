# PB6096 - MOVE CORR with two receivers and SEARCH with no WHEN: the message names the wrong mistake

Both programs are correctly refused (the rows CONFORM); the diagnostic misleads the programmer about why.

**1. MOVE CORRESPONDING, second receiver.** Format 2 of MOVE (§1985:VI.6.19.2) has exactly one identifier-2.

```cobol
       01 G1.
          05 F1 PIC X(3).
       01 G2.
          05 F1 PIC X(3).
       01 G3.
          05 F1 PIC X(3).
       PROCEDURE DIVISION.
       MAIN-PARA.
           MOVE CORR G1 TO G2 G3.
```

`--std 85` and `--std 2023`: `error COBOL0307: unexpected 'G3'. A period may be missing at the end of the previous sentence.`
Expected: a refusal that says MOVE CORRESPONDING takes one receiving group (Format 2 names one identifier-2).

**2. SEARCH without a WHEN phrase.** Both SEARCH formats (§1985:VI.6.22.2) require at least one WHEN.

```cobol
       01  T.
           05 E OCCURS 5 ASCENDING KEY K1 INDEXED BY IX.
              10 K1 PIC 9(2).
       PROCEDURE DIVISION.
       MAIN-P.
           SEARCH E AT END DISPLAY "X"
           END-SEARCH.
```

`--std 85` and `--std 2023`: `error COBOL0001: unexpected 'END-SEARCH'`. Expected: a refusal naming the missing WHEN phrase.
PB1321 already holds SEARCH ... NOT AT END (ANTLR recovery errors after a re-code); this is the missing-WHEN case.

**Fix.** Recognise both shapes in the parser's error strategy (the re-code layer `CobolErrorStrategy`) or bind them as a
specific refusal, each with its own diagnostic code from the catalog, and add a refusal case per shape at every edition.
Sweep the siblings: other verbs whose format allows exactly one operand where a list is written (MOVE CORR is the
reported one; ADD/SUBTRACT CORRESPONDING have the same one-receiver shape).

**Sites:** src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs (`GuessCobolIntent`, `CorrespondingReceiverMessage`, `SearchFormatShapeMessage`)

**Landed.** Both shapes are refused by name with COBOL2269 (the one statement-format-shape code, as hint 0e's other SEARCH shapes): `CorrespondingReceiverMessage` reads the MOVE/ADD/SUBTRACT CORRESPONDING statement the parser completed immediately before the token (the SEARCH ALL walk) and says it names one receiving item; `SearchFormatShapeMessage` says a SEARCH or SEARCH ALL ended (END-SEARCH or the period) before any WHEN phrase, when the expected set says a WHEN is due. A word that opens area A in the 1985 reference format stays the missing period's (COBOL0307). Goldens: `conformance-suite/cases/14.9.37-SEARCH/pb6096-search-no-when`, `pb6096-search-all-no-when`, `14.9.25-MOVE/pb6096-move-corr-two-receivers`, `14.9.2-ADD/pb6096-add-corr-two-receivers`, `14.9.44-SUBTRACT/pb6096-subtract-corr-two-receivers`, refused at every edition.
