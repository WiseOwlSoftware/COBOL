# PB1319 — OPEN — one edition's SIGN rules were never read

## What is known
```
$ cite.py --check 13.18.52.3 "a numeric report group description entry whose picture character-string contains the symbol 'S'"
  OK  §13.18.52.3 1)  (Syntax rules)
```
PB537 landed ONE subject screen (`DataBinder.SignClause.cs`, COBOLNET2422) with no edition gate: "The screen is
version-invariant as §13.18.52.3 is written." The implementer had no 1985 text. It recalled that the 85 wording
may differ in two places: a group SIGN may need at least one signed numeric subordinate, and group SIGN over a
non-DISPLAY subordinate may be treated differently.

## The question to settle
The mission (D13) is four per-edition compilers. For each edition, the fixer has to establish whether
§13.18.52.3's SR1–SR3 match the edition's text. Sources, in the precedence CLAUDE.md rule 1 sets:
- `docs/VERSION_CHANGE_REFERENCE.md`, which has a SIGN row or should have one.
- The 1985 standard's SIGN clause, if a copy can be obtained. GnuCOBOL's `-std=cobol85` behaviour is a
  REGRESSION NET only. It is never authority on an edition's text.

Where an edition differs, the difference goes into the VCR and the construct registry as an edition-gated row.
PB537's screen then asks the registry and stops being version-invariant. Where no edition differs, a VCR note
says so, and the 85 goldens that already exercise the screen (`85/pb537_sign_clause_subjects`) are the witness.

## What closes this note
A written determination, VCR row(s), and, only if an edition differs, a defect note for the gate.
