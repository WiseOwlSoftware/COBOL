# PB1319 — LANDED — one edition's SIGN rules were never read

## What is known
```
$ cite.py --check 13.18.52.3 "a numeric report group description entry whose picture character-string contains the symbol 'S'"
  OK  §13.18.52.3 1)  (Syntax rules)
```
PB537 landed ONE subject screen (`DataBinder.SignClause.cs`, COBOLNET2422) with no edition gate: "The screen is
version-invariant as §13.18.52.3 is written." The implementer had no 1985 text. It recalled that the 85 wording
may differ in two places: a group SIGN may need at least one signed numeric subordinate, and group SIGN over a
non-DISPLAY subordinate may be treated differently.

## The question to settle
The mission (D13) is four per-edition compilers. For each edition, the fixer has to establish whether
§13.18.52.3's SR1–SR3 match the edition's text. Sources, in the precedence CLAUDE.md rule 1 sets:
- `docs/VERSION_CHANGE_REFERENCE.md`, which has a SIGN row or should have one.
- The 1985 standard's SIGN clause, if a copy can be obtained. GnuCOBOL's `-std=cobol85` behaviour is a
  REGRESSION NET only. It is never authority on an edition's text.

Where an edition differs, the difference goes into the VCR and the construct registry as an edition-gated row.
PB537's screen then asks the registry and stops being version-invariant. Where no edition differs, a VCR note
says so, and the 85 goldens that already exercise the screen (`85/pb537_sign_clause_subjects`) are the witness.

## What closes this note
A written determination, VCR row(s), and, only if an edition differs, a defect note for the gate.

## Re-filed as a defect (analyses sweep, 2026-10-23)

Adjudicated read-only by an Opus cobol-adjudicator on main e7cf38ce4; accepted by the Mythos session.

COBOL-85's SIGN clause is stricter than 2023 §13.18.52.3 in two places, and the PB537 screen (COBOLNET2422) applies the 2023 rules at --std 85, so it under-rejects there: (a) a group SIGN needs at least one subordinate signed numeric (PICTURE S) entry; (b) every numeric entry the clause applies to (for a group: each subordinate signed numeric item) must be USAGE DISPLAY. Both repros compile clean at 85; so does the 85 golden conformance-suite/cases/13.18.52-SIGN/pb537_sign_clause_subjects.cob row H ('01 H USAGE COMP SIGN IS LEADING. 05 GB PIC S9(4)'), which pins the wrong acceptance and must move to the later editions. 2023 Annex E lists no SIGN change but NO SIGN, so 2014 = 2023; the edge is DERIVED at 2002 (the edition that recast SR1 around group categories with national group items), stated in a VCR Table 7 row so it can be overturned. Fix: an edition arm in DataBinder.SignClause.cs (the registry row asked by the one screen), negative goldens for (a) and (b) at 85, positive at 2002+.

Evidence: The COBOL-85 SIGN syntax rules are reproduced verbatim in vendor manuals that transcribe ANSI X3.23-1985 (Micro Focus 'The SIGN Clause', Veryant isCOBOL, Fujitsu; IBM Enterprise COBOL states the same): 'may be specified only for a numeric data description entry whose PICTURE contains the character S, or a group item containing at least one such numeric data description entry' and 'The numeric data description entries to which the SIGN clause applies must be described ... as USAGE IS DISPLAY'. Re-run at --std 85: '01 G1 SIGN LEADING SEPARATE. 05 X1 PIC X(3). 05 N1 PIC 9(3).' and a group SIGN over '05 C2 PIC S9(3) COMP' both compile clean; GnuCOBOL 3.2 field.c validate_sign has no per-dialect arm (silent on the edge).

Rule: §13.18.52.3 1) and 2) (2023, checked); 1985 rules from vendor transcriptions of ANSI X3.23-1985, derived per VCR Table 7
