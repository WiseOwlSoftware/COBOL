## Finding — copy-statement-p1 (silent)

The library model maps one text-name onto seven file spellings per directory ('', .cpy, .cob, .cbl, .CPY, .COB, .CBL) and returns the first one that exists. That creates text-names which are not unique within one library, and the ambiguity is resolved silently by an undocumented precedence. The A.1 item 40 determination (locating library text, SR5's allowable literal values) is also missing from CONFORMANCE.md.

**Rows:** SR-7.2.3.3-3

**Repro:**

```
BK3.cpy: '77 BK3VAL PIC X(3) VALUE "CPY".' and BK3.cob: '77 BK3VAL PIC X(3) VALUE "COB".' in the same directory; 'COPY BK3.' then 'DISPLAY BK3VAL.' -> CPY, with no diagnostic.
```

**Expected from the spec:** §7.2.3.3 SR3 'Within one COBOL library, each text-name shall be unique.' So a library in which BK3 names two texts is to be diagnosed as ambiguous, or the implementor-defined locating rule (§7.2.3.4 GR3, A.1 item 40, required and documented) must make the mapping one-to-one and document it.

**Observed:** Probe q03 printed CPY. FindCopybook lines 809-840 return the first hit. CONFORMANCE.md has no A.1-40 row, and PB160 owns the A.1 register debt. Deciding the mapping (extension precedence versus ambiguity error) is implementor latitude and is documented in the same change.

**Code site:** src/Cobol.Net.Frontend/Preprocessor/CopyProcessor.cs#FindCopybook; #CopybookExtensions

## Finding — copy-statement-p2 (silent)

Library availability is not enforced in the Cobol.Net compiler: Frontend constructs CopyProcessor with strict: false unconditionally, so a COPY whose library text does not exist silently becomes a comment (CBL3620 never fires), and FindCopybook falls back from an unavailable OF/IN library-name to the default library

**Rows:** GR-7.2.3.4-2, GR-7.2.3.4-1

**Repro:**

```
p1: `COPY NOSUCHBOOK.` in WORKING-STORAGE of an otherwise valid program. p8b: LIBA/p8book.cpy VALUE "LIBA", ./p8book.cpy VALUE "DFLT"; `COPY p8book OF NOLIB.` DISPLAY LB-A. (E:/Temp/claude/E--CobolSharp/a700c052-f9e4-4942-84ff-a13c7505d6ec/scratchpad/adj-d2/out/probe/copy-p2/p1.cob, p8b.cob)
```

**Expected from the spec:** GR2: library-name-1 'names a resource that shall be available to the compiler and shall provide access to the library text' — an unavailable library-name (and a text-name identifying no library text, GR1) is a violation the compiler reports; it does not incorporate text from a different library.

**Observed:** p1 compiles and runs (prints OK) with no diagnostic; p8b compiles clean and prints DFLT. The CBL3620 error exists but is gated by _strict, which src/Cobol.Net.Frontend/Pipeline/Frontend.cs:142 always passes false for every --std.

**Code site:** src/Cobol.Net.Frontend/Pipeline/Frontend.cs#Preprocess (line 142 strict: false); src/Cobol.Net.Frontend/Preprocessor/CopyProcessor.cs#FindCopybook (lines 815-838 fallback); src/Cobol.Net.Frontend/Preprocessor/CopyProcessor.cs#ResolveOneCopy (lines 412-419)
