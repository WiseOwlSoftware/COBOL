# PB3137 — the briefs' landing-check exit codes are a hand-maintained copy of enqueue.py's CHECKS

> flags: process-only

Source: review r3 of the PB3107/PB3123 branch (finding R3-1), 2026-10-13; filed by the operator.

**Mechanism:** `scripts/orchestrator/enqueue.py` defines the landing checks once, in `CHECKS` (on 2026-10-13: `devlog.py
check`, exit 6, and `orchestrator/landing_check.py`, exit 3). Step 7 of
`.claude/skills/workstream/templates/registrar-brief.md` and of `golden-lane-brief.md` restates them in prose ("runs
the landing checks (exit 3 the R3 file-set partition, 6 the DEVLOG entry)"). When PB3107 deleted
`landing_oracle.py` and its exit 7, both briefs still said ", 7 a stale arch-oracle baseline". Review r3 found it and
the branch fixed the text by hand (commit 9a6336157). Nothing would have failed if the reviewer had not read those two
files.

**Harm:** an agent dispatched with a stale brief is told about a refusal that cannot happen, or is not told about a
new one. A finisher acting on a removed exit code wastes its turns.

**Fix shape (for the implementer to confirm):** a drift test (site: `tests/Cobol.Net.Tests.Unit/LandingPipelineDriftTests.cs`)
that reads the exit codes named next to "landing checks" in every `.claude/skills/workstream/templates/*.md` and in the
workstream SKILL, and asserts they equal the codes in `enqueue.py`'s `CHECKS`, with a planted stale code making it fail
once. CLAUDE.md rule 5: the shape that makes the next retired or added check automatic.

**Related:** PB3023 (one landing script), PB3107 (the retired exit 7), PB3123.
