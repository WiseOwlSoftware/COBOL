**Rule it breaks:** One mechanism per job (DESIGN-architecture-review §5.1; CLAUDE.md rule 4): the pass already owns scope-exact per-unit resolution (VisitUnit selects _currentData/_currentRefs; ResolveItem, FileByName) yet Run builds five group-wide HashSet<string> keyed by CobolName from every unit (FlagConformancePass.cs:128-161), which the detectors test by base name only. DESIGN-flag-directives.md D2 and its e/f bullet call this idiom collision-tolerant, i.e. a knowingly accepted false positive against §7.3.15.4 GR4 e/f/m and §7.3.14.4 GR4 f.

**Scenario:** Compilation group with program A (FD F-A, SELECT ... FILE STATUS IS WS-STAT) and program B (its own 01 WS-STAT PIC XX, not named in any FILE STATUS clause), under >>FLAG-14 I-O-STATUS-04: B's IF WS-STAT = "04" is flagged, because _fileStatusNames holds A's WS-STAT and FileStatusRelation tests BareRefName only (FlagConformancePass.FileStatus.cs:137). The same happens inside ONE program for WS-STAT OF G2 when WS-STAT OF G1 is the status item (the qualifier is discarded), for a level-88 of the same name under another item (fs88 sets), for WRITE REC-OUT in B when A's REC-OUT belongs to a LINAGE file (FlagConformancePass.cs:479-480), and for TERMINATE of B's report sharing a name with A's VARYING report (:565-566). GR4 e flags only a reference to a data item specified in a FILE STATUS clause, so each is a spurious migration warning no source change in B can silence; conversely a qualified WRITE REC-OUT IN F-A is matched by GetText() text and never flagged. Verified by reading: the sets are unioned over group.Units with no unit key, and the detectors never consult _currentData/_currentRefs.

**Landed.** FlagConformancePass.Run builds no name set. Every detector resolves its operand in the current unit's scope and reads the role off the resolved object: the FILE STATUS test resolves the data item (ResolveItem, qualifiers honoured) or the condition-name (the new DataBinder.QualifiedConditionCandidates, the one resolution ConditionBinder.ConditionOf now also reads) and asks whether that item IS a visible file's FileStatusItem; WRITE/REWRITE resolve a record-name (qualified or not) or the FILE file-name to a FileModel among VisibleFiles (the unit's own plus its containers' GLOBAL files); TERMINATE resolves each report-name among DataBinder.VisibleReports. Re-probe on the pin (p2/p4 probes): program PN's own WS-STAT/88/LREC were flagged for PA's FILE STATUS item and LINAGE file, FS OF G2 and IS-04 OF FS OF G2 for G1's, and WRITE REC IN LF was missed; now each is judged by its own item.
