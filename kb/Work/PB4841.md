# PB4841 - the 'rides the managed slots (14.9.3.4 GR9)' citation the SORT branch replaced as wrong remains in ClassifyRedefinesClassesPass, the user-facing COBOL0899 text and Place.cs

**What the report says (the reviewer's words).** R1-4 LEAD (low, not blocking at round 1): `src/WiseOwl.Cobol.Compiler/Binding/Passes/ClassifyRedefinesClassesPass.cs:423` The branch replaced the inherited 'rides the managed slots (14.9.3.4 GR9)' citation at three sort sites as wrong, and its DEVLOG says the other files cite it only for null-seeding, but the same claim remains here, in the user-facing COBOL0899 text, and at Place.cs:303. Re-read: ClassifyRedefinesClassesPass.cs:423 and Place.cs:303 still carry `ISO §14.9.3.4 GR9` for the managed slot.

**R1.** kb/Work PB1071, PB1175, PB152, PB231 cite 14.9.3.4 GR9 (landed); none covers this claim.

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Passes/ClassifyRedefinesClassesPass.cs` (`ClassifyRedefinesClassesPass`), `src/WiseOwl.Cobol.Compiler/Binding/Model/Place.cs`.

Filed from a review lead of a merged fix-lane branch (wave 20261879 to 20261882) by the enqueue clerk; the lead's claim is the reviewer's, not adjudicated here. Harm flag: the citation sits in a user-facing diagnostic text (COBOL0899), so the message may point the reader at the wrong rule. The reviewer says the clause is the wrong one; this note did not run cite.py on it (the quoted claim is not a clause text) and it is the reviewer's claim.

**Fix (landed, wave 20261885).** `python scripts/spec/cite.py --check 14.9.3.4` shows GR9 is "If the INITIALIZED phrase is not specified and data-name-1 is specified, data items of class object or class pointer in the allocated storage are initialized to null": the NULL seeding, not the carrier of a pointer's value. That a pointer class member's value rides a managed slot is the implementor-defined D-SLOT representation (DOC-A.1-210, DOC-A.1-216). The three claims that said otherwise now name D-SLOT: `ClassifyRedefinesClassesPass` (the user-facing rejection text), `Place.cs` (`RedefViewPlace.For`'s backstop message) and `DataBinder.Ptr.cs` (the cell-claim comment). Sweep: every other `14.9.3.4 GR9` in `src` (PlaceRenderer, GroupImageCodec, StorageCell, CobolPtr, RuntimeApi, DiagnosticCatalog COBOL1695, Place.cs `PointerImageOffsetsOf`) cites it for null seeding, which is what it says.

**Sites (as changed):** `src/WiseOwl.Cobol.Compiler/Binding/Passes/ClassifyRedefinesClassesPass.cs` (`ClassifyRedefinesClassesPass.ComputeTier`), `src/WiseOwl.Cobol.Compiler/Binding/Model/Place.cs` (`RedefViewPlace.For`), `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.Ptr.cs`, `tests/WiseOwl.Cobol.Tests.Unit/RedefinesClassificationTests.cs` (`RedefinesClassificationTests.TierD_NestedPointerLeaf_StagedLoud`, which asserted the wrong citation).
