# PB3693 — a carried branch lands twice

**Sites:** `scripts/devlog.py` (`stamp`, `pending_titles`), `scripts/prune_worktrees.py` (`carrying_landing_branch`, the
`live_survey` call that runs it), `scripts/orchestrator/enqueue.py` (`open_predecessors`, `land`: the stamp step),
`scripts/orchestrator/land_lane.py` (none changed: `candidates` and `predecessor_free` read the survey's states and
`open_predecessors`).

## The case (2026-10-24)

PB3665's group (wave 20261102) was planned to continue PB3613's branch `worktree-wf_6ffe8083-b46-11`, so its implementer
merged that branch (8a35b057e). The landing lane then also landed b46-11 on its own (PR #535, merged 03:03:41Z, DEVLOG
2502). PB3665's own landing ran `devlog.py stamp`, which assumes a carried branch lands THROUGH its carrier and folded
PB3613's pending entry into PB3665's entry 2508, so PR #541 carried PB3613's title and history a second time. The
merge queue built #541's group on #535's, the two histories having two merge bases, and the `merge=union` rule on the
PublicAPI files kept `CobolNum.GroupDigits` twice (PB3694): the Release build failed RS0025 and the queue bounced #541.
A finisher (PB3665's report, `## Finisher`) took main's PublicAPI file and rewrote 2508 as PB3665's alone.

## The defect

Since PB3381 a predecessor reviewed CLEAN lands at once, alone. The DEVLOG stamp still folds a carried branch's pending
entry as if it landed through the carrier, and nothing tells the lane or `enqueue.py` that a branch another queued or
waiting branch contains is being landed separately. One rule must decide whether a contained branch lands alone or
through its carrier, read by `contained`, the lane, `enqueue.py land` and `devlog.py stamp` alike: when the carried
branch has landed (or is queued), the carrier's stamp folds nothing and its landing merges main first, so it has a
single merge base. Self-test: a carrier whose carried branch landed alone stamps only its own entry.

## Landed (2026-10-25, fix-lane wave 20261107 group F, with PB3367)

Re-probed by the fixtures of the readers: a successor carrying a WAITING TO LAND predecessor was itself WAITING TO LAND
(the survey), `land` stamped a branch carrying two pending entries without asking whether an open pull request already
lands one of them, and `stamp` folded every pending file. One rule now, read at each of the places: A BRANCH IS LANDED
ONCE; a predecessor reviewed CLEAN lands on its own (PB3381), so its carrier neither lands the same commits again nor
folds the same entry.

- `prune_worktrees.carrying_landing_branch` (new, run after `carrying_findings`): a WAITING TO LAND branch whose tip
  contains another WAITING TO LAND or ENQUEUED branch's tip is IN FLIGHT waiting on it (`waits_on`) until that pull
  request is on main (so the carrier's landing has one merge base), and a WAITING TO LAND branch contained in an ENQUEUED
  one lands through it (`carrier`). The lane's candidates and `landing_order` read states, so the lane is offered the
  predecessor and never its waiting successor. A STOPPED, BOUNCED or NOT QUEUED branch has a finisher and holds nothing.
- `enqueue.open_predecessors` (the one reader of "which open pull request owns an entry this branch carries", read by
  `land` and `land_lane.predecessor_free` alike) gained the PENDING arm: with more than one pending file, an open pull
  request that adds the stamped entry of a pending title (`devlog.slugify` of the title is the stamped file's slug) owns
  that pending entry. `land` asks it BEFORE it stamps and ends exit 15 PREDECESSOR QUEUED; the lane waits on the same
  reader.
- `devlog.stamp`: a pending entry whose title is already a stamped entry of the tree (the predecessor landed on its own
  and main came in) is dropped, never folded; an entry that would leave nothing to stamp is kept.
- `contained` is unchanged: a CLEAN-stamped branch keeps its own lifecycle (PB3381), which this rule relies on.

Self-tests: `prune_worktrees` (`wpred`/`wsucc`: the successor waits; `qpred`/`qsucc`: the predecessor lands through the
queued branch; the landing order offers `wpred` only), `enqueue` (a carried pending title owned by an open pull request is
exit 15 with nothing stamped; an unrelated open pull request, a merged predecessor and GitHub unreadable behave as for the
stamped case), `devlog` (the landed-predecessor drop, and the only-pending-repeats-a-title keep).
