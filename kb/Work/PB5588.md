# PB5588 - at --std 85 without WITH DEBUGGING MODE the characters *> inside a debugging section or a debugging line are refused COBOL0900 as the 2002 floating comment indicator, although that text is compiled as comment lines; the COBOL-85 floating-comment gate reads the text before the debugging comment treatment

**Sites:** `src/WiseOwl.Cobol.Frontend/Preprocessor/SurvivingFloatingComments.cs` (`SurvivingFloatingComments.Report`); `src/WiseOwl.Cobol.Frontend/Pipeline/Frontend.cs` (`Frontend.Preprocess`, `Frontend.LexAndParseOnce`); `src/WiseOwl.Cobol.Frontend/Parsing/DebuggingLineRewriter.cs` (`DebuggingLineRewriter.Rewrite`)

**Mechanism.** kb/Work PB5470 (landed, in the pinned tree) made `*>` an ordinary COBOL-85 text-word for COPY and REPLACE and moved the 85 refusal to `SurvivingFloatingComments.Report`, run in `Frontend.Preprocess` on the text the text stages have finished with. That gate runs on the whole program text. The debugging comment treatment runs later, in `Frontend.LexAndParseOnce`, where `DebuggingLineRewriter.Rewrite` (with `debuggingSectionsAreComments` at 85) moves a debugging section's tokens, and every debugging line's, off the default channel when no WITH DEBUGGING MODE applies. So a `*>` in text that the standard compiles "as if they were comment lines" is refused before it becomes comment, although a comment line may hold any characters of the computer's character set (§1985:III.2, Comment Line). The same characters in an ordinary `*` comment line compile.

**Found by.** The 1985 re-read 5, batch 2 (`kb/Work/PB4996/2026-11-14-reread-5b.md`): the reader of `E:/COBOL-coord/scratch/op-20261114/out-reread5/rs-10.json` read `1985-GR-XV.2.1.3-2` CONFORMS, and its refuter (`rs-10-refute.json`) OVERTURNED it to PARTIAL (over-rejects), with the debugging-line sibling (§1985:VI.4.3.4 GR5).

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094), so `inventory_rows` is empty; the row this note claims is below, recorded PARTIAL naming this note (records-rs5b). The debugging-line rule (`§1985:VI.4.3.4 GR5`) is the sibling the fix sweeps.

**Rules (1 claimed; citations checked with `scripts/spec/cite.py --check`, log `E:/COBOL-coord/scratch/op-20261114/records-rs5b/cites.txt`).**

- `1985-GR-XV.2.1.3-2` (refuter OVERTURNED CONFORMS; harm: rejects-legal-source). `§1985:XV.2.1.3 GR2`: "any USE FOR DEBUGGING statements and all associated debugging sections are compiled as if they were comment lines"; sibling `§1985:VI.4.3.4 GR5`: "any debugging lines are compiled as if they were comment lines".

**Repro.** `E:/COBOL-coord/scratch/op-20261114/out-reread5/refute-rs-10/dbg/dfloat.cob`:

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. DBG.

       CONFIGURATION SECTION.
       SOURCE-COMPUTER. X86.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
```

`cobol.exe --std 85 --source-format fixed --run dfloat.cob`. The sibling `dbg/ddline.cob` has the line `      D    MOVE 1 TO W *> a 2002 floating comment` in MAIN-PARA, with no mode; the control `dbg/dcomment.cob` holds the same characters in a `*` comment line.

**Observed (the pinned compiler of `E:/COBOL-wt/coderead85-tree-d`, main dc1f2dcce8, rerun 2026-11-14 from copies in `E:/COBOL-coord/scratch/op-20261114/records-rs5b/rerun/`; log `E:/COBOL-coord/scratch/op-20261114/records-rs5b/rerun-log.txt`).** `dfloat.cob(14,24): error COBOL0900: the floating comment indicator *> requires COBOL-2002 (targeting COBOL-85)`, exit 65, no object program; `ddline.cob(19,24)`: the same error, exit 65. Control `dcomment.cob` compiles and prints MAIN.

**Expected (from the 1985 text).** No diagnostic: both programs compile, the debugging section and the debugging line are comment, and each prints MAIN.

**Fix direction (root cause, CLAUDE.md rule 4).** The 85 floating-comment gate must judge only text that is program text: either run it after the debugging comment treatment, or have it skip the regions the debugging rewriter will make comment, read from the one place that decides them (`DebuggingLineRewriter`'s section and line finding), not a second copy of that decision. Pair the order with a drift test like `CommentEntryResolutionOrderDriftTests`. Sweep: the COBOL2495 (unseparated `*>`) report from the same gate, and any other COBOL-85 text gate that runs before the debugging comment treatment.

**Lead (filed here as a lead, not a separate note; the clerk may split it).** Every failed COPY at --std 85 also draws a spurious COBOL0900 "floating comment indicator *>" at the COPY's position, outside any debugging section: `E:/COBOL-coord/scratch/op-20261114/out-reread5/refute-rs-10/dbg/dcopymiss2.cob` (`COPY NOSUCHMEMBER.` in MAIN-PARA) gives `error CBL3620: COPY copybook 'NOSUCHMEMBER' not found` and then `dcopymiss2.cob(19,12): error COBOL0900: the floating comment indicator *> requires COBOL-2002 (targeting COBOL-85)` (rerun log above). The COPY stage apparently leaves a `*>` marker in the text where the member was not found, and `SurvivingFloatingComments.Report` reads it as source: the same gate reading text that is not the program's.
