# PB274 — an invariant that was a determination

Found by the arithmetic-wave review fleet over the D-B/D-C/PB194/PB195 working tree, 2026-08-31, and fixed in the change set that landed the wave. Every number below was re-derived independently by the implementer (a 34-digit emulation of `CobolDec.cs` validated against the shipped `pb167` goldens, and 80–120-digit `Decimal` truth) BEFORE the confirming run, and then confirmed by it.

The claim is true of the literal's VALUE and false of the LANE, and the four copies stated it without that
distinction: `NumericRenderer.LiteralNum`'s doc comment, `COBOLNET_NUMERIC_DESIGN.md`, `CONFORMANCE.md` A.1 item
82, and `pb156_float_literal_exact_native`'s own header.

## Measured

```
01 A18 PIC 9(18) VALUE 999999999999999999.   (A18 * B18 = 36 significant digits)
IF A18 * B18 + 0.0E+0 = A18 * B18   →  NE     the decimal128 lane rounds to 34
IF A18 * B18 + 0.0    = A18 * B18   →  EQ     the Int128 lane carries all 36
```

## Disposition — DOCUMENT, do not "fix"

§8.8.1.3 leaves *"the method of evaluating an arithmetic statement"* to the implementor, so both lanes conform
and the choice is a determination. All four copies now say: the VALUE a literal contributes is its exact
§8.3.3.3.3 rule-5 value in every position and every arithmetic mode, and the LANE it selects under native
arithmetic is a published §8.8.1.3 determination — including its consequence that INTERMEDIATE ROUNDING
(§11.9.11), PROHIBITED included, reaches a native statement carrying a float literal. Pinned by
`pb156_float_literal_exact_native`'s LANE / LANEF legs, which is the first time the fact has been observable in
the corpus at all.
