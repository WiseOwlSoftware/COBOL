# PB1957 — OPEN: make the local gates and CI the same build, or reproduce each difference locally

Owner 2026-10-04, after train 1007's group D (PB1402) and train 1013's group M (PB322) each cost a CI round trip and a dropped
cluster: "We should catch as much of these issues locally as possible which can only occur when CI/local use effectively
identical builds." Both reds were invisible to every local gate: PB1944 (ANTLR read the grammar as Cp1252 on the CI Windows JVM,
UTF-8 locally) and PB1955 (the CI `guard` job's NIST loop is not part of any local gate).

## Settled so far

- **Row 40 (and the Linux half of row 41): (b), reproduced locally.** `scripts/linux-gate.sh` gained the default leg
  `guard`, which runs `bash scripts/guard-fast.sh` in the Linux clone exactly as CI's `guard` job does (the NIST suite
  through the `cobol` CLI, the manifest audit, the guard's own self-tests, legacy Unit + Integration), with a private
  `TMPDIR`. Every lander (L10) runs the Linux gate, so it runs it. ⭐ Under batched gating (kb/Work PB2515, the
  owner's rule since 2026-10-10) the implementer runs no Linux gate (I8): it is the lander's, with the rest of the
  population, and an implementer runs it only while the owner has set the implementer scope to `whole`. The invariant
  below still holds, because CI is still never a first run: before every push the lander runs the same code through the
  same processes CI does — the whole population on Windows, the Linux gate (all four legs, `guard` included) and the
  oracle — on the exact head it pushes. It was not added to
  `build-local` on Windows: CI runs the job on Linux only, and a second run under Git Bash would cost minutes for no
  CI difference. `LinuxGateDriftTests.EveryScriptCisLinuxJobsRun_IsALegOfTheLinuxGate` holds every `run: bash
  scripts/….sh` step of a Linux job to a default leg running the same script (wave 1015 group V, with PB1955).

- **The script self-tests: (a), made identical (kb/Work PB2563, 2026-10-08).** CI's audits job (Linux), its
  `windows-build-test` job (Windows) and `greenfield-unit` (`--built`), the gate's `SELF-TESTS` audit and the Linux
  gate's `selftests`/`selftests-built` legs all run `scripts/self_tests.py`, which discovers every self-test under
  `scripts/` and gives each a private coordination directory and a private git global config, so a local run and a
  CI run see the same environment. `SelfTestDiscoveryDriftTests` forbids any of those entry points to name a self-test
  by hand. Since kb/Work PB2914 (2026-10-10) the IMPLEMENTER gate reuses a self-test's recorded PASS while everything
  that self-test read is unchanged; CI, the Linux gate and the lander's gate still RUN every self-test (they are the
  runs that record the PASSes), and the same drift test forbids `--reuse` in CI and the Linux gate, so the invariant
  holds: CI runs nothing the lander's local gate did not run on the same tree. The rest of the audits job (work.py check, check_practices.py and the citation audits CI runs that the
  gate does not) is still PB2431.

## The invariant this note serves (owner 2026-10-04, in CLAUDE.md Testing)

GitHub CI must never fail when the same code was tested locally by the same processes. CI is the verification of the local
process, never its first run, so every CI red is also a defect in the local gates. Two mechanisms follow, both still to build:
(1) a drift test that maps EVERY job of `.github/workflows/build-and-test.yml` to a local leg (a gate leg, the Linux gate, a
CI audit run by the lander) or to a recorded reason it cannot run locally, so a new CI job with no local counterpart fails the
test the day it is added; (2) a post-mortem rule for any CI red: the fix lands with the local-gate change that would have
caught it, and the note names the row of the survey it belongs to. Done so far (2026-10-04): the CI runner and the local WSL
distro are the same Ubuntu release; ANTLR reads grammars as UTF-8 under both JVM defaults; the CI `guard` job's NIST loop
runs in the Linux gate (a fourth default leg).

## The decision the table asks for

Each row below is either (a) made IDENTICAL in CI and local (pin the version, pass the flag, set the variable in both), or (b)
REPRODUCED locally by a gate leg that forces CI's setting, or (c) recorded as irreducible with its reason. Owner direction so
far: use UTF-8 everywhere (the ANTLR step passes `-encoding UTF-8`; no escapes); move CI and the local WSL to Ubuntu 26.04
together (WSL upgraded in place, CI pinned to `ubuntu-26.04`, in that order). Rows the survey could not settle are marked
NEEDS-OPUS and need a judgment before work starts.

Highest value first, by what each already cost or would cost: the CI `guard` NIST leg run locally (PB1955's class); a Release
build and test leg locally (a `[Conditional("DEBUG")]` call site has already been stripped in Release); the explicit UTF-8 for
ANTLR (PB1944, in wave 1014 group R); the compiled-program cache forced off locally as CI has it (`COBOLNET_COMPILE_CACHE=off`);
a pinned time zone; a pinned SDK patch and an explicit JDK; the three audits missing from the gate's `AUDITS` tuple; and the
ubuntu pin.

## 2026-10-07 18:36 PDT — the R1 landing's CI red: a register check read the working tree, CI reads a clean checkout

**What CI saw that the local gates did not.** The R1 landing (PB2118) went red in CI run 37712135076, job `audits`,
step `work.py check`. PB2197 names `src/Cobol.Net.Frontend/Generated/CobolParserCore.cs`, and the R3 rule "every path an
open note names exists" tested that path with `Path.exists()` on the WORKING TREE. The file is the ANTLR build output.
It is never committed and exists in every BUILT checkout. The only local run of `work.py check` was the lander's
own, by hand, in the built worktree, and it passed. Neither gate runs CI's `audits` register step:
`build-local.ps1` has no audits leg, and `linux-gate.sh` runs only the hook self-tests from that job. Both gates were
GREEN. CI's `audits` job runs on a fresh checkout that has not been built, so the file is absent there. The general
shape is that an untracked or generated file makes a missing path look present locally, and a second cause is that
CI's audits job has no local leg.

**Why the fix makes local == CI.** Existence is now read from the git index (`work.tracked_paths`, one `git ls-files`
per check), never the filesystem. The index is the same in a built checkout, an unbuilt one and CI's, so the verdict no
longer depends on whether the tree was built. A `Generated/` path counts as a build output: it is never "missing", and
the note must name the `.g4` it is generated from (`work.build_output_problems`). `test_plan_wave.py` plants an
untracked path that exists locally (`src/Cobol.Net.Frontend/obj/project.assets.json`). It also plants a note that names
only the generated parser. Both plants pass under the old filesystem rule and fail under the new one.

**The sweep** covered every script in CI's `audits` job and `scripts/arch`, looking for `.exists()`, `os.path.exists`,
`.is_file()`, `glob` and `rglob` reads of repository paths:
- `scripts/spec/audit_evidence_supersession.py` (the `path` arm, "cites <path> — that file no longer exists"): the same
  defect. A frozen record citing a generated file passed in a built tree. FIXED: it reads `work.tracked_paths`, and its
