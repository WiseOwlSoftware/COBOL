# PB1249 — OPEN

## Measured

**linkage-section** — The §13.7.3 SR4 referenceability rule for linkage items is not enforced anywhere: a LINKAGE item that is not a USING/RETURNING operand, not subordinate to one, not a REDEFINES/RENAMES of one (or subordinate to that), not a condition-name/index-name of one, and not BASED is bound as ordinary callee-local storage and every reference to it compiles clean.

- **Repro:** out13/probe/linkage-section/sr4.cob --std 2023 --run: callee `LINKAGE SECTION. 01 L-A PIC 9(4). 01 L-Z PIC 9(4). 88 L-Z-ON VALUE 1. PROCEDURE DIVISION USING L-A. MOVE 5 TO L-Z DISPLAY L-Z IF L-Z-ON ...` compiles clean and prints Z=0005. sr4b.cob (main program, no USING, DISPLAY of a LINKAGE item) compiles clean at --std 2023 and --std 85.
- **Expected (spec):** §13.7.3 SR4: a linkage item 'may be referenced within the procedure division of that source element if, and only if, it satisfies one of the following conditions' a)-e) (or is BASED). L-Z and L-Z-ON satisfy none, so each reference (MOVE, DISPLAY, IF) is a compile-time error at every edition.
- **Observed:** Clean compile; L-Z is given callee-local storage and the program runs. Positive arms a)-e) all work (sr4p.cob: 88, INDEXED BY, REDEFINES, RENAMES of a formal). No diagnostic and no 13.7.3 SR4 citation exists in src/Cobol.Net.Compiler.
- **Code site:** src/Cobol.Net.Compiler/Binding/DataBinder.Linkage.cs#CallBindLinkage (the point where LinkageRoots and LinkageFormals/LinkageReturning are both known — the set of referenceable linkage roots is derivable there and must be consulted by name resolution for procedure-division references)
- **Clause (adjudicator):** ISO/IEC 1989:2023 §13.7.3 SR4 (cite.py --check 13.7.3 "It is an operand of the USING phrase or the RETURNING phrase of the procedure division header" -> OK §13.7.3 4) a))
