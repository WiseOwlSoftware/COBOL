# PB5131 - the HANG arm's pid wait has no end condition for a rerun that never writes the pid

**Sites:** `scripts/self_tests.py:1385` (`fleet_arms`: the HANG arm, its pid wait and the doubling rerun loop).

**Found.** Review R3-1 of the PB5098 branch (low, not blocking). The rerun loop ends only when `hang.pid` exists. Nothing ends it
when a rerun of `test_hang.py` finishes without writing the pid (RED, or GREEN past its own 60 s sleep). `check()` only appends
to `fails`, so a regression that makes the planted self-test exit before its write turns the named FAIL lines into an unbounded
loop of reruns (each fast, the limit doubling with no effect), and `self_tests --self-test` never prints its verdict. Second
half: the loop tests existence, not content, so a stop landing between `open(hang.pid, "w")` and its flush leaves an empty
file and `tree_dead` raises `ValueError` on `int("")` (a microsecond window).

**Dispositions of the PB5098 review's other leads (checked on origin/main 2026-11-10).** R1-2 (a fixed 10 s reaping wait in
`tree_dead`) is fixed: `tree_dead` now waits with no limit (self_tests.py:1378, "no wall clock"). R2-1 (a slow start read as a
surviving tree) is addressed by the doubling rerun loop itself; this note is what that loop leaves open. R1-3 is PB5114.

**Owed.** A rerun that has ended (the job's exit observed) without a pid ends the loop with a named FAIL; the pid read tolerates
an empty or partial file (retry, or write the pid atomically in the planted test). Self-test: a planted test_hang.py that exits
at once.
