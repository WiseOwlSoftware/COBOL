# PB2039 — OPEN — `MOVE SELF TO N` is a syntax error where it should be a named refusal

Filed 2026-10-05 by the train-1020b lander from the PB1425 implementer's report (wave 1020 group C, `New defects` 1).

**What happens.** PB1425 made SELF, `[x OF] SUPER` and the object-view (`x AS c`) identifiers of the EXPRESSION tier
(`CobolExpressions.g4#primaryExpression`), so relations, EVALUATE, INVOKE and inline arguments, SET senders and the
RAISING phrase now reach one binder door (`OoBinder.OoIdentifier.cs#OoBindOoIdentifier`). The statement operand rules
that sit OUTSIDE that tier — `sendingOperand` in `src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4` (since kb/Work PB2114 the ONE rule for MOVE, the arithmetic, FROM, INITIALIZE and INSPECT sending operands) and every
other rule that pairs `functionCall` with `inlineMethodInvocation` itself — carry neither `objectView` nor
`selfAndSuper`. So `MOVE SELF TO N` (in a method) parses to nothing and is refused `COBOL0001 unexpected TO`.

**What the standard requires.** `cite.py --check 14.9.25.3 "The class of identifier-1 or identifier-2 shall not be
index, message-tag, object, or pointer"` → OK §14.9.25.3 1). The source is illegal either way, so no program changes
meaning; the defect is that the refusal neither names the operand nor quotes the rule.

**Fix shape.** Let those operand rules carry the identifier tier's OO alternatives (or reuse the expression-tier
identifier rule), bind them through `OoBindOoIdentifier`, and refuse by each statement's own class rule (MOVE SR1 and
its siblings). Sweep every rule that names `inlineMethodInvocation` beside `functionCall`.

**Repro.** A method body containing `MOVE SELF TO N` (N any elementary item), compiled at 2002+. Code site:
`src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4#sendingOperand`.
