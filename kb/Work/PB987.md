# PB987 — LANDED (wave 54 group F)

## Repro — measured
`scratchpad/w48s/p4.cob`: class C892P's GET PROPERTY P returns an incrementing counter (1, 2, 3, …). The main program
runs `PERFORM UNTIL P OF S > 3 OR K > 8 ADD 1 TO K END-PERFORM` and displays K. Observed **`K=09`**; expected
**`K=03`** (P answers 1, 2, 3 on the first three tests, 4 on the fourth — the loop body runs three times).

## The rule
`OK  §8.8.4.13 2)` — "Values are established for arithmetic expressions and functions if and when the conditions
containing them are evaluated." A property reference (object-property, Format 7 of §8.4.3.1.2) is an inline invocation of the GET method; each evaluation of the UNTIL condition must activate the GET method again.

## Code site
`OoWrapPropertyOps` (StatementBinder / BoundTree) hoists the property fetch into a statement-scoped temporary, evaluated
before the statement; function activations have a per-evaluation form (PB892 built it for expression-position
activations) and property fetches have no such twin.

## What the fixer owes
Give the property fetch the same per-evaluation placement the function activation uses inside a condition that is
evaluated more than once (PERFORM UNTIL / VARYING … UNTIL, SEARCH WHEN, EVALUATE subjects evaluated per WHEN are the
siblings to measure). Golden at 2002 with the counter property; the ordering sibling (a property on the right of an
AND whose left side is FALSE must NOT be activated — §8.8.4.13 rule 1 short-circuit) belongs in the same golden.

## Landed — wave 54 group F (2026-09-22)

Re-probed on the implementer's own build: p4 printed `K=09`; after the fix `K=03`. Root: the per-evaluation mark
(`UdfBinder.PendingCount`, an int) marked only the pre-op list, so a window never saw the property ops, which the
statement-level wrap then hoisted. It is now `UdfBinder.Mark` — a `PendingMark(PreOps, PropertyOps)` over BOTH
lists — and every window's `UdfAttachPerEvaluation` drains the property ops registered inside it
(`OoBinder.OoDrainPropertyGets`, GETs ahead of the pre-ops — the statement-level order) into the SAME
`BoundUdfEvaluated` / `BoundUdfEvaluatedExpr` wrapper. The thirteen window sites (ConditionBinder AND/OR, PERFORM
UNTIL, VARYING UNTIL/BY/AFTER-FROM, the six EVALUATE object windows, both SEARCH WHEN forms) needed only `int` →
`var`: a future window inherits both lists by construction. The GET builder is ONE method (`PropertyGet`) used by
the statement wrap and the window drain. Golden `2002/pb987_property_per_evaluation` covers UNTIL, the AND and OR
short-circuits, EVALUATE WHEN order, SEARCH WHEN and VARYING BY — every sibling the note named; negative
`negative/pb987-property-per-evaluation-below-2002` (COBOLNET0900 at 85). GR-8.8.4.13-2 → CONFORMS (batch
`w54f-pb987-property-per-evaluation`, GAP −1).
