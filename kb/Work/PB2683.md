# PB2683 — Delete notes sized by census 79a4b6c58 miss members only the legacy engine used

## What was found (w1041 H, PB2194, landed in train 1041b)
Census R0-0157 at `79a4b6c58` named 46 caller-free members of
`src/WiseOwl.Cobol.Frontend/Diagnostics/DiagnosticDescriptors.cs`. Re-measured on `4a4bd8aa9`, 187 of its 217 members had
no reference. The census counted the other 141 as used because the legacy compiler referenced them
(`git grep` at 79a4b6c58: `DataStatementBinder.cs:113` CBL0901, `ProcedureNameResolver.cs:117` COBOL0400,
`SymbolValidator.cs:104` CBL3101), and that compiler has since been deleted (PB2110). The 187 match census
`cd85e4901794`'s finding R0-0152 member for member.

## The mechanism
`scripts/arch/census.py` THE SCOPE RULE (`scope_of`, the `excluded` arm, `LEGACY_PREFIX`) says of the excluded legacy
projects "nothing in the census depends on it, so leaving it out changes no number about the product". That is false
for reachability: a use FROM an excluded project still kept a product member alive, so a member whose only callers
were legacy was reported as used. With the legacy engine gone from the solution the arm partitions nothing today, so a new
census run is not affected; the damage is in the notes already written from `79a4b6c58`.

## What to do
1. Every OPEN Delete note (`cluster: ["PB2119"]`, `census_ids:` pinned to `79a4b6c58`) is re-measured against census
   `cd85e4901794` (or a fresh run) before its wave is dispatched, and its member list widened to the current dead set.
2. Either correct the scope rule's comment (and make an excluded project's uses not count toward reachability), or
   delete the `excluded` arm now that no project matches `LEGACY_PREFIX`; pin the choice with a `census.py --self-test`
   arm and `ArchCensusDriftTests`.

Repro: `git grep -n "Descriptors\.CBL0901" 79a4b6c58` (a legacy-only caller); code site `scripts/arch/census.py`
(`scope_of`, the THE SCOPE RULE comment block).
