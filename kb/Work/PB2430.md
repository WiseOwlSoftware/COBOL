**Found by:** the PB2118 Draft 10 reviser (PB2118 "Draft 10", "What a tenth refuter should try first" 3). Draft 10's
content containment (E2) excludes a branch from the in-flight set when its committed changes are contained in the
landing; it reads `git` objects, never a worktree's working tree.

**Harm:** an implementer's uncommitted edit to a file the landing also changes is invisible to both containment and
collision: the landing passes, and the implementer's next commit meets a changed base the check never reported.

**Fix direction (rule 5):** treat a worktree's dirty files (`git status --porcelain` per worktree, already enumerated for
the in-flight set) as in-flight changes for collision, and as never contained; a self-test case with an uncommitted
edit on a shared file.
