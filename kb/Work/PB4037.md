# PB4037 — the `ExpressionExtent` remarks give the wrong reason for the bound

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/ExpressionExtent.cs:28` (the remarks), `:86` (the exponent-form literal sentence); `Visit(BoundNumLiteral)`.

**What.** The remarks say the bound holds because every operation is evaluated exactly under every arithmetic mode. Under
`ARITHMETIC IS STANDARD-DECIMAL` (8.8.1.5.2, 34-digit maximum precision) a `+`, `-` or `*` result past 34 digits is rounded,
so the premise is false; the bound is still a valid upper bound (rounding cannot add digits), so the code is right and the
stated reason is not. Line 86 also lists an exponent-form literal as a source of negative scale, which `Visit(BoundNumLiteral)`
already excludes. Cite the clause with `python scripts/spec/cite.py --check` when rewriting.

**Fix shape.** Restate the bound as an upper bound that holds because a rounded result has no more digits than the exact one,
and delete or correct the exponent-form sentence.
