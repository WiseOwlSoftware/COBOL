## Landing: the status line's reading anchors at any age in the current quota week

`budget.live_reading(acct)` no longer takes `now` and no longer tests the reading's age; `LIVE_MAX_AGE` is deleted. The
reading goes into the readings list like any recorded one and `estimate`'s one week rule (`week_start <= noted_at <= now`,
newest wins) decides whether it anchors, so a reading from a previous week is no anchor and a stored reading newer than the
status line's still wins. `current` returns `live_problem`: a present but unreadable or malformed `rate-limits.json` (or one
without `seven_day`) is printed as `METER FILE PROBLEM`, a missing file stays quiet. The output line now ends
`(anchored on the status line's 56 % of 47 min ago + telemetry since)`.

**Fable row.** Not available. The real `~/.claude/rate-limits.json` carries only `seven_day` (`used_percentage`,
`resets_at`) in `rate_limits`, for every session; there is no `five_hour` row and no per-model row. Nothing was changed
for it; `statusline_tap.py` stores whatever rows arrive, so a second row would reach the file without a tap change and
would need a `live_reading` change to be carried through.

**Proof.** `python scripts/orchestrator/test_budget.py`: 64/64 OK, including the arms for a 44-minute-old reading (own figure,
non-null anchor; figure plus telemetry), last week's reading, and a malformed file. Real host, 2026-11-11: the line anchors
on the 56 % reading.
