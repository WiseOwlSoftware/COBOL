# PB97 — LANDED — `01 N PIC 9(5)V99 VALUE 1.5E+3.` → CS0595 backend failure; `88 IS-TEN VALUE 10.` on `PIC ZZ9.99` never true

> ⚙ **flags:** crash, wrong-answer, silent, under-rejects · found 2026-08-18 probing [[PB66]]'s VALUE legs ·
> **landed 2026-08-18** (DEVLOG 1322, the same change set as PB66).

**Measured** (`--std 2023`):
```
       01 NU1 PIC 9(5)V99 VALUE 1.5E+3.        ->  backend compilation failed: (17,24): error CS0595 Invalid real literal
       01 NE PIC ZZ9.99.
          88 NE-IS-TEN VALUE 10.               ->  emitted CobolString.Compare(NE, "10") == 0  (NE holds " 10.00": FALSE)
       01 NE1 PIC ZZ9.99 VALUE 1.5E+3.         ->  compiled silently (SR6 forbids the form)
       01 NE2 PIC ZZ9.99 VALUE 12345.          ->  compiled silently (SR6: no truncation of digits)
```

**Spec:** §8.3.3.3.3 GR5 — a floating-point literal's value is significand × 10^exponent (exact); §13.18.63.3
SR2 — a numeric subject takes numeric literals representable exactly; SR6 — a numeric-edited subject's numeric
literals (formats 1, 2 AND 4 of the VALUE clause) "shall be converted to their numeric-edited forms according to
the rules for the MOVE statement, such that no truncation of digits or sign is required", fixed-point literals for
fixed-point formats and floating-point literals for floating-point formats (ZERO and the literal-zero forms for
either); SR3 — a signed literal needs "a numeric-edited data item with a representation of a sign"; §8.8.4.5 GR2 —
a condition-name compares by the relation-condition rules (so against the EDITED value).

**Mechanism:** the VALUE raw-text pipeline never expanded the floating form — `EmitText.UnscaledAtScale` wrote
`15EL`; `ValidateValueCategory` (the item-VALUE + level-88 funnel) had no form rule; `ValidateNumericValue`
served only category numeric; `ConditionRenderer.StringMembershipValue` decoded the raw literal text for every
alphanumeric-class conditional variable, numeric-edited included.

## As built (DEVLOG 1322)

- `NumericLiteral.IsFloatingPointForm` / `ExpandFloatingPoint` (Frontend Common — the ONE expansion): the exact
  fixed-point text of a floating-point literal.
- `DataBinder.ValidateValueCategory` decides the FORM once for both funnels: a floating-point literal on a
  fixed-point NUMERIC subject is rewritten to its exact fixed-point value (SR2's checks then apply downstream);
  on a fixed-point numeric-edited subject it is COBOLNET1659; a nonzero fixed-point literal on a floating-point
  numeric-edited subject is COBOLNET1659 (the [[PB66]] direction moved here). `NormalizeIfNumericLiteral` admits
  the E-form so a comma-decimal significand normalizes (see [[PB98]]).
- `ValidateNumericValue` serves the numeric-edited subject: digit positions (P excluded) at
  `CobolEdit.MaskScale`, sign-bearing = an editing sign symbol; the floating-point form checks the significand's
  digit run against `FloatMask.SigDigits` and the normalized exponent against `MaxExp` (COBOLNET1625).
- `ValueInitializer.EditedImageOfNumericValue` is the ONE compose of a numeric-edited item's numeric VALUE image
  (fixed → `EditCompose`, floating → `EditComposeFloat`, ZERO at ≥ 2023 — VCR 35), used by the initializer AND by
  `ConditionRenderer.StringMembershipValue`, so a numeric-edited conditional variable's level-88 values (singletons
  and THRU ranges) compare edited images.
- Golden `2023/pb97_value_literal_form_and_88_edited`; negatives `pb97-value-form-fixed-edited`,
  `pb97-value-edited-truncation`. The VCR-86 gate (numeric-literal VALUE for numeric-edited = 2023) now sees the
  floating form too (`IsNonZeroNumericLiteral` reads the significand).
