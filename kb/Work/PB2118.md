# PB2118 — R1 (DESIGN-architecture-review §3 R1)

The one artifact every later wave executes against; an error here compounds through tens of waves, which is why
it is the one planned use of a frontier model. **Prerequisite:** PB2115's census (facts before design); PB2116 and
PB2117 need not have landed. **Models:** author = Mythos 5.1 (`claude-mythos-5-1`), ONLY after the owner's explicit
approval for this dispatch (R69 §4, MANDATORY-PRACTICES P1); refuter = Opus (`cobol-refuter`); a second Mythos
round only if the Opus refuter cannot break the design and the owner approves again. Owner approval closes R1.

## The section states (written INTO `docs/rearchitecture/DESIGN-architecture-review.md`, a new §8 "Target")

1. **Layers and allowed edges:** Editions → Frontend → syntax tree → Binding → bound tree → Validation → Lowering →
   CodeGen (behind `ICodeGenBackend`) → Runtime, each edge written down; an architecture drift test (Roslyn or
   metadata over the built assemblies) fails on any other edge, one rule in one place.
2. **Layout rules:** folder equals namespace; one public type per file; file name equals type; a partial splits only
   along a named concern.
3. **Per god class** (from PB2115's measured census): responsibilities, the types they become, the seam each
   exposes, the extraction order. `DiagnosticCatalog` becomes data plus a generator, keeping every code's identity
   and the `docs/DIAGNOSTICS.md` generation.
4. **Grammar structure:** modular grammars per division or facility where ANTLR's import rules allow; the rules
   already enforced stay.
5. **Closed hierarchies:** which become C# 15 unions and in what order (the forgotten-arm dispatch class), each a
   later R4 wave under the §4 contract; the SDK question itself stays R64's (trails the review).
6. **What is given, not reopened:** the approved §8.13 external-repository design (`DESIGN-external-repository.md`),
   the text model (R51–R53) and every landed owner decision.
7. **The wave plan's SHAPE** (not a list of waves): leaves first — runtime values, editions, front end, binding, code
   generation — with the fix-lane partition rule from R69 §2.

### Decided

1. **Fourteen layers, as the code is** (§8.1): no lowering layer (PIPELINE D1, codegen-backend §2.3); the runtime
   a foundation every layer may use (it references nothing; the one numeric and text law lives there); the compiler's
   layers are its existing namespaces (`Binding.Model` → `Binding.Bound` → the binders → `Validation` → `CodeGen` →
   the driver); the ANTLR parser, its hand-written superclass, the CST façade and the compile-time expressions are one
   front-end layer by construction. The whole allowed-edge list is the proposed `docs/rearchitecture/architecture-edges.json`;
   23 of the 206 measured edges (269 uses) are violations, each named with the wave kind that removes it, and the
   largest refusal is `codegen → binding` (126 uses: model types misfiled in the binder namespace). The drift test is a
   `System.Reflection.Metadata` walk over the built assemblies with a `RuntimeApiGuardTests`-style ratchet, and the
   census cross-checks it for `nameof`.
2. **Layout** (§8.2): folder = namespace (19 findings, 186 files), one public type per file (177 multi-type files, 128
   with more than one public type), file name = type (22 misnamed), partials only along a named concern and only on
   the way to a type; a closed node family is one file named for its root (the §8.5 unit). The census gains the
   three per-type columns so the text-scan counts become record fields. Tests mirror `src/` (635 flat test files).
3. **Names** (§8.2): assembly, executable and package names do not change; namespace roots become the project
   name, extending P15 Cut 3's runtime flip to every project in one rewriter wave (the compiler's root `CobolNet` →
   `Cobol.Net.Compiler` resolves R0-0220 on its own and ends the disagreement between PROJECT_ORG §1.1 and
   module-topology §2.2). Oracle-identical: no emitted C# names a compiler namespace.
4. **The 52 god classes** (§8.3): nine in depth with named target types, seams and order; 43 as a table. Order by
   layer, by measured fix-lane heat (open non-process notes naming the type: `DataBinder` 33, the parse arm 14,
   `DataItem` 11), and by the open external-repository slices' file sets (C rows). `DataBinder` is last among binders;
   the parse-arm split of `VersionConformancePass` is the first binding-side wave; `DiagnosticCatalog` is data plus a
   generator on the `gen-constructs.ps1` pattern, with the frontend's 148-row catalog unified into it; `RuntimeApi`
   becomes the `RuntimeAbi` catalogue of backend-abstraction §2.3; `BoundTree.cs` splits into family files.
5. **Grammar** (§8.4): one fragment per division or facility (`CobolIdentification`, `CobolEnvironment` absorbing
   `CobolSpecialNames`, `CobolProcedure`); the core keeps only the §10 compilation-group skeleton; the lexer stays one
   grammar; zero version predicates measured, so the `{isXXXX()}?` sentence in §3 R1 is corrected and the skill's copy
   is listed below; no grammar wave before the §4 item 3 differential exists; the six grammar leads placed.
6. **Unions** (§8.5): the numeric carrier first (the measured two-arm defect class), then the visitor-less roots,
   `Place`, the closed value kinds, the visitor-covered roots smallest first, `BoundStatement` last, the source
   generator deleted when no root remains; one mechanism per root at every step; before the SDK, a ratchet over the
   469 hand arms.
7. **Given** (§8.6) and **the shape** (§8.7): leaves first, the edges test with the first Move wave, the partition
   rule mechanical (notes' sites + rewriter dry run, checked against the trains and the external-repository §12
   "Today" column); the test-only rule (table enumerations keep; seams move or are renamed; the rest is deleted with
   its tests); the R3 estimate ≈ 105–125 waves by kind (Delete 8–12 · Unify 12–16 · Move 12–16 · Data-ize 2–6 ·
