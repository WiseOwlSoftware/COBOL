# PB5132 - four 85 behaviors that landed with no witness of their own

One mechanism: a fix changes behavior on an arm that the new golden does not reach, so a regression of the arm would pass.

1. **PB5075 composite receivers at 85 (PB5086 report R1-1).** `conformance-suite/cases/_unassigned/pb5075-composite-over-18-digits-85.cob`
   puts ADD, SUBTRACT, MULTIPLY and DIVIDE in one program, and `WiseOwlRefusal_RefusesTheSourceWithItsDiagnostic` asserts only that
   COBOL0805 is present (`EditionHarness.AssertHasDiagnostic`). The MULTIPLY and DIVIDE receivers-only arm has no refusal witness
   of its own: one program per verb, or an assertion of the diagnostic count and lines.
2. **PB5086 SORT same-reel exemption (R1-2).** `SortBinder.cs` (`ScreenMultipleFileReels`, near line 940) exempts SORT USING and
   GIVING files that sit on one MULTIPLE FILE reel (§1985:XI.4.4.3 SR7, checked by the implementer). No golden or NIST program
   sorts files that one MULTIPLE FILE TAPE clause names, so only the MERGE arm is tested.
3. **PB5107 DISABLE sibling (w20261979b R1-1).** The DEVLOG and PB5107 claim the fix also closes the DISABLE I-O TERMINAL sibling
   (§1985:XIV.3.2.4 GR5), but `pb5107_enable_io_both_ways` tests only before and after ENABLE, and `pb4677_mcs_transaction` and
   `pb4677_mcs_key_85` DISABLE without a following RECEIVE. A RECEIVE after DISABLE I-O TERMINAL has no witness.
4. **PB5106 embedded sign (w20261979d R1-2).** The fix also changes an EMBEDDED-sign (overpunched, not SEPARATE) signed numeric
   opposite a group at --std 85, but `pb5106-numeric-with-group-1985.cob` pins only SIGN SEPARATE items.

**Sites:** none (conformance goldens are added under `conformance-suite/cases/_unassigned`, data files).

**Owed.** One accept golden (or a refusal per verb) for each arm, values derived from the rule and then checked against a run.
