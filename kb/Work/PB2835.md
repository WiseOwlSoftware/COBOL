# PB2835 — OPEN — tier 0a cannot match a corpus case name over 50 characters

Found by the w1047e implementer (report lead 1) and Filed by the train 1047 lander, 2026-10-08 20:53 PDT.

## Mechanism
xUnit truncates a theory argument in the test's display name at 50 characters (`…-search-al`), so
`scripts/gate_plan.py`'s tier-0a match of the diff's added corpus rows against the discovered display names finds no
case, and the gate plans the new case into leg 2. During the batched-gating trial (PB2515) leg 2 does not run at the
implementer, so a new golden or negative is NOT executed at its own gate, against I7.

## Repro
Gate run `20261009T021513Z-003f4c` in `E:\COBOL\.claude\worktrees\wf_8750e914-ee4-4`: its
`not-run-Conformance.txt` lists `pb2468-condition-name-reference-modified-search-al` (the manifest name is
`pb2468-condition-name-refmod-search-all` after the implementer shortened it).

## Code sites
`scripts/gate_plan.py` (tier-0a corpus matching) and the corpus theory's display (the Conformance runner's
`MemberData` argument), either of which can carry the full name (a `TheoryDataRow` display name, or a match on the
truncated prefix).
