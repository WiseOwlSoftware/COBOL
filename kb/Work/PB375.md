# PB375 — the CLASS clause is declined with VALIDATE (decided), and is not yet refused

> **⚖ OWNER DECISION, 2026-09-02 — DECIDED, NOT OPEN.** *The CLASS clause (ISO §13.18.11) is **declined with
> VALIDATE**.* Its only consumer is VALIDATE content checking, so it joins the Annex A.4.14 family: a named
> refusal in **COBOLNET1708**'s band, its rules routed to the `validate-only` derived selector, and witnessed
> the way every other declined validation clause is. **This note is the WORK that decision creates**, not the
> question — the question is closed and is not to be re-asked.

## What made it a question, and why it needed the owner

Witness cluster B2 read §13.16.2 Format 1 at the printed page: its `validation-clauses` block **INCLUDES**
`class-clause`. (⚠ The brief that raised this named "§13.18.13?" — that is CODE-SET, a different clause. The
clause in the block is §13.18.11, CLASS.) But **Annex A.4.14 never lists CLASS** among the VALIDATE module's
optional elements. Two readings followed, and neither is decidable from the text alone:

* **CLASS is part of the declined module** — it appears only inside the validation-clauses group, whose whole
  point is the format validation stage of a VALIDATE statement, so A.4.1's "shall accept the syntax … for an
  optional element only when support … is claimed" reaches it through the group that contains it.
* **CLASS is mandatory** — A.4.14 does not list it, and an element the annex does not make optional is one
  A.4.1 obliges an implementation to accept, so `CLASS IS NUMERIC` would be legal source we reject.

The two readings differ in which way the compiler is WRONG today, which is why an agent could not settle it:
one makes silent acceptance an under-rejection, the other makes any refusal a rejection of legal source. The
owner decided the first.

⚠ Also recorded, because it is easy to miss when the surface is written: in §13.16.2 the
`{ INVALID WHEN condition-2 } …` element is **repeatable** — the ellipsis is printed on it.

## Today's behaviour (measured, not assumed)

Every other clause of the §13.16.2 validation-clauses group is refused by name at 2002/2014/2023 —
`DEFAULT` (§13.18.17), `DESTINATION` (§13.18.18), `INVALID` (§13.18.31), `PRESENT WHEN` format 2 (§13.18.41),
`VARYING`'s validation leg (§13.18.64), `VALIDATE-STATUS` / `VAL-STATUS` (§13.18.62) and the §13.18.63 format-5
content-validation entry — all through `DeclinedFacilityPass` and COBOLNET1708. **CLASS is the one that is
not**: the grammar deliberately does not diagnose it, because refusing it before the decision would have
enshrined one of the two readings.

## What implementing the decision needs

⛔ **A FOLLOW-UP IMPLEMENTER OWNS THIS. It was deliberately not done in the landing that recorded the decision**
— the landing's own scope was the A.4.14/A.4.3/A.4.10 witness set, and adding a grammar surface to it would
have shipped an unwitnessed construct in a change set already carrying four merges.

1. **A grammar surface** for the clause in `Grammar/Core/CobolDeclined.g4`, behind the same left-edge
   `{is2002()}?` predicate every rule in that file carries — the clause exists from COBOL-2002, and below that
   `CLASS` is an ordinary user word (§8.9), which a positive control must keep true.
2. **A `DeclinedFacilityPass` refusal override** for the new entry-point rule. `DeclinedFacilityDriftTests`
   derives that obligation FROM the grammar file, so the pass will go red until the override exists — that is
   the guard working, not a failure to fix.
3. **The selector arm** for §13.18.11's rules in `inventory-schema.json`'s `derived-verdicts.validate-only`,
   which currently holds §13.18.11 OUT rather than stamping it (it was the open adjudication). Its rows then
   carry the A.4.14 determination like the rest of the module.
4. **One witness** — a negative fixture `declined-validate-class` asserting COBOLNET1708 at 2002/2014/2023,
   plus the `--std 85` positive control that `01 CLASS PIC X.` is still legal there.
