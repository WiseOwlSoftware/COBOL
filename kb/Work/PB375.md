# PB375 — the CLASS clause is declined with VALIDATE (decided 2026-09-02, landed 2026-09-03)

> **⚖ OWNER DECISION, 2026-09-02 — DECIDED, NOT OPEN.** *The CLASS clause (ISO §13.18.11) is **declined with
> VALIDATE**.* Its only consumer is VALIDATE content checking, so it joins the Annex A.4.14 family: a named
> refusal in **COBOLNET1708**'s band, its rules routed to the `validate-only` derived selector, and witnessed
> the way every other declined validation clause is. **This note is the WORK that decision creates**, not the
> question — the question is closed and is not to be re-asked.

## What made it a question, and why it needed the owner

Witness cluster B2 read §13.16.2 Format 1 at the printed page: its `validation-clauses` block **INCLUDES**
`class-clause`. (⚠ The brief that raised this named "§13.18.13?" — that is CODE-SET, a different clause. The
clause in the block is §13.18.11, CLASS.) But **Annex A.4.14 never lists CLASS** among the VALIDATE module's
optional elements. Two readings followed, and neither is decidable from the text alone:

* **CLASS is part of the declined module** — it appears only inside the validation-clauses group, whose whole
  point is the format validation stage of a VALIDATE statement, so A.4.1's "shall accept the syntax … for an
  optional element only when support … is claimed" reaches it through the group that contains it.
* **CLASS is mandatory** — A.4.14 does not list it, and an element the annex does not make optional is one
  A.4.1 obliges an implementation to accept, so `CLASS IS NUMERIC` would be legal source we reject.

The two readings differ in which way the compiler is WRONG today, which is why an agent could not settle it:
one makes silent acceptance an under-rejection, the other makes any refusal a rejection of legal source. The
owner decided the first.

⚠ Also recorded, because it is easy to miss when the surface is written: in §13.16.2 the
`{ INVALID WHEN condition-2 } …` element is **repeatable** — the ellipsis is printed on it.

## Behaviour before the fix (measured, not assumed)

Every other clause of the §13.16.2 validation-clauses group was refused by name at 2002/2014/2023 —
`DEFAULT` (§13.18.17), `DESTINATION` (§13.18.18), `INVALID` (§13.18.31), `PRESENT WHEN` format 2 (§13.18.41),
`VARYING`'s validation leg (§13.18.64), `VALIDATE-STATUS` / `VAL-STATUS` (§13.18.62) and the §13.18.63 format-5
content-validation entry — all through `DeclinedFacilityPass` and COBOLNET1708. **CLASS was the one that was
not**: the grammar deliberately did not diagnose it, because refusing it before the decision would have
enshrined one of the two readings.

⚠ **This note's own framing was wrong in one word, and the measurement corrects it.** The title said the clause
was "accepted silently". It was not: `05 WS-A PIC X(4) CLASS IS NUMERIC.` drew
`COBOL0307: unexpected 'CLASS'` at EVERY edition — a bare parse error, the same pre-B2 shape every other clause
of the group had. The `silent:` flag records that the FACILITY was never named, not that the clause compiled.

## LANDED 2026-09-03 — what the decision cost, and two premises it did not have right

1. **Grammar surface** — `validateClassClause` + `validateClassOperand` in `Grammar/Core/CobolDeclined.g4`,
   added as an alternative of `validationClause`, which already sits behind the left-edge `{is2002()}?`
   predicate in `CobolData.g4`. Format transcribed from the RENDERED page (PDF p412 / folio 382).
2. **No `DeclinedFacilityPass` override was needed, and that is the design working.** The note assumed one
   (item 2 of the old plan). `DeclinedFacilityDriftTests` obliges an override only for an ENTRY-POINT rule —
   one no other rule in the file references — and an alternative added UNDER `validationClause` is not one.
   `ClauseName` derived "CLASS" with no code change.
   ⛔ **But the derived namer's unstated contract failed its first real test.** It takes the leading TERMINAL
   run of the matched alternative; every earlier alternative took operands that were already sub-rules
   (`literal` / `dataReference` / `condition`), so the contract had never been exercised. CLASS's operands are
   the reserved words NUMERIC / ALPHABETIC / ALPHABETIC-LOWER / ALPHABETIC-UPPER, and an inlined alternation
   would have produced *"the CLASS NUMERIC clause"* — a diagnostic that renames the clause after whatever the
   user wrote. `validateClassOperand` exists for that reason (and is also the faithful transcription of the
   printed brace group); the contract is now written down in `ClauseName`'s doc comment and pinned by
   `DeclinedFacilityTests.ClassClause_IsNamedByItsClauseWord_NotByItsOperand`.
3. **The COBOLNET1708 descriptor's clause list gained CLASS** — no new diagnostic code was needed, which is
   what the descriptor's message-names-the-clause shape is for. `docs/DIAGNOSTICS.md` regenerated.
4. **The `validate-only` selector arm** gained §13.18.11 and lost the `"CLASS clause takes effect"` exclusion
   that existed only to hold the question open. Measured: 75 → 81 selected, the six new ones exactly
   §13.18.11's rows, **zero existing verdicts changed**.
5. **Witnesses** — `conformance:negative/declined-validate-class` (both operand arms, one with the optional
   word IS and one without), plus three facts in `DeclinedFacilityTests`.

⛔ **THE PREMISE IN ITEM 1 OF THE OLD PLAN WAS FALSE, and the correction changed what the tests assert.** The
note said the clause words are user-defined below 2002, "which a positive control must keep true", and proposed
`01 CLASS PIC X.` at `--std 85` as that control. Measured against `tests/version-matrix/reserved-words.json`,
**CLASS is reserved at all four editions** (`r85: true`, "continuous since 1985") — §12.3.7's SPECIAL-NAMES
CLASS clause has always existed. `01 CLASS PIC X.` is refused at every edition, before and after this landing.
The `{is2002()}?` gate is still right, for a different fact: the DATA-DESCRIPTION CLASS clause arrived with
VALIDATE at 2002, so at `--std 85` the entry is a construct the targeted edition does not have and the honest
answer is a syntax error, not the name of a facility. The edition control asserts exactly that
(`ClassClauseAt85_IsNotTheDeclinedFacility_ButAPlainSyntaxError`), and the neighbouring-hazard control asserts
what the shared word really endangers: that §12.3.7's SPECIAL-NAMES CLASS clause still compiles and runs.
