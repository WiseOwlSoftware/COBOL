# PB367 — a handler end derived from paragraph shape

**Rows:** `GR-14.9.49.4-3`, `-7`, `-8`, `-9`, `-12`, `-13`.

## The programs

`<lane3 scratch>/out-b1/probe/gr7-handler-end/{p1.cob,p2.cob,p3-f3.cob,p4-ecio.cob}`.

`p1` (Format 1): `SELECT F1` on an absent file;
`DECLARATIVES D1 SECTION. USE AFTER STANDARD ERROR PROCEDURE ON F1. / D1-P1. DISPLAY "H1". / D1-EX. EXIT. /
D1-P2. DISPLAY "H2". STOP RUN. END DECLARATIVES`; MAIN does `OPEN INPUT F1` then
`DISPLAY "AFTER-OPEN FS=" FS1`. `p3-f3` is the same section shape under `USE AFTER EC EC-USER-DEMO` +
`RAISE EXCEPTION EC-USER-DEMO`. `p4-ecio` is the same shape under `USE AFTER EC EC-I-O-AT-END` + a READ past end
with EC-I-O checking on. `p2` is the control (D1-P2 ends `CONTINUE` instead of `STOP RUN`).

| probe | observed | required |
|---|---|---|
| `p1` | `H1` / `AFTER-OPEN FS=35` | `H1` / `H2` / (run stops at the declarative's own STOP RUN) |
| `p3-f3` | `H1` / `AFTER` | `H1` / `H2` / stop |
| `p4-ecio` | `H1 FS=10` / `AFTER FS=10` | `H1 FS=10` / `H2` / stop |
| `p2` (control) | `H1` / `H2` / `AFTER-OPEN FS=35` | — |

The control isolates the trigger precisely: the ONLY difference is whether a LATER paragraph terminates the run
unit.

## The rule

> §14.9.49.3 SR1: The remainder of the section shall consist of zero, one, or more procedural paragraphs that
> define the procedures to be used.

`--check 14.9.49.3` → **OK**. So the whole remainder of the declarative SECTION is the use procedure, and §14.4
gives the ordinary paragraph-to-paragraph sequence within it: the declarative runs D1-P1, D1-EX and D1-P2 before
GR7 / GR12 / GR13 decide the return.

## What the compiler does

`ProcedureTableBuilder.DeclHandlerEndPc` walks the section's paragraphs BACKWARDS from the second-to-last, and
for the LAST paragraph whose statements are all bare `EXIT`/`CONTINUE` that is still followed by a paragraph
containing `STOP RUN` / `EXIT PROGRAM` / `GOBACK`, returns THAT paragraph's pc as the handler end.
`DeclCollectSection` stores it as `BoundDeclarative.HandlerEndPc`, and **every invocation path passes it as the
bounded `__RunUse` end pc** — `__IoCheck`, `__IoCheckEc`, `__EcDispatch`, `__EcObjDispatch`, `__RunGlobalUse` and
the report engine's `BeforeReporting` delegate. That is why the six rows span every format.

The code comment calls it a *CCVS ACCOMMODATION (documented deviation, the legacy's empirically-validated SQ212A
rule)* for NIST programs that park an unreferenced termination tail inside the declarative. `kb/Work/PB138`
(`status: landed`) already recorded that the deviation *is registered NOWHERE*, but its landing only removed
`CONTINUE AFTER` from the trivial-exit classifier — **the shape itself is untouched.**

## The fix shape

**Stop deriving a handler end from paragraph SHAPE.** A declarative's range is its SECTION. The NIST tail
programs need whatever mechanism actually returns control there — reachability analysis, or the golden
re-baselined against the rule — not a heuristic that silently truncates every USER program written in the same
shape. Landing this needs the NIST cases re-measured first, because the accommodation is load-bearing for them
today; that measurement is part of the work, not a reason to keep the heuristic.

**The documentation half of GR7 c) and GR12 c) is separate and is PB322:** the implementor action after a USE
procedure when the I-O status is fatal is two different behaviours selected by a `>>TURN` directive the rule does
not mention, and A.1 item 218 makes writing that determination down a conformance obligation.

**Code sites:** `ProcedureTableBuilder.cs#DeclHandlerEndPc`, `#DeclIsTrivialExit`, `#DeclTerminatesRunUnit`,
`#DeclCollectSection` · `DispatchEmitter.cs#EmitUseMachinery` · `EcEmitter.cs#EmitDispatchSelector`,
`#EmitObjDispatchSelector`, `#EmitIoCheckEc` · `ProgramEmitter.cs#EmitRunGlobalUse` ·
`ReportWriterEmitter.cs#EmitReportConstruction`.

## Landed — 2026-09-09

**The handler end derived from paragraph SHAPE is deleted, not disabled.** `BoundDeclarative` no longer carries
`StartPc`/`EndPc`/`HandlerEndPc`; it carries ONE `PcRange Range`, which is the declarative section's own
`SectionInfo.Range` (the PB440 shape). `DeclHandlerEndPc`, `DeclIsTrivialExit` and `DeclTerminatesRunUnit` are
gone from `ProcedureTableBuilder`, replaced by a comment recording why no such heuristic may return.

**The rule, re-derived and `--check`ed on today's tree.** §14.9.49.3 SR1 makes the use procedure "the remainder
of the section"; §14.4.2 ends that section only "immediately before the next section … or … at the keywords END
DECLARATIVES"; §14.6.3 rule 1 puts the implied transfer back to the controlling USE at "the last statement" of
"the last procedure in the range of the controlling statement"; and §14.9.14.4 GR7 places EXIT SECTION's landing
point at "an unnamed empty paragraph immediately following the last paragraph of the current section, preceding
any return mechanisms for that section" — whose NOTE names USE as one of those return mechanisms. There is no
reading under which a paragraph earlier than the section's last is the USE return point.

**One construction site.** Six emit sites each spelled `__RunUse(i, decls[i].StartPc, decls[i].HandlerEndPc)`
by hand, which is why one truncated end reached every format at once and no single place could be corrected.
They now all call `DispatchState.RunUseCall(id, range)` — the `__RunUse` twin of PB440's `DispatchCall`, and the
only place a declarative becomes a pc pair. `EcBinder` and `ReportWriterBinder`'s "am I inside this declarative"
tests became `BoundDeclarative.Contains(pc)`, which documents why the arithmetic is legal for a section range
and illegal for an arbitrary (possibly inverted) `PcRange`.

**The NIST accommodation was measured, not assumed.** With the heuristic disabled, `NistDifferentialTests` was
348 of 349 — SQ212A alone depended on it. `SQ212A`'s declarative copies the whole CCVS termination boilerplate
(`EXIT-PARA. EXIT.` → `CLOSE-FILES1` footer + `CLOSE PRINT-FILE` → `TERMINATE1-CCVS` `STOP RUN`) INSIDE the
declarative section, so under the rule the first status-44 WRITE runs that tail and stops the run after test 1 of
17. **Its golden was not canonical CCVS output**: `git log --diff-filter=A` shows `tests/nist/valid/SQ212A.txt`
was ADDED by commit `12f970df`, whose own message reads "SQ212A baselined: clean 47-line report" — the same
commit that invented the heuristic. The golden was a snapshot of the heuristic's output and had been cited ever
since as the heuristic's empirical justification. It is re-baselined to the conforming run and its
`tests/nist/corpus.tsv` row is `divergent` carrying the citation (the row form that already means "the golden IS
the ISO-conforming output and the legacy is what diverges" — IX111A is the precedent). ⚠ The cost is real and is
recorded in the row: 16 CCVS sub-tests are no longer reached in that program.
