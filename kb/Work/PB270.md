# PB270 — a substring scan called total

Found by the arithmetic-wave review fleet over the D-B/D-C/PB194/PB195 working tree, 2026-08-31, and fixed in the change set that landed the wave. Every number below was re-derived independently by the implementer (a 34-digit emulation of `CobolDec.cs` validated against the shipped `pb167` goldens, and 80–120-digit `Decimal` truth) BEFORE the confirming run, and then confirmed by it.

The guard is worth keeping — it is a tripwire on the exact two shapes that shipped and were deleted. What was
wrong was the claim written above it. Reachability is a property of the CALL GRAPH; no substring scan decides it,
and `CobolIntrinsics.RealArgs.cs` already contains `CobolDec.FromDouble(Math.Pow(…))` — legitimately, as the
§8.8.1.3 NATIVE arm — in a file the scan does not read.

**Fixed as:** the comment now states what the scan proves and names both premises it does not enforce; the banned
list gains the near-miss spellings the reviewers identified (`Math.Log2(`, `Math.Cbrt(`, `Math.ScaleB(`, and the
.NET generic-math statics `double.Pow(` / `double.Log(` / `double.Log10(` / `double.Exp(` / `double.Sqrt(`); and
the one premise that CAN be made mechanical — that `CobolDec` is not `partial`, so "this file" is the whole type
— is now asserted.

⛔ **`ToDouble` / `FromDouble` are deliberately NOT banned**, against the original finding's suggestion and with
the reviewers: both are `CobolDec`'s own §8.8.1.5.1 conversion API, defined in that file by necessity and called
from six sites outside it. Banning their spelling would ban the type's public surface, not a development step.

The guard with teeth is the value pins beside it: a binary64 reintroduction gives 1.0618366495807028 where
`PastLoopBoundEscape_KeepsTheNegativeBasesParitySign` needs 1.061836649543504…, whichever file it sits in.
