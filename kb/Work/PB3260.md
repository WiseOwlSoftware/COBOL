# PB3260 — the review finisher's report rewrite drops the Status line, and the wave reads a DONE as SPLIT

Filed 2026-10-16 by the wave-1093 loop unit. No existing note covers this mechanism (grep of kb/Work for a report
with no, missing or dropped Status line: PB3125 and PB3181 concern the branch survey's lifecycle states, not the
header the agent writes).

**Symptom.** Wave 1093 group D (PB651) ran a round-1 review finisher on Sonnet. It merged the reviewed branch,
answered both findings, gated GREEN (run `20261016T133208Z-adaa96`, `LEG 1 ONLY (batched gating, PB2515): GREEN`
at HEAD `dafae64ea`) and returned `status: DONE`. Its rewritten report
(`E:\COBOL-coord\scratch\reports\w1093d-PB651-report.md`) began with `**Branch:** … **HEAD:** dafae64ea…` and had
no Status line, so `python scripts/orchestrator/plan_wave.py --finished <report>` printed
`=== REPORT: NOT FINISHED status=(none) head=dafae64ea… ===`. The wave's `finishedReport` then turned the return
into SPLIT (`claimed: DONE, finisher: DONE, finished: false, review_rounds: 1`) and dispatched no re-review. Left
alone, the next wave's planner would spend a whole finisher (0.16 weekly points) on a branch whose only defect is
one header line.

**Code site.** `.claude/skills/workstream/templates/wf_rolling_wave.js#fixFindings` (line 170): "REWRITE the
report at … for YOUR branch: its header names your worktree, branch, base and HEAD, carries no Review line". The
list leaves out the Status line that `implementer-report-template.md` line 3 puts first and that
`plan_wave.Report.finished` requires. Sibling sweep: `finisher-brief.md` line 20 names `Status: DONE` and is
correct. The implementer's own spec points at the report template. `fixFindings` is the only prompt that
enumerates the header fields without Status.

**Fix shape.**
1. The review-finisher prompt names the header the way the template does: `**Status:** DONE | SPLIT` first, then
   worktree, branch, base and HEAD.
2. Structural: every agent returning DONE or DISCHARGED runs the same finished test on its own report as its last
   step before `StructuredOutput` (`plan_wave.py --finished <report>`, exit 0) and repairs its header until the
   test passes. The predicate stays in one place (Python), the agent asks it the same way the workflow does, and a
   gated DONE can no longer degrade to SPLIT over a header line. Put this in the shared `RETURN_LINE` and in
   `dispatch-spec-implementer.md`, and have `check_practices.py` refuse a spec without it.
3. A self-test in the workflow's test harness: a review-finisher prompt rendered for a fixture group contains
   `Status`.

**Interim handling (wave 1093).** The wave unit put the line back from the finisher's structured return (status
DONE, the gate run above, HEAD equal to the branch tip) as
`**Status:** DONE · (header line restored by the wave-1093 unit …)`. The report now reads FINISHED, so the branch
goes to one branch review (I10) instead of a finisher.

## Addendum 2026-10-17 (wave 1111 w1111h-PB3224-report): the same mechanism, second symptom, and the code sites

Filed by the clerk from the enqueue unit's find (lead 7 of `enqueue-leads-20261017T2330.md`). This note's fix shape item 2
(the returning agent runs `plan_wave.py --finished <report>` on its own report) is the general mechanism: a returned
report's header contract is checked at no point between the agent's return and the branch survey, so every header variant
becomes a new parser fallback. No new note is filed.

**Second symptom.** `E:\COBOL-coord\scratch\reports\w1111h-PB3224-report.md`, as the implementer wrote it, had no
Branch, Base or HEAD field. Its line 3 read
`Group H (wave 1111): PB3224, PB3225. Branch worktree-wf_71ab13ab-689-23, base 4016a67cb (HEAD e9a023c7c when cut), head 0c8947be0.`
`plan_wave.header_sha(HEAD, header)` found no field-position match and fell back to the first `head <sha>` anywhere, which
is the parenthetical cut-time `HEAD e9a023c7c`, not the tip `0c8947be0`. So `prune_worktrees.lifecycle()` judged the report
"uncovered" (one commit since its HEAD), read the branch IN FLIGHT under `--min-age 180` and would have read it DECISION
after that. Its `**Review:** CLEAN ... 0c8947be0...` stamp at the tip was never consulted. The enqueue unit added
`Branch:`, `Base:` and `HEAD:` field lines by hand at 2026-10-17 about 16:20 PDT.

**Code sites (origin/main 8307a2143).**
- `scripts/orchestrator/plan_wave.py:134` `sha_field` and `:151` `header_sha`: the field pattern, then the
  "first `word <sha>` anywhere" fallback that PB3181 added for headers with no field position.
- `scripts/prune_worktrees.py:470-476` `lifecycle()`: the `uncovered` test returns IN FLIGHT or DECISION before the review
  stamp is read at line 478-479.
Related: PB3181 (landed; introduced the fallback), PB3077 (landed).

**Fix shape added.** The same `--finished` self-check should also assert the header's HEAD equals the worktree's `git rev-parse
HEAD` (a returned report whose HEAD is not the tip is repaired by the agent before it returns), so a header variant is
refused at the source and the fallback in `header_sha` can be tightened instead of widened. Drift test: a report fixture
with a parenthetical `(HEAD <sha> when cut)` before the field must not read as the report's HEAD.

The branch reviewer `w1132b-review-r1` then stamped `**Review:** CLEAN w1132b-review-r1 81936edfbd0c…` (the tip).
`scripts/orchestrator/review_findings.py` `stamp()` (~line 415) refuses a report that is not FINISHED
(`plan_wave.Report.finished`), a header with no status line among them (PB3181 shape 3), but a DONE header with NO HEAD sha
passes. `plan_wave.parse_report` reads the HEAD from the header's field only, the stamp line excluded
(`header_sha(HEAD, unstamped)`), so `Report.head` is None, and `scripts/prune_worktrees.py` `lifecycle()` (~line 508) reads
"the report names no HEAD, so it describes no commit of the branch": IN FLIGHT while touched under --min-age 180, then
DECISION. A finished, reviewed CLEAN branch the landing lane never lands, and the wave's handoff reported "8 of 8 groups
reviewed CLEAN" without seeing it. The enqueue unit wrote the sha into the header by hand (2026-10-20 ~11:40 PDT); the survey
then read it WAITING TO LAND.

Mechanism, restated: no writer refuses a DONE report header that names no HEAD sha. Fix shape to record, not decide: one
header check (status line, branch, HEAD sha) that `review_findings.py stamp` applies (refuse; the reviewer returns NO-RESULT
naming it) and the wave applies to the implementer's return, alongside fix-shape item 2 and the HEAD-equals-tip assertion
above. Related: PB3181, PB3027.
