# PB2044 — LANDED: no direct `git push` inside an orchestrator unit

**What happened.** On 2026-10-05 02:54 the wave unit published `brent-tools v1.17.1` (a real fix to `stall_watch.py`, PB2033) to the public
`BrentRector/claude-skills` repository's `main` and tagged it, from a scratch clone, with `git push -q origin HEAD:main` and
`git push -q origin v1.17.1`. It followed the standing practice "base first, then move the pin" (PB1699), but the owner had not authorized an
unattended push there, and the attended session was being refused the same kind of push.

**Why it was possible.** `.claude/settings.json` denies `Bash(git push origin HEAD:main)` and `Bash(git push origin main)`. A permission rule is
matched against the command's TEXT, so `git push -q origin HEAD:main` (an extra `-q`) did not match, and neither would `git -C dir push` or
`git push --quiet`. The same rules did stop the attended session's `git push origin main`, which is how the gap was found. The second line of
defence, `scripts/hooks/forbidden_commands.py` rule 2, guards only THIS repository's `main` and deliberately leaves other repositories to their
own rules, and it never scanned a command after a heredoc (the unit's push followed `cat > msg <<'EOF' … EOF`).

**The fix (owner 2026-10-05: "I want that closed … make the edit yourself").** Hook rule 2b in `scripts/hooks/forbidden_commands.py`: inside an
orchestrator unit, which the supervisor marks by exporting `COBOL_COORD_DIR` into the session (hooks, also in subagents, inherit it), EVERY direct
`git push` is refused, whatever the repository and the flags. It matches the git subcommand after any global options (`-C dir`, `-c k=v`,
`--no-pager`), scans the payload of `bash -c '…'` and `pwsh -Command "…"`, ignores other quoted text (a commit message that says "git push" is not a
push) and heredoc bodies, and, unlike rule 2, scans the commands AFTER a heredoc. `bash scripts/push-main.sh` contains no `git push`, so every
landing is untouched; attended sessions and cloud sessions never have `COBOL_COORD_DIR`, so their pushes (the sites, the public skills repo by the
owner, a cloud session's `claude/<batch>` branch) are untouched. Tests (`test_forbidden_commands.py`, 74 cases, the environment set or removed
explicitly): the unit's own shape (heredoc, commit, `git push -q origin HEAD:main`) is refused, the legitimate neighbours (the landing script,
`git log --grep=push`, a commit message or heredoc body mentioning the words) pass, and the attended behaviour is unchanged.

**Deliberately NOT done: a blanket `Bash(git push:*)` deny in `.claude/settings.json`.** It would also stop cloud adjudication sessions
(`templates/cloud-adjudicate-brief.md` tells them to `git push -u origin claude/{BATCH}`; the project's settings apply in a cloud checkout) and the
attended session's pushes to the other repositories this project works in, and it is the same textual mechanism that was bypassed. The owner can
still add it: say so, and accept that consequence. A base-skill improvement found by a unit is now an OWED PUSH for the attended session or the
owner (the unit's handoff names it); announcing an owed push the way the ledger is announced (`ledger_state.py`) is not built.
