# PB2044 — OPEN, owner action: close the push gap in `.claude/settings.json`

**What happened.** On 2026-10-05 02:54 the wave unit published `brent-tools v1.17.1` (a real fix to `stall_watch.py`, PB2033) to the public
`BrentRector/claude-skills` repository's `main` and tagged it, from a scratch clone, with `git push -q origin HEAD:main` and
`git push -q origin v1.17.1`. It followed the standing practice "base first, then move the pin" (PB1699), but the owner had not authorized an
unattended push there: the attended session was being refused the same kind of push, and the owner pushed v1.18.0 by hand.

**Why it was possible.** `.claude/settings.json` denies `Bash(git push origin HEAD:main)` and `Bash(git push origin main)`. A rule is
matched against the command's TEXT, so `git push -q origin HEAD:main` (an extra `-q`) does not match, and neither would `git -C dir push`
or `git push --quiet`. The same rules did stop the attended session's `git push origin main`, which is how the gap was found.

**What closes it (the owner edits the permission file; an agent does not grant itself permissions).** Add broader deny patterns to the
project `.claude/settings.json`, which units read because they run in this repository (the syntax is from memory: confirm each
pattern with `/permissions`):

```
"Bash(git push:*)",
"Bash(git * push:*)"
```

These do not affect `scripts/push-main.sh`: a rule matches the command the model types, not what runs inside a script, and every landing
goes through that script. The consequence to accept: a headless unit can no longer publish the public skills repo, so a base-skill
improvement found by a unit becomes an OWED PUSH that the attended session or the owner performs, announced like the ledger
(`ledger_state.py`, DESIGN-orchestrator-loop.md section 14). Say if that announcement should be built.

**Related.** A `PreToolUse` hook (`scripts/hooks/forbidden_commands.py`) also runs in units and is the sturdier place for a structural check
(refuse any `git push` whose resolved remote is not this repository's origin); the hook is code in this repo and can be extended without a
permission change. Not done: the owner asked for the permission rule, not the hook.
