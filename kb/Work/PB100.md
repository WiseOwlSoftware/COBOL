# PB100 — LANDED — `ALPHABET A IS LOCALE` → COBOLNET0901 (false); `PIC +$9.9 LOCALE SIZE IS 10` → COBOL0307 (raw); `USE AFTER EXCEPTION CONDITION EC-LOCALE` → accepted

> ⚙ **flags:** silent (an accepted optional-module element), under-rejects, misleading diagnostics · the
> posture-repair half (T0) of the [[PB64]] locale design draft that is owed under EITHER answer to its
> owner-reserved Q1 (rows 4, 5, 11 and A.4.9 item 1; rows 6–10 and 14 landed as PB78 / PB92) · found
> 2026-08-18 re-reading the draft after PB99 · **landed 2026-08-18** (DEVLOG 1324) — the PB64 draft's T0 is
> complete; only its owner-reserved Q1–Q4 remain.

**Spec:** Annex A.4.1 — "An implementation shall accept the syntax and provide the functionality for an
optional element only when support for that language element is claimed by the implementor"; A.4.9 lists the
locale module's thirteen elements: item 1 (EC-LOCALE and EC-ORDER-NOT-SUPPORTED in the RAISING phrases, the USE
statement, the WHEN phrase …), item 8 (PICTURE clause format 2: locale, §13.18.40.2 `PIC IS character-string-1
LOCALE [IS locale-name-1] SIZE IS integer-1`), item 10 (SPECIAL-NAMES: the LOCALE clause AND the LOCALE phrases
of the ALPHABET clause, §12.3.7.2 `ALPHABET alphabet-name-1 [FOR ALPHANUMERIC | FOR NATIONAL] IS LOCALE
[locale-name-2]`). COBOL.NET's ratified posture (council decision 3, 2026-07-03) is documented non-support,
conforming under §4.2.7 + A.4.1 ONLY when each element is refused BY NAME (COBOLNET1518, CONFORMANCE.md §4 item
5) — which that section already CLAIMS for "every locale entry point the module names".

**Measured** (`--std 2023`):
```
       SPECIAL-NAMES. ALPHABET A1 IS LOCALE.               -> COBOLNET0901 'LOCALE' is a reserved word ... user-defined word
       SPECIAL-NAMES. ALPHABET A2 FOR NATIONAL IS LOCALE.  -> COBOLNET0898 not a supported code-name + the same 0901
       01 X PIC +$9.9 LOCALE SIZE IS 10.                   -> COBOL0307 unexpected 'SIZE'. A period may be missing ...
       USE AFTER EXCEPTION CONDITION EC-LOCALE.            -> compiles (the syntax of an unclaimed optional element, accepted)
       >>TURN EC-LOCALE-INCOMPATIBLE CHECKING ON           -> compiles
```

**Mechanism:** LOCALE is not a lexer token; the ALPHABET definition reads it as a code-name-1 cobolWord and the
§8.9 funnel (`VersionConformancePass.ParseArm.VisitCobolWord`) then reports the KEYWORD as a user-defined word
(the PB27 / PB78 / PB92 shape); `pictureClause` has no Format-2 phrase; `EcNameResolution.TryResolve` (the ONE
exception-name funnel, R05) knows no optional-module names.

## As built (DEVLOG 1324)

(a) `DataBinder.AlphabetBind` recognizes `IS LOCALE [locale-name-2]` in either branch at 2002+
(`IsAlphabetLocalePhrase` — the ONE shape test the §8.9 funnel exemption shares) → COBOLNET1518, an identity
alphabet registered so a PROGRAM COLLATING SEQUENCE reference binds; (b) `pictureClause : PIC PIC_STRING
editingPhrase* pictureLocalePhrase?` with the text predicate `pictureLocaleAhead()` (2002+) → COBOLNET1518 in the
entry binder, the character-string analyzed as Format 1 for recovery; (c) `EcNameResolution.TryResolve` refuses the
EC-LOCALE family and EC-ORDER-NOT-SUPPORTED (COBOLNET1518) — USE, RAISE / EXIT–GOBACK RAISING, the
exception-checking PERFORM's WHEN and >>TURN all funnel through it (the PROCEDURE DIVISION header's RAISING admits
only EC-USER level-3 names, §14.2.2 SR7, so it never reaches them); the §8.9 funnel exempts the two keyword slots
(`AlphabetEntryContext` under a LOCALE-phrase definition, `PictureLocalePhraseContext`). Negatives
`pb100-alphabet-locale-phrase`, `pb100-picture-locale-format-2`, `pb100-ec-locale-names`; CONFORMANCE.md §4 item 5
names all three; inventory SR-12.3.7.3-24 / GR-12.3.7.4-5 → DOCUMENTED-NON-SUPPORT.

**Fix shape (as designed):** (a) `AlphabetBind` / `AlphabetBindNational` recognize a first definition entry spelled LOCALE at
