## Landing (2026-11-12, branch witnesses-85n)

**Root cause.** A draft had no library texts in its shape. The drafts pass's answer shape (`audit_batch.py parse_answer`) named only `program`, `expected` and `basis`, so the triage and drafting passes added a `files` member that no reader knew. `run_drafts.tests_of` wrote every test with `"files": []`, and `place_witnesses.py` skipped any draft whose program held a COPY statement (`needs_library`, a guess read from the program text). The harness also staged a declared file flat (`work / Path(declared).name`), so a text in a library folder lost its library. The in-process runner (`ConformanceSuiteRunner.Stage`) keeps the folder.

**Fixed in one place each:**
- One shape of a draft: `audit_batch.draft_problem` checks the program, the outcome, the refused draft's line and control, and `files` (`{"<text-name>.cpy": text}` or `<library>/<text-name>.cpy`; never absolute, never `..`, never deeper than one library). `parse_answer` uses it, and `run_drafts.tests_of` refuses a malformed draft on the same rule, naming the rule. The drafts prompt asks for `files` when the program or its control COPYs.
- `run_drafts.tests_of` writes each draft in a folder of its own, with its library texts beside the program, and declares them on the test and on its control. `place_witnesses.py` judges through the same `tests_of` and `harness_run`, so it needed no second path.
- `run.py Run.staged`: a declared file is staged at its place beside the test's source, the same way `ConformanceSuiteRunner.Stage` does it. A file outside the source's folder is refused.
- `place_witnesses.py`: `needs_library` is deleted. A placed draft's texts lie beside its test and its header declares them (`files`). A text in a library folder is not placed, because only a WiseOwl test may declare one (generate.py). A name the clause folder already holds with other text refuses the run before it writes anything. A `--replace` removes a case's own texts and keeps a text another test of the folder declares.
- `cobol_source.read_lines` (the generator's reader): a COPY in an 85 comment-entry is part of the comment-entry (§1985:XII.2.3 SR10). The comment-entry runs from its paragraph header to the next line with a word in area A (§1985:IV.7.3.3, §1985:VI.3.2.1.2 SR1). Before this, the generator refused `1985-SR-XII.2.3-10`'s placed test: `COPY NOSUCHTEXT: the library text is not a declared file`, from an `AUTHOR. COPY NOSUCHTEXT.` line. That same misreading made `needs_library` skip the draft.

**Proved.**
- Before the fix, `run_drafts.py --state drafts-85n/state` on cobol 25.0.0 (assemblies b23964f775e9) gave `{'MATCH': 6, 'MISMATCH': 15}`. 1985-GR-XII.2.4-3 failed with "CBL3620: COPY copybook 'LIBTXT' not found" (`E:/COBOL-coord/scratch/drafts-85n/runs-before.json`). After the fix the same run gave `{'MATCH': 21}`.
- Self-tests: `run_drafts.py --self-test` PASS. With the fix undone in-process (each test's `files` emptied) it reports FAIL - 1: the two COPY drafts are MISMATCH. `place_witnesses.py --self-test` PASS, and FAIL - 1 with `declared_by_others` stubbed out. `run.py --self-test` ALL GREEN (`staged-library is PASS`). `generate.py --self-test` ALL GREEN (the comment-entry arm). `test_audit_batch.py` GREEN.
