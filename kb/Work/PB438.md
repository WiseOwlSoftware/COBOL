# PB438 — a behavioural fork in a standard defect, chosen in code and written down nowhere

## 1. THE MECHANISM

GR18 as printed contains two consecutive sentences that name DIFFERENT destinations after
imperative-statement-3. Both were verified word for word against the canonical PDF (page 719), so this is a
defect in the STANDARD, not in the transcription. Sentence 2's cross-reference is to a CLAUSE number where a
GENERAL-RULE number belongs, and the clause it names is the RAISE statement rather than this one — GR20 is
plainly meant, mirroring GR17 and GR19.

The emitter routes WHEN OTHER through exactly the same `__RunF3` return path as a named WHEN —
`src/Cobol.Net.Compiler/CodeGen/Verbs/ControlFlowEmitter.cs:166-167`:

    if (p.OtherPc is int opc)
        w.Line($"return __RunF3({HandlerUseId(opc)}, {opc}, {cu}, {cpc});   // WHEN OTHER (imp-3, §14.9.28.4 GR18)");

so it implements the SECOND reading: a nonfatal condition handled by WHEN OTHER resumes IN PLACE and the
remainder of imperative-statement-1 runs.

**Nothing records that choice.** `docs/CONFORMANCE.md` carries determinations for the other two §14.9.28.4
standard defects (FINALLY on the fatal path, at `:246`; RESUME NEXT STATEMENT skipping WHEN COMMON, at `:253`)
and none for this one. Worse, the project's own analysis says the OPPOSITE:
`docs/rearchitecture/PHASE-13-remaining-waves-scout.md:203` disposes of the pair with "the first sentence
already gives the correct destination" — and the code does the second.

**And the covering test cannot see the difference.**
`tests/Cobol.Net.Tests.Conformance/PerformFormat3BehaviorTests.cs:127-140`
(`WhenOther_HandlesUnnamedCondition`) writes `RESUME NEXT STATEMENT` inside the WHEN OTHER body and asserts
`"OTHER\nAFTER\nDONE"`. Under reading (i) the RESUME itself produces the resume-in-place; under reading (ii)
GR20 produces it. **The assertion is identical under both readings, so the green test is evidence about
neither.**

## 2. THE RULE, QUOTED, WITH ITS `--check` LINES

Sentence 1 of GR18 — the destination the project's scout analysis picked:

    python scripts/spec/cite.py --check 14.9.28.4 "If during the execution of imperative-statement-1 any exception condition that is not associated with any exception condition specified in a WHEN phrase is raised"
    OK  §14.9.28.4 18)  (General rules)

Sentence 2 — the one whose cross-reference is broken, quoted here as GR18's own text (the number inside it is
the standard's, and this note deliberately does not pair that number with any quotation of its own):

    python scripts/spec/cite.py --check 14.9.28.4 "control is passed as indicated in General rule 14.9.29 or, if WHEN COMMON is specified, to imperative-statement-4"
    OK  §14.9.28.4 18)  (General rules)

GR20, the rule sentence 2 must mean, which is what makes reading (ii) resume-in-place:

    python scripts/spec/cite.py --check 14.9.28.4 "If the exception condition was nonfatal, execution continues with an implicit CONTINUE statement immediately following the statement in imperative-statement-1"
    OK  §14.9.28.4 20)  (General rules)

⚠ **Independent support for reading (i)**, and the reason this is a genuine fork rather than an obvious typo
fix: §14.6.13.1.4's ordered nonfatal dispatch names only a PERFORM whose WHEN phrase SPECIFIES the
exception-name — it never mentions WHEN OTHER:

    python scripts/spec/cite.py --check 14.6.13.1.4 "the executed statement is within imperative-statement-1"
    OK  §14.6.13.1.4 2)  (Nonfatal exception conditions)
        2) If the executed statement is within imperative-statement-1 of a PERFORM statement that contains a
           WHEN phrase that specifies the exception-name associated with the exception condition or an
           exception-name of a higher …

which is consistent with WHEN OTHER being a block-level catch rather than the per-statement resume mechanism.
Reading (ii) has the symmetry of GR17/GR19 and the likely editorial history (sentence 2 looks like the revision,
sentence 1 like the text it was meant to replace). **The standard does not say which.**

## 3. EXPECTED vs OBSERVED — RE-RUN ON HEAD (89044aa0)

Still reading (ii). HEAD `cobol.exe`, `--std 2023`.

          >>TURN EC-ALL CHECKING ON
               PERFORM
                   RAISE EXCEPTION EC-USER-DEMO
                   DISPLAY "AFTER"
               WHEN EC-BOUND-SUBSCRIPT
                   DISPLAY "SPECIFIC"
               WHEN OTHER
                   DISPLAY "OTHER"
               END-PERFORM
               DISPLAY "DONE".

    $ cobol.exe .../gr18_other_nonfatal.cob --std 2023 --run
    exit 0
    OTHER
    AFTER
    DONE

Under GR18 sentence 1 the required output is `OTHER / DONE` — the remainder of imperative-statement-1 is
abandoned and "AFTER" does not print. The divergence is observable **only** when the WHEN OTHER body does NOT
execute a RESUME and the condition is nonfatal — which is precisely the case no test exercises. A program whose
imp-1 continues after an unnamed exception (a file loop, an arithmetic sequence) executes a different set of
statements under the two readings.

Format 3 is 2023-only (Annex E.3.3 item 36), so there is no edition axis to sweep here.

`process_only: true` is set deliberately: on THIS tree the compiler picks one of two readings the standard itself
offers, and no reading is established as correct, so no wrong answer is measured. ⚠ **If the owner adopts reading
(i), this becomes `wrong_answer: true` and the emitter changes** — flip the flag in the same change set as the
determination.

## 4. THE CODE SITE AND THE SHAPE OF THE REPAIR

* `src/Cobol.Net.Compiler/CodeGen/Verbs/ControlFlowEmitter.cs:166-167` — the WHEN OTHER arm, routed through
  `__RunF3` exactly like a named WHEN
* `src/Cobol.Net.Compiler/CodeGen/EcEmitter.cs:539` — `EmitRunF3`, the shared return path
* `docs/CONFORMANCE.md:246`, `:253` — the two §14.9.28.4 determinations this one must join
* `docs/rearchitecture/PHASE-13-remaining-waves-scout.md:203` — the recorded analysis that contradicts the code
* `tests/Cobol.Net.Tests.Conformance/PerformFormat3BehaviorTests.cs:127-140` — the test that cannot discriminate

**The remedy is the project's standing one for a standard defect, and it is three things, not one:**

1. **Pick the reading** — an owner decision, because the standard's own text is self-contradictory and the two
   readings have independent support (§14.6.13.1.4's item 2 for (i); GR17/GR19 symmetry for (ii)).
2. **Publish it in `docs/CONFORMANCE.md`** beside its two siblings in the same clause. A destination chosen in
   an emitter line is not a determination.
3. **Add a test WITHOUT the RESUME** that pins the chosen destination — a nonfatal EC, a WHEN OTHER body that
   does not resume, and a statement after the raise site inside imp-1. Today's test asserts an observable both
   readings produce, and rewriting it in place is the fix (⚠ do not merely add a second test beside it: the
   existing one's NAME claims GR18 coverage it does not have).

⚠ If the fixer changes the emitter, note that WHEN OTHER and the named-WHEN arm currently share ONE return path.
Reading (i) would make them differ, so the shared `__RunF3` return must grow a destination argument rather than
sprouting a parallel arm — otherwise GR17 and GR18 drift.

## 5. THE SIBLING SWEEP

* **Every green test whose body forces the identical observable under both branches of the rule it names.**
  `WhenOther_HandlesUnnamedCondition` is one; **PB435** is another species of the same disease. The generic
  screen is: for each behaviour test, ask what OTHER implementation of its rule would also pass it.
* **Every §14.9.28.4 destination rule.** GR17, GR18, GR19 and GR20 all name a destination after a handler
  completes, and all four ride the same `__RunF3` chain. Whichever reading is adopted, re-derive all four from
  the rule text at once — the tail of GR20's own fatal/nonfatal fork is the other half of the same machinery.
* **Every standard defect this project has met and not published.** `docs/CONFORMANCE.md` records two for this
  clause; **PB436** finds a third (GR13's unedited step cross-references) also unpublished. A sweep of code
  comments that adjudicate a spec contradiction in prose — rather than in `CONFORMANCE.md` — would find the
  rest.

## 6. ROWS

* `GR-14.9.28.4-18` — PARTIAL. WHEN OTHER IS the unconditional fallback arm after every WHEN and chains to WHEN
  COMMON exactly like a WHEN, which the cited test does establish. What is NOT settled is the DESTINATION: the
  rule carries two mutually exclusive sentences, the compiler implements the second, the project's recorded
  disposition says the first, nothing is published, and no test can see the difference.
