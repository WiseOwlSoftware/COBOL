# PB47 — OPEN — an illegal EVALUATE pairing is diagnosed at the wrong STAGE

> ⚙ **FOUND WHILE CLOSING [[PB45]].** PB45's two defects both ended at the same line — `EvaluateBinder`'s
> `BoundConditionError("EVALUATE TRUE/FALSE paired with a value WHEN object")`. Both were LEGAL source reaching a
> rejection, and both are fixed. What is left at that line is the opposite case: **ILLEGAL source reaching it,
> and being reported at the wrong stage.**

## THE DEFECT

`BoundConditionError` is realized as a **run-time** `NotImplementedCobolFeatureException`. So:

```cobol
EVALUATE TRUE
    WHEN W-Z          *> an identifier object against a TRUE subject
        DISPLAY "X"
END-EVALUATE.
```

compiles CLEAN and throws when that WHEN is reached — and only if it is reached.

**§14.9.13.3 SR10 + Table 15 make this a SYNTAX RULE violation:** "The permissible combinations of selection
subject and selection object operands are indicated in Table 15", and against a **TRUE or FALSE** subject the
table marks only *Condition*, *TRUE/FALSE* and *ANY* permissible — `[NOT] identifier`, `[NOT] literal`,
`[NOT] arithmetic-expression`, `[NOT] boolean-expression`, `[NOT] range-expression` and *Partial-expression* are
all blank, i.e. invalid combinations. A syntax rule violation is a COMPILE-TIME diagnostic.

The mirror case is the same: a *Condition* subject paired with a value object already returns
`BoundConditionError("EVALUATE condition-subject paired with non-boolean WHEN …")` — same wrong stage.

## ⛔ WHY THIS IS NOT COSMETIC

The message says "a COBOL feature that is not yet implemented was reached at run time". It is not
unimplemented — it is **inadmissible source**, and Table 15 says so. A user reads that text as "the compiler is
incomplete" and works around a program bug the compiler should have named at compile time. It is also
COVERAGE-SHAPED: an illegal pairing on a WHEN branch that never executes never reports at all.

## ▶ WHAT TO CHECK FIRST

⚠ **Implement Table 15 as a TABLE, not as a chain of `if`s** (CLAUDE.md rule 5 — the shape that makes the next
case automatic). It is a 9×6 matrix of permissible combinations; a hand-written condition chain per pairing is
exactly the hand-maintained list a structure belongs in, and Table 15 is already machine-transcribable from
`specs/ISO_COBOL.md` (`<a id="table-15">`). Pair it with a drift test that re-derives the matrix from the spec.
⚠ Needs a diagnostic code (session-probe reports the next free) and negative fixtures per invalid combination —
and an edition sweep, since *boolean-expression* and *partial-expression* rows do not exist below 2002.
⚠ Check what ELSE reaches `NotImplementedCobolFeatureException` from a BINDER rather than from genuinely
unimplemented runtime: [[feedback_green_test_can_hold_a_gap_open]] — a loud stage pinned by a green test reads as
a DECISION, and this one was never decided.
