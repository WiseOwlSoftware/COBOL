## Finding

On 2026-11-18 between 20:53 and 20:56 PST, .NET SDKs 11.0.100-preview.7 and 11.0.100-rc.3 were installed on the dev box
beside 10.0.404 (not by a session). The gate of `nightly-toolchain-shards` (run 000001-20261119T045051Z) was then RED on
three Unit tests: `PlatformAssumptionTests.KilledChildEndsAConnectedStream`, `KilledChildEndsAConnectionStillInItsListenBacklog`
and `ConnectToTheKilledListenersSocketFileFails`, each "'dotnet ' ended without the stdout line ... The build failed", the first
printing "Welcome to .NET 11.0! SDK Version: 11.0.100-rc.3.26522.148".

## Root cause

`StartChild` writes the child as a file-based app in a scratch directory and runs `dotnet run` there. An SDK command
resolves its SDK from the nearest global.json; the scratch directory is outside the repository, so none applies and the
muxer takes the newest SDK installed, preview included. `toolchain.py check` cannot see this: it compares the SDK the
repository resolves (10.0.404), which was correct.

## Fix and sweep

The child directory now carries a copy of the repository's global.json, so the child builds with the SDK the manifest names.
Sweep: every other test that starts `dotnet` runs a built assembly (`dotnet <dll>`, which takes the runtime from the
program's runtimeconfig.json, not an SDK) or runs an SDK command inside the repository (AnalyzerBuildsOnceDriftTests,
AnalyzerWiringDriftTests), where the repository's global.json applies. No other site.
