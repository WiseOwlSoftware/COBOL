### Observed
ALL FIVE COMPILE CLEAN and the VALUE is silently discarded. MEASURED at the pin, --std 2023: (a) `05 A PIC X(4) VALUE "AAAA". 05 B REDEFINES A PIC X(4) VALUE "ZZZZ".` -> A and B both display [AAAA] (b_sr12_run); (b) the level-01 form -> both [AAAA] (c_sr12_01_redefines); (c) `05 B REDEFINES A. 10 C PIC X(2) VALUE "ZZ".` -> A [AAAA], C [AA] (b_sr12_sub_run); (d) a group-level VALUE on the REDEFINES entry (c_sr12_group_value); (e) the SR16 Format-2 carrier -> A [AAAAAA], T(1) [AA] (d_sr16_sr12_sub). EDITION-INVARIANT -- the same program compiles at --std 85, 2002 and 2014 (b_sr12_85 / b_sr12_2002 / b_sr12_2014); Annex E records no change to SR12. The OVER-REJECTION CONTROLS pass: a REDEFINES with no VALUE compiles (e_sr12_control) and a level-88 under a REDEFINES compiles (sr12_88_under_redefines) -- both must STAY legal, which is the trap a careless landing falls into. Harm is under-rejection plus a silent drop: the stored value is the one 13.18.63.4 GR5/GR9 would give for the conforming spelling, so nothing is numerically wrong, but the programmer's second VALUE vanishes without a word.
