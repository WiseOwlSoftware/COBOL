# PB4650 - lead from a landed branch's report

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Repository/ExpansionPlacementPass.cs` (`ExpansionPlacementPass.Place`: `homes`, `HomeOf`, `targetHeldElsewhere`, `ReportForeignState`),
`src/WiseOwl.Cobol.Compiler/Binding/MetadataRepositoryProvider.cs` (`IsCompiledAgainst`, `OutputAssemblyName`, `PublishedExpansion`, `RepositoryEntryOrigin.AssemblyName`),
`src/WiseOwl.Cobol.Compiler/Binding/Model/OoClassSymbol.cs` (`ImportedFrom.AssemblyName`), `docs/rearchitecture/DESIGN-external-repository.md` section 10.5.

Crash (backend error). Repro `E:\COBOL-coord\scratch\w20261849e\p1\CLIENT2.cob` after LIBX + CLIENT1 (as reported, not re-run). Different root from the token screens: §9.3.12 identity (report cites it, not validated here).

**Landed (w20261868c).** Re-probe on `630b1f2fb`, `--source-format free`: LIBX, CLIENT1, CLIENT2 failed with `CS0012: The type 'BOX' is defined in an
assembly that is not referenced ... 'LIBX'`. The same arm failed for two libraries holding an identical BOX (CLIENT1 over one, CLIENT4 over the other),
and in the reverse order CLIENT1 imported the expansion `CLIENT2.dll` held, typed with CLIENT2's BOX. Root: the `ExpansionKey` hashes a class's
record and not its home, so "same key" does not say "compiled against the classes this compilation holds". An existing expansion is imported only when
its assembly names the assembly of every actual and resolution (`IsCompiledAgainst`; this group's output for a class written here, which is the
reference cycle of section 10.5 step (3)); a same-key copy elsewhere reports nothing, and when it holds the file placement (a) would write, the
expansion goes into the group's assembly. Witnesses: `ExternalRepositoryExpansionTests.AnExpansionCompiledAgainstALibrarysClass_IsNotImported_ByAGroupThatWritesThatClassItself`
(both orders) and `AnExpansionCompiledAgainstAnotherAssemblysClass_IsNotImported_NorWrittenOver`.
