# PB2521

Filed from the PB1943 refuter (`E:\COBOL-coord\scratch\w1033-adj\PB1943-refute.md` section 4 and corrected decision: "Reference modification of PAGE-COUNTER (`pcref.cob`), a report counter drafted the same way as the sum counter ... The same latitude ruling should decide this sibling, and a parse error is a misdiagnosis either way"). It is undecided, so an analysis; it is a different mechanism from `PB2520` (a parse failure, not a size read).

**Observed.** `pcref.cob`: the pinned build gives `COBOL0001: unexpected '('`; GnuCOBOL 3.2.0 gives "syntax error, unexpected (, expecting TO". Both refuse reference modification of a conceptual numeric report counter.

**Spec status (cite.py --check OK).** `§8.4.3.15.4 GR1`: "PAGE-COUNTER and LINE-COUNTER reference temporary unsigned integer data items of class and category numeric, which are maintained for each report." Like the sum counter (`PB1943`), no usage is stated, while `§8.4.3.3.3 SR1` admits only "a numeric data item of usage display or national"; the counter's representation is therefore implementor latitude (rule 1 precedence; GnuCOBOL gives no usable observation). Owed: the same determination as PB1943 recorded in `docs/CONFORMANCE.md`, then either support with a DISPLAY image or a named refusal in place of the generic parse error. Related: `PB1943`, `PB2520`.
