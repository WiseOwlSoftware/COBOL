# PB5527 - the 2023 messaging RECEIVE (BoundReceiveMessage) collects its INTO receiver as a whole-group operand only: an elementary numeric INTO takes the sender's storage image through EmitImageInto and is likely to drop non-digit content, as PB5489 found for the 1985 RECEIVE

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Passes/UsageCollectionPass.cs` (`Visitor.Visit`, the BoundReceiveMessage overload), `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/MessagingEmitter.cs` (`MessagingEmitter.Emit`, the BoundReceiveMessage arm; read, the image route)

**Mechanism.** `Visit(BoundReceiveMessage)` (line 320) does `P(n.Into)` only. PB5489 fixed the 1985 communication RECEIVE by also calling `Channel(n.Into)`, the elementary character-channel set `StorageFormPass` promotes to image storage (the twin of STRING identifier-3, PB4089): the message is transferred to the receiving character positions (`§1985:XIV.3.5.4 GR3`, checked with `cite.py --check`), so a numeric carrier that parses digits only printed `0034` where `AB34` is right. The 2023 messaging RECEIVE stores the sender's storage image through `MessagingEmitter` `EmitImageInto` (kb/Work PB4957 describes the group route), so an elementary numeric INTO with non-digit message content likely drops the same way.

**Landed (wave 20262033 group A).** Probed on a Debug build with a requestor and a BALANCE server run unit: the server replies AB34, the requestor's `RECEIVE WS-TAG GIVING K-NUM` over `PIC 9(4) VALUE 1234` printed `GOT [0034] LEN=0004`; after the fix `[AB34]`. `Visit(BoundReceiveMessage)` now also records `Channel(n.Into)`. Golden `conformance-suite/wiseowl/cases/14.9.31-RECEIVE/pb5527-receive-into-numeric-message-characters` (server file beside it). No negative below 2023: the facility's refusal is already pinned by `_unassigned/pb374-async-messaging-below-2023`.

**Probe first (original).** Not probed: it needs a requester run unit. `wrong_answer: true` is the SUSPECTED harm, set because the register refuses an open defect with no flag; clear it (and close the note) if the probe prints the characters. The 2002 edition's refusal of a whole numeric INTO is COBOL6171 (PB5384's) for the 1985 statement; check what the 2023 messaging form refuses.

**Fix direction.** If the probe confirms, add the receiver to the character channel in `Visit(BoundReceiveMessage)` and a golden beside PB5489's.
