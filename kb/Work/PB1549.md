# PB1549 — LANDED

Found 2026-09-24 by the golden-lane-2 refuter (dns-witness, draft `2002/l1c40_noncobol_program_address`); **not yet
re-probed by an implementer** — reproduce first.

## Rule

`OK  §14.6.13.1.3 7)  (Fatal exception conditions)` — "If checking for the exception condition is enabled, execution of
the run unit is terminated abnormally as specified in 14.6.12". EC-PROGRAM-NOT-FOUND is fatal (Table 13).

## Repro (refuter)

`>>TURN EC-PROGRAM-NOT-FOUND CHECKING ON`; `SET PP TO ADDRESS OF PROGRAM "System.Console"` with no ON EXCEPTION,
no applicable declarative, no PERFORM WHEN handler; then `DISPLAY "PQ=SET"` and further DISPLAYs. Expected stdout:
`PQ=SET` only (then abnormal termination). Observed: execution continues through the remaining statements. Draft
source: `<scratchpad 9db39f61…>\gl\out\dns-witness\tests\conformance\2002\l1c40_noncobol_program_address.cob`.

## Code sites

- `src/Cobol.Net.Compiler/CodeGen/Verbs/PtrEmitter.cs` `EmitSetEntry` (~L220-236): `ExceptionState.Set` +
  `EcDispatchExpr` + `ResumeTransfer`, with no fatal-termination path when nothing handles the condition.
- The sibling arm that is right: `ProgramRegistry.EntryOfOperand` throws the fatal exception.
- Sweep: the `ADDRESS OF FUNCTION` twin, and every other emitter that raises a FATAL EC through `EcDispatchExpr` +
  `ResumeTransfer` (variant-analysis: is "fatal with no handler ⇒ terminate" in ONE place?).

## Landed 2026-09-24 (wave 59 group I): one fatal default, taken from Table 13

**Re-probed on the worktree build (main 3668923e2):** the refuter draft printed all six lines and exited 0. After the
fix it prints `PQ=SET`, then `abnormal run-unit termination: EC-PROGRAM-NOT-FOUND (fatal)` on stderr, exit 1.

**Root cause:** each emitted raise site wrote `EcDispatchExpr` and `ResumeTransfer` itself, and each had to remember
the `if (r != -2) throw` that §14.6.13.1.3 5)/7) require for a fatal condition. The SET ADDRESS OF PROGRAM site
forgot it. So did its ADDRESS OF FUNCTION twins, EC-FUNCTION-NOT-FOUND and EC-FUNCTION-PTR-INVALID, both fatal
in Table 13. **Fix:** `EcEmitter.EmitSelection` is now the only renderer of the selector, the RESUME landing and the
fatal default. `EmitConditionRaise` and `EmitConditionSet` take a constant name's fatality from the catalog through
the new `EcInfo.IsFatal`, which is also now the one spelling of that test in EcBinder and ExceptionState. All 15 raise
sites (PtrEmitter x5, CallEmitter x3, SequentialIo, SEARCH, CONTINUE AFTER, and the RAISE, size, overflow and
statement-guard arms of EcEmitter) route through it. `EcRaiseSelectionDriftTests` fails if anything else renders the
selector or bakes a constant name's fatal flag. It was made to fail once by injecting both shapes into
PtrEmitter.cs.

**Golden corrected:** `2023/pb452_function_address_runtime`'s declaratives completed normally after a FATAL
condition and expected the run to continue, which §14.6.13.1.3 5) forbids. They now end with RESUME AT NEXT
STATEMENT (NOTE 2). The expected output is unchanged.
