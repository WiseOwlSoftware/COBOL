# PB3806 — an unseen test file edited by the branch loses the whole plan's aim

**Sites:** `scripts/spec/impacted_tests.py#reach_cs`, `scripts/spec/impacted_tests.py#drifted_change`, `scripts/spec/impacted_tests.py#reach_test_file`

## Measured

The drift arm of `reach_cs` runs before the `TEST_PROJECTS` guard. Scenario: map M recorded at X; main then adds
`tests/Cobol.Net.Tests.Unit/FooDriftTests.cs`; a branch cut after that edits `FooDriftTests.cs` plus one src file.
`reach_cs(ix, that path)` with the path in `ix.drift` and not in `ix.known` appends `every_tier1` (probed:
`MapIndex(synthetic_map(), frozenset({p}))` gives "...differs between the map's commit and the base, and the map has never
seen it"; with empty drift it gives `[]`). The whole plan loses its aim and leg 1 falls back to the cheapest slice for the
src change too, whereas the same unseen test file outside drift returns quietly because `reach_test_file` tiers its edited
tests 0a.

## Acceptance

- A path under `TEST_PROJECTS` that is in drift and not in `ix.known` returns as the non-drift arm does (its edited tests
  tier 0a); the fix is the ordering or one shared guard, not a second copy of the TEST_PROJECTS condition.
- A self-test arm: the scenario above yields no `every_tier1` and keeps the src file's own reach.
