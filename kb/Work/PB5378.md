# PB5378 - SEND measures the size of identifier-1 two ways: an elementary COMP, BINARY or PACKED-DECIMAL item by its standard-data-format digits, a group by its storage bytes, so a text length legal for one is status 50 or a transfer of characters the item does not hold for the other

**Sites:**

- `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/CommunicationEmitter.cs#Emit` (the SEND FROM arm)
- `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/OperandText.cs#AsTransferString` (an elementary item's digit image)
- `src/WiseOwl.Cobol.Compiler/CodeGen/Roslyn/PlaceRenderer.cs#SendingGroupImage` (a group's storage image)

**Mechanism.** The SEND FROM operand is rendered by `AsTransferString`, which gives an elementary binary or packed item its digit image (4 characters for `9(4) COMP`) and a group its storage bytes (4 bytes for `XX` plus `9(4) BINARY`, whose standard-data-format size is 6). The text-length range check then measures each against a different size.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids below. Its row is not recorded: the refuter's OVERTURNED verdict is held for adjudication in `E:/COBOL-coord/scratch/coderead-85/held-7.json`.

**Rules (1 claimed; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-GR-XIV.3.6.4-3` - `§1985:XIV.3.6.4 GR3` (refuter: OVERTURNED, harm: wrong status or wrong text): a text length "outside the range of zero through the size of the data item referenced by identifier-1 inclusive" is an error; `§1985:IV.4.3.4`: "The size of an elementary data item or a group item is the number of characters in standard data format of the item".

**Expected (from the 1985 text).** One measure for both kinds.
