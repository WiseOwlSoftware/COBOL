# PB4522 — seconds-from-formatted-time-fraction-stale-scale: SECONDS-FROM-FORMATTED-TIME with fractional seconds returns a wrong value that depends on the previous call

Filed 2026-11-03 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-batch-3000-20261103`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

SECONDS-FROM-FORMATTED-TIME returns a wrong value for a time with fractional seconds whenever an earlier call in the
run left a different scale behind: the whole seconds are taken at the scale of the previous result, not at scale 0.
In one run, `("hh:mm:ss.s" "00:00:01.5")` first gives 1.5 (right), then `("hh:mm:ss.ss" "00:00:01.50")` gives 0.6
instead of 1.5, `("hh:mm:ss.ssssss" "23:59:59.999999")` gives 8640.899999 instead of 86399.999999, and the first call
repeated gives 0.500001 instead of 1.5. The number of fraction digits is not the trigger: the same calls in another
order give other wrong values. Class: wrong output. Fuzz night 2026-11-03: fz00991.

## Minimal test case

Free reference format (`-free`).
```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. SFTFRAC.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 WS-NUM PIC 9(5)V9(9) VALUE 0.
PROCEDURE DIVISION.
    COMPUTE WS-NUM = FUNCTION SECONDS-FROM-FORMATTED-TIME
        ("hh:mm:ss.s" "00:00:01.5")
    DISPLAY "F1 " WS-NUM
    COMPUTE WS-NUM = FUNCTION SECONDS-FROM-FORMATTED-TIME
        ("hh:mm:ss.ss" "00:00:01.50")
    DISPLAY "F2 " WS-NUM
    COMPUTE WS-NUM = FUNCTION SECONDS-FROM-FORMATTED-TIME
        ("hh:mm:ss.ssssss" "23:59:59.999999")
    DISPLAY "F6 " WS-NUM
    COMPUTE WS-NUM = FUNCTION SECONDS-FROM-FORMATTED-TIME
        ("hh:mm:ss.s" "00:00:01.5")
    DISPLAY "F1 " WS-NUM
    STOP RUN.
```

## Environment

cobc (GnuCOBOL) 3.2.0 on WSL2 Ubuntu. `cobc -x -free -std=cobol2014 -o p prog.cob && ./p` (no diagnostic other than
the distribution's `_FORTIFY_SOURCE` redefinition notice).

## Observed result

```
F1 00001.500000000
F2 00000.600000000
F6 08640.899999000
F1 00000.500001000
```
Exit code 0.

## Expected result (per ISO)

§15.79.4 rule 1 (2014 and 2023): the returned value is "((H * 3600) + (M * 60) + S)", where "S is the portion of
argument-2 corresponding to the seconds subfield of argument-1". §15.3.3.2 makes the fraction digits part of that
subfield: a fractional-seconds time format has "at least one lowercase 's' character representing a digit in the
decimal fraction portion of the seconds subfield". Nothing in the rule depends on an earlier call. Expected:
```
F1 00001.500000000
F2 00001.500000000
F6 86399.999999000
F1 00001.500000000
```

## Our compiler

WiseOwl COBOL (fresh judge) prints the expected values for the F1, F2 and F6 calls of the fuzz program; the repeated
F1 line was added by the refuter and not run on WiseOwl.

## Fix site

libcob/intrinsic.c (read in a 3.3-dev tree), `seconds_from_formatted_time`: in the branch for `format.decimal_places != 0`
it sets `seconds_decimal->value` to the whole seconds but does not set `seconds_decimal->scale` (the other branch sets it
to 0), so `cob_decimal_add` uses the scale the decimal was left with by an earlier use.

## Draft issue

**Title:** SECONDS-FROM-FORMATTED-TIME with fractional seconds returns a value that depends on earlier calls

As posted (owner-reviewed, 2026-11-04):

SECONDS-FROM-FORMATTED-TIME returns the wrong number of seconds for a time of one second or more with fractional seconds when an earlier intrinsic function in the run left a scale in the work decimal `d1` that libcob's intrinsic functions share.

### To reproduce

`sftfrac.cob` (attached) makes four calls with extended time formats, the last one repeating the first:

~~~~
       IDENTIFICATION DIVISION.
       PROGRAM-ID. SFTFRAC.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 WS-NUM PIC 9(5)V9(9) VALUE 0.
       PROCEDURE DIVISION.
           COMPUTE WS-NUM = FUNCTION SECONDS-FROM-FORMATTED-TIME
               ("hh:mm:ss.s" "00:00:01.5")
           DISPLAY "F1 " WS-NUM
           COMPUTE WS-NUM = FUNCTION SECONDS-FROM-FORMATTED-TIME
               ("hh:mm:ss.ss" "00:00:01.50")
           DISPLAY "F2 " WS-NUM
           COMPUTE WS-NUM = FUNCTION SECONDS-FROM-FORMATTED-TIME
               ("hh:mm:ss.ssssss" "23:59:59.999999")
           DISPLAY "F6 " WS-NUM
           COMPUTE WS-NUM = FUNCTION SECONDS-FROM-FORMATTED-TIME
               ("hh:mm:ss.s" "00:00:01.5")
           DISPLAY "F1 " WS-NUM
           STOP RUN.
~~~~

    cobc -std=cobol2014 -x sftfrac.cob && ./sftfrac

### What happens

3.2.0 and 3.3-dev r5751 both print the following, and only the first line is right:

~~~~
F1 00001.500000000
F2 00000.600000000
F6 08640.899999000
F1 00000.500001000
~~~~

`sftother.cob`, attached, shows the same after `FUNCTION ABS (-1.25)` and after `FUNCTION NUMVAL ("1.5")`: 10:14:27.8124 comes back as 369.4824 and 3687.5124 instead of 36867.8124.

### What should happen

Every call returns its own time in seconds, whatever ran before it: 1.5, 1.5, 86399.999999 and 1.5. ISO/IEC 1989:2023 15.79.4 rule 1 gives the equivalent arithmetic expression "((H * 3600) + (M * 60) + S)", and 15.3.3.2 makes the fraction part of the seconds subfield S; the same in the 2014 FCD (15.74.3 rule 1).

### Why it happens

In `libcob/intrinsic.c`, `seconds_from_formatted_time` sets the value of `d1` to the whole seconds but not its scale, then adds the fraction with `cob_decimal_add`: after a scale of 1, the 1 second of `"00:00:01.50"` counts as 0.1, and 0.1 + 0.50 gives 0.6. The branch for a format without fractional seconds sets the scale to 0, which is why those formats are always right.

### Proposed fix

The attached `n10-seconds-from-formatted-time-scale.patch` (against 3.3-dev r5751) inserts `seconds_decimal->scale = 0;` before the fraction is added, as the other branch already does, and adds a testsuite case, "FUNCTION SECONDS-FROM-FORMATTED-TIME repeated with fractions", to `run_functions.at`, with ChangeLog entries. With it both programs print the expected values. `make check`: 1373 expected, 9 skipped, 0 failed; the new test fails without the patch.

### Related

[bugs #1294](https://sourceforge.net/p/gnucobol/bugs/1294/): the decimal separator in basic time formats with fractional seconds (`hhmmss.sss`), a different defect whose patch also changes `seconds_from_formatted_time`; the two patches apply together in either order.
