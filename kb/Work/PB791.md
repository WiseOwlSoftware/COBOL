# PB791 — OPEN — the class check that stands in for four rules

Filed 2026-09-06 14:19 PDT by the registrar from the PB770 implementer's report (§"New defects found",
paragraph B): *"The CURRENCY half of the `LiteralChars` misfiling is fixed in this change set … What is NOT swept
is the rest of §12.3.7.3 SR18–SR27 against the same question."* PB770 LANDED in train 19. **The sweep the report
asked for was done here, on main at `07cbb2ad`, by reading the code path rather than by running it — and it does
not come out the way the report's two examples predict.** Both corrections are called out below.

      set that is neither the same as nor equivalent to any of the following: a) digits 0 through 9; …"
python scripts/spec/cite.py --check 12.3.7.3 "It shall be neither a figurative constant nor a hexadecimal literal"
  OK  §12.3.7.3 26)   "26) Literal-8 shall be an alphanumeric or national literal consisting of a single
      character from the computer's compile-time coded character set. It shall be neither a figurative constant

SR18 and SR26 each carry TWO requirements. The compiler implements one of the four.

## The mechanism, quoted from main

`src/Cobol.Net.Compiler/Binding/DataBinder.Switches.cs:341-349` — the whole of the clause's literal screen:

```csharp
private string? CurrencyTextLiteral(Core.LiteralContext lit, string operand, string rule)
{
    if (!int.TryParse(lit.GetText(), out _) && !decimal.TryParse(lit.GetText(), …, out _))
        return LiteralCharsOf(lit);                                    // :345  — everything non-numeric passes
    Edition.Error("COBOLNET0892", $"CURRENCY SIGN {lit.GetText()}: {operand} shall be an alphanumeric or "
        + $"national literal, not a numeric one (ISO §12.3.7.3 SR{rule})");
    return null;
}
```

Its own doc comment (`:334-340`) quotes both SR18 and SR26 in full, including *"that is not a figurative
constant"* — and the body tests only the numeric/non-numeric axis. `feedback_a_dead_lookup_is_also_unverified`'s
cousin: a rule QUOTED in a summary is not a rule enforced in the method.

Both call sites are in `SwitchBindCurrency` (`:358`): literal-7 at `:362` (rule string `"18"`) and literal-8 at
`:378` (rule string `"26"`). There is no other screen — `:379` immediately re-decodes literal-8 through
`LiteralCharsOf` and the only later tests are length (`:380`), SR23 a/b content (`:387`, `:393`) and
`ValidateCurrencyChar`'s SR22/SR27 forbidden set (`:435`).

## ⛔ Premise correction 1 — `CURRENCY SIGN IS SPACE` is NOT silently accepted

The report's first example is *"`CURRENCY SIGN IS SPACE` … want measuring. Harm: under-rejection."* It is
refused, and how it is refused is the actual finding. `LiteralCharsOf` (`:1277-1285`) is:

```csharp
private string LiteralCharsOf(Core.LiteralContext lit)
{
    if (lit.nonNumericLiteral()?.concatenationExpression() is { } ce) return ConcatFolder.Fold(…).Value;
    string text = lit.GetText();
    if (CobolLiteral.IsStringLiteral(text)) return CobolLiteral.Decode(text);
    if (text.Length >= 3 && text[0] is 'X' or 'x' && text[1] is '"' or '\'') return CobolLiteral.DecodeHex(text);
    return text;                                                        // :1284  ⛔ the raw-text word fallback
}
```

A figurative constant reaches here as a LITERAL (`nonNumericLiteral : figurativeConstant | …`), is not a quoted
literal, and falls to `:1284`. So `SPACE` becomes the five-character string `"SPACE"`, length 5, and
`SwitchBindCurrency`'s bare-form arm reports:

```
COBOLNET0890: CURRENCY SIGN "SPACE": without PICTURE SYMBOL the literal shall consist of a single character
  (ISO §12.3.7.3 r22)
```

— a diagnostic that is FALSE about the source (`SPACE` names exactly one character) and cites the wrong rule
(SR22's length requirement, not SR18's figurative-constant ban). ⛔ **This is the SAME `_ => t` word fallback
PB770 deleted, one caller over.** PB770's own note records it: *"the literal route fell through to
`LiteralChars`, which returned the raw text: `ALPHABET X IS SPACE` positioned S, P, A, C, E"* — fixed for the
ALPHABET arm by giving both arms one §12.3.7.4 GR10 mapping, and left intact in the shared helper the CURRENCY
clause calls. `feedback_two_arm_dispatch`; `feedback_scan_all_similar`.

Measured reach of `:1284`: `grep -rn "LiteralCharsOf(" src/` gives THREE call sites — `:345` and `:379` (the two
CURRENCY operands) and `:1218` inside `AlphabetOperands`, where the figurative case is intercepted earlier by the
dedicated `case … figurativeConstant` arm at `:1180`. So after PB770 the raw-text fallback is reachable with a
figurative constant from the CURRENCY clause and from nowhere else. That bounds the fix.

## ⛔ Premise correction 2 — the live under-rejection is the HEX half, not the figurative half

The report's second example pairs `CURRENCY SIGN X"41" PICTURE SYMBOL X"41"` with the figurative case. Traced on
main, the hexadecimal half is the one that gets through, and it gets through cleanly:

- `CURRENCY SIGN "USD" PICTURE SYMBOL X"24"` → `CurrencyTextLiteral` passes it (not numeric) → `LiteralCharsOf`
  decodes the hex to `"$"` → `literal8.Length == 1` passes `:380` → `ValidateCurrencyChar('$')` finds `'$'`
  outside the SR22/SR27 forbidden set → **bound, no diagnostic.** SR26 says literal-8 *"shall be neither a
  figurative constant nor a **hexadecimal literal**"*, full stop, whatever it decodes to.
- The report's own `X"41"` decodes to `'A'`, which IS in the SR27 forbidden set, so that spelling is refused —
  by SR27, for a reason SR26 makes irrelevant. It is the example that hides the defect
  (`feedback_probe_the_shape_the_subject_hides`); `X"24"` is the one that shows it.
- SR19's mirror image IS implemented for literal-7 (`literal7Hex`, `:365-367`, → COBOLNET0890 citing r19), which
  is why the asymmetry reads as an oversight rather than a decision: the clause knows how to detect a
  hexadecimal literal by token text and simply never asks the question of literal-8.

So the live, silent under-rejection is exactly one spelling class: **a hexadecimal literal-8 whose decoded
character is not in the SR27 forbidden set.** That is what `under_rejects` + `silent` are set for here.

⚠ **Derived from the code path, not run** — the registrar did not build (coordinator's instruction). Probe:
compile `SPECIAL-NAMES. CURRENCY SIGN "USD" PICTURE SYMBOL X"24".` plus a `PIC USD9(3)` item at `--std 2023` and
at `--std 2002`, and `CURRENCY SIGN IS SPACE` at `--std 85`; both belong in the fix's negative fixtures.

## Sweep — and one dead branch to delete while you are in here

`LiteralCharsOf:1283`, the `X"…"` arm, is **unreachable**. `CobolLiteral.IsStringLiteral` is
`SplitLiteral(raw) is not null` (`src/Cobol.Net.Frontend/Common/CobolLiteral.cs:72`) and `SplitLiteral` accepts
the `X` / `NX` / `B` / `BX` prefixes, so `:1282` already claims every hexadecimal spelling and
`CobolLiteral.Decode` dispatches to `DecodeHex` itself at `CobolLiteral.cs:126`. The branch at `:1283` therefore
never runs — and `feedback_a_dead_lookup_is_also_unverified` applies: it has never been contradicted because it
has never executed. Delete it rather than trusting it; if the fix wants to KNOW a literal was hexadecimal (SR26
needs exactly that), the question belongs on `CobolLiteral.ClassOf`/`SplitLiteral`'s prefix, which is the ONE
classifier (`CobolLiteral.cs:80`, "kb/Work PB71"), not on a second `text[0] is 'X'` test.

## Fix shape

1. `CurrencyTextLiteral` asks the THREE questions its own summary already states, per operand: class (numeric →
   the existing COBOLNET0892), **figurative constant** (SR18 for literal-7, SR26 for literal-8), and — for
   literal-8 only — **hexadecimal** (SR26). Take the operand's rule set as data, not as a `rule` string glued to
   one message (the sibling defect [[PB789]] is the same parameter mistake one helper over).
2. Delete `LiteralCharsOf`'s `:1284` raw-text fallback. A word that is not a literal is not a literal; every
   caller after PB770 either intercepts the figurative case first or wants a diagnostic. Returning the spelling
   is the mechanism that produced `ALPHABET X IS SPACE` → S,P,A,C,E and now produces `CURRENCY SIGN "SPACE"`.
3. Delete the dead `:1283` branch and ask the prefix question through `CobolLiteral` (above).
4. Negatives per rule and per operand — SR18 figurative, SR26 figurative, SR26 hexadecimal — plus the positive
   `CURRENCY SIGN "USD" PICTURE SYMBOL "U"` so the screen is proven not to over-fire.
