# PB2483 — one STOP file stops both sessions' agents

Owner, 2026-10-07 13:17 PDT: a second Claude Code session, logged into a second Max 20x account (`CLAUDE_CONFIG_DIR=C:\Users\brent\.claude-acct2`), runs every Opus/Sonnet dispatch, the orchestrator loop and the landings (the OPERATOR); the first account's session keeps Mythos work. The owner seeded the second config dir by hand. Owner 13:36 PDT: account 2's week resets Saturday 2026-10-10 10:00 PDT and must be spent to 100 % before then, so every hour the tooling stops dispatch wrongly is quota lost.

**Model:** Opus (tooling with self-tests). All six notes are one mechanism (the account is a parameter of the coordination tooling, never an assumption) and are dispatched as one group.

## Defect

Every dispatch brief tells its agent to check `E:\COBOL-coord\scratch\STOP`. `stop.ps1` and the wave unit create
it to wind the LOOP's fleet down. On 2026-10-07 13:26 the operator moved the loop to account 2 (stop.ps1); the wave
unit created the scratch STOP; the Mythos session's in-session refuter (`1031-r1-refute6.md`) saw it and split after
five of six claims (report `E:\COBOL-coord\scratch\reports\w1031-PB2118-refute6-report.md`, "the STOP file
appeared after H4's line"). The work was not lost (checkpointed) but a Mythos dispatch was cut short by an
unrelated stop.

## Shape

A STOP is scoped: the loop's fleet stops on `{COORD}\scratch\STOP-<wave or run id>` (or a STOP file inside the
workflow's own scratch dir), the owner's global stop stays `{COORD}\scratch\STOP`, and a brief names the STOP files
that apply to it (its own and the global one). `stop.ps1`, the wave unit (`units/wave.md`), `wf_rolling_wave.js`,
the brief templates and MANDATORY-PRACTICES change together; `check_practices.py` checks the scoped form. Sweep every
template and brief generator for the literal `scratch\STOP`.


## Landed (branch acct2-tooling, wave 1033 group T)

A stop is SCOPED (design section 4.6, MANDATORY-PRACTICES P3): the owner's GLOBAL stop `<coord>\scratch\STOP` (every
agent of every session, and the loop, obey it; only `stop.ps1 -Global` creates it and only `-Clear -Global` removes it)
and a FLEET's own `<scratch>\STOP-<scope>` (the loop's `STOP-loop`, an attended wave's `STOP-w<wave>`), which only
the agents whose dispatch names it obey.

- One definition: `coord.py` `global_stop()` / `fleet_stop(scratch, scope)` (a scope is a plain name; a path is refused).
- The supervisor's wind-down creates `STOP-UNIT` and `scratch\STOP-loop`, never the global file; it clears only
  `STOP-loop` at a unit's start; the global stop ends the loop and is never removed by it. `stop.ps1` gains `-Global`
  and reports all three. `units/common.md` and `units/wave.md` carry `{FLEET_STOP}`/`{GLOBAL_STOP}`.
- Every dispatch names both: `plan_wave.py --stop-file` (default `STOP-w<wave>`; refuses the global file) writes
  `stop_file` and `global_stop`; `make_dispatch_specs.py` has one `render()` (the planner's self-test uses it instead of
  two private copies of the format call) and renders nothing without `stop_file`; `wf_rolling_wave.js` refuses args
  without both; the lane-3 workflows take `globalStopFile`.
- `check_practices.py`: the template's `{global_stop}`/`{stop_file}`, a rendered spec's `scratch\STOP` and
  `STOP-<scope>`, a groups file's `stop_file`, the workflows' args, and P3's `STOP-<scope>`. Swept: MANDATORY-PRACTICES
  P3, the workstream SKILL, `references/checkpointing.md`, the implementer/adjudicator/refuter agent definitions;
  `grep` for `scratch\STOP`, `{SCRATCH}\STOP`, `{S}\STOP` leaves only the global stop's own definitions.
- Tests: `test_orchestrate.ps1` (the wind-down never creates the global file; another fleet's stop survives a unit
  start; the global stop ends the loop and stays; `stop.ps1 -Global`, `-Clear`, `-Clear -Global`), `test_plan_wave.py`
  65/65 (a rendered spec names both and passes check_practices; no `stop_file`, no spec; a path scope refused).
