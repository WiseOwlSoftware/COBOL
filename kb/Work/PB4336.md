# PB4336 — `EnsureUtf8` publishes its flag before the work

**Found 2026-10-31** by the PB380 review finisher (wave 20261791 group B, branch `worktree-wf_15d43d1b-129-9`, report
`E:\COBOL-coord\scratch\reports\w20261791b-PB380-report.md`, "New defects (note-ready)").

**Sites:** `src/WiseOwl.Cobol.Runtime/IO/StandardStreams.cs:96` (`StandardStreams.EnsureUtf8`).

`Interlocked.Exchange(ref _applied, 1)` at `StandardStreams.cs:96` precedes the console-encoding and writer setup, so a
concurrent caller returns while the winner is still configuring the streams. It is the shape of PB380 (a latch
published before the work); the report says the two share a root cause "only by family". The report's fix shape is the
same as PB380's `CacheConfigurationLatch` (the latch owns the lock, the flag and the work; a loser waits for the winner).

**Do not edit PB380 for this.** PB380 has two fixes in flight (PR #934 and branch `worktree-wf_15d43d1b-129-9`, see
PB4345); this is a separate site and a separate note. Related: PB899 and PB3193 (the EnsureUtf8 history).
