# PB3335 — delete the whole-store model; coherence at page granularity

Implement FROM `docs/rearchitecture/DESIGN-runtime-library.md` §2.2.1, sections 2.2.1.7 (coherence), 2.2.1.8 (the locks),
2.2.1.11 (d) (the whole-store ban) and 2.2.1.13 (the deletion list). Follows PB3334 (same files). After this group there is
ONE statement path for every keyed connector and every sharing mode.

## Mechanism

- Delete from `KeyedConnector`: `Load`, `Persist`, `PersistIfChanged`, `PersistIsReachable`, `ReadImage`, `ReadThroughAreas`,
  `WriteThroughAreas`, `ReadAt`, `ReadGeneration`, `Reload`, `Fill`, `PersistFrames`, `ReleaseMint`, `StoreHolds`,
  `_storeHeaderBytes`, `_areas`, `HostFaultObserver`, `HostFaultPoint`; from `KeyedStore`: `Version`, `PersistedVersion`,
  `Generation`, `VersionAtEntry`, `Mutated`; from `RecordFraming`: `ComposeStore`, `DecodeStore`, the store-level
  `DecodeHeader`/`WriteHeader`, `ReadHeader`, `ImageMedium`, `GapTag`, `GapBytes`, `EncodeGap`, `MaxStoreBytes`, `HeaderBytes`,
  `OrdinalSlots`, `FrameBytes(StoredFrame)`, `GenerationOffset`, `GenerationProbeBytes`, `DecodeGeneration`; `KeyedStoreTable`
  becomes `StoreTable` (open `PagedStore`s per physical file, the same attach/detach contract). Every caller moves to the engine;
  nothing forwards.
- A connector is COHERENT when its sharing mode admits any other run unit's connector — every mode but `SHARING WITH NO OTHER`
  (`FileLockPosture.AdmitsAnotherRunUnit`, which PB3333 introduced for the connectors on the engine; this group retires the
  whole-store arm of `KeyedConnector._coherent`, so every keyed connector now derives from it). **`AdmitsAnotherWriter` is NOT
  deleted** (finding R2-7): its four callers — `FileSupport.OpenConnectorWriteStream`, `SequentialConnector.ReleaseRecord`,
  `EnsureReaderCoherent` and the EXTEND ordinal count — ask the sequential organization's question, "may another WRITER
  exist", and keep it. `BeginStatement` for a coherent connector: hold the store mutex as today, read page 2 (the work meta),
  compare its `generation` with the one the store LAST SAW there (at OPEN or its own previous statement), adopt page 2 and
  `PagedStore.DropCache` when they differ (2.2.1.7; an INPUT connector that opened a crashed file keeps R6's committed meta
  until page 2's generation changes), raise the next claim above a `stamp mint` found moved, resolve a PROMOTING flag found
  set (`CompletePromotion`'s restart rule, round 4), and — through a writable handle — run the dead-owner step (PB3337)
  before the statement proceeds; a changing statement then CLAIMS, in the store's memory and on page 2, its generation and
  every mint it advances before its first page write (rounds 3 and 4); `CompleteStatement` writes
  the dirty pages and the work meta (the generation = the claim) before the mutex is given back; `WaitOutsideStatement`
  unchanged; the OPEN's adoption rule (R6, with the fence) runs under the same mutex. A `NO OTHER` connector writes its dirty
  pages and work meta at `CompleteStatement` without the mutex and without the generation read; its claim is the store's
  memory alone, raised whether or not the statement completes, so its CLOSE's promotion and retirement stamp above a
  refused statement's pages (round 4, R4-3).
- The input-output areas (§12.4.5.14.3 GR1) become the page cache's floor (2.2.1.13); `HostFile.InputOutputAreaBuffer` keeps
  sizing them. `HostRegionLocks`' comment on why the Windows locks are harmless names 2^44 (the format's largest file) instead of
  `MaxStoreBytes`.
- `SequentialConnector`'s keyed-store check and `KeyedConnector.FixedAttributeConflict` read `MetaPage.Describes`.
- `docs/CONFORMANCE.md` DOC-A.1-75: the rest of the statement-mutex sentence. PB3333 rewrote its RELATIVE half and left
  INDEXED files with "executes each record statement under a byte-range statement mutex on the file, starting from the file
  as it is (re-read when the generation stamp in its header moved) and writing what the statement changed before it ends";
  this group makes the sentence the page-granular wording of 2.2.1.7 for both organizations (every sharing mode but NO
  OTHER, one meta-page read, a cache drop); the lock paragraphs stay. The determination of 2.2.1.10 on a run unit that died
  under APPLY COMMIT is PB3337's, written when the facility exists (CLAUDE.md rule 6: the row describes the current
  compiler).
- `docs/rearchitecture/DESIGN-runtime-library.md`: the "AND ACROSS RUN UNITS: a keyed store another run unit may write is a
  COPY" paragraph and its three bullets, the "Emptying a keyed store" paragraph and every "whole-store" sentence of §2.2 are
  rewritten to describe the engine (the 2.2.1 STATUS line drops its "target" wording); the DEVLOG entry carries the history.

## Tests

- The PENDING rows of 2.2.1.16 and 2.2.1.17 that this group's paths cover (written by PB3331 on `MemoryPageMedium`)
  become running cases in this landing, each expected result still the design text's, never the engine's.
- The matrix `CrossRunUnitKeyedStoreDriftTests` runs: '51' on READ WITH LOCK and REWRITE, IGNORING LOCK, a sibling's WRITE visible
  at the next statement, every run unit's update surviving every CLOSE, RETRY waiting outside the mutex — on both region hosts.
- A coherent statement after another run unit's change reads ≤ 1 + depth + overflow pages (never the file).
- A `SHARING WITH READ ONLY` writer and an `INPUT` reader in another run unit: the reader never meets a half-written path (every
  statement of the writer is one step to it) and sees each WRITE at its next statement — for INDEXED here (PB3333 witnessed
  RELATIVE).
- An `INPUT SHARING WITH ALL OTHER` reader opened on a crashed file (page 2 rejected) reads the committed tree until a writable
  OPEN in another run unit fences the file, and page 2's tree from then on (2.2.1.12's last R6 row).
- The sequential organization's I/O pattern is unchanged: a `SHARING WITH READ ONLY` sequential writer still buffers (no
  per-record flush) and its reader does not re-seek per READ — `AdmitsAnotherWriter`'s callers kept.
- Two run units loading one file through ALL OTHER each write a bounded page count per statement (the quadratic case of PB3330).

## Unblocked (PB3334 landed through wave 1118, group A4)

Both organizations are on the engine and NO connector reaches the whole-store model: `IndexedConnector.WholeStore.cs` is
deleted with its `Load`/`Persist`/`ReadImage`/`Reload`/`StoreHolds`/`HostFaultObserver`, `KeyedStore` (in
`KeyedStoreTable.cs`) is the one engine handle `RelativeStore` and `IndexedStore` derive from, and the keyed lifecycle is
`KeyedConnector`'s (kb/Work PB2753). What is left for this group: `RecordFraming`'s store-level shape (`ComposeStore`,
`DecodeStore`, `ReadHeader`, `MaxStoreBytes`, `HeaderBytes`, `OrdinalSlots`, the gap codec, the generation probe), whose
remaining callers are `SequentialConnector`'s keyed-store check and tests (`FileBoundaryTests.MaxStoreBytes_*`,
`FrameDecoderDriftTests`, the format-5 fixtures of `RelativeEngineTests`/`IndexedEngineTests`, which can write a
format-5 file through a fixture instead); `KeyedStoreTable` → `StoreTable`; `KeyedConnector.CompleteStatement`, now a
pass-through hook; the whole-store ban drift test; DOC-A.1-75 (its statement-mutex sentence describes both organizations on the engine since PB3334; what is left is the StoreTable wording).
