# PB1006 — RETIRED — the premise contradicts §7.2.1 Step 1

## Retired (wave 54, 2026-09-22)

The repro reproduces on the implementer's own build (`p5_srcif.cob(9,12): error COBOL0001`), but the behaviour is
the one the standard REQUIRES. §7.2.1 (text manipulation), Step 1 — `OK §7.2.1` on `cite.py --check`:

> Lines that appear in the false path of an IF or EVALUATE directive, including library text identified in COPY
> statements, may be omitted from the expanded compilation group. SOURCE FORMAT directives in the false path shall
> be processed to correctly interpret input lines.

(Its NOTE: "Recognition of true and false paths during logical conversion is neither required nor precluded.") So
the `>>SOURCE FREE` inside `>>IF V = 2` DOES switch the reference format of the following lines, and `p5_srcif`'s
sequence-numbered line, read as free form, is correctly rejected. The note read §7.3.16.4 GR2/GR3 ("omitted from
the resultant text") as if they settled the reference format; they answer which lines survive Step 2, while the
format is Step 1's, and Step 1 names this case. The normalizer running BEFORE conditional compilation is the
order §7.2.1 prescribes, not a defect.

The implementer first built the one-pass redesign the note asked for (the segmenter driven by the
conditional-compilation driver) and reverted it on finding §7.2.1 — the dispatch spec's "re-probe; a note that
does not hold is re-verdicted" outcome. The two rows the note claimed were never violated; they are re-verdicted
CONFORMS on `conformance:2002/pb1006_source_format_in_false_path`, whose L3 pins the Step-1 behaviour (a
false-path `>>SOURCE FREE` followed by a column-1 DISPLAY that compiles only in free form) so a later "fix" in the
note's direction goes red, with `conformance:negative/pb1006-source-format-false-path-below-2002` as its 1985 half.

## As filed

## Repro — measured
`scratchpad/w49f/probe/p5_srcif.cob`: `>>SOURCE FIXED`, `>>DEFINE V AS 1`, `>>IF V = 2`, `>>SOURCE FREE`, `>>END-IF`,
then a fixed-form sequence-numbered line → `p5_srcif.cob(9,12): error COBOL0001: cannot parse construct near 'DISPLAY'`.

## The rule
`OK  §7.3.16.4 2)` — "If constant-conditional-expression-1 evaluates to TRUE, all lines of text-1 are included in the
resultant text and all lines of text-2 are omitted from the resultant text." (GR3 is the FALSE mirror.) An omitted line
is not in the resultant text, so its >>SOURCE directive has no effect.

## What the fixer owes
Evaluate conditional compilation and the reference-format switch in ONE pass in source order (the format directive is
itself subject to the >>IF state), or make the normalizer consult the >>IF state it would otherwise precede. Golden for
>>SOURCE and for >>PUSH/>>POP SOURCE in an omitted branch, both forms.
