**Wave kind:** defect-for-fix-lane. **Model:** the fix lane's routing (`model_rules.json`).

**Sites:**
- `src/Cobol.Net.Frontend/Grammar/Core/CobolIO.g4:477-489` (readStatement `READ (fileName | FILE fileName)`)
- `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/SequentialIoBinder.cs:153-163` (DeclinedFilePhrase: WRITE/REWRITE only)

**Rule it breaks:** ISO §14.9.30.2 (rendered, PDF p722): both READ formats print `READ file-name-1 …` with no FILE phrase; §5.2.1 makes the printed format the only admitted spelling. The `{ record-name-1 | FILE file-name-1 }` choice belongs to WRITE (§14.9.51.2) and REWRITE (§14.9.35.2) only, where Annex A.4.13 declines it and SequentialIoBinder.DeclinedFilePhrase refuses it by name (COBOLNET1706). The grammar's own comment at CobolIO.g4:592-596 says the FILE arm exists so the binder can SEE it and refuse it; on READ no binder looks (no `FILE()` read anywhere in src/Cobol.Net.Compiler).

**Scenario:** Measured with the built compiler (readStatement unchanged since the pin): a LINE SEQUENTIAL file F1 and `READ FILE F1 RECORD AT END DISPLAY "EOF" END-READ.` compiles exit 0 at --std 2023 with no diagnostic, even under --flag-extensions, and --run prints the record. The program fails on any conforming implementation and WiseOwl COBOL never says so. The FILE arm is the copy-pasted shape of WRITE/REWRITE's two-arm head (feedback_two_arm_dispatch: the arm was added in three places and refused in two).

**Measured how:** R2 batch finding `lexer-grammar-2--code--f1#2` (pair lexer-grammar-2--code), read in the pinned tree at 8be23006851a; skeptics rule upheld, scenario upheld, site upheld.

**Spec:** §14.9.30.2 "<u>READ</u> file-name-1 RECORD [ <u>INTO</u> identifier-1 ]" (`cite.py --check` passed at collection)

**Target:** readStatement is `READ fileName readDirection? RECORD? …` — the `| FILE fileName` alternative deleted, so `READ FILE F1` is a parse error at FILE at every edition (or, if a named refusal is wanted, it routes to the same ClosedFormatPass/COBOLNET1970 shape, never accepted). A negative golden per edition, and the sibling sweep confirmed only WRITE and REWRITE carry the arm legitimately (both already refused).

**Design reference:** §8.4.

**Landed (wave 1077 G).** Re-probed on this build first: `READ FILE F1 RECORD AT END ... END-READ` on a LINE
SEQUENTIAL file compiled exit 0 at --std 2023 (and under --flag-extensions) and `--run` printed the record. The
`| FILE fileName` alternative is deleted from `readStatement` (`src/Cobol.Net.Frontend/Grammar/Core/CobolIO.g4`),
so FILE, a reserved word that is never a fileName, is `error COBOL0001: unexpected 'FILE'` at every --std
(§14.9.30.2 prints `READ file-name-1` in both formats; §5.2.1 admits a general format's words "in the sequence
given in the general format"). A parse error rather than a named refusal: the arm is no optional element to
decline (Annex A.4.13 names WRITE and REWRITE only), and the error points at the unprinted word. Witness:
`tests/conformance/negative/pb2728-read-file-unprinted` (`reject-at: 85 2002 2014 2023`), added to
FMT-14.9.30.2's test-ref. Sibling sweep of every I-O statement head in `CobolIO.g4`: FILE before a file-name
remains only in WRITE and REWRITE (declined, COBOLNET1706) and DELETE FILE (§14.9.10.2 Format 2, printed);
OPEN, CLOSE, START, DELETE, UNLOCK, RETURN and RELEASE take a bare name. `docs/COBOLNET_FILES_DESIGN.md` (the
declined-elements section) records why READ has no FILE arm. The unused `name` local in
`SequentialIoBinder.BindRead` went in the same change.
