# PB607 — OPEN — the audit skips the file kind where a citation matters most

Found 2026-09-05 by the `PB598` implementer, which made the same class of error twice in one session and was
caught by the tool once: `kb/Work/PB594.md:87`'s `§8.8.4.1.2` (a clause that does not exist — §8.8.4.1 has no
subclauses; the relation-condition alphabet rule it meant is §8.8.4.2.7, `cite.py --check 8.8.4.2.7
"Comparison is made with respect to the collating sequence of characters specified for the current alphanumeric
program collating sequence"` → OK) was reported as `[PHANTOM]`, while its own first-draft golden header
citing `8.8.4.1.4` for space-extension (correct: §8.8.4.2.7 item 2) was not. Re-derived on this tree for this
note.

## The two gaps

1. **File kinds.** `audit_code_citations.py` scans `src/`, `docs/`, `kb/` and the C# tests (2846–3076 files in
   today's runs) but not the COBOL sources under `tests/conformance/**` (`.cob`), whose header comments are
   where every golden records the derivation of its expected values — the one place a wrong clause number is
   copied by the next writer, refuter and adjudicator.
2. **Spellings.** The phantom scan keys on the `§`-prefixed form; a bare `8.8.4.1.4` inside a COBOL comment
   (where `§` is uncommon and the corpus convention is `ISO 8.8.4.2.7` / `(ISO §…)`) is not a citation to it.

And one consequence already measured: PB594 reached main with the phantom and `--check` was red at the base of
the next four worktrees; the golden lander that filed it reported both audits at zero — either its audit ran
before the note was written or it ran on a scope that did not include `kb/Work`. That ordering is the second
finding: a lander's audit must run after its last write, on the tree it pushes.

## Fix shape

Extend the phantom scan to `tests/conformance/**/*.cob` (comment lines only — `*>` and column-7 `*`) and to bare
`N(.N)+` clause spellings that follow `ISO`, `§` or a rule-kind word (`GR`/`SR`/`AR`/`RV`/`FMT`); baseline the
current findings (PB476's pattern) so the gate reds only on growth; fire it once against a fixture golden with
`8.8.4.1.4` in its header. Pair with `PB591`/`PB597` (rule-ordinal existence) — one audit family, three blind
spots, and the corpus is the one they share. Add to the lander briefs: both audits run AFTER the last write of
the landing, and their output is quoted from that run.
