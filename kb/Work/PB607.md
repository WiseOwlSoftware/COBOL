# PB607 — OPEN — the audit skips the file kind where a citation matters most

Found 2026-09-05 by the `PB598` implementer, which made the same class of error twice in one session and was
caught by the tool once: `kb/Work/PB594.md:87`'s `§8.8.4.1.2` (a clause that does not exist — §8.8.4.1 has no
subclauses; the relation-condition alphabet rule it meant is §8.8.4.2.7, `cite.py --check 8.8.4.2.7
"Comparison is made with respect to the collating sequence of characters specified for the current alphanumeric
program collating sequence"` → OK) was reported as `[PHANTOM]`, while its own first-draft golden header
citing `8.8.4.1.4` for space-extension (correct: §8.8.4.2.7 item 2) was not. Re-derived on this tree for this
note.

## The two gaps

1. **File kinds.** `audit_code_citations.py` scans `src/`, `docs/`, `kb/` and the C# tests (2846–3076 files in
   today's runs) but not the COBOL sources under `tests/conformance/**` (`.cob`), whose header comments are
   where every golden records the derivation of its expected values — the one place a wrong clause number is
   copied by the next writer, refuter and adjudicator.
2. **Spellings.** The phantom scan keys on the `§`-prefixed form; a bare `8.8.4.1.4` inside a COBOL comment
   (where `§` is uncommon and the corpus convention is `ISO 8.8.4.2.7` / `(ISO §…)`) is not a citation to it.

And one consequence already measured: PB594 reached main with the phantom and `--check` was red at the base of
the next four worktrees; the golden lander that filed it reported both audits at zero — either its audit ran
before the note was written or it ran on a scope that did not include `kb/Work`. That ordering is the second
finding: a lander's audit must run after its last write, on the tree it pushes.

## Fix shape

Extend the phantom scan to `tests/conformance/**/*.cob` (comment lines only — `*>` and column-7 `*`) and to bare
`N(.N)+` clause spellings that follow `ISO`, `§` or a rule-kind word (`GR`/`SR`/`AR`/`RV`/`FMT`); baseline the
current findings (PB476's pattern) so the gate reds only on growth; fire it once against a fixture golden with
`8.8.4.1.4` in its header. Pair with `PB591`/`PB597` (rule-ordinal existence) — one audit family, three blind
spots, and the corpus is the one they share. Add to the lander briefs: both audits run AFTER the last write of
the landing, and their output is quoted from that run.

## Registrar verification 2026-09-06 — gap 1 is CLOSED (and was already closed when this note was written); gap 2 stands; a THIRD blind spot is the one that actually bit

Appended by the registrar while filing the PB741 lander's finding. **id PB766 was allocated for that finding and
is left UNUSED — this note owns it.** Everything below is measured on main `1e7b5085`.

### Gap 1 — "does not read `tests/conformance/**/*.cob`" — no longer true, and it was not true on 2026-09-05 either

The corpus was extracted into `scripts/spec/citation_corpus.py` by `9c08e6fe` *("Citation sweep: ~200 phantom
sites, a gate at zero, and the gate's own two blind spots")*, **2026-09-02 22:18 -0700**, an ancestor of HEAD —
three days BEFORE this note was written (2026-09-05 01:41). Measured membership today:

| corpus function | files | under `tests/` |
|---|---|---|
| `all_files()` | 3548 | **2122** (435 `.cs`, 1687 `.cob`) |
| `declaration_files()` | 1699 | **1687** (`tests/conformance/**/*.cob`) |
| `prose_files()` | 568 | 0 |

`audit_doc_citations.py:256` and `audit_code_citations.py:281` both scan `all_files()`;
`audit_code_citations.py:305` scans `declaration_files()`. `prose_files()` has **no direct caller** — it is only
a component of `all_files()`, so its `tests/`-free glob excludes nothing from either gate. Gap 1 should be struck
from this note's fix shape. ⚠ It is itself an instance of what CLAUDE.md rule 1 warns about: a true-when-written
claim carried forward without re-derivation. (The `--check` verdict line at the foot of a run already reports the
population — `"N files scanned for phantoms, M for construct agreement"` — so the number was one command away.)

### Gap 2 — the bare `N.N.N` spelling — STANDS, and is larger than stated

`audit_code_citations.py:70` `CITE = re.compile(r"§\s?(\d+(?:\.\d+)+)(?![a-z])")`, and the doc audit's
`PAT` (`:83`) and `POST` (`:93`) both anchor on `§` as well. Measured over `tests/conformance/**/*.cob`, comment
text only (`*>`), first segment 1–16, any `§`-prefixed form removed first: **1193 golden files carry 3745
clause-shaped references with no `§` at all.** Every one of them is outside every citation check.

### ⛔ The third blind spot — the one that let the PB741 sites through, and this note does not name it

`891973f7` corrected two sites that had carried the wrong clause since they were written:

- `tests/Cobol.Net.Tests.Unit/BoundaryImageChannelTests.cs:60` — pre-fix
  `AsImage() for an ordinary group (§8.8.4.2.3 SR2 — class alphanumeric)`
- `tests/conformance/2023/da5_table_sort_group_key.cob:13` — pre-fix
  `CLASS ALPHANUMERIC (8.8.4.2.3 SR2)`

The PB741 lander's stated cause — *"Neither citation audit could see them: they scan `src/` and `docs/`"* — **is
false**; membership-tested, `BoundaryImageChannelTests.cs` is in `all_files()` and `da5_table_sort_group_key.cob`
is in both `all_files()` and `declaration_files()`. The audits looked and still said nothing, for three separate
reasons:

1. **PHANTOM was correct to pass.** `cite.py --check 8.8.4.2.3 ""` → OK, §8.8.4.2.3 *Syntax rules* exists. The
   citation was **misfiled, not phantom** (the rule meant is §8.8.4.2.1 *General*, also OK).
2. **The misfiling rule had nothing to grip.** `audit_doc_citations.py` fires only on a **verbatim quoted
   fragment adjacent to the `§`**; both sites paraphrase. No quote, no check — at any path.
3. The `.cob` site additionally had no `§` (gap 2), so it never even produced a candidate.

So the operative defect is: **a citation whose clause EXISTS, is the WRONG one, and carries no verbatim quote is
invisible to every audit in every directory.** That is precisely the failure CLAUDE.md rule 1 names — *"its
quoted text is genuinely in the standard, and the clause NUMBER is never re-derived"* — in its commonest written
form, the paraphrase. [[PB591]] (a prose `§X GR<n>` reference) and [[PB597]] (a wrong GR/SR ordinal inside a
correct clause) are the adjacent halves of the same hole; this is the third and the widest.

### And a measured limit on the doc audit over the golden corpus specifically

`audit_doc_citations.py:77` defines `QUOTED` as a straight-or-curly-quoted run of 30–90 characters whose FIRST
character is `[a-z]` and which excludes the newline — so a matchable fragment must **start with a lowercase
letter** and fit on **one line**. Over `tests/conformance/**/*.cob`: 452
files carry a 30–90-character quoted fragment, **703 fragments, of which only 242 start lowercase** — the other
461 (66%) are uppercase CCVS-style comment prose and can never match, however correct or incorrect their
citation. The PB741 `.cob`'s own quote (`"COMPARED ACCORDING TO THE RULES FOR COMPARISON OF OPERANDS / IN A
RELATION CONDITION"`) is disqualified twice over: uppercase, and split across two comment lines.

### Amended fix shape

1. **Drop gap 1** — done, by `9c08e6fe`.
2. **Keep gap 2** as written: recognise a bare `N(.N)+` spelling that follows `ISO`, `§`, or a rule-kind word
   (`GR`/`SR`/`AR`/`RV`/`FMT`), in `*>` and column-7 comment text.
3. **Add the third**: the paraphrased citation. It cannot be checked by quote-matching, so it needs the other
   handle — the CONSTRUCT-agreement rule `audit_code_citations.py` already runs over `declaration_files()`,
   widened from "the definition-header convention" to "any comment naming a construct beside a clause". The
   module docstring records that running it over `src/**/*.cs` was ~95% false positives and was therefore
   declined; the golden headers are the corpus where the convention DOES hold, and they are already in scope.
4. Both audits already have a whole-file opt-out that is visible in the file and cannot rot silently —
   `MARKER = "audit-code-citations: names-phantoms"` (`audit_code_citations.py:112`) and
   `"audit-doc-citations: names-misfilings"` (`:105`), checked in the first 40 lines. **Any widening must reuse
   that marker, never a checked-in list of exempt sites** (CLAUDE.md rule 8, and this note's own
   `feedback_a_dead_lookup_is_also_unverified` posture).
5. `feedback_green_gates_arent_evidence` for each: restore `§8.8.4.2.3 SR2` into a fixture, watch `--check` go
   red, restore. And per [[PB476]], assert the POPULATION, not only the finding count — the verdict line already
   prints it.
