## 2026-09-04 — the LITERAL-SCREEN half landed with PB208 (landing train 2)

This note's first finding — "`ValidateTableValues` checks SUBSCRIPT GEOMETRY only and never calls the
literal screen" — is CLOSED as a mechanism. PB208 extracted the four inline format-1 checks into
`DataBinder.ScreenValueLiteral` and `ValidateTableValues` now calls it PER OCCURRENCE-LITERAL, storing what
it returns so the `--permissive` numeric rewrite reaches the emitter's per-occurrence `rawOverride` exactly
as it reaches `item.RawValue`. Landed in the same train, PB206 gave that funnel its size (now the
`ValueSubject` descriptor's `SizePositions`, PB598)
argument, and the lander threaded it through `ScreenValueLiteral` — `ValidateTableValues` computes the
ELEMENT's size once (`ValueSizePositions(subject, item.IsDynamicLength, item.IsAnyLength)`) and passes it —
so §13.18.63.3 SR4/SR5/SR10's size sentences now measure a format-2 occurrence literal too.
`ValueFormat2Tests.Format1AndFormat2_ScreenTheSameLiteralAlike` is the drift test that keeps it true: it
compares the two formats' VERDICT SETS over nine literal/picture pairs on both the strict and the
permissive axis, so a rule wired into only one lane reds there instead of shipping.

⛔ **This note stays `open`, and its `inventory_rows` are NOT re-verdicted here.** Where a row is covered by
the train's evidence, that is recorded below so this note's own implementer can verdict it rather than
