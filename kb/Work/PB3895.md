# PB3895 — national-items-displayed-as-utf-16-bytes--reverse-bytes: FUNCTION REVERSE of a national item reverses bytes (REVERSE(N"AB") is not N"BA")

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S4) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\national-items-displayed-as-utf-16-bytes--reverse-bytes.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\national-items-displayed-as-utf-16-bytes--reverse-bytes\`.

## Summary

Under `-std=cobol2014`, `FUNCTION REVERSE` of a national argument reverses the storage bytes. For N"AB" (bytes
`00 41 00 42`) it returns `42 00 41 00`, which is not N"BA" (`00 42 00 41`) and not any sequence of the argument's
characters. Class: wrong output. This is one of the mechanisms the harvest grouped under "national items displayed as
UTF-16 bytes": the fuzz programs fz00117, fz00526, fz03347, fz04502, fz04755, fz00270 and fz05912 (nights 3 to 5)
showed it as `J~I~H~G~F~` (NUL after each letter) where the other national lines show `~J~I...` (NUL before).

## Minimal test case

Free reference format (`-fformat=free`), 8 lines, written for this record.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. NREV.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 NAT PIC N(2) VALUE N"AB".
PROCEDURE DIVISION.
IF FUNCTION REVERSE(NAT) = N"BA" DISPLAY "EQUAL" ELSE DISPLAY "NOT EQUAL" END-IF
STOP RUN.
```

File: `E:\COBOL-coord\scratch\op\pb3838\records\national-items-displayed-as-utf-16-bytes--reverse-bytes.cob`.

## Environment

- `cobc (GnuCOBOL) 3.2.0`, Ubuntu package `gnucobol3 3.2-4build1`, WSL2 (Linux 6.18.54.1-microsoft-standard-WSL2 x86_64).

## Observed result

Compile exit code 0, with `-Wunfinished` warnings for USAGE NATIONAL (line 5) and national literals (lines 5 and 7).
Run exit code 0, output `NOT EQUAL`. A further probe (`work\national-items-displayed-as-utf-16-bytes\fprobe.cob`)
shows `FUNCTION LENGTH(FUNCTION REVERSE(N"1234"))` is 4 (the length is right) and that moving the result to a
`PIC N(5)` item still compares unequal to N"4321".

## Expected result (per ISO)

Output `EQUAL`.

- ISO/IEC 1989:2023 §15.78.1 (checked): "The REVERSE function returns a character string of exactly the same length as
  argument-1 and whose characters are exactly the same as those of argument-1, except that they are in reverse order."
  Its type table gives a national function for a national argument.
- §15.78.4 1) (checked): "If argument-1 is a character string of length n, the returned value is a character string of
  length n such that for 1 <= j <= n, the character in position j of the returned value is the character from position
  n - j + 1 of argument-1." The positions are national character positions; for N"AB" the result is N"BA".

Edition: unchanged since 2002. The 2009 committee draft for ISO/IEC 1989:2014 (CD 1.2, §15.73) carries the same type
table (National to National) and returned-value rule; Annex E of 2023 lists no change.

Edition as recorded by the adjudicator: 2014 (2002 feature; same rule in the 2009 CD §15.73). `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Class

GNUCOBOL-DEFECT: wrong output.

## Our compiler (WiseOwl)

WiseOwl COBOL (built from main 6ed90bd1c), `cobol nrev.cob --std 2014 --source-format free -o nrev.dll`, then
`dotnet nrev.dll`: compile exit 0, run exit 0, output `EQUAL`.

## Fix site (GnuCOBOL 3.2 source, read observationally)

`libcob/intrinsic.c`, function `cob_intr_reverse` (line 3819 in the 3.2 tree): the loop copies byte `size - i - 1` to
byte `i` over `srcfield->size` bytes. For a national field (`COB_FIELD_IS_NATIONAL`) the loop has to move two-byte
character units (and keep surrogate pairs together if UTF-16 surrogates are supported).

## Draft issue

**Title:** FUNCTION REVERSE of a national item reverses bytes (REVERSE(N"AB") is not N"BA")

**Body:**

Environment: GnuCOBOL 3.2.0 (Ubuntu gnucobol3 3.2-4build1), x86_64 Linux.

Steps: `cobc -std=cobol2014 -fformat=free -x nrev.cob && ./nrev` with

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. NREV.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 NAT PIC N(2) VALUE N"AB".
PROCEDURE DIVISION.
IF FUNCTION REVERSE(NAT) = N"BA" DISPLAY "EQUAL" ELSE DISPLAY "NOT EQUAL" END-IF
STOP RUN.
```

Observed: `NOT EQUAL`. DISPLAY of the result shows each NUL byte after its letter (`B\0A\0`), where a national item
holding N"BA" displays as `\0B\0A`.

Expected: `EQUAL`. ISO/IEC 1989:2014 (2023 §15.78.4 rule 1): "the character in position j of the returned value is the
character from position n - j + 1 of argument-1"; for a national argument the function is national and the positions
are national character positions.

Cause: `cob_intr_reverse` in libcob/intrinsic.c reverses `srcfield->size` bytes regardless of the field's class.
