# PB901 — OPEN — a claim in a doc-comment is not evidence, and it looks exactly like evidence

Source: the `PB436` report, "New defects" item 2.

## The proof that it happens

`PerformVaryingDifferentialTests`'s class doc-comment asserted *"the spec's exact reset/augment ordering"*
for as long as the emitter implemented the opposite ordering (PB436 §1). Every test in the class passed
throughout, because every test in it compared COBOL.NET against the LEGACY ORACLE, which had the same wrong
ordering. The doc-comment is the only thing in the file that mentions the standard, and it is the only thing
nothing checks.

PB436's change set repaired that one class. **It is a repeatable shape, not an incident** — which is what
makes it a register item rather than a paragraph in a report.

## The audit this note asks for

For each class under `tests/Cobol.Net.Tests.Conformance/*DifferentialTests.cs` whose doc-comment names a
SPEC behaviour (a §, a rule ordinal, or a sentence about what the standard requires), does ANY test in that
class assert something other than `AssertSameAsLegacy` / `DifferentialGolden.Assert`?

* **No** → the doc-comment is a claim about the standard backed only by agreement with a frozen oracle.
  Either add a spec-derived assertion or rewrite the comment to say what the class actually measures.
* **Yes** → fine; record which test carries the spec claim.

~35 classes. The audit is mechanical enough to be a script, and a script is the right answer: a one-time
sweep re-rots the moment the next differential class is added. The natural home is beside
`audit_evidence_supersession.py`.

## Why `kind: analysis` and not `defect`

Nothing in the compiler is wrong. What is wrong is that a body of tests reads as spec coverage and is not,
which is a measurement gap (memory `verdict_evidence_invariant`, `green_gates_arent_evidence`). The output
of the analysis is a list, and whatever it finds becomes defects.

## Relation to PB900

Same family, different artefact: PB900 is a citation in CODE that no audit reads; PB901 is a claim in a TEST
that no audit reads. One implementer building citation/claim audits takes both.
