# PB1476 — OPEN

## The rule (every citation re-run by the registrar through `cite.py --check`)

> Any other definition of the name is subordinate to a type declaration entry for which the type-name is not referenced in any TYPE clause in the source unit

`python scripts/spec/cite.py --check 8.4.2.2.1 "…"` → `OK  §8.4.2.2.1 4)  (General)`

## Refuter evidence — row `SR-8.4.2.2.1-4` (PARTIAL)

PARTIAL — The exemption holds only while the type-name is 'not referenced in any TYPE clause in the source unit'. A TYPE clause inside ANOTHER TYPEDEF (itself unreferenced) is still a TYPE clause in the source unit, so the type's members lose the exemption and an unqualified reference must be diagnosed as ambiguous. The implementation keys the lapse on the clone reaching the name index (only a TYPE clause on a real data item puts it there), so it keeps exempting a type referenced only from another type declaration. The unreferenced half and the referenced-by-a-data-item half conform (adjudicator a1/a2; my t2 with the TYPE clause in LOCAL-STORAGE correctly lapses with COBOLNET1639).

**Code site.** src/Cobol.Net.Compiler/Binding/DataBinder.cs#BindEntries (TYPEDEF root -> RegisterTypeDecl, kept off Roots and ByName, ~line 834); src/Cobol.Net.Compiler/Binding/DataBinder.cs#QualifiedCandidates

## What the fixer owes

Record 'type-name referenced by a TYPE clause anywhere in the source unit' as a property of the TypeDecl (set by every TYPE clause, template or not) and key the lapse on it (DataBinder.BindEntries ~834, QualifiedCandidates). Negative golden: TYPEDEF T1 with 05 X, TYPEDEF T2 with 05 R TYPE T1, 01 G with 05 X, DISPLAY X → COBOLNET1639; keep a1/a2/t2 as positives.
