# PB3876 — call-missing-program-runs-both-exception-branches: -std=cobol2014: NOT ON EXCEPTION after "ON EXCEPTION DISPLAY ..." in a CALL is attached to the DISPLAY, so a failed CALL runs both branches and a successful CALL runs neither

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S1) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\call-missing-program-runs-both-exception-branches.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\call-missing-program-runs-both-exception-branches\`.

## Summary

In `CALL ... ON EXCEPTION DISPLAY "x" NOT ON EXCEPTION DISPLAY "y" END-CALL`, cobc 3.2 under `-std=cobol2014`
attaches the NOT ON EXCEPTION phrase to the device-format DISPLAY inside the ON EXCEPTION phrase, not to the CALL.
Two wrong results follow from that one parse: when the called program is missing, both "x" and "y" are displayed (the
night's observation: the DISPLAY succeeds, so its own NOT ON EXCEPTION runs); when the call succeeds, "y" is never
displayed (the CALL has no NOT ON EXCEPTION phrase left). The night's description ("CALL of a missing program runs
both branches") is the visible half; the call itself and the program-not-found handling are correct. With
`END-DISPLAY` after the inner DISPLAY, or with an ON EXCEPTION imperative statement that is not a DISPLAY
(`CONTINUE`, `MOVE`), cobc gives the right result. ISO's device-format DISPLAY has no exception phrases, so a NOT ON
EXCEPTION there can only belong to the CALL; GnuCOBOL accepts ON EXCEPTION / NOT ON EXCEPTION on a device DISPLAY as an
extension in every dialect, including `-std=cobol2014`, and that extension changes the meaning of a conforming program.

## Minimal test case

Free reference format (`-fformat=free`), `records/call-missing-program-runs-both-exception-branches.cob` (`SUBOK` is a
contained program; `NOSUCHPG` does not exist):

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. CALLEXC.
PROCEDURE DIVISION.
    CALL "NOSUCHPG"
      ON EXCEPTION DISPLAY "1 ON EXCEPTION"
      NOT ON EXCEPTION DISPLAY "1 NOT ON EXCEPTION"
    END-CALL
    CALL "SUBOK"
      ON EXCEPTION DISPLAY "2 ON EXCEPTION"
      NOT ON EXCEPTION DISPLAY "2 NOT ON EXCEPTION"
    END-CALL
    STOP RUN.
IDENTIFICATION DIVISION.
PROGRAM-ID. SUBOK.
PROCEDURE DIVISION.
    GOBACK.
END PROGRAM SUBOK.
END PROGRAM CALLEXC.
```

## Environment

- `cobc (GnuCOBOL) 3.2.0`, Ubuntu package `gnucobol3 3.2-4build1`, WSL2 Ubuntu on Windows 11.
- `cobc -std=cobol2014 -fformat=free -x -o callexc callexc.cob && ./callexc`
- `-Wall` adds no diagnostic; the default dialect (`cobc -fformat=free -x`) gives the same output.
- Generated C inspected with `cobc -std=cobol2014 -fformat=free -C`.

## Observed result

```
1 ON EXCEPTION
1 NOT ON EXCEPTION
```
exit 0. Nothing is displayed for the second CALL, which succeeds.

Control program `var.cob` (work directory): with `ON EXCEPTION CONTINUE` a successful CALL displays its NOT ON
EXCEPTION text; with `ON EXCEPTION DISPLAY "..." END-DISPLAY` both the successful and the failing CALL take the right
branch. The generated C for the failing case places the second DISPLAY under `if (!cob_glob_ptr->cob_exception_code)`
directly after the first DISPLAY, inside the program-not-found branch, and emits nothing after a successful call.

All five night witnesses reproduce (probe-n3-B2-prog: `EXC-1`, `OK-1`, `EXC-2`, `OK-2`; n3-fz00976, n3-fz04470,
n4-fz01724, n4-fz04544: each ON EXCEPTION text followed by its NOT ON EXCEPTION text), exit 0.

## Expected result (per ISO)

ISO/IEC 1989:2023, all checked with `scripts/spec/cite.py --check`; the DISPLAY general format was read from the
rendered PDF page (printed page 610), not the transcription:

- §14.9.11.2 Format 1 (device): `DISPLAY {identifier-1 | literal-1} ... [UPON mnemonic-name-1] [WITH NO ADVANCING]
  [END-DISPLAY]` — no ON EXCEPTION or NOT ON EXCEPTION phrase. Only Format 2 (screen, `DISPLAY screen-name-1`) has
  them. §14.9.11.1: "The device format of the DISPLAY statement causes data to be transferred to a hardware or
  software device in the operating environment."
- §14.5.3.3: "Any phrase encountered is the next phrase of the most-recently preceding unterminated statement with
  which that phrase may be syntactically associated." A device DISPLAY cannot take NOT ON EXCEPTION, so the phrase
  belongs to the CALL.
- §14.5.1: "Wherever 'imperative-statement' appears in the general format of a statement, 'imperative-statement'
  refers to one or more imperative statements ended either by a separator period or by any phrase associated with
  that general format." — NOT ON EXCEPTION ends imperative-statement-1 of the CALL.
- §14.9.4.4 GR 3) h) 1.: "If the exception condition is any of the EC-PROGRAM or EC-EXTERNAL exception conditions and
  an ON EXCEPTION phrase is specified in the CALL statement, control is transferred to imperative-statement-1. If
  control is returned from imperative-statement-1, control is then transferred to the end of the CALL statement."
- §14.9.4.4 GR 3) i): "If the program was successfully called, after control is returned from the called program the
  ON EXCEPTION phrase, if specified, is ignored. ... otherwise, control is transferred to the end of the CALL
  statement or, if the NOT ON EXCEPTION phrase is specified, to imperative-statement-2".

Expected output: `1 ON EXCEPTION` then `2 NOT ON EXCEPTION`, exit 0.

Edition: the device-format DISPLAY without exception phrases, the scope rules of 14.5 and the CALL exception phrases
are all in 2014 as in 2023; Annex E of the 2023 standard lists no change to any of them, so the result is the same
under the 2014 edition `-std=cobol2014` claims.

Edition as recorded by the adjudicator: 2014. `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Class

Wrong output on conforming source (a vendor extension, exception phrases on a device DISPLAY, applied under the strict
`-std=cobol2014` and changing which statement a phrase belongs to).

## Our compiler (WiseOwl)

`cobol.exe callexc.cob --std 2014 --source-format free -o callexc.dll`, `dotnet callexc.dll`: `1 ON EXCEPTION`,
`2 NOT ON EXCEPTION`, exit 0. On the night witnesses WiseOwl prints only the ON EXCEPTION text for each missing
program.

## Fix site (GnuCOBOL 3.2 source, read observationally)

- `cobc/parser.y`, rule `display_body`, alternative `screen_or_device_display _common_exception_phrases` (line 13205):
  exception phrases are accepted after any DISPLAY, device or screen, with no dialect check.
- `cobc/parser.y`, rules `_common_exception_phrases`, `_common_on_exception`, `_common_not_on_exception` (lines
  17993-18030), whose empty alternatives carry `%prec SHIFT_PREFER`, so a NOT ON EXCEPTION after the inner DISPLAY is
  shifted into the DISPLAY rather than ending it.
No `config/*.conf` option governs exception phrases on a device DISPLAY. A fix: under dialects that do not have the
extension, do not offer the exception phrases after a device DISPLAY (a dialect option, `ok` for the default and
vendor dialects), so the phrase reduces to the enclosing CALL; or, more narrowly, do not attach a NOT ON EXCEPTION to a
device DISPLAY nested in another statement's exception phrase.

## Draft issue

**Title:** -std=cobol2014: NOT ON EXCEPTION after "ON EXCEPTION DISPLAY ..." in a CALL is attached to the DISPLAY, so a failed CALL runs both branches and a successful CALL runs neither

**Body:**

Environment: GnuCOBOL 3.2.0 (Ubuntu `gnucobol3 3.2-4build1`), Linux x86_64.

Steps: save as `callexc.cob` and run `cobc -std=cobol2014 -fformat=free -x -o callexc callexc.cob && ./callexc`.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. CALLEXC.
PROCEDURE DIVISION.
    CALL "NOSUCHPG"
      ON EXCEPTION DISPLAY "1 ON EXCEPTION"
      NOT ON EXCEPTION DISPLAY "1 NOT ON EXCEPTION"
    END-CALL
    CALL "SUBOK"
      ON EXCEPTION DISPLAY "2 ON EXCEPTION"
      NOT ON EXCEPTION DISPLAY "2 NOT ON EXCEPTION"
    END-CALL
    STOP RUN.
IDENTIFICATION DIVISION.
PROGRAM-ID. SUBOK.
PROCEDURE DIVISION.
    GOBACK.
END PROGRAM SUBOK.
END PROGRAM CALLEXC.
```

Observed: `1 ON EXCEPTION`, `1 NOT ON EXCEPTION`; nothing for the second CALL. Exit 0, no diagnostic (also with
`-Wall`).

Expected: `1 ON EXCEPTION`, `2 NOT ON EXCEPTION`. In ISO/IEC 1989:2014 and 2023 the device-format DISPLAY (2023
14.9.11.2 format 1; the DISPLAY statement is 14.9.10 in the 2014 numbering) has no ON EXCEPTION / NOT ON EXCEPTION
phrase, and 14.5.3.3 associates a phrase with the most recently
preceding unterminated statement "with which that phrase may be syntactically associated", which here is the CALL.
GnuCOBOL accepts exception phrases on a device DISPLAY as an extension in every dialect, and the parser
(`display_body` -> `screen_or_device_display _common_exception_phrases`, `%prec SHIFT_PREFER` in
`_common_not_on_exception`) shifts the NOT ON EXCEPTION into the inner DISPLAY. Adding END-DISPLAY after the inner
DISPLAY gives the right result. Suggest gating exception phrases on a device DISPLAY by a dialect option, not allowed
under the ISO dialects, so the phrase reaches the CALL there. `config/cobol2014.conf` already sets
`accept-display-extensions: unconformable`, which does not gate these phrases today but is the natural option to
reuse.
