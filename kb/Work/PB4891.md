# PB4891 - the binary64-ness of a nested selection's returned item is a run-time fact CobolExact carries no mark for

**What the report says (the reviewer's words).** R1-2 LEAD (low): `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/IntrinsicRenderer.cs:1092`
Binary64 flags read `NumX.Real`, and a nested exact-lane selection is not Real although it returned a float item's content;
`MEDIAN (FUNCTION MAX (F M2) M)`: DISPLAY 0.3, COMPUTE 0.30000000000000000277. Left for the clerk: needs a run-time binary64 mark
on `CobolExact`, a redesign beyond that slice. The implementer adds: "its root (the binary64-ness of a selection's returned item
is a run-time fact CobolExact carries no mark for) is shared with nothing else."

**Where it stands on main.** The report's `:1092` is a line of the PB4859/PB4860 branch (`worktree-wf_9707cc12-e4e-40`,
head b6b906bf17), which adds `FunctionValueField.OfBinary64` and is not on `origin/main` at the time of filing (no
`OfBinary64` in `src`); on main the flags are read by `IntrinsicRenderer.AnyFloatItemArgument` and `AllRealArguments`
(both `Landed(x).Real`), the predicates the report names. Re-probe once PB4859 has landed.

**Not probed here.** The clerk reproduced nothing.

**Sites:** `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/IntrinsicRenderer.cs` (`IntrinsicRenderer.AnyFloatItemArgument`, `IntrinsicRenderer.AllRealArguments`).

**Fix (landed, wave 20261905).** Re-probed on dec152346c (PB4859 landed): `DISPLAY MEDIAN (FUNCTION MAX (F M2) M)` showed 0.3 and
`COMPUTE R` stored 0.30000000000000000277; so did MIN (F M) and an odd MEDIAN (F M2 N) as the nested selection, and
`MEDIAN (MEDIAN (F M) N)` stored 0.49999999999999999444 where DISPLAY showed 0.5. Root: the binary64-ness of a value the exact lane
carries was a compile-time list of the WRITTEN operands' kinds (`IntrinsicRenderer.Binary64FlagList`), and which argument a nested
selection returns is a run-time fact. Now `CobolExact` carries the mark itself (`CobolExact.TryBinary64`: `FromBinary64` marks a float
item's content, `FromApproximation` already remembered its double; a selection returns the value whole and `Negate` and `WithPrecision`
keep it; every operation that forms a new value drops it), `CobolIntrinsics.MedianExact` and `MedianWhole` are one body
(`CobolIntrinsics.Median`) that reads the two middles' marks, `MedianBinary64Exact` and the renderer's flag list are deleted, and
`FunctionValueField.OfExact (value, mode)` describes a marked value as the binary64 temporary, so DISPLAY of
`MEDIAN (- FUNCTION MAX (F M2) 1)` (an exact-lane negation) shows 0.45 as COMPUTE stores 0.45000000000000001110 (the mark made
COMPUTE right first, and DISPLAY then showed the exact mean). Golden
`pb4891_even_median_of_a_nested_selection_of_a_float_is_the_binary64_mean` plus its `_below_2002` refusal.
