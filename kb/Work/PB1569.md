# PB1569

Found 2026-09-24 by the golden-lane-2 misc-p34 refuter on pin f0d582ccd; **re-probe first**. Repro:
`<scratchpad 9db39f61…>\gl\run\misc-p34-refute\f.cob` → prints `01`, expected `02`.

Rule: §13.18.57.4 GR1 drops the type's own alignment and GR2 d) applies the alignment of a level-1 item; per §8.5.1.6.3 a
bit group following a same-level bit item would start at the next BIT, but a level-1 bit group starts at the first bit of
a BYTE. (cite.py --check both before quoting.)

Fix: the TYPE expansion must compute the expanded subject's offset with level-1 alignment (the layout pass, not the
TYPE copier); sweep SAME AS (§13.18.49) for the same alignment question. When fixed, GR-13.18.57.4-2 gets a d) leg
(`BLR=02`) added to the golden-lane draft `2002/l1c34_…type…` (misc-p34), which today pins a)–c) only.

## Landed (wave 59 M)

Re-probed on cdb084309: `f.cob` printed `BLR=01`. Root: GR2 d) was modelled nowhere — `CopyEntryDescription`'s
TypeSubject scope withheld the template's own alignment (GR1) but nothing gave the subject the level-1 alignment
d) requires, so `BitLayout.SharesByteWith` let a group-typed bit subject continue its same-level predecessor's byte.

- `DataItem.AlignedAsLevelOne` (DescriptionCopyKind.Alignment) — set by `ExpandType` when the type is a group; carried
  by SAME AS (§13.18.49.4 GR1 re-states data-name-1's description, TYPE clause included) and by a reproduced TYPEDEF
  member; read ONLY by `BitLayout.SharesByteWith`, as a second conjunct beside ALIGNED. It aligns the subject's first
  bit, not each occurrence (no GR2-of-ALIGNED analogue in §13.18.57.4).
- SIBLING ARM (same root — a placement walk not derived from the one predicate): `BitLayout.RunsOf` continued a run on
  "same level" alone, so the image packer (PhysicalModel / GroupImageCodec) packed an ALIGNED member into its
  predecessor's byte while ExtentBits counted a fresh byte — `05 F PIC 1 USAGE BIT. 05 G PIC 1 USAGE BIT ALIGNED.`
  moved to a 2-byte bit view read bit 9 = 0, and a group MOVE back left G = 0. RunsOf now continues a run only where
  SharesByteWith holds, which the TYPE fix needed as well.
- SAME AS swept: §13.18.49.4 has no d); a SAME AS of a plain level-1 bit group is NOT re-aligned (pinned BLR3=01).
  No other clause in the standard places a subordinate "as though it were a level 1 item" (grep of specs/ISO_COBOL.md).

Witnesses: `2002/pb1569_type_subject_level1_bit_alignment` (+ negative `pb1569-type-bit-group-below-2002`) and the
golden-lane draft `2002/l1c34_type_group_hierarchy` with its d) leg (BLR3=02); GR-13.18.57.4-2 re-verdicted CONFORMS.
