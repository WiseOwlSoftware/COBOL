# PB4559 — initialize-to-value-category-list-refused: -std=cobol2014: INITIALIZE ... ALPHANUMERIC ALPHABETIC TO VALUE (more than one category-name) is refused: 'unexpected ALPHABETIC, expecting VALUE'

Filed 2026-11-03 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-batch-3000-20261103`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

Under `-std=cobol2014`, cobc 3.2 accepts only one category-name before TO VALUE in the INITIALIZE statement. The standard's category-name list is enclosed in choice indicators, so one or more categories may be written, each at most once, in any order. `INITIALIZE R ALPHANUMERIC ALPHABETIC TO VALUE` is refused with a syntax error. Class: rejects legal source. Fuzz programs: fz01901 (night fuzz-batch-3000-20261103, slice D4).

## Minimal test case

Free reference format.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. INI1.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 R.
   05 X1 PIC X(2) VALUE "AB".
   05 A1 PIC A(2) VALUE "CD".
   05 N1 PIC 9(2) VALUE 12.
PROCEDURE DIVISION.
    MOVE "zz" TO X1
    MOVE "yy" TO A1
    MOVE 99 TO N1
    INITIALIZE R ALPHANUMERIC ALPHABETIC TO VALUE
    DISPLAY "[" R "]"
    STOP RUN.
```

## Environment

`cobc (GnuCOBOL) 3.2.0`, WSL2 Ubuntu x86_64. Compiled with `cobc -x -free -std=cobol2014 -o p ini1.cob`; when an executable is produced it is run as `./p` under `timeout 10`. Control: `INITIALIZE R ALPHANUMERIC TO VALUE` compiles.

## Observed result

Compile, exit code 1; no executable is produced (the default dialect, `cobc -fsyntax-only -free ini1.cob`, gives the same error):

```text
ini1.cob:13: error: syntax error, unexpected ALPHABETIC, expecting VALUE
```

## Expected result (per ISO)

The program is legal and prints `[ABCD99]`: X1 and A1 (categories alphanumeric and alphabetic) are set to their VALUE, N1 (numeric, not named) is not a receiving operand and keeps 99.

- §14.9.20.2 (checked): the general format `[ { ALL | category-name } TO VALUE ]`, where category-name is the list ALPHABETIC ... PROGRAM-POINTER enclosed in braces WITH choice indicators (rendered from the printed page, 2023 PDF page 667; the 2009 committee draft that became the 2014 edition, printed page 490, prints the same choice indicators).
- §5.2.6.4 (checked): "When enclosed by braces, one or more of the alternatives contained within the choice indicators shall be specified".
- §14.9.20.4 2) (checked): "If ALL is specified in the VALUE phrase it is as if all of the categories listed in category-name were specified": category-name is a list.

Edition: 2014. The 2009 committee draft of the 2014 standard (CD 1.2, 14.9.19.1, printed page 490) prints the same format, with the category-name list enclosed in braces with choice indicators.

## Our compiler

WiseOwl COBOL (fresh judge, `--std 2014 --source-format free`): compiles with no diagnostic; the run prints `[ABCD99]`, exit code 0.

## Fix site

`cobc/parser.y`, rule `_initialize_value`: the alternative is `initialize_category _to VALUE` with a single `initialize_category`; there is no list. (`initialize_category` also omits BOOLEAN and the pointer categories, a comment in the rule says so.)

## Vetting (2026-11-04)

Verdict SOUND (to be reported); the refuter agrees. The category-name list of INITIALIZE is enclosed in braces with choice indicators (rendered 2023 PDF p667 and 2009 CD p512), so one or more categories are legal in the VALUE phrase and in REPLACING (5.2.6.4, 14.9.20.4 2), cite.py --check OK). 3.2.0 and 3.3-dev refuse `ALPHANUMERIC ALPHABETIC TO VALUE` ("unexpected ALPHABETIC, expecting VALUE"; parser.y takes a single initialize_category), and no ticket matches. The draft should add the REPLACING form. The vetting also found a second, wrong-output defect on the same statement, filed as PB4578.
