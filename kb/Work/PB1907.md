# PB1907 — what WiseOwl COBOL does where the standard says "undefined"

## The owner's direction (2026-10-01, verbatim)

"What I would like is to determine what the best/appropriate/current behavior we provide judged against what other
implementations do in each case, document our behavior as what we do in these undefined cases, then produce a golden
that validates our now documented behavior doesn't drift over time."

## Why these six rows exist

Six inventory rows are verdicted CONFORMS and owe a witness, and golden-lane batch gl4 (DEVLOG 1834) found nothing a
golden could pin to the STANDARD, because the standard defines no result. Each rule is listed in Annex A.2, and §4.4
says a run unit that allows such a situation to happen "is a conforming run unit, although the resultant execution is
not defined by standard COBOL" (`cite.py --check 4.4 "A COBOL run unit that allows these situations to happen is a
conforming run unit"` → OK, §4.4 2)).

| Row | Rule | Annex A.2 item |
|---|---|---|
| GR-14.6.10-1 | operands not described by the same data description entry overlap: result undefined | 36 |
| GR-14.9.22.4-13, -18, -21 | INSPECT: an operand occupies the same storage as the INSPECT or tallying identifier | 21 d), e), f) |
| GR-14.9.48.4-18 | UNSTRING: overlapping sending, delimiter, count, pointer or tallying operands | 61 |
| GR-14.9.51.4-13 | WRITE: bytes beyond the end of record-name-1 are undefined | 64 |

## What the owner decided is the closing shape

The behavior is implementor-defined in effect, so it is a documented implementor choice (CLAUDE.md rule 1: ISO where
it controls, otherwise GnuCOBOL, otherwise IBM Enterprise COBOL or Micro Focus; that precedence settles latitude only).
Per case: (1) measure what WiseOwl COBOL does today, (2) survey GnuCOBOL (the tarball `tests/external/gnucobol-3.2.tar.xz`
carries the libcob source; no `cobc` is installed here), IBM Enterprise COBOL and Micro Focus, (3) pick the behavior
and write it into `docs/CONFORMANCE.md` as what we do in the undefined case, (4) land a golden pinning the documented
behavior so it cannot drift, citing the rule and the A.2 item, (5) record the verdict with `record_verdicts.py`. This
is NOT a section 8 owner-signed "no observable obligation" derivation; the owner chose to document and pin instead.
