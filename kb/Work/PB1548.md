# PB1548 — LANDED (wave 59)

## What is established (checked)

`python scripts/spec/cite.py --check 11.3.3 "Object-class-name-2 shall be the name of a class specified in the
REPOSITORY paragraph"` → OK §11.3.3 2). COBOLNET0821 is raised at `src/Cobol.Net.Compiler/Oo/OoClassTable.cs:439`
exactly when the INHERITS name does not resolve through the REPOSITORY funnel (§8.4.6.4, kb/Work PB365). So the
refusal is **correct** for a class whose REPOSITORY does not declare `CLASS BASE` — the lane's drafts must be
re-checked for that before anything is called a defect (§16.2 specifies the standard BASE class and its
BaseFactoryInterface, which carries NEW).

2. Does any rule make BASE available without a REPOSITORY entry (an implicit standard-class repository)? If yes,
   COBOLNET0821 over-rejects.

## Determination and landing (wave 59, implementer J)

Re-probed on the wave-59 build: the misc-p28 draft drew `COBOLNET0821: class 'L1C28CA': INHERITS FROM 'BASE': no such a
class is defined in this compilation group`, and `tests/conformance/2002/oo_hello.cob` (a class with no INHERITS,
`INVOKE GREETER "NEW"`) compiled clean. Both halves of the question are decided by the spec (every citation run
through `cite.py --check`):

1. **A class with no INHERITS clause is legal and has NO New.** §11.3.2 makes `INHERITS` optional. §16.2: "The
   interface BaseFactoryInterface specifies the factory interface of the BASE class" (OK §16.2); §9.3.9: "The subclass
   has all the methods defined for the inherited class definition" (OK §9.3.9); §9.3.14.3: "An instance object is
   created as the result of the NEW method being invoked on a factory object" (OK §9.3.14.3). So New is in a class's
   factory interface exactly when the class inherits BASE, and §14.9.23.3 SR3 — "The value of literal-1 shall be the
   name of a method defined in the factory interface of object-class-name-1" (OK §14.9.23.3 3)) — makes
   `INVOKE root-class "NEW"` an UNDER-REJECT. §16.1's "an implementation may provide alternative root classes" does
   not license an implicit New either: an alternative root class is still a class a program names and inherits.
   The same holds through every receiver rule: SR4 a)/c) (FACTORY OF), SR4 f)/h) (SELF/SUPER in a factory method).
2. **BASE is reached only through the REPOSITORY, and then it must bind.** §16.1: "A standard class BASE shall be
   provided by the implementation" (OK §16.1); §11.3.3 SR2 (OK) requires the REPOSITORY entry; §12.3.8.3 SR6 b) needs
   "information in the external repository for the class" (OK), which the implementation's own standard class always
   has. So 0821 WITHOUT the entry is correct, and 0821 WITH it was an over-reject. §12.3.8.4 GR6 leaves the choice
   between a specifier and repository information implementor-defined (OK §12.3.8.4 6)): a class DEFINED in the group
   under the name BASE wins (recorded in `docs/CONFORMANCE.md` DOC-A.1-163). R44's external repository is NOT needed
   for a standard class.
