# PB4453 - a doc edit forces the full gate

**Seen.** The PB4452 branch (wave 20261829, `worktree-wf_0984eabe-e0e-1`) changes only scripts, notes and docs. Its gate
`000001-20261102T183200Z` ran the FULL lane, which builds the solution and runs the whole Unit, Conformance and
Characterization populations. The gate log reads: "5 of 22 changed path(s) may be read by a compiler test or the build,
e.g. docs/rearchitecture/DESIGN-architecture-review.md". Over the last 61 gates the test phase's median is 12.7 min,
while the tooling lane takes about 40 s plus self-tests. The owner's top-priority fix waited on that gap.

**Mechanism.** `scripts/inert_lane.py` classifies everything under `docs/` as code, because compiler tests read docs.
Examples: SortRuntimeDocShapeDriftTests reads every doc, twenty-odd Unit and Conformance classes read CONFORMANCE.md,
the rule catalog and VERSION_CHANGE_REFERENCE.md, and the Architecture* drift tests read
DESIGN-architecture-review.md. Under the PB4323 rule, any code change then runs the whole population. Yet a doc edit
cannot change what the compiler does. It can change only the result of the tests that read that doc, and the inotify
watch (`inert_lane.py`, THE PROOF) already records which tests read which path.

**Owner direction (2026-11-02, same session):** "There is no compelling reason a compiler change needs to read an
markdown note".

**Fix.** No compiler test (the Unit, Conformance and Characterization assemblies) reads a Markdown file, so `docs/`,
`kb/` and every `*.md` are inert to the gate.
- A test that checks a doc's shape or its agreement with another doc or a script becomes an audit, in Python and with
  no build, and runs in every lane. SortRuntimeDocShapeDriftTests and the readers of CONFORMANCE.md, the rule catalog
  and VERSION_CHANGE_REFERENCE.md are examples.
- A test that checks the compiler against data now kept in Markdown keeps that data in the source it describes, or in
  a non-Markdown data file under the source tree. The Markdown then documents that data and is checked against it by
  an audit. ArchitectureEdgesDriftTests and the allowed-edge table of DESIGN-architecture-review.md are an example.
- The watch's list of Markdown paths a compiler test reads must drop to zero. Pin that with a drift test: no test
  project opens a `*.md`. Remove `docs/` from `inert_lane.py`'s code paths in the same change.
- The merge group still runs everything.

**Also (process, same root).** When a change mixes scripts and docs, the doc edits can land in their own notes or doc
branch so the script change keeps the tooling lane. Until this note lands, a dispatcher should split them.

## Landed (w20261839 group B)

**Sites:** `scripts/inert_lane.py` (`MARKDOWN_ENTRY`, `CLASSIFICATION`, `_under`, `Classification.check`, `markdown_readers`,
`csharp_parts`, `TESTS_MAY_NAME_MARKDOWN`), `scripts/doc_audits.py`, `scripts/docchecks/` (`common`, `register`, `facts`, `design`,
`vcr`, `manual`, `tree`), `scripts/gate.py` (`AUDITS`: `DOC AUDITS`, `ARCH SUBSYSTEMS`, `ANNEX A.1 REGISTER`, `DERIVATION REGISTER`),
`tests/_shared/ConformanceRegister.cs`, `tests/_shared/DocFacts.cs`, `tests/WiseOwl.Cobol.Tests.Unit/DocumentedFactsDriftTests.cs`,
`tests/doc-facts/`, `tests/version-matrix/conformance-register.json`, `conformance-suite/harness/generate.py` (`generate`,
`repository_inputs`).

**What it was.** The owner's direction ("There is no compelling reason a compiler change needs to read an markdown note") made the
note's fix total: no compiler test (Unit, Conformance, Characterization) opens a Markdown file. The watch's record (the Linux
inotify run over the three assemblies once `docs/` and `*.md` were inert) listed the readers; the sources it cannot see (the
repository root is not watched) came from a static scan of `tests/`. Each reader became one of three things (design
`DESIGN-test-build-ci.md` §3.18): a check over the Markdown alone (the `DOC AUDITS` gate audit), a check of a document against a
fact the compiler holds (`tests/doc-facts/compiler-facts.json`, written from the compiler by `DocumentedFactsDriftTests`), or a
datum a test needs that a document also states (an extract the audit holds fresh).

**The pin.** `inert_lane.py check` (an audit in every lane) holds every compiler test source to spelling no Markdown path, calling
no `TestRepo.Docs()` walk and declaring no `TreeScope` without `Kinds`; the Linux watch is its dynamic twin. The `**/*.md` and
`docs/` INERT entries are in `CLASSIFICATION`; the READ entries under them are the ISO text and three data files under `docs/`.

**One decision for the owner (reported, not taken silently).** `specs/ISO_COBOL.md` is a Markdown file ~45 Unit and Conformance
classes read as the ORACLE (CLAUDE.md rule 1: they derive their expected tables from it). It is a READ entry, so a change to it
runs the whole population; moving all of those tables into audits or data files is a campaign of its own, not this note's.
