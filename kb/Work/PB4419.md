# PB4419 — the answer-by-id rule stated twice in an absorbed finisher's spec

**Repro.** On main 08993bcb2, `python scripts/orchestrator/plan_wave.py --from-budget --borrow-days 2 --scratch
'E:\COBOL-coord\scratch' --stop-file 'E:\COBOL-coord\scratch\STOP-loop'` planned wave 20261815, group A (lead PB2103,
`DataBinder.cs`), and ended RED:

```
FAIL     msg-w20261815-a.txt: missing ['PB3777: states twice: fix it at its root (a regression test or golden with it) or answer `no_change_needed` with…', 'PB3777: states twice: your branch is reviewed again when it returns DONE (kb/Work PB3027).…']
```

No code was reserved and no wave launched.

**Mechanism.** Group A is ONE step over `DataBinder.cs` (kb/Work PB4396). `Group.absorb` took in the finishers of two
branches whose branch reviews stamped FINDINGS (`worktree-wf_2201113e-54d-29`, PB4208, and
`worktree-wf_2201113e-54d-26`, PB4240). `finisher_pred`'s FINDINGS arm ended every pred with the same answer-by-id
instruction, and `absorb` joined the preds with a bare `" ".join`, so the spec said it twice. Before PB4396 two
finishers never shared a group, which is why this showed up only now.

**Fix, first branch.** `groups.FINDINGS_ANSWER` held the instruction and `groups.join_preds` (which `Group.absorb` called)
stated it once, at the end. The branch review (R1-1) found the shape wrong: it named ONE rule, and every pred builder
writes rules the same for each branch, so the next two groups of any other kind said theirs twice.

**Fix, at the root (review R1-1).** A pred is FACTS (a branch, a note, a report) and RULES (the builder's same-for-every-
branch sentences). `groups.shared_rule` declares a rule, and `groups.join_preds` keeps every group's facts in order and
states each declared rule once, at the end (a sentence stated twice that no builder declared is stated once too:
`once_rule.without_repeats`). The rules are `RESUME_RULE`, `UNLANDED_RULE`, `LANDED_RULE`, `HALF_RULE`,
`FINDINGS_ANSWER` and `DRAIN_CLAUSE` (`UNLANDED_RULE` names exactly `CARRIED_CLASSES`, the classes `finisher_pred` appends it
for, and the cherry-pick rules carry `CHERRY_PICK_SCOPE`, so a branch's "cherry-pick ONLY those" qualifies them at the end of
a joined pred: review R1-1 and R1-2 of wave 20261821 b); the builders (`branch_resume`, `half_clause`, `finisher_pred`) write facts as
sentences of their own and end with the rule. What belongs to the finished group, not to a branch, is no longer built per
group: the CONTINUATION onto the finished branches a group joined is recorded (`Group.join`, merged by `absorb`) and the
`--drain` clause is added when the group is final (`Group.close_pred`, called once per placed group in `plan_partition`),
so an absorbing group states each once. The sentence rule moved to its one home, `scripts/orchestrator/once_rule.py`
(`check_practices.py` imports it; its own copy is deleted). The half note's reading order had two copies (the half arm in
`plan_finishers` and `PlanState.branch_work_pred`); `groups.half_clause` is the one.

**Reproduced on the unfixed code** (before the answer, joining two preds as `absorb` did): two `branch_resume` preds, two
UNLANDED/LANDED finisher preds, two half preds and every other pairing of the ten kinds repeat a sentence;
two `continuation_pred`s repeat 5 sentences; two `DRAIN` clauses 2. After: none.
