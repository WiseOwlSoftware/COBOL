# PB5211 - at --std 85 READ ... INTO a reference-modified alphabetic item, in a file with more than one record description, compiles: AdmitsIntoOperand admits every reference-modified place as alphanumeric, the 2023 rule, while 1985 keeps the alphabetic category through reference modification

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/Validation/StatementValidation.cs` (`AdmitsIntoOperand`, `CheckIntoReceiver`)

**Mechanism.** With two or more record descriptions, 1985 admits the INTO phrase only when every record and identifier-1 "describe a group item or an elementary alphanumeric item" (§1985:IX.4.5.4 GR7 b, the same words in the sequential and relative READ and in RETURN). `StatementValidation.CheckIntoReceiver` asks `AdmitsIntoOperand`, which answers true for every `RefModPlace` (and `RenamesPlace`) whatever its base item, on the 2023 rule that a reference-modified item is alphanumeric. 1985 says otherwise: the unique data item "has the same class and category as that defined for the data item referenced by data-name-1 except that the categories numeric, numeric edited, and alphanumeric edited are considered class and category alphanumeric" (§1985:IV.4.3.8.4.4 GR5), so a reference-modified alphabetic item stays alphabetic. The predicate has no edition arm, so `READ F1 INTO WA (1:5)` with WA PIC A(10) compiles at --std 85 while `READ F1 INTO WA` draws COBOL1994. One predicate serves the four INTO rules below.

**Found by.** The 1985 refuter pass (2026-11-10; records `E:/COBOL-coord/scratch/refute-85/out/r06.json`, probes `probes-r06/rd7b.cob`, `rd7.cob`, `rd7c.cob`): a refuter attacked the CONFORMS verdict of the indexed READ row, OVERTURNED it, and named the sibling rules; the indexed repro and a sequential twin were run on current main for this note.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids below.

**Rules (4; every citation checked with `scripts/spec/cite.py --check`).**

If all record-names associated with file-name-1 and the data item referenced by identifier-1 describe a group item or an elementary alphanumeric item." Probed (indexed, `rd7b.cob`). Held: PIC N refused at 85 (COBOL0900), a level-66 RENAMES of an elementary alphabetic or numeric item refused, a numeric edited item reference-modified (alphanumeric by GR5) and subscripted and JUSTIFIED receivers admitted.
- `1985-GR-VII.4.4.4-7` - `§1985:VII.4.4.4 GR7` (sequential READ, same text). Probed for this note (`rs7b.cob`, the sequential twin): same result.

**Observed (current main, the build at 3d12682fd2, rerun 2026-11-10).** exit 0, no diagnostic; prints `REFMOD A 00 [0001A     ]`. The sequential twin prints the same. Control (`rd7.cob`, the same FD with `READ F1 NEXT INTO WA`): `error COBOL1994: READ INTO 'WA': ... identifier-1 'WA' is a category-alphabetic item`.

**Expected (from the 1985 text).** `READ F1 NEXT INTO WA(1:5)` draws COBOL1994 at --std 85 as `INTO WA` does: WA (1:5) is category alphabetic (§1985:IV.4.3.8.4.4 GR5), so arm b of §1985:IX.4.5.4 GR7 does not hold, and arm a does not either (two record descriptions). `INTO WE(2:6)` stays admitted (numeric edited becomes alphanumeric).

**Fix direction (root cause, CLAUDE.md rule 4).** The category of a reference-modified item is an edition rule, and it should be answered once: give the place model one edition-aware "category of this reference" reader (1985: the base item's category, with numeric, numeric edited and alphanumeric edited read as alphanumeric; 2002 on: alphanumeric or national), and have `AdmitsIntoOperand` ask it instead of its blanket `RefModPlace` arm. Any other rule that asks the category of a reference-modified operand at 85 (the MOVE table, INSPECT, STRING) then reads the same answer; sweep those callers when the reader lands (kb/Work PB5216 is the INSPECT caller's elementary-item sibling).
