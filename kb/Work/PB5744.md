# PB5744 - FLAG-NATIVE-ARITHMETIC does not flag two operation forms: an intrinsic numeric FUNCTION call with native-usage arguments, and a one-operand arithmetic expression such as IF BL = 1

**Sites:**
- `src/WiseOwl.Cobol.Compiler/Validation/FlagConformancePass.Flag85.cs` `FlagFunctionCall85` (asks FLAG-85 g and e only; never FLAG-NATIVE-ARITHMETIC)
- `src/WiseOwl.Cobol.Compiler/Validation/FlagConformancePass.Flag85.cs` `VisitArithmeticExpression` / `HasOperator` (flags an expression only when it carries an operator)

**One mechanism, two sites (decided from the code).** `§2002:7.2.12` says that when standard arithmetic is in effect an arithmetic operation that uses native arithmetic is flagged. PB5600's detector enumerates the operation SHAPES it asks about by hand (the arithmetic statements, an operator-bearing expression); an operation of a shape not on that list is not asked. Two shapes are missing: (1) an intrinsic numeric FUNCTION whose arguments are native-usage items (COMP-1, COMP-2 or another native usage), which `FlagFunctionCall85` never reaches; (2) a one-operand expression, `IF BL = 1` where BL is a native item (`§2002:8.8.1.3.1` NOTE), which `HasOperator` filters out. Whether a one-operand expression is an "operation" and which function arguments count are determinations to make against `§2002:7.2.12` and `§2002:8.8.1.3` before the code changes; widening `HasOperator` reaches subscripts and VALUE clauses and needs its own goldens (the PB5600 round's reason for leaving it).

**Repro.** A source unit with `>>FLAG-NATIVE-ARITHMETIC` under standard arithmetic and a COMP-1 item F1: `IF FUNCTION ABS(F1) > 0` and `IF F1 = 1` are not flagged. Run with `--std 2002`.

**Direction.** Replace the hand-listed shapes with one query over arithmetic operands (a structure, with a drift test over the grammar's arithmetic-bearing contexts) rather than adding two more shapes.
