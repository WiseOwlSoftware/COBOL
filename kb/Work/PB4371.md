# PB4371 - A wrong item number in the RegistryKey citation

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Model/BoundUnit.cs` (`BoundUnit.RegistryKey`, doc comment at line 61). Lands with PR #967 (PB4266, queued): the report notes the file was not one that round changed.

The comment cites "(§8.3.2.2 2)" for "an outermost unit's [key] is rooted at its EXTERNALIZED name, which alone identifies it in a run unit". Item 2) of that clause's externalized list is "data-names, file-names, and record-names of items described with the EXTERNAL attribute". The outermost program-name is item 1). The sentence "when two or more source elements identify something with the same externalized name, they refer to the same instance" is the clause's unnumbered closing paragraph. This is exactly the inherited-citation failure mode of CLAUDE.md rule 1.

Mechanical check run for this note:

`python scripts/spec/cite.py --check 8.3.2.2 "program-names of outermost programs"` printed `OK  §8.3.2.2 1)  (User-defined words)` with the line `1\) program-names of outermost programs, object-class-names, function-prototype-names, interface-names, method-names, program-prototype-names, property-names, and user-function-names`.

Fix: cite "8.3.2.2 item 1)" for the outermost program-name and the closing paragraph of 8.3.2.2 for the identical-instance rule; re-run `--check` for each phrase.
