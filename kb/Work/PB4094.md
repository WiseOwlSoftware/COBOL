# PB4094 — negative-literal-exponent-overwrites-literal: a negative literal exponent overwrites the literal for later statements (`2 ** -1` twice gives 0.50, then 4.00)

Filed 2026-10-30 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-20261029-224533`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

When the exponent of `**` is a negative numeric literal (`2 ** -1`), libcob 3.2 overwrites the program's one shared
decimal constant for that literal. Later uses of the same literal as the right operand of an arithmetic operator, in a
COMPUTE or in a condition, then read the overwritten value; the same literal as the left operand (`-1 + A`) or as the
operand of `ADD -1 TO A GIVING R` still reads -1. Two identical statements `COMPUTE R = 2 ** -1` give 0.50 and then
4.00, and a later `COMPUTE R = A + -1` with A = 5 gives 7.00 where it gave 4.00 before. Found by the differential fuzz
run fuzz-20261029-224533 (fz00632: `COMPUTE WS-RES = 10 ** -1` printed 100.00 after an earlier `2 ** -1`, and
`10 ** -2` printed 10000.00 after an earlier `2 ** -2`).

## Minimal test case

Free-form reference format (`-free`).

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. NEGLIT.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 R PIC S9(4)V99 VALUE 0.
01 A PIC S9(4) VALUE 5.
PROCEDURE DIVISION.
    COMPUTE R = A + -1
    DISPLAY "1 A + -1  " R
    COMPUTE R = 2 ** -1
    DISPLAY "2 2 ** -1 " R
    COMPUTE R = 2 ** -1
    DISPLAY "3 2 ** -1 " R
    COMPUTE R = A + -1
    DISPLAY "4 A + -1  " R
    STOP RUN.
```

## Environment

- `cobc (GnuCOBOL) 3.2.0`, WSL2 Ubuntu on Windows 11.
- Compiled with `cobc -x -free -std=cobol2014 -o neglit neglit.cob` (exit 0; the only messages are the host's
  `_FORTIFY_SOURCE` redefinition warning), run as `./neglit`.

## Observed result

```
1 A + -1  +0004.00
2 2 ** -1 +0000.50
3 2 ** -1 +0004.00
4 A + -1  +0007.00
```

Exit code 0. Statements 3 and 4 are wrong. The same four lines come with `-std=default` and `-std=cobol85`. Other
probes on the same build: `10 ** -1` then `2 ** -1` gives 0.10 and then 1024.00; `2 ** -1` then `10 ** -1` gives 0.50
and then 100.00. With `2 ** (- 1)` (unary minus on an unsigned literal) both statements give 0.50, and each statement
alone in a program gives the right value. After `COMPUTE R = 2 ** -1`, with A = 5: `COMPUTE R = -1 + A` gives 4.00 and
`ADD -1 TO A GIVING R` gives 4.00 (both right), while `COMPUTE R = A * -1` gives 10.00 (not -5.00),
`COMPUTE R = A - -1` gives 3.00 (not 6.00), and `IF A + -1 = 4` takes its ELSE branch. The same program with
`OPTIONS. ARITHMETIC IS STANDARD-DECIMAL.` prints the same four lines; cobc warns `STANDARD-DECIMAL ARITHMETIC is not
implemented [-Wpending]` and compiles it.

## Expected result (per ISO)

- §8.3.3.3.2 4): "The value of a fixed-point numeric literal is the algebraic quantity represented by the characters in
  the fixed-point numeric literal." The literal `-1` has the value -1 at every place it is written, so statements 1
  and 4 are both 5 + (-1) = 4.00, and statement 3 has the same operands as statement 2.
- §8.8.1.3: "Native arithmetic is in effect when the ARITHMETIC IS NATIVE clause is specified in the OPTIONS paragraph
  or no ARITHMETIC clause is specified." The program has no ARITHMETIC clause, so native arithmetic is in effect, and
  §8.8.1.3 makes it "an implementor-defined method of evaluating an arithmetic expression". The method is the
  implementor's; the values of the operands are not. cobc's own method gives `2 ** -1` the value 0.50 at statement 2
  and in a program by itself, and no method gives two identical expressions over the same literal operands two
  different values, or 5 + (-1) the value 7.
- Edition: the clause numbers above are those of ISO/IEC 1989:2023. The committee draft that became ISO/IEC 1989:2014
  (CD 1.2, 2009) has the same two rules in the same words, so they hold for the edition `-std=cobol2014` claims.

## Our compiler

WiseOwl COBOL (fresh judge `E:\tmp\fuzz-judge-20261030\cobol.exe`, `--std 2014 --source-format free`) compiles the
program with no diagnostic and prints `+0004.00`, `+0000.50`, `+0000.50`, `+0004.00`, exit code 0.

## Fix site

- `libcob/intrinsic.c`, function `cob_decimal_pow`: in the integer-power branch for a negative exponent, the code
  takes the absolute value of `pd2` in place and then stores the power into `pd2` before dividing, so the exponent
  operand is modified.
- `cobc/typeck.c`, function `decimal_expand`, the binary-operator arm: a numeric literal as the right operand is
  passed as `cb_build_decimal_literal (cb_lookup_literal (p->y, 1))`, a decimal constant shared by every use of that
  literal value in the program (`cobc/codegen.c`, `cb_lookup_literal` with `make_decimal`, whose literal cache matches
  on the literal's sign, scale and digits). A literal as the left operand goes through the `CB_TAG_LITERAL` arm of
  `decimal_expand`, which sets a fresh decimal from the literal, which is why `-1 + A` is unaffected. A fix makes
  `cob_decimal_pow` work on a copy of the exponent (or on local temporaries) and never write `pd2`.
- The same branch is unchanged in the 3.3-dev snapshot read for comparison.

## Draft issue

**Title:** a negative literal exponent overwrites the literal for later statements (`2 ** -1` twice gives 0.50, then 4.00)

GnuCOBOL 3.2.0 on WSL2 Ubuntu, `cobc -x -free -std=cobol2014 -o neglit neglit.cob`, run `./neglit`.

After a COMPUTE whose exponent is a negative numeric literal, later uses of the same literal as the right operand of an
arithmetic operator read a different value. In the program below statement 3 repeats statement 2 and statement 4
repeats statement 1, but they print different results:

```
1 A + -1  +0004.00
2 2 ** -1 +0000.50
3 2 ** -1 +0004.00
4 A + -1  +0007.00
```

Expected: `+0004.00`, `+0000.50`, `+0000.50`, `+0004.00`. ISO/IEC 1989:2023 §8.3.3.3.2 4) makes the value of a
fixed-point numeric literal the algebraic quantity its characters represent, so `-1` is -1 each time it is written:
statements 1 and 4 are both 5 + (-1), and statement 3 has the operands of statement 2. The program has no ARITHMETIC
clause, so native arithmetic is in effect (§8.8.1.3); its method is the implementor's, the operands' values are not.
The committee draft that became ISO/IEC 1989:2014 has both rules in the same words. The same output comes with
`-std=default` and `-std=cobol85`.

After the `2 ** -1`, the literal as a left operand (`-1 + A`) and in `ADD -1 TO A GIVING R` still reads -1, but as a
right operand it does not: `A * -1` gives 10.00, `A - -1` gives 3.00, and `IF A + -1 = 4` is false.

Cause, as read in the source: `cob_decimal_pow` (libcob/intrinsic.c) applies `mpz_abs` to the exponent decimal in
place and then stores the power into it before the division. When the exponent is a numeric literal, `decimal_expand`
(cobc/typeck.c) passes the program's shared decimal constant for that literal (`cb_lookup_literal (p->y, 1)`), so the
constant keeps the changed value. Writing the exponent as `(- 1)` avoids it.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. NEGLIT.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 R PIC S9(4)V99 VALUE 0.
01 A PIC S9(4) VALUE 5.
PROCEDURE DIVISION.
    COMPUTE R = A + -1
    DISPLAY "1 A + -1  " R
    COMPUTE R = 2 ** -1
    DISPLAY "2 2 ** -1 " R
    COMPUTE R = 2 ** -1
    DISPLAY "3 2 ** -1 " R
    COMPUTE R = A + -1
    DISPLAY "4 A + -1  " R
    STOP RUN.
```
