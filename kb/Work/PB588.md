# PB588 — OPEN — a wall-clock bound inside a parallel suite is a coin the gate flips

Reported 2026-09-04/05 by two fix-lane implementers independently (`PB205`: "failed once and passed twice
afterwards … spawns `pwsh` with a 180 s cap while 5300 tests run in parallel"; `PB485`: "went red once under the
gate's parallel load and is green both in isolation and on a full re-run"). Neither diff touched a `.g4` file or
the grammar tooling. Re-derived on this tree for this note.

## The mechanism

`tests/Cobol.Net.Tests.Unit/GrammarDiagramGeneratorDriftTests.cs:26-41` — `Generator_RunsClean` launches
`scripts/gen-grammar-diagrams.ps1 -Check` as a child `pwsh` process and asserts it completes cleanly within a
180-second wall-clock budget. Under the wave-local gate the Unit leg runs ~5,300 tests in parallel on a
saturated box (plan §9: ≈24 threads on 24 cores, with COBOL.NET compiles internally parallel), so the child's
wall-clock is a function of the host's load, not of the generator. When the budget is exceeded the failure
carries an empty error message, so the red cannot be attributed from the log — the exact "unattributable red"
`feedback_gate_on_the_verdict_line` forbids waving off as a flake, and both implementers had to re-run the
whole leg to clear it.

`kb/Work/PB376` is the OTHER way this test fails: `-Check` writes to a fixed shared temp path and deletes it
recursively, so two worktrees running the suite at once race. Both are properties of one test; fix them together.

## Fix shape

Take the wall-clock out of the verdict: run the generator to completion (no time bound — a hang is caught by the
suite-level timeout, which names the test) and assert only its exit status and output; or move the check to the
Characterization leg, which runs serially and short. Give `-Check` a GUID-unique output directory (PB376's fix)
in the same change. A drift guard: no Unit test may assert an elapsed-time bound on an out-of-process child
(grep for `Stopwatch`/`WaitForExit(int)` under `tests/Cobol.Net.Tests.Unit` with a process launch in scope),
fired once against the current test before it is trusted.
