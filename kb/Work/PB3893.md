# PB3893 — display-of-function-not-supported: FUNCTION DISPLAY-OF (ISO 2002/2014) is not implemented; -std=cobol2014 reports a syntax error

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S4) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\display-of-function-not-supported.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\display-of-function-not-supported\`.

## Summary

GnuCOBOL 3.2 refuses every reference to the standard intrinsic function DISPLAY-OF. Under `-std=cobol2014` the
diagnostic is `syntax error, unexpected FUNCTION DISPLAY-OF`; under the default dialect it is
`FUNCTION 'DISPLAY-OF' is not implemented`. DISPLAY-OF is part of ISO/IEC 1989 since the 2002 edition, so this is a
missing feature of the edition `-std=cobol2014` claims. Class: feature missing.

## Minimal test case

Free reference format (`-fformat=free`), 10 lines, written for this record (the 35 fuzz witnesses of nights 2 to 5,
for example fz00351, fz00590, fz02191, all reduce to it; 33 of them stop first on the DISPLAY-OF syntax error, five of
those with the variant text `..., expecting (`, and two stop first on `PICTURE clause required`, the separate family
picture-implied-from-value-required).

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. DISPOF.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 NAT PIC N(3) VALUE N"ABC".
01 ALN PIC X(3).
PROCEDURE DIVISION.
MOVE FUNCTION DISPLAY-OF(NAT) TO ALN
DISPLAY ALN
STOP RUN.
```

File: `E:\COBOL-coord\scratch\op\pb3838\records\display-of-function-not-supported.cob`. The two-argument form
`FUNCTION DISPLAY-OF(NAT "?")` draws the same diagnostics.

## Environment

- `cobc (GnuCOBOL) 3.2.0`, Ubuntu package `gnucobol3 3.2-4build1`, WSL2 (Linux 6.18.54.1-microsoft-standard-WSL2 x86_64).
- Commands:

## Observed result

`-std=cobol2014`, exit code 1:

```
dispof.cob:5: warning: handling of USAGE NATIONAL is unfinished; implementation is likely to be changed [-Wunfinished]
dispof.cob:5: warning: handling of national literal is unfinished; implementation is likely to be changed [-Wunfinished]
dispof.cob:8: error: syntax error, unexpected FUNCTION DISPLAY-OF
```

Default dialect, exit code 1: `dispof.cob:8: error: FUNCTION 'DISPLAY-OF' is not implemented`.

`cobc --list-intrinsics` prints `DISPLAY-OF                      No              1 - 2`; `cobc -std=cobol2014 --list-intrinsics` prints
`DISPLAY-OF                      Yes             1 - 2` (re-run for this note on cobc 3.2.0, 2026-10-27; corrected by the refuter: the
record had reported only the default dialect's No).

## Expected result (per ISO)

The program is legal and prints `ABC`.

- ISO/IEC 1989:2023 §15.26.1 (checked): "The DISPLAY-OF function returns a character string containing the
  alphanumeric coded character set representation of the national characters in the argument."
- §15.26.3 1) (checked): "Argument-1 shall be of class national." NAT is national. §15.26.3 2) (checked) bounds the
  optional argument-2: "shall be of class alphabetic or alphanumeric and shall be one character position in length."
- §15.26.4 1) (checked): "A character string is returned with each national character of argument-1 converted to its
  corresponding alphanumeric character representation, if any." The implementor defines the correspondence, but A, B
  and C are in every alphanumeric character set, so the result is "ABC".

Edition: DISPLAY-OF is a 2002 feature, present in the 2014 edition. The 2002 final committee draft (§15.21) and the
2009 committee draft that became ISO/IEC 1989:2014 (CD 1.2, §15.23, with the same argument rules 1 and 2) both define
it, and Annex E of the 2023 standard does not list it as new.

Edition as recorded by the adjudicator: 2014 (introduced 2002; in the 2002 FCD and the 2009 CD; not in 2023 Annex E). `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Class

FEATURE-MISSING (edition 2014; introduced 2002): a standard intrinsic function refused as not implemented.

## Our compiler (WiseOwl)

WiseOwl COBOL (built from main 6ed90bd1c), `cobol dispof.cob --std 2014 --source-format free -o dispof.dll`, then
`dotnet dispof.dll`: compile exit 0, run exit 0, output `ABC`. WiseOwl also refuses a non-national argument-1
(COBOL1546, per the night-4 probe `dof-arg`), so its acceptance here is not an under-rejection.

## Fix site (GnuCOBOL 3.2 source, read observationally)

- `cobc/reserved.c`, `function_list` entry "DISPLAY-OF" (line 3392): marked `CB_FEATURE_NOT_IMPLEMENTED`, which
  `cobc/tree.c` `cb_build_intrinsic` turns into "is not implemented" and `cb_list_intrinsics` into "No".
- `config/cobol2014.words`: line 535 `not-intrinsic-function: DIALECT-ALL`, then line 552 re-activates DISPLAY-OF.
  `cobc/reserved.c` `set_intrinsic_mode` (about line 4980, with its own FIXME) lets that sequence move the entry
  from `CB_FEATURE_NOT_IMPLEMENTED` to `CB_FEATURE_DISABLED` to `CB_FEATURE_ACTIVE`, so under `-std=cobol2014`
  `cb_list_intrinsics` reports Yes and the not-implemented check of `cb_build_intrinsic` is bypassed (refuter, S4).
- `cobc/parser.y`, token `DISPLAY_OF_FUNC` (line 2704), declared with the remark "not used here": no grammar rule
  consumes it, so the re-activated function reaches the grammar as a token it cannot parse: the
  `-std=cobol2014` syntax error. The flip above, not the token alone, is why only `-std` gives the syntax error.
- `libcob/intrinsic.c`, `cob_intr_display_of` (line 7098): a stub that calls `error_not_implemented` under a
  "FIXME: Not implemented!" comment.

## Draft issue

**Title:** FUNCTION DISPLAY-OF (ISO 2002/2014) is not implemented; -std=cobol2014 reports a syntax error

**Body:**

Environment: GnuCOBOL 3.2.0 (Ubuntu gnucobol3 3.2-4build1), x86_64 Linux.

Steps: `cobc -std=cobol2014 -fformat=free -x dispof.cob` with

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. DISPOF.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 NAT PIC N(3) VALUE N"ABC".
01 ALN PIC X(3).
PROCEDURE DIVISION.
MOVE FUNCTION DISPLAY-OF(NAT) TO ALN
DISPLAY ALN
STOP RUN.
```

Observed: `dispof.cob:8: error: syntax error, unexpected FUNCTION DISPLAY-OF` (exit 1). Without `-std`:
`FUNCTION 'DISPLAY-OF' is not implemented`. `cobc --list-intrinsics` lists it as "No", but `cobc -std=cobol2014
--list-intrinsics` lists it as "Yes".

Expected: the program compiles and prints `ABC`. DISPLAY-OF is a standard intrinsic function since ISO/IEC 1989:2002
and is in ISO/IEC 1989:2014 (2023 §15.26): "A character string is returned with each national character of argument-1
converted to its corresponding alphanumeric character representation, if any." Argument-1 is national; the optional
argument-2 is a one-character alphanumeric substitution character. It is also the standard's only conversion from a
national item to an alphanumeric one (2023 Annex D.11.3, informative: national items "can be moved to data items of usage display only by explicit conversion with the DISPLAY-OF function").

Secondary: under `-std=cobol2014` the diagnostic is a syntax error rather than the "is not implemented" message the
default dialect gives. config/cobol2014.words disables every function (`not-intrinsic-function: DIALECT-ALL`)
and then re-activates DISPLAY-OF; set_intrinsic_mode in cobc/reserved.c turns the not-implemented entry into disabled
and then into active (its FIXME notes this), so the not-implemented check is bypassed and the scanner returns
the `DISPLAY_OF_FUNC` token, which no grammar rule uses.
