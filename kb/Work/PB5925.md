# PB5925 - decision: the source listing

## Why
- The owner, 2026-11-17: "Our compiler should have the best listing."
- 1985 requires one (PB5923). The later editions leave it implementor-defined, but a production compiler without a
  listing is behind every competitor.
- Owner order of 2026-11-17: the listing scope is the codebase's decision, recorded after PB4950. This is that note.

## What competitors provide
Survey: `E:/COBOL-coord/scratch/my-20261115/listing-survey/survey.md`. IBM, GnuCOBOL, isCOBOL and Fujitsu BS2000 were
read from vendor pages. Micro Focus, ACUCOBOL-GT and NetCOBOL rest on search summaries, and the design does not depend
on them.
- IBM Enterprise COBOL is the benchmark: source, MAP (data map with offsets, nested-program map), XREF, LIST/OFFSET
  (object code), VBREF (verb counts), FLAG/FLAGSTD. SYSADATA is the only machine-readable listing found (binary
  records), and IBM states its text listing "is not a programming interface", yet tools parse it.
- Micro Focus: LIST, XREF, DATAMAP, SETTING (options in effect), ERRLIST (inline or at the end); honours '/' and
  DATE-COMPILED.
- GnuCOBOL 3.2: -t/-T listing, symbols and xref; its map omits INDEXED BY indexes and level-78 constants.
- Fujitsu BS2000: separate options, source, locator-map and error lists; honours >>LISTING ON/OFF and '/'.
- Nothing found honours >>PAGE or >>DISPLAY UPON LISTING; none implements every standard listing hook.

## The decision
1. ONE listing model, built from the compiler's own structures (preprocessed source with its COPY/REPLACE
   provenance, the bound data model, the symbol table and references, the diagnostics, the options, the emitted C#).
   Every renderer reads only the model; no renderer re-derives a fact.
2. Three renderings of that model:
   - paginated text for people and print (page headings with compiler version, program-name, compile timestamp, page
     number; page size and width options), laid out so readers of IBM listings are at home;
   - HTML with every name linked to its definition and its references, and diagnostics linked to their lines;
   - versioned JSON with a published schema: the stable programming interface no competitor offers.
3. Content, beyond every competitor:
   - source with line numbers and sequence area, COPY and REPLACE expansion shown with nesting depth, the member and
     the replacements applied, and conditional-compilation suppressed lines marked;
   - diagnostics inline at their line and summarised at the end, each citing the rule of the edition in force
     (the PB4950 mechanism);
   - a complete data map: level, name, offset, length, usage, picture, OCCURS/ODO, REDEFINES, and the native .NET field
     or type each item became; indexes and constants included;
   - a cross-reference that classifies every use as defined, read, written or modified, for data-names,
     procedure-names, files, programs and copy members;
   - options in effect, compiler version and edition, statistics (lines, statements, verb counts);
   - a map from each COBOL statement to the emitted C# lines;
   - every standard hook of every edition: '/' and '*' comment lines, DATE-COMPILED, >>LISTING, >>PAGE,
     >>DISPLAY UPON LISTING, COPY SUPPRESS, the effect of logical conversion.
4. Default: on at --std 85 (the edition requires it); on request at 2002, 2014 and 2023. Off is always available.
5. One compilation timestamp feeds the listing heading, DATE-COMPILED and WHEN-COMPILED (1985 requires they agree).
6. The listing is a product surface with a design doc (`docs/rearchitecture/DESIGN-listing.md`, written before code,
   rule 2) and tests whose expected values come from the standard's rules and the JSON schema, not from captured output.
7. DOC-A.1-117 and the conformance entries that lean on "no listing" are rewritten when the listing lands.

## Sequencing
Built as 1985 work (the owner's 1985-first order): PB5923's standard minimum and the model come first, the richer
sections follow in the same design. PB5924 (the catalog hole) runs beside it so the 1985 count is honest.
