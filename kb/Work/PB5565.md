# PB5565 - at --std 85 PADDING CHARACTER is accepted in an indexed (and a relative) file control entry, where 1985 prints it only in the sequential entry

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/FileControlKeyRules.cs` (`FileControlKeyRules.EntryClauses`); `src/WiseOwl.Cobol.Compiler/Binding/FileControlBinder.cs` (`FileControlBinder.BindFileControl`); `src/WiseOwl.Cobol.Compiler/Binding/Model/FileModel.cs` (`PaddingCharacterSpec.InEdition`); `tests/WiseOwl.Cobol.Tests.Unit/FileControlKeyRuleDriftTests.cs` (`PaddingClause_IsCarriedBySequentialFormatAlone`)

**Mechanism.** §1985:IX.2.3.2 (indexed) and §1985:VIII.2.3.2 (relative) print no PADDING CHARACTER clause; the clause belongs to the sequential entry. `FileControlBinder.BindFileControl` captures it into `FileModel.Padding` for every organization, and `FileControlKeyRules.EntryClauses`, whose rows refuse the other formats' clauses on an indexed file (RELATIVE KEY COBOL0863, RECORD DELIMITER COBOL2912), has no sequential-format row for it. kb/Work PB5070 (landed) captured the clause and resolved its operand; its 2026-11-10 addendum named this half (the clause on an indexed or relative entry), which the landing left open. The relative entry accepts it the same way (that addendum's reader).

**Found by.** The 1985 re-read 5, batch 1 (`kb/Work/PB4996/2026-11-14-reread-5.md`): the reader of `E:/COBOL-coord/scratch/op-20261114/out-reread5/rs-01.json` read `1985-FMT-IX.2.3.2` PARTIAL; the row had named only PB5070 (landed).

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094), so `inventory_rows` is empty; the row this note claims is below, recorded PARTIAL naming this note (records-rs5a). The relative format row (`1985-FMT-VIII.2.3.2`) is the sibling the fix sweeps.

**Rules (1 claimed; citations checked with `scripts/spec/cite.py --check`, log `E:/COBOL-coord/scratch/op-20261114/records-rs5a/cites.txt`).**

- `1985-FMT-IX.2.3.2` (read: PARTIAL, harm: under-rejects). `§1985:VII.2.7.4 GR1`: "The PADDING CHARACTER clause specifies the character which is to be used for block padding on sequential files".

**Repro.** `E:/COBOL-coord/scratch/op-20261114/out-reread5/work-rs-01/b_pad.cob`:

```cobol
       FILE-CONTROL.
           SELECT F ASSIGN TO "ix2p.dat"
               ORGANIZATION IS INDEXED
               ACCESS MODE IS DYNAMIC
               RECORD KEY IS FK
               FILE STATUS IS FS
               PADDING CHARACTER IS "*".
       DATA DIVISION.
       FILE SECTION.
       FD  F.
       01  FR.
           05 FK PIC XX.
           05 FA PIC XX.
           05 FD1 PIC XX.
       WORKING-STORAGE SECTION.
       01  FS PIC XX.
       PROCEDURE DIVISION.
       P1.
           OPEN OUTPUT F.
           MOVE "K1" TO FK. MOVE "A1" TO FA. MOVE "D1" TO FD1.
           WRITE FR INVALID KEY DISPLAY "WIK" END-WRITE.
           DISPLAY "W " FS.
           CLOSE F.
           OPEN INPUT F.
           MOVE "K1" TO FK. READ F INVALID KEY DISPLAY "RIK" END-READ.
           DISPLAY "R " FS " " FR.
           CLOSE F.
           STOP RUN.
```

`cobol.exe --std 85 --source-format fixed --run b_pad.cob`

**Observed (the pinned compiler of `E:/COBOL-wt/coderead85-tree-d`, main dc1f2dcce8, rerun 2026-11-14 from copies in `E:/COBOL-coord/scratch/op-20261114/records-rs5a/rerun/`; log `E:/COBOL-coord/scratch/op-20261114/records-rs5a/rerun-log.txt`).** No diagnostic; prints `W 00` and `R 00 K1A1D1`, exit 0.

**Expected (from the 1985 text).** A diagnostic at the PADDING CHARACTER clause of an indexed or relative entry at --std 85, the same refusal `EntryClauses` gives RECORD DELIMITER on an indexed file.

**Fix direction (root cause, CLAUDE.md rule 4).** Give PADDING CHARACTER its sequential-format row in `FileControlKeyRules.EntryClauses` (the one table that says which clause each organization's entry admits) at the editions that print it, so the indexed and relative entries refuse it by that row; sweep the table for any other clause of one organization's 1985 entry that the 2023-cut table admits on another.
