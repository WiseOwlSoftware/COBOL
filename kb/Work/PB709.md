# PB709 — LANDED — §4.2.6 written where §4.2.7 governs

Found 2026-09-05 by the `PB693` finisher (report, "Things that did not hold" 1) while re-deriving the citations of
the VALIDATE-STATUS declined-facility red it was attributing.

## The facts

- §4.2.6 (`cite.py --check 4.2.6 "Language elements that depend on"` → OK) is **processor-dependent** language
  elements — Annex A.3 — and requires a compile-time warning mechanism for unsupported syntactically-detectable ones.
- §4.2.7 (`cite.py --check 4.2.7 "Language elements that an implementor may, but need not, implement are listed in
  A.4"` → OK) is **optional** language elements — Annex A.4 — which an implementor "may, but need not, implement" and
  shall identify in user documentation.
- VALIDATE (the facility the finisher was reading) is Annex A.4 item 14 — optional — yet the posture comment in
  `CobolDeclined.g4` and the A.4 arms of `VersionConformancePass.cs` and `DeclinedFacilityPass.cs` justified the
  decline by §4.2.6. `DiagnosticCatalog.cs`'s per-facility descriptors state the A.3/A.4 split correctly, so the
  rule was written in two places that disagreed.

## Why it mattered

No user program got a wrong answer. This is the `a_real_clause_can_answer_a_different_question` shape: the quoted
text is genuinely in the standard and the clause exists, so `audit_code_citations.py --check` passes, and the wrong
clause propagates into the next comment, golden and DEVLOG paragraph that inherits it. A decline justified by the
processor-dependent clause reads as "we could not", a decline under the optional clause reads as "we chose not to,
and documented it" — the second is the posture the conformance statement actually makes.

## Landed 2026-09-06

**The finding held, and it was WIDER than the note said.** Three things the note did not have:

1. **The difference is normative, not editorial.** §4.2.6 carries two sentences §4.2.7 does not: the MANDATORY
   compile-time warning mechanism, and "it is not required to diagnose syntax errors within this unsupported
   syntax". The four sites were not merely citing the wrong number — three of them were leaning on the *excuse
   sentence*, which does not exist for an A.4 element. The corrected text does not swap a §; it states the real
   ground, that an unclaimed optional element's syntax is not this implementation's to diagnose in the first place
   (§4.2.7 + A.4.1).
2. **Commit and rollback is in BOTH annexes** — Annex A.3 items 6-7 *and* Annex A.4.3 — so the annex is a SET, not
   a choice. `CobolDeclined.g4`'s header named only A.4.3 and the 1579 descriptor named only A.3; both now name both.
3. **`docs/CONFORMANCE.md` was the source, not a victim.** §4's own first bullet grouped "the VALIDATE statement"
   under "A **processor-dependent** element (Annex A.3, §4.2.6) … §4.2.6 ¶3 makes the compile-time warning mechanism
   mandatory", and §1 and the header repeated it as "the COBOLNET1578–1580 band, §4.2.6 third paragraph". That is
   the document §4.2.7 itself makes normative, so the error was in the conformance claim before it was in a comment.
   `COBOLNET_VALIDATION_DESIGN.md` had inherited it with `COBOLNET1560/1578/1579/1580` — which additionally put the
   A.4.2 screen ERROR inside the A.3 warning band.

**The structural fix, taken rather than the citation-only one** (CLAUDE.md rule 5). The annex is now DATA:
`DiagnosticDescriptor.Annex`, a `[Flags] DeclinedAnnex { None, A3, A4 }`, set on all eleven declined-facility
descriptors, with the licensing clause DERIVED from it by `DiagnosticDescriptor.PostureClause` (§4.2.6 / §4.2.7 /
both) so no site writes the clause by hand. `tests/Cobol.Net.Tests.Unit/DeclinedFacilityAnnexDriftTests.cs` holds
it there with five facts: a population assertion; no declined descriptor cites the *other* annex's clause; every
one cites the clause its own annex derives; the datum agrees with the registers in `docs/CONFORMANCE.md` (§2 for
A.3, §5 for A.4); and a can-fail fact that runs both predicates against fabricated descriptors. **Proved failing**
by flipping COBOLNET1580 from A4 to A3 on the live catalog: three of the five went red, including the
CONFORMANCE.md cross-check, and the reverted tree is green.

**The sweep.** `grep -rn "4\.2\.6" src/ docs/` was re-derived site by site against the A.3/A.4 membership of the
element each decorates. Corrected: `CobolDeclined.g4` ×2, `VersionConformancePass.cs`, `DeclinedFacilityPass.cs` ×2,
`CobolParserCore.g4` ×2, `StatementBinder.cs` ×2, `EditionContext.cs`, `Table12StatementNames.cs`, `CONFORMANCE.md`
×4, `COBOLNET_VALIDATION_DESIGN.md`, and a correction banner on `PHASE-13-remaining-waves-scout.md`'s Wave-H section,
which is where the "reusable §4.2.6 warning band (MCS · commit/rollback · VALIDATE)" framing was minted and which
still says "implement FROM this doc". Left alone as CORRECT, each checked: `CobolIO.g4` and `DataBinder.cs` (RECORD
DELIMITER, A.3 item 26), `EcNameResolution.cs` (A.3 item 4), `OptionsBinder.cs` ×3 (A.3 item 2), `ScreenFacility.cs`
and `EditionContext.cs`'s second paragraph and `DiagnosticCatalog.cs`'s REFUSE-band comment (all three state the
split correctly, by contrast), and `CONFORMANCE.md` §2's own header. `docs/DIAGNOSTICS.md` was regenerated from the
catalog. No diagnostic code was allocated: the reserved COBOLNET1884–1885 were not needed and are NOT consumed.
