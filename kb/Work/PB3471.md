# PB3471 — three-organization file-test classes duplicate the harness

Low, non-blocking DUPLICATION lead from the branch review of PB3459 (report `E:\COBOL-coord\scratch\reports\w1134b-PB3458-report.md`, `## Review findings` LEAD 1). PB3459 deliberately left these classes unconverted because `KeyedOrg` has no Sequential arm.

**Mechanism.** One job (register a file in a chosen organization, seed records, build the record image) is written privately in each class that spans Sequential, Relative and Indexed, so a connector API change needs one edit per copy.

**Sites.**
- `tests/Cobol.Net.Tests.Unit/FileLockPostureDriftTests.cs`: RegisterOrg, SeedOne
- `tests/Cobol.Net.Tests.Unit/SharingRefusalStatusTests.cs`: RegisterOrg, Seed
- `tests/Cobol.Net.Tests.Unit/PermanentErrorOutranksRecordLockTests.cs`: Register, Seed, Image
- `tests/Cobol.Net.Tests.Unit/RunUnitFileLockDriftTests.cs`: Register (Org switch, 4-char record)

**Fix shape.** Extend `tests/Cobol.Net.Tests.Unit/KeyedFileHarness.cs` (`KeyedOrg`, `Register`, `Seed`) with a Sequential arm, convert the four classes, delete the private copies in the same change (no forwarders, CLAUDE.md rules 4 and 5). Sweep `tests/Cobol.Net.Tests.Unit` for further Org-switch registrations before cutting the arm.

## Landed

Re-probed on this build: all four private copies were present, and the classes also kept FOUR copies of the one
organization enum (`Org { Sequential, Relative, Indexed }`, `RunUnitFileLockDriftTests` borrowing another class's). The fix
shape above (a Sequential arm in `KeyedOrg`) was the smaller diff and the wrong one: ten keyed-store theories iterate
`Enum.GetValues<KeyedOrg>()`, so a third member would have run every one of them over a sequential file. The restructuring
(CLAUDE.md rule 5):

- `KeyedOrg` became `FileOrg { Sequential, Relative, Indexed }`, the ONE organization enum, with `FileHarness.KeyedOrgs` for
  the keyed-store theories; the four private `Org` enums are gone.
- `KeyedFileHarness` became `FileHarness` (it spans all three organizations). `Register` has a Sequential arm and a throwing
  default, so a fourth organization is one arm and `FileLockPostureDriftTests.EveryOrganisationsHandleAccessLiesInThatBand`
  (it pins the count of concrete connectors against `FileOrg`) is red until it is added. `Delete` and the keyed `Read` assert
  the organization has a key (§14.9.10.3 SR1). `ReadNext` is new and replaces the three private copies (`IndexedEngineTests`,
  `RelativeEngineTests`, `PermanentErrorOutranksRecordLockTests`).
- The four classes call `FileHarness.Tmp/TryDelete/Register/Seed`; no private copy remains. Sweep: no other test class spans
  the three organizations (the other `RegisterRelative(`/`RegisterIndexed(` sites under `tests/` are single-organization files
  with their own record layouts). 17 other test classes keep a private `Tmp` or `TryDelete` (a different job; reported as a lead).
