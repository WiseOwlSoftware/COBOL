# PB165

The named residue of PB133's conformance campaign. Four legs were recorded; **three landed on 2026-09-09** and
the fourth is a different mechanism — a runtime registry — which is why the note stays open with a single
obligation rather than four.

## What remains — the DYNAMIC Format-1 lane's DESCRIPTION check

`CALL "S" USING …` with no `AS` phrase resolves its callee at RUNTIME, so §14.9.4.4 GR3d's conformance check is
a runtime one: *"the rules for conformance specified in 14.8.2, Parameters and 14.8.3, Returning items apply. If
a violation of these rules is detected, the EC-PROGRAM-ARG-MISMATCH exception condition is set to exist if
checking for it is enabled in both the activated program and activating runtime element"*. PB133 wave C2b landed
the COUNT half of that: `ProgramTable` registers each unit's `FormalCount` / `RequiredCount` and its
`ArgMismatchChecking` state at PD entry, and `CallProgram` applies the enabled-in-both gate.

**No DESCRIPTION facts are registered at all.** There is no per-formal category / usage / picture / length
record on `ProgramNode`, so §14.8.2.2, §14.8.2.3.2 and §14.8.2.3.3 have nothing to compare on that lane, and a
non-conforming dynamic call proceeds through `CobolArgAdapt`'s converting views. The AS NESTED and program-
prototype lanes are unaffected — they check all of it at BIND (COBOLNET1684 / COBOLNET1688 / COBOLNET1736).

⚠ **Weigh this against P13's prototype registry before building a second metadata shape.** A program prototype's
§12.3.8.4 GR10 a) definition carries exactly these facts, and P13 has to model them anyway; a hand-rolled
description record on `ProgramNode` would be the second copy of that model, which is the thing rule 8 and
`feedback_one_rule_one_place` exist to prevent. `SR-14.9.4.3-25`'s own residue (b), the prototype lane, is the
same registry.

Rows still owed: **`GR-14.9.4.4-3`** (its leg 3d DESCRIPTION half on the dynamic lane — its OTHER open leg, 3c's
EC-PROGRAM-RESOURCES having no raise site, is not PB165's) and **`SR-14.9.4.3-25`** (residues (a) dynamic-lane
runtime check and (b) the P13 prototype lane).

## Landed 2026-09-09 — the three legs, each measured before and after

**Leg 1 — §14.8.2.3.3, BY CONTENT / BY VALUE elementary conformance, on every lane that knows the callee's
formals at bind.** The rule existed on this tree as `OoBinder.OoContentMismatch`, **private to INVOKE**, so the
Format-2 CALL lane — which §14.9.4.3 SR25 puts under the very same clause — had no by-content screen at all and
`CallBinder`'s conformance loop was a dispatch with a BY REFERENCE arm and nothing else. Measured on the pre-fix
tree: `CALL "S1" AS NESTED USING BY CONTENT A` with `01 A PIC X(4) VALUE "ABCD"` against a `PIC 9(4)` formal
compiled clean and printed **`LA=0000`** — a wrong answer, silently, on source the standard declares in error.
The fix is the EXTRACTION: `OoConformance.ContentMismatch` (identifiers) plus
`ContentArithmeticMismatch` / `ContentBooleanMismatch` / `ContentAlphanumericLiteralMismatch` /
`ContentNumericLiteralMismatch` (the value shapes) now live beside their BY REFERENCE sibling
`DescriptionMismatch`, and `CallBinder.ContentConformanceReason` dispatches on the bound argument's shape.
COBOLNET1688 — the same code the BY REFERENCE arm uses, because it is the same obligation.
⚠ The move carried `OoBinder.cs:719`'s `arg.IsImageCapable` line verbatim to the new site; **[[PB818]] owns that
line** and its one-line cure now applies at `OoConformance.ContentMismatch` instead.

**Leg 2 — §14.8.3 RETURNING conformance** was closed by [[PB204]] for the AS NESTED lane (COBOLNET1736). PB165
closed the DELIVERY half that `GR-14.9.4.4-4` held open: `CallAbi.StoreReturn` stored a character-shaped result
only into a `string` carrier or, via `long.TryParse`, a `long` one, so a result reaching a `ulong` / `Int128` /
`UInt128` identifier-3 — every receiver past 18 digits — was **discarded with no store and no diagnostic**
(measured: a callee returning `"000123"` left a `PIC 9(30)` identifier-3 at its previous value 7). Every
`StoreReturn` overload is now TOTAL: it stores, or it raises `CobolCallException("EC-PROGRAM-ARG-MISMATCH")`
citing §14.8.3.3 and §14.9.4.4 GR3d. Nothing happening is the one outcome GR4's *"the result … is placed into
identifier-3"* excludes. (The row's claim that the pointer / program-pointer / object-reference legs draw a
Roslyn CS1503 was STALE — PB133 wave B had landed them.)

**Leg 3 — §14.2.3 GR9's second allocation regime.** The recorded residue said a nested call's BY CONTENT
arguments "take the prototype-less first regime"; measurement refuted that for two of the three arms. The
"otherwise" arm (the formal's own description, argument COMPUTEd/MOVEd in) and the ANY LENGTH arm were already
realized by the caller's snapshot plus the callee's formal-described adapter. **The DYNAMIC LENGTH arm was
missing outright**, and not only for BY CONTENT: `ProgramEmitter`'s formal-carrier width dispatch had an ANY
LENGTH arm and a fixed arm and no third, so a dynamic-length formal took the fixed arm at its PICTURE length —
which §13.18.19.3 SR1 pins at **exactly one symbol**. Measured, BOTH modes: a 7-character argument arrived as
`LEN=1`, and BY REFERENCE the callee's 2-character store spliced one character into the caller's seven
(`AFTER=[ZBCDEFG]`). `ProgramEmitter.FormalTextCarrier` is now the ONE place the three length regimes are
decided and `CobolArgAdapt.DynText` carries §8.5.1.10.4's replace-and-truncate store.

**Leg 4 — §14.9.4.4 GR12's "except as an argument" exemption, and §8.8.4.8.4 GR1c's transitive omission.** The
emitter recognized "this argument IS a whole formal parameter" by a **`__lnkp` prefix match on the emitted field
name**, which can only ever see a CARRIER-RESIDENT formal, and it guarded only the BY REFERENCE arm. So
forwarding an omitted formal **BY CONTENT** read its accessor (a snapshot is a read, and GR12 says this
reference form is not one), and a **GROUP** formal — whose carrier is a copy-in field with an ordinary name —
forwarded that field, whose fresh carrier answers `IsNull` false. Both measured: each printed
`INNER-SEES-PRESENT` where GR1c requires omitted. `CallEmitter.WholeFormal` now recognizes the case
STRUCTURALLY, by identity against the unit's own `LinkageFormal` items (`CallUnitState.Formals`), and
`CallEmitter.Forwarded` guards every mode's carrier build with the incoming carrier's presence.

**Goldens** — `conformance:2023/pb165_content_conformance` (§14.8.2.3.3's conforming pairings and all three
GR9-second-regime arms), `conformance:negative/pb165-content-nonconforming` (COBOLNET1688),
`conformance:2023/pb165_gr12_forward`, `conformance:2023/pb165_dynamic_length_boundary`,
`conformance:2002/pb165_returning_wide_carrier`.
**Rows closed** — `GR-14.9.4.4-4`, `GR-14.9.4.4-6`, `GR-14.9.4.4-12` all PARTIAL → CONFORMS (GAP 2643 → 2640).

## Extended 2026-10-02 (wave 1003 group C, w1003c, landing PB1040) — the carrier and the registry shape now exist

## Landed 2026-10-04 (wave 1015 group W, w1015w) - the dynamic Format-1 lane's DESCRIPTION check; the prototype lane is the residual

**Re-probed on this tree** (`p165.cob`, the golden's cases): BY REFERENCE `X(4)` -> `X(6)` and `9(4)` -> `9(3)`, BY CONTENT the same, a group 8 -> group 10
BY REFERENCE and a numeric item -> a group formal all ran and printed OK under `>>TURN EC-PROGRAM-ARG-MISMATCH CHECKING ON` with ON EXCEPTION written.

**The rule, from the clauses (each `cite.py --check` OK).** §14.9.4.4 GR3 d) applies §14.8.2 at run time. For "a program for which there is no
program-specifier in the REPOSITORY paragraph of the activating element and there is no NESTED phrase", §14.8.2.3.2 and §14.8.2.3.3 rule 1 say "the formal
parameter shall be of the same length as the corresponding argument" (BY REFERENCE, BY CONTENT and BY VALUE alike); rule 2 (a conversion by COMPUTE, SET or MOVE,
or the identical PICTURE) is for every other lane, and the binder already checks it where the callee is known. For an alphanumeric group, §14.8.2.2 1) BY
REFERENCE: the other item "shall be an alphanumeric group item or an elementary item of category alphanumeric, and the formal parameter shall be described with
the same number or a smaller number of bytes as the corresponding argument"; 2) BY CONTENT: the rules of a MOVE (no length relation).

**The mechanism (one registry, extending PB1040's pair, as the note asked).** `BoundaryItem(Num, Length, Class)` (`CallAbi.cs`) is the one description both sides state;
`BoundaryClass` {Other, Alphanumeric, Group, Exempt} carries the §14.8.2.2 / §14.8.3.2 group facts, and two rules live beside it: `ArgumentConforms(mode, formal)` for an
argument and `Conforms` for a RETURNING pair (which gains the group-class rule: a group paired with a numeric-edited receiver of the same length used to conform).
`CallEmitter.ArgumentLength` (the item's BYTE-LENGTH, `DataItem.ImageWidth`, for a text-carried or native item) and `BoundaryClassOf` are the one measure for the activating
side's `ArgumentFacts` and the activated side's `RegisteredFormal`; a unit that checks EC-PROGRAM-ARG-MISMATCH registers `formals:` at `ProgramRegistry.Register` and a CALL
site that checks it states `Length:`/`Class:` for each data-item argument, so an unchecked program's emitted text is unchanged. `ProgramTable.CallProgram` compares the pairs
under the enabled-in-both gate, before the callee runs, next to the count and RETURNING checks. `CallEmitter.IsDynamicLane` keeps the length rule to its lane: a function, a
NESTED call, a program-specifier's program (and a non-literal target when the element writes any program-specifier) describe no argument, because rule 2 converts there.

**Witnesses.** Golden `2002/pb165_dynamic_call_description_check` (13 cases: nine on the dynamic lane, the group class cases, and a function and a NESTED call that must NOT raise),
`BoundaryItemConformanceTests` (every row of the rule table). Values read off the clauses before the run; the run matched. No negative golden: a mismatch is a run-time
exception condition, not a compile-time refusal, and the EC-model gating below 2002 is the version matrix's.

**Rows.** `GR-14.8.2.3.2-L2.1`, `GR-14.8.2.3.3-L2.1` DIVERGES -> CONFORMS; `GR-14.9.4.4-3` PARTIAL -> CONFORMS (residual (a) 3c is DOC-A.1-14's empty resource set, PB1422; residual (b) is
this leg); `SR-14.9.4.3-25` stays PARTIAL on its (b): a Format-2 CALL whose program-prototype has no compile-time signature (§12.3.8.4 GR10 c, an external repository resolved at execution) is
unchecked, because the registry holds length, numeric profile and class but not the clause-level identity rule 2 compares (ALIGN, BLANK WHEN ZERO, DYNAMIC LENGTH, JUSTIFIED, the PICTURE with its
currency and locale facets). That is the next extension of `BoundaryItem`, not a second shape; the note stays open for it. Batch `w1015w/batch-pb165.json` (GAP 323 -> 320).
