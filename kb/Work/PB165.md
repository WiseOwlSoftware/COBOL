# PB165

The named residue of PB133's conformance campaign (waves C1/C2a/C2b landed the OMITTED facility, the
SR19/SR21 mode checks, the §14.8.2.3.2/§14.8.2.2 BY REFERENCE description conformance on the AS NESTED
lane, and the §14.8.2.1 count rule on both lanes). Four legs remain, each recorded on its inventory row:

1. **§14.8.2.3.3** (BY CONTENT / BY VALUE elementary conformance): "the same as if a MOVE statement were
   performed" / SET-validity — unchecked in every lane; `CobolArgAdapt`'s converting views actively adapt
   mismatched descriptions instead (the batch-8 "papers over" finding). Checkable at bind for AS NESTED
   via `MoveClassifier`; runtime for the dynamic lane.
2. **§14.8.3** RETURNING conformance — the identical-description case works; a mismatch is undiagnosed
   (`StoreReturn`'s typed lanes silently no-op on a cross-carrier pair).
3. **§14.2.3 GR9's second allocation regime**: a NESTED call's BY CONTENT record is described by the
   FORMAL (ANY LENGTH → same category/usage/length as the argument; DYNAMIC LENGTH → a dynamic-length
   item), where the emit still allocates the caller-described first-regime record. Needs a nested flag on
   BoundCallProgram reaching CallEmitter's ArgText (recorded since the PB131 close on GR-14.9.4.4-6).
4. **GR12 forwarding residue** (from wave C1's close on GR-14.9.4.4-12): forwarding an omitted formal
   BY CONTENT raises where the as-an-argument exception should apply, and a NON-resident (group) formal's
   forwarding loses presence (the copy-in local forwards, so the next callee sees a present argument).

The dynamic-lane DESCRIPTION checks (beyond the landed count rule) additionally need per-formal
description facts registered with the program table — weigh against P13's prototype registry, which
subsumes the metadata shape.
