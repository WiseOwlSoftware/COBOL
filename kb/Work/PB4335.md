# PB4335 — `GOBACK RETURNING` in a main program dies at run time

**Found 2026-10-31** by the PB1610 review finisher (wave 20261791 group C, branch `worktree-wf_15d43d1b-129-17`, report
`E:\COBOL-coord\scratch\reports\w20261791c-PB1610-report.md`, "New defects" 1).

**Sites:** `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/CallEmitter.cs` (`EmitGoback`, the former `LoudStmt` arm, now gone); `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CallBinder.cs` (`BindGoback`: the status now travels with RAISING too, and a RETURNING source with no header item folds into it); `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/ControlFlowBinder.cs` (`ReturningAsStatus`); `src/WiseOwl.Cobol.Compiler/Binding/Bound/BoundCall.cs` (`BoundGoback`).

**What happens.** `GOBACK RETURNING ...` in a main program that declares no PROCEDURE DIVISION RETURNING item (the
GnuCOBOL main-program exit-status use) compiles with no diagnostic, and the run then dies with
`NotImplementedCobolFeatureException`. It compiles clean and dies at run time, hence MAJOR with `crashes: true`. The
code path is the no-receiver arm that PB880 (landed) left: PB880 made GOBACK RETURNING's implicit move a bound node for
the receiver case only. The user manual (`docs/manual` migrating page, PR #933) documents the limitation until this is
fixed.

**Spec clause to derive.** The report cites none for this lead. The implementer derives from `specs/ISO_COBOL.md` what
`GOBACK RETURNING` means in a main program with no RETURNING item (§14.9.18 GOBACK) and checks it with `cite.py --check`
before writing a citation; where the standard is silent the precedence is GnuCOBOL, then IBM / Micro Focus (CLAUDE.md
rule 1). This note adjudicates nothing.

**Repro.** A main program ending `GOBACK RETURNING 4.` with no `PROCEDURE DIVISION RETURNING`; compile with
`cobol p.cob --run`. Related: PB880 (the landed sibling arms), PB1610 (the manual that records the limitation).

## Landed (wave 20261799, group C)

Re-probed on the build: `GOBACK RETURNING X` (X a `PIC 9` item; the repro's literal `4` is not accepted by the grammar, the
operand is a data reference) compiled clean and died with `NotImplementedCobolFeatureException`. Fixed at the root: the
binder folds a RETURNING source that has no header RETURNING item to move into (ISO 14.9.18.4 GR2 is conditioned on the
header's phrase) into the GOBACK's termination status, so a main program exits with the operand (GR3 + GR10, DOC-A.1-192's
mapping; GnuCOBOL's RETURN-CODE use) and a called program, which has no result, ignores it. A written status phrase wins.
Sibling found and fixed in the same function: `GOBACK RAISING ... WITH ERROR STATUS 3` built its node without the status,
so a main program exited 0 (GR3 ignores RAISING, GR10 still passes the status). Goldens:
`conformance-suite/cases/14.9.18-GOBACK/pb4335_goback_returning_no_header_item` (2002) and
`pb4335-goback-returning-below-2002` (refused at 85, COBOL0900); exit codes in `StopGobackExitCodeTests`.
