# PB3610 — landings conflict on machine-maintained files; one structural merge, not a finisher per conflict

## Symptom

Landings conflict on shared machine-maintained JSON and pin files, and each conflict costs a finisher cycle (about 100 k tokens plus a re-gate). Measured 2026-10-23:

- `conformance-suite/wiseowl/diagnostics.json` (PB3570, attempt 000016)
- `tests/version-matrix/traceability-inventory.json` (wf_c0ed6078-78e-8)
- `tests/conformance/negative/manifest.json` (wf_d6f41ebf-faa-5)
- `tests/WiseOwl.Cobol.Tests.Unit/RuntimeAbiPinDriftTests.cs` (PR #460 bounce)
- kb/Work notes appended by two branches (PB296 vs PR #448; PB3528)

Evidence for the counts: the landing logs `E:\COBOL-coord\logs\land-lane-*.log` (grep CONFLICT).

**Sites:** `scripts/orchestrator/enqueue.py`, `.gitattributes`, a new key-wise JSON merge driver under `scripts/`, `tests/WiseOwl.Cobol.Tests.Unit/RuntimeAbiPinDriftTests.cs`, a new merge-driver drift test.

## Fix shape (rule 5)

One mechanism: a git merge driver. `.gitattributes` names a Python key-wise merger for the JSON catalogs and the verdict inventory, re-applying verdict batches as `record_verdicts.py` already does; appended-section markdown notes get a union merge. `enqueue.py land`'s merge step installs the drivers. A drift test asserts that every file the landing log has conflicted on in the last 30 days is covered by a driver. The runtime ABI pin is bumped at the LANDING from the merged tree, never by the branch, so two branches cannot bump it twice.

## Landed

Re-probe on this build (2026-10-24): the premise holds. The landing logs (`python scripts/merge_drivers.py --conflicts
E:/COBOL-coord/logs`) count 487 landing logs and the files they stopped on: `tests/conformance/2002/manifest.json` 15,
`tests/conformance/negative/manifest.json` 13 (both manifests are gone from the tree since the conformance suite
replaced them), `conformance-suite/wiseowl/diagnostics.json` 4, `RuntimeAbiPinDriftTests.cs` 4, the traceability
inventory 2, and kb/Work notes 7 over six notes. Prose docs (`DESIGN-runtime-library.md` 5, `CONFORMANCE.md` 2) and source
files stay real conflicts, resolved by a finisher.

One mechanism in two scripts (`scripts/merge_drivers.py`, `scripts/abi_pin.py`):

- **Merge drivers** for the keyed catalogues (`wiseowl/diagnostics.json` and `options.json`, the traceability inventory,
  `constructs.json`) and the work notes. Entries are read from the JSON STRUCTURE (constructs.json has entries at three
  indentations, and diagnostics.json holds raw § beside `\u00a7`, so a parse and re-serialize would rewrite the file),
  merged three-way per key and kept byte for byte. A key both sides changed differently falls back to git's line merge, so
  a finisher sees the usual markers. `DRIVERS` is the registry, `.gitattributes` repeats it, and `--check` with
  `MergeDriverDriftTests` hold the two together.
- **The runtime ABI pin is a measured file**, `src/WiseOwl.Cobol.Runtime/RuntimeAbi.pin`, replacing four constants in the
  test. `RuntimeAbiPinDriftTests` writes the measurement under `WISEOWL_COBOL_WRITE_ABI_PIN=1`, and `abi_pin.py bump|repin` is the author's one command. The pin's merge driver ADDS the counters two branches each
  raised (the finisher's derivation of 2026-10-24, major 18 over main's 17, made automatic) and marks the hashes
  UNMEASURED; the merge measures the merged tree (`abi_pin.py settle`) before its merge commit.
- **One function merges main in**: `merge_drivers.merge`. `enqueue.merge_main` uses it, and so do the finisher,
  golden-lane and predecessor-merge instructions (`plan_wave.py`, `wf_rolling_wave.js`, the briefs: a bare `git merge`
  falls back to a line merge). The review's coverage rule reads it through `merge_drivers.is_drivers_merge`
  (`prune_worktrees.mechanical`), so a merge the drivers made is mechanical and a hand resolution is not.

For the next implementer: `scripts/merge_drivers.py#merge` is the ONE merge of a ref into a branch (never a bare
`git merge`; `--keep` leaves a conflict for a finisher) and `#is_drivers_merge` is the ONE definition of "a clean merge of
main" the review's coverage reads; add a keyed catalogue by adding a `DRIVERS` entry and its `.gitattributes` line
(`--check` is red until both say it). `scripts/abi_pin.py#bump|repin|settle` is the only writer of `RuntimeAbi.pin` (the
test writes it under `WISEOWL_COBOL_WRITE_ABI_PIN=1`); a filtered `dotnet test` caller must run `filter_population.py` first and
scrubbed (three drift tests held that at the gate). Trap: an XML comment may not contain `--` (Directory.Build.props broke
every restore with NETSDK1013).

Estimate corrected (rule 5): the note said the pin is bumped at the LANDING, never by the branch. A branch's gate must be
green on its own tree, so the branch still raises its numbers (now by one command); what the landing owns is the merged
tree's hashes and the sum of the counters, which is what a conflict on the pin always required.

Review round 1 (2026-10-24), two merge-behaviour defects fixed in `merge_drivers.py`: a driver whose keyed merger declines now
lets git's own line merge decide (a clean result merges, as a plain `git merge` does; before, the clean fallback still exited 1
and stopped at CONFLICT), and `merge` answers None, with no commit, for a ref the branch already contains (before, the
empty merge commit failed and read as `CONFLICT in ?`). Both are self-test arms. Estimate corrected (rule 5): the fix shape's
drift test over the last 30 days of landing conflicts cannot run in CI, because the logs live outside the repository
(`E:/COBOL-coord/logs`) and prose and source conflicts are real. Its replacement is `merge_drivers.py --conflicts <logs>`,
which tells the covered files from the uncovered ones, plus `--check` and `MergeDriverDriftTests`, which hold the registry and
.gitattributes together; a new machine-maintained catalogue that starts conflicting is found by that report, not by a red test.
