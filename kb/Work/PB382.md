# PB382 — a funnel that names only the words the grammar already lets through

Found by the PB371/PB375 implementer (2026-09-03) while measuring PB375's false premise that `01 CLASS PIC X.`
is legal at `--std 85`. MEASURED at `--std 2023`, on the tree carrying the CLASS landing:

- `01 DESTINATION PIC X(4).` → `COBOLNET0901: 'DESTINATION' is a reserved word in COBOL-2023 and cannot be
  used …` — the correct, helpful answer, pinned by `conformance:negative/declined-validate-entry-name-still-0901`.
- `01 ALPHABETIC PIC X(4).` and `01 CLASS PIC X(4).` → `COBOL0001: no viable alternative at input '…'` plus
  `COBOL0307: unexpected '…'. A period may be missing at the end of the previous sentence.` — a wholly generic
  pair that says the syntax is bad rather than that the word is reserved, and whose second sentence is actively
  misleading (no period is missing).

Not created by the PB375 landing and not worsened by it: `01 CLASS PIC X.` behaved identically before and after
(verified on both trees).

## Root cause, one place

`VersionConformancePass.IsProvableUserWordPosition` can only fire once the parse has REACHED the entry-name
slot, and `CobolData.g4`'s
`dataName : cobolWord | FILLER | PROCEDURE | {reservedHere("COMMIT")}? COMMIT | {reservedHere("ROLLBACK")}? ROLLBACK`
admits only context-sensitive words (`cobolWord` is GENERATED from `cobol-words.json`'s nameSlot rows) plus four
named exceptions. A reserved word with a dedicated lexer token and no `cobolWord` membership — CLASS, ALPHABETIC,
ALPHABETIC-LOWER, ALPHABETIC-UPPER, NUMERIC and every §8.9 word of that shape — cannot reach the slot, so the
funnel never sees it. The population is mechanically enumerable: every `reserved-words.json` word with a
`CobolLexer.g4` token that is not a `cobolWord` alternative.

## What closes it

⛔ NOT "add these words to `cobolWord`" — that would make them legal user-defined words and contradict §8.9.
The shape is a recovery arm in the entry-name position admitting ANY reserved-word token solely so the funnel can
NAME it — which is what the four `dataName` exceptions already do by hand (PB137 added COMMIT and ROLLBACK
exactly that way, one word at a time: a hand-maintained list where a structure belongs, rule 5). The arm is
derived from the same generated reserved-word table, so the next reserved word is covered the day it is added;
a drift test enumerates the population and asserts every member draws COBOLNET0901 in a name slot; the
`dataName` exceptions fold into the arm. Wave-local gate `~ReservedWord|~CobolWords|~Declined`.

Harm classification: the source is illegal either way, so none of the four harm flags apply and the note is
`process_only` by the PB281/PB283 precedent — a misleading diagnostic is a defect the register cannot yet rank
(the resource/diagnostic-quality axis PB380 records as missing from the harm vocabulary).

## Append — 2026-09-09, registrar (second pass): a FOURTH population — the Report Writer words — measured, and it costs real debugging time

From the **PB528 implementer's report**, "New defects" (a) — `scratchpad/reports/PB528-report.md`. Filed here
rather than as a new note because it is **exactly this note's mechanism**: a reserved word written in a
data-name slot that `dataName` does not admit, producing the `COBOL0001` + `COBOL0307` pair whose "A period may
be missing at the end of the previous sentence" blames the *previous* entry.

### Re-measured on the registrar's own build at `d3ba5795`

```
$ cobol.exe p16_cf.cob --std 85
p16_cf.cob(5,11): error COBOL0001: no viable alternative at input 'CF'
p16_cf.cob(5,11): error COBOL0307: unexpected 'CF'. A period may be missing at the end of the previous sentence.

$ cobol.exe p16_cf.cob --std 2023      (identical)
$ cobol.exe p16b_ch.cob --std 2023
p16b_ch.cob(6,11): error COBOL0001: no viable alternative at input 'CH'
p16b_ch.cob(6,11): error COBOL0307: unexpected 'CH'. A period may be missing at the end of the previous sentence.
```

`registrar2/probe/p16_cf.cob` is `01 CF PIC 999CRCR.`; `p16b_ch.cob` is `01 CH PIC X(4).` after a
well-formed entry, so the "previous sentence" the message accuses is demonstrably fine. **`CF` = CONTROL
FOOTING and `CH` = CONTROL HEADING** — Report Writer abbreviations, §8.9-reserved, and natural data-names for
anyone writing report code.

### The cost, measured by the person who paid it

The PB528 implementer records: *"Cost me ~10 turns to diagnose; a message naming the word would have cost none.
(I renamed my golden's items to `PB01`…`PB18` rather than work around it.)"* That is the harm axis this note's
closing paragraph says the register cannot yet rank — an instance of it, priced.

### ⛔ Premise correction — do NOT inherit the report's clause numbers

The report cites *"ISO §8.10 (reserved words) and §8.4.1 (user-defined words)"*. Both are wrong, and both were
caught mechanically:

```
$ grep -n "^### 8.9 \|^### 8.10 " specs/ISO_COBOL.md
9023:### 8.9 Reserved words
9494:### 8.10 Context-sensitive words

$ python scripts/spec/cite.py --check 8.4.1 "user-defined word"
FAIL: §8.4.1 exists but does NOT contain 'user-defined word'

$ python scripts/spec/cite.py --find "A user-defined word is a COBOL word"
§8.3.2.2   (User-defined words)
```

§8.10 is **context-sensitive words** and §8.4 is **References**. The correct pair is **§8.9 (reserved words)**
— which is what COBOLNET0901 already prints — and **§8.3.2.2 (user-defined words)**. This is the inherited-clause
failure mode CLAUDE.md rule 1 names, caught before it reached a code comment.

### What it adds to the fix

Nothing structural — the recovery arm described above covers CF and CH the day it exists, because it is derived
from the same generated reserved-word table. What it adds is the **drift test's population**: the Report Writer
abbreviations are short, plausible data-names, so they belong in the enumeration the test asserts over.
