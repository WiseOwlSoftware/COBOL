# PB4938 - one fact, passed together, and pinned

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CallBinder.cs` (`CallBinder.ScreenCallOperand`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/ParameterConformance.cs` (`ParameterConformance.ScreenSection`), `conformance-suite/wiseowl/diagnostics/pb4901-call-debug-register-at-85.json` (whole: its expectation)

**Lead R2-2 (low).** PB4901's fix leaves the 1985 CALL storage-section rule decided twice. `CallBinder.ScreenCallOperand` chooses the CLAUSE to cite
(`ctx.Edition.Edition.Year < 2002` -> `§1985:X.5.2.3 SR3`, which names file, working-storage, communication and linkage; checked with `cite.py --check "§1985:X.5.2.3 SR3" "Linkage Section"`),
and `ParameterConformance.ScreenSection` picks the section LIST in the message text by its own `Edition.Year < 2002` test. The clause and the list it states are not one fact passed together: a third
caller (INVOKE is 2002+, but the next caller) can pass a 2023 clause with the 1985 list or the reverse, and the message then states a list its clause does not.
Expected: `ScreenSection` takes the rule (clause plus list) as one typed value chosen once, or derives the list from the clause it is handed.

**Lead R2-1 (low).** The golden `pb4901-call-debug-register-at-85.json` expects the section-list substring ("a data item defined in the file, working-storage, communication, or linkage
section"), changed from the citation substring in review round 1, so NO golden now pins the `§1985:X.5.2.3 SR3` citation, which was PB4901's defect (the diagnostic cited a 2023 rule at 85). The
list text comes from `ScreenSection`'s own edition test, independent of the clause `CallBinder` passes, so the golden would stay green if the clause regressed to `§2023:14.9.4.3 SR3`.
Expected: the golden expects BOTH substrings (the citation and the list), or two goldens. Pair with the typed-rule fix above so the pin follows the one fact.

Source report and leads: `w20261905f-PB4901-report.md`, R2-1 and R2-2.
