# PB385 — the citation tool's answer is right about the TEXT and wrong about the LABEL

Found by the round-2 golden writer `io-use-release-return` while citing §14.9.49.4's Format 3 declarative tiers;
**re-measured here**, and the scope re-derived rather than inherited — the writer reported four sites, the scan
finds **105**.

## The repro

```
$ python scripts/spec/cite.py --check 14.9.49.4 \
    "All format 3 USE statements in which file-name-2 is not specified and exception-name-1 is a level-2 exception-name are examined"
OK  §14.9.49.4 3) e)  (General rules)
    f) All format 3 USE statements in which file-name-**2** is not specified …
```

The excerpt it prints is **f)**. The label it reports is **e)**. The same command for the genuine e) reports
`3) e)` too, so two different rules answer to one citation and neither the caller nor `--check` can tell.

## The mechanism, read out of the transcription

`specs/ISO_COBOL.md` lines 28920–28934: sub-items **a) … e)** of §14.9.49.4 GR3 begin with three spaces of
indent; **f)** and **g)** begin at **column 0**. A column-0 line ends the indented list as far as the resolver
is concerned, so the last letter it saw — `e)` — is what it attributes the next paragraph to. The same
paragraphs also carry stray emphasis the indented siblings do not (`file-name-**2**`, `level-**2**`), which is
the tell that they came through a different path in the OCR pipeline.

**It is not local.** Scanning for a column-0 `x)` paragraph that continues an indented `a)`/`b)`/`c)` run within
twelve lines:

```
column-0 sub-items continuing an indented a)/b)/c) run: 105
   line   2803  b)  continues a) at 2797
   line   3042  b)  continues b) …
   line   8677  e)  through   8695  n)   (the §8.8.4.4.4 class-condition ladder — TEN consecutive items)
   line  11996  c)  d)  e)              (the intermediate-rounding phrases)
   …
```

so whole ladders of rules — the class-condition list, the intermediate-data-item rounding phrases, the CALL
BY CONTENT/BY VALUE sequence, the REPLACE cancellation rules — are all citable only under their first indented
sibling's letter.

## Why it matters more than a formatting nit

CLAUDE.md rule 1 makes `cite.py --check` the mechanical guard against the **inherited citation**: a quoted
sentence that is genuinely in the standard under a clause number nobody re-derived. This defect produces exactly
that artifact **from the guard itself** — the text is verified, the label is wrong, and a caller who does the
right thing still writes a wrong rule id into a code comment, a golden header, a design doc or a DEVLOG entry.
Two CA10 citations were wrong this way before; this makes the same wrongness reachable through the correct
procedure.

## Fix shape

Two parts, and the second is the one that keeps it fixed.

1. **Repair the transcription** (`specs/` is a private submodule, so this is a submodule commit plus a gitlink
   bump): re-indent every column-0 continuation sub-item to the three spaces its siblings carry, and strip the
   stray `**` emphasis those same paragraphs picked up. The 105 sites are mechanically identifiable by the scan
   above, so this is a scripted repair with a diff to read, not 105 hand edits.
2. **Give `cite.py` a drift check that fails on the shape**, not on the 105 instances: no clause may resolve two
   distinct paragraphs to one `§ n) x)` label. That is decidable from the transcription alone, it is what a
   reader of a citation actually relies on, and it makes the next lossy paragraph fail loudly instead of
   answering plausibly. Without it a re-transcription reintroduces the class silently.

⚠ Before repairing, render the printed page for a sample of the 105 (`scripts/render-spec-page.py`) and confirm
the printed standard really does letter them as continuations — `feedback_spec_diagrams_render_pdf`: the OCR was
lossy in a known direction and the indentation is the only evidence the resolver has.

`inventory_rows` is deliberately EMPTY: this defects no compiler behaviour, so no traceability row is
outstanding because of it. What it defects is every future citation, which is why it is filed rather than left
in a report.
