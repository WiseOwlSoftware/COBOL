# PB4755 - BlankLandingRun: suppressed Z positions after the floating string drop digits

**What the report says (R2-1, low, recorded as a lead because a re-review does not re-open round 1 content; the report says the
severity is that scope, not the harm).** `BlankLandingRun`'s walk stops at the floating string's end, but its run of spaces also
takes the suppressed Z positions after the string (SR12 b admits Z beside a FOR character-1), so the widths never add up, the
method returns null, and the per-position reads then drop digits. The report calls it a silent wrong value and a regression
against main. It is outside the round's diff (`CobolEdit.cs:965`).

**R1.** PB4703 (landed) added `BlankLandingRun`; this is its defect, not covered by an open note.

**Sites:** `src/WiseOwl.Cobol.Runtime/Values/Numeric/CobolEdit.cs#BlankLandingRun` (a second walk past `z.End` sums the suppressed positions right of the string), `tests/WiseOwl.Cobol.Tests.Unit/CobolEditStoredSignTests.cs` (`DeEdit_FloatingExtendedSignBlankWideLandingBeforeSuppressedZ_RoundTrips`), the golden `conformance-suite/cases/13.18.40.5-Editing-rules/pb4755_deedit_for_floating_blank_landing_before_z`.

**Fix.** Re-probe 2026-11-05: `PIC LLLZZ9 EDITING L FOR NEGATIVE IS "(("` holding 5 as `      5` de-edited to +00000. `BlankLandingRun` now continues the width sum past the string through the positions to its right when the run outlasts the string (the landing is the string's last position, rule 6 a).
