# PB3593 — the PB3568 class remark misreads ISO 4.2.6 paragraph 3

**Blocked on PB3568:** the files named below exist only on PB3568's branch (`worktree-wf_37d4041f-6f7-25`) until it lands.

## What the review found

`DeclinedFacilityBinder.cs` (class remark, about line 16) and `DeclinedFacilityOperandDriftTests.cs` (docstring, about line 19) cite ISO 4.2.6 paragraph 3 for the claim that declining a facility licenses its BEHAVIOUR to be absent but never its SYNTAX RULES. Paragraph 3 of §4.2.6 says the opposite for an unsupported processor-dependent element: the warning mechanism "is not required to diagnose syntax errors within this unsupported syntax". Checked: `python scripts/spec/cite.py --check 4.2.6 "not required to diagnose syntax errors within this unsupported syntax"` returns OK (§4.2.6, paragraph 3: "An implementation shall provide a warning mechanism at compile time ...").

PB3568's binding of the declined statements' identifiers is therefore a quality choice (GnuCOBOL refuses an undefined name; PB3568's §14.9.50.3 SR citations name the rules it follows), not something §4.2.6 requires. The remark must say so. Whether the MCS and VALIDATE facilities are processor-dependent (A.3) or optional (A.4, where §4.2.7 applies instead) is a spec question for the implementer to settle with a checked citation before rewording; it was not decided here.

The MCS syntax rules the binder does NOT check are recorded in neither the remark, the PB3568 note nor `docs/CONFORMANCE.md` §4 item 1, which names only the SEND TO operand and the message-tag class checks as residuals: RECEIVE §14.9.31.3 SR2 and SR3, SEND §14.9.38.3 SR1 and SR3 (PB3568's report also names VALIDATE SR3, blocked by COBOLNET1708, as a residual). Each clause number is unverified here; the implementer runs `cite.py --check` on each before writing it down.

## Fix

Reword the remark and the docstring to state the actual §4.2.6 position and the reason the operands are bound anyway; list every unchecked MCS and VALIDATE syntax rule, each with a checked citation, in `docs/CONFORMANCE.md` §4 item 1 (the current-state doc, no history).
