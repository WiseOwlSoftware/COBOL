# PB5652 - an unprefixed SUM intrinsic in a report clause expression does not parse at --std 2002

**Sites:** `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolLexer.g4#IsReportSumClauseKeyword` and `#ReportOperandFollows`
(the root: the report-region exception applied where an operand is owed), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs#BindIntrinsic`
and `#ReportSumClauseWord` (the 2014 SR9 refusal, COBOL7933), `src/WiseOwl.Cobol.Editions/Diagnostics/DiagnosticCatalog.cs#ReportSumWithoutFunctionKeyword`.
The grammar file the writer named (`CobolReportWriter.g4`) needed no change.

**Site (lead, from the writer):** `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolReportWriter.g4#reportSumClause` and
`#reportValueOperand`: a report-clause expression always takes `SUM` as the SUM clause keyword, the 2014/2023 reading.

**Rules (each checked with `python scripts/spec/cite.py --check`, verdict OK).**

- `§2002:13.16.52.2 SR1`: "Each data-name-1, identifier-1 or arithmetic-expression-1 is an addend"
- `§2002:8.4.2.2.2 SR2`: "the word FUNCTION may be omitted" (when the intrinsic function name is specified in the REPOSITORY paragraph)
- 2002 has no counterpart of the 2014/2023 SUM rule that makes an unprefixed SUM in a report description entry the clause
  keyword, so at 2002 `SUM OF WA + SUM(WB WC)` is one SUM clause whose single addend is the arithmetic expression
  `WA + SUM(WB WC)`; the keyword reading of the second SUM leaves `SUM OF WA +` with no valid parse.

**Repro** (`E:/COBOL-coord/scratch/gl2002/lane1/run/g2002-13-16-52-sum/fsum/fsum.cob`; `cobol.exe fsum.cob --std 2002 --run`):

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. FSUM.
       ENVIRONMENT DIVISION.
       CONFIGURATION SECTION.
       REPOSITORY.
           FUNCTION SUM INTRINSIC.
       INPUT-OUTPUT SECTION.
       FILE-CONTROL.
           SELECT PRT ASSIGN TO "fsum.txt".
       DATA DIVISION.
       FILE SECTION.
       FD  PRT REPORT IS R1.
       WORKING-STORAGE SECTION.
       01  WA PIC 9(3) VALUE 1.
       01  WB PIC 9(3) VALUE 10.
       01  WC PIC 9(3) VALUE 100.
       REPORT SECTION.
       RD  R1 PAGE LIMIT 20 LINES.
       01  DET TYPE DE LINE PLUS 1.
           03  COLUMN 1  PIC 9(4) SUM OF WA + SUM(WB WC).
       PROCEDURE DIVISION.
       MAIN.
           OPEN OUTPUT PRT.
           INITIATE R1.
           GENERATE DET.
           TERMINATE R1.
           CLOSE PRT.
           DISPLAY "SUM(WB WC) IN PROC = " SUM(WB WC).
           STOP RUN.
```

Expected: compiles; the report line is `0111` (1 + 110). Observed (main b15bb9088f): `fsum.cob(20,54): error COBOL5506:
cannot parse construct near 'WC'`, rc 65. Sibling `.../fsrc/fsrc.cob` (`SOURCE IS WA + SUM(WB WC)`) is the same COBOL5506
at (20,57). Control `.../fsum/fsumf.cob` (FUNCTION SUM written) compiles and runs, and its procedure-division `SUM(WB WC)`
prints 000000110, so the REPOSITORY declaration itself works.

**Rows.** 2002-SR-13.16.52.2-1 (its other addend forms are witnessed by G2SUM01; this leg waits on the fix).

**Sibling sweep.** Every report clause that takes an expression (SOURCE, SUM, PRESENT WHEN, VARYING) with an unprefixed
REPOSITORY intrinsic, and the edition gate of the 2014 keyword rule itself (it applies from 2014 only).

**Landed (2026-11-22, wave 20262146 group M).** The root was the lexer, not the report grammar: `IsReportSumClauseKeyword` made
EVERY bare SUM in the REPORT SECTION the clause keyword (PB924's SR9 region), so the '(' of a keyword-omitted SUM call was a
grouping paren and `SUM(WB WC)` could not parse. The exception now holds only where a clause can begin; where the entry owes an
operand (inside a parenthesis, or after an arithmetic operator, SOURCE IS, SOURCES ARE, SUM OF, PRESENT WHEN, VARYING's FROM/BY,
a relational word) `SUM (` keeps the reference paren the keyword-omitted call reads. The lexer reads no edition: at 2002
(§2002:12.2.7.3 GR13, no SR9) the tree binds as the REPOSITORY intrinsic; from 2014 (§2014:13.18.54.2 SR9, §2023:13.18.54.3 SR9)
IntrinsicBinder refuses it by name, COBOL7933, where it used to be the raw COBOL5506. Re-probe on the fix: fsum/fsrc print 0111 at
2002, sumsrc prints 0006; all three are COBOL7933 at 2023. Witnesses: g2sum07 (accepted at 2002), g2sum08 (refused COBOL1543 at
85/2002, no REPOSITORY), pb5652-report-sum-unprefixed-sr9 (refused COBOL7933 at 2014/2023); the 2023 row SR-13.18.54.3-9 now
carries editions 2014,2023.
