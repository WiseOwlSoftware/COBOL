# PB1672 — OPEN

Filed 2026-09-27 by the train-68b lander from the wave-68 Z implementer report (`w68z-PB1084-report.md`,
"Observation"): the implementer called it no defect; the registrar question it raised is a documentation gap.

**What happens.** A universal INVOKE whose arguments do not conform, into a method with EC-OO-UNIVERSAL checking
disabled at its procedure division header (PB1381's fold), ends the run unit with a
`CobolImplementorFatalException` that carries no EC name (so no declarative can select it).

**Rule.** §14.6.13.1.1 (`cite.py --check 14.6.13.1.1` OK) governs raising when checking is enabled; with checking
disabled the results are undefined (the code comment cites §14.6.13.1.1 NOTE 3's undefined-results latitude), and
§14.9.23.4 GR7 c) raises EC-OO-UNIVERSAL only when checking is enabled in both elements. A latitude choice is
recorded in `docs/CONFORMANCE.md` (CLAUDE.md rule 1) — this one is not.

**Code site.** `src/Cobol.Net.Compiler/CodeGen/Verbs/OoEmitter.cs#OoUnivStop` / `#OoUnivThrow` (the summary
documents the choice); `docs/CONFORMANCE.md` has no EC-OO-UNIVERSAL entry.

**What the fixer owes.** Re-derive NOTE 3's number with `cite.py --check`, then a CONFORMANCE.md row naming the
choice and its authority (ISO latitude → GnuCOBOL's behavior per the owner's precedence).

## Refinement (train 69, 2026-09-28): the fatal stop may be nonconforming, not only undocumented

The wave-69 Z finisher (`w69z-PB1084-report.md`, "New defects") read §14.9.23.4 GR7 c) (`cite.py --check 14.9.23.4
"execution continues as specified in General rule 7g"` → OK §14.9.23.4 7)): on a conformance violation the
invocation "is not successful, and execution continues as specified in General rule 7g" — a rule that does not
depend on EC-OO-UNIVERSAL checking being enabled in both elements (that condition decides only whether the EC is
SET). If that reading holds, `OoEmitter.OoUnivStop`'s run-unit-ending fatal stop is a wrong behavior, not a
latitude choice to document: with checking disabled the invocation should still fail and continue per GR7 g)
(the ON EXCEPTION / unsuccessful-invocation path). The fixer owes the adjudication of that reading first
(spec-lookup; the refuter on the verdict), then either the GR7 g) continuation or the CONFORMANCE.md row this note
already asks for. Code site unchanged: `src/Cobol.Net.Compiler/CodeGen/Verbs/OoEmitter.cs#OoUnivStop`.
