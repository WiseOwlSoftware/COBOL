# PB4078 — `_scalar` passes a malformed double-quoted scalar silently

**Sites:** `scripts/spec/work.py` (`_scalar`)

**Where the code is.** `_scalar` (PB3812) is NOT on origin/main yet: branch `worktree-wf_484eb705-564-32` (PR #791, PB3797, reviewed head `e1b97d1ed`) carries it; read it with `git show e1b97d1ed:scripts/spec/work.py` (the function at line 259, the closing-quote test at line 270). PB3812 reads `landed` on that branch and `open` on main, so the implementer re-reads `_scalar` on the landed code.

**What happens.** `_scalar` promises that a malformed double-quoted scalar is a reported error (`unterminated-quote`), never a silent pass. It tests only `len(v) < 2 or v[-1] != quote`. Two invalid YAML shapes therefore read without an error code: (1) an unescaped quote inside the value (the middle quote ends the scalar in YAML, and the last character is still a quote); (2) a value whose closing quote is itself escaped (a backslash right before the final quote: the quote is the escape's target and the scalar never closes). The reader's fail-open doctrine (the module docstring) wants a reported third answer for both.

**Fix.** Scan the inner text once: a quote that is not preceded by an odd run of backslashes ends the scalar and must be the last character, else the code is `unterminated-quote` (or a new code for a stray quote); an odd run of backslashes before the final quote means the closing quote is escaped. Add one case per shape to the `scalars` section of `tests/version-matrix/work-frontmatter-cases.json`, so `--self-test` holds them.

**Repro.** Not re-probed (R2: the lead names the code site and both shapes, found by reading). The reviewer's words: "an unescaped quote inside the value, and a value whose closing quote is itself escaped, are both invalid YAML and both read without an error code."
