# PB1195 — OPEN

## The rule (every citation re-run by the registrar through `cite.py --check`)

> 6) The logical record released by a successful execution of the REWRITE statement is no longer available in the record area unless file-name-1 or the file-name associated with record-name-1 is specified in a SAME RECORD AREA clause …

`python scripts/spec/cite.py --check 14.9.35.4 "…"` → `OK  §14.9.35.4 6)  (General rules)`

## Refuter evidence — row `GR-14.9.35.4-6` (DIVERGES)

DIVERGES — The adjudicator probed only character-window records. Under determination D-FRA (FileModel.IsOutOfLineRecord, PB981) a dynamic-length elementary record (and pointer-class record) is OUT-OF-LINE: it does not overlay the shared character area, and only READ/RETURN (EmitRecordAreaStore) copies into it. Neither REWRITE emitter propagates the released record to out-of-line records of the SAME RECORD AREA, so GR6's 'also available as a record of other file-names referenced in the same SAME RECORD AREA clause' fails whenever either side is out-of-line. DYNAMIC LENGTH carries no File Section restriction (13.18.19.3) and the compiler accepts it.

**Code site.** src/Cobol.Net.Compiler/CodeGen/Verbs/SequentialIoEmitter.cs#SequentialIoEmitter.EmitRewrite; src/Cobol.Net.Compiler/CodeGen/Verbs/KeyedIoEmitter.cs#KeyedIoEmitter.EmitRewrite

## What the fixer owes

SequentialIoEmitter.EmitRewrite and KeyedIoEmitter.EmitRewrite must run the same SAME-RECORD-AREA propagation READ/RETURN use (EmitRecordAreaStore) for out-of-line records (FileModel.IsOutOfLineRecord, PB981). Sweep WRITE's twin rule (§14.9.51.4, the record 'also available' under SAME RECORD AREA) and RELEASE. Golden with a DYNAMIC LENGTH record in one FD of a SAME RECORD AREA pair.
