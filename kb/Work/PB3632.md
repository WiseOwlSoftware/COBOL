# PB3632 — the sidecar host cannot tell "takes no lock here" from "races exhausted"

Filed 2026-10-24 by the clerk from `E:/COBOL-coord/scratch/reports/w20261028c-PB3518-report.md`, Review LEAD (low; wave 20261028,
landed as PR #490). Related: PB3518 (landed; it fixed the handle host and left this host's question open). Not re-probed by the
clerk.

**Mechanism.** In `SidecarColumnLockHost.cs` (line 59) and `SidecarLockFiles.cs` (line 109) a null Publish result covers two
causes: the host takes no lock at this site, and every race try collided. The exhausted case therefore answers Unavailable
without testing the refused columns, where PB3518 made the handle host test them first (Table 19, §14.9.27.4: a held column that
refuses the request answers refused, not Unavailable). The fix needs a Publish result that tells the causes apart; whether
the user program sees status 61 or the Unavailable mapping is the open question PB3518 recorded for an adjudicator.

**Sites:**
- `src/Cobol.Net.Runtime/IO/Sharing/SidecarColumnLockHost.cs` (line 59)
- `src/Cobol.Net.Runtime/IO/Sharing/SidecarLockFiles.cs` (line 109)

## Landing

For the next implementer: `SidecarLockFiles.Publish` now returns a `RegionLockResult` (`Ok` with the holder in `out holder`;
`Unavailable`: the host takes no lock here; `Held`: every try lost its race) and its callers decide. The refused-column test is
`SidecarColumnLockHost.Unpublishable` (shared with the lock directory a user may not write, PB2917); `SidecarRegionLocks.Hold` looks
at the holders after `Held`. `SidecarLockFiles.RaceInjector` is the test seam that loses attempts (beside `PauseObserver`); a
witness of a WAITING hold that must see a live conflict lets the holder go from another thread, because a waiting hold looks before it publishes again; a waiting hold finding nothing in the way after a lost round publishes ONE more round before Unavailable (review R1-1), witnessed in one thread by releasing the holder from the injector.

Re-probe on a fresh build: the lead was real in BOTH callers, and the note named one. The open question PB3518 left is answered as
it answered the handle host's: a refusal is a conflict with an existing connector (ISO 14.9.27.4 Table 19; 9.1.13.9 1) '61'),
failing to publish is a host limit that is not one, so a holder Table 19 refuses refuses, and nothing else is refused for the failure.
Witnesses: `SidecarColumnLockHostDriftTests.AnExhaustedPublicationBesideAHolderTable19RefusesIsRefused_AndOneNothingRefusesIsUnavailable`
and `RegionLocksDriftTests.AHoldWhoseEveryPublicationTryLostItsRace_IsHeldByAConflictingHolder_AndWaitsForIt` (both red on the old arms).
