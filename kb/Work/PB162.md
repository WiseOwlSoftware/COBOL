# PB162

Battery #30 (2026-08-29): PB130's Format-1 narrowing is ISO-correct — §14.9.4.2 Format 1 prints
BY REFERENCE and BY CONTENT `{identifier-2}` only, no BY VALUE, no literal operands — and the four
differential flips (run_extensions:25/3435/3460, run_misc:1624: `CALL "dump" USING X-1 BY CONTENT 1`,
`CALL "C$TOUPPER" USING X BY VALUE 2`, `USING BY CONTENT LENGTH OF MYTAB`) are all strict rejections of
GnuCOBOL EXTENSIONS, re-baselined with this attribution. Not legal source; nobody gets a wrong answer.

The debt ([[project_dialect_two_axes]]: every leniency is dialect-gated): real-world COBOL writes these
spellings, and `--permissive` currently has no lane for them — the SR22 class screen already
warn-downgrades under permissive (`ValueClassScreen`), but the FORMAT narrowing (`CallContentOperandFormat`
/ the BY VALUE arm reject in CallBinder.BindCall) errors unconditionally. The fix shape: under
`ctx.Edition.Permissive`, accept the Format-1 vendor spellings with a warning and bind them with the
Format-2 semantics they obviously intend (a literal/expression → a detached BY CONTENT value; BY VALUE →
Value mode), keeping the strict lane exactly as landed by PB130/PB132. Survey IBM/MF/Fujitsu acceptance
before wording the warning ([[feedback_survey_compilers_on_latitude]]).

## Landed — wave 56 (fix lane F)

Re-probed on the wave-56 build: `CALL "S" USING X BY CONTENT "WXYZ"`, `USING BY VALUE N` and `USING X "QRST"` drew three
COBOLNET0899 **errors** under `--permissive`. Fixed at the ONE place the narrowing is framed: the five Format-1 sites
in `CallBinder.BindCall` (BY CONTENT literal/expression, BY VALUE, bare literal / boolean / arithmetic expression)
now all call `Format1VendorSpelling` — strict: the unchanged error (`OK §14.9.4.2` "Format 1 (Program)" prints
identifier-2 only); `--permissive`: the same code as a WARNING, and the argument binds with the Format-2 semantics it
spells (a detached BY CONTENT value, the Value mode). Measured after: `A=abcd B=WXYZ`, `A=abcd B=QRST`, `V=000000002`,
`V=000000005` (BY VALUE 5), `V=000000003` (BY VALUE N + 1), `D=7`, and N unchanged at 2. Survey (CLAUDE.md rule 1):
GnuCOBOL accepts all five spellings; IBM Enterprise COBOL and Micro Focus accept BY VALUE and a BY CONTENT literal.
No new diagnostic code. Evidence: `conformance-test:FormatOneVendorCallPermissiveTests` (strict rejects all six
spellings; permissive warns six times and runs to the derived values). Design: COBOLNET_INTERPROGRAM_DESIGN.md.
