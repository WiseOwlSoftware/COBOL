# PB1021 — LANDED

## Landed (2026-09-22, wave 54 group H)
Re-probed first on the implementer's own build (merged with train 52's PB239 branch, which carries the rule):
`q15_invaddr.cob` → `(9,19): error COBOL0001: cannot parse construct near 'ADDRESS'`, `q16_invaddr2.cob` →
`(13,31): error COBOL0001: unexpected 'ADDRESS'`. Both reproduced.

**Fix.** The ONE `addressIdentifier` rule (§8.4.3.1.2 Format 9, PB239) now joins `comparisonOperand` (the
§8.8.4.2.2 Format 3 identifier-3 / identifier-4, which the abbreviated relation reaches through the same rule), every
`invokeArgument` phrase, and the §8.4.3.4 inline form's `argument`. It binds through the ONE
`PtrBinder.BindAddressIdentifier` into a new `BoundAddressOperand` (no Place — the unique data item §8.4.3.11.4 GR1 /
§8.4.3.13.4 GR1 create has no program storage); the ONE category and class classifiers answer data-pointer /
program-pointer and class pointer, so the existing §8.8.4.2.3 SR5 band (COBOLNET0869) screens it with no change;
`ConditionRenderer`'s pointer arms read it through `PtrEmitter.AddressOperandText`. The INVOKE argument conforms by the
ONE §14.8.2 class-pointer verdict (`CallBinder.AddressConformanceReason` MOVED to `PtrBinder`, so CALL and INVOKE read
one copy) and crosses verbatim, never writing back (§14.9.23.3 SR19). The program arm's miss as an ordinary operand is
`ProgramRegistry.EntryOfOperand` (fatal EC-PROGRAM-NOT-FOUND in-statement, §8.4.3.13.4 GR4); the CALL argument keeps
its GR3a delivery. A sign / bare condition over an address-identifier names SR1 / §8.8.4.2.1 (COBOLNET2318) instead of
falling to the internal-error net; the class condition already refused class pointer (COBOLNET2200).
The storage forcing and the 2002 gate (COBOLNET0900) reach the new surfaces automatically.

**Goldens.** `conformance:2002/pb1021_address_identifier_operands` (eight relations incl. the abbreviated and the
program arm; INVOKE bare / BY REFERENCE / BY CONTENT / inline / program arm, each proving the value by §8.8.4.2.16);
`conformance:negative/pb1021-address-identifier-relation-at-85` (COBOLNET0900).

**Residue (leads, not this note).** EVALUATE subject/object (`evaluateSubject` / `evaluateWhenItem` read
`valueOperand`) and the function-identifier argument (§8.4.3.2.3 SR8/SR10) are further identifier positions an
address-identifier may occupy; the INVOKE BY VALUE arm parses but meets the pre-existing BY VALUE method-formal
limitation (COBOLNET0899).
