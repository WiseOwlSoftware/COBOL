# PB1021 — OPEN

## Repro — measured
`scratchpad/reg12/q15_invaddr.cob`: `IF P = ADDRESS OF X` → `q15_invaddr.cob(9,19): error COBOL0001: cannot parse construct
near 'ADDRESS'`. `scratchpad/reg12/q16_invaddr2.cob`: `INVOKE O "M" USING ADDRESS OF X` → `(13,31): error COBOL0001:
unexpected 'ADDRESS'`.

## The rule
`OK  §14.9.23.3 9)` — "Identifier-3 shall be an address-identifier or shall reference a data item defined in the file,
working-storage, local-storage, or linkage section." Format 9 of §8.4.3.1.2 (address-identifier) makes it an identifier;
the relation condition's operands are identifiers (§8.8.4.1 — the fixer re-derives the exact relation-operand rule with
`cite.py --check` before golden-ing the IF arm).

## What the fixer owes
Add `addressIdentifier` to the INVOKE argument and relation-operand rules exactly as PB239 adds it to CALL (grammar
pre-authorized); the storage forcing and the 2002 edition gate then apply automatically. Goldens: INVOKE BY VALUE /
BY CONTENT with ADDRESS OF, and IF P = ADDRESS OF X both ways.
