# R49

Asked 2026-09-25: the orchestrator evaluated the Claude / Claude Code functionality available to the campaign and
ranked twelve recommendations by payoff (better source, build and test, token economy). The owner answered each:

| # | Recommendation | Answer | Where it landed |
|---|---|---|---|
| 1 | Run fleets through the Workflow tool | **Standing opt-in** — never ask per session | MANDATORY-PRACTICES O4; workstream SKILL.md |
| 2 | Hooks that block the rules agents forget | Adopt as recommended | `scripts/hooks/forbidden_commands.py` (+ self-test in CI `audits` and build-local); `.claude/settings.json` deny rules; P12 |
| 3 | Longer prompt cache for subagents | Do | `experimental.cacheTtl: 1h` in each `.claude/agents/*.md` (there is no global subagent setting) |
| 4 | Match model and effort to the job | Do | `.claude/agents/cobol-{implementer,lander,refuter,adjudicator,clerk}.md`; `agentType` in the wf templates |
| 5 | OpenTelemetry cost attribution | Do | `scripts/telemetry/otlp_sink.py` + `usage_report.py`; enabled per machine in `.claude/settings.local.json`; O5 |
| 6 | `claude plugin eval` for the skills | Do | `evals/` in BrentRector/claude-skills |
| 7 | C# language server for the LSP tool | Do | `csharp-ls` 0.28.0 installed as a global dotnet tool (the `csharp-lsp` plugin was already enabled) |
| 8 | A review pass as a lander step | Do | lander-train-brief step 5b; L9 (`/code-review` itself is interactive-only) |
| 9 | Role guardrails in agent definitions | Do | refuter/adjudicator carry `scripts/hooks/readonly_repo.py` (+ self-test) |
| 10 | A routine for the daily resume | **No** | the session cron stays |
| 11 | `/skill-doctor` pruning | Do | interactive-only: the owner runs it; the orchestrator prunes from its report |
| 12 | `/compact` at task boundaries | **Deferred** until evaluated for value | — |

**Safeguard (rec. 4):** a role whose refuter overturn rate rises after moving off `xhigh` is moved back; telemetry
(rec. 5) supplies the per-role cost side of that comparison.

**Measured on adoption:** the guard hook fired on the orchestrator's own heredoc (a `\n` escape inside a Python
heredoc) within minutes of being registered — the exact shape it exists for.

**Follow-up the same day (owner):** "We must integrate these additions/changes into our skills and/or ensure they are
used in all new sessions" and "It should not require manual intervention to use these. If my explicit permission for
something is required, automatic use of such a feature should trigger a query to me, not silently failure to use it."
Landed as `scripts/hooks/tooling_check.py`, run by the SessionStart hook every session: each capability is CHECKED
(OK / REPAIRED / N/A / **ASK-OWNER**); the telemetry sink is started automatically when down; anything needing the
owner (enabling telemetry or the LSP on a new machine, the weekly `/skill-doctor`) prints ASK-OWNER, and the
session-start skill step 3b + MANDATORY-PRACTICES O6 require one AskUserQuestion per ASK-OWNER line. O7 makes the
trigger-bound owner steps (`/code-review ultra` at a multi-train battery close; public-skill evals before a push) a
question at their trigger. P13 + the implementer dispatch template carry the LSP-first navigation rule.
