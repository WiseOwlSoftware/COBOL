## Arm 2 — one record, a dynamic-length member, WRITE aborts the run unit (main)

Found in the wave-48 PB829 implementer report's lead 1 (`w48w/probe/d1_fd.cob`) and re-run here as `reg11/fdd.cob`:
`FD F.` (LINE SEQUENTIAL) `01 R. 05 A PIC X(3). 05 D PIC X DYNAMIC LENGTH LIMIT 20.` `OPEN OUTPUT F` `WRITE R` →
**`Unhandled exception. CobolNet.Runtime.NotImplementedCobolFeatureException: … record-area image of 'R' with a
dynamic-length / dynamic-capacity member (a variable-length group has no fixed record window) — the Tier-C byte island
(no whole-group character image), deferred; COBOLNET_DESIGN §4.2`**. No open note owned it (the Tier-C notes PB164,
PB176, PB204, PB393, PB485, PB504 are all landed). It is the same missing shape at the same boundary: a record area
whose member has no fixed character window.

## Rules

- `python scripts/spec/cite.py --check 13.18.33.4 "Multiple level 1 entries subordinate to a FD or SD entry represent implicit redefinitions of the same area"` → OK §13.18.33.4 3)
- `… --check 13.18.60.3 "may be specified only for an elementary data item at level 1"` → OK §13.18.60.3 14) — a
  POINTER / PROGRAM-POINTER / FUNCTION-POINTER record at level 1 is legal in the file section.
- `… --check 13.18.60.3 "The USAGE OBJECT REFERENCE clause shall not be specified in the file section"` → OK §13.18.60.3 15) —
  the ONE class that stays refused, and it must be refused under SR15 by name.

No syntax rule forbids a dynamic-length or variable-length record from sharing an FD's area; the REDEFINES-clause
rules (§13.18.44.3) govern an explicit REDEFINES only (PB836's subject).

## What the fixer owes (after, or together with, the PB836 landing)

The shared record area is a storage shape the typed-native model must represent: an imageless member (a managed
pointer slot, a dynamic-length string, a dynamic-capacity table) overlapping character records of the same file.
Sites named by the source report: `DataBinder.ComputeTier`'s carrier arm, `StorageFormPass.Classify` arms 1/1b, and
`DataBinder.ClassifyRedefinesClasses`' implicit arm. Determine (CONFORMANCE.md) what a READ into the area does to the
imageless record and what a WRITE from it sends — the file boundary is where bytes are legitimate (memory
`typed_native_only`), and D-DL3's recorded layout for a dynamic-length item (PB829's lead 1, an FD record with a
dynamic-length member crashing at WRITE) is the same boundary. SAME RECORD AREA (§12.4.6.4.4 2)) is the
cross-file twin and gets the same shape. Goldens at 2002 (pointer) and 2023 (dynamic length).
