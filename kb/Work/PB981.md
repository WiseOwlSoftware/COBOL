## Landed

**2026-09-22, wave 52 finisher (on the wave-51 CG branch).** Every probe re-run on this tree's own build first:
`fdp`/`fdq` drew COBOLNET0899 (train 48's staged shape), `fdd` threw NotImplementedCobolFeatureException at WRITE.
All three now compile and run.

**Determination D-FRA** (docs/CONFORMANCE.md §3 — `cite.py --check` OK for §13.18.33.4 3), §8.5.1.10.3,
§8.5.1.10.2, §8.5.1.11.2, §13.18.43.4 5), §14.9.30.4 14), §12.4.6.4.4 2), §13.18.60.3 14)): a dynamic-length
record, a variable-length group or a pointer-class record is an OUT-OF-LINE record. §8.5.1.10.3 lets a
dynamic-length item be "located elsewhere", so it is not linked into the character area's class; the ONE area is
realized at the transfer boundary. A READ/RETURN makes the current record, at its own length, available in every
out-of-line record of the area and of its SAME-clause peers. A WRITE/REWRITE/RELEASE sends the contiguous image
(§8.5.1.11.2), and the implied RECORD clause is Format 2 when a record is variable-length (§13.18.43.4 GR5).
GnuCOBOL, IBM and Micro Focus do not admit a dynamic-length item in the file section, so none of them is a model
to follow.

**The shape.** `FileModel.IsOutOfLineRecord` is the ONE predicate. `DataBinder.LinkImplicitRecordArea` is the ONE
linker; the FD and SD arms used to spell the loop twice. `SequentialIoEmitter.EmitRecordAreaStore` is the ONE store,
serving sequential READ, keyed READ and SORT RETURN. `OperandText.RecordAreaImage` carries the out-of-line arms.
`CobolVarGroup.FromContiguous` is the ONE split rule. `FileConnector.CurrentRecord` / `NoteRecordRead` are the
single writer beside `LastReadLength`. `RecordMax` is the GR14/GR15 truncation bound, kept separate from the area
width so that an unlimited dynamic-length record does not size every READ buffer. The PB836 implicit-area COBOLNET0899
arm keeps only the ComputeTier residue.

**Siblings swept.** The SD arm: `SortRecordOf` admits a variable-length record, and a key after a variable-length
member is refused by name. The SORT USING transfer now releases the current record. The SAME RECORD AREA arm now
has peers. EXTERNAL FDs: an out-of-line record is staged loud, because the run-unit cell would carry only the
character half.

**Goldens.** `conformance:2014/pb981_fd_variable_length_records`, `conformance:2002/pb981_fd_pointer_record`,
`conformance:negative/pb981-fd-dynamic-length-record-at-2002`. Unit: `ImplicitRecordRedefinitionTests` (one row
per out-of-line shape, plus the SAME twin) and `CobolVarGroupContiguousTests`. **Row** GR-13.18.33.4-3 was
re-verdicted CONFORMS with its stale "staged loud" note restated (batch `pb981-out-of-line-records`; it was

No syntax rule forbids a dynamic-length or variable-length record from sharing an FD's area; the REDEFINES-clause
rules (§13.18.44.3) govern an explicit REDEFINES only (PB836's subject).

## What the fixer owes (after, or together with, the PB836 landing)

The shared record area is a storage shape the typed-native model must represent: an imageless member (a managed
pointer slot, a dynamic-length string, a dynamic-capacity table) overlapping character records of the same file.
Sites named by the source report: `DataBinder.ComputeTier`'s carrier arm, `StorageFormPass.Classify` arms 1/1b, and
`DataBinder.ClassifyRedefinesClasses`' implicit arm. Determine (CONFORMANCE.md) what a READ into the area does to the
imageless record and what a WRITE from it sends — the file boundary is where bytes are legitimate (memory
`typed_native_only`), and D-DL3's recorded layout for a dynamic-length item (PB829's lead 1, an FD record with a
dynamic-length member crashing at WRITE) is the same boundary. SAME RECORD AREA (§12.4.6.4.4 2)) is the
cross-file twin and gets the same shape. Goldens at 2002 (pointer) and 2023 (dynamic length).
