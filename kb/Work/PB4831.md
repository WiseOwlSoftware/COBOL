# PB4831 - PERFORM VARYING's Classify reads the varying operand by tree shape, so the BoundBinary sum of FUNCTION LENGTH (VG) is refused COBOL2119 as an arithmetic expression

**What the report says (the reviewer's words).** R2-1 LEAD (low, not blocking at round 2): `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/ControlFlowBinder.PerformVarying.cs:223` Classify reads the varying operand by tree shape, so the BoundBinary sum of FUNCTION LENGTH (VG) is classified Invalid and refused COBOL2119 as an arithmetic expression, while the report sweep says every reader of the call-only shape now agrees. Pre-existing and not touched by the finisher diff, so a lead rather than a re-opened finding. Re-read: Classify still lists `BoundBinary or BoundPower or BoundNegate or BoundExprError => Invalid` with no FunctionValue case.

**R1.** kb/Work PB4764 (landed) is the branch; PB439 is the Classify total-classification note.

**Sites (landed):** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/ControlFlowBinder.PerformVarying.cs` (`BindVaryingOperand`, which now asks the written shape through `ConditionBinder.SoleFunctionCall` before the tree-shape `Classify`, and reads the integer test through `IntrinsicBinder.OperandOf`).

Filed from a review lead of a merged fix-lane branch (wave 20261879 to 20261882) by the enqueue clerk; the lead's claim is the reviewer's, not adjudicated here.

**Fix (landed).** Re-probed on the branch build: `PERFORM VARYING I FROM FUNCTION LENGTH (VG) BY 1` and `... BY FUNCTION LENGTH (VG)` were both refused COBOL2119. `BindVaryingOperand` now classifies a SOLE function-identifier (the written shape, `ConditionBinder.SoleFunctionCall`, the reader every sender position uses) as an identifier whatever tree the binder lowered it to, and asks the SR4 a) / SR5 b) integer test of its `FunctionValue` operand twin. A parenthesized function stays an arithmetic expression (§8.8.1.1) and is still refused. Goldens: `pb4831_perform_varying_length_of_variable_length_group` (accept 2002) and `pb4831-perform-varying-parenthesized-length-of-variable-length-group` (refused COBOL2119 at 2002+). The keyword-omitted `LENGTH (VG)` (REPOSITORY FUNCTION ALL INTRINSIC) already ran.
