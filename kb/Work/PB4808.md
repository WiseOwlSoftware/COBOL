# PB4808 - the source text for PB4759's trigger semantics

[[PB4759]] cannot be implemented yet. The semantics of its triggers are defined by X3.23-1985's Debug module chapter, which is
not in the repository, and the implementer of wave 20261879 group D reports that GnuCOBOL has no equivalent trigger model. Neither
claim has had a second reader, so this analysis starts by checking both.

## The questions

1. Does GnuCOBOL really have nothing to follow here? Rule 1 consults GnuCOBOL before either vendor, so read its source and
   manual first.
2. What do the IBM Enterprise COBOL and Micro Focus manuals define for each trigger kind (data-name, file-name, cd-name)? The
   answer has to cover:
   - which statements fire the declarative, and whether it runs before or after the statement;
   - what DEBUG-CONTENTS holds for each file verb and each communication verb;
   - how DEBUG-SUB-1 to DEBUG-SUB-3 render for a subscripted reference;
   - what `ALL REFERENCES OF` means against a bare data-name;
   - the SORT and MERGE interaction.
3. Does rule 1's precedence reach a facility that only the 1985 edition defines? Rule 1 settles implementor latitude. A rule the
   1985 standard states is not latitude, so a vendor manual may be evidence of that rule and not the authority for it.

## What this note delivers

Either of these:

- A design-doc section that states each rule with its source, plus PB4759 split by trigger kind into notes with one mechanism
  each.
- If the manuals leave a rule open, one owner question naming exactly which rules are missing. The likely question is whether the
  owner can supply the X3.23-1985 text.

The NIST DB programs do not settle any of these rules: they are a regression net, not an authority (rule 1).

Then clear `blocked_by` on PB4759.

## Findings (2026-11-05, Mythos lane, one cobol-adjudicator; owner "CONTINUE")

**1. GnuCOBOL has a full trigger model for data-name and file-name triggers; the report's claim held only for cd-names.** Read in
GnuCOBOL 3.3-dev (WSL `/home/brent/gc-dev/gnucobol-3.3-dev`) and probed on the installed cobc 3.2.0 (`COB_SET_DEBUG=1`,
`E:/COBOL-coord/scratch/pb4808/probe/p1.cob`):
- Targets: `cobc/parser.y:17612-17712` (CD, FILE, FIELD, `ALL [REFERENCES [OF]]`). The CD arm (`17624-17632`) only records the
  target; DISABLE/ENABLE (`13402-13420`) and PURGE (`16014-16020`) are empty, and RECEIVE and SEND are not implemented, so a
  cd-name trigger never fires.
- Data-name trigger: `cobc/typeck.c:1178-1320`. A bare data-name fires on a receiving operand; an ALL target on any reference
  (`1210-1213`); each operand at most once per statement (`1222-1232`); DEBUG-NAME carries the " OF qualifier" chain, 30
  characters (`1235-1247`); DEBUG-CONTENTS is the referenced item (`1253-1255`); DEBUG-SUB-1..3 take the subscripts in written
  order, unused ones spaces (`1257-1314`).
- Timing: `cobc/codegen.c:9254-9290` runs the checks after the statement body. WRITE (`typeck.c:14754`) and REWRITE (`13451`)
  fire the record's data trigger BEFORE the I/O, after the FROM move. GO TO DEPENDING fires before the transfer (ALL targets,
  `codegen.c:8124-8135`). PERFORM VARYING/AFTER/UNTIL fire after each initialization, change or test (`tree.c:6862`,
  `codegen.c:7660-7730`).
- File verbs: OPEN (`typeck.c:13098`) and CLOSE (`9172`) after the I/O, DEBUG-CONTENTS spaces; READ (`13301-13317`) only in the
  no-exception branch (`codegen.c:8527-8532`), DEBUG-CONTENTS the record; DELETE (`9243`, `9279`) and START (`14423`) right after
  the I/O, before the status check, whatever its outcome. WRITE and REWRITE never fire the file-name trigger.
- DEBUG-CONTENTS size: the largest of 30, each field target, each file's maximum record and each CD record (`typeck.c:5143-5200`).
- SORT, MERGE, RELEASE, RETURN: no file or data trigger (`typeck.c:14232-14300`, `cb_emit_release`, `cb_emit_return`).
- GnuCOBOL's tests: `tests/testsuite.src/run_fundamental.at:7814-8114` (file test: OPEN, CLOSE, OPEN, READ with the record,
  CLOSE, no WRITE line; its "time of execution" test of nested statements is an expected failure); `syn_misc.at:4721-4815`
  refuses a subscripted or reference-modified target ("COBOL85 3.2.3 Syntax Rules 10+12").
- Probe on 3.2.0: `MOVE B TO T` does not fire; `MOVE "SET" TO B` fires with SET; OPEN, CLOSE, START, DELETE fire with spaces;
  WRITE and REWRITE do not fire; a successful READ fires with REC1, a READ that took INVALID KEY does not.

**2. The vendors.** IBM Enterprise COBOL 6.4 supports procedure triggers only and sets DEBUG-SUB-1..3 to spaces
(ibm.com/docs/en/cobol-zos/6.4.0?topic=statement-debugging-declarative; ibm.com/docs/en/SS6SG3_6.2.0/lr/ref/rllandeb.html).
Micro Focus "The USE FOR DEBUGGING Statement" (microfocus.com/documentation/reuze/60d/lhdebu0a.htm) states general rules 1-23
for file-name and identifier triggers, agreeing with GnuCOBOL: rule 2 (after OPEN or CLOSE), rule 5(d) (other statements:
immediately after), rule 6(c) (a bare identifier: when its contents are changed), rule 7 (not more than once per operand),
rule 13 (occurrence numbers in DEBUG-SUB-n), rule 22 (READ: the entire record). It never mentions a cd-name. HP COBOL II/XL
implements level 1 only; the Unisys MCP COBOL85 manual has debugging lines only.

**3. The 1985 text** is sold only (ANSI webstore, "ANSI INCITS 23-1985 (R2001)"; ISO 1989:1985 is withdrawn); no free legitimate
copy was found and nothing was downloaded. ISO 2023 prints nothing on this facility, so rule 1's chain goes to GnuCOBOL and
then the vendors.

**Rule 1 settles the two medium-confidence edges by precedence (GnuCOBOL before the vendors):** a bare data-name fires on any
receiving operand, including a store that an ON SIZE ERROR path skips (GnuCOBOL; Micro Focus rule 6(c) says "changed"), and
DELETE and START fire whatever their I/O outcome (GnuCOBOL; neither source states a success condition). One deliberate
departure: nested statements count each operand once per statement as Micro Focus rule 7 states, because GnuCOBOL's own test of
that case is an expected failure, so its code there is a known defect and not a model.

**Still undetermined (cd-name only):** which communication statements fire a cd-name trigger and when, and what DEBUG-CONTENTS
holds for each. Held on the owner in PB4759.

cd-name part, held on the owner (the 1985 text).
