# PB135

Rows: SR-14.9.11.3-2 (DIVERGES), the [standard-binary-arithmetic] grammar finding, sweep notes on ACCEPT/WRITE.

One root shape: program-unit plumbing that class units never got. (1) CobolOO.g4's classDefinition/factoryParagraph/objectParagraph/interfaceDefinition/methodDefinition admit no optionsParagraph — §10.6.1's nine skeletons and §11.2.1 all print it, and spec line 42527 says ENTRY-CONVENTION 'may be specified in the OPTIONS paragraph of a class'. This also breaks §4.2.6's identification obligation for STANDARD-BINARY in OO units (the reject substitutes a syntax error). (2) MnemonicRegistry.Of walks parse-tree parents for a ProgramUnitContext only; a method's chain tops out at compilationGroup, the map is empty, and BindDisplayUpon errors COBOLNET0817 on legal source — while OoDriver.BindClassData's SYNTHETIC reparented unit populates DataBinder.SwitchMnemonics from the SAME rule, so a SWITCH mnemonic resolves where a DEVICE mnemonic does not, inside one method. Three statements, one cause (DISPLAY UPON, ACCEPT FROM, WRITE ADVANCING). Fix: route the device map through the same OO data-binding channel the switch map already rides.
