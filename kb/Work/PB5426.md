# PB5426 - at --std 85 a report group of four hierarchic levels (a format 2 entry subordinate to another format 2 entry) compiles and prints: ScreenReportEntryFormats checks the first entry and a format 2 entry's child but not the depth

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/ReportSectionBinder.cs#ScreenReportEntryFormats`

**Mechanism.** `ScreenReportEntryFormats` (85 only, COBOL2247) refuses a level-01 entry with format 3 clauses and a format 2 entry with no immediate format 3 child, and `ScreenReportEntryClausePresence` refuses PICTURE or COLUMN on a group. Nothing refuses a format 2 entry immediately subordinate to another format 2 entry, which only a format 1 entry may have, so f1/f2/f2/f3 is accepted.

**Found by.** The 1985 code read, read 3 (`kb/Work/PB4996/2026-11-12-read-3.md`): `E:/COBOL-coord/scratch/coderead-85/out-read3/rd-06.json`.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids below. Its rows are recorded PARTIAL naming this note.

**Rules (1 claimed; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-SR-XIII.3.9.3-4` - `§1985:XIII.3.9.3 SR4` (read: PARTIAL, harm: under-rejects; the levels): "A description of a report group may consist of one, two, or three hierarchic levels"

**Repro.** `E:/COBOL-coord/scratch/coderead-85/out-read3/work-rd-06/g1.cob`: `01 DL TYPE IS DETAIL. 02 G1 LINE PLUS 1. 03 G2. 04 COLUMN 1 PIC X VALUE "A". 03 COLUMN 5 PIC X VALUE "B".` Run as `cobol.exe --std 85 --source-format fixed --run <file>` (each probe copied into its own directory by `reprobe-85i/probe.py`).
