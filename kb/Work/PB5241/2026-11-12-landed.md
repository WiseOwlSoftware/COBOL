**Landed (2026-11-12, wave 20262013 group B).** Re-probed on c6da483428: `K2.cob` at `--std 85` printed `SUBX 1` and then
`abnormal run-unit termination: CANCEL 'MAINQ': program is active (ISO §2023:14.9.5.4 GR5 ...)`, exit 1, as the note says.

**Fix.** A behaviour change, so a `DialectBehavior` member, `CancelRefusesEveryActiveProgram` (changed in 2002, VCR row 7.66):
§2023:14.9.5.4 GR5 and §2002:14.8.5.3 GR5 refuse a program "in the active state"; §1985:X.5.3.4 GR5 only one "that has been
called and has not yet executed an EXIT PROGRAM statement". The binder folds it into `BoundCancel.RefusesEveryActiveProgram`,
the emitter passes it to `ProgramTable.Cancel`, and `CancelNode` asks either `Active > 0` (from 2002) or the activations a CALL
entered, `Active - (MainActive ? 1 : 0)` (at 85). The main activation (`ActivateMain`) now sets `Node.MainActive` and no
longer sets `CalledSinceCancel`: no CALL entered it, so it is not "called in this run unit" (§2023:14.9.5.4 GR7,
§1985:X.5.3.4 GR8); from 2002 the active test answers first, so only the 85 arm sees the difference, and there the CANCEL
takes no action at all, its contained programs included. A host's `Cancel()` passes true. The runtime's public surface
changed (`ProgramRegistry.Cancel`, `ProgramTable.Cancel`), so the runtime major is 27.

**Witnesses.** `X.5.3@1985-CANCEL-STATEMENT/pb5241_cancel_main_program_85` (85: `SUB 1`, `AFTER-SELF-CANCEL M=1`, `SUB 2`),
`14.9.5-CANCEL/pb5241_cancel_main_program_active` (2002 2014 2023: the raise, taken by a declarative), and
`CancelCascadeOrderTests` (the main program's CANCEL at each rule through `RunMain`'s exit status; a called program not
exited refused under both).
