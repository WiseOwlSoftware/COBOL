## R2 batch 1b (pin 9e65164eb3a9): 1 finding on this note

### `parser-tree-3--performance--f1#1` (finding, unify, votes refuted/upheld/upheld)

**Finding:** Every speculative reading of CobolParserCoreBase builds a fresh ParserInterpreter, so each of its seven callers pays 1,279 cold DFA objects and full ATN simulation per read; PB4243 names only the entryNameHere caller

**Rule:** performance lens: allocation and complexity on a path that runs per occurrence (dimensions.md 3; DESIGN-architecture-review section 5.4 and section 4 item 5): a per-call cost that a shared cache makes once is repeated per call

**Scenario:** Reading (CobolParserCoreBase.cs:712-731) constructs new ParserInterpreter(GrammarFileName, Vocabulary, RuleNames, Atn, stream) on every call; the Antlr4.Runtime.Standard constructor allocates one DFA per decision of the ATN and a new ParserATNSimulator over them, and the generated CobolParserCore at the pin has 1,279 decisions (AdaptivePredict indexes 0..1278 in src/WiseOwl.Cobol.Frontend/Generated/CobolParserCore.cs), so each read allocates 1,279 DFA objects and predicts every decision from a cold DFA. The readers are entryNameHere (a prediction-time predicate, memoized only per token index and rule), ReadStatementAt and SentenceReadsWithOneOperandFor (per syntax error), ReservedProcedureName (up to three reads per candidate token), ReservedEntryName, VerbAloneIsAStatement (cached per type) and ProcedureReferencesToTheWord, which on CONFORMING source makes one cold read per occurrence of a reservation-gated verb that is not a bare sentence once any bare `VERB.` sentence of that word exists (a 2002+ program with `GOBACK.` paragraphs and GOBACK inside IF statements reads every such sentence, and again on every parse pass, since Reset clears _procedureReferences). PB4243 measured the entryNameHere path on an older pin: about 14 MiB and 10 ms per probe, 400 `05 BINARY-LONG VALUE 5.` entries adding 2.6-4.5 s to one compile; the same constructor serves the other six callers, so a fix scoped to entryNameHere leaves them cold.

**Target:** One speculative-reading component (the probe concern of the CobolParserCoreBase decomposition, section 8.3) owning a single reusable probe interpreter per parser, created once and re-pointed at each new copied-token stream, so the probe DFA warms across reads within a pass and across passes; Reading stays the one entry every caller uses, and a ProbeDfaCreations-style witness counter (the ProcedureNameReadsMade precedent) pins that a compile builds the probe once. Measure the PB4243 400-entry probe and IX113A full compile before and after with perf_baseline.py.
