# PB4092 — enabling one EC-SIZE name checks, and raises, the whole EC-SIZE family

**Sites:** `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/NumericRenderer.cs#CheckedFor`, `src/WiseOwl.Cobol.Runtime/Exceptions/CheckingFlags.cs` (`Size`), `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/ReportWriterEmitter.cs` (PRESENT WHEN / VARYING under `ExceptionState.SizeChecking`)

**Observed.** With `>>TURN EC-SIZE-TRUNCATION CHECKING ON` and nothing else enabled, `IF WS-D * WS-D > 0` (WS-D COMP-2 1.0E200)
raises EC-SIZE-OVERFLOW and ends the run unit. That condition is not enabled. `NumericRenderer.CheckedFor` selects the
checked kernels for any enabled EC-SIZE name, and the checked kernel raises whichever EC-SIZE condition it meets. No
guard asks whether that particular name is enabled. The report compose (PB4031) inherits it through
`ExceptionState.SizeChecking` for PRESENT WHEN and VARYING. Repros: `E:/COBOL-coord/scratch/mythos/w-n1/w20261762d/f1/tr2.cob`
and `tr.cob`.

**Expected (`cite.py --check` OK).** §14.6.13.1.1: "If checking for an exception condition is enabled and an exception
status indicator is set as a result of an exception detected during the execution of a statement, the associated
exception condition is raised". Its NOTE 3: "An exception condition is set to exist only if checking for that condition
is enabled". An overflow when EC-SIZE-OVERFLOW is not enabled takes the not-enabled disposition, which DOC-A.1-70
documents (§14.6.13.1.3 item 8), and is never raised. Enabling EC-SIZE-TRUNCATION checks truncation only.

**Fix.** Decide per exception name, not per family. A checked kernel raises only the conditions whose checking is
enabled (the per-name `CheckingFlags`), and takes the not-enabled disposition for the rest. Sweep every reader of the
family-level size flag (`CheckingFlags.Size`, `EcState.SizeChecking`, `ExceptionState.SizeChecking`). Goldens: each
EC-SIZE name enabled alone, against an overflow, a truncation and a zero divide, in COMPUTE, IF and a report compose.
PB4093 is the store-side sibling.
