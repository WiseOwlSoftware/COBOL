# PB5425 - at --std 85 the INSPECT REPLACING and CONVERTING size rules skip an operand whose size is static but not read by KnownWidth: a reference modification with no length (WS-3 (3:)) and a function-identifier (FUNCTION UPPER-CASE (WS-2)) of the wrong size compile and run

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/Validation/StatementValidation.cs#InspectOperandSize`
- `src/WiseOwl.Cobol.Compiler/Binding/Validation/StatementValidation.cs#CheckInspectLiteralSizes`
- `src/WiseOwl.Cobol.Compiler/Binding/Validation/StatementValidation.cs#CheckInspectCharactersReplacement`
- `src/WiseOwl.Cobol.Compiler/Binding/Validation/StatementValidation.cs#InspectOperandImage`
- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs#KnownWidth`, `#ResultWidth`
- `src/WiseOwl.Cobol.Compiler/Binding/IntrinsicCatalog.cs#IntrinsicResultLength` (the `Length` column of `IntrinsicSig`)

**Mechanism.** Below 2002 `InspectOperandSize` asks a data item's static size of `KnownWidth`, which answers null for a reference modification with an omitted length and for any function-identifier. Both sizes are static here (the item's length less the offset; the function's result length for an argument of fixed length), so the size checks of REPLACING (formats 2 and 3), CHARACTERS BY and CONVERTING never ask them and the statement runs with operands of unequal size.
