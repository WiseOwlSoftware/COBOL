# PB3976 — a golden for LENGTH(FUNCTION SQRT(...)) under a standard arithmetic mode

**Sites:** `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/IntrinsicRenderer.cs` (`IntrinsicRenderer.RenderNum`, the LENGTH arm that
reads `FunctionDeviceText.CallField` / `FunctionDeviceText.ValueField`).
The new golden goes under `conformance-suite/cases/15.50-LENGTH/`.

Filed 2026-10-28 by the enqueue unit's clerk from the PB3951 implementer's lead, carried unchanged.

(low) No golden pins `FUNCTION LENGTH(FUNCTION SQRT(...))` under a standard arithmetic mode: the value-field description
under STANDARD-DECIMAL (SDIDI) differs from the native one (4 against 8 in the implementer's measure). `RenderNum`'s
length arm reaches the answer through `FunctionDeviceText.CallField` / `ValueField`, and shares the standard-decimal
root PB3514 landed. A refactor of either path would change the answer with no test to see it. Add a golden per mode
(native and STANDARD-DECIMAL) whose expected value is derived from the returned-value rule (15.84.4 for SQRT) with a
`cite.py --check`ed citation, not copied from the compiler.
