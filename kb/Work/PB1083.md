# PB1083 — OPEN — the REPOSITORY intrinsic-name user-word screen answers the wrong membership and reaches too few words: `FUNCTION ALL INTRINSIC` is computed as `IntrinsicCatalog

## Rule text (every citation re-run by the registrar)
- `python scripts/spec/cite.py --check 12.3.8.4 "except for those that may have been undefined by the COBOL-WORDS directive"` → `OK  §12.3.8.4 14)  (General rules)`
- `python scripts/spec/cite.py --check 12.3.8.3 "Intrinsic-function-name-1 shall not be specified as a user-defined word within the scope of this REPOSITORY paragraph"` → `OK  §12.3.8.3 12)  (Syntax rules)`

### Adjudicator finding (repository-paragraph, harm rejects-legal-source)
- **Mechanism:** The FUNCTION ALL INTRINSIC list is computed as IntrinsicCatalog.TryGet(<raw written word>) at every consumer, so it ignores both >>COBOL-WORDS (UNDEFINE / SUBSTITUTE / EQUATE) and the edition window of each intrinsic.
- **Repro:** out/probe/repo/gr14a.cob (--std 2023): '>>COBOL-WORDS UNDEFINE "SQRT"', '>>COBOL-WORDS EQUATE "PI" WITH "MYPI"', '>>COBOL-WORDS SUBSTITUTE "E" BY "EULER"', REPOSITORY. FUNCTION ALL INTRINSIC., 01 SQRT PIC 9 VALUE 7., 01 E PIC 9 VALUE 8., DISPLAY SQRT, DISPLAY E, DISPLAY MYPI, DISPLAY EULER. gr14b.cob: same directives, 01 MYPI / 01 EULER declared. gr14ed.cob (--std 2014): FUNCTION ALL INTRINSIC with 01 CONCAT / 01 FIND-STRING / 01 BASECONVERT.
- **Expected (spec):** §12.3.8.4 GR14: ALL = every §8.11 intrinsic-function-name 'except for those that may have been undefined by the COBOL-WORDS directive', a SUBSTITUTE literal-4 replaces the original name, an EQUATE literal-2 is added. So gr14a compiles and prints 7, 8, MYPI=3.14159..., EULER=2.71828...; gr14b is refused (MYPI and EULER are in the ALL list, SR13 / §8.3.2.1 rule 5). Annex E.2 item 13 names BASECONVERT, CONCAT, CONVERT, FIND-STRING, MODULE-NAME, SMALLEST-ALGEBRAIC and SUBSTITUTE as prohibited under ALL only from 2023, so gr14ed compiles at --std 2014.
- **Observed:** gr14a: COBOLNET1649 on 01 SQRT and 01 E, COBOLNET1639 'not defined' on MYPI and EULER. gr14b: compiles and prints 7 / 8. gr14ed at 2014: COBOLNET1649 on all three names. Control gr14c (no REPOSITORY) proves the directive itself works: FUNCTION MYPI = 3.141592653589793, FUNCTION EULER = 2.718281828459045, data-names SQRT/E legal. DataBinder.ScreenRepositoryIntrinsicName, IntrinsicBinder.KeywordOmittedFunction ('catalogued = IntrinsicCatalog.TryGet(name, out var sig)') and ReferenceResolver.IsFunctionBearing each ask the catalog about the WRITTEN word; none calls CobolWordsMap.Resolve (the 'ONE resolution' kb/Work PB250 established) and none applies the D8 edition window that BindIntrinsicCore applies. Three copies of one membership question, none routed through the canonical-word resolver.
- **Code site:** src/Cobol.Net.Compiler/Binding/DataBinder.cs#ScreenRepositoryIntrinsicName (line ~2622); src/Cobol.Net.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs#KeywordOmittedFunction (line ~324); src/Cobol.Net.Compiler/Binding/ReferenceResolver.cs#IsFunctionBearing (line ~2272)
- **Clause (adjudicator):** §12.3.8.4 GR14; §12.3.8.3 SR13; Annex E.2 item 13; §7.3.10.4 GR2-GR4

### Adjudicator finding (repository-paragraph, harm under-rejects)
- **Mechanism:** The §8.3.2.1 rule 5 / §12.3.8.3 SR12-SR13 user-word screen (DataBinder.ScreenRepositoryIntrinsicName) is called from only six declaration funnels (data-name, condition-name, index-name, file-name, paragraph-name, section-name); every other user-defined word class is unscreened.
- **Repro:** out/probe/repo/sr12a.cob (--std 2023): SPECIAL-NAMES. ALPHABET PI IS NATIVE CLASS E IS "A" THRU "Z" SYMBOLIC CHARACTERS ABS IS 66. REPOSITORY. FUNCTION PI E ABS INTRINSIC. ... IF WS-X IS E ... DISPLAY PI. sr12b.cob: REPOSITORY. FUNCTION MOD INTRINSIC. in an outermost program that contains PROGRAM-ID. MOD. gr12.cob: REPOSITORY. FUNCTION ALL INTRINSIC FUNCTION SQRT. (a function-prototype-name spelling an intrinsic under ALL).
- **Expected (spec):** §12.3.8.3 SR12: 'Intrinsic-function-name-1 shall not be specified as a user-defined word within the scope of this REPOSITORY paragraph'; SR13 the same for every intrinsic name under ALL; §8.3.2.1 rule 5 restates it for all user-defined words. The alphabet-name PI, class-name E, symbolic-character ABS and program-name MOD are all §8.3.2.2 user-defined words inside the scope, so each is a compile-time error (COBOLNET1649).
- **Observed:** sr12a and sr12b compile clean and run (CLASS-E; the intrinsic PI; INNER). The screen is correct where it is called (sr13a: 01 SQRT in a contained program under the container's FUNCTION ALL INTRINSIC -> COBOLNET1649), so the defect is the set of CALLERS: SPECIAL-NAMES (alphabet, class, symbolic-character, mnemonic, locale names), program-names, function-prototype-names / program-prototype-names in the REPOSITORY itself, report-names, type-names reached by other funnels never ask it. The rule is written once but reached by an opt-in call per funnel - the next user-word kind is unscreened by construction.
- **Code site:** src/Cobol.Net.Compiler/Binding/DataBinder.cs#ScreenRepositoryIntrinsicName and its six call sites (DataBinder.cs:1129/2603/3481/4807; Procedure/ProcedureTableBuilder.cs:50/159/438); the missing callers in DataBinder.Switches.cs (SPECIAL-NAMES binders) and BinderDriver (program-names)
- **Clause (adjudicator):** §12.3.8.3 SR12, SR13; §8.3.2.1 rule 5

## What the fixer owes
ONE membership function (`IsRepositoryIntrinsic(word, unit)`) that resolves the word through `CobolWordsMap.Resolve` (PB250's one resolution) and applies the D8 edition window `BindIntrinsicCore` applies; the three consumers (`DataBinder.ScreenRepositoryIntrinsicName`, `IntrinsicBinder.KeywordOmittedFunction`, `ReferenceResolver.IsFunctionBearing`) call it. Move the screen to the ONE place every user-defined word is declared (the scope/name registry), so the next word class is screened by construction; drift test over the §8.3.2.2 word classes.
