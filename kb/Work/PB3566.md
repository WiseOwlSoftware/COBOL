# PB3566 — VALUE 0 on a numeric-edited item is accepted before COBOL-2023

## Scenario

GnuCOBOL refuses `VALUE 0` on a numeric-edited item ("numeric literal in VALUE clause of numeric-edited item used"). WiseOwl
gates every NON-zero numeric literal there with COBOL0900 below COBOL-2023, but exempts the literal `0` / `0.0` at every
edition. The D1 adjudicator rules GnuCOBOL's refusal right at 2014. Witnesses by signature: `THEY_REJECT:15.43` (5 programs,
first fz01391 line 10, `PIC $**,**9.99BCR VALUE 0`), `THEY_REJECT:15.58` (5, first fz00667 line 8, `PIC $**,**9.99B VALUE 0`) and
`THEY_REJECT:8.8.1.4.2` (2, first fz02776 line 5, `PIC -9(3)V9(6) VALUE 0`); 12 programs, one finding.

## Expected (spec)

Each citation was re-run through `python scripts/spec/cite.py --check` from the worktree on 2026-10-23 (all OK).

- §E.3.3 43) (OK): "VALUE clause, numeric-edited items and numeric literals. It is now permitted to allow numeric-edited data
  items to be assigned values specified as numeric literals." The change is dated to 2023 and carries no exception for zero.
- §E.2 28) (OK): "VALUE clause and the figurative constant ZERO for numeric-edited items. The figurative constant ZERO or
  ZEROES with or without the ALL phrase, when used as the value for a numeric-edited data item, is now treated as the numeric
  literal zero …" (the checked item continues past that point): the only zero 2014 allowed there was the figurative ZERO.
- §13.18.63.3 6) (OK): "If the item is of category numeric-edited, then, subject to Syntax rules 2 and 3, literals in formats 1,
  2, and 4 of the VALUE clause may be numeric …". Its last sentence ("the integer and decimal forms of the literal zero may also
  be specified for either format", checked) separates fixed-point from floating-point formats INSIDE the 2023 permission; it is
  not an exemption that applies to every edition.

Expected at `--std 2014`: COBOL0900, the refusal WiseOwl already gives for `VALUE 1`, for both `VALUE 0` and `VALUE 0.0`;
at 2023 the program compiles. The figurative constant ZERO stays accepted at 2014.

## Actual (judge e7cf38ce4)

Compiles clean at `--std 2014` and runs, printing `  0.00` for the zero item.

## Mechanism and code site

`src/Cobol.Net.Compiler/Binding/DataBinder.cs:2956` (`ScreenNumericEditedNumericLiteral`): it checks only literals that pass
`IsNonZeroNumericLiteral`, so the literal zero is never checked. This reverses a choice that already landed: the "Complement,
measured" paragraph of kb/Work PB921 exempts the literal zero on purpose, reading the last sentence of §13.18.63.3 6) as an
all-edition exemption.

fz01391, fz00667, fz02776 (first programs of the three signatures); 12 programs in all.

## Orchestrator decision

§13.18.63.3 6) is the 2023 permission (E.3.3 item 43); its last sentence ("the integer and decimal forms of the literal zero may also be specified for either format") distinguishes fixed- from floating-point formats INSIDE that permission, and 2014 permitted only the figurative ZERO (E.2 item 28). kb/Work PB921's "Complement, measured" paragraph read that sentence as an all-edition exemption and left `VALUE 0` ungated; that reading is overturned by this note (rule 1: the spec decides; the 2014 witness is the fuzz run's GnuCOBOL refusal). The implementer gates the literal zero like every numeric literal at 2002/2014 (COBOL0900) and keeps the figurative constant.

## Landed (w1157 group D, 2026-10-23) — the literal zero is a numeric literal

**Re-probe (the worktree's own build, before the fix).** The note reproduced: `VALUE 0` and `VALUE 0.0` on `PIC ZZ9.99`
compiled clean at `--std 2002` and `2014` while `VALUE 10` drew COBOL0900.

**Root.** One predicate, `IsNonZeroNumericLiteral`, answered two different questions: SR6's edition screen
(`ScreenNumericEditedNumericLiteral`: "is this a numeric literal at all", the 2023 permission) and the float-edited form
arm (`ValidateValueCategory`: "is this a NONZERO fixed-point literal", the real zero exemption of SR6's last sentence).
Asked for the first, "nonzero" read "numeric", so zero escaped. It is replaced by `MagnitudeOfNumericLiteral`
(NotNumeric, Zero, NonZero) and each site asks its own question: the edition screen asks `is not NotNumeric`, the form
arm `is NonZero`. The old name is deleted (no alias).

**Determination (overturns PB921's "Complement, measured").** §13.18.63.3 6) ("literals in formats 1, 2, and 4 of the
VALUE clause may be numeric ...") is dated by Annex E.3.3 item 43 and carries no exception for zero; its last sentence
("the integer and decimal forms of the literal zero may also be specified for either format") distinguishes the
fixed-point from the floating-point formats inside that permission. The only zero a numeric-edited item had before 2023
is the figurative constant ZERO (Annex E.2 item 28), which is no numeric literal and stays accepted at every edition.
All four citations were run through `cite.py --check`.

**Sibling sweep.** `IsNonZeroNumericLiteral` had two callers (both converted; the second keeps its nonzero meaning for the
float-edited fixed-point-zero exemption, which is the real one). Every VALUE format reaches the one screen through
`ScreenValueLiteral`/`ValidateValueCategory` (item, table, level-88, report), so `88 X VALUE 0` on a numeric-edited
conditional variable is gated too (`FORMAT3-condition-name-zero`). A BLANK WHEN ZERO item is numeric-edited
(§13.18.8.4 GR2), so `PIC 9(3) BLANK WHEN ZERO VALUE 0` is gated: that is what broke `pb566_blank_when_zero_stored_value`
(accept 85), whose VALUE 0 leg moved to the 2023 witness; the two `pb646_national_form_numeric_2002/2014` goldens seeded a
national numeric-edited item with `VALUE 0` and now store it with a MOVE. The population scans (every conformance case
accepted at 85, 2002 or 2014, 1759 programs through `check-batch` or the CLI; the 459-row NIST corpus, whose only FAILs are
its 18 pending rows) found no other.

**Goldens.** `13.18.63-VALUE/pb3566-numeric-edited-value-zero-below-2023` (`VALUE 0`, `VALUE 0.0`, refused 85/2002/2014 with
COBOL0900), `pb3566_numeric_edited_value_zero_2023` (accepted at 2023, images computed from §13.18.40.5 rule 7 a) and
§13.18.63.3 SR8 NOTE 2), `pb3566_numeric_edited_value_zero_figurative` (ZERO, ZEROES, ALL ZEROS accepted at every
edition). `NumericEditedValueEditionGateDriftTests` gates the zero spellings in every format at 85/2002/2014.
