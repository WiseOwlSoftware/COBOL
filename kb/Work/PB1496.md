## Row `GR-6.5-9` — PARTIAL (editions 85/2002/2014/2023)

'The next input line is obtained and processing iterates at step 1. … The implementor shall define the effect on the source listing, if any, of logical conversion.' (--check OK §6.5 9)). Both converters iterate line by line in source order over the whole compilation group and hand the converted text on (CopyProcessor / conditional compilation run after — §6.5 'before the application of replacing and conditional compilation actions'). The listing half is A.1 item 117: docs/CONFORMANCE.md's directive paragraph states 'no source listing is produced' (>>LISTING/>>PAGE inert), so logical conversion has no listing effect — documented, though not as a DOC-A.1-117 row. The per-step defects are recorded on GR-6.5-2/4/5/6/8. || REFUTED: PARTIAL — Two halves. (1) Iteration: the main-source normalizer does walk every line in order; but for library text the step-1 iteration is not uniform (a sequence-numbered copybook bypasses the directive-aware walk entirely - see GR-6.5-7 / GR-6.5-1), so 'processing iterates at step 1' does not hold for every line obtained. (2) The implementor-defined listing effect is A.1 item 117, 'required' AND 'shall be documented'; the only text is a passing clause in CONFORMANCE.md's directive paragraph ('>>LISTING / >>PAGE ... no source listing is produced, so listing on/off and page ejects are inert'), which answers the directives, not item 117. There is no DOC-A.1-117 determination, and the project's own register audit (scripts/spec/audit_annex_a1.py, gated by AnnexA1RegisterDriftTests) counts item 117 among the 121 REMAINING documentation obligations - the same standard the adjudicator applied to GR-6.1-1 c) (missing DOC-A.1-157 counted as a defect). One half unverified/undocumented => PARTIAL, not CONFORMS.
