# PB5221 - an answered owner question stops every later restart

**Sites:** `scripts/orchestrator/next_unit.py#choose` (the `elif h.get("owner_question")` arm, rule 1);
`scripts/orchestrator/orchestrate.ps1` (`Add-OwnerQuestion`, and its two callers in the supervisor loop: the
owner-question choice arm, which writes the question from the last handoff, and the unit-outcome arm, which writes it
when a unit returns it).

**What happens.** A unit that returns `outcome: owner-question` leaves `owner_question` in `handoff.last.json`. The
supervisor writes it to `OWNER-QUESTIONS.md` and exits 5. That is correct once. But `handoff.last.json` is never changed
afterwards, and `choose` asks only whether the handoff carries a question, never whether `OWNER-QUESTIONS.md` already
holds it or records it ANSWERED. So every restart chooses `owner-question` again, appends a second copy of the question,
and stops without running a unit.

**Witness.** At 17:43 the wave unit 20261989 asked whether pwsh 7.7.0 may be installed (PB5219). The owner answered at
17:40 in the operator session ("We want the latest versions"), and the answer is recorded under that question in
OWNER-QUESTIONS.md. PB5220 then landed the new toolchain (#1482, 21a7781ae8). At 18:33 the operator restarted the loop
(`-BorrowDays 1 -Cluster PB5200`). It read the 17:43 handoff, wrote the same question again at 18:34 and stopped with
exit 5 after 25 s. The restart went through only with an operator steer (`steer.ps1 -Unit campaign`, rule 0), which
`choose` checks before rule 1.

**The shape of the fix.** The question has to have one home, and that home has to record whether it is answered.
`OWNER-QUESTIONS.md` already does both. So `choose` should decide rule 1 from that file: a question it holds as
ANSWERED never stops the loop again, and one it holds without an answer stops it without being written a second time.
The supervisor's two writers should share that test, so a unit that asks a question already in the file does not
duplicate it. A self-test in `next_unit.py` should cover all three cases: a new question, a question asked but not
answered, and a question answered.
