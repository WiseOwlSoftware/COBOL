# PB708 — OPEN — a dead filter term is invisible inside a live filter

Found 2026-09-05 by the `PB691` finisher (report, closing paragraph) while running the gate filter its checkpoint
named verbatim.

## The facts

- `scripts/build-local.ps1` (and `build-local.sh`) run `dotnet test` per assembly with the caller's `-Filter`, and
  refuse a leg that prints no `Passed!`/`Failed!` verdict line — the guard added after the
  `--filter "~X|~Y"` lesson (a filter whose terms lack `FullyQualifiedName` matches NOTHING and exits 0).
- That guard is WHOLE-FILTER: it fires only when every term is dead. A filter of `FullyQualifiedName~A|…|~Z` in
  which one term matches no test in the assembly still selects the others, prints a verdict line, and the dead
  term is never named.
- Concrete instance: PB691's gate filter ended in `FullyQualifiedName~SpecTraceabilityInventory` and was run
  against `Cobol.Net.Tests.Conformance`; the test with that name is `SpecTraceabilityInventoryDriftTests` in
  `Cobol.Net.Tests.Unit`, which build-local runs unfiltered. The Conformance leg reported `Passed! … 1640` on
  every run and nothing said the term had selected zero tests. The implementer's STATUS.md, the finisher and any
  later reader copying the filter forward would all believe the inventory drift test was inside the filtered gate.

## Why it matters

A gate filter is a claim about which tests ran. `feedback_verdict_evidence_invariant` ("a run must assert its
population") and `feedback_measure_the_selectors_complement` both say the same thing: a selector is evidence about
what it RETURNED, never about what it dropped. A dead term is the per-term form of the silent-green filter that
memory `vstest_filter_terms` already records for the whole-filter case — the guard covers the shape that bit once,
not the shape that bites next.

## The fix shape

Per-term population assertion in the ONE place filters are run (`build-local.ps1`/`.sh`, not every caller): split
the filter on `|`, and for each term either `dotnet test --list-tests --filter <term>` against the assembly or
count the term's matches in the verdict's test list; a term with zero matches in an assembly it was aimed at fails
the leg by NAME (`DEAD FILTER TERM: <term> selects no test in <assembly>`). A term legitimately aimed at another
assembly is not an error — the script already runs assemblies separately, so the assertion is per (term, assembly)
and a term must match in at least one of the assemblies the invocation runs. Add the failure to the script's own
self-test so the guard is proven to fire once before it is trusted (`feedback_prove_the_watchdog_fails`).

## Sweep

Every filter string recorded in an implementer STATUS.md, a manifest row or plan §9 is a candidate for a dead term;
the fix makes the next one fail loudly rather than auditing the old ones by hand.
