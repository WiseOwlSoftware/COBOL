# PB708 — LANDED — a dead filter term is invisible inside a live filter

Found 2026-09-05 by the `PB691` finisher (report, closing paragraph) while running the gate filter its checkpoint
named verbatim.

## The facts

- `scripts/build-local.ps1` (and `build-local.sh`) run `dotnet test` per assembly with the caller's `-Filter`, and
  refuse a leg that prints no `Passed!`/`Failed!` verdict line — the guard added after the
  `--filter "~X|~Y"` lesson (a filter whose terms lack `FullyQualifiedName` matches NOTHING and exits 0).
- That guard is WHOLE-FILTER: it fires only when every term is dead. A filter of `FullyQualifiedName~A|…|~Z` in
  which one term matches no test in the assembly still selects the others, prints a verdict line, and the dead
  term is never named.
- Concrete instance: PB691's gate filter ended in `FullyQualifiedName~SpecTraceabilityInventory` and was run
  against `Cobol.Net.Tests.Conformance`; the test with that name is `SpecTraceabilityInventoryDriftTests` in
  `Cobol.Net.Tests.Unit`, which build-local runs unfiltered. The Conformance leg reported `Passed! … 1640` on
  every run and nothing said the term had selected zero tests. The implementer's STATUS.md, the finisher and any
  later reader copying the filter forward would all believe the inventory drift test was inside the filtered gate.

## Why it matters

A gate filter is a claim about which tests ran. `feedback_verdict_evidence_invariant` ("a run must assert its
population") and `feedback_measure_the_selectors_complement` both say the same thing: a selector is evidence about
what it RETURNED, never about what it dropped. A dead term is the per-term form of the silent-green filter that
memory `vstest_filter_terms` already records for the whole-filter case — the guard covers the shape that bit once,
not the shape that bites next.

## The fix shape

Per-term population assertion in the ONE place filters are run (`build-local.ps1`/`.sh`, not every caller): split
the filter on `|`, and for each term either `dotnet test --list-tests --filter <term>` against the assembly or
count the term's matches in the verdict's test list; a term with zero matches in an assembly it was aimed at fails
the leg by NAME (`DEAD FILTER TERM: <term> selects no test in <assembly>`). A term legitimately aimed at another
assembly is not an error — the script already runs assemblies separately, so the assertion is per (term, assembly)
and a term must match in at least one of the assemblies the invocation runs. Add the failure to the script's own
self-test so the guard is proven to fire once before it is trusted (`feedback_prove_the_watchdog_fails`).

## Sweep

Every filter string recorded in an implementer STATUS.md, a manifest row or plan §9 is a candidate for a dead term;
the fix makes the next one fail loudly rather than auditing the old ones by hand.

## Landed

`scripts/filter_population.py` is the ONE place the rule lives, called identically by `build-local.ps1` and
`build-local.sh` right after the solution build and before any leg — so the two twins cannot drift, because
neither carries the logic. It splits the EXPANDED filter into terms (`&`/`|` join, `()` group, `\&`/`\|`
escape) and hands each one back to `dotnet test --list-tests --filter <term>`.

⛔ **vstest answers for its own filter language; this script does not re-implement it.** The cheaper design —
one unfiltered `--list-tests` and substring-match the terms in Python — was MEASURED and is wrong: those are
DISPLAY names carrying theory arguments (`…DayOfWeek_MondayIs1_SundayIs7(clock: "2026-06-08T09:00:00", …)`)
while `FullyQualifiedName` carries none, so `--filter FullyQualifiedName~clock` selects **1** test in
Conformance where the listed names contain "clock" dozens of times. A substring model would have CLEARED a term
vstest calls dead — the exact false-green this guard exists to end. Discovery is ~1.6 s per term against a built
tree, which is the whole added cost. A NEGATED term (`!~X`, `!=X`) is probed through its POSITIVE form: asking
vstest for `!~X` returns every test in the assembly and would call a stale exclusion live.

**Two outcomes, not one, because the two failures do different harm and a guard that cries wolf gets worked
around** (⭐ this is the one place the fix shape above was corrected):

- **DEAD** — the name matches nothing in ANY assembly the invocation runs. A typo or a renamed test; whatever
  the term claimed to cover was tested by nothing. ⛔ The gate does not run (`exit 2`).
- **INERT** — no match in the FILTERED assembly, but a match in one the invocation runs WITHOUT the filter.
  This is PB691 exactly, and it is what the fix shape meant by "a term legitimately aimed at another assembly
  is not an error": those tests DID run, so the gate proceeds — but the term is named and the verdict line is
  stamped `— WITH INERT FILTER TERM(S), SEE ABOVE`. The harm in PB691 was a verdict line that read CLEAN while
  a false claim about the population travelled forward with it, so the verdict line is where the correction
  has to land. The finding also says WHERE the name does live, which is the sentence that would have closed
  PB691 on its first run.

Proof the guard fires before it is trusted (`feedback_prove_the_watchdog_fails`): `--self-test` runs **8 arms**,
every name DERIVED from what the assemblies discover so no arm can rot — a live term (silent), a dead term
(named), ⭐ **a dead term OR'd among live ones (named — the PB708 shape the whole-filter guard passes)**, a dead
exclusion, a term whose class exists only in Unit (INERT, PB691's shape, built by differencing the two
assemblies' class lists), a live exclusion, a grouped filter, and a failed discovery, which must be `exit 2` and
must NOT masquerade as a finding — a MISSING observation is not a negative one. ALL GREEN.

End-to-end through both twins with a deliberately dead term
(`~CorpusManifest|~ZzNoSuchTest_PB708`), byte-identical findings and `exit 2` from each:

```
⛔ DEAD FILTER TERM: FullyQualifiedName~ZzNoSuchTest_PB708 selects no test in Cobol.Net.Tests.Conformance — the
   name matches nothing in Cobol.Net.Tests.Conformance, Cobol.Net.Tests.Unit, Cobol.Net.Tests.Characterization,
   so whatever it was meant to cover was never tested
=== WAVE-LOCAL GATE: NOT RUN — the filter does not name what it claims (filter …) ===
```

And PB691's own seven-term gate filter, which had reported `Passed!` on every run, now names its dead term.

## Not swept, deliberately

`.github/workflows/build-and-test.yml`'s sharded Conformance legs already carry a STRONGER population
assertion than this one — "Assert the shards sum to the discovered population, per platform" fails the workflow
when the shard counts do not sum to `--list-tests`, so a dead term there cannot hide. The two single-purpose CI
filters (`inv1-strong`, `legacy-oracle`) and the two regenerator scripts (`gen-vcr.ps1`,
`gen-diagnostics-doc.ps1`, each a one-term filter whose death would make the generator a silent no-op) are the
remaining unguarded selectors; they are reported as a separate finding rather than folded in here.
