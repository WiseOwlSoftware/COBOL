## What the guidance asked for, mapped onto the real repository

The owner's prompt names placeholder paths (`COBOLSharp/Collation/`, `COBOLSharp.IR/OpCode.cs`,
`COBOLSharp.CodeGen/Lowering.cs`, `COBOLSharp.Runtime/`). COBOL.NET has no separate IR/opcode layer — the compiler
binds to a typed bound tree and emits C# through Roslyn — so each section maps as follows (recorded so the mapping
is never re-derived):

| Prompt section | Real home |
|---|---|
| §1 derived table (`CollationTable.cs`, `CollationElement`, `Lookup`) | `src/Cobol.Net.Runtime/Collation/CollationTable.cs`, `CollationElement.cs`; the generator `scripts/collation/generate-collation-table.py` over `data/unicode/` (pinned CLDR release-48-2 / UCD 17.0.0 files, Unicode License); the table is embedded as `Collation/Data/root-collation.bin` |
| §2 key builder (`CollationKey.cs`) | `Collation/CollationKey.cs` (`Build(text)`, per-level lists, `CompareTo`, `ToByteArray`) |
| §3 engine (`CollationEngine.Compare`, level-by-level) | `Collation/Collator.cs` (the configured, streaming comparison) + `Collation/CollationEngine.cs` (the static façade: `Compare`, `Root`, `Standard`, `ForLocale`, `TryGetOrderingTable`) |
| §4 tailoring (`TailoringRules.cs`, `en-US/fr-FR/es-ES.tailor`, `codePoint primary secondary tertiary`) | `Collation/TailoringRules.cs`; `Collation/Tailoring/{en-US,fr-FR,es-ES,es}.tailor` (embedded; disk override via `COBOL_COLLATION_DIR` or `Collation/` beside the app); `Apply` returns a NEW table — the base is never mutated |
| §5 front-end ("StringType.Collation", emit a collated compare for `IF A < B`) | the binder's collating model (`CollatingModel.cs` — `AlphabetDef` gains the LOCALE / ordering-table arm) and the relation-condition emission; **gated on the PCS in effect being locale-based** (ISO §8.8.4.2.7: locale-based comparison is used only when the alphanumeric program collating sequence in effect is locale based — an unconditional collated `<` would violate the NATIVE default and break the whole conformance battery) |
| §6 IR opcode (`IR_COMPARE_STRING_COLLATION`) + §7 lowering (`→ CollationEngine.Compare`) | the ONE `CobolCollation` carrier the emitters pass (`CobolString.Compare(a, b, __COLLATE)`), whose LOCALE arm calls the engine — the design's §4.4 (T2 collapse + T3 arm) |
| §8 runtime (`CollationEngine.cs`, `CollationKey.cs` in the runtime, reachable from generated code) | `Cobol.Net.Runtime` (public types under `CobolNet.Runtime.Collation`) — generated programs already reference the runtime |
| §9 documentation | `src/Cobol.Net.Runtime/Collation/README.md`, `data/unicode/SOURCES.md`, the design doc's §4.4/§4.9 |

## Landed 2026-08-18 (the engine half — DEVLOG 1326)

- The generator, the pinned data (with the Unicode license and provenance), the embedded derived table (38,787
  mappings, 974 contractions, 968 non-starters, 2,081 canonical decompositions, 23 UTS #10 Table 16 implicit
  ranges, primaries ×16 for tailoring room; 228 KB deflated) and its hash manifest.
- `CollationElement` / `CollationStrength` / `AlternateHandling`, `CollationTable` (root + tailored; Hangul and
  implicit weights computed), `CollationElementIterator` (contractions incl. discontiguous S2.1.1–S2.1.3),
  `Normalizer` (NFD from the table's own data — the host normalizer was measured to lag Unicode 16 and was
  dropped), `Collator` (streaming level-by-level compare, keys), `CollationKey`, `CollationEngine`,
  `TailoringRules`, the four `.tailor` files.
- Tests: 48 unit tests (table, engine, tailoring, conformance samples) + the opt-in full CLDR conformance run —
  **206,298 + 227,809 lines, 0 violations** — + the ICU root-order cross-check corpus (agrees).
