# PB5800 - OPEN: must LINE-COUNTER be qualified when the other report description is in a contained program or is GLOBAL (1985-SR-IV.4.3.8.1-L2.9)?

**Ruling: OPEN.** Whether "exists in a program" counts a contained program's report descriptions and a GLOBAL report's counters when LINE-COUNTER must be qualified is not settled by the 1985 words. The row `1985-SR-IV.4.3.8.1-L2.9` stays `undecided`. Harm: under_rejects under reading A (not set while the row is open). The checker's confidence is low; the refuter was DOUBTFUL. The single-program cases conform (the refuter's own probes); only the nested cases are in question.

**The two shapes.** Both compile at `--std 85` and `--std 2023` and resolve to the nearest report: `lc1.cob`, an outer program with one RD whose Procedure Division writes an unqualified LINE-COUNTER while its contained program specifies a second RD (prints `OUTER 01`); `lc2.cob`, an outer RD `R1 IS GLOBAL` and an inner RD `R2`, where the inner's unqualified LINE-COUNTER is taken as R2's (`IN1 03`; R1's is 01).

**The two readings (the checker's).**
- Reading A (the refuter's): 1985 says a source program may contain other source programs, so the outer source program "specifies" both RDs and SRL2.9 requires qualification in `lc1.cob`; and in `lc2.cob` two LINE-COUNTERs exist in the inner program (R1's is a global name by `§1985:X.4.4.4 GR1`), so `§1985:XIII.3.5.6 SR3` requires qualification there: under_rejects, an 85 arm needed (cause a or c).
- Reading B (the reader's): "the source program" of a Procedure Division is the program the reference is in, its RDs and those global to it, with the nearest-declaration conventions of X.1.3.8.2; then `lc1.cob` needs no qualification (R2 is invisible to the outer program) and `lc2.cob` resolves to the local R2.
- The 1985 words admit both. The X.1.3.8.2 conventions name condition-names, data-names, file-names, record-names and report-names, not special registers, so they do not settle B. 2002 and 2023 say "source element", which excludes contained programs (a pointer only).
- What settles it: a lane ruling on whether "source program" in SRL2.9 (and "exists in a program" in XIII.3.5.6 SR3) counts contained programs' RDs and global counters. `lc1.cob` under reading A is the stronger literal case but would make a reference unambiguous in its own scope illegal.
