# PB5019 - the process-global drift test sees one resolver level only

**Sites:** `tests/WiseOwl.Cobol.Tests.Unit/ProcessGlobalCollectionDriftTests.cs:46` (`EveryRuntimeTypeNamingAResolver_IsClassified`, `ResolverTypes[..5]`).

**Report.** The test classifies only source types that name one of the five ROOT resolvers (`ResolverTypes[..5]`). A type that resolves one level further down, for example through `LocaleCollation`, is neither classified nor in the Reader scan, so the DEVLOG claim that a new resolving type cannot slip past the scan holds for one level only (R2-1 LEAD, low, round 2 of PB3947).

**Same mechanism, found from the other side.** The `CobolIntrinsics` ordering-table paths call `CollationEngine.TryGetOrderingTable`, yet `CobolIntrinsics` is classified non-resolving because 39 test classes name it. A test that sets site variables and calls that path would need `[Collection("process-globals")]` by hand, and the drift test would not say so.

**Fix shape.** Compute the resolver set transitively (a type resolves if it names a resolver or a type that does) and classify per member where a type is both heavily named and partly resolving, so the next layer is automatic; pin it with the drift test itself.
