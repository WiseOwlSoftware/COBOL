## What the docs say

Checked 2026-10-16 by a claude-code-guide agent reading the Claude Code and platform docs.

- `platform.claude.com/docs/en/about-claude/api-credits-for-subscribers`: the Max 20x plan includes $200/month of API
  credits (Max 5x: $100); included credits are spent before purchased ones, expire each cycle, no card needed. The page
  lists the Claude API, Managed Agents, the Agent SDK and the playground as COVERED and Claude Code as "No" (not covered).
- `code.claude.com/docs/en/authentication`: `ANTHROPIC_API_KEY` outranks the subscription login per process; in `-p`
  mode the key is always used when present; `claude --bare -p` never reads OAuth credentials (needs the key or an
  `apiKeyHelper` passed via `--settings <file>`); cloud sessions "always use your subscription credentials" and a key set
  in the cloud environment "doesn't override your subscription credentials".
- `code.claude.com/docs/en/claude-code-on-the-web` and `.../routines`: cloud sessions and routines count toward the
  plan's usage limits; no separate charge; routine overage uses claude.ai usage credits only; API-key auth "is not
  sufficient" for `--cloud`. Nothing documents spending Console credits on cloud work.
- `code.claude.com/docs/en/headless` and `.../costs`: subagents of a `-p` process draw on the same usage (inferred: they
  inherit the process's key); `--max-budget-usd` stops remaining background work at the cap.
- `platform.claude.com/docs/en/manage-claude/workspaces` and `.../api/rate-limits`: workspace monthly spend limits with
  alert thresholds (a breach is HTTP 400 `invalid_request_error`); org-wide monthly cap $500 (Start) / $1,000 (Build), a
  breach is 429 `enforced_spend_limit_reached`.
- `platform.claude.com/docs/en/about-claude/pricing`: Opus 5.5 $4 input / $0.20 cache read / $20 output per MTok; Claude
  Code runs are cache-read heavy.

## What follows for this project

The only documented way to spend the credit is a runner of the project's own on the Claude Agent SDK (or the raw API)
under the key; Claude Code (`claude -p`) and cloud sessions cannot. A unit re-hosted on the SDK's `query()` would need:
the project's settings, hooks and role agents loaded from the tree (the SDK's setting sources), the same unit prompt and
handoff files, the worktree as cwd, the owner's permission mode, and the stdin-open lifetime the supervisor relies on.
The Workflow tool is a harness feature the SDK may not offer, so a rolling wave inside an SDK unit needs an SDK-side
equivalent of `wf_rolling_wave.js` (an open design question). `budget.py` needs an account priced in DOLLARS from
telemetry (list prices) with a stop margin before the credit is exhausted, because a refused request kills an agent
mid-step (owner: "without triggering aborts"); a workspace spend limit and alerts in the Console back it. The key never
enters the repository or a worktree (environment only).

## Owner note (2026-10-16)

The owner is considering removing account 2's membership in the shared org and creating a new org for it so that account
also receives the credit. Doc facts (platform docs "API credits for subscribers", "workspaces", "remove user"): the
subscriber API credit is granted per PLAN and lands in ONE Console organization chosen during the claim; the claim needs
the subscriber's plan role and an Owner, Admin or Billing role in the target organization; each plan links to one
organization and each organization receives credits from only one plan, so a Max subscriber who is only a regular member
of another user's organization cannot link that organization and the docs say to create an organization of their own (or
during the claim flow); changing the linked organization later requires support. Removing a member: Console Members page,
the row menu, Remove member (with "All" selected it removes them from the organization); organization admins and billing
members cannot be removed while they hold those roles; a removed member's personal API keys are archived and not restored
on re-invite, their Claude Code workspace keys stop working, workspace and service-account keys keep working; self-leave
is not documented; credits belong to the organization and every key and workspace in it draws on one balance.
