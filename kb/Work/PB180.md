# PB180

Found by the Step D design scout (2026-08-30). AcceptDisplayEmitter (~:96-98) stores the device transfer into a
promoted (StoreAsImage) member using DisplayTextWidth characters where the window is StorageWidth bytes — live on
TODAY's Tier B (PIC 9(4) COMP under REDEFINES: 4 device chars spliced into a 2-byte window shifts the class
layout). The V59 byte-image discipline never reached this store. FIX: the ACCEPT store for a byte-form member
converts via ParseDisplay→FormatImage (device chars → value → bytes) at the window's width; unit + golden pins.
Must land BEFORE or WITH the Step D widening (the widened members inherit the same store).

## ✅ LANDED 2026-08-30 — DEVLOG Entry 1404 (Step D order, step 2a)
The ACCEPT device store for an image-stored / Tier-B-windowed numeric receiver now takes the SAME
§14.9.1.4 GR1 conversion every numeric receiver takes — ParseDisplay(device chars at DisplayTextWidth)
→ Narrow → FormatImage — replacing the raw-splice arm whose "the characters ARE the storage" comment
was true only of the pre-V59 zoned windows. One lane for zoned AND byte-form windows, identical to the
native path's documented determination (this emitter's own doc).
`AcceptDifferentialTests.Device_TierBBinaryWindow_ConvertsThenReencodes` pins it end to end (stdin
"1234" → the value 1234, window bytes 04 D2 via ORD on the redefined view, sibling intact — the old arm
measured 12594). Wave gate GREEN (Conformance 1343 — the golden and the ACCEPT fact by name · Unit 5032 · characterization 33).
