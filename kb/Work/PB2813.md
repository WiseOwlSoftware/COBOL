# PB2813 — one budget verdict, whoever asks

Found 2026-10-08 16:45 by the operator.

## Measured (account2, day 6 of the week, weekly ≈ 93.4 %)

- The loop was started with `-BorrowDays 3` (owner: burn the week to the 97 % cap by Saturday 10:00). The supervisor calls
  `budget.py --json --borrow-days 3` (`orchestrate.ps1` ~line 448) and logged "weekly 93.26 % of 97 % … -> go" at 16:33.
- The 16:34 land unit ran `budget.py` itself, without the flag, and recorded in milestones "hold-day until 2026-10-09
  10:05" (allowance 85.8 % = 6 days × the daily share). `python scripts/orchestrator/budget.py --account account2` bare
  prints the same hold-day; with `--borrow-days 3` it prints go.
- No harm in that unit (a land unit launches no fleet), but a wave or campaign unit that checks the budget the same way
  holds a fleet the supervisor allowed, and `scripts/orchestrator/units/meter.md` steps 8–9 run `budget.py` bare too.

## Fix (one rule, one place)

The owner's borrow setting is state, not a per-call flag: the supervisor records it (for example in the coord dir's
loop state, which `coord.py loop-state` already reads) and `budget.py` reads it when `--borrow-days` is not given, so
every caller — supervisor, unit, meter template, operator — gets one verdict. Delete the per-call flag from the
supervisor's call once the state is the source (no second path). A self-test: with the loop state at borrow 3, a bare
call and the supervisor's call return the same decision.
