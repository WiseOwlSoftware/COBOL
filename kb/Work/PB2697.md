**Wave kind:** defect-for-fix-lane. Found by the train 1042b lander while reviewing PB2633 (trailing-P negative scale reaching `Pow10.AsWide`), as a sibling of the same mechanism: a PICTURE with trailing P has a NEGATIVE scale (PictureAnalyzer: scale = -trailingP), and a consumer that treats "scale ≤ 0" as "already an integer" forgets the 10^-scale factor.

**Sites:**
- `src/Cobol.Net.Runtime/Values/SetAmount.cs:61` (SetAmount.Land: `if (scale <= 0) { whole = scaled; … }` — the value is `scaled × 10^-scale`)
- callers: `src/Cobol.Net.Runtime/Values/Tables/CobolIndex.cs:90` (SET index UP/DOWN BY), `src/Cobol.Net.Runtime/Control/CobolPtr.cs:187` (SET pointer UP/DOWN BY), `src/Cobol.Net.Runtime/IO/StartKeyLength.cs:41` (START … KEY length)
- correct siblings for comparison: `src/Cobol.Net.Runtime/Intrinsics/CobolIntrinsics.Exact.cs:76`, `src/Cobol.Net.Runtime/IO/ReportWriter.cs:693` (both multiply by `Pow10.AsWide(-scale)`)

**Rule it breaks:** §13.18.40.3 (a P position is a decimal scaling position: `9PP` holding 1 is the value 100) and the SET statement's UP BY / DOWN BY general rules (the index is incremented by the VALUE of the amount).

**Measured:** lander probe `E:\COBOL-coord\scratch\t1042b\probe\setp.cob` on the train 1042b build (src/Cobol.Net.Cli/bin/Debug/net10.0/cobol.dll, base 7fb5cab75 + train): `01 N PIC 9PP VALUE 100.` `SET IX TO 1. SET IX UP BY N. SET W TO IX. DISPLAY "IX=" W.` prints `IX=0002`; `IX=0101` is owed.

**Fix direction:** `scale < 0` multiplies by 10^-scale (checked: a product past Int128 is `SetAmountLanding.BeyondCarrier`), `scale == 0` stays as is; a golden for each of the three callers (index, pointer, START key length) with a trailing-P amount. Sweep every other `scale <= 0` / `scale < 0` early-out over an unscaled value for the same omission.

## Landed (wave 1045 group G, 2026-10-08)

Re-probed on this worktree's build: the lander's `setp.cob` printed `IX=0002` (owed `IX=0101`), and a wider probe
(`E:/COBOL-coord/scratch/w1045g/allp.cob`) showed the defect at EVERY exact-lane consumer of `SetAmount.Land`: SET index
TO (1, owed 100), UP BY, DOWN BY, SET pointer UP BY (moved 2, owed 20), SET capacity (2, owed 20) and START ... WITH
LENGTH (a PIC 9P holding 40 positioned `00` against a 30-character key, owed `23`). SET SIZE was already right (it lands
on the double). After the change every row prints the value the rule owes.

**Citation corrected.** The note cited §13.18.40.3 for the P rule and `cite.py --check` FAILS it there: the text is
§13.18.40.4 GR14 ("The symbol 'P' specifies the location of an assumed decimal point when that point is not within the
number that appears in the data item"), and `spec_refs` listed a §14.9.37.3 that belongs to no rule here; `spec_refs` is
now 13.18.40.4 / 14.9.39.4 (GR4, GR20, GR30) / 14.9.41.4 (GR14).

**Fix.** `SetAmount.Land(Int128, int, out Int128)` multiplies a negative scale out (value = stored × 10^-scale), with
the shared `CobolNum.WideningFits` deciding BEFORE the multiply; a product past Int128 is `BeyondCarrier` (that lane
could not answer it before) and a zero lands as 0 at any scale. `CobolPtr.UpByAmount` used to map only `NotAnInteger`
and would have displaced by 0 on `BeyondCarrier`; both pointer lanes now share ONE mapping (`CobolPtr.Displace`), so
the exact lane answers GR20's EC-RANGE-PTR exactly as the double lane does. `CobolIndex.Land` and `StartKeyLength`
already mapped every landing. Sibling sweep: every `scale <= 0` / `scale < 0` early-out in `src/` was read; the
subscript/ref-mod (`CobolNum.PositionOf`), intrinsic (`IntegerValue`, `Floor`, `Truncate`), report VARYING and date
siblings multiply the factor out already; `CobolNum.PlainValue` (diagnostic text) rendered 1 for 100 and is fixed here,
though no current caller passes it a negative scale.

## Landing

- `src/Cobol.Net.Runtime/Values/SetAmount.cs#Land(Int128,int,out Int128)` owns the trailing-P widening for every SET-family amount and START LENGTH; reuse `CobolNum.WideningFits` for any new negative-scale widening, never a bare multiply.
- `src/Cobol.Net.Runtime/Control/CobolPtr.cs#Displace` is the one landing-to-GR19/GR20 mapping for both pointer lanes; a new lane calls it.
- `src/Cobol.Net.Runtime/Values/Numeric/CobolNum.cs#PlainValue` renders a negative scale as trailing zeros.
- Trap: the exact lane's `BeyondCarrier` is reachable only through a negative scale, and no ITEM reaches it (at most 31 digit positions, §13.18.40.3 SR14), so a unit row drives it.
- Tests: `unit:SetAmountTests`, `unit:CobolPtrTests.UpByAmount_TrailingPAmount_DisplacesByItsValue_AndPastTheCarrierIsGr20`, goldens `conformance:85/pb2697_set_index_trailing_p`, `conformance:2002/pb2697_set_pointer_start_trailing_p`, `conformance:2023/pb2697_set_capacity_trailing_p`.
