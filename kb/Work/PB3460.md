# PB3460 — DOC-A.1-164 describes a deleted whole-store mechanism

Low, non-blocking lead from the branch review of PB3415 (report `E:\COBOL-coord\scratch\reports\w1132f-PB3415-report.md`,
`## Review findings` R1-1; findings file `E:\COBOL-coord\scratch\review-w1132-f.jsonl`). Finding, verbatim:

> docs/CONFORMANCE.md:3323 DOC-A.1-164 (a hit of the implementer sweep for AdmitsAnother, reported accurate) still
> describes a relative or indexed connector whole store loaded and persisted through KeyedConnector._areas, at CLOSE or
> after each statement under any SHARING mode but NO OTHER; PB3334/PB3335 moved both organizations to the paged keyed
> store engine and deleted the whole store, and src holds no _areas field and no WholeStore type.

**Verified on origin/main (26bb0a676), 2026-10-20.** `git grep -n "_areas\|WholeStore" -- src` prints nothing.
`docs/CONFORMANCE.md` line 3323 (the DOC-A.1-164 row, "RESERVE clause — the number of input-output areas when the clause
is not specified") says, in its first paragraph, "for a relative or indexed connector, the buffer its whole store passes
through, one buffer of areas per positional read or write, when it is loaded (at OPEN, and at a coherent reload) and
persisted (at CLOSE, or after each statement that changed it under any `SHARING` mode but `NO OTHER`, kb/Work PB1587) —
`KeyedConnector._areas`; the store handle itself is unbuffered, kb/Work PB2693".

**Sweep of docs/CONFORMANCE.md for the other `_areas` / "whole store" sentences.** Search:
`grep -n "_areas\|[Ww]hole store\|WholeStore" docs/CONFORMANCE.md`. Result: one line, 3323, with two hits on it, both in
the DOC-A.1-164 sentence quoted above ("its whole store passes through" and `` `KeyedConnector._areas` ``). No other line
of the file carries either term. The row's other claims (the sequential connector's buffer, `FileConnector.InputOutputAreas`,
the `AdmitsAnotherRunUnit` release behaviour, the witnesses) were not re-read here and are the implementer's to check
against the engine when it rewrites the keyed arm. Other kb/Work notes that mention `_areas` (PB2693, PB3335) are history
notes and say so; they are not edited.

The text was NOT rewritten by this note. **Fix shape (for the implementer).** Rewrite the keyed arm of DOC-A.1-164 for the
paged keyed store engine (what, if anything, `RESERVE` sizes for a relative or indexed connector now, from
`FileConnector.InputOutputAreas` and the engine's page buffer), read the current code and the engine design
(`docs/rearchitecture/DESIGN-runtime-library.md`), re-point the row's witnesses if one named the deleted field, and run
the inventory drift tests (CLAUDE.md rule 6).

## Landed (wave 1140 A)

Re-probed: `git grep -n "_areas" -- src` prints nothing on 62cd0d954, and DOC-A.1-164 still named `KeyedConnector._areas`.
The keyed arm is rewritten for the engine: a relative or indexed connector's input-output areas are PAGES of the run
unit's page cache for its physical file (`docs/rearchitecture/DESIGN-runtime-library.md` 2.2.1.13), whose capacity the
attaching OPEN raises to at least its areas (`KeyedConnector.Attach` to `KeyedStore.AttachHandle` to `PageCache.Reserve`),
above the cache's own floor of 256 pages; the store handle is unbuffered; a changing statement writes its pages before it
completes in every sharing mode (2.2.1.6), so the sharing-mode paragraph is now the SEQUENTIAL connector's. The row's
witnesses never named the deleted field (the inventory row was re-sited by PB3334), so none moved. Sibling:
`DESIGN-runtime-library.md` §2.2's `OpenConnectorStore` paragraph carried the same `KeyedConnector._areas` sentence;
rewritten. `cite.py --check 12.4.5.14.3 "If the RESERVE clause is not specified, the number of input-output areas
allocated is specified by the implementor"` gives OK §12.4.5.14.3 1).
