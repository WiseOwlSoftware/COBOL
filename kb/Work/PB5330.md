# PB5330 - a CRLF compare or verify file passes the merge and fails the gate

**Sites:** `scripts/spec/merge_reconciliation.py` (`read_json`, `compare_summary`).

## What happened

The 2002 reconcile runs account2-r02, r03 and r04 (workflows wf_fb48f096-c2e, wf_9f9f0d15-6f9, wf_c0a525a5-4d0) wrote
48 agent files. Four of them were CRLF throughout (`compare-p325-p336.json` 43 of 43 line ends, `compare-p637-p648.json`,
`compare-p661-p672.json`, `verify-p761-1.json`); the other 44 were LF. `merge_reconciliation.py --edition 2002` read all
48 as valid and exited 0, and the gate's LINE ENDINGS audit refused the branch (run 000001-20261111T213949Z). The run
before (account2-r01, 18 files) happened to produce none.

## Why it is a defect

The run's own proof (`--compare-summary`, `--claim-key`, the merge) accepts a file the repository refuses, so the
defect is found one gate later by whoever lands the run, never by the agent that wrote it. `line_endings.py --fix`
repaired these four; every later run can repeat it.

## Fix direction

`read_json` refuses a file holding a CR byte, naming it and the fix, so `--compare-summary` fails inside the agent's
STEP 3 and the agent rewrites the file while it still holds the content. Self-test: a CRLF compare file is invalid.
