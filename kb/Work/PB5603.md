# PB5603 - at --std 2002 the communication SEND statement refuses an inline method invocation in FROM and a function-identifier in WITH and ADVANCING

**Sites:**
- `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolCommunication.g4#sendText,` #sendIndicator, #sendAdvancingPhrase

**Mechanism.** The Annex A SEND grammar names its own operand rules: sendText is functionCall | dataReference (no inlineMethodInvocation), and sendIndicator / sendAdvancingPhrase take only dataReference (no functionCall). 2002 identifier-1, identifier-2 and identifier-3 are identifiers, which include inline method invocations and function-identifiers. Not PB4842 (that is the 2023 messaging SEND).

**Inventory.** Rows claimed: `2002-GR-8.4.2.1.3-1`, `2002-SR-8.4.2.4.2-2`, `2002-SR-8.4.2.5.2-1`, `2002-GR-8.4.2.5.3-1`, `2002-GR-8.4.2.5.3-6`, `2002-GR-8.4.2.5.3-7`.

**Rules (each citation checked with `python scripts/spec/cite.py --check`, verdict OK).**

- `§2002:A.2.6.2 SR2`: "Identifier-1 shall reference a data item of class alphanumeric"
- `§2002:8.4.2.4.3 GR1`: "references a temporary data item with the same class, category, and content"
- `§2002:A.2.6.2 SR4`: "Identifier-3 shall reference an integer data item"
- `§2002:8.4.2.2.2 SR9`: "A numeric function shall not be specified where an integer operand is required"

**Repro.** Scratch originals under `E:/COBOL-coord/scratch/op-20261114/read-2002/defects-work/` (p/send-inline.cob, p/sendfn4.cob); the text is inline. Command: `cobol.exe p/send-inline.cob --std 2002 --run`

**Observed.** send-inline (SEND CDOUT FROM OB :: "GETX"): error COBOL0001 cannot parse construct near 'SEND', rc=65. sendfn4 (ADVANCING FUNCTION MOD(5 3) LINES): error COBOL5506 unexpected 'FUNCTION'.

**Expected (from the 2002 text).** both compile: FROM takes an alphanumeric identifier, which an inline invocation returning alphanumeric is; ADVANCING takes an integer identifier, which an integer function is.

**Sibling sweep.** every other CobolCommunication.g4 operand rule (RECEIVE, ACCEPT/ENABLE/DISABLE/PURGE operands) and every grammar rule that writes {identifier} as functionCall | dataReference instead of the shared identifier shape (PB2146 lists three such places).

**Other editions.** 85: inline invocation n/a; the function arm unknown (PB5108 refuses integer functions in identifier slots at 85 on purpose). 2014 and 2023: n/a (no communication facility).
