# PB947 — OPEN — the right verdict, quoted from the wrong letter

Source: the **PB388 (citation fidelity) implementer report**, "New defects" item 3 — found by `PB932`'s citation
sweep, registered there and deliberately NOT made (a behaviour change, out of that wave's scope). The comment in
the tree today states the gap outright and is worth quoting, because it is the note's own witness:

> ⚠ THE PREDICATE BELOW IS THE TWO-EXCLUSION READING the wrong citation carried: it excludes the bit and national
> groups and not the STRONGLY-TYPED or VARIABLE-LENGTH ones, so it over-includes. Registered as a lead rather
> than changed here.

## Observed, MEASURED (`i5_sr24_group.cob`, `--std 2023`)

```
       01 G1.
          88 G1-A VALUE "XXXXXX".
          05 P1 PIC 9(4) COMP.
          05 P2 PIC X(2).
       01 VG.
          88 VG-A VALUE "XXXXXX".
          05 V1 PIC 9(4) COMP.
          05 V2 PIC X DYNAMIC LENGTH LIMIT IS 5.
```

```
(6,11): error COBOLNET1976: condition-name 'G1-A': … may not be associated with an alphanumeric group containing
  an item whose usage is not DISPLAY — ISO §13.16.3 SR24 excludes "c) An alphanumeric group containing items with
  a usage other than display."
(10,11): error COBOLNET1976: condition-name 'VG-A': … may not be associated with an alphanumeric group containing
  an item whose usage is not DISPLAY — ISO §13.16.3 SR24 excludes "c) An alphanumeric group containing items with
  a usage other than display."
```

`G1` is an alphanumeric group and **c) is correct for it**. `VG` is a **variable-length group** — it has a
dynamic-length elementary member — and it draws the **same letter c)**, quoting the standard's own sentence for a
rule it does not violate.

## Expected, from the standard

```
$ python scripts/spec/cite.py --check 3.11 "group item except for a bit group item, a national group item, a strongly-typed group item, or a variable-length group item"
  OK  §3.11

$ python scripts/spec/cite.py --check 13.16.3 "An alphanumeric group containing items with a usage other than display"
  OK  §13.16.3 24)  (Syntax rules)   → "c) An alphanumeric group containing items with a usage other than display."
```

§3.11 defines *alphanumeric group item* as a group item **except for** a bit group item, a national group item, a
**strongly-typed** group item, **or a variable-length** group item — four exclusions — and §13.18.29.4 GR3 is
what makes a group one. SR24 c)'s subject is therefore narrower than the predicate, and §13.16.3 SR24 already
carries the right letter for `VG` two rows further down:

> h) A variable-length group.

So the table is complete and the predicate is not: `c` matches first, and the rows are walked in the standard's
own order with **the FIRST matching row winning** (`ConditionalVariableExclusion`'s own doc says so, and says why
— *"the letter in the diagnostic is the one the programmer looks up"*). That intent is exactly what the
over-inclusion defeats.

## The code site

`src/Cobol.Net.Compiler/Binding/DataBinder.ConditionName.cs`, the `Sr24Exclusions` table, row `'c'`:

```csharp
static d => d.IsGroup && d.GroupUsage is GroupUsage.None
    && AnySubordinate(d, static x => UsageOtherThanDisplay(x))
```

`GroupUsage.None` excludes the BIT and NATIONAL groups (two of §3.11's four) and says nothing about the other
two. The shape the fix wants is **one predicate named for §3.11** — `IsAlphanumericGroupItem` — used by row `c`
and by every other site that means "alphanumeric group item", rather than the two-term test inlined here
(`feedback_one_rule_one_place`).

## What is and is NOT measured, stated honestly

* **Variable-length group: MEASURED above.** Wrong letter, right verdict — h) would refuse it anyway, so no
  legal source is rejected and no wrong answer is computed. The harm is that the user is shown a rule they did
  not violate, which is `under_rejects` only in the sense that the RULE c) claims a population it does not have.
* **Strongly-typed group: NOT measured, and the fixer must not assume it.** Row `g` covers a STRONG type
  *declaration* and a group subordinate to one, and §13.18.57.3 SR2 (COBOLNET1537) bars an 88 immediately after
  any TYPE-clause entry — so the instance case may be refused correctly by a different rule before c) is
  reached. `feedback_validate_the_premise_not_only_the_rule`: probe it before changing the predicate, because
  the fix's observable consequence depends on which of the three fires.
