# PB4433 - hidden-condition arm suppresses COBOL2096 on a bare operand

**Defect.** The new hidden-condition arm of `ReportMisqualifiedCondition` (ConditionBinder.cs:1716, added by the PB2103
review fix ce19f414b) is also reached from the bare-operand classifier (ConditionBinder.cs:1238, IF and EVALUATE)
whenever `Probe` fails. A subscripted scalar data item that hides a container GLOBAL 88 is then told the position
requires a condition-name, and the verdict the same reference draws when no 88 of the spelling exists, COBOL2096
(ISO 8.4.2.3.3 SR2, as the report cites it), is suppressed.

**Witness.** `E:/COBOL-coord/scratch/reports/w20261821a-PB2103-report.md`, R2-1 (low, not blocking at round 2). Not probed by the reporter.
The clause is the report's own; no text is quoted here.

**Fix direction.** The report gives none beyond the symptom: the bare-operand path must reach the hidden-condition arm
only for a reference that is in a condition-name position, so COBOL2096 stays the verdict for a data item.

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/ConditionBinder.cs#ReportMisqualifiedCondition`

## Landed (wave 20261824, group C)

Re-probed on this tree first (`E:/COBOL-coord/scratch/w20261824c/p1.cob`: a container with GLOBAL `88 RELF`, a contained
program with `01 RELF PIC 9`, `IF RELF (1)` and `EVALUATE RELF (1) WHEN 3`): both statements gave COBOL1639 "'RELF (1)' names a
data item, not a condition-name, and this position requires a condition-name", the EVALUATE one adding a false COBOL1634 (Table 15
pairing against a condition the operand never was); `p2.cob`, the same statements with no 88 of the spelling, gave COBOL2096.

Root cause: `ConditionBinder.AnalyzeBareOperand`'s misqualified arm (a declared level-88 whose reference `Probe` could not
resolve) reached the hidden-data-item arm of `ReportMisqualifiedCondition`, which is for positions that admit ONLY a
condition-name (SET Format 4, SEARCH ALL's bare WHEN). A bare operand admits a data item, and ISO 8.4.6.2.1 3) a) makes the
nearer data item the referenced one, so the data item's own verdict (COBOL2096, 8.4.2.3.3 SR2) is the answer.
Fix: `ConditionBinder.NamesHidingDataItem` is the one predicate (also asked by `ReportMisqualifiedCondition`); the bare-operand
arm skips a word it answers true for, so the value arm reports. Pinned by two refusal goldens
(`pb4433_if_...`, `pb4433_evaluate_...`) and `HiddenConditionNameTests.ABareOperand_NamesTheNearerDataItemAndMeetsItsSubscriptRule`
(IF, IF NOT, PERFORM UNTIL, EVALUATE). Review lead R2-2 (the stale verdict list in `SearchAllFormat2Rules`' comment) is fixed too.

**Sites (added by the landing):** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/ConditionBinder.cs#NamesHidingDataItem`, `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/ConditionBinder.cs#AnalyzeBareOperand`, `src/WiseOwl.Cobol.Compiler/Binding/Validation/SearchAllFormat2Rules.cs` (a comment), `tests/WiseOwl.Cobol.Tests.Conformance/HiddenConditionNameTests.cs`.
