# PB5235 - stage 6 of the build redesign: CI reads the same graph and the same store

**Sites:** `.github/workflows/build-and-test.yml` (whole: the merge-group jobs); `.github/workflows/nightly.yml` (whole);
`scripts/buildgraph.py` (`Store`: the store's TRANSPORT only, how a pass record travels to CI; the graph, targets, keys
and dependencies are PB5231's); `scripts/build_targets.json` (whole: read, not restructured).

**What stage 1 left.** `scripts/buildgraph.py` keys each test target by the git blob ids of its declared inputs plus its
facets (platform, configuration, toolchain), and stores a pass in `cobol-build-store/<target>/<key>.json` under the git
common directory, which only this host's worktrees share. CI cannot see it, so the merge group re-runs every population on
both OSes. PB5218 states the declared inputs are checked statically (`buildgraph.py check`) and that the dynamic proof, the
Linux shards' file watch per target, is the remaining work.

**The work.**
1. **The transport.** A pass record is small (target, key, platform, configuration, toolchain, counts). Publish the
   records where CI can read them, PB5207 suggests a ref of the repository pushed with the branch, so a record travels
   with the commit it proves; the evidence files stay on the host that made them. Decide the ref's shape, who writes it
   (the landing, once it pushes) and how it is pruned, and record the decision here.
2. **The merge group computes keys and runs only what is missing.** A first CI job computes every target's key at the
   merged tree for each platform and configuration and emits the set with no pass. The test jobs run only that set. After a
   clean merge of a branch whose targets all passed locally, that is the Linux targets and whatever Release does not share
   with Debug. What CI still proves alone is stated per target in `docs/rearchitecture/DESIGN-test-build-ci.md`, never
   assumed.
3. **The dynamic input proof.** The Linux shards already watch file access. A shard fails when a test of a target opens a
   tracked path outside that target's declared inputs, naming the path and the test. This is what makes "up to date
   exactly when the store holds a pass at its key" safe to trust across hosts.
4. **The nightly** runs the graph's slow targets (the NIST CLI guard, the GnuCOBOL differential, every self-test on both
   OSes) on a schedule, and a red one is recorded where the session probe reads it first.

**Order and shared files.** `scripts/buildgraph.py`: read Mythos's branch `build-stage2-generator` (PB5231) before
touching it and add only the transport. `.github/workflows/`: PB5230 adds one test leg and lands first; merge main after it.

**Before and after** (the DEVLOG entry states both): merge-group minutes per pull request, the share of merge-group jobs
that ran tests already passed locally, and a witness run in which a test reading an undeclared path fails its shard.
