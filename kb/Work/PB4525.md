# PB4525 — highest-algebraic-trailing-p-scaling: HIGHEST-ALGEBRAIC / LOWEST-ALGEBRAIC count trailing P scaling positions twice (PIC 999PP gives 9999900)

Filed 2026-11-03 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-batch-3000-20261103`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

HIGHEST-ALGEBRAIC and LOWEST-ALGEBRAIC of a numeric DISPLAY item whose PICTURE ends in scaling positions (`999PP`) return
a value 100 times too large: 9999900 for `PIC 999PP`, whose largest value is 99900. The P positions are counted twice,
once as digits and once as scale. Leading P (`PP99`) is right.

## Minimal test case

Free reference format (`-free`).
```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. HAPP.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 WS-A PIC 999PP VALUE 0.
01 WS-B PIC S99PP VALUE 0.
01 WS-C PIC PP99 VALUE 0.
01 WS-R PIC S9(9)V9(6) VALUE 0.
PROCEDURE DIVISION.
    COMPUTE WS-R = FUNCTION HIGHEST-ALGEBRAIC (WS-A)
    DISPLAY "HA 999PP  " WS-R
    COMPUTE WS-R = FUNCTION LOWEST-ALGEBRAIC (WS-B)
    DISPLAY "LA S99PP  " WS-R
    COMPUTE WS-R = FUNCTION HIGHEST-ALGEBRAIC (WS-C)
    DISPLAY "HA PP99   " WS-R
    MOVE 99999 TO WS-A
    COMPUTE WS-R = WS-A
    DISPLAY "MOVE MAX  " WS-R
    STOP RUN.
```

## Environment

cobc (GnuCOBOL) 3.2.0 on WSL2 Ubuntu. `cobc -x -free -std=cobol2014 -o p prog.cob && ./p`.

## Observed result

```
HA 999PP  +009999900.000000
LA S99PP  -000999900.000000
HA PP99   +000000000.009900
MOVE MAX  +000099900.000000
```
Exit code 0. The last line shows cobc itself stores at most 99900 in the item.

## Expected result (per ISO)

§15.43.4 rule 2 (2014, 2023; the function is new in 2014): "The value returned is equal to the positive algebraic value of greatest finite
magnitude that may be represented in argument-1." §15.58.4 rule 2: "The value returned is equal to the lowest finite
algebraic value that may be represented in argument-1." §13.18.40.4 rule 14: "each symbol 'P' is counted in the maximum
number of digit positions" and the algebraic value "assumes the decimal point in the prescribed position and zero in
place of each digit position specified by the symbol 'P'". So `999PP` holds at most 99900 and `S99PP` at least -9900.
Expected:
```
HA 999PP  +000099900.000000
LA S99PP  -000009900.000000
HA PP99   +000000000.009900
MOVE MAX  +000099900.000000
```

## Our compiler

WiseOwl COBOL (fresh judge) prints the expected output above.

## Fix site

libcob/intrinsic.c (read in a 3.3-dev tree), `cob_intr_highest_algebraic` and `cob_intr_lowest_algebraic`, the
`COB_TYPE_NUMERIC_DISPLAY` / `PACKED` / `EDITED` case: the value is built as 10 ** `COB_FIELD_DIGITS` - 1 with scale
`COB_FIELD_SCALE`; for trailing P the digit count already includes the P positions and the negative scale multiplies by
10 per P again.

## Draft issue

**Title:** HIGHEST-ALGEBRAIC / LOWEST-ALGEBRAIC count trailing P scaling positions twice (PIC 999PP gives 9999900)

cobc (GnuCOBOL) 3.2.0, WSL2 Ubuntu, `cobc -x -free -std=cobol2014 -o p prog.cob && ./p`.

For `01 WS-A PIC 999PP`, `FUNCTION HIGHEST-ALGEBRAIC (WS-A)` returns 9999900; the largest value the item can hold is
99900 (MOVE 99999 TO WS-A stores 99900). `FUNCTION LOWEST-ALGEBRAIC` of `PIC S99PP` returns -999900; expected -9900.
Leading P (`PIC PP99`) gives the right 0.0099.

ISO/IEC 1989:2014 §15.43.4 rule 2: "The value returned is equal to the positive algebraic value of greatest finite
magnitude that may be represented in argument-1"; §15.58.4 rule 2 likewise for the lowest value; §13.18.40.4 rule 14:
each P is counted in the maximum number of digit positions and stands for a zero digit.

Program (free format):
```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. HAPP.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 WS-A PIC 999PP VALUE 0.
01 WS-B PIC S99PP VALUE 0.
01 WS-C PIC PP99 VALUE 0.
01 WS-R PIC S9(9)V9(6) VALUE 0.
PROCEDURE DIVISION.
    COMPUTE WS-R = FUNCTION HIGHEST-ALGEBRAIC (WS-A)
    DISPLAY "HA 999PP  " WS-R
    COMPUTE WS-R = FUNCTION LOWEST-ALGEBRAIC (WS-B)
    DISPLAY "LA S99PP  " WS-R
    COMPUTE WS-R = FUNCTION HIGHEST-ALGEBRAIC (WS-C)
    DISPLAY "HA PP99   " WS-R
    MOVE 99999 TO WS-A
    COMPUTE WS-R = WS-A
    DISPLAY "MOVE MAX  " WS-R
    STOP RUN.
```
Observed: `HA 999PP  +009999900.000000`, `LA S99PP  -000999900.000000`.
Expected: `HA 999PP  +000099900.000000`, `LA S99PP  -000009900.000000`.

In libcob/intrinsic.c the DISPLAY/PACKED case of `cob_intr_highest_algebraic` builds 10 ** digits - 1 and then applies
the field's negative scale, so the P positions are counted twice.
