# A11 — ANNEX A.1 IMPLEMENTOR-DEFINED DOCUMENTATION REGISTER

- ANNEX A.1 IMPLEMENTOR-DEFINED DOCUMENTATION REGISTER — A.1 lists 222 implementor-defined elements (164 required · 26 conditionally required · 29 optional), of which 199 carry "This item shall be documented in the implementor's user documentation." `docs/CONFORMANCE.md` documents A.3 and A.4 but had no A.1 section at all until 2026-07-20, when §7 was opened with item 158 (margin R).
- **D13 defines "100% conforming" as the mandatory core complete PLUS every required implementor documentation item** — so 199 undocumented determinations are a direct v1.0 conformance gap, not a tidiness issue. Found incidentally while deriving margin R for the reference-format fix (DEVLOG 931); nothing was tracking it.
- Every A.1 row determined + written to CONFORMANCE.md §7, or explicitly dispositioned (N/A where the element belongs to an unclaimed optional/processor-dependent facility)
- **P14 Step 0** (the traceability inventory enumerates A.1 alongside the clause/statement surface; A.1 rows are inventory rows)
- **MEASURED 2026-08-03 — 10 of 199 written, 189 remain.** `python scripts/spec/audit_annex_a1.py` computes it from the catalog parsed straight out of Annex A.1; never hand-count it again. ⛔ **THREE CORRECTIONS TO THIS ROW'S OWN NUMBERS, all found by building that check.** ① "1 of 199 written" was stale — §7 already carried ten determinations (items 2, 59, 158, 202 and the V59 storage family 205–215). ② **The split "164 required · 26 conditionally required · 29 optional" sums to 219, not 222** and was repeated verbatim in CONFORMANCE.md §7; measured it is **164 required · 30 optional · 27 conditionally required · 1 unclassified** (item 176, the SET NaN payload, states its class in prose instead of the standard sentence — a one-item parser gap in `extract_rule_catalog.py`, not a transcription defect). ③ **§7 filed the §15.3.3.2 fractional-seconds determination under item 87, which is `FORMATTED-CURRENT-DATE (accuracy of returned time)` — a different, still-undocumented obligation.** It is **item 202**. Inherited citation, never re-derived: CLAUDE.md rule 1's exact failure mode, and CONFORMANCE.md §7's own preamble calls a wrongly-documented determination worse than an undocumented one. `audit_annex_a1.py --check` now re-derives every number and is proven to fail on that very defect.

**2026-09-02 — the misfiling is now STRUCTURALLY UNSPELLABLE, and its second half was found and closed.** ③ above
described a determination filed under the wrong item; the audit could *detect* that, and detection is a weaker
thing than impossibility. §7's item key is now the inventory rule-id `DOC-A.1-<n>`, and the inventory row's
`code-location` is **computed** from its own rule-id as `docs/CONFORMANCE.md#DOC-A.1-<n>`
(`tests/version-matrix/inventory-schema.json` → `kinds.DOC.anchor-template`; the evaluator is
`Schema.anchor_for` / `AnchorFor`, and `EveryKindAnchoredRow_AnchorsItsOwnRegisterEntry` holds it). A
determination filed under a neighbouring item cannot be *spelled*: the anchor is derived, never typed.

⭐ **And the same failure was live one layer down, in the EVIDENCE rather than the determination** — the half this
row's ③ never named, and the half that actually cost the most. The first A.1 back-fill closed **item 87**
(FORMATTED-CURRENT-DATE, accuracy of the returned time, §15.38.4) on
`CobolDateWindowingTests.SecondsPastMidnight_PinnedClock_ExactTicks` — which is **item 171's** test (§15.80.3 r3),
cites §15.80.3 in its own comment, and never calls `FormattedCurrentDate` at all. One test about item 171 was
closing both 171 and 87. Neither existing gate could see it: `UnresolvedTestRefs` asks only that the method be
declared, and `IsSpecDerived` only that the form and the method name qualify. The structural answer is the §7
row's new machine-readable **`Pinned by`** cell plus `audit_annex_a1.py`'s check that every spec-derived
`test-ref` on a DOC row is named by that item's OWN §7 row — the determination and its evidence made one artifact.
Item 87 is re-referenced onto `NowFunctions_OnePinnedClock_OneInstant`, and **the row is nevertheless left OPEN**:
that test pins **two** fraction digits where the determination claims seven-then-zeros, and a test that does not
verify the determination cannot close its row. Its inventory `test-ref` and its §7 `Pinned by` cell are both
EMPTY — CONFORMS-but-untested, still a GAP, until a golden renders a long fraction field from a pinned clock.
(Orchestrator decision 2026-09-02, over the back-fill's close. The lesson generalises: the second failure mode
this row names is *evidence that names the right function and still does not assert the claim*, and only reading
the test against the determination catches it.)

⚠ **Status stays `open`, and deliberately.** This row's goal is *every* A.1 element determined or dispositioned;
`audit_annex_a1.py` measures **39 of 222 items · 36 of the 195 in scope · 159 obligations remaining** — unchanged
by this work, which recorded the determinations that already existed rather than writing new ones. What changed is
that those 39 are now visible to the burn-down (**18 rows closed, 19 CONFORMS-but-untested**, 2 held for
[[PB280]] Q1) instead of sitting verdict-less while §7 already carried them.

⚠ The denominator is **195, not the 199 A.1 marks "required"**: the derived-verdict lane declines four modules
whose items A.1's own preamble then withdraws (items 84, 85, 173 — the FORMAT and SELECT WHEN clauses — and 86,
format validation). The audit DERIVES that set from the `derived-verdicts` selectors (`unreachable_items`) rather
than listing it, so the next declined module adjusts this count with no edit anywhere.
