# PB5553 - the shard-weights STALE check will redden the nightly a few days after every regeneration, and each red needs a hand regeneration through the code lane

UNVERIFIED LEAD: re-probe before fixing.

**Source, verbatim.** Review w20262036a-review-r1 of PB5552 (findings file
`E:\COBOL-coord\scratch\op-20261114\review-w20262036-a.jsonl`), lead R1-1, low, `scripts/shard_weights.py:28`: "At the
0.10 limit, STALE will redden the nightly a few days after each regeneration. The 2026-11-04 weights already read 0.17
on Linux and 0.32 on Windows on the run of 2026-11-07. Each red needs a regeneration landed through the code lane by
hand."

**What PB5552 did and why this remains.** PB5552 regenerated `tests/_shared/test-weights.json` and made the report fail
early when the work in classes the file does not name exceeds 0.10 of a mean shard. That catches staleness before the
spread goes red, but the test population grows by hundreds of classes a week, so the check will fire again within days,
and the remedy is a manual regeneration that must pass a full local gate. A nightly that is red every few days by design
teaches people to ignore it.

**The direction to examine, as a question for whoever takes the note.** The root is that `TestWeights.Deal`
(`tests/_shared/GateLegs.cs`) gives a class the weights file does not know the 0.1 s default and deals it after every
named class, so new classes pile into one shard (PB5552 measured about 150 s a run landing on Linux shard 2). If the
deal instead gave an unknown class a typical weight (for example the median of the named classes of its assembly) and
spread unknown classes across shards, would a stale file cost little spread, could the STALE threshold be loose, and
would a regeneration become housekeeping instead of the response to a red? An alternative PB5552's worker considered: a
scheduled regeneration, rejected there because a weights change needs a local gate record to land. Whoever takes this
measures before choosing: replay the eight runs of 2026-11-14 through a deal with the changed default and report the
spread.
