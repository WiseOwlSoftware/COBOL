# PB4011 — a `Head:` field after other text on its line is not a field, so prose wins

## What happened

Wave 20261740 group B (PB3974) ran its round-1 review finisher on `worktree-wf_0c0f6eee-9f8-6`. It answered R1-1,
gated GREEN at `caf67d4cf` and rewrote its report (`E:\COBOL-coord\scratch\reports\w20261740b-PB3974-report.md`).
The header carried the base and the head on one line:

```
Base: 1da5e0d6b (origin/main when planned; merged reviewed head 5ba5c563c of worktree-wf_0c0f6eee-9f8-2)   Head: caf67d4cf06eca5a27403725d538f339b65da5ba
```

`reports.parse_report` read the report's HEAD as `5ba5c563c`, the predecessor's head named in the Base field's prose.
`prune_worktrees.py` then printed the branch as `DECISION … DONE, but 2 commit(s) since the report's HEAD 5ba5c563c
that no report describes`. That state asks for "a resumed agent rewrites its report", so nothing in the loop planned
the round-2 review. The loop raised `STALL w20261740b (PB3974)` every ten minutes, from 13:32 until the operator
looked at 18:05, 269 minutes on its branch review.

## The mechanism

`scripts/orchestrator/reports.py#sha_field` builds two patterns per word, and `#header_sha` tries them in order:

1. **The field:** `(?im)(?:^|[·|])[ \t]*\**head\b:?…`. The word must start a line or follow a ` · ` or ` | `
   separator.
2. **The fallback:** `(?i)\bhead\b[:*`\s]*…`. The first `head <sha>` anywhere in the header.

PB3181 put the field first so prose before it cannot win (w1080f's "(reviewed head db7e19186 merged in) · head
5df3c56a3"). But a header whose fields are separated by a run of spaces, which agents write freely, has no field
position for the second field on the line. The field pattern finds nothing, and the fallback takes the first prose
mention. The colon that marks `Head:` as a field is optional in pattern 1 and ignored by pattern 2, so it decides
nothing.

The producer is the review finisher's prompt (`.claude/skills/workstream/templates/wf_rolling_wave.js#fixFindings`):
"its header names your worktree, branch, base and HEAD". It gives no layout, the same gap PB3260 records for the
missing Status line. `implementer-report-template.md` line 3 puts each field after ` · `, which parses.

## Sweep

Over the 924 reports in `E:\COBOL-coord\scratch\reports` on 2026-10-28, a `head:` with its colon anywhere in the
header disagreed with `reports.HEAD` on exactly one report: this one. The family is wider than the HEAD field:
`BASE` uses the same `sha_field` and fails the same way, and PB3084 (open) is the branch field's form of it.

## Fix shape

1. **Parser.** In `sha_field`, a `word:` WITH its colon is a field wherever it follows whitespace, so a run of spaces
   separates fields as ` · ` does. A colon-less `word <sha>` is still read only at a field position, and the prose
   fallback stays last. Add a self-test arm in `test_plan_wave.py` beside the w1080f arm, using this header line,
   for HEAD and for BASE.
2. **Producer, structurally.** Fold this into PB3260's fix item 2. Every agent returning DONE runs the finished test on
   its own report as its last step. That test also compares the report's parsed HEAD with its worktree's
   `git rev-parse HEAD`, and refuses a mismatch. Then any layout the parser misreads is caught by the agent that wrote
   it, whatever its shape, and the predicate stays in one place.
3. **Prompt.** PB3260's item 1 already makes `fixFindings` name the template's header. Name the field separator there
   too.
