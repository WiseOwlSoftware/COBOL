# PB600 — OPEN — the twin PB236 named and did not take

Found 2026-09-05 by the `PB236` implementer, which moved RELEASE's and RETURN's operand rules to bind time and
measured the same shape on WRITE and REWRITE; deliberately left as a second mechanism. Re-derived on this tree.

## The rule

§14.9.51.3 SR1 — `cite.py --check 14.9.51.3 "The write file is the file referenced by file-name-1 or by the
file-name associated with record-name-1."` → the general format's record-name-1 IS a record of a file
description entry, and a name that is not one is the §8.4.2.1 "no such name in this context" violation, a
compile-time matter (§4.2.2). §14.9.35.3 (REWRITE) states the same association for its record-name-1; re-derive
its SR1 text with `cite.py` before implementing (the fix's first step).

## The mechanism

`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/SequentialIoBinder.cs#BindWrite` and `#BindRewrite`: when
record-name-1 does not resolve to an FD record the statement becomes a `BoundUnsupported`, which since PB236 is
announced (COBOLNET1756, warning) and renders as a run-time `NotImplemented` loud — so illegal source behind a
`GO TO` compiles and runs clean with one warning, exactly the RELEASE/RETURN shape PB236 fixed, one verb pair over.

## Fix shape

Route both through `StatementValidation` with COBOLNET1757 and the verb's own clause quoted (WRITE §14.9.51.3
SR1; REWRITE §14.9.35.3 SR1), the same call PB236 wired for RELEASE (`§14.9.32.3 SR1`) and RETURN
(`§14.9.34.3 SR1`) — one screen, four callers. Two negative goldens (a WRITE and a REWRITE of a WORKING-STORAGE
record, each behind a `GO TO` so the old posture's silence is what the fixture distinguishes), all four editions.
