# PB3962 — ZeroTokenRewriter reads the sign of a signed numeric literal that FOLLOWS a figurative ZERO as a binary operator, so an operand list that is not an arithmetic expression no longer parses

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/ZeroTokenRewriter.cs` (`Rewrite`, `IsSignOfNextLiteral`), `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs` (`RawValueOperandText`; `RewrittenAllZeroRawText` deleted), `docs/rearchitecture/DESIGN-frontend-grammar.md` (section 7, the rewriter paragraph), `tests/WiseOwl.Cobol.Tests.Unit/CobolLexerModeDriftTests.cs`

Pre-existing, found outside PB3846's diff. In an operand list that is not an arithmetic expression, a figurative ZERO
followed by a signed numeric literal (`ZERO -1`, `ZERO +1`) is rewritten to `ZERO_ARITH` because the rewriter reads the sign
as a binary operator; the list then no longer parses. PB3846 fixed the one sibling that parses (the level-88 VALUE list,
`DataBinder.RewrittenAllZeroRawText`) at the reader, not at the rewriter, so the root stays. Harm: legal source (a
value list `ZERO -1`) may be refused; the report gives no repro, so the fix starts with one.

## Acceptance
- A repro per list position (level-88 VALUE, WHEN, SEARCH ALL, other operand lists); the rewriter decides operator versus
  sign by the grammar position, not the token shape; remove the reader-side workaround in `DataBinder` if it becomes dead
  (no shim, CLAUDE.md rule 4).

## Landed (wave 20261732, group A) — a sign that touches the next literal's digits is that literal's sign

**Re-probe** (`E:/COBOL-coord/scratch/w20261732a/p1.cob`, p3, p4, base `6974abd43`): `DISPLAY ZERO -1` was a bare COBOL0001
("unexpected '0'"), `DISPLAY N ZERO -1 N` a COBOL2269, and `ADD ZERO -1 TO X`, `SUBTRACT ZERO -3 FROM X` and the level-88
list `VALUE ZERO -1` were refused or read the ZERO as the numeric 0 where the list is not an expression. An EVALUATE `WHEN
ZERO -1` is an arithmetic expression and drew COBOL2993 (a binary operator not followed by a space).

**Mechanism.** `ZeroTokenRewriter.Rewrite` took the type of the ZERO's right neighbour (`+`/`-`) as proof of an operator.
The lexer's default mode lexes `-1` as MINUS INTEGERLIT outside a list region, so the token type cannot tell the operator
of `ZERO - 1` from the sign of `ZERO -1`; the SOURCE POSITIONS can, and the standard states the test: §8.7.1 makes a binary
operator a character "preceded by a space and followed by a space", and §8.3.3.3.2 2) makes a sign "the leftmost character
of the literal", so a sign touching the digits of the next literal is no operator. The grammar-position wording of the
acceptance is the same fact seen from the other side: the sign is an operator only where an expression can follow, and
§8.7.1 spells that as the spacing.

**Fix.** `IsSignOfNextLiteral` (token positions: an integer, decimal, floating-point or DECIMAL-POINT IS COMMA literal
touching the sign) vetoes the FOLLOWING-operator arm only; every operator on the ZERO's left, a spaced operator and the
paren and colon arms are unchanged. The reader-side patch PB3846 added for the VALUE list (`DataBinder.RewrittenAllZeroRawText`)
is dead (an `ALL ZERO -5` list now parses as the figurative constant it is) and is deleted, with no shim. A consequence kept
on purpose: an arithmetic `COMPUTE X = ZERO -1` is now a COBOL0001 at the sign, not COBOL2993, the same position
diagnostic `5 -1` between two operands of a list draws; the source is invalid either way.

**Golden:** `conformance-suite/cases/8.3.3.6-Figurative-constant-values/pb3962_figurative_zero_before_a_signed_literal`
(ADD, ADD GIVING, SUBTRACT, two VALUE lists and the spaced `ZERO - 1` control; accepted at all four editions, so no
refusal program); unit theories `CobolLexerModeDriftTests.Zero_BeforeASignTouchingItsLiteral_StaysFigurative` and
`Zero_BesideAnOperator_IsStillRewritten`; the PB3846 goldens (`88 C VALUE ALL ZERO -5`) now run through the figurative arm.

## Landing (for the next implementer)

- `src/WiseOwl.Cobol.Frontend/Parsing/ZeroTokenRewriter.cs#IsSignOfNextLiteral` owns the sign-versus-operator question for the ZERO's
  FOLLOWING neighbour (token positions: a sign touching an integer / decimal / floating-point / comma-fraction literal). Reuse it for
  any new pass that reads a `+` / `-` beside a word; do not re-ask by token type alone. Trap: the lexer splits `-1` into MINUS
  INTEGERLIT outside a list region, so the token stream carries no sign-literal fact.
- `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs#RawValueOperandText`: the ZERO_ARITH reader patch is gone; a VALUE list
  `ALL ZERO -5` parses through the figurative arm.
- An arithmetic `COMPUTE X = ZERO -1` was COBOL0001 at the sign after this landing (it had been COBOL2993); PB3981 restored
  COBOL2993 by asking the parse (`ZeroSignReading`), so it is COBOL2993 again.
