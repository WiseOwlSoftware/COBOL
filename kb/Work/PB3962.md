# PB3962 — ZeroTokenRewriter reads the sign of a signed numeric literal that FOLLOWS a figurative ZERO as a binary operator, so an operand list that is not an arithmetic expression no longer parses

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/ZeroTokenRewriter.cs:132`, `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs` (`RewrittenAllZeroRawText`)

Pre-existing, found outside PB3846's diff. In an operand list that is not an arithmetic expression, a figurative ZERO
followed by a signed numeric literal (`ZERO -1`, `ZERO +1`) is rewritten to `ZERO_ARITH` because the rewriter reads the sign
as a binary operator; the list then no longer parses. PB3846 fixed the one sibling that parses (the level-88 VALUE list,
`DataBinder.RewrittenAllZeroRawText`) at the reader, not at the rewriter, so the root stays. Harm: legal source (a
value list `ZERO -1`) may be refused; the report gives no repro, so the fix starts with one.

## Acceptance
- A repro per list position (level-88 VALUE, WHEN, SEARCH ALL, other operand lists); the rewriter decides operator versus
  sign by the grammar position, not the token shape; remove the reader-side workaround in `DataBinder` if it becomes dead
  (no shim, CLAUDE.md rule 4).
