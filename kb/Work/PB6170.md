**Wave kind:** unify. **Model:** Sonnet, a mechanical move of one constant.

**Found by PB6168.** Adding C# 15's `closed` modifier to 20 records made
`SpecTraceabilityInventoryDriftTests.EveryCSharpFilesSymbols_AgreeWithThePythonResolver` fail. The Python resolver's
modifier list did not know the keyword, so it lost every type declared `closed`.

The same vocabulary is written in ten places across six tools (the branch review of PB6168 found
`scripts/buildgraph.py`'s two and the test-type abstract flag in `drift_rules.py`):
- `scripts/spec/code_location.py` (`MODIFIERS`);
- `scripts/spec/drift_rules.py` (`TYPE_DECL`, `CLASS`, `_TYPE`);
- `scripts/arch/source_units.py` (`_MODIFIERS`);
- `scripts/prune_worktrees.py` (`DECL`, `METH`);
- `scripts/buildgraph.py` (`FIRST_TYPE`, `TYPE_DECL`);
- `scripts/gen-vault-reference.ps1` (`$declRx`).

PB6168 and its review fix added `closed` to each one. One more copy is `tools/claude-skills/skills/agent-fleet/references/orient.py`
(`_MODS`), which lives in the public skill submodule and needs a change upstream.

**Sites:**
- `scripts/spec/code_location.py:57` (`MODIFIERS`)
- `scripts/spec/drift_rules.py:115` (`TYPE_DECL`, `CLASS`, `_TYPE`)
- `scripts/arch/source_units.py:265` (`_MODIFIERS`)
- `scripts/prune_worktrees.py:202` (`DECL`, `METH`)
- `scripts/gen-vault-reference.ps1:45` (whole: `$declRx` is a script-level variable, not a member)
- `scripts/buildgraph.py:1245` (`FIRST_TYPE`, `TYPE_DECL`)
- `scripts/spec/drift_rules.py` (`test_types`: its abstract flag reads a closed type as abstract too)

**Target:** one Python module owns the C# modifier set, and each Python tool builds its pattern from it. The PowerShell
script reads it through a JSON export or calls the Python. A drift test then fails when any tool spells its own list.
Every list today is a SUBSET of the language's modifiers, chosen for its own position (a type header, a member header,
a local), so the shared module names each subset explicitly instead of one flat list.
