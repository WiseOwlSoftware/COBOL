# PB1924 — LANDED (CONFORMS, w1033)

Filed by the train-1004 lander from wave 1004 group C's report (`w1004c-PB1175-report.md`).

## Question

§14.9.40.3 SR6 d): "A key data item shall not be a variable-length group, an occurs-depending-on data item, a
dynamic-length elementary item or an item subordinate to a dynamic-capacity table" (`cite.py --check 14.9.40.3` OK).
Wave 1004 group C (kb/Work PB1173) reads "occurs-depending-on data item" to include the GROUP that holds the OCCURS
DEPENDING ON (§13.18.38.4 GR8: its size varies), because a varying window cannot be SR6 e)'s "same byte positions".
The lander notes the same group is also a variable-length group, which SR6 d) names separately, so both readings may
refuse it; the adjudicator should say which phrase carries the refusal and whether the diagnostic should cite it.

**Site.** `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/SortKeyAdmission.cs#Violation`. Negative golden
`conformance:negative/pb1173-sort-file-key-odo-group`. The Format-2 SR14 d) ODO-group arm has no witness (unreachable
behind COBOLNET0854).

## Adjudication 2026-10-07 (w1033)

Decision `E:\COBOL-coord\scratch\w1033-adj\PB1924-decision.md`; refuter `PB1924-refute.md` (UPHELD). Pinned build `pin-97006f3` (main `97006f310`); probes `PB1924\`, `PB1924-refute\` (`gen.py`, `run.py`, logs `<probe>_<std>.log`).

**Outcome: CONFORMS, NO DEFECT. Closed as landed; no code change.** The answer to the note's question is yes: `§14.9.40.3 SR6 d)`'s "occurs-depending-on data item" includes the occurs-depending GROUP (read as `§13.18.38.4 GR8`'s
occurs-depending group item), so a file-SORT key that is such a group is refused, and the refusing phrase is "an occurs-depending-on data item" ONLY. The "variable-length group" phrase does NOT apply.

**Spec (cite.py --check OK; the refuter re-ran all 12 and added five).**
- `§14.9.40.3 6) d)`: "A key data item shall not be a variable-length group, an occurs-depending-on data item, a dynamic-length elementary item or an item subordinate to a dynamic-capacity table"; MERGE `§14.9.24.3 4) d)` (with a serial comma).
- "occurs-depending-on data item" is not a defined term; the same statement's Format 2 `§14.9.40.3 14) d)` says "shall not reference a variable-length group or an occurs-depending group item"; `§13.18.12.3 2)` (CODE) uses the same hyphenated form and names the group;
  `§13.18.38.4 8)` defines the occurs-depending group item (conflicts with SR6 e): the same byte positions are the key in all records); `§13.18.63.4 6) a)`.
- Other readings fail: the ODO table entry (already refused by `6) b)` and `f)`; redundancy within d) proves nothing, but SR14 d), the CODE list and `§13.18.63.4` still defeat it); the DEPENDING ON object (the standard says "the depending on data item"; `§13.18.38.3 17)` makes data-name-1 an integer, never a group);
  "variable-length group" (`§8.5.1.12.1`: only dynamic-length elementary items and dynamic-capacity tables make a group variable-length; `§8.5.1.11.1` confirms; an occurs-depending table is neither).
- No implementor latitude ("shall not"); GnuCOBOL 3.2 accepts a, b, c, d, i, l, which makes it under-reject, not authoritative.
