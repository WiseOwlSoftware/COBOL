# PB1733 — OPEN

Filed by the train-72 lander, 2026-09-29, from wave 72 group H's report (PB1721/PB1720, M13).

## Finding

**Observed.** During PB1720's N measurement (four cold gates at once on the shared 32-core host), one Conformance
case went red:
`CorpusRunnerTests_P2.EnabledProgram_CompilesStrict_AndMatchesOutIfPresent(2002, pb969_empty_argument_list)` with the
assertion message `[2002/pb969_empty_argument_list] must run: ` — the `detail` was EMPTY. The same case is green on
every quiet run, including train 72's lander gate (9,321/9,321) and its Linux gate.

**Evidence.** The `n3-r2` m3 log of `docs/rearchitecture/evidence/impact-map-pb1708/m13.txt` (repro driver
`docs/rearchitecture/evidence/impact-map-pb1708/m13-measure-n.py`, the `n3` runs).

**Code site.** `tests/Cobol.Net.Tests.Conformance/CorpusRunnerTests.cs:193–194`
(`var (ran, stdout, detail) = CutRunner.Run(dll, tmp); Assert.True(ran, $"… must run: {detail}")`). The defect is
in `CutRunner.Run`'s failure paths: at least one returns `ran = false` without saying why (exit code, timeout, the
exception, stderr).

**Harm.** A red that cannot be attributed. Under load it reads as a flake, which the gate discipline forbids
calling it, and nobody can tell a real run failure from a host effect.

**Fix shape.** Every `ran = false` path of `CutRunner.Run` names its cause (exit code and stderr, or the timeout and
its limit, or the exception), and a drift or unit test pins that no failure path returns an empty detail.
