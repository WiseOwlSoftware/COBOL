Filed 2026-10-11 by the train 1056b lander from the wave 1056 group G (PB2840 + PB2845) implementer's report, lead 1.

## Code site

`src/WiseOwl.Cobol.Frontend/Preprocessor/ConditionalCompilationProcessor.Display.cs:62`, `ParameterText`:
`inputs.GetEnvironmentVariable(name.ToUpperInvariant())`. The ONE lookup of the DEFINE and DISPLAY directives'
PARAMETER phrase (§7.3.11.4 GR4, §7.3.12.4 GR3; kb/Work PB1533 made every spelling of one name read one variable).

## Why it is a defect

A compilation-variable-name is a COBOL word, and PB2845 moved every other COBOL-word key from the host's case
mapping to `CobolNames.UpperFold` (the Annex C fold, §8.1.3.2 GR3 b). This key was left on the host mapping on
purpose: moving it changes WHICH environment variable is read for a name holding an extended letter (for example a
long s, which the host maps to S and Annex C below 2023 does not), so the canonical environment-variable spelling of
such a name must first be decided in DOC-A.1-49 / DOC-A.1-55 (docs/CONFORMANCE.md), then the key changed to match.

## Repro

`>>DEFINE` a compilation-variable-name holding an extended letter `AS PARAMETER`, set the environment variable under
the Annex C spelling and under the host's upper-case spelling, and `>>DISPLAY` the variable: the host spelling is
the one read.

## Landing

Decision (DOC-A.1-49 / DOC-A.1-55, docs/CONFORMANCE.md section 7): the implementor-defined method of §7.3.11.4 GR4 and
§7.3.12.4 GR3 names the environment variable by `CobolNames.UpperFold(name)` -- the Annex C fold of §8.1.3.2 GR3 b) and
GR4 b) with the basic letters written A-Z, the one upper-case key of every COBOL word in the compiler -- so two spellings
Annex C.2 makes one word (the Kelvin sign and K) read ONE variable and two it keeps apart (a long s and S) read two. An
extended letter stays in its fold (Annex C maps only upper to lower), which is also what every other COBOL-word key of the
compiler does. The ISO standard leaves the method to the implementor (GR4 "an implementor-defined method"), so the choice
follows the project's own single word key, and the precedence of CLAUDE.md rule 1 is met by the ISO text leaving it open and the project's own key being the one every word table uses.

Fix: `ConditionalCompilationProcessor.ParameterText` (the ONE lookup of DEFINE and DISPLAY) reads
`CobolNames.UpperFold(name)`. Witness: `ParameterVariableNameTests` (Unit) asserts the NAME the compilation recorded on its
`CompilationInputs.EnvironmentReads` for both directives, so it holds on a host with case-insensitive environment names.
Drift: `CobolNameFoldDriftTests.HostUpperKey` now also matches `GetEnvironmentVariable(... .ToUpperInvariant())`.
Sibling sweep: every `GetEnvironmentVariable` in src (the other readers take fixed ASCII names; `SwitchStore.VariableNameFor`
is keyed on the ImplementorNames table row `DataBinder.BindImplementorNameEntry` stores, never the user's spelling) and every
host case mapping in `Frontend/Preprocessor` and `Frontend/Pipeline` (the rest only upper-case a word for a message).

Next implementer: `src/WiseOwl.Cobol.Frontend/Preprocessor/ConditionalCompilationProcessor.Display.cs#ParameterText` owns the
environment-variable key of both directives (REUSE `CobolNames.UpperFold`, never a host case mapping);
`tests/WiseOwl.Cobol.Tests.Unit/ParameterVariableNameTests.cs` shows the host-independent witness (the name recorded on
`CompilationInputs.EnvironmentReads`; build the Kelvin sign and the long s from code points, a tool can rewrite a literal).
