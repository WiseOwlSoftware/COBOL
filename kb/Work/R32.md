# R32 — a declared SCREEN SECTION name draws COBOLNET1639 'not defined': the declaration side never registers screen names

> Found by the R21+R22+R30 comprehensive battery's differential leg (2026-08-08): flip
> `syn_screen:221` ("FROM clause"), AGREE_ACCEPT → WE_REJECT_THEY_ACCEPT, ourCodes
> [COBOLNET1560, COBOLNET1639].

THE CASE: a standard SCREEN SECTION (`01 SG.` with FROM-clause fields) + `DISPLAY SG END-DISPLAY`.
`SG` IS declared — in a section this compiler stages (COBOLNET1560 rides along) — but screen names are
never registered in the symbol table, so R30's demanding resolver reports the §8.4.2.1 UNDEFINED
diagnostic on a name the source element plainly declares. The message is factually wrong even where the
feature's staging is the accepted posture: "not defined" and "declared in a section this compiler does
not yet support" are different verdicts, and the first sends the user hunting a typo that does not
exist.

FIX SHAPE (root, not a message patch): the screen-section declaration pass registers screen names like
any other declared names, bound to the staged representation the 1560 family already owns — a reference
then resolves to a DECLARED item and the existing feature-staging posture (loud, named, honest) applies.
If registration is structurally blocked, the interim is still resolution-side: the undefined arm must
not fire for a name whose declaration the parse saw. Related: the broader screen-section support level
is whatever COBOLNET1560's documented posture says — this note is ONLY about the wrong diagnostic.

## LANDED 2026-08-08

`DataBinder.ScreenNames` collects every declared screen name at the COBOLNET1560 site; the COBOLNET1639
report exempts them (the documented compile-accept posture holds) and `RefFailure`'s staged loud names
the actual cause ("declared in the SCREEN SECTION … COBOLNET1560; docs/CONFORMANCE.md §4") instead of a
bare unresolved reference. The SAME mechanism swept to the next namespace the differential surfaced
(scan_all_similar): a declared ALPHABET-name referenced in a data position (run_misc:1759's
`INSPECT … CONVERTING BETA TO ALPHA` — GnuCOBOL's alphabet-operand extension, adjudicated by [[R38]])
is likewise exempt with an honest reason. syn_screen:221 and run_misc:1759 reverted to AGREE_ACCEPT.
Golden: `screen_section_reference` (2023, compile-only — no `.out`). Gate: shared with [[R31]]'s legs.
