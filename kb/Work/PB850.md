# PB850 — LANDED — an acceptance posture that stopped being forced

Source: the `PB492` implementer report, item (D). Filed as an adjudication because nothing in the standard is
ambiguous — what is open is whether COBOL.NET tightens now and what that tightening costs.

## The facts

`ItemCategory.IsAlphanumericOrNational` answers TRUE for alphanumeric-edited and national-edited as well as for
the plain categories. Its consumers are the record-key screen (§12.4.5.12.3 SR2) and the ASSIGN USING operand
screen (§12.4.5.6.3 SR2), both of which name only the PLAIN categories. The predicate's doc comment states the
posture — "errs toward accepting legal source" — and PB492 updated it to say the posture is now a CHOICE rather
than a consequence of national-edited being undecidable.

## The two readings

1. **Keep the acceptance.** Under-rejects two shapes per screen; no wrong answer; no legal source refused.
2. **Tighten to the plain categories.** Conforms exactly, and also tightens ALPHANUMERIC-EDITED, which is a
   separate population with its own corpus exposure (NIST programs use alphanumeric-edited keys nowhere, but
   that is an assertion this note has NOT measured — `feedback_reachability_is_measured_not_deduced`).

## Owner question

Does the record-key / ASSIGN USING screen tighten to the plain categories, accepting that it also tightens
alphanumeric-edited? Measure the corpus exposure before answering.

## Code site

`src/Cobol.Net.Compiler/Binding/Model/ItemCategory.cs` (`IsAlphanumericOrNational`) and its two callers.

## Sibling sweep whoever decides owes

* Every other predicate that fuses a plain category with its edited sibling — grep `IsAlphanumeric`,
  `IsNational` — each one is the same question with a different rule behind it.
