# PB234

**Rows:** `GR-14.9.5.4-3`, `GR-14.9.5.4-4`

after PB154 the CANCEL initial-state machinery still refuses legal source — `ADDRESS OF` a static WORKING-STORAGE item in a RECURSIVE program is rejected outright — and the GR4 containee cascade's reverse-source-order is derivation-verified only.

Rows: GR-14.9.5.4-3 (CANCEL places the program in its initial state — the §14.6.2.3.2 actions), GR-14.9.5.4-4 (the cascade over contained programs, in reverse source order).

WHAT PB154 LANDED, so this note reads as residue and not as doubt. GR3's seven initial-state actions are now evidenced: action 2 by conformance:2002/recursive_ws (static WS reset); action 3 by conformance:2023/pb154_cancel_initial's REOPEN=00 (internal connectors reinitialized); action 5 by ADDR=NULL through the new static BASED bridge (RouteStaticUnitStorage routes a BASED root's BasedPointerField into StaticBasedBridgeAddrs, EmitStaticReset appends `{addr} = ManagedPointer.Null;` per bridge, and the data cell joins NO value-reset set because the data lives in the allocated cell); actions 6/7 by CAP=0000000001 and LEN=0 (dynamic-capacity table emptied, DYNAMIC LENGTH item to length zero). An INDEXED BY cell under a BASED table routes into StaticIndexCells like any other WS index cell — the review fleet caught the BASED arm's `continue` skipping that routing, which would have left a per-activation index cell in static WS — and `__ResetStatics` emits every reset line from the ONE source-ordered WorkingStorageRoots walk, bridge addrs included. GR4's cascade runs both ways in conformance:2023/pb154_cancel_cascade (the §14.9.18 GR2 implicit cancel over an INITIAL container's containees, and an explicit CANCEL of a container re-initializing its called containee while GR7-skipping its never-called one), and ProgramTable.Register now enforces the containers-before-containees premise LOUDLY — a containee whose container is unregistered throws instead of silently dropping out of the cascade.

RESIDUE 1 — LEGAL SOURCE IS STILL REFUSED (GR-14.9.5.4-3, rejects_legal_source). A static WORKING-STORAGE item whose ADDRESS OF is taken inside a RECURSIVE program still draws DiagnosticCatalog.RecursiveWsPointerBacked (DataBinder.cs:594) — PB154 narrowed the message but the rejection stands. Nothing in §13.18.27, §11.10.4 or §14.9.5.4 forbids that source, and the standard's own model is that WORKING-STORAGE in a recursive program is static and shared, so ADDRESS OF it is well-defined. Until a derivation says otherwise this is a compile-time refusal of conforming COBOL, and it sits directly on the mechanism PB154 built, which is why it belongs here rather than in a pointer note.

RESIDUE 2 — THE CASCADE ORDER IS UNOBSERVED (GR-14.9.5.4-4, process_only). GR4 cancels the contained programs in REVERSE SOURCE ORDER. No test observes the order among sibling containees — only GR9's implicit closes could make it visible, and no golden arranges that — so the order remains derivation-verified rather than run-verified. That is exactly the shape a future refactor of the source-ordered WorkingStorageRoots walk would break silently.

WHAT WOULD CLOSE IT: derive whether a pointer-backed static WS item in a RECURSIVE program is genuinely unrepresentable (and if so record it as a documented determination rather than an unexplained reject) or implement it and delete RecursiveWsPointerBacked; and a golden with two sibling containees whose GR9 implicit file closes print in an observable order, asserting reverse source order.

SPEC REFS as carried by the rows: §14.9.5.4 GR3, GR4, GR7, GR9; §14.6.2.3.2 actions 1-7; §14.9.18 GR2; §11.10.4 GR4; §13.18.27.3 SR1b.

## Mechanism

src/Cobol.Net.Compiler/Binding/DataBinder.cs:594 (`Edition.Error(DiagnosticCatalog.RecursiveWsPointerBacked, …)`, descriptor at src/Cobol.Net.Editions/Diagnostics/DiagnosticCatalog.cs:824) sitting on the static-storage routing PB154 built — RouteStaticUnitStorage / StaticBasedBridgeAddrs / StaticIndexCells feeding the ONE source-ordered WorkingStorageRoots walk in EmitStaticReset (`__ResetStatics`) — consumed by src/Cobol.Net.Runtime/Control/ProgramTable.cs#CancelNode and its Register-time containers-before-containees premise
