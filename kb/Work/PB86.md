# PB86 — LANDED 2026-08-18 — `PERFORM COUNT-IT INTEGER(3.7) TIMES` ran once (CNT = 01; 3 owed)

> ⚙ **flags:** wrong-answer, silent, rejects-legal-source (the FUNCTION spelling), under-rejects (a non-integer
> identifier) · found 2026-08-18 by a PB84 probe (`ControlFlowEmitter.CountExpr`'s `_ => "1"` swallow) · fixed the same
> session (DEVLOG 1303).

**Measured** (`--std 2023`, `REPOSITORY. FUNCTION ALL INTRINSIC.`): `PERFORM COUNT-IT INTEGER(3.7) TIMES` displayed
`CNT=01`. `PERFORM COUNT-IT FUNCTION INTEGER(3.7) TIMES` is a parse error (`performTimes: (integerLiteral |
dataReference) TIMES` — no `functionCall` arm, unlike every other identifier slot the grammar admits a
function-identifier in). `PERFORM P X TIMES` with `X PIC 9V9 VALUE 1.2` is accepted (§14.9.28.3 SR2 "Identifier-1
shall be an integer" — under-rejected) and the emitter reads the field's UNSCALED value, so it iterates 12 times.

**Mechanism:** the keyword-omitted intrinsic binds as a `BoundComputedOperand` (`FieldOperand` →
`KeywordOmittedFunction`); `CountExpr` has arms for a literal, a field and an error operand and a `_ => "1"` default
that swallows every other operand. No SR2 integer check exists on the count.

**Fix (landed as designed):** grammar arm `(integerLiteral | functionCall | dataReference) TIMES`; `CountOperand` binds
the function through `IntrinsicBinder` and enforces SR2 for every shape through the ONE integer classifier
(`IntrinsicResultType.IsIntegerOperand`, now public — a scale ≤ 0 numeric elementary item that is not USAGE INDEX,
so a trailing-P picture counts as the integer it is; a function whose RESOLVED type is integer) — COBOLNET1646;
`CountExpr` renders every non-literal count through `NumericRenderer.Align(…, 0)` and the swallow is gone. Swept:
the GO TO … DEPENDING selector, WRITE … ADVANCING identifier LINES ([[PB87]] — the figurative ZERO advanced one
line), STRING/UNSTRING POINTER and TALLYING. Measured (golden `pb86_perform_times_function_count`): INTEGER(3.7) →
3, INTEGER-PART(2.9) → 2, LENGTH("ABCD") → 4, MOD(7, 3) → 1 over a THRU range, an inline INTEGER(2.5) → 2, `PIC 9P
VALUE 20` → 20, a COMP-5 4, and a P-scaled DEPENDING selector selecting by value. Negatives
`pb86-perform-times-non-integer-item` (PIC 9V9, rejected at 85/2002/2014/2023) and
`pb86-perform-times-non-integer-function` (SQRT).

**Original fix design:** §8.4.3.2.4 GR1 makes a function-identifier an identifier referencing a temporary item; SR2's "an
integer" is met by an integer-type function (§15.2 type 5) — GnuCOBOL (`id_or_lit_or_func TIMES`) and IBM evaluate
it. Grammar: `performTimes: (integerLiteral | functionCall | dataReference) TIMES` (functionCall first — it begins
with FUNCTION, unambiguous). Binder `CountOperand`: bind the function through `IntrinsicBinder`; enforce SR2 at BIND
for both shapes — a data item that is not an integer (scale ≠ 0, or not category numeric), or a function whose type
is not integer (§15.2 type 5) — with a new diagnostic. Emitter `CountExpr`: a computed operand renders through
`NumericRenderer.Align(num.Render(count), 0)` (`(long)`); the `_ => "1"` default becomes loud. Golden + two
negatives (`pb86-perform-times-non-integer-item`, `pb86-perform-times-non-integer-function`).
