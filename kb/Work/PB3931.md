# PB3931 — rounded-mode-phrase-not-supported: -std=cobol2014: ROUNDED MODE IS NEAREST-EVEN gives 'syntax error' (config/cobol2014.words lists NEAREST-EVEN-INTERMEDIATE in its place)

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S9) and refutation (RECLASSIFY). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\rounded-mode-phrase-not-supported.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\rounded-mode-phrase-not-supported\`.

## Summary

Under `-std=cobol2014`, GnuCOBOL 3.2 refuses `ROUNDED MODE IS NEAREST-EVEN` with `syntax error, unexpected
Identifier`. The other seven rounding modes compile and run under the same option, and the default dialect accepts
NEAREST-EVEN and rounds correctly. The cause is the reserved-word list that `-std=cobol2014` loads,
`config/cobol2014.words`: it lists `NEAREST-EVEN-INTERMEDIATE` (a word in neither the standard nor cobc's
reserved-word table, plainly the 8.10 row `NEAREST-EVEN | INTERMEDIATE ROUNDING clause and ROUNDED phrase` run
together) where `NEAREST-EVEN` belongs, so under that dialect NEAREST-EVEN is not a keyword, while cobc itself
implements it (reserved.c line 1936). `cobc --list-reserved -std=cobol2014` shows it. The same refusal hits `DEFAULT
ROUNDED MODE IS NEAREST-EVEN` in the OPTIONS paragraph and the ROUNDED phrase of every arithmetic statement.

Class: a GnuCOBOL bug in its `-std=cobol2014` word list, NOT an ISO nonconformance (corrected by the refuter from
`legal 2014 source refused; not optional`). The MODE phrase and the DEFAULT ROUNDED clause are processor-dependent (A.3
14) and A.3 9): "When support for this phrase is provided, support for at least one of the following shall be provided
in the ROUNDED phrase"; the 2009 committee draft's A.3 6) names the NEAREST-EVEN subphrase), and unsupported
processor-dependent syntax may be refused with a compile-time diagnostic (4.2.6; 4.3: such a program "does not compile
successfully" yet the implementation conforms), which cobc gives. Rerun on cobc 3.2.0 matches.

The night-2 family name ("ROUNDED MODE phrase not supported") overstated it: reduction shows only the NEAREST-EVEN
mode is refused; all three witnesses (fz00483, fz02949, fz02950) stop at their first NEAREST-EVEN line.

```cobol

01 R PIC 9.99.
```

File: `E:\COBOL-coord\scratch\op\pb3838\records\rounded-mode-phrase-not-supported.cob`.

The program is legal: the ROUNDED phrase with `MODE IS NEAREST-EVEN` (§14.7.4.2) on a numeric-edited resultant
identifier of COMPUTE.

Sweep, same cobc, `-std=cobol2014`: the same program with AWAY-FROM-ZERO, NEAREST-AWAY-FROM-ZERO, NEAREST-TOWARD-ZERO,

default dialect. `-std=cobol2002`, `cobol85`, `ibm-strict` and `mf-strict` also refuse NEAREST-EVEN; those dialects do
not claim the 2014 ROUNDED MODE phrase, so only the cobol2014 refusal is a word-list bug.

## Expected result (per ISO)

The standard does not require this program to compile: the MODE phrase is a processor-dependent element. ISO/IEC
1989:2023 §A.3 14) (checked): "The MODE phrase is dependent on the capabilities of the processor. When support for this
phrase is provided, support for at least one of the following shall be provided in the ROUNDED phrase" (and §A.3 9)
the same for the DEFAULT ROUNDED clause). An implementation may support a subset of the modes, and §4.2.6 (checked)
lets it refuse an unsupported processor-dependent element with a compile-time diagnostic: "The implementor is not
required to produce executable code when unsupported processor-dependent language elements are used"; such a
program "does not compile successfully" (§4.3, checked). cobc's refusal is therefore a conforming outcome, and the
report is a GnuCOBOL bug: cobc implements NEAREST-EVEN and its default dialect accepts it, so the `-std=cobol2014`
refusal comes only from a misspelled word in that dialect's list.

What an implementation that supports NEAREST-EVEN does (the default dialect's `1.22`), ISO/IEC 1989:2023, each
citation checked with `scripts/spec/cite.py --check`:

- §14.7.4.2, the ROUNDED phrase general format: `ROUNDED [ MODE IS { AWAY-FROM-ZERO | NEAREST-AWAY-FROM-ZERO |
  NEAREST-EVEN | NEAREST-TOWARD-ZERO | PROHIBITED | TOWARD-GREATER | TOWARD-LESSER | TRUNCATION } ]`.
- §14.7.4.3 5): "If the NEAREST-EVEN phrase is specified and the arithmetic value cannot be exactly represented in the
  resultant identifier, the arithmetic value is rounded to the nearest value that can be represented in the resultant
  identifier. If two such values are equally near, the value whose rightmost digit is even is chosen." 1.2250 lies
  halfway between 1.22 and 1.23; 1.22 has the even rightmost digit.
- §8.10: NEAREST-EVEN is a context-sensitive word of the "INTERMEDIATE ROUNDING clause and ROUNDED phrase"; "If a
  context-sensitive word is used where the context-sensitive word is permitted in the general format, the word is
  treated as a keyword".
- §11.9.6.2: the DEFAULT ROUNDED clause has the same eight modes, NEAREST-EVEN among them (the OPTIONS-paragraph
  sibling).

Edition: ROUNDED MODE and its eight modes are new in ISO/IEC 1989:2014 (absent from the 2002 text). The 2009
committee draft CD 1.2 that led to 2014 gives the same ROUNDED MODE IS format with NEAREST-EVEN (its clause 14.7.3.1 of that text) and
lists NEAREST-EVEN as a context-sensitive word; its A.3 6) names the NEAREST-EVEN subphrase of the ROUNDED phrase as
processor-dependent, as the 2023 A.3 14) does for the MODE phrase. GnuCOBOL's own `cobc/reserved.c` tags NEAREST-EVEN "2014 (C/S)". The word NEAREST-EVEN-INTERMEDIATE appears in
none of the 2002 text, the 2009 draft or 2023.

Edition as recorded by the adjudicator: 2014. `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Class

`-std=cobol2014` reserved-word list transcription error (`cobol2014.words` NEAREST-EVEN-INTERMEDIATE for NEAREST-EVEN); not an ISO nonconformance (A.3 14), 9); 4.2.6; 4.3), and not `legal 2014 source refused`. Corrected by the refuter. The `upstream_class` of this note, `rejects-legal-source`, is the nearest member of the kind's closed set: the source is refused only because of the word-list error.

## Our compiler (WiseOwl)

WiseOwl COBOL (built from main 6ed90bd1c), `cobol rmne.cob --std 2014 --source-format free -o rmne.dll`, then
`dotnet rmne.dll`: compile exit 0, run exit 0, output `1.22`. The ADD and DEFAULT ROUNDED siblings print `+1.22`.

## Fix site (GnuCOBOL 3.2 source, read observationally)

- `config/cobol2014.words`, line 318: `reserved: NEAREST-EVEN-INTERMEDIATE*` where `NEAREST-EVEN*` belongs; the file is
  loaded by `config/cobol2014.conf` line 286 (`reserved-words: COBOL2014`). Replacing the word fixes the ROUNDED phrase
  and the DEFAULT ROUNDED clause under `-std=cobol2014`.
- `cobc/reserved.c`, the table entry for NEAREST-EVEN (line 1936): token `NEAREST_EVEN`, context-sensitive in
  `CB_CS_ROUNDED`; it is correct, and has no NEAREST-EVEN-INTERMEDIATE counterpart. (Its FIXME notes that the
  INTERMEDIATE ROUNDING clause context is not handled; that clause is a separate matter.)
- A sweep of the words in `config/cobol2014.words` that `cobc/reserved.c` does not define found no other misspelled
  rounding word.
