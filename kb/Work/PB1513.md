# PB1513 — OPEN

## The rule (every citation re-run through `cite.py --check`)

> b) the associated DEPENDING ON item contains a value that makes the number of bytes in the record exceed the value specified or implied by the file description entry

`OK  §9.1.13.6 4) b)  (Permanent error condition with unsuccessful completion)`


## Finding — `i-o-status-p1` (wrong-answer; rows `GR-9.1.13.6-4`)

**Mechanism.** READ never validates a record made variable by OCCURS DEPENDING ON: after the physical record lands in the record area nothing compares the size its DEPENDING ON item implies against the FD's maximum, so the §9.1.13.6 4) b) '34' has no producer and the READ reports success.

**Repro.** out/probe/iostat-seq/seqst.cob: FD OD. 01 OD-R. 05 OD-N PIC 99. 05 OD-T PIC X OCCURS 1 TO 10 DEPENDING ON OD-N. (FD maximum implied = 12 bytes). A second FD ODW (01 ODW-R PIC X(12)) on the same file writes '99ABCDEFGHIJ'. OPEN INPUT OD; READ OD AT END CONTINUE END-READ; DISPLAY 'ODO-READ=' ST. Observed: ODO-READ=00.

**Expected from the spec.** OD-N = 99 makes the record 2 + 99 = 101 bytes, exceeding the 12 bytes implied by the file description entry, so per §9.1.13.6 4) b) the READ is unsuccessful and the I-O status is '34' (fatal class '3', EC-I-O-PERMANENT-ERROR): ODO-READ=34.

**Observed / reasoning.** MEASURED with the pinned compiler: status 00, record delivered, program continues with an ODO object (99) outside its OCCURS range 1..10. grep: FileStatusCode.PermanentBoundary is referenced only by RelativeConnector.Write's key<1 arm.

**Code site.** src/Cobol.Net.Runtime/IO/SequentialConnector.cs#Read (status arbitration ReadSucceeded(...) offers only 09/06/04/00); the READ emitter in src/Cobol.Net.Compiler/CodeGen/Verbs/SequentialIoEmitter.cs has the record layout (ODO object) and is the natural site to evaluate the implied size

## What the fixer owes

After a READ moves the physical record into the record area, evaluate the record's DEPENDING ON item(s) and, when the implied size exceeds the FD maximum, complete the READ with '34' (unsuccessful; the §9.1.13 exception path). The connector does not know the record layout — the check belongs where the generated READ has the record description (emit a post-read size predicate, not a runtime reflection). Golden: seqst.cob (OD-N = 99 against a 12-byte maximum).
