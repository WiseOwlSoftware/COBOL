# PB5252 - at --std 85 a LINE NUMBER or NEXT GROUP integer of four significant digits compiles (LINE PLUS 1000, NEXT GROUP PLUS 1000 in an unpaged report): ScreenReportLineClauses bounds the integers by the page limit or 9999 (the 2023 rule) where 1985 allows three digits

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/ReportSectionBinder.cs` (`ScreenReportLineClauses`, `BindNextGroupClauses`)
- `src/WiseOwl.Cobol.Compiler/Binding/ReportModel.cs` (`VerticalLimit`)

**Mechanism.** §1985:XIII.3.15.3 SR1 and §1985:XIII.3.16.3 SR2 each say "Integer-1 and integer-2 must not exceed three significant digits in length." `ScreenReportLineClauses` bounds LINE integers by `ReportModel.VerticalLimit` (the page limit, or 9999 for an unpaged report, §2023:13.18.35.3 SR3), and the NEXT GROUP screen likewise refuses only above 9999 (COBOL2284), with no 85 arm. kb/Work PB5079's 1985 confirmation paragraph recorded both (`NEXT GROUP IS PLUS 1000` as its row `1985-SR-XIII.3.16.3-2`, `LINE NUMBER IS PLUS 1000` as an observation) and PB5079 has landed, but both still compile, so this note holds them. The read's other half, a body group of relative lines too tall for its region, is now refused (COBOL2199) and is not part of this note.

**Found by.** The 1985 code read, slice 54.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids below. None of them is recorded: the code read's non-conforming verdicts of slices 36-56 wait in `E:/COBOL-coord/scratch/coderead-85/pipe-for-register.json`.

- `1985-SR-XIII.3.15.3-1` - `§1985:XIII.3.15.3 SR1` (read: PARTIAL, harm: under-rejects): "Integer-1 and integer-2 must not exceed three significant digits in length."
- Sibling: `1985-SR-XIII.3.16.3-2` - `§1985:XIII.3.16.3 SR2`, the same sentence for NEXT GROUP (named in kb/Work PB5079; still accepted).

**Repro.** `E:/COBOL-coord/scratch/coderead-85/reprobe-85c/rw_lineplus1000.cob` (`RD RPT.` unpaged, `01 DTL TYPE IS DETAIL LINE NUMBER IS PLUS 1000.`) and `E:/COBOL-coord/scratch/coderead-85/reprobe-85c/rw_ng1000.cob` (`01 DTL TYPE IS DETAIL LINE PLUS 1 NEXT GROUP PLUS 1000.`); `cobol.exe --std 85 --source-format fixed --run <file>`.

**Expected (from the 1985 text).** Both refused; `PLUS 0999` (three significant digits) accepted.

**Fix direction (root cause, CLAUDE.md rule 4).** The digit limit is one 1985 fact about every Report Section integer that the 1985 text bounds (LINE, NEXT GROUP, PAGE LIMIT, which PB5078 fixed); check it in one helper the three clause screens share, by edition, with tests at 999 and 1000.
