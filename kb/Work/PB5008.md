# PB5008 - is a 98 % uphold rate an independent check

**Found.** Wave 20261931 group a (PB4995). In the audit run the refuter upheld 1,345 of 1,371 verdicts. It is the same
model at the same effort as the pass it checks, so a 98 % uphold may mean it does not catch what the first pass misses.

**Owed.** Before the fleet builds verdicts on the upheld CHANGED and REMOVED rows, a sample audit: an agent re-derives 30
upheld CHANGED or REMOVED rows from the 1985 text and the 2023 rules named, blind to the first verdict; a miss rate
above the uphold rate's complement changes the refute pass (a different model or effort, or a prompt that asks for the
strongest counter-reading first). Record the result here and, if the pass changes, in `DESIGN-spec-conformance-review.md`.

**Result (Mythos session, 2026-11-08: four independent `cobol-adjudicator` audits, blind to nothing but deciding
from the two standards, every citation `cite.py --check`ed; seeded samples, the cases and verdicts in
`E:/COBOL-coord/scratch/pb5008-sample/`).**

| group (records) | sampled | wrong | kinds of error |
|---|---|---|---|
| CHANGED, adjudicate + refute (501) | 18 | 5 (28 %) | 3 should be KEPT, 2 name the wrong or too few 2023 rules |
| KEPT, adjudicate + refute (530) | 15 | 3 (20 %) | 1 should be CHANGED (§1985:X.5.1 GR2 against §2023:14.8.2.2), 2 too few 2023 rules |
| REMOVED, adjudicate + refute (314) | 12 | 0 | (the sample is mostly whole dropped modules: easy cases) |
| KEPT, map + verify (759, on main) | 15 | 0 | none |

The refuter upheld every one of the 8 wrong records: its 98 % uphold rate measures agreement, not accuracy. The errors
fall in three modes: (a) a 1985 rule elsewhere already allows what the record calls new; (b) the record omits the 2023
rule that actually states the requirement (the commonest: a definition restated in §2023:9.1.13.1, a group-parameter
rule in §2023:14.8.2.2, the general rule of §2023:14.7.7 over every arithmetic statement); (c) a compile-time refusal
that 2023 turned into a run-time exception condition (§2023:14.9.39.4 GR2).

**Decision (Mythos session): the adjudicate pass's CHANGED and KEPT records (1,031) are rechecked before anything is
built on them; REMOVED and the map + verify KEPT records stand.** The recheck is a new pass, not a second refuter of the
same shape: one request per record at the highest effort, framed to DISPROVE it, that must (1) search the 1985 text for
another rule bearing on the same element (mode a), (2) list every 2023 rule that states any part of the requirement,
from the full clause and its general rules, not only the record's candidates (mode b), and (3) say whether a refusal
became an exception condition (mode c), quoting both texts. An answer that disagrees with the record goes to a
`cobol-adjudicator`, never to a vote; every correction is recorded through `record_verdicts.py --edition 1985`. The
refute pass keeps its job for REMOVED, and its prompt asks for the strongest counter-reading first. The 8 wrong records
found here are corrected by the same path. Until the recheck lands, the 1985 GAP count (1,087 once PB4995 lands)
overstates progress by the wrong KEPT records it closes.

Side finding: four map + verify rules come from the 1989 Intrinsic Function amendment, whose text sits in the appendix
of `specs/ANSI_COBOL_1985.md`; `cite.py` refuses an edition-1989 citation (there is no 1989 transcription), so they cite
by their 1985 appendix page locator (p.A-35 and the like).
