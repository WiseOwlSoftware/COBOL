# PB1014 — OPEN

## What the fixer owes
Give the typed INVOKE's BY CONTENT formal a caller-side Place (the temporary the formal is initialized from) so every
category — boolean, national, numeric — is stored by the one MOVE store; delete the hand-written boolean arm. This was
item 2 of PB979's note and did not travel with PB979's UNSTRING fix, so it is filed on its own.

## Task brief (research 2026-09-30)

Re-measured on `4a1dda60e`: the BOOLEAN value is correct today (`INVOKE … USING BY CONTENT B2`, `B2 PIC 1(2) VALUE
B"10"`, formal `PIC 1(4)` → `L=1000`, the MOVE result — zero fill on the right). The note's defect is STRUCTURAL: the
boolean-expression / boolean-literal arm of `src/Cobol.Net.Compiler/CodeGen/Verbs/OoEmitter.cs` (~1306-1327,
`StrStoreBoolean` / `ReceivingStore.Characters`) is a second store beside `MoveEmitter.ConvertSource`, which the
identifier arm already reaches (~1620).

- **Spec:** §14.8.2.3.3 2) d) "Otherwise, the conformance rules are the same as for a MOVE statement with the argument
  as the sending operand" (cite-checked OK §14.8.2.3.3 2) d)).
- **Change:** give the rendered boolean value a sender operand the MOVE store accepts (a boolean-valued `BoundOperand`)
  and store it with `U.Move.ConvertSource(sender, a.Formal)`; keep the ANY LENGTH-first ordering the comment records
  (a `PIC 1 ANY LENGTH` formal takes the argument's length). Delete the hand arm.
- **Why now:** PB1113 admits boolean → NATIONAL (Table 16); this hand arm would then store a boolean into a national
  formal with the character store — a wrong value. Land in the SAME change as PB1113.
- **Goldens:** extend PB1113's golden: `B"1"` into `PIC N(4)` → `[1   ]`; `B1 B-AND B2` into `PIC 1(4)`, `PIC X(4)`
  and `PIC 1 ANY LENGTH` (LENGTH = the expression's width).
- **Size:** quarter slot.

## Re-filed as a defect (analyses sweep, 2026-10-23)

Adjudicated read-only by an Opus cobol-adjudicator on main e7cf38ce4; accepted by the Mythos session.

A BY CONTENT boolean argument into an EDITED formal is stored unedited. INVOKE O "ME" USING BY CONTENT B"10" (formal PIC XBX) prints [10 ]; the same into PIC NBN prints [10 ]; CALL ... AS NESTED USING BY CONTENT B1 B-AND B2 (value 10) into PIC XBX prints [10 ] (the CALL literal lane is right, [1 0]). MOVE B"10" TO a PIC XBX item prints [1 0]. §14.8.2.3.3 2) d) makes the crossing a MOVE and §14.9.25.4 6) applies the receiver's editing; Table 16 admits boolean to alphanumeric-edited and national-edited. Root cause is the note's structural point: BooleanArgumentRecord is a second store beside MoveEmitter.ConvertSource. Fix: give the boolean value a sending BoundOperand and store it through U.Move.ConvertSource(sender, formal) on both lanes (keep the ANY LENGTH arm first), delete BooleanArgumentRecord; goldens for XBX and NBN on INVOKE literal + expression and CALL expression. JUSTIFIED RIGHT X(4) and PIC 1(4) formals are already right.

Evidence: Re-run on fuzz-triage-20261023 (main e7cf38ce4): the hand boolean store survived PB1113/PB2587 as CallEmitter.BooleanArgumentRecord (StrStoreBoolean / ReceivingStore.Characters, no editing), shared by INVOKE and CALL; B"10" BY CONTENT into a PIC XBX formal gives [10 ] where MOVE gives [1 0].

Rule: §14.8.2.3.3 2) d) (checked); §14.9.25.4 6) (checked)
