# PB1014 — OPEN

## What the fixer owes
Give the typed INVOKE's BY CONTENT formal a caller-side Place (the temporary the formal is initialized from) so every
category — boolean, national, numeric — is stored by the one MOVE store; delete the hand-written boolean arm. This was
item 2 of PB979's note and did not travel with PB979's UNSTRING fix, so it is filed on its own.

## Task brief (research 2026-09-30)

Re-measured on `4a1dda60e`: the BOOLEAN value is correct today (`INVOKE … USING BY CONTENT B2`, `B2 PIC 1(2) VALUE
B"10"`, formal `PIC 1(4)` → `L=1000`, the MOVE result — zero fill on the right). The note's defect is STRUCTURAL: the
boolean-expression / boolean-literal arm of `src/Cobol.Net.Compiler/CodeGen/Verbs/OoEmitter.cs` (~1306-1327,
`StrStoreBoolean` / `ReceivingStore.Characters`) is a second store beside `MoveEmitter.ConvertSource`, which the
identifier arm already reaches (~1620).

- **Spec:** §14.8.2.3.3 2) d) "Otherwise, the conformance rules are the same as for a MOVE statement with the argument
  as the sending operand" (cite-checked OK §14.8.2.3.3 2) d)).
- **Change:** give the rendered boolean value a sender operand the MOVE store accepts (a boolean-valued `BoundOperand`)
  and store it with `U.Move.ConvertSource(sender, a.Formal)`; keep the ANY LENGTH-first ordering the comment records
  (a `PIC 1 ANY LENGTH` formal takes the argument's length). Delete the hand arm.
- **Why now:** PB1113 admits boolean → NATIONAL (Table 16); this hand arm would then store a boolean into a national
  formal with the character store — a wrong value. Land in the SAME change as PB1113.
- **Goldens:** extend PB1113's golden: `B"1"` into `PIC N(4)` → `[1   ]`; `B1 B-AND B2` into `PIC 1(4)`, `PIC X(4)`
  and `PIC 1 ANY LENGTH` (LENGTH = the expression's width).
- **Size:** quarter slot.

## Landed (2026-10-27, wave 20261027 group B) - the boolean argument is the MOVE's sender, stored by the MOVE's store

**Re-probe.** On the branch's own build (before the change) `E:\COBOL-coord\scratch\w20261027b\p14\q.cob` printed `[10 ]` for
`INVOKE O "ME" USING BY CONTENT B"10"` and `B1 B-AND B2` into `PIC XBX`, `[10 ]` for the same into `PIC NBN`, and `C:XE=[10 ]` for
`CALL ... AS NESTED USING BY CONTENT B1 B-AND B2`; `MOVE B"10"` gave `[1 0]`. The CALL literal lane was already right (it
reaches the activated unit's MoveLanding). JUSTIFIED RIGHT `X(4)` and `PIC 1(4)` were right.

**Root cause.** `CallEmitter.BooleanArgumentRecord`, shared by the INVOKE lane and the CALL lane's known-formal arm, was a
second receiving store beside `MoveEmitter`'s: a three-way switch (group, boolean category, `ReceivingStore.Characters`) that
skipped the receiver's EDITING (alphanumeric-edited and national-edited, `MoveEmitter.CharacterStore`'s edited arm) and
treated an as-if-elementary bit group as a plain group.

**Fix.** The boolean value is the MOVE's sending operand: `BoundBoolOperand` gains `AtItemWidth` (the sender's value taken at
§8.8.2 rule 10's width, `OperandText.AsString` renders it with `BooleanRenderer.RenderAtItemWidth`), and
`BooleanArgumentRecord(BoundBoolExpr, DataItem)` (now an instance method) keeps only the two arms that are not a MOVE into an
elementary item - an ANY LENGTH formal (first, the argument's own length, §13.18.2.4 1) b)) and a plain group formal (GR4's
unconverted group move) - and sends every other formal through `MoveEmitter.RecordValue`, the one receiving store. A numeric
formal cannot reach it (COBOLNET0828 at bind: a boolean is no numeric sending operand, §14.8.2.3.3 2) a)); the arm throws
loudly rather than guess. The hand arm and its `StrStoreBoolean` / `ReceivingStore.Characters` pair are deleted.

**Goldens.** `14.8.2.3.3-Elementary-items-passed-by-content-or/pb1014_content_boolean_move_store` (accept 2002; both lanes,
literal and expression senders into `XBX`, `NBN`, JUSTIFIED RIGHT `X(4)`, `1(4)`, `1(2)`, `X ANY LENGTH`, `1 ANY LENGTH`) and the
negative `pb1014-content-boolean-into-numeric-formal` (COBOLNET0828 at 2002, 2014, 2023).
