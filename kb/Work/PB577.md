# PB577

## Mechanism
`INITIALIZE <group containing an occurs-depending table>` throws NotImplementedCobolFeatureException at all four editions - InitializeBinder's place-kind dispatch has no arm for the place an ODO group resolves to - so the GR6 initialization and the GR9 every-occurrence obligation are both undelivered

### The refutation this note is written from
Row `GR-13.18.63.4-6` was adjudicated CONFORMS and OVERTURNED to `PARTIAL` by the refuter. Its reasoning, verbatim:

> GR6 governs "the initialization of the associated data item", not initialization at one occasion; GR4c ("-- when the object or runtime element is placed in initial state, and -- during the execution of an INITIALIZE statement", cite.py --check OK) makes an INITIALIZE statement the second occasion. On that occasion the compiler does not implement GR6 at all -- it CRASHES: `INITIALIZE <group containing an occurs-depending table>` reaches a runtime NotImplementedCobolFeatureException, "INITIALIZE target 'S' (unsupported place kind)", at --std 85, 2002, 2014 and 2023, with AND without ALL TO VALUE, and with the DEPENDING item inside or outside identifier-1. The source is legal: 14.9.20.3 SR1-SR8 place no restriction on a variable-occurrence identifier-1, and 14.9.20.4 GR8 explicitly contemplates one ("For a variable-occurrence data item, the number of occurrences initialized is determined by the rules of the OCCURS clause for a receiving data item"). ROOT CAUSE LOCATED: InitializeBinder.cs:124-133 -- the `InitializeCursor? cursor = place switch { MemberPlace ..., RedefViewPlace ..., _ => null }` dispatch has no arm for the place kind an ODO group resolves to, so an InitializeErrorAction is emitted. This defect is recorded on NO row of this subject: the adjudicator's GR6 probes are all initial-state, and GR11's DIVERGES (part 3) is about the format-2 VALUE being invisible, a different mechanism. SECOND, SOFTER POINT: the adjudicator labels the ordering sentence "MEASURED", but its probe (N beside T, no storage overlap) cannot discriminate the order -- and NO shape can: SR13 forbids a VALUE at subordinate levels under a group VALUE, SR12 forbids VALUE under REDEFINES, and 13.18.38 keeps the DEPENDING item out of the table, so the table's initialization can never touch the DEPENDING item's storage and the sentence has no consequence beyond sentence 1. The honest evidence kind there is DERIVATION, not MEASURED. Corrected verdict PARTIAL (initial-state occasion conforming and well measured; INITIALIZE occasion unimplemented and fatal).

### Inventory row `GR-13.18.63.4-9` (PARTIAL)
BOTH ARMS OF THE RULE -- "an entry that contains an OCCURS clause" AND "an entry that is subordinate to an entry that contains an OCCURS clause" -- MEASURED, plus the multi-dimensional and group-level shapes. (arm 1) probe gr9occ: `05 E PIC X(3) OCCURS 3 VALUE "ABC"` gives E1/E2/E3 all [ABC] -- every occurrence, not just the first. (arm 2) same probe: `05 G OCCURS 3. 10 A PIC X(2) VALUE "XY". 10 B PIC 9 VALUE 7.` gives A(1)=A(3)=[XY] and B(2)=B(3)=[7]. (multi-dimension) probe gr9multi: `05 G OCCURS 2. 10 H OCCURS 3. 15 A PIC X VALUE "Z".` gives A(1 1)=A(2 3)=[Z] -- all six. (group-level VALUE on the OCCURS entry, GR5 x GR9) same probe: `05 K OCCURS 3 VALUE "AB". 10 P PIC X. 10 Q PIC X.` gives P(1)=P(3)=[A] and Q(1)=Q(3)=[B] -- every occurrence's AREA takes the value. (ODO) probe gr6odo/gr6sub, recorded on GR6's row. COVERING TEST conformance:2002/table_value_occurs is spec-derived: its header quotes "ISO 13.18.63.4 GR 9" and its golden N=007,007,007 / D=01E,01E / C=AB ,AB is computed from the clause plus the PICTURE, across a numeric, a signed-scaled and a character element. NOT A GAP OF THIS ROW: GR9's REPORT-SECTION population (imported by GR21) cannot be built because OCCURS in a report group description is refused by name -- COBOLNET0899 at src/Cobol.Net.Compiler/Binding/DataBinder.Reports.cs:434-437, probe gr21occ -- and that refusal is recorded on GR-13.18.63.4-21 and GR-13.18.63.4-22. || REFUTED: PARTIAL — TWO MEASURED HOLES plus a half-covering test-ref. (1) UNRECORDED ANYWHERE: GR9's population is "a data description entry that CONTAINS an OCCURS clause", which includes OCCURS ... DEPENDING, and GR4c makes an INITIALIZE statement one of the two occasions on which the rule must hold. Over an occurs-depending table `INITIALIZE S ALL TO VALUE` does not assign every occurrence -- it throws NotImplementedCobolFeatureException "INITIALIZE target 'S' (unsupported place kind)" at all four editions (InitializeBinder.cs:124-133). A fixed-OCCURS control in the same shape runs correctly, so this is ODO-specific and is carried by no row of this subject (the adjudicator marked GR6 CONFORMS on initial-state evidence only). (2) GR21 ("General rules 1, 7, 8, and 9 above apply", cite.py --check OK) makes GR9 normative in FORMAT 4, and the vehicle is refused by name: COBOLNET0899 "RD 'R1': OCCURS in a report group description (ISO 13.18.38 repeating entries) is not yet implemented". The source is legal -- 13.18.38.3 SR27 ("A report group description entry that contains an OCCURS clause with a DEPENDING phrase may be followed within that report group only by report group description entries that are subordinate to it", cite.py --check OK) presupposes it. The adjudicator deflects this to rows 21/22, but the rule whose behaviour is undelivered in the report section is GR9's; a CONFORMS here closes a row over refused legal source. (3) TEST-REF covers ONE ARM OF TWO. conformance:2002/table_value_occurs is genuinely spec-derived and registered, and it pins arm 1 ("an entry that contains an OCCURS clause") across a numeric, a signed-scaled and a character element -- but all three of its elements carry their OWN OCCURS, so it never exercises the rule's second named arm, "an entry that is subordinate to an entry that contains an OCCURS clause". One arm of two does not close the row. Corrected verdict PARTIAL.
