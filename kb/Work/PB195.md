# PB195 — the native operand lane keeps a binary64 literal screen it no longer earns

## Measured, both arms, 2026-08-31

Same source, one line, `--std 2023`:

| Mode | Result |
|---|---|
| native (default) | `error COBOLNET1661: floating-point numeric literal '1.0E+400': its value lies outside the implementor-defined exponent range for a floating-point operand — the IEEE binary64 range` |
| `OPTIONS. ARITHMETIC IS STANDARD-DECIMAL.` | compiles; prints `BIG` |

```cobol
IF 1.0E+400 > X DISPLAY "BIG" ELSE DISPLAY "SMALL" END-IF.
```

Nothing about the literal changes between the two runs. The comparison is a relation condition, not an
arithmetic statement, and the literal is an OPERAND — the position PB99 moved onto the exact
§8.3.3.3.3 decimal value.

## The site

`ExpressionBinder.CheckLiteral` (the `else` arm):

```csharp
else if (!NumericLiteral.FitsBinaryFloat(text))
    ctx.Edition.Error(DiagnosticCatalog.FloatingLiteral, … "the IEEE binary64 range, about 4.9E-324 to 1.8E+308" …);
```

The comment above it justifies the bound with D16 — "a floating-point literal is a binary64 operand" — which is
the premise PB99 narrowed: the *arithmetic* lane keeps binary64 precedence for float items and receivers, but
the literal's own VALUE is its exact §8.3.3.3.3 value. Screening the value against the carrier of a lane it need
not enter rejects legal source, and the rejection is a hard compile error, so there is no workaround short of
rewriting the program.

## Relationship to the D-B landing

**This is the same code change as plan item D-B** ("float literal is its EXACT §8.3.3.3.3 value everywhere"),
whose implementation half is: make `CheckLiteral`'s decimal128 range arm unconditional and **delete the
`FitsBinaryFloat` arm**, alongside collapsing `LiteralNum`/`LiteralOperandNum` in `NumericRenderer`. This note
exists so the defect is in the register in its own right — a defect recorded only inside a design item is a
defect the work register cannot rank — and it **closes with the D-B landing**, not separately. If D-B is
re-scoped or deferred, this note stands on its own measurement.

Goldens ride with D-B: the `pb99-floating-literal-range` negative case is the one that currently pins the wrong
bound and must be updated in the same change set, or the fix will look like a regression.
