# PB383 — one guard, two different rules, and the wrong substituted value for both

**Row:** `DOC-A.1-93` (Annex A.1 item 93 — *Function returned values: returned value length exceeds
implementor-defined limits*). Found by the round-2 golden writer `misc-p1`, which drafted the row's witness and
predicted the divergence; **re-measured here against this worktree's own built `cobol.exe`**, not inherited.

## The program

`out/misc-p1/tests/conformance/2023/l1_returned_value_limit_boolean_repro.cob` — **held out of the tree** (a
suspected compiler defect never becomes a golden edit), still in the round-2 scratchpad. Minimal form:

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. L1RVLBOOL.
       PROCEDURE DIVISION.
       MAIN.
           DISPLAY "INLIMIT=[" FUNCTION BOOLEAN-OF-INTEGER(5, 8) "]"
           DISPLAY "OVER=[" FUNCTION BOOLEAN-OF-INTEGER(5, 8192) "]"
           STOP RUN.
```

```
$ cobol.exe l1_returned_value_limit_boolean_repro.cob --std 2023 --run      (exit 0)
INLIMIT=[00000101]
OVER=[0]            <-- the documented answer is  OVER=[]
```

## The rules, each link checked mechanically

* `--check 15.13.3 "a positive nonzero integer"` → **OK §15.13.3 2) (Argument rules)**. 8 192 **is** a positive
  nonzero integer, so **no argument rule is violated** — this is not an argument-rule case at all.
* `--check 15.13.4 "argument-2"` → **OK §15.13.4 1) (Returned value rule)**: the returned value's LENGTH *is*
  argument-2 boolean positions. 8 192 positions is one past the implementor's maximum.
* `--check 15.4 "If the length of the returned value exceeds the maximum length specified by the implementor for
  a returned value, an EC-ARGUMENT-FUNCTION exception condition is set to exist."` → **OK §15.4 (Returned
  values)**.
* `--check 15.3 "If the EC-ARGUMENT-FUNCTION exception condition is set to exist and checking for
  EC-ARGUMENT-FUNCTION is not enabled, the implementor defines the result of the function reference."` →
  **OK §15.3 14) (Arguments)**.
* §14.9.11.4 GR1 then makes a zero-length operand display as nothing, so `OVER=[]` is exactly the image of a
  zero-length returned value.

**The implementor's own determination — which item 93 REQUIRES to be documented — is `docs/CONFORMANCE.md`
row `DOC-A.1-93`:** the maximum returned length is 8 191 character positions, EC-ARGUMENT-FUNCTION is set to
exist, and *"the value returned is the §15.3 checking-off default — **a zero-length value**"*. That row NAMES
this exact enforcement site: `CobolIntrinsics.BooleanOfInteger (argument-2 > 8,191)`.

## What the compiler does

`src/Cobol.Net.Runtime/Intrinsics/CobolIntrinsics.Text.cs#BooleanOfInteger`:

```csharp
if (length < 1 || length > 8191)
{
    Exceptions.ExceptionState.ArgumentError(...);
    return "0";                    // one boolean position, not the zero-length value
}
```

**TWO DISTINCT RULES ARE CONFLATED IN ONE CONDITION, and both get the wrong substituted result.**
`length < 1` is a **§15.13.3 r2 ARGUMENT** violation, whose answer is row **DOC-A.1-90**'s zero-length class
(the class for functions whose returned LENGTH derives from the rejected argument — and BOOLEAN-OF-INTEGER's
length IS argument-2, so it belongs there). `length > 8191` is a **§15.4 RETURNED-VALUE-LENGTH** violation, whose
answer is row **DOC-A.1-93**. Both documented answers are a zero-length value; the code answers `"0"` for both.
The correct return is `string.Empty`.

## The sibling that proves the ROW, not the code, is right

Row 93's *other* named enforcement site, `CobolIntrinsics.BaseConvert`, **does** return the zero-length value —
the golden `tests/conformance/2023/l1_returned_value_length_limit.cob` landed in this same change set and passes
with `OVERHEAD=[    ]` (a receiver pre-filled with `*` comes back all spaces: §14.6.8.5's zero-length space
fill). So this is the two-arm dispatch shape again (`feedback_two_arm_dispatch`): one determination, two
implementations, one of them divergent.

## Fix shape

Split the condition so each rule keeps its own identity and its own citation, and return `string.Empty` from
both arms. Then **sweep**: every intrinsic whose returned length derives from an argument (the row-90 list —
`FORMATTED-DATE`, `FORMATTED-DATETIME`, `FORMATTED-TIME`, `BASECONVERT` — plus every §15.4 length guard) must be
read for the same `"0"`/one-character substitute. The row's witness is drafted and validated; it lands as
`tests/conformance/2023/l1_returned_value_limit_boolean_repro.cob` the moment the guard is correct, and
`DOC-A.1-93` closes then. Until then the row stays open with its `BaseConvert` half witnessed by
`l1_returned_value_length_limit`.

## Landed — 2026-09-04

**Reproduced first**, on this worktree's own freshly built `cobol.exe`: `INLIMIT=[00000101]` / `OVER=[0]`, against
the documented `OVER=[]`. All five citations were re-run through `cite.py --check` rather than inherited.

**The fix is three arms where there was one condition.** `CobolIntrinsics.BooleanOfInteger` now separates
(1) §15.13.3 r2, an ARGUMENT rule about argument-2, whose rejection leaves no length to return because §15.13.4 r1
makes argument-2 *be* the returned length — row `DOC-A.1-90`'s zero-length class; (2) §15.4, a RETURNED-VALUE-LENGTH
rule with a different owner, since 8,192 satisfies r2 and it is the implementor's 8,191-position maximum that is
violated — row `DOC-A.1-93`; and (3) §15.13.3 r1, argument-1 negative with a VALID argument-2, which keeps its
determined length and takes row 90's general clause — argument-2 zero boolean positions. Each arm carries its own
citation. (3) is deliberately *not* zero-length and is the control the other two are measured against.

**The root cause was architectural, and the sweep is the fix for it.** Every string-returning guard raised in one
statement and wrote its substitute in the next, so the two could drift — and did. The numeric half of that
determination had always lived in exactly one place (`ExceptionState.ArgumentError`'s own `return 0`); the text
half had none. `ExceptionState.ArgumentErrorZeroLength` is now that one place: it raises *through* `ArgumentError`
(one fatal path, one checking gate) and returns `string.Empty`, making raise and substitute a single expression.
Ten sites moved onto it — BASECONVERT's five guards, the FORMATTED-DATE / FORMATTED-DATETIME / `EmitFormatted`
family, and §15.87.4 r1's SUBSTITUTE arm (where the STANDARD, not a determination, states the zero length).

**The sweep found no second wrong answer.** Every `ArgumentError` site under `src/Cobol.Net.Runtime/Intrinsics/`
was read, and both `8191` guards in all of `src/`: `BooleanOfInteger` was the only string-returning guard whose
substitute contradicted its own row. `CHAR` / `CHAR-NATIONAL` return one SPACE and are CORRECT — row 90's
fixed-one-character clause. `LOCALE-DATE` / `LOCALE-TIME` / `LOCALE-TIME-FROM-SECONDS` were deliberately left on
their own explicit substitute: §15.52.4 r3's length "depends on the format indicated in the locale", so their class
is neither fixed nor argument-derived and is written down nowhere — reported separately rather than quietly
enrolled in a determination that does not cover them.

**Witnesses.** `conformance:2023/l1_returned_value_limit_boolean_repro` (row 93) and
`conformance:2023/l1_argument_default_boolean_length` (row 90's BOOLEAN-OF-INTEGER site, which had none — the
row's other test-refs never touch the function). Each pairs a §14.9.11.4 GR1 DISPLAY leg with a §15.50.4 r1
LENGTH read-out, because a boolean receiver zero-FILLS (§14.6.8.6) and would have made `"0"` and zero-length
indistinguishable — the observation the obvious golden would have gotten wrong. `DOC-A.1-93` closed
(GAP 3054 → 3053); `DOC-A.1-90` re-recorded with the new witness and the boolean class named.
