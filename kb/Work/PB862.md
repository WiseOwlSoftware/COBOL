# PB862 — OPEN — a rule that cannot be enforced until the implementor publishes a list

Source: the `PB829` implementer report, item (a). Filed as an adjudication because enforcement REQUIRES an owner
decision first: SR8 obliges the implementor to specify the names, so enforcing it means publishing that list —
an A.1 / `docs/CONFORMANCE.md` §7 determination — and a wrong list rejects legal source across the NIST corpus.

## Repro — re-run on this tree

`scratchpad/reg4/probe/p22_specialnames_unknown.cob` (PROGRAM-ID `R4P22`), `--std 2023 --run`:

```cobol
       SPECIAL-NAMES. WIBBLE WOBBLE.
```
```
SN-OK      (rc 0, no diagnostic)
```

`DataBinder.Switches.cs` registers `WOBBLE -> WIBBLE` in `SwitchMnemonics` without checking that `WIBBLE` names
anything this implementation defines.

## The rule, quoted

```
$ python scripts/spec/cite.py --check 12.3.7.3 "The implementor shall specify the names that are available for switch-name-1, feature-name-1, and device-name-1."
  OK  §12.3.7.3 8)  (Syntax rules)
```

§12.3.7.3 SR6 and SR7 add that the implementor may restrict where each mnemonic may be used.

## Owner question

What is COBOL.NET's published set of switch-names, feature-names and device-names? (Survey first —
`feedback_survey_compilers_on_latitude`: GnuCOBOL's device/feature name set is the natural baseline, and the
NIST corpus's usage is the compatibility floor. The answer becomes an A.1 determination and then the screen is
mechanical.)

## Harm

`under_rejects` + `silent`: a typo (`CONSOEL IS PRT`) binds a mnemonic that names nothing, and the
`DISPLAY ... UPON PRT` that uses it goes to the wrong place or nowhere, with no diagnostic at any edition.
