# PB862 — LANDED — a rule that cannot be enforced until the implementor publishes a list

## Landed (wave 46 J, 2026-09-22) — the adjudication answered, the defect fixed

Re-probed first: `SPECIAL-NAMES. WIBBLE WOBBLE.` → `SN-OK`; `CONSOEL IS PRT` surfaced only at the DISPLAY, as
device 'CONSOEL'; and a sibling the note did not name — `CONSOLE IS CON` + `SET CON TO ON` compiled and ran
(`SET-OK`), because every two-word entry's mnemonic landed in the SWITCH registry too.

**The answer (owner-decision protocol — follow the surveyed implementations; recorded in docs/CONFORMANCE.md §7).**
device-names **CONSOLE / SYSIN / SYSOUT / SYSERR** (already documented as DOC-A.1-2 / -59 — no new decision);
feature-names **C01** (= the ADVANCING PAGE advance) and **CSP** (zero lines) — IBM, Micro Focus and GnuCOBOL all
spell both; C02–C12 not provided (no forms-control tape model); switch-names **SWITCH-0…SWITCH-36** (GnuCOBOL) and
**UPSI-0…UPSI-7** (IBM). ⚠ DETERMINATION: "any word is a switch-name" was rejected — it cannot coexist with a
device-name set under §8.3.2.3.1 (a system-name belongs to one type only).

**Fix.** ONE table, `Binding/ImplementorNames.cs` (rows carry kind + device capability + feature advance), read
through ONE entry reader (`ImplementorNameEntry`) by BOTH walkers of the entry — `DataBinder.BindImplementorNameEntry`
and `Procedure.MnemonicRegistry`. SR8 is **COBOLNET2241** at the declaration (also ON/OFF STATUS on a non-switch
name). The mnemonic registry's value is the ROW, so every consumer asks the KIND: ACCEPT/DISPLAY
(`AcceptDisplayBinder.MnemonicDevice`, COBOLNET0817 — the private `AcceptInputDevices` / `DisplayOutputDevices`
sets are deleted), SET (switch mnemonics only, COBOLNET1757), WRITE ADVANCING (§14.9.51.3 SR16, **COBOLNET2243**;
C01 → page, CSP → zero lines). The Option-2 leniency that registered a switch-name as its own mnemonic is gone
(SET's operand is a mnemonic-name). NIST: `XXXXX073` (SQ207M's feature-name) is now supplied as `CSP` by the
preprocessor — it bound only because any word was accepted. Drift: `ImplementorNamesDriftTests` (doc rows and the
2241 text name every table element; every row compiles in its arm; the refusals).

Goldens: `85/pb862_implementor_names`, `negative/pb862-unavailable-device-name`,
`negative/pb862-write-advancing-device-mnemonic`; `FileIoDifferentialTests.WriteAdvancingC01_IsThePageAdvance`.
Test sources that named unavailable system-names were moved onto real ones (SWTEST-* → SWITCH-31…34, PRT-CHAN /
VDEVICE → CSP, HIGHLIGHT/CRT as system-name → CONSOLE, SW-ONE/SW-TWO → SWITCH-1/2).

Source: the `PB829` implementer report, item (a). Filed as an adjudication because enforcement REQUIRES an owner
decision first: SR8 obliges the implementor to specify the names, so enforcing it means publishing that list —
an A.1 / `docs/CONFORMANCE.md` §7 determination — and a wrong list rejects legal source across the NIST corpus.

## Owner question

What is COBOL.NET's published set of switch-names, feature-names and device-names? (Survey first —
`feedback_survey_compilers_on_latitude`: GnuCOBOL's device/feature name set is the natural baseline, and the

mechanical.)

## Harm

`under_rejects` + `silent`: a typo (`CONSOEL IS PRT`) binds a mnemonic that names nothing, and the
`DISPLAY ... UPON PRT` that uses it goes to the wrong place or nowhere, with no diagnostic at any edition.
