# PB5526 - UsageCollectionPass calls Channel(n.Area) on the communication CD area, which is always a group or RedefViewPlace and so a no-op, and its comment says the area holds no numeric value although TEXT LENGTH and MESSAGE COUNT are numeric items of it

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Passes/UsageCollectionPass.cs` (`Visitor.Visit`, the BoundCommunicationStatement overload: the `Channel(n.Area)` call and the comment above it, lines 153-159), `src/WiseOwl.Cobol.Compiler/Binding/CommunicationSectionBinder.cs` (`CommunicationSectionBinder.BuildArea`; read, not changed)

**Mechanism.** PB5489 added `Channel(n.Area); Channel(n.Into);`. `n.Area` is always the CD's implicit description built by `CommunicationSectionBinder.BuildArea` (a level-01 group with subordinate slots, or a `RedefViewPlace` over the first written record), and `Channel` returns at once for a group or a `RedefViewPlace`, so the call does nothing. The comment says the CD area's image is "none of it a numeric value", yet TEXT LENGTH, MESSAGE COUNT and the other status items are numeric items of that area; they take the existing `P(n.Area)` group FromImage path. The comment misstates the design to the next reader, and the dead call suggests a channel that is not there.

**Fix direction.** Delete `Channel(n.Area)` and reword the comment to say what holds (the receiver `n.Into` is the only elementary operand that takes the character channel); keep the PB5489 golden green.
