# PB1914 — OPEN

Filed by the train-1003 lander from wave 1003 group D's report (`w1003d-PB1660-report.md`, new defect 2).

## Finding

**Repro.** At `--std 85`, fixed form: a source line opens a nonnumeric literal that runs to margin R, the next line is
a `D` debugging line, and the line after it is a continuation line (indicator `-`) carrying the rest of the literal.
The continuation joins the DEBUGGING line, not the line that opened the literal, so the literal ends at margin R of the
first line and the debugging line's text gains the tail.

**Code site.** `src/Cobol.Net.Frontend/Preprocessor/ReferenceFormatProcessor.LogicalLineBuilder.cs#Emit`, reached from
`FixedFormConverter.ConvertLine` in `ReferenceFormatProcessor.LogicalConversion.cs` (the `LineKind.Debugging` arm emits
`DebugLineCarrier + area` as a new logical line, which the next continuation line then extends). The behavior predates
PB1705; PB1705 only made the carried line source under WITH DEBUGGING MODE.

**Open question.** ISO §6.5 joins a continuation line to the preceding line, and 2002+ has no debugging indicator
(§6.2.2). Whether the 1985 standard lets a debugging line interrupt a continuation (and if so, which line the
continuation continues) needs the X3.23-1985 text, which is not in the repository. The fixer derives the rule from that
text or from GnuCOBOL (CLAUDE.md rule 1 precedence) before changing the builder, and records the choice in
docs/CONFORMANCE.md.
