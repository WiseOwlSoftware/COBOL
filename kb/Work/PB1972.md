# PB1972

Filed by the train-1015 lander from wave 1015 group Z's lead 1 (PB1020, landed in train 1015).

## The question

§11.3.3 7): "A given class name shall not appear more than once in an INHERITS clause." (`cite.py --check 11.3.3 "A
given class name shall not appear more than once in an INHERITS clause"` -> OK §11.3.3 7)). PB1020 made the rule its own
diagnostic (COBOLNET2791, `OoClassTable.ScreenInheritsNames`), run before the Annex A.4.10 multiple-inheritance
decline, witnessed by `tests/conformance/negative/pb1020-inherits-repeated-class.cob` and `oo-inherits-same-base-twice`.

The row's verdict is still DOCUMENTED-NON-SUPPORT: it is DERIVED by the owner's R43 `oo-optional-items-only` selector
(`tests/Cobol.Net.Tests.Unit/DerivedVerdictDriftTests.cs` ~550), which PB285 recorded when it closed the row. The
rule only bites when INHERITS lists more than one name, i.e. under the declined optional item, so the derived verdict is
defensible; but the compiler now enforces the rule rather than declining it, and the row reads as though it did not.

Owner decision needed: release SR-11.3.3-7 from the selector (re-verdict CONFORMS with the PB1020 witnesses), or keep
the derived verdict. No code is owed either way. Sibling: PB1784 item 2 (the interface twin §11.6.3 SR6 still reports
the bare COBOLNET0840).
