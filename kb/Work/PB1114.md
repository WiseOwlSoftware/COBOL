## Measured (adjudicator / refuter evidence, verbatim)
### [elementary-items] A fixed-point argument passed BY CONTENT to a floating-point formal of a NESTED (rule-2) activation crosses with no landing: the activating side's COMPUTE landing (LandForFormal) covers fixed-point formals only, and the callee's float formal is classified CallCrossing.Text, so the formal reads 0.
- **Rows:** GR-14.8.2.3.3-L2.2 — harm `wrong-answer`
- **Repro:** Outer program `01 A PIC 9(3)V99 VALUE 12.5.` CALL "S" AS NESTED USING BY CONTENT A. Contained S: `01 W PIC 9(3)V99.` LINKAGE `01 L USAGE FLOAT-LONG.` PROCEDURE DIVISION USING L. DISPLAY "IN-S [" L "]". COMPUTE W = L. DISPLAY "W [" W "]". -> prints IN-S [0] and W [00000]; MOVE A TO a FLOAT-LONG in the caller displays 12.5.
- **Expected (spec):** §14.8.2.3.3 2) a): a numeric formal conforms as for a COMPUTE with the argument as sender; §14.2.3 GR9's second allocation regime performs that COMPUTE, so L = 12.5 and W = 01250 (displayed 01250).
- **Observed:** Measured: probe/elementary-items/c_float_disp printed MOVE [12.5], IN-S [0], W [00000] with no diagnostic. The binder admits the pair (ContentMismatch numeric arm: any numeric argument), so the crossing is live; ProgramEmitter.FormalCrossing sends an IsFloat formal to CallCrossing.Text and CallAbi.LandForFormal is only emitted for fixed-point formals — the float landing is the missing arm (location by reading; the wrong value is measured).
- **Code site:** src/Cobol.Net.Compiler/CodeGen/ProgramEmitter.cs#FormalCrossing; src/Cobol.Net.Runtime/Control/CallAbi.cs#LandForFormal; src/Cobol.Net.Runtime/Control/CallAbi.cs#TextValue

## What the fixer owes
Give ProgramEmitter.FormalCrossing a FLOAT class and LandForFormal a float arm (the MOVE float landing, one rounding — see PB1110), so the formal holds the MOVEd value. Sweep BY VALUE and the INVOKE channel for the same classification.
