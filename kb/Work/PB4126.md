# PB4126 — `cobol --std COBOL-2002` crashes with an unhandled InvalidOperationException instead of a usage error

**Sites:** `src/WiseOwl.Cobol.Cli/Program.cs:63` (`Program.BuildParser`, the `--std` option and its validator), `src/WiseOwl.Cobol.Cli/Program.cs:249` (`Program.CheckBatchVerdict`, the check-batch std field), `src/WiseOwl.Cobol.Cli/Program.cs:270` (`Program.TryParseStd`, `Program.StdSpellings`), `tests/WiseOwl.Cobol.Tests.Unit/CliParserTests.cs` (`Std_RejectsAnyNonEditionValue_AsAUsageError_NeverThrows`).

New defect of PB4031's finisher ("Distinct root"). `cobol --std COBOL-2002 <file>` ends with an unhandled `InvalidOperationException`
instead of a usage error naming the accepted values (85, 2002, 2014, 2023). The site is the `--std` validator in `Program.Main`
(Program.cs ~line 60-66 on main):

    stdOption.Validators.Add(result => { if (result.GetValueOrDefault<int?>() is { } y and not (85 or 2002 or 2014 or 2023)) ...

For a value `System.CommandLine` cannot convert to `int?` the option's value read throws; the validator should test
`result.Errors`/the token first, or the option should take a string and the edition parse should own the "accepted values" message
(CLI: one parse of the edition, one message). Add a CLI test over `--std COBOL-2002`, `--std abc`, `--std 1999` (each exits with the
usage error, none throws). Not legal COBOL source, hence not MAJOR: a tool-usage crash.

Repro: `cobol --std COBOL-2002 any.cob` (needs only the exe; R2: the report names the command and the line, so no re-probe done here).

Source: report `w20261762d-PB4031-report.md`, "New defects" third item; PB4031 (landed). The report's first two items are PB4092 and PB4093.

## Landing

Re-probed on the branch build before the fix: `cobol --std COBOL-2002 p.cob`, `--std abc` and `--std ""` each ended in the unhandled
`InvalidOperationException` from `OptionResult.GetValueOrDefault<int?>` at the validator (exit 127); `--std 1999` already gave the usage error.
Fix: `--std` is now an `Option<string?>` like every sibling value option (`--sign-encoding`, `--numeric-display`, `--source-format`,
`--repository-update`); `Program.StdSpellings` and `Program.TryParseStd` are the one place the accepted spellings and the parse live, and the
validator, `Resolve` and the sibling arm all use them. The sibling arm is `cobol check-batch`: its manifest std field was read with
`int.TryParse` and fell back to 2023 on any unparseable text, or compiled at any integer; a present field that is not an edition is now a FAIL
verdict naming the field as written. Every other value option was already a string with its own validator (swept: the only other typed
options are bools and the `string[]` of `--copy`, none of which can fail conversion).
