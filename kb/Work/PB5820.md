# PB5820 - a far pointer's slot-image entry was collectable

**Sites:** `src/WiseOwl.Cobol.Runtime/Control/SlotImageTable.cs#Note` and `#Sweep`; `src/WiseOwl.Cobol.Runtime/Control/PointerImage.cs#FarBase`
(`FarDisplacement`, `CellLife`, the new `ICellLifeEntry`).

**Mechanism.** `PointerImage.FarBase` (kb/Work PB4925) notes a fresh `FarDisplacement(cell, generation, offset)` at the far pointer's own base.
`SlotImageTable.Note` held strongly only `CellLife` and `NamedAddress` and wrapped every other entry in a `WeakReference`, the rule meant for an
addressless pointer's identity, which the program itself holds. Nothing else references a `FarDisplacement`, so the first collection after the
image was rendered emptied the entry, and `DataPointerOf` decoded the token as a `ForeignAddress`: a far pointer written to a file and read back
in the same run unit, its storage still allocated, came back as an address of no storage (EC-BOUND-PTR on dereference, §2023:13.18.5.4 GR4) and
compared unequal to itself. Silent and timing-dependent, so it showed only where another test's allocation collected in between (CI's shard 4/7).

**Repro (deterministic).** `GC.Collect(); GC.WaitForPendingFinalizers();` between `PointerImage.Of(written)` and `PointerImage.DataPointerOf(image)`
in `DataPointerOf_APointerDisplacedBeyondTheWindow_ReadsBackAsItself_NeverAsAnotherArea`: before the fix `Failed: 1, Passed: 10` (the IsType
`CellPointer` assertion, actual `ForeignAddress`, as in the merge group); after it the filtered SlotImage tests `Passed: 22`.

**Fix.** One kind for every entry that names storage of one cell life: `PointerImage.ICellLifeEntry` (`Cell`, `Generation`, `Ended`), implemented by
`CellLife` and `FarDisplacement`. `Note` holds any `ICellLifeEntry` strongly and `Sweep` drops one whose life ended, so a new cell-life entry kind is
retained and swept the same way with no second list. `AnEndedCellLife_IsNotRetainedByTheRunUnitsTable` now images a far pointer into each freed
cell too, pinning that the strong hold does not retain ended storage (review R1-2's rule).

**Sweep for siblings.** The other weak entries are `AreaBase`'s area objects and an addressless pointer's carrier: each is the program's own
object, alive while the program can still name it, so the weak hold is right for them.
