# PB5149 - the uniqueness screen skips GLOBAL constant, report and screen names

**Sites:** the PB5073 uniqueness screen `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.NameUniqueness.cs` (`ScreenGlobalNameUniqueness`, unchanged: the note first named `DataBinder.ClausePlacement.cs`, whole, the fix site not located); the guard it was missing is `src/WiseOwl.Cobol.Compiler/Binding/UserWordCensus.cs` (`Record`) fed by `ReportSectionBinder.cs:79` and `DataBinder.cs:565` (`DeclareUserWord`); the witness `conformance-suite/cases/8.3.2.2-User-defined-words/pb5149-report-name-and-global-data-name.cob`.

**Found.** PB5073's branch review swept for siblings and found that a GLOBAL constant-name, report-name or screen-name that shares its name with a data item is not screened. The screen covers global data-names and index-names only. The rule is §2023:8.4.2.1 (checked with `scripts/spec/cite.py --check`); the exact sentence and which of these names it reaches is not re-derived here.

**Owed.** Read §2023:8.4.2.1 for each name class, extend the screen from one table of name classes (not a per-class list), and add a golden per class.
