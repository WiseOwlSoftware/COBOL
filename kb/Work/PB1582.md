## Task brief (research 2026-09-30)

**Re-measured on `4a1dda60e` (PB1548's BASE has landed): reproduces** — a factory `METHOD-ID. NEW.` in a class that does
not inherit BASE, and `METHOD-ID. NEW OVERRIDE.` in a BASE subclass, both → COBOLNET0836 ("overriding New is a
deferred v1 restriction").

- **Spec (cite-checked):** §11.7.3 SR3 "If the OVERRIDE phrase is specified, there shall be a method with the same method
  resolution signature" (OK 3)); §16.2 declares BASE's factory `Method-id. New.` (OK §16.2) without FINAL; §11.7.3 SR4 a)
  (a class method with an inherited name and no OVERRIDE is refused — so `METHOD-ID. NEW.` WITHOUT OVERRIDE in a BASE
  subclass is still an error, by SR4 a), not by 0836).
- **Change:** delete COBOLNET0836 (`OoClassTable.cs` ~411) and its catalog row; outside BASE's hierarchy NEW is an
  ordinary factory method (INVOKE C "NEW" resolves to it); inside it, `NEW OVERRIDE` overrides BASE's New — the D4
  "generated constructor" realization must dispatch `INVOKE C "NEW"` to the override (virtual `__New` on the factory
  singleton, OO design D4/D7) and `INVOKE SUPER "NEW"` inside it to BASE's creation. Conformance of the override to
  §16.2's New signature (RETURNING an ACTIVE-CLASS reference) through `MethodConformanceMismatches`. Update OO design D4.
- **Goldens (2002):** no-BASE class with factory NEW → `MY-NEW` (and its RETURNING delivered); BASE subclass `NEW
  OVERRIDE` calling `INVOKE SUPER "NEW" RETURNING R` → `MY-NEW` then a usable instance; negatives: `NEW` without OVERRIDE
  in a BASE subclass (SR4 a)), `NEW OVERRIDE` with a USING formal (§9.3.8.2.3 rule 1 vs New).
- **Size:** half slot; touches the D4 creation path — review carefully.
