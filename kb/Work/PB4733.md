# PB4733 — the graceful stop is advisory, and an implementer ignored it

**What happened.** At 21:34 the operator ran `stop.ps1`, which created `E:\COBOL-coord\STOP`, `STOP-UNIT` and
`scratch\STOP-loop`. Wave 20261871 A (PB4700) was planned before PB4700 was held and was the wave's only running
group. Its dispatch spec (`scratch\msg-w20261871-a.txt` lines 78 to 80) says: "before EACH new step check for TWO
files, the owner's global stop E:\COBOL-coord\scratch\STOP and this fleet's own stop E:\COBOL-coord\scratch\STOP-loop;
if EITHER exists, checkpoint-commit, write STATUS.md NEXT and your report, and return status SPLIT." The implementer
made a WIP checkpoint at 21:39 (b18021c06), five minutes later. It did not return. It went on writing tests, goldens and
refusals and committed again at 21:58 (125e164b0), with NEXT naming a full Unit run and the docs. The supervisor's grace
period before it kills a wave unit is `3 * GraceMinutes` = 90 minutes (`orchestrate.ps1:499`). The operator killed
the unit's process tree by hand at 22:00. The branch was abandoned (PB4700), so the extra 20 minutes of agent time were
wasted, and a fleet stop that relies on the agent reading its brief is not a stop.

**What to fix.** Enforce the stop mechanically instead of trusting the brief. A PreToolUse hook (beside
`scripts/hooks/fleet_active_build.py`) could refuse every tool call of a fleet agent while either stop file exists,
except the calls that checkpoint: `git add`, `git commit`, `git push`, writes to STATUS.md and the report. The agent
must then return SPLIT. The hook needs a way to tell a fleet agent from the attended session (the dispatch's
environment or its worktree path), and a self-test. Separately, consider whether 90 minutes of grace for a wave is
right once the hook makes the stop prompt.
