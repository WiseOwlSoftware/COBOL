# PB5125 - at --std 85 a random WRITE of a relative record number above the file boundary returns I-O status 34 through the permanent-error path (INVALID KEY not executed); 1985 defines no 34 for relative files and gives 24 through the invalid key path

**Sites:** `src/WiseOwl.Cobol.Runtime/IO/RelativeConnector.cs#Write`: `if (slot is < 1 or > HighestRelativeRecordNumber) return Status = FileStatusCode.PermanentBoundary; // 34 §2023:14.9.51.4 GR29 b` (line 343 at the pin and on main); no edition arm

**Mechanism.** The 1985 relative-file status list has no 34 at all (its permanent errors are 30, 35, 37, 38 and 39); a write beyond the externally defined boundaries is status 24 and an invalid key condition (§1985:VIII.4.9.4 GR14 b), so the INVALID KEY phrase executes (§1985:VIII.1.3.5 (2)). The compiler returns 34 (§2023:14.9.51.4 GR29 b) with no edition arm, so the INVALID KEY phrase is skipped (with a USE AFTER STANDARD EXCEPTION procedure the procedure runs with status 34). The other 32 expected lines (22, 23, 05, the sequential 24) match. kb/Work PB1192, PB3333 and PB2751 (all landed) implement and order the 2023 statuses 24 and 34 and none treats --std 85. Not asserted: a WRITE with relative key 0, which is not a relative record number in 1985 and for which 1985 states no result; the compiler answers 34 for it too from the same test. Implementor-defined choice the draft rests on: the boundaries of a relative file exclude 9,999,999,999 (WiseOwl's highest permitted number is 2,147,483,647, RelativeConnector.HighestRelativeRecordNumber).

**Found by.** The 1985 witness-drafting pass (kb/Work PB4995 item 3): each rule below is a witness program drafted from the 1985 text alone, run at `--std 85`, and its result differs from what the text requires (outcome MISMATCH). Harm and observed text are the record's; nothing here was re-derived.
