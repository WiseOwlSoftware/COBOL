## Measured

### Finding report-group-description-entry — §13.15.3 SR16 (under-rejects; rows SR-13.15.3-16)

**Mechanism.** report-present-when-scan-over-bound-products: CheckConditionOperands collects PRESENT WHEN conditions only from what the walk PRODUCED (lines, printable fields, sum counters). A condition written on an entry that produces none of these is never scanned, and the name set is only this RD's group, field and sum names

**Repro.** RD R1 CONTROL FINAL PAGE LIMIT 20 LINES. 01 D1 TYPE DE. 03 LINE 1. 05 COLUMN 1 PIC 9 SOURCE WN. 01 D2 TYPE DE PRESENT WHEN LINE-COUNTER > 0. + GENERATE D1 (probe rgde/sr16empty)

**Expected, from the standard.** Refused. §13.15.3 SR16: 'Condition-1 shall not reference any sum counter, LINE-COUNTER, PAGE-COUNTER, or other report section data item.' The rule is a syntax rule on the written clause, independent of whether the entry prints anything.

**Observed.** Compiles and runs (rc 0). The same LINE-COUNTER condition on an entry that does carry a line (probe sr16grp/sr16lc) is refused with COBOLNET1559. A reference to a named intermediate entry, or to another RD's item, is refused only by COBOLNET1639 'not defined' (the kb/Work PB1046 shape), not under SR16. The screen should read the condition off the WRITTEN entry array (the ScreenReportEntryClausePresence shape) instead of the bound products.

**Code site.** src/Cobol.Net.Compiler/Binding/DataBinder.Reports.cs#CheckConditionOperands; #ReportSectionOnlyNames
