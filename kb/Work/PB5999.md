# PB5999 - a timing check of test_orchestrate_stop.ps1 fails under load

In the gate run 000001-20261121T124949Z (a diff of docs, scripts and a few sources, the self-tests running beside the test hosts at 35% machine load)
`scripts/orchestrator/test_orchestrate_stop.ps1` failed 32 of 33 checks: `FAIL: progress: the supervisor logs the PROGRESS line
while the unit runs: got 'False', want 'True'`. The same script alone on the same tree passed 33 of 33 in 21 s. The check (read from the script, not yet traced to its cause) appears to read
the log inside a fixed window while the unit runs, so a loaded host misses the line: a flake to root-fix by waiting on the line
(a bounded poll for the condition), never by a longer sleep and never by a retry inside the gate (CLAUDE.md, Testing).

**Sites:** `scripts/orchestrator/test_orchestrate_stop.ps1` (whole: the one check that reads the log in a fixed window).
