# PB5212 - at --std 85 a debugging line before or within the OBJECT-COMPUTER paragraph compiles (a D-line DATE-WRITTEN or OBJECT-COMPUTER), and so does a debugging line whose program is not syntactically correct both ways: DebuggingLineRewriter keeps or hides lines and checks neither rule of the 1985 debugging-line presentation

**Sites:**

- `src/WiseOwl.Cobol.Frontend/Parsing/DebuggingLineRewriter.cs` (`Rewrite`, `Resolve`, `DebugLines`)
- `src/WiseOwl.Cobol.Frontend/Parsing/DebuggingLineRewriter.cs` (`ParagraphEnd`, `UnitFrame.PermittedFrom`)
- `src/WiseOwl.Cobol.Frontend/Pipeline/Frontend.cs` (`LexAndParseOnce`, `ReportMisplacedDebuggingLines`, `ReportDebuggingLinesBreakingTheProgram`, `ParseCopyOf`)
- `src/WiseOwl.Cobol.Editions/Diagnostics/DiagnosticCatalog.cs` (`DebuggingLineBeforeObjectComputer` COBOL7060, `DebuggingLineSyntaxBothWays` COBOL7061)

**Mechanism.** §1985:VI.4.3.4 GR4 compiles debugging lines "as specified in this presentation of the Nucleus module", which is §1985:VI.7.3, and that presentation has two rules on the program: "A debugging line is only permitted in the separately compiled program after the OBJECT-COMPUTER paragraph." and "The content of a debugging line must be such that a syntactically correct program is formed with or without the debugging lines being considered as comment lines." `DebuggingLineRewriter.Rewrite` is the one place a debugging line becomes source or comment; it groups lines by source unit and asks only whether the unit declares WITH DEBUGGING MODE. It knows where each line sits (it walks the unit's tokens, SOURCE-COMPUTER included) but never asks whether the line comes before the end of the OBJECT-COMPUTER paragraph, so a D line in the Identification Division, or the OBJECT-COMPUTER paragraph itself written on a D line, compiles. It also keeps a D line whose text completes a statement on a normal line, a program that does not parse with the line taken as a comment.

**Found by.** The 1985 refuter pass (2026-11-10; records `E:/COBOL-coord/scratch/refute-85/out/r08.json`, probes `probes-r08/d1.cob`, `d2.cob`, `d5.cob`, `d6.cob`, `d7.cob`): a refuter attacked the CONFORMS verdict of the row below, which tested only where debugging lines run, OVERTURNED it, and the probes were rerun on current main for this note.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the row this note claims is the rule id below. §1985:VI.7.3 has no catalog row of its own; GR4 points to it.

**Rules (1; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-GR-VI.4.3.4-4` - `§1985:VI.4.3.4 GR4` (refuter: OVERTURNED, harm: under-rejects). §1985:VI.4.3.4 GR4: "all debugging lines are compiled as specified in this presentation of the Nucleus module"; §1985:VI.7.3: "A debugging line is only permitted in the separately compiled program after the OBJECT-COMPUTER paragraph."; §1985:VI.7.3: "The content of a debugging line must be such that a syntactically correct program is formed with or without the debugging lines being considered as comment lines."

**Observed (current main, the build at 3d12682fd2, rerun 2026-11-10).** `d5.cob`: exit 0, prints `END`. `d2.cob` (the same program with `DOBJECT-COMPUTER. X.` on a D line and a D-line DISPLAY "DBG" in the procedure): exit 0, prints `DBG`, `END`. `d6.cob`: exit 0, prints `X`, `END`. `d7.cob`, the same as d6 without WITH DEBUGGING MODE: exit 65, `error COBOL5506: unexpected '"X"'`, so d6 is not syntactically correct with its debugging line taken as a comment.

**Expected (from the 1985 text).** d5 and d2 are refused at the D line: it stands before (d5) or is (d2) the OBJECT-COMPUTER paragraph (§1985:VI.7.3). d6 is refused: the program it forms with the D line as a comment does not parse (§1985:VI.7.3), which the compiler can show by the parse d7 already makes.

**Fix direction (root cause, CLAUDE.md rule 4).** Both rules belong to the one pass that owns debugging lines. Placement: `Rewrite` already walks each unit's tokens; record the position where the unit's OBJECT-COMPUTER paragraph ends (or, without one, where the Environment Division or the next division begins) and diagnose, below COBOL-2002, a debugging line that starts before it. Dual syntax: when a unit keeps any debugging line as source, also parse the unit with those lines hidden (the reading `HideAll` already gives a fragment) and diagnose a debugging line whose hiding breaks the parse. Decide in the design doc whether the dual-syntax check runs always or only at 85; the placement check is a plain positional refusal.
