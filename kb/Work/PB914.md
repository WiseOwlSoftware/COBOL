# PB914 — OPEN — thirteen raw sites and no descriptor behind any of them

Source: the **train-42 lander report**, §5, verbatim: *"⛔ FOR THE REGISTRAR — a note's worth of work, not
a lander's: give COBOLNET0867 a `DiagnosticCatalog` descriptor and convert its thirteen call sites in
`OoBinder.cs`. That is the root fix, it lowers the ratchet by 13, and it is one sweep."*

## The measurement

`<scratch>/reg7/probe/r_set_super.cob`, `--std 2023`:

```
r_set_super.cob(7,12): error COBOLNET0867: SET … TO SUPER: SUPER shall not be the sending operand of an
object-reference SET (ISO §14.9.39.3 SR9)
```

and on this tree:

```
$ grep -c 'COBOLNET0867' src/Cobol.Net.Compiler/Binding/Procedure/Verbs/OoBinder.cs
$ grep -rn '"COBOLNET0867"' src/Cobol.Net.Compiler/ | wc -l
```

— every one a raw `ctx.Edition.Error("COBOLNET0867", …)`, and **no `DiagnosticCatalog` entry**. Train 42
re-recorded the semgrep baseline at 416 (from 415) because cluster 1's new SR9 screen added the thirteenth,
and the lander explicitly declined to invent the descriptor inside a landing gate.

## Why a missing descriptor is more than tidiness

A `DiagnosticCatalog` descriptor is where a code's rule text, its suppress key and its ISO reference live,
and it is what `scripts/gen-diagnostics-doc.ps1` reads to build `docs/DIAGNOSTICS.md`. A code with no
descriptor therefore:

* cannot be documented (this is the same hole **PB424** records for COBOLNET0809 / COBOLNET0819),
* cannot be suppressed or referred to by a user,
* and is invisible to every consistency check that walks the catalog.

The citation in its text is real —

```
$ python scripts/spec/cite.py --check 14.9.39.3 "index-name-2 shall be specified"
OK  §14.9.39.3 4)  (Syntax rules)
```

(SR4 checked as the neighbouring ordinal; SR9 is the one 0867 cites) — but it is written thirteen times by
hand, which is exactly the drift surface `audit_code_citations.py` exists to find.

## The fix

One descriptor, thirteen call sites converted to it, the semgrep baseline **lowered** by 13 in the same
commit with the number recorded (that is `kb/Work/PB175`'s own prescription: each finding needs a fix or a
recorded decision plus a re-baseline), and `docs/DIAGNOSTICS.md` regenerated. Then the same question asked
of every other code emitted raw: `grep -rhoE '"COBOLNET[0-9]{4}"' src/ | sort -u` against
`DiagnosticCatalog`'s keys — the set difference is the rest of this sweep, and it should end as a drift
test, not as a second hand list.
