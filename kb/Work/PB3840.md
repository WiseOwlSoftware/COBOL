# PB3840 — one conformance row ID, two determinations

**Sites:** `docs/CONFORMANCE.md` (the two item-92 rows of §7 and the note above the register), `scripts/spec/audit_annex_a1.py` (`ITEM_KEY_RX`, `TOKEN_RX`, `evaluate`, `sweep_lettered_citations`), `scripts/spec/inventory_schema.py` (`register_determinations`), `tests/_shared/ConformanceRegister.cs` (`Build`), `tests/WiseOwl.Cobol.Tests.Unit/DerivedVerdictDriftTests.cs` (`TheRegisterParser_ReadsSection7_AndNotAnEmptyTable`), `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/IntrinsicRenderer.cs` and `src/WiseOwl.Cobol.Runtime/Intrinsics/CobolIntrinsics.Float.cs` (the two citations of the floating-argument row), `docs/INTRINSICS_DESIGN.md`

## The defect

`docs/CONFORMANCE.md` has two rows with the ID DOC-A.1-92: "Characteristics and representation of a numeric intrinsic
function's returned value, and its text image" and "Evaluation of an exact-family intrinsic whose ARGUMENT is
floating-point". Code comments in ten files cite DOC-A.1-92 (IntrinsicRenderer.cs, IntrinsicBinder.cs,
SendingValueTemp.cs, DataItem.cs, AlgebraicRange.cs, RelationComparability.cs, ConditionRenderer.cs, OperandText.cs,
OoBinder.cs, CobolIntrinsics.Float.cs) and cannot say which determination they rely on. The ID audit
(`audit_annex_a1.py`) does not refuse a duplicate.

## Fix

Give the second determination its own ID, re-point each citing site to the row it actually relies on (read each one),
and make the audit refuse a duplicate row ID (sweep: run it over the whole file for any other duplicate).

## Acceptance

- `grep -oE '^\| DOC-[A-Z0-9.-]+ ' docs/CONFORMANCE.md | sort | uniq -d` prints nothing, and the audit fails if it would.
- Every code citation names the row it relies on.

## Landed

Cause: the register keyed a determination by the A.1 item it discharges, so an item that needs two determinations
(item 92: the returned value's characteristics, representation and text image; the evaluation of an exact-family function
with a floating-point argument) filed both under one key, and the audit, the Python reader and the C# reader each had a
comment calling that legitimate and silently kept the first row.

Fix: a row key is unique. The first determination of an item keeps the item's rule-id (`DOC-A.1-92`, the key its
inventory row anchors on), a further one takes the id plus a letter (`DOC-A.1-92b`). `audit_annex_a1.py` refuses a
repeated key and a lettered key with no row for its item, counts each token once, and checks that every lettered token
cited in `src`, `tests` or `docs` is a row (self-test cases prove each refusal can fire). Both register readers now throw on a
repeated key instead of keeping the first. The three citations that rely on the floating-argument arm
(`IntrinsicRenderer.cs`, `CobolIntrinsics.Float.cs`, `INTRINSICS_DESIGN.md`) now name `DOC-A.1-92b`; every other citation
(text image, device form, nominal item, the float family's binary64 returned value) relies on the first row and keeps
`DOC-A.1-92`. A `rules:` header in a golden names the inventory rule-id of the item, which both determinations discharge, so
the goldens are unchanged.
