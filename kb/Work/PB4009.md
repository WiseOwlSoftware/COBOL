# PB4009 — the spec renderer repeats the root file when a note's Sites names only that file

**Sites:** `.claude/skills/workstream/make_dispatch_specs.py`, `.claude/skills/workstream/check_practices.py`

**Observed.** `plan_wave.py` for wave 20261742 rendered `msg-w20261742-c.txt` for PB3996, whose `**Sites:**` line named only
`src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CallBinder.cs`. The spec's "THE GROUP IS ONE ROOT: <file>." and "CODE SITES
the notes name: <file>." then read as one repeated sentence, `check_practices.py` (PB3777, states twice) refused it, and the
planner reserved nothing and wrote no args file.

**Worked around in the notes, not fixed.** PB3996's and PB3997's Sites now name members (`#BindCall`, `#ValidateNumericValue`,
`#Of`), which the register's convention asks for anyway. The renderer still produces a spec its own checker refuses for any
note whose Sites is exactly the root file.

**Fix.** The renderer must never state the same fact twice: when the notes' code sites equal the group's root, say so once
(omit the CODE SITES sentence or render it as "the root above"). Pin it with a check_practices self-test case: a note whose
Sites names only the root renders a GREEN spec.
