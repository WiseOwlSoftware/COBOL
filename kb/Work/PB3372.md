# PB3372 — a SHARING or RETRY phrase makes the open a record-locking participant

Filed 2026-10-18 from wave 1117 group F's report (`E:\COBOL-coord\scratch\reports\w1117f-PB675-report.md`,
"New defects").

## What happens

`FileRegistry.OpenCore` makes ANY SHARING/RETRY phrase (`phraseParticipant`) a record-locking participant
(`_locksRecords`) even with `FileLockMode.None` (`src/WiseOwl.Cobol.Runtime/IO/FileRegistry.cs:1092`,
`src/WiseOwl.Cobol.Runtime/IO/FileConnector.cs:279`). It was reported as a design smell with no harm measured, and not
changed (behavior-affecting, outside that slice).

## What is NOT yet known

The governing rules (the LOCK MODE clause's general rules and the record-locking rules) have NOT been derived or cited
yet. Whoever takes this note derives the expected behavior from the ISO spec with `python scripts/spec/cite.py --check`
first, and builds a repro (an OPEN with a SHARING or RETRY phrase on a file with no LOCK MODE, then a second
connector's access) that shows whether a record lock is taken.

## Landed (wave 1131, group B)

Re-probed on the branch build with `RecordLockingParticipationDriftTests` written first: 33 of 55 cells were red on main.
The registry had TWO answers to "does this connector set record locks": `LocksEffective` asked it at every I-O statement
(a LOCK MODE clause under a sharing mode other than NO OTHER, ISO 12.4.5.9.4 GR1 and GR3), while `SharedOpenAttempt` handed
`FileConnector.AssociatePhysical` the mere PRESENCE of a registered posture. Presence was written by three things that
confer no lock: a SELECT with a SHARING clause alone (GR1 a), `OpenCore`'s `phraseParticipant` registration of a lock-less
posture for ANY SHARING or RETRY phrase (GR1 b) 1.; it also persisted for the life of the run unit), and a LOCK MODE clause
under NO OTHER, the implementor default of EXTEND, I-O and OUTPUT (GR3). Each made `SharedPhysical` non-null, so a
sequential `OPEN EXTEND` paid the whole-file record count (`CountRecords(0, long.MaxValue)`) to seed a release-ordinal mint
nothing reads (`LastWrittenRecordId` is read only when a lock is wanted), and an OUTPUT or EXTEND writer asked the host for a
read-write handle for lock publication it never does. The record-lock half of the I-O statement was right (`LocksEffective` already refused the lock), but ONE OPEN status was wrong: an
OPEN EXTEND of a file the process may write but not read answered '37' for a writer that sets no lock, where §9.1.13.6 6) a) 1. admits
only "the file will not support write operations" and the answer is '00'. Pinned by
`FileAuthorityPresenceTests.OpenExtend_AWriterThatSetsNoRecordLockOnAWriteOnlyFile_IsSuccessful` (3 framings; review round 1 R1-1). The
conformance corpus cannot make a file unreadable, so the witness is a host-only Unit test. The standing goldens `12.4.5.9-LOCK-MODE/l1_lock_mode_omitted_sets_no_lock` and
`l1c17_lock_mode_no_other_inert` pin the I-O statement half.

Fix: `FileRegistry.RecordLocksSetUnder(meta, openSharing)` is the one writing of the rule; `LocksEffective` and
`SharedOpenAttempt`'s `AssociatePhysical` call both read it, and the phrase registration and `phraseParticipant` parameter
are deleted (an OPEN phrase can change the sharing mode, never write a LOCK MODE clause). The posture is derived per OPEN, so
a phrase leaves nothing behind. Tests: `RecordLockingParticipationDriftTests` (14 spellings x 3 framings: participation and
the seeded ordinal; WRITE WITH LOCK sets a lock only under a LOCK MODE clause; a sibling READ gets '51' on the participant's
record and '00' on a lock-less writer's; '35', '61' (also after RETRY exhausts) and '41' leave no participation; per-open
derivation; the structural half). `SharedExtendOpenDriftTests`, `SharedReadCoherenceDriftTests` and
`AlreadyOpenOpenDriftTests` were re-pointed at the new expression.

## Landing

- `src/WiseOwl.Cobol.Runtime/IO/FileRegistry.cs#RecordLocksSetUnder` - the one writing of "this connector can SET record locks under this sharing mode"; REUSE it for any new question about lock participation, never test `_connectorShares` presence or a LOCK MODE value beside it. Trap: `ShareOf(name)` gives a clause-less connector the lock-less default, so a miss needs no special case.
- `tests/WiseOwl.Cobol.Tests.Unit/RecordLockingParticipationDriftTests.cs#Cases` - one table of (SELECT clauses, OPEN phrases) with the expected participation and seeded ordinal; REUSE it to add a spelling. Trap: the plain OPEN is `OpenStatic`, not `OpenShared` with empty phrases.
