# PB518

## Mechanism — data-description-entry-p2
F2 — There is NO clause-site screen for EXTERNAL and GLOBAL. Their only structural gate lives inside the post-bind REGISTRATION scan (CallBindExternalAndGlobal), where the level test and the entry-name test are written as `continue` filters: an entry that fails either is skipped, not diagnosed. A `continue` is a selector, so it is evidence about what it registered and says nothing to the user about what it dropped — an out-of-place or FILLER-named EXTERNAL/GLOBAL clause is accepted, silently stripped of its attribute, and the program then behaves as if the clause had never been written. This one mechanism owns both the GLOBAL half of SR6 and the whole of SR7.

### Expected, from the standard
ISO/IEC 1989:2023 §13.16.3 SR6 (cite-checked): "The CONSTANT RECORD and GLOBAL clauses may be specified only in data description entries whose level-number is 1." §13.16.3 SR7 (cite-checked): "The data-name format of the entry-name clause shall be specified for any entry containing the GLOBAL or EXTERNAL clause, or for record descriptions associated with a file description entry that contains the EXTERNAL or GLOBAL clause." §13.18.27.3 SR1 b) (cite-checked) says the same level-1 restriction for GLOBAL from the clause's own side. Every one of the four repro entries is nonconforming and shall be rejected at compile time.

```
$ python scripts/spec/cite.py --check 13.16.3 "The data-name format of the entry-name clause shall be specified for any entry containing the GLOBAL or EXTERNAL clause, or for record descr..."
  OK  §13.16.3 7)  (Syntax rules)
```

### Observed
All four compile and run clean, at every edition, with no diagnostic. The mechanism is visible in DataBinder.Linkage.cs#CallBindExternalAndGlobal: `if (!int.TryParse(entry.levelNumber().GetText(), out int lvl) || lvl is not (1 or 77)) continue;   // §13.18.22 SR1 / §13.18.27 SR1b — record-description level-01/77 entries only` (~355) and `if (entry.dataName()?.GetText() is not { } name) continue;` (~357). Both comments describe a RULE while the code performs a SKIP. The consequence is not merely permissive: in (a) H is never added to _callGlobalRoots, so a contained program referencing H gets COBOLNET1639 'not defined' — the user's GLOBAL clause was accepted and then annulled. In (b) the record is never re-based onto the run-unit ExternalStore, so two programs that both declare it do NOT share storage (§13.18.22.4 GR4). kb/Work PB163 (status: landed) already names part of this as its residue item (a): 'the 01/77 admission is looser than both SRs (each says level 1; a 77-level GLOBAL/EXTERNAL clause is accepted and registered rather than screened at the clause site) ... a clause-site screen belonging to the §13.18.27 checks, not this registration pass.' The measurements here are WIDER than that text: level 5 (not just 77) is silently dropped, and the entry-name half (SR7) and the FD half are unmentioned there. Note also DataBinder.Reports.cs:317, 'A GENERATE-able detail always has a data-name (§13.16.3 SR7) — unreachable unless the binder let ...', which asserts an invariant the binder does not establish.
