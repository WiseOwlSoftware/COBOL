# PB1781 — OPEN

Found 2026-09-30 by the OO research agent while re-measuring PB480 on main `4a1dda60e` (Debug build of that tree).

## Repro (measured)

```cobol
       PROGRAM-ID. P480E.  … REPOSITORY. CLASS C480E.
       01 U USAGE OBJECT REFERENCE.
       01 G.
          05 G1 PIC X(4) VALUE "ABCD".
       PROCEDURE DIVISION.
           INVOKE C480E "NEW" RETURNING U
           INVOKE U "TG" USING G
       …  class C480E (INHERITS FROM BASE), instance method TG:
           LINKAGE SECTION. 01 LG. 05 L1 PIC X(4).
           PROCEDURE DIVISION USING LG. DISPLAY "TG:" LG.
```

`cobol pb480_grp_eq.cob --std 2023` → `error: backend compilation failed … (138,25): error CS0029: Cannot implicitly
convert type 'string' to '_PRG_P480E._T_200001'`. The generated caller is

```csharp
var __ua0 = new CobolInvokeArg[] { new CobolInvokeArg("S:4:N", G) };      // boxes the record struct
CobolObject.RequireNonNull(U).__CobolInvoke("TG", __ua0, __ur0);
G = (string)__ua0[0].Value!;   // BY REFERENCE copy-out (SR6)                // writes a string into it
```

The same with an 8-byte group into the 4-byte group formal (`pb480_grp`). The typed twin (`INVOKE` through
`USAGE OBJECT REFERENCE C480T`) compiles and runs (`TG:ABCD`).

## The rule

- §14.9.23.3 SR6 (`cite.py --check 14.9.23.3 "neither the BY CONTENT nor the BY VALUE phrase shall be specified and
  the BY REFERENCE phrase, if not specified explicitly, is assumed implicitly"` → OK §14.9.23.3 6)) — a group is
  passed BY REFERENCE through a universal receiver.
- §9.3.6 match rule 3 c)/3 e) (`--check 9.3.6 "is the same class and category"` → OK 3) c)) — two alphanumeric
  groups are the same class and category and carry none of 3 e)'s clauses, so the method MATCHES; §14.8.2.2 rule 1
  (`--check 14.8.2.2 "the formal parameter shall be described with the same number or a smaller number of bytes as
  the corresponding argument"` → OK 1)) then CONFORMS for both probes. Expected output `TG:ABCD` for both.

## Mechanism

`src/Cobol.Net.Compiler/CodeGen/Verbs/OoEmitter.cs#OoUnivCallerRead` has no arm for an image-capable fixed group
(it falls to `PlaceRenderer.Read(p)`, the struct), while `#OoUnivCallerWrite` takes the `OoStringCarried` arm and
writes a string. The D10 canonical-box rule ("`S:*` → string", `docs/COBOLNET_OO_DESIGN.md` D10) is violated on the
READ side. The callee half (`EmitCobolInvokeCase`'s unbox) must be checked for the same asymmetry.

## Task brief (research 2026-09-30)

- **Spec:** §14.9.23.3 SR6, §9.3.6 match rules 3 c)/3 e), §14.8.2.2 rule 1 (all cite-checked above).
- **Change:** make the universal box of a fixed alphanumeric group its character IMAGE on BOTH sides — caller read
  (`OoUnivCallerRead`: the group's image, the same `.AsImage()`-generator path the typed boundary uses per
  `BoundaryImageChannelTests`), caller copy-out (`OoUnivCallerWrite`: splice the image back; for a formal SMALLER
  than the argument, §14.8.2.2 rule 1's prefix — the typed lane's "write-back SPLICES the prefix and preserves the
  tail" rule, OO design D6 item 1), callee unbox/rebox in `EmitCobolInvokeCase`. One predicate decides "carried as
  an image" for read and write (a drift test: every `OoUnivCallerRead` arm has its `OoUnivCallerWrite` twin — the
  asymmetry is this bug's whole mechanism).
- **Goldens (2023; expected from the spec):** `pb1781_universal_group_crossing` — (a) equal-size group → `TG:ABCD`;
  (b) 8-byte argument into a 4-byte formal that MOVEs `WXYZ` into its group → caller sees `WXYZEFGH` (prefix
  spliced, tail kept); (c) a group into an `X(4)` formal and an `X(4)` into a group formal → EC-OO-METHOD (no match,
  §9.3.6 3 e)) under a declarative on EC-OO-METHOD that DISPLAYs the name — **(c) depends on PB480's MATCH relation;
  if PB480 has not landed, pin (a)/(b) only and leave (c) to PB480.**
- **Siblings to sweep:** RETURNING a group through universal (`__ur` delivery), national/bit groups (`G:` keys),
  variable-length groups (`V:` — already has an arm; confirm with a probe), a group OCCURS entry as the argument.
- **Size:** half a batch slot. Independent; land before PB480's restructure (it is a crash today).

## Landed (wave 1001 B)

Re-probed on this wave's Debug build (`u1.cob`: class `C480E INHERITS FROM BASE` with an instance method `TG` taking `01 LG. 05 L1 PIC X(4).`,
caller `INVOKE U "TG" USING G` with `U USAGE OBJECT REFERENCE` and `01 G. 05 G1 PIC X(4)`): `CS0029 Cannot implicitly convert type
'string' to '_PRG_P480E._T_200001'` at the copy-out `G = (string)__ua0[0].Value!`, as filed. Citations re-run (`cite.py --check`):
§14.9.23.3 SR6, §14.2.3 GR8, §14.8.2.2 rule 1, §9.3.6 match rule 3 c), §14.9.23.4 GR8 — all OK.

**Mechanism.** The two halves of the universal lane's box pair disagreed about a fixed GROUP: `OoUnivCallerWrite` took the string arm
(`OoStringCarried` is true of every group, and the callee's `OoUnivUnbox` is `(string)box`), while `OoUnivCallerRead` fell to
`PlaceRenderer.Read(p)` — the record STRUCT — so the caller boxed a struct and then assigned a string back into it. D10's canonical
box (`S:*` → string) was violated on the READ side only.

**Fix.** `OoUnivCallerRead` reads a group through `CallEmitter.CallStringRead` and `OoUnivCallerWrite` returns it through
`CallEmitter.CallStringWrite` — the ONE boundary reader/writer the CALL and the typed INVOKE lanes use (full image of an alphanumeric
group, the elementary alphabet of a bit/national group, kb/Work PB1166), so the universal lane has no spelling of its own. The callee
half (`EmitCobolInvokeCase`'s `OoUnivUnbox`/`OoUnivRebox`) was checked for the same asymmetry and is symmetric: `(string)box` in,
`(object?)local` out. `docs/COBOLNET_OO_DESIGN.md` D10 now states the group box instead of the CS0029.

Sweep (variant-analysis): dispatch = the box arms of `OoUnivCallerRead` / `OoUnivCallerWrite` (and their callee twins), arms =
RefMod, variable-length group, fixed group (FIXED), image-bridged numeric, native-box-over-image numeric, string, object reference,
native. Probed typed-vs-universal after the fix (`UniversalCrossingShapeDriftTests`, nine rows, each pinned to the rule-derived value):
alphanumeric group with a zoned member, national group, bit group, elementary X(4) (control), group with a COMP-3 member, a
subscripted group entry, a group delivered through RETURNING, a group with a fixed OCCURS table, and a variable-length group
(DYNAMIC LENGTH member, 2014) — all agree; six of the nine failed to compile on the pre-fix tree.

**Not done, and why (PB480's).** The note's golden (b) — an 8-character group argument into a 4-character group formal, §14.8.2.2
rule 1's by-reference prefix — is NOT a crossing the universal lane admits: the conformance descriptor is compared by STRING EQUALITY
(`S:8:N` against `S:4:N`), so the method does not MATCH and the invocation is EC-OO-METHOD (probed: `abnormal run-unit termination:
EC-OO-METHOD`). That is the relation kb/Work PB480 / PB1780 restructure, not a crossing defect; the brief's "(a)/(b) only if PB480 has
not landed" was wrong about (b), and (c) group-versus-`X(n)` is equally PB480's. The caller's copy-out therefore writes the callee's
box whole (equal width by the descriptor) and says so; the prefix splice joins the day the match relation admits an unequal formal.

Witnesses: `2002/pb1781_universal_group_crossing` (an alphanumeric group, a national group and a RETURNING group through a universal
receiver) with the negative `pb1781-universal-group-crossing-below-2002` (COBOLNET0900 at `--std 85`), and
`UniversalCrossingShapeDriftTests`.
