# PB2045 — OPEN: local gate runs went RED on 'Access is denied' with no code cause

**Evidence (two runs, both on this Windows host; Linux and CI never showed it).**
1. 2026-10-04 22:43 PDT, lander gate on the PB2015 follow-up: `MoveTable16AskerDriftTests.Table16Alone_IsAskedOnlyByTheKnownNonItemSenders` failed with
   `UnauthorizedAccessException` reading `src/Cobol.Net.Compiler/CodeGen/Roslyn/FigurativeConstants.cs`. The immediate re-run was green.
2. 2026-10-05 about 10:27 PDT, lander gate on the hook-rule change (scripts only): 13 failures in unrelated tests (6 Conformance, 7 Unit), every one an
   access denial: either `System.IO.FileLoadException: Could not load file or assembly 'E:\Temp\CobolNet_Diff_cn_<id>\prog.dll'. Access is denied` (a freshly built
   program loaded by a test) or `UnauthorizedAccessException` on a plain source or fixture file under `E:\COBOL` (drift tests reading `src\Cobol.Net.Compiler\Binding\Model\BoundUnit.cs`,
   `LocaleSymbol.cs`, `RefModZeroLengthState.cs`, `src\CobolSharp.Runtime\ManagedPointer.cs`, a `tests\conformance\negative\*.err`). The re-run was green.

**Not the code.** Both changes under test touched only a hook, its test and docs; no test asserts anything that those could change; and a denial on a source file that
is not being written by anything the gate runs is not a logic failure.

**Hypothesis, with its evidence and its gaps.** Windows Defender real-time scanning denying access to files it is scanning (new DLLs and recently read sources).
For: the Defender operational log shows engine rollback and re-initialisation events (`EngineRollbackMethod`, `MetaStore init error 0X87AF000B`) at 10:06 and 10:11 on 2026-10-05,
shortly before the second red; real-time protection and tamper protection are both on; the failures are scattered and non-repeating. Against or missing: no log line ties a
denial to a scan (the exclusion list needs admin to read), the events precede the red gate by about fifteen minutes, and the first red had no Defender event in its window at all.
Other suspects if the exclusion does not stop it: the Windows Search indexer and the C# language server (both can hold files).

**Action taken (the owner, from an admin terminal, 2026-10-05 about 10:38):** `Add-MpPreference -ExclusionPath 'E:\'`, confirmed by `Get-MpPreference`. The lander gate re-run
that overlapped it was green with zero denials.

**To close:** this note stays OPEN until it has been checked against evidence. Close it when the next five local gate runs (lander or implementer, at any load) show no
`Access is denied` or `UnauthorizedAccessException`; if one recurs, reopen the hypothesis and look at the indexer and the language server. Not built, deliberately: a
retry on denial inside the tests or the gate driver. It would hide a real environment fault (the CI invariant: a local flake is a defect in the local setup, found and fixed,
not retried), and the cause is outside the code.
