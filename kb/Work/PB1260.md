## Measured

### Finding occurs-clause-p1 — §13.18.38.3 SR1 b) (crashes; rows SR-13.18.38.3-1)

**Mechanism.** A Format 4 (DYNAMIC) table is invisible to OdoResolve's 'is this an OCCURS entry' test: the ancestor walk asks `a.Occurs is not null`, and a dynamic-capacity table deliberately leaves DataItem.Occurs null, so an occurs-depending table nested under OCCURS DYNAMIC passes SR1(b) and reaches run time

**Repro.** WORKING-STORAGE: `01 N PIC 9 VALUE 2. 01 R. 05 G OCCURS DYNAMIC FROM 2 CAPACITY IN C. 10 T PIC X OCCURS 1 TO 5 DEPENDING ON N.` then `DISPLAY ... FUNCTION LENGTH(G(1))` (out13/probe/occurs-p1/sr1b_dyn_run2.cob), --std 2023

**Expected, from the standard.** Compile-time rejection. §13.18.38.3 SR1 b): the OCCURS clause 'shall not be specified in a data description entry that ... Has an occurs-depending table subordinate to it' (ALL FORMATS band), so G's Format 4 OCCURS is illegal.

**Observed.** Compiles with only a warning (COBOLNET1756); the run unit then aborts with NotImplementedCobolFeatureException. The same shape under a fixed `OCCURS 3` is rejected COBOLNET0854. This is the two-arm dispatch shape: ReferenceResolver.cs:1806 already knows 'a dynamic table IS an OCCURS dimension though its Occurs is null'. The fix is one 'is a table dimension' predicate for both arms, used by OdoResolve.

**Code site.** src/Cobol.Net.Compiler/Binding/DataBinder.Odo.cs#OdoResolve (the SR1(b)/SR10 ancestor loop, `if (a.Occurs is not null)`)

### Finding occurs-clause-p1 — §13.18.38.3 SR1 a) (under-rejects; rows SR-13.18.38.3-1)

**Mechanism.** The OCCURS clause's level-number restriction is enforced nowhere: a level-01 or level-77 entry carrying OCCURS compiles as a table

**Repro.** `01 A PIC X OCCURS 3.` or `77 A PIC X OCCURS 3.` in WORKING-STORAGE, `DISPLAY "OK"` (out13/probe/occurs-p1/sr1a_01.cob, sr1a_77.cob)

**Expected, from the standard.** Compile-time rejection: §13.18.38.3 SR1 a), 'The OCCURS clause shall not be specified in a data description entry that: a) Has a level-number of 01, 66, 77, or 88'.

**Observed.** Both compile clean and run. Levels 66 and 88 are refused, but through other rules (parse error / COBOLNET1747). A search of src for an OCCURS/level-number screen found none.

**Code site.** src/Cobol.Net.Compiler/Binding/DataBinder.cs (entry binding; no SR1 a) screen exists)

### Finding occurs-clause-p1 — §13.18.38.3 SR10 (under-rejects; rows SR-13.18.38.3-10)

**Mechanism.** The seven-subscript nesting limit is not enforced: an eight-dimension fixed table compiles and runs at every edition

**Repro.** `01 R. 02 A1 OCCURS 2. 03 A2 OCCURS 2. ... 09 A8 PIC X OCCURS 2.` (eight nested OCCURS) then `MOVE "Z" TO A8(1 2 1 2 1 2 1 2)` (out13/probe/occurs-p1/sr10_eight.cob; sr10_eight_85.cob at --std 85)

**Expected, from the standard.** Compile-time rejection: §13.18.38.3 SR10 allows nesting only 'as long as the number of subscripts required does not exceed seven', and §8.4.2.3.3 SR3 says the same ('This allows a maximum of seven subscripts to be specified'). docs/CONFORMANCE.md documents no extension.

**Observed.** Compiles and prints 'Z' at 2023 and at 85.

**Code site.** src/Cobol.Net.Compiler/Binding/DataBinder.Odo.cs#OdoResolve (checks only the DEPENDING half of SR10); no depth check anywhere in the data binder
