# PB4209 — SET names a rewritten ZERO by its rewritten text

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/SetBinder.cs:1309` (`SetBinder.BindSetTo`: `string senderText = amount.GetText();`),
`src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/SetBinder.cs:1365` (`SetBinder.BindSetTo`: `sender.Text` passed to `ScreenIndexAssignmentReceiver`),
`src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/SetBinder.cs:1416` (`SetBinder.IndexAssignmentSenderOf`: `string senderText = sender.Text;`),
`src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/SetBinder.cs:1492` (`SetBinder.BindSetUpDown`: `_fmt.ReportNoFormat(recvs, kinds, SetDirections.UpDown, amount.GetText())`).
The report cited lines 1484 and 1357 on its branch; these are the lines on main at 127843f92. Lines 554, 571, 661 and 810 also
print `sender.Text` in the pointer-sender arms; check each against the written text before changing it.

**The defect (a lead from the branch review, R1-2, low).** The SET diagnostics quote the arithmetic operand by its token text
(`amount.GetText()`, `sender.Text`). A bare figurative ZERO in an arithmetic slot is rewritten to the ZERO_ARITH token
(kb/Work PB3981, PB4120), whose text is `0`, so the message prints '0' where the programmer wrote ZERO. This is PB3961's class
(COBOL2119 spelled a rewritten ZERO as '0') in SET. It pre-dates PB3148 for `ZERO + 1`, but that branch makes it reachable for
every bare ZERO SET now admits (`SET IX UP BY ZERO`).

**Fix direction.** Name the operand as written, through the one helper PB3961 used (see kb/Work PB3961 for its name), at every
site above; add a golden whose refusal quotes `ZERO`. Sweep the other binders that print `GetText()` of an arithmetic
expression.
