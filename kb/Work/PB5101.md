# PB5101 - at --std 85 PERFORM VARYING ... AFTER augments the outer variable AFTER re-initializing the inner one (the 2023 order of PB436); 1985 augments the outer variable first and then sets the inner to its from-value, so the 1985 nest runs the other number of times

**Sites:** `docs/CONFORMANCE.md` (whole: the pin that applies the 2023 order at every edition, named by the record; the emitting member is not located, the record names none; PB436 names `EmitVarying`)

**Mechanism.** The compiler has ONE order for the two operations of a PERFORM VARYING ... AFTER step for every edition, the order `docs/CONFORMANCE.md` pins from the 2023 text under kb/Work PB436 ("the ISO text governs, at EVERY edition"). PB436 is landed and was written when the archive held no 1985 text. The 1985 text states the other order: when condition-2 is true the outer variable is augmented FIRST, THEN the inner variable is set to its from-value (which may be the outer variable, now augmented), then condition-1 is reevaluated. At --std 85 the compiler must follow the 1985 text, so the 1985 order is owed at --std 85 (and the per-edition differences recorded in docs/VERSION_CHANGE_REFERENCE.md). NIST NC201A PFM-TEST-F4-23 (six executions, recorded there as a CCVS defect) asserts the 1985 order.

**Found by.** The 1985 MATCH confirmation pass (kb/Work PB4995 item 3): each rule below is a corrected draft (a "redraft") that the compiler at `--std 85` still fails (redraft_run MISMATCH). Harm and observed text are the records; nothing here was re-derived.

**Inventory.** The traceability inventory carries no 1985 rows yet (PB5094: work.py refuses 1985 ids), so `inventory_rows` is empty; the rows this note covers are the 1985 rule ids listed below (catalog `docs/rearchitecture/spec-rule-catalog-1985.json`).

**Rules (1; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-GR-VI.6.21.4-10` - `§1985:VI.6.21.4 GR10` (record harm: wrong-answer, slice-08): "the content of the data item referenced by identifier-5 is set to literal-3 or the current value of the data item referenced by identifier-6" (item d 1, after "the content of the data item referenced by identifier-2 is augmented by literal-2 or the content of the data item referenced by identifier-4"; Figure 2 draws the same order). The corrected draft covers a, b (zero and negative), c (TEST BEFORE true at entry, TEST AFTER) and d, and mismatches only in d. Every other line matched.

**Repro (`1985-GR-VI.6.21.4-10`, slice-08).** cobol.exe p27r.cob --std 85 --source-format fixed --flag-extensions -o p27r.dll; dotnet p27r.dll

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. PERFORD.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  I    PIC 9  VALUE 0.
       01  J    PIC 9  VALUE 0.
       PROCEDURE DIVISION.
       MAIN-PARA.
           PERFORM SHOW-IJ
               VARYING I FROM 1 BY 1 UNTIL I > 2
               AFTER J FROM I BY 1 UNTIL J > 2.
           DISPLAY "END " I " " J.
           PERFORM SHOW-IJ WITH TEST AFTER
               VARYING I FROM 1 BY 1 UNTIL I = 2
               AFTER J FROM I BY 1 UNTIL J = 2.
           DISPLAY "END " I " " J.
           STOP RUN.
       SHOW-IJ.
           DISPLAY "I=" I " J=" J.
```

**Expected (from the 1985 text).** For the first nest (`PERFORM SHOW-IJ VARYING I FROM 1 BY 1 UNTIL I > 2 AFTER J FROM I BY 1 UNTIL J > 2`) the 1985 text requires `I=1 J=1 / I=1 J=2 / I=2 J=2 / END 3 3` (I is augmented to 2, then J is set to the current value of I). The deciding words: "the content of the data item referenced by identifier-5 is set to literal-3 or the current value of the data item referenced by identifier-6" (§1985:VI.6.21.4 GR10).

**Observed (copied from `1985-GR-VI.6.21.4-10`).** Expected by the 1985 text, for PERFORM ... VARYING I FROM 1 BY 1 UNTIL I > 2 AFTER J FROM I BY 1 UNTIL J > 2: I=1 J=1 / I=1 J=2 / I=2 J=2 / END 3 3 (I is augmented to 2, then J is set to the current value of I). Observed at --std 85: I=1 J=1 / I=1 J=2 / I=2 J=1 / I=2 J=2 / END 3 2: J is reset from I before I is augmented, one extra execution of the set and a final J that is not I. The TEST AFTER arm of the same repro is right (I=1 J=1 / I=1 J=2 / I=2 J=2 / END 2 2). --std 2023 prints the same four lines: the compiler has one order for every edition, the one docs/CONFORMANCE.md pins from ISO 2023 14.9.28.4 GR13 e) 2 under kb/Work PB436 ("the ISO text governs, at EVERY edition"), written when the archive held no 1985 text; NIST NC201A PFM-TEST-F4-23 (six executions, recorded there as a CCVS defect) asserts the 1985 order. Every other line of the redraft matched.
