# PB3464 — the slice reservation reads RUNNING for a finished slice branch

> ⚙ **flags:** process-only

Source: the PB3456 branch review, round 1, finding R1-1 (a LEAD, info, not blocking; report
`E:\COBOL-coord\scratch\reports\w1132z-PB3456-report.md`, "Review findings"; PR #329).

**Site:** `scripts/orchestrator/plan_wave.py` `classify_inflight` (line ~740 on branch
`fix-pb3456-slice-reservation-20261020`, PR #329). The site is on that branch, not necessarily on `main` until
PR #329 merges; this note's fix lands with or after it.

**Finding.** `classify_inflight` labels the slice reservation RUNNING, naming the carrier, whenever any
non-reservation owner holds a slice note, including a FINISHED slice branch (WAITING FOR REVIEW, WAITING TO LAND,
ENQUEUED). The docstring promises RUNNING only once another owner is working on a slice. The hold itself is correct:
an unlanded slice still changes its files. Only the operator-facing word is wrong.

**Failure scenario.** A slice branch is finished and waiting for review or to land. The plan prints the campaigns it
holds as "in-flight work ... [RUNNING]". The operator reads RUNNING, concludes work is still in progress, and waits
on work that is done, when the action that releases the hold is a review or a landing.

**Fix direction.** RUNNING only when the slice owner is IN FLIGHT. A finished owner reads its own lifecycle word
(WAITING FOR REVIEW / WAITING TO LAND / ENQUEUED), as `classify_inflight` already derives for other owners. Add a
`test_plan_wave.py` case per lifecycle state pinning the word, and keep the hold unchanged.
