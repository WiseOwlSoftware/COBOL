# PB5427 landed (wave 20262038 group F)

**Re-probe (Debug build of this branch, before the fix).** `u2.cob` compiled and ran at 85 and 2023; the same programs now draw `COBOL7282` at `EXR` (the item subordinate to `OTHER-EXT`) at both editions, `u5.cob` likewise.

**Root cause.** The rule has a GLOBAL half (one source element, `DataBinder.ScreenGlobalNameUniqueness`) and an EXTERNAL half that compares source elements; the pass that holds the first sees one unit's forest, so the second had no home. It is now `ExternalRecordNameRules.Check`, run at the end of the group bind over every program (and, from COBOL-2002, every class object and factory half) of the group: an item subordinate to an external record (or an external FD's record) that spells the name of an external record is refused. Reach: 85 compares a program with its containers and containees (and itself); 2002 and later compare the whole group (the run unit, `§2023:8.4.2.1`).

**Not claimed.** The reader's open question whether the GLOBAL half must reach names subordinate to a GLOBAL record (`u3`) is untouched; the 1985 row stays PARTIAL for it.

**Goldens.** `pb5427-external-record-name-reused-nested` (refused 85/2002/2014/2023), `pb5427-external-record-name-shared-legal` (accepted at 85, prints `Q`), `pb5427-external-record-name-reused-sibling` (refused 2002 to 2023), `pb5427-external-record-name-reused-sibling-85` (accepted at 85).
