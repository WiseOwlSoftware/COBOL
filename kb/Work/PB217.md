# PB217

Found by the cluster-B review fleet on the pre-commit [[PB169]]–[[PB172]] tree, 2026-08-31. [[PB169]]'s new SR2
screen opened

    if (p is RefModPlace || p.Item.IsGroup) return false;
    if (p.Item.Pic is not { } pic) return false;

**MEASURED, with the guard temporarily restored on the fixed tree** (`--std 2023`, strict):

    01 WS-D PIC X(3) VALUE "007".         STOP RUN WITH ERROR STATUS WS-D(2:2).
      -> error COBOLNET1704: "… shall reference an integer data item or a data item with usage display or usage
         national (ISO §14.9.42.3 SR2 …)"   — quoting the rule the operand SATISFIES
    01 GNAT GROUP-USAGE IS NATIONAL. 05 GNAT-A PIC N(3) VALUE N"012".
                                          STOP RUN WITH ERROR STATUS GNAT.        -> the same COBOLNET1704

**THE SPEC ADMITS BOTH.** Every citation `cite.py --check`ed:

  * §8.4.3.3.3 SR5 — "Unless otherwise specified, reference modification is allowed anywhere an identifier
    referencing a data item of class alphanumeric, boolean, or national is permitted."
  * §8.4.3.3.4 GR6 — "The unique data item has the same class, category, and **usage** as that defined for
    identifier-1, except that: (a) … alphanumeric-edited … (b) … national-edited … (c) the categories numeric
    and numeric-edited are considered class and category national if the usage is national; otherwise they are
    considered class and category alphanumeric." The three exceptions rewrite CLASS and CATEGORY only — never
    USAGE. So SR2's SECOND alternative ("a data item with usage display or usage national") decides a slice, and
    its FIRST cannot: GR6 c has already removed category numeric, which `RefModPlace.Category` — THE ONE GR6
    reader — records as "No ref-mod result is ever category NUMERIC".
  * §13.18.29.3 SR3 — "When the NATIONAL phrase is specified, USAGE NATIONAL is implied for the subject of the
    entry"; §13.18.29.4 GR2 b — a national group "is treated as though it were an elementary data item of usage
    national and class and category national described with PICTURE N(m)". It IS "a data item with usage
    national".

**⛔ AND IT IS AN IN-REPO DOCTRINE VIOLATION, NOT ONLY A SPEC MISREADING — which is what makes the fix
structural instead of two hand-added exceptions.** `DataItem.OperandPic`'s own doc comment reads: "⛔ THE ONE
READER for an item's OPERAND category (D20) … Every site that decides class, category, a Table 16 row, LENGTH
positions, ref-mod admissibility, comparison class or string-operand-ness reads THIS — **never `Pic` guarded by
`IsGroup`** — so a GROUP-USAGE group is a boolean / national operand everywhere at once." `AdmittedStatusItem`
was exactly `IsGroup` followed by `Pic`. The screen's doc comment justified the group exclusion with "§8.5.2.1
gives it class alphanumeric with no elementary description" — true of the ALPHANUMERIC group it was written for
and false of the other two group kinds. It was the wrong READER, not a missing exception.

**FIXED BY:** reading `p.Item.OperandPic` and adding an explicit `RefModPlace` arm that asks GR6's preserved
USAGE. That settles all four group kinds and both slice kinds with no hand-list:

  | shape | OperandPic | verdict | rule |
  |---|---|---|---|
  | alphanumeric group | null | rejected (unchanged) | §8.5.2.1 — no elementary description |
  | GROUP-USAGE NATIONAL group | `(National, Usage.National, …)` | **admitted (new)** | §13.18.29.4 GR2 b |
  | GROUP-USAGE BIT group | `(Boolean, Usage.Bit, …)` | rejected | SR2 names neither |
  | ref-mod of a display/national item | usage preserved | **admitted (new)** | §8.4.3.3.4 GR6 |
  | ref-mod of a usage-BIT item or an alphanumeric group | Bit / null | rejected | SR2 names neither |

**MEASURED AFTER**, values derived first: `WS-D(2:2)` on `"007"` ⇒ "07" ⇒ exit 7; `WS-NUM9(2:2)` on
`PIC 9(4) VALUE 1234` ⇒ the character positions 2–3 "23" ⇒ exit 23 (§8.4.3.3.4 GR2 redefines a display-usage
numeric subject as alphanumeric OF THE SAME SIZE for the slice); the national group `N"012"` ⇒ 12; the bit group
still COBOLNET1704.

⚠ **Regression posture:** the STRICT lane is a RESIDUAL, not a regression — on HEAD `9a89fbd1`
`BindTerminationStatus` bound the operand through `host.Expr.BindExpr`, and a `RefModPlace` never survived the
§8.8.1.1 screen, so the same source already drew COBOLNET0844. What the wave changed is the EPISTEMIC status:
the exclusion became a written position rule under a citation that in fact admits both shapes, which reads as an
adjudicated determination and hides the gap. The `--permissive` lane DID harden (0844 was a warning-and-accept
there, 1704 is an Error in both lanes) — that half is a genuine, if narrow, regression, and it is what this note
closes.
