# PB2514 — one gate cap, read from one place

The owner raised the implementer gate cap to 3 until Saturday 2026-10-10 10:00 PDT (2026-10-07 14:10, after the w1033
capacity survey: gates waited 62 % of gate wall time at cap 1). The cap is `COBOLNET_GATE_SLOTS`, read by each gate
process from its OWN environment (`scripts/gate_slot.py#configured_slots`). The orchestrator loop was restarted with
the variable set to 3; the attended operator session's own agents inherit the session's environment, which has no
variable, so their gates run with the default 1.

## Observed (2026-10-07 16:13 PDT, `COBOLNET_GATE_SLOTS=3 python scripts/gate_slot.py status`)

    slot 1: HELD by implementer gate …\agent-a7ff5e6502d991173 (since 15:50:14)
    slot 2: HELD by implementer gate …\wf_3fe29228-bf0-1 (since 15:58:26)
    slot 3: free
    ticket 446: waiting — implementer gate …\adj-1033 (since 15:59:21)          ← started with cap 1
    ticket 447: waiting — implementer gate …\wf_3fe29228-bf0-4 (since 16:06:30) ← cap 3
    ticket 448: waiting — implementer gate …\wf_3fe29228-bf0-6 (since 16:12:41) ← cap 3

The head ticket can take only slot 1, the queue is FIFO, so slot 3 idles while two gates that could use it wait.
`gate_slot.py status` without the variable also shows only slot 1, which hid the other holders from the operator.

## Shape (rule 4: one rule in one place)

The cap is a property of the SLOT DIRECTORY (the shared `.git/cobol-gate-slots`), not of each process: one writer
(`gate_slot.py set-cap N [--until ISO]`, recording who and why, with an optional expiry so a temporary raise reverts
itself), every gate and `status` reads it there; `COBOLNET_GATE_SLOTS` is deleted (no fallback, no alias). A self-test
plants two gates with different expectations and shows no head-of-line block. Update the gate skill, MANDATORY-PRACTICES
I1/I2 and plan §9 where they name the variable.

## Landed (wave 1033 group V, 2026-10-07, branch `gate-batch`)

Re-probed first on the live slot directory (16:3x PDT): `gate_slot.py status` without the variable showed `1 of 1
slot(s) held`, with `COBOLNET_GATE_SLOTS=3` it showed `3 of 3` — two running gates hidden by the reader's own N.

- `scripts/gate_slot.py#GateSettings` is the ONE place the cap lives: `<git common dir>/cobol-gate-slots/settings.json`,
  written only by `gate_slot.py set-cap N [--until ISO] [--why TEXT] [--by TEXT]` (validated, under `settings.lock`,
  replaced atomically, recording who, when and why) and read by every gate and by `status`. An expiry is an ISO time
  with its UTC offset (a naive one, one already past, and a cap below 1 are refused); once it passes, `DEFAULT_SLOTS`
  (1) is in force again with no one acting. A malformed file stops a gate (`NOT RUN`, exit 2) with the reason.
- `GateSlots.acquire` re-reads the cap on EVERY poll, so all waiters apply one cap at one moment and a raise reaches
  the queue at once; `GateSlots` no longer takes a count. `state()`/`status` probe EVERY slot file, so a slot held
  above a lowered cap is shown (marked as such), and `status` prints the cap and the scope with who set them.
- `COBOLNET_GATE_SLOTS`, `configured_slots` and the `--slots` options are DELETED, no fallback. Callers changed:
  `run_gate_legs.py`, `scripts/spec/record_impact_map.py`. `status` now writes UTF-8 (its em dashes printed as replacement
  characters on the cp1252 console — found while re-probing, fixed here).
- Self-test: 8 arms (was 5); the three new ones — the shared cap (a gate at the head under cap 1 and one behind it
  both take a slot the moment `set-cap 3` is written from a LINKED worktree, the first holder still on slot 1), the
  expiry and the refusals, and `status` showing every held slot — were each seen RED on a planted defect (the cap read
  once per process: `no line matching /gate-slot: took slot 2 of 3/`; `status` probing `range(cap)`: `status hid a
  holder`). `GateSlotDriftTests` asserts all eight by name.
- Docs: DESIGN-test-build-ci section 3.14.6, plan section 9, DOC_INDEX, the gate skill, MANDATORY-PRACTICES I1.

OPERATOR STEP at landing (once, in the shared slot directory): `python scripts/gate_slot.py set-cap 3 --until
