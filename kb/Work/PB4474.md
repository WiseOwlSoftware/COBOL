# PB4474 - residue of the PB4462 semgrep finish

**Where the code is.** Branch `worktree-wf_ec0327b7-bfd-15` (worktree `E:\COBOL\.claude\worktrees\wf_ec0327b7-bfd-15`, head `d13bd499f`); PB4462
is still open on origin/main, so all four are read on the branch. The branch was BLOCKED at enqueue on an `InheritStep.cs` conflict
and has not landed.

1. **Tempered prefix (R1-2).** `scripts/semgrep/invariants.yml:120`, the `pattern-regex` of the diagnostic-code rule:
   `(?m)^(?:(?!//)[^\n])*?(?:...Emit\(...|\.(?:Error|Warning|Report)\()\s*"COBOL\d{4}"`. The prefix `(?:(?!//)[^\n])*?` excludes any
   line with `//` before the match, so `var url = "http://x"; Emit(Severity.Error, "COBOL1234"` is not seen. No product line has the
   shape today. The same tempered prefix is at lines 52 and 85 (the other two `pattern-regex` rules with `(?!//)`). Fix: strip
   `//` comments from the matched text structurally, or anchor the exclusion on a `//` outside a string (a small lexer is not a regex's job
   and semgrep has no comment-aware pattern-regex; a `pattern-not-regex` on the comment form is the available tool).
2. **The `Unparsed.cs` control (R1-3).** `scripts/semgrep/verify.py:237` (check 1) fires each rule in `scripts/semgrep/testdata/Unparsed.cs`, which
   semgrep reads only in part (unreadable spans are lines 14 and 22 only), and the control passes when a newer semgrep reads the file
   in full (it prints a NOTE and still PASSes). The control therefore proves less than `invariants.yml:18` says. A stronger control needs
   per-rule unreadable constructs, or a check that the unreadable set is non-empty so a semgrep that fixes the grammar flags the control
   as obsolete instead of passing.
3. **Stale docstring (R2-1).** `scripts/arch/r2_inputs.py:15` still reads "mech/semgrep.json ... hits by file"; `run_semgrep` now caches
   `{"hits": {file: [...]}, "unread": [files]}` and the shard input gained `semgrep_unread`, which the WHAT list does not name.
