## Measured

### Finding type-clause-p2 — 13.18.57.4 GR1 (with 13.18.58.4 GR3; 13.18.57.4 GR4 read correctly) (rejects-legal-source; rows GR-13.18.57.4-1)

**Mechanism.** TYPE composition drops the template's BASED clause: DataItem.IsBased is classified DescriptionCopyKind.None (its reason misreads 13.18.57.4 GR4 as 'the template's BASED is never carried'), so CopyEntryDescription never transfers it, although BASED is in neither GR1 exclusion list and 13.18.58.4 GR3 hands 'all other data description clauses' to data defined with the type-name. A subject without its own BASED over a BASED TYPEDEF becomes ordinary storage.

**Repro.** E:/Temp/claude/E--CobolSharp/a700c052-f9e4-4942-84ff-a13c7505d6ec/scratchpad/adj-d1/out13/probe/type-clause-p2/t2.cob (--std 2023): `01 T TYPEDEF BASED PIC X(5). 01 X TYPE T. 01 Y PIC X(5) VALUE "HELLO".` then `SET ADDRESS OF X TO ADDRESS OF Y. DISPLAY X.`

**Expected, from the standard.** X is a based item (13.18.57.4 GR1: as though type-name-1's description were coded in place, excluding only level-number, name, alignment, GLOBAL, SELECT WHEN, TYPEDEF; 13.18.58.4 GR3); the SET is legal and DISPLAY shows HELLO; before any SET, a reference raises EC-DATA-PTR-NULL (13.18.5.4 GR3). GR4 governs only the case where the subject writes its own BASED.

**Observed.** COBOLNET0869 "'X': the operand shall be a BASED level-01/77 item" -- the program is refused. The subject-own-BASED case (t3.cob) works.

**Code site.** src/Cobol.Net.Compiler/Binding/Model/DataItem.cs#IsBased (DescriptionCopy(None, ...GR4...)); src/Cobol.Net.Compiler/Binding/DataBinder.cs#CopyEntryDescription

### Finding type-clause-p2 — 13.18.57.4 GR3 (second sentence), 13.16.3 SR9 (wrong-answer; rows GR-13.18.57.4-3)

**Mechanism.** The template's VALUE-implied PICTURE (13.16.3 SR9) is lost whenever the TYPE subject writes its own VALUE: BindPipeline runs ExpandTypes BEFORE SynthesizeImpliedPictures, so at copy time the template has no Pic to copy; SynthesizeImpliedPictures then implies the SUBJECT's picture from the SUBJECT's own literal. The same order affects any SAME AS subject with an own VALUE over a picture-less VALUE-implied target (sibling to sweep).

**Repro.** E:/Temp/claude/E--CobolSharp/a700c052-f9e4-4942-84ff-a13c7505d6ec/scratchpad/adj-d1/out13/probe/type-clause-p2/t4.cob (--std 2023): `01 U TYPEDEF VALUE "ABCD". 01 W TYPE U VALUE "Q".` `DISPLAY "[" W "]" FUNCTION LENGTH(W)`; and E:/Temp/claude/E--CobolSharp/a700c052-f9e4-4942-84ff-a13c7505d6ec/scratchpad/adj-d1/out13/probe/type-clause-p2/t5.cob: `01 U TYPEDEF VALUE "AB". 01 W TYPE U VALUE "QRSTUV".`

**Expected, from the standard.** 13.18.57.4 GR3: U's implicit PICTURE X(4) 'becomes part of the description of the subject', so W is PIC X(4) holding "Q   " and LENGTH(W) = 4; in t5, W is PIC X(2) and the 6-character VALUE literal exceeds it, a 13.18.63.3 size violation the compiler must reject.

**Observed.** t4 prints [Q] and LENGTH 1 (W was given PIC X(1) from its own literal); t5 compiles and prints [QRSTUV]. Without an own VALUE (V TYPE U) the result is right, because the copied VALUE then implies the same picture.

**Code site.** src/Cobol.Net.Compiler/Binding/Passes/BindPipeline.cs#Build (pass order ExpandTypes -> SynthesizeImpliedPictures); src/Cobol.Net.Compiler/Binding/DataBinder.cs#CopyEntryDescription (to.Pic copied only if from.Pic not null)

### Row GR-13.18.49.4-3 — PARTIAL (no separate finding; the adjudicator's / refuter's record)

Code location: `src/Cobol.Net.Compiler/Binding/DataBinder.cs#ExpandSameAs; src/Cobol.Net.Compiler/Binding/DataBinder.cs#ApplyEffectiveUsage`

GR3 (--check 13.18.49.4 -> OK 3)). ExpandSameAs walks data-name-1's ancestors for the nearest OwnUsage when the subject has none, and applies it through the shared ApplyEffectiveUsage, carrying WITH NO SIGN. Alphanumeric group: p07 (G USAGE COMP-5 -> S BYTE-LENGTH 2), p23 (PACKED-DECIMAL -> 3 bytes, -00345), pb646 golden (SAMES under GSGN USAGE NATIONAL -> SLEN=4 8, spec-derived), pb570 golden (NO SIGN via SAME AS). Strongly-typed group: q01 (TYPEDEF STRONG USAGE COMP-5, S SAME AS X OF R -> 2 bytes). The walk does not filter the group kind, but a national/bit group cannot hold an explicit USAGE other than its own implied one (§13.18.29.3 SR2/SR3), so no observable over-application. || REFUTED: PARTIAL — GR3 transfers a USAGE clause only from an ALPHANUMERIC or STRONGLY-TYPED group containing data-name-1; the ExpandSameAs ancestor walk takes the nearest OwnUsage of ANY group kind. The adjudicator's premise ('a national/bit group cannot hold an explicit USAGE') holds only for the entry carrying GROUP-USAGE (13.18.29.3 SR3); a SUBORDINATE group inside a national group is implicitly GROUP-USAGE NATIONAL (a national group, 13.18.29.4 GR2a/GR3) and may carry an explicit USAGE NATIONAL. The compiler transfers it: S SAME AS E under `05 H USAGE NATIONAL` inside `01 G GROUP-USAGE NATIONAL` gets BYTE-LENGTH 6, while the identical E2 directly under a GROUP-USAGE NATIONAL group gives S2 BYTE-LENGTH 3 (the literal reading the adjudicator itself accepted). Same description of data-name-1, two answers; GR3's group-kind filter is not implemented.
