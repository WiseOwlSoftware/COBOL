# PB82 — OPEN — `error COBOLNET1639: 'UNDEFINED-ITEM' is not defined …` names no file, no line, no column

> ⚙ **flags:** usability (a MAJOR user-facing gap, not a conformance divergence) · found 2026-08-18 landing PB63
> (EXCEPTION-LOCATION's "identifier of the source line", RV-15.31.3-L2.3).

**Measured** (`scratchpad/p62/cpyline.cob`, `--std 2023`): a 10-line program with `COPY "P63CPY.cpy".` on line 6
(three copied 01 lines) and `MOVE UNDEFINED-ITEM TO W` on SOURCE line 9 prints
```
  error COBOLNET1639: 'UNDEFINED-ITEM' is not defined - no declaration in this source element gives the name …
```
— no `cpyline.cob(9,…)` prefix at all. Only PARSE-layer diagnostics (COBOL0001/0307 …) carry `file(line,col)`.
And where a line IS reported (the parser; `FUNCTION EXCEPTION-LOCATION`'s third field; RAISE/EC bookkeeping) it is
the ANTLR token line of the RESULTANT text after COPY/REPLACE expansion (§7.2), not a line of the file the user
edits: PB63's probe with a 3-line COPY on line 6 and RAISE on source line 9 reports 14.

**Mechanism:** `Binding/EditionContext.Error/Warning` append bare `"error CODE: message"` strings — the ~160 bind
sites pass no location and the channel accepts none. `EcBinder.EcWrap/BindRaise` and `ProcedureTableBuilder` read
`ctx.Start.Line` from the token stream; the preprocessors (`Preprocessor/CopyProcessor.cs`, REPLACE, the directive
processors) rewrite text without keeping an origin map, so no later stage can recover a source line.

**Fix shape (two halves, one mechanism each):** (1) a STATEMENT/ENTRY CURSOR on the binder context — the
StatementBinder / DataBinder set the current parse context as they walk, and `EditionContext.Error/Warning` stamp
`{file}({line},{col}): ` from it AUTOMATICALLY, so no bind site changes and a new site cannot forget (the CLI and
`CompilerDriver.Result` already print the string); (2) an ORIGIN LINE MAP built by the preprocessing chain (each
resultant line → (source file, source line), COPY nesting included — the `#line`-style table) consulted by every
consumer of `Start.Line`: the parser's diagnostic positions, the cursor of (1), and EXCEPTION-LOCATION's third
field (whose CONFORMANCE.md determination — the resultant-text ordinal — is then revised to the source line; the
§15.30.3 r2b3 NOTE permits either). Drift guard: a golden compiling a program with a COPY and an error after it,
asserting the SOURCE line in the message.
