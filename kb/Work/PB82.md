# PB82 — LANDED — `error COBOLNET1639: 'UNDEFINED-ITEM' is not defined …` names no file, no line, no column

> ⚙ **flags:** usability (a MAJOR user-facing gap, not a conformance divergence) · found 2026-08-18 landing PB63
> (EXCEPTION-LOCATION's "identifier of the source line", RV-15.31.3-L2.3) · **landed 2026-08-18** (DEVLOG 1316).

**Measured** (`scratchpad/p62/cpyline.cob`, `--std 2023`): a 10-line program with `COPY "P63CPY.cpy".` on line 6
(three copied 01 lines) and `MOVE UNDEFINED-ITEM TO W` on SOURCE line 9 prints
```
  error COBOLNET1639: 'UNDEFINED-ITEM' is not defined - no declaration in this source element gives the name …
```
— no `cpyline.cob(9,…)` prefix at all. Only PARSE-layer diagnostics (COBOL0001/0307 …) carry `file(line,col)`.
And where a line IS reported (the parser; `FUNCTION EXCEPTION-LOCATION`'s third field; RAISE/EC bookkeeping) it is
the ANTLR token line of the RESULTANT text after COPY/REPLACE expansion (§7.2), not a line of the file the user
edits: PB63's probe with a 3-line COPY on line 6 and RAISE on source line 9 reports 14. **Also found while landing:**
the parse-layer position itself was one line LATE (`CobolErrorListener` passed ANTLR's 1-based line into the
0-based `SourceLocation`), the fixed-form continuation gates had the same off-by-one, the CC directive diagnostics
reported an index into whatever text was being rendered (a copybook's directive named the copybook's ordinal against
the main file's name), and the NIST archive-marker strip DROPPED lines.

**Mechanism (as found):** `Binding/EditionContext.Error/Warning` appended bare `"error CODE: message"` strings — the
~160 bind sites pass no location and the channel accepts none. `EcBinder.EcWrap/BindRaise` and
`ProcedureTableBuilder` read `ctx.Start.Line` from the token stream; the preprocessors rewrote text without keeping
an origin map, so no later stage could recover a source line.

## As built (DEVLOG 1316) — two halves, one mechanism each

1. **The ORIGIN LINE MAP** — `Frontend/Common/SourceLineMap.cs`: `SourceOrigin(File, Line)`, `MappedText`
   (text + one origin per `Split('\n')` piece — the invariant its constructor asserts), `OriginWriter` (an output
   line piece takes the origin of the FIRST content written into it) and `SourceLineMap` (resultant line →
   origin; `Locate` = the ONE conversion to a 0-based `SourceLocation`). Every line-count-changing stage is
   MAPPED and its string overload is the mapped one's `.Text` (ONE implementation each): the fixed→free
   normalizer (a continuation join REOPENS the head line's origin), the merged CC+COPY driver (`Render(MappedText)`,
   `ExpandCopiesOneLevel(MappedText)`, `NormalizeCopybookMapped`, `ApplyReplaceStatements/ApplyReplacements`
   mapped — the legacy `ExpandCopyStatements` is now the one-level expander fed with itself), and the archive-marker
   strip blanks instead of dropping. `Frontend.Preprocess` returns the `MappedText`, publishes `Frontend.LineMap`,
   asserts every later stage (NIST substitution, the six directive stages) is line-count preserving, and hands the
   map to the parser listener, the directive stages' diagnostics and (via `CompilerDriver`) the binder.
2. **The DIAGNOSTIC CURSOR** — `IDiagnosticSink.Cursor` (a default no-op member; `DiagnosticCursor(Line, Column)` in
   RESULTANT space) positioned with `using var _ = sink.At(…)` (`Editions/DiagnosticCursor.cs`; the parse-context /
   token / `DataItem` forms in `Binding/DiagnosticCursorAt.cs`). `EditionContext` implements it for real: `Error`
   and `Warning` stamp `{file}({line},{col}): ` AUTOMATICALLY through `OriginOf` (the map, else identity on
   `SourceFile`); no cursor ⇒ bare (never a fabricated line). Set points: `StatementBinder.BindStatement` (every
   statement, nested restore), `DataBinder.BindEntries` (every entry) + the FD/SD/SELECT/I-O-CONTROL/SPECIAL-NAMES/
   OBJECT-COMPUTER/RD/report-group/USING-parameter loops, `ProcedureTableBuilder` (declarative sections, procedure
   units), the post-build model passes through `DataItem.DeclaredAt` (captured from the cursor at construction),
   and the two parse-tree passes through `Validation/CursorFollowingVisitor` (the cursor follows the walk).
   `EcLocation` and the bound tree's `SourceLine` fields (`BinderContext.SourceLine(ctx)`) map ONCE at production;
   the TURN / FLAG / REF-MOD-ZERO-LENGTH anchors stay in resultant space by design.

**Determination revised** (docs/CONFORMANCE.md §4): EXCEPTION-LOCATION's third part is the line in the file that
PHYSICALLY holds the statement — a bare number for the main source, `copybook-name(line)` for copied text.

**Drift guards:** `2023/pb82_exception_location_source_line` (COPY + REPLACE + continuation before each RAISE, a
RAISE inside a procedure copybook), `DiagnosticPositionTests` (parse line, bind file(line,col), COPY main/copybook,
REPLACE, continuation, NIST marker, the edition gate, the bare no-cursor form), `SourceLineMapTests` (the map
primitives, the join, COPY/REPLACE origins, the cursor prefix + restore).

**Found on the way, registered:** [[PB93]] (REDEFINES of an undefined data-name accepted silently), [[PB94]] (VALUE
literal category vs subject not enforced — an alphanumeric VALUE on a numeric item reaches Roslyn).
