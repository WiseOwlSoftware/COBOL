# PB2878 — a fast lane for changes no test reads

Owner, 2026-10-09 ~10:30 PDT, on a one-change train that edits only a practices file and two briefs: "Should this
require a full CI run? I would think not."

## Why it does today

- `main` requires the `ci-gate` status with `enforce_admins` on (owner decision 2026-09-06, PB796): every commit needs
  a green CI run; nothing skips it without changing the server-side rule.
- In this repo "docs" are often test INPUTS: `check_practices.py` reads MANDATORY-PRACTICES.md and the brief templates;
  drift tests read DOC_INDEX.md, CONFORMANCE.md and the inventory; `work.py check` validates kb/Work; the landing
  check reads the DEVLOG. A change that touches only such files can still turn CI red.
- Cost: CI runs on GitHub (~10 min wall, no Claude quota); the local gates cost CPU and wall time (~6 min with PB2877's
  concurrency). The quota cost of a landing is the orchestrating turns, not the gates.

## What closes it (design first; rule 5)

1. Classify every tracked path as READ BY A TEST / AUDIT or INERT, mechanically (the tests' and scripts' file reads,
   e.g. from a traced run or a declared manifest), with a drift test that fails when a test starts reading an INERT path.
2. A landing whose changed paths are all INERT runs only the audits job in CI (self-tests, work.py check) and, locally,
   the same reduced gate (the CI invariant, PB1957: one classification used by both).
3. Branch protection keeps requiring `ci-gate`; the reduced run reports it. Measure how many of a week's landings
   would qualify before building it.

## Part 1 (wave 20261026 B, branch worktree-wf_0e51b14b-ced-2)

`changes` job (its doc-only regex deleted), the local gate (`run_gate_legs.py`: an inert change runs the audits and
ends GREEN, no slot, build or leg) and the landing's Linux gate; its proof, an inotify watch around every Linux

sweep, so INERT is `DEVLOG/` alone, and no landing of that week qualifies yet.
