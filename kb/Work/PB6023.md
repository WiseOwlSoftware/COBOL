# PB6023 - the argument constraints are code, not descriptor data; the 1985 messages speak 2023

**What PB6019 did.** Every run-time breach of an intrinsic argument rule now takes ONE path: `ExceptionEngine.ArgumentError` (and its
two text twins) reads the activation's edition (`ICobolProgram.ArgumentBreachTerminates`, installed by `ProgramTable`) and at COBOL-85
terminates the run unit (§1989:A.2.2 p3, §1993:p.B-46); from 2002 it raises EC-ARGUMENT-FUNCTION. `ArgumentBreachEditionTests.
EveryBreach_TakesTheOnePath` refuses a bypass. What a breach DOES is therefore one mechanism.

**What is still per function (1).** The DETECTION of each value constraint is hand code in the function's runtime body, about 80 call
sites of `ArgumentError*` across `CobolIntrinsics*.cs`, `CobolDate.cs`, `CobolLocale.cs` and `CobolTable.cs`, on five carriers (long,
Int128, CobolDec, double, CobolExact). The controller's design for PB6019 (brief w20262131 group r) asked for the constraints as data on
each function's descriptor (`IntrinsicArgumentRules`' rows), checked by one emitter, with a drift test that every AR rule with a value
constraint has an entry. Not done in PB6019, because the kinds are not all data: beside the ranges (FACTORIAL >= 0, RANDOM >= 0, ANNUITY
rate >= 0 and periods > 0, PRESENT-VALUE > -1, ACOS/ASIN in [-1, 1], LOG > 0, SQRT >= 0, MOD/REM divisor non-zero, YEAR-TO-YYYY,
DATE-TO-YYYYMMDD, DAY-TO-YYYYDDD) there are calendar validity (INTEGER-OF-DATE month and day, INTEGER-OF-DAY ordinal), the
collating-sequence size (CHAR, which only the run time's PCS knows), text grammars (NUMVAL, NUMVAL-C, the FORMATTED-* formats,
CONVERT's hex), locale content, and the ALL-subscript count. A descriptor kind per family and an emitted check before each call would
move every one of those out of the bodies that compute on the value, and the bodies' own guards would then be unreachable twins. Decide:
(a) descriptor kinds for the range family only, emitted by one `RuntimeApi.RequireArgument` per carrier, with the bodies' range guards
deleted and a drift test over the 1989 and 2023 AR rows that state a numeric range; or (b) keep detection in the bodies and make the
drift test read the bodies' raise sites against those rows (each range AR row has a raise site citing it). Either makes the next
function's constraint automatic in a way the one-path test alone does not.

**What is wrong at 85 (2), the user-visible half.** The messages of about fifteen of those sites cite the 2023 clause at `--std 85`:
`FACTORIAL argument -4 violates §2023:15.36.3 rule 1`, `SQRT argument-1 shall be greater than or equal to zero (ISO §2023:15.84.3 rule
2)`, likewise LOG, LOG10, ACOS, ASIN, MOD, REM, ANNUITY, PRESENT-VALUE, RANDOM, CHAR, NUMVAL, NUMVAL-C; DATE-OF-INTEGER, DAY-OF-INTEGER,
INTEGER-OF-DATE and INTEGER-OF-DAY already cite §1989 at 85. The ArgumentError suffix PB6019 added cites §1989:A.2.2 p3 and
§1993:p.B-46, so the termination itself is attributed correctly; the function's own rule is not. A descriptor entry carrying both
editions' clauses (option (a)) fixes this structurally; otherwise each site takes the edition's clause as `NotAnIntegerArgument` now
does. Repro: `E:/COBOL-coord/scratch/w20262131r/sweep/*.cob` at `--std 85` (each prints its message on termination).

**A sibling outside the intrinsics (3).** At `--std 85` a reference modification of length 0 (`X (1 + N:N)`, N = 0) terminates with
`EC-BOUND-REF-MOD (fatal): reference modification (1:0) out of range ... (ISO §2023:8.4.3.3.4 item 5c)`: the message names an exception
condition and a 2023 clause in an edition that has neither. Repro `E:/COBOL-coord/scratch/w20262131r/sweep/LENZ.cob`; site the
ref-mod guard's raise (`ExceptionState` EC-BOUND-REF-MOD helper).
