## Why

The owner does not use Obsidian (2026-10-25, above) and no agent opens it: the 105 transcripts of the skills
measurement (docs/rearchitecture/evidence/fleet-optimization/2026-10-25-skills-token-optimization.md) read the register
only through `work.py next`. The Bases files are read by Obsidian alone, yet they cost work: `work.py check` carries
`check_base_agrees` to keep `Work.base`'s filters equal to `HARM_FLAGS`, PB3389 had to add a `blocked` formula, PB3789
filed that the formula was never run, and that note's implementer opened Obsidian on the owner's desktop (PB3798).
The rest of `kb/` (the spec lookup pages, the MOCs, the diagrams) is plain Markdown that agents and skills read without
Obsidian and stays; whether each of those pages still earns its upkeep is a separate question this note does not decide.

## Acceptance

- Each Work.base view a reader needs has a `work.py` subcommand first: `next` is "Fix next"; add `blocked`, `unharmed`
  (open, no harm flag), `analyses` and `landed` (rows closed) with `--json`, each with a self-test; "Everything" is
  `stats` or dropped. Then the two `.base` files and `.obsidian/` are deleted, `check_base_agrees` with them (no shim,
  CLAUDE.md rule 4).
- Every sentence naming `kb/Work.base` or the Obsidian vault in the Sites above names the work.py subcommand instead,
  in the same change (rule 6); a grep of the tree outside DEVLOG/ and kb/Work/ finds none.
- PB3789 closes as superseded by this note (its subject, the Bases formula, is deleted) with `closes_rows: []` and a reason.

## Landed (wave 20261752 group A)

`kb/Work.base`, `kb/Conformance Burn-down.base` and the three `.obsidian/` files are deleted, with `check_base_agrees` and
the `Upstream records` / `blocked` formula / terminal-status checks it carried (no shim). The views a reader needs are
`work.py` subcommands over the one reader of the register: `blocked`, `unharmed` (open, kind not upstream, no
`HARM_FLAGS` flag: the exact complement of `next`'s harm test), `analyses`, `landed` (with the rows each closed) and
`upstream`, each with `--json` and `--top N`; "Everything" is `stats` (now with a harm count). Each is a row of `VIEWS`
(a predicate and a sort key), `HARM_LABELS` is the one table of harm flags (`HARM_FLAGS` is its keys), and `_is_open`
is the one test for "not done", so a new terminal status or harm class reaches every view with no second copy to edit.
`view_findings` (in `--self-test`) lists a scratch register of one note per shape plus one per harm flag and states each
view's listing; falsified by counting `retired` as open (the `landed` view stops listing it) and by adding a harm class
to `HARM_LABELS` (every view covers it with no edit to the test).

The Obsidian-only classification entry leaves `inert_lane.CLASSIFICATION` (the `kb/` entry stays), the `.obsidian/`
entries leave the four C# tree scopes that named them, and every sentence naming `kb/Work.base`, the Bases views or the
Obsidian vault in the tracked docs, skills, design docs and `kb/` pages now names the subcommand (a grep for
`Work.base|Burn-down.base|check_base_agrees|.obsidian` outside `DEVLOG/` and `kb/Work/` finds only the `.gitignore` guard
against an application creating its state in the checkout). PB3789 was already retired as superseded by this note.
`gen-grammar-diagrams.ps1` no longer stamps the `wide-diagram` class the deleted snippet styled.
