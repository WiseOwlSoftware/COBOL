# PB4729 - a bound past 77 digits is not a value past 77 digits

**Witness.** `A PIC 9(20)` = 10^19 + 1, `COMPUTE R = A*A*A*A + 1 - A*A*A*A` (R `PIC S9(9)`) stores 0. A^4 has 77 digits and is below 2^255, so
the VALUE fits the existing 256-bit wide form and the exact answer is +000000001, which GnuCOBOL 3.2.0 gives too. Only the compile-time digit
BOUND (80) is past the form. The same program with `* 1.0E0` on each side (ABCDF) also stores 0 for 1.

**Decided without the owner** (determination of PB4592, wave 20261870 c): CLAUDE.md rule 1 applies, because the answer is within the existing
form and DESIGN §1.2 invariant 2 does not stand in the way. Native evaluation is an implementor-defined technique (§8.8.1.3) with
implementor-defined intermediate rounding (§11.9.11.2 1)); GnuCOBOL is exact here, and so is exact arithmetic within the form.

**Mechanism.** Four arms of `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/NumericRenderer.cs` decide the lane on the compile-time BOUND:
- `#Multiply`: `digits > WideMaxDigits` goes straight to `RuntimeApi.DecMulToOdd`.
- `#Combine`'s nested-quotient arm (`digits <= WideMaxDigits && divisorDigits <= WideMaxDigits`, otherwise `DivTruncatedToOdd`).
- The additive arm (`wideDigits <= WideMaxDigits ? WideAdditive : DecBinary`).
- `#Power`'s literal-exponent arm (`b.Digits * n <= WideMaxDigits`).

**Owed.** When the bound passes 77 digits, each arm routes the operands to the run-time-scaled exact carrier (`NumX.Exact` over
`CobolExact.Mul` / `Add` / `Sub` / `DivTruncated` / `Pow`). That carrier tries the VALUE on the 256-bit form (`CobolWide.TryMul`, `TryAdd`,
`TryUp`, `TryPow`) and falls back only when the value itself leaves the form, as the design already does for the integer power ("exact while
the VALUE fits", PB4569). After the change there is one fallback point, `CobolExact`, instead of five. `ExactWideSettlementDriftTests` already
covers the `NumX.Exact` settling sites. Add a drift test that no `NumericRenderer` arm emits `DecMulToOdd` / `DecBinary` / `DivTruncatedToOdd`
over a wide operand on a bound alone. Golden: ABCD `+000000001` (the determination's section 3). Determination, probes and fix shape:
`E:/COBOL-coord/scratch/op-w20261870/c/determination.md`.

**Sites:** `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/NumericRenderer.cs` (`Multiply`, `Combine`, the additive arm, `Power`).

**Landed (wave 20261872, group A).** Re-probed on the build (`E:/COBOL-coord/scratch/w20261872a/pc/q5.cob`): `A*A*A*A + 1 - A*A*A*A` with A = 10^19 + 1 stores +000000001 (ABCD), and +000000001 with `* 1.0E0` (ABCDF); the main build stored 0.

Fix: the compile-time BOUND is no longer a lane. `NumericRenderer.Multiply` (a digit bound past 77) emits `ExactBinary("*", ...)`; `Divide`'s nested-quotient arm hands exact operands whose bound passes the form to `ExactQuotient` (`CobolExact.DivTruncated` at the run-time working scale); `CombineAdditive`'s wide arm past the bound emits `ExactBinary`; `Power`'s non-literal arm is `CobolExact.Pow` for every base shape. `CobolExact` tries the VALUE on the 256-bit form first (`CobolWide.TryMul`, `TryAdd`, `TryUp`, `TryPow`) and leaves it only when the value leaves it, so the fallback is ONE point, `CobolExact`, instead of five. `DecMulToOdd` has no caller left in `NumericRenderer`; the SDIDI lane remains for a Dec-carried operand (a float literal, DOC-A.1-82's lane determination).

**Golden:** `pb4592_exact_past_the_wide_form` legs ABCD and ABCDF (the determination assigned the golden to PB4592/PB4729 jointly). **Sites:** `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/NumericRenderer.cs#Multiply`, `#Divide`, `#CombineAdditive`, `#Power`; `src/WiseOwl.Cobol.Runtime/Values/Numeric/CobolExact.cs`. The determination's drift test (no `NumericRenderer` arm emits `DecMulToOdd` over a wide operand on a bound alone) is `ExactWideSettlementDriftTests`'s settling list plus the removal of the emitter call: no `DecMulToOdd` text remains in `NumericRenderer`.

operands' bounds were known and their alignment left it (`D PIC 9(19)` + `F PIC 9V9(30)`, 49 digits): the run unit ended with EC-SIZE-OVERFLOW for a sum the pictures hold and GnuCOBOL
gives. A known bound past the carrier now takes `ExactBinary`, as the wide arm and `Multiply` do. Golden
