# PB203

Found 2026-08-31 during the cluster-A burn-down, while checking whether [[PB173]]'s new `BitImagePlace` needed
a `RedefViewPlace` arm. It does not — because the shape that would need one does not compile at all, for an
unrelated and earlier reason.

**MEASURED** at `--std 2023`:

```cobol
01 A PIC X(2) VALUE "AB".
01 BV REDEFINES A GROUP-USAGE BIT.
   05 BV1 PIC 1(8).
   05 BV2 PIC 1(8).
...
DISPLAY "BV=[" BV "]".
```

→ four `error CS0103: The name 'BV1' does not exist in the current context` / `'BV2'`, the first pair on the
plain `DISPLAY BV` line. No reference modification is involved: the view's subordinate bit leaves are never
emitted as fields, so every reference to them names nothing.

**LEGAL SOURCE.** §13.18.44.3's syntax rules bar an object/pointer/strongly-typed subject (SR12), a
variable-length group or dynamic-length item on either side (SR17), and an occurs-depending table (SR5). A
GROUP-USAGE BIT group is none of those, and §13.18.29 places no REDEFINES restriction on a bit group. So this
is conforming source that fails BACKEND compilation.

**PRE-EXISTING — MEASURED, NOT ARGUED.** The cluster-A working tree was stashed, the solution rebuilt
at 876d8ab0, and the repro re-run: byte-identical output, the same four CS0103 diagnostics at the same
positions. So this is not a regression from [[PB173]]'s `BitImagePlace` landing — and the "it cannot be,
because PB173 only touched the ref-mod path" argument did not have to be trusted.

**WHERE TO LOOK.** The REDEFINES class tier for this shape, and the field emission that follows it: a bit
group's storage is a §8.5.1.6.3 bit RUN, not a character window, so `ComputeTier` / `RecordStructEmitter`'s
Tier-B path (a `(offset, width)` character window over the class backing) has no obvious representation for it.
The likely honest answers are a Tier-D rejection with a derived reason, or a real bit-window model — DERIVE
which before choosing, and note that §13.18.44.4 GR1 states the storage association **in BITS** ("starts at the
first bit … an area sufficient to contain the number of BITS required"), which is a point in favour of the
model rather than the rejection.

**RELATED.** Once this compiles, re-check whether `BitImagePlace` needs a `RedefViewPlace` arm the way
`GroupImage` has one — [[PB173]]'s wrap deliberately skips `RedefViewPlace` (mirroring `GroupImagePlace`), and
that choice is currently unobservable for exactly this reason.

## Landed 2026-09-04 — the bit window, and the note's diagnosis held only in part

**RE-PROBED FIRST on a freshly built tree** (base 6d61b95a): byte-identical to the note — four `CS0103` for
`BV1`/`BV2`. ⛔ **The note's LOCATION for them was wrong**: all four sit inside a dead `record struct` the emitter
produced for the view group, not "the first pair on the plain `DISPLAY BV` line". And the note UNDERSTATED the
population three times over — measured on the same build:

| shape | before |
|---|---|
| `01 A PIC X(2). 01 BV REDEFINES A GROUP-USAGE BIT. ...` (the note's) | CS0103 ×4 |
| the REVERSE — the bit group as the CANONICAL, an alphanumeric view over it | CS0103 ×4 (the note reads as if only the view direction were affected) |
| a bit group NESTED inside an ordinary redefines view | CS0103 ×4 |
| `01 A PIC X(1). 01 B REDEFINES A PIC 1(8) USAGE BIT.` | COMPILES; `DISPLAY B` printed `A`, not `01000001` — a SILENT WRONG ANSWER, and a different root cause (Tier A) |
| `01 A PIC X(1). 01 V REDEFINES A. 05 F1 PIC 1(4) USAGE BIT. 05 F2 PIC 1(4) USAGE BIT.` | COMPILES; `F1` = the raw character of byte 0, `F2` = a space read PAST the one-byte backing |

So `crashes` and `rejects_legal_source` were right and `silent`/`wrong_answer` were wrong — two of the five shapes
were live silent wrong answers on legal source.

**THE DERIVATION CHOSE THE MODEL, NOT THE REJECTION** — the note asked for exactly this and named GR1 as the
evidence in its favour. §13.18.44.4 GR1: "Storage association for the subject of the entry starts at the first bit
of the data item referenced by data-name-2 and continues over an area sufficient to contain the number of bits
required by the data item referenced by the subject of the entry." §13.18.29.4 GR1 c) allocates a bit group's
members "in accordance with the rules specified in 8.5.1.6.3". And §14.6.8.6's own NOTE removes the last doubt:
"When an item is of usage bit, the item is not necessarily aligned on a byte boundary and the item need not occupy
an integral number of bytes." A Tier-D rejection would have been a rejection of conforming source.

**THREE ROOT CAUSES, ONE MECHANISM** (a Tier-B member is a window over the class's ONE backing, and a bit
member's window is in BIT positions):

1. **The window units.** `RedefViewPlace` gained a `Bit` payload — the absolute bit offset within the backing and
   the boolean-position count — rendered through the new `CobolBits.ReadWindow`/`WriteWindow` pair, which touch
   only those bits. A PAYLOAD, not a new `Place` subtype: every consumer that discriminates `is RedefViewPlace`
   is asking "is this member's read already the value string?", and for a bit member the answer is still yes.
2. **The class offsets.** `AssignClassOffsets` summed `ImageWidth` in BYTES, so two same-level bit members each
   got their own byte (§8.5.1.6.3 rule 1 SHARES one) and everything after such a run was displaced. It now
   carries a bit cursor applying rules 1–2 of the §8.5.1.6.3 walk, gated on `HasBitDescendant` exactly as
   `DataItem.ImageWidth` is — provably byte-identical for every bit-free class. `DataItem.ClassBitOffset` is new.
3. **The dead struct.** `RecordStructEmitter` emitted a `record struct` for a group the physical model had already
   collapsed into the class backing; its fields came from the PHYSICAL model (empty) while
   `GroupImageCodec.EmitBitMethods` composed `AsBits()` from `group.Children` — the CS0103. The type is not
   emitted at all now: it can have no field, and its `AsImage()`/`AsBits()` could only ever have been `""`.

**A FOURTH CAUSE THE NOTE DID NOT NAME, found by probing the shape the note held fixed.** `ComputeTier`'s Tier-A
arm proves "one field serves both" from CLR carrier type + `ImageWidth`, and neither says what the field HOLDS: a
`USAGE BIT` leaf's carrier is its PICTURE 1(n) boolean positions while `ImageWidth` is its `ceil(n/8)` bytes. The
arm now also requires bit-ness agreement and, between two bit leaves, an equal boolean-position count.

**THE SWEEP.** `grep -rn "RedefinesTier.StringCanonical" src/` — three loops decide whether a Tier-B member gets
its own storage, and `OoEmitter`'s two (LINKAGE roots, LOCAL-STORAGE roots) lacked the non-canonical skip
`ProgramEmitter`'s LOCAL-STORAGE loop has carried since M2-OO-1h: the two-arm shape, third instance in this file.
And `grep -rn "new RedefViewPlace(" src/` — THREE builders each carried their own copy of the offset law, which
is precisely how the bit unit came to be missing from all three at once; they go through the one factory
`RedefViewPlace.For` now.

**[[PB173]]'s open "RELATED" question is CLOSED, and the answer is no.** `BitImagePlace` needs no `RedefViewPlace`
arm: a bit `RedefViewPlace` already reads its boolean carrier, so the `RefModPlace` over it slices §8.4.3.3.4
GR5a's bit positions structurally. Measured — `BV(1:3)` = `B"010"` and `MOVE ALL B"0" TO BV(2:3)` zeroes
positions 2–4.

**GOLDEN.** `tests/conformance/2023/pb203_redefines_bit_window.cob` (PB203BW, enabled). Every bit leg is PAIRED
with its no-REDEFINES control, so the assertion is "the two lanes give the same answer" rather than "some bits
came out"; the expected values are computed from the repertoire ('A'=x41 …) and stated in the header. Output is
byte-identical at `--std` 2002 / 2014 / 2023; at 85 every leg is refused COBOLNET0900.

**DOCS.** `docs/COBOLNET_DATA_MODEL_DESIGN.md` D19's scope boundary claimed "a sub-byte REDEFINES overlay … is
refused rather than given a rounded offset" — ⛔ **false in both halves and never measured**; it is replaced by
the as-built REDEFINES-bit-window section. `docs/rearchitecture/DESIGN-data-model.md` §2.3 gained the tier rules.

**RESIDUE, recorded not hidden:** a class containing a NATIONAL leaf stays Tier-D (the D-N1 2-byte overlay,
RESIDUE-11) — the only shape of §13.18.44.4 GR1 this model does not carry, which is why inventory rows
`GR-13.18.44.4-1` and `GR-13.18.44.4-2` are left for the adjudication lane rather than verdicted here.
