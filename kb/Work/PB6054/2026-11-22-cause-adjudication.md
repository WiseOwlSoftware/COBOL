**2026-11-22, the second half of PB6054 (wave 20262140, group B): the cause of each GnuCOBOL 85 failure, adjudicated for 351 of the 484.** `conformance-suite/measurements/gnucobol.json` now carries `gnucobol-nonconformance` 185 (each with a `§1985:` citation), `non-portable-test` 166 and `unclassified` 133; `generate.py --check` is GREEN and the second-compiler term of the status line falls from 484 to 133.

**How it was decided (the reading is stated so Stage 2 can overturn it).** The buckets are mechanical (design section 5), so the cause is set per bucket and then per test where a test differs from its bucket. Evidence read on this tree, cobc 3.2.0 under WSL at `-std=cobol85`: the first diagnostic and the failing source line of every compile failure outside the COMMUNICATION bucket; the complete `cobc -x` output of the C-compiler failures (`b_6`, `f_5`, `h_SORT_A` undeclared: cobc generated invalid C for valid COBOL, so the `_FORTIFY_SOURCE` warning the bucket key quotes is not the failure); `ALPHABET XYZ IS NATIVE | STANDARD-1 | "A" THRU "Z" | 1 THRU 66 67` compile and `ALPHABET XYZ IS EBCDIC` and `UPSI-7` do not (probes in the wave scratch directory); the actual output of two tests of each output bucket classified `gnucobol-nonconformance`, diffed against its `.out`. A citation is the rule the test's own header names (`§1985:<clause> <rule>` with a quotation from that rule), else the clause's own prose, each checked with `cite.resolve` (the checker `cite.py --check` calls) before it was written; it is therefore the rule the test exercises, not a derivation of why cobc differs.

**Optional modules.** `§1985:I.1.4` ("OPTIONAL MODULES (Not Required in Subsets): Report Writer, Communication, Debug, Segmentation") makes the Communication and Debug modules optional, so a test that needs them cannot be portable, and cobc omitting a module is not a defect of a conforming 1985 compiler. cobc does implement Report Writer, so its differences there are nonconformances.
