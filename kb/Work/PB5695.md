# PB5695 - a 2 TB object compiles clean and NEW exhausts the host

**Incident (each fact observed).** A witness writer of the 2002 golden lane (slug `g2002-15-57-ord`) wrote and ran the probe
below as `dotnet p1.dll` (PID 476748, reported by the Mythos session, which watched the host). The class `G2BIG` holds, in its
OBJECT WORKING-STORAGE, `01 T. 05 E PIC X(1000) OCCURS 2000000000.` (about 2 TB). It compiled without a diagnostic. The run
unit committed 79.8 GB, the host fell to 0.5 GB free commit, and a landing of the other session died in that window
("cannot start new thread", exit 6). The process ended only when the writer's shell time limit (300 s) killed it.

**Sites:** none (not yet located: where the fix lands depends on the choice under "To decide"; the fix names its sites when it takes the note).

**Harm.** `crashes`: the run unit does not fail in a defined way; it exhausts the host. `under_rejects` is NOT set: it would
need the standard or the implementor-limit documentation to require a refusal, which nothing here has yet established (see
"To decide").

**Repro, from `E:/COBOL-coord/scratch/gl2002/lane1/run/g2002-15-57-ord/oonew/p1.cob`.**

⛔ **DO NOT COMPILE OR RUN THIS PROBE. RUNNING IT STARVES THE HOST.** Its source is copied here as text only.

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. G2NEWP.
       ENVIRONMENT DIVISION.
```

A fix's test must use a size the test host can refuse without allocating (the fix decides how: a compile-time limit, or an
allocation that fails before committing).

**Observed.** No diagnostic; the run commits memory until the host is out (79.8 GB when killed).

**Expected: a defined outcome. To decide (open; the fix decides, this note does not).** The candidates, from the standard's
text:

- a compile-time refusal against a documented implementor limit on the size of a data item or record (§2023:4.2.1,
  conformance of the implementation, requires implementor-defined limits to be documented; `docs/conformance/` holds them);
- at run time, the exception condition the standard gives for an object that cannot be created (the INVOKE and NEW rules; for
  ALLOCATE it is EC-STORAGE-NOT-AVAIL).

The citation is to be derived by the fix with `python scripts/spec/cite.py --check`. This note cites nothing it has not
checked, and `spec_refs` is empty for that reason.

**Siblings to sweep (for the fix).** WORKING-STORAGE and LOCAL-STORAGE records of the same size in a program, ALLOCATE of a
giant BASED item, a giant OCCURS DEPENDING ON maximum, a FILE record of that size, SORT work areas.
