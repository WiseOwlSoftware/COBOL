# PB5078 - at --std 85 five Report Writer rules on the report description and GENERATE are unchecked: repeated CONTROLS operand, PAGE LIMIT over three digits, a report group that cannot fit a page, CODE literal length, GENERATE report-name with two detail groups

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/ReportSectionBinder.cs` (`ScreenReportPageIntegers` with `MaxPageLimit = 9999`, `ScreenReportGroupLines`, `BindCodeClause`; the CONTROL clause arm of the RD binder is named without a member), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/ReportWriterBinder.cs#BindGenerate`.

**Mechanism.** The report-description screens apply the 2023 rules at every edition and have no arm for the 1985 text: the CONTROLS uniqueness loop compares written references where 1985 asks for different data items; the page limit bound is 9999 where 1985 says three significant digits; the compile-time fit test covers heading and footing groups only where 1985 says all report groups must fit one page; BindCodeClause accepts any-length literals and an identifier where 1985 says a two-character nonnumeric literal; BindGenerate asks only for a CONTROL clause where 1985 allows GENERATE report-name only for a report with no more than one detail group.

**Found by.** The 1985 `--std=85` draft triage (kb/Work PB4995 item 3): each rule below is a conformance-suite draft that did not MATCH at `--std 85`, and its adjudicator decided COMPILER-DEFECT. Harm and observed text are the records'; nothing here was re-derived.

**Inventory.** The traceability inventory carries no 1985 rows yet, so `inventory_rows` is empty; the rows this note covers are the 1985 rule ids listed below (catalog `docs/rearchitecture/spec-rule-catalog-1985.json`).

**Rules (5; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-SR-XIII.3.7.3-2` - `§1985:XIII.3.7.3 SR2` (record harm: under-rejects, slice-10): §1985:XIII.3.7.3 SR2: "Each recurrence of data-name-1 must identify a different data item." The rule is about the data item a recurrence identifies, not about how the reference is spelled, and §1985:XIII.3.7.3 SR1 allows the spellings to differ: "Data-name-1 may be qualified." So `CONTROLS WS-A WS-A OF WS-G`, where WS-A is the one item of that name and WS-G its group, names one data item twice and is forbidden. The draft as written tests only the textual duplicate (`CONTROLS ARE WS-A WS-A`), which the compiler does refuse; that draft's mismatch is its marked line (the RD entry runs over lines 15 to 17, the draft marks line 16, the compiler reports at the entry, line 15; written on one line the draft and its control MATCH). The corrected draft tests the rule's own words, one data item under two spellings, and the compiler accepts it.
- `1985-SR-XIII.3.8.3-2` - `§1985:XIII.3.8.3 SR2` (record harm: under-rejects, slice-10): §1985:XIII.3.8.3 SR2: "Integer-1 must not exceed three significant digits in length." Integer-1 is the page limit (§1985:XIII.3.8.2: `PAGE [LIMIT IS | LIMITS ARE] integer-1 [LINE | LINES]`), and 1000 has four significant digits. The draft reads the rule correctly and breaks no other rule; its control (PAGE LIMIT IS 999 LINES) compiles.
- `1985-SR-XIII.3.8.3-9` - `§1985:XIII.3.8.3 SR9` (record harm: under-rejects, slice-10): §1985:XIII.3.8.3 SR9: "All report groups must be described such that they can be presented on one page. The report writer control system (RWCS) never splits a multi-line report group across page boundaries." With only PAGE LIMIT written, §1985:XIII.3.8.4 GR2 fixes the regions: "If the HEADING phrase is omitted, a value of one is assumed for integer-2.", "If the FIRST DETAIL phrase is omitted, a value equal to integer-2 is given to integer-3.", "If the LAST DETAIL and the FOOTING phrases are both omitted, the value of integer-1 is given to both integer-4 and integer-5." §1985:XIII.3.8.3 SR8 c confines the group: "A control heading or detail report group, if defined, must be defined such that it can be presented in the vertical subdivision of the page that extends from the line number specified by integer-3 to the line number specified by integer-4, inclusive." The draft's detail group has eleven `LINE PLUS 1` lines and a page of ten (lines 1 to 10), so its description alone shows it cannot be presented on one page. The draft reads the rule correctly; its control (PAGE LIMIT IS 20 LINES) compiles. The repro is the same violation at its smallest: three lines, a page of two.
- `1985-SR-XIII.3.6.3-1` - `§1985:XIII.3.6.3 SR1` (record harm: under-rejects, slice-14): §1985:XIII.3.6.3 SR1: "Literal-1 must be a two-character nonnumeric literal." (§1985:XIII.3.6.1: "The CODE clause specifies a two-character literal that identifies each print line as belonging to a specific report.") `CODE "A"` is a one-character literal, so the draft reads the rule correctly. Its unrelated error, in test and control alike: the RD has no PAGE clause and the detail is described with `LINE 1`, which §1985:XIII.3.15.3 SR5 forbids ("If the PAGE clause is omitted from a given report description entry, only relative LINE NUMBER clauses may be specified in any report group description entry within that report."); the compiler refused the control for that. The corrected draft writes `LINE PLUS 1`. Its control then compiles and runs, and the test, with `CODE "A"`, is accepted without a diagnostic.
- `1985-SR-XIII.3.20.3-6` - `§1985:XIII.3.20.3 SR6` (record harm: under-rejects, slice-14): §1985:XIII.3.20.3 SR6: "When a GENERATE report-name statement is specified in the Procedure Division, the corresponding report description entry must include no more than one detail report group." §1985:XIII.4.3.3 SR2 says the same of the statement: "Report-name-1 may be used only if the referenced report description contains: a. A CONTROL clause, and b. Not more than one detail report group, and c. At least one body group." The draft reads SR6 correctly, but both of its programs carry unrelated errors: the RD has no CONTROL clause, which SR2 a requires for GENERATE RPT, and the control's report footing report group cannot be presented (PAGE LIMIT 20 with no FOOTING phrase gives integer-5 the value 20, §1985:XIII.3.8.4 GR2 c: "If the LAST DETAIL and the FOOTING phrases are both omitted, the value of integer-1 is given to both integer-4 and integer-5", and §1985:XIII.3.8.3 SR8 f places such a group "from the line number specified by integer-5 plus 1 to the line number specified by integer-1, inclusive": lines 21 to 20). The compiler refused both for those reasons, rightly. The corrected draft adds CONTROL IS FINAL to the RD and makes the control's second group a control footing (a body group that is not a detail). The control then compiles and runs; the test, whose RD holds two detail report groups under GENERATE RPT, is accepted without a diagnostic.
