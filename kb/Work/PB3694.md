# PB3694 — union merging duplicates a PublicAPI symbol

**Sites:** `scripts/merge_drivers.py` (`merge_symbol_set`, landed by PB3727; `is_symbol_baseline`, `baseline_duplicates`),
`scripts/orchestrator/landing_check.py` (`baseline_texts`, `baseline_stops`, `check` arm 0b), `tests/WiseOwl.Cobol.Tests.Unit/MergeDriverDriftTests.cs`
(`TheSelfTests_DeclareEveryArm`), `docs/rearchitecture/DESIGN-orchestrator-loop.md` (section 16.9), `.gitattributes` (the
`cobol-keyed-publicapi` row, PB3727).

## The case (2026-10-24)

PR #541's merge-group run 40156159979 failed `Build (Release, warnings-as-errors)` with RS0025: `CobolNum.GroupDigits`
appears twice in `src/WiseOwl.Cobol.Runtime/PublicAPI.Unshipped.txt`. Main had added the line at 266 (PR #535) and the
branch at 268 (it had merged the same work, PB3693). Union is a LINE merge: the same line added at two positions is kept
twice. The finisher reproduced it with `git merge-file --union` on the single merge base GitHub used (070df5a66); the
local merge, on another base, produced one line, so the branch's local gate was green and only CI failed.

## The fix direction

A set-merge driver for the PublicAPI files in `merge_drivers.py` (keep each symbol once, in the files' sorted order,
and refuse a symbol listed in both Shipped and Unshipped), registered for the local merges, plus a duplicate-line check
in `landing_check.py` so a branch that would produce a duplicate is stopped before the queue. GitHub's merge group runs
no custom driver (PB3642), so the landing check is what keeps the queue from bouncing. Sweep the other `merge=union` and
keyed-driver files for the same duplicate-line exposure.

## Landed (wave 20261752 group B)

**Re-probe** (a three-way merge of base `A.A C.C E.E`, main adding `X.X` after `A.A`, the branch adding it after `E.E`): the
union merge kept `X.X` twice, and so did the plain line merge (exit 0, `X.X` twice), which is what GitHub's merge group runs;
the registry's driver (`merge_symbol_set`) made one. So the first half of the fix direction (the set-merge driver, the sweep of
`merge=union`: none remains in `.gitattributes`) was already landed by PB3727, while the merge group's driverless merge
could still duplicate and nothing local read it.

**Fix.** `merge_drivers.baseline_duplicates` is the rule (a symbol twice in one file, or one plain line in two files of one
directory: RS0025), `is_symbol_baseline` names the files from the DRIVERS row; `landing_check.baseline_stops` (arm 0b, exit 3)
reads the baselines of the landing's own tree and of the tree `merge-tree` makes of origin/main and the landing with no driver
configured, and STOPS naming the file and symbol (a finding of the landing's tree is not repeated for the merge that carries it
on; a merge that conflicts has no tree to read). Self-test arms: `landing_check.py --self-test` (five PB3694 cases: duplicate in
a file, Shipped/Unshipped overlap, `*REMOVED*` beside its Shipped symbol lands, the queue's merge duplicating, the same-place
twin merging once) and `merge_drivers.py --self-test` (two arms, declared in `MergeDriverDriftTests`).
