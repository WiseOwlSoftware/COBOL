# PB5240 - an alphanumeric function-identifier is refused where 1985 admits an identifier operand of CANCEL, CALL, and the WITH KEY phrase of ENABLE and DISABLE (COBOL5506 at FUNCTION): cancelTarget, the CALL target and communicationKeyPhrase have no functionCall alternative

**Sites:**

- `src/WiseOwl.Cobol.Frontend/Grammar/CobolParserCore.g4` (`cancelTarget`: `literal | dataReference`; the CALL target)
- `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolCommunication.g4` (`communicationKeyPhrase`: `WITH? KEY (literal | dataReference)`; `sendText` beside it takes `functionCall`)
- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CallBinder.cs` (`BindCancel`, `BindCall`, `CalleeSignatureOf`, `ComputedNameTargetRefusal`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CommunicationBinder.cs` (`BindEnable`, `BindDisable`, `BindPath`, `IsAlphanumericKey`)
- `tests/WiseOwl.Cobol.Tests.Unit/ConstantNameLiteralPositionDriftTests.cs` (`Unwitnessed`: the `communicationKeyPhrase` row, gone with its literal)
- `src/WiseOwl.Cobol.Compiler/Binding/ReportSectionBinder.cs` (`IdentifierOperandOf`, `BindSourceOperand`) and `src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs` (`VisitReportSourceClause`): the SOURCE site, still open

**Mechanism.** With Amendment 1 applied, §1985:IV.4.3.8.3.3 SR3 reads "A function-identifier which references an alphanumeric function may be specified anywhere in the general formats that an identifier is permitted" (save as a receiving operand or where the format's rules exclude it). CANCEL (§1985:X.5.3.2, identifier-1 an alphanumeric data item by §1985:X.5.3.3 SR2), the ENABLE and DISABLE KEY operand (§1985:XIV.3.3.2, §1985:XIV.3.2.2; a sending alphanumeric operand) and CALL identifier-1 are such places. The grammar rules for these operands take a literal or a data reference only, so the parser refuses the function before any binder can apply the category rule. The intrinsic functions are in the 85 compiler (a DISPLAY FUNCTION UPPER-CASE control compiles and runs).

**Found by.** The 1985 code read read the CANCEL, ENABLE and DISABLE formats CONFORMS; their Opus refuters OVERTURNED all three (`E:/COBOL-coord/scratch/coderead-85/out-pipe/slice-40-refute.json`, probe `E:/COBOL-coord/scratch/coderead-85/out-pipe/refute-slice-40/cases/c-func/c-func.cob`; `E:/COBOL-coord/scratch/coderead-85/out-pipe/slice-56-refute.json`, probes `E:/COBOL-coord/scratch/coderead-85/out-pipe/refute-slice-56/k1_en_key_func.cob`, `k2_dis_key_func.cob`, `k3_en_ioterm_func_refmod.cob`). The CALL sibling is the slice-40 refuter's side observation (`call-func`), not a recorded row.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids below. None of them is recorded: the code read's non-conforming verdicts of slices 36-56 wait in `E:/COBOL-coord/scratch/coderead-85/pipe-for-register.json`.

**Rules (3 claimed; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-FMT-X.5.3.2` - `§1985:X.5.3.2` (refuter: OVERTURNED to PARTIAL, harm: rejects-legal-source): `CANCEL {identifier-1 | literal-1} ...`, with `§1985:IV.4.3.8.3.3 SR3` and `§1985:X.5.3.3 SR2` ("alphanumeric data item").
- `1985-FMT-XIV.3.2.2` - `§1985:XIV.3.2.2` (refuter: OVERTURNED, harm: rejects-legal-source): DISABLE ... `[ WITH KEY {identifier-1 | literal-1} ]`.
- `1985-FMT-XIV.3.3.2` - `§1985:XIV.3.3.2` (refuter: OVERTURNED, harm: rejects-legal-source): ENABLE ... the same KEY phrase.

**Repro.** `cobol.exe --std 85 --source-format fixed --run c-func.cob` (its statement: `CANCEL FUNCTION UPPER-CASE(N).`); likewise `k2_dis_key_func.cob` (`DISABLE OUTPUT CD-OUT KEY FUNCTION REVERSE(WS-K).`) and `k1_en_key_func.cob` (`ENABLE INPUT CD-IN WITH KEY FUNCTION UPPER-CASE("pw").`).

**Observed (the records-85c build of origin/main f2cf36fd15, rerun 2026-11-10).** Each exits 65: `cfunc.cob(8,19): error COBOL5506: unexpected 'FUNCTION'. The word FUNCTION is not expected here: expected a user-defined word, LINAGE-COUNTER, LINE-COUNTER, PAGE-COUNTER or a literal`; `k2_dis_key_func.cob(24,38)` and `k1_en_key_func.cob(24,40)` the same COBOL5506. The refuter also saw the refusal at --std 2023.

**Expected (from the 1985 text).** Each compiles: CANCEL takes the function's alphanumeric value as the program name, and ENABLE/DISABLE send it as the key.

**Fix direction (root cause, CLAUDE.md rule 4).** The defect is one fact missing in several rules: "an identifier that is a sending operand may be an alphanumeric function-identifier". Give the shared sending-operand rule the `functionCall` alternative once and make CANCEL, CALL and the KEY phrase use it (as `sendText` does), so the binders' existing category checks (SR2's alphanumeric) apply to the function's category; sweep the grammar for other sending-identifier positions written `literal | dataReference`, and settle the 2023 reading (§2023 function-identifier rules) before deciding the edition span.
