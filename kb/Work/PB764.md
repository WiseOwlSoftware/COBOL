# PB764 — OPEN — a structural rule written down ten times, once per site

Filed 2026-09-06 by the registrar from the PB704 implementer's report ("New defects", N1). **Every claim below
was re-derived against main at `1e7b5085`**; where the report's number was wrong it is corrected here and the
correction is called out, because the whole subject of this note is a claim propagating without re-derivation.

## The mechanism, quoted from main

`src/Cobol.Net.Compiler/Validation/VersionConformancePass.cs`, `VisitCobolWord` (`:2050`). After the length /
underscore checks and the position filter, the method is a ladder of early `return base.VisitChildren(ctx)`
exits, each one meaning *"this occurrence is not a user-defined word, so do not run `FlagReservedUserWord`"*:

```
:2072   if (!CheckedTokenTypes.Contains(ctx.Start.Type) && !IsProvableUserWordPosition(ctx))   // the position filter
:2083   if (IsBareFunctionArgumentWord(ctx))                                                    // §15 phrase words
:2092   if (ctx.Parent is CobolParserCore.EntryConventionClauseContext)
:2115   if (ctx.Parent is CobolParserCore.CallAsPhraseContext && _cobolWords.Is(ctx.Start.Text, "NESTED"))
:2118   if (ctx.Parent is CobolParserCore.LocaleClauseContext locale && … !ReferenceEquals(ctx, localeWords[1]))
:2131   if (ctx.Parent is CobolParserCore.OrderTableClauseContext order && … ReferenceEquals(ctx, orderWords[0]))
:2138   if (ctx.Parent is CobolParserCore.AlphabetEntryContext ae && … IsAlphabetLocalePhrase(adef, _cobolWords))
:2146   if (ctx.Parent is CobolParserCore.PictureLocalePhraseContext)
:2154   if (ctx.Parent is CobolParserCore.CharacterClassificationClauseContext or …ClassificationForPhraseContext)
:2162   for (… a = ctx.Parent; …)  if (a is CobolParserCore.SetLocaleStatementContext)            // ancestor walk
:2176   for (… a = ctx.Parent; …)  if (a is …ValidationClauseContext or …ValidateValidPhraseContext
                                          or …ApplyCommitClauseContext)                          // ancestor walk
:2186   if (word == "EXCEPTION-OBJECT")  for (… a = ctx.Parent; …) if (a is …ObjectReferenceContext or …)
:2199   if (_debuggingModeDeclared && word.StartsWith("DEBUG-", …))
:2202   FlagReservedUserWord(word);
```

⚠ **The report's count is wrong and the correction matters.** It says *"eight per-site `ctx.Parent is …Context`
arms"*. Measured on main: **seven** `ctx.Parent is` arms (`:2092`, `:2115`, `:2118`, `:2131`, `:2138`, `:2146`,
`:2154`) and **three** ancestor walks doing the same job by subtree (`:2162`, `:2176`, `:2186`) — **ten
position-keyed exemptions**, plus two that key on something other than position (`IsBareFunctionArgumentWord`,
the `DEBUG-` register). Ten, not eight, and the ancestor walks are the ones a reader scanning for `ctx.Parent`
misses.

## The rule, re-derived and mechanically checked

- `cite.py --check 8.3.2.1 "Reserved words shall not be used as user-defined words"` → **OK**, §8.3.2.1 1):
  *"Reserved words shall not be used as user-defined words or system-names."* This is the ONLY rule
  `FlagReservedUserWord` enforces, and it governs a *user-defined-word slot*.
- `cite.py --check 5.2.2 "Keywords are reserved words or context-sensitive words"` → **OK**, §5.2.2:
  *"Keywords are reserved words or context-sensitive words. They are shown in uppercase and underlined in
  general formats. They are required in order to select the functionality associated with that keyword…"*
- `cite.py --check 5.2.3 "Optional words are reserved words or context-sensitive words"` → **OK**, §5.2.3:
  *"Optional words are reserved words or context-sensitive words. They are shown in uppercase and not underlined
  in general formats. They may be written to add clarity…"*

Together: a reserved word standing where its own general format prints it — keyword or optional word — is a
**use OF the reserved word**, exactly what §5.2.2/§5.2.3 define it to be, and is therefore outside §8.3.2.1
rule 1 entirely. The funnel's job is to distinguish those two uses; today it distinguishes them by a list of
places.

## The measured proof that the omission is silent to every gate

`cite.py --check 14.9.40.2 "DUPLICATES"` → **OK**, and the general format prints
`[ WITH <u>DUPLICATES</u> IN ORDER ]` — one underline, so WITH/IN/ORDER are §5.2.3 optional words. On main,
`src/Cobol.Net.Frontend/Grammar/Core/CobolIO.g4:744-746`:

```
sortDuplicatesPhrase
    : WITH? DUPLICATES IN? cobolWord?    // cobolWord matches ORDER (not a lexer token)
```

Reproduced against main's own build (`vorder.cob`, the PB704 probe with `IN ORDER`):

```
--std 85    : (clean)
--std 2023  : vorder.cob(24,35): error COBOLNET0901: 'ORDER' is a reserved word in COBOL-2023
              and cannot be used as a user-defined word (ISO 8.9)
```

`ORDER` is `r2002/r2014/r2023 = true` in `tests/version-matrix/reserved-words.json`, so the only phrase that can
demand §14.9.40.4 GR3's defined tie order is unusable at every edition from 2002 — and the diagnostic is a
**false statement about the source**. `orderTableClause` got its arm at PB101 (`:2131`, still on main);
`sortDuplicatesPhrase` never did. `feedback_two_arm_dispatch`, the sixth instance.

## ⛔ Why a dedicated sweep did not find it — the doc records the wrong axis, and still does on main

PB693's finisher swept on *"§8.9-reserved **AND** has a lexer token"*. ORDER is reserved and has **no** token, so
it fell outside the sweep's own definition. That axis is still written into the design SSOT.
`docs/rearchitecture/DESIGN-frontend-grammar.md:396-399`, on main today:

> Every other keyword the grammar routes through `cobolWord` — LOCALE, ORDER, CLASSIFICATION, ATTRIBUTE,
> UCS-4/UTF-8/UTF-16, RELATION, NONE, RECEIVED, COBOL — is §8.10 context-sensitive or unclassified by the
> standard, has NO lexer token, arrives as IDENTIFIER, and no gate can reach it.

Measured against `tests/version-matrix/reserved-words.json`, that sentence is **false for six of the nine words
it names**: LOCALE (r2002+), ORDER (r2002+), NESTED (r2002+, named elsewhere in the same family),
SYSTEM-DEFAULT (r2002+), USER-DEFAULT (r2002+) and COBOL (r85/r2002/r2014, dropped at 2023) are all §8.9-reserved.
Only CLASSIFICATION, ATTRIBUTE and RELATION are absent from the list. **Repairing that sentence is part of this
note's fix** (CLAUDE.md rule 6): it is the sentence that told the last two sweeps not to look.

## The fix shape — a design change, not a sweep

The mirror of `reservedGatedWord` (`src/Cobol.Net.Frontend/Grammar/Core/CobolWords.g4:120`, generated from the
`nameSlot` rows of `tests/version-matrix/cobol-words.json`). That rule is **list-free by construction**: the §8.9
arm hangs on the SHARED RULE, so every use of it is a definition slot and the next definition slot needs no C# at
all. The exemption ladder needs its twin — a shared grammar rule meaning *"a general-format keyword matched by
text because it has no lexer token"* — which `VisitCobolWord` skips with ONE arm on the rule, no slot list, and
no place for the eleventh site to be forgotten. `DESIGN-frontend-grammar.md:387` already states the governing
rule (**"A KEYWORD SLOT MAY NOT BORROW `cobolWord`"**); what is missing is the vehicle for the slots that cannot
take a plain lexer token.

⚠ **It is a DESIGN change and this is why it was not done inside PB704.** LOCALE deliberately must keep arriving
as a bare word: `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs:946` reads
`KeywordWordOf(argCtxs[1]) != "LOCALE"` to recognise `LOWER-CASE(x LOCALE …)`, and `:844`/`:859`/`:914` do the
same for the ORDER-TABLE arguments. So the shared rule needs a **per-call-site word argument**, and ANTLR's
predicate-hoisting behaviour for rule arguments has to be settled before the rule can be written
(`feedback_design_structural_singular_first`). Pair the landing with a drift test that fails when a `.g4` rule
routes a §8.9-reserved word through `cobolWord` without going through the new rule — the test is what keeps
"automatic" true (CLAUDE.md rule 5).

## Where PB704's fix lives, and what it does NOT close

⛔ **PB704's fix is NOT on main.** It sits on branch `worktree-agent-aad37de314c6cef0b` (train 18), head
`3d32e5ce`, base `0a24276f`. Its diff against main:

- `CobolIO.g4`: `sortDuplicatesPhrase : WITH? DUPLICATES IN? ORDER?` — ORDER becomes a lexer token with a
  `cobol-words.json` `nameSlot` row.
- `VersionConformancePass.cs`: the `OrderTableClauseContext` arm at `:2131` is **DELETED** (both ORDER positions
  now stop at the lexer), taking the ladder from seven `ctx.Parent is` arms to six.

That is the right fix for ORDER — and it closes exactly one word. The ladder, and the "the next general format
adds its arm or gets a false 0901" property, survive it untouched. This note is what remains.
