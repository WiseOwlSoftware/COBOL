# PB4544 — code-set-for-phrase-not-supported: -std=cobol2014: CODE-SET FOR ALPHANUMERIC IS alphabet-name is refused ("syntax error, unexpected FOR")

Filed 2026-11-03 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-batch-3000-20261103`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

Under `-std=cobol2014`, cobc 3.2 refuses the `FOR ALPHANUMERIC` form of the file description CODE-SET clause
(`CODE-SET FOR ALPHANUMERIC IS alphabet-name-1`) with "syntax error, unexpected FOR". Only the `CODE-SET IS
alphabet-name` form is parsed. The FOR ALPHANUMERIC / FOR NATIONAL phrases are part of the CODE-SET clause's general
format in ISO/IEC 1989:2002 and later. Class: feature missing. Fuzz programs: fz00106 and 14 more (night
fuzz-batch-3000-20261103, slice D1).

## Minimal test case

Free reference format.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. CS1.
ENVIRONMENT DIVISION.
CONFIGURATION SECTION.
SPECIAL-NAMES.
    ALPHABET AL-STD IS STANDARD-1.
INPUT-OUTPUT SECTION.
FILE-CONTROL.
    SELECT F1 ASSIGN TO "cs1.dat" ORGANIZATION IS SEQUENTIAL.
DATA DIVISION.
FILE SECTION.
FD F1 CODE-SET FOR ALPHANUMERIC IS AL-STD.
01 R1 PIC X(4).
PROCEDURE DIVISION.
    OPEN OUTPUT F1
    MOVE "ABCD" TO R1
    WRITE R1
    CLOSE F1
    MOVE SPACES TO R1
    OPEN INPUT F1
    READ F1
    DISPLAY "[" R1 "]"
    CLOSE F1
    STOP RUN.
```

## Environment

`cobc (GnuCOBOL) 3.2.0`, WSL2 Ubuntu x86_64. Compiled with `cobc -x -free -std=cobol2014 -o p cs1.cob`; no executable
is produced, so nothing is run. Control: the same program with `FD F1 CODE-SET IS AL-STD.` compiles and its run prints
`[ABCD]`, exit code 0.

## Observed result

Compile, exit code 1:

```text
cs1.cob:12: error: syntax error, unexpected FOR
```

## Expected result (per ISO)

The program is legal and prints `[ABCD]`.

- §13.18.13.1 (checked): "The CODE-SET clause specifies the character code convention used to represent data on the
  external media." The general format (§13.18.13.2, checked: "FOR ALPHANUMERIC IS alphabet-name-1") offers `IS alphabet-name-1 [alphabet-name-2]` or one or both of
  `FOR ALPHANUMERIC IS alphabet-name-1` and `FOR NATIONAL IS alphabet-name-2`.
- §13.18.13.3 1) (checked): "Alphabet-name-1 shall reference an alphabet that defines an alphanumeric coded character
  set." AL-STD is STANDARD-1.
- §13.18.13.3 3) a) (checked): "if alphabet-name-1 is specified, all elementary data items of all record description
  entries associated with the file shall be described as usage display"; R1 is.
- §13.18.13.4 2) (checked): "the coded character set used to represent alphanumeric data on the storage medium is the
  one referenced by alphabet-name-1"; the record is converted on WRITE and back on READ, so `[ABCD]` is displayed.

Edition: 2014. The FOR ALPHANUMERIC / FOR NATIONAL phrases came with the national character support of ISO/IEC
1989:2002 (the 2002 text and the 2009 committee draft that led to 2014 both carry `CODE-SET FOR ALPHANUMERIC IS
alphabet-name-1`); Annex E of the 2023 standard lists no change to the CODE-SET clause, so the 2014 format is the one above.

## Our compiler

WiseOwl COBOL (fresh judge, `--std 2014 --source-format free`): compiles with no diagnostic; the run prints `[ABCD]`,
exit code 0.

## Fix site

`cobc/parser.y` (read in the GnuCOBOL 3.2 release source (gnucobol-3.2.tar.xz)), rule `code_set_clause`: its only production is `CODE_SET _is alphabet_name _for_sub_records_clause`;
there is no alternative for `FOR ALPHANUMERIC IS` or `FOR NATIONAL IS`.

## Upstream state

Unreported; tracker not yet searched. NEWS mentions only the "testing support" of the CODE-SET clause for
ASCII/EBCDIC conversion; NEWS and TODO do not name the FOR phrases.
