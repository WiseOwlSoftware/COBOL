# PB396 — one quantifier, three verbs, and a rule that lives in a comment

## THE MECHANISM

`statementBlock : statement+` (`src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4:786-788`) is the right
cardinality; every USE of it writes `statementBlock*`, which restores the zero case the general formats forbid:

* `Core/CobolControlFlow.g4:134-138` — `ifStatement : IF condition THEN? statementBlock* (ELSE statementBlock*)? END_IF?`
* `Core/CobolControlFlow.g4:160-166` — `evaluateWhenClause : evaluateWhenPhrase+ statementBlock* | WHEN OTHER statementBlock* ;` under `evaluateWhenClause+`
* `Core/CobolControlFlow.g4:32-34` — `PERFORM performInlineHead? statementBlock* performWhenPhrase* … END_PERFORM`

In each printed general format the imperative statement is **unbracketed** (IF Format 1, EVALUATE's
imperative-statement-1 inside the outer brace, PERFORM Format 2 between the phrase bracket and END-PERFORM, and
PERFORM Format 3 on its own line above the WHEN group) or is a **brace alternative** (IF Format 2). §5.2.6.2
gives the omission licence to BRACKETED portions only and §5.2.6.3 requires one brace alternative to be
explicitly specified, so in every case it is required — and IF's §14.9.19.3 SR1 states the same thing a second
way as a cardinality ("one or more").

**EVALUATE's WHEN OTHER is the same flattening one level up.** The printed format ends
`[ WHEN OTHER imperative-statement-2 ]` — ONE optional phrase, AFTER the `{ … } …` repetition. Written as a
second ALTERNATIVE of a repeated `evaluateWhenClause`, it becomes admissible **any number of times and at any
position**, and the binder then compounds it silently: `EvaluateBinder.cs:36` does `other = body;` on every
WHEN OTHER it meets, so a second one overwrites the first and the first's imperative-statement-2 becomes dead
source that is never emitted and never reported. **The comment on that very line states the rule it does not
enforce** — `// WHEN OTHER — the else tail (SR: it must be last; later clauses would be dead)`. A rule written
in a comment is not a rule.

**And the flattening has a run-time consequence nothing else in the register charges.** When EVERY clause is a
WHEN OTHER, `EvaluateEmitter.Emit` takes `if (first) { Statements.EmitStatementList(other); return; }` — the
"only WHEN OTHER, emit unconditionally" shortcut — and `EvaluateBinder.Bind` never touches `subjects` at all, so
**the selection subject is not evaluated, not bound, and not even name-resolved**. §14.9.13.4 GR3 requires it to
be evaluated at the beginning of the statement's execution regardless of which arm runs.

the OTHER, which forces the subject through the binder:

```

$ cobol.exe s2B.cob --run   (twin)  → abnormal run-unit termination: EC-BOUND-SUBSCRIPT (fatal): subscript 9 …
```

whose run unit should have terminated abnormally per GR3, and instead imperative-statement-2 runs.

## THE CODE SITES, AND THE SHAPE OF THE REPAIR

* `src/Cobol.Net.Frontend/Grammar/Core/CobolControlFlow.g4:136` (IF, both arms), `:160-166`
  (`evaluateWhenClause`), `:32-34` (PERFORM's merged inline alternative);
  `src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4:786-788` (`statementBlock : statement+`).
* `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/EvaluateBinder.cs:28-38` (`other = body`, the unenforced rule
  in a comment); `src/Cobol.Net.Compiler/CodeGen/Verbs/EvaluateEmitter.cs:31-33` (the only-WHEN-OTHER
  shortcut); `ControlFlowBinder.cs#BindIf` (no cardinality check) and `ControlFlowEmitter.cs#EmitIf` (emits an
  empty C# block); `EcBinder.ExceptionPerform.cs` (COBOLNET1597 counts WHEN phrases but not imp-1).

**Repair (CLAUDE.md rule 5 — put the requirement where the format states it):**

1. `statementBlock+` on every arm that the printed format leaves unbracketed: IF's two, EVALUATE's WHEN clause,
   PERFORM's inline body. That is where the requirement lives, and it makes the next verb automatic.
2. **Lift `WHEN OTHER` OUT of `evaluateWhenClause`** into a single optional trailing element of
   `evaluateStatement`. After that the binder's `other` cannot be assigned twice, and the comment's rule becomes
   structurally true instead of unwritten.
3. **Delete the only-WHEN-OTHER emitter shortcut** (or make it bind and evaluate the subject first and then emit
   unconditionally). The subject's evaluation is GR3's obligation and is independent of arm selection; the
   shortcut is where a compile-time diagnostic and two fatal conditions are being lost.
4. Format 3 PERFORM needs the bind-time check too (the COBOLNET1597 site is the natural home) if the grammar
   arm stays merged.
5. A **drift test over the general formats**: for each unbracketed operand in a format, assert the empty case is
   REJECTED. Make it fail once against the six programs above.

⚠ **Decide the cross-format mixture explicitly, do not inherit it from the quantifier.** Because one grammar
rule covers both IF formats, `END_IF?` also admits `IF X = 1 NEXT SENTENCE END-IF` — NEXT SENTENCE is Format 2
only, END-IF is Format 1 only, and no single format shows the combination. It is accepted today and behaves per
GR4. That is an owner judgement about latitude, not a quantifier slip; record the decision either way.
