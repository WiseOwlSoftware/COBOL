# PB1840 — OPEN

Found by the PB1667 implementer (DEVLOG 1816). `WRITE A AFTER ADVANCING 1` leaves A's line open; `WRITE B BEFORE ADVANCING 1` then presents B on that same line. `SequentialConnector.Present` appends, so the bytes are `AB`, which is also what GnuCOBOL writes; `LinageConformanceTests` LNGBYF pins it. Read against §14.9.51.4 GR25 c)/e) (a zero advance is an overprint, which R54 now writes as a carriage return) the standard puts B at the same vertical position, i.e. overprinted from column 1 (`A` CR `B`). The owner decision R54 covers ADVANCING 0 only. To decide: whether a presentation onto an open line returns the carriage first (one rule, then AFTER 0 would not need its own return), and what that does to NIST print goldens and to the GnuCOBOL survey. Code site: `SequentialConnector.Present` / `WriteAdvancingRecord`.
