# PB6047 - suite 85 Stage 0: the status line `suite_status.py --edition 85` and the completeness report counted on the 1985 catalog's rows

Revision 4 of `docs/rearchitecture/DESIGN-conformance-suite.md` (§8 Stage 0, §13), decided in kb/Work PB6046.

The generator's completeness report counts the 2023 inventory's rows banded at 85 (33 of 1,870 observable) and never the
1985 catalog (3,109 rows, `inventory_view.inventory(1985)`), so the 85 suite has no true measure (measured 2026-11-22 at
608ccf507c; `m85b.py`: 46 rows with a suite test, 1,973 only an uncleared accepted test, 325 only a refusal test, 647 named
by no header, 113 derived, 5 non-support).

**Build:** (1) the report's 85 line counts the 1985 catalog's rows by witness kind, split as design §4.1 asks (uncleared
accepted / refusal only / no header); (2) `harness/suite_status.py --edition 85` prints one verdict line naming the four
terms of design §8 Stage 0 (rows, points, NIST, second compiler) and the transcription term (PB6051), each read from its
own tool; a term whose tool does not exist yet prints `UNMEASURED`, never 0 (an input a tool cannot resolve fails loudly);
(3) a self-test planting each term red; (4) the gate audit reads nothing new. Lands on its own tooling branch.

**Sites:** conformance-suite/harness/generate.py (completeness, print_report, generate); conformance-suite/harness/suite_status.py (status, module_term, transcription_term, second_compiler_term, verdict_line); docs/rearchitecture/DESIGN-conformance-suite.md (design sections 4, 4.1, 8 and 13)

**Lead carried (review R2-1 of suite85-replan):** the design's section 13 still says the revision-3 slices run "each
blocked by the one before"; since revision 4, S8 (PB4684) waits on the pilot (PB3178) and S5 (PB4683) on Stage 4
(PB4696). Correct that sentence in this note's change.

**Landed.** `generate.py`'s `completeness` counts an edition whose own text is held (`inputs.older`: 1985, 2002) on that
edition's catalog through `obligations.classify` (PB6048), and `print_report` prints it split: cleared test, only an
uncleared accepted test, only a refusal test, named by no header. `harness/suite_status.py --edition 85` prints each term
and one verdict line; at this landing: `=== SUITE 85: INCOMPLETE — rows 2961 · points UNMEASURED · NIST UNMEASURED ·
second compiler 484 · transcription UNMEASURED ===` (exit 1; COMPLETE is exit 0, a tool that exists and cannot answer is
exit 2). Points and NIST read `coverage.py` and `crosswalk.py` `unmet(edition)` once PB6050 and PB6049 create them; the
transcription reads the ledger's `second_pass` `{pages_swept, findings}` once PB6051 records one. Self-tests: `selftests/suite_status/test_suite_status.py` plants each term red, the unmeasured term, a tool that cannot answer and a malformed second pass;
`generate.py --self-test` pins the catalog-counted edition. The gate audit reads nothing new. Design section 13's
revision-3 sentence now names S8 (PB4684) behind the pilot and S5 (PB4683) behind Stage 4.
