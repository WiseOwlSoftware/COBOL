# PB1725 — OPEN

Filed by the train-71 lander from wave 71 group D's report (`w71d-PB1718-report.md`, new lead 2), with a second
witness from the train-71 lander itself.

## Finding

The P14 rule (never chain a step after a verdict command) is enforced by `scripts/hooks/forbidden_commands.py`. Its
verdict-command classifier matches the verdict tool's NAME anywhere in a command segment, including in the arguments
of a read-only command, so it blocks legitimate chains:
- `grep -n "dotnet test" scripts/x.sh; echo ---` is blocked (group D).
- `sed`/`grep` on a file whose name contains `build-local.ps1` is blocked (group D).
- The train-71 lander's `sed -i "…NEXT: apply D (overlaps battery.sh, …)" STATUS.md; git add -A …` was blocked as
  "chained after the verdict command `sed -i …`" — the verdict name `battery.sh` appeared only inside sed's script.

**Cost.** Each false block costs a turn, and the agent-cost model is quadratic in turns (P14's own measurement).

**Code site.** The verdict-command classifier in `scripts/hooks/forbidden_commands.py`; its self-tests are
`scripts/hooks/test_forbidden_commands.py` (run in CI `audits`).

**Fix shape.** Classify by the command WORD in command position (the segment's executable, or the script a
`bash`/`pwsh`/`python` runner is given), never by a substring of the whole segment; add each repro above as a
negative self-test case.
