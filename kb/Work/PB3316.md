# PB3316 — PowerShell pipeline input inside a script block is not modeled as stdin

## Found (PB3198 finisher, w1101a, 2026-10-16)
Report: `E:\COBOL-coord\scratch\reports\w1101a-PB3198-report.md`, "New defects (note-ready)". The enqueue unit
allocated PB3316 for this lead. The loop resume unit filed it on 2026-10-16 after reproducing it on main at
00431a624, after PB3198 had landed (#167).

## Repro
Feed the hook the PowerShell tool input on stdin:
- `{"tool_name":"PowerShell","tool_input":{"command":"'git stash' | & { $input | iex }"}}` →
  `python scripts/hooks/forbidden_commands.py` exits 0 (allowed).
- `{"tool_name":"PowerShell","tool_input":{"command":"'git stash' | ForEach-Object { $_ | iex }"}}` → exits 0.
- `{"tool_name":"PowerShell","tool_input":{"command":"git stash"}}` → exits 2 (blocked). Rule 1 does forbid the
  command when it is written directly.

Both piped forms run `git stash`. The string reaches `Invoke-Expression` through `$input` or `$_`, and those are
the script block's pipeline input.

## Mechanism
`scripts/hooks/shell_location.py` models stdin as the upstream stage that a group hands its inner walk (PB3198 R3-1,
`_walk(..., stdin)`). A PowerShell script block that is a pipeline reader (`& { }` or `ForEach-Object { }` on the read
side of a `|`) gets an empty `()` stdin in the substitutions loop of `_command`. `_output` never spells `$_` or
`$input` as a stage. So `iex`, which runs its stdin, sees no command, and rule 1 never sees the `git stash`.

## Fix shape
Hand a pipeline-reader script block's walk the upstream stage as `fed`, and have `_output` read `$_` and `$input` as
that stdin. Add both repros to the forbidden_commands self-test as blocked cases. Sweep for siblings: `Foreach-Object`
and its alias `%`, `Where-Object` and `?` with a script block, and `-Process { }`.
