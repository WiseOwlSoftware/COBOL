# PB5085 - at --std 85 COPY ... REPLACING COPY BY ... and a REPLACE statement not preceded by a separator period compile: the COPY operand reader never excludes the word COPY and REPLACE asks only the 2023 space rule

**Sites:** `src/WiseOwl.Cobol.Frontend/Preprocessor/CopyProcessor.cs#ReadOperand` (the identifier/word arm takes any character-string), `src/WiseOwl.Cobol.Frontend/Preprocessor/CopyProcessor.cs#ApplyReplaceStatements` (asks only §2023:7.2.4.3 SR2, "preceded by a space").

**Mechanism.** 1985 says word-1 and word-2 of COPY REPLACING may be any single COBOL word except COPY (XII.2.3 SR6), and that a REPLACE statement must be preceded by a separator period except when it is the first statement of the source (XII.3.3 SR1). ReadOperand has a nested-copy arm only for pseudo-text and never tests the word form; ApplyReplaceStatements applies the 2023 space rule at every edition, and the record says the 2002 and 2014 editions accept the COPY form too.

**Found by.** The 1985 `--std=85` draft triage (kb/Work PB4995 item 3): each rule below is a conformance-suite draft that did not MATCH at `--std 85`, and its adjudicator decided COMPILER-DEFECT. Harm and observed text are the records'; nothing here was re-derived.

**Inventory.** The traceability inventory carries no 1985 rows yet, so `inventory_rows` is empty; the rows this note covers are the 1985 rule ids listed below (catalog `docs/rearchitecture/spec-rule-catalog-1985.json`).

**Rules (2; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-SR-XII.2.3-6` - `§1985:XII.2.3 SR6` (record harm: under-rejects, slice-13): §1985:XII.2.3 SR6: "Word-1 or word-2 may be any single COBOL word except 'COPY'." In COPY LIBA REPLACING COPY BY DISPLAY. the operand before BY is word-1 of the general format (§1985:XII.2.2) and it is the word COPY, which the rule excepts; a program holding it violates an explicitly stated syntax rule and is not a conforming source program (§1985:I.1.6: "A conforming source program is one which does not violate the explicitly stated provisions and specifications of Standard COBOL."). The draft reads the rule correctly and its marked line is right. (The draft supplies no library text, so as submitted its control failed on CBL3620 'LIBA not found'; with the text its own comment describes supplied as LIBA.cpy, the control compiles and displays OK, and the violating program is the mismatch.)
- `1985-SR-XII.3.3-1` - `§1985:XII.3.3 SR1` (record harm: under-rejects, slice-09): §1985:XII.3.3 SR1: "A REPLACE statement may occur anywhere in the source program where a character-string may occur. It must be preceded by a separator period except when it is the first statement in a separately compiled program." In `DISPLAY "A" REPLACE ==XX== BY =="B"==.` the REPLACE statement follows the literal "A" and a space, not a separator period, and it is not the program's first statement; a syntax rule, so the program is refused. The draft reads it correctly and marks the line that holds the statement.

**Expected (from the 1985 text).** --std 85 refuses `COPY LIBA REPLACING COPY BY DISPLAY.` and a REPLACE that does not follow a period. The deciding words: "Word-1 or word-2 may be any single COBOL word except 'COPY'." (§1985:XII.2.3 SR6).

Line 8 (COPY LIBA REPLACING COPY BY DISPLAY.) draws nothing. The control (REPLACING ZERO BY ZEROS) compiles and displays 'OK'. SIBLINGS RUN at --std 85, all exit 0 with no diagnostic: COPY as word-2 (REPLACING ZERO BY COPY); COPY as word-1 of a later pair (REPLACING ZERO BY ZEROS COPY BY ZERO). The same program is accepted silently at --std 2002 and --std 2014, whose text keeps the rule (§2002:7.1.2.2 SR10: "Word-1 or word-2 may be any single COBOL word except 'COPY', the compiler directive indicator, the floating debug indicator, or the comment indicator."); --std 2023 refuses the word operand itself (COBOL0902).
