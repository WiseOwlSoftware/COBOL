# PB4417 — the unbounded-argument early return in AlignmentMayLeaveCarrier assumes a value that RANGE does not have (SUSPECTED)

**Found:** by the round-1 review of PB4370's branch (R1-1 LEAD, low, not blocking). Harm flags are false because this is
suspected: no probe was compiled for this note, and the mechanism below is read from the code only.

**Site (re-read on origin/main d0b7ed0e2):** `src/WiseOwl.Cobol.Compiler/Binding/Bound/IntrinsicCarrierRules.cs`
`AlignmentMayLeaveCarrier` (~148-161): `if (bounds.Any(t => t is null)) return true;`, added by PB4370 so that one
argument whose aligned bound is past UInt128 sends the whole RANGE, MIDRANGE or MEDIAN list off the native Int128 arm.

**The premise.** The method's own comment (~128) justifies routing the summing family to the SDIDI body because "the
summing family's value ... is as large as its arguments, so every digit a receiver can store (<= 31) lies inside the
SDIDI's 34". That holds for SUM, MEDIAN and MIDRANGE. It does not follow for RANGE, which is max minus min: for
`BIG PIC 9(31)` beside `FR PIC V9(18)` the exact difference has up to 31 integer plus 18 fraction digits, and the SDIDI body
keeps 34. If the SDIDI body rounds to its 34 digits before the receiver's own rounding, a value near a rounding boundary
can round differently from the exact value, and a carry can reach the integer digits; that is the hazard for which the code
keeps MOD and REM loud. Whether the SDIDI body does round at 34 before the receiver does, and whether a conforming program
can then see a different last digit or an integer carry, is the open question.

**Next step.** An adjudicator derives the expected value from the ISO spec (the RANGE function and the rounding of a
function value into a receiver; cite with `cite.py --check`) and compares it with the SDIDI body's answer for a RANGE list
with one wide and one fractional argument. If they differ the note becomes wrong_answer and the fix is to keep RANGE off
the early return (or carry the exact difference). If they agree, the comment at ~128 is narrowed to say why RANGE is safe
and the note closes. Related: PB621, PB4370.
