## Mechanism — value-clause-p2
THE GRAMMAR ORDERS FORMAT 3's TWO TRAILING PHRASES BACKWARDS. The printed general format (PDF p.546 = printed 516, rendered at 200dpi) puts `[ IN alphabet-name-1 ]` at the END OF THE FIRST LINE, after the repeated literal group, and `[ WHEN SET TO FALSE IS literal-4 ]` on the CONTINUATION LINE below it -- so in a general format's reading order IN alphabet-name-1 precedes WHEN SET TO FALSE. src/Cobol.Net.Frontend/Grammar/Core/CobolData.g4:621-624 writes them the other way round: `... valueItem (...)* (WHEN SET TO FALSE_ IS? literal)? (IN IDENTIFIER)?`. The consequence is symmetric: the standard's order is a hard parse error, and an order the standard does not print is accepted.

### Expected, from the standard
13.18.63.2 Format 3, as printed: `{ VALUE IS / VALUES ARE } { literal-2 [ { THROUGH / THRU } literal-3 ] } ... [ IN alphabet-name-1 ]` on the first line, with `[ WHEN SET TO FALSE IS literal-4 ]` printed beneath it. A general format is an ordered sequence, and a construct on a continuation line follows everything on the line above, so `88 C VALUE "Z" THRU "X" IN MYALPH WHEN SET TO FALSE IS " ".` is conforming source and shall compile; `88 C VALUE "Z" THRU "X" WHEN SET TO FALSE IS " " IN MYALPH.` is not.
