# PB4773 - the function twin of a refused REPOSITORY literal falls back to the word, so a refused literal-5 draws a REPO-1 whose sentence says the name sought is the word the source never said

**What the report says (the reviewer's words).** R1-3 LEAD (low, not blocking at round 1): src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs:503 The function twin of the refused literal falls back to the word (BindSpecifierExternalizedName ... ?? fn.GetText()), so a refused literal-5 also draws a REPO-1 whose sentence says the name sought is the word, which the source never said.

**Resolution.** Reproduced on the build (wave 20261881 h), and wider than the lead: FUNCTION F AS "", PROPERTY P AS "", CLASS K AS "" and INTERFACE I AS "" each drew COBOL1761 (SR2) AND a COBOL5962 whose sentence named the word (or an AS "WORD" the source never wrote). Fix in `DataBinder`: a refused literal registers no `FunctionSpecifier`, defers no SR16 property check, and skips the SR6 / SR9 class and interface searches; the word stays declared. The `?? word` fallback is gone. Test: `ExternalRepositoryResolutionTests.ASpecifierWhoseLiteralIsRefused_DrawsNoRepo1ForTheWordTheSourceNeverGave`. A call of the refused function word still draws COBOL1505 (the true "no prototype" sentence). Sites added by the fix: `tests/WiseOwl.Cobol.Tests.Conformance/ExternalRepositoryResolutionTests.cs`; in DataBinder.cs the PROPERTY, CLASS and INTERFACE arms beside the FUNCTION arm.
