# PB3778 — render each role's practice rows into its dispatch; the whole file reaches nobody

**Sites:** `.claude/skills/workstream/make_dispatch_specs.py#render`, `.claude/skills/workstream/make_dispatch_specs.py` (a `practices(role)` reader of the rows file), `.claude/skills/workstream/check_practices.py#BRIEFS`, `.claude/skills/workstream/check_practices.py#check`, `.claude/skills/workstream/templates/MANDATORY-PRACTICES.md` (the "Public skills by role" table, P10, O1), `.claude/skills/workstream/templates/dispatch-spec-implementer.md`, `.claude/skills/workstream/templates/finisher-brief.md`, `.claude/skills/workstream/templates/golden-lane-brief.md`, `.claude/skills/workstream/templates/registrar-brief.md`, `.claude/skills/workstream/templates/implementer-report-template.md` (the self-review section's checklist), `.claude/agents/cobol-implementer.md`, `.claude/agents/cobol-finisher.md`, `scripts/orchestrator/units/wave.md`, `scripts/orchestrator/units/enqueue.md`

## Measured

The file is the ONE home of the rules (owner 2026-09-23) and every brief opens with "read it WHOLE". What happens:
implementers `cat` it, the harness persists the output and shows a 2 KB preview (16 of 22 that touched it), and the
agent greps the rows the spec cites; one agent's own grep names the implementer's set, `P2|P4|P5|P10|P11|P13|I1|I2|I7|I8|I9|I10|I11|R3`.
Finishers read it whole, 7 of 7, twice in 5 of them (82.7K tokens re-read), 17,484 tokens a read for the finisher's
rows (P1-P14 and L1-L13 as they bind it) of about 4K. P10's reading list (three to five public skills and four agent
files, about 25K tokens if read) was followed by 4 of 27 implementers for any `SKILL.md` and 4 for the agent files, at
turns 159-160 of 197; by no finisher. The orchestrator's own session read the file twice too (16.7K tokens, 4.3 % of
its input).

Saving: finisher reads about $28 a week, implementer preview-and-grep turns about $7: **about $35 a week**. The gain
is larger than the saving: a rule that reaches the agent as text in its one dispatch file is the only form the
measurement shows being acted on (the spec's rules, orient.py 23/27, drift_rules.py 27/27, cite.py 19/27), while a rule
behind a "read this file" pointer is not (P10 4/27, P13 0/27).

## Fix

The file stays the one home; the renderer slices it. `make_dispatch_specs.py` gains `practices(role)`: the rows of
"All roles" and of the role's own section, read from the file by row id, rendered into the spec in place of the
pointer sentence ("the standing rules are in MANDATORY-PRACTICES; the ones that bind you follow"), the "Why" column
left out (the reasons stay in the file for the orchestrator and the reviewer). The finisher brief is rendered the same
way (`make_dispatch_specs.py --role finisher` writes the finisher's dispatch file from `finisher-brief.md` plus its
rows; the enqueue unit dispatches that file), and the golden and registrar briefs likewise. P10 becomes a two-line
checklist in the spec, written from what the public skills add beyond the project's rules and the measurement shows
being used: the sibling-sweep query forms (variant-analysis: name the mechanism, query every arm and every place the
rule is written, report the sweep so a zero is evidence) and the self-review questions of the four agent files, each
as one line in the report template's `## Self-review` section; the reading list itself is dropped from P10 (the public
base supplies the method to the orchestrator and the reviewer, who load it as a skill). The orchestrator's units read
their rows the same way (`practices(orchestrator)`), never the whole file.

Guard (O1): `check_practices.py` reads the rows file and asserts, for every rendered spec and brief, that every row id
of "All roles" and of the role's section appears in it with its text as the file states it (collapsed whitespace, the
same comparison `specs_missing_requirements` makes), so a row added to the file reaches the next dispatch
automatically and a row dropped from a render is RED; the P10 checklist lines are patterns in `BRIEFS` for the spec.
`turn_cap_copies` keeps its role.

## Acceptance

A rendered implementer spec carries P1-P14 and I1-I11 and R3 verbatim and no "read WHOLE" sentence; the finisher's
dispatch file carries its rows; `check_practices.py` is RED when one row is removed from a render and GREEN otherwise;
over the next wave the measurement's S2 table shows no `cat` of the file by any implementer or finisher and the
finisher's instruction share under 3 % of its USD.
