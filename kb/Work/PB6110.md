# PB6110 - a pending unit takes the last FEATURE or ANSI-REFERENCE in its window

Re-verified on main ae1136f781. `conformance-suite/harness/crosswalk.py` (the event loop, lines 123-152) sets `pending = unit` at a unit's init-paragraph `PAR-NAME` move and clears it only
at the next `paragraph` event. The R1-1 fix of PB6049 then rewrites the unit's recorded `(lines, feature, reference)` at EVERY later `feature` or `reference` event while it is pending
(line 151: `if pending and kind in ("feature", "reference"): prog.units[pending] = (..., feature, reference)`). A CCVS init paragraph moves PAR-NAME, ANSI-REFERENCE and FEATURE in either order, which is why
the window exists; but every later move in it also overwrites the unit's own:

- a second FEATURE line of the same test (a continuation print line),
- a FEATURE move inside the test paragraph's failure branch before the next paragraph header,
- the next unit's FEATURE moved just before that unit's PAR-NAME move, in the same paragraph.

Self-test case 16 (`conformance-suite/harness/selftests/crosswalk/test_crosswalk.py`) pins one move per window only.

**Failure scenario.** A unit's candidate rows are read from the wrong FEATURE text or the wrong ANSI-REFERENCE, so the unit is mapped (or left `ambiguous`/`unmapped`) from words that belong to its
neighbour: a silent misclassification in the 7,101-unit crosswalk that PB4696's adjudication then starts from.

**Sites:** `conformance-suite/harness/crosswalk.py` (`parse_program`), `conformance-suite/harness/selftests/crosswalk/test_crosswalk.py` (`case_17_...`), `tests/nist/crosswalk/*.json` (9 files regenerated, the adjudicated NC115A kept). Files:
- `conformance-suite/harness/crosswalk.py` (the event loop; line 151)
- `conformance-suite/harness/selftests/crosswalk/test_crosswalk.py` (case 16)

**Next:** bind a unit's FEATURE and ANSI-REFERENCE once, at its own window (the moves between its PAR-NAME move and its test paragraph header, with the moves before the PAR-NAME move
since the previous paragraph belonging to the unit that follows), instead of overwriting; add self-test cases for the three shapes above.

**Landed:** `parse_program` binds a unit's FEATURE and ANSI-REFERENCE once: the moves since the last boundary (paragraph header or previous unit's PAR-NAME move) are its own, a slot none filled takes the FIRST move before the next paragraph header, later moves are the next unit's. Self-test case 17 pins the three shapes; 9 crosswalk files regenerated (`--build` also rewrote the adjudicated NC115A entries, which were restored: `--build` overwriting adjudicated entries is registered in the report).
