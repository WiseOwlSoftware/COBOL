# PB219

Found by the cluster-B review fleet on the pre-commit [[PB169]]–[[PB172]] tree, 2026-08-31.

**THE FOUR SITES**, enumerated rather than assumed (the finding as first written said "two arms"):

  1. `ExpressionBinder.ScreenIndexNameOperand` (R16) — an unconditional `Edition.Error`. Callers: DISPLAY, MOVE,
     STRING, and now the STOP RUN / GOBACK status operand.
  2. `InspectBinder`'s identifier-1 screen — an unconditional `Edition.Error`.
  3. `ExpressionBinder.IndexNameExpr` (R29) — `--permissive` WARNS and coerces to the occurrence number (the
     documented GnuCOBOL extension), strict rejects.
  4. `ReferenceResolver.ResolveSubscriptName`'s new ref-mod arm ([[PB170]]) — an unconditional `Edition.Error`.

Site 4 is the one PB170 added, and it took site 1's posture while the SAME POSITION's other route took site 3's:
`RenderSegment` hands a slash-bearing (or function-bearing, or `**`-bearing) segment to the D18 materializer,
which binds a ref-mod bound with `Expr.BindExpr` → `OperandContext.Arithmetic` → `IndexNameExpr`.

**MEASURED before the fix** (`--std 2023 --permissive`): `MOVE W(IX:2) TO R2` failed with COBOLNET1637 as an
ERROR, while `MOVE W(IX / 1:2) TO R2` warned COBOLNET1637 and ran. Under strict both correctly rejected.

## The disposition, decided once and written down once

**The lane posture follows the SLOT KIND, never the site or the route.** The clause that settles which kind a
ref-mod bound is: §8.4.3.3.3 SR4 — "Leftmost-position and length shall be arithmetic expressions" (`cite.py`
OK). So the ref-mod bound is R29's family, not R16's.

  * **An ARITHMETIC position** (sites 3 and 4): strict REJECTS with the r7 citation; `--permissive` WARNS and
    computes the occurrence number. The emit floor is identical in both lanes — the fast path renders the index
    field either way — so the leniency costs nothing.
  * **An IDENTIFIER slot** (sites 1 and 2): an unconditional Error in BOTH lanes, and **the reason is now
    written at both sites**: the slot needs an IDENTIFIER and an occurrence number is not one, so there is no
    coercion to offer. `dialect_two_axes` constrains the leniencies this compiler implements; it does not
    require inventing one. That was the missing half — the two postures PREDATE the wave, and what was absent
    was not a lane but a stated reason, so the split read as an oversight.

**FIXED BY:** `ReferenceResolver.IndexNameInPositionError` — the dialect-gated arm, with the four-site table in
its doc comment — plus the written reasons at `ScreenIndexNameOperand` and in `InspectBinder`.

**MEASURED AFTER:** strict — both `W(IX:2)` and `W(IX / 1:2)` are COBOLNET1637 errors; `--permissive` — both are
COBOLNET1637 warnings, both compile, and both print `RM=BC`, i.e. the coercion computes occurrence 2 on BOTH
routes. One rule, one disposition, two routes, one answer.

**PINNED BY:** `ArithmeticOperandClassTests.R7IndexNameInARefModBound_HasOneDispositionOnBothRoutes` — four rows
(two shapes × two lanes), which is the first `--permissive` pin COBOLNET1637 has ever had in either of its
dialect-gated homes. The strict fixture `pb170-refmod-index-name` is unchanged.

**DIFFERENTIAL REACH: NONE, by construction.** `scripts/gnucobol_differential.py`'s `compile_once` invokes the
compiler as `[exe, src, '--std', std, '-o', out_dll]` and never passes `--permissive`, so no differential cell
can observe a permissive-lane change (recorded in [[PB169]]'s owed-list, bucket 7).

## The residue this does NOT close

The funnel entry table in `docs/rearchitecture/DESIGN-binder-bound-tree.md` gives the ref-mod bound two rows —
the D18 route and the token-renderer fast path — and the fast-path row declares only axis A, because the fast
path's index-name screen is not in `ScreenPositionOperandClass` at all; it is the separate `TryResolveIndex` arm
fifty lines above. The table exists so that "no slot acquires a rule by default", and it had a slot whose axis-B
posture was undeclared. The lane column is now stated in the code at all four sites; folding it into the design
table's own columns is the durable form and is noted there.
