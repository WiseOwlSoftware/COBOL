# PB4045 — an interrupted fuzz night is recorded as a full one

**Sites:** `scripts/fuzz_history.py` (the night record built from `run.json`, `"hours": meta.get("hours")`),
`scripts/fuzz_night.ps1` (the launcher's log)

**What happened.** Night 8 (`fuzz-20261028-210601`, started 2026-10-28 21:06 PDT) stopped writing at 02:29 when the machine
rebooted: about 5.4 of its 8 planned hours. The launcher log `scratch/fuzz-night-20261029.log` has its two start lines and
nothing else, so a run killed by a reboot looks exactly like one still running; the session had to check the harness pid
and the files' modification times to tell. `fuzz_history.py history --write` then recorded `"hours": 8.0`, the PLANNED
budget from `run.json`, so the history and the page say the night ran 8 hours.

Every program is judged and written as it completes, so the night's results are whole per program and the triage was
valid (4350 judged, 0 WiseOwl defects, 5 upstream records PB4040-PB4044). Only the run's duration and its end state are
wrong.

**Fix.** The harness (or launcher) records the run's end (`ended`, and `completed: true|false` with the reason) in
`run.json`; `fuzz_history.py` records the measured duration and marks an incomplete night as such on the page, and the
morning tooling (`fuzz_triage.py prepare`) says plainly when the run it prepares did not finish.
