The implementor determinations already written: **DOC-A.1-157** (docs/CONFORMANCE.md) — a character position is one
UTF-16 code unit, **except a horizontal tab (U+0009), which advances to the next tab stop — positions 1, 9, 17, 25, …
(tab width 8, GnuCOBOL's default `tab-width`)**; a line is the text between two line terminators (item 156: LF, or
CR LF); a free-form line has 0–255 positions; fixed-form positions 1–6 / 7 / 8–72, a short line read as space-filled
to margin R. So the tab WIDTH is settled (rule 1 precedence, already documented) — only the tab-INSIDE-A-LITERAL
question is open (owner decision in PB1586's brief).

**GnuCOBOL 3.2 (read-only facts, `cobc/pplex.l`):** `ppinput` expands every TAB of every physical line — source and
copybook alike, before any scanning, so inside a literal too — to spaces up to the next multiple of `cb_tab_width`
(`config/*.conf`: `tab-width: 8` in every dialect, range 1–12); a CR not followed by LF is kept as a character (it is
not a line terminator); the auto-format probe (`ppopen_get_file`) expands tabs the same way before it looks at
column 7.

## Today's code (4a1dda60e) — raw lines indexed in many places

The raw decoded text (`CompilationInputs.ReadAllText` → `File.ReadAllText`) is split and indexed independently by:

- `src/Cobol.Net.Frontend/Preprocessor/ReferenceFormatProcessor.cs#StripNistArchiveMarkers` — `Split('\n')`, every
  compilation (not only `--nist`: PB1803);
- `#NormalizeToFreeFormMapped` — `sourceText.Split('\n')`;
- `#FirstSourceDirectiveCandidate` and `#DirectiveText` — `TrimEnd('\r')`, `line[IndicatorColumn]`,
  `ProgramTextArea(line)`;
- `#IsFixedForm` — its own `Split('\n')`, `TrimEnd('\r')`, `line[IndicatorColumn]`, `line[72..]`;
- `ReferenceFormatProcessor.LogicalConversion.cs#FixedFormConverter.Convert` — a THIRD `Split('\n')` + `TrimEnd('\r')`
  per fixed segment (segments are re-joined with `string.Join('\n', lines[a..b])` only to be split again);
- `#ConvertFreeFormMapped` — a fourth `Split('\n')`; `#ConvertFreeLine` gets the raw line.
- Library text enters the same walker (`CopyProcessor.cs#NormalizeCopybookMapped`), and the legacy oracle calls it
  too (`src/CobolSharp.Compiler/Compilation.cs:339-340`, `src/CobolSharp.CLI/Program.cs:131-132`).

No stage expands a TAB, so a TAB counts as ONE position (probe `tab1.cob`: `<TAB><TAB>DISPLAY "TAB-OK".` →
COBOLNET2616 "column 7 holds 'L'" + COBOL0001 at `--std 85` and `2023`), and a TAB inside a literal is kept as the
character U+0009 (probe `tab_lit.cob`: `DISPLAY "[A<TAB>B]"` prints a raw tab). Nothing checks the free-form 255
limit (PB1496), and the lone-CR question is answered differently by this stage (LF only, CR before LF trimmed) and the
lexer (`CobolLexer.g4` treats a lone CR as a line end — PB1496's step-3 section).

## The gap

There is no single place where "a physical line" is defined, so each of the four determinations above (tabs,
terminators, length, archive markers) would have to be written into every splitter, and the physical column a
diagnostic needs (PB1801) is lost at the first `Split`.

## The proposed structure (rule 5 — one stage, every caller changes, no shims)

**`PhysicalLines` (new, `src/Cobol.Net.Frontend/Preprocessor/PhysicalLines.cs`)** — the ONE line-entry stage:

```
PhysicalLines.Read(string decodedText, string file, bool ccvsIndicators) -> PhysicalLineSet
record struct PhysicalLine(int Number, string Text, TabStops? Tabs)   // Text: terminator removed, TABs expanded
```

1. **Terminators** (item 156): split on LF; a CR immediately before LF is part of the terminator; a lone CR is a
   character of the line (GnuCOBOL) — and the lexer's lone-CR line end is removed in the same change (PB1496).
2. **TABs** (item 157): each TAB becomes 1–8 spaces to the next tab stop (positions 1, 9, 17, …). The line keeps a
   `TabStops` map (expanded position → physical character index) ONLY when it held a TAB, so the common line costs
   nothing. Inside a literal: per the owner decision in PB1586's brief (recommended: expand, as GnuCOBOL does).
3. **CCVS archive markers** (`*HEADER,` / `*END-OF,`): blanked here, and only when `ccvsIndicators` (PB1803).
   `StripNistArchiveMarkers` is DELETED and its three callers (Frontend.Normalize and the two legacy ones) change.
4. The set is what EVERY consumer reads: `IsFixedForm` (Auto), `FirstSourceDirectiveCandidate`, `FormatSegments` /
   `DirectiveText`, `FixedFormConverter` (per segment it takes a `ReadOnlySpan<PhysicalLine>`, never a re-joined
   string), `ConvertFreeLine`, and the free-form 255-position check (PB1496 — asked in the FREE arm on the expanded
   length, since a fixed-form line past margin R is legal and only its program-text area counts).
5. `ReferenceFormatProcessor.NormalizeToFreeFormMapped(string …)` becomes `(PhysicalLineSet …)`; the string overloads
   `NormalizeToFreeForm(string, …)` / `ConvertFixedToFree(string)` are deleted or re-pointed so no caller can bypass the
   reader (sweep `tests/Cobol.Net.Tests.Unit` — the unit tests call them directly).
6. The produced `MappedText` carries the physical columns (PB1801) — the reader is where they are born.

**Drift tests.** (a) An architecture test over `src/Cobol.Net.Frontend/Preprocessor/*.cs`: no `Split('\n')` /
`TrimEnd('\r')` / `IndexOf('\t')` outside `PhysicalLines.cs` (the same grep-shaped drift test PB1660 proposes for
`char.IsWhiteSpace`). (b) A unit property: for every generated line, `PhysicalLine.Text` holds no U+0009 and
`Tabs.ToPhysical(Tabs.ToExpanded(i)) == i` for every physical index. (c) Goldens (fixed form): TABs in the sequence
area, in the indicator column (a TAB at column 1 lands the next character on column 9, inside Area A — columns 8–11 —
so `<TAB>PROCEDURE DIVISION.` is a header in Area A with a SPACE indicator, and `<TAB><TAB>DISPLAY` starts in
column 17, Area B), a TAB after six sequence digits (`000100<TAB>` → the TAB fills column 7 and the next character
is column 9), in Area B, and in a literal; free form: a line of 255 positions (accepted) and
256 (diagnosed).

**Sizing.** The reader + re-pointing the five consumers is ONE Sonnet slot once the owner answers the literal
question; it must land BEFORE PB1801 (columns) and together with PB1586 / PB1803. PB1496's terminator + length halves
ride it (same slot if the lone-CR lexer change is small — it is one lexer rule).
