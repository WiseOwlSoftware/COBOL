# PB5866 - at `--std 85` `CONTROLS ARE B R66`, where `66 R66 RENAMES B`, compiles

**Ruling: UPHELD (a), harm under_rejects.** `CONTROLS ARE B R66`, where `66 R66 RENAMES B`, compiles at `--std 85`: the screen that refuses `CONTROLS ARE B B` compares the two resolved entries, and a level-66 entry is another entry. Severity MINOR. Cause (a): wrong at 85 only. The row `1985-SR-XIII.3.7.3-2` does not close on its inherited verdict. It was one of the five rows of 1985 whose first read was contradicted under kb/Work PB5801 (the places of level-66 items), read again after that note's fix landed (pull request 1769), on a compiler built at main 3fd4a31c0d (the Mythos lane's run wf_204d09be-ed1 of the operator's workflow; kb/Work PB5854). The Mythos lane checked it itself, on the same compiler with the tracked probe runner, at `--std 85`; no separate checker ran.

**Mechanism 2, ruled from the text.** `§1985:XIII.3.7.3 SR2` says "Each recurrence of data-name-1 must identify a different data item" (cite.py OK). A level-66 entry with no THROUGH phrase is the same data item under another name: `§1985:VI.5.11.4 GR2` says "all of the data attributes of data-name-2 become the data attributes for data-name-1" (cite.py OK), and it describes the same storage. So `B` and `R66` identify one data item and the clause is to be refused, as `CONTROLS ARE B B` is. A level-66 entry WITH a THROUGH phrase is a group of its own (GR1), and an item that REDEFINES another has a description of its own: neither is the same data item, and the refuter's program that passes those is right. The screen runs below 2002 only (`ReportSectionBinder.cs#ScreenControlItemsDistinct`, the refuter's reading of the code); what 2002 and 2023 require is not ruled here. GnuCOBOL has no check of this rule at all (its parser checks only that the CONTROL clause is not repeated), so it settles nothing; the text does.

**Where:** `src/WiseOwl.Cobol.Compiler/Binding/ReportSectionBinder.cs#ScreenControlItemsDistinct` (the refuter's reading of the code): it compares the resolved entries of the CONTROLS names, and a level-66 entry without THROUGH is a different entry from the item it renames.
