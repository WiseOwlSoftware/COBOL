defects" (3) — `scratchpad/reports/PB389-report.md`. **Re-probed on this worktree's own build at `d3ba5795`.**

these two rules and an implementation is the declaration.

## The rules, quoted, from the transcription

> 20) Identifier-12 shall reference a data item of category function-pointer. Identifier-13 shall be of category
> function-pointer. Identifier-13 shall be the predefined address NULL or shall reference a function-pointer.
> The function-prototypes associated with identifier-12 and identifier-13 shall have the same signature.
>
> 22) If identifier-7 references a restricted program-pointer, identifier-8 shall be the predefined address NULL
> or shall reference a program-pointer and the program-prototypes associated with identifier-7 and identifier-8
> shall have the same signature.

`--check` lines, re-run rather than inherited from the rows' notes:

```
$ python scripts/spec/cite.py --check 14.9.39.3 "Identifier-12 shall reference a data item of category function-pointer"   -> OK  §14.9.39.3 20)
$ python scripts/spec/cite.py --check 14.9.39.3 "the program-prototypes associated with identifier-7 and identifier-8 shall have the same signature"  -> OK  §14.9.39.3 22)
```

**They are the same rule twice.** "The *X*-prototypes associated with the two identifiers shall have the same
signature", over function-prototypes and program-prototypes. Writing it twice is how the two copies drift
(`feedback_one_rule_one_place`).

## Code site

- `src/Cobol.Net.Compiler/Binding/PictureAnalyzer.cs:554-560` — the FUNCTION-POINTER arm of `ParseUsage`,
  `DiagnosticCatalog.UsageFunctionPointer`, with the comment *"recognized, STAGED LOUD (function prototypes =
  P13)"*.
- the PROGRAM-POINTER `TO` arm of the same method (COBOLNET0899, "ISO 13.18.60 GR25").
- Grammar already parses both: `src/Cobol.Net.Frontend/Grammar/Core/CobolData.g4:545` / `:571`
  (`functionPointerUsage`, `programPointerUsage`) — *"superset parse; semantics STAGED LOUD"*.
- **The template is `POINTER TO`**, landed by [[PB153]] with §13.18.60.3 SR18's TYPEDEF requirement enforced as
  COBOLNET0881 — same USAGE-tail shape, same restriction model.

## The other end, which a fixer will otherwise miss

`SetBinder`'s category re-route (`BindSetTo`) tests `Pointer`, `ProgramPointer` and `ObjectReference` and stops
(`SetBinder.cs:63-64`, `:240-299`). **There is no function-pointer arm at all**, so even a declarable
function-pointer would fall through into the Format-1 arithmetic store — a silent wrong answer waiting behind
the loud one. Format 8 must acquire its re-route in the same change set as the declaration.
