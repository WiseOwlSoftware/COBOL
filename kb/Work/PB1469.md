# PB1469 — LANDED

## Landed (wave 65, group A)

The relation between two same-type strongly-typed groups is no longer a whole-group IMAGE comparison. The ONE relation
construction site (`ConditionBinder.CheckedRelational`) asks the ONE pair classifier (`RelationPair.Classify`,
`src/Cobol.Net.Compiler/Binding/RelationPairShape.cs` — Flat · StrongElementOrder · VariableLengthGroup) and lowers a
strong pair (`StrongGroupComparison`, `Binding/Procedure/Verbs/StrongGroupComparison.cs`) to `BoundRelational`s
between corresponding leaves, paired by POSITION (§8.5.3.1), composed lexicographically — `a1 < b1 OR (a1 = b1 AND …)`,
ending FALSE for a strict operator and TRUE for `<=`/`>=`, equality the conjunction. Every leaf therefore compares by
the rule a relation written between those two items uses: FLOAT, signed DISPLAY, SIGN SEPARATE and PACKED-DECIMAL
algebraically, national/alphanumeric under the collating sequence, pointer leaves by identity. Leaves are reached by
the shared `PlaceCursor` (lifted out of `InitializeBinder`), so a subscripted strong group keeps its subscripts; an
OCCURS DEPENDING occurrence beyond the minimum is guarded by the DEPENDING value (§13.18.38.4 GR8). The COBOLNET0899
`strong-group-ordering-signed-leaf` stage and `ContainsSignedNumericLeaf` are deleted; `ContainsNonOrderableLeaf` asks
the §8.5.2.1 class lattice, so a PROGRAM-POINTER / FUNCTION-POINTER leaf is class pointer for SR4 (COBOLNET1535).
Probes on the landing build: sf.cob `T1 LT`, `T3 GT`; sg.cob `T1 LT`; pp.cob ordering refused COBOLNET1535; pointer
equality `EQ`/`NE` (the run-time abort PB244's equality leg recorded is gone with it). Golden
`2002/strong_group_element_order`, negative `negative/pb1469-strong-program-pointer-ordering`. Residue staged under
COBOLNET0899 `strong-group-comparison-member`: a dynamic-capacity table member, an ODO object under an OCCURS inside
the group, a REDEFINES storage tier the cursor cannot reach.

## Finding — `simple-relation-conditions-p1` (wrong-answer; rows `GR-8.8.4.2.1-12`)

**Mechanism.** F3 — strongly-typed group ordering is emitted as a whole-group IMAGE comparison, and the screen that stages the shapes where image order != element order (ContainsSignedNumericLeaf) excludes FLOAT leaves, so a float-leafed strong group orders by its byte image and answers WRONG; the signed-DISPLAY/binary leaf shapes it does catch are refused as 'not yet implemented' (COBOLNET0899) although §8.8.4.2.3 SR4 makes them legal

**Repro.** 01 F-T TYPEDEF STRONG. 05 FX USAGE FLOAT-LONG.  01 A TYPE F-T. 01 B TYPE F-T.  MOVE -5 TO FX OF A  MOVE 3 TO FX OF B  IF A < B DISPLAY "T1 LT" ELSE DISPLAY "T1 GE" END-IF  MOVE -2 TO FX OF A  MOVE -300 TO FX OF B  IF A > B DISPLAY "T3 GT" ELSE DISPLAY "T3 LE" END-IF  -> prints T1 GE, T3 LE (probe srel2/sf.cob, --std 2023). Companion: 01 S-T TYPEDEF STRONG. 05 SX PIC S9(3). … IF A < B -> COBOLNET0899 'recognized but not yet implemented' (sg.cob).

**Expected from the spec.** §8.8.4.2.12: 'each elementary item of the first operand is compared with the corresponding elementary item of the second operand, in accordance with the rules for comparison of elementary items' — FX is class numeric, so §8.8.4.2.4's algebraic value decides: -5 < 3 -> T1 LT; -2 > -300 -> T3 GT. The S9(3) program is legal (SR4 restricts only boolean/message-tag/object/pointer contents) and must compile and print LT.

**Observed / reasoning.** ContainsSignedNumericLeaf is `item.Pic is { Category: PicCategory.Numeric, IsFloat: false, Signed: true }`; a float leaf is excluded, reaches the image comparison, and IEEE sign/exponent bytes do not order algebraically. The root is the image comparison itself (a per-element comparison would make every leaf kind automatic, including the pointer-leaf EQUALITY abort owned by open PB244); no register note owns the 0899 stage.

**Code site.** src/Cobol.Net.Compiler/Binding/Validation/StatementValidation.cs#ContainsSignedNumericLeaf (IsFloat: false); src/Cobol.Net.Compiler/Binding/Validation/StatementValidation.cs#CheckRelationalOperands (COBOLNET0899 stage); src/Cobol.Net.Compiler/CodeGen/Emit/ConditionRenderer.cs (group image relation)

## Refuter evidence — row `SR-8.8.4.2.3-4` (DIVERGES)

DIVERGES — SR4 bars ordering for strong groups with elementary items of class pointer; program-pointer is class pointer (§8.5.2.15 category; program-address-identifier 'class pointer and category program-pointer'). ContainsNonOrderableLeaf (StatementValidation.cs:1597-1604) tests only PicCategory Boolean/ObjectReference/Pointer, omitting ProgramPointer and FunctionPointer (and MessageTag, declined). So `IF T1 > T2` over a TYPEDEF STRONG group with a USAGE PROGRAM-POINTER leaf compiles clean and aborts at run time with NotImplementedCobolFeatureException ('whole-group image ... pointer/object-class leaf'). Accept-illegal-source + runtime abort. Data-pointer, object, boolean, nested and OCCURS leaves, >=/NOT </<=/abbreviated/EVALUATE THRU are correctly refused COBOLNET1535.

**Code site.** src/Cobol.Net.Compiler/Binding/Validation/StatementValidation.cs#CheckRelationalOperands; src/Cobol.Net.Compiler/Binding/Validation/StatementValidation.cs#ContainsNonOrderableLeaf

## What the fixer owes

Replace the group-image relation with a per-element comparison generated from the strong group's layout (every leaf kind becomes automatic, including the pointer-leaf EQUALITY abort PB244 owns); delete the ContainsSignedNumericLeaf 0899 stage; make ContainsNonOrderableLeaf read the CLASS (pointer = data-, program- and function-pointer) rather than three PicCategory values. Goldens sf (T1 LT, T3 GT), sg (LT), and a program-pointer-leaf ordering negative (COBOLNET1535).
