# PB2517

Filed from the PB2071 refuter (`E:\COBOL-coord\scratch\w1033-adj\PB2071-refute.md` section 5, probe `r13u`; flags under-rejects, silent). No kb/Work note covers it (the refuter searched).

**Repro (compiles clean at 2002, 2014, 2023).**

    01 U IS TYPEDEF STRONG.
       05 G VALUE "AB".
          10 A PIC X.
          10 B PIC X.
    01 V TYPE U.

**Expected from the spec (cite.py --check OK).** V.G is a group subordinate to a TYPE-STRONG subject, hence a strongly-typed group item (`§8.5.3.1`, second arm). It carries the VALUE by `§13.18.58.4 GR3`, so `§13.18.63.3 SR1` ("The subject of the entry shall not be a strongly-typed group item or a variable-length group") is violated (informative D.8.3 5) agrees). Control `r17` (`01 W TYPE S VALUE "AB"`, the first arm) is rejected COBOLNET1703.

**Mechanism and site.** `CheckGroupValueDeclarations` skips the clone because `IsGroupValueSubject` excludes `ValueIsCopied` (`src/Cobol.Net.Compiler/Binding/DataBinder.GroupValue.cs:249-250`), and the template's G is not strongly typed (`StrongRoot` is null without a TYPE clause), so the "screened where it is declared" promise never fires. Provenance dedupe may suppress only a predicate the template could already answer, never one that becomes true only on composition (the same hazard as in PB2071's fix shape). The inventory row `SR-13.18.63.3-1` is CONFORMS and must be re-verdicted with the fix. Related: `PB2071`.
