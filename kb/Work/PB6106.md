# PB6106 - decide.py "refuses" and in fact selects

Re-verified on main ae1136f781. `adjudication/pb3319-editions/decide.py` ends its module docstring (line 22) with "Run on the tree BEFORE the batch is applied (it refuses a row
that no longer starts at 85)". The selection (line 78 onward) keeps only rows whose verdict is `DOCUMENTED-NON-SUPPORT` and whose `editions` starts with `85,`, so a row already moved off 85 is
skipped silently: re-run after the batch is applied, the script selects nothing, writes an empty batch and prints OK with exit 0.

- `adjudication/pb3319-editions/decide.py` (module docstring, last paragraph; the selection near line 78)

**Next:** either make the script refuse (an expected-count assertion against the PB3319 note's row list, exit non-zero when the selection is short) or correct the sentence to
"a re-run after the batch is applied selects nothing". The script is a one-shot record of PB3319's decision, so the sentence is the cheaper change.
