`docs/rearchitecture/evidence/fleet-optimization/2026-10-11-pipeline-measurement-2026-10-10.md`). `train_measure.py`
records trains (clusters, first_run, fixed_in_train, attribution_min, population_runs); after PB3023/PB3024 there are no

## Landed (wave 1062 C2)
`scripts/orchestrator/landing_measure.py` replaced `train_measure.py` (deleted with `TrainMeasureDriftTests`; its drift
sweep `LandingMeasureDriftTests.TheRetiredTrainWriter_IsDeleted_AndNothingNamesIt` keeps every tracked file off it).
- **Record:** one JSON object per pull request in `<coord>/landing-measurements.jsonl`, built by patches (`record`), the
  FIRST enqueue time kept, stamps checked in order DONE, review clean, enqueued, merged. `enqueue.py queue` writes the
  record it can the moment the PR is queued (DONE: see the review finisher's paragraph below; local gate seconds = the sum of the worktree's `verdict.json` `timings.wall_s`); a record that cannot be
  written is a loud warning, never a failed landing. `--changes N` counts a lander train's clusters.
- **`complete`** reads `mergedAt`, the count of FAILED merge-group runs of the PR (bounces; a run GitHub cancelled
  because an earlier entry failed is a ripple, not a bounce) and the successful run's wall from `gh`. Not probed live:
  no merge group has run yet (the ruleset is ABSENT), so the `gh-readonly-queue/main/pr-<n>-<sha>` branch shape is
  GitHub's documented one; `complete` prints a warning when a merged PR matches no successful run, and the first
  `summary` after the first queued landing is the live check.
- **`summary`** prints the AFTER column (changes landed per hour, median and p90 minutes DONE to main, bounces per
  landing with causes cluster-defect, load-timing, conflict, infrastructure and UNATTRIBUTED, merge-group CI wall, local
  gate minutes) beside the BEFORE column (the retired train records, batched gating: 1.53 changes/h over 25 trains and
  136 changes at this writing, minutes per landed change from lander start to push as a floor, ejections as the bounce
  analogue; the frozen 2026-10-10 evidence's 41 % gate and 16.5 % push-main + CI shares, each figure re-checked against
  the evidence file by the self-test). A field never observed prints UNMEASURED. `freeze` copies the train records and
  the first after-summary under `evidence/fleet-optimization/` once a PR has landed (not yet run: there is no landing).
- **Ledger:** `gen_ledger.py` shows `landing_measure.landing_rate_input` (the queue's own rate and median minutes per
  landing from two landings, else the trains') in its estimate inputs, and `ledger_plan.estimate_inputs` divides by it.
- **Interim:** a landing through `push-main.sh` (the queue not ACTIVE) writes no record; the train file is the BEFORE column.

## Review finisher (wave 1064 C2): the three branch-review findings
- **R1-1 (DONE was the review stamp's time).** `done_from_report` took the report FILE's modification time, and
  `review_findings.py stamp` rewrites that file before any landing, so DONE was the last stamp (probed: a report
  written at T and stamped at T+40 min gave T+40 min; on the real reports directory the C2 report reads 17:26, its
  implementer's last commit 15:37). It is replaced by `landing_measure.done_times`: the committer time of the HEAD commit
  each DONE implementer report names (plan_wave.parse_report reads status, lead and HEAD; no second report parser).
  A change is one lead note and takes the earliest of its finisher chain (same lead, HEAD an ancestor of the seed's
  HEAD), so a review finisher's landing keeps its first implementer's DONE and the review wait is inside DONE → main.
  `done` only ever moves earlier, so a bounce's re-enqueue cannot put DONE after the first enqueue time.
- **R1-2 (a train recorded no DONE).** The seeds are the reports naming the queued branch AND the reports the
  `Report:` lines of `origin/main..HEAD` name (train_apply.py writes one per cluster): a train records one DONE per
  change (`done_each`), `changes` defaults to the count found, and `summary`'s minutes DONE → on main are per change.
- **R1-3 (the ledger called the trains' floor "DONE to main").** `headline` carries `median_measures`, the label of
  what its minutes are (`MEASURES_AFTER`, `MEASURES_TRAINS`: lander start → push, a floor), and `gen_ledger.inputs_text`
  prints that label instead of its own; a gen_ledger self-test check holds that the trains' figure never reads
  "DONE to main".

## Review finisher (wave 1064 C2, round 2): the two findings on the finisher's branch
- **R1-1 (a landed same-lead report became a later landing's DONE).** The finisher chain took every DONE report with
  the lead whose HEAD is an ancestor of the seed's HEAD; under the merge queue's MERGE method every landed head is an
  ancestor of main and so of every later branch, and leads are reused (PB2426: seven separate records landings), so a
  later landing took the FIRST landing's finish (probed on the real repository: 00:44:49 for a branch committed
  18:30:50). `done_times` now drops every report whose HEAD is already an ancestor of `upstream` (a seed or a chain
  member), the rule plan_wave's branch survey applies; the self-test's done arm carries a landed same-lead report and a
  landed report under a reused branch name, and fails without the filter.
- **R1-2 (PB3040's plan built on the retired train record).** PB3040's step 2 and step 4 now retire a lander entry on
  its terminal report or its branch's merged `landing-measurements.jsonl` record, and say why `train-measurements.jsonl`
  is no source.
