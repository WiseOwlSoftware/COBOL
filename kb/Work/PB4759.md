# PB4759 - the cd-name, file-name and data-name USE FOR DEBUGGING triggers are not modeled

**What the report says (New defect 1).** The cd-name, file-name and data-name USE FOR DEBUGGING triggers are not modeled (staged
COBOL1571 in `FinalizeDebug`), so legal CCVS DB205A (and the DB201A family's data and file triggers) is still refused. The report
says it needs DEBUG-ITEM and DEBUG-CONTENTS instrumentation of ENABLE, DISABLE, PURGE, RECEIVE and SEND, of file I/O and of
data statements, and that it was too large for the slice; the finisher's brief allowed it no note.

**R1.** No open note covers it. PB4713 (landed) modeled the part it did; PB175 and R61 (open) do not concern these triggers.

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/ProcedureTableBuilder.cs#FinalizeDebug`.

**Wave 20261879, group D: BLOCKED with no change (report `w20261879d-PB4759-report.md`).** The note still reproduces on
1a49d173c: `cobol --nist DB205A` gives COBOL1571 twice, and `cobol --nist DB201A` gives COBOL1571 on every data trigger.
The implementer stopped for two reasons. The trigger semantics come from X3.23-1985's Debug module chapter, which is not in
the repository, and ISO 2023 no longer has the facility. The work is also a redesign across `BoundDebugSubject`, `DebugItem`,
`DispatchEmitter` and every statement lowerer, not an edit to `FinalizeDebug`. It asked for an owner decision: supply the 1985
text, or name an IBM or Micro Focus reference.

The wave unit did not relay that as an owner question. CLAUDE.md rule 1 already names IBM Enterprise COBOL or Micro Focus
where GnuCOBOL has nothing, but no one has yet read either vendor's manual to see whether it covers these triggers, or
whether rule 1's latitude clause reaches a 1985-only facility. Do that first. Ask the owner only if it leaves the question
open. Then write a design-doc section and split the work by trigger kind (data-name, file-name, cd-name). Do not send this
note to a Sonnet implementer as one slice again.
