# PB3115 — the ledger trend records a landed branch's commits twice after another merged branch's point

> ⚙ **flags:** silent · process

Found by wave unit 1070 (2026-10-12 21:40 PDT) while committing the main checkout's uncommitted trend points.

**What is in the file.** The 24 points the main checkout's renders appended after 222 committed ones run, by sha:
`7f4e6735 f3aea17d 7c71f301 22ff079d a071fd35 b22722b0 c813cb31 16080262 241c6de2 2827a444 2df3a994 3981a052 b3953448
667431d1 4dfb26c3 23fc06ba 3981a052 b3953448 667431d1 4dfb26c3 92cfea45 a40774c2 c8129c45 c41f1b82`. The four shas
after `23fc06ba` repeat the four before it.

**Mechanism.** `scripts/spec/gen_ledger.py` `missed_points` measures "the measurement-moving commits since the series'
last point" as `git log --reverse <last sha>..HEAD -- <inventory> kb/Work`. Since landings go through the merge queue,
main is a chain of merge commits, and a missed point can be a branch's OWN commit: `23fc06ba` ("File PB3109-PB3113")
is the notes branch's commit that PR 21 merged as `92cfea45`. `3981a052` to `4dfb26c3` are PR 19's branch commits
(`worktree-wf_d63f7207-db5-22`), and none is an ancestor of `23fc06ba` (checked with `git merge-base --is-ancestor`). The next render's `23fc06ba..HEAD` lists them again, each moves the
measurement against the previous point (the series went back to an older register state at `23fc06ba`), and each is
appended a second time. `trend_series` (`last.get("sha") == cur["sha"]`) and the `MOVING_KEYS` test in
`missed_points` compare only with the previous point, never with the series. The chart then draws the inventory going
backwards and forwards across the same commits.

**Expected.** One point per measurement-moving commit on main, in main's order. The likely shape: walk main's
first-parent history (`--first-parent`, measuring each merge's tree) so a branch's own commits never become points,
and skip any sha the series already holds. The existing duplicates in the series (`<coord>/ledger-trend.json` since kb/Work
PB2426, outside any branch: the fix applies the correction there and states it in this note)
are then removed by a regeneration, not by hand.

**Siblings to sweep.** Any other `<sha>..HEAD` range in the orchestrator and ledger scripts that assumes a linear main
(`landing_measure.py`, `ledger_state.py`, `train_measure.py`, the DEVLOG stamp ordering).
