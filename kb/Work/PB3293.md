# PB3293 — CLDR tailoring builder reads strings by whole-key lookup

Source: `E:\COBOL-coord\scratch\reports\w1096f-PB2762-report.md`, "New defects" (branch worktree-wf_123a85e2-640-13, PB2762, PR #135 merged; PB2762 was discharged because the S2.1 walk is already written once, PB2765). Harm: POSSIBLY a wrong answer (a locale's collation table order). The report did NOT compare with ICU, so wrong_answer is not set; this is suspected and unprobed against ICU. Changing this changes tables, so the fix lane owns it (PB2119 contract).

**Mechanism.** The builder reads the current elements of a reset, an extension and a prefix string by `Builder.Lookup`, which takes an exact whole-key tailored entry, else the base table's `GetElements(ReadOnlySpan<int>)`: an exact whole-key contraction, otherwise a per-code-point concatenation. It never walks the tailored-so-far mappings and does not NFD the string. ICU's CollationBuilder (`addReset`/`addRelation`) does both: `getCEs` over the NFD string on the data built so far.

**Code sites** (re-verified on origin/main 494246263; the report's paths lacked the directory):
- `src/Cobol.Net.Runtime/Collation/CLDR/CldrTailoringBuilder.cs` `Lookup` (about :553-563; callers about :462 Reset, :505 extension, :511 prefix).
- `src/Cobol.Net.Runtime/Collation/CollationTable.cs` `GetElements(ReadOnlySpan<int>)` (about :208-221).

**Measured reach (the report's probe, over all 160 CLDR 48 tailorings).** 2,377 looked-up strings contain an earlier tailored contraction: bn/kn/sa-u-co-traditional (e.g. a conjunct holding the tailored virama-joined consonant), my 625, dz 21, bo 2, root-u-co-emoji 15. Also 2 strings where the root walk takes a contraction that the whole-key read misses (bal, two strings: 3 elements versus 2), and 48 strings not in NFD (ar, for example). No other lead shares this root cause.

## Landing (wave 1103 C, branch worktree-wf_cec72c3d-616-1)

**Re-probe (confirmed, now a measured wrong answer).** A temporary probe beside the builder computed both reads for
every reset, extension and prefix string of all 160 CLDR release-48-2 tailorings: 2,469 reset strings read
differently (sa/kn/bn traditional 1,714, my 254, zh stroke/pinyin/zhuyin 356, ar 87, dz 17, root emoji 15, km 6,
cu 5, eor 8, th 2, ko search, ja, ja unihan, ja private-kana, bo 1 each), 20 of them not in NFD; no extension or
prefix string differed in CLDR (synthetic rules reach both arms). Against the host's ICU the old builder disagreed
in zh-CN (`&'(一)'<<<㈠`: ㈠ took U+4E00's implicit weight, not its pinyin one, so ㈠ < ㈦ < ㈢ where ICU has
㈦ < ㈢ < ㈠) and in ar-SA (`&ئا=ﯪ`: ﯪ read the root's ئ, not the tailored one, so ﯪ ≠ ئا where ICU has them
equal). No CLDR key starts with a Hangul syllable, and no tailored contraction starts with a
`[suppressContractions]` code point (both measured by the probe).

**Fix.** `CldrTailoringBuilder.BuiltSoFar` is the mappings the rules have built so far, in the shape the S2.1 walk
reads: each tailored string keyed by its NFD, a first code point's root contractions copied in on first use (ICU's
`copyFromBaseCE32`), suppressed ones never. A reset string, an extension and a prefix are read by
`BuiltSoFar.ElementsOf`: NFD, then the ONE S2.1 walk. That walk was extracted from `CollationElementIterator` into
`ContractionWalker` (code point cursor, longest contiguous contraction, discontiguous extension over unblocked
non-starters), which the iterator now drives too, so the run-time walk and the builder's read cannot drift.
`CollationTable.WithContraction` is the one "replace or insert, longest first" rule both contraction lists use.
Deleted: `Builder.Lookup` and `CollationTable.GetElements(ReadOnlySpan<int>)` (the whole-key read, public, no other
caller; the runtime surface hash re-pinned alone, major 6 kept: no module this compiler emits calls it), and the
write-only `_skipped` counter.

**For the next implementer.**
- `src/Cobol.Net.Runtime/Collation/ContractionWalker.cs#TryMatchContraction` — the one UTS #10 S2.1 matcher; any
  reader of a string's elements walks through it (never a whole-key lookup).
- `src/Cobol.Net.Runtime/Collation/CLDR/CldrTailoringBuilder.cs#BuiltSoFar.ElementsOf` — what a reset, extension
  or prefix reads; `Map` after every relation keeps it current. Trap: a tailored key is keyed by its NFD, so a
  precomposed key is found through its decomposition.
- `src/Cobol.Net.Runtime/Collation/CollationTable.cs#WithContraction` — reuse it to add a contraction to any list;
  `#MapsItsNfdSpelling` — the one rule for which tailored keys map their NFD spelling (not a Hangul-led key), read
  by Rebuild's closure and by BuiltSoFar.Map.
- `src/Cobol.Net.Runtime/Collation/CollationElementIterator.cs` — S2.2 only (fetching); the walk is the walker's.
- Witnesses: `CldrLocaleLoaderTests.ResetExtensionAndPrefix_WalkTheirNfdOverTheRulesBuiltSoFar` (one case per arm,
