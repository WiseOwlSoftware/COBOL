# PB4033 — Git for Windows revisions are invisible to `latest`

**Sites:** `scripts/toolchain.py` (`_image_git`, `GIT`).

**What.** PB4007's rule is that CI and every host run the LATEST release of each tool (owner 2026-10-28). The manifest's
git entry compares git's own release (`2.56.0`); Git for Windows publishes revisions of one git release as
`2.56.0.windows.N`, and the Windows box runs `.3` while `.4` is published. `toolchain.py latest` reports the manifest
current, so the Windows host drifts from the latest with no signal. Independent of the report's R1-1 (fixed there).

**Fix shape.** Give the Windows row its own version key carrying the `.windows.N` revision, read from Git for Windows'
releases, with a self-test arm for a newer revision of the same git release.
