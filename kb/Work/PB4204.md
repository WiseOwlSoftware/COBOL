# PB4204 — a landing writes a worktree under its running gate when an older GREEN record covers the tip

**Sites:** `scripts/orchestrator/enqueue.py` (`tested_locally`, `land` step 1c), `scripts/orchestrator/land_lane.py`
(`tick`, `wait_free`, `gate_lock_free`).

## What happens

`tested_locally` reads the worktree's gate runs newest first and returns `Tested(ok=True)` at the first GREEN run that
covers the tip. It computes `live` (the worktree's gate lock, PB3662) before the loop, but consults it only on the
not-ok path, to word exit 12 instead of exit 14. So when an earlier GREEN run covers the tip and a NEW gate of the same
worktree is running now, `land` treats the tip as tested and goes on to step 2. It merges origin/main into the branch,
stamps the DEVLOG entry and commits, all in the worktree the running gate is measuring. A Linux gate of the tree
(`linux-gate.sh`, PB3649) is not probed on that path at all.

The landing lane does not stop it either. `land_lane.tick` asks `wait_free` and `gate_lock_free` only to RETRY an
attempt that already ended exit 12. Before it launches a first attempt at a head, it never probes the gate lock.

## The recorded case (2026-10-31 08:58 PDT)

The operator's loop restarted at 08:58. Its landing lane started `enqueue.py land worktree-wf_34371f8b-c21-1`
(log `E:/COBOL-coord/logs/land-lane-000466-20261031T155850Z-worktree-wf_34371f8b-c21-1.log`): "4791a290cd25 is covered by
the GREEN local gate run 000003-20261031T034819Z at 0352ff75bc55 (Linux half GREEN)". It merged main, stamped DEVLOG
2851 and queued PR #884. At that moment the Mythos session's own gate was running in the same worktree, after the
branch's second review. That gate's Linux half went RED with `repository-written` when the landing wrote the tree
(Mythos's mail 09:02). The landing itself was correct (run 000003 covers the tip). The harm is the destroyed gate run,
and a RED record in the worktree that a later reader must step over. A running gate can belong to anyone: a finisher,
a hand re-gate or another lane.

## The fix's shape

Make one check, in one place, whose answer does not depend on which records exist: no landing writes a worktree while
a gate of it runs. Before step 2 (the merge), whatever `tested_locally` returned, a live gate lock or a Linux gate of the
tree ends the landing with exit 12 GATE BUSY: nothing ran, nothing is red, and the lane retries that head once both are
free (`wait_free`, the existing mechanism). Then `tested_locally` stops carrying `running`, because step 1c no longer
needs it to tell 12 from 14. The busy check moves to the step that writes, so `Tested` describes evidence only. Add a
self-test arm: a GREEN record that covers the tip, plus a held gate lock, gives exit 12 with nothing merged, stamped or
queued. Sweep the other writers of a branch worktree the loop runs on for the same gap: the finisher's merge, the
review lane's stamp and the enqueue unit's `rearm`.
