# PB6045 - disk-versus-index case drift makes the generator's output differ at one input key

**Observed.** Gate run 000011 (E:/COBOL, ci-shard-limits-30) went RED: `conformance-suite is NOT DETERMINISTIC: at key
d7f9c822719f the store records output 51122261cebc (worktree wf_cfbc976b-c83-1, 08:36Z) and this run wrote
dca22afb429c`. The generator is deterministic on one tree (two runs, `diff -r` empty). The two outputs differ only in
`8.4.2.2@2002-Function-identifier` (the main checkout's DISK spelling) against `8.4.2.2@2002-FUNCTION-IDENTIFIER` (the
index's, and the worktree's disk). PB5694 (2831032b93, 2026-11-15) renamed the folder by case only; on a case-insensitive
filesystem the pull that carried it kept the old spelling on disk (`core.ignorecase=true`).

**Mechanism.** The key reads the inputs as the index names them (or case-insensitively); `generate.py` reads the directory
listing and writes that spelling into every manifest's `clause` and `source`. So one key has two outputs, and the gate
calls it nondeterminism; it names no cause.

**Repaired here by hand:** the folder renamed to the index's spelling in the main checkout (two `mv` steps); a sweep of
every case folder against `git ls-files` found no other drift.

**Owed (root):** the generator (and every tool that writes a repository path into an output) takes path spellings from
the index, never from a directory listing, or the gate refuses a tree whose disk spelling differs from the index's with
that message, before any target runs. Sweep for sibling readers (`os.listdir`/`Path.iterdir`/`glob` over tracked trees
whose results are written out).
