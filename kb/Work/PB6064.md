# PB6064 - `Converted.position` returns a computed column where the converter must refuse

`Converted.position(line, col)` finds the segment holding the original column and, when none does, falls back to `segs[0]` (column
before the first segment) or `segs[-1]`, then returns `seg.col + (col - seg.start)`. A column inside an inline comment the converter
moved to its own line, or inside the spaces skipped at a re-wrap, is covered by no segment; the answer is a plausible but invented
position. The module docstring promises the converter does not guess and fails loudly (`Refused(UNREADABLE, ...)` is raised for an
uncarried line, one branch above).

Fix: raise `Refused` for an uncovered column, and let the caller decide (a diagnostic expectation at such a column cannot be
carried). Add the two uncovered cases (comment moved, re-wrap gap) to the harness self-test. Check each caller of `position`.

**Sites:** `conformance-suite/harness/reformat.py#Converted.position`; its callers in the same module.
