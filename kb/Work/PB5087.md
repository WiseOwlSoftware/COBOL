# PB5087 - at --std 85 a bare GO TO (no procedure-name) in a paragraph holding other statements compiles

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/ControlFlowBinder.cs` (whole: the records name the `GoToFormat` default arm, `host.Alter.AlterBindBareGoTo(g)`, which binds the target-less GO TO without asking what else its paragraph holds, but no member the file declares).

**Mechanism.** 1985 allows a format 1 GO TO without procedure-name-1 only as the single statement of its paragraph. The bare GO TO arm binds the statement for ALTER and never checks the paragraph.

**Found by.** The 1985 `--std=85` draft triage (kb/Work PB4995 item 3): each rule below is a conformance-suite draft that did not MATCH at `--std 85`, and its adjudicator decided COMPILER-DEFECT. Harm and observed text are the records'; nothing here was re-derived.

**Inventory.** The traceability inventory carries no 1985 rows yet, so `inventory_rows` is empty; the rows this note covers are the 1985 rule ids listed below (catalog `docs/rearchitecture/spec-rule-catalog-1985.json`).

**Rules (1; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-SR-VI.6.15.3-3` - `§1985:VI.6.15.3 SR3` (record harm: under-rejects, slice-04): §1985:VI.6.15.3 SR3: "A format 1 GO TO statement, without procedure-name-1, can only appear in a single statement paragraph." Paragraph P1 of the draft holds two statements, `DISPLAY "IN P1".` and `GO TO.`, so the GO TO statement of line 8 breaks the rule. The draft reads the rule correctly; its control (`GO TO P2.`) compiles and displays START, IN P1, END.

**Repro (`1985-SR-VI.6.15.3-3`, slice-04).**

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. GOTEST.
       PROCEDURE DIVISION.
       P0.
           DISPLAY "START".
       P1.
           DISPLAY "IN P1".
           GO TO.
       P2.
           DISPLAY "END".
           STOP RUN.
```

**Expected (from the 1985 text).** --std 85 refuses a bare GO TO in a paragraph with a second statement, at the GO TO. The deciding words: "A format 1 GO TO statement, without procedure-name-1, can only appear in a single statement paragraph." (§1985:VI.6.15.3 SR3).

**Observed (copied from `1985-SR-VI.6.15.3-3`).** Compile exit 0 with no diagnostic; the program runs, displays `START` and `IN P1`, and ends with exit 0 at the GO TO that no ALTER statement ever set (§1985:VI.6.15.4 GR2 requires that "an ALTER statement, referring to this GO TO statement, must be executed prior to the execution of this GO TO statement"). The conforming shape is accepted and works (a paragraph holding only `GO TO.`, altered first: displays START, END), so only the single-statement-paragraph check is missing. Code site: src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/ControlFlowBinder.cs, the GoToFormat default arm (`host.Alter.AlterBindBareGoTo(g)`), which binds the target-less GO TO without asking what else its paragraph holds. cobol.exe 25.0.0 of E:/COBOL/.claude/worktrees/pin-triage (e8a1b94f50), invoked as the conformance-suite adapter's flag command: cobol t.cob --std 85 --source-format fixed --flag-extensions -o t.dll
