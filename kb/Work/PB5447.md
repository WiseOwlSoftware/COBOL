# PB5447 - a file in %TEMP% is a file anyone may hold

**Sites:** `scripts/gen-grammar-diagrams.ps1#Invoke-Rr`, `tests/WiseOwl.Cobol.Tests.Unit/GrammarDiagramGeneratorDriftTests.cs#Generator_RunsClean`

## Root cause, with the evidence

The generator ran `java -jar rr.war ... -out:<tmp>\ccf-<guid>\<frag>.md` and then read that file back. PB44 (2026-08-04)
met the same message on CobolScreen.md and wrapped the read in a retry: 10 attempts, `Start-Sleep 50 x attempt` ms, so
about 2.25 s in all, then `throw`. That narrowed the window and left the cause in place.

1. **The retry's catch clause DID match. The lead that it could not is refuted.** Reproduced (`pwsh`, 7.7.0): a second
   process held a file with `[IO.File]::Open(f,'Open','Read','None')`, and
   `try { [IO.File]::ReadAllText(f) } catch [System.IO.IOException] { ... }` entered the IOException clause with
   `$_.Exception` of type `System.IO.IOException`. PowerShell matches a typed catch against the inner exception of the
   `MethodInvocationException` it wraps a .NET method's throw in. So `orchestrate.ps1#Take-Lock`'s identical clause is
   not defective either.
2. **The red is the 10th attempt's rethrow: all ten attempts were refused.** A bare `throw` inside the catch rethrows
   the original ErrorRecord, whose InvocationInfo is the `ReadAllText` line. Reproduced with the generator's own loop
   shape against a file held with read-write access and read-write sharing: the stderr read "attempt 1 ... attempt 10
   caught by the IOException clause" and then printed exactly the gate's header, `ParentContainsErrorRecordException:
   ...:7`, underlining `[IO.File]::ReadAllText($f)`. The point of failure was the 10th rethrow, not an uncaught first
   attempt, so the hold lasted longer than the whole ~2.25 s backoff.
3. **No other writer shares the path, and the generator's own child had exited.** The directory is
   `ccf-` + a fresh `[guid]::NewGuid()` per run, so no other generator run or test writes it. `& java` returns only
   when java has exited, and a process's handles are closed at rundown before its process object signals. The holder
   was therefore a third process with WRITE access to a freshly written file in %TEMP%. `File.ReadAllText` asks for
   `FileShare.Read`, and a held write access refuses it. Microsoft Defender real-time protection is on on this host
   (`Get-MpComputerStatus`: RealTimeProtectionEnabled True; its exclusions need administrator rights to read).
4. **The holder could not be named by reproduction.** 420 stressed runs did not reproduce it: 12 then 24 concurrent
   workers, each running rr -out: then reading the file at once, with a Restart Manager (`RmGetList`) probe ready to
   name the holder. Both runs reported `violations: 0`. The window needs the full gate's load. The design, not the
   holder's identity, is the defect: any process on the host may open a file in %TEMP%, and this script handed data to
   itself through one.

## The fix

`scripts/gen-grammar-diagrams.ps1#Invoke-Rr` passes the EBNF to rr.war on STDIN (`-`, `-enc:UTF-8`) and takes the
Markdown from STDOUT (no `-out:`, `-Dstdout.encoding=UTF-8`), through a `System.Diagnostics.Process` whose three
streams are UTF-8 and whose stdout and stderr drain concurrently with the stdin write. No file passes between the
script and java, so no other process can hold the handoff. The `ccf-<guid>` temp directory, the `.ebnf`/`.md`
intermediates, the retry loop and its sleeps are deleted. A nonzero java exit fails the run and prints rr's stderr.
rr's stdout output was byte-identical to its `-out:` file for CobolWords and CobolData (`cmp`). The whole
9-fragment run's 10 notes from the old and new scripts are identical (`diff -r`: no output).

The -Check run still writes its notes to a per-run directory in %TEMP%. Those are written once and never read back, so
a scanner holding one cannot fail the run. The final `Remove-Item ... -ErrorAction SilentlyContinue` already tolerates
a held file.

## The test that failed before

`GrammarDiagramGeneratorDriftTests.Generator_RunsClean` now runs the generator under a hostile temp directory. It sets
the child's `TMP`/`TEMP` to a directory of its own. A `FileSystemWatcher` in the test host opens every file created
there with `FileAccess.ReadWrite` and `FileShare.ReadWrite | FileShare.Delete`, waiting out a writer that refuses the
share, and holds it until the run ends. The test asserts exit 0, the summary line, and that at least one file was
held, which proves the holder was live. No clock decides it.

- main's script (`git show origin/main:scripts/gen-grammar-diagrams.ps1`) under the new test: `Failed!  - Failed: 1`,
  "exited 1 while this test held every fresh file", `ReadAllText` on `...\ccf-34f93fd4...\CobolWords.md` "being used
  by another process".
- the fixed script: `Passed!  - Failed: 0, Passed: 1` (46 s).

The first version filtered the holder to `*.md`. The gate's inert-lane audit refuses a compiler test that spells a
Markdown path (kb/Work PB4453, run 000001-20261112T220157Z), and a real scanner holds every fresh file anyway, so the
holder now takes every file. Both verdicts above were re-run with that version.

The test reuses the existing Fact rather than adding a second generator run (35 to 68 s each, the Unit leg's largest
indivisible class), so every gate now proves the property.

## Sibling sweep

- `git grep -n "catch \[System.IO.IOException\]" -- scripts .github tools`: two sites. One is this generator, now
  deleted. The other is `scripts/orchestrator/orchestrate.ps1#Take-Lock`, which catches `File.Open(CreateNew)`'s
  "file exists". Its clause matches (finding 1), and it does not read back a child's output, so it is not this defect.
- The mechanism (a parent re-reading a file its child just wrote):
  - `src/WiseOwl.Cobol.Frontend/Invoke-Antlr4CSharp.ps1` copies `CobolLexer.tokens`, which java wrote to the project's
    `Generated/` folder. Not the same defect. ANTLR's outputs are the build's real artifacts, several files that csc
    also reads as files, and they live in the repository, not in %TEMP%. There is no pipe form, and no red is on
    record.
  - `scripts/fetch-gnucobol-tests.ps1`'s self-test hands `.tar.xz` fixtures between tar processes in a per-run
    sandbox. The subject under test is tar reading a file, so the file is the point.
  - `scripts/gen-vault-reference.ps1` runs no child process that writes its output.
  - None of the three is the same defect.
- Every other `GetTempPath` user in `scripts/*.ps1` (test_autostart, orchestrate_test_lib, test_fuzz_night) builds a
  per-run GUID sandbox for its own fixtures and does not hand a child's output back through it.

## Landing

- `scripts/gen-grammar-diagrams.ps1#Invoke-Rr` - the one call of rr.war (stdin to stdout, UTF-8). Never reintroduce an
  `-out:` file that the script reads back: the pipe exists because a file in %TEMP% can be held by any process.
- `tests/WiseOwl.Cobol.Tests.Unit/GrammarDiagramGeneratorDriftTests.cs#Generator_RunsClean` - `FreshFileHolder` holds every
  fresh file under the child's own TMP/TEMP. Reuse it for any generator test that must prove a handoff cannot be locked.
  The `held > 0` assertion is what keeps it able to fail.
