## Finding — define-directive (under-rejects)

>>DEFINE's operand is split by a string splitter (SplitDefine) that never checks the directive's own general format: no check that compilation-variable-name-1 is present, that it is not a §8.12 compiler-directive word, or that OVERRIDE is not attached to OFF.

**Expected from the spec:** §7.3.11.2: compilation-variable-name-1 is required, and the outer brace is { value-group [OVERRIDE] | OFF } - OVERRIDE is not part of the OFF alternative. §7.3.11.3 SR1: 'Compilation-variable-name-1 shall not be the same as a compiler-directive word' (IF, DEFINED, OFF ... are in the §8.12 table). All four shall be diagnosed (a COBOLNET1619-class directive-syntax error).

**Observed:** ApplyDefine returns silently when the name is empty; SplitDefine strips a trailing OVERRIDE before testing for OFF, so OFF OVERRIDE is taken as OFF; the only name check is the §8.3.2.1 length rule (CobolWordRule). No source consults §8.12 for a compilation-variable-name. Sibling: §7.3.8.4.3 SR1 imposes the same restriction on a defined condition and is likewise unchecked. The registry row (define-directive-2002, DirectiveOperandForm.Stage) delegates operand syntax to this stage, so nothing else catches these.

**Code site:** src/Cobol.Net.Frontend/Preprocessor/ConditionalCompilationProcessor.cs#SplitDefine; src/Cobol.Net.Frontend/Preprocessor/ConditionalCompilationProcessor.cs#ApplyDefine

## Row SR-7.3.11.3-2 — PARTIAL (adjudicator + refuter record)

cite.py --check 7.3.11.3 "the last previous DEFINE directive referring to compilation-variable-name-1 shall have specified the same value" -> OK SR2. OFF removes the name (so bullet 1 'not declared' and bullet 2 'last previous was OFF' coincide), AssignDefine reports COBOLNET1618 when !OVERRIDE and the stored value differs by category-aware equality. Probes: n4 (1 then 2 -> 1618), q11 (1/1/1.0 accepted; 'A' then 'A ' -> 1618, length-sensitive), t7/q7 (after OFF, redefine accepted), q5 (after an OVERRIDE to 2, a plain '1' -> 1618: the LAST previous value governs), t9 (name case-insensitive), r2 (PARAMETER value differing without OVERRIDE -> 1618). Interpretive edge noted, not a defect: a PARAMETER DEFINE whose environment supplies no value undefines silently and a later plain DEFINE is accepted (u1.cob) - SR2 does not say what value a value-less PARAMETER 'specified'. Also covered by unit:ConditionalCompilationDefineTests.Redefine_SameValue_NoOverride_Accepted / Redefine_AfterOff_Accepted. || REFUTED: PARTIAL — SR2 has three admitting bullets; the implementation checks only a stored-value comparison, and a value-less PARAMETER DEFINE bypasses it entirely. After >>DEFINE PX AS 1, a no-OVERRIDE >>DEFINE PX AS PARAMETER with PX unset in the environment silently removes the name (ApplyDefine: 'if (env is null) { defines.Remove(name); return; }', no AssignDefine call), and a following no-OVERRIDE >>DEFINE PX AS 2 is then accepted as if PX had never been declared. Neither DEFINE meets any SR2 bullet: PX WAS declared previously, the last previous DEFINE was not OFF, and it did not specify the same value (1 vs no value; no value vs 2). The value 1 -> 2 change without OVERRIDE, which SR2 exists to forbid, compiles silently. The adjudicator named this edge and called it interpretive. That leaves the edge unverified, not verified. The ordinary branches hold: 1 then 2 -> 1618; after OFF a redefine is accepted; the last value governs; a program in the same compilation group inherits the value (g1: a DEFINE in program 2 differing from program 1 -> 1618); a DEFINE in an omitted >>IF branch does not count (s1).

**Code location:** src/Cobol.Net.Frontend/Preprocessor/ConditionalCompilationProcessor.cs#AssignDefine; src/Cobol.Net.Frontend/Preprocessor/ConditionalCompilationProcessor.cs#ApplyDefine; src/Cobol.Net.Frontend/Expressions/CtValue.cs

## What the fixer owes (and the sibling sweep)

Parse DEFINE from its general format (name, then AS {arith | boolean | literal | PARAMETER} [OVERRIDE] | OFF) and apply SR2's three bullets to the PARAMETER arm too (the value obtained, or 'no value', is what is compared). Negative goldens per shape.
