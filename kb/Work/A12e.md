# A12e — THE SAME CLASS IS IN THE GnuCOBOL DIFFERENTIAL: A COMPILE THAT PRODUCED *NO ERROR TEXT* IS SCORED AS A REJECTI

- THE SAME CLASS IS IN THE GnuCOBOL DIFFERENTIAL: A COMPILE THAT PRODUCED *NO ERROR TEXT* IS SCORED AS A REJECTION
- ⛔ **OBSERVED 2026-08-02 (PB10):** the per-case diff reported one flip, `run_fundamental.at :: "Numeric operations (6)"` moving **AGREE_ACCEPT → WE_REJECT_THEY_ACCEPT** — the REGRESSION direction, which is a 0-tolerance signal. It was spurious: `ourCodes` was **`[]`** and `ourFirstError` was the **EMPTY STRING**, and compiling the extracted case directly exits 0 with no output. The case is 36 lines keyworded `ADD`, with **zero INSPECT statements and zero FUNCTION references**, so PB10 cannot reach it. **A verdict of "we rejected it" with no diagnostic and no error text is not a rejection — it is a lost result**, and scoring it as one manufactures a regression in the one direction the gate treats as unforgivable. Third harness today with this defect class (A12b compile-failure inference, A12c missing verdict line, this).
- Treat "rejected" as requiring EVIDENCE: a non-zero exit AND at least one diagnostic line. A compile that yields neither is UNKNOWN — report it as such and re-run it, never fold it into a verdict bucket.
- With A12b/A12c — the three share one root: **a missing observation is being read as a negative observation**
- **CLOSED 2026-08-03.** A rejection now requires a non-zero exit **AND** at least one diagnostic line; an acceptance requires the output artifact. An evidence-free compile is retried once and then bucketed **`NO_COMPILER_EVIDENCE`**, which counts as a HARNESS failure, is NAMED for re-run, and is never folded into one of the four verdict buckets. ⭐ **The rule is PROVEN before it is applied:** `evidence_control()` compiles one program that must be accepted and one that must be rejected *with a reason*, and the run ABORTS (rc 4) if this build cannot be told apart — because `has_evidence` would otherwise silently reclassify every genuine rejection as a lost result and the differential would go quietly, uselessly clean. Measured on this build: reject = exit 65 + ~300 diagnostic bytes, accept = exit 0 + the `.dll`; there is no third shape. The control was itself proven able to fail against two stub compilers (one that rejects silently, one that accepts without emitting).
