# PB3171 — `plan_wave.py --release` misses a lower-case group selector

**Found 2026-10-14 ~18:02 PDT by the wave-1080 unit**, dropping group A2 (PB3127, kb/Work PB3170) from the plan.

## What happens

```
python scripts/orchestrator/plan_wave.py --release 1080a2
=== DISPATCH LEDGER: released 0 entries (1080a2) ===        exit 1
python scripts/orchestrator/plan_wave.py --release 1080A2
released w1080A2 (PB3127): 11 files
=== DISPATCH LEDGER: released 1 entry (1080A2) ===          exit 0
```

## Mechanism

- `record_dispatch()` (`scripts/orchestrator/plan_wave.py:415`) stores `"letter": g.letter`, the upper-case letter
  (`A`, `A2`).
- `release_dispatch()` (`scripts/orchestrator/plan_wave.py:442`) matches a non-PB selector with
  `selector in (str(g.get("wave")), f"{g.get('wave')}{g.get('letter', '')}")`, an exact, case-sensitive comparison.
- The `--release` help (`scripts/orchestrator/plan_wave.py:1028`) gives the example `a group (1040a)`, lower case,
  and every name a person reads the group from is lower case too: the slug `w{wave}{g.letter.lower()}`
  (`plan_wave.py:942`), the spec `msg-w1080-a2.txt`, the report `w1080a-PB3101-report.md`.

So the documented form never matches. The exit 1 is loud, so nothing is silently held, but a unit that does not read
the count, or a script that ignores the exit status, leaves the group's notes held in flight (PB3114 describes what a
held entry blocks).

## Fix direction

Compare the selector case-insensitively (`casefold()` on both sides) in `release_dispatch()`, the one place a group
selector is parsed, and add a regression test in `scripts/orchestrator/test_plan_wave.py`: a ledger with group `A2`
is released by `1080a2` and by `1080A2`, and `1080a` does not release `A2`. The other reader of the ledger's
letters already folds case: `prune_worktrees.py`'s `in_flight_slugs` lower-cases the `w<wave><letter>` slug it
matches against branch names (`scripts/prune_worktrees.py:538`); sweep the remaining readers of
`inflight-groups.json` for the same upper/lower split.
