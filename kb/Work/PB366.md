# PB366 — two disjoint type hierarchies, one is-test

**Rows:** `GR-14.9.49.4-14` (shared with **PB365**, which owns the binder-side arms of the same format).

## The program

`<lane3 scratch>/out-b1/probe/gr14-f4/factory-univ.cob` — `REPOSITORY CLASS CF1`; `01 FR USAGE OBJECT
REFERENCE.`; `DECLARATIVES F4SEC SECTION. USE AFTER EXCEPTION OBJECT CF1. / F4-P. DISPLAY "F4-HANDLER". END
DECLARATIVES`; MAIN does `SET FR TO CF1.` `RAISE FR.` `DISPLAY "AFTER".`

Observed **`AFTER` alone**. The control `inst-univ.cob` — identical but `INVOKE CF1 "NEW" RETURNING FR.` —
observes `F4-HANDLER` / `AFTER`, so the probe shape is sound and only the FACTORY case fails.

## The rule

> §14.9.49.4 GR14 a): If object-class-name-1 is specified and the exception object that was raised is a factory
> object or instance object of object-class-name-1 or of a subclass of object-class-name-1, the associated
> declarative is executed

`--check 14.9.49.4 "is a factory object or instance object of object-class-name-1 or of a subclass of
object-class-name-1"` → **OK**. `SET FR TO CF1` makes FR reference the FACTORY object of CF1 (§16.2 / §14.9.39),
so the declarative must run.

## What the compiler does

`EcEmitter.EmitObjDispatchSelector` (lines 405-416) emits `if (__obj is {cls.CsName})` using the **INSTANCE**
class name, while `OoEmitter.EmitClassUnit` emits the factory as
`public class {cls.Symbol.FactoryCsName} : {cls.Symbol.Base?.FactoryCsName ?? "CobolObject"}`
(`FactoryCsName = CsName + "__FACTORY"`). **The two type hierarchies are disjoint**, so the C# `is` test can never
be true for a factory object.

GR14 a) names factory and instance objects in ONE clause, so the selector needs ONE predicate covering both: a
runtime class-identity test on the COBOL class symbol, not a C# type test — the same shape
`SET <typed> TO EXCEPTION-OBJECT` already needs for its runtime narrowing.

## Why it is reachable and silent

The typed spelling `USAGE OBJECT REFERENCE FACTORY OF CF1` is separately loud-staged (COBOLNET0899, measured in
`factory.cob`), so the universal object reference above is today's ONLY reachable route to a factory exception
object — but it IS reachable, and it is silent: no declarative runs and nothing says so.

**Code sites:** `EcEmitter.cs#EmitObjDispatchSelector` (lines 405-416) · `OoEmitter.cs#EmitClassUnit` ·
`OoClassSymbol.cs#FactoryCsName`.
