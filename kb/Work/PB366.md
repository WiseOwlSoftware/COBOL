# PB366 — two disjoint type hierarchies, one is-test

**Rows:** `GR-14.9.49.4-14` (shared with **PB365**, which owns the binder-side arms of the same format).

## The program

`<lane3 scratch>/out-b1/probe/gr14-f4/factory-univ.cob` — `REPOSITORY CLASS CF1`; `01 FR USAGE OBJECT
REFERENCE.`; `DECLARATIVES F4SEC SECTION. USE AFTER EXCEPTION OBJECT CF1. / F4-P. DISPLAY "F4-HANDLER". END
DECLARATIVES`; MAIN does `SET FR TO CF1.` `RAISE FR.` `DISPLAY "AFTER".`

Observed **`AFTER` alone**. The control `inst-univ.cob` — identical but `INVOKE CF1 "NEW" RETURNING FR.` —
observes `F4-HANDLER` / `AFTER`, so the probe shape is sound and only the FACTORY case fails.

## The rule

> §14.9.49.4 GR14 a): If object-class-name-1 is specified and the exception object that was raised is a factory
> object or instance object of object-class-name-1 or of a subclass of object-class-name-1, the associated
> declarative is executed

`--check 14.9.49.4 "is a factory object or instance object of object-class-name-1 or of a subclass of
object-class-name-1"` → **OK**. `SET FR TO CF1` makes FR reference the FACTORY object of CF1 (§16.2 / §14.9.39),
so the declarative must run.

## What the compiler does

`EcEmitter.EmitObjDispatchSelector` (lines 405-416) emits `if (__obj is {cls.CsName})` using the **INSTANCE**
class name, while `OoEmitter.EmitClassUnit` emits the factory as
`public class {cls.Symbol.FactoryCsName} : {cls.Symbol.Base?.FactoryCsName ?? "CobolObject"}`
(`FactoryCsName = CsName + "__FACTORY"`). **The two type hierarchies are disjoint**, so the C# `is` test can never
be true for a factory object.

GR14 a) names factory and instance objects in ONE clause, so the selector needs ONE predicate covering both: a
runtime class-identity test on the COBOL class symbol, not a C# type test — the same shape
`SET <typed> TO EXCEPTION-OBJECT` already needs for its runtime narrowing.

## Why it is reachable and silent

The typed spelling `USAGE OBJECT REFERENCE FACTORY OF CF1` is separately loud-staged (COBOLNET0899, measured in
`factory.cob`), so the universal object reference above is today's ONLY reachable route to a factory exception
object — but it IS reachable, and it is silent: no declarative runs and nothing says so.

**Landed 2026-09-09.** Row `GR-14.9.49.4-14` keeps its `DIVERGES` verdict — it carries TWO measured defects and
this note owned only the first; **PB365** owns the second (GR14 b), so the row cannot close here and the GAP is
unchanged (2733). What this landing changed in the row: the notes now record GR14 a)'s factory arm as FIXED, with
the witness, and the `test-ref` names the new goldens.

**The fix.** `BoundDeclarative.EoClassCsName` — a rendered C# type NAME — became `BoundDeclarative.EoClass`, the
RESOLVED `OoClassSymbol`, and `EcEmitter.EmitObjDispatchSelector` now renders the symbol's
`OoClassSymbol.FactoryOrInstanceCsTypes` census as ONE C# or-pattern per entry:
`if (__obj is CF1 or CF1__FACTORY) return __RunUse(…);`. That is the shape of the rule rather than the shape of
one case: GR14 a) names both object kinds in a single clause, so a COBOL class-name in this position is a SET of
emitted C# types, and the census is the ONE place that says which. The "or of a subclass" reach still rides C#'s
`is`, now in EACH hierarchy — both mirror INHERITS (`DOG : ANIMAL` and `DOG__FACTORY : ANIMAL__FACTORY`).
Choosing the C# spelling moved back to the emitter, where it belongs; the bound tree carries the symbol.

**Why not a runtime class-identity test** (this note's original proposal). The C# type system DOES model the COBOL
class hierarchy — as two parallel trees, not one — so no runtime metadata is needed, and a reflection-free
two-arm `is` stays AOT-safe and allocation-free on the raise path. What was missing was not a mechanism but the
census: the compiler knew a class had two emitted halves (`OoEmitter.EmitClassUnit` emits both) and the selector
asked for one.

**The sibling arm, checked and left alone.** `OoEmitter.EmitSetObjectRef`'s `SET <typed> TO EXCEPTION-OBJECT`
narrow tests the INSTANCE name only — and that is CORRECT, not the same bug: §13.18.60.4 GR22 d) 1. b) — "If the
FACTORY phrase is not specified, the object referenced by this data item shall be an instance object of the
specified class or of a subclass of the specified class" (`--check 13.18.60.4` → OK). A typed `OBJECT REFERENCE
CF1` may not hold a factory object, so a factory object failing that narrow into EC-OO-UNIVERSAL is the rule.
Those are the only two emitted C# type tests against a COBOL class-name in the compiler.

**Goldens.** `tests/conformance/2002/pb366_use_exception_object_factory.cob|.out` (PROGRAM-ID `PB366A`) walks
five arms of GR14: the factory object of the named class; the factory object of a class TWO declaratives match
(source-order first-match, "no other declaratives are executed"); the factory object of a SUBCLASS naming no
declarative of its own; an INSTANCE object; and the factory object of a class no declarative names (the
§14.6.13.1.5 tail — "If there is no associated declarative, execution continues as specified in the RAISE
statement"). On the pre-fix tree the first three printed NO handler.
`tests/conformance/negative/pb366-use-exception-object-85.cob|.err` holds the COBOL-2002 edition gate,
COBOLNET0876. `Format4UseObjectSelectorDriftTests` is the drift guard: it asserts against the GENERATED C# that
the class symbol's census equals the set of C# types the backend actually emits for that class, and that the
generated `__EcObjDispatch` tests every one of them — so a third emitted half fails at the census instead of
silently narrowing a user's declarative selection.
