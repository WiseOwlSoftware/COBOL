# PB4410 — three descriptions of the self-test rule predate PB4409

**Sites:** `scripts/orchestrator/land_lane.py:806` (`classify_red`), `scripts/self_tests.py:719` (`Runner._record`),
`CLAUDE.md` (Testing), `kb/Work/PB4409.md`.

PB4409 (#999) split the tooling flag in two. `Lane.tooling` (a changed script) now drives the local gate's self-tests,
and `Lane.reads_tooling` (the old, broad flag, which a `TOOLING_READS` data file such as `docs/CONFORMANCE.md` sets)
drives only CI's `windows-self-tests` job. Three descriptions still state the rule as it was:

1. **`scripts/orchestrator/land_lane.py` 806-809,** the THE RULE comment above `classify_red`. It names the merge group
   as the first run "of the Windows tooling self-tests on a tooling change". Since PB4409 it is also the first run of the
   Windows self-tests that a compiler change's data files reach; CLAUDE.md, the design doc and MANDATORY-PRACTICES I1
   already say so.
2. **`scripts/self_tests.py` 719-721,** the RED message of the unclassified-read proof in `Runner._record`. It says a
   path without a `TOOLING_READS` entry "would skip this self-test in a gate and turn it red in CI's merge group", and
   tells the author to add the entry. After PB4409 a `TOOLING_READS` path also skips the self-test in a compiler
   change's gate; the entry now only reaches CI's `windows-self-tests` (`reads_tooling`). The message should say what the
   entry buys now.
3. **`CLAUDE.md` Testing (lines 134-135) and `kb/Work/PB4409.md` (line 49)** say CI's Linux `audits` job "runs every
   self-test on every merge group". It runs the runner, which reports each `# SELF-TEST-PLATFORM: windows` self-test
   `NOT RUN on linux`, so the Windows-only ones run only in `windows-self-tests`.

**Fix.** Restate all three from the two flags. Sweep `docs/`, `.claude/` and `scripts/` for "every self-test" and
"tooling self-tests on a tooling change" for other copies.
