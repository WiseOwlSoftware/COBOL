# PB5933 - analysis: the 1985 citation of COBOL0865

**Sites:** `src/WiseOwl.Cobol.Editions/Diagnostics/DiagnosticCatalog.cs#DeleteRecordOnSequentialFile` (line 9502, COBOL0865),
`src/WiseOwl.Cobol.Editions/Diagnostics/DiagnosticDescriptor.cs#DiagnosticDescriptor` (its `No1985Rule` parameter, line 74).

**The lead (PB4950 review round 6, R6-1, low).** COBOL0865 records `No1985Rule`: "ANSI X3.23-1985 defines the DELETE statement only in the
relative I-O module (§1985:VIII.4.3.1) and the indexed I-O module (§1985:IX.4.3.1); the sequential I-O module (§1985:VII) has no DELETE
statement and so states no rule about one on a sequential file". By PB4950's contract (`DiagnosticDescriptor.No1985Rule`: "may cite a later
edition's rule at `--std 85`") the message at 85 therefore cites `ISO §2023:14.9.10.3 SR1`. The reviewer's point is that a 1985 program that
uses the 1985 DELETE statement on a sequential file is told a 2023 rule, while the branch elsewhere cites the 1985 general format that does not
print the construct (NEXT GROUP -> §1985:XIII.3.9.2, relative WRITE ADVANCING -> §1985:VIII.4.9.2), so a 1985 citation exists by the branch's
own convention.

**Still true on origin/main (0d4042678a), read this session.**
- `DiagnosticCatalog.cs:9502-9512` still carries `No1985Rule:` and `IsoSection` is the single string `"ISO §2023:14.9.10.3 SR1"`.
- The 1985 text has the DELETE statement only in two modules: `specs/ANSI_COBOL_1985.md` line 17727 (Relative I-O, `## 4.3 THE DELETE
  STATEMENT`) and the matching Indexed I-O clause. `python scripts/spec/cite.py --check "§1985:VIII.4.3.2" "DELETE file-name-1 RECORD"` ->
  `OK  §1985:VIII.4.3.2  (4.3.2 General Format)`; the same for `§1985:IX.4.3.2`; `--check "§1985:VIII.4.3.4 GR1" "The file referenced by
  file-name-1 must be a mass storage file and must be open in the I-O mode"` -> `OK  §1985:VIII.4.3.4 GR1`; `--check "§2023:14.9.10.3 SR1"
  "The DELETE RECORD statement shall not be specified for a file with sequential organization."` -> `OK`.
- The recorded 1985 reads still print the 2023 rule at 85: `tests/version-matrix/code-reads-1985/1985-GR-IX.4.3.4-1.json:47` and
  `1985-GR-VIII.4.3.4-1.json:41` quote "COBOL0865: DELETE RECORD shall not be specified for sequential-organization file 'SQ' (ISO §2023:14.9.10.3
  SR1)", and the latter's evidence calls it "a citation-edition detail".

**What the analysis must decide (this note rules on none of it; it needs the spec reading of the 1985 modules).**
1. Which 1985 rule a DELETE on a file the program declares sequential breaks: GR1 of §1985:VIII.4.3.4 / §1985:IX.4.3.4 ("must be a mass storage
   file", which a sequential file may be) or no rule at all, in which case `No1985Rule` is right and the lead is dropped with this reasoning
   recorded in the descriptor.
2. If a 1985 rule exists: drop `No1985Rule` and give the descriptor a 1985 message, `EditionCitationNet` then asks it of the 85 refusals the
   conformance suite compiles (`conformance-suite/wiseowl/diagnostics/*delete-record*.json` list `85` in `refuse-at`).
3. Refresh the two code-reads above if the message changes.
