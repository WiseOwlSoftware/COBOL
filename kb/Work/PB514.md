# PB514

## Mechanism — data-description-entry-p1
The three 'permitted set' guards are hand-maintained boolean condition lists, one per rule, and they have drifted apart: the DYNAMIC LENGTH list (SR18) is complete, the ANY LENGTH twin thirty lines above it (SR17) is missing GLOBAL and PROPERTY, the SAME AS list (SR12) is missing GROUP-USAGE and PROPERTY, and the CONSTANT RECORD rule keeps TWO different lists -- a same-entry one that honours DYNAMIC LENGTH and a subordinate-entry one that does not (SR13). The SR18 comment even records WHY GLOBAL needs an explicit flag; its sibling was never updated.

### Expected, from the standard
13.16.3 SR17: with ANY LENGTH 'the only other clauses permitted are level-number, entry-name, PICTURE, USAGE, and VALUE' -- GLOBAL (13.18.27) and PROPERTY (13.18.42) are outside it. 13.16.3 SR12: SAME AS composes only with CONSTANT RECORD, entry-name, EXTERNAL, GLOBAL, level-number and OCCURS -- GROUP-USAGE (13.18.29) and PROPERTY are outside it. 13.16.3 SR13: the ANY LENGTH, BASED, BLANK WHEN ZERO, DYNAMIC LENGTH, select-when, SYNCHRONIZED and TYPEDEF clauses and validation-clauses 'shall not be specified in the same data description entry with the CONSTANT RECORD clause, OR IN ANY DATA DESCRIPTION ENTRY SUBORDINATE to' one -- DYNAMIC LENGTH is named, and the subordinate half is not optional. Each repro shall be rejected with a named diagnostic.

### Observed
All five accepted. The guards are: COBOLNET1542 (SR17) testing occurs/redefines/based/external/justified/blankWhenZero/synchronized/sign/typedef/type; COBOLNET1555 (SR12) testing picture/usage/value/sign/justified/blankWhenZero/synchronized/redefines/based/anyLength/type/typedef; COBOLNET1549 (SR13 same entry) plus a SECOND list in BindEntries for the subordinate half reading `BlankWhenZero || Synchronized || IsBased || IsAnyLength || IsTypedef`. COBOLNET1563 (SR18) is the only one that is complete, and it is the newest. This is the two-arm-dispatch shape: five lists expressing ONE idea (which clause words a given clause admits), each edited when its own rule was implemented and never re-derived from the others. The structural fix is a single permitted-set predicate over a decoded clause-presence set, asked once per rule and once per entry (same-entry AND subordinate), with a drift test that asserts every dataDescriptionClause alternative is classified by every such rule -- so the NEXT clause added to Format 1 cannot slip through any of them.
