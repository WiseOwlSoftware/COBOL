# PB3661 — a malformed previous-gate trx costs the plan, names no file, and leaves no evidence

**Sites:** `scripts/gate_plan.py#trx_results` (with `read_previous_run`, `read_reds`, `previous_gates`),
`scripts/test_population.py#read_trx` (the second trx reader), `scripts/run_gate_legs.py` (the `the order plan could not
be made` arm, and the Linux half that empties `TestResults/linux-gate/` before it writes), `scripts/linux-gate.sh`.

## What happened (resume unit, 2026-10-24 ~15:55 PDT)

Gate run `000005-20261024T225004Z` in `E:\COBOL\.claude\worktrees\wf_1973801d-4fe-29` (the merged head 5e110b97e of
PB2974) printed:

> build-local: ⚠ the order plan could not be made — no plan (ParseError: not well-formed (invalid token): line 104295,
> column 36); ONE leg in the plain order

and then ran the whole population of all three assemblies in one leg, GREEN, with its Linux half GREEN.

- The message does not say which file. The plan reads only trx files (`gate_plan.trx_results`, the one `ET.parse` on
  this path): the previous build-local run's (`000004-…/leg-1-*.trx`, which all parse today) and the Linux gate's
  newest run's (`TestResults/linux-gate/*.trx`, the tier 0a reds of the other host, PB3155). So the malformed file was
  a Linux-gate trx left by an earlier `linux-gate.sh` run in that worktree.
- That evidence is gone: this same gate's Linux half emptied `TestResults/linux-gate/` and wrote fresh trx files at
  16:00 (all three parse). A scan of all 108 trx files under every worktree's `TestResults/` found none malformed. The
  cause of the bad file (an interrupted writer, two writers, a raw control character in a test's output) cannot now be
  determined.

## Why it matters

The fallback itself is the conservative one: with a source of reds unreadable the gate cannot know what was red, and
running everything in one leg drops nothing (ORDER, DON'T SKIP, PB1708). The cost is the plan: no fail-fast order and
no leg 2 left to CI, so a ~2 min leg-1 gate becomes a whole-population run (here 3 min Conformance, 2 min 44 s Unit, plus
the Linux half of the whole population). The defect is diagnosability: a reader cannot tell which file to look at, and
the gate itself destroys the file before its verdict.

## The fix

- `trx_results` names the file when it cannot read it, as `test_population.read_trx` does ("<path>: cannot read the trx
  (…)"). Better: ONE trx reader for both (a duplicated mechanism; `test_population.read_trx` already reads the
  definitions and outcomes the plan needs), so the next reader cannot drift from it.
- Before the Linux half empties `TestResults/linux-gate/`, a trx the plan could not read is kept in the run directory
  (for example `unreadable-linux-gate-<name>.trx`), and the plan note names it, so the cause can be found afterwards.
- Decide, and pin with a self-test, whether an unreadable SIDE source (the Linux reds) still costs the whole plan or
  only that source's tier 0a with a loud note. Running everything is the safe reading of "reds unknown", so keep it
  unless the owner's batched-gating cost decision (PB2515) says otherwise.
- Sweep the other `ET.parse` of a trx (`scripts/profile-test-parallelism.py`) for the same unnamed failure.
