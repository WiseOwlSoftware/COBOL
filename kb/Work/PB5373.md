# PB5373 - how a 1985 rule with no reachable witness closes

**Sites:** none (a decision; the tooling it asks for is kb/Work PB5374)

## What is decided

kb/Work PB4995 lists 21 rules of the 1985 edition whose confirmation record is UNDECIDED: each asks what may stand as the
rule's witness when no draft program can show it. They are decided here by class. A class names the record a row needs;
the adjudicator that writes the record still reads the rule and the compiler, checks every citation
(`scripts/spec/cite.py --check`), and moves a row to another class when the rule's text does not fit the one named here,
saying so in the record.

The codebase is Claude's to decide (CLAUDE.md, Ownership; owner 2026-11-10), so these decisions are mine. One of them
changes a bound the owner set himself in 2026-09 (the signature on a derivation, below); it is flagged to him in this
session's report.

## The six classes

1. **The rule itself declares the result undefined.** `1985-GR-IV.4.4.2-L2.1`, `-L2.2`, `1985-GR-XIV.2.2.4-7`, `-29`,
   `1985-GR-XIV.3.6.4-5`. A conforming compiler has nothing to do, and any test would pin WiseOwl's choice as the
   standard's answer (DESIGN-spec-conformance-review.md section 1.1). The row closes on a DERIVATION. The 2023 arm for
   this, `undefined-A.2`, is checked against Annex A.2, which the 1985 standard does not have; the 1985 rows use a new
   arm, `undefined-in-rule`, checked mechanically: the rule's own catalog text states that the result is undefined (or
   unpredictable), and the derivation quotes those words. No complementary-case witness is recorded on such a row: the
   complementary case is another rule's row.

2. **The antecedent needs a medium or a device that WiseOwl defines none of.** `1985-GR-VII.4.7.4-15` (reels),
   `1985-GR-XIV.3.6.4-14`, `-16`, `-18` (a device with vertical positioning, superimposition, a second transmission to a
   line). The row closes on a derivation of the existing arm `unpopulatable-antecedent`, whose `Names` cell states the
   closed set, and only where `docs/CONFORMANCE.md` already documents that absence (section 3.3 for the devices). Where it
   does not, the documentation is written first, in the same change.

3. **The rule's subject is a language element WiseOwl refuses or declines by a documented decision.**
   `1985-GR-VII.2.8.4-6` and the ENTER rules `1985-GR-VI.6.12.4-1`, `-2`, `-3`. The verdict is DOCUMENTED-NON-SUPPORT and
   the witness is the element's named diagnostic: a test that the construct draws it at `--std 85`.
   - §1985:VII.2.8.4 GR6 asks that "all RECORD DELIMITER clauses in the run unit which are associated with that file
     connector must have the same specifications". WiseOwl declines the whole RECORD DELIMITER clause
     (`docs/CONFORMANCE.md` section 2, row 26) and accepts it inert with the warning COBOL1778, so the clause specifies
     nothing two programs could disagree on. kb/Work PB4995 described this row as "refused"; it is a warning, and the
     witness is that warning.
   - The ENTER rows wait for kb/Work PB5308 (refuse ENTER by name at 85). §1985:VI.6.12.3 SR1 says "Language-name-1 is
     specified by the implementor", and WiseOwl specifies none. The three rows are recorded with `1985-SR-VI.6.12.3-1`
     and `-3` when PB5308 lands, never before, and `ENTER COBOL.` is not a witness of them: the rules speak only of
     another language's statements.

4. **The antecedent is the implementor's to define, and WiseOwl defines it.** `1985-GR-IX.1.3.4-6` (the 9x status
   conditions), `1985-GR-VII.4.7.4-14` (the file boundary), `1985-GR-XIV.2.2.4-25` and `-30` (a program the MCS
   scheduled), `1985-GR-VI.6.24.4-3` (the purge, seen by a second run unit). These have an observable obligation in this
   implementation, so they get a TEST, never a derivation. Its expected result comes from the rule's text applied to the
   determination `docs/CONFORMANCE.md` states, and it is a WiseOwl-only test (`conformance-suite/wiseowl/`), since
   another compiler's determination differs. Where the draft shape cannot set the scene (two run units over one MCS, an
   environment set before the run unit starts), the witness is a harness test with that environment, or a unit test named
   `unit:<Class>.<Method>` as the 2023 rows of the communication facility already do. A determination that is not yet
   stated in `docs/CONFORMANCE.md` is stated first.

5. **The rule's whole effect is outside what a run shows, or it asks nothing a compiler could fail.**
   `1985-GR-VI.3.4.4-1` (an effect on the source listing) and `1985-GR-VI.4.4.4-1` (any computer-name is accepted,
   DOC-A.1-127). For the listing rule the adjudicator first establishes whether WiseOwl produces a listing the rule could
   reach: if it does, the witness reads the listing; if it does not, the row is class 2 (`unpopulatable-antecedent`, the
   absence documented). The computer-name rule closes on an acceptance test (the program compiles and runs with an
   arbitrary computer-name at 85): acceptance is observable, so it is not a derivation.

6. **A syntax rule that cannot be broken alone.** `1985-SR-XIII.3.17.3-2` (a SIGN clause applies only to entries
   described as USAGE IS DISPLAY): in the Report Section every violation of it also violates §1985:XIII.3.21.3 SR3, "The
   USAGE clause for a report group item can specify only USAGE IS DISPLAY". The witness is one refusal test that asserts the rule's OWN diagnostic among those reported at
   the violating line (the harness pins a code at a line; it does not require that code to be the only one). If the
   compiler reports only the other rule's code there, that is a defect note, not a witness.

## The signature on a derivation

DESIGN-spec-conformance-review.md section 1.1 has a derivation "signed by the owner": the owner read each argument, and
the schema's `signatures` map holds one key per dated owner decision. The owner delegated the codebase on 2026-11-10, and
the 1985, 2002 and 2014 inventories will need more derivations than he should be asked to read one by one. From this
decision on:

- a derivation is signed by the session that decided it, with a key of the form `claude: <date>` mapped to the decision
  note that read the rows (this note for the rows above);
- the independent read the owner's signature supplied is kept: a derivation of an ARGUED arm
  (`unpopulatable-antecedent`, `indistinguishable-consequent`, `definitional`) is recorded only with an UPHELD record of
  a `cobol-refuter` that tried to write the witness the derivation says cannot exist. An overturned one becomes a test;
- the mechanical arms (`undefined-A.2`, `undefined-in-rule`) need no refuter: the checker is the reader;
- the owner's existing signatures stand as they are.

The six refusals of section 1.1 are unchanged. The design doc and `docs/CONFORMANCE.md` section 8 are updated by the
change that builds this (kb/Work PB5374), not by this note.

## What happens next

- kb/Work PB5374 builds the tooling: the `undefined-in-rule` arm, the signature key and its refuter requirement, and
  section 8 rows keyed by a 1985 rule id.
- One read-only adjudication applies the classes to the 21 rows and writes each row's proposed record (verdict,
  code-location, the test or the derivation text, citations checked), then a refuter reads every closing one. Classes 3
  to 6 need no new tooling and are recorded as their tests land; classes 1 and 2 are recorded when PB5374 lands.
