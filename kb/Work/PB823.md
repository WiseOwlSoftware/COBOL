# PB823 — OPEN — the exclusion was written on the wrong arm

Filed 2026-09-09 by the registrar (second pass) from the **PB803 implementer's report**, "New defects /
observations" (b) — `scratchpad/reports/PB803-report.md` — which recorded it **as a question and explicitly not
as a defect claim**, having built no probe. **The probe was built here, and it reproduces.**

## The measurement

```
$ cobol.exe p21_refmod_class.cob --std 2023 --run
RAW=[123M]
REFMOD-NUMERIC          <-- IF S (1:4) IS NUMERIC   → TRUE
WHOLE-NUMERIC           <-- IF S IS NUMERIC         → TRUE (correct)
exit=0
```

`registrar2/probe/p21_refmod_class.cob` is `01 S PIC S9(4) VALUE -1234.` — stored as the over-punched image
`123M` under the default `ibm` sign encoding — tested twice.

The same shape through a table subscript reproduces too
(`registrar2/probe/p21b_tableall.cob`, `05 S PIC S9(4) OCCURS 2`, `IF S (1) (1:4) IS NUMERIC` →
`SUB-REFMOD-NUMERIC`).

## The rules, quoted, with the `--check` lines actually run

```
$ python scripts/spec/cite.py --check 8.4.3.3.4 "the categories numeric and numeric-edited are considered class and category national if the usage is national; otherwise they are considered class and category alphanumeric"
OK  §8.4.3.3.4 6) c)  (General rules)

$ python scripts/spec/cite.py --check 8.8.4.4.4 "If the category of the data item referenced by identifier-1 is not numeric, the condition is true if the content of the data item referenced by identifier-1 consists entirely of the characters 0, 1, 2, 3"
OK  §8.8.4.4.4 3) d) 2.  (General rules)
```

(The transcription letters that last item **n) 2.** — `specs/ISO_COBOL.md:8694` "n) If NUMERIC is specified,"
and `:8706` "2. If the category … is not numeric …". `cite.py`'s path builder mis-letters items below the rule
ordinal; see [[PB779]]. The RULE is §8.8.4.4.4 3), and the quoted sentence is verbatim.)

So: reference modification makes the unique data item **category alphanumeric** (GR6 c), usage display), and a
non-numeric-category operand is NUMERIC **iff its content is entirely digits** — no operational sign admitted.
`123M` contains `M`. The condition shall be FALSE.

## Expected vs observed

| | expected | observed |
|---|---|---|
| `IF S (1:4) IS NUMERIC` over image `123M` | FALSE (§8.8.4.4.4 3) n)2 via §8.4.3.3.4 GR6 c) | **TRUE** |
| `IF S IS NUMERIC` | TRUE (§8.8.4.4.4 3) n)1.a — the sign is in agreement) | TRUE |

## Mechanism — `src/Cobol.Net.Compiler/CodeGen/Emit/ConditionRenderer.cs:455-481`

```csharp
bool numericField    = numericCategory && fld!.Place is not RedefViewPlace && !fld.Place.Item.StoreAsImage;
// The complement, minus the ref-mod shape: a numeric leaf whose storage IS a character window.
bool windowedNumeric = numericCategory && fld!.Place is not (RefModPlace or TableAllPlace)
                       && (fld.Place is RedefViewPlace || fld.Place.Item.StoreAsImage);
…
string numericTest = windowedNumeric ? RuntimeApi.NumIsNumericImage(…)
    : numericCategory && fld!.Place.Item.OperandPic is { Signed: true } sp
        ? $"CobolClass.IsNumericZoned({arg}, …)"      // the SIGNED test — §8.8.4.4.4 GR3 n)1.a
        : $"CobolClass.IsNumeric({arg})";             // the all-digits test — n)2
```

The RefMod/TableAll exclusion is written on `windowedNumeric` — **the wrong arm**. Excluding a place kind from
one branch of a two-branch chain does not send it to the branch you want; it sends it to the *next* test, and
the next test asks `OperandPic is { Signed: true }` about **the ITEM**, not about the reference-modified
operand. The item is signed, so the sign-admitting test wins.

This is `feedback_one_rule_one_place` from the other direction: the file's own comment insists on "the ONE
category reader", and the reader it uses (`OperandPic.Category`) answers a question about the *item* while the
rule asks about the *operand*. §8.4.3.3.4 GR6 is precisely the transformation between those two subjects, and no
code applies it.

## The fix shape

Apply GR6 where the operand is formed, not where the class condition is rendered: a reference-modified (or
`ALL`-subscripted) operand's effective category is alphanumeric — or national, per GR6 c)'s own condition — and
every consumer that asks "what category is this operand" should get that answer from one place. Then
`RenderClass`'s chain needs no place-kind exclusions at all, and the two arms follow from the category.

## Second observation, reachability NOT measured

The signed arm string-sniffs `sp.SignKind` (`.Contains("Separate")`, `.Contains("Leading")`), so a `SignKind` of
`"BinaryMinus"` would be silently mapped to trailing-overpunch. **I did not establish that a `BinaryMinus` leaf
can reach this arm** — a binary leaf stored as an image goes through `RedefViewPlace`/`StoreAsImage`, i.e. the
`windowedNumeric` branch, and ref-modifying a non-DISPLAY item has its own rules. It is recorded as a lead, not
a claim (`feedback_reachability_is_measured_not_deduced`). Whoever fixes the arm should measure it; a
`SignKind` enum in place of the two `Contains` calls removes the question either way.

Also measured, and worth knowing before writing a golden: `IF S (ALL) IS NUMERIC` over a table does not reach
this code at all today — it dies at run time with `NotImplementedCobolFeatureException: reference 'S(ALL)'`
(the [[PB390]] shape). So the `TableAllPlace` half of the exclusion has no live subject, and the REF-MOD half is
the whole of the reachable defect.
