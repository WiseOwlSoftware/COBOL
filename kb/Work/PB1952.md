## Landed (wave 1042 A, 2026-10-08)

Re-probed on the wave's build: `E:\COBOL-coord\scratch\w1042a\p\m1.cob` (a CLASS whose METHOD moves the method-local
`AE PIC XX/X` and the object's `OAE` to themselves and SETs the method's `IX` and the object's `OX` under
`>>TURN EC-RANGE-INDEX CHECKING ON`) drew no COBOLNET1620; its PROGRAM twin `p1.cob` drew both. After the fix all four
statements warn.

**Fix.** `FlagConformancePass.Run` maps every bound METHOD (`DataBinder.OoBoundMethods` of each class's OBJECT and
FACTORY binders) to its binder, resolver and `OoMethodDataScope`; `VisitMethodDefinition` selects them and activates
the method's scope on the binder for the walk of the method (the overlay `StatementBinder` activates while binding the
same statements, §11.7.4 GR5), restoring it on exit. `FlagIndexSet` asks the scope-aware `SymbolTable.IndexCandidates`
instead of the unit's `IndexNames`, so a method's own index-name (and a nearer data-name shadowing one, kb/Work
PB1047) is seen. Witness: `FlagDirectiveTests.Compile_MethodBody_FlagsMoveToSameNameAndIndexSet`. `docs/CONFORMANCE.md`
DOC-A.1-79 no longer carries the caveat. No golden: the flag is a compile-time warning with no run-time output.

## Found (train 1012, from the w1012k implementer report; PB1375 recorded it in prose only)

§7.3.14.4 GR4 d) and e) apply to every source element, methods included. `FlagConformancePass` name-resolves data
references through `_currentData`, which `VisitUnit` sets for program and function units only; inside a METHOD it is
null, so an operand's category or index-ness is never known and the two detectors stay silent. The warning is
advisory (no wrong answer at run time), but the migration flag promises the user a complete list.

**Repro:** a CLASS with a METHOD whose WORKING-STORAGE declares `01 AE PIC XX/X` (alphanumeric-edited) and whose
procedure division says `MOVE AE TO AE`, compiled at COBOL-2023 under `>>FLAG-02 MOVE-TO-SAME-NAME ON`: no warning;
the same lines in a PROGRAM warn. Probe shape: `E:\Temp\claude\E--COBOL\e8598e10-eb23-44b5-98e0-e0f07cc381fb\scratchpad\w1012k\p\m1.cob`.

**Code site:** `src/Cobol.Net.Compiler/Validation/FlagConformancePass.cs#VisitUnit` (`_currentData`), and the
element model `#VisitElement` / `#SourceElementOf` PB1375 built. The fix needs the class's `DataBinder` plus the
method scope overlay (the binder already has both: `DataBinder.Oo.cs` method bindings), selected per element the
way `SourceElementOf` selects the TURN's element.
