# PB5751 - an ON SIZE ERROR phrase does not stop the statement from setting EC-SIZE-TRUNCATION

**Sites:** `src/WiseOwl.Cobol.Compiler/CodeGen/EcEmitter.cs:747` (`EcEmitter.EmitSizeHandling`): the
`ExceptionState.Set(ecnVar, true)` line runs whether or not `hasPhrase`; only the selection and fatal default are skipped
with a phrase. The member's summary rests the choice on a `§2023:14.6.13.1.3 #1` reading.

**Repro** (`E:\COBOL-coord\scratch\gl2002\integrate-6\repro\sizeerr_phrase_sets_ec.cob`, from the writer's
`lane1\out\g2002u-7-2-19-turn-directive\defects\`):

```cobol
       >>TURN EC-SIZE CHECKING ON
       IDENTIFICATION DIVISION.
       PROGRAM-ID. SZPH.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 A PIC 9 VALUE 9.
       PROCEDURE DIVISION.
           ADD 1 TO A ON SIZE ERROR
               DISPLAY "S [" FUNCTION EXCEPTION-STATUS "]"
           END-ADD.
           DISPLAY "A=" A.
           STOP RUN.
```

**The 2002 rule.** §2002:14.6.4 sets the EC-SIZE conditions to exist only in its no-phrase branch: "If the size error
condition exists and a SIZE ERROR phrase is not specified: ... 3) if the absolute value of the result of an arithmetic
statement exceeds the largest value that may be contained in the associated resultant data item, the EC-SIZE-TRUNCATION
exception condition is set to exist". The phrase branch leaves the receiver unchanged and transfers control to the
imperative-statement; it sets no condition. The informative §2002:E.15 says the same: "if the SIZE ERROR phrase is
specified on an arithmetic statement, the raising of the EC-SIZE exception condition is disabled for that statement".

- `python scripts/spec/cite.py --check "§2002:14.6.4" "If the size error condition exists and a SIZE ERROR phrase is not specified"` -> `OK  §2002:14.6.4  (SIZE ERROR phrase and size error condition)  the text is in the clause`
- `python scripts/spec/cite.py --check "§2002:E.15" "the raising of the EC-SIZE exception condition is disabled for that statement"` -> `OK  §2002:E.15  (Common exception processing)  the text is in the clause`

**Expected** at `--std 2002`: `S [` + 31 spaces + `]`, then `A=9` (no exception condition exists, so EXCEPTION-STATUS is
spaces). **Observed** (`cobol.exe sizeerr_phrase_sets_ec.cob --std 2002 --run`, exit 0): `S [EC-SIZE-TRUNCATION             ]`,
`A=9`. The default edition (2023) prints the same.

**2023.** The 2023 text keeps the same phrase / no-phrase structure in its SIZE ERROR rules (the writer's reading of
§2023:14.7.5); whether the 2023 reading in the member's summary holds is for this note's owner to decide on the 2023
text, so the fix may be all editions or 2002 only. Rows: none of the 2002 inventory is blocked today (the TURN goldens
dropped their SIZE legs); the fix's golden witnesses §2002:14.6.4 at 2002.
