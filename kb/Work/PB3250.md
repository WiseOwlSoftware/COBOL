# PB3250 — a vanished worktree aborts the whole checkpoint write

Filed 2026-10-16 by a clerk from the operator's verified report. No existing note covers this mechanism (grep of
kb/Work for NotADirectoryError, `checkpoint.py`, `worktrees()`: PB2590 concerns the probe's cost and test isolation,
not a worktree vanishing mid-survey).

**Symptom.** `scripts/orchestrator/checkpoint.py#worktrees` (lines 40-68) lists worktrees with
`git worktree list --porcelain`, then for each runs `git(path, "status", "--porcelain")` and
`git(path, "rev-list", ...)` with the worktree as the subprocess cwd. If a worktree is removed between the list and
the status call (`prune_worktrees.py --apply`, or a finished agent's cleanup), `subprocess.run` raises
`NotADirectoryError: [WinError 267] The directory name is invalid`. The exception is non-fatal to the supervisor,
which logs the traceback, but the whole checkpoint write is skipped.

**Evidence.** Seen three times in `E:\COBOL-coord\logs\orchestrate-20261015-104306*.log` (around 2026-10-15 11:17,
13:34 and later).

**Harm.** The supervisor's `checkpoint.json` goes stale for that tick, so a unit dying then gets a handoff built from
an older checkpoint.

**Target fix.** Skip a listed worktree whose path no longer exists or whose git call raises; a vanished worktree is
not a checkpoint error. Add a self-test under `scripts/orchestrator` (beside `test_checkpoint.py`) that removes a
worktree between the list and the status call. Sibling sweep: the other callers that run git with a listed worktree
as cwd (`synthesize` calls `worktrees(repo)`).

**Site.** `scripts/orchestrator/checkpoint.py#worktrees`.
