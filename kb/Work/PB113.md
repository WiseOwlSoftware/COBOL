# PB113 — report-writer format-2 PICTURE: a silent wrong answer today

**Measured 2026-08-28 (the PB64 T6 hardening sweep, read-only):** `DataBinder.Reports.cs:401` binds a report
group entry's PICTURE by reading `clause.pictureClause()?.PIC_STRING()` and never inspects
`pictureLocalePhrase()`. So `02 X PIC ZZ9.99 LOCALE SIZE IS 12.` inside a REPORT SECTION is accepted TODAY
with NO diagnostic — not even the (pre-T6) COBOLNET1518 the working-storage arm raises — and the picture is
analyzed as Format 1: the item's width comes from the mask instead of §13.18.40.4 GR17's integer-1, and no
locale editing exists. §13.15.4 GR2 imports the PICTURE clause's own rules into report group description
entries, so format 2 is LEGAL there and the acceptance is a silent wrong answer, independent of whether T6 has
landed.

**Sibling fact asserted at the same time (a deliberate NON-arm):** §13.15.3 carries NO SIGN-with-LOCALE
prohibition (the §13.16.3 SR19 / §13.17.3 SR9 pair does not exist for report groups), so the fix must NOT copy
the SR19 check to `DataBinder.Reports.cs:408` — a positive golden pins a report group entry carrying both
LOCALE and SIGN as ACCEPTED.

**Fix (rides the PB64 T6 landing):** route the report-group PICTURE bind through the SAME format-2 analyzer as
the data-division and screen arms — one analyzer, three callers ([[feedback_one_rule_one_place]]). Golden: a
report group format-2 item edited through the report writer, plus the LOCALE+SIGN positive.
