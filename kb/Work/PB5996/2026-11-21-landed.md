# PB5996 landed (wave 20262131 group g, train B)

**Re-probe (Debug build of be6c60fd80, before the fix).** `extlen.cob` (EXT-R at X(10) in EXTA, X(100) in EXTB, one source file)
compiled and ran at 85, 2002, 2014 and 2023, printing `B SEES [          ]` / `A SEES [BBBBBBBBBB]`: the one shared cell kept
the first description's 10 characters. A sibling at 2002 and 2014, the records of one EXTERNAL file described at 10 and 100
bytes by two programs of one group (`extfd.cob`), compiled too; at 85 it was already refused by the file description's rule
(`§1985:VII.3.8.4 GR2`, COBOL6847).

**Root cause.** The group-level external rules compared the file connectors' entries (`ExternalFileConnectorRules`) and the
external record NAMES (`ExternalRecordNameRules`, PB5427), and nothing compared the descriptions of one external record. The
run time's registration (`ExternalTable.Describe`, EC-EXTERNAL-FORMAT-CONFLICT) does, but only at 2023 and only when the
condition is enabled.

**Fix.** `ExternalRecordDescription` is now the ONE description of an external record (size, the record name's VALUE key,
the external strong type, CONSTANT RECORD; `ValueSpecificationKey` moved there from `OoEmitter`), read by the run-time
registration and by the new group rule `ExternalRecordDescriptionRules.Check` (COBOL7735), which runs beside
`ExternalRecordNameRules.Check` over the same describers. By edition: 85 compares the size (`§1985:X.4.5.4 GR2`; the record
writes no VALUE, `§1985:X.4.5.3 SR3`); 2002 and 2014 compare the size and the VALUE clause (`§2002:13.16.20.3 GR4`,
`§2014:13.18.22.3 GR4`), and from 2002 the records of an EXTERNAL file description are one external record named by the file
(`§2002:13.16.20.3 GR2b`, GR3); 2023 is unchanged, because the text specifies the run-time outcome (`§2023:14.8.4.3`) and the
suite's `ec_external_format_conflict` reaches it in one compilation group. A complete REDEFINES contributes nothing at any
edition, as each text says.

**Siblings.** EXTERNAL files: the entry agreement (COBOL6847) already ran at every edition; the FD record area at 2002 and
2014 was the gap and is closed here. GLOBAL: one description per item (a contained program references the container's), so
nothing to compare. Separate compilations: at 85 nothing compares them (the documented limit, D-85-EXTERNAL-FD-AGREEMENT,
now also naming the in-group record check); at 2023 the run time does.

**Goldens.** `pb5996-external-record-size-disagrees` (refused at 85, 2002, 2014), `pb5996-g2-external-record-value-disagrees`
and `pb5996-g2-external-file-records-disagree` (refused at 2002, 2014); the legal side is `1985-GR-X_4_5_4-2` (two layouts of
one size, a complete REDEFINES), unchanged.
