# PB2600 — no branch is ever left undecided

**Owner, 2026-10-08 00:00 PDT, verbatim:** "We should never have unused branches left around. We use a branch to test
a change. If the change is accepted, we eventually merge the branch to main and delete the branch. If the change is not
accepted, we either fix it, then merge, or decide it's not the right solution and typically delete the branch if we
decide to abandon that approach."

**Model:** Opus (process tooling with a self-test). One group with PB2601 and PB2602 (wave 1038 group V): all three are
the branch and landing lifecycle.

## Defect

At 00:00 PDT E:\COBOL had 29 local branches. `python scripts/prune_worktrees.py` classifies each by content against
origin/main (MERGED: an ancestor; LANDED: every added file and declared C# name is on main; CHECK: some declared names
are not; UNLANDED: an added file is absent) and `--apply` removes MERGED and LANDED after a 180-minute recency window.
Nothing forced the other rows to a decision, and nothing reported them anywhere a session reads:

- `battery88` and `worktree-agent-a42657b7f46d31559`: dirty worktrees since 2026-10-04;
- `worktree-wf_048cd110-3c5-1` and `worktree-wf_79ef30e1-cd1-7` (CHECK), `worktree-wf_4f556902-4c1-1` (UNLANDED: a PB2087
  negative golden), all since 2026-10-05;
- `worktree-wf_71adb89f-039-1` (CHECK) and `-039-2` (UNLANDED: an arch-oracle manifest);
- the backup ref `r2-fleet-wip-f7794108`;
- the loop's resume units carried "CHECK branches cd1-7, 3c5-1 and 4c1-1 await the attended session" forward from
  handoff to handoff, each unit re-reading and re-deferring them.

The content classes answer "is this branch's work on main?", not "who acts on it next?". A branch nobody owns is the
state the owner's rule forbids, and it was invisible: `session-probe.ps1` printed no branch line at all.

## Fix shape (DONE = the dispatch spec's four items)

1. A mechanical BRANCH LIFECYCLE report: every local branch is IN FLIGHT (a live dispatch: a worktree lock whose
   agent process is alive, a dispatch-ledger entry `inflight-groups.json` naming its wave slug, or a STATUS.md / HEAD
   younger than N hours), WAITING TO LAND (its newest report says DONE), or needs a DECISION (everything else),
   printed by `session-probe.ps1` and usable by the operator tick.
2. The owner's rule in MANDATORY-PRACTICES with its date and quote: a branch ends LANDED then deleted, or ABANDONED by
   a decision recorded in its kb/Work note then deleted. **No bundle.** The dispatch spec said "bundle archived first";
   the owner struck that, 2026-10-08 00:52 PDT: "Archiving to a bundle serves no use and wastes disk space" (the
   operator deleted the 21 existing bundles, 2.2 GB, from E:\Temp). The never-lose-work protection is the
   CLASSIFICATION alone: a branch is deleted only when LANDED/MERGED, or ABANDONED by a decision recorded in its
   kb/Work note first. `prune_worktrees.py --apply` therefore archives nothing (its `--bundle` option and the
   `git bundle create/verify` step are gone, with no flag left behind), and `--include-check` (which deleted
   unlanded CHECK branches on a flag, with only the bundle as protection) is gone too: a branch that is not landed is
   deleted only through `--apply --abandon <branch>`, which refuses unless a kb/Work note already records it ABANDONED.
3. A self-test.
4. Run it and recommend, per DECISION branch, with evidence (read-only; nothing deleted).

Code sites: `scripts/prune_worktrees.py` (`classify` :49, `worktrees` :66, `main` :84), `scripts/session-probe.ps1`
(no branch section), `.claude/skills/workstream/templates/MANDATORY-PRACTICES.md` O10.

## Landed (w1038v, branch `w1038v-branch-lifecycle`)

- `scripts/prune_worktrees.py` is the ONE branch survey. Every local branch and detached worktree gets a LIFECYCLE
  state from a pure rule (`lifecycle`) over what `survey` measures: IN FLIGHT (a worktree lock whose `(pid N)` is a live
  claude process — `coord.process_name`, a reused pid of another image does not count; a lock with no pid; a
  dispatch-ledger wave group still in flight whose `w<wave><letter>` slug starts the branch name, read through
  `plan_wave.inflight_file_sets`; or touched within `--min-age`), WAITING TO LAND (newest `REPORT_NAME` report says DONE,
  written after the branch's last activity, under `--stale-hours`, lead note still open), LANDED (content MERGED/LANDED,
  idle, clean) or DECISION (everything else, with its evidence: SPLIT report, DONE-but-superseded (lead note landed),
  DONE-but-stale, UNLANDED/CHECK with no report, dirty worktree, detached pin). A report binds the branch its header's
  `branch` field names (a header that also names a base or predecessor branch is not about that one). `--brief` (the
  verdict line plus the WAITING and DECISION rows), `--json` (for the operator tick), 16 parallel workers (35 s → about
  20 s on 43 rows).
- `--apply` removes exactly the LANDED rows; `--apply --abandon <branch>` removes a clean idle DECISION row only when a
  kb/Work note has a line naming it with the word ABANDONED. Nothing is archived; `--bundle`, the bundle create/verify
  step and `--include-check` are gone (owner 00:52, above).
- `session-probe.ps1` prints `prune_worktrees.py --brief` every session (`branch :` lines); `session_start.py`'s probe
  timeout rose 90 → 240 s for it (the hook allows 300).
- MANDATORY-PRACTICES O10 restated as the owner's rule with its quote and date, the no-bundle correction, and "every
  session decides its DECISION rows"; `units/resume.md` decides them instead of carrying them forward; SKILL.md §3 and
  `references/landing.md` say the same (and the landing reference no longer tells the orchestrator to `git branch -D`
  by hand).
- Self-test `prune_worktrees.py --self-test`: a scratch repository with 14 rows covering every state and every DECISION
  reason, then `--apply` with four `--abandon` requests (one recorded, three refused); mutation-checked (three
  mutations each turn it RED). It runs in the gate's AUDITS, CI's audits job and the Linux gate's hooks leg.
