## Finding — `identifier` (rejects-legal-source; rows `SR-8.4.3.1.3-6`, `FMT-8.4.3.1.2`, `GR-8.4.3.1.4-1`)

**Mechanism.** Identifier Format 5 (object-view, 8.4.3.5) has no grammar or binder surface; `identifier AS {class|interface|UNIVERSAL}` is refused with a misleading reserved-word diagnostic

**Repro.** A class KDER INHERITS FROM KBASE; in a program: 01 D USAGE OBJECT REFERENCE KDER. 01 U USAGE OBJECT REFERENCE. ... INVOKE KDER "NEW" RETURNING D. SET U TO D AS UNIVERSAL.  (or INVOKE D AS KBASE "SPEAK"). cobol --std 2023 (also 2002/2014).

**Expected from the spec.** 8.4.3.1.2 Format 5 + 8.4.3.5.2: `D AS UNIVERSAL` is an identifier treated as USAGE OBJECT REFERENCE with no class (8.4.3.5.4 GR7), so the SET compiles and U references D's object; `D AS KBASE` is treated as OBJECT REFERENCE KBASE with a runtime conformance check that sets EC-OO-CONFORMANCE on failure (GR2). The source is legal and must compile.

**Observed / reasoning.** error COBOLNET0901: 'AS' is a reserved word in COBOL-2023 and cannot be used as a user-defined word (ISO §8.9) (plus COBOL0301 for the INVOKE form). No objectView rule exists in src/Cobol.Net.Frontend/Grammar and EC-OO-CONFORMANCE has no raise site; object-view is not an A.4.10 optional item, so this is mandatory 2002+ OO core. The ordering component 8.4.3.1.4 GR1 c) therefore does not exist either. Previously recorded only in docs/rearchitecture/PHASE-13-plan-vs-spec-review.md R19; no kb/Work note owns it.

**Code site.** src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4#objectReference (no AS-view tier); src/Cobol.Net.Frontend/Grammar/Core/CobolOO.g4

## Finding — `identifier` (rejects-legal-source; rows `SR-8.4.3.1.3-7`, `FMT-8.4.3.1.2`)

**Mechanism.** Predefined-object Format 6's qualified SUPER arm `object-class-name-1 OF SUPER` has no grammar alternative; objectReference admits only bare SUPER

**Repro.** CLASS-ID. KDER INHERITS FROM KBASE. (REPOSITORY CLASS KBASE.) OBJECT. PROCEDURE DIVISION. METHOD-ID. TALK. PROCEDURE DIVISION. INVOKE KBASE OF SUPER "SPEAK". END METHOD TALK. -- with KBASE defining method SPEAK. cobol --std 2002 (2014, 2023 identical).

**Expected from the spec.** 8.4.3.8.2 prints `[ object-class-name-1 OF ] SUPER`; 8.4.3.8.3 SR6: with one INHERITS class 'object-class-name-1 may be specified', SR4 requires it to be that class. The INVOKE compiles and GR4 restricts method search to KBASE: the program displays KBASE's SPEAK output.

**Observed / reasoning.** error COBOLNET0901: 'SUPER' is a reserved word in COBOL-2002 and cannot be used as a user-defined word (ISO §8.9) - the parser reads `KBASE OF SUPER` as a data-name qualified by a user word. objectReference is `dataReference | NULL_ | SELF | SUPER` with no qualified arm. The mandatory-qualifier case (SR5) needs multiple class inheritance, which A.4.10 item 1 declines, but the single-parent optional form is core. No kb/Work note owns it (DESIGN-SPEC-RECONCILIATION.md row 43 mentions it as deferred prose only).

**Code site.** src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4#objectReference

## Finding — `inline-method-invocation` (rejects-legal-source; rows `GR-8.4.3.4.4-1`)

**Mechanism.** Object-reference-only operand positions (SET Format 5 identifier-4, INVOKE identifier-1) do not admit a Format-4 identifier, so an inline invocation whose GR1 b) temp is an object reference is refused; the functionCall-pairing drift test cannot see these positions because no function returns an object reference

**Repro.** class PRBC method ME: 01 LK-ME USAGE OBJECT REFERENCE PRBC. PROCEDURE DIVISION RETURNING LK-ME. SET LK-ME TO SELF. Program: (a) SET U1 TO A1 :: "ME". -> probe p14_setinline; (b) INVOKE A1 :: "ME" "GETNAME" RETURNING W. -> probe p16_invokerecv

**Expected from the spec.** §8.4.3.4.4 GR1: the inline invocation references a temporary data item with the description of the method's RETURNING item (an object reference described with PRBC); §8.4.3.1.3 SR5 makes it an identifier. §14.9.39.3 SR9 'Identifier-4 shall be an object reference' and §14.9.23.3 SR1 'Identifier-1 shall be an object reference' are satisfied: (a) compiles and U1 references A1's object; (b) compiles and W = 'ACCOUNT '.

**Observed / reasoning.** (a) COBOLNET0867 'identifier-4 shall be an object reference ... never a literal or an arithmetic expression'; (b) COBOL0001 unexpected '::' (INVOKE's objectReference rule is dataReference|NULL|SELF|SUPER). Sweep every object-reference operand position (SET Format 5/7 sending, INVOKE receiver, object-view, relation already works).

**Code site.** SET object-reference binder emitting COBOLNET0867 (SetBinder); src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4#objectReference; tests/Cobol.Net.Tests.Unit/InlineMethodInvocationOperandDriftTests.cs

## Measured (rows this note claims beyond the findings above)

### `SR-8.4.3.1.3-8` — PARTIAL (adjudicator + refuter record, verbatim)

SR8 (cite.py --check 8.4.3.1.3 8) OK): Format 7 is the 8.4.3.9 object property `property-name-1 OF identifier-1`. It parses as a qualified dataReference and ReferenceResolver's object-property binder re-reads it when the qualifier is an object reference (REPOSITORY PROPERTY gate SR1, universal-reference refusal SR2); OoBinder desugars GET/SET per GR1-GR3. Probe o2.cob: `MOVE NM OF D TO W` -> ABCDEF; `NM OF D (2:3)` -> BCD. pb987 golden cites 8.4.3.9. Probes under out/probe/ident with the pinned cobol.exe. || REFUTED: PARTIAL — Format 7 is `property-name-1 OF identifier-3`, and SR1 lets identifier-3 be any identifier. OoTryBindPropertyReference binds only a single bare-word qualifier (a class-name or a typed object reference). A qualified, subscripted object reference is refused as 'not defined'. The bare form works (the adjudicator's probe and my control).

### `SR-8.4.3.1.3-1` — DIVERGES (adjudicator + refuter record, verbatim)

SR1 (cite.py --check 8.4.3.1.3 1) OK): any identifier slot of an identifier format admits any identifier format. Probes p1.cob: function-identifier inside a function argument that is itself ref-modified `FUNCTION UPPER-CASE (FUNCTION LOWER-CASE (A OF G (N))(1:3))` -> G2G; function-identifier in a ref-mod leftmost position `W (FUNCTION LENGTH (W) - 1 : 2)` -> ef; function-identifier as a subscript `A OF G (FUNCTION INTEGER (N))(1:1)` -> G; ref-mod identifier as a function argument -> C. Inline invocation chained on its own temporary is pinned by the spec-derived golden pb428 item 6, which cites this rule. Recursion through Format 5 is impossible only because Format 5 does not exist - that defect belongs to SR-8.4.3.1.3-6, not to this rule. Probes under out/probe/ident with the pinned cobol.exe. || REFUTED: DIVERGES — SR1 makes every identifier slot inside another identifier format accept ANY identifier format. The adjudicator probed only function, subscript and ref-mod nesting. Two other nestings reject legal source: an object property whose identifier-3 is a qualified, subscripted object reference (Format 7 over Format 2), and a data-address-identifier whose identifier-1 is reference-modified (Format 9 over Format 3). Format 5 is also absent, which is SR6's defect.

## What the fixer owes

Make objectReference = the identifier formats that YIELD an object reference (data reference, inline invocation, object view, predefined object incl. `class OF SUPER`, object property), one rule used by every object-reference position (INVOKE, SET, RAISE — PB1197, PB1136), with the object-view binder per §8.4.3.5; OoTryBindPropertyReference resolves a general identifier-3.
