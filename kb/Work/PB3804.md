# PB3804 — module prose that names what the code no longer (or never) has

**Sites:** `scripts/orchestrator/reports.py` (`<module>`) (module docstring), `scripts/orchestrator/groups.py` (`<module>`) (module docstring), `scripts/orchestrator/turns_by_group_size.py#STATUS`, `scripts/hooks/fleet_active_build.py#same_path`, `scripts/orchestrator/land_lane.py` (`<module>`) (module exit table), `scripts/orchestrator/units/enqueue.md` (step 3), `scripts/merge_drivers.py` (`<module>`) (module doc, CLI line near :1060), `scripts/orchestrator/enqueue.py` (`<module>`), `scripts/orchestrator/enqueue.py#SLOT_DRIVER` (the comment above it)

## Measured

Five claims, each verified by the reviewer against the code (CLAUDE.md rule 6, docs describe the current compiler):

1. `reports.py` says every report reader reads it, naming `turns_by_group_size.py`, which imports only `coord` and keeps its own
   status regex (turns_by_group_size.py:41, no NOT STARTED). A NOT STARTED report reads status `?` there while
   `reports.parse_report` reads NOT STARTED; the next status-word change edits `STATUS_WORD` only and the measurement
   silently diverges. Fix: re-point it at `reports.parse_report` (the one reader) or drop it from the list.
2. `groups.py:8` names `check_practices.py` as a reader of `group_requirements`/`campaign_requirements`; it imports only
   `inflight` and reads the rendered groups file.
3. `fleet_active_build.same_path` (:206) still says its two sides come one from the payload cwd and one from a `.git` file
   `gitdir:` line; PB3770 deleted the only `gitdir:` parse. The sides are now a build site (payload cwd, a cd target or a
   named project) against an agent launch cwd read from its transcript (E:/COBOL in one, e:/COBOL in the other).
4. `land_lane.py`'s module table (exit 2 list at :92, exit 5 GATE RED at :96) and `units/enqueue.md:40/46` (exit 5 list,
   the repeated-exit-2 examples) name neither `MERGE NOT COMPLETED` (exit 2, merge-blocked) nor `MERGE NOT COMPLETED,
   BRANCH-CARRIED` (exit 5, merge-failed). DESIGN-orchestrator-loop.md's table and the finisher brief were updated.
5. `merge_drivers.py:70` names the third end of `Merged` as `unsettled`; the field is `incomplete`. The CLI line (:1060)
   and `enqueue.py incomplete()`'s ENVIRONMENT verdict say the merge was clean also for git's own refusals (`_refused`:
   the fast-forward refused, git merge refused to start), where no merge was attempted: `merge_drivers.py merge origin/main`
   with an index.lock present prints "the merge was clean but git merge origin/main failed".

## Acceptance

  the report.
