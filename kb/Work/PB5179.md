# PB5179 - at --std 85 an EVALUATE selection object written as a partial expression (WHEN > 5) compiles: the partial-expression alternative PB398 added has no edition gate

**Sites:**

- `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolControlFlow.g4` (`evaluateWhenItem`)
- `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolExpressions.g4` (`partialExpression`)
- `src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs` (`VisitEvaluateWhenItem`)

**Mechanism.** The 1985 selection object (§1985:VI.6.13.2) is ANY, a condition, TRUE, FALSE or [NOT] an identifier, literal or arithmetic expression with an optional THROUGH operand, and nothing else. kb/Work PB398 (landed) added the partial-expression alternative of the later editions and named its edition gate as owed. `VersionConformancePass.VisitEvaluateWhenItem` gates the boolean forms and not the partial expression, so WHEN > 5 compiles and runs at --std 85.

Verdict, harm, evidence, repro and observed text are the records'; the rows' verdicts are recorded on another branch.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids of the list below.

Code read: No open kb/Work note owns the fix. §1985:VI.6.13.2 prints EVALUATE, one or more selection subjects joined by ALSO (identifier, literal, expression, TRUE, FALSE), one or more groups of WHEN phrases each ending in imperative-statement-1, an optional "[WHEN OTHER imperative-statement-2]" and an optional END-EVALUATE; a selection object is ANY, a condition, TRUE, FALSE, or [NOT] before an identifier, literal or arithmetic expression with an optional THROUGH or THRU second operand, and nothing else. Implemented at 85: evaluateStatement, evaluateWhenClause, evaluateWhenPhrase and evaluateWhenOther hold the shape at every edition (an EVALUATE with only WHEN OTHER, WHEN OTHER twice or not last, a WHEN group with no statement, a missing subject, two objects without ALSO and a doubled THRU are refused; NOT before ANY, TRUE or FALSE is refused by EvaluateBinder.ScreenObjectNegation, COBOL3710), and the later editions' additions that are gated reach 1985: boolean-expression subjects and objects (VisitEvaluateSubject and VisitEvaluateWhenItem, COBOL0900 below 2002) and the range's IN alphabet-name phrase (RangeAlphabet through TryResolveRangeAlphabet, COBOL0900 below 2002). Probed at --std 85: condition, arithmetic-expression, literal and TRUE/FALSE subjects, NOT with and without a THROUGH range of expressions, ANY, a nested EVALUATE and the period-terminated form compile and run. PARTIAL for one arm: evaluateWhenItem's partialExpression alternative has no edition gate, so a partial expression as a selection object (WHEN > 3, WHEN NOT < 3, WHEN NUMERIC, and a bare class-name) compiles and runs at 85. The 1985 object list has no such alternative, and §2002:F.2 item 48 records it as the 2002 change ("A partial expression may now be used as a selection object in an EVALUATE statement."); the row's change record names it among what 1985 refused. kb/Work PB398 (landed) added the alternative and wrote that it and the IN phrase were 2002 additions needing the edition-gate sweep; only the IN phrase got its gate. The witness runs five EVALUATE statements over the 1985 object forms.

**Repro (`1985-FMT-VI.6.13.2`).** `cobol.exe ev1.cob --std 85 --source-format fixed --run`

```cobol

       PROGRAM-ID. EV1.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  A PIC 9 VALUE 5.
       PROCEDURE DIVISION.

               WHEN > 3 DISPLAY "GT"
               WHEN OTHER DISPLAY "OTHER"
           END-EVALUATE.
           EVALUATE A
               WHEN NUMERIC DISPLAY "NUM"

           END-EVALUATE.
           STOP RUN.
```

**Expected (from the 1985 text, the record's).** --std 85 refuses lines 9 and 13: the selection objects of §1985:VI.6.13.2 are ANY, condition-1, TRUE, FALSE and [NOT] identifier-3, literal-3 or arithmetic-expression-1 with an optional THROUGH operand; "> 3" and "NUMERIC" are none of them, and as conditions they would break §1985:VI.6.13.3 SR6 b ("Condition-1, condition-2, or the words TRUE or FALSE appearing as a selection object must correspond to a conditional expression or the words TRUE or FALSE in the set of selection subjects."). The form is the 2002 addition §2002:F.2 item 48: "EVALUATE statement, partial expressions. A partial expression may now be used as a selection object in an EVALUATE statement."

**Observed (the record's).** exit 0, no diagnostic; the program displays GT then NUM. Controls at --std 85: WHEN "A" THRU "Z" IN ALPH draws COBOL0900 (requires COBOL-2002), EVALUATE A B-AND B draws COBOL0900, WHEN NOT ANY draws COBOL3710.

**Fix direction (root cause, CLAUDE.md rule 4).** Gate the partialExpression alternative below the edition that introduced it in VisitEvaluateWhenItem, as a registry construct.
