# PB5385 - USE FOR DEBUGGING reports the wrong occurrence for a receiver whose statement evaluates its subscript late: DebugTriggerEmitter.IdentifiedOnce freezes every data fire's place at the start of the statement, so MOVE 3 TO SUB TE (SUB) stores TE (3) but DEBUG-SUB-1 is +0001 and DEBUG-CONTENTS is TE (1)

**Sites:**

- `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/DebugTriggerEmitter.cs#IdentifiedOnce` (freezes each fire's place at statement start)
- `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/DebugTriggerEmitter.cs#OccurrenceNumbers` and `#FireText`; `src/WiseOwl.Cobol.Runtime/Control/DebugItem.cs#PopulateReference`

**Mechanism.** kb/Work PB5294 (landed) made each data fire identify its place once, at the start of the statement, which is the general rule for an identifier. MOVE, the arithmetic statements with several results and DIVIDE REMAINDER say otherwise for their receivers: each is evaluated just before it is stored. The statement's own store honours that; the debug register is filled from the frozen place, so it describes a different occurrence from the one stored.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids below. Its rows are recorded PARTIAL naming this note.

**Rules (2 claimed; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-GR-XV.3.2.4-14` - `§1985:XV.3.2.4 GR14` (read: PARTIAL, harm: wrong answer): for a subscripted reference that causes the section, "the occurrence number of each level is entered in" DEBUG-SUB-1 through DEBUG-SUB-3.
- `1985-GR-XV.3.2.4-24` - `§1985:XV.3.2.4 GR24c` (read: PARTIAL, harm: wrong answer): DEBUG-CONTENTS is the content of the item "at the time that control passes to the debugging section".
- The statement rules: `§1985:VI.6.19.4 GR2`, "Any length evaluation or subscripting associated with identifier-2 is evaluated immediately before the data is moved to the respective data item"; `§1985:VI.6.4.6 GR2`, "These statements are considered to be written in the same left-to-right sequence that the multiple results are specified".

**Repro.** `E:/COBOL-coord/scratch/coderead-85/out-reread2/work-rr-09/dbg/min14.cob`: `SOURCE-COMPUTER. X WITH DEBUGGING MODE.`, `01 T. 05 TE PIC X OCCURS 3 TIMES VALUE "."`, `01 SUB PIC 9 VALUE 1`, a debugging declarative `USE FOR DEBUGGING ON TE` that displays `DEBUG-SUB-1` and `DEBUG-CONTENTS (1:1)`, then `MOVE 3 TO SUB TE (SUB)`. Siblings in `g14.cob`: `DIVIDE 7 BY 2 GIVING SUB REMAINDER NT (SUB)` and `ADD 1 TO SUB NT (SUB)`. `cobol.exe --std 85 --source-format fixed --run <file>`.

**Observed (the pinned compiler of `E:/COBOL-wt/coderead85-tree-b` (origin/main 8147f008b3; `git diff --stat 8147f008b3 origin/main -- src` is empty at 5237495315), rerun 2026-11-12; `E:/COBOL-coord/scratch/coderead-85/reprobe-85f/log.txt`).** min14 prints `D1 +0001 .` then `T=..3`. g14 prints `NT SUB1=[+0001] C=[0 ]` after each of the DIVIDE and the ADD, whose stores land in NT (3) and NT (2).

**Expected (from the 1985 text).** `D1 +0003 3`: the MOVE's receiver is TE (3). The DIVIDE reports +0003 and the ADD +0002, each with that element's content.

**Fix direction (root cause, CLAUDE.md rule 4).** Identify a receiver's place for the debug fire at the point its statement identifies it for the store (one identification shared by the store and the fire), keeping the statement-start freeze for every operand whose statement has no later rule.
