# PB4062 — `_RETRY_NOTICE` says one warning, matches all of them

**Sites:** `scripts/abi_pin.py#_RETRY_NOTICE`, `scripts/abi_pin.py#host_caused`

(The code lives on PR #774's branch `worktree-wf_484eb705-564-3`, PB3809's fix, and reaches main when that lands. It is not on main at filing.)

`_RETRY_NOTICE = re.compile(r"\bwarning\s+[A-Za-z]+\d+\s*:", re.IGNORECASE)` and its comment describe MSBuild's MSB3026
copy-retry notice only, but the pattern matches EVERY `warning CODE:` line (CS8618, MSB3061, NU1603, ...). `host_caused`
then skips the `_HOST_PHRASE` test (held-file, disk-full, FileNotFoundError) on all of them. That is probably the intended
rule (a warning line reports no failure, so a phrase on it proves no host cause), but the name and comment state a narrower
one, so a reader cannot tell whether an unrelated warning that carries a host phrase is meant to be ignored. Harm: none
observed; the classification of a real failure line is unchanged.

**Fix.** Pick one reading and state it in the code: either the rule is "a warning line reports no failure" (rename to a
warning-line name, rewrite the comment, keep the pattern) or it is MSB3026 only (anchor the pattern on `MSB3026`). Test arm
for the chosen reading: a `warning CS8618` line that carries "is locked by" is ignored (or counted), seen RED first against
the other reading. PB3809 owns the mechanism and is landing on the branch above, so this is filed as a follow-on and not as
an edit to PB3809 (which that landing flips to `landed`).
