# PB4236 — A SELECT entry with no ASSIGN clause compiles and runs at every edition, bound to an invented `<file-name>.txt`; §12.4.5.1 prints ASSIGN unbracketed in all four formats, and the binder screens the other unbracketed clause (RECORD KEY) but not this one

Found by the Mythos front-end review 2026-10-31 (GRAMMAR-REVIEW.md, N7; artifact https://claude.ai/artifact/VpxTVcaFUsArrq59EvUe5r). Pin 84cdb410f.

**Sites** (file:line at pin 84cdb410f): `DataBinder.cs:1302 (AssignTarget = name), :1317`; `FileModel.cs:200`; `FileControlKeyRules.cs:248-275 (COBOL0863)`; `CobolIO.g4:35-39 (the correct any-order superset)`.

**Carried shard findings:** S5-1.

**Evidence paths:** `E:/COBOL-coord/scratch/w-gr1/GRAMMAR-REVIEW.md`, `E:/COBOL-coord/scratch/w-gr1/review-S5.md`, `E:/COBOL-coord/scratch/w-gr1/S5-refute/`.

**Inventory row FMT-12.4.5.1** claims CONFORMS today; this note claims it while open.

**Evidence.** Spec pp.342-344 rendered; §5.2.6.2; GnuCOBOL 3.2 refuses a SELECT without ASSIGN at every `-std`. No corpus file is affected (3,750 SELECTs all write ASSIGN).

**Fix direction.** A (format, required clause) table in the binder, with a drift test that scrapes the transcription so the table cannot rot.

**Landed (wave 20261788 group A).** Re-probed on the build: `SELECT F.` with an FD compiled and ran at `--std 85` and `2023` with no
diagnostic (and an SD, a relative and an indexed entry the same). §12.4.5.1 rendered from PDF p342-344: ASSIGN opens its line with
no bracket in all four formats, and the prime RECORD KEY does in Format 1 (RECORD DELIMITER, RELATIVE KEY, FILE STATUS and the
rest open inside brackets). The fix is `FileControlKeyRules.RequiredClauses`, a table of `RequiredClause(Face, Printed, Applies,
Written)`, screened by `Screen` before the key rules and reported under the new COBOL5701; the RECORD KEY requirement, which was
the one such clause kept as a row of the key-operand table, moved into it (it left COBOL0863, whose subject is a key clause that
was written). `FileModel.AssignWritten` and `FileModel.HasSelect` are the facts, and `AssignTarget` is no longer defaulted to the
file-name, the invention that bound the file to `<file-name>.txt`. `FileControlKeyRuleDriftTests.EveryFormat_PrintsExactlyTheRequired
ClausesOfTheTableUnbracketed` re-reads the four diagrams: every line that opens unbracketed is exactly one row, so the next one a
later edition prints fails there until it is a row. Goldens: `pb4236_assign_clause_forms` (accept 85) and
`pb4236-select-without-assign` (refused at all four editions); `FileControlKeyRuleSpecTests.ASelectEntryWithoutAnAssignClause_
IsRefusedInEveryFormatAtEveryEdition` covers every kind of file at every edition.
