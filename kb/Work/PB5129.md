# PB5129 - at --std 85 CALL ... USING BY CONTENT FUNCTION UPPER-CASE (WS-A) is accepted and the function value is passed; 1985 forbids a function-identifier as a CALL USING operand

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CallBinder.cs#FunctionIdentifierArgumentOf` (landed: asked from `BindCall`'s up-front COBOL-85 judgement beside `Format2OnlySpellingOf`), `tests/version-matrix/constructs/call-function-identifier-argument-2002.json` (landed); `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CallBinder.cs#BindCall` (its USING binder: the `callByContent` arm, about line 366, and the local function `AddBareTemporaryArg`, about line 745 of the pinned tree): a function-identifier is refused only when the prevailing mode is not BY CONTENT, with no edition test for the 1985 rule

**Mechanism.** The 1985 CALL rule (Amendment 1) says identifier-2 must not be a function-identifier, and identifier-2 is the operand of both USING phrases. The compiler refuses a function-identifier operand only when the prevailing mode is not BY CONTENT (COBOL1677, whose message cites §2023:14.9.4.3 SR3: the temporary "can cross only BY CONTENT"), so the 1985 rule is enforced for BY REFERENCE only, through the 2023 rule. The mechanism differs from kb/Work PB5108 (numeric and integer functions outside an arithmetic expression, the intrinsic-function module rule, which this CALL operand is not), and the code site is the CALL binder; kb/Work PB4901 and PB4938 hold the 1985 citation of the CALL storage-section rule (SR3).

**Found by.** The 1985 witness-drafting pass (kb/Work PB4995 item 3): each rule below is a witness program drafted from the 1985 text alone, run at `--std 85`, and its result differs from what the text requires (outcome MISMATCH). Harm and observed text are the record's; nothing here was re-derived.
