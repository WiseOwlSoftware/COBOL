# PB4971 - the map pass's candidate retrieval misses counterparts

**Sites:** `scripts/spec/audit_batch.py#plan_map` (the candidate selection)

Map pass, k = 15 candidates: SAME 1,251, DIFFERS 538, NONE 464. A NONE whose reason names a deleted or replaced feature
(the communication module, the Debug module, ALTER, DATA RECORDS) is right. 217 NONE reasons name no such feature, and
they say the counterpart is missing from the candidates. Examples: `1985-GR-IX.2.3.4-7` ("no candidate addresses the
FILE STATUS clause"), `1985-GR-VI.6.17.4-3` ("would be in 2023 GR 5, which is not among the candidates"). Each of these
becomes an OWN-ROW, which a fleet adjudicator must decide from scratch, when it could carry a 2023 verdict.

Expected: before fleet adjudication, run these rules through a cheap batch re-map with retrieval of another kind (by
clause heading and subject, or with the 2023 clause the reason names). Make that retrieval part of `plan_map`, not a
second tool, so the next edition's audit (2002, PB4813) gets it automatically.
