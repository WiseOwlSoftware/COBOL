# PB2117 — the performance baseline (DESIGN-architecture-review §3 R0, §4 item 5; kb/Work A6)

One mechanism, one place: A6 (the P14 Step-12 perf gate) has wanted an in-repo, CI-trended benchmark suite since
2026-07-19, and the review's R0 needs the same numbers. This note builds it ONCE; A6 records that PB2117 is its
instrument. **Model:** Opus, following `brent-tools:performance-diagnosis` (measure first; a scaling curve and
stack sampling before any opinion). **Prerequisite:** none.

## Output

1. `tests/Cobol.Net.Benchmarks` (exists) gains the suite: compile throughput over the largest corpus programs and a
   copybook-heavy program; generated-program benchmarks for MOVE-heavy loops, PERFORM dispatch, sequential and
   indexed file I/O, with BenchmarkDotNet witnesses (`brent-tools:dotnet-engineering`).
2. The whole-population gate time in both modes, from `build-local.ps1`'s own verdict lines, recorded with the
   machine and conditions.
3. The external comparison: the same programs through GnuCOBOL 3.2 under WSL (`reference_cobc_in_wsl`), so the
   storage-model question A6 raised ("a Tier-B surprise") is answered against an independent implementation. The
   legacy byte engine is not a baseline (R69 §1).
4. The record under `docs/rearchitecture/evidence/perf-baseline/<sha>.md`, cited by every R3 and R4 wave's §4 item 5
   comparison. A regression beyond noise is a finding, never a footnote.

## Rules

No wall-clock assertion in any test (owner 2026-09-25); the baseline is a RECORD compared by a script with a stated
noise band.

## Landing (2026-10-07, wave 1026 group E)

For the next implementer:
- `scripts/arch/perf_baseline.py#main` owns the record and the comparison; `#gate_rows` reads `verdict.json`;
  `#wsl_leg` runs inside WSL (a login shell, so `dotnet` is on PATH). Re-render from the raw JSON it saves in
  `TestResults/perf-baseline/<stamp>.json` with `#render`, never by re-measuring. Trap: a stale data file from the other
  implementation makes GnuCOBOL's indexed OPEN OUTPUT spin; every timed run starts with only the inputs.
- `tests/Cobol.Net.Benchmarks/GeneratedCode/GeneratedProgramBenchmarks.cs#Setup`: call `StandardStreams.EnsureUtf8()`
  before redirecting `Console.Out` (the runtime's first activation replaces it). Adding a program = a `.cob` with one
  `01 LOOP-COUNT PIC 9(9) COMP VALUE n.` line, a `witnesses.tsv` line computed from its formula, and a `[Params]`
  entry; `--self-test`'s "programs agree" case fails when the three disagree.
- `tests/Directory.Build.props`: BenchmarkDotNet builds through a project it generates under `bin/`, which inherits
  this file; anything linked there must compile without xunit, or the project is excluded by name as now.
- BenchmarkDotNet's `--job X` ADDS a job beside the configured one; it does not replace it.

- **The suite** (`tests/Cobol.Net.Benchmarks`): `Compile/CompileBenchmarks` (IX113A, NC105A, NC218A, and SM201A, the
  program with the most COPY statements; `FrontEndAndBind`, the check-only compile, against `FullCompile`) and
  `GeneratedCode/GeneratedProgramBenchmarks` (`Programs/MOVEHOT`, `PERFHOT`, `SEQHOT`, `IDXHOT`, run in-process
  through the generated entry point). Each GlobalSetup is a witness: the compiles must succeed and SM201A must read
  its library texts, and every program's output must equal its line in `Programs/witnesses.tsv`, computed from the
  formula in the program's header. `Programs/EMPTYRUN.cob` is the start-up floor.
- **The script** `scripts/arch/perf_baseline.py`: BenchmarkDotNet (population asserted against the classes'
  `[Params]`), cold `cobol --nist` processes, whole processes on Windows, and the same programs under WSL against
  GnuCOBOL 3.2 at 1x, 2x and 4x LOOP-COUNT (the witness at every scale: both implementations print the same line),
  plus the gate time from `--gate-run`'s `verdict.json` less its slot wait. `--against <record>` re-measures and
  flags a row beyond `max(5 %, 3·√(noise_b² + noise_c²))` as a REGRESSION (allocations 2 %, gate 25 %); a vanished row
  is red. `--self-test`, run every gate by `PerfBaselineSelfTestDriftTests`, proves each arm can fail.
- **The record**: `docs/rearchitecture/evidence/perf-baseline/354c79ef3312.md`. The headline answers are in A6's
  2026-10-07 paragraph: PERFORM dispatch 0.7x GnuCOBOL, MOVE-heavy 3.0x and sequential I/O 2.8x (the string storage
  model, about 926 bytes allocated per MOVEHOT pass), indexed I/O 60x to 330x and super-linear (the unindexed
  `IndexedConnector`), and a warm full compile of IX113A in about 430 ms.
- **Found on the way and fixed**: `tests/Directory.Build.props` linked the xunit-based `_shared` helpers (kb/Work
  PB1719) into the project BenchmarkDotNet GENERATES under the benchmark's `bin/`, so every benchmark case of every
  class reported NA; that host project is now excluded by name.
- **Noise, as measured**: the whole-process rows' session medians agree within 5 % (13 % for the millisecond start-up
  floors) between the two sessions; the
  BenchmarkDotNet and cold-compile rows moved by up to 60 % because other worktrees' gates were running (the record
  carries the host load per session and names those rows). A re-baseline on a quiet host narrows their bands.
