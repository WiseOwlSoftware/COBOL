# PB3107 — the landing oracle serializes input-changing landings

> ⚙ **flags:** process-only

Source: enqueue unit 2026-10-12 15:17 PDT.

`scripts/orchestrator/landing_oracle.py` RULE 1 (a tree carries exactly ONE recorded baseline) and RULE 3 (no path under its
`inputs` changed after the baseline's commit) mean a branch that changes an oracle input must re-record its baseline AFTER
every earlier input-changing branch has merged on main: two branches that each recorded on the same main merge into a tree
with two manifests (RULE 1) or a baseline behind the other's inputs (RULE 3). Each re-record today costs a `cobol-finisher`
(`compare_oracle.py`, `capture_oracle.py --record`, commit; finisher-brief ORACLE stop), then a branch review round for the
manifest commit (enqueue.py refuses it as UNREVIEWED, exit 11: only main's commits, clean merges and DEVLOG-only commits pass
after a CLEAN stamp), then a new landing with both gates, then the merge group's CI.

**Measured 2026-10-12.** Of wave 1069's Review-CLEAN branches, six change oracle inputs (worktree-wf_d63f7207-db5-4, -11, -17,
-18, -22, -30). Only db5-18 carried its own baseline (69e756b0880b, PR 15). db5-4 and db5-11 stopped on exit 7 after both
gates had run GREEN (wasted gates). db5-4's finisher measured `=== ARCH-ORACLE: IDENTICAL — 7780 cases (baseline 60d47c6d52a9,
new b5237d034c28) ===` (the stop was purely mechanical; `E:\COBOL-coord\scratch\finisher-db5-4-compare.log`), and its fresh
baseline went stale the moment PR 15 entered the queue. The five remaining input-changing branches must land strictly one at a
time, each finisher, review, land, merge group before the next may record: about five serial cycles of roughly 50 minutes.
`enqueue.py land` also runs the oracle check AFTER the gates, so a branch it will refuse spends both gates first
(`landing_oracle.py --rev <branch>` answers in seconds before any gate).

**Code sites.** `scripts/orchestrator/landing_oracle.py` (RULE 1-3, RECORD text); `scripts/orchestrator/enqueue.py` (the
checks step, exit 7; the exit-11 review exemption); `scripts/arch/capture_oracle.py`; `scripts/arch/compare_oracle.py`;
`.claude/skills/workstream/templates/finisher-brief.md` (ORACLE stop).

**Fix shape (for the implementer to confirm).** Check the oracle before the gates. When `compare_oracle.py` on the merged head
is IDENTICAL (or differs only in cases the branch's own DEVLOG entry already explains), `enqueue.py` records the baseline on
the merged head itself as a mechanical commit the review exemption admits, like the DEVLOG stamp; stop for a finisher only on
a NEW difference.
