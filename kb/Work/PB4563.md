# PB4563 — present-when-level-01-group-without-line-c-error: Report writer: PRESENT WHEN on a level-01 report group with no LINE clause generates C that does not compile ('rf_N' undeclared)

Filed 2026-11-03 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-batch-3000-20261103`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

cobc 3.2 generates C code that the C compiler rejects when a PRESENT WHEN clause is written on a level-01 report group entry that has no LINE clause of its own (the LINE is on a subordinate entry): the generated code assigns `rf_N.suppress` for a report field that is never declared. No diagnostic comes from cobc itself. Class: crash (invalid generated code). Fuzz programs: fz01249 (night fuzz-batch-3000-20261103, slice D4).

## Minimal test case

Free reference format.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. RW3.
ENVIRONMENT DIVISION.
INPUT-OUTPUT SECTION.
FILE-CONTROL.
    SELECT RPT-FILE ASSIGN TO "rw3.out".
DATA DIVISION.
FILE SECTION.
FD RPT-FILE REPORT IS RPT.
WORKING-STORAGE SECTION.
01 AMT PIC 9(4) VALUE 0.
REPORT SECTION.
RD RPT.
01 DET TYPE IS DETAIL PRESENT WHEN AMT > 0.
   05 LINE PLUS 1.
      10 COLUMN 1 PIC 9(4) SOURCE AMT.
PROCEDURE DIVISION.
    OPEN OUTPUT RPT-FILE
    INITIATE RPT
    MOVE 0 TO AMT
    GENERATE DET
    MOVE 5 TO AMT
    GENERATE DET
    TERMINATE RPT
    CLOSE RPT-FILE
    DISPLAY "DONE"
    STOP RUN.
```

## Environment

`cobc (GnuCOBOL) 3.2.0`, WSL2 Ubuntu x86_64. Compiled with `cobc -x -free -std=cobol2014 -o p rw3.cob`; when an executable is produced it is run as `./p` under `timeout 10`. Control: the same group with `LINE PLUS 1` moved onto the level-01 entry (and the 05 entry made a FILLER group) compiles and the report file holds `0005`.

## Observed result

```text

  124 |         rf_4.suppress = 0;
```

## Expected result (per ISO)

The program is legal, prints `DONE`, and the report file holds the one line `0005`: the first GENERATE (AMT = 0) produces nothing because the level-01 entry is absent, the second prints the detail.

- §13.15.2 (checked): the report group description entry has `[ PRESENT WHEN condition-1 ]` among its clauses, at any level.
- §13.18.41.4, general rule 2 b) (checked): "if the entry is a level-01 entry, the effect on processing is as though the entire report group description were omitted".

Edition: 2014. PRESENT WHEN is a 2002 report-writer clause; Annex E of 2023 lists no change to it.

## Our compiler

WiseOwl COBOL (fresh judge, `--std 2014 --source-format free`): compiles with no diagnostic; the run prints `DONE`; the report file holds `0005`, exit code 0.

## Fix site

`cobc/codegen.c`, function `output_if`, the branch for `STMT_PRESENT_WHEN` (it emits the comment `/* PRESENT WHEN %s: %d */`): when the field has no `COB_REPORT_LINE` flag it uses the report-field prefix `CB_PREFIX_REPORT_FIELD` (`rf_`) and the field id, but a level-01 group with no LINE and no COLUMN has no report-field definition (`output_report_def_fields`), so `rf_<id>` is undeclared (read in the 3.2 source; reproduced with the 3.2.0 binary).

## Draft issue

**Title:** PRESENT WHEN on a level-01 report group without a LINE clause generates C that does not compile

As posted (owner-reviewed, 2026-11-04):

When a report group's level-01 entry has a PRESENT WHEN clause and its LINE clauses are on the subordinate entries, cobc generates C that uses an undeclared `rf_N`, and the C compiler stops. cobc itself gives no diagnostic about it, also with -Wall.

### To reproduce

`pw1.cob` (attached, free format):

~~~~
IDENTIFICATION DIVISION.
PROGRAM-ID. PW1.
ENVIRONMENT DIVISION.
INPUT-OUTPUT SECTION.
FILE-CONTROL.
    SELECT RPT-FILE ASSIGN TO "pw1.out".
DATA DIVISION.
FILE SECTION.
FD RPT-FILE REPORT IS RPT.
WORKING-STORAGE SECTION.
01 AMT PIC 9(4) VALUE 0.
REPORT SECTION.
RD RPT.
01 DET TYPE IS DETAIL PRESENT WHEN AMT > 0.
   05 LINE PLUS 1.
      10 COLUMN 1 PIC 9(4) SOURCE AMT.
PROCEDURE DIVISION.
    OPEN OUTPUT RPT-FILE
    INITIATE RPT
    MOVE 0 TO AMT
    GENERATE DET
    MOVE 5 TO AMT
    GENERATE DET
    TERMINATE RPT
    CLOSE RPT-FILE
    DISPLAY "DONE"
    STOP RUN.
~~~~

    cobc -x -free pw1.cob && ./pw1 && cat pw1.out

### What happens

3.3-dev r5751 stops with

~~~~
/tmp/cob1000_694752_0.c: In function ‘PW1_’:
/tmp/cob1000_694752_0.c:124:9: error: ‘rf_20’ undeclared (first use in this function); did you mean ‘rl_20’?
  124 |         rf_20.suppress = 0;
      |         ^~~~~
      |         rl_20
/tmp/cob1000_694752_0.c:124:9: note: each undeclared identifier is reported only once for each function it appears in
~~~~

and 3.2.0 with the same error. `pw2.cob` (a PAGE HEADING) and `pw3.cob` (a CONTROL FOOTING FINAL), attached, fail the same way, with or without `-std=cobol2014`; each compiles if the LINE clause is moved onto the level-01 entry.

### What should happen

The program compiles, the first GENERATE prints nothing, and `pw1.out` holds `0005`. PRESENT WHEN may be written in a level-01 report group description entry (ISO/IEC 1989:2023 13.15.2; 13.15.3 forbids it only together with GROUP INDICATE), and when its condition is false, 13.18.41.4 general rule 2 b) says: "Furthermore, if the entry is a level-01 entry, the effect on processing is as though the entire report group description were omitted." The same in 2002 and in the 2014 FCD.

### Why it happens

In `cobc/codegen.c`, `output_if` writes the PRESENT WHEN test to `rl_N.suppress` (the report line) only for an entry with `COB_REPORT_LINE`, otherwise to `rf_N.suppress` (a report field). But `finalize_report` (`cobc/tree.c`) makes every level-01 entry a report line, so this group has an `rl_N` and no `rf_N`. Behind that, `report_line_type` and `report_line_and` in `libcob/reportio.c` print a line's child lines without checking its `suppress` flag, so a heading or footing still prints.

### Proposed fix

The attached patch (against 3.3-dev r5751) has `output_if` use `rl_N` for a level-01 entry too, and has `report_line_type` and `report_line_and` skip the child lines of a suppressed line (only a level-01 entry without LINE has any). With it, `pw1.out` holds `0005`, `pw2` prints its heading only on the second page, and `pw3` prints no footing, each identical to its LINE-on-01 spelling.

The libcob change also makes SUPPRESS PRINTING take effect for such a group when it is a report heading, a page heading, the first control heading, a control footing final or a report footing; each printed before, in programs already compiled too. `pw4.cob`, attached, printed `CH A` and now does not, like its LINE-on-01 spelling.

It adds the testsuite case "PRESENT WHEN on level 01 without LINE" to `run_reportwriter.at` (a DETAIL, a PAGE HEADING and a CONTROL FOOTING FINAL) and ChangeLog entries. `make check`: 1373 expected, 9 skipped, 0 failed (1372 unpatched); the new test fails without the patch.

PRESENT WHEN on a group between the level-01 entry and its LINE entries still fails; there the lines are lost even without it, a separate problem.

### Related
