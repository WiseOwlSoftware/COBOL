# PB4146 — conformance-suite partitioning should scale itself

**Sites:**
- `tests/WiseOwl.Cobol.Tests.Conformance/ConformanceSuiteTests.cs#ConformanceSuiteTestsBase` (`Partitions = 24`; the hand-written `ConformanceSuiteTests_P0..P23` classes)
- `tests/_shared/TestPartitioning.cs` (`SliceRows`; the per-partition slot types)
- `tests/WiseOwl.Cobol.Tests.Conformance/ConformancePartitioningDriftTests.cs#TheSuiteRunner_KeepsItsPartitionCount_AndBoundsEveryPartition` (`MaxSuiteRowsPerPartition = 500`)
- `tests/WiseOwl.Cobol.Tests.Conformance/OptionalWordSubsetDriftTests*` (the same pattern, 8 partitions, 3 formats each)

**Why the bound exists (PB2527).** xUnit v2 runs one test class as one serial collection. PB2527 split the corpus into 24
partition classes so the Conformance leg runs 32-wide; it measured the leg falling from about 255 s to 118 s. The drift
test turns red when a partition passes 500 rows, so a growing suite cannot quietly rebuild a serial pole.

**The defect.** The goal is right; the shape is a hand-maintained number guarding a set that only grows (CLAUDE.md rule 5:
"never a hand-maintained list where a structure belongs"; "prefer the shape that makes the NEXT case automatic"):
1. Every crossing of 24 x 500 rows blocks EVERY branch that adds a suite row until someone edits the constant, writes
   new partition classes and slots, and re-measures (2026-10-30: #811 bounced; PB4092/PB4093, PB851, PB596 and PB4096
   waited on the operator's bump).
2. It invites trimming tests to fit: the PB4096 golden was cut to `accept [2002]` (TEST-NUMVAL-F is in 2002, 2014 and
   2023) to stay under the bound (CLAUDE.md rule 3).

**Direction (to be designed, Mythos, design-heavy).**
- The partition count is derived from the row total (rows / a target rows-per-partition, floor 24 per PB2527), and the
  partition classes and slots are generated (a Roslyn source generator reading the suite manifest, or an equivalent that
  keeps xUnit's one-class-one-collection model), so the suite's growth needs no hand edit.
- The drift test guards what matters: every row runs exactly once (TestPartitionAudit), and no partition's measured time
  (the shared timings store) exceeds the others by more than a stated factor. It no longer gates the total.
- The same for the optional-word sweep.
- Done when: adding goldens never turns a drift test red by count alone; the leg's wall time stays at or under PB2527's
  measurement; PB4096's golden is restored to accept [2002, 2014, 2023].

**Also in scope (review lead R1-3 of #828, the operator's bump).** The doc summaries of
`ConformanceSuiteTestsBase.Partitions` and `MaxSuiteRowsPerPartition` on #828 carry dated history ("on 2026-10-30 ... 12,005
rows"); CLAUDE.md rule 6 wants code comments to state the current design only, so the redesign rewrites them. PB4114 (the
partition horizon) is retired into this note by the operator's notes-pb4114-partition-horizon.
