# PB4146 — conformance-suite partitioning should scale itself

**Sites:**
- `tests/WiseOwl.Cobol.Tests.Conformance/ConformanceSuiteTests.cs#ConformanceSuiteTestsBase` (`Partitions`, its doc summary; the `ConformanceSuiteTests_P0..P31` classes)
- `tests/_shared/TestPartitioning.cs` (`SliceRows`; the slot ladder; `TestPartitionAudit.AuditRowSource`, `TestPartitionAudit.Share`, `TestPartitionAudit.OutsideTheirShare`: the share check)
- `tests/WiseOwl.Cobol.Tests.Conformance/ConformancePartitioningDriftTests.cs` (`TheSuiteRunner_KeepsItsMeasuredPartitionFloor`, `TheOptionalWordSweep_KeepsItsMeasuredPartitionFloor_AndSlicesSpellings`; formerly `MaxSuiteRowsPerPartition = 500`, `MaxFormatsPerOptionalWordPartition = 3`)
- `tests/WiseOwl.Cobol.Tests.Conformance/OptionalWordSubsetDriftTests.cs` (`OptionalWordSubsetDriftTestsBase.Partitions`, `AllCases`, `SpellingOf`, `Run`, `EveryOptionalWordSubset_CompilesAndRunsIdentically`; `SpellingRun`; `OptionalWordBaselines.Of`; the `OptionalWordSubsetDriftTests_P0..P7` classes)
- `tests/WiseOwl.Cobol.Tests.Conformance/ArchOracle.cs#OptionalWordSpelling` (one oracle case per spelling)
- `tests/WiseOwl.Cobol.Tests.Unit/TestPartitionCoverageDriftTests.cs#TheShareCheck_NamesEveryPartitionOutsideItsEvenShare`
- `conformance-suite/cases/15.95.4-Returned-value-rule/pb4096_test_numval_f_exponent_char_in_error.cob` (`accept`)
- `docs/rearchitecture/DESIGN-test-build-ci.md` sections 3.11 and 3.11.1; `docs/rearchitecture/DESIGN-architecture-review.md` section 4 (the `optword/` case id)

**Why the bound exists (PB2527).** xUnit v2 runs one test class as one serial collection. PB2527 split the corpus into 24
partition classes so the Conformance leg runs 32-wide; it measured the leg falling from about 255 s to 118 s. The drift
test turns red when a partition passes 500 rows, so a growing suite cannot quietly rebuild a serial pole.

**The defect.** The goal is right; the shape is a hand-maintained number guarding a set that only grows (CLAUDE.md rule 5:
"never a hand-maintained list where a structure belongs"; "prefer the shape that makes the NEXT case automatic"):
1. Every crossing of 24 x 500 rows blocks EVERY branch that adds a suite row until someone edits the constant, writes
   new partition classes and slots, and re-measures (2026-10-30: #811 bounced; PB4092/PB4093, PB851, PB596 and PB4096
   waited on the operator's bump).
2. It invites trimming tests to fit: the PB4096 golden was cut to `accept [2002]` (TEST-NUMVAL-F is in 2002, 2014 and
   2023) to stay under the bound (CLAUDE.md rule 3).

**Direction (to be designed, Mythos, design-heavy).**
- The partition count is derived from the row total (rows / a target rows-per-partition, floor 24 per PB2527), and the
  partition classes and slots are generated (a Roslyn source generator reading the suite manifest, or an equivalent that
  keeps xUnit's one-class-one-collection model), so the suite's growth needs no hand edit.
- The drift test guards what matters: every row runs exactly once (TestPartitionAudit), and no partition's measured time
  (the shared timings store) exceeds the others by more than a stated factor. It no longer gates the total.
- The same for the optional-word sweep.
- Done when: adding goldens never turns a drift test red by count alone; the leg's wall time stays at or under PB2527's
  measurement; PB4096's golden is restored to accept [2002, 2014, 2023].

**Also in scope (review lead R1-3 of #828, the operator's bump).** The doc summaries of
`ConformanceSuiteTestsBase.Partitions` and `MaxSuiteRowsPerPartition` on #828 carry dated history ("on 2026-10-30 ... 12,005
rows"); CLAUDE.md rule 6 wants code comments to state the current design only, so the redesign rewrites them. PB4114 (the
partition horizon) is retired into this note by the operator's notes-pb4114-partition-horizon.

**Re-probe (worktree-wf_d649df57-b95-1, base 90da780ef).** The operator's bump had landed (32 partitions); the generator's
wiseowl manifest held 3,113 test rows and 8,900 refusal rows, 12,013 in all, 376 a partition, so the 500-row bound would
turn red again 3,987 rows later. The defect (an absolute bound crossed by growth alone) still stood.

**Resolution (landed): the count is the host's, the bound is a SHARE, and the sweep's row is a spelling.** The design
correction is DESIGN-test-build-ci.md section 3.11 "How many partitions". A partition's time is its family's time over P (the
stride gives it 1/P of the rows); the leg's ideal wall is the leg's time over the host's T workers; so a partition stays
under the wall while P ≥ T × (the family's share of the leg), and neither side moves when a family grows with the leg.
So:
1. The size bounds are gone. `ConformancePartitioningDriftTests` keeps only the measured floors (24 suite, 8 sweep,
   PB2527) and asserts the sweep's row is one spelling.
2. `TestPartitionAudit` gained a SHARE check, for every family in both assemblies: each partition holds ⌊n/P⌋ or ⌈n/P⌉ of
   each source's n rows. It bounds a partition relatively, so nothing turns red by count alone. Fired twice: a planted
   count (`TheShareCheck_NamesEveryPartitionOutsideItsEvenShare`) and a planted block split of the sweep (P0 holding 200
   of 380 rows: eight violations, one per partition, the audit red).
3. The optional-word sweep's row is now `(format, mask)`, one spelling, compared with the format's bare spelling, which
   `OptionalWordBaselines` observes once per test process for all partitions. As a row per format, a format's whole
   power set (128 compiles for `special-names-85`) landed in one partition; this was the reason the sweep needed a
   3-formats bound. 9 partitions → 8 (PB2527's measured split; the 9th existed only to stay under the bound). The
   architecture oracle's case is per spelling too (`optword/<format>/<unit>`).
4. The partition classes stay hand-written, one line each, NOT generated: the count changes only with the host, and
   deriving it from the row total is impossible in xUnit v2's class-per-collection model without a second copy of the
   rule (the suite's rows exist only at test time, generate.py running in the test process; `scripts/gate_plan.py`
   models a collection as a class). This departs from the note's proposed direction on evidence; the "Done when" holds.
5. PB4096's golden is restored to `accept: [2002, 2014, 2023]`; it matches its `.out` at all three (CLI re-probe and
   the three suite rows green).

## Landing
- `tests/_shared/TestPartitioning.cs#TestPartitionAudit.AuditRowSource` — the share check (③) beside the slot, empty and
  multiset checks; REUSE `TestPartitionAudit.Share`/`OutsideTheirShare` for any balance question, never a size constant.
- `tests/WiseOwl.Cobol.Tests.Conformance/ConformancePartitioningDriftTests.cs` — floors only (24, 8); a family's count
  follows the host's parallelism and its share of the leg (DESIGN-test-build-ci.md section 3.11), never its row total.
- `tests/WiseOwl.Cobol.Tests.Conformance/OptionalWordSubsetDriftTests.cs#AllCases` — a row is `(format, mask)`; a new
  format is one `Formats` row and spreads by itself. Trap: a static cache on the generic family is per partition, so a
  shared per-process cache goes in a non-generic holder (`OptionalWordBaselines`).
- `tests/WiseOwl.Cobol.Tests.Conformance/ArchOracle.cs#OptionalWordSpelling` — one oracle case per spelling,
  `optword/<format>/<unit>`.
- Trap: a design-doc section written with the section sign in a note or comment is read by the CITATIONS audit as an
  ISO clause (a phantom when the standard has no such clause); write "section 3.11".
