# PB4090 — SEND TO message-server-name FROM x without RETURNING is accepted

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/DeclinedFacilityBinder.cs#ScreenSendRequiredPhrases`, `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/DeclinedFacilityBinder.cs#BindSend`, `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/DeclinedFacilityBinder.cs#ClassifySend`, `src/WiseOwl.Cobol.Compiler/Binding/ReferenceResolver.cs#ProbeDeclaration`, `src/WiseOwl.Cobol.Editions/Diagnostics/DiagnosticCatalog.cs#SendPhrasesOfTwoFormats`, `src/WiseOwl.Cobol.Frontend/Grammar/CobolParserCore.g4#mcsSendStatement` (comment), `docs/CONFORMANCE.md` §4 item 1, `tests/WiseOwl.Cobol.Tests.Conformance/SendFormatClassificationTests.cs`, `tests/WiseOwl.Cobol.Tests.Unit/DeclinedFacilityOperandDriftTests.cs#Roster`, `tests/version-matrix/constructs.json` (`async-messaging-2023` source), `conformance-suite/wiseowl/cases/14.9.38-SEND/pb4090-*`, `conformance-suite/wiseowl/diagnostics.json`

**Expected (checked with `cite.py --check`).** §14.9.38.2 Format 1 prints `RETURNING data-name-1` without brackets, so
it is required. The repaired figure notes, measured on PDF page 756, say so. §14.9.38.3 SR2: message-server-name-1
"is the name of a message server run unit". SR4: data-name-1 and data-name-2 "shall be the name of a message-tag data
item". So a SEND whose TO operand is a name that is not a message-tag data item is Format 1, and it needs RETURNING.

**Observed.** PB2024 added the COBOL1850 screen, but it fires only for a literal-1 operand. A name operand is never
resolved: the binder's comment explains that resolving a server name as a data name would refuse legal source. So
`SEND TO SRV FROM X END-SEND` compiles inert under the declined asynchronous messaging facility (CONFORMANCE.md §4).
The facility is declined; its syntax rules are not.

**Fix.** Classify the name without reporting. If it resolves silently to a message-tag data item (USAGE MESSAGE-TAG),
the statement is Format 2, and RETURNING is not part of that format, so a written RETURNING is refused. Otherwise it
is message-server-name-1 (Format 1), and a missing RETURNING draws COBOL1850. Goldens: both formats, with and without
RETURNING, plus an undefined name, which is a server name and therefore not an error. Edition: the facility is 2023
(Annex E), so below 2023 the statement is refused as before. Coordinate with PB3594 (goldens for SEND RETURNING).

## Landed (wave 20261765 B, 2026-10-29)

Re-probed on the tree first: `SEND TO SRV FROM X END-SEND`, `SEND SRV FROM X END-SEND` and `SEND TO TAG FROM X END-SEND` (TAG a
PIC X item) all compiled; so did `RETURNING R` with `RAISING LAST EXCEPTION` on a name AND on a literal operand (PB4085 defect 2).

**Fix.** `DeclinedFacilityBinder.ClassifySend` assigns the written SEND its format ONCE: a literal-1 operand and RETURNING are
Format 1's, RAISING and a TO name that silently resolves (`ReferenceResolver.ProbeDeclaration`, no report, no Place) to a
MESSAGE-TAG item are Format 2's. Evidence for both is the new **COBOL5488** (`SendPhrasesOfTwoFormats`), once, and the
statement is then asked no per-format rule; evidence for neither is Format 1, so `ScreenSendRequiredPhrases` demands RETURNING
of every Format 1 (COBOL1850, now for a server-name operand as well as a literal). A Format 2 TO name is a data-name-2 and
resolves (an undefined one is COBOL1639); a Format 1 name is a message-server-name-1 and is never resolved. SR4's "shall be
a message-tag data item" is NOT screened (the usage is refused by name, COBOL1943, so no compiled program can hold the item;
the existing goldens use a PIC X data-name-1/2). The grammar rule stays one rule: the name is a bare word in both formats
and the format is a fact about its declaration, so a per-format split (PB4085's direction) would still leave the
missing-RETURNING statement to the binder.

**Witnesses.** `conformance:wiseowl/cases/14.9.38-SEND/pb4090-send-format1-server-name-returning` (accepted at 2023, undefined
server name, TO omitted), `-send-server-name-returning-omitted` (COBOL1850), `-send-returning-and-raising`,
`-send-literal-with-raising`, `-send-message-tag-with-returning` (COBOL5488), `-send-format2-undefined-data-name` (COBOL1639);
`SendFormatClassificationTests` pins the absences (no cascade, a message-tag TO name needs no RETURNING). Goldens that wrote
`SEND TO name FROM x` with no RETURNING as a "Format 2" spelling were rewritten as Format 1 (`optional_words_mcs`,
`wave_h_facilities_inert`, `pb374-async-messaging-below-2023`, `pb2024-send-end-send-omitted`, the `async-messaging-2023`
construct source). PB4085 (both defects) is closed by the same change.
