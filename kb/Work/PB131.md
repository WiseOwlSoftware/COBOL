# PB131

Rows: GR-14.9.4.4-5/-6/-9, SR-14.9.4.3-15/-17/-20, findings [call-statement-p1/p2/p3].

CallBinder.BindCall threads ONE three-state `mode` local across both formats. §14.9.4.4 GR5 is printed under FORMAT 1 and names only BY CONTENT/BY REFERENCE; a Format-2 bare argument takes its mode from the corresponding formal (GR9) — `CALL "SUB" AS NESTED USING BY VALUE A B` against `USING BY VALUE LA BY REFERENCE LB` passes B detached and LB's update is lost (silent wrong answer on conforming source). BY VALUE transitivity exists under no rule in the standard. `asNested` is computed and dropped — BoundCallProgram carries no flag — so SR15's COMMON-or-directly-contained scope check, GR9's formal-mode lookup and §14.2.3 GR9's second BY CONTENT allocation regime (formal-described ANY LENGTH/DYNAMIC LENGTH records) are all structurally unreachable, and ResolveVisible's rule-4/probe arms resolve names SR15 forbids. Requires the callee-header lookup (AS NESTED = same compilation group; not blocked on P13).
