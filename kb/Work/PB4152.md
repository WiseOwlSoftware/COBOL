# PB4152 — IsRefusedName's summary was inserted inside SoleDataRef's doc comment

**Sites:** `src/WiseOwl.Cobol.Frontend/Expressions/CompileTimeExpressionEvaluator.cs:633` (`CompileTimeExpressionEvaluator.IsRefusedName`, `CompileTimeExpressionEvaluator.SoleDataRef`).

Review lead R1-1 (low, not blocking at round 1) of the PB3429 / PB3119 branch, now on main (PR #826 merged it). At
`CompileTimeExpressionEvaluator.cs:633-645`, `IsRefusedName` and its `<summary>` ("True for a name that resolves to nothing because its
own definition was refused and reported ... kb/Work PB3119") were inserted AFTER the doc comment that describes `SoleDataRef`
("The sole (unqualified, unsubscripted) data reference an arithmetic expression consists of ... `SoleOperand` ... kb/Work PB224")
and BEFORE `SoleDataRef` itself. `IsRefusedName` therefore carries two `<summary>` elements, the first describing the wrong
member, and `SoleDataRef` (line 643-645) has lost its documentation.

Fix: move the `SoleDataRef` summary down onto `SoleDataRef` so each member has exactly one summary (sweep the file and the
sibling evaluators for another doc comment split by an insertion).

Not filed here: the same report's remark that `DataBinder.WrittenText` is a forwarder of `WrittenSource.Of` is already held by
PB2733.
