# PB685 — OPEN — a required determination the document does not carry

Found 2026-09-05 by the `PB673` implementer (report §"New defects" 1) while writing `DOC-A.1-72`, whose text
refers to item 71 ("the TO phrase's operand is a file-name mapping (item 71)") — and `grep -n "DOC-A.1-71"
docs/CONFORMANCE.md` finds nothing.

## The rule

§12.4.5.2 (`cite.py --check 12.4.5.2 "The meaning and rules for the allowable specification of device-name-1 and
the value of literal-1 are defined by the implementor"` → OK): the TO phrase's operands are implementor-defined, and
Annex A.1 item 71 makes the statement of that definition REQUIRED for a conforming implementation's documentation.
The implementation HAS a rule — `src/Cobol.Net.Runtime/IO/CobolFile.cs#ResolveHostPath`: a target carrying `.`, `/`
or `\` is taken verbatim; anything else is lowercased and given `.txt` in the current directory; there is no
device-name vocabulary — it is simply not stated where §4.2 requires it.

## Fix

Add `DOC-A.1-71` to CONFORMANCE.md §7 stating the value (the PB280 Q3 rule: state it, do not refer), cross-checked
against `ResolveHostPath` and `DOC-A.1-73`'s trimming rule so the two rows compose (a USING operand's trimmed content
is mapped by THIS rule); `audit_annex_a1.py --check` green; the §7 banner counters advanced. Same family as
[[PB645]] (a §2 cell) and the other CONFORMANCE.md completeness notes — check whether more REQUIRED items lack rows
while there (`audit_annex_a1.py` can list the required items without a determination; if it cannot, that is the
structural fix).
