## Finding — `class-and-category-of-data-items-and-literals-p1` (rejects-legal-source; rows `GR-8.5.2.3-4`, `GR-8.5.2.5-4`, `GR-8.5.2.10-4`, `GR-8.5.2.8-2`)

**Mechanism.** F1 - FUNCTION LENGTH / BYTE-LENGTH do not treat a function-identifier argument as the data item of its §15.2 category. BindByteLengthFold has NO arm for a nested function result (BoundComputedOperand), and BindLengthFold has one only for Alphanumeric/National/Boolean results, so every other argument falls to the catch-all arm that calls it 'a numeric literal' and rejects it COBOLNET1627. This is the two-arm dispatch shape: the LENGTH twin got its nested-function arm, BYTE-LENGTH did not, and neither covers index (or numeric) functions.

**Repro.** 01 X PIC X(3) VALUE "abc". 01 IA USAGE INDEX. 01 IB USAGE INDEX. ... DISPLAY FUNCTION BYTE-LENGTH(FUNCTION UPPER-CASE(X)) DISPLAY FUNCTION BYTE-LENGTH(FUNCTION NATIONAL-OF(X)) DISPLAY FUNCTION BYTE-LENGTH(FUNCTION BOOLEAN-OF-INTEGER(5, 16)) DISPLAY FUNCTION LENGTH(FUNCTION MAX(IA IB)) (probes E:\Temp\claude\E--CobolSharp\a700c052-f9e4-4942-84ff-a13c7505d6ec\scratchpad\adj-d2\out\probe\cat1\p3.cob and p7.cob, pinned cobol.exe, --std 2023)

**Expected from the spec.** All four compile. §15.14.3 r1 'Argument-1 shall be an alphanumeric or national literal, a based entry, a type-name, or a data item of any class or category' and §15.50.3 r1 '...; a data item of any class or category; ...'; §8.4.3.2.1 'A function-identifier references the unique data item that results from the evaluation of a function'; §8.5.2.3 item 4 / §8.5.2.5 item 4 / §8.5.2.10 item 4 / §8.5.2.8 item 2 make an alphanumeric / boolean / national / index function a data item of that category. BYTE-LENGTH of the UPPER-CASE result = 3 (1 byte per alphanumeric char), of the NATIONAL-OF result = 6 (2 bytes per national char, D-N1), of BOOLEAN-OF-INTEGER(5,16) = the byte size of 16 boolean positions under the implementation's boolean representation; LENGTH(FUNCTION MAX(IA IB)) = the index item's length in alphanumeric positions per §15.50.4 r3.

**Observed / reasoning.** Each line is rejected: 'error COBOLNET1627: FUNCTION BYTE-LENGTH argument-1 is a numeric literal, which §15.14.3 r1 does not admit ...' and 'FUNCTION LENGTH argument-1 is a numeric literal, which §15.50.3 r1 does not admit ...'. By contrast LENGTH(FUNCTION NATIONAL-OF(X)) = 3 and LENGTH(FUNCTION BOOLEAN-OF-INTEGER(5,16)) = 16 compile and are correct, because BindLengthFold has the BoundComputedOperand arm for those three result categories. kb/Work PB1068 (open, process_only, rejects_legal_source:false) records the BYTE-LENGTH repro but says 'The refusals are right; the words are wrong'. That premise is false: the refusal itself is the defect, so PB1068 should become rejects-legal-source (or be split so the fix is not treated as wording only). The fix belongs in one place: the function-result arm of both folds, keyed on the §15.2 type from IntrinsicResultType.Resolve, not on a list of three categories.

**Code site.** src/Cobol.Net.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs#IntrinsicBinder.BindByteLengthFold (catch-all `_ => InadmissibleArgument(... "is a numeric literal" ...)`, ~line 2394); src/Cobol.Net.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs#IntrinsicBinder.BindLengthFold (BoundComputedOperand arm limited to ResultCategory Alphanumeric/National/Boolean, ~line 2025)
