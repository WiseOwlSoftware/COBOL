# PB662 — OPEN — a known residue, now a note

Found 2026-09-05 by the `PB303` implementer (report §"New defects" D-3), which implemented the `AS literal` phrase on
PROGRAM-ID Format 1 and rendered the printed page for Format 2 (`[ AS literal-1 ] IS PROTOTYPE`, PDF p.280) but
deliberately did not claim `FMT-11.10.2` or `GR-11.10.4-6`: a program prototype is a source-unit KIND (§11.10.4
GR6 gives its meaning; §12.3.8.4 GR10 b) resolves a program name through it), and the grammar/binder have no such
kind for programs — only for functions (`BoundUnit.IsPrototype`, the FUNCTION-ID Format-2 twin). `BinderDriver`
names it in a comment as the missing GR10 b) arm; a residue named in code is a note ([[PB237]]'s registry left it as
its documented deferral, `SR-8.3.2.2-L3.1`/`-L3.2`).

## The rule

§11.10.2 Format 2 (render the page before implementing: `scripts/render-spec-page.py 310`); §11.10.4 GR6
(`cite.py --check 11.10.4 …` on its first sentence first — PB303 validated GR1 only); §12.3.8.4 GR10 b) — a program
prototype in the repository resolves the program-name of a CALL to the prototype's externalized name and signature.

## Fix shape

Model the program prototype as PB237's registry already models the function prototype: `PROGRAM-ID … IS PROTOTYPE.`
binds to a `BoundUnit` with `IsPrototype` and no PROCEDURE DIVISION body (§11.10.3's rules for a prototype
definition — measure which clauses it may carry), registers in the program-prototype registry under its
externalized name (PB303's two-name model), and `BuildProgramDefinitionTable` gains the GR10 b) arm beside GR10 a)
and c). Goldens at 2002/2014/2023: a prototype declared and CALLed through the repository (positive), a prototype
with a body (negative, §11.10.3), a CALL whose arguments disagree with the prototype's signature (negative, PB237's
§14.8.2 conformance check now reaching a program). Re-verdict `FMT-11.10.2`, `GR-11.10.4-6` and PB237's two deferred
`SR-8.3.2.2-L3.*` rows.
