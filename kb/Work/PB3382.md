# PB3382 — no test refuses the sync of an unchanged CLOSE

A LOW lead from the Mythos lane's review of PB3333 (`mythos-a3-review-r4` at `46934aa87`, report
`E:\COBOL-coord\scratch\reports\w1118a3-PB3333-report.md`). The lane assigned it to the operator's clerk, and the
operator files it here. The code it names landed with PB3333 (branch `worktree-wf_14a1e62b-326-20`, PR 255), which
`blocked_by` records.

**The rule.** In `PagedFile.Close` (`src/Cobol.Net.Runtime/IO/Store/PagedFile.cs`, about line 490), a store that
completed no statement since its last promotion only SYNCS. A refused sync there must answer the refusal (the '30'
path), never '00'.

**The gap.** `tests/Cobol.Net.Tests.Unit/Store/PagedFileCrashMatrixTests.cs` (`SceneFor`, about line 60:
`changedA: path == PagePath.Close`):
- At `249e467ca` the CLOSE path's scene left store A unchanged, so the matrix refused and killed that one sync.
- Since `1a2728f7a` the CLOSE path always changes A first, so nothing refuses the sync of an UNCHANGED CLOSE, at the
  page layer or through the connector.
- `KeyedStoreReloadFailureDriftTests` covers only the unrefused CLOSE after a '30'.

**Harm.** A regression that answered '00' for a refused sync of an unchanged CLOSE would pass the gate, and the
program would believe its file durable when the host had refused the write. This is the exception-path case the owner's
rule requires (MANDATORY-PRACTICES I11: "a process death and a refused write or sync at every point").

**The fix.** Add a `PagePath.CloseUnchanged` path next to the changed one: its scene has `changedA: false`, and the
matrix refuses that sync and expects the refusal, at the page layer and through the connector. The expected status
comes from the design's CLOSE rule (DESIGN-runtime-library 2.2.1, the store's sync failure) and the I-O status the
refusal answers. Pin it so a CLOSE scene can never again change A on every path.

## Landed

Re-probed on the build of c82c9213f: `PagedFile.Close` (about line 499) already answers `PermanentError` for a refused sync of a
store that owes no promotion, so the code was right and the GATE was blind. Mutation proof: replacing the final
`return TrySync() ? Ok : PermanentError` with `TrySync(); return Ok;` left no test red except the changed CLOSE's own
refused-sync cell, and nothing at the connector level.

The fix is test-side and structural: `PagedFileCrashMatrixTests` gains `PagePath.CloseUnchanged` (scene `changedA: false`; its
operations are exactly one sync, no write, no read), so the matrix's death/refusal loop, its three continuations and the
refused-read loop run it; `EndsTheRunUnitsUse` replaces two hand-written `Close or Fence` lists; and
`The_CLOSE_scenes_pin_a_promoting_CLOSE_and_a_CLOSE_that_is_one_sync` pins the two scenes' operation shapes so a scene that
changes A on every CLOSE path fails at once. `KeyedStoreReloadFailureDriftTests` gains the connector-level cell
(RELATIVE and INDEXED; ALL OTHER, READ ONLY and the clause-less NO OTHER; with and without a READ first): '30', no page
written, the records kept. With the mutation applied again, the page-layer cell and all 12 connector cells fail.
DESIGN-runtime-library 2.2.1.16 gains the row of a CLOSE that owes no promotion.
