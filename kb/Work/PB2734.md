**Rule it breaks:** ISO 8.3.3.6.4 GR4 (the zero format is the value 0 or a string of the character 0 DEPENDING ON CONTEXT) with GR2 (associated with a compared data item it is repeated to that item's length); a parenthesis that groups a CONDITION is not an arithmetic context. The rewriter's own class comment says its paren arms mean ARITHMETIC parens only (ZeroTokenRewriter.cs:23-41), yet its adjacency test cannot tell a condition's '(' from an arithmetic one: both are the plain LPAREN/RPAREN token.

**Scenario:** Measured on the pin (cobol.exe built at 8be230068, --source-format free --run): 01 WS-A PIC X(3) VALUE "000". then IF WS-A = ZERO prints BARE EQUAL, IF (WS-A = ZERO) prints PAREN NOT EQUAL, and IF (ZERO = WS-A) prints PAREN2 NOT EQUAL. ZeroTokenRewriter.Rewrite mints ZERO_ARITH for the ZERO before ')' (FollowingArithmeticContext holds RPAREN) or after '(' (PrecedingArithmeticContext holds LPAREN); ExpressionBinder.BindPrimary binds ZERO_ARITH as BoundNumLiteral("0") and ConditionBinder.SoleNumLiteral reads it as the literal "0", so the alphanumeric comparison is against "0" padded with spaces instead of "000". A silent wrong branch on legal source; every parenthesized relation, NOT (...) and PERFORM UNTIL (... = ZEROS) against an alphanumeric, alphanumeric-edited or national operand is exposed, at every edition and with all three spellings ZERO/ZEROS/ZEROES.

**Measured how:** R2 batch finding `parser-tree-2--code--f1#1` (pair parser-tree-2--code), read in the pinned tree at 8be23006851a; skeptics rule upheld, scenario upheld, site upheld.

**Spec:** §8.3.3.6.4 "The zero format represents the numeric value '0', one or more of the boolean character '0', or one or more of the character '0' in the computer's runtime coded character set, depending on context." (`cite.py --check` passed at collection); §8.3.3.6.4 "A figurative constant is associated with a data item or literal when, for example, the figurative constant is moved to it, compared with it, or paired with it in a binary operation." (`cite.py --check` passed at collection)

**Target:** A ZERO that no arithmetic operator touches keeps its figurative identity. Either the paren arms leave ZeroTokenRewriter (whether a '(' groups an arithmetic primary is the parser's decision, not adjacency's) or, keeping the token shape, the one sole-operand reader treats a relation operand that is a sole ZERO_ARITH primary as the figurative ZERO so GR4's context (the other operand's class) decides; one rule in one place, a golden for the three probes above at every edition, and a sibling sweep of every other consumer of ZERO_ARITH (CompileTimeExpressionEvaluator, DataBinder:6337, CallBinder).
