# PB1918 — LANDED (wave 1028, PB2111)

Filed by the train-1004 lander from wave 1004 group B's report (`w1004b-PB1368-report.md`).

## Finding

**Site.** `src/WiseOwl.Cobol.Frontend/WiseOwl.Cobol.Frontend.csproj:23` — the `InternalsVisibleTo` item names `Legacy.Tests.Unit`,
an assembly name that no longer exists; the unit test assembly is `WiseOwl.Cobol.Tests.Unit` (`WiseOwl.Cobol.Editions` grants
the right name). Wave 1004 group B had to test `CopyProcessor.OpenStatementAt` and the DISPLAY directive's helpers
through public entry points for that reason.

**Fix shape.** Rename the grant to `WiseOwl.Cobol.Tests.Unit` (no alias kept, CLAUDE.md rule 4), then let the tests that
reached internals indirectly call them directly where that makes them sharper (`OpenStatementAt` first).

## Landed (wave 1028, PB2111)

PB2110 deleted the stale grant together with the legacy unit project, which left the Frontend with no grant at all. PB2111 adds
`<InternalsVisibleTo Include="WiseOwl.Cobol.Tests.Unit" />` to `src/WiseOwl.Cobol.Frontend/WiseOwl.Cobol.Frontend.csproj`, the same item the
Compiler, Editions, Runtime and Cli projects carry, so a unit test can now call a Frontend internal directly. No alias is kept
(CLAUDE.md rule 4). The optional second half (let tests that reached `CopyProcessor.OpenStatementAt` and the DISPLAY directive's
helpers through public entry points call them directly) is a per-test sharpening and is not part of this fix.
