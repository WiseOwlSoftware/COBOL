**Wave kind:** defect-for-fix-lane. **Model:** the fix lane's routing (`model_rules.json`).

**Sites:**
- `src/Cobol.Net.Runtime/Values/Text/CobolDynString.cs:118-160` (CobolDynString.SetSize)

**Rule it breaks:** ISO 14.9.39.4 GR37 (a value that does not evaluate to a nonnegative number sets the length to 0 AND sets EC-STORAGE-NOT-AVAIL); review dimension 2 sibling agreement - the SetSize doc says it mirrors CobolTiming.ContinueAfter, which screens !double.IsFinite first (kb/Work PB138), and SetAmount.Land(double) does the same

**Scenario:** Measured on the pin build (pin-r2 Debug cobol.exe): 01 G. 05 F USAGE FLOAT-LONG. 01 G2 REDEFINES G PIC X(8). 01 D PIC X DYNAMIC LENGTH LIMIT 10. with >>TURN EC-STORAGE-NOT-AVAIL CHECKING ON; MOVE X"7FF8000000000000" TO G2, MOVE "ABC" TO D, SET SIZE OF D TO F prints LENGTH(D)=0 and EXCEPTION-STATUS blank. Expected per GR37: length 0 AND EC-STORAGE-NOT-AVAIL (a USE declarative for it never runs). Mechanism: NaN fails both newLen < 0.0 and newLen > maxSize, falls to (int)newLen, which .NET saturates to 0 silently. The same program with a FLOAT-LONG value -1 does set the condition.

**Measured how:** R2 batch finding `runtime-values-3--code--f1#1` (pair runtime-values-3--code), read in the pinned tree at 8be23006851a; skeptics rule refuted, scenario upheld, site upheld.

**Spec:** §14.9.39.4 "If arithmetic-expression-5 does not evaluate to a nonnegative number, the length of data-name-3 is set to 0 and an EC-STORAGE-NOT-AVAIL exception condition is set to exist." (`cite.py --check` passed at collection)

**Target:** SetSize screens !double.IsFinite(newLen) before the range legs exactly as ContinueAfter and SetAmount.Land(double) do: NaN and -Infinity take the GR37 leg (length 0, raise), +Infinity the GR38 clamp leg; add a unit row per non-finite value and sweep the other double-taking runtime entry points for the same three-leg fall-through

**Design reference:** PB464.
