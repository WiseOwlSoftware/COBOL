**Rule it breaks:** ISO 14.9.39.4 GR37 (a value that does not evaluate to a nonnegative number sets the length to 0 AND sets EC-STORAGE-NOT-AVAIL); review dimension 2 sibling agreement - the SetSize doc says it mirrors CobolTiming.ContinueAfter, which screens !double.IsFinite first (kb/Work PB138), and SetAmount.Land(double) does the same

**Scenario:** Measured on the pin build (pin-r2 Debug cobol.exe): 01 G. 05 F USAGE FLOAT-LONG. 01 G2 REDEFINES G PIC X(8). 01 D PIC X DYNAMIC LENGTH LIMIT 10. with >>TURN EC-STORAGE-NOT-AVAIL CHECKING ON; MOVE X"7FF8000000000000" TO G2, MOVE "ABC" TO D, SET SIZE OF D TO F prints LENGTH(D)=0 and EXCEPTION-STATUS blank. Expected per GR37: length 0 AND EC-STORAGE-NOT-AVAIL (a USE declarative for it never runs). Mechanism: NaN fails both newLen < 0.0 and newLen > maxSize, falls to (int)newLen, which .NET saturates to 0 silently. The same program with a FLOAT-LONG value -1 does set the condition.

## Landed (wave 1045 group G, 2026-10-08)

Re-probed on this worktree's build (`E:/COBOL-coord/scratch/w1045g/nan.cob`, the note's scenario): `LEN=0`,
`ES=[` 31 spaces `]` before; `LEN=0`, `ES=[EC-STORAGE-NOT-AVAIL           ]` after. Cite checked: §14.9.39.4 GR37 and
GR38.

**Fix.** `CobolDynString.SetSize` takes GR37's leg for `double.IsNaN(newLen) || newLen < 0.0`: a NaN fails both range
comparisons and used to reach the `(int)` cast, which .NET saturates to 0 silently. The infinities needed no screen
(−∞ is below zero, GR37; +∞ is above every maximum, GR38's clamp), and both are now pinned. ⚠ DETERMINATION: an
infinity is a NUMBER (ISO/IEC 60559's floating-point numbers include the infinities; only the NaNs are not), so +∞ is
GR38's "evaluates to a number that is greater than the maximum size", clamped and raised; the rejected reading (every
non-finite value is "not a nonnegative number", length 0) would also send +∞ to length 0. The fix does NOT add the
EC-DATA-NOT-FINITE raise `CobolTiming.ContinueAfter` makes: that is §14.6.13.2 item 3, which applies only to a STANDARD
floating-point sending operand, and SET SIZE's own rule names the condition here. Sibling sweep: every public runtime
entry point taking a `double` was listed (`grep "public static ...(double"` over `src/Cobol.Net.Runtime`); the ones with
range legs (`CobolPtr.AllocateReal`, `CobolNum.PositionOf(double)`, `CobolDate.SecondsOfReal`, `SetAmount.Land(double)`,
`CobolTiming.ContinueAfter`, `ReportWriter.VaryingInteger(double)`) all screen NaN first; SetSize was the only
three-leg fall-through.
