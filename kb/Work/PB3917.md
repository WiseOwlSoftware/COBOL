# PB3917 — occurs-dynamic-not-supported--zero-size-table: OCCURS DYNAMIC (announced by -Wpending as not implemented) compiles to a zero-byte record with out-of-bounds stores and exit 0: please make it an error

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S7) and refutation (RECLASSIFY). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\occurs-dynamic-not-supported--zero-size-table.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\occurs-dynamic-not-supported--zero-size-table\`.

## Summary

**Corrected by the refuter (class): unsafe code for an unimplemented OPTIONAL element, not an ISO nonconformance.** Dynamic-capacity tables are optional (2023 A.4.4 2) and 4.2.7, checked; A.4.4 1) of the 2009 draft for 2014), and GnuCOBOL claims no support, so the statements below that `a feature -std=cobol2014 claims` is miscompiled and that the ISO result is `AAABBBWWW` are wrong. What survives is storage safety: a construct that cobc says it does not implement compiles to a zero-byte record with out-of-bounds stores and exit 0 (the -debug run stops with `subscript of 'E' out of bounds: 1`, exit 1; rerun on cobc 3.2.0 matches, parser.y lines 8390-8403 verified). The request is an error in place of the warning. The text below was written before this correction; where it differs, this paragraph governs.

Record text as adjudicated:

GnuCOBOL 3.2 accepts a dynamic-capacity table (`OCCURS DYNAMIC`, ISO/IEC 1989:2014) under `-std=cobol2014` with only
the warning `OCCURS DYNAMIC is not implemented [-Wpending]`, and allocates the containing record with zero bytes. When
the subscripts are data items the program compiles (exit 0) and runs (exit 0): each receiving reference writes outside
the zero-byte record, and the program prints bytes that are not the stored values. With `-debug` the first store
stops the run with `subscript of 'E' out of bounds: 1`. Class: compiles but is not implemented at run time, with
out-of-bounds stores and wrong output.

This record is one half of the family occurs-dynamic-not-supported; the other half,
`occurs-dynamic-not-supported--constant-subscript`, is the same table refused at compile time when the subscripts are
literals.

## Minimal test case

Free reference format (`-fformat=free`), 14 lines, written for this record (reduced from night-3 witness fz00482,
whose literal subscripts land in the other half).

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. OCCDYN2.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 I PIC 9 VALUE 1.
01 J PIC 9 VALUE 2.
01 T.
   05 E PIC X(3) OCCURS DYNAMIC.
01 W PIC X(3) VALUE "WWW".
PROCEDURE DIVISION.
MOVE "AAA" TO E(I)
MOVE "BBB" TO E(J)
DISPLAY E(I) E(J) W
STOP RUN.
```

File: `E:\COBOL-coord\scratch\op\pb3838\records\occurs-dynamic-not-supported--zero-size-table.cob`.

The program is legal: the OCCURS clause is at level 05 (§13.18.38.3 1)), in working-storage (§8.5.1.9.1 3)), with no
FROM, TO, CAPACITY, KEY or INDEXED phrase.

## Observed result

Compile, `-std=cobol2014`, exit code 0. The cobc diagnostic, then the C compiler's (source-context lines omitted):

```
occdyn2.cob:8: warning: OCCURS DYNAMIC is not implemented [-Wpending]
/tmp/cob1279_0.c: In function 'OCCDYN2_':
/tmp/cob1279_0.c:103:3: warning: 'memset' writing 3 bytes into a region of size 0 overflows the destination [-Wstringop-overflow=]
/tmp/cob1279_0.c.l.h:36:17: note: destination object 'b_3' of size 0
/tmp/cob1279_0.c:106:3: warning: 'memset' writing 3 bytes into a region of size 0 overflows the destination [-Wstringop-overflow=]
```

Run, exit code 0, the same on three runs (`od -c`): `B B B \0 \0 \0 W W W \n`, that is `BBB`, three NUL bytes,
`WWW`. The default dialect (no `-std`) gives the same output.

With `-debug`, run exit code 1:

```
libcob: occdyn2.cob:11: error: subscript of 'E' out of bounds: 1
note: maximum subscript for 'E': 0
```

The generated C (`-C`) declares the record as `static cob_u8_t b_3[0]; /* T */` and stores each element at
`b_3 + 3 * (subscript - 1)`.

## Expected result (per ISO)

The program prints `AAABBBWWW` and ends normally.

- ISO/IEC 1989:2023 §8.5.1.9.1 (checked): "Dynamic-capacity tables are tables whose physical and logical capacities
  may vary during execution." With no FROM phrase and no VALUE clause, "the current capacity is initialized to zero"
  (§8.5.1.9.1, checked).
- §8.5.1.9.3 (checked): "When a data item in a dynamic-capacity table is referenced as a receiving item and the value of
  the subscript exceeds the current capacity of the table, a new element is automatically created and the capacity of
  the table is increased to the value given by the subscript." So `MOVE "AAA" TO E(I)` with I = 1 creates element 1
  and `MOVE "BBB" TO E(J)` with J = 2 creates element 2.
- §8.5.1.9.2 (checked): "When a data item in a dynamic-capacity table is referenced as a sending operand, the result of
  the operation is the same as for a fixed-capacity table whose number of occurrences is the current capacity of the
  table." The DISPLAY therefore shows `AAA` and `BBB`; W is untouched.
- General format: §13.18.38.2 Format 4 (dynamic-capacity-table), `OCCURS DYNAMIC [ CAPACITY IN data-name-3 ]
  [ FROM integer-4 ] [ TO integer-5 ] [ INITIALIZED ]`, followed by the KEY and INDEXED phrases.

Edition: dynamic-capacity tables are in ISO/IEC 1989:2014. The 2009 committee draft that led to 2014 (CD 1.2,
2009-08-23) carries the same Format 4 and the same "Implicit changes in capacity" rule (its clause 8.5.1.6.3.2 of that text); Annex E of
the 2023 standard, which itemizes the 2014-to-2023 changes, does not list them as new. GnuCOBOL's own `cobc/reserved.c`
tags CAPACITY as a 2014 word, and its `cobc/ChangeLog` (2014-09-12) records "Added parser support for OCCURS DYNAMIC
along with CAPACITY clause as not implemented".

Edition as recorded by the adjudicator: 2014. `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Class

Compiles but is not implemented at run time: unsafe code for an unimplemented optional element (A.4.4, 4.2.7). A `-Wpending`-only OCCURS DYNAMIC yields a zero-byte record and out-of-bounds stores, exit 0. Not an ISO nonconformance; the request is an error in place of the warning. Corrected by the refuter.

## Our compiler (WiseOwl)

WiseOwl COBOL (built from main 6ed90bd1c), `cobol occdyn2.cob --std 2014 --source-format free -o occdyn2.dll`, then
`dotnet occdyn2.dll`: compile exit 0, run exit 0, output `AAABBBWWW`.

## Fix site (GnuCOBOL 3.2 source, read observationally)

- `cobc/parser.y`, rule `occurs_clause`, the `OCCURS DYNAMIC` arm (line 8390): sets `occurs_min` from FROM (else 0)
  and `occurs_max` from TO (else 0), then `CB_PENDING ("OCCURS DYNAMIC")`, which `cobc/cobc.h` defines as a
  `cb_warn_pending` warning, not an error.
- `cobc/field.c`, `compute_size` (line 2822): sizes the table as element size times `occurs_max`, which is 0, so the
  record gets zero bytes.
- `cobc/codegen.c` subscript arithmetic and `libcob/common.c` `cob_check_subscript` (the `-debug` check, line 4438):
  no capacity tracking or element creation.
- Short of implementing the feature, an error in place of the `-Wpending` warning for OCCURS DYNAMIC would stop the
  out-of-bounds stores.

**Title:** OCCURS DYNAMIC (announced by -Wpending as not implemented) compiles to a zero-byte record with out-of-bounds stores and exit 0: please make it an error

**Body:**

Environment: GnuCOBOL 3.2.0 (Ubuntu gnucobol3 3.2-4build1), x86_64 Linux.

Steps: `cobc -std=cobol2014 -fformat=free -x occdyn2.cob && ./occdyn2 | od -c` with

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. OCCDYN2.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 I PIC 9 VALUE 1.
01 J PIC 9 VALUE 2.
01 T.
   05 E PIC X(3) OCCURS DYNAMIC.
01 W PIC X(3) VALUE "WWW".
PROCEDURE DIVISION.
MOVE "AAA" TO E(I)
MOVE "BBB" TO E(J)
DISPLAY E(I) E(J) W
STOP RUN.
```

Observed: cobc warns `OCCURS DYNAMIC is not implemented [-Wpending]` and compiles (exit 0); gcc warns
`'memset' writing 3 bytes into a region of size 0 overflows the destination` for `b_3`, which the generated C declares
as `b_3[0]` for record T. The run exits 0 and prints `BBB`, three NUL bytes, `WWW`. With `-debug` the first MOVE fails:
`subscript of 'E' out of bounds: 1` / `maximum subscript for 'E': 0`.

Expected: `AAABBBWWW`. OCCURS DYNAMIC (dynamic-capacity tables) is part of ISO/IEC 1989:2014 (2023 §8.5.1.9 and
§13.18.38 Format 4): "When a data item in a dynamic-capacity table is referenced as a receiving item and the value of
the subscript exceeds the current capacity of the table, a new element is automatically created and the capacity of
the table is increased to the value given by the subscript."

Until the feature is implemented, the pending warning lets a program compile and store outside its storage; making
OCCURS DYNAMIC an error under the cobol2014 dialect would prevent that. Related: with literal subscripts
(`MOVE "AAA" TO E(1)`) the same table is refused at compile time with `subscript of 'E' out of bounds: 1`.
