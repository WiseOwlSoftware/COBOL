# PB4074 — CopyProcessor's optional diagnostics bag lets an error disappear

**Sites:** `src/WiseOwl.Cobol.Frontend/Preprocessor/CopyProcessor.cs#ResolveOneCopy`, `src/WiseOwl.Cobol.Frontend/Preprocessor/CopyProcessor.cs` (the constructor's `DiagnosticBag? diagnostics = null` and the six `_diagnostics?` call sites), `src/WiseOwl.Cobol.Frontend/Preprocessor/CopyProcessor.cs#ApplyReplaceStatements`

`CopyProcessor` is constructed with `DiagnosticBag? diagnostics = null` and reports through `_diagnostics?.Report…`. A
processor built without a bag therefore drops every error it finds. PB1092 added one more such path: `ResolveOneCopy`
passes `_diagnostics` to `ReadSourceText`, so a library text whose byte-order mark names an encoding its content is not
well-formed in becomes the comment line "library text malformed" with no diagnostic. The implementer checked the only
bag-less caller, the line-map replay, and found it runs after a pass that already reported each of these errors, so no
user loses one today. That safety is a convention, and the type does not say so.

**Fix.** Make the bag required. Give the replay, if it must not report twice, an explicit mode or its own discard sink
that names why, so an error-reporting path can never be constructed silent by default. Sweep `ApplyReplaceStatements`
(also optional), which has the same shape.
