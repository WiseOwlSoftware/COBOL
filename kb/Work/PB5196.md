# PB5196 - at --std 85 RECORD CONTAINS 5 TO 5 CHARACTERS is refused (COBOL2009) and RECORD CONTAINS 0 TO 5 is accepted: the RECORD clause's integer rules are the 2023 ones at every edition

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/RecordClauseRules.cs` (`Rules`, `Screen`)
- `src/WiseOwl.Cobol.Compiler/Validation/IntegerOperandPass.cs` (`RecordClause`)

**Mechanism.** §1985:VII.3.8.2 prints the three RECORD formats, and no 1985 rule orders integer-4 and integer-5 or allows a zero integer (§1985:III.2: an integer "must be neither signed nor zero unless explicitly allowed by the rules for that format"). Two 2023 rules apply at every edition: the Rules table of `RecordClauseRules` has no edition column, so its row for integer-5 greater than integer-4 fires in `Screen` at 85 and refuses RECORD CONTAINS 5 TO 5 (a legal program rejected); and `IntegerOperandPass.RecordClause` grants zero to integer-2 and integer-4 on the 2023 rules, so FROM 0 TO 5 and CONTAINS 0 TO 5 compile. kb/Work PB5115 is the same 2023 ordered-pair rule in BLOCK CONTAINS, at its own site.

**Found by.** The 1985 code read (2026-11-10; its records are `E:/COBOL-coord/scratch/coderead-85/for-register.json`): each rule below was read against the code sites it names and probed at `--std 85`, and found non-conforming. Verdict, harm, evidence, repro and observed text are the records'; the rows' verdicts are recorded on another branch.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids of the list below.

Checked: §1985:VII.3.8.2: "VARYING"; §1985:III.2: "integer must be a numeric literal which is an integer, and it must be neither signed nor zero unless explicitly allowed by the rules for that format". Code sites read: src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolData.g4#recordClause; src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs#VisitRecordClause; src/WiseOwl.Cobol.Compiler/Binding/FileControlBinder.FileSection.cs#BindRecordClause; src/WiseOwl.Cobol.Compiler/Binding/RecordClauseRules.cs#Screen; src/WiseOwl.Cobol.Compiler/Binding/RecordClauseRules.cs#Rules; src/WiseOwl.Cobol.Compiler/Validation/IntegerOperandPass.cs#RecordClause; src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs#ClauseDataName; src/WiseOwl.Cobol.Compiler/Validation/ClosedFormatPass.cs#ScreenClauseRepetition. Code read: No kb/Work note owns the fix (PB5115 is the same mechanism in BLOCK CONTAINS). §1985:VII.3.8.2 prints three formats: RECORD CONTAINS integer-1 CHARACTERS; RECORD IS VARYING IN SIZE [[FROM integer-2] [TO integer-3] CHARACTERS] [DEPENDING ON data-name-1]; RECORD CONTAINS integer-4 TO integer-5 CHARACTERS (RECORD, VARYING, TO and DEPENDING underlined). Implemented at 85: recordClause's two alternatives parse the three formats with every optional word written or dropped and the phrases in the printed sequence only; BindRecordClause captures the integers and, through ClauseDataName, an unsubscripted (qualified) data-name-1; VisitRecordClause refuses the 2023 word BYTES (COBOL0900). Probed at 85: RECORD CONTAINS 5 CHARACTERS, RECORD 5, RECORD 4 TO 10, RECORD VARYING, RECORD IS VARYING IN SIZE CHARACTERS, FROM alone, TO alone, VARYING 1 TO 10, DEPENDING WS-N and DEPENDING ON WS-N OF G1 compile; RECORD IS 5, CONTAINS VARYING, a signed or data-name integer, DEPENDING ON on a CONTAINS form, DEPENDING before FROM, TO before FROM, a subscripted or literal DEPENDING operand, 4 THRU 10, BYTES and the clause twice are refused, and FROM 10 TO 10 is refused as §1985:VII.3.8.3 SR3 requires. Two departures, both the 2023 rules applied at every edition. (1) Format 3 with equal integers is refused at 85: the Rules table of RecordClauseRules has no edition column (its comment says every rule is present in all four editions) and its row for §2023:13.18.43.3 SR9 (integer-5 greater than integer-4) fires in Screen at 85, but 1985 has no syntax rule for format 3 and §1985:VII.3.8.4 GR14 makes the integers the smallest and the largest record size, which are equal for a file of one record size. (2) Zero is accepted at 85 for integer-2 and integer-4: IntegerOperandPass's RecordClause classifier grants zero on §2023:13.18.43.3 SR7 and SR8 with no edition arm, so RECORD IS VARYING IN SIZE FROM 0 TO 5 CHARACTERS and RECORD CONTAINS 0 TO 5 CHARACTERS compile, where §1985:III.2 (Integer) says an integer of a general format "must be neither signed nor zero unless explicitly allowed by the rules for that format" and no rule of §1985:VII.3.8 allows it. The witness runs the three formats and a bare RECORD VARYING with unequal bounds and reads the records back.

**Expected (from the 1985 text, the record's).** The program compiles, runs and displays OK. §1985:VII.3.8.2 Format 3 is RECORD CONTAINS integer-4 TO integer-5 CHARACTERS; the syntax rules of §1985:VII.3.8.3 speak of formats 1 and 2 only (SR3, "Integer-3 must be greater than integer-2.", is format 2's), and §1985:VII.3.8.4 GR14: "When format 3 of the RECORD clause is used, integer-4 and integer-5 refer to the minimum number of characters in the smallest size data record and the maximum number of characters in the largest size data record, respectively." The file's one record is 5 characters, so both are 5.

**Observed (the record's).** exit 65, no object program: repro-rec-equal.cob(10,12): error COBOL2009: file description entry 'F1': the RECORD CONTAINS clause states 5 TO 5; integer-5 shall be greater than integer-4 (ISO §2023:13.18.43.3 SR9). The second departure (under-rejects): the same program with line 10 written RECORD IS VARYING IN SIZE FROM 0 TO 5 CHARACTERS, or RECORD CONTAINS 0 TO 5 CHARACTERS, compiles with no diagnostic at 85 and displays OK.

**Fix direction (root cause, CLAUDE.md rule 4).** Give the RecordClauseRules table an edition column (its comment says every rule is present in all four editions, which the 1985 text contradicts) and the RecordClause classifier of IntegerOperandPass an edition arm for zero; a drift test pins each row to the editions whose text carries it.
