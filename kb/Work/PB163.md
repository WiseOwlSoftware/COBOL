# PB163

Found while building PB133 wave A's instance-restore golden: `01 LS-X GLOBAL PIC 9(4)` in a container's
LOCAL-STORAGE drew `COBOLNET1639: 'LS-X' is not defined` in the containee — on a plain non-recursive
container too, so this was a general registration gap, not a recursion composition issue.
§13.18.27.3 SR1b (cite-checked): "A data description entry whose level-number is 1 that is specified in
the file, working-storage, local-storage, or linkage section." `CallBindExternalAndGlobal` iterated
`workingStorageSection()` only.

**Fix:** the scan now iterates WS + LOCAL-STORAGE + LINKAGE entries; GLOBAL registers from all three,
EXTERNAL only from WS (§13.18.22.3 SR1: "level 1 data description entries in the working-storage
section" — an EXTERNAL clause outside WS keeps drawing nothing from this pass). The emit-side containment
bridge (`__outer`, §13.18.27 GR2) was already section-agnostic — instance fields either way — so
registration was the whole defect. Golden `2023/pb163_global_local_storage` (SEES=0007) pins the plain
shape; `2023/pb133_instance_restore` exercises the recursive-container LS case.

**Named residue:** (a) the 01/77 admission is looser than both SRs (each says level 1; a 77-level
GLOBAL/EXTERNAL clause is accepted and registered rather than screened at the clause site); (b) SR1b's
FILE-section leg — a level-1 record entry carrying its own GLOBAL clause under a non-GLOBAL FD — still
rides only the GLOBAL-FD path; (c) SR1a/SR1c (constant entries, screen entries). Each is a clause-site
screen belonging to the §13.18.27 checks, not this registration pass.
