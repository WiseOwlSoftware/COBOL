# PB1000 — LANDED

## Repro — measured
`scratchpad/w49c/pv.cob` (`>>TURN EC-ARGUMENT-FUNCTION CHECKING ON`): `01 NEAR-M1 PIC S9V9(20) VALUE
-0.99999999999999999999.` then `COMPUTE F2 = FUNCTION PRESENT-VALUE(NEAR-M1 AMT)` → **`abnormal run-unit termination:
EC-ARGUMENT-FUNCTION (fatal): PRESENT-VALUE argument-1 -1 is not greater than -1 (§15.74.3 r2)`**; the line after it
(`PV-NEAR-M1-RAN`) never prints. AR-15.74.3-2 is CONFORMS today on a witness that does not probe the boundary.

## The rule
`OK  §15.74.3 2)` — "The value of argument-1 shall be greater than –1." −0.99999999999999999999 is greater than −1.

## Code site
The domain screen compares a `double`; for a `table(ALL)` lead argument `IntrinsicRenderer.LeadThenTail` screens the
double of element 0. PB952's branch fixes the same artifact for ACOS/ASIN; this is the PRESENT-VALUE sibling in both
its scalar and its table(ALL) arm.

## What the fixer owes
Screen the argument's DECIMAL value, for the scalar and every table(ALL) element that becomes argument-1; re-verdict
AR-15.74.3-2 with a boundary golden (−0.99999999999999999999 runs, −1 raises).

## Landed — wave 58 group KA (branch `worktree-wf_d8a06e02-3d3-3`)
Re-probed on the worktree build first: the SCALAR arm no longer reproduced the refusal (PB952's `DomainScaled`
already screened the exact scaled rate: `pv.cob` printed `PV-NEAR-M1-RAN`), but it computed from the NARROWED rate —
the binary64 of −0.99999999999999999999 is −1.0, so the discount base `1 + rate` was 0 and the value ±∞ (the
§15.3 default 000.0000 without checking, a fatal "NaN result" with it). The table(ALL) arm still refused the rate:
`PRESENT-VALUE(R(ALL))` with R(1) = −0.99999999999999999999 → "argument-1 shall be greater than -1", because
`LeadThenTail` screened `DomainReal(__xs[0])`, the enumerated binary64.
Fix, at the one seam: (1) `CobolTable.AllArgs` takes an optional `lead` lambda that renders the FIRST element the
walk enumerates (argument-1 by §15.3 rule 14's left-to-right order; only the walk can name it, since an inner ALL
level may range over nothing at the first outer occurrence), and `IntrinsicRenderer.ArgArray`/`AllArgsExpr` pass
a leading argument's own intake to it, so the ALL lead is screened on the element's exact carrier through the ONE
screen. (2) Same root in the EVALUATION: PRESENT-VALUE's body now takes the DISCOUNT BASE — the renderer's
`PresentValueBase` hands `CobolIntrinsics.PresentValueBase(DomainDecAdmitted(exact rate))` (`CobolDec.Add` of 1 and
the exact rate, then narrowed; a float rate's own `1 + rate`, exact by Sterbenz) — so §15.74.4 r1 a)'s
`argument-2 / (1 + argument-1)` is approximated with binary64's relative error instead of divided by zero. The
standard-decimal twin `PresentValueDec` was already exact. Goldens: `85/pb1000_present_value_rate_near_minus_one`
(scalar, ALL lead, one-element ALL lead + written amount: all 100.0000; all 000.0000 before) and two ALL arms added
to `2002/pb952_argument_domain_bound_adjacent` (ALL lead −1 RAISED; ALL lead −0.999…9 silent). Unit
`TableAllLeadTests`. Batch `w58a/PB1000/batch.json` (witness-only on AR-15.74.3-2 and RV-15.74.4-1; GAP unchanged).
