# PB249

**Rows:** `AR-15.96.3-2`, `AR-15.96.3-3`

TRIM's argument-2 is modelled at ONE schema position where the format repeats it, and r3's antecedent — a syntactic condition BindTrim can decide — is decided at run time on an emptiness test.

ROWS: AR-15.96.3-2 (§15.96.3 r2 — 'argument-2 shall be a single character that is either class alphabetic or class alphanumeric') and AR-15.96.3-3 (§15.96.3 r3 — the no-argument-2 default).

HALF ONE — THE REPEATING ARGUMENT HAS ONE POSITION. TRIM is catalogued Variadic 1..inf (`IntrinsicCatalog.cs#Add "TRIM"`, MaxArgs == int.MaxValue) and §15.96.2 prints `[ argument-2 ] …`, so argument-2 REPEATS. `Schema()`'s tail parameter defaults to `'\0'`, so `ArgSchema.Tail` is null and `ArgSchema.At(i)` (`i < Positions.Length ? Positions[i] : Tail`) returns null for every i >= 2; `CrossViolation` iterates `schema.MatchedPositions()`, which yields only {0,1}. Positions 3, 4, … are ENTIRELY UNSCREENED: no class kind, no `ExactWidth(1)`, no `MatchArgument1`. `FUNCTION TRIM(X3 "A" "BC")` draws no diagnostic and reaches `CobolIntrinsics.Trim`, whose `c[0]` silently keeps 'B' and discards 'C'; `FUNCTION TRIM(X-item "A" N"X")` mixes the classes r2 forbids; a class-numeric third argument passes too. THIRD ESCAPE on the same screen: `PredicateViolation`'s ExactWidth arm is `when knownWidth is { } w && w != p.N`, so a NULL width falls to `_ => null` — `IntrinsicBinder.KnownWidth` returns null for `{IsAnyLength: true}` / `{IsDynamicLength: true}` items and for a computed-length ref-mod, so those argument-2s are width-unscreened even at position 1.

HALF TWO — r3's ANTECEDENT IS SYNTACTIC AND IS TESTED ON A VALUE. r3 fires 'When NO argument-2 IS SPECIFIED' — decidable at bind time, and `BindTrim` already knows `operands.Count`. `CobolIntrinsics.Text.cs:531-539` decides it at RUN time instead: `foreach (string c in chars) { if (c.Length == 0) continue; any = true; r = TrimOne(r, mode, c[0]); } return any ? r : TrimOne(r, mode, ' ');` — so r3's default is re-applied after every SPECIFIED argument-2 has been filtered away for being empty. Combined with the ExactWidth fail-open above, `FUNCTION TRIM(X DYN-ITEM)` over an ANY LENGTH / DYNAMIC LENGTH argument-2 currently holding the empty string binds clean, reaches the runtime with `chars = [""]`, and SILENTLY TRIMS SPACES — r3's default applied where r3's antecedent is FALSE. §15.3 rule 14 is explicit about what is owed instead ('If the evaluation of an argument results in an incorrect value for that argument … the EC-ARGUMENT-FUNCTION exception condition is set to exist'); nothing raises it. The same fallback is reached from the table(ALL) lane whenever the ALL enumerates zero elements.

WHAT IS RIGHT AND MUST NOT BE DISTURBED: r3's default VALUE is correct and pinned in both classes — the typed-native model stores a national item as UTF-16 one code unit per character position (`pb15_result_type_follows_argument.g.cs:15` stores PIC N(8) as an 8-char string padded with U+0020, :51 calls `Trim(W_NPAD, 0)`), so the national space IS U+0020 and r3.b needs no separate constant; a distinct national-space constant would be a second mechanism, not a fix. r3.a is pinned by `2023/intrinsics_trim`.

AR-15.96.3-2's OTHER half is CLOSED at HEAD and is carried in the stale-verdict note: the refuter found `FUNCTION TRIM(ALL T)` binding as ONE operand so `BindTrim`'s `if (operands.Count > 1 && DialectLevel < 2023) Error(COBOLNET1502)` never fired and the 2023-only argument-2 form was accepted at --std 2014; `IntrinsicBinder.cs:1025` now reads `if ((operands.Count > 1 || sawAll) && ctx.Edition.DialectLevel < 2023)` with the comment naming that exact hole.

FIX SHAPE: `tail: 's'` plus a tail `ExactWidth(1)` on the TRIM row (the ORD/ORD-MAX rows already use `WithTailPredicate`), `CrossViolation` extended to the tail positions, and r3 decided in `BindTrim` from `operands.Count` with a specified-but-empty argument-2 raising EC-ARGUMENT-FUNCTION instead of falling back to a space. Goldens: a two-argument-2 TRIM (there is currently no TRIM call site anywhere in tests/conformance with more than one), a class-mismatched argument-2 negative, and a DYNAMIC LENGTH empty argument-2.

VERIFIED LIVE AT HEAD (read-only): the TRIM schema row at :784-785 still has no `tail:`; `Text.cs:531-539`'s `any` fallback is present.

## Mechanism

src/Cobol.Net.Compiler/Binding/IntrinsicArgumentRules.cs:784-785 `["TRIM"] = Schema("§15.96.3 r1/r2", ['s','s'], cross: CrossArgRule.MatchArgument1, crossClause: "§15.96.3 r2").WithPredicate(1, ArgPredicate.ExactWidth(1, "§15.96.3 r2"))` — no `tail:`, where SUBSTITUTE at :791-793 has `tail: 's'`; ArgSchema.At returns `Tail` (null) for i>=2 and CrossViolation iterates `schema.MatchedPositions()` (length 2). Runtime half: src/Cobol.Net.Runtime/Intrinsics/CobolIntrinsics.Text.cs:531-539 (`bool any` … `return any ? r : TrimOne(r, mode, ' ')`)
