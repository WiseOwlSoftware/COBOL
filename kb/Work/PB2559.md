# PB2559 — R2's mechanical inputs, once

**Why (B4).** The first brief told every reviewer to "use the census and the LSP": eighty agents would each decide
whether to scan, and a clone family spanning two subsystems would be reported twice under two wave kinds, or by
nobody. Design §5.4 and the review skill put the mechanical checks first because they are free.

**What landed.** `scripts/arch/r2_inputs.py --pin <tree> --out <dir>` runs the semgrep invariants, a
`dotnet build -p:AnalysisLevel=latest-all` in a detached worktree of the pin, the drift-rule query per file and the
open-notes scan once (each step cached, so a re-run resumes), and writes `inputs/in-<shard>.json` per shard (its files,
those facts filtered to them, the census rows, the measured namespace edges), `inputs/in-duplication.json` (every
census clone family, each copy mapped to its shard; one family, one finding) and `inputs/perf.json` (the R0 baseline
and `perf_baseline.py --against`: a performance claim without a measurement is a lead, N3). A modern-C# finding is one
analyzer rule (`wave_kind: modernize`, `analyzer_rule`); a point without a rule id is a lead (N2).
`--batch <label> --shards <ids>` writes the batch's Workflow args. Self-test: `--self-test`.
