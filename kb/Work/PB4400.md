# PB4400 — the LANDING gate class outlives the landing gate

**Sites:** `scripts/gate_slot.py` (`CLASS_ENV`, `LANDING`, `GATE_CLASSES`, `_TICKET`, `gate_class_from_env`, `_ticket_name`, `_service_key`, `_tickets_ahead`, `self_test`), `scripts/self_test_arms.py` (`DECLARED`), `scripts/prune_worktrees.py` (`self_test`), `scripts/verdict_line.py` (`self_test`), `docs/rearchitecture/DESIGN-test-build-ci.md` (§3.14.6).

**What is dead.** Since PB4331 (step 8 of PB4323, landed in #991) `enqueue.py land` gates nothing, so nothing sets
`COBOL_GATE_CLASS=landing` any more. On main 10ae76f52 `grep -rn COBOL_GATE_CLASS scripts` finds it only inside
`gate_slot.py`. The class it selects therefore has no starter, and everything that serves it is dead:

- `scripts/gate_slot.py`: the module docstring (lines 27-31, the `classes` paragraph: "`enqueue.py land` starts, which
  sets COBOL_GATE_CLASS=landing"), the GATE CLASSES block (`CLASS_ENV`, `LANDING`, `GATE_CLASSES`, lines 104-110),
  `_TICKET`'s `-landing` suffix (line 396), `gate_class_from_env` (line 399), the ticket name (line 409), `_service_key`
  (line 412) and the docstrings that describe landing-first service (lines 582, 646, 670); the self-test arms
  `landing_first` (line 1044, registered at 1327) and the landing case at line 1311.
- `scripts/self_test_arms.py`, `gate_slot.py`'s DECLARED entry (from line 215): the arms "landing gates first ..." and
  "a waiting gate says why a later ticket is served first (landing before implementer) ...". (PB4395 moved
  GateSlotDriftTests' arms here.)
- `docs/rearchitecture/DESIGN-test-build-ci.md` section 3.14.6 "The gate cap" (line 1035 lists LANDING FIRST among the
  self-test's arms) and any text of section 3.14 that describes the landing class.

**Sibling (same root, cosmetic):** test data still plants `GATE RED (...)` landing outcomes that no landing writes:
`scripts/prune_worktrees.py:1832-1852` (the `lane-stopped` and `done-branch` attempts) and `scripts/verdict_line.py:87-99`.

**Fix.** One gate class: delete the class, its ticket suffix, the service-order key and the env read, with the self-test
arms, their DECLARED entries and the design text (the slot then serves tickets in order, which is what it already does for
every gate it sees). Replace the planted `GATE RED` outcomes with the outcomes the landing does write now (a refused tip,
exit 14; a queue bounce). Sweep `scripts/` and `docs/` for any other reader of `landing` as a gate class.
