# PB3026 — the tree holds sources; views are rendered

**From the owner's Q1b/Q3 decisions (kb/Work PB3015, 2026-10-11):** with one pull request per branch through a merge
queue, the queue is only as parallel as the landings' files are disjoint. A committed file that is REGENERATED by every
landing that touches its inputs (two PRs adding a drift test both rewrite `docs/DRIFT_RULES.md`) is a guaranteed
collision; a generated file nobody regenerates goes stale (the probe has printed "kb/Conformance burn-down is STALE —
run gen_conformance_notes.py" for days).

**Design:** `DESIGN-test-build-ci.md` §3.17.4 (second bullet).

## What changes
1. Inventory the generators (`grep -rl "Generated — do not hand-edit\|Generated - do not hand-edit\|do not hand-edit"
   docs kb scripts`): `drift_rules.py` → `docs/DRIFT_RULES.md`; `gen_conformance_notes.py` → the `kb/Conformance`
   burn-down; `gen_ledger.py` → `ledger.html` (already outside the tree, in `{COORD}`); any other.
2. Each generated OUTPUT is removed from the tree and gitignored; its generator gains `--check` (renders to a temp
   path, exits non-zero when the sources no longer render or when a tracked copy exists) and `--out` (render on demand).
   `kb/Work.base` is a view DEFINITION (an Obsidian base: a query over the notes) and stays tracked.
3. Readers move to the rendered path or to the generator: `DOC_INDEX.md`'s rows for the generated files say "rendered:
   `python <script> --out <path>`"; `session-probe.ps1` drops its STALE warning (nothing can be stale); skills and
   briefs that said "regenerate DRIFT_RULES.md and commit it" say nothing (there is nothing to commit); the lander's
   step that regenerated the index is gone with PB3023.
4. CI's `audits` job runs every generator's `--check` on `pull_request` and `merge_group`.
5. A drift test: `git ls-files` ∩ (every generator's output path) is empty.

**Not blocked.** Independent of the queue; reduces bounces once PB3024 lands.
