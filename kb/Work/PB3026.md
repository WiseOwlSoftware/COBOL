# PB3026 — the tree holds sources; views are rendered

**From the owner's Q1b/Q3 decisions (kb/Work PB3015, 2026-10-11):** with one pull request per branch through a merge
queue, the queue is only as parallel as the landings' files are disjoint. A committed file that is REGENERATED by every
landing that touches its inputs (two PRs adding a drift test both rewrite `docs/DRIFT_RULES.md`) is a guaranteed
collision; a generated file nobody regenerates goes stale (the probe has printed "kb/Conformance burn-down is STALE —
run gen_conformance_notes.py" for days).

**Design:** `DESIGN-test-build-ci.md` §3.17.4 (second bullet).

## What changes
1. Inventory the generators (`grep -rl "Generated — do not hand-edit\|Generated - do not hand-edit\|do not hand-edit"
   docs kb scripts`): `drift_rules.py` → `docs/DRIFT_RULES.md`; `gen_conformance_notes.py` → the `kb/Conformance`
   burn-down; `gen_ledger.py` → `ledger.html` (already outside the tree, in `{COORD}`); any other.
2. Each generated OUTPUT is removed from the tree and gitignored; its generator gains `--check` (renders to a temp
   path, exits non-zero when the sources no longer render or when a tracked copy exists) and `--out` (render on demand).
   `kb/Work.base` is a view DEFINITION (an Obsidian base: a query over the notes) and stays tracked.
3. Readers move to the rendered path or to the generator: `DOC_INDEX.md`'s rows for the generated files say "rendered:
   `python <script> --out <path>`"; `session-probe.ps1` drops its STALE warning (nothing can be stale); skills and
   briefs that said "regenerate DRIFT_RULES.md and commit it" say nothing (there is nothing to commit); the lander's
   step that regenerated the index is gone with PB3023.
4. CI's `audits` job runs every generator's `--check` on `pull_request` and `merge_group`.
5. A drift test: `git ls-files` ∩ (every generator's output path) is empty.

**Not blocked.** Independent of the queue; reduces bounces once PB3024 lands.
**Code sites:** `scripts/spec/drift_rules.py`, `scripts/spec/gen_conformance_notes.py`, `docs/DRIFT_RULES.md`, `kb/Conformance/`,
`.gitignore`, `docs/DOC_INDEX.md`, `scripts/session-probe.ps1`, `.github/workflows/build-and-test.yml` (audits).

## Landed

`scripts/rendered_views.py` is the ONE registry (`VIEWS`) of rendered views: `drift-rules` (`docs/DRIFT_RULES.md`),
`conformance-burn-down` (`kb/Conformance/`), `diagnostics` (`docs/DIAGNOSTICS.md`), `vault-reference` (`kb/Reference/`),
`grammar-diagrams` (`kb/Grammar/`) and `ledger` (the coordination directory). `docs/DRIFT_RULES.md` and
`docs/DIAGNOSTICS.md` left the tree (untracked, gitignored); the burn-down was already gitignored.
- Generators: `drift_rules.py` gained `--out` and its `--check` now only proves the index renders (every drift test
  states a rule); `gen_conformance_notes.py` gained `--out DIR` and renders in memory for `--check` (its on-disk
  comparison is gone: absent and stale no longer exist); `gen_ledger.py --check` renders in memory instead of comparing
  with the page in the coordination directory (the trend-point check was unwired and would be red after every landing);
  `DiagnosticRegistryDriftTests.DiagnosticsDoc_RendersTheWholeCatalogue` (renamed from `..._IsInSync_...`) proves one row per
  descriptor and writes the view under `WISEOWL_COBOL_WRITE_DIAGNOSTICS_DOC=1`.
- `rendered_views.py --check` enforces, per view, not tracked, gitignored, and renders; plus a sweep that no tracked
  `docs/`/`kb/` markdown declares itself generated without a row. It replaces the gate's `DRIFT RULES INDEX` audit and CI's
  drift-rule step; `RenderedViewsDriftTests` asks its `--tree` mode. `--self-test` runs under `scripts/self_tests.py`.
- Readers: the session probe RENDERS the burn-down every session (its STALE warning is gone), `build_inventory.py` no
  longer regenerates it, `phase_b_batch.py` refuses with the render command when the diagnostics table is absent.
- Kept tracked on purpose (DESIGN-test-build-ci.md section 3.17.4): generated SOURCE the build compiles, data extracted from
  the licensed standard, `kb/Work.base`, and the gating-status block embedded in `VERSION_CHANGE_REFERENCE.md`.

## Landing

Trap: `sed` replacement text containing `&` expands it; heredocs with backslashes are blocked, so write helper scripts with the Write tool.
- `scripts/spec/work.py#is_view_output` - reuse it when a check asks whether a named path exists (a rendered view is not in the committed tree).
- `scripts/spec/drift_rules.py` - `<path>` still answers which drift rules govern a file; the index is `--out <path>`.
- `scripts/spec/gen_conformance_notes.py#write_view` and `scripts/spec/gen_ledger.py` `--check` - render in memory; none compares with a copy on disk.
- `tests/WiseOwl.Cobol.Tests.Unit/DiagnosticRegistryDriftTests.cs#DiagnosticsDoc_RendersTheWholeCatalogue` - one row per descriptor; writes the view under `WISEOWL_COBOL_WRITE_DIAGNOSTICS_DOC=1`.
- Lead (not fixed): the VCR gating block embedded in `docs/VERSION_CHANGE_REFERENCE.md` (`VcrDriftTests.GeneratedStatusIndex_IsInSync`) is still a generated region of a tracked document.
