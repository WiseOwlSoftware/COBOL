# PB3584 — one scratch-repository fixture per self-test, each with its own git helper

**Sites:** a new shared fixture module `scripts/scratch_repo.py` (one git helper, one scratch-repository builder), and the self-tests of `scripts/devlog.py`, `scripts/gate_slot.py`, `scripts/line_endings.py`, `scripts/rendered_views.py`, `scripts/run_gate_legs.py`, `scripts/self_test_inputs.py`, `scripts/self_tests.py`, `scripts/prune_worktrees.py`, `scripts/orchestrator/enqueue.py`, `scripts/orchestrator/land_lane.py`, `scripts/orchestrator/landing_check.py`, `scripts/orchestrator/test_checkpoint.py`, `scripts/orchestrator/test_ledger_state.py`, `scripts/orchestrator/test_plan_wave.py`, `scripts/hooks/status_guard.py`; a new drift test `tests/Cobol.Net.Tests.Unit/SelfTestFixtureDriftTests.cs`.

## Found

Fifteen scripts `git init` a scratch repository in their self-test (`devlog.py`, `gate_slot.py`, `line_endings.py`,
`rendered_views.py`, `run_gate_legs.py`, `self_test_inputs.py`, `self_tests.py`, `orchestrator/enqueue.py`,
`orchestrator/land_lane.py`, `orchestrator/landing_check.py`, `orchestrator/test_checkpoint.py`,
`orchestrator/test_ledger_state.py`, `orchestrator/test_plan_wave.py`, `hooks/status_guard.py`, `linux-gate.sh`), and
seven of them define a local git helper of their own (`devlog.py` `sh`, `prune_worktrees.py` `g`, `rendered_views.py`
`git`, `run_gate_legs.py` two, `enqueue.py` `sh`, `landing_check.py` `sh`, `test_plan_wave.py` `git`).

## The divergence

Change how a self-test drives git in one place (an identity, `maintenance.auto=false` and `gc.auto=0` so a commit loop
spawns no `git maintenance`, a `--quiet`, an initial branch name) and the other helpers keep the old behavior. Measured:
run outside `self_tests.py` (which supplies a private global config with auto-maintenance off), the
`prune_worktrees.py` self-test spawned 74 `git maintenance` processes. And each self-test pays its repository's
construction (init, commits, a bare origin, worktrees) in git processes every run, which is PB3582's cost on Windows.

## The fix (a design, for the implementer)

One shared fixture module, `scripts/scratch_repo.py` (one git helper; one `ScratchRepo` that builds a repository with an origin,
branches and worktrees from a declarative description), every self-test above moved onto it and its local helper
deleted in the same change (CLAUDE.md rule 4: no forwarders). Where a self-test builds the same repository for many
cases, build it once and copy the directory per case (a file copy, no git processes) instead of replaying the commits.
A drift test, `tests/Cobol.Net.Tests.Unit/SelfTestFixtureDriftTests.cs`, refuses a new local git helper in a self-test.

## Landing (wave 20261025, group A)

**Re-probe.** The fixture's own audit (`python scripts/scratch_repo.py --audit`, below) found 65 places on the base
tree (5e20e0801) in 19 files: the note's fifteen less `self_test_inputs.py` (its `"init"` is a set of git subcommand
names, not a repository; no scratch repository) and less `linux-gate.sh` (shell: it clones, it cannot import a Python
fixture), plus five siblings the note had not listed: `arch/file_census_notes.py` (`stage`), `arch/member_index.py`,
`arch/r2_subsystems.py`, `spec/audit_evidence_supersession.py` and `spec/gen_ledger.py`. Two more copies of the
fixture's rules: `gate_slot.drop_git_local_env` (also called by `run_gate_legs.py`) and `self_tests.py`'s own
`_git_local_env_vars`/`_scrubbed_env` and `GIT_IDENTITY`/`GIT_NO_AUTO_MAINTENANCE`.

**The fix.** `scripts/scratch_repo.py`: `ScratchRepo` (`init`, `clone`, `origin`, `worktree`, `run` unchecked, `git`
checked, `write`, `commit`, a `when` that dates a commit, per-object `-c` options), `config_text`, `scrubbed_env`,
`isolate`, and the constants `IDENTITY`, `NO_AUTO_MAINTENANCE` (its measurement moved here from self_tests.py) and
`REPO_CONFIG`. `init`/`clone` append the identity, `maintenance.auto=false`, `gc.auto=0` and no signing to the new
repository's OWN config (no extra git process), so the code under test's git commands get them too, run by hand or by
the runner. Every site above moved onto it and its helper deleted; `drop_git_local_env` and the runner's copies deleted,
the runner's private global config written from the fixture's constants through `config_text`. Two self-tests that
leaked their temp directory (`test_checkpoint.py`, `test_ledger_state.py`) now remove it. The declarative builder the
design sketched was not needed: every self-test's repository is a few `init`/`commit`/`worktree` calls on the object.
Build-once-and-copy has no site: no self-test builds the same repository for more than one case (devlog's and
landing_check's cases branch inside one repository; gate_slot's two `make_repo` calls differ in their settings).

**The audit and the drift test.** `scratch_repo.py --audit` reads every self-test's syntax tree (a function named for a
self-test, a standalone `test_*.py`): SPAWN (a `subprocess` call whose argv is a git argv or a name bound to one), INIT
(a repository created around the fixture; also read in top-level functions only self-test code reaches) and HELPER (a
nested helper over the module's own git runner); GREEN on the tree. `SelfTestFixtureDriftTests` runs it, holds the
fixture self-test's arms from source, adds a text net (`"git"` and `"init"` on one line) and holds the fixture's rules
(`--local-env-vars`, the identity, the maintenance tuple) to that one file.

**For the next implementer.**
- `scripts/scratch_repo.py#ScratchRepo`: the one place a self-test's git starts. REUSE `init`, `clone`, `origin`,
  `worktree`, `commit(when=)`, `git`, `run`; never `subprocess.run(["git", ...])` in a self-test (the audit refuses it);
  call `isolate()` first when the code under test runs git in the same process.
- `scripts/scratch_repo.py#audit`: its scope is functions named `*self_test*` and standalone `test_*.py`; a git argv that
  is only data is no spawn (only a `subprocess` call's argv counts). Trap: a regex rename of `run(` also hits
  `subprocess.run(`.
- `scripts/self_tests.py#private_git_config`: written from `scratch_repo.IDENTITY`/`NO_AUTO_MAINTENANCE` through
  `config_text`; change the settings in the fixture, never here.
- `tests/Cobol.Net.Tests.Unit/SelfTestFixtureDriftTests.cs`: runs `--audit`. A design-doc section in a C# comment is
  "section 3.14.10", never the section sign (the code-citation audit reads it as an ISO clause).
