# PB1720 — PB1708 pivot M2

Filed by the orchestrator from the PB1708 pivot design (workflow wf_08642598-d3c, reviewed APPROVE_WITH_CHANGES, all eleven findings resolved by the reviser), 2026-09-28.
## Mechanism (`docs/rearchitecture/DESIGN-test-build-ci.md` section 3.14.6, section 3.14.9 row M2)

`scripts/gate_slot.py` is a ticketed FIFO counting semaphore under `<git common dir>`, with a `--self-test`. A slot is
released when its holder dies, and an orphaned process tree is killed (a Windows Job object, or Linux flock). An
implementer gate takes a slot before it builds. The lander, the battery and CI never wait. The cap retires on the
measured criterion recorded in PB1708.

## Acceptance

- The self-test's five arms pass, FIFO order included.
- N is measured as the largest value that keeps the lander's whole-Conformance leg within 1.25x of its quiet time,
  with N implementer gates running and their builds included.

Independent of the other mechanisms. It lands in the same train as M13 (PB1721), so no implementer runs an uncapped
whole-population gate.

## Landed in part (wave 71 group E, 2026-09-28): the tool, its self-test and its doc; N is still provisional

`scripts/gate_slot.py` implements DESIGN-test-build-ci.md section 3.14.6 as written: N slot locks and a ticketed FIFO
queue under `<git common dir>/cobol-gate-slots/`, a `GateSlots.acquire(label)` API and a `run -- <command>` CLI for
callers, `status`, and the process-tree rule (a kill-on-close Job object on Windows; the inherited flock descriptor
on Linux, handed to every child through `Slot.spawn_kwargs`). `--self-test` passes its five arms on Windows and under
WSL (python 3.12, git 2.55), and each arm was seen RED on a planted defect: no ticket check (served W2, W1, H-again,
W3), a ticket file counted live while unlocked (the queue never drained), no Job object (the orphaned child and
grandchild survived), the descriptor withheld from Linux children (the orphans ran outside the cap), and
`--git-dir` in place of `--git-common-dir` (two worktrees, two caps). `GateSlotDriftTests` (Unit) runs it in every
Unit run, including CI's Linux unit jobs.

**Still open: the measurement of N.** The acceptance wants the largest N that keeps the lander's whole-Conformance
leg within 1.25x of its quiet time with N implementer gates running, builds included. That needs a quiet host. On
2026-09-28 at 21:50 PDT the shared 32-core host was running wave 71's other implementers (18 dotnet, testhost,
MSBuild and VBCSCompiler processes), so the tool ships `DEFAULT_SLOTS = 2` as the PROVISIONAL value. The measurement
is the NEXT step for M13's train (PB1721), once the slot is wired into `build-local`: a quiet lander leg first, then
the same leg against 1, 2 and 3 concurrent `-Mode implementer` gates, recording each wall time and the host load
beside it. That measurement sets `DEFAULT_SLOTS` and closes this note.

## Landing

- `scripts/gate_slot.py#GateSlots.acquire`: owns the cap. A Python caller uses `GateSlots.for_repo().acquire(label)`
  (a `with` block) and spawns EVERY child with `**slot.spawn_kwargs()`, or Linux orphans escape the cap. A shell
  caller uses `gate_slot.py run --label TEXT -- <cmd>`. Print `slot.describe()` on the verdict line. Trap: all ticket
  file opens and unlinks must stay under `tickets.lock` (a ticket probed between its creation and its lock reads as
  dead).
- `scripts/gate_slot.py#self_test`: every helper loops only while the `alive` sentinel exists, and children run with
  a cwd OUTSIDE the temp root; without both, a red arm leaks spinning processes and Windows cannot delete the root.
  git writes read-only objects, which the cleanup must chmod before `rmtree`.
- `tests/Cobol.Net.Tests.Unit/GateSlotDriftTests.cs`: pins the five arm names. Rename an arm in both places.
- `scripts/gate_slot.py#DEFAULT_SLOTS` is 1, MEASURED (evidence `m13`). To re-measure, run
  `docs/rearchitecture/evidence/impact-map-pb1708/m13-measure-n.py` with three pre-built detached worktrees. Every gate
  runs cold and the lander at Normal. The 1.25x rule is the lander's whole-Conformance wall from `verdict.json`.

## Landed (wave 72 group H, 2026-09-29): N measured, `DEFAULT_SLOTS = 1`

The measurement (evidence `impact-map-pb1708/m13`, script `m13-measure-n.py`) ran on the shared 32-core host with
the rest of the fleet idle. Every gate was cold (`COBOLNET_COMPILE_CACHE=off`, as after a compiler change). Each
implementer ran in its own worktree, with a compiler source touched so it rebuilt, at BelowNormal with
`COBOLNET_GATE_SLOTS=3` so none queued. The lander ran `-Mode lander` at Normal. The measured quantity was the
lander's whole-Conformance leg from its `verdict.json`; the implementers started with it, builds included.

| run | implementer gates | Conformance s | vs that round's quiet |
|---|---|---|---|
| quiet-a / quiet-b / quiet-c | 0 | 143.1 / 135.8 / 133.6 | — |
| n1 / n1-r2 | 1 | 172.8 / 173.5 | 1.24x / 1.30x |
| n2 / n2-r2 | 2 | 220.6 / 202.7 | 1.58x / 1.52x |
| n3 / n3-r2 | 3 | 192.2 / 207.7 | 1.38x / 1.56x |

Two implementer gates are far over the 1.25x line, and one is at it: 1.26x on the pooled quiet time in both rounds.
N cannot be 0, so `scripts/gate_slot.py` `DEFAULT_SLOTS = 1`, and the provisional note is gone. The n3 row is not
three gates: its m3 stopped after 0.9 s on a transient MSB4024 access denial (kb/Work PB1729's mechanism).
**Consequence:** implementer gates now run one at a time, repository-wide. A cold implementer gate measured 281–449 s
under load, so a wave of seven can queue a gate for over half an hour. The cap's retirement criterion (DESIGN section
3.14.6) is unchanged.
