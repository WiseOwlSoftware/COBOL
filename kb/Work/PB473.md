# PB473 — LANDED — the third arm of the evidence rules was never written

Found 2026-09-04 attributing battery #43's single red. Every citation below was re-run on this tree; the code
sites were re-read, not inherited.

## What happened

Battery #43 (worktree at `d908a749`) reported `IF141A: DIFF — REGRESSION!` — 352 MATCH, 1 REGRESSION, and one
NIST-audit finding (`unexpected=1`). PB383 was the standing suspect because IF141A is an intrinsic-function
program and PB383 rewrote the intrinsic guards' zero-length substitutes in the same window.

**There is no output difference.** Battery #43's own compiled binary survived in the worktree
(`tests/nist/output/IF141A.dll`, `compile.rc=0`, Sep 4 16:39; `guard-fast.sh` clears that directory only at the
start of a run). Run in a clean directory with the same `CobolSharp.Runtime.dll` and `COBOL_SWITCH_1=ON`, it
produces a 2001-byte report that is **byte-identical** to `tests/nist/valid/IF141A.txt` — 65 runs out of 65,
including 64 at `-P32`.

## The mechanism

`scripts/guard-run-group.sh:100-117` (mirrored at `scripts/guard.sh:247-270`) decided MATCH by three
`diff <(normalize …) <(normalize …)` comparisons and treated **every** non-zero exit as "not this file". Four
distinct ways of failing to observe anything therefore arrived at the same `else`:

| what happened | what the guard said |
|---|---|
| report absent, run rc=0 (`normalize()`, `:51`, returns silently empty) | `DIFF — REGRESSION!` |
| report truncated, run rc=0 | `DIFF — REGRESSION!` |
| `diff` exits 2 (trouble) — its stderr goes to `/dev/null` on `:101-103` | `DIFF — REGRESSION!` |
| a `<(…)` process substitution delivers short data | `DIFF — REGRESSION!` |
| the program printed a genuinely wrong answer | `DIFF — REGRESSION!` |

Made to fail once, with the compare block verbatim
(`$SCRATCH/battery-43/if141a/compare-arm-hole.sh`):

```
A absent-report    rc=0 -> IF141A: DIFF — REGRESSION!
B truncated-report rc=0 -> IF141A: DIFF — REGRESSION!
C correct-report   rc=0 -> IF141A: MATCH
```

## Reproduced, at the battery's own fan-out

The guard's group loop for IF141A — same `mktemp -d`, same `timeout -k 5 120 dotnet`, same three-way compare —
run 640 times at `-P32` (`$SCRATCH/battery-43/if141a/group-sim.sh`):

```
r260 FAIL rrc=1 size=2001 IDENTICAL-TO-GOLDEN differr=[]
```

* the report is complete and, by `cmp` **in the same shell, immediately after the three diffs failed**, equal
  to the golden byte for byte;
* `diff` printed nothing on stderr — it reported a *difference*, from input that had none;
* `rrc=1`: in the same iteration the run's exit status was corrupted too, with an empty stderr file.

**1 in 640.** Battery #43 ran 332 groups over 376 programs at the same fan-out: **1 in 376.** The concurrent
`dotnet` load is necessary: the compare alone, hammered 3000 times at `-P32` with nothing else running, never
failed (3000 OK / 0 FAIL) — which is why this had never been caught outside a battery.

## The sibling hole — two arms, one fixed (third occurrence)

`rrc != 0` with an **empty** `$errfile` was scored `DIFF — REGRESSION! (run exited 1: )` at `:114`. The COMPILE
arm refuses that shape at `:64` — *"rc=$crc with NO diagnostic — a rejection with no reason is a lost result"* →
NO-VERDICT. The RUN arm scored it. Plan §11 A12b hardened compile and run against "a missing observation read as
a negative one" and left the COMPARE arm untouched; `:114` shows the run arm was only half-hardened as well.

## Why the answer is not a re-baseline

`tests/nist/programs/IF141A.cob:7` — the program tests `FUNCTION VARIANCE` and nothing else, so §15.98 governs
the whole file.

```
python scripts/spec/cite.py --check 15.98.3 "Argument-1 shall be of class numeric"
OK  §15.98.3 1)  (Argument rule)
python scripts/spec/cite.py --check 15.98.4 "For n occurrences of argument-1"
OK  §15.98.4 1) c)  (Returned value rules)
python scripts/spec/cite.py --check 15.60.4 "For n occurrences of argument-1"
OK  §15.60.4 1) c)  (Returned value rule)
python scripts/spec/cite.py --check 15.3 "the EC-ARGUMENT-FUNCTION exception condition is set to exist"
OK  §15.3 14)  (Arguments)
```

§15.98.3 r1 is the function's only argument rule and every argument in the program is numeric, so §15.3 r14
never engages — the program cannot reach the substituted-value machinery PB383 rewrote. §15.98.4 r1 c) divides
by *n*: `VARIANCE(5, -2, -14, 0)` = 194.75/4 = **48.6875**, inside the program's `48.6865 … 48.6885` window
(`IF141A.cob:355-356`); `VARIANCE(10.2, -0.2, 5.6, -15.6)` = 378.80/4 = **94.70**, inside `94.6981 … 94.7019`
(`:430-431`). The ÷(n−1) sample form gives 64.9167 and 126.2667 — outside both. Golden, spec and compiler agree.

## PB383 is excluded

Structurally: PB383's `src/` footprint is entirely `src/Cobol.Net.Runtime/`
(`Exceptions/ExceptionState.cs`, `Intrinsics/CobolDate.cs`, `Intrinsics/CobolIntrinsics.Text.cs`), and the legacy
guard's closure — `CobolSharp.CLI → CobolSharp.Compiler → {CobolSharp.Runtime, Cobol.Net.Frontend →
Cobol.Net.Editions}` — does not contain that assembly:
`ls src/CobolSharp.CLI/bin/Debug/net10.0/` has no `Cobol.Net.Runtime.dll`.
By subject: no NIST program references BOOLEAN-OF-INTEGER, BASECONVERT, SUBSTITUTE, FORMATTED-DATE,
FORMATTED-DATETIME or the LOCALE family (measured with `grep -rl` over `tests/nist/programs/`).
PB386 and the four data-only commits in the window touch no compiler code, and `tests/nist/` has not changed
since `e4d1b449`.

## `inventory_rows` — none claimed, and why

This is a harness defect; it owns no spec rule and its fix re-verdicts no row. The §15.98 rows IF141A exercises
(`AR-15.98.3-1` CONFORMS, `RV-15.98.4-1` PARTIAL/GAP, `FMT-15.98.2` CONFORMS) are named here as context only —
claiming them would attach a measurement defect to rules that are not in question, and `RV-15.98.4-1`'s GAP is
PB56's decimal-carrier work, unrelated. The GAP does not move.

`process_only: true`, `wrong_answer: false` — no user program produces a wrong answer from this. The harm is to
the gate: it can convert a green run into a red one (this happened, and cost a battery), and by the same
plumbing it can lose a real regression into a NO-VERDICT that the current code would have to re-observe. It is
MAJOR because the battery is the project's merge gate and its verdicts must be evidence.

## Fix shape

1. `:101-103` — read `diff`'s exit status: `0` match, `1` real difference, **anything else NO-VERDICT**; route
   `diff`'s stderr to the group error channel instead of `/dev/null`.
2. `:51` — all three candidates absent or zero-length ⇒ `RUN NO-VERDICT (produced no report)`. A wrong answer
   has bytes.
3. `:114` — align with `:64`: `rrc != 0` with an empty `$errfile` is a NO-VERDICT, not a REGRESSION.
4. `:38` — on any non-MATCH, preserve `$WORK` (report, stdout, stderr) into a run-scoped forensic directory
   before the trap fires.
5. Let `guard-fast.sh`'s existing step-3b re-observe the resulting NO-VERDICTs serially — no new retry
   mechanism.
6. Apply all of it to `scripts/guard.sh:247-270` in the same change set; `scripts/guard-verify.sh` proves the
   two equivalent by diffing exactly these lines.
7. Witnesses in `guard-verify.sh`, each failing once before the fix: report-absent → NO-VERDICT;
   `diff` forced to exit 2 → NO-VERDICT; **genuinely wrong report → REGRESSION** (the discriminator, without
   which the fix could turn every regression into a NO-VERDICT and still look green); `rrc!=0` with empty
   stderr → NO-VERDICT vs. with stderr → REGRESSION.

⛔ Do **not** add IF141A to `LEGACY_DIVERGENT`, re-baseline `tests/nist/valid/IF141A.txt`, or label it flaky.
The output is correct, the golden is correct, and the corpus row stays `green`.

## Landed 2026-09-04

All seven contract items, plus the two the implementation proved necessary.

**The rules moved to ONE file first.** Items 1–3 are ~25 lines of nuanced logic that had to be identical in two
scripts whose only bond was a comment claiming they were "kept character-for-character in step" — a claim that
was already false (`guard-run-group.sh`'s `normalize()` carried a `[ -f ]` guard `guard.sh`'s did not) and that
had kept BOTH copies of every hole above. `scripts/guard-verdict.sh` is now THE implementation
(`guard_compile_verdict` · `guard_output_verdict` · `guard_preserve`), sourced by `scripts/guard.sh` and
`scripts/guard-run-group.sh`; they keep only their own plumbing (where the files live, `echo` vs the recording
`v()`, the `FAILURES` counter). `feedback_one_rule_one_place`, and CLAUDE.md rule 5's "prefer the shape that
makes the NEXT case automatic".

**And the compare's root cause was removed, not merely detected** (rule 4). Item 1 makes a `diff` that *cannot
tell* stop being a *difference*, but the failure this note reproduces had `diff` exiting **1** with an empty
stderr, from input that was identical — a short delivery over the `<(…)` process substitution, which this
bash implements over `/dev/fd/63`. So the normalized sides are now MATERIALIZED INTO REAL FILES whose writes
have completed before `diff` opens them, and the normalization pipeline's own exit status is checked
(`-o pipefail`). Exit-status discrimination is defence in depth on top of that. The sweep found one more
process substitution in a verdict path — `guard-fast.sh:174`'s `comm -23 "$POP" <(…)`, where a short read
would have SHRUNK the set of lost results to re-observe — and it is a real file now too. A drift check in
`guard-verify.sh` fails on any `diff <(…)` / `comm … <(…)` in these four scripts.

**Witnesses** (`scripts/guard-verify.sh`, now check (1) of two; `--witnesses` runs just them, seconds). 21
synthetic cases drive the REAL `guard-run-group.sh` over a fake repo root with `dotnet` and `diff` shims on
`PATH`. Six were proved RED against the pre-fix runner first
(`GUARD_GROUP_RUNNER=<old copy> bash scripts/guard-verify.sh --witnesses`, `git show 80c87970:`):

```
  WITNESS FAILED: a report that never appeared is NOT a regression      got: WT001A: DIFF — REGRESSION!
  WITNESS FAILED: a 0-byte report is NOT a regression                   got: WT001A: DIFF — REGRESSION!
  WITNESS FAILED: diff itself failing (exit 2) is NOT a regression      got: WT001A: DIFF — REGRESSION!
  WITNESS FAILED: diff failing on a WRONG report is also NOT a regression  got: WT001A: DIFF — REGRESSION!
  WITNESS FAILED: rc!=0 with an EMPTY stderr is NOT a regression        got: WT001A: DIFF — REGRESSION! (run exited 1: )
  WITNESS FAILED: a non-MATCH preserved no evidence in .../forensics
```

and the same six, plus the two structural checks and the four controls, green afterwards:

```
  ok: control: a correct report is a MATCH
  ok: discriminator: a genuinely wrong report is a REGRESSION
  ok: a report that never appeared is NOT a regression
  ok: diff itself failing (exit 2) is NOT a regression
  ok: rc!=0 with an EMPTY stderr is NOT a regression
  ok: a non-MATCH preserves its report, its streams and both normalized sides
  ok: no verdict-bearing comparison reads through a process substitution
=== (1) WITNESSES: ALL GREEN — every evidence rule proved on the real group runner ===
```

The controls are the point: without "a genuinely wrong report is a REGRESSION" the fix could have turned every
regression into a NO-VERDICT and still looked green.

**Two things the contract did not anticipate.** (a) `guard-verify.sh` now runs the witnesses FIRST and SKIPS the
equivalence proof when they fail — two guards agreeing about a rule that is WRONG is not evidence, and that is
precisely the state in which this defect survived thirteen months of green equivalence runs. (b) `guard-fast.sh`
had no `GUARD_TESTS` subset override, though `guard.sh` has had one; the gate for this change wants the same
subset through both arms, so it has one now, with the same "a subset is not the regression gate" warning.

**Proof.** `bash scripts/guard-verify.sh` in full — the witnesses, then BOTH guards over all 376 programs:

directory exists after a green run.
