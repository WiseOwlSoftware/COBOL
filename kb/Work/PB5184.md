# PB5184 - INSPECT evaluates a function-identifier in the REPLACING half of a format 3 statement after the TALLYING half has run: PlaceIdentification.Freeze returns a non-field operand unchanged and EmitBody renders it inline

**Sites:**

- `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/InspectEmitter.cs` (`IdentifyOperands`, `EmitBody`, `OperandTextOf`)
- `src/WiseOwl.Cobol.Compiler/CodeGen/Roslyn/PlaceIdentification.cs` (`Freeze`)

**Mechanism.** §1985:VI.6.18.4 GR5 evaluates every subscript and function-identifier once, as the first operation of the INSPECT. `InspectEmitter.IdentifyOperands` freezes every data-item operand and `TallyOperandTexts` every TALLYING function-identifier, but `PlaceIdentification.Freeze` returns a non-field operand unchanged, so a function-identifier in the REPLACING half is rendered inline by `EmitBody` / `OperandTextOf` in the InspectReplace call, after the tally has changed the subscript it reads. FUNCTION ... (I) then sees the tallied I: the program prints 3 XAXZ at --std 85 and at --std 2023.

**Found by.** The 1985 code read (2026-11-10; its records are `E:/COBOL-coord/scratch/coderead-85/for-register.json`): each rule below was read against the code sites it names and probed at `--std 85`, and found non-conforming. Verdict, harm, evidence, repro and observed text are the records'; the rows' verdicts are recorded on another branch.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids of the list below.

Checked: §1985:VI.6.18.4 GR5: "If any identifier is subscripted or is a function-identifier, the subscript or function-identifier is evaluated only once as the first operation in the execution of the INSPECT statement.". Code sites read: src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/InspectEmitter.cs#Emit; src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/InspectEmitter.cs#IdentifyOperands; src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/InspectEmitter.cs#TallyOperandTexts; src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/InspectEmitter.cs#EmitBody; src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/InspectEmitter.cs#OperandTextOf; src/WiseOwl.Cobol.Compiler/CodeGen/Roslyn/PlaceIdentification.cs#Freeze. Code read: §1985:VI.6.18.4 GR5 (ALL FORMATS, as Amendment 1 words it): 'If any identifier is subscripted or is a function-identifier, the subscript or function-identifier is evaluated only once as the first operation in the execution of the INSPECT statement.' No edition arm: every edition runs InspectEmitter.Emit, whose first act is IdentifyOperands, which freezes the subscripts (and reference modifiers) of identifier-1, each TALLYING counter, pattern and BEFORE/AFTER delimiter, each REPLACING pattern, replacement and delimiter and the CONVERTING operands into locals, in source order, through PlaceIdentification.Freeze; TallyOperandTexts evaluates each TALLYING function-identifier once into a local before any counter is stored. Conforms for: a subscript on every data-item operand class in formats 1 to 4 (probes: counter as subscript of identifier-1, of a pattern, of a delimiter, of a format 3 REPLACING operand, relative subscript), and a function-identifier in TALLYING or as identifier-1 (the witness: COUNTER, SUBJECT, OPERAND, FUNCTION lines). Does NOT conform for a function-identifier in the REPLACING half of a format 3 statement: PlaceIdentification.Freeze returns a non-field operand unchanged, and EmitBody renders it (OperandTextOf) inline in the InspectReplace call, after the TALLYING counters are stored, so the function and the subscripts of its arguments are evaluated after the format 1 half ran. Freeze's comment that a function's argument subscripts 'were hoisted at bind time' holds only for a function-bearing subscript (StatementBinder.SubscriptSegments), not for a plain subscript on an argument. The result is wrong on either reading of format 3: GR5 puts the function first in 'the INSPECT statement', and §1985:VI.6.18.4 GR17 ('as though two successive INSPECT statements') still requires 'Subscripting associated with any identifier in the format 2 statement is evaluated only once before executing the format 1 statement'. A function whose unsubscripted argument the counter changes (C1 REDEFINES X1; TALLYING C1 ... REPLACING ALL FUNCTION UPPER-CASE (X1)) is read after the tally too: right on the two-statement reading of GR17, wrong on GR5's own wording; the repro avoids that doubt. --std 2023 prints the same, where §2023:14.9.22.4 GR19 ('Item identification of any identifier in the format 2 statement is done only once before executing the format 1 statement') leaves no doubt: a lead against the 2023 rows GR-14.9.22.4-6 and GR-14.9.22.4-19. The occurs-depending length of a format 3 identifier-1 is not this rule (GR5 names subscripts and function-identifiers only); it is GR17's and is kb/Work PB5119.

**Fix direction (root cause, CLAUDE.md rule 4).** Freeze every operand, field or function result, in IdentifyOperands through one rule (a function result is a value, frozen into a local like a subscript), so no operand of any phrase is evaluated after the first operation.
