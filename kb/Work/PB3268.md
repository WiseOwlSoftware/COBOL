# PB3268 — FunctionValuePic holds a NUMERIC function's value at scale 9

Source: `E:\COBOL-coord\scratch\reports\w1084g-PB651-report.md`, "New defects" L1 (implementer's, unchanged; carried unchanged in `w1093d-PB651-report.md`). PB651's own note records it as a lead at lines 94-100 and does not fix it.

**Mechanism.** The §15.4 temporary of a NUMERIC function is a fixed PIC at scale 9 (`SendingValueTemp.FunctionValuePic`, `src/Cobol.Net.Compiler/Binding/Procedure/SendingValueTemp.cs:88`). The value is truncated to that scale before the receiver sees it, so a receiver with more than 9 fraction digits gets zeros past scale 9.

**Repro.** `E:\COBOL-coord\scratch\w1084\w1084g\multi.cbl`: `MOVE FUNCTION PI TO Q1 Q2` stores 3.141592653000000; per PB651, `MOVE FUNCTION PI TO Q3` stores 3.141592653589793 (also SQRT, MEAN, NUMVAL into a receiver past scale 9; STRICT, PIC 9V9(15)).

**Fix shape (the report's).** A carrier-faithful temporary: the temporary holds the value on the carrier the renderer chooses. PB651 notes that carrier is decided in codegen while the temporary is described at bind, so this crosses the bind/codegen boundary. The ISO clause must be derived and checked (`python scripts/spec/cite.py --check`) by the implementer before any code comment cites it; `spec_refs` carries PB651's stated section, unverified here.

Related landed notes that name the same field: PB1890 (subscript-segment temporary at `StatementBinder.SubscriptSegments.cs:72`), PB425, PB923.


## Landed

**Re-probe (own build, 2026-10-16).** `MOVE FUNCTION PI TO Q1 Q2` (PIC 9V9(15)) stored 3141592653000000 in both and
3141592653589793 in the single-receiver control Q3; the note's mechanism was right and wider than its title: the same
intermediate also (a) gave a COMP-2 receiver beside another 3.141592653 (`MOVE FUNCTION PI TO F1 F2`), (b) kept 21
integer digits (`MOVE FUNCTION NUMVAL("1234567890123456789012345") TO B1 B2` with `PIC 9(25)` stored
0000567890123456789012345 in both), and (c) compared an EVALUATE subject at nine places
(`EVALUATE FUNCTION PI WHEN 3.141592653 WHEN 3.14159265358979` took the first WHEN). One root, four symptoms: the
statement-level intermediate was the returned-value item's S9(21)V9(9).

**Root cause.** `SendingValueTemp` used ONE description, `FunctionValuePic`, for two different items. DOC-A.1-92 fixes the
§15.4 returned-value ITEM as S9(21)V9(9) for the questions asked OF the item (`FUNCTION LENGTH`, IN-ARITHMETIC-RANGE,
`NumericReturnedValuePic`); §14.9.25.4 GR1's `temp` is a different item, "an intermediate result item provided by the
implementor", whose only job is to give every receiver the value `MOVE a TO that receiver` gives (and §15.4.1 makes the
returned value "the same for all instances of a given function").

**Fix.** `SendingValueTemp.IntermediatePic` describes the intermediate for the value and its use
(`SendingValueTemp.ValueUse`): an INTEGER function stays S9(30) scale 0; the §15.4.1 float family under NATIVE arithmetic
(`IntrinsicSig.Float`, mode not a decimal engine, the renderer's own dispatch read at bind) and any function whose
receivers are all floating-point items are held on a COMP-2 item, so the store into the intermediate quantizes nothing and
each receiver's own float landing (`ReceiverContext.FloatLanding`) quantizes once at its own scale; every other function is
held in the WIDEST receiver's fixed-point description (`ValueUse.MovedTo`: scale and integer digits from
`PicInfo.ReceiverScale` / `DigitPositions`, a floating-point receiver asking 21 + 17, a character receiver the returned-value
item's 21 + 9, capped at the 38 digits of the `Int128` carrier, integer digits first - `PicInfo.ScaledCarrierDigits`, which
`ReceiverContext.IntermediateDigits` now reads), 21 integer + 17 fraction digits as a value operand (an EVALUATE subject, a
frozen function argument), and the returned-value item's S9(21)V9(9) only for text in an INVOKE character formal.
`MoveBinder` passes the receivers, `OoBinder` the text use. Sibling arms swept: EVALUATE subject (fixed), `ArgumentOrder`
frozen function argument (a frozen `PI` is now a binary64 argument, as un-frozen), INVOKE character formal (unchanged),
SET address-name (character only), the function-bearing subscript temp (`SegmentTempPic`, a different item since PB1890).

**Goldens.** `85/pb3268_function_value_one_evaluation`, `2002/pb3268_function_value_pi_and_wide_integers`,
`2023/pb3268_function_value_float_receivers`, `2023/pb3268_function_value_standard_decimal` (each derived from the spec's
rule and the true decimal expansions; no negative: the change rejects no source). Drift test
`FunctionValueIntermediateDriftTests` holds the carrier over every `Float: true` catalog row under native and
STANDARD-DECIMAL, and that only the three readers of the returned-value item ask for `FunctionValuePic`.

**Residual (named in DOC-A.1-92).** An exact-family value needing more digits than the `Int128` carrier (NUMVAL text of
more than 17 fraction digits as an EVALUATE subject, or a MOVE whose receivers' integer plus fraction digits exceed 38) is
held at the carrier's digits where the un-hoisted reference keeps the SDIDI's: it needs an SDIDI-carried item.
