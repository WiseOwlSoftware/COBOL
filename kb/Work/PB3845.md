# PB3845 — A parse failure masks the bind-time word-character diagnosis

**Sites:** `src/WiseOwl.Cobol.Frontend/Common/CobolWordRule.cs#CharacterViolation`

Repro: the U+00A0-only line of golden `pb1660` draws a bare COBOL0001, never COBOL2773 naming U+00A0 (PB1402's character-outside-Annex-B diagnostic). `CharacterViolation` runs at bind only, so a source whose offending character already breaks the parse never reaches it and the user is told cannot-parse without the cause. Check whether the word-character test can run where the lexer produces the word, so the cause is named at parse time as well.

Register class: a message that names the wrong fault is filed `process_only: true` today because the register has no harm class for it (kb/Work PB3836); the flag becomes the new class when PB3836 lands.

## Acceptance

- The pb1660 line draws COBOL2773 naming U+00A0 (with or without the parse failure), and every other character class `CharacterViolation` rules on is checked the same way.
- Fix the root cause, never simply making the diagnostic pass; be consistent with ourselves barring an explicit requirement differently.
