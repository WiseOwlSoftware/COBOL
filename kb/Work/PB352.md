# PB352 — the START form the standard requires, refused by the rule that requires it

**Rows:** `SR-14.9.41.3-1`, `SR-14.9.41.3-2`, `SR-14.9.41.3-8`, `GR-14.9.41.4-1`, `-2`, `-4`, `-5`, `-6`, `-7`,
`-20`, `-21`. Reported by start p1, p2 and p3 as three mechanisms; it is one early return with five consequences.

## The programs

`<lane3 scratch>/out-b1/probe/seq-start/STPRB2.cob` — `ORGANIZATION IS SEQUENTIAL`, `ACCESS SEQUENTIAL`,
`FILE STATUS IS FS`; OPEN OUTPUT, WRITE `AAA-1`/`BBB-2`/`CCC-3`, CLOSE; OPEN INPUT; READ (yields AAA-1); then
`START SQF FIRST INVALID KEY DISPLAY "H-INV" NOT INVALID KEY DISPLAY "H-OK" END-START` / DISPLAY FS / READ; then
`START SQF LAST ...`. Also `probe/sr2-seq/prb.cob` and `probe/start-p2-h/p2h.cob`.

All **compile with zero diagnostics** and then abort the run unit:
`Unhandled exception. CobolNet.Runtime.NotImplementedCobolFeatureException: ... START on sequential-organization
file 'SQF' (ISO 14.9.41 SR2 FIRST/LAST positioning — a later slice)`.

## The rules

> §14.9.41.3 SR2: If the organization of the file referenced by file-name-1 is sequential, either the FIRST or
> the LAST phrase shall be specified

`--check 14.9.41.3 "either the FIRST or the LAST phrase shall be specified"` → **OK**. SR2 **permits** START on a
sequential file and only constrains the phrase — so `START <sequential-file> FIRST` is legal source and the
message cites SR2 as the reason for refusing what SR2 permits.

> §14.9.41.4 GR20: If FIRST is specified, the file position indicator is set to 1 if records exist in the
> physical file. If no records exist ... the I-O status value ... is set to '23', the invalid key condition
> exists, and the execution of the START statement is unsuccessful.

`--check 14.9.41.4 "the file position indicator is set to 1 if records exist in the physical file"` → **OK**;
GR21 is the LAST twin. §9.1.13.5 item 3 d) independently confirms the status: *a START statement is attempted on
a sequential file that has no records or that does not support the ability to position at the specified record*
(`--check 9.1.13.5` → **OK**). **Note the SHAPE of that rule: an implementation that cannot seek is still obliged
to ANSWER '23', never to abort.**

GR1-GR7 are stated BEFORE the RELATIVE FILES heading, so they govern this organization too: GR1/GR2 (the '47'
open-mode contract and the untouched record area), GR4 (the I-O status is never updated), GR5 (an OPTIONAL absent
sequential file can never raise the invalid key condition), GR6 (neither phrase can be reached), GR7 (the
indicator is never invalidated).

## What the compiler does — three missing layers, not one

1. `KeyedIoBinder.BindStart` returns `BoundUnsupported` for `FileModel.IsSequential` (which covers SEQUENTIAL
   and LINE SEQUENTIAL) **before** `KeyedValidateFile` and before the FIRST/LAST discrimination, so every later
   syntax check in `BindStart` — SR1, SR8, SR3, SR5, SR6 — is unreachable for that organization. Measured:
   `probe/sr1-sr8/prb.cob` line 41, `START SQF KEY IS = SQ-REC WITH LENGTH 2`, draws **zero** diagnostics where
   SR8 requires the LENGTH probe to be rejected (sequential is not indexed).
2. `SequentialConnector.cs` declares **no `Start` or `StartFirstLast` member at all** — grepping *Start* in it
   finds only `_lastReadBlockStart` / `_lastLineStart`.
3. `FileRegistry.StartFirstLast`'s switch has arms for `RelativeConnector` and `IndexedConnector` only and throws
   `MisroutedVerb` otherwise.

**The shape was inherited from a rule of the opposite polarity.** `BindDelete`'s twin at `KeyedIoBinder.cs:147`
raises `ctx.Edition.Error(COBOLNET0865, "... ISO 14.9.10 SR1")` before returning `BoundUnsupported`, because
there the prohibition is real. START copied the shape and not the polarity.

## And one more thing the same early return costs

`BindStart` is the **only** keyed verb that does not call `ctx.Validation.ScreenSortMergeFile` — `BindDelete`,
`BindDeleteFile`, `BindClose` and `SequentialIoBinder.UnsupportedOrg` all do (the PB140 consolidation). So an SD
file whose SELECT carries `ORGANIZATION INDEXED` accepts a START (`probe/sd-start/prb.cob` compiles clean) where
§9.1.19 says *The only statements that may reference a sort file are the RELEASE, RETURN, and SORT statements*
(`--check 9.1.19` → **OK**). That is SR-14.9.41.3-1's row.

## The fix shape

A runtime feature, not a binder tweak. `SequentialConnector` needs a real positioning entry point — a
record-ordinal FPI for FIRST, and for LAST either a seek-to-end or the '23' answer GR21 explicitly provides for a
stream that cannot position at the last record; `FileRegistry.StartFirstLast` needs its third arm; and
`BindStart`'s early return becomes the ordinary bind path with `ScreenSortMergeFile` called like its siblings.
The two further costs of the same early return are **PB353** (the edition gate never fires) and **PB236** (the
refusal is a runtime throw, not a diagnostic).

**Code sites:** `KeyedIoBinder.cs#BindStart` (the `if (file.IsSequential)` arm, lines 207-210) ·
`SequentialConnector.cs` (no `Start` member) · `FileRegistry.cs#StartFirstLast` ·
`StatementEmitter.cs#Visit(BoundUnsupported)` · contrast `KeyedIoBinder.cs#BindDelete`.

## Landed — 2026-09-05

**One early return, five consequences, all five gone.** `KeyedIoBinder.BindStart`'s
`if (file.IsSequential) return new BoundUnsupported(...)` was removed and START now binds for all THREE
organizations, which is what §14.9.41.3 SR2 requires: the rule PERMITS the statement on a
sequential-organization file and only constrains which phrase may appear, so the FIRST/LAST form is the one
shape a conforming START on one can have. The five layers, each with its own site:

- **The binder.** `ScreenSortMergeFile(file, "START")` runs first, like `BindDelete`'s and `BindClose`'s —
  START was the ONE keyed verb that skipped the §13.4.6.3 SR3 / §9.1.19 screen, so an SD whose SELECT carried
  `ORGANIZATION INDEXED` compiled a START and ran against an unregistered connector. Then SR2 rejects every
  non-FIRST/LAST form on a sequential file, in the SAME COBOLNET0862 channel the method already uses.
- **Every rule a statement violates now reports.** SR3, SR8 and SR4 constrain the KEY phrase whatever the
  organization is, so they are screened ABOVE SR2's rejection and above the `operand is null` bail, each of
  which used to swallow the rules below it: `START SQF KEY IS = SQ-REC WITH LENGTH 2` violated SR8 AND SR2 and
  reported neither.
- **The registry.** `FileRegistry.StartFirstLast` has its third arm. The standard writes the rule three times,
  once per organization heading (GR11/GR12 relative, GR18/GR19 indexed, GR20/GR21 sequential), so the
  sequential arm is not an extension — leaving it out made the statement the standard requires the one the
  switch threw `MisroutedVerb` on.
- **The connector.** `SequentialConnector.StartFirstLast` implements GR20/GR21 over `NextFrame`, the ONE
  physical framing walk — **extracted out of `Read`** so START's record scan could not become a second copy of
  the line / varying / fixed-block framing rules (rule 5: the shape that makes the next case automatic).
  FIRST stops at the first frame, LAST walks to end-of-data remembering the last; `SeekToRecord` repositions
  the reader (discarding the buffered data) and resets every derived read fact — the two logical offsets, the
  §14.9.30 GR15 unread remainder, the REWRITE byte anchors, and the §9.1.16 record ordinal, so the next READ
  is numbered correctly. Positioning is INCLUSIVE, which is §14.9.30.4 GR21's own sequential arm b): *"If the
  file position indicator was established by a prior successful OPEN or START statement, the first existing
  record that is selected is made available."* **Every failure arm answers, none aborts** — an empty file, a
  stream that cannot seek (GR20/GR21's second arm, and the rule's own shape: an implementation that cannot
  position is still obliged to answer '23'), and an absent OPTIONAL file (GR5) are all '23'.
- **The edition gate (the PB353 interaction, measured).** With the bail gone, `START <sequential-file> FIRST`
  reaches `VersionConformancePass` and the introduction gate fires: at `--std 85` it is COBOLNET0900
  ("START FIRST/LAST requires COBOL-2002"), and at 2002 / 2014 / 2023 it compiles clean. It previously
  compiled at COBOL-85 with no edition diagnostic at all, because it reached no bound node. Fixture
  `conformance:negative/pb352-start-sequential-first-below-2002`.

**And one thing the sweep found that was not in the note.** §14.9.41.4 GR1's open-mode test was written out
FIVE times — twice in each keyed connector, once more in the new sequential arm — and every copy returned '47'
without invalidating the file position indicator, although GR7 applies to every unsuccessful START and a '47'
START is unsuccessful (the adjudication recorded this as a latent divergence on `GR-14.9.41.4-7` and could not
construct an observing program). `FileConnector.StartOpenModeGuard` is now the ONE site, shaped exactly like
§14.9.30.4's READ preconditions (PB336), and it applies GR7 through the virtual `InvalidateFilePosition`,
which the keyed connectors override to clear their FPI validity bit.

**Goldens.** `conformance:2002/pb352_start_sequential_first_last` walks GR20/GR21 on a record-sequential AND a
line-sequential file, GR2 (the record area survives a START verbatim), GR1's '47' with neither INVALID nor NOT
INVALID running, GR5's absent-OPTIONAL '23', and GR7 read back as '46' on the next sequential READ.
`conformance:2023/l1_table20_seq_relative` gained the Sequential row's four START cells, which became reachable
for sequential organization with this landing; its header note said "START is absent for sequential
ORGANIZATION" and is corrected. Negatives: `pb352-start-sequential-no-phrase`, `-key-phrase`,
`pb352-start-sequential-first-below-2002`, `pb352-start-sort-merge-file`, `pb352-start-length-non-indexed`.

**Rows.** All eleven closed CONFORMS (GAP 2802 → 2784 with PB354's four and the three swept key-clause rows).

**What did not hold on today's tree.** The note says the probe programs "compile with zero diagnostics"; they
now draw COBOLNET1756 at compile time first (PB236's loud-stage carrier landed in between) and then still abort
the run unit. The refusal was no longer silent; it was still a refusal.
