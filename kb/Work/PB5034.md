# PB5034 - citations that landed without `cite.py --check`

**Sites:** `tests/WiseOwl.Cobol.Tests.Unit/MarginRCutTokenTests.cs` (`MarginRCutTokenTests.ACutInACommentEntry_IsNotNamed`, `MarginRCutTokenTests.FreeForm_HasNoMarginR` and the class summary), `src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs` (`ParseArm.VisitApplyCommitClause`, `ParseArm.VisitMessagingReceiveStatement`), `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolIO.g4` (`ioControlClause`), `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.SynchronizedClause.cs` (the file summary and `DataBinder.GateSynchronizedGroup`), `src/WiseOwl.Cobol.Compiler/Binding/Model/DataItem.cs` (`DataItem.Synchronized`), `tests/version-matrix/constructs.json` (`async-messaging-2023`, `apply-commit-clause-2023`, `usage-packed-no-sign-2023`, `sync-on-group-2023`) and its generated `src/WiseOwl.Cobol.Editions/ConstructRegistry.g.cs`, `tests/WiseOwl.Cobol.Tests.Conformance/DeclinedFacilityTests.cs`, `tests/WiseOwl.Cobol.Tests.Conformance/SendFormatClassificationTests.cs`

**One mechanism.** Two reviews (PB5024 R1-1, PB5025 R1-1) each found a citation in a comment that CLAUDE.md rule 1 forbids:
the clause number or locator was written, not run through `python scripts/spec/cite.py --check`.

1. `tests/WiseOwl.Cobol.Tests.Unit/MarginRCutTokenTests.cs:108` says "a comment-entry is commentary (§2023:12.1 is silent on
   its text)". `python scripts/spec/cite.py --check "§2023:12.1" "comment-entry"` fails. The rule the test relies on is the
   1985 definition of a comment-entry (find it with `cite.py --find`), so the comment should cite that, edition named.
2. `VersionConformancePass.cs:688` (as reported) and the `CobolIO.g4` `ioControlClause` comment (~line 346) carry
   "(§2023:E.3.2 2)", which `cite.py --check` rejects ("2 is not a rule designator"). The text on main c9d36f0e19 reads
   "Annex E.3.2 item 2" without an edition prefix, and the clerk did not find the reported string at line 688; the
   implementer re-greps `E\.3\.2` under `src/` and fixes every site.

**Owed.** Re-derive each citation, run `--check`, fix both, then sweep the same mechanism: every `§` citation in a comment
of a file a landing touched. If no audit reads the citation form in comments, add one over `src/` and `tests/`
(`scripts/spec/citation.py` is the parser), so the next one is refused at the gate.

## Landing (wave 20261947 group A)

**Re-probe.** `cite.py --check "§2023:E.3.2 2" "Commit and rollback facility"` printed `FAIL: '2' is not a rule designator`;
`cite.py --check "§2023:12.1" "comment-entry"` printed `FAIL: §2023:12.1 exists but does NOT contain 'comment-entry'`. The 2023
text has no comment-entry at all (`--find` answers NO CLAUSE). The 1985 definition is `§1985:III.2`, "An entry in the
Identification Division that may be any combination of characters from the computer's character set" (--check OK).

**Fix.** The comment-entry test now quotes `§1985:III.2`. The two `(§2023:E.3.2 2)` sites read `(§2023:E.3.2 item 2)`, the form
the repository already uses for an annex list item (51 uses). Every other `E.3.2` citation under `src/`, in the construct rows
and in two test summaries takes the edition form (`Annex E.3.2 item N` becomes `§2023:E.3.2 item N`), and items 1, 2, 5 and 6
were each checked against their own words. A construct row's `citation` string reaches COBOL0900's text, which now reads
`(ISO §2023:12.4.6.3 (APPLY COMMIT clause; §2023:E.3.2 item 2))` (probed at `--std 2014`). The same test file's free-form comment
cited `§2023:6.4` for a paraphrase the clause does not print. It now quotes `§2023:6.4.1`, and its `Annex A.1 item 158` is now
`§2023:A.1 item 158`. The sweep covered every `§` citation that the PB5024 and PB5025 landings added under `src/`, `tests/` and
`conformance-suite/`, and each one passed `--check` (APPLY COMMIT 12.4.6.3 and 12.4.6.3.3, 8.10, 14.9.7, 14.9.36, 13.16.2,
13.18.63 Format 5, A.4.3).

**Audit.** `audit_code_citations.py` already reads every comment under `src/` and `tests/` (0 findings). It cannot refuse the
`§2023:X N)` shape without refusing about 7,600 lines of the tree, because `cite.py` itself prints a rule path in that shape
(`OK  §2023:E.3.2 2)`) and agents paste it. That tooling design question goes to the wave report as a lead and is not fixed
here.
