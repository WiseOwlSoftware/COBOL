# PB3904 — inspect-replacing-size-refused-at-compile-time--checking-on: cobc 3.2: INSPECT REPLACING identifiers of different size refused at compile time even with EC-RANGE-INSPECT-SIZE checking enabled

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S5) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\inspect-replacing-size-refused-at-compile-time--checking-on.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\inspect-replacing-size-refused-at-compile-time--checking-on\`.

## Summary

`INSPECT S REPLACING ALL F BY R` where F and R are identifiers of different size is legal syntax: the size mismatch
is a run-time exception condition, EC-RANGE-INSPECT-SIZE (fatal). The standard lets an implementation refuse to
produce executable code for a fatal exception condition it detects at compile time only when checking for that
condition is not enabled. cobc 3.2 refuses the statement ("REPLACING operands differ in size") in every case, also
when checking is enabled with `>>TURN EC-RANGE-INSPECT-SIZE CHECKING ON` or `-fec=all`, where the standard requires a
program that terminates abnormally when the statement executes.

With checking not enabled the compile-time refusal is implementor latitude: sibling record
`inspect-replacing-size-refused-at-compile-time--checking-off` (NOT-A-DEFECT).

## Minimal test case

Free reference format (`-fformat=free`), `records/inspect-replacing-size-refused-at-compile-time--checking-on.cob`:

```cobol
       >>TURN EC-RANGE-INSPECT-SIZE CHECKING ON
IDENTIFICATION DIVISION.
PROGRAM-ID. INSPSZ.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 S PIC X(4) VALUE "ABAB".
01 F PIC X(1) VALUE "B".
01 R PIC X(2) VALUE "ZZ".
PROCEDURE DIVISION.
    INSPECT S REPLACING ALL F BY R
    DISPLAY "[" S "]"
    STOP RUN.
```

## Expected result (per ISO)

ISO/IEC 1989:2023, each citation checked with `scripts/spec/cite.py --check`:

- §14.9.22.3 rule 6) restricts only literals: "When both literal-1 and literal-3 are specified, they shall be the same
  size". No syntax rule restricts identifier-3 and identifier-5.
- §14.9.22.4 rule 14): "The size of literal-3 or the data item referenced by identifier-5 shall be equal to the size of
  literal-1 or the data item referenced by identifier-3. If these sizes are not equal, the EC-RANGE-INSPECT-SIZE
  exception condition is set to exist and the results of the execution of the INSPECT statement are undefined."
- §14.6.13.1.6, the exception table: EC-RANGE-INSPECT-SIZE, Fatal, "Size of replace items in INSPECT differs".
- §7.3.25.4 rule 6): "If the ON phrase is specified or implied, checking for the exception condition associated with
  exception-name-1 is enabled for the procedure division statements and procedure division headers that follow in the
  compilation group".
- §14.6.13.1.3 rule 7): "If checking for the exception condition is enabled, execution of the run unit is terminated
  abnormally". The paragraph after rule 8): "If checking is not enabled for a fatal exception condition and the
  exception condition is detected by the compiler, the implementor is not required to produce executable code."

The permission to produce no executable code is conditioned on checking not being enabled. With checking enabled the
program is a legal program whose run must end in abnormal termination at the INSPECT (and nothing else is displayed).
Expected: compiles; the run terminates abnormally with EC-RANGE-INSPECT-SIZE. (This reading rests on the condition in
the §14.6.13.1.3 paragraph; a maintainer who reads that paragraph as permitting compile-time refusal in all cases would
decline the report.)

Edition: the INSPECT rule, the fatal classification of EC-RANGE-INSPECT-SIZE (row read from the PDF of the
ISO/IEC 1989:20xx CD 1.2, 2009-08-23, that led to 2014: "EC-RANGE-INSPECT-SIZE Fatal Size of replace items in INSPECT
differs"), the TURN directive and the compile-time paragraph (same wording in that CD and in the 2002 text) are all in
2014.

Edition as recorded by the adjudicator: 2014. `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Class

Rejects legal ISO source (with exception checking enabled).

## Our compiler (WiseOwl)

`cobol.exe inspszt.cob --std 2014 --source-format free -o inspszt.dll`: exit 0; `dotnet inspszt.dll`: exit 1, stderr
`abnormal run-unit termination: EC-RANGE-INSPECT-SIZE (fatal): INSPECT REPLACING operand 1: a 1-character pattern
replaced by a 2-character replacement; ISO §14.9.22.4 GR14 requires equal sizes`. Without the directive WiseOwl runs
the program, leaves S unchanged and prints `[ABAB]` (checking off: implementor-defined continuation).

## Fix site (GnuCOBOL 3.2 source, read observationally)

`cobc/typeck.c`, function `validate_inspect` (line 10158): when both operands have a size known at compile time
(`calc_reference_size` for a reference, the literal size for a literal) and the sizes differ, it reports
"REPLACING operands differ in size" (line 10193; "CONVERTING" at line 10196) as an error, with no test of whether
EC-RANGE-INSPECT-SIZE checking is enabled and no distinction between literals (syntax rule 6, a real error) and
identifiers (general rule 14). A fix keeps the error for two literals and, for identifiers, warns and generates a
run-time EC-RANGE-INSPECT-SIZE when `CB_EXCEPTION_ENABLE (COB_EC_RANGE_INSPECT_SIZE)` is set.
