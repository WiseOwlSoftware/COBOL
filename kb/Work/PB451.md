# PB451 — SET Format 5's receiver discrimination is half-written on two dispatches

Lane-3 adjudication batch b2, group g7-set-a. **Every repro below was re-run on HEAD `89044aa0`**; all still
reproduce.

## 1. THE MECHANISM

§14.9.39.3's Format-5 rules are organised on **two axes at once**: which *sender* is written
(identifier-4 / object-class-name-1 / SELF / NULL) and how the *receiver* is described (interface-name /
object-class-name / ACTIVE-CLASS / universal, and with or without FACTORY and ONLY). `OoBindSetObjectRef`
(`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/OoBinder.cs:855-977`) dispatches on the sender, and then
inside two of those sender arms it must dispatch again on the receiver. **Both inner dispatches were written
with one arm finished.**

**Dispatch A — the SELF sender** (`OoBinder.cs:902-926`). The receiver loop splits on what the receiver's type
name resolves to:

    if (host.OoClasses?.Find(tcn) is { } tcls)                       // :905  CLASS receiver
        if (!cur.ConformsTo(tcls)) … SR12c2                          // :907-910   ← the ONLY test
    else if (host.OoClasses?.FindInterface(tcn) is { } tiface        // :920  INTERFACE receiver
             && !host.OoClasses.ImplementsClosure(cur, host.OoInFactory).Contains(tiface))
        … SR10d1 / SR10d2                                            // :922-925

The interface leg threads `host.OoInFactory` through and even names SR10d1 vs SR10d2 — it **knows** whether the
SET sits in a factory or an instance method. The class leg three lines above never asks. SR12 c) imposes four
conditions on a SELF sender into a class-typed receiver and the class leg implements exactly one of them, c)2.
`host.OoInFactory` appears in this whole arm exactly once, at :921.

That omission is not a soft miss. `OoEmitter.EmitSetObjectRef` (`CodeGen/Verbs/OoEmitter.cs:398-429`) renders
`({tp.Item.Pic!.ClrType})({src})` with `src == "this"` under a doc-comment (`:395-397`) that asserts "**The cast
renders total: conformance was bind-checked (0867)**". SR12 c)3. is precisely the check that makes that
invariant true. In a factory method `this` is the synthesized factory singleton `CLS__FACTORY`, unrelated to the
instance type `CLS`, so the emitted C# does not compile and the user gets a Roslyn error naming a type that
appears nowhere in their program.

⛔ **This is the SAME failure the SR10d fix already repaired for interface receivers, on the sibling arm.** The
comment at `OoBinder.cs:912-919` describes it verbatim ("the emitter rendered a raw `(I)(this)` cast — a runtime
InvalidCastException, or a Roslyn CS error on generated user source …, which the G4 no-CS-on-user-source rule
forbids"). Ask which arm you fixed.

**Dispatch B — the object-class-name sender** (`OoBinder.cs:951-966`). The arm tests only
`tp.Item.Pic!.ObjectClassName is not null` — "is the receiver typed at all" — and refuses **every** typed
receiver with one staged-loud message that names SR13. For a receiver described with an object-class-name that
outcome is right (SR13 requires the FACTORY phrase, which cannot be declared). For a receiver described with an
**interface-name** the governing rule is **SR11**, which *explicitly permits* the assignment when the sender
class's factory carries a matching IMPLEMENTS clause — and that conforming program is refused too, by a message
naming a rule whose own precondition is false for it. The discrimination needed is a call away and is used twice
in this very file (`FindInterface` at :920; `OoConformance.ObjectRefWideningMismatch`).

**The descriptor underneath both.** `PicInfo` (`Binding/Model/PicInfo.cs:345`) models §13.18.60's four-axis
object-reference operand — kind · name · FACTORY · ONLY — as ONE nullable string, `ObjectClassName`. "Typed AND
factory" is therefore not an expressible state, which is why SR13's own mandated receiver shape cannot be
written, why SR13 a)/b) are unreachable, and why SR14's ACTIVE-CLASS rules have no subject.

**And the closure is the wrong relation for SR10 d).** `ImplementsClosure`
(`src/Cobol.Net.Compiler/Oo/OoClassTable.cs:55-71`) walks the *transitive* implements relation — direct
IMPLEMENTS, plus every interface those inherit, plus every inherited class's implements. SR10 d) asks a
**literal** question about the clause text.

⚠ **A `--check` OK is evidence about the TEXT, not about which rule you meant, and this clause proves it.**
SR14 b)1. and b)2. are **word-for-word identical** to SR12 c)3. and c)4.; `--check` on that sentence returns
**12)**, never 14). So rows L8.1/L8.2 cannot be pinned by that fragment — they are pinned by SR14's own lead-in
(returned above as 14)) plus the observation that its sub-rules repeat SR12 c)'s text verbatim. That identity is
not a nuisance: **it is the argument for one shared placement predicate** (§4).

**The SR10 d) reading, stated plainly because it is interpretive.** SR10 spells inheritance out wherever it
means it — a) says "an interface-name that identifies int-1 **or an interface inheriting from int-1**", and
b)/c) say "shall **implement** int-1", which §9.3.11 / §11.4.4 GR1 make the transitive relation. d) says
*neither*: it says the definition "shall be **described with an IMPLEMENTS clause that references int-1**". On
that reading `ImplementsClosure` is strictly more permissive than the rule, and the leniency is not
dialect-gated.

## 4. THE CODE SITES AND THE SHAPE OF THE REPAIR

| arm | file:line |
|---|---|
| SELF arm, CLASS leg (one condition) | `OoBinder.cs:905-911` |
| SELF arm, INTERFACE leg (has the placement test) | `OoBinder.cs:920-925` |
| class-name-sender arm, blanket typed-receiver refusal | `OoBinder.cs:951-966` (the refusal at `:957-964`) |
| the emitter that assumes the bind check | `CodeGen/Verbs/OoEmitter.cs:395-397`, `:423-428` |
| the over-permissive relation | `src/Cobol.Net.Compiler/Oo/OoClassTable.cs:55-71` `ImplementsClosure` |
| the scalar where the spec has a tuple | `src/Cobol.Net.Compiler/Binding/Model/PicInfo.cs:345` `ObjectClassName` |
| the receiver shapes the grammar lacks | `src/Cobol.Net.Frontend/Grammar/CobolOO.g4` `objectReferenceUsage` |

⛔ **Four repairs, each structural, and none of them a new arm** (CLAUDE.md rule 5):

1. **One placement predicate.** `RequireSelfPlacement(receiverDescriptor, host.OoInFactory)`, hoisted out of the
   interface leg so **both** receiver kinds run it. SR12 c)3./c)4. and SR14 b)1./b)2. are the same sentence
   twice; writing it once closes four rows and keeps SR14 automatic when the ACTIVE-CLASS descriptor lands.
2. **Branch dispatch B on `FindInterface` first.** An interface-typed receiver runs SR11's factory-side
   `ImplementsClosure(cls, factory: true)` test (already used by `ValidateImplements`); only a class-typed
   receiver reaches SR13's refusal. Note `OoConformance.cs` computes the *instance*-side closure
   unconditionally, so the same factory/instance distinction SR10 b)1.-vs-b)2. draws is missing in the same
   place — one fix, two rules.
3. **`ObjectClassName` becomes `ObjectRefDescriptor(Kind, Name, Factory, Only)`** and `objectReferenceUsage`
   grows the `FACTORY OF` and `ONLY` shapes. Until it does, SR13 a)/b), SR12 a)1./b)1./c)1., SR14 and GR10's
   typed form have no expressible input, and every screen above is guessing from a string.
4. **SR10 d) screens direct membership**, not the closure: `c.FactoryImplements` / `c.Implements` for the
   *containing* definition, at `OoBinder.cs:921`, with the transitive closure kept for b)/c) where the standard
   asks for "implement".

## 5. THE SIBLING SWEEP THE FIXER MUST DO

* Every other `ImplementsClosure` caller — `ValidateImplements`, `ObjectRefWideningMismatch`, the INVOKE
  conformance path — must be re-read against whether its rule says "described with an IMPLEMENTS clause" or
  "shall implement". They are different relations and the code has one.
* `OoBinder.cs:937-947` (the identifier-4 sender arm) tests `tp.Item.Pic!.ObjectClassName is not null` with the
  same "typed at all" shape; SR12 a)/b)/c) and SR10 a)/b)/c) need the same interface-vs-class split.
* The universal-receiver lane is where every factory assignment currently lives (`p4_gr10_universal` runs and
  reaches the FACTORY method) — every one of those programs silently gives up static conformance, so the
  descriptor landing must sweep them.
* [[PB456]] is the *selection* half of Format 5: these screens only run when the re-route fires at all.
