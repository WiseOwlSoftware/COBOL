# PB1322 — OPEN — comments that describe code that moved

## Sites
- `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/MoveBinder.cs:13-33`: three consecutive `<summary>` blocks
  in front of ONE type.
  - The first describes the §14.9.25.3 SR5 edition gates, which now live in `VersionConformancePass.GateSr5`
    (PB422).
  - The second describes the MOVE binder.
  - The third describes the FROM-phrase rule table, which is its own type.
  - The C# compiler attaches only the last block to the declaration, so two of the three document nothing.
- `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/ConditionBinder.cs:1046`: `<see cref="Gr3Width"/>`. PB589
  replaced `Gr3Width` with `CobolBoolSized` / `BooleanRenderer.RenderAtItemWidth` and
  `RefModPlace.StaticLength`. The lander also found an inventory `code-location` naming
  `ConditionBinder.cs#Gr3Width`. On main `071ff04ea` no row carries it any more, because the train-59 re-verdict
  already moved it. Only the cref remains.

## Why the build does not catch it
`GenerateDocumentationFile` is set neither in `Directory.Build.props` nor in `Cobol.Net.Compiler.csproj`, as a grep
on `071ff04ea` shows. With it off, the compiler never resolves a cref, so CS1574 cannot fire. A doc comment is then never checked against anything.

## What the fixer owes
- Fix the two sites. Move the SR5 summary to `VersionConformancePass`, delete the duplicates and retarget the
  cref.
- The durable half: turn on documentation-file generation for the `src/Cobol.Net.*` projects with CS1574/CS1584
  (unresolved cref) as errors, and CS1591 (missing comment) suppressed. Every stale cref then fails the build.
  Sweep the first run's hits in the same change.
- Measure the build-time cost before and after, and record it in the DEVLOG.
