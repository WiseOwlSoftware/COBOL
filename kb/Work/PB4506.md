# PB4506 — a staged, batched differential fuzz

**Sites:** `scripts/fuzz_batch.py` (whole: new), `scripts/differential_fuzz.py` (`prompt_plan`, `seed_at`,
`first_messages`, `writer_reply`, `Fuzz.__init__`, `Fuzz.seed_for`, `Fuzz._one`, `Settings`, `main`)

**What was missing.** `differential_fuzz.py` interleaves writing, compiling and correcting per program, because its
first writer, a local model, needed correction rounds: on 2026-10-29, 36.6 % of its 6,851 programs were refused by both
compilers and another 14.9 % by WiseOwl alone, with triage finding WiseOwl right in all 92 of those signatures (51.6 %
invalid or empty). A Claude writer (PB4504) needed no correction in the 20-program calibration of 2026-11-03 (0 refused by
both), so the interleaving only costs: every call is billed at the standard rate and the run waits on each.

**As landed.** Three stages. `fuzz_batch.py submit` builds one Message Batches request per program from
`differential_fuzz.prompt_plan`, `seed_at` and `first_messages`, the functions the judge's own row reads (so request `fz00042`
and judged row `fz00042` share a clause and a prompt), with each clause family's system prompt marked for caching, and records
the batch and its plan in `batch.json`. `collect` polls until the batch ends and writes each succeeded reply to
`replies/<id>.json` (text, stop reason, usage) with the counts and token totals in `collect.json`. The judge is
`differential_fuzz.py --writer files --replies DIR`: `writer_reply` reads the written reply, corrections are off, and every
later step (extraction, both compilers, the verdict, `results.jsonl`) is unchanged, so triage reads the run as any other.
A request with no reply is the row's RUNNER_ERROR naming why. The API key is read from `--api-key-file` (first non-empty
line, a byte-order mark dropped) into the SDK client only.

**The comparison the owner asked for.** Validity is measured the way the 2026-10-29 triage licenses: a program is VALID
when WiseOwl compiles it (that run's WiseOwl-only refusals were all WiseOwl-correct), so the local model's baseline is 47.1 %
(3,225 of 6,851: §13.18 27 %, §14.9 32 %, §15 63 %, §8.8 48 %), from its `results.jsonl`; the batch run gets the same count, and its WiseOwl-only refusals
are confirmed by its own triage.

**Witnesses.** `python scripts/fuzz_batch.py --self-test` (request i matches the judge's program i; caching and the token
cap; reply writing for succeeded and errored results; the files writer reads a reply back and refuses a missing one; the
key file); `python scripts/differential_fuzz.py --self-test` (the refactored plan and the existing checks). A 5-request
smoke batch on the API key, 2026-11-03, exercised the real SDK calls.

**The smoke run, end to end (2026-11-03).** A 5-request batch (`msgbatch_01VQuZgkLfyR72RjR4rXwZtr`) went through every
stage before any larger one: collect (5 of 5 succeeded; the family system prompt read from cache from the second request
on), judge (`--writer files`, which the smoke found refused without `--model`: fixed, with a self-test case), validity
(WiseOwl compiled 3 of 5) and triage (`fuzz_triage.py prepare`, two `cobol-adjudicator` slices run headless on the API key
with the workflow's own prompt, `collect` validating the verdicts: one WISEOWL-DEFECT, one WISEOWL-CORRECT, one
GNUCOBOL-SIDE witness of PB3914). Measured costs: generation about $0.021 a program (about 3,600 output tokens with
thinking), triage about $0.39 a signature. A 6,000-request batch submitted before the smoke finished was cancelled with
none processed (the owner: "We do not submit the 6,000 until we've run the smoke test batch thru the entire evaluation
process").

**Branch review round 1 (w20261846e-review-r1).** R1-1 (medium): the judge trusted that reply i is program i, so a judge run
with another `--clauses` / `--seed` / `--in-order`, or a seed clause declined in docs/CONFORMANCE.md between submit and
judge (one extra declined clause moved 519 of the first 600 rows, measured), judged replies as the wrong program with no
error. `batch.json` now records the plan (`plan`: each id's clause number, title and the sha256 of its first request, from
`differential_fuzz.plan_entries`); a files run takes its count, clauses, seed and order FROM `batch.json` and refuses to start
when `batch_plan_problems` finds any program built differently; rows record the batch's model; `--hours` is refused.
Leads taken: R1-2, a `refusal` reply is no program (RUNNER_ERROR), and a `max_tokens` cut names Claude's limit; R1-3,
`submit` writes the record before the billed create and prints the id the moment it exists; R1-4, the self-test runs
`submit` and `collect` end to end through a fake client and checks the judge command carries no plan. The smoke run was
re-judged through the new path (its plan rebuilt and checked against the clauses the first judge recorded): same verdicts.
