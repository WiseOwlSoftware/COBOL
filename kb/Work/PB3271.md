# PB3271 — drift-test scanners include generated test output

Source: `E:\COBOL-coord\scratch\reports\w1093b-PB2099-report.md`, "Note-ready lead (I9; not fixed here, finisher-never-widens)" under "## Finisher". That paragraph's item (3) is a fifth scanner, fixed on PB2099's branch, where the NIST guard wrote generated programs into the same tree.

**Mechanism.** Four more drift tests enumerate `tests/**/*.cs` with only the bin/obj exclusion, so the generated-output hazard is latent in each: `TestRepoDriftTests.cs:46`, `ProcessObservationDriftTests.cs:55`, `NoWallClockAssertionDriftTests.cs:37,65` and `ImpactedTestsDriftTests.cs:143` (all under `tests/Cobol.Net.Tests.Unit/`). They are green today only because no generated NIST program matches their patterns.

**Fix shape (the report's).** One `TestRepo.TestSources()` in `tests/_shared/TestRepo.cs` that excludes bin/, obj/ and `*.g.cs`, used by all five scanners, with a drift test that no test enumerates `TestRepo.Tests()` for `*.cs` on its own.

**Repro.** Run the guard leg (`scripts/guard-fast.sh`) in a worktree, then the unit tests that scan.
