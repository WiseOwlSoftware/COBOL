# PB481 — OPEN — the same helper PB205 fixed for CONTROL, at its three remaining callers

Found 2026-09-04 by the `PB205` implementer while sweeping every caller of `DataBinder.KeyReference`; PB205
fixed the CONTROL / TYPE / RESET ON arms (where §13.18.16.3 SR4 permits a reference modification and the
binder must KEEP it) and measured that the FILE-CONTROL arms have the opposite defect: the format does not
permit one and the binder silently DROPS it. Re-derived on this tree for this note.

## The mechanism

`src/Cobol.Net.Compiler/Binding/DataBinder.cs` — `KeyReference(...)` returns `(Base, Quals)` from a
`dataReference` and discards everything else on the operand. Its callers: RECORD KEY (`:818`), ALTERNATE
RECORD KEY (`:821`), and RELATIVE KEY (`:827`, which keeps `.Base` only — the qualifiers are dropped too).
So `RECORD KEY IS IX-KEY(1:3)` binds as `IX-KEY`, compiles with no diagnostic, and the file is keyed on the
whole six-character item: a program written to key on three characters gets a different file organisation
than it wrote, silently. A subscripted spelling is the same shape (§8.4.2.3.3 SR2 leaves no legal one, since a
key item cannot be a table element — §12.4.5.12.3).

## The rule

```
python scripts/spec/cite.py --check 12.4.5.12.1 "The RECORD KEY clause specifies the prime record key"
OK  §12.4.5.12.1
python scripts/spec/cite.py --check 8.4.3.3.3 "Because the references to data items are restricted to identifiers, where data-name-n is used in a general format or syntax rule, then reference-modification is not permitted."
OK  §8.4.3.3.3 5)  (the NOTE)
```

§12.4.5.12's general format (and §12.4.5.6's ALTERNATE RECORD KEY, §12.4.5.13's RELATIVE KEY) writes
`data-name-1`, not `identifier-1`; §8.4.3.3.3's NOTE is the general statement that a data-name slot admits no
reference modification. The conforming posture is a compile-time rejection naming the clause.

## Fix shape

`KeyReference` becomes a screen, not a projection: it reads the operand's suffixes through
`ReferenceResolver.ReadOperandSuffixes` (PB205's lexical reader) and rejects a reference modification or a
subscript with a named diagnostic citing the clause; RELATIVE KEY keeps its qualifiers. One helper, three
callers, one negative golden per clause (`*> reject-at: 85 2002 2014 2023`), and the existing positive
keyed-file goldens prove nothing legal is refused. The helper's doc comment on main already states the
hazard (PB205 wrote it); the screen is what is owed.
