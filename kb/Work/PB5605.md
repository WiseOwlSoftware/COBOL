# PB5605 - at --std 2002 (and 2023 for a second FD record) an ODO table in an implicitly redefining record is never checked: EC-BOUND-ODO is not raised

**Sites:**
- `src/WiseOwl.Cobol` .Compiler/Binding/Model/PlaceBuilder.cs (the RedefViewPlace path
- not pinned to a member)

**Mechanism.** A record that implicitly redefines another (each record after the first under an FD, every record under a CD) is a RedefViewPlace whose access path never gets the OdoReferenceCheck that BuildAccessPath(..., OdoReferenceCheckFor) attaches to the canonical record, so a DEPENDING ON value outside the OCCURS bounds is not detected.

**Inventory.** Rows claimed: `2002-GR-13.16.36.3-7`.

**Rules (each citation checked with `python scripts/spec/cite.py --check`, verdict OK).**

- `§2002:13.16.36.3 GR7`: "If the value of the data item does not fall within the specified bounds, the EC-BOUND-ODO"
- `§2002:A.1.2.2 SR9`: "Record description entries subordinate to an output CD entry implicitly redefine the record"

**Repro.** Scratch originals under `E:/COBOL-coord/scratch/op-20261114/read-2002/defects-work/` (p/cd-odo.cob); the text is inline. Command: `cobol.exe p/cd-odo.cob --std 2002 --run`

`p/cd-odo.cob`:

```cobol
       >>TURN EC-BOUND-ODO CHECKING ON
       IDENTIFICATION DIVISION.
       PROGRAM-ID. CDODO17.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 N    PIC 99 VALUE 5.
       COMMUNICATION SECTION.
       CD  CDOUT FOR OUTPUT
           DESTINATION COUNT IS DC
           TEXT LENGTH IS TL
           STATUS KEY IS SK
           ERROR KEY IS EK
           SYMBOLIC DESTINATION IS SD1.
       01  CDREC.
           05 H PIC X.
           05 U OCCURS 2 TO 5 DEPENDING ON N.
              10 UX PIC X.
       PROCEDURE DIVISION.
       M1.
           MOVE "HVWXYZ" TO CDREC
           MOVE 7 TO N
           DISPLAY "1 " UX(1)
           DISPLAY "NOT TERMINATED"
           STOP RUN.
```

**Observed.** >>TURN EC-BOUND-ODO CHECKING ON; CD record 05 U OCCURS 2 TO 5 DEPENDING ON N; MOVE 7 TO N; DISPLAY UX(1): prints '1 V' and 'NOT TERMINATED', rc=0. The reader's fd-odo.cob (second 01 under an FD) does the same at 2002 and 2023; the working-storage and sole-FD-record controls terminate with EC-BOUND-ODO.

**Expected (from the 2002 text).** EC-BOUND-ODO set to exist, a fatal condition: the run unit terminates.

**Sibling sweep.** every other check BuildAccessPath attaches on the canonical place (subscript bounds, reference-modification bounds) through a RedefViewPlace; explicit REDEFINES of an ODO group.

**Other editions.** 85: no EC model. 2023: yes for a second FD record (row GR-13.18.38.4-7 is short too).
