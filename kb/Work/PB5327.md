# PB5327 - one BOUNCED row, two decisions: an infrastructure re-arm and a conflict finisher

**Sites:** `scripts/orchestrator/land_lane.py` (`rearm`, and `Decision` at ~line 508: a re-arm at the tip lands the
branch with no other check); `scripts/orchestrator/review_lane.py` (`conflict_cause`, `plan_conflict`: a BOUNCED row with
`foreseen` set gets a conflict finisher); `scripts/orchestrator/units/enqueue.md` step 4 (the unit's re-arm of a bounce it
attributes to infrastructure).

## What happened

PR #1510 (`spec-2002-catalog`) left the merge queue at 20:08Z on `checks_timed_out`: every job of merge-group run
43084093039 had succeeded and `ci-gate` never got a runner (the GitHub Actions outage of 2026-11-11). The row therefore
carried TWO causes at once: an infrastructure bounce, and a FORESEEN CONFLICT with #1512 (`spec-2002-reconcile-tools`,
queued ahead; `git merge-tree` conflicts in `scripts/spec/merge_reconciliation.py`, verified by Mythos 13:20).

- 13:11:27 the enqueue unit (session 1586a2f2) read only the first cause and ran `land_lane.py rearm` ("infrastructure,
  re-queued once"); the land lane started `enqueue.py land` (log `land-lane-000873-20261111T211126Z-spec-2002-catalog.log`).
  It merged origin/main locally and the push was refused GH006 (Mythos had already re-queued the PR by hand), exit 9.
- 13:11:31 the review lane read the second cause and started a conflict finisher (pid 39176, log
  `review-lane-000103-20261111T211131Z-conflict-spec-2002-catalog.log`), which merged #1512's branch in (b2380fceea).
- The operator killed the finisher on the standing instruction that a timeout bounce gets none. The finisher had been
  the right decision and the re-arm the wrong one: the re-arm would have put an UNMERGEABLE head back in the queue.

## Why it is a defect

`rearm` is an unconditional override at the tip: `land_lane.Decision` lands a re-armed head without asking whether the
review lane's `conflict_cause` holds for the same row. Two lanes decide one row from different halves of its state, so
which cause wins depends on tick timing, and the infrastructure half can re-queue a branch that the survey already
knows cannot merge.

## Fix direction

One predicate decides what a BOUNCED row needs, read by both lanes: a row whose `conflict_cause` is not None is a
conflict row whatever else bounced it, `rearm` refuses it (naming the conflict and the finisher run), and `land_lane`
ignores a re-arm recorded against a head that has a conflict cause. Self-test: a BOUNCED row with `checks_timed_out` and
`foreseen` set yields a conflict finisher and a refused re-arm. enqueue.md step 4 says the same in one sentence.
