**Why wrong:** ISO §12.3.7.4 GR4 leaves the external facility to the implementor, and §4.2.5 requires the implementor's definition to be documented and is the contract a conforming implementation keeps. WiseOwl's documented definition (docs/CONFORMANCE.md DOC-A.1-191) is 'the value is read at the first interrogation and a later SET governs for the rest of the run unit'; SwitchStore's own summary ('The probed value is cached on first read') and RuntimeConfig's registry text ('probed once per run unit') say the same. The unset arm of SwitchStore.Get returns false WITHOUT caching, so a run unit that interrogates an unset switch and whose environment then gains COBOL_<NAME> (set by the hosting .NET application or a non-COBOL module) sees the switch-status condition change with no SET: the documented answer is OFF, the program gets ON.

**Scenario:** Measured on the pin (8be230068), a two-program run unit hosted in-process: with COBOL_SWITCH_1 absent the first CALL of SWP prints 'SW1 OFF'; the host then sets COBOL_SWITCH_1=ON and a second CALL in the SAME run unit prints 'SW1 ON' with no SET executed; setting it OFF afterwards still prints 'SW1 ON'. SwitchStore.Get caches the status only on the arm where the variable exists; the absent arm returns false and caches nothing, so every later interrogation calls Environment.GetEnvironmentVariable again. A present-but-empty variable caches OFF at once. DOC-A.1-191 (docs/CONFORMANCE.md) defines the facility as read at the first interrogation, with a later SET governing for the rest of the run unit; SwitchStore's summary and RuntimeConfig's registry text say the same. Separately, SwitchStore's summary still states the pre-PB862 definition 'any switch-name is accepted' (the set is SWITCH-0..36 and UPSI-0..7, DOC-A.1-191), and ConfigEntry.Matches answers the switch family for ANY COBOL_ prefix, so RuntimeConfig.Find("COBOL_TYPO") reports a variable the runtime never reads as a switch variable.

**Reproduction:** Probe sw1.cob (SWHOST calls SWP; SWP: SPECIAL-NAMES SWITCH-1 IS SW1 ON STATUS IS SW1-ON OFF STATUS IS SW1-OFF; IF SW1-ON DISPLAY 'SW1 ON' ELSE DISPLAY 'SW1 OFF'), compiled by the pin cobol.exe and hosted from pwsh 7 on the pin's Cobol.Net.Runtime.dll: ProgramRegistry.Reset(); __CobolModule.Register(); with COBOL_SWITCH_1 absent, CallProgram('SWP') prints 'SW1 OFF'; then Environment.SetEnvironmentVariable('COBOL_SWITCH_1','ON') and CallProgram('SWP') again in the SAME run unit (RunUnit.Current hash unchanged) prints 'SW1 ON' with no SET executed; then setting it to OFF and calling again prints 'SW1 ON' (now latched). Second asymmetry measured on the way: a variable that is PRESENT but empty caches OFF at the first read, so whether the first read latches depends on absent-versus-empty. Direct check on one SwitchStore object: Get('SWITCH-1') False (absent), env set ON, Get True, env set OFF, Get True.

**Landed (wave 1052 G):** re-probed on the worktree build before the fix (SwitchStore.Get: absent False, env ON then True, env OFF still True; empty False then ON still False; RuntimeConfig.Find("COBOL_TYPO") non-null), all three claims reproduced. Fixed at the root in three places:
- `SwitchStore.Get` now caches on BOTH arms (an absent variable latches OFF, as an empty one always did), so the status is read once at the first interrogation by construction; the class summary now states the closed name set by reference to DOC-A.1-191 instead of the pre-PB862 'any switch-name is accepted'.
- The closed switch-name set is written ONCE, `SwitchStore.Names` (SWITCH-0..36, UPSI-0..7); the compiler's SPECIAL-NAMES table (`ImplementorNames.Build`) takes its switch rows from it, so the table and the facility cannot drift (it was two hand-written loops in two assemblies).
- `ConfigEntry` gained `Func<string,bool>? FamilyMember` (an init property; a family that declares none matches no name), and the switch family's test is `SwitchStore.IsVariableName`, so `Matches`/`RuntimeConfig.Find` answer only the variables the runtime reads (COBOL_TYPO is no longer reported). The change is purely additive to the public surface (PublicAPI.Unshipped.txt): a first attempt that replaced the `IsPattern` constructor parameter edited PublicAPI.Shipped.txt and moved `RuntimeAbiPinDriftTests`' surface hash, which would have forced a runtime MAJOR bump (every compiled module refused) for a diagnostic registry record.
Witness: `unit:SwitchStoreTests` (10 cases: absent latch, empty agrees with absent, present ON forms latch, SET governs after the latch, a new store re-reads, closed family, table built from Names). No COBOL golden: the defect is observable only by changing the host process environment between two interrogations in one run unit, which a conformance program cannot do.
