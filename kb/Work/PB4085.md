# PB4085 — the SEND statement's merged formats are not screened per format

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/DeclinedFacilityBinder.cs#ScreenSendRequiredPhrases` and
`src/WiseOwl.Cobol.Frontend/Grammar/CobolParserCore.g4#mcsSendStatement`, both as branch `worktree-wf_66e93b32-365-8` carries them
at `4e8251f4f`. PR #795 (PB2024) adds the screen, so main does not hold this code until that lands.

**One root.** §14.9.38.2 prints two general formats of SEND (Format 1 to a message server, Format 2 with data-name-2).
`mcsSendStatement` merges them into one rule, `SEND TO? (literal | dataReference) FROM dataReference (RETURNING dataReference)?
(RAISING ...)? conditionalPhrases END_SEND?`, so the source's format is never decided. Both defects follow: the parse admits what
neither format prints, and the binder screen has to guess the format from the operand. (PB937 adjudicated the two formats and is
landed; the merged rule it described is still the one in the grammar.)

**Defect 1 (under-rejects).** `SEND TO SRV-NAME FROM M END-SEND`, where SRV-NAME is no data item (so it can only be
message-server-name-1, Format 1), compiles. Format 1 prints `RETURNING data-name-1` without brackets, so the statement omits a
required word. `ScreenSendRequiredPhrases` demands RETURNING only `if (s.literal() is not null)`; a name operand is
message-server-name-1 (Format 1) or data-name-2 (Format 2), which "this binder deliberately does not resolve". Fix shape: a
non-diagnosing lookup that tells a message-server-name-1 from a data-name-2, or, at the root, one parse alternative per format.

**Defect 2 (under-rejects).** The tail `(RETURNING ...)? (RAISING ...)?` admits both phrases in one SEND. No format of §14.9.38.2
prints both.

**Citation.** `python scripts/spec/cite.py --check 14.9.38.2` found "RETURNING", "message-server-name-1" and "RAISING" in
§14.9.38.2 (General formats).

**Direction (not a fix).** Per CLAUDE.md rule 5, split the rule per general format so each phrase set is that format's own and the
screens disappear, rather than a longer screen over the merged rule. Pair it with goldens for both defects and for the legal
RETURNING-only and RAISING-only forms.

**Link.** `scripts/spec/audit_grammar_optional_words.py` reported none of this; PB4086 names that blind spot.

## Landed with PB4090 (wave 20261765 B, 2026-10-29)

Defect 1 is PB4090 itself and defect 2 is the same classification: `DeclinedFacilityBinder.ClassifySend` assigns the written SEND
its format once, a statement with a phrase of each format is the new COBOL5488, and a Format 1 without RETURNING is COBOL1850
(see PB4090's Landed section for the witnesses). The note's direction (split the rule per format) was weighed and not taken:
the name after TO is a bare word in both formats and the format is a fact about its DECLARATION (a message-tag item is
Format 2's, any other name is a message-server-name-1), so a split rule would still leave `SEND TO name FROM x` to a binder
lookup. The grammar rule carries that reasoning as a comment.
