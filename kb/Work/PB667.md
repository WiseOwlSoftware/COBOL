## The rule

§12.4.5.9.3 SR1: "This clause shall not be specified for a file that is the subject of an APPLY COMMIT clause"
(`OK §12.4.5.9.3 1)`) — the full rule continues "for which there is an implicit LOCK MODE IS AUTOMATIC WITH LOCK ON
MULTIPLE RECORDS applied automatically, including for sequential files", the NOTE under §14.9.27.3 SR8 seen from
the other side (PB319 landed SR8's exemption on exactly that fact).

## The mechanism, and the ordering constraint

`src/Cobol.Net.Compiler/Binding/DataBinder.cs#BindFileControl` binds `file.LockMode = MapLockMode(lm)` and checks
only §12.4.5.9 SR2 (the MULTIPLE/sequential conflict); nothing consults APPLY COMMIT subject-hood, which
`BindIoControl` establishes AFTER every file control entry has been bound (PB319 documents this ordering as the
reason SR8 cannot live at the SELECT either). So the check belongs in a pass that runs once subject-hood is known:
at the end of `BindIoControl` over `Files` (or a small post-I-O-CONTROL validation pass), reporting at the LOCK MODE
clause's location.
