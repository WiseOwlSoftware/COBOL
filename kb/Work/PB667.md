# PB667 — OPEN — the other side of SR8's NOTE

Found 2026-09-05 by the `PB319` implementer (report §"New defects" B), on the SAME run that found [[PB666]]: the
APPLY COMMIT witness program carries §12.4.5.9.3 SR1's forbidden pair and compiles under `--permissive`. At strict
it is refused by COBOLNET1709 (the declined clause), so like PB666 the rule is reachable only on the permissive
axis today — and will be reachable everywhere the day APPLY COMMIT is claimed.

## The rule

§12.4.5.9.3 SR1: "This clause shall not be specified for a file that is the subject of an APPLY COMMIT clause"
(`OK §12.4.5.9.3 1)`) — the full rule continues "for which there is an implicit LOCK MODE IS AUTOMATIC WITH LOCK ON
MULTIPLE RECORDS applied automatically, including for sequential files", the NOTE under §14.9.27.3 SR8 seen from
the other side (PB319 landed SR8's exemption on exactly that fact).

## The mechanism, and the ordering constraint

`src/Cobol.Net.Compiler/Binding/DataBinder.cs#BindFileControl` binds `file.LockMode = MapLockMode(lm)` and checks
only §12.4.5.9 SR2 (the MULTIPLE/sequential conflict); nothing consults APPLY COMMIT subject-hood, which
`BindIoControl` establishes AFTER every file control entry has been bound (PB319 documents this ordering as the
reason SR8 cannot live at the SELECT either). So the check belongs in a pass that runs once subject-hood is known:
at the end of `BindIoControl` over `Files` (or a small post-I-O-CONTROL validation pass), reporting at the LOCK MODE
clause's location.

## Fix shape

One check, one descriptor (next free code) naming §12.4.5.9.3 SR1, at the end of `BindIoControl`; a negative
fact under `--permissive` (the corpus has no permissive axis — an xUnit fact beside PB319's
`OpenSharingLockModeTests`) plus the strict control that COBOLNET1709 still refuses first; re-verdict
`SR-12.4.5.9.3-1`. Note the same class as PB666: every §12.4.5.x / §14.9.27.3 rule whose antecedent is an APPLY
COMMIT file is live under `--permissive` and dead under strict — sweep them together (PB371's family list is the
starting population) and land them in one change set with PB666.
