# PB1224 — OPEN

## Measured

**column-clause-p1** — F6 — the 'LINE clause in effect' test for a COLUMN entry reads the running build state (the last OPENED line) instead of the entry's own ancestry, so a COLUMN entry that is a SIBLING of a LINE subtree is silently placed on that line

- **Repro:** `01 DET TYPE DE.` / `03 LINE PLUS 1.` / `05 COLUMN 1 PIC X VALUE "A".` / `03 COLUMN 10 PIC X VALUE "B".` (--std 2023) -> compiles clean, prints 'A        B' on one line
- **Expected (spec):** §13.18.14.3 SR3: "The entry shall also contain a LINE clause or shall be subordinate to an entry containing a LINE clause." The second 03's only ancestor is the 01, which has no LINE clause -> compile-time error (COBOLNET0899's report-column-without-line arm, which does fire when no line was ever opened).
- **Observed:** BindReportEntry tests `line is null` where `line = st.Line`, set when any earlier entry opened a line and not cleared when the walk leaves that entry's subtree. The file already has the right predicate shape (SubordinateToLineClause, L2107) for §13.18.38.3 SR25d. Also: no negative golden witnesses even the no-LINE case.
- **Code site:** src/Cobol.Net.Compiler/Binding/DataBinder.Reports.cs#BindReportEntry (ReportColumnWithoutLine arm ~L1825)
