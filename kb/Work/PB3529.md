# PB3529 — the ONE build was not final

## What happened (2026-10-22 13:08 PDT)

The landing of `notes-pb3379-recurrence-20261022` (three kb/Work and DEVLOG files, no code) stopped on
`=== LINUX GATE: RED (failed or not run: conformance …) ===`. The one red was
`ConformanceSuiteRunnerDriftTests.BothRunners_GiveEverySuiteTestTheSameVerdict`: six suite tests PASS in process and
`run.py NO VERDICT (the compiler did not start: …/src/Cobol.Net.Cli/bin/Debug/net10.0/cobol: No such file or
directory)`, one of them `Text file busy`.

## Mechanism

`scripts/linux-gate.sh` builds the fresh clone ONCE (`dotnet build Cobol.Net.sln`, done 13:08:15) and runs every leg in
parallel against it; the `guard` leg runs `scripts/guard-fast.sh`, whose own `dotnet build` of the CLI was assumed
up to date. It was not: in the clone the frontend was recompiled at 13:08:30, the compiler at 13:08:42 and `cobol.dll`
and the `cobol` apphost at 13:08:42 (a new inode), while the conformance leg's drift test was running the apphost.

The cause is `src/Cobol.Net.Frontend/Cobol.Net.Frontend.csproj#EnsureGeneratedFiles`. The SDK's `CompileDependsOn` runs
`BeforeCompile`, then `_GenerateCompileDependencyCache` (it hashes `@(Compile)`, in order, into
`obj/…/Cobol.Net.Frontend.csproj.CoreCompileInputs.cache`), then `CoreCompile`, which recompiles when that cache is
newer than its output. The target ran `BeforeTargets="CoreCompile"`, after the hash, and appended `Generated/*.cs`
to Compile. On a fresh checkout `Generated/` is absent at evaluation, so the first build hashed a list without the
generated files; every later build's glob finds them, in the middle of the list, so the hash moved and the frontend and
every project above it recompiled. Repro (WSL): clone, `dotnet build Cobol.Net.sln -c Debug`, then
`dotnet build src/Cobol.Net.Cli/Cobol.Net.Cli.csproj -v d`: `Input file "obj/Debug/net10.0/Cobol.Net.Frontend.csproj.CoreCompileInputs.cache" is newer than output file "obj/Debug/net10.0/Cobol.Net.Frontend.pdb"`, and the apphost's inode changes.
Moving only the hook to `BeforeCompile` is not enough: the hash is ordered, and the first build appended the files
where the second globbed them mid-list (measured: the hashes still differed).

## Fix

`EnsureGeneratedFiles` runs `BeforeTargets="BeforeCompile"`, and its ItemGroup removes `Generated/*.cs` from Compile
and appends it on every build (MSBuild runs it when the target is skipped as up to date too), so both builds hash one
list. Measured on a fresh WSL clone: the second build changes nothing (`cobol` and `cobol.dll` keep their inode and
mtime). `AntlrGenerationDriftTests.TheTarget_AddsTheGeneratedFilesBeforeTheCompileInputsAreHashed` pins the hook and the
remove-then-append shape. `scripts/linux-gate.sh` fingerprints the CLI's output after the ONE build and reports
`build-rewritten` RED, naming the changed files, if it moves while the legs run, so a recurrence is named as itself
instead of as a red in whichever leg ran the binary.

**Sites:** `src/Cobol.Net.Frontend/Cobol.Net.Frontend.csproj`, `scripts/linux-gate.sh`,
`tests/Cobol.Net.Tests.Unit/AntlrGenerationDriftTests.cs`, `kb/Compiler/Build System.md`.

Sibling sweep: no other project file adds a Compile item from a target (`BeforeTargets=`/`AfterTargets=` in every
`*.csproj`, `*.props`, `*.targets`: the runtime's ReadyToRun targets and the CLI's publish and opt-in generation targets
add none). The mechanism is not Linux-specific: it also costs a fresh Windows worktree's second build a recompile of the
frontend and the projects above it (deduced from the SDK targets, not measured on Windows).
