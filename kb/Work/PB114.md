# PB114 — pictureLocalePhrase makes IS required before locale-name-1

**Measured 2026-08-28 (the PB64 T6 hardening sweep, read-only):** `CobolData.g4:371` reads
`cobolWord (IS cobolWord)? SIZE IS? integerLiteral` — the IS before locale-name-1 is REQUIRED when the name is
present, so `PIC ZZ9 LOCALE FR SIZE IS 12` is a parse error today. The §13.18.40.2 format-2 figure note
(specs/ISO_COBOL.md:17748) says `PICTURE`, `PIC`, `LOCALE`, `SIZE` are underlined and "`IS`,
`character-string-1`, `locale-name-1`, and `integer-1` are **not**" — and §5.2.3 makes a non-underlined
reserved word an OPTIONAL word. The same production already spells the SIZE half `IS?`: one rule, two
spellings, in one line.

**Fix (rides the PB64 T6 landing):** `(IS? cobolWord)?` — unambiguous because SIZE is a distinct token.
Pre-T6 the wrong arity was masked by the arm rejecting with COBOLNET1518 anyway; at T6 it would reject legal
source outright, so the fix lands with the feature.
