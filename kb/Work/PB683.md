# PB683 — OPEN — a compile-time guess about a run-time fact

Found 2026-09-05 by the `PB340` implementer (report §"New defect"), probe `<a9d94900 scratch>\PB340\probe-openshare.cob`.

## The rule

§9.1.15 makes the OPEN statement's SHARING phrase override the SHARING clause, so a connector opened
`OPEN INPUT SHARING WITH READ ONLY F-B` IS open for file sharing whatever its SELECT says; §9.1.16 makes a record
locked by another file connector inaccessible to it; §14.9.30.4 GR9/GR10 b) (`cite.py --check 14.9.30.4 "A value
is placed into the I-O status associated with file-name-1 to indicate the record operation conflict condition"` →
`OK 10) b)`) require the record operation conflict, I-O status '51'.

## The mechanism

`src/Cobol.Net.Compiler/CodeGen/Verbs/SequentialIoEmitter.cs#LockGoverned`:
`file.Sharing != SharingMode.None || file.LockMode is not null || lockPhrase != None || retry is not null || ignoringLock`
— every term is a compile-time fact about the SELECT or the statement; the OPEN statement's SHARING phrase is a
run-time fact it cannot see. Every verb that consults it is affected (READ, WRITE, REWRITE, DELETE and the keyed
twins), not only READ. §14.9.27.3 SR8 hides the `ALL OTHER` case (it forces a LOCK MODE clause, which sets
`file.LockMode`), which is why only the `READ ONLY` / `NO OTHER` spellings expose it — and why no existing test
could see it.

**Repro** (relative, two connectors on one host file seeded ALPHA/BRAVO): `F-A` declares `SHARING WITH ALL OTHER`
+ `LOCK MODE IS MANUAL`; `F-B` declares neither. Both OPEN INPUT, B's as `OPEN INPUT SHARING WITH READ ONLY F-B`
('00'). `READ F-A WITH LOCK` locks RRN 1. Then `READ F-B NEXT` → `ALPHA|00` (required '51', no record); the same
statement with `RETRY 0 TIMES` → '51'. The runtime governs correctly the moment it is reached; only the compile-time
gate is wrong.

## Fix

Delete the compile-time guess and route those verbs through their governed runtime entry unconditionally — each
already falls through to the plain path on a `_connectorShares` miss (PB340 left `ReadShared` returning the I-O
status with exactly that fall-through), so the predicate duplicates a decision the runtime makes correctly one layer
down. Sweep every caller of `LockGoverned` and the keyed emitter's equivalent; goldens for the `READ ONLY` and
`NO OTHER` OPEN-phrase spellings on all three organizations, with the plain-READ '51' control and the `RETRY 0
TIMES` discriminator. Dispatchable after train 12 lands (PB340 owns `ReadShared`'s new shape).
