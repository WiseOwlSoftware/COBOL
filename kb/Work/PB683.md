# PB683 — LANDED — a compile-time guess about a run-time fact

Found 2026-09-05 by the `PB340` implementer (report §"New defect"), probe `<a9d94900 scratch>\PB340\probe-openshare.cob`.

## The rule

§9.1.15 makes the OPEN statement's SHARING phrase override the SHARING clause, so a connector opened
`OPEN INPUT SHARING WITH READ ONLY F-B` IS open for file sharing whatever its SELECT says; §9.1.16 makes a record
locked by another file connector inaccessible to it; §14.9.30.4 GR9/GR10 b) (`cite.py --check 14.9.30.4 "A value
is placed into the I-O status associated with file-name-1 to indicate the record operation conflict condition"` →
`OK 10) b)`) require the record operation conflict, I-O status '51'.

## The mechanism

`src/Cobol.Net.Compiler/CodeGen/Verbs/SequentialIoEmitter.cs#LockGoverned`:
`file.Sharing != SharingMode.None || file.LockMode is not null || lockPhrase != None || retry is not null || ignoringLock`
— every term is a compile-time fact about the SELECT or the statement; the OPEN statement's SHARING phrase is a
run-time fact it cannot see. Every verb that consults it is affected (READ, WRITE, REWRITE, DELETE and the keyed
twins), not only READ. §14.9.27.3 SR8 hides the `ALL OTHER` case (it forces a LOCK MODE clause, which sets
`file.LockMode`), which is why only the `READ ONLY` / `NO OTHER` spellings expose it — and why no existing test
could see it.

**Repro** (relative, two connectors on one host file seeded ALPHA/BRAVO): `F-A` declares `SHARING WITH ALL OTHER`
+ `LOCK MODE IS MANUAL`; `F-B` declares neither. Both OPEN INPUT, B's as `OPEN INPUT SHARING WITH READ ONLY F-B`
('00'). `READ F-A WITH LOCK` locks RRN 1. Then `READ F-B NEXT` → `ALPHA|00` (required '51', no record); the same
statement with `RETRY 0 TIMES` → '51'. The runtime governs correctly the moment it is reached; only the compile-time
gate is wrong.

## Fix

Delete the compile-time guess and route those verbs through their governed runtime entry unconditionally — each
already falls through to the plain path on a `_connectorShares` miss (PB340 left `ReadShared` returning the I-O
status with exactly that fall-through), so the predicate duplicates a decision the runtime makes correctly one layer
down. Sweep every caller of `LockGoverned` and the keyed emitter's equivalent; goldens for the `READ ONLY` and
`NO OTHER` OPEN-phrase spellings on all three organizations, with the plain-READ '51' control and the `RETRY 0
TIMES` discriminator. Dispatchable after train 12 lands (PB340 owns `ReadShared`'s new shape).

## Landed

Fixed 2026-09-05. `SequentialIoEmitter.LockGoverned` is DELETED and there is no compile-time governance
predicate anywhere: `SequentialIoEmitter` (READ, WRITE, REWRITE), `KeyedIoEmitter` (both READ formats, WRITE,
REWRITE, DELETE) and `SortEmitter` (the §14.9.40.4 GR12 b) implicit READ and the GR15 b) implicit WRITE) each
render their governed runtime entry unconditionally, and the ungoverned renderers were removed from
`RuntimeApi` (`FileRead`, `FileWrite`, `FileWriteAdvancing`, `FileWriteBeforeAndAfter`, `FileRewrite`,
`FileReadKeyedNext`, `FileReadKeyedPrevious`, `FileWriteKeyed`, `FileRewriteKeyed`, `FileDeleteRecord`) along
with the facade entries that then had no caller (`CobolFile`/`FileRegistry` `Read`, `Rewrite`,
`WriteBeforeAndAfter`). Governance is decided one layer down, where the OPEN statement's own SHARING phrase has
been recorded: each governed body opens with a `_connectorShares` probe and falls through to the identical plain
body on a miss, so the added cost on a non-sharing connector is ONE dictionary probe per record verb.

**The sweep found a sibling the note did not name.** `EmitWrite` was a THREE-arm dispatch, and the two
print-control arms (`FileWriteAdvancing`, `FileWriteBeforeAndAfter`) were ungoverned — and, worse, those runtime
entries have no lock or RETRY parameter at all, so `WRITE R BEFORE ADVANCING 1 LINE WITH LOCK` (one legal
statement: §14.9.51.2 Format 1 prints the ADVANCING phrase, the retry-phrase and the `WITH LOCK` bracket
together) silently dropped both phrases. §14.9.51.4 GR10 and GR11 are ALL FILES rules, so the ADVANCING phrases
are the statement's PRESENTATION shape and now travel INTO `WriteShared` as a `WriteAdvance` descriptor, with
`WriteAnyOrg` dispatching the physical shape inside the governed body; `SequentialConnector.WriteAdvancing` and
`WriteBeforeAndAfter` count the record they release (§14.9.51.4 GR12) so GR11 has an identity to lock. `EmitWrite`
is now one call. Recorded as **D20** in `docs/COBOLNET_FILES_DESIGN.md`.

**Measured.** Before: `READ F-B NEXT` on a connector opened `OPEN INPUT SHARING WITH READ ONLY F-B` answered
`ALPHA|00` against another connector's lock; the same READ with `RETRY 0 TIMES` answered `51`. After: both
answer `51`. Before: `WRITE A-REC BEFORE ADVANCING 1 LINE WITH LOCK` left the record unlocked (the other
connector read on to `10`); after, the other connector is refused with `51`.

**Goldens.** `tests/conformance/2023/pb683_open_sharing_read_only` (the `READ ONLY` spelling on sequential,
relative and indexed, with the `RETRY 0 TIMES` discriminator), `pb683_open_sharing_no_other` (the `NO OTHER`
spelling in both open orders, §9.1.15 item 1's `'61'`, and the governed route still answering `'00'` where
record locks are ignored) and `pb683_write_advancing_governed` (the same WRITE in all three printed shapes).

**No inventory rows claimed.** The note owned none, and none of the rows this evidence touches
(`GR-9.1.15-1/2/3`, `GR-14.9.51.4-10/11/12`, `GR-14.9.30.4-9/10`) is FULLY covered by these goldens — each
carries obligations the goldens do not observe (see the report's "rows not claimed" list). Recording a partial
observation as CONFORMS would be a verdict without its evidence.
