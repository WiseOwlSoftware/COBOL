# PB5158 - at --std 85 a NOT phrase is accepted before its positive twin (NOT ON SIZE ERROR, NOT INVALID KEY, NOT AT END, NOT AT END-OF-PAGE, NOT ON OVERFLOW): the one shared conditionalPhrases loop has no edition arm for the printed order

**Sites:**

- `src/WiseOwl.Cobol.Frontend/Grammar/CobolParserCore.g4` (`conditionalPhrases`, `conditionalPhraseHead`)
- `src/WiseOwl.Cobol.Frontend/Parsing/ConditionalPhrases.cs` (`Associates`, `MayAssociate`)

**Mechanism.** Every 1985 statement format that carries a conditional phrase pair prints the positive phrase, then the NOT phrase, then the scope terminator, and the general formats fix that sequence (§1985:IV.2.1: "Clauses must be written in the sequence given in the general formats."). The compiler parses every such statement through ONE rule, `conditionalPhrases` (`({conditionalPhraseAssociates($ctx)}? conditionalPhrase)*`), whose predicate `ConditionalPhraseAssociation.Associates` / `MayAssociate` asks only that a phrase is printed by some format of the statement and is not yet written. Nothing asks the edition about the order, so the any-order reading the rows' change records attribute to the 2002 standard applies at --std 85 for all sixteen formats below: ADD, SUBTRACT, MULTIPLY, DIVIDE and COMPUTE (SIZE ERROR), STRING and UNSTRING (OVERFLOW), the sequential READ and WRITE (AT END, END-OF-PAGE), and the relative and indexed DELETE, READ, REWRITE, START and WRITE (INVALID KEY, AT END). The other 1985 statements with a phrase pair (CALL ON OVERFLOW, RETURN AT END, SEARCH, the relative REWRITE, START and WRITE) take the same loop; the code read did not record them, and the fix covers them by construction.

**Found by.** The 1985 code read (2026-11-10; its records are `E:/COBOL-coord/scratch/coderead-85/for-register.json`): each rule below was read against the code sites it names and probed at `--std 85`, and found non-conforming. Verdict, harm, evidence, repro and observed text are the records'; the rows' verdicts are recorded on another branch.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids of the list below.

Two rows carry a second, separate defect that this note does not own: 1985-FMT-IX.4.6.2 (REWRITE) also accepts the word RECORD after record-name-1 (kb/Work PB5159), and 1985-FMT-VI.6.6.2 (ADD) also accepts Format 2 with no operand before GIVING (kb/Work PB5203). Those rows close when both notes land.
