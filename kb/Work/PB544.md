### Expected, from the standard
`01 M USAGE MESSAGE-TAG.` is conforming COBOL-2023 and shall compile (or, if the facility is staged, be refused BY NAME with a COBOLNET0899-band diagnostic, never a parse error). `01 M USAGE MESSAGE-TAG USAGE DISPLAY PIC X(3).` shall be rejected by SR21.

### Observed
Both fail at the same token with an unnamed parse error -- `error COBOL0001: no viable alternative at input 'MESSAGE-TAG'` / `unexpected 'MESSAGE-TAG'` (u_sr21, u_sr21b) -- so nothing distinguishes the rule's violation from the phrase's absence, and a conforming 2023 program that declares a message-tag data item does not compile. The consequence reaches three rows of this part, not one: SR21 has no subject at all, and SR4's and SR14's message-tag arms are the single unverifiable arm in two otherwise-landed screens (u_sr4_msgtag). This is a general-format gap, so it also blocks the message-tag legs of rules in other clauses that already enumerate the class -- §8.5.2.9, §13.18.44.3 SR12/SR14, §14.9.11.3 SR1, §14.9.20.3 SR1/SR3/SR4, §13.16.3 SR8 (a sibling adjudication already records the §13.16.3 SR8 message-tag leg as unreachable for exactly this reason). The honest interim shape is the one FUNCTION-POINTER already has: parse the phrase at 2023+ and stage it loud by name, so the rules over it become adjudicable and the parse error stops masquerading as a syntax verdict.

## Landed

**RE-SCOPED ON A MEASUREMENT, then fixed at the one place the rule needed a subject.** Two of this note's three
rows no longer reproduced: the grammar surface landed with kb/Work PB487 (`usageKeyword` gained MESSAGE_TAG), so
`01 M USAGE MESSAGE-TAG.` is the NAMED Annex A.3 item-4 decline COBOLNET1943 this note asked for rather than
`COBOL0001`, and both `SR-13.18.60.3-4`'s and `SR-13.18.60.3-14`'s message-tag arms now fire -- MEASURED at
--std 2023 on this worktree's own build: `01 CFG CONSTANT RECORD. 05 Q USAGE MESSAGE-TAG.` is COBOLNET1726 naming
SR4, and `01 G USAGE MESSAGE-TAG. 05 M PIC X(3).` is COBOLNET1724 naming SR14. SR14's OTHER unverifiable arm --
FUNCTION-POINTER at elementary level, which could not fire while `ParseUsage` staged the usage loud and left `Pic`
null -- fires too, since USAGE FUNCTION-POINTER went live with kb/Work PB452 + PB817. All three now carry
witnesses instead of being re-implemented.

**`SR-13.18.60.3-21` is the one that was genuinely open, and its cause was an OVERWRITE.** 13.18.60.3 SR21 -- "If
MESSAGE-TAG is specified, no other usage clauses shall be specified in the data description entry" (`cite.py
--check` OK) -- had no subject at all: `DataBinder.BindEntry` kept a single `usageText` that each successive USAGE
clause overwrote, so `01 M USAGE MESSAGE-TAG USAGE DISPLAY PIC X(3).` bound as a plain DISPLAY item and compiled
with NO DIAGNOSTIC AT ALL, not even the decline, at every edition. A rule whose subject is the SET of usage
clauses cannot be written against a scalar, so the entry now keeps the clause LIST and
`CheckMessageTagExclusivity` reads it, raising COBOLNET2158 BEFORE and INDEPENDENTLY of the decline -- a declined
usage still has syntax rules over it -- in whichever order the two clauses are written.

**The screen is deliberately edition-blind and its witness deliberately is not.** Below 2023 MESSAGE-TAG is an
ordinary user-defined word and the edition-correct answer is the introduction gate, but that routing is broken for
the WHOLE MESSAGE-TAG surface and is one mechanism with one fix (see below). Gating only this screen would re-open
the silent acceptance below 2023 while leaving the sibling wrong, so the screen fires at every edition and
`tests/conformance/negative/pb544-message-tag-usage-exclusive` pins the 2023 cell ONLY -- a golden that also
pinned 2002 would freeze the defect it is waiting on.

Witnesses added: `pb544-message-tag-usage-exclusive` (2158), `pb544-usage-message-tag-in-constant-record` (1726,
SR4's arm), `pb544-usage-message-tag-group` (1724, SR14 arm A) and `pb544-usage-function-pointer-elementary`
(1724, SR14 arm B). All four rows re-verdicted to CONFORMS.

**Registered, not fixed here** (each a mechanism of its own, outside this note):
* A repeated USAGE clause with no message-tag arm -- `01 N USAGE DISPLAY USAGE BINARY PIC 9(3).` -- is accepted
  SILENTLY with the last clause winning. 13.16.2 Format 1 prints `[ usage-clause ]` ONCE, so this is a wider rule
  about clause repetition in a closed general format; the clause list added here is the structure it will be
  enforced from.
* COBOLNET1943 fires at --std 2002 and --std 2014 although its own message text says that below 2023 "the word is
  a user-defined word and the entry draws the ordinary introduction gate". It does not; the A.3 decline pre-empts
  the introduction gate.
* An inherited MESSAGE-TAG usage on a group draws COBOLNET1521, whose text names the FLOATING-POINT usages -- a
  wrong diagnostic for a message-tag item.
