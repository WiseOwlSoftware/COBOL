### Observed
Both fail at the same token with an unnamed parse error -- `error COBOL0001: no viable alternative at input 'MESSAGE-TAG'` / `unexpected 'MESSAGE-TAG'` (u_sr21, u_sr21b) -- so nothing distinguishes the rule's violation from the phrase's absence, and a conforming 2023 program that declares a message-tag data item does not compile. The consequence reaches three rows of this part, not one: SR21 has no subject at all, and SR4's and SR14's message-tag arms are the single unverifiable arm in two otherwise-landed screens (u_sr4_msgtag). This is a general-format gap, so it also blocks the message-tag legs of rules in other clauses that already enumerate the class -- §8.5.2.9, §13.18.44.3 SR12/SR14, §14.9.11.3 SR1, §14.9.20.3 SR1/SR3/SR4, §13.16.3 SR8 (a sibling adjudication already records the §13.16.3 SR8 message-tag leg as unreachable for exactly this reason).
