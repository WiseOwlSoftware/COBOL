# R16 — DISPLAY of an INDEX-NAME compiles clean and throws at run time instead of drawing a compile diagnostic

> R00 ledger-audit orphan (2026-08-08): F11 of `PHASE-B-15.32-15.44-findings.md`, probe-verified OPEN
> against the R10-landed tree (`5312996a`). The probe programs are reproducible from the finding text.

PROBE (2026-08-08): `SET IX TO 1. DISPLAY "SRCH=" IX.` — zero compile diagnostics, then
`NotImplementedCobolFeatureException: computed expression in a string context` (OperandText's
BoundComputedOperand arm). An index-name is not an identifier under §8.4.3.1.2, so the DISPLAY operand slot
does not admit it — the correct answer is a compile-time diagnostic naming the legal spelling
(`SET WS-I TO IX` then `DISPLAY WS-I`), never a silent accept that aborts at run time (§1.4 band).
FIX: a bind-time screen on the DISPLAY (and general string-context) operand path for BoundIndexRef.

## LANDED 2026-08-08

**The rule turned out sharper than the note's §8.4.3.1.2 framing: §13.18.38.3 r7 is a CLOSED LIST** — an
index-name may be specified only as a subscript, in PERFORM/SEARCH VARYING, in SET, or as a
relation-condition operand (cite-checked). Probing the siblings before implementing split the pattern:

- **The crash band** (DISPLAY IX · MOVE IX TO alphanumeric · STRING IX — "computed expression in a string
  context" runtime bombs) and **the silent band** (MOVE IX TO numeric — computed 0002 with no diagnostic)
  both fall to the new **COBOLNET1637** (`index-name-context`), screened at four sites: DISPLAY's operand
  walk, MOVE's sending operand (beside — and matching — the W2-landed COBOLNET0809 judgment that already
  rejects class-index DATA ITEMS in MOVE unconditionally), the ONE `StrUnstrSender` funnel serving all four
  STRING/UNSTRING sending positions, and INSPECT identifier-1 (a compile diagnostic replacing the
  unresolvable-item runtime stage). `IF IX = 2` still binds (r7-legal) — probe-verified.
- **The arithmetic band** (`COMPUTE N = IX + 1` computes 3 silently) is split to [[R29]] rather than fixed
  blind: the screen would live in `RefExpr`'s index arm, which ALSO serves the r7-LEGAL numeric consumers,
  so it needs an OperandContext audit plus the strict/--permissive survey (the GnuCOBOL extension shape).
