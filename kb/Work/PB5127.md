# PB5127 - at --std 85 a control footing's USE BEFORE REPORTING procedure runs before the crossfoot and roll-forward of its sum counters, so it reads the previous totals; 1985 steps a and b precede the USE procedure

**Sites:** `src/WiseOwl.Cobol.Runtime/IO/ReportWriter.cs#BeginGroup` (snapshot, then `ApplyRolled`, then `RunBeforeReporting`: the group's own crossfoot and roll-forward precede its USE procedure, every edition); witness `conformance-suite/cases/14.9.49-USE/pb5127_use_before_reporting_sees_crossfoot`; landed with PB5128 (one root, ReportWriter.cs).

**Mechanism.** §1985:XIII.3.20.4 GR10 orders the processing of a control footing: a, crossfoot the sum counters; b, roll them forward into higher-level counters; c, execute the USE BEFORE REPORTING procedure; d, SUPPRESS skips to f; e, present; f, reset the counters. ReportWriter.BeginGroup runs the USE procedure first and applies the crossfoot and roll after it. The report file prints the crossfooted totals, so the additions are made, but a USE procedure that tests or edits a crossfooted or rolled-forward total acts on the previous value (for example SUPPRESS PRINTING when the total is zero). 2023's own order (§2023:14.9.49.4 GR9 b "After incrementing sum counters defined in the report group") is the same for a same-group addend. kb/Work PB5022 and PB5048 are the 85 acceptance of the same-group crossfoot, PB1272 and PB1294 the presence snapshot and the rolled-total checks; none records the order against the USE procedure. The other five lines of the draft match (including the reset of a SUPPRESSed footing).
