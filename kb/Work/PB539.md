# PB539

## Mechanism — synchronized-clause
sync-group-as-if-not-propagated - 13.18.55.4 GR1's as-if treatment has no code. `01 G SYNCHRONIZED.` records the flag on the GROUP entry (DataBinder.cs:2308-2309) and nothing ever copies it to the subordinate elementary items, so no leaf is ever 'described with a SYNCHRONIZED clause' for the rules that ask that question. The compiler already owns the pattern twice - InheritSignClauses (DataBinder.cs:3437-3447) walks a group's SIGN down to its signed display leaves, and UsageInheritancePass/InheritUsageClauses does the same for USAGE - and neither has a SYNCHRONIZED arm, so this is a missing arm of an existing dispatch, not a new mechanism. The LAYOUT half of GR1 is satisfied vacuously and measurably (with no alignment, group-level and per-leaf SYNCHRONIZED produce the identical record), which is why the harm is latent; the FLAG half is what is missing, and its three consumers are 13.16.3 SR24 d) (a condition-name may not be associated with 'A group containing items described with a JUSTIFIED or SYNCHRONIZED clause'), 13.18.63.3 SR14, and 13.18.58's type-equivalence characteristic list. The fix is one Walk beside InheritSignClauses, which also makes the SR24 d) and type-equivalence work land correctly whenever those rows are taken up.

### Expected, from the standard
13.18.55.4 GR1 - 'When this clause is specified for a group item, it is treated as though it had instead been separately specified for each of the subordinate elementary items for which this clause is permitted.' Annex E.3.2 item 6 - 'This clause may now be specified for a group level data item, when it is treated as though it had been independently specified for each contained elementary data item for which it is permitted.' So after binding `01 G SYNCHRONIZED.` over elementary leaves, each leaf for which the clause is permitted shall be indistinguishable from a leaf that wrote SYNCHRONIZED itself - including for 13.16.3 SR24 d), which forbids a condition-name on 'A group containing items described with a JUSTIFIED or SYNCHRONIZED clause'.

## Landed (wave 20261032, group A)

**Fix.** `DataBinder.InheritSynchronized` (new `DataBinder.SynchronizedClause.cs`) is §13.18.55.4 GR1's missing arm:
each subordinate elementary item takes the clause (its LEFT/RIGHT phrase too, PB538) the nearest enclosing group wrote,
unless its own entry wrote one, and only where the clause is permitted: nothing is handed down below a group-level VALUE
(§13.18.63.3 SR14) or a CONSTANT RECORD (§13.16.3 SR13). A TYPE declaration takes it at the end of `ExpandTemplate`,
before any TYPE subject copies its members (§13.18.57.4 GR1 excludes only the declaration's OWN alignment, and under
GR1 the group's clause was "instead" its leaves'); the storage forest at the end of `ExpandTypes`, so a TYPE or SAME AS
subject that writes the clause reaches the leaves it copied. Every consumer reads one fact: the §8.5.3.1 comparison and
key (`StrongTypeModel`), the §13.16.3 SR24 d) screen (which now reads the members only: a group whose clause reaches no
member contains none), §13.18.63.3 SR14 and the CONSTANT RECORD screen.
