# PB6107 - LANDED - 2002 programs raise the 2014 names for the omitted-argument and function-not-found conditions

Two leads of the PB5599 report (new defect 1 and review R1-1) are one mechanism: the compiler raises each exception condition under one edition-blind name, the 2014 and
2023 one, and at `--std 2002` the standard names a different condition. Re-verified on main ae1136f781:

- **Omitted argument.** `§2002:8.4.2.2.3 GR7` ("If a parameter for which the omitted-argument condition is true is referenced in an activated function ... the
  EC-PROGRAM-ARG-OMITTED exception condition is set to exist") and `§2002:14.8.22.3 GR10` (the same for an invoked method) name EC-PROGRAM-ARG-OMITTED (both found by
  `cite.py --find "EC-PROGRAM-ARG-OMITTED" --edition 2002`; the exception-names table `§2002:14.5.12.1.5` lists only that name). The emitter table
  `src/WiseOwl.Cobol.Compiler/CodeGen/EcEmitter.cs:482-483` raises `EC-FUNCTION-ARG-OMITTED` for a function and `EC-OO-ARG-OMITTED` for a method at every edition.
- **Function locate miss.** `§2002:8.4.2.2.3 GR5` ("If the function is not found, the EC-PROGRAM-NOT-FOUND exception condition is set to exist") names EC-PROGRAM-NOT-FOUND.
  `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/EcBinder.RaiseDeclarations.cs:139` declares `FunctionActivationNames = ["EC-FUNCTION-NOT-FOUND"]`,
  and `CallEmitter.cs:273` and `HostEntryEmitter.cs:239` pass `notFoundEc: "EC-FUNCTION-NOT-FOUND"` for a function. PB5599's landing refuses EC-FUNCTION-NOT-FOUND at 2002, so no
  2002 source can enable or catch the condition the compiler raises. The reviewer reports the same for `SET ... TO ADDRESS OF FUNCTION`
  (`EcBinder.RaiseDeclarations.cs:284`, `PtrEmitter.cs:352`); that arm was not re-derived against the 2002 text here.

**Landed (wave 20262150 group E).** Re-probed on the branch build: at 2002 `>>TURN EC-FUNCTION-ARG-OMITTED` is refused (COBOL0878), so no 2002 source could enable the name the guard raised, and `>>TURN EC-PROGRAM-ARG-OMITTED` enabled nothing for a function (the guard raised through `FunctionArgOmittedError`, whose flag only that refused name could set; probe `fn_omit_2002` after the fix prints `F-CAUGHT 01=EC-PROGRAM-ARG-OMITTED` at 2002). The fix is ONE table: `ExceptionCatalog.NameInEdition` (rows `EC-FUNCTION-ARG-OMITTED`, `EC-OO-ARG-OMITTED` to `EC-PROGRAM-ARG-OMITTED`, `EC-FUNCTION-NOT-FOUND` to `EC-PROGRAM-NOT-FOUND`), asked by `EcBinder.EcWrap` (each declared name), `EcBinder.MarkFormals` (the TURN query and the guard's kind, `OmittedFormal.RaisedKind`) and the activation emitters (`CallEmitter.InvocationText`, `HostEntryEmitter`), with the runtime told "function activation" by `asFunction` instead of reading it off the name (`ProgramRegistry.CallProgram`, `ProgramTable.CallProgram`/`Activate`/`Create`). The `SET ... TO ADDRESS OF FUNCTION` arm (`EcBinder.RaiseDeclarations.cs`, `PtrEmitter.cs`) is unreachable below 2014: `USAGE FUNCTION-POINTER` is refused at 2002 (COBOL0900), so its 2014 names stand. Tests: `conformance:cases/8.4.2.2@2002-FUNCTION-IDENTIFIER/pb6107_function_arg_omitted_2002` (refused twin `pb6107_function_arg_omitted_name_refused_2002`), `ArgOmittedConditionTests.ElementaryReference_At2002_RaisesEcProgramArgOmitted`, `InterProgramFileDifferentialTests.Udf_AbsentFunctionDefinition_RaisesTheEditionsLocateMissCondition`, `EditionExceptionNameTests`.
