# PB3667 — gen_ledger.measure_commits' docstring states a peak memory of one inventory (7.5 MB); the measured peak over 150 commits is 167 MB

**Sites:** `scripts/spec/gen_ledger.py#measure_commits` (docstring, ~line 433; present on branch `worktree-wf_f39d3ad7-d92-12`, PR #523, until it merges).

## What happens

The docstring says each blob is reduced to its summary as it arrives and dropped, "so the peak memory is one inventory (7.5 MB), not one per distinct version". Each inventory blob is decoded and parsed by `json.loads` into row objects before the reduction, so the parsed form is far larger than the 7.5 MB blob. The finisher's own measurement (the PB3647 report and its DEVLOG paragraph) is 167 MB peak over 150 commits, about twenty times the stated figure.

## Fix direction

Correct the sentence to the measured figure and say what it counts (a parsed inventory, not its blob), or state the bound structurally (one parsed inventory at a time) without a number that drifts. The memory behavior itself is as designed; only the comment is wrong.
