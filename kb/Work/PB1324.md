# PB1324 — OPEN — a seam change the seam filter does not cover

## What happened
Train 59's cluster KD (PB444 + PB446) tightened SEARCH's grammar and NEXT SENTENCE placement. Its implementer
gate ran the practice-I1 filter (`MANDATORY-PRACTICES.md` I1: own tests + `~Drift|~EditionGate` + Unit, and
`~CorpusRunner|~Nist` for a shared seam such as `.g4`). The gate was green. The lander's WHOLE-assembly gate
(practice L2) then went red on `RedefinesSubscriptedViewDifferentialTests`, a differential class that
compiles programs using the tightened construct. The lander caught it, as L2 is designed to. The cost was a
re-gate and a fix inside the train, where the implementer could have fixed it for the price of one filter term.

## The shape
The I1 filter selects tests by class name. The classes a seam change can break are the ones that COMPILE COBOL
through the changed seam. That set is not the drift/edition/corpus classes alone: every `*DifferentialTests`
class, and every conformance-test class that compiles inline source, is in it.

## What the fixer owes
- Extend I1's shared-seam term with `~Differential` (measure the added wall time at BelowNormal and record it), or
  better, derive the seam set: a `.g4` or `DataBinder*` change selects every test class that compiles source.
  That is a trait or category on the class, checked by a drift test, not a hand-maintained name list.
- Update `MANDATORY-PRACTICES.md` I1 and `make_dispatch_specs.py`'s rendered gate line in the same change, so
  `check_practices.py` enforces the new term.
