# PB5806 - at --std 85 GROUP INDICATE is accepted on an entry with no COLUMN clause

**The checker rates this medium, and the fix reverses half of the landed kb/Work PB5243, so the implementer reads that note's reasoning first.** PB5243 (landed) built the 85 arm on Table 1 alone; the fix reverses its GROUP INDICATE half only (JUSTIFIED and BLANK WHEN ZERO without COLUMN have no such rule). Ruling: UPHELD (a), wrong at 85 only. Harm: under_rejects. The checker's confidence: medium.

**What is wrong.** An elementary report entry with GROUP INDICATE and no COLUMN clause compiles at `--std 85` with no diagnostic (`gi_nocol.cob`); at 2023 it is refused COBOL2519 ("GROUP INDICATE but has no COLUMN clause"). The 1985 rule requires a printable item (`§1985:XIII.3.13.3 SR1`), and the 1985 definition of a printable item requires a COLUMN NUMBER clause (`§1985:III.2`).

**Mechanism (the checker's reading).** Table 1 (`§1985:XIII.3.9.3 SR11`; page 605 rendered: rows 3 and 4 print COLUMN `P` and GROUP INDICATE `P`, faithfully transcribed) lists combinations that are permissible, not sufficient. SR8a states the same printable-item condition for USAGE over the same `P` cells, and the binder already enforces SR8a. A program must meet every syntax rule, so the entry is refused at 85 as at 2023. Page 624 (folio XIII-43) is scanned, not reconstructed.
