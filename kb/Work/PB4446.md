# PB4446 — EVALUATE's Table 15 refusal hides the operand's own faults

**Observation (PB4433's finisher, low priority, shares no root with PB4433).** With a container GLOBAL `88 RELF` and a
contained `01 RELF PIC 9`, `EVALUATE TRUE WHEN RELF (1) DISPLAY "B" END-EVALUATE.` (repro line 21 of
`E:/COBOL-coord/scratch/w20261824c/p3.cob`) reports only COBOL1634 (Table 15) and not the identifier's own COBOL2096
(§8.4.2.3.3 SR2, the subscript on a non-table item), which the other operand positions of that file (IF NOT, AND, PERFORM
UNTIL, EVALUATE subject and object, `= 3`) each report. The report states that "whether Table 15 should stop the operand
resolution is a separate question, unprobed against a no-88 control".

**Decided (adjudication w20261861 c, 2026-11-04).** The no-88 control (`EVALUATE TRUE WHEN RELF (1)` over a plain
`01 RELF PIC 9`) also reports COBOL1634 alone, so the hidden condition-name plays no part. When Table 15 (§14.9.13.3
SR10) refuses a pair, `EvaluateBinder.BindWhenItem` returns `Constant(false)` before the selection OBJECT is bound,
and every fault in that object's own reference goes unreported: undefined (COBOL1639), ambiguous (COBOL1639), a
subscript on a scalar (COBOL2096, §8.4.2.3.3 SR2), an unsubscripted table element (COBOL2270, SR5), refmod position 0
(COBOL2670), an alphanumeric operand in an arithmetic expression (COBOL0844, §8.8.1.1) and a bad function argument
(COBOL1627). The same goes for the range, condition-2 and partial-expression rows, and for the surplus objects of a
phrase that breaks SR2 (the `Bind` loop clamps to `min(objects, subjects)` and never binds the rest). These are
independent syntax-rule violations, and §4.2.2 requires the warning mechanism "to indicate violations of the general
formats and the explicit syntax rules". The compiler already reports them for every subject, for a condition-name
object and for every permitted pair, and GnuCOBOL 3.2 reports the operand fault in each probe. **Fix:** on the
refused-pair path, and for each surplus object, bind the object's operands standalone by their own Table 15 row (no
subject, no relation checkpoint, no TRUE/FALSE-as-condition), so the pair's secondary checks stay suppressed and the
operand's own faults are reported. `docs/CONDITIONS_EXCEPTIONS_DESIGN.md` §D5a ("A Table 15 refusal ends the pair's
binding") and §D5b's SR2 recovery sentence change with it. Probes:
`E:/COBOL-coord/scratch/op-w20261861/c/p/` (c1, c3, s01 to s27). Determination:
`E:/COBOL-coord/scratch/op-w20261861/c/determination.md`.

**Sites:** `EvaluateBinder.cs` (`EvaluateBinder.BindWhenItem`, `EvaluateBinder.ScreenPairing`, `EvaluateBinder.Bind`'s pairing loop, `EvaluateBinder.BindSurplusObject`, `EvaluateBinder.BindObjectOperandsStandalone`, `EvaluateBinder.BindRangeObject`); `ConditionBinder.cs` (`ConditionBinder.BindPartialOperandsStandalone`); `docs/CONDITIONS_EXCEPTIONS_DESIGN.md` §D5a, §D5b.

**Landed (wave 20261863 group D).** Re-probed on the build: every probe reproduced (a refused pair printed COBOL1634 alone, a surplus object COBOL2106 alone). `BindWhenItem` now binds a refused pair's object standalone by its own row (`BindObjectOperandsStandalone`), `Bind` binds each surplus object the same way (`BindSurplusObject`), the range arm's operands, SR4/SR9 screen and IN phrase are one `BindRangeObject` shared by the pair and the standalone path, and `ConditionBinder.BindPartialOperandsStandalone` binds a partial-expression's own operands with no subject. Goldens: `conformance-suite/cases/14.9.13-EVALUATE/pb4446-*` (three refusals) and `EvaluateObjectOperandFaultTests` (the exact code set of 24 statements, including the guards that must keep drawing COBOL1634 alone).
