# PB4446 — does EVALUATE's Table 15 verdict hide the operand's own COBOL2096

**Observation (PB4433's finisher, low priority, shares no root with PB4433).** With a container GLOBAL `88 RELF` and a
contained `01 RELF PIC 9`, `EVALUATE TRUE WHEN RELF (1) DISPLAY "B" END-EVALUATE.` (repro line 21 of
`E:/COBOL-coord/scratch/w20261824c/p3.cob`) reports only COBOL1634 (Table 15) and not the identifier's own COBOL2096
(§8.4.2.3.3 SR2, the subscript on a non-table item), which the other operand positions of that file (IF NOT, AND, PERFORM
UNTIL, EVALUATE subject and object, `= 3`) each report. The report states that "whether Table 15 should stop the operand
resolution is a separate question, unprobed against a no-88 control".

**To decide.** (1) Probe the same line with no `88 RELF` (control, as `p2.cob` did for PB4433). (2) If the control also
gives only COBOL1634, the behaviour is the EVALUATE operand-combination arm and the question is whether a second,
independent fault in an operand must still be reported once Table 15 has refused the pairing; if the control gives both,
the 88 case is a defect in how the hidden-condition predicate interacts with the EVALUATE WHEN-TRUE arm. Cite checked
against the standard before any change.
