# PB4307 - At `--std 85` `MULTIPLE FILE TAPE.` / `MULTIPLE FILE.` with no file-name compiles clean; GnuCOBOL -std=cobol85 (and ibm, mf) refuse; `TAPE CONTAINS.` already draws COBOL0001

Found by the Mythos front-end review, gap pass, 2026-10-31 (GAP-REVIEW.md, G3-3; artifact https://claude.ai/artifact/KaxkLe85tfZBZ3nZ1tDGTs). Pin e62fbdc35.

**Sites:** `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolIO.g4:370-376` (`multipleFileClause`, `multipleFileTapeEntry`); `src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs:702-704` (`VisitMultipleFileClause`); `src/WiseOwl.Cobol.Compiler/Validation/IntegerOperandPass.cs:111, :204`.

**Finding.** `multipleFileClause` (CobolIO.g4:370-376) makes the whole `{file-name [POSITION integer]}...` list optional: `MULTIPLE FILE TAPE.`, `MULTIPLE FILE.`, `MULTIPLE FILE TAPE SAME AREA FOR F1 F2.` compile rc 0 at 85 (`r3a`, `r3b`, `r3e`); `cobc -std=cobol85`, ibm and mf all refuse ("unexpected ., expecting Identifier"). ISO 2023 prints no format; the 2002 F.1 lists the clause among removed obsolete elements (t2002.txt:43057); every CCVS use names a file. The compiler is inconsistent with itself: `TAPE CONTAINS.` already draws COBOL0001.

**Fix direction.** Fix by name in VersionConformancePass.VisitMultipleFileClause (:702-704), which owns the clause, NOT in the grammar: a required list would fall to the I-O-CONTROL error production's COBOL1970 "'<word>' is not a clause", false at 85 and losing the named COBOL0902 at 2002+ (r3g shows the COBOL1970 trap). 85 negative goldens; a CobolIO.g4 comment marking the optionality deliberate.

**Evidence.** E:/COBOL-coord/scratch/w-gr2/GAP-REVIEW.md (sections 2 and 5.1); G3/r3a-r3g; review-G3.md. Probe names are copied from the shard reports; the refuter folders are E:/COBOL-coord/scratch/w-gr2/G*-refute/. Shard reports: E:/COBOL-coord/scratch/w-gr2/review-G*.md.

## Landed (wave 20261825 group A)

**Re-probe** (pre-fix build): `MULTIPLE FILE TAPE.` and `MULTIPLE FILE.` compiled and ran at `--std 85` (rc 0, `OK`);
at 2002 each drew only COBOL0902; `MULTIPLE FILE TAPE CONTAINS.` drew COBOL0001 at both.

**Fix.** The I-O-CONTROL clauses' own syntax rules live in `DataBinder.BindIoControl` (SAME's beside them), so the
check is there, not in the edition-gate pass the note proposed: `DataBinder.ScreenMultipleFileClause` refuses a clause
with no `multipleFileTapeEntry` with the new COBOL5944 (`multiple-file-names-no-file`) at every edition. From 2002 the
clause is also COBOL0902, and a removed clause written without its files is malformed too. The grammar keeps the list
optional, and a CobolIO.g4 comment says why (COBOL1970's trap). The 85 format is derived, not quoted (GnuCOBOL
cobol85/ibm/mf), and the descriptor says so.

**Goldens:** `cases/_unassigned/pb4307-multiple-file-tape-names-no-file` and `pb4307-multiple-file-names-no-file`
(COBOL5944 at 85, 2002, 2014, 2023). `cases/_unassigned/multiple-file-tape` (a named file) still compiles at 85.
