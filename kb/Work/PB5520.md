# PB5520 - EvaluateOperandCombinations.cs quotes text the 1985 standard does not contain, attributed to VI.6.13.3 SR6 and VI.6.13.4 GR1

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/EvaluateOperandCombinations.cs` (whole: the doc comments carrying the two quotations are on the PB5481 branch, not main)

**Where the code is.** The quotation is NOT on main at filing: it is on the PB5481 branch `origin/worktree-wf_2e8662c7-06c-30`, where line 72 reads `... §1985:VI.6.13.3 SR6 a asks only that a selection object be "a valid operand for comparison to the corresponding operand in the set of selection subjects"`. On main, line 72 of the file is another line. The fix lands after PB5481's branch does.

**Mechanism (rule 1, an inherited citation).** The comment attributes two quotations to the 1985 standard that its text does not contain. The standard says "must be valid operands for comparison ..." (§1985:VI.6.13.3 SR6a) and "are assigned ..." (§1985:VI.6.13.4 GR1b); "is assigned the value and class of the specified literal" is the 2002/2023 GR wording. Mechanical check, this session:

- `python scripts/spec/cite.py --check "§1985:VI.6.13.3 SR6" "a valid operand for comparison to the corresponding operand in the set of selection subjects"` printed `FAIL [text-not-found]: §1985:VI.6.13.3 SR6: 'a valid operand for comparison to the corresponding operand in the set of selection subjects' is nowhere in the 1985 transcription (run --find on a fragment of it)`
- `python scripts/spec/cite.py --check "§1985:VI.6.13.4 GR1" "is assigned the value and class of the specified literal"` printed `FAIL [text-not-found]: §1985:VI.6.13.4 GR1: 'is assigned the value and class of the specified literal' is nowhere in the 1985 transcription (run --find on a fragment of it)`

No behavior is wrong (harm none); the comment misattributes. **Fix:** requote the 1985 text as it reads, or attribute the "is assigned" wording to its 2002/2023 clause, each through `cite.py --check`; sweep the PB5481 diff for other inherited quotations.
