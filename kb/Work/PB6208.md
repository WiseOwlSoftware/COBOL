# PB6208 - OPEN - does bare `ALTER.` / `ENTER.` compile at --std 2023, and should it?

**Lead, not a verdict.** PB6119's implementer probed `ALTER.` and `ENTER.` (and a `COMMIT.`-class probe) at --std 2023 and
grepped the output for the word "error" only: no error line appeared. The result may be a warning, an accepted empty
statement or a real silent accept. Nothing here was verified as a defect.

**What the adjudicator decides.** Whether the general formats of ALTER (an archaic element: procedure-name-1 TO
procedure-name-2 required) and ENTER make the bare keyword illegal, which edition each statement belongs to, and what the
compiler emits for each (read the full output, the exit code and the emitted program, not a grep for "error"). The clause
citation is left to the adjudicator, who checks it with `python scripts/spec/cite.py --check` before writing it; the PB6119
report named a clause that was not re-derived here.

**Repro.** A program whose procedure division holds the sentence `ALTER.` (and another with `ENTER.`), built with
`--std 2023`; read all of the output.

**Sites:** none (an analysis; the code site is found by the adjudication)
