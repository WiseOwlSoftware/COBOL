# PB5208 - an integer argument of an intrinsic function admits an exponentiation with a negative or fractional exponent (FUNCTION MOD (N ** -1, 7), N ** 0.5, N ** M with M signed): NotAlwaysIntegral has no arm for a power and fails open, so the program runs on a truncated argument

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/IntrinsicArgumentRules.cs` (`NotAlwaysIntegral`, `ProvablyIntegral`, `IntegerViolation`)
- LANDED: `src/WiseOwl.Cobol.Compiler/Binding/IntrinsicArgumentRules.cs` (`PowerWitness`, the power arm `NotAlwaysIntegral` calls at the root); `docs/INTRINSICS_DESIGN.md` (the type-6 intake section)

**Mechanism.** An integer argument position takes "An arithmetic expression which will always result in an integer value" (§1989:A.2.2 AR4; the 2023 type 6 says the same). `IntrinsicArgumentRules.NotAlwaysIntegral` refuses an argument only on a witness: a root quotient of a bare item by a literal, an additive spine over a scaled item, or a literal constant that is not an integer. Every other shape returns null and the screen FAILS OPEN. A power has no arm, although `ProvablyIntegral` already knows that a power is integral only when its exponent is a non-negative integer literal. So `N ** -1`, `N ** 0.5` and `N ** M` with M signed pass the screen, and the program runs on the argument truncated to an integer. The compiler refuses `N / 2` at the same position (COBOL1627), so the rule is enforced for one non-integral shape and not for another. No edition arm is involved: the same code runs at every `--std`.

**Rules (1; every citation checked with `scripts/spec/cite.py --check`).**

- `1989-AR-A.2.2-4` - `§1989:A.2.2 AR4` (refuter: OVERTURNED, harm: under-rejects). §1989:A.2.2 AR4: "An arithmetic expression which will always result in an integer value must be specified." With N PIC 9 VALUE 3, `N ** -1` is 0.333... and `N ** 0.5` is 1.732..., so neither always results in an integer, and `N ** M` with M PIC S9 does not either (M = -1). The ALL-subscript half of the row held (ORD-MAX and ORD-MIN over TC (ALL, ALL), TC (ALL, 2), an ODO range), as did the refusals of N / 2, a PIC 9V9 item and NUMVAL at an integer position.

**Repro (`ia1.cob`).** `cobol.exe --std 85 --source-format fixed --run ia1.cob`

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. IA1.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  N PIC 9 VALUE 3.
       01  M PIC S9 VALUE -1.
       01  R PIC S9(4).
       PROCEDURE DIVISION.
       P1.
           COMPUTE R = FUNCTION MOD (N ** -1, 7).
           DISPLAY "A " R.
           COMPUTE R = FUNCTION MOD (N ** 0.5, 7).
           DISPLAY "B " R.
           COMPUTE R = FUNCTION MOD (N ** M, 7).
           DISPLAY "C " R.
           COMPUTE R = FUNCTION FACTORIAL (N ** -1).
           DISPLAY "D " R.
           STOP RUN.
```

**Observed (current main, 3d12682fd2, rerun 2026-11-10).** exit 0, no diagnostic; the program prints `A +0000`, `B +0001`, `C +0000`, `D +0001`. Control: the same program with `FUNCTION MOD (N / 2, 7)` is refused, exit 65, `error COBOL1627: FUNCTION MOD argument-1 divides a data item of scale 0 by the literal 2, which does not always result in an integer value`.

**Expected (from the 1985 text).** Each of the four COMPUTE statements is refused at its argument, as `N / 2` is: no argument written there always results in an integer value (§1989:A.2.2 AR4).

**Fix direction (root cause, CLAUDE.md rule 4).** Give `NotAlwaysIntegral` a power arm built on the reading `ProvablyIntegral` already has: a power whose exponent is a literal that is negative or not an integer, over a base that is not provably 0 or 1, has a valuation that is not an integer; a power whose exponent is a signed item has the same witness at the exponent's negative values. Keep the screen's one reading of "always integral" shared with `ProvablyIntegral` (one table of shapes with a witness each), and pair it with a test that every BoundExpr shape `ProvablyIntegral` rejects is either a witness arm of the screen or recorded as fail-open.
