# PB887 — LANDED — the arm list a general rule says should not exist, and the arm it is missing

Source: the `PB420` report, "New defects" items 1 and 2. The report asked for **ONE note for the pair**,
because both live in the arm list GR6 says should not exist; this is it.

## Arm A — the measured abort

`<scratch>/reg6/probe/p32_accept_float.cob` (PROGRAM-ID `R6P32`), `--std 2023 --run`:

```cobol
01 F USAGE COMP-2.
PROCEDURE DIVISION.
    ACCEPT F
```

```
Unhandled exception. CobolNet.Runtime.NotImplementedCobolFeatureException: ... ACCEPT into floating-point
receiver 'F' (COMP-1/COMP-2 device conversion, deferred)
rc=127
```

The identical statement into `PIC 9(8)` reads the device fine.

```
$ python scripts/spec/cite.py --check 14.9.1.4 "Any conversion of data required between the device and the data item referenced by identifier-1 is defined by the implementor"
  OK  §14.9.1.4 1)  (General rules)
      1) The ACCEPT statement causes the transfer of data from the device. This data replaces the content of
      the data item referenced by identifier-1. Any conversion of data required between the device and the
      data item referenced by identifier-1 is defined by the implementor.
```

The conversion is OURS to define, and §14.9.1.3 SR1 excludes only index, message-tag, object and pointer — a
float receiver is legal source. **The mechanical blocker is that the device window is
`DataItem.DisplayTextWidth`, which is `pic.Digits + sign` for a numeric receiver, and a float PICTURE has no
digit positions.** Closing it therefore needs a §7 CONFORMANCE determination (transfer width + the accepted
character syntax), so it is an ADJUDICATION-FIRST item — the determination is published in
`docs/CONFORMANCE.md` §7 with a drift test reading the number back, the way PB463's A.1 item 62 was.
