# PB88 — LANDED 2026-08-18 — `STRING "12" DELIMITED SIZE INTO GP(3:3)` compiled clean and died at run time

> ⚙ **flags:** crashes (a run-time NotImplemented for ILLEGAL source — the wrong stage), under-rejects (the
> program compiles) · found 2026-08-18 by the PB70 context sweep (a STRING INTO a group ref-mod probe) · fixed the
> same session (DEVLOG 1307).

**Measured** (`--std 2023`): `STRING "12" DELIMITED SIZE INTO GP(3:3)` → compiles without a diagnostic and aborts at
run time with `NotImplementedCobolFeatureException: STRING INTO a reference-modified receiver (ISO §14.9.43.3 SR4)`.
§14.9.43.3 SR4: "Identifier-3 shall not be reference-modified." — the source is ILLEGAL and the standard's
disposition is a compile-time rejection; SR5 (an edited identifier-3, or one with JUSTIFIED) and SR6 (a strongly-typed
group) are the same shape in `StringUnstringBinder.BindString` (`BoundUnsupported` for SR4/SR5; SR6 unchecked), and
SR11 / §14.9.48.3 SR10 (a variable-length group operand) is not checked at all.

**Mechanism:** `StringUnstringBinder` returns `new BoundUnsupported("STRING INTO a reference-modified receiver …")`
— the §1.4 loud stage meant for UNIMPLEMENTED legal constructs — where a syntax-rule violation calls for
`ctx.Edition.Error(...)`.

**Landed (2026-08-18):** ONE helper — `StringUnstringBinder.Reject` — reports **COBOLNET1651** and returns the
`BoundUnsupported` as the backstop; every syntax-rule site calls it: STRING SR4 (ref-modified INTO), SR5 (edited —
and its JUSTIFIED half, unchecked before), SR6 (a strongly-typed group INTO — unchecked before), SR7 (POINTER not an
integer without P), SR11 (a variable-length group — `ReferenceResolver.HasVariableLengthSubordinate`, the ONE
§8.5.1.12 predicate, unchecked before); UNSTRING SR2 (sender category), SR5 (COUNT IN / TALLYING integers), SR6
(POINTER), SR7 (DELIMITER IN / COUNT IN without DELIMITED BY), SR10 (variable-length group operands). An
UNRESOLVABLE name keeps the bare stage (the resolver reported it). Eight negatives `pb88-*`; ten verdicts
SR-14.9.43.3-{4,5,6,7,11} + SR-14.9.48.3-{2,5,6,7,10} → CONFORMS (GAP 4029 → 4019).

**Original fix design:** one diagnostic (COBOLNET1648 `string-receiver-not-permitted`) covering SR4 (ref-modified), SR5
(edited / JUSTIFIED), SR6 (strongly-typed group), SR11 (variable-length group; the same for §14.9.48.3 SR10's UNSTRING
operands via a shared `IsVariableLengthGroup`), emitted at bind; the `BoundUnsupported` returns become errors. Two
negatives per rule family. `ReferenceResolver.RefModExclusion`'s variable-length-group walker
(`HasVariableLengthSubordinate`) is the ONE predicate to reuse — do not write a second.
