# PB3114 — a RED plan still holds its notes and burns its codes

> ⚙ **flags:** silent · process

Found by wave unit 1070 (2026-10-12 18:30 PDT), on its first planner run.

**What happened.** The unit ran step 2 of its prompt from Git Bash with the prompt's Windows paths unquoted:
`plan_wave.py --from-budget --borrow-days 6 --scratch E:\COBOL-coord\scratch --stop-file E:\COBOL-coord\scratch\STOP-loop`.
Bash dropped the backslashes, so the planner got `--scratch E:COBOL-coordscratch` and
`--stop-file E:COBOL-coordscratchSTOP-loop`. It then:

1. reserved `COBOL3581`-`COBOL3604` through `alloc.allocate` (`scripts/orchestrator/plan_wave.py` `main`, the
   loop over `p["groups"]`);
2. created `E:COBOL-coordscratch`, which Windows resolves against the current directory of drive E:, so the folder
   was `E:\COBOL\COBOL-coordscratch\`, untracked, inside the main checkout, and wrote `groups.json`, the eight specs
   and `wf-args-w1070.json` there;
3. appended wave 1070's eight groups to `<coord>\inflight-groups.json` (`record_dispatch`);
4. only then ran `make_dispatch_specs.py`, whose `check_practices.py` refused the stop file (`not a fleet-scoped
   STOP-<scope> file`, P3) and every spec, and exited 1.

The unit recovered by hand: `plan_wave.py --release 1070`, deleted the folder, and re-ran from PowerShell (wave 1070,
codes `COBOL3605`-`COBOL3628`). The 24 codes of the first run stay reserved and unused.

**Harm.** No compiler output changes. The cost is to the loop:
- A RED plan leaves its notes in the dispatch ledger. `held_by_dispatch` then reports each as `held by dispatch
  w<wave>` and the next plan skips it, with nothing in flight. Nothing releases it on its own: the ledger has no TTL
  for a wave entry, by design (the ninth refuter's N5). A unit that does not notice the exit 1 hands off, and the
  notes stay out of every later wave until someone reads the "waiting (a later wave)" line and runs `--release`.
- Every RED run reserves three codes per group (24 for a full wave), never used.
- A non-absolute `--scratch` or `--stop-file` is accepted. The relative scratch put fleet files in the main
  checkout, where a careless `git add -A` would commit them.

**Code sites.** `scripts/orchestrator/plan_wave.py` `main`: the `alloc.allocate("code", ...)` loop, then
`scratch.mkdir`, the `gfile` and `afile` writes, `record_dispatch(cdir, wave, p["groups"], terminal)`, and only last
`subprocess.call([sys.executable, str(MAKE_SPECS), str(gfile)])`. `record_dispatch` and `release_dispatch` in the same
file.

**Expected.** A plan that does not end GREEN changes no shared state. The ledger entry is written only after
`make_dispatch_specs.py` returns 0, or a RED result releases what the run recorded. Codes come back too, either by
an `alloc.py` release of a reservation nothing used or by rendering and checking before reserving. And the planner
refuses a `--scratch`, `--stop-file` or `--coord` that is not an absolute path (`PureWindowsPath("E:foo").is_absolute()`
is False), as it already refuses the owner's global STOP.

**Siblings to sweep.** Other orchestrator scripts that take a coordination or scratch path from the command line
(`land_lane.py`, `enqueue.py`, `make_dispatch_specs.py`, `stall_watch.py` callers), and any script that reserves
through `alloc.py` before a step that can fail. Also check that the unit prompts (`scripts/orchestrator/units/*.md`)
say which shell their commands are written for; this one's Windows paths break in Git Bash unless quoted.

## Landing (wave 1131, group F)

**Re-probe (2026-10-19, this tree before the fix, on a scratch coordination directory).** From Git Bash,
`plan_wave.py --budget-points 3 --no-branches --coord <scratch coord> --scratch E:\COBOL-coord\scratch\w1131f\probe
--stop-file E:\COBOL-coord\scratch\w1131f\probe\STOP-probe` reserved `COBOL4625`-`4627`, created
`COBOL-coordscratchw1131fprobe\` inside the worktree, recorded `w1130a` in the ledger, then went RED on the stop file
and exited 1. After the fix the same command exits 2 with both paths named and changes nothing (alloc, ledger,
filesystem); quoted, it ends GREEN with the codes reserved after the check.

**Fix shape.** (1) THE FLEET PATHS' ONE RULE is `coord.py`: `absolute_problem`, `scratch_problem` (absolute, outside the
checkout) and `fleet_stop_problem` (absolute, named `STOP-<scope>`, so never the owner's `STOP`). `plan_wave.main` asks
them before it plans (exit 2), `make_dispatch_specs.main` before it writes (exit 2), and `check_practices.py`'s
groups-file check reads them instead of its own regex (its rendered-text pattern now builds on `coord.STOP_SCOPE`).
`coord.coord_path` refuses a non-absolute explicit `--coord` (`coord_dir` already refused one), so `mailbox.py send`
and `landing_measure.py summary` cannot write or read a drive-relative directory. (2) `make_dispatch_specs.main`
records the ledger ONLY after `check_practices.py` is GREEN (`--no-record` renders and checks only). (3) `plan_wave.main`
renders and checks on the PEEKED codes with `--no-record`, and only on GREEN reserves one block (`per × groups`),
re-renders with it and records; the args file is written last, so a RED plan leaves no launchable wave. (4) The unit
prompts single-quote every Windows path (`units/wave.md` step 2 and the `gen_ledger.py --out` lines of `wave.md` and
`enqueue.md`), and `units/common.md` says why. Sibling: `scripts/arch/r2_inputs.py` read the coordination directory
from its own `COBOL_COORD` variable (the rest of the tree reads `COBOL_COORD_DIR`); it now takes `coord.coord_path`,
`coord.fleet_stop` and `coord.global_stop`, and refuses its `--stop-file` by `fleet_stop_problem`.

**Residual.** If the second render (the reserved codes) were RED where the first (the peeked codes) was GREEN, its
codes would stay reserved: the two differ only in the codes' text, which no practice reads. `alloc.py` still never
returns a reservation (a gap is harmless; DESIGN-orchestrator-loop section 6).

**Self-tests.** `test_plan_wave.py` drives `main()` on a scratch coordination directory with the plan fixed: a
drive-relative scratch or stop file and a bare `STOP` are refused first (exit 2, nothing reserved, recorded or
written); a stand-in renderer that exits 1 leaves alloc and ledger untouched, writes no args file, and was called with
`--no-record`; the real renderer ends GREEN with the 3 codes reserved after the check and in the spec, and the group
recorded; and `make_dispatch_specs.main` on a RED groups file records nothing (a mutation that records before the check
turns it RED). `coord.py --self-test`: nine path cases and the `--coord` refusal. `test_orchestrate_prompt.ps1` and
`test_orchestrate_campaign.ps1` match the quoted prompt.

**For the next implementer.** `scripts/orchestrator/coord.py#scratch_problem|fleet_stop_problem|absolute_problem` own
the fleet-path rule (REUSE them; never a regex on a stop file's text); `plan_wave.py#main` `render()` is the two-pass
render (peek, check, reserve, render, record); `make_dispatch_specs.py#main` records only on GREEN. Trap: the hook
forbids heredocs with backslashes, and Git Bash mangles `E:\…` in commands: quote, or use forward slashes.
