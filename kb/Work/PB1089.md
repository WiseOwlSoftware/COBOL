# PB1089 — LANDED — the currency set records symbol → string only, discarding literal-7's CLASS at `SwitchBindCurrency`, so §12.3.7.3 SR28 is unenforceable: a national currency str

## Rule text (every citation re-run by the registrar)
- `python scripts/spec/cite.py --check 12.3.7.3 "If literal-7 is of class alphanumeric, the associated currency symbol may be used only to define a numeric-edited item with usage display"` → `OK  §12.3.7.3 28)  (Syntax rules)`

### Adjudicator finding (special-names-paragraph-p1, harm under-rejects)
- **Mechanism:** The currency set records symbol -> string only; literal-7's CLASS is discarded at SwitchBindCurrency, so no PICTURE consumer can enforce that an alphanumeric currency symbol defines only USAGE DISPLAY numeric-edited items and a national one only USAGE NATIONAL
- **Repro:** (a) CURRENCY SIGN IS N"EUR" PICTURE SYMBOL "#".  01 E PIC #9.99.  (b) CURRENCY SIGN IS "EUR" PICTURE SYMBOL "#".  01 E PIC #9.99 USAGE NATIONAL.  (c) CURRENCY SIGN IS N"#".  01 E PIC #9.99.  --std 2023
- **Expected (spec):** §12.3.7.3 SR28: 'If literal-7 is of class alphanumeric, the associated currency symbol may be used only to define a numeric-edited item with usage display. If literal-7 is of class national, the associated currency symbol may be used only to define a numeric-edited item with usage national.' Each of (a)(b)(c) is a compile-time error on the data description.
- **Observed:** All three compile and run (E=[EUR1.50], E=[EUR1.50], E=[#1.50]). Fix shape: carry literal-7's class on the currency-set entry (DataBinder.CurrencySigns) and check it where PictureAnalyzer resolves the symbol against the item's usage. Open edge the fix must decide with a cite: SR25's implied CURRENCY SIGN '$' PICTURE SYMBOL '$' has an alphanumeric literal-7, so a literal reading confines the implied '$' to usage display (`PIC $9.99 USAGE NATIONAL` currently compiles). No kb/Work note owns SR28.
- **Code site:** src/Cobol.Net.Compiler/Binding/DataBinder.Switches.cs#SwitchBindCurrency (_currencySigns); src/Cobol.Net.Compiler/Binding/PictureAnalyzer.cs
- **Clause (adjudicator):** §12.3.7.3 SR28

## Landed — wave 1019 (group E)

`SR-12.3.7.3-28` is re-verdicted **CONFORMS** (batch `w1019e-picture-analyzer`). Re-probed on this build before the fix, all
three of the registrar's shapes compiled and ran (`EUR1.50` / `EUR1.50` / `#1.50`); each is now **COBOLNET2883**.

- **The class is half of the definition.** `_currencySigns` is symbol → `CurrencyDefinition(string Text, LiteralClass LiteralClass)`
  (new `Model/CurrencyDefinition.cs`), recorded at `SwitchBindCurrency` from the ONE literal classifier
  (`OperandLiteralClass`: alphanumeric incl. `X"…"`, national `N"…"`/`NX"…"`, a folded concatenation). `CurrencySigns`,
  `PictureAnalyzer.Analyze`'s `currencies:` parameter and the unit tests' dictionaries all carry the new type (no forwarder, the
  old `string` shape is gone). SR21 compares the whole definition: the same characters in the other class are not "identical
  currency strings".
- **Asked once, for both routes to a usage.** The picture analyzer records the class of the symbol THIS picture uses on
  `PicInfo.CurrencyClass` (null when it uses none) and `PictureAnalyzer.ScreenUsageAgainstPicture` — the one USAGE × PICTURE
  screen the written clause and the §13.18.60.4 GR1 group-inheritance pass (`ApplyEffectiveUsage`) both call — refuses an
  alphanumeric symbol on a USAGE NATIONAL numeric-edited item and a national symbol on a USAGE DISPLAY one. Both sentences of
  SR28 are the one comparison, because the two classes pair with the two usages crosswise-forbidden.
- **The edge, decided with the cite.** SR25 implies `CURRENCY SIGN '$' PICTURE SYMBOL '$'`, whose literal-7 is the ALPHANUMERIC
  `'$'` (`cite.py --check 12.3.7.3 "…the clause CURRENCY SIGN '$' PICTURE SYMBOL '$' is implied for that source unit"` → OK §12.3.7.3
  25)). SR28 says "may be used only", so read as written the implied `$` defines only usage-display numeric-edited items and
  `PIC $9.99 USAGE NATIONAL` is COBOLNET2883 (`CurrencyDefinition.ImpliedDollar`). No corpus program used that spelling; a national
  `$` is `CURRENCY SIGN N"$" PICTURE SYMBOL "$"`. ⚠ DETERMINATION — the owner may overturn; it is one constant.
- **Goldens.** `negative/pb1089-currency-symbol-literal7-class-usage` (five shapes: national on display, alphanumeric on national,
  the same through a group's NATIONAL usage, a bare `N"@"`, the implied `$`; COBOLNET2883 at 2002/2014/2023) and
  `2002/pb1089_currency_literal7_class_pairings` (the three CONFORMING pairings: `EUR1.50 USD1.50 $1.50`).
