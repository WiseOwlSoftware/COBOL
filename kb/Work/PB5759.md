# PB5759 - the tracked record of a code read at an edition

**What is wrong.** Kb/Work PB5692's ruling (2026-11-15) is that a verdict shared from the 2023 adjudication does not
close a 1985 row: every KEPT row of 1985 needs a verdict adjudicated on the code at `--std 85`, a code read with a
refuter. Kb/Work PB5683 says a read that confirms a KEPT row "is kept as a tracked record of the read". No such record
exists:
- `python scripts/spec/audit_batch.py import-reads --edition 1985 --reads <the sample's out/> --record <scratch>
  --state <scratch>` fails with `1985-01: (no rule-id): the record holds no reader's 'cases'`; with `records` renamed
  `cases`, `to must be a list of rule ids ... not None`.
- The read record of `tests/version-matrix/lineage-reads-2002/` pairs an old rule with later rules and its verdict is
  SAME, DIFFERENT or DOUBTFUL. A code read judges a rule against the compiler: CONFORMS, PARTIAL, DIVERGES,
  DOCUMENTED-NON-SUPPORT, with a code location, the edition arms on the rule's path and probes. It has no place there.
- `lineage_reads.pairing_problems` refuses a rule with no candidate pair, and 1985 pairs 0 of 2,274 rules. PB5683's
  sentence that the pairing check "takes the stored record's own targets" describes a docstring, not the code.
- `lineage.next_errors` refuses `verdict`, `code-location` and `derivation` on a KEPT row
  (`inventory-schema.json` `next.verdict-fields`), so the row cannot hold it either. The operator's registrar landing
  of the sample (pull request 1739) stored the re-recorded rows and no confirmed read; it could not re-record four
  KEPT rows the sample contradicted.

**What exists.** The sample (`E:/COBOL-coord/scratch/sample-shared/`): 10 slices, 60 KEPT rows of 1985 read on the
code at `--std 85`; 54 CONFORMS upheld by the refuter, 2 PARTIAL from the reader, 4 CONFORMS the refuter overturned.
Of the 6 not confirmed, 3 are upheld contradictions of cause (a) (kb/Work PB5692's dated adjudication), 2 are cause
(b), 1 is cause (c). The store holds 1,373 KEPT rows of 1985; 570 carry a test-ref of their own.

**Fix direction.** A store of the row's own adjudication, held beside the row until the switch (kb/Work PB5682) folds
it in: `tests/version-matrix/code-reads-<year>/<rule-id>.json`, one file per rule, the edition a parameter. One module
owns it: the record's shape, the import from the reader's and refuter's files as the sample pipeline writes them, the
outcome of a record (confirmed, contradicted, undecided), the audit, and the population still owed a read. The
inventory view counts them. No row's state changes here: the count of KEPT rows not yet confirmed by a code read is
shown beside the edition's GAP, and both reach zero before 1985 is done.

**Sites:** `scripts/spec/code_reads.py` (whole: the new module), `scripts/spec/code_read_store.py` (whole: the new module, the view's half), `scripts/gate_audits.py` (`AUDITS`),
`scripts/spec/inventory_view.py` (`summary`), `tests/WiseOwl.Cobol.Tests.RepoDrift/SpecTraceabilityInventoryDriftTests.cs` (`UnresolvedCodeLocations`,
`EveryCodeLocation_ResolvesInTheTree`), `.github/workflows/build-and-test.yml` (the `audits` job), `scripts/selftests/spec/code_reads/test_code_reads.py` (new),
`tests/version-matrix/code-reads-1985/` (new), `docs/rearchitecture/DESIGN-spec-conformance-review.md` (§10.6)
