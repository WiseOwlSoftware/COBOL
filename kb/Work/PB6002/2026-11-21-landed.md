**Fix.** `rule_moves.split_copies` gives, for every batch of a `record_verdicts.py` run that holds a split, the file
`SPLIT_DIR.format(year=edition)/<the batch file's name>` holding its splits under the batch's label; `record_verdicts.py`
computes them with the move/split validation (a file of that name holding another batch's splits refuses the whole run,
before anything is written) and writes them in the same operation as the store. A batch applied from its own tracked file
is its copy already. The hand-copy step PB5452's mint took is gone; the design's section on the move and the split says so.

**Evidence.** `case_07` fails on the base (`AttributeError: module 'rule_moves' has no attribute 'split_copies'`) and
passes on the branch: the copy is the splits alone under the label, a batch of moves alone leaves none, a re-apply finds
its copy byte for byte, and another batch's file of the same name is refused.
