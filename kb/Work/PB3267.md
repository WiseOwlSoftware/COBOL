# PB3267 — FINDINGS stamp lost when a successor contains the branch

**Mechanism.** `scripts/prune_worktrees.py` `contained(rows, repo)` (line 675) re-labels a row that is a DECISION or a carrier state, whose tip is an ancestor of a carrier's tip, as `IN FLIGHT` with why "contained in <carrier> (<state>): its work lands through that branch" (line 691). The row guard lets a DECISION row whose report carries FINDINGS through to the ancestor test, so a FINDINGS-stamped branch cut into a successor is absorbed into the successor: the survey no longer lists it as a DECISION and `plan_wave.py` plans no review finisher for it. The carrier is reviewed on its own report, which does not contain the contained branch's findings, so nobody answers them. PB3027 introduced `contained()` for a review finisher's merged predecessor (the finisher answers the findings) and a same-file predecessor, not for a successor that merely contains a FINDINGS branch. The self-test in the same file (`fnd-pred` contained in `fnd-fix`) pins the finisher case only.

**Repro.** Branch `notes-PB1754-r2b4b-20261016` (review FINDINGS 3, `review-notes-PB1754-r2b4b-20261016.jsonl`) was cut into `notes-PB1754-r2b5b-20261016`. The 06:13 wave unit was handed "finishers for 74d-18 and r2b4b" and planned one for 74d-18 only (3a8-14). Source: operator steer `E:\COBOL-coord\scratch\operator-steer-20261016-0750.md`, item 4.

**Fix shape (the operator's).** A FINDINGS stamp on a contained branch is inherited by its carrier: the carrier reads WAITING FOR REVIEW with those findings open (or gets the finisher), by one rule in `contained()`, plus a self-test row (a FINDINGS predecessor inside a plain successor must NOT read IN FLIGHT). PB3181 and PB3027 stay landed; this is a gap in their `contained()` arm.
