# PB5593 - COBOL0900's text for an index amount of SET UP BY / DOWN BY names the wrong fault

**Sites:**
- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/SetBinder.cs` (`SetBinder.GateCobol85IndexAmount`, `SetBinder.IsCobol85IndexAmount`)
- `tests/version-matrix/constructs/set-arithmetic-expression-2002.json` (whole: its one description string is the text the diagnostic prints)

**Rule.** Format 2's amount is identifier-3 or integer-2, and "Identifier-3 must reference an elementary numeric integer"
(§1985:VI.6.23.3 SR3, `cite.py --check` OK). kb/Work PB5421 made the edition gate refuse an index-name or an index data
item there (`IsCobol85IndexAmount` returns false for `SetOperandKind.IndexName` / `IndexDataItem` when `upDown`); the
refusal is correct.

**Repro** (`E:/COBOL-coord/scratch/op-20261114/held-adj/set/sf11.cob`, `sf5.cob`; rerun by records-85-held on its build of
origin/main 689413b7de, `records-held/probe/probe.log`), `cobol.exe --std 85 --source-format fixed --run sf11.cob`:

```
sf11.cob(23,38): error COBOL0900: a SET index sending operand that is an arithmetic expression, a non-integer, or a zero
or negative integer requires COBOL-2002 (targeting COBOL-85) - the SET UP BY or DOWN BY operand IY (...)
```

**Expected.** A message that names the fault: the operand is an index-name (sf5: an index data item), and §1985:VI.6.23.3
SR3 requires an elementary numeric integer. **Observed.** The construct row's description, which lists three forms the
operand is not, so the user is told the wrong cause. The fix gives the index arm its own words (a second construct row or
a detail the gate passes), keeps COBOL0900, and pins the text in the PB5421 refusal cases
(`conformance-suite/cases/14.9.39-SET/pb5421-set-up-by-index-name-at-85`, `pb5421-set-down-by-index-data-item-at-85`).
