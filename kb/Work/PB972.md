Filed 2026-09-22 by **REGISTRAR #11** from wave 46 group I's lead 1 and group I2's lead 2 (PB815 implementer report,
PB757 finisher report; lander leads I1 and I2-2 — one mechanism: the per-method conformance rules are written down
twice and rule 9 in neither). **Re-measured on this registrar's own build of main `6871b6e10`** (0/0).

## Premise corrections against the source reports

- The PB815 report named rules **7, 8 and 9** as unenforced. On main **rule 8 is enforced** (`OoConformance.OptionalMismatch`,
  landed with PB757) and **rule 7 is enforced** through `DescriptionMismatch`'s strongly-typed sentence
  (`StrongTypeMismatch`, landed with PB427), which `MethodConformanceMismatches` calls for every formal and for a
  non-object RETURNING. Only **rule 9** is missing. The fixer re-verifies 7 with a golden; this note does not claim it.
- The PB815 report's repro had the direction backwards ("an interface prototype `RAISING CE` implemented by a class
  method with NO RAISING compiles clean"). Rule 9 constrains interface-2 only when interface-1's method HAS a RAISING
  phrase, so that shape is CONFORMING. The non-conforming shape is the reverse, measured below.

## Reproduced

`reg11/i1r9.cob`: `INTERFACE-ID. R11R9I.` with `METHOD-ID. WORK. PROCEDURE DIVISION.` (no RAISING); `CLASS-ID. R11R9C.`
`OBJECT. IMPLEMENTS R11R9I.` with `METHOD-ID. WORK. PROCEDURE DIVISION RAISING R11R9E.` → compiles clean, runs,
prints `IN WORK` / `AFTER WORK`. Expected: a compile-time diagnostic naming §9.3.8.2.3 rule 9 b) against §9.3.11.

## Rule

- `python scripts/spec/cite.py --check 9.3.8.2.3 "If the RAISING phrase is specified in the procedure division header of the method in interface-1, the corresponding method in interface-2 specifies the RAISING phrase"` → OK §9.3.8.2.3 9)
  — a) the same exception-name; b) for an object-class-name, the same class or a superclass, FACTORY iff FACTORY, or an
  interface the (factory / instance) object implements; c) for an interface-name, the same interface or one it inherits.
- `… --check 9.3.8.2.3 "If either of the corresponding formal parameters or returning items in interface-1 or interface-2 is a strongly-typed group item, both are of the same type"` → OK §9.3.8.2.3 7) (enforced — see above)

The RAISING tuple model that rule 9 needs exists since PB815/PB814 (`RaisingTarget`), so the rule is now expressible.

## The duplication (part of the same fix)

§11.7.3 SR9 sends an overriding method to §9.3.8.2.3, which `OoConformance.MethodConformanceMismatches` already
implements ("⛔ the ONE place the per-method conformance rules are written"). `OoConformance.ValidateOverrideSignatures`
(`src/Cobol.Net.Compiler/Oo/OoConformance.cs:31`) re-spells rules 1–6 and 8 with its own diagnostic text instead of
calling it. Collapse the override pass onto `MethodConformanceMismatches` (keeping the covariant-RETURNING leniency
rule 5 grants), then add rule 9 ONCE; a drift test pins that the override pass has no rule text of its own.

## Sibling sweep

Every interface-to-interface conformance asker (§9.3.8.2.3 is also used for INHERITS between interfaces, the
object-reference SET/argument conformance through interfaces, and §11.7.3 overrides); one negative per rule-9 arm
(a, b, c) and one conforming golden with a superclass / implemented-interface match.

## Landed (wave 51, group E)

Re-probed on the implementer's build of `5963d9ca0`: `i1r9.cob` compiled clean and printed `IN WORK` / `AFTER WORK`.
After: `i1r9.cob(41,8): error COBOLNET0841: class 'R11R9C', method 'WORK': RAISING R11R9E: the 'R11R9I' prototype
specifies no RAISING phrase, and it shall specify 'R11R9E' or a superclass of R11R9E with the FACTORY phrase not
specified, or an interface implemented by the instance object of R11R9E (ISO §9.3.8.2.3 rule 9 b))`.

- Rule 9 lives ONCE, in `OoConformance.RaisingMismatches`, called from `MethodConformanceMismatches` — so all three
  askers get it: §9.3.11 IMPLEMENTS (0841), §11.7.3 SR9 overrides (0829) and `InterfaceConformsTo` (the GOBACK SR4 b)
  / EXIT SR5 b) interface relation). Every element of interface-1's phrase needs a covering element: a) the same
  exception-name; b) the class or a superclass with the same FACTORY presence, or an interface in
  `ImplementsClosure(cls, factory)`; c) the interface or one in its INHERITS closure. (`cite.py --check 9.3.8.2.3`
  → `OK §9.3.8.2.3 9)` on the rule sentence, on c)'s "inherited by that interface" and on b)'s "implemented by the
  instance object of that class"; `--check 11.7.3` → `OK §11.7.3 9)`.)
- `ValidateOverrideSignatures` is COLLAPSED onto `MethodConformanceMismatches` (the override is interface-1, per SR9's
  "such that the interface described by the … definition containing this method definition conforms to …"); its
  private copy of rules 1–6 and 8 — and the bare "§9.3.8.2" citations — are deleted. The rule-5 covariant RETURNING
  leniency was already in the shared rule set with the same orientation, so no override that compiled before is
  rejected now except by rule 9. `MethodConformanceRuleSetDriftTests` (Unit) pins that each asker calls the one rule
  set and spells no comparison or rule citation of its own, and that the rule set carries rule 9.
- Sibling of PB975 found on the way: both post-bind passes reported with no position; each now positions at the
  implementing / overriding method (the "not implemented at all" 0841 at the class name).
- Rule 7 re-checked, not claimed: it IS enforced inside `DescriptionMismatch` (`StrongTypeMismatch`) for every
  formal and a non-object RETURNING, but no OO witness exists — a strongly-typed TYPE shared by an interface
  prototype and its implementation needs a type-name visible in both source elements, which an interface cannot
  declare (no WORKING-STORAGE). `GR-9.3.8.2.3-7` stays GAP; reported as a lead.
- Rule 1's "consistent BY REFERENCE and BY VALUE specifications" cannot differ today: every method formal is BY
  REFERENCE (a BY VALUE method formal is refused at bind, COBOLNET0899).

Goldens: `conformance:2002/pb972_raising_conformance` (W1 superclass, W2 implemented interface, W3 inherited
interface, W4 exception-name, W5 interface-1 raises nothing, plus a conforming override) and four negatives
