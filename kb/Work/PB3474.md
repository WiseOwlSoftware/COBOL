# PB3474 — a remaining copy and a remaining description of the never-work rule after PB3465

> flags: process-only · silent

Low, non-blocking leads R1-1 (low) and R1-3 (info) from the round-1 review of the PB3465 branch (`fix-pb3465-never-work-paths-20261020`, head verified 2026-10-20). PB3465 made `coord.NEVER_WORK` (`.claude/settings.local.json`, `STATUS.md`, `TestResults/`) the one list and deleted five copies; its sweep looked at the `git status` / `ls-files` readers. Two places still state the rule on their own.

**Sites.**
- `scripts/prune_worktrees.py:284`, `classify()`: the filter on files the branch adds, `not f.startswith(('TestResults/', 'tools/')) and f != 'STATUS.md'`, is a hand-coded never-work test over a `git diff --name-only --diff-filter=A` reader. It omits `.claude/settings.local.json` (harmless only because that file is tracked on main, so it is never "added") and carries a `tools/` exclusion that `NEVER_WORK` does not have. The `tools/` exclusion is a separate decision to make explicitly: either `tools/` is never work (then it belongs in `coord.NEVER_WORK`) or it is not (then `classify()` is wrongly ignoring added files there).
- `scripts/orchestrator/enqueue.py:13`, module docstring step 1: "The worktree must be clean (STATUS.md and the harness's settings.local.json aside)". `dirty_paths` applies `coord.NEVER_WORK`, which also excludes everything under `TestResults/`, so the description is stale.

**Fix shape.** Route `classify()` through `coord.is_work` (path-wise; decide the `tools/` question first and put the answer in `coord.NEVER_WORK` or drop it), and reword the docstring to name `coord.NEVER_WORK` rather than copy its members. Extend the PB3465 drift test in `scripts/orchestrator/test_plan_wave.py` so a hand-written `TestResults/` or `STATUS.md` test anywhere in `scripts/` fails it. Delete the old test in the same change (no forwarders, CLAUDE.md rules 4 and 5).
