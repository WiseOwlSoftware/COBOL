## Landed — 2026-09-27, wave 68 R (branch `worktree-wf_e9a82a33-6b6-1`)

**Which element's items a method activation checks — pinned.** A method has no external items of its own: §13.4.3 SR1 keeps a FILE SECTION out of a method (`cite.py --check 13.4.3 "FILE SECTION"` → OK 1)), and a method WORKING-STORAGE EXTERNAL item is refused (COBOLNET0899; 2023 bans method WORKING-STORAGE outright). Its statements reference the containing factory's or object's data, so those are the items §14.9.23.4 GR7 d) checks (`cite.py --check 14.9.23.4 "External items are checked to ensure that they comply with the following rules"` → OK 7)).

**The mechanism.** Each class half with external items emits `private static void __DescribeExternals(int __self)` through the same `OoEmitter.EmitExternalDescribes` a program's `DescribeExternals()` uses (now parameterized by signature and self mask). Every method prologue — typed, universal (`__CobolInvoke` calls the same method), PROPERTY accessors — runs `ExternalStore.DescribeAtMethodActivation(__DescribeExternals, <mask>)` BEFORE the module-stack push, i.e. before GR7 e)'s transfer; a violation leaves as a `CobolFatalException` carrying its Table 13 name, which the INVOKE statement's guard selects on as it does EC-OO-METHOD. §14.8.4.1's pair (`OK §14.8.4.1`): the method half is `OoMethodSymbol.ExternalCheckMaskHere`, folded before the METHOD's Environment division by `BinderDriver.ExternalMaskAt` — the one fold program units take too; the activating half is the INVOKE statement guard's new EC-EXTERNAL checking flags (three `EcEmitter.FatalAmbientGates` rows; `EcBinder` queries `ExternalNames` for `BoundInvoke`/`BoundInvokeUniversal`).

**One handshake, not two (rule 5).** The CALL arm's activating half was a pending register (`ExceptionEngine.ExternalCheckMask`) the CALL site set and every `ProgramTable` failure path had to zero by hand (PB133 found one that did not). The INVOKE arm needed the same half, so the register is retired: `ProgramTable.CallProgram` reads the same scoped flags (`ExceptionEngine.ExternalActivatingMask`) before the callee's checking scope opens, and `CallEmitter` no longer emits a mask. `ProgramActivationMaskTests` re-pinned on the flags, plus the method twin.

**Evidence.** x3.cob on the w68r build: `HANDLED=EC-EXTERNAL-FORMAT-CONFLICT` / `AFTER` (was `IN METHOD ABCD` / `AFTER`); x3b.cob (checking off in the activating program) runs the method. Golden `2023/w68r_pb1138_method_external_check` (typed, universal, factory method, and a class whose method has checking off → runs), negative `negative/w68r-pb1138-method-external-below-2023` (COBOLNET0878 at 2002/2014). `GR-14.9.23.4-7` re-verdicted (batch `w68r-verdicts-pb1138.json`): F3 closed, the row stays DIVERGES on F2, owned by [[PB1123]].
