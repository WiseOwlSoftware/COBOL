# PB4868 - below 2023 a message-tag operand of MOVE, DISPLAY and every other verb, and of SET UP/DOWN BY FUNCTION and SET ADDRESS OF ... TO FUNCTION, still draws a class diagnostic beside COBOL0900

**What the reports say (one note, three leads).**

Lead 1: MOVE, DISPLAY and every other verb draw a class diagnostic beside COBOL0900 for a tag operand at 2014 (`a.cob`: MOVE T TO N draws COBOL0809, DISPLAY T draws COBOL1694). Same root as PB4836 beyond SET. Proposed fix: ask the gated-operand question once in `StatementBinder.BindStatementCore` (about line 575) over a statement's own operands (excluding nested statements), replacing `SetBinder.NamesGatedMessageTag`.

R1-1 LEAD (low, not blocking at round 1): `SetBinder.cs:1386` the below-2023 no-op for a same-file function sender is reached only from `BindSetTo`'s classified sender, so SET UP/DOWN BY FUNCTION and SET ADDRESS OF ... TO FUNCTION still draw a class diagnostic beside COBOL0900, while DESIGN-message-control.md 7.1 and the `BindMessageTagSet` doc comment say the statement is a no-op in EVERY format.

Lead 2: `SET <capacity or dynamic-length item> TO FUNCTION <same-file function returning a tag>`: the F14/F16 arms of `SetBinder.BindSetTo` bind the amount before the sender classifier, so the sender hook never sees it; likely a class diagnostic beside the gate (**not probed**, called exotic by the report).

**Repro (the reporting finisher's `a.cob`, compiled at 2014).**

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. PA.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 T USAGE MESSAGE-TAG.
       01 P USAGE POINTER.
       01 N PIC 9(4).
       01 O USAGE OBJECT REFERENCE.
       PROCEDURE DIVISION.
       MAIN-P.
           SET P TO T.
           SET O TO T.
           SET T UP BY 1.
           SET T DOWN BY 1.
           SET N TO T.
           SET T TO P.
           SET T TO O.
           MOVE T TO N.
           DISPLAY T.
           STOP RUN.
```

The report states SET P TO T (COBOL0869), SET O TO T (COBOL0867) and SET T UP/DOWN BY 1 (COBOL2112 twice) were reproduced before PB4836 and were fixed by it; MOVE T TO N (COBOL0809) and DISPLAY T (COBOL1694) remain.

**Not probed.** The clerk compiled nothing. The F14/F16 arms are not probed.

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Bound/StatementBinder.cs` (`StatementBinder.BindStatementCore, about line 575`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/SetBinder.cs` (`SetBinder.NamesGatedMessageTag`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/SetBinder.cs` (`SetBinder.BindSetTo, line 1386; F14/F16 arms`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/SetBinder.cs` (`BindMessageTagSet`), `docs/rearchitecture/DESIGN-message-control.md` (`section 7.1`).

**Landed (wave 20261887 D).** Re-probe on the Debug build at 2014 before the change: MOVE T TO N drew COBOL0809 and DISPLAY T COBOL1694 beside COBOL0900, as the note says. The gated-operand question moved out of `SetBinder` to the one funnel every statement passes through, `StatementBinder.BindStatement` (`StatementBinder.NamesGatedMessageTag`, `StatementBinder.IsGatedMessageTag`), over the statement's own operands (`ParseTreeWalk.OwnDescendants`, which stops at a nested statement): data references, function-identifiers (`IntrinsicBinder.ReturningItemOf`) and inline method invocations (`OoBinder.InlineInvocationReturningItem`, new, diagnostic-free). `SetBinder.NamesGatedMessageTag`, `SetBinder.IsGatedMessageTag`, `SetBinder.MessageTagUsageIsNotThisEditions` and the sender hook in `SetBinder.BindSetTo` are deleted. SET UP/DOWN BY FUNCTION and SET ADDRESS OF ... TO FUNCTION (R1-1) and the F14/F16 arms (Lead 2, whose binds happen after the funnel's question, so every arm is covered by construction; the capacity-item declaration itself was not built into a test) are covered. Witnesses: `tests/WiseOwl.Cobol.Tests.Conformance/MessageTagIntroductionGateTests.cs#EveryVerbAMessageTagOperandReaches_IsTheGateAloneBelowTheIntroduction` and `#ANestedStatementThatNamesNoTagKeepsItsOwnRefusalBelowTheIntroduction`. Sites added: `src/WiseOwl.Cobol.Compiler/Binding/ParseTreeWalk.cs` (`ParseTreeWalk.OwnDescendants`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/OoBinder.InlineInvocation.cs` (`OoBinder.InlineInvocationReturningItem`), `src/WiseOwl.Cobol.Compiler/Binding/Bound/StatementBinder.cs` (`StatementBinder.BindStatement`, `StatementBinder.NamesGatedMessageTag`, `StatementBinder.IsGatedMessageTag`).
