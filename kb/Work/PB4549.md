# PB4549 — report-source-clause-forms-refused: -std=cobol2014: report SOURCE clause: SOURCES ARE and an arithmetic-expression operand are refused

Filed 2026-11-03 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-batch-3000-20261103`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

Under `-std=cobol2014`, cobc 3.2 refuses two forms of the report writer SOURCE clause: the synonym `SOURCES ARE` ("'SOURCES' is a reserved word, but isn't supported") and an arithmetic expression as the operand (`SOURCE IS WS-A + WS-B`: "syntax error, unexpected +"). Both come from one grammar rule, which takes the word SOURCE and one identifier, literal or function. Class: rejects legal source. Fuzz programs: fz00024, fz00026, fz01434, fz01436, fz02139, fz02844, fz02845 (night fuzz-batch-3000-20261103, slice D2).

## Minimal test case

Free reference format.

```cobol
IDENTIFICATION DIVISION.

ENVIRONMENT DIVISION.
INPUT-OUTPUT SECTION.
FILE-CONTROL.
SELECT RPT-FILE ASSIGN TO "srcf.out".
DATA DIVISION.
```

## Expected result (per ISO)

The program is legal and the report file holds two detail lines `12 017`: column 1 is WS-A, columns 4-6 are the value of WS-A + WS-B. The rules are quoted from ISO/IEC 1989:2023; both forms are in COBOL 2002 (its Annex F.2 item 115: "SOURCE allows arithmetic expressions and functions and a ROUNDED phrase") and Annex E of 2023 lists no report writer change from 2014.

- §13.18.53.2 (checked): "<u>SOURCES</u> ARE"
- §13.18.53.3 (checked): "SOURCE and SOURCES are synonyms"
- §13.18.53.3 (checked): "If arithmetic-expression-1 or the ROUNDED phrase is specified, the entry shall define either a numeric data item or a numeric-edited data item"
- §13.18.53.4 (checked): "it specifies the sending operand of an implicit MOVE statement in which the data item referenced by identifier-1 is moved to the printable item"
- §13.18.53.4 (checked): "Arithmetic-expression-1 specifies the operand of an implicit COMPUTE statement that is executed implicitly whenever the associated item is printed"

## Our compiler

WiseOwl COBOL (fresh judge, `cobol srcf.cob --std 2014 --source-format free -o srcf.dll`) compiles it with no diagnostic; `dotnet srcf.dll` exits 0 with srcf.out holding `12 017` twice.

## Fix site

cobc/parser.y `source_clause` (line 9810 of the 3.2 source): `SOURCE _is arith_x flag_rounded`. There is no SOURCES alternative (the word is in the reserved list as unsupported), and `arith_x` is one identifier, literal, function, counter or LENGTH OF, not an arithmetic expression. The rule also takes only one operand, where 13.18.53.2 allows several.

## Draft issue

**Title:** Report writer: please accept SOURCES ARE, the standard synonym of SOURCE IS

As posted (owner-reviewed, 2026-11-04):

cobc lists SOURCES as a reserved word that is not implemented, so a report item whose SOURCE clause is written `SOURCES ARE` does not compile. Report Writer is optional in COBOL 2014 and 2023 and required in COBOL 2002. This asks cobc to accept SOURCES ARE; a patch is attached.

### To reproduce

`srcs.cob` (attached, free format):

~~~~
IDENTIFICATION DIVISION.
PROGRAM-ID. SRCS.
ENVIRONMENT DIVISION.
INPUT-OUTPUT SECTION.
FILE-CONTROL.
    SELECT RPTF ASSIGN TO "srcs.out".
DATA DIVISION.
FILE SECTION.
FD RPTF
    REPORT IS R1.
WORKING-STORAGE SECTION.
01 WS-A PIC 99 VALUE 12.
REPORT SECTION.
RD R1 PAGE LIMIT 10.
01 D1 TYPE DETAIL LINE 1.
   05 COLUMN 1 PIC 99 SOURCES ARE WS-A.
PROCEDURE DIVISION.
    OPEN OUTPUT RPTF
    INITIATE R1
    GENERATE D1
    TERMINATE R1
    CLOSE RPTF
    DISPLAY "DONE"
    STOP RUN.
~~~~

    cobc -x -free -std=cobol2014 -o srcs srcs.cob

### What happens

3.2.0 and 3.3-dev r5751 both stop with (source excerpts omitted)

~~~~
srcs.cob:16: error: 'SOURCES' is a reserved word, but isn't supported
~~~~

and a follow-on syntax error on the same line. The same happens with `-std=cobol2002` and without `-std`; with `SOURCE IS WS-A` on line 16 the program compiles and writes `12`.

### What should happen

The program should compile and write the same `srcs.out` as the `SOURCE IS` spelling. The general format of the SOURCE clause (13.18.53.2) is `SOURCE IS` or `SOURCES ARE` followed by the operands, and ISO/IEC 1989:2023 13.18.53.3 syntax rule 1 says: "SOURCE and SOURCES are synonyms." SOURCES is a reserved word (8.9). The same in 2002 and in the 2014 FCD.

The standard pairs ARE with the plural explicitly for COLUMN: "The keyword ARE may be specified only if COLUMNS, COLS, or NUMBERS is specified." (13.18.14.3 syntax rule 4). It has no such rule for SOURCE and SOURCES; we treat them the same way, as `SOURCE IS` and `SOURCES ARE`, and the patch accepts only those two forms.

### Why it happens

`cobc/reserved.c` gives SOURCES the token -1 (reserved, not supported), and `source_clause` in `cobc/parser.y` takes only `SOURCE _is`. `cobc --list-reserved` shows SOURCES as not implemented.

### Proposed fix

The attached `report-sources-are.patch` (against 3.3-dev r5751) adds the token SOURCES, maps the reserved word to it, and puts the keyword in a `source_keyword` rule, `SOURCE _is | SOURCES _are`. In dialects whose word lists do not reserve SOURCES (cobol85, for one), SOURCES stays a user-defined word. With the patch `srcs` compiles under `-std=cobol2014`, `-std=cobol2002` and the default dialect, and writes the same `srcs.out`, byte for byte, as unpatched 3.3-dev gives for `SOURCE IS`; `cobc --list-reserved` now shows SOURCES as implemented.

It adds the testsuite case "Report SOURCES ARE" to `run_reportwriter.at`, which runs SOURCES ARE and SOURCES alone beside SOURCE IS and checks that SOURCES IS and SOURCE ARE are still refused, with ChangeLog entries in `cobc/` and `tests/`. `make check`: 1373 expected, 9 skipped, 0 failed (1372 unpatched); the new test fails without the patch.

The patch does not add a list of operands, `SOURCES ARE A B` for a repeating entry (13.18.53.3 rule 6), which cobc refuses in either spelling.
