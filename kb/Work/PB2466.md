# PB2466 — LANDED

**Landed (wave 1033 G, 2026-10-07).** Re-probed on the wave's build: `r2.cob` drew COBOLNET1655. Root cause: a span
part was kept in its leaf's CHARACTER positions (`RenamesSpanPart.FromBytes` converted the byte tiling and returned
null for a range that splits a national character), so a byte only half a national character covers had no
representation at all. The fix keeps every part in STORAGE BYTES (`RenamesSpanPart(Leaf, Occurrence, StartByte,
LengthBytes, Outer)`; `FromBytes` is deleted) and makes each spanned cell its storage image:
`ReferenceResolver.SpanLeafPlace` wraps a usage-national leaf in the new `NationalBytesPlace` (UTF-16BE pairs, D-N1,
after `NumericImagePlace` for a national numeric), and a partial part is a `RefModPlace` over that image in bytes.
`PlaceRenderer` reads `NationalBytesPlace` as `NatBytes` and writes it back through `NatReadWindow`; the renderer's
per-leaf national transcoding (`IsNationalRenamesLeaf` / `ReadRenamesLeaf` / `StorageToLeafCharacters`) is gone, so
one decorator owns the conversion. The tiler's `Consider` now builds `RenamesSpanPart`s directly and asks their own
`IsPartial`, and the post-choice refusal is gone. This also closes **PB1902** (a window BOUNDARY on the odd byte of a
national character): that shape is now tiled the same way. Golden `2002/pb2466_renames_half_national_byte` (an
interior half character, a boundary half character, and a half of a table cell, each read and written; values
computed from the byte layout). Batch `w1033g-pb2466` adds the golden and the code sites to GR-13.18.45.4-2.

## Landing

- `src/Cobol.Net.Compiler/Binding/Model/RedefinesModel.cs#RenamesSpanPart` — parts are STORAGE BYTES; `Positions` is
  the one bytes-to-positions conversion (for `GroupAtom.Chars`). Never reintroduce a positions-based part.
- `src/Cobol.Net.Compiler/Binding/DataBinder.cs` (RENAMES THRU tiling, local `Consider`) — builds `RenamesSpanPart`s
  and asks their `IsPartial`; every candidate is addressable.
- `src/Cobol.Net.Compiler/Binding/ReferenceResolver.cs#SpanLeafPlace` — the ONE place a spanned cell becomes its
  storage image (`NumericImagePlace`, then `NationalBytesPlace`); `#PlaceForRenames` slices it in bytes.
- `src/Cobol.Net.Compiler/CodeGen/Roslyn/PlaceRenderer.cs` (`NationalBytesPlace` Read/Write arms) — the national
  transcoding lives there; `RenamesPlace` reads/writes its leaves as they stand. Trap: a byte slice that splits a
  character is written by splicing into the cell's WHOLE byte image first (the `RefModPlace` arm), so the decode
  always sees whole pairs.

Filed 2026-10-07 by the train-1033 lander from the wave-1032 group A implementer report (`w1032a-PB667-report.md`,
new defect 2; that branch is SPLIT and unlanded, so the lead was recorded in `train1032-manifest.json` only).

**Shape.** Sibling of PB1902. PB1902 is a window whose FROM or THRU boundary falls on the odd byte of a national
character; wave 1032 A's (unlanded) fix makes the RENAMES THRU tiler's `Consider` build every candidate through
`RenamesSpanPart.FromBytes`, so it never picks an unaddressable half-character slice at a boundary. A window whose
INTERIOR has a byte covered by only half a national character — the alphanumeric REDEFINES view is shorter than the
national item it redefines, so the tiling crosses a half character mid-window — still has no addressable part kind
for that byte and draws COBOLNET1655.

**Rule.** §13.18.45.4 2) (`cite.py --check`: OK) — "When the THROUGH phrase is specified, data-name-1 defines an
alphanumeric group item that includes all elementary items starting with data-name-2 ..." — the renamed area is a
storage window and is addressed as an alphanumeric group, whatever the leaves' classes.

**Repro.** `E:\COBOL-coord\scratch\w1032a\p\r2.cob`: COBOLNET1655 today; expected to compile and address the bytes.

**Code site.** The RENAMES THRU tiler in `src/Cobol.Net.Compiler/Binding/DataBinder.cs` (`Consider` /
`RenamesSpanPart.FromBytes`). The fix needs a byte-level part kind over the REDEFINES class backing. Land after (or
with) PB1902, whose branch `worktree-wf_19837670-9d4-1` changes the same tiler.
