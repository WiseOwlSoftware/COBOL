# PB4002 — zero-length-literal-read-as-space: -std=cobol2014: a zero-length literal is replaced by one space although zero-length-literals is ok

Filed 2026-10-28 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-20261027-215606`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

Under `-std=cobol2014`, cobc 3.2 replaces a zero-length alphanumeric literal `""` with one space (it warns "alphanumeric
literal has zero length; a SPACE will be assumed") although `config/cobol2014.conf` sets `zero-length-literals: ok`. A
program that uses `""` as a function argument gets the value for a one-character space: `FUNCTION LENGTH("")` is 1
where ISO gives 0, and `FUNCTION TEST-NUMVAL-C("")` is 2 where ISO gives 1. Class: wrong output. Fuzz programs
fz00157, fz03681, fz04386, fz05091 (night fuzz-20261027-215606).

## Minimal test case

Free reference format.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. ZLEN.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 N PIC 9(4).
PROCEDURE DIVISION.
    MOVE FUNCTION LENGTH("") TO N
    DISPLAY "LENGTH " N
    MOVE FUNCTION TEST-NUMVAL-C("") TO N
    DISPLAY "TEST-NUMVAL-C " N
    STOP RUN.
```

## Environment

`cobc (GnuCOBOL) 3.2.0`, WSL2 Ubuntu, x86_64. Compiled with `cobc -x -free -std=cobol2014 -o p prog.cob`, run as
`timeout 10 ./p`.

## Observed result

Compile exit code 0, with the warning `alphanumeric literal has zero length; a SPACE will be assumed [-Wothers]` twice
(lines 7 and 9) and the C compiler's "'_FORTIFY_SOURCE' redefined" warning (the Ubuntu package's build flags, not the
program). Run, exit code 0:

```text
LENGTH 0001
TEST-NUMVAL-C 0002
```

## Expected result (per ISO)

§8.3.3.1 (checked): "If the opening and closing delimiters are contiguous, the length of the literal is zero, and it is
known as a zero-length literal." §8.5.4 8) (checked) counts "A zero-length literal" among the zero-length items.
§15.50.3 1) (checked) admits any alphanumeric literal as argument-1 of LENGTH (where the standard means to exclude a
zero-length literal it says so, as the MAX function's argument rule 3 does), and §15.50.4 3) (checked) makes the value
"an integer equal to the length of argument-1 in alphanumeric character positions", 0. For TEST-NUMVAL-C, a
zero-length argument-1 has no character in error and does not have the NUMVAL-C format, so §15.94.4 1) c) (checked)
gives "(FUNCTION LENGTH (argument-1) + 1)", 1; the NOTE that follows it lists "argument-1 is zero-length" among these
errors.

Edition: zero-length literals are new in the 2014 edition (`docs/VERSION_CHANGE_REFERENCE.md`, row
zero-length-literal-2014), so the rule applies to `-std=cobol2014`. The edge is derived, not quoted: the 2009
committee draft for ISO/IEC 1989:2014 (CD 1.2, std.txt line 4954, 8.3.1.2.1.2 rule 1) still required the length of an
alphanumeric literal to be "greater than zero", ISO/IEC 1989:2023 Annex E does not list zero-length literals among the
changes since 2014, and cobc's own `config/cobol2014.conf` sets `zero-length-literals: ok` where `cobol2002.conf` sets
`unconformable`. Expected output:

```text
LENGTH 0000
TEST-NUMVAL-C 0001
```

## Our compiler

WiseOwl COBOL (fresh judge, `--std 2014 --source-format free`): compiles with no diagnostic and prints `LENGTH 0000`
and `TEST-NUMVAL-C 0001`, exit code 0.

## Fix site

`cobc/scanner.l`, function `read_literal`: when the literal holds no characters it calls `cb_verify
(cb_zero_length_lit, ...)`, issues the warning and then stores one space into the literal buffer whatever the
`zero-length-literals` support level is. A FIXME comment just above the test says the behaviour should depend on the
support level ("OK" meaning standard behaviour).

## Draft issue

**Title:** -std=cobol2014: a zero-length literal is replaced by one space although zero-length-literals is ok

Environment: GnuCOBOL 3.2.0, WSL2 Ubuntu x86_64; `cobc -x -free -std=cobol2014 -o p prog.cob && ./p`.

Program:

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. ZLEN.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 N PIC 9(4).
PROCEDURE DIVISION.
    MOVE FUNCTION LENGTH("") TO N
    DISPLAY "LENGTH " N
    MOVE FUNCTION TEST-NUMVAL-C("") TO N
    DISPLAY "TEST-NUMVAL-C " N
    STOP RUN.
```

Observed: the warning "alphanumeric literal has zero length; a SPACE will be assumed", then `LENGTH 0001` and
`TEST-NUMVAL-C 0002`.

Expected: `LENGTH 0000` and `TEST-NUMVAL-C 0001`. ISO/IEC 1989:2023 8.3.3.1 defines "" as a zero-length literal
(zero-length literals are new in 2014); LENGTH returns the length of its argument in character positions (15.50.4 rule 3), and TEST-NUMVAL-C returns
LENGTH (argument-1) + 1 for a zero-length argument (15.94.4 rule 1 c and its NOTE). `config/cobol2014.conf` sets
`zero-length-literals: ok`, but `read_literal` in `cobc/scanner.l` substitutes a space at every support level (see the
FIXME there).
