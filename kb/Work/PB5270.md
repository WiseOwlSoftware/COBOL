# PB5270 - at --std 2014 the FROM/INTO record-area prohibition is enforced, but 2014 lifted it

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Validation/RecordAreaRule.cs` (`RecordAreaRule.InForce`: `editionYear < 2023`),
`src/WiseOwl.Cobol.Editions/Diagnostics/DiagnosticCatalog.cs` (`IoPhraseOperandIsRecordArea`, COBOL6827: its summary says "The 2023
standard replaces them"), `docs/CONFORMANCE.md` (the COBOL6827 row, editions "85, 2002, 2014"), `docs/FILES_DESIGN.md` (the
DETERMINATION paragraph, now pointing here).

**Mechanism.** PB5077 gated the rule at "every edition before COBOL-2023" because no 2014 text was held: the edition lineage routes
1985 to 2023 across 2014, so 2014 was taken to keep the 2002 rule (a DETERMINATION). The 2014 text, transcribed by PB5268, says
otherwise. Its Annex E lists all five phrases among the substantive changes not affecting existing programs, each "no longer
prohibited" (every citation checked with `scripts/spec/cite.py --check`):

- `§2014:E.3` item 21: "READ file-name-1 INTO identifier-1. A storage area identified by identifier-1 may now be the same storage
  area as, or be shared with, the record area associated with file-name-1".
- `§2014:E.3` item 24: "RELEASE record-name FROM identifier-1. It is no longer prohibited for Identifier-1 and record-name-1 to
  reference the same storage area."
- `§2014:E.3` item 25: "RETURN file-name-1 INTO identifier-1. A storage area identified by identifier-1 may now be the same storage
  area as the record area associated with file-name-1".
- `§2014:E.3` item 26: "REWRITE record-name-1 FROM identifier-1. It is no longer prohibited for identifier-1 and record-name-1".
- `§2014:E.3` item 38: "WRITE record-name-1 FROM identifier-1. Identifier-1 may now reference the same storage area as
  record-name-1".

The 2014 READ statement's own rules agree: its syntax rules carry no such prohibition, and its INTO general rule (`§2014:14.9.29.3`
GR4) has a NOTE referring the overlap to 14.6.9, Overlapping operands, and the MOVE general rules: the model 2023 keeps. The 2002 rule
it replaces is `§2002:14.8.29.2 SR2`.

**Harm.** A program that is legal at 2014, a FROM or INTO operand that is (or begins) the file's record area, is refused at
`--std 2014` with COBOL6827.

**Fix shape.** The rule's last edition is 2002: `InForce` is `editionYear < 2014`, the descriptor's summary and message name 2014 as
the edition that drops the rules (`§2014:E.3`), the CONFORMANCE row's editions become "85, 2002", and the edition-gate tests that
pin the 2014 refusal flip to acceptance with the overlap's undefined result. The sibling sweep: every DETERMINATION that routes an
edge across 2014 for want of the text (`docs/VERSION_CHANGE_REFERENCE.md` Table 7, `docs/CONFORMANCE.md`), checked against
`§2014:E.2` and `§2014:E.3`, the 2002-to-2014 change lists.
