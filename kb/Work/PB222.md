# PB222

Found by the cluster-B review fleet, 2026-08-31, from the witness it had already minted.

`scripts/spec/cite.py` is the mechanical guard CLAUDE.md rule 1 rests on, and its `--check` guarantee is exact
and sound: the text really is inside that clause's own region, so a wrong clause NUMBER cannot pass quietly.
But it also prints a best-effort RULE PATH, computed by walking BACKWARD from the matched line to the nearest
top-level `N)` marker — and a clause's normative prose is not always inside a numbered item. When it is not, the
walk attaches the LAST preceding ordinal, and the output reads exactly like a verified one.

**REPRODUCED, both halves:**

    $ python scripts/spec/cite.py --check 8.8.4.2.1 \
        "A relation condition shall contain at least one reference to an operand that is not a literal"
    OK  §8.8.4.2.1 13)  (General)

    $ python scripts/spec/cite.py --check 8.8.4.2.1 "Two compatible variable-length groups"
    OK  §8.8.4.2.1 13)  (General)

Two different sentences, the same printed ordinal, and only one of them IS item 13. §8.8.4.2.1's numbered list
1)–13) is "Comparisons are defined for the following"; the quoted rule is an unnumbered paragraph AFTER item 13.

**THE WITNESS IS IN THIS REPOSITORY AND THAT IS THE POINT.** [[PB182]] swept the repo for the phantom clause
"§8.8.4.1.1" and repaired every site. Two of the repairs wrote `§8.8.4.2.1 r13` — the substantive proposition was
right, the clause was right, and the ORDINAL came from this tool's own output. The other two PB182 repairs, made
in the same change set, correctly used the bare `§8.8.4.2.1`. So the tool minted a defect of exactly the shape
rule 1 exists to prevent — an inherited ordinal that nobody re-derived — inside the sweep that was fixing
inherited citations. Both `r13` sites are corrected to the bare form in the cluster-B landing; this note owns
the TOOL.

⚠ The tool's own help already hedges — "it is APPROXIMATE below two levels of nesting … read the printed rule
when the ordinal itself is load-bearing" — but the hedge is about NESTING depth, and this failure is about
prose OUTSIDE the list entirely, at top level, where a reader has no cue to distrust it.

## WHAT WOULD CLOSE IT

Make the rule path REFUSE rather than guess. When the matched line is not inside the span of the numbered item
the walk landed on — i.e. the item's own text ended before the match — print the clause with NO ordinal (and,
better, say so: `OK §8.8.4.2.1 (unnumbered prose)`), so the correct citation form is what the tool hands the
reader. A path that cannot be verified should not be printed in the same shape as one that can; a `--check`
whose ordinal is a guess is the "green gate over the wrong subject" shape one layer down from the code.

A regression test is available for free: the two commands above must print DIFFERENT paths.
