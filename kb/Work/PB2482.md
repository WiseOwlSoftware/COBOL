# PB2482 — the session mailbox has no tool

Owner, 2026-10-07 13:17 PDT: a second Claude Code session, logged into a second Max 20x account (`CLAUDE_CONFIG_DIR=C:\Users\brent\.claude-acct2`), runs every Opus/Sonnet dispatch, the orchestrator loop and the landings (the OPERATOR); the first account's session keeps Mythos work. The owner seeded the second config dir by hand. Owner 13:36 PDT: account 2's week resets Saturday 2026-10-10 10:00 PDT and must be spent to 100 % before then, so every hour the tooling stops dispatch wrongly is quota lost.

**Model:** Opus (tooling with self-tests). All six notes are one mechanism (the account is a parameter of the coordination tooling, never an assumption) and are dispatched as one group.

## Defect

`E:\COBOL-coord\mailbox\README.md` (owner 13:35 PDT: "pass work to each other without me in the loop") defines the
message shape and promises `scripts/orchestrator/mailbox.py`. On 2026-10-07 13:47 the operator's hand-written `info`
message carried `E:\COBOL-coord\scratch\x08riefs…` in `refs` (an escape mangled in a one-liner), and the operator's
own `operator-session.json` was invalid JSON (unescaped backslashes) when the next session read it.

## Shape

`scripts/orchestrator/mailbox.py send --to --kind --subject --body --ref … [--needs-owner] [--owner-quote]`,
`list --inbox`, `take <id>`, `done <id> --status --report`, `watch --inbox` (prints and exits when a message arrives,
for a background Bash watcher): validates kind, the 900-character body, non-empty refs, that every path ref exists;
writes atomically; `--self-test`. A `session` subcommand writes/reads `operator-session.json` with a JSON library.
The README points at it; the loop's `land`/`wave` units post a `publish` message where they log LEDGER PUBLISH OWED.
