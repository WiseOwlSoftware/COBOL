# PB4003 — test-numval-31-digit-limit-not-applied: TEST-NUMVAL / TEST-NUMVAL-C accept 32 to 38 digits; ISO returns the position of the 32nd digit

Filed 2026-10-28 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-20261027-215606`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

Under `-std=cobol2014` with native arithmetic (no ARITHMETIC clause), `FUNCTION TEST-NUMVAL` and `FUNCTION TEST-NUMVAL-C`
of a 32-digit string return 0 (valid) where ISO returns 32, the position of the 32nd digit. libcob checks the digit count
against its internal 38-digit limit, not the standard's 31. Class: wrong output. Fuzz program fz00863 (night
fuzz-20261027-215606).

## Minimal test case

Free reference format.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. TNV32.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 N PIC 9(4).
PROCEDURE DIVISION.
    MOVE FUNCTION TEST-NUMVAL("12345678901234567890123456789012")
      TO N
    DISPLAY "TEST-NUMVAL " N
    MOVE FUNCTION TEST-NUMVAL-C("12345678901234567890123456789012")
      TO N
    DISPLAY "TEST-NUMVAL-C " N
    STOP RUN.
```

## Environment

`cobc (GnuCOBOL) 3.2.0`, WSL2 Ubuntu, x86_64. Compiled with `cobc -x -free -std=cobol2014 -o p prog.cob`, run as
`timeout 10 ./p`.

## Observed result

Compile exit code 0, no cobc diagnostic (the only compile-time message is the C compiler's "'_FORTIFY_SOURCE'
redefined" warning, from the Ubuntu package's build flags). Run, exit code 0:

```text
TEST-NUMVAL 0000
TEST-NUMVAL-C 0000
```

A probe with longer strings shows TEST-NUMVAL and TEST-NUMVAL-C still returning 0 for 38 digits, and TEST-NUMVAL
returning 39 for 39 digits: 32 to 38 digits are accepted.

## Expected result (per ISO)

§11.9.5.2 4) (checked): with no ARITHMETIC clause "it is as if the ARITHMETIC clause were specified with the NATIVE
phrase". §15.67.3 3) (checked, NUMVAL) and §15.68.3 6) (checked, NUMVAL-C): "If native arithmetic is in effect, the
total number of digits in argument-1 shall not exceed 31", so a 32-digit string does not conform to the argument rules
and the returned value is not 0. §15.93.4 1) b) 2. (checked, TEST-NUMVAL) and §15.94.4 1) b) 2. (checked,
TEST-NUMVAL-C): "If native arithmetic is in effect, because the character in error for an argument that is greater than
31 digits is the 32nd digit, the returned value is the position of the 32nd digit if no prior error is found."

Edition: TEST-NUMVAL and TEST-NUMVAL-C are 2014 functions. The 2009 committee draft for ISO/IEC 1989:2014 (CD 1.2,
std.txt lines 35192 and 35319) limits the NUMVAL and NUMVAL-C argument to 31 digits whatever the arithmetic ("The total
number of digits in argument-1 shall not exceed 31", its 15.62.2 rule 2 and 15.63.2 rule 7) and gives the 32nd-digit
position in NOTE 2 of its 15.86.3 and 15.87.3, so the 2014 answer is the same. Expected output:

```text
TEST-NUMVAL 0032
TEST-NUMVAL-C 0032
```

## Our compiler

WiseOwl COBOL (fresh judge, `--std 2014 --source-format free`): no diagnostic; prints `TEST-NUMVAL 0032` and
`TEST-NUMVAL-C 0032`, exit code 0.

## Fix site

`libcob/intrinsic.c`, function `cob_check_numval` (shared by `cob_intr_test_numval` and `cob_intr_test_numval_c`): the
digit case returns the error position only when the count exceeds `COB_MAX_DIGITS` (38, `libcob/common.h`). Under
native arithmetic the limit the standard states is 31 (35 and 34 under the standard-binary and standard-decimal modes).
`cob_check_numval_f` uses the same constant.

## Draft issue

**Title:** TEST-NUMVAL / TEST-NUMVAL-C accept 32 to 38 digits; ISO returns the position of the 32nd digit

Environment: GnuCOBOL 3.2.0, WSL2 Ubuntu x86_64; `cobc -x -free -std=cobol2014 -o p prog.cob && ./p`.

Program:

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. TNV32.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 N PIC 9(4).
PROCEDURE DIVISION.
    MOVE FUNCTION TEST-NUMVAL("12345678901234567890123456789012")
      TO N
    DISPLAY "TEST-NUMVAL " N
    MOVE FUNCTION TEST-NUMVAL-C("12345678901234567890123456789012")
      TO N
    DISPLAY "TEST-NUMVAL-C " N
    STOP RUN.
```

Observed: `TEST-NUMVAL 0000` and `TEST-NUMVAL-C 0000`.

Expected: `TEST-NUMVAL 0032` and `TEST-NUMVAL-C 0032`. ISO/IEC 1989:2023 15.93.4 and 15.94.4, rule 1 b) 2 (both
functions are new in 2014):
under native arithmetic (the default when no ARITHMETIC clause is written, 11.9.5.2 rule 4) an argument of more than 31
digits is in error at its 32nd digit, because NUMVAL and NUMVAL-C admit at most 31 digits (15.67.3 rule 3, 15.68.3 rule
6; the 2014 edition's committee draft sets the same 31-digit limit). `cob_check_numval` in `libcob/intrinsic.c` compares the digit count with
`COB_MAX_DIGITS` (38).
