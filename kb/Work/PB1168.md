# PB1168 — OPEN

## The rule (every citation re-run by the registrar through `cite.py --check`)

> 16) For a record sequential file, if the number of bytes in the data item referenced by identifier-1, the runtime representation of literal-1, or the record referenced by record-name-1 is not equal to the number of bytes in the record being replaced, the execution of the REWRITE statement is unsuccessful and the I-O status … is set to '44'

`python scripts/spec/cite.py --check 14.9.35.4 "…"` → `OK  §14.9.35.4 16)  (General rules)`

> 17) b) If the number of bytes … is greater than the number of bytes in the record being replaced, the execution of the REWRITE statement is unsuccessful and the I-O status … is set to '44'. c) … is less than … then a sufficient number of the space character is appended …

`python scripts/spec/cite.py --check 14.9.35.4 "…"` → `OK  §14.9.35.4 17)  (General rules)`

## Finding — `rewrite-statement-p1` (wrong-answer; rows `GR-14.9.35.4-16`)

**Mechanism.** Record-sequential REWRITE compares record-name-1's size with the replaced record ONLY for a varying file: SequentialConnector.Rewrite sets `len = IsVarying ? ... : RecordWidth` and tests `IsVarying && len != LastReadLength`, so on a FIXED-length file (explicit RECORD CONTAINS, or the implicit Format 1 COBOL.NET chooses for a multi-01 FD) a shorter record-name-1 is padded by FitRecord and written over the record with '00'

**Repro.** ORGANIZATION RECORD SEQUENTIAL, FILE STATUS ST; FD F. 01 R1 PIC X(10). 01 R2 PIC X(20). OPEN OUTPUT; WRITE R1 'AAAAAAAAAA'; WRITE R2 ALL 'B'; WRITE R1 'CCCCCCCCCC'; CLOSE; OPEN I-O; READ; READ (record 2, 20 bytes); REWRITE R1 FROM W10 (W10 = 'XXXXXXXXXX'); DISPLAY ST; CLOSE; OPEN INPUT; READ; READ; DISPLAY R2. (scratchpad probe pa.cob)

**Expected from the spec.** The FD has no RECORD clause and no variable-length record, so the implicit clause is Format 1 with integer-1 = 20 (13.18.43.4 GR5 a), CONFORMANCE.md D-FRA) and every record holds 20 bytes (13.18.43.4 GR6). record-name-1 R1 has 10 bytes, not equal to the 20 of the record being replaced, so the REWRITE is unsuccessful with I-O status '44' (14.9.35.4 GR16), and GR14 leaves the record unchanged: ST=44, record 2 still 20 B's.

**Observed / reasoning.** Observed RW10-ON20=00 and the re-read record 2 = 'XXXXXXXXXX' + 10 spaces: the record was replaced. The same program with RECORD IS VARYING IN SIZE FROM 10 TO 20 (probe pb.cob) gives 44 both ways and leaves the file intact, so only the fixed-length arm lacks the GR16 test. The emitter passes length -1 for a non-varying file, but the image it passes is record-name-1's own image, so the runtime has the size it needs (or the emitter can pass record-name-1's byte length explicitly).

**Code site.** src/Cobol.Net.Runtime/IO/SequentialConnector.cs#Rewrite (the `int len = IsVarying ? ... : RecordWidth` / `if (IsVarying && len != LastReadLength)` lines); src/Cobol.Net.Compiler/CodeGen/Verbs/SequentialIoEmitter.cs#EmitRewrite (length argument)

## Finding — `rewrite-statement-p1` (wrong-answer; rows `GR-14.9.35.4-17`)

**Mechanism.** The record-sequential GR16 equality test runs BEFORE the line-sequential branch of SequentialConnector.Rewrite, so a varying LINE-sequential REWRITE of a record SHORTER than the line gets '44', where §14.9.35.4 GR17 c) requires space-padding it to the line's length and succeeding

**Repro.** ORGANIZATION LINE SEQUENTIAL, FILE STATUS ST; FD F RECORD IS VARYING IN SIZE FROM 1 TO 20 CHARACTERS. 01 R1 PIC X(10). 01 R2 PIC X(20). OPEN OUTPUT; MOVE ALL 'B' TO R2; WRITE R2; CLOSE; OPEN I-O; READ; MOVE 'SHORT' TO R1; REWRITE R1; DISPLAY ST; CLOSE; OPEN INPUT; READ; DISPLAY R2. (scratchpad probe pc.cob)

**Expected from the spec.** GR16 applies to 'a record sequential file' only. GR17 c): R1's 10 bytes are fewer than the 20 bytes of the line being replaced, so spaces are appended to make 20 bytes and the REWRITE succeeds: ST=00, the line becomes 'SHORT' followed by 15 spaces.

**Observed / reasoning.** Observed LS-VAR-SHORTER=44 and the line unchanged (20 B's). `if (IsVarying && len != LastReadLength) return RecordSizeViolation` (commented GR16 'record sequential') sits above the `_lineSequential` branch, so it also catches line-sequential files. The same would happen with a DEPENDING ON data-name-1 whose value is less than the line length.

**Code site.** src/Cobol.Net.Runtime/IO/SequentialConnector.cs#Rewrite (the GR16 test is placed before the `_lineSequential` arm)

## Finding — `rewrite-statement-p1` (wrong-answer; rows `GR-14.9.35.4-17`)

**Mechanism.** The line-sequential GR17 b) size test compares the TRIMMED content length (`TrimRecordEnd(Fit(image)).Length`, i.e. WRITE's GR21 trailing-space rule) with the line length, where GR17 b) compares the number of bytes in the record referenced by record-name-1, so a record longer than the line is accepted whenever its extra bytes are spaces, and the line is overwritten

**Repro.** ORGANIZATION LINE SEQUENTIAL, FILE STATUS ST; FD G. 01 G1 PIC X(10). OPEN OUTPUT G; MOVE 'AB' TO G1; WRITE G1 (the line is 'AB', trailing spaces not transferred per 14.9.51.4 GR21); CLOSE; OPEN I-O G; READ G; MOVE 'HI' TO G1; REWRITE G1; DISPLAY ST. (scratchpad probe pc.cob, file G)

**Expected from the spec.** The record being replaced is 2 bytes (a line's length is the characters between delimiters, 9.1.x record-length paragraph); record-name-1 G1 is 10 bytes, which is greater, so GR17 b) makes the REWRITE unsuccessful with '44' and the line stays 'AB'. GR17 has no trailing-space rule; only WRITE's 14.9.51.4 GR21 says spaces are 'not transferred'.

**Observed / reasoning.** Observed LS-10BYTE-ON-2=00 and the file line becomes 'HI'. The existing CA18 test (SequentialFileIoSpecTests.LineSequential_Rewrite_Gr17_Equal00_Longer44_Shorter00) cannot catch this: its cases ('XYZ' in X(5) over 'AB', 'HI' in X(5) over 'CDEFG') give the same result under both readings, although its derivation comment gives the trimmed reading ('XYZ(3) > AB(2)'). If the owner prefers the trimmed reading as the more usable one, that is a departure from the text and needs a CONFORMANCE.md determination rather than a silent choice.

**Code site.** src/Cobol.Net.Runtime/IO/SequentialConnector.cs#Rewrite (`string content = TrimRecordEnd(Fit(image)); if (content.Length > _lastLineBytes) ...`)

## What the fixer owes

Restructure SequentialConnector.Rewrite as ONE dispatch on organization first (record sequential → GR16 equality on record-name-1's byte length for EVERY record-sequential file, fixed or varying; line sequential → GR17 a)/b)/c) on the UNTRIMMED byte count), with the emitter passing record-name-1's byte length for a non-varying file (EmitRewrite passes -1 today). Pin with goldens pa.cob (ST=44, record unchanged), pc.cob (LS-VAR-SHORTER=00, padded line) and the G leg (LS-10BYTE-ON-2=44). The existing CA18 test's derivation comment gives the trimmed reading and must be corrected; if the owner prefers the trimmed reading, that is a CONFORMANCE.md determination, not a silent choice.
