# PB5790 - LEAD, not verified by a ruling: at --std 85 SIGN SEPARATE with BLANK WHEN ZERO is refused (COBOL2422) where the printed Table 1 of the report writer (page 605) permits it

**This is a lead, not a ruling.** The row the checker was reading, `1985-GR-XIII.3.9.4-2`, is REJECTED: the compiler treats the report entry and the Working-Storage entry alike, as the row requires. The lead below is the refuter's attack on OTHER rows, which the checker found real but which no ruling has verified. The checker's confidence: medium.

**The lead.** The printed Table 1 of `§1985:XIII.3.9.3 SR11` (page 605 rendered) marks BLANK WHEN ZERO `P` and SIGN `P` together in the SUM row and in the SOURCE row, so a report entry `PIC S9(5) SIGN LEADING SEPARATE BLANK WHEN ZERO SOURCE x` is legal 1985 source, and `XIII.3.17.3 SR1` ("numeric data description entry whose PICTURE contains the character S") must be read to admit it. The compiler applies `VI.5.4.4 GR2`'s "considered to be numeric edited" first and refuses (COBOL2422, citing §2023 at 85). At 2023, S beside BWZ is refused before SIGN arises (COBOL1934), so for those rows the cause would be (a). The Nucleus twin (Working-Storage) is an open reading on its own (kb/Work PB5191's lead: `kb/Work/PB5191/2026-11-13-landing.md`); Table 1 settles only the Report Section.
