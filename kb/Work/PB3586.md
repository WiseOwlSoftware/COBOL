# PB3586 - a USAGE BIT RETURNING item loses its value on the way back to the caller

## Scenario

Found by the PB3565 implementer while sweeping sole-boolean-operand hosts. Repro (kept at
`E:\COBOL-coord\scratch\reports\w1157j-lead-udf-bit-returning.cob`, run with `--source-format free --run`; never run it inside
conformance-suite, which writes .dll/.g.cs beside the file):

```cobol
IDENTIFICATION DIVISION.
FUNCTION-ID. UBIT.
DATA DIVISION.
LINKAGE SECTION.
01 L-X PIC 9.
01 L-R PIC 1(8) USAGE BIT.
PROCEDURE DIVISION USING L-X RETURNING L-R.
P.
    MOVE B"00001010" TO L-R.
    DISPLAY "INSIDE=" L-R
    GOBACK.
END FUNCTION UBIT.
IDENTIFICATION DIVISION.
PROGRAM-ID. UDF4.
ENVIRONMENT DIVISION.
CONFIGURATION SECTION.
REPOSITORY.
    FUNCTION UBIT.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 B8 PIC 1(8).
01 BB PIC 1(8) USAGE BIT.
PROCEDURE DIVISION.
    MOVE FUNCTION UBIT(3) TO B8
    DISPLAY "MOVE8=" B8
    MOVE FUNCTION UBIT(3) TO BB
    DISPLAY "MOVEBB=" BB
    STOP RUN.
END PROGRAM UDF4.
```

Observed: `INSIDE=00001010`, then the caller's `MOVE FUNCTION UBIT(3) TO B8` shows `00000000`. The same function declared
`PIC 1(8)` (no USAGE BIT) returns `00001010`. Silent wrong answer.

## Rule

The function-identifier's temporary data item takes the description of the item named in the RETURNING phrase, so its value is that
item's value (spec section 8.4.3.2.4 GR1, `cite.py --check 8.4.3.2.4` OK: "the description, class, and category of the temporary data
item is that specified by the description in the linkage section of the item specified in the RETURNING phrase"). Boolean functions
have an implicit usage bit (section 15.2 2, `cite.py --check` OK). The value `B"00001010"` placed in L-R must reach the caller
unchanged.

## Code site (unlocated beyond this)

The PB3565 implementer did not read it: the user-function result copy in `IntrinsicBinder.BindFunctionResult` or the activation
return in `CodeGen/ProgramEmitter.cs`. The `PIC 1(8)` arm works, so the USAGE-BIT arm is the one that drops the bits; compare with
how PB3562 treats a boolean function value (`SendingValueTemp.CharacterUsage`). Sweep the siblings: a USAGE BIT RETURNING item
through MOVE, DISPLAY, a relation condition and a COMPUTE sole operand (PB3565).

**Sites:** `src/Cobol.Net.Compiler/CodeGen/Verbs/CallEmitter.cs` (the note named `IntrinsicBinder.cs` and `ProgramEmitter.cs`;
neither needed a change); golden under `conformance-suite/cases/8.4.3.2-Function-identifier/` (edition 2002 and up).

## Landed

**Root cause (re-probed on the wave-20261024 build; both repros reproduced).** `CallEmitter.BoundaryImageWidth` - the one
answer for the character width of a formal's TEXT crossing, which `BoundaryLength` turns into `CobolArg.Length` and the
registered `BoundaryItem` length - returned `DataItem.ImageWidth` for an elementary item. For `PIC 1(8) USAGE BIT` that is
the OCCUPANCY (`BitLayout.Characters(8)` = 1 storage character), while the item crosses as its 8 boolean POSITIONS
(`CallStringRead`). The caller's RETURNING `CobolArg` therefore stated `Length: 1` and the delivery fitted the 8-position
result to one position. The bit GROUP arm (`IsAsIfElementary`, `AsIfPic.Length`) was already right, which is why the USAGE BIT
item failed while a GROUP-USAGE BIT result and the no-USAGE-BIT item worked. The same defect hit `CALL "SUBR2" RETURNING BB`
for a program, not only a function: `RET=00000000` before, `01010101` after.

**Fix.** `BoundaryImageWidth` answers `Pic.Length` (positions) for an elementary `USAGE BIT` item, so the caller's receiver, the
callee's registration, the .NET host entry's detached storage (`HostEntryEmitter`) and `FigurativeFillWidth` (now reading
`BoundaryImageWidth` instead of `ImageWidth`, an I9 sibling) share one width. Swept and correct: a 12-position item (two
storage characters), a GROUP-USAGE BIT result, an OO method RETURNING and USING a USAGE BIT item, a BY REFERENCE and a BY
CONTENT USAGE BIT argument, a USAGE NATIONAL RETURNING item (national positions already equal `ImageWidth`).

**Goldens:** `cases/8.4.3.2-Function-identifier/pb3586_function_returning_usage_bit` (accept 2002 and up: the function result
moved to a USAGE BIT and a display-usage receiver, a 12-position result, a DISPLAY operand, a relation condition, and the CALL
RETURNING twin) and `pb3586-function-returning-usage-bit-85` (refused at 85, COBOLNET0900).
