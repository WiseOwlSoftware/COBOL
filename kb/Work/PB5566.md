# PB5566 - RECORD KEY IS K and ALTERNATE RECORD KEY IS K compile unqualified when a second K is declared outside the file's records: ResolveFiles prefers the candidate in the file's records instead of reporting the ambiguity

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/FileControlBinder.Resolve.cs` (`FileControlBinder.ResolveFiles`, whose local function InRecords prefers the candidate in the file's records)

**Mechanism.** Every other reference resolves through `DataBinder.QualifiedCandidates` / `UniqueOrReportAmbiguous` and refuses an unqualified name declared twice (COBOL1639): an unqualified FLD or CNT, DEPENDING ON CNT, ASCENDING KEY IS FLAG, RENAMES X THRU Y, a non-unique FILE STATUS item (since kb/Work PB5165 the 1985 entry clauses take no implicit qualifier). `FileControlBinder.ResolveFiles` resolves RECORD KEY and ALTERNATE RECORD KEY with a local `InRecords` that prefers the candidate inside the file's records over counting both, so the key's name never needs its qualifier. Syntax rule 2's requirement that the key lie in the file's record is a constraint on the referenced item, not a disambiguation. The same programs compile at --std 2023 too; the 2023 qualification rule (§2023:8.4.2.1) is the same requirement, so the fix is edition-neutral.

**Found by.** The 1985 re-read 5, batch 1 (`kb/Work/PB4996/2026-11-14-reread-5.md`): the reader of `E:/COBOL-coord/scratch/op-20261114/out-reread5/rs-01.json` read `1985-SR-IV.4.3.8.1-3` PARTIAL; the row named no kb/Work note.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094), so `inventory_rows` is empty; the row this note claims is below, recorded PARTIAL naming this note (records-rs5a).
