# PB3331 — the page layer and the generation ledger

Implement FROM `docs/rearchitecture/DESIGN-runtime-library.md` §2.2.1, sections 2.2.1.4 (the PAGE and META layouts), 2.2.1.6
(rules R1-R6) and 2.2.1.12 (the drift tests), not from this note. This note is the register entry.

## Mechanism

A new folder `src/Cobol.Net.Runtime/IO/Store/` holding the engine's lowest layer, used by nothing in the connectors yet
(PB3333 is the first caller):

- `IPageMedium` — read page n / write page n / sync / page count / set page count, over 4 096-byte pages. Two implementations:
  `HandlePageMedium` (production: `RandomAccess.Read`/`Write`/`FlushToDisk` through a connector's `SafeFileHandle`, one page per
  call) and, under `tests/`, `MemoryPageMedium` (an in-memory page array that logs every write and sync, and can LOSE every
  unsynced write, KEEP them, or TEAR one named page — the crash simulator of 2.2.1.12).
- `PageHeader` / `PageKind` — the 32-byte header (kind, flags, entries, CRC-32C checksum over bytes 8..4095, generation, self,
  next), one encoder and one decoder; a page whose checksum or `self` disagrees is a TORN read, surfaced as a typed result, never
  an exception swallowed.
- `MetaPage` — the format-5 meta layout of 2.2.1.4 (magic `CBNFSTR` + version 5, the §9.1.6 attributes in format 4's
  descriptor encoding, generation, release mint, page count, roots, committed generation, the UNDER COMMIT CONTROL and CLEAN
  CLOSE bits), encoder and decoder; `Describes(path)` reads page 0 through `HostFile.OpenAuxiliary` and answers
  `StoreFormat` {Empty, Described, Foreign} so `KeyedConnector.FixedAttributeConflict` and `SequentialConnector`'s keyed-store
  check can move to it in PB3333/PB3334 (a format-4 file is Foreign: '39', no reader kept).
- `Ledger` — the fresh/freed set since the committed generation (page → last-write generation, state), persisted as a small
  tree of PB3332's engine; until PB3332 lands it is an in-memory map plus a page-array serialization so this group's crash matrix
  can run (that serialization is replaced, not wrapped, by PB3332).
- `PagedFile` — allocation (lowest free page, else growth), the R1-R4 write discipline (`WritePage` refuses a page the committed
  meta references; a fresh page is written in place; a freed page is quarantined), `Promote` (R5: sync, copy work meta to the
  committed slot, sync; the checkpoint policy of 1 024 ledger pages or 4 096 statements for a store not under commit control),
  `Open` (R6: both slots read and validated, the adoption rule, the committed-slot fallback that frees the fresh pages and
  revives the freed ones), `Create` (two meta pages, `SetLength` to two pages), and `IoCounters` (pages read, pages written,
  syncs, per statement) for PB3336's witnesses.

## Tests

- The crash matrix of 2.2.1.12: {process death, power loss with every write durable, power loss losing the last k writes, a
  torn fresh page, a torn meta slot} × {not under commit control, under commit control} → the adopted slot and a consistent file.
- R1: no write targets a page the committed meta references (the medium's write log, checked after every statement).
- R2/R3: the ledger lists exactly the pages written since promotion; a fresh page is rewritten in place.
- R4: a page freed at generation G is not allocated before G's promotion.
- R5: every page the committed slot names was synced before the slot was written.
- The golden hex dump of an empty relative and an empty two-key indexed meta page; the checksum catches one flipped bit in every
  page kind; `self` catches a page read from the wrong offset.
- A medium that refuses the n-th write of a statement leaves the file at the previous statement (atomicity).
