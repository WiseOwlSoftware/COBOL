# PB3331 — the page layer and the generation ledger

Implement FROM `docs/rearchitecture/DESIGN-runtime-library.md` §2.2.1, sections 2.2.1.4 (the PAGE and META layouts, the
POINTER), 2.2.1.6 (rules R1-R6, as corrected on 2026-10-17 after the round-1 review) and 2.2.1.12 (the drift tests), not from
this note. This note is the register entry.

## Mechanism

A new folder `src/Cobol.Net.Runtime/IO/Store/` holding the engine's lowest layer, used by nothing in the connectors yet
(PB3333 is the first caller):

- `IPageMedium` — read page n / write page n / sync / page count / set page count, over 4 096-byte pages. Two implementations:
  `HandlePageMedium` (production: `RandomAccess.Read`/`Write`/`FlushToDisk` through a connector's `SafeFileHandle`, one page per
  call) and, under `tests/`, `MemoryPageMedium` (an in-memory page array that logs every write and sync, and can LOSE every
  unsynced write, KEEP them, TEAR one named page, or SERVE AN OLDER VERSION of one named page — the crash simulator of 2.2.1.12).
- `PageHeader` / `PageKind` / `PagePointer` — the 32-byte header (kind, flags, entries, CRC-32C checksum over bytes 8..4095,
  generation, self, next), one encoder and one decoder; the 12-byte POINTER (page number + the generation of the write it
  names, 2.2.1.6 R3); a read through a pointer verifies checksum, `self` and generation == the stamp, and a page that fails is
  a TORN read, surfaced as a typed result, never an exception swallowed.
- `MetaPage` — the format-5 meta layout of 2.2.1.4 (magic `CBNFSTR` + version 5, the §9.1.6 attributes in format 4's
  descriptor encoding, generation, release mint, page count, transaction mint, the four root POINTERS, committed generation,
  the CLEAN CLOSE bit), encoder and decoder; `Describes(path)` reads pages 0 and 1 through `HostFile.OpenAuxiliary`, takes the
  valid slot with the higher generation, and answers `StoreFormat` {Empty, Described, Foreign} so
  `KeyedConnector.FixedAttributeConflict` and `SequentialConnector`'s keyed-store check can move to it in PB3333/PB3334 (a
  format-4 file is Foreign: '39', no reader kept).
- `Ledger` — the set of pages allocated since the committed generation (page → last-write generation, state ∈ {fresh,
  released, freed}), persisted as a small tree of PB3332's engine; until PB3332 lands it is an in-memory map plus a page-array
  serialization so this group's crash matrix can run (that serialization is replaced, not wrapped, by PB3332). It does not list
  its own pages.
- `PagedFile` — the RESERVATION (a statement reserves its pages first: released pages, then one batch of the lowest FREE-tree
  pages sized to the statement's bound, then growth; nothing is allocated once the ledger is being written), the R1-R4 write
  discipline (`WritePage` refuses a page that EITHER slot's tree references — there is no in-place rewrite; a freed page is
  quarantined; a released page is reusable one statement later), `Promote` (R5: sync, write the work meta into the committed
  slot holding the LOWER generation, sync; the checkpoint policy of 1 024 ledger pages or 4 096 statements for every file),
  `Open` (R6, run by the caller under the store mutex: the three slots read and validated, the committed meta = the valid
  committed slot with the higher generation, '30' when neither validates, the work slot adopted when it validates, descends
  from the committed meta and every listed `fresh` page verifies, else the committed meta adopted and the work slot rewritten
  from it by a writable handle — an INPUT handle adopts in memory — with the abandoned ledger's pages reclaimed; the
  dead-transaction step is PB3337's and this group reads an empty TRANSACTIONS tree), `Create` (three meta pages, `SetLength`
  to three pages), and `IoCounters` (pages read, pages written, syncs, per statement) for PB3336's witnesses.

## Tests

- The crash matrix of 2.2.1.12, every row and column, with the expected cell the section states: {process death after a
  statement; process death mid-statement; power loss with every write durable; power loss losing the last k writes; a torn
  fresh page; a torn work slot; a torn committed slot; both committed slots torn; an OPEN while another handle holds the file}
  × {no transaction; a transaction open at the crash — the transaction column lands with PB3337} → the adopted meta and a
  consistent file; '30' for both committed slots torn.
- R1: no write targets a page the committed OR the work tree references (the medium's write log, both trees walked after
  every statement).
- R2: the ledger lists exactly the pages allocated since promotion with their last generation and state; a released page is
  reused only by a later statement; no allocation after the ledger write starts.
- R3: a page served at an older version under a stamped pointer is refused as torn.
- R4: a page freed at generation G is not allocated before G's promotion.
- R5: every page the committed slot names was synced before the slot was written; two consecutive promotions write different
  slots.
- The golden hex dump of an empty relative and an empty two-key indexed store (the three meta pages); the checksum catches one
  flipped bit in every page kind; `self` catches a page read from the wrong offset.
- A medium that refuses the n-th write of a statement leaves the file at the previous statement (atomicity).
