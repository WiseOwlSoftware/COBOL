## Measured

### Finding type-clause-p1 — ISO/IEC 1989:2023 §13.18.57.3 SR13, SR14, SR15 (under-rejects; rows SR-13.18.57.3-13, SR-13.18.57.3-14, SR-13.18.57.3-15)

**Mechanism.** No report-level census of the group set: nothing in the binder checks the collection of report groups in one RD against §13.18.57.3 SR13 (RH/PH/RF/PF at most once), SR14 (at most one CH and one CF per control level or FINAL) or SR15 (at least one body group). The runtime ReportWriter.AddGroup stores each type in a single slot (or one per control level), so a duplicate silently REPLACES the earlier declaration — its doc comment claims these are 'diagnosed at bind', and they are not.

**Repro.** out13/probe/type-clause-p1/sr13_two_rh.cob (two TYPE RH groups, values R11/R22) -> compiles, report shows only R22; sr13_two_ph / sr13_two_pf / sr13_two_rf likewise; sr14_two_ch_same.cob (two `TYPE CH CX` under CONTROL IS CX) -> only C22 printed; sr14_two_cf_final.cob (`TYPE CF FINAL` + omitted-operand `TYPE CF` under CONTROL IS FINAL) -> only C22; sr15_no_body_nogen.cob (RD with only TYPE RH + TYPE PH) -> compiles and runs. Same at --std 85 and 2002.

**Expected, from the standard.** Each program is nonconforming and must draw a compile-time diagnostic: SR13 'REPORT HEADING, PAGE HEADING, REPORT FOOTING, and PAGE FOOTING may each appear no more than once in any given report description'; SR14 'At most one CONTROL HEADING and at most one CONTROL FOOTING may be defined for each control data item or FINAL of the CONTROL clause'; SR15 'Each report description shall include at least one body group' (DETAIL, CONTROL HEADING or CONTROL FOOTING). Legal controls: distinct CH/CF per level (sr14_distinct_ok) and a CF-only report (sr16_no_detail_ok) must keep compiling.

**Observed.** All the duplicate/no-body programs compile clean; the report output shows the last-declared group winning its slot (the earlier group's lines are lost). ResolveReports computes each CH/CF ControlLevel (after the SR11 omitted-operand resolution) but never compares two groups' (Kind, ControlLevel); no screen counts RH/PH/PF/RF or body groups. The natural home is one pass over model.Groups in DataBinder.Reports.cs#ResolveReports after ControlLevel is known (SR14 needs the resolved level, so an omitted operand and a written one naming the same control collide correctly).

**Code site.** src/Cobol.Net.Compiler/Binding/DataBinder.Reports.cs#ResolveReports; src/Cobol.Net.Runtime/IO/ReportWriter.cs#AddGroup
