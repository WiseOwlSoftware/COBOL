# PB2073 — LANDED — the probe cannot see a function-identifier property object

## Mechanism

`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/OoBinder.PropertyObject.cs#OoBindPropertyObject`, line 53:
`if (probe) return po.objectView() is { } pv ? DescribedByView(pv) : null;` — a probe must not bind a function (a side
effect), so a `functionCall()` object answers null, and `ReferenceResolver.IsObjectPropertyReference` (the ONE test,
PB238 DEFECT 4) reports "not a property" for `BAL OF FUNCTION F (1)`.

## Consequence

§14.9.4.3 SR20 (cite.py OK): "BY CONTENT shall not be omitted when identifier-4 is an identifier that is permitted as a
receiving operand, except that BY CONTENT may be omitted when identifier-4 is an object property." — so
`CALL "P" USING BAL OF FUNCTION F (1)` (no BY CONTENT) should be accepted and is expected to be refused.

## Repro to write

A class with an object property BAL and a user-defined function F returning an object reference to it; a client
`CALL "P" USING BAL OF FUNCTION F (1)` at `--std 2014`. Expected: compiles (SR20's exemption). Fix shape: the probe
classifies a function object by the function's declared RETURNING description (no binding), the same fact the
committing arm reads.

## Landed - 2026-10-07 (wave 1034 group D)

Re-probed on the wave-1034 build (`CALL "P" USING BAL OF FUNCTION F (7)`): refused COBOLNET1677 (the argument bound BY REFERENCE, a synthesized temporary) -- confirmed. The note's shape was the fix: the probe arm of `OoBinder.OoBindPropertyObject` (`DescribedByFunction`) answers the description the function's result temporary WOULD carry (ISO 8.4.3.2.4 GR1, both the function-prototype-name and the function-pointer-name forms) through the new `IntrinsicBinder.ReturningItemOf` -- one diagnostic-free reading of "what does this function-identifier return", shared with `ConditionBinder.IsBooleanUserFunction` (which now also covers a function-pointer) -- and `ReferenceResolver.ResolveObjectProperty` reads the roster off `PropertyReceiver.Described`, the same `RosterOf` the committing arm runs. Every consumer of `IsObjectPropertyReference` (CALL and INVOKE SR20 omission via `MeetsByReferenceRules`, `ScreenSection`, a user function's argument manner `UdfBinder.IsReferenceIdentifier`) now agrees. Goldens: `2023/pb2073_property_of_function_by_content_omitted` (CALL, INVOKE, function argument, function-pointer), negative `pb2073-property-of-function-not-object` (COBOLNET2918). Edition note: the construct compiles at 2014 too; the golden sits at 2023 beside `pb238_call_sr20_object_property`, the rule's own golden.
