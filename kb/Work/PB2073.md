# PB2073 — OPEN — the probe cannot see a function-identifier property object

## Mechanism

`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/OoBinder.PropertyObject.cs#OoBindPropertyObject`, line 53:
`if (probe) return po.objectView() is { } pv ? DescribedByView(pv) : null;` — a probe must not bind a function (a side
effect), so a `functionCall()` object answers null, and `ReferenceResolver.IsObjectPropertyReference` (the ONE test,
PB238 DEFECT 4) reports "not a property" for `BAL OF FUNCTION F (1)`.

## Consequence

§14.9.4.3 SR20 (cite.py OK): "BY CONTENT shall not be omitted when identifier-4 is an identifier that is permitted as a
receiving operand, except that BY CONTENT may be omitted when identifier-4 is an object property." — so
`CALL "P" USING BAL OF FUNCTION F (1)` (no BY CONTENT) should be accepted and is expected to be refused.

## Repro to write

A class with an object property BAL and a user-defined function F returning an object reference to it; a client
`CALL "P" USING BAL OF FUNCTION F (1)` at `--std 2014`. Expected: compiles (SR20's exemption). Fix shape: the probe
classifies a function object by the function's declared RETURNING description (no binding), the same fact the
committing arm reads.
