# PB4492 - two arms of one rule have no witness

**Gap.** `OoConformance.cs` ~80 (D-RP1) states that the property accessor pair (ISO 8.4.3.9.3 SR7) and the interface-to-interface
pair also compare a restricted pointer by the prototype it names, as the override and IMPLEMENTS arms do (PB4442). Only those
two have refusals (`conformance-suite/cases/9.3.8.2.3-Conformance-between-interfaces/pb4442-override-pointer-two-prototypes`,
`pb4442-override-returning-pointer-two-prototypes`, `pb4442-implements-pointer-two-prototypes`). The branch reviewer's probe of a
`GET PROPERTY ... RETURNING TO Q1` / `SET PROPERTY ... USING TO Q2` pair drew COBOL2727 as designed, so this is a missing
witness, not a wrong answer: the arm can regress with the gate green.

**Fix.** One refusal golden per arm, at 2023 (and the editions where the construct exists), expected value from the cited rule
(`cite.py --check 8.4.3.9.3 ...` and `9.3.8.2.3`, run when the golden is written), plus a positive twin where both accessors name
the same prototype through two type names. Land beside PB4491 if its adjudication changes the relation.

**Sites:** `src/WiseOwl.Cobol.Compiler/Oo/OoConformance.cs` (`OoConformance.SignatureDifference`), `conformance-suite/cases/9.3.8.2.3-Conformance-between-interfaces/` (the new goldens beside `pb4442-override-pointer-two-prototypes.cob`).
