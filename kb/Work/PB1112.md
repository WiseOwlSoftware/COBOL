## Measured (adjudicator / refuter evidence, verbatim)
### [elementary-items] The ACTIVE-CLASS formal parameter is screened as a plain description (BY REFERENCE: SameDescriptionAs identity; BY CONTENT: SET SR14 with the formal as receiver) and the INVOKE receiver is never consulted, so §14.8.2.3.2 rule 4 / §14.8.2.3.3's two ACTIVE-CLASS alternatives are both mis-decided: alternative b)/2) (an object-class-name ONLY argument, invoked through that class or a ONLY reference) is refused, and alternative a)/1)'s invocation-target condition (SELF, SUPER or an ACTIVE-CLASS reference) is never checked.
- **Rows:** GR-14.8.2.3.2-4, GR-14.8.2.3.3-1, GR-14.8.2.3.3-2 — harm `rejects-legal-source`
- **Repro:** Class C1, method M: LINKAGE `01 LK USAGE OBJECT REFERENCE ACTIVE-CLASS.` PROCEDURE DIVISION USING LK. Program: `01 X USAGE OBJECT REFERENCE C1 ONLY.` INVOKE C1 "NEW" RETURNING X. INVOKE X "M" USING BY REFERENCE X (and BY CONTENT X) -> COBOLNET0828 (BY REFERENCE: 'object-reference description mismatch'; BY CONTENT: '... does not conform to a receiver described with the ACTIVE-CLASS phrase (SR14)'). Converse: in C1 method N, LOCAL-STORAGE `01 Y USAGE OBJECT REFERENCE ACTIVE-CLASS. 01 O2 USAGE OBJECT REFERENCE C1.` SET Y TO SELF. SET O2 TO SELF. INVOKE O2 "M" USING BY REFERENCE Y (or BY CONTENT Y) compiles and prints IN-M.
- **Expected (spec):** §14.8.2.3.2 4) b): the argument may be "an object reference described with an object-class-name and the ONLY phrase, where the presence or absence of the FACTORY phrase is the same as in the formal parameter, and the method to be activated shall be invoked with that object-class-name or with an object reference described with that object-class-name and the ONLY phrase" -> INVOKE X "M" USING X is legal both BY REFERENCE and (§14.8.2.3.3 2)) BY CONTENT. §14.8.2.3.2 4) a) / §14.8.2.3.3 1) require the method to be invoked with SELF, SUPER or an ACTIVE-CLASS reference when the argument is ACTIVE-CLASS -> INVOKE O2 "M" USING Y shall be diagnosed (O2 is described C1 without ONLY, so neither alternative holds).
- **Observed:** Measured with the pinned cobol.exe: probe/elementary-items/ac_ref_legal and ac_con_legal (pre-edit forms) refused the legal X pairing with COBOLNET0828; ac_ref_bad4a and ac_con_bad4a compiled and ran the illegal O2 pairing (IN-M). OoConformance.DescriptionMismatch's ObjectReference arm and ContentMismatch's ObjectReference arm take only (formal, argument) — the activation's receiver is not a parameter of either, so neither alternative's invocation clause is expressible there.
- **Code site:** src/Cobol.Net.Compiler/Oo/OoConformance.cs#DescriptionMismatch (ObjectReference arm); src/Cobol.Net.Compiler/Oo/OoConformance.cs#ContentMismatch (ObjectReference arm); src/Cobol.Net.Compiler/Binding/Procedure/Verbs/OoBinder.cs#OoBindInvocationArg (the only caller that holds the receiver)

### [elementary-items] The §14.8.2.3.2 rule-2 identical-description comparator omits two clauses of the rule's own list — ALIGN (the ALIGNED clause) and DYNAMIC LENGTH (including its LIMIT phrase) — so a BY REFERENCE argument differing only in those clauses is admitted.
- **Rows:** GR-14.8.2.3.2-L2.2 — harm `under-rejects`
- **Repro:** Outer program `01 A PIC 1(4) USAGE BIT ALIGNED.` CALL "S" AS NESTED USING BY REFERENCE A; contained S LINKAGE `01 L PIC 1(4) USAGE BIT.` -> compiles, runs. Same with A `PIC X DYNAMIC LENGTH` vs L `PIC X`, the reverse, and `PIC X DYNAMIC LENGTH LIMIT 10` vs `LIMIT 20` -> all compile and run.
- **Expected (spec):** §14.8.2.3.2 2): "the definition of the formal parameter and the definition of the argument shall have the same ALIGN, BLANK WHEN ZERO, DYNAMIC LENGTH, JUSTIFIED, PICTURE, SIGN, and USAGE clauses" — each pairing is non-conforming and shall be diagnosed at compile time (§14.8.1 NOTE 1: checked at compile time for the Program format of the CALL statement and INVOKE on a typed reference).
- **Observed:** Probes n_align, n_dyn3, n_dyn4, n_dyn6 (pinned cobol.exe) all printed IN-S / DONE. DescriptionMismatch's Boolean arm compares Justified, BlankWhenZero, Usage, SignKind, EditMask, Locale, Length and never Aligned; the Alphanumeric/National arms compare no dynamic-length fact.
- **Code site:** src/Cobol.Net.Compiler/Oo/OoConformance.cs#DescriptionMismatch (Alphanumeric, National/Boolean/NumericEdited arms)

### [elementary-items] PICTURE identity in the rule-2 comparator is the raw character-string (EditMask) compared out of context, so §14.8.2.3.2 rule 2's exceptions a) (currency symbols match iff the currency STRINGS are the same) and b) (period/comma symbols match iff DECIMAL-POINT IS COMMA is in effect for both runtime elements or neither) are never applied.
- **Rows:** GR-14.8.2.3.2-L2.2 — harm `under-rejects`
- **Repro:** Program SPECIAL-NAMES `CURRENCY SIGN IS "#" WITH PICTURE SYMBOL "$"`, `01 A PIC $$9.99`, INVOKE O "M" USING BY REFERENCE A; class method M LINKAGE `01 L PIC $$9.99` (default currency string "$") -> compiles, prints IN-M [ #0.00]. Program `DECIMAL-POINT IS COMMA`, `01 A PIC ZZ9,99`, method formal `01 L PIC ZZ9,99` in a class without the clause -> compiles, runs.
- **Expected (spec):** §14.8.2.3.2 2) a) "Currency symbols match if and only if the corresponding currency strings are the same" and b) "Comma picture symbols match if and only if the DECIMAL-POINT IS COMMA clause is in effect for both the activating and the activated runtime elements or for neither of them" — both pairings are non-conforming and shall be diagnosed.
- **Observed:** Probes d_cur2 and d_dpc1 (pinned cobol.exe) accepted and ran. d_cur1 ("EUR" vs "$") was refused only because the multi-character currency string changed the item LENGTH — the right verdict for the wrong reason. The comparator's EditMask compare has no access to either side's SPECIAL-NAMES context.
- **Code site:** src/Cobol.Net.Compiler/Oo/OoConformance.cs#DescriptionMismatch (EditMask compares in the Alphanumeric and NumericEdited arms)

### [elementary-items] A bit group or national group argument/formal is routed into the GROUP arm of the rule-2 comparator ("a group argument requires a group or alphanumeric formal"), although §14.8.2.1's NOTE treats both as elementary items and §14.8.2.3.2's 'Additionally' b)/c) make them match an elementary bit / national item of the same position count.
- **Rows:** GR-14.8.2.3.2-L2.2 — harm `rejects-legal-source`
- **Repro:** Outer program `01 A GROUP-USAGE NATIONAL. 05 N1 PIC N(2).` CALL "S" AS NESTED USING BY REFERENCE A; contained S `01 L PIC N(2).` -> COBOLNET1688 'a group argument requires a group or alphanumeric formal'. Same with `01 A GROUP-USAGE BIT. 05 B1 PIC 1(4) USAGE BIT.` against `01 L PIC 1(4) USAGE BIT.`
- **Expected (spec):** §14.8.2.3.2 Additionally b) "A bit group item matches an elementary bit data item described with the same number of boolean positions" and c) "A national group item matches an elementary data item of usage national described with the same number of national character positions" -> both CALLs compile and pass the argument by reference.
- **Observed:** Probes n_ngrp and n_bgrp (pinned cobol.exe) refused with COBOLNET1688. DescriptionMismatch tests `arg.IsGroup` / `formal.IsGroup` before any category, and requires PicCategory.Alphanumeric on the other side.
- **Code site:** src/Cobol.Net.Compiler/Oo/OoConformance.cs#DescriptionMismatch (formal.IsGroup and arg.IsGroup arms)

### [parameters] The 14.8.2.2 rule-1 CATEGORY screen in OoConformance.DescriptionMismatch reads PicCategory.Alphanumeric and DataItem.IsGroup, both of which are wider than the rule's sets: PicCategory.Alphanumeric also carries ALPHABETIC (PIC A) and ALPHANUMERIC-EDITED (EditMask not null) items, and IsGroup is true for a GROUP-USAGE NATIONAL or BIT group, which 14.8.2.1's NOTE treats as an ELEMENTARY national/boolean item. A BY REFERENCE CALL (Format 2, AS NESTED or prototype) or INVOKE pairing an alphanumeric group with any of these therefore binds with no diagnostic, and a national-group pairing then reinter
- **Rows:** SR-14.8.2.2-1 — harm `under-rejects`
- **Repro:** gen.py cases pe/pf/pg/pg2/pk/pl under out/probe/parameters. E.g. pe: WORKING-STORAGE `01 ARG PIC A(10) VALUE "ABCDEFGHIJ".`; `CALL "PES" AS NESTED USING BY REFERENCE ARG`; nested PES LINKAGE `01 FRM. 05 F1 PIC X(5).` PROCEDURE DIVISION USING FRM, DISPLAY "F=" FRM. Pinned cobol.exe --std 2023: compiles and prints F=ABCDE. pg: `01 ARG GROUP-USAGE NATIONAL. 05 N1 PIC N(4) VALUE N"ABCD".` into `01 FRM. 05 F1 PIC X(4).` compiles, prints F= A B.
- **Expected (spec):** COBOLNET1688 at bind for every case: 14.8.2.2 rule 1 requires the side opposite an alphanumeric group to be 'an alphanumeric group item or an elementary item of category alphanumeric'; 8.5.2.2 and 8.5.2.4 make alphabetic and alphanumeric-edited separate categories; 14.8.2.1 NOTE makes a national/bit group an elementary national/boolean item; 14.9.4.3 SR25 makes the conformance rules syntax rules of Format 2.
- **Observed:** pe F=ABCDE, pf F=ABC D, pk/pl accepted, pg F= A B (UTF-16BE bytes), pg2 F=U+4142 U+4344 - all compile with rc=0. The conforming cases (pd PIC 9 argument, pj PIC 9 formal) are rejected correctly, so only the over-wide predicates leak.
- **Code site:** src/Cobol.Net.Compiler/Oo/OoConformance.cs#DescriptionMismatch (group-formal arm `arg.IsGroup || arg.Pic?.Category is PicCategory.Alphanumeric`; group-argument arm `f.Category is not PicCategory.Alphanumeric`); callers CallBinder.cs ~618 and OoBinder.cs ~790
