# PB1681 — OPEN

Filed 2026-09-28 by the train-69 lander from the wave-69 X finisher report (`w69x-PB1355-report.md`, "New
defects" 2). Process-only: a regression net mis-scores one class of case.

**What happens.** GnuCOBOL 3.2's `syn_copy.at` group "COPY: relative copybooks" is `AT_XFAIL_IF([true])` — cobc
itself fails it ("the source for the COPY statement is currently completely ignored"). The differential reads only
the group's `expects_failure` (the AT_CHECK status), so when WiseOwl COBOL behaves as cobc really does (refuses
the relative search, DOC-A.1-40) the case is scored WE_REJECT_THEY_ACCEPT: a flip that looks like a regression
(w69x `diff-full2.log`: syn_copy:125 AGREE_ACCEPT → WE_REJECT).

**Code site.** `scripts/gnucobol_differential.py#run_case` (`they_ok = not chk['expects_failure']`); the group's
XFAIL flag must come from `scripts/gnucobol_extract.py` (AT_XFAIL_IF parsing).

**What the fixer owes.** Extract AT_XFAIL_IF per group and score an XFAIL group as "cobc's expectation is
inverted" (or a separate XFAIL verdict class), then re-baseline only the XFAIL rows; a unit test of the scorer on a
synthetic XFAIL group.
