# PB2986 — the --nist placeholder substitution is an unmapped column-changing stage

Found 2026-10-10 by the train 1055 review of cluster B (PB1688 + PB1671 + PB1801: diagnostics name the SOURCE
column through the origin map). Filed rather than fixed in the train: the fix makes the NIST stage a mapped stage
(about 25 lines in the pipeline every NIST program runs), past the night-stop landing's review bar.

**Repro:** `E:\COBOL-coord\scratch\t1055\review-B\a15.cob` compiled with `--nist NC101A`: the line
`000700     DISPLAY XXXXX058 X ) .` reports its error at `(7,32)`; the `)` is in column 31. `XXXXX058` becomes
`"CONTROL"` (9 characters for 8), so every token to its right on the line is reported one column late (and
`XXXXX055`'s test-name substitution shifts by the name's length).

**Site:** `src/Cobol.Net.Frontend/Pipeline/Frontend.cs` about line 271: `text = NistPreprocessor.Process(text, nist)`
runs after `var lineMap = new SourceLineMap(mapped.Lines)`, and the only check is the line count.
`docs/rearchitecture/DESIGN-cc-in-copy.md` §3.5 names this stage as the one exception to "every stage that changes
the columns is MAPPED".

**Fix shape:** run the substitutions through `OriginWriter` (append the slice up to each match, then the replacement
at `mapped.PointAt(matchStart)`), return a `MappedText`, build `lineMap` after it, delete the exception from §3.5, and
pin the column with a `--nist` case in `DiagnosticPositionTests`.

**Landed 2026-10-11 (wave 1059 E).** Re-probed on a fresh build first: `a15.cob` under `--nist NC101A` reported `(7,32)`; it now reports `(7,31)`, the column of the `)`.

The root: `NistPreprocessor.Process` was a string-to-string stage run after `SourceLineMap` was built, so its length-changing substitutions (`XXXXX058` 8 -> 9, `XXXXX083` 8 -> 6, `XXXXX069` deleted, `XXXXP001` -> `"TF001"`) shifted every later column on the line while the map still described the old text. It is now `Process(MappedText, testName) -> MappedText`, every substitution goes through ONE loop (`RewriteMatches`, on `OriginWriter`), the SELECT-entry arm maps the entry's slice and splices it back (`RewriteRegions`), and `Frontend.Preprocess` builds the line map from the stage's output. The line-count throw is gone: the `MappedText` constructor asserts it for every mapped stage. Sibling sweep: the six directive stages blank whole directive lines and `DebuggingLineRewriter.WithCarrierBlanked` replaces one character by a space, so no other stage changes the columns of a line that keeps text. `DESIGN-cc-in-copy.md` §3.5 loses its exception (and its corrupted `Split` sample). Pinned by `DiagnosticPositionTests.Nist_PlaceholderSubstitution_KeepsTheColumnsToItsRight` (longer, shorter, SELECT-entry, deleted card, COPY library text).
