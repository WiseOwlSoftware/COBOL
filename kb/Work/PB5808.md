# PB5808 - a USE BEFORE REPORTING procedure may change a control data item through a REDEFINES of it (every edition)

**What is wrong.** A store into a REDEFINES alias of a control data item (or of the record holding it) inside a USE BEFORE REPORTING procedure is not refused, at every edition. `MOVE "22" TO WS-RED` (WS-RED REDEFINES the record holding control item WS-GRP) alters WS-GRP's value (the run prints `GRP=2`; the control item changes from 1 to 2), which `§1985:XIII.4.9.3 SR4` forbids. A direct `MOVE 2 TO WS-GRP` is refused COBOL2378, so the store relation walks only the parent chain, not storage aliases. Ruling: UPHELD (b), harm under_rejects. A leftover the landed kb/Work PB363 recorded. The checker's confidence: high.

**Sites:**
- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/ReportWriterBinder.cs#CheckControlDataStores` (the checker's reading: `SameStorageLine` walks the `Parent` chain only; the reader's site, which the checker did not re-read)
- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/ReportWriterBinder.cs#SameStorageLine` (the fix: adds the StorageExtent overlap); `tests/WiseOwl.Cobol.Tests.Unit/DeclarativesStructuralRulesTests.cs` (the witnesses)

       FILE SECTION.
