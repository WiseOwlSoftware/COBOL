# PB3597 - the record-struct lane cannot address the implicit filler gaps of a bit table or the tail of a class run

Two leads of the PB3564 finisher report share one root: in the RECORD-STRUCT lane the implicit filler is not yet an item INITIALIZE can
reach. PB3564 made the class lanes (EXTERNAL, BASED, REDEFINES views) reset it through `BitLayout.WindowFillersOf`; the record-struct
lane stores the pad as ONE hidden string and has no per-gap place.

## Lead 1 (PB3564 R2-2, low): a refusal of legal source

`INITIALIZE G WITH FILLER REPLACING BOOLEAN DATA BY B"1"` over the pad between the occurrences of an ALIGNED bit table in a
record-struct group aborts by name in `InitializeBinder.ExpandImplicitFillers`. The pad is one `__bf<k>` string holding n-1 gaps (a
string of '0'/'1' characters, not the packed backing the window coding reads) and no place addresses a single gap, so the REPLACING
sender cannot be applied to each gap as its own elementary bit item (GR 14.9.20.4 5) a) 2, each implicit filler is an elementary
item). Repro (G = `T PIC 1(3) USAGE BIT ALIGNED OCCURS 2` + `X PIC X`; the second INITIALIZE aborts):
`E:\Temp\claude\E--COBOL\8bd1c3d3-6c48-4db9-ada1-5e4edea40828\scratchpad\w1157\review-i-r2\repl.cob`.

## Lead 2 (low): silently wrong data

A record-struct group that holds the canonical of a Tier-B class (the BRD11 shape: `M2` canonical, `M2R REDEFINES M2`) has a run whose
tail is neither stored (`BitLayout.FillerPositions` marks the run `InClass`, so `FillersOf` omits it) nor windowed (the owner is not
itself in the class, so `WindowFillersOf` does not name it). `INITIALIZE G WITH FILLER` leaves the tail, where the rule resets every
implicit filler (8.5.1.6.3 "implicitly described as a filler elementary bit data item").

## Fix shape (for the implementer)

Make each gap of the pad, and the tail of a class-canonical run, an addressable filler item in the record-struct lane as the class lanes
already do (one enumeration, `FillerPositions`, behind the stored list and the window list), so the next filler shape lands in both.
Sweep the sibling readers of the pad (`GroupImageCodec` pad lines, `GroupValueSlicer`, `PhysicalModel`). Goldens: the REPLACING BOOLEAN
arm and the canonical/REDEFINES tail, 2002/2014/2023. Run each citation through `cite.py --check` first.

**Sites:** src/Cobol.Net.Compiler/Binding/Procedure/Verbs/InitializeBinder.cs, src/Cobol.Net.Compiler/Binding/Model/BitLayout.cs, src/Cobol.Net.Compiler/CodeGen/DataDivision/GroupImageCodec.cs

Site lines are on PB3564's branch `worktree-wf_37d4041f-6f7-47` (87a2182c2; they reach main when PB3564 lands): `InitializeBinder.cs:452`
(`ExpandImplicitFillers`), `BitLayout.cs:243` (`FillersOf`), `:272` (`FillerPositions`), `:321` (`WindowFillersOf`).

## Landed (2026-10-24, w20261024 group B)

**Re-probe.** Both leads reproduced on a fresh build. Lead 1: the repro (`INITIALIZE G WITH FILLER REPLACING BOOLEAN DATA BY B"1"` over `T PIC 1(3) USAGE BIT ALIGNED OCCURS 2` + `X PIC X`) aborted at run time by name. Lead 2: `M2 PIC 1(3)` redefined by `M2R PIC 1(2)` with `MOVE "AB" TO G` read back `@` (0x40) where the rule requires `A`, so the tail was not stored at all (the note called it an unreset tail; the move already lost it).

**Root (one).** Which filler position is stored in a field and which is a window of a class's backing was decided PER POSITION (`FillerPosition.InClass`, set when any run member was in a Tier-B class), when it is the OWNER's fact: an owner a Tier-B class holds has every position as bytes of the backing, any other owner has a field for every position. The per-position flag marked the tail of a run in an owner OUTSIDE the class (the BRD11 shape: the canonical is a run member of an ordinary group) as the class's, so it was neither stored nor windowed. `InClass` is dissolved into `BitLayout.InTierBClass(owner)` (`FillersOf` is empty for a class's owner, `WindowFillersOf` lists every position of it), and `PhysicalModel` declares the tail field after a class canonical that leads a run too (`FillerFieldsOf`).

**Lead 1's shape.** A table pad is n - 1 elementary filler items (8.5.1.6.3), so both lanes receive them in ONE loop over the gaps. The record-struct lane's pad is one stored string of every gap, so a gap is its reference-modified place (`InitializeBinder.PadGapPlace`: start `(v - 1) * gapBits + 1`, length `gapBits`); the class lane's gap is the first gap's item under the table's own occurrence displacement (`WindowFiller`, `cur.Child(table).Indexed(v).Child(gap)`). The class lane had been unrolled to one statement per gap (PB3564 R2-1): `E EXTERNAL` with `T ... ALIGNED OCCURS 2000` generated 2095 lines (389 KB) of C#, now 100.

**Tests.** Goldens `14.9.20-INITIALIZE/pb3597_initialize_with_filler_replacing_boolean_in_a_table_pad` (3 occurrences: two gaps, so a sender smeared over the stored pad fails; the explicit PIC 1(3) / FILLER PIC 1(5) record is the control) and `pb3597_bit_run_tail_beside_a_redefines_canonical` (canonical continuing, leading and followed by a bit item in its run: move, bare INITIALIZE, WITH FILLER), the negative `pb3597-initialize-with-filler-replacing-boolean-below-2002` (COBOLNET0900 at 85), and `BitRunImageDriftTests.AliasedGroup_HoldsTheFillerAGroupMoveWrote` BFL11-BFL13 (record-struct twin = aliased twin = the round trip).
