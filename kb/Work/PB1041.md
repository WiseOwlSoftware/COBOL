# PB1041 — LANDED (wave 59, implementer w59d)

## Measured
```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. B14SN.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 X PIC 9(31) VALUE 1000000000000000000000000000000.
       01 R PIC S9V9(8).
       PROCEDURE DIVISION.
           COMPUTE R = FUNCTION SIN(X)
           DISPLAY "SIN=" R
           STOP RUN.
```

prints **`SIN=00093314F`** (+0.00933146). The exact value, computed with 120-digit decimal reduction mod 2π:
`sin(10^30) = -0.0901169019…`; `sin(1000000000000000019884624838656) = +0.0093314689…` — the compiler answered the
second.
```cobol
       >>TURN EC-ALL CHECKING ON
       IDENTIFICATION DIVISION.
       PROGRAM-ID. B15SB.

       WORKING-STORAGE SECTION.
       01 R PIC S9V9(8).

           COMPUTE R = FUNCTION SIN(1.0E200 * 1.0E200)
           DISPLAY "SIN=" R " EX=" FUNCTION EXCEPTION-STATUS
           STOP RUN.
```

→ `abnormal run-unit termination: EC-ARGUMENT-FUNCTION (fatal): floating-point intrinsic argument out of domain (NaN
result)`: the SDIDI argument narrows to +Infinity and sin(inf) is NaN.

## The rules
`cite.py --check 15.82.4 "The returned value is the approximation of the sine of argument-1"` → `OK §15.82.4 1)`;
COS §15.20.4 1) and TAN §15.89.4 1) are the twins (`--find` located both). The argument is the exact value; an
approximation of the sine of a DIFFERENT number is not an approximation of this one.

## Code site
`IntrinsicRenderer.FloatBody` (`DomainArg` / `DblOf` → `CobolFloat.ScaledToDouble`) for the scaled Int128 carrier;
the Dec/SDIDI carrier narrows through `Dbl`. PB999's WholeRangeBodies fixed LOG/LOG10 on the wide carriers.

constant) before the binary64 kernel, on both the scaled-Int128 and the SDIDI carriers — extend WholeRangeBodies
with the periodic trio. ⚠ Train 57 dropped PB999's first attempt for raising semgrep `cobolnet-no-biginteger`

## Landed

**Re-probe first (own Debug build of `df452130e`).** PB999 had already landed the note's two repros: `SIN(X)` with
`X = 10**30` printed −0.09011690 and `SIN(1.0E200 * 1.0E200)` −0.99853823 with no EC. But PB999's `PeriodicArg`
reduced only from |x| ≥ 2π and only modulo 2π, so the note's OWN rules still failed below 2π, where the function is
ill-conditioned at every multiple of π/2: `TAN(1.570796326794896619231321691639)` = 1.63·10^16 (value 1.33·10^30),
`COS` of it 6.1·10^−17 (value 7.5·10^−31), `SIN(3.14159265358979323)` (a COBOL-85 18-digit item) 1.22·10^−16 (value
8.46·10^−18). The sibling sweep (variant analysis over every Float catalog row, ranked by condition number
|x·f′/f|) found the SAME mechanism, a narrowed exact argument amplified by the body, in LOG / LOG10 at 1
(`LOG(1.00000000000000000000000001)` = 0), ACOS / ASIN at ±1 (`ACOS(0.99999999999999999999999999)` = 0, value
1.414·10^−13) and EXP / EXP10 (condition number |x|: `EXP(700.1234…)` 150 ulps off) — PB999's membership rationale
("the domain is inside binary64", "the substitute's result IS the approximation") measured range, not conditioning.

**Fix.** One mechanism, one set: `IntrinsicRenderer.WholeRangeBodies` now admits every exact operand for SIN, COS,
TAN, LOG, LOG10, ACOS, ASIN, EXP, EXP10 (`ExactIntake.EveryExact`; SQRT stays `Sdidi` — condition number ½), and each
runtime `CobolDec` overload forms the well-conditioned quantity on the exact carrier before narrowing:
`CobolIntrinsics.ReduceQuarterTurns` (new, `CobolIntrinsics.TwoPi.cs`) replaces `ReduceTwoPi` — a decimal
Payne–Hanek reduction to quadrant + residue, Sig × 162 places of 1/(2π) as nine base-10^18 limbs on Int128, error
< 2·10^−124 turns, the residue handed to the body as a double-double (the digit string grew 6200 → 6320 places;
`InverseTwoPiDigitsDriftTests` re-derives it); LOG / LOG10 take the exact x − 1 through Kahan's log1p within ½ of 1;
ACOS / ASIN the exact 1 − |x| through the half-angle identity past ½; EXP / EXP10 split x into its integer part and
EXACT fraction. No BigInteger in the runtime (semgrep counts unchanged). Design: `COBOLNET_INTRINSICS_DESIGN.md`
"An exact-intake float body…".
