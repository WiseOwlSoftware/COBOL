# PB645 — OPEN — a cell that names a place instead of a rule

Found 2026-09-05 by the `PB292` implementer (report §"New defects" (c)). `docs/CONFORMANCE.md` §2 is the normative
§4.2.6 user documentation for the Annex A.3 processor-dependent elements; every row's § cell is supposed to be the
clause the element lives in, so a reader can go from the row to the standard. Row 25 (`| 25 | STANDARD-COMPARE /
EC-ORDER-NOT-SUPPORTED / ORDER TABLE (ISO/IEC 14651) | SPECIAL-NAMES | **Claimed** | …`, main `:91`) says
`SPECIAL-NAMES` — where the ORDER TABLE clause is written, not a clause number.

## Fix

Replace the cell with `12.3.7 / 15.85` (the SPECIAL-NAMES paragraph's ORDER TABLE clause, and the STANDARD-COMPARE
function; `cite.py --check` each against a sentence from its `.1 General` subclause first, the way PB292 did for the
eight placeholders), then tighten `AnnexA3RegisterDriftTests`' placeholder ban from "no `N.x`" to "every § cell is
clause-shaped (`\d+(\.\d+)*` separated by ` / `)", which is free once this row is fixed and closes the class rather
than the instance ([[PB616]], [[PB591]], [[PB597]] are the same family in code and notes).
