**Rule violated:** A compiler or runtime crash on a LEGAL program. The program is legal: ORDER TABLE literal content is the implementor's (12.3.7.4 GR17, which the binder itself cites), and DataBinder's own design says an unresolvable name is a WARNING (COBOLNET1662) with a defined run-time outcome (EC-ORDER-NOT-SUPPORTED, 15.85.4 r2), never a refusal, let alone a crash. Warmup's own contract says a default locale that cannot be resolved is a Warning, never an exception.

**Scenario:** Measured on the pin (8be230068). (a) A legal program with SPECIAL-NAMES ORDER TABLE HUORD IS "hu" compiles clean, but with COBOL_CLDR_DIR naming a directory whose hu.xml contains [suppressContractions [^a]] the compiler dies with an unhandled FormatException ('negated UnicodeSets are not supported in collation data') thrown by CldrParser through CollationEngine.TryGetOrderingTable, which the binder's ORDER TABLE check calls expecting a bool; the designed outcome for a name it cannot resolve is the COBOLNET1662 warning. (b) A program that never collates prints OK, but with COBOL_COLLATION_DIR holding de.tailor '@version 16.0.0' (a site tailoring left at the previous UCA after a runtime upgrade), COBOL_USER_LOCALE=de and COBOL_COLLATION_WARMUP=1 it dies before its first statement with InvalidOperationException from CollationTable.WithTailoring, because CollationRuntime.Warmup catches only CultureNotFoundException, FormatException, IOException and InvalidDataException, while documenting that an unresolvable default locale is a Warning. Initialize sets s_initialized before calling Warmup, so only the FIRST run unit of a process dies and later ones run. The resolution path also throws NotSupportedException (Line.Number overflow, the circular-import throw in Expand), both outside Builder.Run's per-rule catch, so neither caller's filter is complete.

**Reproduction:** (a) COMPILER crash: ot1.cob (SPECIAL-NAMES. ORDER TABLE HUORD IS "hu". ... DISPLAY "OK") compiles clean with the pin cobol.exe; with COBOL_CLDR_DIR=<probe>/badhu holding hu.xml whose standard collation is [suppressContractions [^a]], the same compile exits 1 with 'Unhandled exception: System.FormatException: negated UnicodeSets are not supported in collation data' from CldrParser.ParseSetInto, through CollationEngine.TryGetOrderingTable (called by the ORDER TABLE check in DataBinder.Switches.cs). (b) RUN-TIME crash at start-up: the compiled ot1.dll prints OK normally; with COBOL_COLLATION_DIR=<probe>/tail holding de.tailor = '@version 16.0.0', COBOL_USER_LOCALE=de and COBOL_COLLATION_WARMUP=1 it dies before the first statement: 'Unhandled exception. System.InvalidOperationException: tailoring 'de' was written for UCA 16.0.0 but the base table is UCA 17.0.0' (CollationTable.WithTailoring <- CollationEngine.Resolve <- LocaleManager.GetLocale <- CollationRuntime.Warmup), exit 127. Without COBOL_COLLATION_WARMUP the same program prints OK (it never collates).
