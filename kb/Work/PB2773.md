**Rule violated:** A compiler or runtime crash on a LEGAL program. The program is legal: ORDER TABLE literal content is the implementor's (12.3.7.4 GR17, which the binder itself cites), and DataBinder's own design says an unresolvable name is a WARNING (COBOL1662) with a defined run-time outcome (EC-ORDER-NOT-SUPPORTED, 15.85.4 r2), never a refusal, let alone a crash. Warmup's own contract says a default locale that cannot be resolved is a Warning, never an exception.

**Scenario:** Measured on the pin (8be230068). (a) A legal program with SPECIAL-NAMES ORDER TABLE HUORD IS "hu" compiles clean, but with COBOL_CLDR_DIR naming a directory whose hu.xml contains [suppressContractions [^a]] the compiler dies with an unhandled FormatException ('negated UnicodeSets are not supported in collation data') thrown by CldrParser through CollationEngine.TryGetOrderingTable, which the binder's ORDER TABLE check calls expecting a bool; the designed outcome for a name it cannot resolve is the COBOL1662 warning. (b) A program that never collates prints OK, but with COBOL_COLLATION_DIR holding de.tailor '@version 16.0.0' (a site tailoring left at the previous UCA after a runtime upgrade), COBOL_USER_LOCALE=de and COBOL_COLLATION_WARMUP=1 it dies before its first statement with InvalidOperationException from CollationTable.WithTailoring, because CollationRuntime.Warmup catches only CultureNotFoundException, FormatException, IOException and InvalidDataException, while documenting that an unresolvable default locale is a Warning. Initialize sets s_initialized before calling Warmup, so only the FIRST run unit of a process dies and later ones run. The resolution path also throws NotSupportedException (Line.Number overflow, the circular-import throw in Expand), both outside Builder.Run's per-rule catch, so neither caller's filter is complete.

## Landed (w1051d, 2026-10-10)

Re-probed: main's `cobol.exe` (built 2026-10-08, no Collation file changed since) on `ot1.cob` with
`COBOL_CLDR_DIR=<probe>/badhu` died `Unhandled exception: System.FormatException: negated UnicodeSets are not
supported in collation data` (CldrParser.ParseSetInto), as filed. After the fix the same compile exits 0 with
`warning COBOL1662: ORDER TABLE HUORD IS "hu": the site collation data for 'hu' cannot be used (<probe>\badhu\hu.xml:
negated UnicodeSets are not supported in collation data) …`, and `ot1.dll` under `COBOL_COLLATION_DIR=<probe>/tail`,
`COBOL_USER_LOCALE=de`, `COBOL_COLLATION_WARMUP=1` prints `OK`, exit 0.

**Mechanism.** One typed failure, `LocaleCollationException` (`src/WiseOwl.Cobol.Runtime/Collation/LocaleCollationException.cs`:
data source, line where it has one, reason), raised at each boundary where collation data is read or applied:
`CldrLocaleLoader.ReadFile` (the parser's FormatException, XML/JSON reader errors, an unreadable file or directory;
the failure is cached beside the data so a broken file is read once), `TailoringRules.Parse`/`Load`/`FromDirectory`,
`CollationTable.WithTailoring` (stale `@version`, was InvalidOperationException) and `CldrTailoringBuilder` numbering
(was NotSupportedException out of `Line.Number`). Rule-level problems stay rule-level: the circular `[import]` is now
listed in `Unsupported` and skipped (was a NotSupportedException outside Run's per-rule catch), and `[before n]` with
nothing before it is a NotSupportedException the per-rule catch lists (was InvalidOperationException, which escaped it).
The ONE catch is `CollationEngine.Resolve`: the resolution carries the failure as `ResolvedLocaleCollation.Failure`
over the root order, cached. Consumers: `TryGetOrderingTable` and `IsKnownLocale` answer false; the binder's ORDER
TABLE check warns COBOL1662 with the failure (no new code: the designed outcome); STANDARD-COMPARE's
EC-ORDER-NOT-SUPPORTED message carries it; `LocaleManager.GetLocale` throws it (`TryGetLocale` false); `Warmup` catches
exactly CultureNotFoundException and LocaleCollationException.

**Public surface.** Additive only (`PublicAPI.Unshipped.txt`): the exception type and `ResolvedLocaleCollation.Failure`
(an init property, not a positional parameter, so the shipped constructor and `Deconstruct` are unchanged and the
runtime major is not raised, RuntimeAbiPinDriftTests). `TryGetOrderingTable` keeps its shipped signature; its reason
is `ResolveLocale(name).Failure`.

- Trap: site-file tests run beside unserialized classes; use private-use language codes (qaa–qtz) for the files.
