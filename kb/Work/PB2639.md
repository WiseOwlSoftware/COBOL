**Rule it breaks:** ISO §13.18.40.5 rule 6 (the extended editing sign control symbols are floating insertion symbols and their repetitions are digit positions) and §14.7.5 case 3 (a size error only when the result is further from zero than the resultant item permits); sibling functions must agree (MaskCapacity's own doc: Mirrors Format's prologue exactly; FractionDigits' comment: it counts in both branches below, kb/Work PB491)

**Scenario:** (1) TryFormat (CobolEdit.cs:592) calls MaskCapacity(picture, currency, commaMode) without its edits argument, so for C-ITEM PIC LLLL9.99 EDITING L FOR NEGATIVE IS "DEBIT " (the Annex D.24 shape tests/conformance/2023/pb491_editing_variable_width.cob already declares) the four floating L positions are not counted: capacity 3 instead of 6. COMPUTE C-ITEM = 10 ON SIZE ERROR DISPLAY "SE" END-COMPUTE displays SE and leaves C-ITEM unchanged, because the aligned 1000 >= 10^3; every result of 10 or more is a false size error (ArithmeticEmitter.StoreArith's checked edited arm reaches TryFormat with the rules in its config). (2) Render (CobolEdit.cs:249) and MaskScale (CobolEdit.cs:760, which takes an edits parameter and never forwards it) call FractionDigits without edits, so for a floating character-1 that SR29 lets run past the decimal point, e.g. PIC LLL.LL EDITING L FOR NEGATIVE IS "-", the mask scale is 0 instead of 2: MOVE 1.5 renders the digits of 1 at the fraction positions (   .01) instead of   1.50, and DeEdit (which re-derives the scale through MaskScale) reads the image back off by 10^2. The compiler's PicInfo scale and DataBinder fold go through the same MaskScale, so bind and run agree on the wrong scale; only AlgebraicRange (MaskCapacity with edits) has the right one.

## Landing

**Landed 2026-10-08 (wave 1042 H).** Re-probed on a fresh build before any edit: `C-ITEM PIC LLLL9.99 EDITING L FOR
NEGATIVE IS "DEBIT "` rejected `COMPUTE C-ITEM = 10 ON SIZE ERROR` (and 123.45, Annex D.24's own value), `G-ITEM PIC
LLL.LL EDITING L FOR NEGATIVE IS "-"` rendered `MOVE 1.5` as `   .01` and read back as 1.00 into `9V99`: both as the note
measured. Root cause and fix: the digit-position derivation was written in FIVE places (`Render`, `TryFormat`'s
`MaskCapacity`, `MaskScale`, `FractionDigits`, `DeEdit`), three of which dropped the `EditRule[]` that makes a FLOATING
character-1 a digit position (§13.18.40.5 rule 6). It is now ONE type, `CobolEdit.MaskFacts`
(`CobolEdit.MaskFacts.cs`): `Of(picture, edits, currency)` counts the symbols once, `IsDigitPosition` / `Capacity` /
`FractionDigits` answer every question, and `Render`, `DeEdit`, `MaskCapacity`, `MaskScale` and `TryFormat` read it.
`MaskCapacity` and `MaskScale` take `EditRule[]? edits` as a REQUIRED second argument, so no caller can drop it again
(five callers and two tests updated; no default, no overload). Pinned by `CobolEditMaskFactsTests` (geometry,
bound-versus-render agreement, de-edit scale, and a source scan that the fixed-versus-floating classification is
written only in `MaskFacts`) and the golden `2023/pb2639_floating_char1_digit_positions`.

**The "also found" lead (`Int128.Abs` per site).** `CobolNum.Magnitude(Int128) -> UInt128` is the one MinValue-safe
absolute value (a `UInt128` holds 2^127). Every unsafe site now reads it: `TryStore(Int128)` and `TryStore(CobolDec)`
(unsigned BinaryCapacity arm: `BinaryMagnitude`), `WrapBinary`, `InBinaryRange`, `PositionOf`, `RescaleStoreCap` (its hand
MinValue branch), `InPictureRange` (`CobolNum.Image.cs`), `CobolEdit.Format`/`TryFormat` and
`CobolLocaleEdit.Format`/`TryFormat`. The R2 repro `minv.cob` now stores 2^127 with no size error (it printed SIZE
ERROR and left U at 7); the `StoreOrRaise` lane raises `CobolSizeError`, not a raw `OverflowException`; an unsigned
8-byte receiver wraps -2^127 to 0 (it threw). Safe sites left as they are, named: `CobolNum.Store` / `TryStore` after the
`%= 10^Digits` / capacity test (|v| < 10^38), and the `CobolDec` paths (a 34-digit significand cannot be MinValue).
Pinned by `CobolNumMagnitudeTests` and the golden `2023/pb2639_binary_minvalue_unsigned_magnitude`.
