# PB899 — OPEN — a diagnostic that is correct in memory and wrong on the wire

Source: the `PB391-finisher` report, "New defects" item 3, **which SUPERSEDES the first PB391 implementer's
"the MOVE diagnostic names the sending operand as `.`" lead**. That lead was a misreading:
`ImplicitMovePhrase.WhereOf` renders `MOVE … TO {receiver}` with U+2026 deliberately, because an explicit
MOVE's sender is not named. What happens to it is best-fit encoding.

## The measurement — bytes, not characters

```
$ cobol.exe p13_proto.cob --std 2023 > diag2.txt 2>&1
$ od -c diag2.txt | tail -2
0000200   d       (   I   S   O     025   8   .   9   )  \r  \n
```

`(ISO §8.9)` — U+00A7 arrives as the single byte **0x15**, which is `§` in cp437 and a control character in
UTF-8 and in every Windows ANSI code page. The PB391 finisher captured the same shape for a MOVE
diagnostic: `MOVE . TO KX … (ISO \x15 14.9.25.3 SR8)`, with U+2026 best-fitted to `.`.

## The two arms

```
src/Cobol.Net.Runtime/Control/ProgramTable.cs:126-127
    if (Console.OutputEncoding.CodePage != 65001)
        try { Console.OutputEncoding = new System.Text.UTF8Encoding(false); } catch (System.IO.IOException) { }
```

A RUN program gets UTF-8. **The CLI's diagnostic path has no `Console.OutputEncoding` setup at all** — grep
`src/Cobol.Net.Cli/` for `OutputEncoding` returns nothing but the copied runtime assembly. One rule
("COBOL.NET's output is UTF-8"), two places it could be written, one of them written
(memory `two_arm_dispatch`).

## Why no gate sees it

The corpus runner matches `.err` files on a diagnostic CODE substring (`COBOLNET0901`), which is pure ASCII,
so a mangled `§` is invisible to every golden. A redirected or piped diagnostic is what a user and a CI log
actually read.

## The fix

Set the console encoding ONCE, at the CLI entry point, for both stdout and stderr, and delete the runtime's
copy or have it call the same helper — not a second `if`. Then add a golden that asserts the BYTES of one
diagnostic containing `§`, because a code-substring match will never catch this class again.
