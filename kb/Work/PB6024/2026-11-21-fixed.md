## 2026-11-21 — fixed: a 1985 report has no page width (wave 20262131 group y, branch train85c-rw)

Re-probed first at `--std 85`: a detail line with `COLUMN 990 PIC X(20)` was refused (COBOL2745, SR8 b) though the message itself
said the rule is not COBOL-85's. The cause was structural: `ReportModel.PageWidth` held 999 at every edition, so the three
column screens (§2023:13.18.14.3 SR6 COBOL2710, SR8 b, SR8 c) and the engine's line (`CobolReport`, `Place`, which also cut the
line at 999 and could raise EC-REPORT-PAGE-WIDTH) measured a 1985 report against a bound only COBOL-2002 introduces
(§2002:13.16.37.3 GR5, "If integer-2 is omitted, a value of 999 is assumed for the page width"). The 1985 text bounds no column:
its PAGE clause prints no width phrase (§1985:XIII.3.8.2, rendered page 599), its COLUMN NUMBER clause none
(§1985:XIII.3.11.3, §1985:XIII.3.11.4 GR2), and "The report writer logical record structure of the file associated with
file-name-1 is defined by the implementor" (§1985:XIII.3.2.4 GR2), so the line is bounded only by the record (Annex A.1 item
159). Fix: `DialectBehavior.ReportPageWidth` (2002; VCR row 7.90), read once where the RD is bound: `ReportModel.PageWidth` is
null at 85, the screens ask only a report that has a width, and the emitter passes `CobolReport.NoPageWidth`. 2002, 2014 and 2023
unchanged (the whole Conformance assembly passes). Witness `XIII.3.11@1985-COLUMN-NUMBER-CLAUSE/pb6024_column_past_999_accepted_85`
(the output file holds the 1009-column line); two 2023 cases that also refused at 85 only through the 2002 bound now name 2002+
(`pb1059-column-beyond-assumed-page-width`, and PB6025's `pb957-next-group-exceeds-page-limit`).
