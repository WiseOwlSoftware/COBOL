# PB5567 - two file control entries of one external indexed file that list the same alternate record keys in another order are refused (COBOL6847): FileEntryIdentity compares the ALTERNATE RECORD KEY clauses in written order

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/FileEntryIdentity.cs` (`FileEntryIdentity.Segments`: the ALT segment sorted, the COLL key position named by the key, not its index)

**Mechanism.** `ExternalFileConnectorRules.Check` compares the file control entries of one external file connector through `FileEntryIdentity.Segments`. Its ALT segment is `string.Join` over `FileModel.AlternateKeyNames` in WRITTEN order, while its COLLATING segment is sorted for exactly this reason ("the clauses' order in the entry is not part of their specification"). So two describers that name the same alternate keys, with the same descriptions, positions and DUPLICATES phrases, but write the two ALTERNATE RECORD KEY clauses in the other order are refused, at every edition (§2023:12.4.5.3 GR1 k is likewise silent on order).

**Found by.** The 1985 re-read 5, batch 1 (`kb/Work/PB4996/2026-11-14-reread-5.md`): the refuter of `E:/COBOL-coord/scratch/op-20261114/out-reread5/rs-01-refute.json` OVERTURNED the reader's CONFORMS of `1985-GR-IX.2.3.4-1` to PARTIAL (harm: over-rejects). The row had named only PB5069 (landed). The refuter's other probes agree with the read: ACCESS omitted against ACCESS MODE IS SEQUENTIAL, RESERVE 2 AREA against 2 AREAS and PIC X(2) against PIC XX run; a key JUSTIFIED RIGHT in one entry and PIC 99 against S99 are refused, as they should be.
