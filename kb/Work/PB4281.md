# PB4281 — comment-entry after conditional compilation; the residue PB4241 left

**Sites:** `src/WiseOwl.Cobol.Frontend/Preprocessor/DivisionCursor.cs:114` (`DivisionCursor.ReadDirective`, `DivisionCursor.ConditionalGroup`), `src/WiseOwl.Cobol.Frontend/Preprocessor/ReferenceFormatProcessor.LogicalConversion.cs:178` (`ReferenceFormatProcessor.LogicalConversion.CommentEntryOf`, `ReferenceFormatProcessor.LogicalConversion.BeginsCommentEntry`), `docs/CONFORMANCE.md` (the D-CE2 deviation entry at about :2075, which must describe the current compiler and name this note).

## What happens

1. Residue (same root as PB4241, stage order). A non-standard COBOL-85 comment-entry directly after a `>>IF` group whose branches disagree on the division is read as program text: the §6.5 converter decides "which division" per physical line before conditional compilation, `ConditionalGroup.After` answers "not IDENT" when branches disagree, and a comment-entry cannot be recognised without knowing the division. The exact fix is deciding comment-entry after conditional compilation, a stage-order redesign (CLAUDE.md rule 5: the restructuring, not the smallest diff).
2. The register pointer (review R2-2, low). D-CE2 in `docs/CONFORMANCE.md` says the residue "needs a stage-order redesign registered in the PB4241 report". That report is a scratch file outside the repository and PB4241 is landed, so a current-state doc points at a register CLAUDE.md rule 8 says does not exist. This note is that register; D-CE2 must name PB4281.
3. Unverified, not probed (implementer lead 2). `>>COBOL-WORDS EQUATE "IDENTIFICATION" WITH "IDENT"` respells the header after the converter has read it, so `DivisionCursor` never sees IDENT as IDENTIFICATION (`CompilationUnitStart.cs:54` handles the unit start only). Run the probe first: a program whose header is `IDENT DIVISION.` under that EQUATE with a comment-entry in its identification paragraphs; if the entry is read as program text, it is a second instance of the same root.

## Fix

Decide comment-entry after conditional compilation (or carry the division through the group), pinned by goldens for the disagreeing-branches shape and the EQUATE shape. Replace D-CE2's pointer with this note's id in the same change.

## Re-probe and what the wave 20261799 group B changed

**Item 2 (the register pointer) is FIXED:** docs/CONFORMANCE.md D-CE2 now names this note in place of the scratch report.

**Item 1 reproduces on the build** (`--source-format free --permissive`, 2023): `>>DEFINE X AS 1` / `IDENTIFICATION DIVISION.` / `>>IF X IS DEFINED` / `PROGRAM-ID. CE1.` / `>>ELSE` / `PROCEDURE DIVISION.` / `>>END-IF` / `AUTHOR. Pat O'Brien.` draws COBOL5563 and COBOL2633 on the apostrophe; the same text with `PROGRAM-ID. CE0.` in both branches (agreeing) compiles with the COBOL0902 comment-entry warning and runs. Reachable only under `--permissive` at 2002 or later: `>>IF` is a 2002 introduction (COBOL0900 at 85) and the comment-entry is removed at 2002 (COBOL0902, an error under strict).

**Item 3 is NOT clean, and it shares item 1's root.** `>>COBOL-WORDS EQUATE "IDENTIFICATION" WITH "IDENT"` is harmless (`IDENT DIVISION.` then `PROGRAM-ID.`; the first PROGRAM-ID paragraph enters the identification division anyway; `eq2` compiled and ran). The word the cursor reads is the other way round: `>>COBOL-WORDS EQUATE "DIVISION" WITH "DIV"` / `IDENTIFICATION DIV.` / `PROGRAM-ID. EQ1.` / `PROCEDURE DIV.` / `REMARKS. DISPLAY "HI".` (free form, 2023) draws `COBOL0001: unexpected '.'` at (5,10): the converter never sees `DIVISION`, stays in the identification division, reads the PROCEDURE DIVISION paragraph REMARKS as a comment-entry header and writes `REMARKS. .`. The control without the EQUATE (`PROCEDURE DIVISION.`) prints HI. Any respelling of a word `DivisionCursor` reads (DIVISION, IDENTIFICATION, ID, COPY, REPLACE, the unit paragraph names) by EQUATE or SUBSTITUTE does the same, and so does a SUBSTITUTE of the comment-entry words. This is a program with NO comment-entry that is rejected, which makes it a plain rejects-legal-source defect, unlike item 1's non-standard mix.

**Why it was not fixed in the wave (CLAUDE.md I9, MANDATORY-PRACTICES I9: a redesign beyond the slice).** Both are one root: the §6.5 converter decides "is this a comment-entry paragraph" from the SPELLING of words, before the two stages that change what the words mean (conditional compilation selects branches; `>>COBOL-WORDS` respells words). A per-symptom patch is the wrong shape: teaching the cursor to learn `>>COBOL-WORDS` operands would need the group's word map threaded into every cursor (the converters, `CopyProcessor` at :743 for library text, the merged driver's `ConditionalCompilationProcessor.Render` cursor, which never sees the directive lines because its blocks end at them), and would still leave item 1. The exact shape is to decide after both stages, and the obstacle to simply moving the decision is the reason PB3245 put it into the converter: a comment-entry is arbitrary text (an apostrophe in a name, an unclosed quotation mark, a `COPY` word) that the later scanners must never see. A design that fits: the converter carries a CANDIDATE comment-entry (a paragraph word in the set, plus its body lines) as an inert comment-carrier line like `DebugLineCarrier`, whenever the division is not certain (after a disagreeing group, or whenever `>>COBOL-WORDS` has respelled a word the cursor reads), and the merged driver, which holds the selected branch, the exact cursor and the final word map, either drops the carried lines (identification division: a comment-entry, written as `AUTHOR. .` as now) or restores the text before the block is scanned for COPY and REPLACE. Needed: the carrier kind, the resolution in `ConditionalCompilationProcessor.Render` / `CopyProcessor`, the group map made visible to the cursor, a golden for each shape (disagreeing branches; EQUATE of DIVISION), and the D-CE2 determination rewritten.
