# PB5083 - at --std 85 the USE FOR DEBUGGING execution rules give wrong results: a section-name subject is treated as every paragraph, an ALTER never runs the section, PERFORM LOOP appears only from iteration 2, a USE procedure is reported as START PROGRAM, and a SORT input or output procedure subject is refused

**Sites:** `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/ControlFlowEmitter.cs#EmitOutOfLinePerform` (`__dbgFirst ? DebugCause.Transfer : DebugCause.PerformLoop`) for GR20 only; the sites of the other five are not located (the triage records name none). COBOL1571 is the refusal for GR19.

**Mechanism.** Six general rules of §1985:XV.3.2.4 are violated by the generated debugging calls, in more than one place: a section-name subject is expanded into its paragraphs (so DEBUG-NAME holds the first paragraph, and a qualifier reference runs the section, GR16 and GR9); an ALTER of a subject never executes the section (GR17); the PERFORM transfer reports PERFORM LOOP only from the second iteration (GR20); a USE procedure gets START PROGRAM as DEBUG-CONTENTS (GR21); a subject that is a SORT or MERGE input or output procedure is refused with COBOL1571 where 1985 defines its DEBUG-CONTENTS (GR19, rejects legal source). The register net agrees with the draft on GR20 (CCVS DB101A SIMPLE-PERFORM-TEST expects PERFORM LOOP for a plain PERFORM). These may need splitting at fix time; they are filed together because one facility emits all six.

**Found by.** The 1985 `--std=85` draft triage (kb/Work PB4995 item 3): each rule below is a conformance-suite draft that did not MATCH at `--std 85`, and its adjudicator decided COMPILER-DEFECT. Harm and observed text are the records'; nothing here was re-derived.

**Inventory.** The traceability inventory carries no 1985 rows yet, so `inventory_rows` is empty; the rows this note covers are the 1985 rule ids listed below (catalog `docs/rearchitecture/spec-rule-catalog-1985.json`).

**Rules (6; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-GR-XV.3.2.4-9` - `§1985:XV.3.2.4 GR9` (record harm: wrong-answer, slice-21): §1985:XV.3.2.4 GR9: 'A reference to identifier-1, cd-name-1, file-name-1, or procedure-name-1 as a qualifier does not constitute reference to that item for the debugging described in the general rules above.' The debugging section is on S2 alone and §1985:XV.3.2.4 GR3 a executes it 'Immediately before each execution of the named procedure'; GO TO P2 OF S2 transfers control to P2 (GR18: 'the GO TO statement whose execution transfers control to procedure-name-1'), a procedure no USE FOR DEBUGGING statement names, and it names S2 only as a qualifier. The debugging section must not run.
- `1985-GR-XV.3.2.4-16` - `§1985:XV.3.2.4 GR13` (record harm: wrong-answer, slice-21): §1985:XV.3.2.4 GR16: 'If the first execution of the first nondeclarative procedure in the program causes the debugging section to be executed, the following conditions exist: ... b. DEBUG-NAME contains the name of that procedure.' and §1985:XV.3.2.4 GR13: 'DEBUG-NAME contains the first 30 characters of the name that caused the debugging section to be executed.' The only name in the USE FOR DEBUGGING statement is the section MAIN-SECT, so DEBUG-NAME must be MAIN-SECT.
- `1985-GR-XV.3.2.4-17` - `§1985:XV.3.2.4 GR3` (record harm: wrong-answer, slice-21): §1985:XV.3.2.4 GR3: 'When procedure-name-1 is specified in a USE FOR DEBUGGING statement that debugging section is executed: ... b. Immediately after the execution of an ALTER statement which references procedure-name-1.' and §1985:XV.3.2.4 GR17: 'b. DEBUG-NAME contains procedure-name-1. c. DEBUG-CONTENTS contains the applicable procedure-name associated with the TO phrase of the ALTER statement.'
- `1985-GR-XV.3.2.4-19` - `§1985:XV.3.2.4 GR19` (record harm: rejects-legal-source, slice-21): §1985:XV.3.2.4 GR19: 'If reference to procedure-name-1 in the INPUT or OUTPUT phrase of a SORT or MERGE statement causes the debugging section to be executed, the following conditions exist: ... b. DEBUG-NAME contains procedure-name-1. c. DEBUG-CONTENTS contains: 1) If the reference to procedure-name-1 is in the INPUT phrase of a SORT statement, 'SORT INPUT'. 2) If the reference to procedure-name-1 is in the OUTPUT phrase of a SORT statement, 'SORT OUTPUT'.' The standard defines the program; nothing in §1985:XV.3.2.3 forbids an input or output procedure as procedure-name-1.
- `1985-GR-XV.3.2.4-20` - `§1985:XV.3.2.4 GR20` (record harm: wrong-answer, slice-21): §1985:XV.3.2.4 GR20: 'If the transfer of control from the control mechanism associated with a PERFORM statement caused the debugging section associated with procedure-name-1 to be executed, the following conditions exist: a. DEBUG-LINE identifies the PERFORM statement that references procedure-name-1. b. DEBUG-NAME contains procedure-name-1. c. DEBUG-CONTENTS contains 'PERFORM LOOP'.' GR20 is the only one of GR16 to GR22 that covers a PERFORM (§1985:VI.6.21.4 GR7: 'When the PERFORM statement is executed, control is transferred to the first statement of the specified set of statements'), and for an iterative PERFORM §1985:IV.4.4.2 puts the control-mechanism transfer on every iteration, the first included: 'the control mechanism associated with that PERFORM statement and the first statement in that paragraph for each iterative execution of the paragraph'.
- `1985-GR-XV.3.2.4-21` - `§1985:XV.3.2.4 GR21` (record harm: wrong-answer, slice-21): §1985:XV.3.2.4 GR21: 'If procedure-name-1 is a USE procedure that is to be executed, the following conditions exist: a. DEBUG-LINE identifies the statement that causes execution of the USE procedure. b. DEBUG-NAME contains procedure-name-1. c. DEBUG-CONTENTS contains 'USE PROCEDURE'.' The program is legal: ERR-PROC is not a debugging section (§1985:XV.3.2.3 SR5 forbids only 'Procedure-names defined within debugging sections').

**Expected (from the 1985 text).** See each rule: the debugging section runs only for the named procedure, with the DEBUG-NAME, DEBUG-LINE and DEBUG-CONTENTS values the rule gives. The deciding words: "A reference to identifier-1, cd-name-1, file-name-1, or procedure-name-1 as a qualifier does not constitute reference to that item for the debugging described in the general rules above." (§1985:XV.3.2.4 GR9).

**Observed (copied from `1985-GR-XV.3.2.4-9`).** Expected 'START', 'P2'. The compiler prints 'START', 'DEBUG [P2                            ] [             ]', 'P2': the debugging section on S2 runs, with DEBUG-NAME 'P2'. The qualifier is not what triggers it: p7.cob, the same program with an unqualified 'GO TO P2', prints the same three lines. The mechanism is the one recorded under 1985-GR-XV.3.2.4-16: USE FOR DEBUGGING ON a section-name is treated as naming every paragraph of that section.
