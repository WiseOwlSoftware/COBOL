# PB4520 — index-name-compare-non-integer-operand: -std=cobol2014: comparing an index-name with a non-integer numeric item or literal gives the wrong result

Filed 2026-11-03 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-batch-3000-20261103`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

Under `-std=cobol2014`, a relation condition between an index-name and a numeric data item or literal that is not an
integer gives the wrong truth value. With the index set to occurrence 2, `WS-I < WS-N` (WS-N = 2.5) is false,
`1.5 < WS-I` is false and `WS-I = 2.0` is false; all three are true by the standard, which compares the occurrence
number with the operand's value. cobc drops the operand's decimal point and compares the occurrence number with 25,
15 and 20; `WS-I < 2.5` comes out right only because 2 < 25. Class: wrong output. No compile-time
diagnostic is given. Fuzz night 2026-11-03: fz00409, fz00410, fz01818, fz01819, fz01820 (signature
OUTPUT_DIFFERS:8.8.4.2.13).

## Minimal test case

Free reference format (`-free`).

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. IDXCMP.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 WS-TAB.
   05 WS-E PIC X OCCURS 5 INDEXED BY WS-I.
01 WS-N PIC S9V9 VALUE 2.5.
PROCEDURE DIVISION.
MAIN-PARA.
    SET WS-I TO 2
    IF WS-I < WS-N DISPLAY "T1 LT" ELSE DISPLAY "T1 NOT LT" END-IF
    IF WS-I < 2.5 DISPLAY "T2 LT" ELSE DISPLAY "T2 NOT LT" END-IF
    IF 1.5 < WS-I DISPLAY "T3 LT" ELSE DISPLAY "T3 NOT LT" END-IF
    IF WS-I = 2.0 DISPLAY "T4 EQ" ELSE DISPLAY "T4 NOT EQ" END-IF
    IF WS-I > 2.0 DISPLAY "T5 GT" ELSE DISPLAY "T5 NOT GT" END-IF
    STOP RUN.
```

## Environment

`cobc (GnuCOBOL) 3.2.0` on WSL2 Ubuntu. Compiled with `cobc -x -free -std=cobol2014 -o p idx.cob` (no diagnostic
other than the distribution's `_FORTIFY_SOURCE` redefinition notice) and run as `./p`.

## Observed result

```
T1 NOT LT
T2 LT
T3 NOT LT
T4 NOT EQ
T5 NOT GT
```

Exit code 0.

## Expected result (per ISO)

§8.8.4.2.13 rule 2): relation tests may be made between "an index-name and a numeric data item or numeric literal.
The occurrence number that corresponds to the value of the index-name is compared to the data item or literal." The
occurrence number is 2 after `SET WS-I TO 2`, so 2 < 2.5, 2 < 2.5, 1.5 < 2 and 2 = 2.0 are true and 2 > 2.0 is false:

```
T1 LT
T2 LT
T3 LT
T4 EQ
T5 NOT GT
```

The same words are in the ISO/IEC 1989:2002 text and in the 2009 committee draft that led to 2014 (the edition the
`-std=cobol2014` flag claims), and unchanged in 2023.
The source is legal: WS-N is a numeric data item and 2.5, 1.5 and 2.0 are numeric literals, which rule 2) admits
without an integer restriction.

## Our compiler

WiseOwl COBOL (fresh judge, `--std 2014 --source-format free`) prints the expected five lines, with no diagnostic.

## Fix site

`cobc/typeck.c`, function `cb_build_cond_default`: when either operand satisfies `CB_INDEX_OR_HANDLE_P`, the condition
is built as `cb_build_binary_op (left, '-', right)`, and the C that cobc 3.2.0 generates (`cobc -C`) evaluates it as an
`int` subtraction of the operand's digits with its scale dropped: `(int)(b_3 - 25) < 0` for `WS-I < 2.5`,
`(int)(b_3 - 15) > 0` for `1.5 < WS-I`, `(int)(b_3 - 20) == 0` for `WS-I = 2.0`, and
`(int)(b_3 - cob_get_numdisps (b_4, 1)) < 0` for `WS-I < WS-N` (25 again). A fix compares the occurrence number with
the operand at the operand's scale. The function and test were read in the 3.3-dev tree; the generated C is from 3.2.0.

Environment: GnuCOBOL 3.2.0 (cobc), WSL2 Ubuntu; `cobc -x -free -std=cobol2014 -o p idx.cob`, then `./p`.

Steps: compile and run the program below. The index WS-I is set to occurrence 2.

Observed: `T1 NOT LT`, `T2 LT`, `T3 NOT LT`, `T4 NOT EQ`, `T5 NOT GT`.

Expected: `T1 LT`, `T2 LT`, `T3 LT`, `T4 EQ`, `T5 NOT GT`. ISO/IEC 1989 §8.8.4.2.13 rule 2 (the same words in 2002,
the draft for 2014, and 2023): for an index-name and a numeric data item or numeric literal, "the occurrence number that
corresponds to the value of the index-name is compared to the data item or literal". 2 < 2.5, 1.5 < 2 and 2 = 2.0 are
all true.

generated C (`cobc -C`) drops the operand's scale: `IF WS-I < 2.5` becomes `(int)(b_3 - 25) < 0`, `IF 1.5 < WS-I`
becomes `(int)(b_3 - 15) > 0` and `IF WS-I = 2.0` becomes `(int)(b_3 - 20) == 0`.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. IDXCMP.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 WS-TAB.
   05 WS-E PIC X OCCURS 5 INDEXED BY WS-I.
01 WS-N PIC S9V9 VALUE 2.5.

MAIN-PARA.
    SET WS-I TO 2
    IF WS-I < WS-N DISPLAY "T1 LT" ELSE DISPLAY "T1 NOT LT" END-IF
    IF WS-I < 2.5 DISPLAY "T2 LT" ELSE DISPLAY "T2 NOT LT" END-IF
    IF 1.5 < WS-I DISPLAY "T3 LT" ELSE DISPLAY "T3 NOT LT" END-IF
```
