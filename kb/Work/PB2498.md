# PB2498 — OPEN

Filed by the train-1034b lander from the wave-1034 group B report (PB244, `E:\COBOL-coord\scratch\reports\w1034b-PB244-report.md`,
new defect 3). Unverified: the implementer did not probe the fix.

**Mechanism.** `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs#VariableLengthGroupSum` sums a variable-length
group's current extent for FUNCTION LENGTH / BYTE-LENGTH, and keeps a group with a USAGE BIT descendant (`HasBitDescendant`) as the
named stage COBOL1756, because the bit walk (PB207, PB203) packs bits by the §8.5.1.6.3 rules and the character sum would be wrong.

**Lead.** The group's packed image length probably equals its byte length, so the stage may need only the one-way gate
(`CurrentExtentUse.OneWayImage`) and the bit walk's width per component. Derive the expected value from §15.50.4 and the
§8.5.1.6.3 walk before changing anything.

**Repro.** `E:\COBOL-coord\scratch\w1034b\p\b1.cob`. **Site.** `IntrinsicBinder.VariableLengthGroupSum` (the `HasBitDescendant` stage).

## Landed 2026-10-11 (w1059 H)

Re-probed: a group with an OCCURS DEPENDING table of bit elements (`05 N PIC 9. 05 X PIC 1 USAGE BIT. 05 TB PIC 1 USAGE BIT
OCCURS 1 TO 8 DEPENDING ON N`) staged COBOL1756 at LENGTH and BYTE-LENGTH, as did the same table in a GROUP-USAGE BIT
group (`b1.cob` itself is PB2964's shape, dynamic leaf; it also had a B1 name clash). The note's lead ("the stage may
need only the one-way gate") was not the mechanism: a group that is variable-length only by an ODO table is not an image
case, and its occurrences share bytes (8.5.1.6.3), so the extent is counted in BIT positions exactly as
`OdoModel.WrapGroup` counts the group's own image (`BitLayout.StartBitOf` + `StrideBits`). `BoundOdoExtent` gained
`PositionsPerCharacter` (8 for an alphanumeric group, so the extent rounds up to whole characters, 15.50.4 rule 9 and
15.14.4 rule 4; 1 for a bit GROUP's LENGTH, which 15.50.4 rule 1 gives in boolean positions). The renderer reads the
image channel's `CobolTable.OdoExtentChars`.
Found in the same builder and fixed with it (I9): the LENGTH of a GROUP-USAGE NATIONAL group with an ODO table answered
bytes (10 for 5 occurrences) where 15.50.4 rule 2 counts national positions (5); `VariableLengthGroupSum` now builds a
national group in positions. Golden `2002/pb2498_length_odo_bit_national_group` (bit-bearing alphanumeric group, bit
group, national group). The ALIGNED OCCURS DEPENDING table of a bit GROUP stays a named stage (its trailing filler is
not a boolean position).
