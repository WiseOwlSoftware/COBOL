# PB3332 — the B+ tree

Implement FROM `docs/rearchitecture/DESIGN-runtime-library.md` §2.2.1, sections 2.2.1.4 (INTERNAL, LEAF and OVERFLOW page
bodies, the key orders, the inline/overflow threshold of 1 016 bytes) and 2.2.1.12 (the model test). Follows PB3331 (same
folder; the ledger's serialization becomes this tree).

## Mechanism

- `IKeyOrder` with the four orders of 2.2.1.4: `OrdinalKeyOrder` (bytes; also serves the 8-byte big-endian relative record
  number and the page-number keys of the free and ledger trees), `WeightedKeyOrder` (decode the channel bytes with the file's
  `FileCharacterSet`/`CodeSetConversion`, then the key's `CobolCollation` exactly as `IndexedConnector.KeyCompare` compares
  today, keys cached through the collator's key cache), `CompositeKeyOrder` (a key order, then the trailing 8-byte big-endian
  ordinal). Prefix seek for START's partial key (§14.9.41.4 GR17 b)) is a seek under the same order with a prefix length.
- `BTree` over `PagedFile`: `Seek(key, relation)` for =, >, >=, <, <= and prefix forms, `First`/`Last`, `Insert`, `Replace`,
  `Delete`, and a `Cursor` with `Next`/`Previous` that crosses leaves by the sibling pointer; path copying through
  `PagedFile.WritePage` (which applies R1-R3 itself, so the tree never asks whether a page is fresh); splits at a full page,
  merges or borrows below a quarter full; values past 1 016 bytes in an overflow chain (`OverflowChain` read/write/free).
- The FREE tree and the LEDGER tree are instances of this class keyed by page number; PB3331's interim serialization is deleted
  here (no wrapper: `Ledger` holds a `BTree`).
- `IoCounters` attribution: every page the tree touches is counted on the statement in progress.

## Files

New: `src/Cobol.Net.Runtime/IO/Store/{IKeyOrder,KeyOrders,BTree,BTreeCursor,OverflowChain}.cs`;
`tests/Cobol.Net.Tests.Unit/Store/{BTreeModelTests,BTreeShapeTests}.cs`. Touched: `IO/Store/Ledger.cs` (its serialization
replaced by the tree), `IO/Store/PagedFile.cs` (the free tree).

## Tests

- The model test: insert/delete/seek/next/prev/first/last against a `SortedDictionary` oracle under every key order, with
  composite keys, overflow values (1 017 bytes, 4 065 bytes, 1 MiB) and enough entries to split and merge at three levels;
  seeded, deterministic, every host.
- Shape: a tree of N 8-byte keys has the depth the 2.2.1.4 arithmetic predicts; a READ by key reads exactly depth pages cold;
  a sequential insert run rewrites the rightmost leaf in place between promotions (R3, measured by `IoCounters`).
- The free tree returns the lowest free page and the file grows only when it is empty; the ledger survives a promotion.
