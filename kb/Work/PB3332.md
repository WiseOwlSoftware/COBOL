# PB3332 — the B+ tree

Implement FROM `docs/rearchitecture/DESIGN-runtime-library.md` §2.2.1, sections 2.2.1.4 (INTERNAL, LEAF and OVERFLOW page
bodies, the key orders, the inline/overflow threshold of 1 016 bytes) and 2.2.1.12 (the model test). Follows PB3331 (same
folder; the ledger's serialization becomes this tree).

## Mechanism

- `IKeyOrder` with the four orders of 2.2.1.4: `OrdinalKeyOrder` (bytes; also serves the 8-byte big-endian relative record
  number and the page-number keys of the free and ledger trees), `WeightedKeyOrder` (decode the channel bytes with the file's
  `FileCharacterSet`/`CodeSetConversion`, then the key's `CobolCollation` exactly as `IndexedConnector.KeyCompare` compares
  today, keys cached through the collator's key cache), `CompositeKeyOrder` (a key order, then the trailing 8-byte big-endian
  ordinal). Prefix seek for START's partial key (§14.9.41.4 GR17 b) sets the length, c) and d) truncate, e) compares) is a seek under
  the same order with a prefix length.
- `BTree` over `PagedFile`: `Seek(key, relation)` for =, >, >=, <, <= and prefix forms, `First`/`Last`, `Insert`, `Replace`,
  `Delete`, and a `Cursor` with `Next`/`Previous` that crosses leaves by the sibling pointer; every child reference, root
  reference and overflow link is a STAMPED POINTER (`PagePointer`, page + generation, 2.2.1.6 R3) and every read through one
  verifies the page against its stamp; path copying of the whole path at every statement through `PagedFile.WritePage` (which
  applies R1 itself — no page either slot references is ever written — so the tree never asks whether a page is fresh);
  splits at a full page, merges or borrows below a quarter full; values past 1 016 bytes in an overflow chain (`OverflowChain`
  read/write/free; each link stamped). A statement's pages come from `PagedFile`'s reservation (2.2.1.6 R2).
- The FREE tree, the LEDGER tree, the TRANSACTIONS tree, the UNDO trees and the HOLDINGS tree (PB3337) are instances of this class keyed by page
  number, transaction id or record identity; PB3331's interim serialization is deleted here (no wrapper: `Ledger` holds a
  `BTree`).
- `IoCounters` attribution: every page the tree touches is counted on the statement in progress.

## Files

## Tests

- The model test: insert/delete/seek/next/prev/first/last against a `SortedDictionary` oracle under every key order, with
  composite keys, overflow values (1 017 bytes, 4 065 bytes, 1 MiB) and enough entries to split and merge at three levels;
  seeded, deterministic, every host.
- Shape: a tree of N 8-byte keys has the depth the 2.2.1.4 arithmetic predicts (184-way internal fan-out with 12-byte
  pointers); a READ by key reads exactly depth pages cold; a sequential insert run writes exactly depth pages per statement
  (one path copy, R1, measured by `IoCounters`) and reuses the pages the previous statement released (R2).
- A page served at an older version under a stamped pointer is refused as torn at the read (R3).
- The free tree returns the lowest free page and the file grows only when both the released pages and the free tree are
  exhausted; the ledger survives a promotion.

## Done when

## Landed (wave 1118, group A2)

Built on PB3331 (merged from its branch; it lands through this one). In the tree: `src/Cobol.Net.Runtime/IO/Store/`
`BTree.cs` + `BTreeCursor.cs` (one partial class), `IKeyOrder.cs`, `KeyOrders.cs` (ordinal, weighted, composite; the
numeric keys' codecs), `OverflowChain.cs` (PageChain's successor, the value chain only — PageChain is deleted with the
interim LEDGER and FREE payloads); `Ledger` holds a RESIDENT `BTree`; `PagedFile`'s FREE set is the FREE tree.
Tests: `tests/Cobol.Net.Tests.Unit/Store/BTreeModelTests.cs`, `BTreeShapeTests.cs`, `BTreeCrashTests.cs`; `StoreKit`'s
caller now drives the real tree and its auditor decodes the 2.2.1.4 layouts raw (`ReadNode`); five
`PendingStoreCases` rows hand the tree's COBOL surface (START relations, AT END, '22', '23', '30' with and without a
USE declarative and a FILE STATUS item) to PB3333 and PB3334.

- **Re-probe.** Construction, not a fix: on the merged base the store had no tree (`IO/Store` held the page layer only;
  no connector reaches it). Nothing to discharge.
- **The shape.** Changes are made in memory (the path copied, splits, merges and borrows) and flushed once per
  statement, every changed node written exactly once, children first, then every superseded page released — so R1 and
  R3's corollary hold by construction, and the pages a statement writes are known before `PagedFile.Begin` reserves
  them (`Begin(..., entered: true)` after the caller's `Enter` and its reads). A torn or stale read answers '30' and
  discards the pending edit. Cursors hold their path; `BTree.Adopt` re-roots a tree after a coherent entry and a cursor
  under the old root re-seeks from its key.
- **The ledger on the tree.** It never lists its own pages (R2), so its write SETTLES first: the pages it supersedes
  become `released`, a reserved page it takes leaves the list, a reserved FREE page nobody took becomes `released` —
  repeated until nothing moves, with rebalancing off so its page count only grows and the settling ends.
- **What the cases found in the design (2.2.1.4 corrected in this branch):** a leaf cannot carry a right-sibling
  pointer under path copying (re-pointing a rewritten leaf's neighbour copies every leaf to its left) — `next` is 0 for
  I and L and a cursor climbs its path; the inline rule needs the entry bound too (a 1 016-byte key with a 1 016-byte
  value made a 2 038-byte entry, two of which do not share a page); a midpoint split leaves a sequential load half
  full, so an APPEND splits off only what it added (the 184-way fan-out the arithmetic assumes), and rebalancing runs
  only on a node a change SHRANK (otherwise the append's small right page is merged back at the next append); the
  arithmetic's "6 million / 1.1 billion" holds for 8-byte frames and is now stated with its formula; the START prefix
  is GR17 b) to e), not b) alone.
- **Measured.** A sequential load of 8-byte records: 184 → 1 level, 185 → 2, 34 040 → 2, 34 041 → 3; a cold READ reads
  the depth; a scan reads every page once; a one-record statement writes the depth + the ledger's path (at most 2 over
  3 000 statements) + page 2, and grows the file only once the released pages are all taken.
- **Mutations** (each turned cases red, then reverted): the borrow's separator not updated; a superseded page not
  released; the ledger listing the pages it takes; the internal append split dropped (which the depth boundaries
  alone missed: the fan-out check of the second level was added for it).
- **Branch review round 1 (the review finisher, worktree-wf_14a1e62b-326-16):** R1-1 the reservation sized the ledger
  by the pages a statement RESERVES only, so a DELETE or shortening REWRITE of a committed 4 MB record (1 000 overflow
  pages, as many `freed` entries) threw out of `PageStatement.Complete`; `Begin` now takes a `StatementBound` (pages
  written AND pages released, `StatementBound.Of(trees)`), `Reserve` adds the FREE tree's own superseded pages and
  `Ledger.WriteBound` counts one change per release, level by level. R1-2 a cursor detected a change by comparing roots,
  which a second edit of an already-copied node leaves equal; the tree now carries a change counter (edit, flush,
  discard, adoption) and `ReadValue` after a change looks the value up by key. R1-3 PB3331's review fixes were merged
  (worktree-wf_14a1e62b-326-10) and re-derived on the tree: the boundary in the tree's `Reserve`, refused reads told
  from damage at the resident ledger's load (`PageCheck`), and every tree read point a refused-read case. Mutations
  (each red, then reverted): the root comparison (3 cursor cases), the releases left out of the bound (5), a refused
  read at OPEN taken as damage (3).
- **Branch review (wave 1122 A, review-w1122-a.jsonl R1-1):** a START prefix was narrowed by binary search under every
  order, but a LOCALE-BASED sequence is not prefix-consistent (§8.8.4.2.11: the comparison *"is not necessarily performed
  character-by-character"*; under the root locale "áa" < "ab" while "á" > "a"), so NOT LESS THAN "á" over áa, ab, ác, ad
  answered ác where §14.9.41.4 GR17 c)'s sequential search takes áa, and LESS THAN "á" answered ab where d)'s reverse
  search takes ad. `IKeyOrder.PrefixConsistent` (from `CobolCollation.UsesStandardComparison`, abstract, so every
  collation arm states its shape) now says whether the binary search is valid; otherwise `Seek` walks the tree entry by
  entry in GR17's direction. Cases: `BTreeShapeTests.A_START_prefix_under_a_locale_sequence_is_the_sequential_search_of_GR17`
  and the locale model run `BTreeModelTests.The_tree_agrees_with_a_sorted_model_under_a_locale_order_whose_prefixes_are_not_consistent`,
  both red with the flag forced true.

## Landing — for the next implementer (PB3333, PB3334)

- `src/Cobol.Net.Runtime/IO/Store/BTree.cs` — one tree per root; edits `Insert`/`Put`/`Replace`/`Delete` in memory,
  `PagesToWrite`, then `Flush(statement)` → the new root → `PageStatement.SetPrimeRoot`/`SetAlternateRoot`. The
  statement shape: `store.Enter()` → read and edit the trees → `store.Begin(StatementBound.Of(every edited tree), out
  st, entered: true)` → flush each → `st.Complete()` (see `StoreKit.Commit`). Never call `Begin` before the edits, and
  never with a hand-counted bound: it is the pages the edits write AND the pages they released (review R1-1). A
  `StoreStatus.Boundary` from `Begin` or `Complete` is the connector's to answer by the statement (PB3331).
- `BTreeCursor.cs` — `Seek(key, relation, prefix)` (START's GR17 c)-e)), `First`/`Last`, `Next`/`Previous`,
  `ReadValue`. The trap: after a coherent entry that adopted another run unit's page 2, call `tree.Adopt(meta root)`
  before stepping a cursor, or it walks pages that run unit may have reused (R3 then answers '30'). A cursor may be
  stepped across its own run unit's edits (it re-seeks, review R1-2); reading the value of a current entry an edit
  deleted is refused loudly.
- `KeyOrders.cs` — choose the order at OPEN: ordinal with no CODE-SET and no COLLATING SEQUENCE; `WeightedKeyOrder`
  otherwise; `CompositeKeyOrder` over the key's order for an alternate tree (`Compose(key part, ordinal)`). Pass every
  START with `prefix: true` (the order decides whether the seek is a binary search or GR17's sequential search).
- `Ledger.cs#Write` — the settling loop; `WriteBound` is the reservation's allowance for it.
- Tests: `BTreeModelTests.AuditShape` (the raw shape audit), `StoreKit.ReadNode`, `StoreKit.Commit`.
