# PB3696 — in-wave chaining compares two groups on their PRIMARY file only, so two groups on different members of one primary file that both claim the same secondary file whole run side by side, while the same pair is held when one is in flight

**Sites:** `scripts/orchestrator/plan_wave.py` (`plan`), `.claude/skills/workstream/check_practices.py` (`group_claim`, `claims_meet_without_successor`), `scripts/orchestrator/test_plan_wave.py`, `docs/rearchitecture/DESIGN-orchestrator-loop.md`.

The partition has two lanes that should be one rule (PB2807): the in-flight check meets on every claimed unit, the in-wave chaining meets on the primary file's units only. Make the in-wave rule ask the same `unit_meet` over every file both groups claim, with a self-test pair that shares a secondary file whole.

## Landed (2026-10-25, fix-lane wave 20261107 group C)

**Re-probe.** Two clusters on different members of one primary file that both claim a third file whole were planned side
by side (A, B), and two on different primary files sharing a secondary file also; the same pair is held when one is in
flight.

**Fix.** The in-wave rule asks `collision` (over `unit_meet`) of every placed group, not `unit_meet` on the primary
file of the groups placed on it (`on_file` is deleted): one question for the wave and for the in-flight work. **Sibling
arm.** `check_practices.same_file_without_successor` (O2) was a second copy of the primary-file-only rule with its own
`members_meet`; it is now `claims_meet_without_successor`, which asks `plan_wave.collision` over each group's
`file_set`/`member_set` (a hand-built group with neither falls back to its `root` file, whole), and `members_meet` and
`source_units` are gone from it. **Tests.** Both secondary-file cases chain (A, A2) and the control (nothing shared) stays
side by side; the in-flight rule is asked the same pair; the practices check refuses the same pairs.
