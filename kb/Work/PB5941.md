# PB5941 - the `All` listing row is over its budget with the object code

**Measured** by listing step 8 (w20262104i), Release, one Windows host, `dotnet run -c Release --project
tests/WiseOwl.Cobol.Benchmarks -- --filter '*CompileBenchmarks.FullCompile*'` on `listing-step-8` after its last change
(the IL name cache), allocated bytes per full compile (`E:/COBOL-coord/scratch/my-20261115/listing-build/w20262104i/bench-step8c.md`):

| Program | None | All | All over None |
|---|---|---|---|
| IX113A | 189.57 MB | 256.88 MB | +35.5 % |
| NC105A | 118.36 MB | 160.93 MB | +36.0 % |
| NC218A | 114.31 MB | 158.49 MB | +38.6 % |
| SM201A | 41.14 MB | 56.11 MB | +36.4 % |

Step 6's `All` (no object code) was +11.1 to +20.2 %. DESIGN-listing.md section 9: "Every section in every format: at most 25 %",
and "A row over its budget is a kb/Work defect filed before the step lands".

**Mechanism.** `all` holds `object-code`, the IL of every statement (IBM's LIST): one `ListingInstruction` per instruction, then
the same instructions as text rows and as JSON. A NIST program's dispatch method holds tens of thousands of instructions. The first
build decoded each stretch from its method's start (quadratic: NC105A's `All` was 2,657 MB) and named each token afresh; both are
fixed in the step (`ObjectCodeMapReader.Read` decodes a body once; `IlDisassembler.Decode` names a token once per assembly).

**Sites:** `src/WiseOwl.Cobol.Compiler/Listing/IlDisassembler.cs` (`IlDisassembler.Decode`), `src/WiseOwl.Cobol.Compiler/Listing/ObjectCodeMapReader.cs` (`ObjectCodeMapReader.Read`), `src/WiseOwl.Cobol.Listing/ListingObjectCode.cs` (`ListingInstruction`), `docs/rearchitecture/DESIGN-listing.md` (§9, §13)

**Directions, to decide.** (a) A lighter instruction: the operand as an index into one table of the assembly's names rather than a
string per instruction, with the text and JSON renderers reading the table; (b) the budget's own question, section 13 item 1: whether
`all` should hold the object code at all (IBM's LIST is a separate option), or the budget measure `all` without `object-code`, which
step 6's row is; (c) measure the JSON writer's share, since the JSON form repeats every instruction.
