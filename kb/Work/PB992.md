# PB992 — OPEN

## Repro — measured
`scratchpad/w50c/natsp.cob`: `01 G. 05 GX PIC X(3) VALUE SPACES.` `01 H PIC 9(3) VALUE 123.` `01 HR. 05 HH PIC 9(3).`
`01 K PIC 9(3)` with `KR REDEFINES K PIC X(3)`. Output: **`H=[000]`**, `HH=[   ]`, `K=[   ]`.

## The rule
`OK  §14.9.25.4 4)` — "Any move that is not an elementary move, and does not reference a variable-length group, is
treated exactly as if it were an alphanumeric to alphanumeric elementary move, except that there is no conversion of
data from one form of internal representation to another." The group move stores G's three characters into H's storage
unconverted; H then holds three spaces (its content is not a valid numeric value, which is the program's business). The
three items differ only in where the compiler chose to keep them, so they must agree.

## Code site
The native carrier of an elementary numeric item holds a VALUE, so a character image with no numeric reading is
normalized on store: `DataItem.StoreAsImage`, `CallAbi.WriteCellImage` (BY REFERENCE character formal writing back into
a native argument), `StoreReturn(string, NumProfile)` (RETURNING into a native receiver).

## What the fixer owes
A native numeric carrier must be able to hold an image that is not a numeric value (a side image, or demotion of such
items to image residence when any character channel can reach them — decide at design time, `docs/COBOLNET_DESIGN.md`
typed-native section). The three channels are one mechanism: fix them together and golden all three. Re-homes the
character-channel half of GR-14.2.3-8 from PB965 (PB970 keeps the BINARY/PACKED half).
