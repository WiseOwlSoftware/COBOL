# PB992 — LANDED (wave 56)

## Repro — measured
`scratchpad/w50c/natsp.cob`: `01 G. 05 GX PIC X(3) VALUE SPACES.` `01 H PIC 9(3) VALUE 123.` `01 HR. 05 HH PIC 9(3).`
`01 K PIC 9(3)` with `KR REDEFINES K PIC X(3)`. Output: **`H=[000]`**, `HH=[   ]`, `K=[   ]`.

## The rule
`OK  §14.9.25.4 4)` — "Any move that is not an elementary move, and does not reference a variable-length group, is
treated exactly as if it were an alphanumeric to alphanumeric elementary move, except that there is no conversion of
data from one form of internal representation to another." The group move stores G's three characters into H's storage
unconverted; H then holds three spaces (its content is not a valid numeric value, which is the program's business). The
three items differ only in where the compiler chose to keep them, so they must agree.

## Code site
The native carrier of an elementary numeric item holds a VALUE, so a character image with no numeric reading is
normalized on store: `DataItem.StoreAsImage`, `CallAbi.WriteCellImage` (BY REFERENCE character formal writing back into
a native argument), `StoreReturn(string, NumProfile)` (RETURNING into a native receiver).

## What the fixer owes
A native numeric carrier must be able to hold an image that is not a numeric value (a side image, or demotion of such
items to image residence when any character channel can reach them — decide at design time, `docs/COBOLNET_DESIGN.md`
typed-native section). The three channels are one mechanism: fix them together and golden all three. Re-homes the
character-channel half of GR-14.2.3-8 from PB965 (PB970 keeps the BINARY/PACKED half).

## Landed — wave 56 (fix lane F)

**Decision (the "decide at design time" the note asked for): DEMOTION, not a side image.** A side image would be a
second representation of one storage area, which is exactly what the data model's image promotion exists to avoid.
The compiler already had the mechanism — the whole-group promotion of numeric-DISPLAY leaves (§14.9.25.4 GR4) — and
it had no ELEMENTARY arm. `UsageCollectionPass` now also collects `DataBinder.CharacterChannelItems`, the
elementary items a character channel writes, and `StorageFormPass` promotes them under the ONE eligibility test
(`IsImagePromotable`, extracted from the whole-group arm):

- the receiver of a `MoveKind.GroupToElementary` store — asked of the bound node, so READ INTO / WRITE FROM /
  RETURN INTO / GOBACK RETURNING and every other constructed MOVE are covered without a second site;
- every BY REFERENCE CALL argument and every BY REFERENCE formal parameter (`OK §14.2.3 8)` "occupies the same
  storage area as the argument"; `OK §14.8.2.3.2 1)` a Format-1 pair need only be "of the same length");
- a CALL RETURNING receiver (`OK §14.6.5` "the content of the data item"; `OK §14.9.4.4 4)`), except a
  user-defined function's result temporary, which already mirrors its model's form.

Measured on the wave-56 build: `natsp.cob` H=[000] → **H=[   ]**; a dynamic callee's `MOVE SPACES` into a PIC X(3)
formal over a PIC 9(3) argument A=[000] → **A=[   ]**; a PIC 9(3) formal over a PIC X(3) "ABC" argument
N=[000] → **N=[ABC]** (the fourth channel, found by the re-probe); a RETURNING receiver R=[000] (and an abort on
the base build) → **R=[   ]**; `MOVE G2 TO S` with S PIC S9(3)V9 S=[012B] → **S=[12AB]**. Ordinary numeric crossings
are unchanged (the ADD-5 callee still yields 0015/0016). Goldens `conformance:85/pb992_character_channel_numeric`,
`conformance:2002/pb992_returning_character_content`. The BINARY / PACKED half stays kb/Work PB970's.
