# PB66 — LANDED — `01 E1 PIC -9.9(5)E+99.` used to reject with COBOLNET0899 "recognized but not yet implemented"

> ⚙ **flags:** rejects-legal (was) · **2 inventory rows** (RV-15.43.4-1, RV-15.58.4-1) · **landed 2026-08-18**
> (DEVLOG 1322; data-model design **D21**, which adopts and supersedes
> `docs/rearchitecture/pb66-extfloat-design-draft-2026-08-09.md`).

> `01 E1 PIC -9.9(5)E+99.` → COBOLNET0899. The HIGHEST-ALGEBRAIC / LOWEST-ALGEBRAIC returned-value rules for
> the form could not be evaluated while the description itself could not be declared. A loud stage is deferral
> debt (CLAUDE.md rule 3). Terminology: the 2023 standard names the category FLOATING-POINT NUMERIC-EDITED
> (§13.18.40.4 GR13 b); "external floating-point" appears nowhere in the spec.

## As built (DEVLOG 1322)

- **Description** (`PictureAnalyzer.AnalyzeFloatEdited`): the picture is two strings joined by E (§13.18.40.6 —
  Table 10 applies to each separately, rendered from PDF pages 489–490 to confirm the OCR): the exponent is
  exactly `+9{1..4}`; the significand an optional leading fixed sign then only the symbols Table 10 row E admits
  before E — `9 B 0 / , .` — one point, 1..36 digits (§13.18.40.4 GR13 b: no floating insertion, no zero
  suppression; V P S Z * CR DB and the currency symbol are COBOLNET1658 with a per-symbol message; a SIGN clause
  is 1658 too, §13.18.52.3 SR1). Category numeric-edited, class alphanumeric; `PicInfo.IsFloatEdited` is the
  sole discriminator (`DigitPositions` 0, `Scale` 0); the 2002 introduction gate keys on it through the ONE
  `VersionConformancePass.PictureConstructId` (forest, report printables and the report SUM-counter Analyze
  alike — `ReportSumModel.SkeletonGate`).
- **Editing** (`CobolEdit.Float.cs`, runtime): `FloatMask.Parse` is the ONE parser of the form;
  `FormatFloatMove` (Int128+scale / CobolDec / double senders) normalizes to a leading-nonzero significand
  (§14.6.8.4 GR1), truncates to the significand's digits (GR2 → §13.18.40 alignment), zero → all-zero digits with
  positive signs (§13.18.40.5 r8), BLANK WHEN ZERO honored; overflow → EC-DATA-OVERFLOW (fatal under checking —
  the receiver unchanged; unchecked → the pinned saturated image, a CONFORMANCE.md §4 determination for the
  spec's "undefined") and underflow → zero (§14.9.25.4 GR6 item 4); `TryFormatFloat` is the arithmetic store
  (false both ways out of range = the size error condition, §14.7.5 cases 3 and 4); `DeEditFloat` reads the
  image back to an exact `CobolDec` (§14.9.25.4 GR5 — a de-editing MOVE) and raises EC-DATA-INCOMPATIBLE
  (§14.6.13.2 rule 4, new checking flag + fatal ambient gate) on content no editing could produce.
- **Dispatch** (D-EF5): the form dispatch lives in `RuntimeApi.EditFormatFor` / `EditTryFormatFloat` /
  `EditComposeFloat` and `NumericRenderer`'s FieldNum float arm — never at a call site; MOVE (numeric,
  alphanumeric, edited and float senders), ACCEPT / DISPLAY / STRING, arithmetic GIVING / COMPUTE (ON SIZE ERROR
  both directions; without it the MOVE disposition), VALUE (`ValueInitializer.EditedImageOfNumericValue` — the
  ONE compose the level-88 membership test shares, see [[PB97]]), HIGHEST/LOWEST-ALGEBRAIC (`IntrinsicBinder`:
  the all-nines significand at the maximum exponent, negative for LOWEST of a signed picture, zero for LOWEST of
  an unsigned one — §15.43.4 / §15.58.4 r2 — and COBOLNET1660 when the extreme would fail IN-ARITHMETIC-RANGE
  in the arithmetic mode in effect, §15.43.4 r1 / §15.58.4 r1 / §8.8.4.4.4 GR3 l).
- **VALUE** (§13.18.63.3 SR6): a floating-point literal, ZERO, or the integer / decimal literal zero
  (COBOLNET1659 for a nonzero fixed-point literal — the descriptor covers both directions of the form rule, the
  reverse landing with [[PB97]]); the literal must fit the significand and the exponent range (COBOLNET1625,
  "no truncation of digits or sign"; a negative literal needs the significand's sign symbol, SR3).
- **DECIMAL-POINT IS COMMA**: the picture's point is the comma and the period is the grouping insertion; the
  floating-point LITERAL's comma-decimal twin (`1,5E+3`) is [[PB98]].
