## Finding — `string-statement` (under-rejects; rows `SR-14.9.43.3-3`)

**Mechanism.** M3 - no zero-length-literal screen on STRING's literal-2; the runtime kernel quietly treats a zero-length delimiter as DELIMITED BY SIZE

**Repro.** 01 OUT1 PIC X(10) VALUE SPACES.  STRING "AB,CD" DELIMITED BY "" INTO OUT1  (probe sr3.cob, pinned cobol.exe --std 2023 --run)

**Expected from the spec.** §14.9.43.3 SR3: "Literal-2 shall not be a zero-length literal." §8.3.3.1 defines one: "If the opening and closing delimiters are contiguous, the length of the literal is zero, and it is known as a zero-length literal." The expected result is a compile-time rejection.

**Observed / reasoning.** The program compiles without errors and prints [AB,CD     ]. BindString binds the DELIMITED BY literal through StrUnstrOperand and screens it only for SR1 and SR2. CobolStringOps.StringTransfer's `delimiter is { Length: > 0 }` test then turns it into SIZE, which is the GR3 c) behavior for a zero-length IDENTIFIER-2, not a license for a zero-length literal-2. The same source also compiles at --std 85, where "" is not a legal literal at all. That is a separate lexical question and belongs to the literal owner. Sibling: UNSTRING's DELIMITED BY literal (§14.9.48.3) should be checked for the same missing screen.

**Code site.** src/Cobol.Net.Compiler/Binding/Procedure/Verbs/StringUnstringBinder.cs#StringUnstringBinder.BindString (the delimiter arm, after the SR2 screen)

## Finding — `unstring-statement-p1` (under-rejects; rows `SR-14.9.48.3-1`)

**Mechanism.** UNSTRING DELIMITED BY literal-1/literal-2 is never screened: BindUnstring's per-delimiter check (UnstringSenderCategory) only reads FIELD and intrinsic operands, so a numeric, boolean or zero-length literal passes, and a BoundAllLiteral is folded into the ALL phrase even when the ALL phrase was already written (STRING's twin has Sr1Offence + a BeginsWithAll screen; the UNSTRING arm has neither)

**Repro.** 01 S PIC X(12) VALUE "AB,CD5EF". 01 A PIC X(4). 01 B PIC X(4). 01 C PIC X(4).  UNSTRING S DELIMITED BY 5 INTO A B C.  (also: DELIMITED BY B"1"; DELIMITED BY ""; DELIMITED BY ALL ALL ","; OR ALL ALL ","; ALL ALL SPACES) — pinned cobol.exe --std 85/2002/2014/2023: every form compiles clean and runs (the numeric one splits on '5': A=[AB,C] B=[EF  ]; the zero-length one leaves all three receivers spaces)

**Expected from the spec.** Each is a compile-time rejection: §14.9.48.3 1) "Literal-1 and literal-2 shall be literals of the category alphanumeric or national and shall be neither a figurative constant that begins with the word ALL nor a zero-length literal." A numeric literal and a boolean literal are not of category alphanumeric/national; `ALL ALL ","` is the ALL phrase followed by a literal-1 that is a figurative beginning with ALL; "" is a zero-length literal.

**Observed / reasoning.** BindUnstring: `if (UnstringSenderCategory(v) is { } badDelim) return Reject(...)` — UnstringSenderCategory matches only BoundFieldOperand and BoundComputedOperand{BoundIntrinsicCall}; BoundNumericLiteral / BoundStringLiteral (boolean or zero-length) fall to `_ => null`. Then `if (v is BoundAllLiteral allLit) { v = new BoundStringLiteral(allLit.Literal) ...; all = true; }` runs regardless of item.ALL() already being set. The legal forms (alnum, hex, national literals; SPACE/ZERO with and without the ALL phrase) verified correct. Sibling: kb/Work PB863 (open, literal-category erasure); the zero-length "" is also accepted at --std 85/2002 where it is not a literal at all (lexer-level sibling to sweep).

**Code site.** src/Cobol.Net.Compiler/Binding/Procedure/Verbs/StringUnstringBinder.cs#BindUnstring (delimiter loop); src/Cobol.Net.Compiler/Binding/Procedure/Verbs/StringUnstringBinder.cs#UnstringSenderCategory

## What the fixer owes

One delimiter-literal screen shared by BindString and BindUnstring (StringUnstringBinder.cs): category (needs PB863's literal category, which BoundStringLiteral erases — coordinate), zero length, and ALL-figurative (PB1180's bound shape); UNSTRING's `if (v is BoundAllLiteral) { all = true }` must refuse when item.ALL() was already written. The '' accepted at --std 85/2002 is PB895's lexical question. Negatives sr3.cob and the UNSTRING forms (DELIMITED BY 5 / B"1" / "" / ALL ALL ",").
