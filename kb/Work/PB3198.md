## Landed (wave 1098 group C)

Re-probed on the branch's base (494246263) with the pinned hook, attended (COBOL_COORD_DIR unset): after a
`cat > msg.txt <<'EOF' … EOF` heredoc, `git stash`, `git push origin main` and `dotnet test --filter "~Foo" > log.txt`
each exited 0 (2 alone); `python -c "print(1<<2)"; printf "a\n"` and `git commit -m "never git stash"` exited 2
(false blocks). The note's `worktree_rm_allow.py` CHAIN regex was already gone (PB2599); its second splitter was
`shlex.split` on the step text.

The model the note asked for already existed: `scripts/hooks/shell_location.py` (PB2599, PB3095) was the parser rules
5-7 read. It became the ONE model rather than a new `shell_line.py` beside it (a second model would be the duplication
this note is about):
- `Step.text` / `Step.words` no longer carry heredoc bodies; `Step.heredocs` holds them, each cut at its own delimiter
  line (two heredocs on a line, `<<-`, `\EOF`, CRLF, no delimiter = to the end, as Bash reads it). A `<<` inside quotes,
  a here-string `<<<` and an arithmetic `1<<2` are no heredoc; a heredoc inside `( … )` is skipped whole, so an
  apostrophe in its body no longer opens a quote that swallowed the rest of the line.
- `git_calls(step)` reads every `git` invocation (any position: `FOO=1 git`, `& git`, `xargs git`): global options
  (`-C`, `-c`, `--git-dir=`, `--no-pager` …), the `-C` directory, the subcommand and its words. `git_dir` uses it.
- `forbidden_commands.py`: rules 1-7 read ONE `STEPS` / `GIT_CALLS`; the text-before-the-first-`<<`, the quote blanking,
  `_SHELL_PAYLOAD`, `_PUSH` and `_without_heredoc_bodies` are deleted. Rule 2 judges each push in its own directory
  (a `cd` to another repo elsewhere in the line no longer exempts a push to this one) and reads `+main`; rule 1 reads
  `-c <x>.autostash=…`; rule 3 scans only the bodies; rule 4 checks each `dotnet test` command's own `--filter`
  (`--filter=` too) and its own redirection or pipe reader.
- `worktree_rm_allow.py`: git's argv is `Step.words` (`shlex` deleted); a heredoc-fed call and a drive-relative path
  (`E:x`, what Bash makes of an unquoted `E:\x`) get no decision.
- Siblings fixed by the model with no edit of their own: `fleet_active_build.py` (`is_build_command(step.text)`) and
  `status_guard.py` (`COMMIT.search(s.text)`) no longer read a heredoc body as a build or a commit.

Finished by wave 1101 group A (the w1098c branch cherry-picked onto fda09da03, then):
- A heredoc a shell reads as its SCRIPT is walked as the command line it is (`shell_location._shell_child`,
  `_reads_stdin_script`): `bash <<'EOF'`, `bash -s args`, `sh -e -o pipefail`, `pwsh -Command -` / `-File -`; a
  heredoc fed to a script operand (`bash run.sh <<EOF`, `pwsh -File x.ps1`) stays that script's data. Before it,
  `bash <<'EOF'` + `git stash` + `EOF` passed every rule (the w1098c lead).
- `worktree_rm_allow.decide` reads its git invocation through `shell_location.git_calls` (its private `-C` parse
  deleted): only `-C` global options, applied in order as git applies them; `-c`, `--work-tree` and the like get no
  decision.

Self-tests: `test_forbidden_commands.py` 160 (every rule after a heredoc and after a quoted `<<`, inside a shell-read
heredoc; the PB1725/PB1736 repros), `test_shell_location.py` 99, `test_worktree_rm_allow.py` 56. 17 of the w1098c
forbidden_commands cases fail on the old hook.

For the next implementer:
- `scripts/hooks/shell_location.py#steps` owns the command line (steps, cwd, heredoc bodies, payloads); `#git_calls`
  owns every git invocation. A new guard rule READS these; it never scans `command` text. Trap: an unquoted Windows
  path in Bash loses its backslashes (`E:\x` is `E:x`, drive-relative), so self-test cases spell paths `as_posix()`.
- `scripts/hooks/forbidden_commands.py` rules 1-7 iterate `STEPS` / `GIT_CALLS`; add a rule's after-heredoc and
  quoted-`<<` cases to `test_forbidden_commands.py` (the `HD` / `QS` prefixes).
- `scripts/hooks/worktree_rm_allow.py#decide` grants only a depth-0 step that IS one `git_calls` call with `-C`-only
  options; any doubt is no decision.
- The hooks' Python is not in `scripts/arch/member_index.py`'s index, so a planner's computed file set misses
  `shell_location.py`: declare it by hand when a wave moves a hook rule.
