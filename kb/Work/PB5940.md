# PB5940 - the default listing is not written beside an assembly whose directory the failed compilation never made

**Found** by listing step 8 (w20262104i), compiling NIST `NC101A` without `--nist` into a new directory:

```
cobol NC101A.cob -o out/NC101A.dll --std 85
NC101A.cob(403,7): error COBOL2616: ...
cannot write the listing 'out/NC101A.lst': Could not find a part of the path '...\out\NC101A.lst'.
```

**Mechanism.** The listing's default base is the output assembly's path without its extension (DESIGN-listing.md section 8;
`ListingWriter.Write`). The directory of the assembly is created by the backend (`RoslynBackend.Emit`'s `Directory.CreateDirectory`),
which a compilation that fails in the front end or the bind never reaches, so `ListingWriter.Write`'s `File.WriteAllText` meets a
missing directory and reports one error (the design's refused-write rule, section 4.6). At `--std 85` a listing is required of
every compilation (§1985:IV.7.1, PB5923), and section 4.3 says a listing is produced on every outcome once the source was read,
which is when it is most read.

**Not the same as the refused write.** `ListingOutcomeTests.ARefusedListingWrite_IsOneError_AndChangesNoOutcome` pins an
EXPLICIT `--listing-output` into a missing directory as a refused write, and that stays right: the user named the place. The
default place is the compilation's own output directory, which the compilation creates for the assembly when it gets that far.

**Sites:** `src/WiseOwl.Cobol.Compiler/CompilerDriver.cs` (`CompilerDriver.Compile`), `src/WiseOwl.Cobol.Compiler/Listing/ListingWriter.cs` (`ListingWriter.Write`), `tests/WiseOwl.Cobol.Tests.Conformance/Listing/ListingOutcomeTests.cs` (`ListingOutcomeTests`)

**Fix direction (not built here, a decision of its own).** The listing is misleading in its absence: the one output a failed
compilation is read for is replaced by an error about a directory. The compilation owns the output directory: the one exit
(`CompilerDriver.Compile`) creates the directory of the DEFAULT listing base before `ListingWriter.Write`, as the backend does for
the assembly, keeping an explicit `--listing-output` a refused write. The test: a front-end error with `-o` into a new directory
lists the source.
