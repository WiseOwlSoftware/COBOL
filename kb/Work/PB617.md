# PB617 — OPEN — the additive walk sees items, not literals

Found 2026-09-05 by the `PB248` implementer (report §"New defects" B), which fixed the float-ITEM and E-form-
LITERAL arms of the integer-argument screen and measured this shape as a different missing capability;
re-derived on this tree for this note.

## Repro (`--std 2023`)

```cobol
           DISPLAY FUNCTION CHAR(1.5 + 1)      *> compiles clean; 2.5 reaches the runtime
           DISPLAY FUNCTION CHAR(1.5)          *> COBOLNET1627 (PB248)
```

## The rule

§15.3's integer-argument definition (type 6, `cite.py --check 15.3 "an arithmetic expression that will always
result in an integer value"` — run first): `1.5 + 1` is an arithmetic expression whose value is 2.5, never an
integer; §15.15.3 r1 makes CHAR's argument an integer. The screen at bind must reject it or, where the
expression's value is not static, the runtime must apply §15.3 rule 14's EC-ARGUMENT-FUNCTION posture (PB383's
substituted-result table) — but a literal-only expression IS static.

## The mechanism

`IntrinsicArgumentRules.CollectAdditive` (PB248's always-integral expression walk) accumulates data items and
tests their descriptions through `PicInfo.IsIntegerDescription`; a `BoundNumLiteral` operand has no arm, so a
literal's fraction contributes nothing and `1.5 + 1` is classified integral. The bare-literal path goes through
`HasNonIntegralValue` (on `NumericLiteral.TryParseExact`) and rejects; the expression path never reaches it.

## Fix shape

Fold the additive spine's literals: an arm in `CollectAdditive` that feeds each `BoundNumLiteral` through the
same `HasNonIntegralValue` test, and — the one-step-further case — a constant fold of a literal-only spine
(`ConditionBinder.SoleNumLiteral`'s family) so `1.5 + 0.5` (= 2, integral) is admitted and `1.5 + 1` rejected
on VALUE, not on the presence of a fraction. Positive goldens for `CHAR(1.5 + 0.5)` and `CHAR(3 - 1)`, negatives
for `CHAR(1.5 + 1)` and `CHAR(F + 1)` where `F` is COMP-2 (the latter is PB248's arm — the control), all four
editions.
