# PB2999 — the Linux gate does not put itself on its host

**Found by:** the operator, 2026-10-11 ~09:58 PDT, finishing `worktree-wf_8f6c2cfa-5a7-1` (PB2917+PB2936). The Bash
tool is Git Bash; `bash scripts/linux-gate.sh --nice` (the command `.claude/skills/gate/SKILL.md` gives twice, and
MANDATORY-PRACTICES I8/L10 name) ran there: it cloned the worktree into `C:\Users\brent\linux-gate\wf_8f6c2cfa-5a7-1`,
built with the Windows SDK (`GenerateIfNewer.ps1` failed, MSB3073), and ended
`=== LINUX GATE: RED (failed or not run: corpus-fetch selftests unit characterization conformance guard selftests-built
build; HEAD 07c8ebb51) ===`. No Linux leg ran. The script's own header documents the real invocation
(`wsl -d Ubuntu --cd <worktree> -- bash -lc 'bash scripts/linux-gate.sh ...'`); nothing enforces it.

**Why it matters.** A RED that measured nothing costs a diagnosis and can be misattributed to the change (a lander
would eject a cluster for it); a host check makes it a one-line refusal. Sibling of the CI invariant (PB1957): the
local stand-in for a CI leg must be the CI leg or say it is not.

**Fix direction (owner 2026-10-11 ~10:05: "Why not simply require it to invoke using the proper host rather than
an after the fact check that the correct host was invoked").** The script PUTS ITSELF on its host: at the top of
`linux-gate.sh`, when `uname -s` is not `Linux`, it re-executes itself under WSL with the same arguments
(`wsl.exe -d Ubuntu --cd <this worktree> -- bash -lc 'bash scripts/linux-gate.sh <args>'`) and exits with that run's
status; under Linux it proceeds as today. So the bare command every skill and brief gives is correct from Git Bash,
PowerShell or WSL alike, and no caller has to know the invocation. The one refusal left is a machine with no WSL
distribution: `=== LINUX GATE: NOT RUN (no WSL distribution: ...) ===`, never RED. One entry point, no second wrapper
script (CLAUDE.md rule 4). Self-test: under a faked `uname` the script hands its exact arguments to the WSL launcher.
## Landed (operator, 2026-10-11; owner: "Do the linux-gate fix in this train too")

- `scripts/linux-gate.sh#run_on_linux`, before any argument is read: on a host whose `uname -s` is not `Linux` it runs
  `MSYS_NO_PATHCONV=1 wsl.exe -d Ubuntu --cd <this tree> --exec bash -lc 'bash scripts/linux-gate.sh "$@"' linux-gate
  <its arguments>` and exits with that status; with no `wsl.exe` it prints `=== LINUX GATE: NOT RUN (this host is
  <host>, not Linux, and has no WSL to run the gate on) ===` and exits 2. `--exec`, not `--`: measured, after `--`
  wsl.exe gave the command line to the distribution's default shell, which parsed it again and lost every argument
  (`[/bin/bash][]`); `--exec` delivered `[linux-gate][--legs][unit][--nice]`. `MSYS_NO_PATHCONV`: Git Bash rewrites a
  POSIX-looking argument for a Windows program (DEVLOG: `/mnt/e/...` became `C:/Program Files/Git/mnt/e/...`).
- Self-test `bash scripts/linux-gate.sh --self-test` (discovered by `self_tests.py`; stand-ins for `uname`, `wsl.exe`
  and `cygpath` are shell functions, so it runs the same on every host): 9 checks, GREEN under Git Bash and in WSL.
  Mutations, one line each, each RED: `--` for `--exec`; no `MSYS_NO_PATHCONV`; no Linux pass-through; every leg name
  accepted.
- Found on the first live run (I9): `--legs selftests` (the leg that always runs) reached the leg dispatch's
  unknown-name arm, which wrote "unknown leg" over the real self-tests result and reported the leg twice.
  `check_legs` now accepts only the selectable legs (unit, characterization, conformance, guard) before anything is
  cloned or built (`NOT RUN (bad arguments)`), and the dispatch's unreachable unknown-name arm and the verdict's
  `:unknown` arm are deleted.
- Every caller names the one command now: the four briefs and MANDATORY-PRACTICES I8/L10 gave the long `wsl -d
  Ubuntu --cd <worktree> -- bash -lc ...` form, the gate skill the bare one; all give `bash scripts/linux-gate.sh`
  at the worktree root from any shell. DESIGN-test-build-ci.md (the Linux gate) says so.
