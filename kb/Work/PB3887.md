# PB3887 — exponentiation-right-associative: Chained exponentiation A ** B ** C is evaluated right to left; ISO requires left to right

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S3) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\exponentiation-right-associative.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\exponentiation-right-associative\`.

## Summary

cobc 3.2 parses consecutive exponentiations right-associatively: `2 ** 3 ** 2` is computed as `2 ** (3 ** 2)` = 512.
ISO requires consecutive operations of the same hierarchical level to be executed from left to right, giving
`(2 ** 3) ** 2` = 64. The grammar rule for exponentiation is right-recursive, while the rules for the multiplicative and
additive operators are left-recursive. The program uses data items, so the result does not depend on constant folding.

## Minimal test case

Fixed reference format (cobc's default), 12 lines, `records/exponentiation-right-associative.cob`:

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. POWASSOC.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 A PIC 9 VALUE 2.
       01 B PIC 9 VALUE 3.
       01 C PIC 9 VALUE 2.
       01 R PIC 9(5).
       PROCEDURE DIVISION.
           COMPUTE R = A ** B ** C
           DISPLAY "R=" R
           STOP RUN.
```

## Expected result (per ISO)

ISO/IEC 1989:2023 8.8.1.2 rule 3 (checked): "When the sequence of execution is not specified by parentheses, the order
of execution of consecutive operations of the same hierarchical level is from left to right." The rules of 8.8.1.2
apply "regardless of the mode of arithmetic that is in effect" (checked). So `A ** B ** C` is `(A ** B) ** C` =
`8 ** 2` = 64.

Expected output: `R=00064`.

Edition: Annex E of the 2023 text lists no change to the order of evaluation; the 2009 committee draft that led to
ISO/IEC 1989:2014 (CD 1.2) carries rule 3 in the same words, numbered 8.8.1.1 3) in that text (corrected by the
refuter: 8.8.1.2 is the 2023 number). The requirement holds for `-std=cobol2014`.

Edition as recorded by the adjudicator: 2014. `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Our compiler (WiseOwl)

`cobol powassoc.cob --std 2014 --run` (WiseOwl, built from main 6ed90bd1c): `R=00064`, exit 0. It matches the ISO
expectation.

## Fix site (GnuCOBOL 3.2 source, read observationally)

- `cobc/parser.y`, nonterminal `exp_factor`: its first alternative is `exp_unary EXPONENTIATION exp_factor`
  (right-recursive), built with `cb_build_binary_op (..., '^', ...)`. The `exp` and `exp_term` rules for `+ - * /` are
  left-recursive. Making `exp_factor` left-recursive (`exp_factor EXPONENTIATION exp_unary`) gives left-to-right
  evaluation; the generated `cobc/parser.c` follows from it.

## Draft issue

**Title:** Chained exponentiation `A ** B ** C` is evaluated right to left; ISO requires left to right

**Body:**

Environment: GnuCOBOL 3.2.0 (Ubuntu gnucobol3 3.2-4build1), `cobc -std=cobol2014 -x`.

Program (fixed format):

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. POWASSOC.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 A PIC 9 VALUE 2.
       01 B PIC 9 VALUE 3.
       01 C PIC 9 VALUE 2.
       01 R PIC 9(5).
       PROCEDURE DIVISION.
           COMPUTE R = A ** B ** C
           DISPLAY "R=" R
           STOP RUN.
```

Steps: `cobc -std=cobol2014 -x powassoc.cob && ./powassoc`

Observed: `R=00512` (2 ** (3 ** 2)).

Expected: `R=00064` ((2 ** 3) ** 2). ISO/IEC 1989:2023 8.8.1.2 rule 3 (2014 carries the same rule): "When the sequence of execution is
not specified by parentheses, the order of execution of consecutive operations of the same hierarchical level is from
left to right."

Cause: in cobc/parser.y the rule `exp_factor: exp_unary EXPONENTIATION exp_factor` is right-recursive; the rules for
the other binary arithmetic operators are left-recursive.

cobc also disagrees with itself: the same `A ** B ** C` in a condition goes through `build_expr_reduce` in
cobc/typeck.c, which reduces equal priorities left to right. With A = 2, B = 3, C = 2, `IF A ** B ** C = 64` is true
and `IF A ** B ** C = 512` is false, while `COMPUTE R = A ** B ** C` in the same program stores 512 (output `COND:
LEFT TO RIGHT (64)` then `COMPUTE R=00512`).
