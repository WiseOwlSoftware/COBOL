## Finding — turn-directive (silent)

The activated-program half of EC-PROGRAM-ARG-MISMATCH (§14.9.4.4 GR3 d) is folded against the >>TURN state at the ENVIRONMENT/DATA division line (BinderDriver divLine), borrowing §14.8.4.1's EC-EXTERNAL-only 'before the Environment division' rule, so a TURN written after that line but before the PROCEDURE DIVISION header does not enable checking for the header, contrary to §7.3.25.4 GR6/GR8 which scope TURN to 'procedure division statements and procedure division headers that follow'.

**Rows:** GR-7.3.25.4-6

**Repro:**

```
>>TURN EC-PROGRAM-ARG-MISMATCH CHECKING ON / caller CALL P USING A A ON EXCEPTION DISPLAY "EXC [" FUNCTION EXCEPTION-STATUS "]" NOT ON EXCEPTION DISPLAY "OK" END-CALL; callee in the same group: >>TURN EC-ALL CHECKING OFF before its IDENTIFICATION DIVISION, LINKAGE SECTION 01 X PIC X(4), then '>>TURN EC-PROGRAM-ARG-MISMATCH CHECKING ON' on the line before 'PROCEDURE DIVISION USING X.'
```

**Expected from the spec:** The callee's procedure division header follows an enabling TURN, so checking is enabled for it (GR6); the caller also enables it; §14.9.4.4 GR3 d then sets EC-PROGRAM-ARG-MISMATCH and the call is unsuccessful -> 'EXC [EC-PROGRAM-ARG-MISMATCH]', the same as when the callee's TURN precedes its IDENTIFICATION DIVISION (control TRNH3).

**Observed:** TRNH1 prints 'IN SUB' / 'OK'; control TRNH3 prints 'EXC [EC-PROGRAM-ARG-MISMATCH]'. BinderDriver: divLine = environmentDivision ?? dataDivision ?? procedureDivision; ArgMismatchChecking = Turn.Enabled("EC-PROGRAM-ARG-MISMATCH", null, divLine). The EC-EXTERNAL mask legitimately uses that line (§14.8.4.1); ARG-MISMATCH should fold at the procedure division header line. Sweep other header-associated checks for the same borrowed line.

**Code site:** src/Cobol.Net.Compiler/Binding/BinderDriver.cs (data.ArgMismatchChecking = session.Turn.Enabled(..., divLine))
