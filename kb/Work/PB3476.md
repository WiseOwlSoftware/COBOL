# PB3476 — a report with no HEAD sha holds a CLEAN branch out of the landing lane

**Sites:** `scripts/orchestrator/plan_wave.py` (`Report`, the HEAD read), `scripts/prune_worktrees.py` (`lifecycle`), and their self-tests.

> flags: process-only · silent

## What happened

`w1136c-PB3471-report.md` (implementer DONE, branch `worktree-wf_722bb28c-219-2`) wrote its header as
`**HEAD:** see the trailing commit (code at `ac4f3be8c`)`. The branch reviewer then stamped
`**Review:** CLEAN w1136c-review-r1 bf1cfafc7…`, and `bf1cfafc7` IS the branch tip.

`plan_wave.Report` parsed no HEAD (`head = None`), so `prune_worktrees.lifecycle` took the `uncovered` arm ("the
report names no HEAD, so it describes no commit of the branch"): IN FLIGHT while the branch was touched in the last
`--min-age` (180) minutes, DECISION after. It never reached `landing_state`, so the landing lane never saw a
WAITING TO LAND row, and plan_wave held PB3337, PB3460, PB1278, PB3338 and PB3340 behind it on a file-set collision
(`docs/rearchitecture/DESIGN-runtime-library.md`). Both wave-1137 units planned 0 groups.

Wave unit 1137 wrote the tip sha into the report's HEAD field by hand; the survey then read
`WAITING TO LAND … Review CLEAN at bf1cfafc7981`.

## The defect

Two gaps, both silent:

1. **Nothing refuses a finished report without a HEAD sha.** The implementer template asks for one, but neither the
   rolling wave's finished test nor the reviewer's stamp step checks that the header parses to a commit, so a
   malformed header passes review and is discovered only by a planner that plans nothing.
2. **The lifecycle ignores the stronger evidence it already has.** A review stamp whose sha equals the tip
   (`rv.covers(row.tip)`) proves the reviewed content is the tip, whatever the report's HEAD says. `uncovered` is
   checked before the review stamp is consulted.

## Fix direction

Make the report header a checked contract at the point it is written: the wave's finished test (or the reviewer's
stamp step, `review_findings.py`) refuses a DONE report whose HEAD is not a commit of the branch, and sends it back
to the implementer/finisher. Decide in the design (`docs/rearchitecture/DESIGN-orchestrator-loop.md`) whether a
review stamp at the tip should also cover a report with no HEAD; one owner of "what commit does this report
describe" either way, with a drift test over both readers (`plan_wave.Report`, `prune_worktrees.lifecycle`).

**Recurrence 2026-10-21 (branch `worktree-wf_36fbfc86-472-20`).** The implementer's report gave no HEAD sha, so the branch, reviewed CLEAN at 463538ba2, sat IN FLIGHT until the sha was put in by hand.

## Landed (2026-10-24, wave 20261031 group B)

Re-probed: `plan_wave.parse_report` on a w1136c-shaped header (`**HEAD:** see the trailing commit`, a CLEAN stamp at the tip)
returned `head = None`, and the survey fixture `no-head` (DONE, CLEAN at the tip, no sha in HEAD) read DECISION "names no
HEAD", outside the landing lane. Decided in the design (DESIGN-orchestrator-loop.md, the survey's three coverages): **a
review stamp is the stronger statement of what commit a report covers**. The reviewer stamps the head it reviewed
(`review_findings.py stamp` writes it), so `parse_report` now takes the report's described commit from the header's HEAD
field and, when that field gives no sha, from its review stamp. That is the ONE owner of "what commit does this report
describe": the branch survey (`report_index` copies `Report.head`), the landing lane, `landing_measure` and `gate_state`
all read it. A report with neither a HEAD sha nor a stamp still describes no commit (`no-head-bare`: DECISION, said so);
a report with a sha keeps it whatever the stamp says. No refusal at the stamp step: with the stamp as the anchor a
head-less DONE report is stampable and covered, and a refusal would cost a finisher cycle for a case the system now
reads correctly. The recurrence (2026-10-21, `worktree-wf_36fbfc86-472-20`) is the same shape.

Tests: `prune_worktrees.py --self-test` (`no-head` now WAITING TO LAND, new `no-head-bare` DECISION), `test_plan_wave.py`
(`head_of`: stamp-only, sha-wins, neither). Siblings: every reader of `Report.head` goes through `parse_report` (the one
`header_sha(HEAD, ...)` site); `Report.finished`'s DISCHARGED arm and `gate_state` read the same field.
