# PB700 — OPEN — a known residue, named

Found 2026-09-05 by the `PB352`/`PB354` implementer (report §"New defects" c), while adding the sort-file screen START
had been missing: UNLOCK is the one verb that keeps its own copy. Both arms reject, so no program is miscompiled;
the cost is the usual one — two spellings of one rule, and the next sweep re-finding it.

## The facts

`cite.py --check 14.9.47.3 "sort"` → OK 1): UNLOCK's clause states the sort-file ban in its own words, which is
why the inline screen cites a different § and emits a different code from `ScreenSortMergeFile`'s. PB140's doc
comment on `ScreenSortMergeFile` already calls the old posture "a patchwork … a bind error at UNLOCK" — a deliberate
residue.

## Fix

Route `BindUnlock` through `ScreenSortMergeFile` with the verb name, and let the screen carry BOTH citations where
a verb's own clause restates the rule (a `verbClause` argument, so the message can name §14.9.47.3 SR1 for UNLOCK
and §13.4.6.3 for the rest) — one implementation, one code, the negative golden for UNLOCK on an SD re-trued to
COBOLNET1692 if the code changes (check whether any golden pins COBOLNET1512 first). Small; pairs naturally with
PB699's move of the entry rules.
