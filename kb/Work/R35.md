# R35 — a REPOSITORY-declared ZERO-ARGUMENT user-defined function referenced keyword-omitted falls to the data path: the bare-name arm admits only catalogued intrinsics

> Found by the R21+R22+R30 battery's differential leg (2026-08-08): flips `run_functions:4457`
> ("User-Defined FUNCTION with/without parameter") and `listings:2598`, AGREE_ACCEPT →
> WE_REJECT_THEY_ACCEPT carrying COBOLNET1639 "'WITHOUTPAR' is not defined".

§8.4.3.2.3 SR2 permits omitting the word FUNCTION for a REPOSITORY-declared USER function exactly as for
a declared intrinsic. `IntrinsicBinder.KeywordOmittedFunction`'s bare-name arm (PB7's fix) reads "a bare
name only becomes a function reference when the function genuinely admits ZERO arguments" and answers
that question ONLY from the intrinsic catalog (`!catalogued || sig.MinArgs != 0 → null`) — a
REPOSITORY-declared zero-argument UDF is `declaredFn` but not catalogued, falls through to the data
reference path, resolves to nothing, and since R30 draws COBOLNET1639 (before R30 it compiled clean and
threw at run time — the wrong-stage family again). The argument-list form `WITHOUTPAR(…)` binds fine;
only the BARE zero-argument form is lost.

FIX SHAPE: the bare-name arm asks the UDF side the same zero-arity question it asks the catalog —
host.Udf knows the prototype's formals. The two-arm-dispatch pattern yet again: PB7 fixed the
intrinsic arm of the bare-name form and the UDF arm was never asked.

## LANDED 2026-08-08

The bare-name arm routes a REPOSITORY-declared user-function name straight to `UdfBindCall(name, [])`,
whose prototype machinery owns BOTH verdicts: a zero-formal function binds (and the captured-ref-mod
shape rides `ResultRefMod` exactly as the intrinsic arm's does), and an N-formal function draws its own
COBOLNET1506 arity error — the honest diagnosis, because the user DECLARED the name a function, so
there is no coincidental-collision reading for the data path to protect (the catalogued-name arm keeps
that protection: a bare collision with, say, SQRT stays an ordinary unresolved name). Probes:
`MOVE WITHOUTPAR TO X` runs and prints 0042 (compile-clean death before); `MOVE TWOPAR TO X` draws
"takes 2 argument(s)". Goldens: positive `udf_bare_zero_arg` (2002) + negative `udf-bare-arity`
(reject-at 2002 2014 2023). The differential's run_functions:4457 and listings:2598 flip back at the
next battery. Gate: Udf|Corpus 555/555 · both by name · characterization 33/33.
