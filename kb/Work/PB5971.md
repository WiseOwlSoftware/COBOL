# PB5971 - the move to .NET 11

**The owner's decision (2026-11-20, in chat): "Move to .NET 11".** .NET 11 is GA (SDK 11.0.100, runtime 11.0.0). The
repository, its CI and every host move from .NET 10 to it in one change.

## What moved

- `toolchain.env` and its copy in `scripts/cloud/setup-env.sh`: `DOTNET_SDK_VERSION=11.0.100`. `scripts/toolchain.py`'s guard
  needed no change: it derives the channel from the manifest's own major, so a later major is still a note for the owner.
- `global.json` 11.0.100 (`latestMinor`); `Directory.Build.props` `net11.0` (every project inherits it; the two
  `netstandard2.0` Roslyn components keep it).
- **C# 15** (owner, 2026-11-20: "We should also enable C#15 if that's the version with .NET 11"): `Directory.Build.props`
  `LangVersion` 14 to 15. The 11.0.100 SDK's compiler accepts 15 and refuses 16 (CS1617), so 15 is the newest released language
  version. The solution built at 15 with 0 warnings. The compiler's emitted programs already parse at `LanguageVersion.Latest`
  (`RoslynBackend`), so they needed no change. The docs that state the current language version say C# 15; a label naming the
  version a feature arrived in (the `field` keyword, extension members: C# 14) stays.
- `Directory.Packages.props`: `System.CommandLine` 2.0.9 to 3.0.0 (the .NET 11 train), `Microsoft.CodeAnalysis.CSharp` 4.14.0 and the
  census host's `Workspaces` packages to 5.12.0 (the Roslyn the 11.0.100 SDK ships), `PublicApiAnalyzers` 5.0.0 to 5.6.0 (the newest stable
  release at or below that Roslyn).
- **The target framework is written once** (CLAUDE.md rule 5). Every script that named `bin/<configuration>/net10.0/` now reads
  `Directory.Build.props`: `toolchain.target_framework()` (Python: `perf_baseline.py`, `differential_fuzz.py`, `gnucobol_differential.py`,
  `run_probe.py`, `spec/run_drafts.py`) and `guard_target_framework` in `scripts/guard-compiler.sh` (the guard, its witnesses and the version
  sweep; `guard-run-group.sh` lost its hard-coded default runtime path, which was a second copy). `battery.sh` drops its `--exe` literal.
  `scripts/toolchain_audit.py` (`tfm_offenders`) holds the props to the manifest's SDK major and names any script that spells another
  framework, so the next move is the props, `global.json` and the manifest, and the audit lists what is left.
- Docs, issue templates and skill templates that describe the current toolchain say .NET 11. Dated evidence, the DEVLOG, the pinned
  verdict records and measurements made on .NET 10 keep their text: they are history.
- The compiler's own output moves with the build: `AssemblyPackager` writes the `runtimeconfig.json` from `Environment.Version`, and it
  compiles against the targeting pack the SDK resolves, so a compiled program now runs on the 11.0 runtime.

## Hosts

CI installs 11.0.100 from `toolchain.env` (the install-tool step). The Windows host installs it with winget; WSL with
`scripts/wsl/setup-wsl.sh`; **the cloud environment's setup script changed again (the toolchain block) and must be pasted again.**
