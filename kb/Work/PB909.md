# PB909 — LANDED — the loud stage used as a parser's error handler

Sources: the `PB399` report's "three NON-ISO extensions" lead and the `PB412` report's "~80
`BoundUnsupported` sites are unaudited" lead. They are **ONE mechanism** and are filed as one note: the

A **warning** at compile time and a **crash** in production is the worst of both postures: it is not an
acceptance (the program does not work), it is not a rejection (the program ships), and nothing in the build
output stops a release.

## The rule

```
$ python scripts/spec/cite.py --check 4.2.2 "An implementation shall accept the syntax"
OK  §4.2.2   (Acceptance of standard language elements)
    An implementation shall accept the syntax and provide the functionality for all standard language
    elements required by this Working Draft International Standard …
```

§4.2.2 is the clause this project already stands COBOLNET2117-2120 and COBOLNET2172 on: a general-format
violation gets a COMPILE-TIME mechanism. Neither `REPLACING TRAILING` (not in §14.9.22.2 Format 2) nor
`NOT AT END` (not in §14.9.37.2) is printed by its statement's general format, so under the STRICT dialect
axis each is source to refuse at compile time — or to accept under a DOCUMENTED leniency
(`feedback_follow_gnucobol_on_split_latitude`). The present shape is neither, and that is the defect.

## The code site and the sweep

`grep -rn "new BoundUnsupported(" src/` — ~80 sites. They have never been sorted, and the sort is the work:

* **"unimplemented FEATURE"** — legal source this compiler has not built. A loud run-time stage is the
  honest posture (`COBOLNET_DESIGN §1.4`), but it should be an ERROR at compile time unless the owner has
  decided otherwise, not a warning.
* **"illegal SHAPE"** — source no general format prints. Every one of these is a §4.2.2 compile-time
  obligation and the `BoundUnsupported` is a bug.

Candidates visible from the message text alone, named by the PB412 report and confirmed by grep here:
`InspectBinder.cs:168` (REPLACING TRAILING), `SearchBinder.cs:82` and `:141` (NOT AT END, two arms —
Format 1 and Format 2 — and note `feedback_two_arm_dispatch`: fixing one is the failure mode),
`ArithmeticBinder` "MULTIPLY form" / "DIVIDE form", `CorrespondingBinder` "ADD statement form" /
"SUBTRACT statement form" / "… operand shape", `CallBinder` "CALL target form", `OoBinder` "SET
object-reference sender shape", `StatementBinder` `$"statement '{FirstToken(s)}'"`.

## Why the output of this is a STRUCTURE, not eighty edits

CLAUDE.md rule 5. The sort has to be recorded where it cannot rot: a required classification argument on
`BoundUnsupported` itself (`Unimplemented` vs `IllegalShape`), so a new site cannot be added without
answering the question, plus a drift test asserting that no `IllegalShape` site reaches code generation.
That makes the NEXT case automatic, which a hand list of eighty never will.

## Landed — 2026-09-22, wave 48 (T), worktree `wf_ffdefe6a-659-3`

**Re-probed first** on this worktree's own build (base `ec095d120`): both measurements above reproduced verbatim —
`INSPECT S REPLACING TRAILING` and `SEARCH E … NOT AT END` each drew `warning COBOLNET1756` and aborted with
`NotImplementedCobolFeatureException`. After: `error COBOLNET2269` at the statement, at 85/2002/2014/2023, no 1756.

**The split is two TYPES** (rule 5 — the shape the note asked for, one step further than a classification flag):
`BoundUnsupported` (a deferral, and nothing else) and the new `BoundRejected` (a refusal), whose constructor is
private and whose one factory `BoundRejected.Report(edition, descriptor, message)` records the error BEFORE it
returns and refuses a warning-severity descriptor — so a refusal cannot be silent, and since an error fails the
compile before code generation, `StatementEmitter.Visit(BoundRejected)` throws rather than emit. The third case the
note did not name is the one a SITE cannot classify — an operand the resolver returned null for is either REPORTED
or a shape the resolver has not built — and the funnel (`StatementBinder.BindStatement`) now classifies it: a
`BoundUnsupported` from a statement whose bind already drew an error is a refused statement and announces nothing
(`INSPECT S(1) …` on a non-table item used to draw COBOLNET2096 AND "not implemented"). That covers ~25
"unresolvable operand" sites with no per-site edit and makes the next one automatic.

**The sort of the 45 sites.** REFUSED (`BoundRejected`): INSPECT TALLYING FOR FIRST/TRAILING and REPLACING TRAILING
(§14.9.22.2), SEARCH and SEARCH ALL NOT AT END (§14.9.37.2 — one helper, both arms), ENTRY (no ISO statement) — all
COBOLNET2269 `statement-format-shape`, new; WRITE ADVANCING/END-OF-PAGE on a relative/indexed file (§14.9.51.3
SR3 — SR2's mirror, onto its existing COBOLNET1720); INITIATE/TERMINATE/GENERATE naming no report (§14.9.21.3 SR1,
§14.9.46.3 SR1, §14.9.16.3 SR1/SR2) and a table-SORT key under an inner OCCURS (§14.9.40.3 SR14 e — split from the
REDEFINES-view half, which stays a deferral) onto COBOLNET1757; and twelve grammar-unreachable defensive arms
(MULTIPLY/DIVIDE/COMPUTE/ADD/SUBTRACT/MOVE/CALL/SET/ALTER form) onto 2269, because "no general format prints this"
is true of them and "not implemented" is not. DEFERRED (kept): the three RAISING-identifier exception-object forms
(messages reworded to name the FORM, not the syntax rule), the Tier-C / REDEFINES-view / nested-dynamic sort and
search slices, the UNSTRING ref-mod reception size, the CALL argument classification residue, the catch-all
`statement '…'` arm, and the resolution-failure arms the funnel now classifies.

**Drift.** `BoundDeferralDriftTests` (Unit): a SCAN of every `new BoundUnsupported(` message for the vocabulary of
a violated rule (SR-number, "shall", "extension", "general format", "non-ISO") — asserting its population (45); the
private-constructor/one-factory invariant; each refused member at a GO TO-skipped site (error, code, no 1756); the
