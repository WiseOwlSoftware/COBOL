# PB909 — OPEN — the loud stage used as a parser's error handler

Sources: the `PB399` report's "three NON-ISO extensions" lead and the `PB412` report's "~80
`BoundUnsupported` sites are unaudited" lead. They are **ONE mechanism** and are filed as one note: the
PB412 lead is the sweep, the PB399 lead is three of its members with measurements attached.


`<scratch>/reg7/probe/w2_search_notatend.cob` (⚠ the grammar is
`searchAtEndClause : AT? END statementBlock (NOT AT? END statementBlock)?`, so the NOT branch requires an

A **warning** at compile time and a **crash** in production is the worst of both postures: it is not an
acceptance (the program does not work), it is not a rejection (the program ships), and nothing in the build
output stops a release.

## The rule

```
$ python scripts/spec/cite.py --check 4.2.2 "An implementation shall accept the syntax"
OK  §4.2.2   (Acceptance of standard language elements)
    An implementation shall accept the syntax and provide the functionality for all standard language
    elements required by this Working Draft International Standard …
```

§4.2.2 is the clause this project already stands COBOLNET2117-2120 and COBOLNET2172 on: a general-format
violation gets a COMPILE-TIME mechanism. Neither `REPLACING TRAILING` (not in §14.9.22.2 Format 2) nor
`NOT AT END` (not in §14.9.37.2) is printed by its statement's general format, so under the STRICT dialect
axis each is source to refuse at compile time — or to accept under a DOCUMENTED leniency
(`feedback_follow_gnucobol_on_split_latitude`). The present shape is neither, and that is the defect.

That is exactly the verdict the lead asked for, and the wave-41 **PB412 + PB421 + PB402** group landed it.

## The code site and the sweep

`grep -rn "new BoundUnsupported(" src/` — ~80 sites. They have never been sorted, and the sort is the work:

* **"unimplemented FEATURE"** — legal source this compiler has not built. A loud run-time stage is the
  honest posture (`COBOLNET_DESIGN §1.4`), but it should be an ERROR at compile time unless the owner has
  decided otherwise, not a warning.
* **"illegal SHAPE"** — source no general format prints. Every one of these is a §4.2.2 compile-time
  obligation and the `BoundUnsupported` is a bug.

Candidates visible from the message text alone, named by the PB412 report and confirmed by grep here:
`InspectBinder.cs:168` (REPLACING TRAILING), `SearchBinder.cs:82` and `:141` (NOT AT END, two arms —
Format 1 and Format 2 — and note `feedback_two_arm_dispatch`: fixing one is the failure mode),
`ArithmeticBinder` "MULTIPLY form" / "DIVIDE form", `CorrespondingBinder` "ADD statement form" /
"SUBTRACT statement form" / "… operand shape", `CallBinder` "CALL target form", `OoBinder` "SET
object-reference sender shape", `StatementBinder` `$"statement '{FirstToken(s)}'"`.

## Why the output of this is a STRUCTURE, not eighty edits

CLAUDE.md rule 5. The sort has to be recorded where it cannot rot: a required classification argument on
`BoundUnsupported` itself (`Unimplemented` vs `IllegalShape`), so a new site cannot be added without
answering the question, plus a drift test asserting that no `IllegalShape` site reaches code generation.
That makes the NEXT case automatic, which a hand list of eighty never will.
