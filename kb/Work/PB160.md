### Adjudicator evidence — row `GR-8.3.3.5.4-5` (PARTIAL)

cite.py --check 8.3.3.5.4 "The implementor defines the result of specifying a hex-character-sequence-1 for which no corresponding character" -> OK (rule 5). Behaviour exists: DecodeHexGroups stores any 4-digit group verbatim as a UTF-16 code unit, so a group with no corresponding character (an unpaired surrogate, probe p1 LENGTH(NX"D800")=1) yields that code unit unchanged, no diagnostic, no exception. Half 2 (characters not a multiple of four bits) is vacuous: a UTF-16 unit is 16 bits. BUT the determination is undocumented: Annex A.1 item 97 (cite.py --check A.1 "Hexadecimal national literals (mapping for non-existing corresponding character)" -> OK - required, documented) and item 122 (digits per national character, SR5) have no DOC-A.1-97 / DOC-A.1-122 row in docs/CONFORMANCE.md §7 (grep: absent). Those DOC-A.1 inventory rows own the documentation obligation; this row is PARTIAL because the implementor's definition is implicit in code only and no test pins the non-existing-character result. (A.1 item 97's own parenthetical still says "General rule 4" - a renumbering residue in the spec; the rule is GR5 today.)
