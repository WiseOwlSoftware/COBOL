# PB4459 - OoMethodSymbol.Ctx is nullable by origin (BASE, property accessors, imported) and readers pass it to edition.At without asking the origin

**Sites:** `src/WiseOwl.Cobol.Compiler/Oo/OoMethodSymbol.cs:15` (`Ctx`, with the throwing `Definition` accessor), `src/WiseOwl.Cobol.Compiler/Oo/OoStandardClasses.cs:110`, `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.Oo.cs:960` and `src/WiseOwl.Cobol.Compiler/Binding/MetadataRepositoryProvider.cs:712` (all `Ctx: null`), reader `src/WiseOwl.Cobol.Compiler/Oo/OoConformance.cs:128` (`using (edition.At(impl.Ctx))`). Sites are at the head of branch `worktree-wf_d44be67f-63e-4` (PB2104, PR #1046); line numbers are that head's.

**State at the head.** The review found `Ctx` a non-null positional parameter that was null; the branch's round-1 checkpoint (82c85ae3d) already made it `MethodDefinitionContext?` and added `Definition`, so that part is done. What remains is the shape: a method's ORIGIN is still encoded as the nullness of `Ctx`, while `OoClassSymbol` carries an explicit `OoSymbolOrigin` and a throwing `Ctx`. The two symbol types disagree, and `edition.At(ParserRuleContext?)` accepts the null silently, so a diagnostic about an imported or BASE method (the conformance check at OoConformance.cs:128 runs over inherited and imported implementations) is reported with no position instead of failing or naming the source.

**Fix shape.** Give `OoMethodSymbol` the same `OoSymbolOrigin` as the class symbol, make `Ctx` follow the class symbol's throwing accessor (or split the record so a source method has a non-null definition), and have readers that report a position ask the origin; sweep the other `.Ctx` readers of method symbols. It shares its root with `OoClassSymbol` modelling origin separately from its `Ctx`.

**Landed (wave 20261840, group C).** `OoMethodSymbol` is no longer a positional record with a nullable `Ctx`: it has two constructors, one from a METHOD-ID definition (`Origin` = `Source`) and one from a non-`Source` `OoSymbolOrigin` (`Standard`, `Imported`, and the new `Generated` for a PROPERTY clause's accessor, ISO 13.18.42); `Ctx` throws on every origin but `Source`; the `Definition` accessor and the `Imported` flag are deleted. `OoClassSymbol` and `OoInterfaceSymbol` take the same two constructors, so a `Source` symbol without a definition cannot be built. The readers that tested `Ctx` for null (`CheckingFold.Method`, `DataBinder.Ptr`, the PROPERTY SR5 test in `DataBinder.Oo`, `FlagConformancePass`, `OoClassTable.MethodAt`) ask `Origin`. `OoConformance.ValidateImplements` was the one reader that positioned a diagnostic through a method found by INHERITS or by roster key: a nonconforming BASE `New` or a generated accessor printed COBOL0841 with no `file(line,col):`; it now stands at the implementing class's name, as the not-implemented error does. Witnesses: `OoClassTablePositionTests` (IMPLEMENTS-GENERATED-ACCESSOR, IMPLEMENTS-STANDARD-METHOD) and `OoMethodSymbolOriginTests`.
