# PB494

## Mechanism — synchronized-clause
sync-negative-witness-permissive-comment-stale - the shipped conformance witness for the SYNCHRONIZED-on-a-group edition gate documents the OPPOSITE of what the compiler does under --permissive. conformance-suite/cases/13.18.55-SYNCHRONIZED/sync_group_below_2023.cob's header reads 'Under --permissive it is accepted-inert (SYNC is a no-op) - a warning, not an error - preserving INV-1 continuity', while the shipped compiler raises COBOLNET0900 as a hard error with --permissive at 85, 2002 and 2014. The binder's own comment at DataBinder.cs:3311-3317 records the change and its reasoning (CA14, owner-approved option (a): --permissive is the migration mode for constructs an edition REMOVED and has no meaning for one the targeted edition has not yet acquired), so the code is right and the witness comment was left behind by that change set. A witness file's header is the first thing a maintainer reads when a gate moves; this one would send them to look for a regression that is not there.

### Expected, from the standard
Not a spec divergence - a doc-vs-code contradiction inside a conformance witness. The compiler's shipped behaviour (hard error on both axes) is the owner-approved one and matches SR1 read through Annex E.3.2 item 6: a construct the targeted edition has not yet acquired cannot appear in a legal pre-existing program, so the removed-construct migration mode does not reach it. The witness header shall say so.
