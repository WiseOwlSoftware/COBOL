**Scenario:** OccursChainOf (DataBinder.TableValue.cs:109-119) re-walks Parent, keeps IsTable levels and reverses - SubscriptLevels() line for line, then wraps each level in a TableValueDim. The drift test's regex (SubscriptAdmissionDriftTests.cs:110-111) only matches 'for (DataItem? v = ...; v is not null; v = v.Parent) if (v.IsTable)', so it passes while three copies stand: OccursChainOf spells the test 'if (!n.IsTable) continue;', ReferenceResolver.SubscriptLevelsWithin (ReferenceResolver.cs:1634-1641) spells IsTable out as 'n.Occurs is not null || n.IsDynamicTable', and the RENAMES SR3 screen (DataBinder.RenamesEntry.cs:45-46) declares 'var n'. The next change to what counts as a subscript level (made, as PB877 requires, in DataItem.cs) does not reach the VALUE FROM/TO count and ceiling screens (SR20/SR21) or the odometer fill, so a Format-2 VALUE would be screened and seeded against a dimension list that references to the same item no longer use - the guard that exists to prevent exactly that stays green
