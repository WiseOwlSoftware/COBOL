# PB226

## Landed (wave 56, 2026-09-23) — mostly discharged by PB976, one residue fixed

RE-PROBE on the wave's own build: the note's premise no longer held. kb/Work PB976 (`79b438d82`) routed the
ALPHABET literal phrase (literal-1/-2/-3) and the CLASS range (literal-5/-6) through ONE operand decoder,
`DataBinder.Switches.cs#LiteralPhraseOperand`, which refuses a zero-length literal under SR11 for both clauses
(`ALPHABET A4 IS ""` → COBOLNET1906; `CLASS C1 IS "A" THRU ""` → COBOLNET1671). Literal-4 / literal-9 keep
`TryClauseTextLiteral`. So the zero-length half was already complete at all seven literals.

The RESIDUE, measured: a symbolic-character name in an ALPHABET literal phrase (`SYMBOLIC CHARACTERS BEL IS 8
ALPHABET A1 IS "A" ALSO BEL`) was refused, but under the CLASS rule (`BEL is not a literal … SR14 b2`) — a real
clause answering a different question. It now draws SR11 by name (`BEL — an operand shall not be a
symbolic-character figurative constant (ISO §12.3.7.3 SR11)`), in either clause order: the paragraph's
symbolic-character names are read SYNTACTICALLY before any clause binds (the clauses are order-free; SYMBOLIC
CHARACTERS binds after the walk). In a CLASS range a symbolic-character name cannot be written at all — the
grammar admits only literals there, so it is refused at parse (generic COBOL0309) — see the wave-56 report's leads.
Witness: `ClassClauseForPhraseTests.ZeroLengthLiteral_IsSR11` (+PB226S1/S2). Row SR-12.3.7.3-11 PARTIAL → CONFORMS
by batch `w56e-PB226-sr11-literal-screens`.

**Rows:** `SR-12.3.7.3-11`

§12.3.7.3 SR11 screens only 2 of the 7 literals it names: the ONE `TryClauseTextLiteral` check is wired to LOCALE's literal-4 and ORDER TABLE's literal-9, so a symbolic-character figurative constant or a zero-length literal in an ALPHABET literal phrase (literal-1/-2/-3) or a CLASS literal range (literal-5/-6) is accepted with no diagnostic at any --std or strictness.

Rows: SR-12.3.7.3-11 (PARTIAL, state GAP; code-location DataBinder.Switches.cs#OrderTableBind; test-ref unit:StandardCompareTests.Literal9_ObeysSr10AndSr11).

WHAT THE ROW SAYS (reused): "kb/Work PB101 T7: literal-9's half — a symbolic-character figurative constant or a zero-length literal is refused (COBOLNET0898 citing SR11). Literal-1..6 (the ALPHABET / CLASS / SYMBOLIC operands) are the pre-existing binders' half of the same rule and are not re-verdicted here; PARTIAL records that this landing owns only literal-9."

CITATION, VALIDATED MECHANICALLY THIS SESSION (CLAUDE.md rule 1, not inherited):
  `python scripts/spec/cite.py --check 12.3.7.3 "shall specify neither a symbolic-character figurative constant nor a zero-length literal"` => OK §12.3.7.3 11): "Literal-1, literal-2, literal-3, literal-4, literal-5, literal-6, and literal-9 shall specify neither a symbolic-character figurative constant nor a zero-length literal."
  `--check 12.3.7.3 "shall be alphanumeric or national literals"` => OK §12.3.7.3 10): "Literal-4 and literal-9 shall be alphanumeric or national literals."
SR11 names SEVEN literals; SR10 names TWO. The shared helper implements both and is called at SR10's arity.

WHICH CLAUSE OWNS WHICH LITERAL (read from the §12.3.7.2 general-format figures in specs/ISO_COBOL.md, incl. the repaired figure notes): literal-1 [THROUGH|THRU literal-2] [ALSO literal-3]… is the ALPHABET clause's literal phrase; `{ literal-5 [{THROUGH|THRU} literal-6] }` is the CLASS clause's range; literal-4 is LOCALE; literal-9 is ORDER TABLE. This REFINES the row's parenthetical "literal-1..6 (the ALPHABET / CLASS / SYMBOLIC operands)" in two ways: literal-4 IS already screened (LocaleBind:655), and SYMBOLIC CHARACTERS takes integer operands, not literals. The true residue is exactly FIVE operands across TWO clauses — literal-1/-2/-3 (AlphabetBind) and literal-5/-6 (SwitchBindClass).

MECHANISM, LOCATED: see the mechanism field — `TryClauseTextLiteral` (:683) with SR11's halves at :689 and :726–730; two call sites only (:655, :743); AlphabetBind (:774) and SwitchBindClass (:1145) unscreened.

WHAT IT DOES: illegal source is accepted with no diagnostic at any --std or strictness — `ALPHABET A IS ALL "X"`-style symbolic-character figurative operands and zero-length literals in an ALPHABET literal phrase or a CLASS range bind into a collating sequence / class membership set the standard forbids them to form. Under-reject, not a wrong answer proven; the downstream value effect is unmeasured and should be measured when the screen lands.

WHAT WOULD CLOSE IT: route AlphabetBind's literal-1/-2/-3 operands and SwitchBindClass's literal-5/-6 operands through the SAME `TryClauseTextLiteral` — SR11 half unconditionally, SR10 half NOT applied (SR10 names only literal-4/-9), which means splitting the helper's two rules so each is applied at its own arity rather than adding a fifth caller to a conflated one; plus a negative fixture per clause and a drift guard so a new SPECIAL-NAMES literal operand cannot land unscreened. Prefer the split that makes the NEXT literal automatic (CLAUDE.md rule 5).

## Mechanism

src/Cobol.Net.Compiler/Binding/DataBinder.Switches.cs#TryClauseTextLiteral (:683) — documented in its own summary as "The ONE rule for a SPECIAL-NAMES clause's TEXT literal (ISO §12.3.7.3 SR10 … SR11 …)". Its two SR11 halves are :689 (`nn?.figurativeConstant() is not null` → COBOLNET0898, "SR11's FIRST half, reported before SR10") and :726–730 ("SR11's SECOND half", the zero-length literal). MEASURED: exactly TWO call sites exist in the whole tree (`grep -rn TryClauseTextLiteral src/ --include=*.cs`) — `LocaleBind` at :655 (literal-4, comment: "SR10 / SR11 for literal-4 — the ONE text-literal rule the ORDER TABLE clause's literal-9 shares") and `OrderTableBind` at :743 (literal-9). `AlphabetBind` (:774, and its national twins :940/:987) and `SwitchBindClass` (:1145) — the binders that consume literal-1/-2/-3 and literal-5/-6 — never call it and carry no equivalent check (no `figurativeConstant` / zero-length test anywhere in either). THE ROOT SHAPE: the helper carries TWO rules of DIFFERENT ARITY behind one name — SR10 legitimately names only literal-4 and literal-9, SR11 names seven literals — and it is applied at the arity of the narrower rule, which is exactly why the under-reach was never visible.
