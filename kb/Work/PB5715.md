# PB5715 - at --std 2002 an EXIT PROGRAM or EXIT FUNCTION executed within the range of a GLOBAL declarative of the same element never raises EC-FLOW-GLOBAL-EXIT, which 2002 GR2 sets (fatal), so the run unit continues

**Sites:**
- src/WiseOwl.Cobol.Runtime/Exceptions/ExceptionState.cs#FlowGlobalGobackChecking (no EC-FLOW-GLOBAL-EXIT twin)
- `src/WiseOwl.Cobol.Compiler/CodeGen/EcEmitter.cs` (whole: gate table, line ~526)
- docs/conformance/3/D-GLOBAL-EXIT.md

**Mechanism.** docs/conformance/3/D-GLOBAL-EXIT.md determines that EC-FLOW-GLOBAL-EXIT is never set because 2023 has no rule that sets it; it is applied at every edition. ExceptionState has no twin of FlowGlobalGobackChecking for it, and EcEmitter's gate table lists only EC-FLOW-GLOBAL-GOBACK. 2002 has the setting rule.

**Inventory.** Rows claimed: `2002-GR-14.8.13.3-2`, `2002-GR-14.8.17.3-3`.

**Rules (each citation checked with `python scripts/spec/cite.py --check`).**

- `§2002:14.8.13.3 GR2`: "the EC-FLOW-GLOBAL-EXIT exception condition is set to exist" (`cite.py --check`: OK  §2002:14.8.13.3 GR2  (General rules)  the text is in GR2)
