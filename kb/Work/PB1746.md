# PB1746 — the counter registers' width under GnuCOBOL

## The question

§8.4.3.15.4 GR1 (`cite.py --check 8.4.3.15.4 "temporary"` → OK §8.4.3.15.4 1)): "PAGE-COUNTER and LINE-COUNTER
reference temporary unsigned integer data items of class and category numeric, which are maintained for each report."
The standard gives no size and no usage. kb/Work R26 set the capacity (LINAGE-COUNTER: the page size's digits;
PAGE-/LINE-COUNTER: PIC 9(18)), and wave 73 group C (PB1153, PB1199, PB1318) made the implicit description
`PIC 9(d) USAGE DISPLAY` in every consumer, recorded in `docs/CONFORMANCE.md` beside R26's capacity.

Consequences the owner may not want: `DISPLAY PAGE-COUNTER` prints 18 digits (`000000000000000001`), and
`MOVE LINE-COUNTER TO` a PIC X(4) item stores the leftmost four digits, `0000`.

## What to do

With a local `cobc`, compile a report file with PAGE-COUNTER and LINE-COUNTER referenced in DISPLAY, MOVE to a
PIC X(4), STRING and FUNCTION LENGTH, and record GnuCOBOL's width for each. Where GnuCOBOL's width differs from 18,
the owner decides whether R26's capacity follows it (CLAUDE.md rule 1: the spec is silent, so GnuCOBOL decides the
latitude). Record the result in `docs/CONFORMANCE.md`'s counter-register entry.
