**Rule it breaks:** ISO §14.6.8.3 r2 (and the implementor-defined r1 conversion CobolFloat documents as the same): the algebraic value is converted to the float receiver per ISO/IEC 60559; the method's own contract (CobolFloat.cs:27-36) is the CORRECTLY-ROUNDED double of unscaled x 10^-scale. Sibling agreement (dimensions.md 2): CobolNum.RescaleStoreCap (CobolNum.cs:432-436) and WrapBinary (265-277) document that the R10 bits contract delivers Int128.MinValue and guard it

**Scenario:** Line 40 (and 64) computes mag = -unscaled; Int128's unary minus is unchecked, so for Int128.MinValue mag stays -2^127 (verified on the pin's runtime), which passes 'mag <= 2^53'; (long)unscaled then keeps the low 64 bits of -2^127, which are 0, so the result is 0.0 (or 0f). -2^127 is a legal stored value: AlgebraicRange gives a signed 16-byte BinaryCapacity item its full container range (AlgebraicRange.cs:120-134), so LOWEST-ALGEBRAIC of it is -2^127 at the item's scale. Repro (not run on the pin): 01 S PIC S9(29)V99 COMP-5. 01 D COMP-2. MOVE FUNCTION LOWEST-ALGEBRAIC(S) TO S. COMPUTE D = S. DISPLAY D. Expected about -1.7014118346046923E+36; the scaled operand reaches CobolFloat.ScaledToDouble(Int128.MinValue, 2) through NumericRenderer.Real (NumericRenderer.cs:1191-1207) and D receives 0, silently. The same Int128.MinValue blind spot is the TryStore crash in lead runtime-values-2--code--f2#3: two siblings of RescaleStoreCap's guard were missed.
