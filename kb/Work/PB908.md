# PB908 — OPEN — the group-KIND set asked as "does it have a PICTURE"

Source: the `PB392` report, "New defects" item 1. Re-measured here.

## The measurement

`<scratch>/reg7/probe/d_inspect_bitgroup.cob`, `--std 2023`, `--run`:

```cobol
       01 BG GROUP-USAGE BIT.
          05 B1 PIC 1(4).
       01 TAL PIC 9(4) VALUE 0.
       PROCEDURE DIVISION.
           INSPECT BG TALLYING TAL FOR ALL "0"
```

```
TAL=0004
```

No diagnostic at any stage. The program runs, the BIT group is walked as if it were four alphanumeric
character positions, and the tally it produces is not a fact about anything the user wrote.

## The rule

```
$ python scripts/spec/cite.py --check 14.9.22.3 "alphanumeric or national group item"
OK  §14.9.22.3 1)  (Syntax rules)
    1) Identifier-1 shall reference either an alphanumeric or national group item or an elementary item
       described implicitly or explicitly as usage display or national.
```

SR1 names **two** admissible group kinds by name. A bit group, a strongly-typed group and a
variable-length group are all outside it, and each of them reaches this statement today.

## The code site

`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/InspectBinder.cs:98` — the screen is

```csharp
if (target.Item.Pic is { } tp …)
```

`Pic` is null for every group item, so the whole conditional is skipped for every group and SR1's group arm
is never asked. The comment beside it says as much.

## The fix shape, and why it is one call

`ItemCategory.GroupKindsOf` already exists and already answers the question the rule asks. The repair is one
call against `Alphanumeric | National` where the nullable-PICTURE test stands, in the SAME shape **PB392**
(landed) used to close CORRESPONDING's §14.9.25.3 SR6 arm — that note's title is the identical sentence:
"a rule naming a SET of four group KINDS and the screen was the boolean `IsGroup`". PB392's landing is the
precedent and the reason this is small; it is filed separately because it is a different statement, a
different clause and a different file.

## Rows

**`SR-14.9.22.3-1` is deliberately NOT claimed.** It is GAP and **PB856** (open) already claims it — PB856
owns the other arm of the same rule (INSPECT refusing a NATIONAL *elementary* operand while quoting SR2's
text that admits it). The two are one fill unit: SR1's group half is under-rejected here and SR1/SR2's
elementary half is over-rejected there, and one implementer should write the screen once. `cluster:` names
PB856 for exactly that reason.

## The sibling sweep

Every `.Pic is { }` / `.Pic is null` test in `src/Cobol.Net.Compiler/Binding/` that stands where a rule
names a group KIND. `grep -rn "Pic is {" src/Cobol.Net.Compiler/Binding/ | wc -l` is the population; the
question to ask at each is whether the rule behind it says "elementary" (in which case the test is right)
or names group kinds (in which case it is this defect).
