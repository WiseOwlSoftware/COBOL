# PB3946 — a covered OPEN INPUT / I-O / EXTEND of an EXISTING file takes FileMode.OpenOrCreate, so a file removed between the probe and the handle is created silently instead of refused

**Sites:** `src/WiseOwl.Cobol.Runtime/IO/SequentialConnector.CommitControl.cs` (`HeldWriteStream`), `src/WiseOwl.Cobol.Runtime/IO/SequentialConnector.cs` (`OpenReader`)

PB3635 closed the removed-file arm of `SequentialConnector.BeginAppending`. Its review found the same family in the
opposite direction: a covered sequential or keyed OPEN INPUT / I-O / EXTEND of a file the probe found PRESENT takes a handle
with `FileMode.OpenOrCreate` (`HeldWriteStream`, `OpenReader`). A file removed by another run unit between the probe and the
handle is then created empty and silently adopted, where the right answer is the file-not-found status the probe would have
given a moment later. No repro was written (report: "Same family, opposite direction; no repro written").

## Acceptance
- A present-file OPEN takes `FileMode.Open` (or retries the probe), the removed-in-between case answers the not-found
  status, with a deterministic witness (a test hook that removes the file after the probe, no timing) seen RED first.
- Sweep the keyed connector (`KeyedConnector.TakeFileLock`) and every `OpenOrCreate` in `src/WiseOwl.Cobol.Runtime/IO`.
