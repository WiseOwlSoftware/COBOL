# PB3946 — a covered OPEN INPUT / I-O / EXTEND of an EXISTING file takes FileMode.OpenOrCreate, so a file removed between the probe and the handle is created silently instead of refused

**Sites:**
- `src/WiseOwl.Cobol.Runtime/IO/SequentialConnector.CommitControl.cs` (`HeldWriteStream`)
- `src/WiseOwl.Cobol.Runtime/IO/SequentialConnector.cs` (`OpenReader`)
- `src/WiseOwl.Cobol.Runtime/IO/KeyedConnector.cs` (`FileTaking`, `HostModeOf`, `TakeFileLock`, `Lock`, `LockCreating`, `OpenCore`, `CreateTheFileAgain`)
- `src/WiseOwl.Cobol.Runtime/IO/FileConnector.cs` (`Open`, `OpenOnceEntered`, `OpenAgain`, `MaxPathChangedRetries`)
- `src/WiseOwl.Cobol.Runtime/IO/FileSupport.cs` (`IsRemoved`, `HostWriteMode`, `WriteStreamOf`)
- `tests/WiseOwl.Cobol.Tests.Unit/FileRemovedMeanwhileTests.cs`, `tests/WiseOwl.Cobol.Tests.Unit/FileCreatedAgainDriftTests.cs`

PB3635 closed the removed-file arm of `SequentialConnector.BeginAppending`. Its review found the same family in the
opposite direction: a covered sequential or keyed OPEN INPUT / I-O / EXTEND of a file the probe found PRESENT takes a handle
with `FileMode.OpenOrCreate` (`HeldWriteStream`, `OpenReader`). A file removed by another run unit between the probe and the
handle is then created empty and silently adopted, where the right answer is the file-not-found status the probe would have
given a moment later. No repro was written (report: "Same family, opposite direction; no repro written").

## Acceptance
- A present-file OPEN takes `FileMode.Open` (or retries the probe), the removed-in-between case answers the not-found
  status, with a deterministic witness (a test hook that removes the file after the probe, no timing) seen RED first.
- Sweep the keyed connector (`KeyedConnector.TakeFileLock`) and every `OpenOrCreate` in `src/WiseOwl.Cobol.Runtime/IO`.

## Landing 2026-10-27 (wave 20261728, group B)

**Re-probe on the Debug build, with the file removed after the probe by the Table 19 column request (`ColumnRequestLog.Before`),
before the fix (`FileRemovedMeanwhileTests`, RED on every arm but the uncovered OUTPUT):** a covered sequential I-O or EXTEND of a
non-optional file, and an uncovered sequential EXTEND (`FileMode.Append` creates), answered '00' over a file created empty (the
defect); every other arm answered '30' where §9.1.13.6 item 5 gives '35' and §14.9.27.4 GR13/GR17 give '05'.

**Mechanism:** the host mode of the handle of an OPEN was a property of whichever arm took it, not of the one presence probe. **Fix:**
a handle for a file the probe found PRESENT is `FileMode.Open` in every organization (`KeyedConnector.FileTaking` replaces the
`create`/`newFileOnly` pair; `OpenReader`; `HeldWriteStream`; `HostFile.HostWriteMode` maps `Append` to `Open`), and the refusal
(`HostFile.IsRemoved`) makes `FileConnector.Open` run the OPEN again (`OpenAgain.FileRemovedMeanwhile`, one bound with PB3635's
`FileMadeMeanwhile`), so the answer is the one the removal, run first, gives. **Sweep:** every `FileMode.OpenOrCreate` under
`Runtime/IO` is pinned to its reason by `FileCreatedAgainDriftTests.EveryOpenOrCreateOfTheIoLayerIsOneThatMeansIt`
(an OUTPUT of an unobservable presence; the two restores of a capture). No COBOL golden: the race has no source-level spelling.

**For the next implementer.**
- `KeyedConnector.cs#FileTaking` / `HostModeOf`: the one mapping of the presence probe to the store handle host mode; reuse it for any new keyed arm. Trap: `Replacing` (OUTPUT of a present file) stays `Open`, and the kept handle is never adopted for it.
- `FileConnector.cs#Open` / `OpenOnceEntered`: `OpenAgain.FileRemovedMeanwhile` and `FileMadeMeanwhile` share `MaxPathChangedRetries`; the catch is `presence is Present && HostFile.IsRemoved(e)`, so a creating arm never reads as this race.
- `FileSupport.cs#HostWriteMode`: `Append` is host mode `Open` plus a seek to the end, never a creation. `WriteStreamOf` no longer takes an access argument.
- `SequentialConnector.CommitControl.cs#HeldWriteStream`: `Create` stays `OpenOrCreate` (OUTPUT of an unobservable presence; a present file handle was taken by the capture).
- Witness trap: the Table 19 column request (`ColumnRequestLog.Before`) is the one seam between the probe and the body in every organization; the keyed handle does not go through `IHostMedium`.
