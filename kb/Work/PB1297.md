## Measured

### Finding sum-clause — ISO/IEC 1989:2023 13.18.54.4 GR2 (wrong-answer; rows GR-13.18.54.4-2)

**Mechanism.** RESET ON data-name-3 / FINAL resets only when a DECLARED control footing of that level is presented: EndOfGroupSumReset keys the reset on `group.Kind == ControlFooting && group.ControlLevel == s.ResetLevel`, and a level with no CF has no group to present, so the counter is never reset — GR2's 'assumed to be present' control footing is not modelled.

**Repro.** out13/probe/sum-clause/p2.cob: RD CONTROLS ARE FINAL WS-C (no CF WS-C, no CF FINAL); DET: `COLUMN 1 PIC 9 SOURCE WS-C`, `COLUMN 3 PIC 99 SUM WS-K RESET ON WS-C`, `COLUMN 6 PIC 99 SUM WS-K RESET ON FINAL`; GENERATE DET with (C,K) = (1,1),(1,2),(2,3),(2,4).

**Expected, from the standard.** GR2: reset 'at the end of the processing of the control footing for the specified level of control. If no such control footing is defined, it is assumed to be present and to consist of a 01-level entry alone.' The C 1->2 break processes the assumed CF WS-C before the breaking GENERATE's accumulation (14.9.16.4 GR5), so the column-3 counter restarts: lines '1 01 01', '1 03 03', '2 03 06', '2 07 10'.

**Observed.** Observed '1 01 01', '1 03 03', '2 06 06', '2 10 10' — the RESET ON WS-C counter never resets.

**Code site.** src/Cobol.Net.Runtime/IO/ReportWriter.cs#EndOfGroupSumReset; src/Cobol.Net.Runtime/IO/ReportWriter.cs#Generate (control-break loop presents only registered CFs)

### Finding sum-clause — ISO/IEC 1989:2023 13.18.54.4 GR7 c) 2. (wrong-answer; rows GR-13.18.54.4-7)

**Mechanism.** A repeated data-name-2 in one UPON phrase is collapsed to a membership test: SumTerm.Fires returns a bool (Array.FindIndex >= 0), so `UPON DET DET` adds the addend once per GENERATE DET instead of once per appearance.

**Repro.** out13/probe/sum-clause/p1.cob: WS-K PIC 99 VALUE 60; CF FINAL `COLUMN 10 PIC 999 SUM WS-K UPON DET DET`; two GENERATE DET.

**Expected, from the standard.** GR7: 'It is permissible for the UPON phrase to contain two or more instances of data-name-2 that specify the same detail. When a GENERATE statement for such a detail is executed, the adding takes place as many times as data-name-2 appears in the UPON phrase.' -> 60 x 2 x 2 = 240.

**Observed.** Observed 120. (The identifier-1 duplication half, `SUM WS-K WS-K`, correctly prints 240.) Fix shape: Fires should return the COUNT of matching UPON entries and Generate should add Addend() x count.

**Code site.** src/Cobol.Net.Runtime/IO/ReportWriter.cs#SumTerm.Fires; src/Cobol.Net.Runtime/IO/ReportWriter.cs#Generate
