**Rule it breaks:** ISO 8.3.2.1 3): context-sensitive words may be used as user-defined words outside their construct; 8.3.2.2: a user-defined word is supplied to satisfy the format; 13.18.57.2 Format 1 TYPE TO type-name-1. Paired functions agreeing (dimensions.md 2): the declaration slot (dataName / FUNCTION-ID name -> cobolWord) and the reference slot must admit the same word set.

**Scenario:** MEASURED on the pin build (src/Cobol.Net.Cli/bin/Debug/net10.0/cobol.exe, --std 2023): `01 CAPACITY TYPEDEF PIC 9(3).` then `01 V2 TYPE CAPACITY.` -> `error COBOL0001: unexpected CAPACITY`; renaming the type to CAPT2 compiles and runs (prints 007). Sibling: `FUNCTION-ID. CAPACITY.` is accepted, but `REPOSITORY. FUNCTION CAPACITY.` and `DISPLAY FUNCTION CAPACITY(V)` each draw `COBOL0001: cannot parse construct near CAPACITY`; the same program with the name CAPAX prints 006. CAPACITY is context-sensitive only in the OCCURS clause (8.10 table), so in a TYPE clause and after FUNCTION it is a user-defined word. typeClause (CobolData.g4:493) writes `TYPE TO? IDENTIFIER` and functionName (CobolExpressions.g4:703-714) writes IDENTIFIER plus a hand list of reserved words, so every token-carrying cobolWord alternative (BYTES, CAPACITY, CYCLE, FOREVER, PARAGRAPH, ...) that the declaring slot admits is refused at the referencing slot.

**Measured how:** R2 batch finding `lexer-grammar-1--code--f2#2` (pair lexer-grammar-1--code), read in the pinned tree at 8be23006851a; skeptics rule upheld, scenario upheld, site upheld.

**Spec:** §8.3.2.1 "Context-sensitive words may be used as user-defined words and system-names in contexts other than the language construct in which they are defined" (`cite.py --check` passed at collection); §8.3.2.2 "A user-defined word is a COBOL word that is supplied by the user to satisfy the format of a clause or statement" (`cite.py --check` passed at collection); §13.18.57.2 "Format 1 (type-name)" (`cite.py --check` passed at collection)

**Target:** typeClause reads `TYPE TO? cobolWord` and functionName reads `cobolWord | <the reserved intrinsic names>`, so declaration and reference admit one word set by construction; DataDescriptionCst.TypeRefName reads the cobolWord node. Add a drift assertion over the .g4 text that no user-defined-word reference slot is spelled bare IDENTIFIER outside the argued formatWord / enterOperand / genericClause / predicate-led keyword sites.
