# PB3797 — work.py check does not enforce R3's member rule

**Sites:** `scripts/spec/work.py` (`NoteSites`, `note_sites`, `_mention_members`, `_undeclared_names`, `_members_located`, `sites_problems`, `SITES_RULE`, `CODE_FILE`, `_MEMBER_NAME`, `site_member_findings`, `self_test`), `scripts/arch/source_units.py` (`powershell_units`, `READERS`, `self_test`), `scripts/orchestrator/test_plan_wave.py` (whole: a flat script of checks, one fixture edited), `.claude/skills/workstream/templates/MANDATORY-PRACTICES.md` (R3 and the new P15 rows), `.claude/skills/workstream/templates/registrar-brief.md`, `.claude/skills/workstream/references/rolling-wave.md`, `docs/rearchitecture/DESIGN-orchestrator-loop.md`, and the open notes brought to the rule (kb/Work/PB*.md)

## What happens

MANDATORY-PRACTICES R3 asks a `**Sites:**` paragraph to name each file AND the members the fix changes in it, and the wave planner partitions on those members (`plan_wave.collision`, kb/Work PB3670): a file named without members is claimed whole and holds every other group on it. `work.py check` (`SITES_RULE`) only requires that an open note naming a cluster has a site block, not that its code files carry members. On 2026-10-25 nineteen open PB1957 notes (PB3776, PB3777, PB3778, PB3780, PB3782, PB3788, PB3702, PB3722, PB3725, PB3772, PB3774, PB3723, PB3786, PB3663, PB3703, PB3720, PB3775, PB3779, PB3787) named whole files, so they waited behind one dispatch (w20261702a, PB3728) and each other. The owner's "yes" had the Mythos lane rewrite their blocks to name members.

## Acceptance

- Also add to MANDATORY-PRACTICES the rule PB3798 enforces in the guard hook: no agent starts a desktop GUI application on the owner's screen (Obsidian, a browser, Explorer, a windowed .exe); a check that needs a GUI becomes an owner line in the report (owner 2026-10-25 19:24: "Stop fucking running Obsidian").

`work.py check` refuses an OPEN note whose Sites names a code file (.py .cs .ps1 .js .g4 .sh) with no member and no explicit whole-file reason (a form R3 defines, for example `(whole: restructured)`), and a note naming a member the file does not declare; existing open notes are brought to the rule in the same change; a test covers both.

## Limits the rewrite found (2026-10-25), which the check and R3 must settle with it

- A section number is read only OUTSIDE backticks (`_mention_members` strips code spans before `_SECTION_REF`): `docs/X.md` (§N.N) names a section, `docs/X.md` (`§N.N`) names the whole file. R3's text and the clerk brief that quote the backticked form are wrong.
- A Markdown section is nameable only by its number or by a heading that is a single identifier-like word. The headings of MANDATORY-PRACTICES.md ("All roles", "Implementer / finisher", "Public skills by role (P10)") and of implementer-report-template.md contain spaces or hyphens, so a note that edits them can only claim the file whole; the template briefs, agent definitions and unit files under scripts/orchestrator/units have no headings at all (one `<preamble>` unit). Either the headings get nameable ids or `_MEMBER_NAME` accepts a heading text.
- `.ps1`, `.json` and `.yml` files have no unit reader (`source_units.READERS` holds .cs, .py and .md), so a member named in one is never "located" and the file is claimed whole. A `.ps1` reader (functions) is part of the same change, or the whole-file reason form covers them.
- Top-level script code in a Python file (`scripts/hooks/dispatch_guard.py`) is the unit `<module>`, which a code span cannot name.

**2026-10-29 (clerk, from the review of PB3801, report w20261737g-PB3801-report.md, R1-1, low).** PB3801 removed the desktop-GUI guard (PB3798). The Acceptance bullet above that says to add to MANDATORY-PRACTICES "the rule PB3798 enforces in the guard hook" now names a hook that is gone, and the PB3801 Landed section and its DEVLOG entry say the agent rule "stays text in MANDATORY-PRACTICES", though MANDATORY-PRACTICES carries no such rule yet (a grep for desktop, GUI and Obsidian in it finds nothing). This note is the one that adds it: the bullet is to be read as "state the rule in prose: no agent starts a desktop GUI application on the owner's screen", not as a rule a hook enforces.

## Landed (wave 20261752 group A)

`work.py check` now refuses, for every open note `sites_problems` holds to the site rule (a cluster from PB3443 on, or a running
campaign's: the PB3263 scoping, so the 340 older open notes of idle clusters stay readable), a code file (.py .cs .ps1 .js .g4
.sh) that its Sites block names with neither members nor the explicit whole-file form `` `path` (whole: why the whole file changes) ``
(`NoteSites.unnamed`), and a member the file does not declare (`NoteSites.undeclared`, where a unit reader exists). A file the
change creates needs neither. Re-probe before the change: 61 held notes (180 bare file mentions, 11 notes with stale names)
failed it; after it the register is clean and `--self-test` (`site_member_findings`: 15 shapes over real files) holds the
rule.

The four limits the rewrite found are settled in the one reader: (1) a section number is read outside backticks, and R3 now says
so, with the multi-word-heading limit (a heading of several words has no name but its number, the file whole otherwise);
(2) `.ps1`/`.psm1` have a unit reader (`source_units.powershell_units`: functions, strings, here-strings and `$( )` subexpressions
with their own strings, comments; all 50 tracked scripts read), so a PowerShell member is located and its edits partition by
function; (3) `_MEMBER_NAME` accepts the hyphen of a PowerShell function and the units `<module>`, `<header>`, `<footer>`,
`Type.<own>`, which closes the Python `<module>` limit; (4) the R2 writer's `(Type.Member)` parenthesis without code spans was
read as prose: the 52 site lines of eight R2 notes now use code spans (the reader stays strict about the one form).
The 151 bare mentions of restructuring, backfilled and script-body sites carry `(whole: <reason>)`; the notes whose names had moved
(`plan_wave.py` functions now in `coord.py`, `reports.py`, `dispatch_ledger.py`, `inflight.py`, `groups.py`) point at the files that
declare them. `MANDATORY-PRACTICES` gains P15, the agent rule that no desktop GUI application is started on the owner's screen
(prose, not a hook: PB3801 removed the guard); the Acceptance bullet naming the removed hook is read as the clerk's 2026-10-29
paragraph says.
