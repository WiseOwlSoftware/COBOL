# PB3797 — work.py check does not enforce R3's member rule

**Sites:** `scripts/spec/work.py` (`check`, `SITES_RULE`, `note_sites`), `scripts/spec/test_work.py`, `.claude/skills/workstream/templates/MANDATORY-PRACTICES.md` (`Registrar`: R3)

## What happens

MANDATORY-PRACTICES R3 asks a `**Sites:**` paragraph to name each file AND the members the fix changes in it, and the wave planner partitions on those members (`plan_wave.collision`, kb/Work PB3670): a file named without members is claimed whole and holds every other group on it. `work.py check` (`SITES_RULE`) only requires that an open note naming a cluster has a site block, not that its code files carry members. On 2026-10-25 nineteen open PB1957 notes (PB3776, PB3777, PB3778, PB3780, PB3782, PB3788, PB3702, PB3722, PB3725, PB3772, PB3774, PB3723, PB3786, PB3663, PB3703, PB3720, PB3775, PB3779, PB3787) named whole files, so they waited behind one dispatch (w20261702a, PB3728) and each other. The owner's "yes" had the Mythos lane rewrite their blocks to name members.

## Acceptance

- Also add to MANDATORY-PRACTICES the rule PB3798 enforces in the guard hook: no agent starts a desktop GUI application on the owner's screen (Obsidian, a browser, Explorer, a windowed .exe); a check that needs a GUI becomes an owner line in the report (owner 2026-10-25 19:24: "Stop fucking running Obsidian").

`work.py check` refuses an OPEN note whose Sites names a code file (.py .cs .ps1 .js .g4 .sh) with no member and no explicit whole-file reason (a form R3 defines, for example `(whole: restructured)`), and a note naming a member the file does not declare; existing open notes are brought to the rule in the same change; a test covers both.

## Limits the rewrite found (2026-10-25), which the check and R3 must settle with it

- A section number is read only OUTSIDE backticks (`_mention_members` strips code spans before `_SECTION_REF`): `docs/X.md` (§N.N) names a section, `docs/X.md` (`§N.N`) names the whole file. R3's text and the clerk brief that quote the backticked form are wrong.
- A Markdown section is nameable only by its number or by a heading that is a single identifier-like word. The headings of MANDATORY-PRACTICES.md ("All roles", "Implementer / finisher", "Public skills by role (P10)") and of implementer-report-template.md contain spaces or hyphens, so a note that edits them can only claim the file whole; the template briefs, agent definitions and unit files under scripts/orchestrator/units have no headings at all (one `<preamble>` unit). Either the headings get nameable ids or `_MEMBER_NAME` accepts a heading text.
- `.ps1`, `.json` and `.yml` files have no unit reader (`source_units.READERS` holds .cs, .py and .md), so a member named in one is never "located" and the file is claimed whole. A `.ps1` reader (functions) is part of the same change, or the whole-file reason form covers them.
- Top-level script code in a Python file (`scripts/hooks/dispatch_guard.py`) is the unit `<module>`, which a code span cannot name.
