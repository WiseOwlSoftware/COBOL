# R61 — obsolete or removed? (researched 2026-09-30)

**Question.** Are the '85 comment-entry paragraphs (AUTHOR, INSTALLATION, DATE-WRITTEN, DATE-COMPILED, SECURITY, and the '74 REMARKS) and the debug facility (WITH DEBUGGING MODE, the `D` indicator lines, USE FOR DEBUGGING) OBSOLETE (still accepted, flagged) or REMOVED at each edition? The ISO 2023 text in the repository no longer mentions them (they are gone), and the 2002 / 2014 texts are not in the repository.

**Evidence.**
1. GnuCOBOL 3.2's per-standard dialect files (`config/cobol85.conf`, `cobol2002.conf`, `cobol2014.conf`, maintained against the standards): `comment-paragraphs` = obsolete at 85, **unconformable (= not in the standard) at 2002 and 2014**; `alter-statement` the same; `use-for-debugging` = obsolete at 85, **unconformable at 2002**; `debugging-mode` (WITH DEBUGGING MODE and the `D` lines) = ok at 85, **obsolete at 2002**, **unconformable at 2014**. Its reserved-word lists agree (AUTHOR, INSTALLATION, DATE-WRITTEN, DATE-COMPILED, SECURITY reserved only in the 85 list).
2. Web (corroborating, not primary): sources on the 2002 revision state the elements obsolete in '85 (ALTER, the comment paragraphs, USE FOR DEBUGGING) were deleted in 2002; the debug module is described as an obsolete '85 feature scheduled for deletion.
3. The repository's edition table (`docs/VERSION_CHANGE_REFERENCE.md` rows 7.9, 7.10, 7.17, DEVLOG 589) rejects ALL of them from 2002.

**Determination (owner accepts the research).** Comment-entry paragraphs (AUTHOR, INSTALLATION, DATE-WRITTEN, DATE-COMPILED, SECURITY, and REMARKS): accepted at 85 (obsolete), **rejected from 2002** — the table already says so, and fixed form must enforce it exactly as free form does (PB1758/PB1494). USE FOR DEBUGGING: accepted at 85, rejected from 2002. **WITH DEBUGGING MODE and `D` lines: accepted at 85 AND at 2002 (as an obsolete element, with the obsolete-element warning), rejected from 2014** — this CHANGES rows 7.9/7.17's "rejected >=2002" for that one facility (GnuCOBOL: obsolete at 2002, unconformable at 2014). **Confidence:** comment paragraphs and USE FOR DEBUGGING high (two sources agree with the repository table); the debug-mode 2002/2014 boundary medium (GnuCOBOL only; the ISO 2002 and 2014 texts were not obtained). If the standards are ever acquired, verify F.2 of 2002 against this.

**Work.** PB1802's briefs, PB1705 (R56: the rewriter keeps `D` lines under WITH DEBUGGING MODE at 85 and 2002), the edition table, the ConstructRegistry rows, goldens per edition.

Debug-mode windows applied (wave 1003 D, PB1705): rows `debugging-mode-removed-2014` and `debugging-line-removed-2014`, obsolete 2002, removed 2014.
