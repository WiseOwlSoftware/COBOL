# PB1214 — RETIRED — folded into PB1132

Registrar 14b's PB1132 already owns the cached-singleton LOCAL-STORAGE re-initialization loop missing the BASED item's implicit pointer; PB1214 measured that the same loop misses every cell-routed LS storage (ADDRESS-OF-taken record cells too), so the fix is the whole loop, not one arm. ## Measured

**based-clause** — A program's LOCAL-STORAGE cell-backed roots (BASED implicit pointer, ADDRESS-OF-taken record cell) are skipped by the cached-singleton per-activation LS re-init loop; only OO methods re-seed them (PtrActivationSeed)

- **Repro:** Main: `CALL "GR2BL". CALL "GR2BL".` Sub GR2BL: WS `01 W PIC X(4) VALUE "WWWW".` LS `01 X PIC 9 VALUE 0.` `01 B PIC X(4) BASED.` PROCEDURE: `ADD 1 TO X. DISPLAY "X=" X. IF ADDRESS OF B = NULL DISPLAY "LS NULL" ELSE DISPLAY "LS NOT NULL B=" B END-IF. SET ADDRESS OF B TO ADDRESS OF W. GOBACK.` -> X=1 / LS NULL / X=1 / LS NOT NULL B=WWWW (probe gr2b.cob; same at --std 2014).
- **Expected (spec):** X=1 / LS NULL / X=1 / LS NULL: §13.18.5.4 GR2 'The implicit data-address pointer has an initial value of NULL' with the life cycle of §8.6.5 (association ends at the end of the life cycle of the local-storage data items) and §8.6.4 (local-storage items are 'allocated and set to initial state each time the runtime element containing them is activated').
- **Observed:** ProgramEmitter.cs (~L511) re-initialises LS roots of a non-INITIAL non-RECURSIVE unit, but `else if (root.Class is { Tier: RedefinesTier.StringCanonical }) continue;` skips every cell-backed root, so the BASED root's `__addr_*` field keeps the previous activation's pointer. OoEmitter.PtrActivationSeed performs exactly this re-seed for methods - the program arm is missing (two-arm dispatch). Sibling, same mechanism, outside this row: an LS record whose ADDRESS OF is taken keeps its last-used content across CALLs (sib.cob: A=INIT then A=CHGD; expected A=INIT twice per §8.6.4).
- **Code site:** src/Cobol.Net.Compiler/CodeGen/ProgramEmitter.cs (LS activation re-init loop ~L511-527); src/Cobol.Net.Compiler/CodeGen/Verbs/OoEmitter.cs#PtrActivationSeed
- **Clause (adjudicator):** §13.18.5.4 GR2; §8.6.5; §8.6.4

**local-storage-section** — ls-cached-singleton-reinit-misses-channels: a non-INITIAL non-RECURSIVE program's hand-written LOCAL-STORAGE re-initialization at Call() entry enumerates only root fields, Tier-B backings and INDEXED BY cells, so LS storage routed through the addressable-cell channel (an item whose ADDRESS OF is taken) and the based-bridge address (__addr_X of a BASED item) keeps its last-used state across activations

- **Repro:** E:\Temp\claude\E--CobolSharp\a700c052-f9e4-4942-84ff-a13c7505d6ec\scratchpad\adj-d1\out13\probe\local-storage-section\h_addr.cob: main CALLs LSHSUB twice and once via a PROGRAM-POINTER; LSHSUB has LOCAL-STORAGE 01 L PIC X(4) VALUE \"INIT\". 01 P USAGE POINTER. and does DISPLAY \"L=\" L / SET P TO ADDRESS OF L / MOVE \"MUT!\" TO L / GOBACK. Observed L=INIT, L=MUT!, L=MUT!. Also E:\Temp\claude\E--CobolSharp\a700c052-f9e4-4942-84ff-a13c7505d6ec\scratchpad\adj-d1\out13\probe\local-storage-section\g_based.cob: LS 01 B PIC X(4) BASED; IF ADDRESS OF B = NULL ... ; SET ADDRESS OF B TO ADDRESS OF W: the 2nd CALL prints 'B NOT NULL'. The same programs with IS RECURSIVE (h_addr_rec.cob, g_based_rec.cob) print correct results.
- **Expected (spec):** §13.6.4 GR1: LS items are automatic data; §14.6.2.3.2: automatic data is placed in the initial state every time the program is activated. Action 2 applies VALUE, so L=INIT on every CALL; action 5 sets the address of each based item to null, so 'B NULL' on every CALL.
- **Observed:** Pinned cobol.exe (adj-d1): L=MUT! on the 2nd and 3rd activation; 'B NOT NULL' on the 2nd. The generated C# (h_addr.g.cs, g_based.g.cs) shows the Call-entry reset lines for P, the REDEFINES backing _redef_G and the OCCURS DYNAMIC table DT, and NO reset line for L's addressable cell or for __addr_B. Plain VALUE items, REDEFINES groups, POINTER items, INDEXED BY cells and dynamic capacity DO reset, so the gap is exactly the storage channels the loop does not enumerate. The fresh-instance arm (RECURSIVE / INITIAL / FUNCTION / method) is correct, and every existing LS golden exercises only that arm or plain fields. Two-arm dispatch shape: the static-WS twin (DataBinder.RouteStaticRoot -> __ResetStatics) DOES route StaticBasedBridgeAddrs and StaticAddressableCells; the LS cached-singleton arm re-lists channels by hand and missed both.
- **Code site:** src/Cobol.Net.Compiler/CodeGen/ProgramEmitter.cs#EmitCallMethod (the `!unit.Initial && !unit.Recursive && LocalStorageRoots.Count > 0` loop); compare src/Cobol.Net.Compiler/Binding/DataBinder.cs#RouteStaticRoot (IsBased and PtrAddressableCellOf arms)
- **Clause (adjudicator):** §13.6.4 GR1, GR2; §14.6.2.3.2 lead sentence, actions 2 and 5
