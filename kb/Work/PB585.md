# PB585 — LANDED (by PB505) — the group arm of the format-2 VALUE

Found 2026-09-04 by the `PB208` implementer, which landed the ELEMENTARY format-2 VALUE on the image lane and
measured that the group case cannot be screened where it first looked (`ValidateTableValues` runs at entry bind,
before the forest exists, so `IsGroup` is false for every subject there). Re-derived on this tree for this note.

## Repro (`--std 2023`, after PB208)

```cobol
       01  G.
           05  GT  OCCURS 2 VALUE "ABCD" FROM (1) TO (2).
               10  P  PIC X(2).
               10  Q  PIC X(2).
       ...
           DISPLAY "G=[" G "]"          *> G=[        ]  — eight spaces, no diagnostic
```

## The rule

```
python scripts/spec/cite.py --check 13.18.63.3 "Syntax rules 10, 11,12,13,14,and 15 above apply."
OK  §13.18.63.3 16)
python scripts/spec/cite.py --check 13.18.63.4 "the group area is initialized without consideration for the individual elementary or group items contained within this group"
OK  §13.18.63.4 5)
```

SR16 carries SR13 (a group-level literal shall be of the group's category, or a permitted figurative) onto Format
2, so a group-level table VALUE is legal and its literal is screened by the same rules PB206 unified; GR11
("General rules 1, 2, 3, 4, 5, 6, 7, 8, and 10 above apply.") carries GR5's area deposit onto Format 2, so each
occurrence's group area is initialized from the literal as a whole. The tree does neither: the entry passes
`DataBinder.GroupValue.cs#CheckGroupValueDeclarations` (its `IsGroupValueSubject` reads both carriers), then
`ValueInitializer.FieldInit` and `GroupImageCodec.ImageInitOf` skip it on `!IsGroup` and `GroupValueSlicer.AreaOf`
composes no per-occurrence text — the VALUE is dropped on both lanes.

Distinct from the registrar's `PB500` (a Format-2 VALUE on a MULTI-dimension table) and `PB499` (the INITIALIZE /
ALLOCATE lane blind to the Format-2 carrier): those are the elementary case's other arms; this is the GROUP subject.

## Fix shape

In the group-VALUE pass (`CheckGroupValueDeclarations` → the slicer), treat a `TableValues` carrier on a group
subject as GR5 applied per occurrence: screen each occurrence-literal through PB206's group-subject arm of
`ValidateValueCategory` (category + size against the group's area), then let `GroupValueSlicer.AreaOf` produce one
area per occurrence from `ValueInitializer.ResolveTableValueMap` (PB208's one GR12–GR15 map) so both lanes seed
every occurrence identically. Goldens: a group table with a single literal (GR13 reuse), with `FROM…TO` ranges
(GR14/GR15), and a REDEFINES-aliased twin to cover the image lane; a negative for a numeric literal on the
alphanumeric group table (SR13 via SR16).
