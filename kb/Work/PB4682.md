# PB4682 - a stray file in the main checkout forces a resume unit

**Sites:** `scripts/orchestrator/next_unit.py#repo_state`, `scripts/orchestrator/coord.py#is_work`

**Witness.** `E:\COBOL\caret.log` appeared at 2026-11-04 17:26 during wave 20261868: 722 bytes, the `glbls.cob` compile
output (COBOL diagnostics and `rc=1`) printed twice, with no other content. The wave unit saw it and
left it. `repo_state` then counted it as "1 uncommitted path(s)" and the supervisor started this resume unit on opus. The
resume unit read all of the file and deleted it.

**Writer not found.** A search of this account's session transcripts modified since 17:20 found no command that wrote the
file; they only list and read it. Sessions on the other account (`.claude`) and transcripts last modified before 17:20 were
not searched, so the writer is still unknown. A probe run with its working directory in the main checkout and a relative
redirect would produce this, but no such command was seen.

**Two questions for the fix.** Which guard should catch a probe writing into the main checkout (the forbidden-commands
hook sees the command, but a relative redirect does not show its directory)? And should an unexplained file reach a full
resume unit, or be named to the operator more cheaply? Nothing here is settled.
