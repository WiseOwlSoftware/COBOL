# PB3531 — the drift-rule index misses the tree-wide drift classes

## Lead (facts from the wave 1149 group A finisher report, PB3523's branch)

`python scripts/spec/drift_rules.py scripts/differential_fuzz.py` lists 0 specific rules and 5 sweeps, and does NOT list
`CatalogCoverageDriftTests.NoScriptOrTest_SpellsTheGeneralFormatHeadingItself`, the drift test that stopped the branch's
landing (`=== LINUX GATE: RED (failed or not run: unit; HEAD 7eadf3ddc) ===`, at `scripts/differential_fuzz.py:1544`),
though that sweep scans every tracked script.

Cause: `scripts/spec/drift_rules.py#paths_of` (CALL/LITERAL, lines about 27-28 and `paths_of`) reads only `TestRepo.X(...)`
segments and repo-relative literals. A test that scans `TrackedTree.Files()` (7 drift classes: CatalogCoverage,
ConflictMarker, LandingLane, LandingMeasure, LandingPipeline, NulByte, SelfTestDiscovery) declares no path under
`scripts/`, so `governing()` never lists it for a file there (P11's "ask before editing" missed the rule that stopped this
landing).

The Windows gate did not run that test: this sweep's recorded time is over `gate_plan.SWEEP_CHEAP_SECONDS` (2 s), so tier
0c leaves it in leg 2 (`not-run-Unit.txt` of both Windows runs names it). The landing's Linux unit leg runs the whole
population and caught it, as designed (L10).

The finisher left it unfixed because making those classes count as tree-wide sweeps would make `ConflictMarkerDriftTests`
and `LandingMeasureDriftTests` sweeps, which carry no `[Trait("Sweep", "tree")]`. That moves their gate tier and the
trait/sweep equality the drift guard holds: a gate-planning change beyond that slice.

Repro: `python scripts/spec/drift_rules.py scripts/differential_fuzz.py`.

Code sites: `scripts/spec/drift_rules.py` (`paths_of`, `governing`), `scripts/build-local.ps1` leg planning (and
`gate_plan.SWEEP_CHEAP_SECONDS`).

## Fix shape (from the orchestrator)

The index derives a tree-wide class's governed paths from its `TrackedTree.Files()` filter (the one place the class says
what it scans), so `drift_rules.py <file>` names it and the gate's leg planner can put it in leg 1 for a change to a file
it scans. The tier change for the two named classes (`ConflictMarkerDriftTests`, `LandingMeasureDriftTests`) is measured,
not avoided.

## Landed (wave 1150 group B, 2026-10-22)

**Re-probe.** `python scripts/spec/drift_rules.py scripts/differential_fuzz.py` on the dispatch base printed 0 specific
rules and 5 sweeps, without `CatalogCoverageDriftTests`: reproduced.

**Mechanism.** Seven drift classes (CatalogCoverage, ConflictMarker, LandingLane, LandingMeasure, LandingPipeline,
NulByte, SelfTestDiscovery) read the committed tree through `TrackedTree.Files()` and filtered the list in code, so they
named no path the index could read; the gate's planner had no other source for "this drift test reads that file".

**Fix (one declaration, read by both sides).**
- `tests/_shared/TrackedTree.cs`: `TrackedTree.Files(TreeScope)` is the only read of the tree; `TreeScope(Under, Except,
  Kinds)` is the one filter (`Holds`), declared as a `static readonly` field of string literals in named arguments. The
  parameterless `Files()` is deleted and every caller moved; each sweep's planted failure-branch test applies the same
  scope. ConflictMarker and NulByte now sweep the tree once per test assembly (a `Lazy`), not once per test.
- `scripts/spec/drift_rules.py`: `scopes_of` reads each declaration, `in_scope` applies it as `Holds` does, and a class
  governs every file its scope holds — specifically when the holding prefix is 3+ segments deep, as a sweep otherwise.
  New `--scopes` and `--held`; `--check` fails on a declaration it cannot read. ConflictMarkerDriftTests and
  LandingMeasureDriftTests became sweeps and carry `[Trait("Sweep", "tree")]` (HostWitnessTraitDriftTests' equality).
- The planner: `impacted_tests.Reach.drift_tests` (from the diff alone, with or without a map) feeds a new tier
  `0d` in `scripts/gate_plan.py` — every drift test the index says governs a changed file is leg 1, exempt from the
  budgets and the cap. `TIER_ORDER = 0a, 0h, 0c, 0d, 0u, 1, 2, 3`.
- `TrackedTreeScopeDriftTests` holds every `TrackedTree.Files` call to a declared field of its drift-test class, every
  declaration as the index reads it equal to the compiled value, and `in_scope` equal to `Holds` over each scope's edge
  paths; its failure branch is fired on planted source. Self-test arms in `gate_plan.py` (tier 0d with and without
  timings) and `impacted_tests.py` (the real index names CatalogCoverageDriftTests for `scripts/differential_fuzz.py`).

**After.** `drift_rules.py scripts/differential_fuzz.py` lists 10 sweeps, CatalogCoverageDriftTests among them.

**Measured leg-1 cost** (Unit; shared store's recorded seconds; no map): before 34,324 cases, 723 s, floor 49 s. A diff
of one script + DEVLOG + note (PB3523's shape): 10 governing classes, 1,209 s, floor 111 s. Four landed compiler fixes
of 2026-10-22: 123-173 classes, 3,057-4,227 s, floor 224 s. ConflictMarker and LandingMeasure alone (the tier change the
dispatch named): their cheap planted cases join 0c, and as whole-tree sweeps they are tier 0d at every gate (68 s and
18 s recorded before the `Lazy`; ConflictMarker's two tree tests now share one sweep). Measured wall: this branch's
gate ran leg 1 in 118 s (Unit 111 s with 135 tier-0d cases, Conformance 117 s with 24) against 46 s for the gate just
before it on another branch; GREEN, run 20261022T214759Z-9f44ad. DESIGN-test-build-ci.md §3.14.2 records the
measurement.

Re-gate after the self-review (`TreeScope`'s lists made read-only): GREEN, run 20261022T215759Z-e8ac88, leg 1 in 74 s
(Unit 74 s, Conformance 60 s) with the same 135 + 24 tier-0d cases.

**For the next implementer.**
- `tests/_shared/TrackedTree.cs#TreeScope` — the one filter of a sweep of the committed tree; declare a `static readonly`
  field of literals in named arguments and pass it to `TrackedTree.Files`. Trap: a prose string in a drift test that
  spells `TreeScope Name = new(` is parsed as a declaration (TrackedTreeScopeDriftTests reds on it).
- `scripts/spec/drift_rules.py#scopes_of` / `#in_scope` / `#governed` — reuse `governed(rows, paths)` for "which drift
  tests does this change reach"; `in_scope` must stay equal to `TreeScope.Holds` (`--held` is the differential).
- `scripts/spec/impacted_tests.py#reach_of` — `Reach.drift_tests` is gathered from the diff alone, before any map.
- `scripts/gate_plan.py#tier_of` — 0d is checked before 0c (a governing cheap sweep must not be capped out of leg 1).
- `scripts/spec/drift_rules.py#owners` — an exact-path `Except` entry is the rule's owner and is governed specifically
  (review R1-1); an excepted DIRECTORY is not governed by that scope.
