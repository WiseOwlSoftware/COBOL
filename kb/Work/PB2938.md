# PB2938 — the ref-mod detail names the int clamp, not the operand's value

**Found:** wave 1053 group G (PB2695), report `E:\COBOL-coord\scratch\reports\w1053g-PB2695-report.md`, "New defects"
1, and the sibling sweep in PB2695's Landed section; filed by the train 1053 lander.

**The defect.** A reference modifier's leftmost position or length whose value exceeds an `int` (`01 A PIC 9(21) VALUE
100000000000000000001.`, `>>TURN EC-BOUND-REF-MOD CHECKING ON`, `MOVE X(A:1) TO Y`) raises EC-BOUND-REF-MOD correctly,
but its detail names `reference modification (2147483647:1)`: the `int`-saturated value, never the operand the program
holds. The value stays out of range (the clamp preserves §8.4.3.3.4 rule 5's outcome); only the message is wrong.

**Mechanism.** The same narrowing PB2695 removed from the subscript chain, on a different consumer chain: the operand
reaches the runtime through `RuntimeApi.HostInt32` (`src/Cobol.Net.Compiler/CodeGen/Roslyn/RuntimeApi.cs` about line
1067; `StrRefModStartOffset` about line 1049), and `CobolString.RefMod` / `SpliceInto` / `RefModStartOffset` format the
clamped `int` into the detail (`src/Cobol.Net.Runtime/Values/Text/CobolString.cs` lines 179, 198 and 230). The ref-mod
API is `int`-typed with many callers, which is why PB2695 left it out.

**What closes it.** The PB2695 shape: a position carrier that holds the clamp the accessor uses and the exact value text
built only at the saturation extremes (`Values/Tables/Occurrence.cs` is the subscript twin), threaded through the
ref-mod accessors so overload resolution picks it and no emission site passes display text; a golden with a 21-digit
start and length under EC-BOUND-REF-MOD.

**Rule:** §8.4.3.3.4 5) (the reference-modification range check); the detail text is the implementor's, and it must
name the value the program holds.

# PB2938 — LANDED

## Landed (wave 1056, group E)

**Re-probed on the wave-1056 build** (`E:\COBOL-coord\scratch\w1056e\probe.sh`, 14 shapes, checking ON): every arm
printed the clamp, `reference modification (2147483647:1)` for a start item, `(1:2147483647)` for a length item,
`(1:-2147483647)` for a signed negative, `(-2147483648:1)` for a negative start, the receiver arm
`(2147483647:1) ... receiver`, `SET P TO ADDRESS OF X(A:1)`, the expression arm (`A + 5`, `A * A`), and the item that fits a
`long` but not an `int` (`PIC 9(10)` = 5000000000 printed 2147483647). The literal arm (`X(100000000000000000001:1)`)
printed `9223372036854775807` in BOTH the runtime detail and the compile-time `COBOL2671` screen, and a subscript literal
(`EL(100000000000000000001)`) printed the same long clamp: PB2695's fix had handled only the item and ODO-count arms.

**Root cause.** Not one arm: a position narrowed to a clamp BEFORE the one place that raises. (1) `RuntimeApi.RefModStart` /
`RefModLength` narrowed every position to `int` at the emit site (`HostInt32`, `SpecifiedRefModLength(Int128) -> int`);
(2) `CobolString.RefModPosition` / `RefModValue*` returned the saturated `long`; (3) the three raises (`RefMod`,
`SpliceInto`, `RefModStartOffset`) were three copies of the message over `int` parameters; (4) a literal past `long` was
`PositionConstant(long)` clamped at bind (`TryHostPosition`), for a subscript and a ref-mod alike.

**Fix (the PB2695 shape, on the ref-mod chain; the shape that makes the next carrier automatic).**
- The ref-mod position IS an ordinal position of the same kind as a subscript, so it reuses `Occurrence` (documented as such
  in `Occurrence.cs`) rather than a second copy of the saturating-long-plus-exact-text rule.
- `CobolString.RefModPosition` (all five overloads) returns an `Occurrence` through `Occurrence.Of`;
  `RefMod` / `SpliceInto` / `RefModStartOffset` take `Occurrence` leftmost and length (ONE overload each, so `int` callers
  convert implicitly); `RefModOutOfRange` tests the saturated `long`, so nothing narrows to `int` before the test;
  `SpecifiedRefModLength(Occurrence)` floors one above the omitted sentinel and `Occurrence.AtLeast` keeps the exact text
  of the value the floor moves. The three message copies became ONE (`CobolString.RefModViolation`).
- `RuntimeApi.RefModStart` / `RefModLength` pass the rendered position as it is: the emitted C# differs from before only
  where a `Position32(...)` wrapper is gone, and no emission site passes display text. The ACCEPT receiver's transfer width
  (a host `int`, `AcceptSource.Device`) is now the one place that narrows, through `HostInt32`.
- The expression arm: `RefModValue*` return the exact `Int128` of the 38-digit temporary (`CobolNum.PositionOfWide`), the
  twin of `CobolTable.OccValue*`.
- The literal arm: new `PositionWideConstant(BigInteger)` (signed, so a negative literal is never a negated clamp), built by
  the ONE `ReferenceResolver.HostPosition` (both the integer literal and the integer constant-name), rendered as
  `Occurrence.OfLiteral("...")`, read by the compile-time screen (`LiteralPosition`) so `COBOL2670/2671` name the
  literal; `Position.Bound` counts it and a NEGATION over a value past `long` now routes to the expression binder
  (`-long.MinValue` wraps).
- Found and fixed in the same read: `RefModPosition(UInt128)` returned `long.MaxValue` for every value past `Int128`
  "whatever its fraction" (the sibling arm PB2695 fixed in `CobolTable.Occ(UInt128)`); it now reads the UInt128 itself and
  asks GR1b's integrality of it.

**Public surface.** Shipped members changed type (`RefMod`, `SpliceInto`, `RefModStartOffset`, `RefModPosition`,
`RefModValue*`, `SpecifiedRefModLength`) and `Occurrence.OfLiteral` is new (`PublicAPI.Unshipped.txt`); the one unreleased
major (2, train 1052's) covers it, and `RuntimeAbiPinDriftTests` is re-pinned (`DCEBF2032624C3FB`).

**Tests.** `WideRefModDiagnosticTests` (Conformance, 32 cases: the termination text per arm: item start/length through each
carrier, the expression arm, a literal and a named constant past `long`, a subscript literal, the write / ADDRESS OF / ACCEPT
consumers, checking OFF, the compile-time screen), `OccurrenceTests` (Unit, 7 new: the ref-mod carriers, the UInt128 arm, the
exact intake, the floor, the three raises, `OfLiteral`), golden `2002/pb2938_wide_refmod_position_and_length` (the
CONDITION on each shape; the message text is unobservable from COBOL, so no negative golden below 2002 exists: nothing here
adds syntax or an edition gate).

**For the next implementer.**
- `src/Cobol.Net.Runtime/Values/Text/CobolString.cs#RefModViolation` / `#RefModOutOfRange` — THE one raise and THE one range
  test of a program's reference modification; REUSE them for any new consumer of a ref-mod range (never a third copy).
- `src/Cobol.Net.Compiler/Binding/ReferenceResolver.cs#HostPosition` — THE one integer-literal reader of a position (a
  literal past `long` is a `PositionWideConstant`, never a clamped `PositionConstant`).
- Trap: an `int` argument to a method that takes `Occurrence` converts through `long` (standard then user-defined); a
  `long` overload beside an `Occurrence` one makes every `int` argument CS0121 (PB2695's trap, still true).
- The detail of an EXPRESSION wider than the 38-digit temporary names 10^38 - 1 (saturation by sign, PB2695's documented
  capacity), e.g. `X(A * A:1)` with `A PIC 9(21)`.
