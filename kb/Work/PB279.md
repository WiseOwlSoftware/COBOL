# PB279 — LANDED 2026-09-01 — the fleet build guard froze the SESSION where it should have frozen the TREE

> ⚙ **flags:** process · found 2026-09-01 in session `01PEJTGVQX17pwVbXZq7mYxS` · fixed in a worktree by an
> implementer agent, landed in the main tree by the lander · proof: `--self-test` 37/37 plus a real-repo
> end-to-end probe · siblings [[PB103]] (two modes) and [[PB185]] — all four defects of this hook are the same
> shape, the guard failing CLOSED.

## The measurement

`scripts/hooks/fleet_active_build.py` denied `dotnet build|test|clean|publish|run|msbuild` whenever ANY foreign
transcript of this session had been written in the last 120 s, wherever that agent was working. The owner's
2026-09-01 direction for MAXIMUM SUBAGENT PARALLELISM in the fix lane turned that false denial into the lane's
**binding constraint**: N implementer agents dispatched with `Agent(isolation="worktree")` into N private
checkouts serialized behind each other's mere liveness, each waiting on a collision that could not happen —
two `git worktree` checkouts share no `bin/obj`, no `cobol.exe` and no source file. The rule was the right
harm model applied at the wrong scope.

## The rule now enforced

Deny **iff some FOREIGN live agent works in the SAME working tree as the caller.** Both trees in that
comparison are DERIVED, never listed — a hand-maintained agent→tree map is exactly the shape rule 5 forbids and
would go stale the first time a directory was renamed:

- the **caller's** tree = the repository root of the payload `cwd` — the nearest ancestor holding a `.git`
  entry, a DIRECTORY in the main checkout and a FILE in a worktree. Stopping at the FIRST one is what makes a
  worktree resolve to itself rather than to the repository it was cut from (`repo_root_of`).
- the **main** checkout = that root when its `.git` is a directory, else the `gitdir:` target parsed out of the
  worktree's `.git` file — parsed in-process, not by shelling out, because a PreToolUse hook runs on every
  `dotnet` call and must not pay a subprocess (`main_repo_root`). Relative `gitdir:` values
  (`git worktree add --relative-paths`) resolve against the worktree root.
- a **foreign agent's** tree = `<main>/.claude/worktrees/agent-<agentId>` **when that directory exists**, else
  the main checkout. True by construction: `Agent(isolation="worktree")` creates exactly that path and starts
  the agent in it, so the directory's existence IS the launch mode (`agent_working_tree`).

Three consequences, all intended: a worktree agent builds its own worktree while main-tree fleets run; a
main-tree build is still denied by a live main-tree agent (the original 2026-08-04 purpose, unchanged); and a
main-tree build is ALLOWED while only worktree agents are live.

## The fallback direction

⚠ **Toward the OLD rule, never toward allowing.** If the caller's tree cannot be located, or a worktree's
`.git` file cannot be read or parsed, the agent→tree map cannot be built at all — so the decision reverts to
the SESSION-WIDE deny and every foreign live agent blocks. That is distinct from the hook's fail-OPEN posture,
which covers a BROKEN guard (any exception ⇒ exit 0); this covers an UNKNOWN tree, where allowing is the one
outcome that reproduces the 60-agent waste of 2026-08-04.

## Two deliberate extras the implementer made, both kept

1. **PB103's blunt `/.claude/worktrees/` bail is REMOVED.** It allowed any build whose `cwd` or `cd` mentioned
   that path — which under the new rule would mask the same-tree DENY, letting a worktree agent build while a
   *second* agent probed that very worktree. The precise tree comparison subsumes it; the string test only
   survived as long as it did because nothing measured its complement.
2. **`deny_reason` named `subagents` instead of the agents.** It read `p.parent.name`, and the parent of
   `…/subagents/agent-bbb.jsonl` is the literal directory `subagents`, so every denial blamed the same
   non-existent agent. Now `p.stem`, and the message additionally names the shared TREE and offers
   `isolation: "worktree"` as remedy (d) — the guard now teaches the way out of itself.

## Proof

- `python scripts/hooks/fleet_active_build.py --self-test` ⇒ **SELF-TEST PASS**, 37/37, over REAL temporary
  worktrees (`tempfile.TemporaryDirectory`) so the `.git`-file parse and the `agent-<id>` existence check are
  exercised rather than mocked. It covers both new axes: tree resolution (7 cases incl. relative `gitdir:` and
  the UNKNOWN arm) and scope (12 cases, including all three session-wide fallbacks and `cd <main> && dotnet
  build` issued from a worktree).
- An **end-to-end probe against the real `E:\CobolSharp` checkout and its real `.claude/worktrees/agent-*`
  directories**, with only the fleet's config root synthetic (`CLAUDE_CONFIG_DIR`) so no live transcript was
  touched: with a worktree agent and a main-tree agent live simultaneously, a main-tree build is denied naming
  **only** the main-tree agent, a worktree build denied naming **only** that worktree's agent, a nested
  main-tree `cwd` walks up to the same answer, and the ALLOW arm fires when only the worktree agent is foreign.
  That probe's FAIL branch fired once — on a mis-built expectation of its own, since a caller excludes ITSELF —
  which is the only reason its silence is worth anything.
