# PB292 — a declined processor-dependent element that accepts silently

Found by the A.4.8 / A.4.13 module-witness sweep (2026-09-02) and **re-measured at landing time**, not inherited.

## Measured, on the merged tree

```
       SELECT F ASSIGN TO "pbrecdelim.dat"
           ORGANIZATION IS SEQUENTIAL
           RECORD DELIMITER IS STANDARD-1.
```

`cobol probe.cob --std 2023 --run` → prints `RAN`, exit 0. **No diagnostic of any severity.** The same source
compiles clean at 85/2002/2014, because nothing anywhere is keyed on the clause.

## The mechanism

`src/Cobol.Net.Frontend/Grammar/Core/CobolIO.g4`:

```
recordDelimiterClause
    : RECORD DELIMITER IS? (STANDARD_1 | cobolWord)
    ;
```

and its own comment says the quiet part: *"CobolSharp length-frames variable records itself (4-byte prefix), so
this is parsed and ignored."* A grep for `recordDelimiterClause` / `RecordDelimiterClause` across `src/` returns
hits **only** in `src/Cobol.Net.Frontend/Generated/` — the ANTLR output. **No binder, no model, no emitter reads
it.** The clause is a parse-and-drop.

## Why that is a defect and not a documented posture

`docs/CONFORMANCE.md` §2 row 26 records *"STANDARD-1 phrase of RECORD DELIMITER | 13.x | Not claimed |
Reel-device delimiter; mass-storage model only"* — an Annex A.3 processor-dependent element this implementation
declines. §4.2.6 ¶3 (`cite.py --check`ed) then binds:

> An implementation shall provide a warning mechanism at compile time to indicate use of
> syntactically-detectable processor-dependent language elements not supported by that implementation.

`shall`. The element is syntactically detectable — the grammar detects it — and the warning does not exist. A
declared non-support that the compiler cannot be observed to hold is not a posture, it is an undetectable claim;
this is `feedback_two_arm_dispatch`'s sibling shape that [[PB282]] found in A.4.13, where §5 said "no surface, a
parse error today" and the surface was live.

⚠ **Both arms.** `feature-name-1` (the `cobolWord` alternative) is the twin and is equally unread. A fix touching
only the `STANDARD_1` arm repeats the defect shape the same session found twice.

## The fix is one call on the seam that now exists

Witness cluster A landed `EditionContext.Declined(descriptor, seen)` — THE declined-element seam, whose severity
decides accept-inert (Warning) versus refuse (Error). §4.2.6 ¶3 requires a **warning**, not a refusal, and
explicitly does not require executable code; the conforming shape is therefore a new **Warning** descriptor named
for A.3 item 26, raised from the SELECT-clause binder for both arms, with the bind otherwise unchanged. Two
negatives (`record-delimiter-standard-1`, `record-delimiter-feature-name`) pin it, and the nine
`§12.4.5.11` inventory rows above then close on the witness the way A.4.8's 37 did.

⚠ Correct row 26's citation in the same change set: it reads **"13.x"**, a placeholder, where the clause is
**§12.4.5.11** (`--check`ed). ⛔ **`13.x` is not a one-off — `grep -n '| 13\.x |' docs/CONFORMANCE.md` returns
FIVE rows**: 5 (BLOCK CONTAINS), 12 (FLOAT-BINARY), 13 (FLOAT-DECIMAL), 26 (this one) and 40 ([[PB293]]'s). Every
one is an unresolved citation in the document that IS the §4.2.6 user documentation, so the sweep — deriving each
clause and `--check`ing it — belongs to whichever of these lands first, not to five separate passes.
