# PB292 — a declined processor-dependent element that accepts silently

Found by the A.4.8 / A.4.13 module-witness sweep (2026-09-02) and **re-measured at landing time**, not inherited.

## Measured, on the merged tree

```
       SELECT F ASSIGN TO "pbrecdelim.dat"
           ORGANIZATION IS SEQUENTIAL
           RECORD DELIMITER IS STANDARD-1.
```

`cobol probe.cob --std 2023 --run` → prints `RAN`, exit 0. **No diagnostic of any severity.** The same source
compiles clean at 85/2002/2014, because nothing anywhere is keyed on the clause.

## The mechanism

`src/Cobol.Net.Frontend/Grammar/Core/CobolIO.g4`:

```
recordDelimiterClause
    : RECORD DELIMITER IS? (STANDARD_1 | cobolWord)
    ;
```

and its own comment says the quiet part: *"CobolSharp length-frames variable records itself (4-byte prefix), so
this is parsed and ignored."* A grep for `recordDelimiterClause` / `RecordDelimiterClause` across `src/` returns
hits **only** in `src/Cobol.Net.Frontend/Generated/` — the ANTLR output. **No binder, no model, no emitter reads
it.** The clause is a parse-and-drop.

## Why that is a defect and not a documented posture

`docs/CONFORMANCE.md` §2 row 26 records *"STANDARD-1 phrase of RECORD DELIMITER | 13.x | Not claimed |
Reel-device delimiter; mass-storage model only"* — an Annex A.3 processor-dependent element this implementation
declines. §4.2.6 ¶3 (`cite.py --check`ed) then binds:

> An implementation shall provide a warning mechanism at compile time to indicate use of
> syntactically-detectable processor-dependent language elements not supported by that implementation.

`shall`. The element is syntactically detectable — the grammar detects it — and the warning does not exist. A
declared non-support that the compiler cannot be observed to hold is not a posture, it is an undetectable claim;
this is `feedback_two_arm_dispatch`'s sibling shape that [[PB282]] found in A.4.13, where §5 said "no surface, a
parse error today" and the surface was live.

⚠ **Both arms.** `feature-name-1` (the `cobolWord` alternative) is the twin and is equally unread. A fix touching
only the `STANDARD_1` arm repeats the defect shape the same session found twice.

## The fix is one call on the seam that now exists

Witness cluster A landed `EditionContext.Declined(descriptor, seen)` — THE declined-element seam, whose severity
decides accept-inert (Warning) versus refuse (Error). §4.2.6 ¶3 requires a **warning**, not a refusal, and
explicitly does not require executable code; the conforming shape is therefore a new **Warning** descriptor named
for A.3 item 26, raised from the SELECT-clause binder for both arms, with the bind otherwise unchanged. Two
negatives (`record-delimiter-standard-1`, `record-delimiter-feature-name`) pin it, and the nine
`§12.4.5.11` inventory rows above then close on the witness the way A.4.8's 37 did.

⚠ Correct row 26's citation in the same change set: it reads **"13.x"**, a placeholder, where the clause is
**§12.4.5.11** (`--check`ed). ⛔ **`13.x` is not a one-off — `grep -n '| 13\.x |' docs/CONFORMANCE.md` returns
FIVE rows**: 5 (BLOCK CONTAINS), 12 (FLOAT-BINARY), 13 (FLOAT-DECIMAL), 26 (this one) and 40 ([[PB293]]'s). Every
one is an unresolved citation in the document that IS the §4.2.6 user documentation, so the sweep — deriving each
clause and `--check`ing it — belongs to whichever of these lands first, not to five separate passes.

## Landed 2026-09-05

**Both arms, one code, one bind site.** `COBOLNET1778` `record-delimiter-unsupported` (accept-inert **Warning**,
beside 1578/1579/1580) is raised from `DataBinder.BindFileControl` through the ONE `EditionContext.Declined`
seam, for `recordDelimiterClause` as a whole — so `STANDARD-1`, `feature-name-1`, and each of them with the
optional word `IS` omitted, all draw it, at `--std` 85/2002/2014/2023. Measured before: `RAN`, exit 0, no
diagnostic at any edition on either arm. Measured after: the same `RAN`, exit 0, plus the named warning.

**The two arms are declined on DIFFERENT licences, and the note's "one code, both arms" instinct was right for
the wrong-looking reason.** `STANDARD-1` is Annex **A.3 item 26** — §4.2.6 ¶3 makes the compile-time warning
mandatory and §12.4.5.11.4 GR2 ("the external medium shall be a tape drive") is the dependency made concrete.
`feature-name-1` is **not an A.3 item at all**: it is Annex **A.1 item 150**, which the standard classes
*optional*, and §12.4.5.11.3 SR2 leaves the available names to the implementor. The set specified here is EMPTY
(new §7 row), so §12.4.5.11.4 GR4 has no method to associate. Two grounds, one disposition, one code — splitting
them would have written one rule in two places.

**Accept-inert rather than refuse, and §12.4.5.11.4 GR1 is the whole argument.** "Any method used shall not be
reflected in the record area or the record size used within the function, method, or program" — so unlike an
inert FORMAT clause (COBOLNET1705, which changes which bytes a program reads back), an ignored RECORD DELIMITER
changes nothing a program can observe: GR5's implementor framing governs and the file round-trips.

**Provenance of the decline, as the dispatch required.** `docs/CONFORMANCE.md` §2 row 26 has **no owner decision
behind it** — `git log -S` puts it in `6e9d1d12`, the commit that CREATED the document (P13 Wave H), and it was
never revisited. What landed here therefore does **not** rest on that row: the §4.2.6 ¶3 warning is mandatory
under *either* branch of the open question (implement the ISO/IEC 1001:2012 7.1.2 framing, or keep the decline),
because until it is implemented the element is unsupported either way. The owner question — *should COBOL.NET
provide the STANDARD-1 tape framing, or a feature-name of its own?* — is raised in the implementer report, not
answered here.

**The citation sweep was EIGHT rows, not five.** The note's `grep -n '| 13\.x |'` found one spelling; `8.x`,
`9.x` and `11.x` are the same defect in other chapters (`feedback_scan_all_similar`). All eight are now derived
and `cite.py --check`ed: 5 → §13.18.10, 12 → §11.9.8, 13 → §11.9.9, 26 → §12.4.5.11, 38 → §8.1.2, 40 →
§12.4.5.12.2 / §12.4.5.6.2, 43 → §13.18.43.3 SR7/SR8, 45 → §9.3.5.3 / §9.3.6. **`AnnexA3RegisterDriftTests` is
the rule-5 half**: it bans the placeholder shape outright, asserts the register covers all 46 A.3 items, and
holds every `COBOLNET####` the register names to being a code something in `src/` actually emits — with both
failure branches driven once against fabricated data.

**A miscitation found on the way.** `RecordFraming`'s header cited §9.1.13.6 ("externally-defined boundaries")
as the licence for its physical record framing; that sentence is the I-O status **34** rule about writing past a
*file's* end and answers a different question (`feedback_a_real_clause_can_answer_a_different_question`). The
licence is §9.1.7.2 — "In record sequential files the length of each record is determined by any information the
implementor may add to the record on the physical storage medium (such as record length headers)" — corrected in
the same change set, and it is now the cited ground of the new A.1 item 151 determination.
