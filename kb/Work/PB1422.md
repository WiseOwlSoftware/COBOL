## Finding — `function-identifier` (silent; rows `GR-8.4.3.2.4-6`)

**Mechanism.** EC-PROGRAM-RESOURCES has no raise site for a function activation, and the implementor-defined set of checked resources (Annex A.1 item 89, 'required ... shall be documented') has no DOC row in docs/CONFORMANCE.md, so GR6c's first sentence is neither implemented nor documented as an empty set.

**Repro.** grep -rn 'EC-PROGRAM-RESOURCES' src -> only ExceptionCatalog.cs:185 (the catalog row) and a CallEmitter.cs:271 comment ('has no raise site'). grep 'A.1-89' docs/CONFORMANCE.md -> nothing.

**Expected from the spec.** §8.4.3.2.4 GR6 c): 'If the function is located but the resources necessary to execute the function are not available, the EC-PROGRAM-RESOURCES exception condition is set to exist ... The runtime resources that are checked ... are defined by the implementor.' A.1 item 89 requires that definition to be documented. Either raise it (for example on activation-stack exhaustion or a failed load) or document an explicit determination.

**Observed / reasoning.** The standard's latitude covers WHICH resources are checked, not whether the choice is stated. With no DOC-A.1-89 row the conformance claim for GR6 c) is unanchored. The CALL twin (A.1 item 14, §14.9.4.4 GR3c) and INVOKE (A.1 item 102) should be swept the same way.

**Code site.** src/Cobol.Net.Runtime/Exceptions/ExceptionCatalog.cs:185; src/Cobol.Net.Compiler/CodeGen/Verbs/CallEmitter.cs:271; docs/CONFORMANCE.md (DOC-A.1 table)

## What the fixer owes

Raise EC-PROGRAM-RESOURCES at function activation where CallEmitter does for CALL (one helper), and write DOC-A.1-89.
