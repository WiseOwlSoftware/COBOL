# PB2280 — the Format-2 CALL lane does not reshape a variable-length carrier

Found by wave 1031 group B (kb/Work PB480, report `w1031b-PB480-report.md`, new defect 1), filed by the train-1031
lander.

## Mechanism

PB480 moved the §8.5.1.12 compatibility walk to the runtime (`src/Cobol.Net.Runtime/Values/GroupCompatibility.cs#Walk`
over `GroupAtom` layouts) and taught BOTH INVOKE lanes (universal: `UniversalGroupCarrier.VariableCarrier` /
`WriteBackVariable` / `Deliver`; typed: `OoEmitter.VarGroupShapes`) to rebuild a carrier between two compatible
variable-length groups of different shapes (`CobolVarGroup.Reshape`) and to overlay the formal's store back onto the
argument (`CobolVarGroup.Overlay`, ISO §14.2.3 GR8).

The Format-2 CALL lane was not converted. `src/Cobol.Net.Runtime/Control/CallAbi.cs` `VarGroup` / `VarGroupValue`
(the `vp => vp` identity, about L936 and L986) and `StoreReturn(CobolArg?, CobolVarGroup, int[])`
(`vp.Value = value`) hand the argument's carrier to the formal as it is. The CALL ABI carries `int[]` layouts
(`CobolArg.Layout`, `ProgramEmitter.FormalLayout` / `GroupFormalLayout`, `CallEmitter.BoundaryLayout`), so it has no
`GroupAtom[]` to give `Reshape` / `Overlay`.

## Repro

`E:\COBOL-coord\scratch\w1031b\probe\vvcall.cob` (`CALL … AS NESTED`): the argument `X(2)+dyn+X(5)` opposite the formal
`X(2)+dyn+X(2)` prints `G1=HH/Q/TT   ` (the argument's tail is cut); a dynamic-capacity table opposite `OCCURS 3`
prints `TB:hh/      /AABBCC` and then `D2` is lost. The INVOKE lanes print `G1=HH/Q/TTTTT` and
`TB:hh/AABBCC/xyz` for the same pair (golden `tests/conformance/2014/pb480_universal_variable_length_shapes`).

## Rule

§14.8.2.2 2) "the formal parameter and the argument shall be compatible, as described in 8.5.1.12" (compatible
groups may differ in everything but where their variable-length items lie); §8.5.1.12.3 sentence 3 (a fixed table
opposite a dynamic-capacity table); §14.2.3 GR8 (the formal occupies the argument's storage). All three were run
through `cite.py --check` by the w1031b implementer.

## Fix shape

Carry `GroupAtom[]` across the CALL ABI in place of the `int[]` layout (the layout is derived from the atoms already:
`GroupCompatibility.Layout`), and call `CobolVarGroup.Reshape` / `Overlay` at the three CALL sites. This changes the
ABI's wire format and the emitted C# of every group CALL, which is why the PB480 implementer did not do it inside its
slice. Do it together with kb/Work PB2281 (the second correspondence walk the atoms make redundant).
