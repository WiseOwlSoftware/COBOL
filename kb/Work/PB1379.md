# PB1379 — LANDED

## Landed (wave w0930-numeric — one bundled commit with the seven siblings of this note)

Re-probed first: COMP-2 / COMP-1 `-1.0E-10` into FORMATTED-TIME / FORMATTED-DATETIME / LOCALE-TIME-FROM-SECONDS printed midnight
(`000000`, `16010101T000000`, `12:00:00…`) with no condition; a fixed-point `-0.0000000001` and COMBINED-DATETIME refused it.

**Root cause.** `IntrinsicRenderer.SecondsArg` landed a float with `FloatToScaled(…, "9", Truncation)` and an SDIDI with
`DecToUnscaledIntermediate(…, "18", Truncation)` BEFORE `CobolDate.SecondsOutOfStandardForm` compared against §7.3.17.4's
`[0, 86 400)` / `[0, 86 401)`, and truncation toward zero changes the verdict for a value in (−1 unit, 0). **Fix:** the landing
is membership-preserving — `CobolDate.SecondsOfReal` / `SecondsOfDec` round toward NEGATIVE infinity (a negative value lands
negative; every bound is representable at the landing scale so a landed value crosses a bound exactly when the exact one does;
NaN lands out of the form; an SDIDI past the carrier saturates by sign instead of raising a size error where §15.3 names
EC-ARGUMENT-FUNCTION). Citations (`cite.py --check`): §7.3.17.4 4) and 5) OK (the two registered rules), §15.54.4 2) OK.
**The side observation.** `LOCALE-TIME-FROM-SECONDS(86400)` under ON read the leap second as `24:00:00` (`12:00:00 AM` in en-US)
where FORMATTED-TIME presents 23:59:60; §15.54.4 r2 returns "a character-string containing hours, minutes, and seconds of the time specified by
argument-1". The three consumers now share ONE reading (`CobolDate.TimeOfDay`); `CobolLocaleTests` pinned the wrong
`24:00:00` and now pins `23:59:60` (+ `23:59:60.5`). Goldens `2023/pb1379_time_form_floor_float_carriers_off` / `_on`
(the leap-second locale line names de-DE so it does not depend on the host locale); units `CobolDateSecondsLandingTests`.

**Siblings swept:** the three `SecondsArg` consumers, COMBINED-DATETIME's binary64 body (already exact), the fixed-point arm
(exact at its own scale), the offset arguments (integer intake — now integral-checked by PB1526).


Side observation (refuter, not this rule): LOCALE-TIME-FROM-SECONDS(86400) under ON renders '12:00:00 AM' — the leap second shown as midnight; the fixer should check §15.54's returned value while in the file.
