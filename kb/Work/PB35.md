# PB35 — LANDED — one rule, six clauses, one implementation

> ⚙ **flags:** under-rejects · silent
> The entry named §15.59.3 / §15.63.3 (MAX/MIN) and noted "the screen would have to test LENGTH, not class."
> Both halves were right. **The count was not: the rule appears in SIX clauses and was enforced in ONE.**

## ⛔ THE SWEEP — what the entry named, and what was actually there

`FUNCTION MAX("" "AB")` compiled clean at every edition. So did MIN, ORD-MAX and ORD-MIN. Measured:

| clause | function | rule | reach | before |
|---|---|---|---|---|
| §15.59.3 | MAX | **r3** | every argument (variadic argument-1) | ⛔ silent |
| §15.63.3 | MIN | **r3** | every argument | ⛔ silent |
| §15.71.3 | ORD-MAX | **r2** | every argument | ⛔ silent |
| §15.72.3 | ORD-MIN | **r2** | every argument | ⛔ silent |
| §15.66.3 | NATIONAL-OF | **r3** | argument-1 of two | ✅ enforced |
| §15.85.3 | STANDARD-COMPARE | **r4** | argument-1 AND argument-2 | n/a — `Bind = Unsupported` |

**The one that worked is why the others did not.** NATIONAL-OF's check is hand-written inside
`CheckRepertoireArgs`, so nothing about it generalized — a per-function checker cannot be a home for a rule six
functions share ([[feedback_one_rule_one_place]]).

⚠ **`FUNCTION MAX ( { argument-1 } … )`** — read off the general format. "Argument-1" IS the whole variadic
list, so the prohibition covers EVERY argument, not the first one. That is why it lands on the schema's `Tail`.

## ▶ THE FIX IS A SCHEMA FACT, NOT A SIXTH COPY

`ArgRule` gains `NoZeroLengthClause`, declared beside the position's class rule, enforced in the ONE shared
per-position loop `IntrinsicArgumentRules` already drives (CLAUDE.md rule 5 — the shape that makes the NEXT
clause a table row).

⛔ **IT CARRIES A CLAUSE STRING, NOT A `bool`, AND THAT IS THE LOAD-BEARING DETAIL.** The zero-length rule is a
DIFFERENT ORDINAL from the position's class rule in all six: MAX's class rule is §15.59.3 **r1**, its
zero-length rule is **r3**. A boolean would have made the diagnostic cite r1 for an r3 violation — a citation
that passes `cite.py --check`, because the text really is in the standard, while pointing the reader at the
wrong rule. That is CLAUDE.md rule 1's exact failure mode, and
[[feedback_a_real_clause_can_answer_a_different_question]] is the memory for it.

⚠ **THE TEST IS ON THE LITERAL, NEVER ON A WIDTH.** Each clause says "zero-length **literal**" in those words.
A screen written on the operand's measured width would reject items and figuratives — [[PB1]] is the standing
proof of that direction's cost (an argument screen enforced from an unverified table turned away 12 legal corpus
programs). `pb35_zero_length_literal_legal_forms` pins seven shapes that must keep compiling, including
`FUNCTION MAX(SPACE "A")`.

## ⚙ THE DRIFT TEST FOUND A SIXTH CLAUSE MY OWN SCAN HAD MISSED — on its first run

`ZeroLengthLiteralArgumentDriftTests` derives the function list from `specs/ISO_COBOL.md` rather than
remembering it, scoped to each function's **Argument rules** subclause. Its first cut matched
`shall not be a zero-length literal` and returned FIVE of the six: **§15.85.3 r4 states the identical rule as
"NEITHER argument-1 NOR argument-2 shall be a zero-length literal"**. A drift test whose own pattern has a blind
spot reports coverage it does not have, so the population assertion (`found.Count >= 6`) is what caught it —
[[feedback_verdict_evidence_invariant]], earning its keep on the day it was written.

⚠ **The subclause scoping is also load-bearing, in the other direction.** §15.93/§15.94/§15.95 (the TEST-NUMVAL
family) mention "argument-1 is zero-length" in their RETURNED-VALUE rules as an error the function REPORTS —
a value it computes, the opposite of a prohibition. Matching the phrase anywhere in clause 15 would have demanded
a screen rejecting source the standard defines behaviour for. A test asserts they are NOT swept in.

## ▶ THE TWO ADJUDICATED OUT, each with its reason in the test

- **NATIONAL-OF** stays in `CheckRepertoireArgs`, where its NARROWER class rule already lives: §15.66.3 r1
  admits argument-1 of class alphabetic or alphanumeric but **not national**, which no single `ArgKind` code
  expresses (`'s'` spans national). Splitting ONE function's argument rules across two mechanisms to unify one
  rule across six is the worse trade.
- **STANDARD-COMPARE** is §A.4.9 item 11 + §A.3 item 25 documented non-support (`Bind = Unsupported`), so
  COBOLNET1518 fires before any argument screen and a row would be a dead lookup
  ([[feedback_a_dead_lookup_is_also_unverified]]) — the same disposition [[PB27]] reached for the locale rows.
