# PB1037 — OPEN

## The measurement (the w56d implementer's, reproduced in shape by this registrar's grep)
A literal scan of `src/` for each `ExceptionCatalog` level-3 name finds 64 of 130 with no literal outside the catalog.
The scan is NOISY: EC-I-O-* are raised through the status mapping, so a literal count is not a raise-site count.

## What the fixer owes
A raise-site REGISTRY, not a grep: each raise helper (`ExceptionState.Raise…`, the status mapper, the intrinsic
domain arm, …) declares the names it can set, and a drift test asserts that every name `ExceptionCatalog` marks
turnable is either in some helper's declared set or on an allow-list of declined modules, each entry naming its
kb/Work note or its CONFORMANCE.md determination. Make it fail once (feedback: prove the watchdog fails) by removing
one declaration. PB1036's four names are the first entries it will flag.


## Task brief (research 2026-09-30)

The model is kb/Work **PB1762** (raise-site declarations and the enabled set). **Size: ONE SLOT, NEEDS OPUS** — it has
to classify every catalogued level-3 name and write an honest allow-list entry (note or CONFORMANCE determination)
for each unraised one. **Order: after PB1453** (which creates the operand walker the test reads) **and PB1531** (which
closes the catalog, so the universe is finite).

1. The three sources, each read mechanically (never a hand list):

   every `ExceptionState.*Error` / `Set(name, …)` literal and the status→EC mapping (`ExceptionCatalog.IoMaskNames`).
2. `EcRaiseSiteRegistryDriftTests`: for every catalogued level-3 name, (b) ∩ (c) must be non-empty, OR the name is on
   `DeclinedRaiseSites` (a table in the test project, each entry = name + `kb/Work` note id or `docs/CONFORMANCE.md`
   anchor explaining why it is never raised — e.g. the screen / VALIDATE module names refused with COBOLNET1707/1710,
   the EC-*-IMP names DOC-A.1-100 says the implementation never sets). A name in (b) but not (c) is a dead guard; in (c)
