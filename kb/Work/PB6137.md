# PB6137 — the .tailor chain is not the CLDR chain

**Mechanism.** Two walks answer "which tailoring applies to locale X". `CldrLocaleLoader.Chain` / `ParentOf` walk the CLDR
inheritance chain: explicit parents (nb to no, es-MX to es-419) and script truncation. `TailoringRules.Candidates` walks "the base
tag, then the language". PB2763 made both read `LocaleTag` for the spelling and left the chain shapes alone, so the two still differ.

**Scenario.** A site installs `no.tailor`. The locale `nb` has the CLDR parent `no`, but the .tailor lookup tries `nb` and then the
language `nb`, never `no`: the site file is not applied. Likewise `es-419.tailor` is never read for `es-MX`. Which collation the
program sees depends on which walk answers. `wrong_answer` is possible (the order differs from what the site file configures), silent.

**Why it is a determination, not a unify wave.** Making the .tailor walk read the CLDR chain changes which site file applies to a
locale. That is a behavior change, so it needs a decision on the intended chain (DESIGN-locale-facility) before the code changes. It is
the R2 finding `runtime-text-1--duplication--f1#1`.

**Sites:**
- `src/WiseOwl.Cobol.Runtime/Collation/TailoringRules.cs` (`TailoringRules.Candidates`)
- `src/WiseOwl.Cobol.Runtime/Collation/CLDR/CldrLocaleLoader.cs` (`CldrLocaleLoader.Chain`, `CldrLocaleLoader.ParentOf`)

**Resolution (2026-11-24):** decision: the .tailor lookup follows `CldrLocaleLoader.Chain` (root excluded); `TailoringRules.Candidates` now reads it. Test `ForLocale_SiteFileOfACldrParentApplies`. Design doc updated. Sites changed: `TailoringRules.Candidates`, `TailoringRules` class summary.
