# PB652 — OPEN — a table rebuilt on every lookup

Found 2026-09-05 by the `PB635` implementer (report §"For the orchestrator" (B)), whose new render-time predicate
made the allocation visible: `src/Cobol.Net.Compiler/Binding/IntrinsicArgumentRules.cs:915`
`public static CobolClass[]? Admissible(char kind) => kind switch { … }` returns a new array literal per call, and
the call site at `:1017` (`Admissible(kind) is not { } ok || candidates.Any(ok.Contains)`) plus PB635's
`ArgumentRunIsAllNumeric` run it for every argument position of every intrinsic reference in a compilation. Bind-time
only, so no runtime cost; but a compilation of a large program with thousands of function references allocates
thousands of identical five-element arrays. One of the four required review lenses (performance) applied to a
mechanism that already exists.

## Fix

One `static readonly` array per kind (or a `FrozenDictionary<char, CobolClass[]>` / `ReadOnlySpan<CobolClass>`
switch expression, which allocates nothing), the switch returning the shared instance; the kind table's citations
stay on the table. Callers are unchanged. A unit row asserting reference-equality across two calls for the same kind
pins it.
