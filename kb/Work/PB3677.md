## Repro (measured by the PB3613 implementer on its branch build)

`E:/tmp/r3613/p1.cob`: `CALL "W" USING BY CONTENT FUNCTION MIN(F 3)` with `F` COMP-2 holding 0.0001 sends `0000100`,
where the same call AS NESTED and a MOVE of the function to a group send `000010000000000000000479`.

## Mechanism

A numeric function evaluated on the STANDARD-DECIMAL lane is first truncated by `ToUnscaledIntermediate(6, Truncation)`
because the Format-1 CALL argument is rendered without a receiver. This is the pre-existing receiver-less evaluation of
any Format-1 argument; the implementer left it as a design question (its comment was corrected, the behavior was not).
The reviewer's R1-2 LEAD named the same site: the comment said the Format-1 CALL reads the same digits as AS NESTED.

## Landed (2026-10-25, wave 20261500 group C) - an SDIDI value crosses a CALL at its own exponent

Re-probed on a fresh build: `CALL "W" USING BY CONTENT FUNCTION MIN(F 3)` (F COMP-2 0.0001) sent `0000100`, the value 2
(`MIN(H 3)`, H COMP-2 2) sent `2000000`, and with a REPOSITORY program-specifier a formal `PIC 9V9(12)` took `0.333333000000` of
0.3333333333333333 - all the same cause, one branch wider than the note's repro: the receiver-less landing
(`NumericRenderer.Landed`, `SdidiLandingScaleFloor` = 6) of an SDIDI value (a numeric function that returned one, or a
STANDARD-DECIMAL expression at a CALL whose formal the site cannot see) cut the value before any formal could.

Spec (each through `cite.py --check`): 14.2.3 GR9 moves the argument "without conversion" into a record the length of the
argument (first regime) and fills a numeric formal by "a COMPUTE statement without the ROUNDED phrase" (second regime, GR10
likewise), so only the formal cuts the value; D-B4 gives the group formal the digits of the function's value.

Fix at the root: `CobolArgAdapt.SdidiValue` builds the argument at the value's OWN exponent (Int128 cell at `-Exp` fraction
digits, capped at the carrier's 38, a positive exponent as its integer, the size error of every intermediate landing past the
carrier) and states its `Sending` from the value itself (`CobolDec.ToFunctionText`, `CobolNum.GroupDigits`), so the cell's cap
never shows in a character formal; `WithValueSending` keeps a sending operand already stated. `NumericRenderer.SdidiOf` is the
one question "is this intermediate an SDIDI value" that `Landed` and the CALL arm both ask. Sweep: every other `Landed`
consumer (SET pointer UP/DOWN BY, ALLOCATE, a keyed-I/O START length, an intrinsic argument) is a value-semantics scalar with
no formal to defer to, so the floor stays theirs; the INVOKE lane always knows the formal (`OoEmitter.FormalValue`).

Goldens: `pb3677_format1_sdidi_function_value` (M, C and D lanes agree; the REPOSITORY numeric formal) with its `_below_2002`
negative, `pb3677_format1_sdidi_expression` (STANDARD-DECIMAL `(2 / 3)` and `(1 / 8)` at a prototype-name CALL) with its
`_below_2014` negative, and `SdidiValueArgumentTests` (9 facts). Docs: CONFORMANCE D-B4, COBOLNET_INTERPROGRAM_DESIGN
(argument evaluation). Closes no inventory row.
