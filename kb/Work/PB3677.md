# PB3677 — a Format-1 CALL truncates a STANDARD-DECIMAL function argument to 6 fraction digits

**Sites:** `src/Cobol.Net.Compiler/CodeGen/Verbs/CallEmitter.cs` (the expression arm, `num.Render(expr.Expr, rcv)` with a
receiver-less `rcv`, and the comment at about line 1035), and the golden under `conformance-suite/cases/` that PB3613
added for the AS NESTED and MOVE lanes (a Format-1 leg is the new witness).

Filed 2026-10-24 by the enqueue unit's clerk. Both leads are from PB3613 (branch `worktree-wf_6ffe8083-b46-11`,
PR #535, still open and bounced to a finisher), report `E:\COBOL-coord\scratch\reports\w20261032e-PB3613-report.md`.
PB3613 is held by that branch, so this is a new note that links to it. Not re-probed.

## Repro (measured by the PB3613 implementer on its branch build)

`E:/tmp/r3613/p1.cob`: `CALL "W" USING BY CONTENT FUNCTION MIN(F 3)` with `F` COMP-2 holding 0.0001 sends `0000100`,
where the same call AS NESTED and a MOVE of the function to a group send `000010000000000000000479`.

## Mechanism

A numeric function evaluated on the STANDARD-DECIMAL lane is first truncated by `ToUnscaledIntermediate(6, Truncation)`
because the Format-1 CALL argument is rendered without a receiver. This is the pre-existing receiver-less evaluation of
any Format-1 argument; the implementer left it as a design question (its comment was corrected, the behavior was not).
The reviewer's R1-2 LEAD named the same site: the comment said the Format-1 CALL reads the same digits as AS NESTED.

## Open question for the implementer

What digits ISO requires a Format-1 BY CONTENT function argument to carry is a spec judgment the clerk did not make.
File as open; the fix must come from the spec (CALL BY CONTENT of a function result, §14.9.4) and the design doc, then
be applied to every receiver-less argument arm in the same emitter (sweep).
