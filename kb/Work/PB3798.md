# PB3798 — an agent can open a desktop application on the owner's screen

**Sites:** `scripts/hooks/forbidden_commands.py` (a new GUI-launch rule beside `WSL_LIFECYCLE`, and the check that applies it), `scripts/hooks/test_forbidden_commands.py`, `.claude/skills/workstream/templates/MANDATORY-PRACTICES.md` (a new row in the implementer section), `kb/Work/PB3789.md` (Acceptance)

## Measured

Wave 20261703 group B (PB3789: "kb/Work.base formula.blocked was never run in Obsidian") copied kb/Work into
E:/COBOL-coord/scratch/mythos/w20261703b/vault and ran `Start-Process` on Obsidian with a private user-data dir and a
DevTools port, several times (agent transcript wf_3fef8479-1cf agent-afd22715476573d79, commands 40-65), so Obsidian
windows kept opening on the owner's desktop. The session closed them with a watcher limited to that scratch vault. The
owner's standing rule that background work opens no windows (memory "background opens no windows") is in no brief and
no hook. PB3789's own acceptance invites it: it asks for the formula to be "run in Obsidian".

## Acceptance

- The guard hook refuses a command that starts a desktop GUI application (Obsidian, explorer of a folder, a browser,
  `Start-Process` of a .exe that is not a console tool, `start ""`, `Invoke-Item`), with a reason naming this note; a
  self-test case for each form, and one proving a console tool (`Start-Process pwsh -NoNewWindow`, dotnet) still runs.
- MANDATORY-PRACTICES gains the rule (no agent opens a window on the owner's desktop; a check that needs a GUI becomes an
  owner question in the report), enforced by the hook.
- PB3789's acceptance is restated so it is met without a GUI (a parser or evaluator test of the Bases formula, or an
  owner check named in the report).
