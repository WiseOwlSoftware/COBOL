# PB3798 — an agent can open a desktop application on the owner's screen

**Sites:** `scripts/hooks/forbidden_commands.py`, `scripts/hooks/test_forbidden_commands.py`, `scripts/hooks/gui_launch.py`, `scripts/hooks/shell_location.py` (`Step.shell`), `scripts/hooks/test_shell_location.py`, `docs/DOC_INDEX.md`

## Measured

Wave 20261703 group B (PB3789: "kb/Work.base formula.blocked was never run in Obsidian") copied kb/Work into
E:/COBOL-coord/scratch/mythos/w20261703b/vault and ran `Start-Process` on Obsidian with a private user-data dir and a
DevTools port, several times (agent transcript wf_3fef8479-1cf agent-afd22715476573d79, commands 40-65), so Obsidian
windows kept opening on the owner's desktop. The session closed them with a watcher limited to that scratch vault. The
owner's standing rule that background work opens no windows (memory "background opens no windows") is in no brief and
no hook. PB3789's own acceptance invites it: it asks for the formula to be "run in Obsidian".

## Acceptance

- The guard hook refuses a command that starts a desktop GUI application (Obsidian, explorer of a folder, a browser,
  `Start-Process` of a .exe that is not a console tool, `start ""`, `Invoke-Item`), with a reason naming this note; a
  self-test case for each form, and one proving a console tool (`Start-Process pwsh -NoNewWindow`, dotnet) still runs.
- The MANDATORY-PRACTICES row for the rule is written by PB3797, which edits that file (R3) and whose acceptance now carries it: this note stays off MANDATORY-PRACTICES.md so it is not held behind PB3728 (a Markdown section with spaces in its heading cannot be claimed as a member).
- PB3789 is retired (2026-10-25, superseded by PB3799); nothing to restate.

## Landed (wave 20261705 group A)

Rule 8 of `scripts/hooks/forbidden_commands.py` refuses a command that starts a desktop GUI application. The model is
the new `scripts/hooks/gui_launch.py` (`refusal(step)`), which reads the shared parser's steps (so `cmd /c`, `pwsh
-Command`, `bash -c`, substitutions and script blocks are walked, and a commit message, a `grep obsidian` or a heredoc
body that mentions the words is no launch): (1) launcher verbs (`Invoke-Item`/`ii`, `explorer`, `xdg-open`, `open`,
`wslview`, `rundll32` ...); (2) a named desktop application in command position, by name or path, also behind
`timeout`/`env`/`nohup`/`xargs`/`wsl -e`/`&` (Obsidian, browsers except `--headless`, editors, Office, chat clients);
(3) `Start-Process`/`saps`/`start` default-deny: allowed only for a console tool opened with `-NoNewWindow`,
`-WindowStyle Hidden` or cmd's `/b`, with no `-Verb`, and no GUI program handed to it through its arguments; (4) the
library forms (`[Diagnostics.Process]::Start`, `New-Object -ComObject Shell.Application|WScript.Shell`, Python's
`os.startfile`/`webbrowser.open`). New self-test cases (bash and PowerShell tools) cover every form the acceptance names
and the neighbours that must still run (`Start-Process pwsh -NoNewWindow`, dotnet, grep of the word); the hook is tested
only by feeding it command text. Not caught, as with any deny list: an unknown GUI executable run directly by path (add
its name to `GUI_APPS`) and a GUI launched from inside a script file an agent writes and then runs.
