# PB5275 - at --std 85 a SORT or MERGE written in a USE FOR DEBUGGING section compiles and runs: DeclCollectSection collects a debugging section without a BoundDeclarative, so DeclarativeAtCursor answers null there and the declaratives ban is never asked

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/ProcedureTableBuilder.cs` (`DeclCollectSection`)
- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/BinderContext.cs` (`DeclarativeAtCursor`)
- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/SortBinder.cs` (`ScreenDeclarativePlacement`)

**Mechanism.** SORT and MERGE may appear anywhere "except in the declarative portion" (§1985:XI.4.4.3 SR1, §1985:XI.4.1.3 SR1), and debugging sections are in the declaratives (§1985:XV.3.2.3 SR1). `SortBinder.ScreenDeclarativePlacement` refuses a SORT or MERGE when `BinderContext.DeclarativeAtCursor` finds a declarative, but `ProcedureTableBuilder.DeclCollectSection` collects a USE FOR DEBUGGING section as an ordinary pc range with no `BoundDeclarative`, so the cursor inside it is "not in the declaratives". A SORT in a USE AFTER ERROR section is refused (COBOL2700). Sweep: every other "not in the declaratives" rule that asks `DeclarativeAtCursor` has the same hole.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids below. None of them is recorded: the non-conforming verdicts wait in `E:/COBOL-coord/scratch/coderead-85/p2-for-register.json`.

**Rules (2 claimed; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-SR-XI.4.1.3-1` - `§1985:XI.4.1.3 SR1` (read: PARTIAL, harm: under-rejects): "A MERGE statement may appear anywhere in the Procedure Division except in the declaratives portion"
- `1985-SR-XI.4.4.3-1` - `§1985:XI.4.4.3 SR1` (read: DIVERGES; this note holds its debugging-section half (kb/Work PB5274 the other)): "except in the declarative portion"

**Repro.** `E:/COBOL-coord/scratch/coderead-85/out-pipe/work-slice-47/M2E.cob`: `SOURCE-COMPUTER. X WITH DEBUGGING MODE.`, `DECLARATIVES. DBG-SEC SECTION. USE FOR DEBUGGING ON MAIN-PARA. DBG-PARA. DISPLAY 'DEBUG-SECTION MERGING'. MERGE SW ON ASCENDING KEY SK USING IN1 IN2 GIVING OUT1. END DECLARATIVES.`; `cobol.exe --std 85 --source-format fixed --run M2E.cob`.

**Observed (a build of origin/main f2cf36fd15, rerun 2026-11-11; main has since changed only `IndexedConnector.cs` under `src/`, which none of these repros reaches).** exit 0: `DEBUG-SECTION MERGING`, `CCCC` (the MERGE ran inside the debugging section).

**Expected (from the 1985 text).** Refused at compile time, as in any other declarative section; §1985:XV.3.2.3 SR1 puts debugging sections "together immediately after the DECLARATIVES header".

**Fix direction (root cause, CLAUDE.md rule 4).** Give a debugging section its declarative record (a `BoundDeclarative` of kind debugging) so every declaratives rule sees it, then sweep the callers of `DeclarativeAtCursor` for a rule that must exclude debugging sections.
