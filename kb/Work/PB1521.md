# PB1521 — LANDED

## Evidence

- Run init line: `cwd=/home/user`. Smoke #1 (one repository attached) started IN the repo and its hooks fired;
  smoke #2 attached BrentRector/CobolSharp-private too (required for the submodule), and the platform then starts
  in the parent of both clones. The session's `/tmp/claude-code.log`: "Found 0 total hooks in registry".
- `git submodule status` → `-1dc65bb2… specs-private` (not checked out) until initialized by hand (2.2 s, fine).
- Unit: `Failed: 2, Passed: 29188` — both `ExternalCorpusPopulationDriftTests` (`Assert.Equal() Failure … Expected: 0
  Actual: 1` = the sweep's exit code). The corpus under `tests/external/` is git-ignored and per clone; CI fetches it
  with `scripts/fetch-gnucobol-tests.ps1`, the cloud never did. ⚠ Entry 1678 attributed these two reds to Python
  3.11; that was wrong — only `DerivedVerdictDriftTests` was the Python one (it is green on 3.14).

## Fix

- `scripts/cloud/setup-env.sh` installs a USER-level SessionStart hook (merged into `~/.claude/settings.json`) that
  runs the shim `/usr/local/bin/cobolsharp-session-start`; the shim runs the repo's `session_start.py` only when the
  project dir is NOT the repo (the project hook covers that case — never twice). It also pre-caches the pinned
  GnuCOBOL 3.2 tarball (same URL + SHA-256 as the fetch script) in `/opt/cobolsharp-cache/`.
- `scripts/hooks/session_start.py`, cloud branch: after the submodule init, copies the cached tarball into
  `tests/external/` and runs `fetch-gnucobol-tests.ps1` (which then skips the download).
