# PB857 — LANDED (by [[PB590]], 2026-09-21) — a declined clause's token decision, applied to a construct that is not declined

Source: the `PB646` implementer report, item A. Not PB646's mechanism — it refuses a DISPLAY-form and a BIT-form
boolean identically and did so before that landing.

## Repro — re-run on this tree

`scratchpad/reg4/probe/p19_boolean_class_cond.cob` (PROGRAM-ID `R4P19`), `--std 2023`:

```cobol
       01 BD PIC 1(3) VALUE B"101".
           IF BD IS BOOLEAN DISPLAY "BD BOOLEAN" ELSE DISPLAY "BD NOT" END-IF
```
```
(7,21): error COBOLNET0901: 'BOOLEAN' is a reserved word in COBOL-2023 and cannot be used as a user-defined word (ISO §8.9)
```

## The rules, quoted

```
$ python scripts/spec/cite.py --find "consists entirely of the boolean values"
  §8.8.4.4.4 3) d) 2.  (General rules)
      e) If BOOLEAN is specified, the condition is true if the content of the data item referenced by identifier-1 consists entirely of the boolean values '0' and '1'.
```

§8.8.4.4.2's general format prints BOOLEAN as one of the underlined alternatives; §8.8.4.4.3 SR3 admits an
identifier "whose usage is display or national" and SR5 bars only a numeric or numeric-edited operand. The rule
that defines the answer exists; the word cannot be written.

## Code site

There is no `BOOLEAN` lexer token. `src/Cobol.Net.Frontend/Grammar/Core/CobolDeclined.g4:106` states the absence
as a deliberate choice — *"Adding a BOOLEAN token to serve a construct we decline would edition-gate a word
across USAGE and the class condition for no behavioural gain"*. That reasoning holds for the DECLINED VALIDATE
`CLASS IS BOOLEAN` clause and does not hold for §8.8.4.4, which is a live construct with its own general rule.

## Sibling sweep the fixer owes

* Adding the token moves the word across `USAGE` (`USAGE BIT` / the boolean category) and the class condition
  at once — `feedback_edition_gate_sweep`: BOOLEAN is a 2002+ reserved word, so every `--std 85` program using
  BOOLEAN as a user-defined word must still compile.
* The other class-condition alternatives of §8.8.4.4.2's figure: check each of the fourteen against
  `classCondition` in the grammar, because this one was missing without anything noticing.
* `CobolDeclined.g4`'s comment must be corrected in the same change set (rule 6) — it will otherwise keep
  justifying the absence it no longer describes.
