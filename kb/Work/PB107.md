# PB107 — OPEN — collation engine residue (settings not implemented, build cost, NFD allocation)

> ⚙ **flags:** none harmful — every item is REPORTED (`CldrCollation.Unsupported`, `LocaleInfo.Unsupported`,
> `ResolvedLocaleCollation.Unsupported`) or a cost, never a wrong answer for what is claimed · registered 2026-08-19
> at the [[PB105]] / [[PB106]] landing so the residue is in the ONE register and not in prose.

## 1. CLDR settings the engine does not implement

- **`[caseLevel on]`** (`-u-kc-true`; one CLDR collation in release-48-2, a `search` type) — a separate case
  level between 2 and 3. Implementable as a level-2.5 pass over `ElementCase` in `Collator.Compare`/`GetKey`.
- **`[numericOrdering on]`** (`-u-kn-true`; no CLDR file uses it; a user key) — digit runs by numeric value.
  Implementable in the element iterator (a digit run → one synthetic primary sequence per UTS #35).
- **`[hiraganaQ on]`** (`-u-kh-true`; deprecated in CLDR) — not planned.
- **`<<<<` (quaternary relation)** — Japanese `private-kana` (116 relations): applied as an identity at levels 1–3;
  the kana length-mark distinctions collapse to equal. Implementable with a real level-4 weight line (the engine's
  level 4 today carries only the shifted variables' primaries).

Effect today: `ja` orders as ICU except those quaternary distinctions (the ICU cross-check corpus passes); every
other cross-checked locale (28) is identical to ICU. Which locales ask for what is visible per collation
(`CldrLocaleLoader.Load(tag).Find(type).Unsupported`) and per resolution (`LocaleManager.GetLocale(tag).Unsupported`).

## 2. The fixed cost of building a locale table (~6 ms)

`CldrBenchmarks`: `Build_Es` 6.1 ms / 10.8 MB for THREE rules — `CollationTable.Rebuild` copies the 41,724-element
pool and the 38,787-entry singles dictionary, and the tertiary line renumbers for almost every `<<<` (root
tertiaries are dense), so `Remap` rewrites the whole pool. Once per process per locale (resolved: 20 ns), so not on
any COBOL statement's path; but a host that resolves many locales pays ~6 ms each. Options: a shared pool with
per-table overlays (`Lookup` through a small override dictionary before the base pool), or reserving tailoring room in
the tertiary line at generation time (tertiaries × 4) so `<<<` stops renumbering. Measure before choosing.

## 3. The NFD allocation

`UnicodeBenchmarks`: `Nfd_Accented` 394 B per text vs the host's 32 B; `CollationBenchmarks`:
`Compare_MixedLocaleStrings` 93 B per comparison. `Normalizer.ToNfd` builds a `List<int>` and a string; a
stack/pooled buffer for short inputs (the common case) removes both. Ordering is unaffected.
