# PB5901 ruling

  quoted: "The Procedure Division is identified by, and must begin with, the following header"; the general format that follows is `PROCEDURE DIVISION [USING {data-name-1} ... ] .` (read on the rendered PDF page 541, folio X-25: E:/COBOL-coord/scratch/rulings-1985-open/s1/spec_p541.png; no BY, REFERENCE, VALUE or OPTIONAL in the header).

Sweep the siblings while there: the method/function header forms share the rule (already inside 2002-gated constructs, so only a sharper report). Goldens at --std 85: a refusal golden (`USING BY REFERENCE L1` -> COBOL0900 citing §1985:X.5.1), a refusal golden for the bare `USING REFERENCE L1` spelling (BY is optional in the grammar), and the `USING L1` control that compiles; a 2002 golden that accepts `USING BY REFERENCE L1`.
Reasoning: The 1985 Procedure Division header has exactly one form, printed in §1985:X.5.1 and confirmed on the rendered page: USING followed by data-names. BY REFERENCE in the header is a COBOL-2002 addition (2002 prints it in the header format), exactly like BY VALUE, which the compiler already refuses at 85 with COBOL0900. Accepting it at --std 85 accepts source the 1985 text does not define; no implementor latitude applies, so GnuCOBOL's behavior does not enter. The harm is under-rejection only: the program means the same as the plain `USING L1` (BY REFERENCE is the only 1985 parameter mode on the callee side), so no answer changes.
