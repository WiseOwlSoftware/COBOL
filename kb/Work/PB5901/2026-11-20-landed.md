# PB5901 landed, 2026-11-20 (wave 20262115, group A)

**Re-probe before the fix** (tree a2bd139087): `byref.cob` (`PROCEDURE DIVISION USING BY REFERENCE L1.`) at `--std 85`
exited 0 with no diagnostic.

**Fix.** A new construct row, `pd-header-by-reference-2002` (`tests/version-matrix/constructs/`, regenerated into
`ConstructRegistry.g.cs` and `Constructs.g.cs`), twin of `pd-header-by-value-2002`. `VersionConformancePass.ParseArm.VisitUsingByReference`
checks it whenever the `usingByReference` node is recognized. The node exists only when REFERENCE is written, so a plain
`USING L1` never reaches the check, while both `BY REFERENCE` and the bare `REFERENCE` spelling do. The node serves the
program, function and method headers alike (one `usingClause` rule). Below 2002 a function or method header is already
inside a 2002 construct, so there the extra report is only a sharper message.

**After:** at 85, `pb5901-using-by-reference-at-85` and `pb5901-using-reference-without-by-at-85` are refused with
`COBOL0900: the PROCEDURE DIVISION USING BY REFERENCE phrase requires COBOL-2002`. At 2002, `pb5901_using_by_reference`
runs and prints XYZ (the callee's store reaches the caller).

**Sweep.** No conformance test accepted at 85 writes BY REFERENCE in a Procedure Division header (searched with grep
over `conformance-suite/cases` and `wiseowl/cases`). The CALL statement's BY REFERENCE belongs to 1985 itself
(§1985:X.5.2.2), so it has no construct row.
