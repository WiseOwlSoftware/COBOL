# PB175

Found 2026-08-30 by the PB168 pre-landing review's mechanical step: `python scripts/semgrep/verify.py`
FAILs on the CLEAN tree at `e71c031d` — `cobolnet-no-biginteger` 4 → 34 (+30), 
`cobolnet-raw-diagnostic-code-literal` 423 → 472 (+49), `cobolnet-no-decimal` 3 → 2 (a DOWN, also
unbaselined). Verified by stash/verify/pop that the PB168 working-tree diff contributes ZERO of these —
the drift landed with earlier batches.

Two halves:

1. **Adjudicate the drift.** For each rule, diff the current findings against the baseline set and
   disposition each new site: a genuine violation gets fixed (the banned-numeric rules exist because
   `COBOLNET_DESIGN.md` §1.2 bans those types outside their sanctioned homes); a sanctioned use gets an
   explicit recorded decision, and only then a re-baseline. +30 BigInteger sites is the suspicious one —
   the sanctioned arbitrary-precision home is CobolDec's SDIDI internals; 30 new sites suggests a
   mechanism leaked outward. The raw-diagnostic-literal count (+49) is likelier benign accretion
   (`ctx.Edition.Error("COBOLNETnnnn", …)` call sites the descriptor migration has not reached), but each
   still needs the look. The DOWN on no-decimal must also be re-baselined — a baseline that overstates
   violations hides the next UP.

2. **Give the check a gate seat.** The drift was invisible because verify.py runs in NO gate — not
   build-local, not battery.sh (green_gates_arent_evidence: a check nobody runs cannot go red). Add it as
   a battery leg (it is seconds, no build dependency) so baseline drift fails the comprehensive gate the
   batch it lands, with the usual verdict-line read.
