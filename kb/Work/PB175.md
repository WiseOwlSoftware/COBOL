# PB175

Found 2026-08-30 by the PB168 pre-landing review's mechanical step: `python scripts/semgrep/verify.py`
FAILs on the CLEAN tree at `e71c031d` — `cobolnet-no-biginteger` 4 → 34 (+30), 
`cobolnet-raw-diagnostic-code-literal` 423 → 472 (+49), `cobolnet-no-decimal` 3 → 2 (a DOWN, also
unbaselined). Verified by stash/verify/pop that the PB168 working-tree diff contributes ZERO of these —
the drift landed with earlier batches.

Two halves:

1. **Adjudicate the drift.** For each rule, diff the current findings against the baseline set and
   disposition each new site: a genuine violation gets fixed (the banned-numeric rules exist because
   `COBOLNET_DESIGN.md` §1.2 bans those types outside their sanctioned homes); a sanctioned use gets an
   explicit recorded decision, and only then a re-baseline. +30 BigInteger sites is the suspicious one —
   the sanctioned arbitrary-precision home is CobolDec's SDIDI internals; 30 new sites suggests a
   mechanism leaked outward. The raw-diagnostic-literal count (+49) is likelier benign accretion
   (`ctx.Edition.Error("COBOLNETnnnn", …)` call sites the descriptor migration has not reached), but each
   still needs the look. The DOWN on no-decimal must also be re-baselined — a baseline that overstates
   violations hides the next UP.

2. **Give the check a gate seat.** The drift was invisible because verify.py runs in NO gate — not
   build-local, not battery.sh (green_gates_arent_evidence: a check nobody runs cannot go red). Add it as
   a battery leg (it is seconds, no build dependency) so baseline drift fails the comprehensive gate the
   batch it lands, with the usual verdict-line read.

## Re-measured 2026-09-02 at the cluster-D landing — the raw-literal count went DOWN for the first time

`cobolnet-raw-diagnostic-code-literal` **475 → 439** (−36), the first decrease this note has recorded, and
it was earned rather than re-baselined. Three CODES accounted for 38 of the findings and had **no catalogue
descriptor at all** — `COBOLNET0869`, `COBOLNET0881` and `COBOLNET1529` were emitted from 38 bare string
literals across five binders (`DataBinder` 16 · `SetBinder` 9 · `PtrBinder` 6 · `PictureAnalyzer` 5 ·
`ConditionBinder` 2) and from nowhere else, so they had no `docs/DIAGNOSTICS.md` row, no drift test, and
nothing for `session-probe`'s next-free scan or the suppress-key machinery to see.

⚠ **See the 2026-09-04 section at the foot of this note: the baseline FILE has now been regenerated to
36 / 439, so `verify.py` is green again and an `UP` means a real increase. Half 1 — adjudicate and fix the
drift — and half 2 — give the check a gate seat — are both still OPEN.**

⛔ **They are BANDS, and that is why nobody had catalogued them**: one code over a family of neighbouring
rules, which does not fit a naive one-code-one-rule reading of the descriptor. It fits the catalogue as it
actually stands — `COBOLNET1720` (`io-phrase-forbidden-here`) already spans three syntax rules and
`COBOLNET1707` four statement formats — so each got a descriptor whose Title states the BAND while the site
composes the rule it caught: `pointer-operand-shape` (§14.9.39 · §8.4.3.11 · §8.4.3.13 · §8.8.4.2.16 ·
§14.9.3 · Annex D.9.2.2), `usage-clause-compatibility` (§13.18.60.3 · §13.18.60.4 · §13.18.40.3 ·
§13.18.63) and `type-declaration-shape` (§13.18.58 · §13.18.57.3 · §8.5.3.1 · §8.5.3.3).

**No emitted byte changed**: `EditionContext.Error(DiagnosticDescriptor, string)` forwards to
`Error(descriptor.Code, string)`, so every message is identical and the wave gate proves it. The remaining
439 are the same shape over codes that likewise have no descriptor; the same conversion closes them, and it
is now demonstrably mechanical. `cobolnet-no-biginteger` is unchanged at **4 → 36**.

⚠ **The baseline to compare a landing against is therefore 36 / 439**, not 36 / 475.

## 2026-09-04 — the baseline FILE is regenerated to the registered red, because `UP` had stopped meaning anything

`scripts/semgrep/verify.py` reads exactly one file for its CHECK 2 comparison —
`scripts/semgrep/baseline.json` — and that file still held the **pre-drift** counts (`cobolnet-no-biginteger` 4,
`cobolnet-raw-diagnostic-code-literal` 423, `cobolnet-no-decimal` 3). Confirmed by reading the script, not
assumed: `BASELINE = HERE / "baseline.json"`, `base = json.loads(BASELINE.read_text(...))`, and `--update-baseline`
is the only writer.

Measured on this tree before the change:

```
CHECK 2 — greenfield findings vs baseline
   OK    cobolnet-bound-node-carries-rendered-text: 3 -> 3
   UP    cobolnet-no-biginteger: 4 -> 36
   DOWN  cobolnet-no-decimal: 3 -> 2
   UP    cobolnet-raw-diagnostic-code-literal: 423 -> 439
FAIL: new violations introduced.
```

**The cost was real and recurring.** `verify.py` is in every lander's step 3, so it printed `UP` and exited 1 on
**every clean landing**, and each lander had to re-derive from scratch that its own diff contributed none of it —
PB383's lander did exactly that today. A check that is red on a clean tree teaches its readers to skip it, which
is the same failure half 2 of this note is about.

Regenerated with `python scripts/semgrep/verify.py --update-baseline` to the counts **measured on this tree**:

| rule | file held | now records |
|---|---|---|
| `cobolnet-bound-node-carries-rendered-text` | 3 | **3** |
| `cobolnet-no-biginteger` | 4 | **36** |
| `cobolnet-no-decimal` | 3 | **2** |
| `cobolnet-raw-diagnostic-code-literal` | 423 | **439** |

`python scripts/semgrep/verify.py` now exits **0** with all four `OK`, so an `UP` is again a real increase and a
lander's step 3 is once more a signal.

⛔ **This is bookkeeping, not absolution, and it does not close this note.** The file now agrees with the figure
this note had already registered as the comparison point (36 / 439) — it does not adjudicate a single one of the
32 `BigInteger` sites or the 439 raw-literal sites. Half 1 (disposition each new site: fix it, or record an
explicit decision) and half 2 (give `verify.py` a battery seat, so drift fails a gate the batch it lands rather
than being discovered by a review) are both untouched and still open. The `no-decimal` DOWN from 3 to 2 is locked
in by the same regeneration, so a regression there is now visible.
