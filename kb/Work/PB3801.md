# PB3801 — remove the GUI-launch guard; the fix is not running Obsidian

**Sites:** `scripts/hooks/gui_launch.py` (deleted), `scripts/hooks/forbidden_commands.py` (the GUI-launch arm, rule 8, its import and its docstring line), `scripts/hooks/test_forbidden_commands.py` (the GUI-launch cases), `scripts/hooks/shell_location.py` (`Step`: keep PB3798's parsing-shell field only if another caller uses it, else revert it)

## Why

An agent opened Obsidian because a note (PB3789, now retired) asked for a Bases formula to be "run in Obsidian". PB3799
deletes the Obsidian views, so nothing in the project gives an agent a reason to start it. PB3798 then built a 368-case
filter over every shell command, and its review found forms it still misses (PB3800, retired): a filter of this kind is
never complete and runs on every command. The owner rules the cause is fixed by not running Obsidian, and the filter is
overhead.

## Acceptance

- `gui_launch.py` is deleted and `forbidden_commands.py` no longer imports or applies it; the hook's self-tests pass
  with the GUI cases removed; no reference to `gui_launch` remains outside DEVLOG/ and kb/Work/ (CLAUDE.md rule 4).
- PB3798 gains a `## Superseded` line naming this note.
- The one-line agent rule ("start no desktop application") stays in MANDATORY-PRACTICES through PB3797; it is text,
  not a filter.
