# PB6145 - two push shapes pass the guard hook

Both are stopped by git's own `.githooks/pre-push` (PB6136), so a stamp still cannot reach origin while `core.hooksPath` is set; each is a
hole in the agent-side layer alone, which matters on `--no-verify` or an unset hooks path.

- **R2-1.** `git push --follow-tags` (or `-c push.followTags=true`) publishes an annotated tag pointing at a commit already on origin; rule
  2c scans only tags named on the line, `--tags` and `--mirror`. Fix: under follow-tags, scan every local annotated tag on the pushed
  history that origin lacks.
- **R2-2.** A push after a non-git step that creates a commit (`python mk.py`, `devlog.py`, `git_merge.py`) passes, and so does
  `git fetch . HEAD:refs/heads/other && git push origin other`, because the scan drops a source ref that does not yet exist. Fix: an
  unresolvable source fails closed; a push that follows any step not on the read-only list is refused as a separate-command push (P12).
