# PB4001 — test-numval-national-argument-in-error: TEST-NUMVAL, TEST-NUMVAL-C and TEST-NUMVAL-F return 1 for a valid national argument

Filed 2026-10-28 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-20261027-215606`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

Under `-std=cobol2014`, `FUNCTION TEST-NUMVAL`, `TEST-NUMVAL-C` and `TEST-NUMVAL-F` return 1 for a national argument
whose content is a valid number, such as a PIC N(3) item holding N"123" or the literal N"123.45". The same item gives
123 through `NUMVAL`, `NUMVAL-C` and `NUMVAL-F`, so the value functions accept it and the test functions reject it. ISO
requires 0 when the argument's content conforms to the matching NUMVAL format, and it allows a national argument.
The validators read the national item's storage bytes as alphanumeric characters: the first byte of a UTF-16 code unit
for a digit is 0x00, which is not a valid character, so position 1 is reported. Class: wrong output.
Found by the differential fuzz run fuzz-20261027-215606: TEST-NUMVAL-F of a valid national item in fz00641, fz04166 and
fz05576 (1 where 0 is required), and TEST-NUMVAL of N"12A4" in fz05298 (1 where the first character in error is 3).

## Minimal test case

Free reference format (`-free`), 16 lines, written for this record.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. TNNAT.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 WS-N PIC N(3) VALUE N"123".
01 WS-R PIC S9(4) VALUE 0.
PROCEDURE DIVISION.
    COMPUTE WS-R = FUNCTION NUMVAL(WS-N)
    DISPLAY "NUMVAL " WS-R
    COMPUTE WS-R = FUNCTION TEST-NUMVAL(WS-N)
    DISPLAY "TEST-NUMVAL " WS-R
    COMPUTE WS-R = FUNCTION TEST-NUMVAL-F(WS-N)
    DISPLAY "TEST-NUMVAL-F " WS-R
    COMPUTE WS-R = FUNCTION TEST-NUMVAL-C(WS-N)
    DISPLAY "TEST-NUMVAL-C " WS-R
    STOP RUN.
```

## Environment

- `cobc (GnuCOBOL) 3.2.0`, on WSL2 Ubuntu.
- Compiled with `cobc -x -free -std=cobol2014 -o p prog.cob` (two `-Wunfinished` warnings on line 5, "handling of USAGE
  NATIONAL is unfinished" and "handling of national literal is unfinished", and the C compiler's "'_FORTIFY_SOURCE'

- Run with `timeout 10 ./p`.

## Observed result

```
NUMVAL +0123
TEST-NUMVAL +0001
TEST-NUMVAL-F +0001
TEST-NUMVAL-C +0001
```

Exit code 0. The fuzz program fz00641 shows the same for `TEST-NUMVAL-F` of a PIC N(20) item holding N"123.45"
(1 where 0 is required), and a probe shows it for the literal `FUNCTION TEST-NUMVAL-F (N"123.45")`. The same probe
shows `NUMVAL-C` and `NUMVAL-F` of WS-N returning 123 as `NUMVAL` does, and `TEST-NUMVAL` of a PIC N(4) item holding
N"12A4" returning 1, where the first character in error is in position 3.

## Expected result (per ISO)

- §15.93.3 1): "Argument-1 shall be an alphanumeric or national literal or a data item of class alphanumeric or
  national." §15.95.3 1) says the same for TEST-NUMVAL-F, and §15.94.3 1) gives TEST-NUMVAL-C the NUMVAL-C argument
  rules, where §15.68.3 1) says "Argument-1 shall be of category alphanumeric or national."
- §15.67.3 1) and §15.69.3 1) define the NUMVAL and NUMVAL-F argument content for "an alphanumeric or national literal
  or ... data item"; "123" is a digit string in that format.
- §15.93.4 1) a): "If the content of argument-1 conforms to the argument rules for the NUMVAL function," the returned
  value is 0. §15.95.4 1) a) and §15.94.4 1) a) say the same for NUMVAL-F and NUMVAL-C.

Edition: TEST-NUMVAL, TEST-NUMVAL-C and TEST-NUMVAL-F are in ISO/IEC 1989:2014 (cobc 3.2 accepts them under
`-std=cobol2014`, and `docs/VERSION_CHANGE_REFERENCE.md` lists no 2014-to-2023 change to them). The 2009 committee
draft for ISO/IEC 1989:2014 (CD 1.2, std.txt) has the same argument and returned-value rules under other numbers: 15.86
TEST-NUMVAL, 15.87 TEST-NUMVAL-C (the arguments of 15.63 NUMVAL-C, "Argument-1 shall be of category alphanumeric or
national") and 15.88 TEST-NUMVAL-F, with 15.62 NUMVAL and 15.64 NUMVAL-F admitting an alphanumeric or national
literal or data item. Expected output:

```
NUMVAL +0123
TEST-NUMVAL +0000
TEST-NUMVAL-F +0000
TEST-NUMVAL-C +0000
```

## Our compiler

WiseOwl COBOL (fresh judge `E:\tmp\fuzz-judge-20261028\cobol.exe`, `--std 2014 --source-format free`) compiles the
program with no diagnostic and prints the expected output: `NUMVAL +0123`, then 0 from each of the three test functions.

## Fix site

`libcob/intrinsic.c`: `cob_check_numval` (used by `cob_intr_test_numval` and `cob_intr_test_numval_c`) and
`cob_check_numval_f` (used by `cob_intr_test_numval_f`) walk `srcfield->data` one byte at a time as alphanumeric
characters. Each carries the comment "FIXME later: srcfield may be of category national...", so the gap is known in the
source. The value function `numval` reaches the right value for the same item.
