# PB204

**Split out of [[PB177]] at the cluster-A landing (2026-08-31).** PB177 arm C item 2 carried this as a "GATED
REMAINDER … left OPEN, as a bare question for the owner". It is not an owner question — the no-deferral rule
makes implementation the default and the campaign order is the director's call — so it becomes its own note and
PB177 lands. Nothing about the item changed; only where it is tracked.

## The rule

§14.9.4.3 SR25 read with §14.8.2.2 / §14.8.3.2 and §8.5.1.12 ADMIT a variable-length group across a Format-2
`CALL`, `CALL … RETURNING` and `INVOKE` boundary, **subject to a compatibility relation**. §8.5.1.12.2 gives the
positional correspondence and §8.5.1.12.3 the matching algorithm. This compiler's boundary carrier is a
FIXED-WIDTH character image, which a variable-length group does not have, and no `VariableLengthCompatibility`
predicate exists anywhere in the tree (grep: zero hits).

## Measured posture — LOUD, and that is the one good thing about it

`--std 2023`, verified 2026-08-31 at the cluster-A landing:

```cobol
01 VG.
   05 VD PIC X DYNAMIC LENGTH.
   05 VF PIC X(3).
...
CALL "W12SUB" AS NESTED USING VG
```

→ `error COBOLNET1688: CALL … AS NESTED argument 1 ('VG') does not conform to formal parameter 'LVG': argument
group 'VG' with a dynamic-length / dynamic-capacity member (a variable-length group has no fixed record window)
— the Tier-C byte island (no whole-group character image), deferred; COBOLNET_DESIGN §4.2 (ISO §14.8.2)`.

So it is a **compile-time rejection of legal source**, not a silent wrong answer and not a backend crash. That
is the right interim posture for a deferral (it is loud, it names the deferral, and it cannot corrupt data) —
which is why this note is `rejects_legal_source: true` with `crashes` and `silent` both false. It is still debt.

## What the fix is

A CURRENT-EXTENT carrier for the crossing, plus §8.5.1.12.2's positional correspondence and §8.5.1.12.3's
matching algorithm as a real `VariableLengthCompatibility` predicate at the three boundary sites. It belongs to
[[PB164]]'s variable-length-group family rather than to the crash-fix family PB177 landed: the boundary carrier
is the same fixed-width-image assumption PB164's Tier-C island is built on, and fixing one without the other
would leave two answers to "what is this group's extent at a boundary".

⚠ Do NOT reach for the ODO current-extent machinery as-is. §13.18.38.4 GR8's current extent is a SENDING-OPERAND
rule; `CallEmitter.CallStringRead`'s own doc-comment records why the boundary deliberately carries the FULL
allocation instead (§14.2.3 GR8's storage aliasing, NIST IC207A). A variable-length group's crossing needs its
own extent contract, derived from §8.5.1.12, not a re-use of GR8's.


## ✅ LANDED WHOLE — the relation, the carrier, and the RETURNING half nobody had noticed was missing

**Re-probed first, on a build of this worktree.** The note's repro reproduced exactly (`COBOLNET1688` at
compile time), and re-probing found the surface WIDER than the note recorded: only the BY REFERENCE leg was a
compile-time rejection. `CALL … AS NESTED USING BY CONTENT VG` and `CALL … AS NESTED RETURNING VG` were
**RUNTIME** `NotImplementedCobolFeatureException`s, because `DescriptionMismatch` runs only for
`Mode is Reference` and because **no §14.8.3 RETURNING conformance check existed for an AS NESTED call at all**
— the nested-callee table carried the callee's formals and not its returning item.

**THE RULE.** §14.9.4.3 SR12 — "Identifier-2 shall not reference a variable-length group" — is FORMAT 1's, and
sits under the printed FORMAT 1 heading that opens at SR10 and closes at SR13. Format 2's law is SR25: "The
rules for conformance specified in 14.8.2, Parameters and 14.8.3, Returning items apply", and both of those
ADMIT the crossing: §14.8.2.2 "If either the formal parameter or the argument is a variable length group, the
formal parameter and the argument shall be compatible, as described in 8.5.1.12", §14.8.3.2 the same sentence
over a RETURNING pair. Every citation re-run through `cite.py --check`.

**THE RELATION — `VariableLengthCompatibility`, ONE positional walk, not three passes.** §8.5.1.12.1's three
numbered conditions are three statements about the same left-to-right byte accounting, so they are one walk over
a FLAT atom sequence (REDEFINES subtrees dropped per §8.5.1.12.1; scalar subordinate groups flattened, because
the relation is stated over relative byte positions and is blind to the declaration tree). **The byte accounting
is not re-derived**: `DataItem.ByteWidth` already satisfies §8.5.1.12.3's two collapse conventions BY
CONSTRUCTION — a dynamic-length item's `ElementaryImageWidth` is 0, and a dynamic-capacity table carries no
`Occurs` so a parent sums exactly one element. The one convention the walk applies itself is sentence 3's "the
dynamic-capacity table is considered to be the same length as the corresponding table", which is a fact about a
PAIR and therefore cannot live on either item.

**THE CARRIER — `CobolVarGroup(string Fixed, string[] Dynamic)`, a THIRD crossing form.** A fixed-length group
crosses as one string because §14.2.3 GR8's "same storage area" has a fixed window; a variable-length group has
none, and a flat image is not invertible (the receiver cannot see where a dynamic member's content ends). The
carrier is the §8.5.1.12 model itself: the fixed run with every variable-length component collapsed to nothing —
the very accounting under which compatible groups agree — plus each component's current content in declaration
order. Nested variable-length groups FLATTEN into it (`Slice` hands a nested group its window back), so the
correspondence stays nesting-blind. Emitted as `AsVarImage()`/`FromVarImage()` beside `CurrentImage()`, gated on
**the same** `CurrentExtentImageCapable` capability — moved from `GroupImageCodec` onto `DataItem`, because a
BIND-time screen now has to ask it and a bind phase consulting a codegen class is the layering inversion.

**LANDED, and measured working end to end** (`2023/pb204_vlg_boundary`, `2023/pb204_vlg_invoke` — both matched
their spec-derived expected output on the FIRST run):

- Format-2 `CALL … USING` BY REFERENCE, with write-back — including a formal whose fixed prefix is split
  differently from the argument's, which is what proves §8.5.1.12.2 keys on byte position.
- `CALL … USING BY CONTENT` (§14.2.3 GR9 — a detached cell; the callee's stores reach nothing).
- `CALL … RETURNING`, and `INVOKE … USING … RETURNING` in both directions.
- A dynamic-capacity table crosses at its CURRENT capacity, GROWS in the callee, and comes home grown — the
  receiving side recovering the capacity by dividing by its own element width, which is legitimate exactly
  because §8.5.1.12.3 admits corresponding tables only "when the byte length of their elements is equal".
- The OO UNIVERSAL crossing too: `ConformanceDescriptor` gained a `V:` form from
  `VariableLengthCompatibility.Signature`, so bind no longer refuses such an operand with COBOLNET0866 — and,
  more importantly, `__CobolInvoke` no longer spells `(string)box!` into a `ref CobolVarGroup` parameter, which
  would have been a CS1503 on a method merely DECLARING one (the [[PB177]] arm-A shape).

**THE SIBLING SWEEP FOUND THE RETURNING HALF.** `NestedCallablesOf` carried only `LinkageFormals`, so §14.8.3
was unchecked for EVERY AS NESTED call, not just for variable-length groups: a returning pair of plainly
different descriptions reached the emitter undiagnosed, and §14.8.3.1's "if and only if" presence rule was
unenforced. `NestedCalleeSignature` now carries both halves (the `UserFunctionSignature` shape, which has
carried both since it was written) and **COBOLNET1736** reports the mismatch through THE SAME comparator.

**Diagnostics:** COBOLNET1736 (`call-returning-conformance`) added; COBOLNET1737 not needed.
**Verdicts:** `GR-8.5.1.12.1-1/-2/-3` GAP → CONFORMS (each with its own positive AND negative witness — rule 1
`pb204-nested-vlg-table-correspondence`, rule 2 `pb204-nested-vlg-element-width`, rule 3
`pb204-nested-vlg-position` + `pb204-nested-returning-incompatible`); `SR-14.9.4.3-25` stays PARTIAL with its
residue list corrected (the RETURNING half is closed; BY CONTENT/BY VALUE at the CALL boundary, the dynamic
Format-1 runtime EC, and the prototype lane remain). GAP 3013 → 3010.

**NAMED RESIDUE, unchanged in shape and still loud:** a variable-length group OUTSIDE
`CurrentExtentImageCapable` — an OCCURS DEPENDING member, or a runtime-length item inside a table element —
keeps the documented Tier-C loud rather than acquiring a half-built crossing. That is [[PB164]]'s existing
boundary (CONFORMANCE.md row 57), deliberately not a second one. §8.5.1.12.1's OTHER admission — MOVE and
comparison of a variable-length group against a compatible group — is a different verb's business and is not
touched here.
