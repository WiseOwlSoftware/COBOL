# PB5530 - the other COBOL1965 messages of SearchAllFormat2Rules (SR7, SR10-SR13 and the 2023 KEY-membership refusal at 85) still cite §2023 at 85, 2002 and 2014, and docs/VERSION_CHANGE_REFERENCE.md has no 85 to 2002 row for the two PB5193 sentences

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Validation/SearchAllFormat2Rules.cs` (`SearchAllFormat2Rules.Check`, `CheckKeySide`, `CheckConditionNameSide`, `CheckSendingSide`: every COBOL1965 message string that names `§2023`), `docs/VERSION_CHANGE_REFERENCE.md` (the SEARCH ALL rows)

**Mechanism.** PB5193 (landed) made `CheckKeySubscript` edition-aware so the 2023 SR8 text does not claim `K (IX + 1)` is illegal at 85 (review R1-2). The sibling messages in the same file were left: SR7 (line 77), SR10 to SR13 (lines 220, 249, 264, 317-411) and the 2023 key-membership refusal at 85 for an unsubscripted `K = 05` ("not referenced in the KEY phrase", line 249, `§2023:14.9.37.3 SR8`, checked with `cite.py --check`) all quote or cite §2023 at 85, 2002 and 2014, where the governing rule is that edition's own (PB5193's `1985-SR-VI.6.22.3-4` record). The message misleads a user of the older edition about which standard refuses the program. PB5193 and PB5005 (open, the PB4154/PB4947 sweep witness) do not cover the message citations. Second item: `docs/VERSION_CHANGE_REFERENCE.md` has no 85 to 2002 row for the two sentences PB5193 relaxed, and the row needs a `constructs/` anchor.

**Fix direction.** Make every COBOL1965 message pick its citation from the edition (one helper, not per-message ifs), and add the version-change row with its construct anchor; a drift test that no message string at a lower edition names `§2023` keeps the next message automatic.
