## Measured

### Finding record-clause — 13.18.43.4 GR6 (also GR2, GR1) (wrong-answer; rows GR-13.18.43.4-6, GR-13.18.43.4-2, GR-13.18.43.4-1)

**Mechanism.** Format 1 RECORD CONTAINS integer-1 sizes nothing for a record-bearing file: DataBinder.BindRecordClause stores integer-1 only in FileModel.RecordContains (read solely for a report file's line width) and every connector is registered with RecordWidth, the largest record description, so a file whose descriptions are smaller than integer-1 writes records of the description's size instead of integer-1 bytes.

**Repro.** out13/probe/record-clause/p2.cob: FD F1 RECORD CONTAINS 20 CHARACTERS. 01 R1 PIC X(10). WRITE 'ABCDEFGHIJ', WRITE 'KLMNOPQRST', CLOSE; then read the same file through FD F2. 01 R2 PIC X(20). until status 10.

**Expected, from the standard.** Two records of 20 bytes (file 40 bytes); the first R2 starts 'ABCDEFGHIJ'; RECORDS=02. §13.18.43.4 GR6: 'Integer-1 specifies the number of bytes contained in each record in the file'; GR2: the explicit RECORD clause 'specifies the size of records in the record area'; §13.18.43.3 SR3 allows descriptions smaller than integer-1.

**Observed.** The file is 20 bytes; one record R2=[ABCDEFGHIJKLMNOPQRST]; RECORDS=01. p1.cob: a single WRITE gives a 10-byte file. No diagnostic; data from two logical records merges into one for any reader that honours the clause.

**Code site.** src/Cobol.Net.Compiler/Binding/DataBinder.cs#BindRecordClause (fixed arm: file.RecordContains = n0; return); src/Cobol.Net.Compiler/Binding/Model/FileModel.cs#RecordWidth / #RecordContains; the connector registration in src/Cobol.Net.Compiler/CodeGen/Verbs/SequentialIoEmitter.cs and KeyedIoEmitter.cs

### Finding record-clause — 13.18.43.4 GR10 (wrong-answer; rows GR-13.18.43.4-10)

**Mechanism.** Two-arm dispatch on the unstated maximum: FileModel.VaryMax is `v.Max ?? Math.Max(1, RecordWidth)` for an explicit RECORD IS VARYING clause without TO, but `RecordMax` (MaxRecordSize, which includes a dynamic-length member at its maximum per GR8 b) for the implied Format 2 clause. RecordWidth is the character-window width and leaves out out-of-line and dynamic extents.

**Repro.** out13/probe/record-clause/p12.cob: FD F3 RECORD IS VARYING IN SIZE. 01 R3. 05 A3 PIC X(3). 05 D3 PIC X DYNAMIC LENGTH LIMIT 20. MOVE 'AAA' TO A3, MOVE 14 characters TO D3, WRITE R3. p12b.cob: the same program with the RECORD clause deleted.

**Expected, from the standard.** GR10: with no integer-3 the maximum is 'the greatest number of bytes described for a record in that file', which is 3 + 20 = 23 (GR8 b). The 17-byte record is in range, so FS=00, the same as the implied-clause program.

**Observed.** Explicit clause: FS=44 and nothing written (the maximum is taken as 3). Implied clause (p12b): FS=00 and a 17-byte frame. The same rule has two formulas.

**Code site.** src/Cobol.Net.Compiler/Binding/Model/FileModel.cs#VaryMax (explicit arm uses RecordWidth; implied arm uses RecordMax)
