# PB1081 — OPEN — `fileDescriptionClause` (CobolData.g4) still admits `organizationClause`, `accessModeClause` and `recordKeyClause`, which no §13.4.5.2 file-description format c

## Rule text (every citation re-run by the registrar)
- (format / grammar-shape finding; the printed format is quoted in the finding below)

### Adjudicator finding (general, harm under-rejects)
- **Mechanism:** The FD grammar (fileDescriptionClause, CobolData.g4:69-71) admits organizationClause, accessModeClause and recordKeyClause, which §13.4.5.2's closed file-description formats do not contain, and the binder never reads them: the clauses are accepted and silently ignored at every edition
- **Repro:** FD SQ ORGANIZATION IS INDEXED ACCESS MODE IS DYNAMIC. 01 SQ-REC PIC X(2).  (SQ's SELECT is a plain sequential file) -- compile with --std 85 or 2023 and run
- **Expected (spec):** §13.4.5.2 Formats 1-3 list only EXTERNAL, GLOBAL, FORMAT, BLOCK CONTAINS, record-clause, linage-clause, CODE-SET (and REPORT for Format 3); ORGANIZATION / ACCESS MODE / RECORD KEY are file-control-entry clauses (§12.4.5.1), so the FD entry is not conforming source and shall be diagnosed (at minimum a non-standard-extension diagnostic at strict --std)
- **Observed:** Pinned cobol.exe compiles gG.cob ('FD SQ ACCESS MODE IS RANDOM.') and gH.cob ('FD SQ ORGANIZATION IS INDEXED ACCESS MODE IS DYNAMIC.') with no diagnostic and runs them as a plain sequential file (SSEQ S2/S1/S0). The only references to accessModeClause in src/Cobol.Net.* are the file-control arm (DataBinder.cs:994); the FD alternatives are dead. PB829 (landed) closed the genericClause catch-all in the FD format but not these named alternatives. Out of this subject's rows; recorded as a lead for the registrar.
- **Code site:** src/Cobol.Net.Frontend/Grammar/Core/CobolData.g4#fileDescriptionClause
- **Clause (adjudicator):** 13.4.5.2
