# PB5523 - CODE ALL symbolic-character-1 admits a NATIONAL symbolic character as the alphanumeric literal-1: LiteralEnvironment.SymbolicValue drops the National flag SpecialNamesBinder.SymbolicOf carries

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/ReportSectionBinder.cs` (`ReportSectionBinder.CodeFigurativeCharacters`), `src/WiseOwl.Cobol.Compiler/Binding/LiteralEnvironment.cs` (`LiteralEnvironment.SymbolicValue`)

**Mechanism.** PB5475 added an `ALL symbolic-character-1` arm to `CodeFigurativeCharacters` (`ReportSectionBinder.cs:420`). It reads the character through `LiteralEnvironment.SymbolicValue` (line 104), which returns `SpecialNamesBinder.SymbolicOf(...)?.Value` and discards the tuple's `National` flag. A symbolic character declared national is a national figurative constant, but the CODE clause's literal-1 shall be an alphanumeric literal (`§2023:13.18.12.3 SR1`, checked with `cite.py --check`: "Literal-1 shall be an alphanumeric literal."). The same function refuses `ALL N"C"` for that reason (its doc comment says so), so `CODE ALL SYM1` with a national `SYM1` compiles where `CODE ALL N"C"` is refused.

**Fix direction.** Read `SymbolicOf` (value and flag) in the arm and refuse a national one with the diagnostic the `ALL N"C"` arm uses; add the negative golden. The citation for national symbolic characters being national figurative constants (§2023:12.3.7.4 GR11c, as the review wrote it) did not pass `cite.py --check` on a short quotation and is left out; derive it before quoting it. PB5475's landing file does not cover this (it records the ALL symbolic-character-1 arm only).
