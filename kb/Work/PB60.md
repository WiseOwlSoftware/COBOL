# PB60 — OPEN — NUMVAL/NUMVAL-C/NUMVAL-F value paths parse by remove-then-scan, erasing the format rules they must enforce

> ⚙ **flags:** wrong-answer, silent · **13 inventory rows** (triage 2026-08-09, probe+refute confirmed; the
> per-row mechanisms live in the triage record and each row's inventory notes)

> **The shape: `Replace`/`Trim` then scan.** `Numval` opens with `text.Trim()` plus a TrimEnd (SS15.67.3
> r2 permits embedded spaces ONLY before the first digit — the trim erases the distinction); `NumvalF`
> opens with `text.Replace(" ", "")` (SS15.69.3 r5 forbids spaces inside the significand — erased);
> `NumvalC` removes the currency string with an unanchored, uncounted `Replace` BEFORE format validation,
> so a currency string embedded mid-number, or occurring twice, values as if legal, and the ordering
> (currency-Replace before space handling) inverts the rules' composition. The currency environment is a
> SCALAR pair (`CurrencyString`/`CurrencyPicSymbol`) where SS12.3.7 admits a SET of CURRENCY SIGN
> clauses, and `DecimalPointIsComma` scoping sits at the wrong binder layer (a SCOPING defect outside
> SS15.67). `BindNumvalCFamily` still keyword-sweeps argument positions blind.
> **The fix**: a real format-rule parser per function (the SS15.67.3/68.3/69.3 grammars are small),
> scanning WITHOUT pre-normalization, the DPC/currency environment passed in — goldens per format branch.
> (The RENDERER routing rows — NumvalF's missing StandardDecimal branch, the working-scale quantization —
> are PB56's; the parser rows are this note's.)
>
> ✅ **THE ONE-SCAN UNIFICATION LANDED 2026-08-09 (6 of 13 rows → CONFORMS: AR-15.67.3-2, RV-15.67.4-2,
> AR-15.69.3-5, AR-15.68.3-4, RV-15.68.4-2, RV-15.68.4-3):** each family's TEST- validator and value
> function are now projections of ONE positional scan (`NvScan` for NUMVAL/NUMVAL-C, `NvfScan` for
> NUMVAL-F — validate positionally, accumulate in the same pass), retiring the remove-then-scan shape
> whole. Measured flips: TAB-led argument EC'd (r2's ignorable char is SPACE only) · "-12-" EC'd (the
> formats are alternatives, never a toggle) · "1 2" EC'd under NUMVAL-F (r5's except-clause) · the
> currency consumed at its ONE r4a position, so `NUMVAL-C("R123.45CR","R")` = **-123.45** where the old
> unanchored Replace ate the R of CR and valued a validator-certified string as 0. Sibling landed:
