# PB1688 — LANDED (wave 1053 group C)

## Landing (wave 1053 group C, 2026-10-10)

LEARNED: `Frontend/Common/SourceLineMap.cs#LineOrigin` is the origin of ONE resultant line piece — ordered
`OriginSpan(ResultColumn, SourceOrigin, SourceColumn)`, SourceColumn a PHYSICAL index (a TAB counts one); `.Origin` is
the line that NAMES the piece (PB82's first-content rule), `.Locate(column)` the one resultant→physical column
conversion. Spans are BORN in `ReferenceFormatProcessor.LogicalLineBuilder` through `TextSite` (Line, Column, Index,
Tabs) — the one place a program-text position becomes a physical column for BOTH the origin spans (`Spans`) and the
reference-format gates (`Col`) — and CARRIED by `OriginWriter` (`AppendSlice` rebases the input's spans; text a stage
writes takes `MappedText.PointAt(pos)`). Consumers locate through `MappedText.LocateAt(pos)`,
`SourceLineMap.Locate(line, column, file)` and `EditionContext.LocationOf`; `MappedText.OriginAt` is DELETED and
`SourceLineMapTests.MappedText_ExposesNoColumnlessOriginOfAPosition` keeps a column-less accessor from coming back.
The trap: `SourceOrigin.ToLocation()` had a default column of 0, so every reporter that forgot the column printed
column 1 silently — the parameter is now required.

- Fixed (one mechanism, the PB1801 design): `char_neg_typedef85.cob --std 85` now reports `(5,16)` and `(7,13)` (was
  `(5,9)` / `(7,6)`); a fixed continuation fragment names its own line and column (`MOVE "ABC` / `-    "DEF" TO.` →
  `(8,20)`); a TAB counts one column (`MOVE 1<TAB>TO.` → `(7,21)`); a copybook line, text after a shorter REPLACE
  replacement and a line after `>>SOURCE FORMAT FREE` keep their physical columns; COPY / REPLACE / conditional-

  12, a REPLACE literal operand at 20.

## Finding

**Repro.** `cobol tests/characterization/negative/char_neg_typedef85.cob --std 85` reports its diagnostic at
`(5,9)`; the offending word is at column 16 of line 5.

**Harm.** A wrong source POSITION on every diagnostic the parser or binder raises inside a fixed-form line (the line
is right, the column is program-text-relative). This is a diagnostic-quality defect, not a conformance rule; no ISO
clause governs a compiler's message positions.

**Code sites.** `src/Cobol.Net.Frontend/Common/SourceLineMap.cs#MappedText` (a line origin per output line, no column
offset) and `src/Cobol.Net.Frontend/Preprocessor/ReferenceFormatProcessor.cs#Mapped`, which builds it. The fixed-form
conversion drops columns 1–7, so each output line's origin needs the column its first character came from (and a
continuation join needs the per-fragment offset).

**Note.** The default reference format became FIXED at PB1362 (train 70), so every directive-less source now takes
the fixed-form path and this offset reaches far more programs than it did under auto-detection.
