# PB4766 - bare counter register passes CONCAT and BASECONVERT argument-1, dies at run time

**What the report says (R2-1, low).** Pre-existing and outside that diff, found by the parity probe around the changed
`IsDataItem` screen: a bare counter register passes CONCAT and BASECONVERT argument-1 at compile time and dies at run time,
because `IntrinsicRenderer.StrArgVisitor`'s `BoundComputedOperand` arm renders no image for a register
(`IntrinsicRenderer.cs:1989`). The report names no probe path.

**R1.** No open note covers it. PB4712 and PB4710 (landed) touch `StrArgVisitor` for other arms.

**Sites:** `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/IntrinsicRenderer.cs#StrArgVisitor`
(`Visit(BoundComputedOperand)`, the counter-register arm);
`src/WiseOwl.Cobol.Compiler/CodeGen/Emit/OperandText.cs#IsCounterRegister` (the one register test, so Emit reads `AlgebraicRanges` from `OperandText` alone).

## Landed (wave 20261878 F)

Re-probe on the wave's build (`CONCAT(LINAGE-COUNTER "A")`, `BASECONVERT(LINAGE-COUNTER 10 2)` after OPEN OUTPUT of a LINAGE 20 file): clean
compile, run-time `NotImplementedCobolFeatureException: intrinsic string argument 'BoundComputedOperand'`. Root cause as filed: the
`BoundComputedOperand` arm of `StrArgVisitor` knew the nested string function, the parenthesized operand, the numeric function and
the compound expression, and sent a register to `Loud`. Fix: the arm renders a counter register through the ONE register image
`OperandText.AsString` already gives it in a string context (an unsigned integer item's digits, zero-filled to
`AlgebraicRanges.CounterRegisterDigits`), unconditionally, as the field arm renders a numeric item: a position that bars numeric items
refuses the register at the binder, and `--permissive` coerces it (`TRIM(LINAGE-COUNTER)` now `01`, it died before). Witnesses:
`pb4766_counter_register_concat_baseconvert_argument` (2023, `CONCAT [01A]`, `BASECONV [1]`) and refusal
`pb4766-counter-register-concat-below-2023` (2014, COBOL1502).

**Review round 1 (finisher).** R1-1: `IntrinsicArgumentRules.StaticUsageOf` answered null for a register, so CONCAT r2/r3 and BASECONVERT r1
failed open on `PAGE-COUNTER` (binary) and let `CONCAT(PAGE-COUNTER "A")` compile; it now answers `AlgebraicRanges.CounterRegisterUsage`, and
`CheckConcatArgs` screens a register as the numeric item it is (COBOL1627, COBOL1642; LINAGE-COUNTER, a display item, still passes).
R1-2: CONVERT's ANY source rendered the register's display image through `StorageArg`'s fall-through; `OperandText.CounterRegisterStorageImage`
now gives the storage of its description (PAGE-COUNTER the 4 binary bytes through the report counter item's profile, LINAGE-COUNTER its zoned
digits). R1-3 (lead, same method): a numeric display item no longer `continue`s past r2 beside a national argument. R1-4 (lead): the
§2023:8.4.3.14.4/§2023:8.4.3.15.4 quotes in the comments now match the spec text. Witnesses: `pb4766-convert-any-counter-register-storage` (2023) and
`-below-2023`, refusals `pb4766-page-counter-concat-argument`, `pb4766-page-counter-baseconvert-argument`,
`pb4766-concat-numeric-display-item-beside-national`.
