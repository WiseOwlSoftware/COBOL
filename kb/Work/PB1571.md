## Landed (2026-10-18, wave 1119 group H)

The survey is recorded in `docs/CONFORMANCE.md` §3 D-SMA (a), and it **confirms** the determination: no change to
the PB1036 behaviour or golden. Measured on `cobc` 3.2.0 (WSL, plain and `-debug`) and read from the pinned 3.2
source (`libcob/fileio.c`, `libcob/exception.def`): GnuCOBOL raises only EC-SORT-MERGE-FILE-OPEN, and never
-ACTIVE, -RELEASE, -RETURN, -SEQUENCE (a FIXME in its source), EC-FLOW-RELEASE or EC-FLOW-RETURN, so it has no order
to follow; what it does with a RETURN in an input procedure (takes the record the output procedure is owed) or a
RELEASE in an output procedure (kept before the first RETURN, status '30' after) is a by-product of its store.
IBM documents the restrictions with no condition; Micro Focus documents one fatal run-time error (COBRT099) for a
RELEASE outside the input procedure and a RETURN outside the output procedure alike. Nothing orders two conditions,
so -ACTIVE first stands.

Witnesses added (the source-level coverage the determination lacked; it was pinned at unit level only):
`wiseowl/cases/14.9.40-SORT/pb1571_sort_merge_active_vs_flow` (RETURN in an input range and RELEASE in an output
range with -ACTIVE enabled and not, a nested SORT in an output range, EC-SORT-MERGE-RETURN after AT END),
`pb1571_sort_merge_stray_unchecked` (the same statements with checking off, D-SMA (c)) and the negative
`pb1571-sort-merge-active-turn-at-85`.
