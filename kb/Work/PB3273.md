# PB3273 — no host entry for a strong group with both a variable-length component and a reference

Source: `E:\COBOL-coord\scratch\reports\w1093b-PB2099-report.md`, "New defects", second bullet ("carried from the reviewed branch").

**Claim.** A strong group holding both a variable-length component and a reference has no host entry. The report names this as a GR13 restriction in `PublishedRecordEmitter.Renders`. (Filed when that type was still on PB2099's unlanded branch; it is on main now, `src/Cobol.Net.Compiler/CodeGen/PublishedRecordEmitter.cs`.) See the re-verdict below.

## Re-verdict (2026-10-16, w1105 group H, on a fresh Debug build of main 2b5a81145)

`PublishedRecordEmitter` is on main now (PB2099 landed). The note's claim still reproduces and is the stated restriction:
`E:/COBOL-coord/scratch/w1105h/BOTH.cob` (a strong group `TB` = `PIC 9(2)`, `PIC X DYNAMIC LENGTH LIMIT IS 8`, `USAGE POINTER`
as the formal of `H3BOTH`, beside a plain `H3OK` and a main) compiles, and the generated assembly has entry classes for
`H3MAIN` and `H3OK` only.

**Spec-required, or a gap?** Neither half of the restriction is a rule of the standard. ISO section 14.2.3 13) ("When either
the activating or the activated runtime element is other than a COBOL runtime element, the implementor shall specify the
restrictions and mechanisms for all supported language products", `cite.py --check 14.2.3` OK) obliges the implementor to
STATE a restriction; it does not impose one. The restriction is an implementation gap, and its root is NOT in the host
emitter: the boundary has no crossing form for the shape. The same group cannot cross a COBOL CALL (COBOLNET1688), the
activated program's own formal of it stages the Tier-C loud at its copy-in, and a group MOVE of it is a run-time
`NotImplemented`: all measured under PB3139, which this note now waits on. An entry offered over that boundary could only
reach a loud, so withholding it (DOC-A.1-141, design 4.3) is the honest behavior until the boundary has a form.

**Why `PublishedRecordEmitter` is not changed.** It already composes both halves separately (the CALL lane's cell area with
its slots, `__Area`/`__PutSlots`; the variable-length carrier with its components, `EmitVar`), and `Renders` keeps them
apart on purpose: the `HoldsSlots` conjunct is implied today by `CurrentExtentImageCapable` and stays as the guard, so
that when PB3139 gives the boundary a form, the restriction cannot lift while the record still drops the references. What
this change adds: `HostEntryShapeDriftTests.AGroupHoldingAComponentAndAReference_PublishesNoEntry_WhileTheBoundaryHasNoFormForIt`
pins the withheld entry (the sibling units still publish) AND the boundary's absence of a form (the copy-in loud), so the
test is red the day PB3139 lands and the restriction is then lifted with the record's composition of the new form's storage;
the stale comments on `Renders` and `HostEntryEmitter.Published` and the design 4.3 / DOC-A.1-141 text now say why.

**Fix shape when PB3139 lands.** The form is the cell area plus the group's atoms (`CallEmitter.AreaOf`'s `VarGroupWindow`
arm already states them): the record builds ONE `StorageCell` holding the image run, each reference in its managed slot
(`__PutSlots`) and each component in the cell's dynamic slots (`StorageCell.StoreVarGroupAt`), the argument states
`Area: new CellPointer(cell, 0)`, and the write-back reads the cell back (`VarGroupAt`, `SlotRead`). Then `Renders` drops the
conjunct and this note closes.
