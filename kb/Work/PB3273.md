# PB3273 — no host entry for a strong group with both a variable-length component and a reference

Source: `E:\COBOL-coord\scratch\reports\w1093b-PB2099-report.md`, "New defects", second bullet ("carried from the reviewed branch").

**Claim.** A strong group holding both a variable-length component and a reference has no host entry. The report names this as a GR13 restriction in `PublishedRecordEmitter.Renders`. (Filed when that type was still on PB2099's unlanded branch; it is on main now, `src/WiseOwl.Cobol.Compiler/CodeGen/PublishedRecordEmitter.cs`.) See the re-verdict below.

## Re-verdict (2026-10-16, w1105 group H, on a fresh Debug build of main 2b5a81145)

`PublishedRecordEmitter` is on main now (PB2099 landed). The note's claim still reproduces and is the stated restriction:
`E:/COBOL-coord/scratch/w1105h/BOTH.cob` (a strong group `TB` = `PIC 9(2)`, `PIC X DYNAMIC LENGTH LIMIT IS 8`, `USAGE POINTER`
as the formal of `H3BOTH`, beside a plain `H3OK` and a main) compiles, and the generated assembly has entry classes for
`H3MAIN` and `H3OK` only.

**Spec-required, or a gap?** Neither half of the restriction is a rule of the standard. ISO section 14.2.3 13) ("When either
the activating or the activated runtime element is other than a COBOL runtime element, the implementor shall specify the
restrictions and mechanisms for all supported language products", `cite.py --check 14.2.3` OK) obliges the implementor to
STATE a restriction; it does not impose one. The restriction is an implementation gap, and its root is NOT in the host
emitter: the boundary has no crossing form for the shape. The same group cannot cross a COBOL CALL (COBOL1688), the
activated program's own formal of it stages the Tier-C loud at its copy-in, and a group MOVE of it is a run-time
`NotImplemented`: all measured under PB3139, which this note now waits on. An entry offered over that boundary could only
reach a loud, so withholding it (DOC-A.1-141, design 4.3) is the honest behavior until the boundary has a form.

**Why `PublishedRecordEmitter` is not changed.** It already composes both halves separately (the CALL lane's cell area with
its slots, `__Area`/`__PutSlots`; the variable-length carrier with its components, `EmitVar`), and `Renders` keeps them
apart on purpose: the `HoldsSlots` conjunct is implied today by `CurrentExtentImageCapable` and stays as the guard, so
that when PB3139 gives the boundary a form, the restriction cannot lift while the record still drops the references. What
this change adds: `HostEntryShapeDriftTests.AGroupHoldingAComponentAndAReference_PublishesNoEntry_WhileTheBoundaryHasNoFormForIt`
pins the withheld entry (the sibling units still publish) AND the boundary's absence of a form (the copy-in loud), so the
test is red the day PB3139 lands and the restriction is then lifted with the record's composition of the new form's storage;
the stale comments on `Renders` and `HostEntryEmitter.Published` and the design 4.3 / DOC-A.1-141 text now say why.

**Fix shape when PB3139 lands.** The form is the cell area plus the group's atoms (`CallEmitter.AreaOf`'s `VarGroupWindow`
arm already states them): the record builds ONE `StorageCell` holding the image run, each reference in its managed slot
(`__PutSlots`) and each component in the cell's dynamic slots (`StorageCell.StoreVarGroupAt`), the argument states
`Area: new CellPointer(cell, 0)`, and the write-back reads the cell back (`VarGroupAt`, `SlotRead`). Then `Renders` drops the
conjunct and this note closes.

## Unblocked (2026-10-17, w1114a — PB3139's boundary form is on its branch)

PB3139 lands the COBOL boundary's form for the shape: a strong variable-length group with a reference leaf crosses as
its cell area holding its references and its components together (`OoClassTable.LeafCarried`, `StorageCell.CopyArea` /
`StoreArea`). The published record still composes no such area, so the restriction stands and this note's fix shape
above is the remaining work. Read PB3139's "Progress (2026-10-17, w1111b)" section first: the callee's area formal is laid
over the host's area only when the area states a `Shape` its atoms `LaysOver` (`CobolArgAdapt.Area`), so
`HostEntryEmitter.ArgOver` needs the module's one `GroupAtomTable`; and a host-built dynamic-capacity table needs its
description's element seed, which the program class emits over its private `_P_<uid>` profiles (decide against
DESIGN-external-repository §4.3 and record the choice there).

## Landed (2026-10-18, w1120d + w1121a)

The mechanism is w1120d's (`1fec3f8dd`, cherry-picked onto main 6fb6a20f8 as `a6bc24fb8`, never merged); w1121a finished it.
Re-probed on the w1121a Debug build: `E:/COBOL-coord/scratch/w1105h/BOTH.cob` now has entry classes for H3MAIN, H3OK AND
H3BOTH (`E:/COBOL-coord/scratch/w1121a/run/BOTH.g.cs`), and the C# host probes in `E:/COBOL-coord/scratch/w1121a/probe`
(numeric-edited, packed, COMP-5, float, national, program-pointer, a nested group with its own dynamic-length item and
pointer, a dynamic-capacity table under INITIALIZED with VALUE whose elements hold a pointer and a nested dynamic table
of pointers, and a RETURNING group with a fixed table of variable-length elements) return the values the standard
gives: an occurrence a store creates is initialized from VALUE (§8.5.1.9.3, §8.5.1.9.5), a LIMIT truncates on the right
(§8.5.1.10.4), and every pointer the program sets comes back and is passed in again.

**Fix shape (the design, DESIGN-external-repository §4.3's variable-length row, records it).** `PublishedRecordEmitter.Renders`
asks `DataItem.CurrentExtentTransferImageCapable` (the one member law, a reference a fixed placeholder). The record's `__Area`
starts from the DESCRIPTION'S fresh cell (`__hs<n>` in the host class, `DataEmitter.FreshArea`, with the description's
`_P_` profiles, so a prototype-only unit needs no program class), distributes its carrier into it
(`StorageCell.StoreVarGroupAt`) and sets the references on top (`__PutSlots`, a dynamic-capacity table's element cells
included); the argument states the group's atoms (`Shape`, `DynBase`), so the activated program's formal is laid over
the area (§14.2.3 8)); `__TryGetArea` reads it back. `CellComponents.ShapeOf` is the one window-shape construction
(`VarGroupWindow.ElementShapeOf` delegates). w1121a routed the two element-cell reads through `RuntimeApi.CellDynTable`
/ `TableCurrentOccurrences` (the one emitted form) and corrected the stale restriction text in `HostEntryEmitter.Published`,
DESIGN-external-repository §4.3 and DOC-A.1-141 (both copies).

Witnesses: `HostEntryTests.AHost_PassesAStrongVariableLengthGroupWithReferences_AsTheCellAreaOfItsComponentsAndReferences`
and `HostEntryTests.AHost_PassesNestedComponentsAndReferences_ThroughTheCellArea_AndReadsThemBack` (Conformance; the
second, w1121a's, for the nested group, the element cell's nested table of pointers and the RETURNING fixed table) and
`HostEntryShapeDriftTests.AGroupHoldingAComponentAndAReference_PublishesItsEntry_AsTheDescriptionsOwnCellArea`
(Unit, replacing the restriction pin). `closes_rows: []` (reason in the frontmatter).

**For the next implementer.**
- `DataItem.cs#CurrentExtentTransferImageCapable`: the member law with a reference a fixed placeholder; reuse it, never a second law.
- `Place.cs#CellComponents.ShapeOf(group, walk)`: the one window-shape construction; walk is `Of` for a class-held item, `InLayout` for a description no class holds.
- `DataEmitter.cs#FreshArea(formal, width, firstOrdinal)`: the one fresh-cell factory. Trap: `ClassDynOrdinal` is -1 for an item no class holds, so pass `firstOrdinal: 0`.
- `PublishedRecordEmitter.cs#EmitArea/EmitPutSlots/EmitGetDyn`: trap: `HoldsComponents(table)` is true of a dynamic table itself; ask `ComponentsOf(table).Count > 0` for its element scope. Emit `DynTableAt` through `RuntimeApi.CellDynTable`.
- `HostEntryEmitter.cs#Describe/Storage/Decode`: a record that `HoldsSlots` routes first (`__Area`, `__TryGetArea`); the seed field `__hs<n>` and its `_P_` profiles are declared in the host class.
