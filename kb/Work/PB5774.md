# PB5774 - at --std 85 an index data item named in a CONTROL clause is refused on a 2023 rule, where §1985:XIII.3.7.4 GR3b provides for that control

**What is wrong.** At `--std 85` an index data item named in the CONTROL clause is refused (COBOL1700) on the 2023 explicit-reference rule, though `§1985:XIII.3.7.4 GR3b` provides for exactly that control, and the message cites a 2023 rule (`§2023:13.18.60.3 SR10`, `§2023:8.4.5`) at `--std 85`. 1985's limit on explicit references (`§1985:VI.5.14.3 SR5`) is about Procedure Division statements (`§1985:IV.4.4.1`). Rendered p.597 (XIII-15): data-name-1 is constrained only by SR1 to SR3 (not in Report Section, qualifiable, distinct, no variable occurrence beneath), and GR3b names the index control case explicitly. 1985 defines an explicit reference only for Procedure Division statements, so VI.5.14.3 SR5 does not reach a Report Section clause. 2023 8.4.5 makes a data-division specification an explicit reference and 2023 has no GR3b, so the refusal is right at 2023. `ControlOperandShapeViolation`'s COBOL1700 arm has no edition test. The Mythos lane ran `m3ctl.cob`: refused at `--std 85` with COBOL1700.
