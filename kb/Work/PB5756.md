# PB5756 - 1985-GR-VI.6.10.4-10 cannot be pinned by a golden

**Sites:** none (a record of a row's evidence; `docs/conformance/8/` gains the DRV record when the registrar acts).

**The rule.** §1985:VI.6.10.4 GR10: "If vertical positioning is not applicable on the hardware device, the operating
system will ignore the vertical positioning specified or implied." (`python scripts/spec/cite.py --check
"§1985:VI.6.10.4 GR10" "If vertical positioning is not applicable on the hardware device"` printed `OK  §1985:VI.6.10.4
GR10  (6.10.4 General Rules)  the text is in GR10` on 2026-11-15.)

**Why no program can pin it.** The rule's antecedent is a DISPLAY device on which vertical positioning does not apply.
WiseOwl's DISPLAY devices are standard output and standard error (DOC-A.1-59; `AcceptDisplayBinder.MnemonicDevice`
reads the implementor names). Both are line streams on which vertical positioning does apply: GR9's move to the next
line shows in every DISPLAY case of the suite. So no program at 85 reaches the antecedent. Any output it prints shows
the consequent never fired, and that is consistent with the rule. The 2023 twin is recorded the same way:
`docs/conformance/8/DRV-GR-14.9.11.4-11.md`, class `unpopulatable-antecedent`.

**Decision.** The row gets no golden. It stays a GAP until the registrar records it as an own 1985 verdict on a
`DRV-1985-GR-VI.6.10.4-10` record of class `unpopulatable-antecedent`, mirroring the 2023 twin. A KEPT row cannot hold
a derivation (PB5675). Re-adjudicate this if `ImplementorNames` gains an output device without vertical positioning,
because then the antecedent can be populated and a golden becomes possible.
