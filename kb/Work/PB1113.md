# PB1113 — OPEN

## The rule
> "If the argument is passed by content, the conformance rules are the same as for a MOVE statement"
`cite.py --check 14.8.2.2 "If the argument is passed by content, the conformance rules are the same as for a MOVE statement"` → `OK  §14.8.2.2 2)  (Group items)`

## Measured (adjudicator / refuter evidence, verbatim)
### [elementary-items] The BY CONTENT / BY VALUE literal, expression and INVOKE-identifier lanes carry their own hand-written admission lists instead of asking the COMPUTE question (rule 2a) or the Table 16 MOVE question (rule 2d), so pairs the standard admits are refused: a numeric literal or arithmetic expression into a floating-point formal, a noninteger numeric literal into a numeric-edited formal, an integer numeric literal into a national formal, a boolean expression into a national formal, and (INVOKE only) any fixed-point<->float identifier pair.
- **Rows:** GR-14.8.2.3.3-L2.2 — harm `rejects-legal-source`
- **Repro:** Outer program with `01 A PIC 9(3)V99 VALUE 12.5. 01 B1 PIC 1(4) VALUE B"1100". 01 B2 PIC 1(4) VALUE B"1010".` and CALL "S" AS NESTED USING BY CONTENT <arg>: arg 1.5 with L USAGE FLOAT-LONG; arg A * 2 with L USAGE FLOAT-LONG; arg 12.5 with L PIC ZZ9.99; arg 12 with L PIC N(4); arg B1 B-AND B2 with L PIC N(4) -> each refused COBOLNET1688.
- **Expected (spec):** §14.8.2.3.3 2) a) a numeric formal conforms "the same as for a COMPUTE statement" — a COMPUTE takes any numeric sender into a float receiver; 2) d) otherwise "the same as for a MOVE statement", and §14.9.25.3 Table 16 says Numeric-noninteger -> Numeric-edited Yes, Numeric-integer -> National Yes, Boolean -> National Yes. All five CALLs compile and deliver the value.
- **Observed:** Probes c_lit_float, c_expr_float2, c_lit_ne, c_lit_nat, c_bool_nat (pinned cobol.exe) all refused. ContentNumericLiteralMismatch admits only a fixed-point numeric or an alphanumeric formal; ContentArithmeticMismatch refuses a float formal; ContentBooleanMismatch refuses National 'on purpose' (its own comment); OoBinder refuses fixed<->float identifiers as an INVOKE 'marshalling residue'. The identifier lane already asks MoveTable16 — these lanes are the unmigrated siblings (the two-arm shape).
- **Code site:** src/Cobol.Net.Compiler/Oo/OoConformance.cs#ContentNumericLiteralMismatch; #ContentArithmeticMismatch; #ContentBooleanMismatch; src/Cobol.Net.Compiler/Binding/Procedure/Verbs/OoBinder.cs#OoBindInvocationArg (fixed<->float carrier screen)

### [elementary-items] An index data item formal is answered by the numeric COMPUTE arm (index items carry PicCategory.Numeric) instead of rule 2 b)'s SET rules, and an ANY LENGTH formal of a non-alphanumeric category skips the MOVE question entirely (rule 2 c) relaxes only length), so non-conforming BY CONTENT pairs are admitted.
- **Rows:** GR-14.8.2.3.3-L2.2 — harm `under-rejects`
- **Repro:** Outer program `01 N4 PIC 9(4) VALUE 3.` CALL "S" AS NESTED USING BY CONTENT N4 (and BY CONTENT 3) into contained S `01 L USAGE INDEX.` -> compiles, runs. `01 NI PIC 9V9 VALUE 1.5.` CALL "S" AS NESTED USING BY CONTENT NI into `01 L PIC N ANY LENGTH.` -> compiles, prints IN-S [15].
- **Expected (spec):** §14.8.2.3.3 2) b): an index formal conforms as for a SET statement — §14.9.39.3 SR2 "Identifier-2 shall reference a data item of class index" and SR3 forbid arithmetic-expression-1 into a class-index receiver, so both are diagnosed. 2) c) says only that the ANY LENGTH formal's "length is considered to match"; the category pair is still 2) d)'s MOVE question, and Table 16 Numeric-noninteger -> National = No, so the NI pairing is diagnosed.
- **Observed:** Probes c_num_idx, c_lit_idx, c_al_nat (pinned cobol.exe) compiled and ran; c_idx_idx (index -> index) correctly accepted. ContentMismatch: `PicCategory.Numeric => argCat is Numeric ? null` catches USAGE INDEX formals; the default arm is `formal.IsAnyLength && !arg.IsAnyLength ? null : MoveContentMismatch(...)`.
- **Code site:** src/Cobol.Net.Compiler/Oo/OoConformance.cs#ContentMismatch (Numeric arm and default arm); src/Cobol.Net.Compiler/Oo/OoConformance.cs#ContentNumericLiteralMismatch

### GR-14.9.23.4-4 (PARTIAL)
|| REFUTED: PARTIAL — GR4 (cite OK §14.9.23.4 4)) applies to EVERY argument: keyword-less, BY CONTENT, and BY VALUE (whose operands are also {arithmetic-expression-1 | identifier-5 | literal-2}). Two lanes are verified: the keyword-less and BY CONTENT reductions (qualified, subscripted, sole literal, keyword-less literal) ride the identifier/literal arm. The BY VALUE lane is unreachable: any BY VALUE argument is refused (COBOLNET0828 'formal parameter is BY REFERENCE ... header BY VALUE formals are a later slice'), and a method header BY VALUE formal is COBOLNET0899. So GR4's effect there is unverified — a single BY VALUE identifier is identifier-5, subject to SR15's class message-tag/numeric/object/pointer test, not an arithmetic expression. A second observation points the same way: `BY CONTENT -5` is classified as a literal, but a signed integer literal into a PIC X formal is refused. Table 16 (Numeric Integer -> Alphanumeric = Yes), via §14.8.2.3.3 rule 2 d) (cite OK), makes it legal, and `MOVE -5 TO X` compiles. The literal lane GR4 selects therefore answers wrong for signed literals (OoConformance.ContentNumericLiteralMismatch; the emitter comment says 'moves an UNSIGNED integer literal'). One half verified -> PARTIAL.
- **Code location (record):** src/Cobol.Net.Compiler/Binding/Procedure/Verbs/OoBinder.cs#OoBindInvocationArg

## What the fixer owes
One asker: the BY CONTENT lane asks the Table 16 MOVE question (rule 2 d) through the MOVE validity table, the expression lane the COMPUTE question (rule 2 a), an index formal the SET rules (rule 2 b), ANY LENGTH relaxes LENGTH only (rule 2 c). Delete ContentNumericLiteralMismatch / ContentArithmeticMismatch / ContentBooleanMismatch's private lists (and the emitter's 'UNSIGNED integer literal' assumption). Sweep CALL's BY CONTENT lane.

### Finding — `objects-p2` (rejects-legal-source; rows `GR-9.3.6-L3.4`)

**Mechanism.** INVOKE BY CONTENT screens refuse MOVE-legal argument/formal pairs: a carrier limit (no fixed-point<->float CONTENT conversion) and three per-literal screens narrower than §14.9.25.3 Table 16

**Repro.** Class method formals `01 LF USAGE FLOAT-LONG`, `01 LE PIC ZZ9.99`, `01 LN PIC N(4)`; caller `01 N3 PIC 9(3) VALUE 123`, typed receiver O. (A1) INVOKE O "MF" USING BY CONTENT N3  (A2) INVOKE O "MF" USING 1.5  (A3) INVOKE O "ME" USING 123  (A4) INVOKE O "MN" USING 12  (A5) INVOKE O "MN" USING B"1" - each alone in a program (probe/objects-p2/gen.py).

**Expected from the spec.** §9.3.6 match rule 4 d): a BY CONTENT parameter matches a non-index/object/pointer formal that 'may be a receiving data item in a MOVE statement with the parameter of the invocation as a sending data item'; §14.8.2.3.3 2) a)/d) (COMPUTE for numeric, MOVE otherwise). Table 16: Numeric->Numeric (float) Yes, Numeric->Numeric-edited Yes, Numeric Integer->National Yes, Boolean->National Yes. All five compile and run: A1 LF=123, A2 LF=1.5, A3 'ME:123.00', A4 LN='12' padded, A5 LN='1' padded.

**Observed / reasoning.** All five refused COBOLNET0828: A1 'the fixed-point⇄float CONTENT conversion is not carried across INVOKE ... (a documented marshalling residue, not ISO §14.8.2.3.3)'; A2/A3/A4 'numeric literal argument ... does not conform to the formal parameter (ISO §14.8.2.3.3 — no conforming COMPUTE/MOVE rule applies)' (ContentNumericLiteralMismatch admits only a non-float numeric or an alphanumeric formal); A5 'Table 16 admits a boolean sending operand only to a boolean or alphanumeric receiver' - a misquote of Table 16. The identifier arm (A3b, A6) already admits numeric-edited and national formals through MoveTable16, so the literal/boolean arms disagree with their own sibling. ContentArithmeticMismatch carries the same float refusal for an arithmetic-expression argument. No kb/Work note owns these (PB165 open covers only the dynamic CALL registry; PB1014 is the boolean store path; PB1063 the restricted-pointer under-reject).
