# PB1673 — OPEN

Filed 2026-09-28 by the train-69 lander from the wave-69 Y finisher report (`w69y-PB1427-report.md`, "New
defects"). Wrong diagnostic; the source is still refused.

**What happens.** `tests/conformance/negative/w69y-pb939-value-null.cob` compiled at `--std 85` reports
COBOLNET2576 ("NULL is the predefined address / object reference …"). At COBOL-85 there is no predefined NULL
(§8.4.3.10 is a 2002 facility) and NULL is not in the 85 reserved-word list, so the word is a user-defined word
there: `VALUE NULL` / `CONSTANT AS NULL` should draw the undefined-name / not-a-literal diagnostic the other
unreserved words draw, or the edition gate for the predefined NULL — never the 2002+ context rule.

**Rule.** §8.4.3.10.3 SR1 (`cite.py --check 8.4.3.10.3 "it may be used only as a sending operand in an INITIALIZE
or a SET statement"` → OK §8.4.3.10.3 1) a)) is the rule 2576 names; it has no 85 counterpart.

**Code site.** `src/Cobol.Net.Frontend/Grammar/Core/CobolExpressions.g4` — the `predefinedNull : NULL_` arm of
`nonNumericLiteral` versus the `reservedGatedWord` edition gate (the NULL_ token reaches the literal arm at 85
before the word gate re-reads it as a user word). Consumers: `DataBinder.ReportNonLiteralValueOperand` and
`DataBinder.Constants.cs#BindConstantStringLiteral` (both call `PredefinedNullRule.Report`).

**Repro.** `cobol tests/conformance/negative/w69y-pb939-value-null.cob --std 85` → COBOLNET2576.

**What the fixer owes.** Decide the 85 spelling's verdict from §8.9 / the constructs row for the predefined NULL,
gate `predefinedNull` on its introducing edition (the new-construct skill's edition-gate sweep), and pin the 85
negative's expected code.
