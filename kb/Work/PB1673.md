## Landing — a NULL token at an edition where §8.9 leaves the word free is the undeclared user word

**Re-probe** on 802352531: `cobol conformance-suite/cases/_unassigned/w69y-pb939-value-null.cob --std 85` drew three
COBOL2576 (§8.4.3.10.3 SR1). The sweep (`E:/COBOL-coord/scratch/w20261769b/p/n1.cob`) found every position at 85
saying the same about a NULL the edition does not have: the constant entry's AS operand, DISPLAY, MOVE, STRING, and the
SR1 contexts that ADMIT NULL — a relation (COBOL0869 "or the predefined NULL") and INITIALIZE … BY NULL (COBOL2031,
"class pointer").

**Verdict.** At 85 NULL is a user-defined word (reserved-words.json r85 false; the PB655 determination, whose positive
twin `8.3.2-COBOL-words/pb655_post85_words_user_words` DECLARES a data item NULL there), so an undeclared NULL token
names nothing: the §8.4.2.1 undefined reference, COBOL1639, the verdict PB655 already gave SELF / SUPER / NULL /
ADDRESS in a receiving position (`ExpressionBinder.RefuseNonReceivable`).

**Fix — in the binder, not the grammar.** The grammar keeps its superset parse (the reservation gate retypes a
DECLARED NULL to a user word at 85, so the `predefinedNull` arm is reached only by an undeclared one; editing
`CobolExpressions.g4` was not needed). `UnreservedKeywordReference` (new) is the one statement of that verdict:
`PredefinedNullRule.Report` (every refusing position) asks it first, and `ExpressionBinder.NullAdmittingOperand` (every
SR1 context) refuses NULL through it where the edition has no predefined NULL; `RefuseNonReceivable` lost its private
copy of the text.

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/UnreservedKeywordReference.cs` (new: `UnreservedKeywordReference.IsFreeAt`,
`UnreservedKeywordReference.Report`), `src/WiseOwl.Cobol.Compiler/Binding/PredefinedNullRule.cs`
(`PredefinedNullRule.Report`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/ExpressionBinder.cs`
(`RefuseNonReceivable`, `NullAdmittingOperand`).

**What happens.** `conformance-suite/cases/_unassigned/w69y-pb939-value-null.cob` compiled at `--std 85` reports
COBOL2576 ("NULL is the predefined address / object reference …"). At COBOL-85 there is no predefined NULL

unreserved words draw, or the edition gate for the predefined NULL — never the 2002+ context rule.

**Rule.** §8.4.3.10.3 SR1 (`cite.py --check 8.4.3.10.3 "it may be used only as a sending operand in an INITIALIZE
or a SET statement"` → OK §8.4.3.10.3 1) a)) is the rule 2576 names; it has no 85 counterpart.

**Code site.** `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolExpressions.g4` — the `predefinedNull : NULL_` arm of
`nonNumericLiteral` versus the `reservedGatedWord` edition gate (the NULL_ token reaches the literal arm at 85
before the word gate re-reads it as a user word). Consumers: `DataBinder.ReportNonLiteralValueOperand` and
`DataBinder.Constants.cs#BindConstantStringLiteral` (both call `PredefinedNullRule.Report`).

**Repro.** `cobol conformance-suite/cases/_unassigned/w69y-pb939-value-null.cob --std 85` → COBOL2576.
