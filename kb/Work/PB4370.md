# PB4370 - Runtime method names as the keys of a bound-layer rule table

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Bound/IntrinsicCarrierRules.cs` (`IntrinsicCarrierRules.CrossAligningFunctions`, the renamed `CrossAlignedNativeArms`; `SdidiQuotientFunctions`, `ReturnsSdidiQuotient`; `ExactParseFunctions`, `ReturnsExactParse`; `AlignmentMayLeaveCarrier`); `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/IntrinsicRenderer.cs` (`IntrinsicRenderer.RenderNum`, `IntrinsicRenderer.AlignmentMayLeaveCarrier`, `IntrinsicRenderer.RenderDec`); `src/WiseOwl.Cobol.Compiler/Binding/Procedure/FunctionValueLane.cs` (`FunctionValueLane.Of`); `src/WiseOwl.Cobol.Runtime/Intrinsics/CobolIntrinsics.Exact.cs` (the class summary); `tests/WiseOwl.Cobol.Tests.Unit/IntrinsicCarrierRuleKeyDriftTests.cs` (new: `RuntimeMethodOf`, `EveryKey_IsACatalogFunctionName_SpeltAsItsRowSpellsIt`); `tests/WiseOwl.Cobol.Tests.Unit/Architecture/BackendContract.cs` (`BackendContract.Table`: the three sets leave the L9 leak row for the COBOL-word row); `tests/WiseOwl.Cobol.Tests.Unit/ExactCarrierBoundaryDriftTests.cs`, `FunctionValueLaneDriftTests.cs`, `ReceiverShapeReaderDriftTests.cs`, `IntrinsicRealArgDriftTests.cs`, `IntrinsicArgumentIntakeContractDriftTests.cs` (each maps a key to its runtime body through the catalog row); `docs/rearchitecture/DESIGN-backend-abstraction.md` (section 1.3 L9), `docs/INTRINSICS_DESIGN.md`; `conformance-suite/wiseowl/cases/15.76.4-Returned-value-rule/pb4370_one_wide_argument_leaves_the_carrier.cob` (new, the found defect's witness).

The three tables key on runtime spellings (`"ModScaled"`, `"Numval"`); `docs/rearchitecture/DESIGN-backend-abstraction.md` section 1.2 bullet 2 forbids the bound layer from carrying runtime method names. Key them on the intrinsic's identity (an `IntrinsicSig` or a function enum), and let each backend map identity to its runtime spelling.

The root is the same as lead 1 of round 0 of that report (the L9 operators: rows with no remover). PB2293's open members were grepped: none names these three tables (PB2293 itself is the umbrella), so this joins its cluster rather than extending a member.

**Fix (landed).** The three sets and `AlignmentMayLeaveCarrier` key on the intrinsic-function-name as its catalog row spells it (`IntrinsicSig.Name`, the key `IntrinsicCatalog.TryGet` looks up: `"MOD"`, `"NUMVAL-C"`), and every caller passes `sig.Name`; the runtime body (`IntrinsicSig.RuntimeMethod`) stays the Roslyn renderer's spelling, which its own switch and its own table (`StandardValueFixedByRule`) keep. `CrossAlignedNativeArms` is renamed `CrossAligningFunctions`, since it names functions now, every caller changed in the same commit. `AlignmentMayLeaveCarrier`'s switch names MEDIAN and MIDRANGE instead of a `_` default, and a name outside the set throws `UnreachableException`. The section 6 contract test classifies the three sets as COBOL words, and the new `IntrinsicCarrierRuleKeyDriftTests` holds every key to a catalog row spelt exactly as the key (the sets compare ordinally, the catalog does not), so a misspelt or runtime-spelt key fails the build instead of dropping its function from the SDIDI routing. Behavior-neutral: the probe program `E:/COBOL-coord/scratch/w20261814b/probe/P4370.cob` printed the same output before and after.

**Not changed, by design:** `FunctionValueLane.NativeSdidiBodies`, `NativeSdidiBodiesWithExactResult` and `Selections` key on runtime bodies. They are the binder's restatement of the Roslyn renderer's `RenderDec` switch labels, which `FunctionValueLaneDriftTests` derives from that switch, and they live in `compiler.binding`, outside the backend input the section 6 contract test walks. `IntrinsicSig.RuntimeMethod` on `BoundIntrinsicCall.Sig` is the same shape one layer up, reached through the tolerated `compiler.bound` to `compiler.binding` edge (`BoundIntrinsicCall` to `IntrinsicSig`); the binder also rewrites it (`IntrinsicBinder` chooses `MaxString` for MAX over strings), so the choice of runtime body is made at bind time. Both are reported as leads in the w20261814b report.

**Found on the way and fixed in the same file (MANDATORY-PRACTICES I9): one wide argument among three or more stayed on the native arm and raised EC-SIZE-OVERFLOW.** `IntrinsicCarrierRules.AlignmentMayLeaveCarrier` bounded each aligned argument by `Pow10Bound`, which answers null for a bound past 38 digits, then ordered the bounds with `OrderByDescending` and took the two largest for RANGE, MEDIAN and MIDRANGE. The default comparer orders null BELOW every value, so the unbounded term sorted LAST: with `BIG PIC 9(31)` beside `FR PIC V9(18)` (49 aligned digits) and a third small argument, the two terms taken were the bounded ones, the predicate proved a fit, and the native arm's alignment of BIG raised EC-SIZE-OVERFLOW ("scale alignment to 18 fraction digits exceeds the Int128 intermediate") for `RANGE(BIG FR TH)`, `MEDIAN(BIG FR TH)` and `MIDRANGE(BIG FR TH)`, values a `PIC S9(31)` receiver holds; the two-argument lists answered. PB621's witness passed only because each of its legs had two wide arguments. The fix answers true as soon as any argument's aligned bound is unbounded (the native arm aligns EVERY argument, so that one alignment already escapes), before the largest terms are chosen; `SumOf` now takes only bounded terms. The renderer and `FunctionValueLane` ask the one predicate, so the bind-time prediction moves with it. Witness: `pb4370_one_wide_argument_leaves_the_carrier` (accepted from 2002, the first edition with a 31-digit item): RANGE, MIDRANGE, MEDIAN odd and even with one wide argument, and a no-wide control.

## Landing

- `src/WiseOwl.Cobol.Compiler/Binding/Bound/IntrinsicCarrierRules.cs#CrossAligningFunctions` (and `SdidiQuotientFunctions`, `ExactParseFunctions`, `AlignmentMayLeaveCarrier`): ask with `sig.Name`, never `sig.RuntimeMethod`; a key is the catalog row's exact spelling.
- `tests/WiseOwl.Cobol.Tests.Unit/IntrinsicCarrierRuleKeyDriftTests.cs#RuntimeMethodOf`: REUSE it to compare a set member with a renderer switch label; do not text-parse the catalog again.
- `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/IntrinsicRenderer.cs#RenderDec`: `StandardValueFixedByRule` is the renderer's own table and keys on the runtime body (`m`); the bound sets key on `fn`.
- Trap: renaming a set strands an inventory `code-location` that resolved only through a comment (RV-15.4.1-L2.1); grep `tests/version-matrix/inventory` for the old name before the gate.
- Trap: `OrderByDescending` over `UInt128?` puts null LAST, so an unbounded aligned term is answered before any ordering.
