# PB5224 - the permissive mode resets an ALTER that COBOL-85 would have refused

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Segmentation.cs#CheckAlter` (its `RulesInForce` guard);
`src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/AlterSwitchEmitter.cs#EmitSegmentState`; `docs/CONTROL_FLOW_DESIGN.md`
(whole: the D4 paragraph "the reset never undoes an ALTER made since control entered the segment").

**Witness.** `altx.cob`: MAIN-SEC (segment 0) runs `ALTER A-SW TO PROCEED TO A-ALT` and then `GO TO A-SW`, where A-SW
is in `IND-A SECTION 60`. At COBOL-85 this is COBOL6877 (§1985:XVI.3.3.1). With `--std 2023 --permissive` it compiles
with only the removed-construct warnings COBOL0810 and COBOL0902, and entering segment 60 resets A-SW to its written
target, so the program displays `A INITIAL` where the ALTER asked for `A ALTERED`. Nothing tells the user.

**The shape of the fix.** The permissive mode keeps COBOL-85's run-time meaning for the segment-number, so it should
keep the rule that makes that meaning consistent: either CheckAlter runs in the mode too (refused, or warned and the
reset dropped for that segment), or the reset is not emitted where the restriction is not asked. The design paragraph
changes with it, and a test runs the witness under --permissive.
