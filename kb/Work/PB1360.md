## Finding — compiler-directives (under-rejects)

directive-continuation-join: the fixed-form normalizer (ReferenceFormatProcessor.ConvertFixedToFree) performs column-7 continuation joins before any directive recognition, so a directive line followed by a continuation line becomes one logical line and is accepted, although it was written on two lines.

**Rows:** SR-7.3.3-1

**Repro:**

```
Fixed form, --std 2023: '       >>DEFINE XX AS "AB' / '      -    "CD"' / '       >>IF XX = "ABCD"' / '           DISPLAY "S1H JOINED".' / '       >>ELSE' / ... (E:\Temp\claude\E--CobolSharp\a700c052-f9e4-4942-84ff-a13c7505d6ec\scratchpad\adj-d2\out\probe\cd\S1H.cob; S1G.cob does the same with '>>DISPLAY "AB').
```

**Expected from the spec:** §7.3.3 SR1 'A compiler directive shall be specified on one line, except for the EVALUATE and the IF directives for which specific rules are specified.' The continued >>DEFINE (and >>DISPLAY) must be rejected.

**Observed:** S1H compiles with only the COBOLNET0903 obsolescence warning for the column-7 hyphen and prints 'S1H JOINED'; S1G compiles and runs. Directives continued onto an ordinary (non-continuation) line are correctly rejected (S1A-S1D). Low practical impact; the fix is a rejection when a continuation line follows a directive line.

**Code site:** src/Cobol.Net.Frontend/Preprocessor/ReferenceFormatProcessor.cs#ConvertFixedToFree (the '-' arm reopens the previous output line whatever it was)

## Finding — display-directive (under-rejects)

Fixed-form continuation lines are joined onto a compiler-directive line before directive recognition, so a directive continued across lines is accepted, although §7.3.12.3 SR1 (and §7.3.3 SR1 for every directive except IF/EVALUATE) requires it to be entirely on one line.

**Rows:** SR-7.3.12.3-1

**Repro:**

```
fixed form, --std 2023:
       >>DISPLAY "AAAA
      -    "BBB"
(or '       >>DISPLAY "A"' then '      -    ZZZ QQQ') -> compiles clean. Sibling: '       >>DEFINE XX AS "AAAA' + '      -    "BBB"', then '>>IF XX = "AAAABBB"' selects the true branch (prints JOINED).
```

**Expected from the spec:** §7.3.12.3 1): 'The DISPLAY directive shall begin on a new line and shall be specified entirely on that line.' §7.3.3 1): 'A compiler directive shall be specified on one line, except for the EVALUATE and the IF directives'. A continuation line following a directive line must be diagnosed with a named directive-format diagnostic and must not extend the directive's operand.

**Observed:** All accepted; the >>DEFINE case shows the continued text becomes part of the directive's value, so a value the spec forbids reaches >>IF. The 'begin on a new line' half is rejected (a '>>DISPLAY' after a statement gives COBOL0001 "unexpected '>'") but only by an unnamed parse error. No kb/Work note owns this; it needs a new register note (area compiler/directives, sweep every directive, §7.3.3 SR1 and SR8c).

**Code site:** src/Cobol.Net.Frontend/Preprocessor/ReferenceFormatProcessor.cs (continuation join) feeding src/Cobol.Net.Frontend/Preprocessor/ConditionalCompilationProcessor.cs (CompilerDirectiveLine)

## Row SR-7.3.13.3-2 — PARTIAL (adjudicator + refuter record)

cite.py --check 7.3.13.3 "EVALUATE operand-1 shall begin on a new line and shall be specified entirely on that line." OK. The processor recognizes a directive only when the TRIMMED LINE starts with `>>`, and the operand is the rest of that one line. Probes: `DISPLAY "A" >>EVALUATE 1` mid-line -> not a directive, rejected downstream (COBOL0307 at 5,24); `>>EVALUATE 1 +` continued on the next line -> COBOLNET1619 malformed '1 +'. No existing negative golden. || REFUTED: PARTIAL — Only the half where the split leaves an unparsable first line is detected. When the first line is itself a complete operand, the continuation line is silently swallowed as an omitted pre-WHEN text line: `>>EVALUATE 1` / `+ 1` compiles clean, takes subject 1 and selects WHEN 1 (the writer meant 1 + 1 = 2) -- the SR2 violation is undiagnosed AND the wrong branch is compiled. Also the subject is parsed only when parentActive, so an EVALUATE in an omitted enclosing branch is never checked. Non-directive lines between >>EVALUATE and the first >>WHEN are not admitted by the general format at all, yet the frame (Emitting=false) drops them without diagnostic.

**Code location:** src/Cobol.Net.Frontend/Preprocessor/ConditionalCompilationProcessor.cs#Run.Render; src/Cobol.Net.Frontend/Preprocessor/ConditionalCompilationProcessor.cs#SplitDirective

## What the fixer owes (and the sibling sweep)

Recognize directive lines BEFORE the continuation join (the `-` arm must not reopen a directive line; diagnose a continuation following a directive), and make the EVALUATE arm diagnose a non-directive line between `>>EVALUATE` and the first `>>WHEN` that is a split operand. Negative goldens: continued >>DISPLAY, continued >>EVALUATE operand.

**Rows claimed:** SR-7.3.3-1, SR-7.3.12.3-1, SR-7.3.13.3-2
