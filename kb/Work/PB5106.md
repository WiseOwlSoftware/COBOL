# PB5106 - at --std 85 a numeric item compared with a group is compared as an elementary move would leave it (sign dropped) instead of as a move to a group of the same size: a SIGN SEPARATE operand equals the group -05, not the group 05 followed by a space

**Sites:** none (not located: the records name no site and the implementer locates the comparison member)

**Mechanism.** When a numeric operand is compared with a group (nonnumeric) operand, 1985 treats the numeric operand as though it were moved to a group item of the same size and compares the content of that group. The compiler applies the elementary-move rule instead (sign character dropped: 05 and a space). Its own `MOVE SN TO K` (K a group) stores -05, yet `IF SN = K` is then false (the same with the group as the subject, and with SIGN TRAILING SEPARATE). The move to a group is an alphanumeric to alphanumeric move with no conversion (§1985:VI.6.19.4 GR5 as the record cites it) and the separate sign character is part of the item (§1985:VI.5.12.4 GR6 item c).

**Found by.** The 1985 MATCH confirmation pass (kb/Work PB4995 item 3): each rule below is a corrected draft (a "redraft") that the compiler at `--std 85` still fails (redraft_run MISMATCH). Harm and observed text are the records; nothing here was re-derived.

**Inventory.** The traceability inventory carries no 1985 rows yet (PB5094: work.py refuses 1985 ids), so `inventory_rows` is empty; the rows this note covers are the 1985 rule ids listed below (catalog `docs/rearchitecture/spec-rule-catalog-1985.json`).

**Rules (1; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-GR-VI.6.3.1.1.2-2` - `§1985:VI.6.3.1.1.2 GR2` (record harm: wrong-answer, slice-09): "the numeric operand is treated as though it were moved to a group item of the same size as the numeric data item" (followed by "(in terms of standard data format characters), and the content of this group item were then compared to the nonnumeric operand"). With an unsigned PIC 99 operand the draft cannot tell rule 2 from rule 1; the corrected draft adds `PIC S99 SIGN IS LEADING SEPARATE VALUE -5` compared with a group holding "-05".

**Repro (`1985-GR-VI.6.3.1.1.2-2`, slice-09).** cobol --std 85 --source-format fixed --flag-extensions, then run

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. RELGRP.
       ENVIRONMENT DIVISION.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  G.
           05  G1  PIC X VALUE "0".
           05  G2  PIC X VALUE "5".
       01  N   PIC 99 VALUE 5.
       01  SN  PIC S99 SIGN IS LEADING SEPARATE CHARACTER
               VALUE -5.
       01  H.
           05  H1  PIC X(3) VALUE "-05".
       PROCEDURE DIVISION.
       P1.
           IF N = G DISPLAY "EQUAL" ELSE DISPLAY "NOT EQUAL".
           MOVE " 5" TO G.
           IF N = G DISPLAY "EQUAL" ELSE DISPLAY "NOT EQUAL".
           IF SN = H DISPLAY "SIGNED EQUAL"
               ELSE DISPLAY "SIGNED NOT EQUAL".
           MOVE "05" TO H.
           IF SN = H DISPLAY "SIGNED EQUAL"
               ELSE DISPLAY "SIGNED NOT EQUAL".
           STOP RUN.
```

**Expected (from the 1985 text).** SIGNED EQUAL for `IF SN = H` with H holding "-05", then SIGNED NOT EQUAL after `MOVE "05" TO H`. The deciding words: "the numeric operand is treated as though it were moved to a group item of the same size as the numeric data item" (§1985:VI.6.3.1.1.2 GR2).

**Observed (copied from `1985-GR-VI.6.3.1.1.2-2`).** cobol --std 85 --source-format fixed --flag-extensions: compiles with no diagnostic and prints EQUAL / NOT EQUAL / SIGNED NOT EQUAL / SIGNED EQUAL; the 1985 text requires SIGNED EQUAL then SIGNED NOT EQUAL (§1985:VI.6.3.1.1.2 GR2: "the numeric operand is treated as though it were moved to a group item of the same size as the numeric data item (in terms of standard data format characters), and the content of this group item were then compared to the nonnumeric operand"). The compiler applies rule 1's elementary move (sign dropped: 05 and a space) to a group operand. Its own MOVE SN TO K (K a group) stores -05, yet IF SN = K is then false (probe p22b.cob in the slice's work directory; the same with the group as the subject, and with SIGN TRAILING SEPARATE).
