# PB758 — OPEN — a scope terminator for a statement that has no scope

Found 2026-09-06 in the PB695 family-3 implementer's report (NEW DEFECT D). Verified independently on main at
`0a24276f`. The report filed it as one-directional over-acceptance; **the second harm below was measured while
verifying it and it is the more serious half — a hard-lexed non-word rejects conforming source.** The frontmatter
carries both flags accordingly.

## The premise, checked first — the word does not exist

`feedback_validate_the_premise_not_only_the_rule`: before asking whether END-INVOKE is required or optional, ask
whether the standard has the word at all. Three independent probes, all negative:

1. `grep -c "END-INVOKE" specs/ISO_COBOL.md` → **0**.
2. The canonical PDF's own text layer, every page:
   `for i in range(doc.page_count): 'END-INVOKE' in doc[i].get_text().upper()` → **no page**. So this is not an
   OCR loss in the transcription; the word is not printed anywhere in ISO/IEC 1989:2023.
3. §8.9's reserved-word list carries **23** `END-*` words —
   `awk '/^### 8.9 Reserved words/,/^### 8.10/' | grep -cE "^- END-"` → 23:
   END-ACCEPT, END-ADD, END-CALL, END-COMPUTE, END-DELETE, END-DISPLAY, END-DIVIDE, END-EVALUATE, END-IF,
   END-MULTIPLY, END-OF-PAGE, END-PERFORM, END-READ, END-RECEIVE, END-RETURN, END-REWRITE, END-SEARCH, END-SEND,
   END-START, END-STRING, END-SUBTRACT, END-UNSTRING, END-WRITE. **END-INVOKE is not among them** —
   `cite.py --check 8.9 "END-INVOKE"` → *FAIL: §8.9 exists but does NOT contain 'END-INVOKE'*, while
   `--check 8.9 "END-CALL"` → **OK §8.9 (Reserved words)**, which is the control proving the check can see the
   list.

## Why the standard has none — the rendered format and Table 12

`python scripts/spec/clause_page.py 14.9.23.2` → **PDF page 681, printed folio 651**;
`python scripts/render-spec-page.py 681`. The INVOKE format's last line is

```
[ RETURNING identifier-4 ]
```

and nothing follows it. `figure_extract.py 681` lists every word in the figure and no END-INVOKE appears; the
transcription's figure note (returned by `--check 14.9.23.2 "RETURNING"` → **OK §14.9.23.2 (General format)**)
enumerates the underlined roster as *"INVOKE, REFERENCE, OMITTED, CONTENT, VALUE, USING and RETURNING"* and no
terminator.

The structural reason is legislated, not inferred. `--check 14.5.1 "Statement names are identified in Table 12,
Procedural statements"` → **OK §14.5.1 (General)**; `--check 14.5.3.2 "The scope of a statement may be explicitly
terminated by using its associated scope terminator as specified in Table 12, Procedural statements"` → **OK
§14.5.3.2 (Explicit scope termination)**. Table 12's INVOKE row is

```
| Statement name | Conditional phrase | Explicit scope terminator |
| CALL           | [NOT] ON EXCEPTION | END-CALL                  |
| INVOKE         |                    |                           |
```

— both cells empty, against CALL's filled pair four rows up. INVOKE has no conditional phrase, therefore no
scope to delimit, therefore no terminator. `docs/COBOLNET_OO_DESIGN.md:77` already states the same thing from the
same page: *"The §14.9.23.2 general format is exactly `INVOKE {class|identifier} {method} [USING …] [RETURNING
identifier-4]` — no ON EXCEPTION / NOT ON EXCEPTION and no handler inside END-INVOKE."* The doc is right and the
grammar disagrees with it.

## What the grammar spells

`src/Cobol.Net.Frontend/Grammar/Core/CobolOO.g4:122-124` on main, verbatim:

```
invokeStatement
    : INVOKE invokeTarget invokeMethodName invokeUsing? invokeReturning? END_INVOKE?
    ;
```

and `src/Cobol.Net.Frontend/Grammar/Core/CobolLexer.g4:180`:

```
END_INVOKE   : 'END-INVOKE' ;
```

The lexer rule is unconditioned — no edition predicate, no context sensitivity — so the character string is
reserved at every `--std`. The branch `worktree-agent-a334880f747b22665` does not touch either line.

END-INVOKE appears without a matching INVOKE statement.` **twice** (the declaration and the DISPLAY) |

The third row is the harm the report did not measure. `--check 8.3.2.1 "A COBOL word is a character-string of not
more than 63 characters"` → **OK §8.3.2.1 (General)** — *"A COBOL word is a character-string of not more than 63
characters that forms a compiler-directive word, a context-sensitive word, an intrinsic-function-name, a reserved
word, a system-name, or a user-defined word. Each character … shall be selected from the set of basic letters,
basic digits, extended letters, and the basic special characters hyphen and underscore. The hyphen or underscore
shall not appear as the first or last character in such words."* `END-INVOKE` satisfies every one of those
constraints and is not in §8.9's list, so **it is a legal user-defined data-name and this compiler cannot compile
a program that uses it** — with a recovery hint (`COBOL0306`, a `CobolErrorStrategy` decoration at
`src/Cobol.Net.Frontend/Parsing/CobolErrorStrategy.cs:179`, not a primary diagnostic) that tells the programmer
to look for a missing INVOKE statement they never wrote.

## Why it matters

§4.2.10 3) is exactly on point and it cuts both ways. *"An implementation that introduces additional reserved
words as nonstandard extensions conforms to this Working Draft International Standard, even though the additional
reserved words may prevent translation of some conforming compilation groups"* (`--check 4.2.10 "An
implementation that introduces additional reserved words as nonstandard extensions conforms"` → **OK §4.2.10 3)
(Nonstandard extensions)**) — the latitude is real, but it is conditioned: *"Documentation associated with an
implementation shall identify nonstandard extensions for which support is claimed and shall specify any reserved
words added for nonstandard extensions"* (`--check 4.2.10 "Documentation associated with an implementation shall
identify nonstandard extensions for which support is claimed and shall specify any reserved words added for
nonstandard extensions"` → **OK §4.2.10 3)**). The census: `grep -rn "END-INVOKE" docs/ tests/` returns exactly
one hit, `COBOLNET_OO_DESIGN.md:77`, and it says the standard has no such thing; `grep -rn
"END-INVOKE\|END_INVOKE" src/` outside `Generated/`, `obj/` and the build outputs returns exactly the two grammar
lines above. There is no `docs/DIAGNOSTICS.md` row, no `docs/CONFORMANCE.md` extension claim, no dialect gate.
Nothing claims the extension, so the reservation is not conformant latitude — it is an undocumented private word
that both accepts non-COBOL and refuses COBOL.

## The fix shape

Delete both, in one change set:

```
invokeStatement
    : INVOKE invokeTarget invokeMethodName invokeUsing? invokeReturning?
    ;
```

and the `END_INVOKE` lexer rule at `CobolLexer.g4:180`. `grep -rn "END_INVOKE" --include=*.cs src/` (excluding
`Generated/`) must be re-run to confirm no binder reads the accessor before the token goes; the only grammar
reference today is the one alternative above. Goldens: a NEGATIVE pinning `INVOKE O "M" END-INVOKE.` as a syntax
error at 2002/2014/2023 (the editions that have INVOKE), and a POSITIVE compiling and running a program with a
data item named `END-INVOKE` — the second is what proves the reservation is really gone rather than merely
unreachable from `invokeStatement`.

⚠ **The negative golden must not be written as a DECLINE.** §4.2.7 makes non-support conformant only when it is
diagnosed by name, but this is not a declined ISO facility — there is no facility. A plain syntax error is the
correct answer, and the golden's header should say so, or a later reader will invent a COBOLNET code for it.

## Sweep

Two greps, both cheap and both belonging in CI rather than in a note:

1. **Every scope-terminator token in the lexer against Table 12's column 3.** Table 12 is machine-readable in
   `specs/ISO_COBOL.md` and the lexer's `END_*` rules are one grep; a token on one side and not the other is a
   defect in whichever direction it points. This is the `feedback_a_dead_lookup_is_also_unverified` shape — the
   token has sat in the lexer unchallenged because nothing ever compared it to the list.
2. **Every reserved word the lexer hard-reserves against §8.9's list**, same join, wider. `constructs.json` and
   the CI-owned inventories are the right home; a hand-kept list is not (CLAUDE.md rule 8).
