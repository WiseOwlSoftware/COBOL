# PB831 — OPEN — the one figurative form that DOES have a length, treated as though it did not

Filed 2026-09-09 by the registrar (third pass), **measured** on this worktree's own
`dotnet build CobolSharp.sln -c Debug` (exit 0) at `35f86874` — i.e. AFTER train 26, which is what made this
observable. Found while re-measuring `kb/Work/PB828` (the §13.16.3 SR9 adjudication) against the new `main`.

## Repro — measured, verbatim

`scratchpad/registrar3/probe/p6_sr9.cob` (PROGRAM-ID `PBR828A`), `--std 2023 --run`:

```cobol
01 A VALUE SPACE.
01 E USAGE DISPLAY VALUE SPACE.
01 G VALUE ALL "AB".
…
DISPLAY "G=[" G "] LEN=" FUNCTION LENGTH(G).
```

```
A=[ ] LEN=1        ✅ right — §8.3.3.6.4 GR3 b gives a non-ALL figurative the length ONE
E=[ ] LEN=1        ✅ right, same rule
G=[A] LEN=1        ⛔ WRONG — expected G=[AB] LEN=2
```

No diagnostic of any kind. The program compiles, runs, and prints a value the standard does not permit.

## Expected, from the standard

```
$ python scripts/spec/cite.py --check 13.16.3 "The PICTURE clause may be omitted for an elementary item when an alphanumeric, boolean, or national literal that is not a zero-length literal is specified in the data-item format of the VALUE clause."
  OK  §13.16.3 9)  (Syntax rules)

$ python scripts/spec/cite.py --check 13.16.3 "where length is the length of the literal as specified in 8.3.3, Literals."
  OK  §13.16.3 9) c)  (Syntax rules)
```

SR9 a): *"if the literal is alphanumeric, `'PICTURE X(length)'`"*, "where length is the length of the literal as
specified in **8.3.3, Literals**". §8.3.3.6, *Figurative constant values*, is a subclause of §8.3.3, and inside
it:

```
$ python scripts/spec/cite.py --check 8.3.3.6.4 "When a figurative constant represents a string of one or more characters and the length of the string is not specified in the rules for the context in which the figurative constant is used, the length of the string is determined from context by applying the following rules in order:"
  OK  §8.3.3.6.4 3)  (General rules)
```

> **§8.3.3.6.4 GR3** — *"… the length of the string is determined from context by applying the following rules
> in order: a) When a figurative constant is specified in a concatenation expression, the length of the string
> is one character. **b) When a figurative constant is other than ALL literal-1, the length of the string is one
> character. … c) The length of the string is the length of literal-1.**"*

The rules apply **in order**, so for `ALL "AB"` in a PICTURE-less VALUE clause: (a) does not apply (no
concatenation expression), (b) does not apply (it IS `ALL literal-1`), (c) applies — **length 2**. SR9 a) then
implies `PICTURE X(2)` and the item's initial value is `AB`.

For a bare `SPACE`, (b) applies — length 1, `PICTURE X(1)`, value one space. **That is what the compiler
produces, and it is right** — see "right for the wrong reason" below.

## Mechanism — the root is one sentence of rationale, not a missing branch

`src/Cobol.Net.Compiler/Binding/DataBinder.PictureRequired.cs:73` exempts a figurative VALUE from the SR8
PICTURE-required diagnostic:

```csharp
if (item.RawValue is { } rawValue && IsFigurativeValueText(rawValue)) continue;
```

and `IsFigurativeValueText` (`:123-127`) admits the `ALL` form. The doc comment above it states the premise:

> *"plus the `ALL literal-1` form, which §8.3.3.6 makes a figurative constant too and **which likewise has no
> length of its own** (it is repeated to the size of the item, so an item of unstated size gives it none)."*

The parenthetical is **§8.3.3.6.4 GR2**, which governs the case where *"the length of the string **is** specified
in the rules for the context"* — a sized receiver. An item of unstated size is precisely the case GR2 does NOT
govern and GR3 does, and GR3 c gives `ALL literal-1` a length. So the exemption is right for `SPACE` and wrong
for `ALL "AB"`: the entry then falls to the same recovery `PicInfo` every PICTURE-less leaf gets, which is
`X(1)`, and the initial value is truncated to `A` with no diagnostic.

`feedback_a_real_clause_can_answer_a_different_question`: the rationale cites a real clause about a different
situation, `--check` on it would pass, and the gap shipped.

## ⛔ Right for the wrong reason — the part that will drift

`01 A VALUE SPACE.` yields `X(1)`, which agrees with GR3 b — but **not because anything derives GR3**. It agrees
because the recovery for an unpictured leaf happens to be one character. Nothing in the tree computes a
figurative constant's SR9 length, so the day the recovery width changes, or the day a `national` context makes
GR1 select `N(1)`, or the day a boolean figurative needs `1(length)`, the agreement ends silently. The fix is
not "special-case ALL"; it is **synthesize SR9's implied PICTURE from the literal's category and length,
figurative or not** — which is `kb/Work/PB504` (`SR-13.16.3-9` = NOT-IMPLEMENTED, "the implied PICTURE is
synthesized nowhere). This note is what that missing synthesis DOES to a user's program in the one case the
carve-out made reachable.

## Sibling sweep the fixer owes

Each of these is `ALL literal-1` in a PICTURE-less VALUE and each needs its own measured row before the fix is
called done: `01 G VALUE ALL "AB".` (alphanumeric, above); `01 H VALUE ALL N"AB".` (national — GR1 selects the
national representation, SR9 c) implies `N(2)`); `01 I VALUE ALL B"10".` (boolean, SR9 b) implies `1(2)`);
`01 J VALUE ALL "A".` (length 1 — must stay `X(1)`, the case that looks unchanged and proves nothing);
and the zero-length guard `01 K VALUE ALL "".` (SR9 excludes a zero-length literal, so SR8 shall reject it).
Also the interaction with `>>FLAG-14 VALUE-FIG-CON-LENGTH`: an `ALL literal-1` whose length IS derivable is
arguably not "a data item with no specified length" at all (§7.3.15.4 GR4 k), so whether it should still be
flagged is a question for `kb/Work/PB828`, not a thing to decide in the fix.
