# PB1050 — LANDED

## Measured
`FD RPTF REPORTS ARE R1 R2.` with two legal RDs → `error COBOLNET0899: file 'RPTF': multiple reports on one file
(REPORTS ARE …, ISO §13.18.46) are not yet implemented` (`DataBinder.Reports.cs` `ResolveReports`,
`DiagnosticCatalog.ReportMultipleOnFile`).

## The rule
`cite.py --check 13.18.46.3 "The order of appearance of each report-name-1 is not significant"` → `OK §13.18.46.3 1)`
— the clause takes several report-names. `docs/CONFORMANCE.md` A.4.11 lists other staged report-writer residues but
not this one.

## What the fixer owes
Several report engines sharing one file connector (one line/page position per REPORT, one physical file), per
`docs/COBOLNET_REPORT_WRITER_DESIGN.md`; update its §5 and CONFORMANCE A.4.11 in the same change. Golden: two reports
interleaving GENERATEs on one file.

## Landed (wave 1005 group A, 2026-10-03)

The `ReportMultipleOnFile` refusal (`DataBinder.Reports.cs` `ResolveReports`, COBOLNET0899) is deleted with its descriptor, and `REPORTS ARE r1 r2 …` binds.
Re-probe first: the runtime already had everything a second producer needs - each report is its own `CobolReport` engine (own LINE-COUNTER, page model,
held-back line) over the one connector, `CobolFile.HoldLine` / `ClaimDevice` (kb/Work PB1247) writes a different holder's line first, and the emitted CLOSE
asks every report associated with the file (`SequentialIoEmitter`, the `||` over `VisibleReports` on that file) - so the fix was the refusal, not a second
engine. Probe: two reports with distinct CODEs interleaving GENERATEs on one file wrote the records in GENERATE order.

Goldens: `conformance:85/pb1050_reports_share_file` (GENERATE order DE-A, DE-B, DE-B, DE-A writes AAAA 1, BBBB 1, BBBB 2, AAAA 2; the codes of §13.18.12
separate the reports, §13.18.12.1) and `conformance:2023/pb1050_close_with_active_report_of_two` (R-A terminated, R-B active, `CLOSE` completes 00 and sets
EC-REPORT-NOT-TERMINATED - §14.9.6.4 GR5 "any report"). Citations run through `cite.py --check` (13.18.46.4 GR1/GR2, 14.9.6.4 GR5).
