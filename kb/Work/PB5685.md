# PB5685 - CANCEL's implicit CLOSE of an active report's file raises no EC-REPORT-NOT-TERMINATED

**Sites (lead, from the writer; the integrator confirmed the members exist):**
- `src/WiseOwl.Cobol.Compiler/CodeGen/ProgramEmitter.cs#EmitProgramClass` (line 494, the emitted `CloseFiles()` block: `RuntimeApi.FileCloseIfOpen(...)` per file)
- `src/WiseOwl.Cobol.Runtime/Control/ProgramTable.cs#CancelNode` (the caller)
- The explicit CLOSE's report-active check (PB141's GR5 raise site, `SequentialIoEmitter.EmitClose`) is what the implicit CLOSE lacks.

**Rules (each checked with `python scripts/spec/cite.py --check`, verdict OK).**

- `§2002:14.8.5.3 GR9`: "an implicit CLOSE statement without any optional phrases is executed for each file-name associated with an internal file connector that is open"
- `§2002:14.8.6.3 GR5`: "the CLOSE statement for that file is completed and the EC-REPORT-NOT-TERMINATED exception condition is set to exist"
- EC-REPORT-NOT-TERMINATED is non-fatal (`NF` in the 2002 exception-name table), so the run unit continues and FUNCTION EXCEPTION-STATUS reports it.

The implicit CLOSE is a CLOSE statement, so GR5 applies to it. The same reach applies at 2023 (`§2023:14.9.5.4 GR9`): the repro gives the same output at `--std 2023`.
