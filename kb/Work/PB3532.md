## What happens

`scripts/arch/r2_inputs.py`, `perf_input()` (line ~359):

```python
recs = sorted((REPO / PERF_DIR).glob("*.md"), key=lambda p: p.stat().st_mtime)
...
r = recs[-1].relative_to(REPO).as_posix()
```

It takes the NEWEST performance baseline record under `docs/rearchitecture/evidence/perf-baseline/` by the file's
modification time. Those records are tracked files, so their modification time is when git wrote them into the
checkout, not when the baseline was taken. Today there are two: `354c79ef3312.md` (taken 2026-10-07 09:11 UTC) and
`a13ede547992.md` (taken 2026-10-18 09:39 UTC). In a fresh clone or worktree both are written in the same checkout,
their times tie or fall in an arbitrary order, and the tie goes to the directory's enumeration order (the name on NTFS,
a hash order on ext4). On a host where the older record wins, `inputs/perf.json` names the 2026-10-07 baseline, and
every R2 reviewer measures performance claims against it. Nothing reports the choice as wrong.

Found by the PB3528 finisher's sibling sweep (the same mechanism: an order taken from file-system metadata, which made
`plan_wave.load_reports` plan differently on Windows and Linux).

## Expected

The newest baseline is the one whose record says it was taken last: `conditions.taken_at` in the record's
machine-readable block, which `perf_baseline.read_record` already parses (`YYYY-MM-DD HH:MM UTC`, so it sorts as text),
with the file name as the tie-break so the choice is total. A self-test fixture with two records whose modification
times are the reverse of their `taken_at` order must pick the later `taken_at`.

**Sites:** scripts/arch/r2_inputs.py

## Repro

`touch docs/rearchitecture/evidence/perf-baseline/354c79ef3312.md`, then
`python -c "import sys; sys.path.insert(0, 'scripts/arch'); import r2_inputs; print(r2_inputs.perf_input()['baseline'])"`
from the repository root (the same call `r2_inputs.py --pin <tree> --out <dir>` makes to write `inputs/perf.json`):
it prints the `354c79ef3312.md` path, the 2026-10-07 baseline, although `a13ede547992.md` was taken eleven days later.
