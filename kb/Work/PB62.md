# PB62 — OPEN — TryExpandAll expands table ALL at bind time only, so ODO tables reject and the arity gate sees phantom arguments

> ⚙ **flags:** rejects-legal · **12 inventory rows** (triage 2026-08-09, probe+refute confirmed; the
> per-row mechanisms live in the triage record and each row's inventory notes)

> `IntrinsicBinder.TryExpandAll` expands `table(ALL)` subscripts at BIND time by the OCCURS count and
> emits `BoundOperandError` on OCCURS DEPENDING ON — but the SS15.4 variadic model is a RUNTIME argument
> list, so legal `FUNCTION SUM(T(ALL))` over an ODO table is REJECTED, and a fixed table's expansion runs
> BEFORE the arity gate so arity diagnostics count phantom arguments. `AlignedArgsEx` then forces the MAX
> scale across the whole expansion (RV-15.60.4-1's precision leg). CURRENT-DATE's arity arm miscounts for
> the same before/after reason (FMT-15.21.2), and TryExpandAll runs unconditionally for EVERY catalogued
> function (FMT-15.47.2).
> **The fix**: ALL-expansion becomes a runtime enumeration seam (the emitter iterates the live occurrence
> count), the arity gate counts SOURCE arguments, and both stray arms fall out of the restructuring.
