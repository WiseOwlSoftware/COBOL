# PB1934 — OPEN

Filed by the train-1005 lander from wave 1005 group A's report (`w1005a-PB1706-report.md`, lead 2).

## Question

§13.18.12.4 GR2: the CODE characters "are not included in the descriptions of the lines in the report, but are
included in the logical record size". PB1129 (landed in train 1005) gives the report line `RECORD CONTAINS − code`
positions, but an aligned or overlong printable item that runs past the record is cut by the line image without an
exception condition or a diagnostic. The implementer found no outcome stated for the record-size cut and left it.

**Verdict needed.** Search the standard first (feedback: spec before asking): §13.18.14 (COLUMN), §13.18.39 (PAGE
width), §13.14 (FD with REPORT clause) and the EC table for a rule on a line wider than the record. If the standard
is silent, follow CLAUDE.md rule 1's precedence (GnuCOBOL, then IBM / Micro Focus) and record the choice in
`docs/CONFORMANCE.md`; a bind-time check is possible whenever the line width and RECORD CONTAINS are both known.

**Site.** `src/Cobol.Net.Runtime/IO/ReportWriter.cs#ReportLineImage` (~:1547) and the line-width walk in
`src/Cobol.Net.Compiler/Binding/DataBinder.Reports.cs#ResolveReports`.

## Adjudication 2026-10-07 (w1033)

Decision `E:\COBOL-coord\scratch\w1033-adj\PB1934-decision.md`; refuter `PB1934-refute.md` (NOT UPHELD: the defect is NARROWED and the fix REVERSED; the refuter's version is the outcome). Pinned build `pin-97006f3` (main `97006f310`); probes `PB1934\`, `PB1934-refute\pin\` and `gc\`.
GnuCOBOL sources read from the tarball are GPL and must never be committed.

**Outcome: DEFECT CONFIRMED (silent), NARROWED to a missing exception condition; the cut itself is NOT a defect.** `kind` flips to `defect`; `silent: true`, `wrong_answer: false` (the cut is a documented latitude choice once DOC-A.1-159 states it). Three parts:

1. **Defect: EC-REPORT-COLUMN-OVERLAP (`§13.18.14.4 GR4`) is not raised when the overlapping columns lie past RECORD CONTAINS minus the code.** `rpt4.cob` (RECORD CONTAINS 20; COL 22 X(3) and COL 23 X(3), both PRESENT WHEN true; `>>TURN EC-ALL CHECKING ON`): `EXC=[ ]`, line `0123456789`;
   control `rpt4ctl.cob` (RECORD CONTAINS 40): `EXC=[EC-REPORT-COLUMN-OVERLAP]`. Changing only the RECORD CONTAINS value decides whether an EC the standard requires is raised. GR4 is stated over the report line's column positions, which the PAGE WIDTH bounds (`§13.18.39.4 GR2 b)`), not the record. An overlap straddling into the record IS raised (`pin/p6`):
   the suppression applies only to columns at or past the record. Fix: make `ReportLineImage.Overlaps` and the image's occupancy track columns up to the page width (or the widest line), independent of where the record cut falls. Site: `src/Cobol.Net.Runtime/IO/ReportWriter.cs#ReportLineImage` (`Write` about :1720, `Overlaps` about :1712: `end = Math.Min(start + length, _used.Length)`);
   `CobolReport.Place`'s doc comment states "The line itself is also bounded by the report file's record (its width), where the image is cut."
2. **Not a defect: the cut at RECORD CONTAINS minus code.** REJECT the decision's fix `LineWidth = Math.Max(widest, record - codeLength)`. `§13.18.43.4 GR6`: "Integer-1 specifies the number of bytes contained in each record in the file"; `§13.18.43.1`; `GR2`; `§13.4.5.2` Format 3 carries `[ record-clause ]` and `§13.4.5.3 SR4` confirms a report FD has RECORD CONTAINS; `§13.18.12.4 GR2`: the code characters "are included in the logical record size". So the logical record is integer-1 bytes
   including the code, and "at least integer-1 bytes" contradicts GR6. `§13.4.5.4 GR4` leaves the "structure" (the layout), not the size, to the implementor; what becomes of the columns past integer-1 minus code is `§A.1 159)` latitude (required + documented), and the build's cut is a permissible choice. The project already reads GR6 this way: `src/Cobol.Net.Compiler/Binding/DataBinder.cs` (about :2155, "It SIZES THE FILE — §13.18.43.4 GR6 ... and a report file's line width prefers it") and the landed golden `tests/conformance/85/pb1129_rd_code_literal.cob` (derives the cut from GR2) which the decision's fix would silently reverse.
   The decision's GnuCOBOL evidence was misreported: GnuCOBOL does NOT widen for CODE. Re-measured with `-debug` (`PB1934-refute\gc\`): `ga` RECORD 41, CODE "A": writes `A0123456789    ABCDEFGHIJ`; `gd` RECORD 21: writes; `gb` RECORD 25 (exactly code + widest line): NOTHING written, EC-I-O-LOGIC-ERROR; `ge` RECORD 15 (< code + line): nothing written, EC-I-O-LOGIC-ERROR; `gg` no RECORD clause with CODE: nothing written, EC-I-O-LOGIC-ERROR; `gf` RECORD 15 without CODE: widened to 20 columns.
   Source: `libcob/reportio.c#write_rec` adds `code_len` to the record size, `fileio.c:6651 cob_write` checks `f->record_max < f->record->size` and answers `COB_STATUS_44_RECORD_OVERFLOW`, `cobc/tree.c#finalize_report` never adds the code to `record_max`. GnuCOBOL's CODE leg is unreliable (it refuses records that fit) and its non-CODE widening contradicts GR6, so neither supports the decision. Micro Focus (web snippets only): HOSTRW "the record length used is exactly as specified in the FD if the RECORD CONTAINS clause is specified" and "the last byte of a record may be lost", i.e. keeps the FD length.
   Doc defect, same change: `docs/CONFORMANCE.md` DOC-A.1-159 sentence "A line holds exactly the columns its report group description places" is contradicted by the build; it must state that a report record is the code followed by the line, integer-1 bytes in all, and that columns past integer-1 minus code are not recorded. Also restate `docs/COBOLNET_REPORT_WRITER_DESIGN.md` around :440 and :592 consistently.
3. **Sibling defect: a Format 2 or Format 3 RECORD clause on a report FD bounds nothing**: filed as `PB2519`.
   Cause: `src/Cobol.Net.Compiler/Binding/DataBinder.Reports.cs#ResolveReports` (about :4279: `model.LineWidth = model.File?.RecordContains is { } record ? Math.Max(1, record - (model.Code?.Length ?? 0)) : widest;`) reads only the Format-1 `RecordContains`. The line width should come from the file's maximum record size for every format through the one rule (two-arm shape). An implementer may split it into its own note.

**Spec citations (cite.py --check OK; the refuter re-ran all 12 and added ten).** `§13.4.5.3 SR8` (no record description entries on a report file, so SR3 of the RECORD clause has nothing to measure), `§13.18.14.3 SR6, SR8 b)`, `§13.18.39.4 GR2 b)`/`GR5` (page width, default 999), `§13.18.14.4 GR5` (the only stated truncation, at the page width, with EC-REPORT-PAGE-WIDTH), `§13.18.14.4 GR4`, `§13.18.12.4 GR1/GR2`, `§14.9.16.4 GR1`.
Alternatives rejected by both files: a compile-time error when code + line exceeds RECORD CONTAINS (no syntax rule supports it; rejects legal source); raising EC-REPORT-PAGE-WIDTH or EC-REPORT-IMP for the record cut (the page width is not exceeded).
Goldens: `rpt4` (overlap EC raised with RECORD CONTAINS 20), `rpt4ctl`, `p6`, `pv`/`p3` for the sibling, and keep `pb1129_rd_code_literal`. Severity MINOR.
