# PB1664 — OPEN (adjudication)

Filed 2026-09-27 by the train-67 lander from the wave-67 P implementer report (`w67p-PB1168-report.md`, new
defect 3). PB1540 made the LINE SEQUENTIAL delimiter the host newline (DOC-A.1-114); the record sequential
PRINT stream kept its fixed CR LF, and the implementer documented that as DOC-A.1-146 (c′) rather than move it.

**The question.** The line end a print-control WRITE emits is implementor-defined. CLAUDE.md rule 1's precedence
for latitude (the spec, otherwise GnuCOBOL, otherwise IBM / Micro Focus) points at GnuCOBOL, which writes `\n` to
a binary-mode sequential file. Today `src/Cobol.Net.Runtime/IO/SequentialConnector.cs:779` `PrintLineEnd = CR LF`
on every host.

**Cost of changing it.** Every NIST and report-writer golden that pins print-file bytes moves; the determination
in `docs/CONFORMANCE.md` DOC-A.1-146 (c′) is rewritten.

**What the adjudicator owes.** Survey GnuCOBOL (and IBM / Micro Focus) on a print file's line end, decide under
rule 1, record it in DOC-A.1-146, and either close this note with the current behavior cited or hand a defect
note (with the golden list) to an implementer.
