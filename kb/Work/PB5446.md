# PB5446 - cite.py suggests a sublist designator with a sub-item path that citation.py refuses

**Sites:**

- `scripts/spec/citation.py#RULE` (with `_rule`, `SUBLIST_RULE`)
- `scripts/spec/cite.py#RuleBook.where`

**Repro (origin/main 09ce7dc601).**

    python scripts/spec/cite.py --check "§1985:VII.1.3.5 GR4" "An attempt is made to write or rewrite a record that is larger than the largest or smaller than the smallest record allowed by the RECORD IS VARYING clause"

prints `FAIL [text-not-in-rule]: §1985:VII.1.3.5 has '...' under GRL2.4d.1, not GR4`. Checking the designator it names,

    python scripts/spec/cite.py --check "§1985:VII.1.3.5 GRL2.4d.1" "<the same text>"

prints `FAIL: 'GRL2.4d.1' is not a rule designator: write SR n, GR n, AR n or RV n (its sub-item path glued: GR6d.2), Format
n or Table n`, and so does `GRL2.4d`. `§1985:VII.1.3.5 GRL2.4` with the same text prints OK.

**Mechanism.** `RuleBook.where` composes `rule.designator + render_path(path)`, so a rule of a restarted list
(`citation.rule_designator` writes `GRL2.4`) gains a sub-item path (`d.1`). `citation.RULE` admits a glued sub-item path
only after a plain ordinal (`\d+(?:[a-z0-9.]*[a-z0-9])?`), never after `L\d+\.\d+`. The writer and the reader of the
designator grammar disagree: either the grammar admits a sub-item after a sublist designator (and `cite.resolve` checks it,
as PB5317 does for `GR6c`), or the suggester stops at the designator it can parse. One grammar should be the source of
both, with a self-test that every designator the suggester prints parses.
