# PB3750 — a witness test comment says status 91 is fatal by its first digit

**Sites:** `tests/WiseOwl.Cobol.Tests.Conformance/DocA1Item103WitnessTests.cs` (the comment above `CharacterWithoutByteImageWrite`, added by PR #573), `docs/CONFORMANCE.md` (the DOC-A.1-110 row, the sentence on status 91's fatality, which carried the same slip).

The comment says status 91 is FATAL by its first digit (§9.1.13.1). §9.1.13.1 (checked with `cite.py --check 9.1.13.1`): "Certain classes of I-O status values indicate fatal exception conditions. These are: any that begin with the digit 3, 4, or 7, and any that begin with the digit 9 that the implementor defines as fatal." So a 9x status is fatal only because the implementor defines it so; 91 is fatal by WiseOwl's definition (DOC-A.1-110, where the implementor-defined statuses are recorded). Reword the comment to say that, and check the other witnesses in the file whose comments reason from a status's first digit for the same slip (3, 4 and 7 are right as written).

(2026-10-25, review R1-1, severity low.)

## Landed

Re-probed on the branch: the comment reproduced (it said 91 is "FATAL by its first digit"), and the DOC-A.1-110 row of `docs/CONFORMANCE.md` §7 carried the same wording ("a '9' first digit"). Both now say what §9.1.13.1 says (`cite.py --check 9.1.13.1` OK): a status beginning with 9 is fatal only when the implementor defines it as fatal, and WiseOwl COBOL so defines 90 and 91. The other comments in `DocA1Item103WitnessTests.cs` reason from first digits 3 (status 35), 4 (status 48) and 1 (status 10) only, which are right as written; a repository-wide grep for the same phrasing found no other site. Comment-only change: no behavior change and no inventory row.
