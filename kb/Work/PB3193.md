# PB3193 — EnsureUtf8 changes the host process's console streams

Source: `w1080f-PB3163-report.md` "## New defects / leads" (filed by the clerk, 2026-10-15).

**The lead.** `StandardStreams.EnsureUtf8` (`src/Cobol.Net.Runtime/IO/StandardStreams.cs:58-76`, called from `ProgramTable.RunOnThisThread` on every `RunMain` / `RunModule`) replaces `Console.Out`, `Console.Error` and `Console.OutputEncoding` in the HOST process. It is the same family as PB3163 (a run unit mutating state of the process that embeds it), but a different mechanism: PB3163 was the exit code; this is the display device's encoding.

**Why it is not simply fixed.** A documented PB59/PB899 decision made UTF-8 output on the display device a deliberate behavior, so this needs a design call on the embedding boundary: which side owns the console encoding when a run unit is embedded (an option is to write through a run-unit-owned stream and touch the process console only at the process-entry boundary, the way PB3163 now delivers the exit code once at `ProgramTable.RunModule`). The report says it shares no root with PB3163; do not widen that landing. An implementer designs it from the PB59 and PB899 notes before changing anything, and a host-embedding test pins the result (a host that set its own `Console.Out` before running a unit still has it afterwards).
