# PB5845 - at --std 85 an OPEN refused with status 90 (LINAGE of zero) leaves the file open

**Ruling: UPHELD (a), harm wrong_answer.** The rows `1985-GR-VII.1.3.5-5` and `1985-GR-VII.1.3.5-L2.5` do not close on their inherited verdict. An OPEN refused with status 90 (LINAGE of zero) leaves the file open: a second OPEN gives 41, a WRITE 90, the CLOSE 00. At 1985 a 9x statement is unsuccessful, so the WRITE is 48 and the CLOSE 42. The 2023 continuation (kb/Work PB526) is applied at every edition. The checker's confidence: medium-high (the counter-reading below is the only route to CONFORMS, and it contradicts the implementation's own 9x). Cause (a): wrong at 85 only, as the 2023 rule differs. Severity MAJOR: a wrong-answer defect is at least MAJOR.

**The checker's evidence (rulings.json, copied).** 1985 defines the 9x class as a statement unsuccessfully executed as a result of a condition that the implementor specifies (`§1985:VII.1.3.5`, in GR5), and the implementor chose 90 for a LINAGE page-body value that is not greater than zero (`§1985:VII.3.7.4 GR2`; DOC-A.1-110). Only a successful OPEN results in the file being in an open mode (`§1985:VII.4.3.4 GR1`), and an OPEN must be successfully executed before any permissible input-output statement (`§1985:VII.4.3.4 GR4`). So at 85, after the 90 OPEN, the file is not in an open mode: a second OPEN is not a 41 (the condition of `§1985:VII.1.3.5 GRL2.4` a, an OPEN attempted for a file in the open mode), a WRITE is the 48 condition (GRL2.4 g), and the CLOSE is the 42 condition (GRL2.4 b). Answering 90 to the WRITE reports under 9x a condition that 48 already names, which `§1985:VII.1.3.5 GRL2.5` forbids. The compiler leaves the connector open because the 2023 LINAGE rule keeps the counter state until the file is closed (`§2023:13.18.34.4 GR6`), a continuation 1985 does not have; nothing on the path consults the edition.

**Counter-reading, weighed and not adopted (the ruling's).** The zero value violates a "must" of the LINAGE rule, so the program is outside the standard and anything is allowed. It fails because the implementor has DEFINED the outcome as a 9x condition, and the 1985 meaning of 9x is an unsuccessful statement; an open file after an unsuccessful OPEN contradicts the implementation's own status. The reader's other conclusions (90 and 91 are 9x values, no 61/51/31/71 at 85) stand.
