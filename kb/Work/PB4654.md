# PB4654 - a filed note's Sites can name a path or member that does not exist

**Sites:** `scripts/spec/work.py` (`sites_problems`, `note_sites`)

The enqueue unit's clerk filed PB4616 to PB4653 on 2026-11-04 and `work.py check` passed them. A throwaway script that
looked up every path and member in those notes' Sites paragraphs found five wrong out of 38 notes: three paths in the
wrong directory (PB4640, PB4649, PB4650) and two members no file declares (PB4630, PB4652). The sites were corrected in
the change that files this note.

Two gaps in `sites_problems` let them through:

1. **A note with `cluster: []` outside a campaign is not held to the rule.** Its guard is
   `from_cutover = bool(clusters) and ...`, so an unclustered note skips every check, including the member check PB3797
   added. PB3263 chose that scope so older notes of idle clusters stay readable, and the id cutover
   (`SITES_REQUIRED_FROM`, PB3443) already serves that purpose for old notes. Whether new unclustered notes should be
   held too has not been decided here.
2. **A path that does not exist reads as a file the change creates.** PB3797 made "a file the change creates needs
   neither" legal, and `site_member_findings` pins it, so a mistyped directory passes even on a held note. The two
   readings cannot be told apart from the path alone. One possible shape is an explicit marker for a created file, but
   that changes R3's form and needs the planner's reader changed with it.

Harm: an implementer or the planner starts from a wrong site. The planner partitions on these paths, so a wrong path
also means two groups on one real member are not seen to collide. Compiler output is not affected.

The script is `E:\COBOL-coord\scratch\enqueue-unit-20261104\check_sites.py`, in scratch and not in the tree. Its member
test is a plain substring search of the file, which is weaker than `note_sites`'s unit readers.
