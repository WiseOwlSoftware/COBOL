# PB4320 — C# access text built in the binder (leak L7)

**Found:** by the PB4265 implementer (wave 20261790 group B, branch worktree-wf_d934ffd7-6da-2, report
`E:\COBOL-coord\scratch\reports\w20261790b-PB4265-report.md`), which recorded it as the OPEN row L7 of
`docs/rearchitecture/DESIGN-backend-abstraction.md` §1.3. Campaign PB2293 (owner 2026-10-31: eliminate the backend
seam leaks asap); it shares the root of PB2293's leak L1.

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.Linkage.cs` (`CallBindLinkage`, `GlobalBridgesOf`);
`src/WiseOwl.Cobol.Compiler/Binding/DataBinder.Oo.cs` (`OoBindMethodData`);
`src/WiseOwl.Cobol.Compiler/Binding/Model/AccessPath.cs` (`Reroot`);
`src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/SortBinder.cs:992` (`SortMemberPath`).

**What leaks.** PB4265 made the model's names CLR names, allocated once for both backends. Four binder sites then
compose C# member-access TEXT from them: a carrier-resident formal's `DataItem.ClrName` is overwritten with
`__lnk{Uid}.Value` (`CallBindLinkage`, `OoBindMethodData`); `AccessPath.Reroot` joins `__outer.` onto
`RootFieldSegment.CsField`; `GlobalBridgesOf` builds `anchorOf(x)+x` paths; `SortMemberPath` joins names with `.`. A
string like `__lnk7.Value` is a C# expression, not a name, so it breaks DESIGN-backend-abstraction §1.2's refusal of
C# fragments, and a CIL backend would have to parse it back.

**Fix direction.** The model states the access structurally (the carrier, the member, the outer instance as
`AccessPath` segments or a dedicated place kind); each backend renders it. `DataItem.ClrName` stays the item's CLR
name and is never overwritten with an expression. PB4266's contract test should refuse a `.` or `__outer` inside a
name-typed model string once this lands.
