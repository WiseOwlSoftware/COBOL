# PB5072 - at --std 85 the VALUE-under-EXTERNAL rule reads only the VALUE clause's own entry, so a VALUE on any item subordinate to an EXTERNAL record compiles

**Sites (landed):** `src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs` (`ParseArm.VisitValueClause`, `ParseArm.InExternalRecord` replacing `EntryHasExternal`, with `ParseArm.EnclosingEntry`, `ParseArm.LevelOf` and `ParseArm.HasClause` under `ParseArm.EntryHasClause`).

**Sites (as filed):** `src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs#VisitValueClause` (the gate `EntryHasExternal(ctx)` scans the clauses of the VALUE clause's own data description entry, never the level-01 record it belongs to).

**Mechanism.** 1985 forbids VALUE in any entry that is part of the description or redefinition of an external data record. VisitValueClause asks whether the entry carrying the VALUE has an EXTERNAL clause, and never whether the record it sits under does, so the rule is applied to a level-01 entry only and every subordinate item escapes.

**Found by.** The 1985 `--std=85` draft triage (kb/Work PB4995 item 3): each rule below is a conformance-suite draft that did not MATCH at `--std 85`, and its adjudicator decided COMPILER-DEFECT. Harm and observed text are the records'; nothing here was re-derived.

**Inventory.** The traceability inventory carries no 1985 rows yet, so `inventory_rows` is empty; the rows this note covers are the 1985 rule ids listed below (catalog `docs/rearchitecture/spec-rule-catalog-1985.json`).

**Rules (2; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-SR-VI.5.15.3-4` - `§1985:VI.5.15.3 SR4` (record harm: under-rejects, slice-03): §1985:VI.5.15.3 SR4: "The VALUE clause must not be specified in any entry which is part of the description or redefinition of an external data record." EXT-REC is an external data record (its 01 entry carries EXTERNAL) and `05 EXT-FLD PIC X(4) VALUE "ABCD"` is an entry that is part of its description, so the VALUE clause on line 6 violates the rule; only "condition-name entries associated with such data description entries" may carry one (the rule's second sentence). The draft reads the rule correctly.
- `1985-SR-X.4.5.3-3` - `§1985:X.4.5.3 SR3` (record harm: under-rejects, slice-08): §1985:X.4.5.3 SR3 (first sentence as amended by X3.23b-1993): "The VALUE clause must not be used in any data description entry that includes, or is subordinate to an entry that includes, the EXTERNAL clause. The VALUE clause may be specified for condition-name entries associated with such data description entries." EXT-FLD (line 6) is a data description entry, not a condition-name entry, subordinate to 01 EXT-REC EXTERNAL, and carries VALUE "ABC".

**Repro (`1985-SR-VI.5.15.3-4`, slice-03).**

```cobol
000100 IDENTIFICATION DIVISION.
000200 PROGRAM-ID. EXTVAL.
000300 DATA DIVISION.
000400 WORKING-STORAGE SECTION.
000500 01  EXT-REC EXTERNAL.
000600     05  EXT-FLD PIC X(4) VALUE "ABCD".
000700 PROCEDURE DIVISION.
000800 MAIN-PARA.
000900     MOVE "WXYZ" TO EXT-FLD.
001000     DISPLAY EXT-FLD.
001100     STOP RUN.
```

**Expected (from the 1985 text).** --std 85 refuses a VALUE clause anywhere inside an EXTERNAL record, at the VALUE clause. The deciding words: "The VALUE clause must not be specified in any entry which is part of the description or redefinition of an external data record." (§1985:VI.5.15.3 SR4).

**Observed (copied from `1985-SR-VI.5.15.3-4`).** cobol t.cob --std 85 --source-format fixed --flag-extensions -o t.dll: exit 0: no diagnostic; line 6 draws nothing and the program runs (exit 0), displaying 'WXYZ'. The control (no VALUE) compiles: exit 0: no diagnostic. The compiler knows the rule but applies it to one entry only: the same VALUE written on the 01 entry that carries EXTERNAL (`01 EXT-REC PIC X(4) EXTERNAL VALUE "ABCD".`) is refused, exit 65: t.cob(5,38): error COBOL0900: a data-item or table VALUE clause in the linkage or file section or on an EXTERNAL item requires COBOL-2002 (targeting COBOL-85) — a VALUE clause in an EXTERNAL data item (§1985:VI.5.15.6 GR1 and §1985:VI.5.15.3 SR4 (the 1985 restrictions, changed and deleted); ISO §2023:13.18.63.3; ISO/IEC 1989:2002 Annex F.2 item 145). A level-88 VALUE under the external record compiles and runs (displays 'ON'), as the rule's second sentence allows. Code site: src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs, VisitValueClause: the gate `EntryHasExternal(ctx)` -> EntryHasClause scans the clauses of the VALUE clause's OWN data description entry for an EXTERNAL clause, and never the level-01 record the entry belongs to, so every subordinate entry of an external record escapes construct value-clause-linkage-file-external-2002 (COBOL0900).

Other rules of this note carry their own observed text in `E:/COBOL-coord/scratch/triage-85/out/slice-*.json`.

**Fix (landed).** Re-probed on 7f4f67c7f1: the repro compiled at `--std 85` (exit 0, displays WXYZ). The gate now asks the
RECORD: the entries of a section are one flat list in the parse tree, so `InExternalRecord` walks back to the nearest level-01
or level-77 entry and asks whether it carries EXTERNAL, or REDEFINES a level-01 record of the same section that does
(§1985:VI.5.15.3 SR4's "redefinition"). A level-88 entry stays outside (`InGatedDataEntry`), as the rules' second sentence
admits. Witnesses: `13.18.63-VALUE/pb5072_value_under_external_record_2002` (2002, 2014, 2023: displays WXYZ, ON) and
`pb5072-value-under-external-record-at-85` (COBOL0900 at 85). Probe of the redefinition arm: `01 EXT-RED REDEFINES EXT-REC`
with a subordinate VALUE draws COBOL0900 at 85 (beside COBOL2406, the VALUE-under-REDEFINES rule of every edition).
