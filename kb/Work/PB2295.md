**Found by:** the R1 refuter (wave 1031), who had to load `plan_wave` with the main checkout's `fix_clusters.py`
(`E:/COBOL-coord/scratch/w1031-refute/c9_driver.py` sets `plan_wave.FIX_CLUSTERS`).

**Site:** `scripts/orchestrator/plan_wave.py` (`FIX_CLUSTERS` is the path under `tools/claude-skills/skills/agent-fleet/
references/`), and the worktree state: `git submodule status` in `E:/COBOL/.claude/worktrees/r1-pb2118` prints
`-a6b58d72c… tools/claude-skills` (not initialized).

**Repro:** in any agent worktree, `python -I scripts/orchestrator/plan_wave.py --cluster PB2119 --dry-run
--budget-points 10 --no-branches` → `EXIT=1`, "fix_clusters.py is missing".

**The rule it breaks:** a tool the process tells an agent to run must run where the agent is
(`DESIGN-orchestrator-loop.md` §9.1 names `plan_wave.py --cluster` as the way to compute a campaign's waves;
DESIGN-architecture-review §8.7 tells R1's reviser and R2's reviewers to use it).

**Scenario:** a reviewer re-deriving an estimate in planner units (as R1's refuter and reviser had to) either cannot,
or writes a driver that mixes the worktree's planner with another checkout's clusterer, so the numbers depend on two
trees.

**Fix shape:** one resolver of the public skill path used by every script that reads it (the worktree's submodule if
initialized, else the main checkout's, located through the repo-root locator `TestRepoDriftTests` keeps single), or
initialize `tools/claude-skills` when the worktree is created (`EnterWorktree`/dispatch template); a test that the
planner's dry run succeeds in a worktree without the submodule. **Model:** Sonnet (mechanical, once the resolver choice
is made; NEEDS-OPUS if the choice is contested).
