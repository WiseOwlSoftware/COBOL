# PB3606 — `cite.py --check` and symbol-led quotations

## Scenario

`python scripts/spec/cite.py --check 8.7.5.2 "<> is an abbreviation for NOT EQUAL"` prints OK on syntax rule 8
("NOT = is an abbreviation for NOT EQUAL"), because the matcher drops punctuation and the needle becomes "is an
abbreviation for NOT EQUAL". `--find` locates the real text in syntax rule 11. A caller who trusts the OK writes the
wrong rule number into a note, golden or comment: the inherited-citation failure of CLAUDE.md rule 1.

It is a sibling of [[PB308]] (a punctuation-only needle matched every clause): the same normalization, a different
way to fail open.

## Fix (for the fix lane)

1. A quotation that contains symbols is matched with its symbols kept, or `--check` reports the rule number it matched
   so a mismatch is visible to the caller.
2. A self-test with this exact case: the quotation above against 8.7.5.2 must report syntax rule 11, never rule 8.
3. Sweep the other symbol-bearing quotations in the 2023 text (`>=`, `<=`, `**`, `::`) for the same collision.
