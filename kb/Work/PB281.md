# PB281 — the A.4.8 witness debt

The derived selector `format-select-when-only` (`inventory-schema.json` → `derived-verdicts`) stamped these
**37 rows** DOCUMENTED-NON-SUPPORT on 2026-09-02 from ONE determination — `CONFORMANCE.md` §5's row *"A.4.8 |
FORMAT and SELECT WHEN file handling | Not claimed"*. Every one of them **stays a GAP**, and this note is the
debt.

## The verdict is the cheap half

The schema closes a DOCUMENTED-NON-SUPPORT row only on a test proving the **documented posture is what actually
happens**. A.4.1's first sentence is what makes the posture normative in the first place:

> "An implementation shall accept the syntax and provide the functionality for an optional element only when
> support for that language element is claimed by the implementor." (`cite.py --check A.4.1` → OK)

So the row asks: *does this compiler refuse `FORMAT` and `SELECT WHEN`, and does it say why?* The first half is
yes. The second is no.

## What is actually there — measured, not predicted

**Nothing.** There is no `FORMAT` lexer token and no `formatClause`; `fileDescriptionClause` lists thirteen
clauses and none of them is FORMAT. `SELECT WHEN` has zero grammar hits; `dataDescriptionClause` has no
`selectWhenClause`, and `SELECT` is a lexer token `cobolWord` does not admit. No COBOLNET code in
`docs/DIAGNOSTICS.md` or in `src/` names either clause, there is no `constructs.json` row, and no test anywhere
exercises either construct. The compiler says it in its own source: `DataBinder` carries the comments
*"SR3 — record description entries and no SELECT WHEN (none exists in this grammar)"* and *"REDEFINES, and
SELECT WHEN (not modeled)"*.

So a user who writes `FD F-OUT RECORD IS VARYING FROM 1 TO 80 CHARACTERS FORMAT CHARACTER DATA.` learns that
their **syntax is bad**, not that this implementation declines FORMAT and SELECT WHEN. §4.2.7 is discharged by
the user documentation, so this is conforming — but it is not *good*, and it is not a witness.

⚠ **AND THE POSTURE IS A PREDICTION UNTIL IT IS RUN.** `genericFileDescriptionClause → genericClause : IDENTIFIER
(IDENTIFIER|literal)*` is exactly the escape hatch that turned `DISPLAY screen-name-1` into a silent Format-1
reinterpretation ([[PB260]]) and that let `WRITE FILE` compile clean ([[PB282]]). Every legal FORMAT spelling
carries a keyword token that *should* terminate the generic run — BIT, CHARACTER, NUMERIC are all keywords — but
"should" is a prediction. **Measure it before writing any fixture**, and if the measurement shows silent
acceptance, that is a defect to register, not a fixture to write around. `A.4.13's identical §5 note turned out
false by measurement on the same day`; this module's was inherited from the same sentence.

## What is owed

1. **A recognize-only grammar arm** (pre-authorized): `formatClause : FORMAT (BIT|CHARACTER|NUMERIC)+ DATA?` into
   `fileDescriptionClause`, and `selectWhenClause : SELECT WHEN (conditionName | OTHER)` into
   `dataDescriptionClause`. FORMAT is **non-reserved at COBOL-85 and reserved 2002–2023**
   (`ReservedWords.Table.cs`), so the token must be gated `{is2002()}?` or COBOL-85 source using FORMAT as a
   user-defined word stops parsing — run the mandatory edition-gate sweep.
2. **A named diagnostic, and it should be an ERROR rather than the COBOLNET1560 warning band.** The asymmetry has
   to be argued the way [[PB198]] argued COBOLNET0806: the 1560 facilities (SCREEN, MCS, COMMIT/ROLLBACK,
   VALIDATE) warn because they are **additive** — the program still means what it says with them inert. FORMAT is
   not: §13.18.24.4 GR8/GR9 change **what bytes reach the medium**, and SELECT WHEN changes **which record
   description is used**, with a status-45 failure path. Compiling them inert would write wrong bytes to disk,
   which is a wrong answer and not a missing facility.
3. **Four negative cases plus one unit fact**: `FORMAT CHARACTER DATA`; `FORMAT BIT CHARACTER DATA` (the
   choice-indicator combination, so the recognizer is not pinned to one alternative); `SELECT WHEN
   condition-name-1`; and `SELECT WHEN OTHER` — a two-arm construct needs both arms measured
   (`feedback_two_arm_dispatch`). Plus a unit fact covering 2002/2014/2023 and proving the COBOL-85 leg still
   accepts FORMAT as a user-defined word.

## Three things settled here so they are not re-litigated

- **§4 has NO item for this module.** Its four documented-non-support facilities are MCS, commit/rollback,
  VALIDATE and screen handling. The §5 row IS the whole of the §4.2.7 user documentation, and the `decision`
  string must not invent a §4 reference. (§4 now says so explicitly.)
- **The three DOC rows are stamped, and the licence is Annex A.1's own preamble** — *"When the element is part of
  a feature that is optional or processor-dependent, the item is not required if the optional or
  processor-dependent feature is not implemented"* (→ OK) — which answers DOC-A.1-84's own "This item is
  required" head-on, where the §4.2.7 route only answers it indirectly. `audit_annex_a1.py` was taught the same
  exclusion **derived from the same selectors** in the same change set, so §7's counter (199 → 195 in scope) and
  the inventory cannot give two answers about one item.
- **GR-9.1.13.7-5 (I-O status 45) is deliberately NOT in the set** and wants a one-row owner adjudication. Its
  text names CODE-SET, which is supported surface. Status 45 is *arguably* unreachable without the module — only
  two rules in 4,311 mention "record identification", and §13.18.51.4 GR4 is the only one that SETS the condition
  — but that is a three-clause deduction, and reachability is measured, not deduced.
