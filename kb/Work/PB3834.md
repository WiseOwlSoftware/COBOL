# PB3834 — PB3707's self-test arms depend on the real wall clock

**Sites:** `scripts/orchestrator/enqueue.py#self_test`, `scripts/run_gate_legs.py#self_test`

## The defect

PB3707 (landing with w20261703a) added a STARTING state for a gate run: a run directory younger than
`run_gate_legs.START_WINDOW_S` (60 s) whose spawn record names a live child reads as a gate about to run. Its
self-test arms name the run directory from `datetime.now()` and then assert the STARTING reading after real work has
run:

- `enqueue.py#self_test` names `000001-<now>` and runs a whole `run_land` before it asserts exit 12 (GATE BUSY). If
  that `run_land` takes more than 60 s on a loaded host, the run reads DIED and the arm fails.
- `run_gate_legs.py#self_test` names `000002-<now>` (the `stillborn` run) and another run from `stamp_now` the same way.

Nothing injects the clock, though `run_gate_legs.gate_starting(run, now=…)` and `run_age_s(run, now=…)` already take
`now`. This is a fixed time limit inside a test: a red with no regression (MANDATORY-PRACTICES rules on wall-clock
tests; memory no-wall-clock-tests).

## Fix

Inject the clock into the code under test, not around it: the readers that decide STARTING take `now` from their
caller, and the landing path that calls them (`enqueue.py`'s gate-record reader, `land_lane.py`'s wait) passes one
seam the self-tests set to a fixed instant beside a run directory named from that same instant. Sweep every self-test
in `scripts/` for `datetime.now(` or `time.time()` used to name or age a fixture and convert each the same way.

## Acceptance

- Both self-tests pass with the host clock moved hours forward or back between fixture creation and assertion (a
  test that sets the seam to `run time + 59 s` and `+ 61 s` measures both sides of the window).
- No self-test under `scripts/` names or ages a fixture from the real clock (a grep-based drift arm).
