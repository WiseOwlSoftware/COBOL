# PB5600 - at --std 2002 FLAG-85 and FLAG-NATIVE-ARITHMETIC are gated as words only: trailing text is accepted and no flagging is done

**Sites:**
- `src/WiseOwl.Cobol.Editions/CompilerDirectiveCatalog.cs#CheckOperand` (Text arm)
- `tests/version-matrix/constructs/flag-85-directive-window.json` and flag-native-arithmetic-directive-window.json (DirectiveOperand)
- `src/WiseOwl.Cobol.Frontend/Preprocessor/DirectiveStateRegistry.cs` (whole: the reader pinned no member; the fixer names it) (no state or processor for either)
- LANDED (kb/Work PB5600): `src/WiseOwl.Cobol.Frontend/Preprocessor/FlagDirective.cs` (`FlagDirective`, `FlagOption`, `FlagOptions.All`, `FlagDirectiveLine.TryParse`/`OfWord`/`Row`/`WarningCode`/`ConstructId`/`FormatCitation`), `FlagDirectiveProcessor.cs` (`Process`, `CheckOperand`), `Frontend.cs` (`LeftDirectives`), `DirectiveStateRegistry.cs` (the two rows now carried), `src/WiseOwl.Cobol.Editions/Diagnostics/DiagnosticCatalog.cs` (`Flag85Warning` COBOL7390, `FlagNativeArithmeticWarning` COBOL7391), `src/WiseOwl.Cobol.Compiler/Validation/FlagConformancePass.Flag85.cs` (every detector) and `FlagConformancePass.cs` (`Flag`, `MethodNameScope`), the two `constructs/` rows (now `stage` operands with `directivePlacement`), `tests/WiseOwl.Cobol.Tests.Unit/Flag85DirectiveTests.cs`.

**Mechanism.** The two directives are construct rows with DirectiveOperand Form=Text and the note 'operand syntax is NOT derivable in-repo ... Content unchecked by decision' (stale: the 2002 text prints both formats, 7.2.11.1 and 7.2.12.1). CompilerDirectiveCatalog.CheckOperand checks nothing for a Text row, and no processor implements the warning mechanism, so the directive is recognized and ignored.

**Inventory.** Rows claimed: `2002-SR-7.2.2-3`, `2002-SR-7.2.2-4`, `2002-GR-7.2.3-4`.

**Rules (each citation checked with `python scripts/spec/cite.py --check`, verdict OK).**

- `§2002:7.2.2 SR3`: "When the reference format is fixed-form, a compiler directive shall be written in the program-text area"
- `§2002:7.2.2 SR4`: "When the reference format is free-form, a compiler directive may be followed only by space characters and an optional inline comment"
- `§2002:7.2.11.3 GR1`: "The implementor shall provide a warning mechanism that flags the incompatibilities"
- `§2002:7.2.11.3 GR4g`: "The NUMVAL and NUMVAL-C intrinsic functions shall be flagged"

**Repro.** Scratch originals under `E:/COBOL-coord/scratch/op-20261114/read-2002/defects-work/` (p/d_f85_junk.cob, p/d_f85_numval.cob); the text is inline. Command: `cobol.exe p/d_f85_junk.cob --std 2002 --run`

`p/d_f85_junk.cob`:

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. DF85JUNK.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 X PIC 9 VALUE 0.
       01 Y PIC X(10) VALUE "123".
       PROCEDURE DIVISION.
           DISPLAY "A"
       >>FLAG-85 ALL ON JUNK
           DISPLAY "B"
           STOP RUN.
```

`p/d_f85_numval.cob`:

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. DF85NUMV.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 X PIC 9 VALUE 0.
       01 Y PIC X(10) VALUE "123".
       PROCEDURE DIVISION.
       >>FLAG-85 NUMVAL ON
           COMPUTE X = FUNCTION NUMVAL(Y)
           DISPLAY X
           STOP RUN.
```

**Observed.** d_f85_junk (>>FLAG-85 ALL ON JUNK): compiles, prints A B, rc=0, no diagnostic (the same compiler refuses >>LEAP-SECOND ON JUNK, COBOL1911); d_f85_numval (>>FLAG-85 NUMVAL ON then FUNCTION NUMVAL): prints 3, no warning.

**Expected (from the 2002 text).** d_f85_junk refused (only spaces and an inline comment may follow a directive); d_f85_numval compiles with a warning flagging the NUMVAL reference.

**Sibling sweep.** every other construct row with DirectiveOperand Form=Text; docs/conformance/3/D-IGNORED-DIRECTIVES.md does not list these two, so no recorded decision licenses ignoring them.

**Other editions.** 85: no (no directives). 2014: yes, the construct window runs 2002 to 2014, the same rows apply.
