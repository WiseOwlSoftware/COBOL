# Landing, 2026-11-16: the implementor-names, the refusal of every other word, and SR1 on both arms

**Re-probe on the branch before the fix** (`run_probe.py`, the checker's six programs): `rdfix`, `rdfixs`, `rdfoo`,
`rdown` and `rdstd` compiled and ran exit 0 with warning COBOL1778 only at `--std 85` and `--std 2023`; `rdnone` ran
clean. The defect reproduced as the note states. **After the fix:** `rdfix` COBOL7598 + COBOL7599, `rdfixs` COBOL1778 +
COBOL7599, `rdfoo` and `rdown` COBOL7598 (exit 65 each), `rdstd` exit 0 with COBOL1778, `rdnone` exit 0, at both editions.

**The decision completed.** The implementor-names are GnuCOBOL's (3.3-dev `cobc/parser.y`, `record_delimiter_option`):
BINARY-SEQUENTIAL, the record sequential length prefix (a sequential file's method anyway), and LINE-SEQUENTIAL, which
makes the file LINE SEQUENTIAL. GnuCOBOL's warning arm for any other word is a leniency and is not taken: every other
word is COBOL7598. One table holds them, `src/WiseOwl.Cobol.Compiler/Binding/RecordDelimiterNames.cs`; the binder reads
the operand's text, so neither name is a reserved word. LINE-SEQUENTIAL could be built: the organization
`FileOrganization.LineSequential` is the one switch the emitter and the line sequential connector read, so the binder
sets it (`FileControlBinder.ApplyRecordDelimiter`, after the whole entry, since ORGANIZATION may follow) and marks
`FileModel.LineSequentialByDelimiter`; the three rules whose subject is the WRITTEN phrase (§2023:12.4.5.2 SR12,
§2023:13.4.5.3 SR4, and the format marker of §2023:12.4.5.2 SR11) ask `FileModel.LineSequentialPhraseWritten`.

**SR1** (§1985:VII.2.8.3 SR1, §2023:12.4.5.11.3 SR1) is `FileControlBinder.ScreenRecordDelimiter`, post-build, on both
arms, through `FileModel.HasVariableLengthRecords` (the RECORD clause's variable formats and implied format 2, or a
line sequential file without a format 1 clause), which the FORMAT clause's rule now asks too. The 2023 text differs from
1985 only in wording (feature-name-1 for implementor-name-1), SR2's sentence that the implementor specifies the names, and
SR1's NOTE listing the three ways to variable-length records, the same three 1985 reaches through §1985:II.2.1.4.3 and
the RECORD clause's format 2.

**Siblings found and fixed in the same change:** the 1985 AT END rule exempted every LINE SEQUENTIAL file
(`ExceptionPhraseRequirement.Rule.TryGet`), which at 85 now means a file made line sequential by the clause, so it would
have under-rejected; the external connector identity compared the written phrase, now the method
(`FileEntryIdentity.Segments`); NIST's SQ219A writes the X-card XXXXX070 there, now substituted with BINARY-SEQUENTIAL
(`NistPreprocessor.Process`); and the 1985 case `pb5311-external-reserve-and-delimiter-defaults` wrote the clause on a
fixed-length file, now given RECORD CONTAINS 1 TO 4.
