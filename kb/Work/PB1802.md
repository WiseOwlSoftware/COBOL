## The design

**A. Comment-entry paragraphs — keep the header, discard only the comment-entry.** At every edition the converter
emits the paragraph HEADER (`AUTHOR.` — the word and its period, at its own columns, rest of the line blanked) as
program text and discards only the comment-entry (the rest of the header line and the Area-B lines up to the next
Area-A word). The grammar's five/six rules become `AUTHOR DOT (authorContent DOT)?` (the content is now absent in
fixed form and present in free form), and the ONE gate in `VersionConformancePass` decides: accepted at 85, COBOLNET0902
(error strict / warning `--permissive`, `EditionSeverityPolicy`) at 2002+ — identical in both reference formats.
Keeping the discard at 2002+ is the pre-removal semantics `--permissive` promises. No edition test in the text pass.

**B. Debugging lines — mark, and let the program's clause decide.** Three shapes (OWNER decision, see PB1705's
brief): (1) a pre-parse TOKEN rewriter (recommended) — the lexer lexes a debugging line's text as ordinary tokens
behind a hidden-channel `DEBUG_LINE` marker (the U+FDD0 carrier's successor), and a `DebuggingLineRewriter` beside
`ZeroTokenRewriter` / `CobolWordsRewriter` hides those tokens unless the enclosing source element (or a containing
one — PB1088) declared WITH DEBUGGING MODE in its SOURCE-COMPUTER paragraph, which precedes the procedure division in
the token stream; one pass, per source element; a token-level switch is sound because the COBOL-85 debug module requires a
program to be syntactically correct with and without its debugging lines (1985 text, not in the repo — the
implementer confirms it against the evidence in question 1 below before relying on it); (2) a parse → re-parse fixed point, the
precedent being `ReservationGateRewriter.ParseToFixpoint` and the GR14 implicit-op fixed point (`Frontend.Parse`):
parse with carriers as comments, and when a source element declares the clause, unwrap the carriers in its line range
and re-parse; (3) GnuCOBOL's shape (`cobc/pplex.l`: the preprocessor matches `[WITH] DEBUGGING MODE` lexically and sets
a GLOBAL `cb_flag_debugging_line` from that point on) — cheapest, but not per source element.

**C. Edition scope of the `D` indicator.** 2023: §6.2.2 lists no `D`, so a `D` line is not a fixed indicator at 2023
(today: silently a comment). The removed-construct shape is a registry row (`debugging-line-removed-<edition>`,
COBOLNET0902 strict / warning permissive with the pre-removal comment semantics), not COBOLNET2616, so a migrating
program keeps compiling under `--permissive`. **Which edition removed it is NOT established** — see the evidence
question below; the row's `removedIn` waits on it.

## ⚠ Edition evidence owed (the 2023 text cannot answer; the repo holds no 1985, 2002 or 2014 text)

1. **Debugging lines / WITH DEBUGGING MODE at 2002.** VCR rows 7.9 and 7.17 (landed gate
   `debugging-mode-removed-2002`, COBOLNET0902 at 2002+) say the facility left in 2002. GnuCOBOL 3.2 says otherwise:
   `config/cobol2002.conf` `debugging-mode: obsolete` (not `unconformable`), `config/cobol2014.conf`
   `debugging-mode: unconformable`, and `cobc/pplex.l` recognizes a `>>D` floating debugging indicator commented
   "2002 (only) floating debug line". If GnuCOBOL is right, WITH DEBUGGING MODE is LEGAL (obsolete) 2002 source that
   `--std 2002` rejects today (rejects-legal-source), a 2002 `>>D` line is unimplemented, and the `D` indicator's
   removal edition is 2014. Needs the ISO/IEC 1989:2002 text (Annex F / §7.x debugging) — owner.
2. **REMARKS at 85.** `constructs.json` row `remarks-removed-2002` accepts REMARKS at `--std 85` as "a '74 carryover
   accepted at 85 for CCVS" — i.e. a NIST accommodation applied at every 85 compilation rather than under `--nist`
   (the dialect-two-axes doctrine PB1494 enforced for the column-7 letters). Whether ANSI X3.23-1985 still had REMARKS
   decides whether the 85 acceptance is conforming or a leniency to gate behind `--nist`. Needs the 1985 text.

## Decided 2026-09-30 (owner) — kb/Work R61

Edition windows determined by research: comment-entry paragraphs and USE FOR DEBUGGING accepted at 85, rejected from 2002 (fixed form must enforce what free form does); WITH DEBUGGING MODE and `D` lines accepted at 85 and 2002 (obsolete, warning), rejected from 2014. Decision note R61 (GnuCOBOL dialect files + web; confidence in the body).
