# PB170

PB155 widened the §8.8.1.1 class screen to `OperandContext.ArithmeticIndexWindow` (the R29 contexts: SET,
PERFORM/SEARCH VARYING, compound subscripts, compound relation/EVALUATE operands — pinned by
`pb155-set-to-edited`). The PB155 review fleet's refuter measured the arm that widening cannot reach: a
SIMPLE subscript name resolves in `ReferenceResolver.ResolveSubscriptName` → `PositionRead`, which renders
`CobolTable.Occ(<string field>)` directly from the token — `ExpressionBinder.OperandRef` never runs, so no
class screen fires. `T(XE)` with `01 XE PIC X(4)` (or `PIC XXBXX`) compiles clean under STRICT and
digit-decodes the image, while `T(XE + 1)` now draws COBOLNET0844.

WHAT WOULD CLOSE IT: the same category test at the resolver's subscript-name arm (only an integer numeric
item or an index-name is a legal subscript, §8.4.2.2), a negative fixture `T(<PIC X item>)`, and a sweep of
the resolver's other direct-render arms for the same bypass.
