**Rule it breaks:** §2023:11.3.4 GR6 (§2023:11.6.4 GR4 for an interface): "Parameter-name-1 may be specified within this class definition only where an object-class-name or an interface-name is permitted." AddSkeleton enforces it through DeclarationSlotWords/SlotOf, a hand-written list of declaration name rules (dataName, conditionName, paragraphName, sectionName, methodName, fileName, reportName, propertyName). An index-name is declared by indexNameList (CobolData.g4:776, 784, 793: a bare cobolWord list), which has no case, so SlotOf answers null and the word passes as a reference.

**Scenario:** CLASS-ID. P USING T. with REPOSITORY. CLASS T. and, in the OBJECT data, 01 TBL. 05 E PIC X OCCURS 3 INDEXED BY T. No GR6 diagnostic is raised at the skeleton (OoExpansion.cs:261-268). An expansion REPOSITORY. CLASS PA EXPANDS P USING ACCOUNT. substitutes every user-defined-word occurrence of T (SubstitutedTokens, OoExpansion.cs:595-597), so the expansion declares an index-name ACCOUNT beside its substituted CLASS ACCOUNT specifier; the class definition and the instance definition are separate source elements whose census admits the reuse (§2023:8.4.6.1; OoDriver.BindClassData, kb/Work PB3154), so it compiles clean with the index renamed: exactly the silent rename the AddSkeleton comment (lines 256-260) says the screen exists to prevent. The same gap covers the communication DESTINATION TABLE INDEXED BY list.
