- *A function's returned value kept 34 digits.* `NumericRenderer.FunctionValue` cuts a decimal function value to the standard intermediate data item (§2002:15.3.1 "contained in a temporary standard intermediate data item"): PI and E are their equivalent expressions' 32-digit constants.
- *The equivalent arithmetic expressions ran in the 34-digit model.* The decimal bodies took a `CobolRounding`. They now take `DecArithmetic` (new, runtime), the one parameter that is the SDIDI (`Sdidi`) or the 32-digit standard intermediate data item (`Standard`, each operation cut by `CobolDec.ToSidi`, integer powers by `PowStandard`), so one body is the value in both models. `IntrinsicRenderer.RenderDec` takes every call under ARITHMETIC IS STANDARD (the exact family's equivalence with the SDIDI is a 34-digit one); EXP is `E ** argument-1` over the 32-digit E; MOD and REM skip the exact-integer remainder there.
- *Situation 2.* `IntrinsicRenderer.StandardArgument` rounds a standard intermediate argument to 31 digits unless `IntrinsicCarrierRules.RoundsStandardArgument` says the function keeps all 32: the functions with an equivalent expression in 2002 or 2014, SQRT ("argument-1 is not rounded"), MAX/MIN/ORD-MAX/ORD-MIN (situation 1's comparison among the arguments).
