# PB3862 — the fuzz classifier does not set aside programs that display unwritten storage

**Sites:** `scripts/differential_fuzz.py#classify`, `scripts/differential_fuzz.py` (`row_undefined`, `rederived`, `render_report`, `Fuzz._one`, `self_test`), `scripts/fuzz_undefined.py` (`undefined_results`, `Analysis`, `DataDivision`), `scripts/test_fuzz_undefined.py`, `docs/rearchitecture/DESIGN-differential-fuzz.md` (§2, §7)

## The defect

Eight of the 17 `OUTPUT_DIFFERS:14.9.25` rows of the fifth fuzz night (fz01110, fz01111, fz01282, fz01933, fz01980,
fz02818, fz04400, fz00704; PB3468 class 2) are programs that DISPLAY storage no statement wrote: a `MOVE CORRESPONDING` or
group move whose names do not correspond, then a DISPLAY of items with no VALUE clause. The standard leaves the initial
value undefined (ISO A.2 19), so WiseOwl's zeros and spaces against GnuCOBOL's NULs is not a difference of either
compiler. `classify` reports them as `OUTPUT_DIFFERS`, a candidate wrong answer, so a human triages each one. Harm: triage
time only.

## Failure scenario (verbatim from the report)

"eight of the 17 rows are programs that DISPLAY storage no statement wrote (undefined, section A.2 19);
`scripts/differential_fuzz.py:900` (`classify`) could set such programs aside." Repro:
`E:\COBOL-coord\scratch\op\w-pb3852\w20261711d\src\20261021-fz01111.cob`.

## Acceptance

- A program whose DISPLAYed bytes come from an item no statement wrote and that has no VALUE clause is classified as the
  model's non-conforming program (its own class, counted against the model, never a lead), decided mechanically from the
  source, with a self-test arm per shape (group move with no corresponding names, an item never targeted) each seen RED
  first; an item with a VALUE clause, or written by any statement, still compares.
- Sweep the classifier for its siblings: any other kind of undefined result PB3468 recorded (incompatible data, an
  unchecked out-of-range subscript) that reaches the lead list.
- Standing owner rules: fix the root causes, never simply making the diagnostic pass; always be consistent with
  ourselves barring an explicit requirement differently.

## Landed

**Re-probe** (this branch's build, `src/WiseOwl.Cobol.Cli/bin/Debug/net10.0/cobol.exe`, GnuCOBOL 3.2 under WSL, the harness's own
`observe` and `classify`): fz01111, fz01110, fz04932 and fz04934 of the repro directory all classified `OUTPUT_DIFFERS` before the
change, so the defect reproduced.

**Fix.** The decision is a function of the program's text, so it lives in one place, `scripts/fuzz_undefined.py#undefined_results`,
and `classify` takes its yes/no (`undefined=`). An output difference in a program the function finds something in is the new
class `UNDEFINED_RESULT`, among `MODEL_FAILURE_CLASSES` (counted against the model, never a lead). Definedness is the least
fixed point of the data flow, so the three shapes PB3468 class 2 found are decided: a MOVE CORRESPONDING whose names do not
correspond (fz01111, fz02818), an item never targeted, and a copy (group MOVE or CORRESPONDING) of an unwritten group (fz01110,
fz01933, fz04400, fz00704, fz01282, fz01980). It abstains rather than guesses (COPY, OPTIONS, RENAMES, directives, a second
program), reads any statement that names an item other than as a DISPLAY operand or a MOVE sender as a possible write, and a
VALUE (or a group's) as a write. The row records its findings (`undefined`); `--report` reads a row recorded before this note from
its source, so an old night is shown under the new class.

**The acceptance sweep** (the other undefined results PB3468 recorded that reached the lead list): a literal subscript outside its
OCCURS (`SUBSCRIPT_RANGE`, ISO 8.4.2.3.4 2, 14.6.13.1.1 NOTE 3) and an alphanumeric literal with a letter MOVEd to a numeric
item (`INCOMPATIBLE_DATA`, ISO 14.9.25.4 6; fz04932, fz02113) are decided by the same function. Two PB3468 shapes need the
program RUN and stay leads, by design: a variable subscript or reference-modification position that a PERFORM VARYING leaves
past its bound (fz04934 `WS-EA-VAL (WS-LEN)`, fz04932's `WS-SRC (1:WS-LEN)`), and the content a MOVE moves (a spaces item to a
numeric one). A literal reference-modification range is refused at compile time by both compilers (DOC-A.1-69) and never
reaches the lead list.

Of the 17 rows, the 8 class-2 programs plus fz04932 and fz02113 (incompatible data) become `UNDEFINED_RESULT` (10); fz01932,
fz01981, fz02112, fz04079, fz05487, fz06194 and fz04934 are not decided by a program's text and keep their verdict.
