**What the emitter does today** (`OoEmitter.EmitClassUnit`, `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/OoEmitter.cs:348` and `:395`): a COBOL class is a C# class whose base is the ONE superclass (`public class Q6DD : Q6DB`), its factory half is the sibling `__FACTORY_Q6DD : __FACTORY_Q6DB`, and a typed `OBJECT REFERENCE Q6DD` is a field of C# type `Q6DD?` (`ObjectRefDescriptor.ClrTypeName`). Method resolution (`OoClassSymbol.FindMethod`, `FindFactoryMethod`, `ConformsTo`, `InheritsStandardBase`) walks the single `Base` chain; the `Base` chain is also read by `OoClassTable` (cycle, FINAL, roster marking at lines 406, 515, 931, 1105-1154), `OoConformance` (280, 362), `OoBinder` SUPER search (673-688), `EcBinder` (398), `RepositoryCodec` (66, `ClassRecord.BaseIdentity`), `MetadataRepositoryProvider` (658-672) and the runtime `__CobolInvoke` chain (`base.__CobolInvoke`).

**Why this is not a clause-sized change.** C# has one base class. A class `Q6DD` with superclasses `Q6DB` and `Q6DC` has to be assignable to a variable declared `OBJECT REFERENCE Q6DC`, which today is a C# variable of class type `Q6DC`. Four properties of the spec force the shape:
- §2002:9.3.9 "The subclass has all the methods ... and all the data definitions defined for the inherited class or classes"; the NOTE: "the subclasses are treated as if their source code had a copy of the superclass definitions".
- §2002:11.2.3 GR4: "If the same class is inherited more than once, then only one copy of the data for that class is added" (the diamond: one copy of `Q6DA`'s data, so a part-object per base chain, each carrying its own `Q6DA`, is wrong).
- §2002:9.3.5 rule 2: methods are searched "in left to right order as written in the INHERITS clause".
- SELF inside an inherited method of `Q6DC` must dispatch to `Q6DD`'s overrides, and object identity (`IF A = B`, SET, EC-OO class tests) must see one object.

**The shape that satisfies all four (design, for the implementer of the first slice):**
1. Every class emits, beside its C# class and its factory class, a C# instance interface and a factory interface carrying its whole method roster (own plus inherited, by the one `MethodRoster.Find` linearization, left to right per §2002:9.3.5 rule 2). `ObjectRefDescriptor.ClrTypeName` for the ObjectClass kind then names that interface, exactly as the Interface kind already does (`IsClrInterface`, `OoEmitter.EmitInterfaceUnit`); every conversion site that a CLASS type allowed implicitly (return covariance, `CobolObject` upcast, `OoReturnClrType`) takes the Interface kind's existing cast rule (kb/Work PB1499). Doing it for every class, never only for a class that happens to be a secondary base, is what makes a class imported from a repository (compiled before the subclass existed) work.
2. The primary superclass (first in the clause) stays the C# base class, so the single-inheritance output, `__CobolInvoke` chain and BASE life-cycle are unchanged for every existing program. Each further superclass, and each ancestor of one not already on the primary chain, is a COPY INTO the subclass: the subclass body carries that class's data forest and method bodies re-emitted from the class's own bound unit (the `EmitTypeHalf` parameterization, which already renders fields, methods and dispatch into a named type from a data forest, place table and roster), its fields and members renamed per source class so two inherited classes' same user-defined words cannot clash (§2002:9.3.9: "User-defined words in an inherited class are not visible in the subclass"). A class compiled in the same group re-emits from its bound unit; a class imported from a repository has no bound unit, and needs the repository to carry its method bodies (a `ClassRecord` extension) or the diagnostic stays for that one case with a stated reason.
3. Binder: `OoClassSymbol.Bases` (already carried) replaces `Base` in the walks listed above through ONE linearization (C3 or left-to-right depth-first with a seen set, chosen and recorded in `docs/conformance/`), `SUPER` follows §2023:8.4.3.8.3 SR5 ("If the INHERITS clause of the containing class definition specifies more than one object-class-name, object-class-name-1 shall be specified"; moot today), `OoClassTable` enforces §2002:11.2.2 SR6 and SR7 (FINAL through two bases; conforming inherited prototypes, the interface twin is `OoInterfaceSymbol.ChooseInheritedPrototype`, COBOL2762), and COBOL0849 is retired with its `DeclinedFacilityAnnexDriftTests` row (rule 4: no leftover).
4. Goldens at 2002: the diamond above (one `Q6DA` data copy, left-to-right resolution, FINAL through intermediates legal), a FINAL-twice refusal, a repeated name refusal (SR8, already COBOL2791).

**Sizing, honestly.** About 20 `.Base` walk sites in the compiler, every typed-reference emission site (`ClrTypeName` readers: 469 `ClrName` mentions in `src/WiseOwl.Cobol.Compiler`), the factory half in step with the instance half, the repository record, and the data-copy re-emission, which is the one piece with no precedent in the emitter. That is several mechanisms (descriptor and interface emission; linearized binder walks and rules; data and method copy re-emission; repository carrying), each needing the full gate, and more than one 400-turn implementer. The note's Scope line also names parametric polymorphism; its four rows do not reach it (§2002 has no method resolution signature overloading, only §2023:9.3.5.3), so it stays declined with COBOL0822 and is not part of this note's closure.

**Recommended slicing for the next implementers.** (a) Interface-typed class references and the factory/instance interfaces, behavior-neutral at single inheritance, proven by the whole OO population at an unchanged output; (b) the linearized binder walks and rules with `Bases`, COBOL0849 still refusing 2+ bases so the slice lands green; (c) the data and method copy re-emission plus the removal of COBOL0849 and the goldens, closing the four rows with `record_verdicts`.
