# PB1631 — OPEN

Filed 2026-09-26 by the train-64 lander from the wave-62 O (PB1617) implementer's report, lead 2.

## Repro
`INVOKE obj "M" USING BY VALUE ZERO` — refused with `BY VALUE ZERO: literal-2 shall be a numeric literal when the BY
VALUE phrase is specified (ISO §14.9.23.3 SR16)`. LATENT: the next check in the same arm refuses every BY VALUE
argument because no INVOKE formal is BY VALUE yet, so the wrong reason is reported but no legal program changes
outcome until INVOKE BY VALUE formals are carried.

## Rule
§14.9.23.3 SR16: "If literal-2 or its corresponding formal parameter is specified with the BY VALUE phrase,
literal-2 shall be a numeric literal." §8.3.3.6.3 SR1 a): "If the literal is restricted to a numeric literal, the
only figurative constant permitted is ZERO (ZEROS, ZEROES) without the ALL phrase." So BY VALUE ZERO satisfies SR16.

## Code site
`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/OoBinder.cs:633` — the SR16 guard exempts only `NULL_()` among
figuratives; it must also admit `zeroWord()` without ALL (the CALL twin, `CallBinder.Sr23LiteralIsNumeric`, already
does). PB1617 made BY CONTENT ZERO into a numeric INVOKE formal take the numeric-literal lane (OoBinder ~1003).
