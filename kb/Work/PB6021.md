# PB6021 - a signed integer operand draws a parse error, not the integer rule

**Sites:** `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolData.g4#occursClause` (the OCCURS integer operand), the
data-description recovery that emits COBOL1941, and `src/WiseOwl.Cobol.Compiler/Validation/IntegerOperandPass.cs#Run`
(the one screen that gives a zero integer COBOL2386 with §1985:III.2 p142's words).

**Repro (this branch's build, 2026-11-21):** `python scripts/orchestrator/run_probe.py --root <scratch> --std 85 --exe
<cobol.exe> E:/COBOL-coord/scratch/w20262131o/probes/g-03/p142_signed_refused.cob`:

    p142_signed_refused.cob(9,31): error COBOL0001: cannot parse construct near '+'
    p142_signed_refused.cob(9,31): error COBOL1941: unexpected '+'. '+3' is not a clause of the data description entry for 'E' ...

**Expected.** §1985:III.2 p142 (cite.py OK): "Where the term 'integer' appears in the general formats, integer must be a
numeric literal which is an integer, and it must be neither signed nor zero unless explicitly allowed by the rules for
that format." The refusal is right; the diagnosis is not: `OCCURS 0 TIMES` names this rule (COBOL2386), `OCCURS +3 TIMES`
names a closed clause list that is not the reason. The grammar should take a signed numeric literal where a format says
integer, and the one integer screen refuse the sign with the rule's words (one mechanism for zero and sign); sweep every
general-format integer position for the same shape.
