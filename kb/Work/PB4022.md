# PB4022 — an already-UTF-8 stream with the strict handler still raises on `reconfigure`

**Sites:** `scripts/standard_streams.py:69` (`ensure_utf8`).

**What.** PB3823 made `ensure_utf8` leave a stream untouched when its encoding is UTF-8 and its errors handler is the right
one. When the encoding is UTF-8 but the handler differs (`PYTHONIOENCODING=utf-8` makes stdin `strict`), the function calls
`reconfigure(encoding=..., errors=...)` with both, and `sys.stdin.reconfigure` refuses an `encoding` argument after a read
with `io.UnsupportedOperation`, though the bytes were decoded correctly. The docstring says the refusal propagates only for a
stream NOT yet UTF-8.

**Repro.** `PYTHONIOENCODING=utf-8 python -c "import sys; sys.stdin.readline(); from standard_streams import ensure_utf8; ensure_utf8()"` with `scripts/` on the path.

**Fix shape.** Pass `errors` alone when the encoding is already UTF-8 (the setter that is allowed after a read), `encoding` too
only when it is not; add an arm with `PYTHONIOENCODING=utf-8` after a read.
