# PB4509 — a bare self-name CALL at 85 is taken as a prototype CALL

**Found:** 2026-11-03, PB4503's round-2 branch review (lead R2-2). Pre-existing: origin/main and PB4503's head both
compile `CALL P7 USING N W` clean at `--std 85`, where `P7` is the program's own name and no data item `P7` exists.

**Mechanism.** `BindCall` selects Format 2 through spelling (b): a bare word naming the program's own or a containing
program definition, which `BinderDriver.ProgramPrototypesOf` registers with no REPOSITORY. Below 2002 there is one
CALL format and no program prototypes, so the word is an identifier-1 that must name a data item (or the call must use
a literal). With `formatTwo` true and PB4503's `judgedUpFront` also true, the skipped arguments shift every later
operand's `args.Count` against `calleeFormals`, and the per-argument SR21/SR24 checks are lost.

**Fix.** The prototype registry is an edition-2002 construct: below 2002 the bare word resolves as an identifier and
an undefined one is refused; the edition check belongs where the format is chosen, not on each argument. Re-verify
the citations for the 85 CALL identifier rule with `cite.py --check` before writing them into code or goldens (they
are not recorded here because the review did not check them).
