# PB4509 — a bare self-name CALL at 85 is taken as a prototype CALL

**Found:** 2026-11-03, PB4503's round-2 branch review (lead R2-2). Pre-existing: origin/main and PB4503's head both
compile `CALL P7 USING N W` clean at `--std 85`, where `P7` is the program's own name and no data item `P7` exists.

**Mechanism.** `BindCall` selects Format 2 through spelling (b): a bare word naming the program's own or a containing
program definition, which `BinderDriver.ProgramPrototypesOf` registers with no REPOSITORY. Below 2002 there is one
CALL format and no program prototypes, so the word is an identifier-1 that must name a data item (or the call must use
a literal). With `formatTwo` true and PB4503's `judgedUpFront` also true, the skipped arguments shift every later
operand's `args.Count` against `calleeFormals`, and the per-argument SR21/SR24 checks are lost.

**Fix.** The prototype registry is an edition-2002 construct: below 2002 the bare word resolves as an identifier and
an undefined one is refused; the edition check belongs where the format is chosen, not on each argument. Re-verify
the citations for the 85 CALL identifier rule with `cite.py --check` before writing them into code or goldens (they
are not recorded here because the review did not check them).

**Re-probe (2026-11-03, wave 20261850 B, on 066659303).** `CALL P7 USING N W` in P7 at `--std 85` drew COBOL1684, the
prototype CALL's argument-count check, so the word was still read as a prototype. A nested program's `CALL OUTR` and
`CANCEL OUTR` of its container compiled CLEAN at 85. `CANCEL NOSUCH` at 85 drew COBOL1760, whose message names the
REPOSITORY paragraph and §8.4.6.8, neither of which COBOL-85 has. The CANCEL arm is the sibling: §14.9.5.2's third
operand alternative is the same 2002 spelling.

**Fix (landed).** The edition read is in one place, `CallBinder.ProgramPrototypeNamesExist`, over the new construct row
`program-prototype-name-2002` (ISO/IEC 1989:2002 §8.4.5.7 carries the sentence of the 2023 §8.4.6.8). Four sites ask
it: both arms of CALL's spelling (b) (the registered prototype, and the REPOSITORY specifier no provider answered),
CANCEL's prototype arm, and the PB4503 up-front argument judgement. So below 2002 a CALL is never both judged up front
and Format 2. Below 2002 the bare word is identifier-1 (OK §14.9.4.3 1), OK §14.9.5.3 1)), and one that names no data
item is the §8.4.2.1 undefined reference, COBOL1639, at CALL and CANCEL alike. The registry
`BinderDriver.ProgramPrototypesOf` is the same at every edition. This is a behavioral read
(DESIGN-version-conformance-pipeline §1.1 item 3, the twin of IntrinsicBinder's keyword-omission routing): the spelling
is written exactly like identifier-1, so no recognition gate can see it. The `call-as-phrase-2002` row said the bare
spelling needed no gate because REPOSITORY is 2002-gated; that was false for the containing spelling, and the row now
says so. Witnesses: `conformance-suite/cases/14.9.4-CALL/pb4509_call_containing_program_by_name` (accepted from 2002: a
nested program CALLs its RECURSIVE container by name), the refusals `14.9.4-CALL/pb4509-call-containing-name-85` and
`14.9.5-CANCEL/pb4509-cancel-own-name-85` (COBOL1639 at 85), and the program-prototype-name-2002 version-matrix row.
