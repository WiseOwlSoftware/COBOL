# PB4851 - Python packages outside the toolchain manifest

**The rule.** `toolchain.env` is THE ONE TOOLCHAIN MANIFEST (kb/Work PB4007). Owner 2026-10-28: "CI tooling should match local
tooling versions - always", and "CI and local should always be using the latest version". It names every tool's version, and
CI, the Windows box, WSL and the cloud image install from it.

**The defect.** The Python packages the scripts import are not in it:
- `pyyaml==6.0.3`, `numpy==2.5.4` and `tzdata==2026.4` are pinned in pip lines in `.github/workflows/build-and-test.yml` (twice)
  and `.github/workflows/nightly.yml`. They are three hand-kept copies, and no host installs from them.
- PyMuPDF (19 `import fitz` sites under `scripts/`, all lazy but one) and `anthropic` (`scripts/fuzz_claude.py`, the converter
  PB4816 plans) are named nowhere. CI installs neither, and each host carries whatever it once installed. On 2026-11-06 the
  Windows box had PyMuPDF 1.28.2, which still provides the deprecated `fitz` alias, while the latest release is 2.1.
  `toolchain.py latest` cannot report a package it does not know.

**What it cost.** PB4815 moved `scripts/render-spec-page.py`'s PyMuPDF import to module level. Every local gate passed, because
the host has PyMuPDF. CI's `standard_streams.py --self-test` probes each entry point's `--help` under a Python without it, and
it failed twice in the merge queue (PR #1237). No manifest said whether CI should have the package at all.

**The fix.**
- `toolchain.env` names each Python package the tooling imports, at its latest version: pyyaml, numpy, tzdata, PyMuPDF and
  anthropic.
- `setup-toolchain` installs them in CI, and the Windows box, WSL and the cloud setup install them too. The three workflow pip
  lines are deleted.
- `toolchain.py check` compares each installed package version, and `toolchain.py latest` asks PyPI for each.
- A drift test fails when a script imports a third-party package the manifest does not name. It decides which imports are
  third-party from the standard library list, not from a hand-kept list.
- Decide, with the owner if it is unclear, whether the lazy-import rule stays (scripts usable on a host without PyMuPDF) once
  CI installs PyMuPDF. The standard-streams `--help` probe is the rule's current enforcement.
- When PyMuPDF moves to 2.x, every `import fitz` becomes `import pymupdf`. The finisher of #1237 does this sweep on PB4815's
  branch; check that it landed.

**Sites:** `toolchain.env` (whole: the Python packages are added), `.github/actions/setup-toolchain/action.yml` (whole: installs them), `.github/workflows/build-and-test.yml` (whole: the two pip lines are deleted), `.github/workflows/nightly.yml` (whole: its pip line is deleted), `scripts/toolchain.py` (`check`, `latest`), `scripts/hooks/tooling_check.py` (whole: it prints the package comparison), `scripts/wsl/setup-wsl.sh` (whole), `scripts/cloud/setup-env.sh` (whole).
