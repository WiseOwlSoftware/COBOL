## ⛔ MEASURED FIRST — because the briefs' own warning describes the wrong failure

Run against the already-built `tests/Cobol.Net.Tests.Unit/bin/Debug/net10.0/Cobol.Net.Tests.Unit.dll`
(discovery/execution only — nothing was built, nothing was written), VSTest 18.10.0:

| filter | result |
|---|---|
| `--TestCaseFilter:DiagnosticRegistryDriftTests` (bare — no property, no operator) | **5 tests listed** — vstest defaults a property-less term to `FullyQualifiedName~` |
| `--TestCaseFilter:FullyQualifiedName~DiagnosticRegistryDriftTests` | the same 5 |
| `--TestCaseFilter:~DiagnosticRegistryDriftTests` (leading tilde) | `Incorrect format for TestCaseFilter Error: Invalid Condition '~DiagnosticRegistryDriftTests'` — **selects nothing** |
| `--TestCaseFilter:VcrStatusDriftTests` (valid, names a test that does not exist) | `No test matches the given testcase filter` · **no verdict line** · **EXIT 0** |

**Two distinct silent greens, and the briefs name only the first.**

1. `~X` — a malformed condition. This is `feedback_vstest_filter_terms`, and
   `lander-train-brief.md:11` warns about it in as many words.
2. **A well-formed term that names nothing.** vstest accepts it, runs zero tests, prints no `Passed!`/`Failed!`
   and exits 0. Nothing in any brief mentions this, and it is the one that arrives by ordinary drift — a test
   class renamed, a wave's filter copied forward — rather than by a typo. It is exactly [[PB708]]'s PB691
   instance and exactly what `filter_population.py` was written to catch.

## Two sites that are worse than merely unguarded

- **`lander-train-brief.md:11` contradicts itself in one paragraph.** It says *"⛔ Launch every build and every
  gate through the PowerShell TOOL (`pwsh scripts/build-local.ps1 -Filter "…"` builds the solution and expands
  the filter)"* — and then prints three raw `dotnet test` command lines for the reader to copy. An agent
  following the ⛔ sentence and an agent following the commands get different guarantees, and only the first is
  the one the sentence promises.
- **`gate/SKILL.md:26`'s placeholder is `--filter "<the wave's tests>"`** — no property in the template at all,
  where its neighbour at `:24` shows `FullyQualifiedName~`. `gate/SKILL.md` carries no `~X|~Y` warning anywhere
  (the warning lives only in `lander-train-brief.md:11`), so the file that is named `gate` and describes the
  wave-local gate is the one that shows the reader the un-prefixed form with no caution beside it.

## Why it matters here specifically

A gate filter is a CLAIM about which tests ran (`feedback_verdict_evidence_invariant`,
`feedback_measure_the_selectors_complement`). An agent's report says *"wave-local gate green, filter
`~Corpus|~Negative`"*, a lander verifies the report, and a train lands — and none of those three steps can see
that one term selected nothing. That is not hypothetical: it is [[PB708]]'s PB691 instance verbatim, where the
implementer, the finisher and everyone who copied the filter forward all believed a drift test had run through
the gate's filter and nothing had.

## Fix shape

Route every brief's gate through `scripts/build-local.{ps1,sh}` and **delete the raw `dotnet test --filter`
spellings**, so there is no copyable form of the unguarded shape left. The script already does all of it —
`build-local.ps1:34` / `build-local.sh:38` call
`python scripts/filter_population.py --filter "$Filter" --filtered … --unfiltered …` before the legs run, and
`build-local.ps1:45` refuses a leg with no verdict line.

Per site:

- `gate/SKILL.md:23-26` — one `pwsh scripts/build-local.ps1 -Filter "…"` line replacing all three, since the
  script already runs Characterization and Unit unfiltered.
- the four templates — the same substitution; `lander-train-brief.md`'s ⛔ sentence then matches its own
  commands.
- ⚠ `lander-train-brief.md:11` additionally mandates the FULL Unit assembly and the legacy
  `CobolSharp.Tests.Integration` assembly. Check `build-local`'s assembly set covers both before deleting those
  lines — a "route it through the script" edit that silently drops the legacy assembly would trade this defect
  for battery #57's START KEY red. **Measure the script's assembly list; do not assume it.**

`feedback_green_gates_arent_evidence`: after the edit, make one brief's filter name a nonexistent test once and
confirm the gate REFUSES, before trusting the change.
