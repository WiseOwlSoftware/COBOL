# PB332 — the audit that returns a clean zero for the whole compiler

**Rows:** `FMT-14.9.41.2`, `FMT-14.9.49.2` (`FMT-14.9.30.2` is owned by **PB331**, which repairs the same
grammar rule). Found independently by three adjudication subjects — read p1, start p1, use p1.

## The rule that governs all of them

> §5.2.3: Optional words are reserved words or context-sensitive words. They are shown in uppercase and not
> underlined in general formats. They may be written to add clarity ...

> §8.3.2.4.3: Within each format, uppercase words that are not underlined are called optional words and may be
> specified at the user's option with no effect on the semantics of the format

Both `--check` → **OK**; §5.2.2 confines *required* to the underlined keywords, and §4.2.2 obliges the
implementation to accept the standard language elements.

## The three statements

**READ — `ADVANCING ON LOCK`.** `python scripts/spec/figure_extract.py 722` reconstructs the printed format with
underlining measured from the PDF's vector rectangles and prints `_ADVANCING_ ON _LOCK_` — ADVANCING and LOCK
underlined, ON not. `READ SQF NEXT RECORD ADVANCING LOCK ...` → `error COBOL0001: missing token before 'LOCK'`
(`out-b1/probe/lockcombo/seq5.cob`); `ADVANCING ON LOCK` compiles (`seq6.cob`). The grammar writes
`readAdvancingOnLock : ADVANCING ON LOCK ;` with ON as a bare token. **The extractor is not simply
under-reporting underlines on that page:** the same run marks IGNORING, LOCK, NO, KEY, INVALID, NOT, END,
PREVIOUS, INTO, READ, END-READ, ADVANCING as underlined and RECORD, WITH, IS, AT, the KEY after INVALID, and
NEXT as bare — an internally discriminating result. Every other optional word on that page is already handled
correctly in the same file (`RECORD?`, `WITH? LOCK`, `KEY IS?`, `AT? END`, `INVALID KEY?`), so this is one
missed word, not a policy.

**START — `WITH LENGTH`, and its inverse.** §14.9.41.2 prints `[ WITH LENGTH arithmetic-expression-1 ]` with
LENGTH underlined and WITH NOT underlined — verified by rendering PDF page 784 (printed folio 754) at 600 dpi,
not taken from the OCR. `START IXF KEY IS = IX-KEY LENGTH 3 INVALID KEY ...` is rejected: COBOL0001 *missing
token before 3*, then a COBOL0001/COBOL0306 cascade (`out-b1/probe/fmt/prb.cob`). The grammar writes
`startWithLength : WITH LENGTH arithmeticExpression`. **The same phrase carries the inverse error:**
`startKeyPhrase : KEY IS? comparisonOperator? dataReference (startWithLength)?` makes relational-operator
optional, which the rendered diagram does not — so `START IXF KEY IS IX-KEY` (no operator) compiles and runs
(`out-b1/probe/ix-ops/prb.cob`). The comment defending it cites §14.9.41 for a bracketing the printed format
does not carry, and §14.9.41.4 GR15 supplies the implied EQUAL only when the whole KEY PHRASE is omitted, never
when only the operator is. The operator-set half of that phrase is **PB333**.

The rest of START's format was checked against the same 600-dpi render and is correct: the plain outer bracket
over FIRST/KEY/LAST, the choice indicators on the INVALID group, the un-underlined KEY of INVALID KEY, and
`[ END-START ]`.

**USE — two of four optional words in Format 1, and one in Formats 3 and 4.** §14.9.49.2's figure notes measure
the underlining: in Format 1 `USE`, `GLOBAL`, `EXCEPTION`, `ERROR`, `INPUT`, `OUTPUT`, `I-O`, `EXTEND` are
underlined while `AFTER`, `STANDARD`, `PROCEDURE` and `ON` are not; in Formats 3 and 4 `AFTER` is not
underlined. All five of these are legal and all five are rejected COBOL0001
(`out-b1/probe/fmt-optwords/`, `fmt-f3/`, `fmt-f4/`):

```
USE ERROR PROCEDURE ON F1.          USE AFTER STANDARD ERROR ON F1.
USE EXCEPTION CONDITION EC-ALL.     USE EC EC-ALL.        USE EXCEPTION OBJECT CF4A.
```

The grammar writes `USE GLOBAL? AFTER STANDARD? (EXCEPTION | ERROR) PROCEDURE ON? useOnTarget` — STANDARD and ON
optional, AFTER and PROCEDURE mandatory. **Its own comment shows the reasoning that produced the split:**
STANDARD and ON were relaxed because *the CCVS suite and mainstream compilers write both* spellings — i.e. the
optional-word set was derived from what the witness corpus happens to contain rather than from §8.3.2.4.3, so
the two words no witness omitted stayed required. The corpus is a regression net, never the authority.

## The root: the audit that exists to find this class returns zero

`python scripts/spec/audit_grammar_optional_words.py` (main tree, PDF present) reports *grammar files scanned:
11 · parser rules: 544*, then **statements with a located general format: 0** and **0 candidate(s)**; with
`--statement READ` it says *no general-format page found for statement READ*. Its docstring says it locates the
page from the markdown's `14.9.N.2 General format` heading and its enclosing page anchor — and the de-paging
removed those anchors (`clause_page.py`'s own docstring records the same breakage in the grammar-conformance
workflow). Until it is repaired, every optional-word finding is hand-work, and the compiler has a silently-green
gate over 544 rules.

## The fix shape

Repair the audit FIRST (it is the thing that makes the next case automatic), then let it drive the sweep. For
USE, the optional words of a format are a PROPERTY of the format: make each `useStatement` alternative carry
every non-underlined word as optional (`AFTER? STANDARD? ... PROCEDURE? ON?` / `AFTER?` on Formats 3 and 4) and
let the alternatives disambiguate on the UNDERLINED keywords, which they still can — CONDITION/EC and OBJECT/EO
are lexer keywords immediately after EXCEPTION, so `USE EXCEPTION F1.` is unambiguously Format 1. Pair it with a
drift test asserting that, for each format, every optional-word subset parses to the same bound declarative.

`CobolControlFlow.g4#useStatement` (line 273) · `scripts/spec/audit_grammar_optional_words.py`.
