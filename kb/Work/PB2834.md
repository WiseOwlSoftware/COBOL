# PB2834 — OPEN — line-sequential REWRITE tests '71' before '44'

Found by the w1047b implementer (PB2692+PB2748+PB2751, report "New defects") and Filed by the train 1047 lander, 2026-10-08 20:53 PDT.

## Mechanism
`src/Cobol.Net.Runtime/IO/SequentialConnector.cs#RewriteLine` (line ~1762) encodes the record first and answers
'71' (§14.9.35.4 GR17 d)) when a character has no byte image, before it measures the record against the line it
replaces ('44', GR17 b)). `cite.py --check 14.9.35.4 "line sequential"` → `OK §14.9.35.4 17)`.

## Repro
A LINE SEQUENTIAL file; READ a record of 2 bytes; REWRITE a longer record that holds U+0100. Observed '71'; the
general-rule order gives '44'. Reordering needs one decision first: what b) measures for a record with no byte image
(the encoded length is undefined). The same root as PB2751 (the DOC-A.1-104 order of status tests).
