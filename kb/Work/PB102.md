# PB102 — LANDED — `data/unicode/*.txt` / `*.xml` were subject to line-ending conversion; the content-addressed manifest requires bytes

> ⚙ **flags:** process · found 2026-08-18 by the normalization-subsystem agent (kb/Work [[PB101]] section C) in its
> fresh worktree — `Manifest_InputsAndOutput_MatchTheCommittedFiles` failed before any of its code existed; the main
> checkout (LF) passed · **landed 2026-08-18** in the PB101 batch (DEVLOG 1327).

**Mechanism.** `root-collation.manifest.json` records the SHA-256 of each generator input's BYTES; the drift test
re-hashes `data/unicode/*` to prove the committed table IS the generator's output over the committed sources. With
`core.autocrlf=true`, a checkout rewrites LF → CRLF for text files, so every input hash differs and the test fails
on a clean tree; regenerating THERE would commit CRLF-derived hashes and break every LF checkout.

**Fix.** `.gitattributes`: `data/unicode/*.txt -text` and `data/unicode/*.xml -text` (the `DEVLOG.md -text`
precedent) — every checkout hashes what the generator read. Sibling sweep: `CollationTableTests.cs:49` is the only
byte-pinned tracked-text hash in the test suites.
