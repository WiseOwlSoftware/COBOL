## Finding — `object-property` (rejects-legal-source; rows `FMT-8.4.3.9.2`)

**Mechanism.** Properties reached through an INTERFACE are unimplemented: an interface GET/SET PROPERTY prototype is refused COBOLNET0899 (OoClassTable) and an interface-typed receiver makes OoTryBindPropertyReference return null (table.Find misses), so `prop OF interface-typed-ref` cannot compile

**Repro.** pinned cobol.exe --std 2002 E:/Temp/claude/E--CobolSharp/a700c052-f9e4-4942-84ff-a13c7505d6ec/scratchpad/adj-d2/out/probe/objprop/p13.cob: INTERFACE-ID IPB13 with METHOD-ID. GET PROPERTY BAL (RETURNING PIC 9(5)); class CPA13 `OBJECT. IMPLEMENTS IPB13.` with `01 BAL PIC 9(5) VALUE 100 PROPERTY.`; driver `01 I USAGE OBJECT REFERENCE IPB13. ... SET I TO A. DISPLAY BAL OF I.` -> COBOLNET0899 (interface property prototype) + COBOLNET1639

**Expected from the spec.** Compiles and displays 00100: identifier-1 is an object reference that is not universal (SR2 satisfied), and SR3 requires a get property method 'in the object referenced by identifier-1' — CPA13's instance supplies it.

**Observed / reasoning.** ReferenceResolver.cs:126 `if (cls is null) return null; // interface-typed receivers: property prototypes are a later refinement`; OoClassTable.cs interface arm raises DiagnosticCatalog.OoInterfacePropertyPrototype and `continue`s.

**Code site.** src/Cobol.Net.Compiler/Binding/ReferenceResolver.cs#OoTryBindPropertyReference (:126); src/Cobol.Net.Compiler/Oo/OoClassTable.cs#Build (interface methodPropertySelector arm, ~:213)

## What the fixer owes

Admit the interface property-method prototypes in OoClassTable.Build and resolve an interface-typed receiver's accessor through the interface roster (dispatch through the implementing object at run time). Golden p13.

### Row `FMT-11.7.2` — PARTIAL (editions 2002, 2014, 2023 (METHOD-ID is part of the OO facility introduced by COBOL 2002; absent at 1985))

§11.7.2 prints METHOD-ID. { method-name-1 [AS literal-1] | {GET|SET} PROPERTY property-name-1 } [OVERRIDE] [IS FINAL] . (cite.py --check 11.7.2 "[ <u>OVERRIDE</u> ] [ IS <u>FINAL</u> ]" -> OK). Grammar methodDefinition: METHOD_ID DOT (methodName externalizedNamePhrase? | methodPropertySelector) OVERRIDE? (IS? FINAL)? DOT — exact shape, AS only on the method-name arm, IS optional. Probes (pinned cobol.exe, out/probe/method-id-paragraph): p13_fmt_full `METHOD-ID. M AS "XM" OVERRIDE IS FINAL.` and `METHOD-ID. N FINAL.` compile and run at 2002 and 2023 (B-M / A-N); p11 `GET PROPERTY BAL AS "X"` rejected; p12 `M FINAL OVERRIDE` (wrong order) rejected. Both rejections are correct but report a misleading cascade (COBOLNET0901 'AS'/'OVERRIDE is a reserved word') instead of a syntax diagnostic — diagnostic quality only, not a conformance defect. Existing goldens cover the OVERRIDE IS FINAL arm, the GET/SET PROPERTY arm and the AS arm. || REFUTED: PARTIAL — The general format is shared by method definitions AND method prototypes (§11.7.3 SR2/SR4b/SR8 name prototypes). The {GET|SET} PROPERTY property-name-1 arm is legal in an interface prototype, but the pinned compiler rejects every GET/SET PROPERTY prototype loud with COBOLNET0899 (staged 'not yet implemented'). The class-method arms (method-name AS literal incl. a national literal, GET/SET PROPERTY, OVERRIDE, IS FINAL) do compile. Legal source rejected => not CONFORMS. Needs a kb/Work defect note (none found).

### What the fixer owes
