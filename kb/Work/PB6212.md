## R1-1: two 1985 code reads name a symbol that no longer lives in the file

`tests/version-matrix/code-reads-1985/1985-SR-VI.6.23.3-6.json` and `1985-GR-VI.6.23.4-8.json` (rule ids
`1985-SR-VI.6.23.3-6`, `1985-GR-VI.6.23.4-8`) carry `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/SetBinder.cs#BindSetCondition`
in `code-location` (and `edition-search`/`notes` prose). PB2314 moved the definition to
`SetConditionBinder.cs:26` (`internal BoundStatement BindSetCondition`). `SetBinder.cs:141` still CALLS it
(`Condition.BindSetCondition(b)`).

Root cause worth fixing: `scripts/spec/code_location.py:756-767` `symbol_resolves` tests an unqualified symbol with
`whole_word(symbol).search(declared.code)`, i.e. any occurrence in the code of the file, including a call site. A moved
method whose caller stays behind therefore still "resolves". The check should require the symbol be DECLARED in the file
(`declared.paths`, as the dotted-symbol branch already does), after which the two stale reads fail and are repointed to
`SetConditionBinder.cs#BindSetCondition`. Siblings: sweep every `code-reads-*` for an unqualified symbol that is only
called, not declared, in its file.
