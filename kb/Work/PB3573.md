# PB3573

## Scenario

Review of PB3513 (PR #432), lead R1-1 (low, from `E:\COBOL-coord\scratch\reports\w1157f-PB3513-report.md`).

`src/Cobol.Net.Runtime/Values/Numeric/CobolNum.DeviceDecimal.cs` `ParseDeviceDecimal` (branch `worktree-wf_37d4041f-6f7-6`,
about line 244 at review) counts every integer digit up front, then drops the high-order surplus
(`skip = count - integerCap`) from the front of the run. A non-digit that precedes a dropped digit is rejected, while
GnuCOBOL 3.2.0, whose rules the doc comment says the reader reproduces exactly, skips the non-digit while dropping the
surplus digits. The accepted text differs for a window such as a junk character ahead of an over-wide digit run.

## Fix shape

Probe GnuCOBOL 3.2.0 (cobc under WSL) with a window carrying a non-digit before a surplus high-order digit, make the
reader skip it the same way, and add a golden. Per rule 1 the precedence is ISO, then GnuCOBOL: the ISO spec leaves the
ACCEPT conversion of invalid text implementor-defined, so GnuCOBOL decides. Land after PR #432 (PB3513).
