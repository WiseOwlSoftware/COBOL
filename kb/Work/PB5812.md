# PB5812 - OPEN: do the 1985 USE precedence rules reach across programs (a containing program's USE GLOBAL on the file against the contained program's own USE ON INPUT)?

**Ruling: OPEN.** When the containing program has `USE GLOBAL ... ON` the file and the contained program has its own `USE ... ON INPUT`, the contained program's own procedure runs. Whether the 1985 precedence rules reach across programs is not decided by the text. The row `1985-GR-IX.4.8.4-4` stays `undecided`. Harm: wrong_answer under reading 1 only (not set while the row is open). The checker's confidence: medium. Settled by CLAUDE.md rule 1's order (GnuCOBOL measured, then IBM or Micro Focus) and a 1985 conformance entry. Within one program every probe conforms.

**The case.** The compiler runs the contained program's INPUT declarative (`INNER-INPUT 23`) though the containing program has `USE GLOBAL ... ON GF`.
- Reading 1: `§1985:IX.4.8.4 GR4` ("no other USE statement applies to file-name-1") and GR5b's exception ("except those files referenced by file-name-1 in another USE statement") are unscoped, and `§1985:X.5.5.4 GR1` requires the selected declarative to "satisfy the rules for execution of that declarative", so the INPUT declarative does not qualify and GR1b selects `OUTER-GF-NAMED`: non-conforming (wrong_answer, same at 2023).
- Reading 2: GR4 and GR5b speak of the USE statements of one Procedure Division (`§1985:IX.4.8.3 SR3`, as corrected, and SR6 are so scoped), and `§1985:X.5.5.4 GR1a` (the program's own declarative first) then selects the INPUT one: conforms.
- A hint, not a settlement: read literally, Reading 1 would also let a non-GLOBAL outer USE ON GF, which cannot run in the contained program, suppress the inner INPUT declarative and leave none.
- Pointer only, not checked here: 2023 says the compiler's reading outright ("Within a given procedure division, a USE statement specifying file-name-1 takes precedence", `§2023:14.9.49.4 GR5`).
