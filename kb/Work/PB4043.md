# PB4043 — universal-object-reference-not-supported--invoke-statement: -std=cobol2014: the INVOKE statement is refused ("'INVOKE' is a reserved word, but isn't supported")

Filed 2026-10-29 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-20261028-210601`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

Under `-std=cobol2014`, cobc 3.2 refuses every INVOKE statement: "'INVOKE' is a reserved word, but isn't supported",
followed by "'INVOKE' cannot be used here". The INVOKE statement (§14.9.23.1) is in ISO/IEC 1989:2002 and 2014 and is
not an optional element (the optional object-orientation elements are multiple inheritance and parametric
polymorphism, §A.4.10), so this is a missing feature of the edition `-std=cobol2014` claims. It is a further member of
the object-reference family: kb/Work PB3928 records SET, relation conditions and RAISE on object references; this
record is the statement that uses them. Class: feature missing. Fuzz program fz01963 (night fuzz-20261028-210601); the
same mechanism was recorded from fz00518 the night before and held at filing for a citation mismatch, never filed.

## Minimal test case

Free reference format.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. INV1.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 R USAGE OBJECT REFERENCE.
PROCEDURE DIVISION.
    DISPLAY "BEFORE"
    INVOKE R "M"
    DISPLAY "AFTER"
    STOP RUN.
```

## Environment

`cobc (GnuCOBOL) 3.2.0`, Ubuntu package `gnucobol3 3.2-4build1`, WSL2 Ubuntu (Linux 6.18.54.1-microsoft-standard-WSL2
x86_64). Compiled with `cobc -x -free -std=cobol2014 -o inv1 inv1.cob`; no executable is produced, so nothing is run.
Control: the same INVOKE placed in a paragraph that is never performed is refused too ("'INVOKE' is a reserved word, but
isn't supported", then "'INVOKE' is not a statement"), so the refusal does not depend on the receiver being null.

## Observed result

Compile, exit code 1:

```text
inv1.cob:5: warning: OBJECTS is not implemented [-Wpending]
inv1.cob:8: error: 'INVOKE' is a reserved word, but isn't supported
inv1.cob:8: error: 'INVOKE' cannot be used here
```

## Expected result (per ISO)

The program is legal, so the INVOKE statement is accepted.

- §14.9.23.1 (checked): "The INVOKE statement causes a method to be invoked."
- §14.9.23.3 1) (checked): "Identifier-1 shall be an object reference." R is one.
- §13.18.60.4 (checked): "If none of the optional phrases is specified, this data item is called a universal object
  reference." R is a universal object reference.
- §14.9.23.3 2) (checked): "Literal-1 shall be of class alphanumeric or national and shall not be a zero-length
  literal." "M" is.
- §14.9.23.3 6) (checked): "If identifier-1 references a universal object reference, neither the BY CONTENT nor the BY
  VALUE phrase shall be specified"; the statement has no USING phrase, and the method-name rules of syntax rule 4 apply
  only to a receiver that is not a universal object reference, so every syntax rule is met.
- §13.18.63.4 (checked): "data items of class message-tag, class object, and class pointer are initialized to null", so
  R is null when the INVOKE executes.
- §14.9.23.4 5) (checked): "If identifier-1 is null, the EC-OO-NULL exception condition is set to exist and execution of
  the INVOKE statement is terminated." EC-OO-NULL is a fatal exception (§14.6.13.1.6, checked: "Method invocation was
  attempted with a null object reference", level Fatal).
- §14.6.13.1.3 8) (checked): "If checking for the exception condition is not enabled, the implementor defines whether or
  not execution will continue"; and, in the same clause, "If checking is not enabled for a fatal exception condition and
  the exception condition is detected by the compiler, the implementor is not required to produce executable code."
  Checking is not enabled here.
- §A.4.10 1) (checked): the optional object-orientation elements are "Multiple inheritance" (and parametric
  polymorphism); INVOKE is not optional.

Expected: the INVOKE statement is accepted. The run prints `BEFORE` and then follows the implementor's documented
disposition for an unchecked fatal exception (end the run unit, or continue and print `AFTER`); an implementor that
detects this null receiver at compile time may instead decline to produce executable code. None of these is a refusal
of the INVOKE statement itself, which is what cobc reports, for any receiver.

Edition: 2014. INVOKE is in the 2002 standard (its 14.8.22) and in the 2009 committee draft CD 1.2 that became
ISO/IEC 1989:2014 (its 14.9.22), whose optional-element list names only multiple inheritance in object orientation.

## Our compiler

WiseOwl COBOL (fresh judge, `--std 2014 --source-format free`): compiles with no diagnostic; the run prints `BEFORE`
and then `abnormal run-unit termination: EC-OO-NULL (fatal): INVOKE: the object reference used as the receiver is null
(ISO §14.9.23.4 GR5)`, exit code 1. The fuzz program fz01963 behaves the same at its first INVOKE.

## Fix site

`cobc/reserved.c`: the reserved-word table entry for INVOKE carries token -1 (no grammar token), so
`lookup_reserved_word` reports "'%s' is a reserved word, but isn't supported". `cobc/parser.y` has no INVOKE statement
production (the statement list carries a `TODO: invoke_statement` comment), and the USAGE OBJECT REFERENCE rule
(`conflict_usage`) only raises `CB_PENDING ("OBJECTS")`.

**Title:** -std=cobol2014: the INVOKE statement is refused ("'INVOKE' is a reserved word, but isn't supported")

Environment: GnuCOBOL 3.2.0, WSL2 Ubuntu x86_64; `cobc -x -free -std=cobol2014 -o inv1 inv1.cob`.

Program:


Observed: `warning: OBJECTS is not implemented [-Wpending]` at line 5, then `error: 'INVOKE' is a reserved word, but
isn't supported` and `error: 'INVOKE' cannot be used here` at line 8; exit code 1. The same INVOKE in a paragraph that is

Expected: the INVOKE statement is accepted. It is a required element of COBOL 2002 and 2014 (ISO/IEC 1989:2023
§14.9.23.1): in 2023 the only optional object-orientation elements are multiple inheritance and parametric polymorphism
(§A.4.10), and the committee draft of 2014 lists only multiple inheritance. R is initialized to null (§13.18.63.4), so
the INVOKE raises EC-OO-NULL at run time (§14.9.23.4 5)), a fatal exception (§14.6.13.1.6) whose handling without
checking is the implementor's (§14.6.13.1.3 8)). If INVOKE is not planned for 3.x, a compile-time message naming the
statement as not implemented under -std=cobol2014 would state the gap.
