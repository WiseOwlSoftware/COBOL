# PB3543 — RollbackOnFatal runs when checking is enabled

## Defect

`TransactionControl.RollbackOnFatal` never asks whether checking for the exception condition is enabled. With checking
enabled, a USE procedure or a PERFORM WHEN handler that ends in RESUME AT NEXT STATEMENT therefore runs a ROLLBACK the
standard does not call for, restoring both files and data items.

The rule (re-run through `cite.py --check 14.6.13.1.3`, OK): item 8 opens "If checking for the exception condition is not
enabled, the implementor defines whether or not execution will continue … However, if there is a fatal exception
condition for a file subject to an active APPLY COMMIT clause, then a ROLLBACK statement is executed unconditionally." With
checking enabled, items 4 and 5 apply, and a RESUME continues per item 5 NOTE 2 with no ROLLBACK.

The adjudication read the code on branch `worktree-wf_e05cc4a3-4db-1` (wave 1154's APPLY COMMIT branch, in flight). The
fix follows that branch and belongs to the same cluster as PB3542.
