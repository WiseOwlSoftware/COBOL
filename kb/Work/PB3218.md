**Rule it breaks:** §12.3.7.3 SR11 bars a zero-length literal in literal-1 through literal-6 and literal-9; §8.8.3.3 GR2/GR3 make `"" & ""` a zero-length literal of its class. One rule in one place (DESIGN-architecture-review §5.2; dimensions.md 4): DataBinder.LiteralPhraseOperand (ALPHABET literal-1..3, CLASS literal-5..6) asks CobolLiteral.IsZeroLength(lit.GetText()) on the written token, TryClauseTextLiteral (LOCALE literal-4, ORDER TABLE literal-9) asks text.Length == 0 on the folded value

**Scenario:** Measured with the 2026-10-15 Debug build. SPECIAL-NAMES with `LOCALE LZ IS "" & ""` draws COBOL0898 '... shall specify neither a symbolic-character figurative constant nor a zero-length literal (ISO §12.3.7.3 SR11)'. The same paragraph without the LOCALE clause, holding `ALPHABET AZ IS "" & ""` and `CLASS CZ IS "" & ""`, compiles with exit 0 and no diagnostic; the program runs and `IF X IS CZ` takes the false branch (an empty class). Cause: LiteralPhraseOperand (DataBinder.Switches.cs:1632-1637) tests IsZeroLength on the text `""&""`, which is not zero-length as written, then LiteralCharsOf (1856-1859) folds it to the empty string and returns it as the operand's characters; TryClauseTextLiteral (1088-1103, 1117-1123) folds first and tests the value. The class-and-decode half of TryClauseTextLiteral is likewise an inline copy of OperandLiteralClass (1804-1814) plus LiteralCharsOf, so the two SPECIAL-NAMES literal screens can keep drifting

**Measured how:** R2 batch finding `data-binding-4--duplication--f1#3` (pair data-binding-4--duplication), read in the pinned tree at 8be23006851a; skeptics rule upheld, scenario upheld, site upheld.

**Spec:** §12.3.7.3 "Literal-1, literal-2, literal-3, literal-4, literal-5, literal-6, and literal-9 shall specify neither a symbolic-character figurative constant nor a zero-length literal" (`cite.py --check` passed at collection); §8.8.3.3 "If both literal-1 and literal-2 are specified and both are zero-length literals the value of the concatenation expression is a zero-length literal" (`cite.py --check` passed at collection); §8.8.3.3 "A concatenation expression shall be equivalent to a literal of the same class and value, and may be used anywhere a literal of that class may be used" (`cite.py --check` passed at collection)

**Target:** ONE SPECIAL-NAMES literal decode (fold a concatenation per §8.8.3.3, class it, decode it) feeding ONE SR11 screen asked of the decoded value, used by LiteralPhraseOperand and TryClauseTextLiteral alike (CurrencyTextLiteral keeps only its SR18/SR26 operand rules on top of the same decode); goldens: `ALPHABET A IS "" & ""`, `CLASS C IS "" & ""` and `CLASS C IS "A" THRU "" & ""` each refused under SR11

**Design reference:** §8.3.

## Landed

Re-probed on the Debug build (std 2023): `ALPHABET AZ IS "" & ""` and `CLASS CZ IS "" & ""` compiled clean; `LOCALE LZ IS "" & ""` drew COBOL0898 (the note).

**Fix.** The question is asked once, of the literal AS DECODED: `DataBinder.IsZeroLengthOperand(LiteralContext)` (a plain token structurally via `CobolLiteral.IsZeroLength`, a concatenation through `ConcatFolder.Peek`, so `"" & ""` is the zero-length literal of 8.8.3.3 GR2) and its constant-name arm `IsZeroLengthConstant`. `LiteralPhraseOperand` (ALPHABET literal-1..3, CLASS literal-5..6) and `TryClauseTextLiteral` (LOCALE literal-4, ORDER TABLE literal-9) both ask them; the raw-token test and the `decoded.Length > 0` test are gone. `TryClauseTextLiteral`'s inline class-and-decode copy now reads `OperandLiteralClass` + `LiteralCharsOf`, the pair the ALPHABET / CLASS operands decode through. `SpecialNamesZeroLengthDriftTests` pins that `CobolLiteral.IsZeroLength` is called only inside the two predicates and that both screens ask them. CURRENCY SIGN already tested the decoded string (COBOL0890), so it needed no change.

Goldens (12.3.7-SPECIAL-NAMES, refused at 2014 and 2023; below 2014 the zero-length literal itself is the matrix's COBOL0900): `pb3218-alphabet-zero-length-concatenation`, `pb3218-class-zero-length-concatenation`, `pb3218-class-through-zero-length-concatenation`.
