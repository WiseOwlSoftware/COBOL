# PB3581 — LANDED — CI's Windows script self-tests ran as the last step of the merge queue's longest job

## Measured (merge group run 40004159292, 2026-10-23)

| job | start | end |
|---|---|---|
| Windows build + tests | 18:33:01 | 18:49:35 |
| Guard (WiseOwl COBOL NIST, parallel), the next longest | 18:33:00 | 18:45:29 |

Inside `windows-build-test`, the step `Script self-tests on Windows (self_tests.py)` ran 18:41:53 to 18:49:17: 7.4 of
the job's 16.5 minutes (`=== SELF-TESTS: GREEN — 95 ran in 440s (budget 4 places machine-wide …)`). The default phase
never builds (`self_tests.py` BUILD: the build-reading self-tests run under `--built` in `greenfield-unit`), and the
local gate runs the same runner before its build (run_gate_legs.py AUDITS), so the step waited for a build it never read.

## The fix

A new job `windows-self-tests` (windows-latest; checkout, the pinned tzdata and PyYAML, `python scripts/self_tests.py`,
and the line-ending check over a Windows checkout, which reads no build either), wired into `ci-gate`'s `needs`.
`SelfTestDiscoveryDriftTests.EveryGateEntryPoint_RunsTheRunner_AndNamesNoSelfTestByHand` holds the runner to the new job
and refuses it back in `windows-build-test`, or a `dotnet build` in the new job. Expected effect: the merge queue's wall
drops from about 16.5 minutes to the guard's 12.5, the next limit.

|---|---|---|---|

The Windows job left the critical path: the NIST guard is the merge queue's longest job now, and every landing's queue
wall fell by the time the Windows job ran past it: 2.4 minutes on pr-442 (16.0 against the guard's 13.6); the merge
group's run wall went from 16.4 to 14.1 minutes. (The 3 to 4 minutes first written here was the pre-landing estimate.)
