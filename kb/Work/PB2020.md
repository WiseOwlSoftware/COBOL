# PB2020 — OPEN: two small accuracy gaps found by the battery #88 adjudication (DEVLOG 1883)

1. **The differential reads the autotest's expected status and ignores its XFAIL marker.** Case `syn_copy:125` is marked
   `AT_XFAIL_IF([true])` in GnuCOBOL's suite and the packaged `cobc` 3.2.0 under WSL rejects it ("No such file or directory"),
   yet the differential classified GnuCOBOL as ACCEPTING it, so a CORRECT rejection of ours (PB1355: the working directory and
   the `--copy` directories are searched, not the including file's directory) showed up as a regression flip. The classifier
   (`scripts/gnucobol_differential.py`, the extraction in `scripts/gnucobol_extract.py`) should take the `xfail` flag into
   account and bucket such a case as `GNUCOBOL_XFAIL`, so a flip cannot be created by a test the suite itself expects to fail.
   Every classification rule needs a witness case (a drift test over the extraction).
2. **COBOLNET1619 (a `>>DISPLAY` operand that is not a permitted form) cites §7.3.11 / §13.10.3**, the DEFINE rule. That is
   defensible for the operand-is-a-compilation-variable half, but §7.3.12 is the clause of the directive itself (checked by the
   adjudicator with `cite.py`); the message should cite the clause a user reads first. Check which sub-rule each of the
   message's branches implements before editing the text, and sweep the other COBOLNET16xx directive diagnostics for the same.
