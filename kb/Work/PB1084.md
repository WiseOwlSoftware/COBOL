# PB1084 — OPEN — `BinderDriver.UserFunctionsOf` applies a function definition's OWN self-named function-specifier (`FUNCTION FACT AS "OTHERF"` inside FUNCTION-ID. FACT) as a rem

## Rule text (every citation re-run by the registrar)
- `python scripts/spec/cite.py --check 12.3.8.3 "references to function-prototype-name-1 are to that function definition and this function-specifier is ignored"` → `OK  §12.3.8.3 11)  (Syntax rules)`

### Adjudicator finding (repository-paragraph, harm rejects-legal-source)
- **Mechanism:** UserFunctionsOf applies a function definition's OWN self-named function-specifier (with AS literal-5) as a remap to another function, instead of ignoring it; the program twin (ProgramPrototypesOf) overwrites the self entry and is correct.
- **Repro:** out/probe/repo/sr11.cob (--std 2023): FUNCTION-ID. OTHERF with two USING formals; FUNCTION-ID. FACT (one formal) whose REPOSITORY writes 'FUNCTION FACT AS "OTHERF".' and whose body computes L-R = L-N * FUNCTION FACT(L-N - 1); program SR11P with REPOSITORY FUNCTION FACT computes FUNCTION FACT(5).
- **Expected (spec):** §12.3.8.3 SR11: 'If the specified function-prototype-name-1 is the name of the function definition in which this REPOSITORY paragraph is specified, references to function-prototype-name-1 are to that function definition and this function-specifier is ignored.' The recursive reference is FACT itself: the program prints FACT5=0120.
- **Observed:** COBOLNET1506 'FUNCTION FACT takes 2 argument(s); 1 given' at the self-call - the self reference was bound against OTHERF's signature. UserFunctionsOf walks unit.Data.FunctionSpecifiers and, for name != externalized, sets own[name] = the group function whose externalized name is literal-5, with no test that name is the unit's own name; BindIntrinsicCore then binds against host.UserFunctions[name]. Without the AS phrase (sr11b.cob) the program prints FACT5=0120 only because the unmapped word falls back to the group table. The PROGRAM arm on the identical shape (sr15.cob: PROGRAM SR15P AS "SR15OTH" inside SR15P) recurses correctly because ProgramPrototypesOf overwrites map[unit.Name] with SelfPrototype(unit) - the two-arm shape.
- **Code site:** src/Cobol.Net.Compiler/Binding/BinderDriver.cs#UserFunctionsOf
- **Clause (adjudicator):** §12.3.8.3 SR11

## What the fixer owes
Skip (or overwrite with the self prototype) the entry whose name is the unit's own name in `UserFunctionsOf`, exactly as `ProgramPrototypesOf` does with `SelfPrototype(unit)` — better, extract the one self-entry rule both arms call (the two-arm dispatch). The corrected SR11 citation lands with PB1085.
