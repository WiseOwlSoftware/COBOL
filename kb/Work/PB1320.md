# PB1320 — OPEN — a grammar rule with no reader is an acceptor with no semantics

## The harm shape
A parser rule is written into a `.g4` alternative. Source that matches it parses. If no binder, visitor or
validator ever reads the rule's context, the construct is ACCEPTED and IGNORED, which is the worst form of
under-rejection, because the user sees a clean compile. PB446 measured one: `searchAllKeyPhrase` let
`SEARCH ALL T KEY IS K WHEN …` compile and silently dropped the KEY phrase. PB829 found the `genericClause`
catch-all in six closed formats, which is the same shape at a larger scale.

## What the fixer owes
A **drift test** in `tests/Cobol.Net.Tests.Unit`:
- Enumerate every parser rule in `src/Cobol.Net.Frontend/Grammar/**/*.g4`. The generated parser's `ruleNames`
  is the mechanical source.
- For each rule, require at least one reader in non-generated `src/**/*.cs`: a `Visit<Rule>`/`Enter<Rule>`
  override, or a `ctx.<rule>()` accessor call.
- Anything else goes on an explicit allowlist, and every entry says why:
  - rules consumed only through a parent's `GetText()`;
  - rules that exist only to shape prediction, such as a left-factored helper whose children are read;
  - error productions reported by `ClosedFormatPass`.
- The test has to FAIL once before it is trusted ([[feedback_green_gates_arent_evidence]]). Restore a dead rule
  in a scratch branch and watch it go red.

**Sweep on landing:** every rule the first run flags is either given its reader (a defect, and its own note if it
changes behaviour) or deleted as dead grammar.
