## The rule

§5.2.3 / §8.3.2.4.3 (`cite.py --check 8.3.2.4.3 "uppercase words that are not underlined are called optional
words"` → OK): an un-underlined uppercase word may be omitted "with no effect on the semantics of the format". A
grammar that demands one rejects conforming source; a grammar that relaxes an UNDERLINED one accepts illegal
source silently. The distinction lives in typography, so each candidate is decided by RENDERING its page and
measuring the underline (`render-spec-page.py`, `figure_extract.py`), never by reading the OCR — the transcription's
figure notes are an independent witness, and PB331/PB332 found them right and the grammar wrong every time.

## The three groups, as the implementer sorted them

1. **Cross-construct noise the audit's docstring predicts** — the seven `FILE 12.4.5.8.2 … FILE required in …`
   rows: the FILE STATUS clause's un-underlined `[FILE]` colliding with `DELETE FILE`, `FILE SECTION`, and the
   READ/WRITE/REWRITE `FILE` token; `fileStatusClause` itself already writes `FILE?`. Close these by making the
   audit's closure or its reporting distinguish the clause's own rule from a same-token stranger (a structural
   fix to the tool, so the seven do not reappear every run).
2. **Plausible real findings**, densest in `SPECIAL-NAMES 12.3.7.2` (ten rows: `IS`, `ARE`, `FOR`, `CHARACTERS`
   demanded by `alphabetClause`, `channelClause`, `crtStatusClause`, `cursorClause`, `decimalPointClause`,
   `switchOnClause`, `symbolicCharacterEntry`, `symbolicCharactersClause`, `alphabetForPhrase`; `IS` is not
   underlined anywhere in §12.3.7.2's figures), then one-site candidates in OBJECT-COMPUTER, LOCK MODE, ERASE,
   DYNAMIC LENGTH, CODE-SET, PERFORM (WITH), SEARCH ALL (IS), SET (OF), INVOKE (BY), INITIALIZE (TO ×3), ALTERNATE
   RECORD KEY (WHEN), APPLY (ON), VALIDATE-STATUS (WHEN), VALUE OF (IS), DELETE (ON).
3. **A tool artifact** — `CONTINUE 14.9.9.2 … CONTINUE required in continueStatement`: the statement's own verb
   reported as an optional word; fix the audit (a statement's first word is its keyword).

`[ WHEN SET TO FALSE IS literal-4 ]` carries exactly ONE rule, under FALSE (x 228.02–255.10, 92% cover). All

**A second defect the same measurement found — the two trailing brackets were in the wrong ORDER.** Printed
format 3 ends `… [ IN alphabet-name-1 ]` and puts `[ WHEN SET TO FALSE IS literal-4 ]` on the line AFTER it;
format 5 likewise brackets IN before its `{IS INVALID | ARE VALID}` tail. The rule had them reversed, so the
PRINTED spelling `88 CN VALUE 1 IN AL1 WHEN SET TO FALSE 0` was a COBOL0001 while an order no format prints was
accepted. §5.2.6.2 makes bracket order part of the format. Swapped; no corpus program wrote the unprinted order.

**One structural correction the relaxation forced (rule 5) — `initializeOperandList`.** With THEN and TO
optional, `INITIALIZE X DEFAULT` is the shortest legal spelling of `INITIALIZE X THEN TO DEFAULT`, and DEFAULT
rides `cobolWord` (`cobol-words.json`, `nameSlot: true`), so ANTLR's greedy `{identifier-1}…` loop took it as a
second operand and the statement died on COBOLNET1639 "'DEFAULT' is not defined" — one rejection traded for
another. INITIALIZE now has its own operand list carrying the guard `valueClause` already carries for PROPERTY:
`{!(reservedHere("DEFAULT") && …)}?`. §8.9 reserves DEFAULT from 2002, so at those editions it can never be a
user-defined word (§8.3.2.1); at COBOL-85 `reservedHere` is false AND the DEFAULT phrase does not exist, so the
loop still absorbs it — the correct '85 reading, pinned by its own probe. The guard is deliberately NARROW: the
shared `dataReferenceList` (MOVE, SORT, MERGE, OCCURS INDEXED) keeps its present over-acceptance, which is a
separate question from this statement's ambiguity. Consumers updated: `InitializeBinder`,
`EcBinder.ExceptionPerform`, and the legacy `DataStatementBinder`.

**One residue, reported rather than papered over.** `IN` in `[ IN alphabet-name-1 ]` is un-underlined in formats
3 and 5, but it CANNOT be relaxed: §13.10.3 SR2 lets a constant-name stand "anywhere that a format specifies a
literal", so with IN omitted alphabet-name-1 is indistinguishable from one more literal-2 and ANTLR's greedy
operand loop always wins. An `IN?` would be a DEAD branch. See the family-2 report.

## NEW DEFECT FOUND WHILE LANDING FAMILY 1 — the audit cannot see a word nested in an optional group

`scan_alternative` marks a token optional when it or any enclosing group carries `?`/`*`, so a word that is
REQUIRED inside an optional group is never a candidate. Every sibling in the sweep above was invisible for
exactly that reason: `classDefinitionClause`'s `(FOR (ALPHANUMERIC | NATIONAL))?` rejects
`CLASS X IS "0" NATIONAL`, which §12.3.7.2 permits, and the audit reported nothing. The honest test is per
OPTIONAL-WORD-WITHIN-THE-GROUP rather than per token: for each group, does the rule accept the group's contents
with each un-underlined word deleted? Fixing it will enlarge the candidate list across the whole grammar, which
is why it is filed rather than folded into this change.

## Fix

A read-only confirmation pass, one candidate per page render (a 4-wide read-only chunk is the budget's shape for
it), producing per candidate: the page, the measured underline, CONFIRMED or NOT, and for each confirmed one the
grammar rule and the `?` it needs; then ONE grammar implementer per construct family (SPECIAL-NAMES is one
family) landing the confirmed relaxations with the power-set drift gate (`OptionalWordSubsetDriftTests`, one row
per format) and a positive golden per relaxed word — the word omitted — and the audit's own list re-run to zero.
Groups 1 and 3 are audit fixes, taken first so the list is honest.
