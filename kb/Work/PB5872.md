## The shape decided (the Mythos lane; the fix corrects it where the code proves it wrong, CLAUDE.md rule 5)
1. THE PREFLIGHT is a stage of the ONE gate, in its code lane, after the audits and before the gate waits for a
   slot and starts the whole population: the cheap cases whose red means a derived or pinned file is stale. When
   one is red the gate ends RED at once, its verdict line says PREFLIGHT and names the case, and the whole
   population does not run. This CHANGES the owner's rule of 2026-09-28 ("order, don't skip") for that one case:
   on a preflight red the rest is not run, by his decision above. On a green preflight nothing is skipped.
2. WHAT IS IN IT is DATA with its measurement, in the one file that already declares the test targets
   (`scripts/build_targets.json`), never a list in code: start from the Characterization target whole (37 cases)
   and the classes that pin a derived or pinned file (the runtime ABI pin, the public surface, the dialect and
   documented-facts pins); then MEASURE: read the gate records this host keeps (every worktree's
   `TestResults/build-local/*/verdict.json` and its trx files) for the runs that ended RED on one class, rank
   the classes by how often they were a run's only red and by their own run time, and admit a class only if it
   runs in seconds. Say in the note's landing file what was admitted, what was left out and the numbers.
3. BOUNDED: the preflight's own time on a green run is measured and stated, and a drift test holds it to a
   budget counted in CASES or declared weights, never in seconds on a wall clock.
4. NO CASE RUNS TWICE: a case the preflight ran green is not run again by the whole population of the same gate
   (the per-target pass record and the differential already carry passes: use them, add no second mechanism).
5. THE RECORD: the verdict vocabulary (`gate_verdict.py`), the run's verdict.json and the growth record say
   PREFLIGHT, so that a later measurement can count what it saved.
6. The audits stay as they are (they are already fail-fast). CI's merge group is unchanged: it runs every
   target; say in the design doc that the preflight is a local stage.
7. DOCS in the same change: `docs/rearchitecture/DESIGN-test-build-ci.md` (the gate's order), CLAUDE.md's Testing
   section (one sentence), `.claude/skills/workstream/templates/MANDATORY-PRACTICES.md` and the gate skill.

## What it is not
Not a second gate, not a mode, not a flag (`gate.py --audit-shape` refuses a live line that names a gate mode):
one gate, one shape, with one more stage in its order.
