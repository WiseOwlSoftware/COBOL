## Landed

Branch `worktree-wf_94698d58-de0-2` (wave 20261503 group B). **Re-probe** (`git merge-file --union` on three baselines):
ours removed `A.Y` while theirs added `A.N` beside it, and the union kept `A.Y`; both sides added `A.D` at different
places, and the union kept `A.D` twice (the PB3694 shape). Both reproduced.

**The fix, as section 16.9 states it.** `merge_drivers.merge_symbol_set` computes (base ∪ (ours − base) ∪ (theirs − base))
− (base − ours) − (base − theirs). The `#` header lines come first, then the symbol lines in ordinal order, LF, and the
function never declines. The `cobol-keyed-publicapi` row in `DRIVERS` covers `src/**/PublicAPI.*.txt`, and
`.gitattributes` names it in place of `merge=union`. Three corrections to the design came up while implementing and
landing, and section 16.9 records them:
- **The baselines stay as main has them (corrected at the landing).** The branch first sorted both baselines once and
  repinned the runtime ABI pin (`runtime-hash` reads `PublicAPI.Shipped.txt` line by line). PR #608 then stopped at
  the landing on `PublicAPI.Unshipped.txt` (22:43Z, exit 4): the landing merges main in through MAIN's registry, which
  has no `cobol-keyed-publicapi` driver, so git's line merge met the sorted file against PB3677's additions. Its finisher
  put both baselines and the pin back to main's bytes, so main's changes to them merge without any driver. A new driver
  lands alone; the files' order converges at their first two-sided merge, which the driver sorts.
- **The registry now matches patterns by git's rules.** `pathlib.PurePath.match` lets `**` span exactly one directory,
  where git lets it span any number. The new `merge_drivers.pattern_matches` follows gitattributes(5), and
  `covered_by_driver` and `--check` both read it.
- **Merges read their attributes from the registry.** A branch cut before this landing still has `merge=union` in its
  own `.gitattributes`, which git reads by default. Merging a main whose baseline the driver sorted, it got the union: a
  simulated in-flight branch that added two symbols came out with 31 duplicated lines. `merge_drivers.attributes_tree`
  writes a one-file tree holding the merged-into side's `.gitattributes` followed by a `merge=<driver>` line per
  registry pattern (a later line wins), and `merge`, `merge_conflicts` and `is_drivers_merge` pass it as
  `-c attr.tree=…`, the same way `config_args` already supplied the driver commands.

**Arms.** `--self-test` gained the four arms section 16.9 names, a git-path arm (a baseline both branches changed merges
as a set through a scratch repository), an old-attributes arm (a branch whose `.gitattributes` says `merge=union`
merges through the driver; with `attributes_tree` stubbed out the arm fails with `D.D` twice) and a `patterns:` arm.
`MergeDriverDriftTests.TheSelfTests_DeclareEveryArm` declares all seven.

**Oracle.** The three most recent merges on main in which BOTH parents changed a baseline were 009f47b01, cdd86463e and
677c620a0. Each was re-run through `git merge-tree` with `config_args()` and the new attributes, and each driver result
equals main's baseline as a set (268, 265 and 260 lines), sorted.
