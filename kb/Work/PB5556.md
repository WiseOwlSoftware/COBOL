# PB5556 - PB5413's FileModel.CanOpenExtend cites GR5d for the USE ... ON EXTEND rule (it is GR5e), restates the EXTEND conditions StatementValidation.CheckOpenModeForFile tests with no drift test, and its multiple-file-reel arm is unpinned

UNVERIFIED LEAD: re-probe before fixing.

**R1-1 (citation).** The `CanOpenExtend` doc comment (`FileModel.cs:654`) cites `§1985:VII.4.6.4 GR5d` for "a USE ... ON EXTEND procedure
runs for a file open in that mode". The rule is GR5e: `python scripts/spec/cite.py --check "§1985:VII.4.6.4 GR5e" "If EXTEND is
specified, the associated procedure is executed"` prints `OK`, and the same quotation under GR5d fails with "the right citation:
§1985:VII.4.6.4 GR5e". Correct the comment.

**R1-2 (test gap).** No test covers the multiple-file-reel arm of `CanOpenExtend` (`MultipleFileReels.Count == 0`) or its
report-file exemption (`IsReportFile`); only the access-mode and LINAGE arms have unit cases.

**R1-3 (duplicate rule).** `CanOpenExtend` writes the EXTEND-admissibility conditions (sequential access, no LINAGE, not on a
multiple file reel unless a report file) a second time; `StatementValidation.CheckOpenModeForFile` tests the same three conditions
branch by branch, one diagnostic per cause (`OpenExtendAccessLinage`, `OpenExtendMultipleFileReel`). Nothing ties them: a change to
one leaves the other admitting or refusing a file the first does not. Per rule 5 make the model's predicate the one source (the
validation asks it for the cause, or a drift test walks the file-attribute combinations and asserts the two agree).

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Model/FileModel.cs` (`FileModel.CanOpenExtend`),
`src/WiseOwl.Cobol.Compiler/Binding/Validation/StatementValidation.cs` (`StatementValidation.CheckOpenModeForFile`).
