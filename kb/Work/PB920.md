# PB920 — LANDED — two literals of different classes that denote one value, and a screen that cannot see it

Source: the `PB560` report, "New defects" item 3. Re-measured here, end to end.

## The measurement

`<scratch>/reg7/probe/l_sr27_cross.cob`, `--std 2023`, `--run`, rc=0, **no diagnostic**:

```cobol
       01 X PIC ZZ9.99.
          88 X-TEN VALUE " 10.00" WHEN SET TO FALSE IS 10.
       PROCEDURE DIVISION.
           SET X-TEN TO TRUE
           SET X-TEN TO FALSE
           IF X-TEN
              DISPLAY "X-STILL-TRUE"
           ELSE
              DISPLAY "X-FALSE-OK"
           END-IF
           DISPLAY "XF=[" X "]"
```

```
X-STILL-TRUE
XF=[ 10.00]
```

`SET … TO FALSE` executed, stored the FALSE value, and the condition is still true — because the FALSE
value and the TRUE value are the same six characters. The mirrored spelling (numeric literal-2,
alphanumeric literal-4) does the same.

## The rule

```
$ python scripts/spec/cite.py --check 13.18.63.3 "The value of literal-4 shall not be equal to the value of any occurrence of literal-2"
OK  §13.18.63.3 27)  (Syntax rules)
    27) The value of literal-4 shall not be equal to the value of any occurrence of literal-2. When the
        THROUGH phrase is specified: …
```

SR27 says **value**, not spelling and not class. What the value IS, for this subject, is SR6's business:

```
$ python scripts/spec/cite.py --check 13.18.63.3 "may be numeric"
OK  §13.18.63.3 6)  (Syntax rules)
    6) If the item is of category numeric-edited, then, subject to Syntax rules 2 and 3, literals in
       formats 1, 2, and 4 of the VALUE clause may be numeric when they shall be converted to their
       numeric-edited forms according to the rules of the PICTURE clause …
```

So on a numeric-edited subject the numeric literal `10` IS the string `" 10.00"`, and SR27 forbids exactly
this entry. That the violation is OBSERVABLE is §14.9.39.4 (SET condition-name) over §8.8.4.5.3 (the
condition-name condition), which is what the DISPLAY above shows.

## The code site

`src/Cobol.Net.Compiler/Binding/DataBinder.cs#CheckFalseValueDistinct` — it branches on
`CobolLiteral.IsStringLiteral(lo)` and `continue`s on the mixed pair, i.e. it compares literals only when
both are the same KIND. The rule compares VALUES.

## Landed — 2026-09-21, wave 42 group A

**Reproduced first.** The note's own repro, rebuilt on this worktree's `dotnet build CobolSharp.sln -c Debug`
build of `cobol.exe`, compiled clean and printed `X-STILL-TRUE` / `XF=[ 10.00]` exactly as filed. It now reads:

    error COBOLNET2048: condition-name 'X-TEN' (WHEN SET TO FALSE): the FALSE-phrase literal 10 is equal to
    the VALUE literal " 10.00", so it is a value for which the condition-name is TRUE — literal-4 shall name
    a FALSE value (ISO §13.18.63.3 SR27)

and the MIRRORED spelling (`VALUE 10 WHEN SET TO FALSE IS " 10.00"`) reads the same. That is the answer to
"which arm did you fix?": **both**, because the fix does not branch on literal-2's class at all.

⚠ **One correction to this note's own quotation.** Its second `cite.py` block renders SR6's tail as
*"according to the rules of the PICTURE clause"*; the standard's words are **"according to the rules for the
MOVE statement"** (`python scripts/spec/cite.py --check 13.18.63.3 "according to the rules for the MOVE
statement"` → `OK §13.18.63.3 6)`). The code, the goldens and the verdict carry the standard's wording.

**The fix is ONE reader of "the value of" a VALUE-clause operand**, `DataBinder.ConditionValueOf`, with
`DataBinder.CompareConditionValues` ordering a pair and answering *unknown* rather than inventing a
conversion. On a numeric-edited subject the value is the SR6 edited image, composed by the ONE composer
`ValueInitializer.EditedImageOfNumericValue` — made PHASE-NEUTRAL (it takes `(dialectLevel,
decimalPointIsComma)`, not an `EmitContext`, so the binder can ask SR6's question at bind time without a
second copy of the rule). `ConditionValueRecipeDriftTests` was updated deliberately, as this note demanded:
`TheNumericEditedValueImage_HasExactlyThreeReaders` names `DataBinder.cs` as the third reader and
`TheNumericEditedValueImage_IsPhaseNeutral` pins the signature that keeps it callable from binding.

**Goldens.** `tests/conformance/negative/pb920-false-value-crosses-edited-image` and its `-mirrored` twin
(`reject-at: 2002 2014 2023`, `.err` COBOLNET2048 — the band is 2002+ because the FALSE phrase and
`SET … TO FALSE` are COBOL-2002 additions, so at 85 two COBOLNET0900 gates fire alongside the screen and the
case would pass for the wrong reason), plus the POSITIVE this note asked for,
`tests/conformance/2023/pb920_false_value_cross_class_distinct` — numeric-edited both ways round with
DISTINCT images, a numeric subject and an alphanumeric subject — so the screen was not made unconditionally
loud. Row `SR-13.18.63.3-27` re-verdicted CONFORMS on that measurement (batch
`batch-02-pb920-pb890-pb559-pb503.json`).
