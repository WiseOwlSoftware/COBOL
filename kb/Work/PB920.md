# PB920 — OPEN — two literals of different classes that denote one value, and a screen that cannot see it

Source: the `PB560` report, "New defects" item 3. Re-measured here, end to end.

## The measurement

`<scratch>/reg7/probe/l_sr27_cross.cob`, `--std 2023`, `--run`, rc=0, **no diagnostic**:

```cobol
       01 X PIC ZZ9.99.
          88 X-TEN VALUE " 10.00" WHEN SET TO FALSE IS 10.
       PROCEDURE DIVISION.
           SET X-TEN TO TRUE
           SET X-TEN TO FALSE
           IF X-TEN
              DISPLAY "X-STILL-TRUE"
           ELSE
              DISPLAY "X-FALSE-OK"
           END-IF
           DISPLAY "XF=[" X "]"
```

```
X-STILL-TRUE
XF=[ 10.00]
```

`SET … TO FALSE` executed, stored the FALSE value, and the condition is still true — because the FALSE
value and the TRUE value are the same six characters. The mirrored spelling (numeric literal-2,
alphanumeric literal-4) does the same.

## The rule

```
$ python scripts/spec/cite.py --check 13.18.63.3 "The value of literal-4 shall not be equal to the value of any occurrence of literal-2"
OK  §13.18.63.3 27)  (Syntax rules)
    27) The value of literal-4 shall not be equal to the value of any occurrence of literal-2. When the
        THROUGH phrase is specified: …
```

SR27 says **value**, not spelling and not class. What the value IS, for this subject, is SR6's business:

```
$ python scripts/spec/cite.py --check 13.18.63.3 "may be numeric"
OK  §13.18.63.3 6)  (Syntax rules)
    6) If the item is of category numeric-edited, then, subject to Syntax rules 2 and 3, literals in
       formats 1, 2, and 4 of the VALUE clause may be numeric when they shall be converted to their
       numeric-edited forms according to the rules of the PICTURE clause …
```

So on a numeric-edited subject the numeric literal `10` IS the string `" 10.00"`, and SR27 forbids exactly
this entry. That the violation is OBSERVABLE is §14.9.39.4 (SET condition-name) over §8.8.4.5.3 (the
condition-name condition), which is what the DISPLAY above shows.

## The code site

`src/Cobol.Net.Compiler/Binding/DataBinder.cs#CheckFalseValueDistinct` — it branches on
`CobolLiteral.IsStringLiteral(lo)` and `continue`s on the mixed pair, i.e. it compares literals only when
both are the same KIND. The rule compares VALUES.
