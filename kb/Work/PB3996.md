# PB3996 — Format 1 CALL accepts OMITTED

**Owner, 2026-10-28:** "Letting illegal source code thru is a fatal defect. Bug and must be fixed." Approved for the fix
lane.

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CallBinder.cs#BindCall`,
`src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CallBinder.cs#Format2OnlySpellingOf`,
`src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CallBinder.cs#Format1Narrowing`,
`src/WiseOwl.Cobol.Editions/Diagnostics/DiagnosticCatalog.cs#CallContentOperandFormat`,
`tests/WiseOwl.Cobol.Tests.Unit/CallArgumentFormatDriftTests.cs`

In `CallBinder.BindCall`, the `BY REFERENCE OMITTED` arm (~:238) and the bare `OMITTED` arm (~:549) bind with no
`formatTwo` / `Format1VendorSpelling` check, while every other Format-2-only argument is narrowed on `formatTwo`.

**The rule.** §14.9.4.2 Format 1 (Program) prints the USING phrase as `[ BY REFERENCE ] { identifier-2 } …` or
`BY CONTENT { identifier-2 } …`; OMITTED appears only in Format 2 (program-prototype), under `[ BY REFERENCE ]`. A CALL
with `literal-1` or `identifier-1` and no `AS` phrase is Format 1. `cite.py --check 14.9.4.3 "Identifier-2 shall
reference an address-identifier"` -> OK §14.9.4.3 3).

**Observed** (the judge, main 7f0105fec, `--std 2014` and `2023`): compiles with no diagnostic and prints
`EXC EXC EXC END`; cobc 3.2 refuses the BY CONTENT spelling.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. OM3.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 W PIC X(4) VALUE "ABCD".
PROCEDURE DIVISION.
    CALL "OTHER" USING W OMITTED
        ON EXCEPTION DISPLAY "EXC"
    END-CALL
    CALL "OTHER" USING BY REFERENCE OMITTED
        ON EXCEPTION DISPLAY "EXC"
    END-CALL
    CALL "OTHER" USING BY CONTENT W OMITTED
        ON EXCEPTION DISPLAY "EXC"
    END-CALL
    DISPLAY "END"
    STOP RUN.
```

**Expected:** a compile-time error on each of the three CALL statements, the same diagnostic family that already refuses
the other Format-2-only spellings in Format 1 (PB130's narrowing, PB162's `--permissive` lane for the vendor spellings).
OMITTED is not a vendor Format-1 spelling, so `--permissive` does not admit it unless a design decision says otherwise.

**Fix:** narrow both OMITTED arms on `formatTwo` with the other Format-2-only arguments, in ONE place (the root is that the
narrowing is written per arm, so a new arm is unnarrowed by default: make the Format-1 argument set a single check every
arm passes through, and pin it with a drift test over the grammar's callArgument alternatives). Sweep the siblings that
share the argument grammar: INVOKE, the inline method invocation, and any other statement whose USING accepts OMITTED
only in a prototype format. Goldens: the three negatives above, and a Format 2 CALL with OMITTED that still compiles.

Fuzz programs: fz05249 (the rest of the signature is the cobc `-x` USING harness artifact, fz00312/fz01017/fz03134/
fz03838, and the cobc self-CALL segfault fz00314, PB3873).

## Landed — wave 20261743 (fix lane C)

Re-probed on the wave build: the note's program printed `EXC EXC EXC END`. Fixed at the root the note named: the
narrowing is no longer written per arm. `CallBinder.Format2OnlySpellingOf` names every `callArgument` alternative
(BY VALUE, OMITTED in both spellings, a BY CONTENT expression / literal / constant-name, the bare literal / boolean /
arithmetic / grouped argument) and `BindCall` asks it once per argument before any arm; `Format1Narrowing` frames the
refusal (strict: COBOL0899 error; `--permissive`: the PB162 warning for the five vendor spellings; OMITTED has no
vendor lane, per this note, so it is refused under both). The five per-arm copies and `BareNeedsFormat2` /
`Format1VendorSpelling` are deleted. `CallArgumentFormatDriftTests` fails when a `callArgument`, `callByReference` or
`callByContent` alternative is neither read by the classifier nor listed as printed by Format 1. INVOKE, the inline
method invocation and the function-identifier print OMITTED in their one format (§14.9.23.2, §8.4.3.2.2), so they need
no narrowing. No new diagnostic code (COBOL0899, its description widened). Seven existing goldens and fixtures
(pb757_invoke_omitted, pb971_program_arg_omitted, pb971-arg-omitted-below-2002, pb2087_by_reference_area_formals,
pb2671_omitted_formal_category_default, and the _unassigned pb2096 and pb615) had spelled OMITTED in a Format 1 CALL; each is
now Format 2 (`CALL "P" AS P USING … OMITTED` with a REPOSITORY program-specifier), outputs unchanged.
