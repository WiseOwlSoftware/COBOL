# PB233

**Rows:** `GR-14.9.4.4-L2.1`, `GR-14.9.4.4-L2.2`, `GR-14.9.4.4-L2.3`

a CALL written with only NOT ON EXCEPTION silently swallows a failed activation, and the same unfiltered catch routes EC-FUNCTION-NOT-FOUND into the ON EXCEPTION phrase that §14.9.4.4 GR3h excludes.

Rows: GR-14.9.4.4-L2.1 (§14.9.4.4 3h item 1), -L2.2 (3h item 2), -L2.3 (3h item 3 plus the whole of 3i). ONE emitted catch arm, three rules.

MECHANISM, re-verified live at HEAD. EmitCall computes `hasPhrase = c.OnException is not null || c.NotOnException is not null` (:75), emits `try { <invocation> }`, then the name-filtered `catch (CobolCallException __ce) when (<EnabledProgramNames test>)` (:87 → EmitProgramEcCatch :223-233), and only THEN, when hasPhrase, the UNFILTERED `catch (CobolCallException) { __callErr<id> = true; }` (:88-89). The catch ORDER is right (a filtered arm must precede an unfiltered one or it is dead) and the phrase dispatch that follows is right (`if (__callErr) { on } else { notAlso }` with both phrases; `if (!__callErr) { not }` with only NOT ON; falling through to the end of the statement). Two things about the unfiltered arm are not.

DEFECT 1 — A NOT-ON-ONLY CALL SWALLOWS THE FAILURE (L2.3 half (a), the `silent` flag). Because hasPhrase is true when only NOT ON EXCEPTION is written, the catch is emitted; `c.OnException` is null so no `if (__callErr) { on }` block is written; the NOT body is correctly skipped — and execution then falls to the end of the CALL with no diagnostic, no status and no termination. The identical CALL WITHOUT the NOT ON phrase takes the `!hasPhrase && ecProg.Count == 0` path (:76), emits the bare invocation, and the CobolCallException reaches ProgramTable.RunMain's `catch (CobolCallException cx) { AbnormalTermination(cx.Message) }` — this implementation's documented §14.6.13.1.3 #8 disposition. GR3h has no ON EXCEPTION phrase in that source, so item 2 or item 3 governs and neither permits the failure to be discarded: a phrase that is not a party to the rule changes its outcome. Fix: gate the catch on `c.OnException is not null`, not on hasPhrase.

DEFECT 2 — THE ARM IS FAMILY-UNFILTERED (L2.1 half (i), L2.2 half (B), the `wrong_answer` flag). GR3h item 1 admits only the EC-PROGRAM-* and EC-EXTERNAL-* families into imperative-statement-1, and carries NO checking-enabled qualifier (unlike items 2 and 3) — EnabledProgramNames() already selects exactly those two prefixes one line above, so the rule's own partition is expressed in the file. But ProgramTable.CallProgram also raises a CobolCallException with `notFoundEc == "EC-FUNCTION-NOT-FOUND"` for a user-defined-function locate miss, and that can happen while EVALUATING an argument inside the same try; being a CobolCallException it lands in the unfiltered arm and runs imperative-statement-1. GR3h item 2's second disjunct — 'or if the exception condition is not one of the EC-PROGRAM exception conditions', which requires such a condition to reach the applicable exception processing statements EVEN WHEN a phrase is present — therefore has no implementation at all. Checked and excluded: conditions of other families raised while evaluating arguments (EC-BOUND-SUBSCRIPT and the like) are not CobolCallException and correctly propagate to the enclosing statement's own EC wrapper, so the divergence is scoped to the CobolCallException carrier; and EC-PROGRAM-RESOURCES / EC-PROGRAM-ARG-MISMATCH can reach neither arm, having no raise site beyond their ExceptionCatalog rows (lines 151/158) and being absent from EcBinder.ProgramNames.

WHAT IS ALREADY RIGHT AND MUST NOT REGRESS: the filtered arm sets ExceptionState.Set(__ce.EcName, true) per §14.6.13.1.1, runs the §14.9.49 Format-3 declarative selection, honours `__r >= 0` as RESUME AT and re-throws CobolFatalException when `__r != -2` (§14.6.13.1.3 #5/#7), with RESUME NEXT (-2) falling to the end of the CALL — pinned by conformance:2023/ec_program_ptr_null (>>TURN EC-PROGRAM-PTR-NULL CHECKING ON, USE AFTER EXCEPTION CONDITION, RESUME AT NEXT STATEMENT; .out HANDLED-PTR-NULL / AFTER) and by ExceptionConditionConformanceTests.CallNotFound_Enabled_DeclarativeResumes / CallNotFound_Enabled_NoHandler_FatalTerminates (AssertSpec / AssertFatal, spec-pinned, not legacy-baked). 3i's NOT ON dispatch and EmitPropagationPickup (the activator-side pickup of a callee-staged GOBACK/EXIT PROGRAM … RAISING, honouring RESUME per §14.6.13.1.3 #6) are pinned by conformance:2023/ec_external_format_conflict.

WHAT WOULD CLOSE IT: `c.OnException is not null` on the phrase catch; a family filter (EC-PROGRAM-*/EC-EXTERNAL-* only) on it; routing a non-EC-PROGRAM CobolCallException to EcDispatchExpr regardless of the phrase; and goldens for (a) a NOT-ON-only failing CALL that must terminate the run unit and (b) a UDF-miss raised while evaluating an argument under an ON EXCEPTION phrase.

SPEC REFS as carried by the rows: §14.9.4.4 GR3h items 1/2/3 and GR3i; §14.6.13.1.1; §14.6.13.1.3 #5/#6/#7/#8; §14.9.49 Format 3; Annex E.2 item 1 bullet 3 (the ON OVERFLOW removal — the only CALL entry in Annex E).
