# PB2848 — OPEN — four I/O-status findings around OPEN, WRITE and record counting

Found by the train 1047 lander's review (step 5b; `E:\COBOL-coord\scratch\reports\train1047-report.md`, finding (e)) on cluster 47B (PB2692, PB2748, PB2751), all PLAUSIBLE (traced in code, not run). The lander had no ids left; the land unit reserved this id and the resume unit of 2026-10-08 21:46 PDT filed it.

## The four findings (each needs its repro before its fix)
1. **Crash.** `CobolFile.ResolveHostPath` (`src/Cobol.Net.Runtime/IO/CobolFile.cs:375`) calls `Path.GetFullPath`,
   which throws on a malformed host path. Its callers (`FileConnector.cs:98/105`, `FileRegistry.cs:142/159`) run it
   outside OPEN's I/O-status catch, so a bad ASSIGN value is an unhandled .NET exception instead of an OPEN status.
2. **Wrong status.** A record-locking OUTPUT writer opens its host file ReadWrite; on a file the host grants
   write-only access to, OPEN OUTPUT answers 37 (permission) where a write-only open would succeed.
3. **Wrong status.** `SequentialConnector.CountRecords` (`SequentialConnector.cs:431`, called at `:252`, `:989`,
   `:1026`) runs after the flush and can answer 30 for a record that was in fact written.
4. **Order of conditions.** `FileRegistry.WriteSharedInStatement` (`FileRegistry.cs:1546`) checks the condition that
   gives 54 before the one that gives 44, the pre-existing sibling of PB2751's ordering fix.
