# R37 — adjudicate: the vendor special registers RETURN-CODE / LENGTH OF / SYSTEM-OFFSET — strict-ISO rejection is correct today; vendor-dialect support is a decision

> Found by the R21+R22+R30 battery's differential leg (2026-08-08): 16 flips AGREE_ACCEPT →
> WE_REJECT_THEY_ACCEPT — RETURN-CODE ×7 (run_extensions/run_misc/run_returncode), LENGTH OF ×8
> (lexes as `LENGTH OF item`, a qualified reference to an undeclared LENGTH), SYSTEM-OFFSET ×1
> (run_functions:4375) — all COBOLNET1639 since R30.

These registers are NOT in §8.4.3's closed list of ISO special registers/identifiers — they are
IBM/X-Open/GnuCOBOL extensions. Under the default --std 2023 STRICT posture, "not defined" is the
CORRECT verdict, and the pre-R30 behavior (compile clean, throw at run time) was the wrong stage for
the same verdict. The flips are attributed as spec-correct divergence from a vendor-lenient oracle —
the WE_REJECT_THEY_ACCEPT tier exists for exactly this.

THE OPEN DECISION ([[dialect_two_axes]] / [[survey_compilers_on_latitude]]): whether the vendor
dialect axis (--permissive or a future --dialect) ADMITS these registers, each with real semantics
(RETURN-CODE feeds the process exit code; LENGTH OF is a compile-time size register). Survey
IBM/MF/GnuCOBOL semantics before any implementation; until decided, the strict rejection stands and
the diagnostic's spelling ("not defined") is honest.

**SURVEY COMPLETE 2026-08-08** (web research workflow, primary vendor documents, quotes + URLs in the
run's journal — `wf_1d8f1ced-bfc`):
- **RETURN-CODE** — IBM Enterprise COBOL: implicit `01 RETURN-CODE GLOBAL PICTURE S9(4) USAGE BINARY
  VALUE ZERO`; Micro Focus: predefined `PIC S9(9) COMP` (configurable S9(4)/S9(9)/S9(18) via
  RTNCODE-SIZE); GnuCOBOL: `USAGE BINARY-LONG SIGNED` (signed 32-bit). All three feed the process exit
  code / CALL return channel. ⚠ The three VENDORS DISAGREE on the declared size, so any future
  implementation must pick and document a size (the IBM S9(4) vs MF/GnuCOBOL 32-bit split is the real
  interop question).
- **LENGTH OF** — IBM: implicit `PICTURE 9(9) USAGE BINARY` (9(18) under LP(64)); MF: implicit 9(9);
  GnuCOBOL: a compile-time numeric value, not a stored register.
- **SYSTEM-OFFSET** — GnuCOBOL-ONLY, and not even a register: a reserved-word keyword extension
  replacing an optional argument. IBM and MF: unsupported.
The survey satisfies this note's prerequisite. The strict rejection stands as the documented posture;
whether a vendor dialect ever admits these is a FEATURE decision for the owner (recorded here with the
sizes above so the decision, if taken, starts from the measured landscape).

> **OWNER DECISION 2026-08-08 (closing the vendor axis): COBOL.NET stays STRICT-ISO permanently.**
> GnuCOBOL's non-ISO extensions are NOT implemented behind any dialect mode; --permissive keeps its
> existing coercions only. This note's measured semantics remain the record if history ever reopens it.
