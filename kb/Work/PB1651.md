# PB1651 — OPEN

Filed 2026-09-27 by the train-66 lander from the wave-66 G implementer report.

**Observed.** `python scripts/spec/where.py <clause>` on a Windows console whose code page is cp1252 raises
`UnicodeEncodeError` at `scripts/spec/where.py:61` when it prints a `§` or other non-cp1252 character. It works only
when `PYTHONIOENCODING=utf-8` is set. MANDATORY-PRACTICES P6 names `where.py` as a first-call orientation tool, so
every agent on a cp1252 host hits this.

**Repro.** In a PowerShell or Git Bash console without `PYTHONIOENCODING`: `python scripts/spec/where.py 13.16.3`.

**Fix shape.** Reconfigure stdout to UTF-8 at start-up (`sys.stdout.reconfigure(encoding="utf-8")`), as the other
`scripts/spec/*.py` tools that print clause text do. Sweep the sibling scripts for the same missing call.
