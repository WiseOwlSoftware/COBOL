# PB860 — OPEN — one catch clause for two conditions the standard separates

Source: the `PB771` implementer report, item (a) — MEASURED there with a foreign `FileShare.None` handle held on
the path while this run unit opened the file INPUT:

```
[seq] '30'  ·  [rel] '30'  ·  [ixd] '30'        (ISO 9.1.13.9 item 1 a) requires '61')
```

Pre-existing and uniform (PB740 gave the sequential organization a real file lock and the same '30'), so it is
one note about the status mapping, not three.

```

  OK  §9.1.13.9 1)  (File sharing conflict condition with unsuccessful completion)
      1) I-O status = 61. A file sharing conflict condition exists because an OPEN statement is attempted on a physical file and that physical file is already open by another file connector in a manner that conflicts with this ...
$ python scripts/spec/cite.py --check 9.1.13.6 "A permanent error exists and no further information is available"
  OK  §9.1.13.6 1)  (Permanent error condition with unsuccessful completion)
      1) I-O status = 30. A permanent error exists and no further information is available concerning the input-output operation.
```

'30' is the status for "no further information is available"; here the information IS available and is exactly
what §9.1.13.9 describes.

## Code site, on this tree

`src/Cobol.Net.Runtime/IO/FileConnector.cs:567` — `catch (IOException) { s = FileStatusCode.PermanentError; }`,
with three more `PermanentError` mappings at :574, :575, :661-662.

## Shape of the fix

A host-capability classification in `HostFile` that distinguishes a sharing violation from a permanent error —
Windows `ERROR_SHARING_VIOLATION` (0x20) / `ERROR_LOCK_VIOLATION` (0x21), Unix `EWOULDBLOCK`/`EAGAIN` — and
NEVER an `OSPlatform` literal at the call site (kb/Work PB795). The classification is one function; the mapping
table then reads it.

* The CLOSE, READ and WRITE paths have their own `catch (IOException)` clauses with the same blindness — every
  one of them is a status decision.
* `GR-9.1.13.9-2` (the conflicting-mode arm) is the same rule's other leg and is also GAP.
* kb/Work PB833 owns §9.1.15 2)'s missing Linux/macOS lock; this note is about the STATUS a refusal answers,
