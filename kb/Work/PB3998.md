# PB3998 — national-items-displayed-as-utf-16-bytes--compare-pad: Comparison of national items of unequal length pads the shorter one with 0x20 bytes, so N"A" is not equal to N"A  "

Filed 2026-10-28 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-20261027-215606`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

Under `-std=cobol2014`, a relation condition between two national operands of different lengths pads the shorter
operand with the alphanumeric space byte 0x20 in every byte, not with the national space character. GnuCOBOL's own
national literal N" " is `00 20`, so a PIC N(1) item holding N"A" compares unequal to a PIC N(3) item holding N"A  ",
and a national literal N"A" compares unequal to the same item, although the standard extends the shorter operand
with national spaces. Equal-length national comparisons are right. Class: wrong output. A mechanism of the harvest
family "national items displayed as UTF-16 bytes", distinct from `--national-space-fill` (PB3897, the FILL of an item;
its record names this comparison padding only in passing and its fix sites do not include it): here every operand
holds exactly the characters of its own VALUE literal, and only the comparison's padding is wrong. Fuzz night
2026-10-27/28: fz00575, fz01278, fz02689, fz04803, fz05509, fz06214, fz06215 (signature OUTPUT_DIFFERS:8.8.4.2.10).

## Minimal test case

Free reference format (`-fformat=free`), 11 lines, written for this record.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. NCMPPAD.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 SHORT-N PIC N(1) VALUE N"A".
01 LONG-N  PIC N(3) VALUE N"A  ".
PROCEDURE DIVISION.
IF LONG-N = N"A  " DISPLAY "1 EQUAL" ELSE DISPLAY "1 NOT EQUAL" END-IF
IF SHORT-N = LONG-N DISPLAY "2 EQUAL" ELSE DISPLAY "2 NOT EQUAL" END-IF
IF N"A" = LONG-N DISPLAY "3 EQUAL" ELSE DISPLAY "3 NOT EQUAL" END-IF
STOP RUN.
```

File: `E:/COBOL-coord/scratch/fuzz-triage/fuzz-20261027-215606/records/national-items-displayed-as-utf-16-bytes--compare-pad.cob`.
Line 1 is the control: the item holds its literal's characters, so the equal-length comparison is true on both sides.

## Observed result

Compile exit code 0, with `-Wunfinished` warnings ("handling of USAGE NATIONAL is unfinished", "handling of national
literal is unfinished") and the C compiler's "'_FORTIFY_SOURCE' redefined" warning (the Ubuntu package's build flags,
not the program). Run exit code 0, output:

```
1 EQUAL
2 NOT EQUAL
3 NOT EQUAL
```

## Expected result (per ISO)

Output `1 EQUAL`, `2 EQUAL`, `3 EQUAL`.

- §8.8.4.2.9 (checked): "An operand of class national may be compared with another operand of class national." and
  "Locale-based comparison is used when the national program collating sequence in effect is locale based; otherwise,
  standard comparison is used." The program names no collating sequence, so standard comparison applies; "The length
  of an operand is the number of national character positions in the operand" (1 and 3 here).
- §8.8.4.2.10 2) (checked): "comparison proceeds as though the shorter operand were extended on the right by
  sufficient national spaces to make the operands of equal length."
- §8.8.4.2.10 1) (checked): "The operands are determined to be equal if all pairs of corresponding national characters
  are equal." SHORT-N extended by two national spaces is A, space, space, the characters LONG-N holds.

Edition: national data items, national literals and these comparison rules are COBOL 2002 features; the 2009
committee draft for ISO/IEC 1989:2014 (CD 1.2, std.txt line 8941) has the same rule ("shorter operand were extended on
the right by sufficient national spaces to make the operands of equal length"), and no Annex E item changes it. The result does not depend on the national
collating sequence, because only equality is tested.

## Our compiler

WiseOwl COBOL (fresh judge `E:\tmp\fuzz-judge-20261028\cobol.exe`), `cobol ncmppad.cob --std 2014 --source-format free
-o ncmppad.dll`, then `dotnet ncmppad.dll`: compile exit 0 with no diagnostic, run exit 0, output `1 EQUAL`, `2 EQUAL`,
`3 EQUAL`.

## Fix site

GnuCOBOL 3.2 source, read observationally:

- `libcob/common.c`, `cob_cmp_alnum` (line 1951): after comparing the common length it compares the remainder of the
  longer operand "with spaces" through `compare_spaces` (line 1865), which tests against `COB_SPACES_ALPHABETIC` (the
  PIC X/A/U space string, `libcob/common.h` line 1928), and on the collating path through `common_cmpc (..., ' ', ...)`;
  both are single-byte spaces whatever the category of the operands.
- `libcob/common.c`, `cob_cmp` (line 3834): the national branch is disabled (`#if 0` at line 3863, "FIXME later: must
  cater for national fields, too"), so two national operands reach `cob_cmp_alnum`.

A national comparison needs its own padding character, the national space `00 20` that GnuCOBOL's N" " literal holds.

## Draft issue

**Title:** Comparison of national items of unequal length pads the shorter one with 0x20 bytes, so N"A" is not equal to N"A  "

**Body:**

Environment: GnuCOBOL 3.2.0 (Ubuntu gnucobol3 3.2-4build1), x86_64 Linux.

Steps: `cobc -x -free -std=cobol2014 -o p ncmppad.cob && ./p` with

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. NCMPPAD.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 SHORT-N PIC N(1) VALUE N"A".
01 LONG-N  PIC N(3) VALUE N"A  ".
PROCEDURE DIVISION.
IF LONG-N = N"A  " DISPLAY "1 EQUAL" ELSE DISPLAY "1 NOT EQUAL" END-IF
IF SHORT-N = LONG-N DISPLAY "2 EQUAL" ELSE DISPLAY "2 NOT EQUAL" END-IF
IF N"A" = LONG-N DISPLAY "3 EQUAL" ELSE DISPLAY "3 NOT EQUAL" END-IF
STOP RUN.
```

Observed: `1 EQUAL`, `2 NOT EQUAL`, `3 NOT EQUAL` (exit code 0).

Expected: `1 EQUAL`, `2 EQUAL`, `3 EQUAL`. ISO/IEC 1989:2023 8.8.4.2.10 rule 2 (the same rule in the 2014 edition's
committee draft): when national operands are of unequal length, "comparison proceeds as though the shorter operand were
extended on the right by sufficient national spaces to make the operands of equal length."

Cause, as read in the source: `cob_cmp_alnum` in libcob/common.c compares the excess of the longer operand with
`COB_SPACES_ALPHABETIC` (single-byte spaces), and `cob_cmp` has its national branch under `#if 0`. The excess of a
national operand holds national spaces (`00 20`), which never match `20 20`.
