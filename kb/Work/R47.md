# R47

Asked 2026-09-25 (doc-rows-2, item 159 / kb/Work PB690 blocked on the owner): "When COBOL.NET writes an alphanumeric
record to a sequential or report file with no CODE-SET clause, which encoding should it use? (Today it silently writes
'?' for any character above U+00FF.)" Options: Latin-1 + refuse · UTF-8 · UTF-16.

**Answer: Latin-1 + refuse (the recommended option).** One byte per character position, so record sizes stay fixed —
the GnuCOBOL byte-per-position model and §7 item 209. A character above U+00FF is refused with an I-O status (the
implementer derives which status from §9.1.13 — the refusal must be an I-O condition the program can observe, never a
silent substitution) instead of being written as '?'.

Consequences: PB690 is unblocked (implement the refusal at the sequential/report writer; `SequentialConnector.OpenCore`
keeps Latin-1 but encodes with an exception fallback that maps to the chosen status); doc-rows-2 writes the §7 rows for
items 31 (the computer's coded character set for files), 36, 38, 146 and 159 on this answer, and item 209 stays.
