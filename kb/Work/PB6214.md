# PB6214 — two floating insertion strings accepted when one is an extended currency string

**Mechanism.** `PictureComposition.cs:777`. PB6177's new arm asks a floating extended run `MayPrecede[FloatCurrencyLeft]` (and
`FloatSignLeft`). The `FloatCurrencyLeft` row admits `FloatCurrencyLeft` (a currency run repeating itself), so a preceding `$$`
string passes; a following `$$` is never asked, because the extended run joins no seen set. Read as PB6177's note R2-1 does (GR6 and
SR27 NOTE 5: a character-string holds one floating insertion string, which is why LL99FF and LL9LL are refused) and the SR26
extended form (the currency symbol leftmost, optionally preceded by character-1, or rightmost), a floating extended string beside a
floating currency string is two floating insertion strings and should be refused.

**Fix shape.** Add the extended run to the seen set the floating-string check uses, so it counts as the one floating string in
both orders; test both orders. Sweep the other floating kinds (sign, currency, extended) for the same pairs. Cite only after
`cite.py --check` on the clause read from PB6177.

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/PictureComposition.cs:777`
