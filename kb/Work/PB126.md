# PB126

`RuntimeConfigTests.Describe_NamesEveryEntry_AndReadsOnly` snapshots `Environment.GetEnvironmentVariable(CacheConfig.SizeVariable)`
before calling `RuntimeConfig.Describe()` and asserts it unchanged after — the "Describe writes nothing"
invariant. `CollationKeyCacheTests` (lines ~110–129) legitimately sets that same variable to "1234"/"off"/
"nonsense" and restores it in a finally. Environment variables are PROCESS-global; xUnit runs the two classes
in parallel, so an interleaving that lands the mutator's window inside the reader's snapshot pair fails the
equality assert. Observed ONCE, in PB125's wave-local gate, immediately after five new FactorialDecTests
shifted the schedule; a serial re-run of the test passed (the flake-disposition protocol: name, reproduce in
isolation, attribute the mechanism).

**Fix (landed with PB125):** both classes share `[Collection("process-environment")]` — xUnit serializes
classes in one named collection, which is exactly "as concurrent as correctness allows" for process-global
state (the `site-tailoring-directory` collection is the existing precedent). Sweep: RuntimeConfigTests is the
only env-stability ASSERTER in the suite, and CollationKeyCacheTests the only mutator of a variable it reads;
the other env-mutating classes (locale/tailoring/define tests) restore in finally and have no concurrent
stability reader, so the pair closes the shape.
