# PB126

`RuntimeConfigTests.Describe_NamesEveryEntry_AndReadsOnly` snapshots `Environment.GetEnvironmentVariable(CacheConfig.SizeVariable)`
before calling `RuntimeConfig.Describe()` and asserts it unchanged after — the "Describe writes nothing"
invariant. `CollationKeyCacheTests` (lines ~110–129) legitimately sets that same variable to "1234"/"off"/
"nonsense" and restores it in a finally. Environment variables are PROCESS-global; xUnit runs the two classes
in parallel, so an interleaving that lands the mutator's window inside the reader's snapshot pair fails the
equality assert. Observed ONCE, in PB125's wave-local gate, immediately after five new FactorialDecTests
shifted the schedule; a serial re-run of the test passed (the flake-disposition protocol: name, reproduce in
isolation, attribute the mechanism).

**Fix (landed with PB125, WIDENED after battery #28):** my first sweep grepped only for ENV-stability
asserters and closed the pair — battery #28 immediately falsified that complement claim
(feedback_measure_the_selectors_complement): `CollationTailoringTests.Spanish_EnyeIsALetterAfterN`'s
`Assert.Same` on CollationEngine's per-locale collator cache raced `CobolLocaleTests`/`LocaleManagerTests`'s
`LocaleManager.ClearCache()` (which flushes the engine + CLDR caches) — the SAME shape on a SECOND
process-global, cache IDENTITY rather than env value. The measured complement (grep `Assert.Same(` suite-wide
plus every `ClearCache` caller): five classes mutate or identity-assert process-globals —
RuntimeConfigTests, CollationKeyCacheTests (env var + shared key caches), CobolLocaleTests and
LocaleManagerTests (cache clearers; the old `site-tailoring-directory` pair), CollationTailoringTests
(collator-cache identity). All five now share ONE `[Collection("process-globals")]`; the two older
collection names are retired. Every other `Assert.Same` in the suite is over a local instance or an
immutable root singleton.
