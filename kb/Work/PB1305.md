# PB1305 — LANDED 2026-09-28 (wave 70 V3)

## Landing (wave 70 V3) — Int128 VARYING counters and the EC-REPORT-VARYING raise

- **Re-probed** on the w70 V3 build: `FROM 2 * 3 - 5 BY 4 - 2` and `BY WS-F` (PIC 9V9) were CS0266 backend crashes;
  a noninteger FROM/BY raised nothing. After: `1 3 5` / `1 3 5`, and `FROM 7 / 2` under
  `>>TURN EC-REPORT-VARYING CHECKING ON` runs the declarative (EC-REPORT-VARYING) and RESUME AT NEXT STATEMENT continues.
- **Fix (F1):** the compose locals are `Int128` (§13.18.64.4 GR1 — "an independent temporary integer data item that
  shall be large enough to contain the maximum expected value"); `ReportWriterEmitter.VaryValue` lands FROM/BY in the
  value's own lane through `CobolReport.VaryingInteger` (fixed unscaled+scale / binary64 / CobolDec).
- **Fix (F5):** `VaryingInteger` raises EC-REPORT-VARYING (§13.18.64.4 GR5, Table 13 Fatal) through
  `ExceptionState.ReportVaryingError`; flag `CheckingFlags.ReportVarying`, gate row in `EcEmitter.FatalAmbientGates`,
  bound to GENERATE/TERMINATE by `EcBinder.ReportProductionNames`. ⚠ DETERMINATION: with checking OFF the counter takes
  the value's integer part and the statement continues (GR5 leaves the print line undefined — §A.2 item 63).
- **For the next implementer:** `src/Cobol.Net.Compiler/CodeGen/Verbs/ReportWriterEmitter.cs#VaryValue` is the ONE
  landing of a VARYING value; `src/Cobol.Net.Runtime/IO/ReportWriter.cs#VaryingInteger` the ONE noninteger test (trap:
  a Real or Dec NumX has no compile-time scale — use its overload, never `Align(x, 0)`, which truncates silently).
  Goldens `conformance:2002/pb1305_report_varying_expression`, `conformance:2014/pb1305_report_varying_standard_decimal`,
  `conformance:negative/pb1305-report-varying-85`.
- **Closes** FMT-13.18.64.2 and GR-13.18.64.4-5. **GR-13.18.64.4-3 stays DIVERGES with kb/Work PB1306** (F2 group-entry
  counter, F3 `BY K` refused COBOLNET0899); its notes were restated with F1 fixed (batch `w70v3-PB1305-residual`).

## Measured

### Finding varying-clause — ISO §13.18.64.2; §13.18.64.4 GR3, GR5 (crashes; rows FMT-13.18.64.2, GR-13.18.64.4-3, GR-13.18.64.4-5)

**Mechanism.** F1 - ReportWriterEmitter.VaryValue renders a VARYING FROM/BY arithmetic expression through NumericRenderer.Align(..., 0) and assigns it to a C# `long` local; any expression containing an operator (the renderer widens to Int128) or an operand with nonzero scale produces uncompilable C# (CS0266 Int128 -> long).

**Repro.** RD R-V ... 01 DET-A TYPE DE. 02 LINE PLUS 1. 03 COLUMNS 1 3 5 PIC 9 VARYING K FROM 2 * 3 - 5 BY 4 - 2 SOURCE K.  GENERATE DET-A. (probe out13/probe/varying-clause/vint; also vexpr `FROM 7 / 2`, vscl `BY WS-F` PIC 9V9 VALUE 2.0)

**Expected, from the standard.** §13.18.64.2 admits arithmetic-expression-1/-2; §13.18.64.4 GR3 a)/b): counter = 1, 3, 5 -> line `1 3 5`. For a noninteger value (FROM 7 / 2) GR5 sets EC-REPORT-VARYING and the GENERATE is unsuccessful - never a compile failure.

**Observed.** error: backend compilation failed ... (66,25): error CS0266: Cannot implicitly convert type 'System.Int128' to 'long' ; generated `long __rv2_0 = ((Int128)(((Int128)(2L) * (3L))) - (5L));`

**Code site.** src/Cobol.Net.Compiler/CodeGen/Verbs/ReportWriterEmitter.cs#VaryValue (line ~209) and the `long {VaryName}` locals in EmitFieldPlacements (lines ~131-134)
