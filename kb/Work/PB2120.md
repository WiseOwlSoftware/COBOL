# PB2120 — a named cluster is a plannable unit (R69)

Measured 2026-10-06: `scripts/spec/work.py`'s `actionable()` selects notes with a HARM flag set and not
`process_only`; `.agent-fleet.json` passes `skip_flag: [blocked, process_only]` and `kind: defect` to
`fix_clusters.py`, whose clusters come from code sites under `src/Cobol.Net.*`; `plan_wave.py` plans only from those
clusters. Every R69 item is `process_only: true` with sites in `tests/`, `scripts/`, `.github/`, `docs/` or
`src/CobolSharp.*`, so none can be planned or dispatched by the machinery. Until this lands, the two clusters are
dispatched with a hand-written `groups.json` through the `workstream` skill (`make_dispatch_specs.py`,
`check_practices.py`, the Workflow rolling wave), which is the sanctioned manual path.

**Model:** Opus (orchestrator code with tests; `DESIGN-orchestrator-loop.md` is the design to extend).

## Shape (make the next campaign automatic, CLAUDE.md rule 5)

1. `work.py next --cluster <lead-id>`: the open, unblocked notes whose `cluster` names the lead, ordered by their
   `blocked_by` topology, regardless of harm flags. `work.py check` already validates `cluster` and `blocked_by`.
2. `plan_wave.py --cluster <lead-id>`: groups computed from that set by the notes' declared code sites (no
   `src/Cobol.Net.*` restriction for a campaign cluster; the sites are whatever the notes name), with the same model
   routing (`model_rules.json`), budget and train mechanics as a fix wave; `--dry-run` prints the plan.
3. `orchestrate.ps1 -Cluster <lead-id>`: a campaign lane that runs that cluster's waves between fix-lane trains and
   stops when the cluster is landed. The fix lane's behaviour without `-Cluster` is byte-identical to today.
4. Tests in `test_plan_wave.py` and `test_orchestrate.ps1` for the new selection, and a test that the default path
   (no `--cluster`) is unchanged.
5. `DESIGN-orchestrator-loop.md` gains the campaign lane; the `workstream` skill's dispatch section names it; the
   public `agent-fleet` skill's orchestrator-loop reference describes the pattern (generalized, no ids).
