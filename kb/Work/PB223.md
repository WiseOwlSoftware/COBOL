# PB223

Found by the cluster-B review fleet on the pre-commit [[PB169]]–[[PB172]] tree, 2026-08-31. Both are comment
defects with no behavioural reach, and both are the shape CLAUDE.md rule 6 exists for: a doc that describes the
compiler as it WAS, sitting beside the code that changed it.

**1. `ExpressionBinder.IndexNameExpr`'s summary, doubly stale.** It read: "A true arithmetic position (COMPUTE
and the arithmetic verbs, RETRY, CONTINUE AFTER, **STOP STATUS** …)".

  * The ROUTING half: [[PB169]] took the STATUS operand out of the expression spine entirely.
    `BindTerminationStatus` no longer calls `host.Expr.BindExpr`, so no status operand reaches `RefExpr` or
    `IndexNameExpr`; the r7 rejection for that slot now comes from `ScreenIndexNameOperand` (R16), a different
    mechanism with a different — and correctly different, see [[PB219]] — lane posture.
  * The SPEC half, which is the sharper one: the same change set REFUTES the comment's CLAIM. Calling the STATUS
    slot "a true arithmetic position" is precisely the premise `BindTerminationStatus`'s new doc denies — "⛔ THE
    POSITION IS NOT AN ARITHMETIC EXPRESSION, and binding it as one rejected legal COBOL" — because §14.9.42.2
    writes the slot `{identifier-1 | literal-1}`, not `arithmetic-expression-1`. One file asserted what the
    other file's headline denied.

Fixed by naming the reference-modification bound (§8.4.3.3.3 SR4) in the list instead, and recording the STATUS
slot's departure explicitly — it is named in the summary now only to say that it LEFT and why, since a reader
arriving from PB169 will look for it.

**2. `ControlFlowBinder`'s GOBACK quotation.** The doc bullet read: `SR2/SR6 — "Identifier-1 shall reference an
integer data item or a data item with usage display or usage national"`. The pairing is right and the substance
is identical, but §14.9.18.3 SR6 reads **Identifier-2** — GOBACK's identifier-1 is the RAISING object, so its
status operand is numbered differently from STOP RUN's. Mechanically confirmed both ways:

    cite.py --check 14.9.18.3 "Identifier-1 shall reference an integer data item …"  -> FAIL
    cite.py --check 14.9.18.3 "Identifier-2 shall reference an integer data item …"  -> OK §14.9.18.3 6)
    cite.py --check 14.9.42.3 "Identifier-1 shall reference an integer data item …"  -> OK §14.9.42.3 2)

Fixed by quoting the STOP form (which is what the bullet is about) and naming the identifier-2 difference in the
same sentence, so the wrong spelling cannot be copied out of this comment the way "§8.8.4.1.1" was copied out of
the last one ([[PB182]]). `DiagnosticCatalog`'s own text was checked and is fine — it names SR6 without
re-quoting it.
