## COBOL2326 at `--std 85` cites the rule the statement breaks (wave 20262113 group A); the 2002 and 2014 halves still wait

**Re-probe** (`--std 85`, a build of 8244f1aa4b): `SET K TO 3` over `01 K PIC 9(4)` was refused COBOL2326 "violates ISO §1985:VI.6.23.3 SR2 —
'Identifier-1 and identifier-2 must each reference an index data item or an elementary item described as an integer'", a rule K satisfies.
Reproduced.

**Fix:** `SetBinder.ScreenIndexAssignmentReceiver` names the general rule §1985:VI.6.23.4 GR5's table points each "No" at: an integer data
item receiver sent an integer or an index data item is GR3c ("it may be set only to an occurrence number that corresponds to the value of
index-name-2. Neither identifier-2 nor integer-1 can be used in this case"), an index data item receiver sent an integer is GR3b
("it may be set equal to either the content of index-name-2 or identifier-2 where identifier-2 also references an index data item").
Each pairing carries its later-edition text and its 1985 text as one `(Later, Y1985)` row through `EditionInfo.Cite`, so a 2002 or 2014
text is the `y2002` / `y2014` argument of that call, not a second switch. The sender-class arm that cites SR2 for a sender that is
neither index nor numeric is right and is unchanged.

**Witnesses:** `pb5978-set-integer-item-cites-gr3c-85`, `pb5978-set-index-data-item-cites-gr3b-85`.
