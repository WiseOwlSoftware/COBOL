# R04 — `EXCEPTION-STATEMENT` returns `GO` where Table 12 requires `GO TO`

`EXCEPTION-STATEMENT` returns `GO` where Table 12 requires `GO TO`

> Migrated from the fix queue's RESIDUE block, which never itemised these — so no work list could see them.

## Root cause — LOCATED (2026-08-07, analysis only; nothing changed yet)

`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/EcBinder.cs:470` — `EcWrap` builds the `EcStatementInfo` with

```csharp
enabled, withLoc, s.Start.Text.ToUpperInvariant(), EcLocation(line)
```

**the statement's FIRST TOKEN**, which is the §15.32.3 r2 name for 49 of Table 12's 50 statements and wrong for
the fiftieth. The value travels bound → `EcEmitter.EcStmtLoc` → `ExceptionState.LastStatement` →
`EcFunctions.Statement()` (`src/Cobol.Net.Runtime/Exceptions/EcFunctions.cs:32`), which only pads to 63; every
layer downstream is faithful, so the binder is the single site.

## Spec

- **§15.32.3 r3** — *"The names of the statements are given in Table 12, Procedural statements, in the column
  labeled 'Statement name'."* — validated: `python scripts/spec/cite.py --check 15.32.3 "…"` → OK.
- **Table 12** — spec anchor `table-12` (§14.5.1). **Scraped mechanically: 50 data rows, ACCEPT…WRITE, and
  `GO TO` is the ONLY multi-word name.** (I had eyeballed "55 rows" before measuring; it is 50.)

## ⛔ THE TOKEN AXIS IS THE WRONG AXIS — AND THIS KILLS BOTH OBVIOUS FIXES

`goToStatement : GO TO? procedureName? …` (`Core/CobolControlFlow.g4:202`) — **`TO` is OPTIONAL in this
grammar**, so `GO PARA.` is a GO TO statement whose leading tokens never contain `TO`. Therefore:

- the minimal patch (*"if the first token is `GO`, emit `GO TO`"*) is a hand-maintained special case (rule 5),
  and
- a longest-match of the source's leading tokens against the Table 12 name set — which looks structural — still
  returns `GO` for `GO PARA.`

§15.32.3 r3 names a property of the **statement KIND**, not of how the source spelled it. The kind is exactly
what the parse rule identifies, and `EcWrap` already receives `Core.StatementContext s` — the child rule
(`goToStatement`) is in hand. **The fix is a statement-kind → Table 12 name resolver, keyed on the parse rule,
not on tokens.**

Pair it with a spec-derived drift test in the established shape
(`tests/Cobol.Net.Tests.Unit/EvaluateOperandCombinationsDriftTests.cs` scrapes Table 15 the same way, and
asserts the shape it found BEFORE comparing, so a transcription reformat fails loudly instead of comparing
nothing): scrape Table 12, and assert every `statement` alternative in the grammar resolves to a name in it, so
a newly added statement rule fails until it is mapped.

⚠ Two known wrinkles for whoever implements it: the `statement` rule carries alternatives that are NOT Table 12
statements (`alterStatement`, `entryStatement`, `enterStatement`, `nextSentenceStatement`, the five Wave-H
unsupported-facility arms, `inlineMethodInvocationStatement`) — ALTER in particular is legal COBOL-85 and has no
2023 Table 12 row, so the resolver needs a defined answer for them rather than an assumed one; and
`searchAllStatement`/`deleteFileStatement` are finer-grained than their Table 12 rows (`SEARCH`, `DELETE`).

## Verification the fix will need

A golden that raises a checked EC inside a `GO TO` under `>>TURN … CHECKING ON WITH LOCATION` and reads
`FUNCTION EXCEPTION-STATEMENT` — **written for BOTH spellings, `GO TO PARA` and `GO PARA`**, since the second is
the one that defeats the plausible fixes.
