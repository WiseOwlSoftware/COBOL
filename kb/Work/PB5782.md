# PB5782 - a signed zero breaks a numeric control

**Sites:** `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/ReportWriterEmitter.cs#EmitReportConstruction` (the
character-image arm passes no equality delegate for a numeric control item) and
`src/WiseOwl.Cobol.Runtime/IO/ReportWriter.cs#ControlEntry.ChangedFrom` (falls back to ordinal image equality; its
comment holds that a numeric item's image "is a function of its value", which is untrue of a signed zero). Kb/Work
PB1131 (landed) moved the ALPHANUMERIC controls onto the program's comparison; the numeric arm was left on the image.

**The rule.** §1985:XIII.3.7.4 GR3 a: "If the control data item is a numeric data item, the relation test is for the
comparison of two numeric operands." §1985:VI.6.3.1.1.1: "Zero is considered a unique value regardless of the sign."

**Expected (from the 1985 text):** `NEG ZERO EQUALS ZERO`, `K2=+0`, `CFX`: the second GENERATE compares -0 with +0 as
two numeric operands, which are equal, so no break; the only control footing is the one TERMINATE presents.

**Observed** at `--std 85` (and at `--std 2023`), `cobol.exe negzctl.cob --std 85 --run`, exit 0:
`NEG ZERO EQUALS ZERO`, `K2=+0`, `CFX`, `CFX`. The program's own relation says -0 = 0, and the report writer still
senses a break because the saved image "-0" differs from "+0".

**The fix's shape.** One comparison for every control: the emitter passes the numeric-relation equality for a numeric
control, as PB1131 made it pass the program's alphanumeric comparison, and `ChangedFrom` loses its image fallback for a
numeric item (and its false comment). The same test serves the index-data-item arm (GR3 b) once an INDEX control
compiles. The fix lands the golden of `1985-GR-XIII.3.7.4-3`.
