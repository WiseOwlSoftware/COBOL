**Rule it breaks:** One rule in one place, never two mechanisms for one job (DESIGN-architecture-review §5.2; dimensions.md 4). The rule is ISO §15.59.4 / §15.63.4 (the content of the argument with the greatest or least value, the leftmost on a tie) and §15.71.4 / §15.72.4 (the ordinal of that same argument). ExtremeIndex (Exact.cs:319-328) already writes it once for the string carrier, with the comment 'The one selection algorithm the MAX/MIN/ORD-MAX/ORD-MIN families and their three collation variants all share'. The numeric carriers do not share it.

**Scenario:** The same loop, the same RequireArguments call and the same strict-update tie rule are hand-written in: the aligned Int128 bodies (MaxScaled, MinScaled, OrdMax, OrdMin: Exact.cs:144-159, 292-309); the unaligned pair bodies (SelectMax, SelectMin: Select.cs:25-39); the SDIDI bodies (MaxDec, MinDec, OrdMaxDec, OrdMinDec: Dec.cs:106-143); the binary64 bodies (MaxReal, MinReal: RealArgs.cs:307-310, which call Enumerable.Max and Min, and OrdMaxReal, OrdMinReal: 380-386, 410-416, which loop); and the string ExtremeIndex. A change to the comparison or tie rule must be made five times, and the copies have already disagreed. Measured on .NET 10.0.12: Enumerable.Min([1, NaN]) and Min([NaN, 1]) return NaN, and Enumerable.Max([NaN, 1]) returns 1. The loop's strict comparisons never move off a NaN at position 1 and never onto one later. So over an all-COMP-2 list (IntrinsicRenderer.cs:170 keeps an all-float list in the float lane), MAX(F1 F2) with F1 = NaN and F2 = 1 returns 1 while ORD-MAX returns 1, the NaN's position. MIN(F2 F1) returns NaN while ORD-MIN returns 1, the position of the value 1. Each value and its ordinal name different arguments, against §15.71.4's definition of the ordinal as that of the selected argument. RangeReal and MidrangeReal (RealArgs.cs:347, 365) inherit the LINQ rule. Reachability of a NaN in a COMP-2 item is not measured on the pin (DOC-A.1-70's EC-DATA-NOT-FINITE disposition presupposes one). The drift needs no NaN to cost: every carrier is a separate copy of one rule to review, test and keep in step.
