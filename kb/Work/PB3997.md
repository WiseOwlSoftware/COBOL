# PB3997 — a binary usage's VALUE is not checked against the usage's range

**Owner, 2026-10-28:** "Letting illegal source code thru is a fatal defect. Bug and must be fixed." Approved for the fix
lane.

**Site:** `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs` `ValidateNumericValue` (~:3383) tests only the picture-digit
span (`StoredShapeOf`; a `BinaryCapacity` item's Digits is 3/5/10/19, so 255 "fits" BINARY-CHAR), and its remark defers
"its full binary-capacity range" to a separate discipline that no VALUE check applies. The band is written once, in
`AlgebraicRange.Of` (`AlgebraicRange.cs`, ~:122-137), and read by the runtime store bound and the HIGHEST/LOWEST-ALGEBRAIC
fold; the VALUE check must read the same bound, never restate it.

**The rule.** `cite.py --check 13.18.63.3 "shall be permissible values within the range indicated by the PICTURE clause
or the USAGE clause"` -> OK §13.18.63.3 2). `cite.py --check 13.18.60.4 "The implementor may allow a wider range"` -> OK
§13.18.60.4 12); WiseOwl's band is the native two's-complement range (`docs/CONFORMANCE.md` DOC-A.1-206): BINARY-CHAR
SIGNED -128..+127, UNSIGNED 0..255; BINARY-SHORT -32768..+32767 / 0..65535; BINARY-LONG -2147483648..+2147483647 /
0..4294967295; BINARY-DOUBLE likewise. SIGNED is the default when neither word is written.

**Observed** (the judge, main 7f0105fec): compile rc 0, run prints `+255 +200 +65535 +4294967295 256 -129`, then `-001`
after `ADD 0 TO BC`.

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. R1.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 BC USAGE BINARY-CHAR VALUE 255.
01 BCS USAGE BINARY-CHAR SIGNED VALUE 200.
01 BSH USAGE BINARY-SHORT VALUE 65535.
01 BL USAGE BINARY-LONG VALUE 4294967295.
01 BCU USAGE BINARY-CHAR UNSIGNED VALUE 256.
01 BCN USAGE BINARY-CHAR VALUE -129.
PROCEDURE DIVISION.
    DISPLAY BC " " BCS " " BSH " " BL " " BCU " " BCN
    ADD 0 TO BC
    DISPLAY BC
    STOP RUN.
```

**Expected:** COBOL1625 (the existing "not a permissible value in the range" diagnostic) on each of the six entries, at
compile time. GnuCOBOL 3.2 also refuses them.

**Sweep:** every VALUE form on a range-bounded usage — condition-name (88) VALUE and THRU ranges, VALUE … FROM table
format, the boundary values themselves (-128 and 127 compile; -129 and 128 do not), BINARY-DOUBLE at its 64-bit edges,
and any other usage whose range is set by USAGE rather than PICTURE (COMP-5/COMP-X with the binary-truncation option,
the float usages under §13.18.63.3 2) a)'s implementor rule) so that one check, reading `AlgebraicRange`, covers them all.
