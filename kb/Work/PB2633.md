**Rule it breaks:** ISO §15.8.4 r1 (the ACOS returned value is in [0, pi]) and §14.7.4.3 r2 (no ROUNDED phrase = truncation); loud failure / no silent overflow (DESIGN-architecture-review §5, engineering-standards). Pow10.AsWide documents its range as 0..38 but its out-of-table fallback loop multiplies past 10^38 unchecked.

**Scenario:** 01 R2 PIC S9PP. 01 U2 PIC 9PP. 01 X PIC S9V9 VALUE 0.5. COMPUTE R2 = FUNCTION ACOS(X). COMPUTE U2 = FUNCTION ACOS(X). Run with the pin's built cobol.exe (src/Cobol.Net.Cli/bin/Debug/net10.0, --run): DISPLAY shows R2=J (overpunch -1, i.e. -100) and U2=1 (100); the correct landing of 1.047 truncated to hundreds is 0 (R1 PIC S9P and R0 PIC S9 land correctly: 0 and 1). Mechanism: the receiver scale is -2 (PictureAnalyzer.cs:378 scale = -trailingP); FromDoubleBounded computes limit = CodomainPi37 / Pow10.AsWide(37 - (-2)); AsWide(39) runs the fallback loop and wraps to -2.08e37, so limit = -1 and `q > limit ? limit` returns -1 for every q >= 0. No size error, no EC, under any ROUNDED mode: the clamp runs whenever the catalog row has a codomain (IntrinsicRenderer.cs:780), not only under ROUNDED. Computed for every negative scale: only Pi at -2 (limit -1) and -11 (limit +1) go wrong today, which is luck of the wrap, not design.

**Measured how:** R2 batch finding `runtime-values-1--code--f2#1` (pair runtime-values-1--code), read in the pinned tree at 8be23006851a; skeptics rule upheld, scenario upheld, site upheld.

**Spec:** §15.8.4 "The returned value is the approximation of the arccosine of argument-1 and is greater than or equal to zero and less than or equal to" (`cite.py --check` passed at collection); §14.7.4.3 "If the ROUNDED phrase is not specified, execution is as if ROUNDED MODE IS TRUNCATION had been specified" (`cite.py --check` passed at collection)

**Target:** FromDoubleBounded treats scale <= -1 explicitly (every codomain bound is < 10^38, so the limit at a non-positive-power scale is floor(bound / 10^(37-scale)) = 0 for scale <= -1, computed without a power past 10^38), and Pow10.AsWide fails loudly for an exponent outside 0..38 instead of wrapping (the same hardening PB648 plans for a negative exponent), with a unit row for scale -2 on each codomain constant and a golden COMPUTE into PIC S9PP / 9PP.

**Design reference:** PB648.
