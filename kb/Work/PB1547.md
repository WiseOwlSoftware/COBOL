# PB1547 — OPEN

## Rule
§8.4.3.11.3 SR5: "This identifier format shall not be specified as a receiving operand."
`python scripts/spec/cite.py --check 8.4.3.11.3 "This identifier format shall not be specified as a receiving operand."` → `OK §8.4.3.11.3 5)`.

## Repro
`adjudication/golden-lane-1/held-repros/l1c06-address-of-receiving-operand.cob` (`INITIALIZE ADDRESS OF WS-W`),
`cobol <file> --std 2023` (also 2002, 2014).

- Expected: rejected with a diagnostic for §8.4.3.11.3 SR5 (the address-operand band, e.g. COBOLNET0869).
- Observed: `error COBOLNET0901: 'ADDRESS' is a reserved word in COBOL-2023 and cannot be used as a user-defined
  word (ISO §8.9)`. `MOVE P TO ADDRESS OF W` and `CALL "X" RETURNING ADDRESS OF W` fail identically; `MOVE ADDRESS OF
  W TO P` draws the same misleading 0901 where the real reason is §14.9.25.3 SR1.

## Mechanism / code site
`src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4` — `dataAddressIdentifier` / `addressIdentifier` are reachable
only from SENDING slots; a receiving slot falls through to the reserved-word check. Fix: accept the address
identifier in receiving slots syntactically and refuse it in the binder with an SR5-named diagnostic.

## Row impact
The row SR-8.4.3.11.3-5 stays CONFORMS-but-untested (the source IS rejected, so the verdict holds on under-rejection;
only the witness is blocked): a negative golden with `.err` naming SR5 lands with this fix.

## Golden lane 2 (2026-09-26 11:36 PDT) — repro correction: INITIALIZE is the only SR5-pure witness
The gl2-misc-p2 writer drafted the held negative `gl2m2-address-of-initialize-receiving` (in the lane scratchpad,
not landed — it waits for this fix). Of this note's three repro shapes, only `INITIALIZE ADDRESS OF W` isolates
§8.4.3.11.3 SR5: §14.9.20.3 SR1 admits class pointer and SR7 makes identifier-1 receiving. `MOVE P TO ADDRESS OF W`
is barred independently by §14.9.25.3 SR1 (already pinned as COBOLNET0809 by `negative/pb423-move-pointer-sender`),
and `CALL ... RETURNING ADDRESS OF x` by §14.9.4.3 SR7 ("Identifier-3 shall reference a data item defined in the
file, working-storage, local-storage, or linkage section"), so neither can name SR5 alone. The SR5 negative that
lands with this fix uses INITIALIZE. (Citations re-run through `cite.py --check`: §14.9.25.3 1), §14.9.20.3 7),
§14.9.4.3 7), §8.4.3.11.3 5) — all OK.)
