# PB5854 - the code-read store does not learn that a contradicted row's defect was fixed

**Sites:**
- `scripts/spec/code_read_store.py#owed` (the planner's set: the KEPT rows still owed a read, called through `scripts/spec/code_reads.py#owed` by the `plan` command)

Noticed on Monday 2026-11-16 by the Mythos lane. kind: defect. `process_only: true`. No harm flag. Severity: MAJOR is the filer's to weigh: without it the store's count of contradicted rows can never reach zero, and the edition is not done until it does (DESIGN-spec-conformance-review.md section 10.6.1: "both reach zero before the edition is done"). area: tooling/inventory. related: PB5759, PB5842, PB5811, PB5692.

## What happened
kb/Work PB5811 (an indexed READ past an OCCURS DEPENDING ON maximum set status 34 at `--std 85`, a 2023 condition
only) was ruled from a 1985 code read in batch 5: the row's read is `contradicted` and names PB5811 as its `work`.
The fix landed on main on 2026-11-16 (the landing of kb/Work PB5733, PB5770 and PB5811, pull request 1777). The
store on the import branch still holds the row as contradicted, and nothing will change it: `code_reads.py plan`
lists only rows with no confirmed or contradicted record, so the row is never offered for a re-read; no landing
step adjudicates it; and the read itself was true when it was made.

## The shape that makes the next case automatic (decided by the Mythos lane; to be built)
`plan` treats a `contradicted` record whose `work` note is `status: landed` as OWED A READ again, by reading the
note's status the way the register's own tools do, and the view prints such records apart ("contradicted, fixed
since: owed a re-read"). The re-read replaces the record (`import --replace`), and its reader and refuter judge the
fixed code. Nothing is adjudicated by hand and no fix-lane landing has a new duty: the store reads the register.
A drift test holds it: a planted contradicted record whose note is landed is planned; one whose note is open is
not.

## Lead nobody has checked
The same question for a 2023 row re-recorded PARTIAL from a code-read ruling: a fix's landing re-records its rows
under the fix lane's existing rule (a landed fix writes `closes_rows`), so those are covered; whether every such
landing did so tonight was not checked.
