# PB4110 — the optional-word audit's false candidates

PB3752 adjudicated the audit's six candidates (rendered pages, 55 probes, then a refuter's): all six CONFORM. The audit
will report them again unless it learns three things:

1. **Another alternative of the same rule covers the omission.** `reportColumnClause` NUMBERS (§13.18.14.2, page 416)
   and `reportLineClause` ARE / NUMBERS (§13.18.35.2, page 450): the flagged alternative requires the word, but another
   alternative of the same parser rule accepts every spelling without it. A word is a candidate only when NO alternative of
   the rule admits the spelling that omits it.
2. **The wrong rule for §13.18.19.2.** The audit matched the data-description DYNAMIC LENGTH clause to
   `dynamicLengthStructureClause` (the SPECIAL-NAMES clause, §12.3.7.2, where LENGTH IS underlined, so requiring it is
   right). The rule that parses §13.18.19.2 is `CobolData.g4#dynamicLengthClause`, which already makes LENGTH optional.
3. **symbolicCharacterEntry IS / ARE** (§12.3.7.2, page 322; the audit points at page 320, the wrong page) are decided
   in the binder (`DataBinder.SymbolicEntryGroups`), which the audit cannot see. The marker
   `audit:optional-word IS ARE decided-by DataBinder.SymbolicEntryGroups` is the declared way to say so, BUT it waits for
   PB4108: today that member mis-decides a legal ordinal order, and the marker must not vouch for it.

**Site:** `scripts/spec/audit_grammar_optional_words.py` (the candidate test over a rule's alternatives, `_mandatory` /
`_flat_spellings`, and the section-to-rule map), plus the marker line above
`src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolSpecialNames.g4#symbolicCharacterEntry` after PB4108 lands. Acceptance: the
audit run on main reports none of the six, with a self-test arm per cause.
