# PB5985 - a reserved word as a computer-name gets the generic parse message

PB5920 made a literal computer-name draw COBOL7654, a sentence that says what a computer-name must be. A reserved word in the
same slot (`OBJECT-COMPUTER. GLOBAL.`, `SOURCE-COMPUTER. LENGTH.`) is refused earlier, by the parse layer's residue refusal,
with "cannot parse construct near" (COBOL1970/COBOL1971). Same root as PB5920: the refusal should know it stands in a
computer-name slot and say so, from the half-built context stack (`ClosedFormats.ComputerNameSlotOf`).

**Sites:** `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs` (whole: the residue refusal's slot detection; the fix names the member)
