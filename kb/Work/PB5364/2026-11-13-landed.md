## Landed 2026-11-13 (wave 20262022 group E): the run unit draw is bounded, and a session with no liveness byte answers 92

**Re-probe (Debug build, Windows host).** A forced region-lock host that answers every non-waiting hold `Held` and every waiting
one `Unavailable` (the lock-file host's answers over a lock directory this user may enter but not list) drove `McsStore`'s
constructor through 10 000 liveness-byte draws before the witness's counter threw: `Assert.InRange() Failure: Value not in
range` on the unfixed tree. Without the counter the draw never ends.

**Fix.** `McsStore.DrawRunUnit` draws at most `MaxRunUnitDraws` (4) ids. A fresh 60-bit id is held by another run unit only by a
collision (at most live run units x 2^-60 per draw), so a second `Held` in a row is a host that cannot tell free from held.
The draw answers 0 when the host answers `Unavailable` or `Held` every time, and `Statement` refuses every statement with 92
before it reads anything when the session holds no id: without its liveness byte every other run unit would read the owner
of a message it partly received as dead and drop the row. This is the same rule as the `Unavailable` mutex (design §6),
written as its other half. The `Unavailable` answer used to keep the drawn id and rely on the mutex to refuse; it now refuses
by the same check.

**Witnesses.** `MessageControlTests.HostThatAnswersEveryLivenessByteHeld_IsStatus92_ForEveryStatement_AndDoesNotHang` (every
OS: SEND, ACCEPT MESSAGE COUNT and RECEIVE answer 92, the files are byte for byte unchanged, and the draw stays under the
witness's bound) and `UnlistableLockDirectory_AnswersALivenessByteHeld_AndTheWaitingMutexUnavailable` (Unix: the real
lock-file host over a mode-0300 lock directory gives exactly the answers the forced host models).

**Sibling sweep.** The other random or sequential draws on a region-lock byte are already bounded: `KeyedStore.Draw` (2^16
skips, 0 on exhaustion) and `HandleColumnLockHost.Publish` (`PublishAttempts`). No other `while (true)` in the runtime retries
on `RegionLockResult.Held`.
