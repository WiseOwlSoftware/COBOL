# PB4946 - the ambient run unit never ends at process exit

**Sites:** `src/WiseOwl.Cobol.Runtime/Control/RunUnit.cs` (`RunUnit.Current`, `RunUnit._current`, `RunUnit._openRunUnits`, `RunUnit.NoteOwing`, `RunUnit.EndAtProcessExit`), `src/WiseOwl.Cobol.Runtime/IO/FileRegistry.cs` (`FileRegistry.Owing`, `FileRegistry.OpenCore`, `FileRegistry.SettleOwing`, `FileRegistry.OwesAnEnding`), `docs/CONFORMANCE.md` (whole: DOC-A.1-167's divergence line names this note)

**What happens.** DOC-A.1-167 (docs/CONFORMANCE.md) states that a run unit ends "when `RunUnit.Run`'s body returns, or at
process exit for the ambient run unit, and either way the §2023:14.6.11 actions run". The second half is not implemented:
`RunUnit.Current => _current.Value ??= new RunUnit()` creates the ambient run unit on first use, and nothing in
`src/WiseOwl.Cobol.Runtime` subscribes to process exit (`AppDomain.ProcessExit` has no reader), so nothing ends it. The
document already said "⚠ Diverges today: files are not closed for the AMBIENT run unit at process exit", but it pointed at
PB1253, which landed covering Annex A.1 items 116, 159 and 160 and never this; the divergence had no open note.

**The user's program.** A .NET host activates a WiseOwl COBOL program through its host entry WITHOUT `RunUnit.Run`. The
program WRITEs to a file under APPLY COMMIT, or leaves a file open, and GOBACKs; the host process exits.
- §2023:9.1.18.5: "When a run unit terminates normally, all file changes are permanently committed." That never happens;
  by DOC-A.1-75 the next access to the file rolls the uncommitted changes back as a dead owner's, so data the standard says
  is committed disappears.
- §2023:14.6.11 GR2: "These implicit close statements shall be executed for all open files in the run unit." They are not
  executed; a buffered write of a never-closed file can be lost.

A standalone `cobol` executable is unaffected: its `Main` boundary (`ProgramTable.RunModule`) ends the run unit.

**The fix.** End the ambient run unit at process exit exactly as `RunUnit.Run`'s return does (the §2023:14.6.11 actions,
then the commit), with a host-process witness (a child process that activates outside `RunUnit.Run`, writes under APPLY
COMMIT and exits; the parent reads the file committed). Remove the divergence line from DOC-A.1-167 in the same change.
Check the citations with `scripts/spec/cite.py --check` when writing the goldens.
