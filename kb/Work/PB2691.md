# PB2691 — the bit-group arm of the variable-length pair conversion

## What was found (w1042 C, PB2496, landed in train 1042)
PB2496 made MOVE and the relation condition convert a pair of compatible variable-length groups of DIFFERENT shapes
through their two `GroupAtom` shapes (`CobolVarGroup.Reshape`/`Compare`). A group whose items are USAGE BIT has no
atoms: `VariableLengthCompatibility.GroupAtoms` returns null for it, so `PlaceRenderer.VarGroupInShape` passes the
carrier through unchanged and `CobolVarGroup.CompareInLayout` compares under ONE layout. For two bit groups whose
variable-length components sit at different relative positions, that is the ordinal hand-over PB2496 removed for
character groups (where it was a measured wrong answer: `p\s1.cob` printed `x  a` where the spec gives `xa dd`).

## Status of the evidence
Not probed. The implementer kept the old behaviour deliberately (`p\b1.cob` exercises two SAME-shape bit groups and
passes). The first step is a probe: two compatible bit groups, different component positions (a DYNAMIC LENGTH
bit item before vs after a fixed bit item), MOVE then DISPLAY and compare; derive the expected values from §14.6.9.2
and §8.5.1.12.2 before running it.

## Site
`src/Cobol.Net.Compiler/Binding/Model/VariableLengthCompatibility.cs#GroupAtoms` (line ~186, the null for a bit
group); `src/Cobol.Net.Compiler/CodeGen/Roslyn/PlaceRenderer.cs#VarGroupInShape`;
`src/Cobol.Net.Runtime/Values/CobolVarGroup.cs#CompareInLayout`. Fix shape if it reproduces: bit atoms (bit counts
instead of bytes) in the one atom builder, so bit groups take the same Reshape/Compare path.
