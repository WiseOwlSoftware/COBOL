# PB678 — OPEN — a comparator that was only ever guarded by a refusal

Found 2026-09-05 by the `PB327` implementer (report §"New defects" A), which removed the FD/SD record gate that had
refused every national leaf in a file record — and with it the only thing standing between a national SORT key and a
comparator written for alphanumeric weights. The implementer did not take it: the collation comparator is a
different mechanism from the record codec.

## The rule

§14.9.40.4 GR5 (`cite.py --check 14.9.40.4 "national"` → `OK 5)`): *"The alphanumeric collating sequence that
applies to the comparison of key data items of class alphabetic and class alphanumeric, and the national collating
sequence that applies to the comparison of key data items of class national …"* — two sequences, chosen by the
KEY's class. `SortBinder`'s own comment cites GR5b for the national half; re-run `--check` on the sub-item letter
before it propagates into code.

## The mechanism

`src/Cobol.Net.Compiler/CodeGen/Verbs/SortEmitter.cs` (lines ≈229–242 on PB327's branch) compares
`pa.AsImage()` / `pb.AsImage()` — now the record's BYTES for a national key — with the file's alphanumeric
weights. In the native (no COLLATING SEQUENCE) case the result is right by accident: UTF-16BE byte order is code
point order. Under a declared alphanumeric sequence (an ALPHABET clause, or a `COLLATING SEQUENCE` with an
alphanumeric and a national phrase) the alphanumeric weights are applied to byte pairs — wrong order, status '00'.
The TABLE-sort twin is still staged loud at `SortBinder.cs:176`, whose comment says "file-sort national keys are
separately blocked by the D-N2 FD/SD record gate" — the block PB327 removed; that comment is now false.

**Repro:** an SD whose key is `PIC N(n)` with `SORT … ON ASCENDING KEY <national item> COLLATING SEQUENCE IS <an
alphanumeric alphabet-name>`; compiles, sorts by alphanumeric weight over UTF-16BE byte pairs.

## Fix

One comparator selected by the key's class, for the file sort and the table sort alike: the national sequence
(§14.9.40.4 GR5's second half; `CobolCollation`'s national carrier if it exists, else the identity on code points)
for a class-national key, the alphanumeric one otherwise. Take the table-sort loud stage out at the same time —
it is the same rule. Goldens: a file sort and a table sort, each with a national key under (a) native order and
(b) a declared sequence that would reorder the byte pairs, expected order computed from the rule. Not dispatchable
before train 11 lands (PB327 owns the record image).
