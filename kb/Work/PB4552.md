# PB4552 — report-sum-clause-forms-refused: -std=cobol2014: report SUM clause: UPON with RESET, UPON with two details, a repeated SUM keyword and ROUNDED are refused

Filed 2026-11-03 by `scripts/fuzz_triage.py file` from the triage of the differential-fuzz run `fuzz-batch-3000-20261103`, after an independent refuter. Upstream status `unreported`: the tracker has not been searched (owner-gated, PB3838). The run directory is git-ignored and local: the minimal program below is the repro.

## Summary

Under `-std=cobol2014`, cobc 3.2 refuses four legal forms of the report writer SUM clause: UPON followed by RESET ("unexpected RESET"), an UPON phrase with two data-names ("unexpected Identifier"), the SUM keyword repeated within the clause ("duplicate SUM clause") and the ROUNDED phrase ("unexpected ROUNDED"). All four come from one grammar rule. Class: rejects legal source. Fuzz programs: fz00402, fz01813, fz01812, fz02519, fz02517 (night fuzz-batch-3000-20261103, slice D2).

## Expected result (per ISO)

The program is legal. The report file holds the detail line `12` twice, then the control footing for WS-K with `024` (12 + 12; this sum counter is reset only at FINAL), then the final control footing `048 034 024` in columns 5, 9 and 13: 48 for the first item, because a detail named twice in UPON is added twice per GENERATE; (12 + 5) * 2 = 34 for the second; 24 for the third (ROUNDED changes nothing for integers). The rules are quoted from ISO/IEC 1989:2023. The SUM clause with UPON, RESET and a repeated SUM keyword is in COBOL 1985, and its ROUNDED phrase is in COBOL 2002. Annex E of 2023 lists no report writer change from 2014.

- §2023:13.18.54.2 (checked): "[ <u>UPON</u> { data-name-2 } … ]"
- §2023:13.18.54.2 (checked): "<u>RESET</u> ON"
- §2023:13.18.54.3 (checked): "The whole clause is referred to as a SUM clause even though the SUM keyword may appear more than once"
- §2023:13.18.54.3 (checked): "The ROUNDED phrase may be specified in the SUM clause only if the COLUMN clause is specified for the subject of the entry"
- §2023:13.18.54.3 (checked): "If the current report group is a control footing, its level of control shall be a lower level than that of data-name-3"
- §2023:13.18.54.4 (checked): "It is permissible for the UPON phrase to contain two or more instances of data-name-2 that specify the same detail"
- §2023:13.18.54.4 (checked): "If an UPON phrase is specified, whenever any GENERATE statement is executed for a detail referenced by the UPON phrase"
- §2023:13.18.54.4 (checked): "if the RESET phrase is specified, at the end of the processing of the control footing for the specified level of control"

## Our compiler

WiseOwl COBOL (fresh judge, `cobol sumf.cob --std 2014 --source-format free -o sumf.dll`) compiles it with no diagnostic. `dotnet sumf.dll` exits 0, and sumf.out holds `12`, `12`, `024` and `    048 034 024`.

## Fix site

cobc/parser.y `sum_clause_list` (line 9519 of the 3.2 source) is `SUM _of report_x_list _reset_clause`, and `_reset_clause` is EITHER `RESET _on data_or_final` OR `UPON identifier` (one identifier), never both. A second `SUM OF` in the entry reaches `check_repeated ("SUM", ...)` and is reported as a duplicate clause. No rounded phrase follows. `report_x_list` is a list of `arith_x`, so an arithmetic-expression addend is refused too.

## Draft issue

**Title:** Report Writer SUM clause: accept UPON with RESET, several UPON details, repeated SUM and ROUNDED

As posted (owner-reviewed, 2026-11-04):

The Programmer's Guide (6.9.40 SUM) documents `SUM OF {identifier|literal}... [RESET ON ... | UPON identifier]`, which is what cobc accepts; ISO allows more. We would like cobc to accept four standard forms of the report writer SUM clause that it refuses today: RESET after an UPON phrase, an UPON phrase naming the same detail twice, a second SUM keyword in one clause, and ROUNDED.

### What happens

3.2.0 and 3.3-dev r5751 both print

~~~~
sumf.cob:21: error: syntax error, unexpected RESET, expecting DISPLAY or DISPLAY-1 or NATIONAL or UTF-8
sumf.cob:23: error: syntax error, unexpected Identifier, expecting DISPLAY or DISPLAY-1 or NATIONAL or UTF-8
sumf.cob:24: error: duplicate SUM clause
sumf.cob:25: error: syntax error, unexpected ROUNDED, expecting DISPLAY or DISPLAY-1 or NATIONAL or UTF-8
~~~~

and the same with `-std=default` and `cobol2002`.

### What should happen

We ask that cobc accept the clause as the standard writes it. ISO/IEC 1989:2023 13.18.54.2 writes the clause as `{ SUM OF addend ... [ UPON { data-name-2 } ... ] } ... [ RESET ON { data-name-3 | FINAL } ] [ rounded-phrase ]`, and 13.18.54.3 rule 1 says "The whole clause is referred to as a SUM clause even though the SUM keyword may appear more than once." By 13.18.54.4 rule 7, an UPON addend is added only when a detail it names is generated, once per naming; by rule 2, a counter with RESET is reset only at the footing for the level it names. With these forms the program would compile, and `sumf.out` would hold `12` twice, the WS-K footing `024`, and the final footing `048 034 024`. The same in 2002 (with `[ ROUNDED ]`) and in the 2014 FCD.

### Why it happens

In `cobc/parser.y`, `sum_clause_list` is `SUM _of report_x_list _reset_clause`, and `_reset_clause` is either `RESET _on data_or_final` or `UPON identifier`: one SUM phrase, one UPON name or a RESET, no ROUNDED, and no expressions in `report_x_list`. A second SUM is a second clause to `check_repeated`.

### Proposed fix

We have no patch: the fix is wider than the grammar. Each SUM phrase needs its own UPON list, repeats kept; each counter needs its RESET level and a ROUNDED flag, so new members in `cob_report_sum` and `cob_report_sum_ctr`.
