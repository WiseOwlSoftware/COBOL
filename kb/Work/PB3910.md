# PB3910 — function-reference-modification-refused--refmod-flag-off: FUNCTION CHAR (66) (1:1): 'cannot have reference modification' for standard alphanumeric functions

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S6) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\function-reference-modification-refused--refmod-flag-off.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\function-reference-modification-refused--refmod-flag-off\`.

## Summary

GnuCOBOL 3.2 refuses reference modification of several standard alphanumeric intrinsic functions with
`FUNCTION 'CHAR' cannot have reference modification`. The standard allows reference modification of every
alphanumeric, boolean or national function. The refusal comes from a per-function flag in cobc's function table that
is off for these entries; among the functions of the 2014 edition it is off for CHAR, LOCALE-COMPARE, EXCEPTION-FILE,
EXCEPTION-LOCATION, EXCEPTION-STATEMENT and EXCEPTION-STATUS (and for CHAR-NATIONAL, EXCEPTION-FILE-N,
EXCEPTION-LOCATION-N and STANDARD-COMPARE, which 3.2 does not implement). Class: rejects legal ISO source. Split from
`function-reference-modification-refused` (the parse error that hides this check for the no-argument functions).

## Observed result

`fcharrm.cob`, all three commands, exit code 1:

```
fcharrm.cob:4: error: FUNCTION 'CHAR' cannot have reference modification
```

`q-LOCALE-COMPARE.cob`, exit 1: `error: FUNCTION 'LOCALE-COMPARE' cannot have reference modification`.
`paren.cob`, exit 1: `error: FUNCTION 'EXCEPTION-LOCATION' cannot have reference modification` and the same for
EXCEPTION-STATUS. `FUNCTION UPPER-CASE ("ab") (1:1)` compiles and prints `[A]` (its flag is on). The `()` form of
`paren.cob` is not in the general formats of these functions (§15.33.2 shows no parentheses), so it only shows that
the same flag is off for them; the CHAR program alone carries the claim (refuter's caveat).

## Expected result (per ISO)

The program is legal. CHAR(66) is the character in ordinal position 66 of the program collating sequence, `A` in the
native ASCII set GnuCOBOL uses, so it prints `[A]`.

- §8.4.3.3.3 2) (checked): "If identifier-1 is a function-identifier, it shall reference an alphanumeric, boolean, or
  national function."
- §8.4.3.3.3 5) (checked): "Unless otherwise specified, reference modification is allowed anywhere an identifier
  referencing a data item of class alphanumeric, boolean, or national is permitted."
- §15.15.1 (checked), CHAR: "The type of this function is alphanumeric." §15.51.1 (checked), LOCALE-COMPARE: "The
  function type is alphanumeric." §15.32.1 and §15.33.1 (checked), EXCEPTION-STATEMENT and EXCEPTION-STATUS: "The type
  of the function is alphanumeric." No function definition in clause 15 forbids reference modification of its result.

Edition: 2014. The 2009 committee draft that became ISO/IEC 1989:2014 (CD 1.2) has the reference-modification syntax
rule 2 with the same text (8.4.2.3.2 there) and defines CHAR (15.14), LOCALE-COMPARE (15.47), EXCEPTION-STATEMENT
(15.29) and EXCEPTION-STATUS (15.30).

Edition as recorded by the adjudicator: 2014. `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Our compiler (WiseOwl)

WiseOwl COBOL (built from main 6ed90bd1c), `cobol fcharrm.cob --std 2014 --source-format free -o fcharrm.dll`, then
`dotnet fcharrm.dll`: compile exit 0, run exit 0, output `[A]`. LOCALE-COMPARE: `[=]`. `paren.cob`: `[ ]`, `[  ]`.

## Fix site (GnuCOBOL 3.2 source, read observationally)

- `cobc/reserved.c`, `function_list`: each entry's last field is the reference-modification flag. It is 0 for the
  standard alphanumeric functions named above (and for BIT-OF, BIT-TO-CHAR, HEX-OF, HEX-TO-CHAR and the MODULE-*, MONETARY-*
  and NUMERIC-* functions, which are not in ISO/IEC 1989:2023 and are outside this record), 1 for the other alphanumeric and national functions.
- `cobc/tree.c`, `cb_build_intrinsic`: refuses any reference modifier on a function whose flag is 0 with the
  `cannot have reference modification` error. For a standard function the flag should follow the function's type
  (alphanumeric, boolean or national allows it, per 8.4.3.3.3 2)).

`cb_build_intrinsic` in cobc/tree.c refuses on it.
