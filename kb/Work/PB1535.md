# PB1535 — OWNER

## The question

**How shall an A.1 item whose determination is fixed by the code but absent from §7 be recorded?**

## Why it cannot be recorded as adjudicated

The two adjudication waves (PB1522) produced verdicts for 126 `DOC-A.1-*` rows that are neither NEEDS-OWNER-DECISION nor R42
withdrawals: 76 DIVERGES · 26 PARTIAL · 14 CONFORMS · 10 NOT-IMPLEMENTED. They sit,
shape-valid (`record_verdicts.py --dry-run` passes: GAP 1664 → 1653), in `adjudication/registrar-1/batch-doc.json` on branch
`claude/adj-registrar-1`. Two facts of the schema collide with them:

1. `tests/version-matrix/inventory-schema.json` defines DIVERGES on a kind-DOC row as "§7 documents one thing and the compiler does
   another". For 112 of the 116 CONFORMS/PARTIAL/DIVERGES rows §7 has NO row at all; the adjudicators' brief told them to call a missing
   determination DIVERGES, which the schema's own meaning does not allow.
2. `Schema.anchor_obliged` makes EVERY DOC verdict except DOCUMENTED-NON-SUPPORT carry `docs/CONFORMANCE.md#DOC-A.1-N`, and
   `SpecTraceabilityInventoryDriftTests.UnresolvedCodeLocations` requires that word to exist in docs/CONFORMANCE.md.

**Measured** (registrar-1 step 2; `adjudication/registrar-1/doc-trial-gate.txt`): `batch-doc.json` applied for real, `dotnet build
CobolSharp.sln -c Debug` green, then the filtered gate
`SpecTraceabilityInventory|DefectiveRowCoverage|DerivedVerdict|AnnexA1|WorkRegister` → **Failed 4, Passed 46 (of 50)**:

- `EveryCodeLocation_ResolvesInTheTree` — **122** unresolved code-locations, every one the computed anchor of a DOC row whose item has
  no §7 row ("is no longer in that file");
- `AnnexA1RegisterDriftTests.EveryVerdictedDocRow_HasItsRegisterDetermination` — 122 items verdicted with no §7 row;
- `AnnexA1RegisterDriftTests.EveryDocRow_IsFiledUnderTheItemAnnexA1Names` — 14 rows closing on tests while §7 carries no row
  (35, 94, 104, 118, 119, 125, 138, 154, 155, 170, 192, 193, 194, 201);
- `DefectiveRowCoverageDriftTests` — 111 defective rows unclaimed (a registration gap, closed by this registrar's notes; not part of
  the question).

The inventory was restored afterwards; nothing of `batch-doc.json` is recorded.

## Options

- **(a) Write the §7 rows first (PB1522 step 3), then record `batch-doc.json`.** Every anchor then resolves and every audit finding
  clears. Caveat: a row whose ONLY defect was the missing determination becomes CONFORMS the moment its §7 row is written, so "as-is"
  would record a stale DIVERGES — the rows would have to be re-verdicted from their evidence (in each record's notes) as the §7 rows
  land, item by item. The residual DIVERGES/PARTIAL are the ones with a behavioural defect (PB1527, PB1529–PB1533, and the owning
  notes' mechanisms).
- **(b) Make NOT-IMPLEMENTED / NEEDS-OWNER-DECISION register-decided anchor-exempt, like DOCUMENTED-NON-SUPPORT**, and re-verdict the
  "no §7 row" DIVERGES as NOT-IMPLEMENTED (the determination — the documentation — is not implemented). The rows record now, the gate
  stays green, the burn-down does not move (NOT-IMPLEMENTED is still GAP), and `DefectiveRowCoverage` holds them to their notes.
  Costs a schema change in both readers (`inventory_schema.py`, the C# `Schema`) plus its drift case.
- **(c) Leave the DOC rows verdict-less.** The §7 audit (`audit_annex_a1.py`) already counts every one of them open, the evidence is
  preserved in `batch-doc.json` and the owning notes (PB1534 + the notes `owners_map.py` names), and the verdicts are recorded when
  (a)'s rows land.

**Registrar's recommendation: (c) now, closing through (a) item by item** — each §7 row lands WITH its re-verdicted inventory
record in the same commit, so no anchor is ever recorded before it resolves, no stale DIVERGES is written, and no schema exemption is
invented for a verdict whose meaning (b) would bend. (b) is the right choice only if the owner wants the verdict-less count (133 A.1
rows once `batch-r42.json` is recorded) to fall before the §7 writing does.

## Sub-case the anchor rule gets wrong regardless of the answer: "need not be documented" but CONFORMS

A.1 marks some items as NOT requiring user documentation ("This item need not be documented in the implementor's user documentation" —
`cite.py --check A.1 "This item need not be documented in the implementor's user documentation"` → OK §A.1 35), or "does not have
to be documented"). `anchor_obliged` still obliges such a row's §7 anchor for CONFORMS/PARTIAL/DIVERGES, so a CORRECT CONFORMS can
close only by writing a §7 row A.1 does not require. In this batch: **35, 69, 104, 118, 119, 125, 138, 169, 170, 194, 201, 220** (all
CONFORMS; 69, 169, 220 are also test-needed), plus the PARTIAL/DIVERGES 63 and 113. Does the owner want (i) a voluntary §7 row for each
(the current rule), or (ii) the anchor obligation keyed on the item's documentation duty (the catalog already carries the A.1 text), so
these close on their witness alone?
