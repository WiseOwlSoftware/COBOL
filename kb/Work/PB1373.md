## Finding — cobol-words-directive (rejects-legal-source)

SR3/SR4 word-category tests are keyed on the LEXER vocabulary and the all-edition §8.9 table instead of the 2023 populations (§8.9 reserved at 2023 ∪ §8.10 ∪ §8.11): IsExistingWordCategory accepts any CobolKeywordTokens keyword or any ReservedWords row regardless of edition (under-reject), and IsReservedCategory rejects any CobolKeywordTokens keyword regardless of edition (over-reject). The directive exists only at 2023, so the only correct population is the 2023 one.

**Rows:** SR-7.3.10.3-3, SR-7.3.10.3-4

**Repro:**

```
>>COBOL-WORDS RESERVE "AUTHOR" -> COBOLNET1623 'the new word AUTHOR is a reserved ... word' (rejects legal). >>COBOL-WORDS UNDEFINE "AUTHOR" and >>COBOL-WORDS EQUATE "MEMORY" WITH "RAM" -> compile clean (under-reject).
```

**Expected from the spec:** AUTHOR and MEMORY are not in the 2023 §8.9 reserved-word list, not §8.10 context-sensitive words and not §8.11 intrinsic names (tests/version-matrix/reserved-words.json r2023=false). §7.3.10.3 SR4 therefore permits RESERVE "AUTHOR" (a well-formed data-name) and SR3 forbids UNDEFINE "AUTHOR" / EQUATE "MEMORY" -> both should be COBOLNET1623.

**Observed:** Probes sr4_author_new (1623), sr3_author and sr3_memory (clean). The code comment calls the asymmetry 'the no-false-reject principle', but SR4 as coded does false-reject.

**Code site:** src/Cobol.Net.Compiler/Validation/VersionConformancePass.cs#IsExistingWordCategory; #IsReservedCategory

## Finding — cobol-words-directive (rejects-legal-source)

The frontend's SR4 user-word form check (CobolWordsDirectiveProcessor.UserWord) hand-rolls a stale §8.3.2 word shape instead of the real one: it forbids underscore, requires only 'a letter OR digit' instead of at least one letter, and has no 63-character limit.

**Rows:** SR-7.3.10.3-4

**Repro:**

```
>>COBOL-WORDS EQUATE "DISPLAY" WITH "MY_SHOW" / MY_SHOW "X" -> COBOLNET1623 'MY_SHOW is not a valid user-defined word' (rejects legal). >>COBOL-WORDS RESERVE "123" -> clean. >>COBOL-WORDS RESERVE "<64-character word>" -> clean.
```

**Expected from the spec:** §8.3.2.1: a COBOL word is 'not more than 63 characters', characters from letters, digits, extended letters, 'hyphen and underscore', neither first nor last; §8.3.2.2: a data-name 'shall contain at least one basic letter or extended letter'. So MY_SHOW is legal (displays X), and '123' and the 64-character word are COBOLNET1623.

**Observed:** Probes underscore_new, digits_only_new, long_new. UserWord: word.All(c => char.IsLetterOrDigit(c) || c == '-') && word.Any(char.IsLetterOrDigit), no length test.

**Code site:** src/Cobol.Net.Frontend/Preprocessor/CobolWordsDirectiveProcessor.cs#UserWord

## Finding — cobol-words-directive (under-rejects)

The directive operand tokenizer accepts an unterminated quoted operand as a literal (ReadQuoted returns end-of-string when the closing quote is missing and emits a Literal token anyway).

**Rows:** SR-7.3.10.3-2

**Repro:**

```
>>COBOL-WORDS RESERVE "FOO   (no closing quote) -> compiles and runs clean; FOO is reserved.
```

**Expected from the spec:** §7.3.10.3 SR2: 'Each literal shall be an alphanumeric literal'; an operand with no closing delimiter is not an alphanumeric literal -> COBOLNET1623.

**Observed:** Probe unterminated: rc=0, ACCEPTED-UNTERM.

**Code site:** src/Cobol.Net.Frontend/Preprocessor/CobolWordsDirectiveProcessor.cs#ReadQuoted

**Observed:** Probe sr1_synonym_id rc=0; control sr1_after_id_before_pid (spelled IDENTIFICATION) -> 1623.

**Code site:** src/Cobol.Net.Frontend/Preprocessor/CobolWordsDirectiveProcessor.cs#Process (sawFirstIdDivision); src/Cobol.Net.Frontend/Preprocessor/CompilationUnitStart.cs#IsAt

## Row FMT-7.3.10.2 — PARTIAL (adjudicator + refuter record)

Format: >>COBOL-WORDS { EQUATE literal-1 WITH literal-2 | UNDEFINE literal-3 | SUBSTITUTE literal-4 BY literal-5 | RESERVE literal-6 } (cite.py OK §7.3.10.2). TryParseOption switches on exactly one of the four option words (case-insensitive); TryBinary demands exactly 4 tokens with WITH/BY in slot 3 (wrong join word rejected), TryUnary exactly 2 tokens; any other shape is COBOLNET1623. Probed: all four options accepted, lowercase '>>cobol-words equate ... with ...' accepted (probe lower_kw), apostrophe-quoted literals accepted (apos_lit), unknown option / missing WITH / BY-for-WITH / no option rejected (unit theory). Literal-content defects are SR2/SR4 rows, not the format. || REFUTED: PARTIAL — The four options, join words and arity are parsed correctly, but the operand tokenizer only splits on whitespace: a separator comma or semicolon between elements (legal anywhere a separator space is, §5.2.8 / §8.3.5 SR2) is rejected with COBOLNET1623, so legal source is rejected; and an UNTERMINATED quoted literal (no closing quote) is silently accepted as literal-6 (ReadQuoted returns end-of-string) instead of being diagnosed as a malformed literal.

**Code location:** src/Cobol.Net.Frontend/Preprocessor/CobolWordsDirectiveProcessor.cs#CobolWordsDirectiveProcessor.TryParseOption; src/Cobol.Net.Frontend/Preprocessor/CobolWordsDirectiveProcessor.cs#CobolWordsDirectiveProcessor.TryBinary; src/Cobol.Net.Frontend/Preprocessor/CobolWordsDirectiveProcessor.cs#CobolWordsDirectiveProcessor.TryUnary
