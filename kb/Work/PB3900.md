# PB3900 — floating-point-edited-picture-not-implemented--editing: GnuCOBOL 3.2: floating-point numeric-edited PICTURE (9.99E+99) compiles without diagnostic but MOVE to it is not implemented ("invalid PIC character E")

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S5) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\floating-point-edited-picture-not-implemented--editing.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\floating-point-edited-picture-not-implemented--editing\`.

## Summary

cobc 3.2 accepts a floating-point numeric-edited PICTURE (`9.99E+99`) under `-std=cobol2014` without any diagnostic and
generates a MOVE to it, but libcob's edited-move routine has no handling for the `E` symbol: at run time it prints
"libcob: error: cob_move_display_to_edited: invalid PIC character E" on stderr, stores digits that are neither the
significand nor the exponent, and the program continues with exit code 0. The item's size is also wrong (7, not 8);
that is the sibling record `floating-point-edited-picture-not-implemented--size`.

## Minimal test case

Free reference format (`-fformat=free`), `records/floating-point-edited-picture-not-implemented--editing.cob`:

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. FPEMOVE.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 V PIC 9(3)V99 VALUE 123.45.
01 F PIC 9.99E+99.
PROCEDURE DIVISION.
    MOVE V TO F
    DISPLAY "[" F "]"
    STOP RUN.
```

## Environment

- `cobc (GnuCOBOL) 3.2.0`, Ubuntu package `gnucobol3 3.2-4build1`, WSL2 Ubuntu on Windows 11.
- `cobc -std=cobol2014 -fformat=free -x -o fpemove fpemove.cob && ./fpemove`
- Witnesses: n5-fz03807 (`MOVE 123.45 TO PIC 9.99E+999` printed `3.450000`), n3-fz04593.

## Observed result

cobc exit 0, no diagnostic (only the toolchain's `_FORTIFY_SOURCE redefined` warning). Run, exit 0:

```
[3.45000]
libcob: error: cob_move_display_to_edited: invalid PIC character E
```

(the second line on stderr).

## Expected result (per ISO)

ISO/IEC 1989:2023, each citation checked with `scripts/spec/cite.py --check`:

- §13.18.40.4 rule 13) b): "To define a floating-point numeric-edited item, characters-string-1 shall consist of two
  parts, separated without any spaces, by the symbol 'E'. The first part represents the significand; the second part
  represents the exponent." "The exponent shall be '+9', '+99', '+999', '+9999', or '+9(n)' where n = 1, 2, 3, or 4."
  `9.99E+99` is a valid floating-point numeric-edited PICTURE.
- §14.6.8.4 rule 1): "If the algebraic value of the sending operand is not zero, the exponent and significand of the
  value are adjusted such that the most significant digit of the significand is not zero." Rule 2): "Alignment and
  zero fill or truncation take place as described in the general rules and editing rules in 13.18.40".

123.45 is 1.2345E+2; the significand `9.99` keeps 1.23 (truncation, no ROUNDED); the exponent `+99` edits as `+02`.
Expected output `[1.23E+02]`.

Edition: the floating-point numeric-edited PICTURE was introduced in ISO/IEC 1989:2002 (WiseOwl's edition registry
row `pic-external-float-2002`, citing §13.18.40.4 GR13 b) and §14.6.8.4), so it is part of the 2014 edition that
`-std=cobol2014` claims.

Edition as recorded by the adjudicator: 2014. `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Class

Compiles but not implemented at run time (wrong output with only a run-time error message on stderr, exit 0).

## Our compiler (WiseOwl)

`cobol.exe fpemove.cob --std 2014 --source-format free -o fpemove.dll`: exit 0; `dotnet fpemove.dll`: `[1.23E+02]`,
exit 0.

## Fix site (GnuCOBOL 3.2 source, read observationally)

- `libcob/move.c`, function `cob_move_display_to_edited` (line 878): the editing loop has no case for `E` or for the
  exponent; `E` reaches the default arm (lines 1069-1077), which reports "invalid PIC character" and writes `?`. No
  normalisation of the significand or computation of the exponent exists anywhere in libcob.
- `cobc/tree.c`, function `cb_tree_type` (lines 1595-1597): `CB_CATEGORY_FLOATING_EDITED` is mapped to
  `COB_TYPE_NUMERIC_EDITED`, so the run time treats the item as fixed-point numeric-edited.
- `cobc/tree.c`, function `cb_build_picture`, `case 'E'` (lines 3782-3787) classifies the PICTURE as floating-point
  edited without a "not implemented" diagnostic.

A fix implements a floating-point edited move in libcob (or, until then, has cobc refuse the PICTURE with a "not
implemented" error instead of compiling it).
