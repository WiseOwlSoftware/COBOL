# PB344 — one compiler with a hole where four editions should be

**Rows:** `GR-14.9.30.4-L2.3`, `GR-14.9.30.4-28`, `GR-14.9.49.4-6`. Three subjects found three instances of one
mechanism: an Annex E behaviour change landed as the ONLY behaviour, with no edition conditioning anywhere on the
path.

## Instance 1 — READ PREVIOUS after OPEN on an indexed file (E.2 item 22)

`out-b1/probe/p4x-idx/p4xidx.cob` case C — an INDEXED file with four records; `OPEN INPUT` then
`READ F PREVIOUS RECORD ... AT END ... NOT AT END`. Compiled and run twice, at the default and at
`--std 2014`: **both print `ATEND FS=10`; the outputs are byte-identical.**

Annex E.2 item 22 states the change: *READ PREVIOUS statement following an OPEN statement. Ensure that an at end
condition occurs*, with the justification *the rule itself stated that the first record would be retrieved. The
rule itself has been amended such that an at end condition would occur.* So the 2023 rule d.3 is right for
`--std 2023`, and under `--std 2002`/`2014` the pre-amendment rule applies and the first existing record is
retrieved. `IndexedConnector.ReadSequential:242-243` carries no dialect predicate and no edition parameter
reaches the connector; `RelativeConnector`'s twin comment already calls the `<=2014` gate *a noted deferral*, and
`docs/VERSION_CHANGE_REFERENCE.md` row 29 carries the `gate-behavior-by-dialect <!-- todo -->` marker that
session-probe counts — so the gap is tracked MECHANICALLY while no work note owned it and the traceability row
read as covered. It has an owner now.

**Caveat that bounds the fix:** Annex E is informative and the pre-2023 normative wording is not in
`specs/ISO_COBOL.md`, so the `<=2014` expected result cannot be derived from this document beyond E.2's own
account of it. Recovering the exact prior rule (blame → the commit's `specs` gitlink → `git -C specs-private
show <sha>:ISO_COBOL.md`) is part of the work, and if the prior text is genuinely self-contradictory — E.2 says a
note conflicted with the rule — the disposition is an owner decision rather than a straight gate.

## Instance 2 — INVALID KEY processing and the open-mode declarative (E.2 item 19 a)

§14.9.30.4 GR28 ends *(See 9.1.14, Invalid key condition.)*, and that incorporated contract is
edition-differentiated. Annex E.2 item 19 a) states, of the changes between the previous standard and this one:
*INVALID KEY processing. If an INVALID KEY phrase is not specified and an invalid key condition occurs, any
declarative that specified INPUT, OUTPUT, I-O, or EXTEND would not have been executed. It will now be executed.*
So under 1985/2002/2014 an OPEN-MODE declarative shall NOT run for GR28's condition when no INVALID KEY phrase is
written. COBOL.NET runs it in all four editions. The mechanism is structural, not incidental:
`DispatchEmitter.__IoCheck` short-circuits only on the statement's own phrase
(`if (__invKey && __st[0] == '2') return;`) and then falls through the file-name scope into the open-mode scope
switch with **no edition conditioning anywhere in the file**. GR28's own sentence, its status '23' and its
INVALID KEY transfer are all correct — this is the incorporated half.

## Instance 3 — the USE mode-scope tiers at every edition (§14.9.49.4 GR6 b-e)

The same absent conditioning, reached from the other end: GR6 b-e's 2023 form is applied at every edition because
there is no edition gate anywhere on the mode switch, so at `--std 85`/`2002`/`2014` a mode-scoped declarative
fires where E.2 item 19 a/b says the previous standards did not. GR6 a-e are otherwise implemented and were
verified.

## The fix shape

The three instances share one absent seam: **no edition reaches the runtime connectors or the generated
dispatch hooks at all.** Adding a predicate at each of the three sites is the smallest diff and the wrong shape —
it is the third instance already. The durable answer is to make the compilation edition a property the emitted
unit carries (the `ConstructRegistry` already knows every construct's introducing edition), so a behaviour that
differs by edition is written once against that property, and a drift test asserts that every
`VERSION_CHANGE_REFERENCE` row marked `gate-behavior-by-dialect` has a live predicate. That is also what would
retire the `<!-- todo -->` markers session-probe counts.

**Code sites:** `IndexedConnector.cs#ReadSequential` (lines 242-243) · `RelativeConnector.cs#ReadPrevious` ·
`DispatchEmitter.cs#EmitUseMachinery` (`__IoCheck`) · `docs/VERSION_CHANGE_REFERENCE.md` row 29.

## Landed — 2026-09-13: the compilation's ISO edition reaches the connectors and the USE selector

All three instances are one absent seam and it is now present, in the durable shape rather than three
predicates.

**The register.** `src/Cobol.Net.Runtime/Control/DialectBehavior.cs` is the BEHAVIOUR twin of
`CobolNet.Editions.ConstructRegistry`: a construct row answers *does this edition HAVE this construct?* and
yields a diagnostic; a `DialectBehavior` member answers *which edition's RULE does this construct obey?* and
yields an ANSWER — and no diagnostic can carry the second, because the source is legal at every edition. It
lives in the RUNTIME (the `SignEncoding` precedent) because both sides read it: the emitter folds a
compile-time-decided behaviour, the connectors ask at run time. Three members today —
**ONE** member — `IndexedReadPreviousAfterOpenAtEnd` (VCR row 29) — naming its VCR row, its normative
clause and its Annex E item. Two more were implemented and then WITHDRAWN; see "The correction" below, which
is also where the register's ADMISSION TEST is written down.

**The edition reaches the runtime.** `FileConnector.Edition` (default 2023) is set at registration, per
CONNECTOR — a run unit may link programs from separate compilations, and the rule governing a file's records
is the one the source element that DESCRIBED it was compiled under. `RuntimeApi.FileRegister`,
`FileRegisterRelative` and `FileRegisterIndexed` each take a REQUIRED `int edition` and render a trailing
`edition:` named argument, fed `ctx.Data.Edition.DialectLevel` by both registration emitters.

**Instance 1** (`IndexedConnector.SelectSequentialRecord`): the at-end arm is now conditioned on the one
predicate, and below 2023 the after-OPEN arm is direction-blind. MEASURED before: `--std 2023/2014/2002` all
printed `ATEND FS=10`. MEASURED after: 2023 `ATEND FS=10`; 2014 and 2002 `GOT K001 AAAAAA FS=00`. The ≤2014
answer is derived from Annex E.2 item 22's justification (the prior rule retrieved the first record), the
ISO/IEC Directives Part 2 (the conflicting prior NOTE states no requirement) and Annex E.2's own purpose (the
list of SUBSTANTIVE changes would carry no item 22 had the prior behaviour already been at end) — so the
note's "possibly an owner decision" escape did not fire.

**Instances 2 and 3** were ONE duplicated dispatch — and it had THREE arms, not the two the note and the
predecessor's sweep found: `DispatchEmitter.__IoCheck`, `EcEmitter.__IoCheckEc` and `ProgramEmitter`'s GR4 b)
outward GLOBAL walk `__RunGlobalUse` each rendered their own copy of the GR3 a)/GR5 file-name switch and the
GR3 b)/GR6 b)–e) open-mode switch. All three now call `CodeGen/UseTierEmitter`, so the tier pair is written
ONCE and a fourth selector cannot drift from it. **The per-edition GUARD that first landed inside that emitter
is gone — see "The correction".** The SORT/MERGE USING hook carries a defect of its own (it reads the
implicit CLOSE's status, so a retrieval failure reaches no declarative at all); it is recorded at its site and
is not this note.

**Verified.** Twelve spec-derived goldens whose expected values were computed from the rules BEFORE the first
run and matched on it: `pb344_read_previous_indexed` (2002/2014/2023), `pb344_use_mode_invalid_key` and
`pb344_use_mode_read_exception` (85/2002/2014/2023 each), `pb344_use_f3_perform_preempt` (2023 — GR6's
leading exception-checking-PERFORM clause, which had no test at all). The two `use_mode` programs’ four copies
are now byte-identical BY DESIGN and that identity IS the assertion (see "The correction").
`DialectBehaviorRegistryDriftTests` bolts the registry to `docs/VERSION_CHANGE_REFERENCE.md`, whose row 29
carries the `<!-- behavior:id -->` anchor — a behaviour change can never be a `constructs.json` row, so
`gate:` could not have named it — instead of `<!-- todo -->`; rows 25 and 26 are `<!-- ref-only -->`. Rows
`GR-14.9.30.4-L2.3`, `GR-14.9.30.4-28` and `GR-14.9.49.4-6` re-verdicted PARTIAL → CONFORMS.

## The correction — 2026-09-13, second finisher: the Annex E.2 item 19 a)/b) gate was WITHDRAWN, and the register grew an admission test

The first finisher's branch was GREEN on its own wave-local gate and was **dropped by the train-29 lander**:
`bash scripts/push-main.sh` produced CI run `34755793553`, conclusion `failure`, with FIVE NIST CCVS programs
red — `SQ122A`, `SQ136A`, `SQ137A`, `SQ138A`, `SQ148A`. The lander bisected it by cluster and attributed it
to PB344 unambiguously. The filter was the proximate lesson (`NistDifferentialTests` matched none of the 25
terms the five implementer reports named), but the gate was the actual defect.

### What the five programs assert

The NIST harness compiles at **`--std 85`** (`NistDifferentialTests.NistStd`, default 85), exactly where the
guard was active. All five are sequential-I/O CCVS programs with an OPEN-MODE `USE` declarative:

| program | the operation | the declarative it requires to run |
| --- | --- | --- |
| `SQ122A`, `SQ136A`, `SQ137A`, `SQ138A` | a READ after the at end condition → '46' | `USE AFTER EXCEPTION PROCEDURE INPUT` |
| `SQ148A` | a READ on a file open OUTPUT → '47' | `USE AFTER STANDARD EXCEPTION PROCEDURE OUTPUT` |

`SQ137A` states the requirement in its own failure text: `SEQ-TEST-RD-07.02 READ AFTER AT END FAIL*` with the
remark **"INPUT DECLARATIVE NOT EXECUTED"**, `COMPUTED = NOT EXECUTED`, `CORRECT = EXECUTED`, against
`VII-2,1.3.5, VII-51,4.6.4(5)` — ANSI X3.23-1985's USE statement rules. Note also that `SQ148A`'s declarative
specifies **OUTPUT**, which item 19 b) ("any declarative that specifies INPUT or I-O") never named: the
implemented guard was over-broad on its own terms as well.

### The derivation, from the standard

1. **Annex E is INFORMATIVE** (`## Annex E` / `(informative)`); it states no requirement.
2. **§E.1 scopes it to ONE prior edition** — *"This annex contains a list of the substantive changes between
   the previous COBOL standard and this Working Draft International Standard"* (`cite.py --check E.1` PASS).
   The Introduction names that standard as the 2014 one. E.2 therefore says **nothing at all** about the 1985
   or 2002 editions, and the guard was applied to all three.
3. **Item 19's own justification classes the prior state as defective TEXT, not as a required behaviour** —
   *"The previous COBOL Standard was not clear or missing processing of some I-O exceptions. This change
   clarifies or corrects that processing"* (`cite.py --check E.2` PASS), each sub-item adding *"This appears to
   be an error in previous standards."* (b) / *"...in previous COBOL standards."* (a). A silence is not a
   prohibition; where a prior standard is silent this project follows the model implementations (owner standing
   decision 2026-08-30), all of which execute the declarative — which is precisely what CCVS-85 certifies.
4. **For 1985 the behaviour is positively fixed the other way** by that edition's own validation suite, in the
   five programs above.

So the item 19 a)/b) guard is underivable at 1985 and 2002 and refuted at 1985. **Both halves were
withdrawn**: `DialectBehavior.InvalidKeyRunsOpenModeDeclarative` and `ReadExceptionRunsOpenModeDeclarative`
are deleted (not left dead), `UseTierEmitter.ModeTierEditionGuard` / `ModeTierGuardNote` / `Conjoin` with
them, and the `__read` / `isRead` / `__modeTier` plumbing that existed only to feed the guard is gone from
`__IoCheck`, `__IoCheckEc`, `__RunGlobalUse` and `SequentialIoEmitter.EmitUseHook`. The six `use_mode` `.out`
files at 85/2002/2014 moved to the 2023 layout — derived, not observed: with GR6 b)–e) edition-invariant
every edition produces the 2023 sequence — and the corpus matched all six on the first run.

**Item 19 a) went with b) even though no NIST program tests it** (measured: no `IX*` program has an open-mode
declarative, and of the only `RL*` ones that do, `RL113A`/`RL114A` test mode-MISmatch non-invocation and
`RL115A`/`RL116A` test at end and a WRITTEN `INVALID KEY` phrase). The two halves share one justification
paragraph and one "error in previous standards" sentence; keeping a) while b) is refuted would be enforcing a
lookup nothing had ever contradicted.

### The shape that makes the next case automatic

The register's ADMISSION TEST is now written on the `DialectBehavior` enum itself, in the
`VERSION_CHANGE_REFERENCE` legend beside the anchor kinds, and in `COBOLNET_FILES_DESIGN.md`: **an Annex E
item earns a `behavior:` anchor and a register member only when it says what the PRIOR RULE STATED.** Item 22
does (*"the rule itself stated that the first record would be retrieved"*) and keeps its gate; item 19 a)/b)
says only that the prior text was missing or unclear, and its rows are `ref-only`.
`DialectBehaviorRegistryDriftTests` keeps the register and the VCR rows in agreement in both directions, so
the test cannot be applied to one and not the other.
