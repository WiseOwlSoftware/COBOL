## Landed

Re-probed on the worktree build (fixed form, `--std` default): `>>IF 1 = 0 / >>TURN EC-NOSUCH CHECKING ON / >>END-IF` compiled clean, the same directive outside the `>>IF` gave COBOLNET0711, and `EC-EXTERNAL-FORMAT-CONFLICT` at `--std 2002` was clean in the omitted branch where the compiled twin gives COBOLNET0878. The note's reading was right, with one correction: the "Process comment" at the old lines 109-113 said `dialectLevel` fed the exception-name edition window, and it did not; it does now.

The fix is the target shape. §7.3.25.3 SR2 and the per-name edition window live in ONE place below both channels, `src/Cobol.Net.Editions/ExceptionNameRule.cs` (`TryGet`, `Window`; the front end cannot reference the binder). `TurnDirectiveProcessor.ParseTurn` asks it for every exception-name, so `Process` (compiled) and `CheckOperand` (omitted branch) report alike, and a refused name never enters the `TurnEvent`; the event carries the catalog's canonical spelling. `EcNameResolution.TryResolve` asks the same rule for its unknown-name and window checks, and `TurnState.Build` no longer reports 0711/0878: it asks only the policy half (`EcNameResolution.AdviseResolved` -> `Advise`: declined-module postures, the §15.33 width advisory), and throws on a name the stage did not resolve. Below COBOL-2002 the window is skipped (the directive is already COBOLNET0900).

Witnesses: `conformance:negative/pb2740-omitted-branch-turn-unknown-name` (2002/2014/2023, 0711), `conformance:negative/pb2740-omitted-branch-turn-name-below-2023` (2002/2014, 0878), positives `conformance:2002/pb2740_omitted_branch_turn_valid_names` and `conformance:2023/pb2740_omitted_branch_turn_2023_name`; unit `TurnDirectiveExceptionNameTests` (compiled/omitted parity) and `EcNameResolutionDriftTests.OutsideTheCompiler_TheSr2RuleIsExceptionNameRule` (the callers of the rule and of the catalog are pinned).

Sibling sweep: of the other directives with a stage-owned operand, FLAG-02/FLAG-14/COBOL-WORDS report the same operand-syntax codes compiled and omitted; the only differences are the obsolescence warning (COBOLNET0903) and the COBOL-WORDS placement rule (COBOLNET2652), which are not operand syntax.
