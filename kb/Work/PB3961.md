# PB3961 — COBOL2119's message spells a rewritten ZERO as '0' / 'ALL0': PERFORM VARYING X FROM 1 BY ZERO + 1 reports '0+1' is not one of the operands

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/ControlFlowBinder.PerformVarying.cs:206` (`BindVaryingOperand`), `src/WiseOwl.Cobol.Frontend/Parsing/WrittenSource.cs` (`Of`), `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs` (`WrittenText`; `AsWritten` deleted), `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.Reports.cs` (the former `AsWritten` callers), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/ArithmeticBinder.cs` (`Format1Receivers`, `RefuseNonBooleanComputeOperand`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/ConditionBinder.cs` (the boolean-operand refusals), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CallBinder.cs`, `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs`, `src/WiseOwl.Cobol.Compiler/Binding/Validation/SearchAllFormat2Rules.cs`

The PERFORM VARYING operand-shape screen that emits COBOL2119 builds its message from the operand's `GetText()`,
which carries the rewritten token text (`ZeroTokenRewriter`): `PERFORM VARYING X FROM 1 BY ZERO + 1` prints `'0+1' is not
one of the operands` and `BY ALL ZERO + 1` prints `'ALL0+1'`. Message quality only. Repros
`E:/COBOL-coord/scratch/w20261720b/p/YV.cob` and `ZV.cob`. The fix per the report is `ZeroTokenRewriter.WrittenWord` or a
source-span spelling; sweep every diagnostic that prints an operand's `GetText()` after the rewriter has run.

## Acceptance
- The message spells the operand as written (source span), golden expect text for both repros.

## Landed (wave 20261769, group F) - the message quotes the operand as written

**Re-probe** (`E:/COBOL-coord/scratch/w20261720b/p/YV.cob`, `ZV.cob`, base `802352531`): `'0+1' is not one of the operands`
and `'ALL0+1' is not one of the operands`, as filed.

**Mechanism.** `ZeroTokenRewriter` gives the `ZERO_ARITH` token the text "0" on purpose (readers of an arithmetic
operand parse its text: `IntegerOperandRules.TryHostValue(spec.length.GetText())`), so a diagnostic that quotes a node
with `GetText()` prints the rewritten token and glues every token besides (`ALL0+1`, `A+B`). The fix is at the quoting
sites, not the token: `WrittenSource.Of` (`DataBinder.WrittenText`) is the one "as the programmer wrote it" reader.

**Fix.** `BindVaryingOperand` quotes `WrittenSource.Of(op)` (`'ZERO + 1'`, `'ALL ZERO + 1'`, and every `Sr(from.Text, ...)`
rule of the same phrase). Sibling sweep (the 196 `{...GetText()}` message sites of the Compiler assembly, each read for a
receiver that can hold an arithmetic operand): the user-facing refusals that quote an expression or operand node now use
`DataBinder.WrittenText` too (ArithmeticBinder x4, ConditionBinder x5, CallBinder x2, IntrinsicBinder x1,
SearchAllFormat2Rules x5); the rest quote names, keywords and literals, which hold no ZERO. `DataBinder.AsWritten`, a
second copy of the same slice reader with a glued fallback, is deleted and its five callers use `WrittenText` (CLAUDE.md
rule 4).

**Goldens:** `conformance-suite/cases/14.9.28-PERFORM/pb3961-varying-by-zero-expression` and
`pb3961-varying-by-all-zero-expression` (refused at all four editions; each entry's `expect` is the message text).
