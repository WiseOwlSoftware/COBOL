# PB1762 — OPEN — raise-site declarations and the enabled set

## The rules (cite-checked)

| § / rule | Text | Consequence |
|---|---|---|
| §14.6.13.1.1 | "If checking for an exception condition is enabled and an exception status indicator is set as a result of an exception detected during the execution of a statement, the associated exception condition is raised" | The raise belongs to the DETECTION — an operand evaluated inside a condition, an argument, a subscript — never to a statement KIND. |
| §14.6.13.1.1 | "Therefore, when the general rules for a statement indicate that a specific exception condition exists, it is raised only if checking for that exception condition is enabled." | The statement's guard must carry every name its operands can raise, or the raise is silently lost. |
| §8.4.3.13.4 4) | "If the runtime system cannot locate the program, the EC-PROGRAM-NOT-FOUND exception condition is set to exist and the value of the address-identifier is the predefined address NULL." | Attached to the program-address-identifier OPERAND — wherever it is written (SET, CALL argument, INVOKE argument, relation operand). |
| §14.6.13.1.1 | "There are two types of level-3 of implementor-defined exception-names … The implementor defines the action to be taken, the fatality, and when any of these exceptions are raised." | The EC-IMP-*suffix* names exist only where the implementor DEFINES one — the name universe is closed (PB1531). |

## What the code does today

- `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/EcBinder.cs#EcWrap` → local `QueryFor`: a `switch` over bound-node
  KINDS (≈25 precise arms: `BoundSetEntry` → EC-PROGRAM-NOT-FOUND, `BoundCallProgram` → ProgramNames, `BoundGoback`
  → EC-FLOW-GLOBAL-GOBACK, …) plus an ambient tail (EC-SIZE, EC-BOUND-REF-MOD, EC-FLOW-USE, EC-LOCALE-*, …). Its own
  comments record five earlier instances of the SAME defect shape — a name whose raise site existed but which no arm
  queried, so `>>TURN … CHECKING ON` wrapped nothing: PB452 (SET … TO ENTRY), PB409 (GOBACK GR6), PB326 (report
  verbs), PB349/PB1036 (sort-merge), PB233 (function activation).
- `src/Cobol.Net.Compiler/CodeGen/Verbs/PtrEmitter.cs#ProgramAddressText` asks `ecState.Info` for
  EC-PROGRAM-NOT-FOUND; a relation operand's carrying statement (the IF) has no arm naming it, so the probe
  `p1453.cob` (`>>TURN EC-PROGRAM-NOT-FOUND CHECKING ON`, `IF ADDRESS OF PROGRAM "NOSUCHP" = NULL`) prints `REL-EQ /
  EC= (blank) / AFTER`, exit 0 — MEASURED 2026-09-30, the relation half of PB1453 still reproduces. `BoundInvoke`'s
  arm queries `OoInvokeNames`/`ExternalNames` only, so an INVOKE argument's program-address is the same hole (sibling,
  not yet probed).
- The ONE structural precedent already exists: `EcBinder.ContainsIntrinsic` walks `BoundStatementTree.OwnValueParts()`
  — GENERATED from the semantic model, pinned by `EcArgumentFunctionGateDriftTests` — so EC-ARGUMENT-FUNCTION rides
  every statement that carries a function reference, whatever its kind (the PB26 fix of exactly this shape).
- `src/Cobol.Net.Runtime/Exceptions/ExceptionCatalog.cs#TryGet` accepts ANY `EC-IMP-<valid suffix>` as a fatal
  level-3 name (PB1531 — `RAISE EXCEPTION EC-IMP-WIBBLE` compiles and terminates, MEASURED 2026-09-30), so the catalog
  is not a closed universe a drift test can enumerate.

## The proposed single structure

1. **Operand-declared raise names.** One walker, `EcBinder.OperandRaisableNames(BoundStatement)`, over
   `OwnValueParts()` (recursing into `BoundExpr` / `BoundCondition` / argument parts exactly as `PartHasIntrinsic`
   does), yielding the exception-names each OPERAND kind can raise: `BoundProgramAddress` → EC-PROGRAM-NOT-FOUND;
   the intrinsic-bearing families that today ride `ContainsIntrinsic` (EC-ARGUMENT-FUNCTION, EC-ORDER-NOT-SUPPORTED,
   EC-DATA-CONVERSION, EC-LOCALE-INVALID) fold into the same walker so there is ONE operand scan, not one per family.
   `QueryFor` becomes node-kind names ∪ `OperandRaisableNames` ∪ the ambient tail. PB1453 is its first new consumer.
2. **A closed catalog** (PB1531): `ExceptionCatalog.TryGet` answers only catalogued names plus the user-defined
   `EC-USER-*` family (§14.6.13.1.1 makes THAT family open by definition: "The name is defined by specifying it").
3. **The registry drift test** (PB1037): every catalogued level-3 name is accounted for by exactly one of — a
   `QueryFor` node-kind arm, an operand declaration, an ambient gate, the I-O status→EC mapping
   (`ExceptionCatalog.IoMaskNames`), or an allow-list entry naming its `kb/Work` note or its `docs/CONFORMANCE.md`
   determination ("never raised by this implementation"). A name in none of them fails the build. The allow-list IS the
   honest list of unraised names, reviewed like code. Prove it fails once by deleting one declaration.

## Tasks this model produces (briefs live on the defect notes)

- PB1531 — close the EC-IMP-* arm (COBOLNET0711 already names the refusal) — half a slot; independent.
- PB1037 — the registry drift test over the three sources — one slot, NEEDS Opus (it has to classify ~130 names and
