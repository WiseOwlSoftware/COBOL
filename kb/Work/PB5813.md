# PB5813 - INITIALIZE REPLACING treats a reference-modified alphabetic item as alphanumeric (every edition)

**What is wrong.** `INITIALIZE WA (2:1) REPLACING ALPHABETIC DATA BY "Q"`, where `WA` is `PIC A(3)`, leaves the slice alone, and `INITIALIZE WB (2:1) REPLACING ALPHANUMERIC DATA BY "Q"` fills it (`ini.cob`). 1985 keeps the category of a reference-modified alphabetic item: only the categories numeric, numeric edited and alphanumeric edited become alphanumeric (`§1985:IV.4.3.8.4.4 GR5`), and INITIALIZE REPLACING initializes an item only if it belongs to the category named (`§1985:VI.6.17.4 GR2`). So the first statement writes `Q` and the second changes nothing. The compiler does the reverse at `--std 85` and at `--std 2023` (cause (b): wrong the same way at 2023). The `RefModPlace` arm of `BindInitializeTarget` hard-codes `InitializeCategory.Alphanumeric`, citing `§2023:8.4.3.3.4 GR6`, whose own text also keeps alphabetic: only alphanumeric-edited, national-edited, numeric and numeric-edited are converted. The checker's confidence: high. Harm: wrong_answer.
