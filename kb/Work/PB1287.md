### Finding report-section — §13.8.2 general format; §13.8.4 (one or more report group description entries); §13.10 (rejects-legal-source; rows FMT-13.8.2)

**Mechanism.** F-REPORT-SECTION-SHAPE — reportDescriptionEntry is `RD … DOT reportGroupEntry*`: it has no constant-entry arm (a constant entry after an RD is a parse/reserved-word error) and its `*` admits an RD followed by nothing, where §13.8.2's brace ellipsis and §13.8.4 require one or more entries

**Repro.** (a) REPORT SECTION. RD R-1 PAGE LIMIT IS 10 LINES. 01 KC CONSTANT AS 7. 01 DET-1 TYPE DE LINE PLUS 1. 03 COLUMN 1 PIC 9 VALUE KC. … DISPLAY "KC=" KC. (probe/report-section/c1.cob, --std 2023 or 2002). (b) REPORT SECTION. RD R-1 PAGE LIMIT IS 10 LINES. followed directly by PROCEDURE DIVISION (probe/report-section/c3.cob, any edition).

**Expected, from the standard.** (a) clean compile; report line holds 7; KC=7 displayed (§13.8.2 admits constant-entry in the brace group after report-description-entry, 2002+). (b) a diagnostic: the brace group carries an ellipsis (at least one entry) and §13.8.4 requires an RD to be followed by one or more report group description entries.

**Observed.** (a) c1.cob(12,14): error COBOLNET0901: 'CONSTANT' is a reserved word in COBOL-2023 and cannot be used as a user-defined word (ISO §8.9) — same at 2002. (b) c3.cob compiles and runs (NOGROUPS) at 2023 and 85 with no diagnostic. This duplicates the constant-entry adjudication's F-REPORT-SECTION for half (a); file ONE note covering both halves, since the fix is the one reportDescriptionEntry production (admit constantEntry in the repeated group, require at least one entry) plus the binder routing report-section constants into the constant table.

**Code site.** src/Cobol.Net.Frontend/Grammar/Core/CobolReportWriter.g4#reportDescriptionEntry (line ~27)
