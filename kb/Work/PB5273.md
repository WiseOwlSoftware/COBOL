# PB5273 - RETURN ... INTO and READ ... INTO a reference-modified ALPHABETIC item, in a file with more than one record description, compile: AdmitsIntoOperand admits every reference-modified receiver without asking its category

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/Validation/StatementValidation.cs` (`AdmitsIntoOperand`, `CheckIntoReceiver`)

**Mechanism.** An INTO phrase with two or more record descriptions needs identifier-1 to describe a group or an elementary alphanumeric item (§1985:XI.4.3.4 GR5 b). A reference-modified alphabetic item stays alphabetic: §1985:IV.4.3.8.4.4 GR5 rewrites only numeric, numeric edited and alphanumeric edited to alphanumeric. `StatementValidation.AdmitsIntoOperand` returns true for any reference-modified place, so `W(1:5)` with `W PIC A(5)` is admitted where unsliced `W` is refused (COBOL1994). The Place form of `ItemCategory.IsAlphanumericOrNational` already makes the distinction (kb/Work PB2586 for UNSTRING). READ INTO shares the code; kb/Work PB5211 holds READ INTO at 85 (its title names the reference-modified alphabetic receiver), so this note holds RETURN and the fix covers both.

None of them is recorded: the non-conforming verdicts wait in `E:/COBOL-coord/scratch/coderead-85/p2-for-register.json`.

**Rules (1 claimed; every citation checked with `scripts/spec/cite.py --check`).**

**Fix direction (root cause, CLAUDE.md rule 4).** Ask the place-aware category predicate in `AdmitsIntoOperand` for a reference-modified receiver; one change serves RETURN and READ (close PB5211's receiver half with it).
