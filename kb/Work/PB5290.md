# PB5290 - at --std 85 the Communication Section record rules are checked in storage bytes and skip condition-names: CheckRecords compares ByteWidth with 87 (input CD) and 33 (I-O CD) where 1985 counts standard-data-format characters, and FirstWithValue ignores an 88 VALUE in the second and later records

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/CommunicationSectionBinder.cs` (`CheckRecords`, `FirstWithValue`)

**Mechanism.** The records after an input CD "must describe a record of exactly 87 standard data format characters" (§1985:XIV.2.2.3 SR5) and after an I-O CD of exactly 33 (SR14), and "The size of an elementary data item or a group item is the number of characters in standard data format of the item" (§1985:IV.4.3.4). `CheckRecords` measures `record.ByteWidth`, so a record with a COMP item is wrong both ways: X(83) plus 9(8) COMP (91 characters) is accepted and X(79) plus 9(8) COMP (87 characters) refused; likewise 33 for the I-O CD. Second, "only the first redefinition may contain VALUE clauses" (SR5, SR9, SR14) with no condition-name exception (1985 writes that exception explicitly where it means one, §1985:VI.5.15.6), and a condition-name entry carries a VALUE clause; `FirstWithValue` checks only data-item values, so an 88 in a later record is accepted. The diagnostics cite ISO/IEC 1989:2002 Annex A, the citation matter kb/Work PB4950 decides.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids below. None of them is recorded: the non-conforming verdicts wait in `E:/COBOL-coord/scratch/coderead-85/p2-for-register.json`.

**Rules (4 claimed; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-SR-XIV.2.2.3-5` - `§1985:XIV.2.2.3 SR5` (refuter: OVERTURNED, harm: rejects-legal-source and under-rejects): "must describe a record of exactly 87 standard data format characters"
- `1985-SR-XIV.2.2.3-14` - `§1985:XIV.2.2.3 SR14` (refuter: OVERTURNED to NONCONFORMING, harm: rejects-legal-source and under-rejects): "must describe a record of exactly 33 standard data format characters"
- `1985-SR-XIV.2.2.3-9` - `§1985:XIV.2.2.3 SR9` (refuter: OVERTURNED, harm: under-rejects): "only the first redefinition may contain VALUE clauses"
- `(the size rule)` - `§1985:IV.4.3.4` (the measure SR5 and SR14 use): "is the number of characters in standard data format of the item"

**Repro.** `E:/COBOL-coord/scratch/coderead-85/out-pipe/refute-slice-65/p5b.cob` (input CD, X(83) + 9(8) COMP), `p5c.cob` (X(79) + 9(8) COMP), `p5a.cob` and `p9a.cob` (an 88 VALUE in the second record of an input and an output CD), `E:/COBOL-coord/scratch/coderead-85/out-pipe/refute-slice-64/d1.cob` (I-O CD, X(31) + 9(4) COMP) and `d2.cob` (X(29) + 9(4) COMP); `cobol.exe --std 85 --source-format fixed --run <file>`.

**Observed (a build of origin/main f2cf36fd15, rerun 2026-11-11; main has since changed only `IndexedConnector.cs` under `src/`, which none of these repros reaches).** `p5b`: exit 0, `AB`; `p5c`: exit 65, `error COBOL6169: record 'R1' of CD 'CI' describes 83 character positions`; `p5a`, `p9a`: exit 0, `OK`; `d1`: exit 0, `LEN R2 33`; `d2`: exit 65, `error COBOL6169: record 'R2' of CD 'TCD' describes 31 character positions`.

**Expected (from the 1985 text).** `p5b`, `d1`, `p5a` and `p9a` refused; `p5c` and `d2` accepted.

**Fix direction (root cause, CLAUDE.md rule 4).** Measure the record in standard-data-format characters (the 1985 size the data binder can compute from the PICTURE) and count a condition-name VALUE in the later-record rule, in the one `CheckRecords` loop; test each repro.
