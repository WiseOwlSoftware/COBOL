# PB4473 - a lane reviewer has no permitted scratch place, and nothing enforces the rule

**Where the code is.** PB4466's finisher branch is `worktree-wf_ec0327b7-bfd-8` (worktree `E:\COBOL\.claude\worktrees\wf_ec0327b7-bfd-8`,
head `7bf56e498`); origin/main has only the first PB4466 commits (P16 and the template line may be there, the reviewer wiring is not).

**Site 1 (R2-1).** `.claude/agents/cobol-reviewer.md:37` (branch) tells every cobol-reviewer: anything kept outside the worktree "goes in the
scratch directory your prompt names" and never in the session scratchpad. The workflow reviewer (`wf_rolling_wave.js`, `reviewScratch(g)`,
`<scratch>\review-w<wave>-<letter>\`) is given one. The loop's review lane is not: `scripts/orchestrator/review_lane.py` builds a prompt that names
only the lane's findings file (`review_lane.py:51`, `:155-157`, `<coord>/scratch/review-<branch slug>.jsonl`) and no directory, so a lane
reviewer that needs a probe program or a log has no permitted place and either breaks the rule or stalls. Fix: name
`<coord>/scratch/review-<branch slug>/` in the prompt, create it where the findings file is created, and extend
`check_practices.py`'s BRIEFS pin (it pins the workflow prompt today) to the lane prompt, so the two reviewers are tied to one rule.

**Site 2 (structural next step).** The harness's own system prompt tells every agent to use the session scratchpad; the repo cannot change that,
so P16 and the spec's `Scratch:` line override it by instruction only. The finisher noted that a hook on Write/Bash refusing a path under the
session scratchpad for a DISPATCHED agent (not the operator) is the structural answer, site `scripts/hooks/` beside `dispatch_guard.py`,
`readonly_repo.py` and `shell_location.py`. None exists, so a script-name collision (PB4466's original harm) can recur whenever an agent
follows the harness over P16. The hook needs a way to tell a dispatched agent from the operator (what `readonly_repo.py` already uses for the
read-only roles); decide that first.

**As landed (wave 20261845, group G).** Site 1: `review_lane.py` gives each lane agent its OWN scratch directory, `<coord>/scratch/<review|conflict>-<branch slug>/`
(`scratch_path`: beside the reviewer's findings file, its name without `.jsonl`), created by `launch` before the agent starts, recorded in the run
as `scratch` and named in the prompt by `scratch_line` in the rolling wave's reviewer wording. The conflict finisher is bound the same way (P16 binds every
agent). `check_practices.py` pins both prompt builders (`CODE_PROMPTS`), the enqueue unit's hand-dispatched reviewer is told the same directory
(`units/enqueue.md`), and `review_lane.py --self-test` and `test_plan_wave.py` pin the sentence. Site 2: the dispatched-versus-operator question
had its answer already in `readonly_repo.py`'s mechanism: a hook in an AGENT DEFINITION's frontmatter runs only for that role, never for the operator.
`scripts/hooks/own_scratch.py` refuses a Write/Edit/NotebookEdit target or a Bash/PowerShell command naming the harness's session folder (matched by shape,
`claude*/<slug>/<session uuid>/scratchpad`, in the Windows, Git Bash and Linux spellings), is attached by all seven `.claude/agents/` roles, and
`test_own_scratch.py` fails a role that does not attach it.
