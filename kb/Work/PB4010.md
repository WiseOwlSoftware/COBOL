# PB4010 — the fuzz history page miscounts WiseOwl compiler bugs

**Sites:** `scripts/fuzz_history.py#finding_kind`, `scripts/fuzz_history.py#defects_of`

**R2-1, the kind of a note is decided by a hand-kept area prefix list.** `finding_kind` returns `harness` only when a note's
`area` starts with `tooling` or `docs`; every other non-retired defect counts as a compiler bug. The register also files harness
and process defects under `tests/` (137 notes), `process/` (326), `orchestrator/` (74), `scripts/` and `ci/`. A fuzz night note
in any of those areas is drawn as a WiseOwl compiler bug in the tiles, the per-night chart and FUZZ-LEDGER.md. The register
already carries the fact that decides it: `process_only: true` marks a defect that no user program sees. Read it, rather than a
second list of areas that drifts from the register's.

**R2-2, only night runs are counted.** `defects_of` matches a note whose `source` names a recorded night's run id, so a
compiler bug found by a fuzz run that is not a night is absent from "bugs found in WiseOwl". PB3538 (a landed wrong-answer
COMPUTE defect: chained divisions raising EC-SIZE-OVERFLOW) came from the aborted third-evening run fuzz-20261022-160216 and
appears nowhere on the page. The history must cover every fuzz run whose results directory exists, marking a run that is not a
full night as such, or name the runs it omits.

**Fix (landed with the filing).** Neither the area nor `process_only` can decide it: harness defects sit under five areas
besides `tooling`, and `process_only` is also true of a wrong diagnostic (PB3569, PB3831 and PB3832 are compiler notes with it
set). The fact that decides it is where the defect lives. `site_kind` reads the note's declared sites through
`work.note_sites`: a path or glob under `src/` makes it a compiler bug, others or `none (why)` a harness bug. A block naming only
types or members declares no path (review R1-1), so it classifies nothing. The 16 fuzz defects filed before site blocks are a
closed record, `LEGACY_KINDS` (review R1-2: an area list could never be complete); any other defect nothing classifies stops the
render and `fuzz_triage.py history` refuses it, by name. One register import, `fuzz_history.register()` (review R1-3: fuzz_triage
had its own copy). `unrecorded_runs` counts a finding whose source
names a fuzz run the history holds no night for and lists it as "Run of <date>": PB3538 now counts (23 to 24 compiler bugs, 21
to 22 fixed) and PB3537 is listed as a harness bug. Self-test cases: a sited harness bug under `tests/`, a `process_only` compiler
bug, a legacy note, a short-run finding, a members-only block refused by the page and by `history`.

**Sync (owner 2026-10-28, during the fix: "The fuzz ledger repo file must be kept in sync with the artifact").** One writer,
`write_ledger`, draws the HTML page and FUZZ-LEDGER.md together, both stamped with one LEDGER VERSION (a digest of the content,
not of the time). `mark-published` refuses a page whose version is not FUZZ-LEDGER.md's on origin/main and records the one it
published in `<coord>/fuzz-ledger-published.json`; `status`, printed by session-probe, says current, PUBLISH OWED or REGENERATE
OWED. `render --markdown` is gone: there is no way to write one rendering without the other. SYNC test cases cover each.
Round-2 review leads, all fixed: the stamp carries no build time, so equal content is equal bytes and `status` compares main's
file with a render byte for byte (a hand edit shows); `status` checks the recorded Artifact is the history's (no `--url`); it
checks drift only in a checkout at origin/main and otherwise says UNCHECKED; `history` draws the whole page before writing, so
a missing note, a non-finding or an unclassifiable note anywhere on the page writes nothing; design section 7 lists the SYNC arm.
DESIGN-differential-fuzz.md §6 states both rules; the summary Artifact (https://claude.ai/artifact/UBCptoMp1GohHrvpUFRS7g) is
republished from main's FUZZ-LEDGER.md once this lands.
