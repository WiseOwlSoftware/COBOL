# PB4010 — the fuzz history page miscounts WiseOwl compiler bugs

**Sites:** `scripts/fuzz_history.py#finding_kind`, `scripts/fuzz_history.py#defects_of`

**R2-1, the kind of a note is decided by a hand-kept area prefix list.** `finding_kind` returns `harness` only when a note's
`area` starts with `tooling` or `docs`; every other non-retired defect counts as a compiler bug. The register also files harness
and process defects under `tests/` (137 notes), `process/` (326), `orchestrator/` (74), `scripts/` and `ci/`. A fuzz night note
in any of those areas is drawn as a WiseOwl compiler bug in the tiles, the per-night chart and FUZZ-LEDGER.md. The register
already carries the fact that decides it: `process_only: true` marks a defect that no user program sees. Read it, rather than a
second list of areas that drifts from the register's.

**R2-2, only night runs are counted.** `defects_of` matches a note whose `source` names a recorded night's run id, so a
compiler bug found by a fuzz run that is not a night is absent from "bugs found in WiseOwl". PB3538 (a landed wrong-answer
COMPUTE defect: chained divisions raising EC-SIZE-OVERFLOW) came from the aborted third-evening run fuzz-20261022-160216 and
appears nowhere on the page. The history must cover every fuzz run whose results directory exists, marking a run that is not a
full night as such, or name the runs it omits.

**Fix.** Both in `scripts/fuzz_history.py`, with a self-test case each: a `process_only` note under `tests/` is not a compiler
bug; a note whose source names a non-night run is counted, its run shown. Regenerate FUZZ-LEDGER.md and republish the summary
Artifact (https://claude.ai/artifact/UBCptoMp1GohHrvpUFRS7g) after it lands.
