# PB302 — LANDED — a catalogued exception name with a reader and no setter

> **LANDED 2026-09-02, by the A.4.2 module-witness wave (kb/Work PB260).** All six item-10 positions now
> resolve through ONE exception-name seam (`EcNameResolution`) and draw **COBOLNET1707**
> `screen-statement-unsupported` through `ScreenFacility.ReportExceptionName`, which names the exception and
> the position it was written in. §14.6.13.1.1 licenses raising NO condition for a level-3 name belonging to
> an optional element, but it does not license ACCEPTING the name — a catalogued name with no raise site
> reads as implemented support to every consumer that can see it. Witnesses:
> `negative/a42-ec-screen-raise` (RAISE), `-use` (USE), `-turn` (>>TURN), `-perform-when` (the PERFORM WHEN
> phrase). This note's four inventory rows are re-verdicted DOCUMENTED-NON-SUPPORT on those witnesses in the
> same landing, so they leave the GAP instead of being held OPEN by the silence.

**Found by the measurement `PB260` finding 3 asked for.** PB260 said: *"Where the measurement shows a silent
reinterpretation instead, that is a defect to register, not a fixture to write around."* The golden lane ran that
measurement while witnessing the A.4.2 screen decline, and on this one surface it fails.

## The rule

`cite.py --check A.4.2` → **OK  §A.4.2 10)**:

> 10) EC-SCREEN exception conditions in the RAISING phrase of the EXIT and GOBACK statements, the RAISING phrase
> of the procedure division header, the USE statement, the WHEN phrase of the PERFORM statement, the RAISE
> statement, and the TURN compiler directive

`cite.py --check A.4.1` → OK: the associated syntax rules, general rules and exception conditions are optional
with the element. `cite.py --check 4.2.7` → OK: the decline shall be identified in user documentation.
`cite.py --check 14.9.11.4` → OK §14.9.11.4 19), the DISPLAY general rule naming the four conditions a Format-2
DISPLAY can raise.

**Those six positions need no SCREEN SECTION.** That is the whole point of the finding: every other part of the
screen decline is reached through a SCREEN SECTION header, which draws the named `COBOLNET1560`. These six do not
pass that site at all.

## What is measured

`grep -rn EC-SCREEN src/ --include=*.cs --include=*.g4` (excluding `obj/` `bin/`) returns exactly **six** lines,
all in one file:

* `src/Cobol.Net.Runtime/Exceptions/ExceptionCatalog.cs:51` — `EC-SCREEN` as a level-2 name
* `:180-184` — the level-3 names `EC-SCREEN-FIELD-OVERLAP`, `-IMP`, `-ITEM-TRUNCATED`, `-LINE-NUMBER`,
  `-STARTING-COLUMN`

No other file in `src/` mentions them. **Five catalogued names, zero setting sites, zero diagnostics.** And the
catalogue is a live READER: `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/EcBinder.ExceptionPerform.cs:170-174`
resolves a `WHEN` exception-name through `EcNameResolution.TryResolve` → `ExceptionCatalog`, so
`PERFORM … WHEN EC-SCREEN-FIELD-OVERLAP` binds clean; the same catalogue backs `RAISE`, `USE` and `>>TURN`.

Source to run:

```cobol
       >>TURN EC-SCREEN-LINE-NUMBER CHECKING ON
       IDENTIFICATION DIVISION.
       PROGRAM-ID. PB302R.
       PROCEDURE DIVISION.
       MAIN-P.
           RAISE EXCEPTION EC-SCREEN-FIELD-OVERLAP.
           STOP RUN.
```

No SCREEN SECTION anywhere. Expected today: compiles clean, zero diagnostics.

## Why it is harm and not a disposition

A catalogued name with a reader and no setter **reads as implemented support to every consumer that can see it**
— the author of the program included, who gets no signal that the handler will never fire. `docs/CONFORMANCE.md`
§4 item 4 says the facility is Not provided; §5's own definition of *Not claimed* is "the module's syntax is not
accepted". Silence is neither of the two conforming postures §4 records (a named `COBOLNET1560`-band warning, or
a refusal).

## The fix, and the shape that makes the next case automatic

Not "add five diagnostics". The generalisable shape is a **declined-condition-family screen** on the ONE place
every exception-name reference already funnels through — `EcNameResolution.TryResolve` — driven by a flag on the
`ExceptionCatalog` row rather than by a hand-maintained list of names, so the next declined family (EC-VALIDATE
is the obvious sibling, and PB283 owns it) is handled with no new code. Pair it with a drift test asserting that
**every catalogued level-3 name has either a setting site in `src/` or a declined-family flag** — that is the
invariant whose absence let five names sit unset for the life of the catalogue.

## Why no test lands with this note

Deliberate. A green test pinning today's silence would read as a DECISION
(`feedback_green_test_can_hold_a_gap_open`). The witness lands with the fix. Until then the four rows above stay
**GAP** and `docs/CONFORMANCE.md` §4 item 4 records the silence as a registered defect rather than letting §1's
blanket "recognized … with a NAMED warning" cover it.
