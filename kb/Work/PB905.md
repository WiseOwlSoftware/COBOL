# PB905 — OPEN — a performance item, filed as one, with the conformance question already closed

§14.9.37.4 GR9: *"A non serial type of search operation may take place … in a manner specified by the
implementor."* The current implementation is conforming. Nobody should "fix" this under a rule; it is filed
because the owner's product bar is broader than conformance and PERFORMANCE is one of the four required
review dimensions (`PROMPT.md` §4).

## The measurement

Any `SEARCH ALL`. `src/Cobol.Net.Compiler/CodeGen/Verbs/ControlFlowEmitter.cs#EmitAllScan` emits a loop that
increments the index by 1 and evaluates the WHEN condition at each step; GR1 requires each subscript to be
re-rendered per evaluation. A 10 000-entry table therefore costs 10 000 condition evaluations where the
form the programmer chose exists precisely to cost 14.

## Why this is a BINDER change, and why that matters

A binary search needs the OCCURS KEY list with each key's ASCENDING/DESCENDING direction, and each WHEN
conjunct decomposed into (key, compare-operand). `SearchBinder.BindSearchAll` **already builds that model**
for the SR7-SR13 screens, via `SearchAllFormat2Rules` — and `COBOLNET_CONTROL_FLOW_DESIGN` D12 explicitly
rejected putting it on `BoundSearch` **because nothing at run time consumed it**. This would be the consumer,
so the design decision is re-opened by the work rather than contradicted by it: the fixer updates D12 in the
same change set (CLAUDE.md rule 2).
