# PB4199 — a contained FILE STATUS cannot name a container's GLOBAL data item

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/BinderDriver.cs` (`BinderDriver.BindUnitData`: it runs `data.Bind` before
`InheritGlobalSubtree` and `InheritGlobalReport`), `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs`
(`DataBinder.ResolveFiles`, `DataBinder.ResolveClauseOperand`).

**The defect.** A contained program's own SELECT with `FILE STATUS IS GS`, where `GS` is a GLOBAL data item of the
container, is refused `COBOL1639` ("no declaration in this source element gives the name 'GS'"). The source is legal: a
name described with GLOBAL is a global name, visible in every program contained in the declaring one. `BindUnitData` binds
the contained data division (the ResolveFiles pass runs inside `data.Bind`) BEFORE it inherits the container's globals, so
the name is not yet visible to `ResolveClauseOperand`.

**Spec.** `python scripts/spec/cite.py --check 8.4.6.2.2 "is a global name"` OK (§8.4.6.2.2, scope of data-names with a
GLOBAL clause). The visibility clause for a contained program was not separately located; the citation above is the
definition of a global name only.

**Fix shape (the report's).** Inherit the container's GLOBAL items before the contained data division binds, which is
PB3766's shape applied to data items as well as to report items. PB3766 is open and held by an in-flight implementer
branch; this note shares its root and must be sequenced after it (same file, `BinderDriver.BindUnitData`).

**Repro** (`E:/COBOL-coord/scratch/w20261783b/fs.cob`, probed on the wave build; expected a clean compile):

```cobol

       PROGRAM-ID. OUTERP.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01  GS GLOBAL PIC XX.
       PROCEDURE DIVISION.

       PROGRAM-ID. INNER.

```

operand that goes through `ResolveClauseOperand` in a contained program.
