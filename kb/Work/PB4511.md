# PB4511 — TEST-NUMVAL and TEST-NUMVAL-C report the position OF a C or D that starts an incomplete CR/DB instead of the next position (or LENGTH+1 at the end)

**Found:** 2026-11-03 by the Sonnet-written fuzz batch; adjudicated WISEOWL-DEFECT (Opus adjudicator, billed to the API key), and its reduced repro re-run on a judge built from main 3c8b2845c (`fuzz_triage.py verify`) still shows it.

**The adjudicator's finding.** TEST-NUMVAL (and TEST-NUMVAL-C, same scanner) report the position of a C or D that starts an incomplete CR/DB instead of the next character (or LENGTH+1 at the end): '4.5 D' (X(5)) gives 5, expected 6 (r1c); '4.5 D   ' gives 5, expected 6; '1 D B' 3, expected 4; '12CX' 3, expected 4; TEST-NUMVAL-C('4.5 D   ') 5, expected 6; cobc gives the expected values. Searched kb/Work (PB4096 is the TEST-NUMVAL-F exponent-sign sibling, landed; nothing covers CR/DB). Other lines of the signature are not WiseOwl's: lowercase 'cr'/'db' returning 0 is right (§15.67.3 r1 'in uppercase or lowercase', checked) and cobc's 3/4/5 is its side (not filed: one upstream slot, see report); 32+ digits = PB4003 witness, national = PB4001 witness.

**The rule** (each marked checked by the adjudicator; re-run `cite.py --check` before writing one into code): §15.93.4 1) b) 'the position of the first character in error' (checked); §15.93.4 1) c) LENGTH+1 when 'argument-1 contains valid characters but is incomplete' (checked); §15.93.4 1) b) 1. ''0 1' ... will be 3' (checked: the position is where no conforming completion remains)

**The code site:** src/WiseOwl.Cobol.Runtime/Intrinsics/CobolIntrinsics.Exact.cs:705 (NvScan, the format-B trailing CR/DB arm: 'else return new(i + 1, ...)' when text[i] is C/D but text[i+1] is not R/B or i+1 == n)
