## Code site

`src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4:1519-1521`:

```antlr
raisingClause
    : RAISING cobolWord+
    ;
```

One axis: a list of bare words. It is consumed by
`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/EcBinder.cs:221` (`foreach (var w in rc.cobolWord())
EcAddPdRaisingWord(w.GetText())`), which is why the binder has only a name to work with and cannot know whether
FACTORY was written.

**The fix shape is a phrase model, not three alternatives** (rule 5, `feedback_model_the_rule_shape_not_one_case`):
the RAISING phrase's element is a *target* (exception-name | object-class-name | interface-name) plus a FACTORY
flag — the same tuple [[PB389]] just gave `PicInfo` for the object-reference USAGE clause, which is the template.
`EcState.PdRaisingClasses` becomes a list of that tuple, and SR5 a)/c) and SR4 a)/c)'s "the presence or absence
of the FACTORY phrase is the same in the data description entry … as in the RAISING phrase" becomes a comparison
of two flags instead of an unwritable check.

## ⚠ One leg may be VACUOUS — say so rather than writing a screen that cannot fire

ACTIVE-CLASS description to a class definition, so EXIT's c) leg (ACTIVE-CLASS) may have no reachable subject.
Measure it (`feedback_reachability_is_measured_not_deduced`) and record the determination; do not ship a
diagnostic that can never fire, and do not ship a "TODO" either.

## Landed — 2026-09-22, wave 46 (I)

**Re-probed first on the worktree's own build at `8fe62bd1f`** (probes in `scratchpad/w46i/probe/`):
`PROCEDURE DIVISION RAISING FACTORY OF CE815.` → `COBOLNET0901: 'FACTORY' is a reserved word` — reproduced as the
note's premise correction said. ⛔ **One premise did NOT hold and is corrected here:** the note's second probe,
`GOBACK RAISING FACTORY OF <class>`, is not a printed spelling — §14.9.18.2's raising-phrase is
`{ EXCEPTION exception-name-1 | identifier-1 | LAST EXCEPTION }`, so FACTORY reaches GOBACK only through
identifier-1's DESCRIPTION (`USAGE OBJECT REFERENCE FACTORY OF c`, PB389's operand end). The rule's two ends are
therefore the HEADER (`raisingClause`) and the DATA DESCRIPTION, never the GOBACK statement itself.

**Fix — the phrase is a tuple, partitioned once.**
- Grammar: `raisingClause : RAISING raisingTarget+`, `raisingTarget : FACTORY OF? cobolWord | cobolWord` (OF is an
  optional word — not underlined on printed folio 527). Sibling: `objectReferenceUsage`'s `(FACTORY OF)?` required
  the same plain OF and is now `(FACTORY OF?)?`.
- `Binding/Model/RaisingTarget.cs` (kind × name × FACTORY) and `Binding/RaisingPhrase.cs#Partition` — the ONE
  partition; the program arm (`EcBinder.EcCollectPdRaising`) and the METHOD-ID arm (`DataBinder.Oo`) were two
  verbatim copies and both now call it (`EcNameResolutionDriftTests` adjudicates one site where it had two).
- `EcBinder.RaisingObjectMismatch` — GOBACK §14.9.18.3 SR4 a)–c) / EXIT §14.9.14.3 SR5 a)–c) as ONE comparison of
  the identifier's `ObjectRefDescriptor` against the header tuples, FACTORY flag to FACTORY flag.
- ⛔ **A second defect found on the way, same rule family, fixed at its root:** a method's header RAISING state was
  loaded in `StatementBinder.BindMethodRoster`'s roster-registration loop, which binds no statement, so EVERY
  method's GOBACK/EXIT RAISING was checked against the LAST method's header. It is now loaded in the per-pc bind
  pass (`RaisingPhraseTupleTests.MethodRaising_EachMethodChecksItsOwnHeader` pins it; before the fix a legal
  `GOBACK RAISING EXCEPTION EC-USER-x` in any method but the last drew COBOLNET0717).
- ⚠ DETERMINATION (the note's vacuity question, measured by reading the rules): §14.9.14.3 SR5 c) has no reachable
  subject for EXIT PROGRAM — SR7 confines it to a program procedure division and §13.18.60.3 SR16 confines
  ACTIVE-CLASS to a class. No EXIT-specific screen was written; the shared walk answers c) for GOBACK (golden
  method WORK-A) and EXIT METHOD.
