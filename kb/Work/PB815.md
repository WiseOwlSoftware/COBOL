## Code site

`src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4:1519-1521`:

```antlr
raisingClause
    : RAISING cobolWord+
    ;
```

One axis: a list of bare words. It is consumed by
`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/EcBinder.cs:221` (`foreach (var w in rc.cobolWord())
EcAddPdRaisingWord(w.GetText())`), which is why the binder has only a name to work with and cannot know whether
FACTORY was written.

**The fix shape is a phrase model, not three alternatives** (rule 5, `feedback_model_the_rule_shape_not_one_case`):
the RAISING phrase's element is a *target* (exception-name | object-class-name | interface-name) plus a FACTORY
flag — the same tuple [[PB389]] just gave `PicInfo` for the object-reference USAGE clause, which is the template.
`EcState.PdRaisingClasses` becomes a list of that tuple, and SR5 a)/c) and SR4 a)/c)'s "the presence or absence
of the FACTORY phrase is the same in the data description entry … as in the RAISING phrase" becomes a comparison
of two flags instead of an unwritable check.

## ⚠ One leg may be VACUOUS — say so rather than writing a screen that cannot fire

§14.9.14.3 SR7 confines EXIT PROGRAM to a *program* procedure division while §13.18.60.3 SR16 confines an
ACTIVE-CLASS description to a class definition, so EXIT's c) leg (ACTIVE-CLASS) may have no reachable subject.
Measure it (`feedback_reachability_is_measured_not_deduced`) and record the determination; do not ship a
diagnostic that can never fire, and do not ship a "TODO" either.
