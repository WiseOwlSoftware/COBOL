# PB1060 — LANDED (wave 1021 C)

## Measured
```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. B28EV.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 A PIC X.
       01 B PIC X.
       PROCEDURE DIVISION.
           IF ADDRESS OF A = ADDRESS OF A DISPLAY "IF-EQ" END-IF
           EVALUATE ADDRESS OF A
             WHEN ADDRESS OF B DISPLAY "W-B"
             WHEN ADDRESS OF A DISPLAY "W-A"
           END-EVALUATE
           STOP RUN.
```

→ the IF on line 8 compiles (PB1021 landed that); the EVALUATE on line 9 draws two `COBOLNET2318: 'ADDRESS OF A' is
used as a condition, but it is an address-identifier`. `DISPLAY FUNCTION BYTE-LENGTH(ADDRESS OF A)` →
`COBOLNET0901: 'ADDRESS' is a reserved word` (the grammar's argument rule has no address-identifier).

## The rules
- `cite.py --check 14.9.13.3 "shall be valid operands for comparison to the corresponding operand in the set of selection subjects in accordance with 8.8.4.2"` → `OK §14.9.13.3 7) a)` — a subject/object pair is a relation, and §8.8.4.2 compares data-pointers.
- `cite.py --check 8.4.3.2.3 "Argument-1 shall be an identifier, a literal, a boolean expression, or an arithmetic expression"` → `OK §8.4.3.2.3 8)`; `cite.py --check 8.4.3.2.3 "argument-1 shall be of class numeric, object, or pointer"` → `OK §8.4.3.2.3 10)` (a BY VALUE pointer formal of a user-defined function).

## What the fixer owes
Admit the address-identifier through the SAME operand rule PB1021 introduced (`valueOperand` in evaluateSubject /
evaluateWhenItem; the function-argument rule), let each intrinsic's own class rule then accept or refuse it by
name, goldens for EVALUATE on pointers and a user-defined function with a BY VALUE pointer formal. Sweep the other
`valueOperand` consumers for the same gap.

**Code site (located 2026-09-27).** `src/Cobol.Net.Frontend/Grammar/Core/CobolControlFlow.g4#evaluateSubject/evaluateWhenItem`; also `src/Cobol.Net.Frontend/Grammar/Core/CobolExpressions.g4#functionArgument`, `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/EvaluateBinder.cs#SubjectKind` (code). evaluateSubject/evaluateWhenItem use valueOperand (no addressIdentifier arm; PB1021 added it only to comparisonOperand), so ADDRESS OF falls to the condition arm -> ConditionBinder COBOLNET2318; functionArgument (CobolExpressions.g4:522) has no addressIdentifier arm -> COBOL0901

## Landed (wave 1021 C, 2026-10-05)

- **Re-probed first** on this worktree's build of `17924fbb4`: the note's B28EV program drew the two false
  COBOLNET2318s, and `DISPLAY FUNCTION BYTE-LENGTH(ADDRESS OF A)` drew COBOLNET0901 — both reproduced. After the fix
  B28EV prints `IF-EQ` / `W-A`, and BYTE-LENGTH prints 8.
- **Rules** (each `cite.py --check` OK): §14.9.13.3 SR7 a) "shall be valid operands for comparison to the
  corresponding operand in the set of selection subjects in accordance with 8.8.4.2"; §8.4.3.2.3 SR8 "Argument-1
  shall be an identifier, a literal, a boolean expression, or an arithmetic expression"; SR10 "argument-1 shall be of
  class numeric, object, or pointer" (a BY VALUE formal).
- **Fix.** `CobolControlFlow.g4#evaluateSubject` / `#evaluateWhenItem` and `CobolExpressions.g4#functionArgument`
  take the ONE `addressIdentifier` rule PB1021 gave `comparisonOperand` (storage forcing and the 2002 gate follow it).
  `PtrBinder.AddressIdentifierOperand` is the one value-position binder (the relation operand, both EVALUATE sides and
  the function argument call it; ConditionBinder's private copy of the refused-carrier expression is gone).
  `EvaluateBinder` classifies it as Table 15's Identifier on both axes and compares it through the ONE relation
  checkpoint; `IntrinsicBinder.BindArgOperandCore` binds it, LENGTH/BYTE-LENGTH fold it to the pointer carrier width
  (the new `DataItem.PointerByteWidth`, the constant the four pointer-class usages already used), every class-closed
  intrinsic refuses it by its own §15 rule (UPPER-CASE → COBOLNET1627), and `UdfBinder.UdfArg` passes it on CALL's
  address carrier, BY VALUE to a BY VALUE formal.
- **Found and fixed on the way (a WRONG ANSWER, I9).** A POINTER subject read by two WHEN arms is held in GR3's
  intermediate, and `SendingValueTemp.Materialize` stored it with a MOVE, which stores no pointer: `SET P TO ADDRESS
  OF B` then `EVALUATE P WHEN Q … WHEN P …` took WHEN OTHER. `SendingValueTemp.IdentityStore` now stores every class
  MOVE cannot — index (PB1661), data-pointer, program-pointer, function-pointer, object reference — by its SET.
- **Sibling sweep.** Every value-position consumer of an identifier that admits class pointer: relation operand
  (PB1021), CALL / INVOKE / inline-invocation arguments (PB239, PB1021), SET Format 7 sender — already took
  `addressIdentifier`; the partial-expression comparison reaches `comparisonOperand`. MOVE, DISPLAY and the arithmetic
  positions admit no pointer class, so no arm is owed there.
- **Goldens.** `conformance:2002/pb1060_address_identifier_evaluate_argument` (EVALUATE subject/object/ALSO, the
  materialized pointer subject, BYTE-LENGTH/LENGTH, a UDF reading through the received address: `F ATQZ`);
  `conformance:negative/pb1060-evaluate-address-identifier-85` (COBOLNET0900 at 85).
- **Train 1021 review C-2 (fixed in the cluster).** The usage-keyed argument screens of the two functions whose
  argument-1 is not class-screened — CONVERT (§15.19.3 r7, "except index, message-tag, object reference, pointer,
  function-pointer or program-pointer") and BASECONVERT (§15.12.3 r1, "a usage display or national data item or
  literal") — read `IntrinsicArgumentRules.StaticUsageOf`, which answered null for a `BoundAddressOperand`, so both
  compiled under strict `--std 2023` and aborted at run time in `IntrinsicRenderer`'s NotImplemented render.
  `StaticUsageOf` now answers the unique item's usage (POINTER / PROGRAM-POINTER), and both draw the code a USAGE
  POINTER argument draws (COBOLNET1514 / COBOLNET1642). Goldens `conformance:negative/pb1060-convert-any-address-identifier`
  and `conformance:negative/pb1060-baseconvert-address-identifier`. The `--permissive` path to the same render is
  PB2074, a different gate (the coercion extension of the class screen), and stays open there.
