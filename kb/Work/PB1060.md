# PB1060 — OPEN

## Measured
```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. B28EV.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 A PIC X.
       01 B PIC X.
       PROCEDURE DIVISION.
           IF ADDRESS OF A = ADDRESS OF A DISPLAY "IF-EQ" END-IF
           EVALUATE ADDRESS OF A
             WHEN ADDRESS OF B DISPLAY "W-B"
             WHEN ADDRESS OF A DISPLAY "W-A"
           END-EVALUATE
           STOP RUN.
```

→ the IF on line 8 compiles (PB1021 landed that); the EVALUATE on line 9 draws two `COBOLNET2318: 'ADDRESS OF A' is
used as a condition, but it is an address-identifier`. `DISPLAY FUNCTION BYTE-LENGTH(ADDRESS OF A)` →
`COBOLNET0901: 'ADDRESS' is a reserved word` (the grammar's argument rule has no address-identifier).

## The rules
- `cite.py --check 14.9.13.3 "shall be valid operands for comparison to the corresponding operand in the set of selection subjects in accordance with 8.8.4.2"` → `OK §14.9.13.3 7) a)` — a subject/object pair is a relation, and §8.8.4.2 compares data-pointers.
- `cite.py --check 8.4.3.2.3 "Argument-1 shall be an identifier, a literal, a boolean expression, or an arithmetic expression"` → `OK §8.4.3.2.3 8)`; `cite.py --check 8.4.3.2.3 "argument-1 shall be of class numeric, object, or pointer"` → `OK §8.4.3.2.3 10)` (a BY VALUE pointer formal of a user-defined function).

## What the fixer owes
Admit the address-identifier through the SAME operand rule PB1021 introduced (`valueOperand` in evaluateSubject /
evaluateWhenItem; the function-argument rule), let each intrinsic's own class rule then accept or refuse it by
name, goldens for EVALUATE on pointers and a user-defined function with a BY VALUE pointer formal. Sweep the other
`valueOperand` consumers for the same gap.
