## The defect
`CALL ... USING BY CONTENT A + 1` (and the INVOKE lane) into a `PIC ZZ9.99`, `PIC X(4)` or `PIC N(4)` formal is refused
(wave 1006 group A, PB1113). The governing rule admits it: §14.8.2.3.3 rule 2 d) applies the MOVE rules "with the argument
as the sending operand", and an arithmetic expression argument is a numeric value, the same sender category as a numeric
literal (which PB1113 already admits through the MOVE store).

## Fix
In `src/Cobol.Net.Compiler/Oo/OoConformance.cs#ContentValueMismatch`, the `sender.IsExpression` arm: describe the expression as
a numeric sender (the arm `ContentValue.Arithmetic` already carries the noninteger Table 16 row) and ask rule 2 d)'s MOVE
validity question, so a numeric value into a numeric-edited receiver is admitted and edited, and the alphanumeric and national
receivers keep the rows Table 16 refuses (a noninteger numeric value). Both lanes ask it: the CALL lane through
`ParameterConformance.ContentConformanceReason` and the INVOKE lane through `OoBinder`. The store goes through the receiving
category's MOVE store, as `MoveEmitter.ConvertSource` already does for the numeric literal. Golden at the introducing
edition plus the Table 16 negatives; repro `scratchpad/w1006a/gen1113.py` case `ee` (may be gone: rebuild from the PB1936 text).
