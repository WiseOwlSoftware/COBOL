# PB5912 - the 1985 FD agreement rules for a separately compiled EXTERNAL describer

**Sites:**
- `src/WiseOwl.Cobol.Compiler/Binding/ExternalFileConnectorRules.cs` (`CheckFileDescriptions`: one compilation group only)
- `src/WiseOwl.Cobol.Runtime/Control/ExternalTable.cs` (`ExternalTable.Describe`: the activation-time comparison, gated by `ExternalChecks`)

**What.** `FileDescriptionIdentity`'s rows (LABEL RECORDS, BLOCK CONTAINS, CODE-SET, LINAGE GR11a-c, RECORD, VALUE OF and,
since PB5638, the report-file rule §1985:XIII.3.3.4 GR3) are compared across the describers of one compilation group. Two
programs compiled separately and run in one run unit are compared only at activation, by `ExternalTable.Describe`, whose
checks run under an EC enablement mask; at 85 no EC model exists, so the 1985 rules are asked of no separately compiled pair.
This was PB5638's part 2 ("record it as the documented limit in docs/conformance/ or give the runtime an agreed identity
digest the activation compares").

**To decide.** (a) a documented limit in `docs/conformance/` (the 1985 rules are compile-time checks within a compilation
group), or (b) an FD identity digest in the external descriptor, compared at activation at 85 by a gate that does not depend
on EC enablement, with a defined outcome for a mismatch. Cite each 1985 rule through `cite.py --check`.

**Beside it (one compilation group).** At 85 a LINAGE data-name of an EXTERNAL file that names no external data item is not
reported at compile time: the externality screen in `ExternalFileConnectorRules.Check` is gated `is2023`, though GR11c ("The
same corresponding external data items referenced by data-name-1") makes the items external at 85 too. `FileDescriptionIdentity`
leaves such an operand undecided. Decide it with this note.
