# PB3712 — a deferred link names a head that may not run

**Sites:** `scripts/orchestrator/plan_wave.py` (the `links_per_chain` deferral and the budget loop that appends a skipped head to `skipped`; the code is on branch `worktree-wf_12e98f2a-957-1`, PB3446, and lands with it).

## What happens

The `links_per_chain` deferral runs before the budget loop looks at the chain head. A link whose head was skipped (budget or `max_groups`)
still lands in `waiting` with the message that its predecessor is a group "which this wave runs" and that "the next wave plans it from that
group's branch". Scenario: a campaign wave whose budget fits no group: head A goes to `skipped`, while its successor A2's notes say A is
run by this wave. The operator reading the plan is told work is dispatched that is not.

## Fix

Word the message by whether `g.after` is among the chosen letters ("which this wave runs" against "which waits too"), or test the link
after the head's fate is known. Add a planner self-test arm: a chain whose head is cut by the budget.
