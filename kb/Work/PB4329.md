# PB4329 — step 6 of PB4323: CI matrix by weighted shards

**Owner decision 2 (2026-10-31, Mythos session, in chat).** CI's Guard job (the NIST corpus through the `cobol` CLI) moves from the merge group to the nightly workflow. (The nightly workflow itself is step 9, PB4332.)

**Sites:** `.github/workflows/build-and-test.yml` (whole: the name-split matrix becomes 7 Windows and 5 Linux weighted shards, the `guard` job leaves, `inv1-strong-2023` becomes a Linux step, `conformance-population` folds into `ci-gate`, 11 of 12 listing steps go, one `--list-tests` per OS is uploaded), `tests/_shared/GateLegs.cs` (whole: `GateTestFramework` reads `WISEOWL_COBOL_SHARD=k/N`, sorts classes by weight, assigns greedily longest-first to N bins, runs bin k; an unknown class gets the default weight; this hook is built in step 5, PB4328), `tests/_shared/test-weights.json` (whole: the weights, from step 5).

**Change.** `ci-gate` checks that every discovered name ran exactly once across the shards' trx, so a stale weight costs balance, never coverage. The merge group's critical path (Guard NIST loop 734 s at JOBS=4) leaves; Conformance shards already run the NIST corpus in-process.

**Adds / deletes.** About +60 / -300.

**Effect.** Merge group 15.1 to about 7.7 min (9.6 until step 2, PB4325, splits the 352 s test); 116 to about 77 runner-min.

**Closes.** Nothing.

**Order.** After step 2 (PB4325) for the 7.7-min figure.
