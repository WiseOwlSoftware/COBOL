# Landing, 2026-11-16: at COBOL-85 the program is told the 1985 value of each I-O condition

**Re-probe before the fix** (`run_probe.py`, `rdely.cob`, `--std 85`): `LFW 71`. **After:** `LFW 99`, the other lines unchanged.

**The fix** (docs/FILES_DESIGN.md D33). The connector keeps its condition in the runtime's one vocabulary
(`FileConnector.Status`); the program is told `FileConnector.ProgramStatus`, which at `--std 85`
(`DialectBehavior.IoStatusValuesOutside1985Lists`, VCR row 7.86) is `IoStatus1985.Report`: the file's module value, the
1985 value that names the condition ('06' → '04' by §1985:VII.4.4.4 GR13, '09' → '00', '31' → '30', '34' and '07' on a
relative or indexed file → '30' and '00'), or the condition's own 9x ('45' 92, '51' to '54' 93 to 96, '61' 97, '62' 98,
'71' 99). `FileRegistry.Status`, `IoConditionName` and `ExceptionFile` read it. Each projection keeps the value's class and
criticality (`ExceptionCatalog.IsFatalIoStatus` asks `IoStatus1985.IsCritical` for a 9x), so the returned statuses that
steer the phrases and the program's status that steers the hooks agree. The 9x are the conformance statement's
section 3.13.

**Tests.** `IoStatus1985Tests` re-reads the three module lists from the 1985 text and requires every `FileStatusCode`
constant, on every organization, to report a listed value or a documented 9x of the same class and criticality; the
conformance case `VII.1.3@1985-LANGUAGE-CONCEPTS/pb5882_io_status_1985_values` (85) shows '00' for a line holding SOH,
'04' for an over-length line, '99' for a WRITE of a record holding the delimiter with the USE procedure seeing it, and
that the failed WRITE wrote nothing.
