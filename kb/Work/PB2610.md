# PB2610

Filed from the w1039g adjudication of the GnuCOBOL differential flips at main ea20c28e3
(`E:\COBOL-coord\scratch\reports\w1039g-PB397-report.md`, section "Sibling DEFECT found while probing case 1").
A sibling of the landed PB397 (COBOLNET2966/2967/2968); it touches none of the seven differential cases.

**Harm.** Rejects legal source at every edition. No run-time result is affected: the statement after the GO TO is
unreachable either way.

**Rule.** `OK §14.9.17.3 2)`: "If a GO TO statement represented by format 1 appears in a consecutive sequence of
imperative statements within a sentence, it shall appear as the last statement in that sequence." `OK §14.5.1`: "Any
statement with a conditional phrase that is not terminated by its explicit scope terminator is a conditional
statement", and "A sentence is a sequence of one or more procedural statements, the last of which is terminated by a
separator period." A conditional statement ends the consecutive run of imperative statements, so a GO TO written
directly before one is the last statement of its imperative sequence and SR2 is satisfied.

**Repro** (pinned ea20c28e3; rejected at `--std 85` and `--std 2023`):

           PROCEDURE DIVISION.
           P1.
               GO TO P2
               ADD 1 TO A ON SIZE ERROR DISPLAY 'Z'.
           P2.
               DISPLAY "P2" STOP RUN.

draws `error COBOLNET2967 ... this one is followed by ADD in the same sequence`. The same for
`GO TO P2 IF A = 1 DISPLAY 'Y'.` and, inside a phrase, `IF A = 1 GO TO P2 ADD 1 TO A ON SIZE ERROR DISPLAY 'Z'
END-IF.` Control: `GO TO P2 IF A = 1 DISPLAY 'Y' END-IF.` is correctly refused, because that IF is a delimited-scope
statement and therefore imperative (§14.5.3.2).

**Code site.** `src/Cobol.Net.Compiler/Binding/Procedure/StatementPosition.cs#PlacementRules.GoToLast` uses
`FollowedBy` / `StatementPosition.IsLast`, which treat every statement of the sentence or statementBlock as "the
sequence". The SR2 predicate has to ask whether the following statement is IMPERATIVE.

**Doc.** `docs/CONFORMANCE.md` D-SEQ (a) defines "the sequence" as all the statements of one sentence or phrase,
which is wrong for SR2. D-SEQ (b) ties the STOP RUN rule (§14.9.42.3 SR1, COBOLNET2968) to "the SAME sequence
§14.9.17.3 SR2 names"; probe `DISPLAY 'S' STOP RUN IF A = 1 DISPLAY 'Y'.` is refused with COBOLNET2968 today, so
the fix re-decides that reading too.

**Editions.** All four; the rule text carries no edition qualifier.


## Landed — 2026-10-08 (wave 1039 group Y)

Both claimed rows stay CONFORMS with their reading corrected (batch `w1039y-pb2610-go-to-before-conditional`).
`StatementPosition.EndsImperativeRun` is the SR2 predicate: true when the statement is the last of its sequence or
the statement after it is CONDITIONAL, classified by the existing `ConditionalStatements.IsConditional` (§14.5.1 +
Table 12, read off the parse). `PlacementRules.GoToLast` and `StopLast` both ask it (`FollowedByAnImperative`).

Measured before (ea20c28e3): `GO TO P2 IF A = 1 DISPLAY 'Y'.`, `GO TO P2 ADD 1 TO A ON SIZE ERROR DISPLAY 'Z'.`,
`GO TO P2 EVALUATE A WHEN 1 DISPLAY 'E'.`, the same inside an IF THEN phrase, and `DISPLAY 'S' STOP RUN IF A = 1
DISPLAY 'Y'.` were all refused (COBOLNET2967/2968) at 85 and 2023. After: all accepted. Still refused: GO TO followed
by DISPLAY, by `IF ... END-IF` and by `ADD ... ON SIZE ERROR ... END-ADD` (delimited scope statements are imperative,
§14.5.3.2); STOP RUN followed by DISPLAY or by a delimited EVALUATE.

Sibling sweep: COBOLNET2966 (§14.9.14.3 SR1) is stated over the SENTENCE ("in a sentence by itself"), not over an
imperative run, so `EXIT IF A = 1 DISPLAY 'Y'.` stays refused; it does not make this mistake. COBOLNET2968 shared the
predicate and is corrected with it (D-SEQ (b)). No other caller of `StatementPosition.IsLast` exists.

## Landing

  violation text for GO TO and STOP RUN.
- `src/Cobol.Net.Compiler/Binding/ConditionalStatements.cs#IsConditional` — the one §14.5.1 classifier (also used by
  `ProcedureFormatPass`); do not write a verb list.
