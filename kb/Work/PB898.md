# PB898 — LANDED — one source of truth, and a second copy nobody compares it to

Source: the `PB436` report, "New defects" item 1. **Re-measured on this tree, and the numbers have moved
since the report** — which is the argument for the assertion rather than for the edit.

## The measurement

```
$ awk -F'\t' '$3=="divergent"{print $1}' tests/nist/corpus.tsv
IX111A IX210A IX214A IX215A NC201A NC235A NC236A SQ101M SQ207M SQ208M SQ210M SQ212A ST146A     (13)

$ grep -n LEGACY_DIVERGENT scripts/guard.sh
210:LEGACY_DIVERGENT="IX111A IX210A IX214A IX215A NC201A NC235A NC236A SQ207M ST146A SQ101M SQ208M SQ210M"  (12)
```

`SQ212A` is declared divergent in the manifest and is absent from the script. The PB436 report said 12 vs
11; on this tree it is 13 vs 12. **The list drifts every time the manifest grows, and nothing notices** —
which is the finding, not the missing name.

## The consequence

`scripts/guard.sh:211` — `if [ "$GUARD_DIVERGENT" != "1" ]; then LEGACY_DIVERGENT=""; fi` — so the list is
live only under the opt-in legacy differential. Under `GUARD_DIVERGENT=1`, SQ212A's expected legacy
difference is scored as a regression (the comment at `:277` says "expected (see LEGACY_DIVERGENT) — never a
regression", which is true for the twelve and false for the thirteenth).

## The rule

None — no ISO clause applies. The invariant is the project's own one-source-of-truth rule, and it is
**already asserted for a sibling population**: `CorpusManifestTests.GuardNistPopulation_*` compares the
script's NIST_TESTS list against the manifest. The same test class is the home for this one.

## The fix, in the order it has to happen

1. Assert set EQUALITY between `LEGACY_DIVERGENT` and the manifest's `divergent` rows in
   `CorpusManifestTests`. **Make it fail once** before repairing either side.
2. Then repair whichever side is wrong. ⛔ Deciding whether SQ212A belongs in the list needs a LIVE LEGACY
   RUN — evidence neither the PB436 implementer nor this registrar could take on Windows — so the fixer
   either takes that evidence or asks the owner. Adding the name to make the test green WITHOUT it would be
   the same unmeasured copy in a new place.

## The sibling sweep

Same root-cause family as `kb/Work/PB750` (two NIST runners, one manifest). Every hand-maintained list in
`scripts/guard*.sh` that restates a manifest column is in scope: the NIST population (asserted), the
divergent set (this note), and whatever `guard-fast.sh` and `guard-verify.sh` carry. **A hand-maintained
list where a manifest column exists is the defect** (CLAUDE.md rule 5); the assertion is the minimum, and
reading the column directly is better.

## Landed — 2026-09-19 (wave 39, group CORPUS-FETCH-AND-GUARD)

Re-measured on this worktree and the note held: 13 `divergent` rows in `tests/nist/corpus.tsv`, 12 names in
`scripts/guard.sh:210`, `SQ212A` the missing one.

⛔ **The note's open question — "deciding whether SQ212A belongs needs a LIVE LEGACY RUN" — did not need one,
because a THIRD reader had already adjudicated it.** `scripts/guard-nist-audit.sh` derives each row's EXPECTED
verdict straight out of the manifest: `expect[name] = (status == "divergent" && compiler == "legacy") ? "LEGACY
DIVERGENT" : …`. So under `GUARD_DIVERGENT=1` the AUDIT expected `LEGACY DIVERGENT` for SQ212A while the RUNNER
scored its difference as a regression — the runner and its own auditor disagreeing about one fact read from the
same file. And `corpus.tsv`'s header already declares itself the fold of `scripts/guard.sh LEGACY_DIVERGENT`.
Adding the name to the string would have been the "same unmeasured copy in a new place" the note warns against;
the fix is that there is no string.

`scripts/guard-population.sh` is the ONE reader: `guard_legacy_divergent()` derives the set with a single awk
over the manifest's status column, and BOTH guards source it — `guard.sh` (which held the literal) and
`guard-fast.sh` (which `sed`-extracted that literal out of `guard.sh`, the same defect one level down). ⛔ An
unreadable manifest, or one with no `divergent` rows, returns NON-ZERO and stops the guard: exempting nothing is
not the same as having nothing to exempt, and a silent empty set would report a wall of meaningless regressions.
`--self-test` proves both loud arms fire (5 checks, PASS).

The per-program RATIONALE prose in `guard.sh` was a second, also-incomplete copy of the manifest's note column
(it omitted SQ212A too) — deleted, with a pointer and the `awk` one-liner that prints the set with its reasons.
`guard-compiler.sh`'s prose no longer states a count; it was already stale at ELEVEN.

Witness: `CorpusManifestTests.GuardScripts_CarryNoHandMaintainedNistNameList`. It is stated over **any**
NIST-shaped name list in **any** `scripts/guard*.sh`, not over `LEGACY_DIVERGENT` alone, because the defect is
the SHAPE and the next one will have a different variable name — the sibling sweep the note asks for, made
automatic. It also forbids `sed`/`grep` extraction of the set from another script, requires both guards to source
the helper, and asserts the manifest has divergent rows at all so it cannot pass over an empty set. **Proved
failing first:** with the literal restored it reports `guard.sh:193 LEGACY_DIVERGENT (12 names)` and `Failed: 1`.

Docs: `DESIGN-test-build-ci.md` §3.2 (whose "the bash guard reads the same file for its `NIST_TESTS` and
`LEGACY_DIVERGENT`" was describing an intent the code did not keep) and a `DOC_INDEX.md` GATE row for the helper.
