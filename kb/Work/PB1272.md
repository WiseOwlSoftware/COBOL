## Measured

### Finding present-when-clause — §13.18.41.4 GR2 (with GR3 g) (wrong-answer; rows GR-13.18.41.4-2, GR-13.18.41.4-3)

**Mechanism.** PRESENT WHEN presence is not one snapshot per group presentation: item-level and SUM-entry chains are evaluated at use time (compose / end-of-group), after the page-fit advance

**Repro.** RD R-PW PAGE LIMIT IS 6 LINES HEADING 1 FIRST DETAIL 2 LAST DETAIL 4. 01 PH-G TYPE PH. 02 LINE 1. 03 COLUMN 1 PIC X(2) VALUE "PH". 01 DET TYPE DE. 02 LINE PLUS 1. 03 COLUMN 1 PIC 9 SOURCE WS-N. 03 COLUMN 3 PIC X(3) VALUE "OPT" PRESENT WHEN WS-F = 0. DECLARATIVES: USE BEFORE REPORTING PH-G -> MOVE 1 TO WS-F. MAIN: five times MOVE n TO WS-N, MOVE 0 TO WS-F, GENERATE DET. (probe out13/probe/present-when-clause/pwc.cob)

**Expected, from the standard.** The 4th GENERATE fails the page fit test (4+1 > LAST DETAIL 4) and advances the page; condition-1 was already evaluated with WS-F = 0 'before the processing of any LINE clauses' (§13.18.41.4 GR2), so the line prints '4 OPT'. Expected lines: PH / 1 / 2 OPT / 3 OPT / PH / 4 OPT / 5 OPT.

**Observed.** Observed '4' (OPT absent): the item-level chain is emitted inside the compose method (ReportWriterEmitter.EmitFieldPlacements `if (...) // presence`) and runs at PresentLine, after AdvancePage executed the PH declarative. Only LINE-level chains are snapshotted by ReportWriter.EvaluatePresent. The SUM entry's chain is likewise re-invoked in EndOfGroupSumReset after the group printed, so a SUM entry can be printed (true at compose) yet skipped for reset, or vice-versa, contradicting GR3g's single presence. Fix shape: evaluate every PRESENT WHEN chain of the group (line, item, sum) once in BeginPresentation and pass the snapshot to compose and reset.

**Code site.** src/Cobol.Net.Compiler/CodeGen/Verbs/ReportWriterEmitter.cs#EmitFieldPlacements; src/Cobol.Net.Runtime/IO/ReportWriter.cs#EvaluatePresent; src/Cobol.Net.Runtime/IO/ReportWriter.cs#EndOfGroupSumReset

### Finding present-when-clause — §13.18.41.4 GR2 b) with §13.18.54.4 GR2 (wrong-answer; rows GR-13.18.41.4-2)

**Mechanism.** Every LINE absent is treated as the whole report group omitted: PresentBody returns before EndOfGroupSumReset even when the 01 entry is present

**Repro.** RD R-PW CONTROL IS WS-K PAGE LIMIT IS 40 LINES. 01 DET TYPE DE LINE PLUS 1. 03 COLUMN 1 PIC 9 SOURCE WS-K. 03 COLUMN 3 PIC 99 SUM WS-AMT RESET ON WS-K. 01 CFK TYPE CF WS-K. 03 LINE PLUS 1 PRESENT WHEN WS-SHOW = 1. 04 COLUMN 1 PIC X(3) VALUE "BRK". GENERATE (K=1,AMT=1), (K=1,AMT=2), (K=2,AMT=4) with WS-SHOW=0, then WS-SHOW=1 and (K=3,AMT=1). (probe out13/probe/present-when-clause/pwb.cob)

**Expected, from the standard.** The CF WS-K instance at the 1->2 break has a present 01 entry and one absent line, so it is processed 'as though the entry were omitted' (§13.18.41.4 GR2b) — a 01-only CF, which §13.18.54.4 GR2 still treats as the reset point for RESET ON WS-K ('it is assumed to be present and to consist of a 01-level entry alone'). Expected: 1 01 / 1 03 / 2 04 / BRK / 3 01 / BRK.

**Observed.** Observed '2 07': ReportWriter.PresentBody does `if (first < 0) return;` (its comment asserts 'when EVERY line is absent the effect is as though the entire description were omitted'), skipping EndOfGroupSumReset. GR2b gives whole-group omission only for a level-01 entry; per-sum GR3g suppression already lives in EndOfGroupSumReset, so the early return must still run the reset (and decide NEXT GROUP from the 01's presence, not from line count).

**Code site.** src/Cobol.Net.Runtime/IO/ReportWriter.cs#PresentBody

### Row GR-13.18.41.1-1 — PARTIAL (no separate finding; the adjudicator's / refuter's record)

"The PRESENT WHEN clause specifies a condition under which a report section entry will be processed." (cite.py --check 13.18.41.1 OK). A general/descriptive statement: the clause's condition is captured on every report entry and gates the entry's processing (lines, printable items, sum counters). The precise processing semantics are GR2/GR3 and the defects found there (evaluation timing; all-lines-absent early return) are recorded against GR-13.18.41.4-2, not here. Golden rw_present_when witnesses line- and item-level processing under the condition. || REFUTED: PARTIAL — GR1 says the condition governs whether a report section entry is PROCESSED. The adjudicator itself found two wrong-answer processing defects (logged under GR2) that falsify this general statement on the pinned compiler: (1) item-level and SUM chains are evaluated at use time after the page-fit advance, so the condition that governs processing is not the one the rule set evaluates; (2) a PRESENT level-01 CF entry (no PRESENT WHEN of its own) is not processed at all when every LINE below it is absent - PresentBody returns before EndOfGroupSumReset. An entry with no false condition going unprocessed contradicts GR1 directly. A general rule cannot CONFORM while its only operative realization DIVERGES; the line/item gating that works makes it PARTIAL, not NOT-IMPLEMENTED.
