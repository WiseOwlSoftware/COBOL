# PB4810 - the data-name debugging trigger

**What fails.** `USE FOR DEBUGGING ON <data-name>` and `ON ALL REFERENCES OF <data-name>` are refused COBOL1571 (staged in
`ProcedureTableBuilder.FinalizeDebug`), so a legal 1985/2002-era debug declarative on a data item does not compile (CCVS DB205A
and the DB201A family's data triggers).

**The rules to implement** (sources and line numbers in kb/Work/PB4808.md, Findings):
- A bare data-name fires after any statement in which it is a receiving operand (a store an ON SIZE ERROR path skips included);
  `ALL REFERENCES OF` fires after any statement that references it.
- Each operand fires at most once per statement, nested statements included (Micro Focus rule 7).
- WRITE and REWRITE fire the record's trigger BEFORE the I/O, after the FROM move. GO TO DEPENDING fires before the transfer.
  PERFORM VARYING, AFTER and UNTIL fire after each initialization, change or test.
- DEBUG-NAME: the name with its OF/IN qualifier chain, 30 characters. DEBUG-CONTENTS: the referenced item's content.
  DEBUG-SUB-1..3: the occurrence numbers in written order, outermost first; unused ones spaces.
- DEBUG-CONTENTS is as long as the largest of 30 and each data-name target (and each file's maximum record, PB4811).
- SORT, MERGE, RELEASE and RETURN fire no data trigger.
- A subscripted or reference-modified target is refused.

**Sites:**
- `docs/CONTROL_FLOW_DESIGN.md` (a new section for the debug facility, written FIRST from PB4808 under rule 2)
- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/ProcedureTableBuilder.cs#FinalizeDebug`
- `src/WiseOwl.Cobol.Compiler/Binding/Bound/BoundTree.cs#BoundDebugSubject`
- `src/WiseOwl.Cobol.Compiler/CodeGen/DispatchEmitter.cs` (the after-statement trigger dispatch; members named by the design)
- `src/WiseOwl.Cobol.Runtime/Control/DebugItem.cs#DebugItem`

**Edition.** The debug module is in the 1985 edition only (deleted in 2002); the trigger is accepted where the edition matrix
accepts USE FOR DEBUGGING today.
