# PB4810 - the data-name debugging trigger

**What fails.** `USE FOR DEBUGGING ON <data-name>` and `ON ALL REFERENCES OF <data-name>` are refused COBOL1571 (staged in
`ProcedureTableBuilder.FinalizeDebug`), so a legal 1985/2002-era debug declarative on a data item does not compile (CCVS DB205A
and the DB201A family's data triggers).

**The rules to implement** (sources and line numbers in kb/Work/PB4808.md, Findings):
- A bare data-name fires after any statement in which it is a receiving operand (a store an ON SIZE ERROR path skips included);
  `ALL REFERENCES OF` fires after any statement that references it.
- Each operand fires at most once per statement, nested statements included (Micro Focus rule 7).
- WRITE and REWRITE fire the record's trigger BEFORE the I/O, after the FROM move. GO TO DEPENDING fires before the transfer.
  PERFORM VARYING, AFTER and UNTIL fire after each initialization, change or test.
- DEBUG-NAME: the name with its OF/IN qualifier chain, 30 characters. DEBUG-CONTENTS: the referenced item's content.
  DEBUG-SUB-1..3: the occurrence numbers in written order, outermost first; unused ones spaces.
- DEBUG-CONTENTS is as long as the largest of 30 and each data-name target (and each file's maximum record, PB4811).
- SORT, MERGE, RELEASE and RETURN fire no data trigger.
- A subscripted or reference-modified target is refused.

**Sites:**
- `docs/CONTROL_FLOW_DESIGN.md` (a new section for the debug facility, written FIRST from PB4808 under rule 2)
- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/ProcedureTableBuilder.cs#FinalizeDebug`
- `src/WiseOwl.Cobol.Compiler/Binding/Bound/BoundTree.cs#BoundDebugSubject`
- `src/WiseOwl.Cobol.Compiler/CodeGen/DispatchEmitter.cs` (the after-statement trigger dispatch; members named by the design)
- `src/WiseOwl.Cobol.Runtime/Control/DebugItem.cs#DebugItem`

**Edition.** The debug module is in the 1985 edition only (deleted in 2002); the trigger is accepted where the edition matrix
accepts USE FOR DEBUGGING today.

## Landed (wave 20261885, group A)

The note reproduced on the tree (COBOL1571 for every data trigger, CCVS DB201A). The fix is `docs/CONTROL_FLOW_DESIGN.md` D20, written
from the X3.23-1985 Debug module (the owner's copy, USE FOR DEBUGGING general rules 5-7 and 11-24, which the note's GnuCOBOL and Micro Focus
reading precedes): a data-name or ALL REFERENCES OF operand is a `BoundDebugTarget`; `StatementBinder.BindStatement`, the one funnel, asks
`DebugTriggerPlanner` which fires the statement itself causes and wraps it in `BoundDebugTriggered`; `DebugTriggerEmitter` places them.
Where the 1985 text decides, it replaces the note's list: SORT, MERGE, RELEASE and RETURN DO run the ALL REFERENCES OF section (rule 5 d), and
the WRITE/REWRITE/GO TO DEPENDING/PERFORM moments are the ones the note lists. A subscripted or reference-modified target is COBOL6334 (syntax
rules 10 and 12), a repeated one COBOL6335 (syntax rule 6). Determinations: `docs/CONFORMANCE.md` D-DEBUG-DATA, D-DEBUG-SUB. CCVS DB201A now runs
with no failing test (4 tests deleted by the program's own logic, 8 for inspection). Goldens `pb4810-debug-*` (four accepted at 85, among them the WRITE and REWRITE exception paths: a duplicate-key INVALID KEY and an unopened file, I-O status 22 and 48; two refused).

## Landing

For the next implementer of a statement-level debug trigger:
- `Binding/Bound/DebugTriggerPlanner.cs#DebugTriggerPlanner.Plan` owns the rules; a new moment is a `DebugWhen` and a branch in `PlanLeaf`. REUSE `BoundReferences.Of` and `BoundStores.DirectStoreOf`, never a new per-node list. Trap: `BoundReferences` must stay stateless and outside any `object`-typed field (`BackendContractDriftTests` walks every type of the `Bound` namespace), and the bound layer may not name `Binding.Procedure` (`ArchitectureEdgesDriftTests` ratchet).
- `CodeGen/Verbs/DebugTriggerEmitter.cs#DebugTriggerEmitter.Emit` holds the interior moments for the verb's emitter (`LandBeforeIo`, `LandAfterAction`, `TakeLoopFires`); a verb that has such a moment calls it, and a fire nobody lands throws at the wrapper.
- `Binding/Bound/StatementBinder.cs#BindStatement` is the one funnel: plan AFTER `EcWrap`, skip a debugging section's paragraphs (`_inDebuggingSection`).
- `CodeGen/Verbs/ControlFlowEmitter.cs#InitVaryingTarget` and `Augment` are the store sites two drift lists name (`SetIndexAmountLandingDriftTests`); the debug phases wrap them in `InitVaryingLevel` and `AugmentLevel`, so do not rename the stores.
- `Binding/ImplicitRegisters.cs#ActivateDebugRegisters` is idempotent per width: `FinalizeDebug` re-runs it with the widest target.
- `tests/doc-facts/compiler-facts.json` lists every diagnostic code: regenerate it (`WISEOWL_COBOL_WRITE_DOC_FACTS=1`) with a new descriptor.

**Left open, found on the way (PB4811's neighbours, not this mechanism):** the file-name trigger (PB4811) lands its fires through the same
`DebugWhen` and `DebugTriggerEmitter` hooks (a new `DebugFire` kind per OPEN, CLOSE, READ, DELETE and START, `LandAfterAction` for READ) and
widens DEBUG-CONTENTS by each file's largest record through `ProcedureTableBuilder._debugContentsWidth`.
