# PB1554

Found 2026-09-24 by the golden-lane-2 misc-p20 refuter: `python scripts/spec/cite.py --check 8.5.1.9.1 "The current
capacity of a dynamic-capacity table may be initialized explicitly in the FROM phrase"` prints `OK §8.5.1.9.1 3)
(General)`, but the sentence is the unnumbered paragraph after list item 3); item 3) is about where a dynamic table may
be defined. The writer of `2014/l1c20_capacity_register_set_and_read` had already hand-annotated the same shape for
§14.9.16.4, so this has bitten at least twice.

Fix: make cite.py's locator end a list item at the paragraph break that closes the list, and print the paragraph as
`(General) ¶ after N)` (or its own ordinal) — then re-check every golden header and code comment that carries a `N)`
label produced for a post-list paragraph (`audit_code_citations.py` / `audit_doc_citations.py` re-run).

Second shape (misc-p24 refuter): cite.py labels a REPLACE rule `7) a) 2.` where the printed label is `7) b)` — the
locator mis-nests sub-items, not only post-list paragraphs.

Third shape (misc-p26): cite.py's text matcher ignores operator symbols, so `--check 8.7.5.2 "<> is an abbreviation for
NOT EQUAL"` resolves to SR8 (specs/ISO_COBOL.md:7851 is SR11). The matcher must treat special-character tokens as text.
