# PB1160 — OPEN

## The rule (every citation re-run by the registrar through `cite.py --check`)

> 1) If the RESUME statement is executed within the scope of execution of a global declarative, it is the equivalent of the execution of a CONTINUE statement.

`python scripts/spec/cite.py --check 14.9.33.4 "…"` → `OK  §14.9.33.4 1)  (General rules)`

> 2) The RESUME statement shall not be specified in a declarative procedure for which the GLOBAL phrase is specified in the associated USE statement.

`python scripts/spec/cite.py --check 14.9.33.3 "…"` → `OK  §14.9.33.3 2)  (Syntax rules)`

> 4) Procedure-names within a declarative section may be referenced in a different declarative section or in a nondeclarative procedure only with a PERFORM statement.

`python scripts/spec/cite.py --check 14.9.49.3 "…"` → `OK  §14.9.49.3 4)  (Syntax rules)`

## Finding — `resume-statement` (wrong-answer; rows `GR-14.9.33.4-1`)

**Mechanism.** RESUME is emitted unconditionally as a ResumeSignal throw; §14.9.33.4 GR1's dynamic 'within the scope of execution of a global declarative => CONTINUE' is modeled only as __RunGlobalUse discarding the resume ACTION after the throw has already unwound the declarative, and the local tier does not even discard

**Repro.** probe/resume-statement/gr1a.cob: DECLARATIVES. G SECTION. USE GLOBAL AFTER STANDARD ERROR PROCEDURE ON F. G1. DISPLAY "G-START". PERFORM D. DISPLAY "G-END". D SECTION. USE AFTER STANDARD ERROR PROCEDURE ON OUTPUT. D1. DISPLAY "D-START". RESUME NEXT STATEMENT. DISPLAY "D-AFTER-RESUME". END DECLARATIVES. MAIN SECTION. M1. OPEN INPUT F (file absent). DISPLAY "MAIN-AFTER-OPEN " FS. STOP RUN. Variants: gr1b.cob (the OPEN in a contained program, so the container's __RunGlobalUse runs G) and gr1c.cob (RESUME AT M2 instead of NEXT STATEMENT).

**Expected from the spec.** G-START / D-START / D-AFTER-RESUME / G-END / MAIN-AFTER-OPEN 35 (gr1c: same - the RESUME AT M2 is a CONTINUE, M2 is never reached). §14.9.33.4 1) makes the RESUME a CONTINUE because it executes within the scope of execution of GLOBAL declarative G, which reached D legally by PERFORM (§14.9.49.3 4)).

**Observed / reasoning.** gr1a: G-START / D-START / MAIN-AFTER-OPEN 35. gr1b: G-START / D-START / INNER-AFTER-OPEN 35 / MAIN-END. gr1c: G-START / D-START / M2-JUMPED. The remainder of D and of G is skipped (and in gr1c a GO TO is performed). EcEmitter.EmitResume never consults the run-time `__useActive[global ids]` test that EmitterState.InGlobalDeclarativeRangeTest already builds for EC-FLOW-GLOBAL-GOBACK (PB409); the fix is to make the emitted RESUME a no-op while that test is true (one mechanism for 'in a global declarative's range' across GOBACK and RESUME), and the __RunGlobalUse comment that cites GR1 for discarding the action should be corrected - PB368's refutation answered what the RAISER does, not what the RESUME statement does.

**Code site.** src/Cobol.Net.Compiler/CodeGen/EcEmitter.cs#EmitResume; src/Cobol.Net.Compiler/CodeGen/ProgramEmitter.cs#EmitRunGlobalUse; src/Cobol.Net.Compiler/CodeGen/EmitterState.cs#InGlobalDeclarativeRangeTest

## Finding — `resume-statement` (under-rejects; rows `SR-14.9.33.3-2`)

**Mechanism.** BindResume answers the WHEN-phrase question before the GLOBAL-declarative question, so a RESUME in a WHEN phrase of an exception-checking PERFORM nested inside a USE GLOBAL declarative escapes §14.9.33.3 SR2's flat prohibition

**Repro.** probe/resume-statement/sr2w.cob: DECLARATIVES. G SECTION. USE GLOBAL AFTER STANDARD ERROR PROCEDURE ON F. G1. PERFORM ADD 1 TO N WHEN EC-SIZE RESUME NEXT STATEMENT END-PERFORM. END DECLARATIVES. MAIN SECTION. M1. STOP RUN. (compile at --std 2023)

**Expected from the spec.** Rejected with COBOLNET0713: 'The RESUME statement shall not be specified in a declarative procedure for which the GLOBAL phrase is specified in the associated USE statement' (§14.9.33.3 2)) has no exception for a statement nested in a WHEN phrase inside that declarative.

**Observed / reasoning.** Compiles clean. EcBinder.BindResume: `if (where.InPerformWhen) { ... return new BoundResume(NextStatement); }` precedes `if (decl.Global) return ... COBOLNET0713`. The GOBACK/EXIT sibling screen PlacementRules.RefusedInGlobalDeclarative asks InGlobalDeclarative regardless of the WHEN frame; RESUME should ask it first too (the direct case is already refused and tested).

**Code site.** src/Cobol.Net.Compiler/Binding/Procedure/Verbs/EcBinder.cs#BindResume

## What the fixer owes

ONE mechanism for 'in a global declarative's range' across GOBACK (PB409's EmitterState.InGlobalDeclarativeRangeTest / the `__useActive[global ids]` test) and RESUME: the emitted RESUME is a no-op while that test is true. Correct the __RunGlobalUse comment that cites GR1 for discarding the resume ACTION (PB368's refutation answered what the RAISER does, not what the RESUME statement does). In EcBinder.BindResume ask InGlobalDeclarative FIRST (the PlacementRules.RefusedInGlobalDeclarative order GOBACK/EXIT already use), then the WHEN-phrase question. Goldens: gr1a/gr1b/gr1c at 2002 (positive: G-START / D-START / D-AFTER-RESUME / G-END / MAIN-AFTER-OPEN 35) and sr2w as a negative (COBOLNET0713).
