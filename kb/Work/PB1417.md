## Finding — `function-address-identifier` (rejects-legal-source; rows `SR-8.4.3.12.3-1`)

**Mechanism.** BindSetFunctionAddress screens identifier-1 on namePlace.Item.Pic?.Category, which is null for a group item, so an alphanumeric (or national) group item - and a reference-modification of one - is refused as 'category (none)'.

**Repro.** 01 WS-NAMES. 05 WS-NAME PIC X(6) OCCURS 2.  ...  SET FP1 TO ADDRESS OF FUNCTION WS-NAMES   and   SET FP1 TO ADDRESS OF FUNCTION WS-NAMES(7:6)   (probe/fai/p1b.cob, p1c.cob)

**Expected from the spec.** Both accepted: 8.4.3.12.3 SR1 requires category alphanumeric or national; 8.5.2.1 'an alphanumeric group item has class and category alphanumeric'; 8.4.3.3.4 GR6 gives the reference-modified unique data item the same class and category as identifier-1. With WS-NAMES(7:6)='FAIDBL' the pointer is non-NULL (8.4.3.12.4 GR1 a).

**Observed / reasoning.** error COBOLNET1960: ... identifier-1 shall be of category alphanumeric or national (ISO 8.4.3.12.3 SR1) - 'WS-NAMES' is of category (none); same for 'WS-NAMES(7:6)'. The category test reads the elementary PICTURE category only; group category is never derived (sibling sweep: any other binder that tests Pic?.Category for an alphanumeric-or-national operand has the same hole).

**Code site.** src/Cobol.Net.Compiler/Binding/Procedure/Verbs/SetBinder.cs#BindSetFunctionAddress (the namePlace.Item.Pic?.Category test, ~line 755)

## What the fixer owes

Screen on the item's CATEGORY via ItemCategory (groups are alphanumeric/national by §8.5.2), not on Pic; sweep other `.Pic?.Category` screens (grep).
