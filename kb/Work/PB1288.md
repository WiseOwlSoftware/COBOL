# PB1288 — LANDED 2026-10-04 (wave 1011, implementer E)

## Landed

All in the flat per-RD screen `ScreenReportEntryClausePresence` (COBOLNET2247, once per WRITTEN entry): **SR5** — a level 1 entry with no TYPE and a TYPE below level 1 are refused, and `BindReportEntry` binds a TYPE clause at level 1 only (a stray one used to retype its enclosing group); **SR9** — the COLUMN entry's own LINE clause or an ancestor's, by `SubordinateToLineClause` (PB1224 is this rule seen from the COLUMN clause); **SR12** — a PICTURE in every elementary SOURCE or SUM entry whether or not it prints, SR14's VALUE-only case staying in the binder's PICTURE arm. The two COBOLNET0899 descriptors that carried genuine errors, `report-column-without-line` and `report-item-missing-picture`, are deleted and their callers moved to COBOLNET2247. **GR2 (§13.15.4)** — the printable item now runs the data division's `BlankWhenZeroViolation` / `JustifiedViolation` predicates (COBOLNET2405, `ClauseSubjectCategory`: the one rule, not a copy) and clears the clause on a violation, as `CheckClauseSubjects` does; the report arm was the second arm of PB507's two-arm rule. Pinned by `negative/pb1288-*` (8 programs), `negative/pb1224-report-column-without-line` and `85/pb1288_report_entry_placement`.

## Measured

### Finding report-group-description-entry — §13.15.3 SR5 (under-rejects; rows SR-13.15.3-5)

**Mechanism.** report-type-clause-placement-unscreened: nothing checks where a TYPE clause is written. BindGroupType runs for a TYPE clause at any level and overwrites the enclosing group's Kind, and ReportGroupModel.Kind defaults to Detail, so a level 1 entry without TYPE silently becomes a detail group

**Repro.** (a) 01 D1. 03 LINE 1. 05 COLUMN 1 PIC X SOURCE WA. + GENERATE D1 (probe rgde/sr5notype). (b) 01 D1 TYPE DE. 03 LINE 1 TYPE RH. 05 COLUMN 1 PIC X SOURCE WA. + GENERATE D1 (probe rgde/sr5typesub)

**Expected, from the standard.** Both programs are refused at compile time under §13.15.3 SR5: 'The TYPE clause may be specified only in a level 1 entry and shall be specified in every level 1 entry.' (a) breaks the second half and (b) the first.

**Observed.** (a) compiles and prints `A` (rc 0) at --std 85, 2002 and 2023. (b) is not refused at the TYPE clause. The subordinate TYPE RH retypes D1 as a report heading, and the program then fails only at `GENERATE D1` with COBOLNET0899 'the named report group is not a DETAIL group (ISO §14.9.16.3 SR1)'. Without that GENERATE the group would silently print as a report heading.

**Code site.** src/Cobol.Net.Compiler/Binding/DataBinder.Reports.cs#BindReportEntry (clause loop `BindGroupType(t, group, model)` with no level test); #ReportGroupModel.Kind default

### Finding report-group-description-entry — §13.15.3 SR9 (under-rejects; rows SR-13.15.3-9)

**Mechanism.** report-column-subordination-read-as-line-in-effect: §13.15.3 SR9 is a SUBORDINATION rule, but the binder asks whether a report line is 'in effect' (`st.Line`, the last line opened in the group, reset only at level 1). A COLUMN entry that follows a LINE entry's subtree without being subordinate to it passes, and is silently placed on that earlier line

**Repro.** 01 D1 TYPE DE. 03 LINE 1. 05 COLUMN 1 PIC X SOURCE WA. 03 COLUMN 5 PIC X SOURCE WB. + GENERATE D1 (probe rgde/sr9sib; sr9deep is the cousin variant under 03 G1 / 03 G2)

**Expected, from the standard.** Refused at compile time. §13.15.3 SR9: 'Every elementary entry with a COLUMN clause but no LINE clause shall be subordinate to an entry with a LINE clause.' The 03 COLUMN 5 entry is subordinate only to the 01 entry, which has no LINE clause.

**Observed.** Compiles (rc 0 at --std 85, 2002, 2023) and prints `A   B` on report line 1. The fully line-less case (sr9none) is refused, but on COBOLNET0899 (the 'recognized but not implemented' code) citing §13.18.14, not §13.15.3 SR9. The fix belongs in the flat per-RD screen family (ScreenReportLineNesting / ScreenReportEntryClausePresence), which already walks subordination on the level-number hierarchy.

**Code site.** src/Cobol.Net.Compiler/Binding/DataBinder.Reports.cs#BindReportEntry (`if (line is null)` -> DiagnosticCatalog.ReportColumnWithoutLine); #ReportGroupBuild.Line

### Finding report-group-description-entry — §13.15.3 SR12 (under-rejects; rows SR-13.15.3-12)

**Mechanism.** report-picture-required-only-on-printable-branch: the SR12 PICTURE requirement is asked only inside BindReportEntry's `columns.Count > 0` printable-item branch, so an elementary SOURCE or SUM entry without a COLUMN clause, which is legal, is never checked for its required PICTURE

**Repro.** (a) 01 D1 TYPE DE. 03 LINE 1. 05 COLUMN 1 PIC X SOURCE WA. 05 SOURCE WB. (probe rgde/srcnopic). (b) RD R1 CONTROL FINAL ... 01 TYPE CF FINAL. 03 LINE 3. 05 S1 SUM WN. 05 COLUMN 1 PIC X VALUE "T". (probe rgde/sumnopic)

**Expected, from the standard.** Both are refused. §13.15.3 SR12: 'A PICTURE clause shall be specified in every elementary entry that has a SOURCE or SUM clause.' The rule has no COLUMN condition, and §13.18.54.4 GR1 sizes the sum counter from that PICTURE.

**Observed.** Both compile and run (rc 0). (b) creates a sum counter whose description the standard requires the programmer to supply. With a COLUMN clause (`05 COLUMN 1 SOURCE WA.`) the rule IS enforced (COBOLNET0899 citing SR12), but on the shared 'not implemented' code.

**Code site.** src/Cobol.Net.Compiler/Binding/DataBinder.Reports.cs#BindReportEntry (DiagnosticCatalog.ReportItemMissingPicture inside `if (columns.Count > 0)`); #BindSumClause
