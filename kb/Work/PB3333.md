# PB3333 — RELATIVE on the engine

Implement FROM `docs/rearchitecture/DESIGN-runtime-library.md` §2.2.1, sections 2.2.1.3 (decision 3), 2.2.1.4 ("A RELATIVE
record is one entry"), 2.2.1.5, 2.2.1.9 (the boundary and the new DOC-A.1-107 text, relative half) and 2.2.1.13 (what is
deleted). Follows PB3332 (the tree). The INDEXED organization keeps the whole-store path until PB3334; PB3335 deletes it.

## Mechanism

- `RelativeConnector` opens a `PagedStore` for the physical file (the `StoreTable` entry of the run unit, kb/Work PB143's
  one-store-per-path contract kept: `Attach`, `AttachCreated` with the PB754 refusal, `Detach`) and holds ONE tree keyed by the
  8-byte big-endian relative record number, value = the record's frame (`RecordFraming.EncodeFrameHead` + channel payload, the
  one codec). `OPEN OUTPUT` and the absent-OPTIONAL creation arms call `PagedFile.Create` through the connector's own handle
  (§14.9.27.4 GR17/GR18); every other arm `PagedFile.Open` (the adoption rule). The meta page carries the §9.1.6 attributes, so
  `FixedAttributeConflict` reads `MetaPage.Describes`.
- READ by key = `Seek(=)`; READ NEXT / PREVIOUS = the cursor from the file position indicator under §14.9.30.4 GR21 b)/c) exactly
  as `SelectSequentialSlot` selects today (rule b) inclusive and direction-blind, rule c) exclusive); START = `Seek` with the
  relational operator (§14.9.41.4 GR9), START FIRST/LAST = `First`/`Last`; WRITE random = insert or '22'; WRITE sequential =
  `Last` + 1 clamped by `_lastReleasedSlot` (§14.9.51.4 GR29 a), `NextSequentialSlot` unchanged in meaning); REWRITE = `Replace`;
  DELETE = `Delete`. The statuses and their order (DOC-A.1-104) are the connector's as today; only the medium changes.
- The boundary: `StoreHolds`/`FramedBytesAfterPut` go; a WRITE or REWRITE answers '24' when the engine reports the format ceiling
  or the host's file-too-large refusal, '30' for a full medium (2.2.1.9), and `HighestRelativeRecordNumber`'s '34' stays.
- The dirty pages and the work meta are written at `StoreStatement.Complete` for EVERY relative connector (one statement path),
  the page-2 read and cache drop only for a coherent one. **The coherence condition lands HERE, with the engine** (2.2.1.7,
  2.2.1.14): a connector on the engine is coherent when its sharing mode admits any other run unit's connector — every mode
  but `NO OTHER`, `FileLockPosture.AdmitsAnotherRunUnit`, a new predicate beside `AdmitsAnotherWriter` — because an engine that
  writes at every statement must serialize a `SHARING WITH READ ONLY` writer against the INPUT reader Table 19 admits beside
  it; the indexed connector, still on the whole-store path until PB3334, keeps `AdmitsAnotherWriter` (it persists at CLOSE
  under the mutex, as today), so `KeyedConnector._coherent` is derived from the engine the connector drives, and no landing
  between this group and PB3335 leaves a relative writer unserialized. The coherent statement keeps
  `KeyedConnector.BeginStatement`'s mutex, reads page 2, and adopts it with `PagedStore.DropCache` when its `generation`
  differs from the one the store last saw (R6's choice at OPEN until then), raises its next claim when `stamp mint` is above
  it, and resolves a PROMOTING flag it finds set (2.2.1.7, rounds 3 and 4: `CompletePromotion`'s restart rule); a changing
  statement CLAIMS in the store's memory — its generation and every mint it advances, its own last claim kept whether or not
  the statement completes — and, when coherent, on page 2 before its first page write; a `NO OTHER` statement's claim is the
  memory alone, which its CLOSE's promotion writes to page 2, so a retirement never re-stamps a refused statement's page
  (round 4, R4-3); the dead-owner step of the entry is PB3337's (the TRANSACTIONS tree is empty until then). `Reload` is not called by the relative path. Every OPEN runs `PagedFile.Open` (R6, with the fence
  through a writable handle) under the store mutex.
- `docs/CONFORMANCE.md` DOC-A.1-107: the relative sentences replaced by 2.2.1.9's text. DOC-A.1-75: its relative half is
  rewritten in this landing, because the mutex rule changes for RELATIVE files the day it lands: its statement-mutex
  sentence states that a RELATIVE connector under every sharing mode but NO OTHER runs each record statement under the
  store mutex with the page-granular wording of 2.2.1.7 (one meta-page read, a cache drop, its pages written at the
  statement), and keeps today's wording (`SHARING WITH ALL OTHER`, the whole file re-read when the stamp moved) for INDEXED
  files only, so the row is true between this landing and PB3335's; PB3335 rewrites the rest.

## Closes a note filed before the engine

`StartFirstLast` and `RelativeStore.Remove` answer every positional question by walking `_slots` from the lowest RRN, so a
READ NEXT walk of N records visits N(N+1)/2 keys. The tree keyed by the relative record number replaces that map, so this
group's landing sets PB2755 to `status: landed` (closes_rows_reason naming PB3333), and its scenario is one of PB3336's
count-based cells. Operator, 2026-10-17: PB2755 is `blocked_by` this note and is not planned on its own.

RELATIVE runs on the keyed store engine. `RelativeConnector` drives `RelativeStore` (`IO/KeyedStoreTable.cs`): the run unit's
page I/O over its connectors' own handles (`Store/RunUnitPageMedium`), one `PagedFile` and one B+ tree keyed by the 8-byte
big-endian relative record number, value = `RecordFraming.EncodeFrame` (the one frame codec, `DecodeFrame` through
`ReadFrame`). READ / START are seeks (§14.9.30.4 GR21 b)/c), §14.9.41.4 GR9); WRITE / REWRITE / DELETE are each one page-layer
statement (`RelativeStore.Change`). The coherence condition lands with it: `KeyedConnector.CoherentUnder` — relative asks the new
`FileLockPosture.AdmitsAnotherRunUnit`, indexed keeps `AdmitsAnotherWriter`; OPEN's adoption and CLOSE's promotion run under
the mutex (`InStoreMutex`). The boundary is the host's ('24' for `ERROR_FILE_TOO_LARGE`/`EFBIG` at growth and for 2^32 pages,
`StoreStatus.Boundary`; '30' for a full medium, at the statement); `StoreHolds`/`FramedBytesAfterPut` deleted for RELATIVE,
the whole-store machinery moved to `IndexedConnector.WholeStore.cs` (PB3335 deletes it). `Store/PageCache` (LRU, RESERVE
floor, dropped on adoption). DOC-A.1-107 and DOC-A.1-75's relative halves rewritten; DESIGN-runtime-library 2.2.1.7 and
2.2.1.14 corrected (the verb writes its own statement; CLOSE promotes only what changed). Cases: `RelativeEngineTests`
(death after every write and refusal at every write of WRITE/REWRITE/DELETE/CLOSE under ALL OTHER, READ ONLY and NO OTHER,
