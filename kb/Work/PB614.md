# PB614 — OPEN — a real clause answering a different question, eighteen times

Found 2026-09-05 by the `PB238` implementer's citation sweep (report §14 c), which corrected the four sites it
wrote and the one user-visible message and left the rest; re-derived on this tree for this note.

## The rules

```
python scripts/spec/cite.py --check 13.10.3 "constant-name-1 may be used anywhere that a format specifies a literal of the class and category of constant-name-1"
OK  §13.10.3 2)       ← ADMISSION: where a constant-name may be written
python scripts/spec/cite.py --check 13.10.4 "the effect of specifying constant-name-1 in other than this entry is as if literal-1"
OK  §13.10.4 1)       ← SUBSTITUTION: what writing it means
python scripts/spec/cite.py --check 13.10.4 "the class and category of constant-name-1 is the same as that of literal-1"
OK  §13.10.4 2)       ← CLASS
```

A comment that says "substitute the constant's literal (§13.10.3 SR2)" cites a rule that says something else
true; `--check` cannot tell, which is `feedback_a_real_clause_can_answer_a_different_question` and the class
`PB591`/`PB597` name from the audits' side.

## The sites

`grep -rn "13.10.3 SR2" --include=*.cs src/` → `DataBinder.Constants.cs` (×10), `DataBinder.cs` (×4),
`DataBinder.Odo.cs`, `ExpressionBinder.cs` (×3) at the time of the sweep — each to be read individually:
where the comment explains WHERE a constant-name is admitted, SR2 is right; where it explains WHAT the
binder substitutes, the citation is GR1 (and GR2 for the class).

## Fix shape

A citation sweep with a re-derivation per site (not a find-and-replace — some sites genuinely mean the
admission), the user-visible messages first; the one audit that would have caught it is PB597's rule-ordinal
semantics check, which this note is a measured input to.
