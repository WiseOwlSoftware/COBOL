# PB1635 — OPEN

Found 2026-09-27 while validating PB1628's citations.

## Observation
`python scripts/spec/cite.py --check 8.8.3.3 "equivalent to a literal"` prints `OK §8.8.3.3 c)`. The sentence is
General rule **3** ("3. A concatenation expression shall be equivalent to a literal of the same class and value…"),
which is what the code cites. `--check 8.8.3.2 "figurative constant"` printed `§8.8.3.2 ` with an empty rule. Both
clauses number their rules `1.`, `2.`, `3.` at column 0, while the transcription's convention elsewhere is `1\)`.
`cite.py`'s `TOP = ^(\d+)\\?\)\s` does not match the period form, so the rule path falls back to the last sub-item
seen. `grep -c "^[0-9]\+\. " specs/ISO_COBOL.md` = 263 lines, and some of them may be legitimate numbered lists
(Annex prose), not rules.

## Harm
The citation gate (CLAUDE.md rule 1) is the tool that re-derives a clause number, and here it reports a WRONG one for
a correct citation. An author who trusts it would "correct" GR3 to GR1 c), which is exactly the inherited-citation
failure the rule exists to stop.

## To decide
Render the printed pages (`scripts/render-spec-page.py`) for §8.8.3.2/§8.8.3.3 and a sample of the other 261 lines.
If the PDF prints `1)`, the fix is a transcription correction (fix on discovery, plus the lint/drift test that
would have caught it). If it prints `1.`, `cite.py` must accept both forms. Either way, add a self-test case.
