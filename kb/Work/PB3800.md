# PB3800 — the GUI guard misses an assigned Start-Process and a spaceless call operator

**Sites:** `scripts/hooks/gui_launch.py` (`_command_word`, `refusal`), `scripts/hooks/test_forbidden_commands.py`

## Measured

The PB3798 reviewer verified both end to end on head d892de597 (forbidden_commands.py exits 0):
- R3-2: a PowerShell statement starting with a variable returns no refusal, but an assignment runs its right-hand side:
  `$p = Start-Process obsidian -PassThru`, `$null = ii x.md`. `_command_word` skips only Bash `NAME=value` prefixes. The
  Obsidian incident's own commands were `$p=Start-Process ...` (wave 20261703 group B transcript), so the guard as landed
  would not have stopped it.
- R3-1: `&('obsidian')` / `.('obsidian')` with no space is one word whose inner quoted substitution step is exempted
  (gui_launch.py line 203); pwsh runs it.
The implementer's own residue lead: a computed name (`& ("obs" + "idian")`), an unknown GUI exe by path, or a GUI
started from a script the agent writes then runs is not caught; a deny list cannot be complete, so the acceptance asks
for the shape that makes the next case automatic (CLAUDE.md rule 5).

## Acceptance

- Both forms above are refused, each with a self-test case, including the incident's exact command line.
- The design question is answered in the report with evidence: keep a deny list with these arms, or refuse
  `Start-Process`/`ii`/`start` by default and allow only listed console tools (an allow list makes an unknown GUI exe
  refused, not passed); the chosen shape carries a drift test.

## Retired 2026-10-25

The owner, 21:15 PDT: "The easiest way is to simply not run Obsidian, rather than all these stupid overhead filters to
catch something we shouldn't be running." No filter arms are added; PB3801 removes the guard itself.
