# PB2520

Filed from the PB1943 refuter (`E:\COBOL-coord\scratch\w1033-adj\PB1943-refute.md` section 4: "a wrong-answer sibling of the `PicInfo.SumCounterItem` site that the fix has to sweep, along with every LENGTH or size consumer of the register").

**Observed (pinned build `pin-97006f3`; `PB1943-refute\unpr.cob`).** With `03 CF-T COLUMN 1 PIC 9999 SUM WS-X`, `FUNCTION LENGTH(CF-T)` prints 2 (`Z=[1234] L=[02]`), the binary size of the register. Under any DISPLAY ruling for the counter it must be 4 (the digits `§13.18.54.4 GR1` derives from the PICTURE). The refuter's wording: wrong under any DISPLAY ruling; what the counter's representation is stays implementor latitude (decided in `PB1943`), so the exact expected value is owed by that ruling.

**Site.** `src/Cobol.Net.Compiler/Binding/Model/PicInfo.cs#SumCounterItem` (built at `DataBinder.Reports.cs:3770`) models the counter as `Usage.Binary`; sweep every LENGTH or size consumer of the register. `§13.18.54.4 GR5` (cite.py --check OK): the data-name is the name of the sum counter. This is the same register profile PB1943's reference-modification fix must change, so land them together. Related: `PB1943`, `PB2521`.
