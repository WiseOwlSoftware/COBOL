# PB5365 - Communication runtime comments carry citations cite.py never checked: SetNothingReceived's END KEY change cites only the input CD rule and is untested, PartlyReceivedFrom cites 2002 14.5.10 for abnormal end

**Sites:**

- `src/WiseOwl.Cobol.Runtime/Communication/CommunicationArea.cs:61` (`CommunicationArea.SetNothingReceived`)
- `src/WiseOwl.Cobol.Runtime/Communication/MessageStoreState.cs:185` (`MessageStoreState.PartlyReceivedFrom`)
- the unit test comment that repeats the 14.5.10 citation (find it with `grep -rn "14.5.10" tests/`)

**Mechanism (one, two instances).** A rule citation in a doc comment is the only record of which spec rule a behavior implements, and a citation that is not in the CLAUDE.md rule 1 form (`§<edition>:<locator> <rule>`) is never run through `cite.py`, so it drifts. Two cases from the report: (R1-2) `SetNothingReceived` also changes the input-output CD END KEY (offset 30) on a NO DATA RECEIVE, a behavior change that "no golden or unit test exercises", and whose comment cites only the input CD rule (§1985:XIV.2.2.4 GR12), not the input-output CD rule (GR33 a 3, data-name-5, the report's designator); (R1-3) the `PartlyReceivedFrom` comment cites "ISO/IEC 1989:2002 14.5.10 rule 2" for abnormal end, but 14.5.10 is normal run unit termination and abnormal is 14.5.11 (the report's claim), and the unit test comment repeats it.

**Fix direction.** Re-derive each citation with `cite.py --check` and write it in the rule 1 form; add the input-output CD END KEY case (a RECEIVE NO DATA on an input-output CD) as a unit test or golden, with the expected value from the spec rule; sweep `src/WiseOwl.Cobol.Runtime/Communication/` for other bare edition citations.

**Source.** PB5315's report R1-2 and R1-3.
