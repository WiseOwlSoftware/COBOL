# PB5572 - at --std 85 a RELEASE or RETURN written in the declaratives compiles and runs when no SORT or MERGE of its file has an input or output procedure: GateReleaseReturnRange never asks a declarative statement

**Sites:** `src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs` (`VersionConformancePass.GateReleaseReturnRange`)

**Mechanism.** Since kb/Work PB5104, `VersionConformancePass.GateReleaseReturnRange` refuses (COBOL7081) a RELEASE or RETURN outside the range of every input or output procedure for its file at --std 85. The range is computed by `ProcedureReach.Closure` from the procedures of the SORT and MERGE statements. The gate collects only statements at or after `prog.EntryPc`, so a statement written in the declaratives is never asked. Its own summary gives the reason: the range includes "all statements in declarative procedures that are executed as a result of" the range's statements, which is a run-time fact (and docs/conformance/3/D-SORT-RELEASE-RETURN-RANGE-85.md says the same). That reason holds only where some input or output procedure for the file exists. When the program has no SORT with an input procedure for the record's file (for RELEASE), or no SORT or MERGE with an output procedure for the file (for RETURN), the range is empty, no declarative can run inside it, and the statement is outside every range at compile time. It compiles, and at run time it executes silently with no sort in progress (the RETURN takes its AT END branch).
