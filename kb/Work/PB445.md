# PB445 — seven rules, one missing model

Adjudicated in lane-3 batch b2 (`search-statement` part 1, findings search-p1-F3 and search-p1-F4).
**All eleven repros re-run on HEAD 89044aa0**, each with the legal counterpart that proves the Format-2
machinery is live and it is the screens that are absent.

## 1. The mechanism

`SearchBinder.BindSearchAll` (`src/Cobol.Net.Compiler/Binding/Procedure/Verbs/SearchBinder.cs:81-117`) reads
`table.IndexNames` and `table.Occurs` and **nothing key-related**, and it binds each WHEN through the general
`host.Cond.BindCondition(wc.condition())` as **one opaque expression** (`:102-109`). So neither the ordered key
list nor the WHEN's decomposed operands exist anywhere for a rule to be written against. Every Format-2 syntax
rule needs one of those two things:

| rule | what it needs that does not exist |
|---|---|
| 7 | the key list's existence |
| 8 | key-list membership, plus each operand's subscript and whether it carries `+`/`-` |
| 9 | the condition-name → key association, plus the condition-name's VALUE count |
| 10 | the *complement* of the key list, plus an identifier walk into the arithmetic expressions |
| 11 | the key **order**, plus a per-statement record of which keys the WHEN/AND chain referenced |
| 12 | the variable-length predicate applied to those operands |
| 13 | literal-1 / literal-2 as literals |

This is a **missing model, not seven missing screens**. Writing seven ad-hoc checks against the raw parse tree
would reproduce exactly the fragility the standard's own structure avoids — and rule 12's predicate already
exists (`ReferenceResolver.HasVariableLengthSubordinate`); it is simply never called here, which is the tell
that the operands it would be called on have nowhere to come from.

**The second finding, on the same lines.** The binder's doc comment at `SearchBinder.cs:77-80` states a
conformance argument for its scan technique that rests on a clause about a different question:

> this implementation scans from occurrence 1, conformant since Format 2 requires the table ordered by its
> OCCURS KEYs (SR7) and the WHEN tests key equality.

Syntax rule 7 requires only that the OCCURS clause **carry** a KEY phrase — a requirement on the data
description entry, saying nothing about the run-time ordering of the data. The proposition the comment needs
is the general rule about key sequencing, and that is a condition that shall be true of the **program**, not a
guarantee the compiler may rely on — the following general rule exists solely to define behaviour when it is
false. The argument is unsound twice over (wrong clause; a user obligation dressed as an implementation
guarantee), and it leans on a rule this note measures as entirely unenforced, so it leans on nothing. This is
the `a_real_clause_can_answer_a_different_question` shape: the clause is real, its text is genuinely in the
standard, `--check` passes, and it answers a different question.

The argument is also **unnecessary**, which is what makes it dangerous — it invites a future reader to "fix"
the technique or the enforcement to preserve a justification that was never required.

⚠ **Coverage honesty on rule 12:** only the identifier-3 arm is measured. The data-name-1 arm (a KEY that is

precondition violated) prints `HIT AT 04`, and `gr5_descending` (a correctly-ordered DESCENDING key) prints
`HIT D AT 04`. **No behavioural defect here — a defective argument sitting on top of correct code**, in a
place that will be consulted the next time the technique changes.

## 4. The code site and the shape of the repair

* `.../Verbs/SearchBinder.cs:81-117` `BindSearchAll` — only `IsTable`, `IndexNames.Count` and the
  dynamic-nesting guard; the WHEN loop at `:102-109` binds one opaque condition.
* `.../Verbs/SearchBinder.cs:77-80` — the doc comment carrying the unsound argument.
* `src/Cobol.Net.Frontend/Grammar/Core/CobolControlFlow.g4:241-255` — `searchAllStatement`,
  `searchAllKeyPhrase`, `searchAllWhenClause`. ⚠ `searchAllWhenClause` is `WHEN condition statementBlock*`,
  i.e. the general condition rule in place of Format 2's closed operand shape — **so the operands rules 8-13
  are written about do not exist as parse structure either.** That over-lenient grammar rule is PB446's
  subject, and this note's repair depends on it: the model cannot be built from a rule that does not decompose
  the WHEN.

**The repair, in order (CLAUDE.md rule 5).** (1) Tighten `searchAllWhenClause` to the printed Format-2 shape so
data-name-1, the relational operator, the sending operand and the repeated AND phrase are distinguishable
(PB446). (2) Build a **Format-2 key model** on the bound node: the table's ordered key list from the OCCURS
KEY phrase, and per WHEN/AND entry the resolved key reference, its subscript list, and the sending operand.
(3) Then all seven rules are predicates over that model, written once, in one place — membership, order,
complement, subscript shape, single-valued condition-name, variable-length, zero-length literal — and reported
through the diagnostic channel PB444 says SEARCH still lacks. (4) Delete the syntax-rule-7 clause from the doc
comment and cite the implementor-latitude general rule for the technique and the undefined-choice general
rules for the latitude when the preconditions are false.

**Ordering matters:** the model is what makes the doc comment's argument unnecessary *and* what makes rule 7
enforceable, so the comment must be corrected in the same change or it will be "restored" by the next reader.

## 5. The sibling sweep the fixer must do

* **Format 1's WHEN keeps the general condition rule** — its own syntax rule 6 grants exactly that latitude,
  which is presumably how the Format-2 rule inherited it. Do not tighten both arms; tighten the one the
  standard closes.
* **Every `--check`-passing citation in `SearchBinder`'s comments** must be re-derived, not just this one. The
  same file's INDEXED message miscites itself in two places (PB444).
* **`ReferenceResolver.HasVariableLengthSubordinate`** already exists and is uncalled here; grep for other
  predicates that exist for a rule nobody wired up — an uncalled predicate has never been contradicted.
* **Editions.** Every case reproduces at 85, 2002, 2014 and 2023; Format 2 is COBOL-85, so none of the seven
  rules is edition-gated.

## 6. Rows

All seven are NOT-IMPLEMENTED, and all seven rest on the same measurement: the illegal program compiles clean
and runs, with its legal counterpart measured beside it.

* `SR-14.9.37.3-7` — the KEY phrase requirement: a table with no KEY phrase at all is searched.
* `SR-14.9.37.3-8` — the key-membership and index-subscript requirements, and the `+`/`-` ban: three probes.
* `SR-14.9.37.3-9` — the condition-name requirements: a multi-valued (THRU) condition-name accepted, and the
  `+` ban unenforced.
* `SR-14.9.37.3-10` — the sending operand's exclusion from the key list and from the search index: two probes.
* `SR-14.9.37.3-11` — the preceding-keys requirement: the second key referenced without the first.
* `SR-14.9.37.3-12` — the variable-length-group ban: **the identifier-3 arm only**; the data-name-1 arm is
  untested, blocked by an unrelated rule.
* `SR-14.9.37.3-13` — the zero-length-literal ban.
