# PB1948 — LANDED (wave 1011 B)

Filed by the train-1010 lander from wave 1010 group A's report (`w1010a-PB1294-report.md`, "New defects" item 1).
Same root as [[PB780]] (SR-13.10.3-2 is a whole-language admission; each violating literal position is its own
defect, as [[PB778]] is for EDITING and [[PB1942]] for CURRENCY SIGN). [[PB1947]] fixed the report writer's
integer-n positions (PAGE, LINE, COLUMN, NEXT GROUP, OCCURS STEP / DYNAMIC) with one grammar rule `integerOperand`
and one reader `DataBinder.IntegerOperandValue`; this note is the rest of the language.

## Defect

```
       SELECT F1 ASSIGN TO "SW1.TXT" RESERVE KR AREAS.
       ...
       FD  F1 BLOCK CONTAINS KB RECORDS RECORD CONTAINS KB CHARACTERS.
       ...
       01  KB CONSTANT AS 5.
       01  KR CONSTANT AS 2.
       01  DS PIC X(10) DYNAMIC LENGTH LIMIT IS KB.
```

Each constant operand draws COBOL0309 ("A literal value is expected here"). §13.10.3 SR2
(`cite.py --check 13.10.3 "Except in a compiler directive, constant-name-1 may be used anywhere that a format"` →
`OK §13.10.3 2)`) admits it: each of these formats writes its operand as `integer-n`, a numeric literal, and an
integer constant-name is a literal of that class and category. The value is held to §5.5 1) and to the owning
clause's own rule (unsigned, nonzero where the clause requires it), as `IntegerOperandValue` already does for the
report clauses.

## Landed 2026-10-04 (wave-1011 implementer B)

**Re-probe (own build of 28fc8a7f9).** `sw1.cob` (the program above, with the DYNAMIC item corrected to `PIC X`):
`RESERVE KR AREAS`, `BLOCK CONTAINS KB RECORDS`, `RECORD CONTAINS KB CHARACTERS` and `DYNAMIC LENGTH LIMIT IS KB` each
COBOL0309. Two siblings the note did not name: `LINAGE IS KL LINES WITH FOOTING AT KF LINES AT TOP KT LINES AT BOTTOM KB`
drew COBOLNET1639 on all four operands (the format prints "data-name-1 or integer-1", so the constant parsed as the
data-name arm), and the `pictureLocalePhrase` has two binder readers (data entry, report entry), both bare. PERFORM
`integer TIMES` and WRITE `ADVANCING integer LINES` already accepted a constant (the same dataReference arm, read by the
expression binder).

**Mechanism.** The rest of the language now spells its integer-n positions the way PB1947 spelled the report writer's:
`integerOperand` in `fileReserveClause`, `blockContainsClause`, both `recordClause` formats, `dynamicLengthClause`'s
LIMIT, `pictureLocalePhrase`'s SIZE and `symbolicCharacterEntry`; the ONE reader `DataBinder.IntegerOperandValue`
(`IntegerOperandText` for the full-width DYNAMIC LENGTH LIMIT) reads each. The drift test is inverted: instead of "the
report-writer grammar has no bare integerLiteral" it holds EVERY rule that spells one to
`IntegerOperandRules.LiteralOnlySlots`, a short table of arguments (the four '85 elements ISO 2002 deleted — constants
first exist at 2002; the vendor CHANNEL/RESERVE; the declined SCREEN SECTION; the Segmentation priority-numbers; and the
"data-name or integer" formats LINAGE, PERFORM TIMES, WRITE ADVANCING whose constant-name reaches the binder as the
data-name arm). LINAGE's four operands read the constant through `DataBinder.ConstantOperandValue`, the same reader.
SYMBOLIC CHARACTERS needed a three-alternative entry (literals first, `IS|ARE integerOperand+`, words only) and
`DataBinder.SymbolicEntryGroups`, which re-reads the entry's tokens in source order whatever alternative parsed, because
a constant-name ordinal and the next symbolic-character-1 are the same kind of token and only the unit's constant table
separates them (so `SC-A IS K1 SC-B K2`, which the parse folds into one group, is regrouped as two). BLOCK CONTAINS models nothing, so `BindBlockContainsClause` only
reads (and so validates) its integers. `IntegerOperandRules.RecordClause` now looks through the carrier
(`OperandOf`) when it asks whether an operand follows TO, and `IsFullValueSlot` is the one question the written literal
and the substituted constant share for the host-limit exemption.

LINAGE operand with ZERO top/bottom constants, three SYMBOLIC CHARACTERS spellings; expected lines derived from §13.18.34.4
GR7 c)/d) and §14.9.51.4 GR26), `2002/pb1948_locale_size_constant` (the pb64t6 EC-LOCALE-SIZE verdicts with constant SIZEs),
`2014/pb1948_dynamic_length_limit_constant` (including a constant past the host int: the LIMIT is full width), negatives
`pb1948-block-contains-constant-zero` (COBOLNET2386), `pb1948-reserve-constant-noninteger` (COBOLNET1547),
