# PB3347 — a switch condition-name and a level-88 of the same spelling

Filed 2026-10-17 by the clerk from `w1111d-PB3286-report.md` "New defects" item 2. Kind is adjudication first, because the
report itself says the §8.4.6.1 reading may make the silent resolution correct. Grep of kb/Work for the members
(`SwitchConditions`, `BindImplementorNameEntry`) and the symptom found PB3216 (a second SPECIAL-NAMES declaration is dropped:
declaration), PB454 and PB3153 (neither is this resolution question); none covers it.

## Repro
`E:\COBOL-coord\scratch\w1111d\p\sw1.cob` (the group D worktree's scratch):

```
SPECIAL-NAMES.
    SWITCH-1 ON STATUS IS S-ON.
...
01 V PIC 9 VALUE 1.
   88 S-ON VALUE 1.
PROCEDURE DIVISION.
    IF S-ON DISPLAY "ON" ELSE DISPLAY "OFF" END-IF
```

The unqualified `IF S-ON` binds to the level-88 with no ambiguity diagnostic and prints `ON`, although the switch is OFF.
The report records the clause check as OK; this note re-ran it (below).

## Code sites (origin/main 8307a2143)
- `src/Cobol.Net.Compiler/Binding/DataBinder.Switches.cs:989` `BindImplementorNameEntry`, which registers the ON and OFF
  names at lines 1005-1006 into `SwitchConditions` (declared at line 34, inherited by a contained unit at line 522).
- The resolution side: `ctx.Refs.DescribesOwnItem(dref)` asked before the switch reading (`SetAlterBinder.cs:187-188`,
  `ConditionBinder.cs:1243-1247`, and the other callers a grep of `DescribesOwnItem` lists). The own-item test
  is what lets the 88 win here; there is no ambiguity check between the two declarations.

## Citations (all run through `python scripts/spec/cite.py --check`)
- `--check 8.4.2.1 "In order to use a resource, a statement shall contain a reference that uniquely identifies that resource."` returned OK (§8.4.2.1 General).
- `--check 8.4.6.1 "a source element's reference to such a name, even when it is a different type of user-defined word, is to the item which that source element describes"` returned OK (§8.4.6.1 General). The same paragraph lists "condition-name (declared in a configuration section)" among the words referenced only within the source element that holds the configuration section.
- `--check 8.4.2.2.1 "Qualification of a user-defined name is required unless one of the following is true"` returned OK (§8.4.2.2.1 General): the rule that decides whether two same-spelled condition-names need qualification.

## The question for the adjudicator
1. Reading A (the 88 is correct): §8.4.6.1 says a reference to an identically spelled name is "to the item which that source
   element describes", and the 88 is the item this source element describes; the SPECIAL-NAMES condition-name is only
   reachable where the source element does not describe an item of that spelling. Then the current result is conforming and
   the note closes with a golden that pins it (and a negative showing the switch reading when no 88 exists).
2. Reading B (the pair is ambiguous): §8.4.2.1 requires a reference that "uniquely identifies" its resource and §8.4.2.2.1
   gives qualification no way to separate a configuration-section condition-name from a data-description 88. Then the
   binder owes a diagnostic (new code from the orchestrator's allocation) and PB3216's declaration-side refusal is its
   sibling.
The verdict decides; the fix, if any, follows the shape the verdict names. Probe the sibling spellings the same way before
closing: a mnemonic-name, alphabet-name and class-name against a data-name of the same spelling use the same
`DescribesOwnItem` test, so their answer is the same rule.
