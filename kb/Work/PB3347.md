## The question for the adjudicator
1. Reading A (the 88 is correct): §8.4.6.1 says a reference to an identically spelled name is "to the item which that source
   element describes", and the 88 is the item this source element describes; the SPECIAL-NAMES condition-name is only
   reachable where the source element does not describe an item of that spelling. Then the current result is conforming and
   the note closes with a golden that pins it (and a negative showing the switch reading when no 88 exists).
2. Reading B (the pair is ambiguous): §8.4.2.1 requires a reference that "uniquely identifies" its resource and §8.4.2.2.1
   gives qualification no way to separate a configuration-section condition-name from a data-description 88. Then the
   binder owes a diagnostic (new code from the orchestrator's allocation) and PB3216's declaration-side refusal is its
   sibling.
The verdict decides; the fix, if any, follows the shape the verdict names. Probe the sibling spellings the same way before
closing: a mnemonic-name, alphabet-name and class-name against a data-name of the same spelling use the same
`DescribesOwnItem` test, so their answer is the same rule.

## Adjudication 2026-10-25 (mythos lane, pinned main 51103b9a1)

**Final verdict:** DEFECT  
**Checkpoint (full record):** `E:/COBOL-coord/scratch/mythos/adj-20261025/PB3347.json`

**Expected from the spec:** Reading B. A SPECIAL-NAMES switch condition-name and a level-88 are the SAME type of user-defined word (condition-name, §8.3.2.2.4), so declaring both spellings in one source element is legal (§8.3.2.2's one-type rule is not engaged) but the name is then non-unique: §8.4.2.2.1 requires qualification unless 'No other name has the identical spelling', and §8.4.2.2.3 SR1 requires every explicitly referenced non-unique name to be made unique by qualifiers. Unqualified IF S-ON violates that syntax rule and must be diagnosed (the existing COBOL1639 'does not uniquely identify' family, as for two same-named 88s); IF S-ON OF V is conforming and names the 88 (SR5); the switch reading of that word is unreachable in that element (a switch condition-name takes no qualifier, §8.8.4.6.2). A declaration with no reference is legal and draws nothing. Reading A misapplies §8.4.6.1: that paragraph governs identical names in DIFFERENT, nested source elements ('rather than to the item, possessing the same name, described in another source element'), so it decides only the inherited case: a switch condition-name declared in a CONTAINING program's SPECIAL-NAMES yields silently to the contained program's own 88, which is correct today.
