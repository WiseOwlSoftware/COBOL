## Landed (wave 1115, group C)

**Re-probe on the branch build.** Record sequential, relative and indexed files at `--std 85`, `2002`, `2014` and `2023`:
`OPEN ... WITH NO REWIND` (sequential) answers `07` only when it succeeds; `CLOSE ... WITH NO REWIND`, `REEL`, `UNIT [FOR REMOVAL]`
answer `07` only on an open file; no READ, WRITE, REWRITE, START or DELETE ever answers `07`; an unsuccessful OPEN or CLOSE
keeps its own status (`35`, `41`, `42`, `61`). GnuCOBOL 3.2.0 (WSL, 2026-10-17) gives `07` from `CLOSE` alone (it does not
implement `OPEN ... NO REWIND`) and from no other statement.

**The answer to what the fixer owed.** The refuter was right that the earlier row claimed 85-2014 on the ground that these
were "already the only setters at every edition". Annex E.2 item 16 (`cite.py --check E.2` OK) says the setting "is now
restricted to the execution of the OPEN and CLOSE statements", so an earlier edition let other statements set it, but it
names neither those statements nor the condition they reported, and the repository holds no 1985/2002/2014 text. So there is
no prior rule to implement behind the edition axis: VERSION_CHANGE_REFERENCE row 22 fails its own admission test (an E.2 item
earns a `behavior:` gate only when it says what the prior rule STATED) and is now `ref-only`, a determination that follows
rule 1's order (the standard has nothing for those editions, then GnuCOBOL). The determination is in docs/CONFORMANCE.md
section 3, the older-edition claim is stated as a determination rather than a reading of the older text, and an obtained
text that states a distinct rule would make row 22 a `behavior:` row.

**What now keeps it true.** `IoStatus07SetterDriftTests` (the named constant is read in `CloseByFormat` and
`NoRewindPhraseEffect` only, and the value is spelled nowhere else in the runtime or the code generator), and four goldens
accepted at every edition the rule exists in: `pb1515_io_status_07_open_close_only` (sequential: success and every failure
path, FILE STATUS, USE declarative, AT END), `pb1515_io_status_07_keyed_organizations` (relative and indexed: the same,
INVALID KEY), `pb1515_io_status_07_sharing_conflict` (2002+: a refused OPEN ... NO REWIND answers `61`), and
`pb1515_io_warning_07_raises_ec` (2023: `07` is the exception condition EC-I-O-WARNING, raised by OPEN and CLOSE alone, with
and without a FILE STATUS clause) plus its negative `pb1515-io-warning-07-below-2023` (COBOL0878 at 2002/2014).
