# PB4499 — GnuCOBOL accepts CALL ... USING OMITTED without a program prototype under the ISO dialects

## Summary

ISO/IEC 1989:2023 §14.9.4.2 Format 1 (Program), rendered from the printed page (PDF p618), gives USING only
`[BY REFERENCE] {identifier-2} ...` or `BY CONTENT {identifier-2} ...`; OMITTED exists only in Format 2
(program-prototype), which `AS` or a program-prototype-name selects. ISO/IEC 1989:2002 §14.8.4.1 is the same (OMITTED
only in Format 3, program-prototype), and COBOL-85 has no OMITTED. cobc 3.2 accepts the Format 1 spelling with no
diagnostic, even with `-Wall`, under `-std=cobol85`, `-std=cobol2002` and `-std=cobol2014`.

## Minimal test case

Written for this note (not taken from the GnuCOBOL testsuite):

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. OMITCALL.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 A PIC X VALUE "A".
       PROCEDURE DIVISION.
       MAIN-PARA.
           CALL "SUBPROG" USING A OMITTED
           STOP RUN.
```

`cobc -fsyntax-only -Wall -std=cobol2014 omit.cob` (also `cobol2002`, `cobol85`).

## Environment

GnuCOBOL 3.2.0 (`cobc (GnuCOBOL) 3.2.0`), Ubuntu under WSL2 on Windows 11, 2026-11-03.

## Observed result

No output, exit 0, under each of the three dialects.

## Expected result (per ISO)

A diagnostic: OMITTED is not part of Format 1's USING phrase (§14.9.4.2, `cite.py --check 14.9.4.2 "Format 2
(program-prototype)"`: OK), so the statement does not conform. Under `-std=cobol85` OMITTED is not a COBOL-85 word at all.
The default dialect may keep it as an extension.

## Our compiler (WiseOwl)

COBOL0899 at every edition: "CALL USING OMITTED: the OMITTED phrase belongs to the program-prototype CALL (ISO §14.9.4.2
Format 2) ...". `--permissive` makes it a warning (kb/Work PB4012). The refusal is `CallBinder.Format2OnlySpellingOf`.

## Fix site (GnuCOBOL 3.2 source, read observationally)

`cobc/parser.y`, rule `call_param`, alternative `_call_type OMITTED`: it checks only that the mode is BY REFERENCE and
never asks whether the CALL names a prototype or whether the dialect supports the phrase. A `cb_verify` against a new
dialect option (unconformable in cobol85/2002/2014, ok in the default) when the CALL has no prototype would close it.

**Title:** -std=cobol2014 accepts CALL ... USING OMITTED in a CALL with no program prototype

With `-std=cobol2014` (also `cobol2002` and `cobol85`), cobc 3.2 compiles `CALL "SUBPROG" USING A OMITTED` with no
diagnostic, even with `-Wall`. ISO/IEC 1989:2014 (and 2002, §14.8.4.1) allows OMITTED only in the program-prototype
format of CALL, selected by AS or a program-prototype-name; the plain format's USING lists identifiers only, and COBOL-85
has no OMITTED. Expected: an error, or at least a dialect-controlled warning, under the ISO dialects; the default dialect
can keep the extension. The `_call_type OMITTED` alternative of `call_param` in parser.y checks only BY REFERENCE.

Repro (8 lines) as above; `cobc -fsyntax-only -Wall -std=cobol2014 omit.cob` prints nothing and exits 0.
