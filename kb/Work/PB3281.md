# PB3281 — the national character-class rule is written twice in StringUnstringBinder

Source: PB442's report (`E:/COBOL-coord/scratch/reports/w1091h-PB442-report.md`, "## New defects / leads").

**Sites** (`src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/StringUnstringBinder.cs`, origin/main 4344c7fba):
- `:158` `CharacterCategory = IntrinsicArgumentRules.ClassOf(intoOperand) is CobolClass.National ? PicCategory.National : PicCategory.Alphanumeric` (STRING, GR2 figurative context, PB1185).
- `:347` `var itemCategory = IntrinsicArgumentRules.ClassOf(source) is CobolClass.National ? PicCategory.National : PicCategory.Alphanumeric;` (UNSTRING, GR7 figurative-delimiter context, PB1185).

The two expressions are the same rule (operand class to the figurative-literal character category), written twice: one rule, one place.

**Correction to the lead.** The lead's fix shape says to route both sites through `CharacterContext`. No type, method or doc named `CharacterContext` exists on origin/main (grep over src, docs and kb found no match), so the implementer must create the single home (or find the right existing one) rather than call it. Tree-wide, `ClassOf(...) is CobolClass.National` appears only at these two lines.

**Fix.** One helper that maps an operand to its character category, both sites call it, and a drift test keeps the hand-written form from reappearing. Sweep the binder for other hand-written national class tests in other spellings (`PicCategory.National`, `Usage.National`, `LiteralClass.National`) and fold any that ask the same question.
