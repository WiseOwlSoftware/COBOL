# PB610 — OPEN — the third reference site

Found 2026-09-05 by the `PB237` implementer's reference-site sweep (CALL Format 2 ✅, CANCEL ✅, `ADDRESS OF
PROGRAM` ❌ no grammar, `PROGRAM-POINTER TO` ❌ PB609); re-derived on this tree for this note.

## The rule

§8.4.3.13 Program-address-identifier — its general format is `ADDRESS OF PROGRAM { identifier-1 | literal-1 |
program-prototype-name-1 }` (transcription line ~6605; render the PDF page before implementing, per rule 1's
diagram caution), with §8.4.3.13.3 SR3 constraining program-prototype-name-1 to a declared prototype (`cite.py --check 8.4.3.13.3
"Program-prototype-name-1 shall be a program prototype specified in the REPOSITORY paragraph."` → OK §8.4.3.13.3 3))
and §8.4.3.13.4 GR1 defining the value (`cite.py --check 8.4.3.13.4 "creates a unique data item of class pointer and
category program-pointer that contains the address of a program"` → OK §8.4.3.13.4 1)). It
is the sending operand of `SET program-pointer TO ADDRESS OF PROGRAM …` (§14.9.39) and the only way a
program-pointer acquires a program's address in standard source.

## The mechanism

No parser rule spells the identifier; `SET … TO ADDRESS OF …` binds the data-address-identifier only. The
registry the prototype arm needs exists since PB237 (`StatementBinder.ProgramPrototypes`,
`CallBinder.ResolvePrototype`), and the runtime already carries program addresses for CALL through a
program-pointer, so the work is the identifier's grammar, its binder (three operand kinds; SR3 through the
registry), and SET's pointer arm accepting it.

## Fix shape

Grammar (pre-authorized, `new-construct` shape, 2002+ gated): a `programAddressIdentifier` rule reachable from
SET's sending side and any other position §8.4.3.13 is admitted in; binder: resolve identifier-1 / literal-1 by
externalized name at run time and program-prototype-name-1 through `ResolvePrototype`; goldens: SET from each of
the three forms followed by a CALL through the pointer, the 85 gating diagnostic, and a negative for an
undeclared prototype name (COBOLNET1760's message shape). PB609 (restricted program-pointer) consumes the same
identifier — land it after or with this.
