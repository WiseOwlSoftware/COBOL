# PB1066 — OPEN (DEFINE / FLAG-inline half landed by w59f; SOURCE FORMAT half open)

## Measured
```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. C38DF.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 WS-D PIC X(3).
       PROCEDURE DIVISION.
           PERFORM
               STRING "ABCDEFG" DELIMITED BY SIZE INTO WS-D
           WHEN EC-OVERFLOW-STRING
       >>DEFINE ZZ AS 1
               DISPLAY "HANDLER"
           END-PERFORM
       >>IF ZZ IS DEFINED
           DISPLAY "ZZ-LEAKED"
       >>ELSE
           DISPLAY "ZZ-POPPED"
       >>END-IF
           STOP RUN.
```

prints `HANDLER` then **`ZZ-LEAKED`**.

## The rules
- `cite.py --check 14.9.28.4 "Immediately preceding the END PERFORM phrase, there is an implicit POP ALL"` → `OK §14.9.28.4 14)`.
- `cite.py --check 7.3.22.4 "If ALL is specified, the state of all of the directives other than EVALUATE, IF, PAGE, POP, or PUSH are saved"` → `OK §7.3.22.4 2)`; 3) adds that every DEFINE instance is pushed.

GR-14.9.28.4-14 is CONFORMS on main (PB1004 extended the implicit PUSH/POP to REF-MOD-ZERO-LENGTH and FLAG-02/14) and
this contradicts it.

## Code site
`>>DEFINE` lives in the conditional-compilation driver, which runs BEFORE parsing; PB1004's implicit PUSH/POP runs
over directive state held after it. The frontend-inline FLAG options are the same split.

## What the fixer owes
One directive-state stack for every pushable directive (DEFINE included), with the implicit GR14 PUSH ALL / POP ALL
applied where the conditional-compilation driver can see the PERFORM's WHEN/END-PERFORM boundaries — or the driver
consults the stack the parser keeps. Golden: the probe, plus a >>DEFINE … OFF inside the handler.

## Partially landed (w59f, 2026-09-24) — the conditional-compilation driver's state
The implicit ops now reach the conditional-compilation driver through a FRONT-END FIXED POINT, one mechanism with
the PB1004 replay:
- `ExceptionPerformDirectiveScope` moved to `Frontend.Preprocessor`, and the Format-3 test to
  `Frontend.Parsing.PerformFormat.IsFormat3` (the binder and the COBOLNET0900 gate now ask it too). `Frontend.Parse`
  places the ops after the parse and replays them into every timeline (`Frontend.Directives`); `BinderDriver.Bind`
  no longer does.
- `ConditionalCompilationProcessor.Manipulate` returns every directive ENCOUNTER (resultant line + whether it changed
  the driver's state); `ConditionalCompilationResult.KeyImplicitOps` keys each op to the first later encounter and
  drops pairs enclosing no state change; the text manipulation re-runs with that program — the driver applies each
  keyed op through its own `DirectiveStateStack` — until the parse places the program it was run with. Ordinary
  sources converge on pass 1 with no re-run; only the converged pass's diagnostics are reported.
- Encounter lines are exact across COPY (`ExpandCopiesOneLevel` hands the splice offset to `RenderCopybook`) and
  REPLACE (`CopyProcessor.ReplaceLineMap`).
- Sibling fixed by the same mechanism: the frontend-inline FLAG-02/14 options (e.g. FLAG-14 EVALUATE) held by the
  same driver.

Re-probe on the w59f build: the probe above prints `HANDLER` / `ZZ-POPPED`; with `>>DEFINE ZZ AS 1` before the
PERFORM and `>>DEFINE ZZ OFF` in the handler it prints `HANDLER` / `ZZ-LEAKED` (the defined state restored).

## What remains (the note stays open for it): SOURCE FORMAT
GR14's implicit POP ALL also restores SOURCE FORMAT (§7.3.22.4 2) — every directive but EVALUATE, IF, PAGE, POP,
PUSH), and that state is held by the NORMALIZER (`ReferenceFormatProcessor.NormalizeToFreeFormMapped`, the registry's
`ReferenceFormatProcessor` carrier), which runs before the conditional-compilation driver and COPY, so the w59f fixed
point does not reach it. Measured on the w59f build:

```cobol
           PERFORM
               STRING "ABCDEFG" DELIMITED BY SIZE INTO WS-D
           WHEN EC-OVERFLOW-STRING
       >>SOURCE FORMAT IS FREE
               DISPLAY "HANDLER"
           END-PERFORM
000100     DISPLAY "FIXED-AFTER".                                       ZZZZZZZZ
```
→ `error COBOL0307: unexpected '000100'` (expected: the POP restores FIXED; the line compiles and prints FIXED-AFTER).

What the finisher owes: bring normalization INTO `Frontend.Parse`'s fixed point (today `Normalize` runs once, before
the loop). The normalizer's state is read by EVERY line, not only by directives, so its ops key to source LINES, not
to directive encounters: map each resultant op line to its main-source physical line through the final
`SourceLineMap` (a SOURCE FORMAT slot line keeps its own origin through COPY and REPLACE; an op inside a copybook
takes the COPY statement's main line). Decide — and cite — whether the POP's restored format governs the END-PERFORM
line itself ("Immediately preceding the END PERFORM phrase", §14.9.28.4 14)) or starts on the following line, since
reference format is a per-line property; the first choice can move the END-PERFORM token and must still converge.
Then `GR-14.9.28.4-14` can close.
