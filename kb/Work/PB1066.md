# PB1066 — OPEN

## Measured
```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. C38DF.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 WS-D PIC X(3).
       PROCEDURE DIVISION.
           PERFORM
               STRING "ABCDEFG" DELIMITED BY SIZE INTO WS-D
           WHEN EC-OVERFLOW-STRING
       >>DEFINE ZZ AS 1
               DISPLAY "HANDLER"
           END-PERFORM
       >>IF ZZ IS DEFINED
           DISPLAY "ZZ-LEAKED"
       >>ELSE
           DISPLAY "ZZ-POPPED"
       >>END-IF
           STOP RUN.
```

prints `HANDLER` then **`ZZ-LEAKED`**.

## The rules
- `cite.py --check 14.9.28.4 "Immediately preceding the END PERFORM phrase, there is an implicit POP ALL"` → `OK §14.9.28.4 14)`.
- `cite.py --check 7.3.22.4 "If ALL is specified, the state of all of the directives other than EVALUATE, IF, PAGE, POP, or PUSH are saved"` → `OK §7.3.22.4 2)`; 3) adds that every DEFINE instance is pushed.

GR-14.9.28.4-14 is CONFORMS on main (PB1004 extended the implicit PUSH/POP to REF-MOD-ZERO-LENGTH and FLAG-02/14) and
this contradicts it.

## Code site
`>>DEFINE` lives in the conditional-compilation driver, which runs BEFORE parsing; PB1004's implicit PUSH/POP runs
over directive state held after it. The frontend-inline FLAG options are the same split.

## What the fixer owes
One directive-state stack for every pushable directive (DEFINE included), with the implicit GR14 PUSH ALL / POP ALL
applied where the conditional-compilation driver can see the PERFORM's WHEN/END-PERFORM boundaries — or the driver
consults the stack the parser keeps. Golden: the probe, plus a >>DEFINE … OFF inside the handler.
