# PB5285 - ACCEPT MESSAGE COUNT stops counting a message as soon as its first portion is received: Receive takes the message out of the queue store at the first portion, where 1985 keeps a partly received message in the queue until its last portion

**Sites:**

- `src/WiseOwl.Cobol.Runtime/Communication/MessageControlSession.cs` (`Receive`, `AcceptMessageCount`, `Dialogue.PartlyReceivedFrom`)
- `src/WiseOwl.Cobol.Runtime/Communication/CommunicationArea.cs` (`SetMessageCount`)

**Mechanism.** §1985:XIV.3.1.4 GR1 counts "the number of complete messages that exist in the queue structure". The MCS "logically places in queues or removes from queues only complete messages" (§1985:II.7.5), and STOP RUN must "eliminate from the queue any message partially received by that run unit" (§1985:VI.6.24.4 GR3), so a partly received message is still in the queue. `Receive` takes the message from the store (`MessageStoreState.TakeFromQueue`) at the first portion and keeps the remainder in the run unit's dialogue, so `McsTables.CompleteMessages` no longer counts it.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids below. None of them is recorded: the non-conforming verdicts wait in `E:/COBOL-coord/scratch/coderead-85/p2-for-register.json`.

**Rules (2 claimed; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-GR-XIV.3.1.4-1` - `§1985:XIV.3.1.4 GR1` (refuter: OVERTURNED, harm: wrong-answer): "the number of complete messages that exist in the queue structure"
- `(supporting)` - `§1985:VI.6.24.4 GR3` (the rule that places a partly received message in the queue): "eliminate from the queue any message partially received by that run unit"

**Repro.** `E:/COBOL-coord/scratch/coderead-85/out-pipe/refute-slice-60/a/p.cob` with its mcs.json (Q1 seeded ABCDEFGHIJ and SECND): ACCEPT COUNT, `RECEIVE CIN MESSAGE INTO BUF` (PIC X(5)), ACCEPT COUNT, RECEIVE the rest, ACCEPT COUNT; `cobol.exe --std 85 --source-format fixed --run p.cob`.

**Observed (a build of origin/main f2cf36fd15, rerun 2026-11-11; main has since changed only `IndexedConnector.cs` under `src/`, which none of these repros reaches).** `RCV1 00 ABCDE 0 0005`, `CNT2 00 000001`, `RCV2 00 FGHIJ 2 0005`, `CNT3 00 000001`.

**Expected (from the 1985 text).** `CNT2 00 000002` (both messages still in Q1); the count drops to 1 when the RECEIVE that returns the last portion removes the message.

**Fix direction (root cause, CLAUDE.md rule 4).** Remove a message from the queue when its last portion is received (or count the run unit's partly received message with its queue), keeping STOP RUN's elimination; test the count between portions.
