# PB1316 — LANDED 2026-10-03

## Measured (`glob.cob`, `--std 2023`)
```cobol
       WORKING-STORAGE SECTION.
       01 KC CONSTANT GLOBAL AS 5.
       REPORT SECTION.
       RD RG GLOBAL.
       01 TYPE DE LINE 1.
          05 COLUMN 1 PIC 9 SOURCE KC.
```
```
  error COBOLNET0899: RD 'RG': SOURCE 'KC' does not resolve to a data item (ISO §13.18.53.3 SR4)
```
The clean repro is `srcconst.cob`: `01 KC CONSTANT AS 5.`, a paged `RD R-1 PAGE LIMIT IS 30 LINES.` and
`01 DET-A TYPE DE LINE PLUS 1. 02 COLUMN 1 PIC 9 SOURCE KC.`. It gives the same single line, exit 70, with no
other diagnostic. The report should print `5`.

## The rules
```
$ cite.py --check 13.10.3 'constant-name-1 may be used anywhere that a format specifies a literal'
  OK  §13.10.3 2)  (Syntax rules)
      2) Except in a compiler directive, constant-name-1 may be used anywhere that a format specifies a literal
         of the class and category of constant-name-1. …
```
§13.18.53.2 prints `SOURCE IS { identifier-1 | arithmetic-expression-1 } … [ rounded-phrase ]`. An arithmetic
expression's operand may be a numeric literal, so a numeric constant-name is legal there. §13.18.53.3 SR3 then
requires the entry to be numeric or numeric-edited. SR4 ("Identifier-1 specifies a data item defined in any
section of the data division") governs identifier-1 only, and a constant-name is not an identifier. The code
0899 is the recognized-but-not-implemented code, which says the binder never modelled this arm.

## Site
- The SOURCE operand resolver in `src/Cobol.Net.Compiler/Binding/DataBinder.Reports.cs` resolves the operand as a
  data reference only.
- Diagnostic catalog: `src/Cobol.Net.Editions/Diagnostics/DiagnosticCatalog.cs:1341`.

## What the fixer owes
- SOURCE binds its operand through the ONE arithmetic-expression binder, so a constant-name, a literal and a
  compound expression all work. A lone identifier keeps the SR2 MOVE-validity path.
- A positive golden for a numeric constant SOURCE, and for a literal SOURCE if the grammar admits one.
- **Sweep** SUM's addend (§13.18.54.3 SR5, catalog :1344), PRESENT WHEN, and the report `VALUE` / `LINE` /
  `COLUMN` integer operands (constant-name in place of an integer) for the same data-ref-only resolution.
- PB1315 records the missing location on this diagnostic.

## Landed 2026-10-03 (wave-1009 implementer A)

Re-probed (srcconst.cob, `SOURCE KC` over `01 KC CONSTANT AS 5`): `COBOLNET0899: SOURCE 'KC' does not resolve to a data item (ISO 13.18.53.3 SR4)` reproduced.

**Fix.** The form classifier is one function, `DataBinder.IdentifierOperandOf` (over the syntactic `BareReferenceOf`): a bare word that names a CONSTANT is no identifier but arithmetic-expression-1 with one operand (13.10.3 SR2 with 8.8.1.1), so it takes the expression arm, which already substitutes the constant through `RefExpr`. SOURCE and SUM both ask it, so the SUM addend sweep the note asked for is the same line (`SumAddendRef`): `SUM KC` is an expression addend, SR6's rules. A numeric constant prints (`SOURCE KC` = 5, golden), an alphanumeric one is refused by 8.8.1.1 and by 13.18.53.3 SR3's numeric-entry rule (COBOLNET2141, negative). SWEEP of the other sites the note named, measured on this build (probe cs2): a PRESENT WHEN condition (`WS-X = KC`), a report VALUE operand (`VALUE KC`) and the OCCURS count (`OCCURS KT TIMES`) all accept a constant-name and print correctly - no further site needed a change. Two sites do NOT: the report LINE and COLUMN integer operands (`LINE PLUS KL`, `COLUMN KC`) are parse errors (`COBOL0309: unexpected 'KL'. A literal value is expected here, not a data-name`, grammar `integerLiteral` in `reportLineOperand` / `reportColumnOperand`). Whether `integer-1` of those formats is a position "that a format specifies a literal" (13.10.3 SR2) is the open question and the mechanism is the GRAMMAR, not this binder; it is reported as a lead, not fixed here.

**Spec (cite.py --check OK).** 13.10.3 SR2 ("constant-name-1 may be used anywhere that a format specifies a literal"), 13.18.53.2, 13.18.53.3 SR3.

**Goldens.** `conformance:2002/pb1292_source_operand_forms` line 1 (`SOURCE KC` prints 5), `conformance:negative/pb1316-source-alphanumeric-constant`.
