# PB4401 — a red's class is guessed from its test results alone

**Sites:** `scripts/orchestrator/land_lane.py` (`RedFacts`, `red_facts`, `classify_red`, `bounce_step`), `scripts/orchestrator/queue_facts.py` (`BounceFetch`, `fetch_bounce_results`).

`scripts/orchestrator/land_lane.py` `classify_red` (line 846) decides a merge-queue red's class from `RedFacts`, which
`red_facts` (line 874) builds from the downloaded test results (`queue_facts.fetch_bounce_results`, which returns a
`BounceFetch`) and the branch's gate record. Neither reads the failed run's jobs, steps or artifact list, so two reds get
the wrong class:

1. **Every shard died before uploading (an SDK or runner outage).** `gh run download` finds no artifact, the fetch reports
   `run = 0`, `f.unobserved` is set, and `classify_red` returns `UNCLASSIFIED` ("the red's test results could not be
   read"). The lane then ends the watch BOUNCED and wakes a finisher for what is infrastructure. The class should be
   `INFRA` (re-queued once, no agent). The lane cannot now tell "the run produced no results" from "GitHub was unreachable".
2. **The merged tree fails to BUILD.** No trx is written, `f.failed` is empty, and the arm "no test failed in merge-group
   run N: a job died before or outside its tests" returns `INFRA`, so the lane re-queues once. The build fails again the
   same way and only then reaches a finisher: one wasted merge group (about 25 minutes of CI and the queue behind it).

**Fix (one root).** Read the failed run's job and step facts (`gh run view <run> --json jobs`: each job's conclusion and
its failed step's name) and its artifact list into `RedFacts`. Then: no artifacts and every job failed before its test
step → `INFRA`; a failed build step → `GENUINE` (or a `BUILD` class, if the finisher brief should treat it differently)
with no re-queue; no artifacts because GitHub could not be read → `UNCLASSIFIED` as now. Add a self-test arm for each,
with planted `jobs` JSON, beside the existing `classify_red` arms.

## A third wrong class, made more frequent by PB4409 (2026-11-01, review R2-2 of PB4409)

`scripts/self_tests.py` writes no trx, so a merge-group red in `windows-self-tests` (or in the Linux `audits` job's
self-tests) also leaves `f.failed` empty: `classify_red` (`land_lane.py` line 858 on main after #999) returns INFRA
("a job died before or outside its tests"), the lane re-queues once and `landing_measure.record_red` files an
infrastructure cause. Before PB4409 a compiler change that touched a `TOOLING_READS` file ran its Windows self-tests in
the local gate. Now their first run is the merge group, and compiler changes touch such files routinely (plan section 0 at
every session end, `docs/CONFORMANCE.md`, the grammar). The job and step facts this note's fix reads settle it too: a
failed self-test step is a genuine red (class (d), the first run of those self-tests) and goes to the finisher with no
re-queue. Add the self-test step to the planted `jobs` arms.
