**Scenario:** SequentialConnector does not override HostAccess, so FileLockPostureDriftTests.EveryOrganisationsHandleAccessLiesInThatBand (FileLockPostureDriftTests.cs:525-550) asks the base, which returns FileLockPosture.AccessOf(mode), and passes. FileAccess.ReadWrite : FileAccess.Read` itself, and OpenWriter reaches HostFile.OpenConnectorWriteStream (FileSupport.cs:477-482), which hard-codes FileAccess.Write on both arms. The values agree today, so nothing is wrong yet. The guard exists to stop a mode taking access it does not need, and it cannot see these sites. Suppose OpenReader is changed to ReadWrite for INPUT, for example to give INPUT and I-O one handle shape (its summary already calls it 'THE ONE SPELLING' of both arms). The band test stays green because it reads HostAccess.
