# PB560

## Mechanism — value-clause-p3
`SetEmitter.EmitSet` renders a level-88 literal for `SET condition-name TO TRUE` with a PRIVATE literal recipe instead of the shared VALUE-clause compose. Its switch has three arms — StrStore of the raw decoded text for Alphanumeric/NumericEdited/National, `UnscaledAtScale(low, pic.Scale)` for Numeric, and `FigurativeWordFill` for a bare figurative WORD — none of which is the recipe `ValueInitializer.InitializerFor` uses for the item's own VALUE clause and none of which is the recipe `ConditionRenderer.StringMembershipValue` / `FloatMembershipValue` uses for the condition TEST. §14.9.39.4 GR6 says the literal is placed "according to the rules for the VALUE clause", so all three sites must answer identically; two of them do and the third does not. This is feedback_two_arm_dispatch (the test arm of the numeric-edited case was fixed by kb/Work PB97, landed; the store arm was not) and feedback_one_rule_one_place (one rule written down in three places).

### Expected, from the standard
§13.18.63.4 GR19 — "The characteristics of a condition-name are implicitly those of its conditional variable" — with §14.9.39.4 GR6 — "If the TRUE phrase is specified, the literal in the VALUE clause associated with condition-name-1 is placed in the conditional variable according to the rules for the VALUE clause". Applying those rules: E must hold [ 10.00] (§13.18.63.3 SR6 — a numeric literal for a numeric-edited item "shall be converted to their numeric-edited forms according to the rules for the MOVE statement"); F must hold 0.5 (§13.18.63.4 GR17 imports GR1 — "the actual value given to the item is an approximation of the arithmetic value of the literal"); A must hold "ABABA" (§8.3.3.6.4 GR2 — ALL literal-1 is the literal repeated to the receiver's size); B must hold [   ] (BLANK WHEN ZERO does affect initialization when the literal is a numeric zero — §13.18.63.4 GR8 NOTE 1). In all four cases `IF cond` immediately after the SET must be TRUE, since §8.8.4.5 GR2 tests the same value that was just stored.

### Observed
Measured. The round-trip form is what makes it unarguable: the condition TEST is independently correct (probe gr19_charact and gr17_float88 show the numeric-edited, packed-decimal, alphanumeric and float membership tests all answering correctly), so a SET immediately followed by its own IF returning FALSE localises the defect to the store arm with no appeal to a third party. A fifth arm is unmeasured but visible: a PICTURE format-2 (LOCALE) numeric-edited conditional variable has a runtime compose in `ConditionRenderer.StringMembershipExpr` (RuntimeApi.LocaleEditCompose) and nothing corresponding in EmitSet. FIX SHAPE: delete EmitSet's switch and call `ValueInitializer.InitializerFor(parent.Item, rawOverride: low)` — the ONE recipe already handles figuratives, ALL-literals, numeric-edited images, float and locale — rather than adding a fourth private case. Pin it with a golden that SETs and then tests each category, so the two arms cannot drift apart again.
