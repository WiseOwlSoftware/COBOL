**Q1 — the SOURCE phrase of RECORD KEY / ALTERNATE RECORD KEY is PROVIDED** (owner rule R65; Annex A.3 item 40).
Re-probed on the w1095i build first: `negative/pb358-record-key-source` drew COBOLNET1954 at 85, 2002 and 2023.
- `cite.py --check 12.4.5.12.4 "Record-key-name-1 defines a record key consisting of the concatenation of all
  occurrences of data-name-2 in the order specified"` → OK 2); the §12.4.5.6.4 twin → OK 2).
- **One key shape for both forms.** A record key is a LIST of byte windows end to end: `FileModel.RecordKey`
  (data-name-1 = one segment; SOURCE = one per data-name-2, in order), the runtime `KeySegment`, and the store
  header's key table (format version 5). `IndexedConnector.KeyOf` concatenates the windows through the one slice,
  so uniqueness, ordering, READ / START / DELETE and START's partial key need no second path.
- **Rules.** `FileControlKeyRules` yields one operand per data-name-2, so every rule stated of "data-name-1 and
  data-name-2" reaches each; SR2's last sentence ("All occurrences of data-name-2 shall be of the same category")
  is a new row on both clauses; §12.4.5.6.3 SR4's SOURCE exemption is real. READ … KEY (§14.9.30.3 SR11), START …
  KEY (§14.9.41.3 SR7) and COLLATING SEQUENCE OF (§12.4.5.7.3 SR5) name a record-key-name through
  `FileModel.RecordKeyNameCandidates` (with §8.4.2.2.2 Format 6's file-name qualifier); another file's is refused.
- **Edition.** `record-key-source-2002` (VCR row 7.36, a derived provisional 2002 edge): COBOLNET0900 at 85.
  COBOLNET1954 is retired; the five `negative/pb358-*-source*` decline witnesses are removed, the
  `record-key-source-only` derived-verdict selector and `DRV-SR-12.4.5.7.3-5` withdrawn.
- **Witnesses.** `conformance:2002/pb1099_record_key_source`, `conformance:negative/pb1099-record-key-source-85`,

  CONFORMS; SR-12.4.5.7.3-5 now tested rather than derived; the rest gained witnesses).

- **R1-1 — a SOURCE-form alternate swallowed a foreign-qualified COLLATING SEQUENCE OF.** The one-fault-one-verdict
  guard in `DataBinder.CollatingKeyNamed` read `AlternateKeyClause.Item is null` as "this clause did not resolve",

  clean and the clause was dropped. The guard is now `FileModel.DeclaresUnresolvedKeyNamed`: a SOURCE clause is
  unresolved only when one of its operands is, and matches only under Format 6's qualifier rule. Probe
