## Landed (w74 INSPECT cluster, 2026-09-30)

`CobolInspect` runs ONE comparison cycle (`RunCycle`) for TALLYING and REPLACING in both directions, so the BACKWARD arm is no longer a reverse-the-text-and-the-patterns wrapper around the forward pass: the current position walks right-to-left and each literal is compared LEFT-to-right from it (GR8 NOTE 2 — `cite.py --check 14.9.22.4 "Matching always takes place starting at the leftmost character at the current character position"` → OK §14.9.22.4 8)). GR8c's resume position (`cite.py --check 14.9.22.4 "immediately to the left of the leftmost character position that participated in the match"` → OK §14.9.22.4 8)) is one position left of a hit's leftmost character backward, past the hit forward. `Region` finds the BEFORE/AFTER delimiters in the direction of the scan (rightmost occurrence: AFTER → `[0, p)`, BEFORE → `[p + length, edge)`). CONVERTING needs only the region (its map is positional).

Witness: `conformance:2023/pb1152_inspect_backward_leftmost_match_at_current_position` — Annex D.25 EXAMPLE 5 rows 1–3 (tallying and replacing) plus the leg the reversed scan starved (`ALL "AB"` then `ALL "B"` over `AB` → 1 and 1), FIRST backward, CONVERTING with a multi-character AFTER and the overlap case. EXAMPLE 5 carries printed errata: row 2's final value `AZDBABC` (no phrase of the example produces a `Z`; the rule gives `AVDBABC`) and row 3's COUNT-2 = 4 (no reading of GR9 gives it; the rule gives 0). Row 1's `1 1 0` and row 3's final `BCABCXYD` are reproduced exactly.

**Two spec-literal consequences, pinned and documented (`docs/COBOLNET_STRING_OPS_DESIGN.md`, BACKWARD section), to revisit only on an owner/ISO ruling:** (1) a later BACKWARD comparison can OVERLAP an earlier hit (`ALL "AA"` over `AAA` hits at 1..2 and again at 0..1: TALLYING 2, REPLACING BY "XY" `XYY`; both comparisons read the ORIGINAL text, the later write wins — the annex's row 3 prints exactly that overwrite); `l1c14_inspect_backward_after` K6 changed from `AXY` (the reversed-scan value) to `XYY` for that reason. (2) A multi-character LEADING operand cannot match at the first eligible cycle (the rightmost position holds one character), so `BACKWARD … LEADING "AB"` counts nothing. There is no second implementation to consult — GnuCOBOL 3.2's `libcob/strings.c` has no BACKWARD phrase at all (only TRAILING) — so ISO's text is the only authority, applied literally (owner precedence).
