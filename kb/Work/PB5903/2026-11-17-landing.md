# Landing, 2026-11-17: before 2023 a line-framed file keeps the record rules

**Re-probe before the fix** (`run_probe.py`, the triage program `ls85.cob` of `E:/COBOL-coord/scratch/my-20261115/triage85/g4`,
`--std 85`, on a build of main 5459e4e876): `REC=[ABCDEFGHIJ] ST=04`, `REC=[KLMNOPQRST] ST=00`, `REC=[SHORT     ] ST=00`,
`REC=[LASTLINE  ] ST=00`. PB5882's landing had made the over-length line '04'; the remainder and the short line still
failed, and a third fault of the same root showed: the WRITE dropped the record's trailing spaces.

**The rules** (each checked with `cite.py --check`, OK):
- `§1985:VII.2.8.4 GR1`: the RECORD DELIMITER clause names "the method of determining the length of a variable length
  record on the external medium. Any method used will not be reflected in the record area or the record size used within
  the program." So a WRITE writes the record at its size: a LINE-SEQUENTIAL write dropping trailing spaces changed the
  size a later READ reports (`RECORD ... DEPENDING ON`, §1985:VII.3.8.4 GR11).
- `§1985:VII.4.4.4 GR13`: a record shorter than the minimum leaves the rest of the record area undefined, a longer one
  "is truncated on the right to the maximum size", and "In either of these cases, the READ statement is successful and an
  I-O status is set indicating a record length conflict has occurred", '04' (§1985:VII.1.3.5). The next READ reads the next
  record: the 2023 remainder (§2023:14.9.30.4 GR15, "the file position indicator will reference the next unread character
  in the record") is a line sequential file's rule, and 1985 has no line sequential file.
- `§2002:14.8.29.3 GR13` and `§2014:14.9.29.3 GR14` say the same, so the edge is 2023.

**The fix.** One decider, `SequentialConnector.LineSequentialFileRules` over `DialectBehavior.LineSequentialFileRules`
(changed in 2023, VCR row 7.88; docs/FILES_DESIGN.md, the RECORD DELIMITER paragraph; DOC-A.1-150 amended). Before 2023
`WriteRecord` writes the record at its size and `ReadRecord` gives a line outside the minimum and maximum record size
'04' through `FileConnector.RecordLengthConflicts`, truncating a long line with no remainder; from 2023 both arms are as
they were. The line character set's '09' is asked only from 2023 (at 85 PB5882 already reported it '00').

**After** (`ls85.cob`): `REC=[ABCDEFGHIJ] ST=04`, `REC=[SHORT     ] ST=04`, `REC=[LASTLINE  ] ST=04`, `EOF 10`: the
writer's records are 20 characters (its `RECORD CONTAINS 1 TO 20` and one 20-character description), all over the reader's
maximum of 10.
