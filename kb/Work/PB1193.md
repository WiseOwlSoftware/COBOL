## Refuter evidence — row `SR-14.9.35.3-3` (PARTIAL)

PARTIAL — The adjudicator's premise is false: it says 'a non-GLOBAL FD's records are not visible, so the reference fails'. But §13.18.27.3 SR1 b) lets a file-section 01 record carry its OWN GLOBAL clause, which makes it a global name even when the FD has no GLOBAL. SR3 exists for exactly that case, and it has no mechanism of its own. REWRITE R1 is rejected only because the compiler silently DROPS the GLOBAL clause on a file-section 01 record (a separate defect): a plain MOVE to that global record in the contained program is also rejected with 'R1 is not defined', although it is legal. So the rejection is an accident of that defect, and the diagnostic gives the wrong reason (§8.4.2.1 undefined name instead of §14.9.35.3 SR3). Fix that defect and SR3 is no longer enforced at all. The simple case (neither the FD nor the record GLOBAL) is correctly rejected, so this is PARTIAL.

**Code site.** src/Cobol.Net.Compiler/Binding/BinderDriver.cs#BindUnitData; src/Cobol.Net.Compiler/Binding/DataBinder.Linkage.cs#CallBindExternalAndGlobal

## Refuter evidence — row `SR-14.9.51.3-21` (PARTIAL)

PARTIAL — The adjudicator's premise is false: it says a non-GLOBAL FD's record is not visible in the contained program, so WRITE R fails name resolution. But 13.18.27.3 SR1 b) lets a file-section 01 record carry its OWN GLOBAL clause, and SR21 exists for exactly that case: the record is visible, yet the FD has no GLOBAL, so WRITE must be rejected. The pinned compiler rejects that shape only because it ignores record-level GLOBAL in the file section entirely: MOVE "HELLO" TO R is refused too, with a false 'R is not defined' message. So the SR21 outcome depends on a separate defect, and there is no SR21-specific check. Once record-level GLOBAL is honoured, WRITE R would pass silently. Same finding as the REWRITE twin, SR-14.9.35.3-3. A separate wrong-rejection defect also needs a note: a GLOBAL 01 under a non-GLOBAL FD is not visible to contained programs.

**Code site.** src/Cobol.Net.Compiler/Binding/Validation/StatementValidation.cs#FileWhoseRecordIs; src/Cobol.Net.Compiler/Binding/Validation/StatementValidation.cs#ResolveRecordName

## What the fixer owes

Honour record-level GLOBAL in the file section (BinderDriver.BindUnitData / DataBinder.Linkage.CallBindExternalAndGlobal), then give REWRITE SR3 and WRITE SR21 their own check (StatementValidation.FileWhoseRecordIs / ResolveRecordName: record visible via its own GLOBAL, FD not GLOBAL → refuse). Positive: MOVE to the global record from a contained program; negatives: REWRITE R1 / WRITE R there. Mind §13.18.27.3 SR2 (SAME RECORD AREA files shall not use GLOBAL).
