# PB5810 - RECORD VARYING DEPENDING ON a table element is accepted and the length is then ignored at run time (every edition)

**What is wrong.** `RECORD IS VARYING IN SIZE FROM 4 TO 12 CHARACTERS DEPENDING ON TL`, TL an unsubscripted item subject to OCCURS (an element of a table), compiles clean at every edition, and at run time the length register is not used: `MOVE 13 TO TL (1)` then `WRITE` gives status 00 where the same file with an elementary TL gives 44. The subscripted spelling is refused (`COBOL2024`, which itself says "shall not be subject to any OCCURS clauses"). Cause (b): wrong the same way at 2023. Harm: under_rejects, wrong_answer.

**Why it is wrong.** `§1985:IX.3.2.4 GR5` makes the indexed RECORD clause the sequential one. Its data-name-1 is a data-name, which in a general format must not be subscripted unless the format permits (`§1985:III`), and every table element reference must be subscripted (`§1985:IV.4.3.8.2.3 SR4`; its exceptions do not include the RECORD clause): so an item under OCCURS cannot be data-name-1. The siblings are screened: LINAGE (`COBOL2025`), RELATIVE KEY (`COBOL0863`), FILE STATUS (`COBOL2455` per the refuter). The compiler refuses the subscripted spelling but accepts the unsubscripted one with no diagnostic, and the register is not used at run time. Same at 2023. Not on any of the seven files changed between 5e49d46678 and d7d3f99539. The checker's confidence: high. This note's programs ran on a compiler built at main d7d3f99539.
