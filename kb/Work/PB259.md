# PB259

**Rows:** `FMT-14.9.1.2` · `GR-14.9.7.4-2`

Two rows whose remaining content is a **recorded non-support licence**, and which were nevertheless left at a
defective verdict so that a reader would still see them. `FMT-14.9.1.2` says so in its own notes, in the
standard's own words and then in the author's:

> "docs/CONFORMANCE.md A.4.2 records screen handling as Not claimed (an Annex A.4 OPTIONAL element — the
> owner's posture), so the absence is documented rather than debt, **and the row stays PARTIAL to keep it
> visible**."

That sentence is a work register improvised inside a verdict field. It is exactly the failure CLAUDE.md rule 8
names — a work item living in a paragraph where no work list can see it — and it costs twice: the burn-down
over-reports the defect count, and the visibility it buys is invisible to `work.py next` anyway.

**The register now does that job**, which is what makes these two rows adjudicable rather than stuck. This note
is the visibility; the verdict is free to say what is true.

## The two rows, and what each is actually owed

### `FMT-14.9.1.2` — the ACCEPT general format (PARTIAL)

Formats 1, 2 and 4 match the printed diagram and are spec-pinned (`conformance:2023/pb134_scope_terminators`,
already a spec-derived ref on the row). The sole unmatched alternative is **Format 3, the screen ACCEPT**, which
Annex A.4.2 item 1 names as an optional element — "ACCEPT statement, format 3: screen (14.9.1)" — and A.4.1
makes its "associated syntax rules, general rules, other rules, exception conditions, and I-O status values
also optional, even if not explicitly listed". `docs/CONFORMANCE.md` §5 records A.4.2 as **Not claimed**, and
§5's own preamble states the conforming posture for an unclaimed module: "optional-element syntax is accepted
only when support is claimed — so a parse error or a named error is the conforming posture."

**The question this row needs answered — and it is a genuine adjudication, not a formality:** does an
implementation that does not claim A.4.2 render a general-format row CONFORMS (the unclaimed alternative is not
applicable, so the grammar agrees with the applicable format), or DOCUMENTED-NON-SUPPORT (the format is
partially declined)? The two are not interchangeable — DOCUMENTED-NON-SUPPORT over the WHOLE format would
decline Formats 1/2/4 that are implemented and tested, and CONFORMS must not be recorded until the "parse error
or named error" posture is actually MEASURED for a Format-3 source shape rather than assumed. That measurement
is the same witness `kb/Work PB260` owes for the thirteen screen rows this wave dispositioned, so the two should
land together.

### `GR-14.9.7.4-2` — COMMIT's EC-FLOW-COMMIT rule (PARTIAL)

The rule's subject is the commit facility, which Annex A.4.3 item 4 ("COMMIT statement 14.9.7") makes optional
and `docs/CONFORMANCE.md` §5 records as **Not claimed** (§4 item 2: "COMMIT, ROLLBACK. No transaction manager").
The wrinkle that keeps it out of this wave's licensed batch is real and points the other way: `kb/Work PB137`
(landed) made a COMMIT in a recursive source element or a SORT/MERGE procedure a **bind-time COBOLNET1690
rejection**, pinned by `conformance:negative/pb137-commit-recursive` — which is STRONGER on its static reach
than the runtime exception condition the rule names. So the row is neither plainly declined (something IS
implemented, and it over-delivers) nor plainly partial (the facility it belongs to is not claimed).

**Owed:** decide whether a rule whose facility is unclaimed but whose static half is over-implemented records
as DOCUMENTED-NON-SUPPORT with the PB137 diagnostic as its witness, or as CONFORMS on the ground that a
rejected construct cannot reach the runtime condition. Either way the witness already exists — this is a
verdict decision with its evidence in hand, which is why it is filed as an `adjudication` and not a defect.

## The DISPLAY twin answered the first question, and the measurement it was waiting on has been taken

`FMT-14.9.11.2` — DISPLAY's general-format row, the exact structural twin of `FMT-14.9.1.2` (a device format
that is implemented, plus a screen format that A.4.2 item 9 makes optional) — went to the `kb/Work PB258`
golden round on 2026-09-09 and was recorded **CONFORMS**, with the A.4.2 posture stated in the row's own notes.
The reasoning is available to `FMT-14.9.1.2` unchanged:

- **The precedent already existed.** `GR-8.8.1.2-6` is CONFORMS while one of its three clauses names
  ARITHMETIC IS STANDARD-BINARY, and its notes say why: the declined mode "is loudly refused (COBOLNET0806), so
  that arm is **unreachable rather than unverified**". A declined-but-loudly-refused clause is not a partial
  implementation; it is a clause the standard's own §4.2 machinery removes from the obligation.
- **The measurement PB259 said must precede CONFORMS has been taken**, on a compiler built for the round rather
  than read: the FULL DISPLAY Format-2 shape — `DISPLAY SG AT LINE 5 COLUMN 10 ON EXCEPTION … NOT ON EXCEPTION …
  END-DISPLAY` over a SCREEN SECTION item — **parses** and is refused **by name** with **COBOLNET1707**, whose
  text names the format, cites §14.9.11 and Annex A.4.2 item 9, and says why re-reading it as the device format
  would be wrong. It is a NAMED error, not the parse error the row's own notes still predict.
- ⛔ **So `FMT-14.9.1.2`'s stated reason for staying PARTIAL is now stale in two ways**: "Format 3 … has no
  grammar production" is refuted by `acceptStatement`'s `screenTail?` arm, and "the absence is documented
  rather than debt, and the row stays PARTIAL to keep it visible" is the improvised register this note replaced.
  **Owed:** the same measurement for an ACCEPT Format-3 source shape, then the same verdict. Nothing else.

## Why these two are one note

One mechanism: **a defective verdict used as a bookmark.** Both rows are held below their earned verdict so a
reader will encounter them, in an artifact whose count the owner watches. Sweep for the sibling shape when
either lands — any row whose notes contain "stays PARTIAL", "kept visible", "so it is not forgotten" or the
like is the same improvised register, and the fix is a note, never a verdict.
