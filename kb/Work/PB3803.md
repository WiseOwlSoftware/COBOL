# PB3803 — a dry run that writes

**Sites:** `scripts/orchestrator/plan_wave.py#main`, `scripts/orchestrator/plan_wave.py#plan_main`, `scripts/orchestrator/inflight.py#IndexPolicy`, `scripts/orchestrator/inflight.py#declared_sets`, `scripts/orchestrator/clusters.py`, `scripts/orchestrator/test_plan_wave.py`, `docs/rearchitecture/DESIGN-orchestrator-loop.md`

## Measured

`plan_wave.py --dry-run` writes `clusters-open.json` and `clusters-half.json` (`run_fix_clusters`) and
`clusters-campaign-<lead>.json` (the `--cluster` branch's `coord.write_json`) into the coordination directory, although
the docstring says a dry run "writes nothing". Repro: any `--dry-run`, then the files' mtimes. Site: `plan_wave.py#main`
(`fix_clusters`, the `--cluster` branch).

## Acceptance

- A `--dry-run` leaves every file in the coordination directory unchanged (mtime and bytes), whichever of `--cluster`,
  the fix-clusters path and the default path it takes; the plan it prints is the plan a real run would write.
- A test in `test_plan_wave.py` runs each path with `--dry-run` against a temporary coordination directory and asserts the
  directory listing and mtimes are unchanged (it fails on the current code).
- Sweep: every other `--dry-run` flag in `scripts/orchestrator/` is checked the same way and its result reported.

## Landed

Re-probed with `plan_wave.py --dry-run --no-branches --coord <empty dir>`: `clusters-open.json`, `clusters-half.json` and
their `-notes` views appeared there; with `--cluster` also `clusters-campaign-<lead>.json` and a regenerated
`member-index/<treeKey>.members.json.gz` (a fourth write the note did not name). The planning now runs in a temporary
directory a dry run owns (`plan_main(argv, stack)`), and `IndexPolicy.record_dir` sends a regenerated index there while the
coordination directory's cache is still read. The other `--dry-run` flags in `scripts/orchestrator/` (`adopt_main.py`,
`cancel_superseded.py`, `enqueue.py land|queue`, `orchestrate.ps1`, `autostart.ps1`, `install-autostart.ps1`) each return
before they change anything and are pinned by their own self-tests; `orchestrate.ps1 -DryRun` still creates its logs and
`scratch/dryrun-<pid>` directories by design (it "starts nothing"). A duplicated `FIX_CLUSTERS` assignment in
`clusters.py` went with it.
