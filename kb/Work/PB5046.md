# PB5046 - SUM in a report group that is not a CONTROL FOOTING is accepted at --std 85

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/ReportSectionBinder.cs#ScreenReportEntryClausePresence`, `src/WiseOwl.Cobol.Editions/Diagnostics/DiagnosticCatalog.cs#ReportSumNotInControlFooting`.

**Found.** `§1985:XIII.3.19.3 SR3` reads "(3) A SUM clause can appear only in the description of a control footing report group." (`cite.py --check` OK). At `--std 85` a SUM clause in a report group of another type is accepted.

**Repro.** `conformance-suite/cases/13.18.54-SUM/pb1294-sum-data-name-same-group-not-repeating.cob` compiled with `--std 85` compiles; the source has a SUM clause in a group that is not a control footing.

**Owed.** Refuse it at 85 with the 1985 rule cited, pin it with a golden, sweep the 2002/2014/2023 arms of the same check.

**Landed.** Re-probe on the build: before the fix the golden source compiled at --std 85. Now COBOL6763 (ScreenReportEntryClausePresence, gated by Edition.DialectLevel < 2002) refuses it at 85 only; 2002, 2014 and 2023 compile and run. Goldens: conformance 13.18.54-SUM/pb5046_report_sum_in_detail (accept 2002+) and negative pb5046-sum-not-in-control-footing.
