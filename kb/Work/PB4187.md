# PB4187 — a deleted option file reaches no test

Read on the PB4147 branch (`origin/worktree-wf_adb70c0b-786-1`, pull request #860); main's registries are still `diagnostics.json` and `options.json`.

**Sites:** `scripts/spec/impacted_tests.py` (`reach_of`, line 690; the `status == "D"` arm at line ~716 for a path under `SUITE_REGISTRIES`; the `--self-test` arm "a deleted registry file names no test: no refusal of it remains to run", line ~1153, which pins the hole).

**The defect.** For a deleted file under `SUITE_REGISTRIES`, `reach_of` adds a note and names no test, "a deleted file leaves no refusal or option to run". That holds for `wiseowl/diagnostics/<id>.json`: with its file gone the test has no refusal left. It does not hold for `wiseowl/options/<id>.json`: the test and its `.cob` and `.out` stay and still run, now compiled WITHOUT the option, so a result that changes reaches no tier 0a case. The self-test arm asserts the hole.

Not a regression: main's single-file registry also ignored removed keys. The lane review carried the lead through the merge `b8b33a29f` unchanged.

**Fix direction.** Split the arm by registry: a deleted `options/` file names its test (`registry_test(path)`, the id from the file name) exactly as a changed one does; a deleted `diagnostics/` file names none, and says why. Change the self-test arm to assert both. Sweep every `status == "D"` arm in `impacted_tests.py` for a deleted file whose subject still exists.
