# PB5311 - an external file connector's entries are compared on their clauses as written, so an omitted RESERVE against RESERVE 1 AREA, or an omitted RECORD DELIMITER against STANDARD-1, is refused (COBOL6847) though both specify the same connector; the run-time EC-EXTERNAL-FILE-MISMATCH compares the same segments

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/FileEntryIdentity.cs` (`Segments`)
- `src/WiseOwl.Cobol.Compiler/Binding/ExternalFileConnectorRules.cs` (`Check`)

**Mechanism.** The external connector rule asks for "The same value for integer-1 in the RESERVE clause" (§1985:VIII.2.3.4 GR1 c; §1985:XIII.2.3.4 GR1 d), a count of areas, and an omitted RESERVE clause gets the implementor's count (§1985:VII.2.9.3 GR1), documented as one area (DOC-A.1-164). For RECORD DELIMITER the report rule asks only for a consistent implementor-name-2, and an omitted clause gets the implementor's method (§1985:VII.2.8.4 GR4). `FileEntryIdentity.Segments` renders RESERVE as the written clause (an omitted one as empty) and RECORD DELIMITER as the written phrase, so the agreeing pairs differ. The compiler already compares ORGANIZATION and ACCESS MODE by their effect (an omitted ORGANIZATION matches SEQUENTIAL), and the set-1 refuter upheld the reading. Because the segments also feed the run-time mismatch check, the fix changes it at every edition. docs/CONFORMANCE.md section 3.7.1 records the determination.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids below. None of them is recorded: the adjudicated non-conforming verdicts wait in `E:/COBOL-coord/scratch/coderead-85/held-for-register.json`.

- `(the default)` - `§1985:VII.2.9.3 GR1` (the implementor's count): "If the RESERVE clause is not specified, the number of input-output areas allocated is specified by the implementor"
