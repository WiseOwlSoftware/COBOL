# PB4503 — the Format 1 vendor CALL spellings at --std 85 (owner decision 2026-11-03)

**OWNER DECISION.** Asked whether `--std 85 --permissive` should accept OMITTED in a CALL that names no prototype as
the vendor extension, or keep it a COBOL0900 error because the facility is a COBOL-2002 introduction, the repository
owner answered on 2026-11-03, attended Mythos session: "permissive accepts it at 85 too". It extends PB4012's decision
("Yes, permissive accepts", 2026-10-28) to COBOL-85. The evidence: IBM Enterprise COBOL, whose baseline is ISO
1989:1985 and its amendments (Industry specifications page), lists "ADDRESS OF", "LENGTH OF", "OMITTED", "BY VALUE"
and "RETURNING" in the CALL statement among its IBM extensions; HP's COBOL documents BY VALUE and OMITTED as HP
extensions; GnuCOBOL accepts both under `-std=cobol85` (kb/Work PB4499, bugs #1287). The decision is read here as
covering every spelling of PB4012's vendor lane (`CallBinder.Format2OnlySpelling.VendorLane`), not OMITTED alone: BY
VALUE is the same IBM/HP extension over 85, and the four literal and expression spellings are ALREADY accepted under
`--std 85 --permissive` today, so one rule holds for all six. Overturn that reading here if the owner meant OMITTED only.

**What happens (probed 2026-11-03, CLI built at main 3e62b1816, `CALL "SUBPROG" USING ...`):**

| Spelling | `--std 85` | `--std 85 --permissive` |
|---|---|---|
| `A OMITTED`, `A BY REFERENCE OMITTED` | COBOL0899 error AND COBOL0900 error (`omitted-arguments-2002`) | COBOL0899 warning "accepted under --permissive" AND COBOL0900 error: rejected |
| `BY VALUE N` | COBOL0899 error AND COBOL0900 error (`CallByValue2002`) | COBOL0899 warning "accepted" AND COBOL0900 error: rejected |
| `BY CONTENT "X"`, `"X"`, `BY CONTENT N + 1`, `N + 1` | COBOL0899 error only | COBOL0899 warning, accepted |

Every COBOL0899 text says the spelling "belongs to the program-prototype CALL (ISO §14.9.4.2 Format 2), which the AS
phrase selects". At 85 that is wrong advice: COBOL-85 has one CALL format and no AS phrase or program prototype; the
spelling is simply not in the 1985 CALL at all (a COBOL-2002 introduction, and in 2002 only in the program-prototype
format, §14.8.4.1 Format 3).

**What should happen:**
- `--std 85` (strict): ONE diagnostic per spelling, COBOL0900 "requires COBOL-2002", the edition-gate convention for a
  construct a later edition introduced, with no advice to use AS. The literal and expression spellings get it too:
  §14.8.4.1 of 2002 puts them, like OMITTED and BY VALUE, only in the program-prototype format, and the 1985 CALL has
  none of them (the same vendor evidence; GnuCOBOL's `call_param` alternatives are its own extensions).
- `--std 85 --permissive`: ONE warning, the vendor-extension notice, and the argument binds with the meaning it spells
  (PB4012's binding, unchanged), for each of the six VendorLane spellings. The text names COBOL-85, not Format 2 or AS.
- 2002 and later: unchanged (COBOL0899 error strict, warning under `--permissive`).
- Unchanged at every edition: OPTIONAL formal parameters and the `IS [NOT] OMITTED` condition stay COBOL0900 at 85
  (the decision covers the CALL's argument, not the callee's header), and an OMITTED carried by BY CONTENT stays refused.

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CallBinder.cs` (`Format1Narrowing`, the one framing of
the narrowing; `Format2OnlySpellingOf` and each spelling's `Refusal` text), `src/WiseOwl.Cobol.Compiler/Validation/VersionConformancePass.cs`
(`VisitCallByReference` and the CALL-argument OMITTED gate, `Constructs.OmittedArguments2002`; the BY VALUE gate
`Constructs.CallByValue2002`, line ~2008), `tests/version-matrix/constructs.json` (`omitted-arguments-2002`, the CALL
BY VALUE row), `docs/CONFORMANCE.md` (PB4012's paragraph, which states the permissive lane and the rule-1 survey),
`docs/VERSION_CHANGE_REFERENCE.md` (the 2002 introductions), the goldens of `conformance:cases/14.9.4-CALL/pb3996-call-format1-*`
and `FormatOneVendorCallPermissiveTests`.

**Design note for the implementer.** One owner per edition, so no spelling is reported twice: the pass's CALL-argument
gates for OMITTED and BY VALUE and the binder's `Format1Narrowing` both fire today at 85. The shape that makes the next
spelling automatic is the binder owning all six at every edition (strict: COBOL0899 at 2002+, COBOL0900 through the
construct registry at 85; permissive: the warning), with the pass's two CALL-argument gates removed and the construct
rows' 85 refusals still witnessed by the drift tests. The pass keeps OPTIONAL and the omitted-argument condition.
