## Found (train 1012, from the w1012h implementer report)

The sibling PB1922 left: PB1922 built the shared-area table sort for an element whose pointer-class members are
ELEMENTARY (`10 EP USAGE POINTER`), carrying each member's managed slot with the element image. An element that holds
a pointer TABLE (`10 EP USAGE POINTER OCCURS 2`) is still refused with COBOLNET1756 at bind time — legal source
(§14.9.40.4 sorts the table elements; the pointer values must travel with their element).

**Repro:** `E:\Temp\claude\E--COBOL\e8598e10-eb23-44b5-98e0-e0f07cc381fb\scratchpad\w1012h\p1922b.cob` (PB1922's
golden `conformance:2002/pb1922_table_sort_pointer_element` with `10 EP USAGE POINTER OCCURS 2`).

**Code sites:** `src/Cobol.Net.Compiler/Binding/Procedure/Verbs/SortBinder.cs#SortBindTable` (the slot-member
window check resolves each member with ONE index, `ResolveItemAt`) and
`src/Cobol.Net.Compiler/CodeGen/Verbs/SortEmitter.cs#EmitSharedAreaTableSort` (the slot read/write-back loops run
one level; they need nested loops over each inner OCCURS count). Same root as PB1922: `SlotWindow.MembersOf`
enumerates the members, the windows must be enumerated per inner occurrence.

## Landed (wave 1045 group H, branch worktree-wf_03fdfe4f-4ae-8)

**Re-probed first.** `p1922b.cob` (the repro above) still drew COBOLNET1756 at bind and aborted at run time with
`NotImplementedCobolFeatureException` on the base build.

**Fix (one place each, `cite.py`-checked).** §14.9.40.4 GR24 places the sorted ELEMENTS, and a table element is the
whole of its description, so every managed slot the element holds moves with it. §8.4.2.3.3 SR3 says how each slot
is addressed: one subscript per OCCURS level of the member.
- `SlotWindow.InnerLevelsOf(member, item)` (`src/Cobol.Net.Compiler/Binding/Model/Place.cs`) is the ONE answer to
  "which OCCURS levels lie between the element and the slot member". It is `SubscriptLevels()` read past the
  element's own levels, so no second SR3 walk exists.
- `SortBinder.SortBindTable` asks the place builder for a window at occurrence 1 of every inner level. For a
  dynamic-capacity level it also asks for an addressable current capacity (`CurrentOccurrenceCount`). It still
  defers only a shape the builder cannot place.
- `SortEmitter.EmitSharedAreaTableSort` gathers each slot member as nested arrays, one level per inner OCCURS: a
  fixed level at every allocated occurrence, and a dynamic-capacity level at the source element's current capacity.
  It writes them back in nested loops bounded by the gathered arrays. A member with no inner OCCURS emits the
  one-level form unchanged, so PB1922's golden output is unchanged.

**Sibling fixed in the same change (I9; the same function and the same "the element moves whole" rule): a WRONG
ANSWER.** An EXTERNAL element holding variable-length components (a dynamic-length item, a dynamic-capacity table)
moved as one contiguous image (§8.5.1.11.2), and that image was cut back into components by length. With two
dynamic-length items the first took every character of the second (`1 [ONE1] []`), and the dynamic-capacity
table's occurrences were dropped. Such an element now moves as its §8.5.1.12 component carrier
(`PlaceRenderer.VarGroupBoundaryImage` / `WriteVarGroupImage`), the same pair MOVE and the activation boundary use.
BASED cannot hold these components (§13.18.5.3 SR2); a REDEFINES class cannot either.

**Goldens and negatives.**
- `conformance:2002/pb1951_table_sort_pointer_table_element`: one inner level, then two inner levels in one row
  of an enclosing table.
- `conformance:2014/pb1951_table_sort_external_variable_element`: the carrier sibling.
- `conformance:2023/pb1951_table_sort_external_pointer_dynamic_table`: a dynamic-capacity pointer table. The
  STRONG EXTERNAL type it needs is COBOL-2023, §13.18.22.3 SR5.
- Negatives: `pb1951-table-sort-pointer-table-at-85` (COBOLNET0870),
  `pb1951-table-sort-external-variable-element-at-2002` (COBOLNET0900) and
  `pb1951-table-sort-external-pointer-dynamic-at-2014` (COBOLNET0900).

The design paragraph is `docs/COBOLNET_DESIGN.md` (the Format-2 table SORT storage forms).
