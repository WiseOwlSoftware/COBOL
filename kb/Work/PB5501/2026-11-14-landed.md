## Landed (wave 20262027 group F, 2026-11-14)

**Re-probe (this tree, before the fix).** `E:\COBOL-coord\scratch\w20262027f\p\c1.cob` (`IF 5 / Z > 1`, Z = 0, then `A ** Z`
and `0 ** Z`) at `--std 85`: `abnormal run-unit termination: EC-SIZE-ZERO-DIVIDE (fatal): a zero divisor in a divide operation`,
exit 1, and the same at the default edition. Reproduced. The tree carries PB5484's branch (merged in: `EditionInfo.
UnphrasedSizeErrorEndsOnlyTheStatement` is its fact, not yet on main when this group started).

**Determination.** §1985:VI.6.4.2 GR3 and §1985:VI.6.2.3 GR5 speak of "an arithmetic statement"; the condition has no resultant and
no statement of its own, so the text defines nothing for it. §1985:B.2.2 item 45 is general ("If a size error condition occurs and an
ON SIZE ERROR phrase has not been specified, the program will continue") and 1985 has no fatal exception condition, so the program
continues. The truth value is left undefined by 1985 (item 8 of paragraph 2.2B names only the resultant); the choice is the
implementor's: the relation or sign condition (its own NOT, a relational operator or `IS NOT POSITIVE`, inside it) is FALSE, so a
logical NOT outside it is true. docs/CONFORMANCE.md DOC-A.1-70 carries it. No GnuCOBOL text settles it (its decimal compare of a
not-a-number quotient is its own undefined case), so rule 1's last rung offers nothing to follow.

**Fix.** `ConditionRenderer.SizeErrorGuarded` wraps the leaf of `Visit(BoundRelational)` and `Visit(BoundSignCondition)` in
`CobolSizeError.FalseWhenRaised(() => leaf)` (through `RuntimeApi.SizeErrorFalse`) exactly when `EditionInfo.
UnphrasedSizeErrorEndsOnlyTheStatement` holds and an operand is an arithmetic expression (`BoundBinary`, `BoundPower`,
`BoundNegate` under a `BoundComputedOperand`). EVALUATE WHEN, PERFORM UNTIL, SEARCH WHEN and an abbreviated condition all render
through those two leaves, so they follow (probed: `c2.cob`). From 2002 nothing is wrapped and the fatal termination stays.
