# PB2505

Filed by the w1033 clerk from the PB867 refuter (`E:\COBOL-coord\scratch\w1033-adj\PB867-refute.md` section 2, "Harm 'none' holds for conformance, but say
what users will see"). The refuter calls it "an owner/design choice, not a conformance defect", so it is an analysis.

**Facts.** `PB867` was decided CONFORMS: an un-TURNed `RAISE EXCEPTION EC-USER-x` raises nothing (`§14.6.13.1.1`, `§14.6.13.1.4`). Annex D.2.5 (informative)
prints a "Commit and rollback" sample program with a `USE AFTER EXCEPTION CONDITION EC-USER-FATAL-ERROR` declarative and eleven
`RAISE EXCEPTION EC-USER-FATAL-ERROR` statements and no `>>TURN` directive (rendered PDF pages 1053-1054, printed 1023-1024). On this compiler a user who
copies that sample gets a program that silently runs on past its fatal errors (the first RAISE, after "ERROR OPENING FILES", does nothing).

**Owed (decisions, not implementation).**
1. Whether to add a compile-time warning for a RAISE whose checking is provably off at that statement (the compile-time TURN mask in
   `EcBinder.cs`/`ctx.EcState.Turn.Enabled` already knows; lexical TURN does not reach out-of-line paragraphs, so "provably" must be defined).
2. Whether the D.2.5 sample is reported as a defect against the standard (it contradicts `§14.6.13.1.4` under every reading of `§14.9.29.4 1)`).

## Landed (wave 1084 group C, 2026-10-15)

**Re-probe** (this worktree's build, `E:/COBOL-coord/scratch/w1084/w1084c/probe/pb2505.cob`: the D.2.5 shape, a `USE AFTER EXCEPTION
CONDITION EC-USER-FATAL-ERROR` declarative, `DISPLAY "ERROR OPENING FILES"`, `RAISE EXCEPTION EC-USER-FATAL-ERROR`, no TURN): compiled with no
diagnostic and printed `ERROR OPENING FILES` / `RAN ON PAST FATAL ERROR`. Reproduced.

**1. "Provably" is exact, so the compiler warns.** Checking is lexical: a `>>TURN` governs "the procedure division statements … that
follow in the compilation group" (`§7.3.25.4 6)`, OK), and an exception-checking PERFORM's WHEN phrase is an implicit TURN before
imperative-statement-1 (`§14.9.28.4 14)`, OK; `TurnState.WithImplicitEnable`). A PERFORM reaching an out-of-line paragraph carries no
enablement with it, so the fold at the RAISE's own line IS the run-time answer, and the generated code already obeys exactly that fold:
`EcEmitter.EmitRaise` writes only a comment when `BoundRaise.Enabled` is false for a nonfatal name. `EcBinder.BindRaise` now advises
**COBOL3803** (`DiagnosticCatalog.RaiseCheckingNotEnabled`, Warning, id `raise-checking-not-enabled`) from that same bool, citing
`§14.6.13.1.1` ("it is raised only if checking for that exception condition is enabled", OK) and `§14.6.13.1.4` ("If checking is not
enabled, execution continues as if the exception did not occur", OK) and naming the `>>TURN … CHECKING ON` that would make it raise. The
probe now prints `pb2505.cob(13,12): warning COBOL3803: RAISE EXCEPTION EC-USER-FATAL-ERROR: checking for EC-USER-FATAL-ERROR is not
enabled at this statement, …`; behaviour is unchanged (PB867's CONFORMS stands). Legal source stays legal: a Warning, never a refusal.
A FATAL name with checking off is NOT advised: it terminates (`§14.6.13.1.3 8)`, the implementor arm PB2504 documents), which no user
misses. The other raising statements are not advised either, and cannot be: `EXIT`/`GOBACK … RAISING` raise "if checking for that
exception condition is enabled in the activating runtime element" (`§14.9.18.4 1) b)`), a run-time property of the caller.
Precedence (CLAUDE.md rule 1): the standard prescribes no diagnostic here and the choice changes no behaviour, so it is a QoI advisory
of this compiler's own; GnuCOBOL was not consulted (the agent's isolation hook refused the WSL `cobc` probe).

Tests (`ExceptionConditionConformanceTests`): `Raise_CheckingOff_Nonfatal_IsAdvisedAtEachStatement` (the D.2.5 shape, two RAISEs, two
advisories, compiles clean), `Raise_Advisory_FollowsTheStatementsEnablement` (level-2 TURN ON and a PERFORM WHEN enable, a TURN OFF
disables: exactly one advisory), `Raise_Advisory_IsLexical_NotDynamic` (at 2002 and 2023: a paragraph before the TURN is advised even
though it is performed after it; one after is not), `Raise_CheckingOff_Fatal_IsNotAdvised`. Design doc:
`docs/COBOLNET_CONDITIONS_EXCEPTIONS_DESIGN.md`, the diagnostics band.

**2. The D.2.5 sample is a candidate defect report against the standard**, the same class as kb/Work PB312's two Annex D examples:
Annex D is informative and the sample contradicts `§14.6.13.1.4` under every reading of `§14.9.29.4 1)`. It never licenses raising
without checking. The project files no defect reports today; if it ever does, PB312 and this note are the candidates, and until then
COBOL3803 is what a user who copies the sample sees: one warning per RAISE.
