# PB5479 - at --std 85 OPEN EXTEND of a report file named in a MULTIPLE FILE TAPE clause is refused COBOL6814: CheckOpenModeForFile applies the Sequential I-O OPEN SR2 to report files, which the Report Writer OPEN does not carry

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/Validation/StatementValidation.cs` (`StatementValidation.CheckOpenModeForFile`)

**Mechanism.** A report file is opened by the Report Writer OPEN, which "initiates the processing of report files" (§1985:XIII.4.5.1); its SR1 admits OUTPUT or EXTEND and its SR2 makes the phrases depend only on the Sequential I-O level. The Report Writer module restates the multiple file reel rules of the Sequential OPEN that it keeps (NO REWIND on a reel, GR12's single-file-tape equivalence, GR13 a-c) and does not restate §1985:VII.4.3.3 SR2 ("The EXTEND phrase must not be specified for a multiple file reel"); XIII.2.4.4 GR1 imports the clause, not the Sequential OPEN's syntax rules. `StatementValidation.CheckOpenModeForFile` applies SR2 to every file with `MultipleFileReels`, report files included (it already branches on `IsReportFile` for the INPUT/I-O refusal), so a legal program is refused. The COBOL6816 member check (GR13c) is stated by the Report Writer OPEN too and stays. kb/Work PB5086 (landed) introduced the check. The adjudicator records the counter-reading: XIII.4.5.3 SR2 points to page VII-39, which prints VII.4.3.3 SR2.

**Found by.** The adjudication of the six held rows of `E:/COBOL-coord/scratch/coderead-85/held-9.json` (the 1985 read 4), `E:/COBOL-coord/scratch/held-85/set8/decisions.json`; the account is `kb/Work/PB4996/2026-11-13-held-9.md`.
