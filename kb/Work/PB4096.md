# PB4096 — TEST-NUMVAL-F: a character in error after the exponent's sign reports LENGTH + 1

**Site:** `src/WiseOwl.Cobol.Runtime/Intrinsics/CobolIntrinsics.Exact.cs#NvfScan` (the exponent arm:
`if (ed == 0) return new(n + 1, ...)`).

**Observed** (fresh judge = the run's judge, main 8803a84ff). Repro
`E:/COBOL-coord/scratch/fuzz-triage/fuzz-20261029-224533/adj/B1/probes/tnf/tnf-min.cob`:

| Argument | WiseOwl | ISO | GnuCOBOL 3.2 |
|---|---|---|---|
| `"12.34E+AB"` | 10 | 8 | 8 |
| `"1E++2"` | 6 | 4 | 4 |
| `"1E+"` | 4 | 4 | 4 |

**Expected (ISO/IEC 1989:2023, each citation checked with `cite.py --check`).**
- §15.95.4 1) b): "Otherwise, if one or more characters are in error, the position of the first character in error".
- §15.95.4 1) c): LENGTH + 1 only when the argument holds valid characters but is incomplete (`"1E+"`).
- §15.69.3 1): the exponent `n` is "one, two, three, or four digits representing the exponent", so after `E+` a
  non-digit, non-space character is a character in error.

**Cause.** After `E` and its sign, the digit loop runs zero times on `A` or `+`, and `ed == 0` returns `n + 1`
unconditionally. The significand arm already distinguishes "ran out of text" (r1 c) from "stopped on a character in
error" (r1 b), since PB121; the exponent arm was missed by that sweep. The fix returns `Pos()` when `i < n` and
`text[i]` is not a space, and `n + 1` only at the end of the text (spaces then end: r1 c).

**Sweep to do with the fix:** the same `ed == 0` / end-of-text discrimination in the NUMVAL-F value twin and in the
compile-time folding of a literal argument (PB256 made the scanners shared; check that no second scanner exists).
