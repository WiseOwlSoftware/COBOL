# PB2145 — INVOKE's argument rule is a second copy of CALL's

Found by the PB2114 implementer (wave 1028 group D), filed by the train-1028 lander.

`invokeArgument` (`src/Cobol.Net.Frontend/Grammar/CobolOO.g4:221`) spells out the BY REFERENCE, BY VALUE and BY
CONTENT argument bodies inline instead of naming `callByReference`, `callByValue` and `callByContent`. The argument
shape is the same, so a change to one copy (PB1135's keyword-less expression arm was one) has to be made twice, and
INVOKE's binders read different generated contexts from CALL's.

**Consumers that change with it:** `src/Cobol.Net.Compiler/Binding/OoBinder.cs:157`,
`OoBinder.InlineInvocation.cs:49` and `:124`, `src/Cobol.Net.Compiler/Binding/DataBinder.Ptr.cs:248`, and
`VersionConformancePass.VisitInvokeArgument`.

**Fix shape:** name the three call-by rules in `invokeArgument`, change every consumer to read them, and add a drift
test in the style of `SendingOperandDriftTests` that fails when the bodies are written out again. Check error recovery
as well as legal parses: PB2114 found that naming a rule can change error trees (PB2143).
