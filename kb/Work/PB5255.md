# PB5255 - the spec-reconcile tooling takes the 2002 edition

**Sites:** `.claude/workflows/spec-reconcile.js` (the argument checks, `EDITIONS` with each edition's notation clauses,
`toPages`, the consecutive-page batch cut, both `agent()` calls; its `meta` is the `spec-reconcile` skill's text),
`scripts/spec/merge_reconciliation.py` (`EDITIONS`, `Row`, `merged_rows`, `write_verdicts`, `write_decisions`, `merge`,
`--edition`, the self-test), `scripts/spec/reconcile_ranges.py` (new: `PLANS`, `build`, `clause_pages`, `compact`,
`--write`/`--check`/`--self-test`), `docs/rearchitecture/spec-reconciliation/2002/ranges.json` (new, generated),
`scripts/spec/page_workunit.py` (`units`, slices by `## Page N`, refuses a page the transcription lacks, names the figure
pages, `--self-test`), `scripts/spec/spec_pdf.py` (`PAGE_HEADING`, `pages_of`, moved here from `verify_publishable.py`),
`scripts/spec/sweep_figures.py` (`general_format_pages`), `scripts/spec/verify_publishable.py`, `scripts/spec/citation.py`,
`scripts/spec/rule_catalog_1985.py` (the page heading read through `spec_pdf.PAGE_HEADING`), `scripts/render-spec-page.py`
(a page out of range is an error), `docs/rearchitecture/spec-reconciliation/README.md`, `docs/DOC_INDEX.md`.

**The decisions (the project owner's controller, 2026-11-11; recorded in PB4813's addendum).** The 2002 reconcile runs
through the Workflow on the plan's quota, Opus agents at effort medium, never Message Batches (API credit is money, the
owner's). All 882 pages, the figure pages first; the 57 ambiguous pages and the pages of §2002:11.1.1 and §2002:13.14.1
inside the same run, in its first ranges. One adversarial verify agent per claim stays; the refuter pass over every drawn
figure is the campaign's second phase.

**What the tooling did wrong for 2002, and the fix.**
- The workflow passed no model or effort (host default), defaulted the page list to `[1, 2, 24, 50]`, wrote into
  `E:/COBOL/docs/...` of the MAIN checkout whatever worktree ran it, rendered into one fixed `E:/Temp/specrecon-2002` that
  two fleets would share, told every agent its pages "were selected because they contain FIGURES", and cited 2023's
  notation clauses with a note to find the edition's own. Now `pages`, `edition`, `model`, `effort`, `outDir` and
  `workDir` are all required and checked before any agent starts (a missing, malformed or unknown argument throws naming
  it; a page outside the edition's PDF, a duplicate, an `outDir` that is not `<checkout>/docs/rearchitecture/
  spec-reconciliation/<edition dir>` and a `workDir` inside the checkout are refused). The work units are built in the
  checkout `outDir` lies in. Each `EDITIONS` row states its own notation, each citation checked with `cite.py --check`:
  2002 §2002:5.1.1, §2002:5.1.2, §2002:5.1.5.1, §2002:5.1.5.2, §2002:5.1.5.3, §2002:5.1.6; 1985 §1985:IV.2.1.2,
  §1985:IV.2.1.4, §1985:IV.2.1.5; 2023 §2023:5.2.2, §2023:5.2.6.4, §2023:5.2.7. The priority is worded from the work unit:
  `page_workunit.py` prints the batch's figure pages and prose pages, and the prompt puts diagram fidelity first on a
  figure page and prose on a prose page. A gap in `pages` starts a new batch, so a run of the plan is cut at its batches.
- `page_workunit.py` sliced at `<a id="page-N">` anchors, which no transcription has any more (2023 dropped its pages;
  1985 and 2002 open a page with `## Page N`): every 2002 unit would have been an EMPTY markdown slice, with a warning, and
  an agent comparing a page with nothing can report it clean. It now slices by `## Page N` (`spec_pdf.pages_of`, the one
  reader, moved from `verify_publishable.py`; `sweep_figures`, `citation` and `rule_catalog_1985` read the one
  `spec_pdf.PAGE_HEADING`), exits 2 naming a page the transcription lacks, and for a transcription that keeps no pages
  writes the rendered page alone (`md` null). `render-spec-page.py` skipped a page out of range with a printed line and
  exit 0; it now exits naming the pages.
- `merge_reconciliation.py` merged only 2023. It takes `--edition` (`spec_pdf.add_edition_argument`) and a row per edition:
  2023 reads `agents/` into `LEDGER.json` (the claims-and-verdicts shape `spec-grammar-impact.js` reads; re-merging the 455
  agent files reproduces the committed `LEDGER.json` byte for byte), 2002 reads `2002/` into `LEDGER-2002.json` and
  `2002/REPORT.md`. 1985 has no row (its ledger came from the Message Batches passes; a merge would overwrite its
  decisions).

**The ledger shape: LEDGER-1985.json's.** It is the newer shape and the one the tool after the reconciliation reads:
`verify_publishable.check_ledger` holds a transcription that keeps its pages to `claims` (each decided, each APPLIED edit
on its page), `sweeps` and `boxes`. 2023's `LEDGER.json` shape is read only by 2023's own repair tooling. A 2002 claim
carries the agent's report, the verifier's verdict as `batch` (CONFIRMED, REFUTED, UNVERIFIED) and a decision: REFUTED with
the verifier's reason when refuted, otherwise the repair's. A re-merge keeps each claim's decision, reason and edits and
the ledger's sweeps.

**The plan (`2002/ranges.json`, `reconcile_ranges.py`).** 882 pages, 74 batches of 12 (the last 6): 29 flagged (an
ambiguous page or a page of §2002:11.1.1 (page 197) or §2002:13.14.1 (pages 273-274)), 51 with a figure; 305 figure pages
carrying 445 general formats by `sweep_figures.drawn_figures` (the brief counted 296 figure pages; the conversion run's
`local.json` also records 305 pages with figures, so 305 is the figure-page count the tools give). Halves: `account1` 37
batches (15 flagged, 26 figure, work 662), `account2` 37 (14 flagged, 25 figure, work 665), seven runs of six batches each.
The 57 ambiguous pages exist only in the conversion run's private `local.json`, so the plan carries them as an input:
`--check` regenerates everything else from the tracked transcription and, given `--ambiguous-from`, holds the carried
list to the run's.
