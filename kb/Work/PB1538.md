# PB1538 — LANDED (wave 1004 B, with PB807)

## The rule

> 2) If the compiler does not produce a source listing, the result of the DISPLAY directive is defined by the implementor, otherwise the data transfer shall take place irrespective of whether it is suppressed by the LISTING directive.

`cite.py --check 7.3.12.4 "If the compiler does not produce a source listing, the result of the DISPLAY directive is defined by the implementor"` → OK §7.3.12.4 2).
A.1 item 53 (conversion of the data transferred) and item 55 (how a PARAMETER value is obtained from the operating environment)
are REQUIRED and documented; neither can be written while the directive transfers nothing.

## Precedent (CLAUDE.md rule 1: ISO silent → GnuCOBOL)

GnuCOBOL 3.2 `cobc/pplex.l` `display_finish` (l.2711-2721) `puts()` the collected operands to the compiler's standard output at
compile time (collection l.242-248, 721-734; testsuite `syn_misc.at` 6797-6829: `>>DISPLAY "OK"` prints `OK` when compiling).

## Repro (`/tmp/adj/doc/doc-w1-s2/refute-probe/r53.cob`; re-probed, `--std 2023`)

```cobol
      >>DISPLAY "HELLO-COMPILE" 42
      >>DISPLAY PARAMETER XYZ
      >>DISPLAY "DEV" UPON LISTING
```

Observed: the compile prints nothing (the run prints only the program's own `RUN`). Expected (precedent): `HELLO-COMPILE 42` (and
the other operands) on the compiler's standard output. The directive is consumed by `DirectiveStateRegistry` with no transfer
("NONE HELD").

## Landed (wave 1004 B, 2026-10-02) — with PB807, the same mechanism

Found in the PB807 file and fixed there rather than filed (MANDATORY-PRACTICES I9): the directive evaluated nothing, so
transferring had to wait on the operand grammar PB807 builds. Re-probed first: `>>DISPLAY "HELLO-COMPILE" 42` compiled silently.

**Transfer.** `ConditionalCompilationProcessor.Display.cs#ApplyDisplay` evaluates the operands in order (GR4), reads a
PARAMETER through `ParameterText` — the ONE environment lookup the DEFINE PARAMETER phrase also uses (DOC-A.1-49 / 55, PB1533) —
and writes ONE line per destination: `DiagnosticBag.Transfer(stream, text)`. It is not a diagnostic (a diagnostic names a defect at
a position), so it travels beside them on the sink every phase already holds; `Frontend.Parse` carries the converged pass's lines
(a speculative GR14 pass's are dropped with its diagnostics), `CompilerDriver.Result.CompileOutput` exposes them on every outcome,
and the CLI writes each to the compiler stream it names before the diagnostics. The images are DOC-A.1-53's (alphanumeric and
national as their characters, boolean as 0/1, numeric in the shortest decimal form, joined by one space); a violation or an
unavailable PARAMETER value transfers nothing (a half-evaluated line is not what the author wrote); a directive in an omitted branch
does not run. `CONFORMANCE.md` §3's "recognized-and-ignored" bullet no longer lists DISPLAY.

Witnesses: `unit:DisplayDirectiveTests.*` (including `CompilerDriverResult_CarriesTheTransferredLines`, the carrier end to end),
`conformance:2023/pb807_display_directive_operands` (the legal forms compile; compile-time output is outside the corpus's
program-stdout comparison). Rows closed: DOC-A.1-53, DOC-A.1-55, GR-7.3.12.4-4, GR-7.3.12.4-6 and — claimed by PB1369 — GR-7.3.12.4-1,
GR-7.3.12.4-3, GR-7.3.12.4-5 (batch `w1004b-display-directive`).
