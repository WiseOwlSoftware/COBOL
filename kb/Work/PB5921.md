# PB5921 — the C# tests still leak into %TEMP%

> ⚙ **flags:** process-only. No program compiles or runs differently; the host's temp directory grows without bound,
> and a full disk turns every gate NOT RUN (PB3194's failure, on Windows).

## What was measured (2026-11-17, owner asked for a cleanup of E:\Temp, the host's %TEMP%)

- E:\Temp held **128,291 top-level entries** before the cleanup and 9,731 after (everything older than 24 hours
  deleted, except the `claude` session folder and the VBCSCompiler and NuGetScratch caches).
- Of what was deleted: about 41,000 `file-*.dat` data files (about 367 MB), 56,254 `pb323-*` directories (written
  2026-09-07 to 2026-11-13), about 16,000 directories named by `Path.GetRandomFileName` (`xxxxxxxx.xxx`), 9,194
  `Microsoft.NET.Workload_*.log` installer logs, and the `orch-test-*` (138), `.wolk-*` (43), `specrecon-*` (28),
  `wiseowl-cobol-grammar-check-*` (8), `ccf-*` (7), `gd-burst-*`/`gd-measure-*` (5) and `scoped_dir*` (2) directories.
- **The leak is live:** in the 24 hours before 15:40 PST, 3,758 `file-*.dat` files (34.1 MB) and 2,291 random-named
  directories were left. The largest `file-*.dat` groups: `file-rel` 300, `file-pb679` 201, `file-rand` 75,
  `file-cycle` 75, each `file-pb3336-*-Random-AllOther` 67, `file-F3AE10X` 60.

## The mechanism to find

- `tests/_shared/FileHarness.cs` `Tmp(tag)` returns `%TEMP%/file-<tag>-<guid>.dat`; 142 calls in 35 test files.
  `TryDelete` deletes and REPORTS a refusal (`HarnessLog.ReportLeft`, a `SCRATCH-LEFT` line, PB3194). So a file
  that survives is either (a) never passed to `TryDelete` (a test path with no `finally`, or a sibling file the
  runtime creates beside the host path that nothing names: a lock, journal or index companion), or (b) refused
  and reported: read the harness log's `SCRATCH-LEFT` lines first to tell the two apart.
- The random-named directories: find their creator (a `Path.GetRandomFileName` or `Directory.CreateTempSubdirectory`
  outside `tests/_shared/ScratchDirectory.cs`, or a tool the tests run, such as Roslyn or the compiler's own output).
  `ScratchDirectoryDriftTests` (PB3194) pins C# scratch directories to `ScratchDirectory`; whatever creates these
  escaped it.
- The named directory groups (`orch-test-*`, `.wolk-*`, `specrecon-*`, `gd-*`, `ccf-*`, grammar-check) are from
  script self-tests and tools; `scripts/scratch_repo.py` (PB3194) was meant to own them. Check whether they still
  appear after a run; the newest seen was 2026-11-16.

**Sites:** `tests/_shared/FileHarness.cs` (`FileHarness.Tmp`, `FileHarness.TryDelete`), `tests/_shared/ScratchDirectory.cs` (whole: the one owner of every test temp path, extended to data files)

## The fix's shape (rule 5: make the next case automatic)

One owner of every temp path a test makes, deleted by the owner at the end of the test or the test run, with a drift
test that refuses `Path.GetTempPath()`, `GetRandomFileName` and `GetTempFileName` anywhere in tests/ outside that owner,
and a run-level check that a gate leaves %TEMP% no larger than it found it (a count, not a clock).
