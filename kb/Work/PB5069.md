# PB5069 - at --std 85 nothing checks that the EXTERNAL file connector clauses of a run unit agree (PADDING CHARACTER, ACCESS MODE and RELATIVE KEY): CheckExternalFileConsistency runs at 2023 only and the PADDING CHARACTER clause is never captured

**Sites (landed):** `src/WiseOwl.Cobol.Compiler/Binding/ExternalFileConnectorRules.cs` (`Check`, replacing `BinderDriver.CheckExternalFileConsistency`, called at every edition), `src/WiseOwl.Cobol.Compiler/Binding/FileEntryIdentity.cs` (`Segments`, `Of`, `FileEntrySegment`), `src/WiseOwl.Cobol.Compiler/Binding/Model/DataItem.cs` (`ExternalItemIdentity`, moved from `BinderDriver`), `src/WiseOwl.Cobol.Compiler/Binding/Model/FileModel.cs` (`Padding`, `PaddingCharacterSpec`), `src/WiseOwl.Cobol.Compiler/Binding/FileControlBinder.Padding.cs` (`CapturePadding`, `ScreenPaddingDataName`), `src/WiseOwl.Cobol.Compiler/Binding/FileControlBinder.cs` (the clause arm), `src/WiseOwl.Cobol.Compiler/Binding/FileControlBinder.Resolve.cs` (`ResolveFiles`), `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/OoEmitter.cs` (`EmitExternalDescribes`), `src/WiseOwl.Cobol.Editions/Diagnostics/DiagnosticCatalog.cs` (`ExternalFileEntryDisagreement`, COBOL6847).

**Sites (as filed):** `src/WiseOwl.Cobol.Compiler/Binding/BinderDriver.cs#CheckExternalFileConsistency` (called only under `edition.DialectLevel >= 2023`), `src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolIO.g4#paddingCharacterClause` (its comment says nothing is captured on the FileModel).

**Mechanism.** Two 1985 general rules require every file control entry or PADDING CHARACTER clause of an external file connector in the run unit to carry the same specification. The compiler holds one cross-program externality check, CheckExternalFileConsistency, and BinderDriver calls it only when the edition is 2023 or later, its comment reading the requirement as one that removes a prior-edition freedom; the 1985 text states it as its own rule. The PADDING CHARACTER clause is parsed and nothing is kept, so no later check could see it.

**Found by.** The 1985 `--std=85` draft triage (kb/Work PB4995 item 3): each rule below is a conformance-suite draft that did not MATCH at `--std 85`, and its adjudicator decided COMPILER-DEFECT. Harm and observed text are the records'; nothing here was re-derived.

**Inventory.** The traceability inventory carries no 1985 rows yet, so `inventory_rows` is empty; the rows this note covers are the 1985 rule ids listed below (catalog `docs/rearchitecture/spec-rule-catalog-1985.json`).

**Rules (2; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-GR-VII.2.7.4-6` - `§1985:VII.2.7.4 GR6` (record harm: under-rejects, slice-01): §1985:VII.2.7.4 GR6: "If the associated file connector is an external file connector, all PADDING CHARACTER clauses in the run unit which are associated with that file connector must have the same specifications. If data-name-1 is specified, it must reference an external data item." `FD OUT-FILE IS EXTERNAL` makes the connector external (§1985:X.4.5.4 GR4: "The file connector associated with this description entry is an external file connector."), and WS-PAD is described with no EXTERNAL clause, so it is not an external data item (§1985:III.2: "External Data Item. A data item which is described as part of an external record"). The program violates an explicitly stated provision (§1985:I.1.6), and the violation is decidable from the source text alone. The draft is right.
- `1985-GR-VIII.2.4.4-8` - `§1985:VIII.2.4.4 GR8` (record harm: under-rejects, slice-01): §1985:VIII.2.4.4 GR8: "If the associated file connector is an external file connector, every file control entry in the run unit which is associated with that file connector must specify the same access mode. In addition, data-name-1 must reference an external data item and the RELATIVE KEY phrase in each associated file control entry must reference that same external data item in each case." `FD REL-FILE IS EXTERNAL` makes the connector external (§1985:X.4.5.4 GR4: "The file connector associated with this description entry is an external file connector."), and REL-KEY belongs to KEY-AREA, a record with no EXTERNAL clause, so it is not an external data item (§1985:III.2: "External Data Item. A data item which is described as part of an external record"). The program violates an explicitly stated provision (§1985:I.1.6), decidable from the source text alone. The draft is right.

**Expected (from the 1985 text).** A program whose external file connectors disagree is not a conforming 1985 source program; --std 85 refuses it with a diagnostic at the disagreeing clause. The deciding words: "If the associated file connector is an external file connector, all PADDING CHARACTER clauses in the run unit which are associated with that file connector must have the same specifications. If data-n" (§1985:VII.2.7.4 GR6).

**Observed (copied from `1985-GR-VII.2.7.4-6`).** cobol --std 85 --source-format fixed --flag-extensions: exit 0, no diagnostic; the program runs (exit 0) and displays: 'DONE'. Neither line 8 (`PADDING CHARACTER IS WS-PAD.`) nor line 14 (`01  WS-PAD PIC X.`) draws anything; the control (WS-PAD EXTERNAL) compiles and runs the same. Siblings, both exit 0 with no diagnostic: `PADDING CHARACTER IS NO-SUCH.` (an undefined data-name) and WS-PAD described `PIC X(2)` (§1985:VII.2.7.3 SR3 requires a one-character item): the clause's operand is never bound. Code site: src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolIO.g4, rule paddingCharacterClause (`PADDING CHARACTER? IS? (literal | dataReference)`), whose comment says "Nothing is captured on the FileModel"; and src/WiseOwl.Cobol.Compiler/Binding/BinderDriver.cs, CheckExternalFileConsistency, which holds the externality check (COBOL1624) for FILE STATUS, RELATIVE KEY and LINAGE only and runs only `if (edition.DialectLevel >= 2023)`. Note for the witness: the rule relates two places (the clause, line 8, and the item, line 14); the draft marks line 14, and a fix that reports at the clause would need the mark moved or a two-line site.
