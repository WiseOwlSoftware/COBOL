**Rule it breaks:** §8.8.1.2 r6a admits a zero base with any positive exponent, and nothing bounds the exponent of a base of 1 or -1, so the value is defined (0, 1 or +/-1). §8.8.1.3 lets the implementor choose the technique, not whether evaluation finishes. Loud failure / no unbounded work on legal input (engineering-standards, dimensions.md 2).

**Scenario:** Under native arithmetic, NumericRenderer routes every scale-0 integer base and exponent to CobolIntrinsics.PowNativeIntDec (NumericRenderer.cs:1041-1043). Its loop 'for (Int128 i = 0; i < e && fits; i++)' stops early only when |b| > 1 and the product would leave Int128, after at most 127 steps. For b in {-1, 0, 1} the guard 'mag > 1' is never true, so the loop runs e times. 01 B PIC S9 VALUE 1. 01 N PIC 9(18) VALUE 999999999999999999. COMPUTE R = B ** N executes about 10^18 Int128 multiplications: the run unit never finishes where the value is 1. With N = 999999999 (PIC 9(9)) it spends about 10^9 iterations, seconds of CPU, on a constant result. The same holds for B = 0 (value 0) and B = -1 (value +/-1 by N's parity). No exception condition is raised and no ON SIZE ERROR fires.
