**Rule it breaks:** §8.8.1.2 r6a admits a zero base with any positive exponent, and nothing bounds the exponent of a base of 1 or -1, so the value is defined (0, 1 or +/-1). §8.8.1.3 lets the implementor choose the technique, not whether evaluation finishes. Loud failure / no unbounded work on legal input (engineering-standards, dimensions.md 2).

**Scenario:** Under native arithmetic, NumericRenderer routes every scale-0 integer base and exponent to CobolIntrinsics.PowNativeIntDec (NumericRenderer.cs:1041-1043). Its loop 'for (Int128 i = 0; i < e && fits; i++)' stops early only when |b| > 1 and the product would leave Int128, after at most 127 steps. For b in {-1, 0, 1} the guard 'mag > 1' is never true, so the loop runs e times. 01 B PIC S9 VALUE 1. 01 N PIC 9(18) VALUE 999999999999999999. COMPUTE R = B ** N executes about 10^18 Int128 multiplications: the run unit never finishes where the value is 1. With N = 999999999 (PIC 9(9)) it spends about 10^9 iterations, seconds of CPU, on a constant result. The same holds for B = 0 (value 0) and B = -1 (value +/-1 by N's parity). No exception condition is raised and no ON SIZE ERROR fires.

## Landed (wave 1042 group E, 2026-10-08)

`PowNativeIntDec` answers a base of 0 (0 for a positive exponent; `0 ** 0` and a non-positive exponent are still
EC-SIZE-EXPONENTIATION through `CheckPowRule6`), 1 (1) and -1 (+/-1 by the exponent's parity) directly, in constant time.
For |b| >= 2 the exact loop is unchanged and ends after at most 127 steps whatever the exponent (each step at least
doubles the magnitude), then the documented double approximation takes over, so the loop needed no square-and-multiply.
Cite checked: 8.8.1.2 r6a. Tests: golden `conformance:85/pb2632_power_of_zero_one_minus_one` (the issue's 10 ** 18 exponent for
bases 1, 0 and -1, both parities, plus 2 ** 10 and (-3) ** 3 as the unchanged exact controls); `unit:PowNativeIntDecTests`
(an exponent past `long` for bases 1 and -1, the r6a screen, exact powers up to 2 ** 126, the double fallback). The unit test
has no wall-clock assertion: a regression is a test that does not return, which the gate's test-host timeout reports.
Sibling sweep (`i < e` / `i < n` multiply loops in `src/Cobol.Net.Runtime`): `CobolDec.Pow` is square-and-multiply, and
`CobolDec.QuotientHasRemainder` / `CobolDec` line 497 loops are bounded by a decimal128 exponent, not a user value.

## Landing

- `src/Cobol.Net.Runtime/Intrinsics/CobolIntrinsics.RealArgs.cs#PowNativeIntDec`: bases 0, 1, -1 are answered before the loop; for |b| >= 2 the loop ends after at most 127 steps by itself.
