# PB3830 — the NOT ON SIZE ERROR phrase binds inward, and the grammar should say so once for every paired phrase

The owner APPROVED this on 2026-10-26 at about 11:15 PDT, in chat: "Approve the size-error binding adjudication too".

handled grammatically in the same consistent manner".

**Sites:** `src/WiseOwl.Cobol.Frontend/Grammar/CobolParserCore.g4#statementBlock`, `src/WiseOwl.Cobol.Frontend/Grammar/CobolParserCore.g4#arithmeticOnSizeError`, `src/WiseOwl.Cobol.Compiler/Validation/ProcedureFormatPass.cs#VisitStatementBlock`, `src/WiseOwl.Cobol.Compiler/Validation/ProcedureFormatPass.cs#ReportConditionalOperand`

## The resolved reading: WiseOwl is right

Slice C2 called COBOL2796 on this program a defect (rejects legal source) and the orchestrator relayed it as one. Both
were wrong. Repro:
`E:\Temp\claude\E--COBOL\f2318ea1-8657-407b-8f1b-8fd54f53ad3f\scratchpad\fuzz5\adj\C2\probes\r2796\r2796.cob`
(A PIC 9 VALUE 5, C PIC S9 VALUE -9, D PIC 9 VALUE 0, F PIC X VALUE "-"):

```cobol
           SUBTRACT A FROM C
               ON SIZE ERROR ADD 1 TO D
               NOT ON SIZE ERROR MOVE "N" TO F
           END-SUBTRACT
```

The judge draws COBOL2796 at (11,23), at 2014 and 2023, and the MULTIPLY sibling (`MULTIPLY ... ON SIZE ERROR COMPUTE
... NOT ON SIZE ERROR`, probe `sib2`) is refused the same way.

The deciding rules (each run through `python scripts/spec/cite.py --check`, both OK):

- §14.5.3.3 4): "Any phrase encountered is the next phrase of the most-recently preceding unterminated statement with
  which that phrase may be syntactically associated. If all permitted occurrences of a phrase have already been
  specified for a given statement, a subsequent occurrence of that phrase is not syntactically associated with that
  statement."
- §14.5.1: "Any statement with a conditional phrase that is not terminated by its explicit scope terminator is a
  conditional statement".

The inner `ADD 1 TO D` is the most-recently preceding unterminated statement and ADD's format permits a NOT ON SIZE ERROR
phrase that it has not yet used, so the phrase binds to the ADD. The ADD, with a conditional phrase and no END-ADD, is then
a conditional statement standing inside SUBTRACT's imperative-statement-1, which §14.5.1 does not allow. COBOL2796 is
the correct refusal. GnuCOBOL binds inward too (it prints `D=1 F=N` on this program), which agrees but is no
authority. The slice had cited §14.5.1, which only DEFINES imperative and conditional statements, and missed the
rule that decides phrase ownership (the lesson is in the fifth-night evidence record).

The five other programs of the signature (fz03631, fz04237, fz04490, fz03657, fz05296) were already correct refusals.

## What remains: one mechanism for every paired conditional phrase

The owner's requirement is that all paired conditional phrases (the pairs of Table 12, such as ON SIZE ERROR / NOT ON SIZE
ERROR, AT END / NOT AT END, INVALID KEY / NOT INVALID KEY and ON EXCEPTION / NOT ON EXCEPTION) are handled grammatically in the same consistent manner. Measured by the slice: `CALL ...
ON EXCEPTION DISPLAY ... NOT ON EXCEPTION` compiles and runs correctly (probe `sib1`), and the same-name shape `ADD ... ON
SIZE ERROR ADD ... NOT ON SIZE ERROR ... END-ADD` compiles (probe `se4`), so the families do not all behave alike today.

## Acceptance

- One grammar mechanism implements §14.5.3.3 4) for every Table 12 paired phrase (a phrase binds to the most recently
  preceding unterminated statement that may still take it), replacing any per-family arm, and a drift test pins the
  list of paired phrases to the table so the next one is automatic.
- COBOL2796's message cites §14.5.3.3 as well as §14.5.1.
- Every statement family that owns a Table 12 paired phrase refuses or accepts the nested shape alike, and a
  conformance case per family pins it.
