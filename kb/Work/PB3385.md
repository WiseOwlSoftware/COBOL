# PB3385 — the group guard ignores a chain predecessor's exit status

A LOW lead from the Mythos lane's reviewer (`mythos-a4-review-r3`, report
`E:\COBOL-coord\scratch\reports\w1118a4-PB3334-report.md`), assigned to the operator's clerk.

**The site.** `scripts/guard-run-group.sh` `run_predecessor` (lines 59-75 on the PB3334 branch; it reaches main with
PB3334, which lands through `worktree-wf_14a1e62b-326-19`, hence `blocked_by`). The function runs each declared
predecessor of a consumer in the consumer's clean directory, then drops the predecessor's exit status and grades the
consumer anyway.

**The rule it says it mirrors.** The script's header says it follows `NistRunner`. `NistRunner.cs` lines 52-53 fail
the consumer when a predecessor exits non-zero (`[chain p] run exit non-zero`).

**Who sees it.** In a full group run the predecessor is also graded as its own member, so it goes red there and the
failure is visible. Under a `GUARD_TESTS` subset that names only the consumer, a crashing predecessor goes unreported,
and the consumer is graded over whatever partial file the predecessor left.

**The fix.** `run_predecessor` returns the predecessor's status, and its caller marks the consumer red with the
predecessor named, as `NistRunner` does. It belongs in the one chain-run function PB3383 gives both guard scripts, so
the serial guard gets the same rule. A guard self-test pins a consumer whose predecessor exits non-zero.
