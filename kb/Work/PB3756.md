# PB3756 — a doc comment says MOVE SPACE TO N stores spaces at some editions

**Sites:** `src/Cobol.Net.Compiler/Binding/Bound/BoundInitialize.cs#InitializeStore`.

Doc only. The `InitializeStore` summary (about line 42) says `INITIALIZE G REPLACING NUMERIC DATA BY SPACE` over an ordinary `PIC 9(3)` aborted the
run unit "at every edition where the explicit `MOVE SPACE TO N` stores three spaces". After PB3605 no edition stores spaces from `MOVE SPACE TO N`:
it is COBOL0819 at 85, 2002, 2014 and 2023, and the INITIALIZE form is COBOL2031.

## Fix
Reword the paragraph to the current behavior (the PB880 point stays: the move is bound, not built at emit time). Keep the doc comment current-state only
(CLAUDE.md rule 6); the history belongs to the DEVLOG. Sweep the sibling doc comments of `MoveBinder` and `InitializeBinder` for the same pre-PB3605 claim.
