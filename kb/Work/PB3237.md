**Rule it breaks:** ISO §14.6.13.1.4 3): when checking is enabled and an applicable USE declarative handles a nonfatal condition, 'If a conditional phrase with a NOT phrase is specified in the interrupted statement, the imperative-statement in that phrase is not executed.' kb/Work PB1120 (landed) made every I-O NOT phrase ask SequentialIoEmitter.UseHookResult.NotPhraseGate; KeyedIoEmitter.EmitDeleteFile discards that result

**Scenario:** MEASURED with the current Debug build (src/Cobol.Net.Cli/bin/Debug/net10.0/cobol.exe, 2026-10-15; KeyedIoEmitter.cs:383-399 is identical on the pin and on main): `>>TURN EC-I-O-WARNING CHECKING ON`, `SELECT OPTIONAL F1 ASSIGN TO "delnot-absent.dat" ... FILE STATUS IS FS1`, a declarative `USE AFTER EXCEPTION CONDITION EC-I-O-WARNING` that DISPLAYs, then `DELETE FILE F1 ON EXCEPTION DISPLAY "ON EXCEPTION" NOT ON EXCEPTION DISPLAY "NOT ON EXCEPTION RAN FS=" FS1 END-DELETE` with the file absent. §14.9.10.4 GR14 makes that '05', successful, and the declarative runs, then the NOT ON EXCEPTION imperative runs too. Output: 'DECLARATIVE RAN FS=05' / 'NOT ON EXCEPTION RAN FS=05' / 'AFTER DELETE FS=05'; the second line must not appear. Cause: KeyedIoEmitter.cs:389 calls SeqIo.EmitUseHook(...) and drops the UseHookResult whose NotPhraseGate is `__iorN == DispatchResult.Normal` (SequentialIoEmitter.cs:92), and 391-399 gate NOT ON EXCEPTION on IoStatusClass.Successful(st) alone (or a bare `else`), while EmitInvalid (SequentialIoEmitter.cs:562-572) and the READ arms (SequentialIoEmitter.cs:792,799; KeyedIoEmitter.cs:230-231) consult the gate. PB1120's sweep line names 'READ/WRITE/REWRITE/START/DELETE' (the record DELETE, through EmitInvalid) and not DELETE FILE
