# PB3112 — the Sweep-trait drift check never runs in Windows leg 1

> ⚙ **flags:** process-only

Source: `w1069l-PB3103-report.md` "## Finisher"; enqueue unit 1517's late lead L6.

`HostWitnessTraitDriftTests.TheSweepTrait_IsExactlyDriftRulesTreeWideSweeps_AndThePlannerSeesEveryTrait` (`tests/Cobol.Net.Tests.Unit/HostWitnessTraitDriftTests.cs:84`) takes 7.2 s on Windows (two Python spawns), over `SWEEP_CHEAP_SECONDS` (2.0 s, `scripts/gate_plan.py:100`). So `tier_of` (`scripts/gate_plan.py:342`) never puts it in tier 0c, and with no impact map it lands in tier 1, outside leg 1. A branch that adds a tree-wide drift test without `[Trait("Sweep", "tree")]` passes the Windows gate and goes red only at the landing's Linux gate or in CI. It did: wf_1ce5d560-43a-5 (PB3103), 2026-10-12, on 31e670b83. That is a CI-invariant gap (PB1957).

**A second instance: the cap, not one test, is the defect** (operator, 2026-10-12 22:10). The PB3109 branch
(`worktree-wf_787860dd-104-3`, w1070c, Review CLEAN at `9b2a2bb2f4e6`) added
`tests/Cobol.Net.Tests.Unit/DirectoryNameWatch.cs:48`, `_deletion.Wait(TimeSpan.FromMinutes(2))`. Its Windows gate
was GREEN. Its landing stopped `GATE RED (Linux) on b5e250c20b28` because
`NoWallClockAssertionDriftTests.NoTestSetsALiteralTimeLimit` refused the literal (kb/Work PB3022). That case's
recorded mean is 2.72 s, over the cap, so it too never runs in Windows leg 1. Measured from the shared timings
store (`.git/cobol-gate-timings/timings.json`, the per-case mean `tier_of` compares, 2026-10-12 21:42): **31 of the
129 `[Trait("Sweep", "tree")]` classes have a mean case over 2.0 s, 246 of their 3828 cases.** The slowest:
`GrammarDiagramGeneratorDriftTests` (154 s), `ExternalCorpusPopulationDriftTests` (48 s a case),
`CitationAuditSelfTestDriftTests` (36 s), `BitRunImageDriftTests` (33 s), `ImpactedTestsDriftTests` (32 s),
`ArchReviewFleetDriftTests` (32 s). Each such red costs a whole landing attempt (both gates), a finisher and a
review. The fix must cover every sweep over the cap, not only the trait check.

**Candidate fixes.** Run a cheap check as a gate audit (it only reads the tree). Put a sweep in tier 0a when the
diff touches what it reads (for example, a sweep over test sources whenever the diff adds or edits a test file).
Or make the slow sweeps cheap enough for the cap.
