# PB4901 - the X3.23-1985 DEBUG-ITEM register is refused as an operand of CALL and of SET

**What the report says (the implementer's words).** (1) `CALL ... USING DEBUG-NAME` / `RETURNING DEBUG-LINE` is refused COBOL1677
("no DATA DIVISION entry describes" the register, citing ISO 2023 §2023:14.9.4.3), a 2023 rule applied to the 1985 register;
GnuCOBOL compiles it. Repro `E:/COBOL-coord/scratch/w20261887a/sw/r7.cob`, site `SectionDataItem.cs:37` and the CALL binder.
Outside that group. (2) `SET DEBUG-SUB-1 UP BY 1` is refused COBOL2112 (`E:/COBOL-coord/scratch/w20261887a/sw/r1.cob`);
GnuCOBOL's behavior unchecked. Same root as (1) by the report's word: the register as an operand of other statements.
Flags: rejects_legal_source (a candidate: neither refusal is adjudicated).

**Citations re-checked** (`python scripts/spec/cite.py --check`): `§2023:14.9.4.3 SR3` and `§2023:14.9.4.3 SR7` OK (identifier-2 and
identifier-3 "defined in the file, working-storage, local-storage, or linkage section"). The report's quoted words "no DATA DIVISION
entry describes" are not in the standard (`--find` finds no clause); they are `SectionDataItem.NonSectionKind`'s own text for the register.

**Read on main (2026-11-06).** `SectionDataItem.NonSectionKind` answers `DebugRegisterPlace => "the DEBUG-ITEM special register,
which no DATA DIVISION entry describes"`; `CallBinder` (lines 340, 748, 1436, 1462) and `ParameterConformance.cs:324` reach it for
the COBOL1677 screen. SET's refusal is `SetFormatSelection` (lines 365, 383, 404, COBOL2112). The clerk ran nothing; the repros are
the witnesses. Neither case is held by PB4858 (DEBUG-CONTENTS reference modification, special-register targets, DB205A).

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CallBinder.cs:1465` (`CallBinder.ScreenCallOperand`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/ParameterConformance.cs` (`ParameterConformance.ScreenSection`), `src/WiseOwl.Cobol.Editions/Diagnostics/DiagnosticCatalog.cs` (`CallOperandSection`), `src/WiseOwl.Cobol.Compiler/Binding/Model/SectionDataItem.cs` (`SectionDataItem.NonSectionKind`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/CallBinder.cs`, `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/SetFormatSelection.cs`.

**Re-probe and verdict (2026-11-07, wave 20261905 F).** Both repros reproduce only at `--std 85` (at 2023 the DEBUG clauses are refused COBOL0902 first).
(1) CALL: `§1985:X.5.2.3 SR3` (cite.py OK) says each USING operand "must have been defined as a data item in the File Section,
Working-Storage Section, Communication Section, or Linkage Section"; DEBUG-ITEM's description is implicit (`§1985:XV.3.2.4 GR10`), defined in no
section, so the refusal is CORRECT at 85 and GnuCOBOL's leniency is not authority (CLAUDE.md rule 1). The defect was the diagnostic: it cited the
2023 rule (and its message body listed the 2023 sections). Fixed: at 85 the screen cites
`§1985:X.5.2.3 SR3` (and the '85 section list, via `ParameterConformance.ScreenSection`); golden `pb4901-call-debug-register-at-85` (refuse-at 85, message substring).
(2) SET: `§1985:VI.6.23.2` Format 2 is `SET {index-name-3} ... UP/DOWN BY`; its receiver is an index-name only, and DEBUG-SUB-1 is `S9999 SIGN LEADING SEPARATE`
(`§1985:XV.3.2.4 GR10`), so COBOL2112 is CORRECT at 85: DISCHARGED, no change. Residual (lead, not fixed): the COBOL2112 text lists the 2023 formats
(Format 14, Format 10) and cites only `§2023:14.9.39.2` even at 85.
