## What the code does today

- `src/Cobol.Net.Compiler/Oo/OoClassTable.cs#Build` is one pass that builds interfaces, classes, rosters, INHERITS
  links, the cycle walk and MarkRoster, emitting bare string codes: COBOLNET0820 for duplicate class, END CLASS
  mismatch, the INHERITS cycle (citing "§11.3.2", the general format) and an emitted-name collision; 0840 for
  interface INHERITS/IMPLEMENTS rules; 0842 for property shapes; 0849 (single inheritance, A.4.10) is reached BEFORE
  SR7, so `INHERITS FROM B B` reports the declined facility (PB1020). Parameterized class skeletons never enter the
  table (`OoExpansion`), so SR3/SR5 are never asked of them (PB1505). Interface INHERITS merges inherited rosters
  first-declaration-wins (`OoInterfaceSymbol.cs#AllPrototypes`) — no SR5, no SR4 b) (PB1502).
- `src/Cobol.Net.Compiler/Oo/OoClassTable.cs:411` refuses every factory METHOD-ID named NEW (COBOLNET0836), although
  BASE (kb/Work PB1548, landed) now exists: outside BASE's hierarchy NEW is an ordinary method; inside it `NEW
  OVERRIDE` is §11.7.3 SR3's override (PB1582).
- Data-division placement: the ENVIRONMENT division has one table (`Binding/OoEnvironmentRules.cs`, keyed
  `OoDefinition` × element); the DATA division has an ad-hoc method-only arm (COBOLNET1519 in
  `DataBinder.Oo.cs`), a 2023-only ConstructRegistry gate for method WORKING-STORAGE (PB1308), and nothing for
  LINKAGE/LOCAL-STORAGE in a FACTORY/OBJECT paragraph (PB1251).
- ACTIVE-CLASS: `Binding/Model/ObjectRefDescriptor.cs#ActiveClass(containing)` requires a containing class, so
  `DataBinder.Oo.cs#OoBindObjectRefDescriptor` refuses the phrase in an interface prototype's linkage (COBOLNET1924,
  PB1497), `SameDescriptionAs` compares containing-class names for an override (PB1112's override half), and
  `ClrTypeName` projects the containing class as the C# parameter type (so relaxing the compare alone is CS0115).
- Override/implements C# projection: `OoConformance.cs#ValidateImplements`' covariant `AdapterPair` and the override
  emitter convert only CobolObject-typed returns; an INTERFACE-typed implementation of a universal-returning prototype
  passes the binder (rule 5 a)) and fails in Roslyn with CS0266 (PB1499).

Measured (this tree): `INHERITS FROM C1020B C1020B` → 0849; `CLASS-ID. CSELF INHERITS FROM CSELF` → 0820 citing
§11.3.2; N5C inheriting SPEAK(X) and SPEAK() → compiles; MQ5J re-declaring inherited PING → compiles; factory
METHOD-ID NEW (with and without BASE / with OVERRIDE) → 0836; OBJECT paragraph LINKAGE SECTION / LOCAL-STORAGE
SECTION → compile clean at 2002; method WORKING-STORAGE → compiles at 2002 and 2014 (MW=01, MW=02); ACTIVE-CLASS in an
interface prototype → 1924 + a cascading 0841; interface-typed implementation of a universal-returning prototype →
CS0266; ACTIVE-CLASS formal in an OVERRIDE → 0829; `SET P TO ADDRESS OF OW` (object WS) at 2014 → compiles.

## Proposed single structure

1. **`OoDefinitionRules`** — the twin of `OoEnvironmentRules`: one table keyed (definition kind: class, parameterized
   class, factory, instance, interface, method, method prototype, program/function prototype × element: each DATA
   DIVISION section, ACTIVE-CLASS usage, INHERITS/IMPLEMENTS name list, METHOD-ID attributes), judged ONCE per PARSED
   definition (not per table entry), so skeletons and interfaces are covered by construction. It absorbs COBOLNET1519's
   method arms, PB1251's factory/object LINKAGE/LOCAL-STORAGE, PB1308's method WORKING-STORAGE (with the edition
   window the owner decides) and the SR16 ACTIVE-CLASS placement (a prototype IS a method definition, §10.6.1 NOTE).
   Drift test: every `OoDefinition` × DATA DIVISION section cell has a verdict (admitted / rule cited).
2. **One descriptor per rule** (DiagnosticCatalog, never a bare literal — PB745's standing defect): split 0820 into
   duplicate-class / END-name / §11.3.3 SR3 / SR4; SR7 and §11.6.3 SR6 are "repeated name in an INHERITS clause" (ONE
   rule shape for both clauses, keyed on the WRITTEN name — PB1502's alias question is the owner decision below),
   checked BEFORE the A.4.10 multiple-inheritance decline.
3. **Owner-less ACTIVE-CLASS**: `ObjectRefDescriptor.ActiveClass` without a containing class as a DESCRIPTION (the
   binding GR22 e) makes at activation is a property of the activation, not of the description); the C# projection of
   an ACTIVE-CLASS formal in an override chain is the root declaring class's type (so the override's signature equals
   the base's), and `ValidateImplements`' adapter test moves to a C#-type comparison.
4. **Covariant adapter over every rule-5 return kind** (universal / class / interface / ACTIVE-CLASS) with a drift test
   enumerating `ObjectRefKind` against the adapter's cases (PB1499).

## Progress (wave 1015, group Z)

Decomposition item 1's CLASS half (PB1020 + PB1505) and item 6 (PB1582) are LANDED: §11.3.3 SR3/SR4/SR7 have their own
descriptor (COBOLNET2791, split off COBOLNET0820) and are asked — with SR2/SR5 — of every class definition, the
parameterized skeletons included; SR7 precedes the A.4.10 decline, which counts distinct names. A factory METHOD-ID NEW
is ordinary outside BASE and overrides BASE's New inside it (COBOLNET0836 retired). The interface half of item 1
(§11.6.3 SR6 sharing SR7's descriptor) is still open here.

## Progress (wave 1011, group C)

Decomposition items 3 (PB1251: `OoDefinitionRules`, the DATA-division placement table — `Binding/OoDefinitionRules.cs`) and
4 (PB1497 + PB1112's override half: the owner-less ACTIVE-CLASS description) are LANDED. The C# projection chosen for item 4
is stronger than "the root declaring class's type": an ACTIVE-CLASS formal crosses the method ABI as the universal object type
(`OoEmitter.OoFormalCrossingType`) and the body casts it to the containing class, which makes the interface prototype, the
implementing class and every override one signature. Item 5 (PB1499, the covariant adapter over every rule-5 kind) is
narrower after this: the adapter is chosen by the two projected C# types (`ValidateImplements`).
