# PB3102 — one raisable-name structure and the registry that keeps it honest

Filed 2026-10-12 by the Mythos session (operator task w1069x; the model is PB1762, the brief PB1037). Measured on
`ddee217e3` (scratchpad `ec_names_scan.py`); citations through `python scripts/spec/cite.py --check`.

## Measured

- `ExceptionCatalog` quotes 135 level-3 names. 35 occur in no `src/` file outside the catalog: 18 of the 22
  `EC-<family>-IMP` names (Table 13's implementor-defined level-2 name per family; DOC-A.1-100 records that the
  implementation sets only EC-PROGRAM-IMP, raised by `ProgramRegistry`; the other four are named elsewhere in `src/`),
  the seven `EC-MCS-*` (the Message Control System is declined, CONFORMANCE.md §4), the four
  `EC-SCREEN-*` and three `EC-VALIDATE-*` (declined likewise), `EC-BOUND-FUNC-RET-VALUE`, and `EC-I-O-LOGIC-ERROR` /
  `EC-I-O-PERMANENT-ERROR`, which the I-O status map (`ExceptionCatalog.IoMaskNames`) raises without a literal
  elsewhere. PB1037 counted 64 of 130 on 2026-09; PB1453, PB1531, PB1036 and the sweeps since closed 29 of them.
- `EcBinder.cs` names 82 of the 135, in three forms with no common enumeration: the `QueryFor` switch's ~25
  node-kind arms over eleven family arrays (`SizeNames`, `IoNames`, `ProgramNames`, `OoInvokeNames`, …), the operand
  walker `OperandRaisableNames` (landed by PB1453 with one declaration, EC-PROGRAM-NOT-FOUND), and the ambient tail
  (EC-SIZE for non-arithmetic statements, EC-LOCALE-*, EC-BOUND-OVERFLOW, EC-FLOW-USE, …). The four intrinsic-family
  gates still test `ContainsIntrinsic(node)` beside the walker — the comment at the walker's call site names folding
  them in as this note's work.
- The catalog is CLOSED since PB1531 (`TryGet` refuses an uncatalogued `EC-IMP-suffix`), so the universe a drift test
  enumerates is finite — PB1037's precondition holds.

## The rules (cite-checked)

| Rule | Verbatim fragment | cite.py |
|---|---|---|
| §14.6.13.1.1 | "If checking for an exception condition is enabled and an exception status indicator is set as a result of an exception detected during the execution of a statement, the associated exception condition is raised" | OK §14.6.13.1.1 |
| §14.6.13.1.1 | "Therefore, when the general rules for a statement indicate that a specific exception condition exists, it is raised only if checking for that exception condition is enabled" | OK §14.6.13.1.1 |
| §8.4.3.13.4 GR4 | "If the runtime system cannot locate the program, the EC-PROGRAM-NOT-FOUND exception condition is set to exist and the value of the address-identifier is the predefined address NULL" | OK §8.4.3.13.4 4) |
| §14.6.13.1.1 | "There are two types of level-3 of implementor-defined exception-names" | OK §14.6.13.1.1 |

The raise belongs to the detection (the first fragment), and the statement's enabled set must carry every name its
detections can set (the second), or the raise is lost in silence. A name is raised by a STATEMENT SHAPE (a READ's I-O
status, a CALL's program lookup), by an OPERAND wherever it is written (a program-address-identifier, a function
reference's argument check, §15.3), or AMBIENTLY by a site no bound node identifies (a locale's collating sequence at
use). Those are the three sources the structure must name, each read mechanically.

## Fix shape (apply-ready) — the design is docs/COBOLNET_CONDITIONS_EXCEPTIONS_DESIGN.md D13

1. **One enumeration.** `EcBinder.DeclaredRaisableNames(BoundStatement)` returns the union the `EcWrap` query reads:
   the node-kind arms (the switch stays — it is the structure for statements that raise through their own shape, and
   each arm names a family array), `OperandRaisableNames` and the ambient tail. `QueryFor` becomes that enumeration
   filtered by `Turn.Enabled`; nothing else computes a statement's names. The declared sets are also exposed per
   source — `NodeKindNames`, `OperandRaises`, `AmbientNames` — so the drift test does not re-parse C#.
2. **The intrinsic families fold into the operand walker.** `OperandRaises` gains four declarations keyed on "carries
   an intrinsic call" (`PartHasIntrinsic` over the generated value parts; a LOCALE-bearing module adds EC-LOCALE-INVALID
   for every statement as today): EC-ARGUMENT-FUNCTION (§15.3 item 14), EC-ORDER-NOT-SUPPORTED, EC-DATA-CONVERSION,
   EC-LOCALE-INVALID. `ContainsIntrinsic` and its nested-statement recursion go: a nested statement is wrapped by its own
   `EcWrap` and is its own EC region (kb/Work PB441), so the recursion wrapped twice.
3. **The runtime declares what it raises.** Every raise helper names its names once: `ExceptionState.Raise…` /
   `Set(name, …)` literals are collected by a Roslyn walk of `src/Cobol.Net.Runtime` in the test (no registry object to
   maintain by hand), and `ExceptionCatalog.IoMaskNames` is the status map's declaration.
4. **`EcRaiseSiteRegistryDriftTests`.** For every catalogued level-3 name (`ExceptionCatalog.AllLevel3`, the closed
   universe): it is declared by the binder (1) AND raised by the runtime (3), OR it is on `DeclinedRaiseSites`, a table in
   the test project whose every entry names a `kb/Work` note or a `docs/CONFORMANCE.md` anchor that says why it is never
   raised — the `EC-*-IMP` names DOC-A.1-100 says the implementation never sets (EC-PROGRAM-IMP is raised by
   `ProgramRegistry` and must be declared), `EC-MCS-*`, `EC-SCREEN-*`, `EC-VALIDATE-*` (the declined facilities of
   CONFORMANCE.md §4). A name declared but never raised is a dead guard; raised but never declared is the PB452 / PB1453
   shape; each fails with a message naming the shape. `EC-BOUND-FUNC-RET-VALUE` is the one name with no home today: the
   implementer measures its raise (§15 returned-value rules) and either declares it or files its note before the
   allow-list may name it.
5. **Prove the watchdog fails.** Delete `BoundSetEntry`'s EC-PROGRAM-NOT-FOUND arm locally; the test names it;
   restore.
6. **Goldens.** `conformance:2023/pb3102_intrinsic_names_ride_every_statement` (EC-ARGUMENT-FUNCTION, EC-DATA-CONVERSION
   and EC-ORDER-NOT-SUPPORTED raised from a function reference inside STRING, EVALUATE, SEARCH and a subscript — the
   statement kinds PB26 found silent), pinned alongside the existing `EcArgumentFunctionGateDriftTests`.
7. **Closes** PB1037 (its brief is this shape) and flips PB1762 to landed; PB1453 and PB1531 are already landed.

**Cost.** One Opus slot: the classification of 135 names into declared / raised / declined, and the allow-list with a
note or determination per entry. The owner's trade-off (2026-10-12) favors it: PB1036's four names sat unraised for
months behind a green suite, and the registry is the only shape under which that cannot recur.
