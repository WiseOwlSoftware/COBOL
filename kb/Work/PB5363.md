# PB5363 - messages seeded for a terminal defined enabled:false in mcs.json are RECEIVE-able: does input enter the queue only when the terminal is enabled?

**Sites:** none (analysis; the code site for any later change is `src/WiseOwl.Cobol.Runtime/Communication/McsSeeding.cs:44` (`McsSeeding`)).

**Question owed.** Messages seeded for a terminal that mcs.json defines `enabled:false` are held at seeding and, since PB5315, can be taken by RECEIVE. The report says "1985 reading says input enters when enabled", so a disabled terminal's seeded input would stay out of the queue structure until the terminal is enabled. The report calls this a judgment call, documented nowhere else.

**Owed.** An adjudicator reads the 1985 communication chapter (§1985:XIV; derive the exact enable/disable rule with `cite.py --check`, none is asserted here) and decides: (a) seeded messages of a disabled terminal are not receivable until enabled, or (b) the seeding model is a test fixture outside the standard and the current behavior stands. Either outcome is recorded in `docs/CONFORMANCE.md` (CLAUDE.md rule 1: the implementor choice is documented there). If (a), file the defect note with this one as its analysis.
