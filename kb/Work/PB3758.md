# PB3758 — does match rule 3 e) relax for restricted pointers on the INVOKE lane?

**Sites:** `src/WiseOwl.Cobol.Runtime/Control/ActivationRelations.cs#MatchViolation`, `src/WiseOwl.Cobol.Runtime/Control/ActivationRelations.cs#SameClausesAtFormalLength`.

Filed 2026-10-25 by the enqueue clerk from a lead the PB3686 implementer did not probe (MINOR, rejects-legal-source). `MatchViolation` (ActivationRelations.cs about line 59) ends
in `SameClausesAtFormalLength` (about line 141, called at line 86), so a universal or typed INVOKE passing a pointer restricted to an UNRESOLVED prototype into a formal
restricted to ANOTHER unresolved prototype fails §9.3.6 match rule 3 e) ("the same … USAGE clauses"), while the SET and CALL lanes admit the pair after PB3162 (the
`SamePointerRestriction` relaxation) and PB3686 (the RETURNING lane). The same root as PB3162 and PB3686: unresolved prototype identity.

## Why this is an analysis, not a fix
Whether match rule 3 e) should relax there is a method-resolution question. Method matching decides which method an INVOKE selects, so relaxing the comparison can make two
candidate methods both match (an ambiguity, §9.3.6) that the strict comparison told apart. An adjudicator or the owner reads §9.3.6 3 e) and the ambiguity rules first
(`cite.py --check 9.3.6` on the wording), then either relaxes `SameClausesAtFormalLength` for the restricted pair (with a golden of two candidates that stays unambiguous) or records
the strict comparison as the intended reading with its reason in `docs/CONFORMANCE.md`.

## Not probed
The lead is a code reading. First step: write the INVOKE program with two prototype-restricted pointer types (the shape of PB3686's golden
`pb3686_returning_external_prototype_pointer`) and observe the diagnostic.

## Verdict (2026-10-30): INVOKE CONFORMS; the under-rejection elsewhere is PB4107

Three passes, all with every quote checked by `cite.py --check`, under `E:/COBOL-coord/scratch/adj/`:
1. `PB3758-verdict.md` (cobol-adjudicator): DEFECT, INVOKE rejects legal source; relax `MatchViolation` to compare
   restricted pointers through `SamePointerRestriction`.
2. `PB3758-refute.md` (cobol-refuter): OVERTURNED. The BY REFERENCE rules require identity: §9.3.6 3 e) "the same ...
   USAGE clauses" and §14.8.2.3.2 "both shall be restricted and of the same type", with "same type" defined by §8.5.3.1
   (same type-name). Only SET (§14.9.39.3 SR20 / SR22) and CALL SR14 say "same signature".
3. `PB3758-final.md` (a third, deciding cobol-adjudicator): INVOKE CONFORMS; UNDER-REJECT ELSEWHERE. The refusals this
   note called wrong (typed INVOKE COBOL0828, universal EC-OO-METHOD, the function-pointer twin) are what the standard
   requires. The ISO text decides; no latitude, no owner decision.

So this note closes with no code change and `rejects_legal_source: false`. The relaxation it proposed would have turned
required refusals into silent acceptance. What the adjudication found instead (the BY REFERENCE and RETURNING lanes
answer the identity rules with the signature relation, and never compare the items' own type) is filed as PB4107,
with three goldens and docs/OO_DESIGN.md that encode the under-rejection, and the docs/CONFORMANCE.md determination.
