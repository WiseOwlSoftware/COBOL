# PB3145 — a stamped entry belonging to a still-open queued PR ends the landing as NO ENTRY

> flags: process-only

Source: `E:\COBOL-coord\scratch\reports\w1073b-PB3132-report.md`, "Finisher (2): NO ENTRY".

**What was seen.** `worktree-wf_c6c6fa26-b3b-9` contained `worktree-wf_dfc118ad-872-4`, which had merged `worktree-wf_4959cab1-c5a-12` AFTER enqueue.py stamped c5a-12's entry DEVLOG 2005 (commit 8bceb31ee) and queued it as PR #46. When the landing lane merged main into b3b-9 (733f1e7f3, attempt 20261014T050445450254Z), #46 had not merged, so the branch added two stamped entries (2005 and its own 2016) and enqueue.py ended `=== ENQUEUE: NO ENTRY - the branch adds no single stamped DEVLOG entry to title its pull request ===` (exit 6). `devlog.py stamp` folds only PENDING entries, which is right: a stamped entry is another PR's title and keeps its number (PB3123). #46 merged 47 minutes later, and a clean merge of main then left exactly one entry. Cost: one finisher and one gate for a stop that main resolved by itself.

**Code sites.** `scripts/orchestrator/enqueue.py:433` (`if len(new) != 1: return "", ""` in `pull_request_text`, over `devlog.landing_entries` called at `:430`) and `:545-546` (the `NO ENTRY` end); `scripts/devlog.py:256` (`landing_entries`); the exit classes in `scripts/orchestrator/land_lane.py`.

**Proposed shape.** Classify "an added stamped entry that belongs to a still-open queued pull request" as a RETRY-WHEN (like exit 3's RETRY-WHEN-FREE), not a finisher stop: attribute the extra stamped entries to their pull requests and have the lane retry once those merge. Related: PB3123 (a stamped entry keeps its number).

## Landed (2026-10-24, fix-lane wave 20261104 group A, with PB3662)

Re-probed: `enqueue.land` step 4 reads `devlog.landing_entries`; a branch that merged a predecessor whose entry is stamped
and whose pull request is open adds two stamped entries, `pull_request_text` returns no title and `land` ended exit 6 NO
ENTRY (a STOPPED the lane never relaunches). Fixed at the root, one reader (the note asked for "a RETRY-WHEN, like exit 3"):
`enqueue.open_predecessors(wt, base, branch, gh)` lists the open pull requests into main (GitHub's own list, the branch's
own pull request excluded, with the files each current head changes), and maps each to the entries it adds that the branch
carries and main does not (review R1-2: not by requiring its head to be an ancestor of the branch, which a bounce re-landed
with newer main breaks; a file list GitHub cut off at 100 files still asks the ancestry, with `devlog.landing_entries`). `enqueue.awaited_predecessors` answers a wait only when the entries those pull
requests own, taken from the landing's new entries, leave EXACTLY ONE. `land` then ends the new exit 15, PREDECESSOR QUEUED
(`EXIT_PREDECESSOR_QUEUED`: nothing queued, no report line; the branch keeps the merge and the stamp); GitHub unreadable is
exit 9 (retried once), and a predecessor pull request that CLOSED unmerged leaves no open pull request to wait for, so the
same head ends exit 6 NO ENTRY as before (a finisher's). `land_lane` carries exit 15 in `WAITS`, and
`land_lane.predecessor_free` (through `wait_free`) asks the same reader, so the lane relaunches the same head once no open
pull request owns an entry the branch carries (GitHub unreadable is not free). Self-tests: `enqueue` (a wait with the
branch's own pull request in the list, unreadable GitHub, a closed predecessor, then the merged predecessor lands and the
pull request is titled from the one entry), `land_lane` (exit 15 waits, names the pull request, relaunches the same head
with no `rearm`). The two recorded witnesses (PB3112 at 59.8 min, PB3267) are this shape.
