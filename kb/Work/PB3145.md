# PB3145 — a stamped entry belonging to a still-open queued PR ends the landing as NO ENTRY

> flags: process-only

Source: `E:\COBOL-coord\scratch\reports\w1073b-PB3132-report.md`, "Finisher (2): NO ENTRY".

**What was seen.** `worktree-wf_c6c6fa26-b3b-9` contained `worktree-wf_dfc118ad-872-4`, which had merged `worktree-wf_4959cab1-c5a-12` AFTER enqueue.py stamped c5a-12's entry DEVLOG 2005 (commit 8bceb31ee) and queued it as PR #46. When the landing lane merged main into b3b-9 (733f1e7f3, attempt 20261014T050445450254Z), #46 had not merged, so the branch added two stamped entries (2005 and its own 2016) and enqueue.py ended `=== ENQUEUE: NO ENTRY - the branch adds no single stamped DEVLOG entry to title its pull request ===` (exit 6). `devlog.py stamp` folds only PENDING entries, which is right: a stamped entry is another PR's title and keeps its number (PB3123). #46 merged 47 minutes later, and a clean merge of main then left exactly one entry. Cost: one finisher and one gate for a stop that main resolved by itself.

**Code sites.** `scripts/orchestrator/enqueue.py:433` (`if len(new) != 1: return "", ""` in `pull_request_text`, over `devlog.landing_entries` called at `:430`) and `:545-546` (the `NO ENTRY` end); `scripts/devlog.py:256` (`landing_entries`); the exit classes in `scripts/orchestrator/land_lane.py`.

**Proposed shape.** Classify "an added stamped entry that belongs to a still-open queued pull request" as a RETRY-WHEN (like exit 3's RETRY-WHEN-FREE), not a finisher stop: attribute the extra stamped entries to their pull requests and have the lane retry once those merge. Related: PB3123 (a stamped entry keeps its number).
