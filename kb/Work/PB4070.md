# PB4070 — the review lane's sessions read as the attended operator lane

Grepped kb/Work for PB2814, PB3387, PB3608, PB2778, PB2819: they cover the operator's own watcher, the review lane's existence, the loop
unit's stall_watch and mailbox lane naming; none covers the lane's sessions being mistaken for the operator.

## Mechanism

`review_lane.py#run_agent` starts `claude -p --agent cobol-finisher|cobol-reviewer` with `env = {**os.environ, "COBOL_COORD_DIR": ...}`.
The supervisor's environment carries no `COBOL_LOOP_UNIT` (`coord.LOOP_UNIT_ENV`; `orchestrate.ps1` sets it only on a unit's own process,
line ~468), so the lane's sessions read as the attended OPERATOR lane: `inbox_guard.py#decide` refuses their turn end until they arm
`mailbox.py watch --inbox operator --timeout 0`, and `mailbox.lane` / `session_start.py` name them the operator too. The watcher is a
background task that never ends by itself, so the session outlives its result; each new operator-mailbox message re-wakes it (another paid
turn), until the lane's ceiling kills it (`REVIEWER_CEILING_MIN` 90, `FINISHER_CEILING_MIN` 240).

## Harm

The lane runs at most `MAX_AGENTS = 3` sessions; a finished session that idles holds a slot, so reviews and conflict finishers for other
branches wait for up to 4 hours. A woken reviewer also read the operator's mailbox and moved its cwd into the main checkout.

## Fix direction (recorded, not decided)

`run_agent` marks its session as a loop session (export `coord.LOOP_UNIT_ENV`, e.g. `review-lane-<kind>`, or a lane marker of its own that
`inbox_guard`, `mailbox.lane` and `session_start` read), with a self-test arm in review_lane.py; check `dispatch_guard.py` keeps working
for a marked session (a reviewer dispatches nothing).

**Sites:**
- `scripts/orchestrator/review_lane.py#run_agent`
- `scripts/hooks/inbox_guard.py#decide`
- `scripts/orchestrator/mailbox.py#lane`
