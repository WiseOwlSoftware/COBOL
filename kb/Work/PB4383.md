# PB4383 - DISPLAY operands report their undefined-name diagnostic at the statement's position

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/AcceptDisplayBinder.cs:257` (`AcceptDisplayBinder.BindDisplay`, which binds each `dataReference` operand through `host.Expr.FieldOperand(dref)` with the sink's cursor still at the statement), `src/WiseOwl.Cobol.Compiler/Binding/DiagnosticCursorAt.cs` (`DiagnosticCursorAt.At`, the overload to call per operand).

**Sites (landed):** `src/WiseOwl.Cobol.Compiler/Binding/ReferenceResolver.cs:365` (`ReferenceResolver.ResolveImpl`, which now positions the cursor at the reference), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/AcceptDisplayBinder.cs:279` (`AcceptDisplayBinder.BindDisplay`, per-operand position), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/MoveBinder.cs:117` (`MoveBinder.Bind`, the index-name screen), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/ControlFlowBinder.cs:132` (`ControlFlowBinder.StatusOperand`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/StringUnstringBinder.cs:420` (`StringUnstringBinder.ScreenedField`), `tests/WiseOwl.Cobol.Tests.Conformance/DiagnosticPositionTests.cs` (`OperandOnAContinuationLine_NamesItsOwnLineAndColumn`), `docs/VALIDATION_DESIGN.md` (Positions).

**Read at:** origin/main 4aff86e01 (the DISPLAY binder is unchanged on the PR #971 branch a4f54e0a4). The member that raises COBOL1639 under `FieldOperand` was not traced; the implementer confirms it.

Repro (outside the repo): `E:/COBOL-coord/scratch/w20261804b/fin/l2.cob`: `DISPLAY W-X` on line 8 and `Q-ONE Q-TWO.` on line 9, the two names undefined. COBOL1639 for Q-ONE and Q-TWO is reported at (8,12), the DISPLAY statement, not at line 9. A user editing a long DISPLAY list gets the statement's first line for every undefined operand (the names are in the message, so the diagnosis is misled by position, not lost).

Related: PB1315 (open: diagnostics reported with no location because a walker never positions the sink's DiagnosticCursor), the same family at other statements. Sibling sweep for the implementer: every multi-operand statement binder that binds operands under one statement-level cursor (callers of `FieldOperand(`).

Grepped `kb/Work` for `l2.cob`, `Q-ONE`, `DISPLAY operand`, and COBOL1639 with continuation or position: no note covers this. The wave's first report carried it with a repro that now draws COBOL5818 instead.

## Landed (wave 20261811 group B)

**Re-probe (2026-11-01, main 3b34806eb).** `l2.cob` drew `(8,12) COBOL1639` for both Q-ONE and Q-TWO, the DISPLAY's own
position, though they stand at line 9. The note's guess about `FieldOperand` was half right: the report is made inside
`ReferenceResolver.ReportUnidentified`, which never positioned the sink, so it said where the enclosing statement began.

**Root.** Positioning a diagnostic about a reference was every statement binder's job, so an operand after the first
line of a statement was misplaced for every verb, not for DISPLAY alone. The fix is at the one chokepoint: `ResolveImpl`
opens `using var _ = data.Edition.At(dref)`, so everything the resolution reports (COBOL1639, the ref-mod and linkage
screens, COBOL2364) lands on the reference's first token, and a nested subscript restores the outer one. `BindDisplay`
positions each operand for the screens that run after the resolution (COBOL1637 index-name, the excluded-class refusal).
The three other callers of `ScreenIndexNameOperand` that sat under a statement cursor (MOVE's sender, the STOP RUN /
GOBACK status, STRING/UNSTRING `ScreenedField`) do the same; `ScreenOperandClass` has only the DISPLAY caller.

**After.** `l2.cob`: `(9,16) 'Q-ONE'`, `(9,22) 'Q-TWO'`. `DiagnosticPositionTests` pinned the old statement column in
three places (`BindError_NamesFileLineAndColumn`, and the `cursor` and `switch` rows of
`FixedForm_DiagnosticNamesThePhysicalColumn`); they now pin the operand's. The new fact covers DISPLAY, MOVE, STRING and a
DISPLAY index-name on a continuation line. No conformance golden: the refusal goldens (`wiseowl/diagnostics/*.json`) pin
the edition and the code, never the position.
