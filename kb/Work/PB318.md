# PB318 — four OPEN syntax rules with nowhere to live

**Rows:** `SR-14.9.27.3-1`, `SR-14.9.27.3-2`, `SR-14.9.27.3-5`, `SR-14.9.27.3-6`.

## The programs

All under `<lane3 scratch>/out-b1/probe/open-p1/`, each compiling CLEAN at `--std 2023` **and** `--std 85`
(exit 0, no diagnostics):

| probe | source | rule violated |
|---|---|---|
| `rpt1.cob` / `rpt2.cob` | `OPEN INPUT RPTF` / `OPEN I-O RPTF`, RPTF's FD carrying `REPORT IS RP1` | SR1 |
| `ext1.cob` | `OPEN EXTEND FR`, FR is `ORGANIZATION IS RELATIVE` `ACCESS MODE IS RANDOM` | SR2 |
| `ext2.cob` | `OPEN EXTEND FL`, FL's FD carrying a LINAGE clause | SR2 |
| `rew1.cob` | `OPEN INPUT FR WITH NO REWIND`, FR is `ORGANIZATION IS RELATIVE` | SR5 |
| `rew2.cob` | `OPEN EXTEND FS WITH NO REWIND` on a plain sequential file | SR6 |

`rpt3.cob` (`OPEN OUTPUT RPTF`) is the legal control and also compiles, so the report file really did bind.

## The rules

> SR1: The OPEN statement for a report file shall not contain the INPUT phrase or the I-O phrase.

> SR2: The EXTEND phrase shall be specified only if the access mode of the file connector referenced by
> file-name-1 is sequential and the LINAGE clause is not specified in the file description entry for
> file-name-1.

> SR5: The NO REWIND phrase may be specified only for sequential files.

> SR6: The NO REWIND phrase may be specified only when the INPUT or OUTPUT phrase is specified.

All four `--check 14.9.27.3` → **OK**. Note what SR2 keys on: the **access mode**, not the organization, so
EXTEND stays legal on a relative or indexed file whose `ACCESS MODE IS SEQUENTIAL` and is illegal on any RANDOM
or DYNAMIC one. §13.18.46's general rule independently confirms SR1 and is stronger — a REPORT-clause file may
be referenced in the procedure division only by USE, the WHEN phrase of PERFORM, CLOSE, or an OPEN with the
OUTPUT or EXTEND phrase — so one screen discharges both.

## What the compiler does

`BindOpen` resolves file-names, records modes, and does nothing else. Every fact the four screens need is
already on `FileModel` at bind time: `ReportNames` (populated at `DataBinder.cs:1001`, already consumed by
`EmitFileRegistration`), `AccessMode`, `Organization`, `Linage`. `StatementValidation` is the established home
for exactly this kind of pure check and already holds `CheckWriteEopLinage` (§14.9.51 SR19, the identical LINAGE
shape) and `CheckOpenSharingAllOther` — OPEN simply never asks.

The absence is **measured**, not inferred: every `BoundOpenMode.` site, every `ReportNames` site, every
`.Linage` site and every `EXTEND()`/`REWIND` site in `src/Cobol.Net.*` was searched, plus `StatementValidation`,
`VersionConformancePass` and `FlagConformancePass`.

The diagnosis is sharpest for SR5: **its CLOSE twin §14.9.6.3 SR1 IS implemented** —
`SequentialIoBinder.BindClose` rejects a NO REWIND / REEL / UNIT phrase on a non-sequential file with
`DiagnosticCatalog.ClosePhraseOrganization`, and `FileRegistry.CloseNoRewind` carries a defensive assert that
the bind-time screen held. The same phrase on the OPEN arm of the same verb pair got nothing.

**Code sites:** `SequentialIoBinder.cs#BindOpen` (no screen) · `StatementValidation.cs` (where the four checks
belong, beside `CheckOpenSharingAllOther`/`CheckWriteEopLinage`) · `CobolIO.g4#openFileSpec` (the NO REWIND
token, unread past `VersionConformancePass#VisitOpenFileSpec`) · contrast `SequentialIoBinder.cs#BindClose`.

## Sequencing

SR5 and SR6 cannot be written at all until the NO REWIND phrase is carried into the bound tree, which is the
per-group `BoundOpen` restructuring **PB316** requires and **PB317** needs — the three land together. SR2's
runtime consequence is **PB325**.

## Landed (wave 56, group PB318/PB330/PB333/PB357)

The two remaining rules now have ONE site: `StatementValidation.CheckOpenModeForFile(file, mode)`, called per
file-name from `SequentialIoBinder.BindOpen` with that group's mode, beside SR8's and SR5/SR6's screens. SR1 →
COBOLNET2371 `open-report-file-mode` (on the new `FileModel.IsReportFile`, now also the spelling at the two older
`ReportNames.Count > 0` sites); SR2 → COBOLNET2372 `open-extend-access-linage`, one code for the one sentence,
the message naming the conjunct (access mode not sequential / LINAGE present), both reported when both fail.
`--check 14.9.27.3` SR1/SR2 and `--check 13.18.46.3` SR3 → OK. Re-probed on this build (`w56a/probe/rpt1.cob`,
`ext1.cob`, at 85 and 2023): BEFORE rc 0, no diagnostic; AFTER INPUT/I-O of a report file, EXTEND on RANDOM and
DYNAMIC relative files and on a LINAGE file are rejected, and EXTEND on a relative file with ACCESS MODE IS
SEQUENTIAL is accepted. Goldens: `conformance:2002/pb318_open_extend_sequential_access` (positive, GR15
positioning), `conformance:negative/pb318-open-report-file-input`, `conformance:negative/pb318-open-extend-access-linage`.
⚠ `conformance:2023/pb326_ec_report_file_mode` carried an ARM 2 that opened its report file INPUT — source SR1
forbids — and it was removed (with its `.out` line and the REPORT_WRITER design doc's description) in this change
set. SR9 (I-O with a FORMAT clause) stays discharged by the FORMAT clause's documented non-support (A.4.8).
