# PB1009 — LANDED

## Repro — measured
`scratchpad/w51a/glb.cob` → `error: backend compilation failed … (136,36): error CS0106: The modifier 'private' is not
valid for this item`, `CS0246 '__lnkp0'`, `CS0538`, `CS8156`, `(167,60): CS0120`.

## The rules
`OK  §13.18.27.3 1) b)` — the GLOBAL clause may be specified in "A data description entry whose level-number is 1 that is
specified in the file, working-storage, local-storage, or linkage section."
`OK  §13.18.27.4 2)` — "A statement in a program contained directly or indirectly within a program that describes a global
name may reference that name without describing it again."

## Code site
`BinderDriver.BindUnitData`'s GLOBAL bridge loop and ProgramEmitter's bridge emission: an elementary LINKAGE formal is a
carrier-resident `ref` field (`__lnkpN`), and the bridge writes a member-access path where a property name belongs.

## What the fixer owes
Bridge a carrier-resident formal through the same accessor shape the containing program uses to read it; sweep the
other residences a GLOBAL item can have (group formal, BASED item, and the LOCAL-STORAGE and FILE entries SR1 b) also admits) and
golden each. Not the PB971 mechanism.

## Landed (2026-09-22, wave 54 group B, worktree wf_e17d58be-cc0-2)
Re-probed on this worktree's build: `glb.cob` reproduced exactly (CS0106/CS0246/CS0538/CS8156/CS0120). A wider probe
found TWO more defects of the same root: the contained program's OWN first formal and the container's first
formal were BOTH `__lnkp0.Value`, so the contained program's references to either read one carrier; and a GLOBAL
BASED item's address pointer was never bridged (CS0120 on `__addr_BB`).
- The carrier name is Uid-keyed (`__lnk{Uid}`, the `__omit{Uid}` rule), so no bridge can collide.
- The bridges come from ONE list, `DataBinder.GlobalBridgesOf` (field | Tier-B backing + the StorageCell behind a
  cell-backed class + a BASED class's address pointer | a resident formal's carrier; then presence and index
  members); `CallBridge.Kind` is an enum. `GlobalBridgeResidenceDriftTests` (Unit) runs one row per residence.
- `ADDRESS OF` a global name taken in a contained program forces the cell in the CONTAINER
  (`PtrBindBasedAndAddressables` scans the nested programs for this unit's GLOBAL names); `PtrBinder` asks the
  class (`IsCellBacked`) and `PtrEmitter` renders the cell the class names — both used to consult THIS unit's
  tables, which a contained program's reference could never satisfy (COBOLNET0869 on legal source).
- GLOBAL CONSTANT-names (§13.18.27.4 GR1 names them) now substitute in contained programs; a local constant or
  data-name shadows (`InheritGlobalConstants` / `DropShadowedConstants`) — the recorded P10 residue.
Golden `tests/conformance/2002/pb1009_global_linkage_formal`. Row GR-13.18.27.4-2 stays GAP here: its PARTIAL batch (report-name residue) is
ready at the wave's scratch `w54b/PB1009/verdicts-pb1009.json` and is applied with the note that owns the residue.
