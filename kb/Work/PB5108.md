# PB5108 - at --std 85 a numeric or integer intrinsic function is accepted outside an arithmetic expression (MOVE, DISPLAY, PERFORM ... TIMES), where the 1989 addendum restricts them to arithmetic expressions

**Sites:** none (not located: the records name no site and the implementer locates the function-placement member)

**Mechanism.** The 1989 Intrinsic Function module (§1989:A.2.3 GR2 and GR3, restated by §1985:IV.4.3.8.3.3 SR4 as the records cite it) allows a numeric or integer function only in an arithmetic expression, and a numeric function may not be referenced where an integer operand is required (that third sentence is enforced: COBOL1646). The second sentences are not: `MOVE FUNCTION SQRT (4) TO N`, `DISPLAY FUNCTION SQRT (4)`, `DISPLAY FUNCTION LENGTH (W)`, `MOVE FUNCTION LENGTH (W) TO N` and `PERFORM FUNCTION INTEGER (2.5) TIMES` all compile with no diagnostic at --std 85 (none with --flag-extensions either). One mechanism for both rules.

**Found by.** The 1985 MATCH confirmation pass (kb/Work PB4995 item 3): each rule below is a corrected draft (a "redraft") that the compiler at `--std 85` still fails (redraft_run MISMATCH). Harm and observed text are the records; nothing here was re-derived.

**Inventory.** The traceability inventory carries no 1985 rows yet (PB5094: work.py refuses 1985 ids), so `inventory_rows` is empty; the rows this note covers are the 1985 rule ids listed below (catalog `docs/rearchitecture/spec-rule-catalog-1985.json`).

**Rules (2; every citation checked with `scripts/spec/cite.py --check`).**

- `1989-GR-A.2.3-2` - `§1989:A.2.3 GR2` (record harm: under-rejects, slice-26): "A numeric function may be used only in an arithmetic expression" . The corrected draft is `MOVE FUNCTION SQRT (4) TO N` (line 8); the first draft tested only the third sentence, which is refused (COBOL1646).
- `1989-GR-A.2.3-3` - `§1989:A.2.3 GR3` (record harm: under-rejects, slice-26): "An integer function may be used only in an arithmetic expression" . The first draft sat in ordinary COMPUTE expressions where any numeric function is allowed; the corrected draft is the refusal the sentence requires (line 9, a `MOVE FUNCTION LENGTH (W) TO N` form). The output-shaped strengthening r06a.cob in work-slice-26 already matches.

**Repro (`1989-GR-A.2.3-2`, slice-26).** cobol.exe <file> --std 85 --source-format fixed --flag-extensions -o <file>.dll ; dotnet <file>.dll

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. T1.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 N PIC 9 VALUE 2.
       PROCEDURE DIVISION.
       P1.
           MOVE FUNCTION SQRT (4) TO N.
           DISPLAY N.
           STOP RUN.
```

**Expected (from the 1985 text).** A diagnostic at line 8. The deciding words: "A numeric function may be used only in an arithmetic expression" (§1989:A.2.3 GR2).

**Observed (copied from `1989-GR-A.2.3-2`).** Expected a diagnostic at line 8. Observed: compile exit 0, no diagnostic at any line (none with --flag-extensions either); the program runs and prints '2'. The control (COMPUTE N = FUNCTION SQRT (4)) compiles and prints '2'. Same mechanism, also accepted silently at --std 85: 'DISPLAY FUNCTION SQRT (4)', 'DISPLAY FUNCTION LENGTH (W)', 'MOVE FUNCTION LENGTH (W) TO N', 'PERFORM FUNCTION INTEGER (2.5) TIMES'.
