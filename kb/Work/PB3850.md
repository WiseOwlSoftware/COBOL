# PB3850 — the work-note merge keeps both sides of a replaced line

**Sites:** `scripts/merge_drivers.py#merge_file`, `scripts/merge_drivers.py#union_text`,
`scripts/merge_drivers.py#split_note`, `.gitattributes` (`kb/Work/PB*.md merge=cobol-work-note`),
`.claude/skills/workstream/templates/finisher-brief.md` (the conflict finisher's exit check),
`scripts/orchestrator/land_lane.py` (`conflict_brief`) (the conflict brief it writes), `docs/rearchitecture/DESIGN-test-build-ci.md`
(section 3.17.2 step 2, the drivers)

## The defect

`merge_drivers.py`'s WORK NOTES driver merges a note's frontmatter per key and its body by git's union merge, by design
"a line both rewrote differently is kept twice, visible to the reader, never lost". That is right for two appended
paragraphs and wrong for a replacement: when main replaces a line that the branch also changed (here PB3837's rename
rewrote the old line's paths while main's PB3830 landing replaced the whole `**Sites:**` line), the union keeps the
branch's stale line and main's new one, silently. Nothing reads the result before a reviewer does: PB3837's conflict
finisher returned a merged tree, and only the branch review (R3-1) found the duplicate, which then cost PB3849's gate
and review cycle.

The Mythos lane's check `chk.py` compared each merged file with the rename applied to main's file: 102 of 103 were
byte-identical, and the one that was not was this note. That check is what the finisher should have run before it
returned.

## Acceptance

- A body line that main replaced and the branch changed is a REAL conflict the finisher resolves (or the driver
  resolves it by a stated rule), never a silent union; two appended paragraphs still both survive. The driver's own
  docstring and the design doc state the new rule.
- The conflict finisher's exit check is mechanical: for a branch whose change is a declared transform (a rename), each
  merged file equals the transform of main's file plus the branch's own hand edits; for any branch, a merged note has no
  duplicated `**Sites:**`, frontmatter-derived or heading line. It runs before the finisher returns DONE.
- Self-test arms in `merge_drivers.py --self-test` (replacement vs both-changed vs both-appended), each seen RED first;
  sweep the other drivers (keyed JSON, PublicAPI, the ABI pin) for the same replace-versus-add confusion.
- Standing owner rules: fix the root cause, never simply making the diagnostic pass; stay consistent with ourselves.
