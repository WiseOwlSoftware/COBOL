# PB3788 — split brent-tools so this repository loads only the skills it uses

**Sites:** the public repository `tools/claude-skills` (submodule; local clone `E:\claude-skills`, origin
github.com/BrentRector/claude-skills): `.claude-plugin/marketplace.json`, `.claude-plugin/plugin.json`, a new plugin
manifest for brent-tools-extras, `skills/automating-agent-guardrails/`, `skills/claude-cloud-sessions/`,
`skills/cross-platform/`, `skills/devlog/`, `skills/roslyn-analysis/`, `skills/spec-compliance-audit/` (moved),
`evals/` (the nine cases of the six skills point at the extras plugin), `README.md`, `evals/README.md`; in this
repository `.claude/settings.json` (`enabledPlugins`), `.claude/skills/workstream/SKILL.md` (the pin line), the
`tools/claude-skills` submodule pin.

## Why

The owner's /plugin Stats tab (2026-10-25, E:/COBOL-coord/scratch/mythos/skills-opt/plugin-stats-2026-10-25.md) shows
the six skills never invoked in seven days while their listings (~1.1K tokens) sit in every turn of every session and
agent. The owner chose to disable them; /skills refuses ("locked by plugin"). Measured in the Claude Code binary
(2.x, 2026-10-23 build): a plugin skill's state comes only from an administrator setting or the plugin itself
(`Pro`/`Xke`/`Dpt`), so user and project `skillOverrides` never applied: account 1's settings.json has carried
`user-invocable-only` for these six since 2026-10-15 with no effect. Setting `disable-model-invocation` in the skills'
own frontmatter would hide them for every user of the public plugin and break the nine evals that prove each skill
changes what Claude does (each needs Claude to invoke the skill), against O7. A second plugin in the same marketplace
keeps the skills whole for other users and lets this repository enable only what it uses.

## Acceptance

- The marketplace lists two plugins; brent-tools keeps engineering-standards, review and its agents, variant-analysis,
  spec-oracle, test-gate, dotnet-engineering, agent-fleet, performance-diagnosis (architecture-review's oracle 5) and
  architecture-audit; brent-tools-extras holds the six. Both versions move (1.23.0).
- No alias, forwarder or duplicate (CLAUDE.md rule 4): every reference to a moved skill by its qualified name, in the
  public repo and here, names `brent-tools-extras:<skill>`, and account 1's dead `skillOverrides` entries for the six
  are removed.
- The nine moved eval cases run green against the extras plugin, and one core case (agent-fleet) against the core,
  before the push (MANDATORY-PRACTICES O7; memory "learnings vetted only": a public skill changes only with evidence).
- This repository's pin moves to the new public head in one landing; `.claude/settings.json` enables brent-tools only;
  `tooling_check.py` stays green; a fresh session's skill listing no longer shows the six.
