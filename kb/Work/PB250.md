# PB250

**Rows:** `FMT-15.94.2`

>>COBOL-WORDS is inert for every keyword the ANTLR lexer does not carry as a literal token — so TEST-NUMVAL-C's LOCALE/ANYCASE both reject legal source and silently eat a user-defined word.

ROW: FMT-15.94.2 (§15.94.2, the TEST-NUMVAL-C general format). The FORMAT is implemented correctly — that was re-verified from the printed page and by tracing all eight shapes, including the three untested ones — and the defect is one level down, in how the two keywords of that format interact with §7.3.10 >>COBOL-WORDS.

SPEC GROUND (each --checked on the row): ANYCASE and LOCALE are both §8.9 RESERVED words and neither is in the §8.10 context-sensitive table. §7.3.10.3 SR3 — 'The content of literal-1, literal-3, and literal-4 shall be a reserved word, a context-sensitive word, or an intrinsic function name' — makes both legal operands of the directive. §7.3.10.4 GR2: an EQUATEd literal-2 'may be used in any syntax requiring the use of the reserved word'. GR4: a SUBSTITUTEd literal-5 'shall be used in any syntax where the COBOL word that is the content of literal-4 is documented as required or optional', and literal-4 'shall no longer be a reserved word'. GR3: an UNDEFINEd literal-3 'shall no longer be reserved or restricted in any way' and its syntax 'shall not be available'. §15.94.2 IS such a syntax: it documents LOCALE and ANYCASE as its keywords.

MECHANISM, read end to end. `CobolWordsRewriter.Rewrite` installs a synonym only when `CobolKeywordTokens.TryTokenType` succeeds, and that map is built ONLY from the ANTLR lexer's literal token names. Its own summary asserts an INVARIANT — 'Every reserved word and context-sensitive word is a literal lexer token' — and the invariant is FALSE for LOCALE and ANYCASE: the generated vocabulary jumps 'LESS','LINE','LINES','LOCATION' with no LOCALE and no ANYCASE, and CobolExpressions.g4:359 says so in words. No retype happens, in either direction. `BindNumvalCFamily` then recognises the words by RAW TEXT and never consults `ctx.CobolWords`, although the same file consults it for the function name — ONE RULE, TWO PLACES.

BOTH DIRECTIONS ARE REACHABLE, because the directive is ACCEPTED: `VersionConformancePass.IsExistingWordCategory` (:138-139) passes SR3 through the `ReservedWords.Find(w)` fallback, and `tests/version-matrix/reserved-words.json` carries {"word":"LOCALE", r85:false, r2002:true, …} and the same row for ANYCASE. So the program compiles clean and the directive is SILENTLY INERT.
(1) REJECTS LEGAL SOURCE. `>>COBOL-WORDS EQUATE "LOCALE" WITH "LOCALITY"` then `FUNCTION TEST-NUMVAL-C(X LOCALITY FR)`: LOCALITY and FR bind as OPERANDS, so :1572's `operands.Count is < 1 or > 2` fires COBOLNET1504 — an ARITY error naming the very keyword the program legally renamed.
(2) SILENT WRONG ANSWER. `>>COBOL-WORDS UNDEFINE "ANYCASE"` (GR3) or `SUBSTITUTE "ANYCASE" BY "IGNORE-CASE"` (GR4) makes ANYCASE a user-defined word and withdraws the ANYCASE syntax; `FUNCTION TEST-NUMVAL-C(X ANYCASE)` — where ANYCASE is now the user's currency data item — is STILL eaten as the keyword at :1527, so the compiler turns on case-insensitive currency matching and injects the compilation-unit currency at :1619 instead of using the named item as argument-2, with NO diagnostic.

THE ASYMMETRY IS PROVABLE INSIDE ONE COMPILER: TRIM's LEADING/TRAILING (§15.96.2) ARE literal lexer tokens (`CobolExpressions.g4#fnArgPhraseWord`), so >>COBOL-WORDS IS honoured for that format's phrase words and is NOT honoured for this one. The population is therefore every phrase word carried as a bare IDENTIFIER — CobolExpressions.g4:359 lists ANYCASE, HEX, NAT, ANUM, BYTE, CURRENT, ACTIVATING, NESTED, STACK, TOP-LEVEL — and the sweep is the note's second half.

FIX SHAPE (rule 5 — the structural answer, not the smallest diff): the keyword-token map must be derived from the reserved-word table rather than from the lexer vocabulary, with a DRIFT TEST re-deriving the population so the written invariant becomes true and stays true; and the raw-text keyword comparisons in BindNumvalCFamily (and every sibling bare-word phrase site) must go through the same `ctx.CobolWords` resolution BindIntrinsicCore already uses for the function name. Goldens: a positive for an EQUATEd LOCALE/ANYCASE synonym and a negative for the UNDEFINEd spelling — nothing anywhere currently exercises >>COBOL-WORDS against any function's keyword.

ALSO RECORDED BY THIS ROW (documentation only): `IntrinsicBinder.cs:555-556` still reads 'The LOCALE phrase is the A.4.9 documented non-support (decision 3 …)', contradicting the live T6 LOCALE arm 1000 lines below and the accurate note at :506-510. And the editions for this row were corrected 85,2002,2014,2023 → 2002,2014,2023 from reserved-words.json's r85:false on BOTH keywords.

VERIFIED LIVE AT HEAD (read-only): CobolWordsRewriter.cs:35/:50 and CobolKeywordTokens.cs:42 unchanged; no ANYCASE/LOCALE lexer rule in any .g4.

## Mechanism

src/Cobol.Net.Frontend/Parsing/CobolWordsRewriter.cs:35 and :50 install a synonym only when `CobolKeywordTokens.TryTokenType(canonical, out int kt)` succeeds (DeReservedTokenTypes at :30-37 is guarded the same way); src/Cobol.Net.Frontend/Parsing/CobolKeywordTokens.cs:42's map is built ONLY from the ANTLR lexer's literal token names (:20-37) — and src/Cobol.Net.Frontend/Grammar/Core/CobolExpressions.g4:359 states outright that ANYCASE and friends 'are plain IDENTIFIERs'; IntrinsicBinder.BindNumvalCFamily then matches raw text (KeywordWordOf :2516; `== "ANYCASE"` :1527, `== "LOCALE"` :1547) and never consults `ctx.CobolWords`, while BindIntrinsicCore :446-448 in the SAME file consults it for the FUNCTION NAME
