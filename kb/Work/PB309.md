# PB309 — three lost spaces in the transcription, and a citation that passes anyway

## The defect

```
python scripts/spec/cite.py --check 14.9.8.4 "Otherwise, arithmetic-expression-1 is evaluated to produce an
algebraic value according to the specifications in 8.8.1, Arithmetic expressions."
   observed:  OK  §14.9.8.4 1) a)
   correct :  OK  §14.9.8.4 1) b)
```

The text is **sub-item b) of General rule 1**, as §14.9.8.4 rule 2's own words prove: *"The value obtained
according to rule 1 is then stored"*.

`specs/ISO_COBOL.md:23167` begins at **column 1** — `b) Otherwise, arithmetic-expression-1 …` — and so does line
23165, the NOTE explaining a)'s standard-binary exclusion. Sub-item a) at `:23162` is indented three spaces
(`   a) When native arithmetic, …`). Because b) and the NOTE carry no indentation, the ordinal tracker never
leaves sub-item a) and attributes both to `1) a)`.

## The repair

`specs/ISO_COBOL.md:23165` and `:23167` each gain the three-space indentation that `:23162` carries, so the NOTE
sits under a) and b) is a sibling of a).

⛔ **Why this is a note and not a repair already applied** (against `feedback_fix_transcription_errors_immediately`,
and stated so the exception is deliberate): `specs/` is a **private submodule**, and the landing that found this
pushes only the superproject. The repair belongs to a change set that can commit inside `specs-private`.

## Why it matters, and its sibling

This is precisely the CLAUDE.md rule 1 hazard: **`--check` PASSES on the real text while returning the WRONG
sub-ordinal**, so a design comment or golden citing "§14.9.8.4 GR1 b" is validated against an answer that names
a). Found while deriving `GR-8.8.1.2-7` — the COMPUTE row routes through this very sub-item.

The advised sibling sweep found a SECOND instance with a **different mechanism** — a `cite.py` ordinal-tracker
bug, not a transcription defect — filed as **PB308** mechanism 2. The drift test that pins `§14.9.8.4 1) b)`
belongs with PB308's fix and will stay red until this transcription repair lands, which is the correct coupling:
it is the same wrong answer from two causes.
