# PB1583

Found 2026-09-25 by the golden lane #2 batch-3 lander (Unit passed 29190/29190 re-run alone). Site
`tests/Cobol.Net.Tests.Unit/ConflictMarkerDriftTests.cs:232` (`File.OpenRead`). Fix: open with
`FileShare.ReadWrite | FileShare.Delete`; sweep the test assemblies for other `File.OpenRead` / `File.ReadAllText` sweeps
over the tracked tree that race the corpus runner (the same family as PB1564's shared temp folder).

## Landed (wave 60 A)

The note's mechanism was re-probed and REFUTED. The corpus runner reads `.err` with `File.ReadAllText`
(`FileAccess.Read`, `FileShare.Read`), and that is compatible with `File.OpenRead`. A share-mode conflict also
raises `IOException` (a sharing violation), not the `UnauthorizedAccessException` (access denied) that the golden lane
recorded. Measured on this build: 53 consecutive runs of `ConflictMarkerDriftTests` concurrent with the whole
`~CorpusRunner` leg (3173 cases, including every negative `.err`) all passed. The DEVLOG 1700 red stays unattributed.
Access denied on a read-open usually means a delete-pending file or an ACL, which is a concurrent writer outside the
test assemblies.

What landed:

- **Shared open.** The sweep now opens with `FileShare.ReadWrite | FileShare.Delete`, so a file another handle holds
  for writing or renaming is still read. The retired `File.OpenRead` is refused on Windows in exactly that case.
  `TheSweepReadsAFileAnotherHandleIsWriting` pins this: it was RED with `File.OpenRead` restored ("being used by
  another process") and is GREEN now.
- **Refusals are reported, not thrown.** A refused open is now reported per file with its exception and attributes,
  and the files after it are still swept (`AFileTheSweepCannotOpenIsReportedNotSkipped`). Both tree tests go RED with
  that list, so the next such red names its cause without a re-run.
- **Vanished files.** A file that vanishes between the listing and the open counts as absent, which is the existing
  `missing` rule.

Sibling sweep: every other tracked-tree reader in the test assemblies is a `File.ReadAllText`/`ReadAllLines` over
`src/`, `docs/`, grammars or manifests. The one tracked-tree writer (`VcrDriftTests.GeneratedStatusIndex_IsInSync`)
writes only under `COBOLNET_WRITE_VCR=1`, so none of them races a gate.
