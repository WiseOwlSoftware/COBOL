# PB2533 — reserved words bypass the closed-format error production

Filed 2026-10-07 by the train-1036 lander from the PB1045 implementer's report (wave 1032 group E,
`E:\COBOL-coord\scratch\reports\w1032e-PB1045-report.md`, "New defects").

## What happens

`SD SF GLOBAL.` and `SD SF2 EXTERNAL.` are both non-conforming: §13.4.6.2 prints `SD file-name-1 [ record-clause ] .`
and §13.18.27.3 SR1 d) admits the GLOBAL clause only in a file description entry, which an SD is not
(`cite.py --check 13.18.27.3 "A file description entry"` OK). The compiler refuses both, but with
`COBOL0307: unexpected 'GLOBAL'. A period may be missing…`, a generic parse error that names neither the format nor
the rule. PB829 closed the catch-all at the closed formats and gave each an `unrecognizedClause` error production
that reports by name, but that production is reached through `genericClause`, which begins only at an IDENTIFIER;
a reserved word (GLOBAL, EXTERNAL, BLOCK, …) never enters it.

## Repro

`E:\COBOL-coord\scratch\w1032e\p\sdg.cob` (an SD with `GLOBAL`, a second with `EXTERNAL`), at `--std 2023`.

## Code site

`src/Cobol.Net.Frontend/Grammar/Core/CobolExpressions.g4#genericClause` (`IDENTIFIER (IDENTIFIER|literal)*`) and
`src/Cobol.Net.Frontend/Grammar/CobolData.g4#sortMergeDescriptionClause` (its `unrecognizedClause` alternative). The
same shape holds at every closed format PB829 lists, so the fix is a parse-recovery design for reserved-word-led
clauses in those formats, not one SD alternative.

## Why it was not fixed in the train

It is a parse-recovery design across the PB829 family of closed formats, beyond the PB1045 slice. The source is
already refused, so no program compiles wrongly.

Owner 2026-10-17: addressed in the SORT and file I/O campaign (kb/Work PB3353).

## Landed (w1117a, 2026-10-18) — the parse layer names the format, from the same table

**Re-probe (worktree build, before).** The note's repro `sdg.cob` drew `COBOL0307: unexpected 'GLOBAL'` and
`COBOL0307: unexpected 'EXTERNAL'`. Probing all ten closed formats with a reserved word (scratch `w1117a\p\`): the
data description entry, FD, SD, SELECT, SOURCE-/OBJECT-COMPUTER drew `COBOL0307`/`COBOL0312`; I-O-CONTROL, SPECIAL-NAMES,
the configuration section and the identification division drew a bare `COBOL0001`, the SPECIAL-NAMES one reported in
`compilationUnit`, where nothing remembers the paragraph.

**Fix — the grammar is unchanged; the error strategy finds the production's position in the ATN.** `genericClause`
keeps its IDENTIFIER-led shape (a reserved-word-led run would compete with every named alternative — `SD SF RECORD.`
would read as a foreign word — and, in the paragraph lists, with the headers that follow). `CobolErrorStrategy`:
- **0g hint** (`ClosedFormatResidue`): simulates the ATN from the parser's state and real context to the offending
  token (re-taking the tokens a failed adaptive prediction looked past); a reachable call of `unrecognizedClause`
  names its list rule's format through the new `ClosedFormats.ByRuleIndex`; the INNERMOST open list wins. Excluded: a
  word that may follow the list's separator period (missing period) and a header-opening word (`HeaderWords`, read
  from the ATN: the first token of a rule followed within it by a period, SECTION or DIVISION).
- **Sync override**: at a state whose closure reaches the production (`ReachesErrorProduction`, a per-state flag), a
  reserved word outside the full-context LL(1) set is reported at once and the residue consumed, instead of the base
  strategy exiting a list that may end (`SD SF RECORD 80 EXTERNAL.`, `01 X PIC X BLOCK …`, the paragraph lists).
- Hints 7 (`COBOL0305`) and 19 (`COBOL0312`) are suppressed once a structural hint names the rule, as hint 14 is.
The code and sentence are the pass's own: `ClosedFormat` now carries its catalogue `Diagnostic` (the pass's three-way
code mapping deleted) and `Refusal(word, owner)`; `OwnerName` moved from the pass to `ClosedFormats`.

**After.** COBOLNET1941 / 1970 / 1971 naming the format at every format the parser reaches, one diagnostic each.
Not reached: a reserved word after a SOURCE-/OBJECT-COMPUTER computer-name (`SOURCE-COMPUTER. XYZ GLOBAL.`) — ANTLR's
error-recovery prediction takes the paragraph's exit alternative and reads XYZ as an unrecognized configuration
paragraph (reported as a lead; a grammar restructure of the two paragraphs' optional group).

**Goldens.** Negatives `pb2533-sd-reserved-word-clause`, `pb2533-data-entry-reserved-word-clause`,
`pb2533-special-names-reserved-word-clause`, `pb2533-identification-reserved-word-paragraph` (85 2002 2014 2023);
four existing expectations re-coded to the named refusal (`l1c08-entry-name-qualified`, `l1c21-property-no-get-and-set`,
`pb1252-linkage-entry-using-phrase`, `pb489-linage-phrases-out-of-order`). Unit `ClosedFormatReservedWordTests` (twelve
formats/positions + three controls); `ClosedFormatDriftTests.EveryRuleCallingTheErrorProduction_IsAClosedFormatRuleIndex`.

**For the next implementer (w1117a):**
- `src/Cobol.Net.Frontend/Parsing/CobolErrorStrategy.cs#ClosedFormatResidue` — the ATN simulation (`Closure`, `Config`,
  `Frame`); reuse it for any "which list stands here" question. `#Sync` / `#IsClosedFormatResidueAhead` — the hot-path
  guard order matters (flag, rule-local set, then the full-context set). Trap: the base Sync lets a token pass where
  the list may END; the error then surfaces rules later, so a report-time hint alone misses those cases.
- `src/Cobol.Net.Frontend/Cst/ClosedFormats.cs#ByRuleIndex` / `#OwnerName` / `ClosedFormat.Refusal` — the one table,
  key and wording for both refusal sites.
- `src/Cobol.Net.Compiler/Validation/ClosedFormatPass.cs#VisitUnrecognizedClause` — now just the row's descriptor and sentence.
