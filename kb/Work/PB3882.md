# PB3882 — exception-location-n-not-implemented-at-run-time: FUNCTION EXCEPTION-LOCATION-N compiles under -std=cobol2014 but the run aborts: 'attempt to use non-implemented function'

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S2) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\exception-location-n-not-implemented-at-run-time.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\exception-location-n-not-implemented-at-run-time\`.

## Summary

GnuCOBOL 3.2 under `-std=cobol2014` compiles a reference to the standard intrinsic function EXCEPTION-LOCATION-N with no
diagnostic, and the run ends at the call with `libcob: error: attempt to use non-implemented function`, exit code 1.
The default dialect refuses the same source at compile time (`FUNCTION 'EXCEPTION-LOCATION-N' is not implemented`): the
`-std=cobol2014` (and `-std=cobol2002`) word list re-activates a function that cobc's own table marks as not
implemented. Verdict: GNUCOBOL-DEFECT. Class: compiles but is not implemented at run time. Edition: 2014.

## Expected result (per ISO)

The program is legal and its run displays `[ ]` (one national space, because GnuCOBOL saves no location here; the
condition of §15.31.3 1) below) and then `END`. No rule permits the abort, whatever value the implementor returns.

- §15.31.1 (checked): "The EXCEPTION-LOCATION-N function returns a national character string, part of which is
  implementor-defined, that is the location of the statement associated with the last exception status."
- §15.31.3 1) (checked): when the LOCATION option of the TURN directive (or PERFORM) "is not specified and the
  implementor does not save the location information, the returned value is one national space character." No
  checking is enabled. GnuCOBOL does not save a location here: its alphanumeric twin FUNCTION EXCEPTION-LOCATION
  returns one space in the same program under the same flags (work\exception-location-n-not-implemented-at-run-time\elx.cob, output `[ ]`, exit 0).
- §4.2.2 (checked): the implementation shall provide the functionality of every required element; EXCEPTION-LOCATION-N
  is not listed in A.3 or A.4.

Edition: EXCEPTION-LOCATION-N is part of the 2014 edition: Annex E (§E.1, checked) lists every 2023
addition as added (§E.3.3 22), checked) and does not list it. (Derived; the repository holds no 2014 text. The 2023
wording of §15.31.3 1) names the PERFORM statement's LOCATION option as well as TURN; the case here, no checking at all,
does not depend on that. GnuCOBOL's `cobol2002.words` and `cobol2014.words` activate the function, which agrees.)

Citations inherited from the night records: The slice's §15.31.3 1) checks and is used. Its needs_judgment ('prose names a family of functions') is resolved: the EXCEPTION-*-N functions GnuCOBOL 3.2 stubs are exactly EXCEPTION-FILE-N and EXCEPTION-LOCATION-N (libcob/intrinsic.c stubs), each with its own record. Witness n5-fz03337 is recorded AGREE (both runs exit 0) and n5-fz02044 OUTPUT_DIFFERS with WiseOwl's own exit 1 from a later unchecked zero divisor; neither changes this family.

Edition as recorded by the adjudicator: 2014. `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Fix site (GnuCOBOL 3.2 source, read observationally)

In `gnucobol-3.2` (read observationally; identifiers only):

The function is declared in the compiler's intrinsic table as known but not implemented, and libcob carries only a
stub, but the `-std=cobol2014` word list re-activates it, so the compile-time refusal that cobc has for such functions
never fires:

- `cobc/reserved.c`, `function_list[]`, the `EXCEPTION-LOCATION-N` entry (line 3417): its `active` member is `CB_FEATURE_NOT_IMPLEMENTED`.
- `cobc/tree.c`, `cb_build_intrinsic` (line 7030): a function whose entry is `CB_FEATURE_NOT_IMPLEMENTED` is refused with
  `FUNCTION '%s' is not implemented`. This is the diagnostic the default dialect prints.
- `config/cobol2014.words`: line 535 `not-intrinsic-function: DIALECT-ALL`, then line 557 `intrinsic-function: EXCEPTION-LOCATION-N`
  (`config/cobol2002.words` has the same pair, line 534 and line 555).
- `cobc/reserved.c`, `change_intrinsic` / `set_intrinsic_mode` (line 4979): the DIALECT-ALL deactivation moves the
  entry from `CB_FEATURE_NOT_IMPLEMENTED` to `CB_FEATURE_DISABLED`; the later activation then moves it from
  `CB_FEATURE_DISABLED` to `CB_FEATURE_ACTIVE`. The function's own FIXME comment (line 4981) names this
  not-implemented, disabled, active sequence as unhandled. After it, `cobc -std=cobol2014 --list-intrinsics` reports
  the function as implemented ("Yes") and `cb_build_intrinsic` accepts it.
- `libcob/intrinsic.c`, `cob_intr_exception_location_n` (line 7121): calls `error_not_implemented` (line 3135), which sets
  `EC-IMP-FEATURE-MISSING` and calls `cob_fatal_error (COB_FERROR_FUNCTION)`; `libcob/common.c`, `cob_fatal_error`
  (line 9109) prints `attempt to use non-implemented function` and ends the run with exit code 1.

Two fixes are possible, and they are independent: (a) make `set_intrinsic_mode` keep `CB_FEATURE_NOT_IMPLEMENTED`
through a DISABLED-then-ACTIVE sequence, so that every dialect refuses the function at compile time, as the default
dialect already does; (b) implement `cob_intr_exception_location_n`. The alphanumeric twin `cob_intr_exception_location` (line 4191) is implemented and returns one space for the same program state (probe below); the national function is that value as national characters.

The same mechanism covers all six functions of this group (BOOLEAN-OF-INTEGER, CHAR-NATIONAL, EXCEPTION-FILE-N,
EXCEPTION-LOCATION-N, INTEGER-OF-BOOLEAN, STANDARD-COMPARE; records in this directory), so fix (a) is one change
for all of them and one upstream ticket can carry all six repros.

## Draft issue

**Title:** FUNCTION EXCEPTION-LOCATION-N compiles under -std=cobol2014 but the run aborts: 'attempt to use non-implemented function'

**Body:**

Environment: GnuCOBOL 3.2.0 (Ubuntu gnucobol3 3.2-4build1), Linux x86_64.

Steps:

    cobc -std=cobol2014 -fformat=free -x -o eln eln.cob
    ./eln

with eln.cob:

```
IDENTIFICATION DIVISION.
PROGRAM-ID. ELN.
PROCEDURE DIVISION.
    DISPLAY "[" FUNCTION EXCEPTION-LOCATION-N "]"
    DISPLAY "END"
    STOP RUN.
```

Observed: the compile succeeds with no diagnostic (also with -fsyntax-only -Wall). The run prints nothing from the
DISPLAY statement and ends with exit code 1:

    libcob: error: attempt to use non-implemented function

Without -std (default dialect), the same source is refused at compile time:
`eln.cob:4: error: FUNCTION 'EXCEPTION-LOCATION-N' is not implemented`. `cobc -std=cobol2014 --list-intrinsics` lists EXCEPTION-LOCATION-N as
implemented ("Yes"); plain `cobc --list-intrinsics` lists it as "No".

Expected: the program is valid COBOL 2014 (FUNCTION EXCEPTION-LOCATION-N, ISO/IEC 1989 15.31), a required function,
and no rule permits the run-time abort. The exact value is partly the implementor's: 15.31.3 rule 1 gives one national
space when the LOCATION option is not specified "and the implementor does not save the location information". No
checking with the LOCATION option is enabled, and GnuCOBOL's own FUNCTION EXCEPTION-LOCATION returns one space in the
same place (so it saves no location there); on that reading the run should display `[ ]` and then `END`.

Cause, as far as we can see: config/cobol2014.words (and cobol2002.words) first deactivates all functions with
`not-intrinsic-function: DIALECT-ALL` and then activates EXCEPTION-LOCATION-N; set_intrinsic_mode in cobc/reserved.c turns the
not-implemented entry into disabled and then into active (its FIXME notes this), so cb_build_intrinsic's
"is not implemented" check is bypassed and the call is generated against the libcob stub cob_intr_exception_location_n, which calls
error_not_implemented. Either keeping the not-implemented state through that sequence (compile-time refusal in every
dialect) or implementing the function would remove the run-time abort. The same applies to BOOLEAN-OF-INTEGER,
CHAR-NATIONAL, EXCEPTION-FILE-N, EXCEPTION-LOCATION-N, INTEGER-OF-BOOLEAN and STANDARD-COMPARE.
