# PB837 — OPEN — the USE hook reads the CLOSE's status, not the retrieval's

Source: the `PB344` finisher reports (both the dropped branch's and `PB344-finisher2`, item (a)); named again by
the train-29 and train-31 landers. Re-confirmed AT THE SITE on this tree — the code comment there now states it
as a defect rather than as a justification.

## Observed, at the site (`src/Cobol.Net.Compiler/CodeGen/Verbs/SortEmitter.cs#EmitInputFile`, main `b5ca78fb`)

```
144:  w.Line($"{RuntimeApi.FileClose(f)};   // implicit CLOSE (GR12c / GR7c)");
145:  seqIo.EmitStoreFileStatus(input);
148:  // ⛔ The status this hook reads is the implicit CLOSE's, not the retrieval's - GR12 c)'s CLOSE was
152:  return seqIo.EmitUseHook(input, atEndHandled: true, notNormalLabel: endLabel) | terminable;
```

`__IoCheck` returns on the '0' first character of the CLOSE's '00', so the declarative the failed retrieval owes
never runs.

## The rules, quoted

```
$ python scripts/spec/cite.py --check 14.9.40.4 "as if a READ statement"
  OK  §14.9.40.4 12)  (General rules)
      b) The logical records are obtained and released to the sort operation. Each record is obtained as if a READ statement with the NEXT phrase, the IGNORING LOCK phrase, and the AT END phrase had been executed.
$ python scripts/spec/cite.py --check 14.9.49.4 "unless an AT END or INVALID KEY phrase takes precedence"
  OK  §14.9.49.4 6)  (General rules)
```

The as-if READ is a READ, so its unsuccessful completion owes the file's USE declarative exactly as an explicit
READ does; only the AT END condition is pre-handled by GR12 b)'s own AT END phrase.

## Repro shape (not run — it needs a mid-transfer host failure)

`SORT S-FILE ... USING F` with a `USE AFTER STANDARD ERROR PROCEDURE ON INPUT` declarative, where F's physical
file is made unreadable after the OPEN and before the last record. Expected: the declarative runs with the
retrieval's status ('30'). Observed shape, by construction from the emitted code: the declarative is offered the
CLOSE's '00' and does not run. ⚠ The fixer owes the measured probe — this note is a code-read plus the emitter's
own comment, not a run.

## Code site and the shape of the fix

`SortEmitter.EmitInputFile`: hook the retrieval INSIDE the read loop (status stored per retrieval, `isRead:
true`), and give the implicit CLOSE its own hook after it, the way an explicit CLOSE gets one. MERGE's GR7 b)
twin is the same code path and the same fix.

## Sibling sweep the fixer owes

* `EmitGivingFile` (SORT GR15 / MERGE GR12) — the WRITE side has the same one-hook-after-CLOSE shape.
* Every `EmitUseHook(... atEndHandled: true)` call site: `atEndHandled` suppresses the AT END arm, and the
  question each site must answer is which STATUS the hook is reading.
* `~Nist` is the wave-local filter term that covers this class (five implementer reports named 25 filter terms
  and none of them selected `NistDifferentialTests`).
