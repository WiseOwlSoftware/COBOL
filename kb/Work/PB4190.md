# PB4190 — stall messages go to the operator whoever dispatched the group

## What happened

Between 19:51 and 20:01 PDT on 2026-10-30, the operator loop's progress check posted six `STALL w20261780<x> (...)`
messages to `to-operator`. Wave 20261780 is the Mythos lane's (account 1's quota, scratch `mythos/w-g7`). The operator
can neither act on another lane's agents nor speed them, so each message cost a wake-up and a close. The same happened
for the Mythos lane's PB4150 experiment (w20261775a, three messages that afternoon). The other lane learned of its own
stall only when the operator forwarded one by hand.

## The mechanism

`scripts/orchestrator/progress.py#post_stalls` sends every stalled item to the operator (`mailbox.send(..., to="operator")`).
It reads the dispatch ledger (`<coord>/inflight-groups.json`, written by `scripts/orchestrator/dispatch_ledger.py#record_dispatch`),
which both lanes write. A ledger entry carries `wave`, `letter`, `slug`, `notes`, `files`, `members` and `at`, but not
who dispatched it. So the reporter cannot tell its own loop's groups from the other lane's.

## Acceptance

`record_dispatch` records the dispatching lane (the mailbox's lane names, `operator` / `mythos`, from the session's lane
as `mailbox.py session` knows it; or the wave's scratch root). `post_stalls` sends each stall to that lane's inbox, or
leaves out groups the loop did not dispatch. A self-test arm covers a ledger with groups from both lanes.

## Landed

`record_dispatch` takes a `lane` and writes it on each entry (a group recorded again keeps its first lane, as it keeps
its `at`); `make_dispatch_specs.py#record` passes `mailbox.account_lane`, the account-based rule `mailbox.lane` now
shares (a loop unit has no inbox but does belong to its account's lane). `progress.py` carries each stall's lane
(`stall_lane`; an entry with none goes to the operator) and `post_stalls` sends to it. Arms: `progress.py --self-test`
(a ledger with groups of both lanes and one with none), `test_plan_wave.py` (the lane recorded and kept on a re-render),
`mailbox.py --self-test` (`account_lane` of a loop unit).
