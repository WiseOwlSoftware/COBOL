**Witness.** `E:/COBOL-coord/scratch/w20261863c/p/ALNSTR.cob`: a `01 T TYPEDEF STRONG` group and `01 X TYPE T ALIGNED.` draw COBOL2150 (ISO 13.16.3 SR14: "The TYPE clause shall not be specified in the same data description entry with any clauses except ...") and then a second COBOL1942 ("not an elementary or group data item") and a COBOL0881 on the same entry. Any illegal co-clause does the same.

**Mechanism.** After reporting COBOL2150, `DataBinder.cs#BindEntry` sets `typeRefName = null`, so the entry reaches the later passes as a PICTURE-less leaf. PB1312 measured the same class for `05 B REDEFINES A TYPE T.`.

**Fix shape.** The recovery keeps what the source wrote (the written TYPE name) or marks the entry so the later passes stay silent. Sweep every other pass that reads the cleared clause.

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.cs#BindEntry` (the SR12 and SR14 blocks that cleared the reference), `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.ClausePlacement.cs#ScreenReferenceComposition` (new), `src/WiseOwl.Cobol.Frontend/Cst/DataClauseKind.cs#DataClauseKinds.EntryRoleClauses` (the role clauses the recovery keeps).

## Landing (wave 20261865 C)

Re-probed on the wave's build: `01 X TYPE T ALIGNED.` drew COBOL2150, COBOL1942 and COBOL0881. The SAME AS twin (`01 X SAME AS Z ALIGNED.`, SR12) drew
COBOL1555, COBOL1942 and COBOL0881. `TYPE TP USAGE COMP`, `BLANK WHEN ZERO` and `JUSTIFIED` drew COBOL0881 (and COBOL2405) beside COBOL2150. The root is
the same in both arms: the recovery cleared the REFERENCE (`typeRefName = null`, `sameAsName = null`), so the entry reached the later screens as a
PICTURE-less leaf that kept the refused co-clause.

Fix at the root: the recovery inverts. `ScreenReferenceComposition` (DataBinder.ClausePlacement.cs) runs the SR12 and SR14 screens over the written clause set
BEFORE the decode loop and returns the refused clauses. The loop drops each one (the `placementRefused` discipline) and the TYPE / SAME AS name is kept, so
the entry expands from its type as a legal one does (ISO 13.18.57.4 GR1, 13.18.49.4 GR1). This also makes the receiver-wins copy's warrant (PB513) hold in
the recovery path: a refused PICTURE can no longer discard the type's description. An entry writing both TYPE and SAME AS draws both refusals and keeps SAME AS.

Witnesses: `ReferenceCompositionRecoveryTests` (exactly one diagnostic per co-clause in both arms, the mutual case, the permitted set) and the golden refusal
`conformance:cases/13.16-Data-description/pb4602-type-aligned-one-refusal`.

Review round 1 (R1-1): the recovery drops the DESCRIPTION clauses and keeps the ROLE clauses (`DataClauseKinds.EntryRoleClauses`: TYPEDEF, BASED, PROPERTY),
because a reference to the entry (`TYPE X`, `ALLOCATE X`, `SET ADDRESS OF X`) depends on them. Witnesses: `SameAsWithTypedef_ReferencesToTheTypeDrawNothingFurther`
and `SameAsWithBased_ReferencesToTheTemplateDrawNothingFurther` in `ReferenceCompositionRecoveryTests`.
