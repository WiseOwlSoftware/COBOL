### `parser-tree-3--architecture--f1#4` (finding, extract, votes upheld/upheld/upheld)

**Finding:** The reservation gate hands its token decisions to the binder by writing a mutable property onto the generated CompilationUnitContext, a hand-written partial of generated code that also keeps Parsing/ from ever matching its namespace

**Rule:** a stage hands its result as a value, not as state patched onto another layer type (DESIGN-architecture-review §5.1, §8.1 phase boundaries); §8.2 rule 1 folder equals namespace (census R0-0761, note PB2245); IntegerLiteralParts.cs:6-8 states the same principle for this folder: an extension, not a partial of the generated context, so the context stays the generated type the census records

**Scenario:** CompilationUnitTokenRetypes.cs adds public TokenRetypes { get; set; } to CobolParserCore.CompilationUnitContext. ReservationGateRewriter.ParseToFixpoint sets it as its last act (ReservationGateRewriter.cs:137) and returns only the tree; Frontend.cs:536 and FragmentParse.cs:133 immediately unpack it into a (result, tree.TokenRetypes) tuple for CobolTokenStream.UntilLexStable, and BinderDriver.cs:132 reads it back off the tree into BindSession.Retypes. So the real result of the fixpoint is a pair, carried as a side channel on a parse node: any tree not produced by ParseToFixpoint (a test parse, the fragment parser, a future second entry) answers TokenRetypes.None silently, and a fragment re-parse of that tree then reads freed words as keywords. The partial is also why PB2245 cannot be done by renaming: a partial of CobolParserCore must stay in WiseOwl.Cobol.Frontend.Generated, so Parsing/ keeps one file the folder rule fails on whatever PB2333 does with CobolParserCoreBase.

**Target:** ParseToFixpoint returns a value pairing the tree with its TokenRetypes (a ParsedUnit record, or the tuple UntilLexStable already wants); the frontend result that reaches BinderDriver carries the retypes beside the tree, and FragmentParse.ParseUnit and Frontend read the pair directly. Delete CompilationUnitTokenRetypes.cs, so after PB2333/PB2245 move CobolParserCoreBase, no hand-written file of Parsing/ declares WiseOwl.Cobol.Frontend.Generated. Every caller changes in the same change (CLAUDE.md rule 4).

**Sites:** src/WiseOwl.Cobol.Frontend/Parsing/CompilationUnitTokenRetypes.cs:7-16 (CobolParserCore.CompilationUnitContext.TokenRetypes); src/WiseOwl.Cobol.Frontend/Parsing/ReservationGateRewriter.cs:137 (ReservationGateRewriter.ParseToFixpoint); src/WiseOwl.Cobol.Frontend/Parsing/FragmentParse.cs:113-134 (FragmentParse.ParseUnit); src/WiseOwl.Cobol.Frontend/Pipeline/Frontend.cs:532-537; src/WiseOwl.Cobol.Compiler/Binding/BinderDriver.cs:132

### `parser-tree-3--architecture--f2#2` (finding, delete, votes upheld/upheld/upheld)

**Finding:** CompilationUnitTokenRetypes.cs, the one hand partial of the generated parser, cannot meet PB2245s folder-equals-namespace target by either route it offers; the fix is to take the mutable TokenRetypes property off the parse tree

**Rule:** folder equals namespace (DESIGN-architecture-review §8.2 rule 1, §5.3; census R0-0761, note PB2245); a generated type stays generated (§8.1: the census counts CobolParserCore as authored only because of this partial, which forced the walk to fold nested-type documents into their container, kb/Work PB2417; IntegerLiteralParts.cs states the same preference: an extension, not a partial of a generated context)

**Scenario:** PB2245 says move the files or rename the namespace. For CompilationUnitTokenRetypes.cs neither works: as a partial of WiseOwl.Cobol.Frontend.Generated.CobolParserCore.CompilationUnitContext it must declare that namespace, and the folder that matches it, Generated/, is a build output never committed (§8.4, AntlrGenerationDriftTests), which the census also reads as generated. So the R0-0761 row survives the CobolParserCoreBase rename §8.3 plans, and the census keeps counting the ANTLR parser as an authored type. Meanwhile the partial is a public settable property on a parse node: ReservationGateRewriter.ParseToFixpoint writes it after the fixpoint (ReservationGateRewriter.cs:137) and three readers fetch it back off the tree (Frontend.cs:536, FragmentParse.cs:133, BinderDriver.cs:132), so a phase output rides the tree into the binder, and any code holding the tree may overwrite the retypes every later fragment parse reads.

**Target:** Delete CompilationUnitTokenRetypes.cs. ReservationGateRewriter.ParseToFixpoint returns (tree, retypes); Frontend.LexAndParse and LexAndParseOnce put TokenRetypes in the tuple they already return (beside SourceDebuggingLines and CommentLines) and the front-end result carries it; BinderDriver.Bind takes it as data for BindSession.Retypes; FragmentParse.ParseUnit returns the pair it already builds. CobolParserCore becomes a wholly generated type, PB2245 then covers only CobolParserCoreBase (whose namespace §8.3 R0-0038 already moves to its folder), and PB2245 records that this file left by deletion, not by a move.

**Sites:** src/WiseOwl.Cobol.Frontend/Parsing/CompilationUnitTokenRetypes.cs:5-17 (CobolParserCore.CompilationUnitContext.TokenRetypes); src/WiseOwl.Cobol.Frontend/Parsing/ReservationGateRewriter.cs:137 (ReservationGateRewriter.ParseToFixpoint); src/WiseOwl.Cobol.Frontend/Pipeline/Frontend.cs:536 (Frontend.LexAndParse); src/WiseOwl.Cobol.Frontend/Parsing/FragmentParse.cs:133 (FragmentParse.ParseUnit); src/WiseOwl.Cobol.Compiler/Binding/BinderDriver.cs:132 (BinderDriver.Bind)
