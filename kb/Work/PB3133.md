# PB3133 — the OBJECT-COMPUTER paragraph's 1985 figure is not screened

Source: wave 1071 (unit `w1071h`, PB2532 round 3). PB2532 is held by its branch and is NOT edited (same root as PB2532: a clause list whose 1985 figure differs from 2023's). PB3 (landed) and PB656 (open; `SEGMENT-LIMIT` flags in `reserved-words.json`) were checked first: neither owns clause cardinality.

**Repro (R2, run on the notes worktree's built CLI, `cobol <file> --std 85`):** `E:\COBOL-coord\scratch\w1071h\p2532d.cob` (`OBJECT-COMPUTER. XYZ MEMORY SIZE 10 WORDS MEMORY SIZE 20 WORDS.`) and `p2532e.cob` (`SEGMENT-LIMIT IS 10` before `MEMORY SIZE 20 WORDS`). BOTH exit 0 with no diagnostic: confirmed. Under the 85 figure, `[MEMORY SIZE ...] [PROGRAM COLLATING SEQUENCE ...] [SEGMENT-LIMIT ...]`, each at most once, in that order (derived, not re-quoted from the 2023 text: `python scripts/spec/cite.py --check 12.3.6.2 "OBJECT-COMPUTER"` -> OK for the 2023 general format only).

**Sites.** `tests/WiseOwl.Cobol.Tests.Unit/ClauseCardinalityDriftTests.cs:33-39` `ReviewedExemptions` lists `ObjectComputerClauseContext` as a closed format that repeats elements (the table that would carry the 85 row); `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.Switches.cs:825-850` is COBOL1652 (`ObjectComputerDuplicateClause`), counting PROGRAM COLLATING SEQUENCE and CHARACTER CLASSIFICATION as choice indicators per §5.2.6.4 (so a repeated PCS is already caught at 85, 2423 aside); `src/WiseOwl.Cobol.Frontend/Cst/ClosedFormats.cs:90` is the closed-format table row for it.

**Why the PB2532 implementer left it.** A table row would report a repeated PROGRAM COLLATING SEQUENCE twice at 85 (the new table code and COBOL1652). **The design decision is which one reader owns the §5.2.6.4 counts, the clause table or the binder; choose ONE (CLAUDE.md rule 5), delete the other, and update the design doc in the same change.** Judgment: the 85 order rule needs the 1985 spec; an implementer derives it per CLAUDE.md rule 1, not from this note's summary.

## Landed (wave 1072, group D)

**Re-probe (own build, `--std 85`):** both repros reproduced, exit 0, no diagnostic (`p2532d.cob` repeated MEMORY SIZE; `p2532e.cob` SEGMENT-LIMIT before MEMORY SIZE).

**The design decision the note asked for (CLAUDE.md rule 5): the TABLE owns the counts, the binder does not.** The OBJECT-COMPUTER list became a `ClauseCardinalities` row (`ObjectComputerClauseContext`), built on PB2532's `ClauseList.Earlier` / `At(year)` chain (merged in from that branch before it reached main). From 2002 the §12.3.6.2 figure (rendered from the printed page, folio 285) encloses CHARACTER CLASSIFICATION and PROGRAM COLLATING SEQUENCE in choice indicators within brackets: §5.2.6.4, each alternative at most once, any order (`Sequence` null). Below 2002 the COBOL-85 figure ranks MEMORY SIZE, PROGRAM COLLATING SEQUENCE and SEGMENT-LIMIT once each in that sequence. DERIVED, NOT QUOTED: the repository holds no 1985 text; IBM Enterprise COBOL's language reference prints the same figure, and GnuCOBOL's parser takes the clauses in any order and number (so it is no arm of the precedence). `DataBinder.SwitchBindSpecialNames`'s own counts and `COBOL1652` (`ObjectComputerDuplicateClause`) are DELETED (the code stays retired); from 2002 a repeat is COBOL2104 (the one choice-indicator reader, `ChoiceIndicators.AtMostOnce`, through `ClauseList.ChoiceIndicators`; ISO review R1-1 of w1073b), at the COBOL-85 figure COBOL2423 (separate brackets), a misplaced clause COBOL2987. `ClauseCardinalityDriftTests.ReviewedExemptions` lost `ObjectComputerClauseContext` and gained `TheObjectComputerRow_ScreensTheCobol85FigureBelow2002`.

**Sibling found and fixed (I9):** `UnrepeatedElements.AtMostOnce`'s message said every list "encloses it in its own bracket with no ellipsis", false for a choice-indicator list; the choice-indicator list is no longer reported by it at all (COBOL2423 keeps the bracket-without-ellipsis rule only; the 5.2.6.4 half is COBOL2104).

Goldens: `85/pb3133_object_computer_clauses_in_sequence_85`, `negative/pb3133-object-computer-clause-repeated-85`, `negative/pb3133-object-computer-clause-out-of-order-85`; the two COBOL1652 negatives (`pb78-object-computer-duplicate-clause`, `pb64t5-classification-twice`) now expect COBOL2104.
