# PB3707 — the gate run directory has no state between "made" and "holds the lock"

**Sites:** `scripts/run_gate_legs.py` (`launch_and_follow`, `Gate.run`, `live_gate`, `gate_running`, `lock_running`), `scripts/orchestrator/enqueue.py` (`tested_locally`, which reads a no-verdict run through `live_gate`).

## What happens

`launch_and_follow` makes the run directory and spawns the child. The child takes the gate lock and writes `gate.pid` only inside
`Gate.run`, after interpreter start and imports. Two readers judge the interval between the two moments with different rules, and
both are wrong in one case:

1. **A landing in the window (UNTESTED instead of BUSY).** `live_gate` reads a free lock as "no gate runs". `enqueue.tested_locally`
   in the sub-second window sees the new run, no `verdict.json`, a free lock, and reports "no verdict file (a gate that died)":
   `land` ends exit 14 UNTESTED and the enqueue unit dispatches a finisher to gate a tip whose gate is about to run (its own gate then
   reads BUSY). Run-level repro: start `build-local.ps1` in a worktree and run `enqueue.py land` for it in the same second.
2. **A gate that dies before the lock (running forever).** `gate_running` returns True for a run with no `gate.pid`, since it cannot tell
   it from a gate not started. A child that dies before `Gate.run` (an import error, a killed process) leaves a run with neither
   `gate.pid` nor `verdict.json`, and `watch`/`--await` wait on it with no end (`AWAIT_PENDING_EXIT` only after the caller's limit).

## Fix direction

Give the run directory an explicit starting state: the launcher records the spawn (its child's pid and the time) in the run directory,
and the child's first act under the lock replaces it with `gate.pid`. A reader then decides by three facts: the lock is held (running),
the spawn record is younger than a bounded start-up time and the child process named by it is alive (starting), else the gate died.
Do not decide by a pid alone (PB3662 R1-1: Windows reuses pids). `live_gate`'s docstring ("held exactly while a gate runs") must state the
window until this lands. Self-test arms for both cases: a run directory with a live spawn record and a free lock reads starting; one with a
dead child reads died, within the bounded time.
