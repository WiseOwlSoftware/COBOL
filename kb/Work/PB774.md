# PB774 — OPEN — half a rule, printed as the whole rule

Filed 2026-09-06 by the registrar. **⚠ Derived by READING the path, not by running the compiler** — no built
`cobol.exe` exists in this worktree and building was out of scope. The three links in the chain are each a
single line and are quoted below; the implementer owes the probe.

## The message, and the rule it states

`src/Cobol.Net.Editions/ReservedWords.cs:119-121` — the ONE sentence, deliberately centralized by [[PB693]] so
its two stages cannot drift (`:112-118` says so explicitly, `feedback_one_rule_one_place`):

```csharp
public static string UserWordViolationMessage(string upperWord, int edition)
    => $"'{upperWord}' is a reserved word in COBOL-{edition} and cannot be used as a "
       + "user-defined word (ISO §8.9)";
```

Its two callers, which is why the fix is this string and not a call site:

- `src/Cobol.Net.Compiler/Validation/VersionConformancePass.cs:2224` — the bound-tree §8.9 funnel.
- `src/Cobol.Net.Frontend/Parsing/CobolParserCoreBase.cs:326` — the parser's error listener, for the occurrences
  the reservation gate makes unparseable.

Mechanically checked (`python scripts/spec/cite.py --check`):

- `8.3.2.1 "Reserved words shall not be used as user-defined words or system-names"` → **OK §8.3.2.1 1)**.
  The rule has TWO limbs. The message prints one.
- `8.3.2.3.1 "The types of system-names are"` → **OK §8.3.2.3.1**, which then lists eleven:
  call-convention-name, code-name, **computer-name**, device-name, entry-convention-name, external-locale-name,
  feature-name, library-name, physical-structure-name, **switch-name**, text-name.

A system-name is not a user-defined word — §8.3.2.3.1 opens *"A system-name is used to communicate with the
operating environment"*, a different one of §8.3.2's three word kinds. So for a system-name slot the sentence
the compiler prints is a **false statement about what the source wrote**, while the rule it is enforcing is
correct.

## The reachability — measured against the grammar and the funnel's own filter, not assumed

`feedback_reachability_is_measured_not_deduced`: the question is whether a system-name slot can actually reach
`FlagReservedUserWord`. Two of the eleven kinds are spelled with the user-word rule itself:

- **computer-name.** `src/Cobol.Net.Frontend/Grammar/CobolParserCore.g4:486-488` — `computerName : cobolWord ;`,
  consumed at `:421` by the SOURCE-COMPUTER paragraph
  (`SOURCE_COMPUTER DOT ((computerName computerAttributes?)? DOT)?`).
- **switch-name.** `src/Cobol.Net.Frontend/Grammar/Core/CobolSpecialNames.g4:83-85` —
  `implementorSwitchEntry : cobolWord (IS? cobolWord)? switchOnClause? switchOffClause? ;`. The first
  `cobolWord` is §12.3.7.2's switch-name-1, a system-name; the second is mnemonic-name-1, a user-defined word.
  One rule, two word KINDS, one message.

And the funnel does not filter them out. `VersionConformancePass.VisitCobolWord`, `:2072`:

```csharp
if (!CheckedTokenTypes.Contains(ctx.Start.Type) && !IsProvableUserWordPosition(ctx))
    return base.VisitChildren(ctx);
```

The guard is an **OR**, so a word whose token type is in `CheckedTokenTypes` is checked at EVERY position,
`IsProvableUserWordPosition` notwithstanding — and `CobolLexer.IDENTIFIER` is the set's first member (`:1986-1988`).
A §8.9-reserved word that has NO dedicated lexer token arrives as IDENTIFIER (the mechanism [[PB764]] documents
and [[PB704]] measured for ORDER), so it passes this filter in a computer-name or switch-name slot and reaches
`FlagReservedUserWord(word)` at `:2202`, which renders the sentence above.

⚠ **What this does NOT claim.** `IsProvableUserWordPosition` (`:432-469`) admits only four slots — the data
description / linkage entry-name, a paragraph/section DEFINITION name, the SELECT file-name, and the
program-name — and none of them is a system-name slot. So a reserved word with a DEDICATED lexer token in a
system-name slot takes the other branch and is not funnelled at all; whether it then draws a parse error, a
different diagnostic, or nothing, is not established here and is the second half of the implementer's probe.

## What a user sees today, stated as precisely as reading supports

For the reachable case — a §8.9-reserved word with no lexer token, written as a computer-name or a switch-name,
at an edition that reserves it — the compile ends with the [[PB704]]-shaped line:

```
error COBOLNET0901: '<WORD>' is a reserved word in COBOL-2023 and cannot be used as a user-defined word (ISO 8.9)
```

The program is wrong and the compiler is right to refuse it. The sentence names the wrong limb of the rule and
the wrong clause: **§8.9 is the reserved-word LIST**; the obligation is §8.3.2.1 1). A reader who follows the
citation finds a list of words and no prohibition, and a reader who wrote a computer-name is told about
user-defined words.

## Fix shape

One string and one signature, in `ReservedWords.cs`. The message already takes the word and the edition; it needs
the WORD KIND of the slot, so the two stages can say `user-defined word` or `system-name` — and the funnel
already knows which, because `ctx.Parent` distinguishes `ComputerNameContext` / `ImplementorSwitchEntryContext`
from the rest.

⛔ **Do not add a second message.** [[PB693]] centralized this sentence precisely so the parser arm and the
bound-tree arm cannot diverge; a system-name variant belongs in the SAME method as a second rendering, reached
by a parameter. `feedback_two_arm_dispatch` — ask which arm you fixed: `CobolParserCoreBase.cs:326` is the arm a
sweep for `FlagReservedUserWord` misses.

Two decisions the implementer owes, both cheap:

1. **The citation.** Whether to keep `ISO §8.9` (where the word is listed) or move to `ISO §8.3.2.1 1)` (where
   the prohibition is stated), or print both. This note establishes only that §8.3.2.1 1) is the sentence that
   makes the source non-conforming; §8.9's role in the message may have been a deliberate choice at [[PB693]]
   and should be checked there before it is changed.
2. **Whether the other nine system-name kinds are reachable.** device-name (`ASSIGN TO device-name-1`),
   feature-name (`RECORD DELIMITER IS feature-name-1`), text-name and library-name (COPY) are the next to
   check; each is either a `cobolWord` slot — same defect, same fix, free — or a literal/other slot, in which
   case say so. `feedback_scan_all_similar`.

## Why `process_only`

The compiler's ACCEPT/REJECT verdict is correct in every case this note describes: the source violates
§8.3.2.1 1) and is refused. What is wrong is the sentence a user reads, so nothing here changes what a
conforming program does — the same disposition [[PB765]] carries for its edition-divergent wording, and the same
reason §4.2.16 conformance is silent about it. It is filed because a diagnostic that misdescribes the source
sends the programmer to fix something that is not wrong, which is the harm [[PB496]] and [[PB283]] record for
this exact diagnostic under different mechanisms.
