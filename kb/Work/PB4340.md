# PB4340 — `check-batch --help` shows the root command's `<source>`

**Found 2026-10-31** by the PB1610 review finisher (wave 20261791 group C, report
`E:\COBOL-coord\scratch\reports\w20261791c-PB1610-report.md`, "New defects" 2). The help text sends a reader to a
command line that does not exist: `cobol check-batch --help` lists `<source>` and prints
`cobol <source> check-batch <manifest>`.

**Sites:** `src/WiseOwl.Cobol.Cli/Program.cs:210` (`Program.BuildParser`, the `check-batch` command).

The `<source>` argument belongs to the root command; the subcommand inherits it into its usage line. The fix is in how
`BuildParser` declares the root argument against the subcommand (a root-level argument the subcommand does not take), not
in the help text. The report gives the symptom only; the implementer confirms the mechanism against the System.CommandLine
version the CLI uses. Related: PB2619 (hand-written CLI help for the edition list), PB4126 (the same builder).
