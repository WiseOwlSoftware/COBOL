# PB4420 - a user-defined word folds only an extended letter's own case pair

**Owner decision (2026-11-01, Mythos session).** Asked whether a user-defined word folds U+0130 to the basic `i` and
U+212A to the basic `k` as Annex C.2's table literally lists, the owner established first that the whole mechanism is
COBOL's case-insensitivity ("All of this seems in the context of cobol considered to be a case insensitive language,
correct?"), and then, shown GnuCOBOL's behaviour, decided: **"Follow gnucobol"**.

**The text.** §8.1.3.2 4) b) (checked: `cite.py --check 8.1.3.2`): "An uppercase extended letter is treated as though it
were folded to its corresponding lowercase extended letter, if any, in accordance with the case mapping described in
Annex C". Annex C.2 (checked) lists 1,281 (uppercase, lowercase) pairs generated from Unicode 13's
Changes_When_Lowercased property (its NOTE). Exactly two pairs fold an EXTENDED letter to a BASIC one (measured over the
transcribed table, both rows confirmed on the printed PDF, file pages 1028 and 1032): `(0130,0069)` and `(212A,006B)`.
Rule 4 b) speaks of the "corresponding lowercase **extended** letter"; 0069 and 006B are basic letters, so 4 b) does not
clearly reach these two pairs, and that is the latitude the owner's precedence rule (CLAUDE.md rule 1: ISO, then
GnuCOBOL) gives to GnuCOBOL. (0130 is a genuine Turkish case pair, İ/i beside I/ı; one fold with no locale cannot
serve Turkish and English at once, and the default Unicode fold gives `i` two capitals.) Annex E.2 item 14 is
adjacent but not the same ground: 2023 DELETED `(0131,0069)` and `(03C2,03C3)` because those code points are lowercase
letters (an error in the previous standard), not as a policy on folds that land on a basic letter.

**GnuCOBOL 3.2.0 (the pinned toolchain, WSL, `-free`, default dialect and `-std=cobol2014` alike).**
`01 CUSTOMER-İD` referenced as `CUSTOMER-ID`: `error: 'CUSTOMER-ID' is not defined`. Both declared: two distinct items,
DISPLAY prints `DOTI` then `BASI`. `01 WORK-<U+212A>` referenced as `WORK-K`: not defined. `DİSPLAY "KWD".`:
`unknown statement 'DİSPLAY'`. GnuCOBOL compares extended letters byte for byte (it does not fold even `ÄPFEL`/`äpfel`,
where 4 b) DOES control and WiseOwl keeps the fold); only A-Z fold.

**WiseOwl at main (Debug build of 19:32 PST, main at b44d90fd7).** The first shape compiles and prints `DOTI` (the two names are
one: a wrong answer, silent); the second is refused with COBOL1639 on both references (legal source rejected);
`WORK-<U+212A>` is found as `WORK-K`. Keywords are already outside the fold (owner 2026-10-31, PB4312, PB4240).

**The change.** The fold that compares user-defined words (`src/WiseOwl.Cobol.Runtime/CobolNames.cs`, its table
`CobolNames.Table.cs` generated by `scripts/spec/gen_annex_bc.py` from Annex C.2) applies a C.2 pair only when both
sides are extended letters or both basic: the generator derives the exclusion from the table (an uppercase that is
not a basic letter whose lowercase is), never a hand list, and `AnnexBCDriftTests` / `CobolNameFoldDriftTests` pin
that the excluded set is exactly the derived one (today the two pairs above). `CobolNames`'s doc comment (which states
the opposite determination today), DESIGN-frontend-grammar §3.13, and a `docs/CONFORMANCE.md` determination (the
4 b) reading, GnuCOBOL as the precedence) say it. Goldens: CUSTOMER-İD and CUSTOMER-ID as two items (runs, two
values); a reference by the other spelling refused as undefined; the same with the Kelvin sign; the existing
`pb1965_annex_c_word_keys`, `pb1965-kelvin-spelled-reserved-word`, `pb2845_flag_option_word_annex_c_fold` and the unit
tests that name U+0130/U+212A re-derived against this decision (sweep: every consumer of `CobolNames.Same` / its key).
The UPPER-CASE / LOWER-CASE intrinsics are a separate, implementor-defined mapping (§15.97.4 4)) and are not changed.

**Sequencing.** Same files as the PB4240 review finisher (wave 20261815 group B, branch of worktree-wf_2201113e-54d-26:
the Kelvin golden, the fold's comparisons): this lands AFTER it, merging that branch (kb/Work PB4396: one step per file).

## Landed (wave 20261817, group A)

**Re-probe (Debug build, main of 19:32 PST, before the change).** `CUSTOMER-<U+0130>D` and `CUSTOMER-ID` declared together:
COBOL1639 on both references (ambiguous: one name); `<U+0130>` alone, referenced as `CUSTOMER-ID`: prints the value (one name);
`WORK-<U+212A>` read as `WORK-K`: prints. After: two items (`DOTI`, `BASI`), the other spelling COBOL1639, the Kelvin sign the same.

**The change.** `scripts/spec/gen_annex_bc.py` derives `NotApplied` from the three pair lists (a pair whose two letters are not
both basic or both extended: `crosses_classes`), emits it into `CobolNames.Table.cs` and leaves the pairs out of `C2Mappings`,
`E2Item14Deleted`, `E33Item6Added`. The derived set is `(0130,0069)`, `(212A,006B)` and, in the 2002/2014 table,
`(0131,0069)` (the note named the first two; the third is the same pair class in the E.2 item 14 list, so the dotless i of 2002/2014
no longer folds to `i` either, and `EditionSpelling` respells final sigma alone). `AnnexBCDriftTests` re-reads the lists and holds
the applied lists = the standard less the crossing pairs, `NotApplied` = those pairs, no character at or above U+0080 folds to
ASCII at 2002/2014/2023, and every keyword population (reserved, context-sensitive, intrinsic, implementor names, directive
words) is basic characters only. Dead PB4240-era code removed: `FunctionWord.OfUserWord` (the declaration funnel asks
`OfWrittenWord`), the fold-then-keyword guards in `VersionConformancePass.ValidateCobolWords` / `IsReservedContextOrIntrinsic`,
and `ReservedWordSet.Compose`'s re-keying of the de-reserved words by the fold. `CobolKeywords` stays: it is the keyword
question's home (no table, no allocation, the spelling as written for the directive words).

**Probes of the four named sites** (U+0130 spellings, before / after): `DataBinder.Constants.cs` `F<U+0130>LLER CONSTANT AS 5`
