# PB3708 — the lane backoff test races a 30 s timer

**Sites:** `scripts/orchestrator/test_orchestrate_lane.ps1` (case 1, `Run-Lane 'lanebackoff' @('-BackoffBaseSeconds', '30', '-LandLaneSeconds', '1')` and its assertion `backoff: only the one unit ran`).

## What happens

Case 1 asserts exactly one unit ran and the STOP exit, which holds only if the fake python reaches its 8th lane tick (the tick that creates
STOP) inside the fixed 30 s backoff. The verdict therefore depends on how fast `pwsh` starts. Measured on the review host: the backoff
took 6 of the 8 ticks in 6 s (one per second, each a `pwsh` start of `fake-python.ps1` at about 0.4 s), and the part ran 32.4 s at 73 %
load against 17 s idle. On a starved host or CI runner where a tick (the `pwsh` start plus the 1 s `Wait-Until` wake) takes over about
5 s, the 30 s backoff ends before tick 8, a second failing unit runs, and the check fails (got 2, want 1): a red that passes alone. The
owner's no-wall-clock-tests rule (a fixed time limit decides a verdict) forbids this shape.

## Fix

Make the backoff long enough that only STOP can end it (the review suggests `-BackoffBaseSeconds 600`: the test still ends at the 8th
tick, in the same seconds), so the timer never decides the assertion. Sweep the other cases of the file and the sibling
`test_orchestrate_*.ps1` suites for a fixed backoff, hold or timeout the assertion depends on.

## Landing

`scripts/orchestrator/test_orchestrate_lane.ps1` (`Run-Lane`, case 1): `Run-Lane` fixes no backoff itself, so a case sets `-BackoffBaseSeconds`; give a case that waits on STOP a backoff only STOP can end (600 s; the supervisor caps at 1800 s) and a `-MaxUnits` bound so a regression ends instead of looping. The trap: the 8th-tick STOP is a `pwsh` start per second, so any fixed timer near the tick budget races on a loaded host.

## Landed

`test_orchestrate_lane.ps1` case 1 now runs `-BackoffBaseSeconds 600 -LandLaneSeconds 1 -MaxUnits 2`: the backoff is far longer than the
fake python's 8th tick needs on any host, so only STOP ends it and the timer never decides the verdict (the supervisor caps a backoff at
1800 s, so 600 is honoured). `-MaxUnits 2` bounds a regression: without the lane ticking in a backoff the run ends after the second unit
(runs = 2, the check fails) instead of looping on. Re-probe: the test passed 6/6 before and after on an idle host (26 s, 19 s); the race
needs a tick over about 5 s and is a defect of the assertion's shape, not reproducible idle. Sibling sweep: case 2 (`-BackoffBaseSeconds 2`,
two units, no lane) needs the timer to elapse, which a slow host only delays; the other `test_orchestrate_*.ps1` suites set
`-BackoffBaseSeconds 0` and carry no backoff or hold whose expiry decides an assertion.
