## PB3229 branch review (wave 20262139 group A, round 1) R1-1: a strongly-typed group result was admitted as alphanumeric

**Finding.** The earlier R1-1 fix made `MoveBinder.ScreenFromFunctionClass` ask `IntrinsicResultType.OperandCategory`,
whose field arm answers Alphanumeric for ANY picture-less group, a strongly-typed one included (that reader serves
§2023:15.3 AR2, the function ARGUMENT reading). A function `RETURNING` a strongly-typed group was then admitted by
`WRITE R FROM FUNCTION F`; main had refused it (COBOL1914). Repro: the WRITE golden below, run with `--std 2023`.

**Spec.** §2023:8.5.2.1: "Both the class and the category of a strongly-typed group item are the type-name specified in
the TYPE clause". §2023:8.4.3.2.4 GR1 gives the function's temporary item its RETURNING item's class and category, so the
function is no alphanumeric, boolean or national function: §2023:14.9.51.3 SR4 (WRITE), §2023:14.9.32.3 SR2 (RELEASE)
and §2023:14.9.35.3 SR9 (REWRITE) refuse it.

**Fix.** The screen asks `StrongTypeModel.StrongGroupType` of the result item first and refuses with the type-name as the
category ("this function's result is of category T"); every other result keeps the operand-category reader. Re-probe:
EXIT 65, COBOL1914 at 2002 and 2023 (was EXIT 0 `[ABCDE12345]`). Refusal goldens
`14.9.51-WRITE/pb3229-write-from-strong-group-function` (2002, 2014, 2023) and
`14.9.35-REWRITE/pb3229-rewrite-from-strong-group-function` (2014, 2023; §2002:14.8.33.2 SR9 restricts only an intrinsic
function). Sweep: the other `OperandCategory` admissions (SetBinder.AddressNameOfIdentifier screens a field operand
through its place; IntrinsicBinder.IsStringOperand is an argument position under §2023:15.3 AR2) are not result screens.
