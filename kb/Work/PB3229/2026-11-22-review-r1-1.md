## PB3229 branch review R1-1: a group-returning function crashed the FROM-phrase screen (wave 20262139 group A)

**Finding.** `MoveBinder.ScreenFromFunctionClass` read the function result's category from `MoveTable16.SenderPosition`,
which answers `PicCategory.Group` for an alphanumeric group (the §2023:14.9.25.4 GR4 group move: a Table 16 position, not
a category). After PB3229 routed the message through `ItemCategory.CategoryName(PicCategory)`, which throws for Group,
`WRITE R FROM FUNCTION GRPF` over a function `RETURNING` a group crashed with `InvalidOperationException`; main printed
COBOL1914 "this function's result is of category group".

**Spec.** Both were wrong. §2023:8.4.3.2.4 GR1 gives a user-defined function's temporary item "the description, class, and
category" of its RETURNING item, and §2023:8.5.2.1 says "an alphanumeric group item has class and category alphanumeric".
So the function is an alphanumeric function, which §2023:14.9.51.3 SR4 (WRITE), §2023:14.9.32.3 SR2 (RELEASE) and
§2023:14.9.35.3 SR9 (REWRITE) admit.

**Fix.** The screen asks the one operand-category reader, `IntrinsicResultType.OperandCategory`, which already answers an
alphanumeric group as alphanumeric (and a folded FUNCTION LENGTH as numeric); a null answer is an operand whose binding
reported its own error. `MoveTable16.SenderPosition`'s doc no longer claims the FROM rules as its askers.
Golden `conformance-suite/cases/14.9.51-WRITE/pb3229-write-from-group-function` (accept 2014, 2023) writes and reads back
`[ABCDE12345]`.
