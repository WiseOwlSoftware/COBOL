## Landed (2026-11-16, branch pb5862-arch-oracle-flake)

**The cause, proven.** With the compiled-program store on (every local gate), an oracle case compiled through `CompiledProgramCache.Compile`. Two things followed:
- On a MISS, the compile's `CompilationInputs` recorded the read of its source, which `StageSource` had staged under the store (`.cache/compiled-programs/src/<content hash>/`). That place is outside the case's scratch directory, so `Ambient` called the compile `ambient`.
- On a HIT, the store returns a result whose `Inputs` is empty ("the inputs were verified, not re-read"), so the same case got a digest.

So the observation depended on whether the store already held the compile: whether another host had compiled the case first, or the test's own first call had. The finding's candidate was right that the store is involved. The mechanism is the miss-then-hit pair, not a read of another host's write.

**The fix.** Two parts:
- An oracle observation always compiles for real. `OracleCase.Observe` opens `CompiledProgramCache.Cold()`, an async-local scope in which `Compile` takes nothing from the store. The oracle observes the compiler, as its doctrine says.
- The store's staging directory is the compile's own place. It is named by the hash of exactly the staged content (`CompiledProgramCache.StagedRoot`), so `Ambient` and `AbsentOutside` treat it like the scratch directory.

What "ambient" means is unchanged: what the compiler keys and records about the case's own content is not ambient; anything else it read is.

**The capture is not exposed.** `WiseOwl.Cobol.ArchOracle digests` refuses to run with the store on (exit 3), and the gate starts it with `WISEOWL_COBOL_COMPILE_CACHE=off`. Every capture compile is therefore cold and stages inside its scratch directory, and a case cannot be `ambient` in one gate and carried in the next for this reason.

**Proof.** `ArchOracleDriftTests.AnObservation_IsTheSame_WhetherTheStoreIsColdOrWarm` observes, twice, a program no store has seen, through the path a case uses.
- With the fix removed (no cold scope, and no staging directory among the compile's own places), it FAILED every run: `Assert.Equal() Failure: Values differ`.
- With the fix, it PASSED, as did the whole `ArchOracleDriftTests` class (5/5).
