# A12b — THE NIST COMPILE LEG CANNOT TELL A TRANSIENT FROM A REAL COMPILE ERROR

- THE NIST COMPILE LEG CANNOT TELL A TRANSIENT FROM A REAL COMPILE ERROR — and this one has a NAMED mechanism, unlike A12
- ⛔ **OBSERVED 2026-08-02 (PB13):** `guard-fast.sh` reported `IC222A: COMPILE FAILED — REGRESSION!` / **352 MATCH, 1 REGRESSION**. IC222A compiles CLEAN when re-run serially, and the change under test provably cannot reach it: `guard-fast` drives the LEGACY `cobolsharp.dll`, whose dependency closure is `CobolSharp.CLI → CobolSharp.Compiler → Cobol.Net.Frontend`, and PB13 touched only `Cobol.Net.Compiler` + `Cobol.Net.Runtime` — neither is in that closure. **THE MECHANISM IS IN THE SCRIPT, NOT THE COMPILER:** line 56 runs the compile at `-P$(nproc)` (32 concurrent `dotnet`+Roslyn hosts here) with `>/dev/null 2>&1 \
- \
- true`, and the verdict is then inferred from *whether a `.dll` exists*. So a transient — host startup failure, memory pressure, a file lock on the shared `tests/nist/output` — is INDISTINGUISHABLE from a genuine compile error, and the compiler's own diagnostics, which would settle it instantly, are thrown away. ⚠ This is the MASKING direction too: a program that fails to compile for a real reason reports identically to one that lost a race.
- Capture per-test compile output to `$OUT/<TEST>.compile.log` instead of `/dev/null` and report the first error line with the failure; and/or cap the compile fan-out below `nproc`. Cheap, and it converts every future instance of this from an investigation into a read. **AND ASSERT THE POPULATION (see A12c) — that is the half that makes a false GREEN impossible.**
- With the next `guard-fast` change; do NOT let a red here be dismissed as "parallel flake" again without the log
- **CLOSED 2026-08-03.** Each compile now writes `$OUT/<TEST>.compile.log` + `.compile.rc` instead of `/dev/null`, and `guard-run-group.sh` refuses to call a compile FAILED without a non-zero rc **and** diagnostic text — an evidence-free outcome is `COMPILE NO-VERDICT`, which the audit fails on. The verdict line now carries the first error, so a future instance is a READ rather than an investigation. ⚠ The fan-out was NOT capped: see A12d — capping pays for the damage on every run, and the evidence rules mean contention can only LOSE an observation, which is then re-taken serially.
