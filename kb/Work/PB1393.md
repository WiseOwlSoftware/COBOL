## Finding — `alphanumeric-literals` (under-rejects; rows `SR-8.3.3.2.3-1`)

**Mechanism.** The alphanumeric-literal length cap (8,191 positions) is written only in the NATIONAL and BOOLEAN arms of ExpressionBinder.NonNumericLiteralOperand; the STRINGLIT and HEXLIT arms (and the DATA-DIVISION VALUE path -- probed for alphanumeric; the national/boolean VALUE path is unprobed) construct the literal with no length check, so an over-long alphanumeric literal in either format compiles clean everywhere.

**Repro.** >>SOURCE FORMAT FREE program with `01 W PIC X(9000). ... MOVE "<8,192 A's>" TO W. DISPLAY FUNCTION LENGTH("<8,192 A's>").` and `01 H PIC X(9000) VALUE X"<8,192 x 41>".` -- pinned cobol.exe compiles all three clean and prints 8192 (probe p5/p13 under scratchpad/adj-d2/out/probe/anlit).

**Expected from the spec.** Compile-time rejection of each literal: "The length of an alphanumeric literal, excluding the separators that delimit the literal, shall be less than or equal to 8,191 alphanumeric character positions" (8.3.3.2.3 SR1, ALL FORMATS, so X"..." counts decoded character positions -- 8,192 pairs is 8,192 positions). The 8,191-character literal (p4) stays legal.

**Observed / reasoning.** grep 8191 over src finds the cap only in NationalLiteralOperand / BooleanLiteralOperand (COBOLNET0814, 8.3.3.5.3 SR1 / 8.3.3.4.3 SR1), ConcatFolder (8.8.3.2) and runtime intrinsic guards. The two-arm dispatch: the national/boolean literal arms carry their SR1, the alphanumeric arms beside them never did. Fix at the ONE literal chokepoint (per-class SR1 cap applied wherever a literal token is bound, VALUE included), not a fourth copy; sweep the national/boolean VALUE path too (their cap lives only in the procedure-operand binder).

**Code site.** src/Cobol.Net.Compiler/Binding/Procedure/ExpressionBinder.cs#NonNumericLiteralOperand (STRINGLIT/HEXLIT arms, ~line 209-218)

## Finding — `boolean-literals` (under-rejects; rows `SR-8.3.3.4.3-1`)

**Mechanism.** The 8,191-position literal cap of §8.3.3.4.3 SR1 (and its national/alphanumeric siblings) is enforced in exactly ONE procedure-division operand funnel (ExpressionBinder.BooleanLiteralOperand / NationalLiteralOperand), so every other consumer of a boolean literal - VALUE Format 1, level-88 VALUE, CONSTANT, and the ALL literal-1 figurative (BoundAllLiteral.Of) - decodes through CobolLiteral.Decode with no length check and accepts an over-length literal silently. The rule is a property of the LITERAL, not of its use site; it belongs where the literal is classified/decoded once (one rule, one place), not in a per-funnel copy.

**Repro.** IDENTIFICATION DIVISION. PROGRAM-ID. BL4. DATA DIVISION. WORKING-STORAGE SECTION. 01 B1 PIC 1(8192) VALUE B"<8192 zeros>". PROCEDURE DIVISION. MAIN. DISPLAY "X". STOP RUN.  Also: VALUE BX"<2048 hex digits>"; 88 C1 VALUE B"<8192>"; MOVE ALL B"<8192>" TO B1. Probes: E:/Temp/claude/E--CobolSharp/a700c052-f9e4-4942-84ff-a13c7505d6ec/scratchpad/adj-d2/out/probe/boolean-literals/bl4,bl6,bl8,bl9 (.cob)

**Expected from the spec.** §8.3.3.4.3 SR1: 'The length of a boolean literal, excluding the separators that delimit the literal, shall be less than or equal to 8,191 boolean character positions.' A syntax rule on every boolean literal wherever written, so each repro shall be rejected (COBOLNET0814, as DISPLAY B"<8192>" already is). For BX the measure is the equivalent Format-1 literal's positions (§8.3.3.4.4 GR6), i.e. 4 x digits.

**Observed / reasoning.** All four compile clean and run (print X), while the same literal as a DISPLAY operand draws COBOLNET0814 (probe bl5). Sibling, same mechanism: PIC X(8192) VALUE "<8192 A>" and PIC N(8192) VALUE N"<8192>" also compile clean (probe bl10) - sweep the alphanumeric and national length SRs with the same fix. The existing test NationalBooleanLiteralTests.BooleanLiteral_Over8191Positions_Rejects0814 exercises only the procedure funnel.

**Code site.** src/Cobol.Net.Compiler/Binding/Procedure/ExpressionBinder.cs#BooleanLiteralOperand (the only check); unchecked consumers: src/Cobol.Net.Compiler/Binding/DataBinder.Constants.cs:220-223, BoundAllLiteral.Of (src/Cobol.Net.Compiler/Binding/Bound/BoundTree.cs), the data-division VALUE / level-88 literal path
