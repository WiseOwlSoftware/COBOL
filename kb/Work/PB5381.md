# PB5381 - the SYMBOLIC TERMINAL lock of an input-output CD outlives CANCEL and every CALL of an initial program: Dialogue.LockedTerminalChanged keys it by CD name in a run-unit dictionary nothing clears, so a program in its initial state that names a new terminal gets status 20

**Sites:**

- `src/WiseOwl.Cobol.Runtime/Communication/MessageControlSession.cs#Dialogue` (`LockedTerminalChanged` and the dictionary it keys by CD name)

**Mechanism.** kb/Work PB5283 (landed) made the first statement that references an input-output CD lock the content of its SYMBOLIC TERMINAL item. The lock lives in a run-unit dictionary keyed by the CD name and nothing removes it, so it survives the program's return to its initial state. After CANCEL, or on each CALL of a program with the initial attribute, no statement of the new activation has referenced the CD yet, but the old lock still refuses a new terminal name.

**Inventory.** `work.py check` refuses a 1985 rule id in `inventory_rows` (kb/Work PB5094, open), so `inventory_rows` is empty and the rows this note claims are the rule ids below. Its row is not recorded: the refuter's OVERTURNED verdict is held for adjudication in `E:/COBOL-coord/scratch/coderead-85/held-7.json`.

**Rules (1 claimed; every citation checked with `scripts/spec/cite.py --check`).**

- `1985-GR-XIV.2.2.4-31` - `§1985:XIV.2.2.4 GR31` (refuter: OVERTURNED, harm: wrong status): "After executing the first statement referencing cd-name-1, the content of the data item referenced by data-name-3 must not be changed by the program". A cancelled program "ceases to have any logical relationship to the run unit in which the CANCEL statement appears" (`§1985:X.5.3.4 GR2`).

**Repro.** `E:/COBOL-coord/scratch/coderead-85/out-reread2/refute-rr-11/p31b.cob` with `p31b.json` as `mcs.json` (terminals T1, T2 and T3): SUB31 is CALLed with T2 (00), then T3 (20, correct), then CANCELled and CALLed with T3. The INITIAL-program arm: `E:/COBOL-coord/scratch/coderead-85/reprobe-85f/run/termlock-p28plain/p28plain.cob`, which is `E:/COBOL-coord/scratch/coderead-85/out-reread2/refute-rr-11/p28c.cob` with `CD IOCD FOR I-O` in place of `FOR INITIAL I-O` (p28c.cob on disk now carries the INITIAL clause and is refused COBOL6169 by the 2002 rule against INITIAL with a USING header, so it no longer shows the case the refuter describes). `cobol.exe --std 85 --source-format fixed --run <file>` in a directory holding the mcs.json.

**Observed (the pinned compiler of `E:/COBOL-wt/coderead85-tree-b` (origin/main 8147f008b3; `git diff --stat 8147f008b3 origin/main -- src` is empty at 5237495315), rerun 2026-11-12; `E:/COBOL-coord/scratch/coderead-85/reprobe-85f/log.txt` and `log2.txt`).** p31b ends `SUB3 20`. p28plain prints `SUB1 00` then `SUB2 20`.

**Expected (from the 1985 text).** `SUB3 00` and `SUB2 00`: the cancelled program and each activation of the initial program start with no statement having referenced the CD.

**Fix direction (root cause, CLAUDE.md rule 4).** Make the lock part of the program activation's state, cleared wherever the program's initial state is established (CANCEL, the initial attribute, EXIT PROGRAM of an initial program), rather than a run-unit dictionary. The refuter's second reading (`MOVE "t1"` after a `T1` lock answers 00 because the comparison case-folds) is left to the adjudication.
