# PB5466 - the "without" direction of 1985 debugging-line rule VI.7.3 ("with or without") is untested: no unit compiles WITHOUT the debugging mode a program whose D lines would not parse as source

`§1985:VI.7.3` says: "The content of a debugging line must be such that a syntactically correct program is formed with or without the debugging lines being considered as comment lines." (`cite.py --check`: OK). PB5212 landed the check, `ReportDebuggingLinesBreakingTheProgram`. Its tests cover the direction in which the debugging mode is on; none compiles WITHOUT the debugging mode a program whose D lines would not parse as source, so the direction in which the lines are comments is unpinned, and a change to the check could drop it with no test red. Both directions share one root (PB5212).

**Sites:** `src/WiseOwl.Cobol.Compiler/Frontend.cs` (`ReportDebuggingLinesBreakingTheProgram`: the member the new test pins; the fix is a unit test, in the test file the fixer chooses beside PB5212's).

**Done when** a unit compiles, without WITH DEBUGGING MODE in SOURCE-COMPUTER, a program whose D lines would not parse as source, the test expects the outcome the rule demands (the fixer derives it from the spec and PB5212's note), and it fails when that direction of the check is removed.
