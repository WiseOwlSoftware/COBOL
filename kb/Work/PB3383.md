# PB3383 — the battery's NIST guard shares one directory across programs

A lead from the Mythos lane's PB3334 finisher (report `E:\COBOL-coord\scratch\reports\w1118a4-PB3334-report.md`,
branch `worktree-wf_14a1e62b-326-32`), assigned to the operator's clerk.

**What the finisher found and fixed.** `scripts/guard-run-group.sh` ran a whole NIST chain group in one shared
directory, so IX115A ran over files IX110A and IX114A had left behind (fenced, in the paged store format). The fix runs
each program in a clean directory after only its declared predecessors (`tests/nist/corpus.tsv`'s `chain-preds`). It
lands with PB3334, hence `blocked_by`.

**The sibling it left.** `scripts/guard.sh`, the serial guard the battery runs, still:
- copies the corpus into one `$GUARD_WORK`;
- runs every program from `$NIST_OUT` in the hand-written `NIST_TESTS` order (`for test in $NIST_TESTS`, about
  line 202; `(cd $NIST_OUT && … dotnet "$test.dll")`, about line 228), not the manifest's;
- by its own comment, "still does not clean BETWEEN tests, so TF### carries over".

So a program can meet the TF### files an earlier, unrelated program left behind, and its verdict depends on its
neighbours. It is the same state-carry shape PB642 and PB473 met as false regressions in the battery.

**Two copies.** The two guard scripts now encode the chain run twice: the group script runs each program after its
declared predecessors in a clean directory, and the serial one runs in order in one directory. That is the
duplication PB3199 records for the NIST run environment.

**What goes red when PB3334 lands** (the Mythos reviewer's round 3, `mythos-a4-review-r3`, same report). The
battery's equivalence proof, `scripts/guard-verify.sh` (full mode, lines 461-493), runs the serial `scripts/guard.sh`
beside the group runner and diffs their verdicts. After PB3334's re-captured IX goldens land, IX115A-IX120A run over
the `tf024.txt` IX114A fenced in the shared `GUARD_WORK`, so the two verdict lists differ and the proof fails.
`scripts/guard-fast.sh` lines 2-4 still call the serial guard the authority ("Until that diff is clean, trust
scripts/guard.sh as the authority"), which is now backwards. Repro on Linux:
`GUARD_TESTS="IX109A IX114A IX115A" bash scripts/guard.sh`; IX115A reports that `tf024.txt` differs.

**The fix.** `guard.sh` runs each program in its own clean directory after only its declared predecessors, through
ONE function that both guard scripts call (rule 5: the shape that makes the next case automatic), or the serial arm
is retired and `guard-verify.sh` with it. Either way `guard-fast.sh` lines 2-4 are rewritten to the current state. A
guard self-test pins a consumer whose predecessor's file a non-predecessor would corrupt. The same change retires
`guard.sh`'s hand-written `NIST_TESTS` population and order (kb/Work PB925): with the shared function reading
`corpus.tsv`'s rows and `chain-preds`, nothing needs the hand list, so PB925 and this note close together. The shared function also
carries PB3385's rule (a predecessor's failure fails its consumer).
