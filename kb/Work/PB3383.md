# PB3383 — the battery's NIST guard shares one directory across programs

A lead from the Mythos lane's PB3334 finisher (report `E:\COBOL-coord\scratch\reports\w1118a4-PB3334-report.md`,
branch `worktree-wf_14a1e62b-326-32`), assigned to the operator's clerk.

**What the finisher found and fixed.** `scripts/guard-run-group.sh` ran a whole NIST chain group in one shared
directory, so IX115A ran over files IX110A and IX114A had left behind (fenced, in the paged store format). The fix runs
each program in a clean directory after only its declared predecessors (`tests/nist/corpus.tsv`'s `chain-preds`). It
lands with PB3334, hence `blocked_by`.

**The sibling it left.** `scripts/guard.sh`, the serial guard the battery runs, still:
- copies the corpus into one `$GUARD_WORK`;
- runs every program from `$NIST_OUT` in the hand-written `NIST_TESTS` order (`for test in $NIST_TESTS`, about
  line 202; `(cd $NIST_OUT && … dotnet "$test.dll")`, about line 228), not the manifest's;
- by its own comment, "still does not clean BETWEEN tests, so TF### carries over".

So a program can meet the TF### files an earlier, unrelated program left behind, and its verdict depends on its
neighbours. It is the same state-carry shape PB642 and PB473 met as false regressions in the battery.

**Two copies.** The two guard scripts now encode the chain run twice: the group script runs each program after its
declared predecessors in a clean directory, and the serial one runs in order in one directory. That is the
duplication PB3199 records for the NIST run environment.

**What goes red when PB3334 lands** (the Mythos reviewer's round 3, `mythos-a4-review-r3`, same report). The
battery's equivalence proof, `scripts/guard-verify.sh` (full mode, lines 461-493), runs the serial `scripts/guard.sh`
beside the group runner and diffs their verdicts. After PB3334's re-captured IX goldens land, IX115A-IX120A run over
the `tf024.txt` IX114A fenced in the shared `GUARD_WORK`, so the two verdict lists differ and the proof fails.
`scripts/guard-fast.sh` lines 2-4 still call the serial guard the authority ("Until that diff is clean, trust
scripts/guard.sh as the authority"), which is now backwards. Repro on Linux:
`GUARD_TESTS="IX109A IX114A IX115A" bash scripts/guard.sh`; IX115A reports that `tf024.txt` differs.

**The fix.** `guard.sh` runs each program in its own clean directory after only its declared predecessors, through
ONE function that both guard scripts call (rule 5: the shape that makes the next case automatic), or the serial arm
is retired and `guard-verify.sh` with it. Either way `guard-fast.sh` lines 2-4 are rewritten to the current state. A
guard self-test pins a consumer whose predecessor's file a non-predecessor would corrupt. The same change retires
`guard.sh`'s hand-written `NIST_TESTS` population and order (kb/Work PB925): with the shared function reading
`corpus.tsv`'s rows and `chain-preds`, nothing needs the hand list, so PB925 and this note close together. The shared function also
carries PB3385's rule (a predecessor's failure fails its consumer): PB3385 landed its verdict half in
`scripts/guard-verdict.sh` (`guard_predecessor_verdict`, `guard_predecessor_compile_verdict`), which the serial arm's
chain run calls rather than copying.

## Landed (wave 1131, group D)

**Re-probe** (Windows, Git Bash, this branch's build before the fix): `GUARD_TESTS="IX109A IX114A IX115A" bash
scripts/guard.sh` printed `IX115A: DIFF — REGRESSION! (the report matched but 1 written file(s) do not match
tests/nist/valid-files/IX115A: tf024.txt differs)`, audit `unexpected=1`: the note reproduced.

**Fix: the serial arm is retired, with `guard-verify.sh`'s equivalence proof** (the note's second option, CLAUDE.md
rule 5: one runner makes the next chain automatic). `scripts/guard.sh` is deleted; `scripts/guard-fast.sh` is THE NIST
guard, and `scripts/guard-run-group.sh` its one runner of NIST programs.
- **Population derived** (PB925, landed with this): `guard_nist_population` in `scripts/guard-population.sh`, the
  asserted rows (`green`, `divergent`) plus their declared chain predecessors at any depth, equals the 376 names of the
  retired `NIST_TESTS` exactly. `guard_with_predecessors` adds a `GUARD_TESTS` subset's predecessors to the compile list,
  so a consumer run alone gets its input (IX114A IX115A alone: both MATCH, audit CLEAN).
- **Every program its own job.** The chain graph's connected components (332 groups, each serial in one directory) were
  the coupling's over-approximation once PB3334 gave every program its own directory; `guard-fast.sh` now runs each
  population member as its own `xargs` job, and the serial re-observation re-runs a lost program and every member that
  declares it as a predecessor.
- **Self-test.** `guard-verify.sh` is a discovered `--self-test` (every gate and CI's audits run it) holding the
  evidence-rule witnesses plus three run-directory witnesses over a fake `corpus.tsv`: a consumer is not corrupted by a
  non-predecessor that wrote its file; a consumer run alone gets its declared predecessor's file (both RED against the
  pre-PB3334 shared-directory runner, `git show d633581e9^:scripts/guard-run-group.sh`); and a discriminator (no
  declared predecessor: REGRESSION). A structural witness fails on any other guard script that runs a NIST program.
  `battery.sh` phase 2a is folded into phase 2 (guard-fast.sh runs its self-tests before it measures).
- **Drift tests.** `CorpusManifestTests.GuardNistPopulation_IsDerivedFromTheManifest` (guard-fast.sh reads
  `guard_nist_population`, no guard script names `NIST_TESTS`), `_IsDrawnFromTheManifest` (every member, a predecessor
  included, has a row and a source), `_SurplusIsOnlyPendingPredecessors`; `GuardScripts_CarryNoHandMaintainedNistNameList`
  now scans multi-line assignments (red on a planted copy of the retired `NIST_TESTS`: 372 names).

PB3385 (a predecessor's exit status) landed first, as its own group in the same wave: its rule lives in the one
runner's `run_predecessor` (`guard_predecessor_verdict` / `guard_predecessor_compile_verdict` in
`scripts/guard-verdict.sh`), and with the serial arm retired no second chain run is left to call it.
