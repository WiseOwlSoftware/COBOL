## Acceptance
- `COMPUTE X = ZERO -1` (and the sibling `COMPUTE X = Y -1`) both report COBOL2993; a golden pins the ZERO case. The fix decides
  by grammar position (inside an arithmetic expression the touching sign is still an operator the separator rule must refuse),
  which may fold into the PB3962 root fix rather than add a guard.

## Landed (wave 20261769, group F) - the parse decides the sign's position

**Re-probe** (`E:/COBOL-coord/scratch/w20261769f/zc.cob`, `yc.cob`, base `802352531`): `COMPUTE X = ZERO -1` was COBOL2269
("unexpected '-'") and `COMPUTE X = Y -1` COBOL2993, as filed. The same split held for `IF X = ZERO -1`, `IF ZERO -1 = X`,
`COMPUTE X = (ZERO -1)`, `EVALUATE X WHEN ZERO -1` and `PERFORM UNTIL X = ZERO -1`.

**Mechanism.** PB3962 keeps a ZERO figurative before a sign touching its literal: the right reading in an operand list
and the wrong one in an expression slot. No token test separates the two (the position is the grammar's), so the
decision moved to where the grammar speaks: a pass that fails AT the sign has met an expression slot.

**Fix.** `ZeroSignReading` (one per whole-group parse): `Revise` takes the pass's syntax-error offenders, turns each
figurative ZERO whose touching `+`/`-` offends into `ZERO_ARITH`, and the loop parses again; if the arithmetic reading
fails at that ZERO or its sign too (`MOVE ZERO -1 TO X`) the ZERO is restored and never retried, so a source wrong either
way still reports the operand-list reading's error at the sign. It lives in `ReservationGateRewriter.ParseToFixpoint`,
which every whole-group parse already calls (`ReservationGateParseEntryDriftTests`), fed by the same error-listener
witness as the gate's second witness; it runs only on a pass the reservation gate accepts and only on the error path (a
clean parse costs nothing). The operand-list positions (`DISPLAY ZERO -1`, `ADD ZERO -1 TO X`, the VALUE lists) parse
first time and are untouched.

**Goldens:** `conformance-suite/cases/_unassigned/pb3981-compute-zero-touching-sign` and
`pb3981-relation-zero-touching-sign` (COBOL2993 at all four editions; the PB3962 golden keeps the list positions
accepted); unit tests `ZeroSignReadingTests` pin the flip, the take-back and the end of the loop.

## Landing (for the next implementer)

- `ZeroSignReading.Revise` owns "is this ZERO's touching sign an operator": ask the parse, not the characters. A new
  whole-group parse entry gets it by calling `ReservationGateRewriter.ParseToFixpoint`. `FragmentParse` re-parses read
  lexed list regions (a sign after a separator is a signed literal), so they never meet the case.
