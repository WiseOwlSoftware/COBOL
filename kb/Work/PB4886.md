# PB4886 - the 1985 compiler, audited against the 1985 standard

**Why.** The mission (D13) is 100 % conformance to ISO/IEC 1989:2023, with correct support for 1985, 2002 and 2014 as
per-edition compilers. Today `--std=2023` is audited against its own text: the rule catalog, the traceability inventory
(`tests/version-matrix/inventory/`, 4,214 rows, 0 GAP) and a verdict for every row. `--std=1985` has no such audit. Its
behaviour is checked against two indirect sources:
- `docs/VERSION_CHANGE_REFERENCE.md`, which reconstructs the 1985 language from the later editions' change annexes;
- the NIST CCVS85 suite, a regression net with known holes (CLAUDE.md rule 1).
Neither is the 1985 text. With `specs/ANSI_COBOL_1985.md` reconciled (PB4850), the standard itself can be the authority.

**The plan** (the `brent-tools:spec-compliance-audit` method, as used for 2023; `docs/rearchitecture/DESIGN-spec-conformance-review.md`):
1. **Rule catalog.** Decompose the 1985 file into rules: every syntax rule and general rule, keyed by module, level and the
   1985 numbering. Mark each with its box (level 2, from PB4850's restored boxes) and its amendment (X3.23a-1989,
   X3.23b-1993), because the amended 1985 is a different language level for edition gating.
2. **Map onto the existing inventory.** Most 1985 rules have a 2023 counterpart that already has a verdict. Map each 1985
   rule to its 2023 rule or rules, and carry the verdict only where the text is the same in substance. A rule whose 1985
   wording differs, and every 1985 rule with no counterpart (deleted, obsolete or changed features), becomes a 1985 row of
   its own, adjudicated against `--std=1985` with a pinned compiler.
3. **Check VERSION_CHANGE_REFERENCE.md.** Check its 1985 claims against the 1985 text (PB4850's Connect step starts this).
   Each disagreement is a note, and so is any edition gate the reconstructed claim drove into the compiler.
4. **The conformance statement** (PB4885) is then written from the inventory: the high subset plus all four optional
   modules, with every open row named.
5. **The progress metric** is the 1985 inventory's GAP count, reported beside 2023's in the ledger.

**Cost and order.** The 2023 audit's adjudication ran in concentrated fleet bursts of about a day or two (the owner,
2026-11-07). Most of its calendar time went into building the tooling, which now exists, so this audit is mostly that tooling
run with an edition parameter, and it is smaller: the 1985 language is smaller, and most rows carry a 2023 verdict. The
target is a day or two of fleet time. It needs the reconciled 1985 file first (PB4850).

**The Message Batches arm (owner 2026-11-07: "We also have a large remaining API Batch credit that we can potentially use
for the audit"; $191.60 of promotional credit available).** The independent judgments go to Opus 5.5 through the Message
Batches API, in the shape of the 1985 reconciliation (PB4850): a first pass, then an adversarial verify pass, a canary
before each full submit, and a `max_usd` guard on every submit. The prompts carry the PUBLIC transcription's text only:
no PDF page and no stamp. PB4812's no-API rule covers converting pages, and this is not that.
1. **Mapping (step 2).** One prompt per 1985 rule: its text plus the candidate 2023 rules, found by clause heading and
   wording. The answer is one of SAME (the 2023 verdict carries over), DIFFERS (a 1985 row of its own) or NONE (no 2023
   counterpart), with the 2023 rule ids and the differing words. The verify pass tries to refute each SAME. Disputed
   items go to a fleet adjudicator.
2. **VERSION_CHANGE_REFERENCE (step 3).** One prompt per 1985 claim the reference makes. The answer is CONFIRMED, REFUTED
   or NOT-ADDRESSED, with the 1985 citation (`§1985:<locator>`, PB4887).
3. **Witness drafts.** For each DIFFERS and NONE row, the batch drafts a minimal program and the outcome the 1985 rule
   requires. The fleet compiles and runs each draft under `--std=1985` with the pinned compiler, and records the verdict.
   A draft is never a verdict, and its expected outcome is checked against the rule text before it is used.
The rule catalog (step 1) is a script (`extract_rule_catalog.py` with an edition parameter), and the verdicts stay
with the fleet. A rough estimate, to be measured on the canary: about $40 for the mapping, about half that for its verify
pass, and a few dollars for the drafts. The batch tooling is the reconciliation's (`transcribe_pdf.py`'s restartable batch
state and the scratch `recon1985.py`). It is built into one tool in `scripts/spec/` with that tool's self-test (planted
inputs, a fake client, no API call), not run from scratch. Its design is written into `docs/rearchitecture/DESIGN-spec-conformance-review.md`
as an edition parameter of the one audit, not a second audit, before any wave. The 2002 edition (PB4813) follows the same
path once it is transcribed.

## Landing
- A 1985 paragraph whose heading `KINDS` does not type is a ROW of `docs/rearchitecture/spec-unharvested-rule-blocks-1985.json`
  (disposition and reason, keyed by citation), read by the 2023 arm's own functions in `extract_rule_catalog.py`; never
  add a kind table or an adjudication dict to `rule_catalog_1985.py`. A transcription repair that moves such a paragraph
  shows as a drift at `--check`. `scripts/spec/rule_catalog_1985.py#cite_check` holds every row's citation to the
  transcription.
- `scripts/spec/audit_batch.py#cited` owns an answer's 1985 citation: reuse it (and `CITATION_FIELDS` in a prompt) for any
  new pass that cites the 1985 text; never parse a free-form "citation" string a model writes.
- `scripts/spec/citation.py#RULE_KINDS` is the one list of numbered rule kinds (SR, GR, AR, RV); `NUMBERED_RULE` reads
  kind and ordinal. A heading word ("Function") is never a rule: the locator alone names that paragraph.
- `scripts/spec/citation.py#_real_1985_heads` holds the 1985 file's appendix, front-matter and parent-paragraph heads
  (`_orphan_paragraphs_85`); a region missing for
  a printed heading is a markup fix in `specs/ANSI_COBOL_1985.md` with its LEDGER-1985 entry (a sweep, or the claim's
  decision), never a reader special case. Trap: `verify_publishable --edition 1985` checks a sweep's `now` on its page, so
  re-editing a swept line means editing that sweep's `now`, not adding a second sweep.
