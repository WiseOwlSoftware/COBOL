# PB2465 — LANDED (wave 1045 A, 2026-10-08)

## Landed

Re-probed on the wave's Debug build of 685b44315 (`E:\COBOL-coord\scratch\w1045a\p\c5.cob`, `c8.cob`, `--std 2023`):
`c5` printed `4 2 4` (K, BYTE-LENGTH(W), LENGTH(A)) and `4 8 4 4`; `c8` printed `1 6`, `1 4`, `3 4` — the note's four
shapes exactly. After: `2 2 2`, `8 8 4 4`; `6 6`, `4 4`, `4 4`.

**Shape of the fix (the note's first option: the description completes on demand).**
`src/Cobol.Net.Compiler/Binding/DataBinder.DescriptionCompletion.cs#CompleteDescriptionAhead` brings the operand's
subtree to its completed description when `DataBinder.Constants.cs#BindConstantLength` measures it, through the
pipeline passes' OWN bodies: `SynthesizeImpliedPicturesUnder` (the per-entry body of `SynthesizeImpliedPictures`,
over the subtree and the type declarations it may copy), `ExpandType` / `ExpandSameAs` over the subtree, then
`UsageInheritanceWalk` and `InheritSignWalk` started at the operand with what its ancestors hand down
(`InheritedUsageAt`, a fold of the walk's own `HandDown` with `ImplyGroupUsage`; `InheritedSignAt`). The subtree is
recorded in `_completedAhead`, and the pipeline's two walks pass over it; the implied-PICTURE and TYPE passes are
idempotent. Because a TYPE / SAME AS source may be described later than the demand, `ExpandType` binds a later type
declaration on demand (`BindLaterTypeDeclaration`) and `ExpandSameAsEntry` a later source (`BindLaterRecords` /
`BindLaterEntriesOfOpenRecord`), and a SAME AS source gets its implied PICTUREs and TYPE expansions before it is
copied — all no-ops inside the pipeline, where nothing is described later. §8.4.2.2.1 rule 4's "referenced in any TYPE
clause" now reads `DataItem.WrittenTypeName` (the clause as written), not the pending mark the early expansion clears.
The operand inside the record its constant is demanded by (the PB1941 open-record shape) completes the same way.

**Rule** (`cite.py --check`): §13.10.4 GR5 "determined as specified in the BYTE-LENGTH intrinsic function" OK 5);
GR6 the LENGTH twin OK 6); §13.18.60.4 GR1 OK 1); §13.18.52.4 GR1 "each numeric item subordinate to the group" OK 1);
§13.16.3 SR9 OK 9); §13.18.57.4 GR1 "had been coded in place" OK 1); §13.18.49.4 GR3 OK 3).

**Golden** `2002/pb2465_constant_length_completed_description` (group PACKED-DECIMAL, national group, forward TYPEDEF,
VALUE-implied picture, group SIGN, the open-record arm, SAME AS of a usage-group leaf; each constant beside its
intrinsic). Below-edition: `negative/constant-at-85`. Batch `w1045a-pb2465`.

**For the next implementer.**
- `DataBinder.DescriptionCompletion.cs#CompleteDescriptionAhead` — the one entry point; a NEW pass that changes an
  item's size must join it, or a constant measures the item without it.
- `DataBinder.cs#HandDown` / `#InheritedUsageAt` / `#ImplyGroupUsage` — reuse for any "what does this entry inherit"
  question asked before the usage walk; never re-derive it.
- `DataBinder.cs#UsageInheritanceWalk` and `#InheritSignWalk` skip `_completedAhead` subtrees: a test that binds a
  constant over an item and then expects a usage diagnostic still gets it once (reported early).
- Trap: `ExpandType` clears `TypeRefName`; anything asking "did the source write a TYPE clause" reads `WrittenTypeName`.

**Sibling sweep.** The other compile-time measurement of a data item during the DATA DIVISION bind is the report
arm (`ReportLengthOperand`), whose printable item the report binder builds with its own inheritance, already complete
when measured. Every other size reader (REDEFINES SR8, RECORD clause sizes, VALUE screens) runs in or after the
pipeline. FUNCTION LENGTH / BYTE-LENGTH fold in the procedure division, after it.

## Filed

Filed 2026-10-07 by the train-1033 lander from the wave-1032 group A implementer report (`w1032a-PB667-report.md`,
new defect 1; that branch is SPLIT and unlanded, so the lead was recorded in `train1032-manifest.json` only).

**Shape.** `DataBinder.Constants.cs#BindConstantLength` reads `item.ByteWidth` / `ItemLength.Positions` of the
operand when the constant entry binds, which is before the description-completion passes in `Passes/BindPipeline.cs`
(`SynthesizeImpliedPictures`, `ExpandTypes`, `UsageInheritancePass`, `InheritSignClauses`) have run. Measured:

- `01 G USAGE COMP-5. 05 W PIC 9(4).` — BYTE-LENGTH OF W gives 4; W occupies 2 (group USAGE not yet inherited).
- `01 G. 05 X TYPE T. 05 Y PIC X.` with T `PIC X(5)` — LENGTH OF G gives 1; it is 6 (TYPE not yet expanded).
- a VALUE-implied PICTURE gives 1 where it is 4; a group `SIGN LEADING SEPARATE` gives 3 where it is 4.

The program compiles and runs with the wrong constant value — silent.

**Rule.** §13.10.4 5) (`cite.py --check`: OK) — "If the BYTE-LENGTH phrase is specified ... The value of
constant-name-1 is determined as specified in the BYTE-LENGTH intrinsic function"; §13.10.4 6) (OK) — the LENGTH
twin. The intrinsic measures the item as described, i.e. after every clause that determines its size applies.

**Repros.** `E:\COBOL-coord\scratch\w1032a\p\c5.cob`, `E:\COBOL-coord\scratch\w1032a\p\c8.cob`.

**Code sites.** `src/Cobol.Net.Compiler/Binding/DataBinder.Constants.cs#BindConstantLength`;
the pass order in `src/Cobol.Net.Compiler/Binding/Passes/BindPipeline.cs`.

**Why a redesign.** The measurement must see the completed description, so either the completion passes complete a
record on demand when a constant measures into it, or constant LENGTH/BYTE-LENGTH values are resolved after
completion (with the PB1941 forward-reference arms). It shares the measurement-timing root with PB1941 but is a
separate mechanism.
