# PB3957 — the ORDER row of reserved-words.json says r85=false on the strength of GnuCOBOL's list alone: the 1985 reservation of ORDER is unverified, a possible under-rejection at --std 85

**Sites:** `tests/version-matrix/reserved-words.json` (the ORDER row); `tests/version-matrix/reserved-words-2002.json` (`addedByAnnexF1`);
`scripts/gen-reserved-words.ps1` (the CCVS override block deleted, step 4 `$notReservedAt85`); `src/WiseOwl.Cobol.Editions/ReservedWords.Table.cs` (generated);
`tests/version-matrix/cobol-words.json` (the ORDER row loses `keywordWhereFree`); `scripts/gen-cobol-words.ps1` (step 5c refuses `keywordWhereFree` on a word reserved at every edition);
`src/WiseOwl.Cobol.Frontend/Grammar/Core/CobolWords.g4` (`orderKeyword` gone, generated), `CobolIO.g4` (`sortDuplicatesPhrase`), `CobolSpecialNames.g4` (`orderTableClause`) and `CobolLexer.g4` (the ORDER token comment);
`src/WiseOwl.Cobol.Frontend/Parsing/CobolLexerWordSet.g.cs` (generated); `src/WiseOwl.Cobol.Frontend/Parsing/CobolParserCoreBase.cs` (`PrintsKeyword` comment);
`conformance-suite/profiles/gnucobol.json` (ORDER leaves `extra-reserved-words` 85); tests `ReservedWordsDriftTests.Every2002Word_TheAnnexF1ItemDoesNotNameAsAdded_IsReservedAt85`, `CobolWordsDriftTests.KeywordRules_Are_Generated_From_The_KeywordWhereFree_Rows`.

`tests/version-matrix/reserved-words.json` ORDER had `r85: false`, citing the GnuCOBOL 2002 list only. The 85 SORT
format spells `WITH DUPLICATES IN ORDER`, and the ANSI X3.23-1985 reserved list is commonly given with ORDER, so at 85 a user
word ORDER may be accepted where the 1985 standard reserves it. Repro: `E:/COBOL-coord/scratch/w20261720a/probe/ord1.cob`
`--std 85` compiled. The repository holds no X3.23-1985 text (D-RW3), so this needed an authority before it was a defect.

## Resolution (wave 20261856, 2026-11-03)

The authority is the 2002 standard's own text, which the repository's register holds (kb/Work PB3602 source P2,
`cobolv200112.pdf`): its 8.9 list holds ORDER, and its Annex F.1 item 6 ("The following reserved words have been added",
printed page 835) lists the 84 alphanumeric words 2002 reserved that the previous standard did not, ORDER not among them,
so the previous standard reserved it. Run over the whole 2002 list, ORDER is the ONE word that the item does not name and the
85 flag lacked (318 others agree). The flag came from a "CCVS proof" (DEVLOG 585) that misread ST127A: it spells SORT's
`WITH DUPLICATES IN ORDER` keyword, and no CCVS program declares a data item named ORDER. GnuCOBOL's own 85 list reserves
the word; the generator removed it. Fixed at the root: the override is deleted, the F.1 list is data
(`reserved-words-2002.json addedByAnnexF1`), and the generator and a drift test hold the 85 flag to it for every word.
ORDER now has no free edition, so its `keywordWhereFree` determination (PB3794) and the generated `orderKeyword` rule are gone
and a step-5c guard plus a drift test refuse one on any word reserved at every edition (`>>COBOL-WORDS UNDEFINE` withdraws
the syntax that requires the word, §7.3.10.4 GR3). Probe after the fix: `ord1.cob` is COBOL0901 at 85, 2002, 2014 and 2023;
the SORT phrase still compiles and runs at all four. Recorded in `docs/CONFORMANCE.md` D-RW3.

Sibling found, not fixed (outside this group): F.1 item 6 also names LAST, which GnuCOBOL's 85 list reserves (probably the Report
Writer's LAST DETAIL) - an over-reservation question at most, needing the 1985 text.
