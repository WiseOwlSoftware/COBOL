# PB3995 — gnucobol-keep-on-overflow-comp5: a NOT-only [NOT] SIZE ERROR statement keeps a DISPLAY receiver and overwrites a COMP-5 one

Filed 2026-10-28 to PB3838's bar (its "What a record must carry"), as PB3989's Owed paragraph asks. Upstream status
`unreported`: the tracker has not been searched (owner-gated; nothing is posted outside WiseOwlSoftware).

## Summary

GnuCOBOL 3.2 keeps the receiver unchanged when a statement with a [NOT] SIZE ERROR phrase overflows it
(`COB_STORE_KEEP_ON_OVERFLOW`, `cobc/typeck.c`, the "There is a [NOT] ERROR/OVERFLOW/EXCEPTION" arm), except for a
COMP-5, COMP-X or COMP-N receiver of a statement that has only a NOT ON SIZE ERROR phrase: `build_store_option` sets the
keep flag for those usages only with an ON SIZE ERROR handler (its comment: "Do not check NOT ERROR case, so that we
optimize"), so they take the phraseless store (`libcob/numeric.c` `cob_decimal_get_binary`, the container residue). The
same statement therefore keeps a DISPLAY receiver and overwrites a COMP-5 one.

## Minimal test case

Fixed reference format, `E:/COBOL-coord/scratch/op/pb3995.cob` (outside git, written for this note):

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. KEEPT.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 X5 PIC 99 COMP-5 VALUE 99.
       01 XD PIC 99 VALUE 99.
       PROCEDURE DIVISION.
           ADD 200 TO X5 NOT ON SIZE ERROR DISPLAY "NOT" END-ADD
           ADD 200 TO XD NOT ON SIZE ERROR DISPLAY "NOT" END-ADD
           DISPLAY "X5=" X5
           DISPLAY "XD=" XD
           STOP RUN.
```

## Environment

`cobc (GnuCOBOL) 3.2.0`, Ubuntu package `gnucobol3 3.2-4build1`, WSL2 Ubuntu on Windows 11. Run 2026-10-28, checking
off (no `-debug`, no `-fec`):
`cobc -x -fixed -o pb3995 pb3995.cob && ./pb3995`

## Observed result

```
NOT
X5=043
XD=99
```
exit 0. `NOT` is shown once: the COMP-5 statement ran its NOT ON SIZE ERROR branch (no size error was recognised for it)
and stored the residue 043 ((99 + 200) mod 256); the DISPLAY statement recognised the size error, kept 99, and did not
run the NOT branch. This matches the expectation recorded by the review (X5 043, XD 99).

## Expected result (per ISO)

ISO/IEC 1989:2023 §14.6.13.1.3 item 8 (validated with `scripts/spec/cite.py --check 14.6.13.1.3`, result `OK
§14.6.13.1.3 8)`): "If checking for the exception condition is not enabled, the implementor defines whether or not
execution will continue, how it will continue, and how any receiving operands are affected." §14.7.5 (SIZE ERROR phrase
and size error condition, `--check` OK) governs the phrase. The standard leaves the receiving operand's value to the
implementor, so neither result is a conformance violation of itself. Edition: 2014 (`-std=cobol2014` claims it; the
size error condition is the same). This is therefore a consistency defect, not a conformance bug: within one
implementor-defined disposition, the binary-capacity usages behave differently from every other usage only as an
optimization side effect.

## Class

Wrong output (an inconsistent store: a silent data difference between usages of one statement).

## Fix site (GnuCOBOL 3.2 source, read observationally)

`cobc/typeck.c`, `build_store_option` (the keep flag for COMP-5, COMP-X, COMP-N receivers only with an ON SIZE ERROR
handler; comment "Do not check NOT ERROR case, so that we optimize") and the "There is a [NOT]
ERROR/OVERFLOW/EXCEPTION" arm that sets `COB_STORE_KEEP_ON_OVERFLOW`; the store itself is `libcob/numeric.c`
`cob_decimal_get_binary`. Cited from PB3989's reading of the 3.2 tree; not re-read for this note.

## Draft issue

**Title:** [NOT] SIZE ERROR keeps an overflowing DISPLAY receiver but not an overflowing COMP-5 receiver when only NOT ON SIZE ERROR is given

**Body:**

Environment: GnuCOBOL 3.2.0 (Ubuntu `gnucobol3 3.2-4build1`), Linux x86_64, no `-debug`.

Steps: compile the program below with `cobc -x -fixed -o t t.cob` and run it.

```cobol
       IDENTIFICATION DIVISION.
       PROGRAM-ID. KEEPT.
       DATA DIVISION.
       WORKING-STORAGE SECTION.
       01 X5 PIC 99 COMP-5 VALUE 99.
       01 XD PIC 99 VALUE 99.
       PROCEDURE DIVISION.
           ADD 200 TO X5 NOT ON SIZE ERROR DISPLAY "NOT" END-ADD
           ADD 200 TO XD NOT ON SIZE ERROR DISPLAY "NOT" END-ADD
           DISPLAY "X5=" X5
           DISPLAY "XD=" XD
           STOP RUN.
```

Observed: `NOT`, `X5=043`, `XD=99`. The same statement keeps the DISPLAY receiver and overwrites the COMP-5 receiver
with the binary residue (and runs the NOT ON SIZE ERROR branch for it).

Expected: one disposition for both. ISO/IEC 1989 14.6.13.1.3 rule 8 lets the implementor define how receiving operands
are affected when checking is off, but within that choice the binary usages should not differ from the others as a side
effect of an optimization: `build_store_option` omits the keep flag for COMP-5/COMP-X/COMP-N when there is no ON SIZE
ERROR handler ("Do not check NOT ERROR case, so that we optimize"), so the store takes `cob_decimal_get_binary`'s
phraseless path.
