# PB3421 — work.py check does not validate `severity` against the register's vocabulary

Found by the orchestrator loop's enqueue unit (2026-10-19 ~00:40 PDT) while reading the clerk's notes PB3416-PB3419
(PR #278): PB3418 was filed `severity: MEDIUM`, and `python scripts/spec/work.py check` passed it.

**The vocabulary.** Every reader of the register uses BLOCKER, MAJOR, MINOR, INFO and OWNER: `work.py`'s `actionable`
ranks with `sev = {"BLOCKER": 0, "MAJOR": 1, "MINOR": 2, "OWNER": 3}` (`scripts/spec/work.py:474`), and the register
held 1657 MINOR, 957 MAJOR, 62 INFO, 12 BLOCKER and 8 OWNER notes on 2026-10-19. Two notes were outside it: PB3418
(`MEDIUM`) and PB3291 (`minor`, lowercase).

**The defect.** `check` (`scripts/spec/work.py`, the per-item loop around :425-440) validates the harm flags, the
status heading and `closes_rows`, but never `severity`. An off-vocabulary value therefore passes, and `actionable`'s
`sev.get(..., 9)` ranks it after every OWNER item, so a harmful note filed `Major` or `medium` sinks to the bottom of
`work.py next` with no warning. The branch reviewers' severity words (critical, high, medium, low, info, from
`review_findings.py`) are a second vocabulary a clerk copies from a report into a note, which is how PB3418 got
`MEDIUM`.

**Already corrected (the change that filed this note).** PB3418 `MEDIUM` → `MINOR` (a missing witness does nothing to
a user's program, and the note is `process_only`) and PB3291 `minor` → `MINOR`. The checker gap remains.

**Repro.** Set any open note's `severity:` to `medium` and run `python scripts/spec/work.py check`: it passes.

**Fix.** `check` refuses a `severity` outside {BLOCKER, MAJOR, MINOR, INFO, OWNER}, naming the file and the value (one
constant, read by both `check` and `actionable`'s ranking, so the two cannot drift), with a self-test case per arm.
Sweep: any other frontmatter field with a closed vocabulary that `check` reads but does not validate (`kind`; `area` is free text by design, 437 distinct values on 2026-10-19).
