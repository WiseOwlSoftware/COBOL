# PB3891 — national-ord-reads-high-utf16-byte: FUNCTION ORD of a national character returns the ordinal of its high-order byte (1 for N"A" and N"Z")

Campaign PB3838, tier 4: filed 2026-10-27 from the tier 2 harvest and the tier 3 adjudication (slice S4) and refutation (UPHELD). Upstream status `unreported`: the tracker has not been searched (tier 6, owner-gated). Evidence, outside git on one machine: `E:\COBOL-coord\scratch\op\pb3838\records\national-ord-reads-high-utf16-byte.md` and `.cob`, the refuter's reruns under `E:\COBOL-coord\scratch\op\pb3838\refute\national-ord-reads-high-utf16-byte\`.

## Summary

Under `-std=cobol2014`, `FUNCTION ORD` of a one-character national item returns 1 for every character whose UTF-16
code unit is below U+0100: it returns the first byte of the item's storage (0x00, the high-order byte of the big-endian
UTF-16 code unit) plus one, not the character's ordinal position in the national program collating sequence. Two
characters that the same program compares as unequal (N"A" < N"Z") get the same ordinal. Class: wrong output.

## Minimal test case

Free reference format (`-fformat=free`), 11 lines, written for this record (reduced from WiseOwl fuzz program
fz02784, night 4).

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. ORDN.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 NAT-A PIC N(1) VALUE N"A".
01 NAT-Z PIC N(1) VALUE N"Z".
PROCEDURE DIVISION.
IF NAT-A < NAT-Z DISPLAY "A < Z" END-IF
DISPLAY FUNCTION ORD(NAT-A)
DISPLAY FUNCTION ORD(NAT-Z)
STOP RUN.
```

## Expected result (per ISO)

- ISO/IEC 1989:2023 §15.70.4 2) (checked): "If the class of argument-1 is national, the returned value is the ordinal
  position of argument-1 in the current national program collating sequence."
- §15.70.3 1) (checked): argument-1 "shall be one character position in length and shall be of category alphabetic,
  alphanumeric, or national". The program's arguments are legal.
- §12.3.6.4 10) (checked): with no PROGRAM COLLATING SEQUENCE clause, "the initial program collating sequences are the
  native alphanumeric collating sequence and the native national collating sequence".
- §12.3.7.4 6) (checked): "The implementor shall define the order of characters within the native alphanumeric coded
  character set and the native national coded character set, associating each character with an ordinal position
  within the character set." The order is the implementor's choice; that each character has its own position is not.
- §8.8.4.2.10 1) (checked): in a standard comparison of national operands, "The operand that contains the character
  that is positioned higher in the national collating sequence is the greater operand." The program's own comparison
  finds N"A" < N"Z", so the two characters hold different positions in the national collating sequence and ORD must
  return different values, the one for N"A" smaller. Returning 1 for both is wrong under any native national
  collating sequence the implementor could define. Ordinal 1 is the position of the character whose code is 0, which
  is the high-order byte of U+0041 and U+005A.

Edition: the rule is the same in the 2014 edition. ORD with a national argument is a 2002 feature; the 2009 committee
draft that became ISO/IEC 1989:2014 (CD 1.2, §15.65.2 1) and §15.65.3 2)) carries the same argument and returned-value
rules, and Annex E of the 2023 standard lists no change to ORD.

Edition as recorded by the adjudicator: 2014 (ORD with a national argument is 2002; same rule in the 2009 CD and in 2023). `upstream_edition: 2014` is the edition `-std=cobol2014` claims; the cited clauses were validated with `scripts/spec/cite.py --check` by the adjudicator and again by the refuter.

## Our compiler (WiseOwl)

WiseOwl COBOL (built from main 6ed90bd1c), `cobol ordn.cob --std 2014 --source-format free -o ordn.dll`, then
`dotnet ordn.dll`: compile exit 0, run exit 0, output `A < Z`, `66`, `91` (the same ordinals WiseOwl returns for the
alphanumeric letters A and Z: code unit plus one).

## Fix site (GnuCOBOL 3.2 source, read observationally)

- `libcob/intrinsic.c`, function `cob_intr_ord` (line 4340 in the 3.2 tree): it forms the result from the first byte of
  the argument's data plus one, with no branch on the argument's class or size. A national argument (two bytes per
  character, big-endian) needs the character's code unit read from both bytes and mapped to the national collating
  sequence.
- `cobc/reserved.c`, the `function_list` entry for "ORD" (line 3702), and `cobc/tree.c` `cb_build_intrinsic`, if the
  fix routes national arguments to a separate run-time entry.

## Draft issue

**Title:** FUNCTION ORD of a national character returns the ordinal of its high-order byte (1 for N"A" and N"Z")

**Body:**

Environment: GnuCOBOL 3.2.0 (Ubuntu gnucobol3 3.2-4build1), x86_64 Linux.

Steps:

```
cobc -std=cobol2014 -fformat=free -x ordn.cob && ./ordn
```

with `ordn.cob`:

```cobol
IDENTIFICATION DIVISION.
PROGRAM-ID. ORDN.
DATA DIVISION.
WORKING-STORAGE SECTION.
01 NAT-A PIC N(1) VALUE N"A".
01 NAT-Z PIC N(1) VALUE N"Z".
PROCEDURE DIVISION.
IF NAT-A < NAT-Z DISPLAY "A < Z" END-IF
DISPLAY FUNCTION ORD(NAT-A)
DISPLAY FUNCTION ORD(NAT-Z)
STOP RUN.
```

Observed: `A < Z`, then `000000001` twice.

Expected: two different ordinals, the first smaller. ISO/IEC 1989:2014 (2023 §15.70.4 rule 2): "If the class of
argument-1 is national, the returned value is the ordinal position of argument-1 in the current national program
collating sequence." The program's own comparison places N"A" below N"Z" in that sequence (standard comparison,
2023 §8.8.4.2.10), so the two cannot share ordinal position 1.

Cause: `cob_intr_ord` in libcob/intrinsic.c returns the first byte of the field plus one for every argument class; for
a national field that byte is the high-order byte of the UTF-16 code unit (0x00 for U+0000..U+00FF).
