# PB4507 — INTEGER-OF-FORMATTED-DATE refuses a function-identifier as argument-2

**Found:** 2026-11-03 by the first Claude-written fuzz batch (PB4506 smoke, 5 programs), adjudicated WISEOWL-DEFECT by
slice C1. Witness (reduced by the adjudicator, `E:/COBOL-coord/scratch/fuzz-triage/fuzz-batch-smoke-20261103/adj/C1/probes/iofd/iofd.cob`):

```cobol
       01 WS-D PIC X(10) VALUE "2000-03-01".
       01 WS-N PIC S9(9) VALUE 0.
       PROCEDURE DIVISION.
           COMPUTE WS-N = FUNCTION INTEGER-OF-FORMATTED-DATE("YYYY-MM-DD", FUNCTION UPPER-CASE(WS-D))
```

WiseOwl refuses it with COBOL1627 ("argument-2 shall be a DATA ITEM ... a literal or an expression is not admitted").
The same program with `WS-D` itself as argument-2 returns 145792 (2000-03-01, hand-derived).

**The rule.** §15.48.3 3) (checked): "Argument-2 shall be a data item of the same type as argument-1." §8.4.3.2.4 1)
(checked): "A function-identifier references a temporary data item whose value is determined when the function is
referenced at runtime." So a function-identifier returning an alphanumeric value IS a data item of argument-1's type.
§15.3's argument types use "data item" the same way throughout ("Alphanumeric. A data item of the class alphabetic or
alphanumeric or an alphanumeric literal"), and nested function-identifiers are admitted for every one of them; the
rule's force is to exclude a LITERAL (and an expression, which is not a data item).

**The code site.** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/IntrinsicBinder.cs` (the PB58 screen,
`args[1] is not BoundFieldOperand`): it admits only a field operand, so a bound function call is refused with the
literals the screen was written for.

**Sweep.** Every other "shall be a data item" screen in the binder that tests for `BoundFieldOperand` (intrinsic
arguments and statement operands alike) is a candidate for the same mistake; the fix asks one question, "is this
operand a data item (a field reference, a function-identifier's temporary, ...)", in one place, and the screens use it.
Keep the refusal of literals, figurative constants and arithmetic expressions (under-rejecting is the worse failure).
