# PB3515 — three option readers repeat one pattern

One mechanism: a compile option whose value is one of a closed set of spellings, read from the command line and from
`wiseowl/options.json`, is implemented three times in the same shape: `ZonedSign.OptionSpellings` / `TryParseOption`
(Cobol.Net.Runtime, public API), `InitialReferenceFormatOption`, and `NumericDisplayFormOption` (added by PB3505, which
copied the pattern). This is the duplication dimension of the owner's four review criteria; CLAUDE.md rule 5 asks for the
shape that makes the NEXT option automatic.

Constraint: the `ZonedSign` members are public API pinned by `RuntimeAbiPinDriftTests`, so merging them into one generic
closed-set option reader waits for a runtime major version bump. The two compiler-side readers could merge earlier, but
the unified shape must also carry ZonedSign, so the restructuring is done once, at the bump, with a drift test that fails
when a closed-set option is added outside the shared reader.

**Sites:** src/Cobol.Net.Runtime (ZonedSign option members); src/Cobol.Net.Compiler/Binding (InitialReferenceFormatOption, NumericDisplayFormOption); the tests RuntimeAbiPinDriftTests and NumericDisplayFormDriftTests; a new drift test for the shared reader.
