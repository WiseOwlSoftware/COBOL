# PB357 — the emit site decides an answer the rule gives the runtime

**Rows:** `GR-14.9.41.4-13`, `GR-14.9.41.4-14`.

## The program

`<lane3 scratch>/out-b1/probe/start-p2-j/p2j.cob` (and `start-p2-b/p2b.cob`) — an indexed file,
`RECORD KEY IX-PRIME PIC X(4)`, one record `AB01`; `OPEN INPUT`; `MOVE "AB01" TO IX-PRIME`; then each of

```cobol
START IXF KEY IS EQUAL TO IX-PRIME WITH LENGTH 2.5
START IXF KEY IS EQUAL TO IX-PRIME WITH LENGTH 3 / 2
START IXF KEY IS EQUAL TO IX-PRIME WITH LENGTH WL     *> WL PIC 9V9 VALUE 2.5
START IXF KEY IS EQUAL TO IX-PRIME WITH LENGTH BIG    *> BIG PIC 9(12) VALUE 4294967297
```

Observed **FS=00 for all four** — the START succeeds and positions.

## The rule

> §14.9.41.4 GR14: If arithmetic-expression-1 does not evaluate to a positive nonzero integer that is less than
> or equal to the length of the associated key, the I-O status value in the file connector referenced by
> file-name-1 is set to '23', the invalid key condition exists, and the execution of the START statement is
> unsuccessful.

`--check 14.9.41.4 "does not evaluate to a positive nonzero integer that is less than or equal to the length of
the associated key"` → **OK**. §14.9.41.3 carries no syntax rule confining arithmetic-expression-1 to an integer
expression, so 2.5, 3/2 and 4294967297 are all LEGAL SOURCE whose defined result is FS='23' and the INVALID KEY
branch. All four cases must print FS=23.

## What the compiler does

`KeyedIoEmitter.EmitStart` (lines 344-347) renders the phrase as
`(int)({NumericRenderer.Align(num.Render(le, ReceiverContext.None), 0)})`. `Align`
(`CodeGen/Emit/NumericRenderer.cs:633`) rescales with `CobolRounding.Truncation`, so 2.5 becomes 2 and 1.5
becomes 1; the outer `(int)` then narrows in an unchecked context, so 4294967297 wraps to 1.
`IndexedConnector.Start`'s guard `if (compareLength < 1 || compareLength > keyLength) return StartFail();`
(line 452) is therefore applied **to a value that has already been forced into range** — GR14's predicate is
never evaluated against arithmetic-expression-1 itself.

**The in-range legs are correct** (LENGTH 0 → '23', LENGTH 5 on a 4-character key → '23', LENGTH -1 → '23'),
which is exactly why the defect is silent: the guard looks present and tested.

## The fix shape, and the sweep

Carry the count to the runtime **unrounded** — the scaled / Int128 value the expression really produced — and let
the GR14 predicate (integer-valued AND >= 1 AND <= the associated key's length) be evaluated ONCE, in the
connector, on that value. The emit site must not be allowed to decide the answer by narrowing. Sweep for
everywhere else a §14.9 runtime status depends on an emit-time `(int)(Align(...))` of a user expression — the
RETRY amounts are the obvious neighbours (**PB346**).

**Code sites:** `KeyedIoEmitter.cs#EmitStart` (lines 344-347) · `IndexedConnector.cs#Start` (line 452) ·
`NumericRenderer.cs#Align` (line 633).
