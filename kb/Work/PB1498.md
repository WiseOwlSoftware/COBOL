## The rule (every citation re-run through `cite.py --check`)

> If the description of the returning item of a method in interface-1 directly or indirectly references interface-2, the description of the returning item of the corresponding method in interface-2 shall not directly or indirectly reference interface-1.

`OK  §9.3.8.2.3 5) 2. c)  (Conformance between interfaces) — cite.py's locator attaches the trailing sentence to the last sub-item; it closes the clause`


## Finding — `conformance-for-object-orientation` (under-rejects; rows `GR-9.3.8.2.3-L2.3`)

**Mechanism.** The anti-circularity sentence of §9.3.8.2.3 ('If the description of the returning item of a method in interface-1 directly or indirectly references interface-2, the description of the returning item of the corresponding method in interface-2 shall not directly or indirectly reference interface-1') has no implementation — MethodConformanceMismatches checks rules 1-9 per method pair and nothing examines mutual references between the returning descriptions

**Repro.** --std 2023: INTERFACE-ID. ICIRC (REPOSITORY CLASS CCIRC), METHOD-ID. M, LINKAGE `01 R USAGE OBJECT REFERENCE CCIRC.`, PROCEDURE DIVISION RETURNING R; CLASS-ID. CCIRC, OBJECT. IMPLEMENTS ICIRC, METHOD-ID. M RETURNING `01 R USAGE OBJECT REFERENCE CCIRC.` -> compiles and runs 'OK' (probe L23A).

**Expected from the spec.** Where interface-1's returning description references interface-2 (directly, or indirectly through the referenced class's IMPLEMENTS/INHERITS) and interface-2's references interface-1, interface-1 does not conform to interface-2 -> COBOLNET0841 (IMPLEMENTS) / 0829 (override) / InterfaceConformsTo false. Whether L23A itself is caught depends on the reach of 'indirectly references' (via CCIRC's IMPLEMENTS ICIRC), which the register should adjudicate before the golden is written; a construct unambiguously inside the sentence must be found and pinned.

**Observed / reasoning.** grep over src/Cobol.Net.Compiler/Oo for any reference-cycle test between returning descriptions finds none; the only 'circular' check in the OO tree is the INHERITS-cycle guard in OoClassTable (a different rule).

**Code site.** src/Cobol.Net.Compiler/Oo/OoConformance.cs#MethodConformanceMismatches (absent check)

## What the fixer owes

Add the reference-graph test to OoConformance.MethodConformanceMismatches (or the conformance driver above it): for each conforming method pair whose returning items are object references, walk the interface/class references of each returning description (directly, and through the inherited/implemented interfaces) and refuse the pair when each side reaches the other. One diagnostic from the allocation. Golden + negative from the ICIRC/CCIRC repro.
