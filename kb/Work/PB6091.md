# PB6091 - the third 1985 pass: all pages, piloted first

**The question.** PB6051's second pass (976 pages, 236 claims, 167 confirmed, 23.7M subagent tokens) is repaired on main
(#1953). Group C's report called a third pass "the owner's quota decision". It is not: the quota plan in force for
account 2 this week is the owner's 90 % (2026-11-21), the reading is 33 %, and the owner set PB6051's end himself:
"The markdown must be 100% accurate first. Everything afterwards is driven from the markdown", done "when a full pass
finds nothing".

**Decision.** A third independent pass over all 976 pages. Re-reading only the pages pass 2 changed would not meet the
owner's criterion: a page pass 2 left alone was read twice by agents who could miss the same thing. 73 % of pass 2's
confirmed claims were heading levels, which `heading_levels.py` now derives and lints (PB6057), so a third pass should
cost much less than the second. That is an expectation, not a measurement, so the pass is **piloted** on pages 227-466
(pass 2's chunk 2: 32 of its 38 confirmed claims there were headings). The pilot's tokens per page and confirmed claims
per page set the remaining chunks' pace. If the pilot confirms nothing, the rest runs at once. If its cost per page is
above pass 2's (about 24,300 tokens a page), the scope comes back here before more pages run.

**Coordination.** Each repair changes rule text, which re-opens that rule's code read. Until account 1's PB6090 lands
(the landing check refuses a branch that makes a stored read stale through a rule-digest change), account 2 tells account
1 before a pass-3 repair branch lands, so the re-reads run in the same pipeline (account 1's message of 2026-11-22
14:54).

**Closes** when the third pass's claims are all decided. PB6051 itself closes only if that pass confirms none.
