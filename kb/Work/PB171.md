# PB171

ConditionBinder binds the sign-condition operand with `host.Expr.BindOperandExpr(operands[0])`; the walk
matches `Core.LiteralContext` / `DataReferenceContext` / `ArithmeticExpressionContext` but the grammar's
`valueOperand : arithmeticExpression | nonNumericLiteral` (Core/CobolExpressions.g4) delivers a BARE
`NonNumericLiteralContext` — no arm matches, the queue drains, and the documented fallback returns
`BoundNumLiteral("0")`. `IF "ABC" IS POSITIVE` / `IF SPACE IS NEGATIVE` therefore compile clean and evaluate
`0 > 0` — the silent-degradation shape the fallback's own comment warns about, on source the §8.8.1.1 screen
exists to reject. The comment credits `ArithmeticSendingOperandDriftTests` with pinning the walk's coverage,
but that test only compares the four arithmetic operand rule bodies to each other and never looks at
`comparisonOperand`/`valueOperand`.

WHAT WOULD CLOSE IT: a NonNumericLiteralContext arm in the walk routing through the same NumLiteral screens
(0844 for a non-ZERO figurative / string / hex / national / boolean; ZERO → 0), a negative fixture
`IF "ABC" IS POSITIVE`, and the drift test extended to every rule the walk serves.
