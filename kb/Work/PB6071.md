# PB6071 - a group actual passed to an elementary formal may take the wrong conversion

`OoEmitter.cs` (about line 2170) converts an actual argument for a parameter whose formal is elementary with
`U.Move.ConvertSource(new BoundFieldOperand(sp), a.Formal)`. If `sp` names a GROUP item the conversion treats it as a field
operand, the elementary path. Whether the CALL/INVOKE argument rules route a group actual elsewhere (an alphanumeric-group
reading, a refusal, or BY CONTENT/BY VALUE semantics) is unprobed.

**Probe first:** INVOKE with a group actual and a numeric (and an alphanumeric) elementary formal, BY REFERENCE, BY CONTENT and
BY VALUE, at 2023; derive the expected behaviour with `spec-lookup` (the INVOKE argument-matching rules). Then compare the same
shape in `CallBinder`/`CallEmitter` (the procedural CALL twin) for the same defect.

**Sites:** `src/WiseOwl.Cobol.Compiler/CodeGen/Verbs/OoEmitter.cs#ConvertSource call (~2170)`.
