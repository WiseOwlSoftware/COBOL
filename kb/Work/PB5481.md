# PB5481 - at --std 85 EVALUATE with a literal selection subject and a literal selection object (EVALUATE ZERO WHEN 0, 5 WHEN 5, 5 WHEN NOT 4) is refused COBOL1634: the 2002/2023 combination table is applied with no edition gate

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/EvaluateOperandCombinations.cs` (`EvaluateOperandCombinations.IsPermitted`)
- `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/EvaluateBinder.cs` (`EvaluateBinder.ScreenPairing`)

**Mechanism.** `EvaluateBinder.ScreenPairing` classifies each subject/object pair through `EvaluateOperandCombinations.IsPermitted`, which is the combination table of ISO 2023 (§2023:14.9.13.3 SR10, Table 15; the diagnostic cites it), applied at every edition. That table leaves literal x literal blank, so at --std 85 EVALUATE ZERO WHEN 0, 5 WHEN 5, "A" WHEN "A", 5 WHEN NOT 4 and an ALSO position of the same are refused COBOL1634, while 5 WHEN 1 THRU 9, "A" WHEN "A" THRU "Z", 1 + 1 WHEN 2 and 12 WHEN N3 are accepted, as the 2023 table permits. 1985 has no such table. **The edition the gate starts at (the open fact, settled):** ISO 2002 prints the same table: §2002:14.8.12.2 SR9, "The permissible combinations of selection subject and selection object operands are indicated in table 16" (specs/ISO_COBOL_2002.md, Table 16, whose `[NOT] literal` row is blank under the Literal subject column; cite.py OK). So the table holds from 2002, and the refusal is wrong only below 2002, at --std 85.

**Latitude.** §1985:VI.6.13.3 SR6 a asks that "Identifiers, literals, or arithmetic expressions appearing within a selection object must be valid operands for comparison to the corresponding operand in the set of selection subjects". The adjudicator read that as a property of the operand pair (class, usage and index rules), not of a relation condition as a whole, whose sentence "The relation condition must contain at least one reference to a variable" (§1985:VI.6.3.1.1) concerns the relation condition. EVALUATE builds no relation condition: a literal subject and literal object "are assigned the value and class of the specified literal" (§1985:VI.6.13.4 GR1). SR6a's page reference to the Relation Condition page keeps the other reading alive, so it is latitude, and ISO does not settle it (its table is neither reading). By the CLAUDE.md rule 1 precedence GnuCOBOL decides: GnuCOBOL 3.2 with -std=cobol85 compiles and runs EVALUATE ZERO WHEN 0, 5 WHEN 5, "A" WHEN "A", 5 WHEN NOT 4 and IF 0 = 0 (each prints HIT, as the adjudicator measured with cobc 3.2.0 under WSL, `p/r4/gc/`). Decided: literal x literal is legal at --std 85; the choice goes into docs/CONFORMANCE.md with the fix.
