# PB3290 — the writer audit passes an explicit CRLF writer

**Symptom:** the review finisher of notes-PB1754-r2b5b-20261016 (2026-10-16) gated the branch and the gate stopped
before any leg: `=== BUILD-LOCAL GATE: RED — LINE ENDINGS RED … (run 20261016T212639Z-54a7bf)`, `0 index · 6 working
tree · 0 writers`. The six files were kb/Work/PB3251 and PB3253 to PB3257, written by the batch-5b filing through
`scripts/arch/file_census_notes.py --r2`. Git stored them LF (the index arm was 0), but the checkout held CRLF, so every
later gate of that worktree was RED until `line_endings.py --fix`.

**Root cause:** `file_census_notes.py` wrote every note with an explicit `newline="\r\n"` (file_notes twice,
merge_into_note, file_r2: four calls), against the one-format rule of kb/Work PB3029 (every tracked text file is LF).
`scripts/line_endings.py` `scan_writers` / `unstated_newline` look only for a text-mode write that does NOT state
`newline=` (the Windows default is CRLF), so a writer that states CRLF on purpose is never reported: the audit printed
`0 writers` while naming the six CRLF files the tool had just written. A grep of the tree (`git grep -n -F
'newline="\r\n"' -- '*.py'`) found these four calls and no other.

**Fixed in the same change (I9):** the four calls now write `newline="\n"` (notes-PB1754-r2b5b-20261016, the review
finisher's commit), and the six checkouts were renormalized with `python scripts/line_endings.py --fix`.

**Open (this note):** the audit gap. Target: `line_endings.py`'s writer arm also reports a text-mode write of a tracked
file whose `newline=` is a literal other than `"\n"` or `""` (for a reader), with a self-test case for
`newline="\r\n"` seen failing once on the pre-fix `file_census_notes.py`; `--fix-writers` rewrites such a literal to
`"\n"`. Scope it against the tree first: today the only such writer was the one fixed above, so the extended audit
starts at zero findings.

**Sites:**
- `scripts/line_endings.py:159-200` (unstated_newline, writer_calls, scan_writers)
- `scripts/arch/file_census_notes.py` (the four writers, fixed)
