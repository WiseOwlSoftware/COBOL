# PB5967 - one self-test keyed on the whole tree's file names

**Mechanism.** A self-test's PASS is keyed by what a traced run read (`scripts/self_test_inputs.py`: file content ids; directory listings by `git ls-files`
names; kinds `names`, `paths`, `content`). `scripts/selftests/orchestrator/plan_wave/test_planner.py` runs `git ls-files -z` over the whole repository
(and `git rev-parse HEAD`, `HEAD^{tree}`, `--short origin/main`), so the gate log reports "its PASS is keyed on the name of every tracked file" and the
key moves whenever a branch adds, renames or deletes any file (every DEVLOG entry, kb/Work note or test file does), and with the merge base.

**Evidence** (gate logs under `E:/COBOL/.claude/worktrees/*/TestResults/build-local/*/gate.log`, 2026-11-20): `test_planner.py` re-ran in 272.2 s
(listing-step-6b-r1 run 000002, "93 input(s) changed"), 288.2 s, 304.9 s ("1 input(s) changed"), 321.3 s ("2 input(s) changed"), 476.1 s, and 1443.1 s
(listing-step-6b-r1 run 000001, "90 input(s) changed ... DEVLOG/3866-...md, docs/CONDITIONS_EXCEPTIONS_DESIGN.md ... (+87 more)"), the same
run in which the whole SELF-TESTS phase took 1449 s ("2 ran, 209 reused"). A one-input change (a new file) is enough to trigger the re-run.

**Fix shape** (CLAUDE.md rule 5): the planner reads a tracked-file listing only to find the scripts and kb inputs it plans over; narrow its reads to
the pathspecs it needs (the `git ls-files -- scripts/ .claude/ conformance-suite/harness/` read is already narrow), and run its git commands against a
fixture repository the self-test builds, so no whole-tree listing or HEAD identity is read. Pair with a drift test that fails when a self-test's key
reads the whole tree's names without a declared reason. Also record why the same self-test takes 272 s on one run and 1443 s on another (host load).
