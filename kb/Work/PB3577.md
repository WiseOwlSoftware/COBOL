# PB3577 - the type-name regexes in impacted_tests.py take `struct` as the name of a `record struct`

## Lead (PB3533 report, new defect 2)

Three patterns in `scripts/spec/impacted_tests.py` scan the type declarations of a changed file with an alternation that lists
`record` before `struct`:

- line 239: `TYPE_DECL_RE`, `(class|record|struct|interface|enum)` then whitespace then the name
- line 326: `\b(?:class|record|struct)\s+([A-Za-z_][A-Za-z0-9_]*)`
- line 336: `TYPE_DECL_RE_ALL`, `(?:class|record|struct|enum|interface)` then whitespace then the name

For `internal readonly record struct PhysicalFileIdentity`, the match is `record` followed by `struct`, so the captured name is
`struct`, not `PhysicalFileIdentity`. The impact map then looks up the wrong type name and tiers the tests of such a type
wrongly. Harm: ORDER only (the gate plans the whole population and leg 2 still runs, PB1708), so a test that should be in
leg 1 can land in leg 2. Same root as the `HostWitnessTraitDriftTests` reader PB3533 fixed (commit 97a867292: it read
`record struct` as a type named `struct`).

### Repro

Run the three patterns over the text `internal readonly record struct X {}`: the captured group is `struct`. A test that pins
it: a changed file declaring only a `record struct` maps to its own name.

## Fix shape (for the implementer)

Accept `record struct` and `record class` as one keyword form (try `record\s+(?:struct|class)` before the bare keywords), in ONE
place that all three sites use (they are three copies of one rule), and share it with the `HostWitnessTraitDriftTests` reader
if that test already holds the corrected form. Add a script self-test for each declaration shape.

**Sites:** `scripts/spec/impacted_tests.py` (lines 239, 326, 336).
