# PB492

## Mechanism — picture-clause-p3
pic-national-edited-gap - category NATIONAL-EDITED has no implementation and its recognition arm additionally omits character-1. PictureAnalyzer.Analyze recognizes `expanded.All(c => c is 'N' or 'B' or '0' or '/')` and calls StagedNotImplemented(Constructs.NationalEdited2002) -> COBOLNET0899 at 2002+ / COBOLNET0900 at 85, so no such item can be defined; and because that predicate does not admit the declared EDITING character-1 letters, GR10's character-1 leg falls through to the ELSE branch and is refused as an INVALID PICTURE with a message that contradicts GR10. Table 7 (editing rule 2) grants national-edited simple insertion, which consequently has no implementation either. This is not owner-declined non-support: no Annex A.4 module and no owner decision covers national-edited (PB260/PB261/PB281-PB283 own other declines), and no kb/Work note owns the Phase-4a national residue at all - it is tracked only inside plan section 0's 14g.5 sub-step ledger, where no work register can rank it.

### Expected, from the standard
ISO/IEC 1989:2023 13.18.40.4 GR10: 'To define an item as national-edited, character-string-1 shall include - at least one symbol N, and - at least one instance of character-1 or one of the symbols from the set B, 0, /.' So both `PIC NNBNN` and `PIC NNTNN EDITING "T" IS N":"` (13.18.40.3 SR9 requires the literal to be a national literal when character-string-1 contains N) define a national-edited item, whose simple insertion editing Table 7 then prescribes and whose positions GR1 makes national character positions.

## Landed — 2026-09-12

Category NATIONAL-EDITED is implemented, and the shape is the one the note asked for: the category became
REAL rather than gaining a second staged arm.

**The category IS `{ Category: National, EditMask: not null }`** — data-model design **D-N6**, exactly the pair
alphanumeric-edited already used, and §8.5.2.1 Table 2 is why that is sound (each edited category shares a CLASS
with its plain one, so only the rules worded in CATEGORIES need to tell them apart). `PictureAnalyzer` returns
`PicInfo(PicCategory.National, Usage.National, Length: expanded.Length)` carrying the mask and the item's
`EditingRules`; `StagedNotImplemented(NationalEdited2002)` and `PicInfo.Recovery` are gone, and so is
`PicInfo.SkeletonGate`, whose only reason to exist was carrying the recovered identity forward to the edition
gate. `VersionConformancePass.PictureConstructId` now reads the category-national picture's own `EditMask`, and
`GateDataItem` takes the FINER of the two answers so a national-edited entry draws ONE COBOLNET0900 at 85 and not
a second one naming `national-data-2002`.

**GR7 and GR10 name the SAME set, word for word, and it is now written down once.** §13.18.40.4 GR7
("at least one symbol 'A' or one symbol 'X', and at least one instance of character-1 or one of the symbols from
the set 'B', '0', '/'") and GR10 ("at least one symbol 'N', and at least one instance of character-1 or one of
the symbols from the set 'B', '0', '/'") differ only in the data symbol. Both arms spelled the set out and the
national copy — `expanded.All(c => c is 'N' or 'B' or '0' or '/')` — left character-1 out, which is why
`PIC NNTNN EDITING "T" IS N":"` was refused as an INVALID PICTURE with a message quoting a Table 10 reading GR10
contradicts. The set is now `CobolEdit.IsEditedCategorySymbol`, DERIVED from §13.18.40.5 rule 3's simple-insertion
set minus the grouping separator (Table 10 admits a ',' only beside the numeric rows), read by BOTH arms, with
`CobolEditSimpleInsertionDriftTests.TheEditedCategorySetIsRule3sMinusTheGroupingSeparator` as the drift test.

**Table 7 gives BOTH edited character categories one type of editing, so ONE renderer serves both.**
`CobolEdit.FormatAlphanumeric` → `CobolEdit.FormatSimpleInsertion`, reached only through
`RuntimeApi.EditFormatSimpleInsertion(value, pic)`, and its data positions are now the COMPLEMENT of the
insertion positions rather than a symbol list — so `N` is a data position without a second arm. The `…Alphanumeric`
NAME was itself the mechanism: every consumer that had grown an edited arm had grown only the alphanumeric half.
`PicInfo.IsCharacterEdited` is the ONE predicate for the rules that do not distinguish the two categories, and
MoveEmitter, AcceptDisplayEmitter and StringEmitter read it;
`CobolEditSimpleInsertionDriftTests.NationalEdited_RendersIdenticallyToAlphanumericEdited` runs the same theory
data through `NN{s}NN` and `XX{s}XX` and asserts the images are equal.

**The Table-10 copies are extracted, which is what the code comment left for this note.** The national and
boolean arms each carried a hand-written row of Table 10; `PictureComposition.Validate` now runs BEFORE the
category arms and answers the ORDER question once (`PIC NN9NN` → COBOLNET1935 naming the offending pair). What
remains in each arm is the CATEGORY-DEFINITION rule the matrix cannot answer, cited correctly at last: GR9/GR10
for the national arm, and GR8 for the boolean one — `PIC 11T EDITING "T" IS ":"` is a GR8 failure, not a Table-10
one, because the matrix is deliberately transparent to a declared character-1.

**Three defects the note did not have, found by the sweep and measured before they were claimed:**

1. **A SILENT REJECTION.** The guard `if (hasE || invalid is not null || (hasN && has1))` returned
   `PicInfo.Recovery` after emitting NOTHING whenever an `E`-bearing picture also held `N` or `1`:
   `01 W-1 PIC NE.` and `01 W-2 PIC 1E.` compiled clean as 2-character items. Both are now COBOLNET1935 from
   the one Table-10 walk.
2. **§13.18.40.3 SR9's literal CLASS was unenforced in BOTH directions** — `DecodeEditLiteral` discarded it one
   layer above the validator, so the analyzer could not ask. `PIC NNTNN EDITING "T" IS ":"` and
   `PIC XXTXX EDITING "T" IS N":"` both bound silently. `EditLiteral(Text, National)` carries the class now and
   ValidateEditing screens both halves — **COBOLNET1955**. This discharges kb/Work **PB533**'s finding F4 and
   closes `SR-13.18.40.3-9`; PB533 stays open on its SR8 half (`char.IsLetter` vs "basic letter").
3. **A WHOLE-WIDTH FILL WENT AROUND THE EDITOR.** `MoveEmitter.ConvertSource`'s two early returns produce the
   §8.3.3.6.4 GR2 fill directly, and §14.9.25.4 GR6 makes editing part of every valid elementary move, so the
   fill must be the edit's SOURCE. The figurative guard excepted only the alphanumeric half (`MOVE SPACE TO
   PIC NN0NN` stored five spaces where the zero must stand) and the ALL-literal guard excepted neither
   (`MOVE ALL "X" TO PIC XX/XX` stored `XXXXX` where the slant must stand) — one rule, two call sites, wrong at
   both. Both now read `PicInfo.IsCharacterEdited` and defer to the ONE edited arm, hoisted above the
   per-category switch so no `case` list can shadow it again.

**Table 16's NATIONAL-EDITED ROW.** §14.9.25.3 Table 16 prints national-edited as a SEPARATE row whose only
"Yes" is the "National, National-edited" column, exactly as alphanumeric-edited is separate from alphanumeric.
`MoveTable16.Refusal` carries that row; the receiving COLUMN pairs the two, so only the ROW reads `IsEdited`.
`INITIALIZE` gained `InitializeCategory.NationalEdited` for §14.9.20.4 GR5c's category-name match (GR6c fills it
with national SPACES, the same as national — but the two categories must not be folded).
