# PB3262 — goldens with a relation of two literals

**Mechanism.** PB1470 decided a relation condition whose operands are both literals is WARNING COBOLNET3146 and evaluates as written (docs/CONFORMANCE.md D-RELLITERAL). Goldens that rely on it prove behavior of a non-conforming program. `85/pb1470_relation_of_two_literals_runs` is the deliberate witness and stays.

**Files (found by PB160 round w1091g, all under `tests/conformance/`).** `2002/da1_alphabet_hex_thru.cob:21`, `85/l1c11_key_native_collating_default.cob:72`, `2002/l1c12_hex_alphanumeric_every_group.cob:75`, `2002/l1c19_native_collating_default.cob:45-64`, `85/nested_special_names_inheritance.cob:42`, `2002/pb101_alphabet_locale_pcs.cob:32-33`, `2023/pb111_class_object_computer.cob:34,78`, `negative/pb1082-pcs-undeclared-alphabet.cob:15`, `85/pb793_code_name_alphabets_85.cob:22-47`, `2023/pb793_code_name_alphabets.cob:66-67`, `2023/pb60_nested_configuration_inheritance.cob:66`.

**Fix.** Make one operand a data item holding the literal, keeping each golden's expected output. Then a drift test (the conformance corpus runner counting COBOLNET3146 as a failure for every case except the PB1470 witness) keeps the corpus clean. Repro: compile any listed file and read COBOLNET3146.

**Open question.** The clause number (§8.8.4.2.1, rule 13) is inherited from PB1470 and the lead; `cite.py --check 8.8.4.2.1` with a quoted text was not re-derived by the clerk. The implementer runs it before editing any comment.
