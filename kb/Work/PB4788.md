# PB4788 - a screen entry's slot names no missing period before a section keyword: SCREEN SECTION then 01 LINKAGE SECTION draws COBOL5506, not COBOL0307

**What the report says (the reviewer's words).** A screen entry's slot names no missing period before a section keyword. Flags: misleads_diagnosis, MINOR. Repro: `SCREEN SECTION.` then `01 LINKAGE SECTION.` draws COBOL5506 "The word LINKAGE is not expected here". Truthful and one report, but not COBOL0307. Site: `src/WiseOwl.Cobol.Frontend/Cst/ClosedFormats.cs:182` (`ClosedFormats.EntryAwaitingItsName`, data description entry only); the failing prediction is at the section's entry loop, so no entry context exists. Same family as PB4706, not fixed because the slot test would need a walk-based form.

**R1.** No open note covers it (grep of kb/Work for the member name and key phrase).

**Sites.** `src/WiseOwl.Cobol.Frontend/Cst/ClosedFormats.cs#ClosedFormats.EntryAwaitingItsName` (line 182).

## Landed (wave 20261882 group B)

Re-probed on a fresh build: `SCREEN SECTION.` then `01 LINKAGE SECTION.` drew COBOL5506 listing every clause of the screen entry as expected; the same in a REPORT SECTION RD (`01 LINKAGE SECTION.`) and after a complete screen entry's dangling `01`. `01 PROCEDURE DIVISION.` already drew COBOL0307.

**The note's expectation was half right.** The slot was unrecognized at every entry that is not a data description entry, because a section's entry loop fails its prediction at the header word with the parser still before the level-number, so `ClosedFormats.EntryAwaitingItsName` (which reads the parser's context) found no entry. But COBOL0307 is wrong for THIS repro: ISO 13.2.1 prints LINKAGE SECTION before the REPORT and SCREEN SECTIONs, so no period lets it follow, and PB4706 settled that an out-of-order header after a dangling level-number is the plain COBOL0001 (`01 FILE SECTION.` in WORKING-STORAGE). The fix gives the screen, report-group and constant slots the data slot's behaviour: the same COBOL0001 (`cannot parse construct near 'LINKAGE'`), and COBOL0307 where the header may follow.

Fix shape: `ClosedFormats.EntryAwaitingItsName` covers the four `level-number [name]` entries (`NamelessEntry`), `ClosedFormats.LevelNumberEntryRules` is the one list of their rule names (held to the grammar by `ClosedFormatDriftTests.TheEntriesThatBeginWithALevelNumber_AreTheClosedFormatsLevelNumberEntryList`), `OffendingPosition.FollowsALevelNumber` reads the slot from the walk where no entry context exists, and hint 0i stands down at a slot that yields. Sibling noticed, not fixed (a different mechanism): a report-group `01 SCREEN SECTION.` takes SCREEN as the entry's name (a free cobolWord there), so the 0307 stands at SECTION, not SCREEN.

Goldens: `conformance-suite/cases/13.9-Screen-section/pb4788-header-out-of-order-after-a-screen-entrys-level-number`. Unit: `ClosedFormatReservedWordTests.AnOutOfOrderHeaderAfterADanglingLevelNumber_IsNoKindExpected`. Design: `DESIGN-frontend-grammar.md`, "The slot at every level-number entry".

**Sites (as landed):** `src/WiseOwl.Cobol.Frontend/Cst/ClosedFormats.cs` (`ClosedFormats.EntryAwaitingItsName`, `ClosedFormats.NamelessEntry`, `ClosedFormats.LevelNumberEntryRules`), `src/WiseOwl.Cobol.Frontend/Parsing/CobolErrorStrategy.cs` (`OffendingPosition.FollowsALevelNumber`, `OffendingPosition.OwnerName`, `CobolErrorStrategy.GuessCobolIntent` hint 0i).
