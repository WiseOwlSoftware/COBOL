# PB6205 - OPEN - the loop's review lane double-reviews hand dispatches, and its review is too shallow

**Observed 2026-11-23.** The attended session hand-dispatched two implementers whose reports carried fix-lane names
(`w20262160a-PB6144-report.md`, `w20262160b-PB6131-report.md`). The loop's review lane picked both up on DONE, stamped CLEAN in
about 42 s each, and its landing lane landed them (#2048, #2049), while the session's own reviewers ran in parallel. That
reviewed each branch twice, and the deeper review then found a medium finding (PB6131 R1-1, the crosswalk accepted a basis other
than `mechanical` or `adjudicated: <reason>`) on a tip that had already landed; it took a follow-up branch (#2055).

**Two defects.**
1. The lanes key on the report name and DONE status, not on whether another reviewer already owns the branch. There is no
   claim a dispatcher can set ("reviewer: attended") that the lane honours; today the only workaround is a report name the lanes
   skip (`HOLD-...`).
2. A 42-s review of a branch that changed a crosswalk's acceptance rule did not exercise the rule's negative case. A review that
   finishes faster than it can run the changed tests is evidence it did not read the change.

**Fix shape.** (1) A review claim in the dispatch ledger (`dispatch_ledger.record_dispatch` with the reviewer's owner) that
`review_lane` and `land_lane` honour; (2) a floor on the branch review: it must name, for each changed rule, the negative case it
ran or read, and `review_findings.py stamp` refuses a CLEAN stamp without them.
