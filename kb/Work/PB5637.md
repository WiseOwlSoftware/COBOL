# PB5637 - the MCS device arm has no fault-injection seam

**Sites:**
- `src/WiseOwl.Cobol.Runtime/Communication/McsStore.cs:240` (`McsStore.Transmit`, `McsStore.CutDevice`, `McsStore.CutBack`)
- `src/WiseOwl.Cobol.Runtime/IO/IHostMedium.cs` (`IHostMedium`: the existing seam the message store's page file goes through)
- `tests/WiseOwl.Cobol.Tests.Unit/McsStoreCrashMatrixTests.cs` (whole: the matrix that gets the device arm)

**Gap.** The message store's page file reaches the host through `IHostMedium`, so `McsStoreCrashMatrixTests` refuses or
kills each of its writes and syncs in turn. The device files do not: `Transmit` opens the device with
`FileOptions.WriteThrough` (kb/Work PB5147), `CutDevice` calls `File.OpenHandle` (line 219), and `CutBack` deletes a device
it created, all straight on the host. So a refused or dying device write, a refused sync of a created device's directory
(`HostFile.SyncDirectory`, the new abnormal arm of PB5147: an IOException becoming a 92 refusal with `CutBack`), and a
refused cut have no injected-fault test. PB5147 covered the arm by the 192 related unit tests and the CM CCVS tests, which
never fail a device operation. kb/Work PB4864 (open) is the related gap in the page-file matrix's own assertions.

**Fix direction.** Route the device open, write, set-length, directory sync and delete through an `IHostMedium`-style
device seam (a redesign of the device half of `McsStore`, not a flag), then extend the crash matrix to the device ops and
pin that a refusal at each yields the documented status and leaves no delivered output cut or duplicated.
