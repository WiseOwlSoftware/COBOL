# PB5786 - a contained program's own file-name does not hide its container's GLOBAL data-name of the same word, and the reverse (every edition)

**What is wrong.** A contained program's own file-name does not hide its container's GLOBAL data-name of the same word (and the reverse): `MOVE "LOCL" TO FX` in the contained program, where FX is its file, changes the container's item. Program B declares `FD FX`; its container A declares `01 FX GLOBAL`. GR1's set is every name defined in B plus the containers' global names; X.1.3.8 says a reference "even when it is a different type of user-defined word" is to B's own object, and GR3a makes B's declaration the referenced object. So `MOVE "LOCL" TO FX` in B names B's file and must be refused; the compiler writes A's data item. The reverse (B's `01 GX` data item, A's `FD GX GLOBAL`) lets B's `OPEN OUTPUT GX` open A's file. Same at 2023 (`§2023:8.4.6.1` has the same sentence), cause (b). The two rows are one mechanism: rule 1's set and rule 3a's ranking are both applied per class. The Mythos lane ran `xfile.cob` at `--std 85`: it printed `A FX=LOCL`.

**Sites:**
- `src/WiseOwl.Cobol.Compiler/Binding/Model/SymbolTable.cs#NearestDeclaringData` (hid the tier only for a nearer report entry or condition-name, not a nearer file-name; now also asks `NearerFileNameHides`)
- `src/WiseOwl.Cobol.Compiler/Binding/DataBinder.NonDataNames.cs#NearerFileNameHides` (new; `SymbolTable.NearestDeclaringData` asks it)
- `src/WiseOwl.Cobol.Compiler/Binding/InheritedGlobals.cs#DropShadowed` (now also drops an inherited GLOBAL file a nearer data-, condition- or index-name hides)

**Expected at `--std 85`:** both refused: B's FX is a file-name, not a MOVE receiver; B's GX is a data-name, not an OPEN operand (`§1985:X.1.3.8`, `X.1.3.8.2 GR1`, `GR3a`).
**Observed at `--std 85`** (exit 0): `xfile.cob` prints `A FX=LOCL`; `ydata.cob` prints `A GXR=WROT` (B's `OPEN OUTPUT GX` opened A's file). Both compile and run against the container's object.
**At `--std 2023`** (exit 0): the same, `A FX=LOCL` and `A GXR=WROT`.

**Leads.** Lead nobody has checked (the refuter's sweep, not probed): an own index-name or report-name against a container's GLOBAL data-name or file-name. The file-name lookup through `DataBindState#VisibleFiles` and `InheritedGlobals` has no nearer-data-name test (the checker's site reading). Existing note: none; PB4219 (landed) covers only the APPLY COMMIT / I-O-CONTROL arm.
