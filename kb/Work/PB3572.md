# PB3572

## Scenario

Review of PB3540 (PR #431), lead R1-1 (low, from `E:\COBOL-coord\scratch\reports\w1157b-PB3540-report.md`).

`conformance-suite/cases/14.9.7-COMMIT/pb3540_commit_under_factory_method_unchecked.cob` (line 14) expects a COMMIT under a
factory method, checking off, to be not executed. The golden's comment rests that on "docs/CONFORMANCE.md A.4.3: a forbidden
statement with checking off is not executed", but A.4.3 never states that disposition. ISO §14.6.13.1.3 rule 8 (cite
`--check` OK: "If checking for the exception condition is not enabled, the implementor defines whether or not execution will
continue") makes it implementor-defined, and DOC-A.1-70 says other fatal conditions' dispositions are documented with their
statements. So the unchecked choice for EC-FLOW-COMMIT and EC-FLOW-ROLLBACK is undocumented. The pointer is inherited from the
`pb3544_item8_rollback_under_recursive_element_unchecked` golden and `TransactionControlTests` (pre-existing).

## Fix shape

State the determination in docs/CONFORMANCE.md A.4.3 (a COMMIT or ROLLBACK that EC-FLOW-COMMIT or EC-FLOW-ROLLBACK forbids, with checking off, is not executed;
the run unit continues), then check that every golden and test comment that cites A.4.3 for it resolves. Sweep the sibling
fatal conditions for the same missing per-statement disposition.
