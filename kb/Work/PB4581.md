# PB4581 — the cache searches read a field the cache does not have

**Sites:** `E:/COBOL-coord/scratch/fuzz-vet/step1/p/dupscan.py`, `E:/COBOL-coord/scratch/fuzz-vet/step1/p/sfgrep.py` and `E:/COBOL-coord/scratch/fuzz-vet/step1/p/sfshow.py` (step 1's probes, outside the repository); no tracked script reads the cache at all (`git grep` for `sf-tickets` and `discussion_thread` under `scripts/`, `.claude/` and `tools/` finds nothing), so the searcher the triage needs does not exist in the tree.

**Observed.** The cache (`E:/COBOL-coord/scratch/sf-tickets`, one JSON per ticket, README there) holds the posts of a ticket as the top-level list `posts` (strings), next to `summary`, `description`, `status`, `labels` and `milestone`. `sfgrep.py` reads `(t.get('discussion_thread') or {}).get('posts', [])` and `sfshow.py` reads `t.get('discussion_thread')`, a key no ticket has, and `dupscan.py` matches `summary+description` only. The silent failure: a search of a ticket's discussion returns nothing and reads as "no ticket", with no error. The vetting, searching `posts` itself, found what step 1 had missed: bugs #47 (closed, reopened in a late post for exactly PB4560's case, from #138's posts), bugs #996 for PB4519 (PB3885 already cited it), the note in bugs #480 ("the VARYING clause is syntactically accepted but then completely ignored") for PB4550, and the maintainer remark in bugs #806 for PB4521.

**Fix shape.** One tracked searcher in `scripts/` (named for the cache, with a self-test over a two-ticket fixture that has a hit only in `posts`), reading `summary`, `description` and every string of `posts`, used by `fuzz_triage.py` (PB4580) and by the adjudicator and refuter briefs instead of ad hoc probes; it fails loudly when a ticket has neither a `posts` list nor a `description`, so a schema change cannot return an empty result.
