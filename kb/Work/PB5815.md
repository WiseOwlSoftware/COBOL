# PB5815 - a file written with ADVANCING or LINAGE is opened INPUT or I-O with status 00 and read as fixed blocks: wrong records, no AT END, REWRITE over a line end (every edition)

**What is wrong.** A record sequential file written with any ADVANCING phrase, or described with LINAGE, carries print controls in its stream. OPEN INPUT and OPEN I-O of it give status 00, and READ and REWRITE then treat the stream as fixed records: records that were never written come back, a READ past the last record returns 00 with no AT END, and REWRITE overwrites a line end. The output is identical at `--std 2023` (cause (b)). The ruling: UPHELD (b). Harm: wrong_answer, silent (status 00 on records never placed; REWRITE corrupts the file). The checker's confidence: high.

**Why the 1985 text does not allow it.** ADVANCING is allowed on any sequential WRITE, and a WRITE without it is advanced as if AFTER ADVANCING 1 LINE (`§1985:VII.4.7.4 GR16`); OPEN I-O of a LINAGE file is not barred (`§1985:VII.4.3.3 SR3` bars only EXTEND). 1985 identifies a sequential record by the predecessor-successor relationship set when it was placed (`§1985:VII.2.6.3 GR2`). It requires OPEN I-O to reference a file that supports I-O operations (`§1985:VII.4.3.4 GR17`), and it gives status 37 when the file does not support the open mode (`§1985:VII.1.3.5`). An implementor may refuse such a file at OPEN; it may not deliver records that were never placed. `docs/conformance/7/DOC-A.1-146.md` (c') does not cover reading such a file back.

**What happens.** The compiler writes the print controls into the record stream (DOC-A.1-146 (c'), `SequentialConnector.IsRecordPrintStream` and `SelectLineEnd`); OPEN INPUT and OPEN I-O then succeed with 00 and READ takes fixed-width blocks. Two records were placed in `prta.dat`; three READs return `\n\nA`, `01\n` and a third record with 00, and never AT END. On the LINAGE file, OPEN I-O gives 00, READ returns `\r\nLIN0`, and REWRITE overwrites the first line end and half of record 1 (the file is now `REW00101\r\nLIN002\r\n`).

**Sites:**
- `src/WiseOwl.Cobol.Runtime/IO/SequentialConnector.cs#IsRecordPrintStream` (writes the stream with print controls)
- `src/WiseOwl.Cobol.Runtime/IO/SequentialConnector.cs#SelectLineEnd` (the line end it writes)
- `src/WiseOwl.Cobol.Runtime/IO/SequentialConnector.cs#ReadRecord` (reads the stream as fixed records with no test of its shape; the OPEN INPUT and I-O arms are the same: the checker names them without a member)
- `src/WiseOwl.Cobol.Runtime/IO/FileConnector.cs#Open` and `#SupportsReadOperations` (the fix: the OPEN contract asks once whether the file supports read operations; INPUT and I-O are 37)
- `src/WiseOwl.Cobol.Runtime/IO/SequentialConnector.cs#IsRecordSequentialPrintFile`, `#SupportsReadOperations`, `#NoticeIfLayoutDisagrees` (the fix)
