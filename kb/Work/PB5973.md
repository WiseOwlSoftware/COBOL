# PB5973 - cross-program name hiding is decided by spelling per class, not by §1985:X.1.3.8.2's set-and-qualification rule

## The requirement
§1985:X.1.3.8: when identically named objects exist, "a program's reference to such a name, even when it is a different type of
user-defined word, is to the object which that program describes rather than to the object, possessing the same name,
described in another program". §1985:X.1.3.8.2 GR1: the set is every name program B declares plus every GLOBAL name of A and
of the programs containing A, and "the normal rules for qualification and any other rules for uniqueness of reference are
applied until one or more objects is identified". GR2: "If only one object is identified, it is the referenced object." GR3a:
when more than one is, "If the name is declared in program B, the object in program B is the referenced object."

## What the compiler does (each at `--std 85`, re-run 2026-11-20 on a compiler built at 832bc39c61; the refuter saw `--std 2023` behave the same)
1. **WRONG ANSWER (§1985:X.1.3.8, GR3a).** xrpt1.cob: the container declares `RD R1 GLOBAL`; the contained program declares
   `01 R1 PIC X` and executes `INITIATE R1 / GENERATE DET / TERMINATE R1`. Exit 0, and the container's report is written. R1 in
   the contained program names its own data item, so INITIATE R1 must be refused. xrpt2.cob, the converse: the container
   declares `01 XR PIC X GLOBAL`, the contained program its own `RD XR`; `MOVE 'B' TO XR` compiles, runs and changes the
   CONTAINER's item (prints `O XR=B`). Control: the data-name/file-name pair is right (xfile1.cob is refused COBOL1639;
   kb/Work PB5786).
2. **REJECTS LEGAL SOURCE (GR1, GR2).** one1.cob: the container declares `FD FA GLOBAL` with `01 FREC. 05 FX`; the contained
   program declares its own `FD FA` (record BREC) and writes `MOVE 'QQQ' TO FX OF FREC OF FA`. Over GR1's set only the
   container's FX lies under a FREC under an FA, so by GR2 it is the referenced object; the compiler refuses it COBOL1639
   ("'FX' is declared, but not under the given qualifiers (FREC OF FA)"). In the same program `X OF G` and `C OF CV`, whose
   qualifiers the contained program also declares, DO reach the container's objects: the two qualifier arms disagree.
3. **REJECTS LEGAL SOURCE (GR1).** scope2.cob: a container GLOBAL report's sum counter TOT, referenced `TOT OF CFG` in a
   contained program that declares a data-name TOT, is refused COBOL5092 citing §2023:13.8.6.2.3, a 2023 clause, at `--std 85`.

## The mechanism (one, in three name classes)
Hiding is decided at inheritance, per class, by spelling, before qualification:
- `SymbolTable.Reports.cs#InheritReport` hides an inherited report only when `_visibleReports` already holds the spelling (an
  own REPORT), never for an own data-, condition- or file-name; and it skips an inherited sum counter whenever the program's
  own `_dataNames` holds the spelling.
- `SymbolTable.cs#NearestDeclaringData` consults `NearerEntryHides`, `NearerConditionNameHides` and `NearerFileNameHides`, but
  no nearer report-name.
- `SymbolTable.Files.cs#FileQualifies` resolves a qualifier with `FileNamed(..., NameReach.Visible)` after `HideShadowedFiles`
  has already dropped the container's FA, so a hidden GLOBAL file-name cannot qualify.
None has an edition switch. GR1-GR3 are one algorithm over one name set; the compiler implements it as per-class pre-filters,
so every class pair must be remembered by hand (PB5786 added the file/data pair and left report-name and index-name against a
container's GLOBAL names as unprobed leads).

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/SymbolTable/SymbolTable.Reports.cs:88` (`SymbolTable.InheritReport`), `src/WiseOwl.Cobol.Compiler/Binding/SymbolTable/SymbolTable.cs:126` (`SymbolTable.NearestDeclaringData`), `src/WiseOwl.Cobol.Compiler/Binding/SymbolTable/SymbolTable.Files.cs:156` (`SymbolTable.FileQualifies`, `SymbolTable.HideShadowedFiles`)

## Fix shape (CLAUDE.md rule 5: the shape that makes the next class automatic)
Resolve a reference in program B over GR1's set (B's own condition-, data-, file-, record- and report-names and sum counters,
plus the containers' GLOBAL ones), apply qualification over that whole set, then GR2/GR3 by declaring depth: one resolver and
no per-class hide lists, so a new class pair needs no code. Witness it with a matrix at `--std 85`: every ordered pair of
{condition, data, file, record, report, sum counter} as an own name against a container GLOBAL name, referenced unqualified and
qualified, each expected outcome derived from GR1-GR3. The programs above are its first rows.
