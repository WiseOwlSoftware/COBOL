# PB4752 - a sum leaving the Int128 lane ends the run unit

**New defect 3 (report).** A sum of two 16-byte-container operands (bound 39) still ends at the Int128 lane (a documented size
error, DOC-A.1-179 (1)) while a product and a wide sum of the same operands are exact. The report calls it a documentation
question for the owner, not a defect of the branch.

**R2-3 (report, low).** PB4729's fix (R1-7 of that branch) takes the exact additive only when both operand bounds are known and
within 38 digits, so a sum whose alignment leaves the lane still ends the run unit when one operand has an unknown bound (an
intrinsic's value) or is a 16-byte container. The comment's stated test is the alignment; these two cases are in neither the fix
nor the report's New defect 3, which names only two 16-byte operands at the top of the lane.

**R1.** No open note covers it. PB4729 (landed) is the fix for the case where both bounds are known and within 38 digits.

**Sites:** `src/WiseOwl.Cobol.Compiler/CodeGen/Emit/NumericRenderer.cs#CombineAdditive`.
