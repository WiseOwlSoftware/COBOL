# PB3157 — `enqueue.py land` does not exclude a second run of the same branch

**Sites:** `scripts/orchestrator/enqueue.py` (`land`: the NOTHING TO LAND tests; `self_test`).

> ⚙ **flags:** process-only

Filed by the clerk from `E:\COBOL-coord\scratch\leads-enqueue-2026-10-14.md` item 1 (evidence log `E:\tmp\land-pb3155.log`,
both runs wrote into it, interleaved). Related: PB3023 (the one landing script), PB3103 (landing lane). Not PB3104
(landed; the Linux gate outside the gate slot).

**Mechanism.** `scripts/orchestrator/enqueue.py` (`land`) keeps no per-branch exclusion, so two runs of one branch proceed
side by side. The landing lane guards its own attempts with a running record (pid); a hand or agent launch of
`enqueue.py land` has no such guard.

**Evidence, 2026-10-14.** The clerk for notes-PB3155-gate-leads launched `enqueue.py land notes-PB3155-gate-leads --lane
clerk` in the background, believed the launch had died (its log was empty at first, the gate prints nothing for minutes)
and launched it again. Run A gated c5838f3ba, stamped DEVLOG 2024 (a18478035), opened PR #58 and ended
`=== ENQUEUE: ENQUEUED`. Run B then ran a SECOND Windows leg-1 gate (run 20261014T111114Z-6a687f, slot 2 of 3, about 7.5
minutes) and a second Linux gate on the stamped head a18478035 for a docs-only change.

**Harm.** A duplicated gate holds one of the 3 shared gate slots. Worse if the two runs race to the stamp: two
`alloc.py devlog` numbers for one entry.

**Sibling.** Run B ended `=== ENQUEUE: NO ENTRY — the branch adds no single stamped DEVLOG entry` (exit 6) after PR #58 had
merged at 11:22:15Z. A re-run on a branch that is already queued or merged should end ENQUEUED or NOTHING TO LAND, never
a DEVLOG refusal (exit 6), or the lane misclassifies it as STOPPED.

## Recurrence, 2026-10-17

2026-10-17 ~20:25 PDT: the clerk for `notes-pb3357-ledger-dates-20261017` launched `enqueue.py land ... --lane clerk` twice;
the second launch overwrote the first run's log. Run A queued PR #207 (merged 03:27:59Z, DEVLOG 2173, 13a99f38a). Run B, on
the merged branch, ended `=== ENQUEUE: NO ENTRY — the branch adds no single stamped DEVLOG entry to title its pull request`
(exit 6). Code site: `scripts/orchestrator/enqueue.py`, function `land` (line 502, verified on a0a2ff24f) tests only
`HEAD == origin/main` for NOTHING TO LAND; a branch the queue already merged has HEAD an ANCESTOR of origin/main
(`git merge-base --is-ancestor HEAD origin/main`), falls through to merge/gate/stamp and ends exit 6 at line 546 (same function).

## Landed (wave 20261107 group D)

**Re-probe, two halves.** (1) Two runs of ONE branch side by side: already fixed by PB3310's land lock (`land_lock_path`, `LAND_LOCK_NAME`, exit 13 `REFUSED — another land of <branch> runs`), which `enqueue.py --self-test` drives ("another land of fix runs (enqueue.py land fix (pid 4242"); the note's 2026-10-14 evidence predates it (landed 2026-10-16). Nothing to add for the concurrency half. (2) The re-run on a merged branch: reproduced in the new self-test arm. `land` tested only `HEAD == origin/main` for NOTHING TO LAND; a branch the queue merged (a merge commit with the branch tip as a parent) has HEAD an ANCESTOR of origin/main, fell through to the queue guard, the merge, the stamp and `pull_request_text`, and ended exit 6 NO ENTRY.

**Fix.** `land` now ends exit 0 `NOTHING TO LAND — the branch's tip is already on origin/main (its pull request merged)` when `git merge-base --is-ancestor HEAD origin/main` holds (after the fetch, before the queue guard), so nothing is gated, stamped or queued and the lane reads DONE, never a DEVLOG refusal. Self-test arm: a branch merged into main with `--no-ff` and pushed; the run is exit 0, no gate, no stamp, no `gh` call.
