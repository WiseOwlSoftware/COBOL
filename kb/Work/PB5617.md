# PB5617 - at --std 2002 an implicitly described CD field (TEXT LENGTH and the other CD-entry fields) carries no PICTURE, so passing it BY REFERENCE or RETURNING into a PIC 9(4) item is refused COBOL0828

**Sites:**
- `src/WiseOwl.Cobol.Compiler/Binding/CommunicationSectionBinder.cs#AddSlot`

**Mechanism.** CommunicationSectionBinder.AddSlot builds each implicit CD field as a bare PicInfo (category, usage, length, digits) with no picture character-string. The argument/formal conformance test (same PICTURE, USAGE, SIGN ...) then sees 'USAGE DISPLAY' against 'PICTURE 9(4) USAGE DISPLAY' and refuses. 2002 says the implicit description is equivalent to '02 data-name-2 PICTURE 9(4)'. A CD record item with a written PIC 9(4) passes.

**Inventory.** Rows claimed: `2002-SR-14.8.22.2-14`, `2002-GR-14.8.22.3-3`, `2002-GR-14.8.22.3-8`.
