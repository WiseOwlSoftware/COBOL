## Finding — `data-description-and-representation` (wrong-answer; rows `GR-8.5.4-5`)

**Mechanism.** READ/RETURN INTO over a FORMAT 3 (RECORD CONTAINS m TO n) file whose current record is zero-length never takes §14.9.25.4 GR1's zero-length-item substitution: MoveBinder.BindIntoPhrase wraps every file carrying a VaryingRecordInfo (Format 2 AND Format 3) in BoundCurrentRecord, and MoveClassifier.ZeroLengthItemRoute matches only BoundFieldOperand, so no current-length test is emitted and the zero-length record is stored as an empty alphanumeric slice (no SPACE substitution, no editing). The route's doc-comment reasons §8.5.4 item 5 away as a 'VARIABLE-LENGTH group' that cannot reach an elementary receiver, but a variable-length RECORD is not a §8.5.1.12 variable-length group, and the INTO phrase is precisely where it reaches one. Format 2 (RECORD IS VARYING) is unaffected because §14.9.30.4 GR4 b) / §14.9.34.4 GR5 b) designate that implied move an alphanumeric group move.

**Repro.** FD F RECORD CONTAINS 0 TO 10 CHARACTERS. 01 FR0. 05 FR0E PIC X OCCURS 0 TO 10 DEPENDING ON K.  WS: 01 K PIC 99 VALUE 0. 01 WE PIC XX/XX VALUE "ABCDE".  OPEN OUTPUT F, WRITE FR0, CLOSE F, OPEN INPUT F, READ F INTO WE, DISPLAY "[" WE "]", then MOVE "ABCDE" TO WE, MOVE FR0 TO WE, DISPLAY again. (scratch: out/probe/ddr/p9.cob, pinned cobol.exe --std 2023)

**Expected from the spec.** §8.5.4 item 5 makes a fixed-or-variable-length-format logical record of zero character positions a zero-length item; §14.9.25.4 GR1 'If identifier-1 is a zero-length item, it is as if literal-1 were specified as a zero-length literal'; GR2 treats it as figurative SPACE (receiver is not dynamic-length); a Format 3 file's implied move is classified normally (no GR4 b) group designation), so SPACE is edited into PIC XX/XX: READ F INTO WE -> [  /  ], identical to MOVE FR0 TO WE.

**Observed / reasoning.** READ F INTO WE -> [     ] (five spaces, insertion '/' lost); MOVE FR0 TO WE in the same program -> [  /  ]. One record, two answers.

**Code site.** src/Cobol.Net.Compiler/Binding/Procedure/Verbs/MoveBinder.cs#BindIntoPhrase; src/Cobol.Net.Compiler/Binding/Bound/MoveClassifier.cs#ZeroLengthItemRoute (source is BoundFieldOperand only; doc-comment's item-5 reachability argument); src/Cobol.Net.Compiler/Binding/Bound/BoundTree.cs#BoundCurrentRecord

## What the fixer owes

Give ZeroLengthItemRoute an arm for BoundCurrentRecord (current length test on the record), or classify the INTO source by its minimum length rather than by node type; sweep WRITE FROM / REWRITE FROM / RELEASE FROM.
