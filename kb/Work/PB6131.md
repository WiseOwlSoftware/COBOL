# PB6131 - a crosswalk rebuild silently destroys adjudicated entries

**Repro.** `python conformance-suite/harness/crosswalk.py --build` on `tests/nist/crosswalk/NC115A.json`: 22 units change from `rows` to
`open`/mechanical. The builder does not preserve `basis: adjudicated`; `--check` exempts adjudicated entries, so it stays silent. The PB6110
implementer found it by running `--build`, and restored NC115A from main. Not fixed there (outside PB6110's mechanism).

**Fix.** Decide how an adjudication survives a rebuild (merge by unit key and keep the adjudicated entry, or refuse to overwrite one), and add
a selftest that rebuilds an adjudicated fixture. PB4696 (the crosswalk slice) and its 2026-11-22 residue file are related.

**Second observation, same tool class.** The PB6110 first gate was RED at LINE ENDINGS: Python `open(..., 'w')` wrote CRLF into two files on
Windows (fixed there with `scripts/line_endings.py --fix`). Which writer is not named in the report; check the `--build` path's file writes
for `newline="\n"`.

**Decision (2026-11-23, the implementer's, under the codebase ownership of CLAUDE.md).** An adjudication is a decision, and
a rebuild never decides. Any entry whose `basis` is not `mechanical` is ADJUDICATED (design §6.3). `--build` merges each
program's file by unit name (`crosswalk.merge`): every adjudicated entry is written back verbatim in its unit's place, and
every other unit gets the fresh mechanical map. It REPORTS, never silently, each kept adjudication whose recorded program
facts (lines, FEATURE, ANSI-REFERENCE, flag: the facts it was decided on) the program now contradicts, and each whose unit
the program no longer has (kept after the program's units, so the decision is not lost). Either makes the build's verdict
`BUILD RED` (exit 1), and the entry is re-adjudicated by hand. A unit adjudicated twice stops the build before any file is
written. A change in the MECHANICAL disposition under an adjudication is not a conflict: overriding it is what the
adjudication is for. `--check` runs the same merge (`rebuild_problems`) and refuses a file in which a rebuild would change an
adjudicated entry, so the build and the audit cannot drift apart. The stale-fact case is `audit_unit`'s existing fact check,
now the one function `fact_problems` that both paths use. Rejected: refusing to overwrite (a rebuild of every other unit
would then need a hand step), and storing a copy of the overridden mechanical result (it changes every adjudicated entry
for no decision).

**Landed.** Repro measured first: the builder on origin/main ddf3400a61 replaces all 11 of NC115A's adjudicated entries
with `open`/`ambiguous` mechanical ones (the filing's "22 units" counted each twice). After the fix,
`python conformance-suite/harness/crosswalk.py --build` prints `=== CROSSWALK 85: BUILD GREEN: wrote 459 file(s) to
tests/nist/crosswalk, 11 adjudicated entries kept verbatim, 0 conflict(s) ===` and `git status tests/nist/crosswalk` is
empty; `--check` prints `=== CROSSWALK 85: GREEN: 0 problem(s) over 459 programs ===`. Self-test cases 18-21 of
`conformance-suite/harness/selftests/crosswalk/test_crosswalk.py` (21 cases, 69 expectations, PASS): a rebuild keeps an
adjudicated fixture verbatim and rebuilds the mechanical entry; a stale fact and a vanished unit are each reported and
kept; a unit adjudicated twice fails loudly and writes nothing; the audit names a file that a dropping merge would change;
the written file is LF.

**Line endings.** The `--build` path writes through one function, `crosswalk.write_file`, as UTF-8 bytes (`write_bytes`),
which no newline translation reaches, so it was already LF before this change: 0 of the 459 files carry CRLF after the
rebuild. The PB6110 CRLF came from that implementer's own ad-hoc `open(..., 'w')` scripts, not from the harness. Sweep of
`conformance-suite/` (an AST pass over every `.py` for `write_text` without `newline=` and for a text-mode `open` for
writing without `newline=`): zero sites. The byte writers (`crosswalk.py`, `obligations.py:217`, `run.py:600`, the
crosswalk self-test) encode their own LF. Nothing to fix there.
