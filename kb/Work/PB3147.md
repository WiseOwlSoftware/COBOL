# PB3147 — --std 85 does not enforce area-A placement of paragraph headers

> flags: under-rejects (--std 85 only)

Source: `E:/COBOL-coord/scratch/reports/w1069g-PB2720-report.md`, "New defects (note-ready)" item 1 (branch `worktree-wf_d63f7207-db5-30`, which fixed PB2720 and PB374).

**What was seen.** At `--std 85` a paragraph header written `           P1.` (starts in column 12, area B) compiles. The report found no reference-format check anywhere in the compiler and calls the fix "family-sized" (area A also governs division, section and paragraph headers and level 01/77 items, so the check is a family, not one construct).

**Context.** `kb/Work/PB2720.md`'s "Target" paragraph: "the X3.23-1985 area-A placement, if enforced, is a reference-format rule screened by name in the edition pass at --std 85 rather than a parse predicate". PB2720 removed the `{IsAtLineStart()}?` predicate from `paragraphName` (ISO 2002+ has no area A); this note carries the 1985 half that PB2720 left open.

**Spec.** None cited: the X3.23-1985 reference format is not in `specs/ISO_COBOL.md`. GAP: the implementer must find the governing source for the 1985 rule (see `docs/VERSION_CHANGE_REFERENCE.md`) before implementing.

**Code site.** No reference-format check exists; per PB2720 it belongs in the edition pass, not in `CobolParserCore.g4`. Repro: a one-paragraph program with the header `           P1.` in column 12, compiled with `--std 85`.

## Landing (w1078f, 2026-10-14)

**Re-probed** on the worktree build at c29af1704: `E:/COBOL-coord/scratch/w1078f/probe/p1.cob` (paragraph header
`P1.` in column 12) compiled and ran at `--std 85` (A, B); `q1.cob` (PROGRAM-ID, AUTHOR, CONFIGURATION SECTION,
SOURCE-COMPUTER, FILE-CONTROL, FD, WORKING-STORAGE SECTION, 77, DECLARATIVES, END DECLARATIVES, END PROGRAM in area B;
SELECT, PIC, USE, TO in area A; a section header mid-line) compiled clean. GnuCOBOL 3.2 at `-std=cobol85`
(`areacheck: yes` in `cobol85.conf`, `no` in `cobol2002.conf`) refuses the headers, FD, 01, 77, DECLARATIVES, END
DECLARATIVES and END PROGRAM outside area A and a statement in area A.

**Rule.** ISO 2023 has no areas: §6.3.1 "The program-text area begins in character position 8 and terminates with the
character position immediately to the left of margin R" (`cite.py --check` OK §6.3.1), §6.3.5 continues an entry "by
starting subsequent COBOL words, literals, or picture character-strings in the program-text area of a subsequent line"
(OK §6.3.5). The X3.23-1985 rule is DERIVED (VCR Table 7 row 7.35): an area-A item begins its line in area A, every
other line's first text in area B, a level-number other than 01/77 in either. ⚠ DETERMINATION: the area-B arm covers
every line's first text (a continued clause, USE, a period), and identification / environment paragraph headers are
area-A items — wider than GnuCOBOL's check, which asks neither; measured safe on the 459 NIST programs (no new
failure; NC113M exercises positions 8–11).

**Fix.** The reference format records, the pass asks. `FixedFormLine.AreaAWidth` / `ProgramTextStart` /
`BeginsInAreaA` is the one definition of area A (the comment-entry `FirstAreaAWord` now reads it;
`ReferenceFormatProcessor.AreaAWidth` deleted); `ReferenceFormatMap.PlacementAt(line, column)` keeps where each
fixed-form physical line's program text begins (physical column through `PhysicalLine.ColumnOf`, which `TextSite.Col`
now shares); `FixedFormAreas` (`Frontend.Areas` → `EditionContext.Areas`) places a token through the converged
`SourceLineMap`; `Validation/AreaPlacementPass` (pre-bind, after `LevelNumberPass`) collects the heads and screens every
terminal: rows `fixed-form-area-a-item-outside-area-a-2002` (COBOLNET3734) and `fixed-form-text-in-area-a-2002`
(COBOLNET3735), introduced 2002. Goldens: `2002/pb3147_area_free_placement` (A / 7 / M / B), negatives
`pb3147-area-a-item-in-area-b-85`, `pb3147-statement-in-area-a-85`; unit `AreaPlacementPassTests` (tab-indented text,
library text, continued clause, mid-line header). `85/pb2739_indented_division_header_remarks` (a PROCEDURE DIVISION
header in column 12) moved to `2002/`, the edition where its placement is legal.

**Residual (not closed).** X3.23-1985's "area A of a continuation line" is not screened: a continued literal's
continuation text belongs to a token begun on the line before, and GnuCOBOL 3.2 accepts it at `-std=cobol85`
(probe `E:/COBOL-coord/scratch/w1078f/probe/pc.cob`); without the 1985 text the rule is unverifiable.

**For the next implementer.**
- `src/Cobol.Net.Frontend/Preprocessor/FixedFormLine.cs#ProgramTextStart` — the one area-A definition; never test `< 4` elsewhere.
- `src/Cobol.Net.Frontend/Preprocessor/ReferenceFormatMap.cs#PlacementAt` — per physical line, keyed by PHYSICAL column (a tab counts one), the column `LineOrigin.Locate` names.
- `src/Cobol.Net.Frontend/Preprocessor/AreaPlacement.cs#FixedFormAreas` — resultant token position → placement; reuse it for any line-position rule.
- `src/Cobol.Net.Compiler/Validation/AreaPlacementPass.cs#AreaItems` — a new kind of header is ONE override (or one token in `InlineParagraphHeaders` / `EndMarkerWords`); trap: a front-end check would turn every 85 negative's bind-time code into a FrontendError.
