# PB3147 — --std 85 does not enforce area-A placement of paragraph headers

> flags: under-rejects (--std 85 only)

Source: `E:/COBOL-coord/scratch/reports/w1069g-PB2720-report.md`, "New defects (note-ready)" item 1 (branch `worktree-wf_d63f7207-db5-30`, which fixed PB2720 and PB374).

**What was seen.** At `--std 85` a paragraph header written `           P1.` (starts in column 12, area B) compiles. The report found no reference-format check anywhere in the compiler and calls the fix "family-sized" (area A also governs division, section and paragraph headers and level 01/77 items, so the check is a family, not one construct).

**Context.** `kb/Work/PB2720.md`'s "Target" paragraph: "the X3.23-1985 area-A placement, if enforced, is a reference-format rule screened by name in the edition pass at --std 85 rather than a parse predicate". PB2720 removed the `{IsAtLineStart()}?` predicate from `paragraphName` (ISO 2002+ has no area A); this note carries the 1985 half that PB2720 left open.

**Spec.** None cited: the X3.23-1985 reference format is not in `specs/ISO_COBOL.md`. GAP: the implementer must find the governing source for the 1985 rule (see `docs/VERSION_CHANGE_REFERENCE.md`) before implementing.

**Code site.** No reference-format check exists; per PB2720 it belongs in the edition pass, not in `CobolParserCore.g4`. Repro: a one-paragraph program with the header `           P1.` in column 12, compiled with `--std 85`.
