## What the standard requires

NC215A declares a non-native program collating sequence and then compares a numeric DISPLAY item with the
figurative constant SPACE:

```cobol
OBJECT-COMPUTER. XXXXX083 PROGRAM COLLATING SEQUENCE IS THE-WILD-ONE.
SPECIAL-NAMES. ALPHABET THE-WILD-ONE IS "A" THRU "H" "I" ALSO "J", ALSO "K", ALSO
    "L" ALSO "M" ALSO "N" "O" THROUGH "Z" "0" THRU "9",
...
SEQ-TEST-GF-6.
    IF NINE-DU-9V0-1 < SPACE PERFORM PASS ELSE GO TO SEQ-FAIL-GF-6.
SEQ-TEST-GF-7.
    IF NINE-DU-9V0-1 < QUOTE PERFORM PASS ELSE GO TO SEQ-FAIL-GF-7.
```

Every clause number below was re-derived with `python scripts/spec/cite.py --check` (CLAUDE.md rule 1); the
`--check` output is quoted after each.

1. **SPACE and QUOTE are alphanumeric here.** `--check 8.3.3.6.4 "Otherwise, when a figurative constant
   represents a character value, the figurative constant represents an alphanumeric character value."` →
   **OK §8.3.3.6.4 1)**. There is no national context, so the figurative is an alphanumeric character value.
2. **The comparison is therefore an ALPHANUMERIC comparison, not a numeric one.**
   `--check 8.8.4.2.5 "Comparison then proceeds by the rules for comparison of that alphanumeric or national
   elementary item against the alphanumeric or national operand specified as the other operand in the
   condition."` → **OK §8.8.4.2.5** (*Comparison of a numeric integer operand with an operand of class
   alphanumeric or national*). The integer operand "is treated as though it were moved … to an elementary
   data item of the same length … and of the same class and usage as the alphanumeric … operand".
3. **An alphanumeric comparison collates under the program collating sequence.**
   `--check 8.8.4.2.7 "Comparison is made with respect to the collating sequence of characters specified for
   the current alphanumeric program collating sequence."` → **OK §8.8.4.2.7**.
4. **The OBJECT-COMPUTER clause establishes it.** `--check 12.3.6.4 "When the PROGRAM COLLATING SEQUENCE
   clause is specified, the initial alphanumeric program collating sequence is the collating sequence
   associated with alphabet-name-1"` → **OK §12.3.6.4 9)**.
5. **Under THE-WILD-ONE, '9' collates before the space.** `--check 12.3.7.4 "Any characters of the native
   collating sequence that are not specified in the literal phrase shall assume a position in the collating
   sequence that is greater than that of the highest character specified in this literal phrase."` →
   **OK §12.3.7.4** (the tool prints the approximate path `7) 1.`; the printed sub-item is GR7 k) 3).
   `"0" THRU "9"` puts '9' in the specified set; the space and the quotation mark are not specified, so both
   take a position greater than '9'. `9 < SPACE` and `9 < QUOTE` are **TRUE**, and the NIST golden's `PASS`
   rows for SEQ-TEST-GF-6 and -7 are right. The compiler answers FALSE for both.

## The root cause, which is the part that generalizes

`CollatingSelection.Of` is a correct classifier for the question PB678 asked: *what class is this SORT/MERGE
KEY, and which of the two GR5 sequences does it take?* — and GR5 names a sequence for neither class boolean
nor class numeric (`--check 14.9.40.4 "each separately determined"` → **OK §14.9.40.4 5)**; the MERGE twin,
`--check 14.9.24.4 "The alphanumeric collating sequence that applies to the comparison of key data items of
class alphabetic and class alphanumeric"` → **OK §14.9.24.4 5)**. That is PB678's own citation and is not in
dispute). The comparison renderer asks a **different question**: *which comparison rule of §8.8.4.2 does
this relation condition select, given BOTH operands?* — and §8.8.4.2.5 answers that a numeric integer
operand against an alphanumeric operand yields an **alphanumeric** comparison, which §8.8.4.2.7 collates.
One classifier was made to answer both. `feedback_a_real_clause_can_answer_a_different_question`.

The tell was already written three lines above the defect, in `RenderFigurativeRelational`'s own comment:

```
// A NON-NUMERIC figurative (SPACE/QUOTE/HIGH/LOW-VALUE — anything but ZERO) or an ALL "literal" makes the
// comparison ALPHANUMERIC even against a numeric item …
```

The branch has *already decided* the comparison is alphanumeric before it asks the anchor for its category.

## The fix

⛔ Not "special-case Numeric back to `CollateArg` at the call site" — that re-creates the inline ternary
PB678 correctly deleted, and leaves the next comparison-side caller free to ask the SORT-key classifier the
comparison question again. The structural fix (rule 5 — prefer the shape that makes the NEXT case
automatic):

1. Keep `CollatingSelection.Of(PicCategory?)` as the **SORT/MERGE key-class** classifier it is, and say so
   in its summary (it currently reads as a general one).
2. Add the **comparison-class** selector beside it — one function that implements §8.8.4.2.4–.9's selection
   from *both* operand categories — and make `EmitContext.CollateArgFor` take *that*, so a caller cannot
   supply half a comparison. Each arm, with its `--check`ed clause:
   - numeric × numeric → no collation. `--check 8.8.4.2.4 "a comparison is made with respect to the
     algebraic value of the operands regardless of the manner in which their usage is described"` → **OK**.
   - numeric integer × alphanumeric/national → the alphanumeric/national comparison, §8.8.4.2.5 (checked
     above).
   - alphanumeric × national → national. `--check 8.8.4.2.6 "The alphanumeric operand is treated as though
     it were converted and moved"` → **OK**.
   - boolean → no collation. `--check 8.8.4.2.8 "comparison of their boolean value, regardless of their
     usage"` → **OK**.
3. Thread it from `RenderFigurativeRelational` (the figurative's category is the context's, §8.3.3.6.4 GR1,
   which the branch already computes) and from `RenderMembershipTest`.
4. **Drift test**: assert the emitted collate argument for every (left-category, right-category) pair under a
   declared alphanumeric PCS and a declared national PCS, so "automatic" stays true.
5. **Golden**: extend the numeric anchor into the existing PCS golden family rather than forking a new one —
   `tests/conformance/2002/pb297_figurative_sizing_categories.cob` is the canonical home for
   "which sequence does a figurative comparison read"; add the `PIC 9` legs (vs SPACE, QUOTE, HIGH-VALUE,
   LOW-VALUE and `ALL "…"`) plus the `N9 < " "` literal twin that proves the two spellings agree. Prove it
   RED by reverting the one-line fix.
6. Re-verdict `GR-8.8.4.2.7-1`: its CONFORMS record names
   `ConditionRenderer.cs#RenderFigurativeRelational` as a code-location and its evidence never observed a
   numeric operand; the new legs belong in its `notes`.
