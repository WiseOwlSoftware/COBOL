# PB4153 — SELF and SUPER at COBOL-85 draw 2002 OO rules, not the undefined reference

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/SetSender.cs:87` (`SetSenders.Classify`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/OoBinder.cs:692` (`OoBinder.RefusePredefinedObjectOutsideMethod`).

New defect 1 of PB1906's finisher report. `--std 85` programs that write SELF or SUPER draw the 2002 object-orientation
refusals, which name rules that do not exist at the target edition, rather than the undefined reference that PB655 already gave
SELF, SUPER, NULL and ADDRESS in a receiving position, and that PB1673 / PB1906 gave NULL:

- `SET X TO SELF` and `SET X TO SUPER` at `--std 85` -> COBOL0867 (§14.9.39.3 SR8 / SR9);
- `IF X = SELF` at `--std 85` -> COBOL0827 (§8.4.3.8.3 SR1).

Repros: `E:\COBOL-coord\scratch\w20261769b\f\r_SELF.cob`, `r_SUPER.cob` (SET) and `r_if2.cob` (relation).

**Mechanism (the report's):** it is PB655's determination applied to SELF and SUPER. §8.9 reserves them only from 2002, so an
undeclared SELF / SUPER token at 85 names nothing. The fix asks `UnreservedKeywordReference.IsFreeAt(word, edition)` and reports the
one verdict through `UnreservedKeywordReference.Report` at those sites (`SetSenders.Classify` takes SELF / SUPER by name through
`ConditionBinder.SolePredefinedObject`; `OoBinder.RefusePredefinedObjectOutsideMethod` is the INVOKE / object-view spelling, "among
others"), exactly as PB1673's `NullAdmittingOperand` and PB1906's SET object-reference arm do for NULL. It shares its root with
PB1673; the word and the sites differ. Sweep every reader of the predefined object references (`SolePredefinedObject`,
`SoleOoIdentifier`, relation conditions, INVOKE receivers) for the same edition blindness, and pin each with a refuse-at-85
negative (the pattern of `8.3.2-COBOL-words/pb1673-set-null-undeclared-at-85`).

Source: report `w20261769b-PB1906-report.md`, "New defects (note-ready)" item 1; PB1906 / PB1673 (landed).

## Landed (wave 20261824 group B)

**Re-probe (2026-11-02, main a97cc8567).** `--std 85`: `SET X TO SELF` COBOL0867 (SR8), `SET X TO SUPER` COBOL0867 (SR9), `IF X = SELF` COBOL0827 (§8.4.3.8.3 SR1), `IF X = SUPER` COBOL2900 (SR3), `INVOKE SELF "M"` / `INVOKE SUPER "M"` COBOL0827, `INVOKE NULL "M" USING SELF` COBOL0827, `RAISE SELF` COBOL0848, `RAISE SUPER` COBOL0848, `MOVE P OF SELF TO X` COBOL0827 and `COMPUTE N = SELF` COBOL0827: the 2002 object-orientation rules, for two words §8.9 does not reserve at 85.

**Root.** PB655 / PB1673 gave the undefined reference to the receiving positions and to NULL, but SELF and SUPER were read by name in seven more places, each deciding the word was the predefined object reference without asking the edition. The determination is now one member, `OoBinder.RefuseUnreservedPredefinedObject` (its `selfAndSuper` form, `UnreservedPredefinedObjectRefusal`, returns the refused expression an operand channel carries on), and every reader asks it first: the OO identifier door `OoBindSelfOperand` (relation, COMPUTE and every `SoleOoIdentifier` consumer), `SetSenders.Classify` (SET), both `arg.Self` readers (INVOKE and inline arguments), `OoPredefinedSearchRoot` (INVOKE receiver and object-property object), `OoBindObjectView` and `EcBinder.BindRaise`. `UnreservedPredefinedObjectDriftTests` closes the list: a file that reads the keyword and neither guards nor is a named recognizer fails it, and so does a stale exemption.

**Goldens.** Eight refuse-at-85 negatives `conformance-suite/cases/8.3.2-COBOL-words/pb4153-*-undeclared-at-85` (SET SELF / SUPER, relation SELF / SUPER, INVOKE receiver, INVOKE argument, RAISE, object-property object), each expecting `'SELF' is not defined` or `'SUPER' is not defined`; the 2002 halves already exist (`pb451_set_format5_self_sender`, `pb496_active_class_positions`, `pb815_raising_factory_interface`).
