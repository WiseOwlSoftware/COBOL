# PB4153 — SELF and SUPER at COBOL-85 draw 2002 OO rules, not the undefined reference

**Sites:** `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/SetSender.cs:87` (`SetSenders.Classify`), `src/WiseOwl.Cobol.Compiler/Binding/Procedure/Verbs/OoBinder.cs:692` (`OoBinder.RefusePredefinedObjectOutsideMethod`).

New defect 1 of PB1906's finisher report. `--std 85` programs that write SELF or SUPER draw the 2002 object-orientation
refusals, which name rules that do not exist at the target edition, rather than the undefined reference that PB655 already gave
SELF, SUPER, NULL and ADDRESS in a receiving position, and that PB1673 / PB1906 gave NULL:

- `SET X TO SELF` and `SET X TO SUPER` at `--std 85` -> COBOL0867 (§14.9.39.3 SR8 / SR9);
- `IF X = SELF` at `--std 85` -> COBOL0827 (§8.4.3.8.3 SR1).

Repros: `E:\COBOL-coord\scratch\w20261769b\f\r_SELF.cob`, `r_SUPER.cob` (SET) and `r_if2.cob` (relation).

**Mechanism (the report's):** it is PB655's determination applied to SELF and SUPER. §8.9 reserves them only from 2002, so an
undeclared SELF / SUPER token at 85 names nothing. The fix asks `UnreservedKeywordReference.IsFreeAt(word, edition)` and reports the
one verdict through `UnreservedKeywordReference.Report` at those sites (`SetSenders.Classify` takes SELF / SUPER by name through
`ConditionBinder.SolePredefinedObject`; `OoBinder.RefusePredefinedObjectOutsideMethod` is the INVOKE / object-view spelling, "among
others"), exactly as PB1673's `NullAdmittingOperand` and PB1906's SET object-reference arm do for NULL. It shares its root with
PB1673; the word and the sites differ. Sweep every reader of the predefined object references (`SolePredefinedObject`,
`SoleOoIdentifier`, relation conditions, INVOKE receivers) for the same edition blindness, and pin each with a refuse-at-85
negative (the pattern of `8.3.2-COBOL-words/pb1673-set-null-undeclared-at-85`).
