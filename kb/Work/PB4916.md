# PB4916 - one key file, two accounts

**What changed.** The owner's key file (named by `--api-key-file`; the path is the tool's argument, never written into the
repository) now holds one key per Claude account. Each key is on the line after a label line that names the account's
sign-in, with a blank line between entries. Account 1 (the Mythos lane, `~/.claude`) carries the promotional credit that
PB4886's batch arm is planned on. Account 2 (the operator lane, `~/.claude-acct2`) carries a $200 monthly API credit from
2026-11-07.

**The defect.** `scripts/api_key.py` (`read_api_key`) returns the file's first non-empty line, which is now the label. Every
caller would send the label as its key and fail authentication. That is a loud failure, but every API tool is broken. And no
caller can name the account to bill, so a correct reader that picked "the first key" would bill account 1 silently whenever
the operator's credit was meant.

**The fix (one reader, every caller; no second format, no fallback).**
- `read_api_key(path, account=None)` parses the file as entries. A key line is a token of the key's shape. The line before
  it, if it is not a key, is that key's label. A file with exactly ONE key and no label keeps working, and `account` is
  optional for it.
- With more than one key, `account` is REQUIRED. It matches a label by the account's name (`account1`, `account2`, as
  `scripts/orchestrator/account.py` names them) or by the sign-in the label carries. The account-to-sign-in mapping is read
  from each account's config directory as `account.py` resolves it, and is never hard-coded in the repository. No match, or
  more than one, is an error naming the PATH and the labels found, never a key.
- Every caller takes `--api-account <name>`, passed straight through: `fuzz_claude.py`, `fuzz_batch.py`,
  `differential_fuzz.py`, `spec/transcribe_pdf.py`. A `--help` text names it. A run's state or log records the ACCOUNT NAME
  it billed, never the key.
- Self-test, planted files only: a single bare key, a labeled pair selected by name and by sign-in, a pair with no account
  given (refused), an unknown account (refused), a byte-order mark, and the key never printed in any error. Each caller's
  self-test exercises `--api-account` with a fake client, with no API call.

**Sites:** `scripts/api_key.py` (`read_api_key`, `self_test`), `scripts/fuzz_claude.py` (`use_api_key_file`), `scripts/fuzz_batch.py` (`client_for`), `scripts/differential_fuzz.py` (`main`), `scripts/spec/transcribe_pdf.py` (`main`), `scripts/spec/test_transcribe_pdf.py` (whole: the planted account cases).
