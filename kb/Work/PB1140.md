## Finding — `sort-statement-p2` (wrong-answer; rows `GR-14.9.40.4-7`, `GR-14.9.40.4-16`)

**Mechanism.** SORT's short-record space fill never applies the rules' NATIONAL arm by the rule's own test. The USING release (GR7) pads with CobolString.Store's alphanumeric ' ' through RuntimeApi.StrStore(tmp, sdWidth) whatever file-name-2's record description is; the GIVING write (GR16) pads through the GIVING connector's FitRecord, whose national flag EmitNationalAreaRegistration sets when ANY record of the FD is of category NATIONAL -- so an elementary record of usage national and category numeric / numeric-edited / boolean gets alphanumeric spaces, and a multi-record FD with one national record gets national spaces where arm c) applies.

**Repro.** GR7: FD FN, single record 01 FN-REC PIC N(2); SD SN 01 SN-REC. 05 SN-K PIC N(2). 05 SN-T PIC N(1).; write N"YY", N"XX" to FN; SORT SN ON ASCENDING KEY SN-K USING FN OUTPUT PROCEDURE (RETURN, DISPLAY FUNCTION ORD(SN-T)) -- out/probe/sort-statement-p2/pfill.cob. GR16: FD GN single record 01 GN-REC PIC 9(3) USAGE NATIONAL; SD SN 01 SN-LONG PIC N(3). 01 SN-SHORT PIC N(1).; INPUT PROCEDURE releases SN-SHORT N"1", N"9"; GIVING GN; dump pgive-n.dat -- out/probe/sort-statement-p2/pgive4.cob.

**Expected from the spec.** GR7 a) (only one record description of file-name-2, described as a national data item) -> 'the record is filled with national space characters': ORD(SN-T) = 33 (U+0020). GR16 a) read against the GIVING file (the MERGE twin 14.9.24.4 GR13 a) names file-name-4; the printed SORT text says file-name-2, a slip) -- one record, elementary, usage national, category numeric -> national fill: each record 00 31 00 20 00 20.

**Observed / reasoning.** GR7: ORD(SN-T) = 8225 (U+2020) for both records -- two alphanumeric 0x20 bytes read as one national position. GR16: pgive-n.dat = 00 31 20 20 20 20 / 00 39 20 20 20 20. (Category-NATIONAL GIVING record, pgive2.cob, does get 00 20 00 20 -- that arm conforms.)

**Code site.** src/Cobol.Net.Compiler/CodeGen/Verbs/SortEmitter.cs#EmitInputFile (fixed-SD RuntimeApi.StrStore arm); src/Cobol.Net.Compiler/CodeGen/Verbs/SequentialIoEmitter.cs#EmitNationalAreaRegistration; src/Cobol.Net.Runtime/IO/FileConnector.cs#FitRecord

## What the fixer owes

Decide the fill ONCE, at bind, from the rule's own test (one record description? national data item or elementary usage national? → national space; else alphanumeric) and pass it to both SortEmitter.EmitInputFile's RuntimeApi.StrStore arm and the GIVING connector's FitRecord, instead of SequentialIoEmitter.EmitNationalAreaRegistration's any-national-record flag. MERGE's GR2/GR13 share the shape — sweep. Note the printed GR16 text says file-name-2 where the MERGE twin names file-name-4 (a transcription/standard slip the fixer should record, reading it against the GIVING file).
