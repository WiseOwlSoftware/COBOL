# PB5362 - CaptureValueOf records a VALUE OF literal by source text, so 'A' and "A" compare unequal in FileDescriptionIdentity.ValueOfConsistent

**Sites:**

- `src/WiseOwl.Cobol.Compiler/Binding/FileControlBinder.ObsoleteFdClauses.cs:46` (`FileControlBinder.CaptureValueOf`)
- `src/WiseOwl.Cobol.Compiler/Binding/FileDescriptionIdentity.cs` (`FileDescriptionIdentity.ValueOfConsistent`)

**Mechanism.** The obsolete FD clause VALUE OF captures its literal as source text, delimiters included. Two descriptions of one file that write the same literal with different delimiters ('A' in one, "A" in the other) therefore compare unequal and the consistency check reports a conflict between equal values. The comparison must be on the literal's value (its content after delimiter and continuation processing), the same value the compiler uses elsewhere for a literal.

**Repro.** Not run (the report records it as a lead with a code site, R2). Two FDs for one file naming the same file, one `VALUE OF ID 'A'`, the other `VALUE OF ID "A"`, at `--std 85`; expect no conflict.

**Source.** PB5272's report R1-3: "a file this change does not touch".
