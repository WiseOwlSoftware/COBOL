## COBOL1760 stops calling a declared-but-unanswered REPOSITORY PROGRAM word "undeclared" (PB4633)

A CALL, CANCEL or CALL ... AS naming a REPOSITORY PROGRAM specifier that no provider answers drew COBOL5962 at the specifier (REPO-1, ISO §12.3.8.3 SR14) and then a COBOL1760 sentence at the verb saying the word is "neither declared by a PROGRAM specifier in the REPOSITORY paragraph". The word is declared, so the sentence was false. Re-probe on the wave build (`CALL R2103P`, `CANCEL R2103P`, `CALL "ZZ" AS R2103P`, with `PROGRAM R2103P.` declared and no definition or repository entry) reproduced it at all three verbs.

Fix: the three verbs share one speaker, `CallBinder.ResolvePrototype`, so the sentence is chosen there. A word `CallBinder.DeclaresProgramSpecifier` finds in the configuration's program specifiers now draws "declared by a PROGRAM specifier ... but no program of this compilation group and no entry of the external repository answers that specifier, which is itself refused (SR14)". A word no specifier declares (`CANCEL NOSUCH`) keeps the "neither declared" sentence. The CALL spelling-(b) branch that tested the same table now asks the same helper. The code, the refusal and the edition behaviour are unchanged; DESIGN-external-repository §8.2 step 4 says so.

Witness: `ExternalRepositoryResolutionTests.ADeclaredSpecifierNoProviderAnswered_IsNotCalledUndeclaredByCallCancelOrCallAs` (message text for the three verbs plus the undeclared CANCEL). No conformance case or negative json changes: the existing negatives pin the code. Closes no inventory row (SR-14.9.4.3-16 and SR-14.9.5.3-3 were already CONFORMS).
