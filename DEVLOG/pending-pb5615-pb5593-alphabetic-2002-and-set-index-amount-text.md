## At 2002 an alphabetic item stands where an alphanumeric one does, and the 85 SET index-amount refusal names its operand

Two notes, one binder file's neighbourhood (kb/Work PB5615 and PB5593; wave 20262045 group G).

**PB5615.** `SET PP TO ADDRESS OF PROGRAM NM` with `NM PIC A(8)` drew COBOL2157 at `--std 2002`, and `FUNCTION LOCALE-DATE(D)` over a PIC A item drew COBOL1627. Re-probed on a fresh build, both reproduced. §2002:8.5.2.1 says an alphabetic item "may be specified wherever an elementary alphanumeric data item is permitted as an operand" and is otherwise "treated as though it were an alphanumeric data item"; §2014:E.2 withdrew that and §2023 has no such sentence. The mechanism was a category screen that read category alone, with no edition. The fix is one predicate, `EditionInfo.AlphabeticIsAlphanumeric` (Year == 2002), asked by the two readers every statement-operand screen already used: `ItemCategory.IsAlphanumericOrNational(Place, EditionInfo)` (SET ADDRESS OF PROGRAM and FUNCTION, CALL and CANCEL targets, STRING and UNSTRING operands, INVOKE identifier-2, READ and RETURN INTO identifier-1) and `IntrinsicArgumentRules.Violation(rule, op, edition)` (every function argument position whose class set holds alphanumeric), plus the two A.2 communication screens (RECEIVE INTO, SEND FROM), which held their own PIC A tests. The signatures changed and every caller moved with them; no overload kept the old shape. The file-control clause operands (record keys, FILE STATUS, ASSIGN USING, SORT keys) were left on the DataItem overloads, a lead in the report. Goldens: a 2002 case and a 2014/2023 refusal for the SET, a LOCALE-DATE pair, a CALL/UNSTRING/TEST-NUMVAL case with its UNSTRING refusal, and RECEIVE and SEND translate-only cases. Rows 2002-GR-8.4.2.12.3-4 and 2002-AR-15.41.2-1 now CONFORM (GAP 2169 to 2167).
