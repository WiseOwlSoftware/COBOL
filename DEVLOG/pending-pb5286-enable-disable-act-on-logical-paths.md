## ENABLE and DISABLE INPUT act on the logical paths, and a KEY matches a password with a trailing space (PB5286, PB5287)

**PB5286.** The message control system kept one enabled flag per endpoint, so DISABLE INPUT of a queue left its sub-queues open, ENABLE INPUT of a queue could not reopen a path DISABLE INPUT TERMINAL closed, and ENABLE INPUT TERMINAL could not reopen one DISABLE INPUT closed (§1985:XIV.3.2.4 GR3, GR4; §1985:XIV.3.3.4 GR2, GR3). Re-probe on this build before the fix reproduced the notes' three outputs (`DISABLE Q1 00 / Q1 COUNT 000001`, `ENA Q1 15`, `ENA T1 15`). The fix models the path: a new `Paths` table (tag `L`, queue path, source name) holds each (source, queue) path a statement set, and a path with no row is open when the queue's and the source's own flags are. `MessageStoreState.SetQueuePaths` writes the queue, every queue below it and its path with every defined source; `SetSourcePaths` writes the source and its path with every queue; `Deliver` asks `PathOpen`. A statement is answered 15 when everything it names was already so. Seeding deletes a removed queue's or source's rows. The three repros now print `DISABLE Q1 00 / Q1 COUNT 000000 / DISABLE Q1/S1 15`, `ENA Q1 00 / Q1 000001 / Q2 000000` and `ENA T1 00 / QA 000001 / QB 000001`. DESIGN-communication-facility.md section 6 (the table row and "Logical paths") and docs/CONFORMANCE.md section 3.3 carry the model.

**PB5287.** `MessageEndpoint.Admits` trimmed the KEY but not the defined password, so a password with a trailing space (or of spaces) could never match (status 40). It now compares both as alphanumeric operands (§2023:8.8.4.2.7), so trailing spaces count in neither. An omitted KEY phrase stays honored against a passworded endpoint, decided and recorded in docs/CONFORMANCE.md section 3.3.

**Goldens** (85 only; the statements exist from 1985 and nothing is refused below it): `pb5286_disable_input_structure`, `pb5286_enable_input_reopens_source_path`, `pb5286_enable_terminal_reopens_queue_path`, `pb5287_key_matches_password_with_trailing_space`. Rows: 1985 rule ids stay out of `closes_rows` (PB5094), so both notes close none, with the reason written.
