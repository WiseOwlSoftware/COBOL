## PB3839 (NUMVAL-F one value, approved) and PB3840 (a duplicate conformance row ID) filed

The PB3829 fix left one related case: native NUMVAL-F hands a fixed-point receiver its parse truncated at nine places while DISPLAY and a float receiver get the full value, so ROUNDED MODE AWAY-FROM-ZERO stores 0.1234 where NUMVAL, and GnuCOBOL 3.2 for NUMVAL-F, store 0.1235. The standard leaves the native digits to the implementor (15.69.4 rule 2, 15.4.1), so the precedence rule sends the choice to GnuCOBOL. The owner approved the fix with a standing rule: "We should always be consistent with ourself barring an explicit requirement differently". PB3839 records the measurements and the fix, which waits for the WiseOwl.Cobol rename (PB3837). Reading the determination turned up PB3840: docs/CONFORMANCE.md uses the ID DOC-A.1-92 for two different rows, and no audit refuses a duplicate.
