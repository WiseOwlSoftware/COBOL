## PB4838: a file record carries a pointer or message-tag leaf as its 8-position token, and READ, RETURN, SORT USING/GIVING and MERGE read it back

A file record (FD) holding a pointer or message-tag leaf had no managed-slot half. A WRITE of `01 FREC TYPE T-REC` (a strong type with a `9(2)` and a USAGE POINTER) aborted at run time with NotImplementedCobolFeatureException, and SORT USING/GIVING and every MERGE over an SD record of that type were a COBOL1756 Tier-C warning that aborted on reaching the statement. The re-probe on this wave's build reproduced both. The owner decided on 2026-11-06 that a file carries the leaf's 8-position token and that READ, RETURN and SORT GIVING decode it back to the same reference within the run unit, with a token from another run unit keeping its image and raising on a reference, never reading as NULL.

**The shape.** The codec was already the record struct's `AsImage`/`FromImage` pair; the pointer half of the pair was the missing inverse, so the fix is the inverse and the capability that lets the pair be used for a record, not a second path.

- `PointerImage` (the token of DOC-A.1-216) gains `DataPointerOf`, `ProgramPointerOf` and `FunctionPointerOf`, answered from `RunUnit.SlotImages` (`SlotImageTable`), which records every base the run unit imaged. Bases stay per process, so a token from another run unit can never collide with this one's. A data-pointer base is now per cell life (`StorageCell.Generation`): a pointer decoded into storage that was freed still trips EC-BOUND-PTR. A token the table does not hold decodes to `ForeignAddress` (not NULL, keeps its eight positions, EC-BOUND-PTR on a reference through `CobolPtr.Deref`, §2023:13.18.5.4 GR4) or, for a program or function pointer, the reserved name `PointerImage.ForeignName`.
- `MessageTagImage` is the same family for the message tag: token = the tag's identifier in the run unit (the serial number is part of it, because equality ignores the serial but a reply must reach its message), NULL = zeros, `MessageParty.Unresolved` for an unassigned token, which MessagingProtocol already answers EC-MCS-INVALID-TAG because it belongs to no MCS. DOC-A.1-212's "inside a group those 8 positions read as spaces" became the token; the cell seeds, `CobolPtr.SlotWrite` and ALLOCATE's NULL seed follow through `SlotWindow.CarriesTokenImage` (was `CarriesPointerImage`; the one test now includes the tag).
- `DataItem.RecordImageCapable` is the new layer between image-capable and transfer-image-capable; widening `IsImageCapable` was refused because tag equality (§2023:8.8.4.2.14) ignores the serial the token carries. `GroupImageCodec` emits `FromImage` over a token leaf, `PlaceRenderer.WriteRecordAreaImage` is the record area's store and `OperandText.RecordAreaImage` sends the token, including for an elementary pointer or message-tag record (D-FRA sent a zero-length image for it).
- `SortBinder` no longer refuses USING, GIVING or MERGE over a slot SD record (`SlotRecordFileTransferReason` is deleted). `SortEmitter.EmitInputFile` decodes the USING record into the SD area and releases the slot vector beside the image (`CobolSort.Release` gained `slots`); GIVING writes the stored image, which is the token.
- The object-reference leaf needed no question to the owner: §2023:13.18.57.3 SR8 (COBOL2960) and §2023:13.18.60.3 SR15 already refuse it in a file or sort record, so none reaches the codec.

**Goldens.** `file-record-pointer-and-message-tag-round-trip` (2023: WRITE, READ, READ at end, REWRITE, WRITE to a closed file, a token this run unit never produced), `file-record-pointer-keyed-round-trip` (2002: indexed READ KEY, REWRITE, absent key, relative), `sort-using-giving-record-with-managed-slots` (2023: SORT USING GIVING, USING with an OUTPUT PROCEDURE, MERGE, an empty input file, a foreign token crossing the sort byte for byte), and the refusals `file-record-message-tag-refused-2014` and `file-record-pointer-refused-85`. Unit tests `SlotImageRoundTripTests` (same-run round trip for every category, dangling storage, a token from a second run unit raising) and `MessageTagImageTests`.

**Rows.** None closed: DOC-A.1-212, DOC-A.1-216 and D-FRA keep their CONFORMS verdicts with the determination text and witnesses updated.
