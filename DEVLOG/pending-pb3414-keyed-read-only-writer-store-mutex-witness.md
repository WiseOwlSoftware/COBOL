## PB3414: a behavioural witness that a READ ONLY keyed writer runs every statement under the store mutex

Traceability row GR-14.9.51.4-12 names `KeyedConnector.TakeFileLock`'s predicate (`_coherent = FileLockPosture.AdmitsAnotherRunUnit(HostShare)`, line 150). Weakened to `AdmitsAnotherWriter`, no test in the row's test-ref went red: the one case that noticed (`StoreCoherenceTests.The_keyed_store_asks_about_any_run_unit_and_the_sequential_release_about_any_other_connector`) reads source text and was not in the row.

Re-probe on a fresh build: the mutation reproduced the note exactly (a READ ONLY writer's WRITE made its pages outside the mutex, and `AKeyedReadOnlyWriter_IsReadByAnotherRunUnit_AtTheWrite` stayed green, because it only checks the record is visible after the statement). The code is right and unchanged; the gap was the witness.

The fix is `tests/Cobol.Net.Tests.Unit/ReadOnlyKeyedWriterStoreMutexTests.cs`. A `RefusingPageMedium` installed through `KeyedStore.MediumObserver` sees every page write and sync of the writer's statement before it is made and asks the host what another run unit's reader would meet: a second read-access handle asks the region host whether another handle holds the store mutex byte. Two cases, both organizations, `SHARING WITH READ ONLY` and `ALL OTHER`, on the machine's region host and the lock-file host: (1) a WRITE (tree pages 6 and 7, then page 2), a REWRITE and a DELETE make every operation with the mutex held, and the INPUT reader of the other run unit reads the tree as it stood before and as each statement left it; (2) a host refusal of each page write of a WRITE in turn answers '30' (ISO §9.1.13.6 item 1), the mutex is free on the host when the statement answers, the reader reads the tree as it stood (no record 3, '23'), the permanent error is replayed by the next statement without touching the file (§9.1.13.1), and the CLOSE answers '00'. I chose a seam probe over a thread race on purpose: a reader started inside the statement and left to race passes under the weakening most of the time, whereas "the mutex is held at the write" is what makes any reader wait, and it needs no clock.

Mutation check: line 150 changed to `AdmitsAnotherWriter` turns exactly the six READ ONLY cases red (`write 6 (operation 0), write 7 (operation 1), write 2 (operation 2)` outside the mutex), the six ALL OTHER cases stay green; restored.

Rows: GR-14.9.51.4-12 stays CONFORMS; the batch `pb3414-keyed-read-only-writer-mutex-witness` adds the two new cases and the source-text case to its test-ref and one sentence to its notes (GAP 66 to 66, no row closed). One sentence in DESIGN-runtime-library.md 2.2.1.8 names the new witness. PB3415 (the two stale comments) belongs to another group and was left alone.
