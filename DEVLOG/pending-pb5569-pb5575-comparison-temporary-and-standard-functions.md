## PB5569 and PB5575: the 1985 comparison temporary counts a separate sign, and ARITHMETIC IS STANDARD's functions are 32-digit

Wave 20262057, group A. The branch merges the w20262045a branch (PB5577, its own pending entry beside this one).

**PB5569 (1985, wrong answer).** At `--std 85` a numeric operand compared with a nonnumeric one is "treated as though it were moved to an elementary alphanumeric data item of the same size as the numeric data item (in terms of standard data format characters)" (§1985:VI.6.3.1.1.2 GR1), and a SEPARATE sign's position "is counted in determining the size of the item" (§1985:VI.5.12.4 GR6). The temporary was the item's digits. Re-probe on the branch build: `PIC S99PP SIGN TRAILING SEPARATE VALUE -1200` compared equal to `X(3) "120"` false (it compared "12"), and `ALL "12"` opposite `S9(3) SIGN SEPARATE` 121 was sized to 3 and equal. The fix is one method, `OperandText.AsComparisonTemporary1985`, which `ConditionRenderer.ComparisonText` asks at 85 for every string-relation surface: the de-signed sending image moved left-justified into `DataItem.DisplayTextWidthOf` characters (a trailing-P image cut, any other space-filled). INSPECT keeps `AsItemCharacters`. After: `c T`, `d T`, and `b F`, `c F`, `c2 F` for the ALL literal, as the 1985 text gives. Golden `VI.6.3.1.1@1985-Relation-Condition/1985-GR-VI_6_3_1_1_2-1-sign-separate`; rows 1985-GR-VI.6.3.1.1.2-1 and 1985-SR-IV.4.2.2.2.3-L3.2 PARTIAL to CONFORMS (re-applied after main's registrar re-read had recorded both PARTIAL from the pre-fix tree; 1985 GAP 125 to 123 on the merged tree); `docs/conformance/3.10` updated.

**PB5575 (2002, wrong answer), the intrinsic arm and the GIVING transfer.** Re-probe at `--std 2002` under ARITHMETIC IS STANDARD: `ADD H TO N GIVING R2` with 10^30 + .5 stored 10^30 (COMPUTE stored 10^30 + 1); FUNCTION PI less its 29-decimal literal was 95.03E-31 (the 34-digit constant), SQRT, PRESENT-VALUE, VARIANCE and SUM kept 34 digits, `(MEAN (1 2 2) * 3 - 5) * 10 ** 31` was -1 and `MOD (-99999999999999999999999999999997, 3)` 2. Four mechanisms, each at its one place:
- `ArithmeticEmitter.EmitGiving` settles each receiver (`NumericRenderer.Settle`), so the §2002:8.8.1.3.1.3 situation 3 rounding reaches ADD and SUBTRACT GIVING.
- `NumericRenderer.FunctionValue` makes a decimal function value the 32-digit standard intermediate data item (§2002:15.3.1).
- The decimal intrinsic bodies take a new runtime `DecArithmetic` instead of a `CobolRounding`: the SDIDI or the 32-digit item, each operation cut by `CobolDec.ToSidi` and each integer power developed by `PowStandard`, so one body is the value of the equivalent arithmetic expression in both models. `IntrinsicRenderer.RenderDec` takes every call under ARITHMETIC IS STANDARD; EXP uses the 32-digit E; MOD and REM take no exact-integer shortcut there.
- §2002:8.8.1.3.1.3 situation 2: `IntrinsicRenderer.StandardArgument` rounds a standard intermediate argument to 31 digits unless `IntrinsicCarrierRules.StandardArgumentKeepsAllDigits` names the function (an equivalent expression in 2002 or 2014, SQRT, the comparison functions). INTEGER is an edition edge, "argument-1 is not rounded" in 2002 alone: `DialectBehavior.IntegerArgumentRoundedUnderStandardArithmetic`, VCR row 7.81 (main's PB5816 took 7.80 and enum value 24 first). `StandardArgumentRoundingDriftTests` reads the set from both editions' chapter 15.

After: every value above is the hand-derived 2002 value (10^30 + 1, 95E-31, -2, -1, and so on). Goldens `8.8.1.3@2002-STANDARD-ARITHMETIC/pb5575-std-arith-function-values` (2002, 20 lines, each value computed by hand and by a Python decimal model of the 32-digit truncation) and `15.44-INTEGER/pb5575-integer-argument-rounded-2014` (2014). 19 rows re-verdicted CONFORMS (batches pb5575-std-arith-functions-2002 and pb5575-std-arith-exp10-2002, GAP 1781 to 1762); 15 argument-rule rows stay open in PB5575 with no witness built. `docs/NUMERIC_DESIGN.md`'s ARITHMETIC IS STANDARD paragraph now describes the whole model, including the PowStandard and PROHIBITED behaviour an earlier review had flagged as missing.
