## Two MCS arms get witnesses, and the suite can pin a warning WiseOwl reports on a program it compiles

**PB5340.** Both arms re-probed on this build and already correct; each lacked a witness. `1985-GR-XIV_3_4_4-1-repeated-destination` (§1985:XIV.3.4.4 GR1) names LOOP in two DESTINATION TABLE occurrences, SENDs a portion to each, and PURGEs: status 00, error keys 0 0, then a second PURGE gives 70 and keys 4 4, then an EMI SEND leaves two messages that are only `BB`. `1985-GR-XIV_2_2_4-22-refused-key-already` (§1985:XIV.2.2.4 GR22, Table 2 of §1985:XIV.2.2.6) drives ENABLE and DISABLE OUTPUT with a wrong key over an enabled, a disabled and an unknown destination: status 40 and error keys 5 0 1 and 0 5 1, then ENABLE with the right key shows nothing changed (80, keys 5 0 1). Each was mutated to prove it could fail: with `AlreadyKey` replaced by `NoErrorKey` in `SetOutput`'s lambda the ENABLE and DISABLE lines read `001`; with `DestinationKey` ignoring its occurrence index the first PURGE reads `70 04`. Both mutations were reverted.

**PB5461.** The suite had no form for a program WiseOwl accepts and warns of: `generate.py` refused a flagged test with no `refuse-at` entry, and `WiseOwlRefusal_RefusesTheSourceWithItsDiagnostic` requires an error. A `wiseowl/diagnostics/<id>.json` entry now holds `refuse-at`, `warn-at` or both, with one `expect`. The generator refuses a `warn-at` edition where the test is neither accepted nor flagged, or one also in `refuse-at`, and carries the warning as `warns` on the test's own entry of the wiseowl manifest (a warn-only entry is no refusal row). `ConformanceSuiteRunner` checks it beside the test's own verdict, in `Accept` (compile succeeded, warning reported) and in `Flagged` (the warning at the marked line); `lineage_reads.Suite.read` reads an entry with no `refuse-at`. The five pins of the 1985 declaratives rows are placed as flagged twins of their accepted controls (`1985-SR-XV.3.2.3-2` from `1985-GR-XV_3_2_4-1`, and the VII.4.6, VIII.4.8, IX.4.8 and XIII.4.8 GR2 rows), each `warn-at: [85]`, `expect: COBOL2375`. Mutation: an `expect` of `COBOL9999` on one fails with the real warning in the message. The accepted arm has no suite test, so `ConformanceSuiteWarnsTests` plants three. `generate.py --self-test` gains arms for the manifest key and the three new refusals. README and DESIGN-conformance-suite §3.2 say what is built (the design's `.jsonl` with `lines` and `severity` was never the form on main).

Rows closed: none (both notes claim none; the five rows already had accepted witnesses).
