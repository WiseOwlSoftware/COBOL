## EXTERNAL with TYPEDEF is refused below 2023, and a refused SORT/MERGE silences only its own procedure ranges

**PB5710.** `01 T IS TYPEDEF IS EXTERNAL PIC X(4).` compiled at `--std 2002` and `2014`, though §2002:13.14.2 SR5 and §2014:13.16.2 SR5 both say the EXTERNAL clause shall not share a data description entry with REDEFINES, TYPEDEF or BASED (and §2002:13.16.20.2 SR1 admits EXTERNAL only in file and working-storage record description entries, which a type declaration is not). The cause was the construct row `external-type-declaration-2023` and the comment of `VisitExternalClause`, which gated only the STRONG combination and called the weak one a 2002 form on the strength of §2023:13.18.58.3 SR3, a 2023 sentence. `VisitExternalClause` now asks `EntryHasTypedef` (any TYPEDEF), the row's description, display text and citations say so, and `ConstructRegistry.g.cs` is regenerated. Both repros are refused COBOL0900 at 2002 and 2014 and run at 2023. Goldens: `typedef_external` moves to `accept: [2023]`; `pb5710-typedef-external-weak-below-2023` is refused at 85, 2002 and 2014. Rows `2002-SR-13.14.2-5` and `2002-SR-13.16.20.2-1` closed by a `record_verdicts --edition 2002` batch (GAP 1147 to 1145).

**PB6068.** `GateReleaseReturnRange` skipped every use of a refused statement's file (`procedures.Refused.Contains(file)`), so a stray RELEASE of the same SD elsewhere went unreported. `BoundRejected` now carries `RefusedSortMerge` (the file, the INPUT and OUTPUT phrase ranges resolved quietly at refusal, and whether a written phrase named no procedure) instead of the bare file. `SortMergeProcedures.Of` adds the resolved ranges to its Inputs and Outputs, so `Range` and `CalledFromRange` treat them like a bound statement's, and only an unresolvable phrase leaves its (file, direction) unjudged. Four new facts in `RefusedSortMergeReleaseReturnTests`.
