## The R2 filer matches a finding to a note by mechanism, and writes sites in the form work.py reads (PB3259, PB4080)

Tooling only; no compiler change, so no golden or COBOL probe. Both notes were re-probed on the real data of the 2026-11-27 R2 batches 1a and 1b (pin 9e65164eb, `collected.json`) instead.

**PB3259, what the re-probe showed.** `r2_collect.same_mechanism` merged two findings of one wave kind on any exact or dotted-prefix member overlap or any overlapping site range, and `file_census_notes.file_r2` applied the same test to the already-filed notes (reading each note's site paths WITH their line ranges, which is how a landed note's site beside a new finding's matched). Run over the 12 pairs the two addenda and PB3259's own measurement describe (`scripts/arch/r2_mechanism_cases.json`, built from the real records and the landed notes PB2722, PB2725 and PB3238), the old test called 12 of 12 one mechanism; nine are not (the three landed-note mis-matches of batch 1a, the generated-walk pair, three pairs of batch 1b's oo shard, the type-prefix shape and the SUM-counter shape).

**Fix.** A mechanism is the finder's rule and target carried by one set of members. `same_mechanism` now needs the same wave kind, at least half of the exact member names in common (Jaccard over both sets, so a type is not its member, one shared member of six is not enough, and a finding with no member merges with nothing) and statements that share at least a fifth of their words (the real duplicates score 0.29 to 0.39, the distinct pairs that shared a member 0.03 to 0.16). `mechanisms` joins by complete linkage, so A~B and B~C no longer make A and C one note. `file_r2` decides the groups itself and matches an earlier note through its `r2_members`, **Rule it breaks** and **Target**; a finding that matches a CLOSED note is reported with the note's id under its own reason, not dropped under a bare "already-filed". Batch 1b would now file 17 notes, not the 15 its stored grouping gave. DESIGN-architecture-review.md's R2 filing paragraph and both modules' docstrings state the rule.

**PB4080.** `render_r2` wrote `` `path:lines` (Type.Member) ``, a parenthesis without code spans, which `work.note_sites` reads as prose, so every R2 note claimed its file whole and `work.py check` refused it. `site_line` now writes the member names each in a code span (`work.member_name` is the one definition, shared with the reader), keeps the finder's other words as prose, and claims the file whole with `(whole: why)` for a symbol that names no member, a member the file does not declare (`work.undeclared_names`, made public), and a code file named with no symbol. Round trip: rendered then `note_sites` gives the members; the old form read back as `members={}` with the file unnamed. The 28 notes batches 1a and 1b render read back with 0 unnamed or undeclared sites.

**Sibling sweep.** The census renderers in the same file wrote three more bare code-file sites (dead-artifact code files, a god class's files, an extract step's files and its "The files this step edits" line); they now claim the file whole with a reason, and the census self-test reads every rendered note back through `note_sites`.

**Self-review.** Architecture: one definition of a member name (work.py) and of the match (r2_collect), the filer calls both. Code: the thresholds are named constants with the measured range beside them. Silent failure: a closed-note match is named, a finding with no member is never merged (it files alone). Duplication: `whole_site` / `whole_span` replace three literal forms.
