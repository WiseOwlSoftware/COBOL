## An even MEDIAN over a run-time table(ALL), a bounded list that leaves the carrier, and a wrong GR9 citation (PB4827, PB4826, PB4841)

Three leads filed from the reviews of waves 20261879 to 20261882, all in the intrinsic carrier rules and the pointer-slot citation.

**PB4827.** Re-probe: `FUNCTION MEDIAN (U (ALL) FUNCTION EXP10 (-3))` over an OCCURS DEPENDING table of FLOAT-LONG items, count 3, stored a value one binary64 off `(U (2) + FUNCTION EXP10 (-3)) / 2` (`EVEN NE`); the same call over an OCCURS DYNAMIC table did the same. PB4791 had made a fixed table's parity a bind-time fact; a run-time count has none, so the list stayed a selection on the exact lane, whose even mean is the exact value and not the binary64 one. Fix: `IntrinsicCarrierRules.MedianParityIsRunTime` names the case, and the renderer sends an all-binary64 MEDIAN of that shape to the new `CobolIntrinsics.MedianBinary64Exact`, which decides at run time: odd returns the selected argument whole as its own kind (ISO §15.61.4 1)), even is the binary64 mean of the two middle values (`MedianReal`'s rule, §15.61.4 2), §15.4.1) landed as a float item. Goldens: `pb4827_even_median_through_a_run_time_table_all_lands_by_the_binary64` (2002) and `..._dynamic_capacity_..._` (2014), each with a refused twin.

**PB4826.** Re-probe: `COMPUTE R ROUNDED = FUNCTION SUM (A B)` with a 26-digit `A` in `PIC 9(31)`, `B PIC V9(9)` = .004999999 and `R PIC 9(26)V99` stored `.01` where `A + B` stores `.00`. The PB621 arm (aligned bound past the Int128 carrier) took the SDIDI body, whose 34 digits rounded the 35-digit sum at its last digit, and the receiver's ROUNDED phrase carried it. The note called for an owner call because pb4592 pins the 34-digit rounding; that pin is for a value the exact family cannot hold in 34 digits (`SUM (A*A*A, 1.0E0)`), reached by another arm. Every argument of the PB621 arm is an exact scaled item, so it now takes the whole-value bodies PB4792 gave the unbounded case (`SumWhole`, `RangeWhole`, `MedianWhole`, `MidrangeWhole`), and the receiver rounds once (§14.7.4.3); a standard mode keeps the SDIDI body (§15.4.1 1)). The renderer's one-use `AlignmentShiftsUnboundedOperand` wrapper is deleted. Golden: `pb4826_a_bounded_list_leaving_the_carrier_is_the_exact_value` (expected values by Python Decimal) with its `_85` twin. `docs/NUMERIC_DESIGN.md` D26 states the arm.

**PB4841.** `cite.py --check 14.9.3.4` shows GR9 is the NULL seeding of class object and pointer items in allocated storage; it says nothing of where a pointer's value lives. The managed slot is the implementor-defined D-SLOT representation (DOC-A.1-210, DOC-A.1-216). The user-facing rejection text in `ClassifyRedefinesClassesPass`, the backstop message in `Place.cs` and a comment in `DataBinder.Ptr.cs` now say so; the remaining GR9 citations in `src` cite it for null seeding, which is correct.

Rows re-verdicted: none. Self-review: architecture (one reader for each question, no C# in a bound node), full code (cites checked with `cite.py`), performance (the run-time body sorts one list, as `MedianWhole` does), duplication (the even mean reuses `MedianReal`).
