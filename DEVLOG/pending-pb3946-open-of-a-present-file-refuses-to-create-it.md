## PB3946 — an OPEN of a file found present takes a handle that refuses to create one, and is made again when the file was removed meanwhile

PB3635 closed the made-meanwhile race for creations (`FileMode.CreateNew` after an Absent probe). PB3946 is the opposite direction: an OPEN INPUT, I-O or EXTEND that found the file present took a handle opened `OpenOrCreate` (covered sequential `HeldWriteStream`, I-O `OpenReader`), or `Append` (uncovered sequential EXTEND), so a file another run unit removed between the probe and the handle was created empty and adopted: the OPEN answered '00' over a file that was never there, and a covered OPEN journaled it as present. Every other arm answered '30' where §9.1.13.6 item 5 gives '35' and GR13/GR17 give '05'.

**Re-probe.** With the file removed after the probe by the Table 19 column request (`ColumnRequestLog.Before`, which runs between the probe and the body in every organization), `FileRemovedMeanwhileTests` was RED on every arm but OUTPUT: covered sequential I-O/EXTEND '00' with a created file; uncovered sequential EXTEND '00'; INPUT, I-O, EXTEND of all three organizations '30'; the covered OUTPUT of the sequential file '30'.

**Fix.** The host mode of an OPEN's handle is the one presence probe's decision, in one place per organization. `KeyedConnector.FileTaking` (`Existing`, `Replacing`, `Creating`, `Unprobed`) replaces the `create`/`newFileOnly` bool pair, and only an OUTPUT of an unobservable presence takes `OpenOrCreate`. `OpenReader` takes `Open` unless it creates; `HeldWriteStream` maps `Append` to `Open`; `HostFile.HostWriteMode` maps `Append` to `Open` (the access argument it ignored is gone, with `WriteStreamOf`'s). The refusal is classified once (`HostFile.IsRemoved`) and `FileConnector.Open` runs the OPEN again (`OpenAgain.FileRemovedMeanwhile`), sharing PB3635's bound, renamed `MaxPathChangedRetries`: the new probe finds the file gone, so the OPEN answers what the removal, run first, would have: '35', '05' (a creation for I-O/EXTEND), an OUTPUT's creation journaled with no file at its start. DESIGN-runtime-library.md 2.2.2.14 states the rule.

**Tests.** `FileRemovedMeanwhileTests` (4 modes x covered x optional x 3 organizations, and the bound: three attempts then '30', nothing created); `FileCreatedAgainDriftTests` updated for `FileTaking` and `OpenAgain.FileRemovedMeanwhile`, plus `EveryOpenOrCreateOfTheIoLayerIsOneThatMeansIt`, which pins each remaining `OpenOrCreate` to its reason. No COBOL golden: the race has no source-level spelling.

**Rows.** None claimed or closed (`closes_rows: []`).
