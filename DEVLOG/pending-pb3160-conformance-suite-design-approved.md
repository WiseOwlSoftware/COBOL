## The per-edition conformance suite design is approved and its campaign filed (PB3160, PB3172-PB3179); PB3040's dead dispatch entries now stop landings

The owner asked on 2026-10-14 for every test case to become a separate conformance suite per COBOL edition, in the NIST CCVS's role but modernized, and answered the design's questions one at a time: any COBOL compiler must be able to run the suites; one tree of tests generates the four suites; pilot now, the rest after zero GAP. `docs/rearchitecture/DESIGN-conformance-suite.md` records it. Mythos reviewed revision 1 at the owner's request and found that it would not have run on any compiler but WiseOwl: ISO §4.2.2 requires only an optional warning mechanism for a syntax violation, never a refusal, so a must-reject test would fail conforming compilers; a negative passed vacuously on a compiler lacking the feature; DISPLAY's device form is implementor-defined (§14.9.11.4 GR 1), so the expected outputs were not portable; and documented non-support would have become must-reject tests. Revision 2 replaces must-reject tests with flag tests judged with the compiler's conformance warnings on, each paired with an accepted control, adds a portability lint, routes non-support tests to a WiseOwl-only tree and scopes the move to its 144 consumers; one review claim was refuted (`CutRunner.Normalize` exists). The owner approved revision 2. Its eight slices are kb/Work PB3172-PB3179 in the PB3160 campaign, from the inventory's `editions` field through the generator, the harness, WiseOwl's manifest runner, the move of `tests/conformance/`, the pilot and the release archives. `VERSION_TEST_MATRIX_DESIGN.md` §5, which described a deleted legacy runner and claimed programs run at every later edition, now describes `CorpusRunnerTests` as it is. kb/Work PB3040 gains the day's recurrence: 18 dead hand dispatch entries (up to 989 files each) stopped four reviewed branches at the landing lane with exit 3, and the operator released them by hand for the second time that day.

The branch review (four findings, all documentation) was answered on the same branch. The design's portable-output rules now follow the standard: §14.9.11.4 GR 1 makes the device conversion of every DISPLAY operand implementor-defined, so the portability lint also refuses national operands (WiseOwl prints `ABC`, bytes 41 42 43, and GnuCOBOL 3.2 the UTF-16BE bytes for the same program, both conforming; the first review recorded WiseOwl's output as `A B C`, which was `od -c` column padding misread, and round 1 of the second review re-measured it), and the `implementor-defined` example is now Annex A.1 item 148 (§13.18.43.4 GR 17 names two values, fixed or variable records), because the sign convention of items 177 and 178 (§13.18.52.4 GR 4 and GR 5 b) enumerates nothing and its tests are WiseOwl-only. `DOC_INDEX.md` and `VERSION_TEST_MATRIX_DESIGN.md` §5 say APPROVED, and slice S2 (design §13, PB3177) now names the rewrite of that section.
