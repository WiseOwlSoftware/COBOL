## PERFORM VARYING takes FUNCTION LENGTH of a variable-length group as an identifier (PB4831)

PB4831: `PERFORM VARYING I FROM FUNCTION LENGTH (VG) BY 1 ...` and `BY FUNCTION LENGTH (VG)` over an OCCURS DEPENDING group were refused COBOL2119 as "an arithmetic expression". The re-probe on the branch build reproduced both. Cause: `ControlFlowBinder.Classify` read the operand by tree shape, and the binder lowers that function to a `BoundBinary` sum, which Classify lists as composite. Fix: `BindVaryingOperand` asks the written shape first, through `ConditionBinder.SoleFunctionCall` (the reader the SET sender and relation operand use), so a sole function-identifier is an identifier (ISO §14.9.28.3 SR2, §8.4.3.1.2 Format 1); the SR4 a) / SR5 b) integer test reads the operand twin `IntrinsicBinder.OperandOf(e, functionValue: true)`, which makes the sum an integer function value. A parenthesized function is still an arithmetic expression (§8.8.1.1) and still refused. Goldens: accept 2002 `pb4831_perform_varying_length_of_variable_length_group` (FROM, BY and an index-name loop), refusal `pb4831-perform-varying-parenthesized-length-of-variable-length-group` (COBOL2119). Sibling sweep: the keyword-omitted `LENGTH (VG)`, `PERFORM ... TIMES` and SET senders already accepted it. No inventory row closed.
