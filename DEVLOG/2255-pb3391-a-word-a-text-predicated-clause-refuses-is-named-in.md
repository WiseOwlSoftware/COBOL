## Entry 2255 — 2026-10-19 10:55 PDT — PB3391: a word a text-predicated clause refuses is named in its closed format, and its run is one refusal

Wave 1129 group C (kb/Work PB3391, campaign PB3353). `OBJECT-COMPUTER. XYZ FOO IS 12.` drew a bare COBOL0001 "cannot parse construct near 'FOO'" and then COBOLNET1971 "'IS' is not a paragraph of the CONFIGURATION SECTION", at every edition. ISO §12.3.6.2 prints a closed clause list, and FOO opens none of its clauses (at 85 the SEGMENT-LIMIT and MEMORY SIZE clauses existed, and FOO is neither), so the source is illegal everywhere and the defect is the message.

**Mechanism.** The closed formats' error production opens at a word, and so do the clauses recognized by the TEXT of their word through a left-edge predicate: OBJECT-COMPUTER's `SEGMENT-LIMIT IS? integer`, `MEMORY SIZE …` and CHARACTER CLASSIFICATION, the SPECIAL-NAMES LOCALE clause, and PICTURE's LOCALE phrase before the data description entry's list. When the word run cannot continue at the reserved word such a clause takes next (FOO then IS), the predicated clause is the prediction's sole SLL survivor; ANTLR evaluates the accept state's predicates and throws NoViableAlt at the decision's start token when none holds. The 0g arm declined every IDENTIFIER, on the premise that the production would always have taken one, and the base recovery stopped at the word, so an enclosing list took the rest of the run as its own residue and refused the next token a second time. It is not PB3390's mechanism, whose integer and leading-comma tokens are the production's own token set; PB3391 stays its own note.

**Re-probe (worktree build, before).** The note's repro at 85 and 2023, plus `XYZ FOO IS.`, `OBJECT-COMPUTER. FOO IS 12.` and `XYZ FOO SIZE 12 WORDS`, all gave the bare error and the second refusal. The sibling sweep over every text predicate beside a closed list found the same mechanism at `XYZ FOO BAR IS 12.` (inside the run), `01 X PIC X FOO SIZE 3.` and `SPECIAL-NAMES. FOO BAR IS "x".`. It also found the reserved-word case the arm already named, `XYZ CHARACTER FOO IS X.`, still drawing the second refusal.

**Fix (CobolErrorStrategy only).** `IsPredictionFailedAt` identifies a NoViableAlt whose start token is its offending token. `ClosedFormatResidue(…, predictionFailedAt)` then admits the IDENTIFIER and skips the after-period exclusion for it, because the decision's lookahead already tried every path out of the list. The 0g hint names the word in the innermost open list's format, with the pass's own code and sentence. `Recover` consumes the named token and the rest of the run, up to a recovery-set token no run holds (`ResidueRunTokens`, read from `residueOpening` and `residueItem` in the ATN), so the residue is one refusal for a reserved word too. The grammar comment at `genericClause` (its old claim that the tail's integer exists for SEGMENT-LIMIT's predicate was no longer the reason) and DESIGN-frontend-grammar.md are current. No new diagnostic code (COBOLNET4580-4582 returned).
