## Entry 3189 — 2026-11-05 20:13 PST — The type 6 argument screen reads every call over an item, signed ABS in both regions, and trusts only quotients the arithmetic keeps (PB4794, PB4795, PB4796; PB4805 retired)

One file, `IntrinsicArgumentRules.cs`, three mechanisms of the ISO section 15.3 item 6 reading ("an arithmetic expression that will always result in an integer value"), and one note that no longer reproduces.

**PB4794 - a terminating quotient longer than the arithmetic keeps.** Re-probe: `COMPUTE X = 1 / 1048576 * 1048576` into `PIC 9` stored 0 and `COMPUTE Y = FUNCTION ABS (1 / 1048576 * 1048576)` stored 1. The PB4758 fix took a literal fold as proof of an integer when every quotient TERMINATES; a quotient of 20 fraction digits terminates, and a one-digit receiver truncates a nested quotient at 14. `QuotientsTerminate` is now `QuotientsAreExact`: a quotient (or power) counts only when its expansion terminates within `CobolNum.NestedQuotientScale(0, 0)` fraction digits, the least working scale the arithmetic gives any nested quotient, read from its one home (`ExactRational.IsTerminating` became `FractionDigits`). Golden `pb4794_abs_literal_quotient_long`.

**PB4795 and PB4796 - which calls the additive-spine walk reads.** The call arm read only FUNCTION ABS of a bare unsigned-or-signed item, so `S2 + FUNCTION MAX (S2)` and `S2 + FUNCTION ABS (S2 + 1)` failed open, and a signed `G2 - FUNCTION ABS (G2)` was read as 0 although it is 2 * G2 for a negative G2 (section 15.7.4 1) b)). The arm is now `ReadCall`: a one-argument MAX, MIN, SUM, MEAN, MEDIAN or MIDRANGE is its argument (the spec's one-occurrence equivalents; a table(ALL) argument is many occurrences and is excluded); ABS of a sum of items and constants that cannot be negative where the items are not negative reads as the sum; ABS of a signed item reads as the item in the non-negative region and, in a second walk the screen runs only when it met one, as the item's negation. The constant witness's message no longer says "every other term is an integer", and says where it holds when an ABS of a sum was read. `UnsignedArgumentOfAbs` (misnamed since PB4757) is gone; the two comments that called the signed difference legal describe the unsigned case; the `pb4757-abs-negated-sum-non-integral` header cites 15.7.4 1) b). Goldens: `pb4795-max-identity-sum-non-integral`, `pb4795-abs-of-sum-non-integral`, `pb4796-abs-signed-difference-non-integral` (refused, COBOL1627) and `pb4795_identity_difference_legal` (accepted; the unsigned and MAX differences stay legal). Still fail-open by design: ABS of a sum over a SIGNED item (`G2 - FUNCTION ABS (G2 + 0)`), where one valuation region per item is all a witness gets.

**PB4805 - retired.** `FARTHEST-FROM-ZERO` over `FUNCTION LENGTH` of a variable-length group no longer reaches the loud arm: commit 867fe25c8 (PB4764 review R1-1) added the `BoundComputedOperand { FunctionValue: true, Expr: BoundBinary }` arm to `ConditionRenderer.ComputedExtremeTest` and to `IsIntegerOperand`, and the existing golden `pb4764_length_of_variable_length_group_extreme` runs it (`L-FAR`, `B-NOT-NEAR`, `L1-NEAR`).
