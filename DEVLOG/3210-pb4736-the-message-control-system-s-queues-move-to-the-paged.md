## Entry 3210 — 2026-11-06 13:04 PST — PB4736: the message control system's queues move to the paged store, and a host that cannot lock is refused

Slice 3 of the communication facility (DESIGN-communication-facility.md section 6 and section 9 item 3). The landed store serialised each statement by opening `mcs.lock` with `FileShare.None`. On Unix .NET expresses that as an advisory `flock` and `SafeFileHandle.Unix.cs` ignores one that fails with ENOTSUP or EACCES, so on such a file system two run units ran one statement at once over `mcs-state.json` and a message could be lost or delivered twice.

**What changed.** `mcs.store` is one paged store (the engine of DESIGN-runtime-library.md 2.2.1, store kind `M`) holding one B+ tree whose first key byte is a tag: `Meta`, `Endpoints`, `QueueMessages`, `TerminalMessages`, `QueueCounts`, `Outbound`, `OutboundCounts`, `DeviceEnds` (`McsTables`). The key order is the rules of E.5.5.3 and E.5.5.4: the next message of a designated structure is the first key at or after its prefix, and ACCEPT MESSAGE COUNT reads one row. `McsStore` is the run unit's session: handle, region-lock endpoint, the engine's `PagedFile`, and the presence byte, ended by `RunUnit.Terminate`. Each statement holds the store mutex, enters the store coherently, acts, transmits to the devices and lands the edited tree through `StatementLanding.Complete`. A host whose locks answer `Unavailable` answers 92 before the statement reads anything. `MessageDefinitions` holds what the user defined, immutable; `MessageStoreState` is a view over the tables for one statement; seeding (`McsSeeding`) keeps a kept endpoint's state and messages, seeds a new one once and deletes a removed one with its counts. Deleted with every caller: `mcs.lock`, `mcs-state.json`, `LockWait`, `AcquireLock`, `Commit`, `TakeBack`, and the state's `ToJson`, `Overlay`, `Touch`, `Dirty`, `Empty`.

**Status 92 takes no action, by construction.** For a refusal the engine reports, `McsStore.Refused` decides inside the same mutex hold whether the statement landed: it discards its `PagedFile`, opens a read-only one over the same handle (the adoption rule in memory, writing nothing) and compares the adopted page 2 with the generation the statement stamped and the tree it began on. Landed answers as completed; not landed answers 92; a refused reopen answers 93, a new implementor-defined value whose outcome is not known. docs/CONFORMANCE.md and the user guide carry the 9x determination, 93 included.

**Two corrections of the design.** A device the store never transmitted to is committed at 0, so the first statement cuts the file a dead first transmission created (the design cut only devices with a row). And a statement that answers 92 puts the devices it wrote back to their committed ends and deletes one it created, best effort (`CutBack`, the successor of `TakeBack`): the positional protocol does not depend on it, but the unit tests of the retired store asserted that 92 leaves a device as it was, and that is what a user sees. Both are in the design document.

**Left to PB4737.** The `Waits` table and the bell: seeding deletes no `Waits` row yet, and a RECEIVE without NO DATA still polls.

**Goldens and tests.** No new conformance case: the facility's behaviour is unchanged, and the five `pb4677_mcs_*` goldens and the CCVS CM programs run against the new store as before. `unit:MessageControlTests` covers the region-lock refusal for every statement kind (store and devices byte for byte as they were), 92 and 93, a keyed file at `mcs.store`, the mutex held for the length of a statement, seeding, devices and the presence byte. `unit:McsStoreCrashMatrixTests` runs thirteen statement kinds with the run unit killed after every write and with the host refusing every write from the nth, and asserts the state before or after (never between), counts equal to a recount, and 92 for the state before, completed for the state after.

**Rows.** None: the facility is outside the 2023 text the inventory derives from.

**Review round 1.** Three blocking findings, answered. (R1-1) `Prepare` committed every defined device at 0 and cut its file, destroying delivered output when a run unit met a new store; seeding now lands as a store statement of its own, before the action and before any device is written, and gives each device without a `DeviceEnds` row the length its file has, so output already delivered is kept and a dead statement's tail is never adopted. (R1-2) `Prepare` opened every device file for write; it now looks at the length, opens only a file longer than its committed end, and the cut is best effort, so a read-only or reader-locked device refuses no statement that does not transmit to it. (R1-3) `McsStoreCrashMatrixTests` gains a first run unit killed after every page write and the medium's syncs refused alone from the nth on; the latter found a real defect: a creation refused at its sync left pages that name no committed meta, which refused every later statement, so `McsStore.EmptyUncreatedStore` sets the file back to no bytes. Also fixed: a negative `capacity` is refused at parse (status 91) instead of flipping to never-full, the dead `RootQueues` and `DestinationEndpoint.Definition` are gone, `RefuseSharedDeviceFiles` reads `Devices`, and the stale design, `StatementLanding` and `HostRegionLocks` text is corrected.
