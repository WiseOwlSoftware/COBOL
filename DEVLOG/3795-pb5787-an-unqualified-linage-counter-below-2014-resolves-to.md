## Entry 3795 — 2026-11-16 14:41 PST — PB5787: an unqualified LINAGE-COUNTER below 2014 resolves to the nearest container's GLOBAL LINAGE file

At `--std 85` (and 2002) a contained program with no LINAGE file of its own, under two containers that each declare a GLOBAL LINAGE file, drew COBOL5997 on an unqualified LINAGE-COUNTER, citing only §2023, while the container's own reference was accepted. The re-probe of the note's repro reproduced it (exit 65). `CounterResolver.LinageFileOf` narrowed to the program's own LINAGE files only when it had some (kb/Work PB5166) and otherwise counted every visible one. Below 2014 it now takes the GLOBAL LINAGE files of the nearest declaring container (`NearestContainerLevel`, by `InheritedGlobals.FileDepth`: §1985:X.4.2.4 GR1, §1985:X.1.3.8.2 GR3b.1, as `ReportOf` does for reports), and the ambiguity message cites the running edition's rule (§1985:IV.4.3.8.1 SRL2.8, §2002:8.4.1.1.2 SR6). Goldens: `pb5787-linage-counter-nearest-container-1985` and `-2002` (both display `04`), and the refusal `-2014` (2014 and 2023, COBOL5997). Reverting the fix line turns the 85 and 2002 tests red; restoring it turns all four green. The 1985 code read of `1985-GR-X.4.2.4-1` stays for the campaign's re-read.
