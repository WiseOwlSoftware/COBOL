**Cluster A — PB2087, the CALL / function arm (SPLIT; the INVOKE arm stays open).** *Mechanism.* ISO §14.2.3 GR8: "If the argument is passed by reference, the activated runtime element operates as if the formal parameter occupies the same storage area as the argument." Only an elementary, non-REDEFINED formal aliased its argument (per access, through its carrier). A group formal, a formal another LINKAGE entry REDEFINES and a formal whose ADDRESS OF is taken kept a callee-local field and copied the caller's image in at entry and out at return, so `CALL "S" USING WS-REC WS-REC` gave S two independent images: `MOVE 5 TO F1 OF LK-1` left `F1 OF LK-2` at 1, and the last copy-back won. Callbacks, an EXTERNAL record also passed BY REFERENCE, and nested GLOBAL formals were wrong the same way. *Re-probe.* The note held as written (implementer's `alias1.cob`: before `LK-2 F1 1`, after `LK-2 F1 5`). *Fix shape.* One mechanism, the existing one: a non-resident formal whose area a cell can carry is an AREA formal (`LinkageFormal.IsArea`). `DataBinder.PtrBindBasedAndAddressables` claims its class through the one `StorageCell` forcer and describes it as a BASED item whose implicit data-address pointer IS the formal's carrier field; `CobolArgAdapt.Area` points it at the argument's `CobolArg.Area` (cell plus offset), so nothing is copied. On the activating side the same pass claims onto a cell every group and character-class elementary item named as a BY REFERENCE CALL USING operand or a user-defined-function argument (`CallScanByReferenceOperands`, `ClaimsAnArea`, the ADDRESS OF claim factored into `ClaimAddressableCell` and `AlreadyInACell`), and `CallEmitter.AreaFact` states the area, subscripts, reference modification and ODO included. A copy survives only where the argument has no cell (BY CONTENT, a BY VALUE formal, a native numeric or pointer elementary argument; `CobolArgAdapt.Aliased` tells them apart) and for a variable-length group formal (`CellCanCarry`). An omitted argument gets a blank cell whose pointer answers `IsNull` (`CellPointer.OmittedArgument`). `ParameterConformance` now refuses a strong pointer-leaf group only when it does not cross BY REFERENCE from a cell.
