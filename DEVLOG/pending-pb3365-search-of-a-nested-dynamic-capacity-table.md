## SEARCH and SEARCH ALL of a dynamic-capacity table nested under another table are built (PB3365)

A legal `SEARCH EP(I)` or `SEARCH EP` over `EP PIC X OCCURS DYNAMIC CAPACITY IN ECAP INDEXED BY EX` inside `E OCCURS 3` compiled with a COBOLNET1756 warning and aborted the run unit with NotImplementedCobolFeatureException (found by the wave-1115 PB2849 branch). The re-probe reproduced it in a plain record, an EXTERNAL record, a TYPEDEF'd record and LOCAL-STORAGE.

**Root.** A dynamic-capacity table's scan bound is its current capacity (ISO §8.5.1.9.1) and each occurrence of an enclosing table holds a capacity of its own (§8.5.1.9.2), so the bound exists only for one enclosing occurrence. `SearchBinder.Identifier1` asked for the whole-table path (`BuildTablePath(table)`, null under another table) where the SORT table subject already builds the instance path (`BuildTablePath(table, enclosing)`).

**Fix.** The occurrence is named where §14.9.37.4 GR1 and §14.9.37.3 SR2 put it. `Identifier1` reads identifier-1's enclosing subscripts when it wrote all of them (`ReferenceResolver.ReadTableSubjectSubscripts`, whose `bool tableSubject` became `TableSubject {None, Sort, Search}`). Otherwise `Phrases` binds each WHEN condition under `ReferenceResolver.CaptureEnclosingSubscripts`, which takes the enclosing positions from the first committing subscript reading of a reference to the table, so a subscript that activates a function is never read twice. The bare spelling must work: the standard's own suite writes it (NC233A), and the design record (D16) already says a lower bound on identifier-1's subscript count rejects legal source. `SearchBinder.DynamicTablePath` builds the path once for both formats, and `ControlFlowEmitter.EmitSearch` reads the `CobolDynTable` into one local (`__searchTblN`) that carries the scan bound and the EnterSearch/ExitSearch bracket, so a WHEN body that moves an enclosing subscript cannot send ExitSearch to another occurrence. A nested dynamic table no phrase subscripts has no bound; that is COBOLNET2075 (`StatementValidation.SearchNestedDynamicWithoutOccurrence`), not a guess. Determination D-SRCH-DYN (docs/CONFORMANCE.md §3): the first WHEN-phrase reference, in source order, names the occurrence.

**Goldens.** `cases/14.9.37-SEARCH/pb3365_search_nested_dynamic_table` (accept 2014; capacities 3/1/4 so a bound taken from the wrong occurrence changes the answer; both spellings, both formats, VARYING, a WHEN body that moves the subscript) and the negative `pb3365-search-nested-dynamic-no-occurrence` (refuse-at 2014 and 2023). `SearchOperandResolutionDriftTests` runs the answer and guards that both formats name the instance through the one `DynamicTablePath`.

**Tests that leaned on the old deferral.** `StatementDeferralAnnounceDriftTests.DeferralProgram` and `BoundDeferralDriftTests.GenuineDeferral_StillCompiles_AndAnnounces` used this very shape as the one legal-source COBOLNET1756 exemplar. They now use INSPECT … FOR ALL LINAGE-COUNTER (a special register in a position the resolver routes none to), and the first one's summary records the history and how to pick the next exemplar. The census found no other ISO-legal deferral reachable: GOBACK RETURNING inside a method is a flagged extension, and the SORT/MERGE SD-record, CALL, INSPECT and DISPLAY shapes probed are built.

**Sibling sweep.** Other `BuildTablePath … is null` sites: SORT (instance path, unchanged), `InitializeBinder` whole-table INITIALIZE (a different rule), `CapacityRegisterPlaceOf` (the SR30/SR31 determination). No other SEARCH shape defers.

**Gate.** The finisher cherry-picked the two commits onto main 6fb6a20f8 and gated them: `=== BUILD-LOCAL GATE: LEG 1 ONLY (batched gating, PB2515): GREEN` (run 20261018T164104Z-2679fd; Conformance 11,349/17,680, Unit 33,766/34,109, Characterization 5/36 in leg 1). The new cases ran in leg 1 and passed: the refusal `pb3365-search-nested-dynamic-no-occurrence` (editions 2014 and 2023), the positive `pb3365_search_nested_dynamic_table` (edition 2014), `SearchOperandResolutionDriftTests.NestedDynamicTable_IsBoundedByTheNamedOccurrence_InBothFormatsAndBothSpellings` and `SearchBinder_NamesTheDynamicTableInstanceInOnePlace`, and the two re-pointed deferral tests. The Linux gate is the landing's (batched gating).


**Branch review round 1 (2 findings, both fixed).** R1-1: a WHEN-named occurrence whose subscript bears a function (`EP(FUNCTION INTEGER(I + 1), EX)`) hoisted a path over a D18 temp that the WHEN condition stores only inside its per-evaluation wrapper, so the bound read an unstored temp (NullReferenceException; in a loop, the previous execution value). `ReferenceResolver.CaptureEnclosingSubscripts` now returns an `EnclosingOccurrence` (subscripts plus the pre-ops registered while that subscript list materialized) and `SearchBinder` runs those pre-ops once ahead of the scan in a `BoundSequence`; the golden gained S9 (SEARCH in a PERFORM loop) and S10 (SEARCH ALL), both with the function in the WHEN phrase only. R1-2: the data-model design paragraph described the superseded refuse-the-bare-spelling design; rewritten to the built one (identifier-1 subscripts, else the first WHEN reference, COBOLNET2075 only when neither names the occurrence), and the control-flow D16 paragraph gained the pre-ops sentence.
