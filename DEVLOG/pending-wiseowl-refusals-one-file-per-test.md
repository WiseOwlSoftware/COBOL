## WiseOwl's refusals and compile options are one file per test, so the merge queue lands refusals in parallel (PB4147)

**The mechanism.** `conformance-suite/wiseowl/diagnostics.json` was one JSON object, test id to `{"refuse-at", "expect"}`, and every fix branch that added a refusal edited it. GitHub's merge queue merges with plain git and runs none of the repository's merge drivers, so `enqueue.py` held every later pull request that touched a driver-merged file (exit 16, DRIVER FILE QUEUED): 61 of the landing lane's 79 driver-file holds were this one file, and a wave of N refusal-adding branches landed one at a time, about 25 to 30 minutes apart, while the queue's five-wide build sat idle.

**The re-probe.** On this build `merge_drivers.DRIVERS` still listed `conformance-suite/wiseowl/diagnostics.json` and `options.json` under `cobol-keyed-object`; `generate.py --check` read both through `json.loads` of the whole file. Neither could be merged without the driver.

**The fix shape (CLAUDE.md rules 4 and 5).** The registry is no longer a file. A refusal is `conformance-suite/wiseowl/diagnostics/<test id>.json` (`{"refuse-at": [...], "expect": "..."}`), and a WiseOwl compile option is `conformance-suite/wiseowl/options/<test id>.json`, with `<id>.<step file>.json` for one build step of a multi-unit test (an id holds no `.`, so the first one begins the step file). `generate.sidecar_key` is the one reader of a file name, `load_sidecars` the one directory reader; `repository_inputs` returns the entries in the same dictionaries as before, so the manifests, the in-process runner, `run.py` and `SuiteManifest` are unchanged. The registries' problems (a file that is not `<key>.json`, a subdirectory, a file that is not JSON) are refusals filed against the file's own path, which made `generate.load_implementor_defined`'s problems a `(path, message)` pair as well. I chose one file per refusal over putting `refuse-at` and `expect` in the refused test's header: `cases/` tests are compiler-neutral and every adapter's harness reads their headers, while a WiseOwl diagnostic code is what DESIGN-conformance-suite section 1 keeps out of them. The choice is in that document's section 4.

With no shared file there is no driver to run: `cobol-keyed-object` left `merge_drivers.DRIVERS` and `.gitattributes`, and `Layout` lost its object form (it keys the elements of one array by a field; the inventory and `constructs.json` drivers are the two that remain). The self-test fixtures that used the object driver (`merge_drivers`, `enqueue`, `land_lane`, `prune_worktrees`, `test_plan_wave`, `verdict_line`) now use the constructs-shaped catalogue and `cobol-keyed-constructs`. `impacted_tests.py` maps a registry file to its test by `generate.sidecar_key` (a deleted file names none), replacing `changed_entries`'s diff of a whole JSON object. `gen_ledger.measure_suite`, `session-probe.ps1`, `golden_registered.py`, `NumericDisplayFormDriftTests` and the skills, templates and design documents that told an implementer where a refusal goes follow.

**Drift test.** `MergeDriverDriftTests.TheSuiteRegistries_AreOneFilePerTest_AndNoDriverGovernsThem` fails when a file sits beside the registries' directories under `wiseowl/`, when a registry directory holds anything but `<id>.json`, or when `.gitattributes` gives a `conformance-suite/` path a merge driver. `merge_drivers.py --self-test` also proves that `covered_by_driver` names neither registry directory, which is what `enqueue.driver_file_holders` asks.

**Data.** 3,062 refusals and 5 options were split by a one-off script (not committed); the reconstructed dictionaries equal the old files' parsed content exactly, and `generate.py --check` is GREEN over 5,857 tests with the same counts.

**For branches cut before this landing.** A branch that added a refusal to the deleted `diagnostics.json` meets a modify/delete conflict at its landing merge: write the entry as the file `wiseowl/diagnostics/<test id>.json` and take the old file's deletion.

**Rows.** None: process tooling, `closes_rows: []`.
