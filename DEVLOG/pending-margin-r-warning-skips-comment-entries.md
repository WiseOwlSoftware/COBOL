## The margin-R warning stays silent inside a comment entry (PB5024)

PB4999 made COBOL6688 fire for every token that ends at position 72 with text at 73. A comment entry (AUTHOR, REMARKS and the other identification paragraphs, grammar rule commentEntry) is arbitrary commentary, so a cut there changes no program yet drew the warning. Re-probe on this build: an AUTHOR word ending at 72 with text at 73 drew COBOL6688. Fix: MarginRCutScreen.Warnings now takes the parse tree and skips the tokens a CommentEntryContext holds. The rule "which tokens belong to a comment entry" moved to one place, CommentEntryTokens, which WordCharacterScreen.TreeFacts now also uses (no second copy). Witnesses: unit tests ACutInACommentEntry_IsNotNamed (silent) and TheSameCutInADataDescription_IsStillNamed (warns), plus the conformance case pb5024-comment-entry-cut-at-margin-r. No inventory row closed (closes_rows: []). Self-review: a tail that recurs on two lines is a tag (PB4372), so the data test stands alone; sibling sweep: the only other token-stream screen over the whole stream is WordCharacterScreen, which already skipped comment entries.
