## Entry 3676 — 2026-11-15 04:26 PST — WRITE FILE and REWRITE FILE work from COBOL-2002 (Annex A.4.13 claimed, COBOL1706 retired)

PB5579 (wave 20262043, group E). The FILE alternative of `{ record-name-1 | FILE file-name-1 }` in WRITE and REWRITE was an optional element declined by COBOL1706; §2002:3.1.1 makes it required of a 2002 implementation, so the decline was a refusal of legal source at `--std 2002`.

**Re-probe.** `WRITE FILE F FROM W` (scratch `p/wfile-plain.cob` of the 2002 read) was exit 65, COBOL1706 on main; on this branch it compiles and the file holds the operand's bytes.

**Fix shape.** The standard's model is §2002:14.8.47.3 GR5 and §2002:14.8.33.3 GR8 (§2023:14.9.51.4 GR8, §2023:14.9.35.4 GR9): `MOVE identifier-1 TO implicit-record-1`, then WRITE (REWRITE) the implicit record, which has the description of identifier-1 (of a literal, of a function's returned value). A MOVE between two items of one description is the identity copy, so the record released is the image of the operand itself. `MoveBinder.BindFilePhraseRecord` returns the operand's own place as the statement's record and binds no MOVE; a function value or reference-modified item goes through the existing `SendingValueTemp.Materialize`, a literal through the new `SendingValueTemp.MaterializeLiteral` (a pre-op into an item of the literal's class, category, usage and length). `SequentialIoBinder.BindFileFormat` is the one site for both verbs; it runs before the sequential/keyed reroute, so the sequential, relative and indexed arms share it (`KeyedIoBinder.BindWrite/BindRewrite` now take the FROM bind as a deferred `bindFrom`). The emitters needed two changes: `FileModel.TransfersPastRecord` is false for a record that is not one of the file's (the area image is not sent past an operand that is not in the area), and `SequentialIoEmitter.AreaCharacterViewFor` stores such a released operand into the shared area of a SAME RECORD AREA clause (GR2). The one `FromPhraseRules` function screen is extracted (`ScreenFromFunctionClass`) and the FILE phrase gets its own rows (`WriteFile`, `RewriteFile`: an alphanumeric or national function, SR10 and SR8).

**Syntax rules enforced** (new codes COBOL7351 to COBOL7353, all returned in use): FROM required with FILE (7351); literal-1 not numeric or figurative, no USAGE OBJECT REFERENCE item in identifier-1's description (7352); a bit item statically byte-aligned (7353, `ParameterConformance.ScreenBitAlignment`, the CALL BY REFERENCE walk); a numeric function COBOL1914; a report file COBOL2577; a sort-merge file COBOL1692. `--std 85` refuses the phrase at parse time (construct `write-rewrite-file-phrase-2002`, COBOL0900). COBOL1706 and `DeclinedFilePhrase` are deleted; A.4.13 is Claimed in docs/conformance/5/A.4.13.md and the conformance profile, and the derived-verdict selector `rewrite-write-file-only` and its two drift tests are removed.

**Determination (GR12 leaves it to the implementor).** A fixed-length file takes the operand's image padded with spaces to the record width or cut to it (status 44 is the RECORD IS VARYING rule, §2023:13.18.43.4 GR14); a RECORD VARYING file's length is the DEPENDING item or the image.
