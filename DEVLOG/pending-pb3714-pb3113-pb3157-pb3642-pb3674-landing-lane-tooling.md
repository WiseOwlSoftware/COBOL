## PB3714, PB3113, PB3157, PB3642, PB3674: the landing's verdict line has one home, the lane's runner check cannot be fooled by a reused pid, a merged branch is nothing to land, two landings of one driver file never queue together, and a language server holding SourceGen.dll no longer fails the next build

Five landing-lane tooling defects, one group (wave 20261107 group D, campaign PB1957). None touches COBOL semantics: no inventory row, no diagnostic code, no conformance golden. Each is pinned by script self-test arms, which the self-test runner runs in every gate and in CI, and by drift tests that keep the arms and the wiring from going away.

**PB3714: one home for `=== ENQUEUE: <OUTCOME> (<branch>) ===`.** The prefix was a literal in `enqueue.py` (the writer), a regex over it in `land_lane.py` (the reader) and a second literal in `merge_drivers.py` (the CONFLICT reader), and nothing failed if one was changed without the others. The new leaf module `scripts/verdict_line.py` owns the line (`PREFIX`, `render`, `parse`, `outcomes`) and the CONFLICT outcome inside it (`conflict_outcome`, `outcome_files`, `conflict_files`, moved out of `merge_drivers.py`). `enqueue.py` writes through it; `land_lane.py` and `merge_drivers.py` read through it; the old definitions are deleted, not aliased, and every caller (including `enqueue.py`'s and `land_lane.py`'s own self-test fakes) was changed. It is a leaf because `enqueue.py` imports `merge_drivers.py`. `LandingLaneDriftTests.NoScriptSpellsTheVerdictLine_OutsideItsOneHome` fails when any other script under `scripts/` opens a string literal with the prefix (and a planted-spelling arm shows it fires).

**PB3113: a reused pid read RUNNING.** `land_lane.pid_alive` accepted any live Python with the recorded pid. Reproduced with two real processes. `runner_alive(attempt)` now requires the process to be a Python whose command line names the attempt's own record (`land_lane.py run <record>`), through the new `coord.process_command`; a pid the OS handed to another program carries another command line and reads dead, so `reap` marks the attempt DIED. An unreadable command line is not called dead (that would relaunch a branch beside its live runner). No start-time token was recorded: the record path is already unique per attempt and a start time read at launch can miss a fast runner.

**PB3157: a merged branch ended exit 6.** The note's first half (two runs of one branch side by side) was already fixed by PB3310's land lock (exit 13) and has an arm in `enqueue.py --self-test`. The second half reproduced: `land` tested only `HEAD == origin/main`, but a branch the queue merged has its tip as an ANCESTOR of main, fell through merge, stamp and title, and ended exit 6 NO ENTRY (which the lane reads as a stop). It now ends exit 0 `NOTHING TO LAND — the branch's tip is already on origin/main`, before the queue guard; the arm merges a branch with `--no-ff` and requires no gate, stamp or `gh` call (mutation-checked: without the test the arm fails).

**PB3642: the merge queue merges without the merge drivers.** GitHub builds the merge group server-side with plain git, so two queued pull requests that change one driver-covered file (a keyed catalogue, a work note, the ABI pin) conflict inside the queue though each merged main through `merge_drivers.py` locally. The queue cannot be given the drivers, so landings are serialized per file. `driver_file_holders` (the one reader, beside the now-shared `open_pull_requests`) intersects the branch's own changed files, filtered by `merge_drivers.covered_by_driver`, with the files GitHub lists for every other open pull request; a hit ends the new exit 16 `DRIVER FILE QUEUED` before anything is stamped, pushed or queued, and the lane retries it at the same head once none shares a file (`WAITS`, `driver_files_free`), after which the merge of main brings the other change in through the drivers. A file list GitHub cut off at 100 holds the branch for all its driver files. A repository-wide queue-entry lock (`<git common dir>/cobol-queue-entry.lock`) is held from the look to the queueing so two landings the lane starts side by side cannot both look and both queue. The self-test builds one branch that changes the sample file of EVERY `DRIVERS` pattern, so a new driver is guarded with no new line; `MergeDriverDriftTests.TheLanding_WaitsForAnOpenPullRequestThatSharesADriverFile` holds the wiring.

**PB3674: a language server's lock on `Cobol.Net.Compiler.SourceGen.dll`.** The session's csharp-ls loads the generator from `bin\` and holds it for the life of the session; Windows will not overwrite a loaded image, so every later build in that worktree (the landing's ABI-pin settle, a finisher's gate) failed with MSB3027/MSB3021. Reproduced with a PowerShell 7 process that `Assembly.LoadFrom`s the DLL. A loaded image can be renamed, so the generator project's `MoveAsideHeldOutput` target (every build of it, so every caller at once) deletes a stale output and, when it is held, renames it aside as `<name>.<guid>.held` before the copy; an unchanged output is untouched (incremental builds stay incremental), held copies are deleted when they can be, and an unrenamable file still fails loudly. `scripts/test_held_analyzer_output.py` (Windows self-test) rebuilds a scratch copy with a real holder (premise, fresh-output rebuild, no-op rebuild, holder gone), mutation-checked; `HeldAnalyzerOutputDriftTests` requires the target in every project that sets `IsRoslynComponent`. Solution-wide there is one such project.

**Self-review** (pr-test-analyzer, silent-failure-hunter, comment-analyzer lenses over the diff): the first draft of `runner_alive` returned False for an unreadable command line (a silent "dead" that would have relaunched a live runner's branch); it now treats that case as alive and has an arm. `covered_by_driver` matches by suffix (`PurePosixPath.match`), so a path under another prefix can hold a landing for a few minutes; that only waits, never loses a landing.
