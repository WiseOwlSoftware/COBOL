## An EXTERNAL file's print-file fact is shared by every describing program of the compilation group (PB5570)

kb/Work PB5570: a plain WRITE to an EXTERNAL sequential file whose ADVANCING writes are in another program of the run unit wrote a bare record (P1 and P2 on one line) until that program was first activated, because `FileRegistry.Register` merged `AdvancingDeclared` per describer on activation. Re-probe on this build (`ext.cob` from the note, `--std 85`): 20 bytes `P1  P2  \n\nA2  \nP3  \n`, as the note measured.

Fix: whether the connector is a print file is the ONE connector's property, so `ExternalFileConnectorRules.ShareAdvancing` (called by `BinderDriver` beside the group's other external-connector rules) sets `FileModel.WrittenWithAdvancing` on every describer of an external name when any describer has it. After: 22 bytes `\nP1  \nP2  \n\nA2  \nP3  \n`, identical to the internal GLOBAL control. Golden: `conformance-suite/cases/VII.4.7@1985-WRITE-STATEMENT/1985-GR-VII_4_7_4-16-external` (values computed from §1985:VII.4.7.4 GR16, cite checked). Sweep: LINAGE is passed per WRITE by the executing element, not merged at registration, and §1985:VII.3.7.4 GR11 requires the same values in every describer, so it has no late arrival; the record area and CODE-SET registrations are per-describer calls on the same connector with no per-WRITE effect. The row 1985-GR-VII.4.7.4-16 stays PARTIAL: an external describer compiled apart from the group is still reached only at its activation (the run time's merge).
