## Entry 1995 — 2026-10-12 23:23 PDT — PB3117: the landing lane's runner no longer opens console windows on the desktop

The owner reported terminal windows that flashed up, took focus from their work, and in one case stayed open, blank. `land_lane.py`'s `spawn` (PB3103) started each landing runner with `DETACHED_PROCESS`, which leaves it no console. So every console program a landing started (`enqueue.py`, `git`, `pwsh`, `dotnet`) got a new console, and with Windows Terminal as the default terminal each one opened a window. The window that stayed open belonged to `enqueue.py land` itself, running a gate with its output in the attempt log. The runner now starts with `CREATE_NO_WINDOW`: a console of its own with no window, still separate from the supervisor's, which every child inherits. On this workstation a child started that way reports console code page 437 and no visible window; one started with `DETACHED_PROCESS` reports code page 0, meaning no console. Self-test case 13 requires that. The sweep found one other `DETACHED_PROCESS` launch, the telemetry sink, which starts no children and stays as it is.
