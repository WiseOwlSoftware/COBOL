## PB4818: a report group's level-number before a header reports at the header's first word, and the slot has one wording

**Re-probe.** `REPORT SECTION.`, `RD R.`, `01 SCREEN SECTION.` drew COBOL0307 at (6,18), the word SECTION; the same line in the working-storage, linkage, file and communication sections draws it at SCREEN. The sweep found two more faces. `01 LOCAL-STORAGE SECTION.` after an RD drew COBOL0001 at SECTION where the screen and data slots stop at the word. At 85, where SCREEN is a user word and the format prints no such section, the report-group line named a missing period where the working-storage line draws the plain report at SECTION. The slot also had two wordings of one fault: `unexpected 'FILE'` and `cannot parse construct near 'LINKAGE'`.

**Mechanism.** The note filed this as a name predicate; `dataName` in fact refuses the word already (`noHeaderWrittenHere`, PB4706). `reportDescriptionEntry` decides between `constantEntry` and `reportGroupEntry` before the level-number, and adaptive prediction evaluates a predicate only at the left edge of its decision. So the predicate never ran, both entry kinds survived the gated word, and the prediction died at SECTION with the parser still before the level-number. The screen section's loop escapes only because `screenName` admits no gated word, so `constantEntry` wins alone and enters the entry, where the predicate is asked.

**Fix.** `CobolErrorStrategy.HeaderAnEntryLoopReadAsAName` moves such a report to the header's first word: a reservation-gated word before SECTION or DIVISION at which `OffendingPosition.FollowsALevelNumber` holds. Everything after that follows from the position. The period question decides COBOL0307 or COBOL0001 (§13.2.1), and `NoteGatedOffender` reads the offender, so at 85 the word is retyped, the re-parse takes it as the name, and the report is the working-storage section's at SECTION. No edition test was added. The report's range still reaches the token the prediction died at, so the recovery does not report the fault twice. `Report` words every slot that yields (`EntrySlotYields`) as `unexpected 'WORD'`: which decision met the word is the grammar's shape and tells the user nothing. The two pins that read `cannot parse construct near` at the slot (`pb4706-entry-name-before-local-storage-section`, `pb4788-header-out-of-order-after-a-screen-entrys-level-number`) and their unit theories moved with it.

Restructuring the grammar so the prediction stops at the word was rejected: the loop's decision needs both entry contexts, and factoring the level-number out would change the CST every report and screen binder reads, to move one diagnostic.

Also corrected the clause numbers in `ClosedFormats.EntryAwaitingItsName`'s comment (review lead R1-1 on PB4788): the entries' formats are §13.17.2 and §13.15.2, not their sections' §13.9.2 and §13.8.2.

**Self-review.** Architecture: the rule is one test in the report path, and it asks the slot's own question rather than a second copy; the first draft compared token indices by hand and could have fired after an integer in a procedure statement, so it was replaced by `FollowsALevelNumber`. Performance: error path only, and only at SECTION or DIVISION. Duplication: no second predicate; the design doc carries the paragraph. Found and left for the registrar, as other mechanisms: an unnamed report item with a gated USAGE word is read as a name (`10 NATIONAL COLUMN 1 PIC N(3) ...` draws COBOL0901), and `SCREEN SECTION.` then `01 SCREEN LINE 1.` draws COBOL5506 "expected CONSTANT" rather than naming the reserved word.
