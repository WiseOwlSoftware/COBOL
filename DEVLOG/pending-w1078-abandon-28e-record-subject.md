Writing those records exposed a defect (kb/Work PB3161, landed here) in `prune_worktrees.abandon_record`, the guard that refuses `--abandon` until a kb/Work note records the decision. It accepted any line that named the branch and contained the word ABANDONED. A superseded branch's record names its successor ("`old` ABANDONED, superseded by `new`"; PB1688 and PB1941 carry lines of that shape), so the same line also passed as a decision to abandon `new`, the branch that carries the work. An unrecorded `--abandon new` then deleted it. A line now abandons only the branch the word ABANDONED directly follows: the name, then punctuation, one parenthetical or a copula, then the word. The branch review caught that the first version, which asked the survey for the other branch names on the line, stopped refusing once `old` itself had been deleted (the next survey no longer knew it), so the guard now reads the line alone. The self-test's record names a successor both before and after the word and is checked again with the abandoned branch gone; with the old matcher the run goes RED (three checks), because `split-branch` is deleted. With the new matcher it is GREEN, and a census of the 67 branches kb/Work already records ABANDONED finds each still resolves while the successors those records name do not. The record rule is reworded to match in MANDATORY-PRACTICES O10, the workstream skill's landing reference and the resume unit.

The branch also carries the GAP trend points that the 2026-10-14 ledger render appended to `docs/rearchitecture/evidence/ledger-trend.json` in the main checkout.
