## PB5199 and PB5201: REVERSED is ignored on a medium that cannot be positioned, and a file's print capability is a property of the program

Group D of wave 20262000 (one root: `SequentialConnector`).

**PB5199.** Re-probed first. On Windows a FIFO cannot be opened, so the case is reachable on Linux only; the note's own probe (`OPEN INPUT F REVERSED` on a FIFO) read 00 then 30 on every READ. §1985:VII.4.3.4 GR10 ignores REVERSED on a medium it does not apply to. `OpenCore`'s INPUT arm now asks the one handle it opened whether it can seek: if not, no record count is taken (counting a stream that cannot be rewound would eat the records) and `_reversedInapplicable` makes `PositionReversed` a no-op, so the file reads forward. Witness: `ReversedUnpositionableMediumTests`, over `FaultHostMedium`'s new `NonSeekableReads` handle (a COBOL program cannot make a FIFO, so no golden can); with the guard disabled its FIFO arm reads nothing forward (checked by mutation). The positionable control still reads REC3, REC2, REC1. docs/CONFORMANCE.md (OPEN row) states the determination.

**PB5201.** Re-probed: the note's `plainw.cob` at `--std 85` wrote AAABBB LF CCC LF. The cause was `SupportsVerticalPositioning` reading the capability from the run's history (`_printControl` set by the first ADVANCING write). Decision (sidecar `kb/Work/PB5201/2026-11-11-decision-positioning-is-compile-time.md`): the capability is the program's. `SequentialIoBinder.BindWrite` sets `FileModel.WrittenWithAdvancing` when any WRITE of the file names ADVANCING; `EmitFileRegistration` passes `printFile: true`; `FileRegistry.Register` stores it as `SequentialConnector.AdvancingDeclared` (an EXTERNAL connector's later describer ORs it in). After the fix the probe writes LF AAA LF BBB LF CCC LF, the file the all-spelled-out program writes. A file no WRITE of which names the phrase is unchanged (no leading empty line, GnuCOBOL's default). Golden `VII.4.7@1985-WRITE-STATEMENT/1985-GR-VII_4_7_4-16-plain-first` (the mixed file and the plain-only control); unit `PrintFileDeclarationTests`. docs/CONFORMANCE.md section 4 and docs/FILES_DESIGN.md carry the revised determination, which closes the owner question PB1027 left open.

No inventory row is closed: both rows are 1985 ids that `work.py check` refuses in `inventory_rows` (PB5094). No diagnostic codes used.
