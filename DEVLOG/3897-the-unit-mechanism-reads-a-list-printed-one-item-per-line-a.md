## Entry 3897 — 2026-11-21 04:38 PST — The unit mechanism reads a list printed one item per line, a table printed across pages and a 1985 folio pointer, and places the 72 unread 1985 margin paragraphs (kb/Work PB5998)

kb/Work PB5452's pilot, deciding the first forty 1985 units by hand, found three defects in the mechanism PB5449 landed
(PR #1922). This change fixes them in the one segmentation and the one class test, and changes no catalog row.

**Re-probe.** On main at 471ce00a4f the 1985 reader produced 956 units, 15 of them numbered items, and every one of the
15 held a whole list: §1985:IV.4.2.2.1.1's first unit read "1. alphabet-name 2. cd-name 3. class-name ...". The 1985 PDF
(page 152) prints the list one item per line, and the transcription keeps it that way, so no blank line separated the
items and `segment` started an item only after one. The same clause's second list took label `1` again, as did four of
§1985:X.1.3.8's five lists, so the rows the mint would make from them shared ids. §1989:A.2.4's Table 1, printed over
three pages with its header repeated on each, read as three tables all numbered 1, with `T1.1` to `T1.9` three times;
2002 had the same shape in §2002:14.4 (Table 13), §2002:14.5.12.1.5 (Table 14) and §2002:15.5 (Table 22). And
`class_refusal` refused "See page VI-13, The SPECIAL-NAMES Paragraph." as "no pointer", so no pure 1985 pointer could
ever be disposed `cross-reference`.

**The fix.** An item now starts at its own marker: after a blank line, or on the next line when its number is the open
list's next. A clause's lists are counted, an item's number not following the last item's starting a new list, and an
item of the m-th list is labelled `L<m>.<n>`, the form a rule block's later list has (an addendum to decision PB5448
point 2, recorded beside the note and in the design). `Unit` carries the row's `ordinal` and `sublist`, replacing the
extractor's separate function that parsed them from the label. A table part whose number and header match a table
already read in the clause continues it, its rows numbered on, and its kind is judged over the whole table; `segment`
refuses a clause whose units would share a label instead of minting one id twice. The pointer grammar reads a printed
page, alone or several joined by "and" or ";" ("See page VI-11, ..., and page VI-13, ...", "is specified on page
..."), through one parser, `pointer_targets`; the extractor's resolver accepts a page only when `citation.page_texts`
shows the page printing the pointer's title, so a page with no title, or the wrong one, still fails.
