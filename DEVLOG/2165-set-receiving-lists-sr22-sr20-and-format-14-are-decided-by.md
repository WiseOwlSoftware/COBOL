## Entry 2165 — 2026-10-17 16:43 PDT — SET receiving lists: SR22, SR20 and Format 14 are decided by the whole list, never by the first receiver

Two R2 review findings (PB3224, PB3225) shared one shape: a SET binder read `targets[0]` for a rule the standard states over every receiver, so the verdict depended on the order the receivers were written.

**PB3224.** `SET UPP RP TO ADDRESS OF PROGRAM RPAPB` (UPP unrestricted, RP restricted to a prototype of another signature) compiled clean, and so did the literal and identifier senders, while `SET RP UPP ...` drew COBOLNET1959. `BindSetProgramAddress` kept one `receiverProto` from the first receiver; an unrestricted first receiver made every compare vacuous. `BindSetFunctionAddress` had the same shape (a first receiver restricted to an external-repository prototype with no compile-time signature passed every compare). Fix: §14.9.39.3 SR22 / SR20 is asked of each receiver against the sender, `RestrictedReceiverNeedsPrototype` takes the receiver list, and the receivers-among-themselves check became `ReceiversDisagreeing`, which compares every pair because `PrototypeSignatures.Same` conforms on a missing signature and is therefore not transitive. The function twin's run-time GR14 formal count comes from the first receiver with a compile-time signature. The vendor `TO ENTRY` spelling stays outside SR22, as documented.

**PB3225.** `SET WS-N WS-CAP TO 5` and `SET IX WS-CAP UP BY 1` selected Format 14 (the nearest row for any list holding a register), then `BindSetCapacity` read only `targets[0]`, found no register and returned `BoundUnsupported`: a not-implemented warning and a run-unit abort for illegal source, while the register-first order drew COBOLNET1524. Fix: the whole list is screened first through the new `SetFormatSelection.ReportNotSoleReceiver` (an operand the brace does not admit is named first, SR29, else the count since data-name-2 has no ellipsis), COBOLNET2112 in both orders. COBOLNET1524 was a bare uncatalogued literal used at this one site; it is deleted. The "register could not be addressed" arm was unreachable and is now an invariant exception. Format 16 (`BindSetSize`) uses the same helper and its sole-receiver bind is split out.

Re-probed on the branch build before the fix (all reproduced). Goldens in `conformance-suite/cases/14.9.39-SET/`: three program-address refusals (prototype, literal, identifier sender with the unrestricted receiver first), one function-address refusal (external-prototype receiver first), five Format 14 refusals (register second and first, TO / UP BY / DOWN BY, two registers), and two accepted receiver-order witnesses; every citation went through `cite.py --check`. No inventory row closed (the rows already read CONFORMS). Sibling sweep: no other `targets[0]` read precedes its list check in the SET family; the pointer-to-pointer arms already compared per receiver. Self-review found no duplicated rule; the one design note is that deleting the old pre-pass outright (the note's suggestion) would have dropped a sound refusal for an unknown-signature sender, so it was kept in order-free form.
