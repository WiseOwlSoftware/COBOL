**PB5568.** A section with no paragraphs owned no pc, so `USE FOR DEBUGGING ON <empty section>` compiled to C# naming an undeclared `__dbgItem` (CS0103) and ALL PROCEDURES skipped it. Re-probe on this build: the three repros reproduced as the note says. The premise in `AddNamedDebugSubject` ("a section of no paragraphs is never executed") was wrong: the PERFORM of it and the fall-through into it execute it. Fix shape: where a debugging section is compiled, `CollectNondeclaratives` gives a zero-paragraph section the one no-op pc a declarative section already had (`AddEmptyAnonymousParagraph`), so the subject is recorded by the existing section-subject path and the dispatcher fires the trigger (PERFORM LOOP, FALL THROUGH, START PROGRAM); DEBUG-LINE is the section header's line (1985 GR12 leaves it to the implementor). In a program with no debugging section an empty section keeps its empty range, so PB440's empty-set PERFORM contract and every generated source without debugging are unchanged.
