## The gate's preflight: a stale pin ends the gate before the whole population runs

The owner ordered it on 2026-11-16, ahead of the remaining 1985 fixes (kb/Work PB5872): "why ... are we waiting for a known red to appear, then handle the error?". That day five of six fix branches of one lane needed a second or third gate, and four of those reds were visible in seconds. One run's only red was an emitted-C# snapshot the Characterization host finished 22.1 s after it started, in a run whose test phase took 981.6 s more.

**The stage.** A code-lane gate now runs, after the build and before the population, the test classes `scripts/build_targets.json` declares as a target's `preflight`: classes whose red means a derived or pinned file is stale. They run in one host per declaring assembly, all at once, each handed its classes through the one retry hook. A red one ends the gate `RED — PREFLIGHT RED: <assembly> <case>`, and the population does not run. A green one leaves the population to run less its cases. The population check reads the preflight's trx beside the host's, so a case run twice is RAN TWICE. The record's `preflight` and `preflight_s` let a later measurement count what the stage saved.

**What it holds, and how that was chosen.** From this host's 166 gate records (26 with a test red), ranked by how often a class was a run's only red: the Characterization target whole (EmittedCSharpSnapshotTests, the only red of 2 runs), RuntimeAbiPinDriftTests, BinderMemberReadersDriftTests, DocumentedFactsDriftTests, ArchitectureEdgesDriftTests, BackendContractDriftTests and ArchOracleDriftTests. That is 11 classes, 12.4 s in the committed merge-group weights, against a budget of 10 s a class and 15 s in all. The BUILD TARGETS audit refuses a declared class that no source declares, that no weight measures or that is over budget. SpecTraceabilityInventoryDriftTests (36 s) and the behaviour reds are left out. Measured by hand after a fresh build, the preflight took 56.9 s the first time (the first load of the freshly built assemblies) and 14.9 s warm.

**One point of the decided shape changed.** The note put the stage before the slot wait. Its cases need the build, and the slot rations the build, so the stage runs inside the slot, after the build. It saves the population's test phase, never the slot wait: about 925 s of the snapshot run above and about 423 s of the ABI-pin run. The two runs stopped by the public API baselines were already fail-fast as an audit.

`scripts/selftests/gate/test_preflight.py` covers a red, a green with one whole assembly and part of another, a case run twice, a declared class with no case, the audits and the other lanes unchanged, and re-gates. Its arms were seen to fail with the early return disabled and with the plan's exclusion disabled.
