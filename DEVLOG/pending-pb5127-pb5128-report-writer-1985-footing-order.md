## A control footing's USE procedure runs after its crossfoot and roll-forward, and at --std 85 its page groups see the current control values (PB5127, PB5128)

Both notes came from the 1985 witness-drafting pass and share one root, `CobolReport` in `src/WiseOwl.Cobol.Runtime/IO/ReportWriter.cs`.

**PB5127.** §1985:XIII.3.20.4 GR10 orders a control footing: a) crossfoot, b) roll forward, c) the USE BEFORE REPORTING procedure; §2023:14.9.49.4 GR9 b) invokes the declarative "After incrementing sum counters defined in the report group". `BeginGroup` ran the USE procedure first, so a procedure reading CROSS or GRAND saw the previous instance's totals. Re-probe on this build (probe `RWCFSEQ` of the note, `--std 85`): `USE CF-K A=003 B=030 CROSS=0000 GRAND=0000` where the text requires `CROSS=0033 GRAND=0033`. Fix: `BeginGroup` takes the presence snapshot, performs the group's own additions (`ApplyRolled`), then runs the hook. The snapshot has to come first because §2023:13.18.54.4 GR11 reads it for those additions; it stays one answer per presentation (§2023:13.18.41.4 GR2). Every edition, since 2023's GR9 b) says the same. After the fix the probe prints the note's seven expected lines. Golden `cases/14.9.49-USE/pb5127_use_before_reporting_sees_crossfoot` (85 to 2023).

**PB5128.** §1985:XIII.3.20.4 GR13 a)/b) gives the prior control values only to a control footing's own USE and SOURCE references (and, at TERMINATE, the report footing's); c) gives every other reference the current values. §2023:13.18.16.4 GR4 a) and the 2002 text give a footing's page advance's page heading and page footing the prior values too. Re-probe (`GENBRK`, `--std 85`): `PF A 2` / `PH A 2` where the 1985 text requires `PF B 3` / `PH B 3`. Fix: a `DialectBehavior` member (`ControlFootingPageGroupsSeePriorControlValues`, edition 2002, VCR row 7.54, both editions quoted), `CobolReport.Edition` baked in by `EmitReportConstruction`, and `WithPageGroupControlValues`, which exchanges the saved current values in for the duration of `AdvancePage` (page footing, page heading, OR PAGE headings) and of the TERMINATE page footing while `_footingPhaseCurrent` is set. The TERMINATE page footing is the sibling arm found in the same function; the report footing keeps the prior values (GR13 b). Goldens `cases/13.18.16-CONTROL/pb5128_footing_page_groups_control_values` and `pb5128_terminate_page_footing_control_values`, each with `.85.out` and `.out` (2002 and later).
