## Two Report Writer screens that let a wrong 1985 description through (PB5866, PB1003)

**PB5866: `CONTROLS ARE B R66`, where `66 R66 RENAMES B`.** Re-probed at `--std 85` on this branch before the fix: the program compiled and printed `RAN`, while `CONTROLS ARE B B` was refused COBOL1699. `§1985:XIII.3.7.3 SR2` asks that each recurrence of data-name-1 identify a different data item, and `§1985:VI.5.11.4 GR2` gives a level-66 entry without THROUGH all the data attributes of the item it renames: the two names identify one data item. `ScreenControlItemsDistinct` compared the resolved entries; it now compares each operand's `DataItem.AttributeItem`, the one model-layer reading of a no-THROUGH alias, so no level-66 special case lives in the screen. Sweep at 85 (expected from the two rules): `R66 B`, two level-66 names of one item, a level-66 of a group against the group, `FINAL B R66` all refused; a THROUGH alias and a REDEFINES item stay accepted as other data items. 2023's `SR6` lets two instances refer to the same physical data item, so 2002 and 2023 are unchanged. Goldens: `pb5866-controls-renames-one-item-85` (refused COBOL1699) and `pb5866_controls_distinct_items_85` (runs, the control footings in break order). Row `1985-SR-XIII.3.7.3-2` gains both witnesses (record_verdicts `--edition 1985`); its stored code read is owed a re-read on the fixed code.
