## An unsigned 16-byte COMP-5 operand reaches no Int128 site raw: level-88 tests, COMBINED-DATETIME and the binary64 conversion

PB6265, PB6266. One root: a `NumX.U` operand (a 16-byte unsigned COMP-5 read, a `UInt128`) was handed to an `Int128` site without entering the funnel the arithmetic lane uses (`NumericRenderer.DeU`, or the `CompareU` overload set for a comparison). C# has no `==`, `<=`, `>=` or implicit conversion between `UInt128` and `Int128`, so each site was a Roslyn error (CS0019, CS1503) on legal source with no COBOL diagnostic.

Re-probe on this tree before the fix (`run_probe.py --std 2023`): `01 U PIC 9(25) COMP-5` with `88 U-BIG VALUE 1000000000000000000000` and `88 U-RNG VALUE 5 THRU 2000000000000000000000` gave `error CS0019: Operator '==' cannot be applied to operands of type 'UInt128' and 'Int128'` (and the same for `<=`); `COMPUTE R = FUNCTION COMBINED-DATETIME (D S)` with `S PIC 9(20) COMP-5` gave `error CS1503: Argument 2: cannot convert from 'System.UInt128' to 'System.Int128'`.

PB6265. A numeric level-88 test was a third numeric comparison: `RenderMembershipTest` wrote `read == literal` and `read >= lo && read <= hi` over the raw field read. A condition-name test compares by the relation-condition rules (§2023:8.8.4.5.3 GR2), so each numeric VALUE entry is now the relation pair it is, built as `BoundRelational` nodes over the conditional variable and a `BoundNumericLiteral` (or the figurative-ZERO operand `IF X = ZERO` binds) and rendered by `RenderNumericRelational`. The raw arm, `NumericMembershipValue` and `FloatMembershipValue` are deleted: the float, SDIDI, scaled and unsigned-wide arms are the relation's, with no second copy. The string arm keeps its own method, `RenderStringMembershipTest`; `RenderMembershipTest` is the dispatcher between the two.

PB6266. The COMBINED-DATETIME arm took argument-2 raw from `RawArg`. §2023:15.17.3 AR2 constrains argument-2's value, never its usage, so the arm now binds `NumericRenderer.DeU(RawArg(ic, 1))`, as `SecondsArg` does for FORMATTED-TIME.

Sweep (the same root, other sites): a probe of every numeric intrinsic over an unsigned-wide integer and an unsigned-wide scaled (`PIC 9(18)V99 COMP-5`) argument found three more CS1503s: SQRT, ATAN and ANNUITY over the scaled item, from `NumericRenderer.Real`, whose scaled arm passed the `UInt128` to `CobolFloat.ScaledToDouble(Int128, int)`. `Real` now routes a scaled unsigned-wide operand through `DeU` (scale 0 keeps its exact `(double)` cast), and `ScaledSingle`, the binary32 twin, routes every unsigned-wide operand the same way. A second probe over MOVE and COMPUTE to FLOAT-SHORT and FLOAT-LONG, relations against floats, EVALUATE, SET and the arithmetic verbs found no further site.

Guard: `IntrinsicCarrierAgreementDriftTests.EveryRawArgBinding_EntersTheUnsignedWideFunnel_OrTakesEveryCarrier` fails on any `NumX v = RawArg(...)` binding in `IntrinsicRenderer` that neither wraps `DeU` nor sits in the closed list of the two helpers that take every carrier; its detector has a self-test that fails on the COMBINED-DATETIME arm as it was written.

Goldens: `pb6265_level88_unsigned_wide_comp5` (2002, 2014, 2023; a 25-digit and a scaled 22-digit COMP-5 variable, singleton, THRU, list, ZERO, NOT and SET ... TO TRUE, expected values derived from §2023:8.8.4.5.3 GR1/GR2) and its 85 negative (COBOL0802); `pb6266_combined_datetime_unsigned_wide_comp5` (2014, 2023, expected values from §2023:15.17.4 RV1) and its 2002 negative (COBOL1502); `pb6266_unsigned_wide_scaled_float_arguments` (2014, 2023; SQRT(2.25), ATAN(0), ANNUITY(0, 4), each exact).

Rows: none re-verdicted. The rows the notes touch (GR-8.8.4.5.3-1/-2, AR-15.17.3-2, RV-15.17.4-1) were CONFORMS and stay so; both notes write `closes_rows: []` with the reason.
