This branch also carries kb/Work PB5844 (RECORD DELIMITER, merged from its branch) and the records-1985-code-reads-3
commits (cherry-picked; the PB5860 commit and its revert were skipped as a pair, net zero), each with its own pending entry.

**PB5805: WRITE ADVANCING integer-1 is unsigned.** Re-probe: `+3` and `+0` compiled at `--std 85` and `--std 2023`. The
integer of a general format is "neither signed nor zero unless explicitly allowed" (`§1985:III.2`) and integer-n is
"unsigned and nonzero unless otherwise specified" (`§2023:5.5`); SR5/SR15 lift the zero default only. One predicate,
`NumericLiteral.IsUnsignedForm` (`§2023:8.3.3.3.2 SR2`), is read by `SequentialIoBinder.ScreenAdvancingCount` and by the
CONCAT and BASECONVERT argument screens; the sweep found BASECONVERT asking for `-` only (`BASECONVERT(+101 2 10)`
compiled, now COBOL1642). COBOL2365 now cites the edition's own rule.

**PB5876: an OCCURS DEPENDING ON object is an implicit reference.** Re-probe: `lk_odo.cob` compiled and displayed `L1` as
empty, its object `LN` in a LINKAGE record that is no USING operand. A statement references the items that contribute
to it (`§1985:IV.4.4.1`; `§2023:8.4.5`), so `§1985:X.5.1 GR4` / `§2023:13.7.3 SR4` reach the object. The objects asked
are the extents the operand's place evaluates (`OdoDependence.ExtentObjects`, split from the option-dependent GR7 bound
tests within the one `Rebind` walk), screened in `ReferenceResolver.ResolveImplCore`; SEARCH's end object is screened too.
kb/Work PB1249's written-only reading is overturned (`docs/INTERPROGRAM_DESIGN.md`). Lead left: the file clause operands
(FILE STATUS and the rest) in such a record are implicit references of every I/O statement, and no funnel asks them.
Branch review round 1 (R1-1) found the Format-2 table SORT unscreened: it reads the table's current count
(`§2023:14.9.40.4 GR20`) beside its operand's place, and `SORT L-E` compiled and sorted nothing. The sweep of the count's
readers found a table(ALL) intrinsic argument (`§2023:15.3`) the same, ending its run with EC-ARGUMENT-FUNCTION. Both
now ask `NameResolution.ScreenImplicitLinkageCounts` and give COBOL2746 at 2002, 2014 and 2023, pinned by two refusals
and two controls under `13.7-Linkage-section` (`W-1=CDEBA`, `MAX=C`).

**PB5878: both modes' USE procedures declared.** Re-probe: `r1-modes.cob` ran the attempted mode's procedure. The text
names no order, so CLAUDE.md rule 1 gives GnuCOBOL's: the procedure of the mode the file is open in

read GR6 as excluding the mode the file is open in); its three refused OPENs of the file open INPUT now run `USE INPUT`,
