## Work register: a Linux gate that hung for almost 7 hours is traced to two landings of one branch sharing its snapshot (PB3310)

A Linux gate held a gate slot from 10:15 to 16:57 on 2026-10-16. The slot is one of three, so landing capacity was a third lower for that time. The gate was running for `notes-leads-enqueue-20261016d`, which had already merged at 10:34 as pull request #127. Two `enqueue.py land` runs of that branch had overlapped: a unit's `nohup` launch is outside the landing lane's attempt tracking, and `enqueue.py` has no per-branch lock. `linux-gate.sh` keys its WSL snapshot and its log directory on the tree's basename and deletes both at start, so the second run removed the first run's clone while the first was still testing in it. The first run's `dotnet test` processes then deadlocked in directories marked `(deleted)`, and nothing surfaced a slot held some 60 times longer than a Linux gate takes. The operator stopped the stale tree after re-reading its command line. PB3310 gives the fix: a per-branch lock, per-run snapshots removed on exit (which also closes PB3194's disk leak), and a surfaced ceiling on how long a slot is held.
