## Work register: the $200 API credit gets a note (PB3309), blocked on the owner's sign-in

The owner said the WiseOwl Software API organization holds $200 of API credit, to be used before 2026-11-04. It came from linking account 1 to that organization. Account 2 could only join the organization as a member, and its own credit did not apply. Account 2's billing page says "None of your API organizations can be linked. Create one to start receiving credits." So its own $200 a month needs a new organization of its own, which is an owner action.

The telemetry gives the exchange rate. Account 2 spent about $300–340 of API-priced tokens on 2026-10-16 while its meter moved about 12 points, so a Max weekly point is worth about $25–30 at API prices and the credit buys about 7 points. The difference comes from cache reads: the API bills them, and the subscription meter's calibration does not count them. PB3309 records what the lane needs: the owner's one-time sign-in of a dedicated config dir, an account row of kind `api` with a dollar cap and an expiry, and a check that API-key telemetry is attributed. Telemetry without `user.account_uuid` is counted against both Max estimates today. The note also says when to spend the credit: as overflow while both Max accounts are held.
