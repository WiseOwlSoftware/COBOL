## PB4467 - construct citations name the ISO rule only, and an audit refuses the next one that does not

`ConstructRegistry.Check` interpolates a row's `citation` from `tests/version-matrix/constructs.json` into the edition-gate message and passes it as the diagnostic's citation. The DataBinder extracts (PB2296 to PB2361) move the members those citations named, so each move edited a message a user reads and a deleted member left a citation pointing nowhere.

**Re-probe.** On the pre-fix build, the `range-in-alphabet-2002` source at `--std 85 --source-format free` printed `error COBOL0900: the THROUGH range's IN alphabet-name phrase requires COBOL-2002 (targeting COBOL-85) - ... a COBOL-2002 addition (derived - no 85->2002 row in the 2023 Annex E, the A1 gap D18); bind-site gate (DataBinder.TryResolveRangeAlphabet))`. After the fix the message ends at `a COBOL-2002 addition)`.

**The note counted seven; the data had 132.** 132 of the 312 `citation` fields (a row's, and the `directiveOperand` and `directivePlacement` blocks') named a C# member (`CopyProcessor.GateCopyPhrase`, `PictureAnalyzer.AnalyzeCharacterString`, `CobolPtr.UpByAmount`), a grammar rule (`repositoryEntry`), a file (`CobolParserCore.g4:487`, `v200112.txt`), an emit-site or gate pointer ("parse-arm gate", "introduction gate"), a status ("LIVE (Phase 4d)"), a DEVLOG or register id, a decision id (D8, D18) or a spec line pointer (`@10459`). A scripted pass dropped the segments and parenthetical groups that matched, a hand list of overrides restored the rows whose ISO text sat inside a dropped group, and every changed row was read after the pass. Each citation now names the ISO rule and the VCR row only. The pointers were dropped, not moved: the construct id and its diagnostic code find the gate, and the rows' `description` fields keep the fuller notes. `ConstructRegistry.g.cs` is regenerated.

**The check** is `CONSTRUCT-CODE` in `scripts/spec/audit_code_citations.py`, the audit the gate and CI already run as CITATIONS. It reads the JSON and refuses a citation matching a code shape (C# member, source file, call, PascalCase, camelCase or SCREAMING_SNAKE identifier, generic type, leading underscore) or a project-history shape (LIVE, DEVLOG or register id, phase, wave or step marker, emit-site or gate pointer, decision id, spec line pointer). Shapes rather than a member list, so the next moved member is refused with no edit to the audit. Its `--self-test` fires one arm per kind of token it refuses (fifteen, each declared in `scripts/self_test_arms.py`) on a citation shaped as it shipped, and stays silent on the repaired twin of each and on a GnuCOBOL/ISO/VCR citation.

**Goldens.** The only goldens that held a citation tail were two characterization snapshots, `char_neg_occurs_dyn85` and `char_neg_typedef85` (the gate's Characterization leg went RED on them); regenerated, and their diff is the dropped tails (`data-model D9 - the CobolDynTable<T> growable substrate`, `data-model D17 ... LIVE (weak-TYPE spine)`, `ISO-validation DEVLOG 582; decision-1 policy`) and nothing else. Conformance 21,024/21,024 and Unit 39,527/39,527 were green at that gate. The first run found one more defect of mine: `GR1/GR2` under `§13.18.42` with no `.4` (DIAG-UNQUALIFIED), now `§13.18.42.4 GR1/GR2`, checked with `cite.py --check`.

**Branch.** The first implementer built this on the PB2296 integration branch, still queued as PR #1054 and in conflict with main. The three PB4467 commits do not depend on it (constructs.json, `ConstructRegistry.g.cs`, the citation audit, two snapshots, the note), so this branch carries them cherry-picked onto current main, and no DataBinder, OoDataBinder or DEVLOG 3015 file rides along.

**Docs.** `ConstructDialectStatus.Citation`'s doc, `DESIGN-edition-framework.md` and the audit's docstring state the rule. No inventory row changes verdict (`closes_rows: []` with its reason).
