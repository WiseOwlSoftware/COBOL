## PB3565: COMPUTE with a sole boolean function, parenthesised boolean item or boolean constant-name is Format 2, through the one sole-operand classifier

Fuzz programs fz00030 and fz02828 (run fuzz-20261022-163846) were refused with COBOLNET1511 on `COMPUTE B8 = FUNCTION BOOLEAN-OF-INTEGER(5, 8)` with `B8 USAGE BIT PIC 1(8)`. Re-probe on the worktree build reproduced it, and the sibling sweep found the same refusal on a user-defined boolean function (alone and in parentheses), a parenthesised boolean item (`COMPUTE B8 = (C8)`) and a boolean constant-name (`COMPUTE B8 = KB`). ISO §8.8.2 admits "an identifier referencing a boolean data item" and "a boolean expression enclosed in parentheses", §15.2 2) makes a boolean function a boolean identifier, §8.4.3.2.4 1) gives a function-identifier a temporary data item, and §13.10.4 1) makes a constant-name the literal it stands for (each citation run through `cite.py --check`).

Root cause: a sole right-hand operand parses as Format 1's arithmetic expression, and `ArithmeticBinder.BindCompute` re-routes it to Format 2. The re-route classified the operand with its own copy of the rule, an unparenthesized data reference probed for category boolean. The boolean expression's own leaf (`ConditionBinder.BindBoolOperandValue`) already knew all three forms through parentheses. The fix extracts that knowledge into `ConditionBinder.BindSoleBooleanOperand` and its diagnostic-free twin `IsSoleBooleanOperand`, and the leaf, the routing predicate `IsBooleanValueOperand` and the re-route all call them. The next host of a sole boolean operand gets all three forms by calling the pair, and `SoleBooleanOperandDriftTests` pins the wiring (the re-route may not read `SoleDataRef` or `SoleFunctionCall` itself again). A numeric receiver with a sole boolean function now reports the Format 2 SR2 receiver refusal, as it already did for a sole boolean item.

Goldens: `14.9.8-COMPUTE/pb3565_compute_boolean_sole_identifier` (2002; intrinsic, parenthesised, multi-receiver, user function, parenthesised item, constant-name), refused `pb3565-compute-boolean-function-below-2002` (85), `pb3565-compute-numeric-receiver-boolean-function` and `pb3565-compute-boolean-receiver-numeric-function` (2002 to 2023). IF, EVALUATE (subject and WHEN) and a COMPUTE inside ADD's SIZE ERROR phrases already compiled these forms. No inventory row changes verdict: every row of the family was CONFORMS and the defect was a witness gap.

Found and left: a user-defined function whose RETURNING item is `USAGE BIT` returns zeros to the caller (the MOVE inside the function works), while the same function without USAGE BIT returns the value. It is outside this mechanism and is reported as a lead.
