## PB2509: a record sequential print stream keeps its records whole and framed

**The defect.** A record sequential file written with ADVANCING (no LINAGE clause, not a report file) presented each record as its characters less trailing spaces and wrote a RECORD VARYING record bare. GnuCOBOL 3.2 keeps that file a binary sequential file and writes the whole fixed-length record, and a varying record behind its length header. ISO §14.9.51.4 GR21 states the strip for a LINE SEQUENTIAL file alone, §13.18.43.4 GR6 gives every record of a fixed-length file integer-1 bytes, and §9.1.7.2 leaves a record sequential record's on-medium form to the implementor, so CLAUDE.md rule 1's precedence took GnuCOBOL's, as it took the line end in PB1664. The owner released the note from the PB3420 hold on 2026-11-03.

**Re-probe (branch build, before the fix).** The refuter's two programs: three 8-byte records `AA`, `BB`, `CC` wrote two bytes each (with PB1840's overprint controls between them), and a RECORD VARYING 1 TO 8 pair `AAA`/`BB` wrote `LF AAA LF BB LF` with no length word. Both reproduced.

**The fix.** One predicate, `SequentialConnector.IsRecordPrintStream` (record sequential, a record description, no LINAGE clause), now answers both questions the connector asks of a print stream: its line end (`SelectLineEnd`, PB1664) and the form of its record. `WriteAdvancingRecord` writes such a record at its full GR13 length (`FitRecord`, trailing spaces kept); a RECORD VARYING one also gets the DOC-A.1-151 (a) frame head, written by `Present` after the overprint return so the head belongs to the record, carrying the record's extent table, which `WriteAdvancing` and `FileRegistry.WriteAnyOrg` now pass to the print arm (the print-control WRITE used to drop it, so a variable-length group written with ADVANCING lost the table a plain WRITE gives it). The LINAGE and report shapes keep GR21's strip because GnuCOBOL reclassifies both LINE SEQUENTIAL; the line controls (LF, FF, bare CR) did not move. `PublicAPI.Shipped.txt` carries the new optional parameter. DOC-A.1-146 (c') is rewritten for the two forms and its witness list names the new tests.

**Goldens.** `conformance-suite/cases/14.9.51-WRITE/pb2509_record_sequential_print_stream_form` (accept 2002, because it reads the bytes back through a BINARY-CHAR redefinition) writes a fixed and a varying print file and shows every byte of each (19 and 16 bytes). No refused program: the fix gates no syntax. `PrintStreamLineEndConformanceTests` gains the whole fixed record, the controls between whole records, the framed varying record, the refused length (status 44 writes no frame and no line feed) and the three shapes that still strip.

**Rows.** None claimed, none closed (`closes_rows: []`): DOC-A.1-146 was closed by PB1278 and keeps its verdict.

**Self-review.** Architecture: one predicate for the shape, no second copy of the LINAGE/report test. Full code: the print and plain arms now agree (a fixed record on the plain arm was already written whole). Performance: no allocation beyond the record fit the arm already made. Duplication: `EmitFrameHead` is the one head writer for both arms.
