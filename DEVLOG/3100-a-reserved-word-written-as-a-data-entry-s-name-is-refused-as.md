## Entry 3100 — 2026-11-04 13:34 PST — A reserved word written as a data entry's name is refused as a name, not as a clause (PB4604)

`01 MOVE PIC X.` drew COBOL1941, "'MOVE' is not a clause of the data description entry", and `01 JSON.` drew COBOL0313 followed by the same clause sentence. Both point away from the cause. ISO 13.16.3 SR4 puts the entry-name clause directly after the level-number and makes it optional, so the first word after the level-number is read as the name and as the first clause. A reserved word is neither, and 8.3.2.1 1) says reserved words shall not be user-defined words.

The re-probe on a fresh build showed the whole family: levels 01, 05, 66, 77 and 88, LINKAGE, LOCAL-STORAGE and FILE SECTION records, and words that are not verbs (TO, ZERO, SECTION) all drew COBOL1941, because `ReservedWordUse` and hint 0g both yielded to `ClosedFormatResidue`, which treated the slot as a clause position alone. A second limit hid the rest: the COBOL0901 report took only verbs and reservation-gated words, so a word like TO had no report to fall back on.

The fix marks the slot structurally. `ClosedFormats.EntryNameDueAfter` returns the level-number's token for a data description entry with no data-name, and `OffendingPosition.EntryNameIsDue` compares it with the token before the offending word, so a name or clause already written closes the slot. `ClosedFormatResidue` returns null for a reserved word there that `CobolParserCoreBase.ReservedAsAName` calls a name violation: any keyword section 8.9 reserves at the edition (`ReservedWord` gained a `WordScope`, with `AnyReservedWord` for a position that can only be a name) or a word of the 4.2.10 extension register. COBOL0901 then reports it alone. An extension word other than JSON and XML (ENTRY) draws the COBOL0313 sentence through `ExtensionReservationSentence`, which the JSON/XML hint now shares. The word after a name or a clause (`01 W-A PIC X MOVE.`, `01 PIC X MOVE.`) keeps COBOL1941.

Goldens: three refusals in `conformance-suite/cases/8.3.2.1-General/pb4604-entry-name-*` (a verb, a non-verb, an extension word), each refused at all four editions with its diagnostic file, and an accepted guard, `13.16-Data-description/pb4604-clause-keyword-at-the-entry-name-slot`, whose unnamed `USAGE`, `PIC` and `VALUE` entries must keep compiling. `ClosedFormatReservedWordTests` gains the name-slot theory (ten entries, four editions each, exactly one diagnostic) and the controls. The design gains "The entry-name slot" in `DESIGN-frontend-grammar.md`. No inventory row changed.

One lead stays open: `01 W-A MOVE.` omits "for 'W-A'" from COBOL1941, because a prediction that fails ahead of the parser reports with the entry's context before its data-name is attached.
