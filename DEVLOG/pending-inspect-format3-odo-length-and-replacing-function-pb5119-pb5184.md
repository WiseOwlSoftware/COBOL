## INSPECT format 3: the occurs-depending length and the REPLACING half's functions (PB5119, PB5184)

Two defects in one root, `InspectEmitter.EmitBody` and the identification of a format 3's operands.

PB5119. A format 3 INSPECT of an occurs-depending group whose TALLYING stores into the DEPENDING ON item read the group at length 3 and wrote it back at length 5, destroying characters 4 and 5 (`ZZZ` and two spaces at `--std 85` and `--std 2023`). Re-probe on the build confirmed it. The editions differ, and both edges are quoted: §2023:14.9.22.4 GR19 makes item identification of the format 2 statement happen once before the format 1 statement, and §2023:14.6.4 step 6 puts the occurs-depending length in item identification (the 2002 text is worded the same), so from 2002 the result is `ZZZBA`; §1985:VI.6.18.4 GR17 fixes only the subscripting and the length is read at the start of each successive statement (§1985:VI.5.8.4 GR3), so at `--std 85` it is `ZZZZZ`. Fix shape: `DialectBehavior.InspectFormat3LengthIdentifiedOnce` (ChangedIn 2002, VCR row 7.56). From 2002 `InspectBinder` pins the DEPENDING ON object as a pre-op through the existing `FreezeOdoExtentBeforeRefMod` (made internal, so there is no second copy); at 85 it sets `BoundInspect.ReplacingTakesLengthAnew` and the emitter re-reads identifier-1 after the counters are stored. Goldens `pb5119_format3_odo_length` (2002 2014 2023) and `pb5119_format3_odo_length_1985` (85).

PB5184. A function-identifier in the REPLACING half was rendered inline in the replace call, after the TALLYING counter store, so `REPLACING ALL FUNCTION UPPER-CASE (LIT (I))` read I after the tally raised it (`3 XAXZ` for the golden's `3 XZXB`). `EmitBody` now takes every operand of every phrase through one `Once` closure, in source order, before the first counter is stored; `TallyOperandTexts` takes the closure and `ReplaceOperandTexts` is its twin. Golden `pb5184_replacing_function_once` (85 2002 2014 2023) covers a function pattern and a function replacement.

Rows: 1985-GR-VI.6.18.4-5 PARTIAL to CONFORMS (a `record_verdicts --edition 1985` batch, GAP 689 to 688); 2023 rows GR-14.9.22.4-19 and GR-14.9.22.4-6 stay CONFORMS and gain the witnesses. Nothing is refused, so there is no refusal golden.
