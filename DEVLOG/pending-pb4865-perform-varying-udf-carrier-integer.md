## PERFORM VARYING reads the integer test through the user-function carrier (PB4865)

PB4865: `PERFORM VARYING IX FROM 1 BY FUNCTION TWO ...` (IX an index-name, TWO a user-defined function returning PIC 9) was refused COBOL2120 under ISO 14.9.28.3 SR4 a). The re-probe on the branch build reproduced it. Cause: a function whose evaluation activates a user function binds to the per-evaluation carrier `BoundUdfEvaluatedExpr` (GR12 window), which `Classify` reads through for the KIND but `BindVaryingOperand`'s integer test did not read for the TYPE. Fix: the integer test reads the carrier's `Inner`. Goldens: accept 2002 `pb4865_perform_varying_user_function_integer_operand` (BY and AFTER FROM slots, output computed from the rule), refusal `pb4865-perform-varying-user-function-below-2002` (COBOL0900 at 85). Sibling sweep: `PERFORM ... TIMES` with a user function already ran; no other IsIntegerOperand reader binds a carrier. No inventory row closed.


Review round 1 (R1-1, blocking): reading the integer test through the carrier let a PARENTHESIZED user function (`BY (FUNCTION TWO)`) compile, because the binder drops the grouping parentheses and `Classify` saw only the function reference; main refused it only by the integer test. The same hole existed unparenthesized-by-shape on main for `BY (J)` and `FROM (1)`. Root fix: `BindVaryingOperand` classifies a wholly parenthesized written operand (`SoleOperand.Unparenthesized` differs from the operand) as Invalid, so §8.8.1.1 (a parenthesized operand is an arithmetic expression) refuses it COBOL2119 against the brace group §14.9.28.2 prints. Goldens: `pb4865-perform-varying-parenthesized-user-function`, `pb4865-perform-varying-parenthesized-identifier` (COBOL2119) and, for lead R1-2, `pb4865-perform-varying-user-function-not-integer` (a PIC 9V9 user function stays COBOL2120 in BY and AFTER FROM).
