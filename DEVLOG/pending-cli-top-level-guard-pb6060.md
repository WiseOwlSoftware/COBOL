## The CLI names an internal compiler error instead of printing a raw stack

kb/Work PB6060. An exception thrown inside a compiler pass left `cobol` as a stack trace with status 1. Re-probe on this build: `System.CommandLine`'s default exception handler (not the runtime) catches an action's exception, prints it and answers 1, so a `catch` in the CLI could never have fired. `Program.Main` now invokes the parse with that handler off and wraps the call in `RunGuarded`: it prints `internal compiler error: <innermost WiseOwl.Cobol type on the stack> threw <exception> while running cobol <args>`, then the full exception text (stack included), and exits 70, EX_SOFTWARE, the code the backend's refusal of generated C# already has; a refused source stays 65. One guard covers the compile, `--run`, the listing and both batch verbs; the parallel loops' `AggregateException` is unwrapped to name the throwing pass. Tests in `CliParserTests`: a throwing command action gives 70 and the named report, a parallel entry names its pass, a returned status passes through. The manual's exit table gains the case. Not done: the last source position the pass held; no pass carries one on a shared context, so that is a design lead. Closes no inventory row.
