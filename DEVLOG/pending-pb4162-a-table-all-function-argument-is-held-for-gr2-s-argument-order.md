## PB4162: a table(ALL) function argument is held for GR2's argument order

ISO section 8.4.3.2.4 GR2 evaluates a function's arguments individually, left to right, and section 15.3 14) makes `T (ALL)` "as if each table element associated with that subscript position were specified": a sequence of arguments, each evaluated where it stands in the list. A later argument's user-defined function activation is a statement-scoped pre-op that runs before the statement renders its call, and an ALL operand was neither recorded in the `ArgumentOrder` window nor held, because the backend enumerated it where the call renders. So `MAX (T (ALL), UDF (X))` read T after the activation, and `ArgumentOrder.Hold` had a guard that held a nested call naming an ALL as a value, which gave `LENGTH (MAX (MAX (T (ALL), 1), UDF (X)))` the value's description (4) where the unheld form answered 8 (PB4124's residual).

**Re-probe on the base build.** With an EXTERNAL table the activation changes (21 5 7, then +100 each), `MAX (E (ALL), UDF (0))` answered 121 and `SUM` 333 where the elements held 21 5 7 when the argument was reached (21 and 33), `MAX (1, E (ALL), UDF (0))` 121, and the nested forms of PB4162's own repro (`E:/COBOL-coord/scratch/w20261773a/p8.cob`) disagreed with their unheld twins in value (000000021 against 00000021) and in LENGTH (4 against 8).

**The fix, at the root.** `IntrinsicBinder.TryBindAllArgument` records the operand it builds, and when a later argument registered pre-ops `ArgumentOrder.StoreAt` holds it with `SendingValueTemp.MaterializeTableAll`. The held form is a compiler-temporary TABLE of the element's own description (`DataBinder.CreateCompilerTempTable`, over `CreateCompilerTemp` and a scratch model, so the description clauses are copied by the one `CopyEntryDescription`) and a new pre-op, `BoundHoldTableAll`, that copies the elements the enumeration yields into it in section 15.3's order by the ordinary identity MOVE (`TableHoldEmitter`). The call's operand becomes a `TableAllPlace` over the temporary, so every consumer reads what it read for the source table: the lanes (`AllArgs<CobolDec>`, `<double>`, `<string>`, the Int128 alignment), `FunctionDeviceText.Field`'s description of a selecting function's result, and the `Hold` recursion into a nested selecting call (the report's `array of FunctionValueField` was not needed). The held table is one flat level in enumeration order whatever the number of ALL levels: a fixed table when every range is fixed; a fixed table at the product of the levels' maxima plus a numeric count temporary (`AllCount.Odo`, minimum 0) when a level is OCCURS DEPENDING; a dynamic-capacity table whose capacity the copy sets when a level is dynamic-capacity (the walk runs twice). The guard in `ArgumentOrder.Hold` is deleted.

**Goldens.** `15.3-Arguments/pb4162_table_all_argument_held_for_order` (2002+) answers fifteen results derived by hand from sections 8.4.3.2.4 2), 15.3 14), 15.60.1, 15.61.4 2), 15.71.4 1) and 15.72.4 1) over a one-level, a two-level, a partly subscripted, an OCCURS DEPENDING and a text table and two nested calls, and after each shows the first element read back as 121.5 to prove the activation ran; `pb4162_table_all_dynamic_capacity_held_for_order` (2014+) does the same for a dynamic-capacity table and a dynamic-capacity table nested in a fixed one. Each has its below-edition refusal (`pb4162_table_all_argument_held_below_2002`, `pb4162_table_all_dynamic_capacity_held_below_2014`). `HeldFunctionArgumentDescriptionTests` gains six table(ALL) shapes (held and unheld agree in DISPLAY, LENGTH and BYTE-LENGTH) and `ArgumentOrderDriftTests` a test that `TableAllPlace` is built only where it is recorded and held. IF, EVALUATE, PERFORM UNTIL and a loop body were probed and answer the same.

**Self-review.** Architecture: one mechanism per job (the window records, `Positioned` places, `SendingValueTemp` materializes, the emitter walks), no C# text in the bound node. Full code: the dynamic arm and the nested-dynamic arm ran on the first build; the empty ALL still raises EC-ARGUMENT-FUNCTION at the consuming enumeration. Duplication: the walk is `CobolTable.AllArgs`'s row-major loop written as nested loops over the same index vector, and the element store is `IdentityStore`, the copy every held operand has. A section 8.5.1.12 variable-length group element, the one shape `SendingValueTemp.Model` cannot describe, is refused as a function argument (COBOL1627), so no legal program reaches an un-held ALL operand.

`PB4162` landed; it closes no inventory row (`closes_rows: []`, with the reason).
