## PB5132, PB5133, PB5353, PB5466, PB5555, PB5556, PB5632: the 1985 witness gaps and comment defects close; the debugging-line rule is asked in both directions

Seven small notes, one group. Each was re-probed on the branch's build before it was touched.

**PB5466 (the one that changed behavior).** §1985:VI.7.3 says "The content of a debugging line must be such that a syntactically correct program is formed with or without the debugging lines being considered as comment lines." PB5212 asked one direction: a unit WITH `WITH DEBUGGING MODE` whose lines, hidden, would not parse (COBOL7061). The converse, a unit WITHOUT the mode whose debugging lines would not parse as source, was written into `docs/conformance/3/D-DEBUG.md` as "not asked", with no reason. The re-probe confirmed it: `D    DISPLAY` followed by a normal `DISPLAY "END".` compiled clean at --std 85 and ran. `Frontend.ReportDebuggingLinesBreakingTheProgram` now parses a copy with the comment lines' text (and a hidden USE FOR DEBUGGING section) exposed as source, and reports COBOL7061 the same way; the descriptor's text is direction-neutral. Writing the second parse found a latent defect in `Frontend.ParseCopyOf`: the copied stream was never filled, so the parser's error recovery (`ReadingParses`, which reads the tokens AHEAD of the offender by index) threw `ArgumentOutOfRangeException` on the first syntax error beyond the fetched tokens; the copy is now filled up front. Goldens: `pb5466-debugging-line-syntax-no-mode` (refused, `(25,8): error COBOL7061`) and its control `pb5466-debugging-line-no-mode-parses-both-ways` (accepted, prints END). The gate's first run found ONE corpus case the converse refuses: `pb4298_floating_debugging_text_on_d_line_85` (a no-mode unit whose D line holds `>>D DISPLAY "DEBUG"`, accepted as commentary on the premise "a comment line holds any characters"). §1985:VI.7.3 does not leave a debugging line's content free, and the text is no COBOL-85 source, so the golden is now a refusal (`(28,8): error COBOL7061`, still no COBOL5770, SR8 being a 2002 rule); `docs/conformance/3/D-DEBUG.md` says so. The other 16,821 Conformance cases and the corpus round trips (6,749 binds) passed.

**PB5132 (four missing witnesses).** MULTIPLY and DIVIDE receivers-only composite refusals, one program per verb (`pb5132-multiply-receivers-over-18-digits-85`, `pb5132-divide-...`: COBOL0805, 19 and 20 digits); SORT with both USING files on one MULTIPLE FILE TAPE reel (`pb5132_sort_files_on_one_reel_85`, §1985:XI.4.4.3 SR7, AAAA then BBBB); RECEIVE after DISABLE I-O TERMINAL (`pb5132_disable_io_both_ways`, §1985:XIV.3.2.4 GR5 and GR1: SEND gives 10, RECEIVE no data, the second DISABLE 15, ENABLE then delivers HELLO); an embedded-sign numeric opposite a group (`pb5132-numeric-embedded-sign-with-group-1985`: EQUAL at 85, NOT EQUAL from 2002, with an unsigned control).
