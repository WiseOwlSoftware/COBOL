## Entry 3172 — 2026-11-05 17:16 PST — The paged store engine's statement entry without a connector (PB4734, message control system slice 1)

Slice 1 of DESIGN-communication-facility.md §9: the keyed store engine gets its second client's entry, with no change to keyed files.

**What changed.** (1) `Store/StatementLanding.Complete` is the transaction-free half of `KeyedStore.Change` (size the statement, begin it, flush every tree and set its root, complete with page 2 last, discard every pending edit on a refusal); `TreeChange` and `Edit` moved beside it and the HOLDINGS work stays in `KeyedStore` behind `IStatementAddition`. The design named it `StoreStatement`, which is already the connector's hold on the store mutex, so it is `StatementLanding` and both design docs say so. (2) `StoreKind` is the meta page's organization byte: `R`, `I` and the new `M`, whose page writes `F`, 0, 0 and 0 at the offsets a file uses and records no `FixedFileAttributes`. `MetaPage` carries the kind in place of the attributes, `Decode` refuses an `M` slot with any other value in those fields, `Describes` answers `Foreign` for a committed `M` slot (a COBOL OPEN answers '39', §14.9.27.4 GR10), and `PagedFile.Open(..., messageStore:)` refuses a store of the other family with '30' and writes nothing. No format version change. (3) `PageMediumObserver` replaces `KeyedStore.MediumObserver` as the one fault seam, through all 17 test files and the docs; no alias. (4) `HostRegionLocks.HoldStoreMutex` returns the `RegionLockResult`; its three callers read `Ok` as held, as before. (5) `McsPresenceByte` (`RegionBase + 0x103`).

**Re-probe.** The note is a design slice with no repro; the build was 0 warnings and 0 errors at each step.

**Goldens and tests.** No COBOL golden: nothing a COBOL program can observe changes (the message control system lands in slices 3 and 4). `unit:StoreKindTests` (12 cases): the `M` layout at offsets 40 to 50, each refused `M` field, an unknown organization byte, `Describes` on both families, `Open`'s family check for both directions and both access modes, the core landing for a client with no transaction, refusing at every page write with the pending edit discarded and the next statement succeeding, and the in-hold reopen: refused before and after each write, the adopted generation equals the statement's stamp exactly when the statement landed (one case of all, the page-2 write applied and refused).

**Rows.** None closed; the facility sits outside the 2023 text the inventory derives from.
