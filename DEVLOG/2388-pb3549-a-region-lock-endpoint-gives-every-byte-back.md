## Entry 2388 — 2026-10-22 21:13 PDT — PB3549: a region-lock endpoint gives every byte back explicitly, never by the close of its handle

An abandoned transaction survived the next writable OPEN once in a parallel Linux unit run (`A_transaction_whose_rollback_was_refused_is_never_committed`, abnormal-always: "the HOLDINGS tree is empty once no transaction is open"), and eight isolated runs passed. The note named two candidates; the first is the mechanism. `HandleRegionLocks.Dispose` was a no-op, so the liveness byte of a kept handle given back at the run unit's end was left to the close of its descriptor. A Linux open-file-description lock outlives that close while any copy of the descriptor lives, and a fork in another thread holds one until its exec; Windows says the unlock of a closed handle's locks takes as long as "available system resources" allow. The next OPEN's dead-owner probe then read the dead owner as alive and rolled nothing back.

The re-probe made the race deterministic: a second handle on the same open file (Linux `dup`, Windows `DuplicateHandle`, `tests/_shared/DescriptionCopy.cs`) stands in for the fork. Built from main before the fix, the new `CommitRollbackRuntimeTests` row failed for both keyed organizations with the gate's own message, and the two `RegionLocksDriftTests` rows answered `Held` for bytes a disposed endpoint had held. That drift test had excused the handle-owned hosts ("give a lock back when the connector closes the handle"), which is how the gap stayed green.

The fix keeps the `RegionLocks.Dispose` contract on every host. `HandleRegionLocks` keeps a map of the bytes it holds (holds do not stack, as on the lock-file host), and `Dispose` unlocks each one while the handle is still open. The sibling sweep covered every owner of an endpoint and every host primitive that leaves a lock to a close. `SequentialConnector`'s CLOSE and abandoned OPEN closed their streams before giving the endpoint back; they now flush, give it back, then close. `HandleColumnLockHost` (Windows) now unlocks its column byte before closing its handle, a refused publication's byte included. The OFD column host already did. For the second candidate, `OfdRegionLocks.Classify` is now the one `fcntl` reading for every command. It asks an interrupted call again for as long as it recurs, and a refused lock record (`ENOLCK`) up to four calls in all. The probe's three answers are one enum, `OwnerLiveness` (`KeyedStore.OwnerOf`), which `RollBackDeadOwners` and the lock test read through `MayRollBack`; an owner the host cannot see is read as alive.

The owner's rule for concurrency designs asks for an executable model, and `scripts/models/kept_liveness_model.py --self-test` is it: 522 interleavings of forks, execs and transient probe answers, GREEN. Each of five mutations is RED on the row it names; the old protocol fails `give-back-under-fork` with open, fork, draw, end-refused, detach, dispose, close, B probed Alive. Goldens: the description-copy row, both organizations; a stress row (six rounds, four parallel writable OPENs racing for the dead-owner step while another thread starts child processes without pause); the two drift rows. The design doc's region-endpoint paragraph and dead-owner step say all this. No inventory row closes.
