## A USAGE BIT RETURNING item delivers all its boolean positions to the caller (PB3586)

PB3586: a user-defined function whose RETURNING item is `PIC 1(8) USAGE BIT` returned all zeros to its caller (`MOVE FUNCTION UBIT(3) TO B8` showed `00000000` while the function's own DISPLAY showed `00001010`); the same function declared `PIC 1(8)` was right. The re-probe on a fresh build reproduced the note, and showed the same loss for a program: `CALL "SUBR2" RETURNING BB` returned `00000000`.

**Root cause.** `CallEmitter.BoundaryImageWidth` is the one answer for the character width of a formal's text crossing; `BoundaryLength` turns it into `CobolArg.Length` and the registered `BoundaryItem` length. For an elementary item it returned `DataItem.ImageWidth`, which for `PIC 1(8) USAGE BIT` is the occupancy (`BitLayout.Characters(8)`, one storage character), while the item crosses as its eight boolean positions. The caller's RETURNING `CobolArg` stated `Length: 1`, and the delivery fitted the eight-position result to one position. The bit group arm (`IsAsIfElementary`, `AsIfPic.Length`) was already right, which is why only the elementary item failed.

**Fix.** `BoundaryImageWidth` answers `Pic.Length` for an elementary `USAGE BIT` item. The caller's receiver, the callee's registration and the .NET host entry's detached storage share that width. `FigurativeFillWidth` read `ImageWidth` directly for a non-numeric elementary formal and now reads `BoundaryImageWidth`, so its figurative fill cannot disagree with the window (a sibling found in the same file). The note named `IntrinsicBinder.cs` and `ProgramEmitter.cs`; neither needed a change.

**Sweep.** A 12-position item (two storage characters), a `GROUP-USAGE BIT` result, an OO method with a `USAGE BIT` RETURNING and USING item, `USAGE BIT` arguments BY REFERENCE and BY CONTENT, and a `USAGE NATIONAL` RETURNING item all returned the right value after the change (national positions already equal `ImageWidth`).

**Goldens.** `cases/8.4.3.2-Function-identifier/pb3586_function_returning_usage_bit` (2002 and up; ISO 8.4.3.2.4 GR1 and 14.6.5, both checked with cite.py) moves an 8- and a 12-position function result to a `USAGE BIT` and a display-usage receiver, displays one, compares one, and repeats the case through `CALL ... RETURNING`. `pb3586-function-returning-usage-bit-85` is refused at 85 with COBOLNET0900. No inventory row changes: the rules were already CONFORMS and the note claimed none.
