**I-O (PB1562, F1).** The first landing made an explicit Format 1 file whose record holds a DYNAMIC LENGTH item register VARIABLE, framing its records with an extent table. A second program describing the same file as `RECORD CONTAINS 20` over `PIC X(20)` — the same §9.1.6 fixed attributes, §13.18.43.4 GR6 — got OPEN '39' on a relative file and read the framing bytes as data on a sequential one. Nothing one program's record description adds can be on the medium of a file whose type and size are shared, so the design is the reverse: the file stays FIXED, and a variable-length record is carried in its FIXED FORM — every member at the position it has at its MAXIMUM size, space padded, read back at that width with the padding dropped (D-FRA (vi)). The exact round trip holds for every member that does not end in a space; a trailing space is padding, the one stated loss, and exactness for every value cannot fit in integer-1 bytes.
